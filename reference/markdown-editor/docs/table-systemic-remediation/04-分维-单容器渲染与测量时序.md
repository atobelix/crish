## 3. 表格岛设计（ADR-2 / ADR-4 / ADR-5 落地）

### 3.1 DOM 结构

```
<div class="virtual-row virtual-row-gpu" data-index={startLine}>   ← 外层唯一虚拟项（E12/E18）
  <div class="table-island" data-table-id={id} style="--table-cols: 128px 96px minmax(140px,1fr)">
    <div class="table-island-track">                 ← width:max-content; min-width:100%
      <div class="table-island-probe" aria-hidden>   ← 离屏测量行：absolute; 0×0; overflow:hidden
        <span class="token-table-cell table-island-probe-cell">…</span> × cols
      </div>
      <div class="table-island-header" role="row">   ← sticky；与正文行同列网格
      <div class="table-island-pad-top" aria-hidden>  ← 上哨兵（窗口前各行高之和）
      <div class="table-island-row" data-line-index={i}>  ← 岛内行（grid-template-columns: var(--table-cols)）
      <div class="table-island-pad-bottom" aria-hidden>
```

**落地形态（T4，与草图的两处差异已登记）**：① 哨兵类名实际为 `.table-island-spacer`（`TableBlock.tsx:400-414`），非草图 `pad-top/pad-bottom`；② 列宽载体**不是**岛根上的 CSS 变量 `--table-cols`，而是**每一行容器的内联 `grid-template-columns`**（`TableBlock.tsx:151-161` 算出 `rowStyle` → `:377` 传入 `TableIslandRow` → `TableIslandRow.tsx:121` 写 `style`）。岛根**不写任何样式属性**（`TableBlock.tsx:383-389`）。该偏差的取舍见 §3.4。

- 岛根 `.table-island` 是**唯一** `overflow-x:auto` 所有者（`overflow-y:hidden`、`width/max-width:100%`，`src/styles/table-island.css:16-24`），横向滚动条只有一条（F-Vis-3）；`table-last-row` hack（E2）在 T8 删除。
- **为什么不用原生 `<table>`（ADR-2 已否决，理由写清）**：① 原生表格的列宽/行高由表格布局算法整体求解（`table-layout:fixed` 需要完整列结构、`auto` 随内容与视口浮动），无法只挂载「窗口内若干行」而不引起整表重排与高度塌陷，与行式虚拟化（E18）正面冲突；② `<thead>` 的 sticky 与表格布局、`overflow-x` 滚动容器的交互在各引擎不一致，无法作为「一个虚拟项」的稳定高度来源；③ `<colgroup><col>` 只在真实表格布局中生效，若为它引入 `<table>`，列宽真源会从「一次测量」退化为「浏览器二次求解」，与 ADR-4/I2 冲突。
- **落地形态（T4，与原文偏差已登记）**：岛内行**未**走「`BlockRenderer` 裸行变体」方案，而是**新组件** `src/components/TableIslandRow.tsx`——行级派生（行内 token / 活动态 / 搜索命中 / 流式预演 / 表格身份）一律经共享单元 `deriveLineUnit`（`src/core/lineUnit.ts:155-183`），再直接调 `InlineRenderer`（`TableIslandRow.tsx:123-131`），不套 `BlockRenderer`。**理由**：`BlockRenderer` 的行分支与 `TableRowBlock`/`TableSeparatorBlock` 深度耦合（自带滚动容器、per-cell 写回、`table-last-row`），改其内部变体等于在同一文件里维护两套行结构；新组件把「岛内行」这一新形状独立出来，且与旧路径共用 `deriveLineUnit` 保证 SSOT（§5 I8）。旧路径（`BlockRenderer.tsx`）**本波次零改动**——故接线点 E20 未被消费，`BlockRenderer` 的「裸行变体」不再是本维计划项。开关关闭时岛组件整体不参与渲染（`MarkdownEngine.tsx:2521` 的 `hostAt` 恒 `null`），旧结构零风险。
- 活动行：岛内行由岛按 `activeState` 命中自行加 `is-active-line`（`index.css:453-460`、`:466-468` 依赖该 class；`BlockRenderer.tsx:1540` 现状未加，属 `01-分维` V3 待验证项——岛路径是它的接线点）。
- `contain:paint`（E11）保留：岛整体在行盒内被裁剪，但岛自身已把横向溢出收进自己的滚动区，无内容被裁；岛高含自身滚动条，故与上报高度自洽。

### 3.2 横向滚动所有权

- 表头行与正文行位于**同一** `.table-island-track` 内 → 共享同一个 `scrollLeft`，横向同步是**零 JS 的布局结果**；E3 的两处 `useLayoutEffect` + rAF 守卫 + `tableScrollLeft` 跨行回写在本维路径上不再被消费（该字段的存废归 T5/T8 判定，本维不删）。
- **（设计态原文，保留）** 表头 sticky：`position:sticky; top:0` 置于岛内。**诚实边界**：`overflow-x:auto` 使岛成为滚动容器，`overflow-y` 只能取 `hidden`/`clip`（`visible` 会被计算为 `auto`），故 sticky 相对**岛自身滚动口**成立——F-Lay-1（表头随表横向滚动）天然满足；**「随文档纵向滚动而吸顶」不由该机制提供**，且参考帧 16/17 均为短表、无该证据。若验收要求文档级吸顶，表头必须移出横向滚动容器、成为岛拥有的覆盖层，并对**唯一一个** `scrollLeft` 做单点写入（单源同步，不是 D1 所否决的 N 路同步）——该二选一登记为 U-T3-1，需主控裁决（ADR-2 的「表头 sticky」措辞未区分二者）。
- **落地形态与 U-T3-1 结论（已裁决：`00-总方案` §13 **R6**）**：取「**仅岛内横向同步**」（表头随表横向滚动，满足 F-Lay-1），**不做文档级纵向吸顶**。实际代码**未写任何 `position:sticky` 声明**（`src/styles/table-island.css` 全文无 `sticky`）——表头行是岛轨内的**普通栅格行**（`TableIslandRow.tsx:109` 的 `table-header-row` 类，行容器样式仅内联 `grid-template-columns`），横向同步由「与正文行同处一个 `.table-island-track`」这一布局事实**免费**获得（零 JS、零 `scrollLeft` 回写）。故 R6 的两条要求落地后都成立：F-Lay-1 成立，且「文档级吸顶」这一未采纳分支**无任何实现痕迹**（不残留死 CSS）。参考帧 16/17 均短表、无纵向吸顶证据，与 R6 理由一致。

### 3.3 岛内行窗口化（R1 的直接缓解）

- **启用条件（已落地）**：`rows > ISLAND_WINDOW_THRESHOLD`（实际初值 **60**，`src/core/tableIsland.ts:20`；与 `overscan: 40`（`MarkdownEngine.tsx:956`）同量级）时启用；阈值以下整表渲染（有界成本，视觉与窗口化等价）。窗口计算在 `computeIslandWindow`（`src/core/tableIsland.ts:69-90`）内自行判阈值并返回 `windowed: false`，调用方（`TableBlock.tsx:168-181`）无需二次判定。
- **窗口计算（已落地，O(窗口) 而非 O(rows)）**：入参 = 行数 / 行顶前缀（`RowTopIndex.tops()`）/ 岛内可见顶（`visibleTop`，主控算 `virtualizer.scrollOffset − virtualRow.start`，`MarkdownEngine.tsx:2527`）/ 外层可视高（`parentRef.clientHeight`，`:2528`）。实现以「线性推进 `first`/`last`」求覆盖区间，再上下各扩 `ISLAND_OVERSCAN_ROWS`（实际初值 **8**，`tableIsland.ts:23`）——**与原文的差异**：原文写「`OVERSCAN_PX` 像素带 + 映射行号」，落地改为「行下标带」，省去 px→行的二分/映射（`tableIsland.ts:82-89`）。`visibleTop` 的正确性由岛高上报保证（3.6）。
- **行高来源（已落地）**：岛内 `RowTopIndex`（`Float64Array` 高度表 + 前缀缓存 + 脏标记，`src/core/tableIsland.ts:185-258`），由一个 **ResizeObserver 实例**观察窗口内已挂载行采样（`TableBlock.tsx:309-328`）；未测行用 `estimateRowHeight(lineIndex)`——`(已定型列宽, 行内容)` 的**纯函数**（`useTableIslandWiring.ts:149-161`，内部 `oracle.predict(..., tableColWidthsAtLine(...))`，见 3.6）。列宽先冻结 ⇒ 估算是确定函数 ⇒ 窗口滑动不引起高度震荡。
- **窗口外占位（已落地）**：上/下哨兵 `div` 高度 = 该侧行高之和（已测用实测、未测用估算），实现位置 `src/components/TableBlock.tsx:183-184`（`topSpacer` / `bottomSpacer`）与 `:400-414`（`.table-island-spacer` 渲染；类名见 §3.1 落地形态注）。
- **行号→像素前缀和（已落地，与原文有偏差，如实登记）**：原文要求岛内 **Fenwick**（点更新 O(log n)、前缀 O(log n)）以「避免 O(rows) 扫描」。**实际落地形态**为 `RowTopIndex`（`src/core/tableIsland.ts:185-258`）：`Float64Array` 高度表 + `Float64Array` 前缀缓存 + `dirty` 脏标记，脏时一次 **O(n)** 重算前缀（`tops()`，`:236-248`）；点更新走 `setHeight`（`:222-229`，内置 0.5px 稳定点护栏，与 `HeightMap` 同款）。
  - **偏差理由（反过度设计）**：点更新只来自岛内**已挂载行**的 ResizeObserver（`TableBlock.tsx:309-328`），量级 ≤ 窗口行数（窗口 + 2×overscan）；重建一次 1 万行前缀 ≈ 10µs（`count` 次浮点加法），远低于一帧预算。故不为 O(log n) 引入 Fenwick——少一层数据结构、少一处失效路径（Fenwick 的更新/查询双路径各自可错）。万行场景下前缀重算仅发生在「行高实测真的变化」的帧（`setHeight` 返回 true 才递增 `rowEpoch`，`TableBlock.tsx:320-322`）。
  - **文件域约定变更（已登记）**：原文「该结构私有于 `TableBlock.tsx`，以守住 §8 文件域」**已由主控改为下沉 core**——`RowTopIndex` 落在 `src/core/tableIsland.ts`（纯逻辑、零 DOM / 零 React），以换取可独立单测（`tests/unit/table-island.test.ts`）。§7 文件域表随之更新。
- **一个虚拟项的高度正确性**：岛高 = 表头 + Σ行高（含哨兵），由岛自报（3.6）；断言 `|island.offsetHeight − reported| ≤ 1`。行级 RO **只进 `RowTopIndex`**（`setHeight`，`TableBlock.tsx:320`），永不写 `HeightMap`/`virtualizer`（I3 的守卫）。
- **外层折叠（已落地）**：`rangeExtractor`（`useTableIslandWiring.ts:135-146`）把岛区间折叠为 `[startLine]` 一个索引（E19）——岛内行不会成为外层虚拟项，`getVirtualItems()` 不含区间内部行（jsdom 断言 `data-index == [0,1,2,6,7]`），万行表不产生 O(rows) 虚拟项（这是 R1 的关键：**不是靠返回 `null` 跳过，而是根本不成项**）。折叠实现在 `TableRangeIndex.collapse`（`src/core/tableIslandRanges.ts:119-130`）：非表格行原样保留、表格行只保留宿主行、宿主行不在候选内时**注入**（否则窗口落在表内部时视口内将没有任何虚拟项、整表消失，`:113-117`）。区间探测按**内容 epoch** 缓存（`mainLines` / `streamTail` 引用 + 行数，`tableIslandRanges.ts:159-174`）——无内容变更的滚动/光标帧**零探测**（`stats().probes` 不增长）。
- **批量测量循环的跳过（已落地，I3）**：即使内部行已不成项，批量循环仍**显式**跳过岛宿主行——`if (islandWiring.hostAt(item.index)) continue;`（`MarkdownEngine.tsx:1835`），使「岛高只有一个写者」不依赖折叠这一间接保证。
- 岛内行以 `data-line-index` 标识、`key=lineIndex`，同一源码行只允许一个节点（I8/F-Lay-4）。**已知边界**：岛内行**不提供** `data-index`（该属性要求全局唯一，岛宿主行已占用，`TableIslandHost.tsx:91`）——依赖它的上下方向键跨行导航在岛内退化为「目标行未挂载」（登记见 §5）。
- 跳转（大纲/查找/光标）落到区间内部行时，其逻辑起点等于岛起点 → `scrollToIndex` 落在岛上（行高 0 的语义，见 3.6）。**点击定位已适配岛内行**：`MarkdownEngine.tsx:2337-2342` 先查 `target.closest('[data-line-index]')`（更内层、更精确），未命中再回落 `[data-index]`。

### 3.4 列宽驱动载体：`<col>` 的 div 等价物

- `<colgroup><col>` 仅在原生表格布局生效，与 3.1 的否决理由③同源，**不采用**。
- **推荐（设计态）**：岛根写一个 CSS 变量 `--table-cols`（如 `128px 96px minmax(140px,1fr)`），表头行与全部正文行统一 `display:grid; grid-template-columns: var(--table-cols)`。每个 epoch 只写**一个元素的一次样式**（一次 style recalc），单元格不再接受任何宽度属性 ⇒ E5 的写回回路从根上消失（D4）。
- **落地形态（T4，与推荐方案的偏差，如实登记）**：**未使用 `--table-cols` CSS 变量**。实际为：岛**一次**算出模板字符串（`buildGridTemplate(colWidths, true)`，`TableBlock.tsx:151-154`）→ 包成 `rowStyle`（`:158-161`）→ **每一行容器**各自内联 `grid-template-columns`（`TableIslandRow.tsx:121`）。**取舍**：① 岛根不写任何样式属性（`TableBlock.tsx:383-389`），组件树里列宽只有一个来源（`colWidths` prop），比「岛根 CSS 变量 + 行消费 `var()`」少一层间接；② 代价是每次 `colWidths` 变化会写 **N 个行容器**（N = 窗口行数）的内联样式，而非 1 个元素的变量——因 `rowStyle` 是**同一个 memo 对象**（`:158-161`，引用稳定），React 侧无额外 diff 成本，样式重算仍集中在一次 commit；③ 岛路径下 `colWidths` 变化频率极低（探针一次测量，相同输入零写入，见 §3.5），故未采用「1 元素写」的优化。**注**：`--table-cols` 与 `--col-w-{i}` 在本波次**均未落地**，`src/styles/table-island.css` 内无这两个变量。
- 末列用 `minmax(<末列宽>px, 1fr)`：`track` 保持 `min-width:100%` 时由末列吸收余量，**不产生** E6 的空白条（S2 的「空列」根因是「行盒被撑到 100% 而列宽之和不足」，余量无处安放）。
- **U-T3-2 裁决结论（已落地，`00-总方案` §13 **R7**）**：取「**末列吸收余量**」——落地为 `buildGridTemplate(colWidths, true)`（`src/core/tableIsland.ts:101-114`，`:109-112` 把末轨改写为 `minmax(${tracks[last]}, 1fr)`），`TableBlock.tsx:151-154` 以 `lastFlexible = true` 调用。**理由**：岛轨声明 `min-width:100%`（`src/styles/table-island.css:45-48`）而列宽之和不足时，余量必须由末列吸收，否则轨道右侧留下空白条（症状 S2）。**缺省参数 `false` 保持纯 px 输出**（`tableIsland.ts:103`），既有单测口径不变（`tests/unit/table-island.test.ts` 的 `buildGridTemplate` 用例逐字保留）。
- **与 R7 的关系**：R7 的「Σ(固有列宽) ≤ 内容列宽时按余量分配铺满」由「分配器原样返回 + 末列 `1fr` 吸收」共同满足——分配器**不**把余量硬摊到各列（`allocateColWidths` 在 `Σ ≤ available` 时原样返回，`tableIsland.ts:156-158`），铺满由 CSS 轨道的 `1fr` 完成，故不引入「余量分配算法」这一新的不确定源（I2 保持）。
- 逐列变量 `--col-w-{i}` 供 T6 的列宽拖拽（拖拽直接写该变量）——**本波次未落地**，属 T6 文件域；T6 落地时须与「行容器内联 `grid-template-columns`」这一现有载体对齐（拖拽若走变量，需先决定是否把载体迁回 CSS 变量，或改为拖拽后重跑 `buildGridTemplate`）。

### 3.5 列宽计算（ADR-4 落地：「怎么算」）

- **一次测量（岛内、离屏探针，已落地）**：`.table-island-probe` 为 `position:absolute; width:0; height:0; overflow:hidden; visibility:hidden` 的 0×0 容器（不进岛高、不进滚动范围；`src/styles/table-island.css:91-100`），内放与真实单元格**同一盒模型**（复用 `.token-table-cell` 的 `padding` / `border` / `box-sizing`，`:102-110`）的 `width:max-content; white-space:nowrap` 探针格，逐格读 `getBoundingClientRect().width` → `ceil` → `intrinsic[i]`（`TableBlock.tsx:216-229`）。**jsdom 无布局引擎（rect 恒 0）时返回 `null` 并跳过定型**，绝不把 0 喂给分配器（`TableBlock.tsx:226-228`）——这是 I2 的 jsdom 侧契约（§5 落点表）。
- **探针代表文本（落地口径，与原文有偏差，如实登记）**：原文未规定取样集与 DOM 形态。**实际落地**：① 取样集 = **表头 + 首 `PROBE_HEAD_ROWS`（= 20，`TableBlock.tsx:100`）行**，跳过分隔行（`TableBlock.tsx:189-204`）；② 逐列取取样行中**字符数最长**的单元格**源码文本**为该列代表（`if (text.length > out[c].length) out[c] = text`，`:196-198`）；③ DOM **只渲染一行 `cols` 格**（`TableBlock.tsx:393-399` 的 `probeTexts.map`），对齐 §3.1 的 DOM 结构。取样集与滚动窗口**无关** ⇒ 列宽不随滚动抖动，强于原文「同一（内容、容器宽、窗口行集）恒等」的精确口径（无需「窗口行集」这一维度）。
- **已知偏差（登记为 T5/T6 收敛项）**：探针格渲染的是**源码文本**，而非**解析后的行内 token**。故含 Markdown 语法的单元格（`**bold**`、`[text](url)`、`~~del~~` 等）会被**高估**宽度（语法标记字符在真实单元格中不显示为文本）。**正确做法**：探针渲染该列代表单元格的**解析后 token**（经 `deriveLineNode` / `MarkdownParser.parseLine` 取该格 token 后交 `InlineRenderer`）。本波次**未做**——**不影响 I2 的确定性**（分配器仍是 `(intrinsic, available)` 的纯函数，同输入恒同输出），**仅影响列宽偏宽**（观感，非震荡）。同一偏差也使「`<br>` 硬断行」的探针语义失真（见下条）。
- **为什么不用 `scrollWidth`（ADR-4 已否决路径，必须写清陷阱）**：① 真实单元格一旦换行，`scrollWidth` 等于**换行后**的内容宽而非固有宽——列越窄测出来越窄，形成自增强收缩（D4 的循环依赖）；② `scrollWidth` 取整且**不含右边框**，而列轨是 `border-box`，按它设轨会窄 1px → 内容重新换行 → 行高变化 → I2 震荡；③ 现状正是该路径（E4）。改用探针 rect 同时消除①②。
- **分配规则（确定性 ⇒ I2；已落地）**：`w_i = clamp(ceil(intrinsic_i), MIN_COL_WIDTH, MAX_COL_WIDTH)`（实际初值 `MIN_COL_WIDTH = 100` / `MAX_COL_WIDTH = 480`，`src/core/tableIsland.ts:26,29`；落地于 `allocateColWidths`，`:146-171`）；若 `Σw_i > available`，按「固有宽从大到小（同宽按下标升序稳定）」单趟把超出部分从各列减到 `MIN_COL_WIDTH` 为止（**不再往下减**，`:159-169`）；若 `Σ MIN_COL_WIDTH > available`，允许岛横向滚动（F-Lay-1 合法），不牺牲最小可读宽。`available` 非法（非有限数 / ≤0）时**原样返回** clamp 后的数组（`:156`）——不把容器宽当约束。**纯函数性**：实现不含任何「上一帧结果」或测量时序依赖，同 `(intrinsic, available)` 恒同输出（这是 I2 的根据；`tests/unit/table-island-allocator.test.ts` 48 例覆盖）。
- **跨列合并（设计态，本波次未落地）**：从属格不参与测量（`display:none`，`index.css:416-418`、`InlineRenderer.tsx:451-463`）；主格（`colSpan=k`）产生约束 `Σ_{i..i+k-1} w_i ≥ intrinsic(master)`，不足时按固定顺序补足（差额加到该组**最后一个**轨）。**实际落地的 `allocateColWidths` 不含 colspan 约束项**（`src/core/tableIsland.ts:146-171` 无列组入参），故含 `colSpan` 的表在岛路径下按「逐列独立」分配（主格可能偏窄、由单元格自身换行承担）——登记为 T5/T6 收敛项。
- **`<br>` 多行单元格（设计态口径）**：探针 rect 宽 = 各硬断行中最宽一行（`<br>` 是硬断行，内容不可能更窄而不截断）；纵向增量由行高测量承担。**落地偏差**：因探针渲染源码文本（见上条），源码里的 `<br>` 会以字面字符参与测宽——故该设计态口径**未成立**，同归 T5/T6 收敛项（与「渲染解析后 token」同一处修复）。
- **两级 epoch（精准失效，避免无谓重测；已落地）**：内容 epoch 失效 `intrinsic[]`（需重跑探针）；容器宽 epoch 只重跑分配器（`intrinsic[]` 复用）。容器宽变化的精确解因此是 O(cols)，不是 O(rows×cols)。**落地形态**：① 内容 epoch = `probeSignature`（探针代表文本以 `\u0000` 拼接的**内容签名**，`TableBlock.tsx:213`），与 `epoch = ${startLine}:${endLine}:${cols}:${probeSignature}`（`:238`）共同构成 `intrinsicRef` 的失效令牌——**刻意不用全局 `decorationVersion`**：它在光标/选区变化时也递增，拿它做 epoch 会让「每次按键都重跑探针（一次强制 reflow）」；代表文本只在**列内容真变**时才变 ⇒ 光标帧零探针，编辑帧才重测（`TableBlock.tsx:206-212`）。② 容器宽 epoch = `el.clientWidth` 与 `lastAvailableRef` 比较（`:239,242,251`），未变且内容 epoch 未变则**整体短路**（`:242`）。相同输入重复测量 → 分配器同输出 → 比较后**零写入**（`:253-256`：逐项相等即 `return`，仅实际变化才 `onColWidths` + `recordIslandGridWrite`）。
- **长表边界（落地口径）**：探针取样集 = **表头 + 首 `PROBE_HEAD_ROWS`（= 20）行**，与滚动窗口**无关**（`TableBlock.tsx:191-192`：`last = Math.min(endLine, startLine + PROBE_HEAD_ROWS - 1)`）——故原文「表头 + 窗口内行 + 首 20 行」的窗口依赖项**被有意去掉**（列宽不随滚动抖动，且免去窗口变化时的重测）。原文的「未测行进入窗口时 **grow-only 一次修正**」**本波次未落地**：未测行（> 首 20 行）不参与探针，其内容过宽时表现为**岛内横向滚动**（列宽不追涨），登记为 T5/T6 收敛项。这与 `plan-A4` §3 的「候选态估算 + 闭合定型一次修正」**不冲突**：A4 定「何时定型」（`MarkdownEngine.tsx:2090-2114` 的锁宽/grow-only 语义在开关关闭时原样保留），本 ADR 只换掉「测量基准」（`scrollWidth` → 探针 rect）；开关**开启**时引擎侧定型整体让位（见 §3.7）。
- **落点与收尾（已落地）**：定型写 `TableStore.setTableWidths` + `recordTableWidthSettle`（E17，perf 口径不变）——落点在引擎侧 `islandOnColWidths`（`MarkdownEngine.tsx:1111-1114`），由 `TableIslandHost` 注入身份转发（`TableIslandHost.tsx:84-87`）；列宽载体为**行容器内联 `grid-template-columns`**（非 `--table-cols`，见 §3.4）；`InlineRenderer.tsx:466-478` 的 per-cell 写回在岛内**不被消费**——由**岛作用域规则**中和其内联兜底：`.table-island .token-table-cell{flex:none; min-width:0 !important}`（`src/styles/table-island.css:115-118`；`!important` 有仓库先例：`index.css:442,454,506`）。该文件内分支的**删除**属 T5/T8 文件域，本维不触碰（见 §7 与 U-T3-3）。

### 3.6 高度上报（ADR-5 落地：「谁上报」）

- **唯一上报源（已落地）**：岛根**一个** `ResizeObserver`（**只观察岛根，不观察行**，`TableBlock.tsx:288-304`）→ 读 `entry.contentRect.height`（无 RO 环境退化为挂载后读一次 `el.offsetHeight`，`:293-296`）→ `reportHeight`（`:276-285`）：先过 `STABLE_EPSILON`（= 0.5，`src/core/HeightMap.ts:17`）护栏（`TableBlock.tsx:279`，`|Δ| < 0.5px` 直接返回）→ `recordIslandHeightReport(tableId)`（`:281`，I3 的可断言计数面）→ `onIslandHeightRef.current(height)`（`:282`，经 ref 转发，宿主每帧传新函数引用**不重建 RO**）→ 引擎侧 `applyHeightProtocol` / `onIslandHeight` 写 `hm.setHeight(startLine, islandH)` + `virtualizer.resizeItem(startLine, islandH)`（`useTableIslandWiring.ts:196,229-231`）；区间内部行 `[startLine+1, endLine]` 一律置 0（`useTableIslandWiring.ts:174-184` 的 `zeroInternalRows`，零高先例 E13；`hm.setHeight` 内置 0.5px 护栏，已为 0 时**零写入**且不触碰 virtualizer）。
- **行级 RO 的边界（已落地，I3 的守卫）**：`TableBlock.tsx:309-328` 的**第二个** RO 观察窗口内已挂载行，**只**把实测行高写进岛内 `RowTopIndex`（`index.setHeight(lineIndex - startLine, h)`，`:320`），仅在真的变化（`setHeight` 返回 true）时递增 `rowEpoch` 触发窗口重算（`:322`）——**绝不**写 `HeightMap` / `virtualizer`。故「岛内共两个 RO 实例」但「高度上报源唯一」= 岛根 RO（`tests/unit/table-island-wiring.test.ts`「岛高上报来自岛根（唯一源），稳定后不再增长」）。
- **与 `syncTo` 的次序（已落地）**：`syncTo` 只填新增行预测高（E14），会把新追加的表内行填成非 0 → 高度协议必须在同一 effect 内、`syncTo` **之后**重写「岛宿主行 = 整表高度、内部行 = 0」。调用点 `MarkdownEngine.tsx:1827`（`applyHeightProtocol(virtualizer.getVirtualItems())`），紧接 `hm.syncTo(...)`（`:1818-1823`）之后。`applyHeightProtocol` 以 `isTableIslandEnabled()` 为门（`useTableIslandWiring.ts:188`），开关关闭时空操作。
- **岛高取值的两级（已落地）**：岛宿主行高度 = **实测优先**（`islandHeightsRef`，岛上报后写入，`useTableIslandWiring.ts:194,230`）否则 **`Σ predict` 初值**（`estimateIslandHeight`，`:163-170`）。`estimateSize` 侧同源（`:204-214` 的 `estimateSizeAt`：宿主行 → 已落库高度 / 初值估算；内部行 → 0；非表格行 → `null` 回落既有 `HeightMap` 直查，`MarkdownEngine.tsx:922-926`）。
- **初始岛高用 `Σ predict` 而非 0（已落地，如实登记理由）**：`estimateIslandHeight` = `Σ_{i=startLine..endLine} estimateRowHeight(i)`，下限 `ISLAND_MIN_HEIGHT`（= 28，`useTableIslandWiring.ts:84`）兜底（`:163-170`）。**不用 0 的理由**：若初值取 0，整表会在首帧先**塌陷**、待岛实测上报后再**跳变**——视口内容出现一次可见位移；`Σ predict` 让初值即接近真值，跳变量被压到「估算误差」量级（且估算已按**真实列宽**逐列 wrap，见下条）。
- **滚动锚定复用（已落地）**：岛高变化若发生在视口顶线之上（`item.start + oldH ≤ scrollTop` 且非 `follow` 态），走与批量循环同一锚定语义——原子补偿 `scrollTop`（`useTableIslandWiring.ts:234-247`），使阅读视口内内容绝对静止，否则流式追加大表会跳。
- **对测量纪律的显式例外**：`MarkdownEngine.tsx:1130-1151`（E16）规定「批量测量协议独占、RO 只回缓存值」；ADR-5 允许表格岛自测量。该例外已登记于 `00-调度与执行纪律.md` §7，本维再次确认并落断言（§8 A5）。
- **防两个测量源打架（四道闸，已落地）**：① 批量测量循环**显式跳过**岛宿主行——`if (islandWiring.hostAt(item.index)) continue;`（`MarkdownEngine.tsx:1835`）；**与原文的差异**：不再依赖「区间内部行不成项」这一间接保证（折叠仍在，`:2517-2521`），改为直接判定，更抗回归；`hostAt` 以 `isTableIslandEnabled()` 为门（`useTableIslandWiring.ts:126`），开关关闭时恒 `null`、跳过不生效。② 岛区间内**只有** `onIslandHeight` 一个写者，写入前校验区间归属（`useTableIslandWiring.ts:225-226`：`!range || range.startLine !== startLine` 即返回，**不抛异常**——原文「开发期直接抛」未采用，理由：上报来自 RO 异步回调，抛错会打断测量链）。③ 上报走 `STABLE_EPSILON`（E15）同款阈值护栏（`TableBlock.tsx:279` + `hm.setHeight` 内置护栏），终止「测量→上报→重排」回环。④ **原文「岛只在列宽已冻结前提下上报」未作为显式闸门落地**：岛根 RO 持续观察，列宽定型后内容重排会再触发一次上报（经 `STABLE_EPSILON` 收敛）；「列宽 → 布局 → 岛根 RO → `resizeItem`」这条**自闭环**已足够保证确定性（见 §3.7），无需额外门。
- **oracle 降级为初值估算（已落地）**：`HeightMap.predict` 表格分支（E7）不再承担逐行真值，仅提供**行高估算**与**岛高初值**。落地：`estimateRowHeight`（`useTableIslandWiring.ts:149-161`）对分隔行返回 0，其余行调 `oracle.predict(kind, raw, st, tableColWidthsAtLine(s.getLine, lineIndex))`——即 `predict` 已增加「**真实列宽**」入参（T4a 落地，`MarkdownEngine.tsx:1822` 同款调用），替代 E7 的 `containerWidth/cols` 估算。**与原文的差异**：初值**不含独立的 `+ headerH` 项**——表头行本身就在 `[startLine, endLine]` 区间内，`Σ predict` 已含它（`useTableIslandWiring.ts:166`）。E8 的常量漂移由「正确性缺陷」降级为「估算误差」，但**仍需**保持与 CSS 同步（注释义务不变）。

### 3.7 测量时序契约与失效传播

**每 epoch 严格次序**（同帧、不可交换）：

```
① 失效源：内容变化 / 容器宽变化 / 活动行变化 → epoch++
② 列宽：探针一次测量（内容 epoch）或分配器一次求解（容器 epoch）→ 写 --table-cols + TableStore
③ 高度：同帧读 island.offsetHeight（强制 reflow 一次）→ 上报唯一高度 → 内部行置 0
④ 岛内行高采样：仅更新岛内 Map 与哨兵（用于窗口化），不改变已上报岛高；下次上报时并入
```

**落地形态（T4，逐条对照）**：① 失效源分两类——**内容 epoch**（`probeSignature`，代表文本真变）与**容器宽 epoch**（`clientWidth` 变），二者在 `TableBlock.tsx:235-267` 的同一 `useLayoutEffect` 内判定（见 §3.5）；② 列宽载体为**行容器内联 `grid-template-columns`**（非 `--table-cols`，§3.4），写 `TableStore.setTableWidths` + `recordTableWidthSettle`（`MarkdownEngine.tsx:1111-1114`）；③ 高度**不是同帧强读 `offsetHeight`**——改由岛根 RO 的 `contentRect.height` 异步触发（`TableBlock.tsx:298-303`），**无强制 reflow 读取**（这是相对原文的改进：RO 读的是已提交的布局尺寸）；内部行置 0 与宿主行写入同处一次 `applyHeightProtocol`（`useTableIslandWiring.ts:186-201`）；④ 岛内行高采样只更新 `RowTopIndex` 与哨兵（`TableBlock.tsx:320-322`），不改变已上报岛高——下次岛根 RO 触发时自然并入（无显式合并步骤）。

- **禁止（已落地为结构性排除）**：同一趟里先测高后定型（E9）——岛路径下引擎侧定型已整体让位（`:1918`），**不存在**「先测高后定型」的同趟次序；「定型后不重测」（E10 的后果）——岛路径不依赖批量 effect 的依赖数组，列宽经岛根 RO **自闭环**传播（见下条）。
- **失效传播图**（谁变触发谁）：

| 失效源 | 触发 | 后果 |
|---|---|---|
| 容器宽变化 | ② 分配器 | ③ 岛高重报（RO 自然触发） |
| 内容变化（编辑/流式追加） | ② 探针重测 | ③ 岛高重报 |
| 活动行变化（分隔行 0↔28px，`index.css:441-460`） | 岛内 DOM 变化 | ③ 岛高重报——**旧路径下该高度变化与逐行预测打架，这是 ADR-5 的自然收益** |
| 岛高变化 | `resizeItem(startLine)` | 外层窗口重算（O(1)），**不再回头改列宽** |

- **消除「定型后不重测」（已落地，ADR-4 的真实收益，写清）**：岛路径下**引擎侧列宽定型整体让位**——`MarkdownEngine.tsx:1918` 在批量测量 effect 内以 `if (isTableIslandEnabled()) return;` 直接短路整段 `scrollWidth` 定型逻辑（含非流式闭合定型与流式 W1-3 结构定型锁宽**两条分支**，短路范围 = 该 `try` 块 `:1919-2124`，`catch` 在 `:2125`）。列宽改由**岛内离屏探针一次测量**定义（§3.5），探针测的是**固有宽**（`max-content`，与当前列宽无关）。
  - **为什么这是 ADR-4 的真实收益**：A4 的顾虑是「分隔行到达前不锁宽，避免把表头宽锁死」。在 `scrollWidth` 口径下，早期锁宽会把「按当时窄列**换行后**的内容宽」写成列宽真源 → 锁死且难恢复（自增强收缩，D4 的循环依赖）。在**探针口径**下，测的是固有宽（不随列宽变化）⇒ **早期锁宽也不再锁死表头宽**，A4 的顾虑**自然消失**。故岛路径**无需**「何时定型」的时序博弈（无需区分候选态/闭合态、无需 grow-only 单调修正），一个纯函数 `(intrinsic, available) → widths` 即可（§3.5）。
  - **自闭环传播**：`tableWidths` 变化 → 岛内 `grid-template-columns` 变化 → 岛内容布局变化 → 岛根 RO 触发 → `resizeItem(startLine)`。**不依赖任何 React 依赖数组**——原文担心的 `MarkdownEngine.tsx:2201-2210` 依赖数组缺 `tableWidths` 对表格路径**失效**（岛路径不再经该 effect 回填表格高度）。
  - **开关关闭时**：`:1918` 守卫不生效，旧路径与旧依赖数组**逐字保留**（E9/E10 的现状行为不变，A10 零回归）。
