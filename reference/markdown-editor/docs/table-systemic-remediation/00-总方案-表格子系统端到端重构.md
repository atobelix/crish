## 3. 根因诊断

### 3.1 单一根因

> **表格在本编辑器里不是一个「块（block）」，而是 N 个互不相识的虚拟行。**

全仓不存在表格聚合节点、不存在表格容器 DOM、不存在表格布局所有者。表格的一切语义——表头、列宽、列对齐、选区、横向滚动、导出——**都在「行」这一层被反复重新推导**。

实证（三条 grep 级事实）：

| 事实 | 证据 |
|---|---|
| AST 无表格聚合节点，只有 `table_row` / `table_separator` 行类型 | `src/core/ast.ts:13-14,51-52,78-97`（`LineNode` 仅 `type/raw/inlineTokens/localOffset/length`） |
| 组件层无 `<table>/<thead>/<colgroup>/table-layout` 任何一处 | `grep -rn "<table\|<thead\|<colgroup\|table-layout" src/` → **0 命中**（唯一命中是 `parser.ts:1534` 的注释） |
| 每一行都是独立的横向滚动容器 | `src/index.css:379-391`（`.line-table{overflow-x:auto}`），`BlockRenderer.tsx:1504-1530,1595-1621`（`scrollLeft` 经 zustand + rAF 手工跨行同步） |

### 3.2 派生断层 D1–D8（症状 ↔ 断层 ↔ 证据）

| 断层 | 内容 | 直接症状 | 证据 |

## 5. 架构决策（ADR）

> 每条含「决策 / 理由 / 被否决的替代 / 代价」。**实现期禁止回退到被否决路径。**

### ADR-1　引入 `TableModel` 聚合视图（派生，不改行式虚拟化主干）

- **决策**：新增 `src/core/tableModel.ts`，由「表格行区间 + 分隔行」派生出 `TableModel { id, startLine, endLine, hasHeader, cols, rows: Cell[][], alignments, spans }`。它是**派生视图**，不是 AST 替换。
- **理由**：编辑器的行式虚拟化（`HeightMap` + 每行一个虚拟项）是整个性能体系的基石，**不动**。表格语义集中到 TableModel 一处推导，消灭 D2/D3/D8 的「反复重新推导」。
- **被否决**：把 parser 改成产出 `TableNode` 并替换行类型——会波及 `EditorStore` 增量、装饰映射、区间索引、全部行级测试，爆炸半径过大且与「先定方案避免崩溃」冲突。
- **代价**：TableModel 需要缓存 + 失效策略（表格区间变化时重建）。
  > **事实更正（2026-09-14，裁决 R1）**：本 ADR 初稿称「由 `BlockIntervalTree` 已有的 `'table'` 区间能力承接」——**该能力不存在**。实测：`BlockIntervalTree.buildFromLines` 只产 `code_block`/`callout`/`blockquote`（`BlockIntervalTree.ts:94-103,133-142,152-161`），且该类在 `src/` 内**零实例化**（`new BlockIntervalTree(` 仅出现于 `tests/unit/block-interval-tree.test.ts:11`；引擎实际用的是 `MarkdownEngine.tsx:37-66` 的另一套）。
  > **更正后的落法**：TableModel 用 `src/core/tableModel.ts` 的**模块级缓存**（按表起始行 + 内容代际失效），**不触碰** `BlockIntervalTree.ts`。该文件亦不在 §8 文件域表内，任何 Agent 不得顺手改造它。

### ADR-2　表格渲染改为单容器「表格岛」

- **决策**：新增 `src/components/TableBlock.tsx`：整表**一个容器 DOM**，唯一持有 `overflow-x`；表头 `position: sticky`；岛内自行做**行窗口化**（仅当行数超过阈值时启用）。
- **理由**：一次性消灭 D1（N 个滚动所有者）、S1、S2；为 D7 提供「一个矩形」的绘制坐标系；为 ADR-5 提供「一个高度」的测量对象。
- **被否决**：
  - 保留 per-row 滚动容器、只把 `scrollLeft` 同步改成 CSS 变量——仍是 N 个滚动所有者，D1 未除。
  - 直接换用原生 `<table>` 元素——原生表格布局不可按行虚拟化，会与行式虚拟化正面冲突，引入新的高度塌陷。
  - 用 `table-layout:auto` 让浏览器定列宽——列宽随视口变化，与「列宽一次定型」契约冲突，流式下会反复 reflow。
  - 整表做成单一虚拟项且**不做事内窗口化**——万行压测（18,800 行）与超长表格会退化为一次性全渲染。
- **代价**：外层虚拟化需把「表格岛」当作**一个虚拟项**（高度 = 岛自报高度），与现有「一行一虚拟项」模型有一处显式特例，需在 `HeightMap` / `MarkdownEngine` 中登记并加断言。

### ADR-3　表格身份稳定化

- **决策**：`TableModel.id` 不再由「首行行号」推导，改为**稳定块身份**（由 `EditorStore` 在编辑操作中重映射的行区间身份）。`TableStore` 的 `tableWidths/tableAlignments/tableScrollLeft/selectedCell` 全部改挂该身份。**过渡期自愈**：读取时校验「存储列数 == 当前列数」，不符即丢弃并重算。
- **理由**：根除 D2/D3（S7）。
- **被否决**：用「分隔行内容哈希」当身份——编辑分隔行即换身份，不稳定。
- **代价**：需在 `EditorStore` 引入一处「块身份映射」，与现有编辑操作（splice / applyTableChange / 整文替换）逐一接线，并加不变量测试。

### ADR-4　列宽真源唯一化

- **决策**：列宽由**表格岛内一次测量**产生（基于真实布局的 `max-content` 测量 → 写入该表的 `<col>` 宽度），取消 `InlineRenderer` 的 per-cell `flex:0 0 Npx` 与 `minWidth:100px; flex:1 0 auto` 兜底。
- **理由**：根除 D4（循环依赖）与「列宽随帧变化」（S7）；使列宽成为**单一真源**，高度测量只需读它。
- **被否决**：继续用「逐单元格 `scrollWidth` 取 max」——测量对象是「单元格自身」，会受内容换行反噬（`scrollWidth` 在换行后不再等于内容固有宽）。
- **代价**：需要一次**离屏/受控测量**（在岛内用 `max-content` 的测量行一次性求各列固有宽），并在流式场景下与 `docs/analysis/plan-A4-表格流式.md` 的「候选态 + 闭合定型一次修正」决策合流（**不冲突**：A4 定的是「何时定型」，本 ADR 定的是「怎么算」）。

### ADR-5　高度真源：表格岛自测量（单测量源纪律的显式例外）

- **决策**：表格岛以自身 `offsetHeight` 上报**一个**高度；`HeightOracle` 的表格分支从「逐行预测」降级为「岛高度初值估算」，不再承担逐行真值。
- **理由**：根除 D5/D6（S8/S4）。
- **被否决**：继续逐行预测 + 可见行回填——只要列宽会变，逐行预测必然失配。
- **代价**：这是对现有「批量测量协议独占、RO 只回缓存值」纪律（`MarkdownEngine.tsx:1130-1151`）的**显式例外**，必须在 `08-分维` 与测量纪律文档中登记，并加「同一表格只有一个测量所有者」的断言，防止两个测量源打架。

### ADR-6　选区改为表内单矩形覆盖层

- **决策**：选区改为**表格岛内绝对定位的单矩形**，几何由「4 个角单元格相对岛容器的 `getBoundingClientRect`」求得；选区身份改为**表内相对坐标 `(rowIndex, colIndex)`**；增删行列时按规则**重映射**。
- **理由**：根除 D7（S3）；同时修掉 `SelectionHighlight` 缺布局依赖（`SelectionHighlight.tsx:372`）与 `LINE_HEIGHT=28` 硬编码（`:240`）对表格的误用。
- **被否决**：保留逐格 `inset box-shadow` 拼边——跨虚拟行窗口时上/下边会画在错误的行上，范式上不可能正确。
- **代价**：跨出可见窗口的选区需要**截断 + 越界指示**语义（规格见 `05-分维`）。
  > **代价补充（2026-09-14，裁决 R17）**：当角单元格**未挂载**（岛内行窗口化，ADR-2）时，`getBoundingClientRect` 不可用。此时几何由「**已定型列宽 + 行高缓存前缀和**」求得（列宽与行高都已是真源，故仍满足 I6 的 ≤1px 容差）。该补充规格详见 `05-分维` §3.4。

### ADR-7　导出与编辑共享语义模型

- **决策**：`renderToHtml` 的表格分支改为消费 `TableModel`，输出合法 `<table><thead><tbody>` 结构。
- **理由**：根除 D8（S11）。
- **被否决**：编辑器也改输出字符串——React 组件渲染与字符串投影无法真正合并，强行统一会牺牲渲染层能力。
- **代价**：`tests/commonmark` 的投影器与 `src/core/renderToHtml.ts` 的关系需明确（见 `07-分维`，本文件不展开）。

### ADR-8　交互范式：hover 就近图标工具条 + 边缘 affordance

- **决策**：删除现有 640px 宽文字工具条的形态；改为 ① hover 单元格就近浮现的**图标工具条**（按上下文裁剪动作集）② 表格边缘 **affordance**（列上缘 `-`、右缘 `+`、行左缘拖拽手柄 + `+`/`-`）③ 全部结构操作补键盘快捷键。
- **理由**：直接落实 L2/L3/L4。
- **被否决**：只把现有工具条的文案换成图标——形态仍是「选中后出现、远离鼠标、固定 640px」，L3 未满足。
- **代价**：工具条定位需从「相对选中单元格」改为「相对 hover 单元格」，并与滚动/缩放联动；`TableToolbar.tsx:23-63` 的硬编码 640px 夹取逻辑需重写。

4. **测试资产只增不减**：`tests/unit/table-*.test.ts`、`tests/perf/suite/scenarios/table-stream.mjs`、`scripts/verify-physical-measure.mjs` 的表格场景**不得删除或弱化**；新增断言必须真跑真绿（**禁止 `--no-verify`、禁止骗 CI**）。

### 13.6 T4b 落地裁决（2026-09-14，主控）

> 本节记录 T4b 执行期由主控裁决、**改变了分维文档「本维默认取法」**的项。权威性同 §13.1。

| # | 事项 | 裁决 | 理由（逻辑） |
|---|---|---|---|
| R19 | U-T3-1（表头 sticky 语义） | **取「表头随表横滚」**（岛内同轨普通栅格行，**不加** `position: sticky`） | 岛是 `overflow-x:auto; overflow-y:hidden` 的滚动容器，岛自身不纵向滚动 ⇒ 岛内 `sticky top:0` 物理上无效；表头与正文同轨 ⇒ 横向天然同步（F-Lay-1 满足）。文档级纵向吸顶需把表头移出滚动容器 + 单点 `scrollLeft` 写入，**登记为 T6 的 affordance 定位前置**，不在 B 期做 |
| R20 | U-T3-2（表格窄于内容列） | **末列吸收余量**（`buildGridTemplate(w, true)` → `minmax(<w>px, 1fr)`） | 岛轨 `min-width:100%` 而列宽之和不足时，余量必须由末列吸收，否则右侧留空白条（症状 S2「多出空列」的根因）。缺省参数 `false` 保持纯 px 输出（既有单测口径不变） |
| R21 | 岛内 Fenwick 的归属与形态 | **下沉 `src/core/tableIsland.ts` 的 `RowTopIndex`**，且以「Float64Array 前缀表 + 脏标记 + 一次 O(n) 重算」**取代** Fenwick | ① 下沉 core 才可单测（原 §3.3 要求私有于 `TableBlock.tsx`，与「可测」冲突，按本仓测试资产纪律取可测）；② 点更新只来自岛内**已挂载行**的 RO（量级 ≤ 窗口行数），重建 1 万行 ≈ 10µs ⇒ Fenwick 是过度设计 |
| R22 | 列宽定型的唯一写者 | **岛路径下引擎侧 `scrollWidth` 定型整体让位**（`if (isTableIslandEnabled()) return;`） | 同一张表两个列宽写者 = I2 震荡的直接来源。探针测的是**固有宽**（与当前列宽无关）⇒ ADR-4 下「提前锁宽会锁死表头宽」的顾虑**自然消失**，A4 的「分隔行到达前不锁宽」在岛路径不再需要 |
| R23 | 岛高初值 | **岛宿主行初值 = `Σ predict(row)`**（而非 0） | 若初值为 0，整表先塌陷、RO 上报后再跳变（可见抖动）；`Σ predict` 在 T4a 后已按真实列宽估算，误差小 ⇒ 一次平滑修正。内部行仍一律 0（单一高度源 = 宿主行） |
| R24 | 区间折叠与**窗口注入** | `collapse` 除折叠内部行外，**必须注入宿主行**（窗口落在表内部时宿主行不在候选内） | 否则视口进入长表内部时没有任何虚拟项 → **整表消失**（空白）。此为实现期发现的正确性缺陷，非可选优化 |
| R25 | 与折叠区间相交的表 | **不参与岛渲染**（回落旧路径逐行渲染） | 折叠占位行与岛内窗口化会互相遮蔽（折叠把区间内行置 0 高，而岛自行窗口化并自报高度）；两者语义冲突，回落是唯一无歧义解 |
