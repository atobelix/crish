## 1. 角色与派发

| 角色 | 权限 | 说明 |
|---|---|---|
| 主控 Agent | 唯一可派发子 Agent、唯一可提交 git、唯一可更新 §5 续航锚点 | 本战役所有收口由其执行 |
| 子 Agent（深度 1） | 只执行分配的任务单元；**无派发能力**；**无提交能力** | 工具面已由引擎剔除嵌套派发能力 |

- **每轮派发 5–12 个**子 Agent；任意时刻同时存活 ≤16、同父 ≤16、深度仅 1。方案最终收尾阶段可不保底。
- 派单必须写明：任务单元号（T0–T8）、输入文档、产出文件路径、验收断言、**文件域冲突注意事项**（见 `00-总方案` §8）。
- **执行环境**：子 Agent 统一使用 **pwsh7（PowerShell 7+）**；写文件 **UTF-8 无 BOM**。
- **命令等待纪律**：命令过长时**等待系统推送通知（Reactive Wakeup）**，不要轮询；确需定时器最短 **100 秒**。
- **空返回处理**：子 Agent 空返回**默认是供应商网络问题而非任务失败**——先核查文件是否已落盘、`git status` 是否被并行 Agent 误伤。按空回累计分级：1–3 次 → 用 `task_id` 接续原会话；4–6 次 → 拆分或换新 Agent（单文档/单文件粒度成功率更高），**总任务量不变**；6 次以上才由主 Agent 接管实现。

## 2. Git 纪律（多 Agent 共享仓库，零容忍）

1. **提交权仅归主 Agent**。子 Agent 完成后把改动**留在工作区**，由主 Agent 验证后统一提交。
2. **子 Agent 严禁**：`git commit`、`git reset --hard`、`git checkout .`、`git restore`、`git rebase`、`git stash`。
3. **主 Agent 提交必须限定路径**：`git commit --only <paths...>`，避免误提交并行 Agent 的 staged / 工作区文件。
4. **严禁回撤**：不得覆盖他人已提交或未提交的改动。改错自己的文件 → 用**精确 edit** 修复，不用全局回撤。
5. **被吞并处理**：若待收口改动已被其他 Agent / 定时 git Agent 提交，**只验证内容完整性**（`git show HEAD:<path>` 对比）；完整则不管归属，缺失则追加。**禁止因归属不纯而回退重做**。
6. **hook 阻塞**：`.husky/pre-commit` 的 `git diff --check` 检查**整个工作区**——他人文件的 trailing whitespace 会阻塞提交；对该行做**最小 whitespace 修复**解除阻塞（不碰内容），或上报主控。
7. **禁止 `--no-verify`、禁止绕过门禁、禁止骗 CI**。lint-staged 报错必须修复后重提。
8. 提交信息遵循仓库风格：`feat|fix|refactor|test|docs|chore(<scope>): <描述> BATCH-<批次>`。本战役 scope 建议统一为 `table`。
9. **注意**：本战役工作区位于 `reference/markdown-editor/`，而 git 仓库根是 `C:\Software\conex`（`.gitignore:81-82` 显式解除了 `reference/markdown-editor/**` 的忽略）。提交路径必须写**相对仓库根**的完整路径（如 `reference/markdown-editor/src/core/tableModel.ts`）。
10. **每批提交（用户裁决 L11，2026-09-14）**：「改完一批代码就 git 提交，不然代码都堆一起了」——**每个任务单元收口即提交**（或在同一波次内按逻辑批次分批提交），禁止长期堆积未提交改动。提交粒度要求：**一个任务单元 = 一个可独立 revert 的提交集合**；A 期与 B 期的改动**不得混在同一提交**（`00-总方案` §9.2 规则 3）。
    - 提交前必须门禁全绿：`npm run check:gate && npm run test:gate`。
    - 提交信息带批次标记：`<type>(table): <描述> BATCH-T<N>`。

## 3. 反退避与反过度设计（本战役细则）

### 3.1 反退避

- **效果锁**：`00-总方案` §1 的 L1–L6 不得降级为「简化版 / MVP 砍功能」。冲突只能标出并请示，Agent 无权改目标。
- **纯逻辑规划**：方案只谈逻辑依赖、任务单元、文件域、验收断言；**不谈工期、人天、人员安排**。用户未要求排序时**问题同权**，禁止用 P0/P1 业务优先级砍项。
- **禁止退避裁判**：不得以时间、重要性、方案成熟度、生态流行度、「做不到/太难」否决路径。不确定 → **设计验证**（测试 / 视觉对齐 / 魔鬼用例），禁止把不确定写成不可能。
- **路径合法排序键**：效果完整度 → 正确性/不变量 → 可验证性 → 与已锁定契约一致 → 结构干净。**流行栈安全感不是主裁判**。
- **验证资产**：视觉强制对齐 + 防回归测试是一等公民；测试不可丢。

### 3.2 反过度设计（`ANTI_OVERENGINEERING_GUARDRAILS.md`）

本战役明确**禁止**引入：

- 表格专用虚拟化框架 / 第三方表格库（TanStack Table、AG Grid 等）；
- 表格 CRDT / 协同编辑；
- 表格公式引擎、排序持久化到源码的复杂策略；
- 通用「布局引擎抽象层」——只需 `TableModel` 一个具体模型；
- 为「未来可能」预留的表格插件系统。

**允许且鼓励**：`TableModel` 纯函数化（可单测）、单容器岛 + 岛内窗口化、`<col>` 驱动的列宽。

## 4. 门禁与验证纪律（立体验证，禁止单一检查冒充验收）

任何任务单元在宣称完成前必须履行：

| 层 | 要求 | 命令 |
|---|---|---|
| 静态 | 类型检查 + lint | `npm run check:gate` |
| 契约（表格） | 表格不变量棘轮（10 指标，只允许单向收紧） | `npm run check:table` |
| 契约（行数） | 代码文件行数门禁（14 类策略 + 例外名单棘轮） | `npm run check:length` |
| 单元 | 表格相关单测全绿 | `npm run test` |
| 契约 | 设计 token / SSOT 门禁 + 本战役新增不变量门禁 | `npm run test:gate` |
| 性能 | 表格场景预算不劣化 | `npm run test:perf` |
| 物理 | 真实宿主端到端（非 Mock） | `npm run test:measure` |
| 视觉 | 与 `02-分维` 参考帧逐项对齐（截图 + 几何断言） | `scripts/verify-physical-measure.mjs` 表格场景 |
| e2e | 交互矩阵 | `npx playwright test tests/e2e/*table*.spec.ts` |

**代码行数门禁（用户裁决 L10，2026-09-14）**：

- **按类型分策略**（`scripts/check-file-length.mjs` 的 `POLICIES`，14 类）：`src/core` 600 / `src/components` 600 / `src` 壳层 600 / 样式 800 / 门禁脚本 450 / 验收 harness 1200 / 单测 700 / 契约测试 500 / e2e 700 / 性能套件 1000。
- **三档判定**：合规（`≤ limit`）/ **警告**（`limit < lines ≤ limit × 1.3`，**只提示不失败**，落实「超限 30% 以内可以不强制改」）/ **违规**（`> limit × 1.3`，`exit 1`）。
- **违规处置二选一**：**拆分文件**；或（确有必要时）**显式登记进 `PROTECTED` 例外名单**并写明 `reason`。
- **例外名单是源码内手写常量**（不是外部 JSON）——新增例外必须是一次**可 review 的代码改动**，杜绝静默把膨胀文件加白名单。
- **棘轮**：例外文件的 `ceiling` **只允许收紧**（`--freeze` 只降不升）；例外文件同样**不许继续长大**。
- **直接后果**：`src/core/TableOperations.ts`（832 行，已在例外名单且 ceiling 冻结）**不允许增长** → T6 若要新增「行列重排 / 表头开关 / 排序 / CSV 粘贴」，**必须先拆分模块**（例如按「结构操作 / 文本变换 / 查询」拆为 `src/core/table/` 下的多文件），不得直接往原文件里加。

**硬性**：

- 编译/类型检查通过**仅是底线**，不得作为交付的唯一依据。
- 必须在**真实宿主与执行上下文**中检验端到端物理表现，确保运行时零未捕获异常与非预期告警；**禁止仅在脱水 Mock 中自欺欺人**。
- 修复后不得凭猜测宣称「应该没问题了」，必须有确凿测试与现场证据。
- **禁止补丁式实现**：不得使用盲目遍历循环、坐标测距魔术数字补偿、临时兼容代码。必须穿透表象找架构断层，用原生、精确、O(1) 方式解决（优先通过原生 `data-*` 属性建立 DOM 节点与源码 token 的无损映射）。

## 6. 禁止的半成品状态（落实用户「避免做一半崩溃」）

以下状态**严禁**出现在任何一次提交或交接中：

1. 新模型已建但调用点只改了一半（编译通过但运行时双源并存）；
2. 特性开关已打开但验收矩阵未全绿；
3. 旧路径已删但新路径未接管；
4. 测试被临时注释 / `skip` / 弱化以让门禁通过；
5. 文档描述的架构与代码实际架构不一致（文档先行但未回写实现偏差）；
6. 留下「TODO 待接」的空实现（如 `ContextMenu.tsx:134-137` 那类 stub）而不登记到本战役的未决问题表。
