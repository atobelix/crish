## 3. 表格重构对性能预算的影响分析（核心）

### 3.1 表格岛成为单一虚拟项（ADR-2）

设文档行数 `L`、第 `t` 张表行数 `R_t`（含分隔行）、表数 `T`，则外层虚拟项数由 `L` 变为 `I = L − Σ(R_t − 1)`。逐指标量化：

| 指标 | 方向 | 机制 | 守住的断言 |
|---|---|---|---|
| 虚拟项数 `count` | **↓**（`L → I`） | `useVirtualizer({count})`（`MarkdownEngine.tsx:1036`） | 报告项：`I == L − Σ(R_t−1)`；岛虚拟项计数 `== T`（每表恰 1） |
| 单 item 高度 | **↑**（≈`R_t × 行高`） | `estimateSize` 对岛返回岛自报高度（`MarkdownEngine.tsx:1038-1067`） | 岛 item 高度 `== 岛内行高之和 ±1px`（F-Lay-3，`02-分维:100`） |
| `resizeItem` 调用次数 | **↓**（每表 `O(R)→O(1)`） | 现状逐可见行 `resizeItem`（`:1932,1949`） | 每次定型 `resizeItem ≤ 岛数`；不得回升到逐行 |
| `HeightMap` 前缀和成本 | **持平**（同阶） | 岛回填 = 块内 `O(BLOCK_SIZE)` + `flush O(块数)`（`HeightMap.ts:415-443`） | `setHeight` 单次成本 ≤ 现状；`flush` 每帧 ≤1 次 |
| **逻辑总高守恒** | **不变** | 岛高 == 原 `Σ 行高`（含分隔行 0，`HeightMap.ts:230`） | 逻辑总高偏差 ≤1px；`scrollHeightErrorPct ≤1%`（M2b，`budgets` 档） |
| `scrollMap.enabled` | **不变** | 阈值只依赖逻辑总高（`scrollMap.ts:34-36`） | 岛前后 `enabled` 同值；30M px 分界行为不变 |
| `overscan` 语义 | **漂移（风险）** | `overscan:40` 是 **item 粒度**（`MarkdownEngine.tsx:1068`）；岛内像素高，40 item 不再等于 40 行 | 岛进出视口时单帧挂载节点上限断言（见 §4） |

**口径要点**：item 数下降是账面收益，但**单 item 像素跨度上升**把风险从「每帧 item 数」转移到「岛进出视口那一帧的 DOM 量」——这是 R1（`00-总方案:390`）的性能实体，必须由岛内窗口化 + 单帧节点上限断言承接，不能只看 `count`。

### 3.2 表格岛自测量（ADR-5）

- **RO 上报频率**：RO 只在岛盒尺寸变化时回调（`ResizeObserver` 语义），稳态（无内容/列宽变化）应为 **0 次**；流式每内容变更帧 **≤1 次**（同帧合并）。目标口径：`岛高度上报次数 / 表 / 定型周期 ≤ 2`，空闲滚动 `== 0`。
- **与批量测量协议的边界**：现状纪律是「RO 只回缓存值、逐行测量由批量 effect 独占」（`MarkdownEngine.tsx:1130-1151`）。ADR-5 是**显式例外**（`00-总方案:151-156`），边界必须硬化为：**岛覆盖的行区间从批量 effect 的逐行回填循环中排除**（`:1913-1956` 的 `getVirtualItems()` 迭代跳过岛 item），否则同一表出现两个测量源（R2，`00-总方案:391`）。
- **避免布局抖动**：岛自测量只读 `offsetHeight`（在 RO 回调内，此时布局已结算，不触发强制同步布局）；**严禁**在写 DOM（如写 `<col>` 宽度）之后同帧再读几何。目标口径：`layoutThrash` 计数在「纯滚动」与「流式注入」两场景下 **delta == 0**（哨兵见 `metrics.ts:289-291`）。

### 3.3 列宽一次测量（ADR-4）

- **测量成本**：现状逐可见行逐 cell 读 `scrollWidth`（`:2078-2083,2183-2188`），成本 `O(R_可见 × C)` 次强制布局读；ADR-4 的「岛内一次 `max-content` 受控测量」为 `O(C)` 次宽读 + **1 次**布局读。成本方向 **↓**（`R_可见` 倍）。
- **「定型一次」的 reflow 预算**：一次 `setTableWidths` → 写 `<col>` → 1 次 reflow。A4 已定「闭合定型一次修正 = 单次 reflow」（`plan-A4:49-55`）；ADR-4 只替换「怎么算」，不改「何时算」，故 reflow 次数不增加。
- **`perTableSettles ≤ 2` 仍成立的论证**：路径互斥且各计 1 —— ① 流式期结构定型锁宽 / grow-only 估算 = 1（`MarkdownEngine.tsx:2094-2113`，S-EL-04，`streaming-render/00:19`）；② 闭合（或非流式）岛精确测量 = 1（替代 `:2190-2194`）。合计 `≤2`，与 `budgets.mjs:166` 一致。**禁止**岛在流式期逐帧重测列宽（会使计数突破 2）。
- **与 M6b 的张力（新增风险，见 §6 R8）**：离屏 `max-content` 测量自身读几何 → 计入 `LayoutCount`。必须单次读写分离并断言 `ratio ≤ 2` 且**相对现状不升**。

### 3.4 岛内行窗口化（ADR-2）

- **窗口计算成本**：行高均匀时 `O(1)`（`floor(岛内偏移/行高)`）；单元格换行 / `<br>` 使行高可变（`HeightMap.ts:257-266` 已建模）→ 需岛内行偏移数组 + 二分 `O(log R)`。目标：窗口重算每帧 **≤1 次**，单次耗时 ≤0.2ms（报告项）。
- **窗口切换 DOM 重建成本**：平移 `k` 行 → 挂载 `k × C` 单元格 + 卸载旧行。目标：**存量行节点身份不变**（对齐 M4 口径 `budgets.mjs:137`、`README.md:71`），单帧新增节点 `≤ k × C + slack`。
- **超长表格（18,800 行场景）**：`18,800` = 基线素材 188 行 × 100（`docManifest.ts:118`）；素材库单表最长 **13 行**（`03-complex-tables.md` 实测），`doc03` 40× ≈ 11,520 行 / 约 40 张表（`docManifest.ts:85`）。故岛必须同时满足：① 篇内**多张小表**不膨胀（岛数 `== T`，岛间不共享 DOM）；② **假想万行单表**不退化——岛内挂载行数 `≤ W_max`（与 `R` **无关**），总节点数 `≤ 基线 + T × W_max × C`。

## 5. 流式合流设计（与 A4 严格对接）

### 5.1 A4 已定结论（逐条复述，不改）

| A4 结论 | 出处 | 本战役立场 |
|---|---|---|
| ① 候选态预分类（方案 B）：pipe 行即渲染为候选行；分隔行到达升级为正式；空行/非 pipe 回退 body | `plan-A4:18-38` | **完全承接**，不改判定时机 |
| ② 列宽「估算 + 闭合定型一次修正」（方案 C）：流式中估算，闭合（内容不再变）时一次精确测量 → 单 reflow | `plan-A4:42-56` | **完全承接**；ADR-4 只补「怎么算」 |
| ③ 确认瞬间零跳变：`oldEl === newEl`；列宽定型 reflow 计数 ≤1 | `plan-A4:72` | **升级为合流硬契约**（见 5.3） |
| ④ 流式 500tps 表格场景帧率（P95 < 16.6ms） | `plan-A4:74` | 归入 §4 `M6c` |

### 5.2 合流点与不干预点

- **合流点 1（怎么算）**：ADR-4 的岛内 `max-content` 一次测量 = A4 方案 C 的「闭合定型」实现体；A4 定「何时」，ADR-4 定「怎么算」，二者正交（`00-总方案:149`）。
- **合流点 2（谁上报高度）**：ADR-5 岛自测量；A4 只涉列宽、未涉高度 → **不冲突**。
- **不干预点**：A4 的候选/回退**触发时机**（分隔行到达 / 空行到达）不变；grow-only 锁宽（`MarkdownEngine.tsx:2098-2113`）保留为「估算路径」，**仅**在闭合时被岛精确测量覆盖一次。

### 5.3 候选态 → 闭合态过渡契约

| 项 | 契约 | 依据 |
|---|---|---|
| DOM 身份 | **候选态即按岛挂载**（列宽 = 估算值），闭合时**只更新 `<col>` 宽度与表头 class，不重建节点** | 与 `plan-A4:72` 的 `oldEl === newEl` 一致；违反即破坏 A4 零跳动断言 |
| 是否重建 | **禁止**「候选期行式 → 闭合后岛式」的形态切换（必然重建节点） | 同上；**此为需主控裁决处**（见 §6 裁决项 A） |
| 跳变量上限 | 闭合定型 = 单次 reflow；岛高变化幅度 ≤ 精确高与估算高之差的绝对值，且经 `deltaHeightAbove` 锚定补偿（`MarkdownEngine.tsx:1959-1963`）后**视口内视觉位移 == 0** | F-Lay-3（`02-分维:100`）、M2a 相对脱节 0 容忍 |

### 5.4 与 `streamTableTrackRef` 的关系（结论：**保留，不替换**）

- **结论**：`streamTableTrackRef`（`MarkdownEngine.tsx:2013-2120`）**保留**，降级为**流式估算路径**；岛精确测量是其**闭合后的替代**，二者时序互斥、不并行。
- **理由**：它解决的是「流式期列宽估算 + 增量 grow-only」的**时机与增量成本**（每帧 `O(新增行)`，不整表重扫），是 A4 方案 C「估算」阶段的既有实现（S-EL-04，`streaming-render/00:19`）。删除会同时失去增量能力与 A4 的「估算」半侧，属推翻 A4。
- **边界纪律**：同一表同一时刻**只能有一个测量所有者**（ADR-5 代价项，`00-总方案:156`）。断言：流式会话内岛**不做** `max-content` 测量；闭合后 `track` 置空（`:2117-2119`）且岛接管。

## 6. 风险与缓解

| # | 风险 | 缓解 | 断言 |
|---|---|---|---|
| **R1**（承接，`00-总方案:390`） | 岛成为单一虚拟项后万行/超长表退化为一次性渲染 | 岛内行窗口化 + 行数阈值 | 岛内挂载行数 `≤ W_max`（与 `R` 无关）；18,800 行压测节点上限（§4） |
| **R5**（承接，`00-总方案:394`） | 流式与 A4 耦合 | §5 合流契约 + `streamTableTrackRef` 保留 + 不推翻 A4 | 候选态节点身份不变；reflow 计数 ≤1 |
| **R6**（本维） | 岛 RO 自测量与批量 effect 同帧双测 → 单帧布局次数上升 | 岛行区间从批量回填循环排除（`:1913-1956`） | `layoutThrash` delta == 0（`M6d`） |
| **R7**（本维） | 岛 item 像素跨度大 → `overscan:40`（`:1068`）语义漂移 → 岛进出视口挂载风暴 | 岛挂载/卸载单帧节点上限 + 像素口径复核 | 单帧新增节点 `≤ k×C + slack` |
| **R8**（本维） | `max-content` 离屏测量自身触发强制布局 → 与 M6b 冲突 | 受控容器 + 单次读写分离 | `M6b ratio ≤2` 且相对现状不升 |

**需主控裁决处（不得静默略过，`00-总方案:361`）**：
- **裁决项 A**：候选态 DOM 形态。若 T3 选择「候选期行式渲染、闭合后切岛」，将与 A4 §5.3 零跳动（`oldEl === newEl`）**正面冲突**。建议统一为「候选期即岛式（列宽 = 估算）」。
- **裁决项 B**：流式期岛高度来源。A4 未定高度；ADR-5 若在流式期逐 chunk 上报，RO 频率将突破「闭合一次」语义。建议：流式期岛高用估算、闭合时一次实测。

## 7. 未决问题 U3/U4 的性能侧判定方法

目标：用**性能/几何证据**判定 `f50.png` 行序错乱（U3，`00-总方案:402`）与灰色重影（U4，`:403`）是**真实缺陷**还是**视频帧混合伪影**。**禁止凭猜测归因**（`01-分维:228`）。

**步骤（页面内 `evaluate`，零源码改动为主）**

1. **最小复现**：载入素材文档（`doc00` / `doc03`，`docManifest.ts:44-119`），定位含目标行的表格区间。
2. **静态基线**：源码行序 = `store.getLine(i)`（i 遍历表区间）；DOM 行序 = `container.querySelectorAll('.virtual-row[data-index]')` 按 `data-index` 升序（`[data-index]` 口径见 `verify-physical-measure.mjs:27`）。判：源码序 == DOM 序。
3. **滚动往返 dump**：`scrollTop` 由表前滚至表后、再滚回；每帧记录三项：
   - `[data-index]` 的 `style.transform` / `style.top`（`directDomUpdatesMode` 见 `MarkdownEngine.tsx:1150`）→ 还原 item 顶部像素；
   - `[data-index]` 的 `offsetHeight`（与 `HeightMap` 高度比对；若诊断钩子就绪读 `HeightMap.getHeight(i)`，否则用 `offsetTop` 差分重建，`HeightMap.ts:357-361`）；
   - 该表 `.line-table-row` DOM 节点数 vs 源码 `|` 行数（重复 = 幽灵行）。
4. **判据**：
   - 源码序 == DOM 序 **且** 无重复节点 **且** `transform` 单调且与高度前缀和相符 → U3/U4 为**视频帧混合伪影**（非缺陷）；
   - 出现「同一 `data-index` 两个节点」或「`transform` 非单调 / 与 `HeightMap` 前缀和不符」→ **真实缺陷**，升级为 T4 一等验收项（I8，`00-总方案:194`）。
5. **证据固化**：dump 结果写入 `table-stream.mjs` 的 `notes/metrics`；在 `verify-physical-measure.mjs` **新增** `TABLE-ROW-ORDER-INTEGRITY` 断言（**保留**既有 `:350/:371/:400/:415/:444/:474/:507` 六场景）。

> 诊断钩子 `window.__CRISH_HEIGHTMAP__`（只读 `getHeight/posOf`）为**可选增量**，仅在步骤 3 无法由 DOM 几何还原高度时启用；其登记归 T0/T4，属纯新增，不改既有行为。
