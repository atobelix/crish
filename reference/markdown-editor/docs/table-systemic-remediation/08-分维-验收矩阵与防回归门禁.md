# 08 分维：验收矩阵与防回归门禁

> 上位：`00-总方案-表格子系统端到端重构.md`（§6 不变量、§7 任务单元、§9 分期与止损、§10 验收总表、§13 裁决记录）。
> 本文件是**验收契约**：任何任务单元宣称完成，必须按本文件的对应行提供可复核证据。
> **核心原则**：症状必须被断言反向守住；不变量必须可自动判定；测试资产只增不减。

## 1. 验收分层与命令

| 层 | 目的 | 命令 | 失败即阻断 |
|---|---|---|---|
| L0 静态 | 类型 + lint | `npm run check:gate` | 是 |
| L1 单元 | 纯逻辑正确性（模型 / 身份 / 选区重映射 / 操作） | `npm run test` | 是 |
| L2 契约 | 设计 token / SSOT / **本战役不变量** | `npm run test:gate` + `node scripts/check-table-invariants.mjs` | 是 |
| L3 性能 | 表格场景预算不劣化 | `npm run test:perf` | 是 |
| L4 物理 | 真实宿主端到端（非 Mock） | `npm run test:measure` | 是 |
| L5 e2e | 交互矩阵 | `npx playwright test tests/e2e/table-*.spec.ts` | 是 |
| L6 视觉 | 与 `02-分维` 参考规格逐项对齐 | `scripts/verify-physical-measure.mjs` 表格场景（扩展） | 是 |
| L7 导出 | 导出 HTML 合法性 | `npm run test`（含导出单测） | 是 |

**硬性**：编译与类型检查**仅为底线**，不得作为交付的唯一依据。必须在**真实宿主与执行上下文**中检验端到端物理表现，确保运行时零未捕获异常与非预期告警；**禁止仅在脱水 Mock 中自欺欺人**。

> 用于判定「行序错乱」「灰色重影」是真实缺陷还是视频帧混合伪影。**禁止凭猜测归因**。

1. **最小复现**：载入 `doc00` / `doc03`（素材清单见 `src/assets/docs/docManifest.ts:8,11,83-84,116`），定位含目标行的表格区间。
2. **静态基线**：源码行序 = `store.getLine(i)` 遍历表区间；DOM 行序 = 表格作用域内 `[data-index]` 升序（口径见 `scripts/verify-physical-measure.mjs:27`）。判：源码序 == DOM 序。
3. **滚动往返 dump**：由表前滚至表后、再滚回，每帧记录三项：
   - `[data-index]` 的 `style.transform` / `style.top` → 还原 item 顶部像素；
   - `[data-index]` 的 `offsetHeight`（与高度真源比对；必要时用 `offsetTop` 差分重建）；
   - 该表格行 DOM 节点数 vs 源码表格行数。
4. **判据**：
   - 源码序 == DOM 序 **且** 无重复节点 **且** transform 单调且与高度前缀和相符 → **视频帧混合伪影**（非缺陷）；
   - 出现「同一 `data-index` 两个节点」或「transform 非单调 / 与高度前缀和不符」 → **真实缺陷**，升级为 **T4 一等验收项**（I8）。
5. **证据固化**：dump 结果写入 `table-stream.mjs` 的 `notes/metrics`；在 `verify-physical-measure.mjs` **新增** `TABLE-ROW-ORDER-INTEGRITY` 断言（**保留**既有六场景 `:350/:371/:400/:415/:444/:474/:507`）。

## 11. 防回归与反作弊

1. **测试资产只增不减**：`tests/unit/table-*.test.ts`、`tests/perf/suite/scenarios/table-stream.mjs`、`scripts/verify-physical-measure.mjs` 表格场景、`tests/e2e/table-*.spec.ts` **不得删除、`skip`、注释或弱化阈值**。
2. **禁止 `--no-verify`**：报错必须正面阅读日志并根除，直到门禁正常跑通。
3. **禁止骗 CI**：不得用 mock 冒充真实宿主验收；不得把断言改成恒真。
4. **禁止补丁式修复**：不得用坐标测距补偿、延时盲猜、临时兼容层解决 S2/S3/S4/S6。
5. **SSOT 门禁**：`npm run check:ssot` 必须覆盖表格相关契约（列宽真源、表头真源、身份真源），禁止双源回潮。
6. **文档与代码一致**：实现偏差必须回写对应分维文档与 `00-总方案` §13 裁决记录；禁止文档先行而代码偏离却不留痕。

### 11.1 已知风险：墙钟预算断言在并行套件内抖动（T0 观测）

**观测（2026-09-14，T0）**：`tests/unit/parser-regression.test.ts` 的「2^n 修复：未闭合链接链」用例预算为 100ms，在**全套并行执行**（`npm run test:gate`）时偶发测得 168ms 而失败；**单独运行该文件稳定通过**（54 用例 / 69–73ms，连跑 2 次均绿）。

**判定**：环境抖动（并行 worker 争抢 CPU），**非代码缺陷**。复跑全套即恢复全绿（97 文件 / 1213 用例）。

**处置纪律（硬性）**：

1. **禁止**通过放宽阈值、`skip`、注释断言来「修」它——属弱化测试资产（本文件 §11 规则 1）。
2. 本战役新增的**墙钟类预算断言**（P1 帧率、P5 窗口切换成本等）必须放在 `tests/perf`（独立进程、受控负载）中，**不得**放进 `tests/unit` 的并行套件。
3. 若某次门禁因该用例失败，**先单独复跑该文件**确认是否抖动，再复跑全套；两次均失败才按真实回归处理。
4. 该观测不改变任何既有阈值与场景，仅作为**排障指引**登记。
