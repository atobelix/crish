## 3. 缺口补齐设计（源码落点全部为 `src/core/TableOperations.ts`，除非另注）

### 3.1 行重排 / 列重排（对接 `05-分维` 拖拽协议）

```ts
export function moveRow(text: string, cursorPos: number, fromRow: number, toRow: number): TableOperationResult;
export function moveColumn(text: string, cursorPos: number, fromCol: number, toCol: number): TableOperationResult;
```
`fromRow`/`toRow` 为 0-based 数据行下标（不含分隔行）；`fromCol`/`toCol` 为列下标。

- **源码文本变换**：`moveRow` 取 `table.lines`，目标行 `splice` 出再 `splice` 入（分隔行位置不动）；`moveColumn` 对**每一行**（含分隔行）做同一 `splice` 置换，保证列数恒定、对齐随列迁移。
- **参数校验**：越界 / `from === to` / 表内含合并从属格（`>`/`^`）→ 返回 `{ newText: text, newCursorPos: cursorPos }`（幂等空操作），由 UI 层给出拒绝理由。
- **撤销粒度**：与既有增删行列同口径——**单次操作 = 单步 undo**，走 `applyTableChange(table.startOffset, table.endOffset, newTableText, cursor)`（模式同 `ContextMenu.tsx:216-225`）。禁止逐行多次 `applyChange`。
- **对接契约（给 `05-分维`）**：拖拽层只产出 `(fromRow, toRow)` / `(fromCol, toCol)` 两个整数；落点高亮（F-Drag-2，`02:88`）与源元素降透明度（F-Drag-1，`02:87`）是纯视图行为，**不得**在 `TableOperations` 侧产生任何中间态文本；拖拽取消必须保证文本零变化（F-Drag-3，`02:89`）。

### 3.2 表头开关

**结论：表头是「源码状态」，不是视图状态。**

- **唯一真源**：`TableModel.hasHeader := separatorLineIndex !== -1`。分隔行存在即首行为表头；不存在即无表头。这与 `findTableRange` 已有的 `separatorLineIndex`（`TableOperations.ts:137-145`）同源，消灭 `BlockRenderer.tsx:1565` 的 `tableId === 'table-' + index` 二次推导（I5）。
- **开关的实现**：`export function toggleHeaderRow(text: string, cursorPos: number): TableOperationResult;` ——有分隔行则移除（降级为无表头表格），无分隔行则在首行后插入分隔行。

- **与 `TableModel.hasHeader` 的关系**：`hasHeader` 是分隔行存在性的**纯函数投影**，只读；`toggleHeaderRow` 是唯一写入口。渲染层（`BlockRenderer` / `TableBlock`）与导出层（`renderToHtml`）**都必须读 `hasHeader`**，不得各自判定。
- **明确取舍（需主控裁决，见 §8-U1）**：移除分隔行后，该块在 GFM 语义下**不再是合法表格**（GFM 要求 header + delimiter 成对）。本仓 parser 对「裸管道行块」仍成表（`pipeCount>=3`，见 `01:70` 引 `parser.ts:2380-2390`），因此编辑器内可继续编辑、渲染为无表头表格、导出为 `<table><tbody>`。备选路径「仅视图层去表头样式」被否决：它使表头语义出现第二个真源，直接违反 I5。
- **列对齐保留**：移除分隔行会同时丢失对齐信息。`toggleHeaderRow` 在关闭表头时**必须**把原分隔行的对齐数组回写到 `TableStore.tableAlignments`（视图态保留），重新开启表头时据此重建分隔行（`:---` / `---:` / `:---:`）。

### 3.3 整表插入

`export function insertTable(text, cursorPos, rows: number, cols: number, alignments?: ('left'|'center'|'right')[]): TableOperationResult;`

- **产出结构**：`| 　 | 　 |`（表头行）+ `| --- | --- |`（分隔行）+ `rows - 1` 行空数据行；每行前后各一个空格（与既有风格一致，见 `TableOperations.ts:187`）。
- **落点**：在光标所在**行末**换行后插入（不拆断当前行文本），整块文本替换为 `before + '\n' + tableText + '\n' + after`；光标落在第一个表头单元格内。`rows >= 2`、`cols >= 1`，越界钳制。
- **对齐**：`alignments` 缺省全 `left`；分隔行按 `:---` / `:---:` / `---:` 编码（与 `setColumnAlign:381-383` 同表）。**撤销粒度**：单步。

### 3.4 排序

`export function sortRows(text, cursorPos, colIndex: number, direction: 'asc'|'desc', comparator?: (a,b)=>number): TableOperationResult;`

- **表头行不参与排序**：`hasHeader`（= 有分隔行）为真时，表头行与分隔行**原地不动**，只重排分隔行之后的数据行。
- **稳定性**：显式**稳定排序**——排序键为 `(key, 原始行下标)` 二元组，`Array.prototype.sort` 的稳定性不作为契约依赖。
- **比较器**：缺省为「数值可解析则数值比较，否则 `localeCompare`」，避免 `10` 排在 `9` 前。单元格文本先剥离行内记号（`**`/`*`/`~~`/`` ` ``）再比较。
- **与合并单元格的冲突处理**：**拒绝排序**。若表区间内任一数据行含 `>` 或 `^`（合并从属格），直接返回原文本（幂等空操作）。理由：合并跨度绑定在「主格 + 从属格相对位置」上，重排行序会使 `^` 的垂直语义指向无关行（`unmergeCells:774-810` 的跨度回溯会算错）。UI 侧提示「请先拆分合并单元格」。
- **撤销粒度**：单步（整表区间一次替换）。

### 3.5 列宽拖拽（`setColumnWidth` 接线；与 `04-分维` 的列宽真源衔接）

- **结论：接线，不删除。** `setColumnWidth`（`TableStore.ts:20,40`）是「用户显式列宽」的唯一写入通道；ADR-4（`00:144-149`）定的是**自动测量的算法**，不能替代用户意图覆盖。
- **双通道设计（给 `04-分维` 的接口契约）**：
  - `tableWidths` = **生效列宽**（渲染唯一消费点，`InlineRenderer.tsx:466-478`）；
  - 新增 `userWidths: Record<string, (number | undefined)[]>` = 用户拖拽覆盖值；
  - 生效规则：`effectiveWidth(col) = userWidths[tableId]?.[col] ?? measuredWidths[tableId][col]`。自动测量（岛内 `max-content` 一次测量）**不得覆写**已有 `userWidths` 的列。
- **拖拽写入路径**：`mousedown` 在列边界 → 拖拽中只改**视觉**（CSS 变量或局部 style），`mouseup` 时调用一次 `setColumnWidth(tableId, colIndex, finalPx)`。禁止拖拽过程中逐帧写 store（否则触发逐帧 reflow，违 I2 与 `tests/perf` 的 `perTableSettles ≤ 2`，`00:376`）。
- **最小宽度**：沿用 `TableStore.ts:44` 的 `Math.max(50, width)`。
- **列数自愈**：`userWidths[tableId].length !== TableModel.cols` 时整体丢弃（与 ADR-3 的过渡期自愈同口径，`00:139`）。

### 3.6 CSV 粘贴（`isTabularText` 扩展）

- **结论：不做全局扩展，改为「上下文限定」。** `isTabularText`（`htmlToMarkdown.ts:189-191`）服务于**正文**粘贴路径（`buildPasteText:255-260`），若把「含逗号」判为表格，会把正常含逗号的段落误转为表格——这是不可接受的正文回归。
- **设计**：新增纯函数并保持既有导出签名不变（既有 `htmlToMarkdown` 相关用例不受影响）：
  - `export function isDelimitedText(text: string, delimiter: '\t'|','|';'): boolean;` —— `\t` 恒真；`,`/`;` 要求 ≥2 行且各行分割列数一致且 ≥2。
  - `export function delimitedTextToMarkdown(text: string, delimiter: '\t'|','|';'): string;` —— 支持双引号包裹与 `""` 转义。
- `tabularTextToMarkdown`（`:198`）收敛为 `delimitedTextToMarkdown(text, '\t')` 的薄封装（行为等价，既有测试锁定不变）。
- **接线点**：CSV 判定只在**表格上下文**启用——`HiddenInput.tsx:1373` 的「粘贴到单元格」分支与 `ContextMenu.tsx:122` 的 `paste-cell` 分支中，先探测 `\t` → 再探测 `,`/`;`（用 `isDelimitedText`）→ 命中则走「矩形区域写入」（§3.9），否则退回 `setCellContent` 单格写入。正文粘贴路径**不引入** CSV 判定。

## 4. 导出投影设计（ADR-7 落地）

### 4.1 `renderToHtml` 表格分支改造

- **现状**：`case 'table_row'` 直接 `out.push(renderTableRow(line))`，产出裸 `<tr><td>`；`case 'table_separator'` 空实现（`renderToHtml.ts:713-717`、`:509-524`）。这是 S11/D8 的根因。
- **改造**：新增 `renderTableBlock(lines, start, out): number`，与 `renderFencedBlock`（`:527-553`）/ `renderMathFencedBlock`（`:561-582`）**同构**——从 `start` 起消费连续的 `table_row` / `table_separator` 行，构造 `TableModel` 后一次性输出整块，返回下一行号。主循环 `:713` 改为 `i = renderTableBlock(lines, i, out); continue;`，并**删除** `:716-717` 的 `table_separator` 空分支（区间已被整块消费，不留双路径）。
- **输出结构**：

```html
<table>
  <thead><tr><th align="center">A</th><th>B</th></tr></thead>
  <tbody><tr><td align="center">1</td><td>2</td></tr></tbody>
</table>
```

- **`hasHeader` 投影**：`true` → 首行（分隔行**上一行**）进 `<thead><tr><th>`；`false` → 无 `<thead>`，全部行进 `<tbody><tr><td>`。`<tbody>` 恒存在（即使为空表也输出空 `<tbody></tbody>`），保证 I9 的列数断言有稳定锚点。
- **对齐投影**：`TableModel.alignments` → `th/td` 的 `align="left|center|right"` 属性（GFM 参考实现 cmark-gfm 同款输出，便于断言与比对）。被否决的替代：`style="text-align:…"`——与既有导出器的无内联样式风格（`renderToHtml.ts` 全文无 `style=`）冲突。
- **`colspan` / `rowspan` 投影**：主合并格（`isMergedMaster`，`parser.ts:2583-2587`）输出 `colspan="N"`；`rowspan` 由 `TableModel.spans` 计算（parser 恒置 1，见 `parser.ts:2594`，故**必须**在 `TableModel` 内由 `^` 占位符推导）。从属格（`isMergedSlave`，`:2581-2585`）**不产出任何 `<td>`**（HTML 语义中由 `colspan`/`rowspan` 隐含占位）。
- **单元格内容**：复用 `renderInline`（`renderToHtml.ts:516-518` 现有调用），行内 HTML 令牌（`<br>`、`<kbd>`）按文件头契约原样透传（`:22-24`）。
- **块引用内表格**：区间开始前 `syncQuotes(bq)`（`:637-646`）；表格区间内各行 `blockquoteLevel` 恒定，区间内不改引用层级，区间结束不追加 `</blockquote>`。
- **禁止**：区间内出现裸 `<tr>`（I9 的失败模式）；禁止把 `table_separator` 投影为可见行。

### 4.2 `tests/commonmark/astToHtml.ts` 与 `src/core/renderToHtml.ts` 的关系与收敛方向

- **现状关系**：两投影器是**独立实现 + 等价断言**。`renderToHtml` 从 `astToHtml` 逐函数迁移而来（`renderToHtml.ts:12-19`），差异仅 math（KaTeX vs 占位）；文件头明确「同步红线：本模块不得反向依赖 `astToHtml`，一致性以等价断言维持」（`renderToHtml.ts:17-19`）。断言落点：`tests/unit/render-export.test.ts:218-268`，其中 `:243-245` 与 `:251-267` 的文档**都含表格**，断言 `renderToHtml(doc) === astToHtml(doc)`。
- **结论：不合并，`astToHtml` 保持独立；但 T7 落地前必须先解决等价断言冲突。**
  - **推荐路径 A**：`astToHtml` 的 `renderTableRow`（`astToHtml.ts:546-...`）与主循环 `:780-783` 同步升级为同款 `<table><thead><tbody>` 投影，等价断言继续成立。理由：等价断言是既有红线；`tests/commonmark` 的「零语义修复」契约（`astToHtml.ts:1-27`）针对 **CommonMark spec 语法**，而表格不是 CommonMark 语法（CommonMark 无表格章节），因此表格投影的结构升级不构成违约。
  - **被否决路径 B**：把等价断言收窄为「无表格文档等价」——属于**弱化既有测试资产**，违反 `00:359`。
  - **代价与前置**：`tests/commonmark/` 是 B8b 域，不在 T7 文件域（`00:298` 仅 `src/core/renderToHtml.ts`）。因此 T7 落地需一次跨域协调（`astToHtml` + `tests/commonmark/README` 的偏差点登记）。**此项列为需主控裁决（§8-U2）。**

### 4.3 I9 断言设计

| # | 断言 | 校验方式 |
|---|---|---|
| I9-1 | 导出 HTML 含 `<table>` | `expect(html).toContain('<table>')`；反向断言 `expect(html).not.toMatch(/<tr>/` 裸行（即 `<tr>` 必须由 `<table>` 前缀紧随） |
| I9-2 | `<thead>`/`<tbody>` 列数与 `TableModel.cols` 一致 | 用 jsdom `DOMParser`（`htmlToMarkdown.ts:159-169` 已有同款惰性获取范式）解析后取 `table.querySelectorAll('tr')`，逐行 `Σ(colSpan ?? 1)`，断言每行和 == `TableModel.cols`；有表头时断言 `thead tr` 与 `tbody tr` 的列数和均相等 |
| I9-3 | HTML 可被解析器闭合 | `const doc = new DOMParser().parseFromString(html, 'text/html')`；断言 `doc.body.querySelectorAll('table').length === 1`、`doc.body.querySelectorAll('tr').length === doc.body.querySelectorAll('table tr').length`（无游离 `<tr>`）、`table.rows.length === 源表行数 − 分隔行数`；再断言每个 `<tr>` 的 `children.length` 与其 `Σ(colspan)` 一致（无结构塌陷） |
| I9-4 | 表头投影正确 | `hasHeader === true` → `table.querySelector('thead')` 非空且首个 `tr` 的子元素全为 `TH`；`false` → `querySelector('thead') === null` 且 `tbody` 首个 `tr` 子元素全为 `TD` |
| I9-5 | 合并投影正确 | 含 `>` 的表：`td[colspan]` 计数 == 主格数；`td` 总数 == 源单元格数 − 从属格数；无 `>`/`^` 文本残留在输出中 |

### 6.2 边界：合并单元格 × 排序 × 重排

- 三者共享「单元格相对位置」这一前提，互相冲突：
  - **排序 × 合并** → 排序**拒绝**（§3.4）；
  - **重排 × 合并** → 行/列重排**拒绝**（§3.1 参数校验）；理由同上（跨度会指向无关格）；
  - **排序 × 重排** → 无冲突，但两者都不得跨越分隔行（表头/分隔行位置恒定）。
- **跨表格操作**：**明确不支持**。选区身份为单表 `tableId`（`TableStore.ts:3-10`），`findTableRange` 只返回光标所在表（`TableOperations.ts:115-129`）。防御：若选区源码区间跨越两个表（区间内出现非表格行），结构操作一律拒绝并清空选区，禁止「静默作用于第一张表」。

### 6.3 边界：表格内搜索/替换

**本维不实现，且现状已覆盖。** `FindReplacePanel.tsx:118` 已实现全文查找替换（`searchAll` 分批扫描经 `getLine` 访问器读取行序列，`FindReplacePanel.tsx:196-236`），表格行天然包含在内；接线于 `MarkdownEngine.tsx:132,2477`。本维只需登记一处冲突：`HiddenInput.tsx:1340` 的 `handleTableInteraction` 在单元格选区/编辑态下先于全局键位拦截 `Escape`（`:1392,1533`）与方向键，与查找面板的 `Escape` 关闭、F3 导航之间**键位归属未定义**。处置：表格态下把 `Escape` 定为「先关闭面板、再退出单元格选区」的两级语义，归 T6 的键位表统一登记。

### 6.4 列宽持久化

**结论：列宽是视图状态，不写回源码文本。**

- 源码层**无**列宽语法（GFM/CommonMark 均无），写回源码必然引入私有语法 → 破坏 CommonMark 合规基线（`tests/commonmark`）、污染用户文本、使 undo/diff 语义劣化。

- 若需跨会话保留：落点为**宿主侧 session_meta**（与折叠状态同款思路，`status-P2-现状盘点.md:21`），不进 `src/` 源码文本。**不列为裁决项**，本条为结论。
