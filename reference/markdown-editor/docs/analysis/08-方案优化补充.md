# 方案优化补充（08）——流式三招整合 + 集成前验收门槛

> 依据：07 总纲 + 01-06 分析 + 外部技术讨论的合理借鉴（已剔除夸大成分，仅采纳有代码依据的部分）。
> 定位：对 07 的增量修订，不替换总纲——总纲的轮次结构、闭环模板、约束全部保持。

## 1. 采纳的外部建议（三招，附代码级依据与风险修正）

外部讨论提出三招：直刷 DOM、零拷贝缓冲、16ms 帧对齐。逐招核查后**部分采纳**，并修正其未提及的风险：

### 招 1：流式末行直刷 DOM（绕过 React）——采纳，纳入 R3

**现状**：流式 append → store 更新 → React 重渲染末行（LineItem 行级 selector 已减少范围，但 React 提交仍在）。

**方案**：流式专用末行渲染通道——StreamBuffer 批处理后，若追加内容在同一行内（无 `\n`），直接 `ref.current.textContent += chunk`（命令式 DOM 追加），store 延迟提交（见招 2）；出现 `\n` 时把整行数据同步给 store（一次 React 提交）。

**风险修正（外部讨论未提）**：
- 末行 DOM 与 store 的**暂时不一致**会破坏测量（getCoordinatesFromIndex 全扫的是 DOM）与 verifyConsistency——需要"流式边界协议"：DOM 直写期间标记该行为 `streaming-dirty`，测量/选区/复制操作触达时先 flush
- undo/redo 在流式期间对 dirty 行的处理（流式合并 undo 步已在 R3 计划，直刷不产生 store 事务，天然不占 undo——利好，但要防"流式结束后未 flush 的残留"）
- 与光标跟随：光标在末行时直刷不触发光标重测——需要节流跟随（每帧一次）

### 招 2：零拷贝流式缓冲——采纳，且比外部讨论更紧迫

**现状**（代码级证实）：`appendText` 每次 `const newLinesArr = [...state.lines]`（EditorStore.ts:558）——**流式每批（60 次/秒）全量浅拷贝整个 lines 数组**。百万行时每次拷贝 100 万引用（~8MB），**频率被 StreamBuffer 压到 60/秒，但单次拷贝量 O(全文) 未解决**——外部讨论的担忧属实且可量化。

**方案**：行级 append 结构——append 路径不重建主数组：
```
// 方案 A（推荐）：append-only 尾段
state.streamTail: string[]   // 流式追加行落在独立尾段
state.mainLines: string[]    // 主数组不变（滚动/编辑时才合并尾段）
// 查询：getLine(i) = i < mainLines.length ? mainLines[i] : streamTail[i - mainLines.length]
// 合并：滚动到尾部或用户编辑触达时，一次合并（摊薄成本）
```
- 与 LineOffsetTree 配合：尾段行数少（≤ 几帧的追加），偏移计算直接累加不建树
- 用户编辑发生在主数组中部时不受影响；编辑发生在尾段时先合并
- 与招 1 配合：尾段 = 直刷 DOM 的延迟提交缓冲，天然同一结构

**注意**：方案 A 改变了 getLine/getLineIndex 的查询路径——所有读 lines 的位置（LineItem 渲染/virtualizer count/measure）需走统一访问器。R3 实现时按"访问器先行"顺序做（先加访问器再切存储）。

### 招 3：16ms 帧对齐——已实现，无需新做

StreamBuffer（src/core/StreamBuffer.ts）已是 rAF 批处理。核查确认：批处理存在，**缺的是 flush 语义**（stop/结束流式时强制 flush 尾段——见 05 分析"stop-flush"）。R3 补 stop-flush 即可。

## 2. 集成前验收门槛（"引擎最强"的定义）

用户要求：集成（R5 宿主接入）之前，模块必须确保是当前最强的能力。据此定义**集成前验收清单（R0-R3 完成后必须全部满足）**：

| # | 验收项 | 判定标准 | 对应轮次 |
|---|---|---|---|
| 1 | CommonMark 符合度 | 652 用例接入门禁，核心子集（标题/强调/围栏/列表/引用/转义）≥0.99，全量通过率持续增长（无白名单豁免） | R1 |
| 2 | 解析器健壮性 | 2^n 爆炸修复（失败规则记忆）、token 覆盖守恒 0 违例、缓存 id 唯一、超长行/嵌套炸弹预算内 | R1 |
| 3 | 行高模型 | 滚动条准确性量化（scrollTop 50% 时树预测行号 vs 实际渲染行号偏差 < 1 行）、无测量回环抖动 | R2 |
| 4 | 帧率档位 | 百万行滚动：60fps 达成（P95 < 16.6ms）；500 token/s 流式注入：60fps 达成 | R2/R3 |
| 5 | 流式三件套 | append 零拷贝尾段 + 末行直刷 + stop-flush 全部落地，流式期间用户编辑语义正确（append 光标冲突已修） | R3 |
| 6 | 测试网 | G1-G5 落地：渲染层 RTL 测试网、属性测试不变量集、行为契约、CommonMark 门禁、CSS 契约；门禁总量 ≥ 现有 126 + 新增 120-140 | R3 |
| 7 | 稳定回归 | 全部轮次测试全绿、编译 0 错误、编码校验干净、工作区干净 | 每轮 |

**集成（R5）只有在 1-7 全部满足后启动**——这是"集成前模块最强"的硬门槛，任何一项不达标不进入宿主接入。
