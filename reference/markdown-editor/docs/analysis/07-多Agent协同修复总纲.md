# 多 Agent 协同修复总纲（07）

> 系统性、自上而下的多轮次迭代修复方案。仅含逻辑执行顺序；不涉及时间安排、人员分配、优先级排序——所有列出问题同等重要。方案可复用：每轮输出作为下一轮输入，闭环迭代。每轮最多 12 个 Agent，数量按轮次实际需求灵活决定，不强制占满。
> 依据：01-06 六份分析文档 + 全部实证数据。

## 0. 目标与约束

- 帧率目标：百万行文档 + 500 token/s 流式注入，**60fps 保底、120/140+ 冲刺**（01 的帧率预算表为验收依据）
- 正确性目标：CommonMark 652 用例接入门禁，通过率持续增长（02 的 AST 投影器 + 防作弊条款）
- 测试目标：10 类门禁（03 的 G1-G10），保底新增 60 用例、目标 120-140+ 严格用例
- 形态目标：单文档 20 万 token 可流畅渲染编辑（markdown-editor 主场）；1000 万 token 历史经消息层虚拟化 + 历史折叠承载（宿主对话流）
- 约束：不降低难度凑指标（禁止硬截断/放宽预算伪装通过）；编码铁律（UTF-8 无 BOM）；测试资产入库

## 2. 形态定位（先决判断）

```
单气泡 20 万 token（≈15-20 万行） → markdown-editor 主场（单文档引擎，设计目标即百万行）
历史累计 1000 万 token（≈几千条消息） → 消息层虚拟化 + 历史折叠（宿主对话流职责，非单文档引擎）
```

**结论**：markdown-editor 不限于笔记形态——它是"单文档渲染核心"；1000 万 token 历史需要**三重结构**：
1. 外层：消息列表虚拟化（宿主对话流，可见消息恒定 DOM）
2. 中层：单消息渲染 = markdown-editor（或 AsyncMarkdownBlock 演进统一）
3. 内层：单条长消息内部虚拟化（markdown-editor 已具备）

composer-preview（ProseMirror 块级）定位编辑体验层（不追求极致性能）；chat-composer-component 定位视觉焕新层。三者职责分离，不互相替代。

## 3. 轮次设计（逻辑执行顺序）

### R0 基线固化轮
- 任务：CommonMark 套件接入（AST 投影器 + 652 用例跑分）、性能基线采集（百万行滚动帧率/500 token/s 流式/各瓶颈 profile）、门禁框架 G1-G10 骨架落地
- Agent：识别 1（确认基线方法）+ 实现 3（投影器/性能探针/门禁骨架）+ 验证 1
- 产出：**基线数据**（652 用例通过率分章节、帧率基线、瓶颈排序）→ 作为 R1-R3 的量化对照

### R1 解析器正确性轮
- 任务：修 2^n 爆炸（失败规则位图记忆）→ 6 项缺语法（Setext/缩进代码块/引用链接/自动链接/HTML 块/实体）→ 缓存 id 重复 → token 覆盖守恒 → fence 边界 → `_` 强调族 → 链接校验；同步补 parser 测试矩阵（G5 门槛内）
- Agent：识别 1 + 修复 4（按文件域互斥：parser 块级/parser 内联/缓存与状态/validator）+ 测试 2 + 验证 1
- 产出：652 用例通过率提升报告 + 正确性测试网 → 输入 R2

### R2 性能地基轮
- 任务：行高模型（HeightOracle 预测 + 树状 height map）→ 滚动 rAF 合并 + 命令式位置更新 → 测量缓存（token→textNode 二分索引）→ clone COW → fence 前缀 O(1) → 表格行高 oracle
- Agent：识别 1 + 修复 5（行高/滚动/测量/数据层/表格，文件域互斥）+ 性能测试 1 + 验证 1
- 产出：帧率基线对比（60fps 达成判定）+ perf 门禁 → 输入 R3

### R3 流式与渲染轮
- 任务：append 光标冲突修复 + 流式合并 undo + 渲染层测试网（RTL，G3）+ 装饰层统一（DecorationSet）+ 行为契约测试（G4）+ 不变量集属性测试（G2）
- Agent：识别 1 + 修复 3（store/组件/装饰）+ 测试 3（RTL/属性/契约）+ 验证 1
- 产出：500 token/s 稳定报告 + 渲染层回归网 → 输入 R4

### R4 编辑深度轮
- 任务：事务统一（applyChange 单入口，表格收敛）→ 选区 anchor/head/assoc → IME 状态机（compositionGroupId）→ bidi 骨架 → 剪贴板语义 → a11y 短程
- Agent：识别 1 + 修复 4（事务/选区/IME/bidi 分文件域）+ 测试 2 + 验证 1
- 产出：编辑能力成熟度矩阵推进 + 编辑层测试网 → 输入 R5

### R5 扩展与集成轮
- 任务：规则插件（InlineRuler）+ 语法扩展注册 + 渲染注册表 + 主题注入 + 实例工厂（createEditorStore）+ readOnly 模式 + 宿主对话流外层虚拟化与历史折叠（B 线接入 markdown-editor 渲染）
- Agent：识别 1 + 修复 4（插件/注册/包形态/宿主集成分域）+ 测试 2 + 验证 1
- 产出：宿主集成报告 + 1000 万 token 历史架构验证 → 输入 R6

### R6 压测终验轮
- 任务：帧率三档（60/120/140）验证、1000 万 token 历史模拟（消息层虚拟化 + 折叠 + 单气泡 20 万 token）、CommonMark 通过率终验、回归收敛（全部轮次测试全绿）
- Agent：压测 2（DOM/Canvas 双模式）+ 终验 1 + 汇总 1
- 产出：终验报告 + 遗留登记

## 4. 轮次模板（可复用）

每轮固定五阶段闭环：

```
[识别] 1 Agent：读上轮产出 + 代码，确认本轮问题清单（含范围蔓延拦截）
   ↓
[分解] 1 Agent：任务卡拆分（文件域互斥清单 + 验收标准 + 冲突注意事项）
   ↓
[并行修复] N Agent（≤12，按文件域互斥分配，串行仅限同文件）
   ↓
[验证] 1 Agent：全部门禁回归（npm test + 编译 + 编码校验 + 性能断言）
   ↓
[汇总] 1 Agent：轮次报告（完成清单/遗留/新发现/基线更新）→ 下轮输入
```

规则：
- 每轮 Agent 数按任务量定，不强制占满 12
- 分析类 Agent 只读，写作任务由主 Agent 分配（产出文档路径唯一）
- 同文件改动必须串行（主 Agent 调度）
- 每轮结束提交（测试资产铁律），失败任务下轮重派
- 轮间依赖：R0→R1→R2→R3 串行（基线→正确性→性能→流式）；R4 可与 R2 并行；R5 依赖 R4 的事务层；R6 收口

## 5. 验收与闭环

- 每轮验收 = 该轮任务卡全过 + 门禁全绿 + 基线对比数据（量化改进）
- 帧率验收按 01 的预算表分档判定（60 达成/120 达成/140 达成）
- 正确性验收按 652 用例通过率分章节报告（禁白名单豁免）
- 全部轮次结束后，遗留项进 R-next 循环（方案可无限复用）
