# 分析 A4：表格实时流式（总调度产出）

> 背景：流式输出表格的两个真实问题——表头回溯分类（分隔行未到前 body 已渲染）、列宽跳动（TableStore 按当前行计算）。要求：流式中逐行出现（格式即时）、闭合后列宽定型一次修正、全程避免跳动。

## 1. 现状盘点（文件:行号证据）

**判定路径**（parser.ts）：
- `| a | b |` 行 → parseNormalLine 的表格判定：pipeCount ≥ 2 且行首 `|` → table_row（**但需要上下文**：R1-D 前表格判定含分隔行依赖——当前实现：行独立判定 + table_separator 行单独类型；**分隔行到达前，`| a | b |` 行已被判定为 table_row**（行首 `|` + pipe≥2 即判）——需核对：若流式中第一行已按 table_row 渲染，则表头回溯问题实际是"表头行已按表格行渲染但**缺少表格容器语义**（无表头/无列宽）"
- 关键核对点：`| a | b |`（首行）在分隔行未到时——parser 是否判 table_row？（若判——渲染为 `<tr><td>` 但无表头/列宽——视觉是"无边框裸行"；分隔行到达后表格形态出现——类型本身没跳，**但视觉从裸行 → 表格**是跳变）

**TableStore**：tableWidths 按 tableId（MarkdownEngine 的 tableId 计算——R5 前）逐行收集——流式中每行到达更新列宽 → 列宽变化 → 行重渲染 → 跳动。

**流式表格的真实形态**（AI 输出 `| a | b |\n|---|---|\n| 1 | 2 |`）：
- 行 1 `| a | b |`：table_row（无表头语义）
- 行 2 `|---|---|`：table_separator
- 行 3+ `| 1 | 2 |`：table_row（表头语义由"分隔行后首行"确定——**引擎行级无容器**，表头是高亮样式（table-header-row——B4 前）由"首行"判断）

## 2. 表头回溯方案

### 方案 B（推荐）：候选态预分类

```
流式中 pipe 行（`| ... |` 或 pipe≥2）：
  渲染为"表格候选行"（cell 分割样式：轻分隔线/对齐——视觉即时像表格）
  等待分隔行确认：
    - 分隔行到达 → 候选升级为正式表格（表头高亮 + 列宽定型）——样式增强，无类型跳变
    - 空行/非 pipe 行到达（表格结束且无分隔行）→ 候选回退 body（普通段落）——样式回退
候选态设计关键：
  - 候选与正式的视觉差异最小化（候选已有 cell 分割 + 对齐——正式只是加表头高亮/列宽）
  - 回退（候选→body）的跳动：候选是"表格样式"，回退是"普通文本"——差异明显但**只在"误判"时发生**（AI 输出 pipe 行但不是表格——罕见）；可接受，登记
```

- **确认瞬间零跳变**：候选 → 正式 = 同一 DOM 行加表头 class + 列宽调整（无重建）
- 实现面：渲染层（BlockRenderer 行渲染时——pipe 行无分隔行上下文 → 候选 class）；确认/回退由"新行到达时的上下文判定"驱动（分隔行到达 → 通知前 N 行升级；空行/非 pipe → 回退）

### 方案 A（备选）：分隔行到达后回溯重分类

store 检测 table_separator → 重分类前 N 行 → 重渲染——**跳动源**（前 N 行整行重渲染：样式从 body 跳表格）。仅当候选态无法覆盖时用。

### 方案 C：渲染前瞻——流式中不可靠，弃用

## 3. 列宽定型方案

### 方案 C（推荐）：估算 + 闭合定型一次修正

```
流式中：列宽用"已到行内容的估算"（TableStore 现有机制——按已到行算）
表格闭合（空行/非表格行/文档尾）时：一次精确测量定型
  → 一次 reflow（列宽调整）——跳动控制：定型瞬间的单次调整可接受（内容不再变）
  vs 流式中每行微调（方案 B）——多次跳动，弃用
```

- **定型时机**：表格结束（空行到达）——这是"内容不再变"的信号——单次修正 + 后续无跳动
- 与 TableStore 交互：tableWidths 计算触发从"每行更新"改为"闭合时一次"（流式中用估算缓存）
- **跳动控制**：闭合定型的单次 reflow——与代码块闭合硬化（软渲染→高亮）同级——用户感知为"表格定型"，非抖动

### 方案 A/B：流式中渐进/每行微调——多次跳动，弃用

## 4. 渲染交互

| 项 | 设计 |
|---|---|
| 候选态视觉 | cell 分割（轻分隔线）+ 内容对齐——与正式表格的差异 = 表头高亮 + 最终列宽 |
| LineItem memo | 候选态 class 变化触发该行重渲染（内容帧——R6 已实证可接受）——**仅候选行**，非全窗口 |
| 装饰层 | 表格候选态不加装饰（保持简单） |
| 与代码块对照 | 代码块（软渲染→闭合硬化）已达标；表格（候选→闭合定型）同级体验 |

## 5. 测试方案

1. 流式表格逐行：`| a | b |` → 候选渲染（cell 分割断言）→ 分隔行 → 表头升级（class 断言）→ 行 3+ → 列宽定型（一次修正计数）
2. 回退：`| a | b |` + 空行（无分隔行）→ 回退 body（文本断言）
3. **零跳动断言**：确认瞬间 DOM 节点身份不变（oldEl === newEl——A6 M4 同款）；列宽定型 reflow 计数 ≤1
4. 现有 table 测试回归（table-operations/table-parser-ast——候选态不得破坏闭合表格的现有行为）
5. 流式 500tps 表格场景帧率（P95 < 16.6ms——R6 场景矩阵加表格场景）

## 6. 结论

**推荐：候选态预分类（B）+ 列宽估算/闭合定型（C）组合**——流式中逐行即时表格样式（候选）、确认/回退无类型跳变（class 级）、列宽一次定型（单 reflow）。实现落点：parser 或渲染层候选判定 + TableStore 定型时机改造 + 确认/回退上下文驱动。工作量：中（1 个执行 Agent，涉及渲染层 + TableStore）。
