## 4. 技术契约章节（review-02 消化——进入实现前必须遵守）

**C1 滚动管线与 tanstack 契约**：
- 命令式位置更新的前提：所有消费 `virtualRow.start` 的位置（style.top、click padding 映射 MarkdownEngine.tsx:145-154、blockAt 换算含容器 28px padding/margin）改为统一 `posOf(index)` 访问器（数据驱动，不再读 virtualRow）
- 滚动帧：observer 照常通知（保持 start 正确），但 React 提交被 rAF 合并到"窗口变化帧"；纯位置帧零提交
- 禁止 translateY 增量与绝对 top 叠加（双倍位移）；窗口变化帧必须有复位协议

**C2 行高回填桥接**：
- 移除逐行 measureElement 的替代：HeightOracle 预测 → 实测后写回行高树 → **显式调用 virtualizer.measure()**（或等价刷新协议）→ 单次批量 reflow
- 禁止"保留 measureElement + 期望消除抖动"的双写状态（自相矛盾）

**C3 流式直刷 DOM（招 1 限定版）**：
- 直刷仅限**纯文本末行**（无行内 token/格式的行）；含语法字符的行走正常 append 路径
- dirty 协议必须覆盖渲染路径：直刷期间 React 重渲染会用旧 lineText 覆盖直刷文本——LineItem 对 dirty 行跳过渲染（dirty 标记经 store 传递）
- flush 时机：出现 `\n` / 用户操作触达 / 流式结束 / 滚动到尾部——flush 后 store 与 DOM 一致，恢复常规路径

**C4 尾段零拷贝**：
- 访问器先行：getLine/getLineIndex/渲染统一走访问器，再切存储
- streamTail 上界（如 4096 行）——超限强制合并，防长流式 O(tail) 退化
- 合并时机：滚动触达尾部/用户编辑触达/流式结束

## 6. 集成前验收门槛（V2，08 §2 修订）

1. CommonMark：核心子集 ≥0.99、全量持续增长（黄金判定对锚定投影器）
2. 解析器：2^n 修复、守恒 0 违例、缓存 id 唯一、预算内
3. 行高：滚动条准确性（scrollTop 50% 处首屏行 data-line-start 与 textLength/2 偏差 ≤2 行——替代原"<1 行"不可测项）
4. 帧率：百万行滚动 60fps（P95<16.6ms）+ 500 token/s 流式 60fps
5. 流式：尾段+直刷（限定版）+stop-flush+光标冲突修复全落地
6. 测试：G1-G10 全类落地 + 严格新增 120-140 + 断言点追踪表
7. 稳定：全测试绿/编译 0/编码干净/工作区干净/内存 G9 断言通过
