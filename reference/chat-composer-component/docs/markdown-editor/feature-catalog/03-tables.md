## 0. 本册范围与硬约束

### 0.1 产品冻结（不可推翻）

### 0.2 对标产品（本册比较基准）

| 产品 | 我们取什么 | 我们刻意不取什么 |
|------|------------|------------------|

### 0.3 金标准统一判据（本册每项必须可勾）

一项 F-T-xxxx 标 **金标准** 必须同时满足：

1. **主路径完整**：插入 → 编辑 → 失焦渲染 → 序列化 → 再打开语义一致  
2. **边界完整**：空表、1×1、大表、合并交叉、畸形粘贴、IME、撤销  
3. **键盘可达**：关键操作不必只靠鼠标  
4. **模型正确**：网格真相；covered/anchor 不变量；无整表源码模型  
5. **验收可执行**：本节「验收」条目可自动或 10 分钟人工测完  
6. **模块主人明确**：不进 `editor.js` 上帝堆叠  
7. **失败态可读**：tooltip / reason 中文；导出降级有提示  

只做 UI 壳 = **半成品（≤2 分）**，不算交付。

## 2. 数据与渲染契约（所有 F-T 共用）

> 算法细节可引用 v3-complete；**验收以本册 F-T 为准**。

### 2.1 逻辑网格

```
cells[R][C] 满矩形
anchor 格：内容 + rowspan/colspan
covered 槽：covered:true + anchor:{r,c}；DOM 不输出独立 td
```

**不变量（摘要）**：

| ID | 规则 |
|----|------|
| I1 | 每行列数 = `colCount ≥ 1` |
| I2 | `rowCount ≥ 1`；`hasHeader` 时 r0 为表头语义 |
| I3 | anchor 矩形内除自身外全 covered 且指回 anchor |
| I4 | 合并不越界 |
| I5 | 两 anchor 占用矩形不重叠 |
| I6 | `rows` plain 缓存与 cells 同步（covered 推荐 `''`） |
| I7 | `align.length === colCount` |
| I8 | 默认禁止跨 header/body 合并 |

### 2.2 编辑表面分层

```
表块
 └─ 网格 UI（永不整表 pipe textarea）
     └─ 单元格
         ├─ 默认：WYSIWYG inline surface（runs）
         └─ 可选：cell raw（仅当前格行内 MD 源，非整表）
```

### 2.3 模块主人（实现落点，禁上帝文件）

| 职责 | 建议路径 |
|------|----------|
| 纯函数模型 merge/split/TSV/normalize | `schema` 切片或 `table/model/*` |
| 悬停 +、列宽 handle、菜单壳 | `ui/table-chrome.js`（或拆分） |
| 框选 / 键盘选区 / overlay | `ui/table-selection.js`（新，禁止塞进 editor 巨石） |
| 渲染 / 读 DOM / 命令编排 | `blocks/table` + 薄 editor 挂钩 |
| parse / serialize / 导出策略 | `parse` / `serialize` 表分支 |
| 皮肤与 motion token | `css/.../table.css` + 动效分册变量 |
| 测试 | `tests/**/table-*.test.*` |

### F-T-0001 · 网格编辑锁定（禁止整表源码）

| 字段 | 内容 |
|------|------|
| 优先级 | **P0** |
| 状态 | 规格 |
| 对标 | Notion / Sheets：永远网格；**反** Typora 整表源模式 |
| 模块主人 | `blocks/table` 渲染契约；禁止 `editor` 提供整表 textarea 路径 |

#### 做到最好

- 表块在阅读态与编辑态 **都是结构化网格**；用户认知为「一张表」而非「一段 MD」。
- 聚焦任意单元格 **不会** 把整张表替换为 pipe 源码编辑器。
- 块菜单 / 命令面板 **不提供**「以 Markdown 编辑此表」作为默认或推荐入口。
- 调试用「复制为 Markdown」可以存在，但是 **导出动作**，不是编辑面。
- viewOnly 与可编辑共用同一网格 DOM 骨架，仅 chrome 显隐不同。
- 与段落/标题的「聚焦行源码」模型 **刻意分叉**：表格是结构优先块。
- 文档与 Showcase 必须有一页 FAQ：「为什么表格不显示整表源码？」

#### 非目标

- 高级用户切换「整表源码模式」作为一等公民（若未来加，必须二次确认且默认关，且 **不在本 F 范围**）。

#### 验收

1. 插入表后 DOM 含 `table.mdx-table`，**无** 覆盖全表的单一 `textarea`/`contenteditable` 根。  
2. 连续点击 5 个不同单元格，始终只见网格 + 当前格编辑表面。  
3. 打开含复杂表的 MD，从不自动落入「整表源」。  
4. Code review：禁止新增 `editMode: 'table-source'` 类默认路径。  
5. 人工：产品验收员无法找到「加行/加列」文字按钮与整表源码框（双禁）。

### F-T-0002 · 单元格级编辑 + 可选格内源码

| 字段 | 内容 |
|------|------|
| 优先级 | **P0**（WYSIWYG）· **P2**（格内 raw 开关） |
| 状态 | 规格 |
| 对标 | Notion 格内富文本；Typora **仅借鉴**「源可见」到 **格内** |
| 模块主人 | 格表面 + marks 管道（与行内分册交叉） |

#### 做到最好

- **粒度 = 单元格**：选择、清空、对齐覆盖、合并都以格（及选区）为单位。
- 默认编辑表面：格内 **WYSIWYG**；`**粗**` / `*斜*` / `` `code` `` / 链接在编辑中保持渲染（与全局 marks 管道一致）。
- **同一时刻仅一个格** 处于文本编辑（caret）；多选时是选区态而非多 caret。
- 点击格：进入该格编辑；caret 落在 hit 位置或文末（策略写死：mousedown 可编辑，拖动超阈值转多选，见 F-T-0006）。
- **可选高级**：单元格属性 / 右键「显示单元格 Markdown」→ **仅当前格** 显示行内 MD 源；blur 时 parse 回 runs。
- 格内 **禁止真换行**（GFM 限制）；Enter 语义交给导航（F-T-0005）；Shift+Enter → 插入空格或忽略（写死一种）。
- 空格 **不显示中文 placeholder**（避免表格视觉噪声）。
- covered 槽不可独立进入编辑；命中映射到 anchor。
- IME（中文输入）composition 期间不打断、不重渲丢光标。

#### 非目标

- 格内嵌套 list / code_block / 多段落（P3 评估，非本 F）。

#### 验收

1. 点击 body 格 → caret 在格内；无整表源码。  
2. 输入「你好📦」→ model `text`/`runs` 与 DOM 一致。  
3. 读态含粗体的格，进入编辑仍见粗体（非强制裸 `**`），除非打开 raw。  
4. 打开 raw → 见行内源 → 修改 → blur → runs 更新且读态正确。  
5. 对 covered 区域点击 → 焦点在 anchor，不出现「空壳格编辑」。  
6. 中文 IME 连续输入 20 字不丢字、不跳光标。

### F-T-0003 · 插入默认表与最少结构

| 字段 | 内容 |
|------|------|
| 优先级 | **P0** |
| 状态 | 规格 |
| 对标 | Notion 默认小表；Obsidian 插件常见 2×2 |
| 模块主人 | slash `insert.table` + schema `createBlock('table')` |

#### 做到最好

- Slash `/表格` / `/table`：默认 **3 列 ×（1 表头 + 2 表）**，全空 cell，`align` 全 `left`，`rowspan/colspan=1`。
- 插入后焦点落在 **header 第一格**，可直接输入。
- 最少结构：≥1 列、≥1 行；有 header 策略时删除极端情况仍保持合法 GFM。
- 支持命令：指定行列数插入（P1：`/table 5x4` 或命令面板参数）。
- 默认单元格无「列 1」「列 2」假数据亦可；若用占位文案必须 i18n 且失焦空串策略清晰（推荐 **全空**）。
- 与块拖拽：整表作为原子块可拖，不拆行到段落。

#### 验收

1. slash 插入 → 3×(1+2) 网格可见。  
2. `getDoc()` 中 `cells` 矩形完整，含 merge 字段默认 1。  
3. 序列化为合法 GFM（header + sep + 2 body）。  
4. 删除到极限：仍 ≥1 列且至少可编辑的一行策略符合 F-T-0019。  
5. 撤销插入 → 表消失；重做 → 恢复。

### F-T-0004 · 悬停 + 加行 / 加列（无文字按钮）

| 字段 | 内容 |
|------|------|
| 优先级 | **P0** |
| 状态 | 规格 |
| 对标 | **Notion 标志性 hover +**；明确反对旧式底栏文字按钮 |
| 模块主人 | `ui/table-chrome` |

#### 做到最好

- **右侧中部** `+`：在表末（或当前策略：始终末尾）**加一列**；`align` 追加 `left`；`colWidths` 同步延长。
- **底边中部** `+`：在表末 **加一行** 空单元格（列数对齐）。
- 默认 `opacity:0`；指针悬停表 wrap、表内焦点、或 `.is-chrome-open` 时显示。
- **禁止** 任何可见中文「加行」「加列」按钮（含旧 `.mdx-table-tools` 文字条）。
- `+` 必须是 `button`，`aria-label` 为「添加行」「添加列」（读屏友好；**视觉仍是 +**）。
- 点击有轻微反馈（opacity/scale 受动效分册约束）；`prefers-reduced-motion` 下无夸张动画。
- viewOnly：**不渲染** 或 `display:none` 且不可聚焦。
- 键盘可选：`Alt+=` 加行、`Alt+Shift+=` 加列（写入 keyboard-map；P1 可做）。

## 18. FAQ（产品/用户）

**Q：为什么编辑表格不显示 Markdown 源码？**  
A：行列、合并、列宽是结构操作；网格更安全。Markdown 是保存与交换格式。需要时用「复制为 Markdown」或格内 raw。

**Q：为什么要多选和合并？**  
A：对照表、表头分组、从 Excel 迁入是高频；只有单格 = 玩具表。

**Q：合并后放到 GitHub 会怎样？**  
A：GitHub GFM 不支持合并；导出按策略展开或输出 HTML。Conex 内 JSON/`conex-table` 可保真。

**Q：会做成像 Excel 或 Notion 数据库吗？**  
A：不会做成全功能 spreadsheet/DB。公式列与复杂筛选仅 P2/P3 占位；主战场是 **文档中的专业表格**。

**Q：和标题「聚焦显示 `##`」矛盾吗？**  
A：不矛盾。标题是行内块；表格是结构块。见 §7 分叉说明。
