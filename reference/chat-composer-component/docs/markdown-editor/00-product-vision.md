## 1. 一句话与问题陈述

### 1.1 产品一句话

> 在 Conex 内交付 **Notion 气质的块交互**、**Markdown 可往返**、**阅读态默认精致** 的文档编辑体验：整行/整块实时渲染，可拖拽重排，行首 `/` 与中文 `、` 唤起命令，首挂对话流 Notebook。

### 1.2 现状问题（必须消灭）

| 现象 | 用户感知 | 根因 |
|------|----------|------|
| 整页 blur 才预览 | 「写完才看得见排版」 | 整文档 textarea + 失焦再 `render` |
| `markdown-lite` 极简 | 表格/任务/标题像灰字墙 | 无块模型、无阅读组件 |
| 预览↔源码硬切换 | 「像两个产品在打架」 | 已否决的默认交互（§7.6） |
| 无块拖拽 / 无 slash | 重排靠剪切粘贴；插表靠手写 MD | 缺 Block 模型与命令面板 |
| 控件两端拉扯 | 把手在左、菜单在右，视线来回扫 | 与对话流「左簇」约束冲突 |

**本编辑器不是** `marked()` 再包一层皮肤；是 **内存 Block 树 + 块边界编辑 + Markdown 序列化** 的一等编辑面。

## 2. 产品目标（v1 必须可感知）

目标按用户可验证的能力拆分；实现分期见 `09-implementation-roadmap.md`，此处定义 **Done 时用户能做什么**。

### 2.1 阅读精致（Reading polish）

| ID | 目标 | 可验收标准 |
|----|------|------------|
| G-R1 | 默认 **阅读态** | 打开 Notebook 即见标题层级、列表、表格、任务、callout 的渲染组件，不是 raw MD 墙 |
| G-R2 | 与 Composer 同族 surface | 白底 / hairline / 圆角 / 静态轻 shadow；无 hover 阴影抬升、无侧轨装饰线 |
| G-R3 | 字号与色阶克制 | 正文 ≈14px、辅文 12–13px；标题最多 +1～+2 档；L0/L1/L2 色阶可辨 |
| G-R4 | 表格与 callout 像「组件」 | 表格有对齐与单元格边界；callout 有类型色与图标，非纯 blockquote 灰条 |
| G-R5 | 安全渲染 | HTML 消毒；外链 `rel="noopener noreferrer"`；禁 script |

### 2.2 整行 / 整块编辑（Line & block edit）

| ID | 目标 | 可验收标准 |
|----|------|------------|
| G-E1 | 块边界进入编辑 | 点击文字/空白进入 **该块** 编辑，其它块保持阅读态 |
| G-E2 | 实时预览感 | 退出块或失焦该块后，该块立即回到精致阅读态；**禁止**整页统一 blur 才刷新 |
| G-E3 | 输入热路径局部更新 | 输入不触发「全文 re-parse + 全文 `innerHTML`」 |
| G-E4 | 自动保存 | debounce 300–500ms 写回宿主 / docStore；关面板前 flush |
| G-E5 | 键盘退出 | `Esc`：先关 slash 面板 → 再退出块编辑 → 再关未 pin 的 Notebook（与宿主键盘表对齐） |

### 2.3 拖拽重排（DnD）

| ID | 目标 | 可验收标准 |
|----|------|------------|
| G-D1 | 左侧 6-dot 把手 | hover 块显示把手；拖动出现落点指示线 |
| G-D2 | 同级块重排 | 段落、标题、列表、代码、表格、callout 等可上下重排并写回顺序 |
| G-D3 | 拖拽中阅读态不闪 | 不整页 re-render；仅占位与指示线更新 |
| G-D4 | 键盘可达（最低） | v1 至少提供「上移/下移块」快捷键或菜单项；完整键盘 DnD 可 v1.1 |

### 2.4 Slash 命令（`/` 与 `、`）

| ID | 目标 | 可验收标准 |
|----|------|------------|
| G-S1 | 双触发 | 空段或行首输入 **`/`** 或中文 **`、`（顿号）** 均打开命令面板 |
| G-S2 | 过滤与键盘 | 输入过滤词条；↑↓ 选择；Enter 确认；Esc 关闭并尽量恢复触发字符策略（见 slash 专题） |
| G-S3 | 核心插入 | 至少：H1–H3、段落、无序/有序/任务列表、代码块、引用、表格、分割线、callout |
| G-S4 | 左簇面板 | 面板锚定在光标附近，不与右侧一堆全局按钮抢布局 |
| G-S5 | 中文友好 | 过滤支持拼音首字母或中文名（实现细节见 `05`）；触发符含 `、` 是硬需求 |

### 2.5 宿主与序列化

| ID | 目标 | 可验收标准 |
|----|------|------------|
| G-H1 | Notebook 首挂 | 替换 `NotebookPanel` body；保留 pin / 拖顶栏 / Esc / 顶栏白渐变 |
| G-H2 | Markdown 往返 | 打开 AI 生成 MD → 编辑块 → 再序列化，结构不无故丢失（扩展语法有登记表） |
| G-H3 | 文档类 artifact only | `.md` / 纯文本报告进 Notebook；`.ts/.rs` 等源码路径走 Files 面板，不进本编辑器 |
| G-H4 | 可嵌入 API | 宿主只需提供 `initialMarkdown` + `onChange`/`onSave`；引擎不耦合对话流树 |

### 2.6 目标优先级（冲突时）

```
阅读精致与安全  >  块编辑正确性  >  slash/DnD 完整感  >  扩展语法广度  >  性能极致（万行）
```

万行虚拟列表：文档 **>500 块** 再强制；v1 先保证 API 可插拔（见 briefing 建议默认）。

## 3. 非目标（v1 明确不做）

下列项 **禁止** 占用 v1 工期；若实现 agent 引入，视为越界。

| 非目标 | 原因 | 替代 / 后续 |
|--------|------|-------------|
| **协同 CRDT / OT** | 非多用户实时共编产品阶段 | v2+；预留 doc id 即可 |
| **完整 WYSIWYG Word** | 浮动工具条、复杂样式、分页、页眉脚 | 块级精致 + Markdown，不做版式引擎 |
| **代码文件 IDE** | 语法高亮全语言、跳转、诊断、diff 工作区 | 源码 → 右侧 Files；Notebook 内代码块仅「文档内片段」 |
| **预览 / 源码硬切换为默认** | 用户与 §7.6 已否定 | 可选「复制为 Markdown」或高级「查看源码」抽屉，**非**主模式双 tab |
| **对话流内嵌整页 block 编辑** | 流要冷静扫读，不是第二工作区 | 产物用 chip → 浮层 Notebook |
| **Notion 全套皮肤 / 品牌** | Conex 自有 Composer 语言 | 只借块交互结构 |
| **复杂表格合并 / 嵌套表** | 成本高、序列化脏 | v1：建表、改单元格、增删行列；合并 v2 |
| **插件市场 / 第三方块商店** | 过早 | 内部 `registerBlockType` 足够 |
| **多 Notebook 实例并开** | 规格建议默认单例 | 宿主单例；多文档用切换标题，不并排多浮层 |
| **离线 PWA / 本地 vault 同步** | 超出 artifact 场景 | 工作区文档宿主另开里程碑 |
| **公式排版完整 TeX 编辑器** | 可后置 | 若需要：只读 KaTeX 渲染优先于编辑器 |

## 4. 用户画像与 Jobs-to-be-done

### 4.1 画像 A — AI 生成文档审阅者（主画像）

- **场景**：Agent 输出「重构变更摘要」「测试报告」「迁移说明」等 Markdown artifact。  
- **打开路径**：对话流 Artifact chip → hover/点击 → Notebook。  
- **JTBD**：
  1. **扫读**：30 秒内看懂结构（标题、结论、表格数据）。  
  2. **轻改**：改错别字、补一行结论、勾选任务、调表格单元格。  
  3. **重排**：把「风险」段拖到「结论」前。  
  4. **信得过**：关掉再开内容还在（autosave），不会丢改。  
- **失败态**：blur 才渲染 → 不敢边看边改；源码模式 → 看不懂自己改了什么。

### 4.2 画像 B — 计划 / 任务笔记写作者

- **场景**：计划正文、步骤清单、验收标准写在 Notebook 或未来「计划文档」宿主。  
- **JTBD**：
  1. 用 `/` 或 `、` 快速插入任务列表与标题。  
  2. 勾选任务即时反映（阅读态 checkbox 可点）。  
  3. 与对话流 Purpose 叙事分离：计划细节在文档里，不在流里堆长文。  
- **成功感**：像写 Notion 待办，导出仍是干净 GFM 任务列表。

### 4.3 画像 C — Skill / 说明文档维护者

- **场景**：Skill 说明、工具用法、团队操作手册（中长 MD）。  
- **JTBD**：
  1. 标题层级清晰，callout 标「注意/危险」。  
  2. 代码块可读（复制按钮可后置，v1 至少等宽 + 基础高亮可选）。  
  3. 扩展语法（@mention、文件引用）未来可登记，不破坏往返。  
- **边界**：不把 Skill **源码实现文件** 当 Notebook 打开。

### 4.4 非用户（v1 不服务）

| 角色 | 原因 |
|------|------|
| 实时共编会议记录员 | 无 CRDT |
| 学术长文排版作者 | 无分页/脚注体系 |
| 全职前端用编辑器写 `.tsx` | 应走代码面板 |

### 4.5 JTBD 优先级矩阵

| Job | 画像 | v1 优先级 | 依赖能力 |
|-----|------|-----------|----------|
| 打开即精致阅读 | A | P0 | 行/块渲染 |
| 改一字不丢排版感 | A | P0 | 块编辑 + 局部更新 |
| 拖块重排 | A/B | P0 | DnD |
| slash / 、 插结构 | B/C | P0 | 命令面板 |
| 勾选任务 | B | P0 | task list 块 |
| 改表格单元格 | A/C | P0 | table 编辑 |
| callout 类型 | C | P1 | 扩展 + 视觉 |
| 复制全文 MD | A | P1 | serialize |
| 虚拟列表万行 | C | P2 | 可插拔 API |

## 5. 竞品借用表

原则：**只借结构与交互语法，不借皮肤、信息架构整页与品牌。**  
对话流本身已约束：Notion 的「整页 block 感」不进流；Notebook **内部**可以有块编辑，但仍用 Conex surface。

| 来源 | 借什么 | 不借什么 | 落到本产品 |
|------|--------|----------|------------|
| **Notion** | 块为操作单元；hover 左把手；slash 插块；空段转类型；落点线 | 全套灰底皮肤、侧栏数据库、封面图、评论线程、协同光标、斜体菜单全家桶 | DnD + slash + 块菜单骨架 |
| **Obsidian** | 阅读优先气质；Markdown 为真源；双向链接思想（后置） | **源码/预览硬切换做默认**；重 vault 插件生态；vim 模式优先 | 序列化 MD；默认阅读态 |
| **Typora** | 源码与预览融合的「所写即所得」体感；标题即时样式 | 整篇单一 contenteditable 巨石；弱块模型导致难 DnD | **块边界**融合，而非整页 CE |
| **Linear** | 字重克制、层级少、冷静；列表与标题密度 | 项目管理侧栏、Issue 状态机、快捷键墙 | 视觉 token 与「少按钮顶栏」 |
| **Composer（自家）** | 圆角 surface、hairline、chip、左簇控件 | — | Notebook 外壳与编辑器控件同族 |
| **GFM 生态** | 任务列表、表格、删除线等约定 | 厂商私有 HTML 脏标签当主格式 | parse/serialize 契约 |

### 5.1 刻意差异（Conex 签名）

1. **中文触发**：`、` 与 `/` 并列，不是英文产品的事后 i18n。  
2. **左簇**：把手、插入、块菜单优先左侧聚集；避免「左把手 + 右 `···`」永久两端拉扯（右侧允许极弱次要操作，但不作主路径）。  
3. **宿主分离**：流内冷静 chip；重编辑只在 Notebook 浮层。  
4. **禁令继承对话流**：无侧轨时间线、无 hover 阴影洗版、字号 ≤ 可控档。

## 6. 成功指标

指标分 **量化** 与 **质检清单**；设计轮用清单自检，实现轮接 telemetry 时再接线。

### 6.1 体验时延

| 指标 | 定义 | v1 目标 | 测量方式 |
|------|------|---------|----------|
| **Time-to-first-edit (TTFE)** | 从 Notebook 打开动画完成 → 用户可对任一可见块键入 | ≤ 300ms（冷启动含 parse 中档文档 ≤100 块：≤ 500ms） | 性能标记 `notebook_open` → `editor_ready` |
| **Time-to-reading-paint** | 打开 → 首屏阅读态像素稳定 | ≤ 200ms（≤100 块） | `editor_first_paint` |
| **Block-edit enter** | 点击块 → 光标可输入 | ≤ 50ms | 交互测 |
| **Block-edit exit polish** | 失焦/Esc → 阅读态组件显示 | ≤ 100ms | 交互测 |
| **Slash open** | 输入 `/` 或 `、` → 面板可见 | ≤ 50ms | 交互测 |
| **Autosave latency** | 停止输入 → `onSave` 调用 | 300–500ms debounce + ≤100ms 写回调 | 日志 |
| **DnD drop commit** | 松手 → 顺序稳定 | ≤ 100ms | 交互测 |

### 6.2 正确性

| 指标 | 目标 |
|------|------|
| parse → serialize 往返（核心 GFM 集） | 结构等价率 100%（空白规范化规则见架构文） |
| 扩展语法登记表内往返 | 无静默丢失；无法表示时显式降级块 + 注释 |
| 崩溃恢复 | 刷新前未 flush 的最后一次 debounce 可丢 ≤500ms；关面板必须 flush |
| XSS | 消毒套件用例 0 失败 |

### 6.3 感知精致度检查表（Perceived polish checklist）

实现 / 设计评审 **全部勾选** 才算阅读态达标：

- [ ] 打开文档 **第一眼** 是渲染后的标题与列表，不是 `#` / `-` 灰墙  
- [ ] 表格有清晰网格与单元格 padding，不挤成纯文本对齐  
- [ ] 任务列表 checkbox 可点，完成项有克制删除线或降对比，不刺眼  
- [ ] Callout / 引用有圆角浅底，**无**粗左边框色条（与对话流禁侧轨一致；若类型色用图标+浅底）  
- [ ] 代码块等宽、背景与正文区分弱对比，不霓虹主题  
- [ ] 块 hover 仅显 6-dot 与必要控件，**无**整行阴影抬升  
- [ ] 顶栏按钮 ≤ 必要集（固定、关闭；可选复制）；无分享/侧栏/设置一排 icon  
- [ ] 顶栏白渐变盖住滚动内容，图标始终可读  
- [ ] 空文档有一句克制 placeholder：「输入文字，或键入 / 、 插入…」  
- [ ] 中文标点与西文混排行高 1.6–1.7，不显「挤」  
- [ ] 焦点环符合 a11y，但不破坏冷静气质（细环 / token 色）  
- [ ] 与 Composer 输入区并排截图时，不显得「上面精致、下面简陋」的反转（Notebook 应持平或略偏阅读）

### 6.4 产品结果指标（上线后，可选）

| 指标 | 方向 |
|------|------|
| Artifact 打开后发生编辑的会话占比 | 升高（说明敢改） |
| 打开后 10s 内进入编辑的占比 | 升高（TTFE 体感） |
| 「复制源码/切换源码」求助率 | 降低（说明阅读态够用） |
| 因编辑器卡顿关闭面板的退出 | 降低 |

## 7. UX 原则

### 7.1 原则列表（硬）

| # | 原则 | 操作含义 |
|---|------|----------|
| P1 | **优雅优先** | 任何「能渲染就行」的灰字方案不入库；组件级排版见 `07-visual-system.md` |
| P2 | **冷静** | 过程淡、结论实；编辑器动画短、无弹跳；禁止 hover 阴影洗版 |
| P3 | **阅读默认** | 默认态 = 精致阅读；编辑是短暂、局部的 |
| P4 | **块优先，MD 为序列化** | 内存 `Block[]`；落盘/剪贴板优先 Markdown |
| P5 | **左簇控件** | 把手、`+`、块操作靠左；顶栏右侧只放关闭类 |
| P6 | **精致组件** | 表、任务、callout、代码各自是组件，不是 CSS 偶然样式 |
| P7 | **可扩展注册表** | 新块 = `registerBlockType`，禁止核心 if-else 巨石 |
| P8 | **性能热路径干净** | 禁止全文 `innerHTML = render(all)` 跟输入 |
| P9 | **安全默认** | 消毒、链接 rel、无任意 HTML 执行 |
| P10 | **a11y 非后贴** | 键盘、ARIA、焦点陷阱与浮层规范一起设计 |
| P11 | **与宿主契约清晰** | 外壳（pin/drag/Esc）属宿主；正文编辑属引擎 |
| P12 | **中文一等** | `、` 触发、中文过滤、中文空态文案 |

### 7.2 交互主路径（用户可感知）

```
阅读态块
  hover → 左侧 6-dot（+ 可选左侧 +）
  click 文字/空白 → 该块编辑态
  拖把手 → 重排
  空段行首 / 或 、 → slash 面板 → 插入/转类型
  Esc → 关面板 / 退编辑
  输入停顿 → autosave
```

### 7.3 视觉禁令（继承并扩展对话流）

1. 侧边 border / 竖轨时间线  
2. Hover 阴影、大面积 hover 洗色  
3. 预览↔源码硬切换作默认  
4. 字号档位爆炸  
5. 方块 spinner / 方块 status  
6. 顶栏 icon 堆砌  
7. 高饱和错误大色块（错误用浅标记 + 文案）

### 7.4 文案语气

- 中文产品语气：简短、肯定、不卖萌。  
- Placeholder、空态、错误：说明 **下一步可做什么**。  
- 命令面板词条：中文主名 + 可选英文别名过滤。

## 8. Notebook 必须擅长的内容类型

下列类型是 **v1 质量门**；做不好则 Notebook 失败。细节 schema 见 `02-block-catalog.md` / `blocks/*`。

### 8.1 标题（Headings）

| 要求 | 说明 |
|------|------|
| 层级 | H1–H3 必做；H4 可选；H5–H6 可降级为 H4 或段落+粗体策略（架构裁定） |
| 阅读态 | 字重与间距立刻可扫读；不靠 `#` 字符辨层级 |
| 编辑 | 整块编辑；slash 可转级 |
| 序列化 | ATFM ATx 标题；Setext 可读入、写出偏好 ATX |

### 8.2 表格（Tables）

| 要求 | 说明 |
|------|------|
| v1 必须 | 插入表格（默认 3×2 或 2×2）、编辑单元格、Tab 移动、增删行列 |
| 阅读态 | 对齐、表头区分、横向溢出可滚且不撑破 Notebook 宽 |
| 不做 | 单元格合并、嵌套表、Excel 公式 |
| 序列化 | GFM pipe table；不规则表降级策略见 catalog |

### 8.3 任务列表（Task lists）

| 要求 | 说明 |
|------|------|
| 阅读态可勾选 | 点击 checkbox 即改状态并 dirty → autosave |
| 与无序列表区分 | 渲染与 slash 分条目 |
| 序列化 | `- [ ]` / `- [x]` GFM |
| 嵌套 | v1 支持一层嵌套为佳；更深可后置 |

### 8.4 Callouts（提示块）

| 要求 | 说明 |
|------|------|
| 类型 | 至少 `info` / `warn` / `danger` / `tip`（命名以 extensions 为准） |
| 视觉 | 图标 + 浅底圆角；**避免**粗左侧色条（禁令） |
| 语法 | Conex 扩展 fence 或 `> [!note]` 类；必须可往返 |
| slash | `、提示` / `/callout` 可插 |

### 8.5 其它 v1 应扎实的类型

| 类型 | 最低线 |
|------|--------|
| 段落 | 行内 `**` `*` `` ` `` 链接；编辑时行内标记策略见 line-renderer |
| 无序/有序列表 | 连续块或嵌套策略统一；Enter 续项、Backspace 出列表 |
| 引用 | 阅读态浅底；可与 callout 区分 |
| 代码块 | 语言标签可选；等宽；横向滚动 |
| 分割线 | 克制细线 |
| 纯文本 artifact | mime text 以段落流打开，可升级为 MD 解析 |

### 8.6 明确次优先（可 P1）

- @mention、文件引用 chip 行内  
- 嵌入（图片：安全 URL / 附件 id）  
- 数学公式  
- 高亮 ==text== 等扩展  

### 8.7 内容类型 × 画像  ent

| 类型 | 审阅者 A | 计划 B | Skill C |
|------|----------|--------|---------|
| 标题 | 扫读结构 | 写大纲 | 写手册 |
| 表格 | 改数据 | 排期表 | 参数表 |
| 任务 | 勾验收 | **主战场** | 检查清单 |
| Callout | 读风险 | 写注意 | **主战场** |
| 代码块 | 读片段 | 少 | 用法示例 |

## 9. 风险与开放问题

### 9.1 风险登记

| ID | 风险 | 影响 | 缓解 | 默认策略 |
|----|------|------|------|----------|
| R1 | 整页 contenteditable 回潮 | 光标乱、难 DnD、难局部渲染 | 架构评审卡死「块边界编辑」 | **块模型 + 单块编辑面** |
| R2 | 预览/源码双模式被重新引入 | 违背已决产品决策 | 代码评审黑名单；仅允许「复制 MD」 | **不做硬切换** |
| R3 | 引擎选型瘫痪（PM/TipTap/Lexical/自研） | 设计空转 | reference 阶段 vanilla 验证交互；生产可再评估 | **先 Block Model API，引擎可替换** |
| R4 | Markdown 往返丢扩展 | 用户丢 callout/任务 | 扩展注册表 + 往返测试 | **无测试不进主路径** |
| R5 | 大文档卡顿 | 万行 artifact | 窗口化/虚拟列表 API；>500 块强制 | **先正确后虚拟化** |
| R6 | 表格编辑半成品 | 审阅者主场景失败 | 表格单独 DoD，不与 callout 绑同一里程碑 | **表格 P0 闭环** |
| R7 | 中文 `、` 与中文输入法冲突 | 面板误触/不触 | 仅在行首或空段 + 组成结束后触发；可配置 | **空段/行首 + compositionend** |
| R8 | XSS via MD HTML | 安全事故 | 统一 sanitizer；禁 raw HTML 块默认 | **默认关 raw HTML** |
| R9 | 与 `markdown-lite` 双栈长期并存 | 行为不一致 | 明确 fallback 只读路径与下线日 | **新路径唯一写入口** |
| R10 | Notebook 外壳被改坏 | pin/拖拽回归 | 集成测试保留外壳用例 | **只换 body** |
| R11 | 左簇与块菜单信息过载 | 破坏冷静 | 菜单渐进披露；默认只显把手 | **hover 才显控件** |
| R12 | AI 流式写入与用户同编冲突 | 光标跳动 | 流式期间只读或末尾追加锁 | **流式完成后再允许编辑（建议默认）** |

## 10. 术语表（Glossary）

| 术语 | 定义 |
|------|------|
| **Block（块）** | 文档的一等结构单元：有 `id`、`type`、`props`、可选 `children`。用户拖拽、slash 转换、序列化都以块为界。例：段落、H2、列表项、代码块、表格、callout。 |
| **Line（行）** | 视觉/编辑上的「整行」粒度；多数块在阅读态占据一行或多行视觉行，但 **编辑切换以块为准**。列表场景下「行」可映射为单个 list item 块。文档中「整行渲染」= 不以整页为预览单元。 |
| **Slot（槽位）** | 块内或块间可插入/放置的位置：如块前、块后、表格单元格、列表子级。DnD 落点与 slash 插入点都落到 Slot。实现上可表示为 `{ parentId, index }` 或单元格坐标。 |
| **Slash（斜杠命令）** | 在合法 Slot 输入 `/` 或 `、` 触发的命令面板：过滤、选类型、插入或转换当前块。不是全局应用菜单。 |
| **Serialize（序列化）** | 将内存 `Block[]` 转为可持久化格式的过程；**主格式为 Markdown**（含已登记扩展）。反之为 parse。往返 = parse(serialize(doc)) 在结构上等价（按规范化规则）。 |
| **Host（宿主）** | 挂载编辑器的外壳环境：提供容器 DOM、初始文档、保存回调、只读/流式状态、主题 token。**首个 Host** = 对话流 `NotebookPanel`；未来可为工作区文档、Skill 说明、计划正文。Host 负责 pin/拖拽/Esc 关层面板；Editor 负责块文档。 |

### 10.1 易混澄清

| 说法 | 正确理解 |
|------|----------|
| 「整行编辑」 | 不是浏览器 `contenteditable` 整页一行；是 **按块/行边界** 进入编辑 |
| 「阅读态」 | 精致组件渲染，可含可点 checkbox；不是预览 tab |
| 「源码」 | Markdown 字符串形态；可复制，不作默认双模式 |
| 「Artifact」 | 对话流产物芯片背后的文档对象；mime 为 markdown/text 时进 Notebook |
| 「扩展」 | 超出 GFM 的语法/块，必须进注册表才能往返 |

## 11. 成功叙事（验收故事）

### 故事 S1 — 审阅变更摘要

1. 用户在对话流看到 chip「重构变更摘要」。  
2. 点击 pin 打开 Notebook：立刻看到 H1、表格「模块 | 变更」、任务列表「待回归」。  
3. 修改表格一格「影响面」；拖动「风险」callout 到文首。  
4. 键入 `、` 插入「提示」callout，写一句给同事。  
5. 关闭面板；再打开内容仍在。全程 **没有** 切换「源码模式」。

### 故事 S2 — 写计划任务

1. 空文档 placeholder 提示 `/` 与 `、`。  
2. `、任务` 插入 task list，连续 Enter 写五项。  
3. 勾选两项；阅读态立即反映。  
4. 导出/保存为 GFM，外部编辑器可见 `- [x]`。

### 故事 S3 — 反例（必须失败）

1. 用户点击源码路径 `src/foo.ts` → **不得** 进 Notebook；应走 Files。  
2. 产品经理要求加「预览 | Markdown」tab → **拒绝**，改提供「复制 Markdown」。
