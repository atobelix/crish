# 00 — 现状与差距

> 体检对象：`reference/chat-composer-component` 现有文件预览。  
> 结论：壳有雏形，**解析与架构未达标**，需系统性重构而非补丁。

---

## 1. 现有资产

| 资产 | 路径 | 评价 |
|------|------|------|
| 打开入口 | `window.openPreview(card)` | 可用，API 过窄 |
| 实现 | `js/preview-modal.js` ~676 行 | **单体**，格式分支硬编码 |
| 样式 | `css/preview-modal.css` | 有机中性色，但与 flow tokens 未统一 |
| 壳 HTML | `index.html` `#previewModal` | image / table / pdf 三 viewport |
| 图片能力 | 缩放、旋转、裁剪、画笔 | 功能最完整 |
| 表格 | CSV 文本拆分 + mock 数据 | xlsx **未真解析** |
| PDF | `renderRealPdfFile` | **假 HTML 段落**，非 pdf.js |
| Word | 走 default 分支 | 当 PDF 假页，**零解析** |
| Markdown | 无 | 无 viewport、未接编辑器 |
| 代码 | 无专用 | 无 |
| 图标 | `assets/icons/*` | 扩展名图标可复用 |

---

## 2. 能力对照（现状 vs 目标）

| 格式 | 现状 | 目标 |
|------|------|------|
| 图片 jpg/png/webp/gif | 真预览 + 工具 | 保留并组件化 |
| CSV / TSV | 真文本表 | 分块/大文件友好 + 虚拟滚动可选 |
| JSON / log / txt | 强行表格化 | 代码/纯文本 viewer |
| XLSX | mock 或失败 | SheetJS 真表 |
| PDF | **假页面** | pdf.js 真页 + 缩略图 |
| DOCX | **假页面** | mammoth 消毒 HTML |
| MD / MDX | 无 | MarkdownEditor **view-only** |
| PPTX | 无 | P2 元信息 + 下载 |
| 未知 | 假 PDF | 元信息 + 下载 |

---

## 3. 架构问题

1. **无适配器层**：解析与 DOM 渲染缠在一起。  
2. **无 PreviewModel**：每个格式私自写 `innerHTML`。  
3. **无能力矩阵**：工具栏按钮与格式能力未解耦（PDF 与图片控件混杂风险）。  
4. **无按需依赖**：未来 pdf.js 若同步引入会拖垮 demo。  
5. **动效弱**：`classList.add('active')` 仅 CSS opacity，缺系统化 motion。  
6. **与 Markdown 双轨**：Notebook 可编辑，预览却接不上同一渲染内核。  
7. **错误诚实性不足**：假内容比「不支持」更伤信任。

---

## 4. UI 问题（高级感）

- 与对话流 / Composer 的 token 体系统一不足  
- 工作台密度、标题栏、工具栏层级可再精炼  
- 切换 viewport 时无过渡，观感「硬切」  
- 表格内联 style 色块（绿/黄/红 pill）风格略旧，宜收敛到 design-tokens  

---

## 5. 重构原则（从差距反推）

1. **拆壳、拆适配器、拆 Viewer**  
2. **真解析或诚实降级**  
3. **Markdown 只复用不重写**  
4. **工具栏 = capability**，不为解释模式服务  
5. **motion 对齐 conversation flow**  

→ 详见 02 / 03 / 04 / 06。
