## 文末：栏 A 能否宣称「点保存 → 磁盘出现字段」闭合

**栏 A（源码形状）：可以宣称该动词已接线闭合，不能宣称用户磁盘已被改写。**

闭合的是这条因果链的形状：

```
抽屉草稿 → draftToModelPatch → await updateModel → updateTree
  → serializeModelsYamlTree（thinking / modalities / pricing.cacheRead / contextWindow / capabilities.tools）
  → workbench_save_models_yaml({ content })
  → 成功才 models-catalog-changed
  → openConfigFor(selectModel) 重开
```

手填 / 扫描 / 启用 / 删除 / 协议 / Base URL 汇入同一 `updateTree`。一次性导入有完成标记，之后 `ensureLsImported` 不再读三把配置键。生产 settings-models 不以 `applyMetaForModel` / `setModel*` / `upsertPrice` 为保存真源。

**栏 B / 栏 C：不能宣称闭合。** 本审计未跑测、未跑 4000。完成定义是读磁盘文件，不是「函数被调用」也不是「测文件里 expect yaml」。

**不要关账：** Composer / Picker 读路径（仍 `getModelMeta` / `setModelThinkingLevel`）；出站 HTTP 体 / `request_options`；会话费用。那些是 γ / δ。

### 是否阻断 γ

**不阻断 γ 启动。** γ 依赖的是「写成功后树在 store + 事件已发 + 设置草稿读 store」。栏 A 上这三件事已接线。残留（侧栏 getModelMeta、选择器 128000、PriceConfigModal LS、导入 tools）是 γ 读切或补洞对象，不是「保存仍只写 LS」那种硬阻断。

若主控把「用户真机点保存见到 yaml 字段」当成 β 出关条件，则 **栏 C 未过，β 产品链动词不能对用户关账**——那是验收分层，不是禁止 γ 改 Composer 读路径。
