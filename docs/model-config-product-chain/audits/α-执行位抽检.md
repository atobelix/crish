## L. 新引入 fallback / TODO / 双轨

**判定：未过**

S1 文件域内无 `TODO`/`FIXME` 字面量。问题是 **双轨仍在**，与 `plans/01` §4.6「与 IPC 同一套 v2 解析」、§9「禁止新增兼容层」冲突。

### L1. 两套 v2 解析器（本维应合并，未合并）

| 路径 | 入口 | 行为差 |
| --- | --- | --- |
| IPC 读/校验/保存 | `models_yaml.rs:378` `parse_models_yaml` → `UnifiedModelsYamlFile` / `ModelsYamlProviderV2` | 空文件诚实空树；仅 v1 `models` 可 `providers: None`；先 `normalize_yaml_read_aliases`；供应商 `displayName`/`baseUrl` 为 `Option` |
| live / 投影 | `catalog_types.rs:49` `UnifiedModelsConfig::from_yaml_str` → `ProviderSpec`（`display_name`/`base_url` 必填） | 仅 v1 `models` **直接 Err**（`:63-66`）；**不**走 IPC 那套别名归一；缺 `displayName` 会反序列化失败 |

save 成功后：`save_models_yaml_at` 用 IPC 解析器校验（`models_yaml.rs:598`），再 `reload_live_catalog()`（`:603`）从磁盘用 **另一套** `LiveModels::load_user` → `from_yaml_str` 重解析。  
U5 原文：「`reload_live_catalog` 与 IPC save 共用同一解析。」当前不是同一套。IPC 能保存的树，live 可能 `Err` 而保持上一份快照——磁盘与 live 短暂分叉。

`DynamicYamlModalities` 符号已删除（仅注释残留 `catalog.rs:376`）。旧第二解析器形态换了，**不是**单一解析。

### L2. Store 仍认 `data.tree`

`modelsCatalogStore.ts:98-117`：优先 `providers`，否则 `data.tree?.providers`。  
生产 IPC 已在客户端组装 `tree`（`modelsCatalogIpc.ts:240`），Store 不必再开第二入口。这是双轨读，不是 `convertFlat`，但违反「禁止 `wire.tree` 兼容层」的精神。

### L3. 壳层 DTO 与内核树未并成一份 struct

`ModelsYamlModelV2` / `ModelsYamlProviderV2`（`models_yaml.rs:147-197`）与 `ModelSpec` / `ProviderSpec` 平行。thinking/modalities 已复用内核类型，但供应商必填性、`capabilities` 残留（`:174`）、扁平 `models` 仍返回（`:234`）构成第三份运行形状。U1「直接复用 catalog_types，禁止再复制一套 struct 行为分叉」未收干净。

### L4. `live_catalog` 从未成功时解析失败 → 返回 `empty()`

`protocol.rs:110-122`：`LiveModels::load_user()` `Err` 时 **不写入** `LIVE_CATALOG`，但向调用方 `Arc::new(LiveModels::empty())`。  
文件缺失走 `Ok(empty)`（`catalog.rs:734-736`）是诚实空树。解析失败返回同一空树形状，调用方无法区分「没有配置」与「坏文件」。有上一份快照时 `reload_live_catalog` 会保持（`protocol.rs:128-135`，测试 `:408-418`）。**首次**失败仍像空配置。§4.6 允许「显式错误态」替代；当前不是显式错误。

### L5. 热重载监听是 no-op（有意，但 Store 仍接线）

`setupModelsYamlHotReloadListener`：`modelsCatalogIpc.ts:330-334` 直接 `return () => {}`。  
Store 成功加载后仍注册：`modelsCatalogStore.ts:245-248`。U3 允许删死接线或真 emit；现状是半截调用 + 空实现。不算幽灵命令，但是空壳双路径。

### L6. 选择器仍发明 128000（不在 α 写集，同权记录）

`modelsCatalogSelectors.ts:47-52`：模型无 `contextWindow` 时 `return 128_000`。  
测试仍钉该回退：`modelsCatalogStore.test.ts:751-752`。  
与 M11 / U1「缺省不发明 128K」冲突。类型层已 Option，读选择器未改。属 S3 读路径也可修，但 **α 之后镜像选择器仍发明窗口**，不能假装类型改完就消失。

本项 **不**把 E 的 Default 清空 map 算缺陷。
