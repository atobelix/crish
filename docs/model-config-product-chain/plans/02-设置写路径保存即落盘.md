## 0. 结论先行

当前设置抽屉的「保存」是 **LocalStorage 写路径**，磁盘 `~/.conex/models.yaml` 不被触碰。新轨 `modelsCatalogStore.updateModel` 在生产 UI **零调用**。未提交工作区把 `modalities` / `thinking` / `pricing` 经 `upsertModelMeta` 写进 `crish_model_meta_v1`，这是加固旧岛，**丢弃，不作为本维正路**。

本维把设置写面接到唯一物理真源：

```
草稿（cfgDraft / 服务商协议 Select / 启用开关 / 手填 / 扫描差集）
  → 字段映射为 ModelSpec / ProviderSpec（规范名）
  → modelsCatalogStore.updateModel | addModel | updateProvider | addProvider
  → updateTree
  → writeModelsYamlIpc（S1 闭合后的诚实 IPC = workbench_save_models_yaml）
  → 磁盘 ~/.conex/models.yaml 含同等字段
  → emitUiEvent('models-catalog-changed')   // S3 读路径刷新契约
```

YAML 文本弹窗 `YamlConfigEditorModal` **已经**直打 `workbench_save_models_yaml`，保持同一写路径，本维不另起炉灶。

## 1. 本维效果锁与非目标

### 1.1 效果锁（缺一不可）

用户在设置里做下列任一动作后，**读磁盘文件**（不是读内存、不是读 LS、不是「函数被调用」）必须看到对应字段：

| 用户动作 | 磁盘必须出现 |
| --- | --- |
| 改思考映射表（TitleCase → wire）并保存 | 该模型节点 `thinking:` 为拍平字典；非思考模型该键缺省，不得写空对象 |
| 改多模态 input/output 并保存 | 该模型节点 `modalities.input` / `modalities.output` |
| 改四维单价（含独立 `cacheRead`）并保存 | 该模型节点 `pricing.input` / `output` / `cacheRead` / `cacheWrite` / `currency`；留空则该键缺省，不得写 0 冒充免费 |
| 改服务商默认协议 | 该供应商节点 `protocol:`（规范字面量，Google = `google/generate-content`） |
| 改上下文长度并保存 | 该模型节点 `contextWindow:`（禁止落盘 `contextLength` 作为 yaml 字段名） |
| 改展示名 / 最大输出 Token / 工具开关并保存 | `displayName` / `maxOutputTokens` / `capabilities.tools` |
| 点启用/停用开关 | 该模型节点 `enabled:` |
| 手填或扫描确认新增模型 | yaml 该供应商 `models[]` 出现该 `id`，且后续保存能改到**同一节点** |

同一动作不得再写入：

- `localStorage['crish_model_meta_v1']`
- `localStorage['crish_model_prices_v1']`
- `localStorage['crish_provider_profiles_v1']` 的 **配置字段**（`protocol` / `models` / `baseUrl` 作为能力与目录真源）

凭据（API Key / OAuth / `hasKey`）仍走既有 DPAPI 槽，**禁止**把明文密钥抄进 yaml。这不是第二配置真源，是密钥隔离（反过度设计禁令 8）。

### 1.2 非目标（诚实边界，不是砍效果）

本维 **不** 宣称下列已完成（分属其它维；本维不得为它们发明第二真源）：

| 非目标 | 归属 |
| --- | --- |
| IPC 读回 `providers` 树、消灭幽灵命令 `models_yaml_*`、消灭 `convertFlatModelsToTree` | **S1**。本维消费 S1 的写命令；S1 未闭合则本维不得手拼扁平列表「凑合写盘」 |
| Composer / Picker / 发送前视觉 / 思考档位面板读同一棵树 | **S3**。本维必须广播 `models-catalog-changed`；订阅方是 S3 |
| 出站 HTTP 体含 yaml 字典；`EngineProviderConfig.request_options` 灌 `thinking_map` | **S4**。本维文件域禁止改 `engine_provider` |
| 会话费用 = `PricingEngine` 微元 | **S5**。本维禁止再 `upsertPrice` 进 LS 价表，但不改 Rust 计费 |
| 四态输入 / token / sticky / 保存钮视觉 | **S6** |
| 物理删除 `modelCatalogMeta` 模块、陪葬测试、LS 数据键 | **S7**。本维停写；数据键留给 S3 读切之前的过渡，S7 再删 |
| 真窗口全链（发一条带图/带思考的消息） | **S8** |

设置抽屉 **自身** 在保存成功后必须从 store 重开草稿（写面读回自己刚写下的树）。这不是偷 S3 的活：若保存后仍 `getModelMeta` 重开，用户看到的是 LS 残影，本维效果锁当场失败。

### 1.3 三原则仍生效的旧战役锁

1. `thinking` 拍平 TitleCase → wire；缺省 = 非思考，不得写 `levels` / `mandatory` / `defaultLevel`。
2. `cacheRead` / `cacheWrite` 为独立绝对单价，禁止「输入价 × 0.1」在写路径物化。
3. 预填库只在用户键入模型 ID 或点「智能预填」时填 **草稿**；保存空价 **不得** 把预填/catalog 牌价当成用户配置写进 yaml。

`applyMetaForModel`（`modelsIpcHelpers.ts:66-177`）逐项调用：

### 2.2 生产 UI 从不调用 store 写

全仓 `modelsCatalogStore.updateModel` 生产调用 = 0。定义在 `modelsCatalogStore.ts:277-278`，纯函数在 `modelsCatalogActions.ts:144-181`，引用仅 `modelsCatalogStore.test.ts`。

`debounceSaveModelsYaml`（`modelsCatalogIpc.ts:311-342`）生产 **零调用**。本维点保存必须 `await updateTree` 当时落盘，禁止把保存钮接到 300ms 防抖（用户点保存 = 磁盘已有字段，不是「过一会儿大概有」）。

### 2.4 YAML 弹窗是唯一诚实写面（保持）

`YamlConfigEditorModal.tsx:257-275`：`invokeTyped('workbench_save_models_yaml', { content })`；missing/error → `serviceError`，`canSave` 为 false；成功后 `ensureModelsCatalogLoaded(true)`。本维 **不得** 把它改成 LS，也不得让抽屉保存改走「拼一段 yaml 字符串绕过 store」。弹窗与抽屉必须汇合到同一磁盘文件、同一命令。

### 2.5 打开草稿读的也是 LS

`openConfigFor`（`useModelConfigSession.ts:51-155`）`getModelMeta` + `resolveModelPrice` + 预填兜底。字段名是 `contextLength`、`defaultThinkingLevel`、`capabilities.image`。yaml 规范名是 `contextWindow`、`thinking` 字典、`modalities.input`。

`modelMetaRevision`（`modelProfilesHelpers.ts:25-34`）只签了 displayName / contextLength / tools / image / reasoning，**签不到** thinking 字典、modalities、pricing、protocol。CT-01 对 Wave 4 新字段是盲的。

### 2.6 `profileStorePersistence` 不是配置真源

`saveProfiles` / `loadProfiles`（`profileStorePersistence.ts:38-54,57-153`）读写 `crish_provider_profiles_v1`，空库播种 `DEFAULT_PROFILES`，坏 JSON `catch` 静默播种（问题 22）。本维之后它 **只允许** 作为凭据壳（id 对齐、hasKey、密钥槽），禁止再承担 protocol / models[] / 能力 / 价格。

### 2.7 L10：未提交 setter 不是正路

审计 15 / 21 与当前 `modelCatalogMeta.ts:316-355` 一致：`setModelModalities` / `setModelThinking` / `setModelPricing` 全部 `upsertModelMeta` → `crish_model_meta_v1`。`modelCatalog.ts:56-58` 再导出它们。`applyMetaForModel` 已在调这些符号。

**处置（本维强制）**：

- 工作区这批 diff **丢弃，不提交**。
- 实现不得「先提交 setter 让抽屉编译通过，再慢慢迁 yaml」。
- 实现不得把 setter 改成「内部转调 `updateModel`」而保留 LS `saveMap`——那仍是双写。
- 正路：设置层不再 import `setModel*`；`applyMetaForModel` 这个名字（Meta = LS）废止，换成草稿 → `Partial<ModelSpec>` 的纯映射，再 `store.updateModel`。

## 3. 与相邻维的接口契约

### 3.1 依赖 S1（输入；未闭合则本维禁止降级施工）

S1 必须已经保证，本维才能诚实落盘：

1. 生产写命令只有 `workbench_save_models_yaml`（L3）。`writeModelsYamlIpc` 不得再先打未注册的 `models_yaml_write`。
2. 写入的是 v2 `providers` 树文本；`serializeModelsYamlTree` 保留 `thinking` / `modalities` / `pricing` / `protocol` / `contextWindow`（`modelsCatalogIpc.ts:181-184` 已有拷贝，S1 须让这条成为 **唯一** 序列化，禁止再走 `convertFlatModelsToTree`）。
3. Rust 解析 `ModelsYamlModelV2`（`models_yaml.rs:140-165`）含 thinking / modalities；保存后读回 `providers` 而不是扁平 `models`。扁平 `ModelsYamlModel`（`:87-106`） **没有** thinking/modalities——若 S1 仍让前端读扁平再重建，本维刚写入的字段会在下次 `ensureLoaded` 被丢掉（问题 4、5）。
4. 协议规范名 `google/generate-content`；别名只在边界单向归一，运行时不双枚举（问题 16）。
5. 类型只活在 `modelsCatalogTypes.ts` ↔ `catalog_types.rs`。禁止在 `modelCatalogTypes.ts` 再复制树状契约（L10）。

**S1 未闭合时本维的合法动作**：停工上报，列出缺的 IPC 字段/命令。  
**非法动作**：手拼 yaml、把树拍扁再写、写失败改写 LS、「先保证按钮在」。

### 3.2 本维向 S3 的输出保证

1. 任意成功写（抽屉保存 / 协议 Select / 启用开关 / 手填 / 扫描差集 / YAML 弹窗）之后，`modelsCatalogStore.getState().tree` 与磁盘一致（写失败则内存回滚，磁盘不变）。
2. 成功写 **必须** `emitUiEvent('models-catalog-changed')`（`updateTree` 已在成功枝发送，`modelsCatalogStore.ts:257`）。禁止改成只发 `model-meta-changed` / `profiles-changed` 冒充。
3. 本维不负责让 Composer 订阅该事件；但 **禁止** 以「反正没人听」为由删掉广播。S3 的完成定义是读路径订这个事件并丢掉 `getModelMeta`。
4. 设置抽屉打开/保存后的草稿，字段来自 `selectModel(providerId, modelId)`，不再来自 `getModelMeta`。

### 3.3 本维不向 S4 伸手

`save_models_yaml_at`（`models_yaml.rs:472-479`）成功后已调 `reload_live_catalog()`。热路径是否改读 `live_catalog()` 是 S4。本维文件域 **禁止** 改 `engine_provider.rs` / `build_chat.rs` / `dialect.rs` / `protocol.rs` 出站决议。即使发现 `live_catalog` 仍 `#[allow(dead_code)]`，只在本文件「上报 S4」一笔带过，不在本维修。

### 3.4 身份对齐（写面与 yaml 键）

- yaml 供应商键 = 设置里的 `ProviderProfile.id` 规范化小写（与 `modelsCatalogActions` 已有 `trim().toLowerCase()` 同构）。
- 不发明第二张「profileId ↔ vendor」对照表，不靠展示名模糊匹配合并（`findCatalogModel` 不传 providerId 的串线正是问题 15）。
- 一次性导入用 **同一 id** 把 LS 档案写进 `providers[id]`。`deepseek` 对 `deepseek`；`opencode-go` 就是 `providers.opencode-go`，不要猜成 `deepseek`。

## 4. saveConfig 的唯一合法调用序

设置层所有「把用户改过的模型能力变成真源」的动作，最终必须进入同一条核。`saveConfig` 是抽屉的显式提交；其它即时控件（协议、启用）走同一核的短路径，见 §5。

### 4.1 正序（实现必须按此顺序，不得插 LS 枝）

```
1. 若 selected / configOpenId / cfgDraft 缺一 → return（与现守卫同）
2. await ensureLsImported()          // §6，幂等；未完成不得写
3. await modelsCatalogStore.ensureLoaded()
4. providerId = selected.id.trim().toLowerCase()
5. modelId    = configOpenId
6. 若 store 无该 provider → addProvider（displayName/baseUrl/protocol 来自当前选中档案壳，无 apiKey）
7. 若 store 无该 model    → addModel({ id: modelId }) 再继续（手填未落盘的残态）；不得静默 no-op
8. CT-01：用打开时快照的 modelSpecRevision 与当前 selectModel(...) 签名比对
        不一致 → notify(false, 已有文案) + invalidate 编辑会话 + return
        签名字段见 §4.3，来源是 store 不是 getModelMeta
9. patch = draftToModelPatch(cfgDraft)     // 纯函数，§4.2
10. res = await modelsCatalogStore.updateModel(providerId, modelId, patch)
11. 若 !res.ok → notify(false, res.error)；草稿保留；return
        （store 已回滚内存；此处禁止再 saveMap / upsertPrice / saveProfiles）
12. editSessionConsumer.commit(objectId)
13. 清本地 rev；按 store 当前节点重开草稿（openConfigFor 改读 selectModel）
14. 到此磁盘已有字段；models-catalog-changed 已由 updateTree 发出
```

禁止出现的序：

- `applyMetaForModel` → 任何 `setModel*`
- `upsertPrice`
- `refresh()` 以 `loadProfiles()` 当保存成功的证据
- `openConfigFor` 再 `getModelMeta`
- 写失败 → 写 LS「至少别丢」
- 先 `models_yaml_write` 再 fallback
- 把 `cfgDraft` JSON 整棵塞进 LS 再异步「同步到 yaml」

`saveConfig` 必须是 `async`（或 `void runAsLocalMutation(async () => …)` 且 **await updateModel**）。当前 `useModelConfigSession.ts:185` 的同步 lambda 非法。

`runAsLocalMutation` 仍可用于挡住「自己写盘触发的外部失效提示」。外部失效的事件源从 `profiles-changed` 扩到 **`models-catalog-changed`**（YAML 弹窗保存、其它窗口、本抽屉其它控件）。有未保存草稿则提示 + invalidate，不静默 LWW。

### 4.2 `draftToModelPatch`：草稿 → yaml 规范字段

纯函数，无 IO。输入 `ConfigDraft`，输出 `Partial<ModelSpec>`。禁止输出 LS 形状。

| 草稿字段（现状） | yaml / ModelSpec | 规则 |
| --- | --- | --- |
| `displayName` | `displayName` | trim；空则 `undefined`（序列化省略，展示回退 id） |
| `contextLength` 数字串 | **`contextWindow`** | 只写 `contextWindow`；禁止 yaml 出现 `contextLength` 键（问题 17） |
| `maxOutputTokens` | `maxOutputTokens` | 同现：正整数才写 |
| `caps.tools` | `capabilities.tools` | 布尔 |
| `caps.image` / `caps.video` | **不作为独立真源** | 由 `modalities.input` 推导；序列化时 `capabilities.image/video` 若仍写出，必须与 modalities 同向，禁止永久双写互斥值（L11） |
| `caps.reasoning` / `thinkingEnabled` | `thinking` 在或不在 | 见下行 |
| `thinkingEnabled` + `thinkingMap` | `thinking: Record<string,string>` | 开启且清洗后非空 → 拍平字典；`thinkingEnabled === false` → `thinking: undefined`（键缺省）。禁止 `levels` 嵌套，禁止把 UI 当前档写成 yaml 字段 |
| `thinkingLevel` / `defaultThinkingLevel` | **不写 yaml** | yaml 无该字段（问题 18）。当前选档是会话偏好，S3 处理。本维 `setModelThinkingLevel` 停用 |
| `protocol`（模型级，若草稿有） | `ModelSpec.protocol` | 覆盖供应商默认；缺省则省略（继承 `ProviderSpec.protocol`）。Google 只允许规范名 `google/generate-content` |
| `modalities` | `modalities.{input,output}` | 原样；input 至少语义自洽（允许用户去掉 text，不在写路径偷偷加回） |
| `pricing.*` 字符串 | `pricing.{currency,input,output,cacheRead,cacheWrite}` | 见 §4.4 |

清洗 thinking 键值：与现 `modelsIpcHelpers.ts:105-116` 同——空键、空值丢掉。不得把 `STANDARD_THINKING_PRESET` 在用户关掉思考后仍写入。

### 4.3 `modelSpecRevision`（取代 `modelMetaRevision`）

打开时对 `selectModel(providerId, modelId)` 做稳定 JSON 签名，字段 **至少**：

`displayName, contextWindow, maxOutputTokens, enabled, protocol, thinking, modalities, pricing, capabilities.tools`

实现从 `modelProfilesHelpers.ts` 的 `getModelMeta` 依赖改为 store 选择器。禁止继续只签三个 cap 布尔（thinking/pricing 外部改了却仍「rev 一致」会陈旧覆盖）。

### 4.4 价格写规则（L9 的写面部分）

- 规范键：`input` / `output` / `cacheRead` / `cacheWrite` / `currency` / 可选 `unit`。
- **禁止** 落盘 `inputPerMTok` 等别名（L11：一次性导入可从旧键读入，导入后写路径只写规范键）。
- 四维皆空 → `pricing: undefined`（优雅静默）。禁止写全 0。
- `cacheRead` 是用户填的绝对数。禁止 `cacheRead = input * 0.1`（`DEFAULT_CACHE_READ_MULTIPLIER` 不得出现在本维写路径）。
- **禁止** `upsertPrice`。S5 的账本是 Rust `PricingEngine` 读 yaml；前端价表不是真源。
- **禁止** `applyMetaForModel` 现 `else` 枝（`modelsIpcHelpers.ts:159-176`）：未配单价时把 `findCatalogModel` 牌价抄进 LS。保存空价 = yaml 无 pricing，不是「帮用户填目录价」。
- 用户点「智能预填」只改 **草稿**；点保存后预填数字才成为 yaml 字段（此时是用户确认过的配置，不是运行时偷偷读预填库）。

### 4.5 协议写规则

抽屉里单模型协议下拉已被物理移除（`ModelConfigPanel.test.tsx`「100% 物理移除协议下拉」——这是 UX，S6 维持）。协议的用户改口在 **服务商** `ProviderProfileForm` Select。

- Select `onChange` → `modelsCatalogStore.updateProvider(id, { protocol })`，即时 `await` 落盘（与现「改了就 upsertProfile」同构，只换真源）。
- 选项必须含 S1 规范四值：`openai/chat` / `openai/responses` / `anthropic/messages` / `google/generate-content`。禁止只加 `google/interactions`。
- 模型草稿若带 `protocol`（手填联想 `ManualAddForm.tsx:112` 会写入 `addDraft.protocol`），`addModel` / `draftToModelPatch` 把它当作模型级覆盖写入。

### 4.6 上下文写规则

- 用户在「上下文长度」框里输入的数字 → yaml `contextWindow`。
- 打开草稿时：`String(model.contextWindow ?? '')`，不要读 `contextLength`，不要 `guessContextLength` 把猜测值展示成已保存配置。
- 保存时未填合法正整数：不要用 128000 假上限补；保留节点原值或省略（与「用户没改」同义）。禁止 `KNOWN_CONTEXT` 回潮。

## 6. 一次性 LS → yaml 导入（产品需要，不是永久兼容层）

L11：存量 LS 只允许 **一次性** 导入 yaml 的迁移函数；有完成条件；导入后禁止再写 LS 配置；禁止永久双读 `input`∥`input_per_m_tok`、`capabilities.image`∥`modalities.input`。

### 6.1 为何必须做

用户真正的 Wave 4 配置在三把 LS 键里，yaml 默认模板是空树（`models.default.yaml`：`version: 2` + `providers: {}`）。若只改 `saveConfig` 而不导入，用户一点保存：要么 `updateModel` throw「模型不存在」，要么写到空树上丢掉历史。效果锁要求 **已有配置** 也出现在磁盘，不是只对「本会话新改的那一行」生效。

这不是「长期双轨」。完成条件一旦满足，导入函数对生产写路径是死代码；S7 删除模块。

### 6.2 读哪些 LS（只读一次）

| 键 | 用途 | 不得当作 |
| --- | --- | --- |
| `crish_provider_profiles_v1` | 供应商 id / name / baseUrl / protocol / models[] | 密钥：跳过 `apiKey` 明文，不写入 yaml `apiKey` |
| `crish_model_meta_v1` | 仅 **JSON 里实际存在的键** | `getModelMeta` 的 `guessContextLength` 缺省、空记录模板 |
| `crish_model_prices_v1` | 仅当该键 **存在且解析为数组** 的用户条目 | `loadPrices()` 在缺键时返回的 `DEFAULT_PRICES`（会把种子牌价伪造成用户配置） |

`getModelMeta` / `loadPrices` / `loadProfiles` 都有缺省与坏 JSON 播种。导入必须走 **raw `localStorage.getItem` + JSON.parse**，缺键 = 该源为空，不调用会写回 LS 的 `saveProfiles`（`loadProfiles` 空库会 `saveProfiles(DEFAULT_PROFILES)`，导入过程禁止触发这条）。

坏 JSON：该源视为空，**fail-closed 不播种**（问题 22 不得在导入器重演）。yaml 若已 parseError，**整次导入放弃**，不覆盖用户可修复的文件。

### 6.3 合并规则（禁止三向合并 / AST diff）

反过度设计：与 `probeIncremental` 同构，ID 集合运算 + 缺字段填充。yaml 已有的用户文件是真源。

对每个 LS provider `id`（小写）：

1. yaml **没有** 该 key → 追加整个 `ProviderSpec`（displayName、baseUrl、protocol 归一、models 由下款构造）。不拷密钥。
2. yaml **已有** 该 key → 保留 yaml 的 displayName/baseUrl/protocol（已在文件里的值赢）。仅当 yaml 该字段 **缺省** 且 LS 有明确值时填洞。
3. 对该 provider 的每个 LS 模型 id：
   - yaml 无此模型 → **追加** 节点（LS meta 实有字段 + 价表实有字段，映射为规范名）。
   - yaml 已有此模型 → **按字段填洞**：yaml 该字段已存在（含显式 `false` / `0`）则不动；yaml 缺省且 LS 实有则填。禁止 LS 覆盖 yaml 已有 thinking/pricing。

字段映射（导入读侧允许旧名，写入 yaml 只写新名）：

| LS / 旧 | yaml |
| --- | --- |
| `contextLength` | `contextWindow` |
| `pricing.input` 或价表 `inputPerMTok` | `pricing.input` |
| `cacheRead` / `cacheReadPerMTok` | `pricing.cacheRead`（原样数字，不乘 0.1） |
| `protocol === 'google/interactions'` | `google/generate-content`（单向） |
| `capabilities.vision` | 并入 `modalities.input` 含 `image`（存量 `vision` 迁移，导入器做一次，之后 yaml 不保留 `vision`） |
| `modalities` 实有 | `modalities` |
| 仅有 `capabilities.image/video` 无 modalities | 生成 `modalities.input`（text + 对应项），避免永久双读 |
| `thinking` 字典实有 | `thinking` |
| `defaultThinkingLevel` | **丢弃，不写 yaml** |
| `enabled === false` | `enabled: false`；缺省视为 true 且 yaml 可省略 |

预填库、`catalog.json`、`CATALOG_CACHE_RATES` **不参与导入**。

### 6.4 完成条件（必须可判定，禁止无日期 fallback）

导入成功的 **同一事务** 内：

1. `store.updateTree(merged)` 返回 `ok`（磁盘已是合并树）。
2. 写入完成标记。推荐一把 **非配置** LS 键，例如 `crish_models_ls_import_v1 = { "done": true, "version": 1 }`。这不是模型配置，禁止任何运行时读它来填 thinking/price。
3. 之后 `ensureLsImported()` 见 `done === true` → 立即 return，**零读** 三把配置键。

失败：不写完成标记；下次仍可重试。不得在 catch 里标记完成。不得「过一段时间算了」（问题 22 无日期降级）。

导入后：

- 生产写路径 **零** `localStorage.setItem` 针对 `crish_model_meta_v1` / `crish_model_prices_v1` / 配置字段的 `crish_provider_profiles_v1`。
- **不删除** 这三把键的数据（S3 读路径未切，S7 再物理删除）。L11「导入后删除 LS 配置写」= 删写路径，不是本维清空用户浏览器。
- 禁止双写「yaml + LS 保险」。

### 6.5 触发点

`ensureLsImported` 挂在 **每一次** 本维写入口之前，以及设置页 `ModelsSettingsTab` 挂载时（与现有 `ensureModelsCatalogLoaded` 并列）。幂等、单飞（一个 Promise），禁止并发两次 `updateTree` 互踩。

不要做启动全局自动在用户没打开设置时静默改 yaml——但设置页是本维写面，进入即导入，否则用户看到的列表与即将保存的树分裂。

### 6.6 明确不是什么

- 不是 `loadProfiles` 与 store 的长期同步器。
- 不是每次保存前把 LS diff 进 yaml。
- 不是 `profileStorePersistence` 的新职责——导入器是独立纯模块（建议 `apps/crish-desktop/src/api/modelsLsImport.ts`），读 raw LS，写 store，自己不 `saveProfiles`。

## 12. 打开草稿与列表：写面最小读切

- `thinkingEnabled` = `Boolean(model.thinking && Object.keys(model.thinking).length)`

## 13. 与 YAML 弹窗共写同一文件时的冲突

两入口合法，都写 `~/.conex/models.yaml`：

- 弹窗：整文件文本，Rust 校验失败则不落盘。
- 抽屉：结构化 patch → serialize 整树 → 同一命令。

冲突语义（CT-01）：

- 抽屉打开期间弹窗保存成功 → store `version++` 且 `models-catalog-changed` → 抽屉视为外部变更：有草稿则拒绝下一次 saveConfig 覆盖，提示重开。
- 弹窗打开期间抽屉保存 → 弹窗已有 dirty 检测（`YamlConfigEditorModal.tsx:87,305-310`）；本维不改弹窗 UX，但 store 重载后若弹窗仍显示旧 `originalCode`，那是弹窗自己的脏集。不在本维做三窗 OT。

禁止加「合并引擎」。后写覆盖是原子整文件写；用 rev 拒绝陈旧抽屉草稿，而不是合并。

## 15. 上报主控的缝（本维看见、不私自扩面）

1. **S1 前置**：`writeModelsYamlIpc` 仍先 `models_yaml_write`（`modelsCatalogIpc.ts:254-267`）。本维调用 `updateTree` 会撞这条。S1 必须先把生产写切到 `workbench_save_models_yaml` 且序列化保留树字段，否则本维验收「读磁盘」会在幽灵命令/扁平重建上失败。

3. **问题 18**：yaml 无 per-model 默认档位。若产品要「每个模型记住上次档位」，应在 S1 加字段或明确它只属于会话 settings。本维不偷加。
4. `loadProfiles` 坏 JSON 静默播种（`profileStorePersistence.ts:145-152`）仍在。本维导入器绕过它；S7 再拆。不要在本维「顺便」改播种逻辑导致设置页空窗。
