## 0. 一句话效果锁（用户可感知增量）

会话结束后（或流式 usage 到达后），UI 上的费用数字 **=** `~/.conex/models.yaml` 四维单价经 Rust `PricingEngine` 微元定点的结果。改 yaml 价格再跑一条，数字跟着变。禁止继续用 LocalStorage 牌价做 JS 浮点账本。

完成北极星上本维负责的两环：

```
SSE usage 进入 PricingEngine
    → 会话 UI 展示的费用 = 微元定点结果
```

`pricing_tests.rs` / `devil_cases_tests.rs` 只证明**算法函数体存在**，不是产品链。禁止只跑这两套当本维完成。

## 3. 锁定语义（L9 展开，禁止另起炉灶）

### 3.1 唯一计算入口

```
生产路径禁止出现的算费：
  ModelPricingSpec::calculate_cost
  selectEstimatedCost
  estimateCostUsd / estimateCostUsd4d / estimateSavingsUsd
  tokens/1e6 * price 的任何 JS / f64 账本
  input * 0.1 乘数
  bundled_catalog().input_price_for * f64（含浪费预警）

唯一入口：
  PricingEngine::calculate_cost
  PricingEngine::calculate_cost_from_usage
  PricingEngine::calculate_cost_from_spec   // 仅当 spec→ModelPricing 不丢字段
  CostBreakdown::from_usage / CostBreakdown::calculate  // 薄包装，仍进引擎
```

`catalog_types::ModelPricingSpec::calculate_cost`：**删除**，或改成：

```rust
pub fn calculate_cost(...) -> Option<CostBreakdown> {
    PricingEngine::calculate_cost_from_spec(&Some(self.clone()), ...)
}
```

禁止再返回 `f64`。`catalog_types.rs:485` 那条「1M input + 2M cache_read = 7.7、不扣减」测试必须改成引擎语义（扣减后输入段为 0，不得再钉 7.7）。

### 3.2 cacheRead 是否从 prompt 扣减（单一真值）

锁定 **现行引擎**（`pricing.rs:354-360`），不以 C9 token 恒等式改写账单：

```
non_cached_prompt = prompt_tokens.saturating_sub(cache_read_tokens)
input_micros       = tokens_to_micros(non_cached_prompt, input_rate)
cache_read_micros  = tokens_to_micros(cache_read_tokens, cache_read_rate)
cache_write_micros = tokens_to_micros(cache_write_tokens, cache_write_rate)
output_micros      = tokens_to_micros(completion_tokens, output_rate)
```

- **扣 `cache_read`，不扣 `cache_write`。** write 是独立第四维。Claude 用例（prompt=200_000, read=150_000, write=50_000）已钉：输入段 = 50_000×input，write 段另乘 write 价（`pricing_tests.rs:70-75`）。
- `cache_read > prompt` → `saturating_sub` 归零，不 panic（`pricing_tests.rs:398-401`）。
- C9 `miss = prompt - read - write`（Included）是 **缓存计量**，不是账单公式。`computeCacheMetrics` / `CacheBreakdown` 继续管命中率；**不要**把 miss 拿去乘 input 价当第二套账。
- 前端 `estimateCostUsd4d` 的 `prompt - read - write` **作废**，不得迁进 Rust「纠正」引擎。

本维不把 `CacheAccounting` 塞进 `PricingEngine` 签名（那是改公式，不是接线）。usage 按引擎四个 u64 原样喂入。

### 3.3 无单价 / 免费 / 已定价（三态，禁止塌成 0）

| live 上的 pricing | 引擎返回 | UI 文案 | 禁止 |
| --- | --- | --- | --- |
| 整块缺失 `None` | `None` | **未定价** | 显示 ¥0 / $0 / 免费；再跑 `estimateCostUsd` |
| `Some`，`tiers` 空，input/output/cacheRead/cacheWrite 皆 0 | `Some(CostBreakdown { is_free: true, formatted_total: "免费" })` | **免费** | 显示未定价；显示 $0.0000 |
| `Some`，有非零费率或有阶梯 | `Some`，`is_free: false`，`formatted_total` 带 ¥/$ | 引擎字符串 **原样** | 前端 `toFixed` 重算；硬编码 `$` |
| `Some`，阶梯命中后微元为 0 | `is_free: false`，`formatted_total` 为 `¥0.0000` 或 `$0.0000` | 显示该格式化串 | 显示「免费」（K-13 语义锁） |

S2 必须保证：编辑器四格全空 → yaml **省略** `pricing` 键（已有「留空 = undefined」口径）。若写出 `pricing: { currency: CNY, input: 0, output: 0 }` 会被引擎当成显式免费。本维按引擎结果展示；空键 vs 显式 0 的写入纪律归 S2，本维验收时用「无 `pricing` 键」构造未定价。

缺某一维（如只有 input/output、`cache_read: None`）：引擎 `unwrap_or(0.0)`，该维微元为 0。**整块存在**就不算未定价。

### 3.4 货币

- 只认 yaml `pricing.currency`：`CNY` | `USD`（`Currency` / `CurrencyKind` 已互转，`pricing.rs:45-62`）。
- `formatted_total` 由 `PricingEngine::format_micros` 生成（¥ / $，4 或 6 位规则已有）。前端 **禁止**自己拼 `$` + `number.toFixed`。
- 禁止隐式 USD：live 条目有单价但无 currency → 视为目录损坏，本维按未定价处理并打 warn，不得 `Currency::default()`（USD）入账。
- 多 run 累计：只对 **同一 currency** 把 `total_micros` 做 `saturating_add`。混币种 → 总览不显示相加金额，展示「多币种」或只列出最近一次 `formatted_total`。禁止汇率折算。

### 3.5 价从哪取

```
live_catalog()  →  (provider_id, model_id) 精确命中
                →  Option<ModelPricing>
```

- provider_id = yaml 树的供应商键（与 S1 灌入 `EngineProviderConfig` 的身份同一），**禁止** `infer_vendor(base_url)` / `catalog_vendor()` 把 `deepseek` 变成 `auto` 后找不到价。
- 字段：`currency, input, output, cacheRead, cacheWrite`，可选 `tiers`（`PricingTier.input_tokens_above` + `input`/`output`）。
- **禁止**：`bundled_catalog()`、`CATALOG_CACHE_RATES`、`crish_model_prices_v1`、`input * 0.1`、`input.or(input_per_m_tok)` 第三套双读（S1 应在 live 投影里已经归一成 `input`；本维只读归一后字段）。
- `From<ModelPricingSpec>` 不得 `tiers: Vec::new()`。S1 若尚未把 `tiers` 放进 `ModelPricingSpec`，本维 From 仍须有拷贝位（空向量只能来自「spec 真没有阶梯」）。yaml/TS `inputCost`/`outputCost` 与 Rust `input`/`output` 的字段名同构归 S1；本维消费 `pricing.rs::PricingTier`。

峰谷 2x、storage $/1M·h、Anthropic 1h 写价档、`catalog_price.rs` 半开区间 `[min,max)`：**不进入会话账单**。会话账单 = yaml 四价 + 引擎阶梯（`input_tokens_above` 倒序）。不要在本维把 catalog.json 的 `tieredPricing` 再接一套匹配器（审计 17 K-08：两套阶梯并存；本维收敛为引擎这一套）。

### 3.6 何时算、算几次、写到哪

**算一次（每个带 usage 的 provider 收口）**，不是前端每帧、不是 hydrate 时按最新牌价重算历史。

推荐落点（分层不破）：

1. `session-loop` 继续只聚合 token（`consume_cache_usage`）。**不**新增对 `agent-provider` 的 crate 依赖。
2. `engine_build.rs` 在 `session_loop.run()` 返回后、已有 `outcome.cache_stats` 的同一收口点：
   - `let pricing = live_model_pricing(provider_id, model_id);`
   - `let cost = PricingEngine::calculate_cost(pricing, prompt, completion, read, write);`
   - 写入 `RunUsage.cost`（`Option<CostBreakdown>`）
   - 写入 `RunSnapshot.usage`
3. 多 turn 的 run：`cache_stats` 已是 run 级求和。**用求和后的四计数调用一次引擎**（与当前 tracker 聚合对齐）。不要对总和再套一遍「按单次请求门槛」之外的二次阶梯发明；阶梯匹配的 token 口径 = 这次喂给引擎的 `prompt_tokens`（即 run 聚合 prompt）。若日后要「每 turn 一笔账再加微元」，另开增量，本维不先做两套。

历史账单：快照里的 `CostBreakdown` 是入账时点的账，**改 yaml 不改写旧 run**。用户侧「改价再跑一条数字变」指 **下一条新 run**。

前端：

- `parseRunSnapshotUsage` 增加 `cost: CostBreakdown | null`（`null` = 未定价）。
- `applyRunUsageSnapshot` **删除** `import pricingStore` 与 `pickUsageCostEstimators`。
- `accumulateTokenUsage` 只累加引擎给出的 micros / formatted / currency / 三态。
- `applyStopUsageApprox`：无 usage 样本 → **不得**估费用；token 可用正文近似，费用保持「未定价」或本 run 不写 cost。
- `DELAY_AFTER_STOP_MS` 只允许作为「快照落定」时序，**不允许**当算费算法。有事件携带 cost 则不必靠它算钱。

浪费预警 `waste_alert_event`：同一份 live 单价，用引擎微元表达「若这批 miss 按 input 价 vs 按 cacheRead 价」的差，**禁止**再写 f64 乘除和 `bundled_catalog`。字段若仍叫 `missed_cost_usd` 而币种是 CNY，属于撒谎——改为带 currency 的微元或直接复用 `formatted_total` 差；改事件字段走 `conex-types` 注册表 + 生成绑定（本维允许，因为这是计费呈现，不是思考方言）。
