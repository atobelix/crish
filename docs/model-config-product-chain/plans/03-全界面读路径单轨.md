## 0. 结论先行

设置保存（S2）把树写入 `~/.conex/models.yaml` 并灌入 `modelsCatalogStore` 之后，**主对话模型选择器、思考档位胶囊、附图入口必须只读这一棵内存树**。不刷新整应用、不读 LocalStorage 当配置、不读 `thinkingGear` / `catalog_get` 当档位白名单、不靠模型名正则猜视觉能力。

当前产品读路径仍是多轨（证据见 §2）。本维把生产读路径收成一条：

```
磁盘 yaml（S2 已落盘）
  → live_catalog（Rust，S1/S4 热路径；本维不改 Rust 出站）
  → modelsCatalogStore（前端唯一镜像，L2）
  → 唯一读 API（§3，返回 ModelSpec / ProviderSpec）
  → Composer / Picker / 设置读侧 / 发送前视觉守卫
```

选中的思考档位**不是** yaml 字段（问题 18：yaml 无 `defaultThinkingLevel`，本维不发明该字段）。档位**能力**读 yaml `thinking` 字典；档位**选中值**落在会话运行时字段，发送时拷进请求选项交给 S4。

## 1. 本维效果与非目标

### 1.1 用户可感知增量（效果锁，不得降级）

1. 用户在设置里改思考字典 / `modalities.input` / 展示名 / 启用开关并保存（S2）后，**不必刷新整应用**：主对话模型下拉、融合胶囊思考档、附图是否可挂，立即与 yaml 一致。
2. 用户删除或改名某个模型并保存后，主对话下拉**立即**不再出现旧 id / 立即出现新 id。
3. 思考模型：档位按钮的**可见标签 = yaml `thinking` 字典的 key**（TitleCase，如 `Low` / `High`）；发送时交给引擎的是对应 **value（wire）**。字典缺省或空 → 思考胶囊 **DOM 物理卸载**（三条原则第 1 条）。
4. 纯文本模型（`modalities.input` 不含 `image`）：加图入口不可用（粘贴 / 拖放 / 文件选择里的图片均不得挂上），不是「仍能挂上、发送时再 abort」。
5. 跨厂商标识串线消失：所有按模型查询必须带 `providerId`。

### 1.2 非目标（诚实边界，不是砍效果）

| 不做 | 理由 | 归属 |
| --- | --- | --- |
| 不实现设置「保存即写 yaml」 | 写路径是 S2；本维假定 S2 闭合后 store 已是 yaml 投影 | S2 |
| 不改出站 HTTP 方言装配、不灌 `EngineProviderConfig.thinking_map` | 本维只把「当前 ModelSpec + 选中 Title」交到请求选项 | S4 |
| 不把 `PricingEngine` 接入 session-loop，不删 JS 价表模块 | 本维只保证 S5 能从同一 `ModelSpec.pricing` 读到四维单价 | S5 |
| 不改设置抽屉视觉 token / 四态输入 / sticky | 读路径单轨与样式是不同文件域 | S6 |
| **不删除** `modelCatalogMeta.ts` / `thinkingGear.ts` / `crish_model_meta_v1` / `loadProfiles` 模块 | 物理删除归 S7；本维之后**生产读路径不得再调用它们当配置** | S7 |
| 不把 `defaultThinkingLevel` 写进 yaml | 问题 18 的正解是「选中值不是模型配置」 | 本维明确拒绝 |
| 不把预填库 / `catalog.json` / `bundled_catalog` 当运行读源 | 预填只在用户**键入新模型 ID** 时建议填充（三条原则第 3 条） | S1/S4/S7 |
| 不引入第二套 React store、不复制 `ModelSpec` 为 ViewModel、不写中间件流水线 | 反过度设计：选择器 + 已有 `models-catalog-changed` tick 足够 | — |

### 1.3 本维之后必须为真的不变量

- 生产 UI 读配置：只允许 `modelsCatalogStore` 投影（`selectModel` / §3 API）。
- 生产 UI 刷新配置：只允许 `models-catalog-changed`（或与之同步的 `modelsCatalogStore.subscribe`）。**禁止**只订 `model-meta-changed` 当作「设置已保存」。
- `findCatalogModel` 的 `providerId` 为必参；禁止 `globalModelIndex[0]` / 平铺扫描兜底。
- `isModelVisionSupported` / `checkModelVisionSupport` 只读 `modalities.input`；禁止正则 fail-open。
- Composer / Picker 禁止 `import` `thinkingGear` 的 `resolveCatalogEfforts` / `fetchDescribeEffortsSnapshot` / `THINKING_LEVEL_LABELS`。

## 3. 唯一读 API（从 store / live 投影）

### 3.1 原则

- **类型**：返回 yaml 同构的 `ModelSpec` / `ProviderSpec` / `IndexedModelEntry`（`modelsCatalogTypes.ts:123-206`），禁止再包一层 `LiveModelView`。
- **定位键**：一律 `(providerId, modelId)`，大小写不敏感，与现有 `modelIndex` 键 `${normPId}::${normMId}` 一致（`modelsCatalogStore.ts:109-114`）。
- **载体**：扩展现有 `modelsCatalogSelectors.ts` + `modelsCatalogQuery.ts` 的 `findCatalogModel` 签名；新增一个薄模块集中 **生产只读门面**，避免每个组件自己 `getState().modelIndex.get`。
- **禁止**：新 Zustand store、新 IPC、把 `CatalogModelSpec` 当能力真源、在读路径做 `google/generate-content` → `google/interactions` 改写（协议字面量以内核为准，S1 已锁）。

建议模块路径（实现可同名或并入 selectors，但 **对外符号名必须如下，且只有这一份**）：

`apps/crish-desktop/src/api/modelsCatalogLive.ts`

若行数门禁不允许新文件膨胀，允许把符号放进 `modelsCatalogSelectors.ts` 并从此处 re-export。禁止第三份拷贝。

### 3.2 符号与语义

```ts
/** 未加载或找不到 → undefined。禁止返回猜测对象。 */
function getLiveProvider(providerId: string): ProviderSpec | undefined;

function getLiveModel(providerId: string, modelId: string): ModelSpec | undefined;

/** 启用中的供应商 × 启用中的模型，供 Picker / 设置列表。顺序 = yaml 对象插入序。 */
function listLivePickerEntries(): IndexedModelEntry[];

/** modalities.input 含该模态。modalities 缺省或 input 非数组 → false（闭）。 */
function modelAcceptsInput(
  providerId: string,
  modelId: string,
  modality: string
): boolean;

/**
 * thinking 为非空字典 → 支持思考。
 * 选项 = Object.entries(spec.thinking)，label=key，wire=value。
 * 无合成「默认」项。
 */
function listThinkingOptions(
  providerId: string,
  modelId: string
): { title: string; wire: string }[];

/**
 * 选中 Title 对当前字典的解析，供 UI 与 S4。
 * selectedTitle 不在字典内 → 回落到字典第一项；字典空 → supported=false。
 */
function resolveThinkingHandoff(
  providerId: string,
  modelId: string,
  selectedTitle: string | null
): LiveThinkingHandoff;
```

`LiveThinkingHandoff`（本维定义，S4 只消费、不改语义）：

```ts
type LiveThinkingHandoff =
  | {
      supported: false;
      providerId: string;
      modelId: string;
      thinking: undefined;
      selectedTitle: null;
      selectedWire: null;
    }
  | {
      supported: true;
      providerId: string;
      modelId: string;
      thinking: Record<string, string>; // yaml 字典全文，S4 用作 thinking_map
      selectedTitle: string;            // 字典 key
      selectedWire: string;             // 字典 value
      thinkingFormat?: ThinkingWireFormat; // provider.compat ?? model.compat，可空，S4 再决
    };
```

`getLiveModel` 必须原样交出 `thinking` / `modalities` / `pricing` / `protocol` / `contextWindow` / `enabled` / `displayName` / `compat`。S4、S5 的「当前 (provider, model) 的 ModelSpec」就是这个函数。

### 3.3 `findCatalogModel` 必须带 `providerId`

改签名（`modelsCatalogQuery.ts:151-154`）：

```ts
function findCatalogModel(
  modelId: string,
  providerId: string
): CatalogModelSpec | undefined;
```

- `providerId` **必填**。缺参在类型层即失败。
- 只走 `modelIndex.get(`${normPId}::${normMId}`)`；可保留同供应商 `models[]` 精确 id 匹配。
- **删除** `:183-190` 的 `globalModelIndex[0]` 与 `listCatalogModels().find` 兜底。
- 生产能力/视觉/思考 **禁止**再调用本函数；改走 `getLiveModel`。本函数若仍被联想补全使用，也必须传当前正在编辑的 `providerId`。
- `modelToCatalogSpec` 丢掉 thinking 是门面缺陷：本维不靠它读思考。S7 再删门面。

## 4. 思考档位：字典 key 为标签，value 为 wire；选中值交给 S4

### 4.1 能力面（有哪些档）= yaml `ModelSpec.thinking`

三条原则第 1 条已锁：

```yaml
thinking:
  Low: "low"
  Medium: "medium"
  High: "high"
```

- UI 标签 = key 原文（`Low`，不是「低」，不是 `THINKING_LEVEL_LABELS`）。
- Wire = value 原文（可能是 `low` / `HIGH` / `enabled` / `disabled`，本维不翻译）。
- 字段缺省或 `{}` → 非思考模型 → `ComposerFusedTrigger` 右侧档位 **不渲染**（已有 `isThinkingModel &&` 外壳，条件改为 `listThinkingOptions(...).length > 0`）。
- 禁止合成 `value: 'default'` 项（`thinkingGear.ts:104-105`）。yaml 没有这个键，S4 也无法映射。
- 禁止 `resolveCatalogEfforts` 的正则保底把 `r1` 变成 `off/low/medium/high`。

`thinkingGear.ts` 判定：**是平行真源，本维之后生产不得读。** 文件保留到 S7。`bootstrap-full` 可暂留 `fetchDescribeEffortsSnapshot`，但 Composer 不得依赖其完成。

### 4.2 选中面（当前哪一档）≠ yaml 字段

问题 18：`defaultThinkingLevel` 只活在 LS。正确解不是把它补进 yaml（那会把会话偏好写成模型能力），而是：

| 层 | 存什么 | 生命周期 |
| --- | --- | --- |
| yaml / store | `thinking` 字典（能力） | S2 保存 |
| **会话字段** | `thinkingTitle: string \| null`（字典 key） | 本会话运行时 |
| **请求选项** | 发送瞬间的 `{ thinkingTitle, thinkingWire }` + 完整 `thinking` 字典引用 | 一次 run-task |

**会话字段位置（指定，禁止第三处）：** `SessionRuntimeRegistry` 的 `SessionRuntimeState` 增加 `thinkingTitle?: string | null`（`SessionRuntimeRegistry.ts:27-36` 已按会话隔离 attachments，档位与附件同级、不进 `SessionState` 消息库、不进 yaml）。

不选 `SessionState`：避免把 UI 档位写入会话 SQLite 正文，和 S5 费用快照抢持久化语义。不选全局 `appSettings`：换模型后旧档位名会脏污染。

读写：

- Composer / Picker 点某一档 → `sessionRuntimeRegistry.save(sessionId, { thinkingTitle })`。
- 读展示：`resolveThinkingHandoff(providerId, modelId, runtime.thinkingTitle)`。
- 字典被 S2 改掉、当前 title 消失：handoff 回落到字典第一 key，并回写 runtime，避免胶囊显示幽灵档。
- 切到非思考模型：`thinkingTitle = null`，胶囊卸载。
- 切回思考模型：若 runtime 仍命中新字典则保留，否则第一 key。

新会话 / runtime 无值：用字典第一 key（yaml 插入序），不是 settings 里的 `default`。

### 4.3 交给 S4 的契约（请求选项，不是让 S4 再读 LS）

在 `StreamRequestOptions`（`chatApi.ts:47-87`）增加（名称固定，S4 按此取）：

```ts
thinkingTitle?: string;  // yaml key，Off/Low/High…
thinkingWire?: string;   // yaml value，已按当前 live 字典解析
```

组装点：`slashSendPreflight` 组 payload 时（与视觉守卫同一处，保证发送与 UI 同一快照）调用 `resolveThinkingHandoff`，写入 `finalStreamOptions`。

S4 必须：

- 用 `thinkingWire` 填出站参数；用 `getLiveModel`（Rust 侧 `live_catalog`，L5）的完整 `thinking` 字典当 `thinking_map`。
- **禁止**再 `toLowerCase(settings.defaultThinkingLevel)`（`streamSession.ts:107-111` 的读法在 S4 删除；本维可先让 streamSession **优先**读 `options.thinkingWire`，settings 仅当 options 缺省时的死代码，S7 再删）。
- `supported: false` → 不传 `reasoningEffort` / 不注入思考参数（省略 ≠ 伪造 Off，除非字典里真有 `Off` 且用户选了它）。

用户选了 yaml 里的 `Off`：`selectedTitle="Off"`，`selectedWire` 为字典值（如 `"disabled"`）。这是显式关闭，S4 必须发出对应 wire，不得当成「省略」。

### 4.4 Composer 写路径在本维的变化

`ComposerFusedTrigger.selectLevel`（`:73-88`）**停止**调用 `setModelThinkingLevel`（LS）。**停止**把档位当模型配置写入 yaml。可以暂时继续 `clientApi.updateSettings({ defaultThinkingLevel })` 但不作为任何生产读源——实现时宁可删掉这行双写，以免测试误把 settings 当 SSOT。推荐本维直接去掉对 `defaultThinkingLevel` 的读和写。

Picker 底部「高级选项」思考条（`ModelBadgePickerMenu.tsx:246-270`）与融合胶囊必须同一会话字段、同一 `listThinkingOptions`。禁止一处中文标签、一处 TitleCase。

## 6. 事件：`models-catalog-changed` 为唯一配置刷新

### 6.1 规则

| 事件 | 本维之后的合法用途 |
| --- | --- |
| `models-catalog-changed` | **唯一**「yaml 镜像变了」信号：列表、档位、视觉、展示名、启用、窗口 |
| `modelsCatalogStore.subscribe` | 与上一行同拍的同步监听，允许 |
| `model-changed` | 仅活动 `(providerId, modelId)` 切换 |
| `model-meta-changed` | 生产 UI **禁止作为配置刷新源**。S7 前模块仍可 emit，本维调用方必须卸订阅 |
| `profiles-changed` | 不得驱动 Picker 模型列表。S7 前密钥岛可留 |

S2 保存路径必须（已由 store `updateTree` 保证）在写盘成功后 emit `models-catalog-changed`。本维实现 Agent 若发现 S2 只写 LS 并发 `model-meta-changed`，视为 S2 未闭合，**不得**把 Picker 改回订 meta 事件「先用着」。

### 6.2 删除 / 改名立即反映

`listLivePickerEntries` 每次按当前 `tree.providers` 现算，无另一份 id 缓存。

当前活动模型被删或改 id：

- 复用 `resolveActiveModelAfterMetaChange`（`ModelsSettingsTab.tsx:59-88`）的 **同厂商自愈、禁止跨厂商** 规则，但 `isModelEnabled` 改读 `getLiveModel(...).enabled !== false`，触发源改 catalogVersion。
- 活动 id 在 live 树中不存在 → 同供应商下一个启用模型；没有 → 置空活动模型，徽标走「选择模型」，不得静默切到别的供应商的同名 id（问题 15）。

### 6.3 不刷新整应用

不要求 `location.reload`。store 内存树替换 + 事件 + 选择器同步读取即可。`ensureLoaded(true)` 仅用于外部编辑 yaml / 热更新（store 已有 `setupModelsYamlHotReloadListener`，`:211-214`）。
