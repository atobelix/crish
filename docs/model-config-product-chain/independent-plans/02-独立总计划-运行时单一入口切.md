# 独立总计划 · 运行时单一入口切

> **工作区**：`docs/model-config-product-chain/`
> **切分角度（全文唯一组织轴）**：进程内只允许一个「按 `(providerId, modelId)` 取规格」的函数。协议、思考字典、模态、价格、窗口、兼容字段、出站头策略全部从这一入口长出。UI 只是该入口的投影与编辑器。
> **效力**：独立总计划草稿，供主控合并 `00-总方案.md`。不关账，不改产品源码。
> **锁定**：`00-调度与执行纪律.md` L1–L12；`.agents/LOGIC_PLAN_NO_RETREAT.md`；`docs/agent-roles/general_task/三原则.md`。
> **规划模式**：纯逻辑。只规定不变量、依赖边、任务单元、文件域、验收断言。问题同权。
> **禁止**：把 URL contains、前缀表、LocalStorage meta、`bundled_catalog`、`catalog.json`、预填 JSON、扁平 `models` 重建树、无 `providerId` 的全局首条命中当成入口。

## 0. 诚实边界：借鉴与新提出

**借鉴（只作输入，不当完成声明）**

- L1–L12、§3 用户侧产品链、§4 问题全集 1–24、S1–S8 依赖边：`00-调度与执行纪律.md`。
- 代码事实：审计 `12`（URL/前缀/方言）、`19`（IPC fail-open / `providers` 被丢）、`20`（无日期 fallback / 双字段）、`21`（主控二次汇总）。
- 当前源码（本会话读过）：`protocol.rs`、`engine_provider.rs`、`vendor.rs`、`catalog.rs`、`catalog_types.rs`、`models_yaml.rs`、`modelsCatalogStore.ts`、`modelsCatalogQuery.ts`、`modelsCatalogSelectors.ts`、`modelCatalogMeta.ts`、`modelsCatalogIpc.ts`、`modelsIpcHelpers.ts`、`ComposerFusedTrigger.tsx`、`slashSendPreflight.ts` 等。
- 三条旧战役仍有效原则：thinking 拍平 TitleCase→wire；`cacheRead`/`cacheWrite` 独立绝对单价；预填库只在用户键入模型 ID 时建议填充。

**本切新提出（不是把旧 00 换封面）**

1. **入口不变量 I-LOOKUP**（见 §1.2）：能力问题的答案只能来自一个函数，而不是「同一棵 yaml 树上挂着很多查询函数」。
2. **`live_catalog` 必须索引 `UnifiedModelsConfig` 树，而不是把 yaml 投影进 `ModelCatalog` 扁平条目后再 `lookup(vendor, model)`。** 后一种即使改读 yaml，仍是第二套入口（版本后缀剥离、`*` 厂商默认、跨厂 `lookup_by_model_id`）。
3. **`EngineProviderConfig.provider_id` 是入口能存在的前提**，不是出站维才补的字段。没有这对键，内核只能继续 URL 猜厂商。
4. **身份合一**：yaml `providers` 键 ≡ 活动选择 `providerId` ≡ 凭据槽键 ≡ `EngineProviderConfig.provider_id`。LS `ProviderProfile` 不再是另一套 id。
5. **三仓分类**：规格仓（lookup）、选择指针（哪一对正在用）、凭据仓（按 providerId 取 secret）。只有规格仓回答能力问题。
6. **精确匹配**：禁止 litellm 式后缀剥离与「全局首条同名模型」。未命中就是 `None`。
7. **运行时禁止扁平 `CatalogModelSpec`**：`modelToCatalogSpec` 会把 `google/generate-content` 反映射成 `google/interactions`，并双读价格字段——这是入口污染，不是兼容门面。
8. **拆除判据**：一个符号是否仍是入口，看生产调用是否用它回答「这个模型的 X 是什么」，不看注释是否写「已根除」。

**本文件不做**

- 不写 `plans/0N-*.md`（分维指示文档属后续派单）。
- 不改产品源码、不 git 写、不派子 Agent。
- 不与并行「数据流切」总计划对齐结论；差异见 §11，留给主控按效果完整度 → 正确性 → 可验证性 → L1–L12 → 结构干净取舍。

## 1. 全局效果锁

### 1.1 用户侧产品链（验收北极星，不得缩水）

与纪律 §3 同一条因果链。缺任何一环不得宣称完成：

```
设置抽屉编辑 modalities / thinking / pricing / protocol
  → 点保存
  → 磁盘 ~/.conex/models.yaml 出现同等字段（读文件断言）
  → modelsCatalogStore 与 live_catalog 同时反映该树
  → Composer 模型徽标 / 思考档位 / 附件入口读同一棵树
  → 用户选档位、发消息（纯文本或带图）
  → 出站 HTTP JSON 含 yaml 字典映射出的 wire 键值
     （无图模型若带图：入口不可挂 或 出站硬拒，不得静默改成文本）
  → SSE usage 进入 PricingEngine
  → 会话 UI 展示的费用 = 微元定点结果
```

视觉与交互（token、四态输入、思考区物理卸载、保存钮可达）是同一产品链的用户面。无真实数据链的样式修补视为未完成。

### 1.2 本切加锁的运行时不变量（I-LOOKUP）

设 `S = lookup(providerId, modelId)`。

对任意运行时决策 `D ∈ { protocol, thinking 字典, thinkingFormat, modalities, pricing 四维单价, contextWindow, maxOutputTokens, max_tokens_field, developer_role, cache_control, 会话亲和头策略, 视觉可否挂图, 思考胶囊是否存在 }`：

- **有命中**：`D = f(S)`（含 Provider 继承：模型字段覆盖供应商字段）。
- **无命中**：`D` 不猜测。引擎视为未就绪或该次请求拒绝；UI 显示空/禁用/「—」；费用静默跳过。禁止 `Auto`、禁止 `openai/chat` 缺省、禁止 `128_000`、禁止 URL 子串、禁止模型名前缀表。

推论（必须同时成立）：

| 编号 | 不变量 | 违反形态（当前代码） |
| --- | --- | --- |
| I1 | 进程内 Rust 只有一个 live 树锁，索引对象是 `UnifiedModelsConfig` | `LIVE_CATALOG` 与 `BUNDLED_CATALOG` 并存；热路径读 bundled（`protocol.rs:35-73,112-128`）；Tauri state 再挂一份 `ModelCatalog::bundled()`（`main.rs:990-994`） |
| I2 | 前端只有一个镜像树，查询走同一 `(providerId, modelId)` 索引 | `getModelMeta` 读 `crish_model_meta_v1`；Picker 读 `loadProfiles()`；`findCatalogModel(modelId)` 可丢 providerId 取全局 `[0]` |
| I3 | `EngineProviderConfig` 携带 lookup 键并在构造时灌入规格字段 | 结构体无 `provider_id` / 协议 / 字典（`engine_provider.rs:64-77`）；`request_options` 用 `..Default::default()` 把 `thinking_map` 清成 `None`（`:154-162`） |
| I4 | 出站四轨只消费 lookup 灌入的 map/format，唯一组装器 `assemble_thinking_dialect` | Chat 无 map 走 OpenAI effort + 前缀表覆盖（`build_chat.rs:85-149`）；Anthropic/Gemini 各自硬编码刻度 |
| I5 | 预填库、`catalog.json`、LS meta 永不回答运行时能力问题 | `bundled_catalog()` 决定协议/窗口/缓存/白名单；`thinkingGear` 正则发明档位；视觉三连 fallback |
| I6 | 未命中 ≠ 合法空配置 | `ensureLoaded` 失败写成空 `providers`（`modelsCatalogStore.ts:174-189`）；`load_user_catalog_or_default` IO 错回空目录（`catalog.rs:392-397`） |

### 1.3 允许存在、但不是入口的三仓

| 仓 | 存什么 | 允许的问题 | 禁止的问题 |
| --- | --- | --- | --- |
| **规格仓** | `~/.conex/models.yaml` → live 树 / Store 树 | 「这个 `(provider, model)` 的协议/字典/模态/价格/窗口是什么」 | — |
| **选择指针** | 活动 `(providerId, modelId)`（可落在本机选择标记） | 「用户现在选了哪一对」 | 思考能力、视觉、价格、窗口 |
| **凭据仓** | 按 `providerId` 取 secret（DPAPI / env） | 「这个供应商的 key 是什么」 | 任何 ModelSpec 字段 |

预填 JSON（`modelsAutofillBaseline`）是**编辑器建议**，只在用户键入新模型 ID、写入规格仓之前出现。写入之后只走 lookup。`catalog.json` 同定位：测试夹具或预填种子，禁止热路径 `bundled_catalog()`。

思考**当前档位**（用户选了 High 还是 Low）不是 ModelSpec 字段。铁律要求 yaml `thinking` 是拍平字典，不嵌 `defaultLevel`。档位选择是 UI/会话状态，发送时必须用 lookup 的字典键集校验：键不在字典里 → 不发送思考键（模型无 thinking 则胶囊物理卸载）。禁止把 `defaultThinkingLevel` 写进 yaml 冒充规格，也禁止用它当能力真源。

### 1.4 完成定义（对照 L12）

完成 = 用户侧产品链可逐步断言 **且** 生产热路径对 I-LOOKUP 的反例 grep 为零。
「函数已导出 / 单测绿 / 命令已注册 / 注释写已根除」不是完成。

## 3. 单一 lookup API：签名、语义、调用方清单

### 3.1 键与归一

```
LookupKey = (providerId, modelId)
normalize_id(s) = trim(s) 后大小写折叠（Unicode lowercase，两端必须同算法）
空 providerId 或空 modelId → 直接 Miss，禁止回落全局索引
```

两端各一份纯函数，用同一组夹具钉死：`" DeEpSeEk "` × `" glm-5.3 "` 与 `"deepseek"` × `"GLM-5.3"` 同一键；`" "`、`""` 为 Miss。

### 3.2 Rust 签名（进程内唯一）

放在 `crates/agent-provider` 的规格模块（优先扩 `catalog_types.rs` 已有 `find_model`，不另起 LookupService trait、不做中间件链）。

```rust
/// 进程内唯一按 (provider_id, model_id) 取规格的函数。
/// 未命中 → None。禁止 URL / 前缀 / bundled / 后缀剥离 / 跨厂首条。
pub fn lookup_model<'a>(
    tree: &'a UnifiedModelsConfig,
    provider_id: &str,
    model_id: &str,
) -> Option<ResolvedModel<'a>>;

pub struct ResolvedModel<'a> {
    pub provider_id: &'a str,
    pub model_id: &'a str,
    pub provider: &'a ProviderSpec,
    pub model: &'a ModelSpec,
}

impl<'a> ResolvedModel<'a> {
    pub fn protocol(&self) -> ProtocolKind;           // model ≻ provider；无 Default 猜 chat
    pub fn compat(&self) -> Option<&'a CompatSpec>;    // model.compat ≻ provider.compat
    pub fn thinking(&self) -> Option<&'a IndexMap<String, String>>;
    pub fn thinking_format(&self) -> Option<ThinkingFormat>;
    pub fn modalities(&self) -> Option<&'a ModalitiesSpec>;
    pub fn supports_image_input(&self) -> bool;        // modalities.input 含 image；缺省 false
    pub fn pricing(&self) -> Option<&'a ModelPricingSpec>;
    pub fn context_window(&self) -> Option<u64>;       // 缺省 None，禁止 128000
    pub fn max_output_tokens(&self) -> Option<u64>;
    pub fn max_tokens_field(&self) -> Option<MaxTokensField>;
    pub fn supports_developer_role(&self) -> Option<bool>;
    pub fn headers(&self) -> Option<&BTreeMap<String, String>>; // provider.headers
    pub fn base_url(&self) -> &str;
}
```

壳层门面（`protocol.rs`，去掉 `#[allow(dead_code)]`）：

```rust
pub fn live_tree() -> Arc<UnifiedModelsConfig>;       // 唯一 live 锁
pub fn reload_live_tree() -> Result<(), LiveReloadError>; // 解析失败不得写成空树冒充成功
pub fn lookup_live(provider_id: &str, model_id: &str) -> Option<ResolvedModelOwned>;
```

`ResolvedModelOwned` 是灌进 `EngineProviderConfig` 用的所有权快照（字段克隆；模型规格体积小，禁止为此上环形缓冲或缓存服务）。

**live 锁对象必须是 `UnifiedModelsConfig`，不是 `ModelCatalog`。**
`parse_yaml_to_catalog`（`catalog.rs:810+`）是第二解析器：丢 `compat`、`DynamicYamlModalities` 布尔形状导致数组 modalities 全 false、`p.contains("responses")` 猜 Responses。S1 起 yaml 只 `serde` 进 `UnifiedModelsConfig`。壳层 `models_yaml.rs` 的并行 schema 收敛为同一类型的 IPC 包装，禁止第三套 `DynamicYaml*`。

`ModelCatalog` / `catalog.json` / `bundled()`：仅测试与预填种子。生产符号 `bundled_catalog()` 删除或 `#[cfg(test)]`。

### 3.3 前端签名（Store 投影上的唯一查询）

```ts
export interface ResolvedModel {
  providerId: string;
  modelId: string;
  provider: ProviderSpec;
  model: ModelSpec;
  protocol: 'openai/chat' | 'openai/responses' | 'anthropic/messages' | 'google/generate-content';
  compat?: ProviderCompatConfig;
  thinking?: ThinkingMap;
  thinkingFormat?: 'openai' | 'deepseek' | 'qwen' | 'zai' | 'anthropic' | 'gemini';
  modalities?: ModalityMatrix;
  supportsImageInput: boolean;
  supportsThinking: boolean;
  pricing?: PricingConfig; // 仅 input/output/cacheRead/cacheWrite/perImage/currency/tiers
  contextWindow?: number;  // 禁止发明 128000
  maxOutputTokens?: number;
}

/** 前端唯一 lookup。providerId 必填。Miss → undefined。 */
export function lookupModel(providerId: string, modelId: string): ResolvedModel | undefined;
```

实现：读 `modelsCatalogStore` 的 `modelIndex.get(normalize(providerId)+'::'+normalize(modelId))`，再做与 Rust 同构的继承（protocol / compat）。
禁止再经 `modelToCatalogSpec`。运行时协议字面不得出现 `google/interactions`（该别名只允许在 yaml 读入边界单向归一到 `google/generate-content`，与 `ProtocolKind` 的 serde alias 一致，`catalog_types.rs:110-111`）。

`selectModel` 可保留为 lookup 的内部索引命中；`selectModelGlobally` / `findCatalogModel` 无 providerId 枝 **生产删除**。搜索 UI 需要「按名字找候选」时，返回的是候选 `(providerId, modelId)` 列表，能力仍要再 `lookupModel`。

### 3.4 `EngineProviderConfig` 灌入契约（lookup 的唯一下游宿主）

```rust

    pub modalities: Option<ModalitiesSpec>,

    pub max_output_tokens: Option<u64>,
    pub compat: Option<CompatSpec>,
    pub headers: BTreeMap<String, String>,
    pub endpoint: Endpoint, // 由 protocol 派生，不再与 yaml 平行
    pub stream: bool,
}
```

`load_provider_endpoint`：

1. 取选择指针 `(provider_id, model_id)`；缺一 → `None`（未就绪）。
2. `lookup_live`；Miss → `None`（未就绪，不回落 env 三件套猜厂商）。
3. `api_key`：凭据仓按 `provider_id` 取；没有再看 `ProviderSpec.api_key` / env 模板；仍空 → `None`。
4. 把 Resolved 字段搬进 config。**禁止** `ChatCompletionsRequestOptions { ..Default::default() }` 把字典清掉。

`request_options` 必须显式赋值：`thinking_map`、`thinking_format`、`max_tokens_field`、`vendor`（若还需要枚举，由 protocol/compat 映射，不由 URL）。Anthropic/Gemini 的 `*RequestOptions` 同样带 map/format。

## 11. 与「数据流切」可能的结构差异（供主控合并）

本文件**未读**并行独立总计划，以下是本切对「若按数据流动组织」会怎么切的对照，不是对那份文稿的评论。

| 维度 | 数据流切（典型组织） | 本切（运行时单一入口） |
| --- | --- | --- |
| 主轴 | 字节从哪搬到哪：磁盘 → IPC → Store → UI → HTTP → 账本 | 每个能力问题由谁回答：只能是 `lookup(providerId, modelId)` |
| S1 重心 | 命令名对齐、DTO 字段别写错 | 键存在（provider_id）、树对象是 `UnifiedModelsConfig`、解析器唯一、lookup 符号 |
| 对 `live_catalog` | 容易写成「把 bundled 换成 live，仍用 `ModelCatalog::lookup`」 | **拒绝**：扁平 `ModelCatalog.lookup` 带后缀/`*` 仍是第二入口 |
| 对 `findCatalogModel` | 可能保留扁平门面只要数据来自 yaml | **拒绝**运行时扁平 `CatalogModelSpec`（协议反映射、双价格名） |

| 身份（profile vs yaml 键） | 可能当迁移细节 | **入口前提**：三套 id 不合一则 lookup 参数无法构造 |
| S3 | 「各 UI 改读 Store」 | 「各 UI 改读 lookupModel；选择指针不是规格」 |
| S4 | 「thinking_map 要出现在 body」 | 「builder 禁止再调用任何 infer_*；map 只从已灌装 config 来」 |
| 完成判据 | 链上每跳字段不丢 | 链上字段不丢 **且** 第二入口 grep=0 |
| 过渡兼容 | 较容易留无日期 fallback「先打通」 | 过渡只允许一次性导入；运行时 Miss 显式 |
| 风险 | 数据通了，URL 猜仍回答协议 | 入口硬，但若 S1 身份合一范围估小，UI 选中的 id 对不上 yaml 键 |

**合并建议（给主控，不是让两份计划互相抄）**

- 效果锁与产品链：两切应相同；以纪律 §3 为准，不得合并成较弱的那条。
- 架构脊柱：采用本切 I-LOOKUP + `UnifiedModelsConfig` 精确匹配。不要采用「yaml 灌进旧 `ModelCatalog` 扁平 lookup」的假换源。
- 验收脊柱：采用产品链逐步断言（数据流切通常写得更顺）；每一步加上「该步不得调用表 2.x 旧入口」。
- `EngineProviderConfig.provider_id` 放在契约维（S1），不要留到出站维才发现只能 URL 猜。
- 扁平查询门面：合并时应删运行时类型，而不是「先留着给 Picker」。
- 若数据流切把 S4/S5 的文件域写得更细，可吸收其文件表；若它保留 `infer_*` 作缺字段兜底，按 L7/L5 丢弃该兜底。

取舍键（纪律）：效果完整度 → 正确性/不变量 → 可验证性 → 与 L1–L12 一致 → 结构干净。流行的「catalog.json + vendor 推断」不是合法键。

## 12. 逻辑冲突与须主控/用户显式裁决的点（Agent 不改目标）

下列不是退避，是目标内部张力，必须标出：

1. **窗口字段必填 vs 禁止发明 128k**
   现 Rust `ModelSpec.context_window: u64` 必填，会逼写入 0 或 128000。本切选择改为 `Option`，UI「—」，引擎不钳制。若合并时有人坚持必填，只能要求用户保存时显式填，**仍禁止**代码发明 128000。

2. **选择指针是否允许留在 LS**
   本切允许 LS 只存 `(providerId, modelId)` 指针，因为那不是规格。若合并要求「零 LS」，指针可改存 yaml 外的引擎 config，但不得把指针仓重新塞进 ModelSpec。

3. **Miss 时引擎未就绪 vs 仍允许裸 env 三件套发请求**
   本切：lookup Miss → 未就绪。env 只用于**创建** yaml 供应商，不用于绕过 lookup。若要保留「无 yaml 也能用 env 聊一句」，那是第二入口，须用户显式改效果锁——Agent 不擅自开。

4. **Gemini wire 形状**
   `catalog_types` 注释 `thinkingConfig.thinkingLevel` 与 `build_gemini.rs` 的 `generationConfig.thinking_level` 不一致。本切：形状以 yaml 字典 value + 该协议官方字段为准，lookup 的 format=Gemini 必须有独立 dialect 变体。具体 JSON 路径用抓包钉，不在方案里用注释假装已统一。

5. **profile 仓与 yaml 键历史数据不等**
   导入时以 yaml 为写入目标；LS profile id 能对齐则作 providerId，不能对齐则生成稳定 id 并改选择指针。禁止运行时双 id 映射表常驻。

## 13. 反过度设计（本切主动不做）

- 不引入 LookupService trait、中间件链、动态模型路由器（禁令 4）。
- 不为 lookup 做无锁环形缓冲或跨进程目录服务。
- 不保留 `DegradePolicy::AllowDegrade` 当生产默认。
- 不把 `catalog.json` 与 yaml 做运行时 merge 层（那是第三入口）。
- 预填与 live 两份数据文件可以并存，**调用边**必须分流：编辑器建议 vs lookup。
