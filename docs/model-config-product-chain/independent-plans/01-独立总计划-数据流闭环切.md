## 1. 全局效果锁（用户侧产品链原文，不得缩水）

一条因果链，缺任何一环都不得宣称本战役完成：

```
设置抽屉编辑 modalities / thinking / pricing / protocol
    → 点保存
    → 磁盘 ~/.conex/models.yaml 出现同等字段（可用读文件断言）
    → modelsCatalogStore 与 live_catalog 同时反映该树
    → Composer 模型徽标 / 思考档位 / 附件入口读同一棵树
    → 用户选档位、发消息（纯文本或带图）
    → 出站 HTTP JSON 含 yaml 字典映射出的 wire 键值
       （无图模型若带图：入口不可挂 或 出站硬拒，不得静默改成文本）
    → SSE usage 进入 PricingEngine
    → 会话 UI 展示的费用 = 微元定点结果
```

视觉与交互（token、四态输入、思考区物理卸载、保存钮可达）是同一产品链的用户面，不是「另做的美化」。无真实数据链的样式修补视为未完成。

本切分把这条链读成 **七个存活环**。环与环之间只允许投影，不允许换一份无关字节冒充：

```
R0  用户草稿字节（设置抽屉 cfgDraft：modalities / thinkingMap / pricing / protocol / context）
      ↓ 点保存（唯一写入口）
R1  磁盘字节 ~/.conex/models.yaml（v2 providers 树）          ← L1 唯一物理真源
      ↓ IPC 三命令往返（读必须吃 providers）                 ← L3 / L4
R2  边界 DTO 字节（与磁盘字段同构，thinking/modalities 不得蒸发）
      ↓ 同时灌两面镜像
R3  前端内存镜像 modelsCatalogStore                           ← L2
R4  内核内存镜像 live_catalog()                               ← L5
      ↓ 用户选档 / 挂附件 / 点发送
R5  出站 HTTP JSON（yaml 字典 → wire；modalities 硬约束）     ← L6 / L7 / L8
      ↓ SSE usage + yaml 四维单价
R6  费用数字（PricingEngine 微元 → 会话快照/事件 → UI 只展示） ← L9
```

**完成句只能用环上的动词写**：保存出现字段、镜像反映该树、出站含 wire 键值、费用等于微元。禁止用「函数已导出」「命令已注册」「单测绿」关账（L12）。

## 2. 切分角度：数据是否还活着

### 2.1 为什么不按前后端模块切

旧战役按「Rust 内核 / 前端中枢 / 设置人体工学 / 验证门禁」切，落地的是**模块内可单测事实**。二次审计证明：同一字段在模块 A 里「有」，在模块 B 里「死」。用户侧链断在 **环与环的交界**，不在某个文件缺一个符号。

本计划每一维回答的问题只有一句：

> 用户在抽屉里写下的那组字节，走到这一环时还在不在？若死了，死在哪一次投影？用什么构造让它活过这一环？

### 2.2 字段存活矩阵（当前源码形状 · 本会话只读）

「活」= 该环的输入里有该字段，且输出仍携带同等语义。「死」= 投影丢掉、换源、或用 Default/正则/LS 顶替。

| `thinking` 拍平字典 | 活（cfgDraft.thinkingMap） | **死**（保存不写 yaml） | 读路径再死一次（flatten 无此字段） | 产品 UI 不订 store | 热路径不读 live | `thinking_map=None` | — |
| `modalities.{input,output}` | 活 | **死**（写 LS） | flatten 丢掉 | store 常空 → LS/正则 | 解析器形状不兼容 | 出站无图 part；守卫 dead_code | — |

### S1 · 边界字节同构（R1 ↔ R2）

#### 4.1.1 本维效果

用户（或测试）经 **唯一三命令** 读写 `~/.conex/models.yaml` 后：

1. 读结果的一等字段是 v2 `providers` 树，不是扁平 `models` 重建物。
2. 树节点携带 `thinking`（拍平 `Record<string,string>` / `IndexMap`）、`modalities.{input,output}`、`pricing.{currency,input,output,cacheRead,cacheWrite,tiers?}`、`protocol`、`contextWindow`、`compat.thinkingFormat`。
3. 前端 `modelsCatalogTypes.ts` 与 Rust `catalog_types.rs` 对上述字段同构；壳层 `models_yaml.rs` 的 V2 DTO 是同一份形状的 IPC 投影，不是第三套「丢掉一等字段的 flatten schema」。
4. 运行时协议字面量只有 `google/generate-content`。`google/interactions` 若出现，只允许在读入边界单向归一，不允许运行时双枚举、不允许查询层改写后再反向改写。
5. `live_catalog()` 的解析器必须能把磁盘上的 `{input,output}` 数组读进 `ModalitiesSpec`，把拍平 thinking 读进 `ModelSpec.thinking`。否则 S4 即便改成读 live，视觉/思考仍是死的。

#### 4.1.2 非目标（诚实边界）

- 本维不改设置抽屉保存按钮（S2）。
- 本维不改 Composer/Picker 数据源（S3）。
- 本维不改 HTTP 装配（S4）与结算（S5）。
- 本维可以把 `live_catalog` 的 **解析与查询面** 修好并去掉 `dead_code`，但热路径从 `bundled_catalog` 切到 `live_catalog` 的调用点改写属 S4/S5（本维输出「可被热路径消费的活快照」）。
- 不把预填 JSON / `catalog.json` 提升为真源。

#### 4.1.3 依赖边

- **输入**：无（战役第一环）。磁盘已有 yaml 文件与三命令登记，是本维要消费的现状，不是本维要发明的真源。
- **输出保证**：任意合法 v2 yaml（含 thinking/modalities/pricing/protocol）经 `workbench_read_models_yaml` 回到 TS 的 `tree.providers.*.models[]` 字段完整；经 `ModelCatalog::load_user_catalog` 进入 `live_catalog()` 的 `ModelSpec` 字段完整。
- **后继**：S2 写路径必须产出本维能读的形状；S3 必须订本维灌入的 store；S4/S5 必须读本维灌入的 live。

| C5 | `capabilities` 布尔 vs `modalities` 数组并存多久 | 运行时决议只信 modalities；capabilities 仅迁移期只读 | 调度 L11 禁永久双读，过渡长度未锁 |
| C6 | `catalog.json` 物理留作预填 vs 从 crate `include_str!` 删除 | 热路径零读；预填用 `modelsAutofillBaseline` 一份即可 | 删除 bundled 影响存量测试夹具，属结构干净 vs 测试资产 |
| C7 | 阶梯匹配规则以 PricingEngine 为准还是 catalog_price 为准 | 以 PricingEngine 为准并让 yaml tiers 进入 | 两套规则都有测试，改哪边会红需主控看测试资产 |
| C8 | ThinkingFormat TS `google` vs Rust `gemini` | 以内核序列化名为准，边界单向归一 | 类型同构原则已锁，具体字符串主控并入总方案时钉死 |
| C9 | PricingTier TS `inputCost` vs Rust `input` | 对齐 Rust `input/output` | 同 C8 |
| C10 | 一次性 LS 导入的完成条件（空 yaml vs 用户确认） | 空树自动导入 + 幂等旗；非空 yaml 不覆盖 | 可能覆盖用户已手写 yaml，需主控锁「谁赢」 |

上述冲突 **不缩小效果锁**。无论怎么裁，§1 因果链仍须闭合。

### 8.5 给主控合并键（复述调度，便于对照另一份独立总计划）

取舍顺序：效果完整度 → 正确性/不变量 → 可验证性 → 与 L1–L12 一致 → 结构干净。

本切分若与「运行时单一入口切」的独立总计划在任务切块上不同，合并时保持效果锁原文，任务单元按文件域互斥重排即可，不得因切块不同丢掉问题 1–24 任一条。

## 10. 一句话

用户写下的字段必须作为 **同一组字节** 活过磁盘、活过 IPC、活过两面镜像、活过 HTTP、活成微元数字；中途任何一次换源（LS、catalog.json、正则、Default、JS 浮点）都是断环。S1 锁形状，S2 锁写入，S3 锁读出，S4 锁出站，S5 锁账本，S6 锁真保存面可达，S7 锁竞争源死亡，S8 锁用户侧能跑——八维是一条数据流的八段，不是八个可以砍的模块。
