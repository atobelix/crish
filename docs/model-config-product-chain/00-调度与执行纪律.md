## 1. 为何新开工作区

`docs/provider-model-unification/` 已有总案与五份阶段计划，并落地 Wave 1–4。二次审计证明：落地的是**模块内可单测事实**，产品默认链仍断。若在旧 00 上继续追加「已接线」叙事，会再次抬关。

本工作区的 00 总方案以**用户侧闭环**为终点，旧战役文档降为输入，不继承其完成句。

旧 00 仍锁定、本战役继续遵守的三条原则：

1. `thinking` 拍平为 TitleCase → wire 字符串字典；缺省则非思考，DOM 物理卸载。
2. `cacheRead` / `cacheWrite` 为独立绝对单价，禁止「输入价 × 折扣」假定。
3. 预填库（`modelsAutofillBaseline` / `catalog.json`）只在用户键入模型 ID 时建议填充，**不是**运行时真源。

## 3. 用户侧产品链（验收北极星）

一条因果链，缺任何一环都不得宣称本战役完成：

```
设置抽屉编辑 modalities / thinking / pricing / protocol
    → 点保存
    → 磁盘 ~/.conex/models.yaml 出现同等字段（可用读文件断言）
    → modelsCatalogStore 与 live_catalog 同时反映该树
    → Composer 模型徽标 / 思考档位 / 附件入口读同一棵树
    → 用户选档位、发消息（纯文本或带图）
    → 出站 HTTP JSON 含 yaml 字典映射出的 wire 键值
       （无图模型若带图：入口不可挂 或 出站硬拒，不得静默改成文本）
    → SSE usage 进入 PricingEngine
    → 会话 UI 展示的费用 = 微元定点结果
```

视觉与交互（token、四态输入、思考区物理卸载、保存钮可达）是同一产品链的用户面，不是「另做的美化」。无真实数据链的样式修补视为未完成。

## 4. 问题全集（同权，按依赖归入分维，不按重要性砍）

来源：审计 11–21 主控复核。方案必须覆盖，不得标「以后再说」。

## 5. 逻辑递进分维（分阶段指示文档）

依赖边是**数据能否正确存在**，不是重要性。后维不得在前维契约未闭合时发明第二真源。

```
S1 真源契约与 IPC 同构
    → S2 设置写路径（保存即落盘 yaml）
        → S3 全界面读路径（唯一镜像）
            → S4 出站方言与多模态（HTTP 体）
            → S5 计费入账与费用呈现
```

## 6. 多轮协同闭环（可复用模板）

每轮最多 12 个 Agent，按该轮文件域与依赖**按需**取 5–12；收尾轮可不保底。子 Agent 深度 1，不嵌套。

```
问题识别（本轮输入：上轮报告 + 审计 + git diff）
  → 任务分解（总方案任务单元 ∩ 本轮依赖已满足的集合）
  → Agent 分配（一文一域，同文件串行）
  → 并行修复（只改分配路径；禁止提交）
  → 结果汇总（主控核对 diff 与验收断言）
  → 验证（源码形状 + 本会话真跑测 + 用户路径；三者分开写）
  → 轮次报告（见下）成为下一轮唯一输入增量
```

轮次报告最低字段（S8 详案展开）：

- 本轮闭合的产品链环节（用 §3 链上的动词，不用模块名）
- 未闭合环节与阻断依赖
- 文件清单与是否误伤并行域
- 测：命令、是否本会话真跑、绿/红
- 新引入的 fallback / TODO / 双轨（必须为 0；若有则下一轮输入）
- 建议的下一轮任务单元集合（仍同权，只按依赖可启动）

实现轮逻辑打包（方案可调整切块，但不得把 S7 提前到写/读/出站未通）：

- 轮次 α：S1 契约（无 UI 也能用 IPC 往返 yaml 树）  
- 轮次 β：S2 保存落盘  
- 轮次 γ：S3 读路径单轨  
- 轮次 δ：S4 与 S5 并行（文件域互斥）  
- 轮次 ε：S6（与 δ 文件域不冲突时可并入 δ）  
- 轮次 ζ：S7 删除旧轨 + 测试改写  
- 轮次 η：S8 用户侧全链验收与门禁入库  

每一轮输出必须足以让下一轮 Agent **不必重读全部历史会话**，只读：总方案 + 本维指示 + 上轮报告。
