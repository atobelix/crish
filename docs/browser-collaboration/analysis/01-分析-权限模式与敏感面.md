## 1. R1 权限模式化

### 1.1 现状盘点

**已具备（可直接复用的基础闸门）：**

- 会话级显式开启：`SessionEnablement`（security.rs:143-229），用户唯一来源（`EnableSource::User`，security.rs:100-103），session_meta 落盘 `computer_use_enabled`（security.rs:95 + computer/mod.rs:139-165），未开启零注册（`tool_mount_allowed` security.rs:226；ComputerSlot::register_tools computer/mod.rs:363-375 零注册返回 Ok）。
- 三级急停：`EmergencyStop` 三源一旗（security.rs:467-533），任意模式都不得削弱（R1 裁决「保留显式开启/急停/互斥等基础闸门」）。
- 会话互斥：`ActivationGate`（activation.rs:123-238），守卫②在审批之前（tools.rs:406-414）。
- 空闲挂起：`IdleTimeout`（security.rs:558-611，默认 120s security.rs:544）。

**逐次审批现状（改造目标主体）：**

- 全部 13 工具 `dangerous=true`（tools.rs:114），守卫⑤无条件走 `approve()`（tools.rs:427 → approve:139-198）：`require_approval` → Pending → `ctx.ask` 传输面 → `settle` 收口；急停/并发/未注入一律 Denied 收口（零注入）。
- 审批载荷 `ApprovalRequest`（security.rs:248-257）：动作名+参数摘要+窗口标题+坐标；`type` 明文展示（tools.rs:786-796）。
- 审批状态机为纯逻辑、可测（tests/security_approval.rs：一次一票/并发拒绝/急停竞态 3/3）。

**与既有方案文档的冲突点（必须显式处理，不得悄悄改口径）：**

- 04 §4.2 第 5 行「会话内一键放行（可选）：仅限感知类动作集；交互类**永不**整会话放行」（04-二期立项-电脑操作.md:182）——**R1 的「全自动模式免逐次授权」直接推翻此条**（全自动覆盖注入类）。需在总方案修订该基线，标注「用户裁决 R1 取代 04 §4.2 交互类永不整会话放行」。
- 06 文档「estop 虽只中止不注入，仍走审批」（06-工具面设计.md:96）——全自动模式下 estop 若仍逐次审批会形成「急停也要等批准」的荒谬摩擦；建议 FullAuto/FullAccess 下 estop 免审批（见 §1.2 决策点 D1）。
- 04 §4.1 风险确认对话框文案「动作逐次审批」（04:171 与 ComputerPanel.tsx:211-214）——模式化后文案需随模式动态化。

**前端现状：** ComputerPanel 只有开关+急停+三态（无模式选择）；命令面仅 4 命令（computer_commands.rs:35-74），无配置类命令。设置界面已有权限模式先例（SettingsSecurityTab.tsx 的 `PermissionMode` 选择，api/permissionModes）——R1 的「审批入口/配置做成设置界面独立功能面板」可对齐该交互范式。

### 1.2 系统性改造方案

**（a）模式枚举设计（security.rs 新增，纯逻辑可测）：**

```rust
/// 电脑操作权限模式（R1 用户裁决：默认 Manual；FullAuto 免逐次授权；
/// FullAccess 额外豁免密码管理器拦截——R4）
#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum PermissionMode {
    /// 手动模式（默认）：逐次审批保留（默认拒绝型，04 §4.2 语义不变）
    Manual,
    /// 全自动模式：免逐次授权；显式开启/互斥/急停/空闲挂起/提权拒绝全部保留
    FullAuto,
    /// FullAccess（用户裁决 R4 提及的档位）：FullAuto 全部语义 +
    /// 密码管理器进程拦截豁免（显式高风险授权，面板醒目警示）
    FullAccess,
}
```

**闸门 × 模式开关矩阵（本分析建议，未锁定项标注 D）：**

| 闸门                                 | Manual（默认）  | FullAuto        | FullAccess              | 说明                                                                                                 |
| ------------------------------------ | --------------- | --------------- | ----------------------- | ---------------------------------------------------------------------------------------------------- |
| 会话级显式开启 `SessionEnablement`   | ✅ 保留         | ✅ 保留         | ✅ 保留                 | 任何模式不自动开启；急停/挂起后仍须重新开启                                                          |
| 会话互斥 `ActivationGate`            | ✅ 保留         | ✅ 保留         | ✅ 保留                 | 守卫②审批前（tools.rs:406-414）                                                                      |
| 三级急停 `EmergencyStop`             | ✅ 保留         | ✅ 保留         | ✅ 保留                 | 三源一旗；审批等待期取消路径在旁路模式下退化为「在途注入批次自查」（tools.rs:123-135）               |
| 空闲挂起 `IdleTimeout`               | ✅ 保留         | ✅ 保留         | ✅ 保留                 | 挂起后恢复需重新开启（security.rs:544, 04 §4.4）                                                     |
| 逐次审批 `ApprovalGate`              | ✅ 保留         | ⛔ 旁路         | ⛔ 旁路                 | 旁路 = 守卫⑤直接放行，非注入 None 收口（见（b））                                                    |
| `computer_estop` 自身审批            | ✅ 保留（现状） | ⛔ 免审批（D1） | ⛔ 免审批（D1）         | 建议：安全动作应零摩擦；D1 待主控裁决                                                                |
| 提权窗口拒绝 `TokenElevationProbe`   | ✅ 保留         | ✅ 保留         | ✅ 保留（建议不放松）   | R3 红线（window_gate.rs:351-360 提权优先于白名单）；**建议 FullAccess 也不放松**，放宽须另行用户裁决 |
| 密码管理器进程拦截（R4 新增）        | ✅ 默认拒绝     | ✅ 默认拒绝     | ⛔ 豁免（或改显式授权） | 见 §2                                                                                                |
| 密码/token 数据面抑制（R6 新增开关） | 默认开（可关）  | 默认开（可关）  | 默认开（可关）          | 与模式正交，独立开关（见 §3）                                                                        |

**（b）ApprovalGate 改造点（最小侵入，保持状态机纯逻辑）：**

推荐**不在 ApprovalGate 内部加模式分支**，而是守卫⑤调用侧旁路：

- `GuardCtx` 新增 `mode: Option<Arc<PermissionModeState>>`（`PermissionModeState` = 原子封装，与 gate/stop 同生命周期，由 ComputerSlot 装配，computer/mod.rs:363-375 的注入面扩展一行）。
- `tools.rs::approve()` 入口：`if matches!(mode.current(), FullAuto | FullAccess) { return Ok(()) }`——旁路后不走 `require_approval`，**不产生 Pending、不产生在途**；急停检查（守卫④ tools.rs:423）与互斥/开启（守卫②③）在审批之前，天然仍生效。
- 审计不缺失：旁路不等于无痕——每次旁路放行应记审计事件（动作名+模式+时间戳；复用 `ApprovalGate::last_verdict` 会污染 Manual 语义，建议新增独立的「模式放行审计计数」或经既有审计面登记），断言测试覆盖。
- 备选方案（ApprovalGate 内部判断 `require_approval` 直接返 Granted）**不推荐**：会把「模式」耦合进审批状态机，破坏现有 3/3 竞态测试语义，且与「审批状态机保持纯逻辑」的既有设计（security.rs:28-29）相悖。

**（c）配置持久化（session_meta，对齐既有机制）：**

- 新键 `computer_permission_mode`（与 `COMPUTER_USE_ENABLED_KEY` security.rs:95 并列，键名常量登记在 security.rs；读写接线复用 `ComputerMetaStore` 模式——computer/mod.rs:131-165 的 trait 需扩展为泛化键读写或新增 `load_mode/persist_mode`）。
- 恢复语义：`ComputerSlot::ensure_restored`（computer/mod.rs:250-271）同时恢复模式；**模式恢复后不自动改写审批行为之外的任何闸门**。缺键 = Manual（默认安全）。
- 模式切换命令：`computer_set_permission_mode(mode)` / `computer_get_permission_mode`（computer_commands.rs 新增；错误面沿用 `tool.computer.not_ready` 持久化失败语义 computer/mod.rs:116-128）。**Agent 无权切换模式**（命令仅用户面板调用，同 `EnableSource::User` 哲学 security.rs:100-103）。

**（d）前端面板（两处）：**

1. ComputerPanel.tsx：header 文案「全动作审批」改为按模式显示（Manual=「逐次审批」/FullAuto=「免逐次授权」/FullAccess=「FullAccess 高风险授权」）；风险确认对话框文案动态化（ComputerPanel.tsx:206-226）；新增模式徽标（FullAccess 醒目警示色，对齐 cua「high-severity styling for unrestricted」consent-plan.md:516）。
2. **设置界面独立功能面板（R1 主入口）**：SettingsSecurityTab 或新「电脑操作」分区——模式三选（对齐 PERMISSION_MODES 先例 SettingsSecurityTab.tsx:21-25）、审批入口说明、密码管理器授权项（§2）、敏感抑制开关（§6）、白名单窗口管理（与 04 §4.4/05 §5.2 的 WindowTargetGate 白名单接线，现为遗留项 session.rs:129-133 注入口已留）。

**（e）与 cua 三档的对应（参考而非照搬）：**

- Manual ↔ standard（逐次审批为默认，promptless 不成立——我们是逐动作，语义对应 cua standard 的「consequential action approval」，README.md:23-27）；
- FullAuto ↔ autonomous（会话级一次授权、包络内免提示——但我们**不做能力包络清单**，仅「模式开关」为当前范围；B1 清单 56 报告:97 的「会话审批+技术强制包络」列为后续增强，本分析不纳入 R1 强制范围，避免过度设计）；
- FullAccess ↔ unrestricted（`--dangerously-bypass-approvals` 显式风险承认，consent-plan.md:79；**保留硬不变量**：开启/互斥/急停/提权拒绝，对齐 cua「bypasses prompts but not hard invariants」consent-plan.md:246-262）。

### 1.3 验收断言（R1）

- A-R1-1（模式默认）：新会话/缺键恢复后 `permission_mode == Manual`，`computer_click` 触发审批 Pending（mock ask 断言调用）。
- A-R1-2（全自动旁路）：FullAuto 下 `computer_click` 执行**无审批弹窗**（mock ask 零调用）且返回 `ok:true`。
- A-R1-3（基础闸门不随模式削弱）：FullAuto/FullAccess 下——`estop` 触发后 `computer_click` 返回 `tool.computer.cancelled`（守卫④）；`enablement.disable` 后返回 `tool.computer.not_enabled`（守卫③）；浏览器活跃时返回 `tool.session.exclusive`（守卫②）；空闲挂起后恢复需重新 enable。
- A-R1-4（模式切换不可由 Agent 触达）：工具 schema 无模式参数；`computer_set_permission_mode` 仅命令面（invoke）可达；断言无工具名为 `computer_set_*` 注册。
- A-R1-5（审计）：FullAuto 每次旁路放行记「模式放行」审计事件（计数断言）。
- A-R1-6（前端）：设置面板切换模式 → `computer://state-changed` 载荷含 `mode` 字段（StateChangePayload computer/mod.rs:95-103 扩展 `permissionMode`）；面板徽标按模式变化。
- A-R1-7（estop 免审批，若 D1 通过）：FullAuto 下 `computer_estop` 无审批且全局急停链生效。

## 2. R4 密码管理器授权

### 2.1 现状盘点

- **现状完全缺失**：无任何进程/应用级黑名单。唯一目标面门禁是 `WindowTargetGate`（提权探测 + 白名单，window_gate.rs:86-122）。
- **关键缺口（R4 前置）**：`RealComputerSession::gate_check` 构造 `ActionTarget::Window { title, process: None }`（session.rs:145-148）——**进程名恒为 None**，导致：① 提权探测对生产路径实际跳过（window_gate.rs:96-107 仅 process 非空才探测）；② 密码管理器进程拦截没有输入。session.rs:22 已登记遗留「感知面未提供窗口进程名」。
- open-codex 先例：8 个 bundle id 黑名单（AppDiscovery.swift:507-516），命中直接 `permissionDenied`（:526-528）——**粗粒度进程级拒绝**，与我们 UIA 数据面抑制（perception.rs:274-284）互补（一个堵目标、一个堵数据，56 报告:87 A1）。
- 错误码面：现有 `tool.computer.elevated_window`（error.rs:55-57）把白名单/提权统一映射（error.rs:76-78）；密码管理器拦截若复用该码会混淆语义，建议新增（见下）。
- 与 56 报告 A1 的关系：A1 建议「与提权探测同 gate 点（window_gate.rs）：新增 WindowBlocklist 检查项」（56 报告:87）——本分析采纳并细化。

### 2.2 系统性改造方案

**（a）前置依赖：窗口进程名解析（新增面，Windows 侧）**

- 位置建议：`RealComputerSession::gate_check`（session.rs:141-152）内新增解析——`GetForegroundWindow → GetWindowThreadProcessId → OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION) → QueryFullProcessImageName`，填入 `ActionTarget::Window { process: Some(...) }`。
- 或经感知面暴露（UiaPerception 增 `active_window_process()`）；二选一由实施轮定，**本分析推荐会话面直解**（gate_check 本就是会话面职责，且 window_gate.rs 已有 Toolhelp 进程枚举基础 window_gate.rs:151-183 可复用进程名口径）。
- 解析失败语义：进程名无法解析 = 目标信息不完整。**门禁不静默放行**（R11 联动）：仅当「无拦截策略」（空白名单+密码管理器拦截关闭）时可跳过；否则显式报错（见 §4.2 降级断言）。

**（b）WindowTargetGate 扩展（与提权探测并列，同为 gate 检查项）：**

- 新增 `PasswordManagerProcessPatterns: &[&str]`（Windows 进程名，大小写不敏感匹配，与提权探测口径一致 window_gate.rs:169）：`1Password.exe`、`Bitwarden.exe`、`Dashlane.exe`、`LastPass.exe`、`NordPass.exe`、`Proton Pass.exe`/`ProtonPass.exe` 等（open-codex 8 个 bundle id 的 Windows 进程名等价映射，AppDiscovery.swift:507-516）。
- 构造注入：`WindowTargetGate::with_blocklist(whitelist, blocklist, mode: Arc<PermissionModeState>, ...)`——`check` 次序：**① 提权探测（红线，恒执行）→ ② 密码管理器拦截（按模式：Manual/FullAuto 拒绝、FullAccess 豁免；或经「受信任应用」名单豁免）→ ③ 白名单匹配（04 §4 项 6 空白名单默认放行）**。
- 与提权探测的关系（裁决要求明确「gate 点合并或并列」）：**并列检查项、同一 gate 链**（共享进程名输入与检查点位置），但**语义不同**——提权=硬红线（任何模式不可豁免，对齐 window_gate.rs:351-360 提权优先于白名单的红线测试）；密码管理器=策略项（可按模式/显式授权豁免）。二者**不合并为一个判定**（错误码、豁免逻辑、审计语义均不同）。
- 错误码：建议新增 `tool.computer.blocked_window`（06 文档 §5 码表扩展登记 error.rs 域；`TargetDenialKind` 新增 `Blocked` 变体，conex-shared/src/gate.rs:28-34 扩展——**注意：conex-shared gate.rs 为共享 trait 契约，改枚举需两线（browser/desktop）serde 面同步回归**，见 §5 冲突注意点）。

**（c）FullAccess 豁免 + 额外显式授权项（「不能一刀切封死」双出口）：**

1. **模式豁免**（用户裁决已给）：FullAccess 模式下密码管理器拦截不生效（模式本身是用户显式高风险授权，对齐 cua unrestricted 的「explicit risk acceptance」consent-plan.md:556-557）。
2. **受信任应用显式授权项**（额外出口，建议一并做）：设置面板「电脑操作 → 受信任应用」列表——用户显式添加某密码管理器进程名 → 该条目在**所有模式**下豁免拦截（放入白名单或独立 trusted 列表）。这是「软件的额外显式授权项」的可操作形态（56 报告 B2「会话级白名单」的窄化落地：只做窗口/进程白名单，不做工具参数白名单——反过度设计红线）。

- 两出口默认均关闭，且**只允许用户经设置面板配置**（Agent 无权添加——同 `EnableSource::User` 哲学）。

**（d）数据面联动（R4 与既有抑制互补，不重复造轮子）：**

- 拦截发生在**目标窗口面**（注入前拒绝）；UIA 数据面抑制（perception.rs:274-284）继续保护感知流（即使拦截被 FullAccess 豁免，数据面抑制默认仍开）——两条防线独立生效（56 报告:87「一个堵目标、一个堵数据」）。

### 2.3 验收断言（R4）

- A-R4-1（进程名解析）：`gate_check` 对真实前台窗口返回 `process: Some(...)`（mock 前台窗口断言）；解析失败注入点可见（可测）。
- A-R4-2（默认拒绝）：Manual 模式下目标进程 = `1Password.exe` → `tool.computer.blocked_window`，零注入（设备探针断言）。
- A-R4-3（FullAccess 豁免）：FullAccess 模式下同目标放行（若受信任名单为空）。
- A-R4-4（显式授权项）：设置面板添加 `1Password.exe` 到受信任列表 → Manual 模式下该目标放行；未添加的 `Bitwarden.exe` 仍拒绝。
- A-R4-5（提权红线不随 R4 豁免）：即使密码管理器拦截被豁免/受信任，目标进程为提权令牌时仍返回 `tool.computer.elevated_window`（红线条目不随策略项降级）。
- A-R4-6（错误码面）：`map_session_error` 对 `TargetDenialKind::Blocked` 映射新码；既有 Elevated/Whitelist 映射回归不变（error.rs:137-150 测试扩展）。

## 3. R6 密码/token 抑制选项化

### 3.1 现状盘点

- **硬编码内建（现状，需改造成可配置）**：
  - 常量与纯函数：`PASSWORD_KEYNAME_PATTERNS`（security.rs:642，password/passwd/pwd/secret/token）、`PASSWORD_PLACEHOLDER`/`PASSWORD_REDACTION_PLACEHOLDER`（security.rs:635/638）、`is_password_field_name`/`redact_password_field`（security.rs:648-662）——**无任何开关/参数**。
  - 消费点一（纯函数层）：`perception::suppress`（perception.rs:274-284）在 `convert_node` 无条件调用（perception.rs:239）→ `build_snapshot`（perception.rs:214-225）→ `UiaPerception::snapshot_window`（perception.rs:357-372）与工具层 `computer_snapshot`（tools.rs:357-370）。
  - 消费点二（**设备层**）：`read_node`（perception.rs:398）`if !is_password { 读 ValuePattern }`——IsPassword 元素**连值都不读**（OS 语义上 UIA 对真实密码框通常也不提供值；但此分支是硬编码的）。
- **与既有方案文档的关系**：04 §4.5（04:198-202）与 18 §3.3 把抑制定为「内建硬约束」；R6 裁决将其降为「默认开的可配置项」——**不删默认防护，仅打开用户出口**。注意 56 报告 A4（截屏边界）与此正交（截屏暂停密码控件属另一面，不在本需求范围）。
- 审计面不受影响：审计不落 UIA 密码字段（04 §4.7:210）是审计库策略，与感知回传开关解耦（R6 只动感知数据面）。

### 3.2 系统性改造方案

**（a）配置结构（security.rs 新增，纯逻辑）：**

```rust
/// 敏感抑制策略（R6 用户裁决：默认全开、可配置关闭；运行时可换）
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct PrivacyPolicy {
    /// IsPassword 元素值回传（false = 占位符 <password>；true = 设备层尝试读值）
    pub suppress_password_values: bool,
    /// 键名模式脱敏（password/pwd/secret/token → <redacted>）
    pub redact_keynames: bool,
}
impl Default for PrivacyPolicy { /* 全开 */ }
```

- 运行时可变：经 `Arc<PrivacyPolicy>` + 原子替换（或内部 AtomicBool 对）注入，切换即时生效（不需重启会话）。
- 新增纯函数：`suppress(raw, policy)` 重载（保留旧签名兼容或直接改签名——**直接改签名**，调用面仅 perception.rs 内部两处 + 测试，成本低）。

**（b）运行时接线（双接线点，缺一不可）：**

1. 设备层：`UiaPerception` 持有 `Arc<PrivacyPolicy>`；`read_node` 的 `if !is_password`（perception.rs:398）改为 `if !is_password || !policy.suppress_password_values { 读值 }`。
2. 纯函数层：`build_snapshot(root, policy)`/`convert_node`/`suppress` 透传 policy；`UiaPerception::snapshot_window`（perception.rs:369-371）与工具面 `computer_snapshot` 链路（tools.rs:357-370 → session.rs:190-194）在会话侧持有同一 policy 实例。

- 注入链：ComputerSlot 装配（computer/mod.rs）持有 `Arc<PrivacyPolicy>` → `RealComputerSession`（session.rs:96 字段新增）→ `UiaPerception`。`ComputerOps::snapshot` trait 签名**不变**（policy 在会话内部，mock 测试注入即可）。
- **诚实边界（必须写进文档与断言）**：`suppress_password_values=true` 时，值回传以 UIA `ValuePattern` 实际可读为准——真实密码框的 UIA 可能根本不暴露值（OS 层保护），此时回传为空串属预期，不是 bug；断言应覆盖「设备层尝试读取 + 纯函数层不再脱敏」，而非「必然拿到明文」。

**（c）配置面（与 R1 共用设置面板分区）：**

- 持久化：session_meta 键 `computer_privacy_suppress_password` / `computer_privacy_redact_keynames`（缺键/非 true = 默认开；键名常量登记 security.rs，读写沿用 `ComputerMetaStore` 模式）。
- 命令：`computer_get_privacy_settings` / `computer_set_privacy_settings`（Rust 注册表 main.rs:290-293 同步登记 + command_manifest）。
- 前端：设置面板「电脑操作 → 敏感信息处理」两开关（默认开）；ComputerPanel 不动（面板保持开关/急停/指示的简约定位）。

### 3.3 验收断言（R6）

- A-R6-1（默认开）：缺键/默认策略下，`build_snapshot` 对 IsPassword 节点输出 `<password>`（既有 tests/security_privacy.rs 断言回归不变）。
- A-R6-2（关闭后键名透传）：`redact_keynames=false` 时，name=`pwd_field` 的节点输出原文 `pwd_field`（不再是 `<redacted>`）。
- A-R6-3（关闭后值回传）：`suppress_password_values=false` 时，设备层 mock 提供 IsPassword+可读 ValuePattern 的节点，快照 value 回传原值（纯函数层断言）；IsPassword 且 UIA 不提供值 → 空串（诚实边界断言）。
- A-R6-4（运行时可换）：同一会话内切换 policy 后下一次 `computer_snapshot` 立即生效（Atomic 替换断言，无重启）。
- A-R6-5（默认防护不回潮）：新键缺省/损坏一律回落「默认开」（安全默认，与 `ensure_restored` 的失败回落语义一致 computer/mod.rs:254-261）。
- A-R6-6（审计不变）：抑制开关不影响审计脱敏（04 §4.7 审计库策略独立，断言审计路径零改动）。

## 4. R11 安全文档化

### 4.1 现状盘点

- **威胁模型**：无集中文档；边界散落在 04 §6.2 风险表（04:244-258）与 56 报告 §3.1（同用户代码可绕过一切人工防线，56 报告:58-60）。cua 有集中威胁模型先例（consent-plan.md:129-169：in-scope/out-of-scope 明确分列）。
- **不静默降级**：部分已有显式化——审批门未注入 → Denied 收口（tools.rs:140-144）；ctx.ask 未接线 → Denied 收口（tools.rs:154-164）；热键注册失败降级仅面板按钮「不静默」（security.rs:24、04 §4.3②）；错误码全显式（error.rs 码表）。**存在一处静默跳过面**：
  - `gate_check` 感知不可用 → `return Ok(())` 跳过门禁（session.rs:141-152「感知不可用跳过门禁（空白名单默认放行语义）」）——空白名单下无害，但 **R4 落地后（非空白拦截策略存在时）该跳过会静默放行密码管理器窗口**，必须按策略条件改显式报错。
- 模式化（R1）之后还需补充：FullAuto/FullAccess 的「旁路」必须被文档化为显式授权语义而非静默弱化（审计 + 模式指示 + 风险确认流三重可见，见 §1.2（d））。

### 4.2 系统性改造方案

**（a）威胁模型文档（建议 `docs/browser-collaboration/威胁模型-电脑操作线.md` 或并入总方案安全章节，以下为必须包含的一句话职责清单）：**

- **保护对象**：仅「协议受限的 agent」——模型输出经 13 个 `computer_*` 工具 schema 校验、无任意代码执行能力、经守卫链（tools.rs:401-431）与 `ctx.ask` 审批链交互。
- **不保护**：同用户任意代码（shell/文件/其它工具面逃逸获得同用户代码执行 → 可绕过审批/急停/提权拒绝/密码抑制全部人工防线，需 OS 级隔离；本产品定位真实桌面，声明此边界不承诺）。对齐 cua「daemon is not a boundary against same-user native code」（consent-plan.md:151-158）与 56 报告 §3.1 结论（:58-60）。
- **各防线一句话职责**：
  - 审批（Manual 逐次审批）：防**误操作**——每次注入动作前用户确认（默认拒绝型），拒绝零注入（security.rs:352-401、tools.rs:139-198）。
  - 急停（三级）：中止**在途**注入——任意时刻用户可终止正在执行的输入/拖拽批次并回 Idle（security.rs:467-533、04 §4.3）。
  - 提权拒绝：防**提权窗口注入**——管理员令牌进程窗口恒拒绝，红线不可经审批/模式豁免（window_gate.rs:96-107、:351-360）。
  - 密码抑制/密码管理器拦截：防**凭据进感知流/目标交互**——数据面（perception.rs:274-284）+ 目标面（R4 新增）双层。
  - 模式（R1）：决定**审批介入频率**（Manual=逐次；FullAuto/FullAccess=显式授权后免逐次），不改变上述防线的保护对象声明。
- 模式文档化：三档语义 + FullAccess 警示文案 + 「模式是用户显式授权，Agent 无权切换」。

**（b）不静默降级断言改造（代码面，随 R4/R6 落地）：**

1. `gate_check` 跳过条件收紧（session.rs:141-152）：无拦截策略（空白名单且密码管理器拦截关）→ 跳过且告警登记（现状语义）；**存在拦截策略且感知不可用 → 显式返回 `tool.computer.not_ready`（或新增 `tool.computer.gate_unavailable`）**，禁止静默放行。此为 R11 的核心代码改造点。
2. 补测试：模拟 UIA 故障 + 配置密码管理器拦截 → 断言工具显式报错（非放行）。
3. 保留既有不静默断言并回归：approval 未注入/ctx.ask 未接线 Denied 收口、热键降级提示（tools.rs:140-164、04 §4.3②）。

### 4.3 验收断言（R11）

- A-R11-1：威胁模型文档落盘，含「保护对象=协议受限 agent / 不保护=同用户恶意代码」两条显式声明与审批/急停/提权拒绝各一句话职责（文档存在性+关键词断言，docs 层）。
- A-R11-2：空白名单 + UIA 故障 → 工具仍可执行（现状语义保留，告警登记）；配置密码管理器拦截 + UIA 故障 → 工具返回显式错误码（非放行）。
- A-R11-3：审批门未注入 / ctx.ask 未接线 → `approval.rejected` 显式错误（回归既有 tests 断言 tools.rs:140-164）。
- A-R11-4：FullAuto 旁路有审计 + 面板模式徽标常显（模式旁路不静默，联动 A-R1-5/A-R1-6）。
- A-R11-5：文档声明「全自动/FullAccess 不防同用户代码、不防提示注入」——不静默降级文案面（FullAccess 警示语含「prompt injection 无防护」，对齐 consent-plan.md:167-169）。

## 6. 逻辑依赖排序（R1/R4/R6/R11 先后关系）

结论：**R11（文档部分）并行零依赖可先行；R6 独立闭环；R1 先行定模式枚举；R4 依赖 R1 的枚举（FullAccess 变体）与 R6 无关；R11 断言改造挂靠 R4。**

## 7. 结论汇总（每条一句话）

- **R1 权限模式化**：现状=无条件逐次审批（tools.rs 守卫⑤）与 04 §4.2「交互类永不整会话放行」基线冲突；改造=新增 `PermissionMode`（Manual 默认/FullAuto/FullAccess）+ 守卫⑤调用侧旁路 + session_meta 新键 + 设置面板独立功能面板；依赖=security.rs 根定义先行，FullAccess 供 R4 挂接。
- **R4 密码管理器授权**：现状=完全缺失且窗口进程名恒 None（session.rs:147）使提权探测在生产路径也失效；改造=会话面新增进程名解析 + WindowTargetGate 增 blocklist 检查项（与提权并列、语义独立）+ `tool.computer.blocked_window` 新码 + FullAccess 豁免与受信任应用双出口；依赖=R1 枚举 + 进程名解析前置。
- **R6 密码/token 抑制选项化**：现状=硬编码内建（security.rs:642 + perception.rs 双点）；改造=`PrivacyPolicy` 默认全开可配置 + 设备层（perception.rs:398）与纯函数层（274-284）双接线 + session_meta 键 + 设置面板开关；依赖=独立闭环，含「UIA 不提供值则回传空串」诚实边界断言。
- **R11 安全文档化**：现状=无集中威胁模型、`gate_check` 感知失败静默跳过（session.rs:141-152）是唯一静默面；改造=威胁模型文档（保护对象/不保护/三防线一句话职责）+ gate_check 按策略条件收紧为显式报错 + FullAccess 警示文案；依赖=文档可先行，断言改造挂靠 R4 落地。
