## 0. 结论速览（每条一句话）

- **R2 注入双模式**：推荐「UIA Invoke/SelectionItem/Toggle 语义优先 = 软后台 + 前台坐标注入默认」分层；pen/touch 全量后台列为 P3 不做进 MVP——后台模式未覆盖时返回 `background_unavailable` 由模型显式升级 foreground（对齐 cua macOS-aligned 契约），模式经 `Action::delivery_mode` + 工具参数 + 会话默认三入口透传。
- **R3 虚拟光标**：引擎侧置顶无焦点 overlay 窗口（`WS_EX_TOPMOST+TRANSPARENT+NOACTIVATE+TOOLWINDOW`），跟随注入坐标（foreground 模式随真实光标、background 模式独立显示），急停即隐藏/红色，审批等待期显待命样式。
- **R5 动作结果契约**：`ActionResult` 扩展 effect 五态 + evidence + partial 形状；effect 判定复用 49 联调 T4c（光标回读，action.rs:829-838）与 T5c（UIA ValuePattern 回读，perception.rs:398-408）已验证路径；新增 `computer_verify_state` 依赖 R7 暴露窗口级快照（perception.rs:357-372 snapshot_window 已在、工具面未暴露）。
- **R7 感知补强**：perception.rs 落地 `IUIAutomationCacheRequest` 批量抓取 + query 子串投影纯函数 + 深度/节点预算放宽（6/2000 → 16/5000）+ 快照节点携带 actions 列表 + 暴露窗口级快照入口。
- **R8 注入补强**：session.rs 层落地 WindowFromPoint 遮挡复核（直击 48 坑 2）+ IsIconic 最小化拒绝 + 布局表物理边界校验（-32000 哨兵自然覆盖）+ 可选前台恢复（cua AttachThreadInput 两次+settle 模式）。

## 2. 系统性改造方案

### 2.1 R2 注入双模式（默认 foreground + 可选 background）

#### 2.1.1 机制选型论证（pen/touch 全量 vs UIA Invoke 语义优先 vs 两者分层）

| 候选                             | 机制                                                                                                                                                                                                                                                | 成本                                                                                                                                   | 收益                                                                                              | 判定                                               |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| A. cua pen/touch 全量后台        | `CreateSyntheticPointerDevice(PT_PEN)` + `InjectSyntheticPointerInput` + `NoActivateGuard`（WS_EX_NOACTIVATE）+ `force_foreground_attached` 恢复 + 遮挡拒绝（inject.rs:169-220、237-289、334-368）                                                  | **高**：跨进程合成设备；WPF Wisp stylus 前台依赖、WinUI3 8/8 抢前台实测坑；键盘/文本后台一律不可达；每框架特判矩阵（53 §2.2 诚实清单） | 中：用户可同时用电脑                                                                              | 不做进 MVP（53 §5.2 清单 5 判 P3，与独立评审一致） |
| B. UIA Invoke 语义优先（软后台） | `InvokePattern → SelectionItemPattern → TogglePattern` 阶梯（open-codex runtime.ps1:711-728、917-957 auto 路径）；系统级语义动作，不经输入队列，**不抢焦点 + 免坐标误差 + 有返回值可判定**（53 §2.3 三点）                                          | **低**：复用 `UiaPerception`（windows crate COM 面已直调 ValuePattern，perception.rs:400-402），动作面加一个阶梯函数                   | 高：浏览器内按钮/链接/复选框命中即拿不抢焦点；「软件内协同浏览器」场景强相关（53 §5.2 清单 1 P1） | **MVP 采用**                                       |
| C. 两者分层                      | background 模式 = B 优先 → 未覆盖返回 `background_unavailable`（模型显式升级 foreground，绝不静默抢——cua macOS-aligned 契约 inject.rs:334-346）；PostMessage 坐标兜底列为可选项（接受 Chromium/WPF 静默丢弃面，open-codex 同款取舍）；A 作为后续 P3 | 中                                                                                                                                     | 契约诚实 + 渐进演进                                                                               | **推荐**                                           |

**选型结论：C 分层**。理由：① 我们场景目标窗口以浏览器/原生应用为主，UIA pattern 覆盖率可观（53 §2.3 评估「接入成本低、收益大」）；② 「必须不打扰用户」目前非硬需求（53 §5.2 清单 5 判 P3），pen/touch 的指数级成本（每框架特判 + 竞态恢复）不满足反过度设计红线；③ `background_unavailable` 结构化拒绝保持「background 永不静默跨到 foreground」的诚实契约，且与 R5 的 `refused` 语义天然衔接。**PostMessage 兜底不做进 MVP**（静默丢弃面大、收益低），键盘/文本后台一律 `background_unavailable`（cua 同判，inject.rs:780-786）。

#### 2.1.2 落地位置与数据流

- **`conex-computer/src/action.rs`**：`Action` 枚举注入变体（Click/MouseMove/MouseDown/MouseUp/Drag/Scroll）加 `delivery_mode: Option<DeliveryMode>`（`None` = 会话默认）；`pub enum DeliveryMode { Foreground, Background }`（serde snake_case）；`validate` 不变（模式非参数语义）。
- **`conex-computer/src/perception.rs`**：新增动作面 `invoke_preferred(el) -> Result<bool, PerceptionError>`（Invoke → SelectionItem.Select → Toggle 阶梯，open-codex runtime.ps1:711-728 同构）；`actions_available(el) -> Vec<ActionCapability>` 供 R7 actions 列表复用。
- **`crates/conex-computer-tools/src/session.rs`**：`RealComputerSession` 加 `delivery_mode: AtomicU8`（会话默认，foreground）；`dispatch` 内按模式分支：
  - `Foreground`：现状坐标注入（行为零变化）；
  - `Background`：`click` 时先 UIA 命中（`element_from_point` 或快照 `element_at_point`）→ `invoke_preferred` 成功即完成（不抢焦点）；失败/无 pattern → 返回结构化拒绝（见 §2.3 effect `refused` / 新错误码 `background_unavailable`）。
- **`crates/conex-computer-tools/src/tools.rs`**：注入 8 工具 schema 加可选 `delivery_mode` 枚举参数（`background`/`foreground`）；审批载荷加 `deliveryMode` 字段（§3.3）。

**模式切换入口（三层）**：工具调用参数 > 会话默认（`RealComputerSession::with_default_delivery`）> 硬默认 foreground（用户裁决：成功性更高）。

### 2.2 R3 虚拟光标（AI 可见指示器）

#### 2.2.1 形态候选

| 候选                            | 实现                             | 判定                                                                     |
| ------------------------------- | -------------------------------- | ------------------------------------------------------------------------ |
| 引擎侧置顶无焦点 overlay 窗口   | `CreateWindowEx`（`WS_EX_TOPMOST | WS_EX_TRANSPARENT                                                        | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW | WS_EX_LAYERED`），双缓冲绘制 AI 光标图形；鼠标事件点击穿透 | **推荐**：单进程 Rust 直绘、零 IPC；`WS_EX_NOACTIVATE` 保证不抢焦点；Tauri 壳无关 |
| Tauri 前端 React overlay        | 前端绝对定位组件跟随注入坐标事件 | 不推荐：WebView2 窗口自身会抢焦点，且需引擎→前端坐标事件 IPC（新增通道） |
| 系统光标位图（SetSystemCursor） | 全局替换真实光标                 | 不做：污染真实光标、影响用户                                             |

#### 2.2.2 数据流

```
注入坐标（API）→ ScaleSpec::api_to_phys（coord.rs:103-107）→ 注入后端
                                                      ↓（同一物理坐标，单一事实源）
                                          VirtualCursor::show_at(phys)
        foreground：真实光标随 SetCursorPos 到达注入坐标，overlay 与真实光标同位（双重可见）
        background/UIA Invoke：真实光标不动，overlay 独立显示于注入坐标（“AI 正在这里操作”）
```

- 新模块 `crates/conex-computer/src/virtual_cursor.rs`：`VirtualCursor { overlay_hwnd, visible, state }`；`show_at(Point)` / `hide()` / `set_state(CursorState::{Idle, Acting, AwaitingApproval, Stopped})`；窗口消息循环挂在会话线程（MTA 已就绪）。
- 挂载点：`RealComputerSession::dispatch` 包裹（注入前 show_at 目标坐标、注入后维持显示）；感知动作（screenshot/snapshot）不触发。
- **急停联动**：`EmergencyStop` 置旗（security.rs:525 trigger）→ overlay 立即 `hide()` 或转 `Stopped` 红色态；引擎侧在工具 execute 的守卫④与 `computer_estop` 路径调用（tools.rs:372-385 同一吊销链）。
- **审批联动**：守卫⑤ `Pending`（tools.rs:151-165）期间 overlay 显示 `AwaitingApproval` 样式（目标坐标待命），settle Granted 后跟随注入。
- 与真实光标区分：不同形状/颜色 + 「AI」标签；R7 快照/截屏不回显 overlay（截屏走 xcap 桌面采集，overlay 属另一个窗口——**注意**：overlay 窗口会被截屏捕获到，需 `WS_EX_TOOLWINDOW` + 截屏排除或接受（推荐：overlay 不落入截屏——xcap 采集显示器内容含 overlay，需在 capture 时对 overlay 区域做遮蔽评估；MVP 接受「截屏含虚拟光标」并登记，或 overlay 仅动作期间短暂显示）。

### 2.3 R5 动作结果契约（effect 五态 + evidence + verify_state）

#### 2.3.1 ActionResult 扩展形状（serde）

```rust
// conex-computer/src/lib.rs
pub enum ActionEffect { Confirmed, Partial, Unverifiable, SuspectedNoop, Refused }
pub struct ActionEvidence { pub kind: EvidenceKind }
pub enum EvidenceKind { CursorReadback, ValueReadback, WindowChange }

// 工具层返回形状（tools.rs 注入 8 工具统一）
{
  "ok": true,                       // 兼容保留（过渡期；cua 封闭契约建议最终删除）
  "effect": "confirmed",            // confirmed|partial|unverifiable|suspected_noop|refused
  "route": "global_input" | "accessibility",   // foreground 注入 / 软后台 Invoke
  "deliveryMode": "foreground" | "background",
  "evidence": [{"kind": "value_readback"}],    // 仅 confirmed
  "partial": {"deliveredChars": 34, "totalChars": 50},  // 仅 partial
  "perceptionVersion": 7
}
```

会话层：`ActionResult` 维持 `Done/CursorPosition`（派发闭环不变，避免破坏 `ComputerOps` trait）；**effect 判定放工具层**（tools.rs 有 session 引用可做回读），`ComputerOps` 增量两个方法：`async fn cursor_position(&self) -> Result<Point, SessionError>`（现有 dispatch CursorPosition 薄包装）与 `async fn verify_state(&self, predicates: &[VerifyPredicate]) -> Result<VerificationOutcome, PerceptionError>`（§2.3.3）。

#### 2.3.2 effect 判定逻辑（回读比对/超时/无法判定）

| 动作                            | 判定规则                                                                                                                                                                                                                                                                           | confirmed 证据    | 降级                                                                               |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- | ---------------------------------------------------------------------------------- |
| move/click                      | 注入后回读 `cursor_physical`（action.rs:829-838）→ 物理距离 ≤ 容差（2px，复用 T4c 路径）→ **confirmed**                                                                                                                                                                            | `cursor_readback` | 回读失败/感知不可用 → `unverifiable`；坐标被 R8 遮挡检查拒绝 → `refused`（不注入） |
| type                            | 分块完成后 UIA 值回读（T5c 路径：ValuePattern，perception.rs:398-408）→ 目标输入框值尾部匹配 → **confirmed**；值无变化且预期有变化 → **suspected_noop**；分块间中止（§1.3 块间自查补上后）→ **partial** `{deliveredChars: 已注入块字符数, totalChars: 全部字符数}`                 | `value_readback`  | 回读不可用 → `unverifiable`                                                        |
| key/hold_key/button/drag/scroll | 无坐标/值回读语义：`perception_version` 推进（session.rs:174）仅作**弱证据**（`window_change`）——首版**判 `unverifiable`**（诚实：版本推进是「感知可能变了」，非「动作生效」；cua 定义 confirmed 需可发布读回证据，contract.md:73-76）；窗口级状态变化交由 `verify_state` 显式确认 | —（空证据）       | —                                                                                  |
| 守卫拒绝路径                    | 审批拒/门禁拒/急停（既有错误码）→ effect 语义 = **refused**（54 §2.2「拒绝态完备」优势保持）                                                                                                                                                                                       | —                 | —                                                                                  |

**超时**：回读等待统一上限 500ms（调度线程 sleep 轮询，不阻塞派发线程），超时 → `unverifiable`（防卡）。

#### 2.3.3 verify_state 工具设计（satisfied/unsatisfied/unknown 三态）

- **新感知工具 `computer_verify_state`**（dangerous=true 默认审批，对齐感知 4 工具可配免审；schema：`predicates` 数组 1-8 个 ANDed 谓词 + 可选 `include_snapshot: bool`）。
- **谓词形状**（对齐 cua verify_state 的精确目标绑定，contract/README.md:57-67 的窗口级语义）：
  ```json
  [
    { "window_title": "记事本" }, // 窗口标题存在
    {
      "element": { "role": "edit", "name_contains": "输入", "value": "hello" }
    }, // 窗口级快照内元素存在+值匹配
    { "cursor_at": { "x": 348, "y": 302, "tolerance": 2 } } // 光标位置断言（API 空间）
  ]
  ```
- **实现**：`RealComputerSession::verify_state` → 解析活动窗口 hwnd（UiaPerception 新增 `focused_window_hwnd()`：GetFocusedElement → `CurrentNativeWindowHandle`）→ `snapshot_window(hwnd)`（perception.rs:357-372 已有）→ 谓词求值**纯函数**（新模块 `verify.rs` 或 perception.rs 内，fixture 可单测）。
- **三态语义**：全谓词满足 → `satisfied`（唯一成功终态）；任一明确不满足 → `unsatisfied`；感知不可用/窗口无几何/谓词无法求值 → `unknown`（**永不提升为成功**，contract.md:78-83）。
- 输出：`{"verification": {"status": "satisfied"}, "evidence": [{"kind": "window_change"}]}`。

### 2.4 R7 感知补强

落地位置全部在 `conex-computer/src/perception.rs` + `conex-computer-tools/src/tools.rs`：

1. **`IUIAutomationCacheRequest` 批量抓取**（对齐 cua impl_.rs:1111-1113 描述）：`UiaPerception::new` 时 `CreateCacheRequest` + `AddProperty`（ControlType/Name/IsPassword/BoundingRectangle + ValuePattern 的 Value 属性）→ `CreateTreeWalkerWithOptions`（或 `ElementFromHandleWithOptions`）→ `read_node` 改读 `CachedControlType/CachedName/CachedIsPassword/CachedBoundingRectangle`（单次 COM 往返取全部属性）；`GetCurrentPatternAs` 保留用于动态 pattern 探测（Invoke 可用性，perception.rs:400-402 同构）。验收：5000 节点大树 ≤3s（cua 同量级）。
2. **query 子串投影**（对齐 cua get_window_state query 语义，impl_.rs:1102-1105）：纯函数 `project_query(root: &PerceptionNode, keyword: &str) -> (PerceptionNode, usize, usize)`（保留命中行 + 祖先链，返回 total/returned 计数）；工具层 `computer_snapshot` 加可选 `query` 参数 → 返回 `totalElementCount/returnedElementCount`。
3. **树深度/节点预算放宽**：`MAX_TREE_DEPTH` 6 → **16**（cua 25 / open-codex 64 之间取平衡，浏览器 10k+ 节点树在 5000 节点预算下仍受控）；`MAX_TREE_NODES` 2000 → **5000**（对齐 cua 默认）。工具层 `max_depth/max_elements` 请求级覆盖保留（tools.rs:934-986 二次截断不动）。
4. **快照携带 actions 列表**：`PerceptionNode` 加 `actions: Vec<String>`（"invoke"/"select"/"toggle"，经 `GetCurrentPatternAs::<IUIAutomationInvokePattern>(UIA_InvokePatternId)` 探测，perception.rs:400-402 同构）；R2 软后台直接消费此字段。
5. **暴露窗口级快照**：`PerceptionSource` 加 `snapshot_window_hwnd(hwnd) -> Result<PerceptionSnapshot, PerceptionError>`（包装既有 snapshot_window）；`RealComputerSession` 暴露 `verify_state` 与窗口级快照入口——R5 落地前提（54 §2.2 明确登记）。

### 3.3 与权限模式化（security.rs 分析线）的接口交点

## 4. 验收断言（每条改造的可测断言）

### R2 注入双模式

- `background_click_does_not_change_foreground`：background 模式 UIA Invoke 点击前后 `GetForegroundWindow` 相等（含目标窗口不激活）。
- `background_click_invoke_preferred_when_pattern_available`：命中 InvokePattern 元素 → 走 Invoke（探针断言 pattern 调用，无 SetCursorPos）。
- `background_unavailable_when_no_pattern_and_occluded`：无 pattern 且坐标被遮挡 → 结构化错误（非注入、非 ok:true）。
- `background_type_key_returns_background_unavailable`：background 模式 type/key → 结构化拒绝（键盘/文本后台不可达，对齐 cua 契约）。
- `foreground_default_mode_behavior_unchanged`：默认模式点击路径与 48 冒烟行为一致（0px 偏差回归）。

### R3 虚拟光标

- `virtual_cursor_visible_at_injected_coordinate`：AI 注入 click 后 overlay 光标出现于注入坐标（overlay 窗口 GetWindowRect 断言）。
- `virtual_cursor_visible_when_real_cursor_stationary`：background/UIA Invoke 模式下真实光标不动，虚拟光标仍显示于注入坐标。
- `virtual_cursor_distinct_from_real_cursor`：overlay 绘制样式（颜色/形状/标签）与系统光标可区分（像素采样或样式断言）。
- `estop_hides_virtual_cursor`：急停触发后 overlay 隐藏或转 Stopped 态（≤100ms）。
- `approval_pending_shows_awaiting_state`：审批等待期 overlay 显待命样式；拒绝后隐藏。

### R5 动作结果契约

- `click_miss_returns_unverifiable_not_ok`：点击落空（坐标无目标/遮挡前检查失败路径）→ `effect: "unverifiable"` 而非 `ok:true`（54 §2.1 第一性缺口）。
- `type_success_confirmed_with_value_readback`：type 后 UIA 回读值尾部匹配 → `effect: "confirmed"` + `evidence: [{"kind":"value_readback"}]`（T5c 路径生产化）。
- `type_abort_returns_partial_delivered_chars`：分块间急停 → `partial {deliveredChars, totalChars}`（块间自查落地后，04 §5 项 5 同源）。
- `key_without_readback_returns_unverifiable`：key/hold_key 等无回读证据 → `unverifiable`（诚实契约，不伪装 confirmed）。
- `approval_denied_maps_effect_refused`：守卫拒绝路径 effect 语义 refused（错误码映射不变）。
- `verify_state_satisfied_unsatisfied_unknown`：窗口标题存在 → satisfied；不存在 → unsatisfied；UIA 不可用 → unknown（永不提升）。
- `verify_state_element_value_predicate`：窗口级快照内 element 谓词求值正确（fixture 单测）。

### R7 感知补强

- `cache_request_large_tree_under_3s`：5000 节点大树快照 ≤3s（CacheRequest 生效，对齐 cua 2-3s）。
- `query_projection_keeps_ancestors_and_counts`：query 投影只返回命中行 + 祖先链；`totalElementCount`/`returnedElementCount` 正确（原索引保留）。
- `depth_relaxed_nested_edit_visible`：深度 >6 的嵌套元素可见（fixture 树断言）。
- `node_actions_list_invoke_for_button`：按钮节点 `actions` 含 "invoke"（有 InvokePattern）；无 pattern 节点为空数组。
- `snapshot_window_scoped_to_hwnd`：窗口级快照只含该窗口子树（根 = 目标窗口）。

### R8 注入补强

- `occluded_click_rejected_not_misclicked`：目标被全屏窗口覆盖 → `tool.computer.occluded_target`（48 坑 2 修复回归断言）。
- `phys_point_outside_virtual_desktop_rejected`：物理点 -32000 哨兵 / 桌面外 → 拒绝（图标哨兵检查）。
- `minimized_window_target_rejected`：目标最小化（IsIconic）→ 拒绝。
- `restore_foreground_returns_to_prev_window`：`restore_foreground=true` 时动作后 `GetForegroundWindow` == 动作前（两次+settle 竞态窗口内断言）。
