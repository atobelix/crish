## 1. 结论速览

1. **工具族 13 个**（命名统一 `computer_*`，18 §2.1 动作空间全量覆盖）：注入 8（click/type/key/hold_key/move/button/drag/scroll，全 dangerous）、感知 4（wait/screenshot/cursor_position/snapshot，全 dangerous，默认审批可配免审）、急停 1（estop）。与 04 §2 S5「17 动作 = 17 个 ToolDefinition」的数量差异为本轮**数量裁决**（任务书授权），依据见 §2.1——合并面与 `conex-computer` 的 `Action` 枚举一一对应（click 系列/按下抬起系列本就合并为带参数的枚举变体），增量面补齐 UIA 主通道与 AI 主动急停两个工具化能力。
2. **注册与装配**：`register_computer_tools(registry, config)` 后置注册（对齐 `register_browser_tools` 先例，不进 `register_builtin_tools` 注册数断言面）；**挂载判据内置注册函数**——`config.enablement.tool_mount_allowed()` 为假（未开启/未注入）→ 零注册返回 Ok；幂等跳过同名；命名空间 `computer_*` vs `browser_*` 同注册表共存无键冲突（§3）。
3. **守卫链**：互斥守卫（`ActivationGate` 非 DesktopActive → `tool.session.exclusive`）与开启复查（`check_action_allowed` → `tool.computer.not_enabled`）均在**审批之前**（04 §4.6 / security.rs 注释登记）；审批 = `ApprovalGate` 逐次审批 + 既有 `ctx.ask` 传输面；急停 = `EmergencyStop` 旗自查 + 在途批次自查（§4.2）。
4. **错误码表**：`tool.computer.*` 8 码 + 跨线 `tool.session.exclusive`，本 crate `codes` 常量先行，conex-types 码表登记为遗留接线项（主控登记，§5）。
5. **骨架落地**：`crates/conex-computer-tools`（Cargo.toml + src/lib.rs 单文件骨架）：13 个工具定义（schema/dangerous 定稿）+ 注册函数 + 挂载判据 + `ComputerOps` 会话注入 trait + 8 个单测（注册数/未接线契约/命名空间共存，§7 验收项 1-6 已绿）。

## 3. 注册与装配

### 3.1 注册函数签名与配置（后置注册，对齐 browser 先例）

```rust
// crates/conex-computer-tools/src/lib.rs
pub fn register_computer_tools(
    registry: &mut ToolRegistry,
    config: ComputerToolsConfig,
) -> Result<(), ToolError>

#[derive(Clone, Default)]
pub struct ComputerToolsConfig {
    /// 会话注入面（ComputerOps trait；测试 mock 替身 / 引擎 RealComputerSession）
    pub session: Option<Arc<dyn ComputerOps>>,
    /// 会话级显式开启判据（缺省 None = 视为未开启，零注册安全默认）
    pub enablement: Option<Arc<SessionEnablement>>,
    /// 会话互斥守卫（S3；实施轮接线）
    pub activation: Option<Arc<ActivationGate>>,
    /// 全动作审批门（04 §4.2；实施轮接线）
    pub approval: Option<Arc<ApprovalGate>>,
    /// 三级急停旗（04 §4.3；实施轮接线）
    pub stop: Option<Arc<EmergencyStop>>,
}
```

装配规则（对齐 17 §1.4 浏览器先例）：

- **不进** `agent-tools::register_builtin_tools`（该函数有注册数断言，tools/mod.rs:718-756，
  不可扰动；lib.rs:8-11 注记）——`computer_*` 与 `browser_*` 一样经 `ToolRegistry::register_runtime`
  （registry.rs:49，&self 共享面）并入运行集；
- **挂载判据内置注册函数**（04 §4.1 第 3 点 + security.rs:226 `tool_mount_allowed` 注释登记：
  「S5 注册函数判据」）：`config.enablement.tool_mount_allowed()` 为真才注册；未开启 / 未注入 →
  **零注册返回 Ok**——`computer_*` 工具不存在，模型侧 tool schema 亦不含（安全默认；
  骨架测试 `registration_default_config_mounts_zero` / `registration_disabled_enablement_mounts_zero`
  守护）；
- **幂等**：同名已注册（MCP/引擎预注册/重复调用）跳过不报冲突（骨架测试
  `registration_twice_is_idempotent`）；配置字段为实施轮注入面，注册期不消费；
- **注册失败原子性**：注册过程任一 `register_runtime` 失败 → 结构化错误返回（对齐
  `registration_rejects_invalid_gate_patterns` 先例语义：失败不留下半成品工具）。

### 3.2 幂等键（S5 任务 3）

复用 `agent-tools/src/idempotency.rs`（45-176）既有机制，键 = 会话 + 动作 + 参数哈希
（18 §5 项 4「幂等键 = 会话 + 动作 + 参数哈希」）；注册面零新增代码，执行器层既有
幂等守卫（B5.3）自动覆盖 `computer_*`。注意：注入类工具重复执行有物理副作用，幂等
仅防重试风暴（网络重发），模型侧仍以审批+回显闭环为准。

### 3.3 命名空间共存（computer_* vs browser_*）

- 自研工具统一 `computer_*` 前缀，与 `browser_*` / MCP 桥 `mcp_<server>__*` 天然互斥：
  注册表内无键冲突，`register_runtime` 同名返回 `tool.version_conflict` 的保护同样生效；
- 两族工具同注册表共存、模型同时可见、名称无歧义（骨架测试
  `coexists_with_browser_tools_in_same_registry`：24 + 13 = 37 全注册且 `list_definitions`
  两族齐备）；
- **互斥语义**：注册共存 ≠ 会话共存——`ActivationGate` 状态机（Idle/Browser/Desktop）
  保证两族**不可同时活跃**，工具面互斥守卫（`tool.session.exclusive`）两向生效（§4.2 守卫①）。

## 4. 会话注入面与执行守卫链

### 4.1 会话注入面（ComputerOps，SessionOps 类似抽象）

对齐浏览器线 `SessionOps` 范式（conex-browser-tools/src/session.rs:85：trait 面消费 +
测试 mock 替身注入），桌面线定义 `ComputerOps` trait（骨架已落地，`pub mod session`）：

```rust
#[async_trait]
pub trait ComputerOps: Send + Sync {
    /// 就绪检查：Err(原因) = 工具层应返回 `tool.computer.not_ready`
    fn readiness(&self) -> Result<(), String>;
    /// 动作派发（参数校验 → 坐标换算 → 注入闭环；急停批次自查在会话内）
    async fn dispatch(&self, action: &Action) -> Result<ActionResult, SessionError>;
    /// 截屏感知（缩放后合成帧；zoom region 裁剪为工具层纯后处理）
    async fn screenshot(&self) -> Result<CapturedFrame, SessionError>;
    /// UIA 结构化快照（数据面抑制后产物：密码框占位/键名脱敏）
    async fn snapshot(&self) -> Result<PerceptionSnapshot, PerceptionError>;
    /// 感知版本号（校验路径复用；输入动作后推进）
    fn perception_version(&self) -> u64;
}
```

- 实施轮 `RealComputerSession` 包装 `conex-computer::ComputerSession`（lib.rs:66）+
  `perception::UiaPerception`（perception.rs:318），仅消费 pub 接口；
- 工具层经 `ComputerToolsConfig.session` 注入；未注入 → 执行返回 `tool.computer.not_ready`
  （对齐 browser 的 R-9 gating 语义）；
- 动作前检查器（白名单窗口/提权探测）走 `conex-shared::gate::ActionTargetGate`
  （05 文档 §5.2：`WindowTargetGate` → `tool.computer.elevated_window`），实施轮接入
  守卫链第 6 步（§4.2）。

### 4.2 执行守卫链（顺序即优先级；互斥与开启复查在审批之前）

```
computer_* 工具 execute：
① 会话注入检查   session 未注入            → tool.computer.not_ready
② 互斥守卫       activation.current() 非
                  DesktopActive            → tool.session.exclusive   ← 硬约束，审批前
③ 开启态复查     check_action_allowed()
                  未开启/已挂起/急停后      → tool.computer.not_enabled（零副作用）
④ 急停自查       stop.stopped()            → tool.computer.cancelled
⑤ 逐次审批       approval.require_approval(载荷) → Pending
                  → 引擎经 ctx.ask 送用户   → settle 收口
                  拒绝/急停中/并发请求      → Denied（零注入；approval.rejected）
⑥ 执行           参数校验(→invalid_params) → 坐标换算(→coords_out_of_bounds)
                  → ActionTargetGate 门禁(白名单/提权→elevated_window)
                  → ComputerOps.dispatch / screenshot / snapshot
                  注入批次间自查 stop/abort_token → tool.computer.cancelled
```

- **守卫②在审批之前**（04 §4.6 / 18 §6.3：互斥是硬约束，不占审批资源；两向生效——
  `browser_*` 非 Browser 态同样返回 `tool.session.exclusive`，executor 层统一接线）；
- **守卫③在审批之前**（security.rs:216 `check_action_allowed` 注释登记「04 §4.2 守卫检查点」；
  挂载是注册时刻快照，运行期挂起/急停后回 Idle 由本守卫兜底拒绝）；
- **审批载荷** = `security::ApprovalRequest`（security.rs:248：动作名 + 参数摘要 + 目标窗口
  标题 + 物理坐标；`type` 明文显示，审计只落 sha256）；`approval` 未注入（None）时按
  Denied 收口（安全默认，不静默放行——与 ctx.ask 未接线时浏览器线交互工具的拒绝语义对齐）；
- **审批等待期取消**：等待期间 `stop.stopped()` / `ctx.abort_token.is_aborted()` →
  以 Denied（原因「急停/取消」）收口，拒绝时零注入（security.rs:305-314 注释登记）；
- **急停**：`computer_estop` 触发 `EmergencyStop::global_stop()` + 引擎侧
  `ctx.abort_token.abort()`（同一吊销链，04 §4.3 ①；来源记录为 Global——AI 主动急停
  并入全局急停，无新增 StopSource，改动面最小）；其余工具执行前/批次间自查
  `stop.stopped()`（04 §4.3 急停语义：在途注入按批次自查 → 感知源停止 → 会话回 Idle）。

### 4.3 降级接线（S5 任务 6）

- 能力探测：`supports_vision`（agent-provider/src/models/catalog.rs:127）+ UIA 可用性
  （`conex-computer::perception` 探测）→ 18 §3.4 降级矩阵 4 格（UIA×视觉）；
- 双通道皆无 → **挂载报错拒绝启用**：注册期能力探测失败返回
  `tool.computer.capability_unavailable`（矩阵第 4 格，不静默降级）；
- 单通道：UIA 主通道独立闭环（元素 → 坐标 → 注入）或截屏主通道（坐标全视觉）；
  `computer_snapshot`/`computer_screenshot` 可用性随能力位联动（探测后按矩阵隐藏
  不可用感知工具）。
