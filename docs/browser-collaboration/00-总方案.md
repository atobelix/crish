## 2. 现状总判（三分析文档综合）

- **已具备的坚固底座**：13 工具守卫链（会话注入→互斥→开启态→急停→逐次审批→执行，tools.rs:5-21）、三级急停（security.rs:467+）、互斥（activation.rs）、提权探测框架（window_gate.rs，**但生产路径失效——A1**）、UIA 感知+密码数据面抑制（perception.rs）、前台注入（action.rs enigo+SetCursorPos）、ComputerSlot 装配（computer/mod.rs，1099f955）。
- **最严重发现**：A1 提权探测生产路径失效（进程名恒 None）；A2 桌面线分块无块间自查；A3 ok:true 混淆契约语义；A4 方案文档与用户裁决三向矛盾。**先修基线，再叠加功能。**
- **架构结论**：我们的骨架（UIA 树感知 + 真实事件注入 + 一体化安全面）是正确的第一梯队；缺口集中在「执行后事实契约」「权限模式化」「感知性能与语义补强」「生态暴露面」四块，全部可在既有架构内落地，无架构级推翻。

## 8. 分阶段详案生成与审计流程（用户指定，强制）

1. **详案生成**：子 Agent 依据本总方案的轮次规划，生成**每轮详细方案**（轮次之间按逻辑递进关系拆解，是连贯的计划方案而非总方案复制）；详案须含：任务单元分解、文件域、接口/数据流、验收断言、与前后轮的接口约定。
2. **评审**：多个评审 Agent 并行审计——① 方案逻辑连贯性（需求全集无遗漏、依赖不变量无违反）；② 每轮 Agent 工作量均衡性；③ 文件冲突（同文件跨轮/跨任务单元撞车）；④ 与既有文档（04/05/06）契约一致性。审计维度按 `docs/agent-roles/review/review.md`（默认只分析内部，不参考外部软件）。
3. **定夺与修复**：主控综合评审意见定夺；多 Agent 修复总方案 + 分阶段计划方案（**只与逻辑有关**——不含时间、重要性、人员安排）。
4. **执行放行**：审计通过后，才可派发实现 Agent 执行各轮任务。
