> 证据约定：`文件路径:行号`。复杂度等级：常规 / 1-2 倍 / 3 倍+（相对常规选型；3 倍+ 直接放弃）。

## 0. 一句话结论

**受管独立 Chromium（Chrome for Testing 为主、系统 Chrome/Edge 回退）× 随机端口 CDP 控制通道（loopback + DevToolsActivePort + 生命周期收紧）× 本仓自研薄 CDP 客户端（agent-browser 蓝本）× AX 快照 + data-* 原生标记定位 × 三态域名门禁（allowed/prohibited/IP 阻断）× 会话级最小化 profile 复制（密码/历史/自动填充排除 + 显式确认）× browser_* 工具 dangerous 分级接入既有 PermissionMode 审批与审计 sink × 软互斥协同（用户接管即吊销 AI 令牌）＋ 电脑操作二期以「会话显式开启 + 全动作审批 + 全局急停 + 硬隔离」为门槛。**

复杂度评估：**1-2 倍**（不超阈值；3 倍+ 的 CEF、注入脚本桥、隔离桌面方案均已放弃，见对应维度）。

## 2. 维度 1：渲染实例

### 候选对比

| 候选 | CDP 自动化 | 用户协同（可见可操作） | 导入 Chrome/Edge 数据 | 崩溃隔离 | 体积/复杂度 | 安全 |
| --- | --- | --- | --- | --- | --- | --- |
| Tauri 子 WebView2（`as_child`，Windows only） | 弱：CDP 需 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port` 走调试口，生态不成熟 | 中：嵌入主窗口内嵌原生控件，但 z-order/焦点/DPI 坑多 | **致命伤：WebView2 的 Cookies/profile 格式与 Chrome 不兼容，无法直接复用 Chrome 用户数据**（登录态导入是硬需求） | 差：与主 UI 同属 WebView2 运行时 | 中 | 与主 webview 同进程面 |
| 独立 Chromium（Chrome for Testing / 系统 Chrome/Edge） | 强：完整 CDP（browser-use、chrome-devtools-mcp、agent-browser 全部走此路） | 强：独立窗口，用户可直接操作 | 强：browser-use 整目录 profile 复制先例（`profile.py:838-893`） | 好：子进程，崩溃不影响主 app | 中（多一进程 + 下载/分发 CfT） | 好：独立沙箱 + 独立 user-data-dir |
| iframe（现状，`PreviewCard.tsx:190-202`） | 无：无 CDP、跨域被 X-Frame-Options/CSP 挡（`PreviewCard.tsx:18-19` 注释） | 弱：用户可用但站点常禁止嵌入 | 无 | — | 常规 | 弱：sandbox 受限（当前已加 sandbox 属性） |
| CEF | 强（CEF 自带 API） | 强 | 强 | 好 | **3 倍+：C++ 依赖链、构建集成复杂度不可接受** | 中 |

### 结论

**独立 Chromium 子进程**：默认随产品分发/按需安装 **Chrome for Testing**（agent-browser `cli/src/install.rs` 有 download/install 先例，版本固定可审计），用户机器已装 **系统 Chrome / Edge** 时作为回退（browser-use `BrowserChannel` 枚举 `profile.py:314-324` 覆盖 chrome/msedge 各通道）。iframe 保留仅用于「本地 URL 快速预览」场景（现状功能不删，与 AI 浏览器并存）。

### 理由

1. **数据导入是硬需求且不可妥协**：WebView2 的 profile 格式与 Chrome 不互通，直接淘汰。这是决定性理由。
2. 独立进程 = 崩溃隔离 + 沙箱独立 + 退出杀树可管控（运维友好）。
3. CfT 无自动更新：对安全/运维反而**可控**（版本钉死、更新策略由我们发布节奏决定），且避免用户 Chrome 升级导致 CDP 行为漂移。
4. 参考实现全部验证过此路：browser-use（CDP + 系统 Chrome）、chrome-devtools-mcp（`puppeteer.launch` 连系统 Chrome，`src/browser.ts:231-246`）、agent-browser（CfT 下载 + `--remote-debugging-port=0`）。

### 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| CfT 分发体积与首次下载 | 按需惰性安装（首次使用 AI 浏览器时提示安装），agent-browser `install` 命令先例 |
| 多进程内存占用 | 会话粒度生命周期：空闲超时自动关浏览器（agent-browser daemon 空闲自关先例 `daemon.rs` idle_timeout） |
| 用户同时开自己 Chrome 操作同 profile | 见维度 7（临时复制 + 锁冲突处理），绝不直接占用用户原 profile |

## 3. 维度 2：AI 控制通道

### 候选对比

| 候选 | 暴露面 | 多客户端/调试 | 生命周期可控 | 运维（日志/恢复） | 复杂度 |
| --- | --- | --- | --- | --- | --- |
| a. 固定调试端口（browser-use `CHROME_DEBUG_PORT=9242`，`profile.py:28`） | 差：端口可探测、易被本机进程扫描（9222 是知名攻击面）；browser-use 专门挑非默认端口躲冲突——但**端口固定=可发现** | 好 | 中 | 中 | 常规 |
| b. 随机端口 + DevToolsActivePort（agent-browser `cdp/chrome.rs:408` `--remote-debugging-port=0` + `:687-762` 读文件 + `:943` 解析；chrome-devtools-mcp 连用户 Chrome 也读该文件 `browser.ts:84-103`） | 中：端口随机不可预知；同用户进程仍可读 user-data-dir 下文件 | 好 | 好：stale 文件清理（`chrome.rs:631-633`） | 好：超时等待、端口解析失败路径齐全 | 常规~1-2 倍 |
| c. `--remote-debugging-pipe`（chrome-devtools-mcp 启动自家浏览器时 `pipe: true`，`browser.ts:237`） | **最好：零网络监听** | 差：单客户端、断线重连/多会话处理复杂 | 中 | 差：调试不便（无法 chrome://inspect）、崩溃恢复链路长 | 1-2 倍 |
| d. 注入脚本桥（扩展/content script；agent-browser eve 扩展体系 `extension.ts`） | 好：无端口 | 中 | 中 | 差：协议自研工作量 3 倍+，且扩展行为可被页面探测/干扰（chrome-devtools-mcp 连扩展页都要 targetFilter 过滤，`browser.ts:24-44`） | **3 倍+：放弃** |
| e. 双轨（CDP + 注入） | — | — | — | — | 3 倍+：放弃（单轨 CDP 即可覆盖全部需求） |

### 结论

**b（随机端口 + DevToolsActivePort）**，按 agent-browser 的完整生命周期做法实现：
- `--remote-debugging-port=0` + 启动前删除 stale `DevToolsActivePort` + 轮询等待文件 + 超时失败（`chrome.rs:408, 631-633, 687-762`）；
- WS 地址固定 `ws://127.0.0.1:<port><path>`（Chrome 调试端口仅绑 loopback，`browser.ts:102` 同款）；
- 端口号、WS path 只存在于进程内与 user-data-dir 文件，**不进日志**；
- user-data-dir 位于用户私有目录（`%LOCALAPPDATA%\Crish\...`），文件 ACL 收紧为本用户。

pipe（c）登记为**后续加固选项**（若安全审计要求"我方功能零监听"时切换），当前不采用的理由：我们只有一个客户端（AI 控制层），pipe 单客户端限制不构成阻碍，但其断线重连、日志与调试可观测性显著更差，运维收益为负；而随机端口 + loopback 已将暴露面收敛到「本机同用户进程」，与 Chrome 自身 cookies 文件暴露等价（不扩大威胁模型，见维度 9 论证）。

### 理由

1. 对齐 31 基线 B5 精神：监听仅 loopback + 生命周期收紧；随机端口把「固定端口可探测」变成「随机不可预知」，防御纵深 +1。
2. agent-browser（生产级 Rust 实现）全链路验证过该路径（含 stale 清理、超时、端口解析降级），照抄即可，风险最低。
3. 端口机制同时服务「导入用户 Chrome 数据后以浏览器身份续用」与「AI 连接」两个场景（chrome-devtools-mcp `browser.ts:84-111` 已演示对用户 Chrome 的 DevToolsActivePort 连接）。

### 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| DevToolsActivePort 被同机恶意进程读取 → CDP 全控（读 cookies、注入 JS） | 威胁模型论证：同用户进程本就可读 Chrome cookies 明文文件（`%LOCALAPPDATA%\Google\Chrome\User Data\Default\Cookies`），不新增暴露；仍做 ACL 收紧 + 会话结束即删 |
| Chrome 无 CDP token 认证 | 依赖「端口随机 + loopback + user-data-dir 私有」三重收敛；不引入 `--remote-allow-origins=*` |

## 4. 维度 3：Rust CDP 客户端选型

### 候选对比

| 候选 | 功能完整度 | 审计/门禁/审批钩子 | 依赖面（B9 基线） | 维护风险 | 复杂度 |
| --- | --- | --- | --- | --- | --- |
| chromiumoxide（crate） | 高：Browser/Page 全抽象 | 差：命令封装在库内部，逐命令挂审计/幂等/审批需侵入式改动 | 重：hyper/tokio 大栈 | 中高：维护周期不稳、抽象层绑定其设计 | 中 |
| **自研薄客户端**（agent-browser 蓝本：`cli/Cargo.toml` 仅 tokio-tungstenite + futures-util + serde_json，无 CDP 库） | 按需：只实现所需 domain（Browser/Page/Target/Runtime/Input/Accessibility/Fetch/Network/Storage），agent-browser `cdp/types.rs` 类型化先例 | **最好：所有命令必经我们自己的发送层 → 天然挂审计、幂等、审批、急停钩子** | 轻：新增 tokio-tungstenite（agent-browser 同款 0.24，与 tokio 1 兼容） | 低：协议面收敛（只实现用到的命令），CfT 版本固定后协议稳定 | 1-2 倍 |
| playwright-rs | 高 | 差 | 极重：需 Node 运行时 + playwright 服务器双栈 | 中 | 3 倍+（双栈打包）：放弃 |
| Node 桥（puppeteer 子进程，chrome-devtools-mcp 模式） | 高 | 中：桥接层加钩子可行，但引入 Node 运行时依赖 | 重 | 中 | 2 倍（双运行时）：放弃 |

### 结论

**自研薄 CDP 客户端**，分层：
- `transport`：WS 连接/重连/超时/消息 id 映射（tokio-tungstenite）；
- `types`：AXNode、EvaluateResult 等类型化结构（agent-browser `cdp/types.rs:294-310` 先例）；
- `sender`：唯一命令出口——**在此层统一挂：审计事件（脱敏后）、幂等去重、审批前置、急停检查、超时**。

### 理由

1. 安全/运维视角的决定性理由：**审批与审计必须覆盖每个 CDP 命令**，只有自研发送层能零死角接管；用库则要么绕过库抽象、要么放弃钩子。
2. agent-browser 是生产级 Rust 参考实现（Vercel Labs 出品，320 单测 + 18 e2e），证明工作量可控且已有完整蓝图可抄（snapshot/element/interaction/policy 全套）。
3. B9 基线：新增依赖面最小（单 crate tokio-tungstenite，需按 `31-security-baseline.md:161-169` 做评审登记）。

### 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| CDP 协议维护成本 | 版本钉死 CfT + 协议面收敛（只实现所需 domain/命令）+ agent-browser 蓝本对齐 |
| WS 断线/浏览器崩溃 | transport 层统一错误类型 + 上层会话状态机恢复（维度 9 生命周期） |

## 5. 维度 4：感知快照

### 候选对比

| 候选 | 语义/稳定性 | 数据量 | 隐私面（进模型上下文） | iframe 支持 | 复杂度 |
| --- | --- | --- | --- | --- | --- |
| DOM 树序列化（browser-use 可交互元素索引化） | 中：页面 JS 可探测/污染，树大 | 大（全树） | 大 | 需 OOPIF 处理（browser-use `max_iframes`/`max_iframe_depth` 上限 `profile.py:668-676`） | 1-2 倍 |
| **AX 树**（CDP `Accessibility.enable` + `Accessibility.getFullAXTree`；agent-browser `snapshot.rs:228,315` 蓝本） | 高：稳定语义（role/name/状态），不随 DOM 噪音抖动 | 小：只含语义节点 | 中（文本仍可含敏感字段 → 需字段级过滤） | 好：per-frame session（`snapshot.rs:310` 每 frame enable） | 常规 |
| 纯视觉（截图 + LLM 看图） | 高 | 极大 | **最大：整屏像素进模型** | 好 | 常规（但成本/隐私不可作主通道） | 常规 |

### 结论

**AX 树为主通道 + 截图按需兜底**（browser-use 视觉默认 `auto` 模式同思路：仅按需启用视觉，见其 Agent 参数 use_vision）。截图进入模型前过「敏感审批/模糊化」策略（维度 8 分级）。

### 理由

1. AX 与维度 5 的 `backendNodeId` 定位天然 1:1 对接（AX 节点携带 DOM backendNodeId），精确定位闭环最短。
2. 隐私面最小化符合本视角：文本快照仍可能包含用户输入/个人信息 → 补充规则：**`type=password` 字段 value 一律不回传**（skyvern 有 secret readback 测试先例 `test_input_secret_readback.py`）、快照大小上限截断。
3. agent-browser 已实现完整 AX 快照 + 树构建（`snapshot.rs:941 build_tree`），照抄成熟。

### 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| AX 覆盖率不足（canvas/自定义控件） | 截图兜底 + 语义定位（skyvern semantic locators 思路）作为增强 |
| 快照含敏感文本 | 字段级过滤（password/敏感域）+ 快照大小上限 + 截图审批 |

## 6. 维度 5：元素定位与操作执行、失败重试

### 候选对比

| 候选 | 精确性 | 抗页面漂移 | 实现复杂度 | 与"严禁补丁"原则契合 |
| --- | --- | --- | --- | --- |
| 索引定位（browser-use `click index`） | 中：快照一变即错 | 差 | 常规 | 中 |
| LLM 语义定位（skyvern semantic locators） | 中高 | 中 | 高（LLM 延迟/成本） | — |
| **backendNodeId 映射 + data-* 原生标记**（agent-browser：AX 节点 → backendNodeId 反查 DOM → `el.setAttribute('data-agent-browser-located','true')`（`actions.rs:8285`、`element.rs:627-642`）→ 再经 CSS 选择器/CDP Input 命中） | 高：O(1) 精确命中 | 高：执行前实时校验 | 1-2 倍 | **完全契合**：原生注入 data-* 属性实现 DOM↔快照无损映射（本仓 AGENTS.md「严禁补丁」同款要求） |

### 结论

**backendNodeId + data-* 标记 + CDP Input 中心坐标执行**（agent-browser 蓝本），重试闭环：
1. 执行前校验：目标节点仍存在、可见、可交互（实时 querySelector 确认标记）；
2. 失败 → 重新快照 → 重新解析 → 重试（上限 3 次，browser-use `max_failures=3` 同量级）；
3. 仍失败 → 返回**可操作失败报告**（agent-browser locator-miss 分类 guidance 先例 `element.rs:627`），不静默。

### 理由

- 安全/运维视角：定位即信任根——坐标测距/魔术数字补偿是事故温床（AGENTS.md 明确禁止）；data-* 标记是唯一"原生、精确、O(1)"的映射方案。
- 点击执行用 CDP `Input.dispatchMouseEvent`（浏览器级真实输入事件，页面无法检测为合成），同时天然兼容用户协同（维度 6 令牌机制）。

### 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| SPA 重渲染导致标记失效 | 执行前校验 + re-snapshot 重试 + 失败分类报告 |
| 标记属性被页面脚本清除 | 实时校验后立即执行，窗口期毫秒级；被清除即按失败路径重试 |

## 7. 维度 6：协同模型（冲突处理与安全边界）

### 候选对比

| 候选 | 冲突处理 | 用户接管 | 复杂度 | 说明 |
| --- | --- | --- | --- | --- |
| AI 独占 + 阻塞用户输入 | — | 无（需求即否） | — | 不可选 |
| **软互斥 + 失效令牌**：Rust 侧 generation counter；用户任何交互（键盘/鼠标/导航/焦点变化）→ 递增计数 = 吊销所有 pending AI 动作；AI 每动作先申请令牌再执行；执行中令牌被吊销 → 中止 | 好：用户输入天然优先 | 即时生效 | 1-2 倍 | **本方案** |
| 硬锁（AI 动作期间拦截/屏蔽用户输入） | 好 | 需要 OS 级输入 hook，侵入性强 | 3 倍+ | 放弃 |

### 结论

**软互斥 + 失效令牌 + 急停按钮**：
- 用户交互事件源：主 UI（我们的窗口）转发的输入事件 + 浏览器窗口的 focus/输入事件；
- AI 动作流水线：**令牌检查 → 执行 → 完成后核对令牌未变**（执行后校验，防"用户输入被 AI 最后动作覆盖"）——令牌已变则该动作结果作废，AI 需重新观察（重新快照）；
- 急停按钮/快捷键：立即吊销令牌 + 取消 pending 动作 + 断开 CDP（浏览器保留给用户）；
- 安全边界：AI 不向"用户当前聚焦输入中的字段"注入内容（执行前检查焦点元素；若焦点在用户接管后变化 → abort）；高风险动作走 PermissionMode 审批（维度 8）。

### 理由

1. 独立 Chromium 窗口的用户输入无法被我们拦截（OS 级才可，3 倍+），所以"检测用户活动并让步"是唯一现实路线；软互斥把竞态收敛为"用户最后输入胜出"，语义清晰、可审计。
2. 令牌机制同时服务急停（吊销=急停）与崩溃恢复（重启后令牌归零，一切 pending 作废），运维成本低。

### 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 毫秒级竞态（AI 注入与用户输入同时发生） | 执行前后双令牌校验 + 焦点检查；最坏结果 = 用户最后输入覆盖 AI，可接受且可审计 |
| 用户"接管"后 AI 继续导航 | 导航动作同样过令牌检查；接管后 AI 侧收到 NotifyEvent 必须重观察 |

## 8. 维度 7：数据导入（重点维度）

### 7.1 候选路线

| 候选 | 隐私面 | 锁冲突 | 复杂度 | 说明 |
| --- | --- | --- | --- | --- |
| 整目录复制（browser-use：copytree 全 profile → temp，仅忽略 transient 文件 `profile.py:30-36,89-91`；Local State 一并复制 `:882-885`；WinError 32 检测 `:94-113`） | **大：Cookies/Login Data/History/Web Data 全量进入 AI 可读面** | 处理完整（锁检测 + 提示"关闭 Chrome 或 --cdp-url" `:876-881`） | 常规 | 参考实现 |
| **最小文件集复制 + 显式排除**（本方案）：仅复制 `Cookies`、`Local Storage`、`Session Storage`、`Network\Cookies`；显式排除 `Login Data*`（DPAPI 可解的密码库）、`History`、`Web Data`（自动填充）、`Bookmarks`、`Thumbnails` | **小：AI 会话内无密码/历史/自动填充** | 同 browser-use 锁检测 + 逐文件容错 | 1-2 倍 | **本方案** |
| storage_state（playwright 导出 JSON：cookies+localStorage，browser-use `profile.py:511` new_context 专用；与 user_data_dir 冲突警告 `:769-782`） | 大：**明文 JSON 落盘 = 会话凭据文件** | — | 常规 | 仅作"跨会话持久化"可选通道 |

### 7.2 结论（隐私面为第一权重）

1. **会话级临时 profile 复制**：目标目录 = `%LOCALAPPDATA%\Crish\browser-sessions\<id>\profile`（用户私有 + ACL 收紧），**仅最小文件集**；密码/历史/自动填充**永不进入** AI 浏览器。
2. **复制前显式用户确认**：对话框列出将导入的内容类型（Cookie/本地存储），明示"密码与历史记录不会导入"。
3. **锁冲突**：browser-use 的 WinError 32 检测（`profile.py:94-113`）+ 逐文件容错；检测到 Chrome 占用 → 提示用户关闭 Chrome 或改用"连接已运行浏览器"模式（`profile.py:876-881` 错误文案先例）。参考 skyvern 硬化（0700 目录 + 锁文件 flock + 身份校验 `local_browser_profile.py:30-60`）在 Windows 上的对应：目录 ACL + 独占文件锁（`CreateFile` 独占句柄）。
4. **storage_state 默认不导出**：AI 会话生命周期内登录态随临时 profile 删除即销毁；如产品要求"跨会话保持登录"→ 导出文件必须 DPAPI/加密落盘（agent-browser `auth.rs:121` getrandom 密钥 + AES-GCM 先例；本仓 B3 基线 DPAPI 语义）+ 用户确认 + 审计。**默认关闭此能力。**
5. **剪贴板**：默认**不授予** `clipboardReadWrite`（browser-use 默认授予 `profile.py:355-359`——反向决策，理由：AI 读剪贴板 = 窃取用户复制的密码/验证码的最短路径）；需要时单次审批 + 审计。
6. **下载**：下载目录 = 会话隔离临时目录；AI 触发的下载默认不自动打开，打开/移动需用户确认（skyvern 下载访问控制测试先例 `test_file_download_access_control.py`）。

### 理由

- 安全/运维视角排序：**密码不导入（硬性） > 历史/自动填充不导入（隐私） > cookies 最小导入（功能必需，登录态是导入价值所在） > 确认与审计**。
- 复制到私有目录 + 会话删除，避免污染用户真实 profile，也避免对用户 Chrome 产生锁冲突与数据损坏风险（browser-use 已有破坏性风险提示：`warn_user_data_dir_non_default_version` `profile.py:784-804`）。

### 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| cookies 被复制后 AI 可冒用登录态 | 高风险操作审批（登录提交/付款/下单类动作 Ask）+ 域名门禁 + 会话级生命周期（用完即删） |
| 复制失败（文件被占） | 逐文件容错 + 明确错误提示 + 回退选项（连接模式） |
| storage_state 明文泄漏 | 默认不导出；导出走加密 + 确认 + 审计 |

## 9. 维度 8：工具集分级

### 9.1 browser_* 工具 dangerous 分级（复用本仓 agent-tools PermissionMode 三态 + audit sink）

| 工具 | 风险面 | 默认策略 | 理由/证据 |
| --- | --- | --- | --- |
| `browser_navigate` / `go_back` / `refresh` / `wait` | 低：可见、可撤销 | Allow（受域名门禁约束） | 导航前检查 + 重定向后检查 + 新标签检查（security_watchdog `security_watchdog.py:35-92`） |
| `browser_click` / `type` / `select_option` / `scroll` / `hover` | 中：页面内可见操作 | Allow | 经令牌检查（维度 6）+ 审计 |
| `browser_evaluate` | **高：任意 JS**（读 localStorage/cookies/fetch 任意地址） | **Ask（每次审批）** | chrome-devtools-mcp 将 evaluate 归 debugging 类且 readOnlyHint=false（`src/tools/script.ts:22-24`）；本仓 dev_mcp 高危命令二次 env 先例（`dev_mcp.rs:27-29,46-48`） |

| `browser_clipboard_read/write` | **高** | **Deny 默认，Ask 单次开启** | 反向决策于 browser-use 默认授予（`profile.py:355-359`） |
| `browser_cookies_get` | 高：会话面 | Ask | 冒用风险 |
| `browser_screenshot` | 中：隐私进模型上下文 | Ask（或敏感域自动拒绝） | 登录页/密码框出现时自动模糊/拒绝 |
| `browser_submit`（检测"登录/支付/下单"意图） | 高 | 登录/支付类 → Ask | skyvern login_block 先例 |
| `browser_tabs_*` | 中 | Allow（受门禁） | 新标签 URL 过门禁（`security_watchdog.py:73-92`） |

### 9.2 域名白名单（对齐 browser-use 三件套）

- `allowed_domains`（白名单，可选开启；`*.example.com` 通配；TLD 通配禁止——`profile.py:617-620` 与文档约束）；`prohibited_domains`（黑名单，可配，优先级低于白名单——`profile.py:621-624`）；
- **`block_ip_addresses` 默认开**：阻断 IP 直连（含 localhost/内网）防 SSRF（security_watchdog IP 变体全覆盖实现 `security_watchdog.py:138-174`；skyvern 云端会话拒绝 localhost 先例 `test_mcp_localhost_guard.py`；本仓 B5 出站限制精神）；
- 三个检查点：**导航前（阻断+报错）→ 导航完成（重定向逃逸 → 打回 about:blank）→ 新标签（关闭）**（`security_watchdog.py:35-92` 全套抄）；
- 约束注入任务提示（browser-use `_task_with_domain_constraints` `beta/service.py:1366-1376` 先例），防模型自说自话。

### 9.3 evaluate 限制

- 仅在 **isolated world** 执行（页面 JS 无法干扰我们的注入，也无法窃听执行上下文）；
- 结果大小上限 + 序列化截断 + 超时；
- 与 `CRISH_DEV_MCP_EXEC` 同哲学：默认收紧、显式开启（`dev_mcp.rs:27-29`）。

复杂度：常规~1-2 倍（策略层复用 agent-tools 既有审批/审计基础设施，不新建体系）。

## 10. 维度 9：安全（重点维度）

### 10.1 端口与暴露面

| 项 | 决策 | 证据/依据 |
| --- | --- | --- |
| 调试端口 | 仅 `127.0.0.1` 随机端口（`--remote-debugging-port=0`）+ DevToolsActivePort，**绝不用固定 9222/9242** | agent-browser `chrome.rs:408,687-762,943`；browser-use 固定 9242 反面教材 `profile.py:28` |
| 端口/WS path | 不进日志、不进事件；user-data-dir 内文件 ACL 收紧 | 本视角要求 + B4 脱敏精神 |
| 我方新增监听 | **零新增**：浏览器调试端口是受管子进程行为，不等同我方监听 | 31 基线 B5 `31-security-baseline.md:116-128` |
| 登记 | 调试端口面属"网络监听"触达面 → 按基线 §1 判定表登记 + PR 检查表勾选 | `31-security-baseline.md:17-33` |

### 10.2 审计（复用 agent-tools audit sink）

- 每个 CDP 命令/工具调用出审计事件：工具名、参数（脱敏）、结果摘要（截断）、令牌版本、耗时；
- 敏感事件独立类型：门禁命中（NavigationBlocked）、审批拒绝、急停触发、evaluate、剪贴板、下载、登录提交、cookies 读取；
- 事件写库前过 `conex-telemetry::redact` 脱敏钩子（B4 基线 `31-security-baseline.md:105-114`）；cookie 值/密码/token 永不落日志（agent-browser `commands.rs:190` 先例：错误不回显 secret）。

### 10.3 日志

- 调试日志统一走 tracing + 脱敏钩子；不打印 profile 路径中的敏感片段；
- 浏览器 stderr 定向到会话日志文件（chrome-devtools-mcp `browser.ts:247-252` 先例），供故障排查，日志文件 ACL 收紧。

### 10.4 急停

- 用户可见急停按钮 + 全局快捷键：吊销令牌（维度 6）→ 取消 pending CDP 命令 → 断开 WS → **浏览器保留**（用户接管）；
- 看门狗：AI 单动作超时（browser-use step_timeout 先例）自动取消 + 上报。

### 10.5 沙箱与隔离

- Chromium sandbox 保持开启（browser-use 默认 `chromium_sandbox=True` `profile.py:436-438`）；**绝不使用 `--no-sandbox`**（仅 docker 场景的 browser-use 才用，`profile.py:120-130`）；
- 独立 user-data-dir + 独立进程 = 浏览器完全攻陷也不出沙箱、不伤主 app（对齐基线防御目标 `31-security-baseline.md:58-60`）；
- 渲染边界：快照/截图内容进模型前是唯一"页面→外部"通道，受分级审批约束（维度 8）。

### 10.6 生命周期与故障恢复（运维）

- 启动：删 stale DevToolsActivePort → 启浏览器 → 等端口 → 失败重试/上报；
- 会话结束：杀进程树 → 删临时 profile → 清残留文件（agent-browser `chrome.rs:631-633` + skyvern 孤儿清理 `local_browser_profile.py` 思想）；
- 崩溃恢复：浏览器进程意外退出 → 事件上报 + 自动重启（保留令牌语义：AI 侧 pending 全部作废，需重观察）→ 用户无感；
- 空闲回收：无活动 N 分钟自动关浏览器（agent-browser daemon idle_timeout 先例）。

复杂度：1-2 倍（大部分是"复用既有基础设施 + 照抄参考实现"的组装成本）。

## 11. 维度 10：电脑操作（Computer Use）二期

### 11.1 候选对比

| 候选 | 隔离性 | 用户风险 | 复杂度 | 说明 |
| --- | --- | --- | --- | --- |
| OS 级输入注入（SendInput/mouse_event/keybd_event，Windows） | 无：直接作用真实桌面 | **高：误点其他应用、输入进错窗口、隐私窗口被截屏** | 1-2 倍 | Anthropic demo 是容器内 xdotool（`computer.py` 全套动作/坐标校验/缩放钳制 `:220-291`），**其安全边界是 Docker 容器而非注入本身** |
| 隔离桌面（CreateDesktop 独立 desktop + 流镜像） | 高 | 低 | **3 倍+：Windows 多桌面 UX、视频流、剪贴板桥接全链路** | 放弃（登记为远期增强） |
| 仅限本应用窗口内注入 | 中 | 低 | 常规 | 等于浏览器方案的能力子集，无独立价值 |

### 11.2 结论（一期不做，二期以如下门槛立项）

1. **会话级显式开启**：默认 Deny；开启时 UI 明示"AI 可操作您的整个电脑桌面"，含倒计时确认；
2. **全动作审批**（复用 PermissionMode）：每个注入动作（按键/坐标点击/拖拽）进审批队列（可配置"高频低风险动作批量放行"白名单：普通点击/打字；**禁用键集合**：Win 键、Ctrl+Alt+Del、Alt+F4、锁定/关机快捷键——比对 Anthropic demo 的 `duration>100` 拒绝等参数钳制思路 `computer.py:365-366`）；
3. **全局急停**：独立于浏览器急停的二级快捷键 + 注入线程挂起 + 进程级 kill 兜底；
4. **完整审计**：每个注入动作（键码/坐标/前台窗口标题/截图前后对比）+ 桌面截图（隐私窗口模糊策略）；
5. **与浏览器线硬隔离**：独立 crate（conex-computer）、独立权限开关、独立会话；**浏览器会话与电脑操作会话互斥进行**（防止浏览器线借电脑操作通道扩权）；
6. 屏幕坐标缩放钳制（Anthropic `scale_coordinates` 边界校验 `computer.py:268-291` 先例）防坐标越界误操作。

### 11.3 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 误操作真实应用 | 全动作审批 + 禁用键集合 + 前台窗口校验（仅操作"当前前台窗口"且记录之） |
| 截屏泄密（聊天窗口等） | 截图审批 + 敏感窗口模糊 + 审计 |
| AI 借电脑操作执行任意程序 | 动作白名单化（键鼠动作原语，不提供"运行程序"能力）+ 会话互斥 |

复杂度：1-2 倍（可行，但安全门槛高，排期二期）。

## 14. 验收门槛建议（后续任务书引用）

1. 门禁：`browser_navigate` 到被禁域名/IP → 拒绝 + NavigationBlocked 审计事件（单测）；
