## 0. 模块结构与数据流

```
crates/conex-browser/src/snapshot/
├── mod.rs            # 对外入口：capture_snapshot(tab_id)、validate_snapshot(tab_id, version)（R-1）、SnapshotDocument 类型
├── collect.rs        # CDP 数据采集（DOMSnapshot/DOM.getDocument/AX/Runtime 辅助，见 §1）
├── interactive.rs    # 可交互判定启发式（见 §2）
├── redact.rs         # 脱敏（见 §5）
├── serialize.rs      # 简化树 + 文本序列化 + 索引分配 + 预算截断（见 §3）
└── budget.rs         # 预算常量与截断信息类型（见 §3.4；T-6 参数集中可配）
```

单次快照流水线：

```
collect.rs（CDP 并行采集）→ 中间表示 EnhancedNode（DOM 域数据 + AX 合并 + 样式/布局）
  → interactive.rs（分层启发式判定）→ redact.rs（敏感字段清洗）
  → serialize.rs（简化树 → 紧凑文本 + selector_map）→ SnapshotDocument（携带 snapshotVersion）
```

采集为一次性全量 + 预算截断；跨轮增量仅体现为索引缓存与 `is_new` 标记（§3.5），不采用增量采集（§6）。

## 1. 数据采集

### 1.1 采集方案选定：DOMSnapshot 主采集 + DOM.getDocument 结构 + AX 辅助 + Runtime.evaluate 只读补充

| 候选 | 结论 | 理由 |
|---|---|---|
| `DOMSnapshot.captureSnapshot`（computedStyles 白名单 + includePaintOrder + includeDOMRects） | **主采集** | 一次调用返回全部文档（主文档 + 各同源 iframe 文档）的节点树、布局 bounds、滚动矩形、绘制顺序、计算样式与 `isClickable` 位集；字符串池压缩体积；可挂 layout 数据做可见性/可滚动/绘制序过滤，是唯一能一站式拿到「结构 + 布局 + 样式」的域 |
| `DOM.getDocument(depth=-1, pierce=true)` | **结构通道** | 提供父子关系、backendNodeId、attributes、shadowRoots、同源 contentDocument（pierce 直穿）、frameId；与 DOMSnapshot 按 backendNodeId 关联。不用 getOuterHTML（无布局数据且需整树序列化往返） |
| `Accessibility.getFullAXTree`（逐帧并发） | **辅助通道** | 补齐无障碍 name/role/properties（focusable/checked/valuetext 等 DOM 属性无法表达的状态），供名称提取、可交互判定与表单当前值读取；不用于定位链（定位以 backendNodeId 为准） |
| `Runtime.evaluate` 注入采集 | **否决为主通道，仅作只读补充** | D-3 已否决注入脚本桥为主通道：与 CDP 域能力重复、跨域 iframe 读不到、合成数据与真实渲染状态存在分歧；且 evaluate 本身受维度 17 白名单/审批约束。**但保留两个只读补充点**（均为引擎内置白名单表达式，不经工具层 evaluate 审批面，只读不突变 DOM）：① 各 iframe 实际滚动位置（§1.4 坐标修正）；② JS 事件监听器探测（§2.2，可选增强通道，默认关闭，T-4）。 |

### 1.2 CDP 调用参数与并发

四路请求**并行**发起（`tokio::join!` 或 `futures::join!` 等量并发原语，统一发送层管理），首轮 10s 超时，未完成的取消后重发，再等 2s；AX 树失败可降级为空 AX（主结构不丢），其余三路（snapshot/dom_tree/device_pixel_ratio）失败则整体抛 `SnapshotCollectError` 交由上层重试：

- `DOMSnapshot.captureSnapshot`：`computedStyles` = §1.3 白名单；`includePaintOrder=true`、`includeDOMRects=true`、`includeBlendedBackgroundColors=false`、`includeTextColorOpacities=false`。
- `DOM.getDocument`：`depth=-1, pierce=true`。
- `Accessibility.getFullAXTree`：按 frameId 逐帧调用（见 §1.4）。
- `Page.getLayoutMetrics`：取 CSS 视口与 devicePixelRatio（坐标统一换算 CSS 像素：设备像素 ÷ DPR）。

处理要点（性能关键，均已在参考实现验证）：DOMSnapshot 的 `backendNodeId` 数组与 `layout.nodeIndex` 预构建 HashMap 索引（避免 O(n²)）；`isClickable` 稀有位集转 `HashSet` 提供 O(1) 查询（20k 元素时 list→set 提速约 3000 倍）；同一 backendNodeId 重复出现取首条。文档数超过 `max_iframes` 时截断文档列表。

### 1.3 computed styles 采样白名单

仅采样以下 10 项（样式索引进字符串池，白名单外每加一项都线性增大快照体积并在重型站点触发崩溃，参考实现已踩坑）：

`display`、`visibility`、`opacity`、`overflow`、`overflow-x`、`overflow-y`、`cursor`、`pointer-events`、`position`、`background-color`

用途：可见性（display/visibility/opacity）、可滚动（overflow*）、指针可点（pointer-events/cursor）、绘制序过滤（background-color/opacity，§3.1 折叠）。

### 1.4 AX 树获取与 DOM 合并策略

- 采集：`Page.getFrameTree` 递归收集全部 frameId → 每帧并行 `Accessibility.getFullAXTree(frameId=...)`；主文档帧失败向上抛（走重试/空 DOM 路径），子帧失败仅记录并跳过（广告 iframe 频繁挂断，不得拖垮整体）。
- 合并：以 `backendDOMNodeId` 为键构建 `HashMap<backendNodeId, AXNode>`，与 DOM.getDocument 节点按 backendNodeId 匹配，形成增强节点（DOM 属性 + AX name/role/properties + 布局数据三合一）。AX 检出但 DOM 无对应 backendNodeId 的节点（closed shadow 内部，DOM 通道不 pierce closed shadow）→ 降级标记「不可操作」，不参与可交互判定与索引分配（T-5，见 §3.6）。
- 使用：name（可访问名称优先链：AX name → aria-label → title → placeholder → 文本内容）；role（AX role 与 `role` 属性互补）；properties（focusable/editable/settable/checked/expanded/pressed/selected/required/autocomplete/keyshortcuts/disabled/hidden/value/valuetext）——其中 value/valuetext 仅用于表单当前值展示且受脱敏约束（§5）。
- 去重：AX 节点与 DOM 节点一一对应（backendDOMNodeId），不重复出树；AX ignored 节点不参与可交互判定（排除规则，§2.3）。

### 1.5 iframe 处理策略

| 场景 | 策略 |
|---|---|
| 同源 iframe | `DOM.getDocument(pierce=true)` 直接给出 `contentDocument`，递归进子文档；DOMSnapshot 按文档 frameId 归属各帧布局。后代可见性判定沿 frame 链做坐标平移与视口相交（含滚动修正），iframe 的 bounds 累加进子文档坐标偏移 |
| 跨域 iframe（无 contentDocument） | **二期**（U-4：一期不启用跨域递归）：懒处理——仅当 iframe 自身可见且尺寸 ≥ 10px×10px 时，经 `Page.getFrameTree` 的 `frameTargetId`（frameId 缺失或不在树中时用 src URL 匹配兜底）为目标建 CDP session，递归采集子文档；递归深度 ≤ `max_iframe_depth`，累计处理帧数 ≤ `max_iframes`，已访问 targetId 去重防环。**一期**：跨域帧不建会话、不递归，序列化中以 `|IFRAME|` 占位呈现（§3.2 示例），不分配交互索引（与维度 14 一期 Unsupported 对齐，U-4） |
| iframe 预算 | `max_iframes = 64`（一期为 DOMSnapshot 文档数上限；跨域递归帧数二期并入共用此上限）；`max_iframe_depth = 4`（嵌套深度，防恶意深嵌递归爆炸） |
| 小 iframe / 装饰 iframe | 尺寸 < 10px 的跨域帧不进入；不可见的同源帧子树照常遍历但按可见性过滤；iframe 元素本身在序列化中以 `|IFRAME|` 标记呈现（见 §3.2 示例） |
| 视口阈值 | 可见性 = CSS 可见（display/visibility/opacity）+ 与布局视口相交（上下各放宽 1000px 缓冲，`viewport_threshold`），超出视口但可滚动到达的元素仍保留在树中并按滚动提示呈现 |

iframe 滚动位置：采集前用内置白名单表达式读取各同源 iframe 的 `scrollTop/scrollLeft`，修正子文档坐标（二期跨域帧无法读取时以 DOMSnapshot 的 `scrollRects` 为准）。

## 2. 可交互判定启发式

### 2.1 判定规则总表（按优先级排序，自上而下短路）

判定输入：增强节点（tag、attributes、AX role/properties、computed styles、bounds、是否含 JS 监听器、是否可滚动、后代结构）。规则分四层：**排除前置（P）→ 强正信号（S）→ 结构信号（M）→ 弱信号（W）**。P 层命中即否决；S 层任一命中即通过（权重 1.0）；M/W 层按「命中数 ≥ 阈值」通过。

| # | 优先级 | 规则 | 检测方式 | 权重/条件 |
|---|---|---|---|---|
| P1 | 排除前置 | 非元素节点（文本节点不判可交互） | 节点类型 | 短路否决 |
| P2 | 排除前置 | `html`/`body` 不作为交互目标 | tag 名 | 短路否决 |
| P3 | 排除前置 | 隐藏：display:none、visibility:hidden、opacity≤0、无 bounds（未布局）、被祖先隐藏（沿链 CSS 可见性） | computed styles（§1.3 白名单）+ bounds | 短路否决（例外：`input[type=file]` 常 opacity:0 包裹定制样式，强制可见；开放 shadow DOM 内表单控件无快照数据但属功能元素，豁免；closed shadow 内元素走 T-5 降级，见 §3.6） |
| P4 | 排除前置 | 禁用：`disabled` 属性、`aria-disabled=true`、AX `disabled` property | DOM 属性 + AX | 短路否决 |
| P5 | 排除前置 | AX ignored（装饰性节点） | AX `ignored` | 短路否决 |
| P6 | 排除前置 | SVG 子元素（path/rect/g/circle/use/defs 等）默认装饰 | tag 白名单 | 短路否决（SVG 根 svg 保留；含显式交互信号的 SVG 见 S8） |
| S1 | 强正信号 | 含 JS click 类监听器（click/mousedown/mouseup/pointerdown/pointerup） | getEventListeners 探测（§2.2，不 DOM 突变；可选增强通道，默认关闭，T-4） | 命中即通过；覆盖 React onClick/Vue @click/Angular (click) 等框架绑定；通道关闭时该规则不生效，由其余启发式兜底 |
| S2 | 强正信号 | 原生交互标签：`button`、`input`、`select`、`textarea`、`a`、`details`、`summary`、`option`、`optgroup` | tag 名（大小写不敏感） | 命中即通过 |
| S3 | 强正信号 | ARIA role 属性 ∈ 交互角色集：button/link/menuitem/option/radio/checkbox/tab/textbox/combobox/slider/spinbutton/search/searchbox/row/cell/gridcell/listbox | DOM `role` 属性 | 命中即通过 |
| S4 | 强正信号 | AX role ∈ 交互角色集（同上 + menubar/tree/grid） | AX role | 命中即通过 |
| S5 | 强正信号 | AX 交互属性：focusable、editable、settable、checked、expanded、pressed、selected、required、autocomplete、keyshortcuts 任一为真 | AX properties | 命中即通过（前四项是交互控件直接标志；后六项仅在交互控件上存在） |
| S6 | 强正信号 | 内联事件属性：onclick/onmousedown/onmouseup/onkeydown/onkeyup/tabindex 存在 | DOM 属性 | 命中即通过 |
| S7 | 强正信号 | 大 iframe（宽高均 > 100px） | tag + bounds | 命中即通过（可能含可滚动内容，需可点滚动） |
| S8 | 强正信号 | 显式交互 SVG：SVG 子树中带 onclick/role=交互角色/交互 data-* 的节点 | 属性 | 命中即通过（默认被 P6 排除，此规则是唯一放行口） |
| M1 | 结构信号 | `label`/`span` 包裹表单控件（input/select/textarea，≤2 层深度） | 子树探测 | 命中即通过（label 带 `for` 属性时跳过——避免与真实控件双激活，见 M0） |
| M2 | 结构信号 | 搜索类模式：class/id/data-* 属性含 search/magnify/glass/lookup/find/query/searchbox 等标记 | 属性子串匹配（小写化） | 命中即通过 |
| M3 | 结构信号 | 图标尺寸元素（10px ≤ 宽高 ≤ 50px）且含交互类属性（class/role/onclick/data-action/aria-label） | bounds + 属性 | 命中即通过（图标按钮常见形态） |
| W1 | 弱信号 | cursor:pointer（chrome 漏判兜底） | computed style `cursor` | 命中且无任何排除命中时通过 |
| W2 | 弱信号 | 可滚动容器且无任何可交互后代（滚动目标本身可被索引用于 scroll 动作） | overflow* 样式 + 后代探测 | 通过；dropdown 容器（role ∈ listbox/menu/combobox/menubar/tree/grid 或 class 含 dropdown/select-menu 或 tag=select）**无条件**可交互（select_dropdown 目标） |

补充规则（与表并列）：
- **M0 防双激活**：`label[for]` 命中 M1 时不判可交互（点击会代理到目标控件）；可交互后代的传播型父容器（`a`/`button`/`div[role=button]` 等）不额外分配索引（见 §3.1 容器折叠）。
- **判定缓存**：同节点判定结果按 `(session_id, backendNodeId)` 缓存（CDP 节点 id 在跨域目标间会复用，键必须含 session），避免树构建与序列化阶段重复计算。
- **优先级语义**：P 层否决 > S 层通过 > M 层 > W 层；S 层任一命中即通过（不再看弱信号）；M/W 层仅当 S 层全部未命中时参与。

### 2.2 JS 事件监听器探测（不 DOM 突变）

目的：捕捉框架绑定（React/Vue/Angular）的事件处理，这是纯属性启发式覆盖不到的现代 SPA 形态。全程只读，不改 DOM：

> **通道状态（T-4）**：本通道为**可选增强通道，默认关闭**——S0 spike 实证其对检出率的实际增益后决定默认开关；关闭时 S1 规则不生效，由 AX 与其余启发式兜底，不影响快照主链路。

1. `Runtime.evaluate(includeCommandLineAPI=true, returnByValue=false)` 执行白名单函数：遍历 `document.querySelectorAll('*')`，对每个元素 `getEventListeners(el)`（DevTools 命令线 API，无需注入补丁），收集含 click/mousedown/mouseup/pointerdown/pointerup 监听器的元素**对象引用**。
2. 保护上限（两档，防重型页面拖垮会话）：
   - 全页元素数 > 10000 → 整个探测跳过（改由 AX 与其余启发式兜底）；
   - 命中元素数 > 100 → 返回哨兵标记跳过 resolve 阶段（元素仍会经 AX 等通道检出）。
3. `Runtime.getProperties(objectId, ownProperties=true)` 取出数组元素 objectId 列表，**分批**（每批 20，并发受控，防 CDP 书签簿拥塞饿死截图等并发请求）`DOM.describeNode(objectId)` 解析为 backendNodeId 集合。
4. `Runtime.releaseObject` 释放引用（防内存泄漏）。
5. 探测超时/异常 → 记录日志并跳过（判定降级，不阻塞快照）。

### 2.3 排除规则汇总（隐藏/禁用/装饰/零尺寸）

| 类别 | 判定 | 例外 |
|---|---|---|
| 隐藏 | display:none / visibility:hidden / opacity≤0；或无布局 bounds；或任一祖先满足上述条件 | `input[type=file]`；开放 shadow DOM 表单控件（closed shadow 内元素走 T-5 不可操作降级）；带 aria-\* 校验类属性的隐藏节点（如错误提示关联区） |
| 禁用 | disabled / aria-disabled / AX disabled | 无 |
| 装饰 | AX ignored；SVG 子元素；script/style/head/meta/link/title；纯图标非交互（见 M3 判定） | SVG 显式交互（S8） |
| 零尺寸 | bounds 宽或高为 0 且无滚动内容 | 不可视覆盖层视为可交互（点击命中）的例外**不采纳**：定位以 backendNodeId 为准（无需坐标），零尺寸元素无交互价值，一律排除；避免无效点击噪音 |
| 视口外 | 超出布局视口 ±1000px 缓冲 | 可滚动容器内元素仍保留（滚动可达），序列化时给滚动提示 |

简化树构建步骤（参照参考实现，步骤顺序即预算生效点）：

1. **建树**：深度优先遍历增强树，跳过 §2.3 排除节点与 `style/script/head/meta/link/title`；文本节点仅保留可见且有效长度（>1 字符）的；开放 shadow root 以 `|SHADOW(open)|` 标记进入（SPA 大量交互控件在 shadow 内，必须进树）；closed shadow 根以 `|SHADOW(closed)|` 标记进入，其内部元素经 AX 检出但 DOM 无 backendNodeId（DOM 通道不 pierce closed shadow）→ 降级标记「不可操作」（T-5，不分配索引，计入盲区统计 §3.6）。**预算 1（depth）与预算 2（tree_nodes）在此步生效**（§3.4）。
2. **容器折叠**：对 `a`/`button`/`div[role=button|combobox]`/`span[role=button|combobox]` 等传播型容器，其完全包含在容器 bounds 内的交互后代（containment ≥ 99%）折叠进容器行（属性/文本合并），避免“按钮里套按钮”式噪音；含显式 onclick、有效 aria-label、独立交互 role 的后代不折叠（防 stopPropagation 场景）。
3. **绘制序过滤**（可开关）：按 `paintOrders` 从后向前维护不相交矩形并集（每帧上下文独立，RectUnion 上限 5000 防止重叠层碎片爆炸，超限保守放行），被完全覆盖且背景不透明（background-color 非透明且 opacity ≥ 0.8）的节点标记为被遮盖；文本节点与表单控件不因遮盖而删除（弹窗/下拉场景遮罩下的原文仍需可见——仅保留文本，不给交互索引）。
4. **索引分配**：遍历树，可交互且可见的节点分配模型索引（§3.3），非交互/被遮盖节点不分配；盲区占位元素与不可操作元素（closed shadow 降级，T-5）一律不分配索引。
5. **序列化**：按 §3.2 格式输出文本，**预算 3（text）与预算 4（selectors）在此步生效**（§3.4）。

### 3.2 文本格式规范（示例输出）

格式约定：

- 缩进：每层 2 空格；可交互元素行带 `[N]`（N 为模型索引）；`*` 前缀标记自上一快照新增；可滚动元素追加 `|scroll|`；iframe/shadow 带 `|IFRAME|`/`|SHADOW(open|closed)|` 标记；已知盲区元素带 `|CANVAS|`/`|VIDEO|`/`|IMG|` 占位（§3.6）；closed shadow 内不可操作元素带 `|UNOPERABLE|` 前缀（T-5，无 `[N]` 索引）；文本节点裸文本行；属性以 `key=value` 空格连接（值含空格的加引号）。
- 属性白名单（仅序列化以下属性，防体积爆炸）：`id`、`name`、`type`、`placeholder`、`value`（受脱敏约束）、`aria-label`、`title`、`role`、`href`、`required`、`disabled`、`checked`、`selected`、`format`（日期输入 ISO 格式提示）、`options`（select 前 4 项 + 省略计数，见下）。
- select 展开：`options=北京|上海|深圳|...(23 more)`；日期/时间输入自动附 `format=YYYY-MM-DD` 等（HTML5 输入必须 ISO 格式，模型最易错点，显式提示）。
- 视口外/截断：`... (N more elements - scroll to reveal)`。

### 3.3 索引分配与 backendNodeId 绑定

- **默认索引 = backendNodeId**（CDP 会话内全局唯一，直接可执行，定位链最短，无需坐标）。
- 合成索引：若同一 backendNodeId 需分配多处（理论罕见，跨文档同 id 复用防御），后到者分配合成索引：从「本快照简化树全部 backendNodeId 的 max+1」起递增，避开树中已出现的所有 backendNodeId（保留集合预构建，防碰撞）。
- 绑定：`selector_map: HashMap<u32 /*模型索引*/, NodeRef>`，`NodeRef = { backend_node_id: i64, session_id: String, frame_target_id: Option<String> }` —— 二期跨域 iframe 内元素需带 frame targetId，动作执行（维度 14）凭此直达目标会话；一期仅同源 pierce（同 session 内 backendNodeId 直达），`frame_target_id` 字段保留为空供二期启用（U-4）。
- 稳定性：同一 backendNodeId 在相邻快照间索引恒定（索引 = id 本身），模型无需重新学习。

### 3.4 预算参数（本维度裁决，开放问题 1）

| 参数 | 裁决值 | 含义与生效点 |
|---|---|---|
| `max_depth`（最大层级） | **10** | 简化树深度上限；超深子树整体折叠为 `... (N more elements)` 提示行（保留子树内可交互元素计数提示，不展开）。基准：主流 SPA（React/Vue）典型交互控件深度 ≤ 6；10 覆盖嵌套容器（modal+form+grid）仍有余量，超出部分为长列表/深层菜单，无索引价值 |
| `max_tree_nodes`（简化树元素数） | **1000** | 建树阶段（预算 2）保留节点上限；达到后停止收纳子节点，已遍历但未入树的节点计入 `dropped_nodes`，树尾输出 `... (N more elements)`。基准：常规页简化树 200-600 节点，1000 覆盖复杂页，超限即为海量列表页（进入截断路径） |
| `max_selector_indices`（可交互索引上限） | **500** | 索引分配上限（预算 4）；超出部分元素仍入树（无 `[N]` 前缀，仅文本可读，模型可滚动查看）。基准：模型上下文单次可消化的可点目标约 100-300，500 为上限余量；海量分页按钮/表格行场景被此预算控制 |
| `max_text_len`（单行文本/属性值） | **100 字符** | 序列化阶段（预算 3）逐行截断；属性值与文本节点超限截断并追加 `…`；select 展开仅前 4 项 + 省略计数。基准：行过长淹没上下文且多为长描述文本，100 字符保可读性 |
| 文本节点入树阈值 | > 1 字符且非空白 | 与参考实现一致，过滤装饰性零文本 |
| 防呆上限（内部） | 遍历元素 10000 / 文档 64 / iframe 深度 4 | §1.5 与 §2.2 的采集侧护栏，与输出预算独立 |
| `inactive_budget_factor`（非活跃标签预算系数） | **0.25** | 非活跃标签（维度 15 定义的非当前交互标签）按活跃标签预算的 0.25 倍执行**惰性快照**：`max_tree_nodes` 1000→250、`max_selector_indices` 500→125（其余参数不变）；标签被激活或事件推进版本后自动升级为全额快照（T-6，与维度 15 MAX_TABS 预算分摊一致） |

截断策略总则：**深度与元素数截断都保留「被截内容的可交互元素计数」提示行**（`... (N more interactive elements)`），模型知道下面还有东西但不会被体积淹没；文本截断一律带 `…` 后缀；被绘制序遮盖的节点保留文本行但不给索引。

**参数集中可配（T-6）**：以上预算参数（含 `inactive_budget_factor`）集中定义于 budget.rs 的单一常量/配置结构，支持运行时覆盖；活跃/非活跃标签判定口径以维度 15 为准，13 不重复定义。

### 3.5 快照缓存（(tab_id, version) 键控）与增量匹配（M-6）

- 缓存结构：快照缓存以 **(tab_id, version) 为键**（`HashMap<(TabId, u64), Arc<SnapshotDocument>>` + LRU 链表），与维度 15 §7.3 的 `SNAPSHOT_CACHE_TOTAL = 8MB` 总量预算一致；**LRU 逐出按 (tab_id, version) 键**（最近使用序），总量超限逐出最久未用条目（M-6）。
- 增量匹配：`previous_state`（上一轮 selector_map 的 backendNodeId 集合 + snapshotVersion）从该缓存按当前 (tab_id, version) 的前驱取出，随会话存储、跨动作链复用。
- **版本防回退断言**：缓存写入前断言 `新版本 ≥ 缓存内同 tab 最大版本`（版本单调不减，R-1）；VersionReset 跳变（+1000，11 §5.4 #9 / U-2）为唯一允许的大跳变——跳变时同 tab 全部旧版本条目失效并清出；**任何向旧版本的回退写入一律拒绝并记录审计**（防版本回退伪装成正常快照，M-6）。
- 增量标记：本轮遍历到某节点且 `backendNodeId ∉ 上一轮集合` → `is_new = true`，序列化加 `*` 前缀；复合组件（select/日期/文件等虚拟子组件）恒标记为 new（其结构是合成产物，不参与 id 匹配）。
- 用途：模型聚焦页面变化（弹窗/新按钮）而无需重读全树；不减少采集量（采集仍全量，预算在输出侧）。
- 版本失效：缓存键含版本，`previous_state` 与当前 snapshotVersion 不连续（跨导航/VersionReset 后键自然不命中）时丢弃该轮增量视角，本轮无 `*` 标记（全量视角）。

### 3.6 已知盲区登记（T-16，联动 T-5）

> 盲区定义：快照可感知元素存在、但文本面无法描述其内容语义或无法操作的元素。盲区元素一律以**占位符呈现**（不展开内容）、**不分配交互索引**，并在快照头部 `SnapshotMeta.blind_zone` 统计（§3.1），提示模型「此处有内容但不可见/不可操作」。

| 盲区类别 | 检出通道 | 呈现 | 统计字段 | 备注/演进 |
|---|---|---|---|---|
| canvas / WebGL | DOM 标签 | `\|CANVAS\|` 占位行 | `canvas` | 内容为像素，文本面不可描述；演进项：截图/OCR 增强（S0 实证后评估） |
| 视频画面 | DOM 标签 | `\|VIDEO\|` 占位行 | `video` | 画面内容不可读；无字幕时音频同理不进文本面 |
| 纯图片内容 | DOM 标签（无有效文本/AX name） | `\|IMG\|` 占位行 | `image` | 图片内文字不可读；aria-label/title 仍按属性正常呈现（D4 不误伤） |
| closed shadow DOM 内元素（T-5） | AX 检出（backendDOMNodeId 存在），DOM 无 backendNodeId | `\|UNOPERABLE\|` 前缀 + 名称/角色文本 | `unoperable` | closed shadow 不 pierce；一期降级不可操作、不分配索引；演进项：frame targetId 级聚焦/点击（S0 实证） |
| 跨域 iframe 内容（一期） | Page.getFrameTree（frameId） | `\|IFRAME\|` 占位（§3.2） | 不另计 | U-4：二期建会话递归后自然消除盲区属性 |

盲区元素不参与检出率正负例口径（§7.1）——其为已知限制而非漏检；新增盲区类别需登记本表并同步 `BlindZoneStats`。

## 4. snapshotVersion 集成（R-1 per-tab + M-5 采集事务化 + U-2 VersionReset）

- **版本来源**：维度 11 事件总线内置版本跟踪器，版本**按标签页独立**——`snapshot_version(tab_id) -> u64`（每标签 u64 单调递增），会话级辅助 `global_epoch` 用于跨标签事件（重连/崩溃重启）（R-1，11 §5.4）。快照模块只读它，不自行生成。
- **采集事务化（M-5）**：单次采集为「版本读-采集-校验-提交」四步事务，杜绝「采集了旧 DOM 却标着新版本」的竞态：
  1. **版本读**：起始读 `snapshot_version(tab_id)` 与 `global_epoch`，写入 `SnapshotMeta.snapshot_version` / `SnapshotMeta.epoch`；
  2. **采集**：CDP 四路并行采集 + 增强树构建/序列化（§1-§3）；
  3. **校验**：结束再读版本与 epoch——采集窗口内版本已推进（事件总线版本 > 起始版本）或 epoch 已变化（VersionReset）→ **中止本次采集，不提交**，返回 `Stale`（调用方决定是否重拍）；
  4. **提交**：以 (tab_id, version) 为键写入快照缓存（§3.5，含防回退断言）并返回 `SnapshotDocument`。
  - **中断/崩溃恢复（状态描述）**：采集状态机 `Idle → Collecting{ tab_id, start_version, start_epoch, started_at } → Committed`；提交是唯一写入点，`Collecting` 期间任何中断（abort/断线/进程崩溃）都不产生半成品缓存条目，状态机回到 `Idle`，下次采集从头执行——快照缓存中不存在「未提交」状态，无需清理半成品，崩溃后自然重新采集。
- **校验接口（R-1，与维度 11 §8 门面签名一致，13 不重复定义）**：

```rust
// 契约（11 §8）：维度 13/14/15 共用；Stale 类型来自维度 11 version.rs
pub fn validate_snapshot(&self, tab_id: &TabId, version: u64) -> Result<(), Stale>;
```

- **校验侧 VersionReset 处理（U-2）**：`validate_snapshot` 对以下情形一律返回 `Stale`（不信任旧快照）：
  - 版本不匹配：`snapshot_version(tab_id) != version`（常规推进后的过期，`SnapshotError::VersionMismatch` 语义并入 Stale）；
  - **epoch 变化**：当前 `global_epoch` ≠ 快照携带的采集时 epoch → 期间发生过 VersionReset（重连/崩溃重启/跟踪器 Lagged 重对齐，11 §5.2/U-2）；
  - **版本 +1000 跳变**：当前版本 ≥ 快照版本 + 1000 → 重连/崩溃重启跳变（11 §5.4 #9），一律 Stale。
- **执行时序（维度 14 侧约定）**：动作入队时携带快照 `(tab_id, snapshot_version)` → 执行前 `validate_snapshot` → 不匹配（含 VersionReset）则重快照重试（最多 3 次，含导航竞态延迟重试）→ 匹配后凭 `selector_map[index]` 的 backendNodeId 定位执行。版本号与 epoch 同时进入审计日志（维度 17），支持「动作基于哪个页面状态执行」的事后还原。

| D2 | `autocomplete` 敏感项过滤 value：`current-password`、`new-password`、`one-time-code`、`cc-number`、`cc-cvc`、`cc-exp`、`cc-exp-month`、`cc-exp-year`、`cc-type`、`card-number`、`username`（登录态场景） | 与 D1 同路径（输入标签 + autocomplete 值判定），过滤后占位 `value=[REDACTED]` |
| D3 | AX 侧同步：password 类字段的 `value`/`valuetext` property 在 `_build_enhanced_node` 阶段即清除，不流入后续任何阶段 | 采集层清洗（redact.rs 在合并 AX 后、进简化树前执行），防御纵深 |
| D4 | placeholder/aria-label/title 不视为机密，正常输出（占位提示语无泄密面） | 不误伤可读性 |
| D5 | 不做高熵值启发式猜测（value 长度/熵阈值的启发式误伤率不可接受） | 明确不做；字段级规则已覆盖凭据主入口 |
| D6 | 审计/调试日志中的快照片段同样经 redact.rs | 与维度 17 的日志脱敏联动，同一过滤函数复用 |

脱敏执行点（redact.rs 单一出口，序列化与日志共用）：采集合并后（D3）→ 简化树属性裁剪时（D1/D2）→ 序列化输出（D1 占位）。

## 6. 性能

### 6.1 耗时预算

| 阶段 | 目标（常规页 p95） | 硬超时上限 | 超限行为 |
|---|---|---|---|
| CDP 四路并行采集（含重试窗口） | ≤ 1.5s | **12s**（10s 首轮 + 2s 重试窗口） | 超时任务取消重发；AX 可降级为空；主三路失败或整阶段超 12s → 中止本次采集并返回错误（T-1） |
| 增强树构建 + 可交互判定 | ≤ 300ms | 1s | 判定缓存 + HashMap 预索引保证线性复杂度；超限记录计时（不中断） |
| 简化树 + 序列化 | ≤ 300ms | 1s | 预算截断保证上界；超限以截断信息落日志 |
| **单次快照总耗时** | **p95 ≤ 2s（目标）** | **12s（全局硬超时）** | 5s 硬预算内为正常操作区间；超 5s 返回截断快照 + 警告、不阻塞动作链；超 12s 中止本次采集并返回错误（调用方重试，不产出半成品）；版本竞态（§4）在采集窗口内被检出，返回 Stale 重拍 |

**耗时双层语义（T-1）**：**12s = 硬超时上限**——单次快照（含各阶段）超过即中止并返回错误，不做部分结果；**p95 ≤ 2s（目标）/ ≤ 5s（硬预算）= 正常耗时目标**——常规页满足目标，硬预算内超时返回截断快照 + 警告、不阻塞动作链。原「采集上限 12s vs 单次总耗时 ≤5s」的矛盾表述撤销。

### 6.2 大页面防护（预算叠加）

- 采集侧：样式白名单（§1.3）、文档数 ≤ 64、遍历护栏 10000 元素（§2.2）、RectUnion 5000 上限（§3.1）——**CDP 原始采集载荷上限 150KB**（采集层：DOMSnapshot 返回即按文档数/深度截断，保证载荷不超限；该原始载荷不直接进模型）。
- 输出侧：§3.4 四档预算；**序列化输出预算 32KB**（模型输入面）——无论页面多大，序列化文本一律截断至 ≤ 32KB（§7.2 V3 门禁）。
- **体积双层上界（T-2）**：**32KB = 序列化输出预算（模型输入面）**；**150KB = CDP 原始采集载荷上限（采集层）**。两层语义分离、互不替代；原「序列化文本上界 ≈150KB」表述撤销。
- 定时器贯穿：每阶段计时上报 `SnapshotMeta.captured_at_ms` 明细，供自测与线上观测。

### 6.3 增量/懒采集策略

- **不做增量采集**：每轮快照全量采集（CDP 协议无 DOM 级 diff 能力，伪造 diff 是复杂度陷阱）；跨轮增量只体现为索引缓存 + `is_new` 标记（§3.5），成本为零。
- **懒采集**：跨域 iframe 子树（二期启用，遇到才建会话，§1.5；一期无此路径）；AX 超时降级为空 AX（不阻塞主通道）；JS 监听器探测在超预算时跳过（§2.2 两档保护）。
- **滚动懒呈现**：视口外内容不逐节点展开，以 `... (N more elements - scroll to reveal)` 提示；模型明确滚动动作后下一快照自然带出（滚动本身推进 snapshotVersion）。
- **非活跃标签惰性快照（T-6）**：非活跃标签按 `inactive_budget_factor=0.25` 执行低配快照（§3.4，节点/索引预算按系数缩放），标签被激活或事件推进版本后自动升级为全额快照；与维度 15 MAX_TABS 预算分摊一致。

### 7.1 可交互元素检出率基准（样例集 ≥ 95%）

| JS 监听器 | React onClick 按钮、Vue @click、addEventListener 原生按钮 | 检出 |

| iframe | 同源 iframe 内表单、同源 pierce 递归子树 | 检出（一期）；跨域大 iframe（>10px）内按钮为二期验收项（U-4） |

## 8. 风险与预案

| 风险 | 等级 | 预案 |
|---|---|---|
| DOMSnapshot 在重型站点触发 Chrome 崩溃（已知历史） | 高 | 样式白名单严格收敛（§1.3）；文档数 ≤ 64；升级捕获崩溃事件走 S2 崩溃重启路径 |
| AX 树慢/挂起拖慢快照 | 中 | 并行 + 10s 超时 + 降级为空 AX（主通道不受损）；子帧失败跳过 |
| JS 监听器探测拥塞 CDP（describeNode 风暴） | 中 | 两档上限（10k 元素/100 命中）+ 分批并发（20/批）+ 超时跳过；可选增强通道默认关闭（T-4），默认面不受其影响 |
| 跨域 iframe 无法探测（frameId 缺失/漂移） | 中 | （二期路径）src URL 匹配兜底；仍失败则该帧降级为 `|IFRAME|` 占位 + 隐藏提示，不阻塞主树；一期无跨域递归（U-4） |
| 版本竞态（采集窗口内页面变化） | 中 | 采集事务化四步（§4 M-5）：起始/结束双读版本与 epoch，窗口内推进或 epoch 变化即中止不提交、返回 Stale；动作前 `validate_snapshot(tab_id, version)` + 3 次重试（维度 14）；VersionReset（epoch 变化/+1000 跳变）一律 Stale（U-2） |
| 采集中断/崩溃（半成品快照） | 低 | 提交为唯一写入点（§4 M-5 采集状态机）：中断/崩溃后无缓存条目残留，状态回 `Idle` 重新采集 |
| 预算截断误伤目标元素（目标在被折叠子树内） | 低 | 截断保留「可交互元素计数」提示；模型可滚动/重快照（滚动推进版本自然重拍） |
| 绘制序误删可见元素（遮挡计算偏差） | 低 | 仅删「非文本、非表单、被完全覆盖且背景不透明」节点；过滤可开关；误删最多影响索引密度，不影响定位正确性 |
| 脱敏遗漏（新输入形态绕开字段规则） | 低 | 规则集中在 redact.rs 单出口，D5 明确不做启发式；新形态以测试用例补齐（T5 回归） |
| 已知盲区元素不可读/不可操作（canvas/视频/纯图片/closed shadow） | 低 | 已登记盲区表（§3.6，T-16）：占位符呈现 + 头部统计，模型明示；演进项（canvas OCR / closed shadow 聚焦点击）待 S0 实证后评估 |

## 9. 与相邻维度的接口约定（备忘）

- 维度 11（CDP 通道/事件总线）：提供 `snapshot_version(tab_id)` 读接口、`validate_snapshot(tab_id, version)` 与 `VersionAdvanced/VersionReset` 事件（§4，R-1/U-2）。
- 维度 14（动作执行）：消费 `selector_map`（backendNodeId + sessionId + frameTargetId）与 `validate_snapshot(tab_id, version)`（§4）。
- 维度 12（面板输入转发）：快照不感知用户操作；用户交互引发的布局变化经事件总线推进版本。
- 维度 15（协同模型）：快照与快照缓存按 (tab_id, version) 键控隔离（§3.5 M-6）；令牌吊销后在途快照作废；活跃/非活跃标签口径与预算分摊联动（T-6，§3.4）。
- 维度 17（安全）：evaluate 白名单表达式注册（滚动位置/监听器探测）；审计日志脱敏复用 redact.rs（D6）。
