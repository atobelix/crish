## 2. 执行原语接口

### 2.1 统一返回类型（成功/失败/版本失效三分类）

```rust
/// 动作执行结果：三层分类，供 retry.rs 决策，不向工具面直接暴露
pub enum ActionOutcome {
    /// 成功；payload 供工具面组织返回文本
    Success(ActionSuccess),
    /// 可重试失败：版本失效/节点过期/导航竞态/瞬态，重试状态机接管
    Retryable(ActionError),
    /// 致命失败：门禁拒绝/审批拒绝/入参非法/目标不可达，不做自动重试
    Fatal(ActionError),
}

pub struct ActionSuccess {
    /// 动作后页面是否发生导航（由事件总线判定），供工具面提示
    pub navigated: bool,
    /// 动作后最新 URL（导航时非空）
    pub url_after: Option<String>,
    /// 动作后是否应推进快照版本（引擎判定；导航/布局变更时 true）
    pub page_changed: bool,
    /// 附加数据（evaluate 结果、上传文件数等）
    pub payload: Option<serde_json::Value>,
}

#[derive(Debug, Clone, PartialEq)]
pub struct ActionError {
    pub kind: ActionErrorKind,
    pub message: String,
    /// 第几次派发尝试（1 起）
    pub attempt: u8,
    /// 关联 CDP 错误原文（有则填，供审计/排查）
    pub cdp_raw: Option<String>,
}

pub enum ActionErrorKind {
    VersionInvalid,      // snapshotVersion 不匹配（重连/崩溃重启 VersionReset 后旧版本一律 Stale，U-2）
    NodeStale,           // backendNodeId 无法解析/box 获取失败
    TargetClosed,        // "Target closed" 等：标签页/目标销毁
    ContextGone,         // 执行上下文销毁/帧分离（导航竞态）
    ConnectionLost,      // CDP 连接断开（11 §3.2 CdpError::ConnectionLost，R-9）
    TargetRestarting,    // 浏览器进程启动中/崩溃重启中（维度 10 Launching/Crashed，R-9）
    NotInteractive,      // 元素隐藏/禁用/被遮挡（box 校验不过）
    Timeout,             // 原语级超时（click 15s 等）
    GateDenied,          // 域名门禁拒绝（含 IP 阻断）
    ApprovalDenied,      // 审批未通过（由维度 17 直接拦截，原语层兜底）
    InvalidInput,        // 入参非法（索引越界、路径不存在等）
    Unsupported,         // 目标不可支持（如跨域 iframe 元素未启用，二期启用）
    Aborted,             // 用户接管/令牌吊销（不计入重试额度，R-8）
}
```

### 2.2 统一执行入口（所有原语的公共前/后置）


执行流水线（每步可被 retry.rs 循环）：

```
execute()
 ├─ 1. gate.check(current_url)           维度 17 §4 门禁检查点（含 IP 阻断，R-7）——原语层统一入口

  └─ 7. 审计记录（操作变体 browser-* 以 17 §6.1 为唯一权威，M-4；脱敏 17 §6.2）
```

> **令牌获取与单动作总预算（T-8/T-9）**：
> - **令牌获取在工具层入口**（协同层，经 `ToolContext` 获取 `CollaborationToken`（持有 `AbortToken` 引用，M-2），**早于执行流水线**；桥接定义于 17 工具接线处）；本流水线内第 3 步 `abort.check()` 是**检查**而非获取。与维度 15「入口获取令牌」表述兼容——15 不描述流水线内部顺序，**执行流水线内顺序以本维度为准**（门禁 → 版本 → abort → 定位 → 派发 → 后置复核 → 审计）。
> - **`ACTION_TOTAL_TIMEOUT = 120s`**：单动作总预算，自 `execute()` 进入起算，**含全部重试、等待与分块延迟**；超时 → 返回失败（`Timeout` 级，不再发起新一轮重试）。原语级单次超时（表 2-1，如 type 60s）在总预算内生效；**分块型动作（type）按总预算内分块累计**——块间节流与回读校验时长均计入 120s。

## 3. 定位与坐标解析（locate.rs）

### 3.1 定位链

```
快照索引 [N] ──维度13──▶ backendNodeId ──▶ pushNodesByBackendIdsToFrontend ──▶ nodeId
                                              │
                        ┌─────────────────────┴─────────────────────┐
                        ▼                                           ▼
                  无坐标路径（type/focus/key/select/upload）   坐标路径（click/hover/drag/scroll）
                  DOM.focus(nodeId) / callFunctionOn(objectId)   DOM.getBoxModel(nodeId) → 中心点/四角
                  DOM.setFileInputFiles(backendNodeId, …)        → 遮挡检测 → Input.dispatchMouseEvent
```

- backendNodeId 是快照与执行之间的**唯一契约**：快照序列化时记录，动作时直接携带，不做 CSS 选择器二次查询（防选择器漂移）。
- nodeId 是前端树临时句柄（每次 push 均可能变化），**不允许跨动作缓存**；backendNodeId 在文档生命周期内稳定。
- 跨域 iframe 元素：backendNodeId 属于具体 frame 的 session；若元素位于未启用 iframe 支持的目标内，返回 `Unsupported`（一期默认不启用跨域 iframe，对齐总纲 §3.1）。

### 3.2 选择逻辑：何时走坐标（决策规则）

| 原语 | 路径 | 理由 |
|---|---|---|
| type / key / focus / select_option / upload | backendNodeId 直接注入 | 键盘事件作用于焦点元素；select/upload 有专用 DOM 命令；无需坐标即无坐标漂移 |
| click / hover | getBoxModel 坐标 | 点击命中测试依赖渲染位置，坐标必须真实 |
| drag | 两端 getBoxModel 坐标 | 拖拽目标语义需要两端位置 |
| scroll（页面） | 视口中心坐标 + mouseWheel | 滚动位置与元素无关 |
| scroll（元素） | 滚动容器内：先 `scrollIntoViewIfNeeded` 取 box，再对容器内偏移量滚轮 | 元素在滚动容器内时，若直接按元素全局坐标滚轮会滚错目标 |

**滚动容器内目标**：当元素 `getBoxModel` 的 box 有部分/全部在视口外（client 坐标越界）时：
1. `DOM.scrollIntoViewIfNeeded(nodeId)`；
2. 重新 `DOM.getBoxModel`（滚动后 box 会更新，无需重快照）；
3. 若仍不可见（容器嵌套滚动），循环 step1-2 最多 2 次，仍失败 → `NotInteractive`（可重试，重试状态机走 wait_for 后再试）。

### 3.3 坐标计算（box 校验）

```rust
pub struct ResolvedPoint { pub x: f64, pub y: f64 }

/// 从 DOM.getBoxModel 计算注入点；返回 None 表示 box 无效（元素不可见/零尺寸）
fn resolve_click_point(model: &BoxModel, viewport: &Viewport) -> Option<ResolvedPoint> {
    // model.content 为 8 个数字 = 4 个点（左上/右上/右下/左下）
    let cx = (content[0] + content[4]) / 2.0;   // 对边中点取中心
    let cy = (content[1] + content[5]) / 2.0;
    // 视口裁剪：注入点必须落在 [0, viewport.w/h) 内
    if cx < 0.0 || cy < 0.0 || cx >= viewport.w as f64 || cy >= viewport.h as f64 {
        return None;  // → NotInteractive，触发 scrollIntoView 重试
    }
    // 零尺寸检测：content 四角共点 → 不可见
    if (content[0] - content[4]).abs() < 0.5 && (content[1] - content[5]).abs() < 0.5 {
        return None;
    }
    Some(ResolvedPoint { x: cx, y: cy })
}
```

### 3.4 元素不可见/被遮挡检测

两层校验，全部通过才派发：

| 层 | 手段 | 失败语义 |
|---|---|---|
| 可见性 | `getBoxModel` 返回 null / 零尺寸 / 视口外（§3.3） | `NotInteractive` |
| 遮挡 | `DOM.resolveNode(nodeId)` → objectId → `Runtime.callFunctionOn`：`(x,y) => { const el = document.elementFromPoint(x,y); return el === this || this.contains(el); }`（目标是元素本身或其包含链） | 被遮挡：`NotInteractive` |

- 遮挡检测只对 click/hover/drag 执行（坐标路径）；无坐标路径靠 `DOM.focus` 自身语义。
- 遮挡结果 **false**（被顶层元素盖住）时：不猜坐标补偿（禁止"坐标测距魔术数字"），直接返回 `NotInteractive` → 重试状态机决策（快照可能过时，元素可能已被移动）。

## 4. type 输入规范（keyboard.rs）

### 4.1 分块与节流

| 参数 | 默认值 | 说明 |
|---|---|---|
| `TYPE_CHUNK_SIZE` | 50 字符 | 每块最多 50 个可打印字符 |
| `TYPE_CHUNK_DELAY_MS` | 12ms | 块间延迟；给渲染进程喘息窗口，避免长输入饿死事件循环（对齐 50 字符/12ms 业界节奏） |
| `TYPE_CHAR_EXTRA_DELAY_MS` | 0（可配置） | 组合敏感页面（contenteditable 编辑器）可开 5ms/字符 |
| 块内节奏 | 连续派发不延时 | 块内 keyDown→char→keyUp 三事件紧邻 |

> 分块型动作总时长（块间节流 + 回读校验）累计计入 `ACTION_TOTAL_TIMEOUT`（§2.2，T-9），超总预算即中止返回失败；单次派发仍受表 2-1 原语级超时（type 60s）约束。

```rust
pub async fn type_text(&self, el: &ElementRef, text: &str, submit: Option<Key>) -> Result<()> {
    let chars: Vec<char> = text.chars().collect();
    for (i, chunk) in chars.chunks(TYPE_CHUNK_SIZE).enumerate() {
        self.abort.check()?;                       // 接管/令牌吊销 → 中断（维度 15）
        for &c in chunk {
            self.dispatch_char(c).await?;          // 可打印字符三事件序列（§4.2）
        }
        if i + 1 < chunks.len() {
            sleep(TYPE_CHUNK_DELAY_MS).await;
            self.verify_progress(text, i)?;        // 可读回校验（§4.4）
        }
    }
    if let Some(k) = submit { self.press_key(k).await?; }
    Ok(())
}
```

### 4.2 可打印字符按键事件序列

每个可打印字符派发**三事件**（对齐 Puppeteer 序列，保证 input 事件与 isTrusted=true）：

```
Input.dispatchKeyEvent { type: "keyDown",  key, code, text, unmodifiedText, modifiers, windowsVirtualKeyCode }
Input.dispatchKeyEvent { type: "char",     text }
Input.dispatchKeyEvent { type: "keyUp",    key, code, modifiers, windowsVirtualKeyCode }
```

- Shift 依赖的字符（大写、`!@#`）：`key` 字段传实际字符，`text` 传实际字符，`windowsVirtualKeyCode` 传对应 VK；**不**靠物理键映射猜布局（按字符值注入，布局无关）。
- 未知字符（引擎映射表外）：退化为 `Input.insertText`（§4.4）。

### 4.3 特殊键映射表（key 组合键 + 单键）

键名字符串 → `(code, windowsVirtualKeyCode)` 常量表（`keyboard.rs` 内 `const KEY_MAP: &[(&str, &str, u16)]`，Windows VK 编码）：

| 键名 | code | VK | 键名 | code | VK |
|---|---|---|---|---|---|
| Enter | Enter | 13 | Tab | Tab | 9 |
| Escape | Escape | 27 | Space / " " | Space | 32 |
| Backspace | Backspace | 8 | Delete | Delete | 46 |
| Insert | Insert | 45 | Home | Home | 36 |
| End | End | 35 | PageUp | PageUp | 33 |
| PageDown | PageDown | 34 | ArrowLeft/Up/Right/Down | 同名 | 37/38/39/40 |
| Shift（修饰键位掩码 8） | ShiftLeft | 16 | Control（掩码 2） | ControlLeft | 17 |
| Alt（掩码 1） | AltLeft | 18 | Meta（掩码 4） | MetaLeft | 91 |

> 组合键解析：`"Control+A"` → 修饰键 `[Control]` + 主键 `A`；**先按修饰键 down → 主键 down/up → 修饰键逆序 up**（对齐 browser-use page.py `press` 序列）。边界：`"Control++"` → 修饰键 `[Control]` + 主键 `+`（`+` 作为最后一个 token 时视为字面键）；主键前无修饰符的 `"Enter"` 直接单键 down/up。修饰键释放用 `try/finally` 兜底——主键事件抛错也必须释放已按下的修饰键（防逻辑卡键，对齐 chrome-devtools-mcp input.ts:512-518）。
> 部分站点对组合键用 `e.key === 'Control'` 判断——CDP 注入的 keyDown 事件 `key` 字段按表填 `"Control"`，与真实一致。

### 4.4 IME 组合输入处理（对接维度 12 裁决）

- **AI type 的 CJK 路径**：映射表外的非 ASCII 字符（中文等）**整块**走 `Input.insertText { text }`（提交式文本插入，isTrusted=true，触发 input 事件），不逐字符拼 keyDown——避免合成组合事件与真实输入法语义偏差。
- **维度 12 对接**：用户面板转发路径的 IME 合成（compositionstart/update/end）由维度 12 裁决实现（`Page.inputEvent` 域事件面）；本原语与之共享 `Input.insertText`/`dispatchKeyEvent` 底层管线，两侧语义一致（单通道原则，总纲 §3.3）。
- **组合敏感编辑器**（ProseMirror/CodeMirror 等 contenteditable）：若 `Input.insertText` 后回读值未变化（§4.5 校验失败 1 次），升级为逐字符 `dispatchKeyEvent(keyDown + text)`（该序列触发 Chromium 组合路径）再回读；仍失败 → `Retryable(NotInteractive)` 级错误上报。
- **回读校验**（`verify_progress`）：块派发后 `Runtime.callFunctionOn(activeElement)` 读取 value/innerText 尾部比对；检测到输入未落盘（页面吞字符）时插入缺失片段（`insertText` 补差），连续 2 块失败 → 中断并返回可重试错误。对 `input[type=password]` 快照元数据已标记（维度 13），回读只比对长度不比对明文，审计脱敏（17 §6.2）。

## 5. 重试与失效（retry.rs）

### 5.1 错误分类 → 重试策略映射表

| 错误类别 | 触发条件（含 CDP 错误原文识别） | 策略 | 计入重试次数 |
|---|---|---|---|
| `VersionInvalid` | `snapshot.validate` 失败（动作前）；动作后事件总线版本推进 | **重快照** → 按索引重定位 → 重派发 | ✔ |
| `NodeStale` | `pushNodesByBackendIdsToFrontend` 返回空 nodeIds；`getBoxModel` 报 "Could not compute box model"；`"No node with given id found"` | **重快照** → 重定位（索引在新快照中不存在 → `InvalidInput` 致命）；**3 次重试耗尽 → 返回「节点定位失败」+ 升级提示**（T-10，用户确认后继续/中止，接口点见 §5.3） | ✔ |
| `TargetClosed` | `"Target closed"` / `"Target page, context or browser has been closed"` | 等待 300ms → 校验版本 → 若目标（标签页）已销毁 → `Fatal`；若只是瞬时 → 重快照重试 | ✔ |
| `ContextGone`（导航竞态） | `"Execution context was destroyed"` / `"Cannot find context with specified id"` / `"Frame was detached"` / `Page.frameStartedNavigating`（click 触发导航，坐标已失效） | **延迟重试**（300ms）→ 重快照重试（§5.4） | ✔ |
| `NotInteractive` | box 校验失败（§3.3/§3.4）；`disabled` 属性（快照元数据） | 首次：wait_for 可见（轮询 ≤2s）→ 重试；再次：重快照重试 | ✔ |
| `Timeout` | 原语级超时（表 2-1） | wait_for 对应条件（元素可见/网络空闲）→ 重试 1 次；仍超时 → `Fatal` | ✔ |
| `ConnectionLost` | CDP 连接断开（`CdpError::ConnectionLost`，11 §3.2；R-9） | **不消耗重试额度**：等待 `ConnectionRestored` 恢复事件后重试 1 次；恢复超时（维度 10 崩溃重启窗口）→ `Fatal`；恢复期工具面返回 `tool.browser.not_ready`（17 §1.3） | ✘（恢复后重试 1 次不计入额度） |
| `TargetRestarting` | 浏览器进程启动中/崩溃重启中（维度 10 `Launching`/`Crashed`；R-9） | 恢复期（恢复清单完成前）工具调用由工具层 gating 返回 `tool.browser.not_ready`（17 §1.3）；原语层遇此状态不自动重试 → `Fatal` | ✘ |
| `Aborted` | 用户接管/令牌吊销（`abort.check()` 命中：执行前/分块间/等待间） | 立即中止，不自动重试 | ✘（R-8：用户接管吊销不计入 3 次总上限） |
| `GateDenied` | §7 门禁拒绝 | 不自动重试 → `Fatal`（工具面报门禁错误 `tool.browser.gate_blocked`，17 §1.3） | ✘ |
| `ApprovalDenied` | 审批拒绝（维度 17 在工具层拦截；原语层兜底） | 不自动重试 → `Fatal` | ✘ |
| `InvalidInput` / `Unsupported` | 索引越界、路径非法、iframe 不支持 | 不自动重试 → `Fatal` | ✘ |

> 额度口径（R-8）：**版本失效（`VersionInvalid`）/节点过期（`NodeStale`）等重试性错误计入 3 次总上限**（防无限循环，§5.3）；**`Aborted`/Stale（用户接管吊销）不计入**（接管是外部事件，不消耗自动重试额度）；`ConnectionLost` 的恢复后重试（≤1 次）与 `TargetRestarting` 的 gating 返回亦不计入（R-9）。

### 5.2 snapshotVersion 校验接口（维度 13 提供，本维度消费）

```rust
// —— 维度 13（感知快照）提供的契约（R-1：per-tab 签名，11 §8 统一接口）——
pub trait SnapshotStore {
    /// 标签页独立版本号（11 §5.4 VersionTracker；推进规则单一权威在 11）
    fn snapshot_version(&self, tab_id: &TabId) -> u64;
    /// 预算受限快照（层级/元素数/文本长度截断，维度 13 定参；异步采集）
    async fn take_snapshot(&self, tab_id: &TabId) -> Result<Snapshot, SnapshotError>;
    /// 快照内按索引解析元素元数据（index ↔ backendNodeId 绑定）
    fn element_by_index(&self, snap: &Snapshot, index: usize) -> Option<ElementMeta>;
}

// —— 本维度消费统一契约（11 §8：validate_snapshot(tab_id, version) -> Result<(), Stale>，13/14/15 共用）——
/// 校验动作携带版本是否仍有效，底层复用 11 的 validate_snapshot，此处仅为错误映射；
/// **VersionReset（重连/崩溃重启，11 §5.4 #9；版本跟踪器 Lagged 重对齐，U-2）后旧版本一律 Stale**。
fn validate_snapshot(tab_id: &TabId, version: u64) -> Result<(), ActionError> {
    match session.validate_snapshot(tab_id, version) {   // 11 §8 面
        Ok(()) => Ok(()),
        Err(Stale) => Err(ActionError::new(ActionErrorKind::VersionInvalid,
            "快照版本已过期（版本推进或 VersionReset 后作废）")),
    }
}
```

### 5.3 重试状态机（重快照 → 重定位 → 重试，3 次上限）

```
                 ┌──────────────────────────────────────────────────┐
                 │             execute(primitive, el_ref)           │
                 │  attempt = 1..=MAX_ATTEMPTS (3)                  │
                 └──────────────────────┬───────────────────────────┘
                                        ▼
                        gate.check + validate_snapshot ──✗ GateDenied/InvalidInput → Fatal
                                        ▼
                          locate + 可见性/遮挡检测 ──✗ NotInteractive → wait_for(≤2s) → 重定位(1 次内)
                                        ▼
                              dispatch → CDP 错误？
                  ┌────────────────────┼────────────────────┐
                  ▼                    ▼                    ▼
            VersionInvalid        NodeStale           ContextGone/TargetClosed
            / 动作后版本推进        / box 失败            / 导航竞态
                  │                    │                    │
                  ▼                    ▼                    ▼
            take_snapshot()      take_snapshot()      延迟 300ms + 版本校验
            → element_by_index   → element_by_index     ├─ 版本变化 → take_snapshot
            → 重新派发           → 重新派发             └─ 无变化   → 原 backendNodeId 重派发
                  │                    │                    │
                  └────────── 全部计入 attempt；attempt > 3 → Fatal(最后一次错误) ──┘
```

- **重快照次数与派发次数共用 3 次上限**（对齐 browser-use `max_failures=3`）；每次重快照本身受维度 13 的预算/耗时上限约束（快照超预算 → 原错误原样返回）。
- 状态机输入不变：重定位只换 backendNodeId，**原语参数（文本/按键/坐标方向）不重写**——模型参数不可被重试机制篡改。
- 重试全程检查 `abort`（用户接管）与 `GateDenied`（重快照后 URL 变化触发门禁）：中途用户接管 → 立即中止返回 `Aborted`（维度 15 定语义；**不计入 3 次总上限**，R-8）。
- **NodeStale 重试耗尽升级（T-10）**：`NodeStale` 3 次重试（重快照 → 重定位 → 重派发）仍失败 → 不再自动致命，返回「节点定位失败」并附**升级提示**（向用户说明目标元素反复失效，供用户确认后**继续**——携最新快照再试一轮，或**中止**）；升级接口点接入维度 17 §2.2 审批链（Ask 模式由用户裁决：继续视为审批通过，中止按用户语义返回 `Aborted`）；其余错误类别 3 次耗尽仍按 `Fatal(最后一次错误)` 处理（原语义保留，仅 `NodeStale` 走升级路径）。
- 断线/重启（R-9）：CDP 断连（`ConnectionLost`）或浏览器进程启动中/崩溃重启中（`TargetRestarting`）**不进入自动重试**——等待恢复事件（`ConnectionRestored`）后重试 ≤1 次，恢复超时（维度 10 崩溃重启窗口）转 `Fatal`；恢复期（恢复清单完成前）工具面由 gating 返回 `tool.browser.not_ready`（17 §1.3）。

### 5.4 导航竞态检测

| 检测点 | 手段 | 处理 |
|---|---|---|
| 派发前 | `Page.frameStartedNavigating` 事件（click 前监听）；事件类型 `historySameDocument/sameDocument` 不算竞态 | 命中 → 延迟 300ms → 重快照 |
| 派发后 | 事件总线 `Page.frameNavigated`/`Page.loadEventFired` + 版本推进 | 重快照（click 触发的正常导航不视为错误，`Success{navigated:true}`） |
| CDP 层 | 错误原文含 "context was destroyed"/"Target closed"（表 5-1） | 按表走 |

判定口径：**"导航竞态"= 动作派发窗口内发生了非动作预期的导航**（快照基于导航前页面，坐标/节点已失效）。动作预期导航（click 链接）属于正常结果，后置 URL 门禁复核（§7.1 ③）兜底。

## 6. wait_for 实现（wait.rs）

### 6.1 条件类型与实现

```rust
pub enum WaitCondition {
    /// 元素可见可交互：快照索引（内部解析为 backendNodeId，R-5）
    Element { index: usize },
    /// 页面纯文本子串匹配（document.body.innerText 包含；参数经 JSON.stringify 注入固定模板，R-5）
    Text(String),
    /// 网络空闲：在途请求数归零并持续 quiet 窗口
    NetworkIdle { quiet_ms: u32 },
    /// URL 纯字符串匹配（子串包含；禁止正则/JS 表达式，R-5）
    Url { contains: String },
}

pub struct WaitOptions {
    pub timeout_ms: u32,     // 默认 30_000；Element/Text 默认 10_000
    pub poll_ms: u32,        // 轮询兜底间隔：Text/Url 默认 100；Element 快照轮询定值 max(200ms, 维度13快照耗时预算)（T-7）
}
```

> 条件面（R-5）：wait_for 的入参仅两类——**快照索引**（内部解析为 backendNodeId）与**纯文本/URL 字符串匹配**；**禁止 CSS selector 与 JS 表达式入参**（撤销原 `JsPredicate` 变体与 `Url.regex` 表述，对齐 17 §1.2 `browser_wait_for` schema 的「禁止 CSS selector 与 JS 表达式入参」）。文本/URL 匹配实现为**固定代码模板 + 参数 JSON 序列化注入**（`JSON.stringify` 包裹，永不经字符串拼接进代码文本），谓词代码不含任何模型输入。

### 6.2 事件驱动 vs 轮询

| 条件 | 主路径（事件驱动） | 兜底（轮询） | 说明 |
|---|---|---|---|
| `Text` | 固定代码模板 + `MutationObserver`：`document.body.innerText.includes(<参数>)`，**参数经 `JSON.stringify` 序列化注入**（永不经字符串拼接进代码文本；谓词代码无模型输入，R-5），DOM 变化即重新判定（对齐 WaitForHelper 的 MutationObserver 方案） | 100ms 轮询（同一固定模板） | observer 创建本身设 3s 上限（渲染进程暂停时防止悬挂，对齐 chrome-devtools-mcp `stableDomTimeout`） |
| `Element{index}` | 无（索引只存在于快照） | 快照重拍轮询，间隔**定值** `poll_interval = max(200ms, 维度13快照耗时预算)`（T-7）——以快照耗时预算为下界，防「一次轮询 = 一次全量快照」的无效高频，另设 200ms 绝对下界；快照耗时预算取维度 13 §6.1 双层口径（p95 ≤2s 目标 / ≤5s 硬预算），常量实现，**S0 实证后微调** | 索引内部解析为 backendNodeId（R-5）后复用 §3 定位链可见性校验；快照轮询受维度 13 预算/耗时上限约束，超限按超时处理 |
| `NetworkIdle` | `Network.requestWillBeSent/loadingFinished/loadingFailed` 维护在途计数 | 无 | idle 判定 = 计数归零持续 `quiet_ms`（默认 500ms，对齐 browser-use `networkidle` 语义） |
| `Url` | `Page.frameNavigated`/`Page.frameStartedNavigating` 事件 | 100ms `getTargetInfo().url` | **纯字符串子串匹配（contains），禁止正则/JS 表达式**（R-5）；同文档导航（hash 变化）也命中（`frameNavigated` 的 `sameDocument` 变体） |

- **超时**：默认 30s（对齐 browser-use `WaitEvent` 60s 可调；本引擎默认 30s 可 env `CRISH_BROWSER_WAIT_TIMEOUT_MS` 覆盖）；元素/文本默认 10s。
- 超时错误归类 `Timeout` → 工具面可将其作为结果喂回模型（非致命，对齐 agent-tools `fatalOnError=false` 语义）。
- 等待期间**必须可被 abort 中断**（用户接管即退出，不空等）。

## 7. 域名门禁（gate.rs）

### 7.1 检查点位置（原语层统一入口）

门禁在 `execute()` 流水线第 1 步（§2.2）——**所有原语共用一个入口**，另有两处补充检查点：

| 检查点 | 时机 | 内容 |
|---|---|---|
| ① 动作前（统一） | 每次 `execute` 首步 | 当前 URL host 匹配 + IP 阻断（§7.3，判定流程以维度 17 §4.3 为唯一权威） |
| ② 导航预检 | 点击目标是 `<a href>` 时（`callFunctionOn` 读 href，相对地址解析为绝对） | href 目标 host 预匹配；不在白名单 → `GateDenied`，不派发 |
| ③ 动作后复核 | 动作触发导航后 | 新 URL host 复核；不在白名单 → 回退（`Page.goBack`，仅当上一 URL 在白名单）并返回 `GateDenied`（附"已回退"说明） |

> 导航类原语（navigate/back/forward/reload/new_tab）由维度 17 工具层调同一 `DomainGate` 接口做入口检查（17 §4.4 导航检查点，实现取本维度 §7.1 语义）；本维度保证**动作面**无白名单外执行路径。

### 7.2 匹配规则（维度 17 §4 唯一权威，R-7）

**`DomainGate` 结构与匹配语义以维度 17 §4 为唯一权威实现**（R-7 裁决）：本维度**不定义** `DomainGate`/`DomainPattern` 结构（撤销原自建 allow/deny/block_ip_literals 字段模型），动作面统一经 `conex-browser/src/gate.rs`（17 §4.2）判定。

- **通配符语义（17 §4.2 定死，全项目唯一口径）**：`*.example.com` = 任意子域（**不含** example.com 根域）；`example.com` = 根域 + 任意子域（等效 `*.example.com` 并集）；`**`/`*` = 任意层任意域名；IP 字面量（`127.0.0.1`/`::1`）可入白名单/黑名单；TLD 通配（`example.*`）一律拒绝（配置校验期报错）；**黑名单命中不可豁免（含 full-access）**；scheme 策略（非 http/https 阻断等）以 17 §4.2 `scheme_policy` 为准。
- **默认策略已由 17 §4.1 裁决**（开放问题 3）：白名单为空 = 默认全允许（限公共互联网），IP 直连/保留段为不可豁免硬门禁；白名单非空 = 白名单外一律 Deny。
- 性能注记（沿用本维度原设计意图）：条目 ≤100 时线性匹配可加 HashMap 快速路径；匹配只比对 host（不含端口）与 scheme，路径不参与（门禁不拦路径）。

### 7.3 IP 地址阻断与解析级校验（以 17 §4.3 为准，R-7/R-11）

IP 阻断的**判定流程、保留/内网段表与传输层阻断以维度 17 §4.3 为唯一权威**（IP 字面量判定不触发 DNS；解析后任一段命中即 Deny 且 fail-closed；`Network.setBlockedURLs` 传输层兜底页面自身 JS 的内网/云元数据请求）。本维度只声明动作面消费口径：

- **动作检查点执行 17 §4.3 全流程校验（含解析级）**（R-11）：`execute()` 首步门禁检查即含「scheme 门禁 → IP 字面量判定 → 解析后网段校验 → 60s 重绑定窗口内每动作重复解析校验」；撤销原「动作前热路径字面量级、解析级仅导航场景」的分层表述（R-11 后动作检查点解析级校验为承诺）。
- ② 导航预检 / ③ 动作后复核复用同一判定（17 §4.4 导航检查点语义，实现取本维度 §7.1）。
- 门禁拒绝 → 原语层 `Fatal(ActionErrorKind::GateDenied)`，工具面映射 **`tool.browser.gate_blocked`**（17 §1.3 码表），审计必记（操作变体 `browser-gate`，17 §6.1）。
- 默认策略已由 17 §4.1 裁决（白名单空 = 全允许限公共互联网）；IP 字面量/保留段阻断为**不可豁免硬门禁**，不随白名单配置与权限模式变化（R-7，安全基线 B6/I-03 对齐）。

## 8. evaluate 受限求值（evaluate.rs）

### 8.1 唯一权威：维度 17 §3（R-6）

**evaluate 的实现以维度 17 §3 为唯一设计**：`__crish_read` 白名单代理对象 + 三层校验（静态词法 → isolated world 执行（timeout 2s，constructor 链检查，纯 JSON 返回值）→ 结果预算 64KB/深度 4）。本维度**撤销**原「编译期 helper 表 + 自由求值」双轨设计，不再定义 helper 静态表、自由求值面与禁用面沙箱——上述全部以 17 §3.1/§3.2 为准（白名单 API 与允许/禁止形态见 17 §3.1 表）；本维度只保留原语接口与审批对接点。

### 8.2 原语接口（仅签名，实现引用 17）

```rust
pub struct EvaluateRequest {
    /// 受限求值表达式（允许形态/白名单 API 见 17 §3.1）
    pub expression: String,
    /// 快照元素索引（可选；内部解析为 backendNodeId/objectId 后经代理求值）
    pub element: Option<ElementRef>,
    /// 求值硬限，上限 2000ms（17 §3.2）
    pub timeout_ms: u32,
}

/// 受限求值：实现经 17 §3 三层校验（本原语不自行实现求值面）
/// 失败映射：静态词法/运行时拦截 → 工具面 `tool.browser.eval_forbidden`（17 §1.3）；
/// 能力位未开/审批拒绝 → 工具层先行拦截（17 §2.3/§3.3），原语层凭证兜底 `Fatal(ApprovalDenied)`
pub async fn evaluate(&self, req: EvaluateRequest) -> Result<serde_json::Value, ActionError>;
```

### 8.3 审批与审计对接（17 §3.3/§6 权威）

- 能力位：`SensitiveCapabilities.evaluate` 默认关（17 §2.3 默认拒绝面）；Ask 模式逐次审批（`dangerous=true`，默认拒绝），FullAccess 放行、Plan 拒绝（17 §3.3）。
- 审计：求值入参记 `sha256(expression)` + 长度（17 §3.3 全量审计）；操作变体 **`browser-evaluate`** 以 17 §6.1 为唯一权威，**本维度不自定义审计事件**（M-4）。

## 9. 上传实现（upload.rs）

### 9.1 流程（DOM.setFileInputFiles 主路径）

```
upload_file(el, path)
 ├─ 1. 授权对接：工具层 dangerous=true 走审批（维度 17）；原语层凭证兜底校验
 ├─ 2. 路径校验：绝对路径、存在、可读、非目录、大小 ≤ 500MB（配置项）
 │     └─ 违反 → InvalidInput（文件不落审计明文路径以外内容）
 ├─ 3. 定位元素：快照索引 → backendNodeId（可先走 §3 可见性校验）
 ├─ 4a. 元素是 input[type=file]（快照元数据判定）
 │     └─ DOM.setFileInputFiles { backendNodeId, files: [path] }   ← backendNodeId 直传，无需 push 到前端树
 ├─ 4b. 元素是代理触发器（label/button，点击才弹文件选择）
 │     ├─ 注册 Page.fileChooserOpened 一次性监听（等待 ≤3s）
 │     ├─ Input.dispatchMouseEvent 点击元素（§3 坐标路径）
 │     └─ 事件到达 → 取事件 payload 的 backendNodeId → DOM.setFileInputFiles
 │        └─ 3s 内无事件 → 超时（可重试一次）
 └─ 5. 回读校验：callFunctionOn 读 input.files.length == 1 且 name 匹配
       └─ 不符 → Retryable(Timeout) 级重试
```

- 授权对接口径：上传**默认拒绝**（敲定 D-9：剪贴板/上传默认拒绝）；审批通过后单次授权绑定 `(element 索引, path)`，不缓存跨动作授权。
- 路径安全检查：**仅允许工作区内路径**，过 `resolve_workspace_path` 校验（canonicalize + symlink 双保险 + 组件边界，以 17 §7.2 为唯一权威；撤销原「用户显式授权目录」口子，19-L2）；`..` 穿越与符号链接在 canonicalize 后校验。
- 上传后是否需要触发 change 事件由浏览器自动完成（setFileInputFiles 产生真实 input 事件），无需 JS 补发。

## 11. 风险与预案

| 风险 | 等级 | 预案 |
|---|---|---|
| 合成事件与真实输入行为差异（页面反自动化检测、事件顺序敏感逻辑） | 中 | 统一 CDP Input 真实注入（isTrusted=true，敲定 D-3）；关键路径 e2e 覆盖（E2E-1/3/5）；反检测页面走键盘导航兜底（Tab+Enter 策略，对齐 browser-use 文档建议） |
| 滚动容器/嵌套滚动定位不准 | 中 | §3.2 滚动容器专用路径（scrollIntoViewIfNeeded 后重取 box）；E2E-6 覆盖 |
| 高频用户操作与 AI 动作抖动（版本频繁推进） | 中 | 版本失效重试（§5）+ 令牌最小稳定窗（维度 15）；重试上限防抖死循环 |
| 长输入被页面吞字符/编辑器组合敏感 | 中 | 回读校验 + insertText 补差 + 组合路径升级（§4.4）；60s 超时 |
| 门禁被点击触发的导航绕过 | 中 | 三重检查点（§7.1）：动作前/导航预检/动作后回退复核 |
| 恶意 evaluate 绕过受限求值（词法误判/代理对象逃逸） | 高 | 三层校验以维度 17 §3 为唯一实现（isolated world + `__crish_read` 白名单代理 + constructor 链检查 + 纯 JSON 返回值）；capability 默认关 + 逐次审批 + 全量审计（17 §3.3） |
| 重快照风暴（页面高频变动，快照预算耗尽） | 中 | 3 次上限；重快照预算受维度 13 约束；版本校验失败直接失败而非无限循环 |
| 目标销毁（用户关标签页）竞态 | 低 | `TargetClosed` 分类 → 等待后重查目标存活 → 存活才重试，否则致命（防死循环） |
| 断连/崩溃重启期的动作行为 | 中 | `ConnectionLost`/`TargetRestarting` 分类（R-9）+ 恢复期 `tool.browser.not_ready` gating（17 §1.3）；不消耗重试额度，恢复事件后重试 ≤1 次（§5.1/§5.3） |
| 跨域 iframe 元素动作 | 低 | 一期返回 `Unsupported`（不启用跨域 iframe，总纲 §3.1 对齐；执行面二期启用，U-4）；后续按需扩展 session 路由 |
