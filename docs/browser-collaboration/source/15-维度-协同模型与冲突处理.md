## 1. 范围与目标

本维度定义「用户与 AI 在同一渲染实例上协同操作」的全部冲突处理机制：

| 机制 | 作用 | 对抗场景 |
|---|---|---|
| 软互斥令牌（CollaborationToken） | AI 动作序列持有会话令牌，用户交互即吊销 | 用户与 AI 同时操作 |
| abort 抢断（复用 AbortToken） | 吊销令牌后物理中止 AI 在途动作 | 用户接管、急停 |
| snapshotVersion 失效 | 页面任何变更推进版本，AI 旧版本动作触发重快照 | AI 基于过期感知执行 |
| 指示条/接管状态机 | 状态可见 + 暂停/接管入口 | 用户感知与干预 |

四个机制是同一吊销链的四段：**令牌吊销（语义层）→ abort 中止（执行层）→ 版本失效（感知层）→ 状态切换（呈现层）**。任一机制单独都不完整（方案敲定 D-6 否决项），合一后覆盖全部冲突场景。

实现归属：`crates/conex-browser`（新 crate，Rust）核心协同模块 + `agent-tools` 侧工具校验入口；前端指示条 UI 归维度 12，本维度只定义状态机语义与事件契约。

## 3. 令牌机制（软互斥）

### 3.1 会话令牌结构（Rust 类型）

```rust
//! crates/conex-browser/src/collab/token.rs

/// 会话内标签标识（递增分配，不跨会话复用）
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub struct TabId(pub u64);

/// 令牌持有者：AI 动作序列（引擎侧为 run_id + 序列序号派生 id）
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct TokenHolder {
    /// 持有者标识（动作序列 id，形如 "run-{run_id}/seq-{n}"）
    pub holder_id: String,
    /// 获取时代次：每次 acquire 递增；动作执行随身携带，吊销后旧 epoch 立即失效
    pub epoch: u64,
    /// 获取时刻（单调时钟，诊断与审计用）
    pub acquired_at: Instant,
}

/// 吊销来源（审计日志 + 指示条文案 + 前端提示语三处共用）
#[derive(Debug, Clone)]
pub enum RevokeSource {
    /// 面板输入事件（用户交互；含用户切换标签，见 §7）
    UserInteraction { tab_id: TabId, kind: InputKind },
    /// 用户点击「暂停」按钮（挂起队列语义，见 §6.3）
    PausePressed,
    /// 会话结束 / 全局急停（维度 17 急停接线）
    SessionEnd,
}

/// 用户输入种类（维度 12 归一化枚举的引用面）
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum InputKind { Pointer, Key, Wheel, Ime, Touch }

/// 协同令牌：会话级单持有者软互斥（整个会话仅一枚，跨标签共享所有权）
pub struct CollaborationToken {
    inner: Arc<CollaborationTokenInner>,
}

struct CollaborationTokenInner {
    /// 当前持有者（None = 空闲；RwLock 短临界区，无 await）
    holder: RwLock<Option<TokenHolder>>,
    /// 代次计数器：acquire 递增；吊销不额外递增（清空持有者即失效）
    epoch: AtomicU64,
    /// 最近吊销时刻（单调时钟）——稳定窗判定的唯一权威源
    last_revoke: Mutex<Option<Instant>>,
    /// 最近吊销来源（审计）
    last_revoke_source: Mutex<Option<RevokeSource>>,
    /// 会话级 AbortToken 引用（M-2：吊销联动物理中止；与 ToolContext.abort_token 同一实例，
    /// 工具层经 ToolContext 获取——桥接定义在维度 17 工具接线处，agent-tools 不新增类型）
    abort: AbortToken,
    /// 吊销广播通知：revoke 时 notify_waiters 唤醒稳定窗等待者
    notify: tokio::sync::Notify,
}
```

要点：

- 令牌是**会话级单例**（一个浏览器会话一枚），AI 任一时刻至多持有一个动作序列令牌；「AI 当前操作哪个标签」由 `Coordinator.active_tab` 表达，令牌本身不绑定标签（多标签语义见 §7）。
- 实现完全在 conex-browser 内部（tokio 运行时可用）；不修改 `agent-tools` 的 `AbortToken` 本体——复用面见 §4。
- **令牌桥接（M-2）**：`CollaborationToken` 持有会话级 `AbortToken` 引用（字段 `abort`，引擎装配时注入，与 `ToolContext.abort_token` 同一实例）——`revoke()` 联动 `abort.abort()`（幂等）物理中止在途；browser 工具层经 `ToolContext` 获取同一实例执行 `is_aborted()` 自查。桥接定义落在维度 17 工具接线处（`run_browser_action`），`agent-tools` 不新增类型；本维度只定义持有关系。
- `epoch` 语义：动作执行全程携带 `TokenHolder`（含 epoch）；吊销/重获后旧 holder 的 epoch 与新值不等，`validate` 即失败。这保证「同一 AI run 被吊销后重新 acquire」也必须重快照（页面已被用户改过），而不是无缝续跑。

### 3.2 获取 / 持有 / 吊销规则

```rust
impl CollaborationToken {
    /// 获取令牌（软互斥，async）：
    /// - 已被持有（validate 通过的其他 holder）→ Err(Busy)
    /// - 处于稳定窗内（最近吊销后 < TOKEN_MIN_STABLE_WINDOW）→ 等待窗过或再次吊销（去抖）；
    ///   反复吊销则持续等待，最长 ACQUIRE_TIMEOUT → Err(Timeout)
    /// - 窗过后仍空闲 → 持有成功（epoch += 1，返回新 TokenHolder）
    pub async fn acquire(&self, holder_id: String) -> Result<TokenHolder, TokenError>;

    /// 吊销：1) 记录来源与时刻；2) 清空持有者；3) notify_waiters 广播。
    /// 返回被吊销的持有者（None = 本为空闲），吊销本身幂等。
    pub fn revoke(&self, source: RevokeSource) -> Option<TokenHolder>;

    /// 校验 holder 仍有效：当前持有者存在 且 holder_id/epoch 双匹配
    pub fn validate(&self, holder: &TokenHolder) -> bool;

    /// 正常释放（动作序列自然结束；不推进 epoch、不重置稳定窗）
    pub fn release(&self, holder: &TokenHolder);
}
```

| 规则 | 语义 |
|---|---|
| 获取 | 仅 `idle` 且稳定窗已过才成功；`acquire` 自身负责稳定窗等待（内部 `tokio::time::sleep_until` 到窗终点，任何 revoke 经 Notify 唤醒后重算窗终点） |
| 持有 | 持有期间 AI 可执行动作；每个动作前后调 `validate`（廉价原子读） |
| 吊销 | 任意时刻可吊销（幂等）；吊销即「用户赢」语义，AI 不得自动重获 |
| 释放 | 序列结束或全部动作被吊销后释放；释放不重置稳定窗（避免释放/重获绕过去抖） |

### 3.3 AI 动作序列的令牌生命周期

```
AI 首个动作前              每动作前/后                序列结束
    acquire()  ────────►  validate(holder)  ───────►  release(holder)
        │                       │   │                        │
        │ 成功                  │   └─ 失败（吊销过）          │
        ▼                       ▼                            ▼
   ai-busy（持有）         动作继续执行                idle（空闲）
        ▲                       │
        │                       ▼
        │  用户交互 → revoke() → abort 在途（§4）→ 工具层报 aborted
        └── 稳定窗过后 AI 重新 acquire（重快照后继续）
```

具体规则：

1. **获取时机（工具层入口，T-8）**：AI 计划执行浏览器动作序列时，引擎在动作序列进入执行流水线**之前**，由工具层入口（协同层，`ActionSequence::start`）调 `acquire`——令牌获取早于执行流水线；执行流水线内部顺序（门禁 → 版本 → abort → 定位 → 派发 → 后置复核 → 审计）以维度 14 为准，本维度不描述流水线内部顺序。失败（Busy/Timeout）→ 结构化错误返回 LLM，提示「用户正在操作浏览器，请稍后或询问用户」，不排入队列。
2. **校验时机**：每个动作执行前（快照校验之后、CDP 命令发出前）与执行后各一次 `validate`。执行后校验失败 → 该动作结果标记为 `AbortedByTakeover`（不重试）。
3. **吊销后处理**：被吊销的序列不自动重获；LLM 收到 `browser.aborted` 后自行决定是否重新 acquire（引擎侧 acquire 的稳定窗保证不会立即抢回）。
4. **释放时机**：序列全部动作结束（成功或失败）→ `release`；`SessionEnd` 吊销同时作用于队列中未派发动作（直接丢弃，不入执行）。

### 3.4 用户交互信号源 → 吊销的触发链

信号源 = 维度 12 面板输入转发层。触发链（顺序固定，单向，无回环）：

```
① 面板捕获原生用户事件（pointerdown/keydown/wheel/IME 合成/touch）
      │  维度 12：前端 → 引擎 WebSocket 事件 "input.user-interaction"
      ▼            （载荷：tab_id、InputKind、时间戳、转发 id）
② CollaborationCoordinator::on_user_interaction(tab_id, kind)
      │
③ collab.revoke(UserInteraction{..})          ← 语义层吊销（清持有者、记时刻）
      │
④ seq.abort.abort()                           ← 执行层中止（复用 AbortToken，§4.1）
      │
⑤ sender.cancel_pending(...)                  ← 发送层取消在途 CDP 命令（§4.2）
      │
⑥ bump(tab_id, reason)（维度 11 §8 版本面：per-tab 即时推进，U-1 撤销 200ms 聚合）← 感知层版本失效（§5）
      │
⑦ 动作执行器收到 Aborted → 工具层结构化返回（§4.3）
      │
⑧ panel.send(StateChanged{state: UserTakingOver}) ← 呈现层（§6）
      │
⑨ 前端将该用户事件经 CDP Input 注入浏览器实例（维度 12 原管线，不被本链阻塞）
```

接线要点：

- 吊销发生在**用户事件注入之前**（③-⑥ 先于 ⑨），保证 AI 在途动作不可能与用户输入同帧竞态；用户事件注入本身不等待吊销完成（用户体验优先），wire 序保证：发送层在 ⑤ 之后才发出用户注入命令。
- **吊销链唯一入口（U-9③/M-3）**：`CollaborationCoordinator`（② 起）是吊销链的唯一入口；维度 12 的 `PanelController` 仅做面板侧状态投影与按钮命令（暂停/恢复/接管请求转发本维度处理），不直接触发吊销或状态迁移。
- 同一用户事件只触发一次吊销链（`revoke` 幂等；重复事件仅刷新稳定窗起点，不重复 abort——abort 也幂等）。
- 审计：`last_revoke_source` 落审计日志（维度 17 审计面）；同一 200ms 聚合窗内多次 revoke 合并为一条审计记录（防刷屏）。

### 3.5 令牌最小稳定时间窗（参数与理由）

| 参数 | 默认值 | 可配 | 语义 |
|---|---|---|---|
| `TOKEN_MIN_STABLE_WINDOW` | **800ms** | 是（100-5000ms） | 最近一次吊销后，`acquire` 必须等待窗过才可重获；**同时为接管过渡时长**（U-9：`UserTakingOver` → `Idle`，统一常量） |
| `ACQUIRE_TIMEOUT` | **30s** | 是 | acquire 最长等待（含窗等待）；超时返回 `TokenError::Timeout` |

参数理由（量化）：

- **下界（不宜 <300ms）**：用户输入是突发流（打字 60-100ms/键、拖动连续 pointermove 约 8-16ms 一帧）。若窗过短，AI 会在用户两次按键间隙重获令牌，下次按键又被打断——「抢回-打断」抖动，且每次打断都触发一次 abort+版本推进+审计记录，系统颠簸。300ms 内任意两次相邻用户事件间隔平均小于该值（打字/拖动场景），仍不能消除抖动。
- **上界（不宜 >2000ms）**：窗过长让 AI 在用户短暂停顿后空等，协同感下降（用户停止输入≠拒绝 AI）。
- **800ms 的选择**：约等于「用户完成一次连续输入动作」的自然粒度（一次单击 <100ms、一次短句打字 <800ms、一次滚动停顿 0.5-1s）；同时远小于 LLM 一个思考-动作周期（秒级），AI 无感知停顿。实现上用「窗终点 = last_revoke + 800ms」的**去抖语义**：窗内每次新 revoke 把终点后移，天然消除突发流抖动。
- 该值经 S8 实测校准（验收项 3），配置项便于按用户手感调整。

## 4. abort 对接（抢断执行）

### 4.1 与既有 AbortToken 的接线（复用，不扩展）

既有设施：`crates/agent-tools/src/context.rs:32-52` 的 `AbortToken`（`Arc<AtomicBool>`，`abort()` 幂等、`is_aborted()`、Clone 共享同一标志，无 tokio 绑定）。

**裁决：直接复用既有 `AbortToken`，不扩展、不改写。** 浏览器引擎侧在其上包一层「序列/动作」双级使用，不新增令牌类型。令牌持有关系见 §3.1（M-2）：`CollaborationToken` 持有会话级 `AbortToken` 引用，`revoke()` 即 `abort()`；工具层经 `ToolContext` 获取同一实例（桥接定义在维度 17 工具接线处，`agent-tools` 不新增类型）：

```rust
//! crates/conex-browser/src/collab/coordinator.rs

/// AI 动作序列上下文（引擎装配；seq_abort 与各动作共享同一 Arc 标志）
pub struct ActionSequence {
    pub seq_id: String,
    pub holder: TokenHolder,               // §3 acquire 结果
    pub seq_abort: AbortToken,             // 复用 agent-tools 既有类型
    pub current_action: Mutex<Option<ActionAbort>>,
    pub pending_tools: Mutex<Vec<ToolCallId>>,   // 队列中未派发工具调用
}

/// 动作级中止句柄：每动作从 seq_abort clone（同一标志，幂等共享）
#[derive(Clone)]
pub struct ActionAbort {
    pub action_id: u64,
    pub abort: AbortToken,
    pub pending_commands: Arc<Mutex<Vec<CommandCancelHandle>>>, // 在途 CDP 命令
}
```

接线路径：

1. **引擎装配**：会话启动时 `ToolContext.abort_token` 由 session-loop 注入的**会话级**令牌保持不变（既有机制不动）；`CollaborationToken.abort` 即此同一实例（M-2，§3.1）；AI 动作序列启动时，引擎把 `seq_abort` 挂到动作执行上下文（维度 14 动作执行器读取），`browser_*` 工具执行期间自查 `ctx.abort_token.is_aborted()`——与 shell 等既有工具的中止语义完全一致。
2. **吊销接线**：`revoke()` 返回被吊销序列 → 对该序列 `seq_abort.abort()`（幂等）→ 级联触发所有在途动作与工具调用自查退出。
3. **审批等待期**：browser 交互类工具走审批（维度 17），审批等待期间复用既有「审批等待期支持 abort_token 取消」接线（context.rs 文档注释已述），吊销可中断审批弹窗等待。

### 4.2 在途 CDP 命令的中止实现（request cancel）

CDP 无原生通用 cancel；在维度 11 统一发送层（命令全过自研发送层，D-4）上扩展取消面：

```rust
//! crates/conex-browser/src/cdp/cancel.rs —— 发送层取消扩展（维度 11 发送层内部）

/// 命令取消句柄：发送层为每条在途命令登记
pub struct CommandCancelHandle {
    pub request_id: u64,        // 发送层自增；响应按 request_id 匹配
    pub domain: CdpDomain,      // 取消失败时的域级善后判定
    pub cancel: tokio_util::sync::CancellationToken, // 或等价（自研 Notify 亦可）
}

/// 发送层取消协议：
/// 1) cancel() → 该请求 future 立即 resolve 为 Err(CdpError::Aborted{request_id})
/// 2) 迟到响应：响应到达时按 request_id 查在途表，已被取消则丢弃（不 resolve 任何等待者）
/// 3) 域级善后（可撤销项）：
///    - Input.dispatchKeyEvent 分块序列 → 取消后续分块（type 分块 50 字符/12ms，维度 14 §4.1 TYPE_CHUNK_SIZE/TYPE_CHUNK_DELAY_MS，R-4）
///    - Input.dispatchMouseEvent 序列（down/move/up）→ 若未发出 up，补发 Input.dispatchMouseEvent
///      type=releasedAtViewport 归还鼠标（防「卡死按下」残留状态）
///    - Page.startScreencast / 帧流 → 不取消（只读，随标签切换管理，维度 12）
///    - Page.navigate / 表单提交 → 不可撤销（已发即执行）；仅标记版本推进，重快照兜底（§5.3 边界声明）
/// 4) 兜底：cancel 后 ABORT_GRACE=300ms 内响应未达，从在途表强制摘除（无泄漏）
pub struct CommandCanceller { /* 在途表: Mutex<HashMap<u64, CommandCancelHandle>> */ }
```

竞态处理：

- **abort 与命令完成同时发生**：`CancellationToken` 判定先到者；命令已完成（响应已归位）则取消为空操作；取消先行则丢弃迟到响应。两者都幂等。
- **多命令并发**：一个动作可并发多条命令（如 scroll 期间等待网络空闲），取消作用于动作登记的全部句柄。
- **等待原语**：`wait_for`（维度 14）内部等待器与 `seq_abort` 一起进入 `tokio::select!`，吊销即唤醒返回 `Aborted`。

### 4.3 中止后状态清理

| 清理项 | 动作 |
|---|---|
| 在途命令表 | cancel 或超时后摘除（ABORT_GRACE） |
| 输入分块队列 | type 的未发 chunk 全部丢弃 |
| 等待器 | wait_for / 网络空闲等待器统一唤醒返回 Aborted |
| 动作结果 | 记为 `ActionOutcome::Aborted{reason}`——**不计入 3 次总上限**（R-8：Aborted/Stale（用户接管吊销）不计入；版本失效/节点过期重试**计入**——与维度 14 §5 错误分类显式区分，Aborted 属外部原因、不进重试状态机） |
| 工具层 | browser 工具返回结构化错误 `browser.aborted`（code 语义对齐 `subagent.nesting_denied` 的结构化先例），文案「动作被用户接管中止」 |
| 队列 | `pending_tools` 中未派发调用标记丢弃（不执行、不返回） |
| 指示条 | 状态切换由 §6 状态机统一驱动 |

## 5. snapshotVersion 协同（感知失效）

### 5.1 版本推进事件清单

snapshotVersion 内建于维度 11 事件总线（S1 即内建，非后补——敲定裁决）。本维度定义**推进规则**；**推进规则单一权威 = 维度 11 §5.4 判定清单，下表为镜像，差异以 11 为准（R-1）**。版本按标签独立计数（`TabContext.version`，R-1 per-tab）；会话级辅助 `global_epoch` 用于跨标签事件（重连/崩溃重启跳变，11 §5.4 #9）。

| 事件（维度 11 事件总线） | 推进条件 | 节流/聚合 |
|---|---|---|
| `Page.frameNavigated` | 主帧 URL 变更 | 即时 +1（同帧内合并） |
| `Page.loadEventFired` | 主帧加载完成 | 合并窗口 +1（通常被 navigation 推进覆盖；重连恢复场景兜底「页面就绪」，11 §5.4 #5） |
| `DOM.documentUpdated` | 整文档重写（含 SPA 路由替换） | 200ms 聚合（`VERSION_BUMP_COALESCE`） |
| 用户输入注入成功（CDP Input.dispatch* 已发出，§3.4 ⑨） | 恒推进（用户操作可能改变页面） | **即时 +1**（U-1 撤销聚合窗；`bump(tab_id, InputInjected)`，维度 12 §4.2 落地点） |
| AI 动作执行成功（click/type/scroll/drag 等） | 恒推进 | **即时 +1**（动作管线 `bump(tab_id, ActionDone)`，无聚合窗，U-1） |
| 布局变化（视图尺寸/元素几何变化，维度 13 增量快照对比检出） | 检出即推进 | 归入 DOM 合并窗口（200ms，11 §5.4 #3） |
| `Page.javascriptDialogOpening` / 对话框关闭 | 恒推进 | 立即 |
| 纯样式/动画变化（未引起几何与内容变化） | **不推进** | —— |
| `Console` / `PageError` / 网络请求事件 | **不推进** | ——（脚本/网络活动不改变已渲染文档结构，11 §5.4 #12） |
| 滚动动作（用户 wheel / AI scroll） | **不推进** | ——（滚动后的 DOM 变化由 DOM 事件推进兜底，11 §5.4 #13） |

推进实现（维度 11 §5.4/§8，单一权威——本维度只定义推进规则，调用统一走版本面接口）：`bump(tab_id, reason: VersionReason)` → 目标标签版本 +1（per-tab，R-1）；仅 DOM 类事件经 `VERSION_BUMP_COALESCE`=200ms 合并窗内合并为一次 bump（防高频 DOM 事件风暴）；**用户输入注入 / AI 动作执行即时 +1，无聚合窗（U-1）**；bump 后广播 `VersionAdvanced{tab_id, from, to, reason}`（维度 11 §5.1）。

**口径声明**：版本推进是「可能已变化」的粗信号，宁多勿漏（保守）；精确判定由维度 13 快照对比完成。bump 只读廉价计数，不作为重快照的直接触发器——重快照只在 AI 需要动作时才发生（惰性），避免无谓开销。

### 5.2 AI 动作前校验接口

```rust
//! crates/conex-browser/src/collab/coordinator.rs（browser 工具经注入服务调用）
//! 版本面接口以维度 11 §8 为唯一契约：snapshot_version(tab_id) / validate_snapshot(tab_id, version) / bump(tab_id, reason)（R-1）

/// 版本失效错误：期望版本 ≠ 目标标签当前版本（携带当前/期望版本，供诊断与重快照）
pub struct Stale { pub current: u64, pub expected: u64 }

/// 校验：期望版本 == 目标标签当前版本 → Ok(())；否则 Err(Stale)
/// 签名统一：validate_snapshot(tab_id, version) -> Result<(), Stale>（维度 13/14/15 共用，R-1）
pub fn validate_snapshot(&self, tab_id: &TabId, version: u64) -> Result<(), Stale>;
```

消费面（维度 14 动作执行器在派发 CDP 命令**之前**调用；令牌获取发生在**工具层入口（协同层，早于执行流水线，T-8）**，执行流水线内部顺序（门禁 → 版本 → abort → 定位 → 派发 → 后置复核 → 审计）以维度 14 为准，本维度不描述流水线内部顺序）：

- 交互类动作（click/type/scroll/hover/drag/select_option/upload）携带快照索引与 `snapshotVersion` 入参（维度 13 快照格式内建字段）→ 校验。
- 感知类（wait_for 的元素/文本条件）→ 校验；stale 时直接重快照再评估。
- 导航类（navigate/back/forward/reload）→ 不校验版本（导航自身推进版本，结果语义由返回值承载）。
- `evaluate`（受限白名单，维度 17）→ 校验（脚本可能依赖 DOM 状态）。
- **版本重置处理（U-2）**：收到 `bus::VersionReset`（重连/崩溃重启：全标签 +1000、`global_epoch`+1，维度 11 §5.4 #9；或版本跟踪器自身 Lagged 触发重对齐）后，校验侧旧版本**一律 Stale** → 走重快照后再执行；跟踪器自身 Lagged 场景写 `bus::lagged_recovery` 断言（维度 11 §5.2）。

### 5.3 失效后重快照流程

```
动作校验 → Err(Stale{current, expected})
      │
      ▼
① 丢弃旧快照（维度 13：快照缓存按版本失效）
      │
② 重新快照（维度 13 snapshot 服务：DOM 简化树 + AX，预算 §7.3）
      │
③ 新快照携带新版本号 current；动作入参中的索引重解析（旧索引可能已漂移 → 按
   backendNodeId 重新定位；定位失败按维度 14 重试语义处理）
      │
④ 重新校验（版本已一致）→ 派发动作
      │
⑤ 重试上限：版本失效/节点过期连续重拍 **计入** 3 次总上限（与维度 14 §5.3 共用
   attempt 上限，防无限循环，R-8）；Aborted/Stale（用户接管吊销）**不计入**
   （用户已接管，不再自动重试）
```

**边界声明（不可逆变更）**：AI 已发出的 `Page.navigate`、表单提交、已注入的按键等不可撤回（§4.2 域级善后无法撤销的项）；此时版本已推进、用户看到的页面已变化，兜底手段是「重快照 + AI 从新状态继续」，不存在回滚。此边界写入维度 14 动作原语文档与用户可见文案（指示条提示「页面已由操作改变」场景）。

## 6. 接管 / 暂停状态机（指示条）

### 6.1 状态与事件定义

```rust
//! crates/conex-browser/src/collab/state_machine.rs —— 纯函数状态机（可独立单测）

/// 指示条状态（前端渲染归维度 12；本模块只定义语义与迁移）
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize)]
pub enum PanelState {
    /// 空闲：无 AI 操作，无接管
    Idle,
    /// AI 正在操作（令牌被持有）
    AiBusy,
    /// 已暂停：AI 队列挂起（显式暂停按钮），无在途动作
    Paused,
    /// 用户接管中：吊销已生效，AI 已中止，等待稳定窗
    UserTakingOver,
}

/// 状态机输入事件
#[derive(Debug, Clone)]
pub enum StateEvent {
    /// 令牌获取成功（AI 开始动作序列）
    AiAcquired,
    /// 令牌释放（序列自然结束）
    AiReleased,
    /// 用户交互（§3.4 吊销链）
    UserInteraction,
    /// 用户点击「暂停」按钮
    PausePressed,
    /// 用户点击「继续」按钮
    ResumePressed,
    /// 稳定窗结束（用户停止交互 ≥ TOKEN_MIN_STABLE_WINDOW）
    StableWindowElapsed,
    /// 会话结束 / 急停
    SessionEnd,
}
```

### 6.2 转换规则表

| 当前状态 | 事件 | 次态 | 副作用（引擎执行） |
|---|---|---|---|
| Idle | AiAcquired | AiBusy | 指示条「AI 正在操作」；开始帧/事件高亮（维度 12） |
| Idle | PausePressed | Paused | 指示条「已暂停」 |
| AiBusy | AiReleased | Idle | 指示条消失 |
| AiBusy | UserInteraction | UserTakingOver | 完整吊销链（§3.4 ③-⑧） |
| AiBusy | PausePressed | Paused | 挂起队列（§6.3）；**不吊销**：在途动作自然完成后进入 Paused |
| AiBusy | SessionEnd | Idle | 吊销链（SessionEnd 源） |
| UserTakingOver | UserInteraction | UserTakingOver | 稳定窗重置（保持接管） |
| UserTakingOver | StableWindowElapsed | Idle | AI 可重新 acquire（未主动 acquire 则保持 Idle） |
| UserTakingOver | ResumePressed | Idle | 同 StableWindowElapsed（用户显式放行） |
| UserTakingOver | SessionEnd | Idle | —— |
| Paused | ResumePressed | Idle | 放行队列（AI 重新走 acquire；此时稳定窗已过，通常立即成功） |
| Paused | UserInteraction | UserTakingOver | 吊销链（残留队列丢弃） |
| Paused | SessionEnd | Idle | —— |

非法迁移（防御性：状态机实现为穷举 match，未列组合编译期拒绝）：

- AiBusy → 不可直接到 Idle（必须经 AiReleased）
- Paused → 不可直接到 AiBusy（挂起状态不自动恢复）
- 任意态 → AiBusy 只允许从 Idle 出发（acquire 语义保证）

状态机为纯函数 `fn transition(state: PanelState, ev: StateEvent) -> PanelState`，副作用由 coordinator 在迁移确认后执行（模型-视图分离，单测友好）。

**接管过渡时长（U-9）**：`UserTakingOver` → `Idle` 的过渡时长 = `TOKEN_MIN_STABLE_WINDOW`（**800ms**，统一常量——接管过渡与令牌稳定窗同源，撤销 1.5s 表述）；`StableWindowElapsed` 由「最近吊销时刻 + TOKEN_MIN_STABLE_WINDOW」计时器驱动，`ResumePressed` 可提前放行。

### 6.3 暂停时 AI 队列挂起实现

- **队列结构**：动作调度器为 `mpsc::Receiver<ToolCall>` + 独立 `pending` 列表（未派发调用）。
- **挂起**：PausePressed → 停止从队列取动作（调度循环进入 `paused` 分支，等待 `ResumePressed` 或 `UserInteraction`）；**在途动作不 abort**，自然完成后调度循环停在 paused（指示条文案「已暂停，剩余 N 个动作待执行」——N 实时回传前端）。
- **恢复**：ResumePressed → 调度循环重新取队列；队列动作执行前**重新校验令牌与快照**（暂停期间用户可能已操作——校验保证不基于过期状态执行）。
- **交互接管**：paused 中用户输入 → 走标准吊销链，队列丢弃。
- **与「接管」的区别**：暂停是优雅挂起（等在途完成、保留队列）；接管是立即中止（吊销在途、丢弃队列）。两者入口不同（按钮 vs 用户输入），行为不同（§6.2 两行）。

### 6.4 接管时吊销顺序（固定次序）

任务书裁决次序，代码固化（§3.4 ③-⑧）：

1. **先吊销在途**：`collab.revoke(source)`（清持有者、记时刻）→ `seq_abort.abort()` → 发送层 `cancel_pending`（request cancel + 域级善后）。物理层先停，杜绝「AI 仍在执行时用户输入注入」的副作用竞态。
2. **再通知工具层**：动作执行器收到 Aborted → 工具返回 `browser.aborted` 结构化错误 → LLM 得知被打断（可决定是否重试/询问用户）。
3. **最后前端指示**：`StateChanged{UserTakingOver}` 事件 → 指示条切换「已接管」。状态切换以吊销完成为前提，避免 UI 先亮「已接管」而动作仍在跑。

顺序依据：1 保安全（先停后说）、2 保一致（工具层拿到确定终态）、3 保体验（UI 反映的是已完成的接管）。

## 7. 多标签协同

### 7.1 标签上下文

```rust
//! crates/conex-browser/src/collab/tabs.rs

/// 单标签上下文（TabRegistry: HashMap<TabId, TabContext> 常驻）
pub struct TabContext {
    pub tab_id: TabId,
    pub target_id: String,               // CDP Target.targetId
    pub url: String,
    pub title: String,
    pub version: u64,                    // 本标签 snapshotVersion（§5.1 按标签独立）
    pub snapshot_cache: Option<Arc<Snapshot>>,   // 最近快照（缓存键 (tab_id, version)，预算 §7.3，T-14）
    pub nav_stack: Vec<String>,          // 本标签导航栈（上限 32，会话恢复展示用）
    pub created_at: Instant,
    pub active: bool,                    // 是否当前激活标签
}

/// 标签注册表：增删查 + 激活切换；上限/预算见 §7.3
pub struct TabRegistry { /* HashMap<TabId, TabContext>, active_tab: TabId */ }
```

隔离规则：

- **快照隔离**：版本与快照缓存按标签独立；标签 A 版本推进不影响标签 B 的动作（验收项 5）。
- **令牌**：令牌是会话级单例（§3.1），同一时刻只允许一个动作序列；「AI 操作焦点」= `active_tab`。动作执行前双重校验：令牌有效 + 目标标签 == active_tab（防止 AI 在后台标签滞留动作）。
- **事件订阅分摊**：仅激活标签全量订阅页面事件（导航/DOM/网络/控制台）；非激活标签只订阅 `Target` 生命周期与版本推进事件（降级订阅，内存与 CPU 预算的一部分，见 §7.3）。

### 7.2 标签切换时令牌迁移规则

| 场景 | 令牌/焦点迁移 | 理由 |
|---|---|---|
| AI 调 `switch_tab(target)`（工具） | 焦点迁移到 target；**不吊销**（AI 主动切换）；动作序列令牌保持；目标标签动作前按需重快照（其 version 独立） | AI 主动选择，无冲突 |
| 用户点击面板标签栏切换 | 视为用户交互 → **标准吊销链**（§3.4）：中止 AI 在途（AI 在旧标签的 type/wait_for 被中止） | 用户切走即表示放弃当前 AI 动作；避免「AI 在我没看的标签上操作」——多标签场景最安全默认 |
| 关闭标签（AI 工具或用户） | 若 AI 动作目标为该标签 → 等效吊销（中止在途）；关闭后 TabContext 移除 | 目标消失 |
| 新建标签 | version=0、无快照缓存；不触发任何吊销 | 无冲突 |

**硬性规则**：AI 只能在激活标签上执行动作（动作前校验 active_tab）；用户切换标签后 AI 必须重新 acquire + 重快照才能继续（LLM 从 `browser.aborted`/工具错误感知焦点变化）。

### 7.3 开放问题 4 裁决：标签上限与快照预算分摊

**裁决结论：`MAX_TABS = 8`（默认，配置范围 1-16）；快照预算按活跃性分摊（活跃全额 / 非活跃 25% + 惰性快照 + 总量 LRU）。**

| 参数 | 默认 | 语义 |
|---|---|---|
| `MAX_TABS` | **8**（可配 1-16） | 超限时 `new_tab` 返回结构化错误 `tab.limit_exceeded{max: 8}`，提示关闭标签 |
| `INACTIVE_BUDGET_FACTOR` | **0.25** | 非激活标签快照预算 = 活跃预算 × 0.25 |
| `SNAPSHOT_CACHE_TOTAL` | **8MB** | 全会话快照缓存总量上限；**缓存键 = (tab_id, version)**（对齐 13 M-6），超限按缓存条目 (tab_id, version) LRU 逐出，版本**防回退断言**（缓存版本只进不退，T-14） |
| 事件订阅 | 活跃全量 / 非活跃降级 | 见 §7.1 |

裁决依据：

1. **上限 8 的理由**：每个标签常驻 CDP Target 会话、事件监听器、快照缓存，无上限导致会话数与内存无界增长。8 覆盖典型协同任务（多来源调研 3-5、电商比价 3-4、对照编辑 2），且 8 是浏览器标签栏一屏内自然可见数量；1-16 可配覆盖极端需求，16 以上不开放（超出即触顶）。
2. **预算分摊的量化**：设活跃预算 = 维度 13 单页预算（**max_selector_indices=500 / 序列化输出预算 32KB**，T-13 对齐 13 裁决值，撤销 2000 交互元素 / 512KB 示例；参数归维度 13 定，本维度只定分摊规则）。最坏 8 标签时总预算 ≈ 1 + 7 × 0.25 = **2.75 个单位**（活跃标签 + 7 个非活跃），总量可控；快照缓存总量 8MB 硬顶 + **(tab_id, version) LRU 逐出**（T-14，撤销 last_active_at 依据）+ 版本防回退断言，保证任意时刻内存有界。
3. **惰性快照**：非活跃标签不主动快照，仅在切回时按需重拍（版本失效即重拍）；非活跃快照仅保留首屏可见交互元素（预算 25% 的含义）。
4. **screencast 帧流**（维度 12）：仅激活标签订阅帧流；切换时停止旧标签帧流、启动新标签帧流，帧内存恒定一份。

## 8. 会话恢复

### 8.1 profile 持久化开关（用户显式选择）

- **默认临时**：受管 profile 为会话级临时目录（维度 10 语义），会话结束用完即删。
- **持久化开关**：用户显式选择（两处入口：面板设置项「保留此会话的浏览器数据」+ 关闭面板/退出应用时的首次询问弹窗）。开启后：
  - profile 目录登记为持久 profile：`<data_dir>/browser-profiles/<profile_name>/`（profile_name 由用户输入或自动生成，校验规则对齐 reference agent-browser 的会话名校验思路——`sanitize_session_component` 语义，禁止路径分隔符与非法字符，防目录穿越）；
  - 会话删除仅移除会话状态，不删持久 profile；用户可在设置中显式「删除已保存的浏览器数据」。
- 开关状态写入 `panel-state.json`（与 profile 同生命周期，§8.2），重启读取。

### 8.2 面板状态序列化

```rust
//! crates/conex-browser/src/collab/restore.rs

/// 面板状态快照：与 profile 同生命周期落盘
/// 路径：<data_dir>/browser-profiles/<profile_name>/panel-state.json
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct PanelStateSnapshot {
    /// 序列化格式版本（当前 = 1；格式变更时递增并保留旧版解析器回退）
    pub format_version: u32,
    /// profile 名（目录名）
    pub profile_name: String,
    /// 用户是否显式选择保留数据
    pub persistent: bool,
    /// 标签状态列表（顺序 = 标签栏顺序）
    pub tabs: Vec<TabState>,
    /// 激活标签序号（索引进 tabs）
    pub active_tab: u32,
    /// 写入时刻
    pub saved_at: SystemTime,
}

/// 单标签状态（只序列化可重建信息，不落盘 DOM/快照/令牌等运行期状态）
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct TabState {
    pub url: String,
    pub title: Option<String>,
    /// 导航栈（仅展示用途；恢复时只恢复当前 URL，见 §8.3）
    pub nav_stack: Vec<String>,
}
```

写时机与节流：标签增删、URL 变更、激活切换之后，**500ms 防抖**写入（`PANEL_STATE_WRITE_DEBOUNCE`）；写入失败仅记日志不阻塞（状态可再生成，非关键路径）。

**序列化范围裁决**：只序列化「URL + 标签顺序 + 激活位」最小集，不序列化快照、令牌、事件订阅等运行期状态——恢复后这些一律从零重建（version=0、Idle 态），避免序列化版本漂移带来的复杂迁移面。

### 8.3 恢复流程与失败回退

```
引擎启动 → 检测 <data_dir>/browser-profiles/ 下持久 profile
  │
  ├─ 无持久 profile → 全新临时 profile（常规启动路径）
  │
  └─ 有持久 profile：
       ① 读 panel-state.json（失败 → 回退 C）
       ② 以该 profile 目录启动浏览器进程（复用维度 10 启动管线）
       ③ 依次 Target.createTarget 打开每个标签的当前 URL
          （历史栈不重建——CDP 无法重建会话历史，仅展示用 nav_stack）
       ④ 激活恢复的 active_tab → 帧流重连（维度 12）→ 惰性重快照
       ⑤ 恢复完成事件 → 面板展示「已恢复 N 个标签」
```

| 失败点 | 回退策略 |
|---|---|
| profile 目录不存在/为空 | 新建临时 profile（视同无持久化） |
| panel-state.json 缺失/解析失败/format_version 不兼容 | 仅恢复 profile 数据（cookie/登录态），空标签面板；提示「标签状态未能恢复」 |
| 浏览器进程启动失败（浏览器升级后 profile 不兼容等） | 回退新建临时 profile，数据丢失提示（对齐维度 16 导入的 App-Bound 回读失败引导文案风格） |
| 单个标签 URL 打开失败（站点失效） | 跳过该标签，其余继续；面板标记失败标签 |

**恢复后协同状态**：令牌 Idle、version 全标签归零、无在途动作；AI 恢复操作前照常 acquire + 快照（无特殊分支）。崩溃重启（P0-6）走同一恢复管线（维度 10 崩溃重启保留导航栈与本流程合一）。

## 9. 验收标准（协同 e2e 清单 + 单测）

### 9.1 协同 e2e 清单（S8 阶段门禁，08 §5 S8 展开）

| # | 用例 | 步骤 | 通过断言 |
|---|---|---|---|
| 1 | AI 操作可见 | AI 调 navigate + click；面板观察 | 帧流（维度 12 screencast）内 ≤120ms（P0-2 基准）可见页面变化；指示条全程 ai-busy |
| 2 | 用户交互中断 AI | AI 正在 type 分块；用户点击面板另一处 | ≤300ms 内后续 chunk 不再注入（页面无残留输入）；指示条 user-taking-over；工具返回 `browser.aborted`；Aborted（用户接管吊销）不计入重试额度（R-8） |
| 3 | 稳定窗去抖 | 用户连续滚动 ≥2s，AI 并发尝试重获 | 滚动期间 acquire 等待（不成功）；停止 800ms 后 acquire 成功；期间无「抢回-打断」振荡（审计计数断言） |
| 4 | 版本失效重快照 | AI 快照后用户改动页面 → AI 用旧快照索引 click | 返回 Err(Stale) → 自动重快照 → 新索引重试成功；版本失效重试计入 3 次总上限（R-8，与维度 14 共用） |
| 5 | 多标签隔离 | tabA 版本被用户改动；AI 在 tabB 执行动作；AI 操作 tabA 时用户切 tabB | tabB 动作不因 tabA 失效受影响；用户切换 → tabA 在途中止、AI 不得在非激活标签执行 |
| 6 | 会话恢复（持久化开） | 开启持久化 → 操作（含登录态）→ 重启应用 | 标签列表/当前 URL/激活标签恢复；cookie/登录态保留（维度 16 回读校验联动） |
| 7 | 会话恢复（持久化关） | 默认临时 profile → 重启 | 全新空白会话，无旧标签/profile 数据残留 |
| 8 | 暂停/恢复 | AI 队列 5 个动作，第 2 个时点暂停 | 在途动作自然完成，后续 3 个挂起（指示「剩余 3」）；恢复后从挂起点继续（重新校验令牌/快照） |
| 9 | 标签上限 | 打开第 9 个标签 | `new_tab` 返回 `tab.limit_exceeded{max: 8}`；关闭一个后可再开 |
| 10 | 急停 | 全局急停（维度 17） | 吊销链全路径（abort + cancel + 状态 Idle）在 300ms 内完成 |

## 10. 风险与预案

| 风险 | 等级 | 预案 |
|---|---|---|
| 用户高频输入致 AI 饿死（永远等不到稳定窗） | 中 | `ACQUIRE_TIMEOUT=30s` 超时返回结构化错误，LLM 转而询问用户「是否暂停操作让我继续」；指示条提示用户可点「暂停」放行 |
| 不可逆命令（navigate/表单提交/已注入按键）无法撤回 | 中 | §4.2/§5.3 边界声明：版本推进 + 重快照兜底；type 分块 50 字符/12ms（维度 14 `TYPE_CHUNK_SIZE`/`TYPE_CHUNK_DELAY_MS`，R-4）限制单次冲击 + 分块间 abort 检查；指示条在接管场景提示「已发出的操作可能已完成」 |
| abort 与命令完成竞态 | 低 | 幂等 abort（既有 AbortToken 语义）+ request_id 匹配丢弃迟到响应 + ABORT_GRACE 兜底摘除 |
| 多标签资源失控 | 中 | MAX_TABS=8 + 预算分摊（2.75 单位）+ 8MB LRU + 非活跃标签事件降级订阅 |
| 持久 profile 损坏 / 浏览器升级不兼容 | 中 | §8.3 三级回退：先保 profile 数据、再保标签、最后全新临时 profile + 用户提示 |
| 吊销链中面板事件风暴（拖拽连续 pointermove） | 低 | revoke 幂等 + 吊销审计 200ms 聚合；稳定窗由 last_revoke 驱动天然去抖 |
| 状态机与吊销链并发错序（指示先于中止） | 低 | §6.4 次序固化（先吊销→再工具层→后指示）+ 状态机纯函数 + coordinator 单线程化吊销链执行（同一 executor 内顺序执行，无并发分叉） |
