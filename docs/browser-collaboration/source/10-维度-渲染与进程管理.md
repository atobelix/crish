## 1. 职责边界与本维度交付物

本维度只负责「把浏览器进程可靠地拉起来、管住、收掉」；CDP 协议收发、screencast 帧流、输入注入、快照等由维度 11/12/13 承载，本维度仅提供两个衔接点：

1. **`CdpEndpoint`（端口 + WS path）**——启动成功后交给维度 11 的 CDP 客户端建连；
2. **`BrowserState` 事件流**——状态迁移向引擎事件总线广播（维度 11 总线），供面板与工具层消费。

交付物（全部在 `crates/conex-browser` 内，本维度对应 `process/` 子模块）：

```
crates/conex-browser/
├── Cargo.toml                      # 新增 workspace member；tokio + serde + uuid + dirs
└── src/
    ├── lib.rs                      # 对外门面：BrowserManager::start/stop/status/restart
    ├── process/
    │   ├── mod.rs                  # 状态机 + 主调度（launching/running/crashed/stopping/stopped）
    │   ├── discover.rs             # 二进制发现与选择（CfT 缓存 → 系统 Chrome → Edge）
    │   ├── cft.rs                  # Chrome for Testing 下载/解压/版本缓存（离线可跳过）
    │   ├── args.rs                 # 启动参数构建（纯函数，单测友好）
    │   ├── profile.rs              # profile 目录管理：临时/导入/复制/清理/互斥
    │   ├── active_port.rs          # DevToolsActivePort 轮询/解析/校验
    │   ├── nav_stack.rs            # 导航栈（标签 URL 列表）快照与恢复
    │   ├── endpoint.rs             # CdpEndpoint + SessionToken（Debug 脱敏）
    │   └── platform/
    │       ├── mod.rs              # ProcessTreeKiller / 窗口策略 / 路径表 trait
    │       ├── windows.rs          # Job Object 杀树 + 离屏窗口参数
    │       ├── macos.rs            # 杀组 + 离屏窗口参数
    │       └── linux.rs            # 杀组 + DISPLAY 探测 / headless 回退
    └── events.rs                   # BrowserStateChanged / CrashRestarting / NavStackChanged
```

依赖红线：CDP 域库一律不引（薄客户端属维度 11）；进程管理侧仅 `tokio`、`serde`、`uuid`、`dirs`、`thiserror`、`tracing`（日志），Windows 平台侧按需加 `windows-sys`（Job Object）。

## 2. 二进制发现与选择

### 2.1 优先级与总体流程

```
resolve_backend() -> BackendResolution
  1. CfT 缓存目录存在可用二进制        → Backend::ChromeForTesting { version, path }
  2. （首次使用且用户同意）惰性下载 CfT → Backend::ChromeForTesting   # 见 §2.2
  3. 系统 Chrome                      → Backend::SystemChrome(path)   # 见 §2.3 路径表
  4. 系统 Edge                        → Backend::SystemEdge(path)
  5. 全部失败                          → Err(BrowserError::NoBrowser)  # 带 doctor 诊断清单
```

- 解析结果与来源（provenance）写入 `LaunchReport`，随 `browser://state-changed` 事件上抛（供 telemetry 与排障），版本号启动后经 CDP `Browser.getVersion` 实测回填。
- **选择结果缓存**：同一次引擎进程生命周期内只解析一次（进程内存缓存）；用户显式「刷新检测」或需要不同版本时才重新解析。
- CfT 下载属于**惰性按需**：仅在发现系统无 CfT 缓存且用户接受下载时才联网（面板内提示，对齐 04 文档「首次使用 AI 浏览器时提示安装」）；离线环境直接跳回退链（第 3/4 步），不阻塞启动。

### 2.2 CfT 下载/缓存/版本策略

版本真源（与 agent-browser install.rs:8 同源）：

```
https://googlechromelabs.github.io/chrome-for-testing/last-known-good-versions-with-downloads.json
```

| 项 | 策略 | 说明 |
|---|---|---|
| 版本选择 | `channels.Stable.version`（last-known-good） | 确定性版本，钉死可审计；CfT 无自动更新，升级节奏由我方发布控制（04 文档 §1 论证） |
| 平台键 | win64 / mac-arm64 / mac-x64 / linux64（`cfg!(target_os)+target_arch` 映射） | Linux arm64 无官方构建：直接报错并引导系统 chromium（agent-browser install.rs:401-411 同款） |
| 缓存布局 | `<data_root>/conex/browser/browsers/chrome-<version>/`，解压即目录版本化 | 版本目录并存，升级不破坏旧版；统一根见 §4.1（R-2） |
| 解压 | zip 流式解压；顶部 `chrome-<platform>/` 前缀剥离；`enclosed_name()` 路径穿越防护 + `starts_with(dest)` 校验 | 移植 install.rs:335-398，含 unix 权限位回写 |
| 下载重试 | 3 次，退避 1s/2s；仅对连接失败/超时/5xx 重试，4xx 立即失败 | 移植 install.rs:248-333；进度上报给面板 |
| 已安装判定 | 二进制存在即视为已装（不校验 hash，CfT CDN 走 HTTPS） | 校验启动后 `Browser.getVersion` 实测兜底 |
| 残留清理 | 下载/解压失败即 `remove_dir_all` 目标版本目录 | 移植 install.rs:493 |
| 损坏自愈 | 启动时 `Browser.getVersion` 失败或二进制无法 spawn → 标记损坏 → 重新下载 | 仅在系统无回退二进制时触发 |

二进制路径（解压后）：

| 平台 | 路径 |
|---|---|
| Windows | `chrome-win64/chrome.exe` |
| macOS | `chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing`（x64 同理） |
| Linux | `chrome-linux64/chrome` |

### 2.3 系统 Chrome/Edge 探测路径表

按顺序探测，存在即取（`Path::is_file()` 判断；Windows 附加 `env LOCALAPPDATA` 展开）：

| 平台 | Chrome | Edge | 备注 |
|---|---|---|---|
| Windows | `%LOCALAPPDATA%\Google\Chrome\Application\chrome.exe`<br>`C:\Program Files\Google\Chrome\Application\chrome.exe`<br>`C:\Program Files (x86)\Google\Chrome\Application\chrome.exe` | `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`<br>`C:\Program Files\Microsoft\Edge\Application\msedge.exe`<br>`%LOCALAPPDATA%\Microsoft\Edge\Application\msedge.exe` | LOCALAPPDATA 优先（用户级安装不依赖 Program Files 权限） |
| macOS | `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`<br>`/Applications/Google Chrome Canary.app/.../Google Chrome Canary` | `/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge` | 逐项 exists 判断 |
| Linux | `google-chrome`、`google-chrome-stable`、`chromium-browser`、`chromium`（`which` 解析） | `microsoft-edge`、`microsoft-edge-stable` | 参考 agent-browser chrome.rs:885-905；chromium 列最后（协议漂移面最大） |

Edge 与 Chrome 同 Chromium 内核，参数集完全兼容；仅 CDP 域细节差异（如 `msedge:` 地址栏语义）留待维度 11 能力探测收敛。

### 2.4 失败回退与诊断

- 回退链任何一步失败都**继续往下走**，最终全失败时汇总错误：已检查的路径清单 + 是否有 CfT 缓存但二进制损坏 + 网络可用性（本维度只做一次轻量连通探测，不深挖）+ 引导文案（面板提示下载/指定可执行文件）。
- `BrowserError::NoBrowser` 携带 `Vec<CandidateProbe>`（每项：路径/来源 + 失败原因），供前端渲染「doctor」卡片。
- 系统浏览器回退时的显式声明：进程模块记录 provenance=SystemChrome/SystemEdge，维度 17 安全门禁可据此做差异策略（可选，默认同权）。

## 3. 启动参数集

### 3.1 默认模式：headless=new（主路径）

D-2 已裁决「面板输入转发是协同闭环必要条件、独立窗口直操否决」——**有可见窗口就存在用户绕过 CDP 直接操作的风险**（Alt-Tab 弹出、任务栏点击）。因此默认引擎模式为 `--headless=new`：无窗口即零直操面、三平台行为一致、screencast/Input/Profile 全链路可用（agent-browser 全链路 headless 验证过的组合）。「保持窗口激活」在本模式下的语义 = 渲染不被后台化（§3.1 参数表第 11/12 行保证合成持续输出帧）。

### 3.2 参数表（headless=new 主路径全量）

构建为纯函数 `build_args(config: &LaunchConfig) -> Vec<String>`（args.rs，单测直测）。**每个 `--enable-features` 只允许出现一次**（Chrome 仅认最后一个同名开关，agent-browser chrome.rs:378-405 先例），所有 feature 合并进单条开关。

| # | 参数 | 用途 | 取舍说明 |
|---|---|---|---|
| 1 | `--remote-debugging-port=0` | 随机端口（内核分配），杜绝固定 9222 可探测面 | D-9 硬要求；端口从 DevToolsActivePort 读取 |
| 2 | `--remote-debugging-address=127.0.0.1` | 显式 loopback 绑定 | Chrome 默认即 loopback，显式声明防未来默认值漂移（01 文档 line 229） |
| 3 | `--user-data-dir=<dir>` | 独立 profile（会话级/导入），与用户日常浏览器完全隔离 | 本维度核心参数；目录管理见 §4 |
| 4 | `--headless=new` | 无窗口渲染 | 主路径；headed 离屏为配置项（§3.4） |
| 5 | `--window-size=<W>,<H>` | 初始视口 = 面板尺寸，保证 screencast 宽高比一致 | 启动时由 LaunchConfig.viewport 注入；后续面板 resize 走 CDP `Emulation.setDeviceMetricsOverride`（维度 12） |
| 6 | `--no-first-run` | 跳过首次运行向导/欢迎页 | 防 Profile 初始化弹窗阻塞 |
| 7 | `--no-default-browser-check` | 不提示设为默认浏览器 | 弹窗零容忍 |
| 8 | `--disable-background-networking` | 抑制后台网络（遥测/预取等非业务流量） | 收敛出网面（04 文档 §3） |
| 9 | `--disable-component-update` | 禁用组件自动更新 | 防运行中组件漂移 |
| 10 | `--disable-sync` | 禁用账号同步 | profile 隔离 + 防凭据外流 |
| 11 | `--disable-backgrounding-occluded-windows` | 窗口被遮挡/隐藏时渲染不停 | **screencast 帧连续性依赖**（headless 下无害，headed 离屏模式必需） |
| 12 | `--disable-renderer-backgrounding` | 后台标签页 renderer 不降级挂起 | 多标签协同 wait_for/计时器可靠性 |
| 13 | `--disable-hang-monitor` | 不因「挂起」判定自动杀 renderer | 自动化场景避免误杀 |
| 14 | `--disable-prompt-on-repost` | 表单重提交确认框不出现 | 防对话框阻塞动作链（对话框另由 CDP Page 域拦截兜底） |
| 15 | `--disable-popup-blocking` | 允许 window.open 弹窗 | 登录跳转/SSO 弹窗流依赖；弹窗由 CDP `Page.setWindowOpenHandler` 收口为标签页（维度 11） |
| 16 | `--disable-extensions` | 默认不载扩展 | 最小权限（01 文档 line 235）；导入 profile 需扩展时另行显式 `--load-extension` + 审批 |
| 17 | `--disable-default-apps` | 不自动注册默认应用 | 收敛副作用 |
| 18 | `--metrics-recording-only` | 遥测只记录不上传 | 对齐 04 文档 |
| 19 | `--hide-crash-restore-bubble` | 崩溃重启不弹「恢复页面」气泡 | **崩溃自动重启 UX 必需**（chrome-devtools-mcp browser.ts:207 同款） |
| 20 | `--disable-features=Translate` | 关翻译提示 | 降噪；可移除 |
| 21 | `--enable-features=<合并列表>` | feature 单开关合并 | 本维度预设空；由维度 12/14 按需追加（合并规则不变） |

### 3.3 环境自适应（默认不做降级开关）

| 参数 | 触发条件 | 说明 |
|---|---|---|
| `--no-sandbox` | 仅 `CI` 环境变量 / unix euid=0 / docker、podman、cgroup 容器特征 | 移植 chrome.rs:1330-1367；**桌面首发场景默认不加** |
| `--disable-dev-shm-usage` | 同上容器判定 | 移植 chrome.rs:1372-1397 |
| `--enable-unsafe-swiftshader` | headless 模式恒定追加 | 无 GPU 环境防静默崩溃（agent-browser chrome.rs:463）；**归类「渲染兼容参数，非安全降级开关」**，与 08 §3.1「不做降级安全开关」不冲突，防后续维护误删（评审 20-10-5） |
| `--headless=new` → headed 回退 | Linux 有 DISPLAY 且配置要求 headed 时 | 见 §3.4 |

### 3.4 明确不用的参数（红线，构建函数单测断言「永不包含」）

| 参数 | 不使用理由 |
|---|---|
| `--enable-automation` | 自动化痕迹特征本体：会置 `navigator.webdriver=true` 并弹「受自动化软件控制」提示。我们以裸参数启动 + 自研 CDP 客户端，WebDriver 语义完全不需要 |
| `--remote-allow-origins=*` | D-9 明示不引入（04 文档 line 100）；我方 WS 客户端（tokio-tungstenite）不发送 Origin 头，Chrome 对无 Origin 的 loopback 握手默认放行，无需通配 |
| `--ignore-certificate-errors` | 降级安全开关，明确不做（08 文档 §3.1） |
| `--allow-file-access-from-files` / `--disable-web-security` | 同属降级开关 |
| `--load-extension`（默认） | 扩展零加载；导入 profile 场景经审批后显式追加 |
| `--start-maximized` | 视口尺寸由面板决定，最大化不可控 |
| `--restore-last-session` | 崩溃重启的导航栈由**我们自己管理**（§6.4），不信任 Chrome 会话恢复 |
| 固定端口 `--remote-debugging-port=9222/9242` | D-9 否决固定端口 |
| `--use-fake-ui-for-media-stream` / `--disable-notifications` 类 | 媒体/通知权限交给 CDP `Browser.grantPermissions` 显式管理（维度 17），不用全局降级开关 |

### 3.5 headed 离屏模式（配置项，Windows 首发可用）

当需要更高保真渲染（罕见站点兼容/DRM/WebGL 合成差异）时切换：

- 参数在 §3.2 基础上：去掉 `--headless=new`，追加 `--window-position=-32000,-32000`（离屏定位，Selenium 系成熟做法）+ `--window-size=<W>,<H>`；`--disable-backgrounding-occluded-windows` 保证离屏窗口持续合成 screencast 帧。
- 已知取舍（文档化）：离屏窗口在任务栏/Alt-Tab 可能残留入口，存在用户绕过面板直操的残余面；与 D-2 冲突面最小化需配合面板提示。此模式默认关闭，由产品配置显式开启。
- Linux 无 `DISPLAY` 环境（ssh/CI）强制 headless（不做 Xvfb 依赖，降低运维面；agent-browser Xvfb 方案登记为后续可选）。

## 4. Profile 目录管理

### 4.1 目录布局（R-2 裁决为单一权威；全部位于用户私有数据根）

```
<data_root>/conex/browser/                # 统一根（应用目录名统一 conex，撤销 Crish 命名）
├── browsers/                             # CfT 二进制缓存：chrome-<version>/（§2.2）
├── sessions/<session-uuid>/              # 临时 profile（§4.2）：会话级，用完即删
│   ├── DevToolsActivePort                # Chrome 写入；ACL 随父目录
│   ├── nav_stack.json                    # 导航栈落盘（可选，§6.4）
│   ├── panel-state.json                  # 面板 UI 状态（标签/URL 序，纯 UI）
│   └── (Chrome 生成的 Default/、Cache/ 等)
└── managed/<profile_name>/               # 受管 profile（§4.3）：用户导入/持久化
    ├── profile_meta.json                 # persist 开关唯一存于此（撤销 panel-state.json 双源，R-2）
    ├── panel-state.json                  # 面板 UI 状态（标签/URL 序，纯 UI，不承载持久化开关）
    └── (Local State + <profile_dir>/ 副本)
```

- 统一根：`<data_root>/conex/browser/`（**应用目录名统一 conex**，撤销 Crish 命名，R-2 裁决）。`<data_root>`：Windows `%LOCALAPPDATA%`；macOS `~/Library/Application Support`；Linux `$XDG_DATA_HOME`（缺省 `~/.local/share`）。对齐 Tauri 应用数据目录惯例（04 文档 line 85 的 `%LOCALAPPDATA%\Crish\...` 命名以 R-2 裁决为准撤销）。
- **分层语义（R-2）**：`sessions/` = 临时 profile（非用户资产，会话结束**直接删除**，不走 trash）；`managed/` = 用户导入/持久化 profile（用户资产，删除**走 conex-fs trash**）。两类删除路径分函数实现（§4.4）。
- **ACL 策略**：目录继承平台用户私有目录默认 ACL（Windows `%LOCALAPPDATA%` 仅当前用户可读；unix 默认 0700 语义，创建时显式 `DirBuilderExt::mode(0o700)`）。不额外收紧（对齐 04 文档「同用户进程本就可读 cookies 明文」威胁模型，不扩大暴露面即可）。

### 4.2 会话临时 profile（默认）

- 创建时机：`BrowserManager::start` 首次调用时 `create_dir_all`；目录名 = 会话 uuid，天然唯一，**无端口/无固定名可预测**。
- 生命周期：随会话。面板激活 → 启动；会话结束/面板关闭/引擎退出 → 停止并删除（§4.4 清理时机表）。
- 会话内重启（崩溃自动重启）：**复用同一目录**（登录态/cookie 不丢），仅删除 `DevToolsActivePort`。

### 4.3 用户导入 profile（只读来源复制）

语义：「来源只读」——复制过程绝不写源目录（读 + copy 到受管目录），源浏览器的数据完好性不受影响（D-7 与 01 文档 line 195 同旨）。

复制规格（移植 agent-browser chrome.rs:1211-1326 + browser-use profile.py 锁处理）：

| 步骤 | 细节 |
|---|---|
| 来源选择 | 用户经向导指定来源浏览器（Chrome/Edge）+ profile 名（读源 `Local State` 的 `profile.info_cache` 列出，chrome.rs:1109-1140 同款） |
| 运行锁检测 | 复制前检查源 `SingletonLock`；存在且 PID 存活 → 明确报错「请关闭来源浏览器后再导入」（WinError 32/共享冲突同归此文案，01 文档 line 190） |
| 最小文件集 | 复制 `Local State` + `<profile_dir>/`；**排除表**（两处合并）：`Cache`、`Code Cache`、`GPUCache`、`Service Worker`、`blob_storage`、`File System`、`GCM Store`、`optimization_guide`、`ShaderCache`、`component_crx_cache`（chrome.rs:1211-1222）+ D-7 红线：**Login Data（密码库）、History、Web Data 显式排除** |
| 瞬态文件 | 跳过 `Singleton*`、`*.lock`、`*-journal`、`LOCK` |
| 失败语义 | 逐文件 best-effort（失败跳过记 warning，chrome.rs:1271-1326）；目录级失败则整体报错并清理半成品 |
| 复制目标 | `<data_root>/conex/browser/managed/<profile_name>/`（受管分层，R-2；profile_name 默认取源 profile 名，可用户命名，`--user-data-dir` 直接可用） |
| keychain | 复制后启动参数切换到真实 keychain（§3.2 第 23 行注释） |
| 回读校验 | 启动完成后由维度 16 负责 cookie 回读校验（App-Bound）；本维度只保证目录与启动正确，暴露 `ProfileReadbackProbe` 钩子点位 |

复制为**迁移路径**，默认主路径仍是面板内引导登录（D-7）；本维度只提供复制原语与生命周期，不决定用户流程。

### 4.4 清理时机与删除策略（R-2：临时直删 / 受管走 trash）

| 时机 | 动作 |
|---|---|
| 会话结束/面板关闭/引擎退出 | 优雅停止（§6.3）→ 删除会话临时 profile 目录（直删） |
| 受管 profile 删除（用户发起/持久化关闭） | 走 **conex-fs trash**（用户资产，trash.rs:26-29 铁律，不直接 remove） |
| 崩溃自动重启（会话未结束） | **不删除**，复用目录；仅删 stale `DevToolsActivePort` |
| 启动失败（无进程存活） | 删除本次创建的空目录 + 半成品导入副本（直删） |
| 删除失败 | 3 次重试，间隔 100ms；仍失败记 warning 并登记为孤儿目录（下次启动时清扫 `sessions/` 下无锁文件且目录 mtime 超 24h 的孤儿，agent-browser chrome.rs:70-90 同款重试策略） |

**删除策略（R-2 裁决）**：
- `sessions/` 临时 profile 用 `remove_dir_all` **直接删除**（含锁文件、Profile 目录等），**不走 conex-fs trash**——这是运行期受管目录而非用户资产，与 AGENTS.md 会话产出目录清理语义不同，需在代码注释与评审中显式区分；
- `managed/` 受管 profile 是**用户资产**，删除**必须走 conex-fs trash**（trash.rs:26-29 铁律），不直接 remove；
- 两类删除路径在 `profile.rs` 中分函数实现（`remove_ephemeral()` / `trash_managed()`），单测分别覆盖（§10.1 测试 19/25）。

### 4.5 并发互斥（同 profile 二次启动检测）

| 层 | 机制 |
|---|---|
| 引擎内 | `BrowserManager` 单例持有 `tokio::sync::Mutex`；并发 `start` 直接返回当前状态（幂等） |
| 跨引擎/跨进程 | Chrome 自身 `SingletonLock` 机制 + 我方预检：目标 profile 根存在 `SingletonLock` 且 PID 存活（Windows：`OpenProcess` 成功；unix：`kill(pid, 0)`）→ `Err(BrowserError::ProfileLocked)`，面板提示「该会话浏览器已在运行或来源浏览器未关闭」 |
| stale 处理 | `SingletonLock` 存在但 PID 不存在 → 判定 stale，删除锁文件后继续启动（防崩溃残留卡死） |

## 5. DevToolsActivePort 解析

### 5.1 时序（轮询/超时）

```
launch():
  1. 删除 profile 根下 stale DevToolsActivePort          # 防上次崩溃残留（chrome.rs:631-633）
  2. spawn 浏览器进程（stdout 丢弃、stderr 管道保留）
  3. 轮询循环（deadline = now + 30s，interval = 50ms）：
       a. child.try_wait() == Some(status) → 提前退出错误：
            Err(LaunchEarlyExit { exit_code, stderr_snippet })
       b. 读 DevToolsActivePort → 解析校验（§5.2）成功 → 返回
  4. 超时 → Err(LaunchTimeout { stderr_snippet })
```

与 agent-browser chrome.rs:733-763 完全对齐（50ms 轮询、30s deadline、提前退出检测）。stderr 管道缓存最近 20 行用于所有失败路径的诊断拼接（`chrome_launch_error` 过滤 error/fatal/sandbox 等关键行，chrome.rs:792-848 同款）；**拼接前过 URL 脱敏**——行内可能含 query 敏感参数（评审 21-L10）。

### 5.2 校验规则（active_port.rs 纯函数，单测覆盖）

```
parse(file_content: &str) -> Result<CdpEndpoint, ParseError>
  1. 按行分割 + trim + 过滤空行（chrome-devtools-mcp browser.ts:87-94 同款）
  2. 行 1 = port：u16 解析；1..=65535 范围校验；非法 → ParseError::InvalidPort
  3. 行 2 = ws_path：必须存在（不默认填充）；校验：
       - 以 '/' 开头
       - 无空白/换行/控制字符（防注入）
       - 形如 /devtools/browser/<uuid>（仅作模式提示，不强约束前缀，兼容版本漂移）
  4. 输出 CdpEndpoint { port, ws_path }
```

**连接级验证**：解析成功后立即 WS 建连（2s 超时）并发送 `Browser.getVersion` 校验 id 回包（agent-browser chrome.rs:1005-1028 `verify_ws_endpoint` 同款）。验证失败不视为启动失败，进入重试路径（§5.3）——M144+ 单 prompt 机制下该验证可避免触发多余权限提示（chrome.rs:980-985 注释）。

### 5.3 失败重试与兜底

| 路径 | 策略 |
|---|---|
| 主路径 | 整体启动重试：**最多 3 次**，间隔 500ms（chrome.rs:585-621 同款）；每次重新删 stale 文件 + spawn + 轮询 |
| stderr 兜底 | 主路径超时后（仅诊断用）解析 stderr 中 `DevTools listening on <ws_url>` 行（chrome.rs:765-790）；命中则继续，不命中则用其内容增强错误信息 |
| 端口冲突 | `port=0` 由内核分配，天然无冲突；唯一冲突面 = stale 文件 + Chrome 复用同端口（删除文件已消解）。连接级验证失败即重试 |

**端口生命周期纪律**（D-9）：端口/WS path 只在进程内与 profile 文件中出现；错误信息、日志、事件一律不含端点（§8.3）。

## 6. 进程生命周期状态机

### 6.1 状态定义

```rust
pub enum BrowserState {
    Stopped,                                // 未启动/已销毁
    Launching { attempt: u8 },              // 启动中（重试计数）
    Running,                                // 运行中（CDP 已连、已验证）
    Crashed { reason: CrashReason, restarts: u8 },  // 崩溃，待重启或放弃
    Stopping { graceful: bool },            // 停止中
}
pub enum CrashReason { ProcessExit(i32), CdpDisconnected, LaunchEarlyExit(i32), Unknown }
```

### 6.2 迁移表

| 当前 | 事件 | 目标 | 动作 |
|---|---|---|---|
| Stopped | start() | Launching{attempt=1} | 解析二进制 → 建 profile 目录 → spawn → 解析端口（§5） |
| Launching | 端口就绪 + 验证通过 | Running | 上报 `CdpEndpoint` 给维度 11；发射 `BrowserStateChanged` |
| Launching | 失败且 attempt<3 | Launching{attempt+1} | 清理本次残留；500ms 后重试 |
| Launching | 失败且 attempt=3 | Stopped | 清理 profile（§4.4）；发射错误事件 |
| Running | stop(graceful) | Stopping{true} | CDP `Browser.close` → 等进程退出 |
| Running | 检测到崩溃 | Crashed{restarts+1} | 冻结导航栈；发射 `CrashRestarting` |
| Running | stop(force) | Stopping{false} | 直接杀树 |
| Crashed | 重启定时器 | Launching | 复用 profile；恢复导航栈（§6.4） |
| Crashed | 重启超限（30s 内 3 次） | Stopped | 保留导航栈数据；发射终态错误 |
| Stopping | 进程退出（≤5s） | Stopped | 删 profile（§4.4） |
| Stopping | 5s 超时 | Stopped | 杀树 → 删 profile |

- **意图标志**：`stop()` 由引擎发起（面板关闭/会话结束/急停）时置 `intentional_shutdown`；崩溃检测回路（§6.4）据此区分「我杀的」与「它崩的」，避免自激重启。
- **恢复期门禁（R-9-4）**：`Launching` / `Crashed`（重启定时器期间）状态下工具面不可用——工具层调用返回结构化 `browser.not_ready`（错误码登记于维度 17），前端指示条显示「恢复中」（由 `browser://state-changed` 状态事件驱动）；恢复完成（`Running`）后才恢复工具面与帧流。
- Drop 兜底：`BrowserManager`/进程句柄 `Drop` 实现杀树 + 目录清理（agent-browser ChromeProcess Drop 同款，chrome.rs:67-91）；Tauri `RunEvent::Exit` 与 Ctrl-C 信号（`tokio::signal`）均挂优雅停止。

### 6.3 优雅停止路径

```
stop():
  state = Stopping{graceful:true}; intentional_shutdown = true
  1. 若 CDP 已连：发 Browser.close（Chrome 自flush cookies/SQLite 到 profile）
  2. wait_or_kill(5s)：try_wait 轮询 50ms；超时杀树
  3. 杀树（§9 平台策略：unix killpg / win Job Object+taskkill 兜底）
  4. wait() 收尸（防僵尸）
  5. 删 profile 目录（§4.4）
  6. state = Stopped；发射事件（含耗时与清理结果）
```

优雅等待保证「登录态/临时 cookie 落盘」后再删目录——这是引导登录（D-7）可用性的前提。

### 6.4 崩溃检测与自动重启（保留导航栈）

**检测回路**（tokio 常驻任务，250ms 轮询）：`child.try_wait()` 有退出 → 且非 intentional_shutdown → 崩溃；同时 WS 断连（维度 11 事件）作为次级信号（进程存活但 CDP 挂 → 也走重启路径）。

**导航栈**（nav_stack.rs）：

```rust
pub struct NavStack { pub tabs: Vec<TabEntry>, pub active: usize }
pub struct TabEntry { pub url: Url, pub pinned: bool }   // TargetId 由维度 11 重建
```

- 维护：维度 11 的 `Target`/`Page` 事件持续更新（新标签/导航/关闭/切换）；本维度只存不解释。
- 落盘：状态变化后异步写 `nav_stack.json`（会话 profile 根；防浏览器崩溃瞬间内存态丢失）。崩溃重启后读取覆盖内存态。可选增强（默认开，写入失败仅 warning）。

**重启流程**：

```
on_crash():
  1. 从内存/落盘取 NavStack；发射 CrashRestarting { restarts, reason }
  2. restarts+1；若 30s 窗口内累计 >3 → Stopped + 用户可见错误（CrashLoopDetected）
  3. 500ms 退避后 launch()（复用同 profile，仅删 DevToolsActivePort）
  4. 启动成功 → 经 CDP Target.createTarget 逐标签恢复 URL（**不传命令行**：
     命令行 URL 会暴露在进程列表，且无法恢复顺序/激活态）
  5. 恢复后置 active 标签、上报 NavStackChanged；snapshotVersion 由维度 11 重置（协同失效语义）
```

**多会话内崩溃自愈验收锚点**：P0-6（杀进程后自动拉起并恢复 URL）。

### 6.5 超时与异常退出码处理

| 场景 | 超时/判定 | 动作 |
|---|---|---|
| 启动等待端口 | 30s | 杀树 + 删除本次残留 + 重试（§5.3） |
| 优雅停止 | 5s | 杀树强制 |
| 崩溃重启退避 | 500ms | 见 §6.4 |
| 退出码 0 | 正常（Browser.close 后） | Stopping→Stopped 正常流转 |
| 退出码非 0 且非意图 | 分类：1（常规崩溃）/21（profile 冲突，Windows）/其他 | 归入 CrashReason::ProcessExit，日志带退出码与 stderr 关键行；profile 冲突类额外提示 |
| 退出码非 0 但意图 | 容忍 | 不触发崩溃路径 |

## 7. 会话 token 注入与安全

### 7.1 token 构成与生成（D-9 落地）

CDP 无原生鉴权字段，采用**三重随机面**（端口/WS path/目录；对齐 04 文档「随机端口 + loopback + user-data-dir 私有」三重收敛，评审 20-10-1 文案修正）：

| 因子 | 来源 | 性质 |
|---|---|---|
| 端口 | `--remote-debugging-port=0` 内核分配 | 每会话随机不可预知 |
| WS path | `DevToolsActivePort` 第二行，Chrome 生成 per-session UUID（`/devtools/browser/<uuid>`） | 等效 bearer 秘密：无 path 无法建连 |
| 目录 | `<data_root>/conex/browser/sessions/<session-uuid>/`，uuid v4 由引擎生成 | 目录名即会话标识，文件访问受 ACL（§4.1） |

- `--remote-allow-origins` 一律不传（§3.4）；自研 WS 客户端不发送 Origin 头，Chrome 对 loopback + 无 Origin 握手放行，通道自洽。
- 引擎内 `SessionToken`：`uuid v4`（会话启动时生成，即 profile 目录名），用于「会话↔进程↔profile」三方绑定校验（启动后校验 `Browser.getVersion` 返回的 User-Agent 版本与二进制一致，防错连遗留实例）。

### 7.2 传递与校验

| 环节 | 实现 |
|---|---|
| 生成 | `BrowserManager::start` 内 `uuid::Uuid::new_v4()`；随 profile 目录创建写入内存 |
| 传递 | 进程内结构体字段；**不落盘独立文件**（目录名即载体）；不进 CLI 参数（profile 路径除外，路径本身含 uuid，属目录载体而非日志载体） |
| 校验 | ① 连接级：WS 建连 + `Browser.getVersion`（§5.2）；② 会话级：`Browser.getVersion` 返回 `Browser` 产品名/版本比对 `BackendResolution` 预期，不符即断开重试/报错 |
| 失效 | 停止/崩溃放弃时端口随之释放，WS path 失去意义；profile 删除后文件不可再读 |

### 7.3 日志纪律与前端隔离

- `CdpEndpoint` 与 `SessionToken` 的 `Debug` 实现输出 `<redacted>`；tracing 宏一律不得直接打印结构体（必须经脱敏展示）。单测断言日志面不含 `ws://127.0.0.1:<port>`（端口与 path 不进日志，04 文档 line 84/303 硬要求）。
- **前端零暴露**：screencast 帧、输入转发全部经引擎中转（维度 12），React 面板永远拿不到 CDP 端点字符串；`browser://state-changed` 事件只携带状态/restarts/退出码等，不含端点。

## 9. 关键接口（Rust 类型骨架）

```rust
// ---------- 对外门面（lib.rs） ----------

pub struct BrowserManager { /* 内部：state: Mutex<BrowserState>, process: Option<ManagedProcess> */ }

impl BrowserManager {
    pub async fn start(&self, config: LaunchConfig) -> Result<LaunchReport, BrowserError>;
    pub async fn stop(&self, reason: StopReason) -> Result<StopReport, BrowserError>;
    pub async fn restart(&self, reason: CrashReason) -> Result<(), BrowserError>;   // 崩溃重启入口
```

**Tauri 接线**（S2 验收面）：`apps/agent-workbench/src-tauri` 注册命令 `browser_start(config)` / `browser_stop(reason)` / `browser_status()`，事件名 `browser://*` 走既有 emit 桥；前端面板激活 → `browser_start`，面板关闭/会话结束/`RunEvent::Exit` → `browser_stop(graceful)`；恢复期（`Launching`/`Crashed` 未完成）前端指示条显示「恢复中」且工具面不可用（`browser.not_ready`，R-9-4）。

## 11. 风险与预案

| 风险 | 等级 | 预案 |
|---|---|---|
| CfT 下载失败（离线/CDN 抖动） | 中 | 下载仅惰性触发；连接失败/5xx 重试 3 次退避；失败即走系统 Chrome/Edge 回退链（08 文档风险表同款）；下载失败提示可再试，不阻塞面板可用性 |
| 端口冲突 | 低 | `port=0` 内核分配无冲突面；唯一残留 stale DevToolsActivePort 启动前删除 + 连接级验证（§5.3） |
| profile 锁冲突（来源浏览器开着/同会话双启） | 中 | 三层互斥（§4.5）；错误文案明确「请关闭来源浏览器」；stale 锁自愈 |
| 崩溃循环（驱动崩溃/环境问题） | 中 | 30s 内 3 次重启上限 → CrashLoopDetected 终态 + 用户可见错误；保留导航栈供恢复引导 |
| 隐藏窗口被用户 Alt-Tab 直操（headed 离屏模式） | 中 | 默认 headless=new 根治；headed 模式文档化取舍 + 面板接管提示（维度 15 兜底吊销 AI 令牌） |
| 系统 Chrome/Edge 版本过老（CDP 域缺失） | 中 | `Browser.getVersion` 实测版本进能力探测（维度 11）；版本低于最低线时提示安装 CfT |
| AV/EDR 拦截子进程或注入 | 低 | 失败分类（exit code + stderr 关键字）输出引导文案；不动默认安全开关（§3.3 仅容器场景降级） |
| 孤儿进程/孤儿 profile | 低 | 杀树（Job Object/killpg）+ Drop 兜底 + 启动时孤儿目录清扫（§4.4） |
| App-Bound cookie 复制后不可读 | 高 | 本维度仅提供复制原语与回读钩子；最终结论与引导登录兜底属维度 16（P0-4 已定预案） |
| 优雅停止时 Cookie 未落盘就删目录 | 中 | wait_or_kill(5s) 等 `Browser.close` flush 完成再删（§6.3）；删除失败仅 warning 不阻断会话结束 |
