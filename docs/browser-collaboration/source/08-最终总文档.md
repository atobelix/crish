# 软件内 AI 协同浏览器 —— 最终方案总文档

> 状态：方案敲定后的总纲文档（维度详情由各维度文档承载，见「维度文档索引」）。
> 说明：本文档规定本软件的实现细节，不引用外部项目；设计原则为业界最佳实践内化后的融合方案。
> 配套文档：方案敲定文档（决策记录）、各维度实施文档、多轮迭代修复方案（闭环机制）。

---

## 1. 目标与设计原则

### 1.1 目标

在软件内提供"用户与 AI 共同操作"的浏览器能力：

- AI 的操作用户全程可见（所见即所得，同一渲染实例）；
- 用户可随时手动操作、接管同一实例（双向协同）；
- 支持导入主流浏览器（Chrome/Edge 系）的 cookie、书签、历史与登录态；
- 面向二期扩展"电脑操作（Computer Use）"能力，与浏览器能力共享执行框架与前端面板。

### 1.2 设计原则

| 原则 | 含义 |
|---|---|
| 单实例双控制面 | 一个真实渲染实例；用户控制面 = 面板内原生交互；AI 控制面 = CDP 通道。二者操作同一实例，天然一致 |
| 结构化感知优先 | 快照以 DOM/AX 结构化信息为主（不依赖视觉模型），截图仅作调试/回显 |
| 受管生命周期 | 浏览器实例由引擎受管：随机端口、会话 token、按需启停、用完即删 |
| 复用既有体系 | 工具注册面/权限审批/审计/幂等/MCP 桥全部复用 agent-tools 既有设施 |
| 复杂度红线 | 相比常规方案复杂度 3 倍以上者弃用，1-2 倍以内者优先考虑；效果优先、不计成本与调试时长 |
| 闭环迭代 | 实施按逻辑依赖顺序分阶段推进，每阶段产出即下一阶段输入，可多轮迭代修复 |

## 2. 总体架构：单实例双控制面

```
┌─ Tauri 主窗口 ─────────────────────────────────────────┐
│  左侧：React 聊天/工具面板（既有 UI）                    │
│  右侧：BrowserPanel（浏览器面板，React 壳）              │
│        ├─ 帧渲染层：CDP screencast 帧流 → canvas/视频    │
│        │    （用户所见 = 真实渲染实例的画面）             │
│        ├─ 输入转发层：用户点击/按键 → CDP Input 注入     │
│        │    （用户操作落到同一实例，AI 可见）             │
│        └─ 指示条/接管层：AI 操作指示、接管、暂停          │
└─────────────────────────────────────────────────────────┘
         ▲ CDP（loopback 随机端口 + token）│
┌─ Rust 引擎 ──────────────────────────────┴─────────────┐
│  conex-browser（受管 Chromium 进程 + CDP 客户端）        │
│   ├─ 进程管理：CfT/系统 Chrome/Edge 启动、profile、端口  │
│   ├─ CDP 客户端：长连接、命令/事件总线、快照、输入        │
│   └─ 导入服务：引导登录、profile 复制、书签/历史读取     │
│  agent-tools：browser_* 工具族（注册面/审批/审计）       │
│  MCP 桥：外部 MCP 工具可 attach 同一 CDP 端点            │
└─────────────────────────────────────────────────────────┘
```

### 2.1 架构决策一览（详见表 3 与敲定文档）

| # | 决策点 | 敲定结论 |
|---|---|---|
| D-1 | 渲染实例 | 受管独立 Chromium 进程（CfT 优先，系统 Chrome/Edge 回退）；否决内嵌 WebView2 与 iframe 改造 |

## 3. 分维度设计

### 3.1 渲染与进程管理（对应 D-1）

- **浏览器二进制**：优先使用 Chrome for Testing（CfT，确定性版本、可编程下载）；回退系统 Chrome / Edge 稳定版。
- **实例形态**：独立进程 + 独立 `--user-data-dir`（会话级临时 profile 或用户导入 profile），与用户日常浏览器完全隔离；`--remote-debugging-port=0`（随机端口），从 `DevToolsActivePort` 文件读取实际端口与 WS 路径。
- **生命周期**：受管启停——面板激活时启动，会话结束/超时销毁（临时 profile 用完即删）；崩溃自动重启（保留导航栈）。
- **启动参数**：禁用自动化特征痕迹、禁用后台节流、保持窗口激活；不做任何降级安全开关。
- **跨平台**：Windows 首发；macOS/Linux 复用同一二进制选择与启动逻辑（平台路径差异隔离在进程管理模块内）。
- 复杂度：1-2 倍。风险：CfT 下载网络依赖（离线回退系统浏览器）。

### 3.2 CDP 通道与事件总线（对应 D-3/D-4）

- **连接**：WS 长连接（单一常驻连接，禁止每步重连），会话 token 校验身份。
- **客户端实现**：自研薄客户端，覆盖所需域子集（Page/Runtime/DOM/Accessibility/Network/Console/Input/Emulation/Storage/Browser/Target/SystemInfo），命令序列化-请求-响应-超时-错误码闭环；所有命令经统一发送层（审计/审批/急停挂钩点）。
- **事件总线**：页面事件（导航、帧加载、控制台、网络、对话框）→ 引擎内部事件总线 → 前端面板与工具层消费；内置 `snapshotVersion`（页面版本号）供协同失效判定。
- **能力探测**：启动后探测目标环境能力集（CDP 域可用性、版本），生成能力报告供上层决策。
- 复杂度：1-2 倍。风险：协议版本漂移（按域版本号兼容）。

### 3.3 面板帧渲染与输入转发（对应 D-2）

- **帧渲染**：`Page.startScreencast` 帧流（JPEG，可配帧率/质量）→ WS → Rust → 前端 WebSocket/事件 → canvas 绘制；帧率默认 8-15fps（可调），交互期升帧。
- **输入转发（用户 → 浏览器）**：面板捕获用户鼠标/键盘事件 → 归一化为 CDP `Input.dispatchMouseEvent/dispatchKeyEvent` → 注入同一实例（isTrusted=true，与真实操作一致）；滚动/拖拽/IME 合成事件覆盖。
- **输入转发（AI → 浏览器）**：工具层调用同一 Input 原语，用户与 AI 共享同一注入管线（单通道保证所见一致）。
- **指示条/接管层**：AI 操作中显示"AI 正在操作"条，可暂停（挂起 AI 队列）/接管（吊销 AI 在途操作）；用户交互即触发接管信号。
- **剪贴板/拖放/文件上传**：经面板 UI 桥接（授权后）。
- 复杂度：1-2 倍。风险：帧延迟（120ms 内达标）、高交互页面输入抖动（节流+确认）。

### 3.4 感知快照（对应 D-5）

- **主通道**：DOM 简化树——遍历可见/可交互元素，提取 tag/role/name/状态/位置/backendNodeId；可交互判定采用分层启发式（标签语义、ARIA 角色、事件监听器探测、表单控件包裹、类名/属性模式），排除不可见/禁用/装饰元素。
- **辅助通道**：AX 树补齐无障碍语义（名称、角色、状态）；二者合并去重。
- **序列化格式**：紧凑文本树，可交互元素分配稳定索引（`[N]`），索引与 backendNodeId 绑定；输出预算受控（层级/元素数/文本长度截断）。
- **失效机制**：每次快照携带 `snapshotVersion`；动作前校验版本，失效即重快照。
- **视觉**：截图按需（调试回显/视觉模型就绪后补充），不进模型主通道。
- 复杂度：1-2 倍。风险：超大页面序列化耗时（预算+增量快照）。

### 3.5 动作执行与定位（对应 D-5 执行面）

- **定位链**：快照索引 → backendNodeId →（坐标需求场景）`DOM.getBoxModel` → CDP Input 注入；优先 backendNodeId 直接定位（不依赖坐标）。
- **动作原语**：click（左/右/双击/拖拽）、type（分块输入 + 节流）、key（组合键）、scroll（方向/量/元素）、hover、focus、select_option、upload、evaluate（受限）。
- **失败重试**：版本失效/节点过期 → 自动重快照重试（最多 3 次）；页面导航竞态 → 延迟重试。
- **等待原语**：wait_for（元素/文本/网络空闲/URL），供动作链编排。
- **域名门禁**：动作执行前校验目标 URL 于域名白名单（含 IP 地址阻断）。
- 复杂度：常规。风险：合成 vs 注入事件差异（统一走 CDP Input 真实注入）。

### 3.6 协同模型（对应 D-6）

- **单实例双控制面**：用户输入（面板转发）与 AI 输入（工具层）共用 CDP Input 管线；二者天然共享页面状态。
- **令牌互斥**：AI 动作序列持有会话令牌；用户交互（面板事件）即吊销令牌、中止 AI 在途动作（abort_token 复用既有机制）。
- **版本失效**：任何来源的页面变更（导航/布局变化）推进 `snapshotVersion`，AI 持有旧版本快照的动作触发重快照。
- **可见性**：AI 每个动作前后回传帧/指示（指示条 + 状态文本），用户可随时接管。
- **多标签**：标签列表、切换、新建/关闭；快照与令牌按标签页隔离。
- **会话恢复**：临时 profile 持久化开关（用户选择后保留登录态）；面板状态（标签/URL）随会话恢复。
- 复杂度：1-2 倍。风险：高频交互下令牌抖动（最小稳定时间窗）。

### 3.7 数据导入与持久化（对应 D-7）

- **主路径：面板内引导登录**——用户直接在面板浏览器登录目标站点，cookie 落于受管 profile，长期有效；零解密、零隐私面。
- **迁移路径：最小文件集 profile 复制**——用户显式选择来源（Chrome/Edge/自定义目录）与目标 profile；仅复制最小文件集（Cookies、书签、Local State 等必要项），**显式排除**密码库（Login Data）、历史（History）、Web Data 等敏感大项；复制前校验来源浏览器未运行（锁文件检测）；复制到受管独立目录，不触碰来源。
- **加密兼容预案**：高版本浏览器 cookie 加密绑定浏览器家族（App-Bound），复制后可能存在解密失败——启动后回读校验（尝试访问已知站点 cookie），失败则引导用户走"面板内登录"路径，并提示来源浏览器家族约束（仅同家族可迁移）。
- **辅助：storage_state 导入/导出**：标准 JSON 格式，默认不落盘（内存传递），导出需显式授权。
- **书签/历史**：读取来源书签 JSON 与历史库（SQLite），面板内导入为独立入口。
- 复杂度：1-2 倍。风险：App-Bound 加密兼容（预案已含回读校验）。

### 3.8 工具集与权限（对应 D-8）

- **browser_* 工具族**（挂 agent-tools 注册面，复用审批/审计/幂等/流式）：
  - 导航类：navigate / back / forward / reload / list_tabs / new_tab / close_tab / switch_tab
  - 感知类：snapshot / screenshot / wait_for / get_url / get_title
  - 交互类：click / type / key / scroll / hover / drag / select_option / upload（dangerous=true 走审批）
  - 调试类：console / network（只读）；evaluate（受限白名单 + 审批）
- **权限分级**：导航/感知默认允许；交互类审批；evaluate/上传/剪贴板审批且默认拒绝策略（敏感操作兜底拒绝）。
- **MCP 并存**：既有 MCP 桥可注册外部 MCP 工具；外部浏览器类 MCP 经 `--browserUrl` 附加同一 CDP 端点，与自研工具并存；命名空间隔离（`browser_` vs `mcp_<server>__*`），权限策略各自独立。
- 复杂度：常规。风险：工具面膨胀（按需裁剪，默认最小集）。

### 3.9 安全（对应 D-9）

- **连接安全**：CDP 仅 loopback；随机端口（非固定 9222 等）；会话 token 校验（防本机其他进程探测）；端口生命周期与面板绑定。
- **域名门禁**：白名单/黑名单（通配符支持）；IP 直连默认阻断；导航与动作双检查点。
- **敏感数据**：密码库不导入；快照脱敏（密码/凭据字段过滤）；storage_state 默认不落盘；剪贴板默认拒绝。
- **审批与审计**：危险动作（输入/上传/求值）审批；全部动作审计（脱敏后），急停全局生效。
- **文件**：下载落入受管目录（打开需授权）；上传经显式授权。
- **日志**：审计日志与调试日志分离，敏感字段脱敏。
- 复杂度：常规。

### 3.10 电脑操作二期（对应 D-10）

- **形态**：独立模块（与浏览器线共享面板/执行框架/安全门槛/审计链路），实现 OS 级截屏 + 全局输入注入 + 坐标缩放对齐。
- **启用门槛**：会话级显式开启 + 全动作审批 + 全局急停 + 与浏览器会话互斥（不可同时活跃）。
- **共享层**：面板帧渲染、指示条/接管、输入归一化管线、工具执行框架直接复用。
- **依赖**：视觉模型（截屏感知）或结构化辅助（平台无障碍 API 降级）。
- 复杂度：1-2 倍（独立立项）。风险：误操作（审批+急停兜底）。

## 4. 逻辑执行顺序（分层闭环链）

仅表达逻辑依赖，不含时间/人员/优先级；每阶段输入=上阶段输出，可多轮迭代。
**分层结构（R-13 红队裁决）**：MVP 先行验证核心价值；高杠杆增强以 S0 实测达标（G 判据）为 Gate 再启动，未达标保持 MVP 形态（headed 窗口），不引入替代渲染。

```
S0 技术验证（spike，Gate）
   ├─ P0 项：CDP 连通与 Input 域能力、随机端口/DevToolsActivePort 闭环、
   │         CfT 可用性、profile 复制回读校验（App-Bound 实证）
   ├─ G 判据（帧流路线的 Go/No-Go）：G-1 帧延迟 ≤120ms、G-2 输入延迟 ≤30ms、
   │         G-3 中文 IME 全流程（微软拼音实测）、G-4 接管 ≤800ms
   └─ 备选登记：WebView2 复合方案（G 不达标时的 Windows 专案，复用零面）

MVP（M0-M8，验证产品——headed 可见窗口形态，无帧流/输入转发）：
M1 基础设施：CDP 客户端 + 事件总线（会话级 snapshotVersion）
M2 进程管理：CfT/系统浏览器启动、profile 目录、DevToolsActivePort 解析、崩溃重启
M3 引导登录：面板登录 + persist 开关（仅此两项导入，其余推迟）
M4 可见形态：headed 窗口 + 指示条/急停（无帧流面板、无输入转发、无 IME 桥）
M5 感知快照：DOM 简化树 + AX 辅助 + 索引分配 + 序列化（单标签）
M6 动作执行：Input 原语 + 定位链 + 重试 + 域名门禁（无 evaluate）
M7 工具挂载：browser_* 子集注册进 agent-tools（审批/审计接线）
M8 协同：版本失效 + 粗粒度令牌（吊销基于窗口语义与快照校验）

P1（完整产品，S0 G-1/G-3 达标后启动）：
  S4 帧流 + 输入转发 + IME 桥（G-1/G-3 为 Gate，不达标维持 headed 形态）
  S8 多标签（恢复 per-tab 版本 + MAX_TABS）、evaluate 白名单、剪贴板桥
  S3 扩展：复制迁移/storage_state/书签历史（App-Bound P0-4 实证后）
  S9 MCP attach（只读能力集）、注入桥感知通道（默认关）

P2（差异化增强）：电脑操作二期（共享层复用评审）
```

### 4.1 迭代闭环规则

1. **问题识别**：每阶段验收（见 §5）未过项登记为问题清单；
2. **任务分解**：问题按模块拆解为原子修复项，标注文件域（避免同轮冲突）；
3. **Agent 分配**：每轮 ≤12 个 Agent（按需，不必占满）；同轮各 Agent 文件域互斥（禁止共同修改同一文件，串行化）；
4. **并行修复**：各 Agent 按验收标准独立修复并自验；
5. **结果汇总与验证**：主控收齐后执行阶段门禁（§5），产出更新后的方案/代码作为下一轮输入；
6. 未闭环问题滚动进入下一轮，直至清零。

## 5. 验证体系

| 阶段 | 验收标准 |
|---|---|

## 7. 风险总表

| 风险 | 等级 | 预案 |
|---|---|---|
| 高版本浏览器 App-Bound 加密导致复制后 cookie 不可读 | 高 | 回读校验 + 引导登录兜底 + 同家族约束提示 |

| 用户高频操作与 AI 动作抖动 | 中 | 令牌最小稳定窗 + 版本失效重试 |
| 外部 MCP 工具与自研工具行为差异 | 低 | 命名空间隔离 + 权限独立 |
| 电脑操作误操作 | 高（二期） | 显式开启 + 全动作审批 + 急停 + 会话互斥 |
