# 软件内 AI 协同浏览器——全局选型方案（产品体验/协同视角）

- 视角：产品体验/协同（最看重"用户与 AI 同屏协同"的体验完整性、操作可见性、接管/冲突处理的人机交互设计）
- 日期：2026-08-08
- 约束：不考虑成本、效果优先；每个结论标注复杂度等级（常规 / 1-2 倍 / 3 倍+），3 倍+ 方案直接放弃

---

## 0. 一句话结论与总览

**结论：以"独立 Chromium 进程（系统 Chrome/Edge，launch 或 attach）为唯一真实实例，CDP 全控制 + CDP screencast 帧渲染进 React 面板 + CDP Input 输入转发"为底座；用户与 AI 双控制面共用一个实例；感知用"DOM 简化树 + 截图视觉校验"；数据导入走"面板内登录为主 + attach 接管 + 同家族 profile 复制"三线；browser_* 工具族接入既有 agent-tools 注册面（复用审批/审计/中止令牌）；二期 Computer Use 复用帧渲染+输入转发+接管 UI 共享管线。**

各维度结论速查：

| # | 维度 | 结论 | 复杂度 |
|---|------|------|--------|
| 1 | 渲染实例 | 独立 Chromium 进程 + CDP screencast 帧渲染 | 1-2 倍 |

| 3 | Rust CDP 客户端 | 自研薄客户端（tokio-tungstenite，~15 域子集） | 1-2 倍 |

## 1. 渲染实例

### 候选对比

| 候选 | 同屏渲染 | 用户操作真实实例 | 导入 Chrome/Edge 用户数据 | 跨平台 | 复杂度 | 关键证据 |
|------|----------|------------------|--------------------------|--------|--------|----------|
| A. Tauri 子 WebView2 | 好（原生窗口嵌入） | 是（真实页面） | **差**：WebView2 profile 格式与 Chrome 不兼容，cookie 加密绑定不同，无法复用 | 仅 Windows（macOS WKWebView 无 CDP） | 1-2 倍 | Tauri 壳现有依赖即 WebView2；但 CDP 支持部分域受限、与主窗口共享进程时 AI 可控制主 UI |
| B. 独立 Chromium 进程（系统 Chrome/Edge） | 好（CDP screencast 帧流渲染 canvas） | 是（CDP Input 转发，页面收真实事件） | **好**：launch 同家族 exe + 复制 profile；或直接 attach 用户正在用的浏览器 | Windows 优，macOS/Linux 可 attach 或打包 CfT Chromium | 1-2 倍 | chrome-devtools-mcp `src/browser.ts:84-111`（DevToolsActivePort attach）、`:131-143`（connect）；browser-use `profile.py:838-893`（profile 复制） |
| C. iframe（现状） | 好 | 否（sandbox 受限，AI 无法操作） | 差（跨域 cookie 隔离） | 全平台 | 常规 | `apps/crish-desktop/src/components/workspace/PreviewCard.tsx:190-202`（sandbox=allow-scripts…，`:196`），跨域站点被 CSP/X-Frame-Options 阻断（`:151-164` 已有 canEmbed/loadError 判定） |
| D. CEF | 好 | 是 | 差（需自带内核与 profile 转换） | 全平台 | **3 倍+（放弃）** | 需内置浏览器内核、包体增大、Rust 绑定（cef-rs）维护弱、与 Tauri WebView2 并存冲突风险 |

### 结论与理由

**选 B：独立 Chromium 进程，launch（同家族 exe + 复制/专用 profile）为主、attach（用户已在运行的 Chrome/Edge）为辅；渲染用 CDP `Page.startScreencast` 帧流画到 React canvas，用户输入经 CDP `Input.dispatchMouseEvent / dispatchKeyEvent` 转发。**

理由（产品体验/协同视角）：

1. **同一实例是"共同操作"的前提**：用户与 AI 操作的是同一个真实浏览器页面（同 DOM、同 cookie、同会话）。iframe 的 sandbox 使 AI 完全无法操作第三方页面（`PreviewCard.tsx:196` 只放行了 scripts/same-origin/forms 等，且 X-Frame-Options 拒绝的站点直接无法内嵌，`:151-164`），因此 iframe 方案在能力上直接出局——不是复杂度问题，是核心诉求不满足。
2. **帧渲染 + 输入转发 = 面板内"所见即所得"**：用户看到的就是 AI 看到的那一帧；AI 点击的位置、高亮的元素在帧上叠加显示，用户眼里的"页面状态"与 AI 的快照严格一致，这是同屏协同体验的根基。screencast 方案已被 chrome-devtools-mcp 验证（`screencast.ts:86-90` 用 `page.screencast` 录帧，需 ffmpeg 可选）。
3. **用户数据导入天然可行**：launch 时用同一浏览器家族的 exe（Chrome profile → Chrome exe、Edge profile → Edge exe），复制 profile 后 cookie 等 DPAPI/App-Bound 加密数据可解密（详见第 7 节）；attach 模式则连复制都省了——用户日常浏览器直接成为协同实例。
4. **WebView2 出局的关键原因**：a) profile 格式不兼容，核心诉求"导入 Chrome/Edge 用户数据"直接落空；b) 与 Tauri 主窗口若共享 user data folder 则 AI 经 CDP 可触及主 UI 的 DOM（控制面与安全边界纠缠）；若不共享则无法共享会话，协同失去意义；c) Windows-only，降级链是另外两套实现。

降级策略：Windows 为主平台（系统 Edge 必装，兜底 Chrome）；macOS/Linux 第一阶段支持"attach 已运行浏览器 + CDP 连接但不渲染帧"（或复用系统浏览器窗口 + 操作日志面板），第二阶段可打包 Chrome for Testing（agent-browser 的 `install` 命令即此路线，见 agent-browser AGENTS.md 架构节）。

### 风险

- screencast 帧延迟（本地 loopback 约 100-300ms 可接受）；高动态页面（视频/动画）帧率受限——产品上对"AI 操作期间"保持帧流，用户主动交互时不做帧率承诺。
- 输入转发需处理 IME/合成输入与剪贴板：中文输入法合成、粘贴走 `Input.insertText` / `Input.dispatchKeyEvent` 补全，需专项测试（仓库已有 IME 专项测试资产可参考）。
- 用户面板内交互与 AI 并发输入存在竞态 → 由第 6 节操作锁解决。

## 2. AI 控制通道

### 候选对比

| 候选 | attach 已有实例 | 覆盖能力 | 页面可检测性 | 复杂度 | 证据 |
|------|----------------|----------|--------------|--------|------|
| A. CDP | **支持**（connect/DevToolsActivePort） | 全量（Target/Page/Runtime/DOM/Input/Network/Security） | 中（`--disable-blink-features=AutomationControlled` 等可缓解） | 常规 | chrome-devtools-mcp `browser.ts:63-124`；browser-use 全 CDP（`session.py:15` cdp_use） |
| B. 注入脚本桥（页内 JS/扩展） | 需要装扩展或先有注入载体 | 受 CSP 与页面配合制约 | 高（可被检测） | 1-2 倍 | skyvern 走 playwright+扩展；agent-browser eve 走 sandbox CLI |
| C. 双轨（CDP + 注入脚本） | 支持 | 全量 | 中 | 1-2 倍 | — |

### 结论与理由

**选 C 实质上的"双轨合一"：控制命令一律走 CDP；感知（DOM 快照采集）用 CDP `Runtime.evaluate` 执行页内 JS 完成。**

- 这不是"两条平行控制轨"：快照 JS 是经 CDP 在页面上下文里执行的，两者共享一条 WebSocket 通道、一个 session 会话模型，实现上仍是一个 CDP 客户端。之所以单列说明，是因为快照采集的 JS 体积大（browser-use 的 eval_serializer 注入整个采集脚本），在工程上要独立成模块。
- attach 用户浏览器（第 7 节三线中的一条）**必须** CDP；面板输入转发（第 6 节双控制面）也必须走 CDP Input 域——AI 与用户共用同一注入机制，冲突处理（操作锁）因此只有一个关注点。
- 纯注入脚本桥出局：attach 场景没有注入载体，且扩展模式要求用户浏览器装我们的扩展，破坏"零安装接管"体验。

复杂度：常规。

## 3. Rust CDP 客户端选型

### 候选对比

| 候选 | 维护状态 | 事件模型 | 与仓库契合 | 复杂度 | 证据 |
|------|----------|----------|------------|--------|------|
| A. headless_chrome | 老牌但近两年基本停滞 | 同步回调、异步支持弱 | 一般 | 常规（但改造风险大） | crates.io headless_chrome |
| B. chromiumoxide | 活跃、tokio 原生、类型化 | 好（EventStream） | 域覆盖不全（Accessibility 等缺），且我们要自控多客户端连接/事件扇出 | 常规 | chromiumoxide 官方仓库 |
| C. 自研薄客户端（tokio + tokio-tungstenite + serde） | 自持 | 完全自控（事件总线/多 target 会话/重连） | **最优**：仓库惯例即 Rust 自研内核；agent-browser 已验证（`cli/src/native/` 自研 daemon+CDP client，见其 AGENTS.md 架构节） | 1-2 倍 | agent-browser AGENTS.md；browser-use `session.py:88-131`（CDPSession/SessionManager 事件模型参考） |
| D. Node puppeteer 子进程代理 | 活跃 | 好 | 差：引入 Node 运行时，与纯 Rust 内核架构冲突 | 1-2 倍 | chrome-devtools-mcp（TS 实现本身） |

### 结论与理由

**选 C：自研薄 CDP 客户端，只实现所需域子集（Target / Page / Runtime / DOM / DOMSnapshot / Input / Emulation / Security / Network / Storage / Accessibility(备用) / Log / Browser），事件层直接对接第 6 节的协同事件总线。**

理由：

1. 我们需要的 CDP 面很小且协议极稳定（十年未大变），自研 ~15 域子集是**有界工作量**；domain 需求清单来自第 1/2/4/6 节的明确功能要求，不需要通用化。
2. **多客户端并发连接**（用户 screencast 客户端 + AI 命令客户端可并存，Chrome 允许）与**事件扇出**（导航/DOM/对话框/下载事件同时喂给指示条、锁、快照缓存）是协同模型的核心诉求，现成库的 API 模型（单客户端 + 单 event stream 消费者）反而要反适配。
3. 仓库铁律"架构优雅、杜绝打补丁"：自研能保证审批/中止令牌（`agent-tools/context.rs:103`）精确穿透到每个 CDP 命令（异步取消 = 关掉 pending 命令），这是三方库最难塞的钩子。
4. agent-browser（同为 Rust 产品）已证明该路线可维护性；browser-use 的事件驱动 BrowserSession（`session.py:134-140` 双层架构：高层事件 + 底层 CDP 调用）给出成熟结构模板，我们照搬语义即可。

复杂度：1-2 倍（域子集有界；websocket 重连/超时需自测，browser-use `session.py:588` RECONNECT_WAIT_TIMEOUT 模式可参考）。

## 4. 感知快照

### 候选对比

| 候选 | 信息量 | 坐标/可操作性 | 抗页面变化 | 实现成本 | 证据 |
|------|--------|----------------|------------|----------|------|
| A. AX 树（Accessibility.getFullAXTree） | 语义好、自动忽略装饰元素 | 弱：AX 节点无内置坐标，需经 backendDOMNodeId 反查 getBoxModel | 中 | 常规 | chrome-devtools-mcp `tools/snapshot.ts:12-44`（uid）；agent-browser eve `snapshot.ts`（ref=e12）；本文档环境（页面快照工具即 AX） |
| B. DOM 简化树（交互元素筛选+编号+坐标） | 全量可控 | **强**：每个交互元素带 DOMRect | 中（坐标随布局漂移） | 1-2 倍（移植 browser-use serializer 核心） | browser-use `dom/serializer/serializer.py:41-56`（PROPAGATING 元素合并）、`:110-150`（简化树→paint order→优化→bbox 过滤流水线）；`views.py` EnhancedDOMTreeNode 带 DOMRect |
| C. 视觉混合（截图 + 视觉模型输出坐标） | 抗布局变化（视觉层） | 弱（像素级坐标，精度依赖模型） | **强**（不依赖 DOM） | 常规（但 token 成本高、精度差） | skyvern（vision-LLM + playwright 坐标）；anthropic `computer.py:58-62`（缩放目标）、`:268-291`（坐标缩放换算） |

### 结论与理由

**选 B 为主（移植 browser-use 的 DOM 简化树序列化核心：交互元素筛选、PROPAGATING 元素边界合并、paint-order/bbox 过滤、selector map 编号），C（截图 + 视觉）作为校验层与"难描述页面"兜底，A 仅作补充数据源（role/name 语义可并入简化树标注）。**

理由（产品视角）：

1. **协同体验要求"可指向"**：AI 说"我要点击第 7 号元素"，用户要在帧上看到第 7 号的高亮框。DOM 简化树的 selector map（编号→元素→坐标）天然支撑"高亮渲染到帧上"（browser-use `highlight_elements` + `interaction_highlight_color`，`profile.py:686-698`）。AX 树没有坐标，做高亮要先反查 DOM，且裁剪过深后树与像素对不上。
2. **精准重试**：用户改动页面后 AI 要能"重新锚定"，DOM 简化树携带文本/role/name/位置多重锚点，重查成本低；纯视觉在元素密集页（表单、列表）误点率高、且每步都要付 vision token。
3. 视觉不做主通道的原因是：主通道必须"确定性可复现"（失败重试、审批展示、审计都要描述"点了什么元素"），视觉模型输出天然不确定。视觉作为校验（browser-use `use_vision=auto` 语义）足够，且 `agent-provider` 已支持 image_url 多模态（`catalog.rs:127` supports_vision），成本为零。

复杂度：1-2 倍（browser-use serializer 1300+ 行需按需移植核心流水线：interactive 判定、paint_order、bbox 过滤、iframe 递归——`profile.py:664-676` 有 cross_origin_iframes/max_iframes/max_iframe_depth 上限参数可对齐）。

## 5. 元素定位与操作执行、失败重试（用户操作导致页面变化的场景）

### 设计结论

**定位：双通道。主通道 = 快照 ref 编号（selector map 索引）；辅通道 = 稳定锚点（role + accessible name + 文本片段 + 相对位置）。执行时通过页内 JS 重新解析，ref 失效时自动降级锚点。**

**重试：动作前强制 re-snapshot（每次工具调用先取最新状态，快照 hash 与 AI 所见比对）；执行失败按"重新锚定 → 重试"循环，上限 3 次（对齐 browser-use `max_failures=3`）；重试期间指示条显示"页面已变化，重新定位元素中"。**

证据与依据：

- 每次动作前刷新状态：browser-use 动作执行前取 `get_browser_state`（DOM 缓存按需重建，`session.py:561-563` 缓存字段、`:1224-1236` focus 变更清缓存）。
- ref 失效处理：agent-browser 快照重试（`snapshot.ts:11-26`，CDP 错误 500ms 延迟重试一次）；其 instructions 明确"动作改变页面后必须重新快照，旧 refs 可能失效"（`instructions.md:11`）。
- 用户并发改页：执行前用 DOM 版本计数/快照 hash 校验——**不一致则拒绝执行并让 AI 重看页面**（这是协同场景下唯一诚实的策略：不猜用户意图，只报告"页面已被修改"）。这一步是产品体验红线：AI 不能在用户改过的地方强行执行。

复杂度：常规（跟随已验证模式，无新发明）。

## 6. 协同模型（重点维度）

### 6.1 单实例双控制面（总模型）

```
                 ┌──────────────────────── 浏览器实例（Chrome/Edge 进程）────────────────────────┐
                 │   页面 DOM / cookie / 会话（唯一真相）                                         │
                 └────────────▲───────────────────────────────▲──────────────────────────┘
                    CDP 多客户端连接（Chrome 原生支持并发 client）│
      ┌──────────────┴──────────┐                 ┌───────────┴───────────┐
      │ 用户控制面（面板内）      │                 │ AI 控制面（browser_* 工具）│
      │ · screencast 帧渲染 canvas│                 │ · 同一 CDP 会话/命令路径  │
      │ · 输入经 CDP Input 转发   │                 │ · 快照/点击/输入/导航      │
      └──────────────▲──────────┘                 └───────────▲───────────┘
                     │ 操作锁（单步互斥，用户优先抢断）            │
              ┌──────┴──────────────────────────────────────────┴──────┐
              │ 协同内核（Rust）：事件总线 / 操作锁 / 指示条事件 / 审批桥 │
              └────────────────────────────────────────────────────────┘
```

- 一个真实浏览器实例 + 两个控制面，**不搞"AI 浏览器 + 用户浏览器"双实例镜像**（那是 3 倍+ 复杂度且体验割裂）。
- CDP 允许同一端口多 WebSocket client：用户侧 screencast 流与 AI 侧命令天然并行（chrome-devtools-mcp/Chrome 均验证过 connect 语义，`browser.ts:63-69` 的 connectOptions 即附加式连接）。
- **操作锁（核心原语）**：全局单步锁。AI 动作前 acquire → 执行 → release；锁持有期间用户输入（面板内 mousedown/keydown）→ 立即释放锁并触发用户接管（见 6.3）。用户侧输入不需要锁（用户永远有最高优先级），AI 侧每个工具调用按锁协议排队。
- 中止令牌直接复用 `agent-tools/context.rs:103`（abort_token）：接管时取消 AI 在途步骤，语义与现有审批等待取消一致，零新增机制。

### 6.2 双向事件同步

- **页面 → 内核 → UI**：CDP 事件（Page.navigated / Target.attachedToTarget / Network 状态 / 对话框 / 下载）经内核事件总线（参考 browser-use `session.py:549` event_bus + watchdogs 模式、`:106-132` ResilientEventBus）经 Tauri 事件桥 → React：地址栏、tab 条、加载态、对话框代理、下载提示。
- **AI 动作 → UI**：每个工具调用产生 `action-indicator` 事件（动作类型、目标元素描述、高亮 rect）→ 指示条 + 帧上高亮。
- **用户输入 → 内核**：面板内输入经转发路径同时也上报内核（用于接管判定、冲突检测），不绕过锁。

### 6.3 AI 操作指示条 / 用户接管（体验设计重点）

- **操作指示条**（面板顶部常驻条）：显示"AI 正在：点击『提交订单』（第 7 号元素）"+ 可取消按钮；页面帧上以高亮色框标注目标元素（对齐 browser-use `highlight_elements` + `interaction_highlight_color` rgb(255,127,39) 与 1s 持续时长，`profile.py:686-698`）。指示条必须让用户**预知** AI 下一步要做什么——协同的核心信任机制。
- **用户接管（User Takeover）**：面板内检测到用户任何输入 → 立即进入接管态：
  - 取消在途 AI 步骤（abort_token）、后续排队动作挂起；
  - 指示条切换为"你已接管操作，AI 已暂停"，提供【恢复 AI 执行】【重新指示 AI】两个按钮；
  - 恢复后 AI 先 re-snapshot 再看页面（用户改了什么 AI 必须重看，对应第 5 节策略）。
- **敏感动作审批**：AI 触发需要批准的动作（提交/支付/发布/跨域登录）→ 走既有审批通道（`agent-tools` permission 三态 Allow/Deny/NeedsApproval，`lib.rs:5-6`；ask 回调 `context.rs:63-75`），审批对话框内附**动作前页面截图 + 目标元素高亮**，让用户"看得懂再批准"。

### 6.4 冲突处理策略（按严重度排序）

| 冲突场景 | 策略 | 复杂度 |
|----------|------|--------|
| AI 操作期间用户输入 | 用户抢断（6.3 接管），AI 步骤取消 | 常规 |
| 用户改动页面后 AI 执行旧快照目标 | 执行前快照 hash/DOM 版本校验，不一致 → 拒绝 + re-snapshot 反馈 | 常规 |
| AI 填表时用户改同一字段 | 输入前比对当前 value，与快照不一致 → 以用户值覆盖为准并提示 | 常规 |
| 用户与 AI 同时切 tab | tab 焦点事件单一来源（CDP Target.activateTarget 回环收敛），UI 幂等渲染 | 常规 |
| AI 导航被用户输入打断 | 导航计入操作锁；接管时取消导航并回退指示条 | 常规 |

原则：**冲突时永远偏袒用户、AI 永远先"重看"再行动**——不猜测、不回滚用户操作、不静默覆盖。

### 6.5 多标签页协同

- 内核维护 tab 模型（Target 事件驱动），面板渲染 tab 条（标题/URL/favicon/frame 缩略）。
- **焦点同步**：用户点 tab → `Target.activateTarget`；AI `browser_tab_switch` → 同一路径。两者汇聚到一个焦点状态，指示条展示 AI 当前焦点 tab。
- 每个 tab 独立快照缓存（browser-use `_cached_selector_map` 按 target 管理的语义，`session.py:562-563`、`:1224-1236` focus 切换清缓存），AI 切 tab 后自动 re-snapshot。
- 新 tab 打开（AI 或页面脚本）→ tab 条即时出现；防止用户困惑，AI 新开 tab 时指示条明示"已在新标签页打开"。

### 6.6 操作回放 / 高亮

- 每次 AI 动作记录：(动作 + 目标元素描述 + 动作前截图 + 动作后截图 + 时间戳)，构成**动作日志时间轴**（面板侧栏）。
- 点击某条日志 → 恢复该步的"前后截图对比"并重放目标高亮（高亮 rect 来自该步快照的 selector map 坐标，DOM 可能已变 → 高亮尽力而为，标注"页面已变化"）。
- 不做全自动"回到历史状态"回放（需要页面状态快照/重放引擎，3 倍+，放弃）；日志 + 截图对比已满足协同审计与复盘需求。
- 该日志流同时是安全审计的展示层（第 9 节）。

### 6.7 会话恢复

- 浏览器实例使用**持久 profile 目录**（非临时目录），应用退出优雅关闭（保存 storage state 兜底，browser-use `session.py:757-761` stop() 先 SaveStorageStateEvent）。
- 重开应用 → 复用 profile 启动 + 浏览器自带 session restore 恢复标签页 + CDP 重连（browser-use `RECONNECT_WAIT_TIMEOUT=54s` 重连语义，`session.py:588`）。
- **用户与 AI 的协同状态恢复**：tab 列表、AI 焦点 tab、指示条状态可从内核会话文件恢复；AI 任务中断后恢复时强制 re-snapshot 再继续。

复杂度：6.1-6.7 合计 1-2 倍（模块化：锁/事件总线/指示条/恢复各自独立，无新技术域；事件总线与锁可先在 Rust 单测覆盖）。

## 7. 数据导入（含"登录一次长期有效"体验设计）

### 候选对比

| 候选 | 覆盖数据 | 用户操作成本 | 关键限制 | 证据 |
|------|----------|--------------|----------|------|
| A. 面板内登录（用户与 AI 同实例，登录动作由用户完成） | cookie/localStorage/IndexedDB/会话 全量 | **零成本（首选用法）** | 需要用户在面板内登录一次 | 协同模型天然产物（第 6 节） |
| B. attach 用户已在运行的 Chrome/Edge | 全量（用户日常数据） | 零成本 | 要求用户浏览器先开远程调试；用户浏览器内输入 AI 感知有限（只靠 DOM 变化） | chrome-devtools-mcp `browser.ts:84-111`（DevToolsActivePort 自动发现） |
| C. profile 整目录复制 | 全量 | 一次向导（选浏览器→检测锁定→复制→启动→校验） | **Chrome 127+ App-Bound 加密：cookie 绑定启动 exe，必须同浏览器家族**（Chrome profile 用 Chrome exe 启动）；复制时用户浏览器需关闭 | browser-use `profile.py:89-113`（忽略 Singleton/lock/journal、WinError 32 检测）、`:838-893`（_copy_profile + Local State） |
| D. storage_state（JSON cookies+localStorage） | 部分（无 sessionStorage/IndexedDB/扩展数据） | 高（需导出工具/手工） | 跨浏览器可写，但体验差、site 检测风险 | browser-use `profile.py:511-517`（storage_state 仅 new_context 支持，持久上下文不支持） |
| E. 书签/历史直读 | 书签+历史 | 零（只读展示） | 只读、需处理运行中文件锁 | Chrome `Bookmarks`(JSON) + `History`(SQLite)，读前复制副本 |

### 结论与理由

**三线混合，按体验优先级排序：**

1. **线一（体验主路径）：面板内登录**——协同模型的免费午餐：用户与 AI 共用一个实例，用户在面板里登录任意站点，cookie 直接写入实例 profile，AI 从此继承会话。"用户登录一次长期有效"= 持久 profile 目录 + 登录态持续复用 + 重启恢复。**这是与一切纯 AI 自动化方案（无头浏览器 + storage_state 注入）最大的体验差异点，必须作为产品叙事主线。**
2. **线二：attach 接管**——用户想直接在自己日常浏览器里干活时启用：零导入成本，AI 面板镜像操作（chrome-devtools-mcp 已验证 DevToolsActivePort 自动发现，`browser.ts:84-111`）。
3. **线三：profile 复制向导**——"导入 Chrome 登录态"的显式入口：检测源浏览器版本与锁定状态（复制时跳过锁文件、WinError 32 → 提示关闭浏览器，`profile.py:89-113`、`:872-881`）→ 复制 profile + Local State → **必须用同家族 exe 启动**（App-Bound 加密约束）→ 启动后 `Network.getAllCookies` 回读校验（解密失败的域名列出并提示重新登录）。
4. 书签/历史直读（E）作为面板功能补充：书签 JSON 直接解析，历史 SQLite 只读副本查询，与协同体验无关、独立成小模块。

**放弃点**：storage_state 不作为主路径（跨浏览器导出体验差、覆盖不全）；"复制后跨浏览器家族使用"（App-Bound 解密失败，属硬限制，向用户明确解释）。

复杂度：1-2 倍（复制向导 + App-Bound 校验是有界工作量；attach 与面板内登录是协同模型/控制通道的复用产物，近似零增量）。

## 8. 工具集：browser_* 工具族设计

**结论：以 `browser_` 前缀注册进 agent-tools 的 ToolRegistry（复用 ToolDefinition 的 dangerous/fatal_on_error 声明，`definition.rs:30-47`），权限分级挂 permission 三态判定，全部动作发射 security-audit 事件（`audit.rs:22`、`:107-124`）。**

| 工具 | 功能 | 权限级 | 说明 |
|------|------|--------|------|
| browser_navigate / browser_go_back / browser_go_forward / browser_reload | 导航 | 跨域 NeedsApproval / 同域 Normal | 域名白名单前置校验（第 9 节） |
| browser_snapshot | DOM 简化树 + refs | Normal（只读） | 第 4 节；每次动作前自动附带 |
| browser_screenshot | 截图（回传 image_url） | Normal | 视觉校验层；帧渲染已有流，此为单帧高清 |
| browser_click / browser_double_click / browser_hover | 元素交互 | Normal；提交/危险按钮判定后升格审批 | 定位见第 5 节 |
| browser_input_text / browser_type / browser_press_key / browser_select_option / browser_set_checked | 表单 | 敏感字段（密码/支付）需审批 | 输入经 CDP Input，与用户输入同路径 |
| browser_scroll / browser_find_text | 浏览 | Normal | |
| browser_tab_list / browser_tab_switch / browser_tab_close / browser_tab_open | 标签页 | tab_close NeedsApproval | 与面板 tab 条双向同步 |
| browser_wait / browser_wait_for_text | 等待 | Normal | 对齐 chrome-devtools-mcp `wait_for`（`snapshot.ts:46-73`） |
| browser_dialog_accept / browser_dialog_dismiss | 页面对话框 | NeedsApproval | CDP Page.javascriptDialogOpening 代理 |
| browser_download_info / browser_download_open | 下载 | 打开文件 NeedsApproval | 下载到应用托管目录 |
| browser_evaluate | 页内 JS | **默认 Deny**（调试开关启用 + 白名单） | 双重高风险，不做常态工具 |

对照基准：browser-use 默认工具族（navigate/go_back/wait/click/input/upload_file/scroll/find_text/send_keys/evaluate/switch/close/extract/screenshot/dropdown 系列/done）全部覆盖；upload_file 合并进 browser_input_text 族（CDP DOM.setFileInputFiles）。

工具执行统一走"快照刷新 → 锁 → 锚定 → 执行 → 审计"管线（第 5/6 节），**不允许绕过锁的直接执行路径**（防止未来工具扩展时破坏协同语义）。

复杂度：常规（纯注册面工作，复用既有基础设施）。

## 9. 安全（策略）

| 面 | 策略 | 证据/依据 |
|----|------|-----------|
| loopback 端口 | 随机高位端口 + `--remote-debugging-address=127.0.0.1` 显式 + `--remote-allow-origins` 限定 Tauri 前端 origin；**连接后身份校验**：比对 `/json/version` 的 Browser 标识与启动时生成的 token（DevToolsActivePort 同款机制），防其他进程抢占端口 | browser-use `profile.py:28`（避开默认 9222 冲突）；chrome-devtools-mcp `browser.ts:84-111` |
| 域名白名单 | allowed_domains / prohibited_domains 全导航前置校验（含通配符规则与 O(1) set 优化），block IP 直连（防 SSRF/localhost 探测） | browser-use `profile.py:617-628`（allowed/prohibited 语义）、`:625-628`（block_ip_addresses） |
| 审批 | 复用 agent-tools permission 三态：危险动作（提交/支付/发布/跨域导航/关闭 tab/打开下载）→ NeedsApproval → 前端审批对话框（附截图+高亮，见 6.3） | `agent-tools/lib.rs:5-6`、`definition.rs:38-40` |
| 审计 | 所有 browser_* 动作发射 security-audit（含参数脱敏：密码字段遮罩），denied 决策计数进月度统计 | `agent-tools/audit.rs:22`、`:107-124` |
| 渲染隔离 | 第三方页面只经 CDP 帧流渲染进 canvas，**主 Tauri webview 永不执行页面代码**（消除 XSS 面）；输入转发不跨域读 DOM | 第 1/2 节架构 |
| 页内执行 | browser_evaluate 默认 Deny；快照 JS 走固定白名单脚本（不可被 AI 参数化任意注入） | 第 8 节 |
| 数据面 | 下载文件落应用托管目录 + 打开需审批；profile 复制仅在用户显式授权向导内进行 | 第 7 节 |

复杂度：常规（全部复用既有设施 + 参考库的成熟参数）。

## 10. 电脑操作（Computer Use）二期

### 体验关系：能否复用面板？

**能，且应当复用**。浏览器线落地的四件套——① canvas 帧渲染管线、② 输入转发管线、③ 操作指示条/接管/审批 UI、④ 动作日志回放——与"操作哪个目标"无关。Computer Use 只需替换两个数据源：

- 帧源：CDP screencast → 系统屏幕捕获（Windows：DXGI Desktop Duplication / BitBlt 兜底）；
- 输入注入：CDP Input → 系统级注入（Windows：`SendInput`；对齐 computer-use-demo 的 xdotool 定位，`computer.py:126`、`:256-266`）。

其余（指示条、用户抢断、审批、日志、锁定语义）原样复用——**这正是产品体验一致性所在：无论 AI 操作浏览器还是桌面应用，用户看到的是同一种交互语言**。

### 难度评估

- 全量独立实现：**3 倍+**（窗口句柄/焦点管理、DPI 多屏坐标换算——参考 `computer.py:268-291` scale_coordinates、UAC 提权窗口、进程拉起、不可信应用的风险控制），按约束直接放弃"一期并行"。
- 共享管线后的增量：**1-2 倍**，可作二期独立项目。
- 范围建议：二期限定"当前焦点窗口 + 单显示器 + 无 UAC"为 v1 边界；操作系统级（跨窗口/虚拟桌面）列为三期。

结论：**二期立项，架构上自一期起把"帧渲染 + 输入转发 + 指示条/接管/审批/日志"抽象为与数据源解耦的协同组件**（Rust 侧 trait + 前端组件接口），一期浏览器线即按此组件边界实现。这是唯一需要在一期就做的"前瞻性"设计，成本极低（一个 trait + 前端 props 契约）。

- 依赖：tokio / tokio-tungstenite / serde（CDP）；rusqlite（历史直读，只读）；一期不引入 windows crate（二期再入）。

复杂度：常规（crate 边界即模块边界，无架构新大陆）。

## 12. 复杂度汇总与主要风险清单

### 复杂度汇总

| 等级 | 维度 | 说明 |
|------|------|------|
| 常规 | 控制通道、定位/重试、工具集、安全、crate 划分 | 全部复用既有设施或参考已验证模式 |
| 1-2 倍 | 渲染实例、Rust CDP 客户端、感知快照、协同模型、数据导入 | 主工作量区，均为有界工程，无 3 倍 单项 |
| 3 倍+（放弃/推迟） | CEF 渲染（放弃）、Computer Use 全量独立（推迟至二期共享管线） | 明确排除，不进入一期范围 |

### 风险清单（按影响排序）

1. **screencast 帧延迟与帧率**（协同体验根基）——本地 loopback 实测先行，必要时降级"静态帧 + 事件提示"模式；用户交互期间帧率不承诺。
2. **Chrome 127+ App-Bound 加密**（profile 复制线）——启动后 `Network.getAllCookies` 回读校验，失败域名引导用户面板内重新登录（仍比纯复制体验好）。
3. **面板内输入转发的 IME/剪贴板**（中文输入法）——专项测试（仓库已有 IME 测试资产惯例），`Input.insertText` 路径兜底。
4. **attach 模式下用户浏览器内输入对 AI 不可见**（只能靠 DOM 变化感知）——产品上 attach 模式定位为"AI 辅助浏览"而非"全自动执行"；全自动执行建议回到面板内模式。
5. **CDP 客户端自研的协议面**——锁定域子集并做 fixture 级测试（仓库测试资产惯例）；重连/超时对齐 browser-use 参数。
