## 1. P0 裁决（高严重度，编码前必须闭合）

### R-1 snapshotVersion 架构（评审 19-H1/H2、20-Top2、21 交叉引用）

**裁决**：版本**按标签页独立**（`snapshot_version(tab_id) -> u64`），会话级辅助 `global_epoch` 用于跨标签事件（如崩溃重启）。
- 推进规则**单一权威**（修订 11 文档，以 15 清单为基础统一）：
  - 导航提交 +1；DOM 变更聚合 **200ms** 窗口合并 +1（撤销 50ms）；用户输入注入（面板转发）+1；AI 动作执行 +1；对话框出现/关闭恒推进（**宁多勿漏**，撤销 11 的"不推进"）；console/network/滚动不推进。
- 接口签名统一：`validate_snapshot(tab_id, version) -> Result<(), Stale>`（13/14/15 共用）；11 的 `current_version()` 改为 `snapshot_version(tab_id)`。
- 理由：多标签是产品能力，会话级单值会使非活跃标签的版本互相污染；"宁多勿漏"避免漏推进导致的陈旧操作。

### R-2 目录布局与持久化单一权威（评审 19-H3/H4/H6、20-Top3）

**裁决**：统一根 `<data_root>/conex/browser/`（应用目录名统一 **conex**，撤销 Crish）：
- `sessions/<session_uuid>/`：临时 profile（导航栈 `nav_stack.json`）；会话结束**直接删除**（非用户资产，不走 trash，以 10 为准）；
- `managed/<profile_name>/`：用户导入/持久化 profile（`profile_meta.json`，含 `persist` 开关**唯一**存于此，撤销 panel-state.json 双源）；删除走 **conex-fs trash**（用户资产，以 16 为准）；
- 面板 UI 状态（标签/URL 序）另存 `panel-state.json`（纯 UI，不承载持久化开关）。
- 理由：临时/受管两类资产的删除策略不同（非用户资产 vs 用户资产），目录分层同时解决三处冲突与"trash vs 直删"矛盾。

### R-3 CDP 域命令清单补齐（评审 19-H5）

**裁决**：维度 11 域清单 12→**13 域**，补齐：`DOMSnapshot`（captureSnapshot，13 主采集依赖）、`DOM.pushNodesByBackendIdsToFrontend`、`DOM.scrollIntoViewIfNeeded`、`DOM.focus`、`Runtime.getProperties`、`Page.getLayoutMetrics`、事件 `Page.fileChooserOpened`、`Storage.getCookies`、`Storage.setCookies`。命令清单随之扩充（59→约 72），11 文档补全。
- 理由：13/14/16 的实施依据已落在 11 未列的命令上，S1 门禁否则连带返工。

### R-4 type 分块节奏统一（评审 19-H7、20-B4、21 参数矛盾）

**裁决**：**50 字符/12ms** 分块节奏（以 14 为准）；撤销 15 的"≤5 字符"；分块间 abort 检查与回读校验保留（14 设计）。
- 理由：50/12 为业界实证节奏（防丢字与防节流平衡），5 字符为误写。

### R-5 wait_for 定位面与注入面（评审 19-H8、21-C1 高）

**裁决**：
1. 条件参数支持两类：快照索引（内部解析为 backendNodeId）与**纯文本/URL 字符串匹配**（禁止 CSS selector 与 JS 表达式入参——与 14"禁选择器"一致，撤销 15 的 selector 条件）。
2. **注入面修复**：文本匹配实现为固定代码模板 + 参数 **JSON 序列化注入**（`JSON.stringify` 包裹，永不经字符串拼接进代码文本）；谓词代码无模型输入；wait_for 分级保持"普通"，但实现层禁止任何参数拼入代码。
- 理由：消除"无审批的任意 JS 执行面"（评审 21 高危）。

### R-6 evaluate 唯一设计（评审 19-H9、20、21-C2 高）

**裁决**：以维度 17 的 `__crish_read` 白名单代理 + 三层校验（静态词法 → isolated world 执行 timeout 2s → 结果预算 64KB/深度 4）为**唯一设计**；撤销 14 的"编译期 helper 表 + 自由求值"双轨（14 的 evaluate 原语改为调用 17 的受限实现）。
- **运行时保险补齐**（回应 21-C2）：隔离世界内仅暴露白名单代理对象（方法白名单 + `constructor` 链检查：拒绝 `[].filter.constructor` 类逃逸），DOM 访问仅经代理；审批不变（dangerous + 默认拒绝）。

### R-7 域名门禁单一实现（评审 20-Top1、19-H 交叉）

**裁决**：`DomainGate` 结构与匹配语义以**维度 17 为唯一权威实现**；维度 14 §7.2 删除自建结构，改为引用 17 接口。
- 通配符语义定死：`*.example.com` = 任意子域（**不含** example.com 根域）；`example.com` = 根域 + 任意子域（等效 `*.example.com` 并集）；IP 字面量/IPv6/IPv4 映射、内网段阻断语义以 17 清单为准；黑名单不可豁免（含 full-access）。

### R-8 重试额度统一（评审 20-B4）

**裁决**：版本失效/节点过期重试**计入** 3 次总上限（14 为准，防无限循环）；**Aborted/Stale（用户接管吊销）不计入**（15 保留）；两者在错误分类中显式区分。

### R-9 断线/重启期动作行为（评审 20-B5、19-M 系）

**裁决**：
1. `ActionErrorKind` 增加 `ConnectionLost` / `TargetRestarting` 两类；
2. 恢复期工具调用返回结构化 `browser.not_ready` 错误码（工具层 gating）；
3. 维度 11 重连恢复清单补 **startScreencast 重启**（恢复后通知 12 重启帧通道）；
4. 崩溃重启（10 状态机）完成前，工具面不可用且前端指示条显示恢复中。

### R-10 面板 WS 通道凭据面（评审 21-C4 高）

**裁决**：帧 WS 与命令通道共用会话 token；**token 不进 URL**（帧通道握手经自定义 header 传递，前端持有引用、不落日志）；加 **Origin 校验**（仅放行应用自身 origin）；补日志纪律回归测试（断言端口/WS path/token 不出现在任何日志）。
- 理由：评审指出"同源派生未定义 + 明文进 query"——header 传递 + Origin 校验闭合凭据面。

### R-11 SSRF 传输层实现（评审 21-C3 高）

**裁决**：维度 17 补实现 `Network.setBlockedURLs`（页面级传输层阻断内网/IP 直连请求，响应 11 §3.3 声明）；动作检查点承诺**解析级校验**（导航前解析并校验 IP）；DNS 重绑定缓解：校验通过后 60s 窗口内重复校验（每动作一次）。
- 落点：17 门禁模块增加"传输层 + 解析层"双层。

### R-12 attach 型 MCP 权限收敛（评审 21-C5 中）

**裁决**：外部 MCP attach 同一 CDP 端点时挂**只读能力集**（snapshot/screenshot/console/network）；交互/求值类工具按 17 权限矩阵审批（默认拒绝）；会话级开关控制 attach 允许与否。
- 理由：attach 型 MCP 若获全权（全量 cookie + 任意 evaluate）与权限矩阵冲突。

## 8. 红队轮最终裁决（主 Agent，方案质量兜底）

> 输入：23-红队-渲染与可见性挑战（RT-1）/ 24-红队-否决复审（RT-2）/ 25-红队-假设审计（RT-3）。
> 三份报告立场存在张力（RT-1/RT-2 有条件维持、RT-3 主张 MVP 砍缩），本裁决为最终收敛。

### 8.1 红队核心发现（采纳为事实）

1. 帧流+输入转发**有生产先例**（agent-browser dashboard、skyvern /stream/cdp_input），复杂度有实数可依；但**中文 IME 隐藏输入框桥为全行业首个完整设计、零实测背书**——方案最大单点风险。
2. 输入转发是**执行面必要条件**（即时接管/吊销 AI 在途动作必须输入事件在 Rust 侧可见），版本失效只覆盖"事后检测"；但可独立挂载（"帧流保留+输入禁用"形态合法）。
3. WebView2 否决**理由重心重构**：核心变为"无 SLA + Evergreen 不可钉版本"（CfT 版本钉死是当前方案的核心缓解）；注入桥感知通道部分撤销（只读上报、默认关，登记为 P1 备选）。
4. 40 项裁决中 **52% 为文档自洽修补（B 类）**、C 类 2 项（R-1 per-tab、R-6/R-12 依附）——评审体系健康的标志，但也是方案规模膨胀税。
5. 假设审计：多标签（H-2）、导入全家桶（H-4）、evaluate（H-5）均为"完整产品"级而非"验证产品"级需求。

### 8.2 最终裁决（R-13：实施分层）

**架构主线（D-1/D-3/D-4/D-5/D-9）维持不变**；将 S0-S10 实施链重构为**三层递进**，MVP 先行验证核心价值，高杠杆增强推迟到实证达标后：

**MVP（M0-M8，验证产品）**——目标：软件内 AI 操作浏览器、用户可见可打断，1-2 天 Agent 并行可交付：
1. 受管独立 Chromium 实例（CfT 优先/系统回退）+ 随机端口 + DevToolsActivePort
2. CDP 客户端 + 事件总线（**会话级版本号**，R-1 per-tab 推迟）
3. 引导登录 + persist 开关（仅此两项，其余导入推迟）
4. **headed 可见窗口**（无帧流面板、无输入转发、无 IME 桥——RT-3 采纳）+ 指示条/急停
5. 单标签快照（DOM 简化树 + 索引）
6. 动作执行（无 evaluate；click/type/key/scroll/select_option/upload）
7. browser_* 工具子集挂 agent-tools（审批/审计接线）
8. 版本失效 + 粗粒度令牌协同（吊销基于可见窗口语义：AI 动作前快照校验 + 用户可停）
9. 验收：S0 的 P0-1/P0-3/P0-5/P0-6 + MVP e2e

**P1（完整产品，S0 实测达标后启动）**：
- 帧流 + 输入转发 + IME 桥——**硬门槛 G-1（帧延迟 ≤120ms）/ G-3（中文 IME 全流程，微软拼音实测）前置 S0**，不达标维持 headed 窗口形态（不切 WebView2）
- 多标签（恢复 R-1 per-tab 版本 + MAX_TABS）
- evaluate 白名单（R-6 全套）、剪贴板桥
- 复制迁移/storage_state/书签历史（App-Bound P0-4 实证后）
- MCP attach（只读能力集）
- 注入桥感知通道（默认关，登记）

**P2（差异化增强）**：电脑操作二期（18 文档按原计划）。

### 8.3 附带裁决

- S0 spike 清单扩展：G-1 帧延迟、G-3 中文 IME、G-2 输入延迟 ≤30ms、G-4 接管 ≤800ms、P0-4 App-Bound 实证；**登记 WebView2 复合方案为"帧流路线 Go/No-Go 不达标时的 Windows 专案"**（RT-2，复用面为零、CDP 客户端/快照/协同/引导登录原样套用）。
- B 类裁决（文档自洽修补）保留于文档层（一致性仍重要）但**不驱动 MVP 代码**；C 类（R-1）随 MVP 会话级版本简化，P1 恢复。
- 09 D-3 补注：注入桥仅作感知增强（默认关）。
