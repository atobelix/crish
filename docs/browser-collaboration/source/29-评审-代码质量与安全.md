# 评审：代码质量与安全（E1，Rust 域）—— conex-browser / conex-browser-tools

- 评审范围：`crates/conex-browser/src/`（cdp/ browser/ snapshot/ action/ import/ lib.rs）+ `crates/conex-browser-tools/src/`（含 tools/）
- 评审方式：全量实读（关键路径逐文件），panic 面/unsafe/tokio::spawn/索引越界/字符串切片等模式系统扫描
- 结论：整体工程质量高（锁纪律 B8 恢复式、CDP 宽容解析、脱敏纪律贯穿），以下按严重度列出**可复现、可修复**的具体问题。共 **25 条**：必须修 6 / 建议修 10 / 记录 9。

---

## 一、必须修（高）

### H1 [安全·域名门禁绕过] MvpDomainGate 对「非字面量形态的内网地址」全部放行
- 位置：`crates\conex-browser-tools\src\gate.rs:184-215`（check 的 IP 判定）+ `gate.rs:15-17`（模块头自认遗留）
- 问题描述：默认策略声明「白名单为空 = 全允许（限公共互联网）」，但**仅对 `url::Host::Ipv4/Ipv6` 字面量做保留段判定**。以下形态均被 `url` crate 解析为 `Domain`，走 `allow_host`（空白名单直接放行）：
  1. **十进制/十六进制/八进制 IP**：`http://2130706433/`（=127.0.0.1）、`http://0x7f000001/`、`http://0177.0.0.1/`——Chrome 导航时全部规范化为 127.0.0.1；
  2. **DNS 名解析到保留段**：`http://localhost/`、`http://localtest.me/`（解析到 127.0.0.1）、`host.docker.internal`、任意 `nip.io` 形态——模块头 15-17 行自认「对主机名不做解析，仅字面量判定」；
  3. 单标签主机名（`localhost` 与 `intranet` 类）无任何拒绝规则。
- 触发条件：恶意页面/模型引导浏览器导航到上述 URL（默认配置、无白名单），即可绕过「限公共互联网」打到本机/内网服务（SSRF 面）。
- 修复建议（代码级）：
  - 对 `Host::Domain` 先做数值形态还原：`ip_str.parse::<IpAddr>()` 之外，增加「纯数字/0x/0o 前缀」整型 → 四段点分还原后二次过 `allow_ip`；或以 `url::Host::Domain` 时禁止「全部由数字/0x 组成」的主机名；
  - 至少补：单标签主机名（无 `.`）一律拒绝（除 about 特例），`localhost` 显式列入保留表；
  - 正式实现按模块头承诺接入 DNS 解析级校验（§4.3 步骤 3）与 60s 重绑定窗口（步骤 4）；在接线前，将上述拒绝规则落入 MVP。

### H2 [并发·版本推进丢失] VersionTracker 合并窗口 flush 竞态：新 pending 被陈旧任务吞掉
- 位置：`crates\conex-browser\src\cdp\version.rs:261-273`（`commit_pending`）
- 问题描述：`pending` 是**全局单槽**（非 per-tab）。窗口内 tab A 的 DOM 事件置 pending(gen=1) 并 spawn flush；随后 tab B 的 DOM 事件替换为 pending(gen=2) 并 spawn 第二个 flush。第一个 flush 醒来时 `guard.pending.take()` 取走的是 **gen=2 条目**，比对不匹配后**直接丢弃而不归还**（`if p.gen == gen { ... }` 的 else 分支为空）→ tab B 的版本推进永久丢失。
- 触发条件：两个标签在 200ms 窗口内先后发生 DOM 变更（多标签协同的常态）。
- 后果：tab B 的 snapshot_version 不推进 → `validate_snapshot` 误判有效 → 动作作用于过期快照（点击旧坐标/旧索引），且无任何 Stale 信号。
- 修复建议：
  ```rust
  // commit_pending：先匹配再取，不匹配不得 take
  let matched = guard.pending.as_ref().filter(|p| p.gen == gen).cloned();
  if let Some(p) = matched {
      guard.pending = None; // 仅同代才清除
      commit_bump_locked(&mut guard, watch_tx, bus_tx, &p.tab, p.reason);
  }
  ```
  另建议：`on_event` 合并分支（version.rs:117-131）在 pending 被异 tab 替换时也丢了前一 tab 的窗口（同根因），最小修复是把 pending 改为 `HashMap<TabId, (reason, gen)>` 按 tab 独立槽位。

### H3 [并发·错误语义] CommandSender 幂等缓存短路时，在途合并等待方收到 Cancelled
- 位置：`crates\conex-browser\src\cdp\sender.rs:318-357`（execute ①/①' 步）
- 问题描述：同 IdKey 并发调用：调用方 A 先插入 in_flight 表并创建 `InFlightGuard`（armed=true），随后在 `hooks.idempotent(key)`（①' 步）命中**已完成命令缓存**并 `return result`——guard 的 `Drop`（sender.rs:285-297）检测到未 publish 且 armed，向共享 broadcast 发布 `Err(Cancelled)`。调用方 B（在 ① 步合并等待中）因此拿到 **Cancelled**，而 A 拿到正确缓存结果。
- 触发条件：任何实现 `idempotent` 缓存命中的引擎侧 hooks + 同键并发调用（如双击触发同一开关命令、面板与 Agent 并发同命令）。
- 修复建议：缓存命中分支先发布再返回：
  ```rust
  if let Some(result) = self.hooks.idempotent(key).await {
      if let Some(g) = guard.as_mut() { g.publish(result.clone()); }
      return result;
  }
  ```
  （或把 ①' 缓存检查提前到 ① 在途表插入之前，双路径同语义。）

### H4 [安全·门禁复核缺口] browser_navigate / browser_new_tab 缺「动作后门禁复核」
- 位置：`crates\conex-browser-tools\src\tools\navigate.rs:96-121`（NavigateTool 仅前置检查）、`navigate.rs:396-419`（NewTabTool 同）
- 问题描述：`Page.navigate` 到**白名单内 URL 后被 302 重定向**到内网/保留段地址时，无任何复核。对比：`action/mod.rs:443-463`（run_once ⑥）与 `BackTool/ForwardTool/ReloadTool`（navigate.rs:163-170、219-226、279-290）都有动作后 URL 复核 + 回退 + GateDenied，唯独 `browser_navigate`（最主要入口）与 `browser_new_tab` 缺失。
- 触发条件：`https://example.com/redir` 服务端 302 到 `http://192.168.1.1/admin`（或 `http://localhost/`）——Chrome 对 http(s)→http(s) 跨网段重定向不拦截。
- 修复建议：把 `verify_after_navigation`（navigate.rs:23-44）接入 NavigateTool（导航后 `target_info` 拿到 actual URL 后复核），NewTabTool 在建标签后同样复核新页 URL（可用轮询 `Target.getTargetInfo` 至帧导航完成）。

### H5 [健壮性·栈溢出/目录逃逸] import_copy 递归复制无符号链接处理
- 位置：`crates\conex-browser\src\browser\profile.rs:294-332`（`copy_tree`）
- 问题描述：`src_path.is_dir()/is_file()` **跟随符号链接**，且无任何 symlink 分支：
  1. 源 profile 含 symlink 自环/互环（如 `a -> b`、`b -> a`）→ 无限递归 → **栈溢出崩溃**；
  2. symlink 指向源树外任意目录（如 `C:\`、`/etc`）→ 整目录被复制进受管 profile（数据面意外扩张/耗尽磁盘）；
  3. `is_dir`/`is_file` 与后续 `std::fs::copy` 之间存在 TOCTOU（可被并发替换为链接）。
- 触发条件：用户导入一个被篡改/异常构造的 Chrome 用户数据目录（攻击面：恶意 profile 目录被诱导导入）。
- 修复建议：改用 `symlink_metadata` 判定：`FileType::is_symlink()` → 跳过并计入 skipped（或复制链接本身）；另加总节点数/字节上限与递归深度上限（防御环的另一道保险）。

### H6 [并发·双启动竞态] BrowserManager::start 跨 await 无互斥，并发调用可双启浏览器进程
- 位置：`crates\conex-browser\src\browser\mod.rs:334-397`
- 问题描述：`already_running` 检查（335-341）与 `machine.on(StateEvent::Start)`（360-377）之间隔着 `sweep_orphans`、`resolve_backend(...).await`（346-354）、`prepare_profile`（356）等**非原子窗口**。两个并发 `start()` 都读到 Stopped → 各自 resolve/profile → 各自 `machine.on(Start)`（`debug_assert!` 在 release 无保护，第二次迁移落意外分支被忽略）→ 各自 `tokio::spawn(drive_session)` 且**第二个覆盖 `g.driver`**（第一个驱动句柄被丢弃）→ 两个浏览器进程、两个 profile 目录、`endpoint` 互相覆盖。模块注释宣称「幂等 start（§4.5 引擎内互斥）」但互斥面未覆盖 await 区间。
- 触发条件：引擎/面板同时触发启动（或 crash 自愈与手动 restart 交错）。
- 修复建议：在 BrowserManager 内加一把 `tokio::sync::Mutex` 包住 start/stop/restart 的「检查-启动」临界区；或先置 `machine.on(Start)`（状态先占位）再 await 后续步骤，使第二个调用方看到非 Stopped 直接走 `current_report()`。

## 二、建议修（中）

### M1 [资源·内存面] WS 消息无尺寸上限 + 快照载荷护栏晚于完整接收
- 位置：`crates\conex-browser\src\cdp\client.rs:143-145`（`max_message_size(None)`/`max_frame_size(None)`）、`crates\conex-browser\src\snapshot\collect.rs:636-643`
- 问题描述：传输层显式不设上限（为「快照/帧可能超大」），但 150KB 载荷护栏（collect.rs:637-643）在**完整反序列化为 `Value` 之后**才触发——对抗性大 DOM 页面（如数百万节点）可让 `DOMSnapshot.captureSnapshot` 返回数百 MB 级响应，整包缓冲 + `to_string()` 二次物化 → 内存尖峰/OOM。`parse_frame` 的 base64 解码同样无尺寸护栏（bus.rs:453-456）。
- 修复建议：reader 侧按帧累计字节数设上限（如 64MB，超限断连或丢弃并告警）；`parse_frame` 对 `data` 长度预检（≤ 32MB）；快照命令超时/护栏前置于 `send_page` 响应到达即可。

### M2 [功能缺口] is_password 恒 false → 密码框 type 回读必然失败
- 位置：`crates\conex-browser-tools\src\session.rs:268-273`（element_meta）、`session.rs:367-374`（element_by_index）
- 问题描述：快照序列化面已有脱敏（redact.rs），但元数据未携带密码标记，工具层两处 `is_password: false` 硬编码。`keyboard.rs:440-460` 的 `verify_progress` 对非 password 走**全文本前缀比对**——密码框回读（页面屏蔽/掩码态）必然不一致 → 连续 2 块失败 → `NotInteractive`（keyboard.rs:400-407），密码框输入功能在工具面不可用。
- 修复建议：`SnapshotMeta`/`SerializeOutput` 增加 `password_backend_ids: HashSet<i64>`（redact 判定同源），`element_meta`/`element_by_index` 透传；同时给 `serialize.rs` 输出加「密码字段」标记（不泄值）。

### M3 [资源·任务泄漏] NetworkCounter 每实例泄漏常驻订阅任务；CdpClient/Transport 无 Drop 关闭
- 位置：`crates\conex-browser\src\action\ops.rs:130-156`（`NetworkCounter::new` tokio::spawn 永活）、`crates\conex-browser\src\cdp\client.rs:91-92/245-247`（reader/keepalive JoinHandle 仅存储不 await）、`crates\conex-browser\src\cdp\transport.rs:152/394`（supervisor/forward 任务）
- 问题描述：
  1. 每个 `BrowserPageOps::new`（=每次新 `RealSession`/执行器）都会 spawn 一个**永不停**的广播订阅任务（直到总线关闭），会话重建 N 次即积累 N 个空转任务；
  2. `CdpClient` 被 Drop 但未 `close()` 时（如 Transport drop 不 shutdown），reader/keepalive 任务与 TCP 连接继续存活直到对端关闭——`Transport::drop` 无任何收尾。
- 修复建议：`NetworkCounter` 改为显式 `stop`（watch 通知退出）并在 ops 生命周期结束（Arc 归零）时触发；`Transport` 实现 `Drop`（无法 await 时：abort supervisor handle + 经 `try_lock` 取 client 发送 Close 帧的 best-effort 或登记资源回收任务）。

### M4 [错误语义] CdpError::Internal/Serialize 误映射为 ContextGone
- 位置：`crates\conex-browser\src\action\ops.rs:197`
- 问题描述：`CdpError::Internal`（如命令结果反序列化失败）与 `Serialize` 映射为 `ActionErrorKind::ContextGone` → 重试状态机按「导航竞态」做 300ms 延迟重试 ×3（retry.rs:58-61 策略），白白耗 900ms 且掩盖真实错误（内部错误重试不会自愈）。
- 修复建议：新增 `ActionErrorKind::Internal`（Fatal 策略，不重试）或归入 `Unsupported`；`BadParams/Protocol → InvalidInput` 已正确，保持。

### M5 [健壮性] 驱动任务 panic 后管理器永久卡死
- 位置：`crates\conex-browser\src\browser\mod.rs:375-377`（driver spawn）、`mod.rs:400-437`（stop 依赖 driver）、`mod.rs:232`（`wait_task` 的 expect 不变量）
- 问题描述：`drive_session` 内任何 panic（tokio JoinHandle 二次 poll、expect 不变量被打破等）→ `g.driver` 仍为 `Some(JoinHandle)`（任务已死）→ `stop()` await 死任务后返回 `state = machine.state()`（非 Stopped），且 `start()` 永远走 `already_running` 分支 → **管理器不可恢复**，无任何 watchdog。Drop 兜底（mod.rs:1072-1081）`try_lock` 失败时同样放弃杀树。
- 修复建议：driver 任务外包 `catch_unwind`/`AssertUnwindSafe`，panic 时回调置机器 Stopped + 清 driver + 广播终态事件；`stop()` 在 driver 为死句柄时主动收敛状态机。

### M6 [安全·脱敏缺口] 三类脱敏绕过
- 位置：
  1. `crates\conex-browser\src\snapshot\redact.rs:47-50`：`type=password` 用 `eq_ignore_ascii_case("password")` **未 trim**——`type="password "`（尾随空白）即不敏感，value 明文进快照（对照 autocomplete 分支 redact.rs:54 已 trim，不一致）；
  2. `redact.rs:111-124`（`redact_fragment`）：仅匹配文本形态 `value=`；JSON 形态日志片段（`{"value":"s3cret","type":"password"}`）中 `value=` 不存在 → 不脱敏；
  3. `crates\conex-browser-tools\src\helpers.rs:204-207`（`redact_url_query`）：`Url::parse` 失败**原样返回原始 URL**（含 query 敏感参数）。
- 修复建议：1) type 值先 `trim()`；2) `redact_fragment` 增补 `"value":` 与 `"type":"password"` 共现判定；3) parse 失败时按保守策略输出 `<redacted>` 或至少剥 query 段。

### M7 [安全·供应链/资源] CfT 下载解压无尺寸与完整性校验
- 位置：`crates\conex-browser\src\browser\cft.rs:289-304`（下载无 Content-Length 上限）、`cft.rs:328-384`（解压无总字节/条目数上限）、`cft.rs:407`（`chrome-{version}` 目录名直接拼接 LKG 网络 JSON 的 version 串）、`cft.rs:408-414`（"不校验 hash，§2.2"）
- 问题描述：LKG 端点被劫持/篡改时：超大 zip → 磁盘耗尽；zip 炸弹（高压缩比）→ 解压写爆磁盘；version 串含路径分隔符（注入）→ 目录逃逸。当前仅 HTTPS 通道信任 + `enclosed_name` 防穿越。
- 修复建议：解压前校验 zip 内总条目数与未压缩总字节上限（超限中止并清理）；下载按 `Content-Length` 预检（如 ≤ 500MB）；`chrome-{version}` 目录名经 sanitize（与 `sanitize_profile_name` 同规则）；P1 补 sha256 校验清单。

### M8 [健壮性] 异步上下文中的 std::thread::sleep 阻塞 tokio worker
- 位置：`crates\conex-browser\src\browser\profile.rs:120`（`remove_dir_retry` 100ms×3）、`crates\conex-browser\src\browser\platform\windows.rs:186`（`resume_main_thread` 20ms×3）
- 问题描述：两处均可能从 `drive_session`（async 驱动任务）调用链触发，同步 sleep 占用 tokio worker 线程（最大 300ms/60ms）。单次不致命，但驱动任务内多次失败叠加会挤占运行时线程池。
- 修复建议：`remove_dir_retry` 增加 async 变体（`tokio::time::sleep` + `spawn_blocking` 执行删除）；resume 重试改 `tokio::time::sleep`（函数需 async 化或调用点注入）。

### M9 [竞态·版本推进与快照采集] SnapshotManager 全局限流 + 非活跃标签预算竞态
- 位置：`crates\conex-browser\src\snapshot\mod.rs:316-335`（capture 状态机为全局单槽）
- 问题描述：
  1. `state` 为全局 `Mutex<Option<CaptureEntry>>`——**不同标签**的并发快照也互相 Busy 互斥，多标签协同下第二个标签快照直接失败（`Busy` 错误由工具面按失败处理，未等待重试）；
  2. `capture(tab, active)` 的 `active` 参数在采集窗口内不重读——标签被激活/版本推进后仍按 0.25 系数采集低配快照（模块注释声称「标签被激活后自动升级」，实现未落实）。
- 修复建议：状态机键化（`HashMap<TabId, CaptureEntry>`）；`active` 在提交前重读标签活跃度/版本。

### M10 [竞态·启动与清理] `cleanup_staging`/`sweep_orphans` 与并发导入/启动的窗口竞态
- 位置：`crates\conex-browser\src\import\persist.rs:141-162`、`crates\conex-browser\src\browser\profile.rs:358-382`
- 问题描述：启动时 `sweep_orphans`（sessions/ 下 mtime 超阈值直删）与 `cleanup_staging`（managed/.staging/ 直删）为 best-effort 无互斥——若导入流程正在写 staging、或新会话 profile 目录 mtime 恰好超阈值（时钟回拨场景），可能被并发清扫删除。当前阈值 2 天 + 时钟回拨概率低，但删除语义属破坏性操作，建议对「正在使用的 staging 前缀（`{target}-{tmp_id}`）」加白名单或删除前二次校验 mtime/持有锁。

## 三、记录（低）

### L1 `snapshot\mod.rs:386` 的 expect 已兜底
- 位置：`snapshot\mod.rs:378-386`。`previous` 经 `if previous.is_none() { previous = Some(HashSet::new()) }` 兜底后 expect 不可达，但建议直接用 `unwrap_or_default()` 去掉 panic 形态，消除「不可达 panic」审查噪音。

### L2 `browser\mod.rs:232` wait_task expect（不变量保护）
- 位置：`browser\mod.rs:228-235`。`child` 在 `wait_task()` 调用后被 take，重复调用即 panic——当前 `drive_session:639` 仅调用一次，属设计不变量。建议改为 `Option` 语义（`take().expect`）或文档化禁止二次调用，防止后续重构踩雷（该 panic 面与 E5 根因同类，曾真实炸过驱动任务）。

### L3 `dialog.rs` gen 字段未使用
- 位置：`cdp\dialog.rs:79、171`。`spawn_timeout` 的代数由「状态存在性」隐含（注释已说明），`gen` 已无实际用途，建议删除字段与 `let _ = gen` 以减噪。

### L4 `navigate.rs:438` expect（越界检查后必命中）
- 位置：`browser-tools\src\tools\navigate.rs:422-439`。`target_by_seq` 在 `seq as usize > targets.len()` 检查后 `nth(seq-1).expect`——逻辑正确但建议 `nth(seq as usize - 1).ok_or_else(...)` 消除 panic 形态（低成本）。

### L5 `domains.rs` LayoutViewport 双形态回退取错
- 位置：`cdp\domains.rs:335-341`。`viewport_x` 以 `page_x != 0.0` 判别新形态——当新形态 `pageX == 0`（页面滚动回顶）且旧字段 `x` 恰好非零（异常混合报文）时返回旧值。Chrome 151 实测同报文不共存，概率极低；建议显式以「字段存在性」判别（`Option<f64>` 双字段）。

### L6 `gate.rs` 配置校验放宽项
- 位置：`browser-tools\src\gate.rs:80-91`。`validate_host_part` 允许 `a..b`、前导/尾随连字符、`.` 重复等形态；`*.com` 可配置（命中任意 .com 子域）。属配置错误面而非绕过，建议对齐 public-suffix 校验或至少拒绝空标签。

### L7 `BrowserManager` Drop 的 try_lock 失败路径
- 位置：`browser\mod.rs:1072-1081`。`Drop` 中 `try_lock` 失败（锁被占用）即放弃杀树，进程可能遗留。Drop 不可 await，建议在 `stop()`/`finish_stop` 正常路径保证进程回收（当前已覆盖），Drop 仅作最后兜底并在日志留痕。

### L8 `import\discovery.rs` info_cache 目录名直接 join
- 位置：`import\discovery.rs:193-201`。`profile_dir_has_data` 用 Local State 内 info_cache 的 `directory` 键直接 `user_data_dir.join(directory)`——本地文件信任面，但目录名含 `..`/分隔符时可探测任意路径存在性（信息泄露面极低）。建议复用 `sanitize_profile_name` 或拒绝含分隔符的键。

### L9 快照序列化行内控制字符未净化
- 位置：`snapshot\serialize.rs:909-1019`（render_node）。页面文本/属性值含 `\n`/`\r` 时原样输出，破坏「一行一元素」的结构化面（模型解析歧义），且与工具面 `validate_no_control_chars` 的护栏不对等。建议 `truncate_text` 输出前把控制字符转义为 `\x{..}`。
