## ② 逐维度评审裁决

### 1. 渲染实例：独立 Chromium 进程（否决 03 的 WebView2 主方案）

**结论：采纳 01/02/04 的独立 Chromium（CfT 为主、系统 Chrome/Edge 回退）+ CDP screencast 帧流渲染进 React canvas。**

否决 03 的 WebView2 主方案的三个硬伤：

1. **CDP 能力根基不稳**：03 自己承认 WebView2 CDP 属「官方但未列入稳定 SLA 的能力，随 runtime 更新可能行为漂移」（03 方案风险节）。安全体系建立在"行为可能漂移"的协议面上，基座不牢。独立 Chromium 的 CDP 是全行业三家参考实现（browser-use / chrome-devtools-mcp / agent-browser）共同验证的稳定面。
2. **数据导入维度全线投降**：WebView2 profile 与 Chrome 不兼容 → 03 被迫放弃 profile 复制、以 storage_state 为主路径——牺牲了"导入 Chrome 登录态"这一产品核心价值（02 明确这是与纯 AI 自动化方案最大的体验差异点）。
3. **与主应用共享 webview 运行时面**：03 依赖"独立 environment + 独立端口"来隔离，但 WebView2 与主 UI 同属一个运行时组件（04 指出），隔离靠配置不靠进程边界；独立 Chromium 是天然进程级沙箱 + 崩溃隔离 + 杀树可控。

**吸收 03 的唯一合理点**：`BrowserController` trait 双后端抽象（WebView2/Chromium）。但主后端固定 Chromium，WebView2 仅登记为"不推荐降级路径"，不作为默认。HWND 嵌入保留为 Windows 二期增强（01），macOS/Linux 走同一套 screencast 逻辑。

### 2. AI 控制通道：CDP 单轨 + isolated world 快照采集

**结论：CDP 单轨（四家共识）；快照采集经 CDP `Runtime.evaluate` 在 isolated world 执行（02 路线），不做页面注入事件桥作主感知。**

- 03 的注入事件桥是"用户操作感知"的最直接方案，但代价是向页面注入长期监听脚本（导航后需重注入、页面污染、CSP 冲突、被反自动化检测）。02 的 `Runtime.evaluate` 采集快照同样可感知页面状态，而用户干预检测在桌面场景可由"前端输入事件 + 焦点变化 + 导航事件"（04 路线）覆盖——不需要页面内监听。
- 注入桥降级为**可选增强**（默认关），仅当快照版本校验出现持续漏报时才启用——不在一期主链路。

### 3. Rust CDP 客户端：自写薄客户端（四家共识，无实质分歧）

自写（tokio-tungstenite + serde_json，agent-browser `cli/src/native/cdp/client.rs` 蓝本）；协议类型采纳 03 的 build.rs 从 `cdp-protocol/*.json` 生成子集（减少手写工作量）；命令发送层统一挂审计/幂等/审批/急停钩子（04 的 sender 分层）。此维度无争议，按最优组合落地。

### 4. 感知快照：DOM 简化树为主 + AX 辅助 + 视觉帧可选（否决 03/04 的 AX 主通道）

**结论：采纳 01/02 的 DOM 简化树（browser-use serializer 五步流水线移植）为文本通道主体；AX 树仅作复合控件/表单值补充；视觉帧经 `include_visual` 参数按需（03 演进设计）；`snapshotVersion` 一期内置（03）。**

否决 AX 主通道的理由（针对 03/04）：
- **定位精度**：DOM 简化树的 backend_node_id 直作模型 index → `DOM.resolveNode` 精确命中，O(1) 无损映射（01 证据 serializer.py:645-654）；AX 主通道需 backendDOMNodeId 反查，重定位链更长。
- **覆盖率**：无语义 div 的点击器在 AX 树中丢失（03 自认），browser-use 的 ClickableElementDetector 是多年调优资产，逐条移植是明确的价值。
- **token 论据不成立**：04 以"AX 隐私面小"支持 AX 主，但 03 自认巨型页面 AX 树同样 token 爆炸（需 compact/depth 裁剪）。隐私面由"字段级过滤（password/敏感域）+ 快照大小上限 + 截图审批"达成（04 的 §5 缓解），不必牺牲定位能力换取。
- 03 的正确部分（双通道 + include_visual + snapshotVersion）与 DOM 主通道不冲突，直接吸收。

### 5. 定位与执行：backend_node_id 直作 index，data-* 标记仅作可选确认（否决 04 的必选 data-*）

**结论：采纳 01 的 backend_node_id 直作 index（resolveNode 零页面污染）+ 坐标备 + JS click 兜底 + 执行前三重校验 + 重试 3 次 + 失败分类报告。**

- 04 的 data-* 属性注入（agent-browser 做法）会污染页面 DOM 且可被页面脚本清除。既然 backend_node_id 经 `DOM.resolveNode` 可直接命中，注入 data-* 并非必需——01 的"index 分配 + 碰撞时 synthetic index"更干净。data-* 仅登记为"执行前实时确认"的可选增强，不默认。
- 执行一律 CDP Input 真实事件（四家一致）；拒绝坐标魔术补偿（04 与仓库 AGENTS.md 红线一致）。

### 6. 协同模型：04 软互斥令牌 + 02 指示条/接管 UI + 03 snapshotVersion 统一

**结论：以 04 的 generation counter 令牌机制为内核（用户输入/导航事件递增 → 吊销 pending AI 动作；执行前后双校验；执行中吊销即中止），叠加 02 的操作指示条、用户接管 UI、审批附截图+高亮、动作日志回放。**

- 01 的 busy 互斥承认"无法拦截物理输入"，实质退化为检测+记录——与 04 令牌等价但缺执行中吊销与急停语义，否决。
- 03 的快照版本号与 04 的令牌本质是同一机制（页面变化 → 计数递增 → 旧快照/在途动作作废），统一为一个 generation counter，避免两套计数。
- 02 的接管语义（用户输入 → 取消在途 + 指示条切换 + 恢复前强制 re-snapshot）是产品信任核心，采纳。

### 7. 数据导入（专项裁决见 §③）：面板内登录为主 + 最小文件集复制向导 + 加密 storage_state

**结论：主路径 = 面板内登录（02 线一，协同模型免费产物，零隐私面）；复制线 = 04 最小文件集 + 02 同家族 exe/回读校验；storage_state = 03 的生态语义但按 04 加密落盘、默认不导出。**

否决 01 的整目录复制与 03 的明文 storage_state 主路径，详见 §③。

### 8. 工具集：browser_* 闭环 + chrome-devtools-mcp attach 补深（03 分工）+ 04 分级

**结论：自研 browser_* 约 16-18 工具挂 agent-tools 注册面（复用审批/审计/中止令牌），深度调试工具（lighthouse/trace/memory）不自研，由 chrome-devtools-mcp 插件经 `--browserUrl` attach 提供（03 分工矩阵），命名 `mcp_cdm__*` 与 `browser_*` 前缀隔离，权限双轨统一到三态引擎。分级按 04：evaluate Ask + isolated world；剪贴板默认 Deny；上传 Ask、下载隔离目录+打开 Ask；cookies Ask；登录/支付/发布类 Ask；导航 Allow 受域名门禁。**

### 9. 安全：04 全量 + 02 连接 token + 03 的 target 过滤

**结论：随机端口（`--remote-debugging-port=0`）+ DevToolsActivePort 解析 + 显式 127.0.0.1 + 会话 token 校验（02）+ 域名白名单三检查点（04：导航前/重定向后/新标签）+ block_ip_addresses 默认开 + 扩展默认禁用 + 审批审计脱敏 + 会话生命周期（杀树/清理/崩溃恢复/空闲回收）+ 急停。pipe 登记为加固选项不默认（04 论证成立：单客户端场景下运维收益为负）。**

否决 03 的"白名单默认不设限"：block IP 与 prohibited 域默认生效，allowed 白名单可配（默认宽松但提供限制模式），与 02 的"同域 Normal/跨域 NeedsApproval"组合——默认安全与灵活并存。

### 10. Computer Use 二期（专项裁决见 §③）：做整机，但按 04 门槛 + 02 共享管线

### 11. 技术栈/crate：采纳 01/04 的 conex-browser 单 crate（含 cdp/snapshot/policy/profile/session/tools 子模块）+ conex-browser-tools 挂 agent-tools，二期 conex-computer 平级独立

## ③ 专项裁决（必答项）

### 裁决 1：数据导入主路径——面板内登录为主 + 最小文件集复制（显式排除）+ 加密 storage_state 兜底

| 候选 | 隐私面 | 安全风险 | App-Bound 127+ 影响 | 裁决 |
|---|---|---|---|---|
| A. profile 整目录复制（01） | **最大**：Cookies/Login Data/History/Web Data 全量进 AI 可读面 | 密码库/历史/自动填充被复制 = 一次性全量凭据泄漏面；复制失败破坏源 profile 风险 | 01 声称"同用户复制不破坏 DPAPI"——**证据链断裂**：Chrome 127+ App-Bound 加密下 cookie 密钥绑定启动 exe 身份，参考实现 browser-use `profile.py` 全文件无 App-Bound 处理，01 照抄即踩坑 | **否决（作为唯一主路径）** |
| B. 面板内登录（02 线一） | **零**：无复制、无文件落盘，登录态只存在于会话 profile | 登录态随会话删除即销毁；无导入动作即无导入风险 | 不涉及（不复制） | **主路径**：协同模型免费产物，用户登录一次长期有效 |
| C. attach 用户已运行浏览器（02 线二） | 零复制，但**暴露用户真实浏览器全控制面** | 用户日常 cookie 面 + AI 全控制 + 我方无生命周期控制（无法杀树清理） | 不涉及 | 保留但**默认关闭**，限定"AI 辅助浏览"模式 + 高危动作审批（02 自认 AI 感知有限，恰说明不可作全自动执行面） |
| D. storage_state 明文 JSON（03 主路径） | 明文文件 = 会话凭据文件（04 正确指出） | 落盘泄漏即登录态冒用；跨浏览器可写 | 不涉及 | 否决作主路径；**加密持久化**（DPAPI/AES-GCM + 显式确认 + 审计）保留为"跨会话保持登录"可选开关，默认关 |
| E. 最小文件集复制（04） | 小：仅 Cookies/Local Storage/Session Storage/Network\Cookies | 密码/历史/自动填充永不进入 AI 浏览器 | 必须同家族 exe 启动（Chrome profile → Chrome exe；Edge profile → Edge exe）才可解密；启动后 `Network.getAllCookies` 回读校验，失败域名引导重登（02 正确识别） | **复制线的采纳形态**：作为"导入 Chrome 登录态"显式向导，复制前对话框列明导入内容、明示"密码与历史不会导入" |

**关于"最小化复制是否必要"：必要且不可妥协。** 理由：(a) 密码库（Login Data，DPAPI 可解）与历史/自动填充是纯隐私资产、对 AI 协同零功能价值（AI 登录态只需 cookie），排除它们是"以零功能损失换最大隐私面收敛"；(b) 整目录复制把复制失败/误操作的破坏半径扩大一个数量级（browser-use 有 warn_user_data_dir_non_default_version 破坏性风险提示先例）；(c) 安全基线 B3 精神（凭据最小面）要求导出物最小化。**成本差**：最小文件集复制比整目录复制只多一个排除清单（04 明确列出），复杂度几乎无差——01 选整目录复制是"照抄省事"，不是工程必需。

**书签/历史直读**（四家一致）：仅前端 UI 展示（地址栏/历史面板），**不进 AI 快照上下文**——历史是隐私面，AI 只需当前页与白名单导航，不需要用户浏览史。

### 裁决 2：安全设计对比

| 项 | 裁决 | 依据 |
|---|---|---|
| 端口 | **随机端口 + DevToolsActivePort**（`--remote-debugging-port=0`，循环杀；禁止固定 9222/9242；`--remote-debugging-address=127.0.0.1` 显式；端口/WS path 不进日志） | 四家一致；pipe 登记为加固选项不默认（04 论证：单客户端场景运维收益为负，威胁模型与 Chrome cookies 明文文件等价） |

| 剪贴板 | **默认 Deny，单次 Ask**（04 反向决策 browser-use 默认授予） | AI 读剪贴板 = 窃取用户复制密码/验证码的最短路径；04 是四家中唯一明确此面的 |
| 上传/下载 | 上传 Ask（文件系统进出）；下载落会话隔离目录，打开/移动需确认（04） | 下载到托管目录防任意路径写 |
| 扩展 | 默认 `--disable-extensions`；profile 复制时扩展不导入 | 扩展是额外执行面；最小权限（01/04 一致） |

### 裁决 3：MCP 兼容路径——并存（browser_* 闭环 + chrome-devtools-mcp attach 补深）

**结论：采纳 03 的并存分工，但补充安全约束：**

- **并存而非互斥**：自研 browser_* 覆盖"感知—决策—执行—校验"高频闭环（权限/审计/中止令牌精确穿透）；chrome-devtools-mcp 以 stdio 插件经既有 `register_plugin_server` + `--browserUrl http://127.0.0.1:<port>` attach 提供 lighthouse/trace/memory 深调试能力。全自研 = 重造 Google 持续维护的重资产（3 倍红线）；全 MCP = 高频路径不可控 + MCP 面审批弱（03 自认）。
- **命名冲突：零**（`browser_*` vs `mcp_<server>__*` 前缀天然隔离，bridge.rs:676-678 已验证）。
- **权限差异**：自研工具精确打标走三态引擎；MCP 工具经 `adapt_tool_list` 进注册表由插件注解映射危险等级，策略（smart/confirm/none）全局统一，避免两套世界观（03 的 adapt 方案 + 04 的"策略统一"）。
- **附加安全约束（03 遗漏面）**：chrome-devtools-mcp 必须固定 attach 模式，**禁止其 daemon/launch 路径自启第二个浏览器实例**（03 自认风险）；`mcp_cdm__execute_webmcp_tool`（页面内执行代码）必须 Ask；`mcp_cdm__evaluate` 同 Ask 分级。若 MCP 工具面审批能力不足，宁可裁掉该插件深调试能力也不放行弱审批工具。
- 演进收益：随 chrome-devtools-mcp 上游版本自动获得新工具（lighthouse/performance 等），无需自维护。

### 裁决 4：Computer Use 二期——做整机（否决 03 的"浏览器内视觉主控"），复用共享管线，按 04 门槛

- **否决 03**：二期需求就是"电脑操作"（01/02/04 均确认），03 的"只做浏览器内视觉主控"是用 CDP 已有的坐标输入能力包装一下，实质等于把一期就该有的坐标级输入工具改个名，回避了产品需求。且 03 自己的 screencast + 坐标输入一期就要建（快照/执行都需要），"二期纯模型侧工作"的说法正确，但这证明的恰是"二期整机的执行基础设施本来就该复用浏览器线的帧渲染/输入转发/接管 UI"（02 论证），而不是"二期不用做整机"。
- **采纳 02 的共享管线**：帧渲染、输入转发、指示条/接管/审批/日志四件套与数据源解耦（一期就抽象 Rust trait + 前端 props 契约，成本极低），二期 Computer Use 替换两个数据源（CDP screencast → 系统屏幕捕获；CDP Input → SendInput）。
- **采纳 04 的安全门槛（不可妥协）**：会话级显式开启（默认 Deny + 倒计时确认）→ 全动作审批（复用 PermissionMode）+ 禁用键集合（Win/Ctrl+Alt+Del/Alt+F4/锁屏）→ 全局二级急停 + 注入线程挂起 + 进程级 kill 兜底 → 前台窗口校验（仅操作当前前台窗口）+ 截图敏感窗口模糊 → 坐标缩放钳制（scale_coordinates + 越界钳制）→ **与浏览器线会话互斥 + 独立 crate 无共享内部状态**（防浏览器线借电脑操作通道扩权）。
- 复杂度：1-2 倍（增量）；三期边界（跨窗口/虚拟桌面/隔离桌面 CreateDesktop）登记为远期。

### 裁决 5：演进——视觉模型升级的平滑过渡路径

**采纳 03 的三件套，文本通道换为 DOM 简化树：**

1. **快照接口预留 `include_visual` 参数**（03）：`browser_snapshot` 返回文本树（默认）+ 可选视觉帧；视觉模型升级后只需改模型侧调用策略（文本为主 → 文本+视觉 → 视觉为主），工具面与执行层零改动。与 browser-use `use_vision: "auto"` 同构。
2. **`snapshotVersion` 一期内置**（03）：单调递增 + 页面变化失效，是协同冲突处理与"操作前校验"的公共基础设施——一期不做则二期补的成本高一个数量级。
3. **帧流转发通道一期建好**（03）：`Page.startScreencast` 帧源同时供前端预览与模型（二期视觉主控消费同一条流）。
4. **过渡策略**：DOM 简化树（默认）→ DOM + 视觉校验（模型能力到位后开 `include_visual=auto`，验证层先行）→ 视觉主控（视觉模型成熟后，保留文本树兜底切换）。双通道随时可切换（03 自认的兜底，采纳）。
5. **agent-provider 侧零成本**：`supports_vision` 能力位 + `image_url` 多模态 part 已通（catalog.rs:127 / messages.rs:61），一期截图/视觉帧直接复用。

**否决项说明（明确理由，不和稀泥）**：
- **否决 03 的 WebView2 主后端**：CDP 非稳定 SLA + profile 不兼容（数据导入硬需求落空）+ 与主应用共享运行时面。03 的全部独有贡献（MCP attach、include_visual、snapshotVersion、BrowserController、双通道）不依赖 WebView2，均可在 Chromium 后端落地——03 选错底座但贡献正确。
- **否决 01 的 profile 整目录复制**：隐私面最大 + App-Bound 证据链断裂（browser-use 参考实现无 App-Bound 处理，照抄即踩坑）+ 复制失败破坏半径大。01 选整目录复制是"照抄省事"而非工程必需，最小文件集只多一个排除清单。
- **否决 03 的 storage_state 主路径**：明文 JSON 落盘 = 会话凭据文件；导出物即登录态等价物。
- **否决 03 的"白名单默认不设限"**：block IP 与禁止域默认生效是零成本防御，默认安全与"配置开启限制模式"不冲突。
- **否决 01 的 evaluate 完全不开放**：切断合法调试/测试路径，与"1-2 倍复杂度"约束不匹配；Ask + isolated world 已达最高防御且保留可用性。
- **否决 02 的 attach 主体验地位**：attach 用户日常浏览器 = 用户真实 cookie 面 + AI 全控制 + 我方无生命周期控制，是四方案中最大登录态冒用面；降级为默认关闭的"AI 辅助浏览"模式。
- **否决 03 的 Computer Use 浏览器内视觉主控**：回避产品需求；共享管线论证恰证明整机二期成本是增量 1-2 倍而非 3 倍。
- **否决 04 的 AX 主通道与必选 data-***：AX 牺牲定位精度与覆盖率换取并不成立的隐私论据（过滤层可达同等效果）；data-* 注入页面 DOM 有污染面，backend_node_id 直作 index 更干净。

**安全基线清单（对齐 31-security-baseline.md B1-B10，逐项落地）**：

| 基线 | 本方案落地点 |
|---|---|
| B1 命令门禁 | 浏览器进程 spawn 用参数数组（Command::args，无 shell 拼串）；CfT 下载/安装走既有沙箱门禁 |
| B2 路径校验 | 复制目标 `%LOCALAPPDATA%\Crish\browser-sessions\<id>` canonicalize + 组件边界校验 + ACL 收紧；书签/历史只读路径同规则 |
| B3 凭据处理 | storage_state 默认不落盘；加密持久化走 DPAPI/AES-GCM + 显式确认；cookie 值/密码永不进日志/事件/快照 |

| B9 依赖安全 | tokio-tungstenite 评审登记；CfT 版本钉死可审计；Cargo.lock --locked |

## ⑤ P0 验证清单

1. **域名门禁**：`browser_navigate` 到被禁域名/被 block 的 IP（含 localhost 直连）→ 拒绝 + NavigationBlocked 审计事件（Rust 单测，覆盖三检查点：导航前/重定向后/新标签）。
2. **审批分级**：`browser_evaluate`/`browser_clipboard_read`/`browser_cookies_get` 默认 Ask；Deny 模式下直接拒绝（复用 PermissionMode 测试设施）；evaluate 限定 isolated world 断言。
3. **急停**：运行中触发急停 → pending CDP 命令全部取消 + 令牌失效 + 浏览器实例存活保留给用户（集成测试）。
4. **导入最小化**：Login Data*/History/Web Data/Bookmarks/Thumbnails 断言不进入复制目标目录；目标目录 ACL 断言；复制前确认对话框文案断言（Rust 单测）。
5. **App-Bound 回读校验**：复制后 `Network.getAllCookies` 回读，断言"同家族 exe 可解密 / CfT 启动解密失败域名被标记并引导重登"（e2e，需 Chrome 127+ 环境）。
6. **协同令牌**：用户输入 → generation counter 递增 → AI pending 动作取消；动作执行后令牌变化 → 结果作废 + 指示条提示重看（集成测试）。
7. **快照隐私**：`type=password` 字段 value 断言不出快照树；快照大小上限截断断言（单测）；快照含敏感域时截图自动拒绝/模糊（e2e）。
8. **生命周期**：杀进程树 + 临时 profile 删除 + stale DevToolsActivePort 清理 + 崩溃后恢复事件（集成测试）；空闲回收断言。
9. **日志脱敏**：cookie 值/端口/WS path/密码断言不出现在 tracing 与审计事件（单测）。
10. **剪贴板**：默认无 clipboardReadWrite 授予断言；单次 Ask 后可用（e2e）。
11. **IME**：中文输入法 `Input.insertText` 路径专项测试（复用仓库既有 IME 测试资产）。
12. **MCP attach**：chrome-devtools-mcp 以 `--browserUrl` attach 成功 + 不产生第二个浏览器实例 + `mcp_cdm__evaluate` Ask 生效（集成测试）。
