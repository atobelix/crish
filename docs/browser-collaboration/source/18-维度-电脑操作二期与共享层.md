## 1. 定位与边界

- **形态**：独立模块（建议 crate：`conex-desktop`），与浏览器线**共享**面板帧渲染、指示条/接管、输入归一化管线、工具执行框架、安全门槛/审计；与浏览器会话**互斥**（不可同时活跃，§6）。
- **一期边界**（08 §5 声明）：一期不并入电脑操作；本维度文档为二期立项基础，落地时间在 S10 之后。
- **依赖**：视觉模型（截屏感知）或结构化辅助（平台无障碍 API 降级）——二者均为**能力探测结果**，非硬性前置；Windows 首发以 UIA 为必选降级通道（裁决见 §3.3），视觉模型可用时叠加截屏回显。
- **已有可复用基础**（仓库现状，非新造）：`agent-tools` 的 `AbortToken`（`crates/agent-tools/src/context.rs:33`）、`ToolDefinition.dangerous` + `ctx.ask` 审批面（`definition.rs:38-40`、`permission.rs`）、审计（`audit.rs`）、注册面（`registry.rs`）；`agent-provider` 的视觉能力位 `supports_vision`（`crates/agent-provider/src/models/catalog.rs:127`）与 `image_url` 多模态 part（`request/messages.rs:49-83`）——截图可直接喂模型；注意 cache 白名单只缓存 text 块，**vision 有 token 成本**，这直接支撑结构化辅助立项（§3.3 理由 2）。

## 2. 动作空间

### 2.1 动作枚举与参数

动作集对齐 `computer.py` 三版（20241022 基础集 + 20250124 扩展集 + 20251124 zoom），统一挂在 `computer_*` 工具族下。每个动作 = 一个工具定义（`dangerous=true`，§7.2），参数做严格校验（枚举/取值范围/组合合法性），非法参数返回结构化错误码 `tool.computer.invalid_params`。

| 动作 | 参数 | 语义与约束 | 来源版本 |
|---|---|---|---|
| `key` | `keys: string[]`（归一化键名，§2.4） | 组合键按下（如 `["ctrl","c"]`）：按修饰键序 down → 主键 down/up → 修饰键 up；修饰键多键时保持按住其余键 | 20241022 |
| `type` | `text: string` | 文本输入：分块 + 节流（§2.3）；非 ASCII（中文/emoji）走 Unicode 注入路径（§2.4） | 20241022 |
| `mouse_move` | `coordinate: [x,y]`（API 空间） | 移动光标到指定坐标（先经缩放校验，§4）；`_sync` 语义 = 等待完成再返回 | 20241022 |
| `left_click` | `coordinate?`、`key?` | 左键单击；带 coordinate 时先移动再点击；带 key 时按住修饰键点击（如 ctrl+click） | 20241022 |
| `right_click` / `middle_click` / `double_click` / `triple_click` | 同上 | 右键/中键/双击/三击；双击与三击由后端生成间隔（Windows：`MOUSEEVENTF_LEFTDOWN/UP` ×2 或 ×3，间隔 ≤ 系统双击时间） | 20241022 / 20250124 |
| `left_mouse_down` / `left_mouse_up` | 无（作用于当前光标位置） | 按下/抬起分离原语，供"拖拽/选区/画板"场景由模型编排 | 20250124 |
| `left_click_drag` | `start_coordinate: [x,y]`、`coordinate: [x,y]` | 按下起点 → 移动终点 → 抬起（拖拽）；两端点均走缩放校验 | 20241022 |
| `scroll` | `direction: up\|down\|left\|right`、`amount: u32`、`coordinate?`、`key?` | 滚动；方向映射滚轮增量（§2.2）；支持按住修饰键滚动（如 shift+wheel 横向语义由 OS 决定） | 20250124 |
| `hold_key` | `key: string`、`duration: f32`（秒） | 按住指定键 duration 后松开；`duration` 上限 100s（对齐 computer.py 硬约束） | 20250124 |
| `wait` | `duration: f32`（秒，上限 100） | 等待并返回截屏（感知动作，不注入任何输入） | 20250124 |
| `screenshot` | 无 | 返回缩放后全桌面截屏（base64，PNG）；作为感知闭环的显式刷新点 | 20241022 |
| `cursor_position` | 无 | 返回当前光标位置（API 空间坐标，经物理→API 换算，§4.2） | 20241022 |
| `zoom` | `region: [x0,y0,x1,y1]`（API 空间） | 截屏 + 裁剪指定区域返回（局部放大感知）；区域越界报错 | 20251124 |

参数校验规则（对齐 computer.py）：`coordinate` 必须为非负整数二元组；`mouse_move`/`left_click_drag` 必须带 `coordinate` 且不得带 `text`；`key`/`type` 必须带 `text` 且不得带 `coordinate`；`scroll_amount` 非负整数；`duration` 数值且 ≤100。动作执行前统一走「参数校验 → 坐标换算（§4）→ 审批（§7.2）→ 注入」。

### 2.2 平台实现映射

注入后端抽象为 `InputBackend` trait（签名见 §10），一期只实现 Windows；macOS/Linux 复用同一 trait。

| 动作原语 | Windows（一期） | macOS（二期） | Linux（二期） |
|---|---|---|---|
| 键/组合键 | `SendInput(KEYEVENTF_KEYUP/DOWN)`，虚拟键码表（VK_*）；中文等 Unicode 用 `KEYEVENTF_UNICODE` 直送字符 | `CGEventCreateKeyboardEvent`（键码表 + flags 修饰键） | X11：`XTestFakeKeyEvent`；Wayland：`ydotool key`（参考 computer.py 的 xdotool 语义） |
| 文本输入 | `SendInput(KEYEVENTF_UNICODE)` 逐字符，或剪贴板桥（见风险 R2） | `CGEventKeyboardSetUnicodeString`（CGEvent 直接携带 Unicode 串） | `ydotool type`（xdotool type 的对应物，`--delay` 节流） |
| 鼠标移动 | `SendInput(MOUSEEVENTF_MOVE, 绝对坐标按 65535/屏宽归一)` 或 `SetCursorPos` | `CGEventCreateMouseEvent(MOUSE_MOVED)` 绝对坐标 | `XTestFakeMotionEvent` / `ydotool mousemove --sync` |
| 点击（左/右/中/双击/三击） | `SendInput(MOUSEEVENTF_LEFTDOWN/UP、RIGHTDOWN/UP、MIDDLEDOWN/UP)` | `CGEventCreateMouseEvent(LEFT/RIGHT/OTHER_MOUSE_DOWN/UP)` | `XTestFakeButtonEvent` / `ydotool click`（`--repeat` 对齐 CLICK_BUTTONS 映射） |
| 按下/抬起分离 | `SendInput` DOWN/UP 分别调用 | 同上分离事件 | `ydotool mousedown/mouseup` |
| 拖拽 | `SetCursorPos(起点) → LEFTDOWN → 分步移动(终点) → LEFTUP` | MOUSE_DOWN → DRAGGED 系列 → MOUSE_UP | `ydotool mousemove --sync 起 mousedown 1 mousemove --sync 终 mouseup 1` |
| 滚动 | `SendInput(MOUSEEVENTF_WHEEL, delta=amount×120)`；横向 `MOUSEEVENTF_HWHEEL`（负值表上/左） | `CGEventCreateScrollWheelEvent`（行数） | `ydotool click --repeat N 4/5/6/7`（对齐 computer.py 滚轮按钮 4-7） |
| 光标位置查询 | `GetCursorPos` | `CGEventGetLocation` | `ydotool mousemove --sync` 读取或 XQueryPointer |
| 区域截屏 | 见 §3.1（xcap / GDI） | CGDisplayCreateImage 区域裁剪 | `import`/`gnome-screenshot -f` + crop（对齐 computer.py `convert -crop`） |

实现约定：**Windows 一期统一走 `enigo`（底层即 SendInput）为主实现，Unicode 输入与滚轮 delta 等细节用 `windows` crate 直连 `SendInput` 补足**；禁用注入脚本类方案（与 D-3 否决理由同构：合成事件可信度与控制面问题）。

### 2.3 输入节奏与可靠性（对齐 computer.py）

- `TYPING_GROUP_SIZE = 50`：`type` 按 50 字符分块，逐块注入；块间短暂停顿。
- `TYPING_DELAY_MS = 12`：字符间隔 12ms（Windows 上视应用可调 12-30ms，防止丢失字符）。
- `hold_key`/`wait` 的 `duration` 上限 100s；超过即参数错误。
- 长 `type` 期间每块写入前自查 `abort_token`（§7.3 急停可打断在途输入）。
- 每次注入动作完成后可选返回一张新截屏（`take_screenshot` 语义，配置开关），保证 AI 感知闭环。

### 2.4 键盘归一化

- 键名规范（模型侧输入面）：`ctrl/alt/shift/win`（修饰键）、`a-z/0-9`、`F1-F24`、`enter/tab/space/backspace/delete/escape`、`arrow_up/down/left/right`、`home/end/page_up/page_down`、`caps_lock` 等；映射表集中在 `KeyNameRegistry`（Windows VK 码 / macOS keyCode / Linux keysym 三张表，接口 `resolve(platform, name) -> KeyCode`）。
- 组合键语法：数组语义（`["ctrl","c"]`），不做字符串解析（避免 xdotool 式语法在跨平台泄漏）。
- 中文等非 ASCII：Windows 用 `KEYEVENTF_UNICODE` 直送（避免 IME 状态依赖）；**IME 场景预案**见风险 R2。

## 3. 截屏与感知

### 3.1 截屏实现选型（Windows 一期）

| 方案 | 选型 | 理由 |
|---|---|---|
| `xcap`（Rust crate，跨平台） | **首选** | 跨平台（Windows 底层走 DXGI Desktop Duplication / Windows Graphics Capture，macOS CGDisplayStream，Linux X11）；**原生支持多显示器逐屏捕获与屏幕缩放信息**（monitor 的 x/y/width/height/scale），直接喂 §4.3 布局表；返回字节可直接编 PNG |
| GDI `BitBlt`（windows crate 直连） | 回退 | 远程桌面会话 / 老显卡 / 驱动兼容性兜底；仅主屏或逐屏抓取，需自行 DPI 处理 |
| 轮询截屏（截屏="帧流"） | 禁用为主 | 与 D-2 否决截图轮询同构：延迟与资源不可接受；桌面线改为**事件驱动 + 可选低帧率档**（§5 适配点） |

- 输出格式：PNG（模型友好、无损，成本高于 JPEG 但桌面截屏体积可控，且缩放后体积大降）；JPEG 为低质量档选项（`screenshot` 动作 quality 参数可配）。
- 截屏速度目标：全虚拟桌面缩放后 ≤150ms 产出（xcap DXGI 路径实测通常 ≤50ms）。
- 隐私感知暂停：检测到密码输入控件聚焦（UIA `PasswordEdit` 控件类型，§3.3）时**暂停截屏**并提示，避免凭据入图（§7.5）。

### 3.2 分辨率与缩放策略

对齐 `scale_coordinates` 语义（computer.py:268-291，`ScalingSource.COMPUTER/API` 双向）：

- **只缩不升**：物理分辨率 > 目标才缩放；小于等于目标保持原尺寸。
- **缩放目标集**（模型友好分辨率）：XGA 1024×768（4:3）、WXGA 1280×800（16:10）、FWXGA 1366×768（≈16:9）——与 computer.py `MAX_SCALING_TARGETS` 一致。
- **目标选择**：按宽高比与目标比之差的绝对值 < 0.02 选择最近目标（容差允许真实比例偏差）；**容差未命中**（如 21:9 超宽屏）默认不缩放（避免强制拉伸畸变），提供配置项"强制缩放到 16:9 目标"（可接受 ≤3% 畸变）供视觉模型需求场景。
- **独立 X/Y 缩放因子**（`x_factor = target_w/phys_w`、`y_factor = target_h/phys_h`），不保纵横比——与参考实现一致（`-resize WxH!` 强制），容差选择下畸变 ≤2%。
- 模型侧声明（`ComputerToolOptions` 语义）：`display_width_px / display_height_px / display_number` 上报缩放后尺寸与显示器编号，让模型在 API 空间内出坐标。

### 3.3 结构化辅助裁决（开放问题 5）

**结论：立项。** Windows UIA（UI Automation）结构化辅助作为二期首发**必选降级通道**（而非"可选"），与截屏双通道并存：结构化为主、截屏回显/兜底。

理由：

1. **与项目"结构化感知优先"原则一致**（08 §1.2）：浏览器线已裁定 DOM 简化树为主、AX 辅助、截图按需（D-5）；桌面线的同构答案就是 UIA 树为主、截屏回显——两条线共享同一感知哲学，桌面通道复用浏览器快照的序列化/索引/失效机制，工程同构。
2. **成本硬约束**：vision 有 token 成本且 cache 白名单只缓存 text 块（用户输入背景明示）；长会话全截屏感知成本不可接受。UIA 结构化快照廉价、可缓存、无多模态开销。
3. **精度**：UIA 元素携带边界矩形（`BoundingRectangle`），元素级定位直接映射物理坐标（点可命中控件中心），远高于视觉模型估算像素的误差；点击可靠性提升，审批所见即所得。
4. **工程可行性**：Windows 首发，Rust 侧 `windows` crate 提供完整 UIA COM 接口（`IUIAutomation` 树遍历、`ElementFromPoint` 反向命中测试、`PasswordEdit` 等控件类型、`FocusChanged`/事件订阅）；复杂度 1-2 倍，与浏览器 AX 通道（CDP Accessibility 域）实现思路同构。
5. **降级关系明确**：视觉模型可用时叠加截屏回显（模型看屏 + UIA 出坐标，双通道互补）；视觉不可用/成本敏感时 UIA 树为主通道独立闭环（元素索引 → 坐标 → 注入）。

边界与保留项：

- UIA 覆盖不全（自绘控件、游戏、无 accessibility 的应用）——UIA **不能作为唯一通道**，截屏兜底保留，感知降级矩阵见 §3.4。
- **管理员（提权）窗口**：UIA 与输入注入对提权进程均受限（UI-PIA 会话隔离），检测到目标窗口提权时明确报错（§9 R4），不静默失败。
- macOS（二期）对应 AXUIElement，Linux（二期）对应 AT-SPI——同一 `PerceptionSource` trait 挂不同实现（§10）。

**UIA 数据面抑制（密码框不读文本，22 §3 18 行落点）**：

- **不读取密码文本**：UIA 树序列化时，`PasswordBox` 控件类型（`ControlType.Password`）与 `IsPassword=true` 的元素——**跳过其文本内容**（`ValuePattern`/`Name` 不输出实际字符）；`ValuePattern.IsReadOnly` 为 false 且 `IsPassword` 的控件输出占位符 `<password>`（长度可记、内容不记）；
- **名称/值字段脱敏**：UIA 元素 `Name`（可含当前密码框外文本，如「密码」标签可输出，但**密码类控件的 Name 若含输入内容一律不输出**）与 `Value` 字段过键名模式脱敏（复用 17 §6.2 键名模式库：password/passwd/pwd/secret/token 等命中 → `<redacted>`）；`IsPassword` 为判定优先信号，不依赖键名猜测；
- **联动**：① 密码框**聚焦时暂停截屏**（§3.1 隐私感知暂停，凭据不入图）；② 审计不落 UIA 密码字段（§7.4）；③ `ElementFromPoint` 命中密码框时，其文本同样不回传（即使模型未请求）；
- **平台等价**：macOS `AXValue` 对 secure 文本（`kAXSecureTextField`）同样抑制；Linux AT-SPI `Accessible::get_text` 对 `ATK_ROLE_PASSWORD_TEXT` 抑制——同一 `PerceptionSource` 实现约定，跨平台一致。

### 3.4 感知降级矩阵（能力探测输出）

| 能力 | UIA | 视觉模型 | 感知模式 |
|---|---|---|---|
| 有 | 有 | 结构化主通道 + 截屏按需回显（默认） | |

## 4. 坐标缩放与对齐

### 4.1 缩放目标集与选择算法

目标集固定为 §3.2 三档；算法（纯函数，单测覆盖）：

```
ratio = phys_w / phys_h
target = None
for dim in [XGA(1024x768), WXGA(1280x800), FWXGA(1366x768)]:
    if abs(dim.w / dim.h - ratio) < 0.02 and dim.w < phys_w:
        target = dim; break   # 取首个（有序优先级）且必须小于物理宽度
if target is None: return (phys_w, phys_h)  # 不缩放（或强制缩放配置项）
```

### 4.2 API ↔ 物理双向换算

- 缩放因子：`fx = target_w / phys_w`，`fy = target_h / phys_h`（只缩不升时恒 <1）。
- **API → 物理**（注入前）：`x_phys = round(x_api / fx)`，`y_phys = round(y_api / fy)`。
- **物理 → API**（`cursor_position`/回显标注）：`x_api = round(x_phys * fx)`，`y_api = round(y_phys * fy)`。
- 往返一致性约束（单测断言）：`to_api(to_phys(p)) == p` 在整数像素域误差 ≤1px。

### 4.3 多显示器与 DPI

- **统一物理像素坐标系**：以虚拟桌面左上角（`min_x, min_y`，Windows 上可为负）为原点，全截屏合成图 + 布局表 `Monitors[] { id, x, y, w, h, dpi_scale, image_w, image_h }`；API 空间 = 合成图归一空间（原点 0,0）。
- **DPI 处理**：启动时进程置 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`（`SetProcessDpiAwareness(2)` 兼容旧系统）；注入路径全部使用**物理像素**；前端面板回显/交互层使用逻辑像素，面板坐标 → 物理像素经 `dpi_scale` 换算（面板坐标 → 合成图坐标 → 物理坐标），换算点在归一化管线内完成（§5 适配点 3）。
- 显示器热插拔：布局表重建 → 感知版本号推进（§5 适配点 7）→ 模型持有旧坐标的动作触发重新截屏。

### 4.4 校验链（缩放前后双重校验）

1. **API 空间边界**：`0 ≤ x_api ≤ target_w`（未缩放时 `≤ phys_w`）且非负整数，越界返回 `tool.computer.coords_out_of_bounds`（对齐 computer.py "Coordinates are out of bounds" 语义）。
2. **物理空间回检**：换算后 `0 ≤ x_phys ≤ phys_w`，兜底保护（防缩放舍入越界 1px 时钳制并记审计）。
3. **光标查询回检**（可选）：注入类动作执行后 `GetCursorPos` 与目标比对（|Δ| > 容差时告警审计，不静默）。

## 5. 共享层清单与适配点

复用原则：**接口抽到共享 crate（如 `conex-shared`），浏览器/桌面各持一个实现，面板与工具层零感知差异**；共享组件的既有单元测试全量保留，桌面实现补对等测试。

| # | 共享组件 | 浏览器线实现（一期） | 桌面线适配点（替换面） | 复用方式 |
|---|---|---|---|---|
| 1 | 面板帧渲染 | CDP `Page.startScreencast` JPEG 帧流 → canvas | 事件驱动截屏 + 可选 2-5fps 轮询档（PNG/JPEG） | 抽 `FrameSource` trait（`next_frame`/`request_sync_frame`/`set_frame_policy`），React 面板只消费 `Frame`（bytes + 元数据），**替换面 = 帧源实现**：`CdpScreencastSource` vs `DesktopCaptureSource` |
| 2 | 指示条/接管 | "AI 正在操作"条、暂停、接管按钮 | 同组件复用；接管触发源从"面板输入事件"扩展为"面板输入事件 + 物理输入事件"（桌面线用户输入天然直达，无需转发） | React 组件原样复用；接管回调接 `ActivationGate`（§6） |
| 3 | 输入归一化管线 | 面板/工具事件 → CDP `Input.dispatch*` | 面板/工具事件 → `SendInput`/`CGEvent`/`XTest` | 抽 `InputBackend` trait（§10），**替换面 = 注入实现**：`CdpInputBackend` vs `OsInputBackend`；前端归一化 schema（mouse/key/scroll/drag）共用，后端映射表分平台 |
| 4 | 工具执行框架 | `browser_*` 挂 `agent-tools` registry（dangerous/审批/幂等/流式） | `computer_*` 全动作 `dangerous=true` 挂同一注册面 | 零改造复用；仅新增 `computer_*` 定义与 `ctx.ask` 审批接线（§7.2）；幂等键 = 会话 + 动作 + 参数哈希 |
| 5 | 审计 | `audit.rs` 全量动作审计 | 复用；**扩展字段**：坐标、动作、目标窗口标题、type 文本哈希（§7.4 脱敏） | `audit.rs` 事件结构加 desktop 专有字段（兼容序列化），其余原样 |
| 6 | 急停 | 全局急停 + abort_token 抢断 | 复用全局急停 + **新增热键急停**（`RegisterHotKey`）+ 面板按钮（§7.3） | 复用 `AbortToken`；在途注入按批次自查（§2.3） |
| 7 | 快照/版本失效 | `snapshotVersion`（CDP 事件推进） | 感知版本号：截屏/布局表重建/UIA 树变化/输入动作后推进；动作前校验（对齐 D-6 四合一中的版本失效机制） | 复用版本号机制的数据结构与校验路径，**替换面 = 版本推进事件源** |
| 8 | 能力探测与降级 | CDP 域可用性探测 | UIA 可用性 + 视觉模型能力位（`supports_vision`）+ 管理员权限探测 | 复用能力报告结构，desktop 增加 §3.4 降级矩阵 |
| 9 | 域名/目标门禁 | 域名白名单 + IP 阻断 | **白名单窗口（可选）**：标题/进程匹配（§7.5），非白名单窗口动作拦截 | 复用"动作前检查点"框架，检查器实现替换 |

不共享/不复用：CDP 客户端本身、浏览器进程管理（§3.1/3.2/3.7 维度内容）——桌面线无浏览器进程，感知与注入全部走 OS 原生面。

## 6. 会话互斥

### 6.1 激活状态机

```
enum SessionMode { Idle, Browser, Desktop }
struct ActivationGate { mode: RwLock<SessionMode>, user_confirmed_switch: AtomicBool }
```

| 当前态 | 事件 | 目标态 | 动作 |
|---|---|---|---|
| Idle | 开启浏览器会话 | Browser | 浏览器线既有流程 |
| Idle | 用户显式开启电脑操作（§7.1） | Desktop | 挂载 computer_* 工具面、启动感知源 |
| Browser | 用户发起切换到电脑操作 | Desktop | **必须用户确认**（防 AI 自切换）；执行 §6.2 清理清单①，再激活桌面 |
| Desktop | 用户发起切换到浏览器 | Browser | 执行 §6.2 清理清单②，再激活浏览器 |
| Browser/Desktop | 会话结束/急停/超时 | Idle | 两侧清理 |

- 切换请求只允许**用户显式操作**（面板按钮/设置），AI 工具无切换能力（工具面不暴露）。
- 状态广播：`ActivationGate` 变更 → 事件总线 → 面板（指示条显示当前模式）与工具执行器（模式守卫）。

### 6.2 切换清理清单

切换离开当前会话时**同步完成**（阻塞完成才允许进入新会话）：

① Browser → Desktop：停止 screencast 帧源 → 吊销浏览器 AI 会话令牌（abort_token.abort()）→ 浏览器快照失效（版本号作废）→ 浏览器工具面保留注册但模式守卫拒绝（见下）→ 启动桌面截屏源 + UIA 会话。
② Desktop → Browser：停止截屏轮询 → 销毁 UIA 会话/事件订阅 → 吊销桌面 AI 令牌 → 桌面工具面拒绝态 → 恢复浏览器 screencast 帧源。

### 6.3 工具面互斥守卫

- 模式守卫挂在工具执行器（agent-tools executor 层，与既有守卫同构）：`browser_*` 在非 Browser 态返回 `tool.session.exclusive`（"浏览器会话未激活，当前为电脑操作会话"）；`computer_*` 在非 Desktop 态同理。
- 守卫检查点在**审批之前**（互斥是硬约束，不占审批资源）。
- 急停全局生效（不区分会话），急停后强制回 Idle（§7.3）。

## 7. 安全门槛

### 7.1 显式开启流程（会话级）

1. 用户在设置面板点击"启用电脑操作" → 弹出风险确认对话框（说明：可注入本机全部输入/截屏、动作逐次审批、急停方式）。
2. 确认后 `session_meta` 落盘标记 `computer_use_enabled=true`（会话级持久化；新会话默认关闭）。
3. 注册面按标记挂载 `computer_*` 工具族（未开启时工具不存在，模型侧 tool schema 亦不含）。
4. 开启后首次动作前展示一次性提示（操作可见性说明）。

### 7.2 全动作审批

- 所有 `computer_*` 工具定义 `dangerous=true` → 走既有 `ctx.ask` 审批面（AskChannel/ApprovalGate，`tool.requires_approval` 语义，与 agent-tools 既有接线一致）。
- **默认拒绝型**：`type`（文本）、`key`/`hold_key`（快捷键）、`scroll`（大 amount）、`click` 系列——审批弹窗默认焦点在"拒绝"；`screenshot`/`cursor_position`/`wait`（纯感知）可配置为会话内免审（放行开关，默认也审批）。
- 审批载荷：动作名 + 参数摘要 + 目标窗口标题 + 坐标（物理值）；`type` 显示明文供用户确认。
- 审批等待期支持 `abort_token` 取消（复用既有机制）；拒绝时零注入（审批通过前不触碰输入设备）。
- "本会话放行"（可选）：用户可对本会话一键放行低危动作集（仅感知类），交互类永不整会放行。

### 7.3 急停

- **三级急停**：① 全局急停（复用既有）；② 桌面热键急停（`RegisterHotKey` 注册，默认 `Ctrl+Shift+F12`，可配置；注册失败回退仅面板按钮）；③ 面板急停按钮（常驻显眼位置）。
- 急停语义：`abort_token.abort()` → 在途注入按批次自查（type 分块间/拖拽分步间）→ 感知源停止 → 会话回 Idle（§6.1）。
- 热键注册冲突检测（其他软件占用）：注册失败弹提示并降级到按钮，不静默。

### 7.4 审计脱敏

- 审计字段：动作、坐标（API 空间值）、目标窗口标题、时间戳、审批结论、急停事件。
- **type 文本脱敏**：审计只记 `sha256(text)` 与长度，不落明文（审批弹窗内用户已亲见明文）；密码控件场景（UIA PasswordEdit 焦点）强制脱敏且暂停截屏。
- **UIA 树字段**：审计不落 UIA 元素 `Name`/`Value` 原文（可含敏感内容），只记元素类型、角色、索引与边界矩形；密码框元素（PasswordBox/IsPassword）任何字段（含 Name）一律不落（§3.3 数据面抑制）。
- 截屏不进审计库（体积与隐私），只记感知版本号/图像哈希（供复现排查）。
- 脱敏规则复用 agent-tools 审计既有脱敏框架，扩展 desktop 字段（对齐 08 §3.9 敏感数据要求）。

### 7.5 误操作兜底

- **空闲超时自动停**：桌面会话无 AI 动作/无审批超时（默认 120s，可配）→ 自动挂起回 Idle（不等用户手动）；恢复需重新显式开启。
- **白名单窗口（可选，默认关闭）**：开启后仅允许操作标题/进程匹配窗口；非白名单窗口的动作在审批阶段即拦截（复用 §5 检查点 9）。
- **动作前后回显**：每次注入后自动抓取一张截屏回显到面板（所见即所得，与浏览器线"AI 操作可见"对齐）；用户可随时接管（物理输入即抢占令牌，桌面线天然一致无转发）。
- **密码输入感知暂停截屏**（§3.1 隐私感知暂停）。
- **误注入恢复**：不提供通用"撤销"（OS 级注入无事务），以审批 + 回显 + 急停三件套兜底；审计日志可追溯重放。

## 10. 依赖与接口契约（共享 trait 签名草案）

```rust
// 帧源抽象：面板渲染只依赖此 trait（浏览器/桌面各一实现）
pub trait FrameSource: Send {
    async fn next_frame(&mut self) -> Result<Frame>;            // 事件驱动/轮询取帧
    async fn request_sync_frame(&mut self) -> Result<Frame>;    // 动作后同步回显
    fn set_frame_policy(&mut self, p: FramePolicy);             // 帧率/质量档
}

// 输入后端抽象：归一化动作面的平台映射（浏览器/桌面各一实现）
pub trait InputBackend: Send {
    async fn mouse_move(&self, p: PhysicalPoint) -> Result<()>;
    async fn click(&self, btn: MouseButton, p: Option<PhysicalPoint>, mods: &[KeyName]) -> Result<()>;
    async fn button(&self, btn: MouseButton, down: bool) -> Result<()>;          // 按下/抬起分离
    async fn drag(&self, from: PhysicalPoint, to: PhysicalPoint) -> Result<()>;
    async fn scroll(&self, dir: ScrollDirection, amount: u32,
                    p: Option<PhysicalPoint>, mods: &[KeyName]) -> Result<()>;
    async fn type_text(&self, text: &str) -> Result<()>;        // 内部按 50 字符分块 + 12ms 节流
    async fn key(&self, keys: &[KeyName], hold_ms: Option<u32>) -> Result<()>;
    async fn cursor_position(&self) -> Result<PhysicalPoint>;
}

// 感知源抽象：结构化（UIA/AX/AT-SPI）与截屏的降级面
pub trait PerceptionSource: Send {
    async fn capture(&self) -> Result<ScreenshotSpec>;          // 物理分辨率 + 布局表
    async fn accessibility_tree(&self) -> Result<UiTree>;       // 结构化（元素/角色/名称/边界矩形/索引）
    // 输出约定：UiTree 序列化过数据面抑制（§3.3）——PasswordBox/IsPassword 元素无文本内容
    //（占位符 <password>），名称/值字段过键名模式脱敏；三平台实现同约定
}
```

- 坐标类型约定：`PhysicalPoint` 一律物理像素；API 空间换算由工具层（`ScaleCoordinator`，§4）完成，后端不感知缩放。
- 能力探测输出：`DesktopCapabilities { uia_available, vision_available, elevated_env, session_active, monitors[] }` → §3.4 降级矩阵。

## 11. 开放问题闭环

| 开放问题 | 裁决 | 落点 |

| 5：电脑操作二期的结构化辅助（无障碍 API）是否立项 | **立项**：Windows 首发必选降级通道（UIA），与截屏双通道并存（结构化为主、截屏兜底） | 本文档 §3.3（理由与边界）、§3.4（降级矩阵）、§8 验收项 7 |
