## 0. 勘察结论速览

- **引擎装配点已定位**：工具注册集在 `EngineHandle::new_with_spawner` 构造
  （engine.rs:1193-1222），run 启动时经 `state.engine.tool_registry()` 取共享注册表传给
  `SessionLoopProducer`（core_run_commands.rs:3099-3119、3489-3518）→ `AgentSessionLoop`
  内建 `ToolExecutor`（session-loop/tool_exec.rs:180-209）。
- **工具侧预留了引擎注入面**：`BrowserToolsConfig.session_ops`（lib.rs:92、114-124）——
  引擎可注入 `Arc<dyn SessionOps>` 动态适配，**conex-browser-tools 工具面零改动**即可把
  会话接进工具；仅需在其内部扩展 1 个 trait 方法与 1 个执行管线调用点（详见 §2.2）。

  调用新建（tool_exec.rs:809），**不是**发送层信号源——桥接应在引擎侧把 run 级
  `AbortSignal`（safe_point.rs:37-75）联动到 slot 持有的 `CancellationToken`。
- **高危前置项（非接线本身）**：`crates/conex-browser/` **尚未入库**（git 未跟踪，
  0 个文件被 git 跟踪），根 Cargo.toml/Cargo.lock 已含其 workspace member（未提交）。
  按 AGENTS.md 测试资产保护铁律，**接线第 1 步必须先提交 conex-browser**。
- 并行冲突面：任务书声明 engine.rs/core_run_commands.rs 有在途改动（本勘察时工作区
  两文件干净，但在途批 T-CF 系列历史上频繁触碰其装配段）——这两处标注高冲突，建议
  排队；其余接线点可用**新文件 + 最小新增段**规避（零/低冲突）。

### 2.1 D-A 浏览器会话生命周期锚点

**裁定：进程级惰性单例（一个 `BrowserManager` + 一个会话槽）+ 会话归属槽**。

- 形态：引擎级共享 `BrowserSlot`（新建模块，见 2.2），持有
  `BrowserManager`（进程单例）+ `tokio::sync::Mutex<Option<Arc<BrowserSession>>>`（惰性）
  + 门禁 + 预算 + estop 令牌 + `owner: Mutex<Option<String>>`（当前归属会话）。
- **否决会话级**（每会话一实例）的理由：单实例双控制面（08 D-2/D-3）要求全应用唯一
  渲染实例；浏览器面板是全局右侧面板，不按会话隔离；工具注册表是**引擎级共享**
  （注册时绑定 config），会话级注入与共享注册表冲突。多会话迁移策略（owner 切换）
  登记 P1。
- 生命周期：
  - **启动**：惰性——首次 `browser_*` 工具调用（经 `SessionOps` 异步入口 ensure，
    见 2.2）或前端面板激活命令（`browser_open`，S5）时 `manager.start(LaunchConfig)`
    （browser/mod.rs:334）→ `endpoint()`（:502）→
    `BrowserSession::connect(endpoint, expected, policy)`（lib.rs:269-273，policy =
    引擎侧 CommandPolicyHooks 实现）。
  - **停止**：应用退出（main.rs 退出钩子/`tauri` 事件）`manager.stop(Graceful)`；
    会话删除（delete_session）不清空单例（P1 再定归属策略），面板关闭不杀进程
    （headed 窗口形态下窗口即面板）。
  - `LaunchConfig` 默认：`backend: Auto`（CfT→Chrome→Edge 回退链）、
    `profile: Ephemeral`、`mode: Headed`（MVP M4 可见形态）、`allow_cft_download: false`
    （用户接受才联网，P0-5 结论落地时再开）。

### 2.2 D-B BrowserToolsConfig 注入点（会话怎么进工具）

**方案：注入 `Arc<dyn SessionOps>`（走 lib.rs:92 `session_ops` 预留面），实现
`LazySessionOps`（新建文件，引擎域），内部持 BrowserSlot 动态解析会话。**

- 引擎侧新建 `apps/agent-workbench/src-tauri/src/browser/mod.rs`（新文件，零冲突）：
  - `BrowserSlot`（manager / 会话槽 / estop / owner）；
  - `LazySessionOps`（实现 SessionOps：所有异步方法入口先 `ensure_session().await`，
    同步 `readiness()` 查 manager 状态——启动中/崩溃重启中 → Err（R-9 gating），
    未启动 → 由异步路径启动，同步面返回"未启动"且**由 exec 层先 ensure** 兜底）；
  - `EnginePolicyHooks`（实现 CommandPolicyHooks，见 2.4）。
- **需要 conex-browser-tools 内部 2 处小扩展**（该 crate 无并行改动，低冲突）：
  1. `SessionOps` trait 增加 `async fn ensure_ready(&self) -> Result<(), String>`，
     默认实现返回 `Ok(())`（RealSession 与测试 mock 零改动）；
  2. exec.rs `run_browser_action` 第 ② 步（exec.rs:37-40）改为
     `ops.ensure_ready().await`（保留同步 readiness 的恢复期 gating）。
  效果：**工具面 23 个工具、17 §1.4 六步管线零改动**，仅统一入口多一步 ensure。
- 配置映射：`gate` = 引擎侧注入 17 §4 `DomainGate`（P1；MVP 缺省 MvpDomainGate +
  空白名单默认策略）；`sensitive` = 全关（默认拒绝面红线）；`budgets` = None（默认）；
  `gate_allowlist/blocklist` 留空（P1 前端设置注入）。

### 2.3 D-C register_browser_tools 注册时机

**裁定：引擎构造时后置注册（`EngineHandle::new_with_spawner` 内，
`register_builtin_tools_with_config` 之后、`Arc::new(registry)` 之前，engine.rs:1213-1222
之间插入）。**

- 理由：工具定义静态（23 个），注册表引擎级共享跨 run 复用；惰性注册引入并发注册
  窗口与模型可见性跳变（list_definitions 快照不稳），收益为零。
- 注册失败降级对齐既有先例（engine.rs:1213-1221 warn + tool.not_found 兜底）：
  `if let Err(e) = register_browser_tools(&mut registry, cfg) { warn!(...) }`——失败
  仅缺 browser_* 工具，引擎其余功能不受影响。
- 依赖顺序：`EngineHandle` 需先构造 `Arc<BrowserSlot>`（新字段），再注入
  `BrowserToolsConfig{ session_ops: Some(Arc::new(LazySessionOps::new(slot))), ... }`。
  **EngineHandle 加字段是唯一触碰既有结构的改动点**（§3 冲突矩阵高风险项）。

### 2.4 D-D CommandPolicyHooks 注入

**裁定：MVP 用 AllowAll 实现（新建文件，conex-browser-tools 域提供，引擎装配）。**

- `conex-browser-tools/src/policy.rs`（新文件）提供 `AllowAllPolicy`（零依赖）：
  - `idempotent` → `None`（不短路）；
  - `approve` → `Ok(())`（**CDP 命令级审批放行**——权限面已由 agent-tools 执行器
    侧 dangerous + PermissionMode 三态 + AskChannel 承担，17 §2.2 判定点唯一，不
    重复拦截）；
  - `audit` → tracing 占位（M-4 审计出站接线 P1，脱敏纪律不落敏感值）；
  - `emergency_stop` → 引擎注入的共享 `Arc<AtomicBool>`（既有急停按钮置位）；
  - `abort_token` → slot 持有的 `Arc<CancellationToken>`（M-2 桥，见 2.5）。
- 引擎在 `connect` 时注入：`BrowserSession::connect(endpoint, expected, Arc::new(AllowAllPolicy::new(estop_flag, estop_token)))`。
- 理由：发送层五钩子中 MVP 仅 abort_token/emergency_stop 有真实信号源；approve 与
  audit 重复实现会与工具层既有审批/审计双份记账——AllowAll 是"单一判定点"纪律的
  自然形态（17 §2.2），命令级审批登记为 P1 增强。

### 2.5 D-E abort_token 桥接（M-2）

三层信号当前互不联通（§1.3 表）。MVP 桥：

```
run 级 AbortSignal（core_run_commands.rs:3244，每 run 新建）
   │  run 装配处 spawn watcher（新段，见 S4）：
   │    abort_signal.wait_aborted().await → slot.estop.cancel() + estop_flag.store(true)
   ▼
slot.estop: CancellationToken（BrowserSlot 持有）
   │  = CommandPolicyHooks.abort_token() 返回值（sender.rs:112）→ 发送层在途命令
   │    逐 id 取消（CdpError::Cancelled，sender.rs 语义）
   └─ ActionExecutor 内建 token（session.rs:166）→ 登记遗留（P1 换为 slot token）
```

- 工具侧 `ctx.abort_token`（per-call，tool_exec.rs:809）维持现状：审批等待期取消
  （ApprovalChannel 已接线）与 exec.rs 第①步自查不动；**不做** per-call 与 run 级
  的硬联动（run 级桥已覆盖急停主路径；per-call 令牌无法跨调用存活，桥接无收益）。
- 用户接管（P1 帧流输入转发）与既有急停按钮 → 同一 `slot.estop.cancel()`，语义
  对齐 17 §6.4 ②（发送层）与 ③（分步动作自查）。

## 5. 风险与回滚

| 风险 | 影响面 | 预案/回滚 |
|---|---|---|
| 注册失败（register_browser_tools Err） | 仅 browser_* 缺失，模型侧 tool.not_found，其余引擎功能不受影响 | 对齐先例 warn 降级（engine.rs:1213-1221）；回滚 = 删注册调用 1 行 |
| 浏览器启动失败（进程/端点/握手） | 工具面 `tool.browser.not_ready`（exec.rs gating），run 不受影响（结构化错误喂回模型） | 错误文案带可行动指引（R-9）；启动重试由 BrowserManager 内部状态机承担 |
| 引擎构造 panic（BrowserSlot 装配错误） | **最坏面：应用启动失败** | 红线：装配全走 Result + warn 降级（对齐内置工具注册先例），**禁止 unwrap/expect**；回滚 = 移除新字段/注册调用 |
| 会话槽并发（多 run 并行 ensure） | 双启动竞态 | `tokio::sync::Mutex<Option<...>>` + BrowserManager.start 幂等（非 Stopped 直接返回当前报告，mod.rs:335-341）双保险；S3 单测覆盖并发 ensure |
| 子代理误见 browser_* | 子代理拿到共享会话操作权 | S5 过滤闭包兜底（fail-closed：默认剔除）；未接线前子代理 run 也共享注册表——S4 与 S5 必须同轮落地 |
| Cargo.lock 并行冲突 | 依赖解析合并冲突 | 提交前合并各自增量，cargo 重新解析 |
| conex-browser 未入库丢失 | 测试资产丢失（2026-08-07 事故重演） | **S0 第一步执行**，无回滚选项 |

**回滚总则**：接线 = 新文件 + 依赖 + 2 处高冲突文件的小段新增；无事件 schema 变更、
无数据库 schema 变更、无前端改动——回滚即删除新文件 + 还原 Cargo.toml/engine.rs/
core_run_commands.rs 的增段（git revert 单个提交即可），不影响既有 73 套件基线与
前端门禁。
