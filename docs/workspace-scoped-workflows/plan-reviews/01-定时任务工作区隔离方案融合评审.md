## 二、重大架构裁决与改进项

### 1. 抽屉数据源净化：清退 `cronJobs` 历史暗流
在 `OverviewCard.tsx` 中：
```tsx
// 改造前：
const cronJobs = useSettingsField(selectScheduledTasks);
// workflows 与 cronJobs 累加计数
```
`selectScheduledTasks` 来自 `settingsStore` 的历史 DEMO/占位残余，根本没有物理路径（`cwd`）概念，导致永远在抽屉中展示 2 个幽灵任务。
**改进裁决**：
抽屉计划任务的单一真理源（SSOT）即为引擎真实的 `WorkflowDefinition`（按当前工作区过滤）。若需保留 settings 降级支持，必须同样校验其归属，且在无对应路径时不参与计数。

### 2. 补齐 `useWorkflowsState.ts` 漏传 `cwd` 的底层断层
子 Agent 在代码深度审计中发现：
`useWorkflowsState.ts:308-313` 在调用 `createWorkflow` 时只传了 `name`、`prompt`、`schedule`、`mode`、`enabled`，**遗漏了 `cwd: draft.cwd`**！
导致用户在表单里选了项目，存到底层却成了 `cwd: undefined`！
**改进裁决**：
立即修正 `handleCreate` 与 `handleUpdate`，严格携带 `cwd: draft.cwd` 下发。

### 3. 当前工作区物理根路径的解析权威（SSOT）
在抽屉面板中，当前工作区物理路径的确定规则：
1. 当前处于特定会话时：读取 `session.folder`，通过 `listProjects()` 解析出对应的物理 `path`；
2. 若会话为草稿或无 `folder`：通过 `getWorkspacePath()` 或当前激活项目（`currentProject.path`）作为兜底；
3. 将此权威物理路径传入 `ScheduleSection` 或纯函数过滤选择器。

## 三、最终执行路线图

1. **Step 1：公共路径比对与过滤纯函数**：
   在 `apps/crish-desktop/src/api/projectStore.ts` 或 `workflowScheduler.ts` 中固化 `areWorkspacePathsEqual` 与 `filterWorkflowsByWorkspace`。
2. **Step 2：彻底拔除表单中的“全局”伪概念**：
   更新 `WorkflowForm.tsx`，移除 `{ id: '', label: '默认工作区（全局）' }`，必选项目；更新 `validateWorkflowDraft` 校验 `cwd`。
3. **Step 3：修复 `useWorkflowsState.ts`**：
   补齐 `handleCreate` 遗漏的 `cwd` 传参，接入 `workspacePath` 过滤与会话 `folder` 自动关联。
4. **Step 4：改造 `OverviewCard.tsx` 与 `ScheduleSection.tsx`**：
   基于当前会话/项目的物理路径严格过滤，未配置任务时计数 Badge 彻底消失，展开呈现极简单行「无」。
5. **Step 5：立体化回归验证**：
   单测覆盖路径大小写兼容性、未绑定任务时纯净空态断言，通过真实桌面环境取证。
