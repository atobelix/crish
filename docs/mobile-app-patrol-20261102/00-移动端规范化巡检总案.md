## 一、巡检环境与方法论（后续 Agent 复用）

1. **无头模拟器**：用户离开工位后会话锁屏，模拟器**带窗口启动必崩**（窗口 OpenGL 上下文失效 → `opengl32sw` 加载失败 → 段错误，与 AVD/writable-system/内存无关——勿再误诊）。标准命令：
   `emulator -avd crish_test -no-window -gpu swiftshader_indirect -no-snapshot -no-boot-anim`。
   `screencap` 截图采样不受无头影响。
2. **像素采样法**：`adb exec-out screencap -p` → PIL 找白色面 bbox → 沿穿出边缘的垂直线采样灰度衰减（Δ = 相对背景的变暗量）。已建立的基准见 §三。
3. **uiautomator 定位**：坐标一律从 `uiautomator dump` 的 bounds 取（截图估算会偏 400px）；dump 的 `text` 属性可能是占位符（RN hint），填值验证用截图；git-bash 调 adb 传设备路径必须 `MSYS_NO_PATHCONV=1`。
4. **深链路由矩阵**：`adb shell am start -a android.intent.action.VIEW -d "crish://<route>"` 逐路由打开 + UI 树摘要 + logcat `FATAL EXCEPTION` 计数（回归表见 §五）。
5. **API 34 专用注意**：API 36 镜像有虚拟 pen 设备 + Gboard 手写板教程反复拦截 `input text`（宿主注入失效）；API 34 无此问题。`-writable-system` 在本机两个镜像上均确定性段错误（勿再尝试）。

## 四、规范边界判定（为什么不改——后续勿重复审计）

1. **模块级 StyleSheet 静态间距**：全仓无一例外（无模块级 theme 引用先例）；几何 token 三主题同值、颜色必须 useTheme——现行模式正确。组件体内联裸数字全部是原型直给值+注释背书（Toast 6/14、pip 5.5、审批卡 18/10/14）或 hitSlop。**零真违规。**
2. **容器按钮不加 accessibilityLabel**：内部有可读文本时读屏聚合朗读（加 label 反而屏蔽内容）；**图标钮/透明遮罩层**（IconButton、backdrop）无可读文本、必须带 label——全树核对无缺失。
3. **zIndex 不档位化**：全树仅 3 处（10/10/20）意图清晰；浮层顶层契约靠树序 + Modal（Dialog/Sheet 恒顶、审批浮卡挂根 Stack 末）——3 处数字 + 注释已表达完整意图。
4. **`rgba()` 裸色值 5 处**：全部有原型直给/裁决注释背书（Sheet 把手 0.14、IconButton 玻璃 0.82、Toast 墨色 0.9 等）。
5. **EmptyState 的 64/32 留白**：空态专用大留白，超出 space 阶梯是合理设计。
6. **spring 两平台体系差异**：桌面 Motion v13 `visualDuration/bounce`（全临界阻尼）vs 移动 reanimated `stiffness/damping`（触摸屏偏好回弹）——手感各自调优，不数值对齐（跨端钉版只钉时长四档 + 三缓动曲线）。
7. **worklet 安全**：全仓 3 文件用 `'worklet'`，实现纪律正确（JS 线程值以纯数字捕获进 worklet）；Sheet 2026-11-01 崩溃教训注释 + workletSafety 守卫在位。
