## 关键结论速查

### 1. 丢内容（根因层，已真实宿主坐实）

`apps/crish-desktop/src/api/sessionEventProjection.ts` 对 store 内消息对象**原地 mutate**（`:258`、`:262`、`:282`、`:297`、`:301`、`:307`、`:308`、`:309`、`:327`、`:337`、`:345`、`:355`、`:356`、`:371`、`:389`）⇒ 对象与数组引用均不变 ⇒ `assistantRowPropsEqual`（`chatMessageRowUtils.ts:272` 比较 `prev.msg.blocks === next.msg.blocks`）判等 ⇒ **React.memo bailout ⇒ 不重渲染 ⇒ DOM 停留旧结果**。

**指纹**：fiber props 是新数据、DOM 是旧结果。**下游链路均正确，勿误修。**

> **2026-09-19 复核确认**：上述 mutate 点位逐条回到源码验证为真，memo 判等确为引用比较（`msg.blocks` 使用 `===`）。**该根因未在本次评估中被推翻。**

### 2. 块级结构流式渲染（两层根因）

- **切分层**：`IncrementalBlockSplitter.ts:321-354` 把「段落 / 列表 / 表格」归为一类，持续累积到空行或新块起始才封口 ⇒ 整块在流式全程都是 draft。
- **渲染层**：`MarkdownBlockItem.tsx:83-85` 只对封口块编译，活跃尾块 `:122-124` 直写源码。
- **闪的两个来源**：`:135-138` 的 `el.textContent = ''`（**擦掉容器内残留的上一帧源码**，是刻意的防暴露设计，改法见 `02 §5.4`）+ 源码→渲染的形态剧变。
- **先决条件链**：封口晋升的改造**必须在活跃尾块已渲染真元素之后**，否则会暴露源码。

### 3. 折叠动效（方案缺口，非落地缺失）

`docs/assistant-process-folding/` 8 份详案**从未规定内容区高度过渡**；其 `06-...md:167-192` 的「平滑过渡」指 **BIT 树防阶跃**，与视觉动画是两回事。
**核心难点**：`MessageVirtualizer.tsx:196-208` 的 ResizeObserver 在过渡期间逐帧触发（回调内**无条件** `setActual`，无门禁）⇒ 解法是**动画期高度冻结**（见 `03` §4.2）。

### 4. S7 排队提示

`streamSession.ts:244` 用 `onThought()` 写进**助手思维链通道**，且**绕过**了 `error-notification-governance` 战役已裁决并落地的通知体系。
