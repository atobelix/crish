### B8. 紧凑档的处置（R14，评估后补正）

> **补正记录（2026-09-19 评估）**：初稿本行仅写「**需明确**：主对话界面在该档位下是否仍须 14px」而**未给结论**，与 R3「全改 14px」直接冲突，实现时必然悬空。已补裁决 **R14**。

**事实**：`styles/tokens.css:1330-1335` 定义了一个「紧凑档」覆盖层：`xxs=10px`、`xs=11px`、`sm=12px`、**`base=13px`**、`md=14px`、`lg=16px`。即在该档位下**连 `--font-size-base` 都不是 14px**。

**裁决（R14）**：**紧凑档不得覆盖主对话界面所用的字号令牌。**

**实现口径（二选一，推荐第 1 种）**：

1. **收紧紧凑档作用域**（推荐）：紧凑档仅覆盖侧栏 / 设置 / 状态栏等非对话流区域，**不覆盖** `chat-message-row` / `chat-message` / `chat-tool-call` / `chat-message-list` 四个目录消费的字号令牌。
   - 落地方式：主对话四目录不再消费 `--font-size-base` 这类**可被紧凑档改写**的令牌，改用一个**不受紧凑档覆盖的专用令牌**（如新增 `--md-chat-font-size: 14px`，或直接引用不参与紧凑档覆盖的基值）。
   - 优点：主对话字号恒定，与 R3 一致；紧凑档的既有价值（非对话区省空间）保留。
2. **允许紧凑档生效但主对话强制 14px**：在四个目录显式写死 14px / 专用令牌。
   - 缺点：与「字号令牌 SSOT」纪律有张力，且未来改动需同步两处。

**门禁联动**：§B6 的字号门禁须**在两种档位下各跑一次**（默认档 + 紧凑档），断言主对话界面可见文本 `computedStyle.fontSize` 均 ≥14px。**仅测默认档不足以守住 R14。**

> **注意**：`--font-size-adjust`（`tokens.css:458`，默认 `0px`）是全局微调旋钮，所有 `--font-size-*` 均以 `calc(Npx + adjust)` 定义。若用户调大 `adjust`，主对话字号会 >14px —— 这**不违反** R3（R3 是「不得小于 14px」的下限约束），门禁断言应为 `>= 14px` 而非 `=== 14px`。

### B3. 行高重算（R3 明确要求）

**问题**：多处行高与旧字号绑定，且现存行高本身不准。已知实例：

| 位置 | 现状 | 说明 |
|---|---|---|
| `WorkingStatusIndicator.module.css:6-7` | `height: 24px; line-height: 24px` 配 12px 字号 | 24px 行高对 12px 偏大；改 14px 后须重新校 |
| `ReasoningRow.module.css:191` | `.durationBadge` `font-size: 14px; line-height: 24px` | 已是 14px/24px，可作**基准参照** |
| `FoldableProcessSection.module.css` | 24px 行高体系 | 该体系与 12px 字号绑定；且 `FoldableProcessSection.tsx` 折叠态高度契约依赖 24px |
| `ChatToolCallBlock.module.css:102` | `max-height: 24px` | 单行工具行高度契约 |

**设计要求**：

1. 字号改 14px 后**逐处复核行高**，不得沿用旧值。
2. 24px 单行高度契约（思考行 / 工具行 / 折叠控制栏）需重新推导；`ReasoningRow.module.css:191` 的 14px/24px 组合可作为**已验证基准**（该处已是目标形态）。
3. 行高变更会改变每行实测高度 ⇒ 必须与虚拟滚动协同（见 B5）。

### B4. 代码块的特殊处理（R11）

代码块 14px 等宽字体会**显著加宽行宽**，增加横向滚动。要求：

1. 复核代码块容器是否具备 `overflow-x: auto`；若无需补齐。
2. **不改字号**（R11 已定），只做**容器侧适配**。
3. 既有 `applyCodeIndentToRenderedRoot` / `normalizeCodeBlockIndent`（`api/codeBlockIndent.ts`）需复核在 14px 下的缩进表现。

### B5. 与虚拟滚动的协同

字号 + 行高同时变更 ⇒ **所有历史消息的实测高度全部失效**：

1. 变更后需触发一次全量高度重测（`api/VirtualScrollManager.ts` 的 `hydrateHeightMap`，见 `:348`）。
2. 若存在持久化高度缓存，需一并失效，否则滚动定位错位。
3. 真实宿主复核长会话滚动定位准确性。

### B9. 防回潮门禁

新增**字号门禁**：

- 扫描主对话界面四个目录的 CSS，**不得出现 <14px 的字号声明**；
- 允许白名单（如纯装饰性图标尺寸），白名单须逐条注明理由与 owner（对齐仓库「豁免表三分」纪律）；

5. 字号门禁在 CI 生效：人为插入 12px 声明即变红；**紧凑档下插入 13px 声明同样变红**。
