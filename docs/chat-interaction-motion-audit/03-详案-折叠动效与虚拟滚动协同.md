## 0. 要解决的问题

用户的产品调性是**克制的动效** —— 少而精，但**该有的地方必须有**。当前是「该有的地方也没有」：

- 主对话**整段折叠**（点击频率最高的折叠交互）**零高度过渡**；
- 思考行**结构性无法过渡**；
- 唯一有高度动画的单条工具行因 `max-height: 2000px` **缓动失真**；
- 子 Agent 面板**实际不可折叠**（`open` 无 setter）；
- 工具输入/输出展开**无过渡**。

同时存在一个**真实的架构冲突**：高度动画会与虚拟滚动的高度自愈机制打架（见 §4）。

## 2. 目标：克制的动效（哪些必须有）

按「克制」原则划定**动效作用域**，避免全站滥加：

| 场景 | 是否加高度过渡 | 理由 |
|---|---|---|
| 用户**主动点击**触发的展开/折叠 | **必须有** | 直接操作反馈，无动效即「无响应感」 |
| 流式过程中**自动**发生的展开（如运行中直出展开） | **不加**（或仅淡入） | 非用户操作，加动画会干扰阅读节奏 |
| 收口时**自动**折叠 | **不加** | 同上；且此时用户正在读内容 |
| 检索命中（Ctrl+F `beforematch`）触发的展开 | **不加** | 需要立即定位，动画会延迟命中呈现 |

⇒ **动效只挂在「用户主动点击」这一条路径上**，其余路径即时生效。这是「克制」的具体落地口径。

## 4. 核心难点：高度过渡与虚拟滚动的冲突及解法

### 4.1 冲突机理

| 环节 | 位置 | 行为 |
|---|---|---|
| 高度失效 | `api/VirtualScrollManager.ts:327-341` | `invalidateActual` 保持当前高度与 BIT 树不变（**故意**，防止视口抖动） |
| 高度观测 | `components/chat-message-list/MessageVirtualizer.tsx:196-208` | `ResizeObserver` 在 CSS 过渡期间会**逐帧触发**（约 60 次 / 动画），每次 `setActual` 更新 Fenwick 树并触发重渲 |
| 全量重测 | 同文件 `:240-252` | `useLayoutEffect` 每次 render 全量重测 |

⇒ 直接加 CSS 高度过渡的后果：**逐帧喂 VSM** ⇒ 每帧 O(log N) 树写入 + React 重渲 ⇒ 掉帧、滚动抖动。

### 4.2 解法：动画期高度冻结（Animation-Time Height Freeze）

**不变量**：动画进行期间，该消息行的高度**对 VSM 保持冻结**；动画结束后**一次性**写入终值。

```
点击展开
  ├─ 标记 msgId 进入 animating 集合
  ├─ 触发 CSS 过渡（grid-template-rows 0fr → 1fr）
  │    └─ ResizeObserver 逐帧触发 → 被 animating 门禁拦截，不调 invalidateActual/setActual
  └─ transitionend（或超时兜底）
       ├─ 清除 animating 标记
       └─ 调用一次 invalidateActual(msgId) → RO 回调写入终值 → Fenwick 树更新一次
```

**关键点**：

1. 冻结的是**VSM 写入**，不是 CSS 过渡本身（视觉动画照常）。
2. 必须以 `transitionend` 为准，**并设超时兜底**（避免 `transitionend` 因元素卸载/属性未变而不触发，导致永久冻结）。
3. 兜底超时时长取令牌时长 + 安全余量，**不得使用魔术数字**（应从 `--transition-accordion` 读取，参考既有 `utils/motionTokens.ts` 的 `readTransitionMs` / `readTokenMs` 读取工具）。
4. `prefers-reduced-motion` 下过渡时长为 0 ⇒ `transitionend` 可能不触发 ⇒ 必须走超时兜底路径（或在冻结入口直接检测 reduced-motion 并跳过冻结）。

> **口径统一（2026-09-19 评估）**：本节的「动画结束后**主动调用一次** `invalidateActual`」与 `02-详案` §4.7 初稿的「**不得手动调用**」曾相互冲突。已按 `02-详案` §4.7 的统一规则对齐，**两条规则按场景并存**：
> - **纯流式追加**（无动画）→ RO 自然触发，协调器**不主动写 VSM**；
> - **折叠动画中** → RO 被 animating 门禁拦截，动画结束后**主动写入一次**（本节流程）；
> - **交叉场景** → **用户操作优先**，冻结窗口内忽略流式触发的自动高度变化，窗口结束后一次性写入合并终值。
>
> 两者由 animating 门禁互斥，**不存在同时写 VSM 的窗口**。

### 4.3 与任务 C（真增量流式渲染）的协同

任务 C 保证「流式期间只追加、不重建」⇒ 高度单调增长 ⇒ 与动画期冻结**天然相容**（不会出现「冻结期间又有自动高度变化」的竞争）。

**唯一需注意**：若流式追加恰好发生在用户点击折叠的同一帧，需以**用户操作优先**（冻结窗口内忽略自动高度变化，结束后一并写入终值）。

## 5. 逐点设计

### 5.1 主对话整段折叠（`FoldableProcessSection`）

**现状**：`hidden="until-found"` 切 `display`，无过渡。该属性用于 Ctrl+F 穿透（`beforematch` 唤醒，`:192-205`）。

**设计要求**：

1. **保留** `hidden="until-found"` 语义（Ctrl+F 穿透是一等公民，不得牺牲）。
2. 过渡载体改为 **`grid-template-rows: 0fr ↔ 1fr`** + 内层 `overflow: hidden`：
   - 该模式已在侧栏生产在用：`components/sidebar/SidebarSessionList.module.css:22-35`、`session-list/ProjectsSection.tsx:105`；
   - **对话流版本已写好但未接线**：`components/agent-card/InlineAgentPanel.module.css:361-380`；
   - 优先复用，不新造。
3. **与 `hidden` 的协同**：`hidden` 会强制 `display: none`（不可过渡）。需改为「用 `grid-template-rows` 表达折叠，`hidden` 仅在**动画结束后**挂上」，即：
   - 展开：先移除 `hidden` → 下一帧置 `1fr`；
   - 折叠：先置 `0fr` → `transitionend` 后挂 `hidden="until-found"`。
4. 动效**仅挂在用户点击路径**（§2）：`beforematch` 唤醒与收口自动折叠**即时生效、不播放动画**。

### 5.2 思考行（`ReasoningRow`）

**现状**：条件渲染 + `contain: size layout`（`.module.css:15-22`）⇒ 结构性无法过渡。

**设计要求**：

1. 折叠态**保留 DOM**（不再 `{isExpanded && ...}`），改为与 §5.1 同构的 `grid-template-rows` 方案。
2. **`contain: size layout` 需重新评估**：它使元素对自身尺寸变化「不可见」，会阻断过渡。建议折叠态改用 `contain: layout paint`（保留隔离收益、放开尺寸过渡），或仅在过渡期间临时移除。
3. 保持 24px 折叠态高度契约（与既有排版纪律一致）。

### 5.3 单条工具行（`CompactToolRow`）

**现状**：`ChatToolCallBlock.module.css:388-397` 的 `max-height: 0 → 2000px`。

**设计要求**：

1. **替换 `max-height` 方案**为 `grid-template-rows: 0fr ↔ 1fr`（与 §5.1 统一），消除目标值失真。
2. 若因结构限制必须保留 `max-height`，则目标值须为**实测像素高度**（由 `ResizeObserver` 测得并写入 CSS 变量），**严禁使用 2000px 这类远大于实际值的魔数**。
3. 既有 `useToolExpansionState` 的预锚点捕获/补偿逻辑（`chat-tool-call/toolExpansionState.ts:557-574`）须保留并与新方案兼容。

### 5.4 工具输入/输出面板

**现状**：`ToolCallInputPane.tsx:194-224` 与 `ToolCallOutputPane.tsx` 条件渲染，无过渡。

**设计要求**：

1. 与 §5.3 同构（工具行展开时，输入/输出面板作为其内部结构一并过渡，不单独播动画，避免「双重动画」）。
2. 输出面板可能含大段文本/表格：过渡期间需 `overflow: hidden`，且**不得**因过渡触发内部表格重新布局（与 `02-详案` §4.5 的列宽策略一致）。

### 5.5 子 Agent 面板（`InlineAgentPanel`）

**现状**：条件渲染；`open` 无 setter（`InlineAgentPanel.tsx:56`、`:186-190`）⇒ **实际不可折叠**。用户明确要求该面板与主对话同构，需覆盖。

**设计要求**：

1. **补上 `open` 的 setter**（交互缺陷修复，非纯动效）：点击行标题应切换 `open`，而非仅跳侧栏。
2. 过渡与主对话同构（§5.1）。
3. 保留跳侧栏的入口（作为**第二个**操作，不替代折叠）。
4. 该面板嵌套在主对话过程段内 ⇒ 其展开会改变外层高度 ⇒ 必须走 §4.2 的冻结机制。

## 8. 验收断言（机器可判定）

### 8.1 视觉过渡存在性

1. **高度单调变化**：点击展开后连续采样容器 `getBoundingClientRect().height`，须出现**≥3 个不同中间值**（证明是过渡而非瞬变）。
2. **时长合规**：从点击到高度稳定的耗时落在令牌时长 ±20% 区间内（从 `--transition-accordion` 读取，非硬编码期望值）。
3. **chevron 同步**：chevron 的 `transform` 过渡与高度过渡同时开始（同帧）。

### 8.2 与虚拟滚动协同（核心）

4. **冻结生效**：过渡期间对 `VirtualScrollManager.setActual` 打点，断言调用次数 **≤1**（动画期间为 0，结束后 1 次）。
5. **终值正确**：过渡结束后，VSM 中该行高度等于 DOM 实测高度（误差 ≤1px）。
6. **无滚动跳动**：过渡期间容器的 `scrollTop` 变化为 0（或符合预期锚定），不出现抖动。
7. **超时兜底**：模拟 `transitionend` 不触发，断言冻结在令牌时长 + 余量后自动解除（不永久冻结）。

### 8.3 降级

8. **reduced-motion**：在 `prefers-reduced-motion: reduce` 下，过渡时长为 0（即时完成），且**不进入冻结**（或立即解除）。
9. **快速连击**：连续 5 次快速点击展开/折叠，最终状态与最后一次点击一致，无高度错乱。

### 8.4 交互完整性

10. **子 Agent 面板可折叠**：点击行标题切换 `open`，且过渡与主对话同构。
11. **Ctrl+F 穿透保留**：折叠态内容仍可被页面搜索命中并唤醒（`beforematch` 行为不变）。

## 9. 反过度设计边界

| 禁止 | 理由 |
|---|---|
| 引入 `framer-motion` / `motion` 等动效库 | 全仓当前零使用；CSS 过渡足以覆盖本任务全部场景 |
| 用 JS 逐帧插值高度（rAF 循环） | CSS 过渡性能更优；逐帧写高度会与 VSM 打架 |
| 用坐标测距 / 魔术数字补偿 | 违反仓库纪律（`AGENTS.md` §7） |
| 给所有展开点统一加动画 | 违反「克制」；§2 已划定动效只挂用户点击路径 |
| 为折叠新建一套独立容器组件并复制样式 | 应复用既有 accordion 模式与未接线资产（`InlineAgentPanel.module.css:361-380`） |
