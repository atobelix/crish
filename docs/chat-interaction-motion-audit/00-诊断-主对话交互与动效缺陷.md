# 主对话界面交互与动效 · 缺陷诊断（00）

> 性质：**只读诊断**（分析产物，不含实现方案）。
> 触发：用户反馈两现象 —— ①「工具折叠行的展开和折叠，感觉就是没有动画的效果，或者比较差」；②「『当前会话上一轮任务仍在收尾中，已自动为您排队。』应在主对话界面顶部通知，现在直接入侵了对话界面，而且变成了工具调用的内容展示」。
> 用户给定原则：**排队、错误信息展示、重试这类瞬时状态，一律不留在对话流里**；动效调性为**克制**（少而精，但该有的必须有）。
> 方法：四路并行只读普查（通知链路 / 展开折叠实现 / 对话流内容归属 / 动效令牌体系）+ 主控实地复核关键结论。

---

## 0. 一句话总览

两个现象不是孤立的样式瑕疵，而是**同一类架构断层的两种表现**：**「过程 / 运行状态」与「对话内容」之间的边界没有被系统性建立**。
- 瞬时运行状态（排队）没有合法承载面，只能借道**助手的思维链通道**（`thinking`）混入对话流；
- 过程可视化（折叠容器）的**视觉过渡从未被设计**，既有战役只设计了「数据结构层的平滑」而非「视觉层的动画」。

## 1. 维度一：瞬时状态污染对话流

### 1.1 根因链（排队提示 S7）

| 环节 | 位置 | 事实 |
|---|---|---|
| 文案定义 | `apps/crish-desktop/src/api/userFacingErrors.ts:140` | `S7: '当前会话上一轮任务仍在收尾中，已自动为您排队。'` |
| 域判定 | `apps/crish-desktop/src/api/userFacingErrors.ts:163` | `SESSION_BUSY_RE = /SESSION_BUSY\|已有活动 run\|串行守卫/i` |
| **写入点（根因）** | `apps/crish-desktop/src/api/chat-bridge/streamSession.ts:244` | `callbacks.onThought?.(DOMAIN_MESSAGES.S7)` —— **把运行状态通知写进了助手的思维链** |
| 汇聚 | `apps/crish-desktop/src/hooks/chat-stream/useRunStreamingAssistant.ts:210-217` | `onThought` 推入 `thinkingBatcher` → 成为助手消息的 `thinking` 字段 |
| 渲染 | `apps/crish-desktop/src/components/chat-message/ProcessItemRenderer.tsx:59-104` | 按 `item.kind === 'thought'` 渲染，与工具块（同文件 `:146` 起）**同处一个过程段** |

**结论**：用户观察到的「变成了工具调用的内容展示」由此坐实 —— 排队提示被当作思考项，与工具调用渲染在同一个过程段内。这是**语义误投**，不是样式问题。

### 1.2 第二处入侵：用户气泡的「排队中」角标

| 位置 | 事实 |
|---|---|
| `apps/crish-desktop/src/api/chat-bridge/streamSession.ts:249-253` | 把用户消息状态置 `'queued'` |
| `apps/crish-desktop/src/components/chat-message-row/ChatUserMessageRow.tsx:316` | 在用户气泡内渲染「排队中」角标 |

`queued` 不落库（`apps/crish-desktop/src/store/types.ts:358`），语义上确属瞬时状态，但渲染面在对话流内。

### 1.3 既有治理体系已被绕过（关键）

`docs/error-notification-governance/00-cross-analysis.md` 已于 2026-08-09 裁决展示面收敛：

> 结论 1 收敛点：**onRunError 按错误分类选面**（network/恢复类 → 输入框上方持久条；有正文失败 → 仅气泡卡；无正文失败 → 仅横幅；可行动错误 → 横幅+一次 toast）。

该体系在代码中**已完整落地**：

| 环节 | 位置 |
|---|---|
| 分流裁决 | `apps/crish-desktop/src/hooks/chat-stream/streamCallbacksSurfaces.ts:131` `resolveRunErrorSurface()` |
| 分发执行 | `apps/crish-desktop/src/hooks/chat-stream/streamCallbacksEvents.ts:328-339` |
| 正确承载面 | `apps/crish-desktop/src/components/chat-card/RunNoticeBar.tsx:21` → `ChatStatusRibbons.tsx:377` → `ChatComposerWrapper.tsx:165`（**输入框上方，不在对话流内**） |
| 推送入口 | `apps/crish-desktop/src/hooks/chat-stream/index.ts:160` `pushRunNotice` |

**但 `streamSession.ts:236-266` 的 S7 分支是一条旁路**：它捕获 `startRunTask` 异常后直接 `onThought` + `setSessionMessageStatus('queued')` + `runControl.followUp({ reason: 'serial-guard-auto-queue' })`，**全程不经过 `onRunError` / `resolveRunErrorSurface` / `pushRunNotice`**。

⇒ 这是**对既有裁决的架构回退**：新加的自动排队能力绕过了已建立的展示面治理体系，而不是接入它。

### 1.4 语义失真：文案声称的与代码做的不一致

`streamSession.ts:240-267` 确认存在**真排队 + 收口后重放**机制（`runControl.followUp` → `useGoalMode.ts:160-187` `drainQueuedAfterComplete` 把 `status==='queued'` 的用户消息置 `'processing'` 并重放）。
而次路径（`runtime-error` → `surfaceStreamFailure`）同样输出 S7 文案，却**并不入队**（`apps/crish-desktop/src/api/chat-bridge/BridgeErrorPolicy.ts:99` 把所有域统一归 `kind='network'` → 走 `persistent` 分支，仅展示不入队）。
⇒ **同一文案对应两种事实**：一条真的排队了，一条只是提示。文案与实际语义脱节。

### 1.5 类型层的结构性根因

| 位置 | 事实 |
|---|---|
| `apps/crish-desktop/src/store/types.ts:352` | `MessageSender = 'user' \| 'assistant'` —— **无 `'system'`** |
| `apps/crish-desktop/src/store/types.ts:527` | `SessionMessage` 无 notice / 通知类消息类型 |

⇒ 任何系统级瞬时通知**在类型层没有合法落点**，只能借道 `thinking`（如 S7）或 `errorDetail`。这是「必然入侵对话流」的结构性根因，不修类型层则同类问题会持续复发。

## 2. 维度二：折叠展开动效缺失

### 2.1 先澄清一个陷阱：真正的折叠组件不是 `FoldableToolGroup`

| 组件 | 生产引用 | 结论 |
|---|---|---|
| `apps/crish-desktop/src/components/chat-tool-call/FoldableToolGroup.tsx` | **零引用**（仅 `MessageToolCallsSection.tsx:133` 注释提及） | **死代码** |
| `apps/crish-desktop/src/components/chat-message/FoldableProcessSection.tsx` | `apps/crish-desktop/src/components/chat-message/MessageContent.tsx:569` | **真实生效** |

⇒ 任何针对折叠动效的修改若落在 `FoldableToolGroup.tsx` 将完全不生效。此文件应作为死代码清理，避免后续误修。

### 2.2 主对话整段折叠：零高度过渡

| 位置 | 事实 |
|---|---|
| `apps/crish-desktop/src/components/chat-message/FoldableProcessSection.tsx:178-189` | callback ref 原生切换 `hidden="until-found"` 属性 |
| `apps/crish-desktop/src/components/chat-message/FoldableProcessSection.module.css:131-137` | `.sectionBody:not([hidden]) { display: flex; ... }` |
| `apps/crish-desktop/src/components/chat-message/FoldableProcessSection.module.css:106` | 仅 chevron 有 `transition: transform var(--transition-micro, 100ms ease-out)` |

**展开/收起是 `display` 的瞬时切换，没有任何高度过渡。** 这是用户「感觉就是没有动画的效果」的直接对应项 —— 也是主对话里**点击频率最高**的折叠交互。

### 2.3 思考行 `ReasoningRow`：条件渲染导致无法过渡

| 位置 | 事实 |
|---|---|
| `apps/crish-desktop/src/components/chat-message-row/ReasoningRow.tsx:219-233` | `{isExpanded && <div>...}` —— 整体挂载 / 卸载 |
| `apps/crish-desktop/src/components/chat-message-row/ReasoningRow.module.css:15-22` | 折叠态 `contain: size layout; height: 24px` |
| 同文件 `:205-207` | 仅 chevron 有 `transform 150ms` |

条件渲染使节点在折叠时**不存在于 DOM**，无法对挂载态施加 CSS 过渡；`contain: size layout` 进一步阻断尺寸过渡。

### 2.4 唯一有高度动画之处：缓动严重失真

| 位置 | 事实 |
|---|---|
| `apps/crish-desktop/src/components/chat-tool-call/ChatToolCallBlock.module.css:388-397` | `max-height: 0` → `max-height: 2000px`，`max-height 220ms var(--ease-emphasized)` |

目标值 `2000px` 远超实际内容高度 ⇒ 220ms 中**前约 10% 就走完真实高度**，后段视觉静止。用户感知为「比较差」的正是此处。

### 2.6 与虚拟滚动高度自愈的耦合（加动画的真实障碍）

| 位置 | 事实 |
|---|---|
| `apps/crish-desktop/src/api/VirtualScrollManager.ts:327-341` | `invalidateActual` 注释：「**保持当前高度与 BIT 树不变，平滑过渡防止视口抖动**」 |
| `apps/crish-desktop/src/components/chat-message-list/MessageVirtualizer.tsx:196-208` | `ResizeObserver` 在 CSS 过渡期间会**逐帧触发**（约 60 次 / 动画），每次 `setActual` 更新 Fenwick 树并触发重渲 |
| 同文件 `:240-252` | `useLayoutEffect` 每次 render 全量重测 |

**关键辨析**：既有方案中的「平滑过渡」指的是**数据结构层不阶跃**（防视口抖动），**不是视觉层的展开动画**。两者被同一词汇覆盖，容易误判为「已经做了动画」。

⇒ 加高度动画的正确约束：**动画期间冻结该行高度、动画结束后再 `setActual`**，避免逐帧喂 VSM。

### 2.7 既有折叠战役的方案缺口（重要）

`docs/assistant-process-folding/` 全 8 份详案中，与动效相关的条款仅有：

| 位置 | 条款 |
|---|---|
| `docs/assistant-process-folding/03-图一至图四展开态UI组件详案.md:88-135` | chevron 补全 + 150ms 旋转过渡 |
| `docs/assistant-process-folding/03-...md:483` | 流式思考扫光动效 + reduced-motion 降级 |
| `docs/assistant-process-folding/03-...md:494` | **展开防抖（100ms Debounce）**：拦截快速误触连击，防止动画过程中多次突变高度 |
| `docs/assistant-process-folding/06-动态测高自愈与检索集成详案.md:167-192` | 「平滑过渡不变量」—— 实为 BIT 树防阶跃，非视觉动画 |

**⇒ 全套方案从未规定「内容区展开 / 收起时的高度视觉过渡」。** `03-...md:494` 的「展开防抖」反而暗示作者认为展开会「突变高度」而只需防连击，未把动画列为目标。

**结论：这不是落地缺失，是方案缺口。** 折叠动效需作为既有战役的补充条款立项，而非当作 bug 修复。
