## 核心新机制（单一实现）

`api/tool-presentation/timelineReconciler.ts` 新增两个导出函数，全仓正文建块只此一套：

- `applyStreamedTextToBlocks(blocks, prevText, nextText, opts?)`：正文分段记账。每段正文是一个 text 块，创建即带稳定 id `text-seg-<序号>`（序号 = 消息内正文段创建序，永不复用）与 turnIndex（以最近 thought 块的轮次推导，创建后永不改写——改写会使 reconcile 槽位键漂移）。段间以 tool_call / thought 块为物理界标：界标之后的首个 text 块为活跃段，流式增量只并入活跃段；界标落下即封口上一段。非增量改写（message-end 权威全文、收口择优全文、占位清理）走**锚点重对齐**：已封口段以其内容 trim 后为锚在新全文中顺序定位并换成新版本，尾部余量归活跃段（无活跃段则新建段）——已封口段永不丢失、永不沉底、相对顺序永不改变。`opts.sealActive` 供事件投影在引擎消息切换时显式封口（无工具间隔的相邻段不得并段）。
- `sliceActiveStreamText(streamText, blocks)`：渲染层从流式缓冲切出活跃段正文（已封口段内容依次锚定剥离，剩余即活跃段含未落块增量），替代原偏移切片。

## 逐项对账

### 1. 删补偿、改回插（S1）—— `api/tool-presentation/timelineReconciler.ts`

- `normalizeAssistantTimeline`：**物理删除**补偿①（「有正文但 blocks 无 text 块 → 整条 msg.text 拼成一块追加末尾、turnIndex 0」）。替换为严格限定的无账本兜底：仅当 blocks 与既有块中**一概没有任何 text 块**（分段记账从未在此消息上运行）时，才把全文作为单一段置于末尾（最终答复位是无段信息时的最优先验，且不改变其余块的相对顺序）；凡已存在的 text 块一律经 reconcile 回插。分段记账落地后，正常路径永不触发此兜底。
- `reconcileAssistantMessageBlocks` 第 3 步：**删除**「孤儿一律追加末尾」，改为**邻居锚点回插**——按孤儿块在既有全序中的位置，优先锚定最近的已落位前邻、其次最近的已落位后邻插入，两者皆无才按既有序追加。为此步骤 1/2 新增既有全序与结果键序的平行记录。
- 思考重水合定位：`normalizeAssistantTimeline` 中 thinkingTurns 重建块原为「turn 0 unshift、turn>0 一律 push 末尾」——改为新增 `insertThoughtBlockAtTurnPosition`：同轮 text 块之前 → 更大 turnIndex 块之前 → turn 0 置首 → 否则末尾（最末轮的保序位置）。事故里中段轮次思考被沉底的路径就此关闭。legacy `msg.thinking` unshift 与 thought-legacy 自愈保留（位置正确、且是存量数据修复，非本次点名的两处补偿）。

## 遗留风险（登记）

1. **同任务批量工具事件的段合并窗**：`commitToolPatchToSession` 的微批队列以 queueMicrotask flush，且每个工具经 upsertToolCall 时先快照封口、本批又在入队口补了封口——常规事件投递（一事件一任务）下顺序严格。仅当桥接层在同一同步任务内批量投递「工具→正文→工具」且 flush 未插队时，两段正文可能先并入同一活跃段、工具块随后落在段后。要根除需在入队时记录段界并在 flush 时做段内切分（涉及新的 store 级段切分原语），本批未建；触发条件苛刻且 O1 实测流式期顺序正常，建议收口阶段以桥接层批量投递夹具复核后再裁决是否补建。
2. **无 id 载荷的分段上限**：事件投影对完全没有引擎消息 id 的旧载荷只能以 turnIndex 为段键（退化 turnIndex 下同 turn 的不同段仍会被判为修订覆盖）——真实引擎载荷的 AgentMessage.id 为必填字段，事故会话亦带 id，此限仅及合成/远古载荷；F3 重建时如遇无 id 事件段，可按事件序号补充合成身份。
3. **subagentTimeline 的思考仍走平铺字段**：该面板投影不建 thought 块（a.thinking 仍为最后一轮覆写），其思考展示依赖 normalize 的 thinkingTurns/legacy 重水合。本批按任务书范围只补正文分段；面板多轮思考的逐段化未做，登记待裁决。
4. **MessageContent 的 sliceActiveStreamText 锚定前提**：已封口段内容（trim 后）须为流式缓冲的子串；权威改写已把段内容换成 trim 后的权威片断，其仍是原始缓冲的子串（仅边缘空白差）。锚定失败时函数即停剥离（宁可少量重复、绝不丢正文），且仅影响流式中的尾段呈现，收口后以 blocks 为准。
5. **Rust 侧 stream_text_offset 字段**：前端已不读不写；conex-types/DB 列的去留归 F2（其定稿组装批）裁决，前端行为不依赖它。
