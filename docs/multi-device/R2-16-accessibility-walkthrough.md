## 1. 第一部分：动态字体走查（R2UX-06-04）

### 1.1 走查口径与通用流程

**规范锚点**（R2UX-06-04 / R2UX §4.3 / M4 §6.5 / M4 §3.3）：

1. 所有 Text `allowFontScaling` 默认开（**代码实读确认**：全仓 grep 无任何 `allowFontScaling={false}` / `maxFontSizeMultiplier` 显式设置——所有文本均跟随系统缩放，符合 M4 §3.3「不逐处设置」；但也意味着**没有任何字号上限保护**，固定高度元素内文本会缩放后截断）；
2. 系统缩放 1.0-2.0× 不破版：flex 布局 + 文本不截断**关键信息**；列表行允许随缩放增高；
3. Android ≥200% 无障碍要求（与 iOS 2.0× 对齐）；
4. 固定高度元素（TabBar/AppBar/决策区）内文本缩放验证：**超高时换行/增高而非截断**；
5. 系统最大字号下逐屏走查（M4 §5.10 每屏必测）。

**通用验证步骤**（每屏执行）：

1. `adb shell settings put system font_scale 2.0`；
2. 进入目标屏（配对态依赖 E2E-1；未配对屏可直接进入）；
3. 逐项检查清单表所列布局点；可疑组件截图（`screencap`）；
4. 断言通过/失败记入 §4 执行记录表（失败 → 附截图 + 该组件行号）；
5. 检查滚动容器可滚动、无内容被推出可视区、无文字重叠。

**通用期望断言**：

- 页面无横向溢出（无元素被推出屏外、无水平滚动条意外出现）；
- 关键信息（标题/工具名/决策按钮文案/状态文案）不截断；元信息（时间/大小）截断可接受（R2UX §4.2-2：元信息 ≥3:1 档，信息损失最小化即可）；
- flex 容器随文本增高（列表行 `minHeight` 可增长）、无固定高度容器内文字被垂直裁剪；
- 空态/错误态/骨架态同规走查（M4 §5.10：三态闭环逐屏验收）。
