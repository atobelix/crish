## 1. 平台基线

### 1.1 平台差异矩阵（iOS vs Android）

两平台共享 M4 自研组件库与 token（语义名逐项对齐桌面 `tokens.css`，M4 §3.2），差异只在「平台原生能力与系统惯例」面，全部收敛到适配层 `adapters/platform/` 封装（M4 §2.2.2），表现层不感知平台。

| 差异维度     | iOS                                       | Android                                   | 处置（基准出处）                                                                                                           |
| ------------ | ----------------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 触控目标     | ≥44×44pt（HIG 推荐最小）                  | ≥48×48dp（M3 触控目标规范）               | **双轨热区**：视觉统一 ≥44，Android 热区上浮 48（`HitSlop` 透明扩展，见 §1.2）；M4 §3.4 的「最小可点 44×44dp」为下限不冲突 |
| 返回手势     | 系统边缘左滑（全屏/边缘手势）+ 左上返回钮 | 系统返回键 / 手势条（返回语义=Stack pop） | expo-router Stack 原生行为（M4 §6.1）；Android 返回键在深链页应回到发起 Tab 而非退出 App（M4 §4.2 规则 1）                 |
| Tab 导航     | 底部 tab，支持安全区凹槽                  | 底部导航（M3 规范），无凹槽但有手势条区   | `react-native-safe-area-context`（骨架已装）；TabBar 56dp（M4 §3.4）                                                       |
| 下拉刷新     | RefreshControl（原生）                    | 同左                                      | 原生控件，不自定义（M4 §6.1，平台原生优先）                                                                                |
| 触感反馈     | UIImpactFeedbackGenerator（轻/中/重）     | Haptic Feedback 三档                      | `adapters/platform/Haptics.ts` 三档封装 + 全局可关（M4 §0.2 决策表）                                                       |
| 系统返回数据 | —                                         | 返回键可被应用拦截                        | 拦截仅用于「deciding 返回保护」（F2 §9.3-6），不得用于业务埋点                                                             |
| 动态字体     | Dynamic Type（5 级 + AX1-AX5 辅助级）     | 系统字体缩放（支持 ≥200% 无障碍要求）     | 所有 Text `allowFontScaling` 默认开（M4 §3.3）；验证口径见 §4.3                                                            |
| 键盘避让     | KeyboardAvoidingView（behavior=padding）  | adjustResize（系统自动）                  | 输入场景（配对码/拒绝理由/设置）键盘不遮挡焦点，见 §2.3-4                                                                  |
| 深色模式     | 跟随系统外观                              | 跟随系统 + 可手动三选                     | M4 §3.2 三选（跟随/浅/深），token 完整性单测（§4.2）                                                                       |
| 通知         | APNs + 前台应用内横幅                     | 通道 + 前台应用内横幅                     | F2 §6 统一；前台同源事件不双弹（F2 §6.3）                                                                                  |
| 启动屏       | 品牌静态图                                | 同左                                      | Expo splash 无动画（M4 §7.2 启动屏行）                                                                                     |

### 1.2 触控目标与热区基线（44pt / 48dp 双轨）

| 规则                   | 数值                           | 基准出处                  | 落地方式                                                      |
| ---------------------- | ------------------------------ | ------------------------- | ------------------------------------------------------------- |
| 视觉可交互元素最小尺寸 | ≥44×44（双平台视觉一致）       | HIG / M4 §3.4 触控尺寸    | 自研组件库统一常量 `minTouchSize = 44`                        |
| Android 命中热区       | ≥48×48dp                       | M3                        | `Pressable hitSlop` 补足到 48（视觉不变、热区扩展）；iOS 不补 |
| 行内小按钮间距         | ≥8dp                           | HIG（最小间距）/ M4 §6.5  | 组件间距 token 约束                                           |
| 决策按钮高度           | 44dp（常规）/ 48dp（宽松密度） | M4 §3.7 Button            | Button 组件两档高度（M4 §3.7-1）                              |
| 决策按钮间距           | 两按钮间距 ≥48dp               | HIG / M4 §6.2 / F2 §9.3-1 | ApprovalActionBar 布局常量                                    |
| 列表行高               | 44 / 56 / 72 三档              | M4 §3.4 / F6 §9 密度三档  | ListRow 组件 density prop                                     |

**热区验证**：组件测试断言 `touchTargetSize >= 44`（iOS）与热区扩展逻辑存在；maestro E2E 用真实点击坐标边界验证（如决策按钮边缘点击仍命中）。

### 1.3 导航与返回语义

| 场景                   | 语义                                                  | 基准出处                                            |
| ---------------------- | ----------------------------------------------------- | --------------------------------------------------- |
| 常规 push              | 返回 = pop 上一页                                     | M4 §4.2 规则 1                                      |
| 推送深链冷启动         | 目标页入栈，返回回首页（不堆叠中间页）                | M4 §4.2 规则 1 / F2 §6.2                            |
| 跨 Tab 跳转后返回      | 回到发起 Tab 并静默刷新一次（角标收敛）               | M4 §4.2 规则 2                                      |
| 深链目标不存在         | 渲染对应空态（已过期/已归档/已删除）+ 可返回，不崩溃  | M4 §4.2 规则 3 / M4 §5.9 深链目标不存在行           |

| 返回保护（决策中）     | deciding 状态返回列表，条目显示「处理中」，防重复操作 | F2 §9.3-6                                           |

## 2. 交互规范

### 2.1 手势分层与冲突仲裁

**手势总表**（M4 §6.1 手势体系 + 本方案补充分层与仲裁参数）：

| 层级          | 手势                                       | 作用域            | 基准出处 |
| ------------- | ------------------------------------------ | ----------------- | -------- |
| L0 系统手势   | 边缘滑返回、系统返回键、通知下拉           | 全局（系统接管）  | HIG / M3 |
| L1 列表手势   | 纵向滚动、下拉刷新、上滑加载、点击吸底     | 列表类页          | M4 §6.1  |
| L2 行内手势   | 长按（上下文 Sheet）、横向滑动（审批滑轨） | 审批详情 / 列表行 | M4 §6.1  |
| L3 页面内手势 | feed 过滤 chips 切换、分段控件切换         | 会话详情          | M4 §5.5  |

**冲突仲裁规则**（本方案核心，解决 ScrollView + PanResponder 互斥的社区难题）：

| 冲突对                               | 仲裁规则                                                                                                                                                 | 实现（社区实践）                                                                                                        |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 横向滑轨（滑动确认） vs 纵向列表滚动 | **方向正交 + 激活阈值**：横向位移超过 12dp 前不劫持触摸，未过阈值回吐给 ScrollView；滑轨仅在审批详情页决策区内存在，不扩展到列表（M4 §6.1 手势冲突规则） | `PanResponder` 的 `onMoveShouldSetPanResponder` 用 `abs(dx) > 12 && abs(dx) > abs(dy) * 1.2` 判定；滑轨区不嵌套可滚容器 |
| 长按 vs 滚动                         | 纵向位移 >10dp 后取消长按候选                                                                                                                            | RN 原生 `Pressable onLongPress` + ScrollView `onScrollBeginDrag` 清除候选                                               |
| 上滑加载 vs 吸底跟随                 | 用户上翻（`offset > 40dp`）暂停自动滚底；点「▼ N 条新消息」恢复（M4 §5.5 / M5 `useFollow`）                                                              | `useFollow` hook（M5 §2.1 目录已规划）                                                                                  |
| 下拉刷新 vs 流式追加                 | 刷新期间流式追加正常入 store，渲染节流不放大；刷新完成滚动位置保持                                                                                       | RefreshControl + FlashList 保留位置                                                                                     |
| 手势与读屏                           | 全部可手势操作有等价点按路径（滑动确认降级为两段式点击，M4 §8.4 reduce-motion 条款）                                                                     | 无障碍等价路径（§4）                                                                                                    |
| 手势与深链                           | 流式期间工具卡可展开**禁止导航**（F3 §5.3 防误触）                                                                                                       | 组件内禁 `router.push` 于 streaming 状态                                                                                |

**互斥实现纪律**：滑动确认用 reanimated 手势（M4 §8.4 唯一重手势），经 `react-native-gesture-handler` 的 `simultaneousWithExternalGesture` / `blockExternal` 显式声明与列表滚动的互斥关系；**禁止**在 ScrollView 内裸用 `onTouchStart` 劫持事件（社区已知卡顿源）。

### 2.2 动效时序与 easing 表

**动效总表**（M4 §8.4 四类动效 + 本方案补齐每处时长与 easing 参数）：

| #   | 动效                                     | 时长                                                     | easing                                   | 基准出处                                                                          |
| --- | ---------------------------------------- | -------------------------------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------- |
| 1   | 页面转场（Stack push/pop、Tab 切换）     | 系统默认（iOS ~320ms / Android ~300ms）                  | 平台默认                                 | HIG（100-200ms 常规，全屏转场可至 300ms）/ M3（全屏 300-400ms）/ M4 §8.4 不自定义 |
| 2   | 按压反馈（按钮/列表行）                  | ≤80ms                                                    | 即时（无 easing）                        | HIG 触觉反馈即时性 / M4 §8.4                                                      |
| 3   | 滑动确认（审批 L2 滑轨）                 | 拖动跟手（0ms 延迟）+ 回弹 spring 200ms                  | spring（刚度低、阻尼中，回弹一次不过冲） | M4 §8.4 / F2 §5.3                                                                 |
| 4   | 列表增删（审批卡移除 / outbox 状态切换） | 150ms                                                    | ease-out（进入）/ ease-in（退出）        | M4 §8.4 / HIG 100-200ms                                                           |
| 5   | 骨架屏呼吸                               | 1.5s 循环，opacity 0.4→0.7→0.4                           | 线性                                     | M4 §8.1（社区 shimmer 方案 M4 未采纳，呼吸 opacity 低复杂度一致性）               |
| 6   | Toast 滑入/滑出                          | 滑入 200ms + 驻留 2s（成功/信息）/3s（错误）+ 滑出 200ms | ease-out 入 / ease-in 出                 | M4 §6.4 / HIG 100-200ms                                                           |
| 7   | 倒计时条颜色切换（最后 15s 变红）        | 150ms 颜色过渡                                           | 线性                                     | F2 §4.2（数值）+ 本方案补动效参数                                                 |
| 8   | 拒绝理由 Sheet 上滑                      | 300ms 上滑 + 遮罩淡入 200ms                              | 上滑 ease-out                            | M3 底部弹层（300-400ms）/ M4 Sheet 组件                                           |
| 9   | 决策成功反馈（✓ 徽标）                   | 150ms 淡入 + 500ms 驻留后返回                            | ease-out                                 | F2 §5.2（500ms 返回数值）                                                         |
| 10  | 角标数字变化                             | 150ms 淡入                                               | ease-out                                 | 社区轻反馈惯例                                                                    |

**easing 标准曲线**（跨平台统一语义，经 `adapters/platform/motion.ts` 封装）：

| 语义                       | 曲线                                 | 出处                                          |
| -------------------------- | ------------------------------------ | --------------------------------------------- |
| 标准进入（standard enter） | `cubic-bezier(0.2, 0, 0, 1)`         | M3 标准曲线                                   |
| 强调进入（emphasized）     | `cubic-bezier(0.05, 0.7, 0.1, 1)`    | M3 强调曲线（滑动确认回弹改用 spring 时等效） |
| 退出                       | `cubic-bezier(0.4, 0, 1, 1)`（加速） | M3 退出曲线                                   |

## 6. AI 体验维度

### 6.1 定位与原则（智能默认，不炫技）

**定位**（效果锁：对齐社区最先进 AI agent 移动端范式，但克制在「人的体验为主」）：移动端是远程伴侣（M4 §1.1），AI 维度的唯一目标是**减少人操作负担**——让用户少点、少翻、少看无用信息。**禁止**：AI 生成的假数据、代替用户静默决策、改变权限语义。

| 原则                | 内容                                                                                    | 出处                           |
| ------------------- | --------------------------------------------------------------------------------------- | ------------------------------ |
| P1 智能默认不改权限 | AI 排序/聚合/勾选只影响「先看什么、默认选什么」，不改变允许/拒绝语义（权限对等 F2 §10） | F2 §10                         |
| P2 诚实化           | 未知状态透传保真、无数据不伪造 0、离线灰化旧数据（不显示假新）                          | F1 §4.7 / M4 §1.1-3            |
| P3 可解释           | 智能聚合的每条结果可展开看原始事件；排序规则可感知（紧急在前）                          | 社区 AI 产品「可展开溯源」范式 |
| P4 低噪音           | 聚合以减少打扰为准：通知合并、重复抑制；不因「AI 能力」增加打扰                         | F3 事件去重纪律（5 分钟合并）  |

| #   | 智能行为         | 实现                                                                       | 出处/基准                                         |
