# F4 文件与资产域 · 手机端「文件浏览与项目管理」功能方案

- 文档编号：F4-files-assets
- 所属领域：多端互通（mobile）· 文件与资产域
- 状态：草案（供评审）
- 目标读者：移动端功能设计评审组、实现子 Agent、测试子 Agent
- 依赖关系：桌面端文件命令面（`fs_commands`）、工作区注册表（`workspace.rs`）、工具面（`agent-tools`）均为既有能力，本方案为**复用+封装**，不新增桌面端破坏性改动

---

## 1. 定位与范围

手机端「文件浏览与项目管理」是移动工作台的核心数据域之一：用户离开桌面后，需要随时查看当前项目（工作区）里的代码、文档与配置，定位文件、阅读内容、必要时做受控的小改。

本域的核心约束是**手机端不直接触碰桌面文件系统**：

- 桌面端是文件系统的唯一访问者（Rust 沙箱 + WorkspaceRegistry 授权）；
- 手机端通过多端互通链路把请求发送到桌面端，由桌面端执行既有 `fs_commands` 命令后返回结果；
- 手机端只做三件事：**展示**（目录/内容/元数据）、**缓存**（浏览体验优化）、**受控发起**（读为主，写为显式开启的可选能力）。

### 1.1 范围清单

| 方向 | 纳入 | 不纳入（V1） |
| --- | --- | --- |
| 工作区 | 已授权工作区列表、切换、状态展示 | 新增/授权新工作区（依赖桌面目录选择器） |
| 浏览 | 目录列表、排序、图标、过滤、最近访问 | 拖拽排序、多选批量操作 |
| 查看 | 文本/代码、Markdown、CSV 表格、图片、PDF 摘要 | PDF 内嵌翻页渲染、视频/音频播放 |
| 操作 | 读为主；编辑文本文件（显式开启）、新建小文件 | 删除、重命名、移动、批量写 |
| 搜索 | 文件名搜索（本地过滤 + 远程查找）、目录内过滤 | 全仓库内容搜索（V2 接 grep_search 代理） |
| 传输 | 远程读取 + 分层缓存 + 分块加载 | 离线全文镜像、文件同步 |

### 1.2 术语

- **工作区根（root）**：桌面端 WorkspaceRegistry 已授权根（canonical 绝对路径）。
- **相对路径（relPath）**：相对当前工作区根，`/` 分隔，用于手机端↔桌面端命令传输的统一格式。
- **命令桥（CommandBridge）**：多端互通链路中手机端调用桌面端 Tauri 命令的通道（与安全域共用）。
- **敏感文件**：文件名/路径命中敏感规则（`.env`、密钥、凭证等，见 §7）的文件。

## 2. 桌面端能力盘点（证据）

手机端方案的全部能力都来自桌面端既有实现，盘点如下（文件:行号为证据，禁止再发明平行实现）。

### 2.1 文件命令面（Tauri 命令，`apps/agent-workbench/src-tauri/src/fs_commands/`）

| 命令 | 位置 | 能力 | 手机端复用度 |
| --- | --- | --- | --- |
| `select_folder` | `mod.rs:19-23` | 原生目录选择器，唯一「新授权」入口 | 不可用（需桌面 UI 手势），手机端不得调用 |
| `list_directory` | `mod.rs:27-32` | 列目录：条目含 name/isDir/size/modified；排序为目录优先+字母序；过滤 node_modules/.git/target/dist/build | **全量复用** |
| `read_file_content` | `mod.rs:36-42` | 读文本：maxLines 分块、truncated 标记、1MB 字节上限、二进制/编码拒绝 | **全量复用**（手机端分块读取的底座） |
| `write_file_content` | `mod.rs:50-57` | 写文本：默认拒绝覆盖（overwrite=false → file_exists），自动建父目录 | **全量复用**（受控写入口） |
| `workbench_fs_delete_file` | `mod.rs:61-66` | 删除单文件（回收站接管） | 手机端 V1 **不开放**（风险 > 价值） |
| `workbench_discover_skills` | `mod.rs:74-80` | 技能发现 | 与文件域无关，不接 |
| `workbench_open_workspace` | `workspace.rs:378-387` | 复授权历史根（recent 列表内才放行） | **复用**：手机端切换工作区时校验授权 |
| `workbench_list_workspaces` | `workspace.rs:393-402` | 列出全部已授权根 | **复用**：手机端工作区列表数据源 |

### 2.2 目录条目结构（`directory.rs:53-72`）

```text
ListDirectoryResult { items: DirectoryItem[] }
DirectoryItem { name, is_dir, size?: u64, modified?: string(epoch ms) }
```

要点（手机端设计直接依赖）：

- 隐藏目录（`.` 开头）**未**在 `list_directory` 层过滤，但 node_modules/.git/target/dist/build 已被过滤（`directory.rs:41-51`）；
- 排序由桌面端保证：目录优先，同级字母序（`directory.rs:68-72`）；
- size 仅文件有值，modified 以毫秒时间戳字符串返回（`directory.rs:53-58`）；
- 每次调用只列**一层**（非递归）——手机端树形浏览必须自己维护展开状态，与桌面 `useFileNavigation.ts:54-74` 的 toggleExpand 语义一致。

### 2.3 读取策略（`read.rs` + `types.rs`）

- 字节上限 `MAX_TEXT_FILE_BYTES = 1MB`（`types.rs:6`），超限报 `file_too_large`；
- 行上限：默认 2000、硬顶 5000（`types.rs:7-8`），`ReadPolicy::for_preview` 钳制（`types.rs:308-317`）；
- 二进制嗅探（magic bytes + NUL + 控制字节比例，`read.rs:174-204`）→ `binary_file` 错误；
- UTF-8 校验 → `unsupported_encoding` 错误；
- 返回 `{ content, lineCount, truncated }`，截断语义清晰（`read.rs:131-135`）。

**手机端结论**：`read_file_content` 天然支持「分块续读」——传 `maxLines=N` 得到前 N 行，`truncated=true` 时用更大 `maxLines` 再请求（与桌面 `workspaceFsApi.ts:131-141` 的 `nextFilePreviewLineBudget` 纯函数同构）。手机端无需任何新读取命令。

### 2.4 写入策略（`write.rs:21-55`）

- `resolve_for_write`：词法归一化 + 祖先逐级上溯 + canonicalize 双重沙箱（`types.rs:164-224`），防 symlink 逃逸（测试见 `mod.rs:414-451`）；
- **默认拒绝覆盖**：已存在且 overwrite=false → `file_exists` 错误，文案指引显式传 overwrite=true（`write.rs:28-37`，T-EG-05）；
- 自动建父目录、1MB 内容上限（`write.rs:38-47`）。

**手机端结论**：写操作复用该命令即可获得与桌面完全一致的沙箱与覆盖语义；手机端 UI 层需要把「覆盖」转化为显式二次确认（见 §4.3）。

### 2.5 工作区注册表（`workspace.rs`）

- 信任锚：注册表是唯一真源（`workspace.rs:1-16`）；根只能来自 Dialog（新授权）/RecentList（复授权）/DefaultAppRoot（启动注册）；
- `resolve_guard`：相对路径以活动根为基准；绝对路径 canonicalize 后做前缀匹配（`workspace.rs:185-244`）——手机端传绝对路径也安全；
- recent 列表持久化 `recent-workspaces.json`（webview 不可写，`workspace.rs:67-68`）。

**手机端结论**：手机端工作区列表 = `workbench_list_workspaces` 返回值（已授权根）；切换 = 请求桌面端切活动根（需新增轻量命令，见 §3.1.3 建议项 M4-1）。手机端**没有**能力新增工作区（select_folder 需桌面手势）——这是产品边界，不是缺陷：新工作区的授权必须发生在桌面端，手机端只消费授权结果。

### 2.6 工具面（`crates/agent-tools/src/tools/`）

| 工具 | 位置 | 能力 | 与手机端的关系 |
| --- | --- | --- | --- |
| `read_file` | `fs.rs:24-221` | 行窗口/续读偏移/字符预算，二进制返回引用 | 手机端「AI 会话引用文件」场景经会话链路复用，不直接暴露 |

### 2.8 前端 API 封装（`apps/crish-desktop/src/api/workspaceFsApi.ts`）

- `resolveWorkspacePath`（`:61-91`）：相对拼根、绝对校验前缀、NUL/超长/bidi/保留名/`..` 拒绝——**手机端必须内嵌同构校验**（§7.2）；
- `detectFileKind`（`:247-264`）：扩展名 → text/image/pdf/table/binary；
- `toAssetUrl`（`:202-214`）：`convertFileSrc` 资源协议 URL——**手机端图片/PDF 预览的远程 URL 来源**（桌面端把协议 URL 交给手机端 WebView 加载）；
- `readTextFile` / `writeTextFile` / `listDirectory`（`:99-199`）：命令调用的前端封装，手机端 SDK 层对齐其参数语义。

### 2.9 桌面项目管理（`projectStore.ts`）

- localStorage 项目表：stableProjectIdFromPath 稳定 id（`:38-47`）、listProjects 按最近打开排序（`:100-102`）、openProject 切活动（`:166-183`）、crish-project-changed 事件；
- 手机端**不能**直接读桌面 localStorage——通过命令桥暴露（§3.1.3 M4-1/M4-2）。

### 3.6 手机端新增建议命令面（桌面端侧）

原则：**能不新增就不新增**。V1 尽量只复用 `list_directory / read_file_content / write_file_content / workbench_list_workspaces / workbench_open_workspace` 五个命令。下列为评审项：

| 编号 | 建议命令 | 必要性 | 说明 |
| --- | --- | --- | --- |
| M4-1 | `mobile_switch_active_workspace(path)` | 高 | `workbench_open_workspace` 已存在但 `#[allow(dead_code)]` 未接线（`workspace.rs:376`）；手机端需要它切活动根，接线成本低 |
| M4-2 | `mobile_get_workspace_state()` | 高 | 返回：已授权根列表 + 活动根 + 各根可达性（canonicalize 探测），一次调用替代多次 `list` 拼接 |
| M4-3 | `mobile_search_files(query)` | 中（P1） | 封装 fuzzy_find 的薄壳，带 maxResults 钳制 |
| M4-4 | `mobile_asset_url(relPath)` | 中（P1） | 返回 `convertFileSrc` 结果（桌面端计算协议 URL，手机端只拿 URL 加载），避免手机端直接拼协议 |
| M4-5 | `mobile_grep_search(...)` | 低（P2） | grep_search 工具的参数透传壳，带 maxMatches/maxBytes 严格钳制 |

## 4. 读写策略（核心决策）

### 4.1 读策略：全部开放，分级缓存

- **默认**：所有已授权工作区内的文件可浏览、可读（与桌面同权——桌面也是全量可读）；
- **分块**：首屏 400 行（`FILE_PREVIEW_CHUNK_LINES` 同值），滚动接近底部时按 `nextFilePreviewLineBudget` 阶梯续读（400→800→1200…，对齐 `workspaceFsApi.ts:131-141`）；
- **上限**：单文件 1MB / 5000 行硬顶（桌面端保证），手机端不得自行绕过；
- **敏感文件**：可读但标记 + 不缓存（§7.3）。

### 4.2 渲染策略（手机端适配）

桌面端 `FilePreview.tsx:114-160` 的按类型分派在手机端适配为：

| 类型 | 桌面端方案 | 手机端方案 | 理由 |
| --- | --- | --- | --- |
| text/code | hljs 全量高亮 | 轻量正则高亮（内置语言子集） | 包体与性能：手机端 bundle 不做全量语言包；JS 引擎单线程，万行文件全量高亮会卡顿，改为**首屏窗口高亮 + 滚动增量** |
| markdown | markdownRenderAsync 服务端/异步渲染 | 本地轻量渲染（自带 sanitizer） | 手机端离线/弱网可用；>500KB 降级纯文本 |
| table(csv) | parseCsvPreview 表格 | 同构实现，80 行首屏 | 一致 |
| image | `<img src=convertFileSrc>` | 同构；移动端走桌面端代理出的 http(s) 资源 URL | WebView 无法直接访问桌面 convertFileSrc 的 tauri:// 协议，需代理（§5.4） |
| pdf | iframe 内嵌 | **不做内嵌**：元数据摘要 + 系统打开 | 移动端无桌面 PDF 插件环境，iframe 体验差、带宽大 |
| binary | 提示 | 同构 | 一致 |

### 4.3 写策略：受控开放（建议）

用户要求「与桌面同权」。桌面端写操作的本质是：本地进程内、实时、可立即撤销（编辑态+确认导航）。手机端写文件的价值与风险权衡如下：

**价值**：
1. 移动场景「顺手改一行 bug / 补一句注释 / 改配置」是高频真实需求；
2. 复用 `write_file_content` 命令，沙箱、覆盖语义、错误码全部继承，无需新安全机制；
3. 与桌面同权是产品一致性要求，一刀切禁写会制造「手机只能看不能动」的割裂体验。

**风险**：
1. 小屏编辑易误触/误覆盖（风险 = 覆盖语义下的内容丢失）；
2. 弱网/断线重传导致部分写入的困惑（写入是原子的，命令语义下不存在半写，风险可控）；
3. 写敏感文件（.env 等）会造成安全事故（§7 已挡）。

**建议（结论）**：**V1 开放受控写**，四个闸门：

1. **编辑模式开关**：设置页默认关闭「允许编辑文件」；关闭时浏览页无任何写入口（读白名单之外的界面不渲染）；
2. **写前确认**：新建文件无需确认；覆盖已有文件必须弹二次确认（明确展示目标路径与「覆盖将替换原有内容」文案）——与桌面 `overwrite` 语义对齐，`overwrite=true` 只在确认后发送；
3. **敏感文件禁写**：命中敏感规则的文件，编辑按钮置灰并说明原因（§7.1）；
4. **仅限文本**：`write_file_content` 本身只接受文本内容；手机端编辑入口只在 `detectFileKind`=text/table 时出现（与桌面 `canEdit` 判断 `useFilePreview.ts:103` 同构）。

**明确不开放**（V1）：删除（`workbench_fs_delete_file`）、重命名、移动、批量操作。理由：删除是单向高风险操作，移动端误触概率高、回收站恢复链路依赖桌面端交互；这类操作保留给桌面端，手机端只读展示。如需开放，必须走安全域写权限矩阵审批（P2，F4-F34）。

## 5. 数据来源与传输

### 5.1 架构：手机端是远程客户端，桌面端是唯一数据源

```text
手机端 App
  └─ 文件域前端（浏览/查看/搜索/编辑状态机）
       └─ MobileFsApi（手机端 SDK 层：路径校验 + 命令封装 + 缓存）
            └─ CommandBridge（多端互通链路，加密）
                 └─ 桌面端 AgentWorkbench
                      ├─ 命令面 fs_commands（list/read/write）── WorkspaceRegistry 沙箱
                      └─ 工具面 agent-tools（fuzzy_find / grep_search / file_stat）
```

- 手机端**永不**直接访问桌面文件系统路径；
- 手机端请求中只传**相对路径**（relPath）或空串（=工作区根）；绝对路径在手机端 SDK 层被拒（§7.2 校验），防止路径构造绕过；
- 桌面端收到请求后走既有 `resolve_guard`（`workspace.rs:185-244`），沙箱由桌面端兜底——**即使手机端被攻破，越界读写仍然被拒**。

### 5.2 目录缓存策略

| 缓存对象 | 键 | 失效 | 容量 |
| --- | --- | --- | --- |
| 目录条目 | (workspaceRoot, relPath) | 下拉刷新 / 进入页面 30s 过期 / 写操作成功后主动失效上级目录 | LRU 128 层 |
| 展开态 | 同上 | 切换工作区清空 | 内存态，不落盘 |
| 文件内容 | (workspaceRoot, relPath, lineBudget) | 文件 mtime 变化（详情页可显示「内容可能已过期」+ 一键刷新）/ 敏感文件不缓存 | 文本 ≤ 64MB 总预算，LRU |
| 图片 | (workspaceRoot, relPath, size) | 缩略图 24h；详情图不缓存 | 磁盘缓存 128MB |

设计参照：桌面 `useFileNavigation.expanded` 的「展开即缓存子列表」模式（`useFileNavigation.ts:54-74`）；失效参照 `project_tree.rs:41-43` 的目录指纹思想（mtime + 条目数）——手机端以条目数变化作为强失效信号（条目数相同但 mtime 变的弱场景允许旧数据，读语义可接受）。

**一致性**：手机端是**读镜像**，桌面端是权威。任何「显示旧目录」的场景都接受（与 `project_tree` 缓存误差声明一致，`project_tree.rs:37-39`），UI 提供手动刷新。

### 5.3 大文件与带宽

- **文本**：分块续读（§4.1），单次请求 ≤ 400 行默认；用户明确「加载全部」时才递增预算到 5000 行硬顶。1MB 字节上限由桌面端强制，手机端不做二次放大；
- **图片**：目录列表只加载缩略图（≤128px 宽，桌面端生成缩略图需新增 M4-6 建议：`mobile_file_thumbnail(relPath)`，用 image crate 缩放后返回 base64 或 URL）；详情页按需加载原图；
- **PDF/大二进制**：V1 不传输内容，只传元数据（size/mtime）+ 打开外部应用（§3.3 F4-F25）；
- **带宽预算**：单次浏览会话默认流量上限提示（如 50MB 提醒），避免弱网下无感跑流量；
- **断线**：请求失败 → 展示缓存内容 + 离线横幅 + 重试按钮；写请求失败 → 明确「未保存」，编辑草稿保留在本地，不静默重发（防重复写入）。

### 5.4 图片/PDF 的远程 URL

桌面端 `toAssetUrl` 用 `convertFileSrc` 生成 `tauri://localhost/...` 协议 URL（`workspaceFsApi.ts:202-214`），该协议只能在桌面 WebView 内访问。手机端 WebView 无法直接加载：

- **方案**：桌面端新增轻量 HTTP 资源代理（复用已有 asset 协议后端，仅把响应改经命令桥的 HTTP 通道返回），手机端拿到 `https://<bridge>/assets/<encoded-relPath>` 直接给 `<img>` 加载；
- **安全**：该代理 URL 必须带短期令牌（命令桥会话令牌派生，10 分钟有效）+ 仅接受已授权根内的相对路径（桌面端二次校验）；
- **隐私**：URL 只在手机端内存态，不持久化；令牌失效后图片自动不可加载（天然过期）。

### 5.5 搜索的桌面衔接

- **P0 文件名过滤**：纯本地（手机端已有该层条目数据），零桌面往返；
- **P1 递归文件名搜索**：`mobile_search_files` 薄壳 → 桌面端 `fuzzy_find` 工具（复用其目录索引与模糊匹配，`search.rs`），结果限 100 条、只返回 relPath + kind + size；
- **P2 内容搜索**：`mobile_grep_search` 薄壳 → `grep_search` 工具（`search.rs:59-90`），**默认文件级模式**（matchPerLine=false，只回路径+命中数，带宽友好）；行级模式需用户显式点击「查看上下文」再拉取，且单文件最多拉 20 行命中上下文；
- 工具面参数钳制（maxMatches/maxFiles/maxFileBytes）由桌面端执行，手机端不得传超限值；SKIP_DIRS 内置排除天然生效（`search.rs:29-38`）。

## 7. 安全边界

### 7.1 敏感文件规则（手机端独立判定 + 桌面端兜底）

手机端 SDK 内置敏感规则（与桌面安全基线对齐的简化版，判定为**文件名/路径模式**）：

| 规则 | 示例 |
| --- | --- |
| 密钥/凭证类 | `.env`、`.env.*`、`*.pem`、`*.key`、`id_rsa`、`credentials*`、`secrets*`、`token*`、`*.p12`、`*.pfx` |
| 配置类 | `.npmrc`、`.yarnrc`、`settings.json`（涉密钥时由内容策略兜底） |
| 目录类 | `/.ssh/`、`/.aws/`、`/keys/`、`/secrets/` 下的所有文件 |

对敏感文件：
1. **读**：允许但必须显示警示横幅；内容**不进任何缓存**（内存与磁盘）；
2. **写**：禁止（编辑入口置灰，见 §4.3）；
3. **分享/复制**：分享被拒；复制路径允许（路径本身不涉密）；
4. **传输**：手机端 SDK 在发送读取请求时仍正常放行（桌面端沙箱已授权根），但响应内容标记 `sensitive=true`（由手机端本地判定后附标），上层 UI 依标记渲染。

### 7.2 手机端路径校验（SDK 层，双保险之一）

手机端 SDK 内嵌 `resolveWorkspacePath` 同构校验（`workspaceFsApi.ts:43-91`）：
- 拒绝 NUL、超长（>4096）、Unicode bidi 覆盖字符、Windows 保留设备名、`..` 路径组件；
- 只接受相对路径或空串发送到桌面端；绝对路径一律本地拒绝（提示使用相对路径）；
- 发送前规范化分隔符为 `/`。

**桌面端是最终防线**：即使手机端校验被绕过，`resolve_guard` + `WorkspaceFsGuard` 的 canonicalize 包含性校验仍会拒绝越界（`workspace.rs:185-244`、`types.rs:136-162`）。

### 7.3 缓存隐私

- 文本内容缓存仅限非敏感文件（§7.1），且存储在系统私有存储（应用沙箱内），不写入公共媒体库；
- 图片缓存 128MB 上限，过期自动清理；不缓存 PDF 内容（只缓存元数据）；
- 「清除文件缓存」入口置于设置页，一键清空目录/内容/图片三级缓存。

### 7.4 与安全域衔接（接口约定）

- 命令桥会话由安全域负责（认证、令牌、加密、会话失效）；本域只消费 `CommandBridge.request(cmd, params)` 接口；
- 写操作（F4-F32/F4-F33）属于**敏感操作**：需要安全域标记为「需要用户确认的远端操作」——手机端确认后，桌面端仍按既有命令面权限执行（不新增桌面端信任面）；
- 资源代理 URL 令牌（§5.4）由安全域派生与吊销；
- 新增命令（§3.6 M4-1…M4-5）必须经安全域评审：只读命令（list/read/state/search/asset/thumbnail）默认允许；写命令（`mobile_write_file` 若新增）需与 `write_file_content` 权限一致；
- 会话断开时：全部缓存仍可浏览（离线只读），写入口自动禁用。

### 7.5 审计

- 手机端发起的读/写请求在桌面端记审计日志（路径、命令、结果码、来源标记 `mobile`），写操作必须包含来源标识以便溯源；
- 敏感文件读取单独计数，异常高频读取（如 1 分钟内 >100 次敏感读）触发安全域告警（P2）。
