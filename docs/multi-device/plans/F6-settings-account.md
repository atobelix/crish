# F6 功能方案：手机端「设置、账户与多设备管理」功能域

- 子代理：F6（设置、账户与多设备域）
- 依赖上游：F1 协议域（配对/中继/设备信令底层）、账号中心服务评估结论（F 系列账号评估 Agent）
- 本文档职责：手机端设置 / 账户 / 多设备管理的 UI、交互、用户流程与状态设计；协议底层细节不在本文范围
- 参考代码：桌面端 `apps/crish-desktop/src/store/settingsStore.ts`、`apps/crish-desktop/src/components/settings/`、`apps/crish-desktop/src/components/settings-models/`、`apps/crish-desktop/src/api/transport/`、`apps/agent-workbench/src-tauri/src/config/`

## 1. 结论速览

手机端"设置"采用**三域结构**：账户与设备（登录、配对、设备列表）→ 连接与通知（中继/直连、推送）→ 外观与隐私（本机偏好）。

- 桌面端 11 个设置 tab 中，**4 类同步到手机端可管理**（账户、模型状态、权限模式、数据与隐私）、**3 类手机端只读参考**（用量、定时任务、状态诊断）、**4 类仅在桌面端**（外观皮肤体系、快捷键、扩展、规则编辑），手机端仅提供等价的轻量本机偏好。
- 账户体系**不是使用硬门槛**：未登录可"访客模式"直连已配对桌面；登录解锁云中继、多设备漫游与账号中心凭据（对应 Rust 配置面既有的 `credentialMode = account-center` 分支，`apps/agent-workbench/src-tauri/src/config/provider.rs:153-155`）。
- 首次配对采用**双通道**：局域网直连扫码（优先，<2 分钟达标）+ 云中继配对码（异地兜底），两者共用同一 6 位配对码语义。
- 手机端**只读展示**桌面权限模式与白名单，不允许远程改权限；设置变更一律在桌面端完成（安全红线，理由见 §8）。
- 设置搜索是**一级交互**而非二级增强：桌面端已用"搜索过滤 tab"模式（`settingsTabsMeta.ts:188-193`），手机端继承为搜索栏 + 分组过滤。

## 3. 设置归属决策矩阵（同步 / 只读 / 仅桌面）

决策原则：**影响引擎行为与安全的 → 仅桌面端修改；纯展示与通知渠道 → 手机端管理；跨设备一致才有价值的 → 同步镜像（只读或受限写）**。

### 3.1 同步到手机端管理（手机端可改）

| 桌面项 | 手机端呈现 | 同步方式 |
|---|---|---|
| 模型/profile 激活状态（activeProfileId、defaultModel） | 「模型」页只读卡片 + 「设为默认」按钮（经桌面确认通道） | 镜像 |
| 通知相关开关（匿名分析 enableAnalytics、崩溃遥测 enableCrashTelemetry——桌面 `SettingsPersonalizeTab.tsx:146-159`） | 「数据与隐私」开关 | 双向同步（改手机端需在桌面弹确认？——见 §8.3，建议直接生效 + 桌面 toast） |
| 回答风格 responseStyle | 手机端「通用」单选 | 双向同步（同值语义，无安全风险） |
| 权限模式**展示** | 「安全」只读状态卡片 | 单向镜像 |

### 3.2 手机端只读参考（不改）

| 桌面项 | 手机端呈现 |
|---|---|
| 用量 usage（token 计数、历史） | 汇总卡片（今日/本周），点击跳转桌面详情 |
| 定时任务 schedule / 状态诊断 | 列表只读 + 空态提示"在桌面端管理"；健康摘要（连接状态、核心版本） |
| 规则 rules | 仅显示"已启用 N 条规则"摘要 |
| 工作区路径 | 显示当前活动工作区名 |

### 3.3 仅在桌面端（手机端不提供）

| 桌面项 | 原因 |
|---|---|
| 皮肤预设/亮度/时光过渡/氛围色彩（`SettingsAppearanceTab.tsx:268-309`） | 桌面视觉体系，手机端另有原生外观 §9 |
| 快捷键/发送快捷键 | 键盘专属，手机无意义（手机端用「语音发送」「快速回复」替代） |
| 扩展/技能/MCP 管理 | 配置复杂度高，手机屏不承载（只读摘要） |
| 信任命令白名单编辑 | 安全敏感，见 §8 |
| 设置备份导出/导入 JSON | 手机端不做备份文件，改用「通过云中继迁移设置」（§12.4） |
| 导入外部对话 | 文件扫描只发生在桌面 |
| 合并右侧面板/窗口风格/代码缩进 | 桌面布局专属 |

### 4.2 手机端设置数据模型（前端 Store 设计）

手机端设置域使用单一 `mobileSettingsStore`（zustand 风格，与桌面 `settingsStore.ts` 同构但独立实例），分片如下：

| 分片 | 字段 | 来源 | 持久化 |
|---|---|---|---|
| `session` | `authState: 'guest' \| 'logged-in' \| 'expired'`、`user: {id, name, email, avatar} \| null`、`tokens: {accessAt, refreshAt} \| null` | 账号中心 | 仅令牌（钥匙串） |
| `pairing` | `pairedDevices: PairedDevice[]`、`myDeviceId`、`pairState: 'none' \| 'scanning' \| 'inputting' \| 'handshaking' \| 'done' \| 'failed'` | 协议域设备注册表 | 本机（加密存储） |
| `connection` | `mode: 'auto' \| 'lan' \| 'relay'`、`serverUrl`、`connState: 'connected' \| 'connecting' \| 'disconnected' \| 'error'`、`channel: 'lan' \| 'relay'` | 协议域状态事件 | 本机 |
| `notify` | `masterOn`、`sceneFlags: {message, taskDone, approval, error, deviceOffline}`、`quiet: {on, start, end, policy, ignoreWhileTask}` | 本机 | 本机 |
| `appearance` | `theme: 'system' \| 'light' \| 'dark'`、`fontScale: 0 \| 1 \| 2`、`listDensity` | 本机 | 本机 |
| `privacy` | `syncScope: {prefs, devices, usageSummary, chatRoam}`、`sensitive: {preview, title, notifyHidden, lockHidden}`、`appLock: {on, mode}` | 本机 + 镜像 | 本机 |
| `mirror` | `permissionMode`、`trustedCmdCount`、`activeProfileId`、`usageSummary`、`engineVersion` | 桌面镜像（`config_get` 快照 / 遥测事件） | 仅内存缓存，不持久化（对齐 `settingsStore.ts:15-19` 引擎权威原则） |

关键约束：

- `mirror` 分片**永不本地持久化**，每次冷启动从已配对桌面拉取；拉取失败显示"桌面端离线，显示上次会话缓存"。
- 所有手机端修改项先写本机分片，再按 §8.3 桌面确认通道提交；未确认的变更标记 `pending: true`（UI 显示"待桌面端确认"）。
- 数据模型是本文档的**前端设计契约**，字段名与协议域（F1）传输字段保持 camelCase 一致，避免二次映射。

## 5. 账户体系设计

### 5.1 账户概念与使用门槛

| 形态 | 是否要求登录 | 能力 |
|---|---|---|
| 访客模式 | 否 | 局域网直连已配对桌面（同 WiFi 扫码）、本机聊天记录、外观偏好 |
| 已登录 | 是 | 云中继异地连接、多设备漫游（设置/偏好同步）、账号中心凭据（对应 `credentialMode=account-center`）、推送 |

结论：**登录不是硬门槛**。理由：(a) 桌面端至今是纯本机模型（无登录概念，`SettingsProfileTab.tsx:174-263` 只有本机环境信息），手机端强推登录违背产品连续性；(b) 访客模式降级为"仅局域网直连"，功能边界清晰、安全可控；(c) 登录收益集中在云中继与漫游，用价值引导而不是强制。

### 5.2 与账号中心服务的衔接

依据账号评估 Agent 结论（本文档假定：账号中心服务提供 OAuth2/设备码 + 会话令牌 + 用户信息端点）：

- 登录成功后手机端持有 `accessToken` + `refreshToken`（存系统钥匙串 Keystore/Keychain，绝不落本地明文——对齐桌面 DPAPI 密钥槽精神 `credentials.rs:3-6`）。
- 桌面端在 `credentialMode=account-center` 时**不持有用户密钥**（`provider.rs:153-155` 返回 None），凭据由账号中心下发；手机端登录态**不向桌面透传令牌**，两端的账户关系通过"同一用户 ID 下设备注册表"（F1 协议域）建立。
- 会话保持：refreshToken 静默续期（有效期窗口内自动刷新）；失效则进入"会话过期"态，UI 降级为访客能力并提示重新登录，**不自动登出清数据**。

### 5.3 登录流程（手机端 UI）

```
第一步：打开设置 → 账户卡片显示「未登录 · 访客模式」
第二步：点击「登录」→ 进入登录页（账号密码 / 设备码两种方式）
第三步（设备码）：手机显示 6 位设备码 + 短链接 → 用户在桌面端或浏览器完成授权
   ─ 或 ─
第三步（账号密码）：输入账号密码 → 服务端校验 → 返回令牌
第四步：登录成功 → 账户卡片更新为头像+昵称+邮箱
第五步（可选）：引导「同步偏好到本机」与「关联桌面设备」
```

- 登录失败错误分级：`网络不可用`（引导检查网络）、`账号或密码错误`（重输）、`服务维护中`（稍后重试）、`账号已被锁定`（说明解锁路径）。
- 多账号：支持「添加另一个账号」；当前账号切换在账户卡片下拉；非当前账号仅保留令牌，不做并行会话。
- 退出登录：二次确认（"退出后云中继将断开，本地配对设备仍可直连"）→ 清除令牌与云端缓存，**保留本地聊天记录与配对关系**。

### 5.4 账户卡片（设置首页顶部）

```
┌──────────────────────────────────────┐
│  ◐  未登录 · 访客模式          [登录] │
│      局域网直连可用 · 云中继需登录     │
├──────────────────────────────────────┤
│  ◎  张三  zhang@example.com    ✓ 已登录 │
│      [切换账号 ▾]  [退出]  [同步状态 ✓] │
│      已同步偏好：刚刚 · 设备 2 台       │
└──────────────────────────────────────┘
```

账户卡片三种状态：未登录（访客）、已登录、会话过期（黄条提示 + 重新登录按钮，能力降级为访客）。

### 5.5 登录页设计（账号密码通道）

- 布局：返回栏 + 品牌区（图标 + "登录后解锁云中继与多设备漫游"）+ 输入区（手机号/邮箱、密码带显示切换）+ 主按钮「登录」+ 次级入口（设备码登录折叠项、忘记密码、注册、使用条款）。
- 密码输入框自带显示/隐藏切换；「使用设备码登录」折叠展开为 6 位设备码输入（与配对码同款键盘，§12.3）。
- 登录按钮点击后置 loading（"正在登录…"），防重复提交；失败不跳页，错误内联在输入框下方（§13.3 文案规范）。
- 注册入口在本页可直达（引导外链 WebView 或内建注册表单，由账号中心服务形态决定）。

### 5.6 多账号与切换

- 账号列表页：当前账号（高亮"当前"角标）+ 其他账号行 + 「添加另一个账号」入口。
- 切换账号 = 切换云中继身份；**本地配对设备与聊天记录不受影响**；各账号偏好独立保存（按 `accountId` 分键存本机）。
- 同一时刻只有一个账号活跃（token 生效）；切换后重新拉取该账号偏好（外观/通知/隐私）与设备列表。
- 切换前内联说明："切换后，当前账号的云中继将断开，本地设备仍可直连"。切换失败（网络/令牌）回滚到原账号并提示。

### 5.7 会话保持与令牌生命周期

```
令牌状态机（手机端 session 分片）：
  logged-in ──refreshToken 静默续期成功──▶ logged-in（滑动窗口）
     │                                          ▲
     │ refreshToken 失效 / 服务端吊销            │ 重新登录成功
     ▼                                          │
  expired（能力降级为访客，黄条提示）──────────────┘
```

| 阶段 | 手机端行为 | 用户感知 |
|---|---|---|
| 有效期内 | 静默续期（后台定时器 + 每次启动时校验） | 无 |
| 续期失败 1-2 次（网络抖动） | 保留会话，延长重试间隔 | 无 |
| 续期连续失败或服务端吊销 | 切 `expired`：云中继断开、保留局域网直连 | 账户卡片黄条「会话已过期，重新登录」 |
| 重新登录 | 新令牌替换旧令牌（钥匙串覆写） | 恢复正常 |
| 退出登录 | 主动吊销 refreshToken + 清除令牌与云端缓存 | 回到访客态 |

- 会话过期**不触发**配对关系失效（配对凭据与账号令牌分离存储）。
- 「在其他设备登录了本账号」不强制踢出手机端（允许多端并存，设备列表可见在线数），仅提示"有新设备登录，可在设备列表中管理"。


| 场景 | 手机端呈现 | 用户操作 |

| 云中继断开（网络波动） | 状态卡转圈「正在重连…」，指数退避（UI 显示重连倒计时） | 可手动「立即重连」 |

### 6.4 配对状态机（手机端 UI 层）

```
配对状态机（pairing.pairState）：
  none ──点击「配对新设备」──▶ scanning ──自动发现桌面端──▶ handshaking ──▶ done
   │                            │（扫码/输码模式）▲            │
   │                            └──▶ inputting ──▶┘           └──▶ failed（可重试）
   │                                 ▲ 输码自动提交            │      │
   │                                 └──── 码过期/错误 ────────┘      ▼
   └──▶ 手动输入码直接进 inputting                              none（重置配对缓存）
```

| 状态 | UI 呈现 | 可执行动作 |
|---|---|---|
| `none` | 空态引导卡 +「配对新设备」按钮 | 开始配对 |
| `scanning` | 相机取景框 + 提示"将二维码置于框内" | 切手动输码 / 取消 |
| `inputting` | 六位码键盘 + 过期提示 | 自动提交 / 重新扫码 |
| `handshaking` | 转圈 + "正在交换安全密钥…"（≤ 30s） | 取消（回到扫描） |
| `done` | 成功页 + 命名引导 | 开始使用 |
| `failed` | 内联错误 + 根因文案 | 重试 / 重置配对缓存 |

约束：

- `handshaking` 30 秒超时自动转 `failed`（错误码 `PAIR_HANDSHAKE_TIMEOUT`），提示"网络较慢，继续等待？"。
- `failed` 重试 2 次仍失败时，提供「重置配对缓存」出口（清空本机残留配对凭据，防止脏状态）。
- 配对成功写入设备列表前**必须先通过命名步骤**（默认名 = 设备型号），防止出现无名设备。

### 6.5 设备详情页

布局（`设置 → 账户与设备 → 点选某台设备`）：

- 头部：设备图标 + 名称 + 在线状态行（在线 · 局域网直连 · 延迟 12ms）。
- 基本信息区：设备类型（Windows 桌面端）、引擎版本（仅 desktop 类型）、配对时间、配对方式（本机扫码）、设备 ID 短显、最近活跃。
- 连接通道区：当前通道 + 备用通道（云中继未启用）+ 「测试连接」「查看通道日志」。
- 操作区：「重命名」「强制断开连接」「撤销配对」。

关键行为：

- 「强制断开连接」：立即中断与桌面端的当前通道（不动配对关系），用于桌面端卡死时的急救；断开后设备行回到离线态。
- 「撤销配对」仍走二次确认（§6.2）；撤销后本设备列表不再显示该桌面端。
- 设备 ID 只显示前 4 + 后 2 位（对齐桌面 K-02 last4 脱敏精神，`credentials.rs:7-11`），完整 ID 在「查看通道日志」内可核对。

### 6.6 设备行数据字段定义

`PairedDevice`（协议域设备注册表返回，前端仅消费）：

| 字段 | 说明 | 前端呈现 |
|---|---|---|
| `deviceId` | 设备唯一 ID | 短显（前 4 + 后 2） |
| `name` | 设备名（可重命名） | 行标题 |
| `type` | `desktop \| phone \| tablet` | 图标 |
| `role` | `this \| peer`（本机/远端） | 「本机」角标 |
| `channel` | `lan \| relay` 当前通道 | 连接方式标签 |
| `online` | 在线布尔 | 状态点 |
| `lastActiveAt` | 最近活跃时间 | "N 分钟前" |
| `pairedAt` | 配对时间 | 详情页展示 |
| `engineVersion` | 桌面端引擎版本 | 详情页展示（仅 desktop 类型） |
| `needsReauth` | 配对关系是否失效（桌面重装后） | 红条 + 重新配对引导 |

排序规则：本机恒顶置；其余按 `online` 优先（在线在上），同在线态按 `lastActiveAt` 倒序。

### 7.3 连接状态机与切换规则

```
连接状态机（connection.connState，对齐桌面 transport 四态扩展）：
  connected ◀──connecting──▶ disconnected ◀──▶ error
     │           │（指数退避重连）
     └── 通道切换（lan⇄relay）→ 先 connecting，成功后 connected
```

| 当前态 | 触发 | 下一态 | UI 动作 |
|---|---|---|---|
| connected | 局域网信号丢失 | connecting（自动尝试云中继） | 状态卡转圈 + "正在重连…" |
| connecting | 重连成功 | connected | 绿点恢复 + 轻提示 |
| connecting | 重连超时（30s） | disconnected | 黄条 + 「重连」按钮 |
| connected/connecting | 连续错误（协议层认证失败） | error | 橙条 + 根因文案 + 「查看详情」 |
| disconnected | 用户手动重连 | connecting | 状态卡转圈 |
| error | 用户重试 / 配对重新建立 | connecting | 转圈 |

切换规则补充：

- 通道自动切换仅在 `mode: auto` 下发生；`仅局域网直连` 模式下不自动切云中继（黄条提示"已切换至局域网直连，云中继被禁用"）。
- 云中继通道 5 分钟无心跳视为断流，进入 `connecting` 并走指数退避（UI 显示第 N 次重连）。
- 状态变更事件源：协议域状态事件（与桌面 `workbench-run-event` 广播模式对齐，`tauriTransport.ts:305-341`），手机端只订阅不轮询。

## 8. 权限模式（与桌面同权的边界）

### 8.1 结论建议：手机端不改权限模式，只读展示 + 受限触发

桌面权限模式（`SettingsSecurityTab.tsx:70-91`，ask/auto 等经 `transitionPermissionMode` 切换）决定**工具执行的确认策略**，是引擎安全的核心旋钮。手机端**禁止直接修改**，理由：

1. 权限模式影响的是桌面端 shell 执行行为，远程改等于"手机能改变桌面安全策略"，攻击面大（手机丢失即风险）。
2. 桌面端已有完整、带风险分级的管理 UI（`SettingsSecurityTab.tsx:384-417`），手机端复制一份编辑 UI 属于重复维护。
3. 审批类操作（工具执行确认）走的是**会话内审批流程**（会话域职责），与设置域无关。

### 8.2 手机端「安全」页（只读镜像）

```
设置 → 数据与隐私 → 安全状态
┌──────────────────────────────────────┐
│ 权限模式：ask（每次工具执行前确认）      │
│   由桌面端「安全」设置管理               │
│ 已信任命令：12 条（git status 等）      │
│   高风险命令：需逐一确认                │
│  [在桌面端更改设置]                     │
└──────────────────────────────────────┘
```

- 「在桌面端更改设置」：点击后生成一条**引导链接/二维码**，桌面端扫码直接跳到安全 tab（配合协议域 deep-link 能力）。
- 手机端可**发起**"暂停自动执行"临时开关（如离开工位时远程锁定桌面工具执行）——这是「受限触发」而非改配置：向桌面端发一次性指令，桌面端确认后生效，不改变持久化配置。

### 8.3 手机端修改桌面设置的通道（通用机制）

个别非安全设置（回答风格、通知开关）允许手机端改。统一走**「桌面确认通道」**：

- 手机端修改 → 发送变更请求 → 桌面端弹出确认条（"手机端请求将回答风格改为"详细" [接受] [忽略]"）→ 接受后生效并回推确认。
- 超时（建议 60 秒）未响应 → 手机端提示"桌面端未确认，变更未生效"。
- 桌面端确认条可配置「记住本次选择」（不推荐默认开启，避免静默放权）。

该机制保证：**任何影响桌面引擎的状态变更，最终确认权都在桌面端**（安全基线一致）。

### 8.4 桌面确认通道载荷定义（协议域协作面）

手机端 → 桌面端请求（`mobile_settings_apply` 类命令）：

```json
{
  "type": "mobile_settings_apply",
  "requestId": "req_8f3a",
  "deviceId": "phone-iphone-01",
  "key": "responseStyle",
  "value": "high",
  "nonce": "a1b2c3",
  "ttlSec": 60
}
```

桌面端响应（三态）：

| 状态 | 响应字段 | 手机端 UI |
|---|---|---|
| 接受 | `{ status: "accepted" }` | pending 清除，显示"已生效" |
| 拒绝 | `{ status: "rejected", reason }` | 显示拒绝原因，设置回滚 |
| 超时未响应 | 无响应（60s） | "桌面端未确认，变更未生效" |

约束：

- 请求载荷携带 `nonce` 防重放；`ttlSec` 由桌面端强制执行。
- 同一时刻每台桌面端只接受 1 个待确认变更，新请求进入队列（桌面确认条轮询显示）。
- 该命令由协议域（F1）实现底层，设置域只定义语义与 UI 状态。

### 11.2 关键设计

- **缓存清理**：一键清理渲染缓存/图片缓存；聊天记录数据不清理（仅"清空本机全部数据"在退出登录流程中提供，二次确认 + 说明不影响桌面端数据）。
- **同步范围**：四类数据可独立开关；聊天记录漫游默认关（隐私优先，开时需确认"您的会话内容将加密同步，可随时关闭"）。

- **应用锁**：可选 PIN/生物识别，打开 App 时验证；支持"打开即锁 / 退出后台 5 分钟即锁"两档。
- 与桌面遥测开关的关系：`enableAnalytics / enableCrashTelemetry`（`SettingsPersonalizeTab.tsx:146-159`）在手机端「数据与隐私 → 产品数据」镜像展示（经桌面确认通道同步，§8.3），手机端本机不单独上报遥测。

### 11.3 缓存清理范围定义

| 缓存项 | 内容 | 清理后影响 | 是否随「清理缓存」清除 |
|---|---|---|---|
| 渲染缓存 | markdown/代码高亮 HTML 缓存（对齐桌面 `markdownCache.ts` 同类） | 重新渲染，无数据损失 | 是 |
| 图片/附件缓存 | 会话内图片与附件缩略图 | 需重新拉取（源在桌面端） | 是 |
| 离线消息队列 | 断连期间待发送消息 | **不清除**（误删用户未发送内容） | 否，单独入口 |
| 镜像快照缓存 | §4.2 `mirror` 分片内存缓存 | 下次连接重新拉取 | 是 |
| 聊天记录 | 本机历史会话 | 不提供单条清理（整库清除见退出流程） | 否 |

- 「清理缓存」按钮点击后先显示预计释放量（"预计释放 18.2 MB"），清理完成内联反馈"已清理"。
- 清空全部本机数据（退出登录流程内）：二次确认 + 说明"仅清除本机数据，桌面端与会话记录不受影响"，对齐桌面「清空白名单需确认」的交互惯例（`SettingsSecurityTab.tsx:330-349`）。

### 11.4 敏感信息显示开关联动

| 开关 | 影响面 | 联动约束 |
|---|---|---|
| 消息内容预览 | 通知栏新消息内容 | 通知场景开关「消息内容预览」受此约束（§10.3） |
| 会话标题显示 | 会话列表标题 | 关闭时显示"会话"占位 |
| 通知栏内容隐藏 | 系统通知全部内容 → 仅"新消息" | 独立于预览开关，优先于预览 |
| 锁屏时隐藏内容 | 锁屏界面消息摘要 | 依赖系统"锁屏通知隐藏"权限 |

联动规则：锁屏隐藏 > 通知栏隐藏 > 内容预览（高层级关闭时低层级视觉失效，UI 上置灰低层级开关并标注"受高级别开关影响"）。

## 13. 体验要求

### 13.1 设置项好找（搜索是一级交互）

- 搜索栏置顶常驻（设置页不滚动时也可见），支持：中文标签（"权限""主题"）、拼音首字母（"qx""zt"）、英文别名（"theme""pair"）、模糊匹配（"定时""cron"）。
- 搜索命中后分组高亮 + 逐项定位（点击结果直接打开对应开关页）；空结果给"没找到「xxx」，试试：连接 / 通知 / 外观"。
- 高频入口捷径：设置首页顶部放「配对新设备」「当前连接」两个快捷卡片（桌面端 `SettingsQuickMenu` 同思路，`SettingsQuickMenu.tsx`）。

### 13.2 配对流程 < 2 分钟

- 计时基线：从点「配对新设备」到设备列表出现新条目。分解：环境检测 ≤ 3s、扫码/输码 ≤ 15s、握手 ≤ 30s、成功页 ≤ 2s。
- 每一步都有进度反馈；超过 30s 未完成握手自动提示"网络较慢，继续等待？[继续] [取消重来]"。
- 手动输码自动提交（输满 5/6 位即尝试），避免"还要点一下确定"的额外心智负担。
- 失败重试一次后仍失败 → 给出根因化错误（见下），并提供「重置配对（清空本机配对缓存）」出口，防止"脏状态卡死"。

### 13.3 错误提示友好

错误文案规范：**原因 + 后果 + 可操作动作**，禁止裸错误码。

| 场景 | 友好文案 |
|---|---|
| 配对码错误 | "配对码不正确。请核对电脑上显示的 6 位数字；若已过期请重新生成" |
| 配对码过期 | "配对码已过期（10 分钟有效）。请在桌面端重新生成后再试" |
| 网络不可用 | "当前网络不可用，请检查 WiFi 或移动网络后重试" |
| 桌面端离线 | "桌面端当前未在线，无法完成配对。请先打开电脑上的 Crish 再试" |
| 密钥交换失败 | "安全密钥交换失败，本次配对未建立。请重试；若持续失败请确认两台设备时间一致" |
| 云中继需登录 | "云中继配对需要登录账号。您可以先登录，或改用局域网直连" |

所有错误展示在**当前步骤内联**（不弹全屏错误），保留上一步输入内容（输错配对码不清空已输数字，只提示错误并允许修正——经验上"清空重输"是最大挫败点）。

### 13.4 错误码与文案统一表（协议域错误 → UI 文案映射）

协议域（F1）返回结构化错误码，手机端统一在设置域翻译为友好文案；未命中映射的错误码显示兜底文案 + 错误码（供用户反馈）：

| 协议错误码（前缀约定） | 手机端文案 | 动作 |
|---|---|---|
| `pair.invalid_code` | 配对码不正确，请核对电脑上显示的 6 位数字 | 保留输入，允许修正 |
| `pair.code_expired` | 配对码已过期（10 分钟有效），请在桌面端重新生成 | 重新生成入口 |
| `pair.handshake_timeout` | 安全密钥交换超时，网络较慢，继续等待？ | 继续/取消 |
| `pair.clock_skew` | 配对失败：请校准两台设备的系统时间 | 重试 |
| `pair.already_paired` | 该设备已在配对列表中 | 跳转设备列表 |
| `pair.desktop_offline` | 桌面端当前未在线，请先打开电脑上的 Crish | 稍后重试 |
| `conn.lan_unreachable` | 无法连接本机网络上的桌面端，请检查是否同一网络 | 切换通道 |
| `conn.relay_auth` | 中继连接认证失败，请重新登录 | 登录引导 |
| `conn.channel_error` | 连接异常，正在尝试重连（第 N 次） | 手动重连 |
| `auth.token_expired` | 登录会话已过期，请重新登录 | 登录页 |
| `auth.locked` | 账号已被锁定，请通过 ［说明路径］ 解锁 | 引导 |
| `settings.apply_pending` | 变更已提交，等待桌面端确认 | 显示 pending 标记 |
| `settings.apply_rejected` | 桌面端已拒绝本次变更 | 回滚 |
| `fallback` | 操作失败（错误码：xxxx），请重试或反馈 | 重试 |

## 16. 实施分期建议（供实现任务书引用）

| 阶段 | 范围 | 验收锚点 | 依赖 |
|---|---|---|---|
| M1 连接与配对底座 | 设置壳（分组列表 + 搜索）、连接状态卡、配对向导（扫码/输码）、设备列表（重命名/撤销）、断连重连 UI | T1-T8、T24、T26-T31 | F1 协议域 v1 |
| M2 账户与登录 | 账户卡片三态、登录页（密码 + 设备码）、多账号切换、会话保持、退出登录 | T9-T14 | 账号中心服务 |
| M3 通知与隐私 | 通知三级开关 + 静默时段、数据与隐私页（缓存/同步范围/敏感信息/应用锁） | T15-T22（通知/隐私子集） | 推送通道（F1） |
| M4 桌面确认通道 | 手机端 pending 机制、桌面端确认条组件、镜像数据拉取（config_get 快照） | T17-T18、T32-T36 | 桌面端确认条组件（跨端） |
| M5 收尾 | 设置迁移、快捷卡片、性能埋点、全量回归 | T25、T1-T25 全绿 + 桌面回归 | 无 |

分期原则：

- M1 是硬前置（配对是一切功能的前提），且不依赖账号中心——先交付"访客 + 局域网直连"的最小可用闭环。
- M2 与 M3 可并行；M4 的镜像与确认通道依赖 M1 的配对会话建立。
- 每期结束即提交（遵循仓库提交风格），测试脚本与调试入口立即入库（AGENTS.md 测试资产铁律）。
