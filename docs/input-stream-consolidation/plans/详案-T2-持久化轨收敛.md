## 1. 做什么（T2-1 剥镜像 → T2-2 删轨 → T2-3 死层）

**概念目标（单路径形态）**：会话持久化只保留 **SQLite（conex-db）单一主存写入面**，localStorage 轨（镜像/降级戳/迁移/回退）全部拆除，event 流为唯一时间线骨架；未接线的 `append_session_messages` 死库函数连同其陪葬测试/bench 一并删除。落到不变量 2「只追加」：事件流是事实源，session_messages 仅为前端投影缓存（非第二事实源）。

分三步（**顺序强依赖，不可合并，不可跳步**）：

### T2-1 剥镜像（先剥）

改 `apps/crish-desktop/src/api/session-persistence/sessionRustDbSql.ts` 的 `saveSessionBody`（现 :209-237），把 SQLite 主路径上仍挂着的 localStorage 镜像/降级戳接入点剥离：

| 接入点                    | 现状（文件:行）                                                                | 剥除动作                                                               |
| ------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| SQLite 成功后仍写 LS 镜像 | `sessionRustDbSql.ts:218-220`（`if (msgs.length > 0) lsSaveSessionBody(...)`） | **删**：SQLite 成功 = 唯一落点，不再镜像                               |
| SQLite 成功后清降级戳     | `sessionRustDbSql.ts:223`（`clearDegradedSession(sessionId)`）                 | **删**：无镜像即无降级戳语义                                           |
| invoke 失败回退 LS 正文   | `sessionRustDbSql.ts:226-234`（`logInternalError` + `lsSaveSessionBody`）      | **改**：缺/错命令不再写 LS 返回；降级改为「不落正文 + 数据面可见错误」 |
| 失败后打降级戳            | `sessionRustDbSql.ts:236`（`markDegradedSession`）                             | **删**：降级戳机制整体废弃                                             |

> ⚠️真跑（T2-1 结束门槛，禁跳过，review §②#8/§⑤ 三闸门第一道）：模拟 `save_session_body` invoke 失败两路，断言：
> ① 失败 → **不再写 LS 镜像、不再打降级戳**，转到可感知降级态（errorStore.persistenceStatus / 数据面提示），而非静默 LS 回退；
> ② 成功 → **不再写 LS 正文镜像**，hydrate 不因 LS 陈旧回灌。

### T2-2 删轨（先剥后删）

在 T2-1 基础上删除 localStorage 轨与 RustDb 前端轨的**确无存活面**部分。逐个核实存活面后的精确裁决见 §2.1「存活面裁决表」。

> ⚠️真跑（T2-2 结束门槛）：`rg -l 'sessionLocalStorage|lsSaveSessionBody|markDegraded|clearDegraded' apps/crish-desktop/src` 空；移除 localStorage 引用后 `npm run typecheck` + vitest 快层绿。
