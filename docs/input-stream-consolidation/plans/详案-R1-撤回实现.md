## 0. 一句话概念目标

撤回是**时间线的逻辑截断（只追加不变量保持），不是消息物理删除**：UI 对某 user 节点发起撤回 → 定位该节点 seq 为边界 → **先停后截**（stop 收敛 + 边界冻结原子，评审 01 硬项）→ 发 `timeline-truncate` 事件（boundary seq，旧事件保留）→ 按「类别→回滚策略」回滚 boundary 后副作用 → 前端投影重放至 boundary → 从 boundary user 节点回填文本到 composer。

**负产出（本轮豁免声明）**：`tool-update` 死契约删除归此轮——`AgentEvent::ToolUpdate` 变体 + `event_policy` 错位默认分支 + 前端空实现 + 未接线残留，一次性清零（决策 1）。

## 1. 做什么

### 1.1 前提契约（依赖 T1a，已定型）

`timeline-truncate` 事件的 wire schema 由 `详案-T1-事件模型扩展.md` §1.2(a) 定型 **（T1a，R1 消费，非本详案实现）**：

```
AgentEvent::TimelineTruncate {          // type = "timeline-truncate"，事件域 retraction
  session_id: String,
  run_id: String,                        // 撤回收场的 run（与信封 runId 同值）
  boundary_seq: u64,                     // 截断边界 sequence（重放只到此前）
  reason: TimelineTruncateReason,        // UserRequested | ErrorRollback
  target_message_id: String,             // 被撤回 user 消息稳定 id（文本回填数据源）
  timestamp: String,                     // ISO8601
}
```

- **基本不变量**（T1 §1.2a）：`TimelineTruncate.sequence > boundary_seq`；boundary 之前的旧事件保留、之后的重放忽略。`Critical + Persist + Critical` 必达落库；`event_policy` 独占分支（不落 catch-all）。
- **本详案的职责**：实现**发射方（引擎侧消费 + 停 run + 冻结）**、**回滚执行器（trash + 类别注册表）**、**前端消费（投影重放 + 文本回填）**、**负产出（tool-update 删除）**。**已由 T1a 定义的 `TimelineTruncate` 类型/载荷本身不在此写**。

#### ③ 边界冻结机制（★ 必须设计，评审 01 ②#2 最大逻辑漏洞）

> **问题**：L3 stop 与 `timeline-truncate` 发射不是同一提交单元——若 stop 收敛后、truncate 落库前又写入事件，或 stop 未完全收敛就发 truncate，会「截断后仍有新事件越过 boundary」，撤回重放基准失效（analysis/10 §④缺口1）。

**冻结协议（引擎侧，一次串行事务或同锁区）**：

```
prepare_retraction(session_id, target_message_id, token):
  1. [校验] 会话存在、target 可定位 → boundary_candidate = resolve_boundary_seq(...)
     若找不到 → 返回 Err，不进入冻结（fail-closed，不半冻结）
  2. [停 run] 对会话运行中 run 投 L3 force_cancel（reason="retraction:<seq>"）
     并行对会话 running 子代理 kill_all（同一撤回边界）
  3. [收敛 + drain] 等待该 run 的 terminal 事件确认（run-terminal / run-cancelled）收敛
     到稳定点：drain 控制总线 steer/followUp 队列 + pending_inputs，
     保证无 in-flight 新写入（analysis/10 §④背压/队列缺口）。
     —— drain 到稳定点后，当前仍有能力写入的事件只有：消息增量收口 / 工具批
        收口 / 终态事件（这些都在 run 收口路径内，run-terminal 后自然停写）。
  4. [冻结读 max seq] 在 stop 收敛后的稳定点上，读取会话当前 events 表
     MAX(sequence)，得到 frozen_seq。
     —— 冻结语义：frozen_seq 是本「撤回事务」内不会再被任何事件超过的边界。
  5. [发 truncate] push AgentEvent::TimelineTruncate {
         session_id, run_id, boundary_seq: frozen_seq,
         reason: UserRequested, target_message_id }
     —— TimelineTruncate 自身占 sequence = frozen_seq + 1（或其后），
        保证 TimelineTruncate.sequence > boundary_seq（T1 §1.2a 不变量）。
  6. [冻结完成] 撤回事务内，从此往后的新写入（若因并发残余产生）由
     事件层「冻结护栏」拒绝或归到新 run（见下「冻结护栏」）。
```

**冻结护栏（写侧隔离，保证「截断后无新事件越过 boundary」）**：

- 在会话隔离的**事件写入链**（`orchestrator/events.rs push/append`）挂一个**会话级内存 froze flag + frozen_seq**：
  - 冻结激活期内，任何 `sequence > frozen_seq` 的**非撤离事件**（即非 retraction 自身、非 run 收口的终态事件）写入 → 拒绝（返回 `RetractionFreeze` 错误）**或**打上 `rerouted_to_new_run` 归到冻结后新 run（二选一，见下）；
  - **推荐：拒绝 + 错误回 AI**（fail-closed 语义对齐 exec_single fail-closed），冻结期为短暂窗口（stop 收敛级，毫秒级），拒绝比「归新 run」更简单且不透传新执行；「归新 run」仅当用户在撤回后立即重新提交（新 run 天然从 boundary 后重新开始，与 `timeline-truncate` 语义不冲突）。
- 冻结期边界 = 从「进入冻结协议」到「TimelineTruncate 落库确认」，令牌式（`retraction_token`）单会话互斥：同一会话并发撤回 → 第二次进入前先检查 token，令牌未被释放则排队或拒绝。

**原子性论证（为何可做成原子）**：

1. `drain` 到稳定点 + `frozen_seq = MAX(sequence)` 的读取与 `TimelineTruncate` 的 `push` 落在**同一会话级 async 锁区间**（对齐 events.rs `reserve` 的会话级原子计数器，193-207：会话内全局单调，防同会话并发 run 冲突）；
2. events.rs `reserve` 用 MAX 语义只抬高不回退（`:139 COALESCE(MAX(sequence),0)+1`）——截断后 boundary_seq 是**历史序列上限**，不可能被回退覆盖；
3. 事件层 `push` 是会话唯一写通道（01 审计：engine 只写 events 表）——在锁区间内 stop 收敛后，`frozen_seq` 就是「事件流不会再被本次撤回前的 run 写入超过」的固着点；
4. 前端投影重放「只到 boundary_seq」与事件流只追加天然自洽：`TimelineTruncate` 之后的事件（若有）属于**新 run / 新提交**语义，投影按 `> boundary_seq` 屏蔽或按新 run 段展示。

**并发测试是 R1 硬验收（02 §4：边界冻结 = 硬验收并发测试）**——见 §5.2 冻结并发断言。

**「类别→回滚策略」注册表（扩展点 D，类别轴共用 P1 ——不另建枚举）**：

- **类别轴 = `ToolCategory`**（`crates/conex-types/src/tool.rs:11-14`，P1 保留为投影标签 + 策略分派键；评审 02 ②#3 + 核心模型 §7 纪律 1）。**R1 不新建第二类别枚举**。
- 注册表形态（Rust 侧，`crates/session-loop` 新增，数据驱动，不用 trait 树）：

```rust
// 工具类别 → 回滚策略（扩展点 D）
pub enum RollbackStrategy {
    None,                       // 只读/无副作用：空实现
    TrashRestore,              // 文件写类：snapshot + restore_force（S10b 语义）
    GitRevertGated,            // git 类：过 RevertPolicy 门禁后回滚
}

pub struct CategoryRollbackRegistry {
    map: HashMap<ToolCategory, RollbackStrategy>,
}
impl CategoryRollbackRegistry {
    pub fn default_() -> Self;   // 默认映射：按工具类别粗分
    pub fn strategy_for(&self, category: ToolCategory) -> RollbackStrategy;
    pub fn register(&mut self, category, strategy);  // 扩展点：插件可注册
}
```

- **默认映射**（`default_`）：`Internal` 按工具名/实际类别细分（P1 若接线真类别则直接用真类别；若登记降级为投影标签则 `default_` 用保守默认——写类 `TrashRestore`、只读 `None`）。**类别轴安全判定不读类别**（P1 决策 4）、**回滚策略读类别**（扩展点 D）——两者职责分离。
- **工具可回滚性标记**：在工具执行侧（`exec_single`/`exec_batch`）标记每个 tool-call「回滚类型」，撤回时按 boundary 后这些 tool-call 的输出路径回滚。**最少实现**：不新增 per-tool 元数据枚举，直接由「类别→策略」注册表承接（避免过度设计；P1 类别轴 + 注册表已够，不重复登记面）。
- **扩展点 D 承载面**：撤回/回滚策略在 **Rust 侧** 钩子 + 注册表承载（核心模型 §4 扩展点 D、08 §D5：TS 插件轨承载不了 D）。**撤回逻辑不进核心循环**——挂在核心外（见 §6 禁止项 + §5「核心不反向依赖扩展」）。

### 1.3 负产出：tool-update 死契约删除（本轮豁免声明 · 决策 1）

## 6. 禁止项（明确不做什么）

1. **不物理删除事件**：撤回是逻辑截断（新 `timeline-truncate` 事件），不 DELETE events 表；events 表只追加不变量保持（连 mobile 缓存也收敛为逻辑截断/显式降级，不物理删）。

3. **不在核心循环加撤回逻辑**：撤回是扩展点 D 承载（核心模型 §4 D），不侵入 streaming/tool 核心七步链（07 审计 C1 主战场 handlers 不动）；冻结护栏挂事件写侧扩展检查点，不改核心裁决逻辑。
4. **不新建第二类别枚举**：类别→回滚策略注册表用 P1 既有 `ToolCategory` 类别轴（评审 02 ②#3），不另建类别枚举。
5. **不删引擎 deny 底线 / 不越界 P1/R2 文件**：R1 不写 `permission.rs`/`exec_verdict.rs`（P1）；不改 `persist_plugin.rs:227` 转发守护（R2）；不改 lifecycle row 归一（落文档而非改）。
