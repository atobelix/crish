# 详案任务书模板（D1–D5 · 统一输入流战役）

> 用途：主控在审计收齐后，为每个维度生成详案任务书（v2 流程 §二.4 详案模板落地）。
> 纪律：每份详案必须包含「删什么」；没有删除清单的详案不通过评审。

---

## 任务书结构（每维度一份，填完以下各节）

### 0. 任务标识

- 维度：D1 统一时间线 / D2 注入文本化 / D3 权限注册表 / D4 展示投影 / D5 插件边界
- 前置依赖：依赖的维度（D1 为起点；D2/D3 依赖 D1；D4/D5 依赖前序）
- 相关审计产出：analysis/0X-*.md（本维度的证据底稿）

### 1. 做什么（新增/修复清单）

- 概念目标：本维度要收敛到的「单路径」形态是什么（一句话）
- 新增/改造项（逐条）：目标形态 | 关键文件域 | 改动性质（新增/重构/接线）

### 2. 删什么（删除/合并清单）★ 必填

| 待删项 | 类型（死层/重复路径/陪葬测试/无日期 fallback/波次命名） | 证据（文件:行，来自审计） | 删除方式 | 风险与回滚 |
| ------ | ------------------------------------------------------- | ------------------------- | -------- | ---------- |
|        |                                                         |                           |          |            |

### 3. 依赖与逻辑顺序

- 本维度内部步骤序列（先删后改；删除必须先于依赖它的新增）
- 与其它维度的接缝（谁先谁后、接口契约）

### 4. 文件域

- 唯一文件域列表（Agent 不得越界）
- 跨域收敛任务（如涉及，单独列出并排期，不与并行 Agent 重叠）

### 5. 验收标准

- 功能验收（行为断言，可跑测名优先）
- 负产出验收：删除行数 ≥ 1 / 路径收敛数 ≥ 1；未接线标记新增 = 0
- 门禁：typecheck / 单测 / 涉及 e2e 全绿；波次命名新增 = 0

### 6. 完成后自检（Agent 交回时）

- 我改的文件里没有新增 TODO/未接线标记
- 我没有留下第二条路径（本概念路径数已核实）
- 删除声明附 grep 零命中证据
