### 1.3 F1-γ：输入契约化 — 批次 R7（依赖核心输入契约定义）

**目标形态**：主对话输入不再硬绑 Tiptap（消除 16 §⑤ G1）；富文本为可替换增强、textarea 兜底为核心。

1. **定义核心输入契约**：以 `ComposerFieldProps`（`ComposerField.tsx:27-89`，已覆盖 value/onChange/onSend/onStop(L2)/onForceStop(L3)/onPaste/draft 水合语义/aria 族）为 **canonical 契约基准**，收敛为一个独立类型（如 `composer-input-contract.ts`）：
   - 契约字段：`value/onChange/onSend/canSend/placeholder/disabled/isComposing/setIsComposing/isProcessing/onStop(L2)/onForceStop(L3)/onPaste/onFiles/draft恢复/aria*`。
   - **`onFiles` 注意**：现 `ComposerFieldProps` 无 `onFiles` 字段，主对话附件走父级 `ComposerAttachmentBar` + 隐藏 `<input type=file>`（`ChatComposer.tsx:222-239`）。契约化时**不强行把附件塞进字段 props**，保持附件为壳层职责（避免过度设计，符合 §7-2 接口两实现法则）；契约只覆盖文本输入主域。
2. **`TiptapComposerField` 实现同一契约**：确认 `TiptapComposerField.tsx` 实现 `ComposerFieldProps`（对齐签名），作为富文本可替换变体。
3. **`ChatComposer.tsx:194-220` 改为契约消费者 + 兜底分支**：
   - 抽 `renderInputField()` 统一装配，props 来自同一契约对象。
   - 默认主路 = `TiptapComposerField`（保现状富文本体验），经 `React.lazy` 软接 + `try/catch`/Suspense fallback → 失败时回落到 `ComposerField`（textarea，`onSend` 直调）；或提供显式开关（如 `data-textarea-fallback` / feature 兜底）在装配失败时切 textarea。
   - **禁止**删除 `ComposerField` 纯文本能力（子 agent 侧栏仍复用）。
4. **对 `useSlashSend.ts:75` 的 `chatInput.trim()`（纯文本发送底层）复核**：契约化不改发送底层（发送只吃纯文本），仅解耦"富文本编辑器→纯文本"的提取层。`serializeToMarkdown`（富文本专属）归 Tiptap 变体，textarea 变体无需。
