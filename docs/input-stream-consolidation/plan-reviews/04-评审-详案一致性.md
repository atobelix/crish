## ② 跨详案冲突清单（冲突 | 协调方案）

### B1（实质冲突）· `tool-update` 死契约归属

- **冲突**：框架决策 1 = 删变体、归 R6/R1；`详案-R1` 认领（§1.3 负产出 + §2 D1-D6，含 TU1/TU2 验收）；`详案-C1` §1.C1c/§2 D-C1-5 仍「归 C1c 或 R6 主控裁决 / 删或接入发射二选一」。analyisis/14 §③.2 实证 tool-update=零发射死契约，删变体方向唯一（前端零消费 + event_policy 错位 Persist）。
- **协调方案**：**按框架收敛为一处**——删变体、归 R6/R1（R1 详案已完整）；**`详案-C1` 删除「C1c 收口 tool-update」的裁决段与 D-C1-5 里「删或接入发射二选一」表述**，改为「涉 `conex-types/events.rs` / `tool_events.rs` 的工具契约收口归 R1/R6，C1 不执行」。避免执行轮 C1 与 R1 两 Agent 抢删同一事件面（事件面同文件须串行）。

### B2（依赖链口径）· I1 详案「context-state 载体」与 T1 裁决不一致

- **冲突**：`详案-I1` §1.1② 写「在 T1a 新增 context-state 节点类型（**AgentMessageRole 或 AgentMessageBlock::State 新变体** + metadata.kind 枚举 ContextState）」；而 `详案-T1` §1.1 裁决 1/裁决 2 已定 **role 不扩展、不新块类型、只走 metadata.kind**（context-state 挂 User role + `kind:"context-state"`，正文走既有 text 块）。
- **协调方案**：**`详案-I1` 措辞收敛为「metadata.kind = ContextState（T1a 定案）」，删除「AgentMessageRole 或 AgentMessageBlock::State 新变体」分支**。I1 只消费 T1a 已定类型，不保留替代载体（抽象纪律 1 单类型）。属文字口径冲突，实际落地以 T1a 为准。

### B3（口径残留）· E2 详案 A 承载缝引用 PendingNudgeChannel
