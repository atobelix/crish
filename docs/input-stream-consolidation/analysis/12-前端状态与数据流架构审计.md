## ③ 数据流链图（文字版）

### chat 主链（消息正文/工具）

```
IPC 平铺事件
  → EventRouter.onMsg            (api/chat-bridge/EventRouter.ts:236)   信封预过滤(runId) + 复合因果去重
  → parseBridgeEvent             (api/chat-bridge/handlers/eventParser.ts:355)  生成解析器优先，宽容归一兜底
  → handleAgentEvent(路由+去重)  (EventRouter.ts:149)    tool-end 乱序缓冲(toolTurnRegistry/pendingToolEnds)
  → dispatchEvent                (handlers/dispatch.ts:219)
      ├─ engineDispatchTable(41键) message-start/null, message-delta, message-end …
      │   └─ onMessageDelta/onMessageEnd  (handlers/messageHandlers.ts)
      │         └─ env.callbacks.onChunk / onThought  (StreamCallbacks → hooks/chat-stream/useRunStreamingAssistant)
      │               └─ useStreamCallbacks.buffer.onFrame → streamTextBatcher → streamingStore
      │                     (分帧预算写 streamingStore.byKey, reduce 重渲染)
      │                     └─ tools 经 toolBatcher → streamingStore.setStreamTool
      ├─ onToolStart/Update/End  (handlers/toolHandlers.ts) → tool patch → streamingStore(中间态)
      ├─ onAgentStart/End, onTurnStart/End, onRunTerminal (lifecycleHandlers)
      └─ legacy( subagent-* ) → subagentHandlers → sessionAgentActions

  commitStreamToSession  (hooks/chat-stream/helpers.ts:197)
      → commitStreamToolsToSession → layoutStore.addMessageToolCall/updateMessageToolCall
      → updateMessageText / updateMessageThinking (store message)
      → updateMessageTimeline (layoutStore action → api/toolPresentation.normalizeAssistantTimeline)
      → queueMicrotask clearStream (→ streamingStore 空)   [防白屏时序闭环, helpers.ts:226-233]
渲染（view model → 组件）
  ChatMessageRow → ChatAssistantMessageRow
      → MessageContent (components/chat-message/MessageContent.tsx:138)
          selector:  useStreamingStore(byKey[string:msg.id]) text+tools
          useMemo:   applyStreamTextToMessage / applyStreamToolsToMessage (streamMessageViewModel.ts)
                     （streamingStore 中间态 ⊕ SessionMessage 持久行的**投影合并**，防线2防撕裂）

```

**结论（chat 主链）**：事件（EngineEvent）→ streamingStore（中间态，纯内存）→ view model（`streamMessageViewModel.applyStream*`）→ 组件。**事件流是上游单一写入源**；`layoutStore` 消息正文/toolCalls 是 run 收口/工具快照的**持久投影**；`streamingStore` 是**流式中间态投影**——两组同属于「事件流的派生投影」，但**未合并为单一投影 store**（§⑤）。

### chat 链 view model 定位

- `MessageContent` 内嵌的 `useMemo(() => applyStreamTextToMessage(next, streamText))`（MessageContent.tsx:147-166）是 chat 主链的 **view model 层**：不改 store，只从 SessionMessage + streamingStore 投影出展示 DTO。
- 另有 `api/messageUserProjection.ts`（UserView，~809 行）——但 **04 审计已判定为旁路投影**：真实渲染主路径是 `timelineNormalizer`（`api/tool-presentation/timelineNormalizer.ts`），UserView 仅 `silentComplete` / 调试面板 / 测试消费。两条投影路径并存（§④重复面 4）。

### note / workspace 链

```
chat 消息完成态
  → ChatSendToNoteEntry → bridges/send-to-note.ts（薄桥，surface=chat 完成态 → Intent）
  → transport.sendToNote（noteApi.ts → tauri invoke note_send_to_note IPC）
  → note-paper（block-paper）+ note-doc-written 总线读回（CONN-G1 同 doc 刷新）
  → note-paper 组件的 hydrateProjection / useNoteHydrate（产品自有投影，非 store 域）

workspace 链（布局）
  workspaceShellStore.openOrFocusSession（TabSurface owner）
     → 内部 setActiveSessionId（layoutStore 会话切片）+ bindActiveChatLeafSession（layout-tree）
     → applyDockToTree / ensureAdapterShape（adapterShape → layoutTreeStore）
     ↔ tree→shell 反向投影（registerTreeDockSync，workspaceShellStore.ts:632，经 treeDockProjection 抑制防回环）
```

**结论（note/workspace 链）**：note-paper 是独立编辑表面（block-paper 包 + IPC 桥），**不消费 layoutStore/streamingStore 的消息态**，也不经过 store 域；它通过 `note-doc-written` 总线做写后读回，与 chat 主链**不共享状态树**。workspace（shell↔tree 双向投影）与 chat 消息分隔；shell 是「打开什么」的写 owner，会话正文仍归 layoutStore。

## ④ 状态归属问题清单（含重复面证据）

### 1. 上帝 Store：layoutStore 混合「布局 chrome / 会话域 / legacy workspace」三域

- `layoutStore.ts:141-185` 接口同时含 chrome（uiSize/shellChrome/chatMainSurface/sidebar）+ 会话（sessions/sessionsById/activeSessionId/activeAgentId/composerDrafts）+ workspace（workspaces/dropPreview/draggedTab）+ `<SessionActions, WorkspaceActions>`。
- README § State ownership 与 `storeOwnership.ts` 已明言 `session` 与 `workspace-legacy` 仍挂在 layoutStore（OPT-C1 本波不拆），T11 只拆出 terminal/worker/permission/settings 四域。
- **影响**：凡 React 直接订阅 `useLayoutStore`（含 facets alias）的组件，会因**任何**会话/消息变更 + 任何布局变更而重估价（侧栏用例已有 `useSyncExternalStore` + shell-equal 短路缓解，但 god-store 本质未去）。这是 review.md§4「上帝 Store」绿→黄偏红项。

### 2. 同一状态多份（storeAccess 双份）

- `src/store/storeAccess.ts`（store 侧读面，T11 新，覆盖四域+chrome）**与** `src/api/storeAccess.ts`（编排层，api/store-access/**）+ `api/store-access/componentAccess.ts`（过渡读面）并存。
- **证据**：storeAccess.ts 头部原文「## 双 storeAccess 说明」（storeAccess.ts:8-15）；`componentAccess.ts:1-17` 明言「T11 交付的 storeAccess 未覆盖 sessions/layout-tree/workspace-shell/streaming/draft，故建 componentAccess 过渡」。
- 三份读面指向同一批 store，但调用方可能混用三条入口 → 心智成本 + 门禁（check:store-facade / check-store-writes）维护面。

### 3. 同一状态多份（消息正文双份投影：streamingStore ∥ layoutStore）

- **证据**：`MessageContent.tsx:138-166` 同时订阅 `sessions[].messages[].text` 与 `streamingStore.byKey.text`，经 `applyStreamTextToMessage` 合并；`helpers.ts:197-235 commitStreamToSession` 收口时再从 streamingStore 写回 layoutStore。
- 同一 assistant 消息正文在**两个 store 各存一份**（streamingStore 中间态 + layoutStore 持久行），靠 view-model 投影三角拼接 + 时序闭环（`queueMicrotask clearStream`）维持一致。评 review.md§4「多源真相/高频双平行状态树」——**chat 主链正是最典型的双份状态树**。

### 4. 展示投影双实现：timelineNormalizer（主）∥ messageUserProjection/UserView（旁路）

- **证据**：06 审计 + 本审计复核——真实渲染走 `api/tool-presentation/timelineNormalizer.ts`（`normalizeAssistantTimeline`）；而 `api/messageUserProjection.ts`（~809 行，UserView）仅 `silentComplete` / 调试面板 / 测试消费（见 `api/silentComplete.ts` / UserView debug flag `messageUserProjection.ts:659`）。**两条投影链对同一消息各算一遍**，属 review.md§4「概念路径枚举 >1」。

## ⑤ 收敛建议

### 目标形态（对齐 00 总方案 §5「事件流 = 唯一时间线骨架」）

前端**应收敛为一个「时间线投影 store」**：以事件流（chat-bridge 已解析）为唯一写入源，派生一份「时间线投影」，其余业务 store 明确降为局部/派生。

```
事件流（EngineEvent, chat-bridge 单一解析）
  → TimelineProjectionStore（唯一时间线投影：只追加、幂等、按 seq 归序）
       ├─ selectMessage/session：派生当前会话的 SessionMessage 序列
       ├─ selectTimeline：投影消息 + 流式段 + 工具卡（替换 streamingStore + layoutStore 消息双份）
       └─ 由 run 收口/撤回（withdrawMessage / timeline-truncate）驱动刷新
  → 派生选择器（selectSidebarSessions / selectActiveTimeline / …）
  → 局部 UI 态（composerDraft / overlay / DnD / tree 拖拽——不高频入全局）
  → 纯组件（只订阅派生选择器）
```
