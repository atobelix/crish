## ④ 通用「编辑会话」抽象建议

现状：前端**不存在**「编辑会话」抽象（open→commit/invalidate）。唯一的非形式保护是 `StrictContentRowLeaf.tsx:133 dirtyRef`（开环、永不复位）与 `slashSendDraftManager` 快照（一次性子、Map 单条目）。后端**已有两类可复用先例**：

1. **write_paths 互斥状态机**（`write_paths_state.rs`）——含 **声明记账 / 冲突检测(同锁区间原子) / 原子插入 / RAII 守卫（Drop 释放）/ TTL 过期**。这是「一个持有者声明拥有某资源，他方冲突即拒绝」的引擎级先例，但**只作用于 agent 写**文件路径，**不是用户 UI 编辑**。
2. **lease_guard**（`conex-db/src/lease_guard.rs`）——30min 上传/编辑租约防误杀，是「编辑持有期」数据面先例。
3. **CT-01 CAS**（doc.rev 条件写盘）——版本条件写、冲突即报错的持久面先例。

**建议的「节点编辑会话」四要素**（复用现有而非新建机制，对齐 §7 反过度设计）：

- **open（声明持有）**：编辑开始（contenteditable 首次 onInput / 设置表单打开 / 草稿有内容）→ 对该节点 id 声明一个**本地编辑会话**（可复用 write_paths 的注册表思路，但抽象到「节点 id」而非「文件路径」，读 write_paths_state.rs `WritePathRegistry` 为模板，不含 TTL 跨会话过松）。
- **版本契约（对象级）**：每个可编辑结果节点（草稿/消息/块/设置项）携带 **rev/版本号**（CT-01 已给 doc 级 rev，前端投影未透传给 dirtyRef 叶）。编辑提交时带 `expect_rev`，不符 → 冲突上报（对齐 persistence.rs `PersistError::Conflict`），不静默 LWW。
- **commit（提交并失效）**：提交成功 → 推进 rev、清编辑会话/dirtyRef、发送失效通知（订阅方刷新）。替换 `clearDraftSnapshot`/`dirtyRef=true` 的一次性清空。
- **invalidate（失效传播）**：编辑中若节点被远端/引擎合并、撤回、截断 → 对该 id 的编辑会话发 invalidate（前端组件相斥——依赖节点仍在 DOM 则提示重新确认；撤回 → 丢弃编辑会话且 `withdrawMessage` 跳过正在编辑 id 的提示）。
- **设置表单**：`refresh()` 从手动改为**订阅失效**（外部激活/权限变更发无效事件 → 有未保存 cfgDraft 时提示 / 无则重载），避免陈旧草稿 LWW 覆盖（对应 review §11 缓存失效）。

## ⑤ 对核心模型状态维度（#1 不变量 6）的验证与建议

**核心模型定位**（草案 #1 不变量 6）：内容分「进行中(ongoing) / 终态(settled)」两种状态生命周期——进行中由**增量事件**(delta/progress, 可丢/NoPersist)表达、终态由**必达事件**(end/result, Critical 落库)表达。

**验证结果**：现状代码含两个独立的「状态生命周期」事实源，与模型共振但未归口成统一「节点状态维度」：

1. **进行中节点**：`streamingStore byKey` 中间态（草案已验证）；`updateMessageText` 流式推进（`sessionMessageActions.ts:151-187`）——是「进行中由增量事件表达」的现状实现。
2. **终态节点**：收口 `commitStreamToSession`（helpers.ts:197-235，`queueMicrotask clearStream` 时序闭环防撕裂）——是「终态必达 + 投影切换」的现状实现。

**审计给「节点状态维度」的编辑保护建议**（编辑保护应归为状态维度的哪部分）：

- **对象版本契约**（必须有）：编辑会话必须携带**对象级 rev**（草稿/块/设置项），与 CT-01 的 doc.rev 对齐；前端投影把 rev 透传给编辑面，conflict 才能被发现而非 LWW。
- **编辑会话事件**（进行中维度的扩展）：编辑行为是非增量的「正在进行」——它与增量事件不同（增量可丢、编辑**不可丢且要独占**）。建议在模型补一条「**进行中维度的独占子类：editing session**」：有 open（声明）、commit（必达提交）、invalidate（失效）。它不是一个新节点类型，而是对既有终态/进行中节点附加的**持有态**。
- **失效传播**（终态维度的下游）：engine 侧撤回/截断/远端合并 → 产生终态/截断事件 → 订阅端对「有编辑会话的对象」做 invalidate（丢弃编辑或冲突提示），复用 `MessageSnapshots` 的增量回滚面（其 `'edit'` 死枚举建议接线或删除，避免悬空死在 union）。
- **不新增全局锁**：不做「编辑时全局禁写」——write_paths 已证明「声明+冲突拒绝」比「全局互斥」文明；把 write_paths 的**声明记账/Rail 模式**从「文件路径」泛化到「可编辑节点 id」，并明确**它服务于引擎-引擎互斥，用户 UI 编辑应走同模式的节点级版本契约**。

**收敛度量补充**（供主控 07 表）：

- 双 follow_up 机制并存（useSlashSend `enqueueFollowUpMessage` ∥ composer `onSend` 队列）——1 概念 2 路径，收敛战役 B 扩展点待归一；
- 双 on_committed_expect 实现（persist_plugin.rs:71 / :226）待核唯一接线；
- `MessageSnapshots.operation['edit']` 无生产消费方=死枚举，删或接线二选一；
- 设置页 `profiles` 无失效订阅=review §11 缓存失效红黄债。
