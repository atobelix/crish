## ④ 样式体系评估

### 组织与层级

- **双轨已收敛为单源**：所有颜色/圆角/间距/字号/字重/行高/z-index/过渡/阴影引用 `styles/tokens.css`（**1,000+ 个 token**，`.tsx` 与 `.css` 内禁用裸 hex/rgba）与 `styles/z-index.css`（z-index 唯一真源）。
- **组件样式 = CSS Modules**（`components/` 下 89 个 `*.module.css`，camelCase 类名、组件同目录）；**全局样式**全部集中在 `src/styles/**`（settings/shell/chat/panels），组件层 0 个非 module 全局 css。
- design-system.css 承载全局动画/浮层/elevation 工具类（第 3 层补充层，很薄，96 行）。

### Token 使用率（脚本实测）

- 全局 30 个 css 文件合计 **4,152 次 `var(--...)`** 引用 vs **241 次裸色**。剔除 token 定义文件本身（tokens.css 128 个裸色 = token 值，合规），**业务样式裸色仅 ~113 处**（settings-base.css 37 / settings-models.css 17 / settings-plugins.css 7 为主）。
- 意义：样式已高度 token 化（**~94%**），tokens.css 内部注释、`--tint-*` 淡染族 / `--space-*` 密度阶梯 / `--transition-*` 动效档位成熟。

### Token 治理门禁（真跑存在且有基线）

`src/styles/style-contract.test.ts`（439 行）以 fs 契约断言强制：dark 分支覆盖、禁新裸混色（基线 3）、禁裸 999px（基线 62）、scrollbar 块（≤5）、!important（≤626）、注入 token ∈ 静态定义（双层同源）、悬空引用清零。`a11y-contrast.test.ts`（245 行）守对比度。

### CSS ↔ 组件耦合（className 契约）

- 组件用 CSS Modules `styles.xxx`（camelCase），与全局类**基本解耦**——除 3 个域：**settings**（29 tsx 中 70 处字面量 `className="settings-…"` 绑定 settings-base.css/settings-models.css/settings-plugins.css 等**全局**类）、**diff**（10 处）、**workspace**（12 处）。这些字符串类名组件无法样式隔离，是原子化的主要阻力之一。
- `card-panel/`、`chat-message/`、部分 `settings-extensions`/`note-paper` tsx **无本地 module.css**，直接消费 settings/shell 全局类 → 跨文件 CSS 契约链。

### 命名/魔术数字（review §13）

- tokens 系统已消灭绝大多数魔术数字（z-index/颜色/圆角全 token 化，style-contract 强制）。残存：settings-base.css 内 ~37 处裸色（历史遗留，未 token 化）；部分组件 `className="settings-…"` 字符串类名散落。无波次命名文件（review §13 已达标）。

## ⑥ 原子组件模型建议（落地形态）

### 分层规则（目标楼层 · 可作为目录规范固化）

| 层                                              | 目录约定                                         | 允许依赖                                                               | 禁止依赖                                                         | 现状差距                                            |
| ----------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------- |
| **原子层**（纯展示原子）                        | `components/ui/**`（已有）                       | react/radix/tokens.css/z-index.css + ui/ 内部                          | store/hooks/api/services/业务组件                                | ✗ 见门禁违规（下）                                  |
| **复合层**（业务复合，props + view model 输入） | `components/<domain>/**`，纯展示子件抽为独立文件 | ui/、共享 hook（api/store-access）、api/ 投影（timelineNormalizer 类） | 反向 import 页面壳；直连裸 zustand store（须经 facade selector） | 部分达标，仍有 store 直连                           |
| **页面壳/编排层**                               | `components/shell`/`App*`/`Overview` 等          | 全部上层                                                               | 编排职责不外泄                                                   | 混合（settings/chat-card/workspace 既是壳又是复合） |

### 每层约束

1. **原子层禁 store、纯 props**：ui/ 组件只收 props + callbacks，样式只走 CSS Modules + token。**当下违规须先清零**（见 §③/门禁现状）。
2. **复合层组件消费 view model，不消费裸 store**：所有渲染输入统一为投影产物（`AssistantTimelineItem[]` / `ToolRenderItem[]` / 派生 `SessionMessage`），经 `api/store-access` 的 selector facade 读；写事件一律走 action/IPC，组件不回写 zustand（呼应 04 审计「投影纯函数」结论）。
3. **页面壳只做编排**：不内联业务计算；session/workspace/settings 壳把每屏拆成原子 + 复合 + 少量编排。

### 样式 token 化路径

1. 维持 tokens.css + z-index.css 单源（现状已强）。
2. **消灭全局类残留绑定**：settings/diff/workspace 内 90+ 处字面量 `className="settings-…"` 逐件迁 CSS Modules；card-panel/chat-message 无 module.css 的补建同名 module.css。
3. settings 域 3 个巨型全局 css（settings-base 2,553 / settings-models 2,436 / settings-advanced 664）随其组件模块化逐步收敛到对应 module.css，禁止继续由全局文件承载私有样式。
4. settings 裸色（~73 处）并入 token 语义族（--tint / --color-* / --control-soft-*）。

### 与投影模型的关系（关键 · 承接 04 审计）

- 组件应**只消费 view model**：已存在的投影真身是 `api/toolPresentation/`（timelineNormalizer.buildAssistantTimelineCached / buildToolRenderItems / toolCardPresenter），复合层组件应接受其输出（`AssistantTimelineItem[]`）为 props，而非内部再跑对齐/折叠。
- **收敛点（来自 04 审计，本审计确认前端载体）**：把 `streamMessageViewModel.applyStreamToolsToMessage` 的块对齐下沉并入 `normalizeAssistantTimeline` 单一纯函数（消除 P2 双实现）；当前 `MessageContent.tsx`/`ChatAssistantMessageRow.tsx` 内的 `useStreamingStore` 读取应上移到页面壳层，复合层只收「已合并的 view model」。
