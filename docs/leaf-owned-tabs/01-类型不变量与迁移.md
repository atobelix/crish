## 0. 结论先行

1. **写源**：`LayoutLeaf.tabs: SessionTab[]` + `activeTabId`。`LayoutLeaf.sessionId` 删除。`leaf.tabs` 禁止再放 `panelId` 字符串。
2. **草稿**：每个 draft tab 的 `sessionId = '__pending_draft__:' + tabId`。禁止把全局 `'__pending_draft__'` 写进任何 `SessionTab.sessionId`。I1 的「非 draft 哨兵」按此前缀判定。
3. **工厂**：`createLeaf` 不再接受 `panelId` / `tabs: string[]`；缺省产出「单 chat 叶 + 一个 draft tab」。
4. **迁移**：一次、纯函数、冷启动 restore 入口调用。输入旧树（`leaf.sessionId` + 可能的 tool 子树）+ `openTabs` / legacy map；输出 version=3 纯 chat 树，每 tab 带 `dock`。失败 → 干净单叶 + 一个 draft tab。
5. **persist 校验**：只认 v3 形状；拒绝 tool 叶、空 tabs、重复真实 `sessionId`、全局哨兵、`activeTabId` 不在 tabs。旧规则 `multi-unit-unbound-chat` / `orphan-tool-session` 删除（对齐 I2 / I5）。

## 1. 精确类型草案

### 1.1 版本与常量

```ts
/** 本战役起 LayoutTree.version。v2 = 旧 leaf.sessionId + tabs: string[] + 可含 tool 叶 */
export const LAYOUT_TREE_VERSION = 3 as const;

/** 全局草稿哨兵（session store / enterDraftMode 仍用）。禁止写入 SessionTab.sessionId */
export const PENDING_DRAFT_SESSION_ID = '__pending_draft__' as const;
```

- persist **storage key 不改**（仍 `crish-layout-tree-v1` / window-scoped）。用 `tree.version` + 叶形状判别 v2/v3，不换 key，以免 opt-in restore 丢盘。

### 1.3 `SessionTab`

```ts
export interface SessionTab {
  tabId: string;
  /** 真会话 id，或 `__pending_draft__:${tabId}`。禁止精确等于 PENDING_DRAFT_SESSION_ID */
  sessionId: string;
  title: string;
  /** 项目 id 或 GENERAL_FOLDER（现码字面 '对话'）。缺省写入 '对话'，切项目过滤属维 03 */
  workspaceKey: string;
  dock: RightToolDockState;
}
```

不变量（本维钉死，写路径由维 02 守）：

| 字段 | 规则 |
|---|---|
| `tabId` | 非空；全树唯一（`mintTabId()`） |
| `sessionId` | 非空；真实 id 全树唯一（I1）；draft 用 §1.4 哨兵，亦全树唯一（因含 tabId） |
| `title` | 非空字符串；draft 缺省 `'新对话'` |
| `workspaceKey` | 非空；缺省 `'对话'` |
| `dock` | 必有；缺则 `createDefaultDock()` |

**禁止**加 `isDraft` 布尔字段（总案 `SessionTab` 无此键；draft 由 `sessionId` 前缀判定）。**禁止**保留 `kind: 'conversation'`（树叶已全是 chat，种类字段是旧 `TabSurface` 投影）。

### 1.4 草稿哨兵：per-tab，不是全局 `PENDING_DRAFT`

总案：「每叶可独立 `+`」「该叶 draft 哨兵」「禁止全局单例抢画面」。同一叶可多次 `addTab`，故哨兵必须 **按 tab 唯一**，不能只按 leafId（否则同叶两个 draft 撞 `sessionId`）。

```ts
export function mintTabId(): string {
  return `tab_${Date.now().toString(36)}_${Math.random().toString(36).slice(2, 8)}`;
}

export function mintDraftSessionId(tabId: string): string {
  return `${DRAFT_SESSION_ID_PREFIX}${tabId}`;
}

export function isDraftSessionId(id: string | null | undefined): boolean {
  if (!id) return false;
  return (
    id === PENDING_DRAFT_SESSION_ID || id.startsWith(DRAFT_SESSION_ID_PREFIX)
  );
}

export function isRealSessionId(id: string | null | undefined): boolean {
  return typeof id === 'string' && id.trim() !== '' && !isDraftSessionId(id);
}
```

规则：

1. **`SessionTab.sessionId` 禁止等于** `PENDING_DRAFT_SESSION_ID`（无后缀的全局单例）。工厂若收到它，丢弃并 `mintDraftSessionId(tabId)`。
2. I1 扫描只对 `isRealSessionId` 的 id 做「全树至多一个 tab」。多个 draft tab 合法，因为哨兵不同。
3. persist 另加一条更强检查：任意 `sessionId`（含 draft）全树不得重复——这是 mint 不变量，不是放宽 I1。
4. `moveTab` / `splitTab` **不重铸** draft 哨兵（哨兵含 tabId、不含 leafId，搬叶不失效）。
5. session store 的 `activeSessionId = PENDING_DRAFT_SESSION_ID` **仍是全局画面哨兵**（composer / 不进 `sessions[]`）。活动叶的活动 draft tab 驱动 `enterDraftMode`；其它叶上的 draft tab 只占条带，不抢 composer。映射由维 03 接线，本维只保证树上身份互不碰撞。

与 Demo 对照：Demo `addTab` 给该叶 push `{ id, title }`，本仓等价物是 `createDraftTab()` 推进目标叶。Demo 没有 session 身份，本仓用 per-tab 哨兵补上，而不是全局 `'__pending_draft__'` 让两叶抢同一个 `activeSessionId` 画面。

## 2. 工厂如何改

### 2.1 `createSessionTab` / `createDraftTab`（`sessionTabModel.ts`）

```ts
export function createDraftTab(opts?: {
  tabId?: string;
  title?: string;
  workspaceKey?: string;
  dock?: Partial<RightToolDockState>;
}): SessionTab {
  const tabId = opts?.tabId ?? mintTabId();
  return {
    tabId,
    sessionId: mintDraftSessionId(tabId),
    title: (opts?.title ?? '新对话').trim() || '新对话',
    workspaceKey: (opts?.workspaceKey ?? '对话').trim() || '对话',
    dock: createDefaultDock(opts?.dock),
  };
}

export function createSessionTab(input: {
  sessionId: string;
  title?: string;
  workspaceKey?: string;
  tabId?: string;
  dock?: Partial<RightToolDockState>;
}): SessionTab {
  const tabId = input.tabId ?? mintTabId();
  const raw = (input.sessionId || '').trim();
  const sessionId =
    !raw || raw === PENDING_DRAFT_SESSION_ID
      ? mintDraftSessionId(tabId)
      : raw.startsWith(DRAFT_SESSION_ID_PREFIX)
        ? mintDraftSessionId(tabId) // 外来 draft 哨兵一律改绑到本 tabId，避免撞车
        : raw;
  return {
    tabId,
    sessionId,
    title: (input.title ?? (isDraftSessionId(sessionId) ? '新对话' : raw)).trim() || '新对话',
    workspaceKey: (input.workspaceKey ?? '对话').trim() || '对话',
    dock: createDefaultDock(input.dock),
  };
}
```

`createSessionTab` 收到已是 `__pending_draft__:${otherTabId}` 时仍重铸到本 `tabId`：只用于 **新建**。`moveTab` 搬的是已有 `SessionTab` 对象，不走工厂（总案 I4「同一对象 splice」；不可变实现 = 搬同一字段快照，不换 `tabId` / `dock`）。

### 2.2 `createLeaf`（`types.ts`）

旧签名（删除）：

```ts
createLeaf(panelId: string, tabs?: string[], activeTab?: string, sessionId?: string)
```

新签名：

```ts
export interface CreateLeafInput {
  tabs?: SessionTab[];
  activeTabId?: string;
  /** 仅测试夹具；生产走 generateNodeId */
  id?: string;
}

export function createLeaf(input?: CreateLeafInput): LayoutLeaf {
  const id = input?.id ?? generateNodeId('leaf');
  const tabs =
    input?.tabs && input.tabs.length > 0
      ? input.tabs.map((t) => normalizeSessionTab(t))
      : [createDraftTab()];
  const activeTabId =
    input?.activeTabId && tabs.some((t) => t.tabId === input.activeTabId)
      ? input.activeTabId
      : tabs[0]!.tabId;
  return { type: 'leaf', id, panelId: 'chat', tabs, activeTabId };
}
```

归一化（取代旧 H4「空 tabs → `[panelId]`」）：

1. `tabs` 缺省或 `[]` → `[createDraftTab()]`，**不是** `['chat']`。
2. `activeTabId` 不在 tabs → `tabs[0].tabId`。
3. 不再接受 `panelId`。`createLeaf('terminal', …)` 编译失败。tool 叶工厂（`makeToolLeaf`）由维 04 删除。
4. 不再接受 `sessionId` 叶字段。要绑会话：传入 `tabs: [createSessionTab({ sessionId })]`。

`normalizeSessionTab`：补 `dock`、拒绝空 `tabId`、把精确 `PENDING_DRAFT_SESSION_ID` 重铸为 per-tab 哨兵。缺字段到无法补 → 该槽位换成 `createDraftTab()`（工厂层防御，迁移层另有整树回退）。

## 3. 迁移算法

新文件 `sessionTabMigration.ts`。现有 `migration.ts`（columns → 二叉树）**不是**本函数，本维不改它（见 §10）。

### 3.1 函数签名（纯函数，无 store）

```ts
export interface LegacyOpenTab {
  sessionId: string;
  tabId?: string;
  title?: string;
  workspaceKey?: string;
  rightDock?: Partial<RightToolDockState>;
}

export interface MigrateToLeafOwnedTabsInput {
  tree: unknown;                            // v2 或 v3 或损坏 JSON
  openTabs?: ReadonlyArray<LegacyOpenTab>;  // 内存 TabSurface 快照；冷启动常为空
  openTabsMap?: Readonly<Record<string, string[]>>; // folderKey → sessionId[]（OPEN_SESSION_TABS_KEY）
  activeLeafId?: string | null;
  resolveMeta?: (sessionId: string) => { title?: string; workspaceKey?: string } | undefined;
}

export type MigrateToLeafOwnedTabsResult =
  | { ok: true; tree: LayoutTree; didMigrate: boolean }
  | { ok: false; tree: LayoutTree; reason: 'unrecoverable' };

export function migrateToLeafOwnedTabs(
  input: MigrateToLeafOwnedTabsInput

```

- **无 store 依赖**。调用方（`onRehydrateStorage` / `hydrateWorkspaceShell`）从 `localStorage` 读 map、从 session store 建 `resolveMeta`。
- 冷启动时 `workspaceShellStore.openTabs` 通常是 `[]`（shell 无 zustand persist；真源是 `OPEN_SESSION_TABS_KEY` + 树）。总案「输入 openTabs」在实现上 = `openTabs` 快照 **并** `openTabsMap`。两者都要读。
- 幂等：已是合法 v3 → 只做归一化（空 tabs / 重复真实 id / 残留 tool 叶 / 全局哨兵），`didMigrate=false` 当且仅当输入已是 v3 且无需改写。

### 3.2 何时跑

| 场景 | 行为 |
|---|---|
| `ui.restoreLastWorkspace` = false（默认） | **不**用旧树。直接 `createDefaultTree()`（clean）。与现 ADR 一致。 |
| restore = true | `migrateToLeafOwnedTabs` → `validateRestorableLayoutTree`；任一失败 → `createDefaultTree()` |
| 运行期命令路径 | **不再**读 `openTabs` / `leaf.sessionId`。无运行期双读分支（总案 §10）。 |
| 已是 v3 的日常 persist | 启动 restore 仍走 migrate（幂等归一）+ validate；损坏才回退 |

`dedupeDuplicateSessionChatLeaves` 降为 persist 损坏兜底（总案 §3）。迁移阶段就把重复消掉，运行期维 02 不得靠它纠偏。本维导出 `findDuplicateRealSessionIds` 给校验用。

### 3.3 步骤（restore = true）

**S0 结构门闩**

- `tree` 非对象 / 无 `root` / root 既非 leaf 也非 branch → 失败回退。
- 先序若发现 branch 不是正好 2 子、`splitRatio` 非有限数、direction 非法 → 失败回退。
- 同树 v2/v3 叶混用 → 失败回退。

**S1 收集 chat 叶（v2：`panelId === 'chat'`；v3：已是 chat）**

对每个 chat 叶：

1. 取 `boundSid = (legacy.sessionId || '').trim()`。
2. **忽略** `legacy.tabs: string[]`（那是 panelId）。
3. 若 `isRealSessionId(boundSid)`：`tabs = [makeTab(boundSid, dock)]`，`activeTabId` 取该 tab。`makeTab` 优先用 `openTabs` 里同 session 的 `tabId/title/workspaceKey/rightDock`，否则 `resolveMeta` + `createSessionTab`。
4. 若 `isDraftSessionId(boundSid)`（含全局哨兵或旧 `__pending*`）：`tabs = [createDraftTab()]`，不把全局哨兵写进树。
5. 若无 boundSid：`tabs` 暂空，留给 S2/S6。

已放置的真实 `sessionId` 记入 `placed: Set<string>`。

**S2 折叠 `openTabs` / map 里尚未出现在任何叶上的真实 session**

- 展开源：先 `openTabs[]`（保序），再 `openTabsMap` 各 key 下的 id（按 key 枚举序 + 数组序），跳过已在 `placed`、空 id、draft 哨兵。
- 并入 **当时活动 chat 叶**（`activeLeafId` 命中且为 chat）；否则第一片 chat 叶。
- **不新建叶**（总案 §6.2）。
- 这些 extras 的 `dock` 默认折叠；若 S3 发现该 session 在树上另有 tool 子树（理论上 1:1 旧模型不会，孤儿 tool 见 S3），再覆盖。

单叶常见情形：叶绑 s1、map=`[s2,s1,s3]` → 步骤后 tabs=`[s1,s2,s3]`（绑定优先、extras 追加）。strip 原序不保留。见 §10。

**S3 坞：从 unit 推断，然后丢掉 tool 叶**

对每个已放置的真实 session：

1. 若 `openTabs` 有 `rightDock`，先拷入该 tab.dock。
2. 若树上存在该 session 的 Conversation Unit（现 `findUnitRootId` 语义：chat 叶的 horizontal 父、另一侧纯 tool 子树）：
   - 用与现 `projectUnitDockState` 相同的推断：`collapsed=false`，`openPanelIds` = tool 子树先序 leaf 的 `tabs`（panelId 字符串，这里合法——那是 **工具** id），`activePanelId` = 首个 tool leaf 的 `activeTab`/`panelId`，`widthRatio` = tool 侧占比后 `clampDockWidthRatio`。
   - **树几何优先于 TabSurface.rightDock**（与现 restore「树是坞真源、map 不含 dock」一致）。TabSurface 仅在无 unit 时作 fallback。
3. 无 unit → 保持步骤 1 或 `createDefaultDock()`。

然后 **strip tool 叶**：

- 先序找 `panelId !== 'chat'` 的叶。
- 其父为 branch → promote 兄弟（chat 侧或已 strip 的子树）。与现 `removeNodeFromTree` / 兄弟提升同构，但本函数内做纯结构删除，不调用会写 store 的路径。
- 孤儿 tool（`tool.sessionId` 对不上任何已放置 chat session）：直接丢掉，不为它 mint 会话 tab。
- 垂直/水平 **会话** 分屏拓扑保留（只删 tool 叶并 promote）。例：`H(H(chatA, toolA), H(chatB, toolB))` → `H(chatA, chatB)`，各 tab.dock 已带上。

**S4 多会话分屏**

S1 已按叶绑定各放一个 tab。S3 只删 tool。`V(chatA, chatB)` 无 tool → 原样，各叶一 tab。

**S5 去重（I1，迁移内完成）**

先序扫描所有 tab：

- 真实 `sessionId` 第二次出现 → 从后出现的叶 `tabs` 里删掉该 tab（保留先序第一次）。
- 删后若叶 `tabs.length === 0` → 该叶记入待 prune。
- draft 哨兵若撞车（不应发生）→ 后出现者 `mintDraftSessionId(新 tabId)` 或直接换成新 `createDraftTab()`。

**S6 空 tabs / 无 chat 叶**

- 仍空的 chat 叶：塞一个 `createDraftTab()`（单叶未绑定 + 无 openTabs 的典型路径）。
- 若 S2 已给该叶 extras，不要先塞 draft 再追加——空叶在 S2 前保持空，S2 填完仍空才 S6 mint draft。
- prune：`tabs.length === 0` 的叶（去重造成）提升兄弟；若根被删光 → 失败回退等价物 `createDefaultTree()`。
- strip 之后 **零 chat 叶**（tool-only 旧树）→ 失败回退。

**S7 收尾**

- 每叶：`activeTabId` 校正到 tabs 内。优先「原 `leaf.sessionId` 对应 tab」，否则 `tabs[0]`。
- 每 tab：补 `dock`；`panelId` 强制 `'chat'`；删除叶级 `sessionId` / `activeTab`。
- `tree.version = 3`。
- 返回 `{ ok: true, tree, didMigrate }`。

### 3.4 调用方伪代码（persist / hydrate）

`layoutTreeStore.onRehydrateStorage`：

```
if (!readRestoreLastWorkspaceFlag()) {
  applyCleanColdStartOnState(state); // createDefaultTree()
  return;
}
const result = migrateToLeafOwnedTabs({
  tree: state.tree,
  openTabsMap: loadLegacyOpenTabsMap(),
  activeLeafId: state.activeLeafId,
  resolveMeta: (id) => sessionTitleFolder(id),
});
const tree = result.tree;
const verdict = validateRestorableLayoutTree(tree);
if (!result.ok || !verdict.ok) {
  applyCleanColdStartOnState(state);
  return;
}
state.tree = tree;
state.activeLeafId = resolveActiveLeaf(tree, state.activeLeafId);
// 清 past/future/drag
```

`hydrateWorkspaceShell`：restore 路径 **停止** `migrateFromOpenTabsMap` + `syncShellDocksFromTree` + `ensureAdapterShape` 往树上投影。树在 rehydrate 时已是 v3。shell 只 `setShellReady(true)`；openTabs 写源收缩见维 03。

`applyCleanColdStartOnState` / `applySafeCleanColdStart`：`createDefaultTree()`（单叶 + draft tab）。维 03 删 `resetToCleanDraft` 对 `openTabs=[]` 的依赖。

### 3.5 失败回退

返回 `{ ok: false, tree: createDefaultTree(), reason: 'unrecoverable' }` 的条件：

- 输入无法当成二叉树（S0）。
- 抛异常（try/catch 包整函数）。
- strip 后零 chat 叶且无法从 openTabs 单独重建（本维 **不**用「无树、仅 map」去发明多分屏；无树 = clean。有 map 无树属 restore 树 missing，走 clean，与现「缺树 → missing-tree → clean」一致）。

**不**当失败、在迁移内归一的：

- 空 tabs、重复真实 sessionId、残留 tool 叶、全局 `PENDING_DRAFT`、缺 dock 字段。

回退树不变量：`root.type==='leaf'`，`tabs.length===1`，`isDraftSessionId(tabs[0].sessionId)`，`dock.collapsed===true`，`version===3`。

## 4. `validateRestorableLayoutTree` 新规则

只校验 **v3 运行期形状**。v2 persist 必须先 migrate。不要用本函数直接判 v2。

### 4.1 结构（`isLayoutNodeStructurallyValid`）

叶：

- `type==='leaf'`，`id` 非空字符串
- `panelId === 'chat'`（不是任意 string）
- `tabs` 是非空数组
- 每个 tab：对象，`tabId`/`sessionId`/`title`/`workspaceKey` 为非空字符串，`dock` 为对象且含 `collapsed: boolean`、`openPanelIds: array`、`widthRatio: finite number`（`activePanelId` 允许 `string | null`）
- `activeTabId` 为字符串（是否 ∈ tabs 在下一层语义检查）
- **不得**把 `tabs[0]` 为 string 判为合法（那是 v2，应被 migrate 吃掉；若仍出现 = malformed）

枝：与现码相同（direction、有限 splitRatio、正好 2 子、递归）。

### 4.2 语义（`validateRestorableLayoutTree`）

| 顺序 | 失败 reason | 条件 |
|---|---|---|
| 1 | `missing-tree` | `tree` 空或无 root |
| 2 | `malformed-structure` | 结构守卫失败 |
| 3 | `no-chat-leaf` | 先序零叶（理论上结构合法的空 branch 不存在；防御） |
| 4 | `tool-leaf-present` | 任一叶 `panelId !== 'chat'`（I5） |
| 5 | `empty-tabs` | 任一叶 `tabs.length < 1`（I2） |
| 6 | `active-tab-missing` | `activeTabId` 不是该叶某 `tab.tabId` |
| 7 | `illegal-global-draft` | 任一 `tab.sessionId === PENDING_DRAFT_SESSION_ID` |
| 8 | `duplicate-session-binding` | 任一 **真实** `sessionId` 出现在两个 tab（I1） |
| 9 | `duplicate-tab-id` | `tabId` 全树重复 |

通过：`{ ok: true, chatCount, multiUnit: chatCount > 1 }`。`chatCount` = chat **叶**数（不是 tab 数）。单叶三 tab → `chatCount=1`, `multiUnit=false`。

### 4.3 删除的旧规则

| 旧 reason | 处置 |
|---|---|
| `multi-unit-unbound-chat` | **删除**。新模型下多叶可以全是 draft tab（I2）。未绑定不再非法。 |
| `orphan-tool-session` | **删除**。合法树无 tool 叶；残留 tool 走 `tool-leaf-present`。 |

`duplicate-session-binding` **保留**，但比较键从 `leaf.sessionId` 改为 `tab.sessionId`（仅真实 id）。两个叶各有一个 draft **不算**重复。

### 4.4 与 migrate 的分工

migrate 负责把脏 v2/v3 **变成**应能通过本函数的树，或回退。validate 是 restore 第二道门（手改 localStorage / 写路径 bug）。migrate 之后仍失败 → clean，不再二次猜测。

运行期写路径 **禁止**调用 migrate 当日常纠偏。命令守 I1–I6。`dedupeDuplicateSessionChatLeaves` 仅 persist 损坏兜底（维 02 改写成扫 `tab.sessionId`，或直接删掉改调 `findDuplicateRealSessionIds` + 失败则 clean）。

### 4.5 persist 写出

- `partialize` 仍只写 `tree + activeLeafId + toolColumnCollapsed`。
- 写出的 `tree.version` 必须为 3；叶不得含 `sessionId`/`activeTab`/string tabs。
- **不在** `partialize` 里抛错。坏树若被写出，下次 restore 的 migrate+validate 回退。
- shell **停写**标签列表作为布局真源（维 03）。`OPEN_SESSION_TABS_KEY` 在迁移窗口仍可读；迁完后的运行期不读。本维不删该 key 的历史文件。

### 6.2 迁移：重复 `sessionId`

输入：`H(chatA.sessionId=s1, chatB.sessionId=s1)`，无 tool，openTabs 空。

期望：一叶保留 s1 的一个 tab（先序 A）；B 被 prune（空 tabs）；树变成单叶或 promote 后的单节点；`findDuplicateRealSessionIds` 为空。不回退成全新 draft（这是可归一损坏，不是 unrecoverable）。

### 6.3 迁移：空 tabs

输入：单 chat 叶，`tabs=[]`，`activeTab='chat'`，无 `sessionId`。

期望：该叶 `tabs=[draft]`，不 throw。旧 H4 行为的 v3 等价物。

输入：单 chat 叶，`tabs=['chat']`，无 `sessionId`（默认树 persist）。

期望：**不要**生成 `sessionId==='chat'` 的 tab；生成一个 draft tab。`'chat'` 是 panelId。

### 6.4 迁移：带 `H(chat, tool)` 的旧树

输入：

```
H(
  H(chatA sess=s1, toolA panelId=terminal tabs=['terminal'] sess=s1) split=0.62,
  chatB sess=s2
)
openTabsMap: { '对话': ['s1','s2'] }
```

期望：

- 拓扑 `H(chatA, chatB)`（会话分屏保留，tool 叶消失）
- A.tabs=`[tab s1]`，B.tabs=`[tab s2]`
- s1.dock：`collapsed===false`，`openPanelIds` 含 `'terminal'`，`activePanelId==='terminal'`，`widthRatio` 来自 `1-0.62` 再 clamp
- s2.dock：默认折叠
- `listChatLeaves.length===2`；先序无 `panelId!=='chat'`
- `version===3`；叶上无 `sessionId`

再 validate：`ok===true`，`multiUnit===true`。

### 6.5 迁移：openTabs 多出的 session 并入活动叶

输入：单叶 `sessionId=s1`；map=`{ '对话': ['s1','s2','s3'] }`。

期望：该叶 tabs 的真实 id 集合为 `{s1,s2,s3}`；s1 在前（绑定优先），s2/s3 追加；不新建叶。

输入：两叶 A=s1、B=s2，`activeLeafId=B`；map 含 s1,s2,s3。

期望：s3 只进入 B；A 仍只有 s1。

### 6.6 迁移：tool-only / 损坏 → 回退

| 输入 | 期望 |
|---|---|
| 根为 `terminal` 叶 | `{ ok:false }` 且树 = `createDefaultTree()` |
| `children.length===1` 的 branch | 同上 |
| `tree=null` | 同上 |
| v2 叶与 v3 叶混在一棵树 | 同上 |

回退树通过 validate；含恰好一个 draft tab。

### 6.7 迁移：幂等 v3

把 6.4 输出再喂入 migrate：结构等价（允许新 mint 的 draft tabId 稳定——v3 已有真实 tab 则 **不得**重铸 tabId/sessionId/dock）。`didMigrate===false` 或仅归一化无关字段。

### 6.8 迁移：全局哨兵叶

输入：chat 叶 `sessionId='__pending_draft__'`。

期望：该叶一个 draft tab，`sessionId` 带 `tabId` 后缀，不等于全局哨兵。validate 不得报 `illegal-global-draft`。

### 6.9 validate 本身

| 树 | reason |
|---|---|
| `createDefaultTree()` | ok |
| 6.4 输出 | ok，`chatCount=2` |
| 两叶 tabs 都是 draft（不同哨兵） | ok（旧 `multi-unit-unbound-chat` **不得**再失败） |
| 两叶同一真实 s1 | `duplicate-session-binding` |

| tab.sessionId 精确 `'__pending_draft__'` | `illegal-global-draft` |
| `activeTabId` 指向已删 tab | `active-tab-missing` |
| v2 形状未 migrate 直接 validate | `malformed-structure`（string tabs） |

### 6.10 I1 扫描

`listRealSessionIds` 不含任何 draft。两叶各一 draft + 一叶持 s1 → 真实集合 `{s1}`，无 duplicate。

## 10. 上报（总案缺口 / 歧义）——不改 I1–I6

1. **草稿哨兵字面量未钉死**。总案只写「该叶 draft 哨兵」「禁止全局单例」。本维钉为 `__pending_draft__:${tabId}`（per-tab，因同叶可多个 draft）。若主控要改成 `__pending_draft__:${leafId}`，同叶多 draft 会撞 I1 扫描键——不要改回 leaf 级。
2. **session store 全局 `PENDING_DRAFT` 与树上 per-tab 哨兵的映射**总案未写。本维禁止全局哨兵入 tab；活动 draft tab → `enterDraftMode` 仍写全局哨兵给 composer。维 03 必须接这条，否则「两叶两个 +」仍会抢画面。
3. **`TabSurface` / `openTabs` 并不 persist**。磁盘上只有 `OPEN_SESSION_TABS_KEY`（folder→id[]）和树。总案「输入 openTabs」在冷启动要读 map + 树。本维签名同时收两者。
