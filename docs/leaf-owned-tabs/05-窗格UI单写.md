> **战役**：`docs/leaf-owned-tabs/`
> **总案**：`00-总方案.md`（口径权威）
> **本维文件域**：`PaneHeader.tsx`、`TreeLeafPanel.tsx`、`BinaryTreeWorkspace.tsx`、`LeafToolTabStrip.tsx`

## 0. 一句话

每个 chat 叶的条带、高亮、画面会话、工具抽屉头，都只读 **本叶** `leaf.tabs` / `leaf.activeTabId`；点 / 建 / 关 / 分屏只调维 03 命令。禁止再投影 `openTabs`，禁止再写 `leaf.sessionId`，禁止用全局 `activeTabId` / `activeSessionId` 给邻叶「帮忙高亮」。

## 1. 现状双写（必须拆掉）

现码把「条带成员 / 高亮 / 画面会话 / 叶绑定」拆成四条轨，点一次写多次。

### 1.1 `PaneHeader.handleTabClick`（`PaneHeader.tsx:100-114`）

一次点击顺序写：

1. `setActiveLeaf(leaf.id)`
2. `shell.activateTab(tab.tabId)`（**全局** `openTabs` 的 tabId，无 leafId）
3. `session.setActiveSessionId(tab.sessionId)` 或 `enterDraftMode`
4. `tree.setLeafSessionId(leaf.id, tab.sessionId | undefined)`
5. `bindActiveChatLeafSession(tab.sessionId)`（可能偷绑别的未绑定叶）

违反总案 I3 / I6。邻叶的 `tabsForUnit` 还会拿全局 `activeTabId` 重新投影，两叶抢同一高亮。

### 1.2 `visibleTabs` 走投影（`PaneHeader.tsx:58-64`）

```ts
const raw = tabsForUnit(openTabs, { leafId, sessionId: leaf.sessionId }, allUnits, activeTabId, '');
return raw.filter((t) => !isPendingDraft(t.sessionId) && t.sessionId !== '');
```

依赖 `openTabs` + `leaf.sessionId` + 全局 `activeTabId`。草稿被滤掉。总案效果 5：草稿是该叶真 tab，必须画出来。

`isSingleChatUnit` 已 import 未用，一并删。

### 1.3 `isSelected` 三条件 OR（`PaneHeader.tsx:181, 208-210`）

```ts
const currentSid = (leaf.sessionId || activeSessionId || '').trim();
const isSelected =
  tab.tabId === activeTabId ||  // 全局 shell
  (Boolean(tab.sessionId) && (tab.sessionId === currentSid || tab.sessionId === leaf.sessionId));
```

两叶只要 `sessionId` 对上全局 active，就会**同时**亮。验收「两叶各自高亮自己的 active tab」在这套 OR 下不可能成立。

### 1.4 `sessionForPanel` 回落全局（`TreeLeafPanel.tsx:96-103`）

```ts
const sessionForPanel =
  inDraft && isActive ? activeSessionId : leaf.sessionId || activeSessionId;
```

非活动叶被 `|| activeSessionId` 拖去显示活动叶的会话；活动叶草稿还靠全局 `__pending_draft__` 抢画面。ChatCard / `UnitChromeActions` / `openToolInSession` / `data-session-id` 全吃这个值。

### 1.5 关 tab 摘 unit + 后切 active（`PaneHeader.tsx:117-127` + `workspaceShellStore.closeTab`）

`handleTabClose` 先打 `leavingTabId`，**200ms 后**才 `closeTab(tabId)`。`closeTab` 走 `removeSessionUnitFromTree`（关 tab = 拆 conversation unit），内容区在命令落地前仍钉在被关 tab 上，命令落地后整叶可能被摘掉 → 闪白。JS 定时 200ms 与 CSS 离场 220ms 还不一致。

### 1.6 侧栏「分屏打开」双绑（`useSidebarContextMenu.ts:27-76`）

`openSessionInChatSplit`：

1. 已有 `findChatLeafBySessionId`（读 **`leaf.sessionId`**）→ `openOrFocusSession`
2. 否则：`setLeafSessionId(target, shellSid)` 预绑源叶，`splitLeaf` 出新叶，再 `setLeafSessionId(newLeaf, sid)`，最后 `openOrFocusSession` + 日常 `dedupe`

这就是总案点名的「双绑再 dedupe」。本维禁止保留。

### 1.7 工具条挂在「树上第二叶」

- `flattenTree(..., { collapsedDomain: 'tool' })` 仍把 tool 叶当树节点（`BinaryTreeWorkspace.tsx:161-166`）
- `TreeLeafPanel` 非 chat 分支渲染 `LeafToolTabStrip leaf={leaf}`，把 **tool 叶的 `leaf.tabs: string[]`** 当工具标签（`TreeLeafPanel.tsx:224-226`）
- canvas 上另有一颗绝对定位 `#topQuickDockBtn`（`BinaryTreeWorkspace.tsx:268-293`，`top: 41px; right: 10px`），与 `LeafToolTabStrip` 内再一颗同 id 按钮并存
- `UnitChromeActions.handleToggleRightDock` / canvas 按钮都 `updateRightDock` + **`applyDockToTree`**（改树拓扑）

维 04 把坞收进 `SessionTab.dock` 后，本维必须把工具条 DOM 挪到本叶抽屉头，不再认第二片 leaf。

## 3. `PaneHeader` 三手势：最终只调哪些函数

> 胶囊视觉规格不动：36px 条、`.tabItem` 圆角 6、激活白底+微阴影、Smart Pinning、横向滚轮、`tabSlideIn` / `.tabItemLeaving` 的 220ms 曲线。只换写路径。

### 3.1 `handleTabClick`

**最终只调：`activateTab`。**

```
activateTab(leaf.id, tab.tabId)
```

删除：`setActiveLeaf`、`shell.activateTab(tab.tabId)`、`setActiveSessionId`、`enterDraftMode`、`setLeafSessionId`、`bindActiveChatLeafSession`。

### 3.2 `handleNewTab`（加号、pinned 加号、条带空白双击共用）

**最终只调：`addTab`。**

```
addTab(leaf.id)
```

删除：`setActiveLeaf`、`getCompositionRoot().shell.openNewDraftTab('')`、`useWorkspaceShellStore.getState().openNewDraftTab('')`。

`addTab` 语义（总案）：该叶 push 一个 **本叶独立** draft tab 并激活；邻叶 `tabs` 不动。禁止再走全局唯一 `__pending_draft__`。

### 3.3 `handleTabClose`（关闭钮、中键、`auxclick` 共用）

**最终只调：`activateTab`（可选，立即）+ `removeTab`（220ms 后）。**

算法（必须先切本叶 active 再动画，避免闪白）：

1. 在 **本叶** `leaf.tabs` 里找将关 `tab.tabId` 的下标。
2. **若它是 `leaf.activeTabId` 且 `tabs.length > 1`**：立刻
   `activateTab(leaf.id, neighborTabId)`
   邻居规则与维 02/03 `removeTab` 一致：优先左邻，否则右邻。内容区立刻切到邻居 session，条带高亮立刻跟 `activeTabId`。
   **禁止**等动画结束再切 active——那 220ms 里 `sessionForPanel` 仍指向将删 tab，命令落地后会闪白/空欢迎面。
3. 本地 `setLeavingTabId(tab.tabId)`，走现有 `.tabItemLeaving`（220ms）。**定时器改 220ms**，与 `PaneHeader.module.css:112-117, 163-176` 对齐；现码 200ms 删掉。
4. 220ms 后只调
   `removeTab(leaf.id, tab.tabId)`
   然后清 `leavingTabId`。此时该 tab 已不是 active，`removeTab` 只 splice + 空则 prune，不会再切一次画面。
5. **最后一枚 tab**：没有邻居可切。仍先离场 220ms（条带收口），再 `removeTab`（空叶 prune，根则退化成带 draft 的单叶，I2）。离场期间内容仍显示该 tab 的 session，不先清空。

`removeTab` 负责：本叶内退 active、空则 prune、杀该 session PTY。UI 禁止再调 `closeTab` / `removeSessionUnitFromTree`。

中键路径继续复用 `handleTabClose`，不另写一套命令。

保留：`sessionsById` 只用于 **读标题**（`session?.title \|\| tab.title \|\| '新对话'`），不是写源。`useSessionTabDrag().startSessionDrag` 留给维 06。

## 4. 只读契约（三条硬等式）

### 4.1 `visibleTabs = leaf.tabs`，删除 `tabsForUnit`

```
visibleTabs = leaf.tabs
```

- 类型：维 01 的 `SessionTab[]`，**不是** `string[]`，也不是从 `openTabs` 投影出来的 `TabSurface[]`。
- **包含草稿**。禁止 `filter(isPendingDraft)`。每叶 `+` 出来的 draft 必须在该叶条带可见。
- 禁止再读 `openTabs`、`listChatUnits`、`leaf.sessionId`。
- `key={tab.tabId}` 不变。

`unitTabPlacement.ts` 的生产引用本维清零（当前唯一生产引用就是 `PaneHeader.tsx:22,62`）。文件删除归维 07。

### 4.2 `isSelected = tab.tabId === leaf.activeTabId`

**禁止**任何 OR：

- `tab.tabId === shell.activeTabId`
- `tab.sessionId === leaf.sessionId`
- `tab.sessionId === activeSessionId`
- `tab.sessionId === currentSid`（`currentSid = leaf.sessionId \|\| activeSessionId`）

`aria-selected={tab.tabId === leaf.activeTabId}`。
两叶 A=`s1` 激活、B=`s2` 激活时，A 条只亮 s1 胶囊，B 条只亮 s2 胶囊，即使窗口级 `activeSessionId` 是 s1。

### 4.3 `sessionForPanel = 本叶 active tab 的 sessionId`

```
const activeTab = leaf.tabs.find((t) => t.tabId === leaf.activeTabId)
const sessionForPanel = activeTab?.sessionId   // 真会话或本叶 draft 哨兵
```

**禁止**：

```
leaf.sessionId || activeSessionId
inDraft && isActive ? activeSessionId : leaf.sessionId || activeSessionId
```

下游只吃 `sessionForPanel`，不再各自回落：

| 消费点 | 现码 | 改后 |
|---|---|---|
| `UnitChromeActions activeSessionId=` | `sessionForPanel`（但值是错的） | 同一 props，值改为上式 |
| `ViewRenderContext.sessionId` | 同上 | 同上 |

| 叶根 `data-session-id` | `leaf.sessionId`（`TreeLeafPanel.tsx:202`） | `sessionForPanel`（e2e 仍靠此探针） |

`leaf.sessionId` 字段维 01 删除后，本维不得再写 `leaf.sessionId` 任何读。

草稿：本叶 `activeTab.sessionId` 是该叶 draft 哨兵 → ChatCard 画该叶空白欢迎面；邻叶继续画自己的 active session。禁止再用全局 `isPendingDraft(activeSessionId) && isActive` 劫持活动叶。

## 6. 工具条：从「第二叶的头」改为抽屉头（配合维 04）

### 6.1 DOM 归属

维 04 契约（总案 §5）：chat 叶 `.leafBody` 内 `flex` 行 = 对话流 +（坞未折叠时）内部 resizer + 抽屉。抽屉头复用 `LeafToolTabStrip` **视觉**，但节点在 `.leafBody` 抽屉列里，**不是**第二片绝对定位 leaf。

本维装配：

```
.leaf
  PaneHeader                    ← 会话胶囊，读 leaf.tabs / activeTabId
  .leafBody  (flex row)
    .chatColumn
      UnitChromeActions         ← sessionId = sessionForPanel
      SlotOutlet chat
    [.resizer + .drawerColumn]  ← 仅当 activeTab.dock.collapsed === false
      LeafToolTabStrip          ← 抽屉头，读 dock.openPanelIds / activePanelId
      SlotOutlet tool           ← dock.activePanelId
```

内部 resizer 几何归维 04；本维负责 **把 `LeafToolTabStrip` 从 tool 叶 chrome 拆下来，改挂抽屉头**，并改它的读写源。

抽屉头只读 **本叶 active `SessionTab.dock`**：

```

activeTab   = dock.activePanelId
sessionId   = activeTab.sessionId
```

写路径只调维 03/04：

| 抽屉手势 | 函数 |

| 点工具 tab | `updateTabDock(tabId, { activePanelId })` |
| 关工具 tab | `updateTabDock` 从 `openPanelIds` 去掉；空则 `collapsed: true` |
| `+` 开工具 | `openToolInSession(sessionId, panelId)`（维 04：只 `updateTabDock`） |
| 折叠坞 | `updateTabDock(tabId, { collapsed: true })` |

删除抽屉头内对 `setActiveTab(leafId, panelId)` / `removeTabFromLeaf(leafId, panelId)` / `openTabs.find` 取 `rightDock` 的路径。`tabModeEnabled` 只决定抽屉内「单条多 tab vs 垂直堆叠」，禁止重建会话树（总案 §5）。

关闭工具 tab 已有「先切邻再 220ms 离场」——保留，但切的是 **dock.activePanelId**，不是 `leaf.activeTabId`。

## 7. 侧栏「分屏打开」

文件：`useSidebarContextMenu.ts` 的 `openSessionInChatSplit`，菜单动作 `open-split`。

查找「session 已在某叶」必须扫 **`leaf.tabs[].sessionId`**。现 `findChatLeafBySessionId` 读 `leaf.sessionId`（`conversationUnit.ts:55`），维 02 必须改实现；本维只调改后的查找（或维 03 的 `openSession` 内部查找），禁止本维再写一套 `leaf.sessionId` 扫描。

### 7.1 已在某叶 → 聚焦

```
openSession(sessionId, opts)
```

（内部 `activateTab(hit.leafId, hit.tabId)`。）不 `splitLeaf`，不 mint 第二份 tab（I1）。

`open-current`（当前窗打开）同样只调 `openSession`，不得再走 `bindActiveChatLeafSession`。

### 7.2 未打开，且用户明确要 split → `splitTab` 新叶

禁止现码：

```
setLeafSessionId(target, shellSid)   // 预绑源叶
splitLeaf(target, 'horizontal', 'chat', 'after', 0.5)
setLeafSessionId(newLeaf, sid)
openOrFocusSession(sid)
dedupeDuplicateSessionChatLeaves
```

目标效果：源叶 `tabs` **一个不增**；旁边新叶 `tabs = [该 session 的新 SessionTab]`，并激活新叶。不是「先塞进活动叶再纠偏」。

命令拼法（只调维 03，同一同步栈，中间不 render）：

**优先（上报维 03 提供原子入口，避免 UI 拼两步）**：

```
openSession(sessionId, { split: 'right' })
// 或 splitOpenSession(sessionId, activeChatLeafId, 'right')
```

语义：mint `SessionTab`，对活动 chat 叶做 `splitTab` 式切分，新叶 `tabs=[该tab]`，源叶原 tabs 不变。

**若维 03 坚持 `splitTab` 只接受已有 tabId**，则门面内部（不是 UI）允许：先把 tab mint 到源叶再立刻 `splitTab(src, tabId, src, 'right')` 拿走。UI 仍然只看到一次 `openSession(..., { split })` / `splitTab` 调用，**看不到** `setLeafSessionId`。

region：侧栏「拆分视图」现为水平 after → `region: 'right'`（或维 02 的 `'after'` 映射）。禁止 `region: 'center'`（那是 `moveTab`）。

无 chat 叶时：退化为 `openSession(sessionId)`（单叶），不要为了 split 去 `setLeafSessionId`。
