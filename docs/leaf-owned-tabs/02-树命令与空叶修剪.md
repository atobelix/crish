# 02 — 树命令与空叶修剪

> **战役**：`docs/leaf-owned-tabs/`
> **口径**：采用总案 `00-总方案.md` §2–§4、§I1–I6。本维只规定 **纯函数树命令 + store 薄封装**。
> **文件域**：`layoutTreeInsert.ts` / `layoutTreeMoveRemove.ts` / `layoutTreeTransform.ts` / `conversationUnit.ts` / `layoutTreeStore.ts` / `layoutTreeStoreTypes.ts`（`operations.ts` 仅 re-export）。
> **依赖**：维 01（`SessionTab` / `LayoutLeaf.tabs` / `activeTabId` / 每叶独立 draft 工厂 / `createLeaf` 签名）。维 01 未落地前本维不得改 `apps/`。
> **对照**：`reference/chat-composer-component/js/popovers.js` 1145–1272（`addTab` / `removeTab` / `executeSplit` / `_prune` / `_split`）。对齐所有权与空叶提升，**禁止**抄 `cloneNode`、就地 `Object.assign`、JSON 深拷贝变异节点。
> **非目标**：Shell 命令门面、PTY、`setActiveSessionId` / `enterDraftMode`（维 03）；坞 / tool 叶下树（维 04）；PaneHeader UI（维 05）；拖拽手势与 overlay（维 06）。

---

## 0. 结论

1. 会话手势的**树写路径**收敛为五个纯函数：`activateTabInTree` / `addTab` / `removeTab` / `moveTab` / `splitTab`。空叶不单独对 UI 暴露，由 `removeTab` / `moveTab` / `splitTab` 末尾调用 `pruneEmptyLeaves`。
2. 失败一律 **no-op 并返回原 `tree` 引用**（`result === tree`）。不 throw。I1 重复 `sessionId`（非本 tab）在**函数入口**拒绝。
3. 空叶 prune 对齐 Demo `_prune` 的**语义**：空 `tabs` 的 leaf 被兄弟提升替代父 branch。实现必须不可变（`removeBranch` / `removeLeafFromTree`），禁止 Demo 的 `Object.assign` 就地覆盖。根被删光（或根变成空叶）时 **新建**带一个 draft tab 的单叶，不保留空根。
4. **禁止**第二套 `remainingTab` 填源叶。源叶剩下的就是 `splice` 之后的 `src.tabs`；空则 prune。现码 `sessionTabDropCommit.ts` 三处从全局 `openTabs` 抓另一个 session 写回 `setLeafSessionId` 是死轨，维 06 删除，本维不设计替代。
5. `setLeafSessionId` 从 operations 与 store **删除**，不再是会话身份写端。身份只在 `SessionTab.sessionId`。

## 1. 类型前提（维 01，本维当已成立）

本维不改 `types.ts` 形状，只按总案使用：

```ts
interface SessionTab {
  tabId: string;
  sessionId: string;       // 真会话，或该 tab 自己的 draft 哨兵（唯一，禁止全局单例抢画面）
  title: string;
  workspaceKey: string;
  dock: RightToolDockState;
}

interface LayoutLeaf {
  type: 'leaf';
  id: string;
  panelId: 'chat';
  tabs: SessionTab[];      // 权威。不再是 panelId 字符串
  activeTabId: string;     // 必属于 tabs
}
```

维 01 必须提供（本维直接 import，不另造工厂）：

| 符号 | 用途 |
|---|---|
| `mintDraftTab(workspaceKey?: string): SessionTab` | `addTab` / 根删光兜底。每个 draft 的 `sessionId` **唯一**（例如 `__pending_draft__:${tabId}`），这样 I1 对 draft 同样成立，多叶可同时有草稿 |
| `isDraftSessionId(id: string): boolean` | I1 扫描仍计入（唯一性），但维 03 决定 `enterDraftMode` vs `setActiveSessionId` |
| `createLeaf` / `createDefaultTree` | 产出 `panelId:'chat'` + 至少一个 `SessionTab` + 合法 `activeTabId` |
| `defaultDock(): RightToolDockState` | 新 tab 的坞初值（折叠）。本维不改坞内容 |

旧字段：

- `LayoutLeaf.sessionId` — **删除**（维 01）。本维命令不得再读写。
- `LayoutLeaf.activeTab` — 重命名为 `activeTabId`（维 01）。下文一律用 `activeTabId`。
- `LayoutLeaf.tabs: string[]` — 改为 `SessionTab[]`。旧 `addTabToLeaf(leafId, 'files')` 语义作废。

查找约定（先序，与现 `collectLeaves` / `findNodeById` 一致）：

```ts
function findLeaf(root: LayoutNode, leafId: string): LayoutLeaf | null
function findTabOnLeaf(leaf: LayoutLeaf, tabId: string): { tab: SessionTab; index: number } | null
function findTabLocation(root: LayoutNode, tabId: string): { leaf: LayoutLeaf; tab: SessionTab; index: number } | null
function findLeafBySessionId(root: LayoutNode, sessionId: string): { leaf: LayoutLeaf; tab: SessionTab; index: number } | null
```

`findLeafBySessionId` 扫 `leaf.tabs[].sessionId`，**不再**读 `leaf.sessionId`。同一 `sessionId` 若出现两次（损坏树），返回先序第一个；日常写路径靠入口 I1 拒绝，不靠这个函数纠偏。

## 2. 不变量在入口如何守（I1–I4）

写函数**入口**先判，失败返回原 `tree`。不在函数中段「修一下再继续」。I5（无 tool 叶）由维 01 迁移 + 本维工厂只造 chat 叶保证；I6（UI 不直写）由维 05/03 守，本维负责把旧写端删掉。

### 2.1 共享守卫

```ts
/** 非空 sessionId 是否已属于树上某个 tab（可排除正在搬运的 tabId）。 */
function sessionIdTaken(
  root: LayoutNode,
  sessionId: string,
  exceptTabId?: string
): boolean {
  if (!sessionId) return false;
  const hit = findLeafBySessionId(root, sessionId);
  if (!hit) return false;
  return hit.tab.tabId !== exceptTabId;
}

function requireChatLeaf(root: LayoutNode, leafId: string): LayoutLeaf | null {
  const n = findNodeById(root, leafId);
  if (!n || n.type !== 'leaf') return null;
  return n;
}
```

| 不变量 | 入口动作 |
|---|---|
| **I1** 一个 `sessionId` 全树至多一个 tab | `addTab` / `insertTab`：`sessionIdTaken(root, tab.sessionId)` 为真 → 原样返回。`moveTab` / `splitTab`：用 `exceptTabId = 正在搬的 tabId`，若**其它** tab 已占同一 `sessionId` → 原样返回（损坏树，拒绝再复制一份）。**不**在树层把「重复」改写成 `activateTab`——那是维 03 `openSession` 的语义。树层误调用必须暴露为 no-op，禁止静默聚焦掩盖 bug。 |
| **I2** `tabs.length >= 1` 且 `activeTabId ∈ tabs` | 任何更新叶的路径：写回前断言；空则走 prune，不留下空叶。根删光 → `createFallbackDraftTree`。`activateTabInTree`：`tabId` 不在该叶 `tabs` → no-op。 |
| **I3** 只改目标叶的 `tabs` | `activateTabInTree` / `addTab` / `removeTab` 只 `replaceNode` 那一个 leaf。`moveTab` / `splitTab` 只动 src + dst（及 dst 旁新建的那一叶）。其它叶的 `tabs` 引用保持不变。 |
| **I4** 切分/移动 = **拿走对象**，源空 prune | `moveTab` / `splitTab` 从 `src.tabs` `splice` 出**同一个** `SessionTab` 对象（浅拷贝叶数组，不 `clone` tab，不 mint 新 tab 填源）。源 `tabs.length === 0` 则 `pruneEmptyLeaves`。**禁止**读 `openTabs` / 别的叶 / 全局列表给源叶补一个 session。 |

I1 对 draft 同样扫。前提是维 01 的 `mintDraftTab` 每次给出新的 `sessionId`；若维 01 仍用全局唯一 `__pending_draft__`，I1 会拒绝第二片叶的 `+`——那是维 01 必须消掉的缺口，本维不在命令里特判「draft 可重复」。

### 2.2 失败契约

- 找不到 leaf / tab / dest：返回原 `tree`。
- 入参非法（空字符串、`insertIdx` 非有限数）：返回原 `tree`。
- 几何会成环（`splitTab` 不把祖先塞进子孙；本命令只 split **leaf**，不会环）：返回原 `tree`。
- store 包装：`result === state.tree` 则 `return {}`，不推历史。

## 3. 命令（纯函数）

全部签名吃 `LayoutTree`、吐 `LayoutTree`。Store 再包一层历史 / `activeLeafId`。
命名：纯函数与 store action 同名时，纯函数放 operations 子模块；store 调纯函数。`activateTab` 的树部分叫 `activateTabInTree`，避免和维 03 的壳命令撞名。

### 3.1 `activateTabInTree` — 树部分

```ts
function activateTabInTree(
  tree: LayoutTree,
  leafId: string,
  tabId: string
): LayoutTree
```

**变换**

1. `requireChatLeaf`；失败 → 原树。
2. `tabId` 不在 `leaf.tabs` → 原树（I2）。
3. `leaf.activeTabId === tabId` → 原树。
4. `replaceNode` 为 `{ ...leaf, activeTabId: tabId }`。其它叶不动（I3）。

**守卫**：I1/I4 不适用（不插入、不搬对象）。I2/I3 如上。

**不做**：`setActiveLeaf`、`setActiveSessionId`、`enterDraftMode`。焦点叶与会话画面由 store / 维 03 接。现码 `setLeafActiveTab`（`layoutTreeTransform.ts:43-54`）改名为本函数，并把 `activeTab` 字段改为 `activeTabId`、`tabs.includes(tabId)` 改为按 `tab.tabId` 查找。

### 3.2 `addTab`

总案命令表是 `addTab(leafId)` = 该叶 push 一个 **新 draft** 并激活。纯函数层拆成两档：store / UI 的 `+` 只走 mint；维 03 `openSession` 把已有 `SessionTab` 推进活动叶时走 `insertTab`（不是再造一套所有权）。

```ts
function insertTab(
  tree: LayoutTree,
  leafId: string,
  tab: SessionTab,
  insertIdx?: number
): LayoutTree

function addTab(
  tree: LayoutTree,
  leafId: string,
  workspaceKey?: string
): LayoutTree {
  return insertTab(tree, leafId, mintDraftTab(workspaceKey));
}
```

**`insertTab` 变换**

1. leaf 不存在 → 原树。
2. 该叶已有 `tab.tabId` → 原树。
3. **I1**：`sessionIdTaken(root, tab.sessionId)` → 原树（拒绝双开）。不改写成激活。
4. `insertIdx` 缺省或越界 → 追加末尾；否则 `splice(insertIdx, 0, tab)`。
5. 新叶：`tabs` 含该对象，`activeTabId = tab.tabId`。邻叶不动（I3）。

**`addTab` 变换**：mint 新 draft（新 `tabId` + 新 draft `sessionId`）后 `insertTab`。邻叶的 draft / 真会话都不动。这是总案「每叶可独立 `+`」。

**不做**：不绑 `leaf.sessionId`；不读 `openTabs`；不把 panelId 字符串推进 `tabs`。

对齐 Demo `addTab(pid)`（`popovers.js:1145-1154`）：push 新 tab、`activeTabId = 新 tab`、rebuild。差别：Demo 就地 `push`；我们不可变替换该叶。Demo 无 I1（它允许 clone）；我们拒绝重复真会话。

### 3.3 `removeTab`

```ts
function removeTab(
  tree: LayoutTree,
  leafId: string,
  tabId: string
): LayoutTree
```

**变换**

1. leaf / tab 不在该叶 → 原树。
2. 从该叶 `tabs` 滤掉该 `tabId`（I3：只动这一叶）。
3. 若删的是 `activeTabId`：**仅在该叶内**退到左邻（见 §3.3.1）。其它叶的 `activeTabId` 不动。
4. 若 `newTabs.length === 0`：不写空叶，进入 `pruneEmptyLeaves`（可能走到根兜底）。
5. 否则 `replaceNode` 写回 `{ ...leaf, tabs: newTabs, activeTabId }`。`leaf.id` 不变。

**守卫**：I1 不适用（只删）。I2 由 prune / 兜底保证。I4 不适用。dock 跟 tab 走：删 tab 即丢该 tab 的 `dock`，不「提升」到邻 tab（总案验收：关中间「dock 不丢」指**没被关的 tab** 自己的 `dock` 还在）。

**不做**：不 `removeUnitBySessionId`；不杀 PTY（维 03 在调用前读出 `sessionId` 再杀）；不从全局列表给该叶补 tab。

对齐 Demo `removeTab` → `_rmTab` + `_prune`（`popovers.js:1156-1159, 1221-1234`）。差别见 §3.3.1 与 §4。

#### 3.3.1 左邻公式（锁死，供单测）

总案：「若删的是 active，邻居只在该叶内退（**优先左邻**）」。Demo `_rmTab` 用 `tabs[0]`（剩余第一项），**不采用**。现码 `removeTabFromLeaf` 用 `newTabs[last]`（`layoutTreeMoveRemove.ts:134-137`），**也不采用**。

```ts
const idx = leaf.tabs.findIndex((t) => t.tabId === tabId);
const newTabs = leaf.tabs.filter((t) => t.tabId !== tabId);
const newActiveId =
  leaf.activeTabId !== tabId
    ? leaf.activeTabId
    : newTabs[Math.max(0, idx - 1)]!.tabId;
```

| 删前 `tabs`（下标） | 关 | 原 active | 删后 `tabs` | 新 active |
|---|---|---|---|---|
| `[A, B, C]` | B | B | `[A, C]` | **A**（左邻） |
| `[A, B, C]` | A | A | `[B, C]` | **B**（无左邻 → 原右邻） |
| `[A, B, C]` | C | C | `[A, B]` | **B**（左邻） |
| `[A, B, C]` | B | A | `[A, C]` | **A**（未关 active，保持） |

单叶三 tab 关中间：叶还在、`leaf.id` 不变、两剩余 tab 的 `dock` 原样。

### 3.4 `moveTab`

```ts
function moveTab(
  tree: LayoutTree,
  srcLeafId: string,
  tabId: string,
  dstLeafId: string,
  insertIdx: number
): LayoutTree
```

对齐 Demo `executeSplit` 的 in-place / center / strip 两支（`popovers.js:1174-1198`），不可变版。

**同叶重排**（`srcLeafId === dstLeafId`）

1. tab 不在该叶 → 原树。
2. 从数组取出该对象，按 Demo 规则插回：先 `splice(fromIdx,1)`，再把 `insertIdx` 钳到 `[0, tabs.length]`（**取出之后**的长度），`<0` 或越界 → 末尾。
3. `activeTabId = tabId`。不 prune（长度不变）。

**跨叶**

1. src / dst 缺一、或 tab 不在 src → 原树。
2. **I1**：`sessionIdTaken(root, tab.sessionId, tabId)` → 原树。若 dst **已经**含这个 `tabId`（不应发生）→ 原树。
3. 从 src `splice` 出**该对象**（I4）。dst 在 `insertIdx` 钳制后插入同一对象，`dst.activeTabId = tabId`。
4. src 若仍有 tab：若搬走的是 src 的 active，src 按 §3.3.1 左邻；否则 src `activeTabId` 不变。
5. src 若空：`pruneEmptyLeaves`。dst 的 `id` 不变。禁止给 src 填任何「剩余会话」。

`insertIdx` 非法（`NaN` / 非有限）→ 原树。

### 3.5 `splitTab`

```ts
type SplitRegion = 'left' | 'right' | 'top' | 'bottom' | 'center';

function splitTab(
  tree: LayoutTree,
  srcLeafId: string,
  tabId: string,
  dstLeafId: string,
  region: SplitRegion,
  splitRatio?: number
): LayoutTree
```

对齐 Demo `executeSplit` 的 binary split 支 + `_split`（`popovers.js:1201-1207, 1248-1272`）。

**`region === 'center'`**：直接 `moveTab(tree, srcLeafId, tabId, dstLeafId, /* dest 末尾 */ dest.tabs.length)`。条内插入带下标的路径维 06 应**直接调 `moveTab`**，不要绕 `splitTab('center')` 丢 `insertIdx`。总案「region 为 center 则走 `moveTab`」在本函数内兜底，防止误用。

**边缘**

1. src 上无该 tab、dst 不是叶 → 原树。
2. **同叶且该叶只有这一 tab**：no-op 返回原树（保 `leaf.id`）。Demo 会 `_rmTab` 成空叶再 `_split` 再 `_prune`，净效果几乎是换新 leaf id；产品要稳定 id，锁 no-op。现码 `applyDrop` 已有这条（`layoutTreeTransform.ts:353-358`），保留。
3. **I1**：与 `moveTab` 相同，`exceptTabId = tabId`。
4. 从 src 拿走该 `SessionTab` 对象（I4）。不可变构造新叶：

```ts
const fresh: LayoutLeaf = {
  type: 'leaf',
  id: /* generateNodeId('leaf')，与 createLeaf 同一生成器 */,
  panelId: 'chat',
  tabs: [tab],          // 同一对象，不是 clone
  activeTabId: tab.tabId,
};
```

5. 用 `replaceNode(dstLeafId, createBranch(dir, first, second, ratio))` 把 **dst 叶**换成 branch。方向映射与现 `splitLeaf` / Demo `_split` 一致：

| region | `direction` | `first, second` |
|---|---|---|
| `right` | `horizontal` | `[dst, fresh]` |
| `left` | `horizontal` | `[fresh, dst]` |
| `bottom` | `vertical` | `[dst, fresh]` |
| `top` | `vertical` | `[fresh, dst]` |

`splitRatio` 默认 `0.5`，走现有 `clampSplitRatio`。

6. src 空则 `pruneEmptyLeaves`。dst 原 `tabs` 一字不改（I3）。新叶只含被搬走的那一个 tab。

**禁止**：`splitLeaf(..., newPanelId: string, newLeafSessionId?)` 那种「新叶 `tabs=[panelId]` + 叶级 `sessionId`」来冒充切分。`splitTab` 内部可以复用 `createBranch` + `replaceNode`，但新叶必须带 `SessionTab[]`。禁止 `removeTab` 之后再从全局抓 `remainingTab` 填 src。

Demo `_split` 对目标叶 `JSON.parse(JSON.stringify(node))` 深拷再改成 branch——我们禁止深拷，dst 叶对象只换位置（进 branch 的 child），`id` / `tabs` 保持。

## 4. 空叶 prune（对齐 Demo `_prune`，补根兜底）

### 4.1 Demo 在做什么

`popovers.js:1236-1246`：

```
_prune(node) {
  if (!node || node.type !== 'branch') return;
  this._prune(node.left);
  this._prune(node.right);
  let survivor = null;
  if (node.left.type === 'leaf' && !node.left.tabs.length) survivor = node.right;
  if (node.right.type === 'leaf' && !node.right.tabs.length) survivor = node.left;
  if (!survivor) return;
  for (const k of Object.keys(node)) delete node[k];
  Object.assign(node, JSON.parse(JSON.stringify(survivor)));
}
```

对齐点（采用）：

1. 只修剪 **`type==='leaf' && tabs.length===0`**，不拆有 tab 的叶。
2. 空叶的兄弟（叶或 branch）提升替代父 branch（flatten 一层）。
3. 后序：先处理子再处理自己，于是「两子都空」时先把一边提升，再由上层继续剪。
4. 在 `_rmTab` / 跨叶搬走之后调用，而不是 UI 自己判空。

不对齐（禁止抄）：

| Demo | 本维 |
|---|---|
| `delete` + `Object.assign` 就地覆盖节点（id/type 都变） | 不可变：`removeBranch(root, parent.id, keepIndex)`，与现 `removeLeafFromTree` 同构 |
| `JSON.parse(JSON.stringify(survivor))` 深拷 | 提升 **同一棵** survivor 子树引用（其内部已是新对象的话随命令走） |
| 根是 leaf 时 `_prune` 直接 return，空根可留下 | 总案 I2：根删光 → **新建**带 draft tab 的单叶 |
| 双空子时后一次赋值赢，可能把空叶 assign 到 branch 上再靠上层剪 | 循环删除空叶直到没有，或根兜底；不依赖变异顺序 |

### 4.2 `pruneEmptyLeaves`

```ts
function pruneEmptyLeaves(tree: LayoutTree): LayoutTree
```

算法（有限循环，守卫 32，与现 `dedupeDuplicateSessionChatLeaves` 同风格）：

1. 先序收集 `isLeaf && tabs.length === 0` 的 id。
2. 对每个仍存在的空叶：`removeLeafFromTree(tree, id)`。
3. `removeLeafFromTree` 在目标是 root 时返回 `null`（现 `removeNodeFromTree` 已如此，`layoutTreeMoveRemove.ts:95-96`）→ 视为根删光，立刻 `createFallbackDraftTree(tree.version)` 并结束。
4. 若循环后 `collectLeaves` 为空，或 root 是空叶：同样兜底。
5. 无空叶 → 返回当前树（若全程无改动，返回原引用）。

`removeTab` / `moveTab` / `splitTab` 在可能产生空叶的分支**必须**调用本函数，禁止调用方再手写一遍。

### 4.3 根删光：`createFallbackDraftTree`

```ts
function createFallbackDraftTree(version: number): LayoutTree {
  const tab = mintDraftTab();
  return { version, root: createLeaf(/* chat + [tab] + activeTabId=tab.tabId */) };
}
```

- 新 `leaf.id`（不保留已删根的 id）。单叶关到空是新画面，不是「同一叶 tabs=[]」。
- 恰好一个 draft tab，`activeTabId` 指向它（I2）。
- store 包装必须 `activeLeafId = 新叶 id`（`resolveActiveLeaf` 已能做到，只要新树里有叶）。
- 维 03 见到这棵兜底树时走 `enterDraftMode`，不要再 `ensureChatOnlyTree` / `resetToCleanDraft` 清掉别的状态——树已经是干净单叶。

现码 `removeTabFromLeaf` 在根是唯一叶且关掉最后 tab 时：`removeLeafFromTree` 返回 `null`，然后 `return result ?? tree`（`layoutTreeMoveRemove.ts:128-131`）→ **原树连 tab 都还在**。这是 bug，必须改成兜底 draft 叶，不能保空、也不能假装没关。

现码 `removeUnitBySessionId` 在 unit 占满整树时 `createLeaf('chat')`（`conversationUnit.ts:152-157`），tabs 仍是 `['chat']` 字符串且无 draft tab——本维删除该函数的写路径，根兜底统一走 `createFallbackDraftTree`。

### 5.2 `applyDrop` 改写后的分发

现码四条路径（leaf→split / leaf→merge / tab→split / tab→merge）外加跨域、unit-scope、同 session 再拆一份。I5 后树上只有 chat 叶，跨域 / `isUnitScopedDropAllowed` 在 `applyDrop` 内 **删除**（`dropDetection.ts` 的 unit-scope 由维 06/07 收）。

```ts
function applyDrop(tree: LayoutTree, source: TreeDragSource, zone: DropZone): LayoutTree {
  if (source.type !== 'tab') return tree;           // 会话拖只发 tab；整叶拖不走身份写
  const tabId = source.tabId;
  const src = source.leafId;
  const dst = zone.targetLeafId;

  if (zone.type === 'merge-tab') {
    const insertIdx = /* 由 zone.targetTabId 在 dst.tabs 中的下标换算；缺省末尾 */;
    return moveTab(tree, src, tabId, dst, insertIdx);
  }
  const region = zoneTypeToRegion(zone.type);       // split-left → 'left' 等
  if (!region) return tree;
  return splitTab(tree, src, tabId, dst, region);
}
```

- `TreeDragSource.panelId` 不再参与决策（恒为 chat）。维 01/06 可后删该字段。
- 同叶 + `merge-tab`：`moveTab` 同叶重排（有 `targetTabId`）或仅激活。
- 同叶 + 边缘 + 唯一 tab：`splitTab` 入口 no-op。
- **禁止**再 `removeTabFromLeaf` 后再 `splitLeaf(..., ownerForNewLeaf)`。新叶身份来自被搬走的 `SessionTab`，不是 `srcOwnerSessionId`。
- 旧「目标叶 `sessionId` 与拖来的 session 相同则拒绝 split」（`layoutTreeTransform.ts:293-314`）由 I1 入口取代：对象已从源拿走，不会在 dst 旁再造一份同一 `sessionId`。若损坏树已双开，I1 让整次 drop no-op。

`commitDrop`（store）继续：调 `applyDrop` → 推历史 → `resolveActiveLeaf` → 清 drag 状态。不在 `commitDrop` 里读 shell。

## 7. 单测矩阵

测试文件：`operations.test.ts`（纯函数）、`layoutTreeStore.test.ts`（包装）、`conversationUnit.test.ts`（查找 / 损坏兜底）。旧「`addTabToLeaf` 加 `'files'`」「`removeTabFromLeaf` 摘唯一 tab 后还返回原根含 tab」「`applyDrop` 跨域 chat↔files」「`setLeafSessionId`」用例 **删掉或改写**，禁止为保绿把 `tabs` 改回 `string[]`。

辅助：测试用 `tab(sessionId, tabId?)` 工厂（或维 01 测试工具），`dock` 用默认折叠。

### 7.1 必测（任务书四条）

#### A. 单叶三 tab 关中间

前置：单叶 `id=L`，`tabs=[A,B,C]`（session `s1,s2,s3`），`activeTabId=B`，B 带非默认 `dock`（例如 `collapsed:false, openPanelIds:['terminal']`）；A/C 默认 dock。

`removeTab(tree, L, B.tabId)`

断言：

- `result !== tree`
- `root` 仍是 leaf 且 `id === L`
- `tabs.map(t => t.sessionId) === ['s1','s3']`
- `activeTabId === A.tabId`（左邻）
- `tabs[0].dock` 为 A 原 dock；`tabs[1].dock` 为 C 原 dock（B 的 dock 随 B 消失，**未**被写到 A/C 上）
- 邻叶不存在（本来就没有）

store：`past.length + 1`；`activeLeafId === L`。

#### B. 两叶 move

前置：叶 A `tabs=[t1(s1), t2(s2)]` active=t1；叶 B `tabs=[t3(s3)]` active=t3。二叉树 `H(A,B)`。

`moveTab(tree, A.id, t2.tabId, B.id, 0)`

断言：

- A.tabs 只剩 t1，`activeTabId=t1`，`A.id` 不变
- B.tabs `[t2, t3]`（insertIdx=0），`activeTabId=t2.tabId`，t2 为**同一对象**（`sessionId/dock` 不变）
- 仍两叶，branch 方向/ratio 不变
- 先序扫描 `s1,s2,s3` 各一次（I1）

再测：把 A 的 **唯一** 剩余 t1 再 `moveTab` 到 B 末尾 → A 被 prune，root 变成 B 叶（或 B 被提升），`collectLeaves.length===1`，B.tabs 三个，顺序 `[t2,t3,t1]`。

#### C. 唯一 tab split 后源 prune

前置：叶 A `tabs=[t1(s1)]`；叶 B `tabs=[t2(s2)]`；`H(A,B)`。

`splitTab(tree, A.id, t1.tabId, B.id, 'right')`

断言：

- `collectLeaves.length === 2`（A 消失，B 还在，B 右侧新叶只含 t1）
- 新叶 `tabs[0]` 即 t1 对象，`activeTabId=t1.tabId`
- B.tabs 仍 `[t2]`，B.id 不变
- 树上无空叶、无 A.id
- `s1` / `s2` 各一次

对照：`splitTab(..., A.id, t1, A.id, 'right')`（源=目标且唯一 tab）→ `result === tree`，A.id 仍在。

#### D. 拒绝双开同一 session

前置：叶 A 含 `s1`，叶 B 含 `s2`。

| 调用 | 期望 |
|---|---|
| `insertTab(tree, B.id, tab({ sessionId:'s1', tabId:'new' }))` | `=== tree`，B.tabs 不变，A 仍持 s1 |
| `addTab(tree, B.id)` | **成功**（新 draft 唯一 sessionId），B 多一个 draft，A 不动 |
| `moveTab` 把 A 的 s1 搬到 B | 成功（exceptTabId），不是双开 |
| 损坏树：A、B 都已有 s1，再 `splitTab` A 的 s1 到 B 边缘 | `=== tree`（I1 入口） |

store `addTab` 两次点同一叶 `+`：两个不同 draft `sessionId`，均在该叶 `tabs` 内。

### 7.2 补充（与 prune / 左邻 / 根兜底相关，同权）

| 用例 | 断言 |
|---|---|
| 单叶三 tab 关 active 的首个 / 末个 | 左邻公式 §3.3.1 |
| 单叶一 tab 关掉 | 根兜底：一叶一 draft，**新** leaf id，`tabs.length===1`，`isDraftSessionId` |
| 两叶，关掉 A 的唯一 tab（`removeTab` 不是 move） | A prune，B 提升为 root，B.tabs 原样 |
| `activateTabInTree` 外叶 tabId / 缺 leaf | `=== tree` |
| `moveTab` 同叶 `insertIdx` 钳制 | 对齐 Demo 取出后再钳 |
| `applyDrop` tab + `merge-tab` | 等价 `moveTab` |
| `applyDrop` tab + `split-right` | 等价 `splitTab(...,'right')` |
| `applyDrop` `source.type==='leaf'` | `=== tree` |
| `findChatLeafBySessionId` 命中 tabs 而非旧 `leaf.sessionId` | |

## 11. 验收（本维落地后应能用纯函数证）

对应总案 §9 中属于树的部分：

- 单叶三 tab 关中间：叶还在、tabs 剩两个、未关 tab 的 dock 不丢、leaf id 不变。

- `insertTab` 同一 `sessionId` 到另一叶：树不变。
- 全树关光：恰好一个 chat 叶、恰好一个 draft tab。
- 符号 `setLeafSessionId` / `addTabToLeaf` / `removeUnitBySessionId` 不存在。
- 无任何命令读 `workspaceShellStore.openTabs`。
