# 维 06 — 拖拽并轨

> **战役**：`docs/leaf-owned-tabs/`
> **口径**：`00-总方案.md`（标签长在 chat 叶上；提交只走 `moveTab` / `splitTab`）
> **本轮规范**：`20-本轮执行规范.md`
> **依赖**：维 02（树命令 + 空叶 prune）、维 05（窗格 UI 单写，条带成员 = `leaf.tabs`）
> **文件域**：`SessionTabDragContext.tsx`、`sessionTabDropCommit.ts`、`sessionTabDragFeel.ts`、`sessionTabDragDom.ts`、`sessionTabDrag.module.css`；生产路径拆除 `applyDrop` 调用。
> **对照**：`reference/chat-composer-component/js/popovers.js` `DragController`（1275–1621）与 `executeSplit`（1170–1218）。只对照所有权与手感，禁止抄 `cloneNode` / 就地 `Object.assign`。

**采用总案。** 本维不改数据模型、不改命令语义；只把三套指针轨收成一套，并把提交接到维 02 已落地的 `moveTab` / `splitTab`。空源 prune 由维 02 命令保证，本维不写第二套「源窗格换锚」。

## 0. 结论

生产路径只允许：

1. **一个指针控制器**：`SessionTabDragProvider` 内的 `startSessionDrag(leafId, tabId, title, e)`。
2. **一次 mouseup 只调用一个命令**：同条 / 跨条 / 叶面中心 → `moveTab`；叶面边缘 → `splitTab`；其余 → 取消。
3. **身份是 `tabId` + `leafId`**，不是 `sessionId` 字符串、不是 `panelId` 字符串、不是「top-bar 把 sessionId 当成 leafId/tabId」。
4. **禁止** `remainingTab`、`setLeafSessionId`、`openOrFocusSession` 当落点提交、`applyDrop` 当会话提交、`moveNode(unitRoot)` 搬整棵 Conversation Unit。

工具坞下树之后，工具 tab 不再是布局树叶。工具条拖拽**不得**再切会话树；本控制器删除 `startToolDrag`。抽屉内工具顺序若要排，走 `updateTabDock`（维 04/05），不进本维。

## 1. 现状三轨（必须拆掉）

现在会话拖拽、工具叶拖拽、二叉树叶面拖拽是三套生命周期、两套边缘阈值、两套 overlay、三套提交。

### 1.1 轨 A — 会话条（半落地，提交是错的）

| 层 | 文件 | 做什么 |
|---|---|---|
| 指针 | `SessionTabDragContext.tsx` `startSessionDrag` | pointer 捕获、ghost、条内挤开、叶面 region |
| 手感 | `sessionTabDragFeel.ts` | L1=4、条内 1/3 滞后、**叶面 25%** |
| DOM | `sessionTabDragDom.ts` | ghost pill、indicator、`collectStripTabs(data-session-id)` |
| 提交 | `sessionTabDropCommit.ts` | 见下表 |

`commitSessionTabStripReorder`（`sessionTabDropCommit.ts:29-69`）跨叶时：

1. `setLeafSessionId(targetLeafId, sid)` — 只改目标叶的 `sessionId` 字段，**不搬 tab 对象**。
2. 源叶若正在显示该 sid，从**全局** `shell.openTabs` 里 `find` 一个 `remainingTab`，再 `setLeafSessionId(sourceLeafId, remainingTab.sessionId)`。
3. `shell.reorderSessionTab` 调全局顺序。

这是「投影模型」的提交：条带成员不在叶子上，身份在 `openTabs` + `leaf.sessionId`。跨叶之后源叶可能被偷绑成**别的叶子正在用的会话**（`find` 不限定源叶），直接打穿 I1 / I3。

`commitSessionPaneDrop`（`sessionTabDropCommit.ts:72-164`）：

| region | 现行为 | 错在哪 |
|---|---|---|
| center | `setLeafSessionId(target)` + 源叶 `remainingTab` 换锚 + `openOrFocusSession` | 不搬 `SessionTab`；center 被注释成「只聚焦」，与总案「中心 = moveTab」相反 |
| 边缘且树上已有该 session 的 chat 叶 | `findUnitRootId` 后 `moveNode(sourceAnchor, targetAnchor, direction)` | 搬的是 **Conversation Unit 整棵**（chat+tool 子树），不是一枚 tab |
| 边缘且树上没有 | `insertLeafBesideNode(..., 'chat', sid)` 再 `setLeafSessionId(targetAnchor, remainingTab.sessionId)` | **clone / 旁插新叶**；且 remaining 写到 `targetAnchor`（`sessionTabDropCommit.ts:155-161`），目标叶身份被剩余会话覆盖 |

`startSessionDrag` 只收 `sessionId`，源叶靠 `closest('[data-leaf-id]')`。`applyDrop` 注释写明「top-bar session drag 用 sessionId 作为 leafId/tabId」（`layoutTreeTransform.ts:308-310`）——这就是「会话身份用 string panelId / sessionId 冒充 tabId」的兼容路径，**本维禁止保留**。

命中条带时同时认 `[data-global-session-tab-bar]` 与 `[data-pane-header="true"]`。维 05/07 删除 `GlobalSessionTabBar` 后，本控制器只认窗格条。

手感缺口（对照 Demo，本维要补，不是皮肤）：

- ghost 用 `translate3d(clientX+8, clientY+8)`，不是抓取点。
- 无 `is-detached`。
- 条内仍画 150×26 indicator（Demo 条内隐藏，只挤开）。
- body class 是 `tab-dragging`，CSS 却听 `body.is-tab-dragging`（`PaneHeader.module.css:51`），隔离规则对不上。
- 无 iframe / 编辑器 `pointer-events` 隔离。

### 1.2 轨 B — 工具叶 tab（`applyDrop` 切会话树）

| 层 | 文件 | 做什么 |
|---|---|---|
| 入口 | `SessionTabDragContext.startToolDrag` | `LeafToolTabStrip` `onPointerDown` 调用 |
| 指针 | `toolTabDragRuntime.ts` | 与会话共用 Feel/Dom；rAF 合帧；条内自动滚 |
| 提交 | `toolTabDropCommit.ts` | `setDraggedSource` + `setActiveDropZone` + `store.commitDrop()` → **`applyDrop`** |

`applyDrop`（`layoutTreeTransform.ts:279-401`）的 tabs 是 `string[]`（panelId），split 时 `splitLeaf(..., srcPanelId)` 会在会话树旁长出 tool 叶。这与 I5（树上没有 tool 叶）和维 04（坞在叶内抽屉）冲突。

坞下树之后：工具 tab 是 `SessionTab.dock.openPanelIds` 的抽屉 UI，**不是** `LayoutLeaf.tabs`。本维删除 `startToolDrag` / `runToolTabDrag` / `commitToolTabDrop` 对布局树的提交。禁止「工具 tab 拖到叶面边缘 → split 出 tool 叶 / 切会话树」。

### 1.3 轨 C — `useTreeDrag`（生产未接线，overlay 仍挂着）

`BinaryTreeWorkspace.tsx:143` 调用 `useTreeDrag()`，渲染 `DropZoneOverlay` 与 ghost portal（300–318 行），但 **没有任何生产 UI 调用 `startDragLeaf` / `startDragTab`**（全仓仅测试与 hook 自身）。

它仍占用：

- 第二套 overlay（`DropZoneOverlay` ↔ `sessionTabDragDom.createIndicator`）
- 第二套边缘算法（`dropDetection.ts` 默认 **15%** + 窄板自适应，不是 22%）
- `commitDrop` → `applyDrop`（`string[]` panelId tabs、跨域 chat/tool、unit 作用域）
- body class `tree-dragging`
- ghost 固定偏移 `GHOST_OFFSET_X/Y = 16`（`usePointerDragBase.ts`），与 grabOffset 相反

总案 §7：「生产路径上未接线的 `useTreeDrag` 叶面轨若与新单一 controller 重复则删除或吸收，禁止两套 overlay」。本维吸收语义、拆生产挂载；文件物理删除归维 07。

### 1.4 三轨应收成什么

```
                    pointerdown on PaneHeader tab
                              │
                              ▼
                 startSessionDrag(leafId, tabId, title, e)
                              │
              ┌───────────────┼────────────────┐
              ▼               ▼                ▼
         条内命中         叶面命中            未命中 / Esc
              │               │                │
              ▼               ▼                ▼
         moveTab          center→moveTab      取消
                          edge→splitTab
                              │
                              ▼
                    维 02 命令（含空源 prune）
```

| 旧轨 | 并轨后 |
|---|---|
| 轨 A 指针 + 手感 | **保留并升级**（grabOffset / `is-detached` / 22% / 条内藏 indicator / body 隔离） |
| 轨 A 提交 | **整文件重写**：只调 `moveTab` / `splitTab` |
| 轨 B 指针 | 删除。rAF 合帧、swallowNextClick、条内自动滚 **吸收进轨 A** |
| 轨 B 提交 `applyDrop` | 删除。工具顺序不走本控制器 |
| 轨 C hook + overlay | 生产卸载。落点预览只用本控制器的 indicator |
| `dropDetection` 15% | 会话/树拖拽禁用。见 §5 |

不要把三轨「收敛」进 `usePointerDragBase`：它的 16px ghost 偏移、5px 阈值、`commitDrop`/`applyDrop` 语义与 Demo / 总案都相反。本维不新造第四套基座。

### 2.3 指针生命周期

与现 `startSessionDrag` 同构，吸收轨 B 的三处：

1. **阈值**：`exceedsSessionTabDragThresholdL1`（L1=4，钉死，不用 hypot）。未过阈值的 pointerup = 单击，**不提交**（激活由 `PaneHeader` click → `activateTab`）。
2. **rAF 合帧**：pointermove 只记 `{x,y,dx}`，一帧一次 hit-test（从 `toolTabDragRuntime` 搬入）。
3. **swallowNextClick**：真正拖过之后吞掉随后 click，避免源 tab 卸载前被再激活。
4. **Escape / pointercancel / lostpointercapture**：cleanup，不提交。
5. **条内溢出**：命中 strip 时沿用轨 B 的边缘自动滚。

关闭按钮 `[data-tab-close]` 仍忽略。

命中规则（pointermove）：

1. `elementFromPoint` → closest `[data-pane-header="true"]` → 其内 `[role="tablist"]` → **strip 模式**。
   - **删除** `[data-global-session-tab-bar]` 分支。
   - 工具抽屉条（`[data-leaf-tool-tab-strip]`）**不是**会话落点；命中抽屉头/工具 tab 视为未命中条，落到下面的叶面几何。
2. 否则对 `[data-tree-canvas="true"] [data-leaf-id]` 做矩形命中 + `detectPaneDropRegion` → **pane 模式**。坞下树后这些叶全是 chat 叶。
3. 都未命中 → `target = null`，藏 indicator。

## 3. mouseup 分流表

mouseup 时：`cleanup()` 先拆 DOM，再按冻结的 `target` 分流。**一次只调一个命令。** 命令失败 / 原样返回 → UI 无额外补偿（维 02 失败即原树）。

| # | 条件 | 命令 | 守的不变量 | 不做什么 |
|---|---|---|---|---|
| 0 | `!wasDrag`（未过 L1） | 无 | — | 不 `activateTab`（click 路径负责） |
| 1 | `wasDrag && target == null`（画布外 / 无效） | 无（取消） | — | 不 openOrFocus、不换锚 |
| 2 | Escape / pointercancel | 无（取消） | — | 同上 |
| 3 | strip 且 `sourceLeafId === targetLeafId` | `moveTab(src, tabId, src, insertIdx)` | I3：只改该叶 `tabs` 顺序；`activeTabId = tabId` | 不碰邻叶；不 prune（源未空） |
| 4 | strip 且 `sourceLeafId !== targetLeafId` | `moveTab(src, tabId, dst, insertIdx)` | I4：同一 `SessionTab` 对象 splice；源空则 **命令内** prune | 不 `remainingTab`；不 `setLeafSessionId` |
| 5 | pane `region === 'center'` 且跨叶 | `moveTab(src, tabId, dst, dst.tabs.length)`（追加） | I4 同 #4 | **禁止**「center 只聚焦」；禁止 `openOrFocusSession` 代替搬迁 |
| 6 | pane `region === 'center'` 且同叶 | 无（no-op） | I2 已满足 | 不要无意义 splice |
| 7 | pane 边缘且 **跨叶** | `splitTab(src, tabId, dst, region)` | I4：新叶 `tabs=[该tab]`；源空则 prune | 不 `moveNode(unit)`；不 `insertLeafBesideNode` clone |
| 8 | pane 边缘且 **同叶** 且该叶 `tabs.length === 1` | 无（no-op） | 不能把自己拆成空源再 prune 成同一张叶 | 见 §3.3 |
| 9 | pane 边缘且 **同叶** 且 `tabs.length > 1` | `splitTab(src, tabId, src, region)` | I4：从本叶撕出该 tab 成兄弟叶 | 不是「自己 unit 一律 no-op」；唯一 tab 才是 no-op |

`splitTab` 若收到 `region === 'center'`，维 02 规定走 `moveTab`。控制器在分流表里 **不要把 center 交给 splitTab**，避免双路径。

对照 Demo `executeSplit`（`popovers.js:1170-1218`）：同叶 strip = 原地 splice；跨叶 center/strip = `_rmTab` + 插入 + `_prune`；边缘 = `_rmTab` + `_split` + `_prune`。语义对齐；实现必须走不可变命令，禁止 Demo 式 `Object.assign` / `cloneNode`。

### 3.1 命令签名（本维调用契约，实现在维 02）

以总案 §4 为准。本维假设维 02 已在 `layoutTreeStore`（或 compositionRoot 门面）暴露：

```ts
moveTab(srcLeafId: string, tabId: string, dstLeafId: string, insertIdx: number): void
splitTab(
  srcLeafId: string,
  tabId: string,
  dstLeafId: string,
  region: 'left' | 'right' | 'top' | 'bottom'
): void
```

提交模块只通过这一门面调用。禁止 `useLayoutTreeStore.setState` 手改 `tree`，禁止再 import `applyDrop` / `moveNode` / `insertLeafBesideNode` / `setLeafSessionId` / `findUnitRootId` / `openOrFocusSession` / `reorderSessionTab`。

`insertIdx` 语义（与维 02 对齐，写进双方文档）：

- 目标叶 **先按「源 tab 已不在 dst.tabs 里」计算下标**。
- 同叶重排：`collectStripTabs` 已排除源 tab，`insertIdx` 就是 splice 回去的位置。
- 跨叶：`insertIdx` ∈ `[0, dst.tabs.length]`，`length` = 追加。
- 叶面中心：固定传 `dst.tabs.length`（追加）。不要在 commit 里再读一遍 DOM。

`tabId` 找不到 / 源叶不是 chat / 目标叶不存在：命令原样返回。控制器不补救。

### 3.2 提交模块重写

`sessionTabDropCommit.ts` 整文件替换为：

```ts
import type { PaneDropRegion } from './sessionTabDragFeel';

export function commitSessionTabDrop(input: {
  sourceLeafId: string;
  tabId: string;
  target:
    | { kind: 'strip'; targetLeafId: string; insertIdx: number }
    | { kind: 'pane'; targetLeafId: string; region: PaneDropRegion };
}): void {
  const { sourceLeafId, tabId, target } = input;
  if (!sourceLeafId || !tabId) return;

  const tree = /* 维 03 门面：layoutTreeStore 或 compositionRoot */;

  if (target.kind === 'strip') {
    tree.moveTab(sourceLeafId, tabId, target.targetLeafId, target.insertIdx);
    return;
  }

  if (target.region === 'center') {
    if (sourceLeafId === target.targetLeafId) return;
    const dstLen = readChatLeafTabCount(target.targetLeafId); // 只读，算追加下标
    tree.moveTab(sourceLeafId, tabId, target.targetLeafId, dstLen);
    return;
  }

  // 边缘
  if (sourceLeafId === target.targetLeafId) {
    const n = readChatLeafTabCount(sourceLeafId);
    if (n <= 1) return; // 分流 #8
  }
  tree.splitTab(sourceLeafId, tabId, target.targetLeafId, target.region);
}
```

删除符号（本文件不得再出现）：

- `commitSessionTabStripReorder`
- `commitSessionPaneDrop`
- `remainingTab` / `remainingSessionIds`
- `setLeafSessionId`
- `findUnitRootId` / `findChatLeafBySessionId`
- `moveNode` / `insertLeafBesideNode`
- `openOrFocusSession` / `reorderSessionTab`
- `regionToDirection` 后接 unit 级 move

`readChatLeafTabCount` 只读 `leaf.tabs.length`。不要在提交层再实现 prune、不要 `setActiveLeaf`（命令内应已 `setActiveLeaf` + 激活该 tab，对齐总案 `moveTab`「目标激活该 tab」）。

### 3.3 「自己 unit 边缘 no-op」精确含义

旧码用 `findUnitRootId` 把 chat+tool 合成 unit，同 unit 边缘直接 `openOrFocusSession` 返回。坞下树后 **unit = 该 chat 叶本身**。

| 场景 | 结果 |
|---|---|
| 叶上只有 1 个 tab，拖到**该叶**四边 | **no-op**（验收用例 3）。`splitTab` 会拿走唯一 tab → 源空 prune → 只剩新叶，等于把同一叶挪了个分割，无信息增量且破坏「我还在原叶」的预期 |
| 叶上 ≥2 个 tab，拖到**该叶**四边 | **允许** `splitTab(src, tabId, src, region)`：撕出兄弟叶。这是 I4，不是 no-op |
| 唯一 tab 拖到**另一叶**四边 | **splitTab + 源 prune**（验收用例 2） |

不要把「自己 unit」理解成旧 `findUnitRootId` 的 H(chat, tool) 锚。树上已无 tool 叶。

## 9. 测试

本维负责 commit + feel 单测。指针集成（jsdom 派 pointer 事件）能写则写；E2E 全矩阵归维 07。旧测试「center → 只 openOrFocusSession / 不拆树」「边缘 moveNode 不 clone」**删除或改写**，不得为保绿改回投影模型。

### 9.1 必测（任务书三则）

树 fixture 用维 01 的 `SessionTab[]` 叶，**不要** `createLeaf('chat', ['chat'], 'chat', sessionId)` 那种 panelId tabs。

**T1 两叶拖中心并入**

- 叶 A：`tabs=[s1]`，叶 B：`tabs=[s2]`，水平分屏。
- `commitSessionTabDrop({ sourceLeafId: A, tabId: s1.tabId, target: { kind: 'pane', targetLeafId: B, region: 'center' } })`
- 断言：B.tabs 含 s1 对象（同一 `tabId` / `sessionId` / `dock`）；A 被 prune；根下 chat 叶数 = 1；**零次** `setLeafSessionId`；B.activeTabId = s1.tabId。
- 变体：A 有两个 tab 时，拖其中一个到 B 中心 → A 仍在且少那一枚，B 多那一枚。

**T2 唯一 tab 拖边缘后源消失**

- 叶 A：唯一 tab s1；叶 B：s2。
- drop `{ kind: 'pane', targetLeafId: B, region: 'right' }`
- 断言：出现新叶，`tabs.length === 1` 且就是 s1；B.tabs 仍只有 s2；A 不在树上（prune）；新叶在 B 的右侧（horizontal branch，position after）。
- 不得出现「A 被 remainingTab 填成 s2」导致两叶同一 sessionId。

**T3 拖到自己 unit 边缘 no-op**

- 单叶，唯一 tab s1。
- drop `{ kind: 'pane', targetLeafId: A, region: 'left' | 'right' | 'top' | 'bottom' }`
- 断言：`tree === 原 tree`（引用相等或结构相等且 leaf id 不变）；不新建 branch。

### 9.2 本维一并覆盖

| 用例 | 断言 |
|---|---|
| 同条 reorder | 三 tab `[a,b,c]`，拖 c 到 insertIdx=0 → `[c,a,b]`；邻叶不动；leaf id 不变 |
| 跨条 strip | A=`[a1,a2]` B=`[b1]`，a2 插到 B insertIdx=0 → A=`[a1]` B=`[a2,b1]` |
| 同叶 center | no-op |
| 同叶边缘但 tabs≥2 | `splitTab`：源留其余，兄弟新叶只有被拖 tab |
| 取消 | target null / Escape → 树不变 |
| `SESSION_PANE_EDGE === 0.22` | feel 单测钉死 |
| `detectPaneDropRegion` | 400×200 叶：x=0–87 left，中间 center，x=313–400 right |
| 提交模块源码 | grep 测试或静态：`sessionTabDropCommit.ts` 不含 `setLeafSessionId`、`remainingTab`、`openOrFocusSession`、`applyDrop` |
