## 0. 结论先行

现码**没有**「点击展开面板」的统一互斥规范：

1. **没有 exclusive group / 单例 open id。** 全仓检索 `exclusiveGroup` / `singletonOpen` / `activeMenuId` / `openId` 在浮层体系中零命中。`LayerStackManager.register()`（`LayerStackManager.ts:64-88`）只把新层推进数组并按 `LAYER_TYPE_PRIORITY` 排序，**新开一层不会关掉同级已开层**。
2. **LayerStack 只做 LIFO 退栈，不做同级互斥。** Esc / 外点只关**当前顶层**可退栈浮层（`dismissTop` / `handleGlobalPointerDown`），不是「关掉所有 dropdown」。
3. **登记面极窄。** 生产代码里 `useLayerRegistration` 只被 `ui/Menu` 与 `ui/Dialog` 调用。会话右键、面包屑 flyout、预览历史、计划抽屉、斜杠弹层、目录树、价格模态、Tooltip **全部未登记**。
4. **级联 `parentId` 是死契约。** `layerStackTypes.ts` 声明了 `cascade-submenu` 与 `parentId`，但生产消费方**从未传入 `parentId:`**。模型子菜单 / 排序 flyout / 项目「添加」级联都是 CSS 绝对定位挂在父面板 DOM 里，不是独立 Layer。
5. **Composer 上仅有的「关兄弟」钩子是死的。** `ChatComposer` 声明 `onCloseSiblingMenus?`（`ChatComposer.tsx:113`），打开 `+` 菜单与改权限时会调用；`ChatCard` / `useChatComposerProps` **从未传入**。权限 pill 的 `handleToggle` 打开时也不关模型菜单。
6. 因此「点开第二个应关掉第一个」**不是架构保证**，只在「第二次点击被顶层判定为 outside-pointer」时碰巧成立。真机三开证明这条碰巧路径经常 miss。

分类口径（本文件贯彻，不把 Dialog / Tooltip 混进「应互斥点击面板」，也不漏记）：

| 桶 | 含义 | 互斥期望 |
| --- | --- | --- |
| **A. 应互斥的点击展开面板** | 点按钮（或会话行「更多」/右键）弹出的 Menu / Select / 自管浮层 / flyout / 非模态抽屉 | 全局同时只开一个；级联子面板算同一棵树，不算第二个根 |
| **B. 允许叠在面板之上的模态** | Dialog / ConfirmDialog / 全屏设置 / 向导 / 确认盒 | 可以盖在 A 上；打开 B 时建议收掉 A，但 B 与 B 按模态栈 LIFO；B 内部的 Select 属于 A，互斥的是下拉不是 Dialog |
| **C. 不要漏、但不要算进 A** | Tooltip（hover）、行内 accordion/`<details>`、思考折叠、输入联想（`/` `@@`） | Tooltip 另案（survey/02）；行内展开不是浮层；输入联想是否并入「同时一块浮层」由主控裁决，本文件单列 |

本调研**未逐步真机连点**验证四击；四击结论标「现码结构推断」。互斥失败以用户真机截图 + 现码路径为证据。

## 1. 基座现况（Menu / LayerStack / 坐标）

### 1.1 `ui/Menu`（所有 Radix 下拉的单一基座）

- 路径：`apps/crish-desktop/src/components/ui/Menu/Menu.tsx`
- 实现：`@radix-ui/react-popover` 的 `Popover.Root` + `Portal` + `Content`（`Menu.tsx:338-345`），**非** Radix DropdownMenu / ContextMenu。
- 双模：`openState.open !== undefined` 则完全受控（`isControlled`，`Menu.tsx:159-160`）；否则内部 `useState`。
- 两种触发：
  - **anchor 模式**（`Menu.tsx:242-246`）：只渲染 `Popover.Anchor virtualRef`，**不**渲染 `Popover.Trigger`。开关完全由外部按钮 `onClick` 自管。现用于权限 / `+` / 思考档 / 排序 flyout。
  - **trigger 模式**（`Menu.tsx:247-325`）：`cloneElement` 注入 ref + 50ms 冷却 `onClick`，再包 `Popover.Trigger asChild`。若 trigger 是 `<Tooltip>`，会拆出 `content` 再包回去。现用于模型徽标 / Select / 快捷设置 / 绝大多数「更多」。
- 打开时登记 LayerStack：`useLayerRegistration({ type: 'dropdown-menu', dismissible: true, id: useId() }, isOpen)`（`Menu.tsx:167-180`）。每个 Menu 实例一个随机 `useId()`，**没有共享 group id**。
- 外点：默认 `onPointerDownOutside` / `onInteractOutside` 若点在自己的 trigger/anchor 上则 `preventDefault`，避免 Double Toggle（`Menu.tsx:355-377`）。若消费方传入自定义 `onInteractOutside`，**直接 return，不再做 trigger 豁免**（`SettingsQuickMenu` 走这条）。
- 坐标：运行时定位由 Radix Popper（`avoidCollisions` + `collisionPadding={12}`）。`position.ts` 的 `calculateMenuPosition` 是纯函数单源，**SessionContextMenu 未用它**（该文件自写了一份 `measureMenu`，见 §3.17）。

### 1.2 LayerStack（中枢实际做了什么、没做什么）

`LayerStackManager.ts` 单例。能力：

| 做了 | 没做 |
| --- | --- |
| 入栈、按 type 优先级排序（modal 10 < dropdown/context 40 < cascade 50 < tooltip 60） | **开新 dropdown 时关掉其它 dropdown** |
| Esc 自顶向下关一层（50ms 内不穿透） | 同级互斥 / exclusive group |
| 外点只关**顶层** dismissible（`handleGlobalPointerDown:430-474`） | 外点清掉所有点击面板 |
| 点在顶层 `anchorRef` 内则放行，交给触发器自己 toggle | 识别「点的是另一块面板的 trigger，应关旧开新」 |
| `parentId` 子孙级联关闭 | 生产方传入 parentId |
| `data-floating-active` 静默 Tooltip（CSS `display:none`） | Tooltip 自己调用 `isTooltipSilenced()`（Tooltip.tsx 不读这个 API） |
| 50ms `isWithinCooldown` | 冷却只打在 **trigger 克隆 onClick**（`Menu.tsx:300-304`），anchor 自管按钮不受闸 |

外点判定伪代码（现码）：

```
top = 栈顶 dismissible（可跳过 toast/tooltip）
若 click ∈ top.elementRef 或 top.anchorRef 或 top 的 descendants → 忽略
否则 dismissLayer(top)   // 只关这一层
```

所以：权限开着再点模型徽标，**仅当**模型徽标被判定为权限层的「外面」时权限才会关。模型开着再右键会话，LayerStack **最多关顶层那一个 Menu**；会话右键自己又不在栈里 → 权限/模型残体 + 右键可以共存。

`register()` 重复 id 只覆盖自己（`filter id !== new.id`），不会动邻居。

### 1.3 谁在登记 LayerStack（生产）

| 组件 | type | 条件 |
| --- | --- | --- |
| `ui/Menu` | `dropdown-menu` | `isOpen` |
| `ui/Dialog` | `modal-dialog` 或 `confirm-dialog`（`role==='alertdialog'`） | `open && isMounted` |
| `useVirtualLayer` / `registerVirtual` | `virtual-interceptor` | **生产零调用**（只在 `PhysicalGeometryGuards.test.tsx`） |

`src/hooks/useLayerRegistration.ts` 已下沉到 `ui/internal`，hooks 目录无残留。

**与其它面板叠开的现码路径（对应真机）：**

1. **右键不一定能清掉 Menu 栈。** 右键序列是 `pointerdown` → `pointerup` → `contextmenu`。LayerStack 听 pointerdown，**只 dismiss 顶层**。若权限+模型都已在栈里，一次右键最多关一个，另一个 Menu 留下，再加会话右键 → 仍是两到三块。
2. **排序钮 `stopPropagation`。** `useSidebarHandlers.ts:157-161` `handleSortBtnClick` 里 `e.stopPropagation()` 再 `setSortDropdownOpen(toggle)`。会话菜单的关闭监听是 `document click` 冒泡（`useSidebarContextMenu.ts:118`）。点排序时：会话菜单**收不到** click → **不关**；排序 Menu 打开。会话右键 + 排序可共存。
3. **键盘打开完全绕过外点。** `Shift+F10` / `ContextMenu` 键只调 `openRowMenu`，没有 pointerdown 给 LayerStack。权限/模型保持，会话菜单再开。这是不依赖「外点碰巧」的三开路径。
4. **Esc 双通道。** 会话菜单在 `window` capture 上自己听 Esc；LayerStack 也在 `window` capture 听 Esc。会话后挂载则后注册。同一击 Esc 可能 **Menu 与会话菜单一起关**（不是 LIFO 跨系统），或只关登记了的那一层。行为取决于监听注册顺序，没有契约。

`handleContextMenu`（`useSidebarContextMenu.ts:126-131`）只 `setContextMenu(...)`，**不** `setSortDropdownOpen(false)`，也没有任何「关全站 Menu」调用。

## 6. 「开第二个会不会关第一个」——按机制，不按愿望

没有统一答案。现码里实际发生的是下面几条互不相认的通道：

```
通道 1  LayerStack pointerdown capture（仅已登记层；只关 TOP）
通道 2  Radix DismissableLayer（每个 Popover 各自一份；modal=false，互不关对方）
通道 3  Session 的 document click 冒泡（可被 stopPropagation 切断）
通道 4  FileBreadcrumb / PreviewHistory 各自的 document mousedown
通道 5  各组件本地 useState（Permission / Model / Plus / Thinking / Select / …）
通道 6  死钩 onCloseSiblingMenus
```

| 场景 | 现码最可能结果 |
| --- | --- |
| 点权限，再点模型 | **无保证。** 若模型徽标被当成权限层 outside → 权限关、模型开（还可能撞 50ms 冷却导致模型没开）。若两层都完成 register 且外点 miss → **两开**（真机已见） |
| 权限+模型开着，再右键会话 | LayerStack 最多关 TOP 一个 Menu；会话菜单不进栈 → **两到三开**（真机已见） |
| 会话右键开着，再点排序 | 排序 `stopPropagation` → 右键不关 + 排序开 |
| 任意 Menu 开着，`Shift+F10` 开会话菜单 | 无 pointerdown → Menu 全留着 + 右键 |
| 空态 hover 项目名 | 不走外点 → 已开 Menu 留下 + 项目选择 |
| 点 `+` | 调用空的 `onCloseSiblingMenus`；只靠通道 1 碰巧关顶层 |
| 打开设置 Dialog | Dialog 进栈，**不** `dismissAll` 已开 Menu。全屏遮罩视觉上盖住，状态可能仍 open |
| Esc | 只关栈顶已登记层；会话菜单另听一份，可能双关或错关 |
| 点确认盒 | 确认盒进栈盖在上面（允许）；不自动清 A |

Radix 层面：`Popover.Root` 默认非 modal，**两棵 Popover 本来就可以同时 open**。旧「12 套菜单收敛到 ui/Menu」只统一了皮肤和坐标，**没有统一互斥**。

## 7. 规范缺口（实现波要对的契约，本文件不设计）

现码缺的不是「再加一个 if」，是整段规范。问题同权列出：

1. **没有 exclusive group。** 需要一个（或按窗口一份）「当前点击面板 id」。新开 A 类根面板 → 关掉其它 A 类根。级联子面板（模型列表、排序 flyout、添加项目）挂 `parentId`，随根走，不算新根。
2. **没有单例 open 总线。** Composer 四按钮、会话右键、排序、叶更多、设置内 Select，全是散落 `useState`。`onCloseSiblingMenus` 是失败的局部尝试。
3. **LayerStack.register 语义不够。** 今日 = 入栈。互斥需要「入栈前按 group 驱逐」或显式 `exclusive: 'click-panel'`。仅靠外点 LIFO **证明不够**（真机三开）。
4. **登记面没铺完。** 会话右键、面包屑、预览历史、计划抽屉、斜杠、目录树、价格模态、（若并入）Artifact —— 不登记就不存在于任何全局判断。类型枚举里的 `context-menu` / `drawer` / `popover` / `cascade-submenu` 是注释幻想。
5. **触发器模式不统一。** anchor 自管 vs Trigger 合成 vs 自管 Portal vs 裸 Radix。互斥判断若只 hook 在 Menu `onOpenChange`，自管面板全漏；若只 hook 在 LayerStack 外点，键盘/hover/编程式全漏。
6. **外点通道至少四套**（§6），监听阶段还不一样（capture pointerdown vs bubble click vs mousedown）。`stopPropagation` 即可破坏互斥。
7. **Dialog 与 dropdown 未分层策略。** 需要写清：打开 B 是否 `dismissAll` A；B 在栈上时 A 的 exclusive 是否仍只允许一个 Select；`dismissible={false}` 的设置/向导不得被 dropdown 逻辑关掉。
8. **50ms 冷却与「关旧开新」冲突。** 关旧会 `markCloseTimestamp`，紧接着的开新 click 可能被 trigger 克隆吞掉 → 用户感觉「点了没开」。互斥实现必须让「切换」是一次原子操作，而不是 dismiss + 再 toggle。
9. **模型 `open` 默认 true、权限/模型两套权限 Select（composer 药丸 vs 设置页 Select）state 不共享** —— 不是互斥核心，但是同一「判断逻辑」该收口时的脏点。
10. **测试缺口。** `LayerStackManager.test.ts` 覆盖 Esc LIFO、IME、tooltip 静默、冷却；**没有**「两个 dropdown-menu 同时 register 时是否互斥」的断言。所以互斥从来不是门禁。

5. **空叶「打开文件」**（用户圈的另一标）是 `UnitChromeActions` 的直接按钮，**不是**点击展开面板。不要塞进本文件的修复列表当菜单。
6. **对派单/提示词：** 「浮层战役已收口」不能当互斥已落地。Menu 基座收敛 ≠ exclusive group。下一份实现任务书必须写验收：权限开着再点模型 → 权限 DOM 卸载；两者开着再右键会话 → 只剩会话菜单；`Shift+F10` 同样。没有 exclusive 单测不要宣称修好。

## 10. 总结

桌面端「点击展开」不是一套系统，是 **Menu 基座（Radix Popover）+ 若干自管 Portal + 若干裸 Radix + 若干行内 flyout** 的并集。LayerStack 是 **Esc/外点的 LIFO 栈**，外加给 Tooltip 用的 `data-floating-active`；它**不是** exclusive group。生产只有 Menu 与 Dialog 登记。会话右键 —— 真机第三只脚 —— 完全在栈外，还用冒泡 `click` 和外层 `stopPropagation` 打架。Composer 上权限/模型/加号/思考档四份 `useState`，唯一的兄弟关闭钩子没接线。因此「同一时间只能开一个」在现码里既没有判断逻辑，也没有规范载体；真机权限+模型+会话右键同时开是这条缺口的直接表现，不是回归意外。

桶 A（应互斥）覆盖：composer 四面板、会话右键与行更多、排序级联、用户卡片快捷设置、叶顶栏更多、叶工具添加、项目选择、文件打开方式/更多/面包屑、预览历史、计划抽屉、设置内全部 Menu/Select/级联，以及（待主控）输入联想。桶 B（允许叠层）是 Dialog/Confirm 与全屏设置/向导/确认盒；价格模态是漏登记的 B。桶 C 是 Tooltip、行内 accordion、Toast。下轮实现必须在 A 上建立统一 open id / exclusive group，把未登记的 A 推进同一判断，并写「开新关旧」的原子切换，而不是再加一条 document 监听。
