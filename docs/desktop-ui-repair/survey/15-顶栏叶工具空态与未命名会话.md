## 0. 结论先行

1. **顶栏一排「未命名会话」不是展示层口误，是壳层标题另起炉灶。** 会话权威口径是 `EMPTY_SESSION_TITLE = '新会话'`，且明确「不发明未命名会话」；侧栏走 `sessionListDisplayTitle`，所以同一时刻侧栏有真名、顶栏五枚胶囊全是幽灵字。壳 `TabSurface.title` 在打开时写死，之后没有回写。
2. **空会话主区不是「欢迎面」，是一张灰画布 + 一簇工具图标 + 一枚「打开文件」。** `ChatEmptyState` 源码里有完整三态（「我们该在 {项目} 中处理什么？」/ 快捷 prompt / 无会话 CTA），真机两张图都没有这些字。空画布上唯一成句的产品文案是「打开文件」。
3. **「打开文件」字钮不是 Files 空态 CTA，是 chat 叶 `UnitChromeActions` 文件钮的 Tooltip 文案。** 按钮本身是 icon-only；`label: '打开文件'` 只进 Tooltip / `aria-label`。默认 `side='top'`，贴顶栏时被钳到图标下方，看起来像主区字钮。第二张图鼠标不在文件钮上，这枚胶囊就消失——与「更多操作」残影是同一套门户，但落在空叶中心，被用户当成空态主行动。
4. **叶工具条该不该在空会话以文字按钮出现：不该。** 工具入口可以在发第一条消息前存在（历史「空会话整栏消失」曾是真洞），但空画布的主人公必须是对话落地，不能是「打开文件」。图标簇可以静默存在，不能变成字 CTA，也不能当空态唯一家具。
5. **顶栏 / 叶栏 / 侧栏已经叠床架屋，而且标题还互相打架。** 会话身份同时出现在 `AppTopBar` 标签行和侧栏列表；会话次要动作同时出现在 `ChatHeaderMore` 和侧栏右键；工具同时出现在 `UnitChromeActions`（动词「打开 X」）和 `LeafToolTabStrip`（名词「文件 / 终端」）。注释还在讲已删的 `ChatHeader` / `UnitSessionTabStrip`。

## 2. 会话 Tab 命名

### 2.1 真机

两张工作台图顶栏都是：

- 四枚未激活「未命名会话」+ 一枚激活「未命名会话」带关闭钮 + 「新建对话」加号。
- 第二张图侧栏同时列出「你好啊」「这是一条测试消息」「软软」「测试一下」等。
- 用户看到的是「一排无名克隆」，不是「新会话 / 首条消息短标题」。

### 2.2 权威口径（展示层已经有）

`apps/crish-desktop/src/api/sessionTitle.ts`：

- `:65-69`：`EMPTY_SESSION_TITLE = '新会话'`；注释禁止散落「未命名」「Untitled 会话」。
- `:94-95`：`未命名(?:会话|对话|聊天)?` 被识别为默认占位。
- `:555-560`：`sessionListDisplayTitle` —— 真标题优先，否则从首条用户消息推导，再否则回落「新会话」。默认 / 幽灵标签一律回落「新会话」。
- 测试 `sessionTitle.test.ts:656-687` 钉死：`sessionListDisplayTitle({ title: '未命名会话' }) === '新会话'`；空壳可 prune；「不发明未命名会话」。

侧栏遵守这条：`SessionRow.tsx:14,194` 用 `sessionListDisplayTitle`。所以第二张图侧栏是正常人话。

### 2.3 壳层另写一套（真机字从这里来）

| 位置 | 行为 | 后果 |
| --- | --- | --- |
| `workspaceShellStore.ts:133-145` `makeSessionTab` | `title: (title \|\| '').trim() \|\| '未命名会话'` | 打开时没带 title，胶囊直接刻上幽灵字 |
| `GlobalSessionTabBar.tsx:93-104` `resolveTabTitle` | shell 标题非空就**原样返回**；不走 `sessionListDisplayTitle`；最后还有 `EMPTY_SESSION_TITLE \|\| '未命名会话'`（前半永真，后半是死代码，但暴露作者仍把「未命名会话」当兜底） | 一旦 tab 写进「未命名会话」，永远盖住会话真名 |
| `workspaceChromeTabs.ts:279` `buildSessionTabsForWorkspace` | `(s.title \|\| '').trim() \|\| '未命名会话'` | legacy 行 2 组装同样发明幽灵字 |
| `useSidebarContextMenu.ts:170,178,215` | toast / 删除确认：`targetSession.title \|\| '未命名会话'` | 连归档、分叉、删除文案都可能喊幽灵名 |

`TabSurface.title` 在 `types.ts:25` 是必填字符串。打开之后：

- `openOrFocusSession` 已存在的 tab 只聚焦，**不更新 title**（`workspaceShellStore.ts:171-179`）。
- 全仓 `workspace-shell/` 没有把会话改名 / 自动标题写回 `openTabs[].title` 的路径。
- 侧栏点选会带 `title: target?.title`（`useSidebarHandlers.ts:91-95`）。这是**原始 `session.title`**，不是 `sessionListDisplayTitle`。若实体标题仍是空 / `未命名会话` / `Untitled`，tab 就刻幽灵字；即便后来首条消息推导出真名，胶囊也不改。

不带 title 的打开口（都会掉进 `makeSessionTab` 的「未命名会话」）：

- `GlobalSessionTabBar.tsx:185,197` 丢 tab 恢复 / 点选补开：`openOrFocusSession(sid)` 无 title。
- `TreeLeafPanel.tsx:110` 点叶绑 session：同样无 title。
- `useSlashSend.ts:214` 同类。
- `hydrateWorkspaceShell.ts:97-119` 从 legacy map 恢复：`known` 用 `s.title` 原值；空标题 → `makeSessionTab` 再写成「未命名会话」。树里绑了但 `sessions[]` 已无实体时，`:113` `known.set(sid, {})`，title 必幽灵。

### 2.4 为何能排出五枚相同胶囊

Pending Draft ADR（`docs/architecture/session-pending-draft-adr.md`）规定：点「新对话」只进 `__pending_draft__`，**不往 `openTabs` 塞标签**。`openNewDraftTab`（`workspaceShellStore.ts:373-411`）也按此写：清误写入的 draft tab，`activeTabId = null`，标签行不应出现「新对话」。

因此真机五枚「未命名会话」**不是**草稿标签，而是五条已经进了 `openTabs` 的真实 `sessionId`。可能叠加来源（实现阶段要按 id 对一下，这里只列机制，不断言哪一条单独造成这五枚）：

1. **空壳进了标签行、却被侧栏藏起来。** `shouldListSessionInSidebar` 对默认标题 + 零消息返回 false（`sessionTitle.ts:200-211`）。hydrate GC 会剪空壳，但 **keep 当前活动 id**，且 **shell `openTabs` 不是 `sessions[]`，prune 不会摘标签**。结果：侧栏干净，顶栏挂着无名空壳——与第二张图「侧栏有名、顶栏无名」同构。
2. **恢复 / 点叶 / 丢 tab 补开不带 title**，把已有真会话也刻成「未命名会话」。此时点开本应看到消息，但若当前激活的是空壳而不是侧栏那条「你好啊」，主区仍空。
3. **旧「新建即 mint」脏盘** 留下多枚空壳 id，legacy `crish_open_session_tabs_v1` 仍记着它们。默认冷启动 `readRestoreLastWorkspace()` 为 false（`hydrateWorkspaceShell.ts:59`）会 `resetToCleanDraft`；若本机开了恢复、或本会话里反复 `openOrFocusSession` 空 id，仍能堆到 `MAX_OPEN_SESSION_TABS = 16`。
4. **Tab 标题冻结。** 即使用户后来在侧栏看到推导标题，顶栏仍显示打开那一瞬写下的字。

草稿态标签行有意 `activeId = null`（`GlobalSessionTabBar.tsx:240-242`）：点「新对话」后顶栏**无高亮**。真机却有一枚激活的「未命名会话」，说明当时不在 draft，而在某条已 mint、标题失败的空会话上。

### 2.5 三个词混用

| --- | --- | --- |

## 3. 空态该长什么样（契约 vs 真机）

### 3.1 源码已经写过的空态

`apps/crish-desktop/src/api/chatEmptyState.ts` 三态互斥：

| kind | 标题 | 主行动 | 其它 |
| --- | --- | --- | --- |
| `no-session` | 暂无会话 | 「新建对话」 | 无项目条、无快捷 prompt |
| `filter-empty` | 无匹配消息 | 「清除过滤」 | — |
| `session-empty` | 开始对话（组件里改写成「我们该在 {项目} 中处理什么？」） | **无主行动按钮** | 项目条 + 三条快捷 prompt |

`ChatEmptyState.tsx:276-388`：`session-empty` 英雄句把项目名做成 `ProjectPickerMenu` 内联钮；快捷 prompt 是「分析项目结构 / 查看代码改动 / 检查开发服务」。`ChatCard.tsx:194-211` 在 `emptyKind != null` 时走这条，否则走 `ChatMessageList`。

`useChatEmptyKind.ts:82-91` 已把 PENDING_DRAFT 当成「有活动会话」，避免新建对话落到「暂无会话」。按契约，点「新对话」应看到欢迎面 + 项目 + prompt + 底栏 composer。

### 3.2 真机：契约字一个都没有

两张工作台图主区都没有：

- 「我们该在 … 中处理什么？」
- 「暂无会话」/「新建对话」
- 三条快捷 prompt
- 项目芯片（第二张图项目名在侧栏，不在主区英雄句里）

看得见的只有：叶工具簇、（图 1）「打开文件」胶囊、孤儿 Tooltip、沉底 composer。

### 3.3 源码里会把欢迎面吃掉的闸

这些闸本身有正当理由，但叠加后可以把主区打成「什么都不挂」：

1. **`messagesLoading` → `emptyKind = null`。** `chatEmptyState.ts:119-120`。有活动会话且仍在水合时不闪欢迎面。`ChatCard.tsx:194-217` 于是走 `ChatMessageList`；零消息的虚拟列表就是一张空画布。
2. **loading 候选条件**（`useChatEmptyKind.ts:42-61`）：非 demo、非 draft、`messages.length === 0`，且 `hydratedFromEngine === false` 或已有 `engineCursor` / `engineLastRunId`。3 秒超时后才放行（`:76`）。若 `hydratedFromEngine` / 游标在超时前反复跳动，`useEffect` 会把 `hydrateTimedOut` 重置（`:32-34,70-78`），欢迎面可以一直不来。真机是稳定截图，更像「loading 已过、但 emptyKind 仍是 null」或「走了空列表」，须 9222 看 `data-empty-kind` / `data-messages-loading`（`ChatCard.tsx:170-171`）。
3. **组件内二次抑制。** `ChatEmptyState.tsx:179-182`：`messagesLoading && kind !== 'no-session'` 直接 `return null`。若父级 `emptyKind` 与 `messagesLoading` 短暂同时为真，会留下带 `data-empty-kind` 的空壳容器、里面什么都没有。
4. **欢迎面自己已经剥光。** `ChatEmptyState.module.css:34-51,125-133`：图标 `display: none`，副文案全局 `display: none`。`session-empty` 又没有主 CTA（`chatEmptyState.ts:32,239`）。契约视觉只剩英雄句 + prompt。英雄句一旦没挂上，主区只剩底栏输入。

### 3.4 Composer 与空态是拆开的

`ChatComposerWrapper.tsx:122-123` 注释：composer **始终**在 footer，不再注入 `ChatEmptyState`。props 声明了 `emptyKind`（`:29`）但函数参数没有解构，空/满同一底栏。

金标是**有消息**的对话，composer 沉底正确。空会话若没有居中英雄句，视觉就是「底栏一只输入盒，上面一片荒地」。`ChatComposer.tsx:10,166-178` 会从祖先 `data-empty-kind` 感知落地焦点态；祖先属性缺失时，连这条落地特例都不生效。

### 3.5 空态应该长什么样（本维只锁效果，不写实现）

对照产品已写契约 + 金标气质 + 用户圈注，空会话主区必须同时满足（不得自行降成「先空着」）：

1. **对话优先。** 用户看见的第一句是「在这个项目里做什么」，不是「打开文件」。
2. **有项目锚点。** 现契约的内联项目名可以留，但必须看得见。
3. **有可开始的动作。** 快捷 prompt 或等价的「填入输入框」路径；无会话时才是「新建对话」。不要用工具坞动词冒充空态 CTA。
4. **Composer 是落地家具，不是荒地底栏。** 空态时输入与英雄句要在同一阅读节奏里（现在拆成「可能缺失的居中块 + 永远沉底的 footer」）。
5. **叶工具不是空画布主体。** 见 §4。
6. **空画布上不得漂着侧栏 Tooltip。** 见 §6。

`session-empty` 故意不放主按钮（避免和 composer / FirstRun 抢 CTA）——这个分工成立的前提是英雄句和 prompt **真的在**。真机前提崩了。

## 4. 叶工具条与「打开文件」字钮

### 4.1 真机圈注

图 1：画布左上一条图标（总览 / 文件树 / git / 终端 / 笔记 / ⋯ / 右坞），其下单独一枚白底圆角「打开文件」。用户把它从图标条里拆出来圈。图 2：同一图标条仍在，字钮不在。

缺陷清单第 6 条原文：「空会话主区悬着叶工具图标 + 独立「打开文件」字钮，主对话区空洞。」调研边界用户锁第 5 条点名「空叶打开文件」。

### 4.2 图标条是什么

`TreeLeafPanel.tsx:151,191-198`：`viewRegistry.isPrimary(leaf.panelId)` 为真时，**每个 chat 叶**在 `leafBody` 外挂 `UnitChromeActions`。没有「空会话不挂」的分支。`sessionForPanel` 在 draft + 活动叶时跟 `__pending_draft__`（`:93-99`）。

`UnitChromeActions.tsx:28-58` 清单：

| id | label（Tooltip / aria） | 注册表名词（`registerBuiltInViews.tsx`） |
| --- | --- | --- |
| overview | 打开总览 | 总览 |
| files | **打开文件** | **文件** |
| diff | 打开差异 | 差异 |
| terminal | 打开终端 | 终端 |
| note | 打开笔记 | （扩展激活才渲染，`:162` `getView(id)` 闸） |

按钮是 `Button variant="ghost" size="sm"` + 15px 图标，**没有 `children` 文字**（`:167-180`）。`unitChromeLabel.ts` 的「对话 / 项目名」主标签**没有挂到现组件上**。簇是纯图标。

CSS：`UnitChromeActions.module.css` 无背景、无通栏高、无标题。`BinaryTreeWorkspace.module.css:89-97` `.leafToolHeader` 只做 `flex: 0 0 auto; width: 100%`，**没有 `justify-content: flex-end`**。簇默认**左贴**。空画布上就是「左上角一串灰图标」，像漂在荒地上，不像收好的静默 chrome。

坞折叠时末尾再加「展开右侧工具栏」（`UnitChromeActions.tsx:197-217`）。图 1 / 图 2 都能看到这枚，说明当时右坞是收起的——工具叶 `LeafToolTabStrip` 不在，chat 叶这一簇是唯一工具 UI。

历史文档（`docs/system-audit-and-redesign/…`、`docs/chat-core-connectivity/02-…`）把「空会话不渲染 ChatHeader → 工具入口消失」判成洞，后来把簇常驻到叶上。`docs/block-workspace-architecture/shell-rehost/execution/美学一眼.md` 又锁：簇不是顶栏，禁止抄 30px `--card-header-bg` 通栏，内容靠右。现码挂上了簇，但**左对齐、空画布当背景**，和「静默收在角上」不是同一观感。两份历史都成立：入口不能消失；也不能变成空态主角。

### 4.3 「打开文件」字钮的身份

排除项：

- `ChatEmptyState` 主行动只有「新建对话 / 清除过滤」，没有「打开文件」。
- 桌面 `FilesCard.tsx` 没有「打开文件」空态大钮（移动端 `FileBrowser` 才有 files-empty-state，不在本壳）。
- `viewRegistry` 文件面板标题是「文件」，不是「打开文件」。
- `Button` 无 children 时不渲染 `.buttonLabel`（`Button.tsx:107-109`），图标钮自己不会长出字。

对得上的唯一文案源：`UnitChromeActions.tsx:37` `label: '打开文件'` → `:166` `<Tooltip content={label}>`。

`Tooltip.tsx:83` 默认 `side = 'top'`。图标贴在叶顶、再上面是 36px `AppTopBar`，向上没空间，钳位后落到图标**下方**（`tooltipPositioning` + `Tooltip.module.css:40-50`：`background: var(--bg-elevated)`、`padding: 6px 12px`、小字、白/浅底圆角）。图 1 那枚胶囊的材质、字号、位置，和同图里的「更多操作」残影是一家；图 2 鼠标不在文件钮上就消失。

所以用户看到的「空会话主区字钮」= **被钳到画布里的工具 Tooltip，在欢迎面缺席时被读成 CTA**。它同时踩两条用户锁：空叶「打开文件」，以及「Hover 同一时间只能一个、过快则一个也不显示」（图 1 同时有「打开文件」+ 多枚「更多操作」+「测试一下」）。

动词 / 名词还分叉：叶簇说「打开文件」，工具叶 Tab 说「文件」。空画布上冒出来的又是动词，更像「请打开一个文件」而不是「这是文件坞」。

### 4.4 叶工具条该不该在空会话出现

本维不降效果，只把合法效果写死：

1. **不可以**再把整组工具从空会话卸掉，然后宣称「空态干净了」——那是已证伪的「发第一条之前打不开文件树 / 终端」。
2. **不可以**在空画布正中（或图标下）留下「打开文件」字 CTA，无论它是 Button 还是 Tooltip。
3. **空会话的视觉主角是对话落地**（§3.5），不是工具坞。簇若在，必须是静默附属：默认几乎看不见，hover 才染色；贴右不贴左；不占涂色通栏；不跟 `LeafToolTabStrip` 再叠一条 30px 栏。
4. **有消息之后**簇仍是打开坞的入口，与工具叶名词 Tab 分工：chat 叶用图标打开，工具叶用名词切换。不要在 chat 叶再做一套带字工具条。
5. **draft / 空壳**上点「打开文件」会走 `openToolInSession`；`TreeLeafPanel.tsx:135-139` 对 `__pending` 退回 `openToolInActiveTab`。空草稿上开坞，会把「还没开始的对话」变成「文件树 + 空 chat」。这是 IA 问题，不是小样式：空会话先开文件，等于承认空态主人公是文件。

`ChatHeaderMore` 挂在同一簇里（固定 / 导出 Markdown / 清空记录）。空会话 `canExport` 为 false（`UnitChromeActions.tsx:83`），导出项会藏；固定在 draft 上也不挂（`:186-188`）。空态 ⋯ 里往往只剩「清空记录」或空菜单——又一个空会话不该强调的控件。

## 5. 顶栏 / 叶栏 / 侧栏是否叠床架屋

是。不是「多一个快捷键」那种重复，是**同一身份、同一动作出现在两套（或三套）表面，而且字还不一致**。

### 5.1 会话身份两套表面

| 表面 | 组件 | 标题函数 | 真机 |
| --- | --- | --- | --- |
| 窗口顶栏 | `AppTopBar` → `GlobalSessionTabBar` | shell `TabSurface.title` / `resolveTabTitle` | 「未命名会话」墙 |
| 侧栏列表 | `SessionRow` | `sessionListDisplayTitle` | 真名 |
| （已删）叶内 ChatHeader | 注释还在 | `unitChromeLabel`（项目名 / 「对话」） | 现码不渲染 |

`workspaceChromeTabs.ts:1-7` 自己写过：「行 2 是当前工作区已打开的会话标签（非侧栏全量列表）」。这个分工成立：顶栏 = 打开集，侧栏 = 全量。崩在打开集的标题不跟会话走，空壳又进了打开集。用户无法用顶栏辨认「我打开的是哪一条」，只能回侧栏。顶栏变成无名计数器。

顶栏还有自己的「新建对话」加号（`GlobalSessionTabBar.tsx:309-329`），侧栏也有「新对话」。手势重复可以接受（两处都进 `openNewDraftTab`），但顶栏加号旁边是五枚无名胶囊时，加号看起来像「再造一个未命名会话」，与 ADR「草稿不进标签」相反。

### 5.2 会话次要动作两套菜单

| 动作 | 叶簇 `ChatHeaderMore` | 侧栏右键 `useSidebarContextMenu` |
| --- | --- | --- |
| 固定 / 取消固定 | 有 | 有 |
| 导出 Markdown | 有（有消息才显示） | 有 |
| 清空记录 | 有 | 无（有删除 / 归档） |
| 重命名 / 归档 / 分叉 / 复制 ID / 拆分 / 新窗 | 无 | 有 |

第二张图会话右键铺在空画布上（在此处打开 / 拆分视图 / 重命名 / …）。叶簇 ⋯ 和侧栏 ⋯ 都叫「更多」，触发器都是 `MoreHorizontal`。空画布上同时出现右键面板 + 多枚「更多操作」Tooltip，分不清是侧栏的还是叶簇的。

`ChatHeaderMore.tsx:16-18` 注释还在讲「靠近视口底部自动翻转，不受侧栏滚动条遮挡」——它现在不在旧 ChatHeader，而在叶顶图标簇。

### 5.3 工具身份两套语言

| 表面 | 形态 | 文案 |
| --- | --- | --- |
| chat 叶 `UnitChromeActions` | 图标簇 | 打开总览 / **打开文件** / 打开差异 / … |
| 工具叶 `LeafToolTabStrip` | 30px `--card-header-bg` 名词 Tab | 总览 / **文件** / 差异 / …（`viewRegistry.getTitle`） |
| 坞折叠钮 | 叶簇最右 | 「展开右侧工具栏」 |
| 坞展开后收起 | `LeafToolTabStrip.tsx:168-178` | 「收起右侧面板」 |

同一文件面板：打开时叫「打开文件」，进去了叫「文件」。空会话用户只看得到前一个动词。

`LeafToolTabStrip.tsx:77-78`：无 tab 才不渲染；有 tab 即使只有一个也渲染（保证加号）。工具叶会再占 30px 涂色条。chat 叶簇 + 工具叶条 = 两道工具 chrome。美学一眼禁止 chat 叶抄这条涂色栏——现码没抄皮，但**空会话只露出 chat 叶那一簇**，视觉账记在空画布上。

### 5.4 窗口顶栏自己也挤

`AppTopBar.tsx`：36px 里塞侧栏开关 + 会话胶囊行 + 帮助 + 窗控。胶囊 `max-width: 180px` 且 `flex: 1 1 0`（`GlobalSessionTabBar.module.css:20-21,132-134`）。五枚「未命名会话」均分宽度，字被裁成相同残片，更无法辨认。这不是「再加一行 Tab」能修的；是打开集不该全是同一幽灵字。

金标顶栏的 `adobe illustrator…` **不要搬**。要搬的是「Tab 上能读出不同会话」。

### 5.5 过时注释会把实现带沟里

- `BinaryTreeWorkspace.tsx:6-8`：ChatHeader / UnitSessionTabStrip。
- `ChatComposer.tsx:3`：「次要动作在 card-header ChatHeaderMore」。
- `unitChromeLabel.test.ts:104-114`：仍按已删 ChatHeader 的 DOM 序写契约（还留着 `chat-toggle-msg-filter`）。
- `美学一眼.md:21` 曾写「产品未挂 UnitChrome」——现码已挂。以 `TreeLeafPanel.tsx:191-198` 为准。

实现阶段若按注释去「恢复 ChatHeader 通栏」，会直接违反美学一眼和本维「不要第四道窗框」。

## 6. 空画布上的侧栏残留 Tooltip（本维只记占位）

完整 Hover 互斥 / 孤儿门户归其它 survey（边界第 2、5 条）。本维只记它和空叶的关系：

- 触发器在侧栏：`SessionRow.tsx:335-337` 行标题 Tooltip；`:352-358`「更多操作」；`:50-60` 绝对时间。
- 侧栏收起后（图 1）触发器已不在，胶囊仍停在原坐标，叠在空 chat 叶上。
- 图 2 侧栏还在，滚过后「更多操作」离开对应行，时间戳 `2026/08/15 03:28`、项目上的「你好啊」、会话上的「测试一下」错位停着。
- `Tooltip` 默认无全局单例；`body[data-floating-active='true']` 只在有浮层时藏 Tooltip（`Tooltip.module.css:52-54`），藏不住「没有菜单时的孤儿」。
- 空画布没有对话内容，这些胶囊变成主区唯二的「字」（再加上「打开文件」）。用户会把它们读成空态 UI。

空态修完之后，若孤儿 Tooltip 还在，欢迎面仍会被气泡打断。两条要一起收，不能只擦空态文案。

## 7. 问题清单（同权）

分类只为好找，**不是优先级**。

### 7.A 标题 / 打开集

1. `makeSessionTab` / `buildSessionTabsForWorkspace` 发明「未命名会话」，与 `EMPTY_SESSION_TITLE` 和测试「不发明」直接冲突。
2. `resolveTabTitle` 信任非空 shell 标题，绕过 `sessionListDisplayTitle`，真名永远刷新不进胶囊。
3. `TabSurface.title` 只写一次，rename / 首条消息自动标题 / hydrate 补题都不回写。
4. 丢 tab 恢复、点叶、部分发送路径 `openOrFocusSession` 不带 title。
5. 侧栏 `openOrFocusSession` 传原始 `session.title`，不传展示标题。
6. 空壳可进 `openTabs` 却不进侧栏，顶栏变成无名空壳墙。
7. 归档 / 分叉 / 删除 toast 仍用「未命名会话」兜底。
8. 「新会话 / 新对话 / 未命名会话」三词在壳层混用；草稿不应变成带字 Tab，真机激活态却像「选中了一个未命名会话」。

### 7.B 空态缺席

9. 真机空会话看不到 `ChatEmptyState` 契约字。
10. `messagesLoading` 把 `emptyKind` 置 null → 零消息走 `ChatMessageList` → 空白画布。
11. `ChatEmptyState` 在 loading 时 `return null`，可能留下空容器。
12. 欢迎面 CSS 藏图标、藏副文；`session-empty` 无主按钮。缺席时没有任何降级字。
13. Composer 与空态拆开且 wrapper 丢掉 `emptyKind`，落地输入沉在荒地底。
14. 祖先没有 `data-empty-kind` 时，composer 落地焦点特例不生效。

### 7.C 叶工具 / 「打开文件」

15. chat 叶无条件挂 `UnitChromeActions`，空画布左上悬一簇图标。
16. `.leafToolHeader` / `.toolbarActions` 不靠右，空态上像广告条。
17. 「打开文件」是文件钮 Tooltip 被钳到画布里，被读成字 CTA。
18. 空画布同时出现多枚 Tooltip，违反「同一时间一个；过快则零」。
19. 叶簇动词「打开文件」与注册表名词「文件」不一致。
20. 空草稿上 `openToolInActiveTab` 会把未开始的对话变成工具坞。
21. 空会话 ⋯ 菜单几乎没有合法项，仍占簇位。
22. `unitChromeLabel` 已写「对话 / 项目」但不渲染，空叶没有任何叶内身份，只靠顶栏幽灵 Tab。

### 7.D 叠床架屋 / 过时 IA

23. 会话身份：顶栏打开集 vs 侧栏全量，标题不同源。
24. 新建：顶栏加号 vs 侧栏「新对话」，旁边是无名墙时语义反转。
25. 会话更多：叶簇 `ChatHeaderMore` vs 侧栏右键，空画布上叠在一起。
26. 工具：叶簇图标 vs 工具叶名词条 vs 坞折叠钮，三套开关同一坞。
27. 注释 / 测试仍描述 ChatHeader、UnitSessionTabStrip、消息搜索钮序。
28. `AppTopBar` 36px 均分无名胶囊，裁成无法阅读的相同残片。

### 7.E 空画布被异物占用

29. 侧栏行标题 / 「更多操作」/ 时间戳 Tooltip 在侧栏收起或滚动后停在 chat 叶上。
30. 会话右键、权限菜单、模型菜单（06 的叠开）也铺在同一张空画布上，空态没有任何自己的层去压住它们。

## 8. 实现阶段必须裁决、本维不代裁的点

调研不写方案。下列是收口 `00-总方案` 时不能躲的效果锁（躲 = 降效果）：

1. **打开集标题的唯一函数**是不是 `sessionListDisplayTitle`？壳层还能否保留一份独立 `TabSurface.title` 字符串？
2. **空壳能不能出现在顶栏？** ADR 说空壳不进侧栏、草稿不进标签；顶栏若仍挂空壳，用户锁的「一排未命名」消不掉。
3. **空会话叶工具：挂但不抢画布，还是空态改密度（仍可点）？** 禁止「卸掉入口」和「维持现状当字 CTA」两条退避。
4. **「打开 X」动词还是注册表名词？** 两套必须并成一套给用户看的语言。
5. **欢迎面与 composer 的几何关系**：继续「居中英雄 + 沉底输入」，还是空态收成一组落地（仍要完整英雄句 / 项目 / prompt / 输入，不许砍成只有输入）。
6. **ChatHeader 通栏是否允许复活？** 现码和美学一眼都说不。总案应写死，避免有人按过时注释加回第四道窗框。

## 10. 总结

真机空会话不是「少写一句欢迎语」，而是壳层把对话身份、对话落地、工具入口三件事全做反了。顶栏打开集用已禁止的「未命名会话」刻标题，而且刻完不更新，于是和侧栏真名决裂，排成一墙克隆胶囊。主列有写好的三态欢迎面，真机却走成零消息空列表；画布空出来以后，左上那簇本该静默的 `UnitChromeActions` 变成唯一家具，文件钮的「打开文件」Tooltip 被钳到画布里，看起来像空态主按钮。侧栏孤儿气泡再铺一层，空画布成了异物场。

叶工具条**可以**在空会话存在，以便发消息前打开文件树或终端；**不可以**以文字按钮或残留提示的形式占据空画布，更不可以替代「我们在这个项目里做什么」。顶栏会话 Tab 与侧栏列表可以并存（打开集 ≠ 全量），但必须共用 `sessionListDisplayTitle` 这一套人话，草稿继续不进标签，空壳不准在顶栏复活成幽灵墙。金标只借「干净、有名字、对话优先」；示例里的 `adobe illustrator…` 假 Tab、竖轨、demo 会话列表一律不搬。

主控收口总案时，把 §8 六条效果锁写进方案即可。本文件只梳理，不改代码。
