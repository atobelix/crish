## 0. 读法、锁与诚实边界

### 0.1 用户锁（本文件必须按此写，不得劝退）

- 设置里不能用的按钮已超 80；本范围要把 **每个可点击控件** 记成一条：能用 / 不能用的证据。
- 证据类型：空 handler、disabled、被 overlay 挡住、IPC 吞错、样式点不中。
- 样式退化也记（原生框、圆角满天飞、Windows 粗滚动条、果冻按下、Tooltip 残影、最丑 Toast）。
- 设置按钮圆角 = **7px**（详见 `survey/04`，本文件只在本范围控件上落证据，不重复 token 全表）。
- 点击果冻去掉（详见 `survey/01`）；本范围所有 `ui/Button` 都继承 `:active { transform: scale(0.98) }`。
- Hover 提示同一时间只能一个、快移一个也不显示（详见 `survey/02`）；本范围大量包 `<Tooltip>`。
- 点开展开的面板同一时间只能开一个。
- Toast「已自动获取 7 个模型」点名禁回流；本范围模型扫描正是发射点。

### 0.2 判定口径（问题同权，不按 P0 砍）

| 判定 | 含义 |
| --- | --- |
| **能用** | 有非空 handler；状态或 IPC 有接线；失败有行内/toast 可见反馈；浮层按源码能画在设置壳之上。 |
| **不能用** | 点了无可见结果、点不到、handler 空/接错名、浮层 z-index 被设置壳盖住、overflow 裁切、IPC 失败被吞成「没发生」、控件长得像按钮其实不可点。 |
| **半通** | handler 在，但关键路径吞错、状态撒谎、Esc 误关整个设置、Tauri 下载不确定、成功反馈被 toast 策略丢掉。 |
| **样式失效** | 功能 handler 可能在，但全局 class 蒸发成 UA 原生框、圆角 ≠ 7px、果冻缩放、胶囊 999px、Windows 粗条 + 上下三角。用户口径把这类也算「不能用的按钮」。 |

动态列表（模型行 / 规则删除 / 信任命令 / 设备行 / 导入勾选 / 单价行）**先记模板一条**，文末动态池另计。

### 0.3 没做 / 额外发现

- 未改代码、未提交、未派子代理、未写第二份文档。
- 未跑 CDP、未在真机点一遍；「被 overlay 挡住」是 z-index 算术，不是截图像素。
- 外观 / 通用 / 扩展 / 定时 / 快捷键 **不在本文件展开内容页**（侧栏 tab 按钮本身属于壳，仍列入 §2）。
- **额外发现（上报主控）**：设置壳把主应用 `SidebarFooter`（含假用户名 `orange`、再开一份设置齿轮）嵌进设置侧栏；这不是账户页功能，是壳层错嵌套。
- **对派单的想法**：下轮实现必须先修「设置壳 z=1000 vs Menu z=300」和「Esc capture 不看子层」，否则本范围几十个下拉/菜单改皮也点不开。

## 1. 全范围共性机制（先看这个，后面每条都踩）

这些不是「某一个按钮」的孤立 bug，是本范围 **成片不能用** 的根。

### 1.1 设置壳 z=1000，Menu/Select 面板 z=300 → 下拉点了像没反应

| 层 | 声明 | 计算 z |
| --- | --- | --- |
| 设置全屏 Dialog overlay | `Dialog.module.css:7-12` `--dialog-z`；`SettingsPanel.module.css:261-263` `--dialog-z: var(--z-modal)` | **1000** |
| 设置封面 `.settingsCover` | `SettingsPanel.module.css:7-21` `z-index: var(--z-modal)` + `isolation: isolate` | **1000** + 独立层叠上下文 |
| `ui/Menu` 面板 | `Menu.module.css:5-6` `z-index: var(--z-dropdown)`；`z-index.css:15` `--z-dropdown: 300` | **300** |
| `ui/Select` | 基于 Menu，无更高 z | **300** |
| Tooltip | `--z-tooltip: 9000`（`z-index.css:26`） | **9000**（提示盖过按钮，按钮菜单却在底下） |

Menu 用 `Popover.Portal` 挂 `document.body`（`Menu.tsx:341-342`）。设置 Dialog 也 portal 到 body（`Dialog.tsx:147`）。后挂的菜单 **z 更低**，会被全屏设置盖住。

**推断结论**：设置里所有走 `ui/Menu` / `ui/Select` 的触发器，点击后面板在设置背面。用户观感 = 「按钮不能用」。Tooltip 仍能飘在最顶（9000），和真机「提示在、按钮死」同向。

本范围直接命中：

- 模型「添加服务商」菜单（`ModelsSettingsTab.tsx:63-116`）
- 模型「全局默认模型」级联 Menu（`ModelProfileList.tsx:44-156`）
- 规则作用域 Select（`SettingsRulesTab.tsx:143-153`）
- 安全权限模式 Select（`SettingsSecurityTab.tsx:182-191`）
- 设置侧栏底栏再开的 `SettingsQuickMenu`（菜单 class 把 z 拉到 `--z-modal`，与壳同 1000，谁在上不确定）

### 1.2 Esc 捕获监听不看子层 → 子面板未关，整个设置先关

`useSettingsNav.ts:50-68`：`window.addEventListener('keydown', onKey, true)`（**捕获阶段**）。优先级号称「rules 弹窗 → 清空搜索 → 关闭设置」，但 `rulesModalOpen` 只有规则 tab 会写，而且 **接线名写错**（§8）。

因此：单价弹层、设备确认、模型添加菜单、规则全文、任意 Select 打开时按 Esc，捕获阶段先 `onClose()` 关掉整个设置。

设置 Dialog 自己 `dismissible={false}`（`SettingsPanel.tsx:251`），Esc 不是 Dialog 关的，是壳 hook 关的。

### 1.3 全局皮肤 class 蒸发 → 原生框（与快捷键/扩展真机图同因）

JSX 仍写 `settings-field-input` / `settings-chip-btn` / `settings-rule-preset` / `settings-pane` / `settings-head-tools`，**生产 CSS 零定义**（全仓 `.css` grep 无选择器；只剩 Select 注释和 skills/mcp 的 `:global` 引用）。

本范围受害者：规则自定义输入、安全命令输入、用量单价弹层全部 input、规则预设 chip、安全预设 chip、「+N 更多」。这就是用户说的「退回浏览器默认方框」。

### 1.4 按钮圆角不是 7px

默认档 `--radius-md = 6px`（`tokens.css:264`）。`ui/Button` sm/md 用 `--btn-radius: var(--radius-md, 6px)`（`Button.module.css:13,100-104`）。本范围几乎所有设置按钮默认 **6px**。例外：密钥保存内联 `borderRadius: '7px'`（`ProviderProfileForm.tsx:85`）；添加服务商 `--radius-xl`（12px）；默认模型 trigger `--radius-full`（胶囊）；QuickMenu 主题段 `999px`。详见 `survey/04`。

### 1.5 点击果冻

`Button.module.css:72-74`：`:active:not(:disabled) { transform: scale(0.98) }`。本范围所有 `ui/Button` 按下都会缩。
`Switch.module.css` 文件头写拇指曲线 `cubic-bezier(0.27, 0.2, 0.25, 1.51)`（y2=1.51 过冲）。多端配对开关、模型启用开关、能力矩阵开关都踩。详见 `survey/01`。

### 1.6 Windows 原生滚动条

本范围滚动容器 **没有** `scrollbar-width: thin` / 自定义 `::-webkit-scrollbar`：

- 设置内容 `.coverContent`（`SettingsPanel.module.css:200` `overflow-y: auto`）+ `contain: strict`（203）
- 侧栏 `.navScroll`（132-134）
- 模型轨 `.mrlList` / 详情 `.modelsDetail`（`ModelsSettingsTab.module.css:61-69,171-182`，只设了 `scrollbar-gutter: stable`）
- 导入列表 `.importList`（`ExternalSessionImport.module.css:129`）
- 单价弹层 `.modalList`（`SettingsUsageTab.module.css:89`）
- 规则全文 textarea、QuickMenu `overflow-y: auto`

Windows WebView2 会画出粗条 + 上下三角。用户锁第 5 条。

### 1.7 Tooltip 非单例

本范围几乎每个按钮外包 `<Tooltip>`。`ui/Tooltip` 每实例自己 `visible`（见 `survey/02`）。设置侧栏 12 个 tab 各带 keywords 提示，鼠标扫侧栏会残影。`LayerStackManager` 的 tooltip 静默协议 **无业务调用方**。

### 1.8 内容区 `contain: strict` 再裁一层

`.coverContent`（`SettingsPanel.module.css:198-204`）`contain: strict` + `overflow-y: auto` + `overflow-x: hidden`。不走 portal 的绝对定位飞出（默认模型级联 `.cascadeFlyout`）即使 z 修好，也会被这块裁掉。

### 1.9 Toast 漏网「已自动获取 N 个模型」

产品禁令：`toastQueueLogic.ts:123` 只封 `/^已获取\s/`。
实发文案：`useModelProviderActions.ts:72` `` `已自动获取 ${r.models.length} 个模型` ``。多一个「自动」，策略放行。这就是真机 Toast「已自动获取 7 个模型」。
`notify` 还无视 `ok` 参数（`useModelProfilesState.ts:113-117` 一律 `toast.show(msg)`）。

## 13. 失效计数（本范围）

### 13.1 计数规则

- 上表每个 ID 算 **1 条固定可点控件**（动态逐行模板也算 1）。
- **用户口径失效** = 判定为「不能用」或「半通」或「功能能用但样式失效」。
- 共性果冻 / 默认 6px 圆角 **不**摊进每一颗 Button（否则 SH-03 关闭钮也会被算失效）。这类基座污染单列 §13.3。
- 动态池（模型删除钮 ×N 等）§13.4 另计。

### 13.2 分桶（固定 ID）

固定 ID 总数 = 21+6+12+40+15+14+14+14+5 = **141**。

| 分区 | ID 数 | 能用 | 不能用 | 半通 | 功能通但样式失效 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 壳 SH-01~21 | 21 | 3（03/04/05） | 2（18/19） | 4（01/02/20/21） | 12（06~17） |
| QuickMenu QM-01~06 | 6 | 5（02~06） | 0 | 1（01） | 0 |
| 账户 PF-01~12 | 12 | 8（02/03/06/07/08/09/10/12） | 0 | 3（01/04/05） | 1（11） |
| 模型 MD-01~40 | 40 | 19 | 16（01~13+20~22） | 4（23/24/36/38） | 1（16） |
| 用量 US-01~15 | 15 | 7（01~04/13~15） | 0 | 5（05~07/09/10） | 3（08/11/12） |
| 多端 DV-01~14 | 14 | 3（10/11/12） | 1（14） | 10（01~09/13） | 0 |
| 规则 RL-01~14 | 14 | 3（04/11/14） | 1（01） | 3（02/12/13） | 7（03/05~10） |
| 安全 SC-01~14 | 14 | 4（06/07/08/14） | 1（01） | 1（05） | 8（02/03/04/09~13） |
| 诊断 DG-01~05 | 5 | 2（01/02） | 1（05） | 2（03/04） | 0 |
| **合计** | **141** | **54** | **22** | **33** | **32** |

验算：3+5+8+19+7+3+3+4+2=54；2+0+0+16+0+1+1+1+1=22；4+1+3+4+5+10+3+1+2=33；12+0+1+1+3+0+7+8+0=32；54+22+33+32=141。

**用户口径失效 = 22+33+32 = 87。**

### 13.3 基座污染（不摊进 141，用户仍能感到「每个钮都怪」）

| 污染 | 覆盖面 |
| --- | --- |
| Button `scale(0.98)` 果冻 | 本范围所有 `ui/Button`（导出/导入/扫描/保存/窗控/刷新/清空/添加/删除… **≥40 颗可见钮**） |
| Button 圆角 6px ≠ 7px | 同上，除 MD-22 一颗 7px |
| Switch 过冲 | DV-03 + 模型启用 ×N + 能力开关 |
| 原生滚动条 | ≥8 个滚动容器 |
| Tooltip 非单例 | 侧栏 12 tab + 几乎每颗钮 |
| Esc 捕获关设置 | 所有子 Dialog/Menu/Confirm/单价层 |
| Menu z=300 | 所有 Select/添加服务商/级联 |

若把「每颗 Button 的果冻+6px」按用户口径算不能用，仅可见 Button 就会 **再 +40 以上**，总数轻易过 80。这与用户「设置里不能用的按钮已超 80」同向；其中一部分是基座统一病，不是单控件空 handler。

### 13.4 动态逐行池（空态=0，有数据后线性增加）

| 模板 | 每实例控件 | 判定 | 说明 |
| --- | --- | --- | --- |

| 规则删除 | RL-04 ×R | 能用 | |
| 信任命令删除 | SC-14 ×W | 能用 | |
| 设备 改名/保存/取消/撤销 | DV-10~13 ×D | 半通挂确认 Esc | |
| 单价行 保存/删除/两输入 | US-09~11 ×K | 半通+原生框 | 默认价表非空，K 通常 >10 |

内置 7 壳「没有填密钥的地方」可再记 **7 条缺失表面**（与 MD-20~22 三控件重叠，不把 7×3 乘上去）。

### 13.5 文末数字（本范围）

| 口径 | 条数 |
| --- | ---: |
| 固定可点 ID | **141** |
| 其中能用 | **54** |
| 其中不能用（硬） | **22** |
| 其中半通 | **33** |
| 其中功能通但样式失效 | **32** |

这已经单独超过用户说的「超 80」，且 **还没算** 外观/通用/扩展/定时/快捷键（那些页真机图更惨，全局 class 蒸发同源）。
