## 0. 结论先行

1. **`_left_gu32j_18` 不是思考档，是模型槽外壳。** CSS Modules 哈希对应 `ComposerFusedTrigger.module.css` 的 `.left`（`ComposerFusedTrigger.tsx:90`）。它只是 `<div>`，自己没有 `onClick`、没有 `Menu`。真正开关是宿主塞进来的 `ModelBadgePicker`（`ChatCard.tsx:65-74` → `rightActions` → `{children}`）。用户点的是胶囊左半的模型徽标。
2. **模型徽标仍走 `Popover.Trigger asChild` 旧路。** `ModelBadgePickerMenu.tsx:75` 传 `trigger={children}`，**没有** `anchor`。按钮自己没有 `onClick`、没有稳定 `ref`。这是 06 文档里的结构 D，现码没迁。
3. **权限丸已经换成「自管 `open` + `handleToggle` + `anchor={pillBtnRef}`」。** 注释写「消除 Quad-Click」（`PermissionModeMenu.tsx:18-20`）。结构迁了，**双写状态机没拆干净**，真机仍点不关。注释是假关。
4. **其它按钮能关，不是运气好，是「谁写 `open`」的人数不同。** 加号 / 设置 / 会话「更多」要么只有一个写者、要么第二次写入的是**绝对值 false** 而不是 `!prev`。权限丸是 `setOpen(prev => !prev)`；模型徽标是 Radix `onOpenToggle = setOpen(prev => !prev)`。先被外点关掉、再取反，就会重开。连点 = 开→关→开→关，直到某一次竞态窗口没碰上、或点到药丸外面。
5. **Tooltip 包在 trigger 上不抢 hit-test**（portal `pointer-events: none`，菜单开时还有 `body[data-floating-active] .tooltip { display: none }`）。它抢的是**事件所有权**：`Tooltip.handleClick` **无视** `defaultPrevented`，把子按钮的冷却 `preventDefault` 和 Radix `onOpenToggle` 都跑一遍。冷却锁对「Tooltip + Trigger」组合是空的。
6. **LayerStack 有登记。** 凡是 `ui/Menu` 且 `isOpen===true`，都会 `useLayerRegistration`（`type: 'dropdown-menu'`，`anchorRef: anchor ?? triggerRef`）。权限丸 / 思考档登记的是药丸 `ref`；模型徽标登记的是 Menu 里每 render 换新的匿名 `ref`。Tooltip、会话右键、Toast **不入栈**。
7. **门禁是假绿。** 权限测试「再点一次可关闭」只 `fireEvent.click`，不走 `pointerdown` → LayerStack → discrete flush → `click`。模型测试从 `open=true` 起跳，根本不点触发器关。融合触发测试不覆盖关菜单。

## 3. 状态机逐步：权限丸 `_permPill`

### 3.1 组件拓扑（打开后）

```
div.permModeWrap
  Tooltip(disabled={open})
    button.permPill.no-drag     ← pillBtnRef，onClick=handleToggle
  Menu
    Popover.Root open={open} onOpenChange={setOpen}     ← 第二写者
      Popover.Anchor virtualRef={pillBtnRef}            ← 只读 ref，不写 current
      Popover.Portal > Content
        useLayerRegistration(id=useId(), type=dropdown-menu,
                             anchorRef=pillBtnRef, elementRef=contentRef,
                             onDismiss=() => handleOpenChange(false))
        options.map → 每项再包一个 Tooltip
```

Radix Anchor 模式**不**挂 `Popover.Trigger`。`context.triggerRef` 一直是 `null`（`@radix-ui/react-popover` 只在 Trigger 里 `useComposedRefs(..., context.triggerRef)`）。

因此 Radix 自己这段豁免是死的（`PopoverContentNonModal`）：

```js
const targetIsTrigger = context.triggerRef.current?.contains(target);
if (targetIsTrigger) event.preventDefault();
```

点击药丸 = 点击 Content **外面**。Radix 只靠 Menu 的 `onPointerDownOutside` / `onInteractOutside` 里 `anchor.current.contains(target)` 才 `preventDefault`。少这一下，`onDismiss → onOpenChange(false)`。

LayerStack 的豁免是另一条平行线：`pointerdown` 捕获阶段 `anchorEl.contains(target)` 则放行，否则 `dismissLayer(..., 'outside-pointer')` → 又一次 `setOpen(false)`。

按钮自己还要 `handleToggle` → `setOpen(prev => !prev)`。

**三个写者，一个取反。**

### 3.2 第一次点击（关 → 开）

设初始 `open=false`，Layer 未登记，无 Content。

| 时刻 | 谁 | 做什么 | `open` |
| --- | --- | --- | --- |
| pointerdown | Tooltip `handlePointerDown` | `setVisible(false)`，不拦冒泡 | false |
| pointerdown | LayerStack | 栈里没有本菜单的 dismissible 层（或顶层是别人） | false |
| click | `handleToggle` | `setOpen(prev => !prev)` → true | **true** |
| 提交 | Menu | `Popover.Content` 挂上；`useLayerRegistration(active=true)` 入栈 | true |
| 提交 | Tooltip | `disabled={true}`，提示卸掉 | true |
| 提交 | 基座 | `focusedIndex` 拉到首个未禁用项，`.focus()` 首项 | true |

这一击通常能开。问题不在开。

副作用（不是关不掉的主因，但是叠症）：

- 首项程序化 focus。项外又包 Tooltip。WebView2 里若这次 focus 带上 `:focus-visible`，会再挂一个提示（survey/02 已写「计划项上冒少打扰」一类）。CSS 在 `data-floating-active` 时把 `.tooltip { display: none }`，是视觉静音，**不是** React 卸载。
- 权限丸打开时**不**关模型菜单 / 思考档 / 加号。`ChatCard` **没传** `onCloseSiblingMenus`。`onCloseSiblingMenus?.()` 只在加号**打开**和权限**选中某档**时调用，而且调用方是 `undefined`。用户锁「同一时间只能开一个面板」在这条链上是空的。真机圈注「权限+模型叠开」与此同因。

### 3.3 第二次点击（用户以为在关）

菜单已开，指针还在药丸上。

```
T0  pointerdown  window capture
    LayerStack.handleGlobalPointerDown
      顶层 dismissible = 本菜单（若模型也开着，则是后开的那个）
      content.contains(药丸)? 否
      pillBtnRef.current.contains(target)?
        是 → 记下 anchorPointerDownTarget，return（本层不关）
        否 → dismissLayer → handleOpenChange(false) → setOpen(false)
             + markCloseTimestamp()
    同函数还绑在 document capture 上；PROCESSED_EVENTS WeakSet 去重，不会关两次

T0' React 18 discrete flush（pointerdown 结束后）
    若 T0 已经 setOpen(false)：Content 卸、Layer 出栈、Tooltip disabled=false
    按钮重渲，onClick 仍是同一个 handleToggle

T1  pointerdown 落到 Radix DismissableLayer（deferPointerDownOutside=true）
    药丸不在 Content 的 React 树里 → 记「外点」，把真正的 POINTER_DOWN_OUTSIDE
    推迟到随后的 click（左键）

T2  click 目标阶段
    Tooltip.handleClick → child.onClick = handleToggle
    setOpen(prev => !prev)
      若 T0 没关：prev=true  → false    用户如愿
      若 T0 已关并 flush：prev=false → true   当场重开

T3  click 冒泡 / Radix document 一次性 listener / 以及 capture 里 setTimeout(0)
    派发 POINTER_DOWN_OUTSIDE
    Menu：anchor.contains(originalEvent.target) → preventDefault → 不 onDismiss
    若 contains 失败且 Content 还在：onDismiss → setOpen(false)
```

**点一次「关」的四种落点：**

| 落点 | 用户看见 |
| --- | --- |
| LayerStack 认锚 + Radix preventDefault + 只跑一次 toggle | 关上（和加号一样） |
| LayerStack 当外点关了，flush 后 toggle 取反 | **闪一下还开着** |
| LayerStack 认锚，Radix 没 preventDefault，toggle 先写成 false | 仍关（两次都写 false） |
| 模型菜单叠在栈顶 | 先关掉模型；权限丸被 toggle 再翻一次（关或开取决于当时 `open`） |

真机「点死了」对应的是第 2 / 4 行在连点里反复出现，不是「按钮没 click」。

### 3.4 第三次、第四次……

没有单独的「第三击状态」。每一次落在药丸上的物理点击都是同一套：

```
若此刻 open=true  且 外点先写 false 且 toggle 再取反 → 仍 true
若此刻 open=false 且 只跑 toggle                 → 变 true（误开）
若此刻 open=true  且 外点没抢到                   → 变 false（终于关）
若连点打在药丸边缘，:active scale(0.97) 让 pointerup 落到背后
    → LayerStack handleGlobalPointerUp 当 drag-off 再 dismiss 一次
    → 与 toggle 再打一次
```

连点越快，越容易落在「pointerdown 关 + click 开」的 50ms 窗口里。Anchor 路径**没有** `isWithinCooldown`（那把锁只包在 `trigger` 的 `cloneElement` 上，`Menu.tsx:300-304`）。权限丸的 `handleToggle` 从不看冷却。

点到药丸外面（输入框、空白、菜单项）通常一次就能关：只有 `setOpen(false)`，没有取反。所以用户会觉得「点药丸不行，乱点一下反而行」——这就是「点死了才能关」。

### 3.5 注释为什么是假的

`PermissionModeMenu.tsx:18-20` 写的是「药丸按钮拥有独立 pillBtnRef 与 onClick，消除 Trigger 与 Tooltip 争抢导致的 Quad-Click」。

迁走 Trigger **只去掉了一种**双写（Trigger `onOpenToggle` + DismissableLayer）。现码换成了另一种：

- `handleToggle` 函数式取反
- `openState.onOpenChange: setOpen`（Radix / LayerStack 直接写绝对值）
- LayerStack `pointerdown` 外点
- Radix `deferPointerDownOutside` 在 click 上再判一次
- 无冷却

壳换了，取反还在。06 / 11 / AFFiNE 对照文里写过的「Anchor + `setOpen(prev => !prev)` = 开→关→开」现码原样活着（`docs/frontend-floating-popover-analysis/11-全生命周期交互状态与竞态条件深度分析.md` BUG-06）。

## 4. 状态机逐步：`.left` / 模型徽标

### 4.1 组件拓扑

```
div._left_gu32j_18
  ModelBadgePicker                          ← ChatCard 受控 showModelDropdown
    ModelBadgePickerMenu                    ← open 默认 true；现由父级传入
      Menu trigger={children}               ← 走 Trigger 分支，不是 Anchor
        拆 Tooltip → cloneElement(button, { 每 render 新 ref, 冷却 onClick })
        Popover.Trigger asChild className="no-drag"
          Tooltip(disabled={isOpen})        ← Menu 再包一次
            button.modelBadge               ← 无 onClick，无 ref
        Popover.Content + useLayerRegistration(anchorRef=triggerRef)
```

受控链（一次 `onOpenChange` 要爬四层）：

```
Popover.Root
  → Menu.handleOpenChange
    → ModelBadgePickerMenu onOpenChange
      → ModelBadgePicker setShowModelDropdown
        → ChatCard / useChatModelPicker
          → 整棵 rightActions 重渲 → 新的 <Tooltip><button/></Tooltip>
          → Menu 再拆再 clone → 匿名 ref 先 null 再挂上
```

### 4.2 第一次点击（开）

按钮没有自己的 `onClick`。打开全靠 Radix Trigger：

| 时刻 | 谁 | 做什么 |
| --- | --- | --- |
| click | Tooltip `handleClick` | 先跑 child（Menu 冷却包装，此时无冷却），再跑 rest = Trigger `onOpenToggle` |
|  | Radix | `setOpen(prev => !prev)` → `onOpenChange(true)` |
|  | 上行 | `setShowModelDropdown(true)` |
| 提交 | Content + Layer 入栈；`triggerRef` 接到按钮（若 clone ref 已提交） |

### 4.3 第二次点击（用户要关）

```
T0  pointerdown / LayerStack
    anchorRef = Menu.triggerRef（匿名函数 ref，不是按钮上的 useRef）
    上一轮 ChatCard 重渲若刚跑过 ref(null)：
      triggerRef.current === null
      contains 失败 → dismissLayer → onOpenChange(false) → 上行关
      markCloseTimestamp()
    若 ref 还在：放行

T1  Radix 认外点（按钮不在 Content 里），推迟到 click

T2  click / Tooltip.handleClick（关键断层）
    ① child = Menu 冷却包装
       若 T0 刚 markClose：isWithinCooldown(50) → preventDefault + return
       **不**调用按钮原 onClick（按钮本来也没有）
    ② rest = Radix Trigger onOpenToggle
       Tooltip **不看** defaultPrevented，照样调用
       onOpenToggle = setOpen(prev => !prev)
       若 T0 已写成 false：prev=false → true → 重开

T3  Radix POINTER_DOWN_OUTSIDE
    context.triggerRef.contains(target)
      Trigger 的 ref 也经过 Tooltip useMergeRefs
      mergeRefs 的 deps 含「每次都新的 childRef」→ 提交期同样有 null 窗口
    失败则 onDismiss(false)，与 T2 的 toggle 对打
```

**和 06 描述的 Dual-Ownership 是同一条河，现码没填。** 多出来的只是：LayerStack 冷却本可以拦住 Trigger，但 Tooltip 把 `preventDefault` 吞了。

### 4.4 为何会「四击」而不只是「两击」

一次物理点击的净效果经常是 **关完立刻开**（用户觉得没点上）。下一次再点，又是同一套。中间再叠：

- 子菜单 hover 80ms / leave 150ms（`ModelBadgePickerMenu.tsx:47-58`）让父级重渲，匿名 ref 再抖一次
- 权限丸若同时开着，LayerStack 顶层可能是权限而不是模型：第一击先卸另一层
- 关闭瞬间 `disabled={false}`，指针还在按钮上，Tooltip 复活（视觉上「闪一下没关掉」）
- 惯性连点落在已经是 `open=false` 的按钮上 → Trigger 再打开

不必精确停在「第 4 击」。用户语言是「点死了」。机制是振荡，不是少绑了一个 listener。

### 4.5 `open = true` 默认值

`ModelBadgePickerMenu.tsx:36`：`open = true`。任何漏传 `open` 的调用方会被当成受控常开。现生产路径 `ChatHeaderControls` 有传。测试 `Wrapper` 自己 `useState(true)`，从开着起步，**从来不测「点徽标第二次该关」**。

### 6.2 加号为什么免疫（现码差，不是「锚点魔法」）

加号也是 Anchor，也包 Tooltip，Button 还有 `:active { scale(0.98) }`（`Button.module.css:72-74`）。它能关，是因为：

1. 打开/关闭是 **if 分支写死值**，不是 `!prev`。LayerStack 就算先写成 false，按钮闭包里的 `showPlusMenu` 若还是 true，第二笔仍是 `set(false)`，不会翻回来。
   （若 pointerdown flush 已经换成 `showPlusMenu===false` 的新闭包，理论上会走 else 再打开。加号能稳，说明 **LayerStack 对 `plusBtnRef` 的 contains 经常成功**，根本没先关。权限丸同结构却取反，contains 失败时必翻。）
2. Menu 的 `onOpenChange` **拒绝 true**：只把 false 交给 `onClose`。Radix 没有第二条「再打开」的通道。
3. 关掉则 `return null`，Content / Layer / DismissableLayer 一起消失。

权限丸三条全反：函数式取反、`onOpenChange: setOpen` 通吃 true/false、Menu 关着也挂在树上。

### 6.3 设置为什么免疫（巧合法，不是更正确）

`SettingsQuickMenu` 仍用 Trigger，而且自定义 `onInteractOutside` 让 Menu **提前 return**，锚点保护被跳过。按 06 的表，这更该双写。它能关，是因为按钮写的是 `handleOpenChange(!open)`：`open` 来自**上次渲染闭包**。菜单开着时闭包里 `open===true`，点自己 → `setOpen(false)`。Radix 外点也是 `setOpen(false)`。两笔同向。

把这一行改成 `setOpen(prev => !prev)`，设置会立刻加入「点死了」名单。这不是可复制的规范，是和权限丸对称的反例。

### 6.4 会话「更多」为什么免疫

`openRowMenu` 合成一次 contextmenu 坐标，打开 `SessionContextMenu`（自己的 portal + 自己的外点，**没有** `useLayerRegistration`）。没有 Radix Trigger，没有 `!prev`，没有和 LayerStack 抢 `pointerdown`。第二次点按钮 = 点在菜单外面 → 菜单关。路径完全不同，不能用来证明 Menu 基座没病。

## 7. LayerStack 登不登记、登记了干什么

### 7.1 谁入栈

全仓生产调用 `useLayerRegistration` 的只有：

- `Menu.tsx:167-180`（`dropdown-menu`，`active=isOpen`）
- `Dialog.tsx`（模态）

**不入栈：** `ui/Tooltip`、`ToastStack`、`SessionContextMenu`、模型子菜单 `mbSubMenu`（只是 Content 里的绝对定位 DOM，没有 `parentId`）。

因此：权限丸开着 → 栈上有一层 `dropdown-menu`，`anchorRef` 指向 `pillBtnRef`。
模型开着 → 另一层，`anchorRef` 指向 Menu 内部 `triggerRef`。
两层同时在（叠开）→ `handleGlobalPointerDown` 只处理**排序后的顶层**（同优先级按 `mountedAt`，后开的在上面）。点权限丸时若模型在顶，先卸模型，权限丸的 toggle 照跑。这就是「点一下只掉了一层、菜单还在、再点又翻回来」。

`LAYER_TYPE_PRIORITY`：`dropdown-menu=40`，`tooltip=60`，`toast=70`。注释写「根除 Toast 拦截死锁」，实现却是「从顶往下找第一个 `dismissible`」，**并没有跳过 toast**。Toast 现在根本不 `register`，这条是死注释，不是本 bug 主因。

### 7.2 登记字段

```ts
{
  id: useId(),                 // Menu 实例级，稳定
  type: 'dropdown-menu',
  dismissible: true,
  onDismiss: () => handleOpenChange(false),
  elementRef: contentRef,
  anchorRef: anchor ?? triggerRef,
}
```

`useLayerRegistration` 用 getter 读 `anchorRef`，避免首帧 stale。**解决不了「ref.current 被写成 null」**：模型那条匿名 `ref: (node) => { triggerRef.current = node }` 每次 render 换函数，React 先 `旧(null)` 再 `新(node)`。窗口里 LayerStack / Radix 读到的就是 `null`，contains 失败，当外点关。

权限丸的 `pillBtnRef` 是稳定 `useRef`。Radix `Popover.Anchor virtualRef={anchor}` **只读** `virtualRef.current`，不覆盖（`@radix-ui/react-popper` `index.mjs:65-74`）。所以权限丸的 contains 失败，不能再用 06 的「匿名 ref」解释，要回到第 3 节的双写 / 叠层 / drag-off。

### 7.3 冷却锁装错地方

`isWithinCooldown` 全仓只有 `Menu.tsx` 的 **Trigger clone `onClick`** 在问。Anchor 按钮（权限 / 思考 / 加号）不问。LayerStack 在 `dismissLayer` 里 `markCloseTimestamp`，权限丸的 `handleToggle` 看不见。

即便 Trigger 问了，Tooltip 仍会调用 `restHandlers.onClick`（Radix toggle）。冷却对「Tooltip + Trigger」= 0。对「无 Tooltip 的 ChatHeaderMore」= 有效。这正好解释「顶栏 ⋯ 能关、模型徽标不能关」。

### 7.4 死接口

`LayerRegistration.onPointerDownOutside` 在 hook 里接了，`handleGlobalPointerDown` **从不调用**。消费方无法在中枢层拦外点。现在全靠「contains 则 return」写死。

`handleGlobalPointerUp` 的 drag-off：锚点上按下、在锚点和 Content 之外松开 → 再 dismiss 一次。权限丸 `:active { transform: scale(0.97) }`（`PermissionModeMenu.module.css:31-34`）会在按下后缩小命中盒。贴边点击时，pointerup 的 `target` 可能已不是药丸 → 额外一次 `setOpen(false)`，再跟 `handleToggle` 对打。加号的 Button 是 `scale(0.98)`，模型徽标**没有** `:active` scale。这是权限丸比思考档更「点死」的一条独立机制（思考档 CSS 无 `:active`）。

### 7.5 Tooltip 抢不抢 pointer

| 问题 | 现码 | 结论 |
| --- | --- | --- |
| portal 挡住药丸点击？ | `Tooltip.module.css:7` `pointer-events: none` | **不抢 hit-test** |
| 菜单开着还露着提示？ | `body[data-floating-active=true] .tooltip { display:none }` | 视觉藏，状态机还在 |
| 开着时 `disabled={open}` | 权限 / 思考 / 模型都有 | 提示应卸；关闭瞬间立刻允许再挂 |
| 拦 click 传到按钮？ | `handleClick` 先藏提示再转发 child / rest | **不吞**；问题是**多转了一次** Radix toggle |
| Tooltip 入 LayerStack？ | 无 | 中枢不管提示互斥 |

所以：「Tooltip 包在 trigger 上是否抢 pointer」——**不抢点，抢状态。**

## 8. 问题清单（同权，不排序）

下列每一条都是现码里站得住的问题。不合并成「一个 Quad-Click」以免修一层当全好。

### 8.1 `.left` / 模型徽标

1. `.left` 被用户认成按钮，源码只是槽位；开关逻辑在另一文件的 Trigger 模式里，排障时会找错文件。
2. `ModelBadgePicker` 的 `<button>` 没有 `onClick`、没有 `ref`，开关所有权交给 Radix Trigger。
3. `ModelBadgePickerMenu` 仍 `trigger={children}`，未迁 Anchor。
4. `open = true` 默认值，漏传即常开。
5. Menu 把 Tooltip 拆开再 `cloneElement` 注入**每 render 新的** ref / onClick（`Menu.tsx:277-313`）。
6. 该匿名 ref 就是 LayerStack `anchorRef`，提交期 `null` → 外点误关。
7. ChatCard 重渲会新造整棵 `children`，放大 ref 抖动。
8. Tooltip `handleClick` 无条件调用 Radix `onOpenToggle`，打穿 50ms 冷却。
9. 模型子菜单定时器在 `open=false` / 卸载时不 `clearTimeout`（11 号分析 BUG-01，现码 `ModelBadgePickerMenu.tsx:47-58` 仍无清理 effect）。
10. 没有「点徽标第二次应关闭」的测试；现有用例从打开态起步。

### 8.2 权限丸

11. 文件头注释宣称已消除 Quad-Click，与真机和现码双写矛盾。假关。
12. `handleToggle` 使用 `setOpen(prev => !prev)`，外点先写 false 时必翻回 true。
13. `openState={{ open, onOpenChange: setOpen }}` 让 Radix / LayerStack / 按钮共享同一个 setter，没有「只允许关」的单向阀（加号有）。
14. Anchor 模式 `context.triggerRef === null`，Radix 原厂「点 Trigger 不关」对药丸无效。
15. Anchor 路径没有冷却；`markCloseTimestamp` 对药丸 onClick 无意义。
16. 关掉后 Menu 仍挂在树上层，`Popover.Root` 继续受控听 `onOpenChange`（加号是 `return null`）。
17. 打开权限丸不关模型 / 思考 / 加号；`onCloseSiblingMenus` 在 ChatCard 未接线。与用户锁「同时只开一个面板」、真机「权限+模型叠开」是同一缺口。
18. 选中模式才 `setShowPlusMenu(false)`，只关加号、不关模型。
19. 每个菜单项再包 Tooltip + 打开即 focus 首项（与 survey/02 残影、点名「少打扰」同源）。
20. `:active { scale(0.97) }` 与 LayerStack pointerup drag-off 叠加，贴边点击多一次 dismiss。
21. 测试「再点一次可关闭」只用 `fireEvent.click`，不模拟 `pointerdown`+flush+`click`，也没有 Tooltip 命中盒。假绿。
22. `class="no-drag"` 无 CSS，不能解释点不关，但说明从 Trigger 时代抄过来的壳没清干净。

### 8.3 基座 `Menu` / LayerStack / Tooltip（两条病共用）

23. 一套基座两套模式（`trigger` / `anchor`），事件所有权不统一。消费方看起来都是 `<Menu>`，关闭语义完全不同。
24. `onPointerDownOutside` 若外部传入，**整段锚点保护被 return 掉**（`Menu.tsx:356-359`）。设置快捷菜单正在走这条。再有人抄设置，会把保护抄丢。
25. `onInteractOutside` 同样：外部一传就不再 `contains` + `preventDefault`。
26. Layer 接口上的 `onPointerDownOutside` 从未被中枢调用。
27. `handleGlobalPointerDown` 同时挂在 `window` 和 `document` 的 capture（靠 WeakSet 去重）。HMR 若丢掉单例另起一份，会出现双中枢（推断，本轮未在 9222 验证）。
28. Tooltip 不是 Layer；`isTooltipSilenced()` 无生产调用方（survey/02 已写）。菜单关的那一帧提示可以立刻复活，造成「没关掉」的错觉，诱发连点。
29. 06 文档仍把权限丸画成 Trigger 结构。后续 agent 若当真理，会修错对象。调研边界已禁「浮层战役已收口」。

### 8.4 思考档 / 融合胶囊

30. 思考档与权限丸同构（函数式取反 + Anchor + 通吃的 `setOpen`），用户没点名不等于没有。
31. `ComposerFusedTrigger.test.tsx` 不覆盖「再点思考档应关闭」。
32. 融合胶囊左模型、右思考是两个独立 `open`，中间只有发丝分割，没有互斥。点左边开模型、点右边开思考，可以叠。

### 8.5 测试与验收缺口

33. `Menu.test.tsx`「Anchor 不振荡」用的是**裸按钮**，生产权限丸是 **Tooltip 包按钮**。假绿。
34. 没有任何用例用真实顺序：`pointerdown`（让 LayerStack 跑）→ `pointerup` → `click`，并断言 `onOpenChange` 的调用序列是 `[true, false]` 而不是 `[true, false, true]`。
35. 没有「权限开着再开模型、点权限丸」的叠层用例。
36. 没有「贴药丸边缘 pointerdown、scale 后 pointerup 落在外面」的 drag-off 用例（基座有裸按钮 drag-off，权限丸没接）。
