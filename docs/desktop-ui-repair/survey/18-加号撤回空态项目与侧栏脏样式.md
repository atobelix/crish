## 0. 结论先行

1. **顶栏加号丑，不是缺一张 PNG，是选错了字形。** 现码用 Lucide `MessageSquarePlus`：方气泡 + 左下尖尾 + 气泡内十字。用户说的「太方、有小尾巴、重心不齐」就是这枚 glyph 的几何。参考顶栏是**圆帽十字**（两条 `line`，`stroke-linecap="round"`），不是对话气泡。产品侧栏「新对话」已经另画了一枚软圆角开口方 + 钢笔，顶栏又是第三套。
2. **撤回钮物理上就在输入盒下面。** `ChatComposer` 的 `.footerActions` 是输入行的兄弟，不是消息流。`ChatUserMessageRow` 还写着「消息级撤回 UI 已废弃」。这是旧战役口径；**本轮用户锁盖过它**。引擎链 `core_session_retract` 可以留，入口要进对话。
3. **空态项目面板仍在吃已删的全局类。** `ProjectPickerMenu` 继续 `contentClassName: 'sort-filter-menu open no-drag'`，项继续 `sort-filter-option`。全仓 `*.css` 对 `.sort-filter-menu` / `.sort-filter-option` **零基座定义**。`ui/Menu` 外壳或可残留一层 `menuContent`，里面是 UA 按钮。`AddProviderMenu.test.tsx` 已禁止这两类名，本菜单没跟。
4. **快捷设置外观段是死 `.ui-segment` + 局部补丁。** 浅/深能切（功能在），皮不对：无 `appearance:none`、无 `border:none`、active 用 `--bg-elevated`（和面板同色，暗色选中态蒸发）、轨道用 `--bg-primary`（暗色比面板更黑，挖坑）、内项 `border-radius: 999px` 盖过 7px 锁。`ui/SegmentedControl` 已经改读 `--button-radius: 7px`，本菜单没接。
5. **`.sidebarTop` 自己没有 `:hover`。** 脏来自孩子：`SidebarNav` 的 `--sidebar-hover`（暖色 `control-mix-color` 4%）叠 `ui/Button ghost` 的 `::before`（`--text-primary` 6%）。两套 hover 色、两套圆角（`--radius-xl` 12px vs `--button-radius` 7px）、搜索是 `div.navItem` 只有其中一套。一 hover 就像换了一张皮。
6. **`sessionActionsBtn` 是 28×28 的 `Button ghost sm` 塞进 44×18 的槽、再被 28 行 `overflow:hidden` 裁。** `Button sm` 还带 `padding: 0 10px`（本类没清），内容盒只剩 8px 放 16px 图标；`::before` 6% 遮罩关不掉。行高 `1` 对会话字 `14px × body 1.5`。真机灰方块不是「缺 ⋯」，是几何和遮罩。

### 1.2 为什么「太方、有小尾巴、重心不齐」

Lucide `MessageSquarePlus` 的公开几何（对话方泡 + 左下尖尾 + 泡内十字）：

- **太方**：气泡在 24 视盒里接近正方形，圆角约 2（lucide 默认 `rx` 量级），不是圆帽十字。
- **小尾巴**：左下角消息指针。16px、1.75 描边时尾巴仍可读，看起来像「方块漏了一角」。
- **重心不齐**：十字画在气泡里，不在 24×24 视盒几何中心。尾巴把 bbox 往左下拉，十字视觉偏上偏右。再塞进 26×26 钮，和两侧 26px Tab 的文字基线对不齐。

同窗已经有两枚更干净的「新」字形，顶栏没用：

| 位置 | 字形 | 文件 |
| --- | --- | --- |
| 侧栏「新对话」 | 自定义 SVG：开口软圆角方 `A4.5` + 斜钢笔 | `SidebarNav.tsx:32-48`（注释写明 rx=4.5、避笔身重合） |
| Composer `+` | `Lucide.Plus` 十字 | `ChatComposer.tsx:399` |
| 参考顶栏 | 圆帽十字 13×13，`stroke-width="2"` `stroke-linecap="round"` | `popovers.js:1548-1550` 动态插入 |

三套「新建」图标并存。顶栏这套最像聊天气泡，最不像「加一页」。

## 2. 撤回钮：在输入框下面，不在对话里

### 2.1 用户锁 vs 现码

用户锁：**放在对话里面（消息流），不是 composer 下方。**

现码物理树（`ChatComposer.tsx:336-445` 一带）：

```
ComposerDropHost
  ├─ 队列
  ├─ 输入（Tiptap / textarea）
  ├─ 附件条
  ├─ hidden file input
  └─ .footerActions          ← 输入盒的兄弟，在它下面
       ├─ .leftActions
       │    ├─ + / ComposePlusMenu
       │    ├─ PermissionModeMenu
       │    └─ .retractBtn    ← 在这里
       └─ .rightActions（模型+思考）
```

`.footerActions`（`ChatComposer.module.css:394-408`）：独立一条悬挂底栏，`width: calc(100% - 32px)`，`margin: -1px auto 0`，圆角只在下沿 `0 0 12px 12px`。视觉就是「白输入盒下面又一条」。撤回与 `+`、权限丸同一行。

`ChatCard.tsx:61-64` 无条件把 `onRetract={state.handleRetract}` 传进 composer；`canRetract={state.messages?.some((m) => m.sender === 'user')}`。无用户消息时钮仍在，只是 disabled（`.retractBtn:disabled` 透明度 0.45，`ChatComposer.module.css:473-476`）。空态欢迎面底下也能看见一枚灰撤回——对话里却没有。

### 2.2 消息流侧已经把入口拆掉

`ChatUserMessageRow.tsx:95-96`：

> 撤回（D5/R6 收口）：消息级撤回 UI 链已废弃——用户发起的撤回唯一路径 = ChatComposer 撤回按钮 → 引擎 `core_session_retract`。

`UserMessageActionsBar.tsx:17-54` 现有：时间、复制、（已固定才出现的）取消固定。**没有撤回。**
`AssistantMessageActionsBar.tsx:49-61` 在**最后一条**助手消息上放「重新生成」——这才是「动作属于这条消息」的现成模式。撤回没有对等物。

用户气泡元栏默认隐藏：`.userMeta` `opacity: 0`，`.userStack:hover` 才显（`ChatMessageRow.module.css:90-101`），高度 `min-height: 22px`。若撤回只进 hover 栏，空画布/不 hover 会找不到；若常显，要和这条 hover 契约对齐。两种都是问题，不是方案。

### 2.3 引擎语义是「上一条 user」，不是「composer 控件」

`useChatHandlers.ts:108-136` `handleRetract`：倒找当前会话最后一条 `sender === 'user'`，再 `transport.send('core_session_retract', { sessionId, targetMessageId })`。回填走 `retract-backfill`（`:101-106`）。
**能力在消息 id 上。** UI 绑在 composer 是历史收口，不是引擎约束。

`canRetract` 是「存在任意 user 消息」，不是「最后一条可撤」。有 user 就亮，不管那条是不是引擎允许的边界。survey/12 §2.3 已记；本条补位置。

### 2.4 测把位置钉死在 composer

`ChatComposer.fallback.test.tsx:122-171`：标题「撤回按钮链不受兜底影响（onRetract 常显可点）」，`getByRole('button', { name: '撤回上一条用户消息' })` 挂在 `ChatComposer` 渲染树上。入口搬家后这条测会红——这是测跟着旧位置走，不是用户锁让步的理由。

`.retractBtn` 自己还是 `Button ghost sm`：高 `--control-height` 32（`ChatComposer.module.css:457-459`）对 Button sm 28；圆角 `--radius-lg` 8px 对 `--button-radius` 7px；图标 `Undo2` 16。底栏比参考金标多一枚 32 图标，survey/12 只记过差距，本轮锁的是**位置**。

### 2.5 本条问题（同权）

- **P-RET-01** 撤回画在 `.footerActions`（输入盒下），不在 `ChatMessageList` / `ChatUserMessageRow`。`ChatComposer.tsx:424-439`，`ChatComposer.module.css:394-408,454-480`。
- **P-RET-02** `ChatUserMessageRow.tsx:95-96` 把消息级入口标成废弃；与本轮用户锁冲突。旧战役口径还在源码里。
- **P-RET-03** `UserMessageActionsBar` 无撤回；助手侧「重新生成」已按「最后一条」挂在消息上，用户侧不对称。
- **P-RET-04** 空会话/无 user 时 composer 仍渲染禁用撤回，欢迎面底下多一枚死钮。
- **P-RET-05** 元栏 `.userMeta` 默认 `opacity: 0`。入口进消息流后，显隐契约未定（常显 vs hover）。不定等于以后又找不到。
- **P-RET-06** `canRetract` 与「最后一条 user / 引擎边界」不是同一谓词。
- **P-RET-07** `ChatComposer.fallback.test.tsx:122-171` 把「撤回在 composer」写成绿灯。搬家必须改测，不能靠这条测挡锁。
- **P-RET-08** `.retractBtn` 32×32 / `--radius-lg` 叠 Button sm 28 / 7px，即便搬家，皮仍和消息流 `.iconBtn` 22×22（`ChatMessageRow.module.css:283-295`）不是一套。

`Button sm` 的 `padding: 0 10px` **本类没清**。`box-sizing: border-box` 下内容宽 = 28 − 20 = **8px**，要放 16px 图标。图标被水平裁切，只剩中间一截三点。行高 1 帮不上：这不是文字行，是被 padding 勒死的 icon-only 钮。`IconButton` 的 `.iconButton { padding: 0; width: var(--btn-h) }` 本就是为这个场景，这里没用。

`.sessionActionsBtn:hover { background: transparent }`（`:435-438`）只关 background，**关不掉** `::before` 6%。真机灰方 = 裁切后的 6% 罩 + `--radius-md` 6px（类）对 `--button-radius` 7px（原子）的圆角打架。

会话字 `--font-size-base` 14 × 行高 1.5 = 21px，落在 28 行里还有 7px 空气。三点钮视觉块是 28（裁后约 18 高 × 28 宽的灰），比文字块大，重心偏右偏满。

时间列 `line-height: 1` + `font-size: var(--font-size-sm)`，和标题 14/1.5、按钮 1，同一行三种行高。
