# 设置按钮圆角 7px 与曲率混乱

> 战役：`docs/desktop-ui-repair/`
> 边界：`00-调研边界.md`
> 调研日：2026-08-19
> 性质：只梳理，不改源码、不实现、不提交。
> 用户锁（盖过旧文）：**设置界面的按钮圆角半径 = 7px**。旧胶囊化主张不得盖过本条。

---

## 0. 读法、锁与诚实边界

### 0.1 本轮锁（写问题用，不劝退）

- 设置界面里的 **按钮**（含 icon button、select trigger、分段项、筛选 choice、可点 chip、侧栏 tab、菜单 trigger）正常就是 **7px**。
- 「各种圆角满天飞」要记全，不要用 `docs/frontend-floating-popover-analysis/08-视觉曲率与按钮圆角退化全景分析.md` 的胶囊化契约盖过本条。
- 08 旧文主张 pill / CTA / Tab 一律 `radius-full`（9999px）。那是旧战役；本文件只把它当历史对照，不当目标。

### 0.2 计算约定（未跑 CDP）

- 真值按 **源码声明 + token 表** 推算，不是 `getComputedStyle` 实测。
- 三档：`:root` / 未设 `data-ui-size` / `medium` → **默认**；`html[data-ui-size='small']` → **small**；`html[data-ui-size='large']` → **large**。
- 设置壳上有 `data-density="compact"`（`SettingsPanel.tsx:261,272,308`），**不改** `--radius-*`。半径只跟 `data-ui-size` 走。
- `var(--x, fallback)`：token 存在时用 token，fallback 只在 token 缺失时生效。`--radius-md, 6px` 在默认档就是 6px，不是「可能是 6」。
- 自定义属性继承：`--button-radius: var(--radius-md)` 写在 `:root`，small/large 改 `--radius-md` 后，`--button-radius` 的计算值也会跟着变。但全仓 **没有任何消费点** 读 `--button-radius`。

### 0.3 没做的

- 未连 WebView2 `:9222` 测计算样式。
- 未穷举每个 `<Button>` 实例的运行时 class 拼接顺序（CSS Modules hash 下，同特异性后加载者赢；下文覆盖点按「选择器是否另写 `border-radius`」判定）。
- 死全局类（无 CSS）的 UA 计算值标为 **未实测**。

### 1.2 对用户锁「7px」的直接结论

默认档 **没有** 任何 `--radius-*` 等于 7px。7px 只出现在：

| 出现位置 | 何时是 7px |
| --- | --- |
| small `--radius-lg` | 仅 small 密度的 lg 档 |
| large `--radius-md` | 仅 large 密度的 md 档 |
| small `--item-radius: 7px` | 仅 small 密度菜单项 |
| 裸写 `7px` / 内联 `borderRadius: '7px'` | 与密度无关 |

因此：用户要的「设置按钮恒 7px」，在 **默认密度** 下 **没有任何 token 能直接表达**。`ui/Button` 的 sm/md 走 `--radius-md`，默认是 **6px**，只有把系统 UI 调到 large 才碰巧变成 7px。

### 1.3 仍在的倒挂（dropdown / item，不是 `--radius-*` 本身）

`--radius-md` 随密度变小/变大是合理的（6 → 5 → 7）。但：

- `--dropdown-radius`：默认 8 **小于** small 的 10。
- `--item-radius`：默认 6 **小于** small 的 7。

这是 08 旧文说过的倒挂，**现在还在**，只是默认 `--dropdown-radius` 已从旧文记录的 `radius-md`(6) 改成了 `radius-lg`(8)，倒挂幅度变小，没有消失。

### 1.4 `ui/Button` 自己的档（全仓基座，设置页大量用）

`apps/crish-desktop/src/components/ui/Button/Button.module.css`：

| 类 / size | `--btn-radius` | 默认 | small | large |
| --- | --- | ---: | ---: | ---: |
| `.button` 默认、`.buttonSm` / `data-size=sm`、`.buttonMd` | `--radius-md` | 6 | 5 | 7 |
| `.buttonXs` | `--radius-sm` | 4 | 3 | 5 |
| `.buttonLg` | `--radius-lg` | 8 | 7 | 9 |

变体（primary / secondary / ghost / plain / danger）**不再**改圆角。08 旧文写的「sm/secondary/ghost/danger = `radius-full`」**已过时**。当前注释写明：普通按钮禁止 9999px（`Button.tsx:6`）。

`.iconButton` 只改宽高与 padding，圆角仍跟 size 走。`.spinner` 是 `50%`（加载圈，合法圆）。

设置页绝大多数 `<Button size="sm">` → **6 / 5 / 7**，默认密度是 **6px，不是 7px**。

## 8. 根因（只诊断）

1. **没有 7px token**。默认 `--radius-md=6`，7 只在 large 的 md 或 small 的 lg。
2. **`--button-radius` 空转**。写成 `var(--radius-md)`，Button 却读 `--btn-radius`，两套口子。
3. **设置全局 CSS 被抽走，类名留下**。choice / chip / shortcut / field / btn-rect / ui-segment 变成 UA 或裸 Button。
4. **局部模块各写各的档**：xs / sm / md / lg / xl / full / 裸 5/6/7/8/9/999。
5. **内联 style 钉死像素**，密度档失效。
6. **旧胶囊战役与新 7px 锁叠在同一批选择器上**（cascadeSelectTrigger、schedPresetChip、QuickMenu segment）。

- 输入框要不要跟按钮一起改 7px：**用户未锁**。现状多为 md=6 或 UA。

## 总结

设置页按钮的圆角不是「差 1px」，而是 **没有 7px 这一档，再叠三套写法**。

默认 token 台阶是 2 / 4 / 6 / 8 / 12，**没有 7**。`ui/Button`（设置页主力）在默认密度是 **6px**；只有系统 UI 调到 large，sm/md 才变成 7px。同一设置窗里还能看到：**2px** 字体应用钮、**4px** Dialog 关闭、**5px** 内联确认、**6px** 基座与内联启用钮、**7px** 添加模型 / 保存密钥、**8px** 侧栏 tab、**12px** 返回与添加服务商、**9999** 模型级联 trigger、**UA 未知** 的筛选 / 快捷键 / 预设 chip。

`--button-radius` 写了没人用。旧 `settings-btn-*` 全局表删了，扩展页还在给 Button 贴 `settings-btn-rect`，等于没贴。旧 08 文要的胶囊已经写进 `.cascadeSelectTrigger` 和若干 pill，**必须按新锁改回 7px，不能再当标杆**。

主界面同样乱：+ 是 8、权限/模型是 4、发送在 8/6/4/圆之间切、顶栏 4、会话 Tab 4、Leaf Tab 6、设置齿轮 12。若只收设置页，主界面仍会满天飞。

验收时（实现波，本文件不做）：设置页所有 **button** 的计算 `border-radius` 应为 **7px**（窗控 / Switch / 头像 / 非交互圆点除外）；不得再把胶囊化旧契约写成通过条件。
