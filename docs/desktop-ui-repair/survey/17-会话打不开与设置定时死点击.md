## 1. 对话根本打不开

用户路径三条：**侧栏点会话** / **顶栏点 tab** / **新建后进入**。三条不是同一条 handler，失败点也不只一个。下面每条都可能单独让「对话打不开」，同权，不合并。

### 1.1 三条入口的事件路径（先锁，避免后文串台）

**A. 侧栏点会话行**

1. `SessionRow` `.sessionItem` `onClick`（`SessionRow.tsx:257-263`）→ `selectThis` → `onSelectSession(s.id)`  
2. `Sidebar.tsx:320` 接到 `handleSelectSession`  
3. `useSidebarHandlers.ts:87-108`：`root.session.openOrFocusSession` + `clearAgentPanelFocus` + `setActiveNav('chat')` + `emitUiEvent('open-chat')`  
4. `compositionRoot.ts:241-242` → `workspaceShellStore.openOrFocusSession`  
5. 已有 tab：对齐 `activeSessionId` + `bindActiveChatLeafSession`（`workspaceShellStore.ts:218-229`）；新 tab：灌 `openTabs` + 同上 bind（`:232-244`）  
6. `emit('open-chat')` → `useChatProjectPicker.ts:46` `setMainSurface('chat')`  
7. `TreeLeafPanel` 用 `leaf.sessionId || activeSessionId` 喂 `ChatCard`（草稿活动叶除外）

和 exclusive / z / pointer：行 click **不**走 `toggleExclusiveMenu`。若此时有 dismissible 浮层，LayerStack 只在 **capture `pointerdown`** 关顶层（`LayerStackManager.ts:509-560`），**不** `preventDefault`，按理 click 仍应冒泡到行。若设置全屏开着，FocusTrap 给 `#root` 打 `inert`（`focusTrap.tsx:113-177`），侧栏整列点击为 0。

**B. 顶栏点会话 tab**

1. `AppTopBar.tsx:138-145` 把 `GlobalSessionTabBar variant="caption"` 放进带 `data-tauri-drag-region` 的 `.main`  
2. `TabStrip` / `renderTab` 里 `onClick={() => selectSession(tab.id)}`（`GlobalSessionTabBar.tsx:214-224, 292-316`）  
3. `selectSession`：**已有 tab 且已是 `activeTabId` → 直接 `return`，不 `activateTab`、不 `openOrFocusSession`、不 `emit('open-chat')`**（`:217-221`）  
4. 仅当 tab 不是当前 active 才 `activateTab`（`workspaceShellStore.ts:247-261`）→ bind leaf

和 exclusive / z / pointer：顶栏 `z-index: var(--z-sidebar, 100)`（`AppTopBar.module.css:19`）叠在侧栏同档。祖先 `data-tauri-drag-region` + CSS `-webkit-app-region: drag`（`AppTopBar.tsx:105,140`，`AppTopBar.module.css:18,63`，`GlobalSessionTabBar.module.css:60`）vs 子级只写了 CSS `no-drag`（`GlobalSessionTabBar.module.css:63-70`），**没有**窗控那种 `data-tauri-drag-region="false"`（`WindowControls.tsx:71-111`）。WebView2 上祖先拖区吞子点击是已知形态 → **tab 点击变成拖窗，对话不切**。exclusive 不直接听 tab；但设置 Dialog 开着时顶栏也在 `#root` 的 `inert` 里。

**C. 新建后进入**

1. 侧栏「新对话」`SidebarNav.tsx:24-52` → `handleNewSession`（`useSidebarHandlers.ts:54-71`）→ `shell.openNewDraftTab` + `emit('open-chat')`  
2. 顶栏「+」`GlobalSessionTabBar.tsx:335-355` 同 `openNewDraftTab` + `emit('open-chat')`  
3. `openNewDraftTab`（`workspaceShellStore.ts:427-461`）：清 draft tab、`activeTabId=null`、`enterDraftMode`、**解绑当前 chat leaf 的 `sessionId`**（注释写明：否则 ChatCard 钉死 leaf → 「点了没反应」）  
4. `TreeLeafPanel.tsx:97-101`：`inDraft && isActive` 才把 `sessionForPanel` 换成 draft id；非活动分屏叶仍钉旧会话  
5. ChatCard 走 `session-empty` 欢迎面（`useChatEmptyKind.ts:82-103`，`resolveChatEmptyKind` 在 `chatEmptyState.ts:113-128`）

和 exclusive / z / pointer：新对话钮不走 exclusive。顶栏「+」同样落在 caption 拖区里。设置 `inert` 同样打死。解绑失败或分屏活动叶判断错 → 新建后主区仍是旧会话，观感「进不去新对话」。survey/15 真机空态是灰画布 +「打开文件」残影、欢迎面文案不出现：即使得了 draft，用户也会判成「没打开」。

### 1.2 `selectSession` 对已激活 tab 早退，切不回对话面

- 证据：`GlobalSessionTabBar.tsx:214-224`。已有 tab 且 `activeTabId` 相同 → `return`。  
- `openOrFocusSession` 对「已激活 tab」仍会 `setActiveSessionId` + bind（`workspaceShellStore.ts:223-226`），**顶栏路径连这步都跳过**。  
- 定时面时 tab 仍高亮当前会话。用户从定时点回这条 tab：handler 空跑，`chatMainSurface` 继续是 `scheduled`（`ChatCard.tsx:188-193` 仍渲染 `ScheduledTasksPanel`）。  
- 侧栏再点同一会话会 `emit('open-chat')`（`useSidebarHandlers.ts:107`），顶栏不会。  
- exclusive：无。z-index：无。pointer-events：若拖区已吞掉 click，连这条早退都走不到。

### 1.3 `bindActiveChatLeafSession` 多 chat 零 unbound 时不绑 —— tab 开了、叶不换

- 证据：`leafBindingHelpers.ts:86-134`。规则 4 明文：「多 chat 且无可用 unbound → 不 auto-split（tab 可开而无 leaf）」。  
- ChatCard 真源是 `sessionIdProp`（`useChatSessionMeta.ts:24-28`：`sessionIdProp ?? selectActiveSessionId`）。leaf 仍钉着别人的 session → 全局 `activeSessionId` 变了，画面不变。  
- `openNewDraftTab` 只解绑 **active** 那一叶（`workspaceShellStore.ts:444-455`）。多 chat 时其它叶仍钉死。  
- exclusive：无直接关系。这是打开链路自己的空洞。

### 1.4 单 chat 本应 rebind；`findChatLeafBySessionId` 先命中会跳过 rebind

- 证据：`leafBindingHelpers.ts:102-107`：已有 bound leaf → 只 `setActiveLeaf`，不改别的 unit。  
- 若错误地存在「同 session 两个 leaf」或 find 命中了看不见的那只，用户点侧栏会把 activeLeaf 切到看不见的 pane。  
- `dedupeSessionLeavesInStore`（`:90,26-31`）在 bind 开头跑；dedupe 失败就会走进这条。

### 1.5 ChatCard 钉 `sessionIdProp`，草稿活动叶才跟全局

- 证据：`TreeLeafPanel.tsx:95-101,159-166`；`main.tsx:33-36` `sessionId={ctx.sessionId}`。  
- `inDraft && isActive` 才用 `activeSessionId`。非草稿时 **永远** `leaf.sessionId || activeSessionId`。leaf 有旧 id 就无视刚 `setActiveSessionId` 的新会话。  
- `useChatSessionMeta.ts:47-54` 在 `activeSessionId`（= prop）变化时才 `setMainSurface('chat')`。prop 不变 → 连定时面都切不回去（顶栏早退时更是双漏）。  
- exclusive：无。

### 1.6 顶栏祖先 `data-tauri-drag-region` 吞 tab / 新建「+」点击

- 证据：`AppTopBar.tsx:105` header、`:140` tabs 容器都是 `data-tauri-drag-region`（布尔真）。窗控显式 `="false"`（`WindowControls.tsx:71-111`）。tab / tabMain / tabAdd **没有**这个属性，只靠 CSS `no-drag`。  
- `.tab { touch-action: none }`（`GlobalSessionTabBar.module.css:144`）再叠一层。  
- `.tabLabel { pointer-events: none }`（`:244`）——点击落到内层 span 时，命中的是「不可点」的标签文字，事件目标是父 button；若 WebView 把 no-drag 算在 target 上而不是祖先 button，拖区仍赢。  
- 关系：**pointer-events / 宿主拖区**，不是 exclusive。这是「顶栏 tab 打不开」最像真机的结构。

### 1.7 设置全屏 Dialog：`inert` + 全屏 `pointer-events: auto` 把主壳点死

- 证据：`SettingsPanel.tsx:248-256` `Dialog variant="fullscreen" dismissible={false}`；`SettingsPanel.module.css:8-19` `.settingsCover` `position:fixed; inset:0; pointer-events:auto; isolation:isolate`；overlay `--dialog-z: var(--z-modal,1000)`（`:261-264`）。  
- `Dialog.tsx:113-124,156-169` 登记 `modal-dialog`，FocusTrap `active={open}`。  
- `focusTrap.tsx:130-177`：body 下凡不含 trap 的子节点（`#root`）`aria-hidden` + `inert`。白名单只有 Radix popper / tooltip / toast（`:63-76`），**不含** `SessionContextMenu` portal。  
- 结果：设置一旦开着，侧栏会话、顶栏 tab、新建、定时 **全部 inert**。用户若关不掉设置（见 §3），观感就是「对话根本打不开」。  
- exclusive：设置 `dismissible:false`，LayerStack 外点 **不会**关它（`LayerStackManager.ts:518-527` 跳过非 dismissible 找下一层）。外点只会误关底下的 dropdown，主界面仍然点不动。

### 1.8 残留 Dialog / 未清 inert：主壳假死

- 证据：FocusTrap 靠 `active` 与 unmount `popTrap`。Dialog `useAnimatedPresence` 退场 150ms（`Dialog.tsx:107-110`），`active={open}` 在 `open===false` 时应释放。  
- 若 `open` 与 `isMounted` 撕裂、或 isolation 引用计数没归零（`inertCounts`，`focusTrap.tsx:53,164-177`），`#root[inert]` 会留下。  
- 推断：实现阶段用 CDP 查 `document.getElementById('root').hasAttribute('inert')` 以及是否还有 `[data-dialog-overlay]`。  
- 关系：pointer-events/inert，不是 exclusive 本体，但是 exclusive 落地后 Dialog 也走同一 LayerStack 登记。

### 1.9 LayerStack 双绑定 window+document capture，外点关浮层但不该吞 click —— 除非有人 preventDefault

- 证据：`LayerStackManager.ts:421-430` 在 **window 和 document** 各绑一次 capture `pointerdown`/`pointerup`/`keydown`。靠 `PROCESSED_EVENTS` WeakSet 去重（`:510-511`）。  
- `handleGlobalPointerDown` **不** `preventDefault` / `stopPropagation`。理论上关菜单后会话行 click 仍在。  
- 但 `Menu.tsx:306-310` 的 trigger 克隆 `onClick` 在 `shouldSuppressMenuReopen` 时 **`preventDefault` 并 return**，连原 trigger `onClick` 都不调。这只打在 Menu trigger 上（快捷设置、排序、模型等），不打在 SessionRow。  
- 风险：若某 exclusive 层 `elementRef`/`anchorRef` 为空，每次 pointerdown 都被判外点（`:529-560`），`dismissedByPointer` 残留到下一次 pointerdown 开头才清（`:513`）。同一击内的 click 仍可能被 `wasTriggerClickAfterDismiss` 误伤 **那个浮层的 trigger**，不是会话行。  
- 所以「侧栏点会话没反应」若不是 inert/拖区，更像 1.3–1.5 的 bind，而不是 LayerStack 吞 click。仍列出，避免把 exclusive 一笔勾掉。

### 1.10 行内「更多」28×28 在 hover 后 `pointer-events: auto`，吃掉行尾点击

- 证据：见 §2。`.sessionItem:hover .sessionActionsBtn { pointer-events: auto }`（`SidebarSessionList.module.css:428-432`）。钮高 = 行高 28，贴右。点行尾 = 点更多，**不会**走 `selectThis`（`SessionRow.tsx:365-368` `stopPropagation`）。  
- 用户点标题区才是打开会话；点右侧「看起来像行」的方块是开菜单。菜单再死（§2.4–2.7）→「这行点了没反应」。  
- 关系：pointer-events 从 `none` 切 `auto` 的 hover 门闩。

### 1.11 行 `onPointerDown` 启动拖拽，阈值 6px；更多钮未 stop pointerdown

- 证据：`SessionRow.tsx:268-276` 左键 pointerdown 冒泡到行 → `startSessionDrag`。更多钮只 `onClick`/`onDoubleClick` stop（`:365-372`），**没有** `onPointerDown` stop。  
- `useSessionListDrag.ts:47,273-398`：位移 > 6px 才 `dragging=true`。纯点击应还能 click。拖出 ghost 后 click 常被取消。  
- 更多钮 28px 方块上的微移容易过阈 → 「点会话/点更多都没反应」。  
- exclusive 的 capture `pointerdown` 与拖的 pointerdown 同击；LayerStack 不 preventDefault，两套并行。

### 1.12 `open-chat` 只在 ChatCard 订阅；ChatCard 未挂则定时面切不回来

- 证据：`useChatProjectPicker.ts:41-68` 在 ChatCard 生命周期里听 `open-scheduled` / `open-chat`。  
- 叶没解析到 chat 视图（`TreeLeafPanel.tsx:152,211-225` 未知面板）时，事件没人收。侧栏仍 `emit('open-chat')`，主面状态不改。  
- `createSessionAndOpenChat`（`sessionAccess.ts:50-54`）会直接 `setChatMainSurface('chat')`，**产品入口不走它**，走 shell draft。

### 1.13 丢 tab 恢复 `useEffect` 与用户手势抢 `openOrFocusSession`

- 证据：`GlobalSessionTabBar.tsx:206-212`：`activeSessionId` 有真实 id 且不在 `openTabs` → 自动 `openOrFocusSession`。  
- 新建 draft 把 `activeTabId` 置 null（`workspaceShellStore.ts:435-438`）。若 `activeSessionId` 还不是 pending draft（`enterDraftMode` 竞态），恢复 effect 会把旧会话重新 open，**盖掉刚新建的空态**。  
- 「新建后进入」失败的一条竞态。exclusive：无。

### 1.14 空态真机不等于「会话已打开」（survey/15 未关）

- 证据：survey/15：真机空叶是灰画布 + UnitChrome「打开文件」Tooltip，欢迎面 DOM 契约在 `ChatEmptyState.tsx` / `chatEmptyState.ts` 但真机看不见标题。  
- `ChatCard.tsx:194-211` 有 `emptyKind` 才挂 `ChatEmptyState`；`chatDocFlow[data-empty=true]` 还 `justify-content:center`（`ChatCard.module.css:35-38`）。  
- 用户从列表点进一个 0 消息会话 / 新建 draft，主区仍像「没打开」。这是打开链路的体验断层，不是「handler 没调」，但用户口径包含它。  
- Tooltip `z-index: 9000`、`pointer-events: none`（`Tooltip.module.css:4-8`）——残影不挡 click，但挡认知。

### 1.15 右键「在此处打开」有自己的路径，失败形态与行 click 不同

- 证据：`useSidebarContextMenu.ts:172-177` `open-current` → 同样 `openOrFocusSession`。先 `setContextMenu(null)`（`:169`）。  
- 菜单本身若被 z-index 挡住（§2.7），用户点不到这项。  
- exclusive：菜单 `onDismiss` 关层；选中项不走 LayerStack `item-select`（自管 `onClick`），和 Menu 基座的 item-select 焦点还原不是一条。

### 1.16 分屏 `onPointerDownCapture={handleActivate}` 会把 leaf 的旧 session 写回 shell

- 证据：`TreeLeafPanel.tsx:103-115,189`。点 pane 内部（含 composer）若 `leaf.sessionId` 有值：已有 tab 就 `activateTab`，否则 `openOrFocusSession(leaf.sessionId)`。  
- 用户刚在侧栏打开 B，bind 尚未把 leaf 改成 B，或 bind 失败 leaf 仍是 A：随后任何落在叶上的 pointerdown（包括为了「进入对话」点主区）会把 shell 拉回 A。  
- 与 exclusive 的 capture pointerdown 同阶段、不同监听器。

## 2. `_sessionActionsBtn_19xt5_805`：与行同高 / 点击死 / 面板被遮

用户给的 class hash 对应 `SidebarSessionList.module.css` `.sessionActionsBtn`（现码 `:403-438`；hash 中的 `805` 是打包行号漂移，规则就是这条）。组件：`SessionRow.tsx:355-381`，`data-testid="session-more-button"`。

### 2.1 钮高度被做成与行同高（28 = 28），视觉撑满行

- 行：`.sessionItem` / wrap 高 28（`SidebarSessionList.module.css:251-266`，`SIDEBAR_SESSION_ROW_HEIGHT`）。  
- 钮：`.sessionActionsBtn` **自己写** `width:28px; height:28px`（`:403-411`），又叠 `ui/Button` `size="sm"` → `--btn-h: 28px`（`Button.module.css:94-101`，`.button` `height: var(--btn-h)` `:30`）。  
- 槽：`.sessionTrailing` 只有 **44×18**（`:375-383`）。钮 `position:absolute; top:50%; transform: translateY(-50%)`，在 18px 槽里上下各溢出 5px，正好铺满 28px 行。  
- `.sessionItem { overflow: hidden }`（`:279`）不裁这条（几何刚好贴边）。  
- 关系：样式，不是 exclusive。pointer-events 命中盒 = 整段行高的右 28px。

### 2.2 `ui/Button` ghost/sm 的皮盖过「小 ⋯」意图（survey/11 未关，exclusive 后仍在）

- `Button variant="ghost" size="sm"`（`SessionRow.tsx:356-360`）。  
- ghost hover `::before` 6% 遮罩（`Button.module.css:51-64,143-149`），`pointer-events: none` 只打在伪元上（`:58`），挡不住整钮变灰方。  
- `.sessionActionsBtn:hover { background: transparent }`（`SidebarSessionList.module.css:435-438`）**关不掉** `::before`。  
- sm 水平 padding `--btn-px: 10px`（`Button.module.css:97`）+ `box-sizing:border-box` 的 28 宽里只剩 8px 给 16px 图标 → ⋯ 被挤、发灰。  
- 圆角：Button `--button-radius: 7px` vs 本地 `border-radius: var(--radius-md)`（6px），同特异性，看注入顺序。

### 2.3 默认 `pointer-events: none`，只有行 hover / focus-within 才 `auto`

### 2.5 exclusive 抑制重开：同一击外点关 + 左键更多 = 死点击

- `toggleExclusiveMenu`（`menuOpenGuard.ts:14-22`）：`shouldSuppressMenuReopen(triggerEl)` 为真则 **整段 return**，不开不关。  
- `wasTriggerClickAfterDismiss`（`LayerStackManager.ts:149-168`）：本 pointer 外点关掉的层，anchor 与 trigger 有包含关系就抑制。  
- 测把这写成绿灯：`SidebarContextMenus.exclusive.test.tsx:188-216,281-324`（「外点关后同一更多钮 click 不重开」）。  
- 真机：先开权限/模型/快捷设置/排序（都是 exclusive peer），再点更多 —— **同一 pointerdown 先关旧层**，click 被判「trigger 重开」→ 菜单不出现 = 「点击没反应」。  
- 第二次再点才开（若 dismissedByPointer 已被下一次 pointerdown `:513` 清掉）。这是 exclusive 回归，不是「从没接线」。

### 2.6 开着再点：anchor 豁免导致 LayerStack 不关，toggle 才关 —— 和行 click 抢

## 3. 连续点击设置：主界面 ↔ 设置应来回切，现在不行

产品里「设置」不是一个按钮。至少四条入口，**没有一条是「同一颗钮 toggle 全屏设置」的完整闭环**（快捷键除外）。

### 3.1 入口地图

| 入口 | 文件:行 | 实际动作 | 用户连点期望 | 现码 |
| --- | --- | --- | --- | --- |
| 侧栏右下齿轮 | `SidebarFooter.tsx:28-35` `openSettings()` | 只把 `showSettingsOverlay=true` | 再点关掉 | **不会关** |
| 用户卡片 | `UserProfileCard.tsx:17-44` → `SettingsQuickMenu` | 开快捷 **下拉**（不是全屏） | 再点关下拉 / 或进出全屏 | 双写者 + exclusive 抑制 |
| 快捷菜单「全部设置」 | `SettingsQuickMenu.tsx:178-181,70-78` | `closeMenu` + `openSettings()` | 再点齿轮应关全屏 | 齿轮已在 inert 底下 |
| Ctrl+, / `toggle_settings` | `AppShortcuts.ts:84-86` `toggleSettingsOverlay()` | 真 toggle | 与按钮不一致 | 快捷键能切、按钮不能 |

### 3.2 齿轮 `openSettings` 是单向闩，没有 toggle

- 证据：`settingsUiStore.ts:90-94` `openSettings` 只写 `showSettingsOverlay = true`（可带 tab）；`:154-157` 才是 `toggleSettingsOverlay`。  
- `SidebarFooter.tsx:34` 调用 `openSettings()`，**不用** toggle。测还把「点齿轮 = openSettings 一次」写成契约（`SidebarFooter.test.tsx:45-60`）。  
- 即便第二击能打到按钮，也只是再 set true。  
- exclusive：齿轮不是 Menu trigger，不受 `shouldSuppressMenuReopen`。它死在单向 API + 全屏遮罩。

### 3.3 全屏盖层把齿轮和侧栏都盖住，物理上点不到第二次

- `SettingsPanel.module.css:8-19` fixed 全视口、`pointer-events: auto`、`isolation: isolate`。  
- Dialog overlay `position:fixed; inset:0; z-index: var(--dialog-z, var(--z-modal))`（`Dialog.module.css:7-12`）= 1000 > 侧栏 100。  
- FocusTrap 再给 `#root` `inert`（§1.7）。主界面「设置」钮在 `#root` 里，第二次 click **事件到不了 JS**。  
- 这是「连点设置不能来回切」的硬结构：第一击打开一块盖住自己的模态，第二击没有落点。  
- exclusive：设置 `dismissible:false`，LayerStack **禁止**外点关（外点不是「再点设置」）。I5 之后 Esc 走层栈钩子，外点仍然关不掉。

### 3.4 用户卡片快捷菜单：`handleOpenChange(!open)` × Radix Trigger × exclusive 抑制 = 连点失败

事件路径：

```
UserProfileCard 按钮 click
  → triggerProps.onClick = () => handleOpenChange(!open)   (SettingsQuickMenu.tsx:186-191,25)
  → 同时作为 Menu trigger 交给 Popover.Trigger asChild     (Menu.tsx:321-330, SettingsQuickMenu.tsx:221-235)
  → Menu 克隆 onClick：shouldSuppressMenuReopen? preventDefault : 调原 onClick  (Menu.tsx:306-316)
  → Radix 自己再 toggle open
  → 登记 dropdown-menu，驱逐其它 exclusive
```

问题同权：

1. **双所有权**（survey/03 §2 已记，exclusive 落地后还在）：受控 `open` + Trigger 内部 toggle + 父级 `!open`。外点关（`onOpenChange(false)`）之后同一击 trigger 再 `!open` → 立刻重开（四击族）。`onInteractOutside` 只改 `restoreOnCloseRef` 然后 return（`SettingsQuickMenu.tsx:224-228`），基座不再做 trigger 豁免。  
2. **exclusive 抑制**：旧层（会话菜单/权限/模型）被这一击 pointerdown 关掉后，`wasTriggerClickAfterDismiss` 若把用户卡片判成被关层的 anchor（包含关系），`shouldSuppressMenuReopen` 吞掉 onClick → **连下拉都不开**。  
3. **LayerStack 点在 anchor 内不关**（`LayerStackManager.ts:535-540`）+ 父级 `!open`：第二次点击关还是开取决于 Radix 与受控谁先写。  
4. z-index：快捷菜单走 `ui/Menu` `--z-dropdown:300`。设置全屏已开时菜单若 portal 到 overlay，overlay 把 `--z-dropdown` 改成 **20**（`SettingsPanel.module.css:261-264`）。卡片在设置打开后已经 inert，通常走不到。若 Dialog 退场 150ms 内 overlay 还在、卡片已解 inert，下拉 z=20 会被 `isolation:isolate` 的 `.settingsCover` 盖住 → 「点了设置没出菜单」。  
5. pointer-events：菜单内容 `pointer-events:auto`（`Menu.module.css:13`）。没有全屏透明挡板（Radix Popover 默认无 overlay），不该挡主界面。挡主界面的是全屏设置，不是这层下拉。

### 3.5 「全部设置」关掉下拉再 `openSettings`，之后只能从盖层里出来

- `SettingsQuickMenu.tsx:178-181` `go()`：`closeMenu({restoreFocus:true})` + `openSettings(tab)`。  
- 全屏 Dialog 挂上 → §3.3。用户以为「设置按钮」还能再点一次退回主界面，齿轮已经在 inert 底下。  
- 必须改点「返回应用」或窗控 X 或 Esc。这和「连续点击设置来回切」不是同一手势，现码也没把齿轮换成 toggle。

### 3.6 快捷键能 toggle，按钮不能 —— 两条写者

- `toggleSettingsOverlay`（`settingsUiStore.ts:154-157`）读当前布尔翻转。  
- `AppShortcuts.ts:84-86` 绑 `toggle_settings`。`AppShortcuts.ts:53-57` 捕获 Esc 直接 `setShowSettingsOverlay(false)`，和 LayerStack / `handleSettingsEscape` 抢 Esc。  
- 用户用鼠标连点（真机口径）走的是齿轮/卡片，不走 toggle。  
- exclusive：`hasActiveModal()`（`LayerStackManager.ts:220-224`）给快捷键守卫用（`AppShortcuts` 是否读它需另条；本文件只记层栈认设置是 modal）。

### 3.7 `dismissible={false}` + 外点不关 + 搜索占用第一次 Esc

- `SettingsPanel.tsx:252` `dismissible={false}`；backdrop `onClick` 仅当 dismissible（`Dialog.tsx:169`）→ 点遮罩不关。  
- `handleSettingsEscape`（`useSettingsNav.ts:54-70`）：有搜索词先清搜索 `return true`（层栈不再 dismiss）。用户连按 Esc 的第一次不像「关掉设置」。  
- 这不是按钮连点，但是「出不去设置」的同源。出不去 → §1.7 对话也打不开。

### 3.8 设置壳把 `--z-dropdown` 降到 20，内部 Select/快捷层叠再裂一次

- `SettingsPanel.module.css:259-268` 注释：为了 overlay 内 Menu 不被 `isolation:isolate` 盖住，把 `--z-dropdown` 改成 20，并给 radix wrapper 写 z-index。

- `ChatCard.tsx:184` `data-empty={state.emptyKind != null ? 'true' : undefined}`。  
- `resolveChatEmptyKind`：**`mainSurface === 'scheduled'` 时返回 null**（`chatEmptyState.ts:104,113-116`）。按契约切到定时后 `emptyKind` 应变 null，`data-empty` 揭掉，`.chatDocFlow[data-empty='true'] { justify-content: center }`（`ChatCard.module.css:35-38`）应关掉。  
- 空会话自己的欢迎面：`.chatEmptyState` 已经 `align-items:center; justify-content:center; margin-left/right:auto`（`ChatEmptyState.module.css:1-16`），`.sessionEmpty { text-align:center }`（`:23-32`）。从空态点定时：本来就居中，再换成 640 列，仍居中，只是内容换成任务表。  
- 从 **有消息的拉满流** 点定时：居中跳变最刺眼。这是用户说的「明显错」。

### 4.5 composer / footer 被 `display:none`，列更显「孤零零居中」

- `ChatComposerWrapper.tsx:101-106`：`mainSurface === 'scheduled'` 时 footer `display: none`（含 composer、ribbons）。  
- 叶里只剩一块 640 顶栏式任务面板，垂直方向靠 flex-start 贴上、水平居中。底下大片空画布。  
- 关系：不是 z-index；是主面切换拆掉了对话家具。pointer-events：footer 隐藏后点不到输入区，只能点任务面板或侧栏「返回」类入口。

### 4.6 侧栏 `activeNav` 与 `chatMainSurface` 两份状态

- `useSidebarHandlers.ts:51,82-85,63,97`：`activeNav` 是 **handler 内部 useState**，`'chat' | 'scheduled'`。点定时只改这份 + emit。  
- 真正切视图的是 layoutStore `chatMainSurface`。没有人在 `open-chat` 时把 `activeNav` 设回（`handleSelectSession` 会 `setActiveNav('chat')`，`:97`；顶栏 tab 不会）。  
- 结果：从定时用顶栏回到对话（若 bind 成功、§1.2 又没早退）时，侧栏「定时任务」钮仍可能 `isActive`（`SidebarNav.tsx:57`），主区已经是 chat —— 或反过来，钮看着普通，主区仍居中。  
- exclusive：无。

### 4.7 定时钮本身是满宽 `navItem`，不是居中；被居中的是主列

- `SidebarNav.module.css:10-35` `.navItem { width:100%; ... }`。点它不会把侧栏变成居中。  
- 不要把「钮被点成居中」理解成按钮自己 `margin:auto`；是 **主列 view 被换成居中容器**。  
- `Button ghost sm` 的 28 高叠在 `.navItem` 的 `min-height: var(--control-height)` 上，和会话更多钮同一套 ghost 皮，但用户这条口径是布局不是钮皮。

### 4.8 从定时回对话的路径会被 §1 全部失败点再次挡住

- `ScheduledTasksPanel` 「返回」只 `setMainSurface('chat')`（`ChatCard.tsx:191`），**不** `openOrFocusSession`。若当前是 draft/空叶，回到的是空态居中欢迎面（仍居中，只是换皮）。  
- `openRunSession`（`ScheduledTasksPanel.tsx:70-81`）`setActiveSessionId` + `onBackToChat`，不保证走 shell `openOrFocusSession` / bind。叶钉死时仍可能「回了但对话不是那条」。  
- 顶栏当前 tab 早退（§1.2）是「点 tab 想离开居中定时面」的死路。  
- 设置 overlay inert（§1.7）时连定时钮都点不了；若先点了定时再开设置，关掉设置后 `chatMainSurface` 仍是 scheduled，主列继续居中。

### 4.9 加号菜单里的「定时任务」与 exclusive 的交接

- 加号开着时是 `dropdown-menu` exclusive。点项：`onClose()`（`ComposePlusMenu.tsx:88-89`）写死关，再 emit。  
- 若 `shouldSuppressMenuReopen` 误伤加号钮，只影响下一次开加号，不阻止已经发出的 `open-scheduled`。  
- 不解释居中，只解释「有时要点两次加号」。居中是 4.2 的 CSS。
