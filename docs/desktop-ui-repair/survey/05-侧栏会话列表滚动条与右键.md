## 1. 滚动条：产品 CSS 没有活契约，Windows 经典条必然露出来

### 1.1 侧栏滚动容器是谁

侧栏有两层：外壳不滚，列表区才滚。

- `Sidebar.module.css:40-48` `.sidebarScroll`：`flex: 1; overflow-y: auto; min-height: 0; padding: 14px 10px`。这是**唯一**会话列表滚动盒。
- `Sidebar.module.css:1-14` `.sidebar`：`overflow: hidden; height: 100%`。外壳裁切，不承担滚动。
- `SidebarSessionList.module.css:1-14` `.listScroll`：**明确不设** `overflow-y`（注释写「滚动交给 `.sidebarScroll`」），`flex: none`。
- 会话行本身 `.sessionItem` / `.sessionItemWrap` 是 `overflow: hidden` 的 28px 行，不会出现第二条列表滚动条。

结论：真机侧栏那条粗条，就是 `.sidebarScroll` 的系统滚动条。不是虚拟列表 spacer 画出来的，也不是右键菜单自己的条（右键菜单没有 `overflow-y`）。

### 1.2 产品有没有定制滚动条？

**没有。侧栏 CSS 零 `::-webkit-scrollbar`、零 `scrollbar-width`、零 `scrollbar-color`、零 `scrollbar-gutter`。**

相关 token 还在，但没有消费者接到侧栏上：

- `tokens.css:46-50` `--tint-scrollbar-thumb`（text-primary 18% 混合）
- `tokens.css:507` `--panel-h-scrollbar-size: 3px`
- 暗色同名 token `tokens.css:566`

少数模块只留了**空档位变量**，等一个已经删掉的全局规则来读：

- `LeafToolTabStrip.module.css:38-41` `scrollbar-width: thin` + `--scrollbar-thumb-width: 3px`（注释仍写「shell-scrollbar.css」）
- `GlobalSessionTabBar.module.css:91-92` `--scrollbar-thumb-width: 0px`
- `DiffCard.module.css:1119-1122` 同上，`scrollbar-width: none`

侧栏、`ui/Menu`、`ui/Select`、模型下拉、排序下拉、底栏快捷菜单**都没有**这些档位。

### 1.3 全局唯一出口已被删，门禁还以为它活着

历史（R2-7）：`shell-scrollbar.css` 是 `::-webkit-scrollbar` 唯一出口，5 个伪元素（本体 / track / thumb / hover / active），thumb 约 4px、轨道透明、圆角满。`style-contract.test.ts:227-243` 注释仍写：

> 基线 5 = R2-7 契约化后唯一出口（shell-scrollbar.css：本体/track/thumb/hover/active 五处）

现状：

- `apps/crish-desktop/src/styles/shell/` 只剩 `shell-reset.css`、`shell-layout.css`。**没有** `shell-scrollbar.css`。
- `index.css:2-11` 只 import tokens / design-system / responsive / z-index / shell-reset / shell-layout / focus / reduced-motion / sr-only / breakpoints。
- 壳皮清剿把该文件当「死皮」删掉（`docs/block-workspace-architecture/shell-rehost/01-视口包含块.md:125` 继续拦截文件名 `shell-scrollbar.css`；`d00fbaaf` 一次删 55 行该表）。
- ratchet 是 **上限 ≤ 5**，不是「必须存在 5」。文件删光后命中数为 **0**，测试仍然绿。

这是契约空洞：治理文档说「唯一出口」，壳皮战役说「禁复活该文件名」，真机于是回落到 WebView2 默认条。

### 1.4 Windows 经典条（上下三角）为何出现

WebView2 = Chromium。未写 `::-webkit-scrollbar` 且 `scrollbar-width` 保持默认 `auto` 时，Windows 宿主画出 **classic theme scrollbar**：约 16–17px 宽、上三角、下三角、灰色轨道。用户开了「始终显示滚动条」时更稳；即便 overlay 模式，未定制的条也比金标粗一个数量级。

金标示例自己在 `reference/chat-composer-component/css/composer.css:21-38` 写了全局 5px webkit 条、透明轨道、圆角 thumb——所以示例图里看不到三角。**这是气质参考，不是把那份 composer.css 整文件搬进产品。** 产品要的是：细、无按钮、颜色走 `--tint-scrollbar-thumb`，而且不能靠复活被禁的 `shell-scrollbar.css` 文件名（壳皮门禁还在）。活出口需要新落点（例如 `design-system.css` / tokens 消费规则，或一份**不叫** `shell-scrollbar.css` 的短契约）。本调研不指定实现文件，只标明空洞。

### 1.5 菜单 / 下拉里的条（同一病因）

凡 `overflow-y: auto` 且无滚动条样式的浮层，都会在选项稍多时画出同一条 Windows 粗条。真机 `9lE3DwHRn9.png` 模型下拉右侧就是三角条。侧栏相关点：

| 位置 | 证据 |
| --- | --- |
| `ui/Menu` 基座 | `Menu.module.css:11-18` `max-height: min(70vh, 360px); overflow-y: auto`，无 scrollbar 样式 |
| 排序与过滤下拉 | `SidebarContextMenus.module.css:85-91` `.sortFilterMenu` 同样 `overflow-y: auto` |
| 排序 flyout | 同文件 `:155-161` `.sortFilterFlyout` 再开一条 `overflow-y: auto` |
| 底栏快捷菜单 | `SettingsQuickMenu.module.css:58-66` `.sbQuickMenu` `overflow-y: auto` |
| 会话右键 | `.contextMenu` **没有** overflow-y（项不多，真机这张图右键本身无条） |
| 模型下拉（侧栏外、同因） | `ModelBadgePickerMenu.module.css:12-17`、`:83-91` 主菜单 + 子菜单都 `overflow-y: auto`；真机已圈 |

`ui/Select/Select.module.css` 自己不滚，滚动走 Menu 基座，同一条病。

### 1.6 粗条对侧栏布局的二次伤害

经典条占 16–17px 布局宽（非 overlay 时）。`.sidebarScroll` 只有 `padding-right: 10px`，没有为系统条留 gutter。后果：

- 行尾时间（`.sessionTime` `max-width: 52px`）和 28px「⋯」钮被条吃掉右侧。
- 标题可用宽再减一截，ellipsis 更早（见 §5）。
- 真机 `rMF9MDKPPN.png`：滚动条夹在会话行与右键菜单之间，菜单被挤到画布。

## 2. Tooltip 孤儿、多枚同时出现、项目名上冒会话标题

用户锁（调研边界 §用户本轮锁 2）：**同一时间只能一个 Hover 提示；鼠标过快移动时一个也不显示。** 真机与源码都与此相反。

### 2.1 真机看见的残影

`rMF9MDKPPN.png`（侧栏展开、右键开着）同时可见：

- 项目行 `cone` 上方胶囊 **「你好啊」**（会话标题）
- `<subagent_task` 行上 **「2026/08/15 03:28」**（绝对时间）
- 「查看全部 (28)」旁一枚 **「更多操作」**
- 「对话」区两枚 **「更多操作」**
- 底部「测试一下」旁一枚标题气泡

`9lE3DwHRn9.png`（侧栏已收起，画布空）：画布中部仍漂着两枚「更多操作」+ 一枚「测试一下」。触发器已经不在视口里。

### 2.2 每一行挂了三套独立 Tooltip

`SessionRow.tsx`：

- `:335-339` 整列标题 `sessionTextCol` 包 `<Tooltip content={displayText}>`（未截断也出全标题）
- `:50-60` `SessionRowTime` 把 `<time>` 包 `<Tooltip content={timeAbsolute}>`（`toLocaleString` 绝对时间）
- `:352-378` 「⋯」按钮包 `<Tooltip content="更多操作">`

没有「仅 ellipsis 时才提示」的判定。金标行尾是常驻相对时间，不靠气泡解释「⋯」。

### 2.3 没有全局单例，也没有 delayShow

`ui/Tooltip/Tooltip.tsx`：

- 每个实例自己的 `visible` / `rect`（`:90-94`）
- `handleShow` 在 `mouseEnter` **立刻** `setVisible(true)`（`:187-215`），没有 delayShow
- `delayHide` 默认 0（`:85`）
- 不调用 `useLayerRegistration`，layer 类型表里的 `'tooltip'`（`layerStackTypes.ts:15`）是空位
- 滚动监听只更新 `getBoundingClientRect`（`:152-166`），**不检查**触发器是否仍在滚动盒可见区内，也**不**在滚轮时 hide

所以：快速划过列表 → 多枚气泡同时存在。这就是「多个更多操作残影」的第一层。用户锁「过快则一个也不显示」完全没有对应逻辑。

### 2.4 滚轮不触发 mouseleave：气泡跟着幽灵几何飞出侧栏

经典 DOM：hover 后用滚轮把节点移出指针，**不发** `mouseleave`。Tooltip 仍 `visible === true`。滚动捕获监听把 `rect` 改成触发器现在的 `getBoundingClientRect()`——`overflow: hidden` **不改变** 这个矩形，节点可以落到侧栏外、画布上、甚至负坐标，再被 `computeClampedPosition` 钳进视口（`tooltipPositioning.ts:164-168`）。

于是出现：

- 侧栏内滚 → 气泡钉在画布（`9lE3DwHRn9.png`）
- 侧栏收起（`.sidebar.collapsed { width: 0 }`，`Sidebar.module.css:22-25`，宽度还有 `transition: width var(--transition-spring-layout)`）→ 列表仍挂在 DOM（只是 `inert` + `aria-hidden`，`Sidebar.tsx:300-304`），收起**不触发** window `resize`，Tooltip 不更新，最后一次合法 rect 留在画布原处

`.listScroll` 还开了 `content-visibility: auto`（`SidebarSessionList.module.css:12-13`），跳过绘制的子树几何更脏。本条是推断加强，真机残影不依赖它也能成立。

### 2.5 「项目名上冒你好啊」不是绑错数据

项目文件夹按钮（`ProjectsSection.tsx:129-143`）**没有** Tooltip。`cone` 上方的「你好啊」来自**第一条会话行**的标题 Tooltip（`SessionRow.tsx:335`，默认 `side="top"`，`TOOLTIP_GAP = 8`）。

几何：项目头 `min-height: 24px`（`.folderHeaderRow`），会话行 28px。第一条会话的 top 提示刚好盖在文件夹名上。真机胶囊压在 `cone` 上，也像把 `conex` 的尾字母挡住。这是**定位重叠**，不是 `p.name` 被写成了会话标题。

同类：时间 Tooltip 默认也 `side="top"`，宽文案（`2026/08/15 03:28`）以行尾 44px 触发器为中心做 `translate(-50%, -100%)`，向左盖住标题。真机 `<subagent_task` 行就是这样。

### 2.6 hover 时时间隐身，但还吃指针；「⋯」与时间叠在同一点

```384:432:apps/crish-desktop/src/components/sidebar/SidebarSessionList.module.css

.sessionActionsBtn { position: absolute; right: 0; opacity: 0; pointer-events: none; width: 28px; height: 28px; }
.sessionItem:hover .sessionTime { opacity: 0; } /* 没有 pointer-events: none */
.sessionItem:hover .sessionActionsBtn { opacity: 1; pointer-events: auto; }
```

### 2.7 浮层互斥没关掉侧栏气泡

层栈本意：登记非 tooltip 浮层 → `body[data-floating-active=true]` → `Tooltip.module.css:52-54` `display: none`。

缺口：

1. **`SessionContextMenu` 不登记层栈**（`SessionContextMenu.tsx` 全文件无 `useLayerRegistration`）。右键开着，attribute 不必置位，侧栏气泡继续画。真机右键 + 多枚「更多操作」同时在。
2. 权限菜单 / 模型菜单走 `ui/Menu`，**会**登记（`Menu.tsx:167-180`）。真机这两层也开着，但「少打扰」和侧栏残影仍在。说明要么运行期 attribute 未挂上，要么 CSS 模块选择器没打中 `#tooltip-root` 里的节点。本调研未 CDP，标为**待实现波核验**。
3. 即便 `display: none` 生效，也只是藏，**不** `setVisible(false)`。浮层关掉后 `updateFloatingActiveState` 清 attribute（另有 150ms 静默窗，`LayerStackManager.ts:284-291`），`visible === true` 的孤儿会立刻回闪。

权限项上的「少打扰」来自 `PermissionModeMenu.tsx:96` 给每个 menuitem 包 Tooltip，不是侧栏绑错。列在这里是因为同一张真机图、同一套 Tooltip 没有单例。

## 3. 右键 / 「更多操作」菜单定位

### 3.1 真机：菜单开在画布上，不在行旁边

`rMF9MDKPPN.png`：会话菜单（在此处打开 / 拆分视图 / … / 删除当前对话 / 导出 Markdown）在系统滚动条**右侧**，整块落在主画布，和叶工具条同一列。不是行内、也不是侧栏内部。

### 3.2 两条打开路径，锚点不同

`SessionRow.tsx:209-221` `openRowMenu`：

- 「⋯」钮（`data-testid="session-more-button"`）→ `syntheticContextMenuEvent(..., { anchor: 'right-center' })`
- 键盘 ContextMenu / Shift+F10 → 同一函数
- 鼠标右键 → `onContextMenu` 直接把浏览器事件交给 `handleContextMenu`（`:261-264`）

`syntheticContextMenuEvent`（`:64-106`）：

- `right-center`：`clientX = rect.right + 4`，`clientY = rect.top + height/2`
- 「⋯」在行**最右**。侧栏约 260px，点落在侧栏右缘再 +4px = **画布坐标**
- 再叠加 17px 系统条，菜单更往右

`useSidebarContextMenu.ts:126-131` 把 `e.clientX/Y` 原样存成 `{ x, y, sessionId }`。注释写「严格保存原始物理点击坐标，不可变锚点」。右键点在标题中部时菜单应在侧栏内；点在行尾或点「⋯」时必然进画布。真机更像「⋯」/ 行尾路径。

### 3.3 自己 portal + 自己钳位，不走 `ui/Menu`

`SessionContextMenu.tsx:157-291`：`createPortal(..., document.body)`，`position: fixed; left/top: contextMenu.x/y`。

本地 `measureMenu`（`:23-51`）按 `offsetWidth/Height` 贴视口 8px 翻折。`SidebarContextMenus.tsx:57-58` 注释声称「坐标钳位单源：`ui/Menu/position.ts`」，**会话右键并没有调用它**。两套几何：Radix 碰撞 vs 手写 clamp。

`useLayoutEffect`（`:115-122`）挂载后再写 left/top。首帧已经按点击坐标画在 body 上——对「⋯」路径就是画布。翻折只防溢出视口，**不会拉回侧栏**。

### 3.4 `--z-context-menu` 未定义

```161:166:apps/crish-desktop/src/components/sidebar/SessionContextMenu.tsx
style={{
  left: contextMenu.x,
  top: contextMenu.y,
  position: 'fixed',
  zIndex: 'var(--z-context-menu)',
}}
```

`styles/z-index.css` 只有 `--z-dropdown: 300`、`--z-popover: 500`、`--z-tooltip: 9000` 等。没有 `--z-context-menu`，也没有 `--z-sidebar-menu`、`--z-sidebar-resizer`、`--z-sticky-bar`、`--z-drag-overlay`（这些在侧栏/模型 CSS 里同样被引用）。无效 `z-index` 等于 `auto`。叶工具条 `.header` 是 `z-index: var(--z-sticky, 2); isolation: isolate`（`LeafToolTabStrip.module.css:21-24`）。菜单和叶工具条抢同一画布带，真机「开在叶工具条上」成立。

### 3.5 层栈 / 互斥：会话右键是化外

`layerStackTypes.ts:11` 预留了 `'context-menu'`。`SessionContextMenu` 不登记。后果：

- 不置 `data-floating-active`（见 §2.7）
- 不参与「同一时间一个点击面板」（用户锁 3）。真机：权限 + 模型 + 会话右键三开
- Esc：右键自己在 window 捕获阶段关（`SessionContextMenu.tsx:142-155`），`useSidebarContextMenu.ts:112-116` document 再关一次；与 Menu 基座的 Esc 并行
- 外点：`document` `click` 用 `menuRef.contains`（`:99-124`）。`sortMenuRef` **从未挂到 DOM**（`ContextMenuFlyout.tsx:186-187` 自承「外部持有但未挂载」）。排序关闭其实靠 Radix `onOpenChange`。`closest('.sort-btn')` 也是死代码——按钮 class 是 `styles.sectionSort`，没有 `.sort-btn`

### 3.6 排序下拉 vs 会话右键

排序走 `ui/Menu` + `anchor={sortTriggerRef}`（`ContextMenuFlyout.tsx:247-275`）。无 trigger 时才用 `sortDropdownCoords` 的 fixed left/top。`useSidebarHandlers.ts:157-162` `handleSortBtnClick` 只 toggle，**不再写 coords**（参数 `_setSortDropdownCoords` 已弃）。正常有 ref 时 Radix 锚在「对话」分区排序钮下，这是对的。

会话右键没有这条锚点路径，所以会飞到画布。两条菜单可同时开：右键 `setContextMenu` 并不关 `sortDropdownOpen`，只在 hook 初始化的 document 监听里顺手关排序。

### 3.7 菜单内容与金标气质

产品右键项多（打开 / 拆分 / 新窗 / 重命名 / 置顶 / 归档 / 分叉 / 复制 ID / 删除 / 导出），三项分割线。金标示例没有这张菜单。问题是**位置和互斥**，不是项数本身。导出项再包 Tooltip（`SessionContextMenu.tsx:277`），菜单开着仍可冒「导出为 Markdown」。

## 4. 虚拟列表、「查看全部」、标题截断

### 4.1 窗口化只服务「对话」区，阈值 48

- `sessionListWindow.ts:11-17`：行高 28、阈值 48、overscan 8
- `useWindowedList.ts:62-68`：仅 `generalSessions` 且未搜索、未拖拽时启用
- 置顶、项目文件夹：**全量 DOM**，不窗口化
- 真机「对话」34 条 < 48，**这张图还没窗口化**。残影不是 unmount 漏 portal（Tooltip 卸载会拆 portal），而是 §2.4 那种「还挂着、已经滚出视口」

窗口化一旦超过 48，会把行卸掉。卸掉的 Tooltip 应随组件消失；**未卸掉但被 spacer 顶走**的行仍走 §2.4。`WindowedSessionUl.tsx:57-71` 上下 spacer 是空 `<li>`，不占 hover。

### 4.2 「查看全部」与窗口 range 不同步

`GeneralSection.tsx:47-51`：未展开且 >10 条时 `visibleSessions = slice(0, 10)`，再把这 10 条交给 `WindowedSessionUl`，而 `generalRenderRange` 按 **全部** `generalSessions.length` 算（`useWindowedList.ts:70-108`）。窗口 start/end 相对 10 条切片是错位的。真机 34 条未过阈值，这条此刻不发作，条数一过 48 就会错切。

同文件 `:148-164`：未展开时仍把 `generalSessions.slice(10)` 全量挂进 `data-expanded="false"` 的手风琴（CSS `display: none`，`SidebarSessionList.module.css:33-35`）。等于「查看全部」按钮只是把**另一份已经挂上的隐藏行**显示出来——而展开态其实改的是 `visibleSessions` 全量，隐藏块在展开时又不渲染（`!showAllGeneralSessions`）。两套模型拧在一起：

- 收起：主列表 10 条 + 隐藏 DOM 里其余全部（含各自 Tooltip）
- 展开：主列表全量，隐藏块卸载

`ProjectsSection.tsx:176-220` 同类：默认 6 条，其余挂在 `data-expanded="false"` 里；「查看全部 (N)」是 `<ul>` 里的 `<div>` + 一个 `li.sessionItemWrap` 里的 `Button.sessionItem`。无效 HTML（ul 子元素不是 li），「查看全部」视觉上就是一条浅色会话行。

真机：项目下「查看全部 (28)」，对话下「查看全部 (34)」。金标没有这级折叠，示例条数也少。产品要分组折叠可以，但现在的「假手风琴 + 切片 + 窗口 range」三套并存会制造隐藏行上的幽灵 Tooltip，并让长列表行为不可预测。

项目 6 / 对话 10 两条阈值还不一致。

### 4.3 标题截断是多层吃宽度，不是单纯 ellipsis

CSS：`.sessionText` `overflow: hidden; text-overflow: ellipsis; white-space: nowrap`（`SidebarSessionList.module.css:347-355`）。行高锁死 28px，注释写「禁止 multiLine」（`SessionRow.tsx:224`）。`sidebarMeasure.ts` 的 Pretext 双行 44px **算了没用**：`useWindowedList.ts:42-48` 全写成 `SIDEBAR_SESSION_ROW_HEIGHT`。

再叠加：

- `.sessionTrailing { width: 44px }` 常驻留白（金标时间更窄，且不给「⋯」再留一列）
- Windows 条 16–17px
- `.folderSessions { padding-left: var(--space-2_5) }` 项目内再缩进
- 数据层 `SESSION_TITLE_MAX_LEN = 28` 码点（`sessionTitle.ts:72`）只打自动派生标题；`sessionListDisplayTitle`（`:555-561`）对已有 title **不**截。真机长标题是 CSS 截的

真机：`请帮我在 c/Softwar…`、`你好，请用一句 …`、`分支: 你好啊。分析…`。金标同等宽度能完整显示「重构IPC缓冲通道」「CSS滚动条抖动治理」，因为没有系统条、没有 44px「⋯」槽、hover 不藏时间。

### 4.4 键盘焦点选择器与 CSS Module 对不上

`useSidebarSessionList.tsx:253-270` 导航后 `querySelector('[data-session-id="…"] .session-item')`。行 class 是 `styles.sessionItem`（hash），**没有**全局 `.session-item`。`data-testid="sidebar-session-item"` 在（`SessionRow.tsx:248`）却没用。↑↓ 选会话后焦点可能落不回行。

## 5. Hover 背景、行高密度、点击果冻

### 5.1 果冻（用户锁 1：去掉）

- `.sessionItem:active { transform: scale(0.985) }` + `transition: ... transform var(--transition-press)`（`SidebarSessionList.module.css:275-285`）
- `ui/Button` `.button:active { transform: scale(0.98) }`（`Button.module.css:72-74`）
- 「⋯」、排序、分区 +、查看全部、底栏齿轮都是 `Button`，按下都会弹

金标会话行没有按压缩放。

### 5.2 Hover / 选中

- `--sidebar-hover` / `--sidebar-active`：亮色 4% / 8% `control-mix-color`（`tokens.css:92-100`），暗色 5% / 8% text-primary（`:608-616`）
- `.sessionItem:hover` 用 `--sidebar-hover`（`:295-299`）；`.navItem:hover` 同样（`SidebarNav.module.css:44-48`）
- 底栏用户卡 hover 走 `--bg-hover`（`Sidebar.module.css:94-96`），与列表不是同一 token
- 「⋯」在 `Button` ghost 上还有 `::before` 6% 遮罩（`Button.module.css:52-65`），叠在行 hover 上，行尾一块更脏
- `.sessionActionsBtn:hover { background: transparent }` 只抵消模块背景，抵消不了 Button 伪元素

金标是整行一颗浅胶囊，右侧时间还在。产品 hover = 行染 + 时间消失 + 「⋯」出现 + 「更多操作」气泡。

### 5.3 密度

- 行：28px 固定，列表 `gap: 3px`（`.folderSessions`）
- 分区 label `min-height: 24px`，分区之间 `margin-bottom: 8px`（`.section`）
- 顶栏「新对话 / 定时任务 / 搜索」`min-height: var(--control-height)`（默认 32px 量级），比会话行高
- `.sessionItem` `font-size: var(--font-size-base)`（14px），`line-height: 28px`；时间 `font-size: var(--font-size-sm)`（13px）

金标顶栏与行高更接近，时间字重更轻。产品 14px 中粗 + 13px 时间 + 44px 槽，窄侧栏更容易截字。这不是「要加高行」，是 **28px 里塞了时间、⋯、气泡、系统条** 的冲突。

`.sessionItem.multiLine` / `.hasProjectLabel` / `.sessionSearchSnippet` 仍有 CSS，但 TSX 强制 `display: none` 副行（`SidebarSessionList.module.css:357-362`）。搜索命中 snippet 算了不画（`SessionRow.tsx:200` `void searchHit`）。搜索时行高仍 28，窗口化在搜索期关闭（`shouldWindowSessionList` + `isSearching`）。

## 总结（给主控）

**覆盖了什么。** 侧栏文件域（`Sidebar*.tsx/css`、`session-list/*`、`SessionContextMenu`、`ContextMenuFlyout`、`SidebarFooter` / `UserProfileCard` / `SidebarNav`）对照真机两张图和金标气质：滚动条、Tooltip 残影与错位、右键/更多定位、虚拟列表与「查看全部」、hover/行高/果冻、分组、底栏用户卡，以及 Menu/Select 下拉条同因。证据以 `路径:行号` 和截图现象为主。

**没覆盖什么。** 未启动工作台、未 CDP `9222` 核验 `data-floating-active` 运行期是否挂上；未量 WebView2 滚动条是 overlay 还是 gutter（真机有三角，足够定性）；未跟 Composer 互斥刀抢「少打扰」/模型重复（只作为同屏证据）；未评设置页 7px。`cone` 是截断还是短名，未读用户项目库。

**文档落点。** 仅本文件 `docs/desktop-ui-repair/survey/05-侧栏会话列表滚动条与右键.md`。实现波未开始。滚动条活出口与壳皮「禁 `shell-scrollbar.css` 文件名」冲突，总案必须另找落点，禁止把 1.4 万行旧壳皮整包复活。

**额外发现。**

1. 会话右键不用层栈、不用 `ui/Menu`、`--z-context-menu` 未定义——浮层战役「已收口」文档与真机不符（调研边界已禁止把旧收口当真理）。
2. `style-contract` 滚动条 ratchet 在出口删光后仍绿，门禁空洞。
3. 「查看全部」隐藏手风琴会把未展示会话（含 Tooltip）留在 DOM。
4. 键盘导航 `.session-item` 选择器与 CSS Module 失配。
5. `UserProfileCard` 用户名/工作区硬编码。
6. 金标 hover 保留时间；产品 hover 换成「⋯」，是残影和截断的放大器，不是小视觉差。

**工作流。** 侧栏问题是「全局 Tooltip 单例 + 滚动条契约 + 会话菜单锚点」三件事绞在一起，不宜只改 `Sidebar.module.css` 一条 `::-webkit-scrollbar` 当收工。建议总案把 Tooltip 单例（含快移取消、clip/scroll hide）和滚动条活出口当成跨 `survey/01–08` 的共用底座，侧栏消费它们，而不是侧栏私有再写一套。本子代理按任务书未写 `docs/agent-roles/shared-append/`。
