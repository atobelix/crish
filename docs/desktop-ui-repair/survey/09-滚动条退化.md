## 1. 结论

产品 **没有任何** `::-webkit-scrollbar` 规则（`apps/crish-desktop/**/*.css` 命中 0）。全局契约文件 `styles/shell/shell-scrollbar.css` 已随壳重挂删除且入口不再 import。凡 `overflow: auto|scroll` / `overflow-y/x: auto|scroll` 的容器，在 Windows WebView2 上都会露出 **系统经典粗条 + 上下三角**，而不是细轨/overlay。

用户点名的三处都成立，且不是这三处独有：侧栏会话列表、模型下拉（及同一条 Menu 基座上的所有下拉）、设置快捷键页（以及设置右栏整列）都是未修饰的滚动容器。

设置页「右侧整条被圈 / 右侧被裁 / 露黑」**和滚动容器直接有关**：`.coverContent` 自己做纵向滚动，系统条占布局宽、轨道跟页面 token 脱节；再叠加 `overflow-x: hidden`、`contain: strict`、卡片 `overflow: hidden`、快捷键皮表类名无样式。

`scrollbar-width: thin` / `scrollbar-color` **不能**在本宿主上顶掉 Win32 经典条（见 §3）。参考仓 `docs/composer-preview` 有全局细条，产品没有；**不要整页抄 reference**。

## 3. WebView2 吃不吃 overlay / `scrollbar-width`

本仓 **没有** `additionalBrowserArgs` / `OverlayScrollbar` / `FluentOverlayScrollbars`（全仓无匹配）。

| 机制 | 在本产品 Windows WebView2 上的实际效果 |
| --- | --- |
| 未修饰的 `overflow: auto\|scroll` | 走 Win32 原生主题条：约 16–17px 宽、上下三角、系统灰/黑轨道。**真机所见。** |
| Overlay 滚动条 | Edge 浏览器在 Win11 可开 Fluent overlay；WebView2 默认不开。CSS **没有** 等效开关（`overflow: overlay` 已废）。未设 Chromium feature flag → **不吃 overlay**。 |
| `scrollbar-width: thin` + `scrollbar-color` | Chromium 121+ 语法合法，多数只把原生条略收窄，**三角还在**，仍非 overlay，也不跟 `--tint-scrollbar-thumb` 画成细胶囊。本仓多处只写了这两行，真机仍会是系统条。 |
| `scrollbar-width: none` / `-ms-overflow-style: none` | 意图藏条。无配套 `::-webkit-scrollbar { display:none }` 时，旧 WebView2 可能仍露出系统条。 |
| `::-webkit-scrollbar` | Blink/WebView2 **会**吃：替换原生主题，去掉三角。参考仓走这条。产品现为 0。 |
| `scrollbar-gutter: stable` | **预留**系统条宽度。契约没了以后，等于先挖一条 16–17px 空槽，条一出现更刺眼。 |

`color-scheme`：亮 `tokens.css:531` `light`，暗 `:765` `dark`。系统条跟 OS 主题走，**不跟** `--bg-primary` / `--tint-scrollbar-thumb`。暗页 `hsl(0 0% 5%)` 右侧会贴一条更黑或 3D 灰的系统轨——「露黑」的一条机制。

## 5. 设置页裁切 / 露黑，是否和滚动容器有关

**有关。** 不是「内容碰巧画到黑边」，是滚动盒 + 系统条 + 裁切叠加。

1. **系统条占布局宽**
   `.coverContent` 非 overlay。经典条从内容盒扣约 16–17px。右 padding 32px 被条吃掉一截，行控件更贴边。用户圈的是扣完以后的整条右缘。

2. **`overflow-x: hidden`**（`.coverContent:201`）
   横向溢出直接剪。未造型的 `shortcut-key-btn` / 原生 search 比原皮更宽时，右侧键帽被切。

3. **`contain: strict`**（`:203`）
   含 size + layout + paint + style。paint 把子孙画在 padding box 内。和 `overflow-y: auto` 叠在一起：条在盒内，盒外不允许渗。滚动条轨道若系统色是近黑，右缘就是一条黑带。

4. **卡片再裁一刀**
   `SettingsUI.module.css:63-68` `.settingsUiCard { overflow: hidden }`。行是 flex（`.settingsUiRow:72-85`），控件 `flex-shrink: 0`（`.settingsUiRowControl:141-146`），正文 `min-width: 0`。控件宽过卡片时被卡片剪，不是滚到看不见。

5. **露黑的两条色**
   - 暗色 `--bg-primary: hsl(0,0%,5%)`（`tokens.css:542`）铺满 `.coverContent`；页体 `max-width: var(--settings-content-max, 720px)` 居中（`SettingsUI.module.css:1-8`，token `:521`）。宽窗下，720px 栏目和右缘系统条之间是近黑空带，再加系统轨。
   - 系统条不读 token。亮色页是米灰底 + 3D 灰条；暗色页是近黑底 + 更黑/系统灰条。

6. **双滚**
   `SettingsPanel.tsx:208-223` `handleRootWheel` 把根上的滚轮灌进 `coverContent`。模型/技能等 tab 内部还有 `overflow-y: auto`（§6.3）。外条（整列）和内条（分栏）可以同时是系统条。快捷键页主要是外条。

7. **和「快捷键皮表死亡」叠加**
   无样式的原生 search / button 把行撑宽 → 更容易命中 2+4 的裁切。圈「右侧被裁」时，条、切边、裸控件是一起被看见的。

## 9. 额外发现（任务内连带）

1. **门禁方向反了**：`SCROLLBAR_BASELINE = 5` 只封顶，不保底。删光伪元素测试仍绿。无法防止本次这种「契约文件消失、全面退化」。
2. **`--scrollbar-thumb-width` 是死变量**：三处模块在设，零处规则在读。注释还指向已删文件。
3. **`--tint-scrollbar-thumb` 被挪用**：`ScheduledTasksPanel.module.css:177,222` 拿它当 `box-shadow` 描边，不是滚动条。定时任务真机另有「筛选项退回浏览器默认方框」（`IIhg105wRE.png`）；选择器 `.settings-select-trigger` 的全局皮同样已死。

5. **内联 `overflowY:'auto'`**（`FileTreeView.tsx`、Diff 三视图）绕过 CSS module，即使以后有全局契约，也容易漏。
6. **xterm**：`TerminalCard.module.css:422-424` 给 `.xterm-viewport` 设 `overflow-y: auto`，终端条是第二套系统条。
7. **浮层方案把「原生滚动条」写成验收项**（如 `docs/frontend-floating-popover-analysis/plans/01-…` GEO 用例「内部生成原生垂直滚动条」）。几何上要内滚，视觉上不该是 Win32 粗条。两场文档口径打架。
