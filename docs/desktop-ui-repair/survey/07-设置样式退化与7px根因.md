### 2.2 「套了 CSS module 但哈希没中」——对黑框主体为假，对个别文件为真

黑框主体 **根本没套 module**，所以不存在「哈希没中」。

三种「套了但没中」的变体，不要混：

| 变体 | 含义 | 本战役是否成立 |
| --- | --- | --- |
| A. 写了 `styles.foo`，构建没注入 | module 管道坏了 | **否**。侧栏 `.sidebarTab`（`SettingsPanel.module.css:207-226`）仍有 `border:none` + `--radius-lg`，设置壳没整页退回 UA。 |
| B. 写了全局字符串，定义文件已删 | 选择器在运行时 0 命中 | **是。黑框主因。** 全仓 `*.css` 对 `.ui-segment {` 的基座定义为 0；只剩 `SettingsQuickMenu.module.css:88` 的 **后代覆盖** `:global(.ui-segment-item)`。 |
| C. module 里是 camelCase，TSX 只写 kebab 全局名 | 文件还在，字符串对不上哈希 | **是，但偏模型头。** `ProfileHeader.tsx:42-49` 只写 `"mrd-head"` / `"mrd-title"`，**不 import** `ModelsSettingsTab.module.css`；同文件 module 里是 `.mrdTitle`（`:199`）。这是第三种「没中」，不是外观连体钮的主因。 |

`UsageChart` 是对照实验：同样挂了 `ui-segment-item`，但 **另外** 绑了 `styles.chartSegmentBtn`，且该规则写了 `border: none`（`SettingsUsageTab.module.css:212-217`）。用量「近 7 日 / 近 14 日」**不应**退化成 UA 黑框——证明病根是「有没有自己的 border/background 规则」，不是 `ui-segment-item` 这个字符串有魔法。

### 2.3 「全局 button reset 被拿掉」——作为主因不成立

现网全局 reset（`styles/shell/shell-reset.css:10-14`）：

```css
* {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}
```

**没有** `button, input, select { appearance: none; border: none; background: …; font: inherit }`。

`design-system.css` 只有 elevation / 动画 / `[data-panel]`。
`focus-visible.css:19-24` 只在 `:focus-visible` 时给 button 去 outline、加 focus-ring，**不改默认边框**。

历史皮从来不是「全局 button reset 压住 UA」，而是 **专属类**（`.ui-segment-item`、`.settings-choice-btn`、`.settings-field-input`）各自抹 UA。专属类随 6 张表一起删掉后，UA 按 `color-scheme`（`tokens.css:531` light / `:765` dark）长出系统按钮边框；再叠加 `* { padding:0 }`，相邻 `<button>` 变成「无内边距的黑框连体」。

所以：

- 不是「以前有一条全局 button 抹平，后来被误删，UA 反弹」。
- 是「以前有一组 **控件专属** 规则，被当成死代码删掉，UA 从第一天起就等在下面」。

### 2.4 题 1 一句话

**套了全局类名（不是 CSS module）；定义文件已删，等于选择器 0 命中；全局从不对 `button` 做 UA 抹平，`*` 重置还在且加重连体感。**

## 4. 题 3 · `--button-radius` vs 7px

`tokens.css:345`：`--button-radius: var(--radius-md);`
`tokens.css:264`：`--radius-md: 6px;`
`tokens.css:820`（`[data-ui-size='small']`）：`--radius-md: 5px;`
`tokens.css:896`（`[data-ui-size='large']`）：`--radius-md: 7px;`

| 档 | `--radius-md` | `--button-radius` 计算（若有人读它） |
| --- | ---: | ---: |
| 默认 / 未设 / medium | 6 | **6** |
| small | 5 | 5 |
| large | 7 | **7**（唯一碰到用户锁的档） |

全仓检索 `--button-radius`：源码 **只有这一处定义**。`ui/Button` 不读它：

```11:14:apps/crish-desktop/src/components/ui/Button/Button.module.css
  --btn-h: 32px;
  --btn-px: 12px;
  --btn-fs: var(--font-size-base, 14px);
  --btn-radius: var(--radius-md, 6px);
```

`border-radius: var(--btn-radius)`（同文件 `:34`）。sm/md 都是 `--radius-md`。

设置壳还写了 `data-density="compact"`（`SettingsPanel.tsx:261,272,308`）。全仓 **0 条** `[data-density]` CSS。密度属性是空操作；半径只跟 `html[data-ui-size]` 走。

因此用户锁「设置按钮 7px」在当前 token 几何里：

1. **默认密度永远 6px**（走原子的按钮）。
2. 只有把「UI 密度」拨到「宽松 / large」才碰巧 7px——而拨密度的控件本身是 UA 黑框。
3. 死类裸按钮是 UA 圆角（WebView2 约 2–4px 或 0，未实测），与 6/7 都无关。
4. 08 胶囊残渣仍在：`SettingsQuickMenu.module.css:90` `border-radius: 999px`；`ScheduledTasksPanel.module.css:105` 对话面 chip `999px`；`StatusDiagnosticsPanel` / `ExternalSessionImport` / `SettingsDevicesTab` badge 亦 `999px`。这些 **会盖过** 任何未来的 `--button-radius: 7px`，除非先拆掉。

08 旧文要胶囊；本轮锁要 7px。两套目标写在同一批残留选择器上。实现时若先「恢复 .ui-segment」却把 999px 带回来，就是用旧战役盖过新锁。

## 6. 题 5 · Toast / 侧栏「更多」不是同一张皮

### 6.1 机制对照

| | 设置黑框连体 | Toast「已自动获取 7 个模型」 | 侧栏会话「更多」灰方块 |
| --- | --- | --- | --- |
| 皮还在吗 | **否**（定义文件已删） | **是** `overlay/ToastStack.module.css` | **是** `SidebarSessionList.module.css:402-437` |
| 走原子吗 | 分段/筛选 **否** | 关闭/撤销走 `ui/Button`，再被 module 改皮 | **是** `Button variant="ghost" size="sm"`（`SessionRow.tsx:353`） |
| 退回 UA 吗 | **是** | 否（自定义胶囊 + 竖缝来自 flex gap + × 图标钮） | 否（28×28、`--radius-md` 6px、hover 才显示） |
| 圆角 | UA | 容器 `--radius-lg` **8px**；× 钮 `--radius-xs` **2px** | `--radius-md` **6px** |
| 用户锁 7px | 未参与 | 未参与 | 未参与 |

Toast 的「堵」来自自己的视觉：半透明胶囊、`×` 用 ghost Button 再覆盖 `toastDismissBtn`（背景 `--tint-active`、padding 0 4px）。这是 **有皮但丑**，不是没皮。

「更多」灰方块来自：ghost 原子钮 + 行内绝对定位 28px 方盒 + 默认 6px 角。`IconButton` 存在但没用。这也是有皮但丑。

### 6.2 上层同源（不要说成同一套 class）

三处共享的是 **迁移态**，不是同一张 stylesheet：

1. 原子层已经在仓库里；
2. 业务仍用「全局类名 / 局部覆盖 / 原子 + 再覆盖」三条路；
3. 清剿只砍了全局表，没有把消费者改到原子，也没有把 module 补全。

所以修设置黑框 **不会**自动修好 Toast / 「更多」；共用的只是「谁才是按钮真源」这个问题。若实现时把 Toast 关闭钮、会话更多、设置分段都接到 **同一套 7px 按钮契约**（而不是分别打补丁），才算同一根因落地。用户锁写的是设置按钮 7px，08 胶囊不得盖过——Toast 目前 8px 胶囊、更多 6px 方块，都不是 7px。
