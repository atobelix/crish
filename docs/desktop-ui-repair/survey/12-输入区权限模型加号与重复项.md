## 0. 结论先行

1. **真机「权限 + 模型叠开、输入区被压住」与源码一致，不是看走眼。** 底栏六个可点控件里，至少四个各自持有一份 `useState(open)`；`ChatCard` 不传 `onCloseSiblingMenus`；`LayerStackManager.register` 入栈但不关兄弟层。点击一个面板按钮不会关另一个。
2. **「OpenCode Go 订阅」连续两行不是 React `key` 撞同一 id。** Picker 按 `p.id` 渲染、`normalizeProviderProfiles` 只按 id 去重。同名来自两份产品数据：`profileCatalog.DEFAULT_PROFILES` 的 `opencode-go`，以及设置页 `modelsPresets.PRESETS` 的 `preset-opencode-go`（`addFromPreset` → `createCustomProfile` 新 id、拷同名）。`listPickerProfiles` 不过滤同名。
3. **权限表本身没有把「计划」绑成「少打扰」。** `plan.matrixHint = 只读`，`full.matrixHint = 少打扰`。真机「计划项上冒少打扰」更像 Tooltip 无全局互斥 / 孤儿门户，不是 `permissionModeMeta(opt.id)` 写反。
4. **金标与产品底栏不是同一物件。** 金标是单胶囊：附件卡在输入上方、盾形权限、绿圆发送在底栏右。产品是「大输入盒 + 发送挤在输入行 + 更窄的悬挂底栏」，发送用 `variant=primary`（`--accent-color` 暖深色）+ `CornerDownLeft`，不是绿圆上箭头。本轮只记差距。
5. **斜杠 / @@ 目录树 / 附件条 / 拖放 / 会话右键都不进同一套「只开一层」协议。** 斜杠与目录树是裸 Radix；会话右键是自绘 portal；Tooltip 不调 `isTooltipSilenced()`。浮层战役文档不能当已收口。

## 2. 底栏每个控件：开合与样式

用户锁：点击果冻去掉；Hover 同一时间只能一个、过快则一个也不显示；**所有点击后展开的面板按钮同一时间只能开一个**。

### 2.1 `+`（添加）

**开合**

- 状态在 `useChatSend.ts` 37：`const [showPlusMenu, setShowPlusMenu] = useState(false)`，经 `useChatComposerProps` 交给壳。
- 按钮 `ChatComposer.tsx` 389–397：已开则关；未开则 `setShowPlusMenu(true)` 再 `onCloseSiblingMenus?.()`。
- `ComposePlusMenu` 是 `anchor={restoreFocusRef}` + 受控 `open`（`ComposePlusMenu.tsx` 94–111），不走 `Popover.Trigger`。
- **兄弟关闭是空调用。** `onCloseSiblingMenus` 在 `ChatComposer.tsx` 113 是可选 prop。`ChatCard.tsx` 45–76 整段不传。历史 F-014（`docs/organization/audit/plan/99-EXECUTION-FINDINGS.md`）曾把该回调接成 `setShowPlusMenu(false)`，一点 `+` 永远打不开；T5.4 **拆掉接线、没有换成「关权限 / 关模型 / 关思考 / 关斜杠」**。`+` 能开，但开它不会关别的面板。
- 关 `+` 也不会关已开的权限 / 模型 / 思考。权限 `onChange` 里才 `setShowPlusMenu(false)`（`ChatComposer.tsx` 417–421），那是选完模式，不是开权限时。

**样式 / 交互**

- `+` 是 `Button variant="ghost" size="sm"`（`ChatComposer.tsx` 379–399）。`Button.module.css` 72–74：`:active { transform: scale(0.98) }` —— 点击果冻还在。
- 打开态只加 `styles.isOpen` 背景（`ChatComposer.module.css` 441–445），与金标「小十字、无厚底」比偏大：宽高 `--control-height`（默认 32px，`tokens.css` 438）。
- 菜单项另有 `ComposePlusMenu.module.css` 41–44 `scale(0.98)`。
- 每一项再包一层 `Tooltip`（`ComposePlusMenu.tsx` 113），hint 同时写在项内 `.desc`。菜单开着仍可冒第二层提示；与「同一时间一个 Hover 层」冲突。
- 六项：添加文件 / 使用技能 / 插件 / MCP 工具 / 扩展中心 / 定时任务。后三项都 `openSettings('plugins')`（`ComposePlusMenu.tsx` 58–81），文案三套入口同一设置页——样式问题之外的职责重复。

### 2.2 权限（药丸）

**开合**

- `PermissionModeMenu.tsx` 33：`const [open, setOpen] = useState(false)`，**完全自管**。宿主不知道它开没开。
- `handleToggle`（47–49）只 `setOpen(prev => !prev)`，不关 `+` / 模型 / 思考 / 斜杠。
- 已迁到 `anchor={pillBtnRef}` + 外部按钮（86–89），结构接近 `+`，不再是旧分析文里的 `trigger={<Tooltip><button/>}`（`docs/frontend-floating-popover-analysis/06-权限与模型菜单四击关闭与PopoverTrigger状态机分析.md` 写的是旧皮）。
- **四击仍被真机圈在 `.permPill`。** 机制与 `+` 的差异：
  - `+` 用 `if (showPlusMenu) set(false) else set(true)`，和 Radix / LayerStack 的 `onOpenChange(false)` 同向，关两次仍是关。
  - 权限用 `setOpen(prev => !prev)`（47–49）同时把 `onOpenChange={setOpen}` 交给 Menu（87）。点药丸时 Content 在 portal 里，点击对 Radix 是 outside；若 `pillBtnRef.current` 在 Tooltip `cloneElement` / `useMergeRefs` 的一帧里为空，`Menu.tsx` 355–364 的 `triggerEl.contains` 防误关失效 → Radix `setOpen(false)` 与 `handleToggle` 再翻回 `true`，一次点击变成关→开。再叠加 Tooltip `disabled={open}` 卸挂/重挂，就是缺陷清单第 4 条「四击才关」。
- `LayerStackManager.register`（64–83 行一带）只入栈、按 type 排序，**没有「新 dropdown 顶掉旧 dropdown」**。权限开着再点模型，两层都活。真机「权限菜单 + 模型菜单」叠开由此成立。
- 菜单 `side="top"`（90），从底栏向上盖住输入区。

**样式**

- 真机 / 现码是**文字药丸**「需确认 / 深入分析 / 计划 / 完全访问」+ 小 chevron（`PermissionModeMenu.tsx` 77–83），不是金标的盾形图标。
- `permPill` 高 `--control-height`，`padding: 0 10px`，圆角 `--radius-sm`（4px）（`PermissionModeMenu.module.css` 1–20）。
- `:active { transform: scale(0.97) }`（31–34）——权限自己还有一档果冻，和 Button 的 0.98 不一致。
- 打开态 `--bg-active`（36–39）。
- 菜单 `overflow-y: auto`（80），**没有** `scrollbar-width: thin` / 自定义滚动条。项少时未必出条；与模型列表的粗条是同一类缺口。

### 2.3 撤销

**开合**

- 金标底栏没有撤销钮。产品多一枚 32px 图标，底栏更挤。只记差距，不在本轮改位置。

## 3. 模型列表为何重复

真机：`OpenCode Go 订阅` 连续两行。

### 3.1 不是 key 碰撞同一条

- 渲染：`profiles.map`，`key={p.id}`（`ModelBadgePickerMenu.tsx` 94–104）。
- 装载去重：`normalizeProviderProfiles` 按 **id** 保序去重（`profileValidation.ts` 154–168）。空 id 丢弃；同 id 只留先到。
- 因此两行 = **两个不同 id、同一展示名**。不是 StrictMode 双挂、不是同 key 双 VDOM。

### 3.2 数据源双份（主因，源码可证）

**源 A · 空库种子** `profileCatalog.ts` 84–92：

```ts
{ id: 'opencode-go', name: 'OpenCode Go 订阅', baseUrl: 'https://opencode.ai/zen/go/v1', models: ['deepseek-v4-flash'], ... }
```

`loadProfiles()` 在 LS 空 / 非数组 / 规范化后空时写入整份 `DEFAULT_PROFILES`（`profileStorePersistence.ts` 78–104）。`KNOWN_PROFILE_LABELS['opencode-go']` 也是「OpenCode Go 订阅」（149–150）。

**源 B · 设置「添加服务商 → 常用服务」** `modelsPresets.ts` 16–20：

```ts
{ id: 'preset-opencode-go', name: 'OpenCode Go 订阅', baseUrl: 'https://opencode.ai/zen/go/v1', models: ['deepseek-v4-flash', 'glm-5.2', 'kimi-k3'], ... }
```

`AddProviderMenu` 把 `PRESETS` 逐条列成「常用服务」（`ModelsSettingsTab.tsx` 100–113）。`addFromPreset`（`useModelProfilesState.ts` 260–270）：

- 不查是否已有同名、同 baseUrl、或已有 `opencode-go`；
- 调用 `createCustomProfile({ name: preset.name, baseUrl, models: [] })`；
- `createCustomProfile` 固定 `id = custom-${Date.now().toString(36)}`（`profileStorePersistence.ts` 178–194），`list.push` 追加。

测例 `useModelProfilesState.test.tsx` 49–57 只断言新 id `custom-123`，**不断言去重**。

Picker 数据：`listPickerProfiles()` = `loadProfiles().filter(p => p.enabled !== false)`（`modelCatalogIpc.ts` 322–324）。再在菜单里滤一遍 `enabled`（`ModelBadgePickerMenu.tsx` 61）。**没有按 name / baseUrl 合并。**

所以一次「添加服务商 → OpenCode Go 订阅」就会在种子旁再长出一行同名。用户说「连续两行」：若中间默认壳被删/禁用，或视觉上只盯着这两条，就会是相邻两行；即便 7 个默认壳都在，列表里也会出现两次「OpenCode Go 订阅」（一条在顶、一条在自定义段）。

`preset-opencode-zen` 名是「OpenCode Zen **独占**」，种子是「OpenCode Zen **订阅**」，这两条至少不同字。Go 是字面全等。

### 3.3 排除 / 次因

| 假设 | 结论 |
| --- | --- |
| Picker 把 `DEFAULT_PROFILES` 与 `loadProfiles()` 拼两遍 | **否**。只调 `listPickerProfiles()` → `loadProfiles()` |
| `PRESETS` 直接进 Picker | **否**。PRESETS 只进设置添加菜单；进 LS 必须 `addFromPreset` / 手建 |
| Rust 配置再灌一条 `opencode-go` 进前端列表 | **未看到。** `rustProfileStore.ts` 是密钥/探活/apply 薄封装，不返回 profile 数组给 Picker |
| 迁移复制一份 | `migrateLegacyProfiles.ts` 剥明文 `apiKey`，不按名克隆 profile |
| 两个无 id 都变成 `unknown` | 规范化阶段同 id 会并掉，不会两行 |
| 用户手改另一个壳的 name | 可能，但是第三条路径；源码已提供不靠手改的双份 |
| 只渲染有模型的壳 | **否。** 无模型仍占一行，只是没有 chevron / 子菜单（`ModelBadgePickerMenu.tsx` 95–128）。空库种子里只有 `opencode-go` 预填了 `deepseek-v4-flash`，其余空壳仍出现，列表本来就长 |

本调研**没有**读本机 `localStorage.crish_provider_profiles_v1`，不能写死用户机器上那两行的 id。能写死的是：现码允许、且最省事的路径就是种子 `opencode-go` + 预设 `preset-opencode-go` 落地后的 `custom-*`。

### 3.4 相邻问题（不是重复本身，但同一列表）

- 默认 7 个壳全 `enabled !== false`，Picker 一次铺满，即使用户只配了 Go。
- 菜单打开瞬间同步读 LS，不订阅 `profiles-changed`；设置里删/改名后，已挂着的菜单要关开才刷新（`ModelBadgePickerMenu.tsx` 61 在 render 里直读）。
- 设置页级联触发器也曾展示「OpenCode Go 订阅 · deepseek-v4-flash」（`docs/system-button-audit/01-全系统真值巡检报告.md`），说明同名串在别的面上也会出现；本文件只记 Composer Picker。

| deep | 深入分析 | 同需确认 |
| plan | 计划 | **只读** |
| full | 完全访问 | **少打扰** |

`DESKTOP_PERMISSION_MODE_IDS` 顺序 ask → deep → plan → full（53–57）。菜单 `options.id` 就是这些 id（`PermissionModeMenu.tsx` 51–55）。`renderItem` 里 `permissionModeMeta(opt.id).matrixHint`（93–96）。**源码没有把「计划」接到「少打扰」。**

药丸关闭时 Tooltip 是 ``当前权限模式：${meta.label} · ${meta.matrixHint}``（63–66）。当前若是「完全访问」，药丸上本来就会写「少打扰」；打开后 `disabled={open}`，按理应收。

对话流「批准此计划」（`PlanApprovalRow.tsx`）无 Tooltip，不含「少打扰」。金标里的「计划模式」条是示例叙事，产品默认线性，不在本控件上。

### 4.2 真机「计划项上冒少打扰」更像层，不像表

与缺陷清单第 2 条「Tooltip 漂移 / 错绑」同族：

- 每一项一个独立 `Tooltip`（`PermissionModeMenu.tsx` 96），无「全局只挂一个」协调器。
- `Tooltip.tsx` 187–206 各自 `visible`；不读 `layerStackService.isTooltipSilenced()`；过快划过时可以两个 portal 同时 `isMounted`。
- `delayHide` 默认 0，但测量 / `useAnimatedPresence` / portal 卸挂不是同一帧。从「完全访问」上移到「计划」，「少打扰」门户可以仍停在原几何附近——四项挤在 28px 行高里，看起来就是计划行在冒「少打扰」。
- 键盘打开即焦点首项（`Menu.tsx` 201–207 + 权限测 `PermissionModeMenu.test.tsx` 52–53）。焦点也会 `handleFocus` 出 Tip。焦点与 hover 各管各的，可能一左一右两条。
- Tooltip 门户 `pointer-events: none`（`Tooltip.module.css` 7），滚列表 / 关菜单后若 `visible` 没掉，就是孤儿（侧栏「更多操作」同病，别的 survey 会写；权限菜单是同一套原子）。

所以：**文案表没错绑；展示层会把「少打扰」送到「计划」上。** 不能用改 `matrixHint` 当修法（那是下一阶段的事，这里只标：改表会把完全访问的提示改坏，治不了漂移）。

### 4.3 文案其它问题（同权记下）

- 项 Tooltip 只用 `matrixHint` 短词，不用 `description`（「只出方案，不改项目」等）。扫读要靠菜单字面「计划」，hint 是「只读」——和用户听到的「少打扰」都是四字，更容易认错。
- `deep` 与 `ask` 引擎都是 `ask`（`DESKTOP_TO_ENGINE`，63–68）。菜单两项行为几乎一样，hint 还写「同需确认」，容易以为点了「计划」却仍在确认族——这是产品语义，不是绑定 bug，但会加重「点错行」的感觉。
- `+` 菜单项 Tooltip 与行内 desc 双通道，权限项只有 Tip、没有行内副文。同一底栏两套菜单信息架构不一致。

## 9. 总结

Composer 底栏不是「几个按钮样式差一点」，而是**四套点击面板（+ / 权限 / 模型 / 最深）加三套输入内 suggestion（/ @ @@）再加侧栏右键，没有统一的「只开一层」**。`onCloseSiblingMenus` 被挖空后没有替补；LayerStack 只做 LIFO 外点，不做互斥开；Tooltip 不参与静默。真机权限与模型叠开、输入被盖，是这条结构的直接结果。

模型「OpenCode Go 订阅」两行是**双数据源同名**：种子 `opencode-go` 与设置预设 `preset-opencode-go` 经 `createCustomProfile` 变成两个 id。Picker 按 id 列、按名展示、不去重。

权限「计划 → 少打扰」**不是** `permissionModes` 表写反（计划=只读，完全访问=少打扰），是项级 Tooltip 无互斥、会把上一行的「少打扰」留在计划行附近。

金标密度与绿发送、单胶囊、盾形权限、附件进壳，产品都还对不上；发送在输入行里用深色 primary。这些按边界只登记，本轮不实现。斜杠、目录树、附件双 Tip、拖放遮罩、会话右键都还在互斥网外面。

实现时不要用「浮层战役已收口」旧文挡真机；不要建议搬金标假窗控。
