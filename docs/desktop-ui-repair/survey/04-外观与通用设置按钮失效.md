> 战役：`docs/desktop-ui-repair/`  
> 边界：`docs/desktop-ui-repair/00-调研边界.md`  
> 角色：检查审计子代理（只列问题，不改源码、不 git、不实现）  
> 调研日：2026-08-19  
> 用户原话：**尤其是外观和通用设置里面的按钮，基本上没有能用的。** 设置里不能用的按钮已超 80，样式退化超 60%。

## 0. 读法、锁与诚实边界

### 0.1 范围

只普查设置全屏盖层里：

- 侧栏 id=`appearance`、标签「外观」→ `SettingsAppearanceTab`
- 侧栏 id=`personalize`、标签「通用设置」→ `SettingsPersonalizeTab`
- 打开这两页时同时可见的壳：`SettingsPanel` 顶栏窗控、`SettingsSidebar` 返回/搜索/分类 tab

不普查模型/扩展/快捷键/定时任务等其它 tab（那些由其它 survey 覆盖）。其它 tab 上复用的同一套 `SettingsSchemaRenderer` / `ui/Select` 问题会在「额外发现」点出，不当成本文件已验收。

### 0.2 判定口径（问题同权，不按 P0 砍）

每个可见控件记五件事：

1. `路径:行号`、可见文案、用的是 `ui/Button` / `ui/Select` / `ui/Switch` 还是裸 `<button>` / 裸 `<select>` / 裸 `<input>`
2. 点击/切换：**文案承诺的预期** vs **代码实际**（handler 空、disabled、事件被挡、store 不写、写了没人读、写错 key、IPC/LS 失败被吞、浮层打不开、受控值不回写）
3. 样式：是否退回浏览器默认（黑框、系统按钮皮、0 圆角）；计算应走的 class 是否可能没套上
4. 圆角是否 **7px**（用户锁）。胶囊 / `9999` / 直角 / 2/4/6/8/12 全部记
5. CSS module 是否 import；是否有全局 reset 把设置页打回 UA

**交互失效**：点了达不到该行文案承诺的效果。  
**样式退化**：回 UA、该套的 class 在仓库里没有对应 CSS、或圆角不是 7px。

一条控件可以同时占「交互失效」和「样式退化」两列，两列都记，不合并掉。

### 0.3 没做 / 证据级别

- **未连** WebView2 `:9222`，没有 `getComputedStyle` 截图。圆角与 UA 回退按源码声明 + token 表推算。
- `var(--radius-md, 6px)` 在默认档（未设 `data-ui-size` / `medium`）就是 **6px**，不是「可能是 6」。
- 设置壳写了 `data-density="compact"`（`SettingsPanel.tsx:261,272,308`），仓库内 **没有任何** `[data-density]` CSS；半径只跟 `html[data-ui-size]` 走。
- 「消费方缺失」用全仓 `apps/crish-desktop/src` grep 说话；没搜到就是没搜到，不发明隐藏订阅。

### 0.4 控件怎么渲染出来的（两条 tab 共用）

几乎全部行级控件不是手写，而是：

`SettingsAppearanceTab` / `SettingsPersonalizeTab`  
→ `SettingsSchemaRenderer`（**没有自己的 CSS module**）  
→ `SettingsRow`（`SettingsUI.tsx` + `SettingsUI.module.css`）  
→ 右侧 `control` 槽：`Switch` / `Select` / 裸 `button.ui-segment-item` / 裸 `input[type=range|color|text]`

字体段是唯一大批手写控件：`FontSettingsSection` + `FontSelectField`。

## 1. 横切根因（先读：几乎每个控件都踩其中几条）

### 1.1 全局 class 已死，Schema 还在用——主题/密度按钮回 UA

`SettingsSchemaRenderer.tsx:210-227` 对 `type: 'toggle-group'` 渲染：

```tsx
<div className="ui-segment">
  <button className={`ui-segment-item${isActive ? ' active' : ''}`} …>
```

全仓 `*.css` 里 **已经没有** `.ui-segment` / `.ui-segment-item` 的规则（只剩 `SettingsQuickMenu.module.css:88-95` 在 `.sbQuickSegment` 内部用 `:global` 补胶囊，**管不到** 设置内容区）。

历史文档（`docs/ui-style-audit`、`docs/system-button-audit`）还当 `.ui-segment-item` 是 999 胶囊。源码现状是：class 名还在，样式文件没了。

叠加 `styles/shell/shell-reset.css:10-14`：

```css
* { box-sizing: border-box; margin: 0; padding: 0; }
```

裸 `<button>` 的 UA padding 被清零，又没有 `appearance: none`、没有模块 class。Windows WebView2 上就是：**系统按钮皮 + 黑/灰边框 + 0 圆角 + 命中区≈文字本身**。`.active` 没有背景/描边规则，点了看不出选中。

外观页「浅色/深色」「紧凑/默认/宽松」五枚全部中招。这是「看起来完全不能用」的第一视觉源。

仓库里其实已经有 `ui/SegmentedControl`（`components/ui/SegmentedControl/`，外圆 `--radius-lg`=8px、内圆 `--radius-md`=6px，也不是 7px），Schema **没有接**。

### 1.2 `ui/Select` 浮层 z-index 被设置 Dialog 压住——下拉等于没开

设置壳是 `Dialog variant="fullscreen"`（`SettingsPanel.tsx:248-256`）。

`Dialog.module.css:7-12`：遮罩壳 `z-index: var(--dialog-z, var(--z-modal))`，`--z-modal` = **1000**（`styles/z-index.css:22`）。

`ui/Select` 用 `ui/Menu` → `Popover.Portal` 挂到 `document.body`（`Menu.tsx:341-342`）。  
`Menu.module.css:6`：`.menuContent { z-index: var(--z-dropdown, 100); }`，`--z-dropdown` = **300**（`z-index.css:15`）。

300 < 1000。下拉画在全屏设置盖层**下面**。用户点触发器：open 变 true，看不见面板，再点像没反应。  
`Select.module.css` 的 `.menu` 只设了 `min-width: 180px`，**不改 z-index**。

本两页所有 `ui/Select`（外观：窗口风格 / 代码缩进 / 皮肤预设；通用：回答风格 / 发送快捷键）都中招。

`FontSelectField` 给面板加了 `styles.settingsSelectMenu`，其中写了 `z-index: var(--z-tooltip)`（9000）。与 `.menuContent` 的 300 是同特异性、两份 CSS module，**最终谁赢取决于打包顺序**。源码不能判死。字体下拉标「z-index 竞态，待 CDP」。

### 1.3 全局 reset 不补 button 皮，只拆 UA padding

`shell-reset.css` 的 `*` 清 margin/padding，**没有** `button, input, select { appearance: none; border: 0; font: inherit; }`。  
有模块 class 的 `ui/Button` / `ui/Select` 触发器 / `ui/Switch` 自己补回。  
没模块 class 的裸 button / 裸 range / 裸 color / 裸 checkbox 全部露出 UA。

### 1.4 Schema 不用现成原子，改手写 inline + 死 class

`SettingsSchemaRenderer.tsx` 已 import `Select, Switch`，但：

| schema type | 实际控件 | 仓库里现成却没用的 |
| --- | --- | --- |
| `toggle-group` | 裸 `button.ui-segment-item` | `ui/SegmentedControl` |
| `range` | 裸 `<input type="range">` + inline | `ui/Slider` |
| `color` | 裸 `<input type="color">` + inline | 无原子，但 inline `borderRadius: 6` |
| `string` | 裸 `<input>` + 死 class `ui-text-input settings-text-input` | `ui/Input` |
| `select` / `font-selector` | `ui/Select` + 死 class `settings-personalize-select` | class 无 CSS |

`settings-personalize-select`、`ui-text-input`、`settings-text-input`、`settings-list-empty`、`settings-ui-row-label`：全仓 `*.css` **零规则**。`SettingsUI.module.css:206-210` 有 hashed `.settingsUiRowLabel`，但渲染器用的是**全局字符串** `settings-ui-row-label`，对不上。

### 1.5 `ready={!saving}` 一写全盘禁用

外观 `SettingsAppearanceTab.tsx:90`、通用 `SettingsPersonalizeTab.tsx:75,231`：`ready = settings 已加载 && !saving`。  
`save()`（`useAppearanceSettings.ts:166-189` / `SettingsPersonalizeTab.tsx:56-73`）一进就 `setSaving(true)`。  
主题/缩进/通用任意开关都会让 **整页** Select/Switch/分段 `disabled`。  
`saveSettingsEx` 走 `navigator.locks`（`clientApiSettings.ts:60-83`），**没有超时**。另一窗口占锁时，本页控件会一直灰着，看起来「全坏了」。失败只 toast，成功静默。

### 1.6 写了设置、下游不读 / 读另一把钥匙

通用页多枚 Switch/Select 能把值写入 `crish_settings`，但运行时读面断了或读的是另一 LS key。开关会翻（或翻完弹回），产品行为不变。详见 §4。

### 1.7 圆角 token 默认档没有 7px

`tokens.css:262-266` 默认：xs2 / sm4 / md**6** / lg**8** / xl12 / 2xl12 / full 9999。  
7px 只出现在 `html[data-ui-size='small']` 的 `--radius-lg`（820）和 `'large'` 的 `--radius-md`（896）。  
默认密度下，**没有任何**走 token 的设置按钮会算出 7px。用户锁对默认档是全面未命中。

### 1.8 Switch 滑块还在用过弹弹簧

`Switch.module.css:74`：`cubic-bezier(0.27, 0.2, 0.25, 1.51)`（1.51 过冲）。  
`Button.module.css:72-73`：`:active { transform: scale(0.98) }`。  
用户锁「点击果冻去掉」。本两页所有 `ui/Switch`、所有 `ui/Button` 都踩。

## 3. 外观 tab 逐控件

入口：`SettingsAppearanceTab.tsx`。状态：`useAppearanceSettings.ts`。Schema：`useAppearanceSchema.ts`。皮肤：`useSkinSettings.ts`。

加载失败才渲染「重试」；`settings === null` 只显示「加载中…」无控件。  
`getSettingsEx` 签名是 `Promise<Settings>`，恒返回对象；`useAppearanceSettings.ts:130` 的 `if (cancelled || !sets) return` 里 `!sets` 是死分支。真失败走 catch + toast。

外观 **不** 在 load 时 `setAppSettings`（通用页会）。主题靠 bootstrap 的 `initThemeProjection` + load 里直调 `applyTheme`（`useAppearanceSettings.ts:135-138`）。`applyTheme` **不**写 `crish_theme`、**不**发 `crish-theme-changed`。

### 8.4 额外发现（任务内连带、留给主控）

1. **同一套毒点会污染全设置中心**：`SettingsSchemaRenderer` 是通用渲染器。修外观/通用的 Select z-index 和 toggle-group，等于修所有走 Schema 的页；不修则每个 tab 的 Select 都会「不能用」。
2. **仓库已有 `ui/SegmentedControl` / `ui/Slider` / `ui/Input`，设置页不用。** 继续手写裸控件 + 死 class，是「原子战役已经收口」文档和真机互打脸的典型口。
3. **`crish_send_shortcut` 是只读孤儿 key**，设置写的是 `crish_settings.sendShortcut`。双源。
4. **`hideThinkingBlock` 传到助手行后被 `void`。** 通用开关是假的；外观重置还去写这个字段。
5. **`tabModeEnabled` 三份真源**（settings JSON / layoutStore / workspaceStore），设置只打前两份，UI 动作打第三份或谁都不打。
6. **`enableAnalytics` / `quietStartup` / `collapseChangelog` 是死字段。** 合规/文案承诺层面也是「按钮不能用」。
7. **太阳档会改写主题属性**，和「主题模式」分段抢同一 `data-theme`。两控件互毁。
8. **`restoreLastWorkspace` 受控值不进 `allValues` 依赖**，是确定的 React 受控弹回，不是「感觉」。
9. **成功静默、失败 toast**，再叠加「最丑 Toast」锁：唯一给用户的反馈通道还是那套胶囊 Toast（恢复工作台每次必打）。
10. **`_onBlockingOverlayChange` 只给 rules。** 外观/通用的 Menu 不登记「挡操作层」，和「展开面板同时只能开一个」的锁对不上。
11. **同目录已有另一份 `survey/04-设置按钮圆角7px与曲率混乱.md`**（圆角专档）。本文件按主控派单文件名 `04-外观与通用设置按钮失效.md` 落盘，编号撞车，收口时由主控改名/合并，本子代理不改那一份、不写第二份。
12. **派单/工作流**：两页的「不能用」不是 80 个互不相关的 handler 空，而是 **3 条结构断层**（死 class、Dialog/Menu z-index、设置字段无读面）乘出来的。实现波若按按钮打补丁会再烂一层；应按这 3 条收。
