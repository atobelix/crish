## 3. 新断层

### 3.1 Menu portal 进 Dialog overlay（不限设置菜单）

I5 只要求：**设置 Dialog 内** Menu/Select 高于该 Dialog。实现把逻辑写进 **全局 Menu 基座**：

```347:347:apps/crish-desktop/src/components/ui/Menu/Menu.tsx
      <Popover.Portal container={dialogOverlay ?? undefined}>
```

`DialogOverlayContext` 由任意 `Dialog` 提供（`Dialog.tsx:165`），含确认盒、速查、首次运行、技能编辑、全屏设置。测试把过宽实现冻死：

`Menu.test.tsx:313-330` 标题写「设置壳 z」，夹具却是 **通用 `<Dialog title="设置">`**，断言任意 Dialog 内 Menu 都进 overlay、不挂 body。

当前 overlay 入场只有 opacity（`Dialog.module.css:114-120`），无 transform，固定定位仍相对视口，设置场景 **z 问题能解**。断层是：

1. **概念过宽**：非设置 Dialog 的 Menu 全部改挂 overlay。总案允许「Dialog 确认盒叠在面板上」；确认盒若内含 Select，行为被绑在设置壳补丁上。
2. **首帧 `overlayEl` 为 null**（`Dialog.tsx:101,161` `useState` + ref 回调）。第一次 paint `dialogOverlay=null` → Portal 默认 body（z=300）< overlay（z=1000）。`overlayEl` 写入后再改 container，Radix 会重挂。快开下拉可能闪在层下或被重挂关掉。测用 `waitFor` 掩盖了首帧。
3. **无「非设置菜单仍挂 body」的负测。** Composer/侧栏 Menu 不在 Dialog 树内，源码上应仍挂 body；没有回归网防止以后有人把 Context 提到 App 根。

设置面板 `.settingsCover { isolation:isolate; overflow:hidden }`（`SettingsPanel.module.css:8-20`）在 **panel** 上；Menu 挂 **overlay（panel 的父）**，所以能逃出 cover 裁切——这正是 I5 想要的。不要把 overflow 再套到 overlay 上，否则设置下拉会二次夹死。

### 3.2 I2 菜单静音杀掉 Select / 权限项 hint

- `LayerStackManager.ts:191-200`：除 tooltip/toast 外任何层 ⇒ `isTooltipSilenced()===true`，并打 `data-floating-active`。
- `tooltipController.ts:26-28,40-42`：静音则拒绝占槽。
- Select 项 hint **就是** Tooltip（`Select.tsx:61-98`）。Menu 一登记，hint 的 `scheduleShow` 直接 return。
- 权限菜单同样：`PermissionModeMenu.tsx:101-120` 每项包 Tooltip 展示矩阵。

Menu 默认项用的是 **常驻 `menuItemHint` span**（`Menu.tsx:450-452`），不受静音影响。Select 故意改成悬停 Tooltip，于是被基座误伤。

第 1 轮实现原句：「开着的 Menu 会静音内部 option Tooltip（Select hint 测会红，**与 I2 菜单静音一致**）」。这是 **用实现口径改写用户锁**，不是关锁。

**结构修法（供下轮，本文件不改码）**：静音判定带锚点——trigger 落在当前浮层 `elementRef` **内部** 的 Tip 放行；外部 Tip 才灭。或 Select/权限改回 `menuItemHint` 常驻文案，不要用 Tooltip 冒充项说明。
