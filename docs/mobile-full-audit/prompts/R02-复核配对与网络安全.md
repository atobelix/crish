## 核查重点

1. **缺陷 01「证书钉扎在生产环境从未生效」**
   - 读桌面端实际配对实现（`apps/agent-workbench/src-tauri` 与 `crates/` 下与 pair 相关的模块；报告点名了 `pair_endpoint.rs`、`tls.rs`，请先确认这些文件的真实路径与行号是否存在）。
   - 回答：桌面端 `pair.ok` 载荷、二维码内容里**到底有没有** `tlsFingerprint`？移动端 `verifyStoredFingerprint` 在 `delivered === undefined` 时返回什么、之后的连接是否还有别的校验（例如应用层指纹一致性校验，README 声称“系统 CA 信任 + 应用层指纹一致性校验”）？“从未生效”是否过强——它到底是“未启用”“降级放行”还是“另有等价机制”？
   - 测试桩 `'fp-1'` 导致的警告：核实 `pairingWiring.test.ts` 里报告所列 6 个行号是否吻合。
2. **全局明文流量放行**：读 `plugins/withUserCaTrust.js`，**并读已生成的** `apps/crish-mobile/android/app/src/main/res/xml/network_security_config.xml`（若存在）与 `AndroidManifest.xml`，确认 `cleartextTrafficPermitted` 的实际取值与作用域；它是否 Debug/Release 同样生效？是否有 `expo-build-properties` 等其他配置覆盖？
3. **离线 Outbox 重连恢复断路**：核实 `observationWiring.ts` 创建 `ReconnectingWsClient` 时是否真的没有传 `projections`；追 `ReconnectingWsClient` 里 `projections` 缺省值与 `outboxFlush` 的取值；核实 `approvalWiring.ts` 里 `pendingOpenUnsubscribe` 的生命周期，**重连后是否真的没有任何路径触发 `bridge.flush()`**（全局 grep `flush(` 的所有调用点）。
4. **`Math.random()` 用于认证 Nonce**：核实 `sessionSigning.ts` 报告所引行；Nonce 在协议里的作用（防重放？）及服务端是否另有校验，从而判断严重度是否被夸大。
5. **重连抖动风暴**：核实 `ReconnectingWsClient.ts` 里 `retryCountValue = 0` 的位置、退避公式、是否有抖动（jitter）；“1 秒一次高频重连”是否有代码依据。
6. **缺少 NetInfo / 连接看门狗**：核实 `package.json` 与 `src/**` 是否真无 netinfo；核实握手超时、心跳超时常量及其行号。
7. **国产 ROM（HarmonyOS / HyperOS）兼容性断言**：报告中关于“鸿蒙 NEXT 废除 XML CA 配置”“HyperOS 30 秒冻结后台”“Keystore2 锁屏挂起”等，**有没有任何本仓库代码证据或官方文档出处？** 没有的一律标注为「外部知识，无证据」，建议降级为“待实机验证”，并写出验证实验。
8. **报告建议的修复方案**：其中涉及“桌面端补发指纹”“网卡枚举写入 SAN”“引入 netinfo 依赖”，逐项评估是否符合用户的“非必要不兼容 / 反补丁 / 反过度设计”要求，是否有更简洁的根治路径。
