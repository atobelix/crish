## 任务

### A. 全量转场点盘点（本席位的基础，必须穷尽）

读 `app/_layout.tsx`（Stack 的 `animation: 'slide_from_right'`、账号页 `animationDuration`、`transparentModal + fade`、两个 `formSheet`）、`app/(main)/_layout.tsx`、`app/account/*`、`app/pair/*`、`app/welcome.tsx`、`app/run`、`app/terminal`、`app/approval*`、`app/notifications.tsx`、`app/settings*`，以及所有 `router.push/replace/navigate/back`、`<Redirect>` 的调用点（**全局 grep**），生成**转场点总表**：

| 起点 | 终点 | 触发方式 | 现有机制（原生栈动画/JS Animated/Reanimated/无动画/条件渲染突变） | 时长与缓动来源 | 是否生硬及原因 |

必须包含但不限于这些链路：
1. **开屏 → 主界面**（原生 splash → JS 自绘开屏 → 主界面；与 N01 对接）；
2. **欢迎页 ↔ 主界面**（`Redirect` 无过渡？）；
3. **登录/验证码/设置密码 → 主界面**（账号流程成功后的收尾）；
4. **邮箱页 → 验证码页 → …** 的横向推入、返回；
5. **抽屉 → 页面**（`navigation.closeDrawer()` 与 `router.push` 的先后；是否“先关后推”造成割裂）、抽屉内**会话切换**；
6. **新对话 → 会话详情**（首条消息发出后）；
7. **审批卡/悬浮卡（`ApprovalFloat`）出入场**、`transparentModal` 的 `fade`、`formSheet`；
8. **Toast / Dialog / Sheet** 的出入场；**软键盘出入**引起的布局跳变（输入框、Toast、`ApprovalFloat`）；
9. 列表**数据到达**时的布局跳变（骨架屏/空态 ↔ 内容的切换）、连接状态横幅出现/消失引起的整体下压。

### B. 现有动效实现的盘点与归并

- `theme.motion.*` token 现状（名称、值、被谁使用）；有没有**两套并存的动画实现**（旧 `Animated` API、`FadeIn` 组件、Reanimated 布局动画、`LayoutAnimation`）？逐处登记（文件:行号）。
- 核实 **Android** 上 `react-native-screens`（4.26）原生栈对 `animation` 类型与 `animationDuration` 的真实支持（代码里注释说“iOS 生效”）——读 `node_modules/react-native-screens` 源码给出 Android 行为；**用户环境是 Android，以 Android 为准**。
- 逐帧 `setState` 驱动动画的位置（第一轮发现 `SlideToConfirm` 有此问题，请全局排查是否还有）。

### C. 统一动效体系设计（2–3 个完整方案，给推荐）

- 单一 **motion token 集**（时长阶梯、缓动曲线/spring 参数、层级对应的用途），**单一实现层**（建议基于 Reanimated 4 worklet；若你推荐别的，必须论证），一套**转场规范表**（哪类转场用哪类动效：层级前进/返回、模态、侧滑面板、内容替换、状态切换）。
- **过渡编排的位置**：必须放在导航/布局层的**单一入口**，不得散落在各页面用 `setTimeout` 补偿延迟（反补丁红线）。说明如何处理“先关抽屉再推页面”这类需要编排的场景（用统一的导航封装 or 动画完成回调，论证哪种更简洁）。
- 如何消除“布局跳变”：保留位/骨架/高度动画——选择与论证，必须落到 token。
- **不得**使用描边类过渡（U8）：任何边框扫光、轮廓动画一律不用。

### D. 与删除/重构的关系

列出**应删除的重复动画实现**与**统一替换后的差异**；对每个转场点给出“改成什么、改哪个文件的什么符号”。不要写“优化动画”这类空话。
