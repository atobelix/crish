## 核查重点

1. **9 处 TypeScript 错误复现**：在 `apps/crish-mobile` 下执行一次 `npx tsc --noEmit -p tsconfig.json`（只许跑一次，输出重定向到 `scratch` 目录再读），逐条与报告对照：错误数量、文件、行号、错误码是否一致；若有出入（新增/消失），说明原因。
2. **根因归因**：
   - `FilesCommandError` 构造签名：读定义与所有调用点，报告说“重构后 `retryable` 必填但无默认值”——核实定义行；报告建议“给 `retryable` 默认值 false”是否符合“反补丁”？还是应该**改测试**/改签名使之语义明确？给出你的判断与理由。
   - `DirSortMode` 的真源是否确实是 `'name' | 'mtime-desc' | 'size-desc'`；
   - `WsPhase` 与 `ConnectionPhase` 的概念分层是否如报告所述；测试里直接把 WsPhase 塞进领域 Store 是否真实存在。
3. **12 处 `overlapping act()` 警告**：只对报告点名的 5 个测试文件各跑一次 `npx jest <文件> --runInBand`，**统计警告出现次数**，与“12 处”核对；核实根因“`fireEvent.*` 在 RNTL 14 返回 Promise，需 `await`”——读 `node_modules/@testing-library/react-native` 的类型定义行号作证。
4. **“CI 遗漏移动端”**：读根 `package.json` 的 `typecheck` / `check:*` 脚本、`.github/workflows/*.yml`、`.husky/pre-commit`、`.lintstagedrc.json`、`.dependency-cruiser.cjs`，核实四个遗漏断言**是否各自成立**（注意：CI 里可能有独立的 mobile job，报告提到 `mobile-check`，请确认其真实命令与是否带 `--coverage`）。
5. **假绿测试**：对报告点名的 3 处（`screens.test.tsx:252-256`、`:300-304`、`approvalHistoryScreen.test.ts`）读原文，核实“只断言存在性/纯函数”的说法是否准确。
6. **覆盖盲区**：核实 `TimelineView` 是否真无专属测试（全局 grep）、`ApprovalHistoryScreen` 组件级测试是否真为 0。
7. **“脏警告”清单**：Jest 输出中 `PairingWiring` 指纹警告等是**测试桩问题**还是**生产问题**——与 R02 的结论互相印证。
