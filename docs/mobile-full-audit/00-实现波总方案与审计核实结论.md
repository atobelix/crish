### 1.2 修正 / 作废（不按原文执行）

| 原断言 | 修正口径 |
| :-- | :-- |
| "离线审批重连后永不补发"（02 席 DEF-02） | **不成立**（R02 已推翻）：重连 → `events.subscribe` → `events.subscribe.ok` → `onSyncReady()` → `flushOnce()+reconcile()` 闭环存在。真实缺陷是 V5 的**另一套**投影机制为死代码。 |
| "桌面下发指纹格式非法导致弃防" | 因果倒置：生产是**压根未下发**（V12），格式警告是单测桩 `'fp-1'` 脏数据。修复方向 = 桌面补下发 + 移动端 fail-closed，而非改正则。 |
| `ReconnectProjection` 机制 | 定性为**死代码 + 与真实重放链路重复**。处置 = **删除**（projections 工厂、driveProjection、handleProjection、projectReconnect 及其测试），不接线——避免两套重放设计并存（反过度设计、减重复）。 |
| 大盘 95/52 分、席位 03 的 45/100 | 全部作废（无算式依据）。交付基准 = 缺陷收敛率 + 门禁全绿 + 真机断言。 |
| `animationDuration`（`_layout.tsx:121`） | Android 原生栈不消费，iOS 对 `slide_from_right` 亦不生效 → **删除**伪配置。 |
| `asyncRoutes` 分包 | 原生 Android 不支持（web-only）→ 不做，该路径作废。 |
| 引入 `@shopify/flash-list` / 替换 `@noble` 为 WebCrypto | **拒绝**（前者反过度设计，后者 Hermes 无 `crypto.subtle`，照做即崩溃）。 |
| "150 次跨桥阻塞主桥"、"掉帧 10fps" 等量化 | 无证据，不作依据；相应修复按"确凿的架构事实"执行（批量接口、批处理合并仍做，但不引用其数字）。 |

### 1.3 主控补充发现（实现时一并处理）

- `ensureDatabaseForApp` 每次调用都会重新 open（无 promise 备忘），重复调用有二次打开风险 → 收口为单飞。
- `persistBootstrap` 与 `dbBootstrap` 双层 null 语义分散 → 集中到 dbBootstrap 暴露 `ensureDatabaseReady()`。
- `FeedBridge.onOpen` 对 `windows` 全量 hydrateSession，唤醒风暴下放大请求量 → 唤醒路径仅对活跃窗口做（现有逻辑保留，配合探活阈值）。

## 三、分维实现详案

> 文件域按维组织；每维末尾列删除清单。行号为 2026-10-30 工作区现场。

### 维 A · 启动链路（U1 ≤1s / 死锁根治）

**A1 `accountService.ts` 重构 `hydrateAccount`**
- 新增 `persist` 载荷扩展：session 快照增存 `user_json`（完整 `AccountUser` JSON）与 `profile_json`（可空）。
- `hydrateAccount()` 重写为两段：
  1. **本地段（闸门依赖）**：`loadAccountSession` 纳入 try/catch；任何异常 → 视为无凭据（`loggedOut + hydrated`），杜绝 Keystore 异常死锁（V2a）。有 session → `setAccessToken` + 从 `user_json` 恢复 `user`/`profile` + `status='loggedIn'` + `setHydrated(true)` 立即返回。无 `user_json`（老数据）→ 仅置 `hydrated`，`status='loggedOut'`（下次登录覆盖写快照；不踢已登录用户去 welcome 的场景不存在——无快照即无可用本地态）。
  2. **远程段（后台静默）**：`reconcileAccountRemote()`：`fetchAccountMe`（401→refresh→重试一次）→ `Promise.all(devices best-effort, profile)` → 回写 store + 持久化快照。失败分类：网络/超时 → 保持本地态，`setError` 供 ConnectionBanner；401 且 refresh 失败 → `status='loggedOut'` 平滑登出（不闪跳，守卫自然接管）。
- `startAccountRuntime` 的 `hydrateAccount().finally(syncRemote)` 改为本地段 + `void reconcileAccountRemote()`。

**A2 `app/_layout.tsx` 重写启动编排**
- 删除：JS 自绘 splash（:88-100）、`styles.splash`、`BrandMark/Spinner` 导入、`ACCOUNT_V3_ROUTES` animationDuration 伪配置（:116-123）。
- 新增：`SplashScreen.preventAutoHideAsync()`（模块顶层）+ RootShell 首帧 `useLayoutEffect` → `SplashScreen.hideAsync()`（fire-and-forget）。
- DB：`void ensureDatabaseForApp()` 保留在启动触发（并行、非闸门）；审批接线自行等待（C2）。
- 通知层：`navigate` 改幂等（`router.navigate(path)`，V20）。
- 闸门：`if (!hydrated || !accountHydrated)` 保留但两值均由**纯本地读取**置位（A1 后 ≤50ms），期间为原生 Splash（无 JS 中间帧）。

**A3 `accountApi.ts` / 常量收敛**
- 新增 `src/adapters/account/accountConstants.ts`：`REQUEST_TIMEOUT_MS=12_000`、`SLOW_NET_MS=3_000`、`VERY_SLOW_MS=8_000` 单一真源；`accountApi.ts` 引用之。

**A4 密码登录结构化错误（V17b）**
- `runLoginFlow` 返回结构化 `LoginResult`（`{ok:true} | {ok:false, kind:'credentials'|'network', message}`），页面按 kind 渲染；废除 boolean 吞异常。

**删除清单 A**：`_layout.tsx` splash 块与 styles、ACCOUNT_V3_ROUTES；`hydrateAccount` 的网络阻塞路径（移入后台段）。

### 维 B · 运行时（生命周期 / 清理穿透）

**B1 `dbBootstrap.ts` 单飞 + 就绪门禁**
- `ensureDatabaseForApp` 结果 promise 备忘（同参幂等；测试注入 `options.open` 时不备忘）。
- 导出 `ensureDatabaseReady(): Promise<SqlDriver | null>`（成功→driver；失败→null）。

**B2 `approvalWiring.ts`**
- `ensureApprovalWiring`：gateway 就绪且 driver 未就绪 → `void ensureDatabaseReady().then(driver => 装配单例)`；`createDefaultOutboxPersist(driver)`（driver 为 null 仅发生在 DB 明确失败，注释标明显式降级）。
- `disposeApprovalWiring`：异步清 `approval_queue`（经 `getSqlDriver()` 构造 DAO；driver null 跳过）+ 现有内存复位（V18a，防换机越权回放）。

**B3 `appRuntime.ts`**
- `clearSessionData` 补 `connectionStore.reset()`、`notificationStore` 复位（V18b）。
- `handleAppState`（唤醒）：
  - 无 wiring：paired → `ensureObservationWiring()`；**未配对且账号已登录 → `syncRemote()` 恢复中继**（V19b）。
  - 有 wiring：`phase==='open'` 且 `now - lastRxMs > WAKE_PROBE_MS(15s)` → 主动 `reconnect()`（即时探活，替代盲写）；`connecting` → 不动；其余 → `reconnect()`。
- `lastRxMs` 由 ReconnectingWsClient 暴露（维 C）。

**B4 `observationWiring.ts`**
- `disposeObservationWiring` 补 `openListeners.clear()`（V18c）。
- 删除 `onProjection` 转发（C3 删除投影机制后无此回调）。

**B5 `useCountdownTick.ts`**
- AppState 后台冻结：`background` 清定时器、`active` 立即对齐 `now` 并恢复（V19c）。

**B6 `accountRuntime.ts`**
- 后台（AppState `background`）暂停 discovery 轮询与退避；唤醒立即执行一轮 discovery 并重启定时器（V19）。

**删除清单 B**：无文件级删除；均为行为修正。

### 维 C · 数据面（序列空洞 / 死代码 / 连接健壮）

**C1 `feedBridge.ts` 序列空洞 stash（V4 根治）**
- 新增 `stashBySession = new Map<string, InboundEnvelope[]>()`。
- `handleFrame`（events.push）：`seq > lastSeq+1` → 帧入 stash（按 seq 去重排序）+ 触发 `resumeSession`；**不立即 apply**。
- `seq === lastSeq+1`：正常 apply，随后 `drainStash(sessionId)`：循环取 stash 首帧，`seq <= lastSeq` 丢弃、`seq === lastSeq+1` apply，遇空洞停。
- `handleResumePage` 应用后同样 `drainStash`。会话卸载/unload 时清对应 stash。

**C2 删除死投影机制（V5 根治 = 删除重复设计）**
- `ReconnectingWsClient`：删除 `projections` 选项、`onProjection`、`driveProjection()`；`projectReconnect` 纯函数与测试一并删除（真实重放链路 = `events.subscribe.ok → onSyncReady`，单一真理）。
- `FeedBridge.handleProjection` 删除；`observationWiring` 装配相应收敛。

**C3 `ReconnectingWsClient` 健壮化**
- 握手看门狗：`openSocket` 后 8s 未 open → 主动 close 触发退避重连（清除定时器于 open/close）。
- 退避清零延后：open 后启动 5s 稳定计时器，期满才 `retryCount=0`；期间断开按连续失败退避（V R02-DEF-05）。
- 暴露 `lastRxMs`（心跳收包时间戳，供 B3 探活）。

**C4 `ingestRouter` 批处理（防抖合并，非必需不引入复杂机制）**
- 读现场后定：若 `mapDeviceFrame` 产出可按帧粒度缓冲，则引入 ≤16ms 微任务批合并（关键类型 `approval-requested` 等白名单实时放行）；若耦合过深则记为后续项，不在本波强行抽象。
