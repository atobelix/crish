## 一、用户问题与本批结论

用户原话：工具调用行一加进来，界面就会不自然/卡顿地加入新行；要求对 AI 工作期间**所有新增 DOM 的位置**做普查，并**统一封装**唯一入场通道，不走通道的新增 DOM 不许默默漏掉。

普查结论（代码 + 实机双向核对）：入场现状是**多轨并存**——

1. **AN4 判定核心**（`chat-tool-call/toolRevealState.ts`）设计上与表面无关（呈现记忆、实况时间窗 [-500ms, 2000ms)、批次交错 50ms/行、排空登记），但钩子 `useRevealEntrance` 只被 3 个面消费（工具单行、工具组、子代理分派卡）；
2. **AN2** 只管整条消息行入场；
3. 多个面**自带私有 keyframes**（错误条 `errorBarIn`、缎带芯片 `chipFadeIn`、审批卡/审批坞的 `crish-popover-enter-top` 等），节奏与口径各异；
4. 多个面**完全无入场**：流式叙述/正文段、思考行挂载、重试状态行、工作状态行、上下文注入提示行、定时任务执行卡等，挂载即全高出现，直接顶开下方布局；
5. 工具组存在一个隐性 bug：入场交错 `delayMs` 已计算却从未写入 `--reveal-delay`，组入场延迟恒为 0（本批已修）。

实机改前量测（2026-11-06 ≈00:36–00:41 EST，新会话多工具轮次，探针 = MutationObserver + rAF 高度采样 + PerformanceObserver layout-shift）：**113 个新增子树根、41 次 scrollHeight 阶跃、43 次 layout shift、累计 CLS 0.2211、最大单次 0.1027**；抽查到的每个值得注意的新增节点 computed animationName 均为 `none`（叙述块 0→56.8px / 0→79.5px 瞬时出现、过程段 48→75px 跳变、工具行 24px 瞬时）；完成瞬间在 ~90ms 内出现 **−146px / −34px / +84px** 的高度颠簸（组自动收拢 + 最终答复挂载）。

本批落地：**唯一入场通道** = 判定核心（原 AN4 核心，不动语义）+ 通用钩子/组件（新）+ 共享呈现（原 `crish-row-enter` keyframes + 新全局类）。普查到的新增点逐个接入或逐个点名理由（见第三、六节）。

## 二、统一封装设计

### 2.1 三层结构（每层单一真相源）

| 层 | 位置 | 职责 |
|---|---|---|
| 判定核心 | `src/components/chat-tool-call/toolRevealState.ts`（原 AN4，未改语义） | 该不该播：呈现记忆（同 key 本会话只播一次）、实况时间窗、历史回放拒绝、批次交错 delay、减动效判定（仅系统 `prefers-reduced-motion`) |
| 通用钩子/组件 | `src/components/motion/useEntranceReveal.ts`（新）+ `EntranceReveal.tsx`（新） | 把判定接到任意表面：变体、高度生长驱动、安全兜底定时器；组件形态供根节点可托管的表面直接包裹 |
| 共享呈现 | `src/styles/design-system.css` 的 `@keyframes crish-row-enter` + 新增全局类 `.crish-entrance-fade` | 唯一的入场视觉语言：opacity .6→1 + translateY(4px)→0，时长 `--duration-fast`(150ms)、缓动 `--ease-decelerate`，延迟读 `--reveal-delay` |

旧钩子 `chat-tool-call/useRevealEntrance.ts` 收敛为 **re-export 垫片**（只转出新钩子与类型别名），其 3 个既有消费方与 AN4 全部测试零改动、零回归。运动常量一律复用既有 SSOT（`motionTokens.ts` / CSS token），不另起手感：grow 变体的时长由既有 `calcAccordionDuration(height, true)` 按高度推导（≈150–220ms，与手风琴同源），不是新拍的数字。

### 2.2 钩子 API 与接入约定（后续新面默认走这里）

```ts
const entrance = useEntranceReveal({
  key,          // 必填：稳定身份（约定见下表）；空串 = 不播
  eventTs,      // 事件时间戳 ms；落在实况窗 [-500, 2000) 才播
  liveOnMount,  // 可选：仅限「存在本身即实况事件」的运行时状态面
                // （重试行/审批坞/失败条），eventTs 缺省时以首次判定时刻兜底
  variant,      // 'fade'（缺省）| 'grow'
  replaceHit,   // 承接 AN4：内容被替换命中时抑制
  disabled,     // 显式关闭
});
// → { entering, delayMs, handleAnimationEnd, rootRef }
// 根元素：ref={entrance.rootRef}、entering 时加类 'crish-entrance-fade'
// 并以 style 写 --reveal-delay、data-entering 标记、onAnimationEnd 挂 handleAnimationEnd
```

组件形态：`<EntranceReveal eventKey eventTs variant>`（根 div 托管，className/style/data-* 透传），供没有自有根元素逻辑的表面使用。

**变体口径**：

- **fade**：只动 opacity/位移（共享 keyframes），高度由内容自然决定——用于文本相邻块（叙述/正文段、思考行、注入提示、定时卡）。**文字本身的揭示仍归 RevealPacer**，本通道只管容器，不叠文字动画。
- **grow**：在 fade 之上，JS 内联驱动高度 0→自然高（rAF 漂移重定向：测高变化时从当前呈现高度重设目标；transitionend 收尾；期间 `overflow:hidden`；结束清内联样式）——只用于**挂载时高度已定型的离散行/卡**（状态行、错误条、审批卡/坞），让布局推移全程连续、与贴底滚动补偿同步发生，而不是一帧阶跃。长内容容器（高度封顶 + 内部滚动 + 渐隐口径）**禁用 grow**，只许 fade（见第六节）。

**key 约定**（写在钩子文件头，后续新面照此登记）：工具行 = toolId；分派卡 = `agent:<id>`；工具组 = `group:<msgId>:<firstToolId>`(AN4 既有）;思考 = `thought:<msgId>:<turnIndex>`；文本段 = `seg:<msgId>:<itemKey>`；注入提示 = `ctx:<injectionId>`；重试行 = `retry:<attempt>:<errorKind>`；工作行 = `work:<startTime>`；错误条 = `errbar:<sessionId>:<assistantMsgId>`；审批 = `approval:<toolId>` / `dock:<toolId>`；定时卡 = `sched:<runId>`。

**守卫**：新增契约测试 `src/components/motion/entranceChannel.contract.test.ts`（源码扫描式，与仓库既有守卫同 idiom）钉住四件事：垫片不许再长出第二份判定实现；已登记接入面必须 import 通道（摘掉即红）；已删私有 keyframes(`errorBarIn`/`chipFadeIn`）不许复活；共享呈现类存在且只引用 `crish-row-enter`。

### 2.3 与既有口径的协同

- **滚动锚定**：grow 的高度变化走 CSS transition（逐帧连续），贴底跟随的同步滚动补偿逐帧跟随，不产生阶跃；fade 不改高度。未触碰任何滚动提交逻辑（同步提交口径不变），静止贴真底/发送上推行为不变。
- **高度封顶与渐隐**：通道不绕开既有封顶容器；封顶面只接 fade（见 ReasoningRow/工具行处置）。
- **减动效**：判定核心只认系统 `prefers-reduced-motion`（与 AN4 一致）；`.crish-entrance-fade` 另有显式 reduce 媒体块兜底；CSS-only 消费（动态芯片、停止钮）由 `styles/reduced-motion.css` 的全局时长归零兜底。
- **motion/react 轨**（Toasts/对话框等，AppMotionProvider + strict 门禁）是既有 sanctioned 轨道，不在本批范围，不动。

## 六、未接入点位及理由（逐个点名）

- **整条消息行（AN2）**:#4。AN2 与通道共用同一 keyframes 语言、同一实况窗与减动效口径，是「行级」的既有实例；其时间戳窗 + FIFO 记忆与核心判定等价。强行替换的风险（回归已验收的发送上推/行入场行为）大于收益，故登记为通道的行级实例保留，不动。
- **CompactToolRow 不升 grow**:#1。行级高度生长会与过程段的虚拟化/包含（contain）策略及组级高度叙事叠加；且该文件在打磨批清单内。组/段层面的连续性由组容器（fade + 后续 grow 评估）与段 fade 承担。
- **工具组 grow 延后**:#2。组根已有 accordion 高度机制（grid 展开 + `calcAccordionDuration`)，且运行态默认折叠裁决刚落地（组头形成时高度基本为组头高、近恒定），grow 与 accordion 的合成需在打磨批落地后联合验证，避免双轨高度打架。本批先修 delay bug，组入场已由垫片走通道核心（fade)。
- **toolsTimelineItem / FoldableProcessSection**:#16/#17。透明/被覆盖的中间层，子元素已入场；再叠进入动画即双重动画。FoldableProcessSection 的 R9 占位替换为等高构造，无阶跃可修。
- **组折叠高度**:#18。既有 accordion 已满足「动画全过程与结果同步」，通道只管「入场」不管「开合」，职责不重叠。
- **streamHost / SessionReadyCover**:#19。会话切换遮罩，不是 AI 工作期间的内容新增；其淡入服务于切换掩盖，口径不同。
