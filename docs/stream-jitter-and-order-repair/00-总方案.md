## 二、四大收敛支柱（Core Architectural Pillars）

### 支柱 1：四级因果全序与 SQLite 本地水合单轨（对齐 01、07、09 方案）

1. **时间戳精准解析**：在 `sessionEventProjection.ts` 中废除无条件 `Date.now()` 回退；优先提取 `event.message.createdAt`（ISO8601 毫秒值）与信封 `engineSequence`，确保历史消息因果序单调递增。
2. **两级瀑布流水合策略（Local SQLite First）**：
   - 切换会话时 Phase 1 优先调用本地 SQLite 的 `ensureSessionBodyHydrated`（1~3ms 极速秒开并恢复权威 `seq` 存储序）；
   - 仅当本地数据库记录为空时，Phase 2 才回退至引擎事件重放；
   - 全程受双层 Generation Token 约束，彻底阻断高频切换时的乱序覆盖。
3. **四级严格弱序比较器（CompareMessageOrder SSOT）**：
   排序比较严格按四级代数公理展开：
   $$\text{engineSequence (seq)} \;\to\; \text{timestamp (ts)} \;\to\; \text{roleRank (System=0, User=1, Assistant=2)} \;\to\; \text{naturalNumericId}$$
   引入因果角色权（Role Rank），断言在同毫秒时 User 恒优先于 Assistant，彻底破除 ID 字典序倒置陷阱。

### 支柱 2：无缝快照锁定与零坍塌防御护盾（对齐 02 方案）

1. **四态确定性生命周期状态机**：
   - `ACTIVE`：尾块流式推进，双轨捕获增量单元树（`lockedUnitsRef`）与渲染快照（`lockedHtmlRef`）；
   - `SEALING_PENDING`（封口交接期）：当 `isActiveTail=false` 但 Worker 尚未返回时，快照锁存器继续向下游稳定下发高保真单元树或快照 HTML，**绝对禁止下发空串**；
   - `SEALED_STABLE`：权威 Worker `sealedHtml` 抵达，解开过渡锁，执行 $O(N)$ 原地 Patch，零 DOM 销毁；
   - `COLD_SEALED`：历史冷启动直接消费缓存/权威 HTML。
2. **协调器底层零坍塌护盾（Zero-Collapse Guard）**：
   在 `ReconciledMarkdownHtml` 中增加空串硬防御：若当前容器已有已渲染的子节点，且传入 `html=""` 且无 `incrementalUnits`，强行冻结当前 DOM 结构与盒模型高度，杜绝 0px 塌陷。

### 支柱 3：异步分片原子批收口与物理帧一元化（对齐 03 方案）

1. **原子批决议（Atomic Batch Resolution）**：
   在 `markdownRenderAsync.ts` 中，将单次 `advance` 产生的全部词法分片 Promise 集合封装为原子批次，统一使用原生的 `Promise.all` 批收口；单次推进严格**仅触发至多 1 次 React 状态更新**（重渲染次数减少 66%~90%）。
2. **递增世代令牌（Advance Generation Token）**：
   引入单调自增的 `advanceBatchIdRef`，决议完成时严格比对批次令牌，直接丢弃陈旧微任务，彻底杜绝乱序与撕裂。
3. **时钟源一元化**：
   以 `StreamRenderBuffer`（Level 1 物理帧，单帧 6ms 预算）为正文流式唯一权威时钟源，建立严密的 $1:1$ 物理帧节奏（1 rAF 帧 $\to$ 1 次 Store 更新 $\to$ 1 次分块 $\to$ 1 次原子解析 $\to$ 1 次 DOM reconcile）。

### 支柱 4：程序吸底令牌排他与树状数组即时提交（对齐 04、05 方案）

1. **程序滚动时序令牌契约（`performProgrammaticScroll`）**：
   在 `useVirtualScroll.ts` 中建立 `token` + `targetScrollTop` 双轨校验状态机。程序吸底期间标记 `active = true`，`onScroll` 捕获到匹配的目标事件时静默同步 `scrollTop`，**严禁触发 `bumpGestureEpoch()` 激活 100ms 冻结**。
2. **硬件物理输入排他接管**：
   真实物理硬件输入（`wheel`、`touch`、滑块 `pointerdown`）在捕获阶段立即销毁程序令牌，手势判定无缝接管。
3. **树状数组（VSM）高度每帧（rAF）即时提交**：
   切除 `setActual` 中对 `bumpGestureEpoch()` 的错误延寿调用；吸底跟随态下放行高度提交，树状数组单点更新复杂度仅 $O(\log N) < 0.01\text{ms}$，每帧即时提交彻底消除阶跃突跳，恢复 60fps/120fps 丝滑下延。

## 五、验收基线与硬性红线（DoD & CI Gates）

1. **时序正确性硬指标**：
   - 无论软件如何重启、多标签页如何高频切换，消息时间线完全保全真实因果序，**逆序重排缺陷率严格为 0%**；
   - 同毫秒或并发情况下，用户消息排在 AI 消息之前的正确率达到 100%。
2. **视觉稳定性硬指标（对齐 08 方案）**：
   - 流式修正累计布局偏移 $S\text{-CLS} \le 0.015$（CI 阻断红线 $> 0.05$）；
   - 封口瞬时高度振荡指数 $I_{\text{SHO}} \le 2\%$ 且绝对差 $\le 2\text{px}$；
   - 零节点瞬态计数 $N_{\text{void}} \equiv 0$ 次（严禁段落瞬间被清空删除）；
   - 视口反向跳动幅度 $V_{\text{jitter}} \le 2\text{px}$（红线 $> 8\text{px}$）；
   - 程序吸底手势假阳性误判 $GFPC \equiv 0$ 次。
3. **渲染流畅度硬指标（对齐 03 方案）**：
   - 单次推进触发 React 重渲染比严格保持 $\le 1.0$；
   - 主线程单帧脚本执行耗时 $\le 6.0\text{ms}$，100 tokens/s 极端吐字下帧率 $\ge 58\text{FPS}$。
4. **架构治理硬指标（对齐 06 方案与 ANTI_OVERENGINEERING_GUARDRAILS.md）**：
   - 零外部调度库依赖，零坐标测距魔术数字补偿；
   - 单一真理源单向流动，修改代码严格通过行数门禁与类型检查。
