# 流式渲染与时序修复战役：执行波子 Agent 通用执行规范

> **适用范围**：本战役所有实施波（Wave 1 至 Wave 4）所有子 Agent 必读  
> **指导文件**：`docs/stream-jitter-and-order-repair/00-总方案.md`、`docs/stream-jitter-and-order-repair/plan-reviews/00-主控最终决断书.md`、根目录 `AGENTS.md`

---

## 一、三原则宣誓（强制遵从）

所有执行子 Agent 必须时刻谨记：

1. **诚实**：明确汇报改动了什么、删除了什么、做到什么程度、遗留了什么。没有证据就是推测，不编造测试结果。
2. **必做与禁做**：
   - **必做**：必须在分配的文件域内完成任务；必须完成分配的《物理删除清册》项目；改动必须经过类型检查和测试验证。
   - **禁做**：严禁碰他人文件域；严禁提交 Git（提交权归主控）；严禁 `--no-verify`；严禁使用基于延时的 `setTimeout` 补丁；严禁使用坐标测距魔术数字补偿；严禁引入未经批准的外部依赖。
3. **负责**：对项目负责。发现上游或相邻逻辑缺陷，诚实记录并在汇报中指明，必要时向 `docs/agent-roles/shared-append/问题发现.md` 追加。

---

## 二、架构硬红线与防过度设计底线

1. **单一真理源（SSOT）**：
   - 时序因果全序以四级代数公理为准：`seq -> ts -> roleRank -> id`，严禁添加任何魔术序列号分支；
   - 封口过渡零塌陷以 `lockedUnitsRef` 增量单元树快照为第一真源，禁止高频逐字调用 `toHtml()` 序列化。
2. **负产出红线（有增必有删）**：
   - 任何改动不能只做加法。旧有死分支、死属性（如 `MessageToolCallsSection` 的 `virtualScrollManager` prop 与私有 RO）、死守卫必须彻底物理切除，不能留 TODO 或废弃注释。
3. **代码行数预算守门**：
   - 所有 TypeScript/React 文件必须遵守 `scripts/check-line-counts.mjs`。
   - 特别注意：`sessionEventProjection.ts`（业务逻辑上限 400，基线锁定 350，实测 348）严禁在内部直接追加长代码，必须将时间戳与因果解析拆离到外置纯模块 `sessionEventTimestamp.ts`！
   - 严禁使任何文件突破预警线或上限。

---

## 三、文件域与并行开发纪律

1. **文件域绝对排他**：每个 Agent 只能且必须只能编辑任务书中明确指定的 `File Globs` 范围内的文件。
2. **严禁越界修改**：若发现其他文件存在关联问题，只能在汇报中向主控提出，严禁自行“顺手修改”。
3. **改动留在工作区**：修改完成后，自测通过（运行对应 Vitest 单元测试），不要执行 `git commit` 或 `git reset`，改动直接保存在当前工作区。
4. **统一开发环境**：PowerShell 统一使用 `pwsh` (PowerShell 7+)，写文件统一 UTF-8 无 BOM。

---

## 四、汇报格式标准

完成任务后，请输出结构化报告：

1. **完成度总结**：明确列出“已完成”与“未完成”项；
2. **代码修改清单**：`文件路径:行号` 及改动意图；
3. **物理删除清单**：删除了哪些旧代码、死层、废弃属性；
4. **测试验证结果**：执行的具体测试命令与通过证据；
5. **行数预算自检**：修改后文件的有效代码行数变化情况。
