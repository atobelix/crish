# 新代码质量闸门（强制）

> 落地 ≠ 完成。每一段新代码必须经得起审查，否则回炉。

## 放行条件（全部满足）
1. **意图可陈述**：改动对应 SYSTEMATIC-FIX-PLAN 哪一节、消除哪条伪连通/双轨/硬编码。
2. **无新旁路**：不得用 shell、Null 冒充空参、stub 恒成功、`ok: true` 撒谎、兼容旧轨默认开启。
3. **对称失败**：校验失败必须硬失败且可观测；禁止半边校验（只读不写 / 只前端不后端）。
4. **测试非假绿**：单测覆盖失败路径与越界路径；不得只测 MIME/快乐路径。
5. **门禁可执行**：相关 check 脚本已挂总闸，或文档明确「未接线=未完成」。
6. **二次核查**：code-audit 出具 verification 文档；有 `[!]` 必须修复后再进入下一节。

## 打回条件（任一即回炉）
- 引入第二条实现路径「暂时共存」
- 删除功能后留空 stub 仍被调用
- 测试只断言「不抛错」而无行为断言
- 把风险下推到「调用方注意」而无类型/运行时强制

## 流程
实现 → 自测 → FIX-PROGRESS → code-audit 可证伪核查 → 无阻断项 → 才允许进入方案下一节
