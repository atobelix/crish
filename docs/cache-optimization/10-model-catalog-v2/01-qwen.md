## 4. 缓存机制说明（三套并存，2026-08-03 复核）

### 4.1 显式缓存（cache_control，手动断点，与隐式互斥）

- 开启：messages 的 content 块加 `"cache_control": {"type": "ephemeral"}`（仅支持 ephemeral）；tools 数组中的标记**被忽略**（工具定义作为系统消息一部分参与缓存，工具定义 JSON 序列化需完全一致）。
- 计费：创建 = 标准输入单价 **125%**（若新缓存块前缀已命中，只对新增部分按 125% 计，前缀部分按 10%）；命中 = 标准输入单价 **10%**；其余按原价。
- 限制：最低可缓存 **1024 token**；TTL 5 分钟（命中后重置）；单请求最多 **4 个标记**（超出取最后 4 个）；向前回溯 **20 个 content 块**；缓存创建发生在**模型响应之后**（首个请求不命中）。
- 支持模型（北京）：qwen3.8-max、qwen3.8-max-preview（Token Plan）、qwen3.7-max 全系、qwen3.6-max-preview、qwen3-max、qwen3.7-plus、qwen3.6-plus、qwen3.5-plus、qwen-plus、qwen3.7-flash、qwen3.6-flash、qwen3.5-flash、qwen-flash、qwen3-coder-plus、qwen3-coder-flash、qwen3-vl-plus、qwen3-vl-flash 及部分三方模型（deepseek-v3.2、kimi-k2.6/2.5/2.7-code、glm-5.1）。
- 协议：OpenAI Chat Completions、DashScope、Anthropic 兼容接口均可（计量字段不同，见 00-catalog §11.2）。

### 4.2 隐式缓存（自动，无法关闭）

- 前缀匹配 messages 数组公共前缀；创建无额外费用；命中 = 输入单价 **20%**（百炼部署模型；deepseek-v4-pro 例外，见控制台）；命中率 best-effort 不保证。
- 最低可缓存 token：百炼部署 **256**；**Qwen3.7 系列约 2000**；第三方部署（GLM 512、MiniMax 512）不同。
- 覆盖模型最广：千问 Max/Plus/Flash/Turbo/Coder/VL 全系 + 百炼/万擎部署 DeepSeek + Kimi + GLM + MiniMax + MiMo + Stepfun 等。
- OpenAI 兼容 Batch（文件输入）不享受缓存折扣；Batch 半价与缓存折扣不能同时生效。
- 提升命中：重复内容放提示词开头、差异内容放末尾；同一图像多次提问图像放前，不同图像同一问题文本放前。

### 4.3 Responses API Session 缓存（独立于上两者）

- Header `x-dashscope-session-cache: enable`（默认 disable）；服务端结合 `previous_response_id` 自动缓存对话上下文（响应 id 有效 7 天）。
- 最低可缓存提示词 **1024 token**；TTL 5 分钟；约束与显式缓存一致。
- **支持模型（2026-08-03 更新，已含新旗舰）**：qwen3-max、**qwen3.8-max**、qwen3.7-max（含 2026-05-20 / 2026-06-08 快照）、qwen3.7-plus（含 2026-05-26）、qwen3.6-plus、qwen3.5-plus、qwen3.7-flash、qwen3.6-flash、qwen3.5-flash、qwen-plus、qwen-flash、qwen3-coder-plus、qwen3-coder-flash。
- 计量：`usage.input_tokens_details.cached_tokens`。
- 端点：`POST {base}/compatible-mode/v1/responses`（旧路径 `/api/v2/apps/protocols/compatible-mode/v1/responses` 即将停用）。

### 4.4 与缓存强相关的特化参数（新增）

- `preserve_thinking: true`：把历史 reasoning_content 拼入下一轮输入（会计入输入 token 并计费），**会改变输入前缀结构**——与缓存前缀匹配策略直接相关，多轮缓存场景需评估。
- `reasoning_effort`（qwen3.8-max 支持）：档位越高思考输出 token 越多（按输出计费），不影响缓存。
- 思考模式开启时模型输出 reasoning 块；Anthropic 兼容端点下 thinking 块不可单独标记 cache_control（与官方约束一致，未实测）。

## 5. 特化优化线索

1. **coding 特化**：`qwen3-coder-plus`（1M，4-20 元档阶梯）与 `qwen3-coder-flash`（1M，1-5 元档）是百炼官方编程模型；qwen3.7-plus 为「AI 编程/Agent 开发」综合推荐（1M 上下文、完整工具调用、能力成本均衡）；qwen3.8-max 定位最强推理与编程。Coder 系支持显式+隐式缓存与 Session 缓存，长代码库场景建议静态上下文放 content 块开头并标记 cache_control（工具定义 JSON 一致性要求严格）。
2. **thinking 与缓存关系**：思考 token 计入输出（不参与输入缓存）；`preserve_thinking` 会把推理历史并入下一轮输入从而改变前缀；混合模式默认开启的 qwen3.8/3.7 系在多轮对话下建议关闭思考或保持前缀稳定以提升隐式缓存命中。
3. **成本结构提示**：qwen3.8-max 输出价 36 元/1M 是 flash 的 7.5~45 倍，思考模式默认 xhigh 会放大输出成本；缓存只降输入侧，输出侧无折扣。
