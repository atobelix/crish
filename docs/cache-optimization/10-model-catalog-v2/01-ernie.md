## 0. 结论摘要（先行）

1. **ERNIE 最新全系为 5.1 / 5.0 / 4.5-Turbo（文本与 VL）/ X1.1（深度思考）四档**：`ernie-5.1` 为最新旗舰（128k 上下文，2026-07-13 模型列表与计费页同步更新）；无独立 5.x「Pro」档，5.0 系列含 4 个 Thinking 版本。
2. **官方定价页仅对 4.5-Turbo 系与第三方转售模型提供「命中缓存」子项**；ERNIE 5.1 / 5.0 / X1.1 无命中缓存价目（不等于无缓存，但官方未给折扣价，见 §6.5 未获取项）。
3. **缓存命中折扣因模型而异**：ERNIE-4.5-Turbo 系命中 = 输入价 25%；DeepSeek-V4-Flash 千帆转售命中 = 20%；GLM-5.2 命中 = 25%；Kimi-K2.6 命中 ≈ 16.9%。全部无「缓存写入费」概念（纯自动缓存，无写价子项）。
4. **Anthropic 兼容端点已确认返回 `cache_read_input_tokens`**（2026-06-01 起 `input_tokens = prompt_tokens - cache_read_input_tokens`，官方公告 empm33i0q）；**cache_control 断点参数支持与否官方文档仍未提及**（需实测）。
5. **计量字段已确认**：OpenAI 兼容端点 `usage.prompt_tokens_details.cached_tokens`（用量统计说明）；Anthropic 端点 `usage.cache_read_input_tokens`；千帆控制台用量统计含「cache tokens 数 / cache 触发次数」。
6. **Responses API 已上线**（`https://qianfan.baidubce.com/v2/responses`），支持 deepseek-v4-pro/flash、deepseek-v3.2、deepseek-v3.2-think、glm-5.1、glm-5、qwen3-coder 系列；**ERNIE 系列不在支持列表**；文档称 Responses API「使用缓存机制减少重复计算」但 usage 示例无缓存细分字段。
7. **models.dev 交叉验证结果**：models.dev 未收录任何 ERNIE / 百度千帆条目（grep 全库无匹配），无法用第三方数据交叉核对，只能以官方为准。

## 2. 缓存机制说明（已确认 / 未确认分列）

### 2.1 已确认

- **自动上下文缓存（prompt cache）存在**：计费页对 ERNIE-4.5-Turbo 系与多个第三方转售模型提供「命中缓存」价目；用量统计说明确认「触发上下文缓存后，输入命中缓存的 token 数量」以 `usage.prompt_tokens_details.cached_tokens` 返回，控制台提供「cache tokens 数 / cache 触发次数」指标。
- **命中折扣因模型而异**（官方原文口径：「折扣比例因模型不同而有差异」）：4.5-Turbo 系 25%、deepseek-v4-flash 20%、glm-5.2 25%、glm-5 25%、kimi-k2.6 ≈16.9% 等（见 §1 表内百分比）。
- **Anthropic 兼容端点返回缓存计量**：`https://qianfan.baidubce.com/anthropic/v1/messages`（全量 Chat 模型兼容）；2026-06-01 20:00 起 `input_tokens` 含义改为「未命中缓存部分的输入 token 数」，即 `input_tokens = prompt_tokens - cache_read_input_tokens`；命中 token 按 cache_read 价计费（公告 empm33i0q）。
- **缓存命中不额外计写入费**：全部模型定价表只有「输入 / 命中缓存 / 输出」三列，无 cache_write 子项（与 Kimi / DeepSeek 官方一致，写免费）。
- **Responses API 提及缓存降本**：官方 Responses API 文档称其「使用缓存机制减少重复计算，降低开发者使用成本并提升响应速度」，但示例 usage 无缓存细分字段（见 §5）。
- **Anthropic 兼容端点是 Claude Code / OpenClaw 等生态接入千帆的标准路径**（官方提供 settings.json 配置示例，模型推荐 deepseek-v3.2）。

### 2.2 未确认 / 未获取（诚实边界，不编造）

- **cache_control 断点支持**：Anthropic API 兼容文档全文未提及 `cache_control` / `cache_creation_input_tokens` 参数；官方只确认返回 `cache_read_input_tokens`（读侧）。**能否用 Anthropic 式显式断点控制缓存写入，官方文档无证据，需实测**。
- **最低可缓存 token 数**：官方未公布（无类似 512/1024/4096 的说明）。
- **缓存 TTL / 保留时长**：官方未公布（无 TTL 管理文档）。
- **缓存命中确定性**：是否 best-effort、是否有成本节省保证，官方未说明。
- **ERNIE 5.1 / 5.0 / X1.1 是否支持缓存命中**：定价页无「命中缓存」子项，无法确认这些模型命中缓存是否有折扣（可能按全价计费或未上线），需实测或等官方补充价目。
- **千帆控制台（console.bce.baidu.com）按量计费页**：需登录，本次无法抓取；价格以文档计费页（2026-07-13 更新）为准，文档已注明「商品价格可能存在延迟，最终价格以订单页为准」。

## 3. 上下文窗口与输出限制明细（已确认，来自模型列表页 2026-07-13）

- ERNIE 5.x 与 4.5-Turbo-128k 均 128k 上下文；4.5-Turbo-32k / VL-32k 为 32k；ERNIE-X1.1 为 64k。
- 深度思考模型最大输出含思维链（ERNIE-5.0 思维链 ≤60k、X1.1 ≤64k、DeepSeek-V4 ≤32k、Qwen3.5 ≤80k）；ERNIE 思考模型不支持 thinking_budget 参数，max_tokens 限制 reasoning_content+content 总长度；DeepSeek 系列支持 thinking_budget。
- 第三方模型窗口明显更大：deepseek-v4 系列 1M、glm-5.2 1M、glm-5.1/5 198k、kimi-k2.6 256k、qwen3.5 256k——**千帆通道内做长上下文任务应优先转售模型而非 ERNIE**。

## 4. 特化优化线索（针对 crish 缓存/成本优化）

1. **ERNIE-4.5-Turbo 是千帆通道内唯一有缓存折扣的自研模型**（命中 25%），且价格极低（输入 ¥0.8/1M、输出 ¥3.2/1M），适合高并发低成本场景；但窗口 32k/128k 与输出上限 12288 受限。
2. **deepseek-v4-flash 千帆转售命中价 ¥0.2/1M（20%）**：绝对价最低的命中档之一；但注意千帆转售命中折扣（20%）远不如 DeepSeek 官方直连（2%，$0.0028/1M≈¥0.02）——**同样命中量下千帆通道贵约 10 倍**，纯缓存收益场景应优先官方直连。
3. **GLM-5.2 千帆转售命中 ¥2/1M（25%）** vs z.ai 官方命中 $0.26/1M（≈¥1.9，≈18.6%）——千帆命中折扣比例反而更高，绝对价接近；窗口 1M 是千帆通道内最大的转售模型之一。
4. **分档定价陷阱**：ERNIE 5.1/5.0 输入 >32k 自动涨价（5.1：¥4→¥6；5.0：¥6→¥10），输出价同步上涨；GLM-5.1/5 在 >32k 涨价、DeepSeek-V3.2 在 >32k 涨价但命中价不变（0.40）——命中部分不受分档影响（DeepSeek-V3.2 两档命中价相同），长上下文 + 高命中场景对 V3.2 有利。
5. **ERNIE 5.x 无命中缓存价目**：若成本模型对 ERNIE-5.1/5.0 假设「命中=25%」将错误；官方未给折扣，应保守按无缓存折扣处理，等官方价目补充。
6. **搜索增强 0.004 元/次**：ERNIE 4.5-Turbo 系与 X1.1 触发联网搜索按次计费 + 输入膨胀（search_tokens），成本模型需把「搜索触发」当作独立成本项，非 token 价可覆盖。
7. **Responses API 对转售模型开放（不含 ERNIE）**：走 Responses API 的缓存降本仅对 deepseek-v4-pro/flash、deepseek-v3.2(-think)、glm-5.1/5 生效；ERNIE 仍走 Chat Completions / Anthropic 端点。
8. **Anthropic 端点计量可复用 crish 现有适配层**：cache_read_input_tokens 语义与 Anthropic 官方一致（公告明示「与 Anthropic 的定义保持一致」），读侧字段映射可直接复用。
