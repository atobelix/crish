## 二、逐层诊断：为什么看起来「不高级」

### 2.1 ❌ 字体 — 最致命的短板

**现状** (`tokens.css:120`):
```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Helvetica, ...;
```

**问题**: 全部使用系统默认字体栈。在 macOS 上用 SF Pro 还算体面，但在 **Windows 上会落回 Segoe UI**，这个字体：
- 字重只有 Regular(400) 和 Semibold(600)，缺乏 Medium(500) 的过渡感
- 中文回退到 Microsoft YaHei（微软雅黑），笔画粗糙，字间距松散
- 行距感觉偏大，因为 x-height 不够高

**参考截图中的效果**: Notion 使用自定义 `Inter` + `Noto Sans SC` 的组合，字形紧凑、字重丰富（300/400/500/600/700），中文渲染质量高。

**修复方案**:
```css
@import url('https://fonts.googleapis.com/css2?family=Inter:wght@300;400;500;600;700&family=Noto+Sans+SC:wght@300;400;500;600;700&display=swap');

--font-sans: 'Inter', 'Noto Sans SC', -apple-system, BlinkMacSystemFont, sans-serif;
```

**影响**: 这一条改动就能让整体观感提升 30%。字体是 UI 的「空气」，用户不会注意到它但能感知到差异。

### 2.2 ❌ 页面壳层 — 结构太单薄

**现状** (`shell.css`): 只有 82 行，一个 44px 高的 header + 全白的编辑区域。

**与参考截图的差距**:

| 参考截图有的 | 当前有没有 |
|:------------|:--------:|
| 左侧边栏（页面树 / 收藏 / 搜索） | ❌ |
| 页面封面图（Cover Image） | ❌ |
| 页面图标（Emoji / Icon picker） | ❌ |
| 页面标题区（大字 + 副标题 + 属性） | ❌ |
| 面包屑导航 | ❌ |
| 右上角用户头像 / 分享按钮 | ❌ |
| 底部状态栏（字数 / 最后编辑时间） | ❌ |

**现状 header 的问题**:
- 高度 44px 太矮，Notion 是 45-48px 且有更多呼吸感
- `--bg-primary` 纯白背景与编辑区无区分，没有层级感
- 品牌名 `Conex Composer` 用 `--text-sm` (13px) 太小，缺乏存在感
- 工具栏按钮（导入/复制/下载）挤在右侧，没有分组和间距节奏

**修复方向**:
1. 增加 Sidebar 组件（~300 行 TSX + ~400 行 CSS）
2. 增加 PageHeader 组件（封面图 + 图标 + 标题）（~200 行 TSX + ~250 行 CSS）
3. Header 加入 `backdrop-filter: blur(12px)` + 半透明背景，产生毛玻璃质感
4. 底部状态栏独立组件

### 2.3 ❌ 排版节奏 — 间距不够考究

**现状** (`prosemirror.css:121`):
```css
.ProseMirror > * + * {
  margin-top: 0;
}
```

**问题**: **所有块之间的间距为 0**，完全靠行高（1.6）撑出间距。这导致：
- 标题和段落之间的间距不够明确，视觉层级模糊
- 列表项之间过于紧凑
- 不同类型区块（如段落 → 代码块 → 段落）之间没有「呼吸感」

**参考截图中**: Notion 的块间距是精心设计的——段落间约 4px，标题前约 32px，标题后约 8px，代码块前后约 12px。

**修复方案**: 为不同块类型定义差异化间距：
```css
.ProseMirror > * + * { margin-top: 1px; }
.ProseMirror > * + h1 { margin-top: 2em; }
.ProseMirror > * + h2 { margin-top: 1.4em; }
.ProseMirror > * + h3 { margin-top: 1em; }
.ProseMirror > h1 + *, .ProseMirror > h2 + *, .ProseMirror > h3 + * { margin-top: 4px; }
.ProseMirror > * + pre, .ProseMirror > * + .block-shell { margin-top: 8px; }
.ProseMirror > pre + *, .ProseMirror > .block-shell + * { margin-top: 8px; }
```

### 2.4 ⚠️ 动效系统 — 设计精良但未充分使用

**亮点**: `motion.css` (313 行) 是整个项目最高质量的文件：
- 专业的缓动曲线命名体系（standard/decelerate/accelerate/emphasized/spring）
- 合理的时长阶梯（instant 70ms → slower 380ms）
- 进出不对称（退场 0.6x 进场时长）
- `prefers-reduced-motion` 无障碍降级
- `motion-lift` / `motion-tap` / `motion-stagger` / `motion-affordance` 工具类

**问题**: 这些工具类在组件 TSX 中**几乎没有被使用**。

具体来说：
- `Editor.tsx` 的按钮用了 `motion-tap` ✅ 
- 但 SlashMenu、BubbleMenu、BlockMenu 的 **TSX 组件中没有引用 motion 类**
- `motion-lift` 定义了卡片悬浮抬升效果，但数据库的 KanbanCard、GalleryCard **没有使用它**
- `motion-stagger` 定义了列表交错入场，但 SlashMenu 的列表项**没有使用它**
- `motion-affordance` 定义了悬浮才出现的控件（拖拽手柄），但实际组件**还没有对接**

**修复方向**: 不需要新增 CSS，只需要在 TSX 组件的 className 中正确使用这些已定义好的类。

### 2.5 ❌ 区块视觉 — 功能有但质感缺

#### 代码块 (`code-block-view.css`)

**亮点**: highlight.js 配色与 Notion 暖灰体系适配，行号用 CSS 计数器不进入复制 ✅

**问题**:
- 圆角 `--radius-xl` (8px) 偏小，参考截图中代码块圆角约 12px
- 缺少 **语法高亮主题切换**（当前只有浅色主题）
- header 背景 `--code-header-bg` (#f0efeb) 和代码区 `--code-bg` (#f7f6f3) 对比度太低，头部和内容区分不清
- 没有 **代码块标题/文件名** 的高亮渲染（只有输入框，没有渲染态样式）

#### Callout 块 (`fenced.css`)

**亮点**: 5 种类型配色完整，border-left 设计正确 ✅

**问题**:
- 圆角 `--radius-sm` (3px) 太小，看起来像表格而非卡片
- 缺少 **图标选择面板**
- 编辑模式 `is-editing` 的背景直接切到白色，没有过渡
- 没有 **折叠** 功能的动画样式

#### 数据库 (`database.css` — 20,063 行，最大的 CSS 文件)

**亮点**: 这是目前样式量最大的模块，table 列宽拖拽、单元格类型（标签/日期/复选框/人员）、分组、排序/过滤面板等基础功能都有 ✅

**问题**:
- 样式量大但**视觉差异化不足**——所有视图（table/kanban/gallery/calendar）的卡片/行/格子用的是同一套极简边框，缺乏参考截图中的：
  - 卡片的 `box-shadow` 层级感
  - 彩色标签药丸的饱和度和圆角
  - 行悬浮时的微抬升效果
  - 列头的排序箭头动画
- Kanban 列缺少 **拖拽时的占位线动画**
- Gallery 卡片缺少 **封面图的 aspect-ratio 控制** 和 **悬浮遮罩**

#### 媒体块 (`media-layout.css` + `media-data-blocks.css`)

**亮点**: 图片/视频/音频/文件/书签的空状态和渲染态都有定义 ✅

**问题**:
- 图片块缺少 **拖拽调整大小** 的手柄样式（四个角 + 八个方向）
- 视频块的 iframe 容器没有 `aspect-ratio: 16/9` 控制，高度会坍缩
- 音频播放器的进度条缺少 **自定义滑块样式**（当前用浏览器默认 `<input type="range">`）
- 书签卡片的 OG 预览缺少 **加载骨架屏** 动画

### 2.6 ❌ 菜单系统 — 结构好但质感差一步

**斜杠菜单** (`menus/index.css`):
- 宽度 320px ✅ 分组标题 sticky ✅ 空状态 ✅
- **问题**: 菜单项的图标区域（`.slash-menu__icon`）是方形边框容器，Notion 的是 **彩色圆角矩形 + 白色图标**，视觉冲击力差很多
- 缺少 **搜索输入框** 的样式（当前靠 `suggestion` API 过滤，没有可见的搜索栏）

**气泡菜单** (`menus/index.css:174`):
- 基础结构完整 ✅
- **问题**: 没有 **颜色面板** 的 swatch 悬浮缩放动画
- 链接编辑面板过于简单（只有一个 input），参考截图中还有「移除链接」「在新标签打开」等按钮

### 2.7 ❌ 主题系统 — 完全缺失

**现状**: 只有亮色主题。没有 `tokens-dark.css`，没有 `[data-theme="dark"]` 切换。

**影响**: 这是用户最容易感知到的「不高级」因素之一。现代编辑器（Notion、Obsidian、Typora）都默认支持暗色主题。

**工作量**: ~300 行 CSS（暗色变量覆盖）+ ~50 行 TSX（切换按钮 + localStorage 持久化）

## 四、总结

### 核心结论

当前代码的**基础架构质量很高**——`tokens.css` 的色彩体系完整、`motion.css` 的动效规范专业、`block-shell.css` 的通用外壳设计合理。问题在于：

1. **字体是最大的败笔** — 系统默认字体在 Windows 上的渲染质量直接拉低整体观感
2. **壳层太单薄** — 没有 Sidebar / 封面图 / 页面标题区，看起来像个 textarea 而非产品级编辑器
3. **动效系统设计了但没用上** — `motion-lift` / `motion-stagger` 等工具类定义了却未挂载到组件
4. **区块间距无差异** — 所有块 margin-top: 0，视觉层级完全靠行高硬撑
5. **暗色主题缺失** — 一个不支持暗色主题的编辑器在 2026 年会被认为不完整
6. **区块质感差最后一步** — 功能有了但圆角偏小、阴影太浅、颜色对比度不够、悬浮效果缺乏

### 代码量差距

达到 50,000 行的目标需要新增约 **34,000 行**，分布预估：
- TSX 组件新增 ~12,000 行（Sidebar / PageHeader / 数据库高级视图 / 行内节点 / 表单 / 选择器）
- CSS 样式新增 ~14,000 行（暗色主题 / 新组件样式 / 现有组件打磨 / 响应式）
- TS 逻辑新增 ~8,000 行（Extensions / Hooks / Utils / Services）
