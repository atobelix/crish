## 1. 验收可判定性与假完成空间

### 1.1 「D8 WARN 清零」能否被消判据不消根因骗过

**门禁机制事实**（`scripts/check-provider-single-track.mjs`）：

- `D8_SYMBOLS = ['saveProfiles', 'saveProfileKey', 'setActiveModelId']`（:701），按 stripComments 后**符号字面量命中**计数；
- 岛内命中 → WARN（:742）、岛外已知债务 → WARN（:749）、岛外**新增** → FAIL（`--guide` 文案 :173）；
- WARN **不阻断 exit=0**（问题池锚点已实证「exit=0 仅 D8 两条 WARN」）。

**可被以下手法骗过的空隙**：

1. **改名清零**：把 `saveProfiles` 改名为 `writeProfiles` 等，符号不命中 → WARN=0，但 LS 档案仍是真相源。04 §1.1 第 15 行显式允许「删函数或改名去 D8 符号」——若只改名不迁树，即典型消判据不消根因。01 §3-P2 断言「组件/工具层业务分支只读 credentialStates」与 05 §2.2②③（零回写负向 + 消费面读树断言）是必要补丁，**但 00-总方案 §4 与 01/02 完成定义把「D8 WARN 清零」列为并列完成项，单凭 WARN=0 不足以判定完成**。
2. **删门禁登记表本体而代码未清**：02 §3-P2 与 04 §2.1 均要求「归零后删 `D8_ISLAND`/`D8_KNOWN_DEBT`」——顺序写反（先删表后改码）时，若岛内路径从 `D8_ISLAND` 移除，命中会落到「岛外新增 → FAIL」（仍能拦住），但**直接改脚本 `D8_SYMBOLS` 或整段 D8 则完全静默**。05 §1「反作弊」与 §3.1「清零步骤与生产收敛绑定，禁止只改常量」是唯一对此设防的条文。
3. **正逆向断言缺口**：01/02 给出「UI 只消费 `credentialStates`」「测试不以 LS 键为业务真值」，属**可判定方向但未指定落点文件与断言形态**；05 §2.2 把它落成「mock 树回执 `credentialStates[p].hasKey` 而非 `loadProfiles()`」的可执行设计，并要求 WARN→CEILING 硬红（§3.1：`D8_ISLAND_COUNT_CEILING=16` 只降不升）。

**判定**：仅按 00/01/02 的「D8 WARN 清零」验收**可被骗过**；必须叠加 05 的消费面正负向 + 棘轮升级，才闭环。**建议主控把 05 §2.2/§3.1 写入总案完成判定，WARN 清零降为必要非充分条件。**

### 1.2 「ENGINE_API_DEBT = 0」能否被骗过

**机制事实**（`apps/crish-desktop/src/api/transport/command-contract-drift.test.ts`）：

- `ENGINE_API_DEBT` ×2（`config_get`/`config_update`，:280-304），`ENGINE_API_DEBT_CEILING = 2`（:312）；
- 断言一豁免**仅在 `transport.*` 形态**生效（:418 `ENGINE_API_EXEMPTIONS.has(n) && transportForm.has(n)`）；
- 自证断言（:440-461）：条目必须 (a) 仍以 transport 形态出现、(b) 不得以 invoke 形态出现、(c) ∉ Rust 注册面——任一不满足即红，逼删条目；
- 债务棘轮 `≤ CEILING`（:520-524）。

**已封死的作弊面**：单纯删债务条目而保留 `transport.request('config_get')` → 断言一立刻红（未注册断链）；把名字塞进豁免但改成 `invoke(` 形态 → 豁免不作用 → 红；调用名消失后条目冗余 → 自证 (a) 红逼删。**「表清空 + 断言全绿 + 断链仍在」这一最直接骗法不成立**。

**仍存的假完成空隙**：

1. **删调用不接真源**：删除 `loadEngineConfig`/`updateEngineConfig` 死调用后债务=0、断言绿，但若保留函数壳**恒返回 null / 硬编码成功**而未接统一树或 `settings_*`，总案「完整产品链存活」不满足而判据全绿。01 §3-P1 有「改接单一通道后不得再静默吞错 + 正/逆向回归：合法树读写通」；02 §3-P1 负向偏「绕过树的写路径不可达」，**正向「读到树真值」偏弱**；05 §2.1③明确要求「正向断言调用 `modelsCatalogStore`/`settings_*` 单一合法面」——**必须以 05 为验收下限**。
2. **复活退役命令**：在 Rust 重新注册 `config_get` 可让断言一变绿并逼自证删条目；但 D1 退役符号清单含 `config_get(`（`check-provider-single-track.mjs` :129、:422，kind=rust 命中须=0）可拦。**D1 与 drift 双门必须同时保持绿**，总案完成判定目前只写了 drift（00 §4），未写 D1 复跑——**建议改：完成判定补「D1 退役符号 7 项全 0」**。
3. **REST 孪生路线歧义**：债务条目 evidence 已写明 `GET/PUT /v1/settings` 孪生存在（drift :286-288、:298）。01 待确认#1、02 待确认#1、05 §7.1 均未裁决「删调用 vs 改 REST vs 并入树」。三条路线对「何为正向断言」完全不同（REST 路线正向=HTTP 面，树路线正向=store）。**P1 路线未锁 = 正向断言暂不可判定**——属主控必须先裁的前置。
