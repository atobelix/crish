## 0. 方案定位与硬约束

### 0.1 视角三原则

1. **每期窄文件域**：一个期只动一组互斥（或明确串行争用）的文件；禁止跨期大杂烩 commit，避免「一锅端」合并与回滚事故。
2. **可 git revert**：每期对应独立 commit 粒度（同文件多期时按期拆 commit、同文件串行）；`git revert <commit>` 后工作区回到该期之前语义，**不需手工拆解冲突**。
3. **仍必须收敛（禁永久双路径）**：期与期之间允许的「过渡双路径」必须同时写明——**删除面 + 收敛触发条件 + 收敛后路径数**；任何双路径若只写「暂保留」而无删除动作与终点，视为方案不合格。兼容壳不得成为终态。

### 0.2 与总方案不可变条件对齐（不得削弱）

- 单一写者：`ModelsStore` + `models.yaml`（已立，不得回退）。
- `hasKey` 等凭据状态唯一真源 = 统一树 `credentialStates`；LS 档案不得再作真相源。
- 活动选择 / 最近使用 / 默认模型候选序：身份一律 `(providerId, modelId)`；禁止裸 `modelId`、substring、AppSettings 兜底参与决议。
- 出厂字典只做预填参考，**禁止把预估价写入用户树**（P4 写入门禁已落地，防回潮与读侧对齐仍须收敛）。
- 退役命令零调用；注释不得声称未接线链路已通。
- 不留无删除日期的 fallback；不新建并行路径。

### 0.3 路径数记法

沿用同批方案：`现状 N → 收敛到 M`（M 通常为 1；若存在只读镜像等合法副路径，M=2 并注明主从）。  
「路径」指**同一语义的读/写/决议入口数**，不指 commit 数或文件数。

| 期（=P 标签） | 主题 | 相对依赖 |
