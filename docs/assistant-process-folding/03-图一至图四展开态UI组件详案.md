### 1.2 架构设计与复用原则

1. **单一真理源（SSOT）**：
   - 思考行只有一种实现：`ReasoningRow.tsx`；
   - 工具行只有一种头部容器：`ToolCallHeader.tsx`；
   - 差异与人类意图提炼由纯逻辑函数 `toolHeaderPresentation.ts` 与 `toolHumanDescriptions.ts` 集中派生，无组件层私有分叉。
2. **严格几何隔离与反回流（Layout Containment）**：
   - 头部容器死锁 24px：`height: 24px; min-height: 24px; max-height: 24px; line-height: 24px; box-sizing: border-box;`；
   - 未展开状态应用 `contain: size layout`，阻止流式字符打字引起外层视口反复排版重算；
   - 展开状态切除内部第二重垂直滚动条，融入文档主流，由外部单轨滚动容器统一调度。
3. **零补丁零魔术数字**：
   - 严禁通过 `marginTop: -3px` 或硬编码固定像素定位补偿；所有图文对齐均基于 Flexbox 网格、`align-items: center` 与 `font-variant-numeric: tabular-nums`；
   - 色彩统一使用 Design Tokens 与 HSLA 格式，焦点环遵循 §13 规范（对比度上限约 10%）。

### 2.3 运行态状态标印系统（语义图标 + 运行态脉冲）

#### 现象剖析（代码事实）

`ToolCallHeader.tsx:97-105` 当前为**三元互斥**渲染：

```tsx
// ChatToolCallBlock.module.css 现有配套
<span className={styles.toolRowIcoSlot} aria-hidden="true">
  {running ? (
    <span className={styles.toolPulseDot} aria-hidden="true" />
  ) : isError ? (
    <span className={styles.toolErrorDot} aria-hidden="true" />
  ) : (

```

配套样式均已存在：`.toolRowIcoSlot`（css `:100-114`）、`.toolPulseDot`（css `:217-228`，4px 点 + `tool-dot-pulse`）、`.toolErrorDot`（css `:239-249`，6px `var(--color-error)` 点）。

#### 收敛裁决：**保持三元互斥，禁止叠加式改造**

原方案（「图标常驻 + `.toolPulseRing` 外扩环 + `.toolKindIconRunning` 呼吸」）**予以撤销**，理由：

1. **非法伪变量**：原方案新增 `.toolPulseRing` / `.toolKindIconRunning` 两个**全仓零引用的新样式类**，且 `.isRunning` / `.isError` 在 `.toolRowIcoSlot` 上的组合无任何现有调用点——这正是「功能伪连通」的典型形态（写了类名却没有真实宿主接线）。
2. **破坏语义唯一性**：24px 行内图标槽仅 16px（css `:101-103`）。在 4px 脉冲点 / 6px 错误点之外再叠加发光环，会在极窄槽内产生**三重状态信号**（点 + 环 + 图标），与图一/图四「单点克制标印」基准相悖。
3. **时序错觉**：`running` 态在真实交互中占比不足一次工具调用的极小片段，常驻语义图标的价值在 running 期间**并不高于「正在发生」这一事实本身**。图四的时钟图标表达的是 `timer` **kind**（由 `TOOL_COMMAND_ICONS.timer = 'timer'` 在**非 running 态**渲染），而非 running 态的特殊叠加——原方案对图四语义存在**误读**。

#### 唯一增量：让运行态标印具备「kind 感知」

当前 running 态丢失了 kind 信息（统一 4px 灰点）。按图四基准，**将 4px 点替换为「kind 图标 + 环」不成立**（同上述裁决 2）；采纳的最小方案是**保留 4px 点，仅提升其颜色对比**——复用既有 `.toolPulseDot`，不改结构：

```css
/* ChatToolCallBlock.module.css:217-228 —— 仅改 background 取值，不新增类 */
.toolPulseDot {
  width: 4px;
  height: 4px;
  min-width: 4px;
  min-height: 4px;
  border-radius: 50%;
  background: var(--text-secondary); /* ← 唯一改动：原为 var(--text-tertiary) */
  animation: tool-dot-pulse 1.6s ease-in-out infinite;
  display: inline-block;
  flex-shrink: 0;
  margin-right: 5px;
}
```

**错误态无需改动**：`.toolErrorDot` 已用 `var(--color-error)`，且错误路径文本已由 `.toolErrorParamText`（css `:263-273`）承载 `var(--color-error)`，信号充分。

**负向红线**：严禁新增 `.toolPulseRing` / `.toolKindIconRunning` / `@keyframes tool-ring-pulse` / `@keyframes tool-icon-breath`；严禁在 `.tsx` 中以 `isError ? 'alert-circle' : kindIconName` 伪造错误态图标（错误态由红点 + 红字表达，**不换图标**）；严禁在 `ToolCallHeader.tsx` 的 `.tsx` 中硬编码任何图标名字面量——图标名必须来自 `toolCommandIcon(kind)`（`api/tool-presentation/toolCommandIcon.ts:28`）与 **`@hugeicons/core-free-icons`** 经 `iconMap.ts` 收口的 `IconName` 联合类型。

## 4. 展开卡片在单轨虚拟滚动（VSM）内的体验保障

在图一至图四展开态中，点击单行将展开详细内容（如终端日志 `ToolCallOutputPane` 或代码差异 `ToolCallDiffPreview`）。而在虚拟滚动长列表中，大面积展开极易引发“视口被推跑、滚动条突跳或高度脱水”问题。必须由以下四项纪律构筑护城河：

### 4.1 展开高度突变与相对位移锚定（useToolExpansionState + ΔY ≡ 0）

在 [`apps/crish-desktop/src/components/chat-tool-call/toolExpansionState.ts`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-tool-call/toolExpansionState.ts) 中，已经完整实现了相对位移记录器与黄金防抖窗口。
- **展开防抖（100ms Debounce）**：拦截用户的快速误触连击，防止在动画过程中多次突变高度；
- **原地替换契约（100ms In-Place Replacement）**：连续串行调用的工具在原地发生指示翻转，消除瀑布卡片新增引起的视口抖动；
- **PreActionAnchor 相对位移锁定**：展开前置记录当前滚动容器视口锚点（`scrollTop` 与 `scrollHeight`），展开撑开高度后在浏览器绘制前微调补齐滚动差，确保视觉锚点绝对稳定（$\Delta Y \equiv 0$）。

### 4.2 单轨虚拟滚动测高作废契约（invalidateActual 刚性约束）

- **刚性禁令**：绝对禁止在展开组件（`ToolCallOutputPane` / `ToolCallDiffPreview` / `CompactToolRow`）内部私自实例化 `ResizeObserver` 去直接调用 `vsm.setActual(msgId, height)`。私自调用会跳过滚动引擎的 `actualTick` 调度机制，导致虚拟化高度错乱；
- **合法通道**：
  1. 用户点击展开或折叠触发状态切换；
  2. 触发回调调用 `vsm.invalidateActual(msgId)` 将该条目的高度标记为脏；
  3. 由外层 `MessageVirtualizer` 统一的宿主容器在下一个微任务微帧中读取渲染后的真实 DOM 尺寸，统一回填并同步滚动滑轨。

### 4.3 零内部多重垂直滚动条原则与大内容截断保护

- **零内部垂直滚动条**：展开的卡片禁止设置 `overflow-y: auto; max-height: 400px;` 这类局部矮盒容器！局部独立滚动条会导致鼠标滚轮在滑到卡片时被“捕获劫持”，产生恶劣的交互撕裂感。展开卡片一律使用自然平铺流式展示（`height: auto; max-height: none;`），融入会话主视图；
- **Diff 预览平铺限制**：在 `ToolCallDiffPreview.tsx` 中，默认平铺展示前 24 行（`DIFF_FLAT_PREVIEW_LIMIT = 24`），超出时提供“平铺展开至 200 行”或“在右侧差异面板中查看”，防止单文件万行 Diff 导致 DOM 树过载；
- **终端超长日志保护**：在 `ToolCallOutputPane.tsx` 中，当输出超过 2000 行 / 256KB 保护门限时，自动进行安全截断并外露“在命令检查器中查看完整日志”按钮，实现大容量日志的离线分流。

### 4.4 HTML5 原生搜索穿透协同（hidden="until-found" + beforematch）

当用户需要全局搜索被折叠的过程或历史输出时：
- 隐藏容器使用标准 HTML5 属性 `hidden="until-found"`，而不是传统的 `display: none`；
- 浏览器在用户使用 `Ctrl + F` 命中隐藏区域文本时，会自动对容器分发 `beforematch` 原生事件；
- 组件监听该事件并将自身展开状态 `isOpen` 置为 `true`，配合 `vsm.invalidateActual(msgId)` 实时恢复高度，让用户瞬间看到命中的搜索关键词。

### 6.3 虚拟滚动生命周期无抖动验收断言

1. **位移差分零晃动（$\Delta Y \equiv 0$）**：
   - 当视口上方展开一个包含 300px 内容的工具卡片时，`usePreActionAnchor` 自动介入；
   - 滚动容器的物理滚动条位置瞬间补偿 300px，视口内的正文阅读焦点位置相对于屏幕顶部的物理像素偏移量必须等于 0；
2. **VSM 测高自愈断言**：
   - 监听 `vsm.invalidateActual` 调用序列，展开瞬间必须派发当前 `msgId` 的失效通知；
   - 在随后 16.7ms 帧内，`vsm.getActual(msgId)` 必须更新为包含卡片展开后的真实物理总高，无脱水高度白屏现象。
