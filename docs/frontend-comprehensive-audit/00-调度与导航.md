> **战役状态**：第一轮 6 大专项审计并行盘查中  
> **遵循纪律**：`AGENTS.md` 规范、反退避原则、五大铁律红线、战役工作区结构规范

## 一、盘查背景与全盘诊断初检

通过全仓类型检查、静态门禁扫描与架构巡检，我们确认了前端既有的优秀资产（全仓 11 段 `tsc` 0 报错、G-01~G-17 收敛军规基座合规、`storeAccess` 门面完全收拢、零未注解空 catch）。
但与此同时，现场真实门禁与静态分析捕获到了 **6 大高危/重度问题领域**：

1. **依赖拓扑硬性断裂**：`depcruise` 爆出 `useNativeBrowserInstance.ts ⇄ usePreviewNavigation.ts` 循环依赖，且缺失 dev-server 脚本；
2. **Design Tokens 与色彩 SSOT 全面失守**：`check:color-ssot` 拦截 101 处色彩违规，`check:token-consistency` 拦截 16 处未定义 Token 与 70 处死 Token；
3. **视觉层级与字阶排版漂移**：`check:hierarchy-ssot` 拦截 286 处违规，Composer 与 Sidebar 超出基线，散落大量硬编码行高字号；
4. **国际化双重债务**：`check:i18n:hardcoded` 拦截 24 处源码中文泄漏，`check:i18n:unused` 爆出 1045 个孤立死词条（占比 74%）；
5. **UI 原子基座与 Headless 胶水割裂**：56.2%（315 处）越权穿透导入、1800+ 行自研脆弱胶水（含 focusTrap 30+ 选择器白名单、DOM 原生 removeChild 劫持）；
6. **巨型状态拓扑与会话/流式渲染管道复杂性**：45+ 个 Store/Action 文件协同复杂、Dual-latch 协议与两级缓存防抖同步隐患。

## 三、协作纪律与验收标准

1. **产出规范**：UTF-8 无 BOM、中文内容、结构严谨、必须包含具体文件:行号证据与真实数据；
2. **严禁破坏**：只读分析，严禁直接修改业务代码或使用 `--no-verify` 跳过门禁；
3. **输出互斥**：各 Agent 仅负责写入自己对应的 `audits/0N-*.md` 文件，禁止 cross-write。
