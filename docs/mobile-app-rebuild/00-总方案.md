# 移动端重建总方案（crish-mobile）

> 战役目录：`docs/mobile-app-rebuild/`
> 日期：2026-10-28
> 定位：把 `apps/crish-mobile` 从「能通过单测的工程骨架」重建为一款**真正可用、界面清晰、与桌面端同语言**的移动端伴侣应用。
> 裁决依据（用户，2026-10-28）：① 彻底改进，代码简洁、架构清晰、抽象合理；② 非必要不兼容，反对补丁式与兼容式改进；③ 该删就删，该重构就重构，减少重复；④ 先完成大块改造，再集中测试；⑤ 界面简洁清晰，避免不必要的次要标签与描述，让布局自己说话；⑥ UI 与桌面端一致，同时更适配移动端；⑦ 只有主 Agent 实施，质量优先，无时间 / token 限制。
>
> **远程接入延伸（2026-10-29 已落地）**：局域网直连之外的「同账号登录 + 自动发现 + 远程中继」已完成实现与部署，见 [`04-远程接入与账号自发现方案.md`](./04-远程接入与账号自发现方案.md)。Oracle 中继 `wss://proxy.flowbit.me:8443` 上线；桌面 host 桥 + loopback 网关、移动端账号/RelaySocket/在线发现均已接线；生产账号中心密码登录 500 已修复。
>
> **账号体系（2026-10-29 已落地）**：桌面新增全局账号中心（密码/验证码登录、注册、找回密码、资料/头像、在线设备、登录会话、退出），移动端补齐同样的账号生命周期与资料页；见 [`05-账号体系与登录界面.md`](./05-账号体系与登录界面.md)。

## 1. 结论先行

移动端当前不是「差一点样式」，而是**三层同时断裂**：

1. **界面层**：没有安全区、没有图标系统、没有排版 / 间距 / 圆角 token，页面各自实现头栏、返回、空态、卡片；文案大量暴露内部规格号（F1 §4.7、M4 §5.9、run、相位、环形缓冲），像一个调试面板而不是 App。
2. **运行时层**：会话列表没有初始拉取（`listSessions` 从未注入），连接打开后从未发送 `events.subscribe`，重连对账快照恒为空；文件 / 设置镜像 / 在场查询依赖的远程命令在桌面 WS 面根本没有实现。结果：**首页与文件页在真实环境里恒为空**。
3. **工程层**：Expo CLI 因缺失 `@xmldom/xmldom` 无法启动；配对端口在会话连接时丢失；解绑后观测单例不销毁导致换机重配连回旧主机；云端登录 / 一键直连是服务端 404 的假功能；若干兼容层、占位页、Emoji 图标与重复样板仍在。

因此本轮不是「修几个 bug」，而是：**先建立设计系统与运行时主干，再按 App 的信息架构重写表现层，最后做负产出收口与验收**。

## 3. 目标信息架构（App 应该有什么）

移动端定位为「桌面 Agent 的远程伴侣」：**看进展、批决策、发任务、查文件**。不做桌面全部设置项的镜像。

### 3.1 一级结构（底部 5 Tab）

| Tab | 图标语义 | 主职责 |
| --- | --- | --- |
| 首页 | Home | 连接状态、待审批、最近会话、发起任务入口 |
| 会话 | MessagesSquare | 全部会话、搜索、未读 / 运行 / 审批角标 |
| 审批 | ShieldCheck | 待审批列表、已处理历史 |
| 文件 | Folder | 工作区浏览、文本预览 |
| 设置 | Settings | 连接设备、外观、通知、关于、解除配对 |

### 3.2 二级页面

- 配对：欢迎 / 扫码 / 手动输入（含端口高级项）。
- 会话详情：对话与活动时间线 + 继续输入。
- 审批详情：请求详情 + 允许 / 拒绝。
- 审批历史：已处理记录。
- 运行详情：状态 + 控制 + 时间线 + 终端入口。
- 终端：只读输出回放。
- 通知中心：通知列表 + 全部已读。
- 文件预览：文本 / 占位态。

### 3.3 全局状态

- 启动：品牌 Splash + 恢复配对（不闪屏）。
- 未配对：配对流程（唯一入口）。
- 连接中 / 重连中 / 离线：全局细横幅 + 首页状态行；不阻塞本地浏览。
- 空态：图标 + 一句标题 + 一个动作，不写开发说明。
- 错误态：人话 + 重试；技术码只在诊断区出现。
- 操作反馈：Toast（审批已提交、已全部已读、已断开等）。

### 3.4 明确删除的界面

- 云账号登录、注册、一键免扫码直连。
- 文件「密度 44/48/56」切换。
- 会话详情常驻三枚过滤 chip（收进更多菜单，仅保留「仅看错误」快捷项）。
- 所有「F1 §x」「M4 §x」「run」「相位」「环形缓冲」等用户可见开发术语。
- 通知类别大徽章（改为小圆点 / 图标语义）。
- 审批卡中的原始 sessionId / runId（改为会话标题 + 相对时间）。

## 4. 目标设计系统（详见 `01-界面设计规范.md`）

- **色彩**：对齐桌面 `tokens-palette / surface / text`：品牌绿 `#10b981`，暖灰画布 `#f7f6f5`，卡片 `#ffffff`，发丝线 `#ebeae9`，主文字 `#121212`；深色 `#0f0f0f / #161616 / #1f1f1f`。语义色沿用桌面 danger/warning/info/success。
- **圆角 5 档**：4 / 8 / 12 / 18 / pill（输入胶囊 20 仅 composer 使用；按钮 8，不滥用 pill）。
- **间距 4pt 阶梯**：4 / 8 / 12 / 16 / 20 / 24 / 32。
- **字阶**：caption 11 / meta 12 / body 15 / subhead 17 / heading 20 / title 22 / display 28；移动端正文上浮一档保证可读性。

- **动效**：系统原生转场 + 按压透明度；不做装饰性弹跳；支持 reduce-motion。

## 5. 目标技术架构

### 5.1 移动端分层（保持既有方向，减少样板）

```
app/                       路由与守卫（薄）
src/presentation/ui/       设计系统原子（Screen/Header/Text/Icon/Button/Input/ListRow/Sheet/Toast…）
src/presentation/screens/  页面组合（只依赖 VM + ui + 领域展示组件）
src/presentation/components/ 业务展示块（会话行、审批卡、时间线块…）
src/adapters/              平台绑定、VM、wiring、runtime
src/domain/                纯 store / reducers / 纯函数
src/network/ /pairing/ /notifications/  领域服务
```

关键改动：
1. **新增 `src/adapters/runtime/appRuntime.ts` 单一装配根**：配对成功 / 冷启动恢复后统一建立连接、拉会话、发订阅、按需回填、断线重连、解绑销毁；所有 `use*Vm` 不再各自 ensure 单例。
2. **重写 `FeedBridge` 为订阅驱动**：open → `listSessions` → `events.subscribe(subscribedSessions, cursors)` + `events.subscribeAll(criticalTypes)`；`subscribe.ok` 参与对账；打开会话时 `readSessionEvents` 分页回填。
3. **统一仓库**：`monitorRepository`（status/sessions/events）、`filesRepository`、`settingsRepository` 的发送 / 解析 / 错误映射走同一 `invokeCommand`，删除重复包装。
4. **表现层纯化**：组件不 import `expo-router`；导航一律由 route 注入或页面层注入。
5. **展示投影层**：新增 `presentation/timeline` 纯函数，把原始事件折叠为 `AssistantMessage / ToolCall / Approval / Notice / Error` 块；会话详情不再渲染原始事件行。
6. **设计 token 单一真源**：`adapters/platform/theme.ts` 输出 `colors / space / radius / type / size / shadow`；组件禁止裸值（新增移动端样式守卫，见 §8）。

### 5.2 桌面服务端（必要的配套）

移动端「真正能用」要求桌面 WS 命令面补齐：

- `ws.rs`：把 `remote.<cmd>` 从 6 条硬编码扩展为**白名单通用分发**（覆盖 C01–C32 中已实现的 REST 后端方法）。
- `ApiBackend` 新增并实现：`list_dir / read_file / list_workspaces / switch_workspace`（复用 `fs_commands` + `WorkspaceFsGuard`；新增 `WorkspaceOps` 由 main.rs 注入，避免 CoreStateBackend 持有 Tauri 依赖）。
- 会话索引、事件分页、运行事件、审批历史通过通用分发直接可用。
- 移动端不再依赖 `queryPresence / listDevices / getSettings`：设置「关于」改为本地信息（主机、桌面 ID、连接状态、App 版本），不做无意义的远端镜像。

### 5.3 TLS / 配对可信

桌面服务强制 wss + 自签 CA，移动端原生 WebSocket 无法自定义信任。方案按优先级：

1. **首选（生产，未实施）**：新增本地原生模块 `crish-ws`（Android OkHttp / iOS URLSessionWebSocketTask），按配对下发的 CA SPKI 指纹做 pinning，JS 侧适配标准 WebSocket 接口；配对成功后持久化指纹，替换 `ReconnectingWsClient` 的 socket 工厂。
2. **过渡（已落地）**：系统证书信任引导——桌面「设置 → 多端互通 → 安全连接 → 导出证书」（`multi_device_export_ca`）导出 `crish-ca.crt`；Android 经 `plugins/withUserCaTrust.js` 在 prebuild 写入 network security config（system + user trust anchors），iOS 经描述文件安装并在「证书信任设置」完全信任；wss 传输失败文案直接提示首次连接需信任桌面证书，连接帮助 Sheet 给出两端步骤。
3. **假安全叙事已删除**：当前信任模式 = 系统 CA 信任 + 应用层指纹一致性校验；不是传输层 pinning，UI/README 均按此口径展示。

**落地边界**：原生 pinning 仍为显式后续项（需要 dev build 与 iOS 实机验证）；本轮不伪造「已固定指纹」。Android user CA 信任依赖原生构建，Expo Go 不适用。

本项独立成阶段（见 §7 阶段 6），不与 UI 重构混在一起，避免不可测试的大爆炸。

## 8. 风险与边界

- **TLS 是外部性最强的一项**：原生模块需要 dev build；iOS 无法在 Windows 上实测。计划先完成可验证的 Android 路径与系统信任引导，并在文档中如实标注 iOS 验证状态，不伪造。若你希望本轮只做 UI 与运行时、暂缓原生模块，我会把该项保留为显式阻断并给出验收步骤。
- **桌面服务改动**仅限于 WS 命令分发与文件读命令；不改引擎语义、不降低安全基线。
- **推送**：本轮保证应用在前台/后台存活时的系统通知与通知中心；不实现 Expo Push 服务端注册（桌面推送令牌链路未上线），如需要会单独登记。
- **测试集中跑**：中途只做 typecheck 快速自检，大块完成后跑全量 jest / cargo；最终以全绿为准。
