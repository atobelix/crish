## 1. 结论先行

**目标效果（已达成）**：手机和电脑登录同一个 Crish 账号，电脑端应用在线，手机打开即可看到“我的电脑（在线）”，无需扫码、无需 IP/端口、无需公网暴露配置，自动建立远程控制连接。

**最终路径**：

- 身份：继续使用 `auth.flowbit.me`（首尔）做登录 / refresh / 账号档案；**生产账号中心没有设备注册表**，本轮不新增、不依赖。
- 发现：在线桌面由美西 Oracle 中继的房间状态天然表达（`GET /v1/devices`，Bearer access token），手机只看到当前真实在线的桌面。
- 转发：桌面 host 与手机 client 都只做出站 WSS 连接，经 `wss://proxy.flowbit.me:8443/v1/relay` 盲转发业务帧。
- 桌面复用：host 桥把中继帧送入本机 `127.0.0.1` loopback 网关（随机桥密钥），完全复用既有远程命令 / 事件 / 审批 / 终端协议，不写第二套业务协议。
- 运行时**不依赖 Tailscale**；Tailscale 仅作为本轮部署与排查通道。

## 2. 最终架构

```text
                  ┌──────────────────────────────┐
                  │ auth.flowbit.me（首尔）        │
                  │ 登录 / refresh / /api/auth/me │
                  └──────────────┬───────────────┘
                                 │ HTTPS（登录、身份校验）
          ┌──────────────────────┴──────────────────────┐
┌─────────▼─────────┐                         ┌─────────▼─────────┐
│ 桌面 Crish          │                         │ 手机 Crish         │
│ 账号登录             │                         │ 账号登录 + SecureStore │
│ loopback 网关        │                         │ 在线桌面发现        │
│ relay host 桥        │                         │ relay client 连接   │
└─────────┬─────────┘                         └─────────┬─────────┘
          │ wss host ticket                              │ wss client ticket
          └──────────────────┬───────────────────────────┘
                             ▼
              ┌──────────────────────────────┐
              │ 美西 Oracle 中继（conex-relay） │
              │ 票据签发 + 校验 + 房间 + 转发   │
              │ 无业务存储 / 无 payload 日志    │
              └──────────────────────────────┘
```

### 2.1 账号中心边界

- 只调用 `GET /api/auth/me` 校验 access token（`crates/conex-relay/src/account.rs`）；60s 缓存，失败 fail-closed。
- **不做设备归属校验**：中继房间隔离边界是 `(account_id, host_device_id)`，票据只签发给同一账号；device id 只是账号内的路由标识，不构成跨账号权限。
- 因此不依赖账号中心不存在的 `POST /api/devices`、`/api/devices/:id/seen`；桌面端已删除对应死代码。

### 2.2 在线设备发现（中继提供）

- 桌面 host 连接中继时携带 `deviceName`，票据 claims 带设备展示名（`device_name`），hub 记录在线 host。
- `GET /v1/devices`（Bearer）返回当前账号内在线 host：
  `{ items: [{ id, name, platform: "desktop", online: true, lastSeenAt }] }`。
- 离线桌面不再占位（无注册表），移动端空态即“电脑未在线”；桌面重新上线后下一轮 discovery（15s）自动出现。

### 2.3 票据与协议

- `POST /v1/ticket/host`：Bearer + `deviceId` + `deviceName` → 60s HMAC 票据（host）。
- `POST /v1/ticket/client`：Bearer + `deviceId` + `targetDeviceId` → 60s 票据（client）。
- `GET /v1/relay?ticket=...`：验签 + 过期 + 一次性 `jti` 防重放 + 连接数上限，然后按房间配对。
- 帧协议（JSON）：

```text
客户端 → 中继：{ type: "relay.data", payload: <DeviceEnvelope> }
              { type: "relay.ping", ts }
              { type: "relay.pong", ts }
中继 → 客户端：{ type: "relay.ready", role, roomId, deviceId }
              { type: "relay.peer", state: "online"|"offline", role, deviceId }
              { type: "relay.data", from, deviceId, payload }
              { type: "relay.ping"|"relay.pong", ts }
              { type: "relay.error", code, message }
```

- 中继不解析 payload、不落业务数据；单帧上限默认 1 MiB（与业务网关一致），连接上限默认 1024。

### 2.4 桌面 host 桥

- 登录后启动独立 loopback 网关（`127.0.0.1:<随机端口>`，TLS off，仅桥密钥可连），与面向局域网的 8765 服务生命周期分离；不受多端服务开关影响。
- `POST /v1/relay-loopback` 之外的普通 LAN/WSS 仍走原配对鉴权；loopback 升级需 `Authorization: Bearer <bridge secret>`（64 字符随机值，常量时间比较），连接标记 `trusted_relay`，跳过设备级 HMAC / 配对门控。
- host 桥接每收到 `relay.peer online` 才建立本地 loopback WS；对端离线即关闭；本地帧与远端帧双向包/解 `relay.data`，不解析业务字段。
- 中继断开后 5s 内重新申请票据并重连；票据仅用于 WS 升级，不影响已建立连接。

### 2.5 移动端

- 账号：`src/adapters/account/*`（登录 / refresh / 网络在线设备发现）、`src/domain/store/accountStore.ts`、`src/db/secureStore.ts`（账号凭据独立槽位）。
- 连接：`src/network/RelaySocket.ts` 对上层伪装为标准 WebSocket：先申请 client 票据，等待 `relay.peer online` 才触发 `onopen`，`relay.data` 自动包/解信封，`ping/pong` 自动应答，`replaced/peer.offline` 触发重连。
- 运行时：`src/adapters/runtime/accountRuntime.ts` 订阅账号状态；登录后 15s 轮询在线桌面，目标在线即建立 relay 观测接线；登出/离线即释放连接与本地缓存。
- UI：登录页（`src/presentation/account/accountLoginScreen.tsx`）、首页远程设备卡（`RemoteDeviceCard.tsx`）、设置页账号分组；局域网扫码/手动配对保留为独立兜底入口。

## 4. 安全模型

- 传输：仅 WSS / HTTPS；账号 token 只放 `Authorization: Bearer`，不进 URL、不进日志。
- 票据：HMAC-SHA256 自校验；60s 有效期；绑定 account / device / target / role；一次性 `jti` 防重放；CLI 之外无明文。
- 账号隔离：房间键含 `account_id`；`GET /v1/devices` 只返回调用者账号的在线 host；跨账号无法配对。
- 中继：无业务存储、无 payload 日志；每 IP 30r/m 票据限速 + 每 token 30r/m；单 IP 20 连接；全局连接上限 1024；单帧 1 MiB（与业务网关一致）。
- 内存保险丝：出站队列 **32 帧 + 全局 64 MiB 排队字节预算**；慢消费者/大帧攻击触发背压断链，不会把中继内存放大到 GB 级（`ByteBudget`，单测覆盖）。
- 桌面 loopback 网关：只绑定 `127.0.0.1`，64 字符随机桥密钥，常量时间比较；中继票据证明同账号，桥接不解析业务字段；不暴露到 LAN。
- 应用层：首版 TLS + 票据 + 桥授权；**E2EE 尚未实现**，不得对外宣称“零知识 / 端到端加密”。
- 移动端：refresh token 存 SecureStore，access token 仅内存；登出清理凭据并断开 relay。

## 5. 验收结果（2026-10-29 实测）

1. **账号登录**：`auth.flowbit.me` 密码登录返回 200（修复后）。
2. **在线发现**：真实桌面应用登录后，`GET /v1/devices` 返回
   `[{"id":"1ac961e8-…","name":"DESKTOP-J31MN6T","platform":"desktop","online":true}]`。
3. **中继鉴权**：无 token 的 `/v1/devices`、`/v1/ticket/host` 均 401；无票据 WS 无法升级。
4. **远程控制主链路**：以真实 token 申请 client 票据 → 连接 Oracle 中继 →
   `relay.peer online` → 发送 `remote.listSessions` / `remote.getStatus`，
   桌面经 loopback 网关返回 `result.listSessions`（真实会话列表）与
   `result.getStatus`（dbReady / diagnostics），帧完整往返。移动端侧使用与
   `RelaySocket` / `WsGateway` 完全一致的 JSON 帧协议在 Node 中复现（本机
   无 Android 模拟器，未做移动端 UI 实机点击验收）。
7. **重放拒绝**：同一票据二次升级返回 HTTP 409（`ticket.replayed`）。
8. **验证账号清理**：端到端验证使用的临时 QA 账号已从生产账号库删除
   （sessions / identities / audit_logs / accounts 四表精确清理，操作前备份
   `/root/authfix-20261029/zennav-before-qa-cleanup-20261029.sqlite`，root 600）；
   桌面端已登出，在线设备列表归零。
5. **断线恢复**：中继重启后，桌面 5s 内自动重新申请票据并恢复在线；移动端等待 `peer online` 后重放队列。
6. **移动端构建**：`tsc --noEmit` 通过；`expo export --platform android` 产出 5.3MB Hermes bundle；Jest 98/99 套件通过（唯一失败为并行 Agent 新增的 `useSafeBack.test.tsx` 使用 `render()` 返回值查询导致，与本链路无关；性能粗筛在并行负载下偶发，单独重跑通过）。

## 6. 已知边界与后续

- **E2EE 第二阶段**：当前中继可见转发内容（不落盘）。若要零知识，需要在设备注册/票据交换中引入 X25519 + AEAD；本轮不做。
- **多桌面**：协议按多 client / 多 host 设计，移动端已支持列表与切换；在线发现只显示在线设备。
- **设备管理语义**：账号中心没有设备注册表，桌面设置页的“在线设备”已改由中继房间状态提供（只显示当前在线设备），`auth_get_relay_ticket` / `auth_revoke_device` 等失效旧命令已物理删除；“解除设备”暂不提供（设备离线即自然消失，失窃设备应在手机端退出登录 / 服务端吊销会话）。
- **后台常驻**：移动端被系统挂起时无法保持实时连接；本轮定位“双方应用在线时远程控制”，推送/后台常驻另立任务。
- **证书与端口**：Nginx 证书续期、8443 端口策略变化需同步客户端 `RELAY_PUBLIC_URL`（移动端支持 `EXPO_PUBLIC_RELAY_BASE_URL` 覆盖）。
