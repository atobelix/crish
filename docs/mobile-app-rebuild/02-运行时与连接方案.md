# 移动端运行时与连接方案（crish-mobile）

> 隶属：`docs/mobile-app-rebuild/`
> 定位：运行时装配、订阅 / 回填 / 对账、桌面 WS 命令面补齐、TLS 可信路径。

---

## 1. 目标

移动端在任何页面都共享**一条连接、一套订阅、一个会话缓存**；打开 App 后无需停留在首页也能收到审批与运行事件；断线恢复后自动补齐；解绑 / 换机不会复用旧连接。

现状问题（证据见 `00-总方案.md` §2）：会话列表不拉、订阅不发、对账恒空、文件命令未实现、配对端口丢失、单例不销毁、TLS 无信任。

---

## 2. 移动端运行时（`src/adapters/runtime/`）

### 2.1 生命周期

```
RootLayout
  └─ Auth hydrate（SplashGate）
       ├─ 未配对 → /pair/welcome
       └─ 已配对 → appRuntime.start(session)
            ├─ resolve endpoint（host + persisted port + TLS 模式）
            ├─ ReconnectingWsClient.connect()
            ├─ onOpen:
            │    ├─ remote.listSessions → sessionStore.reconcile
            │    ├─ events.subscribe(top sessions, cursors)
            │    ├─ events.subscribeAll(critical types)
            │    └─ 对已打开窗口做 readSessionEvents 回填
            ├─ onClose: 相位投影（reconnecting/offline）
            └─ unpair / token revoked: appRuntime.stop() + 清空 stores
```

### 2.2 订阅策略

- **会话级订阅**：按会话活跃度（最近打开 / 最近更新）取前 32 个，`events.subscribe` 一次性发送；游标取 `eventStore.windows[id].lastSeq`。打开新会话时重发订阅并加入集合。
- **全局轻订阅**：`events.subscribeAll` 白名单：`approval-requested`、`approval-resolved`、`run-terminal`、`runtime-error`、`runtime-intervention-required`、`security-audit`、`task-*`、`timer-fired`、`cron-fired`。确保未打开会话的审批 / 终态也能到达。
- **会话索引刷新**：连接 open、App 回前台、用户下拉刷新、每 30s（仅前台）调用 `remote.listSessions`。
- **事件回填**：打开会话时 `readSessionEvents({ sessionId, afterSequence: window.lastSeq, maxEvents: 200 })` 循环到 `hasMore=false`；重连时对已打开窗口从 `lastSeq` 续传。

### 2.3 对账

`subscribe.ok` 返回逐会话 `nextSequence / stale`：

- `localCursor` 未定义 → 视为 fresh（建立窗口，等待回填）。
- `serverNext - localCursor > 5000` 或 `stale` → 清空窗口后全量回填。
- `serverNext > localCursor` → 增量回填。
- `serverNext < 0` → 会话已删除，清理窗口与本地索引。

将投影结果交给现有 `projectReconnect` 纯函数（当前恒空输入的缺陷修复），并执行 `FeedBridge` 的 resume / cleanup。

### 2.4 App 前后台

- `AppState` 进入 background：保留连接（系统可能挂起），停止轮询。
- 回到 active：若相位非 open → `client.connect()`；随后刷新会话索引并回填已打开窗口。
- 不再依赖 `ensureObservationWiring()` 在各页面懒启动。

### 2.5 解绑 / 换机

`appRuntime.stop()` 必须：

1. 退订 gateway 监听（feed / terminal / push / approval）；
2. 断开 socket 并清空重连计时器；
3. 重置单例与所有接线实例；
4. 清空 eventStore windows、sessionStore、approvalStore、terminalStore、devicePresenceStore；
5. 清理订阅游标与本地 outbox（保留通知历史？解绑后清空，避免跨设备串扰）。

## 3. 桌面 WS 命令面

### 3.1 通用分发

当前 `handle_remote_command_frame` 只硬编码 `runTask / runControl / cancelRun / approve / deny / listPendingApprovals`（`ws.rs:1155`）。改为：

```rust
let result = backend.dispatch_remote_command(cmd, params_val, msg_id).await;
```

`ApiBackend` 增加默认方法 `dispatch_remote_command`，按白名单（`remote_whitelist.rs`）match 到已实现方法的类型化调用；未实现命令返回 `cmd.unknown`，与现有注册表错误契约一致。

覆盖：

- F1：`getStatus`、`getRunSnapshot`、`readSessionEvents`、`readRunEvents`、`listSessions`、`listBackgroundTasks`、`getTaskOutput`、`getFlowSnapshot`、`listCommands`、`getSearchIndex`
- F2：`approve`、`deny`、`listPendingApprovals`、`approvalHistory`、`checkCommand`（未实现则 unknown）
- F4：`listDir`、`readFile`、`listWorkspaces`、`switchWorkspace`、`searchFiles`、`writeFile`（按需）、`fileStat`（unknown）
- F5：`runTask`、`runControl`、`cancelRun`（`searchSessions` 保持 unknown，移动端本地搜索）
- F6：`getSettings`、`setSettings`、`settingsConfirm`、`pauseAutomation`（`queryPresence` 由移动端移除，不再暴露）

**配对解除（WS 设备域）**：移动端 `unpair` 发 `device.unlink`，桌面按**当前连接令牌哈希**撤销并踢出（不接受 body 中的跨设备 deviceId）；本地清除仍是权威路径（桌面失败也清本地）。桌面重启后，只要存在未撤销令牌，装配面保持 Lan 监听，已配对手机可直接用既有令牌重连。

### 3.2 文件读命令实现

- `ApiBackend` 新增：
  - `list_dir(ListDirParams) -> ListDirResult`
  - `read_file(ReadFileParams) -> ReadFileResult`
  - `list_workspaces(ListWorkspacesParams) -> ListWorkspacesResult`
  - `switch_workspace(SwitchWorkspaceParams) -> SwitchWorkspaceResult`
- `CoreStateBackend` 注入 `WorkspaceOps`（main.rs 用 `AppHandle` 实现）：
  - active root、recent 授权根列表；
  - `guard_for(root)` 构造 `WorkspaceFsGuard`；
  - listing 复用 `fs_commands::directory::list_directory_with_guard`；
  - read 复用 `fs_commands::read::read_file_content_with_guard`；
  - `switch_workspace` 复用 `workspace::workbench_open_workspaces` / 注册表激活逻辑（只允许 recent 内路径）。
- 安全：所有路径先 canonicalize 并校验在授权根内；拒绝符号链接逃逸；大文件 / 二进制 / 编码错误映射为 `DeviceErrorCode`。
- 结果转换为 wire `ListDirResult / ReadFileResult / ...`；补 Rust 单测：正常、越界、不存在、二进制、超限、切换非法根。

### 3.3 事件订阅

- `events.subscribe` 已实现；移动端补发送。
- `events.subscribeAll` 已实现；移动端补发送关键类型。
- `subscribe.ok` 的 `nextSequence / stale` 已可用，移动端接入对账。

## 4. TLS 可信路径

### 4.1 事实

- 桌面 `restart_server` 强制 `tls_enabled=true`（`main.rs:1634`），证书是自签 CA + 叶子，CA 指纹经配对信道下发。
- Lan 绑定时装配面把本机可用局域网 IP + 主机名注入 `tls_extra_sans`，`ServerInstance::bind` 用默认 SAN + 这些条目重签叶子（CA 不变，配对指纹不变）；否则移动端按 IP 连接会因主机名校验失败而握手失败。
- RN 原生 WebSocket 无法注入信任锚 / 做 SPKI pinning；应用层 JSON 指纹比对无法阻止 TLS 劫持（`docs/multi-device/R2-16-acceptance-check.md:95`）。
- 在系统未信任该 CA 时，生产形态在普通手机上**必然握手失败**；按 §4.3 安装证书后可通过。

### 4.2 方案 A（首选）：原生 pinned WebSocket

新增 Expo 本地模块 `modules/crish-ws`：

- Android：OkHttp `WebSocket` + 自定义 `X509TrustManager`（只接受与配对下发 CA SPKI 指纹一致的链）。
- iOS：`URLSessionWebSocketTask` + `didReceive challenge` 中 `SecTrustEvaluate` + SPKI 比对。
- JS 暴露与标准 WebSocket 同形的接口（`send/close/onopen/onmessage/onclose/onerror`），字符串帧。
- `ReconnectingWsClient` 增加 `socketFactory`；配对完成后由 runtime 注入 `createPinnedSocket(caSpkiPin)`。
- 配对前如何拿到 pin？`pair.challenge` 已携带 `tlsFingerprint`（D3 §4.6）；但首次 TLS 握手发生在收到 challenge 之前 → 需要**首次配对使用普通 wss + 系统信任**，或改为在配对码 / 二维码中携带 pin。二维码载荷 `crish-pair://code@host:port` 可扩展 `?pin=<64hex>`，桌面生成时附带 CA 指纹；扫码即可 pin，手动输入则需在输入框提供指纹或先按系统信任连接。
- 若短期内不改二维码：方案 A 只解决「已配对重连」；首次配对仍需方案 B。

### 4.3 方案 B（过渡，已落地）：系统证书信任引导

- 桌面端「设置 → 多端互通 → 安全连接」提供「导出证书」（`multi_device_export_ca`，原生保存对话框，写出 PEM 内容的 `crish-ca.crt`）。
- Android：`plugins/withUserCaTrust.js` 在 prebuild 时写入 `network_security_config.xml`（system + user trust anchors）并在 Manifest 挂载；否则 Android 7+ 默认不信任用户 CA。用户在系统设置 → 安全 → 安装 CA 证书。
- iOS：安装描述文件 → 设置 → 通用 → VPN 与设备管理 → 安装 → 关于 → 证书信任设置 → 完全信任；`NSAllowsLocalNetworking` 已开启，ATS 不阻断局域网连接。
- 连接错误映射：wss 传输失败 → 文案直接提示「首次连接需先在手机信任桌面证书」，连接帮助 Sheet 给出桌面导出路径与两端安装步骤。
- 已知边界：这是**系统级 CA 信任**，不是传输层 SPKI pinning；系统信任范围内的其它证书同样会被接受。应用层仍做配对载荷/本地存储的指纹一致性校验（防轮换与本地篡改），但不阻止 TLS 劫持。方案 A 未实施。

### 4.4 诚实边界

- 当前信任模式 = **系统 CA 信任 + 应用层指纹一致性校验**，不是传输层 pinning；设置页「安全连接」如实展示该口径，不得宣称「指纹固定」。
- Android 的 user CA 信任依赖 prebuild 生成的 network security config；Expo Go 不包含该配置，必须使用 dev build / 正式构建验收。
- iOS 原生安装与信任流程无法在 Windows 实测；交付时明确标注，Android 需在模拟器或真机走通。

## 6. 运行时验收脚本（手工）

1. 桌面开启多端服务 + 配对模式，生成二维码。
2. 手机扫码 → 配对成功 → 首页出现桌面会话。
3. 桌面发起一个含工具调用的 run → 手机首页/会话详情实时出现消息与工具块。
4. 桌面触发审批 → 手机收到推送 / 列表出现 → 允许 → 桌面继续。
5. 断开 Wi-Fi 10s → 恢复 → 会话自动续传，无重复。
6. 手机发起任务 → 桌面执行 → 手机流式显示。
7. 解除配对 → 重新配对到另一台桌面 → 连接指向新主机。
8. 文件页浏览工作区、预览文本。
