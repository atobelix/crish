## 一、修复背景与根因回顾

根据专项审计报告 `docs/message-disappearance-audit/audits/04-虚拟滚动与列表渲染管线审计.md`，虚拟滚动与列表渲染管线存在 4 处导致历史消息被裁切、偏移越界、视口截断或吸底令牌失效的致命生命周期时序缺陷：

1. **VS-01（高危 / 时序冲突）**：`MessageVirtualizer.tsx:149-168` 被动 `useEffect` 晚于 DOM Commit、`useLayoutEffect` 与首帧 `ResizeObserver` 注册执行，且首次挂载时无条件执行。其调用的 `clearHeights()` 抹杀了首帧 `ResizeObserver` 实测高度（导致静态消息退回粗估高度，被 `.listInner` 的 `overflow: hidden` 裁切），并通过 `resetGestureState()` 提前销毁了 `useLayoutEffect` 刚签发的程序吸底豁免令牌（`programmaticScrollStateRef.current.active = true`），使吸底滚动被误判为用户手势并冻结几何更新。
2. **VS-02（中危 / 跨会话状态残留）**：`useVirtualScroll.ts:323-334` 的 `clearHeights()` 清空了高度管理器，但未重置 React `scrollTop` state、`latestScrollTopRef.current` 以及容器 DOM 的 `scrollTop`。从长会话切换到短会话时，旧会话的高偏移量残留导致 `computeVisibleRange` 定位到列表末尾之外，造成顶部历史消息被剔除或视口上半截空白。
3. **VS-04（中危 / 依赖遗漏与防线倒置）**：`useVirtualScroll.ts:257-261` 中 `totalHeight` 的 `useMemo` 依赖数组遗漏了 `ids`；当从条数相同的会话 A 切换到会话 B 时，`totalHeight` 不会立即重算；且 `MessageVirtualizer.tsx` 的 `vsManager.syncOrder(msgIds)` 防线位于 `useVirtualScroll` 求值之后，若当帧 `order` 长度为 0，`vs.visibleRange` 已产出空切片。
4. **VS-05（低危 / 多分屏容器隔离缺失）**：`ChatMessageList.tsx:126-141` 调用 `useScrollAnchor` 与 `scrollToMessage` 时未传入当前分屏容器的 DOM 引用，导致多分屏场景下回退到全局 `document.querySelector` 查找其他分屏的消息与滚动宿主。

## 二、核心修复方案与实现细节

### 1. 修复 VS-01：`MessageVirtualizer.tsx` 切会话布局期同步重置与挂载保护

- **重置时序前移**：将 `activeSessionId` 切换时的重置逻辑从滞后的被动 `useEffect` 移入同步 `useLayoutEffect`。
- **首次挂载保护**：引入 `prevSessionIdRef = useRef<string | null>(activeSessionId)`，在首次挂载时（`prevSessionIdRef.current === activeSessionId`）直接 return 跳过 `clearHeights()`。
- **吸底令牌与实测高度保全**：该 `useLayoutEffect` 严格置于 `messages` 的 `preloadEstimates` 与首帧吸底 `performProgrammaticScroll` 的 `useLayoutEffect` 之前：
  ```tsx
  const prevSessionIdRef = useRef<string | null>(activeSessionId);

  // VS-01：会话切换必须在同步 layout 阶段（且置于 preloadEstimates 与吸底滚动之前！）重置几何状态；
  // 使用 prevSessionIdRef 仅在 activeSessionId 真正发生切换时调用 clearHeights()，
  // 首次挂载时绝不清空首帧 DOM Ref 回调与 ResizeObserver 刚测得的真实高度，
  // 也绝不在 performProgrammaticScroll 之后销毁刚签发的 programmaticScrollStateRef.current.active = true 吸底豁免令牌！
  useLayoutEffect(() => {
    if (prevSessionIdRef.current === activeSessionId) {
      return;
    }
    prevSessionIdRef.current = activeSessionId;
    clearHeights();
    isAtBottomRef.current = true;
    setIsAtBottom(true);
    isAtTopRef.current = true;
    setIsAtTop(true);
    setShowFloorButton(false);
    if (containerRef.current) {
      containerRef.current.scrollTop = 0;
    }
    if (msgIds.length > 0) {
      manager.syncOrder(msgIds);
      manager.preloadEstimates(
        messages.map((m) => ({
          id: m.id,
          height: estimateTimelineMessageHeight(m),
        }))
      );
    }
  }, [activeSessionId, clearHeights, manager]);
  ```
- **生命周期彻底顺畅**：
  - 首次挂载时：DOM ref 挂载与 `ResizeObserver` 测高不被清空，`useLayoutEffect` 执行 `performProgrammaticScroll` 签发的豁免令牌完好无损，原生 `scroll` 事件到达时准确匹配，假阳性手势计数 `GFPC === 0`。
  - 切换会话时：在 Layout 阶段最先执行 `clearHeights()` 清空前序会话、同步重置容器 `scrollTop = 0` 并回灌新会话 order 与估高；紧随其后的 layout effect 灌入估高并执行平滑吸底，令牌签发后再无滞后 effect 将其撤销。

### 2. 修复 VS-02：`useVirtualScroll.ts` `clearHeights` 同步归零偏移量

- 在 `useVirtualScroll.ts` 的 `clearHeights()` 回调中，除清理 `pendingActualRef`、`pendingEstimatesRef`、`resetGestureState()` 与 `manager.clear()` 外，同步执行：
  ```ts
  if (containerRef.current) {
    containerRef.current.scrollTop = 0;
  }
  latestScrollTopRef.current = 0;
  setScrollTop(0);
  setActualTick((t) => t + 1);
  ```
- 杜绝长会话（大 `scrollTop`）切到短会话时 React state 或 ref 残留旧偏移，确保新会话首帧 `computeVisibleRange(0, ...)` 从 `startIndex = 0` 稳定切片。

### 3. 修复 VS-04：`totalHeight` 补齐 `ids` 依赖与 `MessageVirtualizer` 切片非空保底

- **补齐依赖**：在 `useVirtualScroll.ts` 中，将 `totalHeight` 的 `useMemo` 依赖补齐为 `[manager, ids, itemCount, actualTick]`，使同条数不同会话切换时 `totalHeight` 立即触发重算。
- **切片防御**：在 `MessageVirtualizer.tsx` 中，对 `vs.visibleRange` 与 `contentHeight` 增加对齐保底检查：
  ```tsx
  // VS-04：order 与 ids 不一致时同步 order，并确保在计算可见区间前已完成同步，防止空切片
  if (msgIds.length > 0 && vsManager.getOrderCount() !== msgIds.length) {
    vsManager.syncOrder(msgIds);
  }

  const visibleRange =
    msgIds.length > 0 &&
    vs.visibleRange.endIndex === 0 &&
    vsManager.getOrderCount() > 0
      ? vsManager.computeVisibleRange(
          vs.scrollTop,
          vs.viewportHeight,
          messages.length,
          8
        )
      : vs.visibleRange;

  const { startIndex, endIndex, startOffset } = visibleRange;
  const contentHeight =
    msgIds.length > 0 && vs.totalHeight === 0 && vsManager.getOrderCount() > 0
      ? vsManager.getTotalHeight(messages.length)
      : vs.totalHeight;
  ```
- 彻底杜绝在任何边界时序下出现 `messages.length > 0` 但 `visibleRange` 切片为空或 `contentHeight === 0` 的异常。

### 4. 修复 VS-05：`ChatMessageList.tsx` 接入 `useLeafScope` 闭合分屏滚动隔离

- 引入 `useLeafScope()` 获取当前分屏的根容器引用 `leafRootRef`。
- 将 `leafRootRef` 传入 `useScrollAnchor` 的 `scrollContainerRef` 选项，并在搜索高亮跳转时调用 `scopedScrollToMessage(id, leafRootRef?.current)`：
  ```tsx
  const { leafRootRef } = useLeafScope();

  const { jumpToPinned, scrollToMessage: scopedScrollToMessage } =
    useScrollAnchor({
      messages,
      sessionAllMessages: pinSourceMessages,
      showAllMessages,
      scrollContainerRef: leafRootRef,
    });

  useEffect(() => {
    if (!searchHighlightQuery) return;
    const idx = messages.findIndex((m) =>
      messageMatchesSearch(m, searchHighlightQuery)
    );
    if (idx < 0) return;
    const id = messages[idx]?.id;
    if (!id) return;
    scopedScrollToMessage(id, leafRootRef?.current);
  }, [
    searchHighlightQuery,
    activeSessionId,
    messages,
    scopedScrollToMessage,
    leafRootRef,
  ]);
  ```
- 确保多分屏并存时，固定消息跳转（`jumpToPinned`）与搜索高亮定位（`scopedScrollToMessage`）严格锁定在当前分屏的滚动容器内，杜绝跨分屏命中或滚动串门。
