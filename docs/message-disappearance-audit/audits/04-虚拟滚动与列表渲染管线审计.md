## 一、核心审计结论（Executive Summary）

针对本次专项审计的三大核心排查问题，逐行核查与 `git diff` 比对后的结论如下：

1. **当 `messages.length > 0` 时，`useVirtualScroll` 与 `VirtualScrollManager` 的纯数学计算是否会产出空的 `visibleRange`（`startIndex === endIndex`）或 `totalHeight === 0`？**
   - **常规单会话首帧数学计算不会产出 0**：
     - `useVirtualScroll.ts:122-125` 在 Render 阶段同步执行 `manager.syncOrder(ids)`；
     - `VirtualScrollManager.ts:92-99` 对每条消息保底赋予 `fallbackHeight = 120`（`> 0`）写入 `currentHeights` 与 `bitTree`；
     - `VirtualScrollManager.ts:374-406` (`computeVisibleRange`) 对 `viewportHeight` 有双重 `600px` 兜底（`useVirtualScroll.ts:96-98, 105, 110` 的 `DEFAULT_VIEWPORT_HEIGHT_PX = 600` 以及 `VirtualScrollManager.ts:390` 的 `normalizePositiveFloat(viewportHeight, 600)`），在 `count > 0 && this.order.length > 0` 时恒满足 `0 <= startIndex < endIndex <= count`、`startOffset >= 0`（有限浮点数，绝无 `NaN` 或 `-Infinity`）、`totalHeight = 48 + contentHeight + 16 >= 88px > 0`。
   - **但管线中存在 4 处状态流转与生命周期时序缺陷（VS-01 ~ VS-04）**：在**挂载/切会话时序、长会话切短会话、同长度列表切换、以及历史助手消息异步 Markdown 渲染**场景下，会导致**首帧实测高度被抹杀、程序吸底豁免令牌被提前销毁、跨会话残留 `scrollTop` 导致切片偏移失步、或异步 Markdown 渲染失败时正文永久空白**。

2. **近期未提交的虚拟滚动改造（「单轨测高收敛与私有 RO 清退」、「吸底令牌与即时测高」）是否移除了关键容器 `ResizeObserver` 导致 `viewportHeight === 0`？**
   - **容器级 `ResizeObserver` 未被移除，且 `viewportHeight` 不可能为 0**：
     - `useVirtualScroll.ts:101-115` 完整保留了对 `containerRef.current` 的 `ResizeObserverManager` 监听，且初始值与 `0` 高度回退值均为 `DEFAULT_VIEWPORT_HEIGHT_PX` (`600`)。
     - `MessageToolCallsSection.tsx:95-131` 清退内部私有 `ResizeObserver` 后，外层消息行宿主 `<div data-vindex={msg.id} ref={rowMeasureRef(msg.id)}>`（`MessageVirtualizer.tsx:417, 448` → `messageVirtualizerMeasure.ts:8-33`）仍通过 `ResizeObserverManager` 监听整行尺寸。
   - **但新引入的「程序滚动豁免令牌 (`useVirtualScrollGesture`)」与既有 `MessageVirtualizer` 的 `useEffect(clearHeights)` 存在严重生命周期时序冲突（见缺陷 VS-01）**：`useLayoutEffect` 刚签发的吸底令牌在紧随其后的 `useEffect` 中被 `clearHeights() -> resetGestureState()` 无条件销毁，且首帧 `ResizeObserver` 测得的真实高度被 `clearHeights()` 清空。

3. **CSS 样式或 DOM 协调层是否会导致历史消息在视觉上不可见？**
   - Flex 容器链（`.leaf` → `.leafBody` → `.leafChatColumn` → `AppErrorBoundary(display:contents)` → `SlotOutlet(display:contents)` → `.chatBody` → `.chatDocFlow` → `.streamHost` → `.list`）均具备 `flex: 1` 与 `min-height: 0`，无高度坍塌或 `opacity: 0` / `visibility: hidden` 遮蔽。
   - **存在两处视觉不可见/截断风险**：
     1. **历史助手消息首帧空 HTML 与失败无回退（见缺陷 VS-03）**：历史消息（`isSealed = true, isStreaming = false`）走 `useAsyncMarkdownHtml`（异步 Rust IPC `core_md_render` / Worker），缓存未命中时首帧 `renderedHtml === ""`，DOM 渲染为空 `<div></div>`；且 `MarkdownBlockItem.tsx:147` 丢弃了 `useAsyncMarkdownHtml` 返回的 `failed` 标志，一旦异步渲染失败或返回空串，历史助手消息正文将**永久为空白 DOM**。
     2. **`.listInner` 强制 `overflow: hidden` 裁切（见缺陷 VS-01 / VS-04）**：`MessageVirtualizer.tsx:383-389` 在 `.listInner` 上设置了 `height: ${totalHeight}px` 与 `overflow: 'hidden'`；当 `clearHeights()` 抹掉 `ResizeObserver` 实测高度使 `totalHeight` 退回偏小的启发式估高时，超出 `totalHeight` 的底部历史消息会被 `overflow: hidden` 物理截断。

  3. **阶段 2（`useLayoutEffect` 执行）**：
     - `MessageVirtualizer.tsx:204` 将启发式估高灌入 `manager` 并触发 `setActualTick`；

### 【缺陷 VS-02】（中危 / 跨会话状态残留）`clearHeights()` 未重置 `scrollTop` 与 `latestScrollTopRef`，且切会话时 `isAtBottomRef` 在 `useEffect` 中滞后重置，导致长会话切短会话时窗口切片偏移失步

- **涉及文件与精确行号**：
  - `apps/crish-desktop/src/hooks/useVirtualScroll.ts:95, 134, 323-334`
  - `apps/crish-desktop/src/components/chat-message-list/MessageVirtualizer.tsx:149-155, 343-352`
  - `apps/crish-desktop/src/components/chat-message-list/ChatMessageList.tsx:273-284`

- **代码证据**：
  - `ChatMessageList.tsx:273-284` 渲染 `<MessageVirtualizer>` 时未设置 `key={activeSessionId}`，因此从有消息的会话 A 切换到有消息的会话 B 时，`MessageVirtualizer` 与 `useVirtualScroll` 实例保持复用。
  - `useVirtualScroll.ts:323-334` 的 `clearHeights()` 清空了 `manager` 和 `pendingActualRef`，但**没有重置 `scrollTop` state（仍保持旧会话的滚动偏移）和 `latestScrollTopRef.current`**：

- **状态流转缺陷完整链路**：
  1. 用户在长会话 A（例如 100 条消息，`scrollHeight = 15000px`）中向上滚动到 `scrollTop = 6000px` 处浏览历史，此时 `isAtBottomRef.current === false`，`useVirtualScroll` 内部的 `scrollTop === 6000`。
  2. 用户点击切换到会话 B（例如 20 条消息，`totalHeight = 2400px`，或 2 条消息 `totalHeight = 240px < clientHeight = 800px`）：
     - 在会话 B 的首帧 Render 与 `useLayoutEffect`（`MessageVirtualizer.tsx:343`）执行时，由于 `isAtBottomRef.current = true` 写在滞后的 `useEffect`（151 行）中，此时 `isAtBottomRef.current` 仍为 `false`！因此 343 行的 `useLayoutEffect` 直接 `if (!isAtBottomRef.current) return;`，不会将容器滚到底部。
     - 若会话 B 仅有少量消息使 `totalHeight < clientHeight`（`maxScroll === 0`），浏览器在布局期将 `container.scrollTop` 钳制为 `0`；随后 `useEffect` 将 `isAtBottomRef.current` 置为 `true` 并触发重渲染，在下一轮 `useLayoutEffect`（348 行）中：
       `Math.abs(container.scrollTop - maxScroll)` 为 `Math.abs(0 - 0) === 0 <= BOTTOM_STICK_EPSILON_PX (2)`，因此**不会调用 `performProgrammaticScroll`**。
     - 若浏览器对 `scrollHeight` 坍塌引起的 `scrollTop` 钳制未派发 `scroll` 事件（或在测试/特定 WebView2 帧序下未触发 `onScroll`），`useVirtualScroll` 的 React state `scrollTop` 将一直停留在会话 A 的 `6000`！
     - 当 `scrollTop = 6000` 时，`manager.computeVisibleRange(6000, 800, itemCount, 8)` 会定位到列表末尾 `findIndexAtOffset(6000) = itemCount - 1`，计算出 `startIndex = Math.max(0, itemCount - 1 - 8)`、`startOffset = getOffset(startIndex)`。若 `itemCount > 9`（例如 15 条短消息），顶部第 `0 .. startIndex-1` 条消息将被切除在渲染窗口之外，而 `translateY(startOffset)` 又将剩余消息推到视口下方，造成视口上半部分空白！
