# 本轮议题与效果锁：Markdown 引擎架构路径

> **Campaign 目录**：`docs/markdown-engine-architecture/`（正式命名；非临时 compare 目录）
> **议题**：在 Conex/Crish 产品中，Markdown 编辑/流式/大文档引擎的**架构路径与改进方案**（选型 + 融合 + 宿主接线 + 与后续富文本协作边界）。
> **遵守**：`00-多Agent协同修复总纲与复用模板.md`、`.agents/LOGIC_PLAN_NO_RETREAT.md`、`Agents.md`。

---

## 1. 效果锁（不得缩水）

下列为目标效果；Agent **不得**自行改为「先用现成库凑合」或「只做渲染不做编辑」：

1. **Agent 流式一等公民**：高 token/s 追加稳定、未闭合 fence/公式不闪、可与用户编辑共存策略清晰。
2. **大文档可用**：十万行级视口编辑/滚动主路径跟手；热路径禁止全文无界重解析/无界 join。
3. **可编辑所见即所得**：源码映射可逆、IME/选区/事务可测；融合手感（禁止块岛换壳当终局）。
4. **性能与体验双目标**：不因生态流行牺牲效果锁；不因「难」降级。
5. **产品形态**：Tauri + React 壳；设计纪律可对齐 composer brand（零蓝、禁激活行脏 chrome 等已有 BAN）。
6. **扩展**：双链等为扩展而非默认知识库 OS；Markdown 为序列化主格式（本阶段）。
7. **后续边界**：复杂排版多人协作可另核；本阶段不强制在行 MD 核上堆 CRDT。
8. **正式文档内化**：敲定文与实现说明写「本产品机制」；定案前可引用参考实现作论据。

## 2. 复杂度闸（选型）

- 相对「正常可达效果锁的选型」，实现/概念复杂度 **≥ 约 3×** 且无明显效果增益 → **放弃该候选**。
- **1～2×** → 可保留，必须写清多付出的结构换来的效果。
- **调试时间、金钱成本** → 默认忽略。
- **最终效果** → 主裁判。
