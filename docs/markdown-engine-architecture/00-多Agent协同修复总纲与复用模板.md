# 多 Agent 协同修复总纲与复用模板

> **文档性质**：可复用的**逻辑执行顺序**模板（非本轮专用细节）。
> **硬性约定**：
>
> 1. 只规定逻辑顺序、依赖关系、产出契约、验证闭环；**不涉及**时间安排、人员分配、业务优先级排序。
> 2. 清单内问题 **同权**；排序仅允许按 **数据依赖 / 类型依赖 / 文件域互斥**。
> 3. 每轮最多 **12** 个 Agent；按需取用，**不必占满**。
> 4. 遵守 `.agents/LOGIC_PLAN_NO_RETREAT.md` 与根目录 `Agents.md`（反退避、效果锁、测试资产、门禁）。
> 5. 子 Agent 默认类型：**general-purpose**（除非任务书另指只读 explore）。
> 6. **提示词不瘦身**：任务书写全效果锁、动态决策权、防回归、文件域；主控可在派单时**实时补充**文档未写清的现场约束。

---

## 1. 闭环总览（可多轮迭代）

```
[轮次 N 输入] 问题集 / 上轮报告 / 效果锁 / 已锁定契约
       │
       ▼
  ┌─ Phase Σ 调研 ─────────────────────────────────────┐
  │  多 Agent 并行：代码实读 +（允许）开源/本地 reference 对比 │
  │  产出：独立调研文档（可引用外部，标注证据）              │
  └──────────────────────┬──────────────────────────────┘
                         ▼
  ┌─ Phase Δ 项目内分析 ────────────────────────────────┐
  │  多 Agent：仅针对本仓库路径/约束/已有投资               │
  │  产出：项目贴合分析（仍可引用对比结论，但结论必须落到本仓） │
  └──────────────────────┬──────────────────────────────┘
                         ▼
  ┌─ Phase Ω 独立总案/选型（多模型各自成文）──────────────┐
  │  每 Agent 独立输出「完整改进/选型方案」（禁止抄袭同伴）   │
  │  复杂度闸：相对「正常选型」≥3× 复杂度且无效果增益 → 放弃；│
  │           1～2× 可保留并写清换来的效果                   │
  │  成本/工期/调试时间：默认忽略；效果最优为裁判             │
  └──────────────────────┬──────────────────────────────┘
                         ▼
  ┌─ Phase Ρ 选型评审（2～3 Agent）─────────────────────┐
  │  通读全部独立方案 → 各自给出「我认为的最佳方案」         │
  │  必须写清：取舍理由（效果/正确性/可验证/与已锁契约）     │
  └──────────────────────┬──────────────────────────────┘
                         ▼
  ┌─ Phase Μ 主控定案 ──────────────────────────────────┐
  │  主 Agent 综合 → 《总文档》（维度设计）+《方案敲定》     │
  │  正式敲定文：内化实现细节，禁止「照抄某软件」口吻        │
  │  （定案前文档可引用；敲定后只写「本产品要做什么」）       │
  └──────────────────────┬──────────────────────────────┘
                         ▼
  ┌─ Phase Θ 分维度详案 ────────────────────────────────┐
  │  维度数 = Agent 数（≤12）；每 Agent 一维详案            │
  │  输入：敲定文 + 总文档 + 调研/独立案 + 本地 reference   │
  └──────────────────────┬──────────────────────────────┘
                         ▼
  ┌─ Phase Α 维度评审（3 Agent）────────────────────────┐
  │  审：维度划分、任务分配、跨维逻辑、遗漏、缩水、冲突     │
  │  产出：问题清单 + 修订建议（不直接改代码除非进入实现轮） │
  └──────────────────────┬──────────────────────────────┘
                         ▼
  ┌─ Phase Κ 主控修订裁决 ──────────────────────────────┐
  │  吸收评审 → 修订总文档/敲定/维度文 → 冻结本轮契约       │
  └──────────────────────┬──────────────────────────────┘
                         ▼
  ┌─ Phase Ι 实现轮（可选，多轮）────────────────────────┐
  │  按文件域互斥并行实现 + 门禁/视觉/魔鬼测试验证           │
  │  实现叙述：内化方案，禁止对外说「参考了某某软件」         │
  └──────────────────────┬──────────────────────────────┘
                         ▼
  ┌─ Phase V 轮次报告 ──────────────────────────────────┐
  │  完成项 / 契约变更 / 残留问题集 / 下轮输入包              │
  └──────────────────────┬──────────────────────────────┘
                         ▼
              [轮次 N+1 输入] ── 闭环
```

**每一 Phase 的输出必须能成为下一 Phase 的输入**（路径、摘要、未决问题表）。

## 2. 角色与数量（逻辑，非排班）

| 角色                | 典型数量     | 职责                                           |
| ------------------- | ------------ | ---------------------------------------------- |
| 调研 Agent          | 2～6         | 代码/对比/专项勘察；可写 1 份分配文档          |
| 项目内分析 Agent    | 1～4         | 仅本仓约束与贴合                               |
| 独立总案/选型 Agent | 3～6         | 各自完整方案，互不可见定论（主控保证输入对称） |
| 选型评审 Agent      | 2～3         | 读全量独立案 → 最佳案                          |
| 主控                | 1            | 定案、派单、闭环、动态补约束                   |
| 维度详案 Agent      | = 维度数 ≤12 | 单维深写                                       |
| 维度评审 Agent      | 3            | 跨维审计                                       |
| 实现 Agent          | 按文件域     | 代码+测试                                      |
| 验证 Agent          | 1～2         | 门禁/视觉/魔鬼；可与实现分轮                   |

同轮 **合计 ≤12**；若逻辑上需要更多角色，**拆成下一轮**，不在一轮硬塞。

## 3. 主控动态决策权（文档未写死时）

主控在派单瞬间可决定（须写入该子 Agent 任务书，避免口头漂移）：

1. **本轮激活哪些 Phase**（可跳过已满足输入的 Phase，不可跳过效果锁确认）。
2. **输入包裁剪**：给哪些路径、禁止改哪些路径。
3. **对称性**：独立选型 Agent 是否使用完全相同输入（默认相同）。
4. **复杂度闸应用**：对某候选是否已超 3× 正常选型复杂度。
5. **引用策略**：本 Phase 是否允许开源引用；进入「正式敲定/实现」后是否禁止对外引用口吻。
6. **冲突升级**：子 Agent 发现任务书未覆盖的逻辑冲突 → 上报主控，禁止擅自缩目标。
7. **实时补充**：仓库突发状态（门禁红、未跟踪测试、文件锁）写入任务书「现场补充」节。

## 4. 子 Agent 任务书强制结构（提示词不瘦身）

每个子 Agent prompt **必须**含下列节（可增不可删）：

```markdown
## 角色与 Phase

## 效果锁（用户目标原文或主控转述，禁止改写缩水）

## 反退避（粘贴 LOGIC_PLAN 短块或声明必读路径）

## 输入文档与代码路径（精确到目录/文件）

## 禁止触碰路径

## 产出路径与文件名（唯一，如 03-xxx.md）

## 产出格式（标题/表格/证据：路径:行号）

## 动态决策边界（你可自行决定什么；必须上报什么）

## 验证期望（本单若含实现：门禁命令；若纯文档：自检清单）

## 现场补充（主控实时填写，可空）

## 完成定义 DoD
```

### 4.1 子 Agent 必须注意（派单时强调）

- **只做本任务书范围**；发现范围外关键问题 → 写入「上报主控」节，不扩写第二份文档（探索配额）。
- **中文 UTF-8 无 BOM**；证据用 `路径:行号`。
- **独立总案 Agent**：禁止读取其他独立总案产出目录（主控分目录或分波）。
- **正式实现 / 敲定文**：描述为本产品机制，**禁止**「我们采用了和 Typora 一样的…」作为规范语句；内化后的术语用本产品名。
- **选型对比阶段**：必须写清候选差异表（能力/风险/与效果锁贴合），禁止一句「建议用 X」。
- **不得**用工期、人员、生态流行度作为否决主因。

---

## 5. 文件域与并行

- 同文件串行；不同文件可并行。
- 调研/方案默认写 `docs/...` 分配文件；实现轮写 `src`/`crates` 按任务书。
- 产出根建议：`docs/<campaign>/` + `round-*/`；`.agent-outputs/` 仅运行期临时可用，**正式方案以 docs 入库为准**（用户重视方案）。

---

## 6. 验证与轮次报告（模板）

每轮结束主控写 `round-*-report.md`：

| 字段           | 内容                   |
| -------------- | ---------------------- |
| 输入包         | 上轮报告路径           |
| 激活 Phase     | 列表                   |
| Agent 数与角色 | 表                     |
| 产出清单       | 路径                   |
| 契约变更       | 锁定/废止的决策        |
| 残留问题集     | 同权列表（下轮输入）   |
| 门禁/验证      | 命令与结果（若有实现） |

---

## 7. 复用方式

新主题只需：

1. 复制本总纲逻辑（可引用本文，勿改硬性约定）。
2. 新建 `docs/<新主题英文短名>/`。
3. 写 `01-本轮议题与效果锁.md`。
4. 从 Phase Σ 起跑；已有调研可从中间 Phase 进入，但须在报告声明跳过原因（逻辑：输入已满足）。

## 8. 与「用户常用长流程」的映射

| 用户习惯步骤           | 本模板 Phase          |
| ---------------------- | --------------------- |
| 调研                   | Σ                     |

| 多 Agent 独立总案/选型 | Ω                     |
| 评审出最佳             | Ρ（2～3）             |
| 主控总文档+敲定        | Μ                     |
| 分维度详案             | Θ                     |
| 多 Agent 评审维度      | Α（3）                |
| 主控定夺修订           | Κ                     |
| 实现                   | Ι                     |
| 闭环                   | V → 下轮              |
