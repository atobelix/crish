## 1. 基础设施单真源（SSOT）架构

桌面端由于高频的窗口缩放、分屏折叠与流式 Token 渲染，必须严防微观重排风暴（Layout Thrashing）与内存泄漏。全仓已建立两大坚实的运行时基础设施：

### 1.1 `ResizeObserverManager`（单例批处理引擎）
- **实现位置**：`apps/crish-desktop/src/services/ResizeObserverManager.ts`
- **核心机制**：
  - **全局单例**：全生命周期仅实例化**一个**原生的 `ResizeObserver` 对象；
  - **引用计数与多播**：内部维护 `callbacks: Map<Element, Set<ResizeCallback>>`，支持多个业务对同一 DOM 节点进行无干扰监听；
  - **rAF 帧削峰**：采用 `FLUSH_BATCH_SIZE = 5` 的批处理队列，在 requestAnimationFrame 中分帧派发尺寸变更；
  - **动画与拖拽冻结**：支持 `setSuspended(true)`，在多窗格拖拽与折叠动画期间暂停测高回调，避免 60fps 掉帧；
  - **异常沙箱**：回调执行全程受 `try...catch` 保护，单个业务组件异常绝不击穿全局流。

### 1.2 `WindowResizeBridge`（窗口缩放防抖桥）
- **实现位置**：`apps/crish-desktop/src/services/WindowResizeBridge.ts`
- **核心机制**：
  - 在 Tauri 桌面环境下绑定原生 `onResized` API（Web 环境优雅降级为 passive 监听）；
  - 150ms 黄金静默尾随防抖（Trailing Debounce），彻底屏蔽用户拖拽窗口边缘过程中的数百次无意义中间态；
  - 稳定后在 `window` 上统一广播 `'app:window-resize-settled'` 事件。

## 3. G-02（Menu 浮层 2 处违规）深度架构重构

### 3.1 消除 `cloneElement`（`Menu.tsx:241`）
- **原因分析**：历史代码为了隐式为触发器注入 `ref`（供定位锚点）和 `onClick`（注入防重入校验），使用了 `React.cloneElement(trigger, ...)`。这种做法违背 React 19 单向流，存在类型丢失风险。
- **重构解法：Trigger Slot 容器包裹模式**
  重构 `Menu` 组件的 Trigger 渲染逻辑：
  ```tsx
  // 重构前：强制劫持子元素
  const clonedTrigger = React.cloneElement(trigger, {
    ref: anchorRef,
    onClick: handleTriggerClick,
  });

  // 重构后：标准 Slot 宿主容器模式
  <span
    ref={anchorRef}
    className={styles.menuTriggerHost}
    onClickCapture={handleTriggerClickCapture}
  >
    {trigger}
  </span>
  ```
  同时保留已存在的 `anchorElement` 显式传参通道，彻底移除 `cloneElement`。

### 3.2 消除 `stopPropagation`（`Menu.tsx:323`）
- **原因分析**：菜单列表在滚动时，原作者在 `onWheel` 中调用了 `e.stopPropagation()`，试图阻止滚轮事件穿透到下层页面。这腰斩了 React 全局事件冒泡，阻断了手势追踪与外层审计。
- **重构解法：标准 CSS 原生滚动隔离**
  在 `Menu.module.css` 中为菜单滚动容器增加标准声明：
  ```css
  .menuList {
    overscroll-behavior: contain; /* 由浏览器合成层原生隔离滚轮链，零 JS 拦截 */
  }
  ```
  在 `Menu.tsx` 中直接删除 `onWheel={(e) => e.stopPropagation()}` 监听器。
