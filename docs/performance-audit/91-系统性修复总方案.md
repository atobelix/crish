## 0. 强制原则（零容忍红线）

### 0.1 架构原则

1. **SSOT**：每个概念只有一个权威源。数据、配置、事件、样式 token、命令注册表均如此。
2. **物理切除**：废弃轨必须删除代码与样式；禁止注释隐藏、禁止「兼容 Shim」、禁止双写回旧岛。
3. **无幽灵契约**：IPC/API 与主注册表 1:1；禁止调用未注册命令；禁止丢关键字段的破坏性容错回退；禁止 catch 吞核心异常。
4. **无伪连通**：禁止只写纯函数/空转组件而不接入真实调用链；禁止真实调用处传 `Default`/`None`/空配置；禁止 `#[allow(dead_code)]` 死快照充当完成。
5. **无硬编码 / 无魔术数字**：阈值、预算、窗口、限额全部进**单一常量源**（Rust `perf_budget` 模块或前端 `perfBudgets.ts`），由防御脚本断言「值只允许出现在该源」。
6. **无 token 样式欺骗**：UI 100% Design Tokens；禁止裸 Hex / 伪变量；涉及滚动/sticky/层叠时穿透祖先盒模型与 Stacking Context。

### 0.2 交付与验收准则（五端物证）

| 端 | 物证 |
| -- | ---- |
| 触发端 | 真实 UI 交互能发起请求（非仅单测 mock） |
| 传输端 | 契约在主注册表存在且有效收发（registry / manifest / parser 三方一致） |
| 介质端 | 数据完整落**法定存储**；**旧孤岛零写入**且旧键/旧字段被物理删除 |
| 消费端 | 内核真实调用点读取并应用新配置；出站数据/渲染树携带新配置 |
| 负向断言 | 自动化测试断言旧字段/旧方法/旧类名/旧 CSS **已根除**（grep 级 + 行为级） |

模块内自测绿灯、`tsc` 通过、文档声明完成——**均不得单独作为交付依据**。

### 0.3 断言强化原则

每修一类问题，**同步加强对应防御脚本 / 守护单测**，使后续 Agent 改动代码时被门禁引导正确配置。防御面覆盖（但不限于）：

- 事件粒度与 emit 频率（禁止无批注释的逐 delta 全链 emit）
- spawn_blocking 覆盖（async fn 内禁止裸 `std::fs` / 同步 DNS / 同步 UIA）
- 持久化 SSOT（禁止对已废弃 LocalStorage 岛的写路径）
- Design Token 合法性（禁止裸色值）
- 启动静态图与体积预算
- 输出/内存统一预算常量
- memo 边界与内联对象 props（前端热点组件清单）
- 契约三方一致（registry drift）

## 1. 目标态：端到端数据流（SSOT 架构）

```text
【产生】provider SSE
  → session-loop：按 block 边界聚合（禁止无界逐 token 全链放大）
  → 单一 AgentEvent 模型（Arc 共享 payload；统一字节预算）
  → EventBridge：
       ├─ 实时轨：时间窗合并（契约允许后）/ 伪缓冲改真缓冲
       ├─ 收口轨：DB 批量/组提交写入；sequence 单语句
       └─ 旁路（fanout/push）：只读 meta 或 Arc，禁止全量 from_value 二次 parse
  → 前端 transport：每事件 parse 恰 1 次；数据面单路由
  → 热缓冲 streamingStore（无 immer）→ 真增量化切分 → 封口块一次编译
  → 持久域 sessionStore：仅元数据 + 活跃会话 body；输出 hardCap；非活跃 messages 可驱逐
  → 展示层：memo 边界完整；流式不注入非活跃卡
【存储】SQLite：法定唯一会话/事件存储
  - 组提交/ReaderPool 真接线
  - save_session_body 增量 dirty
  - 索引与 GC 出锁
【工具】async 执行 + spawn_blocking 阻塞面 + 统一 output_budget + Arc
【启动】entry 静态图预算门禁（fail 化并接 CI）；catalog 物质重组
【门禁】防御脚本与 90/91 断言同源演进
```

**目标不变量（修复后必须成立）：**

| ID | 不变量 |
| -- | ------ |
| INV-1 | 普通 run：非增量事件跨 IPC **恰 1 遍**（双发消除前为 2 遍的现状不得被「兼容回退」保留） |
| INV-2 | NoPersist 事件：**0 次** sequence 取号 SQL |
| INV-3 | async 工具/命令路径：**0 次** 裸阻塞 syscall 在 worker 线程 |
| INV-4 | 前端 store：对废弃 persist 岛 **0 写** |
| INV-5 | 工具输出：全链同预算常量；超限截断且标记 `truncated` 透传 UI |
| INV-6 | 流式正文：每帧派生计算 **O(delta)**，非 O(全文) |
| INV-7 | 首屏：静态 import 图 ≤ 预算常量；门禁 fail 而非 warn |
| INV-8 | 全部预算/窗口/限额数字只出现在单一 budget 源文件 |

## 2. 依赖拓扑（为何是这个顺序）

```text
Layer 0  契约与预算 SSOT
    │    （无 SSOT 则后续接线会再次分叉）
    ▼
Layer 1  阻塞面治理（spawn_blocking / DNS / UIA）
    │    （阻塞不清则 DB/引擎接线收益被 worker 饿死淹没）
    ▼
Layer 2  引擎事件模型与内存有界（Arc / 收口 / 有界通道 / moka）
    │    （事件模型不定，则 IPC/DB/前端只能打补丁）
    ▼
Layer 3  持久化单轨（SQLite 组提交、save 增量、前端 persist 收窄、驱逐）
    │    （双写不除，内存与磁盘尖峰无法验收）
    ▼
Layer 4  传输收敛（单 parse、轮询单源、旁路 meta）
    │    （前端热路径依赖干净的事件面）
    ▼
Layer 5  前端热路径与装配（切分增量化、卡片 memo、虚拟化 Hooks）
    │
    ▼
Layer 6  重型组件与 Webview（终端存活、Diff worker、合成层）
    │
    ▼
Layer 7  资产与启动（断 catalog 静态边、setup 分级、门禁 CI）
    │
    ▼
Layer 8  强契约事件语义（双发消除、message-start 瘦身、PE-02、Progress）
    │    （必须 schema 升级 + 双端联审，故置后；非「不重要」）
    ▼
Layer 9  观测与防御脚本终态（压测进 CI、V 项回填、负向断言全绿）
```

**并行规则**：同一 Layer 内、**文件域不相交**的工作单元可并行；跨 Layer 禁止「先改消费端再改生产端」的伪连通。

**禁止顺序反例**（本方案明确禁止）：

- 未删 zustand persist 全量 sessions 前，不得声称「持久化已优化」  
- 未接组提交前，不得只改前端 debounce 掩盖 DB 尖峰  
- 未改 parser 单次解析前，不得只加前端 `requestIdleCallback` 延迟 parse  
- 未动契约前，不得静默合并 delta（违反 PE-02）或静默砍 Progress

## 7. Layer 4 · 前端传输收敛

| 项 | 内容 |
