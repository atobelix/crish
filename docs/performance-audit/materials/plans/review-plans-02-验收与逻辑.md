## 0. 审查方法与总判

| 方法 | 说明 |
| ---- | ---- |
| 逐案读结构 | 每案：效果锁、依赖序、删除面、任务四件套、验收（功能/负出/五端）、契约处理、与 91 分歧 |
| 跨案冲突矩阵 | 同一概念被多案认领、同一文件域、同一脚本/CI 所有权 |
| 假完成攻击面 | 「模块绿灯 / tsc / 文档声明 / warn 门禁 / 相对改善 / 相对基线 / 待测可残留」 |

| 对照 v3 §二/§四.3/§八 | 删除面必含、路径 N→M、负产出可验证、禁止无日期 fallback |

**总判（一句话）**：六案删除面与负向断言整体强于「只优化不删」的常见假完成面；最大系统性风险不是「没人写验收」，而是 **跨案 SSOT/文件域/CI 脚本多头认领 + 若干相对型验收 + Progress/PE-02 会签无强制触发点**，主控定 92 时若不做「单主责 + 绝对阈值 + 评审票有截止语义」三件事，会在实现轮把绿灯做成空转。

3. 死代码「删除或接线」必须在任务开始时勾选唯一分支，禁止结束时再选。

### 4.2 契约相关逻辑断环（评审意见）
