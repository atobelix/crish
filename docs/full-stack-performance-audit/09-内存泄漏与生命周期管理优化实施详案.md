### 1.2 关键架构分歧裁决与融合决策矩阵（七大权威裁决）

#### 裁决 1：会话生命周期升级为三级级联取消总线（Three-Tier Cascade Cancellation Bus，根除 VULN-05）

- **裁决结论**：全面采纳 Review-02 §4.4 方案四，将 `SessionLifecycleRegistry` 升级为具备级联取消在行 Worker（Tier 1 计算级）、中止 Rust 流式与墓碑拦截（Tier 2 通信级）、以及写入 SQLite 墓碑写屏障（Tier 3 存储级）的三级级联取消总线。
- **裁决理由**：单纯在前端清理 Map/Set 是“掩耳盗铃”。会话硬删除瞬间，若 WorkerPool 仍有密集任务在算、Rust 内核仍在发 Token、SQLite 延迟写盘尚未落库，已删会话必定在 50~200ms 后被反向写回（幽灵复活）或在控制台爆出未捕获异常。三级级联取消是系统级严密的唯一正确解。

#### 裁决 2：生命周期总线广播单点内聚切入底层 Action，全仓 0 侵入（Review-01 §5.3）

- **裁决结论**：严禁在全仓各个 UI 组件或业务入口分散手工调用清理函数。总线广播必须**100% 严格内聚在底层原子变更中枢**：
  - 硬删除切入点：`apps/crish-desktop/src/store/sessionCrudActions.ts:deleteSession`；
  - 软逐出切入点：`apps/crish-desktop/src/store/sessionEviction.ts:evictSessionMessagesInState`。
- **裁决理由**：无论上层是从侧边栏右键、快捷键、工作区 Shell 关闭还是外部 IPC 触发删除，底层原子 Action 是全仓所有链路的必经漏斗。单点内聚切入，改动仅 2 行，收益覆盖全仓，杜绝漏清死角。

#### 裁决 3：全仓统一持久化防抖常量 `STORAGE_PERSIST_DEBOUNCE_MS = 300`（Review-01 §2.2 与 §5.2）

- **裁决结论**：废除各文档与实现中散落的 250ms、300ms、350ms 随意取值，在 `apps/crish-desktop/src/store/persistenceConstants.ts` 中确立全仓唯一的存储防抖单一真理源：`export const STORAGE_PERSIST_DEBOUNCE_MS = 300;`。`withPersist`、`DebouncedStateStorage`、`store-persistence.ts` 等一律统一引用此常量。
- **裁决理由**：消除不同 Store 在并发输入时的落盘时序不可预测与快照竞态覆盖隐患，实现架构净收敛。

#### 裁决 4：`MessageSnapshots` 演进为纯 Delta 逆向补丁结构，硬性截断 5MB 预算

- **裁决结论**：全面采纳纯差量补丁架构（Pure Delta Reverse Patch），彻底剔除 `SnapshotEntry` 中的全量 `messages: SessionMessage[]` 引用。
- **裁决理由**：在长会话中，变更前全量数组克隆（`messages.slice()`）在 10 层快照下实际吃掉 20MB 物理堆内存，而旧账本仅计 10KB。纯差量架构仅记录被替换/删除的消息切片，将物理内存压缩 95% 以上，且使真实字节账本与底层物理占用完全重合。软逐出（`onSoftEvict`）时立即清空该会话的快照栈。

#### 裁决 5：废除旧切片逐出，收口至感知分屏与 LRU 的三态逐出状态机（P9-02）

- **裁决结论**：物理删除 `sessionMessageEviction.ts`，全仓收口至 `sessionEviction.ts`。在评估逐出时，必须严格读取 `useLayoutTreeStore.getState().collectOpenSessionIds()`，分屏打开的会话哪怕只有 1 像素可见也绝对豁免逐出。
- **裁决理由**：彻底终结多窗格分屏时右侧可见会话被旧切片逻辑误逐出导致正文空白的恶性 Bug。

#### 裁决 6：终端 PTY 前缀扫描批量 Kill，门闩设立 512KB 环形窗口并注入 ANSI 告警（Review-01 §2.4）

- **裁决结论**：全面采纳 `takeAllForSession` 前缀通配匹配规则（`${sid}:terminal:N` 与 `${sessionKey}:split-2`）与 `PtyWriteGate` 512KB 字符环形缓冲；淘汰发生时在头部插入 ANSI 截断告警标记。
- **裁决理由**：彻底阻断底层 Rust 进程孤儿化与 512KB 缓冲泄漏；切回耗时稳定 $\le 8\text{ms}$，且明确提示用户日志被截断。

#### 裁决 7：引入 `FinalizationRegistry` 弱引用兜底自洁与反过度设计收敛（Review-03 §1.4）

- **裁决结论**：在中心化总线确定性广播的基础上，增加轻量级 `FinalizationRegistry` 弱引用守卫作为防漏注兜底；坚决遵守反过度设计红线，不自制复杂事件中间件流水线。
- **裁决理由**：以极小代价实现自愈式资源收口，兼顾确定性即时释放与弱引用安全防护网。

#### 1. 调度中枢接口契约与三级取消架构

```ts
import { workerPool } from '@/workers/worker-pool';
import { sharedSessionStreamManager } from '@/api/sessionStreamManager';
import { recordDeletedSessionTombstone } from '@/api/session-persistence/sessionRustDbHydrate';

export type SessionLifecycleHandler = (sessionId: string) => void;

export interface SessionLifecycleSubscriber {
  /** 唯一标识符，用于调试定位、可观测性与防重注册 */
  readonly id: string;
  /** 会话进入后台软逐出（释放重型内存，保留会话骨架） */
  readonly onSoftEvict?: SessionLifecycleHandler;
  /** 会话硬删除（彻底销毁一切关联内存、定时器、进程与本地存储） */
  readonly onHardDelete?: SessionLifecycleHandler;
}

class SessionLifecycleRegistry {
  private static instance: SessionLifecycleRegistry | null = null;
  private subscribers = new Map<string, SessionLifecycleSubscriber>();
  private finalizationRegistry?: FinalizationRegistry<string>;

  private constructor() {
    // 注册 FinalizationRegistry 兜底自愈守卫（Review-03 §1.4）
    if (typeof FinalizationRegistry !== 'undefined') {
      this.finalizationRegistry = new FinalizationRegistry((heldSessionId) => {
        console.debug(
          `[SessionLifecycleRegistry:GC] Session object for ${heldSessionId} reclaimed by V8 GC.`
        );
      });
    }
  }

  public static getInstance(): SessionLifecycleRegistry {
    if (!SessionLifecycleRegistry.instance) {
      SessionLifecycleRegistry.instance = new SessionLifecycleRegistry();
    }
    return SessionLifecycleRegistry.instance;
  }

  /**
   * 注册生命周期订阅者。返回注销函数。
   */
  public register(subscriber: SessionLifecycleSubscriber): () => void {
    if (this.subscribers.has(subscriber.id)) {
      console.warn(
        `[SessionLifecycleRegistry] Subscriber ${subscriber.id} already registered, overwriting.`
      );
    }
    this.subscribers.set(subscriber.id, subscriber);
    return () => {
      this.subscribers.delete(subscriber.id);
    };
  }

  /**
   * 触发软逐出广播
   */
  public dispatchSoftEvict(sessionId: string): void {
    const sid = String(sessionId || '').trim();
    if (!sid) return;
    for (const [id, sub] of this.subscribers.entries()) {
      if (sub.onSoftEvict) {
        try {
          sub.onSoftEvict(sid);
        } catch (err) {
          console.error(
            `[SessionLifecycleRegistry] Subscriber ${id} failed onSoftEvict for ${sid}:`,
            err
          );
        }
      }
    }
  }

  /**
   * 触发硬删除广播（三级级联取消大总线）
   */
  public dispatchHardDelete(sessionId: string): void {
    const sid = String(sessionId || '').trim();
    if (!sid) return;

    // =========================================================================
    // 【第 1 级：计算级取消 (Compute Tier)】
    // 立即终止 WorkerPool 中排队及正在运行的任务，终止 Worker 实例并重建
    // =========================================================================
    try {
      workerPool.cancelBySession(sid);
    } catch (err) {
      console.error(
        `[SessionLifecycleRegistry:Tier1] WorkerPool cancellation failed for ${sid}:`,
        err
      );
    }

    // =========================================================================
    // 【第 2 级：通信级取消 (Transport Tier)】
    // 通知 Rust 内核发送 abort_run，并在前端流式缓冲中注入墓碑，丢弃一切迟到 Token
    // =========================================================================
    try {
      sharedSessionStreamManager.abortSession(sid);
    } catch (err) {
      console.error(
        `[SessionLifecycleRegistry:Tier2] StreamManager abort failed for ${sid}:`,
        err
      );
    }

    // =========================================================================
    // 【第 3 级：持久化写屏障 (Storage Barrier Tier)】
    // 在 SQLite 与本地持久化层写入墓碑标记，拦截一切在途延迟落盘请求
    // =========================================================================
    try {
      recordDeletedSessionTombstone(sid);
    } catch (err) {
      console.error(
        `[SessionLifecycleRegistry:Tier3] Storage tombstone registration failed for ${sid}:`,
        err
      );
    }

    // =========================================================================
    // 【静态集合与关联资源清理矩阵广播】
    // 驱动注册在案的 12 处模块级集合、PTY 批量收割器与 DOM 弱引用脱钩
    // =========================================================================
    for (const [id, sub] of this.subscribers.entries()) {
      if (sub.onHardDelete) {
        try {
          sub.onHardDelete(sid);
        } catch (err) {
          console.error(
            `[SessionLifecycleRegistry] Subscriber ${id} failed onHardDelete for ${sid}:`,
            err
          );
        }
      }
    }
  }

  /**
   * 为临时会话宿主对象注册垃圾回收观察
   */
  public trackObject(target: object, sessionId: string): void {
    this.finalizationRegistry?.register(target, sessionId);
  }

  /**
   * 仅用于单测环境重置状态
   */
  public resetForTest(): void {
    this.subscribers.clear();
  }
}

export const sessionLifecycleRegistry = SessionLifecycleRegistry.getInstance();
```

#### 2. 真实字节核算算法

```ts
private estimateBytes(delta: MessageDelta, heights?: Record<string, number>): number {
  let bytes = 128; // entry 基础对象头开销
  // 核算被删除消息的序列化开销
  for (const msg of delta.deleted) {
    bytes += (msg.id?.length ?? 0) * 2;
    bytes += (msg.text?.length ?? 0) * 2;
    bytes += (msg.thought?.length ?? 0) * 2;
    if (msg.toolCalls) {
      bytes += JSON.stringify(msg.toolCalls).length * 2;
    }
  }
  // 核算插入消息的元数据开销
  for (const msg of delta.inserted) {
    bytes += (msg.id?.length ?? 0) * 2;
  }
  // 核算高度表开销
  if (heights) {
    bytes += Object.keys(heights).length * 48;
  }
  return bytes;
}
```

```ts
// apps/crish-desktop/src/store/sessionEviction.ts
import { useLayoutTreeStore } from '@/store/layoutTreeStore';

export function evaluateSessionEviction(): number {
  const state = getSessionStoreState();
  const activeId = state.activeSessionId;

  // 【P9-02 核心强化】深度采集分屏树中所有可见窗格绑定的会话 ID
  const openIds = useLayoutTreeStore.getState().collectOpenSessionIds();
  const streamingIds = collectStreamingSessionIds();

  // 筛选已水合且包含正文的候选后台会话
  const candidates: Array<{ id: string; lastAccess: number }> = [];
  for (const s of state.sessions) {
    // 只要是当前主激活会话、分屏任意可见窗格会话、或正在推流会话，一律 100% 绝对豁免！
    if (s.id === activeId || openIds.has(s.id) || streamingIds.has(s.id)) {
      continue;
    }
    if (s.messages && s.messages.length > 0 && s.messagesHydrated) {
      candidates.push({
        id: s.id,
        lastAccess: sessionAccessTimestamps.get(s.id) ?? 0,
      });
    }
  }

  // 超过允许的最大常驻会话数（默认 3）
  const MAX_RETAINED = 3;
  if (candidates.length <= MAX_RETAINED) return 0;

  // 按最近访问时间升序排序（最老在最前）
  candidates.sort((a, b) => a.lastAccess - b.lastAccess);
  const toEvict = candidates.slice(0, candidates.length - MAX_RETAINED);

  for (const item of toEvict) {
    state.evictSessionMessages(item.id);
  }
  return toEvict.length;
}
```

```ts
// apps/crish-desktop/src/api/ptyRegistry.ts
takeAllForSession(sessionId: string): string[] {
  const sid = (sessionId || '').trim();
  if (!sid || sid.length < 3) return [];
  const prefix = `${sid}:`;
  const ptyIds: string[] = [];

  for (const [key, ptyId] of this.bySession.entries()) {
    if (key === sid || key.startsWith(prefix)) {
      ptyIds.push(ptyId);
      this.bySession.delete(key);
    }
  }
  return ptyIds;
}

export async function killPtyForSession(sessionId: string | null | undefined): Promise<void> {
  const sid = (sessionId || '').trim();
  if (!sid) return;
  const ptyIds = ptyRegistry.takeAllForSession(sid);
  for (const ptyId of ptyIds) {
    clearPtyHistory(ptyId);
```

```ts
// apps/crish-desktop/src/components/workspace/ptyWriteGate.ts
export const TRUNCATED_WARNING_ANSI =
  '\r\n\x1b[33m[crish: terminal background output truncated to 512KB to preserve memory]\x1b[0m\r\n';

export function createPtyWriteGate(
  sink: { write: (data: string) => void },
  startHidden = false
): PtyWriteGate {
  const MAX_PENDING_CHARS = 512 * 1024; // 512KB 字符上限
  let hidden = startHidden;
  let pending: string[] = [];
  let pendingChars = 0;
  let hasTruncated = false;

  return {
    setHidden(next: boolean): void {
      if (hidden && !next) {
        let merged = pending.join('');
        pending = [];
        pendingChars = 0;
        // 若后台期间发生过数据截断淘汰，向头部注入显式 ANSI 告警
        if (hasTruncated) {
          merged = TRUNCATED_WARNING_ANSI + merged;
          hasTruncated = false;
        }
        if (merged) {
          try {
            sink.write(merged);
          } catch {}
        }
      }
      hidden = next;
    },
    write(data: string): void {
      if (!data) return;
      if (hidden) {
        pending.push(data);
        pendingChars += data.length;
        // 环形溢出淘汰：弹出最老数据块，并置位截断标记
        while (pendingChars > MAX_PENDING_CHARS && pending.length > 0) {
          const oldest = pending.shift()!;
          pendingChars -= oldest.length;
          hasTruncated = true;
        }
        return;
      }
      sink.write(data);
    },
    dispose(): void {
      pending = [];
      pendingChars = 0;
      hasTruncated = false;
    },
  };
}
```

```ts
export class WindowResizeBridge {
  private connectEpoch = 0;
  private connected = false;
  private cleanupFns: Array<() => void> = [];

  async connect(): Promise<void> {
    const epoch = ++this.connectEpoch;
    this.connected = true;

    try {
      const { getCurrentWindow } = await import('@tauri-apps/api/window');
      const win = getCurrentWindow();
      const unlisten = await win.onResized(() => this.handleResize());

      // 解析后状态复查：已断开或已进入新年份则立即退订
      if (!this.connected || this.connectEpoch !== epoch) {
        unlisten();
        return;
      }
      this.cleanupFns.push(unlisten);
    } catch {
      if (!this.connected || this.connectEpoch !== epoch) return;
      const handler = () => this.handleResize();
      window.addEventListener('resize', handler);
      this.cleanupFns.push(() => window.removeEventListener('resize', handler));
    }
  }

  disconnect(): void {
    this.connectEpoch++;
    this.connected = false;
    for (const fn of this.cleanupFns) fn();
    this.cleanupFns = [];
  }
}
```

```ts
import {
  persist,
  type PersistOptions,
  type StateStorage,
} from 'zustand/middleware';
import { STORAGE_PERSIST_DEBOUNCE_MS } from '../persistenceConstants';

function shallowEqual<T>(a: T, b: T): boolean {
  if (Object.is(a, b)) return true;
  if (!a || typeof a !== 'object' || !b || typeof b !== 'object') return false;
  const keysA = Object.keys(a as object);
  const keysB = Object.keys(b as object);
  if (keysA.length !== keysB.length) return false;
  for (const k of keysA) {
    if (
      !Object.prototype.hasOwnProperty.call(b, k) ||
      !Object.is(
        (a as Record<string, unknown>)[k],
        (b as Record<string, unknown>)[k]
      )
    ) {
      return false;
    }
  }
  return true;
}

export function createDebouncedStorage(
  baseStorage: StateStorage = localStorage,
  debounceMs = STORAGE_PERSIST_DEBOUNCE_MS
): StateStorage {
  const pendingWrites = new Map<string, { value: string; timer: number }>();
  const lastWrittenSnapshots = new Map<string, unknown>();

  const flush = (name: string) => {
    const entry = pendingWrites.get(name);
    if (!entry) return;
    window.clearTimeout(entry.timer);
    pendingWrites.delete(name);
    try {
      baseStorage.setItem(name, entry.value);
    } catch {}
  };

  if (typeof window !== 'undefined') {
    window.addEventListener('beforeunload', () => {
      for (const name of Array.from(pendingWrites.keys())) flush(name);
    });
    document.addEventListener('visibilitychange', () => {
      if (document.visibilityState === 'hidden') {
        for (const name of Array.from(pendingWrites.keys())) flush(name);
      }
    });
  }

  return {
    getItem: (name: string) => baseStorage.getItem(name),
    setItem: (name: string, value: string) => {
      try {
        const parsed = JSON.parse(value) as { state?: unknown };
        const nextState = parsed?.state;
        const prevState = lastWrittenSnapshots.get(name);

        // 顶层浅等脏检查短路：流式期仅改动 messages 时，直接 0ms 返回！
        if (prevState !== undefined && shallowEqual(prevState, nextState)) {
          return;
        }
        lastWrittenSnapshots.set(name, nextState);
      } catch {}

      // 真实脏更新：启动统一 300ms 尾随防抖
      const existing = pendingWrites.get(name);
      if (existing) window.clearTimeout(existing.timer);

      const timer = window.setTimeout(() => flush(name), debounceMs);
      pendingWrites.set(name, { value, timer });
    },
    removeItem: (name: string) => {
      const existing = pendingWrites.get(name);
      if (existing) {
        window.clearTimeout(existing.timer);
        pendingWrites.delete(name);
      }
      lastWrittenSnapshots.delete(name);
      baseStorage.removeItem(name);
    },
  };
}
```

## 四、跨模块协同契约与系统级边界协议

### 4.1 与 Part 08（UI 原子组件与浮层调度栈）的协同契约（LayerStack WeakRef 级联脱钩）

1. **浮层栈与 Detached DOM 级联注销协议（P8-02）**：
   - 当会话发生硬删除时，`SessionLifecycleRegistry` 广播通知 `LayerStackManager`；
   - `LayerStackManager` 执行 `dismissBySessionId(sessionId)`，释放属于该会话的一切弹出层、快捷操作浮层与上下文菜单；
   - 持有 DOM 节点统一采用 `WeakRef<HTMLElement>`，并在 150ms 冷却后强制置空，确保 V8 能即刻回收已卸载会话的 DOM 子树及绑定的 React Fiber。
2. **休眠总线协同**：
   - 在 `document.visibilityState === 'hidden'` 时，主动触发浮层收起与草稿刷脏，暂停后台不必要动画。

---

### 4.2 与 Part 10（冷启动单例惰性加载与内存预算）的协同契约

1. **JIT 惰性派生与销毁对称闭环**：
   - 冷启动阶段保持首屏极简（`ChatMessageList` 懒加载、`WorkerPool` 0 实例、终端 0 进程）；
   - 用户首条消息交互唤起重型资源后，其生命周期严格挂钩在 `SessionLifecycleRegistry`；
   - 会话删除或逐出后，内存状态严格回落至冷启动初始水位。
2. **SSOT 内存预算刚性对齐**：
   - 对齐 `packages/shared-utils/src/bounds.ts` 权威预算：
     - 全局 V8 Heap 预算：$\le 200\text{ MiB}$；
     - 消息撤回栈全局预算：$\le 5\text{ MiB}$；
     - 单 PTY 历史缓冲上限：$\le 512\text{ KiB}$；
     - 隐藏终端门闩上限：$\le 512\text{ KiB}$。
   - 当 `memoryManager` 发出 Level 3 内存预警时，强制触发最老后台会话的 `onSoftEvict` 重资产释放。

---

### 4.3 与后端 Rust PTY 进程及跨层 IPC 桥接的协同契约

1. **终端进程无残留握手**：
   - 前端通过 `takeAllForSession(sessionId)` 保证一次性收割 `${sid}:terminal:N` 与 `${sessionKey}:split-2` 所有子进程；
   - 前端在向 Rust 发送 `workbench_pty_kill` 之前，先本地调用 `clearPtyHistory(ptyId)` 并注销 Fanout 广播；
   - 保证底层进程退出与前端缓冲销毁原子同步。

---

### 4.4 与 Part 04（WorkerPool 异步计算任务与排队取消）的三级取消协同契约（Tier 1）

1. **任务与会话所属权映射**：
   - `WorkerPool` 在入队新任务时，必须记录 `taskIdToSessionId: Map<string, string>`；
2. **`cancelBySession(sessionId: string)` 取消契约**：
   - **排队任务**：从 FIFO/优先级队列中将匹配 `sessionId` 的待调度任务全部出队，调用其对应 `reject(new Error('Session cancelled'))`；
   - **在行任务**：若当前某个 Worker 正在执行匹配 `sessionId` 的任务，主线程调用 `worker.terminate()` 强制杀死底层 Web Worker 线程，并立即重新初始化一个新的 Worker 实例补充回池中，防止昂贵的正则/高亮运算继续霸占 CPU 核心。

---

### 4.5 与 Part 02（流式引擎中止与墓碑拦截）及 SQLite 持久化写屏障（Tier 2 & 3）的协同契约

1. **传输级流式双向截断 (Tier 2)**：
   - 会话硬删除时，`sharedSessionStreamManager.abortSession(sid)` 向后端 Rust 派发 `workbench_abort_run` 指令；
   - 前端 `useStreamingStore` 立即将 `sid` 标记为 Tombstone 墓碑，后续即便由于网络或跨进程延迟收到迟到的 `workbench-run-event`，也在入口处静默丢弃，绝不在 Store 中重新分配条目。
2. **存储层防复活写屏障 (Tier 3)**：
   - 在 `sessionRustDbHydrate.ts` 中维护容量为 500 的 LRU 墓碑集合 `deletedSessionTombstones = new Set<string>()`；
   - 暴露 `recordDeletedSessionTombstone(sid: string): void`；
   - 在 `saveSessionBody`、`saveSessionAgents`、`saveSessionIndex` 执行落盘 IPC 调用前，必须执行检查：
     ```ts
     if (deletedSessionTombstones.has(sessionId)) {
       console.warn(
         `[StorageBarrier] Suppressed write for deleted session: ${sessionId}`
       );
       return;
     }
     ```
   - 彻底阻断异步落盘延迟导致的已删会话“反向复活”。

### 6.2 风险矩阵与回滚兜底策略

1. **三级级联取消与 WorkerPool terminate 重建风险**：
   - 风险：强制 terminate 正在运算的 Worker 实例可能导致其他非关联排队任务被误伤。
   - 兜底：`WorkerPool` 仅终止当前正在执行该会话任务的单个 Worker 实例，其他处于空闲或处理其他任务的 Worker 保持不变；终止后同步补建实例，保障池容量恒定。
2. **SQLite 墓碑容量溢出与写屏障失效风险**：
   - 风险：极端场景下用户快速连续创建并删除超过 500 个会话，导致最老墓碑被逐出，滞后写盘重新复活。
   - 兜底：将 `deletedSessionTombstones` 设为 LRU 缓存，并在 `sessionRustDbHydrate.ts` 的持久化层检查会话是否存在于主 Store 中；若 Store 与墓碑任一显示已被删除，均拒绝写盘。
3. **前缀杀终端误伤风险**：
   - 风险：若 `sessionId` 为空字符串或异常字符，前缀匹配可能误伤其他会话终端。
   - 兜底：`takeAllForSession` 严格校验 `if (!sid || sid.length < 3) return [];`，前缀匹配严格要求带冒号分隔符 `${sid}:`。
4. **纯 Delta 快照逆向计算异常风险**：
   - 风险：极端情况下逆向差量补丁应用失败可能导致撤回显示不一致。
   - 兜底：保留快照序列版本号与 Hash 校验；若补丁应用失败，安全回退至从本地持久化数据库重新加载会话当前权威状态。
5. **存储防抖丢失风险**：
   - 风险：进程突发异常闪退可能导致最后 300ms 的草稿输入未落盘。
   - 兜底：监听 `beforeunload` 与 `visibilitychange`（切后台）；一旦触发立即同步执行 `flush()`，确保数据零丢失。
