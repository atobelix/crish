## 一、协作铁律与质量红线

1. **反退避与问题同权**：遵循 `.agents/LOGIC_PLAN_NO_RETREAT.md` 与根 `AGENTS.md` §1。不按业务 P0/P1 砍项，不隐瞒任何性能隐患，所有发现的问题一视同仁、完整记录。
2. **证据锚定**：每一处性能问题必须给出精确的 **`文件路径:行号`**、关键代码片段、复杂度/开销推导（如时间复杂度 $O(N^2)$、重渲染触发频次、强制同步布局链路、内存驻留上限缺失等）以及根治方向建议。
3. **只读勘察边界**：方案制定与审查阶段严禁修改任何业务源码（`apps/`、`packages/`、`crates/`），最终详案直接落盘至战役根目录 `01-*.md` ~ `10-*.md`；严禁执行 `git commit` / `git reset` 等 Git 写操作。
4. **反过度设计守卫**：遵循 `ANTI_OVERENGINEERING_GUARDRAILS.md`，不提议违反红线的伪优化（如以 95% `React.memo` 覆盖率作硬门槛、`SharedArrayBuffer` 环形缓冲等），聚焦真实架构瓶颈（精确订阅、批量合并、Worker 卸载、虚拟化、合成层动画、有界缓存与生命周期清理）。
