## 二、跨维度横切核心瓶颈与系统性根因剖析

通过对 10 个维度的交叉比对，前端性能瓶颈可归纳为以下 **7 大系统性架构断层**：

### 1. 流式对话热路径的「批处理击穿 + 全量重解析 + 跨窗格级联重渲染」三重叠加

- **批处理阈值语义反转（Dim-02）**：`StreamTextBatcher.shouldForceFlush()`（`streamingStoreCore.ts:110-124`）将**累积全文长度**（`text.length`）与 `maxBufferedChars`（思考 4,000 字 / 正文 8,000 字）比较，而非比较「未刷新的增量 delta 长度」。一旦长回答超过阈值，每个 Token 到达时 `shouldForceFlush()` 恒为 `true`，16ms 帧合并 100% 退化为逐 Token 同步写 Store。
- **子代理流式事件完全绕过批处理（Dim-02）**：`subagentHandlers.ts:57-79` 在多子代理并发输出时，直接以 400–600Hz 频率调用 `useSessionStore` 的 Immer `set`，每 Token 克隆整条消息与 `subAgents` 数组。
- **流式高度每涨 4px 触发全会话历史词法重扫与 DOM 观察器重建（Dim-03 / Dim-09）**：`FlowScrubber.tsx:99-105, 217-309` 的 `heightBucket = Math.floor(totalHeight / 4)` 在流式输出期间每秒变化数十次，导致 `useMemo` 不断失效，对会话内**所有历史消息**重跑 `marked` `Lexer.lex()` 正则词法分析，并销毁重建 `IntersectionObserver` 与子树 `MutationObserver`。
- **行内未闭合 Markdown 字符级切分触发 IPC 洪峰（Dim-04）**：`IncrementalMarkdownInline.ts:156-180` 在遇到未闭合的 `*`、`` ` ``、`[` 时，把后续每个字符切分成独立的 `textPart`，导致 `RichInlineRenderer` 对每个字符发起一次异步 Tauri IPC `core_md_render` 请求。
- **投机闭合计算成果被无声丢弃（Dim-04）**：`useStreamingBlocks.ts:59` 每帧耗费 CPU 计算 `speculativeCloseBlock(text)`，但下游 `MarkdownBlockItem.tsx:79` 将其解构为 `_virtualClosedText` 后直接丢弃，仍传入未闭合的原始 `block.text`。

### 2. 高频主线程同步 `localStorage` 序列化与全量持久化克隆阻塞

- **`withPersist` 在 31Hz 流式帧同步写 `localStorage`（Dim-01 / Dim-09）**：`withPersist.ts:22-37` 无脏检查、无节流；在流式期间每次触发 `useSessionStore.setState`（如 `touchSessionActivity`）都会同步执行 `partialize` + `JSON.stringify` + `localStorage.setItem`。
- **`persistAllSessionsRust` 事前映射击穿 $O(1)$ 引用相等快路径（Dim-02）**：`sessionRustDbHydrate.ts:251-331` 在调用 `isSessionBodyDirty` 之前，先对所有会话执行 `s.messages.map(normalizeAssistantTimeline)` 生成全新数组引用，导致引用相等快路径 100% 失效，每次定时器触发都对所有会话全量 JSON 序列化并計算 FNV-1a 哈希。
- **模块加载期重复全量读取 `localStorage`（Dim-01）**：`layoutStore.ts:109` 与 `workspaceStore.ts:55` 在顶层模块导入阶段各自调用 `createInitialLayoutDefaults()`，连续执行两次 `crish_session_store` 全表 `JSON.parse` 且丢弃 `sessionSeed`。

### 3. 虚拟滚动与重型列表的「假虚拟化」与强制同步布局（Layout Thrashing）

- **侧边栏会话列表虚拟化 100% 失效（Dim-06）**：`useWindowedList.ts:71` 将 `scrollParentRef` 绑定在高度随内容无限撑开的 `.listScroll`（`flex: none`）而非外层滚动容器 `.sidebarScroll`（`overflow-y: auto`）上，导致 `clientHeight === scrollHeight`，`useSessionListWindow` 永远判定 `windowed: false`，全量渲染所有历史会话 DOM。
- **输入框每次击键触发强制同步回流（Dim-05）**：`useComposerMultiline.ts:20-35, 67-193` 在每次按键 `input` 事件中同步调用 5 次 `querySelector`、读取 `clientWidth` / `offsetWidth` / `scrollWidth` 與 `getComputedStyle`，且因依赖 `text` 每 150ms 拆装一次 `ResizeObserver`。
- **分屏拖拽期间 `ResizeObserver` 冻结桥未接线（Dim-06）**：`ResizeObserverManager.ts` 虽设计了 `beginLayoutInteraction()` 冻结门控，但 `useTreeResize.ts`、`LeafDockResizer.tsx` 与 `useSidebarResize.ts` 均未调用，拖拽分割线时 60fps 实时修改 `split.ratio` 触发全子树重渲染与 `ResizeObserver` 测量风暴。
- **块编辑器与 Note-Paper 自动保存卸载重挂（Dim-05）**：`useNoteHydrate.ts:103-153` 因 `activeDoc` 对象引用在每次 400ms 自动落盘后更新，将 `status` 重置为 `'loading'`，直接卸载整棵 `PaperList` 与 `BlockChromeDomHost` 并丢失编辑焦点。

### 4. 重型工具视图（终端、Diff、图片附件）的主线程尖峰与闪烁

- **隐藏终端 `pending` 缓冲区无界积压与切回瞬间单帧卡死（Dim-07 / Dim-09）**：`ptyWriteGate.ts:35-65` 在终端不可见时将所有 PTY 输出追加至无上限的 `pending: string[]`，切换回终端 Tab 时通过 `pending.join('')` 单次同步调用 `term.write` 灌入数 MB 数据，冻结主线程。
- **Diff 视图全文件双模式急切计算与滚动 1 行全屏闪烁（Dim-07）**：`useDiffData.ts:295-302` 在打开 Diff 卡片时同步为所有 $M$ 个变更文件同时计算 Unified 和 Split 两种模式的 LCS Diff；`useDiffHighlightMap`（`codeHighlightBatch.ts:102-143`）在虚拟滚动仅移动 1 行时，用未高亮的 `escapeHtml` 覆盖全部 50 行可见状态，导致已高亮的 49 行瞬间退化为纯文本闪烁。
- **PNG 图片粘贴 12 次冗余重编码与 3 次重复解码（Dim-05）**：`imageProcessing.ts:17-182` 对同一张图片连续 `new Image()` 解码 3 次，且在 `image/png` 格式下忽略 `quality` 参数空跑 4 次完全相同的 `canvas.toDataURL('image/png')` 同步编码。

### 5. UI 原子组件、浮层与 CSS 渲染管线的常驻后台开销

- **`SafeAimEngine` 与 `useSafeAim` 闭合态泄露全屏 `<svg>` 与永久 `mousemove` 监听（Dim-08）**：`SmartExpandablePanel.tsx:72-75` 与 `SmartPanel/hooks/useSafeAim.ts:40-75` 在面板未打开时即向 `document.body` 注入 `100vw × 100vh` 的 `<svg>` 并挂载永不解绑的 `window` `mousemove` 监听器，鼠标在应用内任意移动均触发 120–1000Hz 的 SVG 属性读写与 `getBoundingClientRect()`。
- **`Tooltip` 全局控制器在每次滚动时遍历全表并全树 `querySelectorAll`（Dim-08）**：`tooltipController.ts:82-105` 在没有任何 Tooltip 打开时，仍在每次 `scroll` 事件中遍历页面上数百个 `<Tooltip>` 实例派发 $3N$ 次 `setState`，并调用 `document.body.querySelectorAll`；且单个可见 Tooltip 会启动 60fps `rAF` 每帧轮询 `matches(':hover')` 与 `getBoundingClientRect()`。
- **全局 CSS `[class*='...']` 击穿 Blink 类名哈希桶与全局 `optimizeLegibility`（Dim-08）**：`overlay-scrollbar.css:137-356` 等处的 30+ 个 `[class*='...']` 属性子串选择器迫使每个带 `class` 的节点在样式重算时走子串扫描；`shell-reset.css:20,39` 全局开启 `text-rendering: optimizeLegibility` 使流式文本与终端输出全部落入 HarfBuzz 慢路径。

### 6. 会话生命周期清理断链与多容器内存驻留泄漏

- **`MessageSnapshots` 字节统计漏算全量消息快照（Dim-09）**：`MessageSnapshots.ts:175-192, 252` 在 `SnapshotEntry` 中保存了完整的 `messages.slice()`，但 `estimateBytes` 只计算了 `delta.inserted` 的字节数，导致 5MB 内存上限形同虚设；且会话软逐出（`sess.messages = []`）未清理 `MessageSnapshots` 与 `SessionRuntimeRegistry`。
- **会话硬删除绕过级联清理且 12 个模块级 Map 永久残留（Dim-09）**：侧栏右键删除等入口直接调用 `deleteSession` 绕过 `SessionCoordinator.deleteSessionCascade`，且 12 个按 `sessionId` 索引的模块级 `Map`/`Set` 无清理出口；多终端 `${sid}:terminal:N` 与分屏终端在关闭会话时漏调 `pty_kill`，导致后端 PTY 进程与前端 512KB/终端历史缓冲区永久驻留。
- **`activeTimerIds` 误用 `.add()` 代替 `.delete()`（Dim-09）**：`taskEventHandlers.ts:352` 在 `onTimerFired` 中错误调用 `activeTimerIds.add(payload.timerId)`，导致定时器 ID 集合只增不减。

### 7. 冷启动 `manualChunks` 贪婪吞并、Chunk 循环依赖与首屏水合瀑布

- **`manualChunks` 贪婪吞并 349 个未分配模块并形成双向 Chunk 循环（Dim-10）**：`vite.config.ts:846-877` 中 `chat-provider-catalog` 与 `chat-runtime-core` 顺着静态 `import` 链吞并了全量 Store、IPC Transport 与全部 18 套 UI 组件库，并产生双向静态循环依赖（`node scripts/check-chunk-cycles.mjs` 实测报错退出码 1）。
- **首屏同步预加载 1.5MB JS + 空草稿态拉取 869KB 渲染依赖（Dim-10）**：`index.html` 同步预加载 1,516 KiB JS；且 `ChatCard.tsx:3` 顶层静态导入 `ChatMessageList` → `ChatAssistantMessageRow` → `highlight.js`，即便冷启动处于零消息空态也强制加载并解析近 870KB 消息渲染与高亮代码。
- **首屏挂载期 `hardware-profile.ts` 30ms 主线程忙等与重复 IPC 探针（Dim-10）**：`usePlatformAdaptation` 在首屏水合期同步执行 `3 × 10ms` `while` 忙等循环、临时 IndexedDB 建删库与 3 个 WebGL 上下文创建；同时 `prefs_get('fonts')`、`fetchRecentWorkspaces`、`projectStore.refresh`、`core_get_status` 在启动期各自被重复调用 2–3 次。
