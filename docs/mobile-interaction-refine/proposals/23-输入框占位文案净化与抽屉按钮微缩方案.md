# 23-输入框占位文案净化与抽屉按钮微缩方案

> **所属战役**：移动端交互体验与视觉细节精进（Mobile Interaction Refinement）  
> **涉及模块**：  
> - 核心输入框：`apps/crish-mobile/src/presentation/ui/Composer.tsx`  
> - 移动端首页：`apps/crish-mobile/src/presentation/screens/homeScreen.tsx`  
> - 本地会话引擎：`apps/crish-mobile/src/adapters/conversation/useLocalConversationEngine.tsx`  
> - 抽屉侧边栏：`apps/crish-mobile/src/presentation/components/drawer/CrishDrawerContent.tsx`  
> - 单元测试与规范门禁：`CrishDrawerContent.test.tsx`、`homeScreen.test.tsx`、`useLocalConversationEngine.test.tsx`、`roundButton.guard.test.tsx`  
> **用户核心反馈与裁决**：  
> “输入框的本地对话这个可以去掉，因为用处不大。 按钮的话，稍微小一点，现在看着好像稍微大了一丢丢。”  
> **核心改进原则**：  
> 1. **Placeholder 文案去标签化与纯粹化**：彻底剔除“本地对话 · ”这一繁琐、防御式且对用户无价值的前缀；在远端与本地模式下统一净化为简洁有力的交互提示（`点击发消息、长按语音输入`），消除心智割裂与小屏截断隐患；  
> 2. **抽屉侧边栏动作按钮 36dp 黄金微缩**：将抽屉 5 个动作按钮（扫码、通知、取消搜索、设置、新建对话）由 40dp 精细微调为 36dp，搭配 18dp 图标与 4dp `hitSlop`（严格维持 44dp 无障碍热区）；彻底纠正 40dp 相对 32dp 头像所造成的“层级倒挂”与“笨重感”，呈现呼吸感充盈的轻巧微气垫质感；  
> 3. **全链路微气垫阴影与触控盒几何闭环**：`SoftShadow(button)` 各向同性 360° 微气垫完美贴合 36dp 外形，`operator="out"` 零内渗；`borderRadius` 严格等于 18dp（`diameter / 2` 实值），遵守 Android 阴影与圆角反畸变铁律。

## 一、背景与用户痛点穿透

### 1.1 用户原声与核心诉求剖析

在移动端真机体验中，用户提出了两项直击人机交互细节的敏锐反馈：

> “输入框的本地对话这个可以去掉，因为用处不大。 按钮的话，稍微小一点，现在看着好像稍微大了一丢丢。”

这两项反馈虽寥寥数语，却触及了移动界面**“信息架构自明性”**与**“手持视距下的微排版尺度感”**两大核心命题。

### 1.2 痛点一根因穿透：为什么“本地对话 · ”前缀必须彻底切除

在当前的实现中：
- 审查 `homeScreen.tsx:600-605` 与 `useLocalConversationEngine.tsx:306-308`：
  当设备处于离线本地模式且已配置供应商时，输入框 Placeholder 被拼接为：
  `'本地对话 · 点击发消息、长按语音输入'`。

```tsx
// 现状代码 (homeScreen.tsx)
placeholder={
  remoteMode
    ? '点击发消息、长按语音输入'
    : localEntry.configured
      ? '本地对话 · 点击发消息、长按语音输入'  // <-- 冗余繁琐前缀
      : '先配置本地供应商后即可对话'
}
```

深入剖析该文案带来的三重负向体验：
1. **心智割裂与重复提示**：在主界面顶部，设备选择胶囊已清晰展示“本机”或当前设备名；若未连接，通知浮层与状态看板亦已说明。输入框是用户**“采取行动（Call to Action）”**的交互视口，其 Placeholder 契约是告知用户**“如何操作”**（短按打字、长按说话），而非反复向用户强调“你现在走的是本地链路”。
2. **小屏空间灾难（截断风险）**：
   - `'本地对话 · 点击发消息、长按语音输入'` 共计 19 个中文字符 + 间隔号。
   - 按照 15px 字号（body + 1）与字间距计算，文字总宽度达到 **285dp**。
   - 在 375dp 宽度的设备上，去掉屏幕外边距 32dp（16×2）与卡内边距 20dp（10×2），输入区域仅剩 323dp。此时一旦右侧出现 36dp 的发送盘或附件按钮，占位文案尾部必然被生硬切断或引发不必要的挤压滚动。
3. **消除免责与技术防御感**：方案 10 确立的铁律明定——“界面自明，零说明书废话，不向用户解释底层架构”。去除前缀后，输入体验完全收敛，回归纯净统一。

### 1.3 痛点二根因穿透：为什么侧边栏按钮 40dp“显得大了一丢丢”

在方案 12 中，抽屉动作按钮全面恢复了 `variant="floating"` 白底微气垫，尺寸采用了当时规范中的 `theme.size.iconButton`（40dp）。

然而在抽屉面板（320dp 宽度）这一特定受限空间内，40dp 暴露了明显的排版失衡：

```
【40dp 现状布局：视觉厚重、比例失衡】
┌────────────────────────────────────────────────────────┐
│ [ 搜索会话与命令... (高40) ]   ( ⚲ 40 )   ( 🔔 40 )    │ <-- 两个40dp白圆钮横向占宽90dp，
│                                                        │     白色实体面积大，吸睛过甚
│                                                        │
│ (头像 32) 用户名                 ( ⚙ 40 )   ( ＋ 40 )    │ <-- 40dp工具钮比 32dp 主人头像大了一整圈！
└────────────────────────────────────────────────────────┘     层级颠倒，显得笨拙

【36dp 黄金微调布局：轻巧灵动、主次分明】
┌────────────────────────────────────────────────────────┐
│ [ 搜索会话与命令... (高36/40) ] ( ⚲ 36 ) ( 🔔 36 )     │ <-- 36dp 缩小19%面积，留白大幅释放，
│                                                        │     视觉重心自然归还给搜索与列表
│                                                        │
│ (头像 32) 用户名                 ( ⚙ 36 ) ( ＋ 36 )     │ <-- 36dp 与 32dp 头像形成 1:1.12 的微阶梯，
└────────────────────────────────────────────────────────┘     主次和谐，精致灵动
```

1. **与底部头像的层级倒挂**：
   - 抽屉底部通栏的 AccountAvatar 使用 `theme.size.avatarSmall = 32dp`；
   - 工具性质的设置与新建对话按钮却是 40dp。40dp 圆盘的视效面积是 32dp 的 **1.56 倍**！在视觉心理学中，这意味着工具按钮比用户本人的身份标识更具侵略性，形成了典型的“次要动作盖过主要身份”。
2. **顶部动作簇的视觉拥挤**：
   - 顶部动作簇包含扫码 `drawer-scan` 与通知 `drawer-notifications` 两个并排圆钮。
   - 两个 40dp 圆钮加上 8dp gap，总宽达到 88dp，占抽屉净宽度的近 30%，迫使 `SearchPill` 空间被严重压缩。
3. **36dp 黄金比例的优雅契合**：
   - 在移动端设计中，36dp 是著名的紧凑型操作盘尺寸（Compact Floating Disk）。在主屏输入框中，绿色发送圆盘正是严格的 **36dp**（`theme.size.sendButton = 36`），悬浮回到底部按钮也是 **36dp**（`ScrollToBottomButton`）。
   - 将抽屉动作按钮对齐至 36dp，不仅在全 App 范围内形成了更纯粹的尺寸统一，而且面积精减了 **19%**，完美消除了用户所感知的“大了一丢丢”！

## 三、方案二 · 抽屉动作按钮 36dp 微缩与几何推导

### 3.1 尺寸数值体系与触控盒几何推导

#### 3.1.1 物理尺寸与面积缩减度量
- **原尺寸 (40dp)**：
  - 直径 $D_1 = 40\text{dp}$，外接面积 $S_1 = 1600\text{dp}^2$；
  - 圆角半径 $R_1 = 20\text{dp}$；
  - 图标尺寸 $I_1 = 20\text{dp}$，图标/外径比例 $0.50$。
- **微调后尺寸 (36dp)**：
  - 直径 $D_2 = 36\text{dp}$，外接面积 $S_2 = 1296\text{dp}^2$；
  - 面积减少百分比：
    $$\Delta S = \frac{1600 - 1296}{1600} = \mathbf{19.0\%}$$
  - 这 **19% 的面积精减**恰好消除了手持视距（约 30cm）下的“大了一丢丢”感，使按钮立刻呈现出精巧雅致的微气垫形态。

```
     【40dp 结构剖面】                       【36dp 黄金微调剖面】
 ┌──────────────────────┐               ┌──────────────────┐
 │      hitSlop: 2      │               │    hitSlop: 4    │
 │   ┌──────────────┐   │               │   ┌──────────┐   │
 │   │  内衬留白 10 │   │               │   │内衬留白 9│   │
 │   │    ┌────┐    │   │               │   │   ┌──┐   │   │
 │   │    │ 20 │    │   │               │   │   │18│   │   │
 │   │    └────┘    │   │               │   │   └──┘   │   │
 │   │  外径: 40dp  │   │               │   │外径: 36dp│   │
 │   └──────────────┘   │               │   └──────────┘   │
 │   触控总热区: 44dp   │               │ 触控总热区: 44dp │
 └──────────────────────┘               └──────────────────┘
```

#### 3.1.2 触控盒无障碍无损推导（Accessibility Guarantee）
依据 Apple Human Interface Guidelines 与 W3C WCAG 2.1 AA 级可访问性规范，移动端核心触控目标物理尺寸不得小于 **44×44pt**。

`IconButton.tsx` 内部集成了自动命中盒外扩机制：
```tsx
const hitSlop = Math.max(0, (theme.size.touch - diameter) / 2);
```
- 当 `diameter = 36`，`theme.size.touch = 44`：
  $$\text{hitSlop} = \frac{44 - 36}{2} = \mathbf{4\text{dp}}$$
- React Native 的 `Pressable` 接收数字 `hitSlop={4}` 后，将在上下左右四个物理维度各外扩 4dp：
  $$\text{触控宽} = 36 + 4 \times 2 = 44\text{dp}, \quad \text{触控高} = 36 + 4 \times 2 = 44\text{dp}$$
- **结论**：视觉上微缩 19%，而实际手指触控容错率与有效命中面积保持 **100% 零衰减**，彻底兼顾了极简美学与盲操可用性。

#### 3.1.3 图标尺度与视觉对心比例
- 图标尺寸微调至 **18dp**（由 20dp 降至 18dp，`theme.size.badge = 18` 同值或使用显式 18dp 契约）：
  $$\text{比例} = \frac{18}{36} = \mathbf{0.50}$$
- 图标周围保留 $(36 - 18) / 2 = \mathbf{9\text{dp}}$ 环形充裕留白；
- 几何与视觉中心完全重合，且图标轮廓线宽（1.8~2.0）在 18dp 网格下依然具备极高锐度，绝不模糊发虚。

### 3.2 `SoftShadow` 软阴影与微气垫适配验证

在方案 12 与现行规范中，`IconButton(variant="floating")` 的层次结构为：
1. **最底层**：`SoftShadow(variant="button")`（仅 Android 浅色挂载，iOS 走 BlurView 玻璃底，深色走 surfaceRaised 台阶）；
2. **中间层**：`styles.disc` 纯白圆盘填充节点（`borderRadius = diameter / 2`）；
3. **按压层**：`Animated.View` 按压叠层（`fillPressed` + 120ms 过渡）；
4. **字形层**：`Icon` 矢量字形。

#### 3.2.1 36dp 尺寸下的软阴影物理行为
审查 `SoftShadow.tsx`：
```tsx
const PAD = 36;
const SPECS = {
  button: [
    { dy: 0, sigma: 3, alpha: 0.008 },
    { dy: 0, sigma: 8, alpha: 0.012 },
  ],
};
```
当 `diameter = 36`，传递给 `SoftShadow` 的参数为 `width={36}, height={36}, borderRadius={18}`：
1. SVG 画布尺寸自动展开为 $(36 + 36 \times 2) \times (36 + 36 \times 2) = 108 \times 108$；
2. 基础源矩形以 `x=36, y=36, width=36, height=36, rx=18, ry=18` 绘制；
3. **四周绝对均匀漫射**：近层 $\sigma=3$（扩散 6dp）与远层 $\sigma=8$（扩散 16dp）在 $dy=0$ 下呈 360° 完全同心圆扩散；
4. **内渗刚性切除（`operator="out"`）**：
   通过源形状蒙版切除后，阴影仅存在于 36dp 外部，内部透出率恒为 0，纯白实体表面零脏污、零变灰。

### 3.3 关联组件联动分析与微调方案

#### 3.3.1 顶部 `SearchPill`（搜索胶囊）协同考量

#### 3.3.2 搜索动画插值计算平滑收敛
在 `CrishDrawerContent.tsx` 中，`useActionClusterStyle` 与 `useCancelStyle` 动态控制右侧按钮的折叠与展开：
```tsx
function useActionClusterStyle(
  progress: SharedValue<number>,
  buttonSize: number, // 现传 DRAWER_ACTION_BUTTON_SIZE = 36
  gap: number         // theme.space.sm = 8
) {
  return useAnimatedStyle(() => ({
    // 展开宽度由 88dp (40*2+8) 自动平滑收敛为 80dp (36*2+8)
    width: interpolate(progress.value, [0, 1], [buttonSize * 2 + gap, 0]),
    marginLeft: interpolate(progress.value, [0, 1], [gap, 0]),
    opacity: interpolate(progress.value, [0, 1], [1, 0]),
    overflow: progress.value > 0.01 ? 'hidden' : 'visible',
  }));
}

function useCancelStyle(
  progress: SharedValue<number>,
  buttonSize: number, // 现传 DRAWER_ACTION_BUTTON_SIZE = 36
  gap: number
) {
  return useAnimatedStyle(() => ({
    // 取消叉号宽度由 40dp 自动平滑收敛为 36dp
    width: interpolate(progress.value, [0, 1], [0, buttonSize]),
    marginLeft: interpolate(progress.value, [0, 1], [0, gap]),
    opacity: interpolate(progress.value, [0, 1], [0, 1]),
    overflow: progress.value < 0.99 ? 'hidden' : 'visible',
  }));
}
```
由于 `buttonSize` 已作为参数封装，当传入 36 时，动画插值无缝自适应，无需重写任何动画状态机。

### 5.1 `CrishDrawerContent.test.tsx`：36dp 尺寸与 18dp 圆角断言

```tsx
describe('CrishDrawerContent 按钮微缩 36dp 黄金微调（方案 23 钉案）', () => {
  it('5 个核心动作按钮外径严格为 36dp，圆角为 18dp，hitSlop 补足 44dp 触控面', async () => {
    const view = await render(<CrishDrawerContent />, { wrapper: Wrapper });
    const buttonIds = [
      'drawer-scan',
      'drawer-notifications',
      'drawer-search-cancel',
      'drawer-settings',
      'drawer-new-chat',
    ];

    for (const testId of buttonIds) {
      const button = view.getByTestId(testId);
      expect(button).toBeTruthy();

      // 1. 验证外部物理轮廓严格为 36dp
      expect(button.props.style).toEqual(
        expect.arrayContaining([
          expect.objectContaining({
            width: 36,
            height: 36,
          }),
        ])
      );

      // 2. 验证 hitSlop 触控热区补足为 4dp（(44 - 36) / 2 = 4，保证无障碍触控达标）
      expect(button.props.hitSlop).toBe(4);

      // 3. 验证圆盘填充节点的 borderRadius 严格为 18dp (diameter / 2 实值，零 9999 畸变)
      const disc = button.children.find((child: any) => {
        const styles = Array.isArray(child?.props?.style)
          ? child.props.style
          : [child?.props?.style];
        return styles.some(
          (s: any) => s && s.borderRadius === 18 && s.backgroundColor
        );
      });
      expect(disc).toBeTruthy();
    }

    // 4. 验证 SearchPill 高度严格收敛为 36dp
    const pill = view.getByTestId('drawer-search-pill');
    expect(pill.props.style).toEqual(
      expect.arrayContaining([expect.objectContaining({ height: 36 })])
    );

    // 5. 验证整树零原生 elevation、零 shadow*
    const rootJson = JSON.stringify(view.toJSON());
    expect(rootJson).not.toMatch(/"elevation":/);
    expect(rootJson).not.toMatch(/"shadow(Color|Offset|Opacity|Radius)":/);
  });
});
```

### 6.2 验收基线标准 (Acceptance Criteria)

1. **文案净化无死角**：全 App 无论是未连接时的首页主输入框，还是壳内本地线程详情屏，在已配置状态下均显示干练统一的 `'点击发消息、长按语音输入'`，绝无任何 `'本地对话 · '` 历史遗留文本；
2. **尺寸收敛无违和**：抽屉面板内的 5 个动作按钮（扫码、通知、取消搜索、设置、新建对话）与搜索胶囊高度呈现一致的 36dp 优雅水平线，与底部 32dp 头像形成舒适的 1:1.12 比例，视觉笨拙感与压迫感彻底消除；
3. **触控与阴影无瑕疵**：Android 端浅色主题下 `SoftShadow(button)` 各向同性 360° 微气垫弥散平整，iOS 端 BlurView 通透轻盈；4dp `hitSlop` 使得 36dp 按钮拥有完备的 44×44dp 触控面，盲操命中率 100%；
4. **CI 门禁与单测资产 100% 绿色通行**：所有修改严格遵守架构解耦、零裸色值、零原生阴影、正圆 `R = D / 2` 守卫门禁，测试用例全部通过。
