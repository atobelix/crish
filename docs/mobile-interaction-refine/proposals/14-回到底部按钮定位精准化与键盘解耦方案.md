## 一、背景复盘与用户核心痛点

在移动端对话界面（`ConversationScreen` / `sessionDetailScreen.tsx`）的真机体验走查中，用户提出了严正且清晰的体验反馈：

> **“回到底部的定位还是有问题，明显还是忽视了底部的输入框高度。 点击输入框的时候，这个回到顶部的按钮倒是上推了，但是就这个最不应该上推了。 其他的我看都没上推。”**

这一反馈极其精准地指出了当前“回到底部”悬浮按钮（`ScrollToBottomButton`）在**几何计算**与**交互逻辑**两层面的严重缺陷：

1. **几何计算层面——双倍叠加导致推飞**：
   当用户点击输入框唤起软键盘时，按钮不仅没有停留在合适应对的位置，反而被推高到了接近屏幕中上部（300dp ~ 700dp+），与底部的输入框拉开了数百像素的巨大鸿沟，造成视觉上的严重割裂，用户直观感受到“这完全忽视了底部的输入框高度，不知道飞到哪里去了”；
2. **交互逻辑层面——打字态悬浮物违背人体工学**：
   用户点击输入框的核心意图是**专注输入与文字编辑**。此时界面其它元素（如悬浮头栏、更多菜单、边缘羽化等）均保持稳定不动，唯独输入框因为软键盘抬升而贴底升起。而“回到底部”作为一个辅助浏览历史消息的触发器，在键盘弹起时不仅强行上推，还悬挂在用户视线和输入焦点正上方，产生强烈的视觉侵扰与误触风险。

本方案针对上述痛点，进行底距真理源穿透与键盘行为解耦重构，彻底解决双倍上推、消除打字期视觉遮挡，并建立以输入框实测高度为基准的精准物理锚定。

## 二、问题深度诊断与物理几何失衡分析

### 2.1 缺陷一：双倍键盘高度叠加（按钮飞向屏幕中央）

我们穿透源码，梳理当键盘升起时的数值传递链：

```
【键盘弹起时的数值链条】
1. 硬件软键盘弹起（高度 H_kb ≈ 336dp）
   │
   ├─► JS 线程（useKeyboardHeight）:
   │     keyboardHeight 状态更新为 336dp
   │     useTimelineBottomInset 计算产出:
   │     floatingHeight = effectiveOverlayHeight + keyboardHeight
   │                    = 140dp + 336dp = 476dp
   │
   ├─► sessionDetailScreen.tsx 消费 floatingHeight:
   │     bottomOffset = floatingHeight + theme.space.sm (8dp)
   │                  = 476dp + 8dp = 484dp
   │     传给 ScrollToBottomButton 的 baseBottom = 484dp
   │
   └─► UI 线程 Worklet（useReanimatedKeyboardAnimation）:
         ScrollToBottomButton 内部开启了 followKeyboard = true
         Reanimated 读取 keyboard.height.value = -336dp
         keyboardFollowStyle 计算:
         bottom = baseBottom - keyboard.height.value
                = 484dp - (-336dp)
                = 484dp + 336dp
                = 820dp ！
```

#### 物理结果
在 844dp 高度的常见手机屏幕上，按钮的底边被直接顶到了 **820dp** 的位置（距离屏幕顶端仅剩 24dp）！不仅彻底脱离了输入框，甚至悬挂在顶部导航栏附近。

```
【现行缺陷几何示意图】
+-----------------------------------+ 屏幕顶端 (844dp)
| [Header]                         |
|  (O) <--- 按钮飞到 820dp 极高位置！ | <== 用户反馈：“不知道飞哪去了，忽视输入框高度”
|                                   |
|                                   |
|       (巨大的无效视觉空白)         |
|                                   |
|                                   |
| +-------------------------------+ |
| | [Composer 输入框] (升起高度 476dp) |
| +-------------------------------+ |
| |                               | |
| | [软键盘区域 Keyboard (336dp)]  | |
| |                               | |
+-----------------------------------+ 屏幕底端 (0dp)
```

#### 代码级证据
1. `apps/crish-mobile/src/presentation/timeline/useTimelineBottomInset.ts` 第 128 行：
   ```ts
   const floatingHeight = effectiveOverlayHeight + keyboardHeight;
   ```
   此处产出的 `floatingHeight` 明确包含软键盘高度。
2. `apps/crish-mobile/src/presentation/screens/sessionDetailScreen.tsx` 第 115-116 行：
   ```tsx
   <ScrollToBottomButton
     alignment="left"
     bottomOffset={floatingHeight + theme.space.sm}
     followKeyboard
     onPress={...}
   />
   ```
   此处将已含键盘高度的 `floatingHeight` 赋给了 `bottomOffset`，同时开启了 `followKeyboard`。
3. `apps/crish-mobile/src/presentation/ui/ScrollToBottomButton.tsx` 第 67-71 行：
   ```tsx
   const keyboardFollowStyle = useAnimatedStyle(() => {
     'worklet';
     if (!followKeyboard) return {};
     return { bottom: baseBottom - keyboard.height.value };
   });
   ```
   此处在 UI 线程又执行了一次 `baseBottom - (-keyboardHeight)`，形成了经典的 **$2 \times H_{kb}$ 双重叠加上推**。

### 2.2 缺陷二：键盘交互违背直觉（打字态悬浮遮挡与视线干扰）

用户在反馈中指出：**“点击输入框的时候，这个回到顶部的按钮倒是上推了，但是就这个最不应该上推了。 其他的我看都没上推。”**

这段话触及了移动端交互设计的核心哲学：
1. **用户心智模型的分离**：
   - **浏览态（Browsing State）**：用户手指在时间线上滑，阅读历史消息，离开底部（`follow === false`）。此时用户的意图是“阅览”，快速跳回底部的悬浮按钮是有价值的操作锚点；
   - **输入态（Typing State）**：用户轻触输入框，键盘升起。此时用户的意图 100% 转移到了“文本构思、拼音输入、选择联想词、发送消息”。用户绝对不需要在打字的同时去点击“回到底部”；
2. **界面视觉秩序的破坏**：
   - 在输入态下，屏幕空间被软键盘压缩了近 40% ~ 50%。此时时间线原本就只有上半部分可见；
   - 如果回到底部按钮随着键盘升起悬浮在输入框正上方，它会硬生生切入正在阅读的最后一条消息或思考链卡片上，造成视觉遮挡；
   - 界面中除了输入框因为要供手指打字而必须紧贴键盘顶缘外，头栏、更多操作、背景羽化等全部保持静止。回到底部按钮若跟着升起，成为屏幕中间唯一的跳动悬浮物，极为突兀。

因此，**打字态下回到底部按钮必须静默，严禁在键盘上方悬停或随键盘上推！**

### 2.3 缺陷三：静止底距基准混淆（输入框实测高度未能精准直传）

为什么用户在静态时也会感觉“明显还是忽视了底部的输入框高度”？

排查发现两点根因：
1. **参数语义混淆**：
   `useTimelineBottomInset.ts` 产出的属性中：
   - `overlayHeight`：实测或估算的有效输入区容器物理高度（不含键盘，静态高度约 140dp）；
   - `floatingHeight`：叠加了键盘高度后的动态总高度（`overlayHeight + keyboardHeight`）。
   在 `sessionDetailScreen.tsx` 中，开发者错误地使用了 `floatingHeight` 替代了本应代表静态物理高度的 `overlayHeight`。
2. **多宿主缺少标准底距**：
   在其它宿主屏幕（如 `runDetailScreen.tsx`、`terminalScreen.tsx`）中，未传 `bottomOffset` 时缺省走的是 `insets.bottom + 24dp`；而在有复杂输入框的宿主中，如果不把输入区实测的 `overlayHeight` 准确传给按钮，就会导致按钮沉入输入框内部或浮于半空。

## 三、核心架构重构与交互解耦设计

基于上述根因分析，我们制定“**键盘彻底解耦 + 静态精准锚定**”的重构架构：

```
+-----------------------------------------------------------------------------------+
|                         【新版架构状态转移与图层响应】                            |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  [时间线浏览态 (Keyboard: 0dp)]              [键盘激活打字态 (Keyboard > 0dp)]    |
|                                                                                   |
|  +-------------------------------+           +-------------------------------+    |
|  | [Header 悬浮顶栏]             |           | [Header 悬浮顶栏]             |    |
|  |                               |           |                               |    |
|  |   最新聊天流内容              |           |   可见视口消息流              |    |
|  |                               |           |                               |    |
|  | (↓) 8dp 呼吸间距              |           |                               |    |
|  | [○] 回到底部按钮 (不遮挡输入) |           | [○] 透明度 Worklet 降为 0     |    |
|  | +---------------------------+ |           |     (原地静默淡出，绝不上推)  |    |
|  | | [Composer 输入框容器]     | |           | +---------------------------+ |    |
|  | | (物理高度 overlayHeight)  | |           | | [Composer 输入框容器]     | |    |
|  | +---------------------------+ |           | +---------------------------+ |    |
|  | (insets.bottom 安全区)        |           | [ 软键盘 Keyboard 升起区 ]  |    |
|  +-------------------------------+           +-------------------------------+    |
|                                                                                   |
+-----------------------------------------------------------------------------------+
```

### 3.1 键盘解耦（Decoupled from Keyboard）：打字态静默淡出

彻底废除 `followKeyboard` 的上推逻辑。回到底部按钮采取**原地静默淡出**策略：

1. **零 Y 轴位移（Zero Y-Displacement）**：
   按钮的垂直底距 `bottom` 恒等于静态底距 `baseBottom`，不再随 `keyboard.height.value` 做任何向上平移；
2. **Worklet 驱动平滑淡出（Opacity Fadeout）**：
   利用 `react-native-keyboard-controller` 的 `useReanimatedKeyboardAnimation`，在 UI 线程监测键盘升起进度：
   - 当键盘收起时（`-keyboard.height.value === 0`），透明度为 1（正常可见）；
   - 当键盘开始弹起时，在最初的 0 ~ 40dp 极短位移内，通过插值算法将透明度平滑线性衰减至 0；
   - 当键盘完全升起时，透明度保持为 0，并且将宿主挂载 `pointerEvents="none"`，绝不拦截底层触摸事件；
3. **收起平滑恢复（Seamless Recovery）**：
   当用户完成打字、收回软键盘后，键盘高度归 0。若时间线仍未处于底部（`follow === false`），按钮平滑恢复为透明度 1，重新显现在输入框左上角；如果用户通过向下滑动时间线查看历史，`TimelineView` 的 `keyboardDismissMode="on-drag"` 会顺势收起键盘并显现按钮。

### 3.2 静态物理底距精准锚定（Precision Inset Anchor）

为消除“忽视输入框高度”的视觉失真，建立单真理源（SSOT）底距链条：

1. **输入区高度单源管理**：
   `useTimelineBottomInset` 统一产出 `overlayHeight`：
   - 挂载首帧：由两行 Composer 基础高（98dp）/ 单行高（52dp）+ 快捷条（27dp）+ 附件条（68dp）+ 错误条（48dp）+ 停止胶囊（40dp）+ 容器内边距构成的精确物理保底；
   - 布局就绪：`handleOverlayLayout` 实测回调以 0ms 滞后立即落值，消除尺寸盲区；
2. **输入框左上角上方 8dp 刚性对齐**：
   - **水平坐标（X轴）**：
     `alignment="left"`，取 `left: insets.left + theme.space.lg`（16dp）。与 `KeyboardStickyView` 内部 `paddingHorizontal: 16dp` 的输入框左侧边缘垂直共线；
   - **垂直坐标（Y轴）**：
     `bottom: overlayHeight + theme.space.sm`（`overlayHeight + 8dp`）。按钮的底边缘紧贴在输入框卡片容器顶边缘之上 8dp，呈现出规整、通透、对称的角标布局；
   - **尺寸与圆角**：
     按钮保持 Ø36dp 正圆（`BUTTON_RADIUS = 18dp`），内嵌 18dp 的 `chevron-down` 向下折角符号，符合用户先前关于“符号化、放在输入框左上角”的明确裁决。

## 四、详细代码实现与改造详案

### 4.1 `ScrollToBottomButton.tsx` 改造

#### 关键改动点：
1. **废弃 `followKeyboard` 上推计算**：废除向 `keyboardFollowStyle` 注入 `{ bottom: baseBottom - keyboard.height.value }` 的逻辑，防止双倍叠加；
2. **新增 `hideOnKeyboard` 属性（默认 true）**：在 UI 线程根据键盘逐帧高度计算 `opacity`，键盘弹起时快速淡出（40dp 阈值内衰减至 0），实现绝不上推与视线避让；
3. **保留属性兼容**：将 `followKeyboard` 标记为 `@deprecated`，保留类型接口但内部不再执行上推，确保已有调用方及老测试无感过渡。

#### 代码变更示意：
```tsx
// apps/crish-mobile/src/presentation/ui/ScrollToBottomButton.tsx

export interface ScrollToBottomButtonProps {
  onPress: () => void;
  /** 底部偏移（Tab 页传 tabBar 高度 + 安全区；详情页传 overlayHeight + 8） */
  bottomOffset?: number;
  /** 水平对齐模式：'left' 为输入框左上角（默认对齐 16dp），'center' 为通用居中 */
  alignment?: 'left' | 'center';
  /** 左侧偏移（alignment='left' 时生效，缺省为 insets.left + theme.space.lg） */
  leftOffset?: number;
  /**
   * 软键盘弹起时是否自动原地淡出隐藏（打字解耦铁律，2026-11-04 用户裁决）：
   * 键盘升起时按钮在原位平滑淡出并禁用触摸，绝不上推遮挡视觉与输入；
   * 缺省开启（true）；收起后平滑恢复。
   */
  hideOnKeyboard?: boolean;
  /**
   * @deprecated 已废弃。根据用户裁决，打字态下按钮绝不上推，统一走原地静默淡出。
   */
  followKeyboard?: boolean;
  testID?: string;
}

export function ScrollToBottomButton({
  onPress,
  bottomOffset,
  alignment = 'left',
  leftOffset,
  hideOnKeyboard = true,
  followKeyboard: _deprecatedFollowKeyboard,
  testID,
}: ScrollToBottomButtonProps) {
  const theme = useTheme();
  const insets = useSafeAreaInsets();
  const press = usePressFade();
  const keyboard = useReanimatedKeyboardAnimation();
  const baseBottom = bottomOffset ?? insets.bottom + 24;
  const baseLeft = leftOffset ?? insets.left + theme.space.lg;

  const hitSlop = Math.max(0, (theme.size.touch - BUTTON_SIZE) / 2);

  const handlePress = useCallback(() => {
    haptics.tap();
    onPress();
  }, [onPress]);

  // 键盘解耦动效 Worklet：键盘升起时原地淡出至 0，绝不上移推高；收起后恢复
  const keyboardFadeStyle = useAnimatedStyle(() => {
    'worklet';
    if (!hideOnKeyboard) return {};
    // keyboard.height.value <= 0 (0 = 完全收起, -336 = 完全升起)
    // 在键盘弹起最初 40dp 范围平滑插值淡出
    const kbHeight = -keyboard.height.value;
    const opacity = kbHeight <= 0 ? 1 : Math.max(0, 1 - kbHeight / 40);
    return {
      opacity,
    };
  });

  const positionStyle: ViewStyle =
    alignment === 'left'
      ? { bottom: baseBottom, left: baseLeft }
      : { bottom: baseBottom, alignSelf: 'center' };

  return (
    <Animated.View
      entering={FadeIn.duration(theme.motion.duration.fast)}
      exiting={FadeOut.duration(theme.motion.duration.snappy)}
      style={[styles.host, keyboardFadeStyle]}
      pointerEvents="box-none"
    >
      <AnimatedPressable
        testID={testID}
        accessibilityRole="button"
        accessibilityLabel="回到底部"
        accessibilityHint="双击立即快速滚动到消息流最底部"
        hitSlop={{
          top: hitSlop,
          bottom: hitSlop,
          left: hitSlop,
          right: hitSlop,
        }}
        onPress={handlePress}
        onPressIn={press.onPressIn}
        onPressOut={press.onPressOut}
        style={[
          styles.button,
          positionStyle,
          press.fadeStyle,
        ]}
      >
        <SoftShadowSurface
          preset="button"
          width={BUTTON_SIZE}
          height={BUTTON_SIZE}
          borderRadius={BUTTON_RADIUS}
          fill={theme.colors.surfaceRaised}
          fillStyle={styles.surfaceFill}
        >
          <Icon
            name="chevron-down"
            size={18}
            color={theme.colors.textPrimary}
          />
        </SoftShadowSurface>
      </AnimatedPressable>
    </Animated.View>
  );
}
```

### 4.2 `sessionDetailScreen.tsx` 改造

#### 关键改动点：
1. 从 `useTimelineBottomInset` 解构出代表纯物理浮层高度的 `overlayHeight`；
2. 将 `<ScrollToBottomButton>` 的 `bottomOffset` 由 `floatingHeight + theme.space.sm` 修正为 `overlayHeight + theme.space.sm`；
3. 移除 `followKeyboard` 传参，由组件内置的打字态淡出逻辑接管。

```tsx
// apps/crish-mobile/src/presentation/screens/sessionDetailScreen.tsx

  const {
```
