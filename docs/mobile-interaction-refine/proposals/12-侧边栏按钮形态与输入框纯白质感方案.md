# 12-侧边栏按钮形态与输入框纯白质感方案

> **所属战役**：移动端交互与转场体验攻坚（Mobile Interaction Refinement）  
> **涉及模块**：  
> - 抽屉面板：`apps/crish-mobile/src/presentation/components/drawer/CrishDrawerContent.tsx`  
> - 核心输入框：`apps/crish-mobile/src/presentation/ui/Composer.tsx`  
> - 图标按钮基元：`apps/crish-mobile/src/presentation/ui/IconButton.tsx`  
> - 软阴影渲染基元：`apps/crish-mobile/src/presentation/ui/SoftShadow.tsx`  
> - 规范门禁与单测：`styleTokens.guard.test.ts`、`noShadow.guard.test.ts`、`roundButton.guard.test.tsx`、`CrishDrawerContent.test.tsx`、`uiComposer.test.tsx`、`uiPrimitives.test.tsx`  
> **用户核心反馈**：  
> “侧边栏的按钮怎么没有颜色了呢。 输入框应该是白色的呀。”  
> **核心修复原则**：  
> 1. **侧边栏按钮（Drawer Action Buttons）**：彻底纠偏误伤的 `variant="plain"`，全面恢复为 `variant="floating"`，还原白底圆盘（`#fdfdfd` 叠色合成）、`SoftShadow` 360° 微气垫软阴影与 120ms 丝滑按压反馈；  
> 2. **核心输入框（Composer Card）**：在浅色模式下强制锁定卡体为纯净纯白实体（`#ffffff` / `theme.colors.surface`），完全剥离 iOS 浅色下的 `BlurView` 磨砂与 `surfaceTranslucent` 半透明混色，杜绝底层图层与文字模糊穿透发灰；同时优化极柔微描边与 `SoftShadow(composer)` 微气垫漫反射；  
> 3. **抽屉搜索胶囊（Drawer SearchPill）**：同步纠偏为纯白微浮雕形态，消除灰暗下沉凹槽感；  
> 4. **铁律守门**：100% 遵守 `styleTokens`、`noShadow` 与 `roundButton` 守卫门禁，测试资产零回退。

## 一、背景与问题根因穿透

### 1.1 侧边栏动作按钮退化复盘（“侧边栏的按钮怎么没有颜色了呢”）

在先前的抽屉顺滑度与轻量化改动中，设计意图本是落实用户对会话列表的裁决：“展开后的抽屉每一个选项都不用加上背景色的”（针对 `SessionListItem` / `LocalSessionListItem` 的 `fillSelected` 浅灰条目色块）。

然而，在执行过程中产生了**过度修剪与语义扩大**：
- 审查 `CrishDrawerContent.tsx` 历史提交（`3ed413c` -> 现行代码）：
  - 顶部动作簇：扫码按钮 `drawer-scan`、通知中心按钮 `drawer-notifications`、搜索取消按钮 `drawer-search-cancel`；
  - 底部动作簇：设置按钮 `drawer-settings`、新建对话按钮 `drawer-new-chat`；
  - 上述 5 个核心交互按钮被无差别改写为了 `variant="plain"`！
- **病态表现**：
  - `variant="plain"` 模式下，`IconButton` 不绘制任何背景节点（`discFill` 未渲染），仅绘制孤立的矢量图标字形；
  - 在抽屉底板 `canvasDrawer`（`#f0f0f0` / `#f5f5f5`）灰色调衬托下，顶部与底部的控制按钮退化为悬浮在空中的“光秃秃黑标”，失去了操作实体感、层次落差与按压气垫感；
  - 用户真机视感极为突兀，即刻反馈：“**侧边栏的按钮怎么没有颜色了呢**”。


### 1.2 输入框色彩与质感退化复盘（“输入框应该是白色的呀”）

用户在主界面或会话流中看到输入框时明确指出：“**输入框应该是白色的呀**”。
排查 `Composer.tsx` 的外壳渲染逻辑：

```tsx
// Composer.tsx (现状)
const glassActive = Platform.OS === 'ios' && !reduceTransparency && !locked;

<View
  style={[
    styles.shell,
    {
      backgroundColor: glassActive
        ? colors.surfaceTranslucent // 'rgba(255, 255, 255, 0.78)'
        : colors.surface,           // '#ffffff'
      overflow: glassActive ? 'hidden' : 'visible',
      ...
    }
  ]}
>
  {glassActive ? (
    <BlurView
      intensity={40}
      tint={theme.dark ? 'dark' : 'light'}
      style={styles.glassFill}
      pointerEvents="none"
    />
  ) : null}
  ...
</View>
```

深入分析导致输入框“不纯白、发灰、发脏”的三重物理根因：

1. **iOS 浅色端：`glassActive` 误伤导致 78% 半透混色与模糊穿透**：
   - 在 iOS 平台上，只要不是锁定态且未开启减透明度，`glassActive` 恒为 `true`；
   - 此时 `backgroundColor` 采用 `colors.surfaceTranslucent`（`rgba(255, 255, 255, 0.78)`），并挂载 `BlurView(intensity=40, tint='light')`；
   - **底板混色污染**：在主屏上，输入框下方是底色 `#f4f4f4` 的画布，`0.78` 的白底与底板混色后直接降为约 `#f9f9f9`，失去了纯白质感；
   - **内容穿透污染**：在会话详情屏（`sessionDetailScreen`）中，用户向上滚动时间线时，聊天气泡（深灰色用户气泡、代码块、警告色块等）从输入框背后滑过，`BlurView` 将这些杂乱图层模糊混入输入卡内部，使得输入框表面出现斑驳发脏的灰暗杂质，**绝无“纯白通透”的可读性**！
2. **Android 端：`overflow` 冲突与阴影弥散受阻**：
   - `overflow: glassActive ? 'hidden' : 'visible'`。若未来误开 `glassActive`，会导致 Android `SoftShadow` 被裁减；
   - 在浅色模式下，输入框本身需要一个完全不透明、坚实厚实的纯白背景，作为前景文字与底层动态列表的绝对视觉隔离层；
3. **侧边栏内的搜索输入胶囊（`SearchPill`）同步失色**：
   - `CrishDrawerContent.tsx` 中 `SearchPill` 在浅色模式下被硬编码为 `rgba(0, 0, 0, 0.03)`（微凹槽质感）；
   - 在侧边栏的上下文中，用户对输入框的期待同样是整洁、清晰的白底，灰暗沉陷的凹槽更显得抽屉面板没有精神。

## 二、架构契约与设计系统守卫保障

本方案严格遵守 Conex 项目建立的样式门禁和防回潮铁律，杜绝任何补丁式修补：

### 2.1 样式令牌单一真源（`styleTokens.guard.test.ts`）

- **严禁裸值**：卡体纯白必须取自 `theme.colors.surface`（在 `lightTheme` 与 `neutralTheme` 中严格锁定为 `#ffffff`），不得手写任何 `#ffffff` 或 `#fff` 裸 hex 字面量；
- **描边令牌**：深色模式使用 `theme.colors.borderStrong`（`#2c2c2c`），浅色模式使用微弱柔和描边（`rgba(0, 0, 0, 0.025)` 或 `theme.colors.hairline`）；
- **圆角令牌**：输入框圆角使用 `theme.radius.composer`（30），禁止数字圆角字面量；按钮圆盘使用 `diameter / 2`。

### 2.2 原生阴影全面禁绝（`noShadow.guard.test.ts`）

- **零原生阴影**：严禁出现 `elevation`、`shadowColor`、`shadowOpacity`、`shadowRadius`、`shadowOffset` 或 `.shadow` 成员访问；
- **SoftShadow 是全 App 唯一合法阴影**：
  - 侧边栏按钮（`IconButton` floating 档）：消费 `SoftShadow(variant='button')`，近层 `dy: 0, sigma: 3, alpha: 0.008`，远层 `dy: 0, sigma: 8, alpha: 0.012`；
  - 输入框（`Composer`）：消费 `SoftShadow(variant='composer')`，近层 `dy: 0, sigma: 3, alpha: 0.01`，远层 `dy: 0, sigma: 8, alpha: 0.014`；
  - **内渗切除（operator="out"）**：通过源形状 Alpha 蒙版将投影严格切除于轮廓之外，保证纯白卡体内部零阴影内渗、零发灰。

### 2.3 圆形按钮契约（`roundButton.guard.test.tsx`）

- `IconButton` 圆盘结构：圆角一律为 `diameter / 2` 实值（如 40dp 按钮圆角严格为 20dp，38dp 按钮圆角严格为 19dp），禁用 `radius.pill (9999)`，根除 Android 八边形畸变；
- floating 按钮层次：底层独立渲染 `discFill`（Android 浅色走 `rgba(255, 255, 255, 0.82)`，叠在 `#f0f0f0` 抽屉底合成 `#fdfdfd` 白圆盘），表层独立叠加 `pressOverlay` 120ms 过渡，外溢底层挂载 `SoftShadow`。

## 三、方案详细设计与实施路径

### 3.1 侧边栏按钮形态全面复原（`CrishDrawerContent.tsx`）

将抽屉中的五个核心控制按钮全面由 `variant="plain"` 纠正为 `variant="floating"`：

| 按钮标识 (`testID`) | 语义角色 | 纠偏前形态 | 纠偏后形态 | 尺寸规范 | 视觉质感 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `drawer-scan` | 扫码配对 | `plain` (无底色) | `floating` (白底悬浮) | Ø40 (`theme.size.iconButton`) | 白底圆盘 + SoftShadow 微气垫，按压淡灰过渡 |
| `drawer-notifications` | 通知中心 | `plain` (无底色) | `floating` (白底悬浮) | Ø40 (`theme.size.iconButton`) | 白底圆盘 + SoftShadow 微气垫，支持未读小红点 |
| `drawer-search-cancel` | 取消搜索 | `plain` (无底色) | `floating` (白底悬浮) | Ø40 (`theme.size.iconButton`) | 搜索展开时滑出的白底圆形叉号钮 |
| `drawer-settings` | 系统设置 | `plain` (无底色) | `floating` (白底悬浮) | Ø40 (`theme.size.iconButton`) | 底部通栏左侧控制钮，白底圆盘微气垫 |
| `drawer-new-chat` | 新建对话 | `plain` (无底色) | `floating` (白底悬浮) | Ø40 (`theme.size.iconButton`) | 底部通栏右侧控制钮，白底圆盘微气垫 |

#### 3.1.1 动画容器溢出配合
在 `CrishDrawerContent.tsx` 中，`useActionClusterStyle` 针对动作按钮簇定义了动态裁剪：
```tsx
function useActionClusterStyle(
  progress: SharedValue<number>,
  buttonSize: number,
  gap: number
) {
  return useAnimatedStyle(() => ({
    width: interpolate(progress.value, [0, 1], [buttonSize * 2 + gap, 0]),
    marginLeft: interpolate(progress.value, [0, 1], [gap, 0]),
    opacity: interpolate(progress.value, [0, 1], [1, 0]),
    // 常态时保持 visible 确保 SoftShadow 扩散光晕不被裁剪，搜索动画进行中开启 hidden 平滑收拢
    overflow: progress.value > 0.01 ? 'hidden' : 'visible',
  }));
}
```
恢复 `variant="floating"` 后，常态下的 `overflow: 'visible'` 能够无缝释放 `SoftShadow` 在 40dp 按钮四周各 `36dp` 出血区的均匀漫反射气垫光晕。

#### 3.1.2 搜索胶囊（`SearchPill`）质感同步提升
将 `SearchPill` 的底色从发灰的凹槽 `rgba(0, 0, 0, 0.03)` 调整为符合浅色模式预期的纯白微浮雕胶囊：
- 浅色模式：`backgroundColor: theme.colors.surface`（`#ffffff`）；
- 深色模式：`backgroundColor: theme.colors.surfaceRaised`（`#242424`）；
- 结合原有的 `SoftShadow(pillHeight / 2)`，使抽屉顶部的搜索框与两侧的白圆钮融为一体，彻底消灭“灰脏感”。

### 3.2 输入框（`Composer.tsx`）纯白通透质感重塑

#### 3.2.1 浅色模式强制纯白实体（Force Opaque Pure White）
在 `Composer.tsx` 中，对 `glassActive` 的激活条件进行严格的主题收敛：

```tsx
// 仅在深色模式且 iOS 环境下保留玻璃质感；浅色模式下强制禁用 glassActive！
// 浅色模式下输入框必须是坚实、纯净的纯白实体（#ffffff / colors.surface），杜绝图层混合发灰发脏
const glassActive =
  Platform.OS === 'ios' && !reduceTransparency && !locked && theme.dark;
```

#### 3.2.2 卡体外壳样式（`styles.shell`）属性推导收敛
卡体外壳的样式属性由分散的条件三目运算符收敛为单一真理表：

```tsx
<View
  onLayout={handleCardLayout}
  collapsable={false}
  style={[
    styles.shell,
    {
      minHeight: size.composerMin,
      borderRadius: radius.composer,
      // 浅色模式绝对纯白实色（#ffffff）；深色模式在 iOS 下走半透明，Android 下走实色表面
      backgroundColor: theme.dark
        ? (glassActive ? colors.surfaceTranslucent : colors.surface)
        : colors.surface,
      // 描边层次：浅色走 2.5% 超微极柔边（与白底融为一体且勾勒微边界）；深色走 borderStrong
      borderWidth: 1,

      paddingVertical: twoRow ? 10 : space.sm,

    },
  ]}

    <MemoSoftShadow
      width={cardSize.width}
      height={cardSize.height}
      borderRadius={radius.composer}
      variant="composer"
    />
  ) : null}

  {/* BlurView 磨砂仅在深色模式下的 iOS 渲染，浅色模式下完全不挂载！ */}
  {glassActive ? (
    <BlurView
      intensity={GLASS_BLUR_INTENSITY}
      tint={theme.dark ? 'dark' : 'light'}
      style={styles.glassFill}
      pointerEvents="none"
    />
  ) : null}
  ...
</View>
```

#### 3.2.3 物理质感多维提升解析

1. **绝对纯白实心（100% Solid Pure White）**：
   - 浅色模式下卡体 `backgroundColor` 恒为 `theme.colors.surface`（`#ffffff`）；
   - 背景层具有 100% 遮光能力，不管时间线中如何高速滚动长文本、深色气泡或高对比图片，输入框永远是干净整洁的纯白画布；
2. **零模糊噪点（Zero Blur Artifacts）**：
   - 浅色模式下彻底卸载 `<BlurView>` 组件；
   - 杜绝 iOS 系统原生 UIVisualEffectView 在滚动时产生的 GPU 采样抖动和混色脏斑，同时节省一个全屏渲染通道；
3. **空气浮雕微气垫（Air Micro-Cushion Dispersion）**：
   - 在 Android 浅色下，`SoftShadow(variant='composer')` 通过双层各向同性高斯模糊（近层 σ3 α0.010，远层 σ8 α0.014）向四周漫射；
   - 配合 `overflow: 'visible'`，投影在 `#f4f4f4` 的画布上泛出肉眼仅隐约可见但极为高级的微浮雕气垫感；
   - 内渗切除保证卡体内部绝对纯白，边缘没有任何黑斑内渗；
4. **克制温润的边缘微描边（Subtle Stroke Boundary）**：
   - `borderColor: 'rgba(0, 0, 0, 0.025)'`，透明度仅 2.5% 的黑度微痕；
   - 既保证了在白色底板或高亮场景下输入框轮廓的清晰可辨，又完全杜绝了厚重黑环的压迫感。
