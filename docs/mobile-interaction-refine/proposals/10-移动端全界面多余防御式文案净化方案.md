# 10-移动端全界面多余防御式文案净化方案

> **所属战役**：移动端交互体验与视觉轻量化（Mobile Interaction Refinement）  
> **目标模块**：`apps/crish-mobile`（全端各 Sheet、抽屉会话列表、状态横幅、设置面板、对话流与空态界面）  
> **核心痛点**：用户点名批评移动端多界面充斥“防御式辩解废话”与“保姆式技术说明说明书”，严重违背移动端轻量、克制、高效、直觉的信息架构原则。  
> **设计基准**：iOS Human Interface Guidelines / Material Design 3 / 极简克制 / 视觉纯粹 / 零免责甩锅口吻。

---

## 一、背景与用户痛点溯源

### 1.1 用户裁决与点名批评

在多端协同演进过程中，部分组件开发者为了“向用户解释内部架构边界”、“厘清技术责任”、“规避远程与本地行为差异的咨询”，在移动端多个 Sheet 底部、列表副标题、帮助弹窗中塞入了大量**长篇防御式技术辩解文字**。

用户对此提出了严正批评并下达明确指令：
> “以及我抽屉界面还有几个界面有多余的文字，这种的需要净化掉。  
> `这里切换的是手机本地对话使用的模型（本机供应商配置），与桌面端的全局默认模型无关。`  
> `通过手机远程发起的任务，桌面端会按其安全规则执行：选择「完全允许」时，桌面会以「每次询问」的方式逐条确认；其余档位按所选模式执行。`  
> 这些文字光废话，不要这种防御式的辩解文字说明，这种类似的都可以清理掉，所有界面都要详查并分析如何清理才行。”

### 1.2 为什么“防御式文案”是移动端体验毒药

在移动端（手持设备）人机交互中，屏幕物理纵向与横向空间极为受限，用户心智模型追求的是**“直接交互、直观反馈、即刻行动”**。

当前存量代码中蔓延的防御式文案存在四大核心公害：

```
                 ┌─────────────────────────────────────────────────────────┐
                 │                   防御式文案四大体验公害                 │
                 └─────────────────────────────────────────────────────────┘
                                              │
         ┌──────────────────┬─────────────────┴────────────────┬──────────────────┐
         ▼                  ▼                                    ▼                  ▼
   【免责甩锅感】     【挤占垂直空间】                     【增加心智认知负担】   【破坏视觉高级感】
   向用户陈述“架构    Sheet 底部凭空增加                   用户仅想选个模型，     大段灰字注脚像
   规则与我无关”      30~60px 纯废话高度，                 却被迫阅读 50 字       软件未完成的“补丁
   “降级由桌面负责”，  导致内容被挤压出视口，               网关调度与本地/远程    说明书”，破坏
   充斥开发者的责任    在小屏机上触发不必要的               对比逻辑，令人烦躁。   极简优雅的设计
   防御与免责感。      折叠与滚动。                                               纯粹性。
```

1. **免责甩锅感强**：如 `PermissionModeSheet` 的“通过手机远程发起的任务，桌面端会按其安全规则执行...”，完全是开发人员把网关 `apply_remote_mode` 的后端策略推卸给终端用户；
2. **挤占宝贵空间**：如 `LocalModelSheet`、`ModelSheet`、`SkillsSheet`、`DeviceSheet`，每个底部都硬塞一段 3~4 行的 Tertiary 灰色长句，导致原本中等尺寸的 Sheet 变高，在小屏手机上直接撑满甚至引发滚动；
3. **增加心智认知负担**：用户进入模型选择页只想挑一个模型，根本无需在此刻被动接受“本地模型配置 vs 桌面全局模型”的长篇架构科普；
4. **破坏纯粹的视觉质感**：大段灰字如同软件使用说明书的免责条款，破坏了无描边、软阴影、高呼吸感的现代 UI 质感。

## 二、文案净化四大设计原则

针对全端文案减负与信息架构净化，确立以下刚性原则：

| 原则 | 核心内涵 | 执行标准 | 典型对照 |
| :--- | :--- | :--- | :--- |
| **原则 1：坚决杜绝免责辩解** | 消除任何提及“与桌面无关”、“按其安全规则降级”、“以此处为准”等技术免责文字。 | 凡属架构技术辩解、网关策略说明、责任边界声明，**一律 100% 物理删除**。 | 删 `LocalModelSheet` 底部注脚<br>删 `PermissionModeSheet` 底部安全降级注脚 |
| **原则 2：界面自明，零说明书废话** | UI 控件（列表行、对号、开关、胶囊）本身具备自解释性，不需要保姆式文字教用户如何使用。 | 凡属“点选即可切换”、“点按设为默认”、“失败不影响手填”等操作废话，**直接删除**。 | 删 `DeviceSheet` 操作指南注脚<br>删 `LocalProviderEditView` 手填提示 |
| **原则 3：直接给结论，不解释技术底层** | 遇到状态或异常，直接告知用户当前状态与可行出路，不堆砌底层协议与工作原理。 | 将“附件会随消息发送到电脑执行，本地对话暂不支持附件”等长句**提炼为 6~10 字直接陈述**。 | 优化为 `本地对话暂不支持附件`<br>优化为 `端侧识别` |
| **原则 4：释放垂直留白，视觉纯粹回归** | 删除多余文字后，收敛相关的外边距（`marginTop`）与内衬，使组件回归紧凑舒展。 | 消除因长注脚造成的 Sheet 高度冗余，让弹窗更轻、层级更浅、视觉焦点更聚焦。 | 各 Sheet 底部高度减少 30~50px，小屏设备不再触发溢出滚动。 |
