# 移动端功能补全 · 全流程方案（二期）

> 前置：一期抽屉改版已提交（`feat(mobile): 抽屉改版一期…`）。
> 用户裁决（2026-11-01）：**除「语言」「触感反馈」外，原型功能全部做完**——附件、语音、模型选择、项目选择、权限模式、字体与字号；允许改桌面端与协议；不做半成品；完成后提交代码并经 Actions 构建 APK。
> 本文档 = 调研结论（含文件:行号证据）+ 波次执行方案。**无任何「跳过」项**；每个原 предполож mock 功能都有真实落地路径。

## 0. 调研结论（事实底座）

### 0.1 设备网关 = REST + WS 事件流
- 路由表：`apps/agent-workbench/src-tauri/src/server/router/mod.rs:162-222`——`POST /v1/runs`（run_task）、`GET/PUT /v1/settings`、`GET /v1/assets/url`（**501 占位**，handlers_write.rs:212）、WS `/v1/events`（事件流）。鉴权 = Bearer + 签名请求中间件。
- run 处理链：`handlers_write.rs:22 handle_run_task` → `core_backend/api.rs:201 run_task` → `core_backend/state.rs:200 execute_run_task` → `RunTaskOptions`（`crates/conex-run/src/run/run_launch.rs:703`）→ `run_task_impl`。

### 0.2 引擎已支持多模态（附件地基已存在）
- `RunTaskOptions.content: Option<serde_json::Value>`（OpenAI 形 parts，`type: image_url`）+ `has_images`（run_launch.rs:769-777）；注释明确「远程 run 不携带多模态 content（无桌面附件通道）」——**缺的只是远程传输面，引擎消费路径现成**。
- 桌面本地已在用：`apps/crish-desktop/src/api/chat-bridge/streamSession.ts:92-97`（`hasImages` 由 content parts 判定）。
- 设备协议 `RunTaskParams`（`packages/shared-types/src/generated/device/types.ts:613`）现无 content 字段 → 二期补。
- prompt 256KiB 上限（state.rs:211）；协议 `prompt_ref`（run_settings_device.rs:22）为规划中流上传（**未实现**，本期不依赖）。

### 0.3 权限模式：远程安全不变量
- `PermissionMode = ask | smart | full`（shared-types generated/device/types.ts:37）。
- **远程 full 恒降级 ask + 审计**（state.rs:235-241 `apply_remote_mode`，D5 §4.6.1 / TH-12）——引擎级安全裁定，保留。
- ⇒ 移动端权限选择器真实可选集 = **ask（标准审批）/ smart（快速放行）**；full 不提供（诚实：远程无完全访问）。原型「严格沙盒」在协议中不存在 → 不做假选项。

### 0.4 项目 / 工作区语义
- 桌面项目 = `ProjectEntry { id, name, path }`（`apps/crish-desktop/src/api/projectStore.ts:24-30`，localStorage `crish_projects_v1`）；打开项目 = 设工作区 cwd；会话 `folder` 绑 projectId（projectStore.ts:12）。
- 桌面发起 run：`streamSession.ts:89-97,158-165`——`cwd = getWorkspacePath()`、`permissionMode = getPermissionMode()` 注入 `RunTaskParams`；远程面 `cwd` 已透传（state.rs:258）。
- 后端有工作区注册面：`workspace.rs:13 allow_registered_workspace_roots` + `asset_scope.rs`（资产域 scope）——项目清单数据源在实现时落定为「桌面同步上报」（见 W-B 设计）。

### 0.5 模型选择链
- 真源 = **models.yaml 树**：桌面 `modelsCatalogStore`（api/modelsCatalogStore.ts）经 Tauri IPC `models_yaml.rs`（read/save/validate）读写；活跃模型 = 树 `activeModel`（`setActiveModel`）。引擎 run 按引擎侧读取的 active 模型执行（RunTaskOptions 无 model 字段——模型非 run 级）。
- ⇒ 移动端模型选择 = 远程读写 models.yaml 的 activeModel（新增两个设备端点，与桌面全局语义一致）。

### 0.6 CI / APK
- `.github/workflows/mobile-ci.yml`：push/PR（paths: `apps/crish-mobile/**`、`packages/shared-*`、本文件）+ `workflow_dispatch`；job `mobile-build-apk` = npm ci → build:packages → **`npx expo prebuild --platform android --clean --no-install`** → `gradlew assembleRelease (arm64-v8a)` → upload-artifact `crish-mobile-release-apk`。
- **prebuild 在 CI 内 clean 重生成** ⇒ 新增原生依赖 / app.json 插件 / 字体资源随 `package.json`/`app.json` 提交即可进构建，无需维护 android/ 产物。

### 0.7 移动端既有基建
- `expo-image-picker` 已装（账号头像在用）；`expo-camera` 已装（扫码）；`react-native-gesture-handler` + Reanimated 齐备（SlideToConfirm 为长按/拖动手势参照）；`useKeyboardHeight` 现成。
- 需新增依赖：`expo-document-picker`（文件）、`expo-speech-recognition`（语音 STT，社区库 jamsch/expo-speech-recognition）、`expo-font` + `@expo-google-fonts/jetbrains-mono` + `@expo-google-fonts/fira-code`（等宽字体真源）。

## 1. 波次方案

### W-A 字体与字号（纯移动端，先行热身）
1. `settingsStore` appearance 组新增 `fontScale: 'standard'|'large'|'xlarge'`（1 / 1.125 / 1.25）与 `monoFont: 'system'|'jetbrains'|'fira'`（持久化沿用既有机制）。
2. `theme.ts`：`type` 由固定常量改为按 `fontScale` 生成（`buildTheme` 增参，浅深结构不变，theme.test 结构断言保持）；`mono` 的 fontFamily 按 `monoFont` 选择（google fonts 加载成功前回落系统等宽）。
3. 根布局 `expo-font` 预载两款字体（加载期由原生 Splash 覆盖，无中间帧）。
4. 设置页新增「字体与字号」行 → `/settings-font` 子页：正文字号 3 选 + 等宽字体 3 选，真实生效（对齐原型 subFont）。
5. 测试：settings reducer 往返、theme 按 scale 生成、字体子页选择交互。

### W-B 权限模式 / 项目选择 / 模型选择（协议接入，Composer 顶部控制条回归）
1. **Composer 顶部控制条**（原型 composer-top-controls）：主屏与 composer 上方恢复两枚透明小胶囊——项目 chip（Folder 图标+项目名+下箭头）与权限 chip（Shield 图标+模式名+下箭头）；点按各自弹 Sheet。模型选择放会话页 composer 展开区（原型 model-select 位置），主屏不放（保持极简）。
2. **权限模式**：settingsStore 增 `permissionMode: 'ask'|'smart'`（默认 ask）；`runTaskParamsOf`（useQuickRunVm.ts:56）改为读取设置（更新 R2-07 B4 注释为新裁决）；Sheet 双选 + 「远程不支持完全访问」说明行。
3. **模型选择**：
   - 桌面后端新增设备端点：`GET /v1/models`（清单：provider 分组 + activeModel，读 models.yaml）与 `POST /v1/models/active`（切换 activeModel，复用 `models_yaml.rs` 校验保存链）。协议 crate（conex-device-protocol）+ shared-types parser + ServerState backend + 路由注册。
   - 移动端：`ModelsSheet`（按 provider 分组 + 对号），切换后 Toast 反馈；会话页 composer 展开区显示当前模型 chip。
4. **项目选择**：
   - 桌面后端新增 `GET /v1/workspaces`：返回已注册工作区清单（`workspace.rs` 注册面 + 名称 = 目录 basename）与当前 active 标记。
   - 移动端：项目 chip → `ProjectsSheet`（清单 + 对号）；选中项写入移动端 settingsStore；发起 run 时 `RunTaskParams.cwd` 显式携带所选工作区路径（远程协议 cwd 本就是绝对路径语义，与桌面同构）。不新增「新建项目」（目录创建属桌面文件系统能力，移动端诚实缺省——原型该入口映射为「扫码添加新设备」已有的连接语义）。

### W-C 附件（拍照 / 照片 / 文件）
1. **协议**：`RunTaskParams` 增 `content?: JsonValue`（OpenAI parts，仅 image_url data URL）+ `hasImages?: boolean` + `attachments?: [{name, mime, dataBase64}]`（非图文件）；serde Option+default 向后兼容；shared-types parser + `run_settings_device.rs` + `state.rs` 透传（删除 content/has_images 的 None 硬编码注释）。
2. **桌面后端**：
   - content/hasImages 直通 RunTaskOptions（引擎现成路径）。
   - attachments 落盘：`execute_run_task` 内将每个附件解码写入 `.crish-uploads/<sessionId>/`（conex-fs 域），并在 prompt 末尾追加「附件已落盘」路径清单（工具可读）；单附件 ≤ 4 MiB、总 ≤ 8 MiB、数量 ≤ 4，超限 CmdInvalid 诚实报错。
3. **移动端**：
   - Composer 增「+」钮 → `AttachmentSheet`（拍照 / 照片 / 文件 三卡，对齐原型 action-grid-3）：`launchCameraAsync` / `launchImageLibraryAsync`（quality 0.7、maxWidth 1600 压缩）/ `launchDocumentAsync`（新增 expo-document-picker）。
   - 选中附件以 chip 行预览（可删）；提交时图片 → base64 data URL 组装 `content`（≤4 张）；文件 → `attachments`。
   - jest：picker/document-picker/speech 模块 mock（jest.setup.ts 模式扩展）。

### W-D 语音输入（按住说话）
1. 依赖：`expo-speech-recognition`（Android SpeechRecognizer；RECORD_AUDIO 运行时权限由库内请求）；`app.json` plugins 登记。
2. 交互（原型 voice-recording-overlay）：Composer 麦克风钮**长按**开始识别（LongPress + 手动激活，参照 SlideToConfirm 的手势仲裁）；浮层显示五条波形动画 + partial 实时文本 + 「松开发送，上滑取消」；**上滑取消**（位移阈值）→ 停止并丢弃；松开 → 取最终 transcript：非空 → 填入 composer 并触发提交（与原型「松开发送」一致），空/失败 → Toast 诚实反馈。
3. 状态机纯函数（idle/recording/cancelling/finishing）独立可测；识别错误（无权限/不可用）→ Toast + 回落打字。
4. 主屏与会话页 Composer 共用同一组件能力。

### W-E 收口与发布
1. 全量验证：mobile `typecheck + jest`；desktop `tsc -b` + 改动面 vitest；Rust `cargo check`（改动 crates）+ 相关 `cargo test`；仓库门禁脚本（convergence / i18n / guard）。
2. 分波提交（每波独立 commit，`git commit --only` 限定路径）。
3. push 触发 `mobile-ci.yml`（或 `workflow_dispatch`）→ 下载 `crish-mobile-release-apk` Artifact 验证构建绿。**CI 内 prebuild --clean**，新增原生依赖自动进包。
4. 方案文档收尾：本文件补「执行实录」段（实际改动清单 + 测试结果）。

## 2. 裁决与边界（诚实化）
- 「严格沙盒」：协议无此模式 → 不做假选项（ask/smart 真实二档）。
- full 模式：引擎远程恒降级（安全不变量）→ 移动端不提供，Sheet 内说明。
- 「新建项目」：目录创建属桌面侧本地能力 → 移动端不提供假入口。
- 「语言 / 触感反馈」：用户裁决暂不做。
- prompt_ref 流上传：协议有位、实现未落地 → 本期附件走 base64 内联 + 尺寸钳制，不依赖未实现的流通道；超大附件诚实报错。
