# Conex / Crish — Markdown 渲染系统性整改行动方案

> **战役工作区**：`docs/markdown-rendering-analysis/`
> **文档定位**：整改总方案（SSOT），承接 `00-全景评估与缺陷总述.md` 与 `analysis/01~06`
> **审查基准**：当前仓库源码事实（2026-10-28）；不以文档宣传口径、也不以 `reference/` 原型能力作为交付依据
> **核心原则**：两张渲染面、每面一个渲染器、Islands 扩展、非必要不兼容、先删后建、批量测试
> **效果锁**：不得把本方案降级为「保留旧回退 / 只修样式 / 只补几个语法」的简化版；若与现有锁定冲突，只标出并请示，不自行改目标

## 0. 结论先行

### 0.1 对分析报告的总体裁决

分析报告**代码级事实约八成成立**，是有价值的审查：它准确抓到了渲染能力缺失、流式悬空、死抽象、排版塌陷、链接安全缺口、文档 IR 有损等真实问题。

但报告存在 **5 类系统性偏差**，不能按它的「四归一」原样执行：

1. **把非生产代码计入生产架构**：`reference/markdown-editor` 是 2026-10-27 已裁决的「仅本地参考、不入 Git、CI 不得依赖」目录；把它的 KaTeX/TableIsland 计入「主端架构分裂」会放大问题，也导出了「打捞 reference 资产」这种违反裁决的建议。
2. **把不同产品面混成一个架构**：聊天只读渲染、文档协作 IR、聊天输入框是三个不同面。项目已锁定「markdown-rs 为文档 IR 基座、聊天 pulldown 不升格」（`docs/block-workspace-architecture/plans/03-MD契约.md`）。强行「一个 parser 统一所有面」会推翻已锁定契约。
3. **把「过度转义」误判为「没有清洗 / XSS 敞开」**：当前渲染器把 raw HTML 全部 escape（`crates/conex-markdown/src/renderer.rs:299`），真实问题是**正常安全标签被误杀**与**清洗不是全量/纵深**，不是存在可直接利用的 XSS。修复方向是「只清洗不可信 raw HTML 片段」，不是「再叠加一层 DOMPurify」。
4. **严重度通胀**：报告把排版美化、语法高亮配色、CJK 断字等大量打磨项都标成 P0/P1，并给出不可复现的 2.2/5 评分。本方案不使用 P0/P1 排序，只按逻辑依赖排序（AGENTS §1）。
5. **对库能力的误判**：报告称 Callout 需要自研正则/AST；实际上仓库锁定的 `pulldown-cmark 0.12.2` 已内置 `Options::ENABLE_GFM`，原生识别 `[!NOTE]/[!TIP]/[!IMPORTANT]/[!WARNING]/[!CAUTION]` 五种 `BlockQuoteKind`，当前只是没开 flag、且 `Tag::BlockQuote(_)` 忽略了 kind（`renderer.rs:246`）。这使 Callout 从「大工程」降为「开 flag + 映射事件」。

### 0.2 目标架构一句话

> **Rust 单一渲染内核产出「静态语义 HTML + 交互 Island 占位」；前端只负责块切分、批量调度、Island 注水与事件委托；文档协作 IR 独立走 markdown-rs 面，两边不互相反推、不共用回退实现。**

### 0.3 必须纠正的五个架构错误

1. **渲染实现多头**：Rust 权威渲染、TS regex 回退、Worker `marked`、手写增量会话、表格逐单元格会话，五套实现并存且输出契约不一致。
2. **流式契约空转**：`virtualClosedText` 计算后被丢弃；`timeline` 传入后被丢弃；`render_markdown_stream` 未暴露；`core_md_render_batch` 未接线。
3. **HTML 契约被旧实现绑架**：为了 byte-for-byte 兼容旧正则输出，主动关闭脚注/Math/Callout、把 H5/H6 压成 H4、把所有 raw HTML 转义，导致能力倒退。
4. **大文档靠熔断而非虚拟化**：超过 256KB 直接退化为纯文本查看器（`MarkdownDocumentView.tsx:15`）。
5. **文档 IR 有损**：`BlockKind` 缺 Table/TaskItem/Math/Code lang（`crates/conex-doc-collab/src/ir.rs:14`），序列化丢语言、拍平嵌套、子块无缩进（`crates/conex-md-ast/src/serialize.rs:98`、`assemble.rs:24`）。

### 0.4 明确拒绝的三类建议

| 建议 | 裁决 | 理由 |
| :--- | :--- | :--- |
| 一个 parser 统一聊天/文档/输入框 | **拒绝** | 违反已锁定两面契约；聊天 pulldown、文档 IR markdown-rs 各有职责；输入框是 ProseMirror 行内 schema；强行合并会推倒现有 CRDT/块编辑器 |
| 打捞 `reference/markdown-editor` 的 KaTeX/TableIsland/CodeMirror | **拒绝** | `reference/` 仅本地参考、不入 Git、CI 不得依赖；可参考思路，必须在受跟踪包内重写 |
| 引入 Shiki / CodeMirror 6 / Lezer / WASM 重写 | **拒绝** | 与现有缺陷不成比例；`pulldown-cmark + syntect + two-face` 足以补齐；WASM 双端编译属于过度设计 |

**真桌面验收中发现并修复的问题**（均已补回归测试）：

1. `IslandPortal` 在 Portal 提交后清空 target，导致 React `removeChild` 崩溃 → 挂载前清占位、挂载后 target 归 React 独占。
2. Mermaid 默认 HTML 标签被 DOMPurify SVG profile 清洗后只剩空白节点 → `htmlLabels:false` 输出原生 SVG text。
3. raw HTML 开 / 闭标签被 pulldown 拆成多个事件，逐片段 ammonia 清洗把 `kbd/mark/details` 内容挤到标签外 → 跨事件捕获后整体清洗。
4. Callout 借用语法高亮 token，暗色 warning 显示成蓝色 → 改用 `--status-*` / `--accent-*` 语义色。
5. 本地路径链接同时输出路径按钮与链接文本（重复） → 按钮包裹链接标签，并禁止链接内再生成路径按钮。

未做真桌面流式生成与超长文档虚拟化现场验收（需真实模型流 / 大文档）；这两条由单测与集成测试覆盖，发布前可补一次端到端演练。

Phase 6 的实现取舍（相对 §4 Phase 6 任务的偏差，已同步 `plans/03-MD契约.md` §3.9）：

- `Code` 保持单元 kind，lang/meta 放 attrs（与 `block-paper` 既有 wire 口径一致；语言变更不触发 turn_into）。
- `TaskItem { ordered }` 只带结构位，勾选态放 attrs（勾选是高频可变状态）。
- `Table` / `Math` / `Callout` / `FootnoteDefinition` 的载荷放 `text_snapshot` + attrs，不在 kind 内嵌大结构。
- 标题保留 Conex 章节嵌套约定；列表 / 引用按 mdast 显式嵌套，不再使用容器栈拍平。

## 2. 目标架构

### 2.1 两张渲染面，一条边界

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 面 A：只读 Markdown 渲染（聊天消息 + 文档预览 + 技能详情）            │
│                                                                     │
│  Markdown 源文本                                                     │
│      │                                                              │
│      ▼                                                              │
│  Rust conex-markdown（唯一解析/渲染器：pulldown-cmark 0.12.2）        │
│      ├─ 静态语义 HTML（md-* 契约）                                   │
│      ├─ 代码块（行 span / 行号 / 复制 / 折行 / 折叠 / syntect）       │
│      ├─ Callout / 脚注 / 标题 id / 安全 raw HTML                     │
│      └─ Island 占位（math / mermaid / 未来扩展）                     │
│      │                                                              │
│      ▼  Tauri IPC：core_md_render / batch / stream                   │
│  前端 Markdown 块管线                                                │
│      ├─ MarkdownBlockScanner（仅块边界，不是 Markdown 渲染器）        │
│      ├─ MarkdownRenderScheduler（缓存 + 批量 + latest-wins）          │
│      ├─ MarkdownBlockList（可选窗口化）                               │
│      ├─ MarkdownSurface（innerHTML + Island 注水 + 事件委托）         │
│      └─ Islands（KaTeX / Mermaid / 未来组件）                        │
└─────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│ 面 B：文档协作 IR（块编辑器 / Agent 读写 / CRDT）                     │
│                                                                     │
│  Markdown 源文本 <──P/S──> conex-md-ast（markdown-rs 锁定）           │
│                              │                                      │
│                              ▼                                      │
│                     conex-doc-collab BlockTree（权威）               │
│                     ├─ BlockKind 补完：Code{lang,meta} / TaskItem    │
│                     ├─ Table / Math / Callout / Footnote             │
│                     ├─ 嵌套列表/引用真实父子                          │
│                     ├─ 无损 S（缩进/容器/语言）                       │
│                     └─ 后续：InlineSpan 富文本契约                    │
└─────────────────────────────────────────────────────────────────────┘
```

**边界铁律**：

- 面 A 不得依赖面 B 的 `BlockTree`；面 B 不得用面 A 的 HTML 反推块树（MD 契约 A-MD-08 / I1）。
- 面 A 只有一个渲染器：Rust `conex-markdown`。前端**不再实现 Markdown 渲染**。
- 面 B 只有一个解析器：markdown-rs（已锁定）。不得为了「统一」把它换成 pulldown，或反过来。
- 聊天输入框（Tiptap）是行内 schema，不属于面 A 或面 B 的渲染器；保持独立契约。
- `reference/` 与 `docs/composer-preview/` 只作设计参考，不作为依赖、不 import、不要求 CI 检出。

### 2.2 面 A 的设计原则

1. **一个解析器、一个 HTML 契约、一个清洗器、一个块单元**。
2. **Rust 只产出静态 HTML 与 Island 占位**；KaTeX/Mermaid/未来交互组件由前端注水。这样新语法不需要改前端块管线，新交互不需要改 Rust 渲染器。
3. **块是渲染与缓存的最小单位**：聊天一个语义块一个 block；文档按 8KB 左右把连续块合并为 chunk 用于虚拟化。
4. **流式只重渲染活跃块**：已封口块不再变化；活跃块整块交给 Rust `stream_mode`，不再维护手写增量 DOM 状态机。
5. **没有第二渲染器**：IPC 失败显示纯文本兜底，不偷偷切到 JS/Worker 解析。

### 2.3 面 B 的设计原则

1. 先修**往返**（嵌套/缩进/语言/表格/任务/数学），再谈 inline 富文本。
2. 嵌套由 markdown-rs 的 mdast 递归下降直接产出，废除「容器秩相等就弹出」的拍平逻辑。
3. `BlockKind` 扩展是破坏性变更：不做双形状兼容；一次性迁移/重解析，测试改为断言无损。
4. InlineSpan 是下一阶段，先定契约，不在结构往返未绿时偷关。

### 2.4 Composer 的边界

- 保持行内 schema（heading/list/blockquote 节点禁用）是**产品契约**，不是缺陷。
- 清理 serializer 中 schema 永远不会产生的块级死分支，降低维护面积。
- 不在 composer 内做 Markdown 预览渲染；发送后由面 A 渲染。
- 如果未来需要块编辑，走 `block-paper/note-paper`，不塞回 composer。

## 3. 核心契约

### 3.1 HTML 契约（面 A）

> 这是 CSS、测试、前端交互的唯一锚点。所有实现必须以此为准；不再追求与旧 JS 正则的 byte-for-byte 兼容。

| 元素 | 契约 |
| :--- | :--- |
| 根 | `.conex-markdown.md-rendered[data-md-variant="chat|document"]` |
| 标题 | `<h1 class="md-h1" id="slug">` … `<h6 class="md-h6" id="slug">` |
| 段落 | `<p class="md-p">` |
| 列表 | `<ul class="md-ul">` / `<ol class="md-ol" start>` / `<li class="md-li">`；嵌套加 `md-ul-nested` / `md-ol-nested` |
| 任务项 | `<li class="md-li md-task-item"><input type="checkbox" class="md-task-checkbox" disabled checked>…</li>` |
| 引用 | `<blockquote class="md-quote">` |
| Callout | `<div class="md-callout md-callout-note"><div class="md-callout-title" data-callout-title="note"></div><div class="md-callout-body">…</div></div>`（五种 kind；标题文本由前端按 i18n 注入，Rust 不写死语言） |
| 代码块 | `<div class="md-code-block" data-lang="ts" data-collapsible="true"><div class="md-code-header">…<div class="md-code-actions"><button class="md-code-copy" data-action="copy" data-tooltip-key="markdown.copy"></button>…</div></div><pre class="md-code-pre"><code class="language-ts"><span class="md-code-line">…</span>…</code></pre></div>` |
| 行内代码 | `<code class="md-inline-code">` |
| 表格 | `<div class="md-table-wrap" data-md-table="true" role="region" aria-label="…"><table class="md-table" style="--md-table-cols:3"><thead>…</thead><tbody>…</tbody></table></div>` |
| 链接 | `<a class="md-a" href="…" target="_blank" rel="noreferrer">` |
| 路径链接 | `<button type="button" class="md-path-link" data-path="…">`（含 `file:///` 本地路径） |
| 不安全链接 | `<span class="md-a-unsafe">` |
| 图片 | `<img class="md-img" src="…" alt="…" loading="lazy">` |
| 分隔线 | `<hr class="md-hr">` |
| 行内公式 | `<span class="md-math md-math-inline" data-md-island="math" data-tex="…">$…$</span>` |
| 块公式 | `<div class="md-math md-math-block" data-md-island="math" data-tex="…">$$…$$</div>` |
| Mermaid | 复用代码块外壳，追加 `data-md-island="mermaid"` 与 `<div class="md-island-slot"></div>`；源码仍在 `<pre>` 中可复制 |
| 脚注引用 | `<sup class="md-footnote-ref" id="fnref-1"><a href="#fn-1">1</a></sup>` |
| 脚注区 | `<section class="md-footnotes"><ol class="md-footnote-list"><li class="md-footnote-item" id="fn-1">…<a class="md-footnote-backref" href="#fnref-1">↩</a></li></ol></section>` |

约束：

- Rust 不输出任何 UI 文案（Copy、Note 等），只输出 `data-tooltip-key` / `data-callout-title` / `aria-label` 的结构锚点；前端统一 i18n 注入。
- 行号由 CSS counter 在 `.md-code-line::before` 生成，不是文本节点；复制时按 `.md-code-line` 的 `textContent` 逐行 join，天然不带行号。
- 不再输出 `md-tr-alt` 之类仅用于旧断言的类；斑马纹用 CSS `tbody tr:nth-child(even)`。
- 不输出 `<wbr>`。

### 3.2 Block / Draft 契约（前端）

```ts
interface MarkdownBlockDescriptor {
  id: string;        // 稳定 key：messageId + index + hash（封口）/ index-active（活跃）
  text: string;
  isSealed: boolean;
}

interface MarkdownBlockScanResult {
  sealed: MarkdownBlockDescriptor[];
  draft: string;     // 未封口尾部
}

interface MarkdownBlockScanner {
  append(chunk: string): void;                 // 增量追加
  getSealedBlocks(): string[];                 // O(1) 取已封口
  getPendingDraft(): string;
  flush(): string[];                           // 流结束
  closeDraftForRender(draft: string): string;  // 仅结构补全：围栏/数学/表格
}
```

- 块边界只做**词法**判断：空行、ATX 标题、围栏、`$$`、HTML 块、thematic break；不做行内解析、不做 DOM 投影。
- 列表整体作为一个块；不为每个列表项切块（避免编号重置与视觉断裂）。超长活跃块用节流控制重渲染频率。
- `closeDraftForRender` 只做三类结构补全：未闭合围栏、奇数 `$$`、表格候选（补齐分隔行/末行竖线）。**不做**未闭合 `**`/`*` 的行内猜测，避免误判。
- 表格候选必须至少出现「表头行 + 分隔行（或分隔行前缀）」，否则按普通段落渲染，避免单行 `|` 文字消失。

### 3.3 IPC 与调度契约

```ts
type MarkdownVariant = 'chat' | 'document';

interface RenderOptions {
  variant: MarkdownVariant; // chat: softbreak=<br>; document: softbreak=space
}

interface RenderResult {
  html: string;
  truncated: boolean;
}
```

Rust API：

```rust
pub enum MarkdownVariant { Chat, Document }
pub struct RenderOptions { pub variant: MarkdownVariant }
pub struct RenderResult { pub html: String, pub truncated: bool }

pub fn render_markdown(text: &str, options: RenderOptions) -> RenderResult;
pub fn render_markdown_batch(texts: Vec<String>, options: RenderOptions) -> Vec<RenderResult>;
pub fn render_markdown_stream(text: &str, options: RenderOptions) -> RenderResult; // 内部 stream_mode=true
```

Tauri 命令：

- `core_md_render { text, variant }`
- `core_md_render_batch { texts, variant }`
- `core_md_render_stream { text, variant }`

前端调度器：

- 缓存键 = `variant + text`；缓存 `RenderResult`，命中同步返回。
- 同一 tick 内的多个请求合并为一个 batch（上限 64 条 / 256KB，超限拆批顺序发送）。
- 活跃块走 `stream` 通道，latest-wins：新文本到达时丢弃在途旧结果；节流 33ms（可按块大小降频到 100~200ms）。
- 历史消息/文档预取在组件挂载时入队；虚拟化只挂载可见消息/块，因此不会一次性请求全部历史。
- IPC 缺失/失败：返回纯文本兜底（`markdownPlainTextFallback`），标记 `failed`，不切换 JS Markdown 渲染器。
- 暴露测试统计：`cacheHits`、`cacheMisses`、`ipcCalls`、`pendingBatches`。

### 3.4 Island 契约

```ts
interface MarkdownIslandDefinition {
  name: string;                       // 'math' | 'mermaid' | ...
  selector: string;                   // '[data-md-island="math"]'
  component: React.ComponentType<MarkdownIslandProps>; // 懒加载
  hydrateWhen: 'sealed' | 'visible';  // 活跃块不注水，避免每帧重渲染
}
```

- Rust 只发占位；Island 从 DOM 读取 `data-tex` / 代码块源码。
- `MarkdownSurface` 在 `useEffect` 中扫描自己的根节点，用 React Portal 挂载到占位元素；块卸载即卸载 Portal。
- 活跃块 `data-streaming="true"` 时不注水；封口后一次性注水。
- 未来新增图表、embed、diff、file-tree、ai-card：只新增 Island 定义与对应 Rust 标记，不改块管线。
- 用户 raw HTML 不包含 `data-md-island`（清洗器剥离），不能伪造 Island。
- KaTeX/Mermaid 必须动态 import；Mermaid 需在 Vite chunk 门禁中登记为「懒加载例外」，并加入 startup static-graph deny 名单。

### 3.5 安全契约

**两层 HTML 人口，只清洗不可信的一层：**

| 人口 | 来源 | 处理 |
| :--- | :--- | :--- |
| 可信生成 HTML | Rust 渲染器自己拼的 `md-*` 结构、代码块、表格、Callout、Island 占位 | 不做 ammonia 全量清洗，避免误杀自有结构与反复序列化 |
| 不可信 raw HTML | Markdown 中的 `Event::Html` / `Event::InlineHtml` | 逐片段 ammonia 清洗，严格语义白名单 |

不可信 raw HTML 白名单：

- 允许标签：`a, abbr, b, blockquote, br, code, del, details, div, em, i, img, kbd, li, mark, ol, p, pre, q, s, section, small, span, strong, sub, summary, sup, table, tbody, td, tfoot, th, thead, tr, u, ul, hr`。
- 允许属性：`a[href,title]`、`img[src,alt,title,width,height,loading]`、`details[open]`、`summary`（无属性）、`ol[start,reversed]`、`th/td[colspan,rowspan,align]`、`div/p[align]`、`abbr[title]`、`q[cite]`。
- **剥离**：`class`、`id`、`style`、`data-*`、所有 `on*`、`button`、`input`、`script`、`style`、`iframe`、`object`、`embed`、`form`。
- URL：`a[href]` 仅 http/https/mailto/`#`/相对；`img[src]` 仅 http/https/相对/光栅 `data:image/(png|jpeg|gif|webp|avif|bmp)`；禁止 `javascript:`/`vbscript:`/`file:`（`file:` 在渲染器层转成路径按钮）。
- 外链统一由 Rust 命令 `workbench_open_external_url` 交给系统浏览器；前端不再 `window.open`。
- 远程图片策略：当前 CSP 实际不允许 `https:` 图片；渲染器与 CSP 必须统一。建议默认把远程图片**在渲染层转成可点击链接/占位**，不直接输出 `<img src="https://…">`；白名单里的 http/https 仅用于“允许判定”，最终由渲染层按策略降级。若产品要求内联，再走受控代理/缓存，不直接放行。
- Mermaid SVG 由 DOMPurify（仅此处）清洗；KaTeX `trust: false`；代码块源码始终 escape。

### 3.6 排版契约

- 字阶：H1 22 / H2 18 / H3 16 / H4 15 / H5 14 / H6 13（chat）；document 变体全部用 `em` 等比放大。字重：H1/H2 700，H3~H6 600，新增 `--fw-medium: 500` / `--fw-semibold: 600`。
- 阅读宽：document `--md-measure: 760px`（可调 token），chat 满宽。
- 垂直韵律：Markdown 根容器 `display: block/flow-root`，不再用 flex 承载正文；块内元素统一 `margin-block-start` + `:first-child` 归零；块之间用 `--md-block-gap`。删除 `+`/`:has` 间距补丁。
- 任务项：CSS Grid（`grid-template-columns: 1.2em 1fr`），删除负边距。
- CJK：删除全部 `<wbr>` 注入；启用 `line-break: strict`、`overflow-wrap: break-word`、`word-break: normal`、`text-rendering: optimizeLegibility`、`font-kerning: normal`、`font-feature-settings: 'palt' 1`；`text-spacing-trim`/`text-autospace` 用 `@supports` 渐进增强。
- 表格：`table-layout: fixed` + `--md-table-cols` 计算 `min-width`；外层滚动、表头 sticky、`box-shadow: inset 0 -1px 0` 替代 sticky 边框。
- 代码块：行号 CSS counter；行高亮解析 `{1,3-5}`；软折行/折叠按钮；滚动条不遮最后一行（`padding-bottom` + `scrollbar-width: thin`）。
- 颜色：不新增裸 Hex；全部消费 `--md-*` / `--syntax-*`；语法色按主题预设做覆盖或 `color-mix` 调和，保持对比度。
- 动画：删除 `AdaptiveAnimateTimeline` 与逐词交错；保留一个克制的流式光标即可。若用 motion，只能 `import { m } from 'motion/react'`（AGENTS §22）。

- **HTML 契约 golden**：H1–H6、段落、列表/嵌套列表、任务项、引用、5 类 Callout、表格（含 code span 竖线、短行、header-only）、代码块（lang/meta/行号/行高亮/Mermaid）、脚注、数学、raw HTML 安全标签。
- **变体**：chat（softbreak `<br>`）vs document（softbreak space）；同一输入结构一致、仅允许的差异可枚举。
- **流式**：未闭合围栏、奇数 `$$`、未闭合表格、未闭合 HTML 块；stream 与 sealed 的结构一致性。
- **安全**：script/onerror/javascript:/vbscript:/data:text\/html/类名伪造/DOM clobbering/畸形嵌套；URL scheme；`file:` 处理。
- **截断**：>5MB 返回 `truncated=true`，不产生半截标签。
- **缓存**：variant 键隔离；batch 命中；stream 不写缓存。
- **性能**：1MB 文档与 100 项列表的渲染耗时基准（不作为硬断言，记录趋势）。

### 5.3 前端测试矩阵

- **BlockScanner**：空行/标题/围栏/数学/HTML/表格候选/CRLF/超长列表/未闭合结构；增量与全量 split 结果一致。
- **Scheduler**：同 tick 合并、去重、上限拆批、latest-wins、失败兜底、缓存命中、variant 隔离。
- **Interactions**：复制（行 span join、无行号）、折行、折叠、路径行号剥离、可执行后缀拒绝、相对链接 preventDefault、外链命令调用、锚点滚动。
- **Islands**：math/mermaid 注水、封口前不注水、主题切换重渲、Mermaid SVG 清洗、懒加载不进入首屏图。
- **组件**：`MarkdownBlockItem` 封口块不因 `isStreaming` 翻转重渲；`MarkdownDocumentView` 不再 256KB 退化；历史预取只发批量。
- **回归**：现有聊天/消息虚拟化/摘要/推理行测试更新后全绿。

### 5.4 真实桌面验收（按 AGENTS §15/§16）
