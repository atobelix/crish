## 一、改动效果总体评估（肯定重大战果）

本次系统性重构是一次**极具魄力与成效的底层架构革命**。针对此前分析报告揭露的「四头割裂、形式主义空转、公式图表完全失明、粗暴转义」等顽疾，团队在 24 小时内以极高的工程执行力完成了一次全面推倒重建：

### 1. 物理清退 14,000+ 行死抽象与陈旧管线，确立单一真理源（SSOT）
- 彻底删除了前端 `marked` 依赖、繁杂的 TypeScript 正则回退管线（`markdownPlugins.ts`、`markdownTable.ts` 等），清除了 Web Worker 结构化克隆传递庞大 AST 的低效架构；
- 确立了「Rust `conex-markdown` 2.0 权威渲染内核产出语义 HTML 外壳 + 交互 Islands 插桩，前端超薄水合」的清晰架构，从根本上消除了前后端渲染不一致的确定性漂移。

### 2. 核心语法特性从“完全失明”跃迁至“现代第一梯队”
- **KaTeX 数学公式**：正式接通行内与块级公式渲染，DisplayMath 自动解套，结合前端 Web Worker 异步渲染，彻底解决了生产环境公式裸奔的耻辱记录；
- **Mermaid 可视化图表**：引入 Island 架构，以动态按需加载（`loadMermaid()`，拆分为 `vendor-mermaid` 懒加载包 ~3.8MB）完美隔离首屏体积，实现时序图/流程图矢量渲染；
- **GitHub Callouts (Alerts)**：原生接通 `pulldown-cmark` 的 GFM Alerts，完美支持 `NOTE` / `TIP` / `IMPORTANT` / `WARNING` / `CAUTION` 5 种卡片与高亮色；
- **排版标签拯救**：废黜了无差别 `escape` 的粗暴做法，通过 `html_tag_delta` 跨事件净深度捕获，成功保护 `<kbd>`, `<mark>`, `<details>`, `<summary>`, `<sub>`, `<sup>`, `<u>`, `<abbr>` 等排版标签，同时剥离脚本与危险事件；
- **代码块现代交互**：改用「`.md-code-line` + CSS Counter 伪元素行号」，彻底解开了行号与复制剪贴板之间的死结；支持长代码折叠与代码折行。

### 3. 文档协作 IR 往返无损化（Round-trip Lossless）
- 引入一等公民 `BlockKind::Table` 与 `BlockKind::TaskItem { ordered: bool }`，代码块 `lang` 与 `meta` 解耦进入属性系统；
- 彻底删除了扁平容器栈推演 `assemble.rs`，换用纯递归 `Lowerer`，嵌套列表与引用实现真递归缩进，GFM 核心测试矩阵全部反转为双向幂等无损。

### 4. 流式防抖与调度性能收敛
- 彻底清除了 `_virtualClosedText` 与 `_timeline` 僵尸属性，隔离了 `isStreaming` 对历史已封口块的协调破防（封口块达成 0 重渲染）；
- 接入微任务调度器 `markdownRenderScheduler`，将历史消息渲染聚合为 `core_md_render_batch`，首屏 IPC 往返由 300+ 次骤降至 4~5 次；
- 废黜 256KB 逃生门，引入 `VirtualMarkdownBlockList`。

## 二、严峻遗留硬伤与新引入缺陷（直击痛点）

重构速度极快，但伴随大量旧代码清退与新逻辑引入，代码库中暴露了 **多处 P0 级体验杀手、安全漏洞与逻辑漏勺**：

### 1. 【P0 体验杀手】流式高速吐字 UI 饥饿假死（UI Starvation）
- **代码定位**：`apps/crish-desktop/src/api/markdown/useMarkdownRender.ts:190`
- **缺陷事实**：代码中加入了过度严苛的校验 `if (stopped || textRef.current !== current) return;`。当大模型以 80~100+ tokens/s 高速生成时（每 10~15ms 产生一个 token），耗时 ~30ms 的 Tauri IPC 返回时 `textRef.current` 必然已前移。导致**每次返回的渲染结果被 100% 连续静默丢弃**！
- **用户现场表现**：在大模型高速流式输出期间，界面长达数秒定格在纯文本 fallback 状态，直到模型停顿或输出完毕时，才瞬间暴闪刷出富文本。

### 2. 【P0 体验杀手】超大文档虚拟化完全缺失滚动锚定（Scroll Anchoring），视口剧烈跳跃
- **代码定位**：`apps/crish-desktop/src/components/markdown/VirtualMarkdownBlockList.tsx:85-90`
- **缺陷事实**：`VirtualMarkdownBlockList` 采用绝对定位 `top: map.offsetOf(index)`，但**完全没有引入视口位移补偿（Scroll Anchoring）**。
- **用户现场表现**：当视口上方的内容异步加载（如 Mermaid 渲染出 800px SVG、KaTeX 异步生成矩阵、未声明宽高的大图片），上方高度剧烈膨胀，`HeightMap` 前缀和暴涨，导致视口内所有内容瞬间被向下推挤数百像素，用户正在阅读的焦点直接被弹飞；向上回滚时更会产生向下推挤的严重物理抗拒感。
- **叠加冲突**：CSS `.md-virtual-chunk` 配置了 `content-visibility: auto; contain-intrinsic-size: auto 240px;`，缓冲区外读取出 240px 假高度回填污染了 `HeightMap`，滚入时二次尺寸暴增导致剧烈抖动。

### 3. 【P0 逻辑漏勺】文档协作 IR 契约与 Rust 镜像双重遗漏新增块（静默降级为 Unknown）
- **代码定位**：
  1. `packages/block-paper-contract/src/opsWire.ts:131-189`（`flavourToCollabKind`）
  2. `crates/conex-doc-collab/src/ir.rs:47-87`（`BlockKind::from_flavour`）
  3. `crates/conex-note-runtime/src/store_plan_ops.rs:122-142`（`kind_from_tool_label`）
- **缺陷事实**：
  在本次重构中，虽然在核心 AST 增加了 `Table`、`Math`、`Callout`、`FootnoteDefinition`，但在前端协议层转换器 `flavourToCollabKind` 和 Rust 镜像 `from_flavour` 中，**完全遗漏了对这些新增 flavour 的映射分支**！导致通过协同协议传输或通过工具链调用转块（`pending_turn_into_flavour`）时，**全部被静默退化为 `{ unknown: { flavour } }`**！
- **UI 呈现真空**：`block-paper` 缺少 Table/Math/Callout 专用 Leaf，以 `contenteditable="plaintext-only"` 渲染原始 markdown 纯文本，无富交互。

### 4. 【P0 安全漏洞】`blob:` 协议逃逸为本地特权路径按钮，UNC 路径泄露 NTLM 哈希
- **代码定位**：
  1. `crates/conex-markdown/src/renderer/links.rs`
  2. `crates/conex-markdown/src/url_safety.rs:24`（`JS_VBSCRIPT_DATA_RE`）
  3. `crates/conex-markdown/src/url_safety.rs:88`（`file_url_to_path`）
- **缺陷事实**：
  - `links.rs` 中 `is_local_path_ref` 的检查先于协议检查；其正则排除了 `javascript|vbscript|data`，**却遗漏了 `blob:`**！导致 `[link](blob:payload.rs)` 命中代码后缀正则，被当成合法本地文件直接输出为特权 `<button class="md-path-link">`；
  - `file_url_to_path` 将 `file://server/share` 转换为 UNC 路径 `\\server\share`。在 Windows 上被前端点击送入 `open_path_with_default_app` 时，会向目标服务器发起 SMB 445 请求，**泄漏当前 Windows 登录用户的 NetNTLMv2 哈希**。

### 5. 【排版与交互硬伤】Mermaid 报错源码双重回显，容器查询失效，Tooltips 截断
- **Mermaid 语法报错灾难**：`MermaidIsland.tsx:93-98` 吞没错误日志；CSS 仅在 `[data-mermaid-state='ready']` 时隐藏原始代码块，报错时原始 `<pre>` 与下方错误提示同时展示，导致**同一段源码在屏幕上双重重复显示**；
- **容器查询断裂**：`markdown-typography.css:610` 保留了 `@container (max-width: 540px)`，但误删了 `.md-table-wrap` 上的 `container-type: inline-size`，导致小屏表格自适应直接死锁失效；
- **代码折行溢出截断**：`.md-code-pre code` 遗留了 `min-width: max-content`，开启折行时没有重置为 `0` 或 `100%`，长代码行直接被截断且无法滚动；
- **Tooltips 物理截断**：`.md-code-block` 带有 `overflow: hidden`，顶栏操作按钮 hover 提示绝对定位向上浮出，被父容器顶边界彻底裁切掩杀；
- **超宽 KaTeX 左侧截断**：`.md-math-block` 同时设置了 `overflow-x: auto` 与 `text-align: center`，大矩阵左半部分溢出至负坐标系，浏览器滚动条无法向左回滚，导致左侧公式内容被永久遮挡。

### 6. 【质量工程隐患】重构伴随大面积测试资产丢失，虚拟化列表测试裸奔
- 伴随旧代码清退，`MarkdownBlockItem.test.tsx` (774行)、`StreamingMarkdownView.test.tsx` (315行)、`useStreamingBlocks.test.ts` (191行) 随旧管线一同被彻底删除；
- 最关键的长文档重构组件 `VirtualMarkdownBlockList.tsx` 的单测覆盖率为 **0**，在 `MarkdownDocumentView.test.tsx` 中被粗暴 `vi.mock` 为一个空 div，核心虚拟滚动逻辑处于完全裸奔无保护状态。
