## 1. 方案概述与用户核心红线

### 1.1 背景与用户诉求原文

在 Conex / Crish 桌面客户端的使用过程中，用户针对正文、对话流及代码评审中出现的超链接排版体验提出了明确、坚决的重构要求：

> **用户核心诉求原文**：  
> _“像是带有超链接的这种，应该将文字改成超链接标识才行的，可以加上虚线下划线，以及将超链接的链接改成蓝色的效果。不做向下兼容、不做硬编码、不加任何的important。”_

该诉求切中了当前产品界面最显著的体验痛点：

1. **链接颜色长期挪用品牌墨绿**，在正文中与常规灰色文字对比度弱，且与系统中的“成功（Success）”、“代码差异新增（Diff Add）”状态产生严重语义混淆；
2. **缺乏超链接专属交互标识**，用户在阅读时无法快速预判文字是否可点击、点击后是唤起外部浏览器还是内部代码定位；
3. **下划线形态生硬陈旧**，依然停留在粗暴的浏览器原生实线下划线，缺乏现代高端工具软件（如 Linear、Raycast、VS Code）的细腻排版节奏。

### 1.2 架构目标与五大核心战役指标

结合总方案 `00-总方案.md` §3.4 以及审查报告的技术攻坚裁决，本详案确立五大核心战役指标：

| 战役指标                          | 目标形态与技术标准                                                                                          | 核心价值与质量约束                                                                            |
| :-------------------------------- | :---------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------- |
| **① 清退绿色，确立权威双模蓝**    | Light: `hsl(217 91% 54%)` (`#2563eb`)<br>Dark: `hsl(212 96% 68%)` (`#60a5fa`)                               | WCAG 2.1 AA/AAA 达标（4.95:1 / 7.54:1）；彻底消除语义混淆；不做任何绿色向下兼容               |
| **② 现代精致虚线下划线**          | `underline dashed`，`offset: 3px`，`thickness: 1px`；静息态 45%~50% 半透明留白 $\to$ 悬浮态 100% 饱和高亮   | 消除实线下划线的笨重感；避开字符降笔（g, p, y, q）；多行文本折行盒模型零破坏                  |
| **③ 纯 CSS 物理级防孤行外链角标** | `content: '\a0'` + 复合宽度 `calc(0.8em + 0.22em)` + 右对齐 Mask 遮罩 SVG `↗` 图标                          | **Zero-Orphan 物理锁定**：链接尾部文字与角标永不折行分离；多媒体链接自动排除；零 DOM 侵入     |
| **④ 思维链排版命名空间闭环**      | `ThinkingBlock.tsx` 中的展开全文 `thinkingFull` 与折叠预览 `previewText` 容器补齐 `md-rendered`             | 消除思考过程段超链接样式脱管，全应用统一排版基座 100% 覆盖                                    |
| **⑤ WebView2 安全外跳单轨收敛**   | 抽取统一共享函数 `handleSafeExternalLinkClick`，在 `useChatMessageState` 与 `MarkdownDocumentView` 双向收敛 | 杜绝 WebView2 内部误导航与白屏逃逸；严格执行 `sanitizeUrlCandidate` + `isSafeHref`；落实 SSOT |

### 1.3 核心红线刚性约束

本方案受以下绝对红线约束，执行期间严禁任何违规退避：

1. **不做向下兼容（No Backward Compatibility）**：
   彻底移除超链接对 `--brand-deep`、`--brand` 以及 `--brand-primary` 绿色的引用与 fallback。超链接就是超链接，一律采用全新的权威蓝色 Token。
2. **不做硬编码（No Hardcoding）**：
   严禁在任何组件或模块的 CSS / TS 代码中裸写 Hex 或 HSL 颜色值（如 `#2563eb` 或 `color-mix(..., 40%, ...)`），所有颜色、偏移、样式必须从 `tokens.css` 声明的 CSS Custom Properties 读取。
3. **严禁 `!important`（Zero `!important` Policy）**：
   严禁使用 `!important` 压制样式层叠。通过提升架构清晰度、理清特异性层级（Specificity Hierarchy）与命名空间来解决样式冲突。
4. **测试资产零破坏（Test Asset Integrity）**：
   既有测试文件（`typography-token.test.ts`、`a11y-contrast.test.ts`、`MarkdownDocumentView.test.tsx`）是受保护的核心资产，所有改造必须完全满足其断言契约，实现 100% 全绿通过。

## 2. 系统现状与架构断层深度穿透

### 2.1 双端 Markdown 渲染引擎输出契约验证

在系统的渲染流水线中，HTML 文本由底层 Rust 引擎（高性能通道）与前端 TS Worker（兜底通道）共同生成。通过深度审查其代码实现，确认了双端输出契约的完全一致性：

#### 1. Rust 内核渲染器（`crates/conex-markdown/src/renderer.rs:506-508`）

```rust
write!(
    self.output,
    "<a class=\"md-a\" href=\"{}\" target=\"_blank\" rel=\"noreferrer\">",
    escape_html(&url)
)
.ok();
```

Rust 引擎在解析标准 Markdown 链接 `[text](url)` 时，先通过 `is_local_path_ref` 判断是否为本地路径（转为 `<button class="md-path-link">`），若是 Web 外部链接且通过 `is_safe_href` 校验，则统一输出带有 `class="md-a"`、`target="_blank"` 和 `rel="noreferrer"` 的 `<a>` 标签。

#### 2. 前端 TS Worker 兜底引擎（`apps/crish-desktop/src/api/markdown-render/markdownPlugins.ts:161-163`）

```ts
return pushInline(
  `<a class="md-a" href="${escapeHtml(url)}" target="_blank" rel="noreferrer">${escapeHtml(t)}</a>`
);
```

TS 引擎同样输出 `<a class="md-a" href="..." target="_blank" rel="noreferrer">`。

#### 审查结论：

双端渲染器在架构底层已经达成一致契约：**所有合法的 Web 超链接均稳定具备 `class="md-a"`、`target="_blank"` 属性**。前端排版层完全可以通过 CSS 属性选择器进行 100% 精确拦截，无需对双端解析引擎做任何结构性改动。

### 2.2 本地代码路径微胶囊与 Web 外链的四重正交物理隔离

用户对于本地代码文件跳转极为敏感，任何超链接方案绝不能将本地文件路径识别为 Web 外链或误挂外链箭头。

审查确认，本地路径微胶囊（`.md-path-link`）与 Web 外链（`a.md-a`）在架构上存在**四重物理级隔离**：

```
                    【双端 Markdown 输入解析】
                              │
               ┌──────────────┴──────────────┐
               ▼                             ▼
       [本地路径 (Path)]              [Web 外部链接 (URL)]
               │                             │
① 标签隔离    ▼ <button>                    ▼ <a>
② 类名隔离    ▼ .md-path-link               ▼ .md-a
③ 样式隔离    ▼ 等宽字体 + 中性灰 + 实线     ▼ 正文字体 + 科技蓝 + 虚线 + ↗
④ 事件隔离    ▼ IDE 内部打开定位            ▼ 外部默认浏览器安全唤起
```

1. **DOM 标签物理正交**：本地路径为 `<button>`，Web 链接为 `<a>`；
2. **样式类名正交**：本地路径为 `.md-path-link`，Web 链接为 `.md-a`；
3. **视觉语言正交**：本地路径采用等宽字体（`var(--md-font-mono)`）、中性灰色（`var(--text-secondary)`）与实线下划线；Web 链接采用权威科技蓝、虚线下划线与尾部外链角标；
4. **事件委托正交**：容器级点击事件中，本地路径通过 `closest('.md-path-link')` 拦截并触发 IDE 文件定位；外部超链接由 `handleSafeExternalLinkClick` 拦截并移交系统浏览器，两者分流明确。

### 2.3 绿色品牌色污染与语义冲突根因剖析

排查 `apps/crish-desktop/src/styles/tokens.css` 发现，超链接颜色被错误地绑定到了品牌主色上：

- **Light 主题**（`tokens.css:721-722`）：
  ```css
  --md-link-color: var(--brand-deep, hsl(160 84% 30%));
  --md-link-hover-color: var(--brand, hsl(160 84% 39%));
  ```
- **Dark 主题**（`tokens.css:1467-1468`）：
  ```css
  --md-link-color: var(--brand, hsl(160 84% 39%));
  --md-link-hover-color: hsl(160 84% 55%);
  ```

#### 严重缺陷分析：

1. **语义撞车**：绿色在用户界面中承载“任务成功（Success）”、“代码变更添加（Diff Inserted）”、“Agent 运行中（Active Status）”等核心强状态。将超链接染成墨绿或翡翠绿，使用户在浏览文档和对话时误以为这是一处运行状态提示或代码差异；
2. **色度对比度不足**：在浅色主背景（`#fbfaf9`）下，深墨绿 `hsl(160 84% 30%)` 与深灰正文 `#1a1a1a` 在色轮上色相差极低，用户难以扫视定位链接；
3. **用户体验与行业脱节**：蓝色是人机交互界面中超链接的权威认知色彩。废止品牌绿对于界面的专业感与认知直觉至关重要。

### 2.4 浏览器传统实线下划线沉重与标识符缺失

排查 `apps/crish-desktop/src/styles/markdown-typography.css:458-473`：

```css
.md-rendered .md-a,
.conex-markdown .md-a,
:is(.conex-markdown, .md-rendered) :is(.md-a, a) {
  color: var(--md-link-color);
  text-decoration: underline;
  text-underline-offset: var(--md-link-underline-offset);
  text-decoration-color: var(--md-link-underline-color);
  ...
}
```

1. 采用浏览器默认的 `text-decoration: underline`（实线），视觉线条僵硬，在大段文本中形成厚重的水平视觉横杠；
2. 完全缺失任何超链接指示标识（如 `↗`），用户无法区分纯文本重点与可导航外链；
3. 缺少 `:active` 点击态与柔软的 `:focus-visible` 焦点环，无障碍交互体验残缺。

### 2.5 容器类名脱管断层：`ThinkingBlock.tsx` 思维链渲染双容器

排查 `apps/crish-desktop/src/extensions/conversation-flow/ThinkingBlock.tsx:109-126`：

```tsx
{
  open ? (
    <ReconciledMarkdownHtml
      className={styles.thinkingFull}

      html={fullHtml}
      incrementalUnits={isLive && open ? fullUnitsRef.current : undefined}

      <ReconciledMarkdownHtml
```

#### 严重断层：

`MarkdownBlockItem.tsx:216-219` 正确挂载了 `md-rendered` 类名；然而，`ThinkingBlock.tsx` 在展开全文（`thinkingFull`）与折叠预览（`previewText`）两处，**容器均未挂载 `md-rendered` 或 `conex-markdown`**！  
这意味着思考过程中的所有 Markdown 链接完全脱离了 `markdown-typography.css` 的管控，退化为无样式的野生状态。必须在此处彻底闭环。

### 2.6 局部特异性覆盖与测试契约守门（`ChatMessageRow.module.css`）

排查 `apps/crish-desktop/src/components/chat-message-row/ChatMessageRow.module.css:530-549`：

### 3.2 WCAG 2.1 AA / AAA 对比度数学验证与色差量化

#### 1. 相对亮度（Relative Luminance）与对比度算法

根据 W3C WCAG 2.1 标准规范，RGB 分量线性化公式为：
$$C_{\text{linear}} = \begin{cases} \frac{C_{\text{srgb}}}{12.92}, & C_{\text{srgb}} \le 0.03928 \\ \left(\frac{C_{\text{srgb}} + 0.055}{1.055}\right)^{2.4}, & C_{\text{srgb}} > 0.03928 \end{cases}$$
相对亮度公式为：
$$L = 0.2126 \times R_{\text{linear}} + 0.7152 \times G_{\text{linear}} + 0.0722 \times B_{\text{linear}}$$
两颜色对比度比率为：
$$\text{Contrast Ratio} = \frac{\max(L_1, L_2) + 0.05}{\min(L_1, L_2) + 0.05}$$

#### 2. Light 主题数学推导（底色 `#fbfaf9` vs `#2563eb`）

- 主底色 `#fbfaf9`：$R=251, G=250, B=249 \implies L_{\text{bg}} \approx 0.954$
- 链接色 `#2563eb`：$R=37, G=99, B=235 \implies L_{\text{link}} \approx 0.153$
- 对比度：
  $$\text{Ratio} = \frac{0.954 + 0.05}{0.153 + 0.05} = \frac{1.004}{0.203} \approx \mathbf{4.95:1} \ge 4.5:1 \quad \text{(完全符合 WCAG 2.1 AA 标准)}$$
- 正文色 `#1a1a1a` 为中性灰，蓝色链接在 CIE $L^*a^*b^*$ 空间下的色度距离 $\Delta E^*_{00} \approx 42.6$，肉眼可在 0.1 秒内精准识别。

#### 3. Dark 主题数学推导（底色 `#141414` vs `#60a5fa`）

- 主底色 `#141414`：$R=20, G=20, B=20 \implies L_{\text{bg}} \approx 0.007$
- 链接色 `#60a5fa`：$R=96, G=165, B=250 \implies L_{\text{link}} \approx 0.380$
- 对比度：
  $$\text{Ratio} = \frac{0.380 + 0.05}{0.007 + 0.05} = \frac{0.430}{0.057} \approx \mathbf{7.54:1} \ge 7.0:1 \quad \text{(达到 WCAG 2.1 AAA 极高可读性标准)}$$

### 3.3 现代虚线下划线排版几何规范（Dashed Underline）

为彻底解决实线下划线的笨重感，同时规避 `border-bottom: dashed` 在文本折行时盒模型破碎的缺陷，采用标准 CSS 排版属性组合：

```css
/* 虚线下划线核心排版声明 */

text-decoration-thickness: 1px;
text-underline-offset: var(--md-link-underline-offset, 3px);

```

#### 视觉韵律控制：

1. **静息态半透明留白**：若静止态虚线采用 100% 不透明度，在密集排版中易产生点阵视觉噪点。方案在静息态采用微透明：
   - Light: `color-mix(in srgb, var(--md-link-color) 45%, transparent)`
   - Dark: `color-mix(in srgb, var(--md-link-color) 50%, transparent)`
2. **悬浮态完全高亮聚焦**：当鼠标悬停（Hover）时，`text-decoration-color` 迅速且平滑过渡至 `var(--md-link-hover-color)`（100% 饱和不透明），带来明确、笃定的交互反馈；
3. **下划线 3px 偏移锁定**：`text-underline-offset: 3px`，恰到好处地避开了字母降笔（如 g, j, p, q, y），保证字符下沉部分不被下划线穿刺。

### 3.4 纯 CSS 物理级防孤行外链 `↗` 角标（Zero-Orphan Typographic Indicator）

#### 1. 孤行（Typographic Orphan）缺陷机理深度剖析

审查发现，若仅使用传统伪元素写法：

```css
/* 存在孤行缺陷的旧方案 */
.md-rendered a::after {
  content: '';
  display: inline-block;
  width: 11px;
  height: 11px;
  margin-left: 3px;
  ...
}
```

- 在排版引擎的行盒格式化上下文（Line Box Formatting Context）中，`<a>` 是 `inline` 行内元素，而 `::after` 声明为 `inline-block` 原子行内盒；
- 根据 Unicode 折行算法 UAX #14，CJK 中文字符之间均是合法的软断行机会（Soft Wrap Opportunity），而 `margin-left: 3px` 进一步提供了断开边界；
- 当长链接文本（如 `[关于系统架构全景设计的深入分析](https://...)`）排到行尾时，如果行宽刚好容纳最后一个汉字“析”，但容不下随后的 `3px + 11px` 图标宽度：**排版引擎就会把伪元素小图标推到下一行的行首！**
- 这将导致下一行行首孤零零出现一个小箭头 `↗`，形成极具破坏性的排版孤行破损。

#### 2. 纯 CSS 防孤行解决方案：Unicode `\a0` + 复合宽度 + 右对齐 Mask

为在**零 DOM 侵入（无需额外 span 标签）、零 JS 介入（不影响极速协调）**的前提下根治孤行，详案确立**工业级纯 CSS 防孤行物理锁定机制**：

```css
/* 纯 CSS 物理级防孤行外链指示角标 (Zero-Orphan External Link Indicator) */

  :is(.md-a, a):is(
    [target='_blank'],
    [href^='http://'],

  content: '\a0';
  display: inline-block;

  width: calc(0.8em + 0.22em);
  height: 0.8em;
  margin-left: 0;
  vertical-align: -0.05em;

    opacity var(--transition-fast, 120ms ease),

:is(.conex-markdown, .md-rendered)
  :is(.md-a, a):is(

```

#### 物理级防孤行核心机理：

1. **Unicode `\a0`（NO-BREAK SPACE）**：UAX #14 规定，在不换行空格与其前驱字符之间，**绝对禁止发生软换行**。排版引擎在计算折行时，必须将最后一个字符与 `\a0` 绑定为不可分割的整体；
2. **复合宽度替代 `margin-left`**：废黜外边距 `margin-left`，将伪元素宽度定义为 `calc(0.8em + 0.22em)`，通过 `right center` 将 SVG Mask 靠右绘制。左侧的 `0.22em` 自然充当文字与图标的保护留白；
3. **空间不足自动携行折行**：当行尾空间不足以容纳“末尾字 + 复合伪元素”时，排版引擎会**连同末尾字符一起折入下一行**，100% 杜绝小箭头单独出现在新行行首；
4. **多媒体防御盾**：`:not(:has(img, svg, picture, video, canvas)):not(.has-image)`，杜绝在 Shields.io 徽章、图片或内联媒体链接尾部错误挂载小箭头；
5. **页内锚点与安全过滤防御盾**：`:not([href^='#']):not([href^='javascript:'])`，确保文档内目录锚点跳转不挂载外链指示符；
6. **微动效动力学（Micro Motion）**：悬停时图标微移 `translate(0.5px, -0.5px)`，透明度从 0.7 提升至 1.0，120ms 丝滑过渡。

## 4. WebView2 外部安全跳转与单一真理源（SSOT）架构

### 4.1 安全外链分发漏洞剖析与防护边界

在 Windows 桌面端的 WebView2 架构中，如果未对超链接点击做容器级事件代理拦截，会产生以下致命安全隐患：

1. **WebView 内部重定向**：点击 `target="_blank"` 的外部超链接可能直接在客户端主窗口内打开目标网页，导致 Crish 前端界面被覆盖；
2. **恶意协议逃逸**：恶意链接可能包含 `javascript:`、`data:text/html`、`file:///` 等高危 scheme，若仅用裸正则 `/^https?:\/\//i` 判定，无法拦截这类伪协议的执行；
3. **合法协议丢失**：如 `mailto:support@example.com` 属于合法外链，若只匹配 `http(s)` 会导致系统邮件客户端无法被调起。

### 4.2 统一外链安全公共模块（`markdownSanitizer.ts`）

将外链判定、安全清理与唤起逻辑提升收敛至 `apps/crish-desktop/src/api/markdown-render/markdownSanitizer.ts`，作为全系统的单一真理源（SSOT）：

```ts
/** 与 isSafeHref 一致的外链 scheme 判定（大小写不敏感） */
export function isExternalNavigableHref(url: string): boolean {
  return /^https?:\/\//i.test(url) || /^mailto:/i.test(url);
}

/**
 * 安全调用外部系统默认浏览器打开链接，杜绝 WebView2 内部跳转。
 * 唯一安全链路：sanitizeUrlCandidate → isSafeHref → isExternalNavigableHref → window.open
 */
export function openExternalUrlSafely(url: string): void {
  const sanitized = sanitizeUrlCandidate(url);
  if (!sanitized) return;
  if (!isSafeHref(sanitized) || !isExternalNavigableHref(sanitized)) return;

  if (typeof window !== 'undefined') {
    window.open(sanitized, '_blank', 'noopener,noreferrer');
  }
}

/**
 * 容器级事件委托中通用的 safe external link 拦截分发器。
 * 命中并处理外链或危险链接时返回 true（已阻止默认行为与冒泡），未命中返回 false。
 */
export function handleSafeExternalLinkClick(
  e: React.MouseEvent | MouseEvent,
  target: HTMLElement
): boolean {
  const anchor = target.closest('a');
  if (!(anchor instanceof HTMLAnchorElement)) return false;

  const href = anchor.getAttribute('href');
  if (href == null) return false;

  const sanitized = sanitizeUrlCandidate(href);
  if (!sanitized) {
    e.preventDefault();
    e.stopPropagation();
    return true;
  }

  // 合法外部协议：通过系统默认浏览器安全唤起
  if (isExternalNavigableHref(sanitized)) {
    e.preventDefault();
    e.stopPropagation();
    if (isSafeHref(sanitized)) {
      openExternalUrlSafely(sanitized);
    }
    return true;
  }

  // 未知或危险绝对 scheme：强制拦截掐灭，禁止落入 WebView2 原生导航
  if (/^[a-z][a-z0-9+.-]*:/i.test(sanitized) && !isSafeHref(sanitized)) {
    e.preventDefault();
    e.stopPropagation();
    return true;
  }

  // 相对路径与页内锚点 # 放行
  return false;
}
```

### 4.3 `useChatMessageState.ts` 与 `MarkdownDocumentView.tsx` 双向收敛

- 在 `useChatMessageState.ts` 中引入 `handleSafeExternalLinkClick`，填补对话流容器事件委托的空白；
- 在 `MarkdownDocumentView.tsx` 中移除私有内联实现，改为调用公共 `handleSafeExternalLinkClick`；
- 全系统对超链接点击的拦截行为实现 100% 净收敛。

### 5.5 `apps/crish-desktop/src/api/markdown-render/markdownSanitizer.ts`

在文件末尾追加并导出公共安全外跳分发函数：

```ts
/** 与 isSafeHref 一致的外链 scheme 判定（大小写不敏感） */
export function isExternalNavigableHref(url: string): boolean {
  return /^https?:\/\//i.test(url) || /^mailto:/i.test(url);
}

/**
 * 安全调用外部系统默认浏览器打开链接，杜绝 WebView2 内部跳转。
 * 唯一安全链路：sanitizeUrlCandidate → isSafeHref → isExternalNavigableHref → window.open
 */
export function openExternalUrlSafely(url: string): void {
  const sanitized = sanitizeUrlCandidate(url);
  if (!sanitized) return;
  if (!isSafeHref(sanitized) || !isExternalNavigableHref(sanitized)) return;

  if (typeof window !== 'undefined') {
    window.open(sanitized, '_blank', 'noopener,noreferrer');
  }
}

/**
 * 容器级事件委托中通用的 safe external link 拦截分发器。
 * 命中并处理外链或危险链接时返回 true（已阻止默认行为与冒泡），未命中返回 false。
 */
export function handleSafeExternalLinkClick(
  e: React.MouseEvent | MouseEvent,
  target: HTMLElement
): boolean {
  const anchor = target.closest('a');
  if (!(anchor instanceof HTMLAnchorElement)) return false;

  const href = anchor.getAttribute('href');
  if (href == null) return false;

  const sanitized = sanitizeUrlCandidate(href);
  if (!sanitized) {
    e.preventDefault();
    e.stopPropagation();
    return true;
  }

  // 合法外部协议：通过系统默认浏览器安全唤起
  if (isExternalNavigableHref(sanitized)) {
    e.preventDefault();
    e.stopPropagation();
    if (isSafeHref(sanitized)) {
      openExternalUrlSafely(sanitized);
    }
    return true;
  }

  // 未知或危险绝对 scheme：强制拦截掐灭，禁止落入 WebView2 原生导航
  if (/^[a-z][a-z0-9+.-]*:/i.test(sanitized) && !isSafeHref(sanitized)) {
    e.preventDefault();
    e.stopPropagation();
    return true;
  }

  // 相对路径与页内锚点 # 放行
  return false;
}
```
