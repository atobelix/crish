## 1. 执行摘要与审计结论

经过对 `apps/crish-desktop` 中与输入框浮层、提示条、快捷菜单相关全部组件源码与样式体系的逐行排查，得出以下核心结论：

1. **输入框上方提示胶囊（`ComposerNoticeBar`）存在“入场偏慢、退场瞬断”的双重体验断层**：
   - 入场时长达 `260ms`（`ComposerNoticeBar.module.css:33`），对于微交互提示显得反应迟缓；`scale(0.98)` 变形幅度偏大，在 760px 宽度下引发肉眼可见的字体重采样模糊；
   - 点击关闭（Dismiss）或外部状态清理时，React 树直接将节点 `null` 卸载（`0ms` 物理硬拔），伴随 `48px` 高度与 `6px` 外边距瞬间塌陷，引发输入卡片发生 **54px 剧烈跳动（Layout Shift）**。
2. **快捷菜单（`TiptapSlashMenu` 及 `@` 提及建议菜单）缺失物理空间位移动画**：
   - 动画仅声明了 `popoverFadeIn`（`TiptapSlashMenu.module.css:9-16, 33`），**只有透明度 `opacity: 0 -> 1`，位移 `transform` 值为 0**；
   - 菜单完全没有“从光标或输入框边缘顺滑浮现”的物理空间暗示，体验生硬平铺；退出阶段直接通过 ProseMirror 扩展的 `component.destroy()` 瞬间销毁，毫无退场平滑度。
3. **状态浮条与错误提示缺乏系统性动效标准**：
   - `ComposerErrorBar`（错误条）**完全没有任何 CSS 动画**（`ComposerErrorBar.module.css:1-19`），出现时直接把整个输入区顶下；
   - `DynamicChipBar` 缩放幅度达 `scale(0.96)`（4% 剧烈缩放），在小尺寸 Chip 上呈现类似果冻抖动的瑕疵；
   - `PermissionModeMenu` 与 `Menu.module.css` 广泛引用了全仓**未定义的 `@keyframes cds-popover-enter`**，导致部分浮层入场动画实际上处于**静默失效（0ms 闪现）**状态。

## 2. 用户核心诉求与体验痛点梳理

### 用户诉求原文

> _“像是弹出输入框上面的提示的时候，应该是有一定的动画位移的，一定要是比较丝滑的那种，响应要及时，也不要弄的和果冻一样上下跳。”_

### 诉求拆解与准则映射

| 诉求维度         | 用户原意解读                                | 工业级微交互实现准则                                                               | 禁忌红线（反模式）                                         |
| :--------------- | :------------------------------------------ | :--------------------------------------------------------------------------------- | :--------------------------------------------------------- |
| **动画位移**     | 弹出时要有向上浮起的空间物理轨迹            | `translateY(6px) scale(0.985)` $\to$ `translateY(0) scale(1)`                      | 严禁仅有纯透明度淡入（`opacity` 孤立变化，缺乏物理深度）   |
| **丝滑顺畅**     | 视觉流动自然，边缘清晰，无闪烁              | 基于 GPU 合成层（`transform` + `opacity`），高帧率渲染                             | 严禁操作 `height/margin` 引发整页主线程 Reflow 重排        |
| **响应及时**     | 指令发出或触发瞬间立即出现，毫不拖泥带水    | 严格收敛于 **150ms ~ 180ms** 快出曲线                                              | 严禁使用 $>220\text{ms}$ 的缓慢拖沓动画（如现有 260ms）    |
| **杜绝果冻跳跃** | 严禁 overshoot 弹性反弹，严禁大幅度缩放变形 | 严格使用 `cubic-bezier(0.16, 1, 0.3, 1)`（无过冲单调渐近），缩放克制在 $\ge 0.985$ | 严禁弹性曲线（如弹簧 bounce、过冲 $y > 1.0$ 的橡皮筋振荡） |
| **优雅离场**     | 关闭时不突兀消失，输入框不骤跳              | **100ms ~ 120ms** 快速淡出加速，容器平滑合拢                                       | 严禁 0ms 直接 unmount 导致下层布局瞬间跳跃                 |

#### 缺陷根因分析

- **位移归零（Zero-Displacement）**：`popoverFadeIn` 仅包含 `opacity: 0 -> 1`。斜杠菜单在输入框内键入 `/` 或 `@` 时是平铺就地渐显，没有物理纵深感；
- **方向盲目（Direction-Agnostic）**：Radix Popover 会在 `Popover.Content` 上自动打上 `data-side="top"` 或 `data-side="bottom"` 属性。因为输入框常驻屏幕底端，菜单绝大多数情况下是**向上弹出**（`side="top"`），理应从光标处由下至上轻盈升起（`translateY(6px)`）；若在视口上方则应反向（`translateY(-6px)`）。当前完全未利用 `data-side` 进行区分；
- **曲线错配**：使用了 `var(--transition-fast)`（即 `var(--ease-standard) = cubic-bezier(0.4, 0, 0.2, 1)`），这是为颜色渐变设计的对称曲线，初速度不足，缺乏几何位移所需的“迅速破土（Fast-out）”质感；
- **离场硬销毁**：ProseMirror Suggestion 插件在 `onExit` 或按下 `Escape` 时直接执行 `component.destroy()`，React 根被瞬间卸载，没有退场加速淡出，弹窗直接“掉帧式闪没”。

## 4. 顺滑克制微交互动效设计规范

基于用户提出的“**有一定动画位移、丝滑、响应及时、不要弄的和果冻一样上下跳**”核心指示，确立以下微交互物理动效标准：

### 4.1 几何位移空间轨迹（Micro-Displacement）

```
[向上浮动入场：输入框上方提示 / 向上弹出菜单]
         Y 轴
          ▲
  目标位置 │  ● (translateY(0), scale(1.0), opacity: 1.0)
          │  ↑
          │  ↑  [位移幅度: 6px，缩放: 0.985]
  初始位置 │  ○ (translateY(6px), scale(0.985), opacity: 0.0)
          └─────────────────────────────► X 轴
```

- **初始位移量**：`translateY(6px)`。6px 是视觉阈值中的“黄金微距”——既能清晰向大脑传递“浮起”的空间层级意象，又绝不引起跨元素的大面积视觉遮挡或位移眩晕。
- **初始缩放比**：`scale(0.985)`（1.5% 微缩放）。
  - 对比 `0.96`（4% 缩放）：消除了“先缩小后猛弹大”的果冻畸变；
  - 对比 `1.0`（纯位移无缩放）：增加了物体从后景向前景纵深推入的微立体感；
  - 避免文字光栅化重采样毛刺：在 Chromium / WebView2 环境中，$\le 1.5\%$ 的缩放可以在 GPU 纹理采样下保持亚像素平滑，不产生字体模糊抖动。

---

### 4.2 时间与缓动曲线数学验证（Zero-Overshoot）

#### 为什么是 160ms ~ 180ms？

- 响应延迟阈值（Reaction Threshold）：心理物理学研究表明，桌面人机交互的感知即时线在 100ms 左右。
- 160ms 入场时长既提供了肉眼可辨的优雅帧序列（60Hz 下 10 帧，120Hz 下 19 帧），又绝不阻塞用户连续输入。
- 相比现存的 260ms，响应感知速度提升了 **38.5%**。

#### 为什么绝对零果冻？`cubic-bezier(0.16, 1, 0.3, 1)` 数学证明

项目 Design Token 中已有的 `--ease-emphasized` 定义为：
$$\text{CubicBezier}(P_0=(0,0),\ P_1=(0.16, 1),\ P_2=(0.3, 1),\ P_3=(1,1))$$

1. **零过冲保证**：控制点纵坐标 $y_1 = 1.0, y_2 = 1.0$。根据三次贝塞尔曲线凸包性质（Convex Hull Property），曲线的所有点必须落在控制点构成的凸多边形内。
   $$\forall t \in [0, 1],\ 0 \le y(t) \le \max(0, 1.0, 1.0, 1.0) = 1.0$$
   因此，$y(t)$ **绝对不会超过 1.0**，位移在到达目标位置（0px）时平滑贴合，物理上不可能产生任何弹性回弹、超调或果冻晃动。
2. **极速爆发与从容收尾（Fast-out, Gentle-stop）**：
   - 起始导数：$\left.\frac{dy}{dt}\right|_{t=0} = 3(y_1 - y_0) = 3 \times 1 = 3.0$（初速度极高，键盘按下或提示触发瞬间立即响应）；
   - 终止导数：$\left.\frac{dy}{dt}\right|_{t=1} = 3(y_3 - y_2) = 3 \times (1 - 1) = 0.0$（终端速度精确为 0，平稳着陆）。

---

### 4.3 退出动画机制（Graceful Exit Phase）

微交互不仅要有优雅的进场，更需要利落的离场。

- **离场时长**：严格控制在 **100ms ~ 120ms**（比进场快约 35%）。
- **离场曲线**：加速曲线 `cubic-bezier(0.4, 0, 1, 1)` 或 `ease-in`。
- **离场位移**：`translateY(0) scale(1)` $\to$ `translateY(4px) scale(0.985)`，微沉并迅速隐去。
- **容器平滑合拢**：提示条关闭时，外层容器高度使用 CSS Grid `grid-template-rows: 1fr -> 0fr` 进行 120ms 同步过渡，彻底消灭 54px 的瞬间布局跳动。

---

### 4.4 纯合成层与零重排保障（GPU-Only Compositing）

所有核心微动效严格限定于：

```css
will-change: transform, opacity;
transform: translate3d(0, var(--motion-y, 0), 0) scale(var(--motion-scale, 1));
opacity: var(--motion-opacity, 1);
```

- 动画全程在 GPU Compositor 线程独立完成；
- 避免触发布局重排（Reflow / Layout）与重绘（Repaint）；
- 动画完成后由 CSS `forwards` 保持终态，或通过 `animationend` 释放 `will-change`，保障显存纯净。

### 6.2 风险评估与防御设计

1. **CJK 输入法（IME）组合态冲突**：
   - 风险：拼音输入时如果菜单发生位移，是否会引起候选词框错位？
   - 防御：`safeCursorAnchor.ts` 与 `TiptapSlashMenu.tsx` 已有严格的 `isComposing` 冻结屏障（Line 130-137），动画仅在 Popover 挂载时触发一次，IME 组合态下坐标与节点维持完全静止，零漂移。
2. **GPU 显存占用风险**：
   - 风险：多个浮层滥用 `will-change` 是否会导致图层爆炸？
   - 防御：微动效均在 160ms 内完成，CSS 终态通过 `forwards` 保持；容器静止后无常驻额外复合图层。
3. **高频连续 Dismiss/切换**：
   - 风险：用户快速点击关闭或连续触发多条 Notice 时是否会状态重叠？
   - 防御：离场定时器与 `key={notice.id}` 绑定，ID 切换立即重置定时器，保证状态幂等。
