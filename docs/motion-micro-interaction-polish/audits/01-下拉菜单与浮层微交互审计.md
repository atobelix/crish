## 1. 执行摘要与审计核心结论

经过对 `apps/crish-desktop` 中所有下拉菜单、通用浮层组件、触发器按钮及 Design System 动画体系的完整逐行排查，本审计员得出以下**核心结论**：

1. **致命的全局关键帧命名断层（Silent Keyframe Break）**：
   - 全局基础设计层 [`design-system.css:28`](file:///c:/Software/conex/apps/crish-desktop/src/styles/design-system.css#L28) 中定义的是 `@keyframes crish-popover-enter` 与 `@keyframes crish-popover-exit`；
   - 然而，核心通用组件 [`Menu.module.css:38`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Menu/Menu.module.css#L38)、[`Select.module.css:168`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Select/Select.module.css#L168) 以及 [`PermissionModeMenu.module.css:148, 167`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/PermissionModeMenu.module.css#L148) 却全部引用了**全仓根本不存在的 `@keyframes cds-popover-enter` 与 `cds-popover-exit`**；
   - 浏览器在解析到不存在的 keyframe 名称时，直接判定动画为无效并跳过，导致这批下拉菜单在点击展开时处于**完全 0ms 瞬间生硬闪现**的死寂状态。

2. **CSS 选择器特异性劫持（Specificity Cascade Override）**：
   - 即使部分组件试图在自己的 module 中修正动画（如 [`ModelBadgePickerMenu.module.css:13`](file:///c:/Software/conex/apps/crish-desktop/src/components/provider/ModelBadgePickerMenu.module.css#L13) 正确书写了 `crish-popover-enter`）；
   - 但因为其底层通过 `<Menu panel={{ contentClassName: styles.mbMenu }}>` 渲染，DOM 同时挂载了 `styles.menuContent` 与 `styles.mbMenu`；
   - `Menu.module.css:37` 使用了 `[data-state='open']` 属性选择器，特异性（`0-2-0`）高于 `ModelBadgePickerMenu` 的纯类选择器 `.mbMenu`（`0-1-0`），导致失效的 `cds-popover-enter` 反向强行覆盖了正确的动画定义，使修复徒劳无功。

3. **核心复用基座 `SmartExpandablePanel` 动画全面裸奔**：
   - 支撑了桌面端核心业务的浮层基座 [`SmartExpandablePanel.module.css:5-22`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/SmartExpandablePanel/SmartExpandablePanel.module.css#L5-L22) 的 `.panel` 主容器以及 `.cascadeSubmenu`（二级级联子菜单，行 324-340），**从头到尾没有任何 `animation` 声明**；
   - 依赖该基座的 `ProjectPickerMenu`（项目选择器）、`ComposePlusMenu`（加号菜单）、`ChatHeaderMore`（会话设置）、`SubagentHeaderPanel`（子智能体面板）、`ToolTabAddButton`（分屏标签页添加），全部表现为瞬态生硬突兀弹出。

4. **锚定点失真与方向逆行动态（Transform-Origin & Direction Inversion）**：
   - 多处组件将 `transform-origin` 死锁为 `top left` 或未声明（默认 `50% 50%` 中心缩放），完全忽视了 Radix UI 注入的动态变量 `--radix-popover-content-transform-origin`；
   - 现有入场动画只有单向的向下偏移 `translateY(-4px)`。当菜单在页面下方被触发（例如在输入框顶部向上展开的 `ComposePlusMenu` 或 `PermissionModeMenu`）时，菜单本应从下往上轻微升起，现有的向下位移导致浮层呈现**反向撞击触发按钮**的穿模与违和感。

5. **触发器 Chevron 箭头旋转微交互大面积空缺**：
   - 用户截图中清晰可见的“下拉展开时小箭头顺滑 180° 翻转”（从指向下平滑旋至指向上），在现存代码中几乎全盘缺失：
     - `ComposerProjectPicker`：按钮内渲染了 `<AppIcon name="chevron-down" />`，但 CSS 没有任何旋转规则，展开时箭头纹丝不动；
     - `SelectTrigger` & `Combobox`：虽然定义了 transition 属性，但未挂载任何 `.open .chevron` 旋转规则；
     - 仅 `PermissionModeMenu` 写了旋转，但使用的是线性仓促的 `100ms ease`，视觉质感偏硬。

6. **退出动画被强制掐灭（Destructive Unmount）**：
   - [`Menu.module.css:41-44`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Menu/Menu.module.css#L41-L44) 对 `[data-state='closed']` 暴力配置了 `animation: none; display: none;`；
   - 这直接导致 Radix UI 内部的 `react-presence` 动画等待机制失效，在点击外部或选中选项时，浮层像被瞬间“物理切除”一样瞬间黑屏消失，毫无退场收束感。

#### 根因剖析

- 在历史重构过程中，部分样式文件将 `crish-` 前缀误写或遗留为了 `cds-`（Crish Design System 缩写）；
- 全仓没有任何地方声明 `@keyframes cds-popover-enter`。在 CSS 规范中，引用未声明的 `@keyframes` 属于无操作（No-op），动画引擎直接跳过执行；
- **受灾面**：全桌面端凡是直接或间接基于 `ui/Menu`、`ui/Select` 的下拉菜单，入场动画全部瘫痪。

### 3.2 选择器特异性冲突：高特异性幽灵规则覆写有效动画

1. 模型选择器面板 [`apps/crish-desktop/src/components/provider/ModelBadgePickerMenu.module.css:1-13`](file:///c:/Software/conex/apps/crish-desktop/src/components/provider/ModelBadgePickerMenu.module.css#L1-L13)：

3. `Menu.tsx` 内部类名拼合 [`apps/crish-desktop/src/components/ui/Menu/Menu.tsx:275-301`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Menu/Menu.tsx#L275-L301)：

   const contentClasses = [styles.menuContent, contentClassName].filter(Boolean).join(' ');

   <Popover.Content className={contentClasses} ...>

#### 根因剖析

- 最终渲染的 DOM 元素为 `<div class="menuContent mbMenu" data-state="open">`；
- CSS 特异性计算：
  - `.menuContent[data-state='open']`：一个类选择器 + 一个属性选择器 $\to$ 特异性为 `(0, 2, 0)`；
  - `.mbMenu`：单一类选择器 $\to$ 特异性为 `(0, 1, 0)`；
- 浏览器强制采用 `(0, 2, 0)` 的规则，即 `Menu.module.css` 中的 `animation: cds-popover-enter`。原本在 `ModelBadgePickerMenu.module.css` 中写对的 `crish-popover-enter` 被**彻底覆盖并杀死**。

## 4. 工业级丝滑微交互动效规范与数学基准

### 4.1 时间与速度曲线收敛（140ms / 100ms / 150ms）

遵从 `AGENTS.md` 铁律与 Apple 物理流体动效体系，全桌面端下拉微交互统一收敛为三档黄金时间节奏：

```
[ 入场 (Enter) ] : 140ms ~ 150ms  -- cubic-bezier(0.16, 1, 0.3, 1)  (var(--ease-emphasized))
[ 离场 (Exit)  ] : 100ms          -- cubic-bezier(0.4, 0, 1, 1)      (加速渐隐，毫不粘滞)
[ 箭头 (Chevron)] : 150ms          -- cubic-bezier(0.16, 1, 0.3, 1)  (与浮层展开同频呼吸)
```

- **数学解析**：`cubic-bezier(0.16, 1, 0.3, 1)`（Ease Emphasized）在时间轴 $t=0.3$ 时已完成超过 70% 的位移，给用户以极其轻盈、灵敏的即时响应；随后在后半段优雅减速入位，视觉干净利落。

### 4.2 双向微位移与缩放矩阵（Top / Bottom 双极性）

为根除“向上展开时向下撞击”的物理悖论，必须引入基于 Radix `data-side` 的双向极性动画矩阵：

| 展开朝向（`data-side`）  | 初始帧（0%）                                           | 终态帧（100%）                                   | 默认锚点（`transform-origin`）                                 |
| :----------------------- | :----------------------------------------------------- | :----------------------------------------------- | :------------------------------------------------------------- |
| **`bottom`（默认向下）** | `opacity: 0; transform: scale(0.97) translateY(-4px);` | `opacity: 1; transform: scale(1) translateY(0);` | `var(--radix-popover-content-transform-origin, top center)`    |
| **`top`（向上展开）**    | `opacity: 0; transform: scale(0.97) translateY(4px);`  | `opacity: 1; transform: scale(1) translateY(0);` | `var(--radix-popover-content-transform-origin, bottom center)` |
| **`left`（向左展开）**   | `opacity: 0; transform: scale(0.97) translateX(4px);`  | `opacity: 1; transform: scale(1) translateX(0);` | `var(--radix-popover-content-transform-origin, right center)`  |
| **`right` / 级联子菜单** | `opacity: 0; transform: scale(0.97) translateX(-4px);` | `opacity: 1; transform: scale(1) translateX(0);` | `var(--radix-popover-content-transform-origin, left top)`      |

- **缩放系数校准**：原 `scale(0.95)` 或 `scale(0.96)` 在文字密集菜单中形变过大，导致字形在抗锯齿重采样时产生肉眼可见的发虚；**校准为 `scale(0.97)`**，既保留细腻的空间景深层次，又杜绝字形畸变。

### 4.3 严格零果冻弹跳与防过冲约束（Zero-Overshoot）

- **棘轮契约遵守**：严格遵守 [`motion-concentric-contract.test.ts:115-116`](file:///c:/Software/conex/apps/crish-desktop/src/styles/motion-concentric-contract.test.ts#L115-L116) 的硬性底线：
  ```ts
  // 严格防线：临界阻尼与衰减震荡下，y2 绝不允许 > 1.05 (彻底封杀 1.5 弹性过冲)
  if (y2 > 1.05) violations.push(...);
  ```
- 方案中采用的 `cubic-bezier(0.16, 1, 0.3, 1)` 其 $y_2 = 1.0$，单调凸函数，**绝对没有反弹过冲**，从数学原理上消灭任何“果冻上下弹跳”。

### 4.4 GPU 纯合成层与零 Reflow 准则（Compositor-Only）

- 浮层与箭头的动效属性**100% 限制在 `transform` 与 `opacity`**；
- 严禁通过动态改变 `height`、`padding` 或 `top/left` 实现展开动画；
- 在动画执行阶段声明 `will-change: transform, opacity;`，动画结束后通过 `forwards` 保持或在静止态由合成器自动回收，杜绝常驻显存泄漏。

## 6. 动效参数前后对比与风险评估矩阵

### 6.1 参数对比矩阵

| 组件 / 场景                    | 现有参数与实现                          | 优化后参数与规范                        | 预期视觉效果提升                               |
| :----------------------------- | :-------------------------------------- | :-------------------------------------- | :--------------------------------------------- |
| **入场时间 (`popover-enter`)** | `180ms`（偏软拖沓）或 `0ms`（死键失效） | **`140ms`** 黄金快出                    | 响应极快，手指点击与画面浮现零感知延迟         |
| **缓动曲线 (`easing`)**        | 未生效或内联 bezier                     | **`cubic-bezier(0.16, 1, 0.3, 1)`**     | 前 30% 迅速就位，后 70% 丝滑减速，绝对零弹跳   |
| **微位移距离 (`translateY`)**  | 固定 `-4px` 或 `0px`（纯淡入）          | **方向自适应 `±4px`**（按 `data-side`） | 消除向上展开时逆向撞击，物理空间逻辑 100% 自洽 |
| **缩放比例 (`scale`)**         | `0.95` ~ `0.96`（形变过大，字体发虚）   | **`0.97`**（微幅高级景深）              | 既有清晰层级感，又保全微小字体的锐利度         |
| **退场机制 (`popover-exit`)**  | `display: none`（0ms 硬生生抹去）       | **`100ms`** 快速淡出渐隐                | 视线收拢平缓，消除画面跳切与闪烁               |
| **Chevron 箭头旋转**           | 全仓大面积缺失（0° 静止死锁）           | **`180deg` / 150ms 同步翻转**           | 完美对齐用户现场截图，交互反馈笃定完整         |
| **加号按钮联动 (`plusBtn`)**   | 仅背景色渐变                            | **`rotate(45deg)` / 150ms**             | 加号顺滑转换为叉号，关闭意图一目了然           |

### 6.2 风险评估与防御策略

1. **Radix Popover 退出动画闪烁风险（Radix Presence Race）**：
   - _风险_：若在 `[data-state='closed']` 挂载 `animation`，若动画名称未匹配或未触发 `animationend`，可能导致元素延迟卸载或死锁留在 DOM；
   - _防御_：确保 `@keyframes crish-popover-exit` 在全局 `@layer` 或顶层绝对可靠定义，且动画时长硬编码在 `100ms`，并在 `tests` 中增加 Jest/Vitest 计时断言。
2. **Reduced Motion 无障碍体验**：
   - _规范_：已在 `reduced-motion.css` 中将 `--transition-popover-enter` 统一置为 `0ms !important`。在开启系统减少动画时，平滑降级为无动画，不产生视觉晕眩。
3. **低配机型与 Eco 性能模式**：
   - _规范_：`tokens.css` 中已声明 `html[data-perf-tier='eco']` 将全部过渡时间清零，动画全量走合成层，绝不占用 JS 主线程与 CPU 重排。
