### 3.1 CSS 选择器语法陷阱：Subsequent Sibling (`~`) 导致全局穿透与次序混乱

#### 详案声明规则
```css
/* DIM-01 声明规则 5 */
.listInner > [data-chat-flow-kind="user"] ~ [data-chat-flow-kind="assistant"]:not([data-followup="true"]) {
  margin-top: var(--chat-flow-gap-turn, 20px);
}
```

#### 语法陷阱剖析
- **CSS 标准定义**：
  - `A + B`：相邻兄弟选择器（Adjacent Sibling），**仅且仅当** B 紧随在 A 之后时生效；
  - `A ~ B`：后续兄弟选择器（Subsequent Sibling），只要 B 是 A 后面的**任意兄弟节点**，无论中间隔了多少其他元素，全部生效！
- **穿透破坏场景**：
  在多轮对话中，首个 User 消息出现后，后续列表中**所有的** Assistant 消息都会命中 `user ~ assistant`！
  即使中间隔了 `turn-process` 过程折叠卡片，或者在同一轮次中助手输出了两个非 followup 的独立分段，第二条 Assistant 依然会被该选择器强行注入 20px 间距，而不是标准的 16px 间隙；
- **审查建议**：必须将跨角色交替规则由 `~` 纠偏为直接相邻兄弟选择器 `+`：
  ```css
  .listInner > [data-chat-flow-kind="user"] + [data-chat-flow-kind="assistant"]:not([data-followup="true"]) {
    margin-top: var(--chat-flow-gap-turn, 20px);
  }
  ```

### 3.2 轮次转折视觉节奏断层：缺失 `Assistant + User` 规则

#### 现象穿透分析
- 审查 DIM-01 §1.3 声明的 6 条规则，详案只规定了 `User ~ Assistant`（20px），**完全没有定义 `Assistant + User`（即上一轮助手回答完毕后，用户发起新一轮提问）的垂直间距**！
- 在没有任何特定规则命中时，新轮次的用户提问只能退化为规则 3 的通用间隙：`16px`；
- **视觉心流破裂**：上一回合长篇大论的回答结尾，与下一回合全新的用户 Prompt 之间，仅仅相隔 16px（甚至比同回合提问到回答的 20px 还要紧凑！）。视觉上两个回合完全粘连在一起，破坏了对话轮次感。
- **审查建议**：显式补齐新轮次开启的相邻兄弟规则，注入清晰的 24px～28px 视觉呼吸留白：
  ```css
  .listInner > [data-chat-flow-kind="assistant"] + [data-chat-flow-kind="user"],
  .listInner > [data-chat-flow-kind="turn-process"] + [data-chat-flow-kind="user"] {
    margin-top: var(--chat-flow-gap-new-turn, 24px);
  }
  ```

### 3.3 虚拟滚动前置空垫片（Top Spacer）对 Sibling-combinator 的物理破防

#### 渲染内核事实
在 `MessageVirtualizer.tsx:228` 中：
```tsx
<div style={{ height: startOffset, flexShrink: 0 }} aria-hidden />
```
- 该元素是 `.listInner` 的首个子元素；
- **关键细节**：该元素声明的是 `aria-hidden`（可访问性无障碍隐藏），而**不是 HTML 原生属性 `hidden`**！
- 在 CSS 选择器语义中，`:not([hidden])` 会将该垫片判定为**可见元素**！

#### 物理破防推导
1. 当 `startIndex === 0` 且 `startOffset === 0` 时（首屏或顶部）：
   该垫片高度为 0，但真实存在于 DOM 中。紧随其后的第一条消息（`messages[0]`）由于前面存在一个 `:not([hidden])` 的兄弟，**直接匹配上了 `~ :not([hidden])` 规则**！
   导致首条消息顶部被凭空推开 16px，产生异常的顶部空隙！
2. 当发生虚拟滚动、视口滑移至中部时：
   `messages[startIndex]` 前面始终有 Top Spacer，因此始终持有 16px `margin-top`。
   然而，`VirtualScrollManager` 在计算几何前缀和时，`getOffset(startIndex)` 是纯高度累加，**并未将该 16px margin 计算在内**！
   这会导致虚拟窗口切片渲染的位置与 VSM 纯数学计算位置产生 **16px 的物理错位**，并在高速滚动中引发微小的视口跳动！
- **审查建议**：
  1. Top Spacer 必须显式增加 `data-vsm-spacer="top"` 属性，并在 `startOffset === 0` 时挂载原生 `hidden`；
  2. Sibling-combinator 规则必须严密排除垫片：
     ```css
     .listInner > :not([hidden]):not([data-vsm-spacer]) ~ :not([hidden]):not([data-vsm-spacer]) {
       margin-top: var(--chat-flow-gap, 16px);
     }
     ```
