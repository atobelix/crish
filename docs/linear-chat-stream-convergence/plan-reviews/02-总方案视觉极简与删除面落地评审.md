## 一、CSS 规范合规性穿透审查（Conex §12 / §13 / §14 纪律）

经对照仓库根目录 `AGENTS.md` 通用协作纪律，对总方案第 5、6、7 章给出的样式规范与设计代码进行逐行审查，发现以下合规性问题与防护漏洞：

### 1.1 Conex §12 纪律（Tooltip / 悬停提示）合规性核验

#### 现状代码事实
在现行 `ChatUserMessageRow.tsx` 中，存在直接使用原生 HTML `title` 的不合规代码：
- `ChatUserMessageRow.tsx:210`：`title={img.alt || '查看图片'}`；
- `ChatUserMessageRow.tsx:237`：`title={a.path || a.name}`。
原生 `title` 在 Windows WebView2 下会弹出系统默认灰黄色生硬气泡，严重破坏视觉一致性，明确违反 Conex §12（“始终使用项目自定义 `<Tooltip>` 组件，不要用原生 HTML title”）。

#### 总方案审查与漏审盲区
1. **用户气泡改造未明确清理原生 title**：总方案第 7.2 章重构了气泡的几何学与圆角，但未在逻辑任务清单中明确要求将上述两处原生 `title` 替换为 `<Tooltip>` 组件；
2. **24px ToolRow 截断文本缺乏 Tooltip 映射**：
   - 审查总方案第 5.5 章给出的组件骨架（`ToolRow.tsx:783-787`）：
     ```tsx
     <span className={`${styles.toolSummary} ${isRunning ? styles.toolSummaryLive : ''}`}>
       {summary}
     </span>
     ```
   - 在旧实现 `ToolCallHeader.tsx:92-139` 中，超长摘要由 `<Tooltip content={human}>` 或 `<Tooltip content={filePath}>` 严密包裹；
   - 总方案在推行 24px 极简单行规范时，直接裸写了 `{summary}`，且未引入 `<Tooltip>`！由于参数被 CSS `text-overflow: ellipsis` 强行截断，用户将**彻底丧失查看完整参数与执行详情的悬停入口**。如果后续实现者随手补上一句 `title={summary}`，将立刻诱发 Conex §12 违规！
3. **修订要求**：
   - 在 `ToolRow` 中必须显式引入项目标准 `<Tooltip>`：
     ```tsx
     <Tooltip content={summary || humanLabel} delayDuration={300}>
       <span className={styles.toolSummary}>{summary}</span>
     </Tooltip>
     ```
   - 且必须注意：`<Tooltip>` 容器在 24px Flex 布局中不可产生额外的 `display: inline` 折行容器，须配置 `asChild` 或确保内部元素拥有正确的 flex 伸缩属性。

### 1.2 Conex §13 纪律（输入框、焦点态与克制阴影）合规性核验

#### 现状与总方案审查
Conex §13 明确规定：“默认不要重阴影；任何情况下焦点/激活态不得使用硬实线；相对基线，灰色加深混入文本色不超过约 10%（例如 `color-mix(in srgb, var(--border-color) 90%, var(--text-primary) 10%)` 为上限量级）；常规元素优先约 3%–6% 混入以保持柔软。”

1. **常态气泡阴影审查（合格）**：
   - 总方案第 7.5 章（L1077-1081）提出的发丝内嵌阴影：
     ```css
     box-shadow:
       0 0 0 0.5px color-mix(in srgb, var(--text-primary) 6%, transparent),
       0 1px 2px 0 rgba(0, 0, 0, 0.03);
     ```
   - 其扩散环采用 6% 文本色混入，严格落在 Conex §13 的 3%~6% 推荐区间内，质感柔和克制。
2. **致命漏审：键盘焦点态（`:focus-visible`）完全裸奔**：
   - 在 `ChatUserMessageRow.tsx:180-189` 中，当用户文本超长（`isLong=true`）时，气泡被赋予了交互角色：`role="button"`、`tabIndex={0}`；
   - 在总方案第 5.5 章中，`ToolRow` 整行被定义为 `<button type="button" className={styles.toolRowHeader}>`；
   - **审查发现**：总方案在第 5 章和第 7 章的全部 CSS 规范中，**完全没有声明 `.userBubble:focus-visible` 与 `.toolRowHeader:focus-visible` 的样式！**
   - **运行时灾难**：当用户通过键盘 Tab 键进行可访问性导航时，浏览器内核（WebView2）会强制触发默认的高对比度粗黑边框（`outline: 2px solid #000`），不仅将 22px 超椭圆气泡打得支离破碎，更直接击穿 Conex §13 的 10% 对比度红线！
3. **修订要求**：必须在 CSS 规范中显式补齐软环焦点声明：
   ```css

   .userBubble:focus-visible,
   .toolRowHeader:focus-visible,
   .reasoningRow:focus-visible {
     outline: none;
     box-shadow:
       0 0 0 0.5px color-mix(in srgb, var(--text-primary) 6%, transparent),

### 2.1 24px 高度盒模型与垂直居中物理精度

```

| [16px 槽位]  gap:6px  [13px 标题]  gap:8px  [2x2 圆点]  gap:8px  [13px 参数摘要]  [等宽后缀]    |

#### 代码事实比对与排版陷阱
- **现状代码**：`ChatToolCallBlock.module.css:70-71` 中 `.toolRowHead` 为 `min-height: 32px; padding: 6px 8px;`，行高被撑开至 32px 以上；

- **物理精度陷阱**：
  1. **内边距溢出**：若沿用任何纵向 padding（例如 `padding: 4px 8px`），在 24px 总高度限制下，内容区域仅剩 16px，而 13px 文字搭配 `line-height: 24px` 必将导致文字顶部或底部被裁切；

### 2.2 超长参数截断机制与 Flex 弹性收缩死角

在 Agent 执行真实工具调用时，参数通常极其冗长（例如包含长达 200 字符的文件绝对路径或带有管道符的 Bash 脚本）。

#### Flex 截断断裂点审查
在 Flexbox 规范中，元素的默认 `min-width` 为 `auto`。当子元素包含不换行超长文本时，容器会被无条件撑爆，导致 `text-overflow: ellipsis` 彻底失效！
审阅总方案第 5.1 与 5.5 章，发现未对 Flex 传导链进行完整闭环声明。

#### 建设性修订：完整的 Flex 刚性传导防线
为保证在 `--chat-col-max: 760px` 乃至小屏 360px 下参数绝不撑爆，必须确立四级约束：
1. **行头容器**：`.toolRowHeader { width: 100%; min-width: 0; }`；
2. **前置固定要素**：
   - `.toolIconSlot { flex-shrink: 0; width: 16px; }`
   - `.toolTitle { flex-shrink: 0; font-weight: 500; font-size: 13px; }`
   - `.dotSeparator { flex-shrink: 0; }`
3. **弹性截断要素**：
   ```css
   .toolSummary {
     flex: 0 1 auto;
     min-width: 0; /* 核心守门：允许收缩至 0px */
     overflow: hidden;
     text-overflow: ellipsis;
     white-space: nowrap;
     color: var(--text-secondary);
     font-size: 13px;
   }
   ```
4. **后置固定要素**：
   - 耗时或状态圆点必须带 `flex-shrink: 0; margin-left: auto;`，保证无论参数被截断到多短，右侧的耗时信息（如 `1.2s`）永远完整显示且不会被挤出视口。

### 2.3 槽位 100ms 原地替换（Chevron Swap）重绘表现与可访问性审查

总方案第 5.2 章提出了一个极具创意的交互方案：在左侧 16px 槽位内，通过鼠标悬停实现 ToolKindIcon（类型图标）与 ChevronIcon（折叠箭头）的原地 100ms 交叉淡入淡出，保持右侧文字 0 像素晃动。

#### 1. 合成器图层与重绘表现（优异）
- 方案仅对 `opacity` 与 `transform` 声明 `transition: 100ms ease`；
- 在现代 Chromium（WebView2）渲染管线中，`opacity` 与 `transform` 属于纯合成器属性（Compositor-only），**完全不会触发 Layout（回流），也不会触发主线程 Paint（重绘）**；
- **微小瑕疵**：当消息流中存在连续 30 个工具行且鼠标快速滑过时，频繁触发的动态图层提升可能引发 GPU 内存抖动。
  - **加固建议**：为 `.toolIconSlot` 添加 `contain: paint;`，切断一切图层溢出。

#### 2. 可访问性（a11y）与键盘失焦缺陷（重大漏洞）
总方案给出的 CSS 选择器为：
```css
.toolRow:hover .toolKindIcon { opacity: 0; transform: scale(0.85); }
.toolRow:hover .toolChevronIcon { opacity: 1; transform: scale(1); }
```
- **漏洞**：**只监听了 `:hover`，完全遗漏了键盘聚焦！**
- 当视障用户或纯键盘用户使用 Tab 键将焦点导航至 `ToolRow` 时，由于没有鼠标 hover，Chevron 图标永远是 `opacity: 0`；用户完全不知道这是一个可以按 Enter 展开的折叠器！
- **修复选择器**：必须同步支持 `:focus-visible` 与 `:focus-within`：
  ```css
  .toolRow:hover .toolKindIcon,
  .toolRow:focus-within .toolKindIcon {
    opacity: 0;
    transform: scale(0.85);
  }
  .toolRow:hover .toolChevronIcon,
  .toolRow:focus-within .toolChevronIcon {
    opacity: 1;
    transform: scale(1);
  }
  ```

#### 3. 静态不可折叠（Static/Non-expandable）行的假交互（Affordance Lie）
- 代码事实：在现行 `CompactToolRow.tsx:153` 中，通过 `const expandable = toolHasExpandableBody(tc);` 判断工具是否有内容可展开（部分轻量工具调用无详情）；
- 如果一个工具没有返回体、不可折叠，鼠标悬浮时**绝不能把工具图标替换为 Chevron 箭头**！否则用户点击后没有任何反应，构成交互欺骗；
- **修复方案**：槽位原地替换必须受 `[data-expandable="true"]` 属性门禁保护：
  ```css
  .toolRow[data-expandable="false"] .toolChevronIcon {
    display: none !important;
  }
  .toolRow[data-expandable="false"]:hover .toolKindIcon {
    opacity: 1 !important;
    transform: none !important;
  }
  ```

### 2.4 流式思考行 `latestLine` 动态追踪之布局排版物理缺陷

在总方案第 4.2 章中，提出流式思考行使用 `latestLine(text)` 追踪最新生成的文本，并给出以下排版建议：
> “容器标记 `data-follow-end="true"`，应用 CSS `justify-content: flex-end; text-align: right;`……右侧边缘始终固定展示最新产生的字符，形成如同打字机般的自然推进视效。”

#### 现场物理推演与视觉崩塌分析
请审查以下真实渲染场景：
1. 当大模型刚开始输出思维链时，缓冲区只吐出了三个字：“我想想”；
2. 按照方案的 `justify-content: flex-end; text-align: right;`，这三个字会瞬间**飞到整行 760px 宽度的最右侧末端**！
3. 此时整行的视觉效果为：
   `[›] [思考] [·] ---------------------------------------------------- [我想想]`
   左侧标签与右侧文字之间出现了长达 **500 像素的荒谬空白断裂**！
4. 随着模型持续吐字，文字向左反向生长，直到填满整行后才与左侧标签连接。这种“右侧反向填充”在 LTR（从左至右）阅读习惯中极其反直觉、令人眩晕。

#### 建设性修正方案
不要使用全局的 `text-align: right` 或 `justify-content: flex-end`。正确的流式追踪排版逻辑应为：
1. **短文本时（未溢出）**：采用标准的 `text-align: left`，紧贴在 `思考 · ` 之后自然流出；
2. **长文本时（发生溢出）**：保持 LTR 文字方向不变，但在 CSS 中启用 `direction: ltr` 配合内联平移，或者通过 `scrollLeft = scrollWidth` 自动滚至末尾，或者仅在文字宽度超过可用宽度时才添加 `data-follow-end` 类名；
3. **最极简优雅解**：
   ```css
   .reasoningSummary {
     display: inline-block;
     max-width: 100%;
     white-space: nowrap;
     overflow: hidden;
     text-overflow: ellipsis;
     /* 纯自然流：左侧对齐，尾部追加柔和微光，无需反向跳动 */
     text-align: left;
   }
   ```
   这种处理方式既保证了短文本时不漂移，又保证了长文本时平稳截断，彻底消除“右侧跳字”病灶。

## 三、架构内部矛盾穿透审查：单一滚动宿主 vs 专有卡片局部滚动

## 四、DOM 嵌套合规性穿透审查：原生按钮与交互卡片

### 4.1 HTML 规范违背：嵌套交互元素（Nested Interactive Controls）

在总方案第 5.5 章中，给出的组件骨架为：
```tsx
export const ToolRow: React.FC<ToolRowProps> = ({ ... }) => {
  return (
    <div className={styles.toolRowWrapper}>
      <button
        type="button"
        className={styles.toolRowHeader}
        onClick={() => onToggle(toolCall.id)}
      >
        <div className={styles.toolIconSlot}>...</div>
        <span className={styles.toolTitle}>{humanLabel}</span>
        <span className={styles.toolSummary}>{summary}</span>
      </button>
      ...
    </div>
  );
};
```
与此对应，总方案第 5.4.3 章（Read / Search 卡片）要求：
> “Hover Underline 胶囊：文件路径悬浮时出现发丝下划线……点击直接调用 Tauri 后端命令 open_in_editor……键盘防误折叠：监听 Space 与 Enter 键，在用户操作路径链接时通过 e.stopPropagation() 阻止触发外部行折叠。”

#### 致命语法与运行时冲突
- **W3C HTML 规范铁律**：`<button>` 元素内**严禁包含任何交互式内容（Interactive Content）**，包括 `<button>`、`<a>`、`<input>` 等；
- 如果 `.toolRowHeader` 是一个 `<button>`，当文件名或路径链接本身也是一个可点击按钮（或包含复制按钮）时，将产生 `<button><button>path</button></button>` 的嵌套结构；
- **浏览器的破坏性行为**：现代浏览器内核遇到嵌套 button 时，会在解析阶段强制闭合外层 button，导致 React 的 Virtual DOM 与真实 DOM 树严重错位，引发 Hydration Error、点击事件冒泡错乱，甚至导致外部折叠动作与内部路径打开同时被触发！

#### 建设性修复方案
1. **方案一（ARIA 语义替代法，对齐现有稳健做法）**：
   保留外部为 `div`，通过标准 ARIA 属性赋予按钮行为：
   ```tsx
   <div
     className={styles.toolRowHeader}
     role="button"
     tabIndex={0}
     aria-expanded={isExpanded}
     onClick={() => onToggle(toolCall.id)}
     onKeyDown={handleRowKeyDown}
   >
   ```
   内部的路径胶囊和复制按钮作为子交互元素，通过 `e.stopPropagation()` 阻止事件上浮，完全符合 HTML 规范与无障碍基线。
2. **方案二（分列插槽法）**：
   采用 Grid 布局，将整行分为 `[展开控制区（button）] [路径可点击区（独立button）] [后缀]`，从 DOM 树结构上彻底解耦嵌套。

### 7.2 建议二：建立单一滚动宿主 DOM 树纯洁性扫描断言（`ScrollerPurity.test.tsx`）

- **痛点**：行内组件开发者容易不自觉地加入 `overflow-y: auto` 与 `max-height`，导致多滚动条恶疾反复回潮。
- **刚性防护实现**：在集成测试中挂载完整的 `ChatMessageList`，深度遍历渲染后的 DOM 树：
  ```ts
  it('除虚拟滚动主容器外，会话列表内部任何子节点严禁存在有效纵向滚动轨道', () => {
    const { container } = render(<ChatMessageList messages={mockMessagesWithAllNodeTypes} />);
    const scrollNodes = Array.from(container.querySelectorAll('*')).filter((el) => {
      const style = window.getComputedStyle(el);
      const isScroll = style.overflowY === 'auto' || style.overflowY === 'scroll';
      const isMainScroller = el.classList.contains('virtual-scroller-main');
      return isScroll && !isMainScroller;
    });

    // 强制断言违规微型视口数为 0
    expect(scrollNodes).toHaveLength(0);
  });
  ```

### 7.3 建议三：建立 24px 单行极简尺寸隔离门禁（`ToolRowContainment.test.tsx`）

- **痛点**：流式生成时子元素尺寸外溢引发全局 ResizeObserver 频繁触发与视口抖动。
- **刚性防护实现**：通过测试提取编译后的 CSS Module 或检查真实挂载样式：
  ```ts
  it('24px 极简工具单行必须严格声明 contain: size layout 与固定高度', () => {
    const { container } = render(<ToolRow toolCall={mockTool} isExpanded={false} />);
    const row = container.querySelector(`.${styles.toolRowHeader}`) as HTMLElement;

    expect(row).not.toBeNull();
    expect(row.style.contain || getComputedStyle(row).contain).toMatch(/size/);
    expect(row.style.height || getComputedStyle(row).height).toBe('24px');
  });
  ```
