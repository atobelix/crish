## 二、重点审查项一：维度三（DIM-03）24px 极简思考行深度核对

### 1. 24px 尺寸隔离机制（`contain: size layout`）与盒模型防坍塌

在深层思考模型（如 DeepSeek-R1、Claude 3.7 Extended Thinking）流式输出期间，每秒数十个 Token 持续涌入。DIM-03 在 `ReasoningRow.module.css` 中建立了硬件级尺寸隔离机制：

- **硬件级尺寸隔离**：
  ```css
  /* 未展开态严格执行 24px 硬件级尺寸隔离，切断流式回流风暴 */
  .reasoningContainer:not([data-expanded='true']) {
    contain: size layout;
    height: 24px;
    min-height: 24px;
    max-height: 24px;
    box-sizing: border-box;
    overflow: hidden;
  }
  ```
  `contain: size` 强制浏览器在计算外部文档流布局时，完全忽略内部文本尺寸，仅以声明的 24px 高度参与宿主计算；`contain: layout` 彻底阻断了内部文本变化对外部祖先节点的 Reflow 冲击。
- **Chromium `<button>` 盒模型防坍塌加固**：
  在 Chromium/Blink 内核中，原生 `<button>` 在 `contain: size` 下极易水平坍塌为 0px。`ReasoningRow.module.css:25-48` 显式声明：
  ```css
  .reasoningRow {
    display: flex;
    width: 100%;
    max-width: 100%;
    height: 24px;
    min-height: 24px;
    max-height: 24px;
    box-sizing: border-box;
    contain: size layout;
    align-items: center;
    margin: 0;
    padding: 0 var(--space-1, 4px);
    border: none;
    background: transparent;
    cursor: pointer;
    overflow: hidden;
  }
  ```
  `ReasoningRow.test.tsx` 中第 62–78 行建立了永久 CSS 样式断言，验证了 24px 与盒模型的绝对刚性。

### 2. 512B 尾窗切片（`extractLatestLine`）与首窗切片（`extractFirstLine`）算法

- **$O(1)$ 复杂度保证**：
  在 `ReasoningRow.tsx:51-113` 中实现了仅截取头部或尾部至多 512 字符的纯函数：
  ```ts
  export function extractLatestLine(text: string): string {
    if (!text) return '';
    const tail = text.length > 512 ? text.slice(-512) : text;
    const trimmed = tail.trimEnd();
    if (!trimmed) return '';
    const lastReal = Math.max(trimmed.lastIndexOf('\n'), trimmed.lastIndexOf('\r'));
    const lastLit = trimmed.lastIndexOf('\\n');
    let line = trimmed;
    if (lastReal >= 0 && lastLit >= 0) {
      line = lastReal > lastLit ? trimmed.slice(lastReal + 1) : trimmed.slice(lastLit + 2);
    } else if (lastReal >= 0) {
      line = trimmed.slice(lastReal + 1);
    } else if (lastLit >= 0) {
      line = trimmed.slice(lastLit + 2);
    }
    return line.trim();
  }
  ```
  该实现不仅处理了真实系统换行符（`\n`、`\r`），而且兼容了字面量 `\n`。
- **性能实测**：
  在 `ReasoningRow.test.tsx:16-28` 的基准用例中，面对 **3000 行、约 60KB** 的超长前缀历史思考文本，`extractLatestLine` 执行耗时实测为 **$0.02\text{ms} \sim 0.04\text{ms}$**，远低于 0.5ms 的预算上限，在整个流式生命周期内杜绝了 V8 垃圾回收（GC）停顿。
