## 一、评估结论先行：DIM-01 与 DIM-05 的划分合理性与耦合度深度评估

### 1.1 划分合理性与冲突隐患诊断
在主控初始拟定的维度划分中：
- **DIM-01** 设定为「重复与死层清理及巨石 CSS 拆解」（关注 `ChatMessageRow.module.css` 28KB、`ChatAssistantMessageRow.tsx` 双写类名、废弃卡片样式）；
- **DIM-05** 设定为「纯净画纸排版与 70.2% 气泡规范」（关注剥离 Assistant 外层卡片框线、落地 70.2% 宽比与 22px 超椭圆气泡、操作栏外置下沉 6px）。

**交叉验证核心结论**：
**DIM-01 与 DIM-05 在概念划分上明确，但在物理实现层存在「同文件 100% 深度重叠」的严重冲突隐患**。
1. **核心修改靶心完全重合**：两者的第一核心修改对象均为 `ChatMessageRow.module.css`、`ChatAssistantMessageRow.tsx`、`ChatUserMessageRow.tsx`。
2. **违反同文件串行铁律**：仓库根目录 `AGENTS.md` §3 及调度纪律明文规定「同文件串行，严禁多 Agent 并发写入同一文件」。若将 DIM-01 与 DIM-05 作为两个独立子 Agent 同时派发，势必引发激烈的 Git 冲突与代码回撤事故；
3. **语义互逆但操作一体**：在 Assistant 消息体中，「剥离外层卡片框线（DIM-01 的死层清理）」与「打造零外框纯净画纸（DIM-05 的画纸排版）」本质上是**同一套 DOM 重构与样式覆写的正反两面**；在 User 消息体中，「清理 userBubble 历史不对称圆角与多余 padding（DIM-01）」与「落地 22px 超椭圆与 42px 几何单行（DIM-05）」亦是同一段 CSS 代码的替换。

### 1.2 维度编排建议：重构融合或严格双阶序列锁
为保证战役平稳推进，本分析员提出两种可行的收敛路线：

- **方案 A（强烈推荐：融合为单一核心大维度）**：
  将 DIM-01 与 DIM-05 深度整合成 **「DIM-01: 纯净画纸排版、70.2%气泡与巨石样式死层清剿（Visual & Dead Layer Convergence）」**。
  - 由同一子 Agent / 同一实现流贯通执行：**先删死代码与死层 DOM → 再行巨石 CSS 拆分 → 同步落地 70.2% 黄金律与极简画纸规范**。
  - 收益：消除一切跨维度合并冲突，全流程一气呵成，行数净收敛彻底。
- **方案 B（双阶段序列阻断锁，维持 5 维度编制）**：
  若战役必须维持 5 个维度的既定编排，则必须在调度协议中施加**强序约束（Sequential Barrier）**：
  - **Stage 1 先行**：DIM-01 作为战役第一波先锋，**仅做减法与解耦**——彻底删除死样式、剥离异构子组件 CSS、清除 DOM 死层，使 `ChatMessageRow.module.css` 净瘦身；待 DIM-01 完全落盘验收后；
  - **Stage 2 跟进**：DIM-05 启动，在已瘦身的轻量样式骨架上，专注注入冷蓝灰设计 Token、22px 超椭圆气泡与外置下沉 6px 规范。

## 三、硬编码阴影、多重边框与设计规范（DIM-05）差距审查

依据 `docs/linear-chat-stream-study/04-UI设计规范与极简视觉样式体系对比.md` 与根目录 `AGENTS.md` §13、§14 铁律，盘点当前样式表中的视觉毒点：

### 3.1 违背暗色/亮色自适应与硬编码问题
1. **硬编码深色值 Fallback（L101-102）**：
   ```css
   .userImageWrapper {
     border: 1px solid var(--border-subtle, rgba(255, 255, 255, 0.08));
     background: var(--bg-card, #1e1e1e);
   }
   ```
   - 违背规范：直接使用 `rgba(255, 255, 255, 0.08)` 与 `#1e1e1e` 作为 fallback，在 Light 亮色主题下直接导致背景发黑、边框发白失效。
2. **硬编码纯黑投影（L979-980）**：
   ```css
   .flowPlanStepNum {
     border: 1px solid var(--border-color, rgba(0, 0, 0, 0.15));
     box-shadow: 0 1px 2px rgba(0, 0, 0, 0.03);
   }
   ```
   - 违背规范：直接使用硬编码 `rgba(0, 0, 0, 0.03)` 投影，破坏了现代语义 Token 体系。

### 3.2 负 Margin 暴力拉伸与布局破坏（L22-31）
```css
.row.searchHit {
  background: color-mix(in srgb, var(--accent-color) 8%, transparent);
  border-radius: var(--radius-xl);
  padding: 4px 6px;
  margin-left: -6px;
  margin-right: -6px;
  width: calc(100% + 12px);
  max-width: calc(min(var(--chat-col-max, 760px), 100%) + 12px);
  box-sizing: border-box;
}
```
- **架构诊断**：使用 `-6px` 负边距与 `calc(100% + 12px)` 进行背景拉伸，这在虚拟滚动容器中会触发极其恶劣的横向水平溢出（Horizontal Overflow）和亚像素抖动，违背 `AGENTS.md` §7「严禁临时补丁」要求。

### 3.3 与 Figma 标杆（DeepSeek-Harness）规范差距
| 视觉要素 | 当前 Conex 现状（`ChatMessageRow.module.css`） | Figma 标杆规范（`04-UI设计规范...`） | 收敛落地指导 |
|---|---|---|---|
| **用户气泡圆角** | L66: `border-radius: 14px 14px 4px 14px;`（老旧尖角） | **22px 超椭圆（Superellipse）平滑圆角** | 统一为 `border-radius: 22px;`，消除尖角 |
