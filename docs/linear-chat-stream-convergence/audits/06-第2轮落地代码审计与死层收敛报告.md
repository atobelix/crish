## 三、重点审查项二：垂直间距体系与 16px 幽灵空白防护

### 1. 相邻兄弟选择器（Adjacent Sibling-combinator）接管垂直节奏

```css
  margin-top: 16px;

```

### 2. Spacer 的 `hidden` 属性防护机制（根除首行 16px 幽灵空白）

- **问题病灶**：在虚拟滚动体系中，列表顶部存在一个用于几何占位的 Spacer（`height: startOffset`）。若直接使用常规相邻兄弟选择器 `* + *`，第一条真实渲染的消息行会紧跟在 Spacer 之后，被错误赋予 `margin-top: 16px`，导致列表顶部产生无法消除的 16px 幽灵空白。
- **精确解法审查**：
  1. 在 `MessageVirtualizer.tsx:354` 与 `431` 中，向顶部与底部 Spacer 显式注入 HTML 原生 `hidden` 属性：
     ```tsx
     <div
       hidden
       data-vsm-spacer=""
       style={{ height: startOffset, flexShrink: 0 }}
       aria-hidden
     />
     ```
  2. 在 `ChatMessageList.module.css:51-53` 中，通过 CSS 规则强制恢复 Spacer 的几何占位渲染：
     ```css
     [data-vsm-spacer] {
       display: block;
     }
     ```
  3. **选择器穿透分析**：
     - Spacer 带有 `hidden` 属性，因此它**不匹配** `:not([hidden])`；
     - 第一条真实消息的前驱是 Spacer（未命中 `:not([hidden])`），因此第一条消息**绝不会触发** `:not([hidden]) + :not([hidden])`，其 `margin-top` 保持为 `0`；
     - 第二条真实消息的前驱是第一条真实消息（两者均命中 `:not([hidden])`），精准获得 `margin-top: 16px`；
     - 当发生滚动产生 `startOffset > 0` 时，Spacer 维持 `display: block` 撑开视口，且首条切片消息依然不受 16px 挤压。
- **Typography Token 测试验收**：
  执行 `npx vitest run apps/crish-desktop/src/components/chat-message-row/__tests__/typography-token.test.ts`：
  - **14 项断言全量通过（14 passed in 6ms）**。
  - 验证了 H1~H6 阶梯字号、段落垂直韵律、末尾段落 `margin-bottom: 0` 归零规则及微排版规范全部符合设计基线。

### 2. 相对滚动坐标算法（`useScrollAnchor.ts`）彻底取代 `scrollIntoView`

- **原生跳动病灶切除**：彻底删除了 `el.scrollIntoView({ behavior: 'smooth', block: 'center' })`；
- **纯坐标居中算法**：
  ```typescript
  const diff = elRect.top - scrollerRect.top;
  let relativeOffsetTop = diff + scroller.scrollTop;
  // 亚像素与 jsdom 环境回退：沿 offsetParent 链累加 offsetTop
  if (diff === 0 && (el.offsetTop > 0 || curr !== scroller)) { ... }
  const viewportHeight = scroller.clientHeight;
  const targetHeight = el.clientHeight;
  let targetScrollTop = relativeOffsetTop;
  if (viewportHeight > 0) {
    targetScrollTop = relativeOffsetTop - Math.max(0, (viewportHeight - targetHeight) / 2);
  }
  scroller.scrollTop = Math.max(0, targetScrollTop);
  ```
- **算法优势**：只计算当前消息相对唯一滚动宿主的绝对偏移量，并仅向宿主写入 `scroller.scrollTop`，绝对不触碰上层祖先容器（如桌面全局布局、分栏面板），根除了祖先视口被动向上扯动的顽疾。
