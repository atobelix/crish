## 一、主控亲自阅读代码之客观事实记录

### 1. 视口滚动与锚定现状：双重滚动子系统与魔术数字
- **事实 1（ChatMessageList.tsx:139-142）**：搜索高亮消息跳转依然采用 `window.setTimeout(() => { scrollToMessage(id); }, 40)` 魔术延时，在列表长程滚动时由于虚拟列表高度未测量，极易跳脱；
- **事实 2（MessageVirtualizer.tsx:62-120）**：`useVirtualScroll` 依赖 `ResizeObserver` 在 DOM 渲染后异步回调 `setActual(msgId, height)`；当大段思考或工具折叠引起高度剧烈缩小时，浏览器内核的地表收缩钳位（Floor Clamping）会触发原生 `scroll` 事件，虚拟列表当前缺少 `observedTopRef` 单一账本，导致误判为“用户手动滚离底部”；
- **事实 3（TimelineThoughtSection.tsx:34-59）**：折叠思考组件内部居然自建了一套独立的滚动系统（`userScrolledUpRef`，`scrollHeight - (scrollTop + clientHeight) > 36`，`el.scrollTop = el.scrollHeight`），在虚拟列表容器内形成了**外层虚拟滚动与内层思考滚动的嵌套内耗**。

### 1.2 过程折叠现状：缺失轮次过程收敛
- **事实 4（MessageContent.tsx:76-120）**：时间线主体（`TimelineBody`）对 `thought`、`tool`、`text` 采取平铺并联渲染；
- **事实 5（MessageToolCallsSection.tsx:27-48）**：当一个 Agent 连续执行 10 次工具调用时，无条件展开所有工具或生成占地巨大的卡片堆叠；在当前轮次结算（Turn Closed）后，**没有任何机制将其收拢为单行发丝线折叠栏**，导致数千像素的“工具卡片瀑布”隔断了用户问题与最终答案。

### 1.3 思考过程表现：缺乏单行流式追踪与零重排隔离
- **事实 6（TimelineThoughtSection.tsx:78-140）**：当前思考块要么是静态折叠（`思考了 3.4秒 >`），要么直接展开为大段 Markdown 滚动区域。在流式生成中，**缺乏像标杆那样的 24px 单行固定高度（`contain: size layout`）、单行最新 Token 追踪（`latestLine` + `justify-content: flex-end`）与 2.6s 跑马灯微光动效**，导致生成时外层列表高频抖动。

### 1.4 视觉样式现状：28KB CSS 巨石与冗余类名
- **事实 7（ChatAssistantMessageRow.tsx:106-114）**：存在大量的历史双写类名：
  `className={`${styles.row} ${styles.rowAssistant} msg-row msg-row-assistant ...`}`
  CSS Module 与全局 class 混杂；
- **事实 8（ChatMessageRow.module.css）**：体积高达 **28,337 字节**，充斥着针对不同历史卡片、不同边框、重度阴影的废弃样式，且 Assistant 消息外层依然带有容器框，严重违背了“内容即画纸”的极简哲学；
- **事实 9（ChatUserMessageRow.tsx:140-190）**：用户气泡宽度未建立 70.2% 严格约束，操作按钮依然嵌入在气泡区域，缺少外置下沉 6px 的视觉呼吸空间。

## 二、主控初始维度拆解框架

基于上述代码事实，主控确立本战役的 **5 个初始维度**（必须包含一个「重复与死层」基石维度）：

| 维度编号 | 维度名称 | 核心关注领域与代码范围 | 预设收敛目标 |
|---|---|---|---|
| **DIM-01** | **重复与死层清理及巨石 CSS 拆解** | `ChatMessageRow.module.css`（28KB）、`ChatAssistantMessageRow.tsx` 双写类名、废弃卡片样式、`setTimeout` 延时补丁 | 强制负产出：删除无用样式行 ≥ 500 行，清理双写类名与嵌套内耗 |
| **DIM-02** | **视口防抖与自适应滚动锚定引擎** | `ChatMessageList.tsx`、`MessageVirtualizer.tsx`、`useScrollAnchor.ts` | 建立 PagingAnchor 快慢双径算法与 observedTopRef 防钳位账本，消除抽搐与误脱底 |
| **DIM-03** | **24px 极简单行折叠与渐进式展开** | `TimelineThoughtSection.tsx`、`MessageToolCallsSection.tsx`、`chat-tool-call/` | 落地符合 Figma 122:9479 的 24px `DisclosureRow`、带跑马灯扫光的单行思考与工具行 |
| **DIM-04** | **轮次过程折叠状态机与全文搜索穿透** | `MessageContent.tsx`、`TimelineBody`、状态机推导逻辑 | 引入 7 布尔量折叠状态机，在轮次终态收拢为 33px 发丝线，接入 HTML5 `hidden="until-found"` |
| **DIM-05** | **纯净画纸排版与 70.2% 气泡规范** | `ChatAssistantMessageRow.tsx`、`ChatUserMessageRow.tsx`、设计 Tokens | 剥离 Assistant 外层卡片框线，落地 70.2% 宽比与 22px 超椭圆气泡，操作栏外置下沉 6px |
