## 二、目标架构与构造级隔离设计

### 2.1 会话与分屏作用域单向穿透契约（`A-01`, `A-06`, `A-08`）

1. **`useChatSessionMeta` 作用域加固**：
   - 内部统一使用 `const targetSid = useScopedSessionId(sessionIdProp)`，确保即使上层未显式传递 `sessionIdProp`，也能从 `LeafScopeContext` 精确获取分屏绑定的 `sessionId`，绝不越级回退全局 `activeSessionId`。
2. **发送与流式全链路显式签名**：
   - `useChatComposerProps` 将 `sessionId: activeSessionId` 显式传入 `useChatSend`。
   - `UseChatSendOptions` 与 `UseChatStreamOptions` 新增 `sessionId?: string | null`；`useChatSend`、`useChatStream`、`useSlashSend`、`useStreamCallbacks`、`useRunStreamingAssistant` 全链路通过 `useScopedSessionId(options.sessionId)` 锁定当前分屏会话 ID。
   - `slashSendPreflight.ts` 中 `runPreflightChecks` 优先使用传入的 `activeSessionId`（即分屏 `scopedSessionId`），消除对全局 `useSessionStore.getState().activeSessionId` 的隐式依赖。
3. **模型/思考选择器与附件批注移除**：
   - `ComposerFusedTrigger` 与 `ModelBadgePickerMenu` 改为使用 `useScopedSessionId(sessionIdProp)` 读取与写入会话级模型和思考强度覆盖（`setSessionModel` / `setSessionThinkingLevel`）。
   - `ChatComposer` 在 `handleRemoveAttachment` 中通过 `useScopedSessionId(sessionId)` 传递 `scopedSessionId` 给 `removePendingFileAnnotation(target.annotation.id, scopedSessionId)`。

### 2.2 按 `sessionId` 索引的流实例与渲染缓冲隔离（`A-02`, Guard-2）

1. **共享流管理器与按会话隔离的渲染缓冲表（`hooks/chat-stream/sessionStreamManager.ts`）**：
   - 在 `apps/crish-desktop/src/hooks/chat-stream/sessionStreamManager.ts` 中导出共享单例 `sharedSessionStreamManager`（基于 `SessionStreamManager` 内部 `Map<string, ActiveStream>` 天然支持多会话并发流）以及按 `sessionId` 索引的 `StreamRenderBuffer` 注册表（`registerSessionRenderBuffer` / `getSessionRenderBuffer` / `flushAndRemoveSessionRenderBuffer`）。
   - `useStreamBatchers` 默认复用 `sharedSessionStreamManager`，避免不同分屏各自实例化导致流状态不可见。
   - `useRunStreamingAssistant` 在启动流时按目标 `sid` 注册专属 `StreamRenderBuffer`，并在流结束或中止时仅冲刷和清理该 `sid` 对应的 `StreamRenderBuffer`（严格满足 `review-01` Guard-2，绝不跨会话冲刷或销毁其他分屏正在流式渲染的缓冲区）。
2. **精确停止生成与作用域事件过滤（`hooks/chat-stream/useStreamCallbacks.ts`）**：
   - `handleStopGeneration(targetSessionId?: string)` 与 `handleForceCancelGeneration(targetSessionId?: string)` 优先解析 `targetSessionId || scopedSessionId`。
   - 全局 `stop-generation` 事件通过 `onScopedUiEvent('stop-generation', ...)` 消费：
     - 若事件携带显式 `sessionId` 或 `leafId`，仅匹配分屏消费；
     - 若事件无作用域载荷（如全局快捷键触发），仅焦点分屏（`isActive === true`）消费；
     - 当目标会话既无活跃前端流（`!cur`），又无处理中/排队中消息且无 `engineLastRunId` 时，静默忽略，不再误弹「后台任务停止请求已发送」Toast。

### 2.3 多草稿分屏项目目录注册表与按 ID 独立转正（`A-04`, `A-05`, `B-02`, `B-03`, Guard-3）

1. **草稿目录按 `draftSessionId` 独立存储**：
   - 依托 `store/draft-routing/draftFolderRegistry.ts`（`draftFolderRegistry` + `useDraftFolder`），在 `store/sessionDraftActions.ts` 中导出 `draftFolderBySessionId`、`setDraftProjectFolder(folder, draftSessionId)`、`getDraftProjectFolder(draftSessionId)` 与 `materializeDraftSession(folderOverride, targetDraftSessionId)`。
   - 当分屏处于 `__draft__:<nonce>` 状态时，`setDraftFolder(folder, draftSessionId)` 与 `ProjectPickerMenu` 同时更新 `draftFolderRegistry.set(draftSessionId, folder)`；`useChatSessionMeta` 通过 `useDraftFolder(targetSid)` 响应式获取当前草稿分屏的独立项目目录。
2. **消除 `commitDraftIfNeeded` 全局焦点早退陷阱（Guard-3）**：
   - `commitDraftIfNeeded(opts?: { title?: string; folder?: string; draftSessionId?: string })` 接收显式 `draftSessionId`。
   - 判定逻辑改为：若 `opts?.draftSessionId` 是合法草稿 ID（`isPendingDraft(opts.draftSessionId)`），**无论全局 `st.activeSessionId` 是否为真实会话，均强制执行草稿物化创建新会话**！
   - 物化创建新会话 `newId` 后：
     - 读取 `opts.folder || draftFolderRegistry.get(targetDraftId) || cur.draftFolder || ...` 作为新会话归属目录；
     - 将 `composerDrafts[targetDraftId]`（含 `sessionDraftManager` 缓冲）及 `sessionRuntimeRegistry` 中的附件、思考标题原子迁移至 `newId`；
     - 清理 `draftFolderRegistry.delete(targetDraftId)`；
     - 若当前转正的并非全局焦点会话（例如从非焦点草稿分屏触发发送），保持或按分屏上下文平滑升级对应分屏标签页（`promoteDraftTab(targetDraftId, newId, title)`）。
3. **`slashSendDraftManager` 作用域对齐**：
   - `resolveTargetSessionId(scopedSessionId, rawInput)` 在检测到 `isPendingDraft(scopedSessionId)` 时，直接调用 `commitDraftAndOpenShell({ draftSessionId: scopedSessionId, title })`，彻底摆脱对 `useSessionStore.getState().activeSessionId` 的依赖。

### 2.4 行内编辑粘贴隔离与附件事件作用域门控（`A-07`, `B-04`, `B-08`）

1. **行内编辑框独立粘贴路由（`ChatCard.tsx`）**：
   - 在 `ChatCard.tsx` 中构造专属于行内编辑状态的粘贴处理器（将粘贴图片或文件转换为 `PendingAttachment` 并写入 `setEditAttachments`），挂载到 `editComposerElement` 的 `onPasteImage` 与 `onPasteFiles`，严禁复用底部主输入框的 `state.composerProps.handlePasteImage / handlePasteFiles`。
   - 同时补齐 `onPastePath: state.composerProps.handlePathsSelected` 绑定。
2. **附件 Hook 作用域门控（`useChatAttachments.ts`）**：
   - 使用 `useScopedSessionId(activeSessionId)` 解析 `currentKey`。
   - `crish-attachments-changed` 与 `conex:attach-text-file` 监听统一接入 `shouldConsumeScopedEvent` 校验，拒绝非本分屏的跨屏广播污染。
   - 暴露 `handlePastePath: handlePathsSelected` 供上下游统一调用。

## 四、验收断言清单

1. **非焦点分屏发送与流式路由断言（`A-01`）**：双分屏（Pane A 为 `session-a` 且非焦点，Pane B 为 `session-b` 且为全局焦点）并排时，在 Pane A 触发发送，消息与流式助手回复 100% 写入 `session-a`，`session-b` 零污染。
2. **并发流精确停止与缓冲冲刷断言（`A-02` + Guard-2）**：`session-a` 与 `session-b` 同时流式输出时，停止 `session-a` 仅中止 `session-a` 的流并冲刷 `session-a` 的 `StreamRenderBuffer`，`session-b` 流式输出继续且无误弹 Toast。
3. **双草稿分屏独立选项目与转正断言（`A-04`, `A-05`, `B-02`, `B-03` + Guard-3）**：
   - Pane A（`__draft__:pane-a`）选择项目 `/repo/alpha`，Pane B（`__draft__:pane-b`）选择项目 `/repo/beta`，两者徽章显示与 `draftFolderRegistry` 完全独立；
   - 即使全局 `activeSessionId` 位于真实会话 `session-real` 或另一草稿分屏，在 `__draft__:pane-a` 触发转正/发送时，依然创建归属于 `/repo/alpha` 的新会话并迁移 `__draft__:pane-a` 的草稿文本与附件。
4. **模型与思考选择器分屏隔离断言（`A-06`）**：在非焦点分屏切换模型或思考强度，仅更新该分屏绑定 `sessionId` 的 `sessionModels` / `sessionThinkingLevels`。
5. **行内编辑粘贴与主输入框隔离断言（`A-07`）**：在历史消息行内编辑框中粘贴图片/文件，仅进入 `editAttachments`，底部主输入框 `attachments` 保持为空。
6. **移除附件批注分屏隔离断言（`A-08`）**：在非焦点分屏移除含 `annotation` 的附件，仅删除该分屏 `sessionId` 下的待发送批注。
