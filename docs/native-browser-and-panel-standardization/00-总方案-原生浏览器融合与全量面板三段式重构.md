## 一、方案背景与核心痛点剖析

在桌面端工具交互中，右侧协同面板存在两大系统性架构断层：

1. **AI 浏览器与应用预览的「过度设计与心智割裂」**：
   - **历史遗留的过度设计**：此前通过后台启动 Chrome 实例，再通过 Tauri Channel 以 JPEG 逐帧截屏推送到前端 `<FrameCanvas>`，并在上方覆盖全透明 `<InputLayer>` 拦截鼠标滚轮与键盘事件、用 1px 隐藏动态移动 `<input>` 伪装 IME 输入法桥接；
   - **巨大缺陷**：画面卡顿模糊、无法原生划词复制、无原生右键菜单、IME 候选框频发错位丢字、CPU/内存占用极高（15%~35%）；
   - **视图割裂与噪音**：应用内同时存在「应用预览」与「AI 浏览器」两个割裂的 Tab，且面板底部塞了 500 行的 Chrome 书签导入、History 库导入与登录态导出表单，宛如“毛胚房运维脚手架”。

2. **右侧全量面板的「样式退化与规格漂移」**：
   - `FilesCard`、`DiffCard`、`FileViewerCard`、`AgentCard` 的顶栏高度（28px~40px 浮动）、按钮尺寸（24px~28px）、边框线（双重边框或无边框）与内边距（散落 margin）缺乏统一规范；
   - 部分面板在 Tab 下方多叠出了重复的 fake 导航栏（三行图标退化）。

## 二、架构决策（Architecture Decisions）

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    右侧协同面板标准三段式架构模型                           │
├─────────────────────────────────────────────────────────────────────────┤
│ 第 1 段 · Header (38px)  | LeafToolTabStrip                             │
│   • 高度严格锁定 38px，无下边框 (border-bottom: none !important)          │
│   • Tab 标签项高度 26px (圆角 4px)，新建加号 26px，右固定坞按钮 28px      │
├─────────────────────────────────────────────────────────────────────────┤
│ 第 2 段 · Toolbar (32px) | 面板专属次级工具栏 (side-panel-toolbar)        │
│   • 高度严格锁定 32px，顶部无分割线，底部 1px 发丝边框                     │
│   • 所有动作按钮统一 26px × 26px (圆角 4px)，图标统一 14px                │
│   • 控件 (输入框 / 下拉 / 分段胶囊) 高度统一 24px (上下各留白 4px 垂直居中) │
│   • 间距节奏全量统一为 gap: 4px 等距，彻底消除自定义 margin 偏移          │
├─────────────────────────────────────────────────────────────────────────┤
│ 第 3 段 · Body (Flex: 1) | 面板核心工作区 (side-panel-body)              │
│   • 100% 填充满下方区域 (flex: 1 1 auto; overflow: hidden / auto)       │
│   • 无独立 Toolbar 的面板 (总览 Overview / 终端 Terminal) 纯粹铺满      │
└─────────────────────────────────────────────────────────────────────────┘
```

### 决策 1：废除旧式 Canvas/InputLayer 投屏，收敛至单真源原生 `PreviewCard`
* **物理瘦身**：彻底废除并物理删除 `FrameCanvas.tsx`、`InputLayer.tsx`、`IndicatorBar.tsx`、`useFrameStream.ts` 等过度设计文件（瘦身 4,500+ 行代码）；
* **原生 60/120fps 硬件加速**：统一以原生嵌入式 Webview / Iframe 作为「应用预览与浏览器」的唯一载体，获得 100% 原生划词选中、原生右键、原生系统级 IME 输入法与零帧流 CPU 开销；
* **视图路由收敛**：从 `main.tsx` 与 `registerBuiltInViews.tsx` 中移除独立的 `browser` 视图，统一收拢为 `preview`（应用预览）。

### 决策 2：AI 动作指令「原生驱动 DOM」+「100% 实时肉眼可见视觉反馈」
* **W3C 规范级原生事件派发**：AI 执行 `click`、`type_text`、`scroll` 等指令时，通过轻量 DOM Bridge 直接派发真实 DOM 事件；通过注入原生 `value` 描述符穿透 React `_valueTracker`，自动触发真实页面的状态更新；
* **非侵入式实时视觉反馈（Ghost Cursor Overlay）**：
  * 在外层挂载轻量 `InteractionOverlay`（`pointer-events: none`）；
  * AI 移动时，呈现柔和的平滑贝塞尔曲线光标点；
  * AI 点击时，产生直径 32px 的涟漪波纹与动作意图气泡（如「AI 正在点击『提交订单』」）；
  * AI 打字时，呈现拟真的流式逐字打入效果，用户肉眼实时看清 AI 的一切动作。

### 决策 3：浏览器数据导入与配置迁移至「设置（Settings）中心」
* 在 `settingsTabsMeta.ts` 与 `SettingsPanel.tsx` 中注册「受管浏览器」设置项，挂载 `BrowserImportSection`；
* 用户可在设置中导入 Chrome 书签 JSON、History 数据库与管理登录态，彻底还右侧工作区面板一片清爽。

### 决策 4：全量其余右侧面板严格对齐三段式规范
* **代码产物 (`FilesCard`)**：`filesBar` 规范为标准 32px `side-panel-toolbar`，按钮 26px，等间距 4px；
* **代码差异 (`DiffCard`)**：`DiffHeaderControls` 规范为标准 32px `side-panel-toolbar`；
* **单文件查看 (`FileViewerCard`)**：顶部 header 规范为标准 32px `side-panel-toolbar`；
* **协作体 (`AgentCard`)**：`AgentCardHeader` 规范为标准 32px `side-panel-toolbar`；
* **总览 (`OverviewCard`) & 终端 (`TerminalCard`)**：规范为纯 Body 满屏容器。
