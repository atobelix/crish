## T14 · 门禁阶梯上线与接线

**目标**：让「门禁绿」变成真约束——全部 token 门禁**有自动触发点**，单一入口 `check:tokens-all`。

**现状事实（2026-09-11）**
- 仅 `check-token-consistency` 与 `check-css-encoding` 真正接入 CI。
- `package.json:46` 的 `check:desktop` 链在 husky / CI / turbo 中**无任何调用点** → 15 个 token 门禁实为手动。
- **6 个脚本零引用**：`check-ui-negative-churn` · `check-coverage-threshold` · `check-lr-t1-memory-prod-ban` · `check-legacy-shim` · `check-sec7-gfm-emoji` · `check-conex-db-size`。
- `.husky/pre-commit` 仅 `git diff --check` + `check-conflict-markers`（**不含 token 门禁**）；`.husky/pre-push` 仅 `typecheck && npm test`。

**文件域**：`scripts/` · `package.json` · `.husky/` · `.github/workflows/`
**⚠️ 注意**：`scripts/check-token-consistency.mjs` 与 `check-color-ssot.mjs` 可能仍被并行会话修改 → 本单元**只做接线与聚合入口**，不修改这些脚本内部逻辑。若必须改 → 先 `git status` 确认干净。

**步骤**
1. 把 `check:desktop` 拆为可独立调用的 `check:tokens-*`（每个 token 门禁一条）。
2. 新增单一入口 `check:tokens-all`：串行执行全部 token 门禁 + token 契约测试。
3. 接入 `.husky/pre-push` 与 CI（`ci.yml`）。
4. 每个门禁的输出满足 **FAIL 五元组契约**：`违反项 · 文件:行号 · 当前值 · 阈值 · 正确做法（可复制的修复形态）`；**禁止**只报 `FAIL: X = N > baseline`。支持 `--list` 与 `--guide <metric>`。
5. 处理 6 个零引用脚本：接入或删除（删除须说明理由；**不得删除仍是资产的契约测试**）。

**验收断言**
1. `gate_wiring_gap` = **0**（每个 token 门禁都有自动触发点）。
2. `orphan_script` = **0**。
3. `node scripts/check-tokens-all...` / `npm run check:tokens-all` 可跑，退出码语义正确；全绿时 exit 0。
4. 每个门禁的 FAIL 输出实测满足五元组（各给一例）。
5. **负向用例**：证明每个新增门禁在违规输入下会 FAIL（防「门禁恒绿」）。
6. **未提升任何棘轮基线**；`git diff` 中无基线被抬高。

**红线**：禁 `--no-verify` · 禁把门禁改成永远 exit 0 · 禁删除测试资产 · 不得 git 提交。

## T15 · 全链路物证采集与终局校验

**目标**：交付的唯一依据是**产品链路真存活**。严禁以「模块内自测绿灯 / typecheck 无报错 / 文档声明完成」作为交付依据。

**文件域**：只读 + 测试代码（不得改生产代码；发现生产缺陷 → 回报并新开单元）

**五类物证（缺一不可）**

| 端 | 物证 | 采集方式 |
|---|---|---|
| **触发端** | 用户在 UI 的交互能准确发起请求：切换主题 / 密度档 / 字号调节 / 皮肤 / 强调色 | 真机操作 + 截图组（`light × dark` × `medium × large` 四组合） |
| **传输端** | 跨层契约在主注册表中真实存在并有效收发 | `G-COMMAND-1TO1` 输出 + 注册表 `文件:行号` 引用 |
| **介质端** | 数据无损落盘至法定存储；**旧孤岛零写入且被物理清退** | `G-NO-LEGACY-WRITE` 负向断言 + 存储快照前后 diff |
| **消费端** | 内核真实业务调用处读取并应用新配置；出站数据/渲染树真实携带 | 四组合 `getComputedStyle` 实测值 + 渲染树属性导出 |
| **负向断言** | 旧字段 / 旧方法 / 旧类名已彻底根除 | `expect(...).not.toContain(...)` 形式；**须避免 `check-token-consistency` 把否定断言误计为消费方**（该门禁的已知口径缺陷，见 `../01-分维` §二 L3 与 `../audits/02` §2.4） |

**终局校验清单**
1. `check:tokens-all` 全绿（含 L0–L8 各级门禁）。
2. `check-token-consistency` PASS 0/0/0，基线未被抬高。
3. `G-SSOT-DEF` / `G-SSOT-INJECT` / `G-STATIC-DEFAULT` / `G-B-CLASS` = 0。
4. `G-FALLBACK-CONFLICT` = 0；`G-FALLBACK-BARE` 棘轮降到目标。
5. `G-CASCADE` = 0（四组合）。
6. `G-KEY-REGISTRY` / `G-NO-LEGACY-WRITE` / `G-NO-READ-FALLBACK` / `G-CONFIG-REGISTERED` = 0。
7. `G-COMMAND-1TO1` = 0；`G-GHOST-EXEMPTIONS-EMPTY` = 0；清单唯一化。
8. 零未捕获异常、零非预期告警（真实宿主运行）。
9. **关键回归证据**：改 `tokens.css` 一处 → 四组合全部反映（消灭「改静态真源界面不变」）。
