> **上游**：`00-总方案-Token消费面统一与分裂收敛.md` §二目标态 · §一（P1–P9、P21–P33）

## 一、本维的病根（一句话）

**同一语义有 2–3 个写者，且优先级最高的写者是 JS 内联样式。** 于是「改静态真源」与「改运行时」都不足以让全局一致——不存在单一可改点。

三条并行真源的实测规模：静态 `tokens.css`（498 token）· 11 个 JS 注入写入点（覆写其中 **34 个**语义 token）· 2036 处兜底。另有存储层 11 个双轨 key、跨层 24 个未注册命令、四份并存命令清单。

## 二、A/B 双类模型落地（T6）

### 2.1 分类判据（唯一，不得各自解释）

| 判据 | 归 A 类（设计 Token） | 归 B 类（运行期量） |
|---|---|---|
| 变更驱动力 | 设计决策（改主题/密度/性能档） | 用户交互 / 测量（拖动、悬浮、缩放、索引） |
| 生命周期 | 随主题档位变化 | 随 DOM 实例 / 单次会话变化 |
| 是否可静态枚举 | 是 | 否（运行时才知道值） |
| 默认值 | 静态声明即默认 | **必须有静态声明兜底**（消除「静态不可知」） |
| 写者 | **只有** `tokens.css`（+ `z-index.css` 授权） | JS，**唯一写者**，必须登记 |

### 2.2 已知违规（P1/P2/P3）与处置

| # | 现状 | 处置 |
|---|---|---|
| P1 | **34 个语义 token 被 JS 覆写**：`--bg-*`(7) `--surface-*`(4) `--shell-chrome-bg` `--shell-inset-bg` `--text-*`(3) `--border-color/subtle` `--composer-bg` `--terminal-bg/fg/cmd` `--control-mix-color` `--control-soft-bg/-hover/-active` `--accent-green/red-light-adaptive` `--font-size-adjust` `--font-sans` `--font-mono` `--md-code-tab-size` `--sidebar-width` `--chat-col-max` | 按 §三 偏好派生链改造：**JS 只写参数**，语义 token 改为 CSS 内派生 |
| P2 | `--text-primary/-secondary/-tertiary` 被 `themePersonalization.ts` 与 `oklchColorGuard.ts` **两个 JS 写者争用** | 合并为**单条派生公式**；对比度守卫改为**调整参数**（如 `--user-brightness`），不再直接写 `--text-*` |
| P3 | `--ui-scale` 只有 JS 注入、无静态定义 | 在 `tokens.css` 增静态默认 `--ui-scale: 1;`，并按 B 类登记 |
| P19 | `--chat-stream-pad-x` 无定义、靠兜底存活 | 静态声明（值取 `chatScrollGeometry` 的 SSOT 常量），删兜底 |

> **注意**：`--sidebar-width` / `--chat-col-max` 属 **B 类**（用户拖拽 / 常量注入），**不得**按 A 类禁写；但必须在 `tokens.css` 有静态默认，且注入点入登记表。**这是 T6 必须先于 T7 的原因**——未分类就禁写会直接打断侧栏拖动。

### 2.3 登记表（`scripts/token-registry.json`）

由 L2 门禁消费，形态见 `01-分维-防御脚本断言阶梯.md` §二 L2。要求：

1. `bClass[]` 覆盖**全部**实际 JS 写入点（双向差集为零）。
2. `componentIslands[]` 覆盖全部组件私有前缀（T9 交付）。
3. `externallyInjected[]` 含 `--radix-*` 2 项。
4. 登记表**本身**受门禁约束：未登记者写入即 FAIL（`G-B-CLASS`）。

## 三、偏好派生链（T7，本维的核心结构性手术）

### 3.1 现状调用链（需拆除的）

```
main.tsx:112 initSsrGlobals
 → :113 initVisualPresentationController  (visualThemeController.ts:23 → applyUiSize:28-33 写 --ui-scale)
 → :116 bootstrapTheme                    (themeStore.ts:136 → readStoredTheme:137 → applyTheme:138 写 data-theme:80-86
                                            → readStoredPersonalization:139 → applyPersonalization:140
                                            → themePersonalization.ts:360-404 写 ~28 个语义 token
                                            → applyTextContrastGuard:407 → oklchColorGuard.ts:117-126 再写 --text-*)
 → :119/:123 写 --sidebar-width / --chat-col-max
 → AppBootstrap.ts:180 bootstrapFonts     (fontStore.ts:156-165 写 --font-sans/-mono/--md-font-*/--sep-font-*)
 → :188 initCodeIndentProjection          (codeBlockIndent.ts:66 写 --md-code-tab-size)
 → :251-267 重复写 data-ui-size / data-density / data-shell-chrome   ← 与 visualThemeController 双轨
```

### 3.2 目标链（保留两个写者，其余归零）

```
用户偏好（skin / accent / fontSizeAdjust / brightness / uiScale）
        │  写者①：ThemeProjection（唯一）
        ▼
  参数层（B 类，唯一注入面）
  --user-accent-h / -s / -l     --user-surface-tint
  --user-brightness             --font-size-adjust     --ui-scale
        │  CSS 内派生（color-mix / calc / hsl），零 JS 参与
        ▼
  语义层（A 类，tokens.css 静态声明，只读）
        │
        ▼
  写者②：visualThemeController（唯一）── 只写 DOM 属性：data-theme / data-ui-size / data-shell-chrome
```

**结果**：JS 对 A 类 token 的写入 = **0**；DOM 属性写者 = 1（拆掉 `AppBootstrap.ts:251-267` 的重复写）。

### 3.3 派生示例（每条都要在 `tokens.css` 落成）

```css
/* 参数层：B 类，有静态默认，JS 可覆写 */
:root {
  --user-accent-h: 160;      --user-accent-s: 84%;     --user-accent-l: 39%;
  --user-surface-tint: 0%;   --user-brightness: 0;     --font-size-adjust: 0px;
  --ui-scale: 1;
}

/* 语义层：A 类，只读派生 —— 亮/暗/密度/性能四档各自定义，JS 不参与 */
--accent-primary:        hsl(var(--user-accent-h) var(--user-accent-s) var(--user-accent-l));
--md-link-color:         var(--accent-primary);
--bg-card:               color-mix(in srgb, var(--surface-card) calc(100% - var(--user-surface-tint)), var(--tint-strong));
--text-primary:          color-mix(in srgb, var(--text-ink) calc(100% + var(--user-brightness) * 1%), transparent);
--border-color:          color-mix(in srgb, var(--text-primary) 12%, transparent);
--composer-bg:           var(--surface-card);
--terminal-bg:           …;   /* 由主题档静态给出 */
--font-sans:             …;   /* 字体族改为 B 类参数 + 静态族声明组合 */
```

**约束**：派生必须**只用 CSS 能力**（`color-mix` / `calc` / `hsl()`），不引回 JS；派生链不得跨主题块（每个主题块自行给出该档的派生结果）。`@supports oklch` 渐进增强块（`tokens.css:1460`）同步更新。

### 3.4 顺序与去风险

1. 先做 **T6 分类**（否则误禁 B 类）。
2. 再做 **参数层引入**（新增静态声明，不动消费点）——此时旧注入仍在，界面不变。
3. 再**逐族切换**语义 token 为派生形态（按 `--bg-*` → `--text-*` → `--border-*` → `--surface-*` → `--composer-*` → `--terminal-*` → `--control-*`），每族切换后跑 `G-CASCADE` + 视觉回归。
4. 最后**物理删除** JS 中对应的 `setProperty` 调用与参数计算中已无用的分支。
5. 删除 `AppBootstrap.ts:251-267` 的重复 DOM 属性写入；`SettingsQuickMenu.tsx:215-217` 的第二入口收敛到投影。

## 五、孤岛与泛名（T9）

1. **泛名立即修**：`ToastStackModern.module.css` 的 `--gap` / `--height` / `--scale` → `--toast-gap` / `--toast-height` / `--toast-scale`（该文件已有 `--toast-*` 惯例，`--toast-index` 就是对的）。**危害**：无前缀泛名会被任意后代消费者的 `var(--gap)` 意外命中。
2. **作用域收敛**：私有 token 只定义在**组件根选择器**内，禁止出现在 `:root`。
3. **登记**：123 个孤岛进 `token-registry.json.componentIslands`；同时在 `tokens.css` 顶部**索引注释区**列出「全局体系 vs 组件私有」边界（只登记名字与归属，不搬定义）。
4. **晋升通道**：当第二个文件需要同一语义 → 必须**晋升为全局 A 类 token**，禁止复制定义（这正是 `--btn-*` 4 处分裂的成因）。

## 七、本维验收断言

1. `G-SSOT-DEF` = 0（授权白名单外无跨文件重复定义）。
2. `G-SSOT-INJECT` = 0（JS 不写任何 A 类 token）。
3. `G-STATIC-DEFAULT` = 0（B 类全部有静态默认）。
4. `G-B-CLASS` 双向差集 = 0。
5. `G-DOM-ATTR-SINGLE-WRITER`：`data-theme`/`data-ui-size`/`data-density`/`data-shell-chrome` 各 **1** 个写者。
6. `G-KEY-REGISTRY` / `G-NO-LEGACY-WRITE` / `G-NO-READ-FALLBACK` / `G-CONFIG-REGISTERED` 全部 = 0（含**负向断言**）。
7. `G-DEAD-FRAMEWORK`：零调用导出棘轮递减至 0。
8. `G-COMMAND-1TO1` = 0；`G-GHOST-EXEMPTIONS-EMPTY` = 0；`G-MANIFEST-SINGLE-SOURCE` = 1 份。
9. **介质端物证**：存储快照前后 diff 证明旧 key 零写入且已物理清退。
10. **消费端物证**：改 `tokens.css` 一处后，`getComputedStyle` 在亮/暗 × 中/大 四组合下**全部**反映该改动（消灭「改静态真源界面不变」）。
