# 01 · 分维 · 防御脚本断言阶梯

> **上游**：`00-总方案-Token消费面统一与分裂收敛.md` §五
> **目标**：把「门禁」从**事后统计**升级为**事前指路**——后续 Agent 改代码时，门禁以「你违反了 X，正确做法是 Y」的形式给出可复制的修复形态。
> **纪律**：测试资产只扩展不删除（`AGENTS.md` §9）；棘轮基线**只降不升**；禁止 `--no-verify` 绕过。

---

## 一、设计原则

### 1.1 分级锁定（本阶梯的核心）

每条门禁**紧随其守护的维度修复之后在同一批上线**，而不是战役收尾统一补。理由：

- 若先修后补，修复期间无哨兵 → 其他 Agent 可能重新引入刚清掉的形态（`docs/design-token-ssot` 的 G1/G2 落成但 G3–G6 未建，正是此坑）。
- 若先补后修，基线必须设在「脏值」上 → 门禁为绿但语义为红，再次制造「门禁绿、仓库脏」。

因此阶梯顺序 = 修复顺序，一一对应 §四拓扑。

### 1.2 两类门禁，两种语义

| 类型 | 语义 | 基线 | 适用 |
|---|---|---|---|
| **硬失败（zero-tolerance）** | 违反即 `exit 1`，**不允许任何存量** | 无基线，目标恒为 0 | 真源重复、JS 注入 ∩ A 类、矛盾兜底、层叠计算值不符、旧 key 写入、命令 1:1 |
| **棘轮（ratchet）** | 实测 > 登记 → FAIL；≤ 登记 → 通过 | 标记区 `<metric> <count>`，**只降不升** | 裸兜底数、裸 px 数、`!important`、魔术补偿、零调用导出 |

> 现有 `check-layout-tokens.mjs` 的 `bad_space_fallback`、`style-contract.test.ts` 的 `RADIUS_999_BASELINE` 是棘轮范式来源；`check-token-consistency.mjs` 的 `undefined_refs` 是「目标应为 0 却设了 0 基线」的正确形态。

### 1.3 输出契约（**强制**，不用则拒收）

每条 FAIL **必须**输出五元组：

```
[门禁名] 违反项 · <文件:行号> · 当前值 <N> · 阈值 <M> · 正确做法：<可复制的修复形态>
```

反例（**禁止**）：

```
[check-token-consistency] FAIL: undefined_refs: 当前 2 > 基线 0（+2）
```

正例：

```
[G-SSOT-INJECT] JS 注入 A 类 token
  · apps/crish-desktop/src/api/themePersonalization.ts:360  ->  --bg-card
  · 当前：JS 写 --bg-card（A 类：设计 Token，仅 tokens.css 可写）
  · 正确做法：把 --bg-card 改为 CSS 内派生（color-mix），JS 只写参数
      --bg-card: color-mix(in srgb, var(--surface-card) calc(var(--user-brightness) * 1%), transparent);
    并删除该 setProperty 调用。参考 docs/token-consumption-unification/02-分维-真源唯一化与多轨物理清退.md §2.3
```

**辅助标志**：每个门禁支持 `--list`（全量明细）与 `--guide <metric>`（只打印某指标的「正确做法」段落），便于 Agent 快速自纠。

**`G-CASCADE` 的落地方式**（关键——jsdom 不足以做完整层叠）：

- 首选：在 vitest 中加载真实 `tokens.css` 文本 + 手工构造匹配的 DOM（`<html data-theme="light" data-ui-size="large">`），用 `getComputedStyle` 读值。若 jsdom 对自定义属性层叠支持不足 → 降级为**纯逻辑层叠评估器**：解析 CSS 规则，按 (specificity, source order) 计算胜出声明，断言胜出方 == 预期档位。**该评估器本身必须有针对 `[attr]` vs `html[attr]` vs `:root` 的特异性单元测试**（正/逆/退化态穷举）。

## 三、门槛（Definition of Done，逐级）

阶梯每一级的「完成」= 下列**全部**成立：

1. 该级全部门禁**可跑通**且退出码语义正确（硬失败项 = 0；棘轮项 ≤ 基线）。
2. 该级每条门禁**至少有一个负向用例**（构造违规输入必须 FAIL）——防止「门禁恒绿」。
3. 该级每条门禁**有自动触发点**（`pre-push` 或 CI）。
4. 该级门禁的 FAIL 输出满足 §1.3 五元组契约。
5. 该级引入的基线文件已入版本库，且**未提升任何既有基线**。
6. 未删除、未弱化任何既有测试资产（`AGENTS.md` §9）。
