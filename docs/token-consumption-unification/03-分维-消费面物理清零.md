# 03 · 分维 · 消费面物理清零

> **上游**：`00-总方案-Token消费面统一与分裂收敛.md` §一（P10–P17、P18–P20、P34–P37）
> **承载单元**：T3 · T4 · T10 · T11 · T2
> **对应门禁**：L3 全部 + L4 全部 + L7
> **纪律**：**去兜底** ≠ **改兜底**。把错的兜底改成对的，等于保留了第二套真源——同样违规。

---

## 一、本维的病根

消费层的 8,333 处 `var()` 引用中，**2,036 处自带裸字面量兜底**（24.4%）。这些兜底本应是「定义缺失时的安全网」，却被当作**本地默认值**使用，从而长成了**第二套未经授权的 token 系统**。

三重危害（按严重度）：

1. **静默降级到异规格**：token 一旦缺失，界面不是「无样式」而是「换一套值」。
2. **兜底与真值矛盾**：**59 个 token** 的兜底值互相矛盾且与 `tokens.css` 不符 → 同一视觉语义在不同文件里是不同数值。
3. **屏蔽能力**：`var(--font-size-base, 14px)` 的兜底是裸 px，**绕过 `calc(14px + var(--font-size-adjust))`** → 兜底一生效，字号调节偏好静默失效；`--transition-*` 的兜底更是私藏了 **5–10 种**动效规格，使降动网格（`reduced-motion.css`）改 token 却**穿透不到这些消费点**——无障碍链路存在实质缺口。

## 二、兜底四分法（T3）

对每一处 `var(--x, <兜底>)`：

| 档 | 判据 | 处置 | 说明 |
|---|---|---|---|
| **A1 错误兜底** | 兜底值与真值**不符**（含 59 个矛盾 token 的全部变体，如 `--transition-fast` 的 `120ms ease`×68、`--font-mono` 的 `monospace`×49、`--opacity-disabled` 的 `0.45`×16、`--radius-xs` 的 `3px`×6） | **必改**（最高优先） | 它们是「门禁绿、视觉不一致」的直接来源 |
| **A2 等价兜底** | 兜底值与真值数值一致（如 `var(--radius-sm, 4px)` 且真值 4px、`var(--shadow-color, #000)`） | **渐进清理** | 分批去兜底，写裸 `var(--x)`；按 `--space-*` → `--radius-*` → `--font-size-*` → `--transition-*` → `--shadow-*` 推进 |
| **A3 语义兜底** | 兜底是**另一个 token**（`var(--hairline, var(--border-subtle))`、`var(--shadow-lg, var(--shadow-md))`、`var(--radius-full, 9999px)`） | **保留** | 这是合法的语义降级链，不是裸值，**不得误判为违规** |
| **A4 白名单** | `--radix-*` 外部注入；`var(--tooltip-translate, translate(0))`（`style-contract.test.ts:486-491` 已钉死）；`--chat-stream-pad-x` 类待补定义者（由 T2 先补定义再删兜底） | **保留** | 白名单条数纳入棘轮 |

**核心原则**：**默认值由静态声明提供，消费点写裸 `var(--x)`。token 缺席应当是门禁可见的失败，而不是运行时静默换规格。**

### 2.1 专项裁决

| 项 | 裁决 | 依据 |
|---|---|---|
| `--font-size-*`（全族） | **一律去兜底**（含数值"正确"的） | 任何裸 px 兜底都绕过 `--font-size-adjust`；字号调节是产品功能，不可静默失效 |
| `--transition-*` / `--duration-*` | **一律去兜底** | 去兜底后降动网格才真正生效；改兜底无法修复无障碍链路 |
| `--font-mono` / `--font-sans` | **一律去兜底** | 字体栈是完整设计决策，任何短兜底都会改变渲染字体 |
| `--text-*` / `--bg-*` / `--border-*` | 去兜底；**先解决 P1 遮蔽**（`02` 分维）再动 | 这些 token 当前被 JS 覆写，兜底与注入叠加判断困难 |
| 基础块**无**静态定义的 token | **不删兜底**，登记上报 | 删了会真的缺失；需先由 T6 判定 A/B 类并补静态默认 |

## 五、样式假象整治（T11）

### 5.1 层叠生效（P34/P35，本维唯一新增的根本性缺陷）

| 环节 | 事实 |
|---|---|
| 基础/亮色块 | `tokens.css:33-35` → `:root, html[data-theme='default'], html[data-theme='light']`，最高特异性 **0,1,1** |
| 密度档块 | `tokens.css:1300`/`:1364` → `[data-ui-size='small'\|'large']`，特异性 **0,1,0** |
| 属性落点 | `data-theme` 与 `data-ui-size` **都写在 `<html>`**（`themeStore.ts:80`、`themePersonalization.ts:132`；`visualThemeController.ts:30`、`AppBootstrap.ts:255/264`） |
| **结论** | **亮色主题下 `html[data-theme='light']`(0,1,1) 压制密度档(0,1,0) → 密度档静默失效；暗色下仅 `:root`(0,1,0) 匹配 → 同特异性靠源码序 → 生效**。同一功能主题相关地不一致 |
| 最小可验样本 | `--space-1`：基础块 `:702`=4px、small `:1323`=4px、large `:1387`=6px。**亮色+large 实得 4px（应为 6px）** |
| 修法（二选一，推荐 ②） | ① 密度档选择器升为 `html[data-ui-size=…]`（→0,1,1，靠源码序取胜）；② **基础块去掉 `html[data-theme='light']`，只留 `:root`** —— 语义上「基础档」本就不该与主题挂钩，且能同时消除对 `data-theme='default'` 的冗余依赖 |
| 门禁 | 新增 `G-CASCADE`：**四组合真机断言** `getComputedStyle(html).getPropertyValue(name)` == 该组合应生效的声明值。落地方式见 `01-分维-防御脚本断言阶梯.md` §二 L4 |

> **为何必须新增此门禁**：现有 `layout-contract.test.ts:73-135` 只做**文本存在性/整数性/单调性**断言，从不评估层叠胜出方——这正是「门禁绿、功能死」的判定缺口。

### 5.2 层叠上下文陷阱（P36）

**10 处**同元素/祖先链同时具备「创建层叠上下文」与「`fixed`/`sticky`/`z-index` 抬升」：
`GlobalErrorBanner`（fixed+transform+z）· `ToastStack` · `SettingsPanel`（fixed+`isolation:isolate`:19+`contain:strict`:279）· `sessionTabDrag`（fixed+`z-index:100000`）· `PreviewCard.positioner`（fixed+will-change）· `ToastStackModern.toastCard`（will-change+absolute+`z-index:calc(1000-var(--toast-index))`）· `Sidebar.sidebarScroll`（`contain:layout paint`+`translateZ(0)`）· `SidebarSessionList`（contain+translateZ）· `FilesCard.filesBody`（isolate+z）· `SegmentedControl`（祖先 isolate + 子 z-index:1）。

`Menu.module.css:3` 已**自述该陷阱**：「只给 `.menuContent` 设 z 压不住 `isolation:isolate` 的壳」→ 因此把 `z-index` 改挂到 `[data-radix-popper-content-wrapper]`(4-6)。这是正确的穿透做法，应作为范式推广。

处置：`G-STACKING-REGISTERED` 登记表制（`scripts/stacking-traps.json`），每条须说明**为何必要**；能在不创建层叠上下文的前提下表达的，改掉。

### 5.3 sticky 脆弱契约（P37）

`ModelsSettingsTab.module.css:280-281` 自述「`overflow:hidden` 会把 footer 的 sticky 截断在中间祖先里」→ `.mrdModelList{overflow:visible}`(282)。同类：`ChatScrollFloorSlot.module.css:3`（零高度 sticky，消除旧架构硬编码 148px）、`FlowScrubber.module.css:1-8`（禁钉在视口）、`overlay-scrollbar.css:117-132`（依赖 `[class*='viewport']`）。

处置：`G-STICKY-CONTRACT` 登记制——每个 `sticky` 必须能证明其包含块无 `overflow: hidden/auto` 祖先，或显式登记该约束。
