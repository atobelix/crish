## 三、逐处分析（设计意图 · 现有 token 核对 · 建议）

### 3.1 SettingsShortcutsTab:74 `.shortcutKeyBtn.recording`（已知 3 处之一）
- **① 设计意图**：录制态为「活态焦点」语义。亮色底为白卡，`--brand` 注入 4% 已可辨；暗色底为深灰卡，`--brand` 4% 几乎不可见，故提到 12%，前景同步由 `--brand-deep`（暗）切 `--brand`（亮）以保 WCAG 对比。
- **② 现有 token 核对**（读 `tokens.css`）：`--brand`（: 定义面存在）、`--brand-deep`、`--bg-card` 均存在；**无** `--recording-*` 族。其暗色值 `color-mix(--brand 12%, --bg-card)` 是「同公式换比例」，非新色板。
- **③ 建议**：`--recording-bg`（L `mix(--brand 4%, --bg-card)` / D `mix(--brand 12%, --bg-card)`）、`--recording-fg`（L `--brand-deep` / D `--brand`）。**但全仓仅此 1 处**（grep `recording` 仅 SettingsShortcutsTab 一处 `.shortcutKeyBtn.recording`），**未达 ≥2 处门槛 → 按纪律就地注释授权，不入库**（见 `03` §六）。

### 3.2 ModelsSettingsTab:36 `.modelsRail`（已知 3 处之二）
- **① 设计意图**：左导轨在亮色是「微混纸面」的浅容器；暗色回归纯底板使右侧模型卡（更沉）浮起。属「surface 层级暗色反转」语义。
- **② 现有 token 核对**：`--bg-primary`/`--bg-card` 存在，但亮色 `color-mix(--bg-primary 35%, --bg-card)` 是**一次性混色比例**，无对应语义 token；暗色值 `var(--bg-primary)` 直接命中现有 token。
- **③ 建议**：`--models-rail-bg`（L `mix(--bg-primary 35%, --bg-card)` / D `var(--bg-primary)`）。全仓仅 ModelsSettingsTab 1 处 → 单处一次性取值 → 就地注释授权，不入库。

### 3.3 ModelsSettingsTab:558 `.modelConfigPanel`（已知 3 处之三）
- **① 设计意图**：活动模型卡内的配置面板，需比卡面更沉做嵌套下沉；亮色用既有 `--bg-card-subtle`，暗色需更深（60% 纸面 + 40% 卡面）才在暗卡内分层。
- **② 现有 token 核对**：`--bg-card-subtle` 存在（L `text-primary 2%` / D `text-primary 2.5% on --bg-card`），但暗色分支**覆盖为不同值** `mix(--bg-primary 60%, --bg-card)`，故 `--bg-card-subtle` 不能表达；该混色比例无现 token。
- **③ 建议**：`--models-panel-bg`（L `var(--bg-card-subtle)` / D `mix(--bg-primary 60%, --bg-card)`）。与 #2 同为 ModelsSettingsTab 单文件、且**值不同**（rail 用纯 `--bg-primary`、panel 用 60% 混色）→ 二者非同一语义，各自仅 1 处 → 均就地注释授权，不入库（若裁决同意合并为「models 屏暗色表面下沉」单族，需确认两处视觉可 unified，否则不得强行共用一 token）。

### 3.4 Button:160-163 `.buttonSecondary`（含 `.theme-dark` 冗余写法）
- **① 设计意图**：次级按钮暗色实体化。亮色纯白卡片；暗色转灰玻片。
- **② 现有 token 核对**：暗色 4 个覆盖值**全部由现有 token 派生**（`--text-primary`/`--bg-card`/`--shadow-color`）——**无任何新色板/新档位需求**。
- **③ 建议**：**无需扩档**。收编方式为将 `--btn-*` 暗色值并入 `tokens.css` 暗色块（归 T7 真源唯一化 / T8 `ui/Button` 私域 token 族归位，见 `05-分维` P7）。另：`:162-163` 的 `.theme-dark` 写法是 `:160-161` `html[data-theme='dark']` 的**冗余同源选择器**（因 TokenRuntimeController 同时写属性与 class），收编时应二选一、删冗余。

### 3.5 Dialog:23 `.backdrop`
- **① 设计意图**：遮罩暗色加深。
- **② 现有 token 核对**：`--shadow-color` 存在；但 scrim 强度 22%/48% 与模糊 16/20px **无现 token**（`--surface-overlay` 存在但为 `0.65` 固定 scrim，不等同）。
- **③ 建议**：`--dialog-backdrop-bg` / `--dialog-backdrop-blur`（L/D 各一值）。全仓仅 Dialog 1 处 → 就地注释授权，不入库（若后续新增第 2 处浮层遮罩再统一）。

### 3.6 ComposerNoticeBar:24 `.noticeBar` 与 3.7 `:54 .noticeBar.error`
- **① 设计意图**：提示条（普通/错误）暗色下沉保对比。
- **② 现有 token 核对**：值均由 `--surface-paper`/`--bg-card`/`--color-error`/`--border-subtle` **现有 token 派生**；无新色板。
- **③ 建议**：`--notice-bar-bg`（L `--surface-paper` / D `--bg-card`）、`--notice-bar-error-bg`/`--notice-bar-error-border`（L/D 比例差）。各仅 1 处 → 就地注释授权，不入库。

## 四、收编后层叠行为影响分析

**通用原则**：收编 = 在组件内将 `background/color/--btn-*` 等声明改为 `var(--语义token)`，并在 `tokens.css` 暗色块（`:764` 起）补该 token 的暗值定义；组件内 `:global(html[data-theme='dark'])` 选择器**整段删除**。由于亮/暗取值原样迁移，**渲染像素零变化**，仅消除「绕过换主题只换 token 值契约」的选择器。

逐处影响：

| # | 收编后组件侧写法 | 浅色取值（与现状是否一致） | 暗色取值（与现状是否一致） | 视觉变化 |
|---|---|---|---|---|
| 1 | `background: var(--recording-bg); color: var(--recording-fg)` | 一致（`mix(--brand 4%, --bg-card)`） | 一致（`mix(--brand 12%, --bg-card)` / `--brand`） | 无 |
| 2 | `background: var(--models-rail-bg)` | 一致（混色 35%） | 一致（`--bg-primary`） | 无 |
| 3 | `background: var(--models-panel-bg)` | 一致（`--bg-card-subtle`） | 一致（混色 60%） | 无 |
| 4 | `--btn-*`（已在 base 定义，删暗块） | 一致 | 一致（全部现有 token 派生） | 无 |
| 5 | `background: var(--dialog-backdrop-bg); backdrop-filter: blur(var(--dialog-backdrop-blur))` | 一致 | 一致 | 无 |
| 6 | `background: var(--notice-bar-bg)` | 一致（`--surface-paper`） | 一致（`--bg-card`） | 无 |
| 7 | `background: var(--notice-bar-error-bg); border-color: var(--notice-bar-error-border)` | 一致 | 一致 | 无 |
| 8 | 与 #4 合并删除冗余 | 一致 | 一致 | 无 |

**层叠风险点**：`:global(html[data-theme='dark'])` 选择器特异性为 `(0,1,1)`（属性选择器+类），与组件内 `.shortcutKeyBtn.recording`（类+类，`(0,2,0)`）同场时暗块胜出；收编为 token 后，token 在 `html[data-theme='dark']` 块 `(0,1,1)` 定义、在组件内以 `var()` 消费（`(0,2,0)` 类选择器内声明），层叠秩序保持一致，**无特异性翻转风险**。Dialog/Button 等同理。

## 五、与 tokens.css 串行序的衔接点

`README.md` §三 规定 `tokens.css` 串行序 **T2 → T6 → T7 → T8 → T11**，本分维（B6）与 T26 **均不写 `tokens.css`**。衔接如下：

| 衔接单元 | 职责 | 本 T26 产物如何衔接 |
|---|---|---|
| **T7**（真源唯一化 / 主题块） | 在 `tokens.css` 暗色块补 token 定义、私域 `--btn-*` 等族归位 | T26 登记的 `--recording-bg`/`--models-rail-bg`/`--models-panel-bg`/`--dialog-backdrop-*`/`--notice-bar-*` 待 T7 裁决后在暗块补定义（若裁决为扩档）；否则由消费文件就地注释授权 |
| **T8**（ui/Button 等族归位） | `ui/Button` 私域 token 族归位到全局 | #4/#8 Button 暗块收编归 T8；`:162-163` 冗余 `.theme-dark` 选择器在 T8 一并删 |
| **T2 / T6 / T11** | 地基/分类/层叠修复 | 本 T26 不触碰；但收编后若新增 token，须经 T6 的 `token-registry.json` 登记与 T11 选择器层叠校验 |
| **P11 层叠穿透**（属 T18/C） | 浮层 z-index / stacking | Dialog backdrop 收编需注意其 `position:absolute; inset:0` 是否被祖先 `isolation/contain` 截断——与 T18 同查 |

> **裁决依赖**：T26 只「勘测 + 登记」。是否落 `tokens.css`、落哪些 token、落哪个暗块位置，全部由 T7/T8 在 `tokens.css` 串行序内裁决，T26 不预写。

## 六、与既有 token 重合结论（无需扩档清单）

经逐处核对 `tokens.css`（亮块 `:33-`、暗块 `:764-`），以下分支的暗色取值**完全可由现有 token 表达或派生**，本勘测结论为**无需新增任何档位**：

| 分支 | 重合的现有 token | 结论 |
|---|---|---|
| Button `.buttonSecondary` 暗块（#4/#8） | `--text-primary` / `--bg-card` / `--shadow-color` / `--hairline` | ✅ 现有 token 派生，**无需扩档**；归 T8 私域族归位 |
| Dialog `.backdrop`（#5） | `--shadow-color`（强度/模糊无现 token，但单处） | ⚠️ 主值现有；强度/模糊为单处一次性 → 就地注释授权 |
| ComposerNoticeBar `.noticeBar`（#6） | `--surface-paper` / `--bg-card` | ✅ 现有 token，**无需扩档**（单处 → 注释授权） |
| ComposerNoticeBar `.noticeBar.error`（#7） | `--color-error` / `--bg-card` / `--border-subtle` | ✅ 现有 token 派生，**无需扩档**（单处 → 注释授权） |
| SettingsShortcutsTab `.recording`（#1） | `--brand` / `--brand-deep` / `--bg-card` | ⚠️ 值现有，但「录制态」语义仅 1 处 → 不建新 token，就地注释授权 |
| ModelsSettingsTab `.modelsRail`/`.modelConfigPanel`（#2/#3） | `--bg-primary` / `--bg-card` / `--bg-card-subtle` | ⚠️ 值现有，但混色比例为单处一次性 → 就地注释授权 |

**最终结论**：T26 实测后**无任何主题分支强制要求新增 `tokens.css` 档位**。所有暗色取值要么已是现有 token 派生，要么是单文件一次性混色比例（按扩档纪律就地注释授权、不入库）。B6 §七 预登记的 `--recording-bg` 与「models 浮层底色」经查均**未达「同一语义 ≥2 处」门槛**，登记条目与自查结论见 `03-待裁决扩档需求.md` §六。
