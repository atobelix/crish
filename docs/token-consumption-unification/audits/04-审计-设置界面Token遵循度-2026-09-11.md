## 〇 结论先行

**判定：设置界面的 token 遵循度整体偏弱——token「被引用」了，但引用方式系统性携带裸兜底与裸几何值，构成第二真源；且存在一处已实测证实的档位级失效。**

| 指标 | 值 |
|---|---:|
| 审计 CSS 文件（去重） | **41**（设置域自有 28 · 外壳 3 · 共享 UI 组件 12 · 跨域复用 1） |
| 审计行数 / 声明数 | 9,439 行 / 5,336 条声明 |
| `var()` 引用 | 1,893 |
| **F1 裸兜底（值与真值一致）** | **355**（占 var 引用 18.8%） |
| **F1 兜底矛盾** | **61 处声明 / 68 次 var 出现**（其中 7 处为运行时注入白名单，真矛盾 **54 处**） |
| **F4 裸几何值（px 直接量）** | **751**（占声明 14.1%） |
| F3 组件私域岛 / 跨文件私域 | 180 / 7 |
| F6 悬空引用 | 12（**全部**为 Radix/Tooltip 运行时注入白名单，**无真实缺陷**） |
| F4 裸颜色字面量 | **0** ✅ |
| `!important` | **0** ✅ |
| 运行时 `setProperty` 注入 | **0** ✅ |
| 违规声明合计 | **1,344**（占声明 25.2%） |

**三条主结论**：

1. **「写法合规」掩盖了「真源分裂」**。设置域几乎每条 `var()` 都带兜底值（355 处），token 一旦缺失或被删，界面会静默落到兜底值而无人察觉；其中 **54 处声明（68 次 var 出现）的兜底值与 tokens.css 真值直接矛盾**（例：`.navBack` 用 `var(--control-height-lg, 32px)`，真值是 36px）。现有门禁 `check-token-consistency` 只统计「无兜底引用」，对这 430 处裸兜底**完全不可见**——这是本次审计发现的最大盲区。
2. **浅色/默认主题下「界面尺寸（密度）」三档整体失效（已实测证实）**。50 个密度相关 token 同时定义在 `(0,1,1)` 主题块与 `(0,1,0)` 密度块，浅色主题按特异性被主题块永久压制。真实 Chromium 实测：浅色下 `--space-1/--font-size-base/--control-height/--radius-lg/--header-height` 在 small/medium/large 三档**取值完全相同**；暗色下三档正常。详见 §2。
3. **模型屏（models）是设置域分裂热点**：1,479 行 CSS 中 251 条违规（裸几何 153 + 裸兜底 95），另叠加 **41 处硬编码内联 style** 集中在 `settings-models/` 的 7 个子组件——该屏是「CSS module + token」与「TSX 内联样式」双轨并行的重灾区。

## 二、定义面档位层叠实测（F5，最严重）

### 2.1 结构

`styles/tokens.css` 中密度档与主题块的**选择器特异性不匹配**：

| 块 | 选择器 | 特异性 |
|---|---|---|
| 基础 + 浅色 | `:root, html[data-theme='default'], html[data-theme='light']`（tokens.css:33-35） | **(0,1,1)**（经 `html[data-theme]` 匹配） |
| 暗色 | `html[data-theme='dark']`（:764） | (0,1,1) |
| 密度 small | `[data-ui-size='small']`（:1293） | **(0,1,0)** |
| 密度 large | `[data-ui-size='large']`（:1357） | **(0,1,0)** |

**50 个 token 同时定义在主题块与密度块**：`--space-0_5…10`(13) · `--font-size-xxs…xl`(7) · `--radius-xs…3xl`(7) · `--line-height-*`(3) · `--control-height(-sm/-xs/-lg)`(4) · `--icon-size(-sm/-lg)`(3) · `--header-height` · `--panel-gap/-pad-x/-pad-y`(3) · `--card-header-*`(4) · `--settings-sidebar-width` · `--tab-gap` · `--md-text-size/-code-font-size/-table-font-size`(3)。

### 2.2 运行时属性落点（代码实测）

- `data-theme` → `html`（`TokenRuntimeController.ts:465`）**且** `body`（:467）
- `data-ui-size` → `html`（`visualThemeController.ts:31`、`useAppearanceSettings.ts:249/254`）**且** `body`（`AppBootstrap.ts:264`）
- **但 `App.tsx:117` 调用 `useAppBootstrap({setAppSettings, productShell})` 未传 `uiSize`** → `AppBootstrap.ts:252` 取 `uiSize || 'medium'` → **`body` 恒为 `data-ui-size="medium"`**；而 tokens.css 只有 small/large 两档块，`medium` 无块 → `body` 上密度块不命中，只能继承 `html` 的解析结果。

### 2.3 浏览器实测（真实 Chromium + 真实 tokens.css）

复刻运行时属性分布（`html=真实档位 / body=stale medium`），对 body 后代元素取 `getComputedStyle`：

| token | theme=default | theme=light | theme=dark |
|---|---|---|---|
| `--space-1` | small=4px · medium=4px · **large=4px** ✗ | 同左 ✗ | 4/4/**6px** ✓ |
| `--font-size-base` | 13/13/**13px** ✗ | 同左 ✗ | 13/14/**16px** ✓ |
| `--control-height` | 30/30/**30px** ✗ | 同左 ✗ | 30/32/**34px** ✓ |
| `--radius-lg` | 8/8/**8px** ✗ | 同左 ✗ | 8/8/**10px** ✓ |
| `--header-height` | 32/32/**32px** ✗ | 同左 ✗ | 32/36/**40px** ✓ |

**结论（已实测，非推理）**：
- 浅色 / 默认主题：`html[data-theme='light']` 以 (0,1,1) 压制密度块 (0,1,0) → **设置页「外观 → 界面尺寸」三档对 50 个 token 全部无效**。
- 暗色主题：暗色块未定义这 50 个 token，只剩基础块 `:root`(0,1,0) 与密度块 (0,1,0) 同特异性，密度块在源码序后方胜出 → 正常生效。
- 对照组：若 `body` 的 `data-ui-size` 与 `html` 同步（修掉 App.tsx 缺参），三档在**所有主题**都正常生效——即 **一行传参修复即可让密度在浅色主题复活**。

### 2.4 连带失效：两个「幽灵属性」

`AppBootstrap.ts:262-266` 写入的 `data-density` 与 `data-shell-chrome`，在 `src/**/*.css` 中**零消费**（grep 全仓无命中）→ 「密度语义」「壳层样式模式」两个设置项写得出、读不进。设置域内反而用**硬编码** `data-density="compact"`（`SettingsPanel.tsx:278/289/325`、`SettingsSidebar.tsx:74`、`SettingsQuickMenu.tsx:258/284`、`FontSelectField.tsx:184`）——该属性同样无 CSS 消费方。

## 五、修复建议（消费面收敛，不动定义体系）

**原则**：只收敛消费面；禁止趁机重做 token 定义、禁止自扩档位（确需新档 → 走 `03-待裁决扩档需求.md` 登记）。

**A. 一行修复解锁密度档（最高杠杆）**
`App.tsx:117` 向 `useAppBootstrap` 传入 `uiSize`（来自 layoutStore），使 `body` 的 `data-ui-size` 不再钉死 `medium`。已实测：该修复让浅色主题三档全部生效，无需改动 tokens.css。

**B. 外壳祖容器去裸兜底（13 屏同时受益，共 73 处）**
`SettingsPanel/SettingsQuickMenu/SettingsUI` 三个文件：删去与真值一致的兜底值（`var(--space-2, 8px)` → `var(--space-2)`）；矛盾兜底改为正确 token（`--control-height-lg` 兜底 32px → 删兜底；`--transition-micro` 兜底 120ms → 删兜底）。

**C. 54 处矛盾兜底按「先删兜底、后对真值」两步收敛**
优先级：`--transition-micro`(19 声明/33 次) > `--opacity-disabled 0.45`(11) > `--focus-ring` 两文件互斥 > `--z-dropdown`（Menu:9 兜底 100，实际把设置内下拉层级压到 100）> 其余单点。`--font-size-xl 20px`（SettingsUI:42）虽只 1 处，但它是**所有 13 屏的页标题字号**，修复杠杆同样很高。

**D. 127 处刻度外裸值迁档**
`999px` → `var(--radius-full)`（7 处，纯错值）；`140px` 表单最小宽度 → 登记为布局 token 或改用容器查询；小数刻度（10.5px 等 15 处）→ 按 §7.1 上真机核验 DPR 表现后归档或保留并注释授权。

**E. models 屏双轨归一**
`settings-models/` 7 个子组件的内联样式迁入 CSS module 并 token 化；`sr-only` 两处内联改用 `styles/sr-only.css` 既有类。

**F. 主题分支下沉收编**
3 处 `:global(html[data-theme='dark'])` 改为语义 token（如新增 `--recording-bg` 类），或至少收编到 `design-system.css` 统一登记。

**G. 门禁棘轮（新增盲区指标，基线只紧不松）**
现有门禁不覆盖裸兜底。建议在 `check-token-consistency.mjs` 增加 `bare_fallback_refs` 与 `contradictory_fallback_refs` 两项指标，初始基线取本次实测值（`bare_fallback=430` / `contradictory=75`），只降不升；`--button-radius` 这类「锁死禁止覆写」的 token 可白名单化兜底（或直接视为违规，二选一需裁决）。

## 八、方法复现

1. **导入闭包**：从 `SettingsPanel.tsx` 与 13 个 tab 入口做静态 import / 动态 `import()` 递归解析，得到 41 个唯一 CSS（脚本含 `@/` 与相对路径解析、`.module.css` 归集）。
2. **CSS 解析**：自写解析器（`csslib.py`）处理 `@media/@supports` 嵌套与注释，产出带行号的 `(selector, prop, value)` 记录；`var()` 用括号配对递归展开，兜底只在顶层逗号切分（规避 `var(--a, var(--b, 4px))` 截断陷阱）。
3. **真值表**：从 `tokens.css`/`z-index.css` 等定义面提取每 token 的全部取值，`var(--x)` 型定义递归展开 ≤3 层；兜底值与真值集合比对 → 一致/矛盾。
4. **F5 实测**：Playwright + Chromium 加载真实 `tokens.css`，按运行时属性分布设 `html`/`body` 属性，`getComputedStyle` 取 6 组合 × 18 token 实际值。
5. **逐元素明细**：按选择器聚合违规声明，输出附录 A（3,817 行）。
