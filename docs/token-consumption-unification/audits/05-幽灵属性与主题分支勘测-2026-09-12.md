## 五、待裁决项（上报主 Agent / 产品决策）

### 5.1 「壳层样式」设置项是否为幽灵设置

- **事实**：设置页"壳层样式"设置项经 `useAppearanceSettings.ts:155` 订阅 `layoutStore.shellChromeMode`，并在变更时写入 DOM 属性 `data-shell-chrome`（`:267/271/272`）；`AppBootstrap.ts:263/266` 亦写入该根属性。
- **消费面**：`data-shell-chrome` 在 `*.css` 中 **0 命中**（CSS 零消费）；仅 JS 侧（visualThemeController 监听 layoutStore、测试断言）读取。
- **判定**：DOM 属性本身被 JS 消费（**未切除**，故非严格"无消费者"），但**其视觉效果在 CSS 层完全不可见**——设置项"写得出、界面不变"。这与 P3"幽灵契约"同源。
- **处置**：**禁止自行删除 UI**（产品决策）。两条路径上报裁决：
  - **路径 A（接线）**：在 shell CSS（`styles/shell/shell-reset.css` 或 shell-layout）新增 `[data-shell-chrome='classic'|'unified']` 选择器，让该设置项产生真实视觉差异（如标题栏/边框形态）。
  - **路径 B（下线）**：若产品判定该设置无存在价值，由产品决策后下线设置项 UI 及其 store 字段（`layoutStore.shellChromeMode`），而非保留无效应控件。

### 5.2 SettingsQuickMenu 测试预存失败（非本单元引入）

- 失败用例：`SettingsQuickMenu.test.tsx:72-79`「键盘漫游：ArrowDown 循环聚焦」。
- 验证：临时**恢复** `data-density="compact"` 后重跑，该用例**依旧失败** → 证明失败与本次死属性切除无关，属预存问题（jsdom 焦点漫游 / Menu roving 实现层面）。
- 其余 5 例 + `SettingsPanel.wheel` + `visualThemeController` 测试均绿。
- 建议：另派单元排查 Menu 焦点漫游；本单元不背此锅。
