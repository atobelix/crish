# 防御体系改进台账（发现 → 门禁）

> **用途**：本项目出现的**每一个问题**都必须转化为一条防御能力。本台账是「发现 → 门禁」的唯一映射表，也是下次同类问题的第一道拦截点。
> **纪律**：发现被记录但未转化为门禁 = 未完成。每条须有 **证据 · 门禁动作 · 状态 · 负向验证方式**。
> **更新于**：2026-09-11

## 二、门禁自身的缺陷（元层发现 → 已转化为门禁）

| # | 发现 | 证据 | 门禁动作 | 状态 |
|---|---|---|---|---|
| **D6** | **接线缺口**：41 个 check 脚本中大量未接入 husky/CI，「有门禁」只是纸面事实 | 实测：`check:desktop` 链在 husky/CI/turbo 中**无调用点**；`check-layout-tokens`/`check-color-ssot`/`check-text-color` 等仅手动 | **新增棘轮指标 `unwired_guard`**：每个守卫必须接入 husky 或 CI，否则进 `UNWIRED_ALLOWLIST` 并写明理由 | ✅ 指标 = 20（存量，棘轮） |
| **D7** | **接线检测假阴性**：CI 以 `npm run check:xxx` 调用，不含文件名字面量 → 只按文件名判断会把**已接线**的门禁误报为未接线 | 实测：`check-css-encoding` 等确在 `ci.yml` 中，却被漏判 | `check-guard-system.mjs` 增加「门禁文件 ← npm 脚本名」映射，支持 `npm:<key>` 间接接线判定 | ✅ 29 → 20（消除假阴性） |
| **D8** | **检测器假阳性**：用 `[\s\S]{0,1200}?` 跨块匹配 `process.exit(0)`，会把紧随其后的**合法成功分支**误判为「静默建线」 | 实测：修好后的 `check-token-ssot.mjs` 仍被误报 | 改为**花括号配平取块**，只在「基线缺失」分支块内检测 `exit(0)` | ✅ 误报消除（1 → 0） |

| **D10** | **聚合缺位**：逐个跑门禁时首个 FAIL 中断后续（`&&` 链），看不到全貌 | 无聚合入口 | 新增 `check:tokens-all` 聚合入口：**全部跑完再汇总**，为每项失败附 `--guide` 复现提示 | ✅ 已落地 |

| **D24** | **守卫自身性能不可用**：逐路径调用 `git check-ignore` 共 45 次 spawn，在本仓库（60 万+ 资产）实测 **2 分 50 秒** → 作为 pre-commit 完全不可用（等同于变相禁用） | 实测计时 | 改为**单次批量调用**并解析 stdout → **5.7 秒**。教训：**守卫的性能就是它的可用性**；超慢守卫会被开发者绕过或禁用 | ✅ 170s → 5.7s |

## 四、门禁可移植的元教训（写入新守卫的必读清单）

1. **检测器必须双向验证**：新增检测规则后，既要证明它会 FAIL（负向夹具），也要证明**不该 FAIL 的不会 FAIL**（正向夹具）。本轮 `D7`/`D8` 两次翻车都源于只验了单向。
2. **假阴性比假阳性更危险**：假阳性让人不信任门禁，**假阴性让人误以为安全**。接线检测必须覆盖「经 npm 脚本间接调用」这类间接路径。
3. **不要用宽松正则跨语义块匹配**：`[\s\S]{0,N}` 这类匹配必然跨块误伤；需要块级判定时用**花括号配平**。
4. **守卫自身也要被守卫**：门禁不接线 = 纸面事实；门禁静默通过 = 反效果；门禁无指引 = 把成本转嫁给下一个执行者。三者都有指标了。
5. **「不能跑」与「跑出来是错的」要分开计量**：BOM 让 `node --check` 误报，但脚本实际可用 —— 把 BOM 作为独立卫生债（`bom_in_guard`），而不是谎报 `broken_guard`。
6. **基线不是垃圾桶**：硬失败指标目标恒为 0，**不读基线**；存量只能进缺口台账。
7. **守卫的性能就是它的可用性**：一个 2 分 50 秒的 pre-commit 守卫会被所有人绕过或禁用。凡涉及子进程批量探测，必须合并为单次调用。
8. **「资产未入库」是无声的**：本地一切正常，故障只在 clone / CI 环境出现。凡是"必须随仓库分发"的东西（门禁、登记表、基线），都要有一条门禁确认它真的会被提交。
9. **先看仓库既有惯例再动手**：`.gitignore` 的逐条 `!` 放行是既有约定，新守卫必须沿用；忽略这一点会让资产静默丢失。
