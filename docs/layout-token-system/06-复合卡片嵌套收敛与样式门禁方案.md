### 1.2 架构愿景与重构边界

本方案旨在建立一套覆盖**全链路复合卡片嵌套收敛、侧栏与全屏设置解耦、既有样式契约清零与新型布局 Token 静态门禁**的工业级工程规范。

1. **边界约束**：方案范围严格覆盖工具调用卡片族（`ModernToolCall`、`ChatToolCallBlock`）、子代理协作面板（`InlineAgentPanel`、`AgentCard`）、高危审批卡片（`ApprovalAskCard`）、全局侧栏（`Sidebar`、`SidebarNav`、`SidebarSessionList`）、全屏设置壳层与通用排版（`SettingsPanel`、`SettingsUI`、`ModelsSettingsTab`）、既有样式契约（`style-contract.test.ts`）以及全新门禁引擎（`check-layout-tokens.mjs`、`layout-contract.test.ts`）。
2. **零退避原则**：绝不通过“删除断言”、“放宽基线阈值”、“隐藏功能”等退避手段达成测试通过；每一项问题必须穿透至根因，给出具有 O(1) 复杂度、完全自洽的原生解决方案。

### 1.3 四大核心设计军规（零容忍）

依据 `AGENTS.md` §1、§7、§13，本方案全流程刚性贯彻以下四项底线原则：

1. **【铁律一：单一包含块盒模型（Single Box Model Principle）】**
   嵌套子视图（如内嵌 Diff、内嵌终端、内嵌参数 Pre）在父级容器中一律放弃外边框（`border: none`）、外圆角（`border-radius: 0`）与外边距（`margin: 0`），统一由父级卡片承担外轮廓。**严禁使用任何 `!important` 强行清空样式，必须通过属性（Props）与数据驱动形态（Variants）从源头渲染无边框内嵌形态。**
2. **【铁律二：同心圆角几何法则（Concentric Radius Formula）】**
   任何具有可见边框或背景的嵌套容器，其外层圆角 $R_{outer}$、内层圆角 $R_{inner}$ 与内衬 $Padding_{inner}$ 必须严格遵循物理同心公式：
   $$R_{inner} = \max(0, R_{outer} - Padding_{inner})$$
   当 $Padding_{inner} \ge R_{outer}$ 时，内层直接退化为平直直角（$0\text{px}$），彻底终结“内大外小”的畸变几何。
3. **【铁律三：原生容器隔离取代 JS 事件拦截（CSS Containment over JS Hack）】**
   禁止在 React 组件根节点监听 `onWheel` 并通过 `scrollTop += deltaY` 模拟滚动；必须通过清晰的语义化容器架构（长文档型 `data-layout-kind="document"` vs 视口工作台 `data-layout-kind="workbench"`），依赖 CSS 原生的 `overflow`、`overscroll-behavior: contain` 与 `contain: strict` 实现纯天然的滚动隔离。
4. **【铁律四：门禁不可逾越与渐进棘轮只降不增（Ratchet Monotonicity）】**
   门禁系统是架构资产的守护神。修复现有 5 项契约测试失败；新建 `check-layout-tokens.mjs` 静态守卫；全仓裸混色、裸像素间距、非法负 margin 实行棘轮机制（Ratchet），违规数量只能单调递减，新增违规在 Git Hook 与 CI 快层刚性阻断。

## 二、工具卡片与子代理面板嵌套边框/内衬收敛方案

### 2.1 根治 3 重边框嵌套与暗色发脏（单一包含块边界法则）

#### 2.1.1 嵌套边框叠加机理与暗色发脏剖析
在当前的 DOM 树中，从消息行到最终代码 Diff 呈现出灾难性的 4 层封闭描边堆叠：
- **L6 展开卡主体**（`.toolResultBody`）：`border: 1px solid var(--border-subtle); border-radius: 8px;`；
- **L7 输入输出分区**（`.toolSectionInput`）：`border-bottom: 1px solid var(--border-subtle);`；
- **L8 差异卡片主体**（`.diffCard`）：`border: 1px solid var(--border-subtle); border-radius: 10px;`；
- **L9 差异标题行**（`.diffCardHeader`）：`border-bottom: 1px solid var(--border-subtle);`；
- **L10 内嵌代码块**（`.codeBlockCard`）：`border: 1px solid var(--border-subtle); border-radius: 8px;`。

在深色模式（Dark Mode）下，`--border-subtle` 通常由 `hsl(215 15% 20%)` 或 `color-mix` 派生。当三层深灰色线条在 10px 的狭窄物理空间内连续并置时，视网膜感知到的不是精致的层次，而是厚重、脏污、压抑的“多层线框囚笼”；并且由于各层 border-radius 互不匹配（外 8px、中 10px、内 6px），在转角处形成参差不齐的光学黑边与亚像素抖动。

#### 2.1.2 单边框架构与容器边界重构（Border Containment Architecture）
推行**单一包含块原则**：
1. **外壳独占轮廓权**：只有顶层的 `.toolResultBody`（或 `.jsonToolCard`、`.terminalCard`）允许拥有 `border: 1px solid var(--border-subtle)` 与 `border-radius: var(--radius-card-outer, 8px)`；
2. **内嵌子卡片边框剥离**：当 `ToolCallDiffPreview`、`ModernCodeBlock`、`ModernTerminalToolCall` 渲染于展开卡主体内时，其外层描边统一降解为零（`border: none`），外圆角统一降解为零（`border-radius: 0`）；
3. **语义分割线取代全闭合矩形**：各功能分区之间不再通过独立卡片封装，而是通过极简的 1px 单向分割线分隔：
   ```css
   .toolSectionDivider {
     height: 1px;
     background: var(--border-subtle);
     margin: 0;
     border: none;
   }
   ```
4. **同心圆角硬锁合**：对于卡片内部确需保留的独立胶囊元素（如 `.paramPill`、`.diffStatAdd`），严格遵循数学法则：
   $$R_{pill} = \min(4\text{px}, \max(0, R_{outer} - Padding))$$
   锁定胶囊最大圆角为 4px（`var(--radius-sm)`），彻底杜绝转角贴边畸变。

### 2.2 彻底废除 `.embeddedDiffCard` 的 4 个 `!important` 补丁（属性驱动盒模型）

#### 2.2.1 现状批判
在 `ChatToolCallBlock.module.css:609-614` 中，存在极其恶劣的“补丁代码”：
```css
/* apps/crish-desktop/src/components/chat-tool-call/ChatToolCallBlock.module.css:609-614 */
.embeddedDiffCard {
  border: none !important;
  border-radius: 0 !important;
  margin: 0 !important;
  background: transparent !important;
}
```
这种写法存在三重严重弊端：
1. **违背架构军规**：直接违背了 `AGENTS.md` §7“严禁使用补丁代码，必须穿透表象找到架构断层”的底线；
2. **覆盖面极其脆弱**：仅当父级手动传递了 `embeddedDiffCard` 类名时才生效；一旦渲染其他子组件，多重边框立即原形毕露；
3. **CSS 特异性污染**：使用 4 个 `!important` 阻断了所有正常的 CSS 级联机制，导致后续的主题定制和紧凑模式覆盖彻底失效。

#### 2.2.2 属性驱动（Variant-Driven）单一盒模型方案
彻底删除 CSS 中的 `!important` 覆盖规则，改为基于 React 属性与原生 CSS 属性选择器的正交化模型：

1. **类型契约升级**：
   在 `ToolCallDiffPreview.tsx`、`ModernTerminalToolCall.tsx`、`ModernCodeBlock.tsx` 的 Props 中，正式引入：
   ```typescript
   export interface NestedCardLayoutProps {
     /**
      * 容器渲染形态：
      * - 'standalone': 独立卡片（带外边框、圆角、外边距、阴影）
      * - 'embedded': 内嵌卡片（无外边框、直角贴边、零外边距、背景透传）
      * 默认值：'standalone'
      */
     variant?: 'standalone' | 'embedded';
   }
   ```
2. **DOM 属性投影**：
   组件根节点通过 HTML5 数据属性暴露自身形态：
   ```tsx
   <div
     className={styles.diffCard}
     data-card-variant={variant}
     data-testid="tool-diff-card"
   >
     ...
   </div>
   ```
3. **CSS 模块原生零侵入编排**（`ModernToolCall.module.css`）：
   ```css
   /* 基座：所有形态共享排版与布局 */
   .diffCard {
     width: 100%;
     box-sizing: border-box;
     overflow: hidden;
     position: relative;
     height: auto;
   }

   /* 独立卡片态 (Standalone)：独立外显时施加完整闭合视觉 */
   .diffCard[data-card-variant='standalone'] {
     margin: var(--space-2, 8px) 0;
     border: 1px solid var(--border-subtle);
     border-radius: var(--radius-card-outer, 8px);
     background: var(--bg-card);
     box-shadow: var(--shadow-sm);
   }

   /* 内嵌模式 (Embedded)：在工具卡内部作为内衬平铺，天然无边框，无 !important */
   .diffCard[data-card-variant='embedded'] {
     margin: 0;
     border: none;
     border-radius: 0;
     background: transparent;
     box-shadow: none;
   }
   ```
通过这一改造，无论父级是 `ToolCallOutput` 还是独立画布，内嵌组件依据上下文属性自动决定自身盒模型，4 个 `!important` 被彻底、永久地从代码库中清除！

### 2.3 头部控制行收敛归一为 24px / 32px 标准双阶梯

#### 2.3.1 头部高度从 8 级离散到 2 级收敛
根据调研报告 06 统计，现有系统存在 `22px`、`24px`、`26px`、`28px`、`32px`、`33px`、`36px`、`40px` 共 8 级混乱高度。不仅破坏了垂直节奏（Vertical Rhythm），更导致子代理面板中 `styles.agentCardHeader`（32px）与 `styles.agentCardHeaderSlim`（28px）同时挂载引发的死代码冲突。

本方案将全仓所有工具卡片、时间线与子代理面板的头部控制行，严格收敛为 **2 级工业级高度阶梯**：

├─────────────────┼──────────┼───────────────────────┼─────────────────────────┤

### 5.2 核心静态拦截引擎：`scripts/check-layout-tokens.mjs` 规范与实现设计

新建 `scripts/check-layout-tokens.mjs`，基于成熟高效的静态文本扫描与正则状态机，提供刚性拦截。

#### 5.2.1 脚本核心架构设计

```javascript
/**
 * scripts/check-layout-tokens.mjs
 * 布局 Token 与盒模型安全刚性门禁脚本
 *
 * 核心检查项：
 * 1. 裸像素间距拦截 (Bare Pixel Spacing)：margin/padding/gap 严禁裸写非标像素；
 * 2. 非法负边距拦截 (Illegal Negative Margins)：严禁任何绝对值 > 2px 的负 margin；
 * 3. 跨层穿透选择器拦截 (Anti-Penetration)：严禁在 module.css 中对子组件使用 :global(...)；
 * 4. Fallback 单源校验 (Fallback SSOT)：所有 var(--space-N, fallback) 必须与 :root 完全等价。
 */

import { readFileSync, readdirSync } from 'node:fs';
import { join, resolve } from 'node:path';

const SRC_DIR = resolve('apps/crish-desktop/src');
const TOKENS_PATH = resolve('apps/crish-desktop/src/styles/tokens.css');

// 1. 建立 :root 静态真源字典
const SPACING_SSOT = {
  '--space-0_5': '2px',
  '--space-1': '4px',
  '--space-1_5': '6px',
  '--space-2': '8px',
  '--space-2_5': '10px',
  '--space-3': '12px',
  '--space-3_5': '14px',
  '--space-4': '16px',
  '--space-5': '20px',
  '--space-6': '24px',
  '--space-8': '32px',
  '--space-10': '40px',
};

// 白名单文件（全局定义样式不属于业务组件拦截域）
const GLOBAL_STYLE_WHITELIST = new Set([
  'tokens.css',
  'index.css',
  'design-system.css',
  'reduced-motion.css',
  'overlay-scrollbar.css',
]);

// 负 Margin 白名单规则（仅允许发丝贴合与触控微调）
const ALLOWED_NEGATIVE_MARGINS = new Set([
  '-1px',
  '-2px',
]);

export function runLayoutChecks() {
  const errors = [];
  const files = walkFiles(SRC_DIR);

  for (const filePath of files) {
    const filename = filePath.split(/[\\/]/).pop();
    if (GLOBAL_STYLE_WHITELIST.has(filename)) continue;
    if (filename.endsWith('.test.ts') || filename.endsWith('.test.tsx')) continue;

    const content = readFileSync(filePath, 'utf8');
    const lines = content.split(/\r?\n/);

    // 执行规则 1 ~ 4 检查
    checkBarePixels(filePath, lines, errors);
    checkNegativeMargins(filePath, lines, errors);
    checkPenetrationSelectors(filePath, lines, errors);
    checkFallbackSSOT(filePath, lines, errors);
  }

  if (errors.length > 0) {
    console.error(`\n❌ 发现 ${errors.length} 处布局 Token 违规项：\n`);
    for (const err of errors) {
      console.error(`  - [${err.rule}] ${err.file}:${err.line} -> ${err.message}`);
    }
    process.exit(1);
  }

  console.log('✅ 布局 Token 与样式契约门禁检查全部通过！');
}
```

#### 5.2.2 四大拦截引擎规则细节
1. **Rule 1: 裸像素间距拦截**：
   匹配包含 `margin`, `padding`, `gap` 的声明行，识别出含有 `3px`, `5px`, `6px`, `7px`, `9px`, `10px`, `11px`, `13px`, `14px`, `15px`, `18px`, `22px`, `26px`, `28px` 等未被 `var(...)` 包裹的裸像素值。
   - 例外放行：`0`, `0px`, `1px`（描边贴合）、`2px`（亚像素居中补偿）。
2. **Rule 2: 非法负边距拦截**：
   匹配 `margin-top: -Npx`, `margin-bottom: -Npx` 等，当且仅当 $N > 2$ 时触发硬阻断：
   `"禁止使用非法负 margin: ${val}。大尺寸位移必须改用 transform: translateY() 或 absolute 定位。"`
3. **Rule 3: 跨层穿透选择器拦截**：
   在 `*.module.css` 中匹配 `:global(button)`、`:global(.input-container)`、`:global(.model-badge-btn)` 等选择器：
   `"禁止跨层穿透重写子组件样式。必须通过子组件 Props 或局部 CSS 变量通信。"`
4. **Rule 4: Fallback 单源契约校验**：
   正则抓取 `var\((--space-[\w_]+)\s*,\s*([^)]+)\)`，若第二个参数存在且不等于 `SPACING_SSOT[token]`，即刻阻断：
   `"--space-2 的法定静态值为 8px，检测到错误回退值: 6px。"`

## 七、方案总结与结论

本方案针对 Conex / Crish 桌面端长久存在的“边框嵌套发脏”、“样式补丁累加”、“高度缩进离散”、“全屏设置耦合”与“样式门禁失守”等系统性顽疾，进行了深入骨髓的根因剖析与工程级重塑：

1. **结构净收敛**：通过推行「单一包含块盒模型」与属性驱动机制，彻底拔除了 `.embeddedDiffCard` 中 4 个丑陋的 `!important`，消除了转角曲率畸变与深色模式视觉污染；
2. **几何秩序建立**：将离散多达 8 级的高度收拢归一为 24px（紧凑行）与 32px（标题栏）双阶梯，全仓指示点锁定 6px，缩进锁定 24px 严格栅格，修复了审批卡片在紧凑模式下的光学补偿缺失；
3. **架构正交解耦**：制定了完善的 `--sidebar-*` 与 `--settings-*` 专有 Token 体系，消歧 `--settings-content-max` 为 820px，将长文档与视口工作台在 CSS 层面原生分型，连根拔除了 29 行生硬的 `handleRootWheel` JS 补丁；
4. **门禁长治久安**：修复了现场失败的 5 项既有契约断言，新建 `check-layout-tokens.mjs` 静态守卫与 `layout-contract.test.ts` 测试套件，构建了从 Phase 0 到 Phase 4 的单调递减棘轮基线，确保未来迭代零回潮。

方案设计完全遵循《反过度设计硬性红线》与《通用协作纪律》，各项技术选型纯粹基于原生 CSS 盒模型与轻量静态扫描，无沉重第三方抽象，具备极高的可维护性与生产落地确定性。
