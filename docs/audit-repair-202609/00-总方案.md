#### T1 ConPTY slave 保活误诊：回退死代码 + 真因验证
- **问题**：f05f9c9b 在 `apps/agent-workbench/src-tauri/src/pty/session.rs:84-89` 增加 `_slave: Option<Box<dyn SlavePty + Send>>` 保活字段，注释称「drop slave 会 ClosePseudoConsole 杀子进程」。已核实 portable-pty 0.9.0 源码（`win/conpty.rs` `openpty`）：`ConPtySlavePty { inner: master.inner.clone() }`——slave 与 master 共享同一 `Arc`，session 生命周期内 master 始终持有，drop slave 不可能触发 ClosePseudoConsole。该改动基于错误诊断，属无效复杂度 + 误导性注释。
- **文件域**：`apps/agent-workbench/src-tauri/src/pty/session.rs`。
- **方案**：
  1. 删除 `_slave` 字段、`create_session` 中的 `#[cfg(windows)] slave_holder` 分支（恢复 Unix/Windows 统一 `drop(pair.slave)` 惯例，删除误导注释）。
  2. 若历史上确曾观察到「子进程秒死」，另开验证任务定位真因（候选：master 提前 drop、`resize` 在 spawn 前调用、子 shell 自身崩溃）；在真因确认前不做任何补偿代码。
  3. 追加一个 Windows 单测/集成探针：spawn PTY → drop slave → 2s 后断言子进程仍存活、写命令有回显（防回归锚）。
- **验收**：`cargo test -p agent-workbench` 全绿；新探针在 Windows 真机通过；`session.rs` 中无 `_slave` 与相关注释残留。

#### T7 空笔记首块闭环（打通「点击 → 真实块 → 打字落盘」）
- **问题链**（三处叠加导致空笔记打字永远 `unsaved`）：
  1. `NotePaperStrictBody.tsx:64/116` 的 `onInitFirstBlock` 全仓无调用方传入——点击空白只会切 `emptyInitRow` 本地态，不创建块；

  3. `TextEngine::apply_edit`（`crates/conex-doc-collab/src/text_engine.rs:332`）对未注册块 `ensure_hot` 直接报错 → 每次 text_edit 必败。
- **文件域**：`apps/crish-desktop/src/components/note-paper/NotePaperStrictPanel.tsx`、`NotePaperStrictBody.tsx`、（只读参照）`packages/block-paper/src/chrome/structureIntentToWire.ts`、`crates/conex-doc-collab/src/block_id.rs`。
- **方案**（复用既有 Insert 管线，零新概念）：
  1. `NotePaperStrictPanel` 实现 `handleInitFirstBlock`：生成真实块 ID（`crypto.randomUUID()`，与引擎 `BlockId::parse` 对齐），经既有结构意图管线（`structureIntentToOps` 的 `insert_block`/`slash_insert` + `collabOpsToJson`，order key 走既有 `resolveOrderKey`）通过本面板已用的 `resolvedApplyOps` 下发 Insert op；
  2. 成功后将真实块 ID 记入面板状态，`emptyInitRow` 渲染行的 `blockId` 由幽灵 ID 换成真实 ID（prop 透传至 `StrictContentRowLeaf`）；
  3. `NotePaperStrictPanel` 向 `NotePaperStrictBody` 传入 `onInitFirstBlock={handleInitFirstBlock}`；
  4. Insert 失败（backend 未接线）时初始化行保持但状态条显式「未连接存储」，不得假成功。
- **验收**：
  - jsdom：空文档点击 → `resolvedApplyOps` 收到 1 条 insert op（id 为合法 UUID）→ 行 blockId 更新为真实 ID；
  - jsdom：输入 "ab" → 依次收到 insert + text_edit，mock 后端记录 ops 序列；切换文档再切回，hydrate 回读内容一致（真机以 Tauri MCP 验证一遍端到端）。

#### T8 持久化差量化 + debounce + `flushPendingDraft` 真接线
- **问题链**：
  1. `NotePaperStrictPanel.tsx:168-198` `persistBlockText` 每次击键发 `{op:'text_edit', start:0, end:[...oldText].length, insert:newText}`——整块删除再整块插入：每键 O(n)、破坏引擎侧 undo/协作语义；
  2. `useNoteDocumentManager.ts:17/138/159` 的 `flushPendingDraft`（切换/新建前 500ms 赛马刷盘）唯一调用方 `NoteLeafHost.tsx:52-55` 从未传入——宣称的脏刷盘是死路径。
- **文件域**：`NotePaperStrictPanel.tsx`、`useNoteDocumentManager.ts`、`extensions/note-paper/NoteLeafHost.tsx`。
- **方案**：
  1. **差量 op**：新增纯函数 `computeTextEditOp(oldText, newText, blockId)`（common prefix/suffix 按码点修剪，产出单条 `[start,end)` 替换 op；无变化返回 null），配穷举单测（正逆对称、纯插入、纯删除、全删、IME 段替换、码点边界/emoji）。文件域放 `components/note-paper/noteTextEditOp.ts`（纯函数，零 React 依赖）；
  2. **debounce**：`onTextChange` 路径改为 400ms debounce 合并（同一 block 只保留最后一次差量基准），`onTextCommit`（失焦）路径立即 flush；`lastPersistedTextRef` 语义升级为「已确认落盘文本」；
  3. **flushPendingDraft 接线**：面板暴露 `flushPendingDraft`（同步 flush 所有 block 的待落盘差量，返回 Promise），`NoteLeafHost.tsx` 传入 `useNoteDocumentManager`；hook 内 500ms 赛马守卫逻辑保留不变；
  4. 切换文档时（`key={activeDocId}` 重 mount）unmount 前效应里同步 flush 一次（防 debounce 尾巴丢失）。
- **验收**：
  - `noteTextEditOp.test.ts` 穷举用例全绿；
  - 面板测试：连打 10 键只发 1 次 apply（debounce 后），内容与最终态一致；blur 立即 flush；switch 文档前 flushPendingDraft 被调用；
