# 统一模型能力、动态热更新与自适应交互方案 · 总纲

> **战役工作区**：`docs/model-capability/`
> **版本**：v3.0（动态热更新、通用思考契约与自适应缩写全面演进）
> **定位**：Conex / Crish 模型能力与交互体系最终实施指导总案
> **核心诉求**：
> 1. 思考等级全面采用英文展示（`Default`, `Low`, `Medium`, `High` 等），彻底清理“提供方默认”等生硬突兀文案；
> 2. 摒弃 AI 幻觉与过时写死的静态 catalog，建立**通用思考强度设计**，允许用户通过外部配置文件自主定义/纠正任意模型的思考形态与档位；
> 3. 建立模型配置的**外部文件热更新（Hot Reloading）管线**，实现外部配置保存即生效，零重启客户端；
> 4. 设计**模型名称智能自适应缩写算法（SADA）**，确保在容器窄宽时压缩空间且**绝对不失去关键版本与变体判别度**（彻底根治 `muse-spark-1.2-contributor` 与 `muse-spark-1.3-contributor` 截断为同名的问题）；
> 5. 全面重构模型与思考选择交互，实现自适应零重排渲染与高可读 Tooltip。

## 一、现状深度诊断与技术债根因分析

### 1.1 思考等级呈现生硬与前后端契约断层
- **UI 呈现断层**：
  - 在 [`ComposerFusedTrigger.tsx:31, 109`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/ComposerFusedTrigger.tsx#L31-L109) 中，代码在当前未显式设置思考档位时（值为 `'default'`），直接将 `'default'` 格式化为中文 `'提供方默认'` 渲染在右侧胶囊按钮内。
  - 该胶囊右半边缺少任何“思考”、“档位”等属性标识，使得用户在视觉上只看到【模型名称 | 提供方默认】，认知完全错位（误以为这是“模型提供方”，而非“思考等级”）。
- **前端消费侧断裂（严重 Bug）**：
  - 刚刚的后端重构将 `reasoning_effort_tiers` 与 `thinking_level_map` 合并为 `thinking_tiers`（JSON 为 `thinkingTiers`）。
  - 但前端 [`thinkingGear.ts:80`](file:///c:/Software/conex/apps/crish-desktop/src/api/thinkingGear.ts#L80) 漏改，仍读取旧字段，导致所有模型计算出的思考档位集 `offered` 恒为空数组 `[]`。
  - 前端被迫退化为只剩一项：`{ value: 'default', label: '提供方默认', isProviderDefault: true }`，所有真实思考档位（低/中/高/关闭）全部从界面蒸发。

### 1.2 内置 Catalog 静态固化与 AI 幻觉污染
- **编译期死绑定**：
  - [`crates/agent-provider/src/models/catalog.rs:342`](file:///c:/Software/conex/crates/agent-provider/src/models/catalog.rs#L342) 使用 `include_str!("catalog.json")` 打包进二进制。任何修改、新增模型或纠正参数必须重新编译整个 Rust 项目。
- **过时与幻觉条目充斥**：
  - 历史 catalog 记录了大量早期由 AI 凭空构想或过时的条目（如包含虚构的 `claude-fable-5`、`claude-opus-4-8` 等，而真实的 Gemini 3.8 Flash、SenseNova 6.8 等未收录）；
  - 随着现实世界中大模型快速迭代，硬编码的 JSON 无法跟上节奏。未被收录的新模型（如用户正在使用的 `muse-spark-1.3-contributor`、`sensenova-6.8-flash-lite`）直接被视作“未知模型保守不支持”，导致思考能力彻底不可用。
- **历史覆盖层僵化**：
  - 既有 `catalog_override.rs` 只开放了修改价格与窗口的白名单（`OVERRIDE_WHITELIST`），且明确禁止新增未收录条目，更不支持 `thinking_tiers`。

### 1.3 模型配置非热更新且存储碎片化
- **双轨与孤立存储**：
  - 内置目录在 Rust 内存 `Arc<RwLock<ModelCatalog>>`；
  - 用户在 UI 上添加的 Profile 和自定义模型保存在浏览器 `localStorage.crish_provider_profiles_v1`；
  - 密钥存放在 Rust DPAPI。
  - **没有任何外部文件可以作为模型能力的真实配置源**，更没有基于操作系统的文件监控（File Watcher）热重载能力。

### 1.4 超长模型名称的粗暴截断与判别度崩溃
- **简单 Ellipsis 的致命缺陷**：
  - [`ChatHeaderControls.tsx:168`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-card/ChatHeaderControls.tsx#L168) 使用 `text-overflow: ellipsis; white-space: nowrap;`。
  - 当输入框窄小（例如侧边栏展开、分屏或多窗口）时，长模型名称右侧被截断：
    - `muse-spark-1.2-contributor`  →  `muse-spark-1...`
    - `muse-spark-1.3-contributor`  →  `muse-spark-1...`
  - 核心版本差异（`1.2` vs `1.3`）以及角色变体（`contributor`）全被裁切，用户完全无法辨别当前生效的模型；
  - 同时，未截断时整段长名称强行撑大胶囊，严重挤占 Composer 文本输入区与发送按钮。

## 三、分维度技术方案设计

### 3.1 维度一：外部配置文件契约与热更新引擎（Hot-Reload Engine）

#### 3.1.1 配置文件规范与多级覆盖
支持两级外部配置文件（优先级由高到低）：
1. **工作区级配置（L2 Workspace）**：`<workspace_root>/.conex/models.json`（针对特定项目研发的私有微调/专有模型）；
2. **用户全局配置（L1 User Global）**：`~/.conex/models.json`（跨工作区共享，开发者个人的模型偏好与自定义配置）；
3. **内置安全基准（L0 Bundled）**：`catalog.json`（离线保底基线）。

**配置文件格式契约 (`models.json`)**：
```json
{
  "$schema": "https://crish.dev/schemas/models-v3.json",
  "version": 1,
  "models": [
    {
      "model": "sensenova-6.8-flash-lite",
      "vendor": "sensenova",
      "provider": "sensenova",
      "displayName": "SenseNova 6.8 Flash Lite",
      "contextWindow": 262144,
      "maxOutputTokens": 16384,
      "thinkingFormat": "thinking_budget",
      "thinkingBudgetDefault": 2048,
      "thinkingBudgetMax": 32768,
      "thinkingTiers": {
        "low": 1024,
        "medium": 4096,
        "high": 16384
      }
    },
    {
      "model": "muse-spark-1.3-contributor",
      "vendor": "muse",
      "displayName": "Muse Spark 1.3",
      "thinkingFormat": "reasoning_effort",
      "thinkingTiers": {
        "low": "low",
        "medium": "medium",
        "high": "high"
      }
    },
    {
      "model": "gemini-3.8-flash",
      "vendor": "google",
      "displayName": "Gemini 3.8 Flash",
      "contextWindow": 1048576,
      "maxOutputTokens": 65536,
      "thinkingFormat": "thinking_budget",
      "thinkingTiers": {
        "minimal": 512,
        "low": 2048,
        "medium": 8192,
        "high": 24576
      }
    }
  ]
}
```

#### 3.1.2 热重载引擎实现机制（Rust）
在 `crates/agent-provider/src/models/hot_reload.rs` 中实现：
1. **文件监听与防抖**：
   - 使用 `notify::RecommendedWatcher` 监听用户配置文件所在目录；
   - 引入 200ms 防抖定时器（Debounce），合并编辑器多次保存事件（如临时文件写入与重命名）；
2. **故障隔离与容灾铁律**：
   - **绝不 Panic，绝不损坏旧数据**：
     - 若外部 JSON 语法错误（如少括号、尾逗号错误）或字段类型不合法，记录 Warn 日志；
     - 内存中的 `Arc<RwLock<ModelCatalog>>` 保持原样不动；
     - 通过 Tauri 事件向前端发送 `catalog:config_error { path, message }`，UI 给出轻量 Toast 提示，不阻断当前会话；
3. **读写分离与并发安全**：
   - 解析、反序列化与多层合并全部在**本地局部变量中完成**（零锁开销）；
   - 只有在验证通过后，才获取 `Arc<RwLock<ModelCatalog>>` 写锁；
   - 写入新条目，`version += 1`，迅速释放锁；
4. **Tauri 联动广播**：
   - 触发 Tauri 事件 `app_handle.emit("catalog:reloaded", CatalogReloadedPayload { version, total_models })`。

### 3.2 维度二：通用思考能力契约与多协议 Wire 映射

#### 3.2.1 思考参数形态（`ThinkingFormat`）抽象
彻底消除以往“为每个模型写死逻辑”的弊病，将思考参数在传输层的物理形态抽象为标准枚举：
```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum ThinkingFormat {
    /// 字符串档位注入（如 OpenAI o3/o4、DeepSeek R1、Kimi、GLM）
    /// wire: { "reasoning_effort": "low" | "medium" | "high" }
    ReasoningEffort,

    /// 整数 Token 预算（如 Anthropic Claude 3.7、Gemini 2.5/3.8 Flash）
    /// wire: { "thinking": { "type": "enabled", "budget_tokens": 2048 } }
    ThinkingBudget,

    /// 级别字符串（如 Gemini 部分方言）
    /// wire: { "generation_config": { "thinking_level": "LOW" | "HIGH" } }
    ThinkingLevel,

    /// 纯开关布尔型（如 Qwen 系列）
    /// wire: { "enable_thinking": true | false }
    QwenEnableThinking,

    /// 自适应思考模式
    /// wire: { "thinking": { "type": "adaptive" } }
    ThinkingAdaptive,

    /// 无思考能力或由模型自主托管
    None,
}
```

#### 3.2.2 档位到 Wire 参数的动态映射规则
当用户在前端选择档位（如 `high`）时，`dialect.rs` 按条目中的 `thinking_format` 和 `thinking_tiers` 执行真接线：
1. **若为 `ReasoningEffort`**：
   - 查询 `entry.thinking_tiers["high"]`，若有自定义 wire 映射（如 `"deep"`），使用 `"deep"`；否则直接使用 `"high"`；
2. **若为 `ThinkingBudget`**：
   - 查询 `entry.thinking_tiers["high"]`，读取配置的数字（如 `16384`）；
   - 若用户配置的是字符串，尝试解析为 u32；若缺省则回退到 `thinking_budget_default`；
   - 注入 `thinking: { type: "enabled", budget_tokens: budget }`；
3. **若为 `Default`（未设置或选择默认）**：
   - **不注入任何显式思考字段**，完全交由模型服务商默认处理，保持 wire 请求干净纯正。

### 3.3 维度三：模型名称智能自适应缩写算法（SADA）

针对超长模型名称（如 `muse-spark-1.2-contributor`、`sensenova-6.8-flash-lite`、`muse-spark-1.3-contributor`），设计 **SADA（Smart Adaptive Disambiguation Algorithm）**。

#### 3.3.1 核心分词与判别提取规则
1. **四元组分词模型**：
   通过分词规则（`-`, `_`, `/`, 空格，及驼峰）将模型名切分为：
   `[Vendor/Family] - [Version] - [Size/Spec] - [Variant]`
   - `muse-spark-1.3-contributor` → Family: `muse-spark`, Version: `1.3`, Variant: `contributor`
   - `sensenova-6.8-flash-lite` → Family: `sensenova`, Version: `6.8`, Spec: `flash`, Variant: `lite`
2. **第一优先级铁律：版本号绝对保护**：
   - 含有数字和版本标号的 Token（`1.2`, `1.3`, `6.8`, `3.8`, `r1`, `v3`, `20250826`）**享有最高保留权重，绝对禁止裁切**；
3. **确定性高频缩写词典**：
   - `contributor` → `ctrb`
   - `sensenova` → `snova` / `sn`
   - `spark` → `spk`
   - `flash` → `fsh`
   - `lite` → `lt`
   - `preview` → `prev`
   - `checkpoint` → `ckpt`

#### 3.3.2 动态多阶自适应形态定义
| 原模型名 | Level 1: Full (全量) | Level 2: Compact (紧凑，省45%) | Level 3: Micro (极简，省70%) |
| :--- | :--- | :--- | :--- |
| `muse-spark-1.2-contributor` | `muse-spark-1.2-contributor` (26c) | `muse-1.2-ctrb` (13c) | `ms-1.2-c` (8c) |
| `muse-spark-1.3-contributor` | `muse-spark-1.3-contributor` (26c) | `muse-1.3-ctrb` (13c) | `ms-1.3-c` (8c) |
| `sensenova-6.8-flash-lite` | `sensenova-6.8-flash-lite` (24c) | `snova-6.8-flite` (15c) | `sn-6.8-fl` (10c) |
| `gemini-3.8-flash` | `gemini-3.8-flash` (16c) | `gemini-3.8-fsh` (14c) | `gem-3.8-f` (9c) |

> **关键断言**：在任何紧凑级别下，`muse-spark-1.2` 与 `muse-spark-1.3` 的区分度为 **100%**，绝对不会退化为无法分辨的 `muse-spark-1...`！

#### 3.3.3 CSS Container Query 零重排渲染实现
在前端渲染时，避免 JS `ResizeObserver` 导致的重排重绘，通过预渲染多级文本与原生 CSS 容器查询配合：
```html
<span class={styles.adaptiveModelName} title={fullModelName}>
  <span class={styles.full}>{fullModelName}</span>
  <span class={styles.compact}>{compactModelName}</span>
  <span class={styles.micro}>{microModelName}</span>
</span>
```
```css
.modelContainer {
  container-type: inline-size;
}
.full { display: inline; }
.compact { display: none; }
.micro { display: none; }

@container (max-width: 220px) {
  .full { display: none; }
  .compact { display: inline; }
}

@container (max-width: 140px) {
  .compact { display: none; }
  .micro { display: inline; }
}
```

### 3.4 维度四：英文思考等级与诚实 UI 状态机

#### 3.4.1 纯英文 Label 与语义规范
前端统一建立英文标准映射字典，废止“提供方默认”等口径：
```typescript
export const THINKING_LEVEL_LABELS: Readonly<Record<string, string>> = {
  default: 'Default',
  off: 'Off',
  minimal: 'Minimal',
  low: 'Low',
  medium: 'Medium',
  high: 'High',
  xhigh: 'X-High',
  max: 'Max',
};
```

#### 3.4.2 胶囊与选择器交互状态机
1. **具有思考能力的模型**：
   - 胶囊右半边渲染：`[ 🧠 Default ]` 或 `[ 🧠 High ]`；
   - 悬停 Tooltip 呈现完整说明：`Thinking Level: High (Active: Deep reasoning mode)`；
   - 点击展开纯英文下拉选项列表：`Default`、`Low`、`Medium`、`High` 等；
2. **不具备思考能力的模型（`supports_reasoning == false`）**：
   - 思考胶囊**优雅自动收起/隐藏**，输入框左侧模型胶囊独立居右，彻底腾出界面空间；
   - 杜绝给纯文本/无思考模型挂一个不知所云且无法选择的“提供方默认”。

## 四、红蓝攻防对抗矩阵（Adversarial Test Matrix）

| 编号 | 红方攻击向量 (Attack Vector) | 潜在破坏后果 | 蓝方防御与加固措施 (Defense Implementation) |
| :--- | :--- | :--- | :--- |
| **SEC-01** | **Windows 文件并发独占锁**<br>外部编辑器（如 VSCode）在保存 `models.json` 时持有写锁，watcher 瞬间读取返回空内容或 Permission Denied。 | 后端读到半截 JSON，崩溃或误把 catalog 清空。 | **加固机制**：引入重试退避（3 次，每次 50ms），读空或失败时**严格保留旧内存快照**，绝不覆写。 |
| **SEC-02** | **恶意语法注入与坏字段**<br>用户写错 JSON 逗号、或者给 budget_tokens 传了 `"invalid_string"`。 | 反序列化 Panic，主进程崩溃。 | **加固机制**：强类型 serde 校验 + 错误静默阻断；仅合规条目更新，报错通过 Tauri IPC 弱提示。 |
| **SEC-03** | **频繁修改引发的重载风暴**<br>脚本或外部工具以毫秒级频率不断 touch 配置文件。 | 锁竞争剧烈，CPU 飙升，前端重复渲染卡死。 | **加固机制**：200ms 防抖队列，同一个合并周期只触发一次原子写入和一次前端广播。 |
| **SEC-04** | **极窄屏幕布局挤压崩塌**<br>窗口缩小到 320px，模型胶囊、语音按钮和发送按钮发生重叠折行。 | 按钮不可点击，文本溢出穿透。 | **加固机制**：CSS Container Query 配合 `min-width: 0` 与 Flex 优先级，模型名平滑降级为 `ms-1.3-c`，必要时仅显示图标。 |
