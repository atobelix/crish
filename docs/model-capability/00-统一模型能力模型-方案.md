# 统一模型能力模型（Unified Model Capability）方案 · v2（单源裁决）

> **战役工作区**：docs/model-capability/
> **状态**：勘察完成 · 方案定稿（2026-09-03 主控，按用户裁决修订 v2）
> **背景**：用户指出思考强度 UI 谎报「High」、能力数据缺失导致思考功能实际不可用、多协议思考参数各自为政；要求统一模型能力建模（思考配置 / 上下文与输出长度 / 图片视频支持 / 输出类型），并以 Tauri MCP 真机验收。
> **v2 修订（用户裁决，取代 v1）**：**不允许向后兼容、不允许多轨实现、不允许硬编码**。v1 的「系列兜底表优先 + 目录覆盖双源合并」与「effectiveCapability 平行字段」废止。

---

## 一、现状勘察结论（根因，v1 保留）

### 1.1 UI 谎报档位（直接可见缺陷）
- `apps/crish-desktop/src/components/provider/ModelBadgePickerMenu.tsx:138`：档位未设置时硬编码 `return 'High'`。
- `apps/crish-desktop/src/components/chat-composer/ComposerFusedTrigger.tsx:31`：正确显示「提供方默认」。两 UI 面不一致；`THINKING_PILLS` 为硬编码数组。

### 1.2 能力数据缺失
- `crates/agent-provider/src/models/catalog.json`：151 条内置，0 条含思考档位映射、0 条能力位 = true。档位面板恒回落「提供方默认」。

### 1.3 能力描述面硬编码多轨（v2 重点废除）
- `MODEL_SERIES_CAPABILITIES` 前缀猜测表（`vendor_capability.rs`）：按模型名前缀硬编码推断思考能力——**正是用户禁止的硬编码**。
- `describe_model`（`capability.rs`）双源合并「目录档位 ∪ 系列兜底」——**多轨实现**，v2 废除为单源。
- `ModelBadgePickerMenu` 的 `THINKING_PILLS` 静态数组——硬编码。

### 1.4 能力字段缺口
- 无视频输入支持位、无输出类型字段（text/image/video/audio）、无思考参数形态字段（format/budget 在各 builder 各自推导）。

### 1.5 协议面（4 套）
OpenAI chat / Responses / Anthropic / Gemini；思考参数形态各异（reasoning_effort / thinking.budget_tokens / thinking_level / reasoning:{effort}）。Responses 轨思考未接线（`build_responses.rs` 注释「未来经 reasoning:{effort} 接线」）。

## 二、设计目标（v2 单源）

1. **能力真源唯一 = `ModelCatalogEntry` 条目**：思考档位映射、思考参数形态、窗口、输入/输出模态、输出类型、能力位全部**入条目字段**；`catalog_get` 原样下发条目，前端唯一读目录。**无第二数据源、无平行字段**。
2. **零向后兼容双轨**：catalog 字段一次性落定为新契约；旧字段（reasoningEffortTiers/thinkingLevelMap 双载体）合并为单一 `thinkingTiers`。不保留旧路径。
3. **零硬编码猜测**：删除 `MODEL_SERIES_CAPABILITIES` 前缀表与 `THINKING_PILLS`；未收录模型 = 条目缺省（保守默认，不猜测）。
4. **UI 诚实呈现**：档位未设置 → 「提供方默认」；档位选项 = 目录单源；能力徽章 = 目录单源。
5. **各协议全部真接线**：chat / anthropic / gemini / responses 四 builder 均按条目思考参数形态映射。

## 三、统一能力契约（catalog 条目字段，单源）

`ModelCatalogEntry` 能力面字段（新增/合并，全部 `#[serde(default)]` 可缺省）：

```
// ── 思考（合并旧 reasoning_effort_tiers / thinking_level_map 双载体为单载体）──
thinking_tiers: Option<TierEffortMap>     // 档位→wire 拼写；None=隐藏/不支持档
thinking_format: Option<String>           // "reasoning_effort" | "thinking_budget" | "thinking_adaptive" | "thinking_level" | "qwen_enable_thinking" | "zai_thinking" | "openrouter_reasoning" | "none"
thinking_budget_default: Option<u32>      // 档位映射到的预算 token（anthropic/gemini 系）
thinking_budget_max: Option<u32>          // 预算上界（可选）
supports_reasoning: bool                  // 粗粒度门（= thinking_tiers 非空）

// ── 窗口（既有保留）──
context_window: Option<u64>
max_output_tokens: Option<u64>

// ── 输入/输出模态（新增，唯一真源；旧 supports_* 位由模态派生）──
input_modalities: Option<Vec<String>>     // text | image | video | audio | pdf
output_modalities: Option<Vec<String>>    // text | image | video | audio

// ── 能力位（派生自模态，保留为便捷位）──
supports_vision: bool        // = input 含 image
supports_video_input: bool   // = input 含 video（新增）
supports_audio_input: bool   // = input 含 audio
supports_audio_output: bool  // = output 含 audio
supports_pdf_input: bool     // = input 含 pdf
```

- **wire 协议**：沿用既有 `mode`（chat/responses/anthropic/gemini/both）+ `supports_responses` 单一真源（`resolve_wire_protocol` 不属能力猜测，保留）。
- **未收录模型**：条目缺省 → supports_reasoning=false、模态空（保守默认），前端不渲染思考档位与能力徽章。
- **`describe_model` 收敛**：改为纯投影——仅从条目字段组装 `ModelCapability`，**不做系列兜底**。

## 四、落地步骤

1. **Rust · catalog 条目字段**：`models/catalog.rs` 新增 `thinking_tiers`/`thinking_format`/`thinking_budget_*`/`input_modalities`/`output_modalities`；旧 `reasoning_effort_tiers`/`thinking_level_map` 删除（单载体）；`supports_video_input` 新增；`supports_vision` 等位保留并文档标注「派生自模态」。
2. **Rust · 能力投影**：`request/capability.rs` `describe_model` 改为单源投影（仅条目字段，删系列兜底）；`vendor_capability.rs` 的 `MODEL_SERIES_CAPABILITIES`/`infer_thinking_capability` 退役（或仅保留内部映射函数、不再作能力猜测）。
3. **Rust · 协议 builder**：chat/anthropic/gemini/responses 四 builder 统一从 `thinking_format` + `thinking_tiers` 映射；`build_responses.rs` 补 `reasoning:{effort}` 接线。
4. **Rust · catalog 数据补齐**：内置 `catalog.json` 151 条按真实已知能力补 `thinking_tiers`/`thinking_format`/模态/输出类型；未知条目留缺省。
5. **前端**：
   - `thinkingGear.ts`：档位数据源切到条目 `thinkingTiers`（单源）；删 `reasoningEffortTiers`/`thinkingLevelMap` 双载体读取。
   - `ModelBadgePickerMenu.tsx`：删 `THINKING_PILLS` 硬编码与 `'High'` 谎报 → default 显示「提供方默认」，选项走 thinkingGear 单源。
   - 模型选择器能力徽章（上下文/输出/模态/输出类型）读目录单源。
6. **Tauri MCP 真机验收**：思考档位面板选项、default 显示、能力徽章、发送时 wire 参数四协议核对。

## 五、验收断言

- 未设置档位时两 UI 面均显示「提供方默认」（0 处硬编码 'High'）；
- 思考档位面板选项 = 目录 `thinkingTiers`（单源），非仅「提供方默认」；
- 档位显式选择后发送，wire 请求含对应思考参数（chat/anthropic/gemini/responses 四形态正确）；
- 前端可读 video 输入位与输出类型；未收录模型不渲染思考档位与能力徽章（保守默认）；
- 全仓 0 处 `MODEL_SERIES_CAPABILITIES` 硬编码猜测、0 处 `THINKING_PILLS`、0 处 `reasoningEffortTiers`/`thinkingLevelMap` 双载体残留。

---

## 六、范围声明

- 仅统一「思考 / 窗口 / 模态 / 输出类型」四类；temperature 等其他采样参数维持现状（非本战役）。
- `resolve_wire_protocol`（mode + supports_responses）是既有单一真源，不属能力猜测，保留。
- catalog 数据补齐以真实已知能力为准；不编造未知模型能力。
