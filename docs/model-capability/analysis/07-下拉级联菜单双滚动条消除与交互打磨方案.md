## 一、 问题背景与缺陷全景

在 Conex / Crish 桌面端设置页面的「设置 -> 模型」模块中，用户点击「全局默认模型」下拉框（由 `ModelsCascadeSelect` 承载）时，触发弹窗呈现出以下四项恶性缺陷（现场还原见用户截图）：

```
┌────────────────────────────────────────────────────────────────────────┐
│ 现场缺陷解剖图                                                         │
│                                                                        │
│   [全局默认模型] ─── 点击展开                                         │
│   ┌───────────────────────────────────────────────┐                    │
│   │ MenuContent 顶层 Popover 面板 (外壳)          │                    │
│   │ ┌───────────────────────────────────────────┐ │ ║ 滚动条 1 (外层)  │
│   │ │ CascadeList 冗余面板 (套娃内壳)           │ │ ║                 │
│   │ │ 选择服务商与模型                          │ │ ║ 相距仅 6px!      │
│   │ │ ----------------------------------------- │ │ ║                 │
│   │ │ Anthropic                           > ────┼─┼─╫─┐ 滚动条 2 (内层)│
│   │ │ OpenAI                              >     │ │ ║ │               │

│                                                       └───────────────┘
└────────────────────────────────────────────────────────────────────────┘
```

1. **恶性双层紧挨滚动条（Parallel Dual Scrollbars）**：
   弹窗右侧出现了两条物理距离仅隔 6px、几乎完全并列的垂直滚动条，视觉极其拥挤粗糙，且滚轮滚动时产生父子容器抢占滚动的震荡感。
2. **二级菜单被外框物理截断（Inline Flyout Clipped by Overflow）**：
   鼠标悬停在服务商行（如 Anthropic）展开二级模型列表（`.cascadeFlyout`）时，子菜单项被主弹窗的右/左外框直接生硬切断，文字被裁切或整个子面板不可见。
3. **套娃双层卡片面板（Double Card Shell Redundancy）**：
   外层 `Menu.module.css` 已经声明了 14px 圆角、1px 细边框、6px 内边距、背景模糊与投射阴影；内层 `.cascadeList` 又重新声明了一整套 14px 圆角、边框、6px 内边距和独立背景与阴影，形成严重的“卡片套卡片”视觉脏污。
4. **安全三角区（Safe Triangle）方位倒置与划过闪退**：
   鼠标斜向划向二级菜单时，二级菜单瞬间闪退闭合；经查代码，行内图标为 `<Lucide.ChevronRight />`（向右），CSS 却是 `right: calc(100% + 4px)`（向左弹出），而传入安全三角状态机的参数却硬编码为 `'right'`，造成几何向量叉积判定全向相反，防闪退机制完全失灵。

#### 双滚动条生成的物理机制剖析
1. **历史架构漂移导致的“套娃面板”**：
   在早期的重构中，`ModelsCascadeSelect` 曾使用原生的 `ReactDOM.createPortal(<div className="cascadeList">, document.body)`。当时 `.cascadeList` 作为最顶层的弹出面板，因此被赋予了背景、阴影、圆角、边框与内边距。
   随后在 UI 原子化收敛时，外层直接套上了 `<Menu>` 组件。但 `<Menu>` 本身就是一个完整的 `Popover.Content`（类名为 `.menuContent`）。这导致 `.cascadeList` 变成了子面板。
2. **两处潜在的滚动触发源**：
   - **机制 1（内外层重复 max-height）**：若内层 `.cascadeList` 或其包裹项被显式或隐式限制了 `max-height` 并设置 `overflow-y: auto`，内层在自身右侧生成滚动条；而外层 `.menuContent` 因其子节点高度达到自身 `max-height`，也在外层右侧生成滚动条。因为外层有 `padding: 6px`，两条滚动条便相隔 6px 并列贴靠。
   - **机制 2（绝对定位子元素撑开父级溢出区 Scrollable Overflow Area）**：
     根据 **W3C CSS Overflow Module Level 3 §2.1** 规范：
     > *“The scrollable overflow area of a box includes the scrollable overflow area of all non-positioned or positioned descendants whose containing block is the box or a descendant of the box.”*

     `.cascadeFlyout` 作为 `.cascadeRow`（`position: relative`）的子节点，属于绝对定位元素。当 `.cascadeFlyout` 包含数十个模型、高度达到 `280px` 时，它向下延伸的几何包围盒直接计入了祖先滚动容器 `.menuContent` 的滚动溢出区！
     这导致即使主服务商列表只有 3~4 项，只要二级菜单展开，外层 `.menuContent` 立即被强行撑出纵向滚动条；同时 `.cascadeFlyout` 自身也具有 `overflow-y: auto;`（带有自身的滚动条），在视觉上直接构成了并列恶性双滚动条！

### 2.2 根因 B：包含块物理截断（W3C 盒模型与 X 轴裁剪）

#### 代码病灶
```css
/* apps/crish-desktop/src/components/settings-models/ModelsSettingsTab.module.css:1101-1110 */
.cascadeFlyout {
  position: absolute;
  right: calc(100% + 4px);   /* 试图向父级行的左侧水平展开 180px */
  top: 0;
  min-width: 180px;
  max-height: 280px;
  overflow-y: auto;
  ...
}
```

```html
<!-- DOM 渲染层级 -->
<div class="menuContent" style="overflow-x: hidden; overflow-y: auto;">  <!-- 裁剪根源 -->
  <div class="cascadeList">
    <div class="cascadeRow" style="position: relative;">
      <span>OpenAI</span>
      <ChevronRight />
      <!-- 内联绝对定位子节点 -->
      <div class="cascadeFlyout" style="position: absolute; right: calc(100% + 4px); top: 0;">
        <button class="cascadeOption">gpt-4o</button>
      </div>
    </div>
  </div>
</div>
```

#### 渲染管线裁剪原理
1. 根据 **CSS 2.1 Visual Formatting Model (§11.1.1 Overflow)**：
   一旦容器设置了 `overflow-x: hidden`，任何超出容器 Padding Box 的内容必须在渲染树 Paint 阶段执行裁剪截断。
2. 即使开发者将 `overflow-x` 设为 `visible`，根据 CSS 规范：**只要 `overflow-y` 为 `auto` 或 `scroll`，`overflow-x` 就绝不可能单独保持 `visible`，浏览器会自动强制解析为 `auto` 或 `hidden`**。
3. 因此，直接内联在 `.cascadeRow` 内部的 `.cascadeFlyout` 向左延伸的 180px，位于 `.menuContent` 左边界之外，被浏览器渲染引擎 100% 切除，形成用户截图中的“菜单项被外框截断”。

### 2.3 根因 C：安全三角区（Safe Triangle）方位倒置与交互闪退

#### 代码病灶
查看 `ModelProfileList.tsx` 第 96-104 行：

```tsx
// apps/crish-desktop/src/components/settings-models/ModelProfileList.tsx:96-104
onMouseLeave={(e) => {
  if (isFly && flyoutRef.current) {
    const rect = flyoutRef.current.getBoundingClientRect();
    safeTrackerRef.current.enter(
      { x: e.clientX, y: e.clientY },
      rect,
      'right' // 致命错误：在此处硬编码了 'right'！
    );
  }
}}
```

#### 几何向量计算失效分析
查看 `SafeTriangle.ts` 中根据 placement 构建三角形的逻辑：

```typescript
// apps/crish-desktop/src/components/ui/internal/SafeTriangle.ts:86-92
if (placement === 'right') {
  return [
    cursor,
    { x: submenuBounds.left, y: submenuBounds.top },
    { x: submenuBounds.left, y: submenuBounds.bottom },
  ];
}
```

1. 当 `placement === 'right'` 时，算法假定子菜单在光标**右侧**，因此用子菜单包围盒的**左边缘**（`submenuBounds.left`）与光标构成三角形；
2. 但实际上，CSS 写的是 `right: calc(100% + 4px)`，子菜单物理位于光标的**左侧**（$X_{\text{submenu}} < X_{\text{cursor}}$）；
3. 此时生成的三角形在几何上是面向右方的无效区域（甚至是反向退化的扁平几何）；
4. 当用户鼠标向左侧的子菜单移动时，`isPointInTriangle` 判定点在三角形外部，Grace Timer 无法锁定，瞬间将 `isSuspended` 重置为 `false`；
5. 鼠标经过行与子菜单之间的 4px 间隙时，触发了 `onMouseLeave`，React 立即卸载 `.cascadeFlyout`，导致菜单剧烈闪退！

### 2.4 根因 D：硬编码向左展开与视口左侧溢出

1. `.cascadeRow` 中的图标是 `<Lucide.ChevronRight />`（向右指引），但弹出方向却是向左，违背交互认知统一性；
2. 弹窗位于页面不同位置或窗口缩小至 800px 时，若选择框靠近视口左侧边缘（例如 $X < 190\text{px}$），向左弹出 180px 会导致子菜单出现负坐标（$X < 0$），直接飞出屏幕可视范围，用户完全看不见内容。

## 三、 架构重构与体验打磨方案

彻底解决上述问题的核心不是“缝缝补补调 margin”，而是建立**单一真理源（SSOT）**的容器架构：
1. **外壳收敛**：剥离 `.cascadeList` 的全部多余外壳样式，统一归由 `<Menu>` 基座控制；
2. **浮层解耦（Portal 化）**：二级子菜单脱离父级 `overflow` 包含块，通过 `ReactDOM.createPortal` 独立挂载至顶层；
3. **响应式刚性几何钳位**：复用基座纯函数 `calculateSubmenuPosition`，实现左右自适应翻转与防越界钳位；
4. **安全三角动态同构**：展开方向、指示图标与安全三角向量计算动态同构（Direction Isomorphism）；
5. **滚动与焦点防护**：主列表滚动时自动收起子菜单，彻底消除无序悬空与抢焦。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 重构后架构拓扑图                                                            │
│                                                                             │
│ [ DialogOverlayContext / document.body ] (顶层 Portal 容器)                  │
│   │                                                                         │
│   ├── 主菜单层 (Menu / Popover.Content) ───────────────────────────────────┐│
│   │     ├── 单一真理源外壳 (.cascadeMenuContent): 唯一背景、圆角、阴影      ││
│   │     ├── 唯一 Y 轴滚动条: overflow-y: auto; overflow-x: hidden           ││
│   │     └── .cascadeList: 纯 Flex 布局，零边框、零阴影、零额外 Padding       ││
│   │           ├── 服务商行 1 (ChevronLeft/Right 动态跟随方向)               ││
│   │           └── 服务商行 2 (作为 Anchor 挂载源，不内联子菜单 DOM)        ││
│   │                                                                        ││
│   └── 二级子菜单浮层 (createPortal 独立挂载) ◄─────────────────────────────┘│
│         ├── 彻底逃逸外层 overflow 截断，无物理裁切                          │

└─────────────────────────────────────────────────────────────────────────────┘
```

```tsx
  const activeLabel =
    activeProfile && activeModelId
      ? `${profileDisplayLabel(activeProfile).replace(/\s*\/\s*默认$/, '')} · ${formatModelDisplayName(
          activeProfile.id,
          activeModelId
        )}`
      : '请选择默认模型...';

  // 展开二级子菜单并计算几何位置
  const openSubmenu = useCallback((profileId: string) => {
    const rowEl = rowRefs.current.get(profileId);
    if (!rowEl) return;
    const rect = rowEl.getBoundingClientRect();
    // 采用基座刚性双向数学钳位算法（默认优先向右展开，若空间不足自动 Flip 至左侧）
    const placement = calculateSubmenuPosition(rect, 200, 280, 4, 8, 'right');
    setFlyoutPlacement(placement);
    setFlyProfileId(profileId);
  }, []);

  const closeSubmenu = useCallback(() => {
    safeTrackerRef.current.reset();
    setFlyProfileId(null);
    setFlyoutPlacement(null);
  }, []);

  const currentFlyProfile = useMemo(() => {
    return enabledProfiles.find((p) => p.id === flyProfileId) ?? null;
  }, [enabledProfiles, flyProfileId]);

  // 注册二级菜单至全局 LayerStack，避免点击时父级 Popover 误判为 outside click
  useLayerRegistration(
    {
      id: submenuLayerId,
      type: 'cascade-submenu',
      dismissible: true,
      onDismiss: closeSubmenu,
      elementRef: flyoutRef,
    },
    Boolean(flyProfileId && flyoutPlacement)
  );

  return (
    <Menu
      openState={{
        open,
        onOpenChange: (nextOpen) => {
          setOpen(nextOpen);
          if (!nextOpen) closeSubmenu();
        },
      }}
      position={{ align: 'start', side: 'bottom', sideOffset: 4 }}
      panel={{ contentClassName: styles.cascadeMenuContent }}
      trigger={
        <button
          type="button"
          className={styles.cascadeSelectTrigger}
          style={{ minWidth: '220px', justifyContent: 'space-between' }}
        >
          <span className={styles.cascadeSelectValue}>{activeLabel}</span>
          <Lucide.ChevronDown
            size={14}
            style={{ opacity: 0.6, flexShrink: 0 }}
          />
        </button>
      }
    >
      <div
        className={styles.cascadeList}
        onMouseLeave={() => {
          // 仅当没有激活的安全三角区保护时才关闭
          if (!safeTrackerRef.current.isGraceActive()) {
            closeSubmenu();
          }
        }}
      >
        <div className={styles.addMenuTitle}>选择服务商与模型</div>
        {enabledProfiles.length === 0 ? (
          <div className={styles.cascadeEmpty}>暂无已启用的可用模型</div>
        ) : (
          enabledProfiles.map((p) => {
            const isFly = flyProfileId === p.id;
            const isCurrentActive = p.id === activeProfileId;
            const cleanLabel = profileDisplayLabel(p).replace(
              /\s*\/\s*默认$/,
              ''
            );

            // 根据动态定位结果决定箭头朝向（Left 或 Right）
            const isFlippedLeft = isFly && flyoutPlacement?.side === 'left';

            return (
              <div
                key={p.id}
                ref={(el) => {
                  if (el) rowRefs.current.set(p.id, el);
                  else rowRefs.current.delete(p.id);
                }}
                className={`${styles.cascadeRow} ${isFly ? styles.isOpen : ''}`}
                onMouseEnter={(e) => {
                  if (flyProfileId && flyProfileId !== p.id) {
                    // 若鼠标正划在通往上一个二级菜单的安全三角区内，拦截切换
                    if (safeTrackerRef.current.isGraceActive()) {
                      const isSafe = safeTrackerRef.current.check({
                        x: e.clientX,
                        y: e.clientY,
                      });
                      if (isSafe) return;
                    }
                  }
                  openSubmenu(p.id);
                }}
                onMouseLeave={(e) => {
                  if (isFly && flyoutRef.current && flyoutPlacement) {
                    const rect = flyoutRef.current.getBoundingClientRect();
                    // 传入真实的物理展开方向 ('left' | 'right')，构建正确的向量三角区
                    safeTrackerRef.current.enter(
                      { x: e.clientX, y: e.clientY },
                      rect,
                      flyoutPlacement.side
                    );
                  }
                }}
              >
                <span
                  style={{
                    fontWeight: isCurrentActive ? '500' : 'normal',
                    flex: 1,
                  }}
                >
                  {cleanLabel}
                </span>

                {isFlippedLeft ? (
                  <Lucide.ChevronLeft size={14} className={styles.cascadeChev} />
                ) : (
                  <Lucide.ChevronRight size={14} className={styles.cascadeChev} />
                )}
              </div>
            );
          })
        )}
      </div>

      {/* 二级模型列表：通过 Portal 独立挂载至根节点，彻底消除父级 overflow 截断与双滚动条 */}
      {currentFlyProfile && flyoutPlacement &&
        createPortal(
          <div
            ref={flyoutRef}
            className={styles.cascadeFlyoutPortal}
            style={{
              left: `${flyoutPlacement.x}px`,
              top: `${flyoutPlacement.y}px`,
              transformOrigin: flyoutPlacement.transformOrigin,
            }}
            onMouseEnter={() => safeTrackerRef.current.reach()}
            onMouseLeave={() => closeSubmenu()}
          >
            {currentFlyProfile.models.map((m) => {
              const selected =
                currentFlyProfile.id === activeProfileId && m === activeModelId;
              return (
                <button
                  key={m}
                  type="button"
                  className={`${styles.cascadeOption} ${selected ? styles.isOn : ''}`}
                  onClick={() => {
                    onChange(currentFlyProfile.id, m);
                    closeSubmenu();
                    setOpen(false);
                  }}
                >
                  <span className={styles.cascadeOptionText}>
                    {formatModelDisplayName(currentFlyProfile.id, m)}
                  </span>
                  {selected && (
                    <Lucide.Check
                      size={14}
                      className={styles.cascadeCheck}
                    />
                  )}
                </button>
              );
            })}
          </div>,
          dialogOverlay ?? document.body
        )}
    </Menu>
  );
};
```

## 五、 交互细节打磨与防异常设计

### 5.1 响应式防溢出定位策略（Dynamic Anti-Overflow Clamping）

1. **水平刚性双向钳位**：
   - 算法优先探测触发器右侧空间是否满足 $W_{\text{submenu}} + \text{offset} = 204\text{px}$；
   - 若右侧空间充足，采用右展开（`side = 'right'`）；
   - 若弹窗位于屏幕右侧边界，右侧空间不足且左侧空间更大时，自动翻转为左展开（`side = 'left'`）；
   - 最终坐标经过双向数学钳位公式约束：
     $$\text{clampedX} = \min(\max(\min X, \text{targetX}), \max(\min X, \max X - W))$$
     **数学上绝对保证 $X \ge \min X$ 且 $X + W \le \max X$，杜绝任何负坐标与屏幕右侧溢出**。

2. **垂直自适应对齐与贴边向上钳位**：
   - 初始对齐行首顶部：$\text{targetY} = \text{rowRect.top} - 4$；
   - 当靠近视口底部时，钳位公式自动限制 $\text{clampedY} \le \text{viewportHeight} - \text{submenuHeight} - \text{edgePadding}$，使子菜单贴底向上延伸，绝不沉入任务栏下方。

3. **指示图标动态同构**：
   - 当算法决策展开至右侧时，行尾渲染 `<Lucide.ChevronRight />`；
   - 当算法决策翻转至左侧时，行尾动态渲染 `<Lucide.ChevronLeft />`；
   - 彻底避免“右箭头却向左弹出”的逻辑背离。

---

### 5.2 安全三角（Safe Triangle）交互丝滑化

```
         (cursor离开行)
           P (clientX, clientY)
           |\
           | \
           |  \   Safe Triangle (叉积同号区间)
           |   \
           |    \ 300ms Grace Period
           |     \
           |      + Vtop (submenu.left, top)
           |      |
           |      | [Flyout 子菜单]
           |      |
           +──────+ Vbottom (submenu.left, bottom)
```

1. **正确绑定真实展开侧**：
   `safeTrackerRef.current.enter(cursor, rect, flyoutPlacement.side)` 严格消费动态定位计算出的 `side`。
   - `side === 'right'`：顶点取子菜单左上角与左下角；
   - `side === 'left'`：顶点取子菜单右上角与右下角；
   彻底根治由于方向写反导致的向量叉积正负号反向问题。
2. **防误触阻尼与即时意图响应**：
   - 用户斜向滑向子菜单时：光标位于三角区内，相邻行的 `onMouseEnter` 被优雅挂起 300ms，子菜单保持常驻；
   - 用户垂直快速移动选择其他服务商时：光标离开三角区，`check()` 立即返回 `false` 并重置计时器，立刻响应新行的展开，零迟滞感。
3. **主菜单滚动联动收起**：
   在基座 `<Menu>` 滚动或视口变化时，触发 `closeSubmenu()`，避免主菜单列表滚动后子菜单悬浮在空中的“浮层脱靶”现象。

---

### 5.3 键盘无障碍（A11y）与焦点安全

1. **严禁声明式 `autoFocus` 抢夺**：
   二级子菜单中的选项按钮严禁设置 `autoFocus`。
   原生 `autoFocus` 会触发浏览器的 `scrollIntoView`，在打开菜单瞬间造成视口滚动震荡，并导致光标丢失。
2. **受控键鼠分离模式**：
   - 纯鼠标操作：仅通过 `hover` 与 `SafeTriangleTracker` 驱动，不调用 `.focus()`，避免焦点虚线框与背景色跳动；
   - 键盘漫游支持：支持在当前行按 `ArrowRight`（或展开侧对应方向键）进入二级子菜单并高亮首项，按 `ArrowLeft` 或 `Escape` 返回主菜单。
