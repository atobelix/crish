> **文件标识**：`docs/model-capability/analysis/04-服务商界面整体视觉重构与样式规范方案.md`  
> **状态**：方案已锁定（视觉重构与样式规范权威方案）  
> **适用范围**：AI 服务商与模型设置模块（`ModelsSettingsTab`）、服务商列表导轨（`ModelProfileList`）、模型配置工作台（`ModelConfigEditor` / `ModelList` / `ModelConfigPanel` / `ManualAddForm`）、样式表（`ModelsSettingsTab.module.css`）  
> **核心原则**：纯逻辑规划、反退避（`.agents/LOGIC_PLAN_NO_RETREAT.md`）、严禁打补丁（AGENTS.md §7）、聚焦克制规范（AGENTS.md §13）、系统 Design Tokens 全量对齐、架构净收敛与死代码彻底清退

## 一、背景与用户诉求审视

### 1.1 现场用户批评与痛点溯源
在最近的用户可用性与视觉走查中，用户对模型配置界面的视觉质量提出了直截了当的严厉批评：
> **“ai服务商界面有点偏离我们的设置界面整体的主题样式了，看着挺丑的。灰度也是乱用，看着很难受。排版也是不行。你重新检查一下吧。”**

这一批评准确击中了当前 AI 服务商界面的致命弱点：
1. **风格脱节，形同“外挂页面”**：Conex 桌面端设置中心（通用、外观、规则、快捷键、扩展服务）经过多轮沉淀，已经形成了以“纯正白卡底（Paper Base）、极细柔和细线（Hairline Border）、克制聚焦环（Restrained Focus Ring）、轻量无边际呼吸感”为核心的设计语言。而现有的模型管理界面（`ModelsSettingsTab`）却自立门户，像一个生硬移植进来的粗糙 IDE 分割工具窗口，与外层典雅克制的主题格格不入。
2. **灰度滥用，层次反转（Gray Layering Chaos）**：在浅色模式下，界面内充斥着深浅不一的无序灰块——大面积深灰侧导轨（`--bg-secondary`，7.9% 灰度）、泥坑般的灰底输入框（`--bg-primary`，5.5% 灰度）、死板突兀的实心灰色标签胶囊（`--tint-active`）。导致视觉焦点混乱，界面显得肮脏、沉重且廉价。
3. **排版失衡，节奏割裂（Broken Visual Rhythm）**：外层强制写死 `border-radius: 0` 和魔术数字高度；左侧选中项与系统一级侧边栏导航质感脱节；右侧工作区各子卡片之间缺乏有机呼吸感，内联样式凌乱散落；模型行被做成一块块独立的灰积木，导致大量无效视觉噪点。
4. **代码腐化，死代码严重超标**：`ModelsSettingsTab.module.css` 累计膨胀至 **1165 行**，其中近 60%（约 700 行）是历史迭代遗留但实际已脱钩的死代码（如 `modelsBilling*` 计费体系、`modelsPrice*` 价格表、旧版 `modelsModelRow*` / `modelsCtxBtn` 渲染体系等），不仅造成样式表极其臃肿，更让样式覆盖混乱失控。

### 1.2 重构目标与验收标尺
- **目标一：100% 纯正卡底化**。彻底根除深浅灰块在工作区的粗暴铺陈，将整个两栏工作区封装为系统标准的一级卡片容器（`SettingsCard` 契约，`var(--bg-card)` 纯白纸面，`12px` 圆角，`var(--border-color)` 纤细边框）。
- **目标二：彻底净化灰度，回归 Design Tokens 单一真理源（SSOT）**。废除所有硬编码灰色、废除灰底输入框、废除死实心灰胶囊。全面对齐 `tokens.css` 中的 `--bg-card`、`--border-subtle`、`--tint-hover`、`--tint-active` 以及语义化徽标。
- **目标三：双栏经典排版同构**。左侧服务商导轨与系统一级导航（`SettingsSidebar`）保持视觉同构（选中态为纯白浮起微卡片 + 微阴影）；右侧详情工作台采用流式细线列表排版（对齐快捷键、扩展服务页面），提供清晰优雅的视觉重心。
- **目标四：死代码彻底脱水收敛**。彻底清退历史无用类，将 1165 行臃肿样式净化至 **320~350 行** 高内聚、符合现代 CSS 规范的高性能样式表。

### 2.1 毒点一：五层灰度套娃与底色无序横跳（Layering Hell）
在 Conex 设置中心架构中，`SettingsPanel.module.css:198` 明确界定：
```css
.coverContent {
  background: var(--bg-elevated, var(--bg-card, hsl(0 0% 100%)));
}
```
即进入右侧内容区后，用户处于纯白纸面卡底基准上。然而 `ModelsSettingsTab.module.css` 却自作主张构造了五层反向层叠：
1. **第 1 层（外壳）**：`.modelsSplit` 使用 `border-radius: 0; background: transparent;`，毫无卡片一体感。
2. **第 2 层（左轨与右台）**：左侧 `.modelsRail`（line 21）强制赋予 `background: var(--bg-secondary);`（Light 下为 7.9% 灰度）；右侧 `.modelsDetail`（line 181）强制赋予 `background: var(--bg-primary);`（Light 下为 5.5% 灰度）。在白底纸面上挖出两块巨大且互不协调的灰底！
3. **第 3 层（模型行）**：右侧内的 `.mrdModelRow`（line 385）再次赋予 `background: var(--bg-primary);`。
4. **第 4 层（展开面板）**：展开模型配置 `.modelConfigPanel`（line 848）竟然反转使用了 `background: var(--bg-secondary);`。
5. **第 5 层（输入控件）**：面板内的表单输入框 `.mrdFieldInput`（line 296）又跳回 `background: var(--bg-primary);`。

**视觉后果**：浅色模式下，界面呈现出“白底 -> 灰工作台 -> 灰列表项 -> 深灰展开面板 -> 浅灰输入框”的反复横跳，层级逻辑彻底崩溃，给用户极其强烈的压抑与脏乱感。

---

### 2.2 毒点二：泥坑式灰输入框（Murky Gray Inputs vs System Crisp Inputs）
系统标杆输入框（参考 `Input.module.css` 与 `SettingsPanel.module.css` 的 `.search`）的统一契约是：
- 背景：`background: var(--bg-card);`（纯正无暇的纸白）
- 边框：`border: 1px solid var(--border-subtle);`（极其克制的中性灰浅线）
- 聚焦：边框温和变深（混入不超过 10% 文本色），背景保持透亮，绝不允许重阴影与粗黑框。

而在 `ModelsSettingsTab.module.css:288-317`：
```css
.mrdFieldInput {
  background: var(--bg-primary); /* 灰底泥坑 */
  border: 1px solid var(--border-subtle);
  border-radius: var(--radius-md);
}
.mrdFieldInput:focus {
  background: var(--bg-primary); /* 聚焦依然是灰底！ */
  box-shadow: none;
}
.mrdSearch {
  background: var(--bg-primary); /* 搜索框也是灰底泥坑 */
  border: 1px solid var(--border-color);
}
```
**视觉后果**：输入框在卡片上不仅没有提供清爽明朗的书写指引，反而凹陷成一块块污浊的浅灰凹槽，文字阅读对比度受损，完全背离了 Conex 优雅现代的桌面视觉规范。

---

### 2.3 毒点三：实心灰块胶囊与状态标签粗糙化（Solid Gray Capsules vs Translucent Pills）
在 `McpSettingsTab.module.css:28-61` 等标准页面中，状态药丸统一采用扁平透亮体系：
```css
.mcpStatusPill {
  background: transparent;
  border: 1px solid var(--border-color);
  color: var(--text-tertiary);
  border-radius: 999px;
}
```
而 `ModelsSettingsTab.module.css` 中大量使用了 `background: var(--tint-active);` 实心死灰：
```css
.mrdCtxPill {
  font-size: var(--font-size-xxs);
  padding: 1px 5px;
  border-radius: var(--radius-xs);
  background: var(--tint-active); /* 实心灰色死块 */
  color: var(--text-tertiary);
  font-family: var(--font-mono);
}
.mrlItemTag {
  background: var(--tint-active); /* 实心灰色死块 */
  color: var(--text-tertiary);
}
.mrdPillOff {
  background: var(--tint-active); /* 实心灰色死块 */
  color: var(--text-tertiary);
}
```
**视觉后果**：`var(--tint-active)` 本是用于按钮点击态的临时着色，被拿来作为常驻标签背景后，在视口中堆积出大量毫无信息层级的暗色块，视觉噪点密集。

### 2.4 毒点四：左侧导轨激活态与系统一级导航违和（Left Rail Active State Clash）
对比全局侧边栏导航（`SettingsPanel.module.css:232-238`）：
```css
.sidebarTab.active {
  background: var(--bg-card, hsl(0 0% 100%));
  border: 1px solid var(--border-subtle);
  box-shadow: var(--shadow-sm);
  color: var(--text-primary);
  font-weight: var(--font-weight-medium, 500);
}
```
系统一级导航的激活项是一个极其优雅的**纯白浮起微卡片**，带 1px 浅细边框与柔和微阴影。  
而在 `ModelsSettingsTab.module.css:95-103` 中：
```css
.mrlItem.isActive {
  background: var(--bg-active, var(--tint-active)); /* 深灰平铺长条 */
  border-color: var(--border-color);
}
```
左侧服务商列表的选中态是一个灰蒙蒙的深灰条，悬停没有任何高光反馈。用户在左侧主导航看到的是白卡浮起，进入模型页后看到的却是灰条凹陷，破坏了同一应用内的心智统一性。

---

### 2.5 毒点五：模型列表行碎裂化与呼吸感缺失（Fragmented Block Rows vs Fluid Border List）
在 `ModelList.tsx` 与 `ModelsSettingsTab.module.css:377-399` 中：
```css
.mrdModelRow {
  padding: 8px 12px;
  border-radius: var(--radius-lg);
  border: 1px solid var(--border-subtle);
  background: var(--bg-primary); /* 独立灰色积木 */
}
```
每个模型都被封装为一个带有背景和圆角的独立灰框，当一个服务商拥有 20 个模型时，视口中直接并排堆叠了 20 个紧挨着的灰方块。  
**视觉后果**：极度拥挤破碎。标准设置界面（快捷键、规则列表、扩展列表）均采用“**卡片外框 + 内部行间 Hairline 分隔**”的优雅流式排版，模型列表却使用了最原始的积木块堆砌。

---

### 2.6 毒点六：1165 行样式的“死代码坟场”（Dead Code & Legacy Waste）
对 `ModelsSettingsTab.module.css` 进行全量跨文件引用交叉比对（通过 AST 与 ripgrep 精确检索），发现超过一半的选择器根本没有任何 TSX 组件消费：
1. **计费系统全量死代码（line 631-807，共 177 行）**：`.modelsBilling`、`.modelsBillingToggle`、`.modelsBillingToggleMain`、`.modelsBillingTitle`、`.modelsBillingSub`、`.modelsBillingToggleSide`、`.modelsBillingChevron`、`.modelsBillingBody`、`.modelsBillingHint`、`.modelsBillingEmpty`、`.modelsPriceRow`、`.modelsPriceField`、`.modelsPriceList`、`.modelsPriceItem` 等，业务早已移出或重构，样式全部裸死在文件中。
2. **已废弃旧版模型行体系（line 456-620，共 165 行）**：`.modelsModelsHead`、`.modelsModelList`、`.modelsModelRow`、`.modelsModelMain`、`.modelsModelLive`、`.modelsModelCtx`、`.modelsCtxBtn`、`.modelsCtxInput`、`.modelsIconBtn` 等，早已被 `ModelList.tsx` 的 `.mrd*` 体系替换，残留 165 行僵尸代码。
3. **已废弃卡片与头部旧类（line 200-260，共 61 行）**：`.mrdPill`、`.mrdPillOn`、`.mrdPillOff`、`.mrdToggleBtn`、`.mrdCard`、`.mrdCardTitle` 等，均已无消费点。
4. **重复或无用按钮与边距补丁（约 150 行）**。

**结论**：1165 行样式中有 **超过 550 行** 属于必须立刻铲除的死代码垃圾，这是导致界面维护困难、样式污染蔓延的技术根因。

## 三、系统设置界面设计规范基准（SSOT Benchmarking）

为了让模型配置界面彻底“回归家庭”，必须严格对齐 Conex 桌面端现有的四大标杆契约。

### 3.1 标杆一：全局设置容器与卡片契约（`SettingsUI`）
来自 `components/settings/SettingsUI.module.css`：
```css
/* 页面主干 */
.settingsUiPage {
  max-width: var(--settings-content-max, 820px);
  margin-left: auto;
  margin-right: auto;
  gap: var(--space-4, 16px);
}

/* 一级实体卡片 */
.settingsUiCard {
  background: var(--bg-card, hsl(0 0% 100%));
  border: 1px solid var(--border-color, hsl(35 10% 86%));
  border-radius: var(--radius-xl, 12px);
  overflow: hidden;
  display: flex;
  flex-direction: column;
}

/* 内部流式行 */
.settingsUiRow {
  padding: 10px 14px;
  border-bottom: 1px solid var(--border-subtle);
  background: transparent;
}
.settingsUiRow:last-child {
  border-bottom: none;
}
```
**对齐契约**：服务商主界面必须遵循此卡片契约，容器是带有 `12px` 圆角和纯白卡底的整体，内部行通过 `var(--border-subtle)` 自然隔开。

---

### 3.2 标杆二：输入控件与微焦点态（`Input.module.css` & AGENTS.md §13）
来自 `components/ui/Input/Input.module.css` 与 `AGENTS.md` 焦点态铁律：
```css
/* 标杆输入框 */
.input {
  background: var(--bg-card); /* 纯正通透白底 */
  border: 1px solid var(--border-subtle);
  border-radius: var(--button-radius, 7px);
  color: var(--text-primary);
  height: 32px;
}

/* 聚焦戒律：禁止粗黑边框，混入度不超过 10% */
.input:focus,
.input:focus-visible {
  outline: none;
  background: var(--bg-card);
  border-color: color-mix(in srgb, var(--border-color) 90%, var(--text-primary) 10%);
  box-shadow: 0 0 0 1.5px color-mix(in srgb, var(--border-color) 94%, var(--text-primary) 6%);
}
```
**对齐契约**：Base URL、API Key、搜索框、上下文长度输入框，全部继承纯白卡底与 7px 几何圆角，聚焦时维持纯净透亮。

### 3.3 标杆三：实体键帽与浮起胶囊（`SettingsShortcutsTab`）
来自 `components/settings/SettingsShortcutsTab.module.css:23-51`：

**对齐契约**：无论是左侧激活条目，还是右侧的实体交互项，若需要强调，均使用纯白卡底 + 精确投影（`--shadow-sm`），呈现出优雅的高级实体纸面触感。

## 四、Design Tokens 权威映射与替换矩阵（Design Tokens Remapping）

本方案对模型配置界面中用到的所有 CSS 变量做刚性统一，杜绝私有变量与任意灰度滥用。

### 4.1 容器与背景色映射表
| UI 元素 | 现状（错误用法） | 重构后权威 Design Token | 说明与视觉效果 |
| :--- | :--- | :--- | :--- |
| **双栏总容器外框** | `background: transparent; border-radius: 0;` | `background: var(--bg-card); border-radius: var(--radius-xl, 12px);` | 回归一级设置卡片纸底，12px 柔和圆角 |

## 十、总结

本方案穿透了用户批评的本质——**并非单一组件的微调，而是长期迭代造成的样式脱节、灰度失控与死代码腐化**。  
通过确立“**纯正白卡底（Paper Base）、极细柔和细线（Hairline Border）、克制聚焦环（Restrained Focus Ring）、轻量流式排版**”四大标杆，完成了 Design Tokens 的刚性重映射，重构了左右分栏的骨架韵律，并物理清退了 70% 的死代码。  
方案落盘于 `docs/model-capability/analysis/04-服务商界面整体视觉重构与样式规范方案.md`，为后续工程实现提供了精准、免猜测、零退避的技术蓝图。
