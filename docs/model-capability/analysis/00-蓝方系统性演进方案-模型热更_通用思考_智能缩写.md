# 蓝方系统性演进方案 · 模型热更新、通用思考模型与自适应缩写

> **战役工作区**：`docs/model-capability/`
> **模块定位**：蓝方架构详案（面向红方攻防审计与实施落地）
> **针对问题**：
> 1. 思考等级中文展示生硬（“提供方默认”等文案语义突兀，无思考标识）；
> 2. 内置 catalog 充满早期 AI 幻觉生成的过时条目（如不存在的 fable-5/opus-4-8，而现实中的 Gemini 3.8 Flash、SenseNova 6.8 等未收录）；
> 3. 模型配置完全为编译期打包或前端 localStorage，缺少外部配置文件与热更新（Hot Reload）能力；
> 4. 超长模型名（如 `muse-spark-1.2-contributor`、`sensenova-6.8-flash-lite`）在容器窄宽时被粗暴截断失去关键版本号与区分度。

---

## 一、模块一：外部配置文件与热更新引擎（Hot-Reloading Engine）

### 1.1 现状与架构断层
- **编译期死绑定**：`crates/agent-provider/src/models/catalog.rs:342` 使用 `include_str!("catalog.json")` 编译打包，任何模型能力的增加或修正必须重新编译 Rust 代码。
- **历史覆盖局限**：`catalog_override.rs` 存在过时覆盖白名单（只允许改价格与窗口，严禁新增条目，不支持 `thinkingTiers`）。
- **前端配置偏离**：自定义 Profile 存放在前端 `localStorage.crish_provider_profiles_v1`，无法通过外部文件集中配置与版本管理。

### 1.2 蓝方热更新方案设计
```
[外部配置文件]
~/.conex/models.json  或  <workspace>/.conex/models.json
          │
          ▼ (notify / debounced file watcher 200ms)
[Rust Hot-Reload Manager (crates/agent-provider/src/models/hot_reload.rs)]
          │
          ├── 1. 语法与 Schema 校验（容灾防崩溃）
          ├── 2. 合并层（L0 Bundled 基线  +  L1 User Overlay 增量/全量覆盖）
          ├── 3. 原子写入 Arc<RwLock<ModelCatalog>>，bump version
          │
          ▼ (Tauri Event: `catalog:reloaded { version, count }`)
[前端响应层 (apps/crish-desktop/src/api/thinkingGear.ts & stores)]
          │
          ▼
   无感刷新 UI 思考档位 / 上下文窗口 / 模型选项（零重启应用）
```

#### A. 配置文件定位与格式规范 (`~/.conex/models.json`)
```json
{
  "$schema": "https://crish.dev/schemas/models-v2.json",
  "version": 1,
  "updatedAt": "2026-09-03T07:30:00Z",
  "models": [
    {
      "model": "sensenova-6.8-flash-lite",
      "vendor": "sensenova",
      "provider": "sensenova",
      "displayName": "SenseNova 6.8 Flash",
      "contextWindow": 262144,
      "maxOutputTokens": 16384,
      "inputPrice": 0.1,
      "outputPrice": 0.3,
      "thinkingFormat": "thinking_budget",
      "thinkingBudgetDefault": 2048,
      "thinkingBudgetMax": 32768,
      "thinkingTiers": {
        "low": 1024,
        "medium": 4096,
        "high": 16384
      }
    },
    {
      "model": "muse-spark-1.3-contributor",
      "vendor": "muse",
      "displayName": "Muse Spark 1.3 Contributor",
      "thinkingFormat": "reasoning_effort",
      "thinkingTiers": {
        "low": "low",
        "medium": "medium",
        "high": "high"
      }
    }
  ]
}
```

#### B. 容灾与安全不变量
1. **静默容灾**：若外部 JSON 解析失败（如语法错误/写文件未刷盘），**严禁 panic**，继续使用现有内存 catalog，并通过日志与前端事件上报 `catalog:config_error`，UI 展示弱提示，不中断用户工作流。
2. **读写死锁防护**：采用短临界区读写分离，解析与校验全部在锁外完成；仅在准备应用时获取写锁并原子替换。
3. **防抖保护**：文件变动事件经 200ms 防抖，防止编辑器连续写入或外部同步工具引发的风暴。

## 二、模块二：通用思考能力契约（Universal Thinking Architecture）

### 2.1 彻底抛弃硬编码与 AI 幻觉
旧代码的致命缺陷在于试图由 AI 助手在内置库中硬编码各模型的思考参数，导致：
- 出现虚构模型；
- 新模型因无内置映射而被降级为不支持思考；
- 前端因字段名不匹配（`thinkingLevelMap` vs `thinkingTiers`）彻底失效。

### 2.2 通用思考形态抽象
统一抽象为 5 种标准形态（`ThinkingFormat`）：
1. `reasoning_effort`：字符串档位（`low`, `medium`, `high`），如 OpenAI o3/o4、DeepSeek R1、Kimi 等；
2. `thinking_budget`：Token 预算数字（如 Anthropic Claude 3.7、Gemini 2.5/3.8 Flash），支持各档位映射到具体 Token 预算；
3. `thinking_level`：级别字符串，如 Gemini 部分接口的 `"LOW" | "HIGH"`；
4. `thinking_adaptive`：自主根据提示词动态平衡思考；
5. `custom`：自定义请求字段映射（由用户在配置文件中指明 wire 字段名与值）。

### 2.3 前端档位解析统一（修复 `thinkingGear.ts` 契约）
- 将前端 `thinkingGear.ts` 彻底切到单一数据源 `thinkingTiers`。
- 允许用户为任一模型显式配置其支持的档位集。当模型配置了档位，前端实时渲染对应英文选项；未配置且 `supports_reasoning == false` 时，UI 优雅收拢，不呈现思考调节器。

## 三、模块三：模型名称智能自适应缩写算法（Smart Adaptive Abbreviation）

### 3.1 核心痛点
- 现状：`text-overflow: ellipsis` 从尾部截断。
- 灾难案例：
  - `muse-spark-1.2-contributor`  →  `muse-spark-1...`
  - `muse-spark-1.3-contributor`  →  `muse-spark-1...`
  - 核心版本号与修饰词被完全切掉，失去一切判别度，两模型看起来毫无区别。

### 3.2 自适应高判别分词缩写算法（SADA - Smart Adaptive Disambiguation Algorithm）
模型名称分词为四元组：`[Vendor/Family] - [Version] - [Size/Spec] - [Variant]`。

#### A. 缩写铁律
1. **版本号绝对保留**：包含数字、小数点、代际（如 `1.2`, `1.3`, `6.8`, `3.8`, `r1`, `v3`）的段为第一优先级判别键，**绝对禁止省略**。
2. **长特征词确定性压紧字典**：
   - `contributor` → `ctrb`
   - `sensenova` → `snova` 或 `sn`
   - `flash-lite` → `f-lite`
   - `checkpoint` → `ckpt`
   - `extended` → `ext`
3. **多阶自适应形态**：
   - **Level 1 (Full)**：`muse-spark-1.3-contributor` (26 字符)
   - **Level 2 (Compact, 容器中等)**：`muse-1.3-ctrb` (13 字符，省 50% 空间，区分度 100%)
   - **Level 3 (Ultra-Compact, 容器极窄)**：`ms-1.3-c` (8 字符，省 70% 空间，区分度仍达 100%)
   - 另一个模型对比：
     - `sensenova-6.8-flash-lite`
     - Level 2: `snova-6.8-flite` (15 字符)
     - Level 3: `sn-6.8-fl` (10 字符)

#### B. 零重排渲染实现（CSS Container Query 方案）
- 避免 JS ResizeObserver 频繁重计算引起的 Layout Thrashing。
- 在 React 组件中预计算好 `data-full`、`data-compact`、`data-ultra`，利用 CSS `@container (max-width: ...)` 纯原生毫秒级切换，搭配 `<Tooltip>` 悬停展示官方全名与完整模型 ID。

## 四、模块四：思考等级纯英文与诚实 UI 呈现

### 4.1 英文 Label 全面替代中文直译
将原有中文字样全面改为标准英文：
```typescript
export const THINKING_LEVEL_LABELS_EN: Readonly<Record<string, string>> = {
  default: 'Default',
  off: 'Off',
  minimal: 'Minimal',
  low: 'Low',
  medium: 'Medium',
  high: 'High',
  xhigh: 'X-High',
  max: 'Max',
};
```

### 4.2 胶囊 UI 呈现重构
- 杜绝出现孤立的“提供方默认”字样；
- **若当前模型支持思考**：
  - 胶囊右半边：`[ 🧠 Default ]` 或 `[ 🧠 High ]`；
  - 悬停 Tooltip：`Thinking Level: Default (Follow model provider)`；
  - 点击弹出清晰的英文选项菜单：`Default`、`Low`、`Medium`、`High` 等。
- **若当前模型不支持思考**：
  - 胶囊右半边思考控件**自动收起/隐藏**，不挤占任何输入空间；或者置灰展示并在 Tooltip 说明当前模型不支持思考调节。
