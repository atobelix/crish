## 一、 评审背景与问题定位

在现代化 AI 桌面客户端（Conex / Crish）中，大语言模型标识符呈现出爆发式的复杂化与异构化特征。真实调用链中的模型名称常携带提供商路由、组织命名空间、代际版本、硬件参数规模、量化精度、微调分支及快照日期等冗长信息（如 `openrouter/anthropic/claude-3-5-sonnet-20241022:beta`、`Qwen/Qwen2.5-Coder-32B-Instruct-GGUF/qwen2.5-coder-32b-instruct-q8_0.gguf`）。

与此同时，桌面客户端容器展示空间呈现出极端动态与受限的特征：
1. **底栏状态胶囊（Status Bar Capsule）**：与思考档位、延迟、Token 计数并列，安全宽度仅 **60px ~ 110px**；
2. **窄侧边栏与多栏分屏（Narrow Sidebar & Split View）**：会话标题宽度常压缩至 **120px ~ 180px**；
3. **模型选择下拉框与对话顶栏（Dropdown & Header）**：中等空间约为 **200px ~ 300px**。

传统方案在面对长模型名时存在三大致命缺陷：
- **末尾省略截断（Tail Ellipsis）**：将 `muse-spark-1.2-contributor` 与 `muse-spark-1.3-contributor` 均截断为 `muse-spark-1...`，发生**信息塌陷与同名碰撞**，用户彻底丧失辨识度；
- **朴素中间截断（Middle Ellipsis）**：将 `claude-3-5-sonnet-20241022` 变为 `claude...1022`，挖空核心规格 `sonnet`，保留无意义的快照数字；
- **静态字典硬编码（Static Dictionary）**：面对本地模型（Ollama）、企业私有微调（LoRA）或未来厂商新模型时命中失败，直接瘫痪。

为此，设计团队产出了三套独立架构方案（方案-A、方案-B、方案-C）。本报告旨在**独立、客观、尖锐、代码级**地综合分析三套方案的技术高下与通用性差异，并出具权威裁决与融合实施蓝图。

### 2.1 方案-A：SADA-Omni（语义熵锚定与层级自适应系统）
- **核心哲学**：将“版本与代际（Version/Generation）”确立为拥有最高不可侵犯权重的绝对物理锚点，任何压缩级别均不得裁切；
- **管道设计**：物理降噪与拓扑解构 $\to$ 混合分词（智能保护浮点数如 `1.3`, `3.5`） $\to$ 七大语义槽位推演 $\to$ 信息熵加权与辅音骨架收缩 $\to$ 上下文碰撞检测与差异提升 $\to$ 四阶离散压缩态（Full, Compact, Short, Micro）；
- **未知词压缩**：首字母保留 + 辅音骨架抽取 + 重复辅音折叠（`contributor` $\to$ `ctrb`）；
- **前端集成**：纯原生 CSS Container Queries，多 Span 占位配合 `@container` 切换 `display: inline/none`；
- **防御完备性**：给出工业级红蓝对抗测试矩阵（SEC-01 至 SEC-05，防御空值、超长灌水、ReDoS 等）。

### 2.2 方案-B：SADA-X（信息熵自适应引擎 + MUDT 最小唯一消歧）
- **核心哲学**：立足“零字典依赖”为第一原则，以信息熵梯度划分为理论骨架，通过严谨的数学集合差分消除候选集碰撞；
- **管道设计**：形态清洗与驼峰拆分 $\to$ 启发式语义角色分类 $\to$ **MUDT（Minimum Unique Discriminative Tokens）消歧提权** $\to$ 辅音骨架压缩 $\to$ 四阶空间自适应收缩；
- **消歧模型**：在候选模型集合中计算同族差分向量 $\text{DiffTokens}(M_i) = \bigcup_{j \neq i} (\text{Tokens}(M_i) \setminus \text{Tokens}(M_j))$，将差异 Token 强制提权为 Hard Pin（权重 1.0），从数学上 100% 杜绝同名碰撞；
- **前端集成**：CSS `@container` 配合 `content: attr(data-...)`，并严格遵守仓库规范包裹自定义 `<Tooltip>` 组件。

### 2.3 方案-C：SAMNA（语义感知模型名称自适应缩写算法）
- **核心哲学**：计算语言学分词 + 语义角色标注（SRL）+ 渐进式空间降解；
- **管道设计**：URI 路径剥离 $\to$ 智能分词 $\to$ 语义角色标注 $\to$ 四级渲染（L0~L3）或字符预算拟合（`abbreviateToFit`） $\to$ 同胞动态消歧；
- **未知词处理**：依赖预设的 `FAMILY_CAPSULE_MAP` 与 `SPEC_COMPACT_MAP`；对未知词主要采用首字母/前两字符切片（`slice(0, 2)`），缺乏音标级骨架压缩机制；
- **前端集成**：**使用 JavaScript `ResizeObserver` 配合 React `useState` 动态测量并重新渲染**；
- **消歧模型**：按基础缩写分组，若碰撞则尝试追加日期后4位或修饰词，最终兜底追加 3 位简单 Hash 字符串（如 `[ABC]`）。

## 三、 六大核心维度深度横向对比与代码级穿透

### 3.1 维度一：分词器与语义槽位推断能力（Lexical & Semantic Parsing）

| 评审指标 | 方案-A (SADA-Omni) | 方案-B (SADA-X) | 方案-C (SAMNA) | 深度剖析与代码级高下 |
| :--- | :--- | :--- | :--- | :--- |
| **浮点数版本保护** | **完全保护**。正则与分词器显式保护 `\d+(\.\d+)+`，`1.2`, `1.3`, `3.5` 绝不会在点号处断开。 | **良好**。在分类阶段识别浮点版本，但在分词正则阶段拆分连字符时稍粗。 | **较弱**。分词器将 `.` 纳入 `replace(/[-_.:/]/g, ' ')`，容易误将浮点数拆为两个离散数字。 | **方案-A 胜出**。方案-A 的分词阶段对浮点点号做了前瞻保护，避免了语义断裂。 |

### 3.2 维度二：未知模型与长标识符泛化自适应能力（Generality & Unknown Adaptation）

这是衡量方案“通用性”强弱的核心主干。

| 评审指标 | 方案-A (SADA-Omni) | 方案-B (SADA-X) | 方案-C (SAMNA) | 深度剖析与通用性裁决 |

### 3.3 维度三：上下文候选集消歧能力与防碰撞精度（Context Disambiguation）

当界面同时展示同系列或同前缀模型时（如 `muse-spark-1.2-contributor` 与 `muse-spark-1.3-contributor`，或 `claude-3-5-sonnet-20240620` 与 `claude-3-5-sonnet-20241022`）：

| 评审指标 | 方案-A (SADA-Omni) | 方案-B (SADA-X + MUDT) | 方案-C (SAMNA) | 深度剖析与消歧精度判定 |
| :--- | :--- | :--- | :--- | :--- |
| **消歧数学理论** | 碰撞探测 + 关键槽位回溯提升（检测到 micro/short 相同时，回溯并提取快照后4位或 Tier 字符）。 | **MUDT（最小唯一判别 Token 集）模型**：<br>形式化构建同族对比矩阵，提取差分集合 $\bigcup (\text{Tokens}(M_i) \setminus \text{Tokens}(M_j))$，动态提权为 Hard Pin。 | 分组哈希消歧：<br>按基础缩写分组，若长度 $>1$ 则尝试提取日期后4位或修饰词，最终兜底生成 3 位 Hash 字符。 | **方案-B 理论最严密，完胜 A 与 C**。<br>方案-B 的 MUDT 模型具有普适的数学美感，不局限于“日期”或“规格”，任意导致差异的 Token 均能被精准提取并提权锁定；方案-C 引入 Hash 后缀（如 `C-3.5S[0620]` 或 `[A3F]`）可读性较差。 |
| **跨层级防撞保证** | 保证在 L2/L3/L4 均保持版本号不可侵犯，消歧介入消除碰撞。 | 无论在 Standard、Compact 还是 Micro 级别，均在算法第一阶段完成消歧提权，全层级零碰撞。 | 仅在各层级渲染后比对分组并追加后缀。 | **方案-B 最优**。先提权后渲染，架构更连贯。 |

## 五、 “哪个更好”与“哪个通用性更强”的核心裁决

### 5.1 核心裁决一：哪个方案通用性更强？
**结论：方案-A（SADA-Omni）的通用性（Generality）最强！**

#### 根因依据：
1. **彻底跳脱静态字典绑架**：方案-A 构建了完整的“物理层拓扑剥离 + 词法槽位自动推演 + 辅音骨架自适应收缩”体系。无论面对私有微调（`fin-advisor-v2.1-qwen-72b`）、本地深层物理路径（`D:/models/.../q4_k_m.gguf`）、还是完全未知的专有名词（`synthesizer` $\to$ `synth`, `hyperion` $\to$ `hypr`），均能以纯算法确定性输出高度优雅且符合认知习惯的缩写；
2. **极端与边缘场景覆盖最深**：方案-A 进行了业界罕见的 **40+ 真实极端模型全谱系评测**，并针对无版本模型、纯数字标识、超长灌水输入、ReDoS 边界设计了极高鲁棒性的防御；
3. **对比之下**：方案-C 强依赖有限的内部静态字典，未知词直接回退到粗暴截断，通用性严重不足；方案-B 虽然也具备音节骨架算法，但在物理层异构格式清洗（如复杂多级网关、本地盘符、通道后缀）的覆盖面与极限用例防御深度上，略逊于方案-A。

### 5.2 核心裁决二：哪个方案更好？
**结论：方案-B（SADA-X）在“系统架构设计”与“工程规范成熟度”上综合表现更好；而方案-A 在“算法深度”与“视觉交互呈现”上更好。方案-C 存在严重架构硬伤，不予采纳。**

#### 深度对比剖析：
1. **为什么方案-B 更好？**
   - **消歧理论无可挑剔（MUDT）**：方案-B 提出的“最小唯一判别 Token 集”算法，将上下文同胞模型的消歧问题提升到了严格的数学集合差分高度。它不再基于主观猜测去抓取“日期”或“规格”，而是直接提取模型之间的正交差异特征并硬锚定提权，从根源上消除了任何多模型共存场景下的“撞脸”；
   - **严格恪守仓库纪律**：方案-B 100% 遵循本仓 `AGENTS.md` §12 规范，严格集成使用全局自定义 `<Tooltip>`，避免了方案-A 误用原生 `title` 的合规事故；
   - **开箱即用与测试完备**：方案-B 提供了单文件级高内聚代码及配套的 Vitest 单测断言，工程集成门槛极低。
2. **方案-A 的不可替代优势在哪里？**
   - **DOM 级原生 CSS 容器查询**：方案-A 采用多 Span 切换方案，比起方案-B 的 CSS `content: attr()`，既实现了零重排，又保留了文本的高亮、光标选中与无障碍支持；
   - **工业级输入防护**：SEC-01 至 SEC-05 的防爆浆与 ReDoS 审计，是长线高可用系统的必要屏障。
3. **方案-C 的致命伤是什么？**
   - **违背性能红线**：在 2026 年现代前端架构下，仍然使用 `ResizeObserver` + `useState` 进行文本测距与动态渲染，会在列表滚动与分屏拖拽时产生不可接受的布局抖动与主线程掉帧；
   - **消歧体验较差**：在冲突时直接追加 3 位 Hash（如 `C-3.5S[ABC]`），对终端用户极不友好。
