# Repair Campaign · 多 Agent 协同修复战役

> 系统性、自上而下的多 Agent 协同修复框架的执行档案。
> 方法论本体见 `00-playbook.md`（可复用，适用于多轮次迭代修复场景）。

## 与历史文档的关系

- `docs/frontend-audit/` 为**历史档案**：首轮 8 维度审计、9 批次修复（BATCH1-9）、复审 3 份、第二轮方案 4 份 + 评审 2 份 + master plan v1.0。本目录的轮次执行以其为输入档案，不迁移、不重写。
- 本目录为**当前权威工作目录**：从多模型独立分析开始，重新走完整选型/方案/评审/详设/执行闭环。

## 轮次结构（一轮内的逻辑阶段）

```
阶段 A 问题识别     多 Agent 独立分析（各维度）→ 独立方案文档
阶段 B 方案评审     2-3 Agent 评审前面的方案，各自给出最佳方案
阶段 C 主控整合     主 Agent 写总文档（维度划分+规则）+ 方案敲定文档
阶段 D 总方案评审   2 Agent 评审总文档（任务分配/维度划分/逻辑关系审计）
阶段 E 修订         主控定夺，派 Agent 修订文档
阶段 F 维度详设     维度数量 Agent 各写单一维度详细文档
阶段 G 维度评审     3 Agent 评审维度文档 → 针对性调整
阶段 H 定稿修订
阶段 I 执行         多 Agent 并行执行，批次独立提交，门禁全绿
```
