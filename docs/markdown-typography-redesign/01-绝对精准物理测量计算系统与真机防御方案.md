## 一、战役背景与反退避纲领（Mission & Non-Retreat Principles）

### 1.1 用户核心痛点深度工程定性

在真实排版与富文本编辑交互中，用户遇到了极其严重的体验退化与错位现象：
1. **光标时灵时不灵**：“这个鼠标是一会准一会不准，同一行的不同位置也是时灵时不灵。”在同一行文字里，点击某些字光标精准，但点击另一些字（或同一汉字的左右两侧）时，光标莫名偏离一个汉字甚至整段文字。
2. **多选高亮飞天或隐形**：“鼠标多选现在好像也不显示东西了，比刚才的显示错位又更退步了。以及鼠标位置和选中位置差了十万八千里啊。”
3. **表格交互出现脏灰矩形**：“点击编辑以后，为什么会出现和格子一样高的灰色矩形呢。矩形位置有时候还和矩形选择框不匹配。单元格拖拽模式，左上角的第一个也会出现一个灰色的矩形框。”
4. **性能严重迟滞与卡顿**：长文档加载后主线程阻塞，点击响应延迟数百毫秒，大纲条目重叠堆砌。

### 1.2 为什么“测不准，就什么都有问题”

富文本与 Markdown 编辑器的本质是**“离散字符状态机与连续物理图形画布的双向映射”**：
- **正向映射（Index $\to$ Coords）**：光标（`CursorLayer`）、文本选择框（`SelectionHighlight`）、输入法候选框（IME Follower）、浮动工具栏（Floating Toolbar）必须根据文档字符索引 $i$，在屏幕物理视口上画出绝对精准的矩形。
- **逆向映射（Coords $\to$ Index）**：用户的物理鼠标点击、滑动圈选、触摸事件输入一个绝对物理坐标 $(X, Y)$，系统必须无歧义地解析为文档中的唯一字符索引 $i$。

**如果正逆向测量映射存在任何误差：**
- 正向绘制的光标偏离物理字符，文本像被割裂；
- 逆向命中的字符与用户所指不符，造成乱插字、删错字；
- 选区计算使用错误的高宽与起点，导致高亮矩形飞出屏幕、拉伸畸变；
- 表格单元格和通用文本选区打架，产生遮挡字体的灰色矩形。

因此，**测量计算系统是整个编辑器最核心的物理基石。测不准，上层的一切排版美化、样式调整、交互功能都是空中楼阁！**

### 1.3 根除“打补丁、猜比例、伪实现”的五大硬性铁律

根据仓库总纲《反过度设计防线》与《反退避协作纪律》，在本次测量计算系统重构中，立下五大绝对铁律：

```
                              ┌────────────────────────────────────────────────────────┐
                              │            物理测量计算系统五大绝对铁律                 │
                              └───────────────────────────┬────────────────────────────┘
                                                          │
         ┌───────────────────────┬────────────────────────┼───────────────────────┬───────────────────────┐
         │                       │                        │                       │                       │
```

1. **绝对禁止“猜比例”算命法**：严禁在代码中写死 `charWidth = fs * 0.6`、`cjk = ascii * 2` 等人造规则。在现代字体（含 OpenType 特征、非等宽中文、加粗微调、字距微调、多语言混排）下，任何猜比例的算法都必然崩溃。
2. **必须使用真实 DOM Range 实测**：每一个在视口内渲染的字符，浏览器都已经完成了物理布局。测量必须通过原生的 `Range.getBoundingClientRect()` 获取真实的物理坐标包围盒。
3. **坐标系单一纯洁，禁止二次叠加**：彻底梳理容器、视口与内容坐标系。严禁出现“由于元素挂在滚动容器内，又额外加了一次 `scrollTop`”的低级叠加错误。
4. **图层状态绝对解耦**：表格模式（单元格选中、多格框选、单元格就地编辑）与文本选区状态必须显式解耦，状态互斥，杜绝全局选区向表格注入全局高亮矩形。
5. **真机刚性防守，不实测毫无意义**：绝不拿 JSDOM 的脱水单元测试自欺欺人。必须构建基于真实 Chromium 宿主的真机自动化物理防御脚本，对每一个字符与每一个点击点进行物理包围盒与光标坐标的像素级对齐断言。

## 二、现存测量计算系统四大致命缺陷深度代码复盘（Root Cause Forensics）

### 2.1 缺陷一：双轨测量分裂与“2.0 字符比例数学算命法”的误差雪崩

#### 现场实测证据与数据反差
在用户上传的截图 `media_1788533080612.png` 中，文本为：
```
### 9. 扩展语法 (Math, Kbd, Spoiler, Sub/Sup)
```
用户点击“展”字，自绘光标却落在了“扩”和“展”之间。用户反馈：“同一行不同位置一会准一会不准”。

通过我们在真实 Chromium 环境（页面 ID: 2）运行 Canvas 字体探测与 DOM Range 现场测量，测得的数据如下：
- 英文字符实际宽度：`wAscii = 8.8518px`
- 中文字符实际宽度：`wChinese = 16.0999px`
- **真实中英字宽比值：$16.0999 / 8.8518 = 1.8188$**
- 但是，旧代码 `measure.ts` 与 `HiddenInput.tsx` 中写死的回退规则为：
  ```ts
  const fs = parseFloat(window.getComputedStyle(container).fontSize) || 14;
  const ascii = fs * 0.6; // = 8.4px
  return { ascii, cjk: ascii * 2 }; // = 16.8px (写死 2.0 倍)
  ```

#### 为什么同一行会“一会准、一会不准”？
审查 `HiddenInput.tsx` 的 `indexFromClientPoint` 与 `measure.ts` 的 `getGlobalIndexFromDOMNode`：
```ts
// 命中分支 1：精准 Token 路径
if (typeof document.caretRangeFromPoint === 'function') {
  const range = document.caretRangeFromPoint(clientX, clientY);
  if (range && range.startContainer) {
    const idx = getGlobalIndexFromDOMNode(range.startContainer, range.startOffset, container);
    if (idx !== null) return idx; // <- 只有击中纯文本 TextNode 正中时才准！
  }
}
// 命中分支 2：几何回退路径
const col = predictColumn(lineText, relX, fallbackCharWidths(container));
return lineStart + Math.min(col, lineText.length);
```

1. **准的时候（分支 1）**：当鼠标正好点在长文本 Token 内部的字符正中时，Chromium 的 `caretRangeFromPoint` 能够直接捕获到该 `Text` 节点，并通过 `startOffset` 精确计算出字符偏移量。此时走的是物理测量，所以是准的。
2. **不准的时候（分支 2）**：当鼠标点在行首、行尾、字符间隙、Token 边界（如 `### ` 与 `9. 扩展语法` 之间），或者点在内边距上时，`caretRangeFromPoint` 吸附到了外层 `div.line-block`。`getGlobalIndexFromDOMNode` 找不到子节点，直接返回 `null`！
3. **回退算法的累加雪崩**：一旦进入 `predictColumn`，系统开始用 `16.8px` 累加预测汉字位置。每一个汉字产生 $(16.8 - 16.1) = 0.7\text{px}$ 的估算偏差，加上英文字符 $(8.4 - 8.85) = -0.45\text{px}$ 的负偏差，在混排字符串中误差剧烈震荡。**当文字行达到第 15~20 个字符时，累计误差直接突破 10~15 像素（跨过半个到整个汉字宽度）**，于是光标直接被吸附到前一个汉字或后一个汉字，表现出“一会准一会不准、时灵时不灵”的现象！

### 2.2 缺陷二：坐标系混乱与 `SelectionHighlight` 的双重滚动叠加（Double-Scroll Bug）

#### 现场实测证据
在用户上传的 `media_1788532432730.png` 与 `media_1788532972159.png` 中：
- 鼠标在文档下方（滚动位置约 4,000 像素处）进行文本框选拖拽；
- 选区高亮矩形（灰色透明块）却完全不跟随鼠标，而是死死贴在页面最顶端，或者甚至飞到屏幕可视区上方（`top: -210px`）。

#### 代码根因穿透
审查 `MarkdownEngine.tsx` 与 `SelectionHighlight.tsx`：
```tsx
// MarkdownEngine.tsx
<div
  ref={parentRef}
  className="editor-container editor-scroll-container"
  style={{ height: '100%', overflow: 'auto', position: 'relative' }} // <- 滚动容器自身已经是 position: relative
>
  <SelectionHighlight containerRef={parentRef} ... />
</div>
```
```tsx
// SelectionHighlight.tsx (原代码)
newRects.push({
  top: lineRect.top - containerRect.top + container.scrollTop, // <- 致命错误！
  left: left - containerRect.left + container.scrollLeft,
  width: Math.max(0, right - left),
  height: lineRect.height,
});
...
<div className="selection-layer" style={{ position: 'absolute', inset: 0, pointerEvents: 'none' }}>
  {rects.map((rect, i) => (
    <div key={i} className="selection-rect" style={{
      position: 'absolute',
      top: rect.top, // <- 这里的 top 是相对于 selection-layer 的
      left: rect.left,
      width: rect.width,
      height: rect.height
    }} />
  ))}
</div>
```

**为什么会产生“差了十万八千里”？**
1. `.selection-layer` 挂载在 `.editor-scroll-container` 内部。在 CSS 标准层叠上下文模型中，当一个容器设置了 `position: relative` 且 `overflow: auto` 时，其内部的 `position: absolute` 子元素已经处于该滚动流的内容坐标系内！
2. 当容器向下滚动 `scrollTop = 4000px` 时，页面内部元素物理上已经被向上位移了 4000 像素。
3. `lineRect.top` 是行元素在视口中的物理坐标。`lineRect.top - containerRect.top` 恰好等于当前行在视口可视区内的相对位移。
4. 如果此时再强行加上 `container.scrollTop`，就等于**将滚动距离重复相加了两次**！
   - 当 `scrollTop = 0` 时：$0 + 0 = 0$，选区勉强是准的；
   - 当 `scrollTop = 4000` 时：计算出的绝对 `top` 暴增 4000 像素，导致渲染出来的矩形直接飞出了天际，用户鼠标在当前视口圈选，选区却飞在数千像素之外！

### 2.3 缺陷三：表格模式与通用文本选区碰撞——“和格子一样高的灰色矩形”与外溢根因

#### 现场实测证据
在用户上传的 `media_1788533380837.png`、`media_1788533418889.png`、`media_1788533452269.png` 中：
1. 单击单元格时选中，再次点击进入编辑模式时，单元格内部出现了一个“和格子一样高的灰色矩形”；
2. 单元格拖拽选中多个格子时，左上角的第一个单元格内部文字（如“已完成”）背后也压着一个深灰色的垂直矩形块；
3. 这个矩形有时候比蓝色的单元格选择框还宽，甚至外溢到了右侧相邻的单元格中。

#### 代码根因穿透
审查 `BlockRenderer.tsx`、`InlineRenderer.tsx` 与 `SelectionHighlight.tsx`：

```
Markdown 引擎存储层模型：
行 142: "| 已完成 | < 2ms | 核心渲染组 | 95% |"  <-- 这在 EditorStore 里是一整行文本！
   │
   ├─ Token 0: "|" (table_pipe)
   ├─ Token 1: " 已完成 " (table_cell, start=3200, len=6)
   ├─ Token 2: "|" (table_pipe)
   ├─ Token 3: " < 2ms " (table_cell, start=3207, len=7)
   └─ ...
```

1. **状态污染（Cross-Store Contamination）**：
   在 `InlineRenderer.tsx` 的表格单元格鼠标事件中：
   ```ts
   // 点击单元格时：
   tableStore.enterCellSelection(tableId, lineIndex, colIndex);
   // 致命行：顺手把全局光标和选区设到了该 Token 开头！
   if (start !== undefined) {
     useEditorStore.getState().setCursorPos(start + 1);
   }
   ```
2. **`SelectionHighlight` 的无差别全局绘制**：
   `SelectionHighlight` 监听的是 `decorations` 中的 `selection` 装饰。
   当用户双击进入编辑、或者拖拽选中时，`EditorStore` 的 `selectionStart` 与 `selectionEnd` 覆盖了单元格内的字符区间（例如 `start=3201, end=3204`）。
   `SelectionHighlight` 在遍历文档中的行时：
   ```ts
   const lineStart = attrInt(line, 'data-line-start');
   const lineLen = attrInt(line, 'data-line-length');
   // 发现整行 table-row (3200..3240) 与当前选区 (3201..3204) 有交集！
   const lineRect = line.getBoundingClientRect(); // line 是整个 TABLE ROW！
   newRects.push({
     top: lineRect.top - containerRect.top,
     left: startCoord.left - containerRect.left,
     width: endCoord.left - startCoord.left,
     height: lineRect.height, // <- 表格整行的高度！
   });
   ```
3. **视觉灾难形成**：
   `SelectionHighlight` 绘制了一个高度等于整个表格行（`lineRect.height`）、宽度等于选中文本物理跨度的灰色矩形（`var(--blue-selection)`），并将其平铺在表格上！

4. 如果鼠标点击的 `clientX` 小于当前行第一个可见字符的 `left`，直接返回 `lineStart`（行首）；

### 3.5 物理二分探测算法核心 TypeScript 工业级实现

以下为 `src/core/measure.ts` 中新增的物理二分探测引擎核心实现代码：

```ts
/**
 * 物理行文本节点描述符
 */
interface MountedTextNodeEntry {
  node: Text;
  localStart: number; // 文本在行内的局部字符起始偏移
  length: number;     // 文本长度
}

/**
 * 扫描行元素内所有参与物理渲染的 Text 节点（跳过 syntax-hidden、katex 等）
 */
function collectRowTextNodes(rowEl: HTMLElement, lineStart: number): MountedTextNodeEntry[] {
  const result: MountedTextNodeEntry[] = [];
  const walker = document.createTreeWalker(rowEl, NodeFilter.SHOW_TEXT, {
    acceptNode(node: Node) {
      const parent = node.parentElement;
      if (!parent) return NodeFilter.FILTER_REJECT;
      // 忽略隐藏的 syntax-hidden、以及 katex 内部预览
      if (parent.closest('.syntax-hidden') || parent.closest('.katex-html')) {
        return NodeFilter.FILTER_REJECT;
      }
      return NodeFilter.FILTER_ACCEPT;
    },
  });

  let currentNode = walker.nextNode();
  while (currentNode) {
    const textNode = currentNode as Text;
    const globalIdx = getGlobalIndexFromDOMNode(textNode, 0, rowEl);
    if (globalIdx !== null) {
      result.push({
        node: textNode,
        localStart: Math.max(0, globalIdx - lineStart),
        length: textNode.nodeValue?.length || 0,
      });
    }
    currentNode = walker.nextNode();
  }

  // 按行内局部偏移排序
  result.sort((a, b) => a.localStart - b.localStart);
  return result;
}

/**
 * Tier 2: 真实 DOM 文本节点二分物理探测器
 * 输入：行元素、目标 clientX、行起点、行长度
 * 输出：与 clientX 物理欧氏距离最小的文档索引
 */
export function locateRowIndexByPhysicalBisection(
  rowEl: HTMLElement,
  clientX: number,
  lineStart: number,
  lineLen: number
): number {
  if (lineLen <= 0) return lineStart;

  const textNodes = collectRowTextNodes(rowEl, lineStart);
  if (textNodes.length === 0) return lineStart;

  const range = getSharedRange();

  // 1. 检查行极左边界：小于第一个字符左缘，直接归入行首
  try {
    range.setStart(textNodes[0].node, 0);
    range.setEnd(textNodes[0].node, Math.min(1, textNodes[0].length));
    const firstRect = range.getBoundingClientRect();
    if (clientX <= firstRect.left) {
      return lineStart;
    }
  } catch {
    // 忽略异常
  }

  // 2. 检查行极右边界：大于最后一个字符右缘，直接归入行尾
  try {
    const lastEntry = textNodes[textNodes.length - 1];
    range.setStart(lastEntry.node, Math.max(0, lastEntry.length - 1));
    range.setEnd(lastEntry.node, lastEntry.length);
    const lastRect = range.getBoundingClientRect();
    if (clientX >= lastRect.right) {
      return lineStart + lineLen;
    }
  } catch {
    // 忽略异常
  }

  // 3. 在所有可见文本节点中二分定位目标节点
  let bestDist = Infinity;
  let bestIndex = lineStart;

  for (const entry of textNodes) {
    const textLen = entry.length;
    if (textLen === 0) continue;

    // 二分搜索该 TextNode 内部字符
    let lo = 0;
    let hi = textLen;

    while (lo <= hi) {
      const mid = (lo + hi) >> 1;
      // 测量 mid 处的物理包围盒（折叠 Range）
      range.setStart(entry.node, mid);
      range.setEnd(entry.node, mid);
      let r = range.getBoundingClientRect();

      // 折叠 Range 遇到零高宽时展开 1 字符回退测量
      if (r.width === 0 && r.height === 0 && mid < textLen) {
        range.setEnd(entry.node, mid + 1);
        r = range.getBoundingClientRect();
      }

      const charX = r.left;
      const dist = Math.abs(charX - clientX);

      if (dist < bestDist) {
        bestDist = dist;
        bestIndex = lineStart + entry.localStart + mid;
      }

      if (charX < clientX) {
        lo = mid + 1;
      } else {
        hi = mid - 1;
      }
    }
  }

  return Math.min(lineStart + lineLen, Math.max(lineStart, bestIndex));
}
```

```ts
export class CoordinateTransformer {

  public static clientToContent(client: ClientCoords, container: HTMLElement): ContentScrollCoords {
```

### 4.3 彻底根除 `SelectionHighlight` 抛飞的数学证明与重构设计

#### 数学位移等价性证明
设：
- 屏幕原点为 $(0, 0)$；
- 滚动容器在屏幕上的位置为 $(C_x, C_y)$；
- 容器当前垂直滚动量为 $S_y$；
- 某文本行在屏幕视口中的渲染矩形顶边缘为 $L_y$；
- 挂载在滚动容器内部的绝对定位层 `.selection-layer` 顶边缘相对于容器边框为 $0$。

根据 CSS 层叠上下文与滚动流定位公理：
挂载在滚动容器内的子元素 `el`，其 CSS `top: T` 渲染在屏幕视口上的最终垂直坐标 $P_y$ 满足公式：
$$P_y = C_y + T - S_y$$

现在我们需要让高亮矩形在屏幕上的物理顶端 $P_y$ **严格等于** 文本行在屏幕上的物理顶端 $L_y$：
$$P_y = L_y$$
将公理公式代入目标方程：
$$C_y + T - S_y = L_y$$
求解 CSS `top` 属性 $T$：
$$T = L_y - C_y + S_y$$

#### 旧代码的错误推导
旧代码错误地将 $T$ 计算为：
$$T_{\text{error}} = (L_y - C_y + S_y) + S_y = L_y - C_y + 2S_y$$
导致矩形在屏幕上的最终渲染位置为：
$$P_{y,\text{error}} = C_y + T_{\text{error}} - S_y = C_y + (L_y - C_y + 2S_y) - S_y = L_y + S_y$$
**可见：渲染出的矩形与真实文本行之间的物理像素误差正好等于当前滚动量 $S_y$！**
当页面向下滚动 4000 像素（$S_y = 4000$）时，选区矩形被向下偏移 4000 像素，超出可视区，视觉表现为完全抛飞或错位！

```js

const TARGET_URL = 'http://localhost:5173/';
const TOLERANCE_PX = 0.5; // 刚性物理对齐阈值：0.5 像素以内

async function main() {
  console.log('🚀 启动真实 Chromium 物理测量计算防御测试...');
  const browser = await chromium.launch({ headless: true });
  const page = await browser.newPage({ viewport: { width: 1280, height: 900 } });
  
  await page.goto(TARGET_URL);
  await page.waitForSelector('.editor-scroll-container');
  await page.waitForTimeout(500); // 等待初始渲染与字体加载稳定

  // 执行全场景物理对齐断言
  const report = await page.evaluate(async (maxTolerance) => {
    const results = [];
    const container = document.querySelector('.editor-scroll-container');
    
    // 待测行选择器列表
    const testSelectors = [
      { name: 'H3标题中英混排', selector: '.line-h3', targetText: '扩展语法' },
      { name: 'H1标题大字号', selector: '.line-h1', targetText: '高性能' },
      { name: '行内样式加粗混排', selector: '.style-bold', targetText: '加粗' },
      { name: '表格单元格文本', selector: '.token-table-cell', targetText: '已完成' },
    ];

    for (const test of testSelectors) {
      const el = Array.from(document.querySelectorAll(test.selector)).find(
        (node) => node.textContent && node.textContent.includes(test.targetText)
      );
      if (!el) {
        results.push({ name: test.name, status: 'FAILED', reason: '未找到测试节点' });
        continue;
      }

      el.scrollIntoView({ block: 'center' });
      const textNode = Array.from(el.childNodes).find(n => n.nodeType === Node.TEXT_NODE && n.nodeValue.includes(test.targetText));
      if (!textNode) {
        results.push({ name: test.name, status: 'FAILED', reason: '未找到纯文本子节点' });
        continue;
      }

      const str = textNode.nodeValue;
      const targetCharIdx = str.indexOf(test.targetText[0]);
      
      // 测量目标字符的物理包围盒
      const range = document.createRange();
      range.setStart(textNode, targetCharIdx);
      range.setEnd(textNode, targetCharIdx + 1);
      const charRect = range.getBoundingClientRect();
      const centerY = charRect.top + charRect.height / 2;

      // 5 个物理测试点：0%, 25%, 50%, 75%, 100%
      const testPoints = [
        { label: '0%', x: charRect.left + 0.1, expectLeft: true },
        { label: '25%', x: charRect.left + charRect.width * 0.25, expectLeft: true },
        { label: '50%', x: charRect.left + charRect.width * 0.5, expectLeft: false },
        { label: '75%', x: charRect.left + charRect.width * 0.75, expectLeft: false },
        { label: '100%', x: charRect.right - 0.1, expectLeft: false },
      ];

      for (const pt of testPoints) {
        // 模拟鼠标点击
        const targetElement = document.elementFromPoint(pt.x, centerY) || el;
        targetElement.dispatchEvent(new MouseEvent('mousedown', { bubbles: true, cancelable: true, clientX: pt.x, clientY: centerY }));
        targetElement.dispatchEvent(new MouseEvent('mouseup', { bubbles: true, cancelable: true, clientX: pt.x, clientY: centerY }));
        targetElement.dispatchEvent(new MouseEvent('click', { bubbles: true, cancelable: true, clientX: pt.x, clientY: centerY }));

        // 获取光标元素
        const caret = document.querySelector('.cursor-caret');
        if (!caret) {
          results.push({ name: `${test.name} [${pt.label}]`, status: 'FAILED', reason: '未渲染 cursor-caret' });
          continue;
        }

        const caretRect = caret.getBoundingClientRect();
        const expectedX = pt.expectLeft ? charRect.left : charRect.right;
        const delta = Math.abs(caretRect.left - expectedX);

        if (delta > maxTolerance) {
          results.push({
            name: `${test.name} [${pt.label}]`,
            status: 'FAILED',
            reason: `物理错位超出阈值: 误差=${delta.toFixed(2)}px (上限=${maxTolerance}px), caretLeft=${caretRect.left.toFixed(2)}, expectedX=${expectedX.toFixed(2)}`,
          });
        } else {
          results.push({ name: `${test.name} [${pt.label}]`, status: 'PASSED', delta: delta.toFixed(3) });
        }
      }
    }

    return results;
  }, TOLERANCE_PX);

  await browser.close();

  let hasFailure = false;
  console.log('\n📊 物理对齐实测防御矩阵报告：');
  for (const item of report) {
    if (item.status === 'PASSED') {
      console.log(`  ✅ ${item.name} -> 对齐误差: ${item.delta}px`);
    } else {
      console.error(`  ❌ ${item.name} -> 失败: ${item.reason}`);
      hasFailure = true;
    }
  }

  if (hasFailure) {
    console.error('\n🚫 物理防御门禁拦截：检测到物理排版测量系统存在精度退化！');
    process.exit(1);
  } else {
    console.log('\n🎉 全部真实物理对齐测试 100% 满分通过！');
  }
}

main().catch(err => {
  console.error('测试执行异常:', err);
  process.exit(1);
});
```
