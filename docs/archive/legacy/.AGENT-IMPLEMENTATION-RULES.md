# Agent 实现规则

## 核心原则

1. **只读不写总纲**：可以阅读 `IMPROVEMENT-PLAN-MASTER.md` 了解全局上下文，但只执行分配给自己的具体子方案
2. **不读同级产出**：同一轮次中不读取其他 agent 正在写的文件，避免依赖未完成的工作
3. **代码优先，文档次之**：每个任务输出实际可运行的代码文件，附必要的头注释
4. **兼容性**：新代码必须与现有代码共存，不破坏已有功能。移除旧代码前先建新路径，迁移后再清理
5. **保持现有风格**：TypeScript 类型严格，中文注释，CSS Modules 风格
6. **自包含**：每个 agent 的输出应该独立可用，不产生未定义的交叉引用

## 文件规范

- 新建文件放在 `apps/crish-desktop/src/` 下对应的子目录
- 工具函数/纯逻辑：`src/utils/` 或 `src/api/`
- React hooks：`src/hooks/`
- React 组件：`src/components/` 下对应子目录
- 全局样式：`src/styles/`
- 服务层：`src/services/`

## 提交规范

- 每个 agent 输出完成后，用 `write` 工具将文件写入磁盘
- 不执行 `git commit`（除非用户明确要求）
- 不删除已有文件（除非方案明确要求）

## 轮次纪律

- 同一轮次 agent 之间**不互相通信**
- 下一轮次 agent 可以读取上一轮次已完成的文件
- 每轮结束后我会检查产出，安排下一轮
