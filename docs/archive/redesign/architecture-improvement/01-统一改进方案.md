# 统一改进方案

> 整合产品信任契约、UI 系统连贯、Streaming Transport、可观测性与会话加载、Daemon 运行时选型等 5 个方案。
> 按逻辑阶段分组，每个工作包包含前置条件、执行步骤、涉及文件。

---

## 阶段概览（依赖序）

```
P0 [契约基础]
  ├── T0: 配置契约文档 (无代码)
  ├── T1: 技能 ID + activation 对齐
  ├── T2: 规则 → scoped-context
  ├── T3: MCP 诚实 UI
  ├── T4: 安全/账户假控件收敛
  ├── T5: 砍死轨 (providers/cron/假模型)
  ├── T6: Slash/Goal 正式收敛
  ├── T7: 能力门闩 (list-capabilities)
  └── T8: 仓库卫生
P1 [协议与架构]
  ├── P1-A: 协议验证器拆分 (schema.ts 拆分)
  ├── P1-B: 服务接口抽象化
  └── P1-C: God Class 拆分
P2 [测试与质量]
  ├── P2-A: 关键模块测试补充
  ├── P2-B: Fuzz/压力/恢复测试
  └── P2-C: CI 质量门
P3 [可观测性]
  ├── P3-A: 结构化日志
  ├── P3-B: OpenTelemetry 集成
  └── P3-C: JSONL 轮转与健康检查
P4 [性能优化]
  ├── P4-A: Bundle 分析与优化
  ├── P4-B: 渲染性能优化
  └── P4-C: 缓存策略增强
P5 [安全加固]
  ├── P5-A: 密钥管理增强
  ├── P5-B: 输入验证全覆盖
  └── P5-C: 供应链安全
P6 [工程基础设施]
  ├── P6-A: Monorepo 工具引入
  ├── P6-B: CI 矩阵扩展
  └── P6-C: 自动发布
```
