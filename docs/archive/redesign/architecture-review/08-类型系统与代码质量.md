# 诊断方向 08：类型系统与代码质量

## 检查目标
评估 TypeScript 类型系统的使用深度、代码规范一致性、潜在类型安全隐患及整体代码可维护性。

## 检查清单

### 8.1 类型安全
- [ ] `as any` 使用：统计所有包中的使用量（当前 packages 下约 11 处）
- [ ] `as unknown as T` 使用：这是一个比 `as any` 更普遍的问题（packages 下约 100+ 处）
- [ ] 泛型函数缺失类型参数：`<T = unknown>` 的默认类型是否被准确传递
- [ ] 函数返回类型是否显式注解而非依赖推断
- [ ] tsconfig 中 `noUncheckedIndexedAccess` 和 `exactOptionalPropertyTypes` 是否已开启
- [ ] `catch (e: any)` 是否应替换为 `catch (e: unknown)` + 类型守卫
- [ ] 是否使用 Branded/Nominal 类型防止 ID 传参混淆（如 `RunId = string & { __brand: 'RunId' }`）
- [ ] Zod schema 与手写 TypeScript 类型是否一致，是否存在类型漂移

### 8.2 类型组织
- [ ] 超大类型文件拆分：`types.ts` (1756 行)、`validators/common.ts` (1730 行)
- [ ] 协议消息类型是否应与内部类型/生命周期类型分离
- [ ] 跨包共享类型是否集中在 shared-types 还是散布在各包
- [ ] 平台相关类型与核心类型的分离
- [ ] 类型导出隔离：`index.ts` 是否暴露了不应公开的内部类型

### 8.3 代码可维护性
- [ ] 函数/模块的圈复杂度——是否存在过长的 switch/if-else 链
- [ ] 魔术数字/字符串是否提取为具名常量
- [ ] 硬编码中文是否影响国际化（`App.tsx` `lang='zh-CN'`、`sessionActions` `'双击ESC分叉'`)
- [ ] 死代码清理：`isDemoMode()` 分支在 ~30 个引用点中的必要性
- [ ] `console.log` 在生产代码中的保留合理性
- [ ] `@deprecated` 标记的导出是否有新代码继续引用

### 8.4 命名与风格一致
- [ ] 文件名风格统一（`kebab-case` vs `PascalCase`）
- [ ] 导入路径格式统一（`.js` 后缀 vs 无扩展名）
- [ ] 函数命名规范：`get*` / `fetch*` / `query*` / `load*` 是否混用
- [ ] Props 类型命名：`XxxProps` 是否统一
- [ ] 代码注释中的中英文混杂

### 8.5 代码异味
- [ ] 参数过多函数（超过 4 个参数是否需要 Options 对象）
- [ ] 布尔参数控制不同路径（flag 参数是否需要拆分为独立函数）
- [ ] 长链式 `a.b.c.d` 是否存在 null/undefined 风险
- [ ] 复杂条件表达式是否提取为具名函数
- [ ] `vi.useFakeTimers` 在测试中是否清理正确

### 8.6 大文件专项审查（Top 10 largest）
- [ ] `provider-openai-compatible.ts` (2666 行) —— 是否可拆分为 provider 基类 + 各 API 兼容层
- [ ] `validators/common.ts` (1730 行) —— 验证器是否可按领域拆分
- [ ] `orchestrator.ts` (1725 行) —— orchestrator 核心逻辑是否可提取
- [ ] `types.ts` (1756 行) —— 类型定义分层
- [ ] `agent-session-loop.ts` (1300+ 行) —— 会话循环逻辑抽取
- [ ] `server-runtime-factory.ts` (1099 行) —— factory 职责拆分
- [ ] `sessionActions.ts` (1065 行) —— action 分组
- [ ] `daemonChatBridge.ts` (959 行) —— chat bridge 拆分
- [ ] `sessionPersistence.ts` (931 行) —— 持久化层拆分
- [ ] `server.ts` (930 行) —— server 类职责拆分

## 检查方法
- 统计 `as any` 和 `as unknown as T` 的数量
- 审查 tsconfig 中 strict 系列选项的配置
- 对超大文件（>800 行）逐个人工审查其职责数量
- 统计 `console.log` 和 `@deprecated` 标签
- 审查 Zod schema vs 手写类型的一致性
