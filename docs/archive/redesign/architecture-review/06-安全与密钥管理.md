# 诊断方向 06：安全与密钥管理

## 检查目标
评估系统的 API 密钥管理、输入验证、数据安全、跨进程通信安全及供应链安全。

## 检查清单

### 6.1 密钥管理与凭据安全
- [ ] API Key 在进程间传输是否经脱敏——`redactedApiKeyStatus()` 仅暴露 `hasApiKey`/`source`/`last4`
- [ ] 多 API Key 源的优先级管理（5 层配置层叠：default → workspace → user → env → runtime）
- [ ] API Key 在前端 localStorage 的存储是否安全
- [ ] daemon-ready 日志中 `last4` 是否应视为敏感信息
- [ ] WebSocket 连接是否有认证机制还是信任同机访问
- [ ] SecretRedactor 的脱敏能力——`redactText`/`redactJson`/`redactMessages` 是否覆盖所有日志输出点
- [ ] `process.env` 密钥读取是否有统一的白名单注册机制

### 6.2 输入验证
- [ ] WebSocket 入站消息经过 schema 验证（自定义 `validateInboundMessage` 而非 zod）
- [ ] daemon 端 `validators/` 目录的验证覆盖了哪些消息类型
- [ ] 用户输入（聊天内容、文件路径）是否经安全检查——`resolveUnderRoot()` 路径遍历防护
- [ ] 文件上传是否有类型/大小/路径遍历检查
- [ ] tool call 参数是否有类型和范围验证
- [ ] terminal command 是否经风险分类清理后再执行
- [ ] ChatComposer 的 textarea 是否有 maxLength 限制

### 6.3 Web/I/O 安全
- [ ] Tauri CSP 配置：`script-src 'self'`（安全）、`frame-ancestors` 是否缺失
- [ ] 前端 LLM 输出的 Markdown/HTML 是否经过 sanitize（当前未使用 DOMPurify）
- [ ] 跨标签页通信（BroadcastChannel）的 origin 验证
- [ ] Tauri v2 capability 权限配置是否遵循最小权限原则（`capabilities/` 配置）
- [ ] CSP 中 `frame-ancestors 'self'` 防点击劫持

### 6.4 供应链安全
- [ ] 是否配置 Dependabot / Renovate 自动依赖扫描（当前缺失）
- [ ] `npm audit` 结果中是否存在高危/严重漏洞
- [ ] Rust crate 的 security advisory 检查
- [ ] `ws` 库的 CVE 历史（DoS、内存泄漏）
- [ ] 是否依赖低维护的第三方包（`@chenglou/pretext@0.0.8`）

### 6.5 代码级安全风险
- [ ] 搜索 `eval`、`Function` 构造函数调用
- [ ] 动态 `import()` 的参数是否可被外部控制（`@vite-ignore` 的合理性）
- [ ] `any` 类型绕过导致的安全校验缺失
- [ ] 硬编码凭据、URL、API endpoint
- [ ] 进程内通信的 TLS/加密

## 检查方法
- `rg "apiKey|password|secret|token|credential"` 搜索所有引用
- 审查 tauri.conf.json 的 security 配置
- 追踪 WebSocket 消息从接收到处理的完整验证链路
- 运行 `npm audit` 和 `cargo audit`
- 审查 Tauri capability 配置
