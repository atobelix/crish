# Crish Desktop 系统连贯改进计划（逻辑顺序）

> 仅按依赖与因果关系排序，不设优先级时间表。
> 每一阶段完成后再进入下一阶段，避免「半修好的表面」叠在未修好的底子上。

---

## 0. 问题总览（从用户现象倒推根因）

| 现象 | 更可能根因 |
|------|------------|
| 获取模型列表 / 连通测试「无法访问」 | 浏览器 `fetch` 受 CORS 限制；Tauri 未装 `plugin-http`；错误文案过度归因为跨域；密钥未从最新 profile 读取；Base URL 与供应商约定不一致 |
| 侧栏滚动条离分割线远 | `.sidebar-scroll` / `.sb-list-scroll` 内边距过大 |
| 右侧面板点击卡顿 | `togglePanel` / 全量 `setState` 重排列与组；加号菜单定位错误导致布局抖动 |
| 加号菜单看不清 | 菜单在 tabs 内 `absolute`，被 `overflow` 裁切或宽度不足 |
| 标签只剩图标、易误点关闭 | `.card-tab--tool` 强制隐藏文字、窄宽；关闭钮叠在图标上 |
| 标签行不能横向滚 / 中键滚 | 未处理 `wheel` → `scrollLeft`；中键默认行为未禁 |
| 字发灰、界面浮 | 对比度与字重已部分改，需与标签/总览一起收口 |
| 审批/技能/MCP/高亮/总览 | 已有骨架，需与新标签交互、模型真源对齐 |

## 1. 引擎与供应商契约（一切 UI 的底座）

### 1.1 供应商 HTTP 约定（已查公开文档）

OpenAI 兼容族（DeepSeek、多数网关、OpenAI 自身）：

- **Base**：常为 `https://api.deepseek.com` 或 `https://api.deepseek.com/v1`（二者择一，勿重复拼 `/v1`）
- **列模型**：`GET {base}/models`，Header：`Authorization: Bearer <key>`
- **对话**：`POST {base}/chat/completions`，JSON：`{ model, messages, max_tokens, … }`
- **鉴权**：Bearer；失败时 HTTP 401/403，不是 CORS

浏览器里直接 `fetch` 公网 API 常被 CORS 拒绝；**引擎（daemon）侧 Node `fetch` 无 CORS**，与聊天主路径一致。

### 1.2 本阶段交付

1. **列模型 / 连通测试一律优先走 daemon**（新增协议或复用现有能力）：
   - 入站：`probe-provider-models` / `probe-provider-chat`（命名以仓库协议风格为准）
   - 出站：对应 `…-response`，含 `ok`、`status`、`models`/`latencyMs`、`error` 明文
2. Desktop `modelCatalog`：
   - 已连引擎 → daemon 探测
   - 未连 → 再尝试本地 `fetch`，错误区分：未连接引擎 / HTTP 状态 / 解析失败 / 网络
3. Base URL 规范化：去尾 `/`；若已以 `/v1` 结尾不再叠一层；文档化各预设默认 Base
4. 设置 UI：**任何结果必有内联提示**（成功/失败），禁止静默

### 1.3 约束

- 不把 API Key 打进日志或 toast 全文
- 不假装 CORS「修好」却仍只在浏览器裸 fetch
- 协议变更同步 registry / 类型 / 简单测试

## 2. 设置 · 模型页（建立在 1 之上）

1. 「获取列表」「连通」调用 1.2 的 API
2. 操作中禁用按钮 +「进行中…」；结束必写 status 条
3. 密钥保存后立即可用于探测（profile 热读）
4. 失败文案：人话 + 可行动作（检查 Base、保存密钥、确认引擎已连接）

---

## 3. 壳层视觉可读性（全局 token，先于局部组件）

1. 正文/次要/三级文字对比保持「不发灰、不浮」
2. 标签与导航可用 medium 字重，避免全站 400 发虚
3. `card-header` 与右侧工具条（files-bar）**同高**
4. 不恢复「壳层乱加粗」；仅修正对比与层级

---

## 4. 右侧工作区标签系统（逻辑上依赖 3 的尺寸 token）

### 4.1 信息架构

- 标签行：**整行可用**（图标 + 短标题 + 关闭）
- **禁止**默认「仅图标」导致误点关闭
- 关闭钮：仅 hover 时在标签**右侧**出现，不覆盖主图标热区
- 标签后 **`+`**（Obsidian 式）：打开面板列表
- 行尾：侧栏收起/展开（非二次「展开面板」迷宫）

### 4.2 交互

1. 标签行 `overflow-x: auto`；**普通滚轮横向滚动**（`wheel` → `scrollLeft`）
2. **禁用中键自动滚动**该行（`auxclick`/`mousedown` button===1 preventDefault，保留中键关标签若已有）
3. `+` 菜单：`position: fixed` + 视口定位，**不被 overflow 裁切**；点击外部关闭
4. 打开面板：`togglePanel` 路径避免不必要全树重算；能 focus 已有 tab 则不重建列

### 4.3 总览面板

- `overview` 为侧栏默认入口之一
- 内容：进行中步骤、Agent（运行中置顶）、改动文件、上下文摘要；MCP/技能/规则跳转设置
- 长列表分区折叠

---

## 5. 左侧边栏滚动条与分割线

1. 缩小滚动容器与右边框间距至 **1～2px**（检查 `.sidebar-scroll` / `.sb-list-scroll` / padding-right）
2. 滚动条样式不抢宽；与主内容区分割线视觉贴合

---

## 6. 对话与工具呈现（建立在稳定引擎与布局之上）

1. 工具行：读/搜/编/壳等线型圆角图标，重量一致
2. 代码块 / 文件预览：highlight.js
3. 路径链接：点击 → 文件侧栏
4. 工具结果区：微差底 + 四边若隐渐隐
5. 审批：通俗问句 + **必有输入框**；不占快捷功能区；可有「需要权限」提示条滚到卡片

---

## 7. 运行错误与流式

1. 系统错误 → 横幅/toast，**永不进 AI 正文**
2. 有 delta 则真流式；无 delta 则 message-end 渐进
3. 流式光标

---

## 8. 技能 / MCP / 规则（产品诚实）

1. 技能 ID 与 runtime 对齐；自发现需确认
2. MCP 诚实空态与启停能力
3. 规则 upsert scoped-context
4. 顶栏/总览只做跳转，不伪造未接能力

---

## 9. 性能与卡顿（在 4 的交互路径上收口）

1. 分析右侧 `togglePanel` / `setState` 是否导致整棵 workspace 重挂载
2. 打开已存在 tab 时只改 `activeCardId`
3. 加号菜单、总览列表避免大 re-render
4. 必要时 `memo` Overview 子块
