## 1. 文件所有权纪律（两轮通用，硬约束）

1. **package.json（根）唯一编辑者 = T1**。其余任务一律只读；任何任务发现自己需要改动脚本位、依赖位或 workspaces，把诉求写入轮末汇总，由 T1 统一落盘。
2. **根 Cargo.toml 的 members 段唯一编辑者 = T3**；`[workspace.lints]` 段归 T13（R4 任务，不在本手册轮次内），T3 与其余任务一律不得触碰 lints 段。
3. **T4 不碰 package.json**——测试断言所需数据以只读方式读取。
4. **T16 / T18 只读 package.json 的脚本位**——可用于交叉验证与命名对齐，不得写入任何脚本内容。
5. 文件域边界以各任务声明为准，越域修改一律禁止。

## 2. 三条「不要做」（不实的审计项，禁止执行）

1. **不要做「node_modules 假绿」处理**。该审计项不实：workbench 的 tsc 是真实红色（`apps/agent-workbench/src` 内存在对已删 TS 包的 import），不存在「依赖已装好所以编译可以通过」的假象。T4、T5a 必须真实修复源码，不得以任何理由跳过。
2. **不要做「workspaces 挂了 11 个已删包」的批量清理**。该审计项不实：根 package.json 的 workspaces 共 9 个包，全部真实存在（`apps/crish-desktop`、`apps/agent-workbench` + packages 下 7 个），其中只有 `packages/decision-engine` 是死包。已删的 agent-* 包根本不在 workspaces 里，不得把 8 个活包当已删包处理。
3. **不要删除 src-tauri/Cargo.toml 的 url 依赖**。该审计项不实：url 在 `apps/agent-workbench/src-tauri/src/host_openers/resolve.rs:118`（`url::Url::parse`）有真实使用，必须保留。T3 只删除 `tokio-tungstenite`（:27）与 `conex-ipc`（:44）两处死依赖。
