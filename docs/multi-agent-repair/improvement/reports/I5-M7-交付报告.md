## 1. 事件设计（Rust 侧三事件产出，events.rs）

| 事件 | 必填字段 | 可选字段 | 说明 |
| --- | --- | --- | --- |
| `subagent-started` | sessionId, subagentId, subagentRunId, role, capabilityMode, startedAt | description, mode, parentToolCallId | runId 由信封注入 = 父 run（ParentID 语义 01 B1-2）；前端消费位 subagentHandlers.ts:17-26 全覆盖 |
| `subagent-event` | sessionId, subagentId, subagentRunId, event | — | event 为结构化负载 `SubagentEventPayload { kind: progress/message/tool, payload? }`，前端整体透传（:38-42） |
| `subagent-ended` | sessionId, subagentId, subagentRunId, status, endedAt | summary | status 规范值 completed/failed/cancelled——cancelled 命中前端 /cancel/ 分支映射 stopped 展示（:50-56），Rust 不产生 stopped 值（M2 状态映射） |

配套类型：`SubagentEventKind`（kebab-case）、`SubagentEventPayload`、`SubagentEndStatus`（lowercase）、
`BackpressureLevel`（Delta/Soft/Critical）+ 静态判定函数 `event_backpressure` / `subagent_event_kind_backpressure`。
全部可选字段一律 `#[serde(default, skip_serializing_if = "Option::is_none")]`（minor 兼容，changelog §四 1.3 登记）。

## 2. 背压分级（04 报告 1e：Delta→Soft→Critical，delta 可丢、terminal 必达）

分类**静态可判定**，写入事件注册表每事件 `backpressure` 字段，护栏双向锁定：

| 级别 | 事件 | 语义 |
| --- | --- | --- |
| Delta（可丢） | message-delta（既有非持久化语义）、subagent-event 的 progress 类 | 不落库不阻塞 drive loop |
| Soft（尽力） | subagent-event 的 message/tool 类 | 可丢弃重发 |
| Critical（必达） | 其余全部（含 subagent-started/subagent-ended、run-terminal、审批、审计等） | 落库不丢 |

- 既有 28 事件仅 message-delta 为 delta，其余保持 critical——**不改变既有丢帧语义**（先例 buffer.rs `drop_class_of`：非 delta 全 Critical）；
- subagent-event 条目另带 `kindBackpressure: { progress: delta, message: soft, tool: soft }`（kind 级映射，注册表 `SubagentEventKind` 枚举值全覆盖校验）；
- Rust 侧 `event_backpressure` / `subagent_event_kind_backpressure` 与注册表逐事件断言一致（registry_drift.rs §7 三测试）；
- 生成产物新增 `ENGINE_EVENT_BACKPRESSURE` / `SUBAGENT_EVENT_KIND_BACKPRESSURE` 常量（前端 EventRouter 消费位，类型安全）。
