## 0. 结论先行

- **31 引擎事件 → 14 钩子**：11 个引擎事件映射到 12 个钩子（tool-end 一源双钩），
  2 个钩子（model.beforeRequest / model.afterResponse）无引擎事件源（M14 补源，E1 只挂钩）；
  其余 **20 个引擎事件无对应钩子**，继续走事件总线消费（前端/遥测），不进插件面。
- **公式锁定**：31 = 11（映射）+ 20（无对应）；14 = 12（映射钩子）+ 2（补源钩子）。
- **批次**：第一批接 6 个映射（session.start/end、turn.start/end、tool.pre/post，
  含 06 已接的 turn.end/tool.pre/tool.post 三个现状点）；第二批接 8 个钩子
  （tool.error、context.compact.start/end、error.occurred、model.beforeRequest/afterResponse、
  subagent.start/end）。
- **背压**：全部映射引擎事件均为 Critical（必达落库）——Delta/Soft 仅 message-delta 与
  subagent-event 的 kind 级分类，均不在映射面内；映射表「背压级别」列由冻结测试与
  `event_backpressure` 静态判定锁定。

## 1. 映射方向与规则

- **映射方向**：引擎是事件源，钩子是消费面（03 §2.1 语义原样保留）；
- **禁止为凑齐而强行映射**：无对应即事件总线消费，不预开全量（kimi matcher 思路延伸，
  03 §2.2 设计理由）；
- **同源多钩子仅 tool-end 一例**：tool-end（isError=false）→ tool.post、
  tool-end（isError=true）→ tool.error 追加广播，保留 ToolHook.onError 控制能力（禁令 14）；
- **补源钩子不占映射行**：model.beforeRequest/afterResponse 由 02 方案 M14（I7）补
  `crates/agent-provider/src/events.rs` 事件源，E1 只挂钩不补源；
- **subagent 域唯一发射方**：subagent.start/subagent.end 只消费 M7 定稿的
  subagent-started/subagent-ended 信封（03 §2.3，E1 不得在 orchestrator 域重复发射）。

## 2. 完整映射表（31 口径，14 行）

> 钩子事件名点分（`packages/shared-types/src/hooks.ts`）；引擎事件名 kebab-case
> （`crates/conex-types/src/events.rs` 注册表）；payload 字段映射以引擎事件字段 → 钩子
> payload 字段（hooks.ts 声明，E1 补齐 HookPayloadMap 全 14 载荷）；背压级别为引擎事件
> 静态分级（registry_drift 已锁定注册表）；是否落库 = Critical 落库不丢语义。

| # | 引擎事件 | 钩子事件 | 批次 | 背压 | 是否落库 | 接线点 / payload 字段映射要点 |
| --- | --- | --- | --- | --- | --- | --- |

| 7 | `tool-end`（isError=true） | `tool.error` | 第二批 | Critical | 是 | 同 tool-end 点位，isError=true 时追加广播；on 模式可转 retry 信号（保留 ToolHook.onError 控制能力） |
| 8 | `context-compression-start` | `context.compact.start` | 第二批 | Critical | 是 | compression 域处理起点；sessionId ← sessionId、trigger ← reason（映射 trigger 语义）、currentTokenCount ← tokensBefore |

| 10 | `runtime-error` | `error.occurred` | 第二批 | Critical | 是 | 引擎错误分类处；sessionId ← sessionId、error ← error、retryable ← retryable；插件自身错误也进此事件（错误事件化） |

## 3. 无对应钩子的引擎事件（20 个，事件总线消费，不进插件面）

> 设计理由（kimi matcher 思路延伸，03 §2.2 原样保留）：插件钩子面是**策略/观察的窄面**，
> 全量转发会造成 handler 噪声与测试面失控；这 20 个事件继续走 31 事件总线给前端/遥测
> 消费；若未来插件确需订阅，以新增映射（+测试）的方式逐个开面，不预开全量。

| 分类 | 引擎事件 | 不进插件面理由 |
| --- | --- | --- |
| 收场复用 | `agent-end` | 随 `run-terminal`/`session.end` 收场事件总线消费，不单独映射钩子 |
| 流式消息 | `message-start` / `message-delta` / `message-end` | 流式消息正文由前端水合投影消费，插件只读面不需要（窄面原则） |
| 工具进度与批语义 | `tool-update` | 进度增量（预留 tool-args-delta），插件不消费 |
| | `tool-batch-start` / `tool-batch-end` | 批语义由单工具 pre/post/error 覆盖，插件不消费批容器 |
| 修复审计 | `tool-input-repaired` | 修复审计内部链路，对插件透明 |
| 厂商诊断 | `provider-diagnostic` | 厂商诊断（前端仅 logInternalError），对插件透明 |
| 编排干预 | `runtime-steering` / `runtime-intervention-required` | 编排干预走控制总线 L0-L3 既有通道，插件不重复消费 |
| 审批 | `approval-requested` / `approval-resolved` | 审批面已有中间件/审批链（I3 ApprovalGate），插件不重复消费 |
| 检查点 | `checkpoint-created` / `checkpoint-restored` | 检查点（C1）对插件透明 |
| 缓存测量 | `cache-stats-updated` / `cache-waste-alert` / `cold-cache-warning` | 仅测量展示，不干预循环（P5 语义） |
| 安全审计 | `security-audit` | 审计面独立闭环（I2-S8 删除接管/红线拦截），插件不消费 |
| 子代理过程事件 | `subagent-event` | 过程增量（progress=Delta 可丢、message/tool=Soft），窄面原则不映射；subagent 生命周期由 start/end 两钩子覆盖 |

## 4. 冻结机制（映射表与代码双向锁定）

### 4.1 Rust 侧（`crates/conex-types/tests/event_hook_mapping.rs`，9 测试）

| 测试 | 锁定内容 |
| --- | --- |
| mapped_engine_events_exist_in_enum | 11 个映射引擎事件 ∈ `AgentEvent::ALL_TYPE_NAMES`（enum 变体断言） |
| unmapped_engine_events_exist_in_enum | 20 个无对应引擎事件 ∈ `AgentEvent::ALL_TYPE_NAMES` |
| mapping_partitions_all_engine_events | 31 = 11 + 20 全集划分：映射 ∪ 无对应 = 全集、交集为空、无重复 |
| hook_names_are_frozen_14 | 14 钩子名唯一、点分命名；补源钩子在全集内 |
| every_hook_name_has_mapping_row | 14 = 12（映射钩子）+ 2（补源钩子），补源钩子不得出现在映射行 |
| only_tool_end_has_two_hooks | tool-end 为唯一同源双钩特例（tool.post/tool.error） |
| mapped_backpressure_annotations_match_judgement | 映射事件背压全 Critical，与 `event_backpressure` 静态判定一致 |
| hook_names_exist_in_hooks_ts | 每个钩子名以字面量出现在 `packages/shared-types/src/hooks.ts`（跨 TS 侧锁定） |
| mapping_contract_anchors | 第一批接 6 事件在映射面内；31 - 11 = 20 恒成立 |

### 4.2 TS 侧（`packages/shared-types/src/hooks.test.ts`，8 测试）

| 测试 | 锁定内容 |
| --- | --- |
| HOOK_EVENT_NAMES 恰为 14 项且唯一 | 运行时断言 |
| 全部为点分命名 | 禁令 14 命名格式 |
| 现有 6 个事件命名保留 / 新增 8 个事件命名 | 12 → 14 定稿不退化 |
| 类型层双向锁定 HookEventName ⇄ HOOK_EVENT_NAMES | 契约 ⊆ HookEventName（可赋值）+ HookEventName ⊆ 契约（分配式穷举断言，新增事件名未同步常量即编译失败） |
| 映射行去重 12 个钩子 / tool-end 双钩特例 | 映射表钩子侧一致性 |
| 14 = 12 + 2 全在 HOOK_EVENT_NAMES | 映射钩子 ∪ 补源钩子 = 全集 |
| 映射引擎事件 11 个 kebab-case | 与 Rust 侧口径一致 |

### 4.3 变更纪律

改动任一侧必须三处同步：本报告 §2/§3 表 → Rust 测试常量 → hooks.ts（事件名与
HOOK_EVENT_NAMES）；映射表的 payload 字段映射随 E1 的 HookPayloadMap 落地后，
以类型层断言继续冻结（E1 验收含「枚举级冻结测试：HOOK_EVENT_NAMES 14 项与
Rust `HookEventKind::as_str()` 全集一一对应」）。
