## 1. 声明机制设计

新模块 `crates/agent-tools/src/write_paths.rs`（Reasonix WritePathSet 落地）：

- **`WritePathClaim`**：`{ holder, session_id, path(规范化绝对路径), mode, claimed_at_ms, expires_at_ms }`
  ——任务书结构 + 必要扩展：`holder`（谁占用，冲突错误信息必需）、`expires_at_ms`（TTL 超时释放）。
- **`ClaimMode`**：`Write | Delete`——互斥检测不区分模式（都是写操作），模式仅作错误信息与审计展示。
- **`WritePathRegistry`**：会话级记账（每会话一实例，`session_id` 固定）。
  - `claim(holder, paths, mode)`：多路径原子化声明——校验失败或任一冲突即整体拒绝；
    **冲突检测与插入在同一锁区间完成**（防 TOCTOU：检测后、插入前他方抢注）；
    同持有者同路径重复声明去重续期（子代理可写自己声明范围内路径，扩展不冲突）。
  - `claim_one` 便捷形态；`check_conflict`（纯预检，供 M6 spawn preflight / `ValidateNonOverlappingWriteClaims`）；
    `active_claims`（快照）；`release_holder`（幂等释放）。
  - **`WriteClaimGuard`（RAII）**：守卫持有注册表同一实例的 `Arc`，Drop 即释放本持有者全部声明
    ——工具执行期随作用域结束（成功/错误/panic/取消）自动释放；子代理 run 期由 M2/M6 持有守卫到结束。
- **`validate_write_path`**（M3 任务卡内容 1 校验纯函数）：复用 `resolve_workspace_path`
  （symlink 解析后比较、`..` 越界拒绝、工作区外拒绝、深度上限），另显式拒绝 glob（`* ? [`）。
- **Overlaps 检测**：路径前缀语义（组件级）——`a/b/c.txt` vs `a/b/` 冲突、同路径双向命中、
  `a/b` vs `a/bc` 不冲突（组件边界）；比较基于归一化（统一分隔符 + Windows 小写 + 去尾部分隔符），
  跨平台确定性一致，Windows 大小写折叠由归一化层承担。
- **锁中毒处理**：按项目约定 A 模式（记录错误、取回内值继续，不 panic，PE-07 T07.6 对齐）。

## 2. 互斥接线（引擎级）

- **ToolContext 扩展**（`context.rs`）：
  - `write_claims: Option<Arc<WritePathRegistry>>`——注册表挂载点，None = 未接线不强制（现状行为保持）；
  - `write_claim_holder: Option<String>`——声明持有者（子代理 run id；None = 会话主身份），
    同持有者声明不互斥是「子代理可写自己声明路径」的语义前提。
- **写工具接线**（`claim_write_guard` 助手，未接线返回 None 直通）：
  - `write_file`（fs.rs）：路径解析后声明 `Write`；
  - `delete_file` / `delete_dir`（delete.rs）：目标声明 `Delete`；
  - `shell_command`（shell.rs）：删除形态重定向路径——全部目标先声明再执行（任一占用整链拒绝，
    不产生部分删除）；普通命令目标无法静态预知不声明（对齐 Reasonix checkpoint：bash 副作用不跟踪）。
- **冲突拒绝**：错误码 `tool.write_path_conflict`（本域局部码，对齐 shell.rs 的
  `tool.requires_approval` 模式），消息结构化含**谁占用 / 会话 / 模式 / 声明时刻 / 有效期至**；
  `WritePathConflict` 结构化类型供 M6 预检程序化消费。
- **接线位**：`session-loop/src/tool_exec.rs:656-657` 补 `write_claims: None, write_claim_holder: None`
  （ToolContext 新增字段的编译必需位；执行器按会话装配注册表归 M2/M6）。

## 3. 只读子代理工具集裁剪

新模块 `crates/agent-tools/src/readonly.rs`（Reasonix ReadOnlySubagentToolRegistry 落地）：

- `WRITE_TOOL_NAMES`：`write_file / delete_file / delete_dir / shell_command`（shell 整体剔除——
  bash 副作用无法静态预知，删除形态重定向不能覆盖全部写形态）；
- `READONLY_TOOL_NAMES`：`read_file / list_dir / file_stat / grep_search / fuzzy_find / diff_text`；
- `filter_readonly_registry`：**白名单语义（fail-closed）**——白名单外的工具一律剔除
  （含未来新增的未分类工具，防新写工具漏网），返回新注册表不改动原表；
- 挂接点：M2 run_subagent spawn 时按 capabilityMode 装配（M3 任务卡内容 5）。

## 4. 超时释放

- 声明带 TTL：`DEFAULT_CLAIM_TTL_MS = 60_000`（60s 无活动自动释放，防悬挂）；
- `expire_stale_at(now_ms)`（显式时钟）/ `expire_stale()`（系统时钟）清扫过期声明；
  `claim` / `check_conflict` 前置自动清扫（惰性释放，过期声明不阻塞新声明）；
- `WriteClaimGuard` Drop 释放是第二道保险（TTL 是第一道）。

## 7. 遗留与交接

1. **会话级注册表装配**：`write_claims` 接线为 None（未强制）——M2（run_subagent 执行上下文）
   与 M6（调度器）按会话创建 `WritePathRegistry` 并注入 ToolContext，子代理 run 期持有
   `claim(run_id, write_paths)` 守卫到结束；父代理写预留（ReserveParentWrite）消费
   `check_conflict` / `claim` 即可，接口已就绪。
2. **冲突策略**：当前冲突 = 直接拒绝（结构化错误，无审批）——对齐 M3 任务卡「冲突声明直接拒绝」；
   若调度需要串行排队语义，M6 可在拒绝错误上叠加等待队列（本模块不持有队列）。
3. **跨会话互斥**：注册表按会话隔离（对齐 Reasonix 会话级记账）；同一工作区跨会话写冲突
   不在本任务范围（isolationMode=none 约束下的已知边界）。
4. **并行域协调**：
   - `lib.rs` 补 `pub mod subagent_inject;` 声明（M4 在途遗留，缺失导致 crate 无法编译，
     已补一行声明；若 M4 后续自行补充需去重）；
   - M2 `subagent.rs` 递归守卫测试在途波动（SiblingsExceeded vs ConcurrentExceeded 断言），
     轮末已收敛，workspace 全绿确认无残留；
   - 只读白名单不含 `run_subagent`（spawn 工具，fail-closed 剔除），M2 若需只读子代理
     再派生子代理（深度收紧场景）需在 spawn 侧单独放行。
5. **shell 普通命令不声明**：非删除形态 shell 命令写目标不可预知，引擎不互斥（对齐
   Reasonix checkpoint「bash 副作用不跟踪」）；如后续需要，可由语义分析层升级覆盖。
6. **持久化**：声明随 session_agents 落库（M3 任务卡三问）归 M6 唯一写面（session_meta /
   subagent_path_json 扩展），本模块提供 `WritePathClaim` serde 序列化支撑，不落库。
