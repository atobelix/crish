## 一、工具设计（wait_subagents，注册面 11→12）

新增 `crates/agent-tools/src/tools/wait_subagents.rs`（agent-tools 是叶子 crate，
对齐 I4-M2 subagent.rs 接线约定——只定义契约、纯逻辑与工具本身；session_meta
落库与终态事件流接入在引擎侧实现 [SubagentWaitChannel]，测试域以 conex-db
dev-dependency 验证落库与重启恢复链路）。

- **入参**：`subagentIds: string[]`（必填非空，run_subagent 返回的 subagentId）；

- **通道契约**：[SubagentWaitChannel] trait（persist_declaration /
  snapshot / wait_for_terminal / inject 四方法），引擎侧实现，与

  未接线返回结构化 common.unsupported 错误（零副作用）。

## 二、三模式（04 C8 §2.1：主 agent 视角等待策略，不改变 C6 子代理调度与并发预算）

| 模式 | 语义 | 实现 |
| --- | --- | --- |
| await-all | 等待全部指定子代理终态（completed/failed；cancelled 归一 failed，I0 裁决）后再规划下一步；期间事件只记录不打断（无 L2/L3） | `wait_for_terminal(ids, None)` 缺省不限时；显式 timeoutMs 作逃生上限 |
| timer | 等待 `dispatch_wait_ms`（默认 30s，`DEFAULT_TIMER_WAIT_MS`）后唤醒主 agent 规划，未完成任务保持运行 | `wait_for_terminal(ids, Some(30s))`；timer 语义 = 单次 wait 带超时；全部提前终态则提前返回 |
| parallel-work | 分发后立即返回，主 agent 转入并行工作，子代理事件经 L1 注入带回 | `snapshot(ids)` 立即快照，`allTerminal` 由快照计算，不产生阻塞等待 |

显式 `timeoutMs=0`（任意模式）→ 非阻塞快照（02 Top 7「省略或 0 = 快照」语义）；
与「省略」区分：省略走模式缺省，显式 0 强制快照。

## 三、等待原语（yield 语义，pi 借鉴——本任务覆盖）

- **工具化而非引擎阻塞**：主 agent 的等待经 wait_subagents 工具调用承载，
  单次返回 + 状态摘要，主 agent 串起后续行动（ref-analysis 01 B2）；
  工具内部异步等待子代理终态事件，不占用引擎循环。
- **事件驱动优先**：[wait_for_terminal_events] 原语（tokio mpsc + timeout_at）
  消费终态事件流直到全部终态或超时：
  - 终态事件只记录不打断；重复事件幂等忽略；非等待名单子代理终态忽略
    （并发其它子代理）；事件流关闭 → 返回当前态（fail-open 不 panic）；
  - 超时 → `timed_out=true`，未完成子代理保持 running 返回；
  - elapsed = ended_at - dispatched_at（终态）/ now - dispatched_at（未终态）。
- **引擎侧接线面**：订阅 subagent-ended 事件流（M7 信封：
  subagentId / status / summary / ended_at，本模块 `SubagentTerminalEvent`
  与之一一映射），灌入 mpsc 交原语消费；L3 强停经 abort token 竞速取消由
  引擎侧实现方承担。

## 四、持久化（dispatch_* session_meta 键，04 §4 键隔离 C8 独占）

调度声明 [DispatchDeclaration]（mode / wait_ms / subagent_ids /
dispatched_at_ms）经 [SubagentWaitChannel::persist_declaration] 落库，
工具每次等待前持久化——重启后可恢复「等待什么」：

- 键：`dispatch_mode` / `dispatch_wait_ms` / `dispatch_agents`（JSON 数组）/
  `dispatch_dispatched_at`（epoch ms）；
- 恢复：`DispatchDeclaration::from_meta_pairs`（关键键缺失/非法 → None，
  fail-open 不 panic）；`remaining_wait_ms(now)` 重启后按 dispatched_at 重算
  剩余等待（timer 到点判定 `is_expired`）；
- conex-db 只读（get/set_session_meta 既有接口），生产代码不引 conex-db。

## 五、运行中注入（L1 soft_inject 通道，control.rs C8 主写权）

`crates/session-loop/src/control.rs` 扩展（只加不删，既有 L0-L3 语义不变）：

- `ControlBus::request_subagent_inject(subagent_id, prompt, source)`——经
  L1 steer 环 transfer 到目标 run 的下一安全点（pi steer 语义），reason
  带 `subagent_inject:<id>` 可观测标识；
- `subagent_inject_message(subagent_id, prompt)`——user 角色文本消息，
  created_at 与 steering 侧同源（now_iso_utc），id 带子代理标识 + 自增序号
  （同毫秒不碰撞）；
- 注入不打断流：drain 聚合恒为 SoftInject（无 L2/L3）；L3 强停仍优先
  （control.rs:315 drain_as_action 优先级不变）；
- 工具侧：wait_subagents 可选 `inject` 参数，等待期间经 channel.inject
  路由到目标 run 的 steer 环；
- await-all「等全部终态再规划」的提示词纪律由工具契约承载（description
  声明「await-all 等待全部终态后再规划下一步」）+ 引擎语义（allTerminal
  全真前不返回）。
