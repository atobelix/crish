## 2. 唯一性确认

- **subagent 域唯一发射方收口**：M7 只定义类型/背压/信封（其交付报告遗留 4 明确「发射点 EventQueue 接线归 M6 后段 / M14 收口」）；M14 落地为 `subagent_events.rs` 单模块——03 方案 E1 只挂钩不补源（不得在 orchestrator 域重复发射），模块头文档显式声明。
- **无重复发射断言**（测试锁定）：
  - `subagent_events_emitted_once_on_spawn_and_terminal`（flow_scheduler.rs）：两节点链路事件流 = started(A)→ended(A)→started(B)→ended(B) 各恰一次（共 4 条）；**重复终态通知不重复发射 ended**（幂等断言）。
  - `session_start_end_map_to_run_lifecycle_without_duplication`（events.rs）：一次 run 生命周期 agent-start / run-terminal 各恰一次、流首尾锚定（映射而非双发）。
  - `without_emitter_no_subagent_events`：未挂载发射器零事件（可选接线语义）。

## 3. 背压

- `subagent-started` / `subagent-ended`：Critical（EventQueue 落库不丢，注册表 30/32 号既有锁定）。
- `subagent-event`：kind 级——progress=Delta、message/tool=Soft（M7 注册表既有）；**本轮将 `orchestrator::events::event_class` 扩展**：progress 类归 NonPersistent（不落库不阻塞 drive loop），message/tool 与既有持久化语义一致（`subagent_event_progress_is_non_persistent` 测试锁定）。
- `session.start/end`：映射自 agent-start/run-terminal——注册表均 Critical（既有），不新增条目。
- `model.*`：ProviderStreamEvent 通道事件（**不入 AgentEvent 注册表**：非会话事件、不落 events 表；消费面在 I8 钩子桥）。分类文档化于 events.rs 模块：before-request/after-response 为 Critical 级观测事件（必达语义由请求层观测器保证）。
- **注册表 31 事件不变**：M14 未新增 AgentEvent 类型，registry_drift 护栏无漂移（`cargo test -p conex-types` 全绿）。
