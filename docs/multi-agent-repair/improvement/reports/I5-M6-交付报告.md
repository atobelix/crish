## 1. 依赖图模型

新模块 `crates/orchestrator/src/flow_graph.rs`（调度核心，约 1500 行含测试）：

- **`FlowNode { id, task, depends_on, parallel, on_failed, is_composite }`**：
  - `depends_on` = 04 文档 `after`（对齐 jcode PlanItem.blocked_by），**允许
    前向引用**（按 id 引用，声明序只决定同层串行顺序）；
  - `parallel` = 04 文档 `parallel`（是否允许与无依赖关系的同级并发）；
  - `on_failed` = 节点级策略覆盖（None = 会话级 `flow_on_failed` 默认）；
  - `is_composite` = 综合节点标记（gate / verify / critique 类，合成唤醒位）。
- **`FlowDeclaration { tasks, planner_run_id }`**：planner_run_id 为综合 run
  亲和记录位（jcode NodeMeta.planner 对齐）。
- **持久化**：`session_meta` `flow_*` 键命名空间——
  `flow_declaration`（单键 JSON，Q3 裁决：任务数 >20 再建表）、`flow_state`
  （节点 → run 映射 + 唤醒标记）、`flow_on_failed`（会话级默认策略）、
  `flow_reserved` / `flow_released`（预算两计数）、`flow_max_concurrent` /
  `flow_max_siblings` / `flow_auto_composite`（可配位，默认 6 / 5 / true）。
- **接入面**：`FlowScheduler::new(会话, spawner, meta)` + `declare_flow`；
  引擎侧（workbench）把 subagent-ended 事件回传
  `on_subagent_terminal(run_id, SubagentState)` 即完成事件驱动闭环。
- **session.rs 主写权**：保持 C6（M6）独占权但本轮未改动——依赖图经
  session_meta 持久化，与 SessionTree（会话树/叶子）正交，无自然并写点；
  树主写权保留给后续轮次（C1 恢复 / C7 fork 只读引用冻结接口不受影响）。

## 2. 环检测（staged-clone 原子回滚）

- **`FlowGraph::detect_cycle`**：DFS 三色标记，返回环路径（`["a","b","c","a"]`，
  相邻对 = depends_on 关系）。
- **声明路径**：`FlowGraph::from_declaration` = 候选图全量校验（空声明 →
  重复 id → 自依赖 → 未知引用 → 环），**未通过不写任何 `flow_*` 键、
  不 spawn 任何 run**（04 C6 验收 5：含环声明被拒且零 run，测试锁定）。
- **增量加边**：`FlowGraph::add_dependency` = staged-clone（克隆本图 → 克隆上
  加边 → 环检测 → **通过才原子替换**）；发现环返回错误且本图不被改写
  （测试锁定：拒绝后图结构与加边前完全一致）。
- **自依赖禁止**：`after` 不含自身，单独错误类型（`SelfDependency`）。

## 3. gate 强制 / 并发预算

- **gate（就绪判定）**：`is_ready` = 待启动 且 全部前置 **completed**
  （running / pending / failed 均不启动）；已 completed 节点只推进不回溯。
  失败节点按生效策略放宽（Skip / Report 视为满足、Block 视为阻塞）。
- **事件驱动不轮询**：`on_subagent_terminal` 内部调 `advance()`（不动点循环：
  一轮推进产生的 spawn 失败可能改变后置就绪/阻塞判定，迭代有界收敛）；
  预算满的就绪节点保持就绪，**等下一终态事件自动重试**——测试断言
  「完成一个 → 终态事件返回值里立即可见补位 spawn」，全程无轮询循环。
- **并发预算 reserve/release（复用 RecursionGuard）**：
  `ConcurrencyBudget { reserved, released }`，in_flight = reserved − released；
  每次 reserve 前经 `check_recursion_guard(RecursionGuardSnapshot{depth:1,
  active_siblings: in_flight, active_concurrent: in_flight}, guard)` 判定
  （maxSiblings=5 先命中、maxConcurrent=6 兜底，DEFAULT_RECURSION_GUARD）；
  记账「已分配」而非「已消耗」。10 个 parallel 任务峰值 = 6（≤ maxConcurrent，
  测试锁定）；挂接外部 run（attach_run）同样过预算检查（BudgetExceeded）。
- **跨重启重算**：`ConcurrencyBudget::recompute(active, terminal)` →
  reserved = 活跃 + 已终态、released = 已终态 → in_flight = 活跃数
  （已完成任务预留被 released 抵消，防 double-charge；重算值回写 meta）。

## 4. on_failed 三策略（任务卡 Skip / Block / Report 映射）

| 策略 | 任务卡语义 | 实现 | 上报 |
| --- | --- | --- | --- |
| `Skip` | 跳过且不影响同级 | 失败节点对后置的依赖视为满足，后置照常启动 | 不上报 |
| `Block` | 阻塞依赖它的节点并上报 | 依赖节点置 `Blocked`（终态，含传递阻塞），Block 传播迭代到不动点 | NodeFailed + Blocked 双上报 |
| `Report` | 照常推进但记录 | 后置照常启动，失败留痕 | NodeFailed 上报 |

- 生效策略 = 节点 `on_failed` ?? 会话级 `flow_on_failed`（默认 Block，对齐
  04 文档默认 abort；术语映射 Block=abort、Skip=skip、Report=retry_once
  去重试形态，模块头文档登记）。
- spawn 失败（引擎侧拉起失败）→ 节点按失败处理、释放预留、产生
  SpawnFailed 上报，并走同一策略语义（Block 时后置阻塞，同一调用内收敛）。
- 重复终态事件幂等（不重复 release / 不上报）。

## 5. 重启恢复

- `FlowScheduler::load(session_id, spawner, meta, session_agents 行)`：
  1. 读 `flow_declaration`（缺失/损坏 → NotFound，fail-open 不 panic）；
  2. 读 `flow_state`（节点 → run 映射 + 唤醒标记）；
  3. **节点状态从 session_agents 行重建**（每任务状态在 session_agents 行，
     不重复落两份真源）；run 映射缺行 = 数据不一致 → 按失败处理并积压上报；
  4. 预算跨重启重算并回写；
  5. 调用方 `advance()` 恢复推进——测试断言：已完成节点不重复启动、
    运行中节点恢复为 Running（run id 不变）、崩溃窗口内已就绪未 spawn 的
    后置节点补启动、编排继续推进至终态。
- 声明提交点语义：先写 `flow_declaration`（锚点）→ 重置 state/budget →
  内存替换；声明写成功前崩溃零副作用，之后崩溃按新声明从零推进
  （旧编排必已终态才允许替换，无部分运行态）。

   RecursionGuard 兜底，调度器暴露 `budget_in_flight()` 供引擎合并快照。
5. **一轮一编排**：`declare_flow` 在旧编排全终态后允许替换；`reset_flow`
   显式清空（抹 `flow_declaration` 键）。多编排并行（session_meta 键后缀
   区分）列入开放问题，Q3 建表裁决时一并评估。
6. **同层串行语义**：`parallel=false` 的节点按声明序与同层串行（spawn
   顺序 = 声明序），未做显式串行锁——依赖推进天然单线程（单调度器实例），
   语义即声明序。
