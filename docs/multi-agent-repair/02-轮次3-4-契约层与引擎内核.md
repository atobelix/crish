## 0. 阅读指引与全局依赖

本轮承担四条主链路的核心改造：

1. **契约层**：Rust 域事件成为双端契约唯一事实源（T6），前端分派与解析全部改为消费生成产物（T7）。
2. **引擎内核**：工具执行获得会话级上下文（T9），审批流从"软拒绝喂回模型"改为真实审批事件（T10）。
3. **前端状态**：layoutStore 从 god-object 拆为按域 store（T11），依赖规则微观化守门（T14）。
4. **债务收口**：workspace.lints 从空壳填充（T13），conex-db 单文件拆分（T15）。

### 全局串行依赖边

```
R1            T3（定稿 members）──► T13（workspace.lints 填充，R4）
              T1（package.json 清理）──► T15（conex-db 拆分，R4）
              T16（性能基线自动回写）已于 R2 执行，见 01 号手册 5.2

R3            T6（契约生成）──► T7（EventRouter 重构，R4）
              T9（ToolContext）──► T10（权限规则引擎，R4）

R3 内部       T6 / T9 / T11 / T14 四条线写集不相交，可并行（见 1.4）
R4 内部       T7 / T10 / T13 / T15 四条线写集不相交，可并行（见 3.4）
```

| 边 | 方向 | 语义 | 开工闸 |
|---|---|---|---|
| T7 → T6 | R4 → R3 | 分派表 handler 入参类型与单 schema 全部引用 T6 生成产物 | 汇合点 R3-M 通过，生成产物冻结 |
| T10 → T9 | R4 → R3 | 审批通道挂在 `ToolContext.ask`，requires_approval 判定消费 T9 迁移后的工具集 | T9 新签名合入 |
| T13 → T3 | R4 → R1 | T13 需在 T3 定稿根 Cargo.toml members 后动工（同一文件所有权串行）；lint 集合选择由 T13 自行裁定 | T3 的 members 终态可用 |
| T15 → T1 | R4 → R1 | T15 需在 R1（T1）完成 package.json 清理后新增脚本位（package.json 所有权：R1 归 T1，R4 归 T15） | T1 的 package.json 清理终态可用 |

> 注：T16（性能基线自动回写）归属 R2，已在 01 号手册 5.2 执行完毕，本手册不再登记依赖边。

#### T6 契约生成链路（替代 77 处手工对齐）

**目标**：Rust 域事件 enum（24 种）成为双端契约唯一事实源；TS 类型与解析器全部由生成脚本产出，手工对齐清零。

**文件域**：
- 写：`crates/conex-types/src/**`（事件 enum、载荷结构、derive 标注）
- 写：生成器（`crates/conex-types/build.rs` 钩子或独立脚本 `scripts/generate-engine-bindings.mjs`，二选一，交付时冻结入口）
- 写：`packages/shared-types/src/generated/engine/**`（生成产物，入库版本控制）
- 删改：77 处"对齐 TS 端"注释（逐处核对后移除）

**内容**：
1. 盘点 24 种域事件，产出编号清单（事件名 → 载荷结构 → 序列化格式），作为后续轮次引用的事件注册表。
2. 在事件 enum 与载荷结构上标注生成 derive；序列化保持 serde 现有帧格式不变。
3. 生成器产出三类文件：事件联合类型、各载荷类型、解析器（与前端现有 zod 风格对齐），统一落到 `generated/engine/**`。
4. 幂等性：生成脚本连续运行两次，产物 diff 为空。
5. 全量删除"对齐 TS 端"注释，凡有信息价值的转写进事件注册表文档。

**验收命令**：
- `cargo test -p conex-types`
- 生成脚本连续运行两次后 `git diff --stat` 为空（幂等）
- `rg -c "对齐 TS 端" crates/conex-types/src` 输出为 0
- `npm run typecheck`（生成类型可编译）

#### T9 Tool::execute 引入 Context

**目标**：全部工具获得会话级上下文，中止、审批提问、工作区根目录通道就位，为 T10 铺路。

**文件域**：
- 写：`crates/agent-tools/src/definition.rs`（trait 与 `ToolContext` 定义）
- 写：`crates/agent-tools/src/tools/**`（shell 等全部工具迁移）
- 写：`crates/agent-tools/src/context.rs`（ToolContext 类型与构造器）
- 写：调用点（session-loop、orchestrator 中的 execute 调用，由编译驱动发现）

**内容**：

3. 参数手工 require_string 解析保留；需要会话级数据的工具改从 ctx 读取。
4. 全部工具与既有测试随迁移；旧签名清零。

**验收命令**：

#### T7 EventRouter 重构（依赖 T6）

**目标**：16 个 `if(type===)` 分支清零，改为 `Record<EventType, Handler>` 分派表；双 zod 合并为单一 schema（引用 T6 生成产物）。

**文件域**：
- 写：`apps/crish-desktop/src/api/chat-bridge/EventRouter.ts`
- 写：`apps/crish-desktop/src/api/chat-bridge/handlers/**`（按事件域拆分 handler 文件）
- 只读引用：`packages/shared-types/src/generated/engine/**`（T6 产物）

**内容**：
1. 以 T6 生成的 EventType 联合类型建立 `Record<EventType, Handler>` 分派表，handler 入参为具体事件信封类型。
2. 删除全部 16 个 `if(type===)` 分支与等价的 switch 串行分支。

#### T10 权限规则引擎（依赖 T9）

**目标**：消费 dangerous 标记与 requires_approval；审批不再落 SoftDeny，而是产生真实 approval 事件（走 `ctx.ask` 通道）；tool_exec.rs:557 折叠路径删除。

**文件域**：
- 写：`crates/agent-tools/src/`（definition.rs、新增 permission 模块、shell 工具）
- 写：tool_exec.rs:557 所在文件（移除 SoftDeny 折叠）
- 写：事件 enum（如需新增审批事件变体，走 T6 生成链路同步并重生成 TS）

**内容**：
1. 权限判定函数：输入 dangerous 标记 + requires_approval + 当前配置，输出"允许/拒绝/需审批"三态。
2. 需审批时经 `ToolContext.ask` 发出真实审批请求事件，等待用户裁决；等待期间支持 `abort_token` 取消。
3. tool_exec.rs:557 移除 SoftDeny 折叠，改为透传审批状态，不再把"待审批"伪装成"模型可自行降级执行"。
4. 新增测试：**危险命令产生审批事件**——对带 dangerous 标记的 shell 命令调用 execute，断言产生 approval 事件且命令未直接执行。
