## 遗留风险
- 访问栈只存 href：若某会话在入栈后被删除，返回导航到该 href 时由会话屏自身的缺失态承接（sessionDetailScreen 已按可选 sessionId 设计），不崩但可能落到空态页一次；属可接受残余，未做有效性预检（避免为边缘场景引入跨层依赖）。
- 访问栈未随登出/换账号复位（`resetSessionVisitStack` 已预留导出）：href 仅含会话 id、不含账号维度，换账号后理论上可能导航到不存在的会话（同上，空态承接）。是否接入账号生命周期留收口裁决，本批未擅自接线 accountService。
- `dismissTo` 分支以 canGoBack 近似「栈中有主页」：若栈形为 [设置页, 会话页]（无主页且可回退），dismissTo('/') 在 expo-router 中的行为是导航到主页并清中间页，与 navigate 的差别仅在不留旧会话残留——比原无条件 navigate 更贴方案意图，但该栈形下与方案字面（有主页才 dismissTo）有近似成分，已在此明示。
