## 一、核实结论（逐嫌疑判定）

### 嫌疑 1：落定动画被任意触摸打断后无人收口，抽屉冻在半开位 ——

C 世代 `onTouchesDown`（当前磁盘版 L168–177）对**全屏任何一处落指**无条件执行 `cancelAnimation(progress)` 并快照 `startProgress`——包括点按、包括主列表纵向滚动的起手、包括动画落定途中的任意触碰（这是另一工作线「手到即停/即时接管」的**有意设计**，其在途测试用例名即「手到即停(cancelAnimation)」）。问题是接管失败时没有收口：

- 手势随后被判 fail（纵向滚动意图，FAIL_DY=12 极易触发）或根本未激活就抬指（纯点按）时，RNGH 语义下 `onEnd` **不会**被调用（未激活的手势只有 `onFinalize` 会无条件触发）；
- 当前实现**没有注册 `onFinalize`**（全文件 grep 无此字样，在途测试的 mock 手势链里也没有这个回调位）；
- 结果：progress 冻在中间值，无任何动画把它送回 0/1；`onAnimationFinished` 永不触发，isOpen/phase 与视觉位置脱节（场景 `pointerEvents` 仍按旧 isOpen 判定、tap-dismiss 层不出现、BackHandler 未注册）。用户下一次成功滑开/滑上抽屉前，界面停在半开僵局——体感正是「卡手」，且**只在「落定动画在飞的窗口内又去触摸/滚动」时中招**，与「时不时」完全吻合。
- 在飞窗口不短：C-HEAD 的 withTiming 为 250–350ms 量级；在途弹簧（damping 30 / stiffness 260，阻尼比 ζ≈0.93）完全静止需约 0.5–0.8s。典型触发链：点会话行 → 抽屉开始收拢 → 用户立刻在主界面滑动列表 → 冻住；或轻扫开抽屉后马上抓列表滚动 → 冻住。「滑动多了才卡」的另一面：滑动越频繁，撞上在飞窗口的概率越高。
- B 世代无此问题（无 cancelAnimation，触摸不打断 withTiming）。A 世代有 onTouchesDown 但未见 cancelAnimation（grep 无），同样无此问题。**这是 C 世代回归引入的新机制。**

### 嫌疑 2：仲裁回调无「已激活」防护，拖动中途可能被自己的 fail 判定打断 ——

C 世代 `onTouchesMove`（L179–220）在手势的整个触摸流期间持续运行，内部 fail/activate 判定**不区分手势是否已经 activate**（无 event.state 检查、无已激活标志位）。RNGH 2.32 中 `onTouchesMove` 在手势 ACTIVE 后仍持续收到触摸事件，`stateManager.fail()` 经 `setGestureState(handlerTag, FAILED)` 直达原生侧（已查随仓 `gestureStateManager.js` 确认）；而 RNGH 原生编排器本身就会对 ACTIVE 手势执行取消迁移（手势竞争落败方即走此路），故 ACTIVE→FAILED 是原生支持的迁移。若原生侧受理已激活手势的 fail，则：抽屉拖动途中手指方向漂移、任一采样点满足 `absDy > 12 && absDy > absDx`（拖动变向、减速、指腹滚动都常见）→ 手势当场死亡，`onEnd` 不触发、抽屉停在手指离开的位置——**字面意义的「滑动中途卡手」**。修复动作（仲裁只在未激活期生效）无论原生语义如何都是正确的防御，装机验证只需做慢速斜向拖动态确认。

### 嫌疑 3：激活死区 + 激活瞬间位移跳变（全世代通病）——

- 激活前手指先走 14dp 死区（ACTIVATION_DX，全世代未变），画面零响应；
- `onUpdate` 用**原始** `event.translationX` 换算 progress（`startProgress + translationX / maxTranslate`），激活瞬间 translationX 已含那 14dp，于是卡片在激活帧一次性跳过 ≈14dp（抽屉宽 320dp 的约 4.4%）；
- 体感 = 「先粘住不动、然后猛地窜一下」，是平滑拖动里最典型的顿挫感来源之一。B 世代声明式 offsets 同理（activeOffsetX 14dp 后首帧 onUpdate 同样含全量 translationX）。

### 嫌疑 4 后半（补齐）：判定——成立（次级，与嫌疑 1/2 叠加放大）

- 单采样定案意味着：横划起手第一帧的纵向噪声即可判 fail、手势当场死亡。单独看，它只损失一次滑动；但与嫌疑 1 叠加时后果放大——落定动画在飞时的一次横划被噪声判 fail，`onEnd` 不触发而 `onFinalize` 缺席，progress 冻死；与嫌疑 2 叠加时，它是「中途自杀」的触发采样来源之一。
- 处置口径：fail 判定加去噪——多采样确认（连续多个采样或时间窗口内 dy 持续占优）后再定案，具体窗口结合 RNGH 原生语义实测定（波 4c 定案）。

### 嫌疑 5（补齐登记）：PERF-DX 的「动画中点翻转 isOpen」嫌疑——B/C 世代已排除

- A 世代确有动画中点（progress 过 0.5）经 `useAnimatedReaction` 翻转 isOpen 的形态；B/C 世代 isOpen 只在落定时同步，本嫌疑在当前世代不成立，排除（V3 核查同判）。

## 二、根因排序（补齐）

1. **主因 · 嫌疑 1**：落定动画可被任意落指 `cancelAnimation` 打断、而手势未激活/被判 fail 时无 `onFinalize` 收口——唯一能解释「冻在半开、状态与视觉脱节、且只在在飞窗口内触摸才中招（与『时不时』吻合）」的机制，C 世代回归引入。
2. **次因 · 嫌疑 2**：仲裁无「已激活」防护，拖动中途可被自己的 fail 判定杀掉——字面意义的滑动中途卡手（原生侧是否受理待装机证，防御修法无条件正确）。
3. **次因 · 嫌疑 4**：FAIL_DY=12 单采样无去噪——既是独立误判源，又是嫌疑 1/2 的触发器。
4. **体感项 · 嫌疑 3**：14dp 激活死区 + 激活瞬间跳变——不「卡死」但制造顿挫，全世代通病。

（旁证：I-N1 主页约 8px 异层露边与嫌疑 1 同源——静止残值只能来自手势中断后 progress 停在中间值，被一轮完整抽屉开合归零；V3 已实证此归因路径。）

## 三、修复方案（补齐，与《系统性解决方案》波 4c 定案一致）

1. **补 `onFinalize` 收口**：手势未激活结束/被判 fail 时，未落定的 progress 按 `drawerReleaseTarget` 就近落位（送回 0/1）；与 `onEnd` 防双重收口（只认先到者）。收口用例同批进抽屉手势测试套件。
2. **`onTouchesMove` 仲裁加「已激活即不再判定」防护**：激活后触摸流只走 `onUpdate`，不再执行 fail/activate 判定。
3. **fail 判定去噪**：多采样确认后再定案（窗口由施工方结合 RNGH 原生语义实测定）。
4. **激活跳变修正**：progress 换算扣除激活偏移（`translationX` 先减 ACTIVATION_DX 的有向分量再换算），与上两项同批。
5. **I-N1 同批核查**：静止态主层变换残值——若来自落定未收口，与第 1 项同源同批；若来自初始进度值/恢复路径，单列修法。
6. **明确不动**：提交阈值口径（COMMIT_TRAVEL 0.25、FLING ±400 双向，wave 3 用户定案）；「手到即停」设计意图本身（问题在缺收口，不在即停）。

## 四、验证方法（补齐）

1. **装机定向复现**（修复前应可复现、修复后应消失）：抽屉落定动画在飞（开/合均测）时落指滚动主列表 → 观察是否冻在半开位；轻扫开抽屉后立即抓列表滚动同理。
2. **慢速斜向拖动态**：验证嫌疑 2 的中途 fail 是否发生（兼验 RNGH 激活后 `onTouchesMove` 是否仍回调的原生语义问题）。
3. **手感对照**：激活瞬间位移连续性（录屏逐帧看激活帧是否跳变）；去噪后横划起手成功率。
4. **性能对照**：修复后 gfxinfo 与 I-P 基线（jank 6.07%、p99 150ms、高输入延迟 8,444 次）对照，确认收口未引入新的帧损。
5. **测试面**：抽屉手势套件含 `onFinalize` 收口新用例全绿；相关守卫不回退。
