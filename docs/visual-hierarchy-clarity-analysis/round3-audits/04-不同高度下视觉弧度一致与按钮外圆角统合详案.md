## 1. 背景与用户痛点原声深度对账

### 1.1 用户原声与核心诉求

### 1.2 现状视觉割裂的现场表现（图二深度穿透）

## 2. 深度根因穿透：混乱为何持续滋生？

### 2.1 根因一：Token 别名映射漂移陷阱（`--radius-md` 假 8px）
查看 `apps/crish-desktop/src/styles/tokens-radius.css:40-59` 的真实映射定义：
```css
/* [WAVE2-DEPRECATED-ALIAS] 旧圆角尺寸梯度别名桥接层 */
--radius-xs: var(--radius-row);     /* 6px */
--radius-s:  var(--radius-row);     /* 6px */
--radius-sm: var(--radius-row);     /* 6px */
--radius-md: var(--radius-row);     /* 6px ⚠️ 核心陷阱！ */
--radius-m:  var(--radius-row);     /* 6px */
--radius-btn: var(--radius-control); /* 8px */
--radius-input: var(--radius-control); /* 8px */
--button-radius: var(--radius-control); /* 8px */
--radius-lg: var(--radius-control); /* 8px */
```
- **开发者直觉**：业界常规设计系统（如 Tailwind / Radix）中 `md` 通常对应 8px。开发者在编写 `Sidebar.module.css` 时，习惯性写下 `border-radius: var(--radius-md, 8px)`；
- **运行时真相**：浏览器读取 CSS 变量时，由于 `--radius-md` 存在有效定义，Fallback `8px` 被完全丢弃，实际生效的是 `--radius-row`（**6px**）！
- **后果**：本意想做 8px 微圆，结果运行时全部被缩水压至 6px！导致用户敏锐地指出：“我看圆角还更小了呢，还没上一版的圆角大呢！”

### 2.2 根因二：局部重构中“滥用 50% 正圆”过度补偿
- 在历史解决“方块太生硬、角弧打架”的局部修复中，部分开发者走到了另一个极端：将独立按钮随手写上 `border-radius: 50%`（如 `UnitChromeActions.module.css:177` 的 `.topActionBtn`、`ChatComposer.module.css:257` 的 `.plusBtn`）；
- 这一局部补丁违背了**工具栏按钮的网格对齐纪律（Grid Discipline）**。正圆（Circle）在排版视觉上具有强烈的发散感和向心感，适合作为浮动动作靶点（Floating Action Button）或头像；但在密集水平工具条（Toolstrip）中，多个正圆按钮并排会出现“排珠（Bead String）”效应，彻底破坏顶栏的水平视线基准。

### 2.3 根因三：金标基准 `_assistantMeta_` 的物理与几何本质解构
为什么用户觉得 `_assistantMeta_` 内部的按钮最舒服？
查看 `ChatMessageRow.module.css:985-1013`：
```css
.iconBtn,
button.iconBtn {
  width: 28px;
  height: 28px;
  min-width: 28px;
  max-width: 28px;
  padding: 0;
  --btn-px: 0px;
  --btn-h: 28px;
  --btn-icon-size: 16px;
  border-radius: var(--button-radius, 7px); /* 运行时映射为 8px */
  color: var(--text-tertiary);
  background: transparent;
  ...
}
```
1. **尺寸标尺**：严格对齐 `--row-h-list: 28px`；
2. **倒角数值**：`var(--button-radius)` = `var(--radius-control)` = **8px**；
3. **曲率比例系数**：
   $$k = \frac{R}{H} = \frac{8\text{px}}{28\text{px}} \approx 28.57\%$$
4. **几何感知**：
   - 当 $k < 20\%$ 时，角点残留明显棱角，视觉感知为“工业硬方块”；
   - 当 $k > 40\%$ 或 $50\%$ 时，四边平直段严重收缩，视觉感知为“圆球/药丸”；
   - 当 $k \in [25\%, 30\%]$ 时，矩形的平直边段（Straight Segments）与四角平滑转折曲线（Smooth Tangent Arcs）达成完美的视觉张力平衡，呈现出如 macOS Sequoia 顶栏图标或 iOS 系统级控件的 **Smooth Squircle（平滑方圆）** 质感！

## 3. 【不同高度下视觉弧度一致性】数学体系与设计规范

用户深刻指出：“不要以我认可的，你需要制定不同高度下的，视觉弧度一致的方案才行。”  
要彻底告别“拍脑袋定圆角”，必须建立严密的**视觉等弧度曲率模型（Visual Equivalent Curvature Model）**。

### 3.1 视觉等弧度曲率模型（Visual Equivalent Curvature）
人眼在观察不同尺寸的带圆角控件时，所感知到的“圆润程度”（Curvature Intensity）并不取决于绝对半径 $R$ 的毫米数，而是取决于**角弧半径与控件主体尺寸的相对比例系数 $k$**：
$$k = \frac{R}{H} \quad (\text{其中 } H \text{ 为控件物理高度或短边长})$$

为了确保在不同界面层级（密集行、标准工具栏、大型控制卡片）下，用户视线扫过时感受到**完全一致的视觉弧度韵律**，全应用统一裁定基准曲率系数：
$$k_{\text{target}} \approx 25\% \sim 30\% \quad (\text{金标基准系数 } k_0 = \frac{8}{28} \approx 28.6\%)$$

### 3.2 4 档高度标准化映射标尺（SSOT 契约）

根据 $R = \operatorname{round}(H \times k_0)$，并结合 2px 物理像素网格对齐，全仓严密确立以下 4 档控件圆角标尺：

| 规格档位 | 物理高度 $H$ | 目标曲率 $k$ | 计算半径 $H \times k$ | 最终裁定圆角 $R$ | 对应 Design Token | 适用交互基元典型场景 |
|---|---|---|---|---|---|---|
| **Tier 1: Dense (紧凑级)** | **20px ~ 24px** | $25\% \sim 29\%$ | $5.0 \sim 6.9\text{px}$ | **6px** | `--radius-row` | 24px 面包屑项目名按钮、标签页关闭钮背景、微型属性 Badge |
| **Tier 2: List (列表级)** | **26px ~ 28px** | $28.5\% \sim 30.7\%$ | $7.4 \sim 8.0\text{px}$ | **8px** | `--radius-control` | **`_assistantMeta_` 动作钮、标签栏新建 `+` 钮、顶栏右侧工具钮、输入坞加号钮** |
| **Tier 3: Control (控件级)**| **32px** | $25.0\%$ | $8.0\text{px}$ | **8px** | `--radius-control` | 侧栏顶部折叠按钮（32px）、标准输入框、表单次级按钮 |
| **Tier 4: Chrome (壳层级)** | **36px ~ 40px** | $25\% \sim 30\%$ | $9.0 \sim 12.0\text{px}$ | **10px ~ 12px** | `--radius-card` | 浮层快捷菜单项、大号主操作按钮、独立卡片容器 |

> **关键定理（Theorem of Control Unification）**：  
> 处于 Tier 2（28px）与 Tier 3（32px）的日常最高频操作按钮，其曲率比分别为 $8/28 \approx 28.6\%$ 与 $8/32 = 25.0\%$，均严格处于黄金比例区间 $[25\%, 30\%]$ 内。因此，**8px（`--radius-control`）是全仓 28px~32px 图标按钮唯一的数学最优真解**！

### 3.3 严格的几何分类与 50% 正圆白名单制度
为杜绝 50% 正圆的无序蔓延，建立严格的白名单准入规则：

```
                    ┌──────────────────────────────┐
                    │      界面元素圆角分类裁判      │
                    └──────────────┬───────────────┘
                                   │
              ┌────────────────────┴────────────────────┐
              ▼                                         ▼
   【白名单场景（允许 50% / Pill）】          【常规交互基元（严格遵循 8px 标尺）】
   1. 语义药丸（Model Pill、状态 Badge）       1. 顶栏所有快捷动作按钮（浏览器/文件/更多）
   2. 饱满用户头像（Avatar 26/32px）          2. 侧栏顶部折叠展开按钮
   3. 嵌套长胶囊内的行内点（会话条快捷钮）       3. 标签栏新建标签 `+` 按钮
   4. 微型角标状态点（在线/更新脉冲点）         4. 底部输入坞附件 `+` 按钮、取消按钮
                                              5. 面包屑项目名等文字按钮（降回 6/8px）
```
