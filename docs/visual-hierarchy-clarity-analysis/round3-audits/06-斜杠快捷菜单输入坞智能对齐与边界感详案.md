## 一、 现状还原与视网膜病理排查

### 1.1 视觉现场病理还原
在 Conex / Crish 桌面工作台中，斜杠快捷菜单（`TiptapSlashMenu`）承担着用户输入 `/` 触发 AI 系统指令（如 `/clear`、`/stop`、`/settings`）及个人 Skills 命令的核心交互入口。
根据现场视网膜证据与用户真实反馈（“以及连智能对齐也没有昂，这个也需要补充完善”、“好像是有智能对齐，但是体验上可能不好。梳理一下，继续改就行了”），斜杠弹层存在显著的视觉割裂与对齐脱靶问题：

```
+---------------------------------------------------------------------------------------------------+
|  Chat Stream Message Column (chatCol, width ≈ 720px, left = 111px)                                |
|                                                                                                   |
|                                       [ 病理态：斜杠快捷菜单 (窄条) ]                             |
|                                       x=248px 突兀冒出，宽度仅约 320px~480px                       |
|                                       +-----------------------------------+                       |
|                                       | /clear  清空当前会话              |                       |
|                                       | /stop   中断当前模型推理          |                       |
|                                       | /skill  个人技能...               |                       |
|                                       +-----------------------------------+                       |
|                                                                                                   |
|  [ 主输入坞卡片 (Composer Card, width = 720px, left = 111px) ]                                    |
|  +---------------------------------------------------------------------------------------------+  |
|  | [＋] [Auto Approve] | /                                             | [Model Badge] [Send] |  |
|  +---------------------------------------------------------------------------------------------+  |
|  |<--- 137px 空悬隙 --->|                                                                         |
+---------------------------------------------------------------------------------------------------+
```

对比用户期望的理想设计（ChatGPT Work / Claude 沉稳浮动指令坞）：
1. **水平基线脱节**：输入卡片和对话流的整体左边框位于 `x = 111px`，但弹层的左边框却漂移到了 `x = 248px`，左侧出现了宽达 **137px** 的巨大空白断层（恰好位于加号按钮与权限选择菜单的正上方，完全悬空）。
2. **宽度急剧萎缩**：弹层没有与输入坞卡片实现同宽饱满咬合，而是萎缩为窄条（`width ≈ 320px~480px`），孤立悬挂在卡片偏右位置，产生强烈的“局部小气泡”、“脱水失重感”。
3. **圆角与边界感断裂**：
   - 现存 `TiptapSlashMenu.module.css` 中的外圆角采用 `--radius-card`（16px）或退化值，内条目采用 `--sep-item-radius`（8px），与新版输入坞的 `--radius-dock: 21px` 缺乏同心半径对应关系（Concentric Radius Gap）；
   - 边框仅使用 `var(--border-color)`，缺乏高质感浮层特有的双层微边缘（Double-Rim: `--surface-card` + `--edge-rim`），在暗色模式下与编辑器背景融为一团，缺乏明确的纵深立体边界感。

### 2.2 关键代码断点实证与数据推导

#### 1. 为什么 `left` 偏偏精准地落在了 `x = 248px`？
通过查阅 [`ChatComposer.module.css:151-177`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/ChatComposer.module.css#L151-L177)：
```css
/* 单行模式：左侧控制组、中间输入框、右侧动作组 */
.composerCard:not(.isMultiline) .inputMainLayout {
  grid-template-areas: 'left-ctrl text actions';
  grid-template-columns: auto minmax(0, 1fr) auto;
  column-gap: 6px;
}
```
结合输入坞的物理测量：
- 主输入卡片 `composerCard`（`data-composer-card`）在主列 `chatCol` 居中，左边缘为 **111px**；
- 卡片内部内衬 `padding-left` 为 **10px**（`--composer-pad-x-start`）；
- 左侧操作槽 `.actionLeft` 包含：加号按钮 `.plusBtn`（**32px**）+ 权限模式胶囊 `.permissionModeBtn`（约 **85px**）+ 内部间隙（**4px**）= **121px**；
- 主网格列间隙 `column-gap` 为 **6px**；
- 中间输入槽 `.fieldSlot` 及内部的 `.input-container` 的物理左坐标为：
  $$\text{Left} = 111\text{px} + 10\text{px} + 121\text{px} + 6\text{px} = \mathbf{248px}!$$

#### 2. `SlashExtension.ts:173-196` 为何落入陷阱？
```typescript
// apps/crish-desktop/src/components/chat-composer/SlashExtension.ts:173-176
const cardEl =
  (view.dom?.closest('[data-composer-card]') as HTMLElement | null) ||
  (ctx.containerRef?.current as HTMLElement | null);
```
- **病因 A（`closest` 的偶发断裂）**：在 Tiptap Suggestion 初次挂载或更新事务中，ProseMirror 视图的 `view.dom` 在 React 渲染周期中尚未完全 attach 到文档树，或者在无外层主卡片的宿主环境下，`closest('[data-composer-card]')` 容易求值为 `null`；
- **病因 B（`containerRef` 的致命误绑）**：在 [`TiptapComposerField.tsx:352-358`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/TiptapComposerField.tsx#L352-L358) 中，`containerRef` 竟然被绑在了：
  ```tsx
  <div ref={containerRef} className="input-container" data-composer-field="1">
  ```
  它代表的只是 `fieldSlot` 内部的输入字段，完全不是卡片整体！回退到 `ctx.containerRef.current` 瞬间使得 `cardRect.left` 被污染成了 **248px**！
- **病因 C（光标测量与魔术数字）**：若两层均失败回退至 `calculateSafeCursorAnchor`（[`safeCursorAnchor.ts:205-228`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/safeCursorAnchor.ts#L205-L228)），光标测量的坐标同样是用户输入 `/` 处的文字物理坐标（**248px**），其宽度为光标宽度（**2px**）。而在 [`TiptapSlashMenu.tsx:387-390`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/TiptapSlashMenu.tsx#L387-L390)：
  ```tsx
  style={{
    width: anchor && anchor.width >= 48 ? `${Math.round(anchor.width)}px` : undefined,
  }}
  ```
  `anchor.width >= 48` 是硬编码魔术数字！当 `anchor.width = 2` 时条件不满足，`style.width` 被置为 `undefined`，弹层宽度彻底失控，被内容撑成狭窄的 320px，且由 `align="start"` 钉死在 `x = 248px`！

## 三、 智能锚定与视觉边界重构方案

### 3.1 架构设计思想：输入坞单一真理源（Composer-Level SSOT）
斜杠快捷菜单不是单字符的行内拼音候选条，而是**会话操作台的核心级指令坞**。
必须在架构层面确立：**无论光标在单行输入框的何处游走，斜杠快捷菜单始终以主输入卡片（`[data-composer-card]`）为水平居中与宽度咬合的唯一几何真理源！**

```
+---------------------------------------------------------------------------------------------------+
|  Chat Stream Column (chatCol)                                                                     |
|                                                                                                   |
|  [ 改造后：斜杠快捷菜单 (饱满指令坞) ]                                                            |
|  x = 111px, 宽度 = 720px 与输入卡片完全对齐！外圆角 18px，内条目 12px，双层立体边缘             |
|  +---------------------------------------------------------------------------------------------+  |
|  | [Icon] /clear    清空当前会话                                                               |  |
|  | [Icon] /stop     中断当前模型推理                                                           |  |
|  | -- 技能 ---------------------------------------------------------------------------------- |  |
|  | [Icon] /skill:review  代码评审专家                                              [个人]      |  |
|  +---------------------------------------------------------------------------------------------+  |
|  | ↕ 8px 精确正向安全间距                                                                       |
|  +---------------------------------------------------------------------------------------------+  |
|  | [＋] [Auto Approve] | /                                             | [Model Badge] [Send] |  |
|  +---------------------------------------------------------------------------------------------+  |
|  [ 主输入坞卡片 (Composer Card, width = 720px, left = 111px) ]                                    |
+---------------------------------------------------------------------------------------------------+
```

### 3.2 几何锚定与对齐规则
1. **多重备援卡片探测器（Card Rect Resolver）**：
   - **Level 1**：显式注入的 `cardRef`（由 `ChatComposer.tsx` 挂载在主卡片根节点上）；
   - **Level 2**：`view.dom?.closest('[data-composer-card]')`（DOM 祖先遍历）；
   - **Level 3**：`view.dom?.closest('[data-composer-wrapper]')` 或外层 `[data-composer-dock]`；
   - **熔断保护**：绝不允许使用中间文本字段 `.input-container`（left=248px）作为卡片位置回退。
2. **水平中轴对齐与宽度弹性**：
   - 锚点包围盒宽度设为卡片物理宽度：`width = cardRect.width`；
   - 锚点左边界设为卡片物理左边界：`left = cardRect.left`；
   - `Popover.Content` 设置 `align="center"` 或 `align="start"`（当二者同宽时表现一致），通过 `--chat-column-width` 自动实现大屏适配与居中；
   - 垂直方向：通过 `side="top"`、`sideOffset={8}`、`avoidCollisions={true}`，确保在输入坞上方恰好 8px 处整齐升起，空间不足时优雅翻折至下方。

### 3.3 视觉拓扑与 Token 契约重构
严格遵守无魔术数字、纯 Token 驱动的视觉规范：

| 元素 | 现存病理值 | 重构后设计规范 | 说明 |
| :--- | :--- | :--- | :--- |
| **外层容器圆角** | `16px`（`--radius-card`） | **`var(--radius-slash, 18px)`** | 介于卡片（21px）与菜单之间，形成饱满而有机的层级围合 |
| **内部条目圆角** | `8px`（`--sep-item-radius`） | **`var(--radius-slash-item, 12px)`** | 满足 $R_{\text{inner}} = R_{\text{outer}} - \text{padding}$ 的同心几何美学（$18px - 6px = 12px$） |
| **背景色** | `var(--bg-elevated)` | **`var(--surface-card, var(--bg-elevated))`** | 与新版系统统一的高阶卡片表面色 |
| **边缘轮廓** | 单层 `1px solid var(--border-color)` | **`1px solid var(--edge-rim, var(--border-subtle))`** | 消除粗糙灰框，暗色模式下拥有微发光精细边界 |
| **阴影** | `box-shadow: none` | **`var(--shadow-lift-card)`** | 克制柔和的立体微阴影（混入比 ≤ 4%），摆脱苍白悬浮感 |
| **内边距** | `padding: 6px` | **`padding: 6px 8px`** | 横向间隙更舒展，文字不贴边 |

### 4.4 `apps/crish-desktop/src/components/chat-composer/SlashExtension.ts`
**目的**：重构 `clientRect` 卡片几何提取逻辑，消除 248px 回退陷阱。

- **行号区间**：`L95-L105`、`L121` 与 `L171-L196`
- **修改详情**：
  ```typescript
  // 1. 在 SlashExtensionOptions 与 SuggestionRenderCtx 扩充 cardRef
  export interface SlashExtensionOptions {
    extraItemsRef?: { current: SlashCommandItem[] };
    listboxId?: string;
    containerRef?: { current: HTMLElement | null };
    cardRef?: { current: HTMLElement | null };
  }

  // 2. clientRect 内部几何解析升级
  clientRect: () => {
    const view = props.editor?.view;
    if (!view || !props.range) return lastCachedBox;

    if ((view.composing || (view as any).input?.composing) && lastCachedBox)
      return lastCachedBox;

    try {
      // 优先级 1: 显式注入的 cardRef 引用
      // 优先级 2: DOM 向上寻找最近的 [data-composer-card]
      // 优先级 3: 外层 [data-composer-wrapper] 容器
      const cardEl =
        (ctx.cardRef?.current as HTMLElement | null) ||
        (view.dom?.closest('[data-composer-card]') as HTMLElement | null) ||
        (view.dom?.closest('[data-composer-wrapper]') as HTMLElement | null);

      if (cardEl && typeof cardEl.getBoundingClientRect === 'function') {
        const cardRect = cardEl.getBoundingClientRect();
        if (cardRect.width > 0 && cardRect.height > 0) {
          const extendedRect = Object.assign(
            new DOMRect(
              cardRect.left,
              cardRect.top,
              cardRect.width,
              cardRect.height
            ),
            {
              suggestedSide: 'top' as const,
              nearEdge: false,
              isFallback: false,
              isValid: true,
            }
          );
          lastCachedBox = extendedRect;
          return lastCachedBox;
        }
      }

      // 仅在完全脱离卡片场景（如纯单测极端脱水状态）才使用光标测量作为备援
      const rawBox = measureCursorLineBox(view, props.range.from, 1);
      // ...
    } catch {
      return lastCachedBox;
    }
  }
  ```
