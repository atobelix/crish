# 领域 5 详案：全局浮层外大圆角 18px 与内同心 12px 几何工程详案

> **方案定位**：彻底根治用户反馈的“圆角比上一版更小”、“斜杠快捷键 r 角不够圆、内外圆角没统一”、“缺少大圆角高级质感”等核心痛点。重构全局浮层菜单几何体系，确立以 **外大圆角 18px + 边距 6px + 内同心 12px** 为核心的现代桌面端浮层视觉标杆。  
> **上位依据**：`AGENTS.md` §1（反退避）、§11（CI 治理）、`P4-容器基元与圆角描边语言.md`、`concentric-radius.contract.test.ts`。  
> **实施原则**：数学严密（$R_{\text{inner}} = R_{\text{outer}} - \text{Padding}$）；Token 单源（SSOT）；清除 Dead Fallback；消除过度束缚。

### 1.2 根因穿透：Token 降级死循环与 Dead Fallback

#### 1. Token 级一刀切降级死循环
在提交 `7b3fc38d78`（BATCH-VH-W1 实施阶段 P4：容器基元与圆角描边语言）中，为了收敛全仓圆角为“5 档角色”，在 `apps/crish-desktop/src/styles/tokens-radius.css` 中做了如下硬性别名绑定：
```css
/* apps/crish-desktop/src/styles/tokens-radius.css */
--radius-card: 12px;
...
--sep-radius-outer: var(--radius-card); /* 强行降格绑定到 12px！ */
```
而在 `apps/crish-desktop/src/styles/tokens-components.css` 中：
```css
/* apps/crish-desktop/src/styles/tokens-components.css */
--sep-item-radius: var(--radius-row); /* 强行降格绑定到 6px！ */
```
`--sep-radius-outer` 和 `--sep-item-radius` 本是全仓所有浮层（SmartPanel、Menu、PlusMenu、SlashMenu、ContextMenus）共享的基准尺寸。当这两个变量被硬生生压低到 12px 和 6px 时，下游所有组件被无差别一键压扁。

#### 2. CSS 变量 Fallback 沦为“死代码（Dead Fallback）”
下游业务组件的开发者深知浮层需要大圆角，因此在编写样式时，通常保留了较大的回退声明：
- `TiptapSlashMenu.module.css:10`: `--slash-radius-outer: var(--radius-card, 16px);`，`--slash-radius-inner: var(--sep-item-radius, 8px);`
- `SidebarContextMenus.module.css:6`: `border-radius: var(--sep-radius-outer, 14px);`
- `SmartExpandablePanel.module.css:12`: `border-radius: var(--sep-radius-outer, 14px);`

然而，**根据 W3C CSS Custom Properties 规范**：只要变量在 `:root` 或任何祖先节点被声明过（哪怕值被赋为 12px），浏览器就绝对**不会执行逗号后面的 fallback**！
因此，开发者手写期望的 16px、14px、8px 回退值变成了 **100% 无法触达的死代码**，所有浮层外圆角被强行封死在 12px，内圆角被死死封锁在 6px！

#### 3. 浮层菜单（Overlay）与页面内容卡片（Card）的语义角色混淆
在 P4 设计中，把所有容器强行归并为 5 档：`row (6px)`、`control (8px)`、`card (12px)`、`dock (20px)`、`pill (9999px)`。
这漏掉了桌面端一个极重要的容器角色：**浮层菜单容器（Flyout Menu / Overlay）**。
浮层菜单处于最高层景深（z-index 300~500），悬浮于阴影之上，面积小巧（180px~300px）。若强制套用页面内容卡片的 12px 方圆角，整体观感必然显得生硬、拘谨、缺乏现代流体感。

## 2. 浮层现代几何规范：外大圆角 18px 与内同心 12px 黄金体系

### 2.1 同心圆几何公理（Concentric Geometry Axiom）
在具有嵌套圆角和边距的视觉设计中，内圆角与外圆角必须共享同一个圆心（Concentric Arcs），才能消除视觉对抗与边缘厚度不均。
数学公式为：
$$R_{\text{inner}} = R_{\text{outer}} - \text{Padding}$$

```
╭─────────────────────────────────────────────────────────────────────────╮  ▲
│                                                                         │  │
│    ╭───────────────────────────────────────────────────────────────╮    │  │ Padding = 6px
│    │  [Icon]  菜单项条目高亮态 (Hover Item)                        │    │  │
│    ╰───────────────────────────────────────────────────────────────╯    │  ▼
│    R_inner = 18px - 6px = 12px                                          │
╰─────────────────────────────────────────────────────────────────────────╯
◀─────────────────────────── R_outer = 18px ─────────────────────────────▶
```

### 2.2 核心参数黄金比例裁定
1. **外容器圆角（$R_{\text{outer}}$）锁定为 `18px`**：
   - 参考 macOS Sonoma/Sequoia、Raycast、Linear 等标杆桌面端产品，浮层容器外圆角均在 16px~20px 之间；
   - 18px 是容纳阴影弥散（`box-shadow: var(--shadow-lg)`）与界面留白的黄金平衡点，既温润如玉、从容饱满，又绝不拖沓。
2. **容器内边距（$\text{Padding}$）恒定保持 `6px`**：
   - 6px 是桌面端兼顾视觉紧凑与呼吸感的最优物理内衬，既避免了 4px 的贴边紧绷，又杜绝了 8px/10px 的松垮空旷。
3. **内部条目圆角（$R_{\text{inner}}$）精准匹配为 `12px`**：
   $$R_{\text{inner}} = 18\text{px} - 6\text{px} = \mathbf{12px}$$
   - 在 28px~32px 的条目物理高度下，12px 圆角呈现出极其优美的弧度。在圆角转折处，外壳圆弧与条目高亮圆弧间隙恒定为 6px（等宽物理光圈），彻底根除“外圆内方”或“转角变厚”的畸变。
4. **条目排版紧凑化收紧**：
   - 选项上下 padding 统一收紧至 **`3px ~ 5px`**，条目高度保持在 **`28px ~ 32px`**；
   - 解决通用 `Menu.module.css` 历史遗留的 `8px 10px` 虚胖边距，单屏垂直展示项数提升约 25%~30%，大幅改善长菜单浏览效率。
