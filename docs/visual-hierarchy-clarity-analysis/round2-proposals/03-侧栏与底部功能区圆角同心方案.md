# 方案 03：侧栏与底部功能区圆角同心与操作按钮正圆化方案

> **方案定位**：针对 Round 2 用户在实际体验中反馈的两处致命圆角断裂（图 2 会话项快捷按钮不同心、图 3 底部功能区左大右小割裂），编制端到端的彻底重构详案。  
> **上位依据**：`00-总方案.md`、`P4-容器基元与圆角描边语言.md`、`P7-外壳与侧栏.md`、`01-实施状态台账.md`。  
> **实施原则**：严禁打补丁、严禁魔术数字、严禁局部样式特判；穿透几何本质，基于同心数学公理与 Design Token SSOT 实现视觉与工程的净收敛。

## 1. 背景与用户痛点原声对账

在最新的视觉验收中，用户指出了侧边栏区域存在两处极为刺眼的几何撕裂与圆角不一致问题：

### 1.1 痛点 1（图 2 现场对账）：会话列表项快捷按钮圆角不同心
> **用户原声**：“消息列表的圆角以及三个快捷按钮对应的背景圆角，我看好像也没对齐吧。”

- **现状现象**：
  - 侧栏单行会话项（`.sessionItem`）采用高度 **28px** 的大圆角条（`border-radius: var(--radius-lg);`，视觉呈现为大胶囊感）；
  - 鼠标悬停在会话项上时，右侧悬浮浮现 3 个快捷操作按钮（置顶、归档/分屏、更多操作 `...`）；
  - 当鼠标进一步悬停在某个快捷按钮上时，按钮背后弹出一个 **8px 小圆角矩形**背景（`.sessionActionsBtn` 中手写了 `border-radius: var(--radius-md, 8px);`）；
- **视觉冲突与几何破裂**：
  - **内外圆角严重不同心**：长胶囊外框包裹着 8px 小圆角矩形，内外轮廓的曲率半径、圆心坐标完全脱节；
  - **边缘挤压生硬**：快捷按钮高度达 24px/26px，在 28px 的会话条内上下仅留 1~2px 缝隙，矩形底色一出现就像在胶囊条里强行贴了一个方补丁，极其突兀生硬。

### 1.2 痛点 2（图 3 现场对账）：底部功能区左大右小两种圆角割裂
> **用户原声**：“第三个是一个功能区，出现两种圆角，应该改成圆角比较大的那种。”

- **现状现象**：
  - 侧栏底部底栏（`.sidebarFooter`）由左右两列组成：

  - **同一功能区两种截然不同的曲率并存**：左右两个控件在视觉上属于同一视觉层级（都是侧栏底部基础功能控件），物理高度一致（均为 32px），但在几何语言上却一圆一扁、一柔一硬，形成了明显的“左侧是大胶囊、右侧是小方块”的视觉撕裂。

## 2. 根因穿透与几何断层深度分析

### 2.1 痛点 1 根因：长胶囊容器与小圆角矩形动作点的几何悖论

#### 1. 同心圆数学公理的失效
在平面几何与设计工程中，两个嵌套的同向同轴圆角矩形若要实现“同心（Concentric）”，必须严格满足同心方程：
$$R_{\text{inner}} = R_{\text{outer}} - \text{Padding}$$
当父容器是高度 28px、两端饱满圆弧的会话胶囊（$R_{\text{outer}} \approx 14\text{px}$）时，若内部快捷按钮也是矩形：
- 上下 padding 仅为 $2\text{px}$（若按钮为 24px），按方程计算 $R_{\text{inner}} = 14 - 2 = 12\text{px}$；
- 左右两端由于按钮横向并排（共 3 个按钮），无法均匀维持 2px 的全向 padding；
- 现行代码却直接硬套了一个通用控件的 `--radius-md`（8px）。这导致内层角曲率（8px）与外层角曲率（14px）的同心圆弧度差高达 $14 - 8 = 6\text{px}$，在人眼中呈现出明显的“角点不同轴”、“内外圆心漂移”。

#### 2. 尺寸定义双源冲突（CSS 26px vs TSX 24px）
- 在 `SidebarSessionList.module.css:631-636` 中：
  ```css
  .sessionItem .sessionActionsBtn,
  .sessionActionsBtn {
    width: 26px;
    height: 26px;
    border-radius: var(--radius-md, 8px);
  }
  ```
- 在 `SessionRow.tsx:33-40` 中：
  ```typescript
  export const SESSION_ACTIONS_BTN_PX = 24;
  const ACTION_BTN_STYLE: React.CSSProperties = {
    width: SESSION_ACTIONS_BTN_PX, height: SESSION_ACTIONS_BTN_PX,
    ...
  };
  ```
- **后果**：TSX 内联样式（24px）与 CSS（26px）相互打架，且由于 CSS 中带有 `--btn-icon-size: 14px` 与 `border-radius: var(--radius-md, 8px)`，导致在不同渲染阶段尺寸和圆角呈现不稳定，加剧了不自然感。

---

### 2.2 痛点 2 根因：历史局部特判破坏了底部几何统一性

查看 `Sidebar.module.css:307-313` 的真实源码：
```css
/* 侧栏设置按钮统一为 8px 微圆图标卡片 */
.footerGearCol :global(.icon-button),
.footerGearCol button {
  --btn-radius: var(--radius-md);
  border-radius: var(--radius-md);
}
```
- **根因溯源**：在历史重构中，开发者误以为右侧设置按钮作为独立图标按钮，应当遵循普通控件的 8px 圆角规范，于是针对 `.footerGearCol` 增加了一条强行降级的局部覆盖规则；
- **忽略了并列关系**：左侧 `UserProfileCard` 高度为 32px，声明为 `border-radius: var(--radius-xl, 16px);`（即两端半径正好等于高度一半 $32 / 2 = 16\text{px}$，形成饱满胶囊）；右侧设置按钮的尺寸为 32×32px。当用户视线扫过底栏时，直接看到一个 32px 胶囊与一个 32px 紧绷小方块挤在 8px 间距内，瞬间产生不协调感。

## 3. 重构方案一：会话列表项快捷按钮正圆化（Circle Unification）与几何居中

### 3.1 正圆化几何原理（Circle Unification Principle）
- **为什么必须是正圆（Circle, 50%）**：
  1. **脱离角曲率冲突**：在长条形或胶囊型容器内部，任何带有小圆角矩形（Rounded Rect）的悬停背景都会因“矩形嵌套矩形”而触发人类视觉对角弧度平行的严苛审视；
  2. **正圆的全向各向同性（Isotropic）**：正圆（$R = 50\%$）在所有方向上的曲率恒定，它在视觉上被大脑归类为**独立的浮动动作靶点（Floating Action Target）**，天然与长条容器的矩形外框解耦；
  3. **业界前沿实践对齐**：无论是 macOS 侧栏、Telegram、Discord 还是 Linear、Raycast，列表项尾部的快捷图标按钮悬停背景统一采用**正圆形**，营造出如水滴般的轻盈呼吸感。

```
【改造前：大胶囊套小方块（角弧打架）】
╭─────────────────────────────────────────────────────────────╮
│ 会话标题文字...                   [ 8px方块 ] [ 8px方块 ] [ 8px方块 ] │
╰─────────────────────────────────────────────────────────────╯

【改造后：大胶囊内嵌正圆动作点（优雅呼吸、同轴居中）】
╭─────────────────────────────────────────────────────────────╮
│ 会话标题文字...                     ( 24正圆 )  ( 24正圆 )  ( 24正圆 )  │
╰─────────────────────────────────────────────────────────────╯
  ↑ 行高 28px                         ↑ 24×24px 正圆，上下留白各 2px，垂直完美居中
```

### 3.2 尺寸规格裁决：统一为 24×24px

- **尺寸比选表**：
  | 规格 | 宽×高 | 28px 行高下的垂直留白 | 优点 | 缺点 | 裁定结果 |
  |---|---|---|---|---|---|
  | **22×22px** | $22 \times 22\text{px}$ | 上下各 $3\text{px}$ | 留白更从容，精致感强 | 触控靶面稍小；需同步修改 TSX 常量与单测断言 | 备选 |
  | **24×24px** | $24 \times 24\text{px}$ | 上下各 $2\text{px}$ | 1. 与 `SessionRow.tsx` 常量 `SESSION_ACTIONS_BTN_PX = 24` 100% 契合，零测试破坏；<br/>2. 与侧栏分组头部的 `.folderMoreBtn`、`.sectionNew`（24×24px）保持全侧栏动作钮尺寸统一；<br/>3. 点击热区更大（符合 WCAG 靶面建议） | 上下留白 2px 需保证严格居中 | **★ 最终裁决** |

- **几何居中与布局参数**：
  - 会话行高度：`height: 28px;`
  - 按钮尺寸：`width: 24px; height: 24px; min-width: 24px; min-height: 24px;`
  - 按钮圆角：`border-radius: var(--radius-circle, 50%);`
  - 按钮间隙：`gap: 2px;`（微幅拉开 1px 至 2px，避免相邻两个正圆背景在 hover 时相撞）
  - 图标尺寸：
    - 置顶（`pin` / `pin-off`）：`size={14}`
    - 归档（`archive`）：`size={14}`
    - 更多（`more-horizontal`）：`size={16}`
  - 图标在 24px 正圆内采用弹性盒完全居中（`display: inline-flex; align-items: center; justify-content: center;`）。

### 3.3 交互动效与状态叠加
- **静止态**：按钮背景完全透明（`background: transparent;`），图标颜色为 `--text-tertiary`；
- **悬停态（Hover）**：
  - 背景注入 `--state-hover`（`background: var(--tint-hover, var(--state-hover));`）；
  - 图标提升为 `--text-primary`；
  - 过渡平滑：`transition: color var(--transition-micro), background-color var(--transition-micro);`；
- **按下态（Active）**：
  - 背景注入 `--state-active`（`background: var(--tint-active, var(--state-active));`）。

## 4. 重构方案二：底部功能区圆角彻底统合

### 4.1 核心动作：彻底拔除局部特判
在 `Sidebar.module.css` 中，将第 307~313 行的特判代码**物理删除**：
```css
/* 彻底删除以下错误特判 */
.footerGearCol :global(.icon-button),
.footerGearCol button {
  --btn-radius: var(--radius-md);
  border-radius: var(--radius-md);
}
```

### 4.2 统合为 16px 大圆角 / 正圆呼应
- **几何同心与曲率对称原理**：
  - 左侧 `UserProfileCard`：物理高度 $32\text{px}$，圆角 $R = 16\text{px}$，在视觉上两端呈现曲率半径为 $16\text{px}$ 的标准半圆弧；
  - 右侧 `SettingsIconButton`：尺寸为 $32 \times 32\text{px}$。
    - 当为其赋予 $R = 16\text{px}$（或 `50%` 正圆）时，它在几何上正好是一个**半径 $16\text{px}$ 的完美正圆**！
    - **视觉对称**：左侧胶囊的右端半圆（半径 16px），与右侧正圆按钮的左侧圆弧（半径 16px），在水平间距 8px（`--space-2`）的留白中形成**完全等同的同心弧线呼应**！彻底根除“一软一硬、一大一小”的割裂感。

```
【改造前：左胶囊 vs 右方块（曲率断裂）】
╭──────────────────────────────╮   ┌──────┐
│ (👤)  Developer              │   │  ⚙   │  ← 8px 硬方块（破坏底部视觉节奏）
╰──────────────────────────────╯   └──────┘
  ↑ 16px 饱满圆角胶囊 (高 32px)

【改造后：左胶囊 vs 右正圆（曲率同径 R=16px，完美呼应）】
╭──────────────────────────────╮   ╭──────╮
│ (👤)  Developer              │   │  ⚙   │  ← 32×32px 正圆 / 16px 大圆角，与左侧完全同径！
╰──────────────────────────────╯   ╰──────╯
  ↑ 16px 胶囊 (高 32px)              ↑ 16px 正圆 (高 32px)
```

### 4.3 底部更新提示按钮（`updateAvailable`）统合
当应用检测到新版本时，`.footerGearCol` 会在设置齿轮左侧渲染一个【更新】按钮：
- 现行代码使用 `Button variant="ghost" size="sm"`，默认继承普通按钮的 8px 圆角；
- **重构规范**：将该更新按钮同样设定为 **饱满胶囊圆角（`border-radius: var(--radius-pill, 9999px);` 或 `16px`）**，高度统一为 32px，与整行所有元素达成 100% 胶囊化统一。

### 4.4 侧栏折叠态（`iconCollapse`）的优雅自洽
当侧栏处于折叠状态（宽 48px）时：
- 左侧 `UserProfileCard` 折叠为 32×32px 的图标按钮；
- 右侧 `SettingsIconButton` 尺寸同为 32×32px，垂直排列于下方；
- **重构规范**：折叠态下两者同样统一为 **正圆（`50%` 或 `16px`）**，彻底消除折叠态下残留的 8px 小方块特判。

## 7. 自动化契约测试与防回归断言设计

### 7.1 新增静态契约测试用例（`sidebar-concentric-radius.contract.test.ts`）
在 `apps/crish-desktop/src/styles/` 或 `apps/crish-desktop/src/components/sidebar/__tests__/` 下增加契约守护：

```typescript
// @vitest-environment jsdom
import { describe, expect, it } from 'vitest';
import { readFileSync } from 'node:fs';
import { resolve } from 'node:path';

describe('侧栏与底部功能区圆角同心契约测试 (SIDEBAR-CONCENTRIC-RADIUS)', () => {
  const sidebarCssPath = resolve(__dirname, '../Sidebar.module.css');
  const sessionListCssPath = resolve(__dirname, '../SidebarSessionList.module.css');
  const sidebarCss = readFileSync(sidebarCssPath, 'utf8');
  const sessionListCss = readFileSync(sessionListCssPath, 'utf8');

  it('断言 1：.sessionActionsBtn 严禁包含 var(--radius-md) 或 8px，必须声明为正圆', () => {
    const btnMatch = sessionListCss.match(/\.sessionActionsBtn\s*\{[^}]+\}/);
    expect(btnMatch).toBeTruthy();
    const btnBlock = btnMatch![0];
    expect(btnBlock).not.toMatch(/border-radius:\s*var\(--radius-md/);
    expect(btnBlock).not.toMatch(/border-radius:\s*8px/);
    expect(btnBlock).toMatch(/border-radius:\s*(?:var\(--radius-circle[^\)]*\)|50%)/);
  });

  it('断言 2：.sessionActionsBtn 尺寸必须锁定为 24px（消除 26px 冲突）', () => {
    const btnMatch = sessionListCss.match(/\.sessionActionsBtn\s*\{[^}]+\}/);
    expect(btnMatch).toBeTruthy();
    const btnBlock = btnMatch![0];
    expect(btnBlock).toMatch(/width:\s*24px/);
    expect(btnBlock).toMatch(/height:\s*24px/);
    expect(btnBlock).not.toMatch(/width:\s*26px/);
    expect(btnBlock).not.toMatch(/height:\s*26px/);
  });

  it('断言 3：.footerGearCol 严禁包含 8px / var(--radius-md) 特判', () => {
    const gearColMatch = sidebarCss.match(/\.footerGearCol[^{]*\{[^}]+\}/);
    if (gearColMatch) {
      expect(gearColMatch[0]).not.toMatch(/var\(--radius-md\)/);
      expect(gearColMatch[0]).not.toMatch(/border-radius:\s*8px/);
    }
    // 全文检查 .footerGearCol 的任何子选择器
    const fullRules = sidebarCss.match(/\.footerGearCol[^{]+button[^{]*\{[^}]+\}/g) || [];
    for (const rule of fullRules) {
      expect(rule).not.toMatch(/var\(--radius-md\)/);
    }
  });

  it('断言 4：.footerGearCol 必须绑定 16px 或正圆圆角', () => {
    expect(sidebarCss).toMatch(
      /\.footerGearCol[\s\S]*?border-radius:\s*(?:var\(--radius-xl[^\)]*\)|16px|50%)/
    );
  });
});
```
