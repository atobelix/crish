# 方案 02：单行消息输入框与内部按钮形态守卫方案

> **方案定位**：针对 Round 2 用户在实际使用中对消息输入框视觉感受的核心痛点（单行输入框样式维持之前紧致饱满的形态；内部按钮与容器彻底杜绝小圆角，严格只保留胶囊型与正圆形两种形态），编制系统性几何基准、排查清单、整改详案与契约测试。  
> **上位依据**：`00-总方案.md`、`P4-容器基元与圆角描边语言.md`、`P6-输入坞一体化.md`、`01-实施状态台账.md`、`AGENTS.md` §13（输入框与焦点态）。  
> **实施原则**：建立刚性几何不变量；杜绝魔术数字补偿；以纯 Token 与原生 CSS 契约实现输入坞全场景的优雅统一与视觉降噪。

## 1. 背景与用户痛点原声对账

在最新的视觉验收体验中，用户明确指示了关于输入框外观与几何形态的核心要求：

### 1.1 用户原声与核心痛点
> **用户原声**：“消息输入框在只有一行的时候，维持之前的样式，里面的按钮什么的，也只有胶囊型和圆形。我看现在很多按钮或者显示的容器圆角，还是有小圆角的情况。这个也需要详细排查。”

对照物证与现场物理表现（`docs/visual-hierarchy-clarity-analysis/evidence/ours-crish.png` 及当前代码实现）：
1. **单行输入框形态被改“笨重”**：
   - **历史样式（认可态）**：垂直内边距为紧致的上下 `6px`，内部控件高度 `28px`，总高度仅为 $6 + 28 + 6 + 2 = 42\text{px}$，搭配 `border-radius: var(--composer-radius-single, 20px)`，在视觉上两端圆弧正好包住上下边缘，呈现出轻盈、饱满、圆润的**水平胶囊药丸（Dock Pill）**形态；
   - **P6 调整后（痛点态）**：垂直内边距被放大为 `padding: var(--space-2_5, 10px)`，总高度膨胀到 $10 + 28 + 10 + 2 = 50\text{px}$。由于高度从 42px 变厚到 50px，原本的 20px 圆角在两端出现了上下明显的平直直段，原本精致的药丸胶囊退化成了一个**略带圆角的大厚方块**，丧失了单行时原有的轻盈感。
2. **输入框内部元素小圆角严重泛滥（违背视觉秩序）**：
   - 权限模式菜单（`完全访问 ⌵`）：直接套用了普通表单控件的 `border-radius: var(--radius-control)`（**8px 小圆角**），在 28px 高度的条目中呈现为一个突兀的长方形小块；
   - 融合模型选择胶囊（`ComposerFusedTrigger`）：外层两端圆弧硬编码为 `--sep-radius-outer`（**12px 方圆角**），没有形成半圆闭环；
   - 内嵌提示条与审批条的操作按钮：提示条去配置/重试按钮（`.actionBtn` / `.ghostBtn`）采用 `var(--radius-row)`（**6px 小圆角**）；审批条按钮（`flowPermissionBtn`）采用 `var(--radius-sm, 6px)`（**6px 小圆角**）；
   - 关闭与控制按钮：提示条关闭叉号（`.closeBtn`）采用 `var(--radius-sm, 6px)`，进度条操作按钮（`.planActionBtn`）采用 `var(--radius-sm)`（**4px 小圆角**），形成了一群尺寸参差不齐的小方块；
   - 外部悬浮提示条（`SetupHintBanner`）：右侧操作按钮（`.chatSoftHintAction`）显式使用了 `--soft-hint-btn-radius: var(--radius-md, 8px)`（**8px 紧绷小圆角**）。

## 2. 根因穿透与几何法则重建

### 2.1 根因分析：缺乏统一的“二值形态法典”
1. **多重圆角 Token 的无序渗透**：
   历史上开发各个子组件（`ComposerPermissionBar`、`ComposerEmbeddedNotice`、`ComposerPlanProgressBar`、`PermissionModeMenu` 等）时，开发者习惯性地从通用设计系统抓取 `--radius-sm` (4px/6px)、`--radius-md` (6px/8px)、`--radius-control` (8px)、`--radius-lg` (8px/10px) 来修饰按钮与徽标。
2. **容器内外几何语言的断裂**：
   输入坞（Composer Dock）作为一个视觉上极具品牌识别度的特殊浮动组件，其设计语言天然属于**流体悬浮岛（Floating Fluid Island）**。在这样的大圆角外壳下，内部如果出现微小的方角（4px~8px），会与外框圆弧产生激烈的视觉对抗，破坏界面的精致感。

### 2.2 确立铁律：输入框内交互元素“二值形态法则”（Binary Shape Law）
在输入坞（`.composerCard`）内部空间及与其直接关联的提示坞内，**刚性确立唯一合法形态二值法则**：

$$\text{Shape}(\text{Interactive Element}) \in \{ \mathbf{Circle}\,(50\%), \;\mathbf{Pill}\,(\text{var}(--\text{radius-pill})) \}$$

- **绝不允许第三种形态**：输入框内**绝对禁止**任何 $4\text{px} / 6\text{px} / 8\text{px} / 12\text{px}$ 的小圆角矩形！
- **形态分配公理**：
  - **正圆形（Circle, 50%）**：凡是**宽高比约为 1:1 的单图标操作按钮、关闭按钮、删除点、状态指示点**，必须且只能为正圆；
  - **胶囊型（Pill, 9999px）**：凡是**承载文本、文本+图标、多段式组合的条状按钮、徽标、操作芯片**，必须且只能为饱满半圆胶囊。

## 3. 单行输入框视觉与几何基准

### 3.1 单行态（Single-Line Baseline）几何物理基准

| 几何维度 | 设计裁定值 | 规范 Token / 表达式 | 视觉效果与工程解释 |
|:---|:---|:---|:---|
| **外围圆角** | 饱满大胶囊 | `border-radius: var(--radius-pill, 9999px);` | 维持旧版完美药丸胶囊观感，两端 100% 半圆弧收尾，无平直切段 |
| **控件基准行高** | 28px 恒定 | `height: 28px;` | 加号、权限模式、文本输入行、发送按钮严格共享 28px 物理中线 |
| **垂直内边距** | 上下各 6px | `padding-top: 6px; padding-bottom: 6px;` | 回归旧版紧凑留白节奏，消除 10px 带来的笨重感 |
| **水平内边距** | 左右各 10px | `padding-left: 10px; padding-right: 10px;` | 消费 `--composer-pad-x` 与 `--composer-pad-x-start` 单源参数 |
| **总物理高度** | 42px 经典高度 | $6\text{px} + 28\text{px} + 6\text{px} + 2\text{px (边框)} = \mathbf{42px}$ | 视觉重心轻巧紧致，悬浮感十足 |
| **表面底色** | Raised 阶梯 | `background: var(--surface-raised);` | 暗色模式消费 Oklab mix 13.0% 阶梯，清爽不厚重 |
| **边缘发丝与微光** | 柔和微光 | `border: 1px solid var(--edge-rim);`<br/>`box-shadow: var(--shadow-lift-raised);` | 消除粗重描边，保留轻微高光景深 |
| **焦点状态（Focus）**| 克制混入 | `border-color: var(--edge-focus);` | 严格遵守 AGENTS.md §13：常规态 6% 文本色混入，落地空态 3%，零生硬黑环 |

### 3.2 从单行到多行的平滑自适应展开机制（Adaptive Expansion）

```
【单行态：42px 紧凑全胶囊（Single-Track Pill）】
╭───────────────────────────────────────────────────────────────────────────────────╮
│ (＋) [完全访问 ⌵]   输入消息，或键入 / 打开命令…                     [模型选择 ⌵] (⌃) │
╰───────────────────────────────────────────────────────────────────────────────────╯

                                      │ 键入多行 / 粘贴附件 / 弹出审批
                                      ▼
【多行态：优雅展开双层大圆角卡片（Two-Tier Dock Card）】
╭───────────────────────────────────────────────────────────────────────────────────╮
│ [内嵌顶槽：权限审批 / 运行通知 / 计划进度]（若有时平滑滑入）                       │
├───────────────────────────────────────────────────────────────────────────────────┤
│ [附件引用胶囊 / 批注芯片]（若有时）                                               │
├───────────────────────────────────────────────────────────────────────────────────┤
│ 第一层：多行文本输入区（自适应拉伸 24px ~ 220px 滚动）                             │
│                                                                                   │
│ 第二层：底栏控制对齐轴                                                            │
│ (＋) [完全访问 ⌵]                                             [模型选择 ⌵] (⌃) │
╰───────────────────────────────────────────────────────────────────────────────────╯
```

- **平滑演进状态机**：
  1. **圆角曲率连续过渡**：
     - 单行态：`border-radius: var(--radius-pill, 9999px);`（两端完美半圆弧）；
     - 多行态：平滑过渡为 `border-radius: var(--radius-dock, 20px);`（大圆角卡片）；
     - 过渡属性：`transition: border-radius var(--duration-normal) var(--ease-decelerate);`，杜绝瞬间生硬跳变；
  2. **垂直内边距平滑扩展**：
     - 单行态：上下各 `6px`（总高度 42px）；
     - 多行态：扩展为上下各 `10px`（`--space-2_5`，容纳两层排版的垂直呼吸间距）；
  3. **布局网格结构自适应**：
     - 单行态（单轨横排）：`grid-template-areas: 'left-ctrl text actions';`，左侧加号与权限、中间文字、右侧参数与发送，共享 28px 轴线；
     - 多行态（双轨分层）：
       `grid-template-areas: 'text text text' 'left-ctrl . actions';`
       上轨文本区自由展开；下轨左侧控制组（加号+权限）与右侧动作组（模型+发送）紧密吸附在卡片底部，垂直间距为 6px（`--space-1_5`）。

## 7. 自动化单测契约：`composerGeometry.contract.test.ts`

在 `apps/crish-desktop/src/components/chat-composer/__tests__/composerGeometry.contract.test.ts` 建立刚性自动化门禁：

```typescript
import { describe, it, expect } from 'vitest';
import fs from 'node:fs';
import path from 'node:path';

describe('输入坞几何不变量契约（Composer Geometry Contract）', () => {
  const composerDir = path.resolve(__dirname, '..');

  it('铁律断言：输入坞内部交互元素严禁出现 4px/6px/8px/12px 小圆角声明', () => {
    const cssFiles = fs.readdirSync(composerDir)
      .filter((f) => f.endsWith('.module.css') && !f.includes('Menu')); // 排除外部下拉浮层

    const forbiddenRadiusPattern = /border-radius:\s*(var\(--radius-(sm|md|control|row|lg|xl)\)|4px|6px|8px|12px|var\(--sep-radius-outer\))/i;
    const violations: { file: string; line: string }[] = [];

    for (const file of cssFiles) {
      const content = fs.readFileSync(path.join(composerDir, file), 'utf-8');
      const lines = content.split('\n');
      lines.forEach((line, index) => {
        // 排除代码块内部 pre/code 及外层大卡片声明
        if (
          forbiddenRadiusPattern.test(line) &&
          !line.includes('.fieldWrapper') &&
          !line.includes('code') &&
          !line.includes('pre')
        ) {
          violations.push({ file, line: `L${index + 1}: ${line.trim()}` });
        }
      });
    }

    expect(
      violations,
      `检出输入框内部交互元素使用了小圆角违规声明:\n${JSON.stringify(violations, null, 2)}`
    ).toEqual([]);
  });

  it('单行态外框不变量：未展开时外框必须声明为全胶囊 --radius-pill', () => {
    const chatComposerCss = fs.readFileSync(
      path.join(composerDir, 'ChatComposer.module.css'),
      'utf-8'
    );
    // 校验 .composerCard 默认声明为全胶囊
    expect(chatComposerCss).toMatch(/\.composerCard\s*\{[^}]*border-radius:\s*var\(--radius-pill/s);
    // 校验单行态垂直 padding 为 6px
    expect(chatComposerCss).toMatch(/padding:\s*6px\s+/);
  });

  it('多行态外框不变量：展开时平滑演进为大圆角 --radius-dock', () => {
    const chatComposerCss = fs.readFileSync(
      path.join(composerDir, 'ChatComposer.module.css'),
      'utf-8'
    );
    expect(chatComposerCss).toMatch(/\.composerCard\.isMultiline\s*\{[^}]*border-radius:\s*var\(--radius-dock/s);
  });

  it('操作按钮二值断言：plusBtn 与 sendBtn 必须恒定声明为正圆 50%', () => {
    const chatComposerCss = fs.readFileSync(
      path.join(composerDir, 'ChatComposer.module.css'),
      'utf-8'
    );
    const sendControlsCss = fs.readFileSync(
      path.join(composerDir, 'ComposerSendControls.module.css'),
      'utf-8'
    );

    expect(chatComposerCss).toMatch(/\.plusBtn\s*\{[^}]*border-radius:\s*50%/s);
    expect(sendControlsCss).toMatch(/\.sendBtnCircle[^{]*\{[^}]*border-radius:\s*50%/s);
  });

  it('权限菜单胶囊断言：PermissionModeMenu trigger 必须恒定声明为 --radius-pill', () => {
    const permCss = fs.readFileSync(
      path.join(composerDir, 'PermissionModeMenu.module.css'),
      'utf-8'
    );
    expect(permCss).toMatch(/\.trigger\s*\{[^}]*border-radius:\s*var\(--radius-pill/s);
  });
});
```
