# 视觉层级清晰度分析 · 维度 01：色彩与明度分层（Surface Layering / Elevation）

> **分析对象**：参考界面（Codex，截图 `ref-codex.png`） vs 我们的界面（Crish，截图 `ours-crish.png`，暗色主题）  
> **核心议题**：为什么参考界面凭借『侧栏 / 主区 / 卡片 / 输入框』形成清晰、沉着且纯净的明度台阶，而我们的界面各区域明度几乎一致、扁平发乌、视觉层级塌陷？  
> **分析员身份**：UI 视觉分析员（只读分析，严禁改动源码，基于截图取样、源码锚点与实测物理数据）

## 结论摘要

1. **表面别名黑洞导致卡片层级彻底塌陷（ΔL* = 0, 1.000:1）**：
   暗色主题下，`tokens.css:1059-1060` 强行将 `--surface-card`、`--surface-elevated` 与 `--surface-paper` 全部别名指向主画布 `--surface-main`（`#141414`）。导致无论是信息流中的报告卡片（如实测 `Crish 架构勘测报告`）、右侧面板（`RuntimePanel.module.css:12`）还是普通卡片容器，其背景色与底层画布完全同色，明度差 $\Delta L^* = 0$，对比度为绝对相同的 **1.000:1**。容器边界完全消融，逼迫全界面只能退化为依赖 1px 线条（线噪）来圈定范围。
2. **三档底色 SSOT 导致表面逻辑与明度阶梯倒挂**：
   暗色定义中将 `--surface-outer`（侧栏、顶栏）设为 `#1e1e1e`（$L^*=11.26$），而主画布 `--surface-main` 却沉底设为 `#141414`（$L^*=6.32$），形成“外壳比内容区亮”的反向明暗场；更严重的是，下凹表面 `--surface-sunken`（`tokens.css:1061`）被指派给外层 `#1e1e1e`，导致**下凹区在物理上反比主平面高出 4.94 个 $L^*$ 亮度点**，语义与物理规律完全错位。
3. **输入区浮力不足，重黑阴影在暗色下物理隐形**：
   底部 Composer 输入框在暗色模式下仅取值 `--surface-input`（`#232323`，$L^*=13.71$），相对主画布对比度仅为 **1.17:1**（Codex 为 **1.47:1**，$\Delta L^* = 14.37$），无法建立交互中心地位；其所谓浮层投影（`ChatComposer.module.css:1285`）声明为 `color-mix(in srgb, #000 1.5%, transparent)`，在 `#141414` 底板上造成的像素位移不足 0.3 个 RGB 级，在光学上绝对不可见。
4. **交互项对比度过冲（Contrast Overshoot）撕裂全局**：
   在静态容器全面躺平（0 阶差）的同时，激活项（Sidebar 活跃会话、顶栏活跃 Tab）却通过 `--elevate-3`（`tokens.css:1093`，18.7% 叠加）强行抬升至 `#464646`（$L^*=29.72$），对比度骤升至 **1.95:1**（$\Delta L^* = 18.46$）。界面在“死黑铁板一块”与“刺眼聚光灯高光”两个极端跳跃，缺乏中间层过渡。
5. **架构断层：预设数据丰富但在注入与测试层被刚性阉割**：
   `themePresets.ts:165-181` 在 `dark-cozy` 预设中原本规划了 5 级合理表面（`bgPrimary: #141414`, `bgTertiary: #181818`, `bgSecondary: #1e1e1e`, `bgCard: #232323`, `bgElevated: #262626`），但在 `skinPaintPlan.ts:297-300` 中被强行以 `void bgTertiary; void bgElevated;` 丢弃；随后在 `threeTierSurface.contract.test.ts:72-93` 中将“所有别名全归并到 outer/main/input 三档”作为 CI 门禁硬性钉死，将这一破坏视觉纵深的架构缺陷反向固化为契约。

## 参考界面做对了什么（具体）

参考 Codex 界面（`docs/visual-hierarchy-clarity-analysis/evidence/ref-codex.png`），其深色主题的干净与高级感，来源于其深谙现代暗色设计系统的**表面高程阶梯规范（Surface Elevation Hierarchy）**：

### 1. 明确的基底明度锚定与纵深预留（Base Canvas Anchoring）
- **截图观察（中心与右侧大区域）**：Codex 将主对话工作区画布与右侧辅助面板（子智能体）底色统一锚定在深沉克制的 `#181818`（RGB 24, 24, 24，$L^* = 8.25$）。
- **设计智慧**：它没有把背景做成发灰的发亮底板，也没有把所有区域涂死为纯黑 `#000000`。`#181818` 作为“地平面（Ground Plane）”，为上层所有卡片、气泡与操作浮层留出了充裕的**向上提亮动态范围（Luminance Headroom）**。

### 2. 交互底座的鲜明浮起（Composer Elevation）
- **截图观察（底部输入卡片区域）**：底部的 “和 Codex 一起工作” Composer 采用了明显的悬浮深灰胶囊。
- **实测数据**：Codex Composer 底色取样为 `#363636`（RGB 54, 54, 54，$L^* = 22.62$）。
- **层级台阶**：相对主画布 `#181818`，Composer 的亮度差高达 **$\Delta L^* = +14.37$**，WCAG 对比度达到 **1.47:1**（纯底色对比），形成明确的物理高程（相当于 8dp~12dp Elevation）。用户在扫视屏幕时，输入区域作为主要行动点（Call to Action）自然成为第一视觉落点，而无需加粗黑线或厚重外描边。

### 3. 内容与状态徽章的中间层级（Content Pills & Badges）
- **截图观察（聊天流下方的改动统计）**：`3 个文件已更改 +14 -10` 徽章。
- **实测数据**：背景取样为 `#2D2D2D`（RGB 45, 45, 45，$L^* = 18.47$）。
- **层级台阶**：介于画布基底（$L^* = 8.25$）与 Composer 输入框（$L^* = 22.62$）之间，$\Delta L^* = +10.22$，对比度为 **1.29:1**。它不需要 1px 描边，凭借这一级微弱却坚决的中间底色（Tier 2），自然在深黑画布上将元信息聚集为一个视觉整体。

### 4. 外框与主区之间的精细分割（Subtle Hairline & Dock）
- **截图观察（左侧 Dock 与右侧抽屉分界）**：
  - 左侧图标 Dock 栏底色取样为 `#1F2024`（RGB 31, 32, 36，$L^* = 12.30$），与画布基底差值微弱但可辨（$\Delta L^* = 4.05$）。
  - 分隔主画布与右侧子智能体面板的竖向分割线实测为 `#2B2B2B`（RGB 43, 43, 43，$L^* = 17.53$），对比度仅 **1.25:1**。
- **设计智慧**：分割线明度严格受控，仅比背景略亮约 9 个 $L^*$ 点，充当柔和的边界提示，绝不割裂整个工作台的统一场域。

### 5. 交互高亮状态的克制提亮（Restrained Active States）
- **截图观察（左侧 Dock 活跃 Home 图标）**：活跃图标的背衬药丸实测为 `#323233`（RGB 50, 50, 51，$L^* = 20.78$）。
- **层级台阶**：相对 Dock 栏背景 `#1F2024`，亮度增量仅为 **$\Delta L^* = +8.48$**（对比度 1.22:1）。视觉反馈沉稳清晰，既明确标识了当前位置，又没有刺眼的聚光灯感。

## 我们的现状与根因（带证据）

在暗色主题截图 `docs/visual-hierarchy-clarity-analysis/evidence/ours-crish.png` 中，界面呈现出发乌、扁平、缺乏层次且局部刺眼的混乱观感。通过深入前端 CSS Token 体系与运行时注入机制，确认根因如下：

### 1. 表面别名全归并，Card 与 Elevated 光学归零
- **源码证据**：[`apps/crish-desktop/src/styles/tokens.css:1044-1065`](file:///c:/Software/conex/apps/crish-desktop/src/styles/tokens.css#L1044-L1065)
  ```css
  html[data-theme='dark'] {
    --user-surface-outer: #1e1e1e;
    --user-surface-main: #141414;
    --user-surface-input: #232323;
    --surface-outer: var(--user-surface-outer, #1e1e1e);
    --surface-main: var(--user-surface-main, #141414);
    --surface-input: var(--user-surface-input, #232323);
    
    --surface-chrome: var(--surface-outer);
    --surface-paper: var(--surface-main);
    --surface-card: var(--surface-main);     /* 致命：卡片底色 = 主画布底色 */
    --surface-elevated: var(--surface-main); /* 致命：浮层底色 = 主画布底色 */
    --surface-sunken: var(--surface-outer);   /* 致命：下凹底色 = 外层浅灰 */
    
    --bg-primary: var(--surface-paper);
    --bg-secondary: var(--surface-chrome);
    --bg-tertiary: var(--surface-sunken);
    --bg-card: var(--surface-card);
    --bg-elevated: var(--surface-elevated);
  }
  ```
- **截图实测证据**：
  - 聊天流中的助手产物卡片（`Crish 架构勘测与自主长程循环测试报告`，坐标 $x=350, y=530$）实测颜色为 `#141414`（RGB 20, 20, 20）。
  - 周围的主画布（坐标 $x=300, y=200$）实测颜色同样为 `#141414`（RGB 20, 20, 20）。
  - **对比度断言**：主画布与卡片容器之间，**$\Delta L^* = 0.00$，对比度 1.000:1**。
- **后果**：卡片在视觉上根本不存在！卡片的标题、标签、折叠钮完全裸露在深黑画布上，没有任何背景支撑。为了防止内容散架，UI 只能被迫在卡片边缘加上 1px 的 `--border-subtle`，最终沦为到处是细线框的“线噪界面”。

### 2. 倒挂的明度阶梯（Inverted Elevation）
- **外层比主层亮**：
  `--surface-outer` 为 `#1e1e1e`（$L^* = 11.26$），`--surface-main` 为 `#141414`（$L^* = 6.32$）。在外侧侧栏、顶栏的包围下，中间的主工作区像一个塌陷下去的黑洞。
- **Sunken 反向发光**：
  `tokens.css:1061` 声明 `--surface-sunken: var(--surface-outer);`。在暗色模式下，`--surface-outer` 为 `#1e1e1e`，比画布 `--surface-main`（`#141414`）高出近 5 个 $L^*$ 点。任何消费 `--surface-sunken`（语义上代表挖空、凹陷、轨道）的组件，渲染出的视觉效果不是“陷下去”，而是“凸出来并泛白”，与现实物理隐喻完全相反。

### 3. Composer 输入框浮力严重不足与阴影假象
- **源码证据**：[`apps/crish-desktop/src/components/chat-composer/ChatComposer.module.css:1284-1287`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/ChatComposer.module.css#L1284-L1287)
  ```css
  .composerCard {
    background: var(--composer-bg, var(--surface-input));
    box-shadow:
      0 1px 3px color-mix(in srgb, var(--shadow-color) 1.5%, transparent),
      0 3px 8px -1px color-mix(in srgb, var(--shadow-color) 2%, transparent);
  }
  ```
- **实测取样证据**：
  - Composer 内部底色取样为 `#232323`（RGB 35, 35, 35，$L^* = 13.71$）。
  - 主画布为 `#141414`（$L^* = 6.32$）。
  - 对比度仅为 **1.17:1**（$\Delta L^* = +7.39$）。
  - 提示条 `Setup Banner`（`首次使用请先配置服务商密钥与模型`）取样同样为 `#232323`（$L^* = 13.71$）。
- **光学失效分析**：
  1. 提示条与输入框同色且紧密贴合，导致视口底部形成两个明度一模一样的灰色胶囊，缺乏主次主从关系。
  2. `--shadow-color` 在暗色模式下为 `#000`。在 `#141414`（RGB 20）的主画布上叠加 1.5% 的纯黑投影：$20 \times (1 - 0.015) = 19.7$。**0.3 个 RGB 阶的亮度衰减远低于人眼辨识阈值（Just Noticeable Difference，JND 约为 1.5~2.0 RGB 阶）**。该投影在物理显示器上等同于纯粹的死代码，根本无法起到提供 Elevation 的作用。

### 4. 交互项对比度过冲与高光刺眼
- **源码证据**：[`apps/crish-desktop/src/styles/tokens.css:1089-1126`](file:///c:/Software/conex/apps/crish-desktop/src/styles/tokens.css#L1089-L1126)
  ```css
  --elevate-step-3: 18.7%;
  --elevate-3: color-mix(in srgb, var(--element-ink) var(--elevate-step-3), transparent);
  --tab-active-bg: var(--elevate-3);
  --sidebar-active: var(--elevate-3);
  ```
- **实测取样证据**：
  - 侧栏活跃项（`你现在作为 Crish 核心架 10/12`，坐标 $x=30, y=346$）实测为 `#464646`（RGB 70, 70, 70，$L^* = 29.72$）。
  - 顶栏活跃标签页实测同为 `#464646`（RGB 70, 70, 70，$L^* = 29.72$）。
- **失衡现象**：
  - 侧栏背景是 `#1E1E1E`（$L^* = 11.26$），活跃项直接跳到 `#464646`（$L^* = 29.72$），明度差暴增 **$\Delta L^* = +18.46$**，对比度高达 **1.95:1**。
  - 对比 Codex 的 Dock 活跃项仅从 $L^*=12.30$ 提升到 $L^*=20.78$（$\Delta L^* = +8.48$）。
  - Crish 的交互高亮是 Codex 跃迁幅度的 **2.18 倍**！静态卡片毫无起伏，活跃项却如同聚光灯打在灰墙上，造成严重的视觉刺激与不适。

### 5. 架构级阉割与契约测试绑死（Root Pipeline Decoupling）
- **源码断层追踪**：
  1. [`apps/crish-desktop/src/api/themePresets.ts:165-173`](file:///c:/Software/conex/apps/crish-desktop/src/api/themePresets.ts#L165-L173) 中，`dark-cozy` 预设明确设计了 5 个不同梯度的表面：
     ```ts

     bgSecondary: '#1e1e1e',
     bgTertiary: '#181818',
     bgCard: '#232323',
     bgElevated: '#262626',
     ```
  2. 但在 [`apps/crish-desktop/src/services/token-runtime/skinPaintPlan.ts:297-300`](file:///c:/Software/conex/apps/crish-desktop/src/services/token-runtime/skinPaintPlan.ts#L297-L300) 中，派生函数却赫然写着：
     ```ts

     void bgTertiary;
     void bgElevated;
     void shellChromeBg;
     ```
     预设中原本正确的 `bgTertiary`、`bgElevated` 被彻底强行丢弃！
  3. [`apps/crish-desktop/src/services/TokenRuntimeController.ts:187-191`](file:///c:/Software/conex/apps/crish-desktop/src/services/TokenRuntimeController.ts#L187-L191) 仅向根节点注入 `--user-surface-outer`、`--user-surface-main` 与 `--user-surface-input` 三个变量。
  4. 最终在 [`apps/crish-desktop/src/styles/threeTierSurface.contract.test.ts:72-93`](file:///c:/Software/conex/apps/crish-desktop/src/styles/threeTierSurface.contract.test.ts#L72-L93) 中，契约测试用正则断言：
     ```ts

     ```
     直接通过单元测试，把“Card / Elevated 必须等于 Main”这一设计缺陷给锁死成了合规要求。

## 与其他维度的耦合点

色彩与明度分层（Surface Layering）是整个 UI 视觉层级的地基。本维度的崩塌直接触发了后续一系列连锁视觉病态：

1. **与【维度 03：边框分隔与视觉噪声】的因果耦合**：
   - **因**：由于 `--surface-card`、`--surface-elevated` 与 `--surface-main` 完全同色（$\Delta L^* = 0$），卡片与浮层失去了底色衬托这一“靠场区分”的原生能力。
   - **果**：前端开发者为了让用户看出“这是一个卡片 / 对话块 / 输入栏”，只能到处给元素挂 `border: 1px solid var(--border-subtle)`。全屏 1578 处 border 属性正是表面阶梯缺失逼出来的畸形产物。
2. **与【维度 05：对话流信息架构】的内容呈现耦合**：
   - **因**：对话流中的长程工具调用（ToolCall）、思考块（ThinkingProcess）与测试报告（Markdown / TerminalCard）没有可依赖的微亮卡片衬底。
   - **果**：信息无法形成紧凑的卡片收敛，只能把每一个工具、折叠块全做成裸露的文本行，并大量滥用折叠 Chevron（`&#8250;`）来标识可交互性，导致右侧出现折叠箭头排队现象。
3. **与【维度 07：输入区与状态条】的几何挤压耦合**：
   - **因**：Composer 输入框（`#232323`）与 `ComposerNoticeBar` 提示条（同为 `#232323`）在明度上零阶差，二者无法在空间上形成“提示条附着于底座上方”的景深关系。
   - **果**：只能采用平铺的上下双圆角胶囊硬堆叠，产生了双层闭合描边的严重几何冲突。
4. **与【维度 08：设计系统一致性】的契约冲突**：
   - `themePresets.ts` 已经包含了 5 级表面数据模型，却被 `skinPaintPlan.ts` 强行折叠截断；同时 `threeTierSurface.contract.test.ts` 将“旧别名全落在三档上”作为单测护栏。修复本维度必须联动修改契约测试，打破“把错误断言当规范”的历史包袱。

## 架构级修复方向

严禁任何通过临时局部调色（如在 `ChatComposer.module.css` 局部写死 `#363636`，或给卡片加 `style={{ background: '#222' }}`）的打补丁行为。必须从 Design Token 体系与运行时派生架构进行系统性治理：

### 1. 废除暗色“三档强制归并”，恢复五级表面高程体系（5-Tier Elevation Scale）
重构 `tokens.css` 暗色模式块，解绑 `--surface-card` 与 `--surface-elevated`，建立单调递增、语义清晰的五级表面系统：

```css
/* 架构级暗色五级表面高程契约 (Dark Surface Elevation Hierarchy) */
html[data-theme='dark'] {
  /* Tier -1: Sunken 下凹层（代码块底、内嵌列表轨道；低于画布，严禁高于画布） */
  --surface-sunken: #0d0d0d;    /* L* ≈ 3.5, 相比画布深 3 个 L* 点 */

  /* Tier 0: Ground/Canvas 主工作区画布底板 */
  --surface-main: #141414;      /* L* ≈ 6.3, 全局基准地平面 */

  /* Tier 1: Outer Chrome 外框基座（侧边栏、顶栏；微弱浮起或平齐） */
  --surface-outer: #181818;     /* L* ≈ 8.2, 柔和锚定，不再突兀发亮 */
  --surface-chrome: var(--surface-outer);

  /* Tier 2: Card / Container 内容卡片与静态分组（报告、代码块、设置项） */
  --surface-card: #1c1c1c;      /* L* ≈ 10.5, ΔL* = +4.2，形成自然的容积面 */
  --surface-paper: var(--surface-card);

  /* Tier 3: Floating / Composer 交互浮动底座与输入框 */
  --surface-input: #272727;     /* L* ≈ 15.2, ΔL* = +8.9, 形成强烈的交互中心 */
  --composer-bg: var(--surface-input);

  /* Tier 4: Elevated Popover / Modal 弹出层、下拉菜单、Dialog */
  --surface-elevated: #2d2d2d;  /* L* ≈ 18.5, 顶层悬浮面 */
}
```

