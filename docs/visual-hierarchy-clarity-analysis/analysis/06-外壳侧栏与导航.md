# 维度 06：外壳与导航——侧栏、标题栏、面包屑、标签页（App Shell & Navigation）

> **分析对象**：
> - 参考界面：Codex 桌面应用（`docs/visual-hierarchy-clarity-analysis/evidence/ref-codex.png`）
> - 我们的界面：Crish 桌面应用暗色模式（`docs/visual-hierarchy-clarity-analysis/evidence/ours-crish.png`）
> 
> **核心命题**：为什么 Codex 的外壳看上去干净利落、视线落点明确，而 Crish 的外壳给人感觉层级繁复、元素拥挤、视线漂移且没有视觉锚点？

---

## 结论摘要

1. **外壳信息元素总量悬殊（56 vs 29）**：Crish 在视口上方与左侧的外壳导航区堆叠了 **56 个信息/交互元素**，而 Codex 仅有 **29 个**（减少 48.2%）。Crish 的外壳承担了过多未经降噪的文字标签、日期元数据与空态占位。
2. **多层 Chrome 垂直吞噬与「三重回音」冗余（74px 垂直高度）**：Crish 同时挂载了顶层标签栏（`PaneHeader`，36px）与下方卡片顶栏（`UnitChromeActions` 面包屑，38px），纵向连续霸占 74px 空间。在左上角仅 100px×300px 的局部区域内，当前会话标题以三种不同截断形态在侧栏选中项、顶部标签、面包屑中**连续重复出现 3 次**（「三重标题回音」）。而 Codex 仅保留 36px 的单轨标题栏，将视觉重心 100% 留给正文。
3. **暗色主题 Token 反转导致「视觉倒挂」与视线迷失**：在暗色主题下，`SidebarSessionList.module.css:411-413` 硬编码将所有未选中会话标题强制提升为 `--text-primary`（对比度高达 9.56:1），且 `:436-440` 将右侧时间戳强制提升为 `--text-secondary`（对比度 5.43:1）；而选中态胶囊底色对比度仅 1.77:1。结果导致侧栏 13 条会话标题与 13 个日期在纵向形成两条高度耀眼的「斑马线」，选中项与未选中项对比反转，用户视线完全被高亮日期带走，失去落点。
4. **低价值空态与折叠切换粗暴占据黄金轴线**：侧栏「项目」分段在无数据时强行渲染高度达 37px 的居中文字「暂无项目」（`SidebarSessionList.module.css:11-16`），在视觉正中硬性打断列表连续性；底部「查看全部 (78)」采用居中弱文字按钮，与上方左对齐会话结构脱节。Codex 则通过紧凑的分组标题（如「已开启 · 2」、「完成 · 20」）与步进展开（「再显示 10 个」）保持流式节奏。
5. **顶栏动作簇辨识度低且语义混合**：右侧快捷操作区将「浏览器（globe）」、「文件管理器（folder-tree）」、「更多操作（more-horizontal）」与独立常驻的「坞开关（sidebar-right）」4 个仅 14px 的小图标紧密并排，没有逻辑分组分割线，图形语义晦涩（用户难以辨识 folder-tree 与分支的区别）。Codex 在主栏仅保留极其清晰的 `...` 与分屏图标，复杂子智能体状态则完全后置进专属右面板。

## 参考界面做对了什么

观察 `ref-codex.png`，Codex 在外壳与导航的架构设计上体现了极强的「克制与层级感」：

### 1. 极致纤薄的 48px 单轨活动栏（Activity Bar）
- **左侧导航极度收敛**：Codex 没有在左侧常驻 260px 宽的文字会话侧栏，而是采用仅约 48px 宽的纯图标垂直导轨（Activity Rail）。
- **纯粹的图标语言**：容纳 Home、历史、对话、归档、@提及、更多、分支等 7 个核心图标，底部放置用户头像（`HA` 橙色圆形）。
- **零文字干扰**：不显示会话名称、不显示日期时间戳、不显示折叠分组，完全消除了侧栏对主阅读区的视觉抢夺。

### 2. 单轨合并型面板标题（Single-Row Pane Header）
- **垂直高度仅 ~36px**：Codex 主窗格顶部仅有一行简洁标题栏，包含：
  - 左侧：编辑铅笔图标 + 文件夹图标 + 简洁会话名（「分析 Conex 当前问题」）；
  - 右侧：`...` 更多操作按钮 + 分屏布局切换按钮。
- **无重复 Tabs 与 Breadcrumb**：Codex 没有在标题上方再加一层浏览器 Tab 栏，也没有在下方再加一层 Breadcrumb，会话身份识别单一、确凿、干净。

### 3. 右侧任务面板的清晰层级（Subagents Panel）
- **专职面板分离**：将复杂的多任务/子智能体状态移至右侧专属面板（「子智能体」），主次分明。
- **结构化分组**：分组标题极其克制（「已开启 · 2」、「完成 · 20」），采用点分隔符与数字。
- **信息权重严谨**：
  - 彩色状态图形（绿/金/蓝微标）作为视觉引导；
  - 任务标题为 Primary 亮白字；
  - 副标题（如 `checking modelVendor chunk size`）为压暗次级文字；
  - 耗时与相对时间（如 `1m 8s`、`2分钟前`）右浮动且深度降噪，绝不反客为主。

## 我们的现状与根因（带证据）

### 1. 外壳元素计数与视觉轰炸（现状与截图证据）
在 `ours-crish.png` 中，外壳导航区域的元素呈现明显的「过载」状态：
- **顶部顶栏与标签区**：Crish 图标 + 品牌名 "Crish" + 会话标签页（含关闭 x）+ 新建标签 "+" + 窗口三键（最小化/最大化/关闭），共 7 个元素。
- **卡片顶栏面包屑与快捷键**：类别 "对话" + 分割符 "/" + 会话标题 + 浏览器图标 + 文件图标 + 更多菜单 + 侧坞开关，共 7 个元素。
- **侧栏顶部操作区**：品牌形态切换按钮 + "Crish" 标题 + "新对话"（含图标）+ "定时任务"（含图标）+ "扩展"（含图标）+ 搜索输入框（含搜索图标），共 9 个交互元素。
- **侧栏列表与元数据区**：
  - 置顶组：标题 "置顶" + 箭头 + 3 行（每行含标题 + 日期 "9/18"、"9/6"、"7/29"）= 8 个元素；
  - 项目组：标题 "项目" + 箭头 + 空态 "暂无项目" = 3 个元素；
  - 对话组：标题 "对话" + 箭头 + 10 行可见会话（每行含标题 + 日期）+ "查看全部 (78)" 展开按钮 = 23 个元素；
- **侧栏底部**：用户头像 + "Developer" + 设置齿轮 = 3 个元素。
- **外壳元素合计**：$7 + 7 + 9 + 8 + 3 + 23 + 3 = 56$ 个视觉元素。
在视口的一半面积内，56 个元素几乎以同等对比度并存，导致视线没有视觉焦点。

### 2. 侧栏行高、选中态与暗色 Token 倒挂（根因分析与代码证据）

#### (1) 行高与密集排布
- **源码依据**：`apps/crish-desktop/src/components/sidebar/SidebarSessionList.module.css:361-382`
  ```css
  .sessionItemWrap {
    height: 28px;
    min-height: 28px;
    max-height: 28px;
  }
  .sessionItem {
    height: 28px;
    min-height: 28px;
    max-height: 28px;
    padding: 0 var(--space-1_5, 6px) 0 var(--space-8);
    font-size: var(--font-size-base); /* 14px */
  }
  ```
- **量化事实**：在仅 28px 的微小行高内，放置 14px 字号的文本，剩余上下垂直间隙仅各 7px。
- **问题表现**：列表采用无间距（`gap: 0`）垂直紧密排列，13 行会话标题和 13 个日期紧密咬合，视觉上形成一整块灰白相间的密集体块。

#### (2) 暗色主题下的「文字亮度倒挂」致命伤
- **源码依据**：`apps/crish-desktop/src/components/sidebar/SidebarSessionList.module.css:411-413` 与 `:436-440`
  ```css
  /* 深色会话名再亮一档。悬停和选中仍只靠底色区分。 */
  :global(html[data-theme='dark']) .sessionItem {
    color: var(--text-primary);
  }
  
  :global(html[data-theme='dark']) .sessionTime,
  :global(html[data-theme='dark']) .sessionItem.active .sessionTime,
  :global(html[data-theme='dark']) .sessionTitleHint {
    color: var(--text-secondary);
  }
  ```
- **WCAG 对比度实测数据**（基于 `tokens.css:1044-1144` 变量链与 pwsh WCAG 计算）：
  - 侧栏底色 `--surface-outer`：`#1e1e1e`（RGB: 30, 30, 30，相对亮度 $L = 0.014$）
  - `--text-primary`：`color-mix(in srgb, #f5f5f5 80%, black)` = RGB: 196, 196, 196，相对亮度 $L = 0.551$
    - **未选中会话标题对比度**：$(0.551 + 0.05) / (0.014 + 0.05) =$ **9.56:1**（极高亮度！）
  - `--text-secondary`（即 `.sessionTime` 日期）：`color-mix(in srgb, #f5f5f5 60%, black)` = RGB: 147, 147, 147，相对亮度 $L = 0.291$
    - **日期元数据对比度**：$(0.291 + 0.05) / (0.014 + 0.05) =$ **5.43:1**（远超 WCAG AA 4.5:1 基准）
  - 选中项胶囊底色 `--sidebar-active`（`--elevate-3`）：$30 + 0.187 \times (245 - 30) =$ RGB: 70, 70, 70，相对亮度 $L = 0.063$
    - **选中项底色对侧栏底色对比度**：$(0.063 + 0.05) / (0.014 + 0.05) =$ **1.77:1**（极其微弱！）
- **视觉崩塌根因**：
  原本在浅色主题下，未选中项是次要灰字，选中项是高亮黑字。但在暗色模式下，CSS 补丁将**所有未选中的会话全部强行刷成最高对比度 9.56:1 的白字**！
  与此同时，右侧的日期「9/18」、「10/12」等以 5.43:1 的高对比度常驻闪烁。选中的会话项（「你现在作为 Crish 核心架」）仅仅依靠一个对比度仅 1.77:1 的暗灰底色（RGB 70 vs 30）来区分！
  其结果就是：**未选中项比选中项还要抢眼，右侧日期连成一列白色栅栏，用户一眼扫过去，根本分不清哪一条是当前选中的会话**。

### 3. 多层 Chrome 垂直重叠与「三重回音」（垂直空间与层级分析）

- **源码依据**：
  1. `apps/crish-desktop/src/components/top-bar/AppTopBar.tsx:26-47` 与 `apps/crish-desktop/src/styles/tokens.css:636`：
     `--header-height: 36px;` 承载标签栏 `PaneHeader`；
  2. `apps/crish-desktop/src/components/chat-card/UnitChromeActions.module.css:3-23`：
     ```css
     .chatTopHeader {
       height: 38px;
       min-height: 38px;
       background: var(--bg-card, var(--bg-primary));
     }
     ```
- **垂直空间消耗**：$36\text{px} + 38\text{px} = 74\text{px}$ 纯外壳高度。
- **「三重标题回音」现象分析**：
  在 `ours-crish.png` 中观察屏幕左上方区域：
  1. 侧栏选中行（`SessionRow.tsx:428`）：`你现在作为 Crish 核心架`（14px 字号）
  2. 顶栏标签页（`PaneTabItem.tsx`）：`你现在作为 Crish 核心架构自检 Ag...`（13px 字号）
  3. 卡片面包屑（`UnitChromeActions.tsx:285-295`）：`对话 / 你现在作为 Crish 核心架构自...`（13px 字号）
  这三个标题在垂直距离不到 100px、水平距离不到 300px 的狭小区域内，以完全相同的浅色文字重复了 3 遍！
- **架构断层根因**：
  系统在架构演进中同时保留了三套导航范式，且三者互不知晓：
  - 传统桌面多标签页模型（`PaneHeader`，仿浏览器多标签）；
  - Web 文档层级面包屑模型（`UnitChromeActions`，仿知识库面包屑）；
  - 经典桌面多会话侧栏（`Sidebar`，仿聊天客户端会话栏）。
  三套模型机械并存，导致空间被双层 Chrome 硬生生切走 74px，并且在视觉上制造了极大的信息冗余。

### 4. 右上角图标簇辨识度低与逻辑混杂

- **源码依据**：`apps/crish-desktop/src/components/chat-card/UnitChromeActions.tsx:317-374`
  - 按钮 1（`:328`）：`AppIcon name="globe" size={14}`（Tooltip: "浏览器"）
  - 按钮 2（`:344`）：`AppIcon name="folder-tree" size={14}`（Tooltip: "打开文件"）
  - 按钮 3（`:358`）：`ChatHeaderMore`（`name="more-horizontal" size={14}`，Tooltip: "更多操作"）
  - 按钮 4（`TreeLeafPanel.tsx:494-501`）：`AppIcon name="sidebar-right" size={14}`（Aria-label: "展开/收起右侧工具栏"）
- **问题分析**：
  1. **尺寸过小与点击靶心不足**：图标仅 14px，被塞在 28px×28px 的微型按钮中，彼此间距仅 4px。
  2. **隐喻模糊（Metaphor Ambiguity）**：
     - 在聊天会话顶栏，一个地球仪（globe）图标很容易被用户误解为「联网搜索」或「网络连接状态」，而实际上它打开的是 Webview 预览侧坞；
     - `folder-tree` 呈现为一个带树状分支的小文件夹，用户第一眼极易误以为是 Git 分支或代码树，而实际上是打开文件面板。
  3. **职责混淆未分组**：这 4 个图标涵盖了「视图切换（预览/文件）」、「会话操作（置顶/导出/清理）」和「工作区布局控制（右侧坞开合）」，却被一字排开放在同一容器内，没有任何视觉分割符或胶囊分组。

#### (2) 「查看全部 (78)」弱化与割裂

## 与其他维度的耦合点

1. **与【维度 01：色彩、主题与对比度】的耦合**：
   - 侧栏文字层级的崩塌根本上源于暗色主题 Token 的粗暴覆写。`tokens.css:1142-1148` 规定了 `--text-primary`、`--text-secondary`、`--text-tertiary` 的梯度，但 `SidebarSessionList.module.css:411-440` 违规跳过梯度，将暗色会话全部升格为 `--text-primary`，直接摧毁了原本的设计阶梯。
2. **与【维度 02：排版与文本层级】的耦合**：
   - 侧栏 28px 行高与 14px 字号（`--font-size-base`）组合，在行内留白极少的情况下同时容纳标题与日期，导致文字无法形成自然节奏；
   - 标题在三处重复呈现时，字号分布杂乱（14px 侧栏、13px Tab、13px 面包屑），缺乏明确的主次比例。
3. **与【维度 03：布局结构与空间几何】的耦合**：
   - 多层 Chrome（36px 顶栏 + 38px 卡片顶栏）是二叉树布局微内核（`TreeLeafPanel`）与顶层应用外壳（`AppTopBar`）职责边界未划分清楚的产物；二者叠加直接侵占了 74px 的黄金阅读空间。
4. **与【维度 04：视觉噪声与信息密度】的耦合**：
   - 侧栏 13 个高亮日期在右侧垂直对齐，与左侧标题形成「双轨视觉噪声」，使用户视线在左右两侧不断震荡，无法在会话核心内容上定焦。

## 架构级修复方向

> **声明**：本节仅提供系统架构与单一真理路径（SSOT）级别的设计方案，杜绝使用魔术数字补丁。

### 1. 顶层 Chrome 架构收敛（单轨统一标题栏 SSOT）
- **合并多层 Chrome 容器**：
  废除 `AppTopBar`（36px）与 `UnitChromeActions`（38px）的上下垂直堆叠结构。实现**单轨标题栏（Single-Track Chrome）**：
  - 当叶窗格处于多 Tab 状态时：将标签页与动作按钮整合在同一高度为 36px 或 38px 的单轨栏内（类似现代浏览器或 VS Code 标签栏右侧内置 Action 图标）；
  - 当窗格处于单会话状态时：仅展示一次当前会话标题与项目标识，彻底消除「三重回音」现象，将垂直开销净收敛 36px。

### 2. 侧栏信息降维与「活动栏/抽屉」双态架构
- **解耦导航与列表**：
  参考 Codex 的 Activity Rail 模式，将全局功能（新对话、定时任务、扩展、设置）提炼为常驻的 48px 窄图标轨（Icon Rail）。
- **会话列表抽屉化或按需展开**：
  宽版会话列表（260px）可作为弹出式抽屉（Drawer）或折叠面板存在，主工作区常态下获得全屏沉浸感。
- **空态与低价值元素降噪**：
  - 移除「暂无项目」文本块：无项目时直接不渲染该区域，或仅在「项目」分组标题旁提供轻量的 `+` 图标按钮；
  - 展开交互升级：将「查看全部 (78)」重构为类似 Codex 的流式步进展开（如「展示更多会话」）或虚拟化平滑无限滚动，禁止在列表断口处突兀插入居中弱文字块。

### 3. 暗色模式 Token 语义回归与「主次重排」
- **彻底清理局部暗色强行提亮补丁**：
  删除 `SidebarSessionList.module.css:411-413` 与 `:436-440` 的反转规则，回归全局色彩 Token 阶梯：
  - **未选中会话标题**：统一使用 `--text-secondary`（暗色下对比度约 5.4:1，既清晰又后退）；
  - **选中会话标题**：使用 `--text-primary`（对比度 9.56:1）并搭配中等字重 500；
  - **日期与时间戳**：降级至 `--text-faint` 或 `--text-tertiary`（对比度降至 1.9:1 ~ 2.7:1），仅在当前行被 Hover 或处于 Active 态时才微调浮现，消除右侧常驻的「斑马栅栏」；
  - **选中胶囊底色强化**：提升 `--sidebar-active` 的透明叠加百分比或明度增量，使选中胶囊对底板的对比度达到 2.5:1 ~ 3.0:1 的清晰轮廓。

### 4. 快捷操作簇的语义分组与隐喻重构
- **逻辑分块隔离**：
  将当前杂糅的 4 个按钮按职责解耦为两组：
  - 【视图侧坞组】：包含预览（Webview）与文件管理（Files），放入具有胶囊背景的 Segmented Control 或紧凑 Button Group；
  - 【会话操作组】：包含更多菜单（`...`）与右侧坞开关，使用垂直分割线（Divider）或空间留白清晰隔离；
- **图标隐喻替换**：
  使用通用且明确的图标（如用浏览器窗口图标替代 Globe，用通用文件/代码图标替代具有多义性的 `folder-tree`）。
