> **分析员职责**：纯视觉层面的整体对照维度，从真实使用者第一眼体验建立客观事实基线。  
> **对比基准**：  
> - **参考界面**：Codex 桌面端暗色界面（`evidence/ref-codex.png`，1024×778）  
> - **我们界面**：Crish 桌面端暗色界面（`evidence/ours-crish.png`，1024×682）  
> **代码版本基准**：当前工作区最新源码（`apps/crish-desktop/`，暗色主题 `html[data-theme='dark']`）

## 结论摘要（先行，3-6 条）

1. **第一眼落点撕裂与锚点迷失**：Codex 的第一眼视线路径遵循极简的「左侧阅读轨 → 底部蓝色主动作（Call to Action）按钮」的单向流动；而 Crish 在第一眼瞬间爆发**三大争抢焦点的视觉冲突**——顶部重复的两道截断标题（标签页与面包屑）、正中突兀悬浮的右对齐深色气泡、底部输入框上方横贯全宽的警告条（`SetupHintBanner`），视线陷入左右横跳与上下搜索。
2. **三栏空间正交解耦 vs 单栏信息泥浆坍塌**：Codex 将界面物理划分为功能严格正交的「48px 极窄活动轨（导航）+ 582px 居中文档流（结果）+ 394px 专职看板（任务监控）」，主次分明；Crish 缺少专职子任务面板，将历史会话抽屉（200px）、长程任务执行日志、工具状态、思考用时、巨幅最终报告全部平铺挤压在单一流中，造成不可逆的视觉杂讯积压。
3. **高动态对比度 vs 人为压灰导致的「磨砂泥浆感」**：Codex 保持底板纯净（#181818，亮度 0.01）的同时，正文和活跃任务标题直接采用高对比度纯白/冷白（#FEFEFC，亮度 0.99，WCAG 对比度达 17.6:1）；而 Crish 在 `tokens.css:1142` 硬性规定 `--text-primary` 为 `color-mix(in srgb, #f5f5f5 80%, black)`（实测 #C3C3C3，对比度仅 10.4:1），辅助状态甚至跌至 #616161（对比度仅 2.97:1，严重违反 WCAG AA 4.5:1 基准），导致整个界面像蒙了一层灰尘。
4. **单垂直轴线秩序 vs 多重跳跃对齐线**：Codex 内容流严格贯彻**单垂直主轴（x=68px）**，所有图标、说明、段落、代码行首完全左对齐；Crish 存在至少 5 条错落的垂直对齐线（x=200px, 204px, 290px, 312px, 580px），加之右侧一整列冗余的折叠箭头（`>`），导致边缘线噪密度达到极高水平。
5. **字符级逻辑错位与视觉口吃**：Crish 的工具调用组件在业务逻辑上存在严重冗余（`ToolCallHeader.tsx:70`），将人类语义解释（`human`）与机器动作参数（`actionText + paramText`）强行并列平铺，产生「列出目录 crates 列出目录 crates」、「写入 inventory.json 修改 inventory.json」等肉眼可见的字符级口吃现象，极大破坏了专业工具的高级感。

## 参考界面做对了什么（具体）

### 1. 顶栏外壳：极度克制，彻底让位给工作区
- **事实观察**：Codex 顶部仅占用 40px 高度（`y: 0..40`），背景色为纯净微暗的 #202021。左侧为最轻量化的四个文字菜单（`文件 编辑 视图 帮助`），中间完全留白（留白率 91.8%），右上角为系统级最小化/最大化/关闭按钮。
- **视觉心智**：顶栏在心理模型上属于「操作系统与桌面外壳」，Codex 坚决不让会话业务标题上浮污染顶栏，使视线零停留，直接穿透到底层工作区。

### 2. 侧栏结构：48px 极窄图标导轨（Activity Bar）
- **事实观察**：宽度仅为 48px（占整屏宽度 4.69%），包含垂直居中的 8 个单色线框图标，底部以一枚橙色圆形用户徽章（"HA"）作为视觉收尾。
- **视觉心智**：在现代工作流中，99% 的注意力应该留在内容与结果中。Codex 默认将空间消耗巨大的「历史会话树」隐藏在抽屉之内，通过 48px 图标轨将 95.3% 的屏幕横向面积完整释放给主任务。

### 3. 内容流 IA：文档流排版（Notebook/Document Flow）而非聊天室
- **事实观察**：Codex 彻底摒弃了移动端聊天软件（微信/Slack）的「左右气泡式」设计。它采用类似于 Jupyter Notebook / GitHub Actions 的**连续流式文档结构**：
  - 工具调用不包外框、不加重背景，仅以一枚尺寸为 14px 的精致彩色多边形图标（青色、绿色、黄色微标）+ 单行紧凑动作（`Asset scope sync fix开始工作`）呈现；
  - 核心输出（`npm run test 已通过...`）直接融入文档正文，行高舒适，无卡片边框包裹；
  - 变更统计封装为微型胶囊（Pill：`3 个文件已更改 +14 -10`），背景为温和的低饱和深灰，配合绿色 `+14` 与红色 `-10`，信息一目了然。

### 4. 底部输入区：单一高聚合悬浮控制台（Unified Capsule）
- **事实观察**：位于 `y: 660..778`，为一块独立居中的大圆角矩形卡片（宽度 582px，圆角约 20px）。
  - 上层输入区：占位文字 "和 Codex 一起工作"（#686868）；
  - 下层动作区：将 `+` 附加、`ⓘ 完全访问` 权限胶囊、模型选择 `6 Luna Max ˅`、麦克风以及最终执行按钮完美内嵌在同一个卡片底部；
  - **唯一视觉锚点**：右下角的蓝色实心圆形按键（#2C74D9 内嵌白色 Stop 方块），形成了整个主界面中唯一的高饱和度发光点，构成了完美的视线终点（Call to Action）。

### 5. 右侧面板：专职子智能体与任务监控看板（Dedicated Inspector）
- **事实观察**：右侧开辟出 394px（占宽 38.48%）的独立面板，专用于多智能体调度与长程任务追踪：
  - 顶部清晰分段：`已开启 · 2` 与 `完成 · 20`；
  - 运行中任务以醒目的亮黄色小太阳（Recovery state review）和青色棱镜（Startup graph analysis）高亮提示，辅以运行时长（`1m 8s`）；
  - 已完成任务以时间倒序整齐排列，右侧紧贴统一的时间戳（如 `2分钟前`、`12分钟前`）。
- **视觉心智**：这彻底解决了 Agent 运行时「大量中间工具调用冲垮主聊天屏幕」的根本矛盾，将主干对话与分支任务在物理空间上实现了解耦。

## 我们的现状与根因（带证据）

### 1. 顶栏：双层标题重复渲染与纵向空间浪费
- **截图证据**：在 `evidence/ours-crish.png` 顶部：
  - 第一层（`y: 0..36`）：标签页显示 `你现在作为 Crish 核心架构自检 Ag... ×`；
  - 第二层（`y: 36..70`）：面包屑显示 `对话 / 你现在作为 Crish 核心架构自...`。
  两条长标题在纵向 34px 的间距内连续出现，两侧都被省略号生硬截断，文本重复率达 100%。
- **源码根因**：
  - 第一层由 [PaneHeader.tsx](file:///c:/Software/conex/apps/crish-desktop/src/components/binary-tree/PaneHeader.tsx#L377-L382) 渲染：属于分屏多标签页头；
  - 第二层由 [UnitChromeActions.tsx](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-card/UnitChromeActions.tsx#L246-L277) 渲染：作为对话列的 sticky 操作行。两者在单个标签且无多分屏时没有做互斥或折叠合并，强行占用了 70px 的宝贵纵向高度。

### 2. 侧栏：全功能抽屉长占 200px 且信息信噪比极低
- **截图证据**：左侧 200px（占整屏 19.53%）被 `Sidebar` 长期占据。其内部包含大量历史测试残留会话（连续 8 条重复的 `你好啊`），并且每个条目右侧散落着 `9/18`、`9/6`、`10/12` 等日期角标，边缘参差不齐。
- **源码根因**：
  - [Sidebar.module.css](file:///c:/Software/conex/apps/crish-desktop/src/components/sidebar/Sidebar.module.css#L1-L14) 将宽度锁定为 `--sidebar-width`（默认 200-240px），未提供类似 VS Code / Codex 的极简 Activity Bar 折叠态；
  - 会话列表组件缺少智能命名与会话分组收敛策略，无效测试标题直接平铺在界面首屏。

### 3. 内容流：移动端气泡残留与字符级逻辑口吃
- **截图证据 1（气泡撕裂）**：正中间出现一个右对齐的黑色圆角气泡：`上面那个是系统的指令哈，不是我说过的内容呢，这是在调试呢`。在左对齐的工具调用与代码输出之间，突然出现右对齐气泡，将使用者的视线强行拽至右侧边缘（x=580px..890px），随后又摔回左侧。
  - **源码根因**：[tokens.css](file:///c:/Software/conex/apps/crish-desktop/src/styles/tokens.css#L1115-L1119) 定义了 `--user-bubble-bg`，继承了传统移动端微信式 IM 布局，未对齐桌面开发工具的连续笔记本流范式。
- **截图证据 2（字符级口吃）**：
  - 截图文本第 1 处：`📁 列出目录 crates 列出目录 crates >`
  - 截图文本第 2 处：`🔍 搜索「pub async fn run」 Grep "pub async fn run" >`
  - 截图文本第 3 处：`📄 写入 inventory.json 修改 inventory.json +32 -0 >`
- **源码根因**：
  - 在 [ToolCallHeader.tsx](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-tool-call/ToolCallHeader.tsx#L70-L72) 中：
    ```ts
    const showHumanLabel = Boolean(
      human && human !== actionText && human !== paramText
    );
    ```
    当 `human` 为 `"列出目录 crates"`，而 `actionText` 为 `"列出目录"`、`paramText` 为 `"crates"` 时，判断条件全部为真！
  - 紧接着在 [ToolCallHeader.tsx](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-tool-call/ToolCallHeader.tsx#L117-L130) 中无脑连续渲染：
    ```tsx
    {showHumanLabel ? <span className={styles.toolHumanText}>{human}</span> : null}
    <span className={styles.toolActionText}>{actionText}</span>
    <span className={styles.toolParamText}>{paramText}</span>
    ```
    导致 `human` 与 `actionText + paramText` 产生完全相同的两遍拼接，在界面上形成了极其刺眼的文本重复！

### 4. 底部输入区：`SetupHintBanner` 截获主焦点的双卡片灾难
- **截图证据**：输入框上方横亘着一个大圆角矩形条：`🔑 首次使用请先配置服务端密钥与模型 [去配置]`（尺寸约 604×48px）。它拥有与输入框完全相同的背景（#232323）、发丝线边框（#2E2E2E）和圆角。
- **源码根因**：
  - [ChatStatusRibbons.tsx](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-card/ChatStatusRibbons.tsx#L310) 将 `<SetupHintBanner />` 挂载在主对话页脚上方；
  - [SetupHintBanner.module.css](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-card/SetupHintBanner.module.css#L17-L29) 刻意使用 `--surface-input` 背景与 `var(--soft-hint-radius)`，将其模拟成一个卡片。
  - **严重后果**：用户第一眼扫到底部时，完全无法分辨哪个是输入框、哪个是提示条；且配置引导本应是一次性或轻量 Toast，做成常驻实体卡片后，常年侵占视线首位。

### 5. 暗色色彩系统：人为压黑导致的整体混浊（Muddy UI）
- **截图证据**：在暗色背景下，Crish 的主要文字呈现暗沉的灰白，辅助文字与思考时间（`已思考 45.3s...`）甚至暗到几乎无法辨识。
- **源码根因**：
  - [tokens.css](file:///c:/Software/conex/apps/crish-desktop/src/styles/tokens.css#L1142-L1146)：
    ```css
    --user-text-primary: #f5f5f5;
    --text-primary: color-mix(in srgb, var(--user-text-primary) 80%, black); /* 实测 #C3C3C3 */
    --text-secondary: color-mix(in srgb, var(--user-text-primary) 60%, black); /* 实测 #939393 */
    --text-tertiary: color-mix(in srgb, var(--user-text-primary) 40%, black); /* 实测 #626262 */
    --text-faint: color-mix(in srgb, var(--user-text-primary) 30%, black); /* 实测 #494949 */
    ```
  - 设计意图原本是防止高对比度刺眼，但激进的 `color-mix(..., black)` 导致主要文本亮度从 1.0 骤降至 0.54，辅助文本亮度暴跌至 0.11。实测 `已思考 45.3s` 的 WCAG 对比度仅为 **2.97:1**，直接跌破 WCAG AA 要求的 4.5:1 红线！

2. **顶栏单轨化与双层标题熔断（Single-Track Title Collapse）**：
   - 重构 `PaneHeader` 与 `UnitChromeActions` 的父子架构。在单标签页或无多窗格状态下，**强行熔断第二层面包屑**，将面包屑与操作按钮向上并入顶栏单轨；
   - 标题严格实行单一真理来源（SSOT），禁止在 40px 纵向距离内两次输出相同会话名称。
3. **色彩阶梯重构与暗色高动态范围（HDR Dark Theme Architecture）**：
   - 废除在 `--text-primary` 中混入 20% 黑色的消极降级策略；
   - 确立清晰的三级暗色文字亮度阶梯：
     - 正文与高价值标题：直通 `#FFFFFF` 或 `#F8F9FA`（亮度 1.0，对比度 ≥ 15:1）；
     - 二级元数据与路径：`hsl(0 0% 75%)`（对比度 ≥ 7:1，严格满足 WCAG AAA）；
     - 三级说明与时间：`hsl(0 0% 55%)`（对比度 ≥ 4.5:1，刚性守住 WCAG AA 红线）；
   - 彻底清除整个界面「灰蒙蒙、蒙着一层泥浆」的视觉病态。
4. **对话流从「IM 聊天」向「沉浸式工程笔记本」范式转移**：
   - 废除 `--user-bubble-bg` 与居右气泡布局，统一改为主轴左对齐的工程提问块；
   - 修复 `ToolCallHeader.tsx` 的文案拼接逻辑：建立严格的语义去重流水线，当 `human` 包含或等价于 `actionText + paramText` 时，强制只输出干净的人类语义，严禁机械重复。
5. **输入区焦点锚点归一化（Unified Composer Hub）**：
   - 物理移除挂载在输入框正上方的实体卡片 `SetupHintBanner`；
   - 引导与错误提示降级为输入框内部轻量软提示（Inline Placeholder Hint）或系统级轻量 Toast，绝不形成与输入框争抢焦点的独立外壳；
   - 在输入框右下角引入高饱和度主执行色彩锚点（如品牌蓝/纯绿圆形实体按键），给使用者一个清晰明确的最终视线归宿。
