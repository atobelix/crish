# 维度 05 分析报告：对话流信息架构——过程信息 vs 结论正文

## 结论摘要

1. **视觉层级发生「倒错」：过程行排版被过度加权，正文被撕裂为碎片**
   在 2026-09-11 的排版调整中，Crish 强制将过程元素（思考行、工具调用行、折叠栏）的字号统一为 `14px`（与正文完全一致，甚至大于 Markdown 局部 `13px`），字重同为 400。加之模型「一句正文解释接一个工具调用」的输出节奏，使得主界面呈现出「一句话正文 → 一条工具行 → 一句话正文 → 一条工具行」的斑马线穿插形态。结论正文失去了段落块聚力，被喧宾夺主的过程行切碎淹没。

2. **终态折叠状态机被硬编码击穿，聚合机制在交错流中「颗粒无收」**
   既有设计案（`docs/assistant-process-folding`）虽规划了「后继有正文则默认折叠（铁律一）」与「工具聚合（铁律三）」，但落地代码 `timelineSegmenter.ts:118-131` 硬编码将所有分支设为 `defaultExpanded = true`；且组级折叠（`FoldableToolGroup.tsx:73`）门槛设为单段内 `toolCount >= 2`。由于交错输出导致每段仅含 1 个工具，组折叠与段折叠双双退化，导致 5 步自主循环直出 5 个全宽工具行，每行均拖带右侧 chevron，视觉噪音成倍放大。

3. **单条工具行视觉元素多达 7 个，且存在严重的文案重复拼接 Bug**
   Crish 工具行塞满了图标、意图文本、动作词、参数路径、差异统计（+32 -0）、执行耗时与折叠箭头共 7 个视觉元素。更严重的是，`ToolCallHeader.tsx:70-73` 存在判定缺陷，导致意图说明与动作参数无条件同时渲染，界面上直出 `列出目录 crates 列出目录 crates`、`搜索「pub async fn run」 Grep "pub async fn run"`、`写入 inventory.json 修改 inventory.json +32 -0` 等冗余文本，造成强烈的视觉混乱。

4. **暗色对比度阶梯压缩，用户气泡底色「潜行」**
   在暗色主题下，Crish 主背景为 `#141414`，正文 `--text-primary` 被 80% 压灰（#c4c4c4，WCAG 对比度 10.56:1），过程行的 `--text-tertiary` 压为 #626262（对比度仅 3.02:1，低于 WCAG AA 正常字号 4.5:1 的门槛）；用户气泡背景在主底上叠加 9% 墨色（实际约 #282828），与底色对比度仅 **1.25:1**，容器感极其微弱。而 Codex 结论文字达到接近纯白的 15.03:1，过程文字为 5.28:1，具有陡峭鲜明的前景/背景阶梯。

5. **子智能体缺乏空间隔离与色彩身份语义**
   Codex 将 20+ 个子智能体剥离至右侧独立面板（「子智能体」面板），并在对话流中通过蓝、绿、金、紫、粉等高辨识度彩色几何头像作为实体身份锚点；Crish 缺乏侧边专属面板，所有子智能体状态被迫堆叠在主对话流中，且图标均为单色灰色线性图标（或单个 `zap` 图标），无法形成扫视时的认知锚点。

## 参考界面做对了什么（具体）

参考截图：[`ref-codex.png`](file:///c:/Software/conex/docs/visual-hierarchy-clarity-analysis/evidence/ref-codex.png)

### 1. 严格执行「前景正文 - 背景元数据」的双轨信息层级
在 Codex 的对话流中，结论正文与过程信息有本质的视觉分级：
- **结论正文（Foreground）**：采用大字号（约 14-15px）、高对比度纯白文本（实测对应 RGB 约 `#ececec`，与背景对比度高达 `15.03:1`），行高保持在 1.6 左右，段间距达 12-16px，形成完整、扎实的信息块。代码关键词（如 `npm run test`、`PID 40340`）配有深灰胶囊衬底，视觉锚点明确。
- **过程信息（Background）**：字号降为约 12-13px，色彩使用柔和次级灰（约 `#8c8c8c`，对比度 `5.28:1`），**彻底取消外边框、底色卡片与行末折叠箭头（chevron）**。其视觉定位如同正文之间的「呼吸发丝记号」，完全不与正文争抢视觉焦点。

### 2. 激进且语义化的过程聚合（Aggregated Micro-actions）
Codex 避免将每一次细碎的底层系统调用暴露给用户：
- 当产生连续的文件修改与终端执行时，界面将其聚合为单行极简谓词：如「编辑了文件运行了命令」；
- 操作结果收敛为紧凑的胶囊徽章（如 `3 个文件已更改 +14 -10`），不把具体文件路径和参数指令全量平铺成多行；
- 只有在真正需要查看细节时，用户点击该行才会展开，默认状态下保持极高的信息密度。

### 3. 主对话流与长程子智能体的物理空间分离（Dual-pane Split）
Codex 将复杂的自主协作过程从线性聊天流中剥离：
- **右侧专属面板**：设立「子智能体」独立抽屉（标注「已开启 · 2」、「完成 · 20」），显示所有并行 Agent 的运行状态、实时耗时（如 `1m 8s`、`1m 37s`）与最新步骤（如 `checking modelVendor chunk size`）；
- **主对话流减负**：主时间线仅保留关键里程碑打点（如 `Asset scope sync fix 开始工作` / `已完成`），主干对话只呈现最终集成测试报告与审计记录，保证阅读链路连贯不中断。

### 4. 色彩作为「实体身份识别（Identity Anchor）」
在 Codex 中，颜色并非装饰，而是承载实体索引：
- 工具调用保持单色中性灰，不滥用颜色；
- 每一个独立子智能体拥有独一无二的**彩色几何体/花瓣矢量头像**：
  - `Asset scope sync fix`：翠绿正八面体
  - `Recovery state review`：金黄八角花瓣
  - `Eslint error cleanup`：天蓝双环绳结
  - `Import failure state`：橙红花冠
  - `Workspace gate review`：紫色微阵列
- 当用户在右侧列表与左侧主对话流之间扫视时，彩色头像构成了强烈的跨视口映射线索。

## 与其他维度的耦合点

1. **与维度 01（整体空间布局与抽屉管理）的耦合**：
   Codex 之所以能让主聊天流干净，根本原因在于其采用了「双轨空间分离」：将 20+ 个子 Agent 的实时状态与耗时全部收纳进右侧「子智能体」专属面板。Crish 目前缺少统一的侧栏运行任务宿主，所有子任务的步骤和输出只能平铺在主对话流中，造成主时间线空间负载过重。

2. **与维度 02（色彩系统与表面层级 Tokens）的耦合**：
   暗色主题下的 `--user-bubble-bg`（9% 叠加）和 `--text-primary`（80% 压黑）直接由 `tokens.css` 的全局混色规则决定。暗色阶梯对比度过小（气泡对比度 1.25:1）使得界面各区块边界模糊，正文发污。

3. **与维度 03（排版与垂直节奏）的耦合**：
   过程行的 24px 极简行高度原本是好的约束，但由于 14px 字号和 0 垂直间距的密集堆叠，与 Markdown 正文的 `1.65` 行高和段落 `margin-bottom` 形成了强烈的韵律冲突，交错出现时产生明显的视觉抖动与断裂。

4. **与维度 04（边框与微交互控制）的耦合**：
   Crish 在每一条单工具行和思维链末尾均挂载了旋转 chevron 箭头（`&#8250;`），且单工具行具备整行 hover 变黑交互。这些微交互控件在垂直方向上排成一列，将用户的注意力从左侧的正文拉扯至右侧的控制符号上。

## 架构级修复方向

> 遵循架构优雅与 SSOT 铁律，坚决杜绝魔术数字补丁。

### 1. 架构级重构：建立「轮次过程收敛器（Turn Process Convergence Engine）」
- **痛点根治**：彻底根除以「正文项」为物理边界盲目切割分段的弊病。
- **方案架构**：
  引入轮次终态收敛模型（Turn-level Convergence Pipeline）。当一条 Assistant 消息进入结算态（或已有最终结论时）：
  - 将所有中间交错的零散工具调用（Tool Calls）与状态句统一抽取，在逻辑上聚合成一个**结构化过程汇总槽（Turn Process Summary Capsule）**；
  - 默认呈现为单行极轻聚合行，如：`[图标] 已执行 5 步操作（读取、检索、修改） · 耗时 45.3s 〉`；
  - 正文部分则恢复为一个干净、无打断的连续 Markdown 文档流；
  - 只有当用户显式点击该聚合行时，才在就地或侧边栏展开原始的时间线交错执行流。

### 2. 修复 `ToolCallHeader` 的单真理源（SSOT）文案展示管线
- **痛点根治**：根除 `列出目录 crates 列出目录 crates` 的二重文本 Bug。
- **方案架构**：
  在 [`apps/crish-desktop/src/components/chat-tool-call/toolHeaderPresentation.ts`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-tool-call/toolHeaderPresentation.ts) 中建立确定性的文案裁决协议：
  ```typescript
  export interface SanitizedToolPresentation {
    /** 唯一的首要展示标签（已去重、已消解动词冗余） */
    primaryLabel: string;
    /** 次要技术参数（路径或过滤参数，与 primaryLabel 互斥） */
    secondaryParam?: string;
  }
  ```
  废除在 JSX 中同时输出 `human`、`actionText`、`paramText` 的三元拼接，确保任何单工具行至多输出一个意图标签与一个技术参数，实现 `O(1)` 的语义纯净度。

### 3. 排版尺度与暗色 Tokens 梯度校准
- **排版分级解耦**：
  - 过程元素（思维链折叠行、工具调用行）降级为辅助元数据尺度：字号固定绑定为 `--font-size-xs`（12px），字重保持 400，消除与正文争夺视觉重心的现象；
  - 结论正文恢复为主体尺度：`--font-size-base`（14px），行高 `1.65`；
  - 移除单工具行右侧的 chevron 箭头（仅在真正包含多工具折叠的聚合栏保留指示器）。
- **暗色对比度拉开**：
  - 正文 `--text-primary` 的向黑混合比例从 80% 提升至 92%~95%（对应亮度 ~#ececec），将对比度拉至 14:1 以上；
  - 用户气泡底色 `--user-bubble-bg` 的提亮幅度由 9% 提升至 14%~16%（对应约为 `#323232`），或补充发丝边框 `1px solid color-mix(in srgb, var(--user-text-primary) 12%, transparent)`，使气泡容器相对底色对比度达到 1.8:1 以上，形成明确的对话边界。

### 4. 引入 Subagent 实体色彩哈希与独立管理抽屉
- **色彩标识系统**：
  构建 `agentColorMap` 算法，根据 Subagent 的 `agent.id` 或 `agent.name` 计算确定性散列值，从 8 组高辨识度无障碍色轮（Emerald Green, Amber Gold, Cerulean Blue, Orchid Purple, Coral Rose 等）中选择主题色，搭配语义矢量几何图标；
- **空间分离机制**：
  在主界面右侧建立轻量级「任务与协作子智能体（Agent Tasks Tray）」面板，承载后台并行执行的子 Agent，解耦主时间线，使对话流专注于结论交付。
