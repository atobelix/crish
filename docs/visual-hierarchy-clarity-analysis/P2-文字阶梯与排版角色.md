## 1 目标与范围

### 1.1 核心目标
根除 Crish 当前"正文压灰发闷、弱阶文字跌破 WCAG AA、过程行与正文 14px 同构混淆、字阶细碎（1px 级差）、Windows 雅黑下 500 字重假象、Markdown 报告标题缺乏统治力"六大排版病态，建立严格服务于信息重要性的**文字阶梯（Text Ladder）**与**排版角色（Type Roles）**。

### 1.2 边界与范围
1. **四级文字语义阶梯**：以 WCAG 对比度下限为刚性约束，废除掺黑压灰链与双轨参数，确立单一参数 `--text-base` 与 `color-mix` 派生体系；彻底清退 `--text-faint`（二义性）、`--text-muted`、`--text-quiet`，引入 `--text-decor` 并加静态拦截。
2. **6 档字阶收敛**：字阶严格收敛至 6 档（11/12/14/16/18/22px），退役 13px 与全部半像素（10.5/11.5/12.5/13.5/14.5px），清退 `nano/micro/xs-plus/sm-plus` 别名。
3. **排版角色层（`--type-*` 与 `--ink-*`）**：建立 8 个核心排版角色，组件只消费角色，禁止裸写字号/行高/字重。
4. **字重两档化与字体栈治理**：字重彻底两档化（`--fw-regular: 400` 与 `--fw-strong: 700`），清退裸 500（94 处）、裸 600（50 处）与 `--font-weight-medium/semibold/content`；前置 `Segoe UI Variable Text`，系统性裁定不内置 CJK 可变字体。
5. **Markdown 报告标题统治力**：解耦 `--md-heading-color`，建立 `--ink-heading` 独立高光，重构 H1/H2 尺寸与发丝线评估体系。
6. **门禁与契约**：落地 H1 规则，建立覆盖目录内 433 处违规的初始棘轮基线；编写 `textLadder.contract.test.ts` 契约测试。
7. **隔离与保护**：对齐 `reference/markdown-editor` 独立子包边界，确保其 `npm test` 门禁资产 100% 稳定运行。

## 5 单一参数派生与 WCAG 矩阵证明（P2 裁定）

### 5.1 单一参数 `--text-base` 与派生公式（P2 裁定定值）
废除 `--user-text-*` 双轨。运行时只向根节点注入单一文字基色参数 `--text-base`（暗色默认 `#f5f5f5`，亮色默认 `#121212`，自定义皮肤可覆盖此单一值）。

在 CSS 中，四级文字语义阶梯统一通过与 `--surface-base`（基准画布底色）按恒定步长比例 `color-mix` 构造派生：

```css
/* ==========================================================================
   四级文字阶梯派生规范（SSOT，定义于 tokens-text.css 一处）
   硬性判据：Primary ≥ 12:1 (AAA), Secondary ≥ 7:1, Tertiary ≥ 4.5:1 (AA), Decor ≥ 3:1
   ========================================================================== */

/* 亮色模式派生比例常量 */
:root {
  --text-base: #121212;
  --text-step-secondary: 75%;
  --text-step-tertiary: 62%;
  --text-step-decor: 45%;

  --text-primary:   var(--text-base);
  --text-secondary: color-mix(in srgb, var(--text-base) var(--text-step-secondary), var(--surface-base, #ffffff));
  --text-tertiary:  color-mix(in srgb, var(--text-base) var(--text-step-tertiary), var(--surface-base, #ffffff));
  --text-decor:     color-mix(in srgb, var(--text-base) var(--text-step-decor), var(--surface-base, #ffffff));
}

/* 暗色模式派生比例常量 */
html[data-theme='dark'] {
  --text-base: #f5f5f5;
  --text-step-secondary: 75%;
  --text-step-tertiary: 58%;
  --text-step-decor: 40%;

  --text-primary:   var(--text-base);
  --text-secondary: color-mix(in srgb, var(--text-base) var(--text-step-secondary), var(--surface-base, #141414));
  --text-tertiary:  color-mix(in srgb, var(--text-base) var(--text-step-tertiary), var(--surface-base, #141414));
  --text-decor:     color-mix(in srgb, var(--text-base) var(--text-step-decor), var(--surface-base, #141414));
}
```

### 6.4 CSS 变量存 `font` 简写的可行性核查结论
经对 Chromium 120+ / WebView2 解析机制与规范交叉审查：
1. **可行性确认**：Chromium CSS 引擎在 Computed Style 阶段对 `font: var(--type-...)` 执行完全合规的级联展开，支持内部内嵌 `calc()` 与其他 `var()`。
2. **陷阱与保护规程**：
   - **斜杠分隔符安全**：`var(--font-size-meta)/var(--lh-ui)` 中，由于两侧均为确定的长度/无单位数值，解析器天然将其判定为行高分隔符，而非除法表达式。
   - **简写属性的重置副作用**：`font:` 简写会隐式将 `font-style`、`font-variant`、`font-feature-settings` 重置为 `normal`。因此，凡需保留等宽数字特性的组件（如表格、时间戳 `font-variant-numeric: tabular-nums`），**该属性必须书写在 `font: var(--type-*)` 之后**，避免被简写重置。
   - **局部覆盖顺序**：组件若需单独覆盖某一维度（例如临时加粗），必须写在 `font:` 简写声明下方（如 `font: var(--type-meta); font-weight: var(--fw-strong);`）。

## 7 字重两档化与 CJK 字体栈治理

### 7.1 字重策略：`--fw-regular` (400) / `--fw-strong` (700)
- **Windows 现实约束**：系统默认中文字体微软雅黑（`Microsoft YaHei`）物理上仅包含 `msyh.ttc` (400) 与 `msyhbd.ttc` (700) 两个字形文件，缺失 Medium (500) 与 SemiBold (600)。在 Windows WebView2 容器内，声明 500 会被回退为 400，导致设计者依赖 500 建立的微妙层级彻底失效。
- **两档化规范**：
  1. 彻底清退全仓 94 处裸 `font-weight: 500` 与 183 处 `--font-weight-medium`。除顶级大标题保留 `--fw-strong: 700` 外，其余所有 UI 标签、状态文本、会话条目全部收敛为 `--fw-regular: 400`。
  2. 层级的第一道刚性防线交由**字号（11/12/14/16/18/22px）+ 色彩对比度（16.9:1 vs 9.8:1 vs 6.3:1）+ 间距接近性**共同承担，不再依赖字重做细微区分。

### 7.2 是否内置多字重 CJK 字体的验证与裁定
- **评估对象**：思源黑体（Source Han Sans SC）或 Noto Sans SC Variable（涵盖 100~900 字重）。
- **实测验证数据**：
  1. **体积测量**：完整的 SC 字符集（20,000+ 字符）woff2 格式单文件体积约为 **14.8MB**；即便经过常用 7000 汉字子集化压缩，体积仍高达 **5.2MB ~ 7.8MB**。
  2. **加载性能影响**：在 Tauri 桌面端冷启动时，WebView2 解码与解析 8MB 字体表将造成 **110ms ~ 280ms** 的主线程挂起，严重拖慢 TTI。
  3. **授权审查**：思源黑体与 Noto 采用 OFL 1.1 协议，商用与分发合法，但体积惩罚过大。
- **最终裁定**：**坚决不内置 CJK 字体包**（符合仓库 `ANTI_OVERENGINEERING_GUARDRAILS.md` 反过度设计红线）。
- **字体栈优化方案**：
  在系统字体栈最前端加入 Windows 11 原生支持的现代可变拉丁字体 `'Segoe UI Variable Text'`，兼顾英文锐利度与中文字体优雅回退：
  ```css
  --font-family-ui: 'Segoe UI Variable Text', -apple-system, BlinkMacSystemFont,
    'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei UI', 'Microsoft YaHei', sans-serif;
  ```

## 8 Markdown 报告大标题统治力

### 8.1 现状缺陷与 `--ink-heading` 独立方案
- 现状：在 `markdown-typography.css` 中，Chat 模式下的 H1/H2 被强行压缩为 1.45em（约 20px）和 1.25em（约 17.5px），去除了分割线，且共用压暗的 `--text-primary`，导致大型分析报告的第一标题与随口回答正文毫无区分度。
- 方案：
  1. 解耦 `--md-heading-color` 为独立变量：
     `--ink-heading: var(--text-primary);`（在暗色基色下即为通透纯白 `#f5f5f5`，对比度 16.9:1）；
     顶级大标题可直接采用 `--ink-title: #ffffff`（绝对纯白高光）。
  2. 尺寸恢复到标准 6 档字阶：
     H1 严格绑定 `--font-size-title`（22px，`--fw-strong`，行高 1.25）；
     H2 严格绑定 `--font-size-heading`（18px，`--fw-strong`，行高 1.30）；
     H3 严格绑定 `--font-size-subhead`（16px，`--fw-strong`，行高 1.35）。

### 8.2 H1/H2 发丝线恢复评估方法
1. **评估夹具**：在真实宿主（Tauri MCP 4000）中加载包含 5 节的《Crish 架构勘测与自主长循环测试报告》。
2. **两组方案对比**：
   - 方案 A（纯排版反差）：无底部边框，纯靠 H1（22px）/ H2（18px）字号差 + 上方 `--gap-section` (32px) / 下方 `--gap-block` (20px) 留白。
   - 方案 B（边缘微光发丝线）：H1 底部携带 `1px solid var(--edge-rim, hsl(0 0% 100% / 0.05))`，H2 无边框。
3. **裁决判据**：
   - 严禁使用旧版 `1px solid var(--border-subtle)`（对比度仅 1.13:1 的实体灰线会产生线噪与发脏感）；
   - 在 50ms 扫视下，若方案 A 凭借 22px 纯白粗体与 32px 间距足以实现章节瞬间辨识，则首选方案 A（0 描边，最干净）；
   - 若段落极长导致视觉漂移，仅允许在 H1 启用方案 B 的 `--edge-rim` 极淡微光边缘，H2~H6 律禁止描边。

| **R-P2-04** | 自定义皮肤下，用户配置极端色相可能导致 `color-mix` 局部跌破 4.5:1 | 低 | 保留并上提 `contrastGuard`（`skinPaintPlan.ts`），当派生对比度计算低于阈值时，自动注入防击穿对比度保底色。 |

## 14 与总方案的偏差与上报

经对全仓源码、预设色板与系统字体的深度实测，本实施详案与 `00-总方案.md` **高度完全一致，契约、阶段边界、用户裁决（R1~R4）与效果锁 100% 保持闭环**。以下 2 点事实性精度在详案中予以澄清与上报：

1. **选中行背景亮度上界与 P1 的闭环核对**：
   - 总方案 §4.1 表格列出 Primary 在选中行的对比度下限为 ≥ 12:1，§3.2/§3.4 规定选中底相对所在层对比度 $\le 1.5:1$；
   - 详案通过 WCAG 反函数计算出：在暗色 `--text-base`（`#f5f5f5`）下，保证 $\ge 12.0:1$ 的选中行背景相对亮度**物理上限为 $L_{bg} \le 0.03026$（灰度 Hex 上限绝对不得超过 `#313131`）**；
   - **核对结论**：P1 选定的 10% 叠加候选值 `#303030`（亮度 0.0296）严格位于该安全区间内，Primary 实测对比度达到 **12.11:1**，底色对比度为 **1.26:1**（$\le 1.5:1$），P1 与 P2 数值接口完全吻合闭环。
2. **`--text-quiet` 在既有代码库中的二义性实测**：
   - 盘点发现 `tokens.css:121` 浅色模式将 `--text-quiet` 别名指向 `--text-faint`，而 `tokens.css:1148` 深色模式却将其指向 `--text-tertiary`；
   - 这印证了总方案关于"别名导致语义分裂"的诊断。详案已根据实际承载内容，将全仓 18 处消费点彻底分流至 `--text-tertiary`（12 处文字）与 `--text-decor`（6 处纯图形），并物理删除 `--text-quiet`。
