## 3. 并行域环境（极其重要）

仓库内存在**多个并行 Agent/线程**同时工作：

- **markdown-editor 域**：`reference/markdown-editor` R4 编辑器（render 事务层/outline+fold 等），高频提交（ROUND-P2）。
- **browser 域**：`crates/conex-browser`（浏览器自动化，加入 workspace members 后 **Cargo.toml 有重复 tokio 键曾被我修复**）+ `crates/conex-browser-tools`（**当前编译破坏：缺 executors_watch/max_tabs 等 8 文件未提交 M**，阻塞 cargo test --workspace）+ `apps/agent-workbench/src-tauri/src/browser/` + 前端 BrowserPanel 系。
- **multi-device 域**：`docs/multi-device` 方案 + `apps/agent-workbench/src-tauri/src/server/`（跨端 fanout 等）+ `apps/crish-mobile/`。
- **用户定时 git 线程**：用户启动的自动提交线程（防数据丢失），会把工作区未提交改动卷走提交（批次归属可能乱），**需核对提交完整性**；也做过 rescue 提交（untracked 文件补入库）。
- **stash/reset 事故历史**：并行域多次 `git stash pop` / `git reset` 引入冲突标记（`<<<<<<< Updated upstream` 等 15+ 处被我解决）、卷走/还原过我的改动（均已恢复或核验内容无损）、引入过编码损坏（TerminalCard.xterm.tsx 乱码+结构破坏，已修）。

**调度原则**：
- 实施前必 `git status` 检查目标文件是否被并行域修改（M 标记先读最新再改）。
- 提交时**精确 add 本域文件**，绝不用 `git add -A`/`git add .`（会把并行域中间态卷进来）。
- 冲突标记解决统一取"upstream（HEAD/新版）"优先；语义冲突需查实现再判。
- cargo 全量测试被并行域阻塞时，用 `cargo check -p <本域 crate>` 验证我方 Rust 面。
- 端口：5174 被 `reference/mobile-companion-app` vite 占用（并行域）；tauri MCP 调试需 `CRISH_MCP_SOCKET=1` 启动且 4000 端口空闲。

## 8. 注意事项与坑（经验清单）

1. **并行域竞争**：见 §3。提交只用精确 `git add <本域文件>`。
2. **子 Agent 空返回**：返回空两种可能（做了没回报/没做）——用 git status/文件存在性判断；任务书要求"上次空返回请务必完成"可提高成功率；仍空则主控直接做或换派。
3. **PowerShell 引号陷阱**：`${res.message}` 等 `${}` 会被 PowerShell 插值破坏 python -c 内嵌脚本——**用脚本文件（write 工具）代替内联 python -c**。
4. **文件读取显示损坏**：子 Agent 环境 Read 大文件可能行重复损坏——用 Grep（单行干净）或小批量 Read；Edit 用精确 oldString。
5. **编码问题**：仓库历史有 GBK→UTF-8 乱码固化（mojibake），check-css-encoding 只查 FFFD 检测不到乱码——第二轮 R2-1 升级门禁；新增文件必须 UTF-8 无 BOM。
6. **stash 纪律**：验证时避免 `git stash` 全量操作（并行域交叉会引入冲突标记）；用 `git checkout` 单文件或干脆不 stash。
7. **cargo 全量阻塞**：并行域 conex-browser-tools 编译破坏（缺 executors_watch/max_tabs）→ 用 `cargo check -p <本域>`；等待并行域收敛。
8. **前端既有失败面**（非本轮引入，勿误修）：快照哈希漂移（已随批次 9 更新）、并行域中间态（TiptapEditorField/useBrowserSession 等，随时变化）。
9. **用户偏好**：成功提示静默、错误必须显示且明确（"什么服务"）、重复提示收敛、组件化留扩展点（避免过度抽象）、"第一梯队"目标（需真机验证/打包/真实 Summarizer）。
10. **未决事项（后续可选）**：stability-closure 的 P0（迁移守卫 W1-W5/app_dir release 双分支/健康循环 H1-H9/降级用户可见）、release 打包+updater 闭环、真实 DeepSeek Summarizer（用户有 key）、真机冒烟（npm run smoke 未建）。
11. **测试资产铁律**：删测试/脚本前 `git ls-files` 确认已入库；`.mjs` 被 .gitignore 误伤需 `git add -f`（scripts/ 白名单已部分放行）。
