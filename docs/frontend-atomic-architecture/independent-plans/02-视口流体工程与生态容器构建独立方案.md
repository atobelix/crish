在现代智能体协作开发桌面平台 Conex / Crish（底层基于 Rust 异步高性能事件引擎、中层依托 Tauri 宿主通道、上层承载 WebView2 React 18 现代化前端）中，人机交互的绝大部分心智流转发生在**AI 对话流响应视口**、**层级调度浮层** 以及 **高维复合工程容器** 之中。

### 1.2 冷中性黑白灰工业美学底座与色彩阶梯矩阵

为了彻底根除长期以来界面中存在的“脏感”、“泥黄感”与“艳俗杂色感”，本方案确立纯粹冷中性黑白灰的最高视觉准绳：

1. **色彩空间严格规范**：
   - 杜绝散落的 `rgba(r, g, b, a)`，全面拥抱现代 CSS Color Level 4 语法：`hsl(h s l / a)` 或 `color-mix(in srgb, ...)`；
   - 浅色模式（Light Mode）采用纯冷白底层（`hsl(0 0% 100%)`）与极淡微冷灰卡片底色（`hsl(220 14% 98%)`）；
   - 深色模式（Dark Mode）采用纯净深空冷灰（`hsl(220 13% 10%)` ~ `hsl(220 13% 14%)`），彻底拔除 `themeStore.ts` 注入的暖黄泥色内联样式；
2. **状态色彩降噪法则**：
   - 常规状态（模型切换、系统注入、工具调度、思维链推进）一律使用冷中性灰度表现，禁止使用亮绿、荧光青、亮橙、鲜紫等大面积色块；
   - 仅当发生硬件级或物理磁盘耗尽等致命阻断时，才允许使用克制的语义警示红（`hsl(0 65% 52%)`）。

| 色彩角色 Token | 浅色模式（Light Mode） | 深色模式（Dark Mode） | 语义用途与层级约束 |
| :--- | :--- | :--- | :--- |
| `--bg-canvas` | `hsl(0 0% 100%)` | `hsl(220 13% 10%)` | 桌面最底层画布背景 |
| `--bg-surface` | `hsl(220 14% 98%)` | `hsl(220 13% 13%)` | 消息行、卡片与工具视口底色 |
| `--hairline` | `hsl(220 13% 90% / 0.8)` | `hsl(220 13% 22% / 0.8)` | 1px 物理发丝级极细边框 |
| `--border-subtle` | `hsl(220 13% 86%)` | `hsl(220 13% 26%)` | 容器外框与分割线基线 |
| `--text-primary` | `hsl(220 20% 12%)` | `hsl(220 15% 94%)` | 标题与高对比正文 |
| `--text-secondary` | `hsl(220 10% 40%)` | `hsl(220 10% 68%)` | 辅助说明与工具输出文本 |
| `--text-tertiary` | `hsl(220 8% 60%)` | `hsl(220 8% 46%)` | 时间刻度与微分割线标注 |

### 1.3 焦点态与激活态克制对比度（≤10%）数学模型与样式实现

依据仓库协作指令 `AGENTS.md` §13，任何输入框、可交互行、按钮或药丸在获得焦点（Focus）、激活（Active）或悬停（Hover）时，**禁止使用深黑、粗实实线边框**（如直接使用 `var(--text-primary)` 或外挂 `0 0 0 2px black`）。

#### 数学混合公式：
$$\text{BorderColor}_{\text{focused}} = \text{color-mix}\left(\text{in srgb}, \text{var}(--\text{border-subtle})\; (100 - X)\%,\; \text{var}(--\text{text-primary})\; X\%\right)$$
其中加深混入度 $X$ 严格约束在：
$$3\% \le X \le 8\% \quad (\text{硬性上限 } X_{\max} = 10\%)$$

#### 标准样式实现模版：
```css
/* 标准克制焦点与激活态实现 */
.interactiveElement {
  border: 1px solid var(--border-subtle);
  background-color: var(--bg-surface);
  transition: border-color var(--transition-fast, 150ms ease),
              background-color var(--transition-fast, 150ms ease);
}

.interactiveElement:focus-visible {
  outline: none;
  /* 严格控制加深混入度在 6%~8% 量级，呈现出柔软、微灰、肉眼可辨但不刺眼的勾勒 */
  border-color: color-mix(
    in srgb,
    var(--border-subtle) 92%,
    var(--text-primary) 8%
  );
}
```

### 1.4 六大刚性底线红线穿透

1. **输入框（Composer）绝对保护边界**：`apps/crish-desktop/src/components/chat-composer/` 目录下全部文件为神圣不可侵犯的基石，代码变动行数严格为 0 行；
2. **纯粹逻辑推进，同权平铺**：严禁按业务价值将问题划分为 P0/P1 并放弃修复任何已识别问题；所有列出问题在逻辑架构上同权推进；
3. **严禁波次/批次命名**：提交信息与任务书严禁出现 `Wave *`、`Batch *` 等字眼，统一采用语义化领域标记（如 `feat(status-divider)`、`cleanup(injection)`）；
4. **先删后改，收敛优先**：每个任务单元在落地新原语前，必须首先物理删除依赖的旧路径、旧类名与冗余逻辑，确保交付后整体代码量实现净负增长（净删除 $\ge 3,500$ 行）；
5. **单轮 Agent 派发规模约束**：单轮调度子 Agent 数量严格保持在 **5–12 个**，任意时刻同时存活未终态 Agent $\le 16$，同父 $\le 16$，递归深度严格限制为 1；
6. **零盲目补偿与作弊代码**：严禁使用 `setTimeout(..., 300)` 延时盲猜、坐标硬编码测距补偿、或通过 `--no-verify` 跳过代码门禁。

## 二、多 Agent 协同治理闭环框架与调度协议

### 2.1 六步标准自循环流水线闭环详解

为了实现跨轮次、高并发、自愈合的多 Agent 协同工程治理，本方案建立标准化的自循环流水线闭环：

```
┌────────────────────────────────────────────────────────────────────────┐
│                   多 Agent 协同自闭环流水线（六步自闭环）                │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 精确问题识别 (Problem Identification)                                │
│    - 读取代码实勘证据，提取组件物理文件路径与具体破坏行号；                │
│    - 标记架构断层：如 168px 矮盒卡死、展开取反漏洞、Fenwick 缺失等。       │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 2. 纯逻辑任务分解 (Task Decomposition)                                 │
│    - 拆解为完全正交、互无文件读写冲突的原子任务单元 (Task Units)；           │
│    - 严格划定每个单元的「删除面清单」与「构建产出物白名单」。              │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 3. Agent 隔离分配 (Agent Allocation: 5–12 个)                          │
│    - 单轮按领域派发 5–12 个专职子 Agent（深度恒为 1，无派发工具）；        │
│    - 明确传入：输入文档基准、改动文件白名单、删除清册与验收标准。            │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 4. 并行修复与现场自测 (Parallel Execution & Verification)              │
│    - 子 Agent 严格遵守“先删后改”，落盘代码；                           │
│    - 运行针对性单元测试与 TypeScript 检查；禁止调用 git commit。          │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 5. 结果聚合与统一收口 (Result Aggregation & Master Commit)              │
│    - 主控审查改动完整度，排查文件冲突；                                    │
│    - 主控使用 `git commit --only <paths>` 进行领域级单原子提交。            │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 6. 立体验收与下一轮输入 (Stereo Verification & Next Iteration)         │
│    - 运行全量 TypeScript、Vitest 单测与 CI 门禁脚本；                      │
│    - 生成本轮收敛台账，未尽长尾问题直接格式化为下一轮输入。                  │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.2 单轮 5–12 Agent 协同调度准则与拓扑结构

依据仓库协作指令 `AGENTS.md` §2，调度必须贯彻以下准则：
- **数量区间**：每轮派发子 Agent 数量严格保持在 **5 至 12 个**；
- **存活守卫**：任意时刻全局存活（未进入终态）Agent $\le 16$，同父 $\le 16$；
- **深度防线**：递归深度严格为 1，子 Agent 的工具注册表彻底移除 `run_subagent`，杜绝递归派发诱发死锁；
- **运行环境**：子 Agent 执行命令统一采用 **pwsh7（PowerShell 7+）**，文本文件保存统一采用 UTF-8 无 BOM。

### 2.3 状态上报、空返回分级容错与接管阈值协议

根据 `AGENTS.md` §2 与实践经验，子 Agent 在遭遇供应商网络抖动或超长输出时可能出现空返回（无最终消息或无产出）。主控 Agent 必须按以下四级阶梯分级处理：
1. **落盘优先核查**：子 Agent 出现空返回时，**默认是供应商网络超时而非任务失败**；主控优先核查目标文件是否已经物理写入磁盘，并执行 `git status` 确认工作区改动；
2. **1–3 次空返回（接续原会话）**：若未落盘或未完工，优先使用 `task_id` 接续原 Agent 会话继续执行；
3. **4–6 次空返回（细化拆分重派）**：若接续仍然失败，将任务拆分为单文件/单组件粒度，重新分配新子 Agent 推进；
4. **6 次以上连续失败（主控接管）**：累积空回超过 6 次，主控 Agent 直接接管该任务的代码编写与落盘，确保战役绝不卡死。

### 2.4 多轮迭代数据接力协议与状态持久化

跨轮次治理必须具备状态自愈与数据接力能力：
- **状态持久化**：每轮收口完成后，在 `docs/frontend-atomic-architecture/execution-logs/` 目录记录结构化日志（包含变更路径、删除行数、新增测试用例及依赖关系）；
- **动态依赖图更新**：下一轮启动时，主控读取最新的 Git 状态与已删除文件索引，自动排除已消灭的死路径，动态计算下一轮无冲突的并行任务集；
- **收敛核算断言**：每轮结算时自动核算全仓代码净增量，确保净收敛（负增长）指标持续推进。

### 2.5 严格文件互斥隔离与串行归口机制

为了杜绝多 Agent 并行时的写文件踩踏与 Git 冲突：
1. **文件所有权独占原则**：同一个物理源码文件在同一轮次中**严禁分配给两个或以上的 Agent**；
2. **样式与组件绑定归属**：若某组件包含 `.tsx`、`.module.css` 与 `.test.tsx`，必须作为一个原子包完整分配给同一个 Agent，严禁样式与结构分离派发；
3. **公共 Barrel 文件（index.ts）由主控统一串行收口**：如 `@/components/ui/index.ts`，各子 Agent 仅在各自子目录编写完整导出，由主控统一登记导出，杜绝 Git 合并冲突。

```tsx
import React, { memo } from 'react';

export type StatusDividerKind =
  | 'model-switch'      // 模型切换事件
  | 'permission-change' // 权限模式变更
  | 'env-inject'        // 环境变量注入

  timestamp?: number;
  className?: string;
  'data-testid'?: string;

  switch (kind) {

};

  id,
  kind = 'general',
  text,
  timestamp,
  className = '',

}) => {

      </div>
      <div className={styles.line} aria-hidden />
    </div>
  );

StatusDivider.displayName = 'StatusDivider';
```

### 5.4 LayerStackManager 全局单例调度中枢（LIFO 退栈与 IME 门闩）

#### 5.4.1 核心职能
调度管理 Dialog、ConfirmDialog、Popover、Tooltip、DropdownMenu、ContextDialog 等所有全局浮层，彻底解决以下三大生产事故：
1. **多层并存 ESC 键竞争全关**：用户在打开二级确认弹窗后按下 ESC，外层 Dialog 与内层 ConfirmDialog 同时关闭；
2. **CJK IME 中文输入法 229 选词误关**：用户在输入框使用拼音打字按下 ESC 取消选词，外层浮层直接被粗暴关闭；
3. **50ms 连击穿透抖动**：双击关闭或双击打开按钮导致状态机震荡闪烁。

#### 5.4.2 核心状态机实现规格代码

```typescript
/**
 * apps/crish-desktop/src/components/ui/internal/layer-stack/LayerStackManager.ts
 * 浮层调度中枢单核状态机 (LayerStackManager)
 */
export interface LayerRegistration {
  id: string;
  layerType: 'dialog' | 'popover' | 'tooltip' | 'menu';
  dismissOnEscape?: boolean;
  onDismiss: (reason: 'escape' | 'pointer-outside') => void;
  mountedAt?: number;
}

export class LayerStackManager {
  private static instance: LayerStackManager | null = null;
  private layers: LayerRegistration[] = [];
  private lastCloseTimestamp = 0;
  private sequence = 0;

  private constructor() {
    this.attachGlobalListeners();
  }

  public static getInstance(): LayerStackManager {
    if (!LayerStackManager.instance) {
      LayerStackManager.instance = new LayerStackManager();
    }
    return LayerStackManager.instance;
  }

  public register(layer: Omit<LayerRegistration, 'mountedAt'>): () => void {
    const fullLayer: LayerRegistration = {
      ...layer,
      mountedAt: ++this.sequence,
    };
    this.layers.push(fullLayer);

    return () => {
      this.layers = this.layers.filter((l) => l.id !== layer.id);
    };
  }

  private attachGlobalListeners(): void {
    if (typeof window === 'undefined') return;
    window.addEventListener('keydown', this.handleKeyDown, { capture: true });
  }

  private handleKeyDown = (e: KeyboardEvent): void => {
    // 1. CJK 中文输入法合成锁刚性放行（keyCode 229 或 isComposing）
    if (e.isComposing || e.keyCode === 229 || e.key === 'Process') {
      return;
    }

    if (e.key === 'Escape') {
      // 2. 50ms 连击防抖锁
      const now = Date.now();
      if (now - this.lastCloseTimestamp < 50) return;

      // 3. LIFO 倒序严格单层退栈
      if (this.layers.length > 0) {
        const topLayer = this.layers[this.layers.length - 1];
        if (topLayer.dismissOnEscape !== false) {
          e.preventDefault();
          e.stopPropagation();
          this.lastCloseTimestamp = now;
          topLayer.onDismiss('escape');
        }
      }
    }
  };
}
```

### 6.2 多媒体画廊 ZoomPan 手势平移缩放变换容器

#### 6.2.1 架构设计思想

5. **叶内受控最大化（Leaf-Bounded Maximized Mode）**：支持在当前工作区分屏视窗内一键铺满，严禁破坏宿主分屏。

```tsx
/**
 * ZoomPan 几何变换引擎核心公式
 */
function calculateZoomPivot(
  prevScale: number,
  nextScale: number,
  cursorX: number,
  cursorY: number,
  prevTranslateX: number,
  prevTranslateY: number
) {
  const scaleRatio = nextScale / prevScale;
  const nextTranslateX = cursorX - (cursorX - prevTranslateX) * scaleRatio;
  const nextTranslateY = cursorY - (cursorY - prevTranslateY) * scaleRatio;
  return { nextTranslateX, nextTranslateY };
}
```

### 6.3 基于 Fenwick Tree 动态行高的高性能 DiffViewer 架构

#### 6.3.1 几何错位根因解密
在 `DiffCardUnifiedView.tsx:118` 与 `DiffCardSplitView.tsx` 中：

然而在第 30 行与第 47 行，代码行均开启了：
```css

```
**致命矛盾**：一旦视口变窄或代码行字符较长，长行会自动折行变成 2 行（44px）、3 行（66px）甚至更高。但虚拟列表调度引擎依然愚蠢地按固定的 22px 计算偏移量（`offsetTop = startIndex * 22`），导致：
1. 随着向下滚动，真实物理高度与虚拟高度偏差急剧累积；
2. 虚拟视口中的行出现严重堆叠覆盖、重影；
3. **长文件底部的大量差异代码直接被虚拟视口截断吞噬，用户完全无法审查！**

#### 6.3.2 树状数组（Fenwick Tree）动态行高索引模型
引入数学上时间复杂度最优的树状数组（Binary Indexed Tree / Fenwick Tree）：
- **前缀和查询（Query Prefix Sum）**：$O(\log N)$ 复杂度算出任意第 $k$ 行的物理 `offsetTop`；
- **单点更新（Point Update）**：当某一折行通过 ResizeObserver 测量出真实高度变化时，$O(\log N)$ 复杂度更新整棵树；
- **视口定位（Locate Visible Index）**：在树状数组上执行倍增二分查找（Binary Lifting），以 $O(\log N)$ 极速定位当前视口内的起始行。

#### 6.3.3 核心实现代码：`FenwickRowHeightManager.ts`

```typescript
/**
 * apps/crish-desktop/src/components/diff/FenwickRowHeightManager.ts
 * 基于树状数组的高性能动态行高几何解算器（彻底解决折行虚拟列表截断问题）
 */
export class FenwickRowHeightManager {
  private size: number;
  private tree: Float64Array;
  private heights: Float64Array;
  private defaultHeight: number;

  constructor(itemCount: number, defaultHeight = 22) {
    this.size = itemCount;
    this.defaultHeight = defaultHeight;
    this.tree = new Float64Array(itemCount + 1);
    this.heights = new Float64Array(itemCount);

    // 初始化：单点全量填充默认高度
    for (let i = 0; i < itemCount; i++) {
      this.heights[i] = defaultHeight;
    }
    // 线性 O(N) 批量构树
    for (let i = 1; i <= itemCount; i++) {
      this.tree[i] += defaultHeight;
      const parent = i + (i & -i);
      if (parent <= itemCount) {
        this.tree[parent] += this.tree[i];
      }
    }
  }

  /**
   * 单点高度更新：当 ResizeObserver 测出实际行高与预期不符时触发
   */
  public updateHeight(index: number, newHeight: number): void {
    if (index < 0 || index >= this.size) return;
    const delta = newHeight - this.heights[index];
    if (Math.abs(delta) < 0.5) return; // 0.5px 微扰动阈值防抖

    this.heights[index] = newHeight;
    let i = index + 1;
    while (i <= this.size) {
      this.tree[i] += delta;
      i += i & -i;
    }
  }

  /**
   * 查询第 0 到 index-1 行的总高度（即第 index 行的物理 offsetTop）
   * 复杂度：O(log N)
   */
  public getOffsetTop(index: number): number {
    if (index <= 0) return 0;
    if (index >= this.size) index = this.size;
    let sum = 0;
    let i = index;
    while (i > 0) {
      sum += this.tree[i];
      i -= i & -i;
    }
    return sum;
  }

  /**
   * 获取列表总物理高度
   */
  public getTotalHeight(): number {
    return this.getOffsetTop(this.size);
  }

  /**
   * 根据当前视口 scrollTop，利用倍增二分法定位当前可见第一行索引
   * 复杂度：O(log N)
   */
  public findStartIndex(scrollTop: number): number {
    if (scrollTop <= 0) return 0;
    let idx = 0;
    let currentSum = 0;
    // 2 的最大幂次向下寻找
    const maxPower = 1 << Math.floor(Math.log2(this.size || 1));
    for (let step = maxPower; step > 0; step >>= 1) {
      if (idx + step <= this.size && currentSum + this.tree[idx + step] <= scrollTop) {
        idx += step;
        currentSum += this.tree[idx];
      }
    }
    return Math.min(idx, this.size - 1);
  }
}
```

```tsx
/**
 * apps/crish-desktop/src/components/settings-mcp/EnvVariableTable.tsx
 * 环境变量 Key-Value 动态编辑组件（打通后端 McpServerConfig.env 契约）
 */
import React, { useState, useCallback, memo } from 'react';
import { Plus, Trash2, Eye, EyeOff } from 'lucide-react';
import styles from './EnvVariableTable.module.css';
import { Button, Input, IconButton } from '../ui';

export interface EnvEntry {
  id: string;
  key: string;
  value: string;
  isSecret?: boolean;
}

export interface EnvVariableTableProps {
  value: Record<string, string>;
  onChange: (env: Record<string, string>) => void;
  disabled?: boolean;
}

export const EnvVariableTable: React.FC<EnvVariableTableProps> = memo(({
  value,
  onChange,
  disabled = false,
}) => {
  const [entries, setEntries] = useState<EnvEntry[]>(() =>
    Object.entries(value || {}).map(([k, v], i) => ({
      id: `${Date.now()}-${i}`,
      key: k,
      value: v,
      isSecret: k.toLowerCase().includes('token') || k.toLowerCase().includes('key') || k.toLowerCase().includes('secret'),
    }))
  );

  const syncUp = useCallback((list: EnvEntry[]) => {
    const record: Record<string, string> = {};
    list.forEach((e) => {
      const trimmedKey = e.key.trim();
      if (trimmedKey) record[trimmedKey] = e.value;
    });
    onChange(record);
  }, [onChange]);

  const handleAddRow = () => {
    const next = [...entries, { id: `env-${Date.now()}`, key: '', value: '', isSecret: false }];
    setEntries(next);
    syncUp(next);
  };

  const handleRemoveRow = (id: string) => {
    const next = entries.filter((e) => e.id !== id);
    setEntries(next);
    syncUp(next);
  };

  const handleUpdateKey = (id: string, newKey: string) => {
    const next = entries.map((e) => (e.id === id ? { ...e, key: newKey } : e));
    setEntries(next);
    syncUp(next);
  };

  const handleUpdateValue = (id: string, newVal: string) => {
    const next = entries.map((e) => (e.id === id ? { ...e, value: newVal } : e));
    setEntries(next);
    syncUp(next);
  };

  const handleToggleSecret = (id: string) => {
    setEntries((prev) => prev.map((e) => (e.id === id ? { ...e, isSecret: !e.isSecret } : e)));
  };

  return (
    <div className={styles.tableRoot}>
      <div className={styles.tableHeader}>
        <span className={styles.headerTitle}>环境变量 (Environment Variables)</span>
        <Button
          type="button"
          size="sm"
          variant="ghost"
          icon={<Plus size={12} />}
          onClick={handleAddRow}
          disabled={disabled}
        >
          添加变量
        </Button>
      </div>

      <div className={styles.entryList}>
        {entries.length === 0 ? (
          <div className={styles.emptyTip}>暂无环境变量配置（如 GITHUB_TOKEN、DATABASE_URL）</div>
        ) : (
          entries.map((entry) => (
            <div key={entry.id} className={styles.entryRow}>
              <Input
                size="sm"
                placeholder="KEY (如 API_KEY)"
                value={entry.key}
                onChange={(e) => handleUpdateKey(entry.id, e.target.value)}
                disabled={disabled}
                className={styles.keyInput}
              />
              <div className={styles.valInputWrap}>
                <Input
                  size="sm"
                  type={entry.isSecret ? 'password' : 'text'}
                  placeholder="VALUE"
                  value={entry.value}
                  onChange={(e) => handleUpdateValue(entry.id, e.target.value)}
                  disabled={disabled}
                />
                <button
                  type="button"
                  className={styles.eyeBtn}
                  onClick={() => handleToggleSecret(entry.id)}
                  title={entry.isSecret ? '显示明文' : '隐藏密文'}
                >
                  {entry.isSecret ? <EyeOff size={12} /> : <Eye size={12} />}
                </button>
              </div>
              <IconButton
                size="sm"
                variant="ghost"
                icon={<Trash2 size={12} />}
                onClick={() => handleRemoveRow(entry.id)}
                disabled={disabled}
                aria-label="删除此行"
              />
            </div>
          ))
        )}
      </div>
    </div>
  );
});

EnvVariableTable.displayName = 'EnvVariableTable';
```

```typescript
 * apps/crish-desktop/src/components/diff/__tests__/FenwickRowHeightManager.test.ts
 */
import { describe, it, expect } from 'vitest';
import { FenwickRowHeightManager } from '../FenwickRowHeightManager';

describe('FenwickRowHeightManager', () => {
  it('应正确初始化默认行高与总高度', () => {
    const manager = new FenwickRowHeightManager(100, 22);
    expect(manager.getTotalHeight()).toBe(2200);
    expect(manager.getOffsetTop(0)).toBe(0);
    expect(manager.getOffsetTop(1)).toBe(22);
    expect(manager.getOffsetTop(10)).toBe(220);
  });

  it('单点高度更新后，前缀和应正确且高效反映累积高度', () => {
    const manager = new FenwickRowHeightManager(10, 20);
    // 将第 2 行折行高度从 20 变为 60 (+40)
    manager.updateHeight(2, 60);

    expect(manager.getOffsetTop(2)).toBe(40); // 0, 1 行不受影响
    expect(manager.getOffsetTop(3)).toBe(100); // 0, 1, 2 行: 20 + 20 + 60 = 100
    expect(manager.getTotalHeight()).toBe(240); // 原始 200 + 40 = 240
  });

  it('倍增二分法应精准在 O(log N) 复杂度内定位视口第一行', () => {
    const manager = new FenwickRowHeightManager(100, 20);
    manager.updateHeight(5, 80); // 第 5 行高度变成 80

    expect(manager.findStartIndex(0)).toBe(0);
    expect(manager.findStartIndex(40)).toBe(2);
    expect(manager.findStartIndex(100)).toBe(5);
    expect(manager.findStartIndex(150)).toBe(5);
    expect(manager.findStartIndex(180)).toBe(6);
  });

  it('压力边界：50,000 行大数组高频单点更新与查询延迟应 <0.1ms', () => {
    const N = 50000;
    const manager = new FenwickRowHeightManager(N, 22);
    const start = performance.now();
    for (let i = 0; i < 1000; i++) {
      manager.updateHeight(i * 45, 44);
      manager.getOffsetTop(i * 45 + 10);
      manager.findStartIndex(i * 800);
    }
    const duration = performance.now() - start;
    expect(duration).toBeLessThan(100); // 1000 次操作耗时严格小于 100ms
  });
});
```
