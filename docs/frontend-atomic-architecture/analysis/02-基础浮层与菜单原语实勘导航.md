### 2.1 Dialog.tsx 架构与生命周期解构

`Dialog.tsx`（237 行）是全仓模态交互的最高权威基座。其核心职责是将 React 虚拟 DOM 挂载至 Portal 根节点（优先 `#modal-root`，回退 `document.body`），并在容器内协同编排遮罩背景、内容面板、头部、标题、描述、关闭按钮、操作底部等关键解构槽位。

其运行时 DOM 拓扑树如下所示：

```html

  <div data-focus-trap="true" style="display: contents;">
    <div class="Dialog_overlayEnter__xxx" data-dialog-overlay="">
      <!-- 遮罩背景：响应点击 dismissible 关闭 -->
      <div class="Dialog_backdrop__xxx" aria-hidden="true"></div>

      <!-- 弹窗物理面板 -->
      <div
        role="dialog | alertdialog"
        aria-modal="true"
        aria-labelledby="«titleId»"
        aria-describedby="«descriptionId»"
        class="Dialog_dialog__xxx Dialog_dialogMd__xxx Dialog_dialogEnter__xxx [customPanelClass]"
      >
        <!-- 头部插槽：标题与右上角关闭按钮 -->
        <div class="Dialog_dialogHeader__xxx">
          <h2 id="«titleId»" class="Dialog_dialogTitle__xxx">...</h2>

        </div>
```

#### 关键实现技术点：
1. **三件套原生装配**：组件内部天然装配 `useAnimatedPresence`（进出场动画双阶段驱动）、`useRestoreFocus`（退栈焦点还原）与 `FocusTrap`（物理焦点圈定与 inert 隔离），业务消费方无需感知繁琐的状态同步。
2. **LayerStackManager 深度集成**：第 113-124 行调用 `useLayerRegistration`，向调度中枢登记自身的生命周期（类型映射为 `modal-dialog` 或 `confirm-dialog`，标记 `modal: true`），在中枢层接管全局 Esc 键事件。
3. **DismissableLayer 分支标记**：最外层包裹 `@radix-ui/react-dismissable-layer` 的 `<DismissableLayer.Branch asChild>`，使 Radix 下拉菜单与浮层能够准确感知自己处于合法分支内，避免将 Dialog 判定为外部点击。

### 2.4 dialogOverlayContext.ts 局部层叠穿透机制

源码仅 8 行，却扮演着跨组件层级穿透的枢纽角色：
```typescript
import { createContext } from 'react';

export const DialogOverlayContext = createContext<HTMLElement | null>(null);
```

#### 架构断层根因与解法：
- **痛点场景**：全局规范中，弹窗模态层层级为 `--z-modal: 1000`，而下拉菜单与选择器层级为 `--z-dropdown: 300`。如果在模态对话框内部（或全屏设置页 SettingsPanel 中）嵌入 `Select` 或 `Menu`，若浮层直接 Portal 到 `document.body`，其 z-index (300) 会被 Dialog 遮罩壳 (1000) 彻底掩埋在下方，导致用户点击下拉框时菜单不可见。
- **历史错误做法**：粗暴抬高全仓 `--z-dropdown` 至 1100，破坏了全局分层拓扑。
- **优雅解法**：`Dialog.tsx` 在遮罩外壳绑定 `ref={setOverlayEl}`，并通过 `<DialogOverlayContext.Provider value={overlayEl}>` 向下广播自身的 DOM 实例。位于其内部的 `Menu.tsx` 与 `SelectContent.tsx` 通过 `useContext(DialogOverlayContext)` 自动获取该节点，并将自身 Portal 挂载到该 overlay 节点下。由于与 Dialog 处于同一局部层叠上下文中，局部 z-index (300) 即可天然压过 Dialog 面板，完美解决了层叠死锁。

### 2.5 focusTrap.tsx 引用计数隔离引擎与白名单放行

`focusTrap.tsx`（269 行）是全仓键盘无障碍与焦点安全的绝对基石。它彻底重构了朴素的 FocusTrap 循环，引入了基于引用计数的沙盒隔离状态机：

#### 1. `FocusTrapIsolationManager` 核心数据结构：
```typescript
class FocusTrapIsolationManager {
  private static instance: FocusTrapIsolationManager;
  private trapStack: HTMLElement[] = [];
  private inertCounts = new Map<Element, number>();
  private snapshots = new Map<Element, InertSnapshot>();
  ...
}
```
- **多层嵌套隔离**：维护 `trapStack` 栈。当弹窗 A 打开时，将 body 下除 A 以外的节点打上 `inert` 与 `aria-hidden="true"`；当弹窗 A 内部再弹出二次确认框 B 时，弹窗 A 自身也被打上 `inert` 暂时冻结；当 B 关闭时，A 恢复交互。`inertCounts` 计数器确保节点在被多层 Trap 引用时不会提前失活。

#### 2. 白名单旁路机制（Whitelist Bypass）：
为了防止动态挂载到 `document.body` 的临时气泡浮层被 Dialog 错误打上 `inert` 导致无法交互，第 63-84 行硬编码了放行谓词：
```typescript
private isWhitelisted(node: Element): boolean {
  if (
    node.hasAttribute('data-radix-popper-content-wrapper') ||
    node.getAttribute('data-tooltip-portal') === 'true' ||
    node.getAttribute('data-toast-container') === 'true' ||
    node.classList.contains('radix-popper-content-wrapper') ||
    node.classList.contains('toaster') ||
    node.id === 'toast-portal' ||
    node.id === 'tooltip-portal' ||
    // 自研 Select / Combobox 原子浮层白名单放行
    node.getAttribute('data-slot') === 'select-content' ||
    node.getAttribute('data-slot') === 'combobox-content' ||
    node.getAttribute('role') === 'listbox' ||
    node.hasAttribute('data-floating-layer') ||
    node.querySelector?.(
      '[data-slot="select-content"], [data-slot="combobox-content"], [role="listbox"], [data-floating-layer]'
    ) != null
  ) {
    return true;
  }
  return false;
}
```

### 3.3 position.ts 纯数学坐标定位与双向刚性钳位引擎

`position.ts`（437 行）是全仓自研的浮层几何计算核心，彻底消灭了浮层在边界处反复翻转的「Double Flip」恶疾：

#### 1. Windows 11 无边框最大化 8px 溢出感知（`getEffectiveViewport`）：
在 Windows 系统下，无边框（Frameless）窗口最大化时，系统会在四周留出 8px 的不可见渲染缓冲区。如果不做处理，浮层如果贴边计算，会有 8px 被裁剪到屏幕外。
```typescript
if (isWindows && isMaximized) {
  return {
    width: Math.max(320, rawW - 16),
    height: Math.max(200, rawH - 16),
    offsetLeft: 8,
    offsetTop: 8,
  };
}
```
该函数自动感知 `html[data-window-maximized='true']`，精准补偿四周 8px，为全仓浮层提供了绝对真实的物理视口边界。

#### 2. 不可变防抖单源计算（`calculateMenuPosition`）：
- **决策模型**：分别对垂直轴（`spaceBelow`, `spaceAbove`）与水平轴（`spaceRight`, `spaceLeft`）进行单向空间判定。只有当目标方向放不下且反向空间**严格大于**当前方向时才触发翻转（Flip）。
- **刚性安全钳位**：
  ```typescript
  const clampedX = Math.min(Math.max(offsetLeft + edgePadding, targetX), Math.max(offsetLeft + edgePadding, offsetLeft + vp.width - menuWidth - edgePadding));
  const clampedY = Math.min(Math.max(offsetTop + edgePadding, targetY), Math.max(offsetTop + edgePadding, offsetTop + vp.height - menuHeight - edgePadding));
  ```
- **动画 Origin 联动**：翻转后自动将 `transformOrigin` 翻转（如实际向上展开时设为 `'bottom left'`），保证进场形变始终从锚点方向喷射。

#### 3. 二级级联子菜单几何定位（`calculateSubmenuPosition`）：
- **双向刚性数学钳位不变式（Two-Way Clamping Invariant）**：默认优先向左展开（适应侧边栏在右侧的常见布局）；当左侧放不下且右侧空间更大时翻转至右侧；
- 钳位边界绝对满足：`minX <= clampedX <= maxX - submenuWidth` 与 `minY <= clampedY <= maxY - submenuHeight`，彻底杜绝负坐标与右侧溢出。

#### 4. 测量抗形变（`measureAndCalculateMenuPosition`）：
使用 `offsetWidth`/`offsetHeight` 而非 `getBoundingClientRect().width`，免疫 CSS scale(0.96) 进场动画引起的尺寸畸变测量。

### 4.4 tooltipPositioning.ts 严格几何校验与 4 向智能翻折算法

`tooltipPositioning.ts`（242 行）将 Tooltip 的碰撞解算抽离为零 React 依赖的纯几何函数：

## 七、底层调度中枢与几何守卫实勘（ui/internal）

### 7.1 LayerStackManager.ts 单核调度状态机与 LIFO 倒序退栈

`LayerStackManager.ts`（687 行）是整个桌面端浮层架构的大脑，解决了多层浮层同时存在时的生命周期调度难题：

```
[LayerStackManager] 全局单核拓扑栈
▲ 顶层 (Top)  Level 100: Virtual Interceptors (快捷键录制 / 分屏拖拽)
│            Level 50:  Cascade Submenus (二级级联子菜单)
│            Level 40:  Dropdown & Context Menus (Menu / Select 下拉)
│            Level 30:  Popovers (PreviewCard / 气泡卡片)
│            Level 20:  Drawers (抽屉侧拉栏)
│            Level 15:  Confirm Dialogs (二次确认警示框)
▼ 底层 (Base) Level 10:  Modal Dialogs (全屏设置 / 帮助模态弹窗)
```

#### 核心机制：
1. **LIFO 倒序退栈**：当按下 Esc 或点击外部时，调度中枢从栈顶倒序向下寻找首个 `dismissible: true` 的图层关闭，绝不一击穿透全部图层。
2. **100ms 黄金防重入冷却锁（`isWithinCooldown`）**：
   在图层关闭后的 100ms 窗口内，任何新的快速连击均被视为震荡重入并被静默吸收，彻底消除了点击外部关闭菜单时误伤背景按钮的问题。
3. **同级独占驱逐（`evictExclusivePeers`）**：
   当登记 `dropdown-menu` 或 `context-menu` 时，自动排查并主动注销已经存在的其他同级菜单，但**保留属于当前菜单的级联子菜单**（通过祖先指针 `hasAncestor` 判定）。
4. **生命周期 Trace 审计**：
   内部维护容量为 100 的环形缓冲区 `traceHistory`，记录每个 Layer 的注册时间、销毁时间与退出原因（`escape`, `outside-pointer`, `item-select`, `parent-dismissed`），为疑难交互排查提供了完整的数据黑盒。

```typescript
let preferredDirY = idealDirY;
if (this.currentDirY && this.currentDirY !== idealDirY) {
  const currentSpace = this.currentDirY === 'down' ? spaceBelow : spaceAbove;
  const idealSpace = idealDirY === 'down' ? spaceBelow : spaceAbove;
  preferredDirY = idealSpace - currentSpace > this.hysteresisY ? idealDirY : this.currentDirY;
}
this.currentDirY = preferredDirY;
```
- **作用**：当菜单在视口中轴线附近时，如果用户轻微滚动或展开项高度微变，若仅根据 `spaceBelow > spaceAbove` 判定，会导致菜单在「向上」与「向下」之间疯狂震荡。通过设定 `hysteresisY = 32px` 门槛，只有当反向空间比当前空间大出整整 32px 时才允许改变方向，具有极强的物理抗抖动性。

## 十、核心缺陷、坏味道与架构断层清册（Defect Catalog）

### 10.1 缺陷 01：浮层定位算法多头割裂与五重重复造轮子

- **缺陷现象**：全仓同时存在 **5 套**完全独立的浮层定位解算实现：
  1. `Menu/position.ts`（437 行）
  2. `Select/internal/positionGeometry.ts`（121 行）

  4. `Tooltip/tooltipPositioning.ts`（242 行）
  5. `SmartExpandablePanel/PositionEngine.ts`（202 行）
- **严重危害**：
  - 各引擎对视口安全边缘的留白标准不一（有的 8px，有的 12px）；
  - 仅 `Menu/position.ts` 实现了 Windows 最大化 8px 溢出补偿，其他 4 套引擎在 Windows 最大化状态下均存在贴边内容被裁剪的问题；

  - 仅 `Select` 实现了原位覆盖对齐（`alignItemWithTrigger`）；

### 11.2 统一定位计算中枢（FloatingPositionEngine）规格设计

#### 统一入参契约：
```typescript
export interface FloatingComputeOptions {
  anchorRect: DOMRect;               // 触发源几何矩形（支持虚拟鼠标点或 DOMRect）
  contentWidth: number;              // 待弹出浮层实测宽度
  contentHeight: number;             // 待弹出浮层实测高度
  preferredSide?: 'top' | 'bottom' | 'left' | 'right';
  preferredAlign?: 'start' | 'center' | 'end';
  sideOffset?: number;               // 默认 6px~8px
  edgePadding?: number;              // 默认 8px
  alignItemWithTrigger?: boolean;    // 是否开启原位覆盖对齐（Select 消费）
  selectedItemOffsetY?: number;      // 选中项在内容区内部的垂直偏移
  hysteresis?: number;               // 滞后容差防抖门槛（默认 32px）
  previousPlacement?: CalculatedPlacement; // 上一帧结果（防抖比对用）
}

export interface FloatingComputeResult {
  x: number;                         // 刚性钳位后的 CSS Left
  y: number;                         // 刚性钳位后的 CSS Top
  side: 'top' | 'bottom' | 'left' | 'right';
  align: 'start' | 'center' | 'end';
  transformOrigin: string;           // 动画缩放原点
  arrowOffset: number;               // 动态指示小尖角中轴相对位移
  isFlipped: boolean;                // 是否发生避让翻转
}
```

## 十二、实勘总结与归档索引

### 12.1 实勘核心结论总结

1. **整体基底优秀**：
   - `LayerStackManager` 调度中枢设计精良，其单核 LIFO 倒序退栈、100ms 黄金冷却防重入锁、CJK IME 229 中文输入法放行机制以及生命周期 Trace 审计，展现了极高的工程深度，为全仓复杂浮层交互提供了稳定的底座。
   - `focusTrap.tsx` 采用原生 inert 引用计数与沙盒隔离，从根源上消除了多层模态弹窗相互踩踏的顽疾。
   - `Tooltip` 实现了严苛的活跃期多重物理真实性守卫，零残影、零脱离漂移。
2. **割裂与债务突出**：
   - 浮层定位算法存在多达 5 重重复造轮子现象，能力互不相通；
   - `SafeAimEngine` 存在源码级双源副本与 `z-index: 2005` 硬编码；
   - `PreviewCard` 存在单文件 767 行臃肿、裸写 rgba 投影以及 fallback 8000 颠覆层级的严重缺陷；
   - FocusTrap 白名单与特定 DOM 属性硬编码耦合，缺乏统一的契约归约。
3. **重构收益明确**：
   - 按照第十一章的蓝图演进，可净消减冗余代码约 **1,200 行**；
   - 将全仓浮层定位统一至单核纯数学引擎，使全仓浮层天然获得 Win32 最大化补偿与 32px 滞后容差防抖能力；
   - 消除全部样式违规项，使设计系统达到 100% 的 Token 单真理源闭环。
