## 一、实勘概述与战役定位全景

### 1.1 战役背景与实勘使命

在现代现代化桌面工作台与 IDE 开发环境中，**工作区文件系统（Workspace File System）** 与 **多媒体展示画廊（Media Gallery）** 承载着开发者极其高频的信息流交互：
- **文件浏览与导航**：树形目录展开/折叠、多层级面包屑下钻、文件名搜索过滤、工作区根切换；
- **文件操作与查看**：单文件源码查看、变更对比（Diff）、Git 提交历史溯源、外部编辑器/系统资源管理器跳转；
- **多媒体与多格式内容预览**：图片浏览、PDF 审阅、CSV/表格展示、Markdown 富文本渲染、代码语法高亮与行内批注；
- **设计展示与原子陈列**：设计系统组件走查、视觉规范验收、工具调用交互卡片陈列。

在前期战役中，`crish-desktop` 实现了虚拟化树形渲染、ARIA 键盘漫游、叶内安全隔离（S6 门禁）等诸多关键能力。然而，随着功能迭代与多批次补丁叠加，该体系积累了深层的架构断裂与视觉缺陷。本篇实勘的使命，正是全面穿透 `src/components/files/` 与 `src/components/gallery/` 的每一行代码与样式，摸清底细、直面失范、制定归位方案。

### 2.2 扁平化虚拟滚动渲染机制（TreeNode 与 useVirtualScroll）

#### 2.2.1 一维展平数据流
文件树并没有采用嵌套递归的 DOM 树结构，而是采用将树形层级预先“一维展平（Flattened Array）”的架构。数据源来自 `useFileNavigation` 产生的 `flatTree: TreeNode[]`：
```ts
export type TreeNode = FsDirEntry & { depth: number };
```
每个节点记录自身的物理属性（`path`, `name`, `isDir`, `size`）以及树形深度（`depth: 0, 1, 2...`）。只有被显式展开（`expanded[path]`）的目录，其子节点才会被递归追加到 `flatTree` 数组中。

#### 2.2.2 虚拟视口动态切片
在 `FileTreeView.tsx:57-69` 中，组件接入了自定义虚拟滚动钩子 `useVirtualScroll`：
```tsx
const ids = useMemo(() => flatTree.map((e) => e.path), [flatTree]);
const { visibleRange, containerRef, onScroll, totalHeight } =
  useVirtualScroll({
    ids,
    itemCount: flatTree.length,
    fallbackHeight: ITEM_HEIGHT,
  });

const { startIndex, endIndex } = visibleRange;
const visibleItems = useMemo(() => {
  return flatTree.slice(startIndex, endIndex + 1);
}, [flatTree, startIndex, endIndex]);
```

#### 2.2.3 绝对定位与滚动容器
外层容器拥有 `position: relative` 与 `totalHeight = flatTree.length * 28px` 的占位高度。视口内的可见节点通过物理绝对坐标定位：
```tsx
const globalIdx = startIndex + index;
const top = globalIdx * ITEM_HEIGHT;
// style: { position: 'absolute', top: `${top}px`, left: 0, width: '100%', height: '28px' }
```
这一机制保证了即使工程包含数万个文件，DOM 树中渲染的节点始终保持在当前视口所需的 20~40 个之间，避免了超大 DOM 导致的内存与重排崩塌。

### 2.3 ARIA Tree Pattern 语义与键盘无障碍漫游链路

经过历史审计 F7-F35 的重构，`FileTreeView.tsx` 严格对齐了 W3C ARIA 1.2 Tree Pattern 规范，消除了以往把行节点定义为 `role="button"` 的无障碍断层：

1. **容器语义**：外层滚动容器声明 `role="tree"` 与 `aria-label="文件树"`；
2. **行节点语义**：
   - 声明 `role="treeitem"`；
   - 声明 `aria-level={e.depth + 1}`，精确向屏幕阅读器报告当前目录嵌套深度；
   - 声明 `aria-selected={selected === e.path}`，表明当前活动选中态；
   - 对于目录节点，声明 `aria-expanded={expanded[e.path] ? 'true' : 'false'}`；叶子节点则省略该属性。
3. **行间漫游与键盘快捷键状态机**（`FileTreeView.tsx:88-126`）：
   - `ArrowDown`：将焦点移至 `globalIdx + 1` 行；
   - `ArrowUp`：将焦点移至 `globalIdx - 1` 行；
   - `Home`：直接将焦点跳至首行 `globalIdx = 0`；
   - `End`：直接将焦点跳至末行 `globalIdx = flatTree.length - 1`；
   - `ArrowRight`：若当前聚焦的是未展开的目录，触发 `onToggleExpand` 原地展开；
   - `ArrowLeft`：若当前聚焦的是已展开的目录，触发 `onToggleExpand` 原地折叠；
   - `Enter`：触发 `onSelect(node.path, node.isDir)`，直接打开或激活该节点。

### 2.4 深度缩进计算与几何排版瓶颈（10px * depth 挤压陷阱）

实勘发现，`FileTreeView.tsx:203` 中的缩进计算采用如下逻辑：
```tsx
paddingLeft: 4 + e.depth * 10,
```
在现代工程（例如 `apps/crish-desktop/src/components/files/hooks/__tests__/...`）中，目录深度常达到 6 到 10 层：
- 当 `depth = 8` 时，左侧 `paddingLeft = 84px`；
- 在侧边栏默认宽度（例如 240px~280px）下，减去 84px 缩进，再减去折叠箭头（16px）、文件图标（14px）、Git 状态标识（约 18px）和文件大小（约 40px），留给文件名渲染的可用宽度仅剩 **68px~108px**；
- 导致像 `useFileNavigation.test.tsx` 这样的文件名被严重截断为 `useFileNav...`，开发者根本无法辨识文件全名；
- 更严重的是，容器样式中未设置任何水平滚动条（`overflow-x: hidden`），深层文件不仅被挤压，而且完全无法横向滑动查看。

### 2.5 多选机制（Multi-selection）彻底缺失现状深度分析

**实勘现场证据**：

### 2.6 右键上下文菜单（Context Menu）彻底缺失现场剖析

在实际代码走查中，我们在 `FileTreeView.tsx` 全文中搜索 `onContextMenu` 或 `contextmenu`，**命中次数为 0**！

**造成的交互灾难**：
- 用户在文件树行上右键点击，只会弹出 WebView2 / 浏览器的原生默认上下文菜单（包含“审查元素”、“刷新”等开发菜单），或者被全局无感知拦截；

  2. 视线向上移动数十至数百像素，找到顶部工具栏中的 `FileActions`；
  3. 点击小小的下拉三角形或 `MoreHorizontal` 图标，在弹出的菜单中二次寻找对应动作。
- 这种交互路径严重违背了 Fitts 定律与桌面软件的操作直觉。

### 2.7 双击交互与事件冒泡冲突现场审计

在 `FileTreeView.tsx:207-208` 中：
```tsx
onClick={() => onSelect(e.path, e.isDir)}
onDoubleClick={() => onDoubleClick(e.path, e.isDir)}
```
- 对于文件夹：单击执行 `toggleExpand`（展开/收起目录），双击执行 `handleRefresh(path)`（将当前目录作为工作区视图根进行刷新下钻）；
- 然而，浏览器的标准 `dblclick` 必然先触发两次 `click` 事件。在第一次点击时，目录已经触发了一次 `toggleExpand`，随后紧跟的第二次点击再次触发 `toggleExpand`，最后才触发 `onDoubleClick`；
- 这导致双击时经常出现目录瞬间展开又合上，随后整棵树刷新的“闪烁假死”现象；必须在原子化重构中引入定时器防抖或解耦单击展开与双击下钻的语义冲突。

### 3.2 路径解析与面包屑芯片渲染（BreadcrumbItem）

组件通过 `useMemo` 将当前工作路径智能拆分为扁平的面包屑芯片链：
```tsx
const breadcrumbs: BreadcrumbItem[] = useMemo(() => {
  if (!root) return [];
  const dir = view === 'detail' && selected ? pathDirname(selected) || root : cwd || root;
  const rel = pathRelativeToRoot(dir, root);
  const items: BreadcrumbItem[] = [{ label: rootLabel, path: root }];
  if (rel && rel !== '.') {
    let acc = root;
    for (const part of rel.replace(/\\/g, '/').split('/').filter(Boolean)) {
      acc = joinLocal(acc, part);
      items.push({ label: part, path: acc });
    }
  }
  if (view === 'detail' && selected) {
    items.push({
      label: selected.split(/[\\/]/).pop() || '',
      path: selected,
      isFile: true,
    });
  }
  return items;
}, [cwd, root, rootLabel, selected, view]);
```
- 路径分隔符统一兼容 Windows 反斜杠 `\` 与 POSIX 正斜杠 `/`；
- 首项自动收敛为项目根文件夹名称（`rootLabel`），而非生硬的绝对路径；
- 尾项若为正在查看的文件，自动赋予 `isFile: true` 标记。

- 浮层拥有独立的键盘焦点捕获（`autofocus` 搜索框）、`Escape` 快捷键退出以及点击外部遮罩关闭逻辑（`document.addEventListener('mousedown', onDoc)`）；
- 在浮层内部，可以就地呈现该目录下的完整子树结构，支持点击子目录原地平滑展开（`toggleExpand`），多层兄弟节点常驻可见。

### 3.4 浮层内搜索过滤与异步懒加载状态机

2. **搜索过滤与智能排序**：顶部配置有极简搜索框，通过 `filteredEntries` 纯函数计算：
   - 文件夹永远置顶（`isDir ? -1 : 1`）；
   - 过滤内部噪音（`.git`、`--` 前缀等内部保留目录排在业务目录之后）；
   - 采用自然数字感知算法（`localeCompare(..., { numeric: true, sensitivity: 'base' })`）排序。

### 3.5 未保存脏状态提示点（filesDirtyDot）联动逻辑

当用户在编辑器中修改了源码且尚未保存时，`FileBreadcrumb.tsx:475-479` 提供了精细的视觉反馈：

### 3.6 浮层绝对定位与视口溢出遮挡风险评估

实勘发现，`FilesCard.module.css:260-277` 中对 Flyout 浮层的定位采用如下声明：

### 6.1 useFileNavigation.ts 状态转移与目录读取状态机

### 6.2 useFilePreview.ts 状态转移与分页预读预算（Budget）机制

对于超大文本文件，如果一次性读取数百兆内容注入 DOM，会导致前端彻底无响应。`useFilePreview.ts` 实现了精密的**分页预读预算（Budget）控制体系**：

```
                    ┌─────────────────────────────────────────────────────────────┐
                    │            useFilePreview 分页预读状态机架构                │
                    └─────────────────────────────────────────────────────────────┘
                                                   │
                openFile(filePath) 初始预算: 表格 200 行 / 文本 200 行
                                                   │
                                                   ▼
                                      readTextFile(path, budget)
                                                   │
                            ┌──────────────────────┴──────────────────────┐
                            ▼                                             ▼
                   res.truncated === false                       res.truncated === true
                   全部内容已读入                                触发截断标志 setTruncated(true)
                   canLoadMore = false                                            │
                                                                                  ▼
                                                                     底部呈现【继续加载更多】按钮
                                                                                  │
                                                                                  ▼
                                                                           loadMoreLines()
                                                              nextFilePreviewLineBudget(lineBudget)
                                                                                  │
                                                                                  ▼
                                                                     行预算递增: 200 -> 400 -> 800...
                                                                     最大上限: FILE_PREVIEW_MAX_LINES (5000)
```

- 初始预读：常规文本与代码首屏仅预读 200 行（`FILE_PREVIEW_CHUNK_LINES`）；
- 滚动触底/手动点击：调用 `loadMoreLines()`，通过算法步进计算下一档预算；
- 最大上限锁定：硬性门禁设定为 5000 行（`FILE_PREVIEW_MAX_LINES`），超过该上限后展示“已达预览上限”，彻底杜绝内存泄漏。

### 6.3 确认弹窗 Promise 门禁桥（ConfirmGate）与未保存数据保护

历史版本中，当用户修改了代码尚未保存而试图切换文件时，系统直接调用了阻塞式的浏览器原生 `window.confirm`，这在 Tauri 桌面壳中会冻结事件循环，破坏 UI 渲染。


### 6.4 外部文件修改覆盖检测机制（openedContentRef）

在多 Agent 并行或外部工具（VS Code / Git）同时修改文件的场景下，用户在内置编辑器中点击“保存”极易造成不可逆的代码覆盖。

### 8.5 缩放与平移手势（Zoom & Pan）彻底缺失的体验痛点

## 十、现有文件列表密集度与视觉噪点量化评估

### 10.1 列表行高、字体与图标比例（28px 固定行高的利弊）

当前 `FileTreeView.tsx` 采用固定行高 `ITEM_HEIGHT = 28px`：
- **字体层级**：`font-size: var(--font-size-sm, 13px)`；
- **折叠图标**：`size = 12`，外层按钮 16x16px；
- **文件图标**：`size = 14`，外层容器 14x14px；
- **元素间距**：`gap: 3px`。

**评估结论**：
- 28px 在常规屏幕下是一个兼顾紧凑与点击精度的平衡值；
- 但在长列表滚动时，由于没有提供行高自适应（Compact 24px / Default 28px / Comfortable 32px）的密度选择，无法满足部分用户需要在一屏内扫视上百行代码文件的极客需求。

### 10.2 深层缩进挤压与水平截断评估（数学模型计算）

如前所述，`paddingLeft: 4 + e.depth * 10` 缺乏上限约束与横向滚动机制。我们对不同嵌套深度下的可用排版空间进行了数学建模计算：

| 目录嵌套层级 (Depth) | 左侧 Padding (px) | 折叠键与图标占用 (px) | 侧栏 240px 下剩余宽度 | 侧栏 280px 下剩余宽度 | 视觉表现状态 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Depth = 0 (根级) | 4px | 33px | 203px | 243px | 优良，文件名与大小均完整 |
| Depth = 2 (常规包层) | 24px | 33px | 183px | 223px | 正常，文件名少有截断 |

### 10.3 Git 状态与元信息拥挤噪点（M/A/D/? 与文件大小并列）

在 `FileTreeView.tsx:261-285` 中：
```tsx
{!e.isDir && gitStatusMap[e.path] ? (
  <span
    className={styles.filesGitStatus}
    style={{
      color:
        gitStatusMap[e.path] === 'M'
          ? 'var(--color-warning)'

            ? 'var(--color-success)'
            : gitStatusMap[e.path] === 'D'

                ? 'var(--text-tertiary)'
                : undefined,
    }}

  </span>
) : null}
{!e.isDir && e.size != null ? (

  </span>

```
- Git 状态直接使用了内联 style 注入 CSS 变量，增加了 DOM 属性解析开销；
- Git 状态字母（如 `M`）与文件大小（如 `1.2K`）紧密贴在文件名后方，当空间不足时，`filesRowName` 的 `flex: 1` 发生剧烈收缩，三个元素堆积在一起，产生强烈的视觉噪点。

### 10.4 焦点态与激活态边框对比度评估（对齐 AGENTS.md §13）

依据仓库权威指令 `AGENTS.md` §13（UI 输入框与焦点态：默认不要重阴影，克制激活边框，焦点对比度上限约 10%）：

在 `useTreeSelection` 中实现标准桌面级选择算法：
1. **普通单选（Single Click）**：

2. **离散追加（Ctrl / Cmd + Click）**：
   - 若已存在则移除，不存在则追加：

     ```ts
     const next = new Set(selectedIds);
     ```

3. **连续范围选择（Shift + Click）**：
   - 提取 `from = min(lastAnchorIndex, currentIndex)` 与 `to = max(lastAnchorIndex, currentIndex)`；
   - 批量将 `flattenedList.slice(from, to + 1)` 的全部 ID 合并进 `selectedIds`；
4. **全选快捷键（Ctrl / Cmd + A）**：一键选中当前可见的全部文件节点。

### 12.3 ZoomPanViewport 视口平移与滚轮平滑缩放原语设计

开发纯数学驱动的 `useZoomPan` 变换引擎：
```ts
export interface TransformState {
  scale: number;        // 缩放比例 (0.1 ~ 5.0)
  translateX: number;   // X 轴平移偏移 (px)
  translateY: number;   // Y 轴平移偏移 (px)
  rotation: number;     // 旋转角度 (0, 90, 180, 270)
}
```
1. **滚轮缩放（Wheel to Zoom）**：
   - 监听 `onWheel` 事件，基于当前鼠标光标所在点作为缩放原点（Anchor Point），实现“指哪缩哪”的直觉体验；
2. **拖拽平移（Drag to Pan）**：
   - 按住鼠标左键（或在放大状态下直接拖拽），计算 `dx = e.clientX - startX`，平滑更新 `translateX / translateY`；
3. **双击自适应（Double Click to Fit / Reset）**：
   - 双击在 `scale === 1` 与 `scale === fitScale` 之间平滑切换；
4. **键盘快捷键**：
   - `+` / `-` 缩放步进 10%；
   - `0` 还原 100% 原始尺寸；
   - `r` 顺时针旋转 90 度。

### 12.4 触控板平移与双指捏合手势适配（Pinch-to-zoom）算法

利用现代浏览器 Pointer Events 与原生 `wheel` 的 `ctrlKey` 标识：
```ts
if (e.ctrlKey) {
  // 浏览器双指捏合事件，映射为平滑缩放
  handlePinchZoom(e.deltaY);
} else {
  // 双指滑动，映射为双向平移
  handlePan(e.deltaX, e.deltaY);
}
```
在 macOS 触控板与 Windows Precision Touchpad 上提供媲美原生的手势响应。

### 12.5 MediaGalleryViewer 多图画廊原语交互体系

在 `MediaGalleryViewer` 中集成现代相册能力：
1. **多图轮播（Carousel）**：当用户在当前目录下选中一张图片时，自动搜寻同目录下全部图片，支持键盘左右键快速切图；
2. **底部缩略图轨道（Thumbnail Rail）**：轻量水平滚动的缩略图列表，高亮当前图片；
3. **EXIF 信息胶囊**：显示图片物理分辨率（如 `3840 x 2160`）、文件大小、色彩通道及格式。
