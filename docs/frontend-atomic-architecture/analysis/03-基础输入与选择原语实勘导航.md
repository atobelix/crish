## 一、实勘背景与架构基准

### 1.1 任务目标与范围界定

本实勘是【前端原子化组件库战役】的 03 号专项任务，目标是对桌面端系统（`apps/crish-desktop`）中所有基础文本输入、多行编辑、单选下拉、多选搜索以及潜在表单录入原子进行全面、深入、逐行的现场实勘，厘清其职责边界、契约完整度、样式规范合规性、底层数学模型及历史债务，为后续原子组件库收敛提供具有权威指导意义的一手实勘导航。

本次实勘严格覆盖的源码与样式目录为：
1. `c:/Software/conex/apps/crish-desktop/src/components/ui/Input/` 及其全部源码、样式与专项测试。
2. `c:/Software/conex/apps/crish-desktop/src/components/ui/Select/` 及其内部子目录 `internal/`、`__tests__/`，涵盖 `Select` 族与 `Combobox` 族的全部复合组件、样式与算法。
3. 表单周边录入原子（如 `Slider`、`Switch`、`SegmentedControl`）作为表单生态对比参考。
4. 全局表单录入缺失项（重点排查 `NumberInput`、独立 `Autocomplete`、通用 `FormField` 等）。

### 1.2 全局规范与核心红线核查依据

在实勘过程中，所有组件、样式与交互均严格对照以下四项顶层契约进行逐项审验：

1. **`AGENTS.md` §13 输入框与焦点态红线**：
   - **默认不要重阴影**：输入框、搜索框等默认严禁加厚重 `box-shadow`，保持干净、扁平、轻量。
   - **克制的激活边框**：输入框在 `active` / `focus` / `focus-visible` / `focus-within` 态时，严禁使用粗、深、实心黑边（禁止直接用 `var(--text-primary)` 或厚重 `0 0 0 1px/2px/3px` 黑环）。
   - **可控对比度与 10% 刚性红线**：任何情况下焦点/激活态不得使用硬实线；相对基线，灰色加深混入文本色**严格不超过 10%**（例如以 `color-mix(in srgb, var(--border-color) 90%, var(--text-primary) 10%)` 为上限量级；常规元素优先 3%~8% 混入以保持柔和）。
   - **输入框四态体系（Input Four-Patterns）**：
     - 形态 ①【侧边栏无边框纯净型】：常态 `background: transparent, border: none, box-shadow: none`。
     - 形态 ②【主对话底栏胶囊型】：ChatComposer 消息发送输入条。
     - 形态 ③【标准卡片表单原子型】：微圆角（4~8px）、细发丝边框（1px solid subtle border）、柔和焦点环。
     - 形态 ④【内联浮层/卡片顶栏筛选框（纯光标极简型）】：全态仅光标闪烁，严禁非透明边框与深色焦点外框。
2. **`AGENTS.md` §7 严禁补丁、绕过与立体验证纪律**：
   - 严禁使用盲目猜测的延时、坐标魔术数字补偿。
   - 严禁绕过类型检查与单元测试门禁。
   - 保持单一真理路径（SSOT），坚决清退死代码与历史债务。
3. **`ANTI_OVERENGINEERING_GUARDRAILS.md` 反过度设计红线**：
   - 杜绝过度分层与六段式中间件滥用，保持直接、精炼、原生的状态机与几何解算模型。
4. **`components/ui/README.md` 原子层分层隔离准则**：
   - `ui/` 原子层只允许依赖 `react`、`react-dom`、`tokens.css`、`z-index.css`。
   - 严禁反向依赖业务组件（`components/(?!ui)`）、业务 store（zustand）、业务 hooks、api、services。

#### 2.1.3 状态管理与受控/非受控双轨机制
组件设计了优雅的受控/非受控双轨同步算法（Lines 121-140）：
```typescript
const isControlled = value !== undefined;
const [uncontrolledHasValue, setUncontrolledHasValue] = useState<boolean>(
  () => {
    if (defaultValue !== undefined && defaultValue !== null) {
      return String(defaultValue).length > 0;
    }
    return false;
  }
);

const hasValue = isControlled
  ? value !== null && String(value).length > 0
  : uncontrolledHasValue;

const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  if (!isControlled) {
    setUncontrolledHasValue(e.target.value.length > 0);

```
- **核心价值**：清空按钮（Clear Button）需要根据是否有文本动态决定挂载与卸载。在非受控状态下，如果每次按键都在组件内维护完整的字符串副本，会造成不必要的渲染开销；`Input.tsx` 仅使用一个布尔值 `uncontrolledHasValue` 进行轻量跟踪，性能损耗趋近于零。

#### 2.1.4 IME 输入法组合状态机（Composition Guard）
在东亚语言（中文拼音、五笔、日文假名）输入场景中，敲击英文字母后按 `Enter` 键确认选词是用户的本能习惯。若前端框架简单地在 `onKeyDown` 中监听 `e.key === 'Enter'`，会造成在确认中文选词的瞬间意外提交表单、发送消息或触发搜索。

`Input.tsx` 构建了工业级 IME 防误触状态机（Lines 87-119）：
```typescript
// IME 输入法合成状态锁
const isComposingRef = useRef(false);

const handleCompositionStart = (
  e: React.CompositionEvent<HTMLInputElement>
) => {
  isComposingRef.current = true;
  onCompositionStart?.(e);
};

const handleCompositionEnd = (
  e: React.CompositionEvent<HTMLInputElement>
) => {
  isComposingRef.current = false;
  onCompositionEnd?.(e);
};

const handleKeyDown = (e: React.KeyboardEvent<HTMLInputElement>) => {
  onKeyDown?.(e);
  if (e.defaultPrevented) return;
  // 关键拦截：输入法合成中、原生 isComposing 为真、或 keyCode 为 229 / Key 为 Process 时，丢弃回车提交
  if (
    isComposingRef.current ||
    e.nativeEvent.isComposing ||
    e.keyCode === 229 ||
    e.key === 'Process'
  ) {
    return;
  }
  if (e.key === 'Enter' && !e.shiftKey) {
    onEnter?.((e.currentTarget as HTMLInputElement).value);
  }
};
```
**三重防御剖析**：
1. **第一重：React 标准 Composition 事件同步**：通过 `isComposingRef` 记录生命周期；
2. **第二重：原生事件跨层断言**：读取 `e.nativeEvent.isComposing`，防止 React 合成事件批处理滞后；
3. **第三重：Windows/Chromium 平台专用边界防御**：在部分 Windows 输入法下，选词回车的键码可能为 `keyCode: 229` 或 `key: 'Process'`，通过硬性判定将其无情丢弃，确保只有真正的最终回车才能触发 `onEnter`。

#### 2.1.7 清除按钮（Clearable）与原生原型链事件模拟

```typescript
const handleClear = () => {
  onClear?.();
  const inputEl = internalInputRef.current;
  if (inputEl) {
    const valueSetter = Object.getOwnPropertyDescriptor(
      window.HTMLInputElement.prototype,
      'value'
    )?.set;
    valueSetter?.call(inputEl, '');
    const event = new InputEvent('input', {
      bubbles: true,
      cancelable: true,
```

该方案穿透了 React 重写原生 input value setter 的屏障，连续派发真实的 `InputEvent` 与 `change` 事件，使得原生事件监听器、React SyntheticEvent 与各类状态管理库均能 100% 同步清空。

```typescript
const handleKeyDown = (e: React.KeyboardEvent<HTMLTextAreaElement>) => {
  onKeyDown?.(e);
  // 关键拦截：输入法合成中、原生 isComposing 为真、或 keyCode 为 229 / Key 为 Process 时，丢弃回车提交
  if (
    isComposingRef.current ||
    e.nativeEvent.isComposing ||
    e.keyCode === 229 ||
    e.key === 'Process'
  ) {
    return;
  }
  if (e.key === 'Enter' && !e.shiftKey && onEnter) {
    e.preventDefault();
    onEnter((e.currentTarget as HTMLTextAreaElement).value);
  }
};
```
**判定矩阵**：
1. 若消费方未传入 `onEnter`：敲击 `Enter` 不受任何阻拦，执行原生换行行为；
2. 若消费方传入了 `onEnter`：

   - 用户敲击 `Shift + Enter`：不拦截，允许正常换行；
   - 用户敲击纯 `Enter`：调用 `e.preventDefault()` 阻止换行，将当前值回传给 `onEnter` 触发提交。

### 3.2 Textarea.module.css 现代 CSS 架构分析

#### 3.2.1 field-sizing: content 零 JS 回流自适应高度
这是整个前端原子层最具技术先进性的设计之一。
传统自适应高度方案需要在每次按键时执行：
`textarea.style.height = 'auto'; textarea.style.height = textarea.scrollHeight + 'px';`。
这种做法的代价是毁灭性的：
- 每次读取 `scrollHeight` 都会强制浏览器同步计算整个页面的排版树（Forced Reflow）；
- 每次修改 `style.height` 又触发重绘（Repaint）；
- 在长文档或频繁打字时极易产生卡顿掉帧。

`Textarea.module.css` 在第 26 行直接启用了 Chromium 现代原生能力：
```css
.nativeTextarea {
  field-sizing: content; /* Chrome 123+ / WebView2 原生自动高度，0 JS 开销 */
  min-height: 56px;
  max-height: 240px;
  overflow-y: auto;
  resize: none;
  box-sizing: border-box;
  width: 100%;
  padding: var(--space-2, 8px) var(--space-3, 12px);
  font-family: var(--font-sans, inherit);
  font-size: var(--font-size-base, 14px);
  line-height: var(--line-height-normal, 1.5);
  color: var(--text-primary);
  background: color-mix(in srgb, var(--bg-primary) 40%, var(--bg-card));
  border: 1px solid var(--border-subtle);
  border-radius: var(--radius-md, 6px);
  outline: none;
  transition:
    border-color var(--transition-micro, 120ms) ease,
    background var(--transition-micro, 120ms) ease;
}
```
**技术优势**：
1. **0 行 JS 逻辑**：浏览器排版引擎在底层原生计算文字行高与换行，零脚本执行开销；
2. **0 次强制回流**：渲染管道自然流转，打字体验如同丝般顺滑；
3. **阈值平滑回落**：当内容高度超过 `max-height: 240px` 时，原生滚动条自动平滑激活。

#### 3.2.2 尺寸矩阵与高度阈值界定

### 4.3 SelectRoot.tsx 状态编排引擎

`SelectRoot.tsx`（295 行）是所有状态流转与选项注册的核心中枢。

#### 4.3.1 受控与非受控双轨生命周期
组件内部对 `value` 与 `open` 均维护了 `[uncontrolledState, setUncontrolledState]`，并根据外部是否传入对应的 prop（`value !== undefined`）动态决断真值来源。在触发变更时，不仅触发表准的 `onValueChange(nextVal)`，还向下兼容业务层历史的 `onChange(nextVal)` 回调。

#### 4.3.2 选项注册与虚拟集合同步机制（registerItem）
`SelectItem` 并不会常驻在静态 DOM 树中。`SelectRoot` 通过高阶注册机制统一调度：
```typescript
const registerItem = useCallback(
  (itemId: string, itemValue: string, itemDisabled = false, itemLabel = '') => {
    const newItem: RegisteredItemData = {
      id: itemId,
      value: itemValue,
      disabled: itemDisabled,
      label: itemLabel || itemValue,
      index: 0,
    };
    itemMapRef.current.set(itemValue, newItem);

    setItems((prev) => {
      const filtered = prev.filter((i) => i.id !== itemId);
      const next = [...filtered, newItem];
      return next.map((item, i) => ({ ...item, index: i }));
    });

    return () => {
      setItems((prev) => prev.filter((i) => i.id !== itemId));
    };
  },
  []
);
```
每次子项挂载，都会分配单调递增的 `index`，并在注销时自动清理，保证键盘漫游的索引永远与屏幕渲染的可见项保持 1:1 绝对同步。

#### 4.3.3 JSX 静态子树提取算法（extractItemsFromChildren）
在闭合状态下，浮层未挂载，`registerItem` 尚未执行。为了让 `SelectValue` 能够在触发器上即时准确地显示选项文案，`SelectRoot` 在内存中利用 `extractItemsFromChildren` 进行静态语法树预扫描，生成 `staticMap`，实现了微秒级的初次渲染与文案解析。

#### 4.3.4 高亮项漫游计算（highlightedIndex）
浮层展开的瞬间，通过 `useEffect` 计算初始高亮项：
1. 若已有选中值且选项列表中存在该项，直接对准该项的索引；
2. 若无选中值，调用 `items.findIndex((i) => !i.disabled)`，自动跳过被禁用的条目，聚焦在第一个可选项上；
3. 浮层关闭时立即将 `highlightedIndex` 归位为 `-1`。

#### 4.3.5 单选与多选分流处理
在 `selectValue` 中（Lines 159-174）：
- **单选模式**：派发新值 -> 关闭浮层（`handleOpenChange(false)`） -> 自动把焦点送回触发器按钮（`triggerRef.current?.focus()`），保证全键盘用户的操作焦点不发生漂移；
- **多选模式**：基于不可变数组进行追加或移除（`arr.splice` / `arr.push`） -> 保持浮层开启，方便用户连续多选。

### 5.1 Combobox 设计定位与 Autocomplete 替代关系

#### 5.3.2 键盘漫游事件链与回车选中安全保护
```typescript
const handleKeyDown = (e: React.KeyboardEvent<HTMLInputElement>) => {
  onKeyDown?.(e);
  if (
    e.defaultPrevented ||
    ctx.disabled ||
    ctx.isComposingRef.current ||
    e.nativeEvent.isComposing ||
    e.keyCode === 229 ||
    e.key === 'Process'
  ) {
    return;
  }

  const items = ctx.items.filter((i) => !i.disabled);

  if (e.key === 'ArrowDown') {
    e.preventDefault();
    if (!ctx.open) {
      ctx.setOpen(true);
    } else if (items.length > 0) {
      ctx.setHighlightedIndex((prev) => {
        const next = prev + 1;
        return next >= ctx.items.length ? 0 : next;
      });
    }
  } else if (e.key === 'ArrowUp') {
    e.preventDefault();
    if (ctx.open && items.length > 0) {
      ctx.setHighlightedIndex((prev) => {
        const next = prev - 1;
        return next < 0 ? ctx.items.length - 1 : next;
      });
    }
  } else if (e.key === 'Enter') {
    if (ctx.open) {
      const targetIndex = ctx.highlightedIndex >= 0 ? ctx.highlightedIndex : 0;
      const target = ctx.items[targetIndex];
      if (target && !target.disabled) {
        e.preventDefault();
        ctx.selectValue(target.value);
      }
    }
  } else if (e.key === 'Escape') {
    e.preventDefault();
    ctx.setOpen(false);
  }
};
```
当浮层未展开时按 `ArrowDown` 会先唤出浮层；展开后上下键在有效项之间循环；按 `Enter` 优先选中当前高亮项，若无高亮项则智能选中首个合法项。

### 6.1 useFloatingPosition.ts 浮层定位 Hook 深度拆解

`useFloatingPosition.ts`（210 行）是连接 React 状态与浏览器物理视口的核心桥梁。

#### 6.1.1 触发器尺寸测量与 CSS 变量实时注入
在 `updatePosition` 中，通过原生 `getBoundingClientRect()` 测定触发器的物理几何参数：
```typescript

const anchorWidth = triggerRect.width;

contentEl.style.setProperty('--anchor-width', `${anchorWidth}px`);
```
**架构收益**：
通过向浮层 DOM 元素实时注入 `--anchor-width` CSS 变量，浮层的 CSS 可以直接声明：
`width: max(calc(var(--anchor-width, 160px) + 20px), 220px);`
从而消除了用 JS 频繁设置 `contentEl.style.width` 引起的样式与脚本耦合，保证浮层与触发器永远保持几何响应式对齐。

#### 6.1.2 视口事件监听与智能防抖/节流（RAF + ResizeObserver）
当页面滚动或窗口尺寸变化时，浮层必须实时重新解算坐标。但如果盲目监听所有事件，极易导致严重的卡顿。
`useFloatingPosition` 实现了精密的防御管道（Lines 159-189）：
1. **内部滚动事件穿透过滤**：
   ```typescript
   if (
     e &&
     e.type === 'scroll' &&
     contentRef.current &&
     contentRef.current.contains(e.target as Node)
   ) {
     return;
   }
   ```
   如果滚动的目标是下拉列表自身，立即 return 退出！这一步至关重要：它消除了在下拉列表中滚动内容时导致浮层重新计算坐标的死循环。
2. **requestAnimationFrame（RAF）节流**：
   全局滚动与 resize 事件合并至 RAF 队列，一帧内无论触发多少次滚动，最多仅执行一次几何解算，杜绝强制重排抖动。
3. **ResizeObserver 监听**：
   自动监听触发器元素尺寸变化，当页面其他区域折叠导致触发器位移时，浮层自动平滑追随。

#### 6.1.3 全局图层栈（LayerStackService）纳管与物理级联注销

#### 6.2.1 原位对齐模式（Appica / Base UI 对齐算法）
在 `alignItemWithTrigger={true}` 模式下，模拟现代操作系统系统级下拉的物理特性：
```typescript

  const targetX = triggerRect.left - (popupWidth - triggerRect.width) / 2;
  const targetY =
    typeof selectedItemOffsetY === 'number'
      ? triggerRect.top + triggerRect.height / 2 - selectedItemOffsetY
      : triggerRect.top - 4;

  const clampedX = Math.min(Math.max(minX, targetX), maxX);
  const clampedY = Math.min(Math.max(minY, targetY), maxY);

  return {
    x: clampedX,
    y: clampedY,
    side: 'bottom',
    align: 'center',
    transformOrigin: 'center center',
  };
}
```
通过将选中项的垂直几何中心与触发器的垂直几何中心对齐，展开时已选项直接精确覆盖在按钮上方，实现零位移确认。

#### 6.2.2 垂直翻折（Flip）与空间可用度决策算法
在常规模式下，动态评估触发器上下两侧的剩余空间：
```typescript
const spaceBelow = vp.height - (triggerRect.bottom - offsetTop) - sideOffset - edgePadding;
const spaceAbove = triggerRect.top - offsetTop - sideOffset - edgePadding;

let actualSide: 'bottom' | 'top' = side;
let targetY = 0;

if (side === 'bottom') {
  if (popupHeight > spaceBelow && spaceAbove > spaceBelow) {
    actualSide = 'top';
    targetY = triggerRect.top - popupHeight - sideOffset;
  } else {
    targetY = triggerRect.bottom + sideOffset;
  }
}
```
当屏幕下方被任务栏或视口边缘遮挡且上方空间更宽敞时，毫秒级翻折至上方展开，同时动态设置 `transformOrigin` 为 `bottom ...`，使展开缩放动效方向与物理位置完全统一。

#### 6.2.3 刚性钳位（Rigid Clamping）与视口安全边距保障
计算出的坐标最后通过两端截断钳位：
```typescript
const minX = offsetLeft + edgePadding;
const maxX = Math.max(minX, offsetLeft + vp.width - popupWidth - edgePadding);
const minY = offsetTop + edgePadding;
const maxY = Math.max(minY, offsetTop + vp.height - popupHeight - edgePadding);

const clampedY = Math.min(Math.max(minY, targetY), maxY);
```
杜绝任何浮层超出屏幕边缘造成水平或垂直滚动条异常闪烁。

### 6.3 comboboxHighlight.tsx 关键词高亮算法

`comboboxHighlight.tsx`（38 行）实现了健壮的文本高亮切分逻辑：

```typescript
export function highlightMatches(text: unknown, query: string): React.ReactNode {
  if (text == null) return '';
  if (typeof text !== 'string') {
    if (React.isValidElement(text)) return text;
    text = String(text);
  }

  const str = text as string;
  const trimmed = query ? query.trim() : '';
  if (!trimmed || !str) return str;

  const escaped = trimmed.replace(/[.*+?^${}()|[\]\-]/g, '\$&');
  const splitRegex = new RegExp(`(${escaped})`, 'gi');
  const testRegex = new RegExp(`^${escaped}$`, 'i');

  const parts = str.split(splitRegex);
  if (parts.length <= 1) return str;

  return parts.map((part, i) =>
    testRegex.test(part) ? (
      <span key={i} className={styles.highlightText}>
        {part}
      </span>
    ) : (
      part
    )
  );
}
```

#### 关键算法亮点：
1. **正则特殊字符转义**：
   如果用户在搜索框输入 `c++`、`[test]` 或 `*.*`，若不转义直接传给 `new RegExp` 会抛出致命的 `SyntaxError` 异常导致白屏；算法通过 `replace(/[.*+?^${}()|[\]\-]/g, '\$&')` 实现了绝对防御。
2. **捕获组拆分（Capturing Group Split）**：
   `split(new RegExp('(' + escaped + ')', 'gi'))` 使得匹配到的关键词片段自动作为独立元素保留在切分数组中。
3. **杜绝 RegExp lastIndex 变异死锁**：
   在很多劣质开源实现中，开发人员直接使用同一个带 `g` 标志的全局正则既做 `split` 又做 `test`。JavaScript 引擎的规范规定：带有 `g` 标志的正则表达式对象在调用 `test()` 时会记录 `lastIndex` 状态，多次循环测试会导致命中率随机失效！本算法专门使用了一个**无 `g` 标志的独立纯净正则 `testRegex = new RegExp(\`^${escaped}$\`, 'i')`**，彻底杜绝了状态变异。

### 6.4 extractChildrenItems.ts 静态 JSX 提取算法

`extractChildrenItems.ts`（45 行）使用递归算法在内存中解算虚拟 DOM：
```typescript
export function extractItemsFromChildren(
  children: React.ReactNode,
  result: Map<string, ExtractedItemMeta> = new Map()
): Map<string, ExtractedItemMeta> {
  React.Children.forEach(children, (child) => {
    if (!React.isValidElement(child)) return;
    const props = child.props as Record<string, unknown> | null | undefined;
    if (props) {
      if ('value' in props && typeof props.value === 'string') {
        const val = props.value;
        let label = '';
        if (typeof props.label === 'string') label = props.label;
        else if (typeof props.children === 'string') label = props.children;
        else label = val;
        result.set(val, {
          value: val,
          label: label || val,
          disabled: Boolean(props.disabled),
        });
      }
      if (props.children) {
        extractItemsFromChildren(props.children as React.ReactNode, result);
      }
    }
  });
  return result;
}
```
通过递归深度优先遍历，在组件首屏闭合状态下提前解析出所有的 `SelectItem` 与 `ComboboxItem`，为无需展开即可显示选中值的极速体验奠定了算法基石。

#### 7.1.2 原生 number 输入控件的致命缺陷清单
直接裸用 `<Input type="number">` 或原生 `<input type="number">` 会给桌面端带来五大无法容忍的体验缺陷：
1. **鼠标滚轮静默篡改数值（Silent Value Corruption）**：
   在浏览或滚动包含长表单的页面时，若光标无意停留在正在聚焦的原生 number 输入框上方，滚动滚轮会直接触发数值递增或递减！用户往往在毫不知情的情况下篡改了关键配置参数，引发严重的生产故障。
2. **非法输入引发空字符串断裂（Scientific Notation & Empty Target Value）**：
   W3C 标准规定：原生 `type="number"` 允许输入科学计数法符号 `e`、`E` 以及 `+`、`-`。当用户键入 `12e` 时，输入框内部判定为未完成的非法数字，此时 `e.target.value` 会直接返回空字符串 `""`！业务表单的校验逻辑会立即报错“必填项不能为空”，甚至导致下游保存崩溃。
3. **原生 Spin Button 视觉破坏**：
   Windows WebView2 会强制渲染系统底层的灰色微调箭头，不仅尺寸过小、触靶困难，而且无法适配主题颜色与圆角，严重破坏了应用整体的纯黑/柔灰高级质感。
4. **长按连续步进加速缺失**：
   用户需要将数值从 1 调整到 60 时，原生控件必须机械地连续点击 60 次鼠标。现代专业设计系统（如 VSCode、Figma、Blender）均提供按住步进按钮自动加速递增的物理模拟。
5. **单位徽标与前缀/后缀无法内联嵌入**：
   诸如 `分钟`、`ms`、`px`、`%`、`tokens` 等物理单位，目前只能依靠外置的独立文本标签或括号提示，无法以一致的几何基准嵌入在输入框内部右侧。

### 7.2 Autocomplete 独立原语的缺失与 Combobox 职责混淆

在当前体系中，`Combobox` 试图同时包揽“下拉选择”与“自动补全”两项职责，但这导致了概念模型与交互状态的严重混淆：
- **真正的 Combobox 核心目标**：从一个已知的数据集合中选择一项或多项（Selection from discrete set）。用户打字只是为了过滤候选列表，最终必须命中集合中的有效项目。
- **真正的 Autocomplete 核心目标**：用户在进行**自由文本输入**（Free-form text input，如输入自定义 URL、文件绝对路径、终端执行命令、Prompt 模版），下拉列表仅仅是提供辅助的联想推荐（Suggestions）。用户既可以直接敲回车采纳某条建议，也可以完全不采纳任何建议，直接提交自己输入的任意未在列表中的原始文本。

由于缺乏独立的 `Autocomplete` 原语，业务组件被迫在 `Combobox` 上打各种布尔补丁（如魔改 `itemToValue`、拦截回车），不仅容易引发逻辑断裂，而且破坏了类型契约。

### 7.5 表单级校验、表单字段上下文（Form Field Context）断层

### 7.6 虚拟化滚动支持缺失与大列表性能瓶颈

当前 `SelectContent` 与 `ComboboxList` 均直接执行 `children` 或 `filteredItems.map(...)`，全量挂载 DOM 节点。
当遇到以下典型大列表场景时：
- 全局大模型选择列表（如聚合供应商提供数百个开源与商业模型时）；
- 本地历史会话归档列表；
- 代码工程扁平文件检索列表（上千个文件路径）。
展开下拉列表的瞬间会一次性创建上千个含有事件监听和样式计算的真实 DOM 节点，造成明显的界面卡顿和垃圾回收压力。组件库急需支持可插拔的轻量视口虚拟滚动。

### 7.7 清除按钮 DOM 元素类型与无障碍语义不一致

实勘中发现一个不严密的语义分歧：

- `ComboboxInput.tsx` 的清除按钮采用原生 `<button type="button" className={styles.clearBtn} aria-label="清空输入">`；
- **但 `SelectClearButton.tsx`（Lines 8-28）却采用了 `<span role="button" tabIndex={-1} aria-label="清空选值">`**！
在 HTML 规范与 WAI-ARIA 最佳实践中，永远应当优先使用原生的 `<button>` 标签。用 `<span>` 模拟按钮不仅需要手动监听 `onKeyDown` 的回车与空格键，而且在无障碍辅助设备上的行为一致性弱于原生按钮。必须统一收敛为原生 `<button>`。

#### 8.2.3 核心实现代码原型（含物理步进加速与滚轮安全防御）
```tsx
import React, { useState, useRef, useCallback, useEffect, useId } from 'react';
import styles from './NumberInput.module.css';

export function NumberInput({
  value: controlledValue,
  defaultValue,
  onChange,
  size = 'md',
  min = -Infinity,
  max = Infinity,
  step = 1,
  precision,
  stepper = true,
  allowWheel = false,
  unit,
  disabled,
  readOnly,
  label,
  hint,
  error,
  ...restProps
}: NumberInputProps) {
  const isControlled = controlledValue !== undefined;
  const [internalValue, setInternalValue] = useState<number | null>(defaultValue ?? null);
  const value = isControlled ? controlledValue : internalValue;

  const [displayString, setDisplayString] = useState<string>(() => {
    return value !== null && value !== undefined ? String(value) : '';
  });

  useEffect(() => {
    if (isControlled) {
      setDisplayString(value !== null && value !== undefined ? String(value) : '');
    }
  }, [isControlled, value]);

  const updateValue = useCallback((nextVal: number | null) => {
    let clamped = nextVal;
    if (clamped !== null) {
      clamped = Math.max(min, Math.min(max, clamped));
      if (precision !== undefined) {
        clamped = Number(clamped.toFixed(precision));
      }
    }
    if (!isControlled) {
      setInternalValue(clamped);
    }
    setDisplayString(clamped !== null ? String(clamped) : '');
    onChange?.(clamped);
  }, [min, max, precision, isControlled, onChange]);

  // 1. 物理步进加速状态机
  const timerRef = useRef<NodeJS.Timeout | null>(null);
  const stepCountRef = useRef(0);

  const startStepping = (delta: number) => {
    if (disabled || readOnly) return;
    const baseStep = () => {
      updateValue((prev) => {
        const curr = prev ?? (delta > 0 ? (min > -Infinity ? min : 0) : (max < Infinity ? max : 0));
        return curr + delta * step;
      });
      stepCountRef.current += 1;
    };

    baseStep();

    // 随着长按时间延长，自动提升触发频率（物理加速度）
    const scheduleNext = () => {
      const delay = Math.max(30, 200 - stepCountRef.current * 15);
      timerRef.current = setTimeout(() => {
        baseStep();
        scheduleNext();
      }, delay);
    };

    scheduleNext();
  };

  const stopStepping = () => {
    if (timerRef.current) {
      clearTimeout(timerRef.current);
      timerRef.current = null;
    }
    stepCountRef.current = 0;
  };

  // 2. 滚轮安全防御（默认完全阻断数值篡改）
  const handleWheel = (e: React.WheelEvent<HTMLInputElement>) => {
    if (!allowWheel) {
      // 允许页面正常滚动，绝对不修改输入框数值
      return;
    }
    e.preventDefault();
    const delta = e.deltaY < 0 ? 1 : -1;
    updateValue((prev) => (prev ?? 0) + delta * step);
  };

  // 3. 键盘上下键微调
  const handleKeyDown = (e: React.KeyboardEvent<HTMLInputElement>) => {
    if (e.key === 'ArrowUp') {
      e.preventDefault();
      updateValue((prev) => (prev ?? 0) + step);
    } else if (e.key === 'ArrowDown') {
      e.preventDefault();
      updateValue((prev) => (prev ?? 0) - step);
    }
  };

  // 4. 输入字符合法性过滤（只允许数字、负号和小数点，彻底清除 'e' 科学计数法）
  const handleInputChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const raw = e.target.value;
    if (raw === '' || raw === '-') {
      setDisplayString(raw);
      if (!isControlled) setInternalValue(null);
      onChange?.(null);
      return;
    }
    const parsed = Number(raw);
    if (!isNaN(parsed)) {
      setDisplayString(raw);
      if (!isControlled) setInternalValue(parsed);
      onChange?.(parsed);
    }
  };

  const handleBlur = () => {
    if (displayString === '' || displayString === '-') {
      updateValue(null);
    } else {
      updateValue(Number(displayString));
    }
  };

  return (
    <div className={`${styles.wrap} ${styles[size]}`}>
      {label && <label className={styles.label}>{label}</label>}
      <div className={styles.shell}>
        <input
          type="text"
          inputMode="decimal"
          className={styles.input}
          value={displayString}
          disabled={disabled}
          readOnly={readOnly}
          onChange={handleInputChange}
          onBlur={handleBlur}
          onKeyDown={handleKeyDown}
          onWheel={handleWheel}
          {...restProps}
        />
        {unit && <span className={styles.unit}>{unit}</span>}
        {stepper && !disabled && !readOnly && (
          <div className={styles.stepperBox}>
            <button
              type="button"
              tabIndex={-1}
              className={styles.stepBtn}
              onMouseDown={() => startStepping(1)}
              onMouseUp={stopStepping}
              onMouseLeave={stopStepping}
              aria-label="增加数值"
            >
              ▲
            </button>
            <button
              type="button"
              tabIndex={-1}
              className={styles.stepBtn}
              onMouseDown={() => startStepping(-1)}
              onMouseUp={stopStepping}
              onMouseLeave={stopStepping}
              aria-label="减少数值"
            >
              ▼
            </button>
          </div>
        )}
      </div>
      {error && <p className={styles.error}>{error}</p>}
      {hint && <p className={styles.hint}>{hint}</p>}
    </div>
  );
}
```

### 8.4 统一 IME 状态机 Hook：`useImeComposition`

将 `Input`、`Textarea`、`ComboboxInput` 三处分散重复的 IME 状态机提炼为通用原子 Hook：`apps/crish-desktop/src/components/ui/internal/useImeComposition.ts`：

```typescript
import { useRef, useCallback } from 'react';

export interface UseImeCompositionOptions {
  onEnter?: (value: string) => void;
  onKeyDown?: (e: React.KeyboardEvent<any>) => void;
  onCompositionStart?: (e: React.CompositionEvent<any>) => void;
  onCompositionEnd?: (e: React.CompositionEvent<any>) => void;
  allowShiftEnter?: boolean; // Textarea 模式下为 true
}

export function useImeComposition({
  onEnter,
  onKeyDown,
  onCompositionStart,
  onCompositionEnd,
  allowShiftEnter = false,
}: UseImeCompositionOptions) {
  const isComposingRef = useRef(false);

  const handleCompositionStart = useCallback(
    (e: React.CompositionEvent<any>) => {
      isComposingRef.current = true;
      onCompositionStart?.(e);
    },
    [onCompositionStart]
  );

  const handleCompositionEnd = useCallback(
    (e: React.CompositionEvent<any>) => {
      isComposingRef.current = false;
      onCompositionEnd?.(e);
    },
    [onCompositionEnd]
  );

  const handleKeyDown = useCallback(
    (e: React.KeyboardEvent<any>) => {
      onKeyDown?.(e);
      if (e.defaultPrevented) return;

      // 三重防御：状态锁 + 原生标志位 + Windows 专有键码
      if (
        isComposingRef.current ||
        e.nativeEvent.isComposing ||
        e.keyCode === 229 ||
        e.key === 'Process'
      ) {
        return;
      }

      if (e.key === 'Enter') {
        if (allowShiftEnter && e.shiftKey) {
          // 允许换行，不触发提交
          return;
        }
        if (onEnter) {
          e.preventDefault();
          onEnter(e.currentTarget.value);
        }
      }
    },
    [onKeyDown, onEnter, allowShiftEnter]
  );

  return {
    isComposingRef,
    handleCompositionStart,
    handleCompositionEnd,
    handleKeyDown,
  };
}
```
通过 60 行精炼的纯逻辑，实现对整个表单录入体系输入法行为的完全统一。
