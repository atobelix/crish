# 最终维度定案与全域删除面总框架

> **战役工作区**：`docs/frontend-atomic-architecture/`
> **核心使命**：以纯粹冷中性黑白灰为美学基石，重塑 AI 对话流响应界面；保护输入框（Composer）现有优秀设计绝对不变；全域建立原子化、可扩展五层 UI 组件库；彻底清除全仓死层、重复路径与设计异味。
> **制定依据**：全仓 24 份逐行实勘报告（37,765 行代码实勘记录） + 6 份独立维度提案（585 KB 详尽论证） + 主控个人代码深度交叉验证。
> **铁律准绳**：推进单位为「领域概念」而非「波次/批次」；收敛先于增强（先删后改）；每个维度均有强制且经过验证的「删除面」，净收敛代码量 $\ge 5,900$ 行。

## 维度一（强制固定）：全仓重复与死层清理 (DIM-CONVERGENCE-CLEANUP)

### 领域目标与治理边界
作为本战役的基石维度，严格践行“收敛先于增强（先删后改）”铁律。清退全仓存量重复路径、废弃架构遗留、无引用死层与未生效样式，为后续原子组件库搭建与对话流重塑扫清障碍。

### 主控代码实勘证据
- **双轨 storeAccess 断层**：`src/store/storeAccess.ts` 与 `src/api/storeAccess.ts` 并存，二者职责严重重叠。在 `src/store/storeAccess.ts:8-32` 中甚至出现长达 25 行的妥协性注释，指导开发者何时从 api 导入、何时从 store 导入，在打包时极易诱发 ESM 循环引用与 `storeAccess is not a function` 运行时空指针。
- **文件预览 11 个幽灵 CSS 类名事故**：`FilePreview.tsx` 内部大量引用 `.filesPreviewMedia`、`.filesPreviewPdf`、`.filesTableWrap`、`.filesNoteContent` 等 11 个样式类，但在全工程所有 CSS/Module 集中搜索，定义次数为 0，导致多媒体文件预览直接裸奔无视口约束。
- **失效样式死层**：`Select.module.css` 遗留 368 行样式规则，但该组件早已改用内联或无头架构，所有选择器处于全未匹配状态；`ToastStack.module.css` 存在未引用的孤儿文件。
- **废弃树形切片**：`workspaceStore.ts` 仍保留早期废弃的卡片看板与旧版文件树同步逻辑，从未在生产环境执行。

### 强制删除面清单
- **文件级物理删除**：
  - 删除 `apps/crish-desktop/src/api/storeAccess.ts`（统一归位至 `src/store/storeAccess.ts` 单一真理源）。
  - 删除 `apps/crish-desktop/src/components/ui/Select.module.css` 中的 368 行未生效死类规则。
  - 删除未引用的孤儿样式文件 `apps/crish-desktop/src/components/ui/ToastStack.module.css`。
- **模块与类名级收敛清除**：
  - 清除 `FilePreview.tsx` 中引用的 11 个零定义幽灵类名，转为原子化标准容器包装。
  - 剔除 `workspaceStore.ts` 中废弃的 `workspaceTreeSlice` 存量死逻辑。
  - 清理全仓遗留的 `TODO`、`FIXME` 与临时 hack 注释（净清理 $\ge 35$ 处）。
- **删除面验收指标**：净删除代码行数 $\ge 2,500$ 行，全仓 `storeAccess` 引用唯一归位，0 幽灵类名。

## 维度二：AI 对话响应流与视口体验重塑 (DIM-RESPONSE-FLOW)

### 领域目标与治理边界
直击用户截图中反映的核心痛点，对 AI 对话流响应界面展开系统性攻坚。将臃肿、刺眼、复读的注入卡片彻底解构为符合现代审美的发丝微分割线；释放思维链受困的视口；将纵向拉伸的多步工具调用收敛为紧凑流水线。**严格保护输入框（Composer）现有优秀设计与模型选择 UI 绝对不变。**

### 主控代码实勘证据
- **注入卡片倒反天罡展开逻辑**：`CompactInjectionRow.tsx:57` 判定表达式为 `!(injection.defaultFolded ?? ((injection.content || '').length > 160))`。当文本长度 $\le 160$ 字符时，取反操作 `!(false)` 导致计算结果恒为 `true`，使得所有短状态切换全部被强制默认展开。
- **100% 文本双重复读**：卡片 Header 已经呈现了状态文本，Body 却调用昂贵的 Web Worker 与 `StreamingMarkdownView` 把一模一样的内容再次打印在灰色底盒中。
- **7 色高饱和彩虹条与 2.5px 粗框**：`ContextInjectionBlock.module.css:288-345` 声明了 2.5px 粗左边框，并硬编码了亮绿（`#10b981`）、亮橙（`#f59e0b`）、亮蓝（`#3b82f6`）、荧光青（`#06b6d4`）、鲜紫（`#8b5cf6`）、警报红（`#ef4444`）等 7 种鲜艳彩虹色。
- **思维链 168px 矮盒窒息限制**：`TimelineThoughtSection.tsx` 中展开态硬编码 `max-height: 168px`，顶部和底部各带 20px 渐变遮罩，实际阅读视口仅剩 112px（约 5 行文字）。
- **连续工具调用纵向撕裂**：每个工具调用单例渲染大卡片，连续 5 步调用纵向拉伸近 3,000px。

### 强制删除面清单
- **结构与逻辑级删除**：
  - 废除 `ContextInjectionBlock` 与 `CompactInjectionRow` 中的外层大卡片包裹结构。
  - 彻底删除 `InjectionBody.tsx` 中的双重文本复读逻辑与 Web Worker 异步渲染链路。
  - 物理删除 `ContextInjectionBlock.module.css:288-345` 中 7 种高饱和彩虹色声明及 2.5px 粗左边框样式。
  - 纠正 `CompactInjectionRow.tsx:57` 中的取反逻辑漏洞。
- **视口与限制级删除**：
  - 删除 `TimelineThoughtSection.tsx` 中 `max-height: 168px` 限制及上下 20px 渐变淡出遮罩。
  - 消除连续单例工具调用大卡片的纵向拉伸结构，收拢为单行紧凑流水线。
- **保护红线**：
  - `apps/crish-desktop/src/components/chat-composer/` 下全部文件保持 100% 原样不变。
- **删除面验收指标**：系统上下文切换高度由 80px~140px 压缩至 $\le 20px$，双重文本复读率清零，彩虹色出现率归零，思维链阅读视口无条件释放，净删除代码 $\ge 900$ 行。

## 维度三：基础交互与表单录入选择原语库 (DIM-INTERACTIVE-PRIMITIVES)

### 领域目标与治理边界
建立位于 `@/components/ui/` 的 Layer 1（基础交互控制）与 Layer 2（文本输入与表单选择）原子原语体系。全面清退业务层中裸写的 HTML 原生控件，落实焦点对比度 $\le 10\%$ 的冷中性设计法则。

### 主控代码实勘证据
- **四大关键原语架构真空**：全仓完全缺失标准化的 `Checkbox`、`Radio`、`ToggleButton`、`ToggleGroup` 原语组件。
- **野生裸写控件遍地开花**：
  - `MirrorDriftStatusBar.tsx:239-247` 直接裸写 `<input type="checkbox">`；
  - `block-paper/src/chrome/chromeHostAssembly.ts` 甚至使用原生 DOM `document.createElement('input')` 命令式构建复选框并硬编码十六进制色值；
  - 便签与设置中频繁使用 SegmentedControl 或按钮数组拼凑单选功能。
- **输入框焦点态生硬**：部分输入框在获得焦点时直接使用硬实黑线或过深对比度边框，违反 $\le 10\%$ 混合红线。
- **数字输入防误触机制缺失**：直接使用原生 `<input type="number">`，页面滚动时滚轮极易误篡改关键数值。

### 强制删除面清单
- **野生控件与裸写标签清退**：
  - 清退全仓所有裸写 `<input type="checkbox">` 与 `createElement('input')`（收敛替换为标准 `Checkbox` 原语）。
  - 清退表单中用按钮拼凑单选的临时实现（收敛替换为标准 `Radio` / `RadioGroup`）。
  - 清退业务层直接裸写的 `<input type="number">`（收敛替换为带步进守护的 `NumberInput`）。
- **违规样式删除**：
  - 彻底删除输入框获取焦点时的粗黑硬边框，统一收敛为不超过 10% 混入度的柔软微灰混合边框。
  - 删除 `Textarea` 组件中依赖 `scrollHeight` 强制浏览器同步重排的传统计算逻辑，改用原生现代 CSS `field-sizing: content`。
- **删除面验收指标**：全仓原生裸写 `<input type="checkbox">` 与 `<input type="number">` 归零，统一导出规范原子原语，代码净收敛 $\ge 800$ 行。

## 维度四：视觉反馈与浮层弹窗原语体系 (DIM-FEEDBACK-OVERLAY)

### 领域目标与治理边界
建立 Layer 3（视觉展示与状态反馈）与 Layer 4（浮动层与弹窗）原子原语体系。消灭艳俗彩色色块与刺眼脉冲光晕，消除 24px 双层浓黑大阴影，建立全局唯一的 ESC 键退栈管理中枢。

### 主控代码实勘证据
- **刺眼脉冲光晕**：`subagent-dot-pulse` 声明了 4.5px 粗暴的绿光脉冲动画，在黑色背景下极为刺眼，破坏宁静专业质感。
- **24px 浓黑大阴影泛滥**：Popover、Menu、Dropdown、`sessionTabDrag` 中硬编码了 24px 浓重投影（如 `0 12px 24px rgba(0,0,0,0.4)`），产生沉重的视觉脏感。
- **骨架屏关键帧丢失**：`Skeleton.module.css` 引用的 `.skel-shimmer` 关键帧在样式中丢失，导致骨架流光动画失效，呈现死板灰色块。
- **浮层层级与 ESC 键竞争**：多个 Dialog 与 Popover 并存时，ESC 按键往往同时关闭所有浮层，缺少严格的 LIFO 栈管理。

### 强制删除面清单
- **动画与光晕物理删除**：
  - 物理删除 `subagent-dot-pulse` 及其关联的 4 处 4.5px 粗暴脉冲光晕关键帧，统一收敛为 6px 极简冷中性微呼吸点 `StatusDot`。
- **大阴影与彩色色块清退**：
  - 彻底清退散落在所有浮层组件中的 24px 双层浓黑大阴影，全面改用 1px 极细发丝边框与极微投影（$\le 4\%$ 不透明度）。
  - 清退彩色药丸与高亮彩条，Badge 与 Tag 全面中性化，仅通过明度与字重传递信息。
- **孤儿与碎片文件清理**：
  - 清除孤儿 `ToastStack` 存量代码，收敛至 `@/components/ui/Toast`。
- **删除面验收指标**：4.5px 粗暴脉冲光晕出现率归零，24px 浓黑大阴影清零，全局浮层 ESC 按键单次精准退栈，净删除代码 $\ge 700$ 行。

## 维度五：高级工程容器与扩展生态治理 (DIM-COMPOSITE-CONTAINERS)

### 领域目标与治理边界
建立 Layer 5（高级复合工程容器）原语标准。解决 MCP 环境变量配置缺失致命断层，校正代码比对器自动折行截断事故，消除暗黑模式刺眼纯白底方块，治理便签系统内部野生控件。

### 主控代码实勘证据
- **MCP 环境变量配置关键功能断层**：`McpServerForm.tsx` 与底层后端 `McpServer` 接口完全缺失 `env` 环境变量配置项。主流 GitHub、PostgreSQL 等需要注入 Token 的服务完全无法通过界面配置。且卡片上遗留废弃的启停幽灵按钮，头部堆叠 3 个鲜艳彩色 Badge。
- **暗黑模式刺眼纯白方块**：`ManualAddForm.tsx` 与 `ScanResultsModal.module.css` 硬编码 `#ffffff` 背景色，在深色模式下呈现刺眼白色强光方块；大模型核心参数 Temperature 与 Top-p 在前端界面完全缺失。
- **代码比对器折行几何截断错位**：`DiffCardUnifiedView.tsx` 与 `DiffCardSplitView.tsx` 硬编码固定行高 `rowHeight = 22px`，但代码行启用了 `white-space: pre-wrap` 自动折行。视口收窄折行时，虚拟列表偏移计算错位，造成底部代码行被吞噬。
- **便签备忘录野生控件泛滥**：`note-paper/` 内部存在 5 大野生裸写控件（原生 Checkbox、密集原生 Button、无障碍盲区 Dialog、加权重命名 Input）。

### 强制删除面清单
- **硬编码与失效逻辑删除**：
  - 彻底删除 `ManualAddForm.tsx` 与 `ScanResultsModal.module.css` 中的 `#ffffff` 硬编码纯白背景。
  - 删除 MCP 卡片上已废弃失效的启停幽灵按钮及堆叠彩色徽章。
  - 删除 `DiffCard` 中硬编码固定 22px 行高的粗暴逻辑，引入 Fenwick Tree 动态行高管理器。
- **野生控件清退**：
  - 清退 `NoteSidebarDrawer.tsx` 等便签模块中的 5 大野生裸写控件，替换为标准原子组件。
- **删除面验收指标**：暗黑刺眼白底方块归零，MCP 环境变量 Key-Value 动态编辑可用，Diff 自动折行截断彻底根除，净收敛代码 $\ge 850$ 行。

## 维度六：全局状态网格与自动化工程门禁 (DIM-STATE-GUARDRAILS)

### 领域目标与治理边界
全面治理 Zustand 状态订阅拓扑，根除 4 大高频重绘病灶。清理主题系统内联注入的暖黄泥色。建立刚性自动化工程门禁脚本，拦截未来任何向原子化规范倒退的代码提交。

### 主控代码实勘证据
- **四大高频重绘病灶**：
  - `PaneHeader.tsx:86` 订阅整本 `sessionsById` 字典，导致任意一个会话收到一条消息，全屏所有视窗 Header 逐帧全部重新渲染；
  - `ChatMessageList.tsx` 订阅整条 Session 对象，用户打字时上千条历史消息触发重复 Diff；
  - 多个关键选择器缺少 `useShallow` 浅比较保护，流式打字时帧率大幅滑落至 18 FPS。
- **主题暖黄内联污染**：`themeStore.ts` 内部存在 18 处通过内联样式强制覆盖的暖黄泥色变量，严重污染了现代冷中性设计质感。
- **门禁真空**：缺少自动化工具拦截野生裸写 `<input>`、大阴影、高饱和彩条的回潮。

### 强制删除面清单
- **内联样式与粗粒度订阅删除**：
  - 彻底删除 `themeStore.ts` 中 18 处暖黄泥色内联覆盖样式，回归 Design Tokens 物理冷中性。
  - 消除 `PaneHeader` 对全量 `sessionsById` 的粗暴订阅，改为细粒度原子选择器。
  - 消除 `ChatMessageList` 对完整 Session 实体的直接解构，全面接入 `useShallow`。
- **落地刚性工程门禁**：

## 全局实施总准则与先删后改铁律

- **先删后改原则（收敛优先）**：执行任何新增或功能增强任务前，必须首先完成其依赖概念的旧路径物理删除或收敛；未完成删除动作的增强方案禁止合入。

- **立体双验收门禁**：所有维度必须同时通过“功能正确性验收”与“负产出代码收敛验收”，两者缺一不可。
