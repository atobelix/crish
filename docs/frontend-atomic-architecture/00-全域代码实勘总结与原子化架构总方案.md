## 对话流响应界面核心硬伤与重塑标准

### 直击截图痛点：系统上下文注入大卡片彻底清算

在您上传的截图中，每次仅仅在输入框切换模型或权限模式，对话流中便赫然插入一条巨大的 `[系统上下文注入 · 状态切换] 当前已切换到模型...` 卡片。经过任务书 12 专项实勘，查清了以下四大代码病灶：

- **反常展开逻辑（倒反天罡）**：在 `CompactInjectionRow.tsx:57` 中，计算默认展开的表达式为 `!(injection.defaultFolded ?? ((injection.content || '').length > 160))`。开发者原意是对大于 160 字符的长内容展开，但在括号外加了取反运算 `!`，导致**小于 160 字符的短文本计算结果恒等于 `!(false) === true`**，所有一句话的轻微状态切换全部被强制默认展开！
- **100% 文本逐字双重复读**：卡片顶部的标题栏已经清晰显示了状态文字，但在下方展开的灰色方框 Body 中，又通过昂贵的 `StreamingMarkdownView` 把完全一模一样的内容打印了一遍，视口空间被浪费 15%~30%。
- **违规彩虹色与粗边框**：`ContextInjectionBlock.module.css:288-345` 声明了 2.5px 粗左边框，并硬编码了亮绿、亮橙、亮蓝、荧光青、鲜紫、警报红、墨绿等 7 种鲜艳彩虹色，严重破坏了黑白灰宁静质感。
- **重塑为 20px 极简居中黑白灰微分割线（Status Divider）**：彻底废弃外层大卡片、粗彩边框与展开 Body。改为极简居中微分割线：
  左右两侧各一条 1px 发丝级中性灰细线（`var(--hairline)`），中间包裹 11px 单行低饱和中性灰说明文字（`var(--text-tertiary)`），高度不超过 20px，居中平铺，零彩色、零外框、零展开卡片。

### 思维链 168px 矮盒卡死与压抑感释放

- **病因**：`TimelineThoughtSection.tsx` 在模型进行长思维链推理时，展开态被硬编码了 `max-height: 168px`，且顶部与底部各带有 20px 的渐变淡出遮罩。这导致在长达上万字的推理流中，实际阅读视口仅剩惨淡的 112px（约 5 行文字），用户必须在极小的狭缝中痛苦滚动。
- **重塑**：打破固定高度枷锁，改为自然展开的开阔视界；提供极简微胶囊折叠手柄，展开时全高度通透呈现，彻底消除遮罩与滚动受限的压抑感。

### 连续工具调用纵向拉伸 3 屏与时间线聚合

- **病因**：在连续执行终端命令或读写文件时，前端会为每个工具调用渲染一个全尺寸卡片。由于缺少聚合流水线，5 步连续调用就会在垂直方向拉伸近 3,000px，严重撕裂阅读上下文。
- **重塑**：收敛为单一紧凑流水线（Tool Execution Pipeline）。在折叠状态下仅展示一行中性状态药丸与执行耗时，点击时通过抽屉（Inspector）或平滑展开展示终端细节。

### 输入框（Composer）核心设计保护原则

用户明确确认：**当前输入框（Composer）与模型选择界面的设计非常优秀、非常喜欢，绝对禁止改动！**
在本次架构重塑中，输入框体系（`chat-composer/` 的四层垂直堆叠、Tiptap 富文本内核、模型选择胶囊、加号扩展菜单与发送控制组）被列为**受保护的基石核心**，不作任何削减或破坏，所有重构精力完全聚焦在响应流（Response Flow）与底层原子组件库上。

## 全局原子化组件库架构体系设计

针对全仓 28 个零散目录、组件随意堆叠的现状，我们将建立一套清晰、庞大、原子化且可无限扩展的组件库架构。整个体系统一归位在 `apps/crish-desktop/src/components/ui/`，划分为严密的五层金字塔架构：

```
Layer 5: 复合工程容器原语 (Tree, ZoomPan, Diff, Kanban)
Layer 4: 浮动层与弹窗原语 (Dialog, Popover, Tooltip)
Layer 3: 视觉展示与状态反馈原语 (Badge, StatusDot, Toast)
Layer 2: 文本输入与表单选择原语 (Input, Textarea, Select)
Layer 1: 基础交互控制原语 (Button, Switch, Toggle, Radio)
Base: 纯粹中性黑白灰设计Token (tokens.css, Typography)
```

### Layer 1 基础交互控制原语族

- `Button` & `IconButton`：统一 5 大变体（primary / secondary / ghost / subtle / danger）与 4 种尺寸（sm / md / lg / xl），内置 `bare` 裸核心模式与 40px 隐式触控安全区。
- `Switch`：0ms 乐观状态机，带有四层异常防死锁回滚机制（同步捕获、Promise 守护、5000ms 超时回退、原点收敛）与果冻拉伸微动效。
- `SegmentedControl`：WAI-ARIA 1.2 漫游焦点，单例 ResizeObserver 自适应测量滑块，同心大圆角几何体系。
- `Slider`：2px 发丝极细轨，44px 隐式指针命中区，支持指针越界捕获（`setPointerCapture`）。
- **补齐四大架构真空**：
  - `Checkbox`：二态与三态（indeterminate 半选），原生 SVG 描边绘制，统一替代全仓 4 种野生裸写复选框。
  - `Radio` & `RadioGroup`：纯中性单选原语，替代过去在表单中强行使用 SegmentedControl 或 Button 数组的割裂做法。
  - `ToggleButton` & `ToggleGroup`：支持受控锁定开闭与多选切换，统一管理消息置顶 Pin、文件过滤等交互。

### Layer 2 文本输入与表单选择原语族

- `Input`：单行文本录入，内置搜索图标槽、一键清空与原生安全密码显隐；集成 IME 输入法中文合成锁；焦点态采用 ≤10% 柔软微灰混合边框，严禁粗实黑线。
- `Textarea`：率先拥抱原生现代 CSS `field-sizing: content` 自适应高度，彻底摒弃传统的 `scrollHeight` 强制重排反模式。
- `Select` & `Combobox`：单选与多选下拉列表，支持模糊过滤、标签胶囊与浮层穿透挂载。
- **新建缺失原语**：
  - `NumberInput`：专业数值微调输入框，彻底替换业务中裸写 `<input type="number">` 的危险做法，防御滚轮误篡改与非法科学计数法字符，支持长按连续步进加速。
  - `SearchInput`：带有即时防抖、清除按钮与快捷键（`/` 或 `Ctrl+K`）呼出的标准化搜索原子。

### Layer 3 视觉展示与状态反馈原语族

- `Badge` & `Tag`：纯中性灰度标签，以文字对比度代替大面积彩色背景色块；支持单色语义微点。
- `StatusDot`：6px 极简状态指示圆点（在线/离线/运行/等待），采用柔和无害的微呼吸动效，彻底废除 4.5px 粗暴绿光脉冲。
- `StatusDivider`：前文定义的 20px 居中极简微分割线，专用于对话流中的状态切换、上下文注入通知与时间节点提示。
- `Skeleton`：修复丢失的 `.skel-shimmer` 关键帧，提供流光占位与卡片骨架。
- `Toast`：统一现代 3D 堆叠视口（`ToastViewport`），支持手势甩动滑离与堆叠矩阵透视。

### Layer 4 浮动层与弹窗原语族

- `Dialog` & `ConfirmDialog`：统一的双主题毛玻璃 Backdrop，全局唯一的 ESC 键捕获栈（`LayerStackManager`），IME 中文选词保护，50ms 连击防抖。
- `Popover` & `Tooltip`：纯函数几何解算引擎，支持视口边缘自适应翻转；彻底清退 24px 浓黑大阴影，收敛至极简低对比度微发丝边框。
- `DropdownMenu`：数据驱动的级联子菜单，支持键盘方向键漫游与安全三角鼠标防掉出保护。

### Layer 5 复合工程容器原语族

- `Tree`：通用高性能树形控件，支持虚拟滚动、多选操作（Shift / Ctrl）与右键上下文菜单。
- `ZoomPan`：图片与多媒体手势容器，支持鼠标滚轮平滑缩放、拖拽平移与双击复原。
- `DiffViewer`：解耦的纯算法代码比对容器，引入 Fenwick Tree 动态行高索引，彻底解决折行几何错位。
- `TaskControl`：统一的后台任务与子代理控制面板，具备状态透视、进度感知与前端直接强杀（Kill）通道。
- `EnvVariableTable`：专为 MCP 服务器与环境变量配置设计的动态 Key-Value 编辑器，支持动态增删行与敏感字段掩码。

## 全仓核心架构断层与重大隐患清册

实勘过程中，我们在各个业务域中排查出了若干直接导致视觉崩坏、功能不可用或性能骤降的代码级重大事故与断层：

- **文件预览 11 个核心 CSS 类名全库定义为 0 严重事故**
  在 `FilePreview.tsx` 中引用的 11 个关键类名（`.filesPreviewMedia`、`.filesPreviewPdf`、`.filesTableWrap` 等）在全仓 CSS 中完全未定义。导致图片展示裸奔无约束、PDF 视窗严重塌陷、划词批注浮层完全脱节。
- **MCP 扩展服务致命功能断层：环境变量 Key-Value 动态行完全缺失**
  在 `McpServerForm.tsx` 与底层的 `McpServer` 接口中，完全没有环境变量（`env`）配置项。现实中主流的 GitHub、PostgreSQL 等需要注入 Token 或连接串的 MCP 服务，在当前界面下完全无法配置运行。同时界面上仍遗留已废弃的启停幽灵按钮，卡片头部堆叠 3 个鲜艳彩色 Badge 造成强烈的视觉噪音。
- **暗黑模式刺眼纯白底方块与大模型核心参数缺失**
  `ManualAddForm.tsx` 与 `ScanResultsModal.module.css` 硬编码了 `#ffffff` 背景色，在深色模式下呈现出刺眼的白底方块；且整个前端界面完全没有提供大模型核心的 Temperature（温度）与 Top-p（核采样）微调滑块，上下文长度也仅为毫无校验限制的裸文本输入框。
- **便签备忘录内部 5 大野生裸写控件泛滥**
  排查出 5 处野生实现：`MirrorDriftStatusBar.tsx` 裸用原生 `<input type="checkbox">`；底层通过 `document.createElement('input')` 粗暴构建复选框并硬编码十六进制色值；`NoteSidebarDrawer.tsx` 密集裸写 4 类原生按钮；自制无障碍盲区的 `dialogOverlay` 浮层；行内重命名裸写 `<input>` 依赖多层 `!important`。
- **代码比对器 pre-wrap 自动折行虚拟列表几何错位**
  `DiffCardUnifiedView.tsx` 与 `DiffCardSplitView.tsx` 硬编码了 `rowHeight = 22px`，但其内部代码行却开启了 `white-space: pre-wrap` 自动折行。视口变窄折行时，虚拟列表仍然按固定 22px 计算偏移，造成严重的几何偏差，甚至在查看长文件时出现底部代码被无故截断吞噬。
- **Zustand 状态层双轨 storeAccess 与 4 大高频重绘病灶**
  工程同时存在 `src/store/storeAccess.ts` 与 `src/api/storeAccess.ts`，UI 组件混用导入，违反单真理源原则并在打包时诱发循环依赖空指针；`PaneHeader` 订阅整本 `sessionsById` 导致全屏所有 Header 逐帧重绘；`MessageList` 订阅整条 `Session` 导致打字时上千条消息重新 Diff；选择器缺少 `useShallow` 导致流式打字时帧率从 60 FPS 骤降至 18 FPS。

## 纯粹中性黑白灰设计系统与样式法则

为了彻底根除界面中的“脏感”、“泥黄感”与“艳俗感”，我们将全面重构 Design Tokens，确立纯粹中性黑白灰的铁律：

- **冷中性色彩梯队**：以物理冷中性黑白灰为基座，浅色模式采用纯净微冷白底色与 1px 极细发丝边框；深色模式采用深空冷灰，彻底清除 `themeStore.ts` 注入的暖黄泥色内联覆盖。
- **零彩色状态指示**：常规状态（如模型切换、权限确认、会话状态）一律采用中性灰度呈现。除非极其严重的致命物理阻断（如系统崩溃、物理磁盘满），严禁在界面上滥用红色、橙色、绿色大面积色块。
- **克制的焦点对比度（≤10% 铁律）**：任何输入框、按钮处于激活（Active / Focused）状态时，禁止出现粗、深、实心黑框；相对基线，加深混入文本色严格控制在 3%~8%（上限 10%），呈现为肉眼可辨但极其柔软的浅灰勾勒。
- **极简低对比度微发丝阴影**：全面清退散落在 `sessionTabDrag`、Popover 与 Menu 中硬编码的 24px 双层浓黑大阴影，代之以 1px 发丝微线与极轻微的 2px 浅阴影（`hsl(0 0% 0% / 0.04)`）。
