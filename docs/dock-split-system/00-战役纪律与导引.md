# 右侧功能区分屏系统建设战役（Dock Split System）— 纪律与导引

> 战役代号：`dock-split-system`
> 启动时间：2026-10-27
> 权威协作纪律遵循：仓库根目录 `AGENTS.md`、`.agents/LOGIC_PLAN_NO_RETREAT.md`、`docs/agent-roles/`。

---

## 一、战役背景与用户核心意志

1. **大窗口维度（顶栏大标签页）**：
   - 顶栏 `class="_tabsContainer_1wzf4_71"`（即 `PaneHeader.tsx` 的 `styles.tabsContainer`）是按**对话（Session）**划分的大窗口标签栏。
   - 顶栏保留独立大工具标签（如不绑定具体会话工作区的常规独立 Terminal，用于全局命令行操作），但属于顶层窗口体系。
   - **绝对隔离红线**：对话内部在右侧功能区打开的窗口/面板，**绝对不能拖拽到顶部的 `_tabsContainer_1wzf4_71` 里面**！对话内的工具完全归属于当前会话右侧功能区生态。

2. **对话窗口内部闭环（左对话 + 右功能区）**：
   - 用户期望在**当前的对话窗口内实现所有的功能**，不需要在顶层切分会话，也不用在多个大窗口之间频繁跳出。
   - 左侧为对话区（消息流、思考过程、输入框）；
   - 右侧功能区（Right Tool Dock）必须具备**分屏系统（Split Screen System）**能力。

3. **分屏系统迁移到右侧功能区**：
   - 将此前在工作区顶层实现的二叉树分屏、分割线调节（Sash Resize）、落点检测（DropZone）等能力，下沉并迁移到**右侧功能区（`leafDockDrawer`）**内部；
   - 支持在右侧功能区内自由进行上下分屏、左右分屏、Sash 拖拽调比、分屏内多 Tab 切换；
   - 完美承载原生 ConPTY 终端、网页/浏览器预览、文件树、Diff 比对、总览等工具的协同工作。

## 二、战役工作区结构规范

严格遵守 `AGENTS.md` §4「战役工作区结构规范」：
1. **工作区根目录白名单**：仅存放纪律文档（本文件等）、总方案文档（`00-总方案.md`）、分维终稿详案。
2. **子目录仅允许一级**：
   - `analysis/`：第一轮现状调研与分维架构深度分析；
   - `independent-plans/`：第二轮独立总方案（2~3 份）；
   - `plan-reviews/`：第三轮方案交叉评审；
   - `detailed-plans/`：第四轮分维最终实现详案。
3. **归类充分原则**：同类文档归入同一子文件夹，禁止建立仅两三个文件的碎片文件夹。

## 三、第一轮派发计划（6 个专职分析 Agent）

- **Agent 1**：`analysis/01-分屏引擎模型与数据契约下沉.md`（状态树模型、序列化、与 SessionTab 解耦）
- **Agent 2**：`analysis/02-右坞容器与分屏渲染架构.md`（`leafDockDrawer` 容器改造、多窗格渲染、Sash 调节）
- **Agent 3**：`analysis/03-顶栏大窗口收敛与独立常规终端.md`（顶栏 `PaneHeader` 纯净化、独立常规 Terminal 机制）
- **Agent 4**：`analysis/04-拖拽体系与域隔离防线.md`（右坞内部专属拖拽流、物理级切断向顶栏逃逸）
- **Agent 5**：`analysis/05-多窗格运行时与资源生命周期.md`（ConPTY 终端、WebView 浏览器、Diff 等并发实例隔离与清理）
- **Agent 6**：`analysis/06-分屏交互体验与自适应布局.md`（右坞分屏工具栏、一键分屏、最大化/还原、容器查询）
