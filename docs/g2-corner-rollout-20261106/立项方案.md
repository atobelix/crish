### 1.3 关键订正与多轨总账

1. **popover keyframes 副本数订正**：动效审计 B 记「16 份字节相同副本」。扫描 2 本轮逐行定位的实测为：**6 个文件、18 个本地 keyframes 定义**（enter 5、enter-top 4、exit 5、exit-top 4），正典在 design-system.css（4 个定义）。差异可能来自审计后 SEP 增补一对或计数口径（按块/按名）不同。**本方案以扫描 2 的逐行定位（6 文件 18 定义）为准，审计 B 的 16 就此订正。** 副本文件：ui/Menu（4）、ui/Select/Select（4）、ui/Select/SelectContent（4）、provider/ModelBadgePickerMenu（2）、ui/SmartExpandablePanel（2）、settings/SettingsQuickMenu（2）。另有同族近亲（值对齐但自名自义）：DraftUndoToast、FileAnnotationPopover、PreviewCard、AnnotationChipItem 的本地对。处置见 §五 F2。
2. **别名层倒置**（三路互证）：861 条声明中 var 引用占 79.8%，其中约 **76%（约 524 条）挂在自称待清除的 WAVE2 废弃别名层**；语义角色层近乎闲置（`--radius-card` 仅 6 条引用）。「值没散，名字的权威层散了。」
3. **同心推导多轨**：组件本地同心链 6 条（composer / annotation / slash / soft-hint / toast / sep）+ 模块私有半径变量 **≥15 个**，值同源但定义分散——这是用户「不要放在哪里都是了」的现状形态全貌。

## 二、真相源设计定稿

以扫描 4 草案为底，吸收其余三路的约束。设计原则：**名义半径的真相源已经存在（tokens-radius.css / theme.ts），不新建数值体系；要新建的是「形状层」——一个参数、一份生成代码、一组接入面。**

### 2.1 参数层（tokens 内新增形状区）

桌面在 `styles/tokens-radius.css` 增设形状区（与半径定义同文件同作用域，深浅共用）：

```css
/* 形状层（G² 连续曲率）—— 全产品唯一形状来源 */
--corner-exponent: 2.42;          /* 超椭圆指数 n，全产品单值 */
--corner-kappa-peak: 1.337;       /* κ_peak = 1.337 / R，校验用常量，随 n 由公式锁定 */
```

- **单值而非逐档**：n 是曲率语言本身；逐档可调 = 每个表面自选形状，集中管理即失效。R 只决定 κ 大小，n 决定曲线族。
- **档位 → 形状待遇映射表**（写进 tokens 注释 + 守卫断言；表中「待定档」的最终待遇取决于待裁决 #1/#2）：

|---|---|---|---|

| 模态 | 名义 `--radius-modal` 24（实际消费走别名 2xl 20 / 3xl 24，见族 2） | `dialog` 36 / `overlay` 30 | G² 全表面（第一波）；名义值收敛随待裁决 #4 |
| 浮层外框 | `--radius-menu-outer` 18 / `--sep-radius-outer` | `menu` 18 / `sheetApproval` 24 | G² 全表面（第一波） |
| **R16 档（单独立档）** | 别名 `--radius-xl` 16（角色层无对应档） | `card` 20 / `codeCell` 16 | G² 全表面（第一/二波）。**扫描 1 硬约束**：16 是聊天域用量最大的外框档之一（图片、附件卡回退、Diff 预览卡、ApprovalDock、GoalRibbon、行状态底、草稿 toast、ui/PreviewCard），角色系在 card 12 与 dock 20 之间是空档——参数表必须为 R16 单独立档，设计稿参数表本有 R16（κ_peak ≈ 1/12.0） |

### 2.2 生成层（单一生成代码）

核心生成函数，单一实现，桌面/移动各一份同构转写 + 同一数值测试向量互校验：

```ts
// 输入：实测宽高、四角名义半径（逐角可为 0 = 该角直角/关闭）、指数 n
// 输出：闭合轮廓路径；每角取超椭圆四分之一段采样（设计稿 24 点/角，偏差 <0.02px）
cornerPath(w: number, h: number, r: {tl,tr,br,bl}, n = CORNER_EXPONENT): PathString
kappaPeak(R: number, n = CORNER_EXPONENT): number  // = ((n−1)/2)·2^(1/2+1/n) / R
```

由三路约束补强的生成法要求（定稿）：

1. **逐角开关**（扫描 1）：r 逐角独立，0 = 直角。覆盖 GoalRibbon docked、引用块、Sheet 顶角、气泡尾角。
2. **双轮廓切换**（扫描 1）：同一表面两态半径不同（pinPickerPopover 10→20）时，生成器须能产出两条轮廓并支持切换；是否补轮廓形变过渡由该面施工时定，不在生成层写死。
3. **max-content 宽表面优先可拉伸 SVG 背景层**（扫描 1）：SEP 族宽度由内容定且打开后可能因异步内容改宽，JS 测尺寸生成在此族最脆弱——此族首选 `background-size: 100% 100%` 的可拉伸 SVG 背景层；固定/可测尺寸面可用测尺寸生成。生成层须同时提供两种承载形态，接入清单逐面注明用哪种。
4. **同心链在生成层收口**：内层轮廓由生成器以 `R − padding` 直接生成（角占位 = 名义 R 保证与现行 `concentric-radius.contract.test.ts` 的公理完全兼容，数值断言不改、形状层另加断言）。禁止各模块再手写 calc 同心推导；现存 6 条本地同心链 + ≥15 个私有半径变量随迁移逐个退役，退役进度由棘轮清单跟踪（§2.4）。
5. **尺寸节拍**：仅在尺寸**落定**时重算；拖拽/动画进行中冻结为起始尺寸轮廓（槽 E 首个实测此策略）。生成结果按 (w,h,R) 缓存。
6. **桌面承载形态**：带阴影面走行内 SVG 背景层 + `filter: drop-shadow`（阴影跟随轮廓）；`<input>` 类 void 元素走同路径 `clip-path`；需要裁切子元素的面保留内层同轮廓 clip（接入清单逐项登记「裁切需求：有/无」）。
7. **移动承载形态**：并入 SoftShadow 体系——`SoftShadowSurface` 已按实测尺寸生成 SVG 轮廓，把其圆弧轮廓换成 cornerPath 输出即完成形状升级，宿主 API（传数值半径）不变。

### 2.3 接入层与禁止清单

接入面只声明**档位名**（`dock`/`modal`/`menu-outer`/`card`/`r16`…），不出现半径数字、更不出现路径数据。桌面两种接入形态（施工批二选一定死，不许两存）：

```tsx
// 形态 A：组件（适合本就是组件的表面：Dialog / Card / Popover / Toast …）
<G2Surface radius="dock" shadow="composer">…</G2Surface>
// 形态 B：全局工具类 + 数据属性（适合 module CSS 宿主；与 S4 退场层选全局类的理由相同——
// 全局类定义在 design-system.css 内，不存在 module CSS 按名引用悬空的失效模式）
<div class="crish-g2" data-g2-radius="20" data-g2-shadow="composer">
```

中央构造点范式沿用 `binary-tree/tabStripVars.ts` 的先例（「token 名不得散落到组件文件」的唯一构造点纪律）。

**五条禁止清单**（写入守卫，逐条对应检查）：
① 模块 CSS/TSX 中手写 SVG 角路径或 `corner-shape` 声明；
② 新增私有半径变量（`--*-radius` 局部定义）；
③ 新增裸 px `border-radius`（豁免清单除外）；
④ 以 `corner-shape` 作为唯一实现（可作渐进增强叠加，不得替代生成层）；
⑤ 生成函数被复制到第二个文件（两端同构转写是唯一例外，须共用测试向量）。

**边框面的统一处置原则**（扫描 1/3 共同约束，定稿框架、默认值待裁决 #5 拍板）：带 1px 边框的面在 G² 化后，旧弧边框必然与新轮廓在角部错位，二选一——(a) 边框改由同一生成路径描边（同路径 stroke）；(b) 该面去边框、改亮度台阶分面（与产品无描边方向一致，但属设计变更）。**每族默认（施工时按此执行，裁决后如有变更只改本表）**：

| 表面族 | 默认 | 理由 |
|---|---|---|
| 族 1 composer 卡 | (a) 同路径描边 | 边框是设计稿已定案的卡面构成（设计稿面板保留了轮廓描边口径） |
| 族 3 弹层/菜单族 | (a) 同路径描边 | `--border-panel` 是弹层分面的现行手段，整族去除是设计级变更 |
| 族 4 悬浮预览对 | (a) 同路径描边 | 描边+阴影是该面对的核心结构，改造本就是结构级 |
| 族 5 工具展开区（.toolResultBody/.batchBar） | (a) 同路径描边 | 边框是现行设计，R10 错位虽小但可见 |
| 族 2 模态族 | (a) 同路径描边 | 设置壳的 1px 边框与壳同为一面 |
| 族 12 启动器 Hub 卡 | (b) 去边框候选 | 单卡、底色台阶已足分面——**仅候选**，随待裁决 #5 一并定 |
| 其余零散带边框小面 | (a) 同路径描边 | 保守默认，不借 G² 推广顺手改设计 |

### 2.4 守卫设计（验产物，不只验意图）

沿审计 B 的 T8 教训（keyframes 悬空事故：守卫只验定义收敛、引用侧 42 处悬空在全绿收口里存活），三层：

**第一层 · 源码契约**（新文件 `g2-corner.contract.test.ts`，不改旧契约）：
1. 参数唯一性：全仓只有 tokens-radius.css 定义 `--corner-exponent` 且值 = 2.42；生成函数只有一处实现（路径白名单断言）。
2. 禁止清单扫描：全仓 CSS/TSX 正则扫 `corner-shape`、手写角路径特征、私有 `--*-radius:` 局部定义、裸 px `border-radius`——命中即红；豁免只能登记在契约内的豁免表（带理由与表面名，不许整文件豁免）。豁免表初始成员含 DiffCard 直角契约面（用户裁决）与 §1.4 排除项。
3. **棘轮基线**：现存违规（裸 px ≈30–40、私有半径变量 ≥15、别名层引用 ≈524 若纳入）逐项列成基线清单，断言「实际违规集合 ⊆ 基线集合」；基线只能由迁移批在同提交里删行，只减不增（kf-audit 原型的同构应用）。

**第二层 · 产物验证**（专防悬空）：
1. served-CSS/CSSOM 探针：构建后断言已接入面的最终样式**真的携带生成几何**（SVG 背景层存在且路径非空），不只断言源码写了类名。
2. 生成函数数值测试：采样偏差 < 0.02px；`kappaPeak(20) ≈ 1/14.96`；角占位包围盒恰为 R×R；`R − padding` 同心生成与旧同心契约数值断言并行不悖；两端共用同一组测试向量。
3. 计算值断言替代文本断言：半径相关的契约断言逐步从「源码文本」改为「计算值」（见 §五 F7）。

**第三层 · 视觉验收**（每波收口）：Chrome 无头全页截图 + 角部 5× 放大裁切存档，与胶囊端弧并置核对；MCP live 探针取 computed 样式；移动端加 P40 Pro 真机截图与帧率观察。视觉验收不进 CI，但每波报告必须附裁切图——G² 是视觉标准，最终裁判是像素。

### 2.5 风险与回滚（沿扫描 4，定稿保留）

主要风险八项（缓解均内建于上文）：① 阴影不跟随轮廓（drop-shadow 近似差距、filter 建立包含块影响 fixed 子元素——带阴影面逐个列入迁移槽单独验收）；② 尺寸动画中轮廓重生成（落定才重算、动画中冻结，槽 E 实测）；③ 焦点环被 clip-path 裁（void 元素已在设计稿验过焦点走亮度台阶；非输入面默认不用 clip-path）；④ 内容溢出裁切语义变化（接入清单逐项登记裁切需求）；⑤ 在场 SVG 层重绘成本（长列表面接入前先做滚动帧率 A/B，小半径面不在前两波）；⑥ 移动端 elevation 前科与 Kirin 990 性能（第 0 波试点先测）；⑦ 他线纠缠（沿 09:01 裁决动态排序，§三逐波写明）；⑧ 口径中途变更（待遇表是数据不是代码，改档只改表与接入声明，不动生成层）。

**回滚面干净**：形状层是叠加层——迁移不删除原 `border-radius` 声明（退居兜底），名义半径数值全程不动。单表面回滚 = 摘掉一处 G² 接入；整波回滚 = 按槽提交逐笔 revert，棘轮基线在回滚提交中声明回加。无不可逆步骤。
