# G² 圆角推广立项扫描 3 —— 壳与面板（桌面端）

- 扫描时间：2026-11-06 约 09:35–09:50 EST；分支 `chore/settings-rework-20261101`，HEAD `948a8f1ec`；行号以扫描时 PC 工作区磁盘内容为准（树内有他线未提交改动，且 S5b/S6 正在改会话列表动效与 Menu/SEP 一带，本报告只登记圆角，不登记动效归属）。
- 方法：`git grep` 全量普查 `border-radius` / `--radius*` / `corner-shape` / `clip-path`，再逐文件读选择器上下文核对关键表面；展开类表面按补充指令深挖全链路。
- G² 规格基准：设计说明第十一节——超椭圆角族 `(R−x)^n + (R−y)^n = R^n`，n = 2.42，κ_peak = 1.337/R，角占位 = 名义半径 R；生产须以自生成几何（SVG 背景层 / clip-path / 原生路径）复现，不得以 corner-shape 为唯一实现。

## 〇、总判定

1. **产品内 G² 现状 = 0 处。** `apps/crish-desktop` 全仓 `corner-shape` 引用 0 次；以 SVG 路径 / clip-path 实现的圆角 0 处（clip-path 仅 AnimatedCounter 数字滚轮的 `inset(50%)`，与圆角无关）。全仓唯一的 "squircle" 字样是侧栏底部一处**注释**（意图写了、实现是普通圆弧，见 §二 T3）。我范围内所有圆角均为普通圆弧、方角（radius: 0）或真圆（50%）。
2. **普查量级**：`apps/crish-desktop/src` 内 `border-radius` 声明共 **938 行**（含测试与 token 文件），其中含 `var()` 引用 716 行、纯字面量 222 行。本报告核心范围（sidebar/、binary-tree/、files/、overview/、shell/ 五目录 + ui/PreviewCard + workspace/PreviewCard + ComposerPlanProgressBar + App.module.css，不含测试）共 **149 处**声明，其中 39 处无 var()——绝大多数是 `radius: 0` 与 `50%`，真正的数值字面量只有 6 处（10px×3、18px×1、1px×2），但都落在高可见表面上（用户卡、启动器搜索栏）。
3. **定义层是双层制**：`styles/tokens-radius.css` 上层是 5 档角色 token（SSOT 自称），下层是一整层标注 `[WAVE2-DEPRECATED-ALIAS]` 的待废弃别名；实际引用量别名层约 **670 次**、角色层约 **170 次**（git grep 命中量级，含定义与测试）——别名层仍是事实主力，「专门集中管理」的首要障碍不是缺 token，而是存量引用压倒性地挂在自称待废弃的那一层上。

## 四、最难三处

### 之一：`.leafBody` 内容矩形（`BinaryTreeWorkspace.module.css:350`，现 12px via `--radius-l`）

全产品爆炸半径最大的一个角：每个叶的主区、右侧坞抽屉（含最大化态）、所有窗格工具的外角都由它一处裁切形成。它难在三层：① **值先要裁决**——它挂在废弃别名 `--radius-l`（12px）上，而设计正典里「坞级」名义半径是 `--radius-dock` 20px（该 token 唯一消费者却是 composer，见 T2）；G² 化是按 12 保形转换、还是顺势对齐 20，是产品决定不是机械替换，且 12→20 会连带改变叶内一切贴边内容的可用角域。② **实现层**——它是 flex 布局容器 + overflow hidden + 底色 `--leaf-card-bg`，尺寸随窗口/分屏/抽屉动画逐帧变；设计稿的生成法是「按实测尺寸出路径」，产品化需要尺寸驱动的持续重算（或等价的纯 CSS 技法），且其裁切域内住着聊天滚动区（含 S3 悬浮滚动条）、抽屉保活壳等多个已验收结构，任何呈现层替换都要回归这些面。③ **契约真空**——它不在 concentric-radius 契约的钉住面内，改对改错没有现成守卫兜底，须先补计算值级守卫再动。

### 之二：带边框浮层对——ui/PreviewCard `.popup`（16px）与 NewTabLauncherPopover `.popoverContent`（18px）

两者同病：**border + box-shadow + （后者）内滚 + scale 入退场**四要素叠在一个圆角盒上。普通圆弧时代这四者由 border-radius 一并解决；G² 的两条现行出图路线各破一处——clip-path 裁掉边框与阴影、SVG 背景层不描边且与内滚裁切需另行安排。设计稿对请求面板给出的解（SVG 层 + drop-shadow 跟随轮廓）可移植，但浮层还要叠加：PreviewCard 的 Bézier 箭头锚位、Popover 的滚动区裁切与 Radix Presence 退场保活。结论：这两面需要「外壳/内滚」结构拆分级的改造，应作为 G² 基建（中央出图工具）建成后的第二批，而不是第一批试水面。

### 之三：侧栏会话行族（`SidebarSessionList.module.css`，12 处圆角声明）

难在它是一个**状态机而不是一个面**：同一行展开态 10px（`--radius-lg`）、侧栏折叠态 8px（`--radius-md`）；拖拽幽灵是第三个值 16px（`--radius-xl`）且与源行不一致；行外有两层手风琴裁切壳、列表本体是窗口化虚拟列表（行回收复用），且 S6 正在给同一批行加增删/重排/退场动画。G² 若走逐行路径生成，生成时机要嵌进虚拟化回收与 FLIP 测量之间，稍有不慎就与 S6 的几何补位互相踩踏；若走纯 CSS 中央技法，又要同时覆盖 10/8 两态与幽灵层。施工切分上它必须与 S6 收口对账后单独成批，且先统一「幽灵=源行」的同值纪律再谈曲率。
