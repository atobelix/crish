# G² 圆角推广立项扫描 ②：弹层与设置（桌面端）

- 扫描时间：2026-11-06（只读，未改任何代码）
- 范围：`apps/crish-desktop/src` 的全部 popover / menu / dropdown、Dialog/Modal、上下文菜单、Toast/通知、Tooltip、设置面板全链、登录/账号浮层
- G² 规格基准：设计说明第十一节——超椭圆角族 n = 2.42、κ_peak = 1.337/R、角占位 = 名义半径 R；生产须以自生成几何（SVG 背景层 / clip-path / 原生路径）复现，不得以 corner-shape 为唯一实现
- **总判定：本范围内现状圆角全部为普通圆弧，无一处已 G² 化**（下表「G²」列统一为「否」，不再逐行重复）。全域 `border-radius` 声明约 460+ 行落在约 110 个 CSS 文件（本范围目录口径）。

### ToastCard 圆角全链路（token → CSS → 组件）

```
tokens-radius.css  --radius-md: 8px（别名层）
  → ToastStackModern.module.css :88  .toastCard 局部定义

      --toast-py: var(--space-2_5, 10px)          （:85，纵向 padding）
```

这是全产品少有的**真同心推导**（外角 = 内钮角 + 间距），与 menu 族的 token 直给形成对照。G² 化时该推导关系应保留：名义 R 仍 18，轮廓换 n=2.42 超椭圆即可，钮侧（8px 小角）按同一生成法或维持小圆弧由施工批定。

### 动效 × 圆角相互影响（Toast 是全产品耦合最深的面）

- **堆叠变换**：非 front 卡以 `transform: translate… scale(1 − 0.08·index)` 叠放（:78、:146-153），展开态回到 scale(1)（:157-163）——变换作用于整元素，G² 背景层（SVG）随元素缩放，轮廓形状不变（等比缩放下超椭圆指数不变），无冲突。
- **进场**：本地 `@keyframes toastEnterBottom`（:230，translateY(120%) scale(.92) → 原位），仅 `data-state='entering'` 触发；**退场/滑动关闭走 transform transition**（:246-264，translateX(100%+40px) scale(.96)），非 keyframes——两套机制并行，改角不动其时序。
- **硬耦合：`overflow: hidden`**（:105）。卡内进度条（`.progressTrack/.progressBar`，:274-292，本地 toastProgress scaleX 动画）贴底边排布。CSS 的 overflow 裁剪跟随 **border-radius** 而非背景层：若 G² 只以 SVG 背景层呈现、border-radius 保留 18px 圆弧，则裁剪轮廓（圆弧）与视觉轮廓（G²）不一致——角部会出现进度条被多裁/少裁的像素级错位。**Toast 改 G² 必须背景层 + clip-path 同步换轮廓**，不能只换背景。
- 阴影：toastCard 用 box-shadow（随 border-radius 走）——换 G² 后须改走 drop-shadow 跟随轮廓，与设计稿口径一致，需与堆叠 scale 叠加实测。

### DraftUndoToast 的配方位置

本地 keyframes `undoToastIn/undoToastOut`（文件内自带定义，值对齐 popover -top 变体 scale .97/+4px，时长走 --transition-popover-enter/exit）+ S4 退场经 `data-closing` 属性。它是「本地副本」模式的正确样本（与 §六-1 的 popover 副本同因：Vite CSS Modules 按名跨模块引用会悬空）。G² 点仅外角一处（16），风险低。

- 壳的进/退场由 ui/Dialog 本地 keyframes 承担（dialog-enter scale .96→1 / dialog-exit，[data-ending-style] 触发，Dialog.module.css:154/159/172/183）——变换作用于 .panel 本体，G² 背景层随之缩放，无时序冲突。
- `.settingsModal` 同 Toast 有 **overflow: hidden**：左侧导航与内容区在四角贴边，裁剪轮廓与 G² 背景轮廓不一致的风险同 §四（须 clip 同步）。且面板尺寸大（max 1040×760），是 G² 轮廓采样/性能的压力面。
- 子页切换（.coverContent 整页替换）无圆角参与；行组卡无进退场动画，改角为静态替换，风险低。
- 特异性注意：只改 Dialog 基座不会传导到设置面板（被 [role='dialog'] 覆盖同值挡住），反之亦然——**两处定义必须成对处理或先收敛为一处**，这是设置壳 G² 化的首要改造点。
- 守卫：`settings-css-guard.contract.test.ts` 对设置 CSS 有既有断言，半径变更须同步核对契约。

### 附带发现（口径漂移，登记）

- 全局类 `.settings-select-trigger` 被 FirstRunWizard（:127）与 ScheduledTasksPanel（:230）的 `:global(...)` 规则引用，但**全仓无任何组件输出该类名**（TSX/CSS 全量搜索零发射方）——两处 border-radius 规则（--radius-xl / --radius-md）为死规则，G² 推广时应一并清理登记，勿当作活面改造。

## 六、深挖 ③：斜杠面板 TiptapSlashMenu 与 popover 副本的关系

### 圆角全链路

```
tokens-radius.css  --radius-menu-outer: 18px / --radius-menu-inner: 12px
  → TiptapSlashMenu.module.css .popoverContent（:9-15）本地变量转译：
      --slash-radius-outer: var(--radius-menu-outer, 18px)
      --slash-radius-inner: var(--radius-menu-inner, 12px)
      --slash-pad: 6px
  → border-radius: var(--slash-radius-outer)（:28）；.menuItem（:71）var(--slash-radius-inner)
  → 18 − 6 = 12：与 Menu 正典同构的真同心对
宿主：TiptapSlashMenu.tsx → Radix Popover（@radix-ui/react-popover ^1.1.23，仓内唯一的 Radix 弹层；
      其余 popover/menu/dialog 均为 Base UI 或自研）
```

### 与「16 份副本」的确切关系：它不是副本持有者，而是按名消费者——且动画已死

- 它的进/退场（.module.css:44-58）**直接按名引用** design-system.css 的全局 keyframes：`animation: crish-popover-enter / -enter-top / -exit / -exit-top`，本文件**无本地定义**，文件头注释自称「浮层配方归队（AN2/A6）：进/出场统一走全局共享 keyframes」。
- 但按已实证的 Vite CSS Modules 机制（产物 served CSS 核验，见 keyframes 审计）：module 内 `animation` 的 keyframes 名会被 scoped 重命名，指向无定义名 → **斜杠菜单的进/退场动画当前实际是死的**（动效审计 B 的悬空清单已列 TiptapSlashMenu）。「归队」的方式恰是失效的方式。
- 与副本持有者形成两极：Menu/Select 等把 keyframes 抄进本模块（活着，但多轨）；SlashMenu 只按名引用（单轨，但已死）。G² 推广若只换圆角不动配方，这条死动画会原样带过；若顺带收敛配方，须先裁决统一路线（全局工具类 vs 本地副本），属立项决策点。

### G² 改造点与独有风险

1. 外角 18 一处、内项 12 一处，几何面小；`.popoverContent` 有 `overflow-y: auto`（max-height 420px）——滚动内容贴角，overflow 裁剪跟 border-radius 走的老问题同样存在。
2. **独有风险：`backdrop-filter: blur(20px)` + 半透底**（`--slash-menu-bg` 回退 --surface-overlay）。backdrop-filter 的作用区域按元素盒 + border-radius 裁剪；若 G² 改走 SVG 背景层（元素自身底色改透明、填充交给 SVG），blur 区域仍按旧 border-radius 圆弧裁剪，角部会出现「模糊到圆弧、填充是 G²」的双轮廓错位。此面在改 G² 前须先做一轮渲染实测，不能直接套 Toast/菜单的配方。
3. box-shadow 用 `--shadow-lift-card`（:30），换 G² 后须改 drop-shadow 跟随轮廓并与该 token 对齐。
4. transform-origin 走 Radix 的 `--radix-popover-content-transform-origin`，进场动画（若先修活）为 scale 类变换，与 G² 无冲突。

## 八、本范围最难的三处

1. **Dialog 基座 + 设置面板壳（§五-2 / §三首行）**：全产品最大的圆角面（1040×760）、overflow:hidden 裁剪、Base UI [data-ending-style] 退场时序、且 20px 同值两处定义（基座 + [role='dialog'] 覆盖）互相挡传导。G² 落地须「背景层 + clip-path + drop-shadow」三件套同步换，还不能碰坏嵌套弹窗的遮罩交还逻辑（Dialog.module.css:45-51 的 :has 链）。改造面牵连所有走 Dialog 的模态。
2. **Toast 堆叠卡（§四）**：transform 堆叠（逐卡 scale/translate 实时合成）+ overflow:hidden + 进场 keyframes 与退场 transition 双机制 + 底部进度条贴角——动效与圆角的耦合全产品最深；裁剪轮廓必须与 G² 填充轮廓逐像素一致，堆叠缩放下还要保持。
3. **TiptapSlashMenu（§六）**：唯一 Radix 弹层 + backdrop-filter 半透模糊 + 动画配方本身已死——「先修活配方、再换角」复合面，且 backdrop blur 的裁剪形状与 SVG 背景轮廓的错位是全产品独有、未经实测的风险，不能套用其它 popover 的现成配方。

（次难备考：ColorPicker 的字面量收编属量大但机械；Select 双轨合并属前置整理而非几何难点。）
