## 1. 目标与原则

### 1.1 用户四诉求(本方案的全部验收基线)

| # | 诉求 | 语义 |
|---|---|---|
| 1 | 网络中断继续 | provider 网络问题中断输出后,能经系统调度继续任务 |
| 2 | 子 agent 分配上限 | 明确真值并统一口径 |
| 3 | 子 agent 失败恢复 | 子 agent 网络中断后,主 agent/系统能恢复;主 agent 可接管继续、可关闭子 agent 重来 |
| 4 | 「未停就该一直工作」 | 只要 agent 未主动停止、用户未手动停止,agent(主/子)应能一直工作;goal 模式下未完成任务但 agent 主动结束,系统也能继续 |

### 1.2 设计原则(五份方案共识,评审确认)

1. **接线而非新写**:恢复所需算法资产(C7 四级阶梯 + Episode 预算 + fork 三态、retry.rs 退避、内核重试阶梯、T-CF-11 拉起器、checkpoint 三件套)全部已实现且测试充分,本轮缺口 100% 是接线与数据面补全。
2. **单一自动继续通道**:所有自动继续(error 可重试 / goal 未完成 / 定时器到期 / 子代理失败通知 / 重启恢复 / watcher 异步唤醒)共用 `PendingMessageQueue + decide_idle_resume + spawn_idle_resume_run`(core_run_commands.rs:2505-2671),差异仅在唤醒源与注入文本;不新造循环。
3. **引擎为权威,前端为投影**(goal 域):goal 状态与判定进引擎,前端 /goal 循环降级为投影与入口。
4. **禁补丁禁假接线**:禁止占位树/占位实现后再二次接线;所有接线一次到位。
5. **同文件同批**:stream_error.rs、core_run_commands.rs 等汇聚文件单次改完,禁止分批串行改动。
6. **数据面集中**:事件登记、命令登记集中一次;键命名空间各能力独占。

### 1.3 选型复杂度标准(用户裁定)

候选实现**代码量差距在几千行以内时,直接选效果更好的**;差距过大(数倍)才放弃。评估含测试代码量。

## 4. 维度依赖 DAG(逻辑执行序,不含工期)

```
D1 传输层 ──────────────┐
                        ├──→ D2 主run error续run ──┐
D3 C7接线 ──→ D4 命令面/工具面                        │
                        │                          ├──→ D6 唤醒链路 → D7 恢复质量
D5 goal 引擎化 ─────────┘(四源并入 D6 判定) ──────────┘
D8 观测/UI:横切,事件面随 D3/D5、UI 面随 D4
```

- **并行集**:{D1, D3, D5, D6-①(store 真适配), D8-hydrate 项} 互相独立。
- **串行链**:D1→D2;D3→D4;D6-①→D6-②(watcher)→D6-③(恢复条目);D6→D7。
- **同批约束**(实现批次,非维度合并):
  - D1+D2 同批(stream_error.rs 同文件单次改;退避/熔断/provider_error/error 续 run 一次落地,防止「快速连打」风暴在跨 run 层面复现)。
  - D2 与 D5 的 decide_idle_resume 分支同批接线(:2513 区域一次改完,error 分支与 goal_pending 分支并存,error 轮不计 stalled)。
  - 事件登记(D3 的 recovery-* + D5 的 goal-*)集中一次登记,禁止分两批。
  - core_run_commands.rs 为 D1/D2/D3/D4/D5/D6 汇聚面,派单按文件互斥串行。
  - **run_restore 合并批**:D3+D5+D6+D8 同批串行(run_restore 单函数一次改完)。

## 5. 护栏与红线汇总(整合版 = 五方案并集 + 评审补充)

1. **12/5/1 递归守卫只增不减**:恢复路径 fork 必须显式走 spawn 守卫,先释放旧 run 记账;嵌套禁令不变。
2. **用户显式停止永不自动续**:Stopped/Aborted/abort_signal/user_touched 为硬条件,扩展至全部新唤醒源(含 error 续 run 与 goal_pending)。
3. **连续失败上限**:error 续 run ≤3(Episode 预算 main 指纹)+ 退避 + 非 retryable 不续;run 内重试与跨 run 重试分层预算。
4. **空转护栏**:IDLE_RESUME_MAX_EMPTY_ROUNDS=3;定时器/Cron 空注入轮**不计** streak(待命是正常态);goal 续轮无 AI 产出**计入**空转且按 stalled 独立计数。
5. **goal 护栏**:max_rounds/max_stalled 持久化于 goal_state;错误收场不续轮;stalled 签名连续相同超限转人工。
6. **探索类文档配额不绕过**:fork 沿用同 session_id 时配额语义自动延续。
7. **Episode 预算(默认 3,重启不重放授权)+ 会话级熔断**(连续 6 次、成功归零、闸 run 内重试、手动不受限、部分保留断流计入)。
8. **恢复风暴护栏**:子代理 interrupted 只通知不自动 fork;恢复条目按会话合并注入(上限 16 条,超出注明省略);watcher 首轮延迟与最小拉 run 间隔。
9. **重复副作用防护**:三层 produced_content 镜像;重试基于完整对话新请求;建议重试 run 装配 ToolIdempotencyGuard。
10. **token 成本**:失败尝试不记账;goal 轮数硬上限 + 成本观测(RecoveryStatus.goalState.currentRound)。
11. **性能红线**:F2-27 spawn_blocking 覆盖 RecoveryCoordinator 全部持久化路径 + 命令面(kill_all/resume/kill_subagent)+ goal_state/熔断键读写 + store 真适配调用面。
12. **数据面纪律**:键命名空间各能力独占、宽容解析 fail-open、单写方、事件 minor 兼容、命令双端四步登记。
13. **测试资产门禁**:recovery.rs 24 单测 + 4 集成测试 37 用例作接线回归面;markdown-editor 门禁与 5 个专项 spec 不受影响;禁止 --no-verify。

## 7. 轮次执行规则(多 Agent 协同)

1. 每轮 ≤12 个 Agent,按实际需求灵活确定数量,不强制占满。
2. 每轮完整链路:问题识别 → 任务分解 → Agent 分配 → 并行修复 → 结果汇总 → 验证门禁 → 输出为下一轮输入。
3. 同文件串行纪律:core_run_commands.rs、stream_error.rs、events.rs 等汇聚文件的改动,派单按文件互斥(同一文件不同时派两个 Agent)。
4. 每轮完成后 git 提交(主控执行);轮次间文档落盘 UTF-8 无 BOM。
5. 本轮产物:dimensions/ 8 份维度文档 → 维度评审(3 个 Agent)→ 修订 → final/ 定稿。
