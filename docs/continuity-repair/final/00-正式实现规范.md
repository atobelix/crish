## 1. 方案目标与验收基线

### 1.1 能力目标(对应用户四诉求)

| # | 能力 | 达成形态 |
|---|---|---|
| 1 | 网络中断继续 | 传输层分级重试 + 会话级熔断 + 主 run error 自动续 run + 子代理四级恢复阶梯,「断网不丢任务」 |
| 2 | 子代理上限口径 | 统一表述:同时运行(未终态)子代理 ≤12、同父 ≤5、深度仅 1(DEFAULT_RECURSION_GUARD 真值) |
| 3 | 子代理失败恢复 | 主 agent 三决策路径:接管(自己继续)/ 重派(resume_subagent)/ 关闭重来(kill_subagent + 重派);系统侧四级恢复阶梯兜底 |
| 4 | 「未停就该一直工作」 | 统一自动继续通道(唤醒源汇聚 → 收口判定 → 拉起器)→ 覆盖 error 续 run / goal 续轮 / 定时器 / 子代理通知 / 重启恢复;goal 引擎化为权威 |

### 1.2 验收基线(全能力集)

1. 网络波动下任务不中断:单 run 内瞬态重试(带退避)耗尽 → 自动续 run(预算内)→ 子代理经恢复阶梯;全程无需用户干预。
2. 用户显式停止永不自动续;非瞬态错误(Auth/Quota/InvalidRequest)不自动续。
3. goal 未完成 stop 收场 → 引擎自动续轮至完成/上限/停滞;12 轮上限、stalled 检测、错误轮不计。
4. 无人值守:定时器/Cron 跨重启持久化;AI 休眠后到期事件由 watcher 拉起 run。
5. 重启恢复:状态一致性 + 主 run 续跑(恢复条目)+ 子代理只通知不自动重派。
6. 全部自动恢复受预算/熔断/空转/配额四重护栏约束,不产生恢复风暴。
7. 既有门禁全绿:recovery.rs 24 单测 + 4 集成测试 37 用例、markdown-editor 门禁、5 专项 spec、registry_drift、command_manifest 条数(107/102/5)。

## 3. 能力契约(实现必守)

### 3.1 自动继续通道(单一机制)

所有自动继续共用 `PendingMessageQueue + decide_idle_resume + spawn_idle_resume_run`:

| 唤醒源 | 触发条件 | 注入文本 | 预算/护栏 |
|---|---|---|---|
| error 续 run | reason=Error && retryable && !熔断 && 预算内 | 「上一轮 provider 中断(<kind>),继续任务」 | Episode 预算 fingerprint("main", 任务, error-retry) ≤3;不计空转 streak |
| goal 续轮 | reason=Stop && goal_pending(未完成 && 未达上限) | goal 前缀 + nextSteps 增强 | max_rounds/max_stalled;无产出计入空转 + stalled 独立计数 |
| 定时器/Cron | 队列条目(timer-<id>/cron-<id>) | 到期提示 | 空注入轮不计 streak(待命正常态) |
| 子代理通知 | 队列条目(subagent-terminal-<run_id>) | 终态摘要 | 无预算(通知非恢复) |
| 重启恢复 | run_restore interrupted → restore-<run_id> 条目 | 「上次被重启打断,请继续」 | 主 run 自动续跑;子代理只通知不自动 fork;合并注入 ≤16 条 |
| watcher 异步 | 队列非空 && 无活动 run && !user_stopped | 由队列内容决定 | 首轮延迟 5s、最小拉 run 间隔 10s、串行守卫防重入 |

**硬边界**:Stopped/Aborted(用户停止)/abort_signal/user_touched 一律不自动续;error 轮不计 goal stalled;子代理 run 永不参与 idle 续 run(防自续循环)。

### 3.2 传输层恢复阶梯(分层决策链)

```
流错误(ClassifiedStreamError)
  ├─ 瞬态(RateLimit/ServerError/Timeout/Network)
  │    ├─ 熔断闸:provider_fail_streak ≥6(连续,成功归零,部分保留断流计入)→ 直接 fatal
  │    └─ 退避重试:max(指数 750ms×2^(n-1), Retry-After);429 钳 min(5min, 预算),
  │       其余钳 8s;总预算 60s;abort select! 竞速;上限 3 次/run
  ├─ ContextLengthExceeded → length 阶梯(8192→16384→32768,×2 次)→ 压缩阶梯
  ├─ PayloadTooLarge → 压缩阶梯(真实压缩 + 重试 1 次)
  └─ 其余(不可重试)→ fatal → PROVIDER_ERROR → RunOutcome.provider_error 填充
```

熔断键:`provider_fail_streak` {count, first_fail_at_ms, last_fail_at_ms, window_ms}(窗口默认 0=无窗口);熔断触发发 `runtime-intervention-required` + `recovery-escalated(detail=Some("circuit-trip"))`;手动路径不受限。

### 3.3 恢复阶梯(子代理)

| 阶梯 | 机制 | 触发 |
|---|---|---|
| 1 | 收口后重派:原 run failed(reason=recovery-retry)+ 预算内重派新 run(mode=recovery-retry) | 瞬态错误且预算内;不消费 Episode、无 steering |
| 2 | 主 agent 激活:steering 条目(recovery-<run_id>)+ recover_notifications 落库 | 阶梯 1 预算耗尽;重启后 restore_steering_notifications 重排 |
| 3 | fork 重分配:SessionTree::fork + 三态上下文继承(Verbatim/Summarized/New)+ Episode 预算 | 主 agent 决策(resume_subagent 命令面);走 spawn 守卫受 12/5/1 约束 |
| 4 | 上报用户:recover_needs_user + 尝试明细 | 全部预算耗尽 / 非瞬态 |

装配:每会话 RecoveryCoordinator 五件套(store/queue/tree/spawner/policy);SessionTree 经 from_session_record 重建;全部持久化走 spawn_blocking(F2-27)。

### 3.4 goal 引擎化

- 载体:session_meta `goal_state` {goal, max_rounds, max_stalled_rounds, current_round, stalled_rounds, progress_signature, stopped_reason, schemaVersion, updatedAtMs}(snake_case;唯一写方=收口 RoundAssessment)。
- 判定:RoundAssessment(纯函数)= endReason × 本轮产出 × goal_state → Continue/Completed/NoProgress/Blocked;L0+L1 完成门禁;stalled = 工具批指纹(无工具轮不变);allows_auto_continue 首个生产调用。
- 续轮:四源 goal_pending → spawn_idle_resume_run(mode=goal-continue);注入 = 队列事件优先 + goal 前缀拼接。
- 事件:goal-round-started/completed/continuation-decided(载荷以 D5 §3.9 统一字段集,envelope 通道)。
- 前端:??5 分叉统一 12;decideGoalContinuation 保留过渡,投影化消费事件。

### 3.5 子代理三决策路径(主 agent 侧)

| 决策 | 入口 | 机制 |
|---|---|---|
| 接管继续 | 主 agent 自由裁量(文档化确认) | 收到失败通知后不重派、下一轮自行继续;通知承载错误 kind/retries |
| 重派 | resume_subagent 命令 | kill-for-resume + fork 新 run(三态继承 + Episode 预算 + 幂等) |
| 关闭重来 | kill_subagent 命令 + 主 agent 工具(新) | 单目标 L3 强停 + mark_row_failed;kill_all 批量语义保持 |

### 3.6 checkpoint 机制面

收口采集(collect_checkpoint_from_messages)→ set_leaf_checkpoint → 拉起器注入(read_leaf_checkpoint 摘要,500 字符截断,损坏降级);Verbatim fork 带 history 注入(RunFailureContext.history + SubagentSpawnRequest.history);水合 error 态放行 + failed-turn 标记。

## 5. 红线(不可谈判)

1. 12/5/1 递归守卫只增不减;恢复路径 fork 显式走 spawn 守卫;嵌套禁令不变。
2. 用户显式停止(Stopped/Aborted/abort_signal/user_touched)永不自动续。
3. 子代理 interrupted 只通知不自动 fork(自动重派违反「所有子 Agent 由主 Agent 分配」)。
4. 测试资产门禁:recovery.rs 24 单测 + 4 集成 37 用例作回归面;markdown-editor 门禁与 5 专项 spec 不受影响;禁止 --no-verify。
5. 探索类文档配额不绕过(fork 沿用同 session_id 自动延续)。
6. 禁止假接线/占位实现后再二次接线;同文件同批(stream_error.rs、core_run_commands.rs、run_restore 单函数)。
7. 事件登记集中一次(41→49),禁止分两批。
8. F2-27 spawn_blocking 覆盖全部同步 SQLite 调用面(含命令面)。

## 7. 闭环迭代机制(多轮适用)

1. 每轮:问题识别 → 任务分解 → Agent 分配(≤12,文件域互斥)→ 并行修复 → 结果汇总 → 验证门禁 → 输出为下一轮输入。
2. 子 Agent 空返回:默认供应商网络问题——先核查落盘,未落盘原样重派(不设上限);6 次以上由主控接管或拆小重派。
3. 每轮完成后 git 提交;文档 UTF-8 无 BOM。
4. 发现任务书未覆盖问题:子 Agent 上报 → 主控裁决 → 裁决归档(追加本文件或 02-定夺)。
5. 最终实现以本文件 + 各维度文档为准;如需偏离,必须显式标注「与正式规范冲突」并提请主控批准。
