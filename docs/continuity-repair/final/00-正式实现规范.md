### 1.2 验收基线(全能力集)

1. 网络波动下任务不中断:单 run 内瞬态重试(带退避)耗尽 → 自动续 run(预算内)→ 子代理经恢复阶梯;全程无需用户干预。
2. 用户显式停止永不自动续;非瞬态错误(Auth/Quota/InvalidRequest)不自动续。
3. goal 未完成 stop 收场 → 引擎自动续轮至完成/上限/停滞;12 轮上限、stalled 检测、错误轮不计。
4. 无人值守:定时器/Cron 跨重启持久化;AI 休眠后到期事件由 watcher 拉起 run。
5. 重启恢复:状态一致性 + 主 run 续跑(恢复条目)+ 子代理只通知不自动重派。
6. 全部自动恢复受预算/熔断/空转/配额四重护栏约束,不产生恢复风暴。
7. 既有门禁全绿:recovery.rs 24 单测 + 4 集成测试 37 用例、markdown-editor 门禁、5 专项 spec、registry_drift、command_manifest 条数(108/103/6,含 core_compact_now)。

## 3. 能力契约(实现必守)

### 3.1 自动继续通道(单一机制)

所有自动继续共用 `PendingMessageQueue + decide_idle_resume + spawn_idle_resume_run`:

| 唤醒源             | 触发条件                                                             | 注入文本                                                         | 信息分级(接收面,§9)                                                                    | 预算/护栏                                                                                                                  |
| ------------------ | -------------------------------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| error 续 run       | reason=Error && retryable && !熔断 && 预算内                         | 「继续任务」                                                     | AI 对话(最小化,不携带重试细节);kind/进度走临时通知(§9.1)                               | Episode 预算 fingerprint("main", 任务, error-retry) ≤3;不计空转 streak                                                     |
| goal 续轮          | reason=Stop && goal_pending(未完成 && 未达上限)                      | goal 前缀 + nextSteps 增强                                       | AI 对话(任务级)                                                                        | max_rounds/max_stalled;无产出计入空转 + stalled 独立计数                                                                   |
| 定时器/Cron        | 队列条目(timer-<id>/cron-<id>)                                       | 到期提示                                                         | AI 对话                                                                                | 空注入轮不计 streak(待命正常态)                                                                                            |
| 子代理通知         | 队列条目(subagent-terminal-<run_id>)                                 | 终态摘要                                                         | AI 对话(steering 注入,含 kind/retries);progress 走 subagent-event 观测面(不给 AI 对话) | 无预算(通知非恢复);运行中 progress 汇报经 subagent-event 通道(E3,§8.3),终态才写 steering                                   |
| content-resume(E1) | reason=Stop && 最后消息 providerErrorKind ∈ 瞬态四类 && 预算内(§8.1) | 「上一轮生成中断(<kind>),请从断点继续完成,不要重复已输出的内容」 | AI 对话(续写指令,锁定模板)                                                             | content_resume_max 默认 2,独立指纹域;熔断闸;不计空转 streak                                                                |
| 重启恢复           | run_restore interrupted → restore-<run_id> 条目                      | 「上次被重启打断,请继续」                                        | AI 对话                                                                                | 主 run 自动续跑;子代理只通知不自动 fork;合并注入 ≤16 条(注:该 16 为恢复条目数,与 16/16/1 守卫 max_concurrent 的 16 无关联) |
| watcher 异步       | 队列非空 && 无活动 run && !user_stopped                              | 由队列内容决定                                                   | 由队列内容决定                                                                         | 首轮延迟 5s、最小拉 run 间隔 10s、串行守卫防重入                                                                           |

**硬边界**:Stopped/Aborted(用户停止)/abort_signal/user_touched 一律不自动续;error 轮不计 goal stalled;子代理 run 永不参与 idle 续 run(防自续循环)。

### 3.2 传输层恢复阶梯(分层决策链)

```
流错误(ClassifiedStreamError)
  ├─ 瞬态(RateLimit/ServerError/Timeout/Network)
  │    ├─ 熔断闸:provider_fail_streak ≥6(连续,成功归零,部分保留断流计入)→ 直接 fatal
  │    └─ 退避重试:max(指数 750ms×2^(n-1), Retry-After);429 钳 min(5min, 预算),
  │       其余钳 8s;总预算 60s;abort select! 竞速;上限 3 次/run;
  │       每次尝试经 provider-diagnostic 事件(phase=Retry, attempt/max_attempts)展示,
  │       临时通知区老虎机滚动呈现,不进对话(§9.1)
  ├─ 部分保留断流(已产出部分文本后断流,最后消息 providerErrorKind ∈ 瞬态四类)
  │    → 收场 reason=Stop → decide_idle_resume Stop 分支子分支自动拉起续写 run(E1,§8.1):
  │      指纹域 content-resume 上限 2;注入锁定模板
  │      「上一轮生成中断(<kind>),请从断点继续完成,不要重复已输出的内容」;
  │      已产出文本经历史水合携带,不重复注入请求体;续写 run 自身 Error 收场 → 降级 error 通道
  ├─ ContextLengthExceeded → length 阶梯(8192→16384→32768,×2 次)→ 压缩阶梯
  ├─ PayloadTooLarge → 压缩阶梯(真实压缩 + 重试 1 次)
  └─ 其余(不可重试)→ fatal → PROVIDER_ERROR → RunOutcome.provider_error 填充
```

熔断键:`provider_fail_streak` {count, first_fail_at_ms, last_fail_at_ms, window_ms}(窗口默认 0=无窗口);熔断触发发 `runtime-intervention-required` + `recovery-escalated(detail=Some("circuit-trip"))`——事件流呈现 + UI 横幅,不落对话(§9.3);手动路径不受限。

压缩阶梯(E2 增强,§8.2):压缩触发必须携带 LLM Summarizer——无 Summarizer 时预检/用户消息边界/manual 路径**不压缩、等待 LLM 可用**(发 `runtime-intervention-required` + 预算钳制兜底);溢出致命路径**默认直接 fatal**(文案含「LLM 不可用」,显式失败不静默丢语义),可选豁免 `compact_allow_stub_fallback=true`(临时 stub + 后台补摘要自动替换,默认关);溢出压缩重试上限 1→2(可配 `compact_overflow_retries`)且**绕开预检共享计数**(max_auto_compactions_per_run 仅约束预检/用户消息边界/分阶段,溢出自有 compression_retries 防死循环)。

### 3.3 恢复阶梯(子代理)

| 阶梯 | 机制                                                                                   | 触发                                                               |
| ---- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 1    | 收口后重派:原 run failed(reason=recovery-retry)+ 预算内重派新 run(mode=recovery-retry) | 瞬态错误且预算内;不消费 Episode、无 steering                       |
| 2    | 主 agent 激活:steering 条目(recovery-<run_id>)+ recover_notifications 落库             | 阶梯 1 预算耗尽;重启后 restore_steering_notifications 重排         |
| 3    | fork 重分配:SessionTree::fork + 三态上下文继承(Verbatim/Summarized/New)+ Episode 预算  | 主 agent 决策(resume_subagent 命令面);走 spawn 守卫受 16/16/1 约束 |
| 4    | 上报用户:recover_needs_user + 尝试明细                                                 | 全部预算耗尽 / 非瞬态                                              |

装配:每会话 RecoveryCoordinator 五件套(store/queue/tree/spawner/policy);SessionTree 经 from_session_record 重建;全部持久化走 spawn_blocking(F2-27)。

### 3.4 goal 引擎化

- 载体:session_meta `goal_state` {goal, max_rounds, max_stalled_rounds, current_round, stalled_rounds, progress_signature, stopped_reason, schemaVersion, updatedAtMs}(snake_case;唯一写方=收口 RoundAssessment)。
- 判定:RoundAssessment(纯函数)= endReason × 本轮产出 × goal_state → Continue/Completed/NoProgress/Blocked;L0+L1 完成门禁;stalled = 工具批指纹(无工具轮不变);allows_auto_continue 首个生产调用。
- 续轮:四源 goal_pending → spawn_idle_resume_run(mode=goal-continue);注入 = 队列事件优先 + goal 前缀拼接。
- 事件:goal-round-started/completed/continuation-decided(载荷以 D5 §3.9 统一字段集,envelope 通道)。
- 前端:??5 分叉统一 12;decideGoalContinuation 保留过渡,投影化消费事件。

### 3.5 子代理三决策路径(主 agent 侧)

| 决策     | 入口                                   | 机制                                                           |
| -------- | -------------------------------------- | -------------------------------------------------------------- |
| 接管继续 | 主 agent 自由裁量(文档化确认)          | 收到失败通知后不重派、下一轮自行继续;通知承载错误 kind/retries |
| 重派     | resume_subagent 命令                   | kill-for-resume + fork 新 run(三态继承 + Episode 预算 + 幂等)  |
| 关闭重来 | kill_subagent 命令 + 主 agent 工具(新) | 单目标 L3 强停 + mark_row_failed;kill_all 批量语义保持         |

**主 agent 消息工具(E3,§8.3)**:新增 `send_message` 工具,仅主 agent 工具集(子代理剔除面扩展,与 run_subagent/kill_subagent 同面);来源标记 `metadata.source="main-agent"`,**不标记 user_touched**(防「续 run 被自己抑制」);target=subagent 经 ControlBusResolver + request_subagent_inject 走 L1 steer 注入(不打断子代理流,reason=`subagent_inject:<id>`);target=self 写会话消息留档 + 当前 run followUp 环,run 已收口时经 PendingMessageQueue 入队(下一轮 decide_idle_resume 消费);目标不可达 → 结构化 InjectFailed;两通道未接线 → common.unsupported。

**子 agent 运行中汇报(E3,§8.3)**:子代理 run 每轮收口后,本轮新增消息(assistant 文本截断 + 工具调用摘要)经 **subagent-event 通道**(kind=progress/message/tool,SubagentEventEmitter::emit_event)发射——补齐生产零发射现状;运行中汇报**不写 steering 队列**(职责分离:汇报=观测面,唤醒=终态面,防 16 并发唤醒风暴);wait 语义零改变(await-all 只认 subagent-ended);失败信息完整性走终态面(D1 provider_error.kind + D3 阶梯 2 摘要)。

### 3.6 checkpoint 机制面

收口采集(collect_checkpoint_from_messages)→ set_leaf_checkpoint → 拉起器注入(read_leaf_checkpoint 摘要,500 字符截断,损坏降级);Verbatim fork 带 history 注入(RunFailureContext.history + SubagentSpawnRequest.history);水合 error 态放行 + failed-turn 标记。

## 5. 红线(不可谈判)

1. 16/16/1 递归守卫只增不减(同时运行(未终态)子代理 ≤16、同父 ≤16、深度仅 1;12/5/1→16/16/1 扩额依据 = 用户补充需求,max_siblings 必须同步 16 否则 16 并发不可达);恢复路径 fork 显式走 spawn 守卫;嵌套禁令不变。
2. 用户显式停止(Stopped/Aborted/abort_signal/user_touched)永不自动续。
3. 子代理 interrupted 只通知不自动 fork(自动重派违反「所有子 Agent 由主 Agent 分配」)。
4. 测试资产门禁:recovery.rs 24 单测 + 4 集成 37 用例作回归面;markdown-editor 门禁与 5 专项 spec 不受影响;禁止 --no-verify。
5. 探索类文档配额不绕过(fork 沿用同 session_id 自动延续)。
6. 禁止假接线/占位实现后再二次接线;同文件同批(stream_error.rs、core_run_commands.rs、run_restore 单函数)。
7. 事件登记集中一次(41→49),禁止分两批。
8. F2-27 spawn_blocking 覆盖全部同步 SQLite 调用面(含命令面)。

## 7. 闭环迭代机制(多轮适用)

1. 每轮:问题识别 → 任务分解 → Agent 分配(≤12,文件域互斥)→ 并行修复 → 结果汇总 → 验证门禁 → 输出为下一轮输入。
2. 子 Agent 空返回:默认供应商网络问题——先核查落盘,未落盘原样重派(不设上限);6 次以上由主控接管或拆小重派。
3. 每轮完成后 git 提交;文档 UTF-8 无 BOM。
4. 发现任务书未覆盖问题:子 Agent 上报 → 主控裁决 → 裁决归档(追加本文件或 02-定夺)。
5. 最终实现以本文件 + 各维度文档为准;如需偏离,必须显式标注「与正式规范冲突」并提请主控批准。

### 8.1 E1 断网自动接续(内容级续写)

- **三级定义**:① 传输级重连(未产出,同请求重发,§3.2 既有 + D1 硬化);② **内容级续写(本次新增核心)**——部分保留断流(已产出部分文本)收场为 Stop 后,decide_idle_resume Stop 分支新增子分支自动拉起续写 run;③ 会话级续接(D2 error 通道,续写 run 自身 Error 收场即自然落入)。
- **关键事实**:部分保留断流收场是 reason=Stop(非 Error),今日 D2 error 通道不可达——续写 run 填此洞;内核「已产出不重试」三层纪律(streaming.rs:117 / retry.rs:412-428 / recovery.rs:205-217)**零触碰**——续写是新 run,叠加非替代。
- **续写 run 触发(全部满足)**:收场 reason=Stop;最后一条 assistant 消息为纯文本(无 tool_calls)且 metadata.providerErrorKind ∈ 瞬态四类(rate-limit/server-error/timeout/network,D7 流中断标注,与 D1 熔断 S2 计数同一数据源);providerErrorRetryable != false;!user_touched && !abort;熔断未触发;content-resume 预算内;content_resume_enabled=true(默认)。非瞬态 kind / length 截断 / 消息含 tool_calls / 用户显式停止 / 熔断触发 → 不续写保持现状。
- **注入模板(锁定,测试断言绑定)**:「上一轮生成中断(<kind>),请从断点继续完成,不要重复已输出的内容」;已产出文本经 SessionHistoryCache 收口缓存 + resolve_history_source Cache 分支水合,天然成为续写 run 对话中的 assistant 前缀,**不重复注入请求体**(零协议级依赖,chat/responses 双轨全厂商可用)。
- **护栏**:续写次数上限 content_resume_max 默认 2(独立指纹域 `content-resume`,同 recover_episodes 键,与 error-retry 域互斥);熔断闸;abort 竞速;失败尝试不记账;队列卫生(is_steering=true + group_id=recovery-<run_id> 去重);**② 优先于 goal_pending**(具体中断上下文优先)。
- **降级链**:续写 run 自身 Error 收场 → 自然落入 D2 error 通道(③);② 预算耗尽 → 停止自动动作,半截保留交用户;用户手动路径不受限。
- **排期**:E1 先决依赖 D7 流中断标注(providerErrorKind),接线排 D7 之后(§6 轮 3 A12)。

## 9. 设计约束(用户补充:临时通知/前缀不变性/信息分级)

> 2026-08-11 用户补充三条设计约束,约束本规范全部通道与注入设计;与前述条款冲突处以此章为准(用户效果锁,最高优先级)。

### 9.1 临时通知与老虎机滚动重连

- **临时通知语义**:临时通知 = 事件流呈现、**不进 conversation**、可清除的 UI 呈现通道——区别于 steering 注入与会话消息,不构成对话上下文,可被用户清除或自动消失。
- **老虎机滚动重连**:自动重连进度(1/6 → 2/6 → …)单起一行,以「老虎机滚动」样式展示在临时通知区;重连按设定的尝试数值滚动(max_attempts),**不进入对话上下文**。
- **载体**:重连进度经 `provider-diagnostic` 事件(phase=Retry, attempt/max_attempts 已承载,复用 stream_error.rs:213 emit_retry_diagnostic)发射 → 前端临时通知区消费渲染;该通道不写 conversation、不写 steering 队列。
- 失败/重连的诊断细节(错误 kind、退避延迟、剩余预算)一律不进对话,仅在临时通知区呈现(用户可见、AI 不可见)。

### 9.2 前缀不变性与缓存命中

- **硬约束(重试/续写)**:所有设计尽可能保持对话前缀不变以提升 provider 前缀缓存命中——
  - 重试/续写请求**不改变已 commit 消息**(历史水合零改动);
  - **system prompt 字节级稳定**(同会话内构建结果恒定,不因重试/续写漂移);
  - **缓存亲和头保持端点不变**(重试/续写不切换端点,亲和头字节一致)。
- **压缩 = 唯一前缀重写点(可接受的例外)**,但要求:
  - 摘要块稳定序列化(同一输入产生同一摘要块,可复现);
  - 压缩阈值合理,避免频繁压缩(阈值与触发条件受 §8.2 配置钳制);
  - 压缩后**仍保留 system 前缀**(system 段不被压缩改写)。
- 若某项设计必然破坏前缀且无法提升缓存命中,可酌情设计——优先路径:摘要块稳定化 / 避免频繁压缩 / 缓存亲和头保持。

### 9.3 信息分级表(重试信息分级)

| 场景                  | 呈现通道                                     | 给 AI?     | 说明                                     |
| --------------------- | -------------------------------------------- | ---------- | ---------------------------------------- |
| 瞬态重试进度(1/N→N/N) | 临时通知(provider-diagnostic 事件,§9.1)      | 否         | 老虎机滚动,不进对话                      |
| 熔断触发              | runtime-intervention-required 事件 + UI 横幅 | 否         | 事件流呈现 + 横幅,不落对话               |
| error 续 run          | 注入文本最小化「继续任务」                   | 是(最小化) | 不携带重试细节;kind/进度走临时通知(§9.1) |
| 子 agent 失败         | steering 注入(recovery-<run_id>)             | 是         | 含 kind/retries(失败信息完整性走终态面)  |
| goal 续轮             | goal 前缀 + nextSteps 注入                   | 是         | 任务级信息,AI 需要目标上下文             |

**分级原则**:瞬态重试/自动重连的进度与诊断**不给 AI 看到**(走事件流 + 临时通知);只有真正需要 AI 关注的失败(如子 agent 任务失败)才注入对话给 AI;主 run error 续 run 的注入文本最小化(不携带重试细节)。注入文本最小化为固定串「继续任务」→ 请求体前缀与 kind 解耦(不同 kind 不再产生不同前缀),同时服务 §9.2 前缀不变性。
