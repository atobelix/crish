## 4. 实用功能建议清单（对齐用户诉求）

用户四诉求：**断网继续 / 子 agent 恢复 / goal 继续工作 / 自动调度**。以下按「效果完整度 → 正确性 → 可验证性 → 与已锁定契约一致」排序。

### P0-1：C7 恢复阶梯生产接线（断网继续）

- **价值**：直接回答「断网继续」——子 agent run 遇网络波动时由引擎自动重试（阶梯 1）→ 主 agent 软注入（阶梯 2）→ fork 重分配（阶梯 3）→ 用户决策（阶梯 4）。当前生产路径阶梯 1/2 完全不触发，断网即 run 失败，无恢复可言。
- **依据**：04 §2 C7 验收 1-6；recovery.rs 模块头 F2-08 待接声明（自证缺口）；05 §5 操作手册同构。
- **最小实现**：
  1. 在 subagent_spawner 的 provider 流错误处装配 `RecoveryCoordinator::on_subagent_run_failure`（瞬态错误分类 → ladder1_decision → 重试/上行）；
  2. 实现每会话 RecoveryCoordinator 生命周期（RecoveryStore 适配连接 session_meta；SessionTree 装配；SubagentSpawner 复用）；
  3. 阶梯 2 通知经 PendingMessageQueue（已有）落库，重启后 `restore_steering_notifications` 重排（已有函数）；
  4. 按 F2-27 走 spawn_blocking（RecoveryStore 同步 SQLite）。
- **验收锚点**：04 C7 验收断言 1-6（注入 2 次瞬态错误自动恢复、预算耗尽产生 steering 条目、fork 留痕、重启后通知仍在）。

### P0-2：C1 checkpoint 恢复闭环接线（子 agent 恢复）

- **价值**：直接回答「子 agent 恢复」——续跑时优先消费检查点摘要而非回放全量历史，长任务（调研/实现）中断后可低成本继续；与 C7 阶梯 3 fork 组合形成完整恢复链。
- **依据**：04 §2 C1 验收 1-4；05 §1 checkpoint 优先规则（能恢复就不重做）；session.rs 已具备 read/set_leaf_checkpoint（落库面就绪）。
- **最小实现**：
  1. 安全点采集接线：在子 agent run 收口/安全点处调用 `collect_checkpoint_from_messages`（已有纯函数）→ `SessionTree::set_leaf_checkpoint`（已有）；
  2. 恢复注入接线：续跑/重分配路径读取 `read_leaf_checkpoint`（已有）→ 经 ContextInjector 注入「检查点摘要 + 目标剩余」段（M5 注入点已预留，engine.rs 注释可见）；
  3. 损坏降级：parse 失败返回降级标记（已有错误语义）→ 回退最近完整消息 + 通知主 agent。
- **验收锚点**：04 C1 验收 1-4；orchestrator/tests/checkpoint.rs 已有采集侧断言可扩展为注入侧断言。

### P1-1：resume_subagent 命令落地（子 agent 恢复的显式入口）

- **价值**：给用户/主 agent 一个「继续该子代理」的手动兜底（kill 后 resume、失败后 resume）；fork 三态上下文继承（Verbatim/摘要/New）与 Episode 预算逻辑已实现，纯命令面成本低。
- **依据**：03-D T-D-09（未完成项）；recovery.rs fork_and_reassign / ForkContextMode / RecoveryBudget 已可用。
- **最小实现**：新增引擎命令/工具 `resume_subagent(subagent_id, prompt?)` → 调 `fork_and_reassign` + 消费 Episode 预算 + ForkRecord 落库；可选前端 failed 卡片 resume 按钮。
- **验收锚点**：03-D T-D-09 验收（kill 后 resume → fork 新 run、三态判定、预算记账；crash_consistency 扩展）。

### P1-2：子代理预算覆盖（防超窗 fatal）

- **价值**：长任务子代理（无钳制）超窗直接 fatal 是「断网继续/长任务恢复」的底层破坏者；注入 context_window 后至少获得 max_tokens 钳制，配合压缩阶梯才有恢复余地。
- **依据**：DEEPCHECK-06 §1（P0）；修复方向原文：spawner 装配 RunTaskOptions 时按生效模型窗口注入 context_window（与主会话同源）。
- **最小实现**：`subagent_spawner.rs:364-365` 的 `context_window: None` 改为从引擎 provider 模型 catalog 解析注入；顺带装配 compaction_policy（DEEPCHECK-11 P0-1 共享断链）。
- **验收锚点**：子代理 run 预算装配断言（context_budget Some、钳制生效）。

### P1-3：子代理产出回传（摘要空洞修补）

- **价值**：主 agent 目前拿不到子代理最终结论文本（summary 恒占位符/None），恢复与编排都依赖「知道子代理完成了什么」——这是 checkpoint 摘要与恢复注入的内容源。
- **依据**：DEEPCHECK-06 §6（P0）：三处丢失路径（ended summary、DB 行 summary、无查询工具）。
- **最小实现**：收口时把最终 assistant 文本前 N 字符写入 ended 事件 summary / 行 summary（最小方案）；或新增子代理会话查询工具。
- **验收锚点**：DEEPCHECK-06 §6 修复方向断言。

### P1-4：goal 续轮补全（goal 继续工作）

- **价值**：直接回答「goal 继续工作」。当前 Rust 侧只有 GoalComplete 事件与 blocked reason 语义，goal 模式无 rounds 推进；补「stop 后评估续轮 + 注入决策工具」即可支撑长目标任务跨 run 推进。
- **依据**：00-master-plan D1（goal 轮次策略）；10-phase-b B4.5 验收（goal 续轮/无进展 blocked/max-rounds/stalled/429 退避不计轮）；C2 grok goal system 对比（classifier/orchestrator 为成熟参照，但最小件只需 rounds 推进 + 决策注入）。
- **最小实现**：复用 normalize.rs `allows_auto_continue`（已有判定）→ run 收口 stop 且 goal 模式时评估续轮 → 注入 goal 决策工具/摘要 → 续轮计数与 maxRounds/stalled 判定（restore.rs 已有 blocked reason 字面量可承接）；不引入 classifier（C2 建议先做最小件）。
- **验收锚点**：10-phase-b B4.5 语义（05-test-mapping 的 TS 锚点 1337-1842 的 Rust 等价测试）。

### P2-1：C9/C10 生产装配收尾（压缩与重注入）

- **价值**：C10 的 skill/mcp 注入函数（dead_code）与 C9 的 Summarizer 生产实现是「上下文连续」的保障——长会话不因压缩断链丢失任务状态。成本低（函数已写，只差装配）。
- **依据**：engine.rs:1493/1515（`#[allow(dead_code)] // E5 接线`）；DEEPCHECK-11 断链①/②。
- **最小实现**：core_run_commands 装配 ContextInjector 时挂载 skill/mcp 注入段；生产 SummarizerFactory 提供 LLM 摘要实现（复用 agent-provider 通道）。

### P2-2：DAG 可视化（T-D-12，已决策做）

- **价值**：自动调度已就绪但不可见；F11b 已规划（纯 CSS/SVG + 开关默认关），是「自动调度」体验的收尾。
- **依据**：03-D T-D-12；00 总方案 F11b。
- **状态提示**：尚未见执行产物，属待办。
