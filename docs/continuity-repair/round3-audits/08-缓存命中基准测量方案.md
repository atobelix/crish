## 2. 可测量指标

| #   | 指标                     | 定义                                                                                     | 来源                                             |
| --- | ------------------------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------ |
| M1  | 命中率 hit_ratio         | cacheRead / input_total(input_total=0 → None,隐藏非 0%)                                  | cache_breakdown(C9 真源)                         |
| M2  | 缓存写入占比 write_ratio | cacheWrite / input_total                                                                 | 同上                                             |
| M3  | 单请求命中事件           | 每次请求 cached_tokens>0 的布尔 + read/write/miss 数值                                   | ProviderUsage 解析层                             |
| M4  | 重试/续写命中率          | 重试尝试次数 N≥2 时,第 2..N 次请求中 cache_read>0 的比例(分母 = 重试次数,非 run 数)      | MockServer 请求序号 + usage                      |
| M5  | system prompt 漂移检测   | 同一会话跨 run 的 system_prompt 字节指纹(FNV-1a)相等性;不等 → 记录漂移告警(检测不改请求) | 03 审计建议 5;engine.rs:2311-2325 既有指纹可复用 |
| M6  | wire 前缀字节一致性      | 相邻请求体(system+messages 投影)前缀字节相等性,或记录后离线 diff                         | MockServer RecordedRequest.body                  |
| M7  | 压缩后恢复命中           | 压缩 run 后第一次请求 miss(预期,归因 Cold/Compaction)→ 后续请求 read>0 且单调不减        | RunCacheStats + generation                       |
| M8  | 长会话渐进命中           | 连续稳定前缀请求下 cached_tokens 单调不减(服务端缓存池增长语义)                          | 逐请求 usage 序列                                |

口径红线:所有比率计算只走 cache_breakdown 派生(C9),禁止「各算各的」;只测不改——测量绝不改动请求字节(P5 §1.3)。

## 4. 基准测试设计(端到端,mock server 按请求序号注入递增 cached_tokens)

基建:复用 agent-provider tests/common MockServer(handler 闭包按连接计数分叉响应,记录每请求头/体)+ engine 级 ResponsesMockServer 形态。**基准判定不依赖真实厂商**——mock 按「前缀一致 → 返回 cached_tokens 递增」的既定语义响应,验证的是我们的请求面与测量面符合该语义;真实厂商命中由指标面板验证(§5)。

| #   | 场景                   | 脚本序列                                                                                                                  | 断言要点                                                              |
| --- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| B1  | 重试后命中             | 连接 1:SSE 发 2 帧后断流(瞬态)→ 退避 → 连接 2:完整流 + usage{cached_tokens=前次 input_total};两请求体逐字节一致           | M4=100%;M6 字节相等;亲和头 x-grok-conv-id 两请求值相同;hit_ratio 上升 |
| B2  | 续写 run 命中          | run 1:发 2 帧断流(部分保留)→ 收口 → 续写 run:请求体 = 前次前缀 + 尾部新 user(锁定模板);usage cached_tokens = 前缀部分     | M6 前缀相等(仅 TailAppend);M4=100%;注入模板精确等于锁定模板(E1 §3.2)  |
| B3  | 压缩后 miss 一次再命中 | 长对话触发压缩(trigger=预检)→ 压缩后首请求 usage cached_tokens=0(归因 Cold/Compaction,不计浪费)→ 下一请求 cached_tokens>0 | M7 成立;generation+1 后基线重建;system 段仍在前缀内                   |
| B4  | 长会话渐进命中         | N=5 轮稳定前缀(每轮追加 1 条 user 消息)→ mock 逐轮返回 cached_tokens 单调不减                                             | M8 成立;M1 全程 ≥ 上轮                                                |
| B5  | 破坏对照(反例)         | 故意在轮 2 前改 tools 排序 → 该轮 cached_tokens 回落                                                                      | M8 断裂检测有效(证明指标能测出前缀破坏)                               |

测量方法:每场景输出(1)逐请求 usage 序列(2)hit_ratio/write_ratio 曲线(3)wire 字节 diff 报告(4)耗时对比(mock 可选注入首帧延迟,参照 ttfb_measure.rs 计时模式);人工看板项,不做性能断言。
