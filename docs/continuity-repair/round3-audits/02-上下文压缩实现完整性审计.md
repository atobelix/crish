### 2.1 F1 — LLM 摘要强制 ✅（L2 为变体取舍）

**引擎面（conex-compaction）**：

| 设计规则                                       | 证据                                                                                                                             | 结论 |

| 禁止纯丢弃式（中性 stub 禁止面）               | `StubPolicy::{StubAllowed, LlmRequired}`（lib.rs:227-235）；`compact_agent_messages_with_stub_policy` 带决策面（lib.rs:567-744） | ✅   |
| 无 Summarizer + 强制 → 不压缩、不产生 stub     | `llm_blocked_plan`：对话原样、`llm_unavailable=true`、`dropped_ids` 携带应丢 id（lib.rs:289-310）；无注入分支（lib.rs:680-687）  | ✅   |
| 摘要 Err / 非 Schema V1 JSON / 超预算 → 同禁面 | lib.rs:669-678（Err 与非法 JSON 均转 `llm_blocked_plan`）                                                                        | ✅   |
| stub 仅豁免路径可用                            | `compact_agent_messages`（旧签名）= StubAllowed（lib.rs:541-555，向后兼容面）                                                    | ✅   |

**预检路径（L1）**：`maybe_compact_preflight` 无 Summarizer/摘要失败且强制 → 不压缩、不计数、发 `runtime-intervention-required`（reason=「LLM 摘要不可用，压缩等待 LLM 可用」，handlers/mod.rs:375-391）——与 E2 §2.2 L1 一致 ✅。

**溢出致命路径（L3）**：`compression_ladder` 中 `plan.llm_unavailable` → 不落 stub、不重试、直接 fatal（stream_error.rs:339-349）；fatal 文案经 `compression_fatal_note` 输出「；LLM 摘要不可用，溢出未压缩——直接终止（不再重试）」（stream_error.rs:481-487）✅；豁免 = `compact_allow_stub_fallback=true` 或 `compact_require_llm=false` 任一放行 → StubAllowed（stream_error.rs:325-331）✅。

**Critical 废止**：`ThresholdDecision::Critical` 注释明确「语义废止（E2 裁决 1）——不再意味着『不依赖 AI 的同步硬压缩』」（lib.rs:73-91）；`classify` 仅作水位判定、消费方仅 tool_output.rs 与单测（lib.rs:83-90、127-140）✅。

**测试证据**：`overflow_without_summarizer_fatals_with_llm_unavailable_note`（stream_error.rs:1673-1722，断言对话原样/无 stub/无事件/文案含「LLM 不可用」）、`overflow_stub_fallback_exemption_allows_stub`（:1728-1745）、`overflow_require_llm_disabled_allows_stub`（:1751-1764）、`overflow_summarizer_error_fatals_with_llm_unavailable`（:1770-1802）✅。

**🟡 变体取舍（L2）**：E2 §2.2 L2 设计「同步摘要失败 → 压缩动作整体延后为『摘要待就绪』挂起态，后台重试成功后再替换对话」——实现选择了 **放弃压缩**（对话原样 + 事件/fatal），未引入挂起态（预检路径不携带 dropped_ids 发起后台补摘要，handlers/mod.rs:375-391 仅发事件返回）。语义上比 L2 更保守（宁可不压也不半途），未违反「效果锁」禁止面（禁止的是纯丢弃，而非放弃压缩）；但「等待 LLM 可用后自动补压」的自动性弱于设计（仅靠下一次触发重试）。

## 4. 改进建议（对照「社区最佳」目标）

### 4.1 达成「社区最佳」缺的三块拼图（按实现顺序）

1. **F3 用户消息边界先行**（依赖最小，且是 F2 低功耗模式的前置）：
   - prepare_turn 步骤 2 改「dequeue → hold → 边界判定（含 awaiting/retired 块被动触发）→ record_message」；trigger 增 `UserMessage` 变体并集中登记；
   - 边界判定复用 `maybe_compact_preflight` 的引擎调用与 apply_compaction 单点（E2 §4.2 已定义共用面），仅在估算时机（不含 hold 消息）与被动触发点两处差异化；
   - 顺带实现「摘要重试被动触发」：awaiting/retired 块存在 → coordinator.try_trigger 重新摘要（新 run 首请求即携带完整摘要）。

2. **F2 摘要层低功耗模式**（依赖 F3 的被动触发点）：
   - `MAX_SUMMARY_ATTEMPTS`（4）达上限后不再 retired 永驻，转入低功耗：停止主动退避，等待被动触发点（用户消息边界 / 新 run 装配 / 下一次压缩触发）；
   - 接线 `compact_summary_max_attempts`（默认 8，护栏累计成本）与 `compact_summary_retry_window_ms`（默认 30min，窗口内无被动触发则重置计数）两键；注意与 ai_summary.rs 的 RetryGuardSummarizer（重试 3 次/3s）区分口径，避免双真源；
   - retired 语义测试（summary_dispatch.rs:507-531）按新语义修订保留为回归面。

3. **F4 /compact 与 F5 分阶段总结**（依赖面小，可并行）：
   - F4：`core_compact_now` 由「登记先行」转 registered=true（command_manifest.rs:230 + commandManifest.ts:214 + commandMap.ts 白名单 + make_handlers! 注册 + core_run_commands.rs 实现体）；实现体 = Summarizer 解析 → 对话取数（运行态 LoopState / 空闲态 session_history 水合）→ compact_agent_messages（trigger=Manual，budget = target 或 window-reserve）→ apply_compaction 等价动作 + 块表落库 + Start/End 事件 → 返回 {tokens_before, tokens_after, dropped, summary_state}；前端 resolveSlashCommand 增 compact kind + useSlashSend 分支 + SlashExtension 菜单项；旧命令补 deprecated 标注；
   - F5：新增 Stage 触发评估（run 收口或空闲异步，里程碑 40/60/80%，每阶梯对话生命周期一次，estimate/window 双源口径）→ Summarizer 对完整对话产出 Schema V1 阶段总结（tier=stage-N、droppedIds 空、custom range）→ 系统提示词段注入（build_system_prompt 输出后拼接，零对话污染）+ set_leaf_checkpoint 载荷；事件建议并入 ContextCompressionEnd 的 Stage 变体（事件总数最小化，符合 00 规范红线 7 集中登记）。

### 4.2 补齐可配性（D1 §3.5 数据面闭环）

- 壳层装配面（run_task_impl 或 SessionLoopProducer options 构造处，core_run_commands.rs:5271 同区）读取三键 `compact_require_llm` / `compact_overflow_retries` / `compact_allow_stub_fallback`（宽容解析 fail-open 对齐 summary_dispatch.rs:84-89 模式），与 `compaction_policy_for`（core_run_commands.rs:2391）同批；这样 options 默认值（2/true/false）与设计一致 + 用户可配，双满足。
