## 2. F3 用户消息边界（hold → compact → append）

### 2.1 改动点（prepare_turn.rs 步骤 2 改写，:37-39）

```
dequeue → 用户消息入 hold 区（不 record_message）
  → 边界压缩判定（trigger=UserMessage）：
     条件 1：estimate_context（handlers/mod.rs:276）≥ window-reserve
            或存在 awaiting/retired 摘要块（F2 被动触发，不阻塞发送）
     条件 2：Summarizer 可用（不可用 → 发 runtime-intervention-required 事件，消息照常发送）
     条件 3：compactions_this_run < max_auto_compactions_per_run（handlers/mod.rs:346）
     动作：对「不含 hold 消息」的对话 compact_agent_messages（budget = window-reserve）
           → 复用 apply_compaction（handlers/mod.rs:427，唯一前缀重写点 + 计数 + Start/End 事件）
  → record_message（用户消息入对话尾部）
步骤 5 预检（prepare_turn.rs:93）因计数封顶自然跳过；未压缩（LLM 不可用）不消耗计数
```

### 2.2 UserMessage 变体登记

- `ContextCompressionTrigger` 增 `UserMessage` 变体（tool.rs:313-330，插入 Auto 后）；reason 枚举同步扩展（tool.rs:336-341）。
- 事件登记面集中一次：`conex-types/src/events.rs` ContextCompressionStart/End 载荷接受新 trigger + `conex-types/src/device/events.rs:126-127` 事件名表（如无新事件名则仅 payload 变体）；按 00 规范 §5 红线 7 双面登记，registry_drift 门禁必须绿。

### 2.3 用户消息 100% 保留

- 压缩对 hold 消息透明：切割点恒在 hold 之前，用户消息必在发送序列尾部；估算（estimate_context）不含 hold 消息——更保守、更早触发。
- 与预检共存：预检（Threshold）保留「多轮工具回合后无新用户消息超限」场景；同 turn 边界优先。

### 2.4 测试断言

1. hold 消息不进压缩输入：压缩前后对话尾部 = 用户消息原文（逐字节相等）。
2. UserMessage 触发事件 trigger 字段正确；LLM 不可用 → 不压缩、消息照发、事件含「LLM 摘要不可用」。
3. 边界压缩消耗单 run 计数，同 turn 预检跳过；未压缩不计数、预检可再试。
4. awaiting/retired 块存在 → 边界触发 try_trigger 补摘要（coordinator 单飞，summary_coordinator.rs:40 全局 ≤2 不变）。

### 2.5 文件域

- `crates/session-loop/src/loop/handlers/prepare_turn.rs`（步骤 2 改写）、`handlers/mod.rs`（边界判定复用面，或新增 maybe_compact_user_boundary）、`crates/conex-types/src/tool.rs`（变体）、`crates/conex-types/src/events.rs` + `device/events.rs`（登记）、`handlers/mod.rs` 与 `prepare_turn.rs` 测试域。

## 3. F4 slash 命令（/compact → core_compact_now → Manual）

### 3.1 完整链路（实现顺序即派单顺序）

```
① 前端 SlashExtension 菜单项（DEFAULT_SLASH_COMMANDS 或 extraItemsRef 注入）
② resolveSlashCommand 登记 compact kind：kind 联合类型 + SLASH_COMMAND_SPECS 表
   （resolveSlashCommand.ts:19、62-99）、matchArg/withArg（:172-235）、
   slashUsageHint/canonicalSlashFill（:310-340，canonical 补「/compact 」）
③ useSlashSend.handleSendChat 分支（useSlashSend.ts:75-135，grill-me 先例 :135）：
   不写对话、不建会话（isSessionlessSlash 语义），调 daemon
④ 引擎命令 core_compact_now(session_id, target_tokens?) 实现体（core_run_commands.rs）：
   运行中会话 → 返回「空闲执行」标记不打断活动流（复用 useSlashSend follow_up 先例 :390-400）
   Summarizer 解析（summarizer_for）→ 无 → 结构化错误「LLM 摘要不可用，未压缩」
   对话取数：运行态 LoopState.conversation / 空闲态 session_history 水合
   compact_agent_messages（trigger=Manual，budget = target 或 window-reserve）
   → apply_compaction 等价动作（对话替换 + blocks 落库 + Start/End 事件）
   → 返回 {tokens_before, tokens_after, dropped, summary_state}
⑤ 前端 toast/事件投影 → 下次 run 装配经 session_history 携带压缩后序列
```

### 3.2 registered=false→true 时机

- **同一任务卡内**：实现体 + make_handlers! 注册落定后，同轮翻转三处——command_manifest.rs:242 改 true、commandManifest.ts:219 改 true、commandMap.ts:39 白名单补 `core_compact_now`；commandManifest.test.ts:152 断言改 `toBe(true)`；条数断言更新（实测基线 +1：108/103/6，D4 §1.2 A5 口径）。
- 旧 `core_compact_messages`（core_commands.rs:246-262）保留兼容 + 注释标 deprecated。

### 3.3 护栏与测试

- 目标 token 下限 ≥ reserve + keep_recent，非法值 → 前端 toast 用法；manual 不受 `max_auto_compactions_per_run` 限制；noop（无切割点）→ 结构化错误 + 原因。
- 测试：① 空闲态端到端（前端解析 → core_compact_now → 对话替换 + 块表 + Manual 事件 + 返回值）；② 运行中会话拒绝/空闲执行标记；③ 无 Summarizer 错误；④ registered 三处一致 + 条数。

## 4. F5 分阶段总结

### 4.1 里程碑与 Stage 触发

- 新配置键 `compact_stage_ratios`（JSON 数组，默认 [0.4, 0.6, 0.8]，E2 §7.1）；阈值 = estimate/window 比例（estimate_context 双源口径，handlers/mod.rs:276）。
- 触发点：**run 收口**（Stop 收场路径，drive_run_loop 收口附近）评估里程碑；每阶梯对话生命周期内只触发一次（会话级标记，新 run 重新评估）；空闲异步走 coordinator 单飞（全局并发 ≤2 + 墙钟 60s 护栏复用，summary_coordinator.rs:40）。
- 触发即经 Summarizer 对**完整对话**产出阶段总结（「AI 自己总结」），失败走 F2 层 1 重试机制。

### 4.2 LLM 阶段总结（Schema V1）

- 复用 Schema V1 骨架（schemaVersion/blockId/generation/droppedIds/height/tier/goal/constraints/progress/decisions/nextSteps/criticalContext，summary_document.rs:20-33），required 骨架不改（校验兼容 :71-98）；`tier = "stage-N"`；droppedIds 空数组；custom 字段 `range`（覆盖消息 id 区间）。
- 稳定化纪律：同一阶段文本重复注入逐字节一致（E2 §6.5 ①同纪律，防缓存碎片）。

### 4.3 注入与 checkpoint

- **系统提示词段注入（主选）**：新 run 装配 `options.system_prompt` 时在 build_system_prompt 规范化输出后（core_run_commands.rs:5929 装配点）拼接「阶段性总结段」（md 渲染 + tier 标注）——零对话污染、天然跨 run 携带。
- **落 checkpoint**：`collect_checkpoint_from_messages`（safe_point.rs:255，现仅测试调用）扩展采集阶段总结 → `set_leaf_checkpoint`（orchestrator/session.rs:545）落载荷；恢复/续跑经 `read_leaf_checkpoint`（:514）→ 注入系统段。协议段 checkpoint_prompt_section（checkpoint.rs:16）既有，无需新协议。
- 事件：新增 `context-stage-summary-created`（tier/range/goal/nextSteps 载荷）；若事件总数最小化要求，并入 ContextCompressionEnd 的 Stage 变体。双面登记（events.rs + device/events.rs）。

### 4.4 测试断言

1. 40/60/80% 阈值命中即触发，每阶梯仅一次（伪造 estimate 驱动）。
2. 阶段总结 = Schema V1 合法 JSON（tier=stage-N、droppedIds 空）；注入后 system 段含阶段总结且对话零污染。
3. checkpoint 落库 → read_leaf_checkpoint 读回 → 恢复 run 首请求含阶段总结（跨重启集成测试，C10 同款）。
4. compact_stage_ratios 可配（[0.5] 单阶梯等）。

### 4.5 文件域

- `crates/session-loop/src/loop/`（Stage 触发评估 + coordinator 通道）、`handlers/` 或收口路径、`crates/conex-types/src/tool.rs` + `events.rs` + `device/events.rs`（Stage 变体 + 事件登记）、`crates/session-loop/src/safe_point.rs` + `crates/orchestrator/src/session.rs`（checkpoint 接线）、`apps/agent-workbench/src-tauri/src/core_run_commands.rs`（注入拼接）。

## 5. F2 摘要层补全（低功耗模式 + 两新键）

### 5.1 retired → 低功耗

- `MAX_SUMMARY_ATTEMPTS=4`（summary_dispatch.rs:52-53）耗尽后**不再 Retired 永驻**（:317-327）：停止主动退避，转**被动触发**——用户消息边界（F3）/ 新 run 装配 / 下一次压缩触发时经 coordinator.try_trigger 重新摘要（单飞面不变）；主动退避期护栏不变（[1,3,9]s + 墙钟 60s + 全局 ≤2）。
- 既有退休测试按新语义修订保留为回归面（summary_dispatch.rs:507-531 及 :552/:587 非 JSON/超时用例）。

### 5.2 两新键

- `compact_summary_max_attempts`（默认 8，累计成本护栏）：常量仅存在于 ai_summary.rs:466（RetryGuardSummarizer 域），需在 session-loop 调度器消费——统一两域口径（审计 S2 双真源风险）；`from_session_meta` 扩展（summary_dispatch.rs:643-689 测试域）。
- `compact_summary_retry_window_ms`（默认 30min）：窗口内无被动触发则重置尝试计数。
- 注意：与 RetryGuardSummarizer（<500 字符退化重试 3 次/3s）口径区分，不互相覆盖。

### 5.3 测试

1. 第 5 次尝试后不 retired，块保持 awaiting，等待被动触发；触发后摘要成功升级 committed。
2. 累计尝试 > 8 时停止重试；窗口内 0 次被动触发 → 计数重置。
3. 用户消息边界触发被动补摘要（与 F3 集成）。

### 5.4 文件域

- `crates/session-loop/src/loop/summary_dispatch.rs`、`summary_coordinator.rs`、`handlers/mod.rs`（边界被动触发点）、`crates/conex-compaction/ai_summary.rs`（常量统一口径）。
