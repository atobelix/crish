### 3.2 ② 独立 watcher（无人值守最后一跳）

**模块归属**：新模块（建议 `apps/agent-workbench/src-tauri/src/wake_watcher.rs`，不并入 watchdog.rs——职责正交：watchdog 是「无事件时制造事件」，watcher 是「有事件时拉起 run」；同文件会混淆两个判定循环）。模块头注记对齐 watchdog.rs:1-30 风格。

**每会话 spawn（仿 watchdog.rs:307-319）**：

```rust
pub(crate) struct WakeWatcherOptions {
    /// 首轮延迟（防重启恢复条目/定时器补发/通知重排与用户新 run 竞争；
    /// 评审 selection-03:95 建议 5s）
    pub first_tick_delay: Duration,   // = 5s
    /// 周期扫描间隔（默认 2s——覆盖 10ms 定时器 fire 粒度到拉起的延迟）
    pub period: Duration,             // = 2s
    /// 最小拉 run 间隔（防 watcher 抖动反复拉起失败重试风暴；自决 10s）
    pub min_launch_interval: Duration, // = 10s
}

pub(crate) fn spawn(
    runtime: &tokio::runtime::Handle,
    state: Arc<CoreRunState>,
    session_id: String,
    options: WakeWatcherOptions,
) -> tokio::task::JoinHandle<()> {
    runtime.spawn(async move {
        tokio::time::sleep(options.first_tick_delay).await;   // 首轮延迟
        let mut interval = tokio::time::interval(options.period);
        loop {
            interval.tick().await;
            wake_watcher_tick(&state, &session_id, &options).await;
        }
    })
}
```

**tick 判定（纯逻辑，单测可直驱，仿 watchdog.rs:214-226 tick/scan 分离）**：

```
async fn wake_watcher_tick(state, session_id, options):
  1. 队列空（pending_queue.has_pending()，core_run_commands.rs:2522-2528 同款锁内读）→ return
  2. 该会话有活动 run（active_runs 扫描，core_run_commands.rs:3210-3216 同款）
     → return（串行守卫在拉起器处兜底，此处提前短路减少噪音）
  3. 会话级 user_stopped 标记存在（§8 决策 1）→ return（用户显式停止过，
     直到用户发新 run 清除——护栏 2「用户显式停止永不自动续」跨 run 语义）
  4. resume_empty_streak[session] 已超限（> IDLE_RESUME_MAX_EMPTY_ROUNDS，
     core_run_commands.rs:2561-2582 计数由收口维护，watcher 只读判停）
     → return（空转护栏复用）
  5. 距上次拉起 < min_launch_interval（内存 last_launch_at 表）→ return（抖动护栏）
  6. spawn_idle_resume_run(Arc::clone(state), session_id, Vec::new())
     ——注入文本走「空 Vec」：队列条目由新 run 收口时的 decide_idle_resume
     drain（core_run_commands.rs:2585-2592）；或直接经
     drain_pending_to_inject_messages 取条目传入（两方案见 §8 决策 2）
     → 记录 last_launch_at
```

**与 decide_idle_resume 的关系（不替代、防重入）**：
- watcher 是「收口判定」的补充：收口判定覆盖「run 收口时刻队列有货」；watcher 覆盖「收口后新事件入队」的窗口（03-Goal与调度:208-211）。
- 防重入三重保障：① tick 第 2 步「无活动 run」短路；② `run_task_impl` 串行守卫（core_run_commands.rs:3208-3216）拒绝后发者——watcher 与收口判定并发双拉时仅一个成立（验收 A5）；③ 最小拉 run 间隔防失败重试风暴。
- 不续条件对齐：abort/user_touched 的 run 级语义（core_run_commands.rs:2513-2519）跨 run 等价物 = 会话级 user_stopped 标记（§8 决策 1）。
- **与 watchdog 的关系**：并存不重叠。watchdog 判定含「活跃定时器抑制」（watchdog.rs:236-238：AI 设了定时器=有机制在等，不插嘴）；watcher **无**此抑制——定时器到期条目本身就是它的唤醒源（定时器在等事件，到期后该提醒）。watchdog 写队列 → watcher 拉起 run，两者可接力但判定互不依赖。

**spawn 时机（每会话，幂等）**：
- 点 1：`run_restore` 成功路径（core_run_commands.rs:2201-2236）后，对 `outcome.sessions` 的每个会话 spawn（恢复条目/定时器补发需要消费方）；
- 点 2：`run_task_impl` 装配处（core_run_commands.rs:3169 起）对会话首次出现惰性 spawn（新会话）；
- 持有：CoreRunState 新增 `wake_watchers: Mutex<HashMap<String, JoinHandle<()>>>`（会话 → 任务句柄，幂等去重）；进程退出随 runtime 销毁，无需显式关停（测试面可经句柄 abort）。
- 生命周期语义：会话级存活（与 watchdog 每会话任务同语义，watchdog.rs:307-319 注记），run 收口不销毁——否则 AI 休眠后 watcher 也跟着没了，回到断点 2。

### 3.3 ③ run_restore 恢复条目生成

**接线点**：`run_restore` 成功路径（core_run_commands.rs:2201-2236）末尾、`save_snapshot_now`（:2213）之后、返回前（对齐 D3 的 `restore_steering_notifications` 同批位置，03-恢复阶梯:97 阶段 A-3）。

**伪代码**：

```rust
/// 重启恢复条目生成（断点 3 消费端；00-总纲-维度设计.md:80 D6-③）
fn enqueue_restore_entries(state: &CoreRunState, outcome: &RestoreOutcome) {
    let mut queue = state.pending_queue.lock()...;
    for record in &outcome.interrupted {          // restore.rs:74-89 InterruptedRun
        let now = now_ms();
        let is_subagent = record.session_id.starts_with(SUBAGENT_SESSION_PREFIX); // "sub-sess-"，subagent_spawner.rs:289
        let (target_session, text) = if is_subagent {
            // 子代理 interrupted：只通知主 agent，不自动 fork（裁决 #20）
            match parent_session_of(&state, &record.session_id) {   // session_agents 行 parent_session_id，subagent_spawner.rs:676
                Some(parent) => (parent, format!(
                    "子代理 run {} 在重启时被中断（{INTERRUPTED_ERROR}），请决策：重派 / 接管 / 放弃",
                    record.run_id)),
                None => continue,   // 父归属查不到 → 仅日志 + run-interrupted 事件已留痕（restore.rs:626）
            }
        } else {
            (record.session_id.clone(), format!(
                "上次运行（run {}）在重启时被中断，请继续未完成的工作", record.run_id))
        };
        queue.replace_or_enqueue(SteeringInputEntry {
            id: format!("restore-{}-{now}", record.run_id),   // 带时间戳保唯一（对齐 watchdog.rs:295）
            text,
            attachments: Vec::new(),
            enqueued_at: now,
            group_id: Some(format!("restore-{}", record.run_id)), // 键形状：restore-<run_id>
            is_steering: true,                                    // 容量挤占受保护
        });
    }
}
```

**要点**：
- **主 run 自动续跑**：主会话队列条目 → 主会话 watcher（首轮延迟 5s 给用户留窗口）或下次收口消费 → `drain_pending_to_inject_messages` 注入 → history 经 SessionHistoryCache 续接（core_run_commands.rs:2714-2718 收口已缓存，spawn_idle_resume_run 装配 history:None 回退缓存 :2637-2671）。
- **子代理只通知**：通知条目注入**父会话**队列（父归属经 session_agents 行解析，subagent_spawner.rs:296 row_for 落库 parent_session_id）；主 agent 收到后自由决策（接管/重派/kill+重来，裁决 #16 机制确认）。**禁止**对 sub-sess-* 会话生成「续跑」条目——子代理会话无 watcher 拉起语义（子代理 run 收口即终态，core_run_commands.rs:2867-2871），且自动 fork 违反「所有子 Agent 由主 Agent 分配」红线（01-敲定方案.md:91 红线 3）。
- **消费语义**：条目由 watcher / 下次收口消费（03-Goal与调度:217 断点 3）；队列条目经 group_id `restore-<run_id>` 去重（replace_or_enqueue 语义 steering_queue.rs:147-156）——同 run 不重复堆积。
- **注入文本**：「上次被重启打断，请继续」主源（任务书原文）；子代理通知含 INTERRUPTED_ERROR 文案（restore.rs:51）。
- **与 D2 预算的关系**：恢复条目**不消费** recover_episodes 预算——restore 源不消费 recover_episodes 预算（02-定夺 W8：唤醒源枚举为前瞻设计，预算仅 error-retry 域消费）；恢复条目是「队列事件驱动」而非「error 自动续」，D2 预算只管 error 分支，指纹含唤醒源类型 restore（01-敲定方案.md:22 裁决 #8）；风暴防制靠护栏 8（合并上限 + watcher 延迟）而非预算。

**文件域**：core_run_commands.rs（run_restore + helper）。

### 3.4 ④ 合并注入上限（≤16 条）

**落点**：`drain_pending_to_inject_messages`（core_run_commands.rs:2603-2626）。

```rust
/// 合并注入上限（评审 selection-03:220 建议 ≤16 条；超出保留最新并注明省略）
const RESTORE_MERGE_INJECT_LIMIT: usize = 16;

fn drain_pending_to_inject_messages(queue: &mut PendingMessageQueue, _session_id: &str) -> Vec<AgentMessage> {
    let entries = queue.dequeue_all();
    if entries.is_empty() { return Vec::new(); }
    // 保留最新 ≤16 条（省略最旧——旧条目信息过时风险高；FIFO 尾部即最新）
    let (kept, omitted) = if entries.len() > RESTORE_MERGE_INJECT_LIMIT {
        let split = entries.len() - RESTORE_MERGE_INJECT_LIMIT;
        (entries.split_off(split), entries.len())
    } else {
        (entries, 0)
    };
    let mut text = kept.iter().map(|e| e.text.as_str()).collect::<Vec<_>>().join("\n");
    if omitted > 0 {
        text = format!("{text}\n（其余 {omitted} 条唤醒通知省略，详情见事件流）");
    }
    // ... 其余照旧（id 沿用首条条目 id 保证幂等，core_run_commands.rs:2616-2625）
}
```

要点：
- 省略条目的轨迹：恢复域条目有 recover_notifications 落库冗余（recovery.rs:89），定时器/子代理终态条目有事件表（TimerFired / subagent-ended Critical 落库）——**队列只承载提醒，不承载全量**（selection-03:220 理由）；事件流查询面 core_read_session_events 既有（05-契约观测 D3）。
- 上限常量建议命名 `RESTORE_MERGE_INJECT_LIMIT`（不限于恢复条目——drain 是全部队列源的公共合并面，一次定界覆盖全部源）。

### 3.5 ⑤ 空注入轮不计空转 streak

**落点**：`decide_idle_resume` 空转计数分支（core_run_commands.rs:2561-2582）。

现状：`had_ai_output ? 清零 : +1`——仅定时器/Cron 源触发（无队列条目）的续 run 若 AI 无产出，会被计入空转，3 轮后停（07-后台任务 G5:149 的误伤）。

```rust
// 计数前先判定「空注入轮」——按唤醒源区分（02-定夺 W2）：
// empty_inject = (唤醒源 ∈ {timer, cron}) && 无队列条目 && 注入文本为空
let empty_inject = matches!(wake_source, WakeSource::Timer | WakeSource::Cron)
    && !queue_pending           // queue_pending 已在 :2522-2528 判定
    && inject_text.is_empty();
...
if had_ai_output {
    *entry = 0;
} else if empty_inject {
    // 定时器/Cron 空注入轮不计 streak（裁决 #21：待命是正常态）；不增不减，保持原值
} else if is_goal_round {   // goal 续轮（D5 四源）走独立计数路径
    // goal 无产出计入空转（*entry += 1 同普通轮），且按 stalled 独立计数
    //（stalled 独立计数在 D5 的 goal_state，本域只保证不误伤）
    *entry += 1;
    if *entry > IDLE_RESUME_MAX_EMPTY_ROUNDS { ...停止... }
} else if is_error_resume { // error 续 run（D2 error 分支）走独立计数路径
    // error 续 run 不计 streak（预算在 D2 的 recover_episodes 域独立计数）
} else {
    *entry += 1;
    if *entry > IDLE_RESUME_MAX_EMPTY_ROUNDS { ...停止... }
}
```

- 语义边界（02-定夺 W2 / 裁决 #21 分场景）：**定时器/Cron 空注入轮不计**（本维度）；**goal 续轮无 AI 产出计入空转且按 stalled 独立计数**（D5 域——goal 轮经四源命中，走 `is_goal_round` 独立计数路径；stalled 独立计数在 D5 的 goal_state）；**error 续 run 不计 streak**（D2 域——error 续 run 由 D2 error 分支拉起，预算在 recover_episodes 域独立计数）。
- 判定依据 = 「本轮是否有真实任务输入」（01 决策 7 语义，selection-01 附带裁决:82）：空注入轮判定为**唤醒源 ∈ {timer, cron} && 无队列条目 && 注入文本为空**（三者同时成立才不计）；goal 续轮（D5 四源）与 error 续 run（D2 error 分支）不受空注入判定影响，走各自独立计数路径。
- 副作用注意：`empty_inject` 轮仍**清零**与否——设计为「不增不减」（保持原值）：长等待定时器场景每轮无产出不消耗计数，也不虚假清零（有产出轮自会清零）。
