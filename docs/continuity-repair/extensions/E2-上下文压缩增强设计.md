## 0. 结论速览

1. **LLM 摘要强制（F1）**：现状引擎在 Summarizer 缺失/失败时降级「中性 stub」（lib.rs:550-573）＝**纯丢弃式**（语义保留度 = 0，DEEPCHECK-11 §4）——这正是用户要求的「线性压缩」禁止面。设计：压缩触发必须携带 Summarizer；无 Summarizer **不压缩、等待 LLM 可用**（预检/用户边界/manual 三路径），并配套「等待期护栏」；溢出致命路径保留「瞬态 stub + 后台补摘要自动替换」为**唯一显式豁免**（须主控裁决）。与 04 C9「失败降级占位符」及双阈值 Critical「不依赖 AI」（lib.rs:76-83）**直接冲突**，标注见 §9。
2. **失败自动重试（F2）**：「压缩不成功就自动尝试」拆两层精确语义——**摘要层**（块表 state ≠ committed → 后台退避重试，现状 4 次退休，新：护栏约束的持续重试 + 用户消息边界被动重试，不设退休绝对上限）与**压缩层**（压缩后仍超限 → 重试压缩，现状上限 1，新：上限 1→2 且溢出阶梯绕开预检共享计数，DEEPCHECK-11 §7 建议）。重试**不换 Summarizer 实现**（per-session 实例，engine.rs:789-802），配置 reload 后新 run 自然换新实例。
3. **用户消息边界触发（F3）**：prepare_turn 现在先 record_message 再压缩（prepare_turn.rs:37-39/93），用户消息已入对话。设计改为「**hold → compact → append**」：用户消息先入 hold 区，对不含用户消息的对话压缩，压缩后对话 + 用户消息一起发送——「发送的消息算压缩后发送」＝压缩发生在用户消息入队之前，用户消息 100% 保留；同时作为摘要重试的被动触发点（awaiting/retired 块补摘要）。
4. **slash 命令（F4）**：新增 `/compact`（别名 `/压缩`/`/compress`，可选目标 token 数），链路 = 前端 resolveSlashCommand 登记 → useSlashSend 分支 → 新 daemon 命令 `core_compact_now` → CompactionEngine + Summarizer → 对话替换 + 块表 + 事件（trigger=Manual，tool.rs:319 变体已存在）→ 前端反馈。运行中会话走「空闲执行」语义，不打断活动流；手动路径不受单 run 计数限制（对齐「手动路径不受限」红线）。
5. **分阶段总结（F5）**：对话长度达里程碑阈值（默认 40%/60%/80%，可配）时由 LLM 对**完整对话**产出结构化阶段总结（Schema V1 骨架，tier 标记阶段，summary_document.rs:20-33）；新 run/新会话装配时注入**系统提示词段**（core_run_commands.rs:3550 build_system_prompt 输出后拼接）；阶段总结同时落为 checkpoint 载荷（session.rs:514/545 接线）；与终结摘要（goal/nextSteps）形成素材继承链，贯通 05 文档 P1「nextSteps 续轮注入」。
6. **数据面**：新增 5 配置键（compact_* 命名空间延续）+ ContextCompressionTrigger 增 UserMessage/Stage 变体（登记面按 00 规范 §5 红线 7 集中登记）+ 新命令 core_compact_now（command_manifest 107/102/5 基线变化，按 P1-1 裁决更新）；对 D1（溢出重试参数化）、D7（fatal 附注文案）、D8（事件登记 + UI 投影）的修改点见 §7。

## 2. F1 — LLM 摘要强制（禁止纯丢弃式）

### 2.1 「线性压缩」的定义与禁止面

**定义**：压缩动作产出「非 LLM 来源的摘要消息」即线性压缩——本仓库具体形态 = 中性 stub 占位符（lib.rs:862-869）：丢弃消息正文、仅留 `[Compacted(block-id) N 条消息 · 摘要见块表]` 句柄、`summary_is_llm=false`、state=awaiting。因摘要块表是机器/前端概念、模型无法读取，**信息保留度 = 0**（DEEPCHECK-11 §4 评估），语义等价「线性裁剪 + 占位」。任何**未经 Summarizer 成功产出合法 Schema V1 JSON 的压缩动作**均落入禁止面。

### 2.2 强制规则（设计）

| 规则 | 语义 | 落点 |
|---|---|---|
| **L1（默认）** | 压缩触发时 `state.summarizer` 为 None → **不执行压缩、等待 LLM 可用**（不产生 stub）；触发点发 `runtime-intervention-required`（复用 steering_evaluation.rs:68-75 模式）提示配置缺失 | maybe_compact_preflight（handlers/mod.rs:296 起）；compression_ladder（stream_error.rs:155 起）；F3 边界触发；F4 命令面 |
| **L2** | 同步摘要失败（Err / 非 JSON / 超预算）→ **不落 stub 先行**：压缩动作整体延后为「摘要待就绪」（挂起态），后台重试成功后再替换对话；「压缩不成功不生效」而非「先丢后补」 | compact_agent_messages 摘要分支（lib.rs:550-573）改为返回挂起计划；summary_dispatch/coordinator 承接 |
| **L3（豁免，须主控裁决）** | 溢出致命路径（ContextLengthExceeded/PayloadTooLarge 用尽全部阶梯）在 Summarizer 缺失时：**A）不压缩直接 fatal 上报**（默认，语义最严格）；或 **B）临时 stub + 后台补摘要成功自动替换**（保 API 调用不失败，stub 仅为瞬态）。**本设计推荐 B 仅作显式可配豁免**（`compact_allow_stub_fallback=true`），默认 A | compression_ladder（stream_error.rs:142-205）；fatal 附注（stream_error.rs:274-291） |
| **L4** | 双阈值 Critical（95%）「同步硬压缩不依赖 AI」语义**废止**（lib.rs:80-82 注释随实现修订）：临界线同样走 LLM 摘要；窗口内无法摘要时按 L3 裁决处理，宁可 fatal 不纯丢弃（与「效果锁」红线一致） | CompactionThresholds 注释 + classify 消费方（tool_output.rs:320 不受影响） |

### 2.3 与现有降级路径的冲突处理

| 既有路径 | 现状 | 冲突处理 |
|---|---|---|
| 04 C9「失败降级占位符」 | 06 文档 §2.1 C9 行（设计源） | **与正式规范冲突**：C9 降级语义被用户新要求否决；文档修订标注「C9 降级条款由 E2 取代」 |

## 3. F2 — 压缩失败自动重试

### 3.1 「压缩不成功就自动尝试」的精确语义（两层分解）

**层 1：摘要生成不成功（摘要层）**——判定 = 块表 `state != committed`（recovery.rs:11-13；summary_dispatch.rs:272-330）。

| 现状 | 设计 |
|---|---|
| 后台退避 [1,3,9]s、attempts ≤4（含同步 1 次）、墙钟 60s/次、耗尽 → **retired 永驻**（summary_dispatch.rs:47-58、272-330；tests:507-527 钉死退休语义） | ① **废除「退休绝对上限」**：attempts 达旧上限后不退休，转入「低功耗模式」——停止主动退避，改为**被动触发重试**：用户消息边界（F3）/ 新 run 装配 / 下一次压缩触发时重新触发摘要（复用 coordinator.try_trigger 单飞面，summary_coordinator.rs:119-175）；② 主动退避期护栏不变（单飞 + 全局 ≤2 + 墙钟 60s）；③ 新增累计尝试上限 `compact_summary_max_attempts`（默认 8，防无界成本）+ 观察窗口 `compact_summary_retry_window_ms`（默认 30min，窗口内 0 次被动触发则重置计数） |
| 失败不记账（D1 §6.2 纪律） | 保持：摘要调用失败不进主对话 usage；但摘要尝试计入块 `attempts`（已有字段，recovery.rs:73）+ 发 provider-diagnostic（phase=summary 扩展）留痕 |
| 摘要成功 | 块表 summary_json 落库（blocks.rs:66-87）+ 对话链消息替换为 committed 渲染（summary_dispatch.rs 回调面已具，:24-26） |

**层 2：压缩后仍超限（压缩层）**——判定 = `plan.tokens_after > budget_tokens` 或 provider 仍报 ContextLengthExceeded/PayloadTooLarge。

| 现状 | 设计 |
|---|---|
| 溢出重试上限 `MAX_OVERFLOW_COMPRESSION_RETRIES = 1`（stream_error.rs:38、151-153） | 上限提为 2（常量 + 可配 `compact_overflow_retries`，DEEPCHECK-11 §7 建议②）；第二次重试前重新估算并**优先尝试更小保留预算**（keep_recent_tokens 阶梯下调：20K→12K→8K，DEEPCHECK-11 §8 建议的机制化） |
| 预检与溢出共用单 run 计数（stream_error.rs:162-164；loop/mod.rs:304）→ 预检可能饿死溢出恢复（DEEPCHECK-11 §7 冲突 1） | **溢出阶梯绕开预检共享计数**（溢出自有 compression_retries 已防死循环，DEEPCHECK-11 §7 建议①）；max_auto_compactions_per_run 仅约束预检/边界/分阶段。**与正式规范冲突标注**：既有测试 `overflow_compaction_respects_run_limit`（stream_error.rs:678-686 域）断言需按新语义修订 |
| 无合法切割点 noop → 不重试直接 fatal（stream_error.rs:174-177） | 保持（请求体未变重试必败语义，T06.2.2 裁决）；但 noop 本身计入「待重试」标记（F3 联动：用户消息边界重试 noop——对话增长后切割点可能重新合法） |
| 重试是否换 Summarizer 实现 | **不换**：Summarizer 按会话解析、per-session 实例（engine.rs:789-802），重试 = 同一实例重试；provider 配置 reload 后新 run 经工厂重新解析获得新实例（core_run_commands.rs:1631-1632 注释），「换实现」仅此自然路径生效 |

### 3.2 与熔断的关系

摘要重试为独立 LLM 调用（C14 隔离，engine.rs:814-825），**不写主对话 `provider_fail_streak` 熔断键**（D1 §3.2.1，core_run_commands.rs 收口计数不受影响）；摘要连续失败由块 attempts + 诊断事件观测，不触发主会话熔断。摘要失败与压缩 fatal 之间无联动（压缩 fatal 走既有 provider_error 数据面，D1 §3.4）。

## 4. F3 — 用户消息边界触发

### 4.1 现状与目标形态

现状：prepare_turn 步骤 2 先 dequeue → record_message（用户消息入对话，prepare_turn.rs:37-39），步骤 5 才预检压缩（prepare_turn.rs:93）——压缩发生在用户消息入队**之后**，估算含用户消息。

需求：「用户发送消息后重试压缩，发送的消息算压缩后发送」——压缩作为**用户消息边界动作**：先压缩、再把用户消息附上发送，保证（a）用户消息 100% 保留、绝不进丢弃段；（b）压缩估算不含用户消息（更保守、更早触发）；（c）若此前压缩失败（awaiting/retired/noop），边界时自动重试（F2 被动触发）。

### 4.2 设计（hold → compact → append）

```
prepare_turn 步骤 2（prepare_turn.rs:37-39 改写）
├─ dequeue 用户消息 → 先入 hold 区（不 record_message）
├─ 边界压缩判定（trigger=UserMessage，枚举扩展见 §7.2）：
│    ├─ 条件 1：上下文估算（estimate_context，handlers/mod.rs:235-243）≥ 阈值
│    │         或存在 awaiting/retired 摘要块（补摘要，不阻塞发送）
│    ├─ 条件 2：Summarizer 可用（F1 L1；不可用 → 发事件 + 跳过压缩，消息照常发送）
│    ├─ 条件 3：单 run 计数未达上限（max_auto_compactions_per_run）
│    └─ 动作：对「不含用户消息」的当前对话 compact_agent_messages（budget_tokens =
│         window - reserve）→ 摘要同步一次 + 失败后台重试（F2 层 1）
├─ record_message（用户消息入对话——压缩后序列尾部）
└─ 步骤 3-6 不变（turn-start / steering / 预检步骤 5 因计数封顶自然跳过）
```

「发送的消息算压缩后发送」实现形态 = **压缩发生在用户消息入队（record_message）之前**；压缩算法对 hold 消息透明，切割点恒在 hold 消息之前，用户消息必然处于发送序列尾部。与预检触发的区别：预检（Threshold）保留服务「无新用户消息但上下文超限」场景（多轮工具回合后）；边界触发（UserMessage）服务「用户显式干预」场景。两者共用 `apply_compaction`（handlers/mod.rs:350-401，唯一前缀重写点 + 计数 + 事件），trigger 字段区分。

### 4.3 优先级与既有触发关系

| 关系 | 语义 |
|---|---|
| 边界 vs 预检 | 同 turn 内边界触发优先（步骤 2 先于步骤 5）；边界消耗单 run 计数后预检自然跳过；「边界触发未压缩（LLM 不可用）」不消耗计数，预检可再试 |
| 边界 vs 溢出 | 边界压缩后仍超窗 → 请求照发 → provider 超限 → length 阶梯 → 溢出压缩（独立计数，F2 层 2）——三重防御链完整 |
| 边界 vs 摘要重试 | 边界是 F2 层 1「低功耗模式」的被动触发点：awaiting/retired 块 → try_trigger 重新摘要，摘要成功块升级 committed，**新 run 首次请求即携带完整摘要** |

## 6. F5 — 分阶段总结（阶段性摘要 → 新上下文携带）

### 6.1 语义定义

「分阶段总结」= 对话长度达到**里程碑阈值**时，由 LLM（Summarizer 通道，即「AI 自己总结」）对**当前完整对话**（非丢弃段）产出结构化进度总结（progress summary）；新 run/新会话建立（新上下文）后把总结传给 AI。与压缩摘要（丢弃段摘要）的差异：压缩摘要 = 有损折叠的历史压缩；阶段总结 = 无损视角的进度快照，二者并存、互为素材。

## 8. 验收断言

### F1（LLM 摘要强制）

- A1：Summarizer 未注入（`summarizer_for` 返回 None）时，预检（maybe_compact_preflight）与溢出阶梯（compression_ladder）**均不执行压缩**（对话零变化、无 stub 消息、无 ContextCompressionStart 事件），并发 runtime-intervention-required。
- A2：注入 FailingSummarizer（恒 Err）且 `compact_require_llm=true` 时，压缩不落 stub——对话保持原样，后台重试记录尝试次数；无任何 `summary_is_llm=false` 的摘要消息入对话。
- A3：`compact_allow_stub_fallback=true` 且 Summarizer 恒失败时，仅溢出路径（trigger=Overflow）允许临时 stub，且摘要成功后块升级 committed 并替换链文本（stub 非永驻）。

### F2（失败自动重试）

- B1：摘要层：FailingSummarizer 注入下，attempts 累计达旧上限 4 后**不 retired 永驻**——用户消息边界触发（F3）后 try_trigger 重新摘要，块状态从 awaiting → committed（用成功型 RecordingSummarizer 断言补摘要路径）。
- B2：压缩层：溢出阶梯在压缩后仍超限时自动重试第 2 次（keep_recent_tokens 阶梯下调 20K→12K），两次压缩后 token 单调下降；`compact_overflow_retries=1` 时行为回退现状。
- B3：预检消耗单 run 计数后，溢出阶梯仍可压缩（计数解耦）；既有 `overflow_compaction_respects_run_limit` 测试按新语义修订后全绿。

### F3（用户消息边界触发）

- C1：上下文超阈值时发送用户消息 → 压缩事件 trigger=UserMessage 且发生在用户消息 record 之前——压缩后对话尾部恒为用户消息（用户消息 id 在 kept_ids 中、绝不在 dropped_ids）。
- C2：估算口径：边界压缩的 tokens_before 不含用户消息（较「先入对话再压缩」的旧序估算更小）。
- C3：存在 awaiting 块时发送用户消息 → 摘要重试任务被重新触发（attempts 递增），不阻塞消息发送。

### F4（slash 端到端）

- D1：`/compact` 空闲态端到端：前端解析 → core_compact_now → 对话替换 + 块表落库 + ContextCompressionStart/End（trigger=Manual）→ 前端收到 {tokens_before, tokens_after, dropped}；下次 run 装配的 initial_conversation 含压缩后序列。
- D2：`/compact 60000` 目标 token 生效（budget_tokens=60000）；非法参数（非数字/低于下限）返回 InvalidInput；运行中调用返回「空闲执行」标记且不打断活动流。
- D3：Summarizer 不可用时 `/compact` 返回结构化错误「LLM 摘要不可用，未压缩」，不产生 stub、不替换对话。

### F5（分阶段总结）

- E1：对话跨过 40% 里程碑（estimate/window）→ 后台产出 tier="stage-1" 的 Schema V1 阶段总结落块表；同阶梯不重复触发（里程碑幂等）。
- E2：新 run 装配的 system_prompt 包含阶段总结段（含 goal/nextSteps 字段）；压缩终结摘要以阶段总结为 existing 迭代合并（摘要文本含阶段总结关键内容）。
- E3：阶段总结落 leaf checkpoint；重启恢复/续跑注入路径（read_leaf_checkpoint）在无阶段总结时降级现状行为（无 checkpoint 段）。
