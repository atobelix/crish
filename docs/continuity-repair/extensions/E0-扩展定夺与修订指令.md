## 二、E2 冲突裁决(用户要求优先,效果锁)

### 裁决 1:LLM 摘要强制(用户要求①「不要线性或不经过 llm 处理后的压缩」)

- **裁决**:废止「降级中性 stub(纯丢弃式)」与「双阈值 Critical(95%)同步硬压缩不依赖 AI」(lib.rs:550-573、lib.rs:76-83)两处既有语义;压缩触发必须携带 LLM Summarizer。
- 行为:Summarizer 缺失时——预检/用户消息边界/manual 路径**不压缩、等待 LLM 可用**(发事件 + 预算钳制兜底);溢出致命路径(ContextLengthExceeded/PayloadTooLarge 用尽全部阶梯)**默认直接 fatal**(显式失败不静默丢语义,fatal 文案含「LLM 不可用」),可选豁免 `compact_allow_stub_fallback=true`(临时 stub + 后台补摘要自动替换,默认关)。
- 文档标注:04 C9「失败降级占位符」条款标注「由 E2 取代」;`compact_l1_placeholder` 键语义反转预留(V2 改为允许 stub 降级显式开关)。

### 裁决 2:压缩失败自动重试(用户要求②)

- **裁决**:溢出压缩重试上限 1→2(可配 `compact_overflow_retries`),且溢出阶梯**绕开预检共享计数**(max_auto_compactions_per_run 仅约束预检/边界/分阶段;溢出自用 compression_retries 防死循环)。
- 摘要层:块表 state≠committed → 重试,护栏约束持续重试 + 用户消息边界被动触发。
- 既有测试修订:`overflow_compaction_respects_run_limit`(stream_error.rs:678-686 域)按新语义修订(溢出不受预检计数约束)。

### 裁决 3:用户消息边界触发(用户要求③)

- 采纳 E2 F3:prepare_turn 改「hold→compact→append」——压缩发生在用户消息入队前,用户消息 100% 保留(kept_ids,绝不在 dropped_ids),压缩后对话尾部恒为用户消息;trigger 新增 `UserMessage` 变体。

### 裁决 4:slash 命令(用户要求④)

- 采纳 E2 F4:`/compact`(别名 `/压缩`/`/compress`,可选目标 token)→ resolveSlashCommand 登记 → useSlashSend 分支 → 新引擎命令 `core_compact_now` → Manual 触发 → 事件反馈;命令条数 107→108/102→103/5→6。

### 裁决 5:分阶段总结(用户要求⑤)

- 采纳 E2 F5:里程碑阈值默认 [0.4, 0.6, 0.8](estimate/window 比例,可配 `compact_stage_ratios`),每阶梯对话生命周期内只触发一次;LLM 对当前完整对话产出结构化阶段总结(Schema V1 骨架 + tier 标记),注入系统提示词段;阶段总结同时落 checkpoint 载荷;与终结摘要(goal/nextSteps)形成素材继承链(贯通 05 文档 P1 续轮注入)。

## 三、E1 裁决要点(断网自动接续)

- 三级定义:① 传输级重连(未产出,同请求重发,已覆盖+D1 硬化);② **内容级续写(本次新增核心)**——部分保留断流(metadata.providerErrorKind ∈ 瞬态四类)收场为 Stop 后,decide_idle_resume Stop 分支新增子分支:预算内(独立指纹域 `content-resume`)自动拉起续写 run,注入锁定模板「从断点继续,不要重复已输出内容」,history 经 SessionHistoryCache 天然含已产出前缀;③ 会话级续接(D2 error 通道,续写 run 自身 Error 收场即入)。
- 关键事实:部分保留断流收场是 reason=Stop(非 Error),今日 D2 error 通道不可达——续写 run 填的是这个洞。
- 内核零改动:「已产出不重试」三层纪律(streaming.rs:117/retry.rs:412-428/recovery.rs:205-217)叠加非替代;续写 run 是新 run,不违反。
- 护栏:续写次数上限默认 2、熔断闸、abort 竞速、失败自然降级;与 D1 熔断 S2 计数同数据源(D7 标注)。
- 排期:E1 依赖 D7(流中断标注)之后接线。

## 四、E3 裁决要点

- **上限 16/16/1**:max_concurrent 12→16、max_siblings 5→16(必须同步)、max_depth 1 不变;改动面 = subagent.rs:497-501 常量 + shared-types/subagent.ts:57-65 镜像 + 既有上限测试 7 处数字修正 + 文档引用;flow_graph 预算自动跟随;注意 00:84「合并注入 ≤16 条」为恢复条目数,与上限 16 语义不同需加注防混淆。
- **send_message 工具**:仅主 agent 工具集(子代理剔除面扩展);target=subagent 复用 L1 steer 注入、target=self 走 followUp 环 + 会话留档;来源标记 `metadata.source="main-agent"`,**不标记 user_touched**(防「续 run 被自己抑制」)。
- **汇报接线**:subagent-event 通道(progress/message/tool)现成但 emit_event 生产零发射;接线 = 子代理 run 每轮收口后增量消息经 emit_event 发射;运行中汇报**不写 steering 队列**(职责分离:汇报=观测面,唤醒=终态面,防 16 并发唤醒风暴);失败信息完整性走终态面(D1 provider_error + D3 阶梯 2 摘要)。
- **闭环**:失败上报 → 阶梯 1 自动重派 → 阶梯 2 主 agent 激活 → 三决策路径(接管/resume_subagent/kill_subagent+重派)→ 重派走 16/16/1 守卫。

## 六、验收基线追加(扩展能力)

1. 断流(已产出部分)→ 自动续写 run 且无重复输出;续写失败 → 降级 error 续 run。
2. 16 个并行子代理可同时运行(16/16/1);第 17 个拒绝(ConcurrentExceeded{max:16})。
3. 主 agent 可经 send_message 向子代理/自身注入;注入不抑制自身续 run。
4. 子代理运行中汇报经 subagent-event 可见;失败上报含 kind/retries。
5. 压缩必经 LLM:无 Summarizer 时预检/边界/manual 不压缩等待、溢出默认 fatal;摘要失败自动重试。
6. 用户消息边界:超阈值时用户消息先压缩后发送,用户消息 100% 保留。
7. `/compact` slash 命令端到端可用。
8. 分阶段总结:40%/60%/80% 里程碑触发一次;新 run 注入阶段总结;落 checkpoint。
