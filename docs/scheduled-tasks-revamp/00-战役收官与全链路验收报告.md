## 二、六大核心加固铁律落地验收

1. **CRIT-01（代际-协程物理绑定铁律）**：
   - 在 `sched.rs` 的 `update_task` 中，仅当 schedule 表达式改变且任务为 Active 时才推进 generation 并重新 spawn 计时协程；若仅更新 Prompt、CWD、TargetSessionId，严格保留原倒计时协程与代际；单测 `test_update_task_crit_01_generation_binding` 100% 验证。
2. **CRIT-03（启动装配时序铁律）**：
   - 在 `main.rs` 中，`ProductionScheduledLauncher` 在 `reg.restore().await` 之前先行注入，彻底消灭启动冷启动触发时由于 Launcher 未就绪导致的降级漏击。
3. **INT-01（输入态保护屏障）**：
   - 在 `sessionDraftManager.ts` 中维护输入焦点锁与 1500ms 打字屏障；高频后台定时流式消息推送期间，用户在输入框敲击的内容一字不丢，撤销栈完好无损。
4. **INT-02（全局工作区沙箱兜底）**：
   - 定时任务未指定 `cwd`（空字符串）时，后端自动解析并创建 `<app_data_dir>/scheduled-tasks-sandbox`，前端提供“🌐 全局工作区”一等公民选项，绝不因缺少 CWD 拒绝执行。
5. **INT-04（会话删除自愈降级）**：
   - 绑定的目标会话若被用户删除，后台触发前自动检测 `store.session_exists`，自愈清空失效 ID 并平滑回退至独立后台会话执行，避免任务崩溃挂死。
6. **INT-06（原子 Selector 隔离）**：
   - 侧边栏会话行通过 `useSessionActiveScheduleCount(sessionId)` 和 `useSessionSchedules(sessionId)` 局部订阅，只有绑定了任务且任务发生实质变更的会话才会局部重渲染，全量会话列表零性能损耗。
