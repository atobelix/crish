## 一、战役背景与破局目标

### 1.1 现状核心痛点穿透

在既有实现中，定时任务存在七大阻断日常使用的结构性断层：

1. **单任务控制彻底失灵**：用户点击暂停，`WorkflowBackend::update` 仅修改本地存储，未通知底层 `SchedulerRegistry`；随后的 `list()` 盲目使用注册表快照将未更新的状态反向冲刷覆盖数据库，界面反复弹回。
2. **应用重启后定时任务协程全亡（历史悬案）**：`engine_build.rs` 的 `try_current()` 在主 GUI 线程同步执行时必为 `Err`，导致开机 `restore()` 被完全跳过，已配置的任务重启后彻底不再触发。
3. **虚假完成与幽灵死信队列**：触发时直接硬编码 `status: "completed", duration_ms: Some(0)`，往孤儿会话 `sched-{cron_id}` 的队列推入文本后便结束，根本没有调用 `run_task_impl`，没有模型推理与工具调用，Agent 从未真正执行。
4. **双写抹杀致任务触发后神秘蒸发**：底层 `CronTask` 到期后写回同一存储键，直接抹除上层 `StoredWorkflow` 的 `name`、`schedule`、`cwd` 等字段，反序列化失败后整条任务从列表隐形丢失。
5. **历史孤儿 Running 记录永久蓝色假死**：历史执行记录缺乏终态收口，滚动修剪硬编码保护 running，导致用户任务已标为“已暂停”，但下方历史记录依然永久挂着蓝色【运行中】，造成强烈撕裂感。
6. **对话内自动化与会话孤岛断裂**：数据结构与 Agent 工具缺乏目标会话归属，硬编码为幽灵会话，无法在用户当前对话内流式呈现执行过程与成果。
7. **前端表单能力缺陷、双轨包袱与视觉违规**：`sch.minutes` 与 `intervalMinutes` 双轨兼容混乱；Cron 任务被强行降级为 manual；侵入式 `useEffect` 强制绑架工作区；缺乏 5 字段 Cron 输入与目标会话选择；存在原生 title 与违规重阴影。

### 1.2 战役终极目标与去兼容现代化方针

彻底重构底层调度器、执行引擎、IPC 命令层与前端 UI，实现：

- **单任务原生启停**（0ms 响应、不弹回、代际防复活）；
- **开机 100% 异步自愈恢复与历史孤儿 Running 终结收割**；
- **真实 Agent 执行循环**（真实调用模型/工具、真实耗时与摘要收口、排队防踩踏）；
- **对话内自动化双模绑定**（当前对话追加执行 vs 独立专用后台会话）；
- **全生命周期 ID 恒定与底账防洗白**；
- **前端全功能 Cron 表单与现代视觉交互**；
- **单轨纯净实现**：彻底清退 `sch.minutes ?? sch.intervalMinutes` 的双重兼容层，统一契约唯一为 `intervalMinutes`，不搞过度版本；
- **核心资产与安全底线零妥协**：守牢对话历史完整性、正在打字屏障、全局沙箱隔离、已删除会话防灵异复活与细粒度徽标性能防线。

## 三、五大阶段核心方案成果与去兼容现代化决策

### 阶段 1：Rust 底层调度器核心治理与单任务生命周期

- **四态生命周期模型（Active / Paused / Completed / Cancelled）**：废弃单一模糊布尔值，确立单任务在底层具有独立暂停、恢复与停止能力。
- **协程代际保护（`generation: u64`）**：每次启停更新递增代际号，重建时严格校验代际匹配，彻底杜绝僵尸协程复活。
- **开机 Restore 异步可靠闭环与孤儿收割**：在 `main.rs` 异步恢复区挂载 `restore().await`，配合 `AtomicBool` 幂等防重入与离线任务并发补发，开机时对落盘但未终态的 `status = "running"` 孤儿记录自动批量收割为 `interrupted`。
- **AA-02 锁治理规约**：互斥锁严格限制在微秒级内存读写，锁绝不跨 `await`，锁释放后执行磁盘持久化。

### 阶段 2：真实 Agent 执行驱动与无人值守唤醒闭环

- **彻底清退虚假完成与死队列**：彻底废除触发时硬编码 `completed / 0ms` 和孤儿会话盲塞队列的假逻辑，初始状态记录为真实 `running`。
- **生产级 `ProductionScheduledLauncher`**：通过 `Weak<CoreRunState>` 破除强引用循环，调用真实 `run_task_impl`，产出多轮模型对话与工具调用。
- **终态收口钩子 `on_scheduled_run_terminal`**：运行结束时自动调用 `update_run_finish`，提取助手回复纯文本（截断至 300 字符）作为摘要，计算真实耗时并更新终态（completed / failed）。
- **串行排队与 WakeWatcher 接力**：若目标会话正在生成回复，任务标为 `queued`，由 `WakeWatcher` 在前序 Run 释放后自动无缝接力拉起，杜绝并发崩溃。

### 阶段 3：目标会话绑定与对话内自动化定时任务能力

- **单轨双模目标会话归属模型**：
  - **当前会话绑定（Bound Mode）**：`target_session_id = Some(sid)`，执行流直接追加到当前会话；
  - **独立专用会话（Isolated Mode）**：`target_session_id = None`，自动归档为专用后台会话。
- **Agent 工具上下文感知**：彻底消除 `CreateWorkflowTool` 对 `_ctx` 的下划线忽略，默认自动读取并绑定当前 `ctx.session_id`。
- **核心资产零破坏与 INT-01 正在打字保护屏障**：用户的已有会话历史绝对严禁清空损坏；流式执行时严格遵守正在打字屏障，绝不抢占输入焦点、绝不冲刷用户草稿。
- **INT-02 全局任务安全沙箱**：未指定工作区路径时，强制降级到全局独立隔离沙箱目录，绝不能降级到客户端工作区，杜绝误伤误删客户端本体。
- **INT-04 已删除会话防灵异复活与自愈**：目标会话被删后，触发时严禁灵异复活重建会话，自动自愈转为 `isolated` 独立后台记录。
- **INT-06 侧栏细粒度徽标存储（`SessionScheduleBadgeStore`）**：采用轻量原子 Store 维护会话计数，仅精准通知受影响节点，杜绝全量重绘。

### 阶段 4：Tauri IPC 命令面与元数据双向一致性

- **工作流 ID 恒定铁律（ID Invariance）**：重构 `update-workflow`，废除修改表达式时 `cancel + register` 的反模式，通过底层原地热替换保持 `cron_id` 与创建时间恒定，历史运行记录永久继承。
- **JSON 字段安全合并（Safe Field Merge）**：底层写回时合并保留非调度字段，彻底根除双写抹杀 Bug。
- **彻底删除 `list()` 盲目反向覆盖**：确立数据库作为业务真源，删除未同步快照覆盖数据库的代码，确保暂停/启用 100% 稳定。
- **单轨索引存储**：统一使用 `sched_index`，加载时直接收敛，不再维护过度历史多轨。

### 阶段 5：前端 UI 交互、表单能力与状态同步

- **彻底清退旧兼容垫片**：彻底删除 `sch.minutes ?? sch.intervalMinutes` 的双重兼容层，统一契约唯一为 `intervalMinutes`；彻底删除冗余的历史版本字段兼容转换代码。
- **细粒度行锁与 2000ms 乐观保护窗口**：废弃全局单点 `busy` 锁，单行切换 0ms 乐观翻转；引入 2000ms 保护期，阻断外部快照反向冲刷，失败精准回滚。
- **5 字段 Cron 输入与实时人读徽标**：支持标准 Cron 输入；行内动态联动双态人读徽标（合法显示 `✓ 执行时机：工作日 09:00`，非法显示红徽）；提供常用预设芯片。
- **解除工作区绑架**：移除强制覆写 `cwd` 的 `useEffect`，前端支持“全局 / 不限项目（独立隔离沙箱执行）”。
- **终结历史运行记录假死**：前端全面支持 `interrupted` 状态机，`RunHistoryList.tsx` 渲染中性黄/灰徽标与原因 Tooltip，杜绝任务已暂停但历史记录仍为“运行中”的撕裂感。
- **视觉规范全面对齐**：清退原生 title，统一自定义 Tooltip；聚焦边框混入 ≤10%，杜绝粗黑硬边与外凸重阴影。

## 五、实施波次规划（Implementation Waves）

遵循先底座、再执行、次契约、后前端的依赖链，划分为 4 个单轨实施波次：

```
Wave 1: 底座与生命周期治理 (Phase 1 + Phase 4 存储层)
   │  • sched.rs 单任务生命周期 API (pause/resume/update)
   │  • main.rs 开机 Restore 异步闭环挂接与孤儿 running 记录收割
   │  • Safe Field Merge 与 sched_index 单轨存储
   ▼
Wave 2: 真实执行管道与会话上下文 (Phase 2 + Phase 3 工具与路由)
   │  • ProductionScheduledLauncher 接入 run_task_impl 真实执行循环
   │  • on_scheduled_run_terminal 真实收口与摘要提取
   │  • CreateWorkflowTool 上下文感知与 target_session_id 注入
   │  • INT-02 全局沙箱降级与 INT-04 已删会话自愈逻辑
   ▼
Wave 3: 命令面全链路一致性与单轨契约 (Phase 4 命令面 + Phase 3 路由)
   │  • update-workflow 原地热更新与全字段原子补丁 (ID Invariance)
   │  • list-workflows 彻底移除脏快照反向覆盖
   │  • 统一下发 intervalMinutes 单轨契约，清除旧多轨字段
```
