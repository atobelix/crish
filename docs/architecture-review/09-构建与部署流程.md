# 诊断方向 09：构建与部署流程

## 检查目标
评估构建系统的效率、CI/CD 流水线、发布流程、多平台支持及开发体验。

## 检查清单

### 9.1 构建效率
- [ ] 根目录的 scripts 数量（60+）是否过多——是否需要脚本管理工具（nx/turborepo）
- [ ] esbuild + tsc 双构建模式是否增加了构建复杂度和时间
- [ ] TypeScript 声明文件生成是否作为独立步骤浪费 CI 时间
- [ ] 构建缓存是否有效（esbuild 增量构建、tsc --build --incremental）
- [ ] `development` 条件 export 是否在 production 中正确解析

### 9.2 CI/CD 流水线
- [ ] CI 是否包含了类型检查、lint、单元测试、集成测试、构建、产物上传
- [ ] CI 中是否包含了 Rust/Tauri 的编译（macOS + Windows + Linux 三平台）
- [ ] 是否配置了自动版本发布与 changelog 生成
- [ ] PR 检查是否包含必要的 check（test、lint、typecheck、build）
- [ ] CI 缓存策略是否有效（node_modules、Cargo registry、esbuild cache）

### 9.3 多平台支持
- [ ] 平台相关代码是否使用了正确的条件编译（process.platform、platform.select）
- [ ] 文件路径分隔符是否使用了跨平台方案（path.join > 字符串拼接）
- [ ] 默认数据目录在不同 OS 上的解析是否正确（Windows %LOCALAPPDATA% vs Linux ~/.crish）
- [ ] Shell 命令在不同 OS 上的兼容性

### 9.4 开发体验
- [ ] 开发模式（dev scripts）的启动时间和热重载效果
- [ ] HMR（Vite 热更新）是否跨进程边界工作正常
- [ ] source map 是否正确配置
- [ ] 调试配置（launch.json、.vscode 配置）是否方便
- [ ] pre-commit hooks（husky + lint-staged）的检查速度

### 9.5 发布流程
- [ ] 版本号管理是否使用 changesets 或 semantic-release
- [ ] Tauri 应用的签名与 notarization 是否配置
- [ ] 更新机制（Tauri updater）是否集成
- [ ] 发布产物（安装包、可执行文件）的自动化构建

## 检查方法
- 实际运行 `npm run build` 并计时
- 审查 `.github/workflows/` 中的每个 YAML 文件，分析步骤间依赖
- 检查 Tauri 配置中的 bundle 和 security 设置
- 审查 pre-commit 钩子的配置和 lint-staged 的范围
- 检查跨平台路径处理代码的正确性
