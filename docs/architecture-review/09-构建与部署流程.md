# 诊断方向 09：构建与部署流程

## 检查目标
评估构建系统效率、CI/CD 流水线、发布流程、多平台支持及开发体验。

## 检查清单

### 9.1 构建效率
- [ ] 根目录 scripts 数量（约 48 个）是否过多——是否需要 monorepo 工具（nx/turborepo）
- [ ] esbuild + tsc --emitDeclarationOnly 双构建模式是否高效
- [ ] `build:types` 手动删除 tsbuildinfo 是否抵消了增量编译收益
- [ ] 构建缓存：esbuild 增量构建、node_modules 缓存（CI 中缺失）
- [ ] `development` 条件 export 在生产环境是否正确解析

### 9.2 CI/CD 流水线
- [ ] CI 是否包含：lint → typecheck → test:coverage → build → 产物上传
- [ ] CI 是否包含 Rust/Tauri 编译（目前仅 ubuntu-latest，缺 macOS/Windows 矩阵）
- [ ] 自动版本发布与 changelog 生成（changesets/semantic-release 缺失）
- [ ] PR 检查包含 test/lint/typecheck/build
- [ ] CI 缓存策略：node_modules（缺失）、Cargo registry（有）、esbuild（缺失）

### 9.3 多平台支持
- [ ] 平台相关代码是否使用条件编译（`process.platform` 被 Vite 硬编码的修复）
- [ ] 文件路径使用 join 而非字符串拼接
- [ ] 默认数据目录跨平台解析正确性（Windows %LOCALAPPDATA% vs Linux ~/.crish）
- [ ] Tauri bundle 跨平台签名与 notarization
- [ ] CI 中 Rust 编译需扩展至 Windows + macOS

### 9.4 开发体验
- [ ] dev scripts 的启动时间和热重载效果
- [ ] HMR 跨进程边界（Vite → Tauri webview）的工作情况
- [ ] source map 配置正确性
- [ ] 调试配置（launch.json、.vscode 配置）的完整性
- [ ] pre-commit hooks（husky + lint-staged）的检查速度
- [ ] `.husky/pre-push` 是否包含了必要的 pre-push 检查

### 9.5 发布流程
- [ ] 版本号管理（当前内部包全部 0.1.0）
- [ ] Tauri app 签名与 notarization
- [ ] Tauri updater 配置（当前缺失）
- [ ] GitHub Release 自动化发布
- [ ] 构建产物 size-limit/bundle 分析 CI 步骤

## 检查方法
- 运行 `npm run build` 并计时
- 审查 `.github/workflows/` 的每个 YAML 文件
- 审查 Tauri 配置中的 bundle、security、updater 设置
- 审查 pre-commit hook 配置
- 检查跨平台路径处理代码的正确性
