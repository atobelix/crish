# 诊断方向 06：安全与密钥管理

## 检查目标
评估系统在 API 密钥管理、输入验证、数据安全、跨进程通信安全等方面的安全性。

## 检查清单

### 6.1 密钥管理与凭据安全
- [ ] API Key 在进程间传输时是否经过脱敏
- [ ] API Key 在前端 localStorage 中的存储是否安全
- [ ] daemon-ready 日志中是否泄露了密钥信息（last4、keySource）
- [ ] 是否支持多 API Key 源的优先级管理
- [ ] WebSocket 连接是否有认证机制（还是信任同机访问）
- [ ] Tauri 与 daemon 之间的 IPC 是否加密

### 6.2 输入验证
- [ ] WebSocket 入站消息是否经过 schema 验证（使用 zod 或其他）
- [ ] 用户输入（聊天内容、文件路径）是否经过安全检查
- [ ] 文件上传是否有类型/大小/路径遍历的检查
- [ ] tool call 参数是否有类型和范围验证
- [ ] terminal command 是否经过风险分类清理后再执行

### 6.3 Web/I/O 安全
- [ ] Tauri CSP（Content Security Policy）配置是否合理限制了脚本执行
- [ ] 前端是否对 LLM 输出的 Markdown/HTML 进行了 sanitize
- [ ] 跨标签页通信（BroadcastChannel/localStorage）来源是否验证
- [ ] Tauri capability 权限配置是否遵循最小权限原则

### 6.4 依赖安全
- [ ] 是否配置了自动依赖漏洞扫描（Dependabot、Snyk）
- [ ] npm audit 结果中是否存在高危/严重漏洞
- [ ] Rust crate 是否存在已知的 security advisory
- [ ] 是否依赖了未经审计或低维护的第三方包

### 6.5 代码级安全问题
- [ ] 是否存在 eval/Function 构造函数调用
- [ ] 是否存在动态 `import()` 且参数可被外部控制
- [ ] `any` 类型绕过导致的安全校验缺失
- [ ] 秘密信息的硬编码（token、URL、API endpoint）

## 检查方法
- 搜索关键字 `apiKey`、`password`、`secret`、`token`、`credential` 的引用
- 检查 tauri.conf.json 中的 security 配置
- 审查 WebSocket message 的输入验证链路（从收到到处理）
- 运行 `npm audit` 和 `cargo audit` 检查已知漏洞
- 审查 Tauri capability JSON 的范围
