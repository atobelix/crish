# 诊断方向 05：测试覆盖与质量保障

## 检查目标
评估测试架构的完整性、测试策略的有效性、测试质量与测试基础设施的健全度。

## 检查清单

### 5.1 测试覆盖边界
- [ ] 核心模块（agent-runtime/runtime.ts、agent-session-loop.ts、server.ts、orchestrator.ts）是否有单元测试
- [ ] 未覆盖的模块/文件清单——哪些关键路径没有被测试触及
- [ ] 配置文件中 test include 是否包含了所有测试类型（单元、集成、fuzz、recovery）
- [ ] 每个 test suite 是否对应到具体的功能模块而非模糊的测试

### 5.2 测试质量
- [ ] 是否存在只测 happy path 不测 error path 的测试
- [ ] 是否有依赖实现细节的脆弱测试（如断言内部状态而非公共行为）
- [ ] mock 的使用——是 mock 接口还是 mock 具体实现
- [ ] 测试中的时间控制是否使用了 `vi.useFakeTimers` 且 cleanup 正确
- [ ] 测试间是否共享了可变状态（module-level caches、全局单例）

### 5.3 测试基础设施
- [ ] CI 中的测试是否包含所有测试类型（unit + integration + fuzz + recovery）
- [ ] 覆盖率阈值是否设置且严格执行
- [ ] 测试报告是否生成并可在 CI 中查看
- [ ] 是否有性能回退测试（benchmark regression detection）
- [ ] 是否有端到端测试覆盖完整用户流程

### 5.4 特殊测试类型
- [ ] Fuzz 测试——覆盖了哪些边界输入
- [ ] 压力/负载测试——daemon 在高并发消息场景下的表现
- [ ] 恢复测试——断线重连、crash 后的状态重建
- [ ] 竞态测试——并发修改状态、并发 WebSocket 消息
- [ ] 安全测试——XSS、注入、API 密钥泄露

### 5.5 测试可维护性
- [ ] 是否有测试助手/工厂函数共享（mock factories、test data builders）
- [ ] 测试文件命名与源文件结构是否对应
- [ ] 测试数据是否硬编码还是使用生成器
- [ ] 跨包测试使用的依赖是否是模拟而非真实模块

## 检查方法
- 运行 `npx vitest run --coverage` 获取覆盖率报告，人工审查未覆盖区域
- 对每个 package 列出其源代码文件与测试文件的比例
- 审查测试中的 mock 模式——是否依赖了无接口的具体类
- 检查 `vitest.config.ts` 和 `vitest.integration.config.ts` 的 include patterns 是否完备
