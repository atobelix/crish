## 1. Rust 侧极限单元测试套件设计 (RS-01 ~ RS-10)

在 `crates/agent-provider/src/parse/think_tags_tests.rs` 中落地以下极限场景断言：

| 用例 ID | 测试场景 | 输入切片序列 | 预期断言 |
|:---|:---|:---|:---|
| **RS-01** | 标准单 Chunk | `"<think>abc</think>def"` | 1 个 `Thought("abc")`, 1 个 `Text("def")` |
| **RS-02** | 极限逐字切碎 | `"<"`, `"t"`, `"h"`, `"i"`, `"n"`, `"k"`, `">"`, `"a"`, `"<"`, `"/"`, `"t"`, `"h"`, `"i"`, `"n"`, `"k"`, `">"` | 思考内容严格为 `"a"`，标签 0 泄露 |
| **RS-03** | 虚假开标签回滚 | `"<table border=1>"` | 严格产出 `Text("<table border=1>")`，零丢字 |
| **RS-04** | 思考态内虚假闭标签 | `"<think>x < 1 </table y</think>"` | `Thought("x < 1 </table y")` |
| **RS-05** | EOF 异常截断冲刷 | `"<think>unfinished"` $\to$ `finish()` | 冲刷产出 `Thought("unfinished")`，不崩溃 |
| **RS-06** | 闭标签后首换行消除 | `"<think>a</think>\n# Title"` | 标题前无多余空行，首个 `\n` 被精准吸收 |
| **RS-07** | 多重连续思考块 | `"<think>1</think><think>2</think>body"` | 正确产出两个 `Thought` 块及正文 |
| **RS-08** | CJK 多字节边界切分 | `"<think>中文思考</think>正文"` (UTF-8 字节中途切开) | 多字节 UTF-8 字符无乱码损坏（零 U+FFFD） |

## 2. 前端侧 Vitest 单元测试套件设计 (TS-01 ~ TS-06)

1. **`messageHandlers.idempotent.test.ts`**：
   - 断言 `onMessageEnd` 连续触发 3 次（模拟重试与多轮收口），`state.assistantText` 严格不变，`callbacks.onChunk` 调用次数为 **0**。
2. **`timelineBlocksReconcile.test.ts`**：
   - 断言多轮 `updateMessageTimeline` 触发后，历史轮次的 `tool_call` 与 `thought` 块 100% 留存。
3. **`parseMarkdownIntoBlocks.test.ts`**：
   - 断言包含嵌套 `<div>`、LaTeX `$$...$$` 公式与 CommonMark 代码块的长文本能够被准确切分为离散 Block 序列。

## 4. 《反退避与零破坏验收清单》（Anti-Regression Checklist）

- [ ] **严禁降级**：绝不允许为了规避状态机复杂度而在前端使用简单的正则全局替换。
- [ ] **严禁伪流式**：绝不允许在流式期间使用纯文本而在收口时整体替换为 Markdown。
- [ ] **严禁破坏性过滤**：绝不允许在更新时间线时通过 `filter(type === 'tool_call')` 丢弃 `thought` 块。
- [ ] **门禁全绿**：
  ```pwsh
  # 必须执行并通过的组合门禁
  cargo test --workspace
  npm run typecheck
  npm test
  ```
