# 03-分维实现详案：消息生命周期与多轮幂等收口详案

> **所属战役**：`docs/markdown-stream-refactor/`
> **核心目标**：彻底消除 `message-end` 与 `onChunk` 的交互冲突，设计单生产者流式状态机，根治多轮会话（`turnIndex > 0`）与重试下千字大段文字重复两遍的严重缺陷。
> **涉及文件**：
> - `apps/crish-desktop/src/api/chat-bridge/handlers/messageHandlers.ts` (核心修改)
> - `apps/crish-desktop/src/api/chat-bridge/handlers/streamState.ts` (状态结构演进)
> - `apps/crish-desktop/src/hooks/chat-stream/helpers.ts` (commitStreamToSession 幂等保证)

---

## 1. 文字重复 Bug 根因解剖与形式化证明

### 触发链路分析

1. **实时轨（`onMessageDelta`）**：在第 $k$ 轮流式中，字符实时累积至 `state.assistantText` 并触发 `callbacks.onChunk(delta)`。
2. **收口轨（`onMessageEnd`）的致命缺陷**：
   ```typescript
   // 旧实现问题代码：
   segs[turnIndex] = mergeAssistantTextPiece(segs[turnIndex] ?? '', piece);
   const joined = segs.filter(Boolean).join('\n\n');
   state.assistantText = joined;
   if (state.assistantText.length > prevLen) {
     const addedDelta = state.assistantText.slice(prevLen);
     callbacks.onChunk(addedDelta); // <--- 致命二次注入！
   }
   ```
3. **当 Gateway 返回全量文本时**：`piece` 本身就是整段累积文本，`segs.join` 导致长度暴增一倍，`slice(prevLen)` 直接切出整整第二份完整文本推入 `onChunk`，造成大段文字 100% 重复输出两遍。

## 2. 核心架构设计：单增量生产者铁律 (Single Producer Invariant)

```
[增量渲染队列 callbacks.onChunk] <==== 唯一写入源 ==== [onMessageDelta (实时流)]
                                                              ▲
                                                              │ 严禁二次写入！
[权威落盘账本 sessionStore]      <==== 权威写入源 ==== [onMessageEnd (多轮收口)]
```

### 规则 1：生产者严格分离

- **`onMessageDelta`**：负责打字机实时动画，是调用 `callbacks.onChunk` 的**唯一合法入口**。
- **`onMessageEnd`**：**严禁调用 `callbacks.onChunk`**！其唯一职责是将权威消息快照写入多轮分段账本 `messageEndTurnSegments[turnIndex] = piece`，供持久化与收口使用。

### 规则 2：强类型多轮账本 (`StreamTurnLedger`)

```typescript
export interface StreamState {
  cancelled: boolean;
  finished: boolean;
  assistantText: string;
  assistantThought: string;
  unsub: (() => void) | null;
  endTimer: ReturnType<typeof setTimeout> | null;
  /** 每轮权威文本快照（按 turnIndex 索引） */
  messageEndTurnSegments?: string[];
}
```

## 3. `onMessageEnd` 完全幂等重构实现

```typescript
export function onMessageEnd(
  env: HandlerEnv,
  envelope: EngineEnvelope<'message-end'>
): void {
  const { state, callbacks } = env;
  const msg = envelope.event.message;
  if (msg.role !== 'assistant') return;

  const { text, thought } = projectAgentMessageContent(msg);

  // 1. 思考链收口：权威覆盖，不追加
  if (thought.trim()) {
    state.assistantThought = thought.trim();
    callbacks.onThought?.(state.assistantThought);
  }

  // 2. 正文收口：多轮分段权威覆盖，严禁调 onChunk 追加！
  if (text.trim()) {
    const piece = text.trim();
    const turnIndex = envelope.event.turnIndex ?? 0;
    if (!state.messageEndTurnSegments) state.messageEndTurnSegments = [];
    const segs = state.messageEndTurnSegments;
    while (segs.length <= turnIndex) segs.push('');
    // 幂等设置对应轮次的权威文本
    segs[turnIndex] = piece;
    state.assistantText = segs.filter(Boolean).join('\n\n');
  }

  // 3. 缓存指标处理
  const metrics = computeCacheMetricsFromUsage(msg.metadata);
  if (metrics) {
    state.lastMessageCacheMetrics = metrics;
    callbacks.onMessageCacheMetrics?.(metrics);
  }
}
```

## 4. `commitStreamToSession` 幂等收口保证

1. **同值短路保护**：若 `sessionStore` 中目标消息文本与即将提交文本一致，直接跳过写操作，防止无谓的全局 React 重新渲染。
2. **延时微任务清理**：`queueMicrotask` 清理 `streamingStore`，确保 React 完成 DOM 挂载，彻底杜绝切瞬白屏。
