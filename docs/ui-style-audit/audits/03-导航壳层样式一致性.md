# 03 · 导航壳层样式一致性审计（A3）

- **审计员**：A3（前端样式审计）
- **审计范围**：`apps/crish-desktop/src/components/sidebar/`（Sidebar、SidebarNav、SidebarSessionList、SidebarContextMenus 及 session-list 渲染链）、`components/top-bar/`（AppTopBar）、`components/shell/`（WindowControls、GlobalSessionTabBar、sessionTabDrag*）
- **判定判据**：仓库根 `AGENTS.md` §12（Tooltip）/ §13（输入框焦点态）/ §14（色彩空间与现代 CSS 语法）；token 真源 `apps/crish-desktop/src/styles/tokens.css`
- **方法**：只读代码（.css/.tsx/.ts），交叉 grep 验证 token 定义与引用；未读 docs/ 下任何历史文档

## ① 总评

**结论先行：token 化率整体较高，但存在三类系统性问题——z-index token 卫生失控（3 个未定义 token、其中 2 处无兜底已实际失效）、同一侧栏内 hover 配方双轨（暖褐 vs 中性）、最高频交互面（侧栏会话行）键盘焦点不可见。**

分维度概述：

1. **颜色 token 化**：好。侧栏 hover/active 主链路（导航项、会话行、右键菜单项）正确走 `--sidebar-hover`/`--sidebar-active`；组件内几乎没有裸十六进制色。唯一硬编码违规是窗口关闭键的红底白字（token 已存在却未用）。`var()` 兜底值里残留一批旧式 `rgba(...)` 和与真值不符的误导性 fallback（均属死代码，不影响运行但污染 §14 口径）。
2. **尺寸体系**：中。侧栏导航项高度走 `--control-height`、图标走 `--icon-size`，规范；但**会话行高 28px 在 CSS 里硬编码 6 处 + TS 常量内联注入形成双源**，顶栏按钮（28/32/26px）全部不挂 `--control-height-sm` 等 gear token——密度档切换时导航壳层不会联动。
3. **焦点态**：分裂。导航项/标签页走柔和外圈 `--focus-ring`（合规），共享 Button 走 1.5px 低混入环（合规）；但**会话行（role=treeitem，roving tabindex + 方向键漫游）完全没有 :focus-visible 样式**，键盘用户看不到焦点在哪，直接违反 §13「焦点变化须可见」；右键菜单项又用第三种 inset 描边语言。dark 主题 `--focus-ring-color` 混入 30% text-primary，远超 light 的 8%，也超出 §13 约 10% 的上限口径。
4. **反馈强度**：量级基本一致（hover 均 4% 混入档），但配方不统一：侧栏主链路用暖褐 `--sidebar-hover`（control-mix-color 4% over bg-secondary），页脚/头部控件与顶栏全部用中性 `--tint-hover`/`--bg-hover`（text-primary 4%）——light 主题下同屏存在两种色相的 hover。按压反馈只有会话行有 `:active`，导航项没有。
5. **现代语法与暗色**：好。color-mix/hsl 斜杠透明度已是主流写法；除关闭键红外无主题相关硬编码，暗色适配基本由 token 免费获得。
6. **z-index**：差，是本次最严重的发现。`--z-sidebar-resizer`、`--z-drag-overlay`、`--z-sticky-bar` 三个被消费的 token **在整个 src 内无任何定义**（z-index.css 定义的近名 token 是 `--z-resizer`/`--z-sticky`，拖拽浮层既有契约档位是 `--z-toast`），其中两处消费无兜底值，声明按 CSS 规则整条失效。
7. **跨区域一致性**：侧栏会话行 vs 顶部全局标签同为「会话入口」，高度（28 vs 26）、圆角（8 vs 4）、字号（14 vs 12）、选中态语言（平涂 tint vs 卡片描边+阴影）全面分叉，未见成体系的对应关系说明；详见 §② 对比表。
8. **§12 Tooltip 合规**：✅ 审计范围内所有悬停提示（窗控三键、侧栏开关、帮助、标签关闭、会话时间、更多操作）均使用自定义 `<Tooltip>`，未发现原生 `title`。

## ③ 问题清单

### 🔴 违规（违反 §13/§14 判据，或声明已实际失效）

**R1 · 关闭键悬停色硬编码，token 已存在未消费**
- `apps/crish-desktop/src/components/shell/WindowControls.module.css:33-34`：`.closeBtn:hover { background: #e81123; color: #ffffff; }`
- tokens.css:257-258 已定义 `--window-close-bg: #e81123` / `--window-close-fg: #c50f1f`（注释明确标注「shared by app top bar + inset chrome」），本处绕开真源直接写裸 hex。改色时必然漂移。

**R2 · 侧栏会话行键盘焦点不可见（违反 §13「焦点变化须可见」）**
- `SessionRow.tsx:260-266`：行元素 `role="treeitem"` + `tabIndex` roving（选中行 0 其余 -1），且有完整方向键/F2/ContextMenu 键盘协议（SessionRow.tsx:295-327）；
- 但 `SidebarSessionList.module.css` 全文（含 `.sessionItem` 260-309、`.sessionItemWrap` 251-258）**没有任何 `:focus-visible`/`:focus` 规则**——键盘漫游时视觉零反馈。这是用户视线最高频停留区的可达性缺口。
- 连带：重命名输入框 `.sessionRenameInput:focus` 只改 `border-color`，而该输入框 `border: none`（SidebarSessionList.module.css:324,336-339），border-color 变更无效，同样无可见焦点态。

**R3 · 三个 z-index token 悬空（无定义），其中两处无兜底已实际失效**
全 src grep 验证：`--z-sidebar-resizer`、`--z-drag-overlay`、`--z-sticky-bar` **均无 `:` 定义**；`styles/z-index.css` 提供的近名正牌 token 是 `--z-resizer`（z-index.css:12）、`--z-sticky`（z-index.css:7），拖拽浮层的既有契约档位是 `--z-toast`（style-contract.test.ts:86-89、tabDragGhost.ts:62-63 已锁定该口径）。
- `Sidebar.module.css:272`：`z-index: var(--z-sidebar-resizer);` 无兜底 → 声明按「invalid at computed-value time」整条失效，resizer 回落 auto；
- `GlobalSessionTabBar.module.css:432`：`.dragGhost { z-index: var(--z-drag-overlay); }` 无兜底 → 同上失效（注：该类本身未被引用，见 Y8，但失效事实成立）；
- `SidebarSessionList.module.css:549`：`var(--z-drag-overlay, 1000)` 靠兜底 1000 存活，与 `--z-toast`(1000) 数值巧合相同但来源分叉；
- `SidebarContextMenus.module.css:153`：`.sortFilterFlyout { z-index: var(--z-sticky-bar); }` 无兜底 → 失效为 auto。该 flyout 是 `position:absolute` 嵌在菜单行内（ContextMenuFlyout.tsx:89-101），z-index 失效后与后续兄弟行的绘制顺序失去保障（后续行 hover 有底色，可能盖住飞出的选项层）；
- `GlobalSessionTabBar.module.css:37`：`var(--z-sticky-bar, 2)` 靠兜底 2 存活，与 z-index.css 档位体系（dock=10/chrome=100）脱节。

**R4 · dark 主题焦点环比 light 强约 4 倍，超 §13 混入上限口径**
- tokens.css:105-109（light）：`--focus-ring-color = control-mix-color 8%`；tokens.css:677（dark）：`= text-primary 30%`。
- 该 token 被审计范围内 `SidebarNav.module.css:76`、`GlobalSessionTabBar.module.css:197,351,418` 直接消费。§13 口径为焦点混入 ≤约 10%；dark 30% 属 token 层定义（不在审计目录内），但作为判据冲突必须上报，建议 dark 收敛至 10–12% 档或单独定义 ring 档位。

### 🟡 漂移（不成体系/双源/语言分裂）

**Y1 · 同一侧栏两种 hover 配方（暖褐 vs 中性）**
- 主链路走 `--sidebar-hover`/`--sidebar-active`（暖褐 control-mix-color）：SidebarNav.module.css:54,65、SidebarSessionList.module.css:286,299,305、SidebarContextMenus.module.css:46；
- 同屏的页脚/头部控件走 `--bg-hover`/`--bg-active`（= 中性 `--tint-*`）：Sidebar.module.css:97,101,185,190,221,333、SidebarSessionList.module.css:136,240、SidebarContextMenus.module.css:126,188。
- light 主题下 `--control-mix-color` 为 hsl(35,40%,30%)（tokens.css:69），与中性黑 tint 存在可感知色相差；dark 下两公式趋同（tokens.css:664-675 注释亦承认此差异）。用户在同一侧栏内滑动会感到 hover 底色「忽暖忽灰」。

**Y2 · 会话行高 28px 双源（CSS 硬编码 ×6 + TS 常量内联）**
- CSS：SidebarSessionList.module.css:253-255（wrap min/max）、264-266（item min/max）、357（line-height 28px）、373-374；
- TS：`SIDEBAR_SESSION_ROW_HEIGHT = 28`（api/sessionListWindow.ts:11）经 SessionRow.tsx:255 以 inline style 再注入一遍 height/min/max。
- 同一几何两个真源，改行高必须同步两处；且 28px 数值上等于 `--control-height-sm`/`--sep-item-height` 却未挂接，密度档不联动。

**Y3 · 顶栏按钮尺寸不挂 gear token**
- sidebarBtn/helpBtn 28×28（AppTopBar.module.css:40-43,98-101）、winBtn 32×28（WindowControls.module.css:10-11）、tabAdd 26×26 八连声明（GlobalSessionTabBar.module.css:382-395）。
- 数值恰与 `--control-height-sm`(28)/26 档重合，但 `[data-ui-size]` 切换（tokens.css:901-903,977-979）不会传导到导航壳层——小字号档下正文控件变小而壳层按钮不变。

**Y4 · 图标尺寸散点化，窗控三键 glyph 不齐**
- CSS 侧规范走 `--icon-size`（SidebarNav.module.css:47-48）；TSX 侧内联 size 散布：AppTopBar.tsx:120,158（16）、WindowControls.tsx:82（15）,96,98（13）,113（16）、GlobalSessionTabBar.tsx:68（ADD_PLUS_SIZE=13）,302,330（12）、SessionRow.tsx:400-404（14）。
- 同一水平排上的最小化(15)/最大化(13)/关闭(16) 视觉重量不一；且全部绕过 `--icon-size` 密度联动。

**Y5 · 焦点态三种语言并存**
- 外圈 `--focus-ring`：SidebarNav.module.css:74-77、GlobalSessionTabBar.module.css:195-198,347-352,416-419；
- inset 1px `--border-color` 描边：SidebarContextMenus.module.css:51-53（contextMenuItem）；
- 共享 Button 的 1.5px 6% 混合环：ui/Button/Button.module.css:72-76（topBar 全部按钮实际走这套）。
- 三者各自柔软度尚可（单项均合规），但同一壳层内键盘 Tab 一圈会出现三种不同的焦点外观，未成体系。

**Y6 · 按压反馈有无不一**
- 会话行有 `:active` 按下变色（SidebarSessionList.module.css:285-288）；导航项是裸 `<button>` 且显式关掉了 ::before 罩（SidebarNav.module.css:41-44），无任何 `:active` 样式；tabAdd/winBtn 亦无（topBar 的 sidebarBtn/helpBtn 因走 ui/Button 获得 ::before 按压罩）。同为高频点击目标，反馈手感不一致。

**Y7 · 「选中会话」两套视觉语言（跨区域重点）**
- 侧栏：平涂 `--sidebar-active`（SidebarSessionList.module.css:304-309）；
- 顶栏标签：bg-workspace 卡片 + `text-primary 12%` 描边 + 微投影（GlobalSessionTabBar.module.css:200-207）。
- 平涂 vs 浮卡的分野本身可以是合理的层级隐喻（画布上的凸起胶囊），但配合 §② 表中高度/圆角/字号的全部分叉，两条入口看不出「同一对象两种容器」的体系感，更像两次独立设计。建议至少对齐圆角档与字号档的推导关系（如 tab 字号 = 行字号 − 2 档的规则化映射），并在 token 层留注释锚点。

**Y8 · 拖拽 ghost 三套实现、两套死代码**
- 在用：侧栏 `sidebarDragGhost`（useSessionListDrag.ts:158,226 → SidebarSessionList.module.css:540-553，bg-elevated 卡片风）；
- 死代码①：`.dragGhost` 类（GlobalSessionTabBar.module.css:430-454）grep `styles.dragGhost` 无任何 tsx 引用；
- 死代码②：`createGhostPill`/`topbar-tab-drag-ghost`（sessionTabDragDom.ts:105-130）导出后无调用方。
- 同为「拖着会话跑」的浮层，侧栏与顶栏若各自演化会出现两种 ghost 观感；建议删除死代码并统一到一份 ghost 规格（顺带解决 R3 中 dragGhost 的 z-index 失效问题）。

### 🔵 建议（卫生/收敛类）

**B1 · 清理 `var()` 内旧式 rgba 死兜底（§14）**
- AppTopBar.module.css:60,118、GlobalSessionTabBar.module.css:192,339,362,408、WindowControls.module.css:28：`var(--tint-hover, rgba(128,128,128,…))` 等。主 token 恒有定义，兜底永不生效；保留旧式 rgba 违反 §14「避免散落 rgba」口径，建议删兜底或改 hsla。

**B2 · 误导性 fallback 与真值不符**
- `var(--radius-md, 8px)`（真值 6px）：Sidebar.module.css:326,396；
- `var(--space-2, 6px)`（真值 8px）：Sidebar.module.css:356；
- `var(--transition-fast, 150ms ease-out)`（真值 cubic-bezier(0.4,0,0.2,1)）：AppTopBar.module.css:53-54,111-112、GlobalSessionTabBar.module.css:184-187 等多处。
- 平时不生效，一旦 token 被改名即静默落入错误值；建议统一清为无兜底或正确兜底。

**B3 · navItem 头部的 `--btn-*` 自定义属性死代码**
- SidebarNav.module.css:11-14 设置 `--btn-hover-overlay/--btn-active-overlay/--btn-radius/--btn-h`，但 navItem 是裸 button（非 ui/Button），且其 ::before 已显式禁用（41-44），四个变量无消费者。

**B4 · 重命名态绿色实线 outline 与全局焦点语言割裂**
- SidebarSessionList.module.css:477-482：`outline: 1.5px solid var(--accent-primary)`。非深黑不违 §13 硬线，但与 `--focus-ring` 家族不同源；建议改为 focus-ring 变体或在注释中锚定「编辑态专用」语义。

**B5 · 胶囊圆角未用 `--radius-full`**
- Sidebar.module.css:213,245 写 `999px`；token 体系已有 `--radius-full: 9999px`（tokens.css:324）。

**B6 · `--z-context-menu` 未定义、靠内联兜底续命**
- SessionContextMenu.tsx:165-166：`zIndex: 'var(--z-context-menu, var(--z-popover))'`，注释自认「未定义时整条作废」。当前行为正确（回落 popover=500），建议转正 token 或直写 `var(--z-popover)`，消除第四个幻影 token。

**B7 · standalone 条高 32px 局部变量与 `--titlebar-row-h`(28px) 并存**
- GlobalSessionTabBar.module.css:7 vs tokens.css:327。caption 变体覆写为 100% 不受影响；standalone 备用路径引入第二套条高口径。

**B8 · 侧栏结构 padding 魔数**
- Sidebar.module.css:34（12px 10px）、43（14px 10px）、53（4px 10px 8px）：未走 `--space-*`，与 iconCollapse 分支的 8px（350-376）手工对齐；建议 token 化便于密度联动。

**B9 · 悬停显隐动效两套技术**
- 会话行 opacity 切换（SidebarSessionList.module.css:435-446）vs 标签关闭钮 width 16→48 形变（GlobalSessionTabBar.module.css:326-332）。width 形变每帧触发布局，opacity 合成器友好；性能档 eco 下两者表现也会分叉。建议低频区统一 opacity + 渐变遮罩方案（tabClose 已有渐变底，具备改造条件）。

## ④ Top 问题小结

1. **z-index token 卫生（R3，最高优先）**：三个未定义 token、五处消费、两处无兜底实际失效；正牌 token（`--z-resizer`/`--z-sticky`/`--z-toast`）就在 z-index.css 里，属「名字打错 + 体系失忆」型事故，修复成本低、回归风险高（右键飞出层叠序、拖拽 ghost 层级）。建议一次性收编并让 style-contract 测试覆盖「消费的 z token 必须有定义」。
2. **会话行键盘焦点不可见（R2+B4）**：最高频交互面 + 完整键盘协议 + 零视觉反馈，违反 §13 可见性底线；与重命名输入框一并补 `:focus-visible`（走 `--focus-ring` 家族即可与导航项/标签页统一）。
3. **关闭键颜色绕过 token（R1）**：一行改动，删裸 hex 换 `--window-close-bg/-fg`。
4. **hover 双轨与选中双语言（Y1/Y7）**：light 主题同屏两种 hover 色相、「会话入口」两侧四项基础规格全分叉。建议先立规则（侧栏面一律 `--sidebar-*`；workspace 面一律 `--tint-*`；tab 与行建立字号/圆角的推导映射），再决定是否合并配方。
