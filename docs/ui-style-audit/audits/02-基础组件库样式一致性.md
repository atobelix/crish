# 02 · 基础组件库样式一致性审计（A2）

> 审计范围：`apps/crish-desktop/src/components/ui/` 全部原子件（Badge / Button(+IconButton) / ConfirmDialog / Dialog / Input / Textarea / Menu / SegmentedControl / Select / Slider / SmartExpandablePanel / Switch / TabStrip / Tooltip）。
> 判据：仓库根 `AGENTS.md` §12（Tooltip）、§13（输入框焦点态）、§14（色彩空间与现代 CSS 语法）；token 真源 `apps/crish-desktop/src/styles/tokens.css`。
> 方法：只读代码（.css/.tsx/.ts），全量模式扫描（hex / rgba / var() 悬空引用 / z-index / 魔法 px）+ 逐组件对照。审计日期：2026-08-21。

---

## ① 总评

**结论先行：核心交互六件套（Button / IconButton / Input / Textarea / Switch / Slider / SegmentedControl / Badge）纪律性优秀；弹层家族（Dialog / Menu / Select / SmartExpandablePanel）是全部主要漂移的聚集地；Tooltip 作为 §12 规范载体自身不达标。**

分维度概览：

| 维度 | 评价 |
| --- | --- |
| 1. 组件间规格互比 | **两套设计系统并存**：主 token 族（7px 按钮锁 / 4 档 24-28-32-40 高度）与 SEP `--sep-*` 族（14px 外径 / 6px 内衬 / 28px 条目）。Select、Menu 已整体迁到 SEP 规格，Dialog 又是第三个圆角刻度（16px），互比失配集中在弹层。 |
| 2. 焦点态合规（§13） | **比率合规、机制不统一**：所有焦点混入均 ≤10%、无深黑实线、默认无重阴影——§13 红线零违反。但存在三种焦点语言（1.5px ring / 2px ring / 纯背景色），且 tokens.css:111-120 专门定义的 `--focus-ring-subtle` / `--focus-ring-strong` 在 ui/ 内 **0 消费者**，各组件内联手抄同一 color-mix 公式。 |
| 3. 颜色 token 化率 | 六件套 100%（0 裸 hex/rgba）；违规集中在 Dialog（1 hex + 3 rgba）、Menu（~12 rgba）、Select（~15 rgba + 2 hex）、SEP（1 组裸 rgba 阴影）。 |
| 4. 尺寸 token 化 | 高度刻度普遍硬编码 px（24/28/32/40），不消费 `--control-height-*`；后果是 UI size gear 对 Button/Input/SegmentedControl 失效、对 Select 生效，混排时高度失配；lg 档 40px 与全局 `--control-height-lg: 36px` 直接冲突。 |
| 5. Tooltip 质量（§12） | 柔和阴影 ✓、主题色一致 ✓；**圆角胶囊 ✗**（实际 4px 小圆角矩形，依赖的 `--radius-tooltip` token 全仓未定义）。 |
| 6. 现代 CSS / 暗色 / z-index | color-mix / `:has()` / `field-sizing` 使用现代 ✓；旧式 `rgba()` 约 30 处待收敛（§14）；**Dialog 暗色主题整体失效（硬编码白底）**；z-index 来源基本走 token，唯 `--z-dropdown-menu` 为悬空引用。 |
| 7. 边缘状态 | Button loading/disabled/active、Input error/clearable/password、Select error/disabled、Switch/Slider disabled 均完备；缺口：Badge 移除钮与 Input 行内动作钮无 `:focus-visible`、Select 无 loading 态、Input readOnly 无视觉区分。 |

## ③ 问题清单

### 🔴 违规（违反 AGENTS.md 判据或功能性缺陷）

1. **Dialog 暗色主题整体失效**：`Dialog.module.css:31` 面板背景硬编码 `background: #ffffff`，全文件无任何 `html[data-theme='dark']` 覆盖；`:17` 遮罩 `rgba(0,0,0,0.04)`、`:34` 阴影同为裸值。暗色主题下所有基于 ui/Dialog 的弹窗（含 ConfirmDialog）将呈现刺眼白色面板。应改 `var(--bg-elevated)` / `var(--shadow-lg)` / `var(--tint-overlay)`。
2. **Tooltip 违反 §12「圆角胶囊」**：`Tooltip.module.css:48` `border-radius: var(--radius-tooltip, var(--radius-sm, 4px))`——`--radius-tooltip` 在 tokens.css 及全仓**无定义**（悬空引用），实际渲染 4px 微圆角矩形而非胶囊。§12 明文要求自定义 Tooltip 提供「圆角胶囊、柔和阴影」。柔和阴影（`--shadow-lg`，:49）与主题色（:46-47）两项达标。
3. **ui 库内部使用原生 `title` 作悬停提示（§12 禁令）**：`SmartExpandablePanel/SmartPanelHeader.tsx:44` 搜索清空按钮 `title="清空搜索"`（与 ：45 `aria-label` 并存）。§12 要求一律用项目 `<Tooltip>` 组件包裹，禁用原生 title 气泡。
4. **`--z-dropdown-menu` 悬空引用**：`SmartExpandablePanel.module.css:23` 与 `:354` 引用的该 token 在 tokens.css / z-index.css 中**不存在**（实际定义名为 `--z-dropdown`，tokens.css:451），恒走 fallback 300/310。一旦 `--z-dropdown` 层级调整，SEP 面板与其子菜单不会跟随，属层级来源失控。

### 🟡 漂移（同族组件间规格失配 / token 体系绕过）

5. **Input 与 Textarea 圆角失配**：`Input.module.css:30` 用 `var(--button-radius, 7px)`，`Textarea.module.css:41` 用 `var(--radius-md, 6px)`——同屏并排的输入族一个 7px 一个 6px，视觉可感知。
6. **弹层阴影三套规格并存**：Menu 双层（`Menu.module.css:33-34`）、Select 单层（`Select.module.css:108`）、SEP 主面板又一套（`SmartExpandablePanel.module.css:17`，`0 16px 36px -6px`）；而 tokens.css:173-175 已提供统一 `--sep-shadow`，全家族只有 SEP 子菜单（:349）在用。Menu/Select/SEP 主面板应统一收编到 `--sep-shadow`。
7. **弹层圆角三个刻度**：Dialog 16px（:33）/ Menu·Select·SEP 14px / `--dropdown-radius` token（= `--radius-lg` 8px，tokens.css:399）无人使用。`[data-ui-size]` 档位还会把 `--dropdown-radius` 改写为 10px/14px（tokens.css:883,:959），但 Menu/Select 硬编码 14px 完全不受档位控制。
8. **焦点环 token 绕过（ui/ 内 0 消费者）**：tokens.css:111-120 专门定义 `--focus-ring-subtle`（border 94%/text 6%）与 `--focus-ring-strong`（90%/10%），而 Button.module.css:74-75、Input.module.css:55-56、Textarea.module.css:58-59、Switch.module.css:56-57、Slider.module.css:80-81、SegmentedControl.module.css:120-121、Dialog.module.css:173-174 全部内联重抄同一 color-mix 公式。数值当前一致，但 token 一旦调整（如 §13 收紧到 5%），七个文件不会跟随。附带发现：`--focus-ring-strong` 在 light 主题是**颜色值**（tokens.css:116-120）、在 dark 主题却是**box-shadow 值**（tokens.css:679-680），类型跨主题翻转，任何消费者都无法安全使用——token 层自身缺陷。
9. **Select 触发器焦点样式独树一帜**：`Select.module.css:49` 用 `0 0 0 2px var(--tint-focus-ring)`（几何 2px、不改 border-color），与家族 A 型（1.5px + border 双通道）不一致；且 `--tint-focus-ring` 是 10% 混入（tokens.css:38），处于 §13 上限，观感比兄弟组件更重。
10. **尺寸档与全局 control-height 脱钩**：Button（Button.module.css:10,:86-116）与 Input（Input.module.css:26-27,:66-91）四档高度硬编码 24/28/32/40，不消费 `--control-height-xs/sm/base/lg`（tokens.css:494-497）；lg 档 40px 与全局 `--control-height-lg: 36px` 冲突。Select 触发器反而正确使用 `var(--control-height)`（Select.module.css:23）会随 `[data-ui-size]` 缩放——同一设置行里 Button(恒 32px) 与 Select(small 档 30px) 并排时高度失配，UI size gear 对按钮/输入框整组失效。
11. **旧式 `rgba()` 约 30 处（§14）**：重灾区 Menu.module.css（:53,:58,:89,:94,:99,:103,:164-165）、Select.module.css（:42,:58,:149,:154,:159,:163,:167,:173）、SmartExpandablePanel.module.css（:17,:235,:239 裸值部分）、Dialog.module.css（:17,:34）。其中大量是 `--sep-bg-item-hover` / `--tint-hover` / `--sep-divider-color` 已有 token 的手写复制，且靠 `:global(html[data-theme='dark'])` 再手抄一遍 dark 值（如 Menu:93-95 vs tokens.css:708-709 已有同值 dark token）——双重冗余，应删覆盖直用 token。
12. **Select 勾选图标硬编码品牌色**：`Select.module.css:213` `color: #059669`、`:217` `color: #10b981`——tokens.css:128-130 已有 `--brand-primary` / `--brand-deep`，属无谓绕过。
13. **禁用透明度三种口径**：token `--opacity-disabled: 0.5`（tokens.css:486）；Button/Input/Textarea/Switch/SegmentedControl/Slider fallback 写 0.45（如 Button.module.css:80）；SEP 直接硬编码 `opacity: 0.45` 不走 var（SmartExpandablePanel.module.css:243）；Menu fallback 又写 0.5（Menu.module.css:109）。fallback 与真值不一致是潜伏漂移。
14. **Badge 移除钮与 Input 行内动作钮缺 `:focus-visible`**：Badge.module.css:123-143（`.removeButton` 仅 hover）、Input.module.css:140-193（`.inputAction` 仅 hover）——键盘聚焦时回落浏览器默认蓝色 outline，与全系统自定义柔焦环冲突（§13 精神：焦点变化须可见但须受控）。
15. **同文件双口径示例**：Menu.module.css:53 `menuTitle` 分隔线硬编码 `rgba(29, 28, 26, 0.06)`，同文件 ：144 `separator` 却正确使用 `var(--sep-divider-color)`。
16. **Menu z-index fallback 自相矛盾**：Menu.module.css:7 fallback 300、:11 fallback 100（同一 `--z-dropdown` 两个 fallback 值；token 存在时无害，纯属 sloppy）。
17. **Button primary 边框硬编码黑混合**：Button.module.css:129 `color-mix(in srgb, var(--accent-color) 80%, black 20%)`——`black` 应走 `--shadow-color` 或既有 `--brand-deep`。
18. **Tooltip 细节魔法数**：Tooltip.module.css:50 `padding: 6px 12px`（对应 `--space-1_5`/`--space-3`）、:69 `font-size: 11px`（对应 `--font-size-xxs`）。
19. **死代码/死引用一组**：Badge.tsx:72 引用未定义的 `styles.badgeInteractive`；Textarea.tsx:104-105 引用未定义的 `textareaWrapSm/Lg`；Input.tsx:199 引用未定义的 `inputWrapDisabled`；Tooltip.module.css:74-76 与 ：85-87 的 dark 覆盖与基础规则（:46,:82）完全同值，是 no-op 死代码。
20. **SEP 主面板 token 族混搭**：SmartExpandablePanel.module.css:13 `var(--bg-card, hsl(35 10% 98%))`——主 token 名配 SEP 色系 fallback，语义混乱（dark 下靠 `--bg-card` 正确翻转，功能无损，但 fallback 误导阅读者）。

### 🔵 建议

21. **TabStrip 基座补默认焦点态或在契约中声明**：TabStrip.module.css 全文仅 `.tabLabel`（9 行），tab 的 `:focus-visible` 完全依赖消费方传入 `tabClassName`；建议基座提供一层可被覆盖的默认柔焦环，防止新消费方遗漏键盘可见性。
22. **SEP 内嵌 badge 与 ui/Badge 收编**：SEP:304-311 的 badge（fs 10px / padding 1px 5px）与 ui/Badge（h≥18px / fs≥11px）是两套并行徽标规格；建议 SEP 复用 ui/Badge xs 档或对齐刻度，避免「badge」一词双义。
23. **Select 补 loading（异步选项）边缘态**；Input 补 readOnly 视觉区分（当前仅语义禁写，外观与常态无异）。
24. **Slider 轨道色与 Switch 轨道同源**：Slider.module.css:41 用 `--border-color` 原色，Switch 用专用 `--switch-track-bg`；可考虑统一到「轨道族」token（如 `--tint-divider`）让两个线性控件质感一致。
25. **Dialog backdrop blur(1.5px) 可 token 化**（Dialog.module.css:18），避免下一个弹层再抄一个私有模糊值。
26. **清理 Menu 调试描边的硬编码品牌色**（Menu.module.css:164-165 `rgba(16,185,129,…)`），debug 视觉亦可走 `--brand` 系 token。

## ④ Top 问题小结

1. **Dialog 暗色白板（🔴#1）**——唯一的功能性视觉缺陷，用户可直接看到；修复成本低（3 个值换 token），收益最高，建议最优先。
2. **Tooltip 非胶囊 + `--radius-tooltip` 悬空（🔴#2）**——§12 的规范载体自身不达标，且暴露「组件注释宣称 100% token 化、实际依赖不存在 token」的验证缺口；与 🔴#4（`--z-dropdown-menu`）、🟡#8（焦点环 token 0 消费）同属一类病根：**token 悬空/绕过没有门禁拦截**。建议建立 var() 引用-vs-tokens.css 定义的静态校验。
3. **弹层家族三套规格（🟡#5/#6/#7）**——圆角 16/14/8、阴影三套、padding 各写各的；`--sep-shadow`、`--dropdown-radius`、`--sep-padding` 三个现成 token 无人认领。收编动作集中且机械。
4. **焦点语言三分 + token 绕过（🟡#8/#9 + C 型清单）**——§13 比率红线全部合规（这是好的一面），但七处内联手抄公式使未来收紧阈值变成七文件联动改造；先落 `--focus-ring-subtle/strong` 消费，再谈统一 C 型背景式焦点的对比度。
5. **尺寸档脱钩（🟡#10）**——UI size gear 对按钮/输入框静默失效、lg 档 40 vs 36 冲突，属于「看起来正常、档位切换才露馅」的隐性回归面；建议 Button/Input 高度改挂 `--control-height-*` 并让 lg 档二选一对齐。
