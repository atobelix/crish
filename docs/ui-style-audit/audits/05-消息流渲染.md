## ① 总评

**结论：token 化基础面良好，但「悬空引用」是本链路最大系统性风险，共发现三类共 18 个悬空变量，其中 1 处已构成浅色主题功能性缺陷。**

分维度评价：

1. **颜色 token 化率**：主色/文字/边框/hover 高度走 `var()`，`color-mix()` 现代语法普及率高，整体 token 化率约 90%+。但存在三类悬空引用：
   - **主题定义不对称**：`--accent-green-light-adaptive` / `--accent-red-light-adaptive` 仅在 tokens.css 的 dark 块定义（tokens.css:747-756），FileViewerCard 无 fallback 直接引用 → 浅色主题下增删行背景计算无效退化为透明（🔴-1）。
   - **从未定义**：`--flow-*` 家族 9 个变量、`--tint-subtle`、`--bg-surface` / `--bg-surface-subtle`、`--accent-amber`、`--brand-line` 全仓无定义点，思考链视觉体系实际完全跑在 fallback 硬编码上（🟡-4）。
   - **z-index 未注册家族**：5 个 z-index 变量在两份真源中均不存在（🔴-2）。
2. **代码块 token 族**：`--md-code-*` 族在审计域内仅 DiffCard gutter 一处使用（DiffCard.module.css:790）；ChatToolCallBlock 全部代码输出区绕开该族，改用悬空的 `--bg-surface` 或透明底（🟡-6）。
3. **消息行规格体系**：区分度策略清晰——用户右对齐气泡 / 助手扁平无泡流 / 工具透明行+缩进结果体；但圆角与间距未收敛到 token 阶梯（14px 硬编码 vs radius-xl 12px vs radius-lg 8px），用户气泡 padding 绕过既有 space token（🟡-10、🟡-15）。
4. **思考链层级**：内联态（缩进+meta 字号+渐隐）与 Modal 态（mono 行号+标题色）信息层级成立，但支撑它的 `--flow-*` token 全部悬空；同组件两个渐隐用不同页面底色 token，必有一处与真实背景错色（🟡-7）。
5. **DiffCard 配色**：主链路有专用 `--diff-*` 族且 dark 有独立提亮 fg，可读性有保障；但全链路并存**三套 diff 配色系统**，其中 ChatToolCallBlock 内嵌 git diff 把 raw accent 色当整行正文色，暗色下 AA 不达标风险（🟡-5）。
6. **焦点态合规**：正面例充分（92/8、90/10 mix 恰在 §13 上限量级内）；问题集中在两处搜索输入框 `outline: none` 无替代指示、一处 focus 边框直接用全值 `--text-tertiary` 超 §13 混入上限（🟡-13）。
7. **Tooltip 合规**：CacheMetricsBadge / FlowScrubber / FullThoughtModal / ChatUserMessageRow 均正确使用自定义 `<Tooltip>`；仅 ModelBadgePickerMenu 设置按钮残留原生 `title`（🔴-3）。
8. **§14 现代语法**：散落 raw `rgba()` 约 12 处（非 fallback 位），另有暗色下不可见的硬编码黑滚动条（🟡-11、🟡-12）。
9. **z-index 层级**：FlowScrubber 用 `--z-dock(10)` 正确；Modal 由 Dialog 承载；但 FilesCard 卡内浮层层级因悬空 token 三种状态并存（500 / auto / auto），层叠关系失控（🔴-2）。
10. **跨组件一致性**：徽章类 5 种规格互不一致（字号 xs/xxs/11px 硬编码三轨）；CacheMetricsBadge 的 hit 与 write 两态因 `--accent-green` 与 `--accent-primary` 同值而视觉不可分（🟡-8、🟡-9）。

## ③ 问题清单

### 🔴 违规 / 功能性缺陷

**🔴-1 浅色主题下 FileViewerCard diff 增删行高亮完全失效**
`--accent-green-light-adaptive` / `--accent-red-light-adaptive` 仅在 `html[data-theme='dark']` 块定义（tokens.css:747-756），light 块无定义；FileViewerCard 引用时**无 fallback**（FileViewerCard.module.css:263,268,272,277）→ light 主题属性计算无效退化为 transparent，增删行底色消失。对照：DiffCard 同类用法带 fallback（DiffCard.module.css:662-668,988-991）。修复方向：token 补 light 定义，或引用处补 fallback。

**🔴-2 z-index 悬空引用家族（5 变量 7 处），卡内浮层层级失控**
以下变量在 tokens.css 与 z-index.css 均未定义，且部分无 fallback → 计算无效退回 `auto`：
- `--z-pinned-bar`：ChatMessageList.module.css:42（置顶条 sticky 层失效）；FileTreeView.tsx:214（内联 zIndex）
- `--z-card-footer`：FilesCard.module.css:48,95,1104
- `--z-breadcrumb`：FilesCard.module.css:332（面包屑 flyout）
- `--z-dropdown-menu`：FilesCard.module.css:696（**无 fallback**）；ModelBadgePickerMenu.module.css:27（有 `var(--z-dropdown)` 兜底）
- `--z-decorative`：ChatToolCallBlock.module.css:355

后果：同一张 FilesCard 内 `filesMoreMenu`=500（--z-popover）、`filesOpenMenu`=auto、`filesBcFlyout`=auto，三者互相重叠时层叠顺序由 DOM 序决定，与设计意图不符；置顶条与 scrubber（--z-dock=10）的压盖关系同样失守。修复方向：在 z-index.css 注册或统一改用既有档位。

**🔴-3 原生 `title` 作主悬停提示（违反 §12）**
ModelBadgePickerMenu.tsx:180：设置按钮 `title="模型管理..."`。虽另有 sr-only span 兜底可访问性，但 hover 主提示仍走浏览器原生气泡。应改为 `<Tooltip content="模型管理...">` 包裹。域内其余组件（CacheMetricsBadge.tsx:36,79,105、FlowScrubber.tsx:53、FullThoughtModal.tsx:189,200,211、ChatUserMessageRow.tsx:134）均为自定义 Tooltip ✅；AppErrorBoundary/Dialog 的 `title` 为组件 prop 非 DOM attribute，不属违规。

### 🟡 漂移

**🟡-4 `--flow-*` token 家族整体悬空（9 变量），思考链视觉跑在 fallback 上**
`--flow-summary-indent` / `--flow-font-meta` / `--flow-meta` / `--flow-meta-hover` / `--flow-meta-soft` / `--flow-chevron-color` / `--flow-chevron-hover` / `--flow-thinking-max-h` / `--flow-font-plan-title` 全仓无定义点（CSS/TS 均查证，TS 侧仅注入过无关的 `--flow-output-max`）。证据：ChatMessageRow.module.css:481,499,501,512,605,613,674,711,716,718,866,915,934,936,988,989,1020。后果：思考链字号/缩进/颜色的「可调 token 面」不存在，实际全部吃 fallback 字面量；后续想全局调 meta 字号或缩进必须逐行改 CSS。同类悬空还有 `--tint-subtle`（ChatMessageRow.module.css:74）、`--bg-surface`/`--bg-surface-subtle`（ChatToolCallBlock.module.css:339,362,384,531-535；ModelBadgePickerMenu.module.css:236）、`--accent-amber`（ChatToolCallBlock.module.css:416,610）、`--brand-line`（ChatMessageRow.module.css:966）。

**🟡-5 三套 diff 配色系统并存；ChatToolCallBlock 内嵌 git diff 正文对比度不足**
- 系统 A（规范样板）：DiffCard 用专用族 `--diff-line-add-bg` / `--diff-gutter-add-fg` 等，dark 有独立提亮 fg（DiffCard.module.css:815-853；tokens.css:457-475,854-872）✅
- 系统 B：ChatToolCallBlock `.gitDiffLineRow.addition/.deletion` 用 `--accent-green-light`/`--accent-red-light` 作行底、raw `--accent-green`/`--accent-red` 作**整行正文色**（ChatToolCallBlock.module.css:893-938）。tokens.css:238-243 注释自证 raw accent 作文字色不满足 AA 才引入 `--text-success-strong` 等变体；dark 下 accent-green hsl(142,35%,42%)（tokens.css:739，与 light 同值）铺在 hsl(142,35%,16%) 底上，正文可读性存疑。
- 系统 C：FileViewerCard 用 `--accent-*-light-adaptive`（见 🔴-1）。
建议收敛到 A 族（`--diff-*` 已覆盖 line/gutter/word 三层语义）。

**🟡-6 代码块组件未走 `--md-code-*` token 族**
`--md-code-bg/border/fg` 双主题均有定义（tokens.css:97-104,642-644），但审计域内唯一使用点是 DiffCard gutterNum（DiffCard.module.css:790）。ChatToolCallBlock 的 `.toolSectionContent` / `.toolOutputCode` / `.toolInputCode` / `.toolValPre` / `.toolResultPreCmd` 等代码呈现区全部绕开该族，用悬空 `--bg-surface` 或纯透明底（ChatToolCallBlock.module.css:452-458,550-561,528-542,479-486）。工具输出即代码块语境，应消费 md-code 族以获得双主题一致的代码底/边/字。

**🟡-7 同组件两个渐隐用了不同页面底色 token，必有一处错色**
`.thinkingBodyContainer::before/::after` 渐变基于 `--bg-page`（ChatMessageRow.module.css:692-708），`.thinkingFadeOverlay` 渐变基于 `--bg-primary`（:730-735）。两 token 实际值不同（light：#ffffff vs #f4f5f7；dark：#0c0c0b vs hsl(0,0%,5%)，tokens.css:122-123,598,682）。同一视觉位置的上/下淡出与悬浮淡出若底色选择不一致，其中一处必然与真实聊天背景产生可见色差。需确认消息流真实 backdrop 后统一。

**🟡-8 徽章规格漂移（详见 §2.3 表）**
五种徽章字号/内边距/圆角/彩色方案互不一致；`11px`、`999px` 等字面量绕过既有 `--font-size-xxs`、`--radius-full`。证据汇总见 §2.3。

**🟡-9 CacheMetricsBadge hit/write 两态视觉塌陷**
`--accent-green` 与 `--accent-primary` 在 light/dark 均为同值 #10b981（tokens.css:128-130,688-690）；`.hit`（CacheMetricsBadge.module.css:17-22）与 `.write`（:24-33）用同构的 12%/25% color-mix → 「命中」与「写入」两种语义渲染出几乎相同的绿色胶囊，四态语义模型（含 miss 灰态）观感退化为两态。建议 write 态换独立语义色（如 `--color-warning` 系）或改变形态（描边/实心区分）。

**🟡-10 圆角阶梯混乱 + fallback 值与 token 实际值系统性不符**
同一层级容器分别取 14px 硬编码（用户气泡，ChatMessageRow.module.css:65；该值恰等于 `--sep-radius-outer` 却未引用）、radius-xl 12（toolRow）、radius-lg 8（accordionItem）、radius-md 6（thoughtModalBody）。同时大量 fallback 字面量与 token 现值不符，形成误导：`var(--radius-xl, 10px)`（ChatToolCallBlock.module.css:340，实际 12）、`var(--radius-md, 8px)`（FullThoughtModal.module.css:47，实际 6）、`var(--radius-sm, 6px)`（FilesCard.module.css:56，实际 4）。fallback 本不生效，但会在 token 改名/删除时静默注入错误值，且误导维护者对现值的认知。

**🟡-11 §14 raw `rgba()` 残留（非 fallback 位）约 12 处**
ChatMessageRow.module.css:838（`box-shadow: … rgba(0,0,0,0.03)`）；DiffCard.module.css:249,1463；FileViewerCard.module.css:66；ModelBadgePickerMenu.module.css:10（双段阴影）,107,125-131（滚动条四连 !important）,266（activePill 双段阴影）。§14 要求优先 `hsl(h s l / a)` 斜杠透明度；阴影基色应走 `--shadow-color` + color-mix（tokens.css:260-261 已有基建）。

**🟡-12 ModelBadgePickerMenu 暗色适配缺陷**
滚动条 thumb/track 硬编码 `rgba(0,0,0,0.18/0.3)`（ModelBadgePickerMenu.module.css:107,125-131）→ dark 主题深底上近不可见；mbMenu 阴影硬编码 rgba 黑（:10）而非主题化 `--shadow-lg/--shadow-2xl`（tokens.css:339-351,805-817 双主题现成）。另 `.thinkingPill.activePill` 阴影 rgba 硬编码（:266）。

**🟡-13 焦点态问题三点（对照 §13）**
- ThoughtSearchBar `.searchInput` `outline: none` 且容器无 `:focus-within` 替代指示（ThoughtSearchBar.module.css:16-24）→ 键盘焦点不可见；
- ModelBadgePickerMenu `.searchInput` 同样裸 `outline: none`（ModelBadgePickerMenu.module.css:61-71）；
- FilesCard `.filesSelForm input:focus` 边框直接切到全值 `--text-tertiary`（FilesCard.module.css:1152-1155），相对 `--border-color` 是一次大幅加深，超出 §13「混入文本色 ≤10%、常规 3–6%」上限量级。
正面合规样例（供对齐）：DiffCard `.commitInput:focus` 92/8 mix（DiffCard.module.css:724-731）、`.accordionActive` 90/10（:506-512）、ChatToolCallBlock 结果体边框 92/8（ChatToolCallBlock.module.css:341-346）。

**🟡-14 `--accent-blue` 语义漂移：Zero-Blue 收敛后仍被当「信息蓝」引用**
`--accent-blue` 已收敛为墨绿 #065f46/#34d399（tokens.css:198,758），但 DiffCard `.lineHeader` 背景/序号槽（DiffCard.module.css:860-867）与 `.fileNameLink:hover`（:918）、ChatToolCallBlock `.toolSectionBadgeOutput`（ChatToolCallBlock.module.css:406）仍引用它表达「diff 头/链接/OUTPUT 标签」的信息色语义 → 实际渲染为绿系，与相邻 success 绿难以区分。应迁移到 `--color-info`（其本就指向 `--accent-blue`，语义等价但命名不再说谎）或中性灰阶。

**🟡-15 用户气泡规格硬编码 + 悬空阴影 token**
`border-radius: 14px 14px 4px 14px`、`padding: 10px 14px` 均为字面量（ChatMessageRow.module.css:65-66），未消费 `--sep-radius-outer`(14)/`--space-2_5`/`--space-3_5`；`box-shadow` 引用从未定义的 `--tint-subtle`（:74，见 🟡-4）。作为消息流中唯一的实心气泡，其规格应完全 token 化以便密度档位联动。

### 🔵 建议

**🔵-16 过时蓝色 fallback 群清理**
Zero-Blue 前的 `#0288d1` / `#38bdf8` / `#3b82f6` / `#c45c5c` 等 fallback 永不生效但持续误导：ThoughtOutline.module.css:80-83,96；FullThoughtModal.module.css:17,88；CacheMetricsBadge.module.css:25,32；DiffCard.module.css:486；ToolCallHeader.tsx:157。建议随下次触碰顺手清为中性或现行值。

**🔵-17 死代码：`.toolResultBody > *` 的 z-index 提升**
ChatToolCallBlock.module.css:353-356 用悬空 `--z-decorative` 抬升子元素，但该容器并无 `::before` 装饰层可避让，规则整体（含悬空引用）可删。

**🔵-18 中文注释乱码（历史编码事故痕迹）**
ChatMessageRow.module.css:6（`/*      ?token  ?720/680px  ?*/`）及 tokens.css 多处注释呈问号乱码。不影响运行但损害可维护性，建议按 chinese-encoding-guard 流程批量修复。

**🔵-19 FlowScrubber 刻度按钮缺 `:focus-visible` 样式**
FlowScrubber.module.css:53-109 的 `.tick` 为 `<button>` 但未定义键盘焦点态，仅靠 UA 默认 outline，与域内其他自定义 `--focus-ring` 风格不一（对照 ChatMessageRow.module.css:228-236）。建议补 `box-shadow: var(--focus-ring)`。

**🔵-20 Tooltip 内容板字号硬编码**
