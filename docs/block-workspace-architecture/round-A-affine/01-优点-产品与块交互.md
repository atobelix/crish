# AFFiNE 优点：产品与块交互体验

> **调研对象**：`reference/markdown_compare/AFFiNE`  
> **视角**：Notion 皮——块操作、slash/面板、画布/文档融合、阅读写作流  
> **对照标尺**（非抄写目标）：Tauri + TS + RS；Notion 级块交互；性能与体验双双超过参考；多人实时协同；TS 扩展生态；Rust 做重计算/状态沉底  
> **方法**：只读源码与 BlockSuite 文档；每条优点绑定可复核路径  
> **不谈**：工期、人员、业务优先级排序

---

## 1. 优点清单

### 1.1 文档与画布同一份块树，双编辑器切换而非两套数据

**现象**：用户可在「页面文档」与「无边界画布（edgeless）」间切换；二者共享同一文档状态，画布上的 note 里仍是完整富文本块，不是截图式副本。产品叙事明确「Docs and whiteboard are now fully merged」。

**证据**：

- 产品定位：`reference/markdown_compare/AFFiNE/README.md`（“Docs, canvas and tables are hyper-merged”“A true canvas for blocks in any form”）
- 框架动机与双编辑器：`blocksuite/docs-site/guide/overview.md`（`PageEditor` / `EdgelessEditor` 共用富文本能力；多模态同一数据源）
- 应用壳按 `DocMode` 挂载 page 或 edgeless 编辑器，同一 `Store`：`packages/frontend/core/src/blocksuite/block-suite-editor/blocksuite-editor.tsx`

---

### 1.2 Note 是「文档段落容器」与「画布便签」的统一载体，带显示模式

**现象**：内容落在 `affine:note` 容器内；同一 note 可声明仅文档可见、仅画布可见或两者皆见，切换时会调整在兄弟 note 列表中的相对顺序，避免「edgeless-only 笔记」污染文档阅读流。

**证据**：

- 显示模式枚举：`blocksuite/affine/model/src/consts/note.ts`（`NoteDisplayMode`: `both` / `doc` / `edgeless`）
- 改显示模式时重排 note：`blocksuite/affine/blocks/note/src/commands/change-note-display-mode.ts`
- 画布态 note 可折叠/展开、选中时露出溢出内容：`blocksuite/affine/blocks/note/src/note-edgeless-block.ts`

---

### 1.3 Slash 菜单：输入触发 + 分块扩展配置 + 分组动作

**现象**：输入 `/` 在当前行弹出命令面板；可转标题/列表/代码、对齐、样式，以及上移/下移/复制/删除、日期插入等；各块类型可注册自己的 slash 项，最终合并为一张菜单。

**证据**：

- 触发键与 IME 兼容路径（compositionEnd + inlineRange 同步后再判 `/`）：`blocksuite/affine/widgets/slash-menu/src/widget.ts`
- 默认动作（Move Up/Down、日期等）：`blocksuite/affine/widgets/slash-menu/src/config.ts`
- 按 DI 合并多源配置：`blocksuite/affine/widgets/slash-menu/src/extensions.ts`（`SlashMenuConfigExtension` + `mergeSlashMenuConfigs`）
- Note 侧转块/对齐/格式项：`blocksuite/affine/blocks/note/src/configs/slash-menu.ts`
- 表块等亦可挂自己的 slash：`blocksuite/affine/blocks/table/src/configs/slash-menu.ts`、`view.ts`

## 2. 与「块操作」相关的机制素描（选型级）

下列为架构意图素描，不堆接口清单。

### 2.1 三层分离：Store 树 / Std 运行时 / Widget 交互壳

| 层                   | 职责                                        | 产品含义                                 |
| -------------------- | ------------------------------------------- | ---------------------------------------- |
| **Store**            | 块树 CRUD、历史（`captureSync`）、CRDT 持久 | 「改什么」唯一真相；undo/redo 与协同同源 |
| **Std**              | 选区、事件分发、command、块/widget 视图映射 | 「如何选、如何触发」与 UI 框架解耦       |
| **Widgets / Blocks** | slash、drag、toolbar、各 flavour 渲染       | 「Notion 皮」几乎全在此层堆叠            |

文档心智模型见 `blocksuite/docs-site/guide/working-with-block-tree.md`：`host.std` 上暴露 `selection` / `command`；块树经 schema 约束嵌套（page → note → 内容块）。

### 2.2 选区是数据，不是 DOM 副作用

选区以可序列化模型表达（`text` 跨块 from/to、`block` 路径列表、`surface` 画布元素等），分组（group）隔离 note 内选区与表/画布选区。UI（高亮、toolbar、远程光标）**派生**自选区状态，利于协同 awareness 与深链 highlight。

### 2.3 块操作的主路径

```
用户意图（键入 / 拖 / 框选 / slash / 快捷键）
    → 事件进入块树冒泡（event dispatcher）
    → 更新 selection 或解析触发器（如 `/`、markdown 前缀）
    → command 链或 store.add/update/move/delete
    → 视图按 model 重绘；widget 订阅 selection/信号再定位
```

拖放额外走 **Slice 快照 + Transformer 中间件**（跨文档 id、列表重编号、卡片样式），保证「剪贴/拖入」语义一致。

### 2.4 文档-画布融合的结构要点

- **同一 doc**：切换 mode 换编辑器宿主，不换数据源。
- **Note 容器**：文档流 = 可见 note 的纵向排列；画布 = note/图形在 surface 上的几何布局。
- **displayMode**：控制 note 是否进入文档阅读序列。
- **surface-ref / embed-synced-doc**：把「另一视图或另一文档」嵌回线性阅读，而不是只做外链跳转。
- **Note slicer / drag from gfx|block**：在空间与结构两种编辑范式间来回改同一模型。

### 2.5 扩展面：配置注册而非改核心

- Slash / Toolbar / Keyboard toolbar 均以 **Config Extension + DI 合并** 扩展。
- 新块通过 schema + view + 可选 slash/toolbar configs 接入。
- Inline 通过 attributes schema 与 markdown matcher 扩展行内语义（链接页、颜色等）。

### 2.6 交互壳清单（产品可见层）

| 交互            | 主要位置                     |
| --------------- | ---------------------------- |
| Slash 面板      | `widgets/slash-menu`         |
| 拖拽把手 / 加块 | `widgets/drag-handle`        |
| 选区工具栏      | `widgets/toolbar`            |
| 页面框选        | `widgets/page-dragging-area` |
| Note 切开       | `widgets/note-slicer`        |

## 3. 对本产品可内化的效果启发

> 只写**目标效果与机制意图**；禁止「照搬 AFFiNE 某 API」。

### 3.1 效果：一份内容，两种主导导航范式

- **线性阅读/写作**与**空间编排**应对同一底层块图切换「投影」，而不是两套互相同步的副本。
- 机制意图：容器块携带「出现在哪些投影」的元数据；切换投影只改宿主与过滤规则。

### 3.2 效果：块操作手感 = 选区类型齐全 + 统一动作出口

- 用户需要至少：行内选区、整块多选、跨块文本选、（若有画布）元素选。
- 同一动作（删除、复制、转类型、对齐）应对所有选区类型有可预期结果，UI 入口可多个（slash / 快捷键 / 悬浮条 / 拖放），**语义表唯一**。
- 机制意图：选区可序列化；动作层（命令/事务）吃选区快照，不吃临时 DOM。

### 3.3 效果：写作快路径与发现路径并存

- **快路径**：markdown 前缀、热键、点空白续写、把手 `+` 加段——不打断心流。
- **发现路径**：slash 分组搜索、空页 starter——降低功能不可发现成本。
- 机制意图：转块配置表一处定义，多入口复用；IME 合成期不误触发。

### 3.4 效果：拖放是一等公民，含预览与跨边界

- 拖时有落点指示与幽灵预览；可在文档内重排、列表内重编号、跨文档粘贴时身份重生。
- 机制意图：拖放载体是块切片快照 + 中间件管道，而非仅 DOM reorder。

### 3.5 效果：画布能力「回灌」文档流

- 用户应能在文档中**看到**画布片段或嵌套页，而不总是跳走；预览可 Peek，需要时再进全屏编辑。
- 机制意图：引用/嵌入块指向稳定 id；阅读态与编辑态权限可分级。

### 3.6 效果：协同可见但不抢焦

- 他人选区/光标实时可见、色彩稳定；本地拖选与键入不被遮挡层截获。
- 深链/评论定位应有短暂高亮与滚动锚定（page 与画布坐标转换规则清晰）。

### 3.7 效果：移动端不降级成「纯 textarea」

- 软键盘场景仍能改块类型与格式；工具条避让视口。
- 机制意图：编辑激活信号驱动工具条；虚拟键盘抽象可替换。

### 3.8 效果：扩展生态挂在「配置合并点」

- 第三方块应能贡献 slash 项、工具栏段、快捷键与行内属性，而不 fork 宿主。
- 机制意图：TS 侧扩展注册表 + 内核（Rust）只认稳定的块图/选区/事务协议。

### 3.9 与本产品栈的对齐提示（非实现方案）

| 效果域                         | 可沉到底座（RS）的意图 | 宜留在 TS/UI 的意图 |
| ------------------------------ | ---------------------- | ------------------- |
| 块图事务、选区归并、协同 diff  | 正确性与性能           | —                   |
| slash 布局、动画、拖拽预览 DOM | —                      | 高频迭代的皮        |
| 命令语义表                     | 可校验的动作契约       | 绑定具体 UI 触发    |
| markdown 前缀规则              | 规则表可下沉           | IME/浏览器事件细节  |

## 4. 不确定处

1. **运行时手感未实测**：本报告基于本地源码与 guide 文档，未在本环境启动 AFFiNE 客户端做交互录屏；动画时序、大文档掉帧、协同冲突表现需另轮实测。
2. **文档与 monorepo 包名漂移**：guide 仍写 `@blocksuite/block-std` / `@blocksuite/lit` 等历史名，当前树以 `blocksuite/framework/std`、`affine/*` 为准；机制仍成立，包路径以仓库现状为准。
3. **slash 默认项是否含全部块类型**：`defaultSlashMenuConfig` 偏「日期与行操作」；大量转块项来自各 block 的 `SlashMenuConfigExtension` 合并结果——完整菜单以运行时 DI 合并后为准，本文未枚举全量。
4. **Database / Table 多视图的「产品叙事」强度**：README 强调 tables hyper-merged，块与 data-view 包体量大，但其「块交互」细节（行选、看板拖）未在本轮逐文件展开。
5. **AI 伴侣**：README 大力宣传 multimodal AI；与块插入流的接线在 `packages/frontend/core` AI 模块，未作块操作主证据链。
6. **BlockHub 等历史入口**：仓库中以 drag-handle `+`、slash、starter-bar 为主路径；是否仍保留独立 block-hub 面板需再搜产品分支/feature flag，本轮不断言。
