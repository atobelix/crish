# AFFiNE / BlockSuite：性能、内存、大文档与桌面壳 — 缺点与风险

> **范围**：`reference/markdown_compare/AFFiNE`（v0.27.0 镜像）
> **立场**：从架构与源码线索推断瓶颈与风险；**无基准数据处一律标「推断」**；禁止无依据的「一定卡」。
> **对照**：本产品栈固定 **Tauri + TS + RS**；目标 **性能与体验双双超过** AFFiNE/BlockSuite（效果锁）。
> **姊妹文**：工程复杂度见 `04-缺点-复杂度与工程DX.md`。

## 0. 结论先行

| 维度          | 架构事实（有代码）                                                                            | 风险定性                                                              |
| ------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Page 文档渲染 | 根与 note **全量子树 Lit 挂载**，未见文档级虚拟列表                                           | 十万级块/行时 DOM + 每块 CE 成本主导（**推断**量级）                  |
| Edgeless 视口 | 有网格索引 + 视口内外 `idle/active/survival` 显隐；桌面默认 **无 overscan、无 low-zoom park** | 大画布靠 culling 减可见层，但 **模型/Yjs/视图注册仍全量**（**推断**） |
| Turbo 位图    | Worker 位图加速存在，**默认关**（实验旗）                                                     | 未开时远距离缩放仍走 DOM 路径；开后交互仍回落 DOM                     |
| 编辑热路径    | 每段 `InlineEditor`：Y.Text → Lit `render` 整段行树；IME 可触发整编辑器重建                   | 长段落 + 高频输入/协同写的主线程压力（**推断**）                      |
| 协同光标      | Awareness + 远程选区 widget：`getClientRects` + throttle 60ms + blockUpdated 全量重算         | 多光标时布局读放大（**推断**）                                        |
| 数据层        | **Yjs 在 JS 堆**；UndoManager 跟踪 `yBlocks`                                                  | 大文档驻留、历史膨胀、GC 压力在 V8（**推断**）                        |
| 桌面壳        | **Electron 39** + helper UtilityProcess + 隐藏 BrowserWindow worker                           | 多 Chromium 进程基线内存与 IPC 税相对 Tauri 更高（**推断**量级）      |
| 内存红线证据  | 视口/Canvas 注释与 iOS 路径明确写了 jetsam、compositing budget、chunked hide                  | 团队已用「生存模式」补救；桌面默认路径仍偏「全量 composited DOM」     |

**一句话**：BlockSuite 在 **白板视口** 上做了认真的 culling / canvas 分层 / 可选 turbo；在 **长文档 Page 模式、内联编辑热路径、Yjs 同进程、Electron 多进程** 上仍是典型「浏览器编辑器上限」结构——本产品要用 **Rust 扛重 + Tauri 壳 + 真正的文档虚拟化/分页** 正面打穿，而不是在同一层再堆 feature flag。

## 1. 风险清单

图例：**证据** = 源码/配置直接可复核；**推断** = 由架构推出的量级/体验风险，未经本仓基准测量。

| ID  | 风险                                     | 证据要点                                                                                                                                                                       | 类型                               | 对本产品的含义                                                                                       |
| --- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- | ---------------------------------------------------------------------------------------------------- |
| R1  | **Page 模式无文档级虚拟化**              | `page-root-block` `renderChildren` 过滤后挂全部 note；`note-block` 再 `renderChildren(this.model)`；`EditorHost.renderChildren` = `repeat` 全 children                         | 证据 + **推断**（大文档 DOM 爆炸） | 十万行若映射为数万块，必须 **窗口化挂载**，不能「一块一 CE」全挂                                     |
| R2  | **每块 Lit 自定义元素 + 子树**           | `BlockComponent` extends Lit `ShadowlessElement`；`_renderModel` 为每块实例化 tag + widgets 映射                                                                               | 证据；内存/启动 **推断**           | 块视图应可池化/轻量投影；热路径避免「块 = 完整组件实例」默认                                         |
| R3  | **Inline 热路径整段重绘**                | `RenderService._onYTextChange` → `this.render()`；按 delta chunk 生成 `v-line`/`v-element` 后 `lit` `render` 进 root；catch 分支 `rerenderWholeEditor`（注释：IME 可搞崩 Lit） | 证据；长文卡顿 **推断**            | 输入路径 O(改动) 优先，禁止默认 O(段全文 DOM 重建)；IME 不得整页拆树                                 |
| R4  | **协同远程选区布局读放大**               | `doc-remote-selection`：`getClientRects` / `getBoundingClientRect`；`throttle(..., 60)`；`blockUpdated` 与 `viewportUpdated` 触发更新；多用户 `flatMap` 算 rect                | 证据；N 光标 **推断**              | 远程光标必须 **增量 + 视口裁剪 + 少强制布局**；大 N 时走 canvas/overlay 批绘                         |
| R5  | **Yjs 同进程 CRDT + Undo**               | store 依赖 `yjs`；`HistoryExtension` = `Y.UndoManager([yBlocks])`；inline 与 reactive proxy 绑 Y 结构                                                                          | 证据；大文档内存/GC **推断**       | 重计算与权威文档态应在 **Rust**；前端持投影/窗口，不持「整仓 CRDT 热路径」                           |
| R6  | **Edgeless 可见层优化 ≠ 模型卸载**       | `GfxViewportElement`：`idle` 仅 `visibility:hidden` + contain；low-zoom **park** 需 `SKIP_REFRESH_DURING_GESTURE` + `LOW_ZOOM_GESTURE_ACTIVE_BLOCK_LIMIT>0`（桌面默认 0）      | 证据；桌面大画布 **推断**          | 大画布要 **空间索引 + 真卸载/LOD**，不能只 hidden 仍占 CE 与层                                       |
| R7  | **Canvas 多层 stacking 内存**            | `canvas-renderer`：stacking canvas pool、debug 指标含 `canvasMemoryBytes`；iOS low-zoom 绕过 stacking；`CANVAS_DPR_CAP` 桌面默认空 = 全 DPR                                    | 证据；HiDPI 大视口 **推断**        | 画布预算要硬上限（DPR/层数/像素）；层间穿插用统一合成策略而非无限 canvas                             |
| R8  | **Turbo 默认关闭且交互回落 DOM**         | `enable_turbo_renderer` default `false`（canary 才可配）；`defaultOptions.enableBitmapRendering: false`；zoom 高于阈值或交互 → pending/DOM                                     | 证据                               | 「有加速路径」≠ 默认体验；打赢须 **默认路径** 就快                                                   |
| R9  | **表格虚拟滚动默认关**                   | `enable_table_virtual_scroll: false`；data-view 有 `pc-virtual` 实现                                                                                                           | 证据                               | 数据库大表不能依赖实验旗；默认即 windowed                                                            |

| R11 | **React 壳 + Lit 编辑器双运行时**        | core 同时 `react`/`lit`；`lit-adaper` 桥接；turbo/选区等在 Lit 树                                                                                                              | 证据；桥接帧税 **推断**            | 单一 UI 宿主；扩展协议，不叠第二套调和器                                                             |
| R12 | **Electron 多进程基线**                  | `@affine/electron` electron `^39`；`helper-process` UtilityProcess fork；`worker/pool` 隐藏 `BrowserWindow` 作 worker                                                          | 证据；相对 Tauri RSS **推断**      | 桌面基线内存与冷启动必须按 **单 WebView + Rust 侧车** 设计，禁止再复制 Electron worker 窗            |
| R13 | **手势/视口刷新节流是补救层**            | `VIEWPORT_REFRESH_PIXEL_THRESHOLD=18`、`MAX_INTERVAL=120`；`raf-coalescer`；chunked hide「防 mobile 内存尖峰」                                                                 | 证据                               | 说明全量刷新路径存在；本产品应 **结构性少刷新**，而非只加 throttle                                   |
| R14 | **Grid 默认格子 3000 模型单位**          | `DEFAULT_GRID_SIZE = 3000`                                                                                                                                                     | 证据；极密元素查询 **推断**        | 空间索引粒度需可按元素密度调；避免一格过多元素                                                       |
| R15 | **重型依赖可进编辑邻域**                 | core：mermaid、typst wasm、pdf-viewer、katex、shiki 等（见 `04` D9）                                                                                                           | 证据；首包/内存 **推断**           | 预览/图表 **惰性 + 进程外/ worker**；禁止进输入热路径                                                |
| R16 | **Yjs 被 resolutions patch**             | 根 yarn patch yjs（见 `04` D9）                                                                                                                                                | 证据                               | 协同核心带补丁 = 升级/性能回归雷；自研应零 patch 或自有实现有测试围栏                                |
| R17 | **官方叙事：2000 形状 canvas 仍 100fps** | `docs-site/blog/document-centric.md` 对比 tldraw                                                                                                                               | 证据（营销/博客）                  | 只覆盖 **纯 canvas 形状** 场景；**不覆盖** 巨量 DOM note + 富文本 + 多光标（不可外推为全文体验上限） |

## 2. 架构证据切片（按子系统）

### 2.1 Page：全量子树挂载

```399:420:reference/markdown_compare/AFFiNE/blocksuite/affine/blocks/root/src/page/page-root-block.ts
  override renderBlock() {
    // ...
    const children = this.renderChildren(this.model, child => {
      // 仅过滤 EdgelessOnly note，其余全部渲染
      return !(isNote && displayOnEdgeless);
    });
    return html`
      <div class="affine-page-root-block-container">${children} ${widgets}</div>
    `;
  }
```

`EditorHost.renderChildren` 对 `model.children` 做 `repeat` 全量 `_renderModel`（`lit-host.ts:96-104`）。
`note-block` 再对 note 内块全量 `renderChildren`。

**搜索线索**：framework/std 下 **无** `virtual/recycle/IntersectionObserver` 类文档窗口实现；`virtual` 出现在 **页面列表** 与 **实验性 table virtual scroll**，非正文编辑器。

### 2.2 Edgeless：视口 culling + 默认「不 park」

- `viewportRuntimeConfig`（`framework/std/src/gfx/viewport.ts`）：
  - 桌面：`OVERSCAN_RATIO=0`、`OVERSCAN_RATIO_BLOCK=0`、`LOW_ZOOM_GESTURE_ACTIVE_BLOCK_LIMIT=0`、`CANVAS_DPR_CAP_BY_ZOOM=[]`
  - 注释明确：mounted block → WebContent **独立合成层**；放大 overscan 会把进程推向 iOS jetsam
  - `will-change: transform` 在 idle 块上于 mobile skip 模式有害（100+ 层 ~100ms stall → 进程被杀）——`viewport-element.ts:203-212`
- 显隐状态机：`block-idle` / `block-active` / `block-survival`；桌面刷新路径会 throttle（18px / 120ms）
- `maxConcurrentRenders` 默认 2 + `scheduleUpdateChildren`：缓解 **同时** 激活尖峰，不减少 **稳态** 挂载上限

**推断**：大画布平移时主线程仍可能为「进出视口的 DOM 激活/样式/层提升」付费；模型与 view map 仍随文档规模增长。

### 2.3 Surface Canvas

- `CanvasRenderer`：主 canvas + 可选 **stacking canvas** 池（层穿插 DOM/canvas）；debug 暴露 `canvasMemoryBytes`、`lastRenderDurationMs` 等
- 视口求交 + `GridManager`（`DEFAULT_GRID_SIZE=3000`）做可见元素查询
- iOS 低缩放 survival：可 bypass stacking canvases、DPR cap、gesture 期间 skip refresh——说明 **内存/合成预算** 是真实约束，而非臆测

博客自称 ~2000 形状 >100fps（`document-centric.md:178`）：有利于「纯矢量层」叙事；**与「每 note 内完整 InlineEditor DOM」叠加时的上限是不同问题**。

### 2.4 Turbo Renderer（可选）

- 扩展 `ViewportTurboRendererExtension`：Worker 绘制 layout 位图，交互/高 zoom 回落 DOM
- 产品接入：`featureFlagService.flags.enable_turbo_renderer`，**defaultState: false**，且 `configurable: isCanaryBuild`
- 仅 edgeless 注册（`TurboRendererViewExtension`：`!enableTurboRenderer || !isEdgeless` 则不 register）

**推断**：默认用户路径 **不享受** turbo；即便开启，编辑/缩放抖动时仍有 DOM 往返与 1s debounce 类逻辑，体验连续性依赖状态机。

### 2.5 编辑热路径（Inline + Y.Text）

- 每次 Y.Text 变更：`RenderService` 重建 lines → `lit.render` 到 root
- IME 异常：`rerenderWholeEditor` 清空子节点并删除 lit 内部 `ChildPart` 后整树重绘（`render.ts:163-166,188-199`）
- 依赖链：contenteditable + 自研 range ↔ Y relative position 同步

**推断**：单段落极长、或远程高频 delta 时，主线程与布局压力上升；与「Rust 侧 OT/CRDT + 前端增量 patch」模型对比处于劣势位。

### 2.6 协同光标 / 远程选区

- `AffineDocRemoteSelectionWidget`：
  - 读 `awarenessStore.getStates()` + `remoteSelections`
  - 几何：`Range.getClientRects` / block `getBoundingClientRect` / `getSelectionRectsCommand`
  - 更新：`throttle 60ms`；**任意** `blockUpdated` 重算当前远程选区；viewport 更新 **立即** `_updateSelections`
- Edgeless 另有 remote-selection 包路径（同类 overlay 思路）

**架构张力**：远程人数 × 选区矩形数 × 强制布局 ≈ 主线程争用；与本地输入、canvas 刷新抢同一帧。

### 2.7 桌面 Electron 壳

| 组件      | 路径线索                                              | 性能相关含义                     |
| --------- | ----------------------------------------------------- | -------------------------------- |
| Main      | `packages/frontend/apps/electron/src/main/`           | 完整 Chromium 主进程             |
| Helper    | `helper-process.ts` → `utilityProcess.fork`           | 额外 Node 工具进程（nbstore 等） |
| Worker 窗 | `worker/pool.ts` 隐藏 `BrowserWindow`                 | 又一类 renderer 级内存占位       |
| Renderer  | `electron-renderer` 加载与 web 同源 core + BlockSuite | 编辑器全在 Chromium 堆           |
| 依赖      | `electron: ^39`，helper 侧仍链 `yjs`                  | 壳与数据均偏重 JS                |

相对 **Tauri（单一系统 WebView + Rust 后端）**：**推断** 冷启动、空闲 RSS、多窗场景基线更高；IPC 与多进程生命周期也更复杂（与 `04` D5 构建税叠加）。

### 2.8 已有「快」与「不全快」的分界

| 场景                  | 机制                           | 默认是否启用               |
| --------------------- | ------------------------------ | -------------------------- |
| 工作区文档列表        | react-virtuoso                 | 是（列表组件）             |
| Database 表           | `pc-virtual` GridVirtualScroll | **否**（flag false）       |
| Edgeless 位图 turbo   | Worker turbo-renderer          | **否**                     |
| Edgeless 视口外 block | idle hidden / 可选 park        | 桌面：hidden 为主，park 关 |
| Page 长文             | —                              | **无窗口化**               |
| 纯 canvas 形状        | grid + canvas 重绘             | 是（surface 路径）         |

## 3. 与「十万行 / 大画布 / 多协同光标」的架构张力

下列张力是 **结构冲突**（目标规模 vs 当前默认实现），不是工期排序。

### 3.1 十万行级文档（Page）

| 张力    | 一侧                          | 另一侧                                                       |
| ------- | ----------------------------- | ------------------------------------------------------------ |
| T-Doc-1 | 产品要「打开即流畅滚动/定位」 | 全量块 CE + 每文本块 Inline 根                               |
| T-Doc-2 | 协同要整份文档一致性          | Yjs 全量在渲染进程堆内                                       |
| T-Doc-3 | Undo 要细粒度                 | `UndoManager` 跟踪整棵 `yBlocks`，历史与文档同胀（**推断**） |
| T-Doc-4 | 大纲/搜索/导出要扫全文        | 若扫的是 DOM 或全量 JS model，与窗口化渲染抢资源             |

**推断的失效模式（非断言必现）**：初始 mount 时间与内存随块数近似线性；滚动时若未来补虚拟化，又与 **每块 contenteditable 焦点/选区** 强耦合，回补成本高。

### 3.2 大画布（Edgeless）

| 张力       | 一侧                               | 另一侧                                                      |
| ---------- | ---------------------------------- | ----------------------------------------------------------- |
| T-Canvas-1 | 无限画布 + 缩放到概览              | 低缩放时可见元素数暴涨；DOM note 与 canvas 形状混排         |
| T-Canvas-2 | 形状走 canvas 可保帧率（博客口径） | Note/文本仍要 DOM 编辑能力 → 视口内 DOM 上限仍在            |
| T-Canvas-3 | stacking canvas 正确层序           | 层数 × 视口像素 × DPR = 显存/内存（代码已为 iOS 写 bypass） |
| T-Canvas-4 | turbo 位图减 DOM                   | 默认关；且编辑时必须回 DOM，缩放/平移状态机复杂             |
| T-Canvas-5 | 桌面不过度 park                    | 与 mobile 内存策略分叉 → 同一套代码两套预算，回归面大       |

### 3.3 多协同光标

| 张力       | 一侧                      | 另一侧                                                     |
| ---------- | ------------------------- | ---------------------------------------------------------- |
| T-Collab-1 | Awareness 实时            | 每次几何解析触发布局（getClientRects）                     |
| T-Collab-2 | 任意人编辑 `blockUpdated` | 远程选区 widget **全局** 节流重算                          |
| T-Collab-3 | 光标要贴着远程 IME/选区   | Inline 远程 range 用 Y relative position + 可能整段 render |
| T-Collab-4 | 人数上升                  | 每用户一套 DOM overlay 节点（rect div + 标签）             |

**推断**：在「大文档 + 多用户同时键入」交叉场景，输入帧与远程 UI 帧最容易互相饿死——这是效果锁必须单独立项验收的组合场景，而非单独测「本地打字」或单独测「空闲光标」。

### 3.4 数据面 vs 视图面「同尺度」

BlockSuite 文档中心叙事（data 与 editor 分离）**有利于**换渲染器；但当前默认实现仍是：

- **权威数据**：Yjs（JS）
- **权威视图**：Lit DOM（Page）+ Canvas/DOM 混合（Edgeless）
- **权威壳**：Chromium 多进程

三者同尺度膨胀时，**没有**「Rust 扛重」的卸压阀——这是与本产品目标栈的根本分叉。

## 4. 本产品要打赢时必须正面解决的点（效果锁语言）

> 下列为 **效果完整度** 约束：不得降级为「简化版 / 以后再说」而不标冲突请示。表述对齐 `00-调研边界与效果锁.md`。

### 4.1 文档规模

1. **打开并流畅编辑「十万行量级」文档**：滚动、跳转标题、块选、输入的主路径不得依赖「全量块 DOM 同时挂载」。
2. **内存与打开时间随可见窗口近似常数级增长**（允许对数/弱线性索引），禁止默认路径随全文块数线性涨到不可用。
3. **权威文档状态与重计算在 Rust**；前端仅窗口投影 + 交互；禁止把整份 CRDT 热数据钉死在 UI 线程作为唯一实现。

### 4.2 编辑热路径

4. **本地键入**：单字符/IME 组合在长段落上保持跟手；禁止默认「整段 Lit 树拆除重建」作为主路径。
5. **IME / 选区正确性** 与性能同时成立：不得以「卡了再整页 rerender」为恢复策略成为常态。
6. **单一 UI 渲染管线** 承载块与行内（或明确的零成本桥）；禁止 React+Lit 双调和器进入输入关键路径。

### 4.3 大画布

7. **大画布概览与缩放**：低缩放用 LOD/聚合/位图或 GPU 层，且为 **默认开启** 的策略，而非 canary flag。
8. **视口外资源真释放**（或等价预算控制），而非仅 `visibility:hidden` 占着自定义元素与合成层。
9. **Canvas/图层像素预算** 有硬上限与可观测指标（对齐 AFFiNE 已暴露的 memory debug 方向，但要产品级默认防护）。
10. **DOM 富文本与矢量层混排** 时仍满足帧率目标——验收必须包含「大量 note + 形状」混合，而不是只测纯形状。

### 4.4 多人协同

11. **多远程光标/选区** 在大文档下：增量更新、视口裁剪、避免每帧 N 次强制布局。
12. **远程编辑与本地输入并发** 时，光标层不得饿死输入；输入不得长时间阻塞光标层（同一帧预算可调度）。
13. **协同合并与历史** 的重逻辑不在 UI 线程膨胀到与文档大小同阶而不可控（Rust 侧可测上限）。

### 4.5 桌面壳与依赖面

14. **Tauri 壳基线**：空工作区与打开大文档的 RSS/启动时间优于 Electron 多进程方案（应用内对比基准，不空口）。
15. **重型预览**（PDF/图表/排版引擎）默认惰性，不进入冷启动与输入路径。
16. **表格/数据库大数据**：默认窗口化，不以实验旗充当完成定义。

### 4.6 验证资产（效果可证伪）

17. 建立并守住自动化/半自动场景：十万行滚动与输入、大画布缩放平移、N 远程光标、混合 note+shape；指标含帧时间、内存、打开耗时。
18. 回归不得以「关掉协同 / 缩小文档 / 只测空文档」冒充通过。

## 5. 与本产品栈的不对位摘要

| AFFiNE/BlockSuite 默认倾向            | 本产品锁定方向             |

| 双 UI 运行时（React+Lit）             | 单一宿主                   |
| Turbo/表虚拟滚动实验态                | 同等能力为默认完成定义     |
