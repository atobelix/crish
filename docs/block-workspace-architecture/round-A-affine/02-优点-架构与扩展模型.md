# AFFiNE / BlockSuite 优点：架构与扩展模型

> **调研对象**：`reference/markdown_compare/AFFiNE`（BlockSuite 框架 + affine 业务扩展）  
> **视角**：架构分层、扩展点、数据真相与更新传播；只谈可内化机制意图，不照搬包名。  
> **本产品对照**：Tauri + TypeScript + Rust；TS 侧扩展生态；重状态/协同可沉 Rust；块操作 + 实时协同。  
> **边界**：优点分析；无证据不吹捧；流行度不否定自研。

---

## 1. 架构分层（文字图 + 证据）

BlockSuite 将「可协同的文档内核」与「可替换的编辑运行时/视图」切成清晰层，AFFiNE 业务块再按 **Store / View 双轨** 挂载。

```
┌─────────────────────────────────────────────────────────────────────┐
│  产品壳（AFFiNE 前端 / Electron / 服务端）                           │
│  packages/frontend|common|backend …                                  │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 装配 extensions、workspace、同步源
┌───────────────────────────────▼─────────────────────────────────────┐
│  affine 业务扩展面（可插拔）                                         │
│  ┌──────────────────┐  ┌──────────────────┐  ┌────────────────────┐ │
│  │ Store 扩展集合    │  │ View 扩展集合     │  │ Model / Schema     │ │
│  │ schema/adapter   │  │ block/widget/    │  │ flavour 数据契约    │ │
│  │ gfx element 类型 │  │ inline/keymap/   │  │ GfxCompatible 块   │ │
│  │                  │  │ command/fragment │  │                    │ │
│  └────────┬─────────┘  └────────┬─────────┘  └─────────┬──────────┘ │
│           │  ext-loader          │  scope: page|edgeless|…           │
└───────────┼──────────────────────┼───────────────────────────────────┘
            │                      │
┌───────────▼──────────────────────▼───────────────────────────────────┐
│  framework/std — 编辑运行时（DOM 相关可装，但接口与 DI 解耦）         │
│  BlockStdScope：Command / Event / Selection / Clipboard / ViewStore   │
│  GfxController：viewport / layer / tool / surface middleware          │
│  Inline：按块拆分的 Y.Text 富文本                                     │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 读写 Store / 订阅 slots
┌───────────────────────────────▼─────────────────────────────────────┐
│  framework/store — 数据层（可无 DOM）                                 │
│  Workspace → Doc → Store(block tree) → BlockModel + Schema            │
│  SyncController / Reactive Proxy ←→ Y.Map / Y.Text / Y.Array          │
│  Transformer / Adapter / Selection / History（StoreExtension）        │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ CRDT 二进制流 / Awareness / Blob
┌───────────────────────────────▼─────────────────────────────────────┐
│  framework/sync — 同步引擎                                           │
│  DocEngine(main + shadow peers) · Awareness · Blob · DocSource 抽象  │
└───────────────────────────────┬─────────────────────────────────────┘
                                │
┌───────────────────────────────▼─────────────────────────────────────┐
│  framework/global — DI Container / Disposable / gfx 几何原语         │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.1 分层证据路径

| 层                                | 职责                                    | 证据                                                                                                                           |
| --------------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 框架总览（headless + components） | store / inline / std 与业务 blocks 分离 | `blocksuite/docs-site/guide/overview.md`（Architecture 表）；`blocksuite/framework/`                                           |
| Store 数据层                      | 协同文档状态、块树 CRUD、无 DOM 扩展    | `blocksuite/framework/store/src/model/store/store.ts`；`extension/store-extension.ts`（注释：_run in a none-dom environment_） |
| Std 编辑运行时                    | 命令、事件、选择、视图、Gfx 控制器      | `blocksuite/framework/std/src/scope/std-scope.ts`（`internalExtensions` 清单）                                                 |
| Sync                              | Doc/Awareness/Blob 多源同步             | `blocksuite/framework/sync/src/doc/engine.ts`；`doc/source.ts`（`pull/push/subscribe`）                                        |
| DI                                | Extension = 向 Container 注册工厂       | `blocksuite/framework/global/src/di/container.ts`；`store/src/extension/extension.ts`                                          |
| 扩展装载                          | Store/View 双 Manager + scope           | `blocksuite/affine/ext-loader/`（`manager.ts`、`store-provider.ts`、`view-provider.ts`、README）                               |
| 业务装配入口                      | 内部 store/view 扩展清单                | `blocksuite/affine/all/src/extensions/store.ts`、`view.ts`                                                                     |
| Model 契约                        | flavour schema / Gfx 双栖 note          | `blocksuite/affine/model/src/blocks/**`                                                                                        |
| 块实现样例                        | store 注册 schema；view 注册 UI/keymap  | `blocks/paragraph/src/store.ts`、`view.ts`                                                                                     |

### 1.2 分层带来的架构优点

1. **数据与视图可独立部署**：`StoreExtension` 明确要求能在无 DOM 环境运行（服务端、Worker、测试、未来的 Rust 宿主侧镜像逻辑）。视图扩展只在 `BlockStdScope` / host 挂载时装配。
2. **同一文档多视图**：View scope 区分 `page` / `edgeless` / `preview-*` / `mobile-*`（`view-provider.ts`），**同一 Store 真相**上换 UI 扩展集，而不是复制两套文档模型。
3. **框架与产品平权复用**：overview 明确 BlockSuite 与 AFFiNE 关系类似 Monaco/VSCode，但组件边界保证「产品无特权」——扩展都走同一 DI 注册面。
4. **Gfx 与文档同树**：`affine:page` 根下同时挂 `affine:note`（文档 hub）与 `affine:surface`（画布元素容器）；`NoteBlockModel` 用 `GfxCompatible` 混入 `xywh/index`，`displayMode` 控制 Doc/Edgeless 可见性——**白板不是旁路文档**。

## 2. 扩展点清单与优点

核心机制：**一切可插拔能力 = `ExtensionType { setup(di: Container) }`**，再由更高层的 Provider（Store/View）按 scope 批量 `context.register([...])`。

### 2.1 扩展点总表

| 扩展点                    | 作用层      | 注册方式（机制）                                                  | 优点                                                                        | 证据                                                                                                               |
| ------------------------- | ----------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **Block Schema**          | Store       | `BlockSchemaExtension(schema)` → `BlockSchemaIdentifier(flavour)` | 块类型契约可注册、可校验父子/role；新块 = 新 schema 而非改核心              | `store/src/extension/schema.ts`；`defineBlockSchema` 用法见 `paragraph-model.ts`；`schema/schema.ts` 的 `validate` |
| **Store Extension**       | Store       | `StoreExtension` / Provider `context.register`                    | 生命周期 `loaded/disposed`；无 DOM 服务（history、selection、业务 adapter） | `store-extension.ts`；paragraph `store.ts` 注册 schema + adapters                                                  |
| **Block View**            | Std/View    | `BlockViewExtension(flavour, lit-tag)`                            | 数据 flavour 与渲染组件解耦；可换渲染器                                     | `std/src/extension/block-view.ts`                                                                                  |
| **Widget View**           | Std/View    | `WidgetViewExtension(flavour, id, lit-tag)`                       | 块级辅助 UI（工具条、slash menu）挂到 host 块，不污染 model                 | `std/src/extension/widget-view-map.ts`；`docs-site/guide/block-widgets.md`                                         |
| **Flavour 标记**          | Std         | `FlavourExtension(flavour)`                                       | 为服务/事件绑定提供 flavour 身份                                            | `std/src/extension/flavour.ts`                                                                                     |
| **Keymap**                | Std         | `KeymapExtension(factory, options?)`                              | 按 flavour / 全局挂快捷键，与块实现同包分发                                 | `std/src/extension/keymap.ts`；paragraph `view.ts`                                                                 |
| **Command**               | Std         | `CommandManager.chain().pipe(...).run()`                          | 可组合、可 try/tryAll 的编辑动作管道；UI 与状态变更中间层                   | `std/src/command/manager.ts`；`docs-site/guide/command.md`                                                         |
| **Inline Spec**           | Std/Inline  | `InlineSpecExtension` + InlineManager                             | 链接/引用/公式等行内类型可插拔；属性 schema 用 zod 校验                     | `std/src/inline/extensions/inline-spec.ts`；`docs-site/guide/inline.md`                                            |
| **Gfx Extension / Tool**  | Std/gfx     | `GfxExtension`（`key` + `extendGfx`）                             | 画布工具/交互与文档块同一 DI 面；可扩展 controller                          | `std/src/gfx/extension.ts`；`tool/`                                                                                |
| **Surface Element 类型**  | Store+Model | surface 上注册 brush/shape/connector… store 扩展                  | 画布图元类型与块 flavour 对称可扩展                                         | `affine/all/src/extensions/store.ts` 中 Brush/Shape/…StoreExtension                                                |
| **Adapter / Transformer** | Store       | 块级 adapter 扩展 + `Transformer` middleware                      | 导入导出（md/html/notion…）按块分发，不绑死编辑器                           | paragraph `adapters/`；`store/src/transformer/transformer.ts`                                                      |
| **Selection 类型**        | Store       | `StoreSelectionExtension` 等                                      | 块/文本/surface 选择可扩展；awareness 可同步                                | `store/src/extension/selection/`；std selection                                                                    |
| **History**               | Store       | `HistoryExtension`（internal）                                    | 撤销与 CRDT 同源，不另造一套 undo 树                                        | store `internalExtensions`                                                                                         |
| **Config Extension**      | View        | 如 `ParagraphBlockConfigExtension({ getPlaceholder })`            | 同一块实现可配置产品差异（占位符等）                                        | paragraph `view.ts` + zod optionsSchema                                                                            |
| **LifeCycle Watcher**     | Std         | `LifeCycleWatcher` / editor life-cycle                            | 挂载/渲染/卸载钩子统一，避免散落副作用                                      | `std-scope.ts` 生命周期调用                                                                                        |
| **Clipboard / DnD**       | Std         | internal + 可扩展 adapter                                         | 剪切板与拖放走统一管道                                                      | `std/src/clipboard/`；`extension/dnd/`                                                                             |
| **Fragment（辅助面板）**  | View        | DocTitle / Outline / FramePanel… ViewExtension                    | 编辑器周边 UI 与核心块同扩展体系                                            | `affine/all/src/extensions/view.ts` Fragment 段                                                                    |
| **DocSource / Provider**  | Sync        | `DocSource` pull/push/subscribe                                   | 本地 IndexedDB、广播、远端 WebSocket 等多后端可插拔并行                     | `sync/src/doc/source.ts`；`engine.ts` main+shadow peers                                                            |
| **ext-loader 装配**       | 产品        | `StoreExtensionManager` / `ViewExtensionManager`                  | 按 scope 收集扩展、`configure` 改选项、DI 取 manager                        | `ext-loader/README.md`；`manager.ts`                                                                               |

### 2.2 扩展模型优点（归纳）

1. **单一注册原语（DI setup）**  
   块、widget、keymap、inline、gfx、schema 全部收敛到 `setup(di)`，第三方与一等公民同一路径（见 `extension.ts` 文档中的非块示例：水果加工器——刻意说明模式不限于块）。

2. **Store / View 双轨拆包**
   - Store：`schema + adapter`（可在 headless 跑测试/同步）。
   - View：`BlockView + Keymap + Markdown 输入 + Config`。  
     证据：`ParagraphStoreExtension` 只注册 schema/adapters；`ParagraphViewExtension` 只注册视图与交互（`blocks/paragraph/src/store.ts` / `view.ts`）。

3. **Scope 条件装配**  
   ViewProvider 可按 `page` vs `edgeless` 注册不同扩展，预览/移动端减载或换 UI，**不必 if-else 散落在核心渲染**（`view-provider.ts` README 示例）。

4. **块树关系由 Schema 声明**  
   `role: root | hub | content` + `parent/children`（支持 glob）在 CRUD 时校验（`schema.validate`、`DocCRUD.addBlock`）。扩展新块时契约显式，降低「任意嵌套炸树」风险。

5. **Command 管道复用复杂编辑**  
   多步编辑（缩进/分割/合并）拆成纯函数命令再 chain，利于测试与快捷键/slash menu/工具栏共用同一动作源。

6. **Inline 按块拆分**  
   每个块的 `Y.Text` 独立 `InlineEditor`，避免「整篇一个大富文本」的复杂度（overview + inline 指南）。扩展行内类型不影响块树拓扑。

7. **Widget 与 Block 解耦**  
   工具条、远程选区、拖动手柄作为 widget 挂到 flavour，可单独开关/替换，不进入持久化 props。

## 3. 数据真相与更新传播：优点

### 3.1 文档如何表示

| 概念      | 表示                                                            | 证据                                                                                  |
| --------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Workspace | 多 Doc 集合 + meta + blob 引擎                                  | `store/src/extension/workspace/workspace.ts`                                          |
| Doc       | 一块协同文档容器（Y 子文档）                                    | `docs-site/guide/store.md`                                                            |
| Store     | 从一个 Y.Doc（或其一部分）物化的块树运行时                      | `store.ts` 类注释：_A store is a piece of data created from one or a part of a Y.Doc_ |
| Block     | `Y.Map`（YBlock）：`sys:id/flavour/children/version` + `prop:*` | `DocCRUD.addBlock`；`SyncController`                                                  |
| 富文本    | `internal.Text()` → Y.Text + delta attributes                   | paragraph schema；inline 指南                                                         |
| 画布图元  | Surface 块 props 内 `elements: Boxed<Y.Map<...>>`               | `surface-model.ts`                                                                    |
| 快照      | 嵌套 JSON `BlockSnapshot` / `DocSnapshot`（导入导出）           | `transformer/`；`docs-site/guide/data-synchronization.md`                             |
| 在线真相  | **CRDT 二进制流**（非 JSON 权威）                               | data-synchronization _Document Streaming_；blog `crdt-native-data-flow.md`            |

典型树（创建空文档惯例）：

```
affine:page (root)
├── affine:surface          ← 画布元素
└── affine:note (hub, GfxCompatible + displayMode)
    └── affine:paragraph…   ← content
```

证据：`docs-site/guide/store.md` 中 `createEmptyDoc` 示例；note `displayMode: DocAndEdgeless | DocOnly | EdgelessOnly`（`consts/note.ts`）。

### 3.2 更新如何传播（单向 CRDT 优先）

设计意图（blog 与实现一致）：

```
本地 UI / Command / 远端 peer / Undo
        │
        ▼
  先改 YModel（Y.Map / Y.Text / …）
        │  Y.Event 增量
        ▼
  SyncController / 块树物化（Proxy + Signal）
        │  store.slots.blockUpdated 等
        ▼
  View 订阅 → 按 block id 局部刷新
```

关键实现证据：

- **写路径走 Y**：`DocCRUD.addBlock` 直接写 `Y.Map` 并 `schema.validate`，不是先改内存树再双向同步。
- **读路径由 Y 观察驱动**：`SyncController` observe `yBlock`，更新 proxy props 与 `prop$` signals，回调 `onChange(key, isLocal)`。
- **Store 事件统一出口**：`StoreSlots.blockUpdated` 带 `add|delete|update` + `isLocal`（`store.ts`）。
- **协作透明**：应用层不区分本地/远端——远端 apply update 走同一管道（`crdt-native-data-flow.md`）。
- **同步多源**：`DocEngine` main peer + shadow peers；`DocSource` 抽象 pull/push/subscribe，可同时接本地持久化与网络（`engine.ts` 注释图）。
- **瞬时态分流**：光标等走 Awareness，不进文档历史（blog _Unidirectional Update Flow_）。

### 3.3 数据面优点

1. **单一真相源（CRDT-native）**  
   避免「编辑器内部 model ↔ CRDT」双向绑定的经典坑；协作、历史、多端同步同一条写路径。

2. **流式加载与多 Provider**  
   空 Doc + 连接 provider 即可灌入二进制状态；创建与加载对称（data-synchronization）。利于本地优先、离线、多后端。

3. **快照与流式双通道**
   - 协同/持久：CRDT 流
   - 交换/迁移：Snapshot + Adapter（md/html…）  
     两条通道分层，不把 JSON 当协同权威。

4. **Schema 约束的块树**  
   role + parent/children 在写入时校验，扩展块仍保持树不变量。

5. **响应式物化层**  
   Y → Proxy/Signal，UI 可细粒度订阅 props（`text$`、`xywh$` 等），利于按块更新而非整页重绘。

6. **Gfx 与文档共享同一 Store 事件面**  
   Note 既是文档 hub 又是画布对象；surface 元素与块更新可共用协作与历史基础设施。

7. **无 DOM Store 便于把重逻辑下沉**  
   StoreExtension 设计目标含 none-dom——与「重状态/协同沉 Rust」方向兼容（机制上数据面可离 UI）。

## 4. 对本产品的内化启发（机制意图）

> 表述为可落地的架构意图，**不是**「引入 @blocksuite/*」或复制包结构。

### 4.1 强制分层：真相内核 / 编辑运行时 / 扩展装载 / 壳

| 意图                   | 本产品落点建议                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------- |
| **文档真相内核无 UI**  | Rust 持有块树 + 协同 OT/CRDT（或等价），暴露确定性 patch 与查询；TS 不另持第二套权威 model     |
| **编辑运行时在 TS**    | 命令管道、快捷键、选区映射、widget 布局、IME 等留在 TS/WebView；只消费内核事件                 |
| **扩展装载器一等公民** | TS 侧 `register(extension)` 统一面：块类型、渲染、快捷键、导入导出、画布工具；产品壳只装配清单 |
| **壳（Tauri）**        | 窗口、文件、权限、进程；不把块语义写进壳                                                       |

### 4.2 Store / View 双轨扩展

- **数据扩展**（schema、校验、adapter、协同序列化）：可 headless 测试；可部分镜像到 Rust 校验。
- **视图扩展**（组件、widget、keymap、placeholder 配置）：按 mode（文档/画板/预览/移动）条件装载。
- **验收意图**：同一文档字节流，在「仅数据」环境可解析；换 view 包不改磁盘格式。

### 4.3 块契约显式化

- 每块：`type/flavour` + props schema + 允许的父子关系 + 版本。
- CRUD 写入前校验（对齐 `Schema.validate` 意图）。
- 行内格式与块拓扑分离（块内富文本独立序列，避免整篇单一 text rope 绑死所有功能）。

### 4.4 单向更新管道（协作默认正确）

```
UI 事件 → Command（可组合） → 内核 apply(patch)
                              → 事件流（含 local/remote 标记仅供调试/UI 装饰）
                              → 视图订阅
```

- **禁止**「先改 UI 状态再异步回写真相」作为主路径。
- 远端 patch 与本地 command 走同一 apply，UI 无需协作专用分支。
- 光标/拖拽预览等进 **presence/awareness** 通道，不进文档历史。

### 4.5 文档 + 画板统一真相

- 根文档同时容纳「流式块容器」与「二维图元层」。
- 可双栖对象（类似 note）：文档内是 hub，画板上是带几何的节点；用 **显示模式** 字段控制视图过滤，而不是复制数据。
- 扩展面：块类型与画板工具/图元类型对称注册。

### 4.6 同步源可插拔

- 抽象「文档字节流源」：`pull / push / subscribe`（对齐 DocSource 意图）。
- 引擎支持 **主源 + 影子源**（本地盘 + 网络同时在线）。
- 重合并与持久放 Rust；TS 只绑 provider 与 UI 状态（连接中/冲突提示）。

### 4.7 交换格式与协同格式分离

- 协同/自动保存：内核原生增量（二进制）。
- 复制粘贴、Markdown、迁移：snapshot 树 + 按块 adapter。
- 扩展第三方格式时只加 adapter，不改协同协议。

### 4.8 命令与 Widget 作为扩展交付单元

- 复杂块操作（缩进、分割、表格编辑）以 **可测试 command** 交付，快捷键/菜单/AI 工具共用。
- 浮动 UI 用 **widget 挂载策略**（挂到块类型或全局 scope），不写进持久化 props。

### 4.9 与本产品栈的对齐摘要

| BlockSuite 机制优点 | 内化到 Tauri+TS+RS                  |
| ------------------- | ----------------------------------- |
| CRDT 为唯一真相     | Rust 内核为唯一真相；TS 投影        |
| Store 无 DOM        | 内核与 adapter 可单测、可非 UI 进程 |
| DI/Extension 统一面 | TS 插件/扩展生态入口                |
| View scope          | 同一文档多模式 UI 包                |
| Schema role/parent  | Rust 侧强制树不变量                 |
| Command chain       | TS 编辑语义层，调用内核事务         |
| DocSource 多 peer   | 本地优先 + 实时同步可并行           |

## 6. 小结

BlockSuite 架构优点不在于「用了 Yjs/Lit」本身，而在于：

1. **真相层与视图层硬切**，且真相层默认可协同、无 DOM；
2. **扩展原语统一（DI setup）**，块/行内/widget/命令/画布/同步源同一玩法；
3. **Store/View 双轨 + View scope** 支撑 headless 与多模式 UI；
4. **CRDT 单向管道** 使协作对应用层透明；
5. **文档与画板同树**，用 schema 与 displayMode 统一复杂知识结构。

对本产品：把上述意图映射为 **Rust 真相内核 + TS 扩展生态与编辑运行时 + 可插拔同步源 + 块/画板统一文档模型**，即可内化其架构收益，而无需复刻其包名与实现栈。
