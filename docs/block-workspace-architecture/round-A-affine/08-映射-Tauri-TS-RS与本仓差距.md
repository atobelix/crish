# 08 映射：AFFiNE/BlockSuite → Tauri + TS + RS 与本仓差距

> **调研轮次**：round-A-affine  
> **效果锁**（见 `docs/block-workspace-architecture/00-调研边界与效果锁.md`）：栈 **Tauri + TypeScript + Rust**；目标 **Notion 的皮（块与丰富交互）+ Rust 的心（极速、低内存、原生协同计算）**；必备 **块操作 / 多人实时协同 / TS 扩展生态**；性能与体验须**双双超过**参考产品。  
> **表述纪律**：机制意图可借鉴；设计句用本产品内化语言，禁止「照抄 AFFiNE」作方案落点。  
> **证据源**：`reference/markdown_compare/AFFiNE`（抽样）、`reference/markdown-editor`（行级引擎边界）、`apps/crish-desktop` + `apps/agent-workbench`（已定桌面壳）。  
> **日期**：2026-08-10

## 0. 结论先行

| 判断                     | 内容                                                                                                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 栈对照                   | AFFiNE 桌面 = **Electron 壳 + TS 内核（Yjs/BlockSuite）+ 少量 Rust 原生（nbstore SQLite/blob 等）**；本仓 = **Tauri 壳 + React/TS 前端 + 重 Rust 内核（session/fs/db/markdown）**——**Rust 权重倒置**是差异也是超车杠杆。 |
| 可借鉴                   | 分层（壳 / 块 UI / 文档模型 / 事务协同 / 存储 / 扩展）、块 flavour 注册、Widget 叠加交互、Store↔View 扩展分离、local-first 多实现存储后端、Transformer 导入导出。                                                        |
| 必须自研                 | 文档/协同 **权威状态在 RS**（非 Yjs 主线程权威）；块树与事务；协同合并与 awareness；块 UI 与 slash/拖放等交互面；与 Agent 工作流的文档工作区契约。                                                                       |
| 可复用第三方（边界严格） | 算法/协议层可选（如 CRDT 库的**计算内核**、网络库），**不得**把 Electron 运行时、BlockSuite 整体、Yjs 前端权威模型绑成不可替换底座。渲染库（KaTeX 等）按块类型注入。                                                     |
| 与 `markdown-editor`     | **并存 + 有边界的演进**：行级 Markdown 引擎继续服务 AI 流式/聊天历史/源码向编辑；块工作区是**新文档模型面**，经适配层互通（MD↔块树），**禁止**用块树整盘替换行级引擎的流式职责。                                         |

## 2. 分层详表

### 2.1 产品壳（Shell）

| 维度           | 内容                                                                                                                                                                                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AFFiNE**     | Electron：`packages/frontend/apps/electron`（main/helper/preload）+ `electron-renderer`；原生能力部分经 `packages/frontend/native`（Rust）补 SQLite/blob/录音等；文档写明「Electron 包一层预构建 Web + 部分 native」。                                               |
| **机制意图**   | 壳与编辑内核解耦；重 IO / 本地库下沉 native；多窗口、托盘、更新、深度链接。                                                                                                                                                                                          |
| **本栈建议**   | 继续以 **Tauri + `src-tauri` 命令面** 为唯一桌面宿主（`crish-desktop` 消费 `@tauri-apps/api`，`agent-workbench` 承载引擎与 FS/会话命令）。块工作区能力以 _*core_* / workspace / 新 doc__ 命令** 扩展，而不是新壳。窗口、剪贴板、文件系统对话框、单实例等沿用现有桥。 |
| **自研边界**   | **必须自研/已自研**：IPC 契约、权限与工作区沙箱（`conex-fs` / `resolve_workspace_path`）、会话与 Agent 运行时。                                                                                                                                                      |
| **第三方边界** | 可用 Tauri 官方插件（dialog 等）；**禁止**以「Electron 生态成熟」改栈。                                                                                                                                                                                              |
| **本仓现状**   | 壳与 Agent 工作台已深集成；**尚无**独立「块文档工作区」产品面，文件能力偏 Agent FS / 产出目录（04-EG），不是 Notion 向知识库壳。                                                                                                                                     |
| **差距**       | 工作区导航（树/收藏/最近）、文档元数据 UI、多标签文档、离线优先的文档级生命周期——需在 Tauri 壳内新增产品模块，不新建第二壳。                                                                                                                                         |

### 2.2 块 UI（Block Views & Widgets）

| 维度                        | 内容                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AFFiNE**                  | 块包：`paragraph` / `list` / `code` / `table` / `database` / `image` / `attachment` / `bookmark` / `callout` / `latex` / `note` / `surface` / `frame` / embed 系列等。Widget：`slash-menu`、`drag-handle`、`toolbar`、`remote-selection`、`linked-doc`、`keyboard-toolbar`、edgeless 系列。Inline 与 rich-text 独立包。Gfx：viewport、layer、tool、grid。      |
| **机制意图**                | **一切可放置的内容是块**；块有稳定 id 与 flavour；交互控件是 **Widget 叠加** 而非写死在块内；page 与 edgeless 共享块模型、不同呈现。                                                                                                                                                                                                                           |
| **本栈建议**                | - **Page 模式**：React 虚拟化块列表（块级，非仅行级）+ 块句柄 / 浮动工具条 / slash 菜单 / 拖放排序。<br>- **Edgeless（画布）模式**：独立 viewport 层（后续），块实例挂到画布变换；与 page 共用文档模型投影。<br>- 块视图注册表：`flavour → React 组件`；未知 flavour 降级占位块。<br>- 选区：块选 + 文本选两层（对齐 BlockSuite selection 的意图，实现自研）。 |
| **自研边界**                | 拖放、slash、远程光标绘制、块菜单、嵌套缩进交互、表格/数据库 UI——**体验核心，自研**。                                                                                                                                                                                                                                                                          |
| **第三方边界**              | KaTeX/Shiki 类按块注入；虚拟列表可用 TanStack Virtual（行级引擎已验证）；**不**引入 Lit/BlockSuite 运行时做主 UI。                                                                                                                                                                                                                                             |
| **与 markdown-editor 关系** | 行级引擎的 `BlockRenderer` 是 **Markdown 行类型渲染**，不是 flavour 块树。块 UI 可 **复用** 其 token 渲染/表格/公式经验与 CSS 语义，但列表单元是 **BlockNode**，不是 `lines[]` 行。                                                                                                                                                                            |
| **差距**                    | 本仓无 slash/块拖放/数据库块/画布；markdown-editor 有表格 Excel 向、大纲、查找替换——可迁移为「文本块内」能力，不能覆盖「块间操作」全量。                                                                                                                                                                                                                       |

### 2.3 文档模型（Doc Model）

| 维度           | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **AFFiNE**     | `BlockModel`：id、children、props（含 Text）、schema/flavour；`Store` 管理块增删改与查询；底层 `Y.Doc` / `YBlock` 作协同载体；Schema 校验；Transformer 做切片与导入导出。                                                                                                                                                                                                                                                                        |
| **机制意图**   | 结构化树 + 类型化属性；文本是一等属性；本地变更与远程更新同一模型；schema 演进可版本化。                                                                                                                                                                                                                                                                                                                                                         |
| **本栈建议**   | - **权威**：Rust 侧 `Doc` / `Block` / `Props`（serde 友好），事务应用后产生版本/时钟。<br>- **投影**：TS 侧只读或可写代理（写路径一律 `doc.apply(op)` → IPC/本地内核），用信号或 store 订阅 diff 做 UI 更新。<br>- **双表示**：<br> - **块树**：工作区文档、协同、块操作的权威；<br> - **行级 MD 缓冲**：聊天流式、导出 .md、Agent 读写友好；经 **双向适配器**（见 §3）。<br>- Schema：flavour 注册 + 属性 zod/JSON Schema（TS）与 RS 镜像校验。 |
| **自研边界**   | 块树、schema、事务 op 集、父子顺序（可用 fractional index 类算法）——**必须自研**。                                                                                                                                                                                                                                                                                                                                                               |
| **第三方边界** | 可参考 fractional indexing 等公开算法；**不**以 Y.Map 树为唯一存储形状（避免 JS 权威）。                                                                                                                                                                                                                                                                                                                                                         |
| **本仓现状**   | `conex-db` 的 `blocks` 是 **会话压缩块**（compaction），**不是**文档编辑块模型。markdown-editor：`lines: string[]` + `LineOffsetTree` + 行 AST——**线性源码模型**。                                                                                                                                                                                                                                                                               |
| **差距**       | 完整文档块模型从 0 建；需明确「哪些文档走块树、哪些走纯 MD 行缓冲」的产品边界（建议：知识库/笔记/协同文档 → 块树；聊天消息/Agent 流 → 行级引擎）。                                                                                                                                                                                                                                                                                               |

### 2.4 事务与协同（Transaction & Collab）

| 维度                     | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AFFiNE**               | 编辑进入 Yjs 更新；`framework/sync` 分 doc / blob / awareness 引擎与 peer；nbstore 再封装 cloud/idb/sqlite/broadcast；remote-selection widget 画远端选区。                                                                                                                                                                                                                                                                                                        |
| **机制意图**             | local-first：离线可写；上线合并；光标/选区 presence；blob 与 doc 分通道。                                                                                                                                                                                                                                                                                                                                                                                         |
| **本栈建议**             | - **写路径**：UI 意图 → 规范化 `Op`（insert_block / move / set_prop / text_edit …）→ **RS 事务**（原子、可撤销栈、可复制到协同日志）。<br>- **合并**：RS 内 CRDT 或 OT+版本向量（选型属实现细节，目标是正确并发与低内存）；TS 不跑权威合并。<br>- **Awareness**：独立轻量通道（选区、用户色、当前块 id），可丢、可覆盖，不进文档历史。<br>- **与 Agent 共存**：Agent 写文件走 `conex-fs` 时，打开的文档需 **外部变更检测 + 再加载/三路合并** 策略，避免静默覆盖。 |
| **自研边界**             | 事务语义、撤销/重做、协同合并、冲突可见性——**自研（重心在 RS）**。                                                                                                                                                                                                                                                                                                                                                                                                |
| **第三方边界**           | 可嵌入成熟 CRDT **库**作计算内核（若许可与性能达标），封装在 RS 边界内；前端不直连 Yjs Provider 作为架构中心。网络层可用 WebSocket（本仓已有 `server/ws` 多设备面，可复用扩展）。                                                                                                                                                                                                                                                                                 |
| **markdown-editor 现状** | `EditorOperation` 行级 splice + 500ms 合并 undo；`appendText` 流式快通道不进 undo；**无**并发合并、无 awareness（分析文档已标协作后置）。                                                                                                                                                                                                                                                                                                                         |
| **差距**                 | 从「单用户行级 undo」到「多用户块/文本事务」是最大架构跃迁；行级引擎若参与协作，只宜作为 **投影** 或 **只读副本**，不宜各自为政多写。                                                                                                                                                                                                                                                                                                                             |

### 2.5 存储（Storage）

| 维度           | 内容                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AFFiNE**     | nbstore：`StorageType = blob                                                                                                                                                                                                                                                                                                                                                          | doc | awareness | indexer | *Sync`；实现 idb / sqlite（桌面 native）/ cloud / broadcast-channel；worker 消费同步；BM25 类本地索引。 |

| **第三方边界** | SQLite（已用）、对象存储协议（S3 兼容可选）；不强制 IndexedDB 为桌面主存。                                                                                                                                                                                                                                                                                                            |
| **差距**       | 无文档级 doc-sync/blob-sync 产品面；nbstore 级抽象需内化设计，而非移植包名。                                                                                                                                                                                                                                                                                                          |

## 3. 与现有 `reference/markdown-editor` 的关系

### 3.1 能力边界速写（行级引擎）

| 已强                                                     | 弱 / 无                          |
| -------------------------------------------------------- | -------------------------------- |
| 行级 AST + LRU、增量 fence 状态、虚拟滚动                | flavour 块树、块拖放、slash 菜单 |
| `appendText` 流式、StreamBuffer 帧批                     | 多人协同 / awareness             |
| DOM↔源码 `data-token-*` 无损映射                         | 画布 / 数据库块                  |
| 表格操作、大纲、查找替换、grapheme、IME 基础             | 多文档 store 工厂未完成产品化    |
| 门禁：vitest unit（grapheme/undo/parser-redos/chunk 等） | Yjs/CRDT、持久化工作区           |

（详见 `reference/markdown-editor/docs/analysis/05-*.md`、`06-*.md`、`04-*.md`。）

### 3.2 关系选项（逻辑对比，不排工期）

| 选项                      | 定义                                                        | 优点                                 | 风险 / 代价                               | 效果锁兼容性                |
| ------------------------- | ----------------------------------------------------------- | ------------------------------------ | ----------------------------------------- | --------------------------- |
| **A. 严格并存**           | 块工作区全新栈；markdown-editor 只服务聊天/流式/纯 MD 文件  | 边界清晰；不破坏行级门禁资产         | 两套渲染语义需视觉对齐；重复实现表格/公式 | ✅ 不降级 AI 体验           |
| **B. 演进耦合**           | 把行级引擎「长成」块编辑器（lines → 伪块）                  | 复用虚拟滚动与映射                   | 线性模型硬撑树与并发，易成补丁架构        | ⚠️ 易违背「禁止打补丁」纪律 |
| **C. 适配层互通（推荐）** | 块树权威；MD 导入导出与「源码模式」走行级引擎；聊天保持行级 | 各司其职；共享 token/表格/公式渲染件 | 需维护 MD↔块 适配正确性与往返测试         | ✅ 完整效果 + 可验证        |
| **D. 行级仅为只读投影**   | 块编辑唯一；行级只读渲染消息                                | 编辑模型单一                         | 削弱流式软渲染与源码级编辑优势            | ⚠️ 可能牺牲 AI 流式目标     |

**推荐逻辑排序键**（对齐 Agents.md：效果完整度 → 正确性 → 可验证性 → 契约一致 → 结构干净）：

1. **C（适配层互通）** 为默认结构关系。
2. **A** 作为实现阶段的过渡（适配器未齐时先并存）。
3. **B/D** 仅在能证明不变量与门禁不丢时再评估，**不得**默认选 B 用补丁合并模型。

### 3.3 边界契约（建议冻结的不变量）

1. **聊天历史 / AI 流式** 继续禁止「整页重渲染伪流式」；行级引擎（或其对等增量渲染）保持第一渲染面（与既有 40/23 方案铁律一致）。
2. **`reference/markdown-editor` 测试资产不可删**（Agents.md 铁律）；引擎改动必过 `npm test`。
3. **块文档** 的协同与撤销以块/文本 Op 为准；从 MD 粘贴进入块树走 Transformer，不把整篇 MD 当唯一运行时模型。
4. **完成态权威 HTML** 可与 `conex-markdown` 对齐校验；块 UI 与 MD 渲染的 CSS 语义宜共享 token，避免两套「看起来像 Markdown」的漂移。
5. **DOM↔逻辑映射**：行级已有 `data-token-*`；块级需 **块 id + 块内 offset** 原生映射，禁止坐标猜距补丁。

### 3.4 共享 vs 隔离（模块级）

| 可共享（抽成包）                                                                     | 必须隔离                                                      |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| 行内 token 解析子集、公式/代码高亮渲染、颜色自适应、表格单元格交互思想、虚拟滚动工具 | 权威文档状态、协同合并、块 schema、slash/拖放状态机、画布变换 |
| 查找高亮/装饰层数据结构思想（DecorationSet）                                         | 全局单例 EditorStore（需工厂化后再被宿主多实例使用）          |
| 性能度量与门禁方法论                                                                 | 流式 `appendText` 与块事务的 undo 策略（语义不同）            |

## 7. 机制意图提炼（可内化的「为什么」，非 API 抄写）

1. **壳与内核分离**：壳只做窗口与系统；文档正确性不依赖壳类型——支撑 Tauri 路径。
2. **模型与视图分离**：同一块模型，page/edgeless 多种视图——支撑后续画布而不复制数据。
3. **扩展按 scope 注册**：store 扩展 vs view 扩展——避免核心 if-else 膨胀。
4. **doc / blob / awareness 分通道**：历史、附件、光标生命周期不同——设计存储与网络时照做。
5. **Transformer 边界**：导入导出是适配器，不是运行时格式绑架——MD 与块树共存。
6. **Native 下沉 IO/索引**：AFFiNE 已部分承认；本仓应 **更彻底**（合并与权威状态也在 RS）。
7. **Widget 叠加交互**：slash/拖放/远程选区不写死块内——可测、可关、可扩展。
