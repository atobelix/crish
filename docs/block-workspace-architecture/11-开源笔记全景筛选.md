## 4. 筛选键（与效果锁对齐）

对每个候选问五问（细节在 Round C 各文档展开）：

1. **文档真相在哪一层？**（JS Yjs / Go 事务 / Rust collab / SQLite blob / 文件 MD）
2. **大文档与输入热路径能否虚拟化、能否不整树重绘？**
3. **块 ID + 结构化 mutate 是否一等？**（Agent 批量改是否安全）
4. **MD 是契约还是导出凑合？**
5. **若忽略本仓现状，该架构的「理论上限」是否高于 Tauri+RS+TS 自研？**

## 7. 与用户问题的对齐

> 「选型一定是方案最好的那个，不要因为当前技术栈的缺点导致拉低了上限。」

本波的成功标准：

- 若发现 **某栈在性能/协同/AI 可操作/写作静默上有更高可验证上限**，必须在 `08` 里写明，并给出是否迁移建议。
- 若 **Tauri+RS+TS 仍是最高上限组合**，也必须用跨产品证据写明，而不是「因为我们已有」。
