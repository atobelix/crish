## 0. 结论先行

1. 合法三张皮（`blockChrome.css` / `paperList.css` / `NotePaperPanel.module.css`）的 **6% 软环与 H1–H6 级差公式仍在库内**。产品主壳是 BinaryTree + 11 个内置视图、**没有 `note`**，三张皮只被 `NotePaperStrictPanel` 等 note-paper 侧效 import，**BinaryTree 路径零加载**。用户看见的不是「6% 还在」，而是空白叶或「未知面板类型」。
2. **可达的唯一合法收敛**：02 的扩展激活模块 `registerView('note')` 工厂渲染 `NotePaperStrictPanel`（它已 side-effect import 三张皮）。**禁止**为了「保险」把 chrome / paper-list 再写进 `index.css`（卸扩展后仍整页灌皮，且违背「笔记是扩展」）。

4. **源码推演（非像素证伪）**：当前两层 `display:contents` 让二级选择器 **打不中** `.header`；顶栏今天更可能「没事」。但这是 **未与纸面对过的壳规则**，02 工厂多包一层 / 去掉 contents / 加深选择器，顶栏立刻会被 `flex: 1 1 0%` + `max-height: 100%` 拉高。05 先写绝缘，再在 9222 量像素，不赌推演。
5. 挂 Strict **会顺带挂上** `ConexFloatHandle`（坐标测距 + 新 `rgba` + 假 `+`）。那是违纪第三套皮，**不是** V1/V4。拆除挂载点属 04 死层；本维负验收：产品 note 叶不得出现该胶囊。04 未拆则 05 **不得**宣称皮完成。

### 3.3 `leafBody` 二级 flex 会不会压扁顶栏

#### 3.3.1 规则原文

```333:340:apps/crish-desktop/src/components/binary-tree/BinaryTreeWorkspace.module.css
.leafBody > *,
.leafBody > * > * {
  flex: 1 1 0%;
  min-width: 0;
  min-height: 0;
  max-height: 100%;
  width: 100%;
}
```

注释（同文件 `:332`）写的是给 ErrorBoundary / Suspense 包一层后，让 Terminal / Files / Chat **根**吃满。这是 **盲打两代子孙** 的填充，不是纸面契约。

纸面自己的列：

| 节点 | 现规则 | 被二级规则打中后 |
| --- | --- | --- |
| `.panel` | `display:flex; column; flex:1; min-height:200px`（module `:13-18`） | 再吃 `flex:1 1 0%; max-height:100%` ——填满叶子，可接受 |
| `.header` | `flex-shrink:0; min-height: var(--card-header-min-height, 36px)`（`:50-61`） | 简写 `flex:1 1 0%` **重置** grow/shrink/basis；`flex-shrink:0` 即使后胜也 **挡不住 grow=1**。顶栏与 body/footer **均分**叶子高。再加 `max-height:100%`，顶栏理论上可拉到整叶 |
| `.body` | `flex:1; overflow:auto`（`:181-197`） | 再吃一遍 fill，通常仍是滚区，但与顶栏均分后正文变矮 |
| `.footer` | `flex-shrink:0`（`:582-591`） | 同顶栏，被拉高成第三条「带」 |

特异性都是 (0,1,0)（`.leafBody > * > *` vs `.header`）。胜负取决于模块装载序，**不是**契约。

#### 3.3.2 选择器树 vs 盒树（必须分开说）

| 问题 | 答案 | 证据 |
| --- | --- | --- |
| `>` 会不会因 `display:contents` 跳过节点？ | **不会。** 选择器走 DOM 树 | CSS Display L3；contents 只取消盒，不改子组合器 |
| 当前 `.leafBody > *` 命中谁？ | `AppErrorBoundary` 那层 contents `div` | `AppErrorBoundary.tsx:216` |
| 当前 `.leafBody > * > *` 命中谁？ | `SlotOutlet` 那层 contents `div` | `SlotOutlet.tsx:189-196` |
| `section.panel` 是第几层 DOM？ | **第三层**，现规则 **打不中** | §2.6 |
| 纸面是谁的 flex 项？ | **盒树**上：两层 contents 把 `section.panel` **提升**为 `.leafBody` 的 flex 项 | 因此 `.panel { flex:1 }` 能撑满叶子；`.header` 仍是 **panel 的** 子项，默认 grow=0 |

审计 02 §5 / §8.12 写「会压纸面内部第二层」——在 **把 contents 当成选择器也跳过** 的前提下成立。02b §3.14 写「选择器打到真实视图根」——对 **盒树** 成立，对 **选择器** 不成立。本文以规范为准，并把分歧标成 **推断风险**，用 9222 收口。

对照：`ChatCard.tsx:118-121` 根是 **Fragment**，自己的 `.chatBody` 已写 `flex:1 1 0%; max-height:100%`（`ChatCard.module.css:1-12`）。聊天能填满 **不是** 因为二级规则打中了它（同样隔着两层 contents），是卡片自己填。纸面 `.panel { flex:1 }` 同构。**顶栏风险不来自「现在已被打中」，而来自规则与纸面从未对过、下一步随时会打中。**

#### 3.3.3 什么时候顶栏真的会被压扁（同权列出）

1. **02 工厂把 header/footer 提升成 `leafBody` 的盒树子项**（Fragment 多根、或把 Header 与 Body 拆成 Slot 兄弟）。
2. **去掉** ErrorBoundary / SlotOutlet 的 `display:contents`，且工厂直接返回 `<section.panel>`：此时 panel 变成 `.leafBody > * > *`（或 `> *`），**header 变成再下一代**——若有人把选择器改成三代「打穿」，header 中招。
3. **为了「打到视图根」加深选择器**（`.leafBody > * > * > *` 或 `.leafBody *`）。三代打中 `section.panel` 还可接受；四代或通配会打中 header。
4. **02 在 Strict 外套一层不带 `display:flex; flex-direction:column; min-height:0` 的实盒**，再在那层上套用二级 fill：内部 panel 的 `flex:1` 失效，`min-height:200px` 被叶子 `overflow:hidden` 裁切（01/02b 已写）。看起来像「顶栏没了」或「纸被切头」。
5. 浏览器对「contents + flex」的旧实现差异（须 9222 证伪，不在方案里赌某一引擎）。

#### 3.3.4 完整解（O(1)，禁止测距补偿）

反「打补丁」：不写 `header { margin-top: -Npx }`，不按坐标估顶栏。锁 **视图根契约 + 顶栏绝缘**。

**给 02 的工厂锁（05 验收，02 实现）**：

1. 工厂返回 **单一根**：`<NotePaperStrictPanel ... />`，不要 Fragment 多根。
2. 不要把 `NotePaperStrictHeader` 抽到面板外当 `leafBody` 兄弟。
3. 若必须包一层适配器：该层必须是 `display:flex; flex-direction:column; min-height:0; flex:1 1 0%; max-height:100%`，并把 `data-leaf-view-root` 打在这一层或打在 `section.panel` 上（推荐直接打在 `section`：`buildStrictPanelSectionDataAttrs` 加 `'data-leaf-view-root': '1'`，不新增包装）。
4. 不要为 note 再造 Host / EmptyState。

**05 自己改的绝缘（实现波，且是本维唯一允许动的 CSS）**：

在 `NotePaperPanel.module.css` 用 **(0,2,0)** 锁死顶栏/底栏，使其无论二级规则是否打中都不 grow：

```css
/* 对抗 BinaryTree .leafBody > * > * 的 flex:1 1 0%；不改 V1/V4 */
.panel > .header,
.panel > .footer {
  flex: 0 0 auto;
  max-height: none;
  width: 100%;
  min-height: unset; /* header 仍吃自己的 --card-header-min-height */
}
.panel > .body {
  flex: 1 1 0%;
  min-height: 0;
  max-height: none; /* 滚动交给 overflow:auto，不被 100% 与顶栏均分 */
}
```

`.panel > .header` 特异性 (0,2,0) **稳定压过** `.leafBody > * > *` 的 (0,1,0)，与装载序无关。

**不要**在本维删掉 `.leafBody > * > *`。聊天 / 终端 / 文件若仍依赖「两层实盒」填充，删规则会误伤 11 个内置视图。把「11 视图迁到 `data-leaf-view-root`、删除通配子孙」列为 **后续可做、非本维关门条**（见 §9）。

若 9222 仍见顶栏被拉高：只允许 (a) 检查工厂是否违反锁；(b) 加强上述 (0,2,0)；(c) 在 `BinaryTreeWorkspace.module.css` **仅**给 note 加排除，例如：

```css
.leafBody :global([data-leaf-view-root]) > :global(header),
.leafBody :global([data-testid='note-paper-strict-panel']) > :global(header) {
  flex: 0 0 auto;
  max-height: none;
}
```

排除必须用 **已有探针**，禁止新魔术 class。同文件 01 也在改 `.section/.canvas`——实现时 **串行**，05 只碰 `/* Leaf body */` 段。

#### 3.3.5 顶栏复验句

在叶高 > 0 的真壳 note 叶上：

| 断言 | 口径 |
| --- | --- |
| header 计算高 | ≥ `--card-header-min-height`（36px）且 **远小于** `.leafBody` 高（例如 < 20% 叶高；单行徽章不折成半屏） |
