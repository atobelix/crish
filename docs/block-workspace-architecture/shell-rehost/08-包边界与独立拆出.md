## 4. 收敛形状：契约 + kit + 纸面核可离开桌面

### 4.1 三层可带走的定义（本维钉死）

| 层 | 可带走的内容 | 不可假装已带走 |
| --- | --- | --- |
| **契约** | 全部 W0 类型与 `EDITOR_SURFACES` / `SendToNoteIntent` / opsWire / 坐标系 | 业务实现、IPC、React |
| **kit** | Viewport / HeightMap / pin / Diff / SelectionStore / ImeMachine | 真实 DocSession、yrs 句柄、行级 store |
| **纸面核** | BlockChrome / SlashMenu / PaperList / PM·CM6 叶 / `createCollabApplySink` / mdPrefix / chrome.css / paper-list.css | React 面板、Tauri invoke、桌面 tokens、H1 persist、窗口壳 |

「可离开桌面」的验收语义（**逻辑**，不是本轮工期）：

1. 另起一个 **不含** `apps/crish-desktop` 的宿主，只依赖三包 + 自己的 `applyOps` / `hydrate` 适配，能编译纸面 Model 与 Intent 写锥。
2. 桌面删掉 note-paper 之后，三包 `typecheck` / 包内 vitest 仍绿。
3. 桌面 **反向** 不得出现 `@crish/block-paper/src/...` 或 `crates/conex-doc-collab` 的 TS 类型 import。

现码对 (3) 已基本满足（无深路径）。对 (1)(2)：**React 宿主与 IPC 仍在桌面**，所以 **今天还不能** 说「拷三包就能开独立软件」。见 §8。

### 4.2 桌面只剩三件事

| 桌面职责 | 本轮 02 对应 | 禁止膨胀成 |
| --- | --- | --- |
| **激活视图** | `extensions/note-paper/activate.ts`（总方案示例名）调用 `viewRegistry.registerView`，返回注销 = `deactivate` | 写进 `registerBuiltInViews` 当第 12 内核 |
| **打开** | `UnitChrome` / 工具条经已有 `openToolInSession(sessionId, 'note')` | 复活 `open-note-paper-strict` 当产品主路径；`setChatMainSurface('note')` |
| **IPC 适配** | 工厂内部继续用 `createTauriNoteHydrateIpc` / `resolveProductStrictApplyOps` | 在 `App.tsx` 里 `invoke('note_document_hydrate')`；把 `DocSession` 句柄传到 React |

叶子工厂伪代码（逻辑，不是本维实现）：

```
ctx: ViewRenderContext
docId = resolveProductStrictDocId({
  wsId: ctx.sessionId ?? ctx.leafId,          // 诚实：今天 H1 用的是 wsId，02 须写清映射

return <NotePaperStrictPanel docId={...} hydrateTransport={transport} ...sinks />
```

`NotePaperStrictPanel` **必填** `docId` + `hydrateTransport`（`notePaperStrictProps.ts:63-68`）。工厂不得省略 transport、不得在面板内静默 fixture。

### 4.3 官方捆绑默认开、可关

总方案 §7：`main` / composition **可选** 调用激活。纪律：

- 调用点只 `activateNotePaper()` / `deactivateNotePaper()`。
- `deactivate` = `registerView` 的返回函数（`ViewRegistry.ts:54-83` 已摘槽 + 删 view）。
