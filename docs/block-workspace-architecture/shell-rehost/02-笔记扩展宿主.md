## 1. 总判

- 纸面实现仍在：`NotePaperStrictPanel` 必填 `docId` + `hydrateTransport`（`notePaperStrictProps.ts:64-68`）；产品工厂 `createProductStrictHydrateTransport`（`hydrateProjection.product.ts:77-87`）；H1 `resolveProductStrictDocId`（`workspaceEmptyStateStrictDoc.ts:84-117`）。

- 审计 `01`/`06`/`07` 建议「往内置名单加 `note`」——**与用户口径冲突，作废该写法，保留「叶子里能挂 Strict」的效果**。

## 3. 必须回答：默认单 chat、chat 叶不挂 strip，人怎么打开 note

### 3.1 默认几何（为何 strip 帮不上）

冷启动 `layoutTreeStore`：`restore=false` 时强制 **单 chat + `toolColumnCollapsed=true`**（`layoutTreeStore.ts:220-227,488-506`）。

`BinaryTreeWorkspace.tsx:147-152`：

```
multi = listChatLeaves < 2
flattenTree(..., { collapsedDomain: !multi && toolColumnCollapsed ? 'tool' : undefined })
```

默认单 chat → 工具域宽度被压成 0，**DOM 上没有工具叶**，用户看不见 `LeafToolTabStrip`。

`TreeLeafPanel.tsx:142-143,180-181`：

- `isChat = viewRegistry.isPrimary(leaf.panelId)`（chat 为 `category:'primary'`）
- `{!isChat ? <LeafToolTabStrip /> : null}`

所以 **主对话叶永远没有加号菜单**。把 `note` 注册成 tool 视图，**不会**让默认单 chat 长出加号。这是设计，不是漏写。**禁止**为了开笔记给 chat 叶挂 `LeafToolTabStrip`。

### 3.2 已写好但没挂上的活入口

`UnitChromeActions` **就是**给 chat 用的坞入口：

- 硬编码 `UNIT_TOOL_PANELS`：overview / files / diff / terminal（`UnitChromeActions.tsx:21-46`）
- 点击：`openToolInSession((activeSessionId \|\| '').trim(), panelId)`（`:102-105`）
- 坞折叠时另有 `right-dock-toggle`（`:177-197`）

`openToolInSession`（`openTool.ts:24-68`）对 **任意** `panelId`（含将来的 `'note'`）已经做完解折叠，**不必改 store**：

1. `openPanelIds` 并入该 id；`activePanelId = mapped`；**`collapsed: false`**（`:42-51`）
2. `updateRightDock` + `applyDockToTree` → `makeToolLeaf`（`adapterShapeTreeOps.ts:75-84`）写出 tool 叶，`tabs`/`activeTab` 为 `'note'`
3. `applyDockToSession` 在 dock 未折叠时 **`targetCollapsed = false`**（`adapterShapeStoreOps.ts:226-227`）
4. 若全局 `toolColumnCollapsed` 仍为 true，再 **`setToolColumnCollapsed(false)`**（`openTool.ts:66-68`）

注意：审计 `06` **BUG-14** 说的是 `splitLeaf` **不**写 `toolColumnCollapsed:false`。本维主路径 **不走 `splitLeaf`**，走 `openToolInSession`。不要把 BUG-14 补丁塞进本维，也不要用 `splitLeaf(..., 'note')` 当打开。

### 3.3 断点：ChatHeader 已删，UnitChrome 成孤儿

`BinaryTreeWorkspace.tsx:7-8` 注释仍写「单 unit chat：ChatHeader（第 2 行）」。
**文件不存在**：`ChatHeader.tsx` / `UnitSessionTabStrip.tsx` 已被红队「沉浸顶栏」物理删除。`ChatCard.tsx:118-229` 只有消息流 + Composer，**不** import `UnitChromeActions`。

全仓 `UnitChromeActions` 引用：自身 + `UnitChromeActions.scoped.test.tsx`。产品树 **零挂载**。

因此默认单 chat **现在**连「打开终端/文件」的 UnitChrome 都看不见（ribbons / 全局事件是旁路）。本维若只 `registerView` 而不挂 chrome，笔记与终端同一命运：**store 能开、用户摸不到**。

### 3.4 锁死的打开序列（默认单 chat）

```
用户看见：一叶 ChatCard（无 LeafToolTabStrip）
        │
        ▼
TreeLeafPanel(isChat) 在 leafBody 之外挂 UnitChromeActions

        │

        │
```

草稿 `__pending*`：沿用现码 `TreeLeafPanel.tsx:133-137`——无正式 session 则 `openToolInActiveTab`。UnitChrome 传入的 `activeSessionId` 用 `sessionForPanel`，与 chat 叶同一会话作用域。

**禁止的替代：**

## 4. 做什么

### 4.1 扩展激活模块（新目录，领域词）

路径（实现可微调文件名，**目录语义不得改**）：

```
apps/crish-desktop/src/extensions/note-paper/
  activate.ts          # activateNotePaper / deactivateNotePaper
  noteViewFactory.tsx  # ViewRenderContext → Strict 面板（lazy 可）
  noteUri.ts           # 可选：prefix 'note:' → { viewId:'note', params.docId }
  honesty.ts           # 复用 EMPTY_STATE_PAPER_HONESTY_ATTRS 或同义常量
  *.test.ts(x)
```

这是 **桌面宿主适配层**，不是新插件内核。以后拆独立软件：带走 `packages/*` 纸面核 + 本目录；换壳只要再实现一次 `registerView` 调用。

#### `activateNotePaper(): () => void`

1. `viewRegistry.registerView({ id, title, icon, category, component })`
   - `id: 'note'`（叶 tab / dock panelId 用这个短 id）
   - `title: '笔记'`（或 thunk：有 `params.docId` 时显示短 id）
   - `icon`: lucide `FileText` 或等价，**本模块 import 图标**，不要写进 `registerBuiltInViews.tsx`
   - **`category: 'tool'`**（才能进 `getToolViews()` → C3）
   - **不要** `category: 'primary'`（否则 `isPrimary` 为真，会被当成 chat 域、不挂 strip、flatten 当对话叶）
   - `component`: factory 产出的 `NotePaperView`
2. 可选：`viewRegistry.registerUriResolver({ prefix: 'note:', resolve })`
   - `note:<docId>` → `{ viewId:'note', params:{ docId } }`
   - **不要**写进 `ViewRegistry.initDefaultResolvers`（那是内核 file-viewer 基线，`ViewRegistry.ts:20-51`）
3. 记下 `unregisterView` + `unregisterUri`，合成 `deactivate`
4. 幂等：二次 activate 允许 `registerView` 覆盖（现码 `:56-60` 先卸旧槽再挂）；模块级保存当前 deactivate，便于官方捆绑只持有一份
5. **返回** deactivate（与 `registerView` 对称）

#### `deactivateNotePaper(): void`

1. 调 activate 保存的注销函数：删 `views` 项 + 卸 keyed 槽 + 卸 `note:` resolver
2. 再调是 no-op
3. **不** `viewRegistry.clear()`（会误伤 11 内置）
4. **不**改 layout tree 里已存在的 `'note'` tab（卸扩展后叶走 fallback，见 4.4）。清空 tab 是壳职责，不是扩展内核

#### 官方捆绑默认开

`main.tsx` 在 `registerBuiltInViews(builtinViewFactories)` **之后**（约 `:125`）调用：

```ts
activateNotePaper(); // 官方捆绑默认开
```

可关：抽 `shouldActivateOfficialNotePaper()`，默认 `true`；测 / 未来设置可注入 `false`。本维 **不必**做设置 UI。

`builtinViewFactories` **不加** `note` 键。`registerBuiltInViews` **不加**第 12 段。

### 4.2 视图 factory（喂源改到扩展，不喂死 Host）

红队补丁 **作废**：`docId={ctx.sessionId}` 且不传 `hydrateTransport`。

锁：

```
wsId     = getActiveProjectId() || getWorkspacePath() || 'default'
           （工作区键，禁止用 ctx.sessionId）
explicit = ctx.params?.docId          // URI note:<id> 或 open 时写入的 params
recent   = 本维可暂不接生产查询（无 list-recent IPC）
resolution = resolveProductStrictDocId({
             wsId,
             productStrictDocId: explicit,
             recentPersistedDocId: recent ?? null,
           })
transport  = createProductStrictHydrateTransport(resolution.docId)
```

渲染：

- `<NotePaperStrictPanel docId={resolution.docId} hydrateTransport={transport} />`
- 根上摊 `EMPTY_STATE_PAPER_HONESTY_ATTRS`（或同义）：`data-open-complete=not-claimed` 等（`workspaceEmptyStatePaperEntry.tsx:47-53`）。旧钉在死 Host 上；**新叶必须另钉**，禁止「旧钉还在、新叶不钉」
- 可摊 `buildStrictDocBindingDataAttrs(resolution)`（`workspaceEmptyStateStrictDoc.ts:120-127`）
- 侧效皮：`NotePaperStrictPanel.tsx:30-32` 已 import `chrome.css` / `paper-list.css`。扩展挂上后产品路径才会加载皮（`05` 复验，本维不改公式）

`NotePaperStrictPanel` 继续待在 `components/note-paper/`。**禁止**把面板搬进 `App` / `view-registry`。

本维 factory **不**承诺「打开即非空非 fixture」。无绑定时走 `strict-${wsId}` 诚实空（H1 第 4 档）。有 Tauri 仍 `source=tauri-ipc`；无 Tauri `fixture`、禁伪装。这是 G-HYD-3/4 纪律，**≠** `03` 打开完成。

### 4.3 把 UnitChrome 挂回 chat 叶（唯一产品主入口）

在 `TreeLeafPanel.tsx:180-181` 对称挂载（**leafBody 之外**，与 strip 同级）：

```tsx
{isChat ? (
  <UnitChromeActions activeSessionId={sessionForPanel} />
) : (
  <LeafToolTabStrip leaf={leaf} />
)}
```

- **不是**复活 `ChatHeader.tsx`（项目名行 + 搜索 + 30px 旧顶栏）。只挂已经拆出的 `UnitChromeActions`。
- **不是** `AppTopBar` 加笔记钮（窗口壳 ≠ 会话坞；且顶栏属红队/收敛工作区，`00` 勿动）。
- 多 chat：每片 chat 叶各一枚 UnitChrome，带自己的 `sessionForPanel`，坞不串会话（现 `openToolInSession` 已隔离）。

`UnitChromeActions.tsx`：

1. `UNIT_TOOL_PANELS` **增加**官方捆绑项 `{ id:'note', label:'打开笔记', testId:'chat-open-note', Icon: FileText }`
   - 这是 **捆绑默认 chrome 清单**，不是「note 变成内置视图」。视图仍只在 activate 后存在。
2. **渲染闸**：`viewRegistry.getView(id)` 为空则 **不渲染**该钮。用 `useSyncExternalStore(viewRegistry.subscribe, getVersion)`，activate/deactivate 后钮出现/消失。
3. 点击仍只走 `openToolInSession`，禁止 `setChatMainSurface`。
4. 四个旧工具同样过闸（防御；内置正常时恒真）。

C3 无需改 `LeafToolTabStrip`：activate 后 `getToolViews()` 自动含 `note`。

### 4.4 卸扩展后的叶（诚实 fallback）

`SlotOutlet.tsx:105-122`：有 `entryKey` 但 keyed 未命中时 **`return null`**，**丢掉** `fallback`。因此 `TreeLeafPanel.tsx:195-199` 的「未知面板类型」在未注册 `note` 时 **不会出现**（叶身空白）。

本维在 `TreeLeafPanel` 内、调用 `SlotOutlet` 前：

```
if (!resolved.definition) {
  渲染现有 emptyState：「未知面板类型：{leaf.activeTab}」
    + 若 activeTab==='note' 或 startsWith('note:')，可加一句「笔记扩展未激活」
  不进入 SlotOutlet
}
```

**不要**为这件事去改 `SlotOutlet` 通用语义（共享基础设施，越权）。本维只保证 note 卸掉后 chat 用户看得见诚实空，而不是白叶。

```

```
