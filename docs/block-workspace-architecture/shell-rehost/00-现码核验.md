### 2.2 `registerView` / 注销

`ViewRegistry.ts:54-84`：

```
registerView(view): () => void
  若同 id 已有 → 先跑旧 slot 注销
  views.set(id, view)
  slotCore.registerKeyed('workspace.leaf.panel', { id, key: id, component })
  返回 () => { 注销 keyed 槽; views.delete(id); version++; notify }
```

**API 支持注销。** 现码调用点只有 `registerBuiltInViews.tsx` 的 11 次，**全部丢弃返回值**。全仓再无 `registerView(`。没有「注销后叶子应变」单测（`ViewRegistry.test.ts` 只测 `clear()`）。

`registerBuiltInViews` 有一次性旗标：`isBuiltInRegistered && getView('chat')` 则直接 return（`registerBuiltInViews.tsx:58-60`）。这只挡内置批注册，**不挡** 之后再 `viewRegistry.registerView({ id: 'note', ... })`。

重入风险（额外）：第二次 `registerView` 同 id 会覆盖。第一次返回的注销闭包按 **id** 删当前表项，可能把第二次注册一并删掉。扩展 activate 必须自己持有**最后一次**返回值。

### 2.3 `SlotOutlet`

`SlotOutlet.tsx:91-197`：订 `slotCore` version → 按 `entryKey` 走 keyed，否则 single / list / chain → 失败用 `fallback`。外壳 `display: contents` + `data-slot`。叶子传入 `entryKey={resolved.definition?.id ?? leaf.activeTab}`（`TreeLeafPanel.tsx:194`）。未注册 id → keyed 空 → fallback「未知面板类型」。

槽契约：`SlotTypes.ts:21-24` `'workspace.leaf.panel'` kind=`keyed`，ownerProps=`ViewRenderContext`。

`registerKeyed` 返回删除该 key 的函数（`SlotCore.ts:60-76`）。与 `registerView` 注销对称。

### 2.4 URI resolver

`ViewRegistry.ts:21-51` 构造时只装 **一条** 内置解析器：前缀 `file-viewer:`，解析 `filePath / initialMode / line`。`resolveView`（`99-124`）：先精确 id，再按 prefix 扫 resolver。

`registerUriResolver`（`87-96`）也返回注销函数。产品侧 **零调用**（只定义）。没有 `note:` 解析器。

`ViewRegistry.test.ts:82-92` 期望 hash（`#architecture` / `#L20-L40`）被剥掉；现码 resolver **不处理 `#`**。测与码可能不一致。本文未跑测，标推断。

`isPrimary`（`ViewRegistry.ts:184-191`）：`chat` / `chat?` / `chat:` 或 `category === 'primary'`。同测 `99-100` 期望 `__pending_draft__` / `pending:new-session` 为 true——**现码做不到**。同样标推断。

### 2.5 路径数（本节）

内置视图路径 11。扩展注册 API 1 条（`registerView`）。URI 解析器活 1 条（仅 file-viewer）。注销 API 有、消费 0。

- **block-paper → contract + editor-kit。** 注释可提到桌面 `SlashMenuOverlay` 路径，无运行期 import 桌面。
- **桌面 `note-paper` 生产源码：主依赖 `@crish/block-paper`**（Strict 面板、chrome/list 挂载、slash、mdPrefix 等）。`@crish/editor-kit` 只在 `PaperListDomMount.test.tsx` 出现。`@crish/block-paper-contract` 只在 `editorSurface.ts:4` **注释**里出现（本地重定义 surface，避免等 contract 合并）。
- 三包 **都不** `import` `apps/crish-desktop` 作为模块。

方向（现码）：

```
block-paper-contract
        ↑
   editor-kit
        ↑
   block-paper
        ↑

```

总方案「实现留在包、桌面只宿主」与现码 **大体一致**。缺口：桌面 `package.json` 仍直依赖 contract / editor-kit（生产几乎不用）；`note-paper` 仍是 **应用内目录**，不是独立包。以后拆独立软件要搬的是这一整目录 + 对 `api/note*Ipc` 的桥。

包 3 + 桌面宿主 1。生产倒依赖 0。`note-paper` 仍在应用内。

## 8. 总方案「笔记用 registerView 当扩展」在现码上是否可行

总方案锁（`00-总方案.md` §1–2、§7）：调用已有 `registerView`（可注销）；**不要**把 `note` 写进内置 11；`main`/composition **可选** 调激活；`UnitChrome` 或等价活入口 `openToolInSession(..., 'note')`。

### 8.1 API：可行

| 条件 | 现码 |
| --- | --- |
| 不改 11 名单也能挂视图 | `registerView` 是公开方法，与 `registerBuiltInViews` 一次旗标无关 |
| 自动进叶子 Slot | 注册时写 keyed `workspace.leaf.panel` |
| 可卸 | 返回函数删 map + 槽 |
| 打开命令不拒绝未知 id | `openToolInSession` 不查表 |
| tool 叶加号自动发现 | `getToolViews()` 读当前注册表 |

扩展模块应：`category: 'tool'`（若标 `primary`，会被 `isPrimary` 当成对话域，flatten/坞逻辑会错）；`component` 适配器里自备 `docId` + `hydrateTransport`（上下文没有这两项）；可选 `registerUriResolver('note:')`；保存注销函数作 `deactivate`。

H1 resolver 与产品 hydrate 工厂 **已经存在**，只是喂死 Host。总方案「喂源改到扩展视图」是接线问题，不是缺 API。

### 8.2 产品发现：现码不够，且与总方案预锁有摩擦

1. **`UnitChrome` 不是活入口。** 总方案 §7 写「`UnitChrome` 或等价活入口能 `openToolInSession(..., 'note')`」。现码 `UnitChromeActions` 未挂载，且四钮写死不含 note。chat 叶又无 Tab 条。只 `registerView` **用户从主对话叶点不出笔记**。
2. 冷启动工具列折叠 + chat 叶无 strip → 加号菜单要等先打开别的 tool。这不是 API 不行，是缺第一条产品手势。
3. 注销后若 dock/tabs 仍留着 `note`，叶子变「未知面板」。没有自动收坞。
4. 内置批注册丢弃注销函数；无 deactivate 测。
5. `ViewRenderContext` 不承载 hydrate。工厂必须自己调 `createProductStrictHydrateTransport` + H1（或把 persist id 放进 `params`）。

**可行，不等于已经能用。** 总效果仍要求：激活模块 + 一条用户摸得到的打开。打开完成（真 WebView + persist 非 fixture）按总方案仍是下一刀。
