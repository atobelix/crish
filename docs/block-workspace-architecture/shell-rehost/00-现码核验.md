## 1. 产品主壳调用链

### 1.1 启动

`apps/crish-desktop/index.html` 加载 `/src/main.tsx`。`startup()` **先** `registerBuiltInViews(builtinViewFactories)`（`main.tsx:129`），再条件调用 `activateNotePaper()`（`main.tsx:131-133`），再 bootstrap、再 `createRoot` 挂 `App`。

### 1.3 叶子怎么出内容

```
BinaryTreeWorkspace
  flattenTree(...)
  → 每个 FlatPanel → TreeLeafPanel
       resolveView(leaf.activeTab)
       chat 叶 → UnitChromeActions（挂 leafBody 外）
       非 chat 叶 → LeafToolTabStrip

         → slotCore.getKeyed → view.component(ViewRenderContext)
```

`ViewRenderContext` 仍是 `panelId / leafId / sessionId / isActive / openView / fallbackTitle / params`。**没有** `docId`、`hydrateTransport`——笔记工厂自己解析。

### 1.4 路径数（本节）

活入口 **1**：`App` → BinaryTree。死壳 `Workspace` **已删**。叶子内容出口 **1**：keyed `SlotOutlet`。

## 2. viewRegistry：id 清单与 API 实样

### 2.1 内置仍 11，无 note

`registerBuiltInViews.tsx:53-163` 与 `main.tsx:26-110` `builtinViewFactories` 对齐：`chat` / `terminal` / `preview` / `overview` / `files` / `diff` / `runtime` / `agent` / `browser` / `flow-dag` / `file-viewer`。注释仍写「全部 11 个」。**没有**把 `note` 写进内置表。

`getToolViews()` = `category === 'tool'`。`file-viewer` 是 auxiliary，不进加号。`chat` 是 primary，不进。

### 2.2 `registerView` / 注销

`registerView` 仍返回注销函数，并挂 keyed `workspace.leaf.panel`。

现码调用点：

- `registerBuiltInViews` 11 次（返回值仍丢弃）
- **`activateNotePaper`** 持有最后一次注销，作 `deactivateNotePaper`（`activate.ts:34-63`）

同 id 重入：activate 先跑旧 `currentDeactivate` 再注册，自己持有最后一次 unsub。

`registerBuiltInViews` 一次旗标只挡内置批注册，**不挡**之后再 `registerView({ id: 'note' })`。

### 2.3 `SlotOutlet`

叶子传入 `entryKey={resolved.definition?.id ?? leaf.activeTab}`。未注册 id → keyed 空 → fallback「未知面板类型」。activate 之后 `note` 有 definition，走 `NoteLeafHost`。

### 2.4 URI resolver

内置仍只装 `file-viewer:`。`activateNotePaper` **额外** `registerUriResolver(NOTE_URI_RESOLVER)`（`note:`）。产品侧不再是「零调用」。

### 2.5 路径数（本节）
