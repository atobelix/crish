## 0. 结论先行

1. **高度链只许 CSS 包含块**（flex 吃剩余 + `min-height:0`）。禁止 rAF / `ResizeObserver` / `getBoundingClientRect` **补高度**。现码叶子几何是 **abs + flatten 百分比**，不是量盒。
2. **叶子仍是 abs + `%`。** 不要改成全树 flex 重排。`flattenTree` 出 0–1 rect；`layoutEffect` / sash `paintFlatLayout` 只把 `%` 写进已有节点。
3. **`activate` 必须 lazy。** 启动路径不得同步拉 `NotePaperStrictPanel` / `@crish/block-paper` 整树。现码 `App` / `main` / 二叉树 / `UnitChrome` **还没**拖进纸面核；02 若静态 import 工厂，会一次拖进 CSS + chrome + PaperList + slash。
4. **`UnitChrome` 的 `viewRegistry` 订阅：现码没有。** 02 若按详案把 `useSyncExternalStore(viewRegistry.subscribe, getVersion)` 放进 `UnitChromeActions`，**只打挂了 chrome 的 chat 叶，不打 tool 叶、不打 ChatCard。** 但 `registerView` 会 `slotCore.bump('workspace.leaf.panel')`，**所有叶的 `SlotOutlet` 都会重渲一次**——这是现成插槽语义，activate/deactivate 各一次可接受。禁止把订阅抬到 `TreeLeafPanel` / `BinaryTreeWorkspace`。
5. **`ConexFloatHandle` 16.6ms 测距：组件还在，产品挂载已被把手 Agent 从 `NotePaperStrictPanel` 卸掉。** 产品路径（含将来 02 工厂挂 Strict）**不再**跑这段 pointermove。文件与单测仍在，任何人再 import 就会回到产品路径。01/02 **禁止**挂回，也禁止把测距抄进高度链。
6. **本轮禁止的「优化」**：预解析整篇、环形缓冲、95% `React.memo` 门禁、为 flatten 加 Worker、用观测器给叶子补高、新插件运行时。见 §6。

## 2. 高度链必须保持 CSS O(1)，禁止量盒补高

### 2.1 现码几何（不是量盒）

```
flattenTree(root)                    // 纯函数，0–1 rect，无 DOM
    │
    ├─ BinaryTreeWorkspace useMemo    // 树变才算；stabilize 复用 leaf/rect 引用
    │
    ├─ TreeLeafPanel layoutEffect     // 写 top/left/width/height = rect*100 + '%'
    │                                 // body.tree-resizing 时直接 return，不覆盖 sash
    │
    └─ useTreeResize.paintFlatLayout  // 仅 sash 手势：同一套 % 直写 leaf/sash
                                      // 启动手势时 canvas 量一次像素，算 ratio
```

证据：

- `layoutTreeFlatten.ts:62-78`：单次递归，输出百分比 rect；折叠域宽/高压 0。
- `BinaryTreeWorkspace.tsx:147-154`：`useMemo` 调 `flattenTree`；`156-162` 按 id 复用 `LayoutLeaf` / rect，避免父级 re-render 打穿 `React.memo`。
- `TreeLeafPanel.tsx:113-127`：注释写明「几何由 layoutEffect 写 DOM，不用 React style prop」；**只写 `%`，不读盒**。
- `useTreeResize.ts:130-180` `paintFlatLayout`：同样写 `%`；`238` `getBoundingClientRect` **只在 `startResize` 一次**，把 branch 的 0–1 换成像素算 ratio，**不是**给叶子补 `height: Npx`。
- `useTreeResize.ts:296-322`：pointermove 用 rAF 刷 `%`。这是 **sash 跟手**，不是高度链。

包含块（01 要补的那条）必须让「`height: 40%` 相对画布确定高」成立。现码断点仍在：`#root` / `.app-container` / `.main-layout` / `.workspaces-*` **零规则**（`00-现码核验.md` §6；`index.css:1-10` 无 `shell-layout.css`）。`.canvas` 仍 `height: auto`（`BinaryTreeWorkspace.module.css:33-39`）。父级 auto 时子级 `%` 解成 0——这是 **CSS 断链**，不是「没量到」。

### 2.2 O(1) 的含义

对每一层盒子：**只靠父级已确定的高度 + 自己的 flex / `%` 一次解析**。N 个叶子 = N 次百分比指定，**没有**「量第 i 个再写第 i+1 个」的链式 layout。

01 已锁的公式（`01` §1.2）：列/行 flex 吃剩余 + 每个 flex 子项 `min-height:0`（行上再加 `min-width:0`）。禁止 `calc(100vh - var(--header-height))` 当主公式。禁止 `100dvh` / `100svh` 双单位。禁止 `transform` 打飞 fixed。

`.leafBody` 已是 `flex: 1 1 0%`（`:318-332`）。`.leafBody > * > *` 的二级 fill 归 **05**，本轮不要用 JS 去「保护顶栏高度」。

### 2.3 禁止的补高（出现即本轮失败）

| 禁 | 为什么 |
| --- | --- |
| `ResizeObserver` 看 `#root` / `.canvas` / `.leaf` 再 `el.style.height = px` | 量盒补高；每帧/每次 resize 强制 layout |
| `requestAnimationFrame` 循环把 canvas 高抄给叶子 | 高度链变轮询；与 sash 已有 rAF **抢同一条热路径** |
| `getBoundingClientRect` / `offsetHeight` 写进 `layoutEffect` 当叶高 | 破坏 `%` 模型；live resize 时会和 `paintFlatLayout` 互踩 |
| 给 `.leaf` 写 `min-height: 300px` / 复活 `is-narrow` | 假保底；01 已否。现盘已无该段，禁止加回 |
| `MutationObserver` / `IntersectionObserver` 侦叶子再补高 | 新观测器框架；解决不了包含块 |
| 把 `SkeletonFallback height={400}` 改成「量完再铺」 | 400 是 loading 闪一下，不是 0 高根因（`01` §3.3） |

**允许（已存在，不要借机删，也不要扩到高度链）：**

- sash **启动**时对 canvas 量一次像素（`useTreeResize.ts:238`）。
- sash **拖拽中** rAF 写 `%`（不是写 px 高）。
- 9222 **验收读** `getBoundingClientRect().height > 0`（`01` §6.1 B）。读 ≠ 写。

### 2.4 01 落地时的性能验收（源码层）

- 新表只有几何，无皮、无 `transform`、无 `!important`、整文件 ≤ 120 行（`01` §2.2）。
- 高度链 CSS **不得** `@import` / 引用 `@crish/block-paper`（`08`：高度链不得 import 纸面核）。
- `TreeLeafPanel` layoutEffect **仍只写 `%`**。diff 里若出现 `rect.height` 以外的 px 赋值 → 打回。
- 不要求本轮给高度链加 benchmark。骨架落盘 ≠ 视口交付；9222 未绿不得说「主区能看见」。

## 3. 叶子仍 abs + `%` 时，不要改成全树 flex 重排

### 3.1 现模型

| 层 | 定位 | 证据 |
| --- | --- | --- |
| `.canvas` | `position: relative`；流内 flex 子，吃 section 剩余 | `BinaryTreeWorkspace.module.css:33-45` |
| `.leaf` | `position: absolute`；几何全靠 inline `%` | 同文件 `:52-78`；`TreeLeafPanel.tsx:123-126` |
| sash | 绝对定位在 branch 分割线 | `paintFlatLayout` `:168-178` |
| `.leaf` 内部 | **叶内** 才是列 flex（strip + `leafBody`） | `:66-68`、`:318-332` |

`flattenTree` 与 sash 的契约是：**同一套 0–1 矩形**。拖拽时 `body.tree-resizing` 让 `layoutEffect` 让路，避免 React 把两侧拽回 store 旧 rect（`TreeLeafPanel.tsx:115-117`）。

### 3.2 为什么不能改成全树 flex

把叶子改成流内 `flex: 1` / 嵌套 flex 行：

1. `flattenTree` 的 `%` 与 sash `splitRatio` **立刻失效**，要重写整棵树的布局算法。
2. 多叶 + 折叠域（`collapsedDomain: 'tool'` 宽压 0）在 flex 里会变成「最小内容宽」而不是 0，默认单 chat 解折叠语义变。
3. live resize 现在是 **O(叶数) 写 style**、零 React commit（`paintFlatLayout`）。改 flex 后每次 pointermove 会触发浏览器对整棵 flex 树重排，还要解决「store 旧 ratio vs 跟手」——`layoutEffect` 注释里的 bug 会回来。
4. 01 已点名：红队把 `.leaf { flex: 1 1 0% }` 当病灶是写错层——叶子是 abs，改 flex **改变不了** 百分比高（`01` §1.1「不是路径」；§7.6）。

**本轮锁死：**

- **不要**改 `.leaf` 的 `position: absolute`。
- **不要**给 `.canvas` 加 `display: flex` 指望撑高子级（`01` §2.4：子级全是 abs，流内仍无子项）。
- **不要**把 `flattenTree` 改成读 DOM 量宽再回填。
- **不要**为「好写」把二叉树换成 CSS grid / 嵌套 flex 分栏。
- 叶 **内部** 保持 flex（strip 锁高、`leafBody` 吃剩余）。02 把 `UnitChromeActions` 挂在 `leafBody` **之外**、与 strip 同级（`02` §4.3）——chrome 必须 `flex: 0 0 auto`，**禁止**再给 chrome 量高后去改 `leafBody`。

`BinaryTreeWorkspace` 已有的 `stabilizeLeafEntries` / `stabilizeBranches` + `TreeLeafPanel` `React.memo`（按 leaf 字段 / rect / flags 比较）是 **现成、够用** 的跳过重绘。本轮不要再包一层「全树 memo 框架」。

## 5. UnitChrome 的 `viewRegistry` 订阅会不会打到所有叶

### 5.1 现码：没有这路订阅

`UnitChromeActions.tsx` **零** `viewRegistry` / `useSyncExternalStore`。全仓生产组件里，**没有** `viewRegistry.subscribe` 的 uSES。

现成、会打到 **每一叶** 的是另一条：

```
registerView
  → slotCore.registerKeyed('workspace.leaf.panel', { key: id, component })
  → SlotCore.bump(slotKey)                         // SlotCore.ts:60-68, 130-132
  → 该 slotKey 的全部 listener

每个 TreeLeafPanel 里一个 SlotOutlet
  useSyncExternalStore(slotCore.subscribe(slotKey), getVersion(slotKey))
  // SlotOutlet.tsx:98-101
```

因此：**只要 02 调用 `registerView('note')`（即便 component 是 lazy），所有已挂叶的 `SlotOutlet` 会因 version++ 重渲一次。** 默认单 chat = 1 叶；分屏 = 叶数。activate / deactivate 各一次，不是指针热路径。

`TreeLeafPanel` 自己在 render 里同步读 `resolveView` / `isPrimary` / `getTitle`（`:142-143,178`），**不订阅**。表变了若父级不 re-render，叶子标题/闸不会自己更新——所以 02 才要在 **按钮上** 订表。

`LeafToolTabStrip` 在 render 里 `getToolViews()`（`:80-83`），也 **不订阅**。C3 靠「坞展开后 strip 本来就会随 leaf props 画」；不要为 C3 再给每个工具叶订一份全局表。

### 5.2 02 计划中的订阅：打哪些叶

`02` §4.3：

> 渲染闸：`viewRegistry.getView(id)` 为空则不渲染该钮。用 `useSyncExternalStore(viewRegistry.subscribe, getVersion)`。

`ViewRegistry.notify` 遍历 **全部** `listeners`（`ViewRegistry.ts:204-206`）。`getVersion()` 是一个全局计数，任何 `registerView` / `registerUriResolver` / `clear` 都会 ++。

挂载点（`02` §4.3）是 **chat 叶、`leafBody` 外**：

```
TreeLeafPanel
  UnitChromeActions      ← 仅 isChat；uSES 订 viewRegistry
  leafBody
    SlotOutlet           ← 订 slotCore（已有）
```

| 订阅放哪 | 谁重渲 | 本轮 |
| --- | --- | --- |
| `UnitChromeActions` 内部（详案） | **每个 chat 叶的工具条**。默认 1；多 chat = chat 叶数。**不**重渲 tool 叶，**不**重渲 `ChatCard`（memo 边界在 `TreeLeafPanel`，uSES 在子组件） | **允许** |
