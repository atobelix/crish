**一句话**：

> **当前栈（Tauri + TS + RS）没有拉低本产品的可验证上限。**

> 真正会拉低上限的，是选 AFFiNE/Docmost 式 **JS 真相**、AppFlowy 式 **Flutter 皮**、SiYuan/Anytype 式 **第二原生语言 + 重壳/闭许可**、或 VNote 式 **无块/无协同/无 TS 扩展**。

### 1.1 各路「理论上限」与「结构天花板」

#### 1 · Electron + BlockSuite/Yjs（AFFiNE）

| 项       | 证据 / 含义                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 真相层   | Yjs 在 **JS**；编辑热路径不经 Rust（round-A `06`）                                                                             |
| 大文档   | Page 模式全量子树挂载，**无文档级虚拟化**（`05` R1）；Yjs 堆 + Undo 同进程                                                     |
| 壳       | Electron 39 + UtilityProcess + 隐藏 worker 窗 → 基线内存税                                                                     |
| Native   | SQLite/FTS/y-octo 侧车；**非**块树权威（`06`）                                                                                 |
| 上限结论 | 块交互/远端选区/扩展 **产品完成度最高标尺之一**；**性能与 AI 批量写的理论上限被「CRDT+模型在 V8」锁死**。嵌它 = 继承该天花板。 |

#### 2 · Flutter + Rust（AppFlowy）

| 项       | 证据 / 含义                                                                                                                 |
| -------- | --------------------------------------------------------------------------------------------------------------------------- |
| 真相层   | **yrs + collab 在 Rust**；UI 发事件（round-B `02`）                                                                         |
| 协同洞   | syncV2 注释未全实现；退回 diff/forceReload（round-B `04` D5）                                                               |
| 皮       | Flutter 与 **TS 扩展生态结构性互斥**（`04` D1）                                                                             |
| 许可     | **AGPL-3.0** 禁整仓嵌入                                                                                                     |
| 上限结论 | 「心」方向正确，证明 **RS 权威可量产**；终局皮若锁 Flutter，则 **AI 工作栈 Web/TS UI 与扩展上限被砍**。不可作本产品终局栈。 |

#### 3 · Electron + Go kernel（SiYuan）

| 项       | 证据 / 含义                                                                                                                                                                                                                  |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 架构     | Go `kernel/` 权威 + TS Protyle + Electron（`siyuan/AGENTS.md`）                                                                                                                                                              |
| 事务     | `PerformTransactions` + `flushLock` 串行队列（`kernel/model/transaction.go`）                                                                                                                                                |

## 2. 理论最优组合（忽略本仓）— 拆层定义

在 **完全不参考 Conex/Crish 现状** 的前提下，为目标效果选栈：

```
┌──────────────────────────────────────────────────────────────┐
│ 皮：单一 TS/Web UI 运行时                                      │
│  · 块视图 / slash / 把手 / 多选 / 静默纸面 / AI 对话呈现         │
│  · TS 扩展注册表（store 能力 vs view 装饰分轨）                 │
│  · 行级流式编辑器（AI 输出）与块树纸面 **并存**，权威不在行级    │
├──────────────────────────────────────────────────────────────┤
│ 壳：轻量原生 WebView 宿主（Tauri 类；非 Electron 多进程默认）    │
│  · 只做窗口/IPC/权限/系统能力；不持文档真相                     │
├──────────────────────────────────────────────────────────────┤
│ 心：原生领域内核（语言优选 Rust，Go 为同构次优）                 │
│  · 块树模型 + 增量 Op + 事务串行/可测合并                        │
│  · CRDT 或等价 merge **在此层**（非渲染进程 JS）                 │
│  · 存储（SQLite/快照/blob）+ 索引（FTS）                       │
│  · Agent/MCP：block/document/search… 工具面直接打在此层          │
│  · MD ⟷ 块树 一等序列化契约                                    │
└──────────────────────────────────────────────────────────────┘
```

### 2.1 为何不是「某一家现成栈」整体更高？

| 若整体采用    | 立刻输掉的维度                                          |
| ------------- | ------------------------------------------------------- |
| AFFiNE 整栈   | A（大文档/JS CRDT）、壳内存；E 批量写易爆堆             |
| AppFlowy 整栈 | G（TS 扩展）、H（AGPL）、B（协同洞）                    |
| SiYuan 整栈   | H（AGPL）、壳、B（实时协同）、与 AI 栈双语言            |
| Anytype 整栈  | H（Source Available）、F（MD 非一等）、对象模型绑架产品 |
| Logseq 整栈   | B、G、H、E                                              |
| VNote 整栈    | B、C、E、G                                              |
| Docmost 整栈  | A、E、F、H、本地 AI 工作栈深度                          |

**最优是「机制拼图 + 自研装配」**，不是「星数最高的 monorepo fork」。

### 2.2 心语言：Rust vs Go vs C++（忽略本仓）

| 心语言   | 支持论据                                                                                               | 反对/降维                                                   |
| -------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| **Rust** | AppFlowy yrs 生态；与高性能索引/加密同生态；无 GC 停顿利于大合并；**若 AI 运行时也用 RS 则零第二原生** | 块编辑器 UI 库不如 Web 生态（故皮必须 TS）                  |
| **Go**   | SiYuan/Anytype **已量产** 内核权威 + 工具面                                                            | 与 RS AI 栈并存 = 双原生；GC；与 Tauri 集成常见但非第一公民 |
| **C++**  | VNote 写作路径；极致原生                                                                               | 扩展/AI/协同生态与交付成本；与 TS 扩展宿主割裂              |

**忽略本仓仍选 Rust 为心**：不是因为「仓里已有」，而是 **在「还要做 AI 工作栈」前提下，单原生语言闭环的上限更高**。若产品 **没有** AI 运行时约束，Go 心（SiYuan 同构）与 Rust 心 **同构**，上限接近；**有** AI 原生时 Rust 胜出。

### 2.3 壳：Tauri vs Electron vs 纯原生

| 壳                   | 上限                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------- |
| **Tauri 类**         | 壳税最低档之一；IPC 清晰；与 RS 心同进程友好                                            |
| **Electron**         | 能跑满 TS 皮与调试体验；**基线内存/多进程** 永久税（AFFiNE/SiYuan/Logseq/Docmost 均付） |
| **纯 Qt 无 WebView** | 写作 D 维可更高；**C/G/E** 崩盘                                                         |

忽略本仓：**仍选轻量 WebView 壳**；Tauri 是该类中与 Rust 心匹配度最高的量产选项，不是「因为仓库用了」。

## 3. 路径依赖审计：先前推荐压低了什么？

对照 09 / 10 表述 vs 跨产品上限：

| 10/09 表述                                 | 是否路径依赖                                | 是否压低上限                       | 修订                                                                                |
| ------------------------------------------ | ------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------- |
| 「栈形态锁定 Tauri+TS+RS 是唯一同时满足…」 | **部分**（「与现有 Agent 同进程」依赖本仓） | **否**                             | 改为：**跨产品论证下的最优**；同进程是 **加分闭包**，不是唯一合法性来源             |

| 「心永远 Rust」                            | 若无 AI 栈，Go 同构                         | **对无 AI 产品略窄；对本产品不窄** | 维持 Rust；写明 **Go 为同构次优，不因「Go 笔记更成熟」换心**                        |

| 「行级与块并存」                           | 弱依赖本仓 markdown-editor                  | **否**（AI 流式普遍需要）          | 维持硬锁；行级权威化 **否决**                                                       |

### 3.1 被「本仓现状」可能 **误伤** 的维度（诚实列出）

| 维度                               | 风险                                                                                       | 是否构成换栈理由                                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| **WebView IME / 合成** 相对纯 Qt   | 中文 IME、候选窗、强制布局：Web 路径有历史坑（AFFiNE 亦有 composition 特判与整树重绘回退） | **否**。应用 **本仓 markdown-editor 级 IME 纪律 + 不整树拆** 打穿；换 Qt 丢块/协同/扩展 |
| **块 UI 冷启动完成度**             | 自研皮前期弱于 AFFiNE/Protyle 开箱                                                         | **否**。完成度靠清单验收，不靠嵌引擎；嵌引擎 = 继承 JS/Go 真相                          |
| **note-gen 同壳样本偏「采集+MD」** | 证明 Tauri+AI 可出货，**不**证明块工作区已有上限样本                                       | **否**。说明 **缺口在块心，不在壳**                                                     |

**结论**：路径依赖存在于 **措辞与落地便利**；**不存在**「因本仓 Tauri 而被迫接受更低理论天花板」的选型错误。

## 4. 可验证上限排序（效果完整度）

> 排序键：六维乘积（块×协同×AI 工具×TS 扩展×大文档×静默），不是单一明星维。

| 秩    | 路径                                               | 理由（可验证）                                                   |
| ----- | -------------------------------------------------- | ---------------------------------------------------------------- |
| **1** | **Tauri + TS + Rust 心（自研块/协同/MD/tools）**   | 无维被结构锁死；壳税低；心可与 AI 同语言；扩展语言正确；许可自由 |
| **2** | **轻壳 + TS + Go 心（SiYuan 同构、非 AGPL 自研）** | 与 #1 同构；若 AI 心也是 Go 则接近；双语言或换 AI 栈则降为 3     |
| **3** | **Electron + TS + 原生心（RS/Go）**                | 皮/心可顶；**永久壳税** 使 A/内存输 #1                           |
| **4** | **AppFlowy 形 Flutter+RS**                         | 心强；**G 维结构失败**                                           |
| **5** | **AFFiNE / Docmost 形 JS 真相**                    | C/B 产品完成度高；**A/E 批量写天花板**                           |
| **6** | **Anytype 形对象+CRDT 中间件**                     | B/对象强；**H/F 与 MD 工作栈错位**                               |
| **7** | **Logseq 形 CLJS+DataScript**                      | query 强；协同/扩展/AI 工具面非顶                                |
| **8** | **VNote 形纯 Qt MD**                               | D/A 单人写作强；产品形态不覆盖目标                               |

**#1 不是「我们只能做这个」——是「这个集合里没有更高总上限」。**

## 5. 中途换栈的真正诱因清单（与正确反应）

## 6. 细节关注：六维红线

### 6.1 IME

| 来源         | 事实                                                        | 本产品锁                                                               |
| ------------ | ----------------------------------------------------------- | ---------------------------------------------------------------------- |
| AFFiNE       | composition 特判；异常路径 `rerenderWholeEditor`（`05` R3） | **禁止** IME 触发整编辑器拆树                                          |
| WebView 通病 | 候选窗与 DOM 选区不同步                                     | 组合态期间：**本地缓冲 + 提交后再 commit op**；可复用行级引擎 IME 组件 |
| VNote/Qt     | 原生 IME 路径理论上限高                                     | **不**因此改终局壳；用测试锁中文/日文连续输入                          |

### 6.2 虚拟化

| 来源     | 事实                                                    | 本产品锁                                            |
| -------- | ------------------------------------------------------- | --------------------------------------------------- |
| AFFiNE   | 列表 virtuoso；**正文无**文档级虚拟化；表虚拟滚动默认关 | **打开文档**必须窗口化；验收轴=打开大文档/滚动/输入 |
| AppFlowy | 树↔扁平适配 + 重载路径放大闪烁风险                      | 前端只持 **投影窗口**，不持权威全树 DOM             |
| SiYuan   | 百万字宣称 + 内核索引；Protyle 仍为 contenteditable 向  | 学其 **索引/事务**；不学其 HTML 字符串权威          |

### 6.3 CRDT / 合并位置

| 路径             | 位置                                                          | 裁决                                 |
| ---------------- | ------------------------------------------------------------- | ------------------------------------ |
| AFFiNE / Docmost | **JS Yjs**                                                    | **否决为权威**                       |
| AppFlowy         | **Rust yrs**                                                  | **方向正确**；补齐增量 apply 完成度  |
| Anytype          | **Go Any-Sync**                                               | 机制可学；许可与语言不入国           |
| SiYuan           | 事务队列，**非**实时 CRDT 主叙事                              | 学串行 apply；实时多人另建 RS collab |
| **本产品**       | **`conex-doc-collab`（RS）**；TS 只发意图、收投影与 awareness | **硬锁**                             |

库名（yrs / 自研 / 其他）**可演进**；「合并在 RS」**不可推翻**。

### 6.4 Agent 块 API

## 7. 修订后的锁定声明（相对 10 号）

### 7.1 维持（仍是终局）

1. **文档/块/协同/索引权威在 Rust**（从第一行可写代码起）。
2. **壳 = 轻量 WebView 宿主（落地 Tauri 2）**；禁止 Electron 终局。
3. **皮 = 单一 TS UI 运行时**；禁止 Flutter；禁止 React+Lit 双栈。
4. **行级流式引擎 ∥ 块树权威**；禁止行级冒充块。
5. **MD 往返 = 契约**；**doc-tools/Agent 工具面 = 一等**。
6. **不 fork** AFFiNE / AppFlowy / SiYuan / Anytype / Logseq / Docmost；AGPL/Source Available **不入国**。
7. 默认纸面 = **静默 MD 写作 + 块操作**；DB/画布可后挂、默认可关。

### 7.2 修订（相对 10 号修辞与论证）

| 10 号原意                             | 修订                                                                                                  |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 「唯一同时满足…」偏 **本仓便利** 论证 | 改为：**Round C 跨产品上限论证下的最优组合**；本仓已有 = 落地同构优势，**不是**上限来源               |
| 对 Go 心着墨偏「不要第二语言」        | 补强：**Go 心与 Rust 心同构**；在「无 AI 运行时」假设下二者接近；**在 AI 工作栈假设下 Rust 严格更优** |
| 对纯原生写作上限未显式裁决            | 补强：**VNote/Qt 在 D 维可更高，总上限更低**；不换栈，用 IME/虚拟化验收打穿 WebView 路径              |
| 「评审前可修订」                      | **本文即上限裁决**；10 号方向 **不推翻**；后续评审应审 **实现契约与验收断言**，而非重开壳/心语言      |

### 7.3 最终锁定句（替换 10 号 §6 的论证基础）

> **在忽略任何既有仓库绑定的前提下**，为「AI 工作栈级块笔记 + 静默写作 + 多人协同 + TS 扩展 + 大文档性能」选取的 **理论最优栈** 是：
> **轻量 WebView 壳（Tauri）+ 单一 TypeScript 皮 + Rust 文档权威心（块树 · 增量 op · 协同合并 · 存储索引 · Agent/MCP 工具面）+ Markdown 一等契约。**
>
> 该结论由 AFFiNE（皮标尺/JS 天花板）、AppFlowy（RS 心标尺/Flutter 互斥）、SiYuan（工具面与 MD/事务标尺/AGPL·Go·Electron 代价）、Anytype（中间件心/许可与 MD 错位）、Logseq（query 标尺/生态隔离）、Docmost（Yjs 样板/JS 上限）、VNote（原生写作单维）、note-gen（Tauri+AI 壳可行但块心未给出）交叉证伪「更高总上限存在」而得。
>
> **本仓已有 Tauri/TS/RS 与 Agent，并不降低该上限，而是与该最优组合重合。**
> **中途只允许换模块实现，不允许换壳品类、心语言、或真相所在层。**
> **这不是过渡方案，就是终局方案。**
