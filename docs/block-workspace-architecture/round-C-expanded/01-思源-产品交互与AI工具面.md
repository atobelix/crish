## 1. 产品定位与架构摘要

### 1.1 定位（官方口径）

思源是**隐私优先的个人知识管理系统**：细粒度块级引用 + Markdown 所见即所得。
证据：`README.zh-CN.md:69-116`（内容块 / 编辑器 / 数据库 / 闪卡 / OpenAI / API / 集市）。

核心卖点与本分析相关：

| 能力                     | 说明                                         | 证据                                         |
| ------------------------ | -------------------------------------------- | -------------------------------------------- |
| 块级双链                 | 任意块有稳定 ID，支持引用、嵌入、反链        | README 特性；MCP `ref` 工具                  |
| WYSIWYG 块编辑           | Protyle + Lute AST                           | `AGENTS.md:93`；`docs/SY-FORMAT.zh-CN.md:10` |
| 大文档                   | 动态分块加载（非整树 DOM 虚拟列表）          | `app/src/protyle/scroll/event.ts:84-119`     |
| 数据库（Attribute View） | 表/看板/画廊 + 行虚拟滚动                    | `kernel/av/`；`render/av/virtualScroll.ts`   |
| HTTP API + MCP + CLI     | 多入口改数据，默认不直改 `.sy`               | `docs/SY-FORMAT.zh-CN.md:16-33`              |
| 内置 AI Agent            | 系统提示注入领域模型 + 写操作确认 + 本地快照 | `kernel/agent/agent.go:43-119`               |

### 1.2 仓库分层

| 层           | 路径                                   | 职责                                              |
| ------------ | -------------------------------------- | ------------------------------------------------- |
| 领域/事务    | `kernel/model/`                        | 块树、事务、索引、搜索、AV、历史、同步            |
| 树节点       | `kernel/treenode/`                     | 内存 BlockTree + 容器校验                         |
| HTTP API     | `kernel/api/`（`router.go` ~400 端点） | 前端与第三方统一入口                              |
| MCP 工具     | `kernel/mcp/tools/`                    | 原生工具注册；Agent 与外部 MCP 共用               |
| Agent        | `kernel/agent/`                        | LLM 循环、确认、快照、工具执行                    |

| 前端 AI 遗留 | `app/src/ai/`                          | 选区 AI 写作（slash「AI 编写」）                  |

`AGENTS.md:51-99` 给出完整模块地图。

### 1.3 数据模型一句话

`.sy` = Lute AST 序列化 JSON，根恒 `NodeDocument`，一切状态在树里（`docs/SY-FORMAT.zh-CN.md:10`）。
块 ID 稳定且跨引用；**官方路径（HTTP/MCP/CLI）**负责 AST 序列化与双索引（`blocktree.db` + `siyuan.db` FTS5）同步；直改盘需重建索引（同文档 §0.5）。

Agent 系统提示对领域做了可操作定义（容器块 vs 叶子块、标题下内容是**后续兄弟**而非 children、列表嵌套规则、hPath vs 内部 path）——`kernel/agent/agent.go:45-53`。这对工具契约设计极有参考价值。

## 2. 产品交互清单（有代码证据）

### 2.1 Slash / Hint 面板

### 3.3 操作粒度：文档级 vs 块级

```
Notebook
  └── Document (NodeDocument, 也是块)
        ├── Heading / Paragraph / List / SuperBlock / AV / ...
        └── 标题「下级内容」在 AST 中是 following siblings（agent.go:48）
```

| 意图       | 推荐工具链                                                             |
| ---------- | ---------------------------------------------------------------------- |
| 找内容     | `search.fulltext` → `block.get` / `batch_get`                          |
| 探结构     | `document.list` → `document.get` → `block.get_children` → `breadcrumb` |
| 新建       | `document.create` → `block.append/insert`                              |
| 改一节     | `block.update`（**仅该块**）                                           |
| 改并追加   | `update` **然后** `append/insert`（工具描述强制约定）                  |
| 整文档搬家 | `document.move`（hPath）；块内重排用 `block.move`                      |
| 日记       | `dailynote.*` 而非 `document.create`                                   |

`block.update` 会 **pin 原 ID**，防止 Markdown→DOM 生成新 ID 导致引用断裂（`block.go:300-354`，注释对照 HTTP `updateBlock`）。

容器校验：仅 `parentID` 无兄弟锚点时 `CheckContainerParent` / `CheckListItemNesting`（`block.go:168-172, 411-418`）——降低 Agent 造非法树的概率。

### 3.4 批量改的安全性（Agent 视角）

思源做了多层护栏，**不是「LLM 直接写盘」**：

1. **写操作 UI 确认**
   - 系统提示：`Write operations ... auto-prompt the user via UI`（`agent.go:119`）
   - `needsConfirm`：`ActionEffects` 优先；否则 `safeActions` 白名单只读 action；外部 MCP/插件未知能力默认确认（`agent.go:1098-1154`）
   - `safeActions` 含 get/list/search/breadcrumb/…；**写 action 禁止与只读同名**（注释 `1099-1100`）

2. **本地仓库快照**
   - `needsLocalSnapshot`：本地写可先快照，支持回滚事件（`agent.go:1157-1183`；session 测试含 `rollback` 类型）

3. **副作用元数据**
   - `Tool.EffectScope`：local / external / mixed / unknown（`types.go:21-42`）
   - `ActionEffects`：`LocalRead/LocalWrite/DataEgress/ExternalCost` 四维（`types.go:48-53`）
   - 部分工具已精细化（search/image/skill/sql）；多数原生工具仍靠 `safeActions` + 默认 local 推断

4. **执行中断语义**
   - `executeTool`：ctx 取消时返回 `executionUnknown`，**禁止自动重试**（`agent/tools.go:44-97`）——避免重复插入

5. **Image 幂等**
   - `image.go` 用 operation key 落盘记录，同 key 可复用结果（`runImageOperation` / `image_test.go`）

6. **MCP 鉴权**
   - Admin + Readonly 中间件；管理级原语不可匿名（`server.go:29-30`）

7. **粒度克制**
   - MCP `block` **没有** HTTP 级 `batchUpdateBlock`；LLM 侧是逐块/逗号 ids 的 batch **读**（batch_get/batch_kramdown）
   - 写仍以单块事务为主 → 确认粒度细、回滚面小，但**吞吐低于程序化 HTTP batch**

**诚实评价**：确认+快照对「偶发 Agent 误写」友好；对「用户授权的千级块重构」会确认疲劳，且 MCP 写路径未充分暴露 batch——批量安全与批量效率之间偏安全。

### 3.5 领域系统提示（工具面之上的契约）

`agent.go:43-119` 是少见的、与工具一一对齐的**运行时领域说明书**：

- 容器/叶子枚举
- 标题 sibling 陷阱
- 列表嵌套合法树
- 引用链接格式 `[title](siyuan://blocks/<id>)`，**禁止捏造 ID**
- text-mark / HTML block 的可渲染约束
- 用户指南笔记本 ID（多语言）作为功能权威
- file 工具红线与写确认纪律

**可迁移点**：工具 schema 描述 + 系统提示双重契约，比「只有 JSON Schema」显著降低模型误用。

### 3.6 前端遗留 AI 写作

`app/src/ai/actions.ts`：`fillContent` 把模型输出 `SpinBlockDOM` 插入选区（`17-27`）；自定义 prompt 存 `LOCAL_AI`。
Slash「AI 编写」走这条路径（`hint/extend.ts:60-63`），与内核 Agent **并行存在**——产品上从「补全/改写」演进到「带工具会话」。

## 4. 体验细节：IME、选区、Chrome、性能

### 4.1 IME（输入法）

主路径 `app/src/protyle/wysiwyg/index.ts:2799-2864`（注释链到 issue #3027）：

| 机制               | 行为                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| `compositionstart` | `isComposition=true`；表格内记录 cell+offset；非 Mac 写 wbr HTML                                 |
| `compositionend`   | 有 `event.data` → `input(..., needRender)`；空数据 → 可能 `updateTransaction` 回退；表格恢复光标 |
| keydown/input      | 多处 `event.isComposing` 短路（`keydown.ts:167,629`；`callout.ts:98`；`hint/index.ts:343+`）     |
| 微软双拼 / 搜狗    | 注释明确差异：双拼勿在 keydown 记历史；搜狗选中续输不走 keydown（`2805-2806,2928-2930`）         |
| 标题/背景          | `header/Title.ts`、`Background.ts` 同样 `isComposing` + `compositionend`                         |

结论：思源把 IME 当一等公民，且按输入法厂商 quirks 分支——块编辑器可抄的**策略**是 composition 期间禁止结构键与事务提交，结束时再 spin DOM。

### 4.2 选区

`app/src/protyle/util/selection.ts`：

- 编辑器范围判定 `selectIsEditor`
- 表格跨 cell 选区修复 `fixTableRange`（`29-47`）
- 块内/跨块全选 `selectAll`（`49+`）
- 与字数统计、工具条联动

块级多选：`protyle-wysiwyg--select` + gutter/菜单操作，与字符级 Range 双轨。

### 4.3 静默写作 vs 块 Chrome

| 元素          | 策略                             | 证据                    |
| ------------- | -------------------------------- | ----------------------- |
| Gutter        | 悬停显示；滚动 `gutterOnly` 隐藏 | `scroll/event.ts:49-51` |
| 浮动工具条    | 滚出编辑区隐藏                   | `scroll/event.ts:16-24` |

| 超级块 resize | 仅 col 布局插入手柄              | `block/util.ts:108-124` |

写作态 DOM 仍以 contenteditable 块为主，chrome 叠在旁边而非侵入文本流。

### 4.4 性能策略（虚拟化有无）

**文档正文：不是 React 式 windowing 虚拟列表**，而是 **动态分块加载（chunked load）**：

- 配置：`window.siyuan.config.editor.dynamicLoadBlocks`
- 向上滚到顶附近：`getDoc` `mode:1` + `size: dynamicLoadBlocks`，`CB_GET_BEFORE`（`scroll/event.ts:84-111`）
- 向下滚到底附近：对称加载（`113+`）
- `data-eof` 标记文档端点；滚动条块索引 `protyle.scroll.updateIndex`
- 产品宣称「百万字大文档」（`README.zh-CN.md:97`）依赖此机制 + 后端按需序列化 DOM

**Attribute View 行：有虚拟滚动**

- `app/src/protyle/render/av/virtualScroll.ts`（`trimAVRowsSync`、`getBodyVirtualData`）
- 滚动时 rAF 合并 sticky 行与 trim，避免布局抖动（`scroll/event.ts:31-42` 中文注释）

**其它**：图片 lazy（`setLute.ts` `SetImageLazyLoading`）；emoji 懒渲染；粘贴超大 HTML 分 chunk 写入 DOM（`paste.ts:415-420`）。

| 区域      | 策略                            | 可抄性                       |
| --------- | ------------------------------- | ---------------------------- |
| 正文块    | 服务端分页/前后拼接，非整表虚拟 | 自研可做「按块窗口加载」契约 |
| AV 表     | 前端虚拟行                      | 表场景必备                   |
| 嵌入/图表 | 进入视口/显式 render            | 重渲染块延迟                 |

## 5. 优点可抄机制 vs 不可嵌入的 AGPL/实现

### 5.1 可抄（机制 / 契约 / 模式）——**不抄代码**

1. **块 ID 稳定 + 全树事务**
   更新钉 ID（pinBlockID）；所有写走 `PerformTransactions`。

2. **工具面 action 聚合 + 极详细 Description**
   单工具多 action、枚举写清；update vs append 语义写进 Description。

3. **领域系统提示与工具对齐**
   容器/标题 sibling/列表嵌套/hPath 写入 system prompt。

4. **确认矩阵：safeActions × ActionEffects × Source**
   只读白名单 + 效果四维 + 外部工具默认危险。

5. **写前快照 / 中断不可重试**
   `executionUnknown`；本地 EffectScope 快照。

6. **数据面分层**
   HTTP（全）/ MCP（LLM 子集）/ CLI / 直改 `.sy` 的优先级说明（`SY-FORMAT`）。

7. **file 工具与领域工具隔离**
   日志调试 vs block/document 写——防止 Agent 用文件 API 绕过索引。

8. **动态加载大文档 + AV 虚拟行** 的分层性能策略。

9. **IME composition 生命周期** 与结构操作互斥。

10. **静默 chrome**：gutter/工具条按需、滚动即藏。

11. **frontend 工具**：Agent 可 `focus_block` / `open_document` 对齐用户视口（仅交互会话）。

12. **question / todo_write** 元工具：澄清与进度，不污染笔记数据。

### 5.2 不可嵌入 / 不可直接搬用

| 项                          | 原因                                                                |
| --------------------------- | ------------------------------------------------------------------- |
| **AGPL-3.0 源码**           | 网络服务传染；商业闭源产品不可直接合入思源实现                      |
| **Protyle 编辑器实现**      | 巨型 contenteditable + 定制事务；耦合 Lute GopherJS / 内核 DOM 协议 |
| **Lute AST / `.sy` 格式**   | 独立生态；迁移成本是「协议兼容」不是「拷贝目录」                    |
| **kernel/model 事务与索引** | 深度绑定 SQLite FTS、blocktree、dejavu 同步                         |
| **petal 插件 API 表面**     | 许可证与 API 稳定性与主仓绑定                                       |
| **集市/会员/Inbox/云同步**  | 产品商业与云侧，非通用笔记内核                                      |

**正确用法**：把思源当 **参考实现与契约教科书**，在自有许可证下重做工具面与编辑器；引用其交互语义与 API 形状时保持 clean-room。

## 6. 对「专精 AI 工作栈笔记」的可迁移点

面向 Conex/Crish 类 **AI-first 笔记/工作栈**（工具契约优先，不抄 UI）：

### 6.1 工具面契约建议

| 契约项           | 思源做法                    | 迁移建议                                                        |
| ---------------- | --------------------------- | --------------------------------------------------------------- |
| 资源分层         | notebook / document / block | 保留；Agent 系统提示写清父子与 sibling 语义                     |
| 单工具多 action  | `block` 一函数多 verb       | 便于 LLM 选工具；Description 必须写清「update 不 append」类陷阱 |
| 读批量 / 写单笔  | batch_get vs 单事务 update  | 读可批量降 token；写默认单资源 + 确认                           |
| 稳定 ID          | pinBlockID                  | Agent 往返必须幂等 ID                                           |
| 只读白名单       | `safeActions`               | 集中表 + 测试锁死「写 action 不得撞名」                         |
| 效果元数据       | LocalWrite / Egress / Cost  | 决定确认与是否快照                                              |
| 领域提示         | 内置 user guide 笔记本      | 产品内「权威文档 ID」供 Agent 检索，禁止臆造功能                |
| 禁止 file 写数据 | 红线写在 prompt + 描述      | 工作区文件工具与笔记 CRUD 分离                                  |
| 结构化提问       | `question` 工具             | 多笔记本/多目标时避免纯文本列表                                 |
| 视口联动         | `frontend.focus_block`      | Agent 改完后引导用户看见变更                                    |
| 外链协议         | `siyuan://blocks/<id>`      | 自研可用自定义 scheme 或 deep link                              |

### 6.2 不建议原样照搬

- contenteditable 块 chrome 全套（成本极高）
- 超级块布局（非 AI 工作流刚需）
- 把 SQL 直接暴露给 LLM（思源有，但需严格只读与限流）
- 写路径完全依赖用户逐条确认（长任务需「会话级授权策略」扩展）

### 6.3 与思源差异化空间（AI 工作栈）

思源强在 **PKM 块交互 + 近年补齐的 Agent/MCP**；
AI 工作栈笔记可在以下处拉开：

- **任务/会话原生对象**（todo_write 仅会话态，非一等笔记对象）
- **批量重构工具**（带预览 diff + 一次确认 + 事务）
- **更强的工具输出截断与分页契约**（思源 file limit=200 有起步）
- **多 Agent / 子 Agent 工具隔离**（思源单会话工具全集）
- **非 AGPL 内核**便于嵌入产品

## 7. 诚实上限：做到了什么、卡在哪里

### 7.1 已做到（证据充分）

1. **完整块级 PKM 交互**：slash、gutter 拖拽多选、折叠、超级块、缩放聚焦、双链/嵌入/反链。
2. **统一事务写路径**：UI / HTTP / MCP 共用 `PerformTransactions`。
3. **成熟 IME 与选区工程**：厂商 quirks、表格 composition 恢复。
4. **大文档可用的动态加载** + AV 虚拟行。
5. **Agent 工具面已产品化**：原生工具覆盖笔记主域；确认、快照、中断未知态、system prompt 领域模型、frontend 视口控制。
6. **MCP 对外暴露**且强制管理员鉴权。
7. **公开 HTTP API 文档**与 `.sy` 格式说明，利于生态与迁移。

### 7.2 卡点与边界

| 卡点                      | 说明                                                                                         |
| ------------------------- | -------------------------------------------------------------------------------------------- |
| AGPL                      | 限制闭源产品直接复用实现                                                                     |
| 编辑器复杂度              | Protyle 历史包袱重，边缘 IME/嵌入/AV 持续修 issue                                            |
| MCP 写能力 < HTTP         | 无 batch 写；Agent 批量改文档效率与确认成本矛盾                                              |
| ActionEffects 未全覆盖    | 多数工具仍依赖 action 名白名单，扩展时易踩「同名安全」坑（测试已有防御样例 `tools_test.go`） |
| file 工具双刃剑           | 虽 prompt 禁止写数据，工具本身仍暴露 write/delete——靠确认与纪律                              |
| semantic search / 图像    | 依赖外部模型配置与会员/成本；egress 需确认                                                   |
| 前端 AI 与内核 Agent 双轨 | 用户心智与能力边界可能分裂                                                                   |
| 标题 sibling 模型         | 对人类大纲直觉不友好，Agent 必须专门教——迁移时要么改模型要么同样写进契约                     |
| 虚拟化不全                | 正文靠动态加载非精细 windowing；极端超长单块仍可能卡                                         |

### 7.3 一句话结论

思源是 **块级知识库交互的高完成度参考**，近年把 **MCP + 确认式 Agent** 接到同一事务与块 ID 体系上，工具面契约（尤其 `block`/`document` 语义、safeActions、领域 system prompt）对「专精 AI 工作栈笔记」**高度可迁移**；
其 **Protyle 实现与 AGPL 本体不可嵌入**。自研应 **复用语义与安全模型，重做引擎与许可证边界**，并在批量 Agent 写与会话级授权上做得比思源更贴 AI 工作流。
