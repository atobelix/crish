# Round C · 思源 SiYuan：Go 内核事务、块模型与 MD 纪律

> 代码根：`reference/markdown_compare/siyuan`
> 证据以 `kernel/` 与官方 `docs/` 为主；前端 `app/src/protyle` 仅作「投递侧」对照。
> 本篇为只读分析，不改源码。许可 **AGPL-3.0**——机制可内化，**禁止整仓/深拷贝嵌入**。

---

## 0. 一句话结论

| 问题                     | 答案                                                                                                                                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **文档真相在哪一层？**   | **Go 内核持有权威**：磁盘 `.sy`（Lute AST 的 JSON 序列化）+ 事务串行写盘；SQLite（`temp/siyuan.db` / `blocktree.db`）是**可重建索引**，不是权威。前端 Protyle 持 **乐观 DOM 投影**，通过 `/api/transactions` 投递 op。 |
| **一致性如何保证？**     | 全局 `txQueue` + `flushLock` **单写者串行**；非 CRDT。同步是 **dejavu 文件级快照/合并**，冲突可生成副本文档。                                                                                                          |
| **MD 是否一等契约？**    | **AST（Lute）是一等真相**；标准 MD 是 **导入/导出视图**；编辑热路径走 **BlockDOM（HTML 形态）↔ AST**，不是 raw MD 往返。                                                                                               |
| **与 AFFiNE / AppFlowy** | AFFiNE = Yjs 真相在 JS；AppFlowy = yrs 真相在 Rust；思源 = **文件 AST + Go 事务**，实时协同弱、块 ID/索引/AI 工具面强。                                                                                                |
| **对本产品**             | **内化机制清单**（事务队列、稳定块 ID、索引派生、MD/AST 纪律、Agent 工具打在块 API）；**否决整仓 Go 嵌入**（语言分裂 + AGPL + Electron 壳）。                                                                          |

## 1. 架构分层与「文档真相」

### 1.1 三层分工

```
┌─────────────────────────────────────────────────────────────┐
│  app/（Electron + TS）                                      │
│  Protyle WYSIWYG：contenteditable DOM + 前端 Lute(GopherJS) │
│  职责：交互、乐观应用 op、滚动/动态加载请求、WS 广播消费      │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP /api/transactions*
                           │ WebSocket 广播 transactions
┌──────────────────────────▼──────────────────────────────────┐
│  kernel/（Go，领域权威）                                    │
│  model.Transaction → loadTree → 改 Lute AST → WriteTree     │
│  sql.UpsertTreeQueue → FTS/refs 索引；treenode.blocktree    │
│  agent/ + mcp/：工具面直打块/文档 API                        │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│  磁盘工作区                                                  │
│  data/<boxID>/**/*.sy     ← 权威内容（AST JSON）            │
│  temp/siyuan.db + FTS     ← 可重建搜索/引用索引             │
│  temp/blocktree.db        ← 块 ID → 路径映射                │
│  history/ + repo/         ← 文件历史 / dejavu 快照同步       │
└─────────────────────────────────────────────────────────────┘
```

权威声明（官方文档与代码一致）：

- `.sy` = Lute AST 树的 JSON；根节点恒 `NodeDocument`（`docs/SY-FORMAT.zh-CN.md:9-11`）。
- 文件系统保存权威原始内容；`temp/` 下 SQLite 是可重建索引（`docs/WORKSPACE.zh-CN.md:9`）。
- 直接改盘绕过事务/索引同步，需重建索引（`docs/SY-FORMAT.zh-CN.md:16-33`）。

### 1.2 真相边界（硬规则）

| 层                   | 持有什么                        | 是否权威                              |
| -------------------- | ------------------------------- | ------------------------------------- |
| 磁盘 `.sy`           | 整棵文档 AST（JSON）            | **是**（持久真相）                    |
| Go 内存 `parse.Tree` | 事务内加载的树                  | 事务过程中的工作集                    |
| `blocktree.db`       | `id → root/path/box/type`       | **否**，可从 `.sy` 全量重建           |
| `siyuan.db` + FTS5   | blocks/spans/refs/markdown 投影 | **否**，`UpsertTreeQueue` 派生        |
| Protyle DOM          | 块 HTML 投影（`data-node-id`）  | **否**；乐观 UI，以事务提交后广播为准 |
| 前端 `lute.min.js`   | 本地 DOM↔MD 辅助、`NewNodeID`   | 解析器副本，**写权威仍走内核**        |

**读路径一致性闸门**：`GetDoc` 入口先 `FlushTxQueue()`，避免读到未落盘数据（`kernel/model/file.go:599`）。

### 1.3 前端不是第二真相

Protyle 在本地对 `doOperations` 做 DOM 侧乐观更新（`app/src/protyle/wysiwyg/transaction.ts:91-178`），但：

1. 写路径统一入内核队列：`api/transaction.go` → `model.PerformTransactions`（`kernel/api/transaction.go:79`）。
2. 推送前 `FlushTxQueue()` 等写完再广播（`kernel/api/transaction.go:98-99`）。
3. 撤销权威在内核 `GlobalUndoLog`（内存态，按 rootID 分栈），不是仅前端 undo 栈（`kernel/model/undolog.go:68-76`）。

## 2. 事务 / 串行化如何保证一致性

### 2.1 全局写队列（核心不变量）

实现：`kernel/model/transaction.go`。

| 构件                      | 作用                                        | 证据                                    |
| ------------------------- | ------------------------------------------- | --------------------------------------- |
| `txQueue` + `txQueueLock` | 入队缓冲                                    | `:87-92`、`PerformTransactions:154-164` |
| `flushQueue` 50ms ticker  | 定时批量取出                                | `:98-110`                               |
| `flushLock`               | **全局互斥写**，同一时刻只 `performTx` 串行 | `:102-109`、`flushTx:113`               |
| `isFlushing` atomic       | `FlushTxQueue` 自旋等待                     | `:59-63`、`:91`                         |
| `Transaction.state`       | 0 初值 / 1 未提交 / 2 已提交 / 3 已回滚     | `:2078`                                 |
| `PerformTxSync`           | undo/redo **同步**持锁执行                  | `:66-85`                                |

入队按 `Timestamp`（前端 `reqId`）稳定排序（`:161-163`），保证多批请求顺序可预测。

```
前端/API/CLI
    │ PerformTransactions  // 仅入队，几乎立即返回
    ▼
 txQueue ──(50ms)──► takeQueuedTransactions
    │
    ▼ flushLock
 performTx: begin → 逐 op do* → commit|rollback
    │
    ▼ commit
 writeTreeUpsertQueue → filesys.WriteTree + sql.UpsertTreeQueue
 GlobalUndoLog.Record / IncSync / 动态锚文本刷新
```

### 2.2 事务生命周期

**begin**（`:2123-2132`）：清空 `trees/nodes`，`NewLute()`，`state=1`，`tx.m.Lock()`。

**op 分发**（`:248-409`）：`create/update/insert/delete/move/append/...` 以及大量 `AttrView*` 属性视图 op。任一步失败 `rollback` 并返回 `TxErr`。

**commit**（`:2135-2196`）：

1. 对 `tx.trees` 逐树 `writeTreeUpsertQueue`（落盘 + 索引入队）。
2. `PushSaveDoc` 通知 UI。
3. `refreshDynamicRefTexts` 刷新动态锚文本（可能波及引用树，记入 `changedRootIDs`）。
4. 属性视图 `SaveAttributeView` / `ReloadAttrView`。
5. `IncSync()` 触发同步脏标记。
6. `state=2`，**仅成功提交**才 `GlobalUndoLog.Record(tx)`。

**rollback**（`:2199-2203`）：丢弃内存 `trees/nodes`，`state=3`，**不写盘、不入撤销栈**。

**panic 恢复**（`:228-238`）：未提交态回滚；已提交 panic 不二次回滚（`txErrFromPanic`）。

注意：`Transaction` 的「事务」**不是** SQLite BEGIN/COMMIT 包裹整棵文档语义；它是 **内核级文档 AST 变更单元**。SQLite 侧另有独立 `sql` 操作队列（见 §5）。

### 2.3 操作载荷形态

```go
// kernel/model/transaction.go:2020-2078
type Operation struct {
    Action, ID, ParentID, PreviousID, NextID string
    Data any   // update: BlockDOM 字符串；create: Tree 等
    // … 属性视图 / 闪卡 字段
}
type Transaction struct {
    Timestamp int64
    DoOperations, UndoOperations []*Operation
    trees map[string]*parse.Tree  // 本 tx 触达的 root 树缓存
    fromAPI, isReplay bool
    // …
}
```

**update 热路径**（`:1543-1680`）：

1. `loadTree(id)` → 经 blocktree 定位 `.sy`，整树加载进 `tx.trees`。
2. `operation.Data`（BlockDOM HTML）→ `luteEngine.BlockDOM2Tree`。
3. 旧节点引用/折叠标题/属性视图联动处理。
4. `oldNode.InsertAfter(updated); oldNode.Unlink()` 替换子树。
5. `writeTree` 仅标记 `tx.trees` + 立即 `treenode.UpsertBlockTree`；真正落盘在 commit。

同一事务内多 op 共享 `tx.trees` 缓存，避免重复读盘。

### 2.4 大插入 / 大删除批处理

- `processLargeInsert` / `processLargeDelete`：当 op 数 ≥ 32 且形态符合时，走批量路径（`:435+`、`:462+`），避免逐条过重。
- 失败码含 `TxErrCodeDataIsSyncing`、`TxErrCodeBlockNotFound`、`TxErrCodeSkipTx`（跨加密边界移动跳过等）（`:180-187`）。

### 2.5 与「CRDT 实时协同」的本质区别

|        | 思源事务                       | CRDT（Yjs/yrs）                |
| ------ | ------------------------------ | ------------------------------ |
| 并发写 | **单写者串行**（`flushLock`）  | 多副本并发 merge               |
| 冲突   | 同步层文件级冲突副本           | 操作可交换收敛                 |
| 撤销   | 逆 op 重放（`UndoOperations`） | 通常 tombstone/undo stack 另建 |
| 多窗口 | WS 广播同一事务结果            | 状态向量同步                   |

多客户端/多窗口：**同一内核进程内**串行；跨设备靠 **repo 同步**（§7），不是 OT/CRDT 编辑合并。

## 3. 块模型、ID 稳定性、引用与索引

### 3.1 块 = AST 上带 ID 的节点

- Block 节点有 `ID`；内联/标记节点无 ID（`docs/SY-FORMAT.zh-CN.md:72-78`）。
- 容器块：`NodeDocument / List / ListItem / Blockquote / SuperBlock / Callout` 等（同文档 §4）。
- 运行时投影结构 `model.Block` 含 `ID/RootID/ParentID/Markdown/Content/Refs/...`（`kernel/model/block.go:42-75`），主要用于 API/搜索返回，**不是**磁盘格式。

### 3.2 块 ID 格式与稳定性

- 格式：`YYYYMMDDHHMMSS-xxxxxxx`（14 位时间戳 + 7 位 `[a-z0-9]`）（`docs/SY-FORMAT.zh-CN.md:84-88`）。
- 生成：`ast.NewNodeID()`（Lute）；前端亦可 `Lute.NewNodeID()`（`app/src/protyle/...`）。
- **根 ID = 文件名**（去掉 `.sy`），改根 ID 等于改路径（`docs/SY-FORMAT.zh-CN.md:57-63`）。
- **引用按块 ID**，不按文件路径；移动文档/改名时 `blocktree` + path 更新，引用关系靠 ID 保持。

稳定性纪律：

- `Properties.id` 必须与节点 `ID` 一致。
- `ResetNodeID` 仅在复制等场景显式调用（`treenode/node.go:37+`）。
- 跨加密边界块引会被 `degradeCrossBoundaryBlockRefs` 降级为纯文本（`transaction.go:1577-1578`）。

### 3.3 两套索引

#### A. BlockTree（定位索引）

`treenode.BlockTree`：`ID, RootID, ParentID, BoxID, Path, HPath, Updated, Type`（`kernel/treenode/blocktree.go:39-48`）。

- 库路径：`temp/blocktree.db`，表 `blocktrees`（`:90`）。
- 事务中每次 `writeTree` 即 `UpsertBlockTree`（`transaction.go:2256-2259`）——**写路径上立即更新**，供后续 op 定位。
- 全量可 `forceRebuild` 从磁盘重建。

#### B. 内容索引（搜索 / 引用 / FTS）

`temp/siyuan.db` 表结构（`kernel/sql/database.go:145-249`）：

| 表                                               | 用途                                      |
| ------------------------------------------------ | ----------------------------------------- |
| `blocks`                                         | 块投影：content/markdown/ial/hash…        |
| `blocks_fts`                                     | FTS5 external content，`content='blocks'` |
| `spans`                                          | 行级片段                                  |
| `refs`                                           | 块引用 def→ref                            |
| `assets` / `attributes` / `file_annotation_refs` | 资源与属性                                |
| `block_embeddings`                               | 向量嵌入                                  |

**upsert 增量**：按块 `hash` 跳过未变更块（`sql/upsert.go:436-489`），大文档局部编辑不全表重写。

**队列**：`sql.operationQueue` + `FlushQueue`（`kernel/sql/queue.go`）；`UpsertTreeQueue` 异步索引，与文档写解耦。相同 root 的 index/upsert 可覆盖合并（`queue.go:412+`）。

### 3.4 引用刷新

- 更新块时收集 old/new def IDs，异步 `refreshRefCount`（`transaction.go:1621-1636`）。
- commit 时 `refreshDynamicRefTexts` 推送动态锚文本变更树 ID 列表。
- `TransferBlockRef` / `SwapBlockRef` 提供引用迁移（`block.go:452+`）。

## 4. MD / AST / BlockDOM：往返纪律与风险

### 4.1 三套「表面」

| 表面                    | 角色                     | 主 API / 入口                                                               |
| ----------------------- | ------------------------ | --------------------------------------------------------------------------- |
| **AST JSON（.sy）**     | **持久权威**             | `filesys.WriteTree` → `render.NewJSONRenderer`（`filesys/tree.go:420-421`） |
| **BlockDOM**            | 编辑传输格式             | `BlockDOM2Tree` / `Tree2BlockDOM`；`doUpdate` 收 HTML 字符串                |
| **Markdown / Kramdown** | 导入导出、复制、部分 API | `ExportStdMarkdown`、`GetBlockKramdown`、`NewStdLute` 导入                  |

内核 Lute 默认配置（`kernel/util/lute.go:51-89`）关键开关：

- `SetProtyleWYSIWYG(true)`、`SetBlockRef(true)`、`SetKramdownIAL(true)`、`SetSuperBlock(true)`、`SetTextMark(true)`
- 关闭脚注/ToC/YAML front matter/heading ID/setext 等（与 `.sy` 禁用类型一致）

前端另有 **GopherJS 编译的 `lute.min.js`**，用于本地渲染与粘贴语法（与 Go Lute 同源思想，版本需与内核对齐）。

### 4.2 热路径不是 MD round-trip

```
用户击键 → Protyle DOM
         → transaction { action: update, data: outerHTML }
         → kernel BlockDOM2Tree → 替换 AST 子树
         → JSON 写 .sy
         → Tree2BlockDOM 切片回前端（GetDoc / 广播）
```

**MD 不是编辑中介**。因此：

- 日常编辑 **不** 经过 commonmark 解析损失。
- 导出标准 MD / 导入 MD 才是有损边界。

### 4.3 Round-trip 风险矩阵

| 路径                      | 风险       | 说明                                                                                  |
| ------------------------- | ---------- | ------------------------------------------------------------------------------------- |
| BlockDOM → AST → BlockDOM | **低～中** | 权威路径；仍可能有 HTML 空白/HTMLBlock 空行折叠等规范化（`transaction.go:1654-1665`） |
| AST JSON 落盘 → 再读      | **低**     | `parseJSON2Tree` + `fixTreeJSONData` 修复 `\u0000` 等（`filesys/tree.go:493+`）       |
| AST → 标准 MD → AST       | **高**     | 块 ID、IAL、超级块、块引、属性视图、折叠态等 **无法无损**映射到 commonmark            |
| AST → Kramdown IAL → AST  | **中**     | 保留更多 IAL；仍非全部 Protyle 语义                                                   |
| 直接手改 `.sy`            | **高**     | 易破坏 `CanContain`（如 List 下只能 ListItem，`SY-FORMAT` §5.3）与双索引              |

**结论（纪律）**：

1. **一等契约是 AST（含块 ID + IAL）**，不是「仓库里是一堆 .md」。
2. MD 是 **interop 层**：导入用 `NewStdLute`（允许缩进代码块等），导出用专用导出管道。
3. AI/Agent 改内容应走 **事务 API / MCP 块工具**，禁止模型直接写 raw MD 覆盖 `.sy` 当权威。

### 4.4 格式化与 MD 相关内核入口

- `model/format.go`：FormatRenderer 规范化树（合并相邻 TextMark 等）。
- `api/lute.go`：`copyStdMarkdown`、`html2BlockDOM` 等边界转换。
- `GetBlockKramdown`：块级 Kramdown 视图（`block.go:1077+`）。

## 5. 存储布局与写路径细节

### 5.1 工作区布局（摘要）

完整规范见仓库 `docs/WORKSPACE.zh-CN.md`。要点：

```
<workspace>/
  conf/conf.json
  data/
    assets/ | storage/ | plugins/ | …
    <boxID>/                 # 笔记本 = 目录名 ID
      .siyuan/conf.json
      <docID>.sy             # 文档 = 文件名 ID
      <docID>/<child>.sy     # 子文档配对目录
  repo/                      # dejavu 数据仓库
  history/                   # 编辑历史归档
  temp/
    siyuan.db | blocktree.db | history.db | …
```

**父子文档铁律**：文档 `A` = `A.sy` + 可选 `A/` 子目录；移动必须同步（`WORKSPACE.zh-CN.md:116-133`）。

### 5.2 写盘路径

`writeTreeUpsertQueue`（`model/file.go:1149-1160`）：

1. `filesys.WriteTree(tree)`
2. `sql.UpsertTreeQueue(tree)`
3. 刷新文档信息缓存

`WriteTree`（`filesys/tree.go:346-389`）：

1. `prepareWriteTree`：空文档补段落、`UpgradeSpec`、JSON 渲染（可 indent）。
2. 加密笔记本：`encryptData` 后写密文；缓存比对应明文。
3. 与缓存/磁盘相同则 **跳过写**（避免无变更重复 IO）。
4. `WriteFileByMmap` / `filelock.WriteFile`。
5. 超大文件警告 `ExceedLargeFileWarningSize`（配置默认约 8MB 量级，`conf.go:331-334`）。

### 5.3 与 SQLite「事务」的关系

- 文档语义事务：`model.performTx`（§2）。
- 索引写：`sql` 包内 `BEGIN`/`COMMIT`（见 `treenode/blocktree.go` 与 `sql` 队列 flush），**滞后于** `.sy` 落盘；读搜索前可能需 `WaitFlushTx` / 任务 `DatabaseIndexCommit`。

权威顺序：**先文件，后索引**。索引损坏 → 重建；文件损坏 → `corrupted/` 隔离或历史回滚。

## 6. 大文档性能机制

| 机制                       | 做法                                                                        | 证据                                 |
| -------------------------- | --------------------------------------------------------------------------- | ------------------------------------ |
| **动态加载块**             | `GetDoc` 按 `mode/size/startID/endID` 切片渲染 BlockDOM，非整树一次吐给前端 | `file.go:585-778`                    |
| **DynamicLoadBlocks 阈值** | 子块计数超配置则启用滚动条分段加载                                          | `file.go:744-748`、`conf.go:405-406` |
| **读前冲刷写队列**         | `FlushTxQueue` 防脏读                                                       | `file.go:599`                        |
| **事务内树缓存**           | `tx.trees[rootID]` 多 op 共享                                               | `transaction.go:2243-2253`           |
| **索引 hash 跳过**         | 未改块不重写 SQL 行                                                         | `sql/upsert.go:443-459`              |
| **大插入/删除批处理**      | op≥32 特殊路径                                                              | `transaction.go:435+`                |
| **异步索引队列**           | 写盘不阻塞 FTS 全量                                                         | `sql/queue.go`                       |
| **task 队列**              | 历史生成、引用计数、索引提交等延后                                          | `kernel/task/queue.go`               |
| **Tree 数据缓存**          | `cache.SetTreeDataInBox` 避免重复序列化比对                                 | `filesys/tree.go:360-386`            |
| **批量 LoadTrees**         | ants 池并行读多文档                                                         | `filesys/tree.go:113-143`            |

限制（对本产品警示）：

- 权威仍是 **整文件 AST**；超大单文档 JSON 解析/序列化仍是 O(全文) 内核成本。
- 前端 contenteditable + 字符串 HTML 作为 op 载荷，**不利于精细 CRDT 与虚拟化**（选型文档已标「不要复刻」）。
- 百万字宣称依赖 **动态加载 UI + 索引增量**，不是无限大单 DOM。

## 7. 协同模型：文件快照，不是 CRDT

### 7.1 同步栈

- 库：`github.com/siyuan-note/dejavu`（`go.mod` + `model/repository.go`）。
- 流程：`syncData` → `repo.Sync` / `SyncDownload` / `SyncUpload`（`sync.go`、`repository.go:1687+`）。
- 全局 `syncLock` 防并发同步（`sync.go:171-178`）。
- 同步中写事务可返回 `TxErrCodeDataIsSyncing`。

### 7.2 合并与冲突

`processSyncMergeResult`（`repository.go:2054+`）：

- 结果：`Conflicts` / `Upserts` / `Removes` 文件列表。
- **冲突**：若 `Conf.Sync.GenerateConflictDoc`，对冲突 `.sy` 加载后 `resetTree(..., "Conflicted")` **生成冲突副本文档**（`:2066-2109`），不是行级三路合并。
- 冲突侧同时可写入 `history/` 并索引。
- 有变更后 **增量/重建索引**（`incReindex` / upsertIndexes）。

**判定**：思源协同 = **串行本地事务 + 仓库级文件同步 + 冲突副本**。
与 AFFiNE（Yjs 实时）/ AppFlowy（yrs collab）**不在同一问题域**；它更接近「Git 式同步的笔记库」，编辑期不做 CRDT 收敛。

### 7.3 多窗口

- 同一内核：事务串行 + WS `transactions` 广播（`api/transaction.go:95-118`）。
- 附带各 root 的 undo/redo 可用性状态，供多窗口按钮同步（同文件注释 `:120` 一带）。

## 8. 撤销、历史、冲突细节

### 8.1 撤销（内存 GlobalUndoLog）

`kernel/model/undolog.go`：

- 全局单例，**按 rootID 分栈**，默认每栈最多 64 条（`:75-76`）。
- 仅记录：`fromAPI && len(UndoOperations)>0 && !isReplay`（`:107-112`）。
- 跨文档 op：同一 `UndoEntry` 指针挂在多个 root 栈；撤销一端联动移除（`:31-38`、`UndoCommit`）。
- 重放：`PerformTxSync` + `MarkReplay`，失败 `UndoRollback` 精确回栈。
- **重启清空**（内存态）。

前端另有 Protyle 本地 undo 协作（`protyle/undo/`），但跨窗口权威以内核日志 + 广播状态为准。

### 8.2 文件历史

`kernel/model/history.go`：

- 定时 `GenerateFileHistory`：对已打开笔记本拷贝最近修改文档到 `history/`（`:72-85`）。
- 间隔 `Conf.Editor.GenerateHistoryInterval`（分钟）。
- 回滚：`RollbackDocHistory` / `RollbackAssetsHistory` / `RollbackNotebookHistory`。
- 历史可 FTS 检索（`FullTextSearchHistory`）；`history.db` 索引。

与撤销区别：**撤销** = 逆 op 即时重放；**历史** = 文件级时间点快照。

### 8.3 同步冲突

见 §7.2：可选 **Conflicted 副本文档** + history 归档；用户手工合并。

## 9. 与 AFFiNE（Yjs-JS）/ AppFlowy（yrs-RS）本质差异

| 维度         | AFFiNE                        | AppFlowy                    | **思源 SiYuan**                     |
| ------------ | ----------------------------- | --------------------------- | ----------------------------------- |
| 文档真相     | Y.Doc 块属性（**JS 热路径**） | collab/yrs 文档（**Rust**） | **`.sy` Lute AST + Go 事务**        |
| 一致性原语   | CRDT 自动合并                 | CRDT（完成度有洞）          | **单写者队列**                      |
| 持久化       | SQLite/blob + 同步管道        | RocksDB/本地 server 等      | **明文/密文文件为主**，SQLite 索引  |
| MD           | adapter / 导出                | 有转换层                    | **AST 一等，MD 强导出/导入**        |
| 块 ID        | 框架内 ID                     | 块 ID + external text       | **稳定时间戳 ID，引用一等**         |
| 实时多人     | 强（Yjs）                     | 有                          | **弱；主叙事是单机/库同步**         |
| AI 工具面    | 有能力非内核中心              | 模块化                      | **kernel agent + MCP 直打块 API**   |
| 壳           | Electron                      | Flutter                     | Electron                            |
| 许可         | 主体偏 MIT                    | AGPL                        | **AGPL**                            |
| 对本产品映射 | 学块交互皮                    | 学 RS 心与域切分            | **学事务/ID/索引/MD 纪律/Agent 面** |

**一句话**：

- AFFiNE 证明「Notion 级块交互可以在 JS CRDT 上堆起来」——代价是真相在 JS。
- AppFlowy 证明「心可以沉 Rust」——UI 在 Flutter。
- 思源证明「**领域权威在原生内核 + 前端只投事务**」可量产——原生是 **Go**，协同是 **文件库** 不是 CRDT。

本产品锁定：**Rust 心 + Tauri 壳 + 增量 op**；思源贡献的是 **机制同构**，不是栈同构。

## 10. 对本产品「Rust 心」：应内化 vs 明确否决

### 10.1 应内化的机制清单（不照搬实现）

1. **单一写权威 + 全局串行（或文档级串行）事务队列**
   - 防撕裂、防索引与文件交错。
   - 对应：`PerformTransactions` / `flushLock` / `FlushTxQueue`。

2. **稳定块 ID 作为引用主键**
   - 路径可变、ID 不变；引用/反链/嵌入全挂 ID。

3. **持久真相与索引分离**
   - 权威可序列化结构（类 `.sy` 或更优的分块存储）；搜索/引用索引可重建、可 hash 增量。

4. **编辑传输用结构化 op，而不是「整文件 MD 覆盖」**
   - 思源用 BlockDOM op；本产品应用 **RS 块树增量 op**（可更细粒度），同样禁止 Agent 直接覆写全文当唯一路径。

5. **MD 作为一等契约的「边界语言」**
   - 导入/导出/剪贴板/AI 上下文要有 **明确有损边界** 文档；内核 AST/块树才是 round-trip 目标。
   - 编辑热路径 **不要** 强制 MD↔树来回。

6. **读路径与写路径的屏障**
   - 读文档前等待 inflight 写完成（类 `FlushTxQueue`）；或版本号/fence。

7. **大文档：切片加载 + 索引增量 + 异步派生任务**
   - UI 不绑整树 DOM；索引队列与写解耦。

8. **Agent/MCP 工具粒度对齐块/文档事务**
   - 思源 `kernel/mcp/tools` + `kernel/agent`：AI 改笔记走同一事务语义。
   - 本产品 Agent 已在 Rust——更应 **同进程直调** 文档事务，而不是再嵌一套 Go。

9. **撤销 = 可序列化逆 op**；历史 = 文件/快照层——两层不要混成一种抽象。

10. **同步策略显式选型**
    - 若要做实时多人：学 AppFlowy/AFFiNE 的 CRDT，**不要**假装思源事务能当 CRDT。
    - 若库级同步：冲突副本策略清晰可测（思源 `GenerateConflictDoc`）。

### 10.2 明确否决

| 否决项                                          | 原因                                                                                    |
| ----------------------------------------------- | --------------------------------------------------------------------------------------- |
| **整仓 Go 内核嵌入 / cgo 嵌 SiYuan**            | 与 Conex **Rust Agent 同进程**目标分裂；双运行时、双工具链、调试与发布灾难              |
| **AGPL 深拷贝/衍生**                            | 传染风险；选型文档已锁「禁 AGPL 嵌入」                                                  |
| **Electron 壳**                                 | 与 Tauri 目标冲突                                                                       |
| **以 contenteditable HTML 字符串为长期权威 op** | 难虚拟化、难精细 merge、难安全校验；可学「事务边界」，实现应更结构化                    |
| **把 SQLite 当唯一文档真相**                    | 思源自己都把文件当权威；索引当真相会丢失可移植性/可 diff 性（除非产品明确选择 blob 库） |
| **用标准 MD 文件树当唯一权威却宣称块引用无损**  | 与思源实践相反；ID/IAL 会丢                                                             |
| **中途把真相迁回 JS Yjs「先能跑」**             | 与已锁「Rust 心」冲突（见 `10-选型锁定`）                                               |

### 10.3 建议映射（机制 → 本仓落点）

| 思源机制                   | 本产品落点（方向）                                     |
| -------------------------- | ------------------------------------------------------ |
| `model.Transaction` + 队列 | Rust 文档服务：`apply_ops` 串行/分 shard 队列          |
| `.sy` AST JSON             | RS 块树快照格式（可分块；勿无脑复制 JSON 整树）        |
| `blocktree.db`             | 块定位索引（SQLite/或现有 conex 存储）                 |
| FTS + refs                 | 派生索引任务；可重建                                   |
| Lute 纪律                  | 统一 MD 解析策略（自研或选型 RS 库），**配置矩阵单测** |
| MCP 块工具                 | Agent tools 直接调文档事务 API                         |
| dejavu 冲突副本            | 若做文件同步：冲突策略产品化；实时协同另选 CRDT        |

## 12. 验收式摘要（给主控合并用）

1. **真相层**：Go 内核 + `.sy` AST；前端是投影；SQLite 是派生索引。
2. **一致性**：全局 `flushLock` 串行事务；非 CRDT。
3. **MD**：AST 一等；BlockDOM 是编辑管线；标准 MD 有损边界明确。
4. **差异**：相对 AFFiNE/AppFlowy，思源是「文件权威 + 事务队列 + 库同步」学派。
5. **性能**：动态加载 + 索引 hash 增量 + 异步队列；整树 JSON 仍是上限。
6. **对本产品**：内化事务/ID/索引/MD 纪律/Agent 工具面；**否决 Go 整仓与 AGPL 嵌入**；协同若要实时必须另建 RS 合并，不能指望照搬思源同步。
