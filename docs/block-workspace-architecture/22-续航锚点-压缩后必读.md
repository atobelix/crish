## 4. 多 Agent 轮次模型（用户 2026-08-11 钉死 · **三套独立计数**）

> **铁律**：下列 **三套名额互不占用、不可相加混算**。禁止把「审计 + 方案包 + 审计后执行」塞进同一个 6。

| #     | 计数桶               | 名额从哪来                                                                    | 职责                                                                                  |
| ----- | -------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| **①** | **审计 Agent**       | **单独计**（通常每轮 1；与 ②③ 无关）                                          | 审上轮 → 审历史 → 落盘 + 写出/追加下一阶段计划（`audit/*/04-…`）                      |
| **②** | **计划方案 Agent**   | **方案里已经写死的数量**（`plans/09` 包表 / 当轮 `04` 派单表「本波 N 包」等） | 按文档交付对应 Strict/Skeleton 包；**派几个 = 方案写几个**，不是「往 6 上凑」         |
| **③** | **审计后执行 Agent** | **独立上限 6**（可 0–6；不打满正常）                                          | 消化审计红/黄补洞、审计计划里标的「须先修/补焊」项等；**不吃** ② 的名额，也**不占** ① |

**统一轮次形态（①∥② 同轮并行；③ 勿忘）**：

```
每轮同时：
  ① 审计×1     —— 审「上一轮已合入」→ 落盘 + 写出/刷新「下一轮」04
  ② 方案执行×P —— 用「上一轮已落盘的 04 / 09 写死表」派单（P=表行数）
  ③ 审计后执行×E —— 用「上一轮审计标红/黄补洞」或本轮审计若已先结束则并入；E≤6 独立
```

| 要点       | 内容                                                                                    |
| ---------- | --------------------------------------------------------------------------------------- |
| **①∥②**    | **同一轮一起做**，禁止「等审计跑完再派方案」串成两轮（压缩后主控易忘）                  |
| **② 依据** | 派 ② 时读 **上一轮** `audit/*/04`（或 09 下一闸表）；**本轮 ① 产出的 04 给下一轮 ② 用** |
| **③ 勿忘** | 审计红/黄补洞 **必须**占 ③ 桶；无洞则 E=0；**禁止**因并行 ② 把 ③ 漏掉                   |
| **文件域** | ① 只写 `audit/**`（+19/22 指针）；②③ 分锁业务树；同文件串行                             |

**禁止**：

- 把 6 当成「全轮总 Agent 数」或「②+③ 合计 ≤6」
- 方案写 3 却为打满 6 硬派空包
- **只派 ② 不派 ①**，或 **只派 ① 干等再派 ②**（违反同轮并行）
- **有 ③ 清单却漏派**
- 用 ③ 偷换 ② 的包定义 / 偷关 EL
