## 0. 结论先行

| 项                 | 裁决                                                                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **主路径**         | **块纸面外壳自研（React 投影 + 窗口化挂载）** + **叶子富文本输入核 = 裸 ProseMirror（窗口级、单块/单叶子）**；**文档权威永在 RS**；TS 只持「当前窗口投影 + 本地 selection 映射 + 乐观 DOM」               |
| **强备选**         | **全自研 contenteditable / 投影**（无 PM 依赖）：仅当裸 PM 的「整文档 Schema 假设」或「单 EditorView 生命周期」经魔鬼用例证明**无法**被压成「叶子窗口」且仍满足 IME/选区不变量时启用                      |
| **弱备选（局部）** | TipTap **仅**作「叶子 PM 扩展脚手架」研究样本，**禁止** TipTap+Yjs / Collaboration 当局；CodeMirror 6 **仅**作代码块叶子输入核（与行级引擎可共享纪律）                                                    |
| **否决**           | 整嵌 BlockSuite 当局 · Yjs-in-JS 当局 · TipTap/Docmost 整栈当局 · Lexical 作文档真相 · Slate 老路径当局 · Quill 当局 · 用行级 `lines[]` 冒充块树                                                          |
| **必须自研**       | 块 chrome（把手/多选/拖放/slash 宿主）· 静默模式 · **块选 + 文本选双层映射**（`blockId + offset` ↔ DOM）· RS op 投影 apply · 窗口虚拟化 · composition 隔离策略与行级对齐 · 远端选区绘制（awareness 只读） |
| **可调包**         | 叶子层：`prosemirror-model/state/view/transform/commands/keymap/history`（MIT）；代码块叶子可选 CM6；KaTeX/Shiki 等**渲染**件                                                                             |

**一句话**：

> 呈现引擎是 **投影机**，不是 **真相机**。Notion 级块交互的「宇宙」在自研外壳；击键/IME/行内 mark 的「显微镜」用裸 PM（或等价叶子核）压在 **单块窗口** 内。任何让 PM/TipTap/Yjs 持有整树权威的路径，与 08/12 硬锁互斥。

```
┌──────────────────────────────────────────────────────────────┐
│  块纸面外壳（自研 TS/React）                                   │
│  · 块列表虚拟化 / 折叠 / 多选矩形 / 把手 / slash 宿主 / 静默   │
│  · SelectionBroker：BlockSel ∥ TextSel ∥ RemoteAwareness       │
│  · 写路径：Intent → normalize Op → IPC → RS apply → Diff 投影   │
├──────────────────────────────────────────────────────────────┤
│  叶子输入核（每「活动」叶子 0..1 个 EditorView）               │
│  · 裸 ProseMirror：paragraph / heading / list item 文本…     │
│  · 可选 CM6：code fence 叶子                                  │
│  · schema 只描述**叶子内** inline；块类型/父子在 RS            │
├──────────────────────────────────────────────────────────────┤
│  权威（Rust，见 D2）                                          │
│  · 块树 + 结构化 Op + 叶子文本 CRDT/delta · 事务/origin/权限   │
└──────────────────────────────────────────────────────────────┘

行级 markdown-editor（聊天/流式）── 模型隔离 ── 共享：IME 状态机纪律、
  data-* 无损映射思想、虚拟滚动工具、token/公式渲染件
```

## 1. 该层效果锁（不可降级）

### 1.1 用户可见（Notion 级块交互 + 静默写作）

| ID      | 效果                      | 不变量 / 可感信号                                                                                             |
| ------- | ------------------------- | ------------------------------------------------------------------------------------------------------------- |
| E-D1-01 | **块为一等公民**          | 任意内容块有稳定 `blockId`；转类型 / 缩进 / 移动 / 删除不丢引用身份（与 D2 块 ID 契约一致）                   |
| E-D1-02 | **Slash 命令**            | `/` 在叶子内触发；**IME 合成中不误触发**；compositionEnd + 范围同步后再判 `/`（对齐 AFFiNE slash 纪律）       |
| E-D1-03 | **块把手 + 拖拽**         | 悬停出 handle；多选拖拽重排；落点指示线；跨文档拖入时 **重生成 id**（机制学 AFFiNE middleware，实现自研）     |
| E-D1-04 | **多选**                  | 文本选（单叶子内 / 跨叶子）与 **块级框选** 两套；块菜单/批量转类型/批量删除对块选生效                         |
| E-D1-05 | **MD 前缀快路径**         | 行首 `# `、`- `、`1. `、`[] ` 等在空格/Enter 时转块；**composing 期间禁止**                                   |
| E-D1-06 | **静默写作（默认 L0）**   | 默认 chrome 极少（对标 Typora / 思源 gutter 滚动即藏）；把手/工具条/slash **按需露出**；不挡输入与 IME 候选窗 |
| E-D1-07 | **IME 一等**              | 中日韩合成不丢字、不拆错 undo、候选窗锚在光标；禁止 composition 中整树/整窗口重建 DOM                         |
| E-D1-08 | **大文档可活**            | 十万级块：仅窗口内挂载真实可编辑 DOM；滚动流畅；非窗口块为占位/测量骨架                                       |
| E-D1-09 | **块转类型不丢选区**      | paragraph→heading / list 等：光标逻辑位置（块内 offset 或 mark 边界）在投影后可恢复                           |
| E-D1-10 | **远端选区可画**          | awareness 光标/块高亮可丢、可覆盖；**不进**文档历史；与本地选区分层                                           |
| E-D1-11 | **Agent 批量写不撕裂 UI** | 远端/Agent 大批 op 到达时：窗口 diff 应用；焦点块优先保活；不整页 remount                                     |
| E-D1-12 | **与行级引擎并存**        | 聊天流式仍走行级；笔记块纸面不调用 `lines[]` 当局；共享渲染件不得共享权威 store                               |

### 1.2 架构不可见不变量

| ID      | 不变量                                                                                                 |
| ------- | ------------------------------------------------------------------------------------------------------ |
| I-D1-01 | **呈现层不持文档权威**；最多持「窗口投影 + 本地 selection 映射 + 乐观未确认 intent 队列」              |
| I-D1-02 | 写路径：`UI Intent → Op → RS`；禁止「只改 DOM / 只改 PM doc 当最终提交」                               |
| I-D1-03 | **禁止**浏览器 `Y.Doc` / JS CRDT 作唯一真相（可研究 y-protocol 互通，见 D2）                           |
| I-D1-04 | **禁止**整嵌 BlockSuite / Protyle 运行时当局                                                           |
| I-D1-05 | 逻辑选区坐标 = **`{ blockId, offset                                                                    | anchor/head }`**（及块多选集合）；**禁止**长期以像素坐标猜块 |
| I-D1-06 | DOM 映射优先 **`data-block-id` / `data-offset` 类原生属性**（对齐行级 `data-token-*` 纪律），O(1) 反查 |
| I-D1-07 | 叶子输入核 **可销毁可重建**；销毁不得丢未提交 composition（先 commit 或 abort 策略显式）               |
| I-D1-08 | 虚拟化卸载块时：若持焦点/composition → **钉住**或 **先结束合成**；禁止静默丢字                         |
| I-D1-09 | schema：**块类型与树形状在 RS**；PM/CM schema 仅叶子 inline 子集                                       |
| I-D1-10 | 许可：呈现依赖 MIT/Apache 等可商用；不因编辑器包引入 AGPL 运行时                                       |

### 1.3 裁判键（重申）

效果完整度 → 正确性/不变量 → 可验证性 → 与「RS 心 + TS 皮 + Tauri 壳 + 双引擎」契约一致 → 结构干净。
**不得**以「业界都用 TipTap+Yjs」「BlockSuite 开箱完成度高」把真相迁回 JS 或整嵌引擎。

### 2.3 分维深评

#### 2.3.1 Schema / 事务模型

| 候选           | Schema                                              | 事务                                                       | 对「块树在 RS」的含义                                                                                                                |
| -------------- | --------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **裸 PM**      | `Schema` 节点/mark；`doc` 为树                      | `Transaction` + `EditorState.apply`；插件过滤              | **若**把整篇笔记建模为单个 PM doc → 与 RS 双真相风险极高。**合法用法**：PM doc = **单叶子**（或极小片段）的 inline 树；块父子不进 PM |
| **TipTap**     | 扩展声明 node/mark                                  | 同 PM；高层 `editor.commands`                              | 默认「一页一 Editor」；Collaboration 扩展把事务灌进 Yjs → **与 I-D1-02/03 冲突**                                                     |
| **Lexical**    | 节点类 + 配置                                       | 不可变 `EditorState` 更新；`update` 闭包                   | 可把 Lexical 当叶子；整页单实例同样有虚拟化与双真相风险                                                                              |
| **CM6**        | 文本 + 语法树扩展；非通用块 schema                  | 事务 + change set                                          | 适合 **代码叶子**；不承担块树 schema                                                                                                 |
| **自研 ce**    | 完全自定；建议与 RS flavour 镜像                    | 必须自研「intent 事务」；禁止只改 DOM                      | 与 D2 Op 可直接同构                                                                                                                  |
| **混合 C6**    | RS：块 flavour + props；PM：叶子 inline schema 子集 | 块 op 在 RS；叶子 text_edit 经 PM step → 映射为 RS text op | **唯一默认同时满足**「块事务可测」与「行内编辑成熟」                                                                                 |
| **BlockSuite** | flavour + Y 绑定 BlockModel                         | 进 Y 更新                                                  | 真相在 JS CRDT 族（round-A/C 已裁）                                                                                                  |
| **Slate**      | 自定义 Element 树                                   | operation 列表                                             | 可投影，但 IME/历史协作债重，无本仓已证优势                                                                                          |
| **Quill**      | Delta blot                                          | Delta 事务                                                 | 表达力停在「富文本嵌入」，不是块工作区                                                                                               |

**不变量钉**：任何候选的「编辑器内部 doc」在架构图上只能标为 **Projection**，apply 远端时必须能 **reset/patch 而不产生反向权威写**（除本地未确认 intent 的 rebase）。

#### 2.3.2 与 RS op 投影的兼容性

| 投影方向 | 要求                                                                                          | 候选适配                                                                                     |
| -------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| RS → UI  | 窗口内块 props/text 增量 patch；保持焦点映射                                                  | C5/C6 最干净；C1 需自定义 `NodeView` + 禁止默认 history 当局；C2 需关掉 collab、自写 storage |
| UI → RS  | 击键/删/行内 mark → `text_edit` / `set_prop`；Enter 拆块 → `split_block`；拖拽 → `move_block` | 必须在 **dispatch 边界** 截获，不能等「整 doc JSON 导出」                                    |
| 冲突     | 本地 optimistic + RS reject/rebase                                                            | 所有候选都要自研队列；**无**包替                                                             |

**适配器契约（推荐冻结）**：

```
type LeafProjection = {
  blockId: BlockId
  // 与 RS 叶子文本 CRDT/版本对齐的只读快照或 diff
  text: string | Delta
  marks?: InlineMark[]
}

// 叶子核 → 意图（尚未权威）
type LeafIntent =
  | { type: 'text_edit'; blockId; range; insert?; delete?; marks? }
  | { type: 'split_block'; blockId; offset }
  | { type: 'request_slash'; blockId; offset }

// 外壳 → 意图
type ChromeIntent =
  | { type: 'move_blocks'; ids; parent; index }
  | { type: 'turn_into'; ids; flavour }
  | { type: 'set_block_sel'; ids }
```

PM `Step` / CM `ChangeSet` / Lexical `Node` 变更 **只允许**在 Adapter 内翻译为上述 Intent；**禁止**把 PM JSON 整棵当 RS 存储形状。

#### 2.3.3 虚拟化可行性

| 策略                   | 说明                                  | 谁友好                                                                   |
| ---------------------- | ------------------------------------- | ------------------------------------------------------------------------ |
| **文档级窗口挂载**     | 仅 render `scrollTop` 附近 N 个块 DOM | C5/C6 天生；思源动态加载是同构标尺（非整树虚拟列表也行，但是「窗口化」） |
| **单 EditorView 全树** | 十万节点进一个 PM/Lexical doc         | C1/C2/C3 **结构敌对**；AFFiNE Page 全挂载是反例（round-C `08`）          |
| **回收叶子 View**      | 失焦销毁 PM View，保留块壳占位        | C6 **核心技巧**；须处理 I-D1-07/08                                       |
| **CM6 自身虚拟**       | 长代码块内虚拟行                      | C4 作为代码叶子 **加分**                                                 |

**结论**：效果锁 E-D1-08 把「单 View 整文档」方案在结构上降为不合格（除非另证能窗口化 doc 切片且选区跨窗正确——当前无竞品干净范例，**不作为主路径**）。

#### 2.3.4 协同选区映射

| 层        | 内容                                                           | 通道                          |
| --------- | -------------------------------------------------------------- | ----------------------------- |
| 权威文档  | 不存光标                                                       | —                             |
| Awareness | `{ user, color, anchor: {blockId, offset}, head?, blockIds? }` | 可丢（D2）                    |
| 本地      | SelectionBroker 统一块选/文本选                                | 内存                          |
| 绘制      | 远端层绝对定位或 CSS highlight；**不**改文档 DOM 文本节点内容  | React portal / canvas overlay |

PM 的 `Position` 仅在 **叶子存活** 时有效；跨块选区必须升格为 **多段 blockId+offset**，不能假设全局 PM pos。
行级引擎已有「逻辑 offset 可映射 OT/CRDT」思想（`reference/markdown-editor` 分析文档）——块级应 **同构升级为 blockId 前缀**，而非复用行号。

#### 2.3.5 扩展模型

| 扩展点            | 主路径落点                           | 不可放在                         |
| ----------------- | ------------------------------------ | -------------------------------- |
| 新块 flavour 视图 | 壳：`flavour → React 组件`           | PM 顶层 node（会诱使整树 PM）    |
| 行内 mark / 短码  | 叶子 PM plugin / mark                | —                                |

| Agent 工具        | **RS**（学思源 MCP），不经编辑器扩展 | 编辑器插件直写盘                 |

## 5. 推荐主路径 · 备选 · 换引擎触发条件

### 5.1 主路径（C6）：自研块壳 + 窗口级叶子裸 PM（+ 代码叶 CM6）

**构造要点**：

1. **块壳**：React（与现皮一致）虚拟化列表；每块壳带 `data-block-id`；非活动块 = 只读投影 HTML/React（可来自 RS 预渲染或轻量 token 渲染）。
2. **活动叶子**：focus 时挂载 **一个** `EditorView`；`pmDoc` 由 `LeafProjection` 构建；`dispatchTransaction` → 译为 `LeafIntent` → 入 RS。
3. **失焦**：flush 未确认 intent → 销毁 View → 回只读投影（或 keep-alive 池限 N 个，上限可测）。
4. **跨块选区**：外壳管理；进入多块选时叶子 PM 选区降级/只读。
5. **History**：叶子内 composing/连续输入可本地 group；**Undo 命令默认打到 RS**（origin=user），保证与 Agent/远程同一时间轴。
6. **静默**：chrome 状态机独立 store；与选区解耦。

**为何胜出（合法裁判键）**：

| 键         | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 效果完整度 | 壳可打满 Notion/AFFiNE/思源交互清单；叶子 IME/行内不从零造轮 |
| 正确性     | 权威单点在 RS；PM 生命周期被窗口约束，难漂移成第二真相       |
| 可验证性   | Adapter + SelectionBroker 可单测；魔鬼用例可钉               |
| 契约一致   | 对齐 08/12/13；与 D2 混合 op、D5 投影/IME 同向               |
| 结构干净   | 块树不进 PM schema；映射走 data-* 而非测距                   |

### 5.2 备选

| 优先级 | 路径                                  | 启用条件（仅不变量/效果，非口味）                                                                                                                |
| ------ | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **B1** | **全自研 contenteditable 投影**（C5） | 魔鬼用例证明：叶子 PM 在 Tauri WebView 下 **无法** 满足 E-D1-07（IME）与 I-D1-07/08（挂卸）的合取；或 PM 强制全局 pos 导致跨块选区正确性不可修复 |
| **B2** | **叶子改 Lexical**                    | 同 B1 但问题出在 PM 特有 API，且 Lexical 多实例 + React 集成在验证中 **严格更优**（IME/映射/包体综合）                                           |
| **B3** | **代码叶强化 CM6**                    | 主路径已含；当代码块成为热路径且 PM 代码编辑体验不足时 **扩大 CM6 比例**，非换整引擎                                                             |
| **B4** | TipTap 糖衣                           | 仅当扩展 DX 在 **不引入 collab/Y** 前提下减少叶子样板，且 Adapter 测试全绿——**默认不需要**                                                       |

### 5.3 何种不变量破坏才允许「换呈现引擎」

允许评估换核的 **仅** 以下情况（须带失败用例与复现，提交主控裁决）：

| 触发 ID | 破坏的不变量/效果                                                       | 允许的动作                                             |
| ------- | ----------------------------------------------------------------------- | ------------------------------------------------------ |
| T1      | E-D1-07：目标 WebView 上 IME 无解（丢字/卡死/候选窗错位）且非自研壳 bug | 换 **叶子核**（PM↔自研 ce↔Lexical），**不**换 RS 权威  |
| T2      | E-D1-08：窗口化在「焦点钉住 + 十万块」下无法同时成立                    | 改虚拟化策略或叶子挂载模型；仍禁止整树单 View 当唯一解 |
| T3      | I-D1-05/06：逻辑选区与 DOM 无法建立 O(1) 可靠映射                       | 重做映射层或换叶子核；禁止像素补丁冒充修复             |
| T4      | I-D1-01：某路径证实呈现层不可避免持真相                                 | **路径非法**，改架构而非「换成另一个 JS 真相引擎」     |
| T5      | 许可：依赖变为 AGPL/Source Available 污染                               | 换依赖或自研替代                                       |

**明确永不构成换引擎理由**：生态流行度、招聘熟悉度、「AFFiNE 开箱更快」、与 Docmost 同构省事、想用 Yjs 光标组件。

## 9. 诚实边界

- **开箱完成度**：主路径冷启动时，块 chrome 清单会暂弱于 AFFiNE/Protyle **产品填充**——须用 §7 清单追上；**禁止**用整嵌引擎换完成度（会锁死 08/12 上限）。
- **裸 PM 不是银弹**：叶子级仍有 WebView IME 差异；行级引擎的 composition 纪律要 **迁到块叶子**，不是自动免费。
- **「仅 NodeView」**：若解读为「整页仍是一个 PM doc、块用 NodeView」→ **等同 C1 全树**，虚拟化不友好，**不是**本文 C6。C6 = **外壳列表 + 至多窗口级多个短命 EditorView**。
- **未跑** 本轮真实 10 万块基准数字：DV-VIRT-* 为验收钉，指标阈值由 D5/实现波填入硬预算，本文钉的是 **结构可行性与失败模式**。
