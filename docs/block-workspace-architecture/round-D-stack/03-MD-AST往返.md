## 0. 结论先行

| 项                                      | 裁决                                                                                                                                                                                 |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **主路径**                              | **双轨**：RS **块树 IR（运行时权威）** + **Conex-MD 方言（磁盘/Agent/互操作一等契约）**；编辑热路径走块 op，**不**每键 MD↔树；落盘/工具/剪贴板/导出走 **parse ⟷ serialize 契约管线** |
| **GFM 基座（调包）**                    | **首选 `markdown-rs`（crate `markdown`）** 作 CommonMark/GFM/mdast 基座；**备选 `comrak`**（完整 AST + GFM 规格同源）                                                                |
| **必须自研**                            | Conex 块 IR、块 ID 编解码、扩展语法（callout/wiki/TOC/合并表…）、规范化策略、有损边界报告、与 D2 merge/事务接线                                                                      |
| **`pulldown-cmark` / `conex-markdown`** | **延续聊天行级流式渲染面**（MD→安全 HTML）；**不**升格为块纸面权威往返引擎——现状能力缺口是结构性的，不是「再写一层 adapter 就够」                                                    |
| **TS remark/mdast**                     | **仅工具链 / golden 对照 / CI 辅助**；禁止作运行时权威                                                                                                                               |
| **思源 Lute**                           | **学纪律不嵌**：AST 权威热路径、Kramdown IAL/块 ID、标准 MD 有损边界显式化；AGPL 禁嵌                                                                                                |

**一句话**：

> **MD 是契约语言，不是「导出凑合」；权威块树在 RS。** 标准 GFM 用成熟 RS 解析基座；Conex 语义与块 ID 自研封顶。`conex-markdown` 继续服务聊天预览，块工作区另建 **MD↔BlockIR** 往返 crate（可与之共享 sanitizer/高亮，不共享「真相形状」）。

## 2. 往返不变量（契约核）

下列不变量是 D3 的「正确性钉子」。任何候选/实现若不满足，则不得称为「MD 一等」。

### 2.1 语义层（Semantic Round-Trip）

记：

- `P` = parse：`&str` → `BlockTree`（RS）
- `S` = serialize：`BlockTree` → `String`（Conex-MD 或 pure-gfm 模式）
- `N` = normalize：语法无关空白/列表标记/fence 长度等 **规格内** 规范化

| #    | 不变量                   | 形式化                                                                                 | 验收              |
| ---- | ------------------------ | -------------------------------------------------------------------------------------- | ----------------- |
| RT-1 | **结构幂等**             | `P(S(t)) ≡ t`（在 BlockTree 等价关系下；忽略纯 UI 态）                                 | 属性测试 + golden |
| RT-2 | **文本幂等（规范化后）** | `N(S(P(md))) = N(md)` 对 **GFM 核心 + Conex 规范子集**                                 | golden files      |
| RT-3 | **双次稳定**             | `S(P(S(P(md)))) = S(P(md))`                                                            | 防振荡            |
| RT-4 | **块 ID 守恒**           | 凡带 ID 的块：`P→S→P` 后 ID 集合与父子序守恒（除显式 delete/merge op）                 | ID 矩阵测         |
| RT-5 | **引用守恒**             | 块引用/wiki 目标 ID 在往返后仍可解析；断链可诊断不可静默变纯文本（除非 pure-gfm 降级） | 引用图测          |
| RT-6 | **模式分离**             | `mode=conex` 与 `mode=pure-gfm` 的有损差集 **可列举**；pure-gfm 不得声称 ID/扩展无损   | 模式矩阵          |
| RT-7 | **合并后仍可契约**       | D2 merge 结果 `t'` 必有 `S(t')` 合法且 `P(S(t')) ≡ t'`（E-D2-06）                      | 与 D2 联测        |

### 2.2 等价关系 `≡`（什么算「一样」）

**计入等价**：块类型、块序、父子、任务勾选、表格行列与对齐、围栏语言标签、链接目标与标题、强调边界语义、块 ID、Conex 扩展节点类型与载荷。

**不计等价（允许 N 吞掉）**：行尾空格、最终 EOF 换行、无序列表 `-`/`*` 统一、有序起点显示策略（源 `1.` 可保留）、围栏反引号个数 ≥ 内容所需最小、无意义空行压缩（规格写死策略）。

**禁止计入「规范化」偷渡**：不得把「丢掉块 ID / 拆合并单元格 / 剥离数学」算作 N——那些是 **有损模式** 或 bug。

### 2.3 边界分层（三层表面）

```
┌─────────────────────────────────────────────────────────────┐
│  L0  用户/Agent 可见 MD 文本（Conex-MD 或 pure-gfm）         │  ← 一等契约
└────────────────────────────┬────────────────────────────────┘
                             │ P / S（本决策单元）
┌────────────────────────────▼────────────────────────────────┐
│  L1  RS BlockTree IR（含 ID、props、叶子文本 CRDT 句柄）    │  ← 运行时权威
└────────────────────────────┬────────────────────────────────┘
                             │ 投影（D1/D5）；非权威
┌────────────────────────────▼────────────────────────────────┐
│  L2  TS 只读镜像 / 编辑器投影 / 聊天 HTML（conex-markdown） │
└─────────────────────────────────────────────────────────────┘
```

**禁止**：L2→L0 旁路写权威；L0 直接覆写文件绕过 L1 事务（Agent 工具实现必须经 RS apply）。

## 3. 有损点清单（必须显式）

> 原则：有损不可消灭处，必须 **分档 + 可测 + 可报告**。禁止「看起来能导出」却静默毁结构。

| 类别                  | 现象                               | 往返风险                                         | 契约策略                                                                                             |
| --------------------- | ---------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| **GFM 表格**          | 无 colspan/rowspan；对齐仅左/中/右 | 合并单元格 **无法** 无损进 pure GFM              | Conex 模式：扩展语法或 HTML table 节点（规格钉死）；pure-gfm：**拆平或逐格重复** + 降级报告          |
| **原始 HTML**         | 块级/行内 HTML、注释               | 解析器默认消毒/丢弃/透传策略不一；安全与保真冲突 | **白名单**块（如注释承载 ID）；其余默认 escape 或 `HtmlBlock` 保留原文（二选一写进规格，禁止半透传） |
| **数学**              | `$…$` / `$$…$$`                    | GFM 无；易与货币符号冲突                         | Conex 扩展节点；pure-gfm：保留源码围栏或降级为代码块并报告                                           |
| **脚注**              | `[^id]`                            | GFM 有；部分基座开关默认关；与块引用语义易混     | 启用则纳入 RT；禁用则解析为普通文本并文档化                                                          |
| **任务列表**          | `- [ ]` 嵌套/中断                  | 列表紧密度与懒延续边界                           | 钉 GFM 行为；golden 覆盖嵌套 task                                                                    |
| **硬换行 / 软换行**   | 两空格 vs `\` vs 段落              | 序列化选择影响 diff                              | N 统一一种；规格写死                                                                                 |
| **setext 标题**       | `===`                              | 与 ATX 语义同、形状不同                          | 序列化 **只出 ATX**；parse 仍接受 setext                                                             |
| **缩进代码块**        | 四空格                             | 与列表嵌套歧义                                   | 序列化 **只出围栏**；parse 可接受缩进                                                                |
| **自动链接**          | `<http://>` / 裸 URL               | GFM autolink 规则细                              | 开启矩阵单测；序列化偏好显式 `[](url)` 或保留 autolink（二选一钉死）                                 |
| **HTML 实体**         | `&amp;`                            | 往返可能「解开再编」                             | 文本节点存解码后 Unicode；S 按需再编码                                                               |
| **YAML front matter** | `---` 头                           | 非正文块                                         | 文档 props 侧车或首块 `FrontMatter`；不进正文块 ID 空间                                              |
| **Conex callout**     | `> [!NOTE]` 等                     | 外置渲染器当普通引用                             | Conex 模式保留；pure-gfm 降为 blockquote + 报告                                                      |
| **wiki / 块引**       | `[[…]]` / 自定义 ref               | 外置丢失                                         | Conex 保留；pure-gfm 降为普通链接或纯文本 + 报告                                                     |
| **折叠 / UI 态**      | fold、选区、scroll                 | **不应**进 MD 契约                               | 禁止写入 S；存 session/UI 层                                                                         |
| **块 ID**             | 见 §4                              | pure-gfm 读者噪音                                | conex 模式写入；pure-gfm **剥离 ID** 并声明「引用不可携」                                            |
| **emoji shortcode**   | `:smile:`                          | 非 GFM 核心                                      | 不进核心 RT；可选扩展                                                                                |
| **智能标点**          | 弯引号                             | 破坏源码级往返                                   | **禁用**（`conex-markdown` 已对 pulldown 关闭 SMART_PUNCTUATION，块管线保持）                        |

**聊天渲染面（`conex-markdown`）额外有损**（不要求块契约）：思考占位剥离、输入截断 `MAX_MARKDOWN_INPUT`、非 img 的 raw HTML escape——这些 **不得** 泄漏进块纸面 `P/S`。

## 4. 块 ID 如何进入 MD

### 4.1 候选编码

| 方案                      | 形态示例                                            | 优点                                                     | 缺点                                               | 裁决                          |
| ------------------------- | --------------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------- | ----------------------------- |
| **A. HTML 注释**          | `<!-- conex:id=20260811… -->` 紧贴块前/后           | 多数 MD 工具忽略；实现简单；与 HTML 白名单可对齐         | 手改易丢；pure 预览仍「可见噪音」；嵌套块需纪律    | **可选辅**                    |
| **B. 属性扩展（推荐主）** | 标题/段落尾 ` {#bid}` 或 Kramdown 形 `{: id="bid"}` | 可读；与 Pandoc/Kramdown 生态相近；思源 IAL **机制同构** | 非 GFM 标准；外置可能当正文                        | **Conex 模式主编码**          |
| **C. 旁路 map**           | `note.md` + `note.conex-ids.json`                   | 正文干净                                                 | **两文件易不同步**；违背「MD 一等」；合并/移动灾难 | **否决作主**；仅迁移/修复工具 |
| **D. 标题锚唯一**         | 仅用 slug                                           | 无扩展                                                   | 改标题即断链；无段落 ID                            | **否决**                      |
| **E. 数据岛**             | 文末 ` ```conex-meta`                               | 集中                                                     | 局部编辑/切片加载差；冲突大                        | **否决作主**                  |

### 4.2 推荐规格（主路径）

1. **稳定 ID 格式**（可对齐思源思路，不必同形）：全局唯一、URL-safe、生成单调可排；**根文档 ID 与路径策略**在 D4 钉，D3 只要求 **内容内 ID 可序列化**。
2. **Conex-MD 主编码 = 块属性尾附**（方案 B）：
   - 块级：在块「逻辑末」写入 `<!--c:ID-->` **或** 行尾 ` {#ID}`——**实现前用 golden 二选一钉死一种主形式**（推荐 **紧凑 HTML 注释 `<!--c:ID-->`** 作为机器主，属性尾附作可读别名若需要）。
   - **推荐定稿倾向**：`<!--c:ID-->` 作为 **机器权威 in-band 标记**（注释在 CommonMark 属 HTML；parse 时剥离为节点属性，**不进可见文本**）；序列化时写回块边界稳定位置（块起始行前独占一行，避免行内打断中文）。
3. **叶子内联**不分配块 ID（对齐思源：容器/块节点有 ID，标记节点无 ID）。
4. **pure-gfm 导出**：剥离全部 ID 标记；可选生成「引用对照表」附录（默认关）。
5. **旁路 map**：仅 `conex repair` / 导入迁移；日常保存 **禁止** 只写 map 不写 in-band。
6. **冲突**：parse 遇重复 ID → 后者分配新 ID 并记 warning（可进 Agent 可见诊断），禁止静默覆盖引用图。

### 4.3 与思源 IAL 的「学不嵌」

思源：`SetKramdownIAL(true)`，块属性进 Kramdown IAL；标准 MD 导出丢 IAL（round-C `02` §4）。  
本产品：

- **学**：ID/属性 in-band；标准/GFM 导出分档有损；热路径不靠 MD。
- **不嵌**：Lute、`.sy` JSON、GopherJS 双端解析器。
- **差异**：默认用户文件保持 **可 git diff 的 MD**，不是默认 `.sy`。

### 5.3 对本仓 `pulldown-cmark` / `conex-markdown` 的延续论证（禁止默认最优）

**现状事实**（代码）：

- `crates/conex-markdown`：`pulldown-cmark` 事件 → **自定义 HTML** + syntect 高亮 + ammonia 消毒 + moka 缓存。
- 公共 API 全是 `render_markdown*` / `highlight_code`——**无** `parse_to_blocks` / `serialize`。
- Options：`ENABLE_TABLES | ENABLE_TASKLISTS | ENABLE_STRIKETHROUGH`；**不**开 smart punctuation；HTML 仅透传安全 img（`renderer.rs` 头注释与 Options）。
- 契约是 **CSS 选择器 byte 兼容**（`md-rendered` / `code-fence` / …），不是 BlockTree 往返。

**结构洞**（为何不能「已有=块纸面最优」）：

1. **无 AST 产品类型**：事件流适合渲染，不适合块 ID、移动、merge、索引投影。
2. **无 serialize 一等路径**：`pulldown-cmark-to-cmark` 只能近似还原事件对应的 MD，**不能**表达 Conex 块 IR、合并表、ID 策略、降级报告。
3. **安全策略与保真冲突**：聊天消毒（escape 非 img HTML）与笔记「保留 HTML 块/注释 ID」目标相反；混用一管线会互相污染。
4. **双引擎已锁**：行级流式（聊天）∥ 块纸面；`conex-markdown` 属于前者。

**延续结论**：

| 面                         | 决策                                                                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 聊天 / 工具卡片 / 流式预览 | **保留** `pulldown-cmark` + `conex-markdown`；继续 HTML 契约测试                                                                |
| 块工作区 MD↔IR             | **新建** RS 管线（建议 crate 名方向：`conex-md-ast` / `conex-block-md`，名称非本波锁定）；**不**在 `renderer.rs` 上长出第二真相 |
| 共享                       | sanitizer 策略表可抽取共享；**解析 Options 矩阵分面配置**，禁止一套 Options 打天下                                              |

### 5.4 分维深评（基座 C2 vs C3 vs C4）

#### GFM 正确性与扩展

- **comrak**：长期以 GFM 兼容为卖点，AST 可 format；适合「规格对齐 GitHub」。
- **markdown-rs**：宣称 CM/GFM 测试极强，**mdast** 与 TS 生态同构，利于 golden 双端对照；math/footnote/frontmatter **开箱**。
- **纯自研**：扩展最自由，但 CM 边角（链接目的地、强调嵌套、列表打断）会变成无尽洞——**违反可验证性优先于「全自控安全感」时，不应全盘自研 GFM**。

#### 块 IR 映射成本

三者都 **不能** 直接等于 Conex BlockTree：都必须 **自研 lowering/raising**（mdast/comrak AST → 块 IR）。  
差异在「标准节点覆盖率」与「源码位置信息」：markdown-rs 带 position，利于诊断与 Agent 指错行。

#### 序列化可控性

往返质量取决于 **自研 S**，不取决于「库能否 to_html」。  
库的价值是 **P 的标准子集正确性**；S 必须按 Conex 规范化规约手写（或基于库 format 再后处理 ID/扩展）。

## 6. 调包边界 vs 必须自研

### 6.1 可调包（公开 API 面）

| 依赖                      | 允许用途                                       | 禁止用途                                    |
| ------------------------- | ---------------------------------------------- | ------------------------------------------- |
| `markdown` / `comrak`     | CM/GFM 词法与标准 AST 节点；脚注/表/任务等开关 | 直接当产品 BlockTree；直接当磁盘权威绕过 IR |
| `pulldown-cmark`          | 聊天 HTML；可选「快速预览」只读                | 块保存路径；块 ID 权威解析                  |
| `pulldown-cmark-to-cmark` | 实验/对照；事件调试                            | 块契约 S 的唯一实现                         |
| `ammonia` / 高亮          | 预览消毒与代码色                               | 定义 MD 语义                                |
| TS `remark`/`mdast`       | CI golden 对照、编辑器 lint、文档站            | 运行时 parse 写回 RS                        |

### 6.2 必须自研（禁止用包顶替）

1. **Conex Block IR** 类型与 schema 校验（与 D2 op 一致）。
2. **`P` lowering / `S` raising`**：标准 AST ↔ 块 IR；扩展节点。
3. **块 ID 编解码与冲突修复**（§4）。
4. **规范化器 N** 与 **模式**（conex / pure-gfm）。
5. **有损报告** 结构（路径、块 ID、原因码）。
6. **与事务/Agent 接线**：`apply_md_patch` / `export_md` 走同一 RS 入口。
7. **golden 与属性测试夹具**（§8）。

### 6.3 否决路径（结构洞，非工期）

| 否决                                        | 原因                                |
| ------------------------------------------- | ----------------------------------- |
| 以 `conex-markdown` HTML 输出反推块树       | HTML 已丢 ID/结构；消毒不可逆       |
| TS remark 作唯一 parse，结果 JSON 塞进 RS   | 违背 I-D3-01；双端语义漂移          |
| 整嵌 Lute / 思源导出管道                    | AGPL；Go 运行时分裂                 |
| 仅旁路 ID map + 纯 GFM 正文当「块引用无损」 | 与思源实践与 E-D3-03 冲突           |
| 每键击 `S∘P` 整篇                           | 性能与 IME 灾难；违背思源已验证纪律 |
| 内部唯一权威为专有 JSON，MD 仅「尽力导出」  | 违背「MD 一等契约」硬锁             |
| 用智能标点/重排美化当默认 S                 | 破坏 RT-2/RT-3 与 git diff          |

## 7. 与 Agent 读写 MD 的契约

### 7.1 工具面分层

| 层                | 工具形态                                          | 语义                             | 要求                                        |
| ----------------- | ------------------------------------------------- | -------------------------------- | ------------------------------------------- |
| **T0 结构主路径** | `block.insert/update/delete/move` 等              | 直接 IR op；origin=agent         | 与 UI 同事务模型（学思源 MCP）              |
| **T1 MD 片段**    | `apply_markdown { parent_id?, index?, md, mode }` | `P(md)` → 子树 → 事务插入/替换   | 返回新块 ID 列表 + warnings                 |
| **T2 文档 MD**    | `read_document_md` / `write_document_md`          | 整篇 `S`/`P`；write 必经 RS 事务 | write 默认 `mode=conex`；大文档须分块或限流 |
| **T3 外部文件**   | 工作区 `.md` 导入                                 | 同 T2；冲突走 D2/D4              | 禁止 Agent 直写绕过内核                     |

### 7.2 Agent 不变量

| ID  | 不变量                                                                                              |
| --- | --------------------------------------------------------------------------------------------------- |
| A-1 | 任意 MD 写路径最终 `apply` 进 RS；**磁盘可见 MD = S(权威树)**（或异步落盘队列与读屏障，类 FlushTx） |
| A-2 | Agent 不得依赖「未规范化的源字节全等」；以 **BlockTree 等价 + N 后文本** 为准                       |
| A-3 | pure-gfm 写出若剥离 ID，必须在 tool result 声明 `lossy: true` 与条目                                |
| A-4 | 读给模型的上下文优先 **稳定 S(conex)** 或 **块级 MD 切片**（带 ID 标记），避免 HTML 投影            |
| A-5 | 批改：支持「按块 ID 替换 Markdown 正文」；比整文件覆盖更安全                                        |
| A-6 | 失败：parse 错误带行号/offset；不写半棵树（事务原子）                                               |

### 7.3 推荐 API 形状（逻辑，非实现）

```text
parse_md(md, ParseOpts{ mode, strict_ids }) -> Result<(BlockTree, Vec<Diag>)>
serialize_md(tree, SerializeOpts{ mode, emit_ids }) -> Result<(String, Vec<Lossy>)>
apply_md_fragment(doc_id, target, md, opts) -> Result<ApplyReport>  // 内含 P + tx
export_md(doc_id, mode) -> Result<ExportReport>
```

TS 侧仅 `invoke` 上述能力；本地可缓存只读 `String` 镜像，**invalidate on event**。

### 8.3 CI 门禁建议

- **快层**：`gfm-core` + ID + 安全 HTML。
- **中层**：全 golden + 属性测试固定种子。
- **禁止**用「HTML 快照近似」冒充 MD roundtrip（H-03 纪律：真 `P/S`）。

### 8.4 规范化黄金律

- golden 入库的是 **`expected.normalized.md`**，不是「作者随手格式」。
- 另存 `input.raw.md` 测 parse 容忍度；断言针对 tree 与 normalized。

## 12. 验收式摘要（给主控 / D7）

1. **MD 是契约不是导出凑合**；**权威树在 RS**；TS 只读镜像。
2. **往返不变量** RT-1..7：结构幂等、规范化文本幂等、ID/引用守恒、模式分档、merge 后可 S。
3. **有损点**表覆盖表格/HTML/数学/脚注/扩展/UI 态；pure-gfm 必报告。
4. **块 ID** in-band（推荐 `<!--c:ID-->` 机器主编码）；旁路 map 不主存。
5. **Agent**：T0 块 op + T1/T2 MD；全部经 RS；lossy 显式。
6. **测试**：golden + 属性 + 安全；真 P/S，禁 HTML 冒充。
7. **推荐**：双轨 IR+MD；基座 **markdown-rs**（备 comrak）；自研块层；**pulldown/conex-markdown 仅聊天延续**。
8. **思源**：学 AST 纪律与 IAL 思想；禁嵌 Lute。
9. **禁止**默认「已有 pulldown = 块往返最优」——已论证结构不充分。
