## 0. 结论先行

| 项                | 裁决                                                                                                                                                                                                        |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **主路径**        | **SQLite（rusqlite，WAL）统一本地关系/元数据/时钟/出站队列/块投影/FTS5** + **文档权威 = snapshot + pending updates（BLOB 表或 CAS 文件 + manifest）** + **附件 CAS 文件系统分离** + **索引可全量/增量重建** |
| **延续 rusqlite** | **延续并升格为块工作区权威落盘面之一**——不是「聊天会话库顺便用」，而是文档/同步/索引的**默认本地引擎**；论证见 §2.3.1 / §11                                                                                 |
| **否决默认路径**  | **纯 redb/sled 当唯一库**（缺 SQL/FTS/迁移生态）；**纯文件系统 MD 当权威**（破块 ID/事务/协同）；**全文真相塞进 CRDT 编码态**（搜索不可查、不可重建）；**整嵌思源/AFFiNE/AppFlowy 存储栈**                  |
| **索引**          | **主：SQLite FTS5**（块正文 + 属性列 + refs 表）；**强备选/升级：tantivy**（大库 BM25/中文分词/独立进程索引）；二者皆**派生、可丢、可重建**                                                                 |
| **与 D2 协同**    | 合并引擎只负责 apply/merge/encode；**落盘 = Persistence 插件**（本地先写）；**索引 = 异步侧车**（不阻塞 apply）                                                                                             |
| **未来同步**      | 本地完整可写；doc / blob / awareness / indexer 分通道（学 AFFiNE nbstore 七类 storage）；水位与内容分离                                                                                                     |

**一句话**：

> **心在 RS 的本地优先 = 权威编码态（snapshot+op/update 日志）+ SQLite 关系面与可重建索引 + CAS 附件；不把 MD 文件树当真相，也不为「纯 Rust KV 洁癖」丢掉已验证的 rusqlite/WAL 资产。**

## 1. 该层效果锁（不可降级）

### 1.1 用户可见

| ID      | 效果                   | 不变量                                                                                        |
| ------- | ---------------------- | --------------------------------------------------------------------------------------------- |

| E-D4-02 | **杀进程可恢复**       | 崩溃后打开工作区：文档编码态完整；未 checkpoint 的 pending updates 不丢                       |
| E-D4-03 | **搜索可用**           | 全文命中块；按块属性（type/tag/status/…）过滤；跳转到稳定 block id                            |

### 1.2 架构不可见不变量

| ID      | 不变量                                                                                                              |
| ------- | ------------------------------------------------------------------------------------------------------------------- |
| I-D4-01 | **权威内容 ≠ 索引**；索引与 block 投影表可从权威重建（思源纪律）                                                    |
| I-D4-02 | **附件 blob ≠ 文档 doc**；分存储、分同步通道、分 GC                                                                 |

### 1.3 裁判键（重申）

效果完整度 → 正确性/不变量 → 可验证性 → 与「RS 心 + TS 皮 + 本地优先 + 未来同步」一致 → 结构干净。
**不得**以「KV 更潮」「文件即 Git 友好」砍掉事务一致性或可重建索引。

### 2.3 分维深评

#### 2.3.1 SQLite / rusqlite（S1）——**延续并升格**

| 项           | 内容                                                                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **已有资产** | `crates/conex-db`：schema 迁移链、WAL 压力测（`tests/stress_write.rs`：8 线程×500 事件）、busy/锁纪律、事件 append + 会话元数据                      |
| **能力匹配** | 单文件/分文件库、ACID、`BEGIN IMMEDIATE`、FTS5、JSON1、备份 API、跨平台 `bundled` 静态链                                                             |
| **桌面竞品** | AFFiNE 桌面 **DocStoragePool = SQLite**（snapshot/updates/clocks/blob/FTS）；AppFlowy **元数据/上传/快照条数 = SQLite**；思源 **索引 = SQLite+FTS5** |
| **风险**     | 单写者吞吐上限；超大 BLOB 与热索引同库可能页缓存争用；需 **分库或分表纪律**（见 §3）                                                                 |
| **裁决**     | **默认主存**。不是「聊天库凑合用」，是块工作区 **关系面 + 默认真相容器** 的一等选择                                                                  |

**为何不「已有=最优」的偷懒论证**：若 redb/sled 在 **文档 CRDT 热写 + 全文查询 + 迁移** 三维同时更优，应替换。实测与竞品对照显示：

- 热写可用 **pending updates 追加** 缓解（S8）；
- 全文与属性查询 SQLite 原生；
- 迁移/备份/调试（`sqlite3` CLI）对桌面运维是刚需。
  纯 KV **必须自研** 半套查询与 FTS → 效果锁「搜索 + 属性」完整度下降，故 **不替换主路径**。

#### 2.3.2 redb（S2） / sled（S3）

|             | redb                                                                                                                                                                                              | sled                                                 |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 优点        | 纯 Rust、ACID、无 C 依赖、适合 collab `doc_id → bytes`                                                                                                                                            | 历史纯 Rust KV 选项                                  |
| 结构洞      | 无 SQL/FTS；块属性/refs/队列要用第二套索引；运维无可视 SQL                                                                                                                                        | 社区定位与长期维护面弱于 redb/SQLite；同样无查询语言 |
| 合理角色    | **可选**：若未来证明「编码态 BLOB 与 FTS 同库锁竞争」成为硬瓶颈，可拆 **collab KV（redb）∥ meta+FTS（SQLite）**——对齐 AppFlowy RocksDB+SQLite **双库**，但用 redb 替代 RocksDB 以保持纯 Rust 可选 | **不推荐**新引入                                     |
| 与 AppFlowy | AppFlowy 用 **RocksDB** 存 `state_vector + doc_state`；我们若双库，语义对齐「CRDT 态 vs 关系元数据」，实现换 redb/SQLite BLOB 均可                                                                | —                                                    |

**否决「redb/sled 唯一库」**：搜索需求（全文+块属性）与同步队列/权限元数据会把 KV 逼成「手写 SQLite」，重复造轮且丢失本仓 rusqlite 测试资产。

#### 2.3.3 文件系统 MD / 块 blob + manifest（S4）

| 角色                       | 是否允许                                                                                           |
| -------------------------- | -------------------------------------------------------------------------------------------------- |
| **权威文档**               | **否**（作默认）。破坏：细粒度协同 update、稳定块 ID 与路径解耦、事务原子、Agent 批回放            |
| **导出/互操作视图**        | **是**。MD 一等契约 = 可导出/可导入，不是「磁盘上的 .md 即真相」（与思源 AST≠标准 MD、D2/D3 一致） |
| **块级 JSON/二进制文件树** | **可选冷存储**（归档、dejavu 形历史包）；热路径仍 snapshot+log                                     |
| **manifest**               | **是**：工作区清单、blob 引用、schema 版本——宜放 SQLite 或单一 `workspace.json`，且与迁移版本绑定  |

思源对照：权威是 `.sy`（AST JSON）+ 事务，**不是**一堆标准 MD；`temp/*.db` 可重建。本产品若要「文件可摸」，应提供 **导出目录** 或 **可选 mirror**，并明确 **mirror 延迟与冲突策略**（D2 M8）。

#### 2.3.4 FTS5（S5）vs tantivy（S6）

| 维度       | FTS5                                             | tantivy                                                                                |
| ---------- | ------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 部署       | 与 SQLite 同库/同连接族；零新进程                | 独立索引目录；schema 自管                                                              |
| 块属性过滤 | `blocks` 表 JOIN / external content FTS          | 需把属性建成 stored/fast 字段                                                          |
| 中文       | 需 tokenizer 扩展或 n-gram 配置；能力有限        | 分词器可插拔；上限更高                                                                 |
| 重建       | `INSERT` 投影表 + rebuild FTS                    | 删目录/全量 index 管道                                                                 |
| 本仓       | rusqlite 可开 `fts5` feature；运维简单           | archive 方案曾规划代码搜索；笔记可复用引擎思想                                         |
| 竞品       | 思源 FTS5；AFFiNE 桌面 SQLite FTS；Web 自研 BM25 | AppFlowy/Anytype 侧车 Tantivy 线索                                                     |
| **推荐**   | **默认主索引**                                   | **大库/中文相关性/独立索引进程** 时升级；可与 FTS5 **并存**（双写或主 tantivy 仅搜索） |

**硬锁**：无论 FTS5 或 tantivy，**索引损坏不得导致文档不可读**；提供 `reindex_workspace`。

#### 2.3.5 内容寻址附件（S7）

```
blob_id = sha256(bytes)
path    = <workspace>/blobs/ab/cd/abcd…  （或 flat）
refs    = SQLite: (doc_id, block_id, blob_id, mime, size, created_at)
```

| 不变量            | 说明                                                                              |
| ----------------- | --------------------------------------------------------------------------------- |
| 文档只存 **引用** | 块 prop `src: blob:<id>` 或等价；snapshot 不含大文件字节                          |
| 去重              | 相同内容单份存储                                                                  |
| GC                | 引用计数或 mark-sweep；同步删除走 blob 通道                                       |
| 同步              | 独立 `blob` / `blobSync`（AFFiNE）；上传队列可 SQLite（AppFlowy `upload_file_*`） |
| 安全              | 路径规范化、禁止 blob_id 跳出根；可选加密 at-rest 另议题                          |

**否决**「附件 BLOB 默认塞进文档 snapshot 表」作为唯一方式（小图标可例外内联）。

#### 2.3.6 snapshot + pending update/op log（S8）

对齐 D2（编码态 + 可选 op 日志）与 AFFiNE：

```
读路径: snapshot ⊕ pending_updates → （可选）squash → 新 snapshot，标记 merged
写路径: 每次本地 commit → APPEND pending（轻）→ 更新 doc clock
后台:   阈值/空闲/打开时 squash；快照条数封顶（AppFlowy ≤5 可学）
```

| 层                           | 存什么                                                                                  |
| ---------------------------- | --------------------------------------------------------------------------------------- |
| **协同编码态**               | yrs/loro 等 `Update` 二进制 或 shallow snapshot（D2 选定核）                            |
| **结构 op 审计**（可选并行） | 自研 `Op[]` JSON/二进制：origin/agent 批、权限审计、魔鬼回放——**可裁剪**，非 merge 必需 |
| **产品历史**                 | 命名版本、时间线 UI：指向某 snapshot 或 frontiers（Loro）/ 外部历史包                   |

## 3. 文档 / 块 / op / 快照布局建议

### 3.1 工作区磁盘骨架（推荐）

```
<workspace_root>/                          # 用户选定目录或 app data 下的 space
  workspace.sqlite                         # 元数据 + 文档 snapshot/updates + 投影 + FTS + 同步水位
  workspace.sqlite-wal / -shm              # WAL 边车（运行时）
  blobs/                                   # CAS 附件（权威二进制）
    ab/cd/<sha256>
  exports/                                 # 可选：MD 导出镜像（非权威）
  history/                                 # 可选：打包历史/备份 zip（非热路径）
  tmp/                                     # 上传分片、重建索引临时
  .workspace-lock                          # 单写者/多实例策略（见 §4）
```

**分库备选**（大库或运维需要时，非第一天必须）：

| 文件                         | 内容                                                |
| ---------------------------- | --------------------------------------------------- |
| `docs.sqlite`                | snapshots / updates / doc clocks                    |
| `meta.sqlite`                | 工作区树、权限缓存、outbox、blob refs、indexer 游标 |
| `index.sqlite` 或 `tantivy/` | 仅派生索引                                          |

会话/Agent 继续可用现有 `conex-db` 库文件，**与笔记工作区库分离**（I-D4-08），避免 Agent 事件洪峰与笔记 FTS 争用。

### 3.2 SQLite 逻辑表（最小充分集）

> 名称为建议契约；实现时可合并/改名，但 **职责不得混「权威/派生」**。

#### A. 文档权威与时钟

| 表              | 键/列（要点）                                                                                 | 角色                                      |
| --------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------- |
| `docs`          | `doc_id PK`, `title`, `created_at`, `updated_at`, `schema_ver`, `tombstone`                   | 文档元数据                                |
| `doc_snapshots` | `doc_id PK`, `blob BLOB`, `codec` (`yrs_v1`/`loro_snap`/…), `state_vector BLOB`, `updated_at` | 最近压缩态                                |
| `doc_updates`   | `id INTEGER PK`, `doc_id`, `seq`, `blob`, `origin`, `created_at`                              | pending WAL；`(doc_id, seq)` 唯一         |
| `doc_clocks`    | `doc_id PK`, `clock INTEGER`                                                                  | 本地逻辑时钟（AFFiNE 形 timestamp/clock） |
| `peer_clocks`   | `peer_id, doc_id, pushed, pulled, remote`                                                     | 同步水位（**非**文档体）                  |
| `outbox`        | `id`, `channel` (`doc`/`blob`/…), `payload_ref`, `status`, `tries`                            | 上云重试队列                              |

#### B. 结构 op 审计（可选，与 D2 事务壳对齐）

| 表           | 要点                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------- |
| `op_batches` | `batch_id`, `doc_id`, `origin` (`user`/`agent`/`remote`/`system`), `agent_run_id?`, `committed_at` |
| `ops`        | `batch_id`, `ord`, `op_type`, `block_id`, `payload_json`                                           |

> 协同收敛以 **编码态 updates** 为准；`ops` 服务 Agent 回放/审计/撤销策略，可按保留策略 GC，**不得**成为唯一恢复源，除非明确 dual-write 验证。

#### C. 块投影与搜索（**派生**）

| 表               | 要点                                                                                            |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| `blocks`         | `block_id PK`, `doc_id`, `parent_id`, `ord`, `type`, `text`, `props_json`, `hash`, `updated_at` |
| `blocks_fts`     | FTS5，`content=blocks` 或自有列 `text` + `type` + 可检索 props                                  |
| `block_attrs`    | 需要索引的属性展开：`block_id, key, value`（或生成列）——支撑「status=todo」类过滤               |
| `refs`           | `from_id, to_id, ref_kind`                                                                      | 块引用/反向链接                                      |
| `indexer_cursor` | `doc_id`, `indexed_clock` 或 `state_vector`                                                     | 增量索引水位（AppFlowy `prev_sync_state_vector` 形） |

**重建**：扫 `docs` → 解码 snapshot⊕updates → 投影 `blocks`/`refs` → 重建 FTS。`hash` 跳过未变块（思源 upsert 纪律）。

#### D. 附件

| 表/路径         | 要点                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------- |
| `blobs`         | `blob_id PK`, `size`, `mime`, `created_at`, `refcount` 或仅清单                             |
| `blob_refs`     | `doc_id, block_id, blob_id`                                                                 |
| 文件 `blobs/**` | 原始字节；写文件成功再提交 SQL 引用（或反之：先 SQL pending 再 finalize——需崩溃恢复状态机） |

#### E. 工作区与树

| 表                        | 要点                                                          |
| ------------------------- | ------------------------------------------------------------- |
| `folders` / `space_nodes` | 笔记本/文件夹树（可与 doc 同 CRDT folder 对象，落盘仍有投影） |
| `workspace_meta`          | `key, value`：schema 版本、索引世代、特性开关                 |

### 3.3 内存 vs 磁盘职责

```
┌─────────────────────────────────────────────────────────┐
│  DocSession（D2，RS 内存）                               │
│  热文档：结构树投影 + 文本 CRDT 句柄 + undo               │
└─────────────────────┬───────────────────────────────────┘
                      │ PersistencePlugin::flush
                      ▼
┌─────────────────────────────────────────────────────────┐
│  workspace.sqlite                                        │
│  APPEND doc_updates → 更新 doc_clocks                    │
│  （阈值）squash → doc_snapshots + mark merged            │

                      │ 异步 Indexer sidecar（不阻塞 apply）
                      ▼
┌─────────────────────────────────────────────────────────┐
│  blocks / blocks_fts / refs / indexer_cursor             │
└─────────────────────────────────────────────────────────┘

                      ▼
┌─────────────────────────────────────────────────────────┐

```

## 4. 一致性（事务）

### 4.1 本地写事务边界

| 场景                      | 事务要求                                                                                                                                                         |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **单次用户/Agent commit** | 同一 SQLite 事务：`INSERT doc_updates` + `UPSERT doc_clocks` +（可选）`op_batches`；失败全滚                                                                     |
| **squash**                | 读 snapshot+updates → 合并 → `UPSERT doc_snapshots` + `DELETE/mark merged updates` + clock；**单事务**，避免半 squash                                            |
| **索引 upsert**           | **独立事务/连接**；失败可重试；不得回滚已成功的文档 commit                                                                                                       |
| **附件 finalize**         | 状态机：`pending → file_written → ref_committed`；崩溃可 GC 孤儿文件或重试                                                                                       |
| **跨文档 Agent 批**       | 产品层 batch：要么多 doc 顺序事务 + 补偿，要么显式「工作区级锁」；默认 **单 doc 原子**，跨 doc 声明 best-effort 或 2PC 轻量（第一期单 doc 原子即可满足 E-D2-04） |

### 4.2 读一致性

- **打开文档**：`BEGIN` 读 snapshot + 所有 pending updates（或预先 squash 到临时缓冲）；与思源 `FlushTxQueue` 类似，**读权威前确保内存 apply 队列已刷盘**（若写路径异步 flush，打开前 `flush_doc`）。
- **搜索**：允许 **近实时**（索引落后 clock 最多 N 秒或 M 条）；UI 可标「索引中」。不得因索引滞后返回「文档不存在」。

### 4.3 WAL 与多连接

- **PRAGMA journal_mode=WAL**；`busy_timeout`；写连接少而专（本仓 stress 已验证 WAL 并发 append 纪律，可沿用）。
- 多窗口：**单进程多连接**优先；多进程同库需 file lock + 明确「第二实例只读」或 socket 复用主进程（产品策略，存储层预留 `workspace-lock`）。

### 4.4 崩溃模型

| 故障点                   | 期望                                                                                                                        |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 事务中崩溃               | SQLite 回滚；内存 DocSession 丢未 flush 部分——若 D2 要求「击键已确认」，flush 须在 ACK UI 前完成或可恢复 write-ahead 于磁盘 |
| squash 中崩溃            | 未提交则旧 snapshot+全量 pending 仍在；可再 squash                                                                          |
| 索引写崩溃               | 文档完好；cursor 未推进 → 重试                                                                                              |
| blob 文件写完 SQL 未提交 | 孤儿 blob → 启动 GC                                                                                                         |
| SQL 提交文件未写完       | 禁止：必须先完整写临时文件 `rename` 再提交 ref                                                                              |

## 5. 大库性能不变量

| ID  | 不变量                  | 手段                                                                              |
| --- | ----------------------- | --------------------------------------------------------------------------------- |
| P1  | **打开文档 ≠ 加载全库** | 按 `doc_id` 读 snapshot/updates；文件夹树分页/惰性                                |
| P2  | **击键写放大受控**      | 只 APPEND update；禁止每键全量重写 snapshot                                       |
| P3  | **squash 可调度**       | 阈值（pending 字节/条数）、idle、关闭文档、备份前                                 |
| P4  | **索引增量**            | `indexer_cursor` + 块 `hash`；同 doc 队列可合并（思源 `UpsertTreeQueue`）         |
| P5  | **FTS 不阻塞 apply**    | 专用连接/线程；背压时丢延迟不丢文档                                               |
| P6  | **附件零拷贝路径**      | 大文件流式哈希入库；预览用 OS 缓存/mmap                                           |
| P7  | **快照配额**            | 历史 snapshot 环形（学 AppFlowy 每 object 上限）；产品「命名版本」另存 `history/` |
| P8  | **投影窗口**            | 与 D5 一致：磁盘可有全量 blocks 投影，**内存**只 hydrate 视口                     |
| P9  | **真空策略**            | 定期 `PRAGMA optimize` / 可控 `VACUUM`；WAL checkpoint 不阻塞 UI 线程             |
| P10 | **搜索延迟预算**        | 热查询走 FTS 索引；禁止默认 `LIKE %x%` 全表扫作为主路径                           |

**数量级目标（验收方向，非工期）**：

- 10⁴ 文档元数据列表：可滚动，首屏索引查询。
- 单文档 10⁵ 块：打开与搜索该文档块可完成；全库 FTS 有进度。
- pending updates 在阈值内 squash，单 doc 行数不无限增长。

## 6. 搜索需求：全文 + 块属性

### 6.1 查询面（产品）

| 能力              | 实现落点                                                   |
| ----------------- | ---------------------------------------------------------- |
| 全文              | `blocks_fts` MATCH；返回 `block_id, doc_id, snippet, rank` |
| 类型/标签/状态等  | `blocks.type` / `block_attrs` / JSON 生成列 + 索引         |
| 反向链接          | `refs` 表                                                  |
| 标题/文档级       | `docs.title` + 根块投影                                    |
| 路径/笔记本       | space 树 JOIN                                              |
| 组合              | SQL：`MATCH` + attr 谓词 + doc 过滤                        |
| （未来）符号/代码 | 可另接 tantivy 字段或 tree-sitter 侧车（archive 方案思想） |

### 6.2 索引管道

```
Doc commit (clock++)
  → 通知 Indexer(doc_id, clock)
  → 解码权威 → 遍历块
  → 若 hash 变：UPSERT blocks / attrs / refs
  → FTS 同步（external content 或手动）
  → indexer_cursor = clock
```

### 6.3 FTS5 为主、tantivy 为升级

| 阶段             | 选择                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------- |
| **默认**         | SQLite FTS5 + `blocks` 关系过滤（运维一体、重建简单、与思源/AFFiNE 桌面同构）          |
| **触发 tantivy** | 中文相关性明显不足；全库规模使 FTS5 维护/锁不可接受；需要独立索引进程/多工作区并行检索 |
| **双写期**       | 允许 FTS5 与 tantivy 并行验证；**查询路由单一真相**（开关），避免结果漂移无测          |

### 6.4 不可放入搜索索引的

- 附件二进制正文（可选：仅文件名/OCR 另管道）。
- Awareness、光标。
- 权限密文/密钥材料。

## 8. 与协同引擎（D2）落盘关系

### 8.1 插件化（学 AppFlowy，不嵌 AGPL）

```
DocSession::apply(ops)
  → 内存权威更新
  → emit 投影 patch（UI）
  → PersistencePlugin::on_commit(encoded_update | full_state_hint)
        → 本地 SQLite APPEND（同步或短队列，ACK 策略见下）
  → SyncPlugin::enqueue（可选，有网）
  → Indexer::notify（异步）
```

| 策略                            | 语义                                               |
| ------------------------------- | -------------------------------------------------- |
| **本地先写**                    | 无网也 commit；Sync 失败不回滚本地                 |
| **磁盘插件常驻 / 同步插件按需** | 对齐 AppFlowy Collab 建造器                        |
| **打开 miss**                   | 本地无 doc → 拉云 doc_state → 落入 snapshot → 再开 |

### 8.2 编码态 vs 结构 op

| 数据                    | 生产者                  | 消费者                                   |
| ----------------------- | ----------------------- | ---------------------------------------- |
| `Update`/snapshot bytes | D2 Text/Structure codec | 持久化、同步、reload                     |
| 结构化 `Op[]`           | D2 事务壳               | Agent 审计、可选 undo、测试回放          |
| `blocks` 投影           | Indexer 从权威解码      | 搜索、反向链接、大纲 API                 |
| awareness               | 内存/短 TTL             | **默认不落文档库**（可 transient store） |

### 8.3 与 AFFiNE nbstore 七类 storage 对齐（机制）

| AFFiNE 类型           | 本方案落点                                          |
| --------------------- | --------------------------------------------------- |
| doc                   | `doc_snapshots` + `doc_updates`                     |
| docSync               | `peer_clocks` + `outbox`                            |
| blob / blobSync       | `blobs/` + `blob_refs` + 上传队列                   |
| awareness             | 内存 / 可选短表；不进历史                           |
| indexer / indexerSync | `blocks*` + `indexer_cursor`（及未来 tantivy 目录） |

**差异（硬锁）**：AFFiNE 桌面仍可能 JS 编排 merge；我们 **merge/apply 只在 RS**，SQLite 只存字节与元数据，不把 Yjs 真相放 WebView。

### 8.4 与思源事务对照

| 思源                       | 本方案                                           |
| -------------------------- | ------------------------------------------------ |
| 串行 `flushLock` 写 `.sy`  | CRDT/混合合并后 **编码字节** 落盘；单 doc 写事务 |
| 索引异步 `UpsertTreeQueue` | **同构** Indexer 侧车                            |
| 索引可重建                 | **同构**                                         |
| 无击键级多副本 merge       | D2 补齐；存储层用 snapshot+updates 支持          |

### 8.5 与 AppFlowy collab 存储对照

| AppFlowy                              | 本方案                                |
| ------------------------------------- | ------------------------------------- |
| RocksDB：`doc_state` + `state_vector` | SQLite BLOB 或未来 redb；**语义相同** |
| SQLite：用户/快照条数/上传/索引游标   | **同构并加强**（FTS 也可在此）        |
| 快照 ≤5                               | 采纳环形配额                          |
| Instant index + state_vector 差量     | `indexer_cursor`                      |

## 10. 否决路径及原因（结构洞，非工期）

| 路径                              | 结构洞                                                                           |
| --------------------------------- | -------------------------------------------------------------------------------- |
| **纯 redb/sled 唯一存储**         | 全文+属性+迁移+同步队列均自研半套 DB；丢本仓 rusqlite/WAL 验证资产；调试面差     |
| **纯文件系统 MD 权威**            | 无细粒度 update、块 ID 绑路径、Agent 批与协同冲突模型退化；与 D2/MD 契约纪律冲突 |
| **索引当权威**                    | FTS/blocks 损坏或重建窗口导致「内容消失」错觉；与思源铁律相反                    |
| **附件进文档 snapshot**           | 写放大、同步带宽、GC 困难、大库内存                                              |
| **每击键全量重写 snapshot**       | 大文档磁盘与主线程（若误放 UI）灾难；AFFiNE 已证明 pending 必要                  |
| **JS/IDB 作桌面唯一持久**         | 与「心在 RS」、Agent 同进程、备份/迁移工具链冲突；仅可作 Web 目标备选实现        |
| **整嵌思源/AFFiNE/AppFlowy 存储** | AGPL/绑定/双心；机制已吸收完毕                                                   |
| **向量 RAG 作默认搜索**           | 内存与构建成本高；精确块 ID/属性场景不匹配（可后置可选，不作 D4 主路径）         |

## 11. 推荐主路径 + 备选 + 迁移触发

### 11.1 主路径（锁定推荐）

1. **引擎**：`rusqlite` + **WAL** + 自研迁移（延续 `conex-db` 纪律，**新工作区 schema**）。
2. **文档权威**：`doc_snapshots` + `doc_updates` + `doc_clocks`（S8）；codec 字节来自 D2。
3. **附件**：工作区 `blobs/` **CAS** + `blob_refs`（S7）。
4. **索引**：投影表 `blocks` / `block_attrs` / `refs` + **FTS5**（S5）；全量/增量可重建。
5. **同步预备**：`peer_clocks` + `outbox`；通道分离 doc/blob/indexer。
6. **MD**：export 管线与可选 mirror；**非权威**。
7. **与 D2**：PersistencePlugin 本地先写；Indexer 异步；awareness 不进权威库。

### 11.2 备选组合

| 备选                             | 何时                                                                                 |
| -------------------------------- | ------------------------------------------------------------------------------------ |
| **SQLite meta + redb collab KV** | 证明 snapshot/updates 与 FTS **同库锁/页缓存** 成为硬瓶颈；语义仍双库（AppFlowy 形） |
| **tantivy 主搜索**               | FTS5 中文/规模不够；保留 SQL 属性过滤或把属性进 tantivy 字段                         |
| **历史包文件系统**               | 用户要 dejavu/Git 形长历史：`history/` 打包，热库仍 SQLite                           |
| **Web 目标 IDB**                 | 若未来纯 Web：实现同一 Storage trait；**桌面主路径仍 SQLite**                        |

### 11.3 迁移触发（仅当不变量被破坏）

| 触发                                          | 行动                                                |
| --------------------------------------------- | --------------------------------------------------- |
| SQLite 在目标硬件无法满足 P2/P5（有基准证据） | 拆 redb 存编码态 或 拆 index 库                     |
| FTS5 相关性/语言验收失败                      | 上 tantivy，查询路由切换，重建索引                  |
| 多活写同文件需求超过 WAL 多连接模型           | 单写者服务进程 + RPC（非换流行 KV）                 |
| 监管/用户强制「目录即 MD」                    | **增加** mirror 与冲突 UI，**不**删除 snapshot 权威 |

### 11.4 魔鬼验收断言（供 Round E / 测试钉）

1. 写入 N 次 update 后杀进程 → 重开文档字节与编码态等价。
2. 删除 `blocks`/`blocks_fts` → 文档仍可开；`reindex` 后关键词可搜回。
3. 同一 blob 上传两次 → 磁盘单份；两 ref；删一文后 refcount 正确 GC。
4. 断网编辑 → outbox 堆积 → 上线 drain → peer clock 单调。
5. 十万级 pending 触发 squash → 行数下降、reload 一致。
6. Agent 批 1000 op 单事务：失败零写入；成功可审计 `op_batches`。
7. 搜索 `type:task + 全文` 走索引计划，而非全表 `LIKE`。
8. 工作区库与 `conex-db` 会话库分离；迁移备份含 checkpoint 后一致字节（沿用现有备份纪律）。

## 14. 收束

**D4 推荐主路径**：在 **Rust 心** 内，用 **已验证的 rusqlite/WAL** 承载工作区 **snapshot + pending updates + 关系元数据 + FTS5 派生索引 + 同步水位**；**附件 CAS 分目录**；**索引永远可重建**；**MD 只做契约视图**。

redb 仅作为「编码态拆库」备选；tantivy 作为「搜索上限」升级；文件系统 MD 不作权威。与思源（索引派生）、AFFiNE（update 日志与分通道）、AppFlowy（本地先写、双库职责、快照配额）机制对齐，**实现与许可边界自研收敛**。
