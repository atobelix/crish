## 2. 评审强制清单（每份必须逐条给 通过/漏洞/待证）

### 2.1 效果锁

- [ ] 块操作完成度目标是否被「先用简化编辑器」静默缩水
- [ ] 静默写作是否仍一等
- [ ] 多人协同是否仍要求 RS 合并
- [ ] Agent 块级 mutate 是否一等
- [ ] MD 往返是否契约级

### 2.2 上限与路径依赖

- [ ] 忽略本仓后最优是否仍成立
- [ ] 是否因「本仓有 markdown-editor / pulldown / sqlite」误锁次优
- [ ] 调包是否引入 AGPL/商业毒条款

### 2.3 结构不变量

- [ ] 单一 apply 管道
- [ ] 呈现层无权威
- [ ] 行级 ∥ 块树不混模型
- [ ] 扩展不能直写磁盘绕过心

### 2.4 可验证性

- [ ] 每个推荐栈是否附带魔鬼用例 / 性能契约 / 往返测试钉
- [ ] 中途换实现触发条件是否可客观判定（禁止主观「感觉慢」）

### 2.5 反退避

- [ ] 文档中是否出现禁词：工期、人天、P0 砍功能、业界都用所以…
- [ ] 不确定处是否标「待验证」而非「不可能」

## 3. 评审输出格式

```markdown
# 结论（5 行内）

# 漏洞表（编号 / 严重度:结构|上限|契约|可验证 / 证据 / 建议修订）

# 通过项

# 必须补充的验收断言

# 对 D7 / 12 的具体改句建议（可直接粘贴）
```

严重度：

- **结构**：会强制中途换栈或双真相
- **上限**：单维或总上限被锁死
- **契约**：MD/Agent/扩展可破坏不变量
- **可验证**：无法钉死，后续会嘴遁
