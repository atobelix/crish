## 1. 主控必须记住的教训（本会话）

| #   | 教训                                                                                   | 反面做法（禁止）                                                 |
| --- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| L1  | **计划文档 ≠ 已注入子 Agent**。唯一可靠通道是 **prompt 强制列表 + 要求先 read_file**   | 只写「交付清单摘要」当任务书                                     |
| L2  | **没有第二通道** 自动加载 `docs/block-workspace-architecture/**`                       | 假设「文档在仓库里 Agent 会自己看」                              |
| L3  | **Round 测绿 ≠ 效果锁关闭**；包 ID 不得偷换 09 定义（W6-A≠抽样冒充全表）               | 「门禁 224 绿」「W6-C 交付」掩盖 TBD                             |
| L4  | **伪完成比没写更毒**：A-\* 测名/常量在、语义无（undo、结构 encode 占位）               | 挂 ID 锚点交差                                                   |
| L5  | **大规模偏离禁止止痛**：不得「再开一轮修修」代替重走方案流程                           | 在空心 hydrate 上继续堆 UI/Round                                 |
| L6  | **低质量代码可不 git**；未按文档的半成品 **可丢**                                      | 为保进度把垃圾提交进历史                                         |
| L7  | 审计阶段可看全库文档；**正式实现**只给：总方案/分维计划/约束锁/注意事项 + **本包计划** | 实现 Agent 自由翻竞品/审计全卷导致目标漂移（或相反：什么都不给） |

## 2. 流程阶段（重启后强制顺序）

```
[已完成] 质量审计  audit/2026-08-11-round-quality/**
     │
     ▼
[进行中] 多维对齐分析  analysis/R2-*/**
     │  相对 15/00/0N/18/08 + 审计：保留 / 废弃 / 必须回写方案的缺口
     ▼
[下一步] 方案再生     plans 修订草案 + 总方案补丁
     │
     ▼
[下一步] 方案双评审   效果架构 + 可执行性（同 E1/E2 精神）
     │
     ▼
[下一步] 方案改进落盘 回写 00–09 / 08 / 09 / 18 补丁
     │
     ▼
[显式口令后] 实现波   按 09 包派发；每包强制文档集（§4）
```

**禁止**：跳过分析/评审直接「P0 焊代码」——用户已否决止痛路径。
**例外**：用户再次显式口令「跳过方案直接实现某包」才可破例，且仍须强制文档集。

## 3. 文档分层（Agent 可见范围）

### 3.1 审计 / 分析 / 方案 Agent（宽读）

可读：

- `15` / `18` / `00`–`09` / `interfaces` / `specs` / `acceptance`
- `audit/**` 全部
- `round-D-stack` / `round-E-review` 相关
- 代码只读勘察

### 3.2 正式实现 Agent（窄读 — 用户定夺）

**只允许** prompt 列出的：

| 类        | 路径模式                                                                              |
| --------- | ------------------------------------------------------------------------------------- |
| 总维度    | `plans/00-总方案.md`                                                                  |
| 本维计划  | `plans/0N-*.md`（仅本包）                                                             |
| 约束锁    | `15`、`18`（及相关补丁条）                                                            |
| 注意事项  | `20` 本章 §1+§4；`08` 中与本包验收 ID 相关段；`LOGIC_PLAN_NO_RETREAT` 要点可摘录      |
| 接口/规格 | **仅**本包依赖的 `interfaces/*`、`specs/*`                                            |
| 验收      | 本包 **A-\* ID 列表全文**（可摘自 D7/08，必须贴进 prompt 或指定单一 acceptance 文件） |

**禁止实现 Agent**：

- 以「继续 Round」代替读 0N
- 自由发挥缩小验收
- 提交前无「对照验收 ID 自检表」

### 3.3 每包 prompt 强制块（实现波）

```
## 强制阅读（先 read_file 再改代码）
1. plans/00-总方案.md
2. plans/0N-（本维）.md
3. 15-评审后锁定修订.md
4. 18-实现波前待决锁定-H1H2H3M1.md（若触及）
5. 本包 specs/interfaces（列路径）
6. 20-流程重启 §1 教训 + 本包验收 ID

## 本包
- 包 ID / 文件域 / 验收 ID 列表 / 禁止项
- 对照审计缺口 ID（若本包负责关闭）

## 完成定义
- 列出每条 A-* 的测名或「无测=未完成」
- 禁止宣称 EL / Wave 关闭除非 08 条件满足
```

## 4. 代码资产态度（用户裁决）

| 类                                          | 态度                                                                         |
| ------------------------------------------- | ---------------------------------------------------------------------------- |
| 已 commit 的 R1–R8 代码                     | **现状库存**：分析阶段判定保留/改造/废弃；**不**因「已提交」自动等于方案正确 |
| 未按文档的半成品 / 伪 A-\* / 未 commit 缝补 | **可丢、不入库**                                                             |
| 审计文档                                    | **保留**，作为方案再生输入                                                   |

本重启已 **丢弃** 工作区未提交的 R9 缝补向改动（doc-collab/block-paper/editor-kit 等），避免垃圾污染下一阶段。

## 5. 多维分析产出约定

目录：`docs/block-workspace-architecture/analysis/2026-08-11-realign/`

| 文件                               | 内容                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------- |
| `00-索引.md`                       | 总表：维 → 结论 → 方案动作                                             |
| `D1-心与合并.md` … `D7-双引擎.md`  | 每维：文档要求 / 库存代码 / 差距 / **方案必须改什么** / **实现包建议** |
| 不做「再写一堆实现 TODO 冒充方案」 | 方案动作要能回写进 `plans/0N`                                          |

颗粒度对齐：**问题同权**（LOGIC_PLAN）；排序键仅：效果完整度 → 正确性 → 可验证性 → 契约一致 → 结构干净。
