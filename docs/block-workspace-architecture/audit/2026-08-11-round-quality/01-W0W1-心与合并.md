# 总判

**整体定性：有实质推进的「可测骨架 + 半语义实现」，不是空仓；但距离「按文档做满」仍有多处 🚨 伪完成与 🟨 上限塌陷点。若把 R1–R8 / W0–W1 叙述读成「心与合并已按 15/18 交付」，属于虚标。**

做得真、值得保留的：

- 单一本地写入口 `DocSession::apply` 的**预校验后突变**路径，对用户 Op 批有 A-INV-09a 级「失败零改」测。
- yrs 封装为 **crate 私有** `mod text_engine`，公共 API 不 re-export yrs 类型（A-INV-05 方向正确）。
- H1 热集/冷藏（pin + LRU + snapshot）与 A-MEM-01/02/03 引擎测**有真语义**。
- M2 主路径 `maybe_split_huge_in_tx` / `partition_utf8` / A-HUGE-01/02 单测**真分段**。
- W1-F 双 peer harness 文本侧走真实 yrs state update；结构侧诚实标注「op 日志重放」。
- PersistencePlugin trait 形状与 W0-D 大体对齐，并补了 `tx_id`（A-INV-09b）。
- Loro 仅 `dev-dependencies`，生产路径不依赖（W0-L 边界正确）。

未做满 / 缝补冒充完成的主轴：

1. **写锥不闭**：`pub tree` / `pub rev` 可旁路；`apply_remote_text_update` 是第二权威写路径且**不**走 `on_committed`；`on_committed` 失败时树/文本**已改不回滚**。
2. **TxGuard 是礼仪对象**：无跨引擎共享状态机；原子性靠 `validate_batch` 前置，自动 split 尾段与 persist 失败路径未纳入真回滚。
3. **A-COL-04 / A-MEM-04 / 01 §Undo**：`Origin` 有枚举、注释写「便于后续 undo」，**无 undo 栈 / 无按 origin 过滤**——ID 锚点 + 注释冒充契约。
4. **M1 并发 move**：单端环拒 + 同批删胜有；**无 Lamport/peer 全序破环**（MV-02 并发语义）；结构互推仍是 JSON op 重放，不是树 CRDT 合并。
5. **Loro oracle 未对照自研**：只测 Loro 自己会不会环，**没有**「同 Op 序列 → DocSession vs Loro 终态一致」属性测。
6. **hydrate / 结构 encode 空心**：`HydrateBlob` 可 load，但 DocSession **无** `hydrate` 重建树；结构 `EncodedUpdate` 是 `rev.to_le_bytes()` 占位（note-runtime 亦注释「不重建树」）——A-COL-05 / A-INV-04 心侧半截。
7. **A-HUGE 数据层最低关闭集未齐**：01/02 绿；**04/05/07 无专测 ID 挂钩**；只读折叠备路径缺失；grapheme 仅 char 边界。

**上限风险一句话**：在「结构 op 日志重放 + 无 undo + 第二写路径 + 占位结构 encode」之上继续堆 UI/Agent，会把 EL-04（多人收敛）、EL-03（大文档内存/恢复）、A-INV 写锥锁全部做成**演示级真相**，后期换真 CRDT/真事务时必炸联测。

# 严重缺口（按上限风险排序）

## 1. 写锥未真正封闭（A-INV-01 / EL-04/05 上限）

- **`DocSession.tree` / `rev` 公开可变**：任意依赖方可在不经 `apply` 时改权威树与版本。
- **`apply_remote_text_update`**：权威文本 + `rev++`，**跳过** `TxGuard` / `validate_batch` 批语义 / **`on_committed`**。双 peer 演示能绿，落盘/outbox 路径静默丢远程合入。
- **上限塌法**：Agent/UI 工具若误用 public 字段或只调 remote update，出现「内存真相 ≠ SQLite 权威」——正是 15 关闭的 V3/S1 漏洞重开。

## 2. 事务原子性是「预检假说」不是 TxGuard 真共享（A-INV-09a/b）

- `TxGuard`（`tx.rs`）不持有树/文本快照，commit/rollback 只拨布尔。
- 用户 Op：**validate → mutate** 对预检失败有效。
- **mutate 后** `on_committed` 失败 → 返回 `Persist` 错，**内存已提交**。
- **自动 huge split** 在用户 Op 成功后执行，注释写明失败不可回滚。
- **上限塌法**：磁盘满/插件拒写时「成功半持久」；崩溃恢复与编码态一致性无法证伪。

## 3. 结构合并仍是 op 日志重放（A-COL-01/06 / M1 / EL-04）

- `SimplifiedEncodedOps` = `serde_json` of `Vec<Op>`（`harness.rs:17–38`）。
- 结构 `EncodedUpdate.bytes = rev.to_le_bytes()`（`session.rs:438–441`）。
- **无** parent+fractional 的并发 merge、**无** Lamport 破环（MV-02 规格）。
- **上限塌法**：两人同时拖块/嵌套时，不是「收敛到规格终态」，而是「后到的 op 拒掉或覆盖式重放」——协同上限卡死在脚手架，却已挂 A-COL-01 用例名。

## 4. Undo 全家桶空壳（A-COL-04 / A-MEM-04 / A-INV-09c 后半 / plans/01）

- 全 crate **零** undo 栈；Origin 只进 CommitBatch 标签。
- A-MEM-04 测试名与 `a_mem` 常量存在，内容是「冷→热再编辑」。
- **上限塌法**：产品若宣称「冷块受限 undo」或「Agent 批可整批撤销」，当前代码无法支撑；属于典型 **ID 锚点伪完成**。

## 5. Hydrate / 打开文档心路径空（W1 与 00「真实 hydrate 前不得宣称打开完成」）

- `PersistencePlugin::load_doc` 有；`DocSession` **无** 消费 `HydrateBlob` 重建 `BlockTree`+TextEngine。
- `init_block_with_text` 标 `dead_code` /「W1 后续」。
- note-runtime 已写明结构 encode 占位、**不重建树**（交叉证据，非本 crate 文件域但暴露心缺口）。
- **上限塌法**：EL-03/04 恢复链路断；A-INV-04「已提交可恢复」心侧未闭。

## 6. Loro「对照」未接线（W0-L / A-SWAP 逃生门）

- oracle 测 Loro 自身 CyclicMoveError。
- **从不**对同一场景跑 `DocSession` 并 diff。
- **上限塌法**：自研规则改坏时无 oracle 红灯；真要 A-SWAP 时缺少对照基线。
