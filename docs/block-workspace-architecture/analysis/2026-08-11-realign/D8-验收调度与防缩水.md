## 2. `09` 必须如何改写：两轨利弊与推荐

### 2.1 选项 A — 仅恢复严格定义（单轨）

**做法**：

- 全文冻结：`W6-A` **永远** = A-BLK-01…14 全表 e2e（+ 明确 e2e 目录/WebView 环境）；不得在任何进度文件标题使用 W6-A 除非关闭条件逼近审查。
- 历史缩水交付 **改称** `W3-x-hotfix` / `pre-W6` / 无包号「契约抽样」。
- `W3-D` 在未接 PM 前 **禁止**写「完成」；任务名改为真实交付或拆出 `W3-D0`。

| 利                                          | 弊                                                                          |
| ------------------------------------------- | --------------------------------------------------------------------------- |
| 词义单一，主控/Agent 零歧义                 | 大量已落盘测名/进度标题与包号冲突，清理成本高                               |
| 与当前 `09` 字面、08 EL 映射 **零语义债务** | 骨架工作「没有合法包 ID」→ 易再被塞进邻近正式包（复发 S1）                  |
| 审计对照简单                                | 并行骨架（假数据 chrome、结构门常量、IME L1）在索引上 **不可见** → 调度失明 |

### 2.2 选项 B — 显式「骨架包」ID 两轨（关闭轨 + 骨架轨）

**做法**：每个易被缩水的正式包，**成对**出现：

| 轨                     | ID 形态               | 含义                                                         | 可否宣称 EL/Wave 关闭                         |
| ---------------------- | --------------------- | ------------------------------------------------------------ | --------------------------------------------- |
| **关闭轨（Strict）**   | 保持现有 `Wn-X`       | 与今日 `09` 验收列 **同义**；唯一可关 EL 映射的包            | 仅本轨完成 + 08 条件                          |
| **骨架轨（Skeleton）** | `Wn-X-S` 或 `Wn-X.sk` | 允许：类型/接口/假数据/L1 单测/mock sink/结构门常量/文档矩阵 | **明确禁止**关 EL；完成只表示「可并行脚手架」 |
