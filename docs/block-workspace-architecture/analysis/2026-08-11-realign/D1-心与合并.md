## 总判（结论先行）

**库存定性（与审计一致，抽样复核）：**  
`conex-doc-collab` 是 **方向正确、可测骨架 + 半语义** 的库存，**不是空仓**，也 **不是** 按 `15`/`18`/`01` 做满的「文档心与合并已交付」。

| 层                | 判定                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------- |
| 栈向 / 写入口意图 | 与锁同向：RS `DocSession::apply`、yrs crate 私有、热冷 H1、HUGE 主路径分段、PersistencePlugin 形状       |
| 相对文档「做满」  | **未满**：写锥未闭、结构合并非 CRDT、Tx 非真回滚、undo 空、hydrate 空、结构 encode 占位、Loro 未对照自研 |
| 效果锁            | **EL-03/04/05 一律未关闭**（`08`：缺测=未交付；Round 绿 ≠ EL 关闭）                                      |

**方案再生必须回答的不是「还差哪些函数」，而是：**

1. **终局合并语义**在方案层是否仍钉「自研树 Op + 日志/编码可恢复 + 双 peer 规则表」，还是默许「JSON op 重放 + 单端拒环」冒充 A-COL；
2. **写锥与跨引擎事务**是否要把 `18` H2 / A-INV-09 写成可证伪契约（含 persist 失败、huge split、远端文本路径）；
3. **打开/恢复（hydrate）**是否升为心维 **硬前置**（`00` 已写「真实 hydrate 前不得宣称打开文档完成」——任务书 `01` 正文几乎未钉）；
4. **伪 A-\***（A-MEM-04 / A-COL-04 等）在方案与验收会计上如何 **去锚点冒充**。

**不建议推倒重写 crate**；建议 **方案层先钉满语义与退出条件**，再允许实现波按条文重焊。半成品/伪 ID **可丢**（`20` §4），但热冷文本、预检批、yrs 私有、HUGE 分段主路径应标 **保留改造**。
