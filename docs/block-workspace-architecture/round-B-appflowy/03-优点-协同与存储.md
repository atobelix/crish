# AppFlowy：协同 / 存储优点与实现线索

> **范围**：`reference/markdown_compare/AppFlowy`（客户端 `frontend/rust-lib/`；协同 CRDT 库在外仓 **AppFlowy-Collab**，本树以 git rev 钉入 workspace）。
> **立场**：只谈**协同与存储**侧可借鉴的优点与证据；不做工期/人天；不把「流行」当裁判。
> **对照**：本产品栈 **Tauri + TypeScript + Rust**；目标 Notion 的块皮 + **Rust 的心**（本地优先、实时协同、低内存）。
> **路径前缀**：下文相对 `frontend/rust-lib/`，除非写绝对/仓库根路径。

---

## 0. 结论先行

| 维度                 | 一句话                                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **本地优先是否成立** | **成立（客户端侧）**：权威状态在本机 RocksDB（CollabKVDB）；编辑不依赖云；Local 模式整条 `AppFlowyServer` 可空实现且文件云存储直接 `None`。            |
| **协同模型**         | **yrs CRDT**（`yrs = 0.21`）+ 插件管线：磁盘插件常驻，云同步插件按 Auth 惰性挂载；WebSocket 通道按 object 订阅。                                       |
| **双存储分工**       | **RocksDB** = collab doc_state / state_vector；**SQLite** = 用户/元数据/快照/上传队列/索引游标；职责清晰，适合沉 Rust。                                |
| **云/本地同构**      | `AppFlowyServer` trait 一套服务面；`LocalServer` vs `AppFlowyCloudServer` 实现切换；`ServerProvider` 按 `AuthType` 懒建。                              |
| **对自研最值得搬的** | ① Collab 建造器 + 插件 finalize；② 本地先写再异步上云；③ 打开文档「本地 miss → 拉 doc_state」；④ 上传断点队列；⑤ 快照条数封顶；⑥ Server trait 双后端。 |
| **本树边界**         | **AppFlowy-Cloud 服务端源码不在本镜像**；实时合并协议细节在 `client_api` + 外仓 `SyncPlugin`；self-host 以公开文档/Docker 栈描述为主。                 |

### 1.1 打开 / 编辑 / 同步（文档路径）

1. **打开** `DocumentManager::open_document` → `create_document_instance(enable_sync=true)`
   - 先 `CollabPersistenceImpl::into_data_source()` 读本地；
   - 若本地无此 doc：`cloud_service.get_document_doc_state` 拉 `DocStateV1`（跨设备首开）。
   - 证据：`flowy-document/src/manager.rs:237-338`。
2. **建造** `AppFlowyCollabBuilder::create_document` → `build_collab`：
   - `spawn_blocking` 建 `Collab`；
   - **总是**挂 `RocksdbDiskPlugin`（本地持久化）；
   - `enable_undo_redo`。
   - 证据：`collab-integrate/src/collab_builder.rs:158-302`。
3. **finalize**（`sync_enable` 时）：
   - 若尚无 cloud plugin 且 provider 为 `AppFlowyCloud`：通过 `CollabCloudPluginProvider::get_plugins` 挂 **`SyncPlugin`**（WS sink/stream + 60s 超时等）；
   - Local provider：**不挂**同步插件；
   - 然后 `initialize()`。
   - 证据：`collab_builder.rs:304-358`；`flowy-core/src/deps_resolve/cloud_service_impl.rs:603-687`。
4. **编辑通知** `subscribe_document_changed`：block 变更 + awareness + sync_state / snapshot_state 推 Flutter。
   - 证据：`flowy-document/src/document.rs:11-78`。
5. **创建文档** 先 `save_collab_to_disk`，再 **tokio 后台** `create_document_collab` 上云（失败不阻塞本地返回）。
   - 证据：`manager.rs:163-191`。

### 1.2 Auth / 服务器双轨

| Auth                | 环境变量                        | Server 实现           | 同步插件            | 文件云                          |
| ------------------- | ------------------------------- | --------------------- | ------------------- | ------------------------------- |
| `Local = 0`         | `APPFLOWY_CLOUD_ENV_CLOUD_TYPE` | `LocalServer`         | 无                  | `file_storage() = None`         |
| `AppFlowyCloud = 2` | 另需 base/ws/gotrue URL         | `AppFlowyCloudServer` | `SyncPlugin` via WS | `AFCloudFileStorageServiceImpl` |

- 证据：`flowy-server-pub/src/lib.rs:36-62`；`server_layer.rs:41-47,139-167`；`local_server/server.rs:106-108`；`af_cloud/server.rs:245-267`。
- Self-host 客户端只换 **同一套 Cloud 配置**（`AFCloudConfiguration`：base_url / ws_base_url / gotrue_url），无单独「self-host 协议」分支——证据：`flowy-server-pub/.../af_cloud_config.rs`；产品 README 链到公开 Self-hosting 指南（`README.md:51`）。

### 1.3 双存储角色（重要不变量）

| 存储                           | 内容                                                                                                                                                                         | 入口                                                                                    |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **CollabKVDB (RocksDB)**       | 每个 collab object 的 `state_vector` + `doc_state`；workspace/uid 分区                                                                                                       | `UserDB::open_collab_db` → `CollabKVDB::open`；写路径 `flush_doc` / `RocksdbDiskPlugin` |
| **SQLite `flowy-database.db`** | 用户资料、workspace 成员、**collab_snapshot**（每 object 最多 5）、**upload_file_*** 队列、**af_collab_metadata**（prev_sync_state_vector）、chat/AI 离线消息、shared views… | Diesel migrations；`flowy-sqlite::init`                                                 |
| **SQLite `cache.db`**          | 应用 KV 配置偏好                                                                                                                                                             | `KVStorePreferences`                                                                    |
| **文件系统**                   | 上传临时 `cache_files/`；collab db zip 历史备份                                                                                                                              | `StorageManager`；`CollabDBZipBackup`                                                   |

协作 **文档内容** 不走 SQLite 行表，而走 CRDT 编码进 RocksDB——这是与「块表 + OT 日志」类架构的根本分界。

### 1.4 文件附件管线

```
选择文件 → StorageService 写本地 temp → SQLite upload_file_table(+ parts)
        → FileUploader 优先级队列（max 3 并发）
        → Cloud multipart create/part/complete
        → 完成后标记 / 进度 broadcast → Flutter Isolate stream
```

- 启动时 `prepare_upload_task` 从 SQLite **恢复未完成上传**（离线/崩溃续传线索）。
- 证据：`flowy-storage/src/manager.rs:58-136`；`uploader.rs:21-100`；migration `2024-06-16-131359_file_upload/up.sql`。

### 1.5 索引侧车（协同数据 → 搜索/AI）

- `InstantIndexedDataWriter`：collab finalize 后排队；**30s tick** 扫存活 collab → consumer（Tantivy / embedding）。
- `af_collab_metadata.prev_sync_state_vector` 用于增量 rag 索引差量。
- 证据：`collab-integrate/src/instant_indexed_data_provider.rs`；`flowy-ai-pub/src/persistence/collab_metadata_sql.rs`；`flowy-core` full/instant index 模块。

## 2. 优点清单（现象 → 证据 → 对自研的含义）

### A1. 真正的「Local 一等公民」，不是「云的降级模式」

- **现象**：`AuthenticatorType::Local` 默认回退；`LocalServer` 完整实现 `AppFlowyServer` 的用户/文件夹/库/文档/搜索/chat 面；文档云读返回 `RecordNotFound`（逼走纯本地路径）；`create_document_collab` no-op；**无文件云**。云能力可关 `set_enable_sync` 使 client 侧变为 `None`。
- **证据**：`flowy-server-pub/src/lib.rs:50-55`（非法/缺省 → Local）；`local_server/server.rs` 全文件；`local_server/impls/document.rs:12-49`；`af_cloud/server.rs:113-119,166-168`。
- **含义**：本地优先 = **同一 trait 的第一实现**，而不是在云路径上 `if offline`。自研应用层应 `LocalBackend` / `CloudBackend` 同构，UI 与 DocumentManager 无分支爆炸。

### A2. 统一 Collab 建造器：磁盘插件常驻 + 云插件按需

- **现象**：所有 Document / Folder / UserAwareness / WorkspaceDatabase 经 `AppFlowyCollabBuilder`；`build_collab` 一律 RocksDB 插件；`finalize` 才按 `CollabPluginProviderType` 决定是否 `SyncPlugin`。workspace_id 与当前打开工作区不一致直接报错（防异步串工作区）。
- **证据**：`collab_builder.rs:126-151,274-358`；`plugin_provider.rs` trait 极薄。
- **含义**：
  - **O(1) 心智模型**：对象生命周期 = 建 → 挂持久化 →（可选）挂同步 → initialize。
  - 自研可把「持久化 / 同步 / 索引 / 审计」全做成 **Collab 插件点**，避免在 DocumentManager 里 if-else 扩散。

### A3. 写路径本地提交、云侧异步（创建不阻塞编辑）

- **现象**：新建文档：校验本地不存在 → encode → `save_collab_to_disk` → **立即返回** `EncodedCollab`；`tokio::spawn` 再 `create_document_collab`。
- **证据**：`flowy-document/src/manager.rs:163-191`。
- **含义**：本地优先的延迟预算落在磁盘 flush，而非 RTT。云失败可后续重试（本树 create 路径未看到完整 outbox 表——见 §4 不确定项）。

### A4. 打开路径：本地优先，miss 再拉云（多设备首开）

- **现象**：明确注释「user_device_a 创建，user_device_b 打开」时本地无则 `get_document_doc_state`；空 doc_state 当 RecordNotFound。
- **证据**：`manager.rs:244-266`。
- **含义**：不强制启动全量同步；按文档惰性拉取，利于大工作区。

### A5. 关闭文档的「软缓存」与 awareness 清理

- **现象**：`close_document` 移出热缓存 → `removing_documents` 保留 **120s** 可 restore；同时 `clean_awareness_local_state`。
- **证据**：`manager.rs:341-364`。
- **含义**：快速切换标签不重复 hydrate CRDT；协同光标/选区不泄漏僵尸状态。自研可原样借鉴 TTL 软缓存策略。

### A6. 服务面 trait 化 + pub 契约 crate 分层

- **现象**：`AppFlowyServer` 聚合 user/folder/database/document/chat/search/file + WS；领域侧只依赖 `flowy-*-pub` 的 cloud trait（如 `DocumentCloudService`），不直接绑 HTTP。
- **证据**：`flowy-server/src/server.rs:58-152`；`flowy-document-pub/src/cloud.rs:7-37`。
- **含义**：Rust 内核可单测 mock；换传输（HTTP/WS/本地）不改 DocumentManager。**高度适合 Tauri 侧「Rust 内核 + 可选远端」**。

### A7. 双库职责切分清晰（CRDT 状态 vs 关系元数据）

- **现象**：RocksDB 只服务 collab 编码；SQLite 管用户、上传、快照 BLOB 元数据、同步游标；配置另库 `cache.db`。
- **证据**：`flowy-user/src/services/db.rs:17-27,100-163`；`flowy-sqlite` migrations；`kv/kv.rs:12-18`。
- **含义**：避免「一切塞进一个 SQLite 大表」的锁竞争；也避免「一切 RocksDB」导致 SQL 查询/迁移痛苦。自研块工作区可对齐：
  - **CRDT/编码态 → 专用 KV**；
  - **账号/队列/索引游标 → SQLite**。

### A8. 本地快照有硬上限（防无限膨胀）

- **现象**：`collab_snapshot` 表；`CollabSnapshotSql::create` 事务内插入后若同 object **>5 条则删最旧**。
- **证据**：migration `2024-01-07-041005_recreate_snapshot_table`；`flowy-core/src/deps_resolve/collab_deps.rs:94-139`。
- **含义**：本地优先也要 **存储预算**；快照是安全网不是归档系统。

### A9. Collab DB 可校验 + zip 备份历史

- **现象**：`UserDB::backup`：打开并 `validate_collab_db` 成功才异步 zip；按日命名，清理旧备份。
- **证据**：`flowy-user/src/services/db.rs:39-62,166-208`。
- **含义**：CRDT 库损坏可恢复线索；桌面端「数据隐私优先」叙事有工程落点（README 价值主张：`README.md:137-139`）。

### A10. 网络可达性与 sync 开关进入插件层

- **现象**：`AppFlowyCollabBuilder::update_network` → `CollabConnectReachability`；Cloud server 持 `enable_sync` / `network_reachable`；WS 断线时 `attempt_reconnect`（随机延迟，防 thundering herd）。
- **证据**：`collab_builder.rs:114-124`；`af_cloud/server.rs:53-54,166-173,282-346`。
- **含义**：离线不是 UI 提示，而是 **连接状态机** 贯穿同步插件。

### A11. 附件上传队列持久化 + 并发上限 + 进度扇出

- **现象**：SQLite 记录 chunk 元数据；堆队列；`max_uploads: 3`；`broadcast` 进度；Flutter 侧 Isolate 注册流。
- **证据**：`uploader.rs:73-86`；`manager.rs:103-150`；`upload_file_table` migration。
- **含义**：大文件/弱网是本地优先的一部分；协同文档里的图片不应只靠「内存 Promise」。

### A12. 领域对象共用同一 Collab 类型系统

- **现象**：`CollabType`：Document / Folder / WorkspaceDatabase / UserAwareness…；建造 API 对称；外仓 AppFlowy-Collab 宣称 folder/database/document 同一 `Collab` + 插件。
- **证据**：`collab_builder.rs` 各 `create_*`；workspace `Cargo.toml` collab-* rev `4dfccef`；公开 README [AppFlowy-Collab](https://github.com/AppFlowy-IO/AppFlowy-Collab)。
- **含义**：工作区树、数据库行、文档块 **共享同步与持久化基建**，只换领域 schema。自研若做「页 + 库 + 画布」应尽早统一 object 模型，而不是三套同步。

### A13. Self-host 与官方云共用客户端协议面

- **现象**：客户端只认 URL 三元组 + GoTrue；产品文档提供 Docker/Local Host/生产 self-host；公开部署栈含 **PostgreSQL(pgvector)、Redis、MinIO、GoTrue、Nginx、Cloud API、Worker**（第三方部署说明与官方文档一致口径）。
- **证据（本树）**：`AFCloudConfiguration`；`README.md:51`。
- **证据（公开，非本树源码）**：AppFlowy Local Host Deployment 写明纯本机部署「**no collaboration**」——协作需要可达的 Cloud 栈；self-host 是 **可选云**，不是第二客户端。
- **含义**：隐私叙事可落地为「用户自带云」；客户端代码无需 fork。自研若要 self-host，应同样 **一份协议、两套部署**。

### A14. CRDT 选择 yrs（Rust 原生）而非在 UI 层做 Yjs

- **现象**：workspace 直接依赖 `yrs = "0.21.0"`；领域 collab 在 Rust；Flutter 只收通知/事件。
- **证据**：`frontend/rust-lib/Cargo.toml:90-98,150-157`；AppFlowy-Collab README（yrs 封装）。
- **含义**：与本产品「Rust 的心」同向——**合并与编码在原生侧**，UI 只投影。对比 AFFiNE 大量 TS/Yjs 路径，AppFlowy 把协同计算压在 Rust，更贴近我们的目标约束。

### A15. 索引与协同解耦（侧车 consumer）

- **现象**：collab finalize 注册 embedding queue；instant writer 周期吐 `UnindexedCollab`；metadata 表记 state_vector 游标。
- **证据**：`collab_builder.rs:314-322`；`instant_indexed_data_provider.rs:69-99`；`collab_metadata_sql.rs`。
- **含义**：搜索/AI 不阻塞编辑事务；本地优先下离线也可建本地索引（Tantivy 在 local search 路径）。

## 3. 适合「沉进 Rust」的部分（对本产品可执行摘录）

下列条目按 **效果完整度 → 正确性 → 可验证性 → 与已锁契约一致** 排序（非业务 P0）。

| #   | 可沉部分                                            | 建议形态                                                                               | 证据锚点                                        | 验收方向                                      |
| --- | --------------------------------------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------- | --------------------------------------------- |
| R1  | **Collab 对象生命周期**（建/开/关/删 + 软缓存 TTL） | `conex-collab`：object_id 注册表 + `open/close`                                        | `DocumentManager` 缓存/`removing_documents`     | 单测：关后 120s 内 reopen 无二次 hydrate 标记 |
| R2  | **持久化插件协议**                                  | `PersistencePlugin`：load/save `EncodedCollab`；默认 RocksDB 或 SQLite-blob 二选一可配 | `CollabPersistenceImpl` / `RocksdbDiskPlugin`   | 杀进程后 state_vector 可恢复                  |
| R3  | **同步插件协议**                                    | `SyncPlugin`：sink/stream 抽象；实现可先 in-process 再 WS                              | `CollabCloudPluginProvider` + `SyncPlugin::new` | 双客户端 mock 合并最终一致                    |
| R4  | **Server trait 双后端**                             | `WorkspaceBackend`：Local / Cloud 惰性                                                 | `AppFlowyServer` + `ServerProvider`             | 切换 Auth 不改 Document API                   |
| R5  | **创建：本地 commit + 异步 replicate**              | 写盘成功即 OK；replication outbox                                                      | `create_document` spawn                         | 断网创建仍可读本地                            |
| R6  | **打开：本地 miss → fetch doc_state**               | 惰性拉取                                                                               | `create_document_instance`                      | 仅第二设备首开打网络                          |
| R7  | **上传 outbox**                                     | SQLite 任务 + 并发上限 + 进度事件                                                      | `flowy-storage`                                 | 重启后续传                                    |
| R8  | **快照配额**                                        | 每 object N 份环形                                                                     | `CollabSnapshotSql`                             | 第 6 次创建后仅 5 行                          |
| R9  | **网络 reachability → 同步状态**                    | 连接状态机进内核事件                                                                   | `update_network` / WS state                     | UI 只订内核 sync_state                        |
| R10 | **统一 CollabType 扩展点**                          | 页/块文档先；库/文件夹同总线                                                           | `CollabType` + builder 多 create                | 新类型只加 schema + 校验                      |
| R11 | **增量索引游标**                                    | `prev_sync_state_vector` 存 SQLite                                                     | `af_collab_metadata`                            | 二次索引不重扫全文                            |

**明确不要沉 / 不要照搬的**（与 round-B 缺点文一致，此处仅协同视角）：

- Flutter 通知与 Isolate 进度桥（本产品用 Tauri event / webview）。
- Diesel 迁移风格本身非必须；可换 sqlx，**表职责**可保留。
- 外仓 AppFlowy-Collab 整仓依赖（AGPL 面 + API 漂移）；应 **吸收问题与管线**，自研 yrs 封装或可选兼容层。
- AWS DynamoDB 配置残留（`collab-integrate/src/config.rs`）像历史路径，不宜当主架构。

## 6. 与本产品效果锁的对齐备注

- **多人实时协同**：AppFlowy 路径是 **yrs + WS SyncPlugin + 可选 self-host Cloud**；本地模式故意无实时多端——设计诚实（Local ≠ 伪协同）。
- **块操作性能**：本文件不评 Flutter 编辑器；Rust 侧 collab 编码与 RocksDB flush 是性能敏感点，且已用 `spawn_blocking` 隔离。
- **TS 扩展生态**：协同/存储优点几乎全在 Rust；**可迁移**；UI 协同呈现（awareness 光标）需在 TS 重做投影。
- **超过参考产品**：可打的差异点包括——更干净的单一 UI 宿主、显式 **replication outbox**（补 A3 的不确定）、以及 self-host **无商业席位暗桩** 的协议自研（若需要）。

## 7. 一页备忘：最小可抄管线

```
open(object):
  if local_kv.has(object): src = Disk
  else if cloud: src = fetch_doc_state(object)
  else: error
  collab = build(src) + DiskPlugin
  if cloud_auth && sync_on: collab += SyncPlugin(ws.subscribe(object))
  collab.initialize(); cache.insert(object)

edit(object, op):
  collab.transact(op)           # yrs
  # DiskPlugin 持久化；SyncPlugin 若在线则推送

create(object, data):
  encode → local_kv.flush       # 必须成功
  return ok
  async: cloud.create_collab    # 尽力

close(object):
  clear_awareness
  move cache → soft_ttl(120s)
```

此备忘即 AppFlowy 客户端协同/存储的「可验证骨架」；细节以 §1–§2 证据为准。
