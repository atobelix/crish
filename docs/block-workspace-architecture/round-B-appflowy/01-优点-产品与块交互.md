# AppFlowy 优点：产品与块交互体验

> **调研对象**：`reference/markdown_compare/AppFlowy`（shallow clone of AppFlowy-IO/AppFlowy）
> **视角**：Notion 替代叙事——文档块、数据库多视图、看板、跨端原生体验
> **对照标尺**（非抄写目标）：Tauri + TS + RS；Notion 级块交互；性能与体验双双超过参考；多人实时协同；TS 扩展生态；Rust 做重计算 / 状态沉底
> **方法**：只读 README / 产品插件 / 数据库 UI / Rust 文档内核；每条优点绑定可复核路径
> **不谈**：工期、人员、业务优先级排序；禁止把「Flutter Widget」当作本产品实现方案

---

## 1. 优点清单

### 1.1 产品叙事把「数据主权 + 跨端原生」钉在 Notion 皮之上

**现象**：对外明确定位为 _Open Source Alternative To Notion_；能力海报覆盖 Kanban、Grid 数据库、站点文档、AI、模板与跨设备；价值三角写死为 **数据隐私优先 / 可靠原生体验 / 社区驱动可扩展**，而非单纯功能清单比拼。

**证据**：

- 定位与截图叙事：`reference/markdown_compare/AppFlowy/README.md:1-40`（Kanban / Grid / Sites / AI / Templates / Work across devices）
- 动机与价值：同文件 `:108-144`（Notion 弱数据安全与移动兼容；目标「Notion 功能 + 数据安全 + 跨平台原生」；building blocks + collaboration infra）
- 技术栈声明：同文件 `:55-58`（Flutter + Rust）

**对本产品**：Notion 皮不是「再做一个在线 SaaS 壳」，而是 **块交互完整体验**；「心」必须本地可算、可离线、可跨端一致——与本仓 Tauri+RS 目标同向。

---

### 1.2 块类型以「组件构建表」一等公民注册，错误块兜底

**现象**：编辑器不为硬编码 `switch(type)` 渲染全部块，而是 `Map<String, BlockComponentBuilder>`：每种节点类型对应 builder；缺失时走 error builder。可配置选项动作（`...` / `+`）、padding/placeholder、列表图标、hover 菜单。Slash 菜单仅在白名单节点类型上触发。

**证据**：

- 全局配置与 Slash 支持集：`frontend/appflowy_flutter/lib/plugins/document/presentation/editor_configuration.dart:22-52`（`supportSlashMenuNodeTypes`）
- Builder 契约说明：同文件 `:54-102`（「Every block type should have a corresponding builder… Otherwise errorBlockComponentBuilder」）
- 编辑页装配：`.../editor_page.dart`（`buildBlockComponentBuilders` + `slashMenuItemsBuilder`）

**对本产品**：块扩展应是 **类型键 → 渲染/命令/序列化协议**，而不是散落的 if/else；缺类型时降级可见，避免整页白屏。

---

### 1.3 Slash 菜单：场景分流（桌面 / 移动 / 表内 / 本地模式）

**现象**：同一 `/` 入口按上下文换菜单项集合——移动端单独表；简单表格内裁剪可插入类型；本地模式关闭 AI 写作者；嵌入数据库依赖 `DocumentBloc` 才开放「新建 Grid/Board/Calendar」。默认菜单覆盖：AI、标题、列表、表、分栏、内嵌/引用数据库、callout、大纲、公式、代码、toggle、emoji、日期提醒、图库、文件、子页面等。

**证据**：

- 场景分支：`.../editor_plugins/slash_menu/slash_menu_items_builder.dart:13-55`
- 默认项清单：同文件 `:58-145`（含 `gridSlashMenuItem` / `kanbanSlashMenuItem` / `calendarSlashMenuItem` + referenced 变体、`subPageSlashMenuItem`）
- 表内裁剪注释：同文件 `:48-55,148+`

**对本产品**：命令面板不是一张静态 JSON，而是 **上下文函数**（宿主环境 × 当前节点 × 能力开关）；数据库插入必须绑定「当前文档/工作区」身份，否则只能做「引用」不能做「内联新建」。

---

### 1.4 块把手三位一体：加块 / 选项菜单 / 可视拖拽重排（含分栏合成）

**现象**：块侧提供 `+`（打开 Slash）与 `...`（选项列表）；拖拽时绘制水平/垂直指示条，左右中位可把目标拖入 **分栏（columns）**，而不只是「插在上下」。拖拽中可全局关闭 drag menu（例如列宽调整时），避免手势冲突。

**证据**：

- `+` / `...` 并列：`.../editor_plugins/actions/block_action_list.dart:8-48`
- 可视落点（上下线 + 左右入栏）：`.../actions/drag_to_reorder/visual_drag_area.dart:8-80`
- 拖菜单全局闸：`editor_configuration.dart:23-28`（`EditorGlobalConfiguration.enableDragMenu`）

**对本产品**：块操作面应统一为 **选中模型 + 动作协议**（插入 / 转块 / 删除 / 复制 / 拖到 path）；分栏不是独立「布局编辑器」，而是 **拖放几何产生的结构变换**。

---

### 1.5 Turn into：块类型变换是一等选项动作

**现象**：块选项菜单内嵌「Turn into」二级弹出，由 `BlockActionOptionCubit` 驱动，支持在选区跨父子块时仍正确归一化 selection——用户不必删了重插就能在段落/标题/列表/quote 等之间切换。

**证据**：

- UI 入口：`.../actions/option/turn_into_option_action.dart:14-100`
- Cubit 与 mention/子页联动清理：`.../actions/block_action_option_cubit.dart`（含 mention 的 pageId 处理）

**对本产品**：转块应是 **保内容、换 schema** 的事务，而不是「删节点 + 新建」；对协同场景必须落到同一套 op 语义上。

---

### 1.6 文档内嵌数据库块：Grid / Board / Calendar 与「引用」双路径

**现象**：文档节点类型直接编码 `grid` / `board` / `calendar`；属性带 `parent_id` + `view_id`，校验子节点必须为空（数据库是叶级嵌入）。Slash 可 **在当前文档下新建视图**（`ViewBackendService.createView` + `insertInlinePage`），也可插入 **referenced** 已有数据库。嵌入支持 compact mode 事件回写节点属性。

**证据**：

- 块键与校验：`.../editor_plugins/database/database_view_block_component.dart:11-57`
- 渲染挂载 `DatabaseViewWidget`：同文件 `:111-120`
- 内联新建 Grid/Board/Calendar：`.../database/inline_database_menu_item.dart:11-71`
- Compact mode 写回 attributes：`database_view_block_component.dart:89-101`

**对本产品**：文档与数据库不是两个 App，而是 **同一工作区图中的两种视图宿主**；「内联新建」与「引用已有」必须从交互上区分（所有权 / 删除级联 / 协同权限）。

---

### 1.7 数据库：一份数据，多布局（Grid / Board / Calendar）+ Tab 切换

**现象**：`DatabaseLayoutPB` 三态映射布局名、图标与 `ViewLayoutPB`；同一 `DatabaseController` 可被 TabBar 上的不同 layout builder 消费；Board 在桌面/移动分叉页面但共享 controller 与 setting bar。产品层可对同一 dataset 增加布局视图而不复制行数据。

**证据**：

- 布局扩展：`.../database/widgets/database_layout_ext.dart:7-34`
- TabBar 抽象：`.../database/tab_bar/tab_bar_view.dart:38-93`（`DatabaseTabBarItemBuilder.content/settingBar`）
- Board 桌面/移动分流：`.../database/board/presentation/board_page.dart:41-63`
- Controller 聚合 field/row/group/layout 监听：`.../database/application/database_controller.dart:50-80`

**对本产品**：数据库「视图」= **同一行集上的投影配置**（layout + group + filter + sort + field 可见性）；UI 壳可多套，**行/单元格权威状态只能有一份**（宜沉在 RS）。

### 1.8 行详情即完整文档：RowDocument 复用文档编辑栈

**现象**：打开数据库行详情时，不只编辑属性 cell，还挂载完整 `DocumentBloc` + `AppFlowyEditorPage` 作为行正文；空文档状态回写 `RowDocumentBloc`，与属性区一体。数据库行因此具备「卡片字段 + 长文档」双层信息结构（Notion 式）。

**证据**：

- `RowDocument` / `_RowEditor`：`.../database/widgets/row/row_document.dart:22-100`
- 与 `DocumentBloc`、`ViewBloc`、drop/transaction 服务同页装配：同文件 `:76+`

**对本产品**：行主键下应能挂 **附属文档对象**（独立 collab 文档 id），交互上像「展开详情」，存储上不要把长文塞进 cell 字符串。

### 1.9 字段类型丰富且声明式能力矩阵（分组 / 筛选 / 排序）

**现象**：UI 支持的字段类型包括 RichText、Number、单/多选、日期、Media、URL、Checkbox、Checklist、LastEdited/Created、Relation、Summary、Translate 等；扩展方法声明 **哪些类型可分组、可筛选、可排序、可新建分组**——看板分组能力直接由字段类型矩阵驱动，而不是 Board 页面硬编码。

**证据**：

**对本产品**：字段类型是 **插件点**（解析 / 渲染 / 过滤 / 分组 / 默认值）；看板只是「可分组字段 × 列 UI」的消费方。能力矩阵应可测试、可扩展。

### 1.10 行内 Mention：页面 / 日期提醒 / 外链 / 子页——写作流内知识网

**现象**：文本属性中嵌入 mention 字符与结构化 map；类型含 page、date（含 reminder 兼容）、externalLink、childPage；可带 pageId/blockId、reminderOption。配合 inline_actions 处理器（child page、date、page reference、reminder），写作时 `@`/快捷入口即可织网。

### 1.11 子页面块：文档树可从正文生长

**现象**：`sub_page` 块节点仅存 `view_id`（及 cut/copy 标记），校验无子节点；点击导航到真实 View；与 mention 的 childPage、文件夹 View 体系打通——用户可在文档流内「长出」层级，而不必只靠侧栏新建。

### 1.12 跨端分形：同一插件，桌面/移动两套交互壳

**现象**：Board/Grid/文档工具栏均对 `UniversalPlatform` 分叉——移动端独立 Board 页、移动 Slash 项、移动 toolbar v3（底部 AA 菜单、附件、缩进等）；桌面保留浮动工具栏与拖拽把手。产品坚持 **真原生跨端**（桌面 + iOS/Android 商店分发），而非「桌面完整、移动只读」。

**证据**：

- README 分发面：`README.md:42-50`（Desktop / App Store / Play Store / Self-host）
- Board 分叉：`board_page.dart:52-63`

**对本产品**：跨端不是缩放 CSS，而是 **同一领域模型 + 分形交互适配**；块操作在触控下的目标尺寸、手势与键盘收起策略必须单独设计，但 **op 与文档模型不得分叉**。

### 1.13 编辑事务适配：前端树 ↔ 后端扁平 collab 文档

**现象**：编辑器维护树形 `Node` + `Transaction`；`TransactionAdapter` 将 operation 转为后端 `BlockAction` 与 external text delta（create/update），经 `DocumentService.applyAction` 下沉。Rust `flowy-document` 订阅 block 变更 / awareness / snapshot / sync state，再通知客户端。这是「Notion 皮」与「Rust/CRDT 心」的接缝。

**证据**：

- 适配器职责注释：`.../document/application/editor_transaction_adapter.dart:16-28`（「editor tree / backend flat」）
- apply 路径：同文件 `:45-108`（text delta 与 block actions 分批）
- Rust 订阅与通知：`frontend/rust-lib/flowy-document/src/document.rs:11-78`（`DidReceiveUpdate` / Awareness / Snapshot / SyncState）
- Collab 构建：`frontend/rust-lib/collab-integrate/src/collab_builder.rs`（`Document` / `Folder` / `Database` collab 类型）

**对本产品**：UI 树可以按渲染需要组织；**持久化与协同必须是可交换的 op 日志 / CRDT 文档**。接缝层要可测（transaction → action 黄金样例），避免 UI 状态与协同状态双写漂移。

**现象**：文档页可展示协作者头像栈（awareness 驱动，溢出 `+N` tooltip）；粘贴命令明确支持 desktop/web/mobile，并分路处理 in-app JSON、HTML、图片、纯文本、块链接等——写作体验上接近 Notion「什么都能贴进来」。

## 2. 块 / 数据库交互机制素描

```
┌─────────────────────────────────────────────────────────────────┐
│  Flutter 产品层（appflowy_flutter/lib/plugins）                  │
│  document/  database/  inline_actions/  mobile/ ...             │
│                                                                 │
│  ┌──────────────────┐   ┌────────────────────────────────────┐  │
│  │ appflowy_editor  │   │ Database UI                        │  │
│  │ Node 树 + Sel.   │   │ Grid | Board | Calendar            │  │
│  │ Transaction      │   │ + TabBar 多视图                    │  │
│  │ BlockComponent   │   │ + RowDetail → RowDocument(编辑器)  │  │
│  │ Builder Map      │   │ + Cell skeleton（桌面/移动分形）    │  │
│  └────────┬─────────┘   └─────────────────┬──────────────────┘  │
│           │ 嵌入 database 块               │                      │
│           │ parent_id + view_id            │ DatabaseController   │
│           ▼                                ▼                      │
│  TransactionAdapter              Field/Row/Group/Filter 监听     │
│  tree op → BlockAction + external text delta                     │
└────────────────────────────┬────────────────────────────────────┘
                             │ FFI / protobuf 事件
┌────────────────────────────▼────────────────────────────────────┐
│  Rust 内核（frontend/rust-lib）                                   │
│  flowy-document  │  flowy-database2  │  flowy-folder              │
│  collab-integrate → collab Document / Database / Folder           │
│  本地 KV/RocksDB 插件 + 云插件；snapshot / sync_state / awareness │
│  变更 → Notification → 前端 Bloc 刷新                             │
└─────────────────────────────────────────────────────────────────┘
```

### 2.1 文档块路径

1. 用户输入 / Slash / 拖拽 / 粘贴 → `EditorState.apply(Transaction)`
2. `TransactionAdapter` 拆成 external text 与 block actions → `DocumentService`
3. Rust `Document`（collab）提交 → 订阅回调 `DidReceiveUpdate`
4. 远端/多端更新回灌编辑器（collab adapter / listener）
5. Awareness 独立通道驱动协作者头像

### 2.2 数据库路径

1. `View` 带 `layout`（Grid/Board/Calendar）→ `DatabaseController` 打开
2. Rust `flowy-database2` 维护 fields / rows / cells / groups / filters / sorts / calculations
3. UI 布局只订阅投影：Board 用 group controller；Grid 用行列虚拟；Calendar 用日期字段
4. 文档内嵌块只存 `view_id`，渲染时挂同一套 `DatabaseViewWidget`
5. 行详情打开附属 `documentId`，复用完整文档块编辑栈

### 2.3 文档 ↔ 数据库耦合点

| 耦合     | 机制                                                   | 路径锚点                             |
| -------- | ------------------------------------------------------ | ------------------------------------ |
| 内联新建 | 当前文档 id 为 parent 创建 View，再 `insertInlinePage` | `inline_database_menu_item.dart`     |
| 引用已有 | referenced_* Slash 项                                  | `slash_menu_items_builder.dart`      |
| 嵌入节点 | `grid`/`board`/`calendar` + `view_id`                  | `database_view_block_component.dart` |
| 行正文   | Row → 独立 Document                                    | `row_document.dart`                  |
| Compact  | 事件总线改节点 attribute                               | `compact_mode_event` + database 块   |

## 3. 对本产品的效果启发（内化语言）

> 约束：本产品为 **Tauri 壳 + TS 交互面 + Rust 心**；下列只谈 **效果与结构不变量**，不谈 Flutter 控件搬迁。

1. **块注册表效应**
   用户感知到的「什么都能插」来自 **开放类型表 + 统一命令面**，而不是单一巨型编辑器类。本产品应锁定：`blockType → {schema, render, commands, markdown/html codec, collab op}` 的稳定协议；TS 扩展只实现协议，不碰内核事务机。

2. **命令面板上下文化**
   Slash 项随「是否在表内 / 是否本地 / 是否有文档身份」变化——效果是 **菜单永远短而相关**。本产品命令注册应支持 predicate，而不是全局大表硬过滤。

3. **拖放即结构编辑**
   上下插入与左右合成分栏同一套拖放几何——效果是用户用空间语言改文档结构。本产品拖放应输出 **path 事务**（move/wrap/unwrap），禁止「先删后贴」式丢 id。

4. **数据库是投影，不是另一份文档格式**
   Grid/看板/日历共享行集——效果是改一个 status，三视图同动。本产品应：Rust 权威行存储 + 视图配置（layout/group/filter/sort）可序列化；前端布局可替换。

5. **行 = 字段卡 + 附属长文档**
   任务/CRM/笔记混合场景依赖此结构。本产品行模型预留 `body_document_id`，详情面板挂同一套块编辑器实例（只读/编辑权限与页级协同策略一致）。

6. **文档内嵌视图**
   「在笔记里嵌看板」是 Notion 替代叙事的关键完成度。本产品块类型中应有 **view-embed**（持有 viewId + 可选 compact），与侧栏打开是同一数据。

7. **写作织网**
   页面 mention、子页块、日期提醒构成低摩擦知识网。本产品 inline 节点与块级 subpage 都要进入索引与「反向链接」查询（宜 RS）。

8. **跨端分形只停在壳**
   桌面把手 + 移动底栏是壳差异；事务、字段矩阵、视图投影必须同源。本产品用 **同一 Rust 领域 API**，TS 层做 desktop/mobile 交互适配，禁止两套 schema。

9. **接缝层可测**
   树编辑 ↔ 扁平/CRDT 的 adapter 是正确性核心。本产品应对「插入块 / 转块 / 拖入分栏 / 粘贴 HTML」建立 op 级黄金测试，性能目标挂在 **apply 路径毫秒级**，而非仅 FPS 主观感。

10. **协同在场感**
    头像栈与 sync 指示器是多人产品的「活着」信号。本产品 awareness 与文档 op 通道分离，UI 只订阅投影。
