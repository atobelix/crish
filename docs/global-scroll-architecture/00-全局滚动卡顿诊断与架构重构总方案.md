## 〇、结论先行

### 0.1 技术选型结论

**当前卡顿与滚动条失真，不是 React + Tauri（WebView2/Chromium）选型本身的固有上限。**

| 层 | 判定 |
| --- | --- |
| Chromium 合成器 / 原生滚轮惯性 / 覆盖式滚动条 | 能力足够；VS Code、Cursor、Discord、Slack 同栈可稳定 60fps |
| 本仓前端**滚动几何模型 + 主线程耦合方式** | 是根因所在：动态测高驱动的 `scrollHeight` 在滚动手势中振荡；滚动路径上 React setState / 强制布局读写互相放大；多套滚动条与多套补偿逻辑互踢 |

对标标杆（Chromium 系桌面应用）的共同原则不是「不用 React」或「不用虚拟列表」，而是：

1. **文档坐标系在手势期间冻结**：滚轮/惯性阶段 `scrollHeight` 与滑块几何是常量；测高修正只允许发生在**视口外区域**或**手势 idle 桶**，并配合锚点保持。
2. **滚动主路径零 React 提交**：`scroll` 只更新像素偏移与（至多）可见索引集合；滑块位置用直接写 `transform`，不经 state 驱动整树 reconcile。
3. **确定性几何优先**：Diff / 代码 / 树等半静态内容禁用「估高→实测→改总高」热路径；固定行高或完整折行前缀和，误差为 0。
4. **单一滚动宿主 + 单一滚动条真理源**：禁止同一视口内「原生条 + 自定义条 + 时间轴 scrubber」三套几何各算各的。
5. **用户手势优先**：任何自动吸底、测高补偿、Blink Scroll Anchoring 都不得改写与用户 `deltaY` 相反的 `scrollTop`。

### 0.2 症状 ↔ 根因总表

| 现象 | 主根因（架构断层） | 代码锚点（摘录） |
| --- | --- | --- |
| 滚轮卡顿、反向快搓更糟 | 每次 `scroll` → `setScrollTop` / `setMetrics` 整状态提交；RO/测高在滚动中改 BIT → `setActualTick` 二次 commit；`FlowScrubber` 在 scroll 上对气泡做 `getBoundingClientRect` | `useVirtualScroll.ts:136-138`；`ScrollArea.tsx:305-327`；`FlowScrubber.tsx:165-203`；`useVirtualScroll.ts:154-198` |

## 一、证据链：现有实现测绘

### 1.1 运行时拓扑（现状）

```text
会话消息流
  .list [data-chat-scroll-container]  ← 唯一 overflow-y:auto（DIM-02）
    .listInner height=totalHeight + padding 48/20/16
      translateY(startOffset) 切片
    + 原生 ::-webkit-scrollbar（overlay-scrollbar.css）
    + FlowScrubber（另一套 wheel→scrollTop、另一套比例尺）
Diff 卡片
  内层 overflow 节点 + useVirtualScroll(heightOnly)
  Split/Unified：硬编码 rowHeight=22 + min-height
  Plain：VirtualCodeEngine 双模 + 实测 rowHeight/charWidth
FileTree
  overflow + useVirtualScroll(fallback 28) —— 未设 actual
ScrollArea（设置页等通用容器）
  自定义滚动条 + updateMetrics setState + 拇指 transform
```

### 1.2 消息流虚拟化主路径（VSM）

- `VirtualScrollManager`：Fenwick 树 O(log N) 前缀和，按 id 存 `{estimated, actual}`。
- 初始：`estimateTimelineMessageHeight` 结构化估高灌入 `preloadEstimates`（`MessageVirtualizer.tsx:201-216`）。
- 实测：行上 `ResizeObserver` → `el.offsetHeight` → `setActual` → rAF 批 flush → `|Δ|>4` 则 `setActualTick` → `totalHeight` / `visibleRange` 全量重算（`useVirtualScroll.ts:154-198, 122-134`）。
- 视口上方 Δ 累计后 `el.scrollTop += deltaAbove`（`useVirtualScroll.ts:184-192`）。
- 滚动：`onScroll` → `setScrollTop`（每事件一次 React 更新）。
- 吸底：`useLayoutEffect` 在 `[messages, totalHeight]` 上 `scrollTop = maxScroll`（`MessageVirtualizer.tsx:328-341`）；wheel capture 仅当 `deltaY<0` 解锁。

**这是一条「测高 ⇄ 总高 ⇄ scrollTop」闭环。在用户快速反向搓动时，新行进入窗口 → 大量 estimated 被 actual 替换 → 总高阶跃 → 原生 `scrollHeight` 与滑块尺寸同步跳变 → 若再叠加补偿写 `scrollTop`，即出现抽搐、拉回与掉帧。**

### 1.3 Diff / 代码预览

| 组件 | 几何模型 | 风险 |
| --- | --- | --- |
| `DiffCardSplitView` / `UnifiedView` | `rowHeight = 22` 常量；`total = n*22`；行 `minHeight: 22` + `pre-wrap` 折行 | 折行后真实行高 > 22 → 切片重叠/空白/滚动条与内容错位；折叠条 `min-height:22` 可被撑高 |
| `VirtualPlainCodeViewer` + `VirtualCodeEngine` | 有折行前缀和与实测 rowHeight，方向正确 | `uiSize` 变更 `clearHeights`；行高/字符宽阈值更新触发引擎重建；`heightOnly` 仍把 scrollTop 交给 React state |
| `FileTreeView` | 固定 28px + VSM fallback | 未 `setActual`，高度依赖 CSS 恰好 28；与动态树混用会漂 |

### 1.4 滚动条双轨

1. **系统/WebKit 细条**（`overlay-scrollbar.css`）：尺寸由 Blink 按真实 `scrollHeight` 计算 → 与虚拟化总高直接耦合。
2. **ScrollArea 自定义条**：`thumbHeight = (clientHeight/scrollHeight)*track`；`handleScroll` 同时改 DOM `transform` 与 `setMetrics` → 任何 `scrollHeight` 变化重算 thumb。
3. **FlowScrubber**：按 VSM `manager.getHeight` 分段比例 + 对 scroller 再挂 `wheel` 写 `scrollTop`（`FlowScrubber.tsx:153-156`）。

三套比例尺在动态高度场景下无法恒等 → 「脱节感」。

### 1.5 历史债与已部分落地项

`audits/13` 的 22 条危险代码中，margin 黑洞、部分 content-visibility、行级私有 RO 等**部分已修复**（如 `ChatMessageList.module.css:42-44` 纯净垂直节奏、`.row` 剔除 content-visibility）。
但**架构层问题仍在**：手势期间允许 `scrollHeight` 变化、滚动路径 React 化、多滚动条多真理源、Diff 非确定性行高。
Plan 05 描述了测高统一目标，**尚未形成「滚动几何冻结协议」与「滚动条单一 SSOT」**。本文补上这两层。

## 二、根因穿透（Pipeline / 计算几何）

### 2.1 为什么掉帧？

Chromium 滚动默认在合成器线程推进。以下会把工作拉回主线程并与下一帧对齐失败：

1. **每个 scroll 事件 React commit**（`setScrollTop` / `setMetrics`）→ reconcile 可见切片 DOM。
2. **RO 回调读 `offsetHeight`（强制布局）并改 BIT**，同帧再改 `scrollTop` / `totalHeight` → layout / paint / 再 layout。
3. **`FlowScrubber.updateActiveTicks`**：scroll 上对多个 `getBoundingClientRect` + O(N) 遍历 order。
4. **流式 `messages` 引用变化** → `useMemo` 估高 + `preloadEstimates` + 可能 `actualTick`。
5. **反向快搓**：上一行 actual 修正与下一行 estimated 纠正交替，积压到主线程，表现为「越搓越卡」。

### 2.2 为什么滚动条忽长忽短、抽搐？

原生 thumb 物理模型（量级关系）：

\[
\text{thumb}_h \propto \frac{\text{clientHeight}}{\text{scrollHeight}} \times \text{track}_h
\]

自定义 ScrollArea 同式。只要虚拟列表在滚动中不断改 BIT 总高，`scrollHeight` 阶跃，`thumb_h` 即阶跃——**这不是 CSS 动画，是几何输入在变**。抽搐 = 高频小幅 `scrollHeight` 抖动（估高/实测交替、上方补偿、流式、折叠展开）。

### 2.3 为什么上下互踢拉回？

同时存在的写 `scrollTop` 来源：

| 来源 | 行为 |
| --- | --- |
| 用户 wheel / 惯性 | 真实意图 |
| 吸底 `useLayoutEffect` | `scrollTop = maxScroll` |
| 测高补偿 | `scrollTop += deltaAbove` |
| ScrollArea / FlowScrubber | `scroll*` API / `scrollTop +=` |
| 浏览器钳制 | 上方内容变矮时 clamp，易被误判为「回底」 |

任一来源与用户 `deltaY` 符号相反 → 拉扯感。快速反向搓时补偿与吸底竞态最明显。

### 2.4 静态列表为何也抖？

Diff/预览不依赖「流式插入」，但：

- 行高模型与真实排版不一致（折行、`min-height`、折叠条）；
- 容器宽/字号变化重建引擎 → 总高变；
- 外层若仍挂动态 VSM 或 ScrollArea，仍会读到振荡的 `scrollHeight`。

**静态内容 + 错误几何模型 = 同样失真；与虚拟化算法优劣无关。**

## 三、目标架构（系统性根治）

### 3.1 设计锚点（统一比喻）

把每个垂直滚动面板建成 **「文档坐标系」**：

- 文档坐标 \(y \in [0, H)\)，\(H\) 在 **Gesture Epoch**（滚轮/惯性/拖拽 thumb 期间）内为**冻结常量**。
- 视口只保存 `scrollTop: number` 与渲染窗口 `[i0,i1)`。
- 测量/折叠/流式只允许在 **Commit Epoch** 修改高度表 \(h_i\)，并立即做 **锚点重投影**（见 3.3），禁止「静默改 H 不改锚」。
- 滚动条是文档的**函数**：`thumb = f(scrollTop, H, clientH, track)`，与内容列表**同一 H**。

### 3.2 能力分层（三条模式，按内容确定性选型）

```text
Mode-FIXED   行高常数 h（树、Diff 分栏在禁用折行或强制单行截断时）
Mode-ENGINE  折行视觉行前缀和 × 等行高（代码查看器、VS Code 式 Diff）
Mode-DYNAMIC 动态高（消息流）——必须走 Gesture 冻结 + 锚点补偿
```

禁止：Mode-DYNAMIC 热路径用于本可 Mode-FIXED/ENGINE 的 Diff/树；禁止 ENGINE 在 scroll 中依赖 DOM 实测改总高。

### 3.3 动态列表：Gesture Epoch + 锚点代数（消息流 SSOT）

**协议（不得旁路）：**

1. **GestureActive**（`wheel`/`touchmove`/`pointerdown` 在滚动条/键盘 PageUp… 起，至 `scrollend` + 短 idle）：
   - 冻结：`getTotalHeight()` 与 spacer `height`、原生 `scrollHeight` 输入源不变。
   - 允许：只更新 `scrollTop` 派生的 `visibleRange`（可 rAF 合并）；**禁止** `setActual` / `preloadEstimates` 改 BIT。
2. **Commit Epoch**（gesture 结束或流式空闲）：
   - 批量写入 actual；
   - 对**视口上方**高度差 \(\Delta_{above}\)：在**同一帧 paint 前**执行 `scrollTop += Δ_above`（锚点 = 视口顶第一行 id + 行内偏移）；
   - 视口下方/内的修正不得改变锚行 id。
3. **吸底模式机**（独立状态，非散落 ref）：

```text
state: Free | Following | LockedByUserUp
wheel(deltaY<0) → Free（立即，capture）
nearBottom && Following → follow stream
LockedByUserUp → 仅当 |scrollTop-max|≤ε 且用户显式到底才回 Following
禁止：RO 回调、actual flush、Estimates 在 Free 时写 scrollTop
```

4. **估高策略**：`estimated` 仅作**未测量项**占位；已 actual 项在会话内**单调稳定**（除非内容版本变更）；禁止 `invalidateActual` 后回落 fallback 导致 BIT 阶跃（沿用 Plan 05 意图，写入门禁）。
5. **padding**：`listInner` 的 48/16 必须纳入文档模型（`H = padTop + Σh + padBottom` 或改为行内 padding 且 spacer 不含双计）——**单一公式，写进几何契约测试**。

### 3.4 滚动事件与渲染解耦

| 职责 | 实现 |
| --- | --- |
| 读 `scrollTop` | 原生 `scroll`（passive）→ rAF 合并到 `scrollFrame` |
| 更新 React 可见窗口 | **仅当** `startIndex/endIndex` 或冻结总高变化时 commit（`useSyncExternalStore` 或轻量 store，避免整列表 props 风暴） |
| 滑块位置 | 直接写 thumb `style.transform`；尺寸变化单独订阅 `H/clientH` 低频通道 |
| ScrollArea `metrics` | 拆成 `geometry`（H、client）与 `position`（top）；position 不进 React 或仅进 ref；避免 60Hz `setMetrics` |
| 禁止 | scroll 回调里 `getBoundingClientRect` 网络式扫描；scroll 里 setState 消息业务状态 |

### 3.5 滚动条物理稳定

1. **单一 H**：所有滚动条读同一 GeometryStore，禁止 ScrollArea 自读 DOM 一套、VSM 一套。
2. **Gesture 内 thumb 不改高度**：只改 top（与原生滚动一致）。
3. **固定最小 thumb** 防止短到不可抓，但不得用它掩盖 H 抖动。
4. 会话区：优先 **单套** 覆盖式滚动条；FlowScrubber 若保留，其 tick 比例必须读同一 `GeometryStore`，且 **禁止**在 scrubber 上再写 `scrollTop += wheel` 与主列表双驱动（改为「仅当指针在 scrubber 上时把 wheel 映射为文档坐标 jump」且与主滚动互斥）。

### 3.6 Diff / 代码：确定性几何

**Split/Unified 强制迁到 Mode-ENGINE（或 Mode-FIXED + 单行截断）：**

- 与 `VirtualCodeEngine` 同一折行估算（或禁用折行：`pre` + 横向滚动，行高 = 实测一次后的常量）。
- `collapseBar` / 占位行 **高度必须等于 `rowHeight` 的整数倍**并写入前缀和表（禁止仅 `min-height:22` 的流式高度）。
- 禁止行内 `pre-wrap` 与「每项 22px」并存。
- 分栏左右共用同一 visual row 表，避免左右各估。

**Plain 查看器：**

- 保留 Engine；`rowHeight/charWidth` 变更走 **Commit Epoch** + 保持「视觉行索引锚点」而非像素 scrollTop 裸乘。
- 测量元素与虚拟行分离，测量 RO 不得在 scroll 中改总高（可测量，但 H 变更进 Commit Epoch）。

### 3.7 文件树

- Mode-FIXED：`ITEM_HEIGHT` 与 CSS `height/line-height` **常量契约测试**；`useVirtualScroll` 不需要 actual 通道。
- 若未来可变高（多行标签）：复用 Mode-DYNAMIC 协议，不得半套。

### 3.8 边界韧性

| 边界 | 策略 |
| --- | --- |
| 快速反向搓 | Gesture 冻结 H；overscan 可按速度自适应，但不改 H |
| 窗口拖拽 Resize | debounce Commit：先锁 scrollTop 相对锚，再换行宽引擎 |
| 字号/uiSize | 清测高缓存必须在 Commit；预估行高表随 token 重算；锚点保持 |
| 流式 token | 文本追加只影响「当前处理中」行；Following 才跟底；历史行 actual 稳定 |
| 极限矮视口 | 沿用 FileTree 已有矮视口逻辑，上移到通用 Geometry 工具 |
| 禁止 | 定时器盲测 scrollHeight、魔术 px 补偿、`--no-verify` |

### 阶段 F — 门禁与观测

- 单测：Geometry 冻结、锚点、Diff 行高整除、树行高。
- 源码契约：禁止在 `onScroll` 内直接 `setState(scrollTop)` 的新规则（eslint 或自定义 check）。
- 手工/自动化：真 Tauri 宿主（§15 调试纪律，**禁止** 9222 CDP 与 mock 会话验收）长会话 2000+ 消息、大 Diff、深树；Performance 面板目标：主线程滚动路径无 >4ms 连续 long task 风暴；thumb 高度在手势中 std=0。

## 九、空屏缺陷与实现回补

### 9.1 现象

消息流「顶部残句 + 大片空白」：原生可滚，但可见切片未盖住视口。

### 9.2 根因

1. **`clearHeights` 身份随 `ids` 抖动**：`[activeSessionId, clearHeights]` 反复清空 → order 空且同引用不回灌 → 空窗口。
2. **`scrollTop` 与 React 脱节**（rAF 合帧）：原生已滚到中部，虚拟窗口仍按旧 top 物化。
3. **clear 后未立刻 `syncOrder` + `preloadEstimates`**。

### 9.3 已落地修复

| 修复 | 位置 |
| --- | --- |
| `clearHeights` 仅依赖 `manager`，ids 走 ref | `useVirtualScroll.ts` |
| `onScroll` **同步** `setScrollTop` | `useVirtualScroll.ts` |
| 会话/uiSize 清空后立刻 `syncOrder` + `preloadEstimates` | `MessageVirtualizer.tsx` |
| 估高 `useMemo` 依赖 `manager` 而非整个 `vs` | `MessageVirtualizer.tsx` |
| Gesture Epoch：滚动期缓冲测高，idle 一次提交 | `useVirtualScroll.ts` |
| Diff Mode-FIXED 22px + 禁折行 | `fixedRowViewport.ts` + Split/Unified |
| ScrollArea 位置变化不 `setMetrics` | `ScrollArea.tsx` |

### 9.4 验收

- `useVirtualScroll` / Gesture / Diff 几何契约测试全绿。
- 真机长会话快搓不应再持续空屏；瞬时闪白若仍有，继续查 overscan 与 RO 回写。
- `MessageVirtualizer.perf` 在 jsdom 并行负载下可能敏感（基线亦然），以真机为准。
