# 维度九：计算机操作与浏览器自动化生态对比

> **战役工作区**：`docs/deepseek-harness-comparison/`  
> **对比范围**：DeepSeek Harness Webhook/Shell vs Conex Computer Use 与 Browser Automation

---

## 一、对标核心源码路径

- **DeepSeek Harness (`dsh`)**：
  - `reference/deepseek-harness/packages/webhook/webhook/src/index.ts` (Webhook 自动化触发)
  - `reference/deepseek-harness/packages/shell/shell/src/index.ts` (命令执行与进程管道)
- **Conex (Crish)**：
  - `crates/conex-computer/src/lib.rs` (屏幕捕获、键鼠模拟与屏幕坐标定位)
  - `crates/conex-computer-tools/src/lib.rs` (面向模型的 Computer Use 工具注册)
  - `crates/conex-browser/src/lib.rs` (CDP 驱动无头/有头浏览器)
  - `crates/conex-browser-tools/src/lib.rs` (浏览器点击/导航/DOM 选择器工具)

---

## 二、架构设计与机制对比

### 1. 外部操作触达能力
- **DSH**：以服务端与开发者命令行自动化为核心，缺少直接针对桌面 GUI 交互（Computer Use）和浏览器可视化的原生内建支持。
- **Conex**：原生内置两套大模型外部操作体系：
  1. `conex-computer`：支持类似 Claude Computer Use 的原生桌面操作系统自动化（截图、点击、输入、滚动）；
  2. `conex-browser`：基于 CDP 的原生浏览器控制与 DOM 元素拾取器。

### 2. 优劣裁判
- **裁判**：**Conex 具有压倒性优势**。在 GUI 自动化、浏览器交互与现代 Agent 前沿交互场景中，Conex 的原生能力覆盖面远大于 DSH。
