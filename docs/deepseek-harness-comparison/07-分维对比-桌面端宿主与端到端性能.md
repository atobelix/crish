# 维度六：桌面端宿主整合与端到端性能对比

> **战役工作区**：`docs/deepseek-harness-comparison/`  
> **对比范围**：DeepSeek Harness Electron + Node + pnpm 宿主 vs Conex Tauri 2 + Rust 进程内引擎

---

## 一、对标核心源码路径

- **DeepSeek Harness (`dsh`)**：
  - `apps/desktop/src/main.ts` (Electron 启动与资源初始化)
  - `apps/desktop/src/host-process.ts` (内置 Node 子进程与管道分帧 RPC)
  - `apps/desktop/src/project-manager.ts` (内置 pnpm 项目管理与 store)
- **Conex (Crish)**：
  - `apps/agent-workbench/src-tauri/src/main.rs` (Tauri 2 壳与进程内装配)
  - `crates/conex-markdown/src/lib.rs` (Rust 增量流式 Markdown 渲染)
  - `apps/crish-desktop/src/` (React 19 + Vite 桌面前端)

---

## 二、架构设计与机制对比

### 1. 宿主与进程模型
- **DSH (三层重型架构)**：
  - Electron 主进程 -> 管道 -> 独立 Node.js 二进制子进程（Cordis 运行时）-> 内置 pnpm -> 渲染进程。
  - 需要在客户端携带整套 Node 二进制与 pnpm 脚本，跨进程序列化与通信开销大，冷启动显著延迟。
- **Conex (单进程高性能架构)**：
  - Tauri 2 壳 + Rust 引擎同进程运行（In-Process）。
  - 无网络端口、无独立守护进程、无额外 Node 依赖。
  - 前后端通信直接通过原生 Webview IPC 分发，毫秒级冷启动。

### 2. 流式渲染与 UI 响应
- **DSH**：前端处理复杂流式 Markdown 易造成主线程卡顿与 DOM 抖动。
- **Conex**：自研 `conex-markdown`（pulldown-cmark + syntect + moka），将 Markdown 解析与语法高亮下沉到 Rust 多线程池，前端只做极轻量 DOM 增量更新。

### 3. 优劣裁判与高下判定
- **裁判**：**Conex 具有压倒性统治优势**。在安装包体积、内存常驻、启动速度、操作流畅度与能耗方面，Conex 完全超越 DSH。
