# 维度一：内核架构与插件扩展体系对比

> **战役工作区**：`docs/deepseek-harness-comparison/`  
> **对比范围**：DeepSeek Harness Cordis 插件体系 vs Conex 多 Crate / Trait 架构与 Plugin-SDK

---

## 一、对标核心源码路径

- **DeepSeek Harness (`dsh`)**：
  - `packages/core/agent-loop/src/index.ts` (Cordis Service 声明与生命周期)
  - `packages/core/scope/src/` (作用域化注入与边界隔离)
  - `packages/bundle/base/src/` (profile 组合与 patch 注入)
- **Conex (Crish)**：
  - `crates/session-loop/src/lib.rs` (Crate 组织与公开类型导出)
  - `crates/session-loop/src/loop/loop_runner.rs` (构建器注入与装配)
  - `packages/plugin-sdk/src/` (TS 侧插件 SDK 与能力暴露)

---

## 二、架构设计与机制对比

### 1. 扩展机制
- **DSH (Cordis 微内核)**：
  - 采用时空可组合性（Spatiotemporal Composability）。
  - 没有特权内核，一切皆插件（包括 session、agentLoop、tools）。
  - 运行时动态加载，支持 `cordis.patch.yml` 在不改动源码的情况下覆盖/替换任意服务实现。
- **Conex (Rust Workspace + Trait 门面)**：
  - 核心逻辑由 Rust 严格控制，跨 Crate 采用单向无环图（DAG）依赖。
  - 核心回路（session-loop、orchestrator）通过 Trait 解耦，扩展以编译期静态组装为主。

### 2. 优劣裁判与高下判定
- **DSH 优势**：动态性、生态扩展性碾压，任何开发者可以通过发布 npm 包深度改写行为。
- **Conex 优势**：编译期强类型安全、无运行时动态查找开销、依赖链条绝对可控、杜绝运行时服务注入丢失。
