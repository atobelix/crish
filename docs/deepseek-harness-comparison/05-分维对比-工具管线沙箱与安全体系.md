# 维度四：工具管线、沙箱与安全体系对比

> **战役工作区**：`docs/deepseek-harness-comparison/`  
> **对比范围**：DeepSeek Harness Tools / PTC / Sandbox vs Conex agent-tools / conex-sandbox AST 门禁

---

## 一、对标核心源码路径

- **DeepSeek Harness (`dsh`)**：
  - `packages/core/tools/src/index.ts` (工具瀑布流水线与注册表)
  - `packages/core/tools/src/ptc.ts` (Program-The-Call / 代码模式执行器)
  - `packages/sandbox/sandbox-local/src/index.ts` (Linux bwrap / macOS Seatbelt / Win32 ACL)
- **Conex (Crish)**：
  - `crates/agent-tools/src/lib.rs` (内置工具执行与写路径互斥)
  - `crates/conex-sandbox/src/lib.rs` (语义 AST 拆分与门禁)
  - `crates/session-loop/src/approval.rs` (动态审批通道与 ToolContext)

---

## 二、架构设计与机制对比

### 1. 工具交互范式（PTC 亮点）
- **DSH 独创 PTC**：模型编写 Python/TypeScript 脚本，通过内部 SDK（`await tools.name(...)`）一次性完成数据获取与过滤，大幅减少上下文占用。
- **Conex**：传统单工具调用模式，每次工具调用都需要往返一次模型请求。

### 2. 沙箱与安全防线
- **DSH**：尝试使用真正的操作系统级内核沙箱（Bubblewrap/Landlock、Seatbelt、Windows ACL Restricted Token）。
- **Conex**：应用层 AST 语法树切分 + 正则黑名单 + 用户审批门禁，严格避开过度设计的内核沙箱维护黑洞。

### 3. 优劣裁判与高下判定
- **PTC 模式**：**DSH 领先一代**，是 Conex 极需学习吸收的方向。
- **沙箱工程落地**：Conex 的应用层 AST 门禁在跨平台可靠性与可维护性上更具务实优势。
