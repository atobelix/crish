## 二、子 Agent 派发与执行纪律

1. **纯代码驱动（Code-Only Verification）**：
   - 用户明确指示：“**后面子agent就不允许看文档了，让他们专心看代码即可**”。
   - 子 Agent 派发 prompt 中必须直接提供目标代码文件清单与核心函数/结构体名，禁止依赖双方项目中的 `README`、`docs/` 或说明文。
2. **禁止浅尝辄止与泛泛而谈**：
   - 必须穿透到代码实现细节（如内存所有权、生命周期、错误传递链、锁争用、序列化开销、状态机转移穷举度、安全沙箱逃逸面等）。
   - 必须指出具体缺点与代码破绽，不能一味吹捧，也不能盲目自大，实事求是分高下。
3. **单轮派发规模**：
   - 符合 `AGENTS.md` §2 调度规则（单轮 5–12 个）。
   - 6 个核心审计子 Agent 并行执行，分别覆盖上述 6 个专业维度。
4. **输出标准**：
   - 产出必须为 UTF-8 无 BOM 中文 Markdown；
   - 引用代码位置统一采用 `文件路径:行号`；
   - 每一小节必须有明确的：【代码位置】、【Conex 现实实现】、【DSH 现实实现】、【深度优劣对比（谁做得好）】、【破绽与技术债务】。
