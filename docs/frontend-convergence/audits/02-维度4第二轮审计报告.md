## 六、关注点汇总（非阻塞）

以下为审计中观察到的可改进点，不构成红线，供后续轮次参考：

1. **pricingStore hub 保留 386 行**：虽属合法（用户价表存储 + 4D 估算是 hub 核心职责），但若后续进一步收敛，可考虑将 `resolve4dPrices` / `estimateCostUsd4d` 等纯估算函数抽至 `pricingEstimator.ts`，hub 进一步瘦身至纯装配 + localStorage 读写。当前 386 行低于业务逻辑 400 上限，不违规。

2. **基线新增 tabDragPrimitives(349) / tabDragResolve(383) 登记**：两子模块接近业务逻辑 400 上限的 85% 警告线，已诚实登记基线。后续若继续增长需触发拆分；当前属合法登记，非违规。

3. **typecheck 既有 117 错误**：本轮零新增，但战役外既有错误（ExternalSessionImport / DiffCard / MessageActions 等）仍存。MessageActions.tsx 的 `showToast` 未定义（4 处 TS2304）属真实缺陷（缺 `useToast()` 调用），建议后续轮次治理，非本轮 T4-11/T4-9 引入。

4. **useMcpServerListState 输入仍为 29 字段平铺**：hook 将 29 平铺字段收拢为 3 分组对象，消除了 McpServerList 的 props 爆炸；但 hook 自身的输入参数仍是 29 字段平铺（`useMcpServerListState.ts:62-90`）。这是 McpSettingsTab → hook 的接口，属 hook 输入面，非组件 props 面，不违反 T4-9 目标（组件 props ≤15）。后续可考虑将 useMcpSettings 返回值也分组，但属优化项非必项。

5. **SessionStrip / GlobalSessionTabBar 收敛方式为 hook 内聚**：这两个组件的 props 收敛依赖 hook（useWorkspaceChromeState / useStoreWithEqualityFn）而非显式子对象分组，与 T4-9「props 分组为子对象」的典型形态略有差异。但效果相同（props ≤15），且 hook 内聚是更优的模式，不违规。
