## 1. 项目目标与最终形态

- 目标：软件内"用户与 AI 共同操作"的浏览器——AI 操作用户可见、用户可随时接管同一实例、可导入 Chrome/Edge 用户数据；二期电脑操作。
- 形态：**受管独立 Chromium 进程**（CfT 优先/系统 Chrome/Edge 回退，独立 profile）+ CDP 单通道（loopback 随机端口 + 会话 uuid）；MVP 为 headed 真实窗口；P1 为帧流（Tauri Channel）渲染进面板 canvas + 输入转发 + IME 隐藏输入框桥。
- 否决（红队验证后维持）：WebView2 内嵌（无 SLA/profile 不互通）、独立窗口直操（吊销信号源失效）、注入脚本主通道（isTrusted=false）、CEF（3 倍复杂度）。

## 6. 关键经验与坑（接手者必读）

1. **空返回 = 网络问题**：子 Agent 汇报空但文件可能已落盘——先查文件/代码再决定重派；重派时拆小（单文档/单文件任务成功率远高于多文件组任务）。
2. **并行环境**：十几个 Agent 同时开发。派单必须限定文件域（"其他文件只读"）；lib.rs/Cargo.toml 等共享文件由主控收口；**并行 Agent 的 git 操作会误伤**（曾出现 stash-pop UU、整批文件被 git restore）——发现异常先查 git status，别慌着重做，文件常在其后续提交中。
3. **git 事故处理**：索引 UU 阻塞一切 commit → `git reset HEAD -- <path>` 仅重置索引（工作区冲突文本保留，由冲突方处理），不要替并行 Agent 解决冲突内容。
4. **禁止 --no-verify/绕过门禁**；中文注释 UTF-8 无 BOM（写完自查前 3 字节非 EF BB BF）；不擅自 git commit（除非用户指示/轮次收口）；测试资产立即入库（AGENTS.md 铁律）。
5. **设计约束红线**：不引 chromiumoxide（自研 CDP 客户端）；不把 browser_* 注册进 register_builtin_tools（后置注册）；evaluate 唯一设计是 17 §3 三层校验；门禁 DomainGate 唯一实现在 conex-browser-tools/src/gate.rs；错误码登记走 conex-types + TS 双端。
6. **U-13 裁决**：帧流下行走 Tauri Channel（非 WS，前端 WS 无法自定义 header）；输入上行走 invoke（browser_input）。
7. **派单前读文档**：无方案文档的项不派子 Agent（防摇摆，见 gaps 文档派单纪律）。
