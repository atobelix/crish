# 调研：DAG 可视化、多模型扩展点、输出目录命名

> 定位：feature-gap 系列前端/架构调研文档，为 feature-gap 方案（`docs/feature-gap-analysis/plans/`）的三个待定夺/待决项提供落地设计。
> 相关任务：T-D-12（DAG 可视化）、T-D-10（多模型模式）、T-EG-08（输出目录）。
> 用户决策：DAG 可视化**做**（符合视觉体系 + 随时可下线）；多模型模式**不做**但预留扩展点；输出目录命名**带日期**（`<日期>-<conversation-id>` 形态）。
> 结论速览：三项均为低成本改动（合计约 1 个任务卡量级）；DAG 可视化建议「纯 CSS/SVG + 默认关闭的功能开关」；多模型只加一个 `model_override` 字段不实现逻辑；输出目录命名改为 `<YYYY-MM-DD>-<session_id>` 并入 T-EG-08 任务书。

## 1. 现状调查

### 1.1 视觉体系与可复用资产

#### 1.1.1 设计 token 体系（单源）

样式规范以 `apps/crish-desktop/src/styles/tokens.css` 为唯一真源，新组件**禁止裸 hex/rgba**（`components/ui/README.md:26-39` 门禁约束）。与本主题直接相关的 token 分组：

| 用途 | token | 证据位置 |
|---|---|---|
| 语义色（成功/警告/错误/信息 + 底色/边框） | `--color-success` / `--color-warning` / `--color-error` / `--color-info` 及 `-bg` / `-border` 后缀 | `tokens.css:72-84`（浅色）、`tokens.css:445-457`（深色） |
| 背景层级 | `--bg-primary` / `--bg-secondary` / `--bg-tertiary` / `--bg-card` / `--bg-elevated` | `tokens.css:10-19`（浅色）、`tokens.css:393-400`（深色） |
| 边框 | `--border-color` / `--border-subtle` / `--hairline` / `--hairline-strong` | `tokens.css:25-31`（浅色）、`tokens.css:406-412`（深色） |
| 圆角 | `--radius-xs` ~ `--radius-2xl` / `--radius-full` | `tokens.css:161-167` |
| 间距阶梯 | `--space-0` ~ `--space-16` | `tokens.css:301-317` |
| 字号阶梯 | `--font-size-xxs` ~ `--font-size-2xl` | `tokens.css:243-257` |
| 阴影 | `--shadow-sm` / `--shadow-md` / `--shadow-lg` / `--shadow-2xl` | `tokens.css:174-194` |

深色主题同族映射：`html[data-theme="dark"]` 块内语义色变量整体重赋值（`tokens.css:391-507`），组件只消费变量名即可自动适配双主题，无需深色特判。性能档（high/balanced/eco）由 `data-perf-tier` 控制过渡与模糊开销（`tokens.css:669-704`），DAG 状态动画应只依赖 `--transition-*` 变量，不写死时长。

#### 1.1.2 ui 原子层与分层门禁

- 三层结构：`components/ui/`（原子层）→ 业务组件层（`components/` 下域目录）→ 页面/编排层；门禁脚本 `npm run check:ui-layer` 扫描 import 越界（`components/ui/README.md:9-24`）。

#### 1.1.4 图形库依赖现状

- `apps/crish-desktop/package.json` **无任何图形/图表库**（react-flow / mermaid / recharts / d3 / echarts / cytoscape 均未命中）。
- 全仓唯一 mermaid 依赖在 `packages/conex-mdx/package.json:53`（`mermaid ^10.0.0`），用途是 MDX 文档渲染，不在桌面 UI 依赖链上，**不构成引入先例**。
- 结论：DAG 可视化用**纯 CSS/SVG** 实现，零新依赖、零体积成本，且天然符合 token 体系（图形库自带样式通常难以对齐 `--color-*` 语义变量与圆角/密度体系）。

项目**没有中心化 features 注册表**，现有开关分两种惯例：

## 2. DAG 可视化方案（T-D-12：做，可下线）

### 2.1 决策摘要

- **做**，但限定两条铁律：①严格复用视觉体系（token + ui 层 + RuntimeSection 区段模式，不引入图形库、不发明样式）；②**随时可下线**——`flow_dag_visible` 功能开关，默认关闭，关闭时零渲染零请求零事件订阅，下线 = 前端删组件，引擎零改动。
- 渲染方式由 03-D 原方案的 Mermaid **改为纯 CSS/SVG**：项目无图形库依赖先例（§1.1.4），Mermaid 的运行时解析、主题不一致、样式注入都与 token 体系冲突；DAG 节点规模（单会话子代理数通常 ≤ 20）远小于需要图形库的规模，手写分层布局完全够用。
- 总量级：约 0.5~1 个任务卡（只读查询命令 + 前端组件 + 开关 + 测试）。

### 2.2 渲染方式（纯 CSS/SVG）

**节点**：DOM 卡片（div + CSS Modules），不引入画布渲染。
- 底色 `var(--bg-card)`、边框 `var(--hairline-strong)`、圆角 `var(--radius-lg)`（对齐卡片体系 `tokens.css:15,31,164`）。
- 左缘状态色条 + 状态圆点，映射对齐 `AgentTeamBoard` 语义与 token 语义色：

| 状态 | wire 名 | 色 token | 视觉 | 依据 |
|---|---|---|---|---|
| Pending | pending | `--color-info` 淡化/`--text-tertiary` | 灰色描边点，无填充 | `flow_graph.rs:373`；`AgentTeamBoard.tsx:33` 默认灰 |
| Running | running | `--color-info`（蓝） | SVG 圆环旋转 spinner | `AgentTeamBoard.tsx:16-30` 同款 |
| Completed | completed | `--color-success`（绿） | 实心绿点 | `AgentTeamBoard.tsx:35-37` |
| Failed | failed | `--color-error`（红） | 实心红点 | `AgentTeamBoard.tsx:38-40` 橙色在 agent 域、DAG 域用 error 更贴合语义色 |
| Blocked | blocked | `--color-warning`（橙） | 实心橙点 + 节点整体降透明度 | `tokens.css:76-78` |

- 节点内容：标题（节点 id 或 task 截断，`--font-size-sm`）+ 副行（run 状态摘要，`--font-size-xs` / `--text-tertiary`），长度用 `text-overflow: ellipsis`（对齐 `RuntimePanel.module.css:46-49`）。

**连线（依赖边）**：CSS 边框线方案（非 SVG path）——节点列间用 1px `var(--hairline-strong)` 水平线与竖线连接（网格对齐），复杂跨层边可退化为「上节点底缘 → 下节点顶缘」的简单折线。理由：依赖图是「无环有向图」，拓扑分层后同层并行、层间连线规整，CSS 网格足够；SVG 仅在边数/交叉多时作为后续增强项。

**布局**：前端拓扑分层算法（纯函数）——按 `depends_on` 求最长依赖深度作列号（层 = 深度），层内并行节点横排（对齐 `parallel` 语义：声明序为同层串行顺序，`flow_graph.rs:99-102`）。图数据量小，无需图形库自动布局。

**空态/无声明态**：无编排声明（无 `flow_declaration` 键）时区段不渲染（对齐 `SecurityAuditSection.tsx:27` 空态隐藏模式）。

### 2.3 组件设计（FlowDagView）

```

components/workspace/FlowDagView.module.css — 节点/连线/状态样式（token 变量）
components/workspace/flowDagLayout.ts       — 纯函数层：拓扑分层 / 边生成 / 状态色映射 / 空态判定
components/workspace/flowDagLayout.test.ts  — 纯函数单测
components/workspace/flowDagStore.ts        — zustand 事件 store（§2.5）
hooks/useFlowDagVisible.ts                  — 功能开关 hook（§2.4）
```

- 层级归属：业务组件层（`components/workspace/` 域，与 RuntimePanel 同域）；纯函数层抽到 `flowDagLayout.ts`（对齐 `runtimePanelLib.ts` 纯函数层先例）。
- 挂载点：RuntimePanel 新增一个区段「编排图」（`RuntimePanel.tsx:169` 附近，SecurityAuditSection 与 PlansSection 之间），复用 `RuntimeSection` 基座（标题 + 计数：如 `5 节点 · 2 运行中`）；计数文案/aria 走纯函数层。
- 只读约束：无任何交互写面（03-D 原方案「不新增写入面，编排权仍在主 Agent」保留，`03-D多Agent调度方案.md:739`）。
- ui 原子层消费：区段内如需要按钮/工具提示用 `ui/index.ts` barrel 导入（`ui/index.ts:5-10`），禁止跨域直接 import（`components/ui/README.md:58-59`）。

**数据结构（纯函数层 API 草案）**：

```ts
// flowDagLayout.ts
export type DagNodeState = 'pending' | 'running' | 'completed' | 'failed' | 'blocked';

export type DagNode = {
  id: string;
  task: string;
  dependsOn: string[];   // 依赖边源
  parallel: boolean;
  isComposite: boolean;
  state: DagNodeState;
  subagentRunId?: string;
};

export type DagEdge = { from: string; to: string };

// 拓扑分层：最长依赖深度 = 层号；返回 层号 → 节点列表
export function layerNodes(nodes: DagNode[]): DagNode[][];
// 边生成：由 dependsOn 展开为边表
export function buildEdges(nodes: DagNode[]): DagEdge[];
// 状态 → token 变量名映射（组件消费 CSS 变量，不写裸色值）
export function stateColorVar(state: DagNodeState): string;
// 空态判定：无节点 / 无声明 → null（区段不渲染）
export function dagEmpty(nodes: DagNode[] | null): boolean;
// 计数文案 + aria（对齐 runtimePanelLib 职责）
export function dagCountLabel(nodes: DagNode[]): { label: string; ariaLabel: string };
```

### 2.4 功能开关（flow_dag_visible，默认关）

**决策：默认关闭**——用户需要才开；默认关时 RuntimePanel 完全不挂载该区段（零渲染零请求零事件订阅）。

- **存储与读取**：localStorage 直读键 `crish_flow_dag_visible`（对齐 `RESTORE_LAST_WORKSPACE_LS_KEY` 模式：`'true'/'1'` → true，缺失/脏值 → false 安全默认，`layoutTreeStore.ts:201-217`）；**不写入 `settingsStore.appSettings`**（引擎事件权威回灌会覆盖本地选择，`settingsStore.ts:16-19`）。
- **读取 hook**：`useFlowDagVisible()`（同步 localStorage 直读，对齐 `hydrateWorkspaceShell.ts:53` 直读先例；stale 场景可加 storage 事件监听，非必须）。

```ts
// useFlowDagVisible.ts
const FLOW_DAG_VISIBLE_KEY = 'crish_flow_dag_visible';
export function useFlowDagVisible(): boolean {
  try {
    const raw = localStorage.getItem(FLOW_DAG_VISIBLE_KEY);
    return raw === 'true' || raw === '1';
```

- **门控位置**：RuntimePanel 装配层——`const flowDagVisible = useFlowDagVisible(); ... {flowDagVisible && <FlowDagView .../>}`（`RuntimePanel.tsx:78-178` 装配模式内）；开关关 → 区段组件、store 订阅、查询请求全部不启动。
- **开关语义表**：

| 场景 | 行为 |
|---|---|
| 默认（键缺失） | false，区段零挂载 |
| 运行中切换开 → 关 | 组件卸载，事件订阅/轮询随组件卸载清理（useEffect cleanup），下次刷新零开销 |
| 运行中切换关 → 开 | 组件挂载即发一次快照查询 + 开始订阅事件，状态补全 |
| 多窗口/多标签 | 同 tab 会话内 localStorage 事件可选监听；跨窗口不强一致（与 tabMode 同级语义） |

- **设置面板开关（可选增强）**：若用户想要 UI 入口，做一个小布尔开关放设置面板（Settings 键形态对齐 `tabModeEnabled`，`clientApi.ts:122`）；但开关真值仍以 localStorage 为准（设置面板写入时同步该键，双写模式对齐 `tabModeEnabled` 与 layoutStore 双写，`clientApi.ts:121-122` 注释）。首版可不做 UI 入口，dev 键即可。
- **下线语义**：开关关闭即「零残留」——组件不挂载、store 不建、事件不订阅、无请求；彻底下线 = 删除 FlowDagView + flowDagLayout + flowDagStore + useFlowDagVisible + localStorage 键（全部前端文件，**引擎零改动**——查询命令是通用只读面，保留无害）。

## 3. 多模型扩展点方案（T-D-10：不做，留扩展点）

### 3.1 决策摘要

- **不做**（用户决策）：不实现多模型模式（不做设置开关、不做 per-run 覆盖逻辑、不做 AI 自动选型）。

## 4. 输出目录命名方案（带日期）

### 4.1 决策摘要

- **做**：输出目录命名带日期，形态 `<YYYY-MM-DD>-<conversation-id>`（用户决策：带日期便于按时间排序查找）。
- **不用标题**：`<日期>-<标题>` 需要会话标题溯源链路（前端有、引擎侧无，§1.5）——成本高，按用户决策不引入标题，保留 conversation-id 段（04-EG 原方案已论证，`04-EG编辑工具与文档工作区方案.md:891`）。

### 4.2 命名格式

```
<workspace_root>/.agent-outputs/<YYYY-MM-DD>-<session_id>/
```

- 日期段：本地时区、零填充（`2026-08-04`），避免 UTC 边界跨日导致「凌晨产出排错天」。
- id 段：沿用现净化规则（剥离 `\/:*?"<>|` 与控制字符，对齐 `applyFileDiff.ts:55-61` 思路，`04-EG编辑工具与文档工作区方案.md:741`）；净化后追加日期前缀不引入新非法字符。
- 稳定性：会话**首次** resolve 时生成并写 session_meta `"{session_id}:output_dir"`（键不变），幂等命中后恒返回同一路径（`04-EG编辑工具与文档工作区方案.md:742`）——同会话不会因跨日再调用而漂移。
- 惰性创建语义不变：仅写 meta 不建目录，`dirCreated: false`，首次写入时自动创建（`04-EG编辑工具与文档工作区方案.md:741`）。
