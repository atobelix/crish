3. **事件注册表/背压双护栏**：registry_drift.rs:625-700 把 `event_backpressure`/`subagent_event_kind_backpressure` 与注册表 backpressure/kindBackpressure 字段双向锁定，timer/cron 事件专项断言在场（:746-897）——背压分级静态可信。
4. **watch 域接线**：escape_watch.rs:39 消费 `FileChangeEvent/UndeclaredWrite`，判定面（:211-265）对 Removed/Renamed 置 has_destructive，契约形状逐字一致。
5. **impact 域接线**：conex-types::impact 上移后 conex-fs 重导出（impact.rs:12），delete.rs/audit.rs/core_run_commands.rs 消费一致，无形状漂移。
6. **gatekeeper 接线**：shell.rs:210-253（Blocked→红线审计、RequiresApproval→审批通道、未接线→tool.requires_approval）+ process.rs/host_openers/cli_bridge 双防线实例化一致。

## 4. 总评

三个 crate 的**契约纪律是仓库标杆**：41 事件枚举 + 注册表 + 生成链 + 背压分级由
registry_drift/event_hook_mapping 双护栏锁定（E-27/B-40 同域机制保持）；cron/timer
的固定偏移确定性测试（预检报告列为可信度标杆）；trash 的 checksum 防篡改 +
拒绝覆盖 + 登记失败移回构成完整守卫链；watch 的 Rename 聚合 + flush 线程 +
WeakSender 生命周期设计成熟。

新发现的 20 条集中在三个系统性弱点：

1. **Windows 路径/命令形态在 bash 风格解析器下的失真与盲区**（A2-M1/M2/ML3/ML5）：
   语义层解析器以 Unix 转义/参数语义实现，PowerShell 生态的 scriptblock、.exe
   扩展名、`/s /q` 参数、裸反斜杠路径四类形态未被覆盖——删除形态识别与目标
   收集存在系统性漏判/失真面。建议集中补 Windows 形态用例矩阵。
2. **文件系统递归与恢复路径的信任边界**（A2-H1/M4/ML6）：注释承诺的
   「不跟随符号链接」与实现不符（递归层），登记文件 original_path 无验证。
   删除接管是安全关键路径，此面最值得优先加固。
3. **错误码/枚举 wire 的 legacy 残留与双轨**（A2-M5/L5/L6/L7）：双映射入口
   码分裂 + 与 TS 同构的码表分类争议 + PascalCase legacy，属一致性收尾面。
