- 死代码点位总数（含孤儿产物）：**约 13 项**（9 个代码实体/文件 + 2 个孤儿 Rust crate + 3 个孤儿 TS 包，含空壳 decision-engine）

- 待接线（登记保留）：**约 44 处**（§1.2 各域，均有轮次注释；大部分已登记技术债清单）
- 测试专用/合理保留：**约 50+ 处**
- allow 过期待清理：**4 处**（E1-E4）
- 文档路径：`docs/feature-gap-analysis/audit/A8-死代码与未接线专项审计.md`

### 总评

1. **纪律良好**：110 处 allow(dead_code) 中约 95% 有可追溯的接线/测试注释，且与已登记技术债清单高度重合；全仓编译警告仅 1 条，说明 `cfg_attr(not(test))` 遮蔽策略执行到位。
2. **真死代码集中在孤儿产物**：conex-net/conex-stream 两个 Rust crate 与 logger/telemetry/conex-mdx/decision-engine 四个 TS 包是 R 轮重写前的遗留，g5 清理只处理了依赖声明未处理本体——建议一次性清理并同步 workspace members。
3. **唯一值得警惕的接线缺口**：`audit_sink` 未装配（安全审计面 no-op）与 `persist_outputs` 未 override（产出清单不落库）属于"契约已定义、引擎实现一半"的状态，与 44 处轮次登记面不同，未在已知缺点清单中显式登记。
4. **过期的 allow 注释（E1-E4）** 是审计噪声源，应随代码触碰移除，防止"接线承诺已兑现却标记为待接线"的双向误判。
