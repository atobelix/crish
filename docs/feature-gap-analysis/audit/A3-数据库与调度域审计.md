## 总评

**持久化域（conex-db）**：迁移链 v1→v6 的逐版本事务、col-check 幂等、孤儿过滤（v3→v4）设计扎实，是全仓少见的「防御完备」面；但**备份时序与「DROP 前备份」语义不符（N01）**是最接近数据安全底线的问题——当前行为依赖 WAL autocheckpoint 的偶然性，一旦该行为变化（SQLite 版本/事务大小），升级中途失败将无回退保障。`map_run_row` 静默 Failed（N04）是数据面定时炸弹：未来任何状态字面量扩展都会静默破坏旧数据。

**调度域（flow_graph）**：staged-clone 环检测、Block 传递不动点、预算 recompute 防 double-charge 是亮点；但**parallel 字段静默未实现（N12）**属于「契约承诺了行为而代码没有」，是最高优先级的契约缺陷。flow 持久化整体建立在「session_meta 单键 KV + 多键顺序写」之上，declare/reset/spawn 后持久化三处崩溃窗口（N13/N14/N15/N16）都源于此——接线战役（A-02）开启前修复成本最低。

**恢复域**：四阶梯设计完整、预算制与幂等语义清晰（C-41 已登记确认）；**Completing 漏判（N19）**与 **fork 崩溃窗口（N20）**是恢复正确性的两个真实缺口，均有明确的修复路径。恢复审计取号口径（N22）与 fork 数组无界增长（N21）属工程化欠账。

**lifecycle**：kill_all/resume 的语义冻结清晰，但都踩在「全量快照覆写」的脆弱模型上（N24/N05）——这是本域最值得先动的结构面：补 conex-db 单行定点更新 API 即可同时化解 kill_all、set_subagent_path、spawn 落库三处竞态。

**事件与 steering**：事件序列（T08.12）、持久化分流（delta 不阻塞）、终态唯一（run-terminal）是高质量设计；审计聚合器内存无界（N27）是唯一需要立即收口的资源问题。
