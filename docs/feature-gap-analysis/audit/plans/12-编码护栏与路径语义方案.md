## 二、方案总纲

### 2.1 设计原则（本方案四条硬约束）

1. **编码写回 fail-closed**：所有「读-改-写回」路径在解码后必须校验 lossy 替换是否发生，发生即拒绝写盘（结构化错误 + 引导文案），绝不静默改写原字节；只读路径（read_file）保持 lossy 诚实显示不受影响。
2. **解析器语义优先兼容目标平台形态**：semantics 解析器的转义/参数语义按「Windows + PowerShell 生态优先」补齐（反斜杠路径、scriptblock、`/s /q` 参数），同时保证既有 Unix 形态用例全部回归。
3. **文件系统遍历不跟随符号链接**：递归遍历统一 `symlink_metadata` 单一入口，symlink/junction 一律按「单条目计、不递归」处理，兑现 impact.rs 模块头注释承诺（impact.rs:5-6）。
4. **恢复路径信任边界校验**：meta.json 反序列化得到的 original_path 视为不可信输入，恢复前必须通过「绝对路径 + 无 `..` 组件 + 不在 trash 根内」三重校验；nil-content 删除需双条件确认。

### 2.2 与既有登记项的关系

- P2 与 A1-M1 同根：执行链无 catch_unwind（tool_exec.rs 全域无捕获），panic 会击穿 run task——本方案不引入 catch_unwind，改为「计算面根治」（不产生非法边界），符合「防护在源头」的既有风格；
- P5 的既有测试 `symlink_cycle_does_not_hang`（impact.rs:191-203）只覆盖顶层 symlink 且 Windows 整体跳过——本方案补齐「目录内指向祖先的 junction」用例（`mklink /J` 普通用户可建，无需管理员）；
- P7 修改方向对齐 `error.rs:1019-1024` 自述原则「单一真源，禁止散落 map_err」——以 `core_error_code`（PE-03 §2.4.2 映射表）为唯一真源。

## 四、任务卡详情

### T-PD-01 multi_replace 编码护栏（A1-H1）

**涉及文件**：

- `crates/agent-tools/src/tools/mod.rs`：`DecodedText` 结构（:335-341）、`decode_text`（:346-385）
- `crates/agent-tools/src/tools/replace.rs`：`execute` 步骤 4 解码段（:105-115）
- `crates/agent-tools/src/tools/fs.rs`：`read_file` 解码调用点（:108，只读路径，**不改行为**）

**改动点**：

1. `DecodedText` 增加 `pub lossy_replaced: bool` 字段（语义：解码过程是否发生了替换字符 U+FFFD 注入）；
2. `decode_text` 四个文本分支分别补严格校验：
   - utf-8 无 BOM 分支（:379-384）：`std::str::from_utf8(bytes)` 失败即 `lossy_replaced = true`（不再无条件走 `from_utf8_lossy`）；
   - utf-8-bom 分支（:363-369）：对 BOM 剥离后的 `&bytes[3..]` 同样严格校验；
   - utf-16le/be 分支（:347-361）：`decode_utf16` 的 `from_utf16_lossy` 改为 `from_utf16`，失败（未配对代理项）标记 `lossy_replaced = true`（现有 `decode_utf16` 签名调整或新增严格变体）；
   - 二进制分支（:371-378）`lossy_replaced = false`（本身即拒绝路径）；
3. `replace.rs` 步骤 4（:110-115）在 `is_binary` 拒绝之后追加：`if decoded.lossy_replaced { return Err(结构化错误) }`。错误文案（对齐「二进制文件无法做文本替换」风格）：`"{display}: 文件不是有效 UTF-8（疑似 GBK/latin1 等 legacy 编码），拒绝替换以防破坏原编码字节；请先将文件转码为 UTF-8 再操作"`；
4. `fs.rs` read_file 只读路径保持 lossy 显示（诚实显示契约，不拒绝不报错）。

**风险**：

- 构造点波及面小：`decode_text` 全部构造点集中在 mod.rs（:346-385），调用点仅 replace.rs:109 / fs.rs:108 / mod.rs 测试（:514/:520/:525）——字段追加为增量改动，无外部破坏；
- 行为变化是模型可见的：GBK 文件替换从「静默破坏」变为「结构化拒绝」——预期行为（fail-closed），文案需明确引导；
- 不引入 GBK 正向解码（避免新依赖），拒绝为第一层；后续增强（可选）：schema 增加 `encoding` 入参并接入 `resolve_write_encoding` 允许显式转码写回（本任务不做，登记为后续项）。

**验收标准**：

1. 构造 GBK 字节文件（无 BOM、无 NUL，如「中文」两字的 GBK 编码 `D6 D0 CE C4`）执行 multi_replace → 返回结构化错误，错误文案含「legacy 编码」引导，**文件字节零改动**（raw_bytes 前后一致）；
2. UTF-16LE/BOM、UTF-8/BOM 文件替换照常（既有 `multi_replace_preserves_utf16le_encoding` 回归）；
3. read_file 对 GBK 文件仍可读（lossy 显示），不报错不拒绝（fs.rs 行为不变）。

**测试锚点**：

- `replace.rs` tests：新增 `multi_replace_rejects_legacy_encoding`（GBK 字节写文件 → 断言错误 + 字节不变）；既有 `multi_replace_preserves_utf16le_encoding`（:978）保持；
- `mod.rs` tests：既有 decode 用例（:514/:520/:525 区域）补 `lossy_replaced` 字段断言；新增 `decode_text_marks_lossy_for_invalid_utf8`（含 GBK 样例、孤立代理项 UTF-16 样例）。

### T-PD-02 search.rs Unicode 边界 column 安全（A1-M1）

**涉及文件**：

- `crates/agent-tools/src/tools/search.rs`：`line_hit` 闭包（:142-151）、column 计算（:175-181）

**改动点**：

1. 大小写不敏感分支的命中偏移换算改为**原始行 char 级定位**：对原始行用 `char_indices()` 逐字符折叠（`char.to_lowercase()`）与折叠后的 query 做前缀比对，命中即得到原始行的真实 char 位置（双游标映射：原文 char 游标 + 折叠后字节游标同步推进），column 直接用原始行 char 列号计算——彻底消除「lowered 串字节偏移 → 原始行切片」的长度错位；
2. 兜底防 panic（防御层）：column 计算统一改 `line.get(..byte_offset.min(line.len()))`（`Option` 语义），`None` 时向回退到最近 char 边界（`is_char_boundary` 循环递减）再取前缀——即便未来引入其它偏移来源也不会 panic；
3. regex 分支（:144）`re.find(line).start()` 天然位于原始行 char 边界，不动；大小写敏感分支（:146）`line.find()` 同理，不动。

**风险**：

- 列号数值会变化：现状对含大小写折叠长度变化字符的行本就错位（甚至 panic），修复后为「正确 char 列」，属行为修正非回归；既有 ASCII 用例（main.rs column=9）不受影响；
- char 级折叠映射实现需小心维护双游标同步（折叠可能 1 字符 → 多字符，如 `İ`→`i̇`），建议拆成独立纯函数 + 单测锁定。

**验收标准**：

1. 行含 `İ`（U+0130）与查询「i̇」形态（caseSensitive=false）→ 不 panic，column 为合法 char 列号；
2. 行含 `ﬀ`（U+FB00，3 字节 → 折叠 2 字节）→ 不 panic，column 正确；
3. 既有 ASCII 命中用例 column 数值不变（`grep_finds_matches_with_line_column` :468-504 的 column=9 断言保持）。

**测试锚点**：

- `search.rs` tests：新增 `grep_case_insensitive_unicode_length_mapping`（构造含 `İ`/`ﬀ` 的行 + 大小写不敏感查询，断言不 panic + column 数值）；新增 `grep_column_fallback_stays_on_char_boundary`（直接调 column 换算辅助函数，断言任意字节偏移输入不 panic）；
- 既有 `grep_finds_matches_with_line_column`（:468）、`grep_regex_mode_and_case_sensitive`（:506）保持。

### T-PD-03 Windows 路径语义（A2-M1 + 顺带 ML3）

**涉及文件**：

- `crates/conex-sandbox/src/semantics.rs`：`split_command_args`（:201-256）、`extract_delete_targets`（:296-343）

**改动点**：

1. **转义剥离兼容 Windows 路径**（核心）：`split_command_args` 的 `c == '\\' && quote != Some('\'')` 分支（:215-218）改为「上下文判定」——`\` 仅当后跟**转义需求字符**（空白、引号、`\\` 自身、`$`、`` ` ``、`;`、`&`、`|`、`(`/`)` 等 shell 元字符）时按转义处理（吞反斜杠保后字符）；后跟普通路径字符（`t`、`a`、`.txt`、`\` 后跟盘符/分隔符等）时**原样保留反斜杠**。采用单套跨平台语义（不按 cfg(windows) 分支），因本产品命令面为 PowerShell 环境且 semantics 需保持纯函数跨平台确定性测试；
2. **Windows 风格参数跳过**（顺带闭环 ML3）：`extract_delete_targets` 参数循环（:328-341）在 `/` 开头分支前追加判定——`/s`、`/q`、`/f`、`/S`、`/Q`、`/F`（含 `/s /q` 组合形态）显式跳过不入 targets；其余 `/` 开头（Unix 绝对路径 `/tmp/x`）保持现状入 targets；
3. 盘符路径分支（:332）保持不动——修复后裸参数 `C:\temp\a.txt` 拆参即正确，无需改动盘符判定。

**风险**：

- **本方案回归风险最高的任务**：转义语义放宽会影响 Unix 形态（如 `rm -rf \` 续行、`echo a\ b` 内联转义空格）——`\` 后跟空格仍按转义处理，故空格转义不受影响；需完整回归 semantics.rs 既有测试面（:666-957，含 `remove_item_literal_path` :724 单引号形态）；
- `/s` 跳过与「Unix 单字符目录名目标」冲突（`rm /s` 罕见场景会误丢目标）——可接受边界，任务卡内文档化该判定口径；
- 与 T-PD-04 同文件，必须串行（见 §五）。

**验收标准**：

1. `rm C:\temp\a.txt`（裸参数、无引号）→ delete_targets 精确含 `C:\temp\a.txt`（不再损坏为 `C:tempa.txt`），overall_class 仍 DeleteShape；
2. `rd /s /q C:\x` → targets 不含 `/s`、`/q`，分类不变（Redline 判定 :493-499 不回归）；
3. 既有用例全回归：`remove_item_literal_path`（:724）、`windows_drive_root_redline`（:806）、Unix 转义形态、`cd /d C:\`（:868）等。

**测试锚点**：

- `semantics.rs` tests：新增 `rm_bare_windows_path_preserved`（裸 `C:\temp\a.txt`）、`rm_backslash_path_with_spaces_in_dirname`（`C:\my dir\a.txt` 空格目录）、`win_style_flags_not_collected_as_targets`（`rd /s /q C:\x` 断言 targets 内容）；
- 既有用例全量保持。

### T-PD-04 PowerShell scriptblock 删除形态（A2-M2 + 顺带 ML5）

**涉及文件**：

- `crates/conex-sandbox/src/semantics.rs`：`analyze_indirect` 的 `foreach-object` 分支（:442-452）、`normalize_command`（:259-272）

**改动点**：

1. **scriptblock 主形态**：`foreach-object` 分支增加「首 token 为 `{`」的识别——args 中 `{` 起至 `}` 的 token 序列剥去花括号后 `join(" ")` 拼为内层命令，递归 `analyze()`（对齐 `find -exec` 的拼接先例 :421-441）；`$_`、`$_.FullName` 等管道变量占位按普通 token 保留，递归后 `Remove-Item $_.FullName` 自然命中 `remove-item` → DeleteShape；
2. **`-Process` 形态修复**：现状（:446-448）只取 `-Process` 后**单个** token（得到 `{`）→ analyze("{"）空段漏判；改为 `-Process` 之后剩余参数全部 join（对齐 bash `-c` 分支 :394-399 的 rest 拼接先例），并复用第 1 点的花括号剥离；
3. **顺带可选收尾（ML5）**：`normalize_command` 在去路径前缀（:267-270）后剥离 `.exe` 扩展名（`powershell.exe` → `powershell`、`cmd.exe` → `cmd`），补 `powershell.exe -Command "Remove-Item x"` 形态命中——低风险两行改动，与本任务同函数域，一并完成；
4. 判定语义不变：scriptblock 内层为 DeleteShape → `has_indirect_delete = true`（overall 保持 Indirect，由命令面消费拦截，对齐既有 `indirect_delete_wrapper_flagged` :829 契约）。

**风险**：

- scriptblock 内复合（`{ Remove-Item $_.FullName; Write-Output ok }`）经 join 后由 `analyze` 自然拆段处理，无需额外逻辑；
- 花括号剥离需注意嵌套/字符串内花括号（极罕见，超范围，任务卡文档化边界）；
- 与 T-PD-03 同文件，串行执行（依赖 §五 顺序）。

**验收标准**：

1. `Get-ChildItem | ForEach-Object { Remove-Item $_ }` → `has_indirect_delete = true`；
2. 独立段 `ForEach-Object { Remove-Item $_.FullName }` → `has_indirect_delete = true`；
3. `ForEach-Object -Process { Remove-Item $_ }` → 命中（-Process 修复）；
4. `ForEach-Object { Write-Output $_ }` → **不**误报（normal 内层不置标记）；

**测试锚点**：

- `semantics.rs` tests：新增 `foreach_object_scriptblock_delete_flagged`、`foreach_object_scriptblock_normal_not_flagged`、`foreach_object_dash_process_scriptblock_flagged`、`powershell_exe_command_delete_flagged`（ML5）；
- 既有 `indirect_delete_wrapper_flagged`（:829）等间接形态用例保持。

### T-PD-05 symlink/junction 递归遍历修复（A2-H1）

**涉及文件**：

- `crates/conex-fs/src/impact.rs`：`walk_dir`（:58-84，根因 :67）
- `crates/conex-fs/src/trash.rs`：`dir_size`（:475-486，根因 :482）

**改动点**：

1. **impact.rs `walk_dir`**：`entry.metadata()`（:67）改 `entry.symlink_metadata()`；`meta.is_dir()` 改 `meta.file_type().is_dir()`；新增 symlink 分支（`meta.file_type().is_symlink()`，Windows junction 同样命中——Rust 以 FILE_ATTRIBUTE_REPARSE_POINT 判定）：**按单条目计（count += 1，size 按 symlink_metadata.len() 即链接自身大小），不递归**——兑现模块头注释承诺（impact.rs:5-6「遍历一律使用不跟随符号链接的 symlink_metadata」）；
2. **trash.rs `dir_size`**：同款改造——`entry.file_type()?.is_dir()` 判定后，非目录条目的大小从 `entry.metadata()`（:482，跟随链接）改 `entry.symlink_metadata()` 取链接自身大小；symlink/junction 恒不递归；
3. 统一遍历元数据获取入口为 `symlink_metadata` 单一来源（消除 metadata / file_type 混用面）。

**风险**：

- 行为变化：目录内 symlink 目录从「递归统计目标内容」变为「计 1 条链接」——影响面评估数字变小，属**正确化**（原行为破坏性更大：栈溢出），验收标准中明确数字口径；
- Windows junction 测试依赖 `cmd /c mklink /J`（普通用户可建，无需管理员），但 CI/容器环境可能不可用——测试沿用既有 `symlink_cycle_does_not_hang` 的 skip 模式（失败即 skip，本地 Windows 真机可跑）；
- 与 T-PD-06 同文件（trash.rs），串行执行（见 §五）。

**验收标准**：

1. 目录内建 `sub/loop` junction（指向该目录自身或其祖先）→ `assess` 正常返回，**不栈溢出、进程不挂**，file_count 有限值（环内条目计 1）；
2. `trash_file` 对含 junction 环的目录 → `dir_size` 正常返回（trash 全链路不挂）；
3. 顶层 symlink 行为保持（`symlink_cycle_does_not_hang` :191-203 既有用例不回归）。

**测试锚点**：

- `impact.rs` tests：扩展现有 `symlink_cycle_does_not_hang`（:191）——新增目录内 `sub/loop → 祖先` 场景；Windows 分支用 `std::process::Command::new("cmd").args(["/c", "mklink", "/J", ...])` 建 junction（失败 skip，对齐 :202 注释模式）；
- `trash.rs` tests：新增 `dir_size_does_not_follow_junction_cycle`（目录含 junction 环 → dir_size 返回有限值）。

### T-PD-06 trash restore 路径校验 + 原子登记（A2-M4 + 顺带 ML6）

**涉及文件**：

- `crates/conex-fs/src/trash.rs`：`restore`（:276-310）、`restore_force`（:318-351）、`entry_dir`（:388-398）、`write_meta`（:402-418）、`path_is_within`（:542-552）

**改动点**：

1. **新增校验函数** `validate_original_path(original: &Path, trash_root: &Path) -> Result<()>`，三重校验：① 必须绝对路径（`is_absolute()`）；② 逐组件无 ParentDir（`components()` 含 `Component::ParentDir` 即拒绝）；③ 不在 trash 根内（`path_is_within` 拒绝——顺带修复 ML6：`path_is_within` 比较改为统一分隔符 + Windows 小写归一，对齐 `watch.rs normalize_for_compare` 同款，见第 4 点）；
2. **restore / restore_force 入口接入**：`read_meta` 之后、任何移动/复制/删除动作之前调用校验（:301-306、:325、:334-348 全部覆盖）；
3. **nil-content 分支双条件确认**（:326-333）：`remove_all(original, false)` 前置条件收紧为「`!meta.original_existed` **且** `entry_dir.join(PAYLOAD_DIR)` 不存在」（payload 意外存在即拒绝删除）；
4. **write_meta 原子写**（:416）：`fs::write` 改「同目录临时文件 `meta.json.agent-tmp` + rename」（对齐 replace.rs `atomic_write` 先例），防崩溃半写登记；
5. **顺带闭环 ML6**：`path_is_within`（:542-552）从「大小写敏感前缀比较」改为「统一分隔符 + Windows 小写归一」比较（对齐 agent-tools `normalize_for_compare` mod.rs:414-425 口径），并更新注释口径（消除「注释声明与实现矛盾」）。

**风险**：

- 兼容性：旧登记数据若含相对 original_path，恢复会被拒绝——写入侧恒写绝对路径（`abs_clean` :158/:217 保证），影响面收敛为历史异常数据，任务卡文档化「拒绝即提示重建条目」；
- `path_is_within` 归一化改动影响 trash_file/snapshot 的「trash 根内拒绝」守卫（既有测试 :719、:887、:900）——需全量回归；
- 校验函数复用 `path_is_within` 时注意其「守卫非攻击边界」定位（trash 根内目标被拒绝的语义）。

**验收标准**：

1. 手改 meta.json：original_path 为 `..\..\victim.txt`（相对 + 穿越）→ restore 与 restore_force 均拒绝，victim 文件不被触碰；
2. 手改 meta.json：original_path 为 trash 根内路径 → 拒绝；
3. nil-content 条目 payload 目录意外存在 → restore_force 拒绝删除；
4. 正常链路全回归：`trash_list_restore_roundtrip`（:624）、`snapshot_restore_force_overwrites`（:850）、`snapshot_nil_content_restore_force_deletes`（:866）、`tampered_payload_rejected_on_restore`（:665）等既有用例保持；
5. write_meta 原子写后无 `meta.json.agent-tmp` 残留。

**测试锚点**：

- `trash.rs` tests：新增 `restore_rejects_traversal_original_path`、`restore_rejects_original_path_inside_trash_root`、`restore_force_nil_content_requires_absent_payload`、`path_is_within_case_and_separator_normalized`（ML6：`c:\trash\a` vs `C:\TRASH`、`C:/trash/a` 斜杠变体）；
- 既有 trash 测试面全量保持。
