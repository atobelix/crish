## 三、任务卡详情

### DD3-T1 multi_replace 编码护栏（A1-H1，裁决 D4 fail-closed）

**文件域 / 根因**：`crates/agent-tools/src/tools/mod.rs`（`DecodedText` :335-341、`decode_text` :346-385、`decode_utf16` :388-400）+ `crates/agent-tools/src/tools/replace.rs`（步骤 4 解码段 :105-115、落盘 :163-167）。根因：`replace.rs:109` 调用 `decode_text`，其无 BOM 分支 `mod.rs:380` 无条件 `String::from_utf8_lossy`——GBK/latin1 等无 NUL 的 legacy 编码文件被替换为 U+FFFD 后，写回 `replace.rs:165-167` 按 BOM 探测以 utf-8 落盘，**原字节被静默改写**。`mod.rs:371` 的 NUL 判定（二进制分支）仅捕获含 `\x00` 的文件，GBK 文本（高位字节 0x80~0xFF）完整绕过。`fs.rs:108`（read_file 只读调用点）**不改行为**。

**函数级改动点（详细设计）**：

1. **非 UTF-8 探测（不猜编码）**：UTF-8 为自校验编码，判定核心 =「严格解码失败即标记」，**不做 GBK/latin1 具体识别**（fail-closed 只需知道「不是 UTF-8」；GBK 双字节 `0x81~0xFE` 引导 vs latin1 单字节 `0x80~0xFF` 的差异不构成判定输入——任何非 UTF-8 字节序列统一拒绝，避免编码猜测误判合法 UTF-8）。BOM 探测先于 NUL 检查的顺序（`mod.rs:345` 注释）保持不动。
2. **`DecodedText` 新增字段**（:335-341）：`pub lossy_replaced: bool`（语义：解码过程是否注入 U+FFFD 替换字符）。
3. **`decode_text` 四分支严格化**（:346-385）：
   - utf-16le/be 分支（:347-361）：`decode_utf16` 内部先 `String::from_utf16` 严格尝试，失败（孤立代理项）回退 `from_utf16_lossy` 并置 `lossy_replaced = true`；成功则 `false`。构造点仅本函数两处（:349/:357），改签名为返回 `(String, bool)` 或内部记标记均可，**无外部波及**；
   - utf-8-bom 分支（:363-369）：`std::str::from_utf8(&bytes[3..])` 失败 → 走 lossy 且置标记（BOM 剥离逻辑不变）；
   - 二进制分支（:371-378）：`lossy_replaced = false`（该路径本身即拒绝）；
   - utf-8 无 BOM 分支（:379-384）：`std::str::from_utf8(bytes)` 失败 → lossy 解码 + 置标记。
4. **`replace.rs` 步骤 4 追加拒绝**（:115 之后、步骤 5 EOL 归一之前）：`if decoded.lossy_replaced { return Err(...) }`——置于 `is_binary` 拒绝之后，两错误语义不重叠（二进制分支标记恒 false）。错误文案（`ToolError::execution_failed`，对齐「二进制文件无法做文本替换」风格，含引导关键词）：`"{display}: 文件不是有效 UTF-8（疑似 GBK/latin1 等 legacy 编码），拒绝替换以防破坏原编码字节；请先将文件转码为 UTF-8 再操作"`。
5. **BOM 与 encode 侧**：`replace.rs:165-166` 复用的 `fs.rs:366/400`（resolve_write_encoding / encode_text）**零改动**——UTF-16LE/BE、UTF-8-BOM 文件严格解码通过后照常续写，护栏只拦「解码失败」，不改变编码路由。
6. **与既有 decode/encode 关系**：`decode_text` 从「无条件 lossy」升级为「严格 + 标记」；只读路径 `fs.rs:108` 保持 lossy 诚实显示（不拒不报错）；`encode_text` 不动。

**测试要求（先落锚点跑红）**：`replace.rs` tests 新增 `multi_replace_rejects_legacy_encoding`（写「中文」GBK 字节 `D6 D0 CE C4` → 执行 → 断言错误含「legacy 编码」且 `raw_bytes` 前后一致）；`mod.rs` tests 新增 `decode_text_marks_lossy_for_invalid_utf8`（GBK 样例 + UTF-16 孤立代理项样例 `D8 00` → `lossy_replaced == true`）；既有 `decode_text_detects_bom_and_binary`（mod.rs:512）与 `multi_replace_preserves_utf16le_encoding`（replace.rs:979）补/保持断言。

**验收**：① GBK 文件 multi_replace → 结构化错误 + 引导文案 + **文件字节零改动**；② UTF-16LE/BOM、UTF-8/BOM 替换照常（:979 回归）；③ read_file 对 GBK 仍可读（fs.rs 行为不变）；④ `cargo test -p agent-tools` 全绿 + `cargo check --workspace --all-targets` 零警告。

**风险与接口**：模型可见行为变化（静默破坏 → 拒绝）属预期（fail-closed，裁决 D4）；构造点集中 mod.rs:346-385，无外部破坏；GBK 正向转码（显式 `encoding` 入参）登记为后续增强（12 方案范围声明，本卡不做）。**跨批接口核对（11-T6 幂等面，批 1 已落）**：multi_replace 属 edit 类幂等域工具——11-T6（幂等 record 一致性）后「store 失败 → 重试重新执行」路径与编码护栏拒绝的交互，本卡实现时按 31 §7「T6 ↔ 12-T-PD-01」核对（编码失败不产生幂等 record；重试路径不因护栏拒绝重复副作用）。

### DD3-T2 search.rs Unicode 边界 column 安全（A1-M1）

**文件域 / 根因**：`crates/agent-tools/src/tools/search.rs`（`line_hit` 闭包 :142-151、column 计算 :179）。根因：大小写不敏感分支（:148-150）字节偏移取自 `line.to_lowercase()` 串，再对**原始行** `line[..byte_offset.min(line.len())]` 切片（:179）——Unicode 大小写折叠改变字节长度（`İ` U+0130 2B→`i̇` 3B、`ﬀ` U+FB00 3B→`ff` 2B）→ 非 char 边界切片 **panic** 或列号错位；执行链无 catch_unwind（tool_exec.rs 全域无捕获）→ panic 击穿 run task。

**函数级改动点**：① 大小写不敏感命中改为**原始行 char 级双游标换算**，拆独立纯函数 `case_insensitive_char_column(line: &str, query: &str) -> Option<usize>`（返回原始行 char 列号）：对原始行 `char_indices()` 逐字符折叠（`char.to_lowercase()`）与折叠后 query 前缀比对，原文 char 游标与折叠串字节游标同步推进，折叠 1→多字符（`İ`→`i̇`）由 `char.to_lowercase()` 迭代消费对齐；② 兜底防 panic（防御层）：column 计算改 `line.get(..byte_offset.min(line.len()))`（Option 语义），`None` 时按 `is_char_boundary` 递减回退到最近 char 边界再取前缀——未来其它偏移来源亦不 panic；③ regex 分支（:144）与大小写敏感分支（:146）天然位于原始行 char 边界，**不动**。

**测试要求**：新增 `grep_case_insensitive_unicode_length_mapping`（含 `İ`/`ﬀ` 行 + caseSensitive=false 查询 → 不 panic + column 为合法 char 列号）；新增 `grep_column_fallback_stays_on_char_boundary`（直测换算/回退辅助函数，任意字节偏移输入不 panic）；既有 `grep_finds_matches_with_line_column`（:469，column=9 断言）、`grep_regex_mode_and_case_sensitive`（:507）保持。

**验收**：① `İ` 行 + 「i̇」形态查询 → 不 panic，column 合法；② `ﬀ` 行（3 字节→折叠 2 字节）→ 不 panic，column 正确；③ ASCII 命中用例 column 数值不变；④ `cargo test -p agent-tools`（search 域）+ `cargo check --workspace --all-targets` 零警告。

**风险与接口**：列号数值对非 ASCII 折叠字符为行为修正（正确 char 列）非回归，ASCII 面不变；不引入 catch_unwind（计算面根治，符合「防护在源头」风格）；批 3 与 DD3-T7（error.rs）文件互斥。

### DD3-T3 Windows 路径语义（A2-M1 + 顺带 ML3）

**文件域 / 根因**：`crates/conex-sandbox/src/semantics.rs`（`split_command_args` :201-256、`extract_delete_targets` :296-343）。根因：:215-218 无条件 `c == '\\' && quote != Some('\'') → escaped`（吞下一字符）——`rm C:\temp\a.txt` 拆参后变 `C:tempa.txt`，而盘符分支 :332 对损坏串仍命中 → 删除目标失真（影响面评估与审计 targets 系统性错误）；ML3 顺带：:335 `/` 开头分支把 `/s` `/q` `/f` 误收为 targets（`rd /s /q C:\x` 污染）。

**文件域 / 根因**：`crates/conex-fs/src/impact.rs`（`walk_dir` :58-84，**根因 :67**）+ `crates/conex-fs/src/trash.rs`（`dir_size` :475-486，**根因 :482**）。根因：`walk_dir` 用 `entry.metadata()`（跟随符号链接）+ `meta.is_dir()` 判真 → 目录内 symlink/junction 指向祖先 → 无限递归**栈溢出**；模块头 :5-6 承诺「遍历一律使用不跟随符号链接的 symlink_metadata」未兑现（顶层目标 :24 正确、递归层 :67 违背）；trash.rs:482 `dir_size` 同根（trash_file 对目录计大小触发）；既有测试 `symlink_cycle_does_not_hang`（impact.rs:191-203）只覆盖顶层 symlink（:197）且 Windows 跳过（:202）。

**函数级改动点**：① `impact.rs walk_dir`：:67 `entry.metadata()` → `entry.symlink_metadata()`；:71 `meta.is_dir()` → `meta.file_type().is_dir()`；新增 symlink 分支（`meta.file_type().is_symlink()`，Windows junction 由 Rust 按 `FILE_ATTRIBUTE_REPARSE_POINT` 判定同样命中）：**按单条目计（count += 1，size 取 `symlink_metadata().len()` 即链接自身大小），不递归**；② `trash.rs dir_size`：:479 `entry.file_type()?.is_dir()` 判定（`DirEntry::file_type` 不跟随目标）后，非目录分支 :482 `entry.metadata()` → `entry.symlink_metadata()`；symlink/junction 恒不递归；③ 两文件统一「symlink_metadata + file_type().is_dir()」单一元数据入口（消除 metadata / file_type 混用面）。

**Windows mklink 测试可行性**：`cmd /c mklink /J <link> <target>` 建目录 junction **普通用户可建、无需管理员**（区别于 symlink 需 SeCreateSymbolicLinkPrivilege），可行性成立；但 CI/容器环境可能无 cmd 或目录权限受限 → 沿用既有 skip 模式（impact.rs:202 注释先例：失败即 skip，本地 Windows 真机必跑）。改动本身无平台分支，静态可信不依赖测试机可用性。

**测试要求**：`impact.rs` tests 扩展 `symlink_cycle_does_not_hang`——新增目录内 `sub/loop → 祖先` junction 场景（Windows 分支 `Command::new("cmd").args(["/c","mklink","/J",...])`，失败 skip），断言 `assess` 正常返回、file_count 有限；`trash.rs` tests 新增 `dir_size_does_not_follow_junction_cycle`（目录含 junction 环 → dir_size 返回有限值）。

**验收**：① 目录内 `sub/loop` junction 指向祖先 → `assess` 不栈溢出不挂，环内条目计 1；② `trash_file` 含 junction 环目录 → `dir_size` 正常；③ 顶层 symlink 行为保持（:191 既有用例不回归）；④ `cargo test -p conex-fs`（impact + trash 域）+ `cargo check --workspace --all-targets` 零警告。

**风险与接口**：行为正确化（symlink 目录从递归统计目标内容 → 计 1 条链接，评估数字变小，验收明确口径）；与 DD3-T6 同文件（trash.rs），00 §6.2 要求批 4 内 05→06 串行（同 agent 合并）；impact.rs 消费方（delete.rs / audit.rs / core_run_commands.rs，A2 §3 正面确认 5）无签名变更。
