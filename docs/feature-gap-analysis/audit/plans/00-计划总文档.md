## 2. 执行纪律（执行子 Agent 必须遵守）

1. **文档依据边界**：只读本文件 + 自己任务的对应分维度方案（10~15 之一）；不得读审计原始报告/方案草稿/其他维度方案全文。执行中发现任务书未覆盖问题 → 上报主 Agent 裁决，不擅自扩范围。
2. **编码铁律**：所有写入文件 UTF-8 无 BOM；**禁止用 PowerShell 默认编码写文件**（Set-Content/Out-File 默认 GBK，B-21/B-39 教训）；写盘后回读校验中文正常（`check_chinese_text.py` 自查无告警）。
3. **只改自己域**：严格遵守所在方案的「文件冲突矩阵」（10 §九 / 12 §五 / 15 §二）；同文件多卡必须按本文件 §6.2 硬串行序列执行；轮次报告声明文件所有权；跨域改动必须登记上报，不得顺手改其他任务卡文件。
4. **测试先行**：每卡先落测试锚点（引用方案文档行号）→ 跑红 → 实现改动 → 转绿；禁止「改实现后补测试」。端到端卡（批 3 装配轮）必须先有 E2E 断言骨架。
5. **测试可信标准**（判定「可信」须同时满足）：
   - 真实执行：被测路径用真实实现（真实子进程/SQLite/watcher/引擎执行器），替身只允许在出站边界记录调用（MockGate、RecordingSpawner 型）；
   - 断言具体值：字段级/字节级/DOM 属性级断言，拒绝空断言与「断言自身实现」（验证桩自身）；
   - 不 mock 被测逻辑：sched/timers 测试落点用真实 `PendingMessageQueue`，禁止自实现探针桩；
   - 不用固定 sleep：timers 注入时钟 + 轮询收口（对齐 watchdog 先例）；
   - 不静默降级：工具/注册表未装配时测试必须 fail，不得走模拟分支兜底全绿。
6. **提交纪律**：**不要 commit**（主调度统一提交，每任务卡一个独立提交）；**不改 Cargo.toml**（除非任务卡明确——本战役无卡改 Cargo.toml，15-T-4 改的是根 package.json）。
7. **完成判据**（每卡收口自检）：`cargo check --workspace --all-targets` 零警告（含 test 构建）→ 接线卡同时完成「移除对应 allow(dead_code)」→ 相关测试全绿 → 与任务卡验收标准逐条核对。
8. **汇报格式**（三态：完成 / 受阻 / 需裁决）：
   ```
   进度检查结论：…
   完成情况：…（对照任务卡验收标准逐条）
   测试摘要：新增 N 条 / 回归 M 条 / 断言锚点（文件:行号）
   偏差：…（与方案的任何偏离，含文件所有权冲突）
   遗留：…（邻接登记项）
   ```
9. **只读子 Agent 红线**：探索/评审类不写文档（配额红线）；方案阶段已结束，本战役执行子 Agent 均为实现类。
