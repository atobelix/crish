### 2.3 统一测试验收标准（什么算「测试可信」）

判定一条测试「可信」，须**同时**满足：

1. **真实执行**：被测路径用真实实现（真实子进程/SQLite/watcher/引擎执行器），替身只允许在「出站边界」记录调用（MockGate、RecordingSpawner 型），不允许替身参与被测逻辑；
2. **断言强度**：字段级/字节级/DOM 属性级断言（如 raw_bytes 字节一致、enqueued 载荷字段、data-node-id 拓扑），拒绝「空断言刷绿」与「断言自身实现」（验证桩自身）；
3. **无静默降级分支**：工具/注册表未装配时测试必须 fail，不得走模拟分支兜底全绿；
4. **无时序脆弱**：不依赖固定 sleep 精确计数（注入时钟/轮询化）；平台差异用显式注释 + skip 边界（mklink 可用性），不隐瞒降级；
5. **门禁可复现**：`cargo test --workspace`（73 套件基线）不回归；前端 `npm run typecheck` + `npx vitest run src` 基线失败集（oklchColorGuard / userFacingErrors / sessionRustDbWriteModel / DiffCard.perf）**不新增**；`check-clippy-baseline.mjs` 新增告警 0。

> 说明：基线失败集四项为既有已知失败，本战役验收口径是「不新增、不扩大」，修复它们属并行域/既有债范畴，不在本战役范围（诚实边界，见 §六）。
