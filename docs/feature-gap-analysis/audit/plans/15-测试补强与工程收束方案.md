### T-3：timers 注入测试时钟（A9 P1-3）

**涉及文件**：`apps/agent-workbench/src-tauri/src/timers.rs`、`apps/agent-workbench/src-tauri/src/engine.rs:688-692`

**改动点**：
1. **注入时钟**（对齐 watchdog.rs:331-341 `test_clock` 模式）：`TimerRegistry` 增字段 `now: Arc<dyn Fn() -> u64 + Send + Sync>`，生产默认 `now_ms`（timers.rs:55）；`register`（:348 时间基准）、`cancel`（:406）、`restore`（:439）、`fire_timer`（:653）全部走注入时钟；
2. **到期任务改轮询**：`spawn_fire_task`（:600-608）由单次 `sleep_until(Instant::now() + sleep)` 改为「10ms 粒度循环：`now() >= expires_at` 即 fire，cancel 靠既有 abort」——统一生产/测试一条路径，消除「注入时钟与 Instant 真实时钟混用」问题；
3. **测试构造**：`test_registry()`（:789-804）注入 `Arc<AtomicU64>` 时钟（同 watchdog），新增 `#[cfg(test)] with_clock` 构造器（或测试面直接构造，engine.rs 生产装配点 :688 用默认时钟不变——若签名必须扩展则同步改 :688-692，与 T-5 串行）；
4. **消除 8 处真实 sleep**（:844/886/943/1051/1072/1088/1165 各 1200ms + :961 100ms）：测试改为「冻结时钟注册 → 推进时钟越过到期点 → 轮询收口断言」；「应恰好注入一条」（:846）等精确计数因时钟冻结而确定成立；
5. **顺带拆 P2 析取断言**（A9 清单 P2 首项）：`timer_registry_persists_and_recovers`（:948-951）的 `!a.is_empty() || !b.is_empty()` 析取 → 阶段 A 注册后先断言未到期不发射、阶段 B 单侧断言发射方；
6. timers 测试区的 `ProbePending`（timers.rs:760-774）**一并换真实 `PendingMessageQueue`**（timers.rs:44 已依赖 orchestrator，同 T-2 模式）——消除同源镜像，`assert_early_exit_notice`（:807-816）适配 queue 快照。

**风险**：中。
- **生产行为变更**：sleep_until 精确到期 → 10ms 粒度轮询。定时器最小注册时长 1s（:326 校验），10ms 抖动在语义等价范围；cancel 路径不变（abort）。须引擎级回归确认（engine.rs:3381/3418 已有「注册定时器到期 → 队列出现条目」测试覆盖生产路径）；
- **轮询任务泄漏**：测试中任务若未到点（时钟未推进）而测试结束，JoinHandle 随 registry drop——现有 abort 语义已覆盖，测试收口加轮询护栏（上限 ~50×10ms）；
- **restore 路径**（:438-497）的 remaining 计算走注入时钟，测试共享时钟下「重启恢复」用例（:911-970）行为保持。

**验收标准**：9 个 timers 测试全绿且套件纯等待时间从 ~8.5s 降至 <1s；生产注册/取消/恢复语义不变（引擎级测试回归）；P2 析取断言拆分完成。

**测试锚点**：timers.rs 9 测试（:834-1180）；engine.rs:3381/3418（真实 PendingMessageQueue 落点）；A9 抽样 10（watchdog 注入时钟零 sleep 为对照标杆）。

**改动点**（方案 A——推荐，路由型引擎级 sink）：
1. 新增 `RoutingAuditSink`（engine.rs 或独立小模块）：持有 `Mutex<HashMap<session_id, AuditSink>>` 注册表 + 内部 `CountingAuditSink`（共享 `Arc<DeniedStats>`，G10 落地）；

3. CoreRunState 在 run 启动块注册 session 路由、run 收口注销（对齐 escape_watch 句柄生命周期 :2606-2627 模式）；无活动 run / 未注册时事件仍 tracing 兜底（Noop 语义不炸）；
4. **降级选项**（若路由复杂度不被接受）：维持 None + 本方案登记（A8 已列），审计链收束整体延后至 F12 端到端轮——不作为本维度验收阻断。

**风险**：中。
- 多 run 并发：同一 session 多 run 并行时按 session 路由的最后注册者分发——需在方案内约定 run 级优先级（新 run 覆盖旧 run，与事件收口旁路点口径一致）；
- 共享面冲突：`engine.rs` 与 `core_run_commands.rs` 均为高频触碰面，须在轮次报告声明所有权、与同文件任务（T-5/T-3）串行；
- sink 生命周期：run 收口后未注销的注册项必须清理（防 session 泄漏），注销失败兜底 = tracing 告警 + 条目 TTL 清理（或简化为收口强制注销）。

**验收标准**：工具删除 / 审批拒绝路径的 `security-audit` 事件经路由 sink 到达 run 事件桥（前端面板可见，信封带 run_id）；`DeniedStats` 计数随 denied 决策增长（G10 验收）；无活动 run 时事件 tracing 兜底不 panic；run 收口后注册表无残留。

**测试锚点**：agent-tools 工具层既有 `RecordingAuditSink` 断言（shell.rs:1803+ / delete.rs:465）不变；新增引擎级测试：路由分发（多 session）、denied 计数、收口注销；A8 总评 3 的「契约已定义、引擎实现一半」缺口消除。
