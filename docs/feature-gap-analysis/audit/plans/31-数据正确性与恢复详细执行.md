## DD2-T1（N04）runs 未知状态透传：显式 Unknown 变体

### 1. 文件域
- **独占**：`crates/conex-db/src/runs.rs`；`crates/orchestrator/src/restore.rs`（与 T4 同一 agent 串行内独占）；`crates/orchestrator/src/run.rs`；`packages/shared-types/src/orchestration.ts`。
- **禁碰**：`recovery.rs:652-660` 写边界保持严格（登记「写严格/读透传」对称语义）；`session.rs` / `persist.rs` 仅编译核对透传签名；`apps/agent-workbench/src-tauri` 仅编译面核对（若壳层存在 RunStatus 窄化类型需同步放宽——grep 核对点）。

### 2. 根因（证据）
- `runs.rs:363-375`：`map_run_row` 注释自称「按 Unknown 兜底」，实现为 `RunStatus::from_str(&status_str).unwrap_or(RunStatus::Failed)`（runs.rs:365）——未知字面量静默改写为 failed。
- 破坏链：`query_all_runs`（runs.rs:276-295）与 `get_run`（runs.rs:165-178）共用该映射 → 恢复全量扫描 `store.query_runs()`（restore.rs:536）把未知态 run 误判终态 failed，不打断、不收口。
- 双路径分裂：快照路径 `SnapshotRun::to_stored_run`（restore.rs:212-225）对未知字面量 fail-closed（`from_str` Err → SnapshotError 拒绝加载）；DB 行路径 fail-open 且破坏。
- 前端：`orchestration.ts:5` `RunStatus` 联合类型已窄化（连 completing 都没有），未知字面量无法表达。

### 3. 改动点（枚举变体设计 + Copy 移除机械迁移面 + TS 放宽点）

**3.1 枚举变体设计**（`runs.rs:15-44`）：

```rust
// 删除 Copy 派生（Unknown 携带 String）；as_str 返回值 &'static str → &str
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum RunStatus {
    // ...既有九态不变...
    /// 未知状态字面量（roundtrip 保真透传；不参与 FromStr 解析——
    /// 写边界保持严格，recovery.rs:652-660 语义不动）
    Unknown(String),
}
impl RunStatus {
    pub fn as_str(&self) -> &str {
        match self { /* 既有九态同前 */ RunStatus::Unknown(s) => s }
    }
}
```

- `map_run_row`（runs.rs:363-375）：`from_str` 失败分支返回 `Ok(RunStatus::Unknown(status_str))`，删除 `unwrap_or(Failed)`；`FromStr` 本身**不改**（未知仍 Err，供写边界/快照严格面使用）。
- `SnapshotRun::to_stored_run`（restore.rs:212-225）：放宽为与 DB 行路径一致——`from_str` 失败 → `RunStatus::Unknown(self.status.clone())`，不再拒绝加载（语义 fail-closed → fail-open 保真，随文档冻结，11 方案 §T1 风险已记录）。
- `is_inflight`（restore.rs:668-677）：显式列出 `RunStatus::Unknown(_) => false`（保真保留、不打断）；恢复循环（restore.rs:540-549）`_ =>` 默认臂不会命中 Unknown（is_inflight 已滤），无需改判逻辑，但 Unknown 分支追加**显式上报**：`RestoreOutcome` 新增 `unknown_status_runs: Vec<(String, String)>`（run_id + 原字面量）或至少 `tracing::warn!(target: "restore", run_id, status, "未知状态字面量保留")`——二选一由实现者取前者（可测试），上报计数写入恢复输出。
- `run.rs` 状态机：`is_terminal`（run.rs:129-134）显式排除 Unknown（不落入三终态 matches）；`transition`（run.rs:137-179）为 Unknown 增加显式臂——任何事件 → `TransitionError`（视为死态，不可迁移）。
- 写边界：`recovery.rs:652-660` 不动；`persist.rs` Store 签名透传编译核对。

**3.2 Copy 移除的机械迁移面**（编译器逐点指引，人工核对语义分支）：
1. `restore.rs:544` `let previous_status = run.status;` → `.clone()`（run 后续仍使用）；
2. `run.rs:137` `match (self.state, event)` → `match (&self.state, event)`（match ergonomics 下分支模式不变，无逐臂 clone）；
3. `run.rs:163-168` `TransitionError { from: self.state, ... }` → `from: self.state.clone()`；
4. 全仓断言面（grep `RunStatus::` 约 100+ 处，如 drive.rs/approval.rs/cancel.rs/crash_consistency.rs/restore.rs 测试区）`assert_eq!(run.status, RunStatus::X)` → 左操作数补 `.clone()` 或改 `&run.status == &RunStatus::X`；
5. `insert_run`/`update_run_status` 实参传值处：字面量构造无需改；从变量移动处（如 restore.rs:569 `db_status` 已克隆构造）按编译器指引补 clone；
6. `matches!`/`match` 判别点（is_inflight、is_terminal、restore.rs:545-549）语义分支逐点核对——重点三处：is_inflight、restore 映射、状态机转移表。

**3.3 TS 前端放宽点**（`orchestration.ts:5`）：
`export type RunStatus = "queued" | ... | "failed" | (string & {})`——string 兜底使未知字面量通过类型检查，消费面「原样显示」；并同步放宽 Rust 壳层（apps/agent-workbench）若存在的窄化映射（grep 核对）。文档冻结「未知字面量原样显示」语义。

### 2. 根因（证据）

### 3. 改动点（API 草案 + 迁移清单）

**3.1 conex-db 新 API 签名草案**（`agents.rs`，均返回 `Result<(), DbFailure>`；复用 `SessionAgent`（conex-types/src/lib.rs:189-224，17 列含 v6 三列）字段集）：

```rust
/// 单行更新 status/ended_at（kill_all 用）。只动目标行，不碰 messages。
/// 缺行静默成功（affected=0，不报错——与 save 面宽容语义一致）。
/// ended_at 语义：仅当原值为 NULL 才写入（SQL: ended_at = COALESCE(ended_at, ?4)），

/// 单行更新 subagent_path_json（set_subagent_path 用）。
/// 缺行静默成功；调用方（recovery）自行按 affected 判定 NotFound。
pub fn update_session_agent_path(
    &self, session_id: &str, subagent_run_id: &str, path_json: &str,

/// 单行 upsert（spawn 落库用）。全 17 列 INSERT ... ON CONFLICT(session_id, agent_id)
/// DO UPDATE SET（v6 三列随行）。
/// 关键：禁止 INSERT OR REPLACE——REPLACE 语义 = DELETE+INSERT，PK 冲突会删除
/// 旧行并触发 session_agent_messages 的 FK 级联清空该 agent 全部消息；
/// ON CONFLICT DO UPDATE 保留旧行与 messages。
pub fn upsert_session_agent(&self, row: &SessionAgent) -> Result<(), DbFailure>;
```

设计要点：①update_* 与 upsert 的字段集与 `save_session_agents`（:177-201 列清单）严格一致（v6 三列 task_type/display_label/allowed_write_paths_json 随行）；②单行 API 两两交错互不覆盖（不同行不同 key），竞态收敛为「同属性最后写赢」；③`lib.rs` 公开导出核对（SessionAgent 类型在 conex-types，pub 面扩展）；④`map_agent_row` 字段映射双向核对。

## DD2-T5（N12）flow parallel 串行约束（裁决 D2 已冻结）

### 1. 文件域
- **独占**：`crates/orchestrator/src/flow_graph.rs`；`crates/orchestrator/tests/flow_scheduler.rs`。**禁碰**：其余 orchestrator 文件（恢复/调度域其他卡）。

### 2. 根因（证据）
- `FlowNode.parallel`（flow_graph.rs:101-104）声明语义「false = 与同级串行，声明序为串行顺序」；
- `is_ready`（flow_graph.rs:1459-1471）只按 depends_on 判定；`advance` 就绪集合（:951-956）只过滤依赖 → parallel=false 与 parallel=true 行为无差别；
- 全仓引用仅测试（flow_graph.rs:1702 序列化往返）与文档；生产零调用点（A3 N30，declare_flow/load/reset_flow/on_subagent_terminal 均未接线）——接线战役（A-02）前完成成本最低。

### 3. 语义说明（裁决 D2 冻结：「同级」= 同 depends_on 集合）
- 同级 = depends_on 集合相同的节点（同一波次同时就绪）；parallel=false 的节点须等待「同 depends_on 集合、声明序在前、且同样 parallel=false」的节点全部进入**终态**后才就绪；parallel=true 节点不受约束（显式声明并发）；不同波次节点不受影响。
- 前置同级节点判定放宽：Failed/Skip/Report 生效策略视为满足（与 is_ready 依赖判定同口径，flow_graph.rs:1463-1470）；Failed/Block 由既有 `propagate_block`（:1476-1499）把本节点置 Blocked（终态），is_ready 无需再挡。

### 4. 改动点（实现位置：flow_graph.rs 调度判定）
1. `is_ready`（:1459-1471）增加同级串行检查——新增私有 helper：
```rust
/// 同波次串行前置检查：声明序在前、同 depends_on 集合、parallel=false、
/// 且状态非终态（Failed 按生效策略放宽）的同级节点存在 → 尚未就绪
fn serial_predecessor_pending(&self, graph: &FlowGraph, node: &FlowNode) -> bool {
    if node.parallel { return false; }
    graph.nodes().iter()
        .take_while(|n| n.id != node.id)            // 声明序在前（graph.nodes() 即声明序）
        .any(|n| n.depends_on == node.depends_on
             && !n.parallel
             && !self.serial_predecessor_satisfied(n))
}
// serial_predecessor_satisfied：Completed/Blocked/Cancelled → true；
// Failed → 生效策略 Skip/Report 为 true、Block 为 false；其余非终态 → false
```
2. `is_ready` 就绪判定追加 `&& !self.serial_predecessor_pending(&graph, node)`（graph 由调用方传入或经 self.graph 取，签名对齐 :1459 既有形态）；
3. `advance`（:930-1122）**无需结构性改动**：就绪集合每轮重算（:951-956）+ 终态事件驱动重推进（on_subagent_terminal → advance，flow_graph.rs:1121）满足「前一同级完成后第二节点才启动」的事件驱动语义——不轮询、预算不足只延迟不死锁（ready_ids 为空 → break，:957-958）；
4. `FlowNode.parallel` 文档注释（:101-104）补充「同级 = 同 depends_on 集合」精确语义；模块头（:49）行为描述与实现对齐。
- 复杂度：同波次判定 O(同波次数²)，任务数 >20 才建独立表（Q3 裁决），当前规模无性能风险。

### 5. 测试要求
| 测试 | 断言要点 | 可信标准 |
| :--- | :--- | :--- |
| flow_scheduler.rs 新增 `serial_siblings_start_in_declaration_order`：声明两个同波次（同 depends_on=[]）parallel=false 节点 → 第一个 spawn 后第二个仍 Pending → 注入第一个 Completed 终态事件 → 第二个 Running | RecordingSpawner 记录 spawn 时序（spawn1 先、spawn2 在 terminal 事件后） | 真实 FlowScheduler + RecordingSpawner 型出站桩（记录调用，不 mock 被测逻辑） |
