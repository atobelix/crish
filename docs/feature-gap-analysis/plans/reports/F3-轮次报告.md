## 三、新发现

1. **（主调度，重大）notifier_message_and_payload_shape 挂起根因**：测试代码 `let q = queue.lock()` 守卫为**函数级作用域**（非块级），`notify_failed` 再次 `queue.lock()` → **同线程 Mutex 重入死锁**（Windows SRWLOCK 死锁而非 panic）。修复：全部锁断言收进块作用域。此挂起曾伪装为"环境问题"（并行下随机、串行稳定、单测必挂），实际是测试代码 bug；期间 cargo fingerprint 与僵尸测试进程（超时杀 cargo 不杀测试子进程，PID 43532 锁定 exe 导致 LNK1104）加剧了排查难度。
2. **（C1）nudge 通道诚实边界**：PendingNudgeChannel 实例在 orchestrator 的 PendingMessageQueue 内部，壳层无访问入口 → 生产路径 None（通知文本经 tracing 留痕），测试注入内存队列断言；T-AB-18 的 steering 注入承担真实通道。
3. **（C1）daemon_job_handle 登记**：daemon Job 句柄原封装在模块私有 static，资源采样无法获取——新增纯只读 getter（不改行为不触生命周期）。
4. **（C2）事件契约零扩展裁决**：security-audit 载荷不动（扩展会波及 agent-tools/session-loop/壳层 7+ 构造点），TaskAuditRecord 独立记录后经 EventQueue 逐条推 security-audit。
5. **（C2）normalize.rs 七 arm 落位**：event_session_id_mut 任务域七 arm 由 C1 验证补丁正式落位。
6. **（C3）前端镜像欠账**：trash_list/purge/restore 3 条 Rust 侧已注册但前端未镜像（并行 trash 域在途）；本次仅同步 workbench_send_input（75/79）。
7. **（C5）clamp_text 去留裁决**：全仓无其他调用方（改造前仅 read_file 使用）——以 #[allow(dead_code)] 保留，后续轮次可接管或删除。
8. **（C5）contentOffset 与 endLine 缺省联动**：实现为 endLine 缺省 = max(startLine-1, contentOffset) + maxLines，无 contentOffset 时与契约一致。
9. **（主调度）并行域编码污染**：process.rs 首行曾被写入 UTF-8 BOM（已清理）；此前 core_run_commands.rs 曾 317 行 GBK 乱码——并行域写入工具链编码风险持续存在。
10. **（主调度）cargo fingerprint 污染**：并发 cargo 进程可产生错误 fingerprint 状态（复用旧二进制、跳过源码变更）；排查期强制 touch 源码触发重编译解决。target 曾因 cargo clean -p 误清 18.1GB（全仓冷构建一次），后续轮次避免再 clean。
11. **（C6）glob_match 顶层目录语义**：`**/generated/*.rs` 不匹配顶层 generated/gen.rs（**/ 需后跟 /）——排除顶层需 `generated/**` 或 `**/generated/**`；测试按嵌套结构构造。
