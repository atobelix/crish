## 三、新发现

1. **（A1）Windows PowerShell 5.1 stderr CLIXML 噪音**：首启 stderr 混入「正在准备首次使用模块」progress 记录；改造前后行为一致，非流式化回归；同步语义测试 stderr 断言改用包含式。
2. **（A1）adopt 失败孤儿风险**：kill_on_drop(false) 下 adopt 返回 Err 时 Child 已移入失败调用、无法回收，进程残留；建议 A3 注册表 adopt 失败路径自行 reap 兜底（F2 T-AB-11 承接）。
3. **（A1）BufReader 缓冲丢失规避**：into_inner 会丢弃缓冲内未消费字节——流式循环采用 fill_buf/consume 全量消费，adopt 移交零数据丢失。
4. **（A1）Unix 树杀仍只杀 shell 进程**（kill -TERM 单进程，taskkill /T 是 Windows 专属）——既有限制，F2 两阶段终止时建议升级。
5. **（A2）powershell -Command "cd x" 走间接执行分支整体为 Indirect 而非 CdShape**——与既有「内层删除→Indirect+标记」同构；任务书只要求段首形态，如需内层 cd 标记建议另加 has_indirect_cd 字段（未动结构）。
6. **（A3）Windows taskkill 无 /F 返回码不稳定**：实测有时 Err「只能通过强制终止」、有时 Ok 但进程树仍存活；graceful_terminate_ok 断言按两阶段语义修正（最终 5s 内必退），不纠结返回码。
7. **（A3）宿主 Job 包裹不阻断 daemon Job 接线**：Win8+ 嵌套 Job 下 AssignProcessToJobObject 实测成功；接线保持 best-effort 降级。
8. **（A4）notify Windows 语义实测**：Windows 上 rename = Modify(Name(From))+Modify(Name(To)) 两事件；创建文件可产出 Create+Modify 两条；排除过滤需覆盖全部发射分支（初版只过滤 Create/Remove 导致排除测试失败，已修）。
9. **（A4）flush 设计补充**：被动 flush 在「删除后无后续事件」场景永远不转正（实测失败）——改为独立 flush 线程（WeakSender 生命周期自动退出）+ stop() 兜底 flush 剩余。
10. **（A4）tokio 1.52 `Sender::close` 是 Receiver 方法**：方案设想的 stop 关通道不可行，stop 语义改为 unwatch + flush 剩余。
11. **（A4）`contracts/engine-events.json` 未被 git 跟踪**：`.gitignore:155` 的 `*.json` 规则长期忽略它；本次 force-add 入库（注册表真实改动），建议后续评审 ignore 规则（仓库级决策）。
12. **（主调度）并行缓存优化域与前端 markdown 域有大量未提交改动**：core_run_commands.rs 194 行（附件 LFI/sanitize）、crish-desktop 全系、ChatComposer/SlashExtension/@tiptap（package.json 已加依赖但未 npm install 导致 typecheck 报模块缺失）。F1 未触碰；typecheck 基线被并行域改动污染（非 F1 回归）。
13. **（主调度）测试竞态**：全量并行跑时 graceful_terminate_ok 与 sanitize_user_prompt 偶发失败、单独跑通过——并行域实时改文件与测试并行执行的瞬时竞态；已修正断言提升稳健性。
