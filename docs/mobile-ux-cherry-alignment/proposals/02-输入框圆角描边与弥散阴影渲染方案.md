## 一、现场事实与核心病灶深度复盘

### 1.1 用户真实反馈
用户在真机（如华为 P40 Pro / 鸿蒙系统，DPR $\approx 2.75 \sim 3.0$）实测时反馈：
> “输入框旁边的阴影有点问题。你看看这个输入框的圆角是和圆一样的圆角吗？反正看着弥散的效果没有，以及这个描边也是各个方向不均匀。”

这三句反馈一针见血地指出了当前移动端底栏 Composer 在**几何拓扑**、**光栅化着色**与**光学衰减模型**上的三大工程与数学断层：
1. **圆角不似正圆**：单行输入框两端并非浑然天成的正半圆胶囊，而是呈现受挤压的椭圆钝切角或非对称侧向突起。
2. **描边四向不均**：四周 1px 细线在上下左右呈现不同粗细、浓淡甚至局部断续，上沿与左沿偏淡偏细，下沿与右沿偏重偏粗。
3. **弥散质感缺失**：阴影无法形成柔和扩散的空气感漫反射微气垫，肉眼看去仅是一道紧贴边框的狭窄暗灰硬边，超出 10px 范围后完全断崖式消失，毫无高级漫射光晕。

## 二、第一病灶：圆角几何断层与数学推导

### 2.1 物理事实：单行高度与胶囊几何约束
在 `theme.ts` 中当前配置为：
- `size.composerMin = 52`（即单行卡片容器基准物理高度 $H = 52\text{dp}$）；
- `radius.composer = 30`（此前因用户反馈“半径大一点”被简单调整为 30）。

#### 物理胶囊（Stadium / Capsule）的几何充要条件
设任意矩形的高为 $H$、宽为 $W$（通常 $W \gg H$，移动端常见 $W \approx 320\text{dp} \sim 390\text{dp}$）：
一个封闭图形两端要构成**标准正半圆圆弧**（Circular Semicircle），其端点曲率半径 $R$ 必须且只能满足：
$$R_{\text{capsule}} = \frac{H}{2} = \frac{52}{2} = 26.0\text{dp}$$
此时两端圆弧为半径 $26\text{dp}$ 的 180° 正圆弧，曲率 $\kappa$ 恒定为：
$$\kappa = \frac{1}{R} = \frac{1}{26} \approx 0.03846\text{dp}^{-1}$$
其切线在上下水平边缘处无缝相切，具有严格的一阶导数连续性（$C^1$）与曲率连续性（$G^1$）。

### 2.2 设定 $R = 30\text{dp}$ 时两套渲染引擎的数学分裂

当将 `radius.composer = 30` 同时传给 Android 原生 `View` 与 SVG `<rect>` 时，触发了灾难性的双轨裁切冲突：

#### (1) SVG 规范下的椭圆畸变（W3C SVG 1.1 / 2.0 §9.4）
在 `SoftShadow.tsx` 中，投影轮廓由 `<SvgRect rx={borderRadius} ry={borderRadius} width={W} height={H} />` 绘制。SVG 规范对超规圆角强制执行**独立轴向钳位**：
$$r_x' = \min\left(rx, \frac{W}{2}\right) = \min(30, 175) = 30\text{dp}$$
$$r_y' = \min\left(ry, \frac{H}{2}\right) = \min\left(30, \frac{52}{2}\right) = \min(30, 26) = 26\text{dp}$$
因为 $r_x' \ne r_y'$（$30 \ne 26$），SVG 绘制的角**根本不是圆弧，而是椭圆象限弧（Elliptic Arc）**！  
其参数方程为：
$$x(\theta) = 30 \cos\theta, \quad y(\theta) = 26 \sin\theta \quad (\theta \in [0, \pi/2])$$
计算该椭圆在各连接点处的曲率半径 $R_{\text{eff}} = 1 / \kappa$：
- **与顶/底水平边连接点**（$\theta = \pi/2$）：
  $$\kappa_{\text{top}} = \frac{a}{b^2} = \frac{30}{26^2} = \frac{30}{676} \approx 0.04438 \implies R_{\text{eff}} \approx 22.53\text{dp}$$
- **与左右侧垂直边连接点**（$\theta = 0$）：
  $$\kappa_{\text{side}} = \frac{b}{a^2} = \frac{26}{30^2} = \frac{26}{900} \approx 0.02889 \implies R_{\text{eff}} \approx 34.62\text{dp}$$

**畸变后果**：端头在水平向平缓而在转折角处陡峭，比正圆在左右两侧各多凸出了 $30 - 26 = 4\text{dp}$ 的椭圆突起。

#### (2) Android 原生 View 的等比缩放裁切（CSS Backgrounds & Borders Level 3 §5.5）
Android 原生 `ReactViewBackgroundDrawable`（Skia `SkRRect`）遵循 CSS 规范，当相邻圆角之和大于边长时（$30 + 30 = 60 > 52$），执行**全局统一缩放因子**：
$$f = \min\left(1, \frac{W}{r_{tl} + r_{tr}}, \frac{H}{r_{tl} + r_{bl}}\right) = \min\left(1, \frac{W}{60}, \frac{52}{60}\right) = \frac{52}{60} \approx 0.86667$$
$$r_x = 30 \times \frac{52}{60} = 26\text{dp}, \quad r_y = 30 \times \frac{52}{60} = 26\text{dp}$$
Android View 的背景被缩放回了 $R = 26\text{dp}$ 的正圆！

#### (3) 物理轮廓与阴影轮廓脱节
| 构件 | 渲染载体 | 水平半轴 $r_x$ | 垂直半轴 $r_y$ | 几何形态 |
|:---|:---|:---:|:---:|:---|
| **实体输入框** | Android View | $26.0\text{dp}$ | $26.0\text{dp}$ | 正圆弧胶囊 |
| **底层阴影轮廓** | SVG `<rect>` | $\mathbf{30.0\text{dp}}$ | $\mathbf{26.0\text{dp}}$ | **椭圆弧畸变** |
| **几何偏差** | $\Delta = \text{SVG} - \text{View}$ | **$+4.0\text{dp}$** | **$0.0\text{dp}$** | **左右两侧各溢出 4dp 阴影鼓包** |

这使得用户肉眼看到：**输入框本身的白底虽然被系统压回了 26px，但底下的阴影却是一个 30px×26px 的椭圆，在左右两侧形成了明显的暗影鼓包，直接暴露出几何断层！**

### 2.3 动态扩高模式（$H = 98\text{dp} \sim 120\text{dp}$）下的曲率平滑连续性

当输入框注入 `model` 成为两行形态，或用户多行输入扩高至 $H = 98\text{dp}$ 时：
- 高度变为 98dp，此时 $\frac{H}{2} = 49\text{dp} > 30\text{dp}$。
- 若维持固定圆角，此时 $R=26\text{dp}$ 与 $R=30\text{dp}$ 都小于 $H/2$，不再触发任何轴向截断，均表现为正规圆角矩形。
- **原型基准对照**：检查 `reference/crish-mobile-drawer/css/variables.css` 第 47 行与 `composer.css` 第 50-69 行：
  ```css
  --radius-composer: 26px; /* 输入框无论单行(52px)还是双行(98px)，圆角严格锁定 26px */
  ```
  原型明确定案：`--radius-composer: 26px` 是不可动摇的单一真源（SSOT）。
  - 单行 $H=52\text{dp}$ 时：$R=26\text{dp}$ 精确是 $H/2$ 完美胶囊。
  - 双行 $H=98\text{dp}$ 时：$R=26\text{dp}$ 保持四角曲率半径绝对不变，动画展开期间四角形状完全不发生形变跳变（$C^1$ 视觉恒定）。

#### 自适应平滑连续曲率算法（Dynamic Capsule Clamp Formula）
为彻底防御任何未来高度微调导致圆角溢出，确立统一的几何自适应函数：
$$R_{\text{render}}(H) = \min\left(R_{\text{token}}, \left\lfloor \frac{H}{2} \right\rfloor\right)$$
- 当 $H = 52\text{dp}$ 且 $R_{\text{token}} = 26\text{dp}$ 时：$R_{\text{render}} = 26\text{dp}$（严格正圆）；
- 当外部误传入 $R_{\text{token}} = 30\text{dp}$ 时：$R_{\text{render}} = \min(30, 26) = 26\text{dp}$，从架构层拦截椭圆断层；
- 在 iOS 平台上显式补充 `borderCurve: 'continuous'`（苹果 Squircle 平滑连续超椭圆算法），在 Android 上通过 $R_{\text{render}}$ 保持严密的各向同性圆弧。

## 三、第二病灶：描边方向不均匀根因排查

用户指出的“描边也是各个方向不均匀”，经排查属于**子像素物理栅格化相位偏差**、**极低 Alpha 量化噪声**与**SVG 绝对定位层级偏移**三重叠加所致。

### 3.1 根因 A：子像素光栅化相位漂移（Fractional DPR Phase Shift）
- 在 `Composer.tsx` 中定义：
  `borderWidth: 1`（React Native 逻辑 dp）。
- 现代高分辨率手机屏幕的 DPR 常为非整数（例如华为 P40 Pro 为 $2.75$，其余设备常见 $2.625$ 或 $3.0$）。
  $$1\text{dp} \times 2.75 = 2.75\text{ 物理像素}$$
- Android Skia 绘制 `borderWidth: 1` 时采用中心描边（Stroke Center），即路径内外各扩展 $1.375\text{px}$。
- 在屏幕网格上，$2.75\text{px}$ 无法对称地落入整数像素阵列：
  - 若输入框的绝对屏幕坐标包含小数（如 $Y = 724.3\text{px}$），上边框与下边框的光栅化覆盖率（Pixel Coverage）会产生严重相位差：
    - **上边框**：跨越 3 个物理像素，覆盖率为 $[0.375, 1.0, 1.0]$；
    - **下边框**：跨越 4 个物理像素，覆盖率为 $[0.125, 1.0, 1.0, 0.625]$。
  - 光栅化抗锯齿（Coverage Antialiasing）将覆盖率直接乘入颜色的 Alpha 通道，导致上边看起来锐利而窄，下边看起来模糊而宽。

### 3.2 根因 B：极低 Alpha（$0.025$）导致的 8-bit 量化断续
- `Composer.tsx` 第 892 行写死：
  `borderColor: theme.dark ? colors.borderStrong : 'rgba(0, 0, 0, 0.025)'`
- 计算 $2.5\%$ Alpha 在 8 位颜色通道（$0 \sim 255$）中的离散量化值：
  $$\text{Alpha}_{8\text{-bit}} = \text{round}(255 \times 0.025) = \text{round}(6.375) = 6$$
- 当抗锯齿覆盖率介入调制时：
  - 覆盖率 $80\%$ 的像素：$\text{round}(6 \times 0.8) = 5$；
  - 覆盖率 $50\%$ 的像素：$\text{round}(6 \times 0.5) = 3$；
  - 覆盖率 $30\%$ 的像素：$\text{round}(6 \times 0.3) = 2$。
- 在 Alpha 仅为 $2 \sim 6$ 的极微弱区间内，**1 个单位的量化跳跃即代表 $20\% \sim 50\%$ 的明暗跳变**！在 OLED 屏幕上，这直接表现为边框某些方向发灰、某些方向彻底透明断裂，产生肉眼极度明显的“粗细浓淡不均匀”。

### 3.3 根因 C：容器 Border-Box 与 Padding-Box 引发的 1px 几何偏心
在 `Composer.tsx` 中：
```tsx
<View style={[styles.shell, { borderWidth: 1, ... }]}>
  <MemoSoftShadow width={cardSize.width} height={cardSize.height} />
  ...
</View>
```
在 React Native Android 端（Yoga 引擎）：
- 父容器 `shell` 具有 `borderWidth: 1`，其内边距盒子（Padding Box）从 $(1\text{dp}, 1\text{dp})$ 开始；
- 子元素 `SoftShadow` 采用绝对定位 `top: -PAD, left: -PAD`。在部分 Android 架构版本中，绝对定位以 Padding Box 为原点；
- 内部 SVG 矩形绘制在 $(PAD, PAD)$，叠加后相当于将阴影中心向**右下方偏移了 $+1\text{dp}$**！
- 这导致阴影本身不对称：上左外露更少，下右外露更多；深色描边叠在偏移的阴影基底上，进一步加剧了方向不均匀的视觉错觉。

### 3.4 描边工程收敛方案
1. **物理单像素对齐（Hairline Snapping）**：
   摒弃裸 `borderWidth: 1`，强制收敛至物理像素真源：
   $$\text{borderWidth} = \text{StyleSheet.hairlineWidth} = \frac{1}{\text{PixelRatio.get()}}$$
   无论 DPR 是 $2.75$、$3.0$ 还是 $3.5$，物理线宽恒定为**恰好 1 个整物理像素**，彻底消除亚像素抗锯齿扩展。
2. **色值浓度重归合理感知带**：
   放弃脆弱的 `rgba(0, 0, 0, 0.025)`，采用经过原型验证的中性灰微描边：
   - 浅色：`rgba(0, 0, 0, 0.06)`（8-bit Alpha 为 15，抗锯齿稳定性提升 $250\%$，且在浅灰背景上轻柔如丝）；
   - 深色：严格锁定 `colors.borderStrong`（`#2e2e2e`）。
3. **坐标盒子隔离**：
   将 `SoftShadow` 移至无描边的包装外层，彻底消除 `borderWidth: 1` 对绝对定位原点的像素级偏移。

## 四、第三病灶：弥散阴影缺失根因与多层高斯漫反射算法

### 4.1 核心病灶：`operator="out"` 对边缘能量的毁灭性抑制

在 `SoftShadow.tsx` 中，阴影滤镜节点链包含以下逻辑：
```xml
<FeGaussianBlur in="SourceAlpha" stdDeviation={layer.sigma} result="b1" />
<FeFlood floodColor="#000000" floodOpacity={layer.alpha} result="c1" />
<FeComposite in="c1" in2="b1" operator="in" result="s1" />
<FeComposite in="s1" in2="SourceAlpha" operator="out" result="t1" />
```
原作者为了防止阴影“渗入卡片内部”（内渗），加入了 `operator="out"`。但该操作在数学上直接摧毁了弥散衰减的前半段！

#### 数学推导：边缘处的二次方衰减陷阱
设源矩形在边缘附近的 Alpha 分布为 $S(x)$（$x$ 为向外的垂直距离，卡内 $x < 0$，卡外 $x > 0$，边界 $x = 0$）：
由于抗锯齿的存在，$S(x)$ 在 $x = 0$ 处平滑过渡，有 $S(0) = 0.5$。  
高斯卷积核产生的模糊 Alpha 为 $B(x) = (S * G_\sigma)(x)$。在半平面边缘处：
$$B(0) = \frac{1}{2} \text{erfc}(0) = 0.5$$
现在代入 `FeComposite operator="out"` 的合成公式：
$$T(x) = \alpha \cdot B(x) \cdot (1 - S(x))$$
在紧贴输入框边缘的交界点 $x \to 0^+$：
$$T(0) = \alpha \times 0.5 \times (1 - 0.5) = \mathbf{0.25 \times \alpha}$$
**边缘有效 Alpha 被硬生生削减了 $75\%$！**

代入当前 `SPECS.composer` 参数实测：
- 近层：$\sigma_1 = 6, \alpha_1 = 0.06 \implies T_1(0) = 0.06 \times 0.25 = \mathbf{0.015}$（$1.5\%$ Alpha）；
- 远层：$\sigma_2 = 18, \alpha_2 = 0.08 \implies T_2(0) = 0.08 \times 0.25 = \mathbf{0.020}$（$2.0\%$ Alpha）；
- 双层在边缘合成后的总峰值 Alpha 为：
  $$\alpha_{\text{total}}(0) = 1 - (1 - 0.015)(1 - 0.020) = \mathbf{0.0347} \approx 3.47\%$$

### 4.2 光学感知分析：为什么人眼判断“弥散效果没有”？

底色背景为纯中性浅灰 `#f9f9f9`（RGB 为 249）或 `#f5f5f5`（RGB 为 245）。  
当阴影与 `#f9f9f9` 叠加时，其在距离 $d$ 处的实际像素亮度变化为：
$$\Delta \text{RGB}(d) = 249 \times \alpha_{\text{total}}(d)$$

根据高斯误差积分计算各距离的衰减剖面：
| 距离 $d$ | 近层 $\alpha_1(d)$ | 远层 $\alpha_2(d)$ | 合成 $\alpha_{\text{total}}(d)$ | 产生色阶差 $\Delta \text{RGB}$ | 屏幕呈现 RGB | 人眼感知状态 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---|
| **$0\text{dp}$（边缘）** | $0.0150$ | $0.0200$ | **$3.47\%$** | $\approx 8.6$ | $240.4$ | 极微弱灰阶（勉强可辨） |
| **$6\text{dp}$（$1\sigma_1$）** | $0.0095$ | $0.0295$ | **$3.87\%$** | $\approx 9.6$ | $239.4$ | 紧贴边框的细窄灰环 |
| **$12\text{dp}$** | $0.0020$ | $0.0230$ | **$2.49\%$** | $\approx 6.2$ | $242.8$ | 处于肉眼辨识临界线 |
| **$18\text{dp}$（$1\sigma_2$）** | $0.0008$ | $0.0127$ | **$1.35\%$** | $\approx 3.3$ | $245.7$ | **进入弱光不可辨盲区** |
| **$24\text{dp}$** | $\approx 0$ | $0.0060$ | **$0.60\%$** | $\approx 1.5$ | $247.5$ | **8-bit 色阶量化归零** |
| **$36\text{dp}$（$2\sigma_2$）** | $0$ | $0.0018$ | **$0.18\%$** | $< 0.5$ | $249.0$ | **物理全黑像素无变化** |

#### 结论
在当前的参数与运算逻辑下，**整个阴影的有效视觉半径仅有不可怜的 8px~12px**！  
超出 12px 之后，由于 Alpha 过低直接被 8 位颜色通道舍入丢失（色阶差 $< 2$）。用户在手机上自然只能看到一条紧紧贴在描边外侧的硬灰圈，而远处的“高斯弥散扩散波”全部死在量化噪声之下！

### 4.3 三层递进式高斯漫反射弥散模型（3-Tier Ambient Diffusion Algorithm）

借鉴 Cherry Studio 移动端与 VisionOS 的高级浮雕环境光漫反射算法，必须构建**三层能量梯次递进**的阴影结构：

```
+---------------------------------------------------------------+
| Tier 3: Ambient Glow (远场漫射光晕, σ=24, dy=0, α=0.08, 宽大舒展)  |
|   +-------------------------------------------------------+   |
|   | Tier 2: Floating Volume (中场悬浮体积, σ=10, dy=4, α=0.07)  |   |
|   |   +-----------------------------------------------+   |   |
|   |   | Tier 1: Contact Occlusion (近场接触咬合, σ=3, α=0.05) |   |   |
|   |   |   +---------------------------------------+   |   |   |
|   |   |   |         Composer Card (White Fill)     |   |   |   |
```

1. **Tier 1: 接触咬合层（Contact Occlusion）**
   - 物理使命：锚定物理形态边缘，防止悬浮物体在光照下发飘。
   - 参数：$dy = 1\text{dp}, \sigma = 3.0\text{dp}, \alpha = 0.05$。
2. **Tier 2: 悬浮体感层（Floating Volume）**
   - 物理使命：赋予输入框从背景上抬升 $4\text{dp} \sim 6\text{dp}$ 的真实物理体积感。
   - 参数：$dy = 4\text{dp}, \sigma = 10.0\text{dp}, \alpha = 0.07$。
3. **Tier 3: 宏观环境漫射气垫层（Atmospheric Penumbra）**
   - 物理使命：构建四周均匀扩散、半透明渐变的温润气垫光晕，彻底激活“弥散感”。
   - 参数：$dy = 0\text{dp}$（严格各向同性 360° 均匀漫射）, $\sigma = 24.0\text{dp}, \alpha = 0.08$。

#### 出血边距核算
最大扩散半径 $\sigma_{\max} = 24.0\text{dp}$，高斯衰减的三倍标准差物理区间：
$$3\sigma_{\max} = 3 \times 24 = 72\text{dp}$$
最大偏移量 $|dy|_{\max} = 4\text{dp}$。  
画布四周最小出血边界（Padding）：
$$\text{PAD} = 3\sigma_{\max} + |dy| + 4 = 72 + 4 + 4 = \mathbf{80\text{dp}}$$

#### 解耦内渗架构（Painter's Algorithm 替代 `operator="out"`）
彻底解决边缘能量衰减的核心钥匙是**渲染层级解耦**：
```tsx
<View style={styles.composerWrapper}>
  {/* 1. 阴影层置于容器底层，不再执行 operator="out"，保持真实的高斯扩散 */}
  <SoftShadow width={width} height={height} borderRadius={26} />
  
  {/* 2. 实体卡片置于阴影上方，以纯白实心背景完全遮盖内部，无内渗 */}
  <View style={styles.composerCard}>
    {children}
  </View>
</View>
```
当实心白底由位于上方的 Card 绘制时，依据画家算法（Source-Over），卡片内部的阴影被自然完全遮蔽（100% 阻隔内渗）；而在卡片外侧，阴影从 $x = 0$ 处以完整的 $B(0) = 0.5$ 饱满能量向外顺滑弥散，彻底根治 $0.25$ 衰减断层！
