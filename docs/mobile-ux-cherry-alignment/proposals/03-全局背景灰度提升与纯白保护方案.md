## 一、执行摘要与战役定位

### 1.1 业务背景与用户现场诉求
在 Crish Mobile 移动端交互重构战役中，用户在多款设备（包含华为 P40 Pro 等主流 OLED / LCD 移动端真机）实测后提出明确的视觉优化意见：
> **用户原声指令**：
> “还有我提议，整体的界面灰度都可以提一下，大概统一提升2个点看看吧。但是已经是白色的就保持白色好了，包括按钮和设置的每个选项行以及一些输入框等等吧，只要是白色的就可以保持。”

该诉求切中了当前浅色界面存在的**视觉基座偏轻、物理层级扁平、卡片边界在强光环境下辨识度不足**的痛点。

### 1.2 现有视觉体系根因断裂诊断
1. **背景底色与纯白表面对比度仅 1.05:1（近乎融为一体）**：
   - 现有浅色模式下，主屏幕底色 `canvas` 为 `#f9f9f9`（RGB 249, 249, 249），抽屉底色 `canvasDrawer` 为 `#f5f5f5`（RGB 245, 245, 245）。
   - 纯白组件（输入框 Composer、设置卡片 `surfaceGrouped`、浮动白圆钮 `surfaceRaised`）色值为 `#ffffff`（RGB 255, 255, 255）。
   - 经 WCAG 2.1 相对亮度复算，`#ffffff`（相对亮度 1.000）与 `#f9f9f9`（相对亮度 0.947）的对比度仅为 **1.053:1**，亮度差值 $\Delta L$ 仅为 **0.053**。在户外阳光直射或高色温屏幕下，用户肉眼几乎无法察觉底色与卡片的边界，导致组件漂浮感完全缺失，界面失去纵深感。
2. **去阴影裁决实施后的层次补偿需要**：
   - 在 2026-11-02 的移动端去阴影裁决中，全 App 全面禁用了系统级 elevation 与生硬黑影，全面转向“靠亮度台阶与微柔漫反射区分层级”。
   - 当阴影退役后，区分“背景面”与“前景卡片”的全部重担落在了底色的明度差（Luminance Delta）上。当前仅 2.35% 的灰度使得这一台阶过于微弱，加深底色灰度是强化物理层次感的最优雅、最轻量的解法。
3. **纯白元素边界守卫必须严格锁定**：
   - 灰度提升**仅针对承载性背景容器**（Canvas / Drawer / FillSubtle），严禁盲目全局下调导致输入框、设置卡片、按钮等操作实体变灰变脏。必须建立绝对的纯白 `#ffffff` 白名单保护网。

### 1.3 方案核心产出
1. **精准数值模型**：确立以 sRGB 阶位与 HSL 明度为基准的“+2% 灰度提升”数学公式，确定 `canvas` 从 `#f9f9f9` 调优至 `#f4f4f4`（灰度从 2.35% 上浮至 4.31%，精准提升 1.96% ≈ 2.0%），`canvasDrawer` 从 `#f5f5f5` 调优至 `#f0f0f0`（灰度从 3.92% 上浮至 5.88%，精准提升 1.96% ≈ 2.0%）。
2. **纯白组件保护白名单**：对输入框卡片（Composer）、设置选项卡片（SettingsRow / Card）、悬浮按钮（IconButton floating / ScrollToBottomButton）、弹窗与 Sheet 表面（Modal / Sheet Surface）进行 Token 链条梳理与白名单固化。
3. **全量 WCAG 对比度安全复算**：全 token 对扫描全部通过 WCAG AA 正文 $\ge 4.5:1$ 与元信息 $\ge 3.0:1$ 标准，`surface` vs `canvas` 的相对亮度差扩大近 **1 倍**（0.053 $\rightarrow$ 0.098），空间进深感倍增。
4. **工程实施与测试守卫适配**：无缝更新 `theme.ts`、`styleTokens.guard.test.ts`、`theme.contrast.test.ts`，确保零架构负债与零破坏性回退。

## 二、数学建模与精准色值校准

### 2.1 灰度与明度的数学定义与真源对照
在参考原型 `reference/crish-mobile-drawer/css/variables.css` 中，色板最初便以严格的纯中性灰（$R = G = B$）定义：
```css
/* reference/crish-mobile-drawer/css/variables.css 原型定义 */
--bg-drawer: #f5f5f5;     /* RGB(245, 245, 245) 4.0% 纯中性灰 */
--bg-main: #f9f9f9;       /* RGB(249, 249, 249) 2.5% 纯中性灰 */
--bg-subtle: #f9f9f9;     /* 2.5% 纯中性灰 (RGB 249, 249, 249)，极轻柔浅灰底色 */
--pure-white: #ffffff;    /* 纯白 */
```
在色彩工程学中，中性灰度值定义如下：
$$\text{Gray Percentage} = \frac{255 - R}{255} \times 100\% \quad (R = G = B)$$
$$\text{Lightness} (L) = \frac{R}{255} \times 100\% = 100\% - \text{Gray Percentage}$$

- 纯白 `#ffffff`：$R = 255$，$\text{Gray} = 0.0\%$，$L = 100.0\%$；
- 原型 `--bg-main` (`#f9f9f9`)：$R = 249$，$\text{Gray} = \frac{6}{255} \approx 2.35\%$（原型标定 2.5%），$L = 97.65\%$；
- 原型 `--bg-drawer` (`#f5f5f5`)：$R = 245$，$\text{Gray} = \frac{10}{255} \approx 3.92\%$（原型标定 4.0%），$L = 96.08\%$。

### 2.2 灰度提升 2%（2 个百分点）的精确推导

用户要求：“整体的界面灰度都可以提一下，大概统一提升2个点看看吧”。
提升 2 个百分点，即：
$$\text{Target Gray} = \text{Current Gray} + 2.0\%$$
换算至 8-bit sRGB 单通道阶位变化：
$$\Delta R = 255 \times 0.02 = 5.10 \text{ 阶位}$$

#### 1. 主画布底色 `canvas` / `canvasGrouped` / `fillSubtle`：
- 当前值：$R = 249$ (`#f9f9f9`)
- 扣减 5.10 阶位：$249 - 5.10 = 243.90$
- **方案 A（四舍五入为 244，十六进制 `#f4f4f4`，推荐）**：
  - $R = G = B = 244$
  - 新灰度：$\frac{255 - 244}{255} = \frac{11}{255} \approx 4.31\%$
  - 灰度差值：$4.31\% - 2.35\% = \mathbf{+1.96\%}$（与 2.0% 目标相差仅 0.04%，极度精准）
  - 明度 $L = 95.69\%$
- **方案 B（向下取整为 243，十六进制 `#f3f3f3`，备选）**：
  - $R = G = B = 243$
  - 新灰度：$\frac{255 - 243}{255} = \frac{12}{255} \approx 4.71\%$
  - 灰度差值：$4.71\% - 2.35\% = \mathbf{+2.36\%}$
  - 明度 $L = 95.29\%$

#### 2. 抽屉与台阶底色 `canvasDrawer`：
- 当前值：$R = 245$ (`#f5f5f5`)
- 扣减 5.10 阶位：$245 - 5.10 = 239.90$
- **方案 A（四舍五入为 240，十六进制 `#f0f0f0`，推荐）**：
  - $R = G = B = 240$
  - 新灰度：$\frac{255 - 240}{255} = \frac{15}{255} \approx 5.88\%$
  - 灰度差值：$5.88\% - 3.92\% = \mathbf{+1.96\%}$（与 2.0% 目标完全契合）
  - 明度 $L = 94.12\%$
- **方案 B（向下取整为 239，十六进制 `#efefef`，备选）**：
  - $R = G = B = 239$
  - 新灰度：$\frac{255 - 239}{255} = \frac{16}{255} \approx 6.27\%$
  - 灰度差值：$6.27\% - 3.92\% = \mathbf{+2.35\%}$
  - 明度 $L = 93.73\%$

### 3.3 纯白保护的架构防护铁律
为防止开发过程中误将 `surface`、`surfaceGrouped` 或 `field` 随底色一并“降权调暗”，制定以下守卫断言规则：
1. **SSOT 单一真源隔离**：`canvas` 系列代表 Background Layer（背景层），`surface` 系列代表 Surface Layer（表面层）。灰度调节只允许注入 Background Layer。
2. **源码断言守门**：在 `styleTokens.guard.test.ts` 中，对 `surface: '#ffffff'`、`surfaceGrouped: '#ffffff'`、`surfaceRaised: '#ffffff'`、`field: '#ffffff'`、`fieldFocus: '#ffffff'` 建立恒等断言，任何对纯白集合的篡改将导致 CI 与门禁立即报红。

## 四、全量色彩对比度与空间层级科学检验

依据 WCAG 2.1 与项目标准 `theme.contrast.test.ts`（正文 $\ge 4.5:1$、辅助元信息 $\ge 3.0:1$），对底色变更为 `#f4f4f4` / `#f0f0f0` 后的全量色彩对比度进行严格审计与数学验算。

### 4.1 相对亮度（Relative Luminance）基准数据
根据国际照明委员会（CIE）与 W3C WCAG 推荐标准，计算 sRGB 相对亮度：
$$R_{\text{linear}} = \begin{cases} \frac{R}{255 \times 12.92} & \frac{R}{255} \le 0.03928 \\ \left(\frac{R/255 + 0.055}{1.055}\right)^{2.4} & \frac{R/255} > 0.03928 \end{cases}$$
$$L = 0.2126 \times R_{\text{linear}} + 0.7152 \times G_{\text{linear}} + 0.0722 \times B_{\text{linear}}$$

| 颜色名称与色值 | sRGB 通道值 | 线性化通道值 | 相对亮度 $L$ | 说明 |
|:---|:---|:---|:---|:---|
| **纯白 `surface` (`#ffffff`)** | 255, 255, 255 | 1.0000 | **1.0000** | 纯白卡片与表面基准 |
| **旧底色 `canvas` (`#f9f9f9`)** | 249, 249, 249 | 0.9469 | **0.9469** | 原浅色画布背景 |
| **新底色 `canvas` (`#f4f4f4`)** | 244, 244, 244 | 0.9022 | **0.9022** | **方案 A 新浅色画布背景** |
| **旧抽屉底 `canvasDrawer` (`#f5f5f5`)** | 245, 245, 245 | 0.9109 | **0.9109** | 原抽屉背景 |
| **新抽屉底 `canvasDrawer` (`#f0f0f0`)** | 240, 240, 240 | 0.8677 | **0.8677** | **方案 A 新抽屉背景** |
| **主标题/正文 `textPrimary` (`#171717`)** | 23, 23, 23 | 0.0097 | **0.0097** | 墨色文字真源 |
| **次级说明 `textSecondary` (`#555555`)** | 85, 85, 85 | 0.0908 | **0.0908** | 次级文本 |

### 4.3 空间物理层级进深感评估
1. **微弱漫反射阴影的显性化**：
   在 Android 端，`SoftShadow` 采用微弱的高斯漫反射（`rgba(0, 0, 0, 0.008)` 与 `rgba(0, 0, 0, 0.012)`）。在旧底色 `#f9f9f9` 上，阴影与背景混色仅产生不到 1 个阶位的微弱变化；当底色降至 `#f4f4f4` 时，纯白卡片自带的明度跃升（$\Delta L = 0.098$）与边缘软漫反射产生共振，卡片立即呈现出类似真实纸张（Real-world Physical Paper Card）的悬浮质感。
2. **纯白输入框（Composer）的存在感强化**：
   在会话主界面，纯白输入框由原先的“融于背景中、找不到输入区域”转变为“视线聚焦的中心操作岛”，在无需增加重描边或生硬黑框的前提下，优雅达成高对比度。

## 五、暗色模式与中性灰主题的隔离保护

### 5.1 暗色模式（Dark Mode）完全免疫机制
暗色模式（`darkBase`）属于完全独立的反向亮度系统：
- 暗色画布底色：`canvas = '#121212'`
- 暗色抽屉底色：`canvasDrawer = '#0e0e0e'`
- 暗色卡片表面：`surface = '#171717'`、`surfaceGrouped = '#1c1c1c'`、`surfaceRaised = '#1e1e1e'`

在暗色体系中，物理规律是“越靠近前景的卡片越明亮，背景最黑”。本方案的 2% 灰度提升针对浅色模式的底色明度冗余；暗色模式色板**完全保持现有基线不变**，严禁引入任何针对深色背景的误触改动。

### 5.2 纯净中性灰模式（Neutral Theme）的连带同步
在 `theme.ts` 的架构定义中：
> `neutralTheme`（纯净中性灰）遵循**推导规则 1**：“结构层（底/面/线/文字/alpha 档/玻璃档）本就是纯中性灰（R=G=B 或纯黑 alpha），与浅色同值——本档的‘纯净’与浅色共用同一灰阶骨架”。

因此，根据系统架构的一致性原则：
1. `neutralBase` 中的结构层背景色 `canvas`、`canvasGrouped`、`canvasDrawer`、`fillSubtle` **必须与浅色 `lightBase` 严格保持同值**，同步升级至 `#f4f4f4` 与 `#f0f0f0`。
2. `neutralBase` 中的功能色与状态色（墨色主操作、砖红、赭黄、纯灰等）维持原降饱和口径不变。
3. `styleTokens.guard.test.ts` 中 `NEUTRAL_STRUCTURAL_KEYS` 断言确保二者骨架恒等，无架构漂移。
