## 一、任务背景与核心改造目标

在上下文状态（`context-state`）审计中，用户明确提出：

> “当前已切换到模型 ornith:latest（服务商 ollama）。权限模式：full。思考档位：Max。 这个不是系统提示吗，是随到用户发送的消息后面，不是一个单独用户输入内容的。 你看看这是什么情况吧”

前端发送流水线此前存在以下结构性缺陷：

1. **独立载体分裂**：在发送前通过 `flushContextStateBeforeSend` 调用 `contextInjectionDispatcher.inject` 生成独立的 `ctx-carrier-...` 助手载体消息卡片；
2. **消息格式松散**：用户消息的乐观入库仅写入原始 `displayText`，未将切换环境的上下文与当次输入做高内聚聚合；
3. **双重提示隐患**：若状态既作为独立 carrier 卡片挂载，又随附进用户消息，会在会话流中造成重复冗余提示。

根据用户与总方案要求，本任务完成了前端发送流水线的端到端重构：

- **高内聚用户消息正文**：当存在暂存状态时，将当次用户消息正文结构化聚合为：
  ```
  [用户输入]
  <displayText>

  [系统环境上下文]
  <flushedContextState>
  ```
- **剔除独立载体卡片**：在 `flushContextStateBeforeSend` 中彻底移除 `contextInjectionDispatcher.inject(...)` 调用，避免生成 `ctx-carrier-...` 冗余卡片；保持基线与快照的比对（`diffContextStateSnapshot`）与签名更新（`setLastSentContextSignature`, `setLastSentContextSnapshot`），精准返回 `rawText`；
- **双通道一致性保障**：在正常空闲发送（`useSlashSend.ts`）与运行中排队（`enqueueFollowUpMessage` in `slashSendQueueHelper.ts`）中保持格式完全一致；
- **后端透传契约**：继续将 `flushedContextState` 赋予 `streamOptionsWithClientMsg.contextState`，确保 Rust 内核在 `run_launch.rs` 装配系统提示词时能够直接提取。

## 二、逐文件详细改动说明

### 2.1 `apps/crish-desktop/src/hooks/chat-stream/useSlashSend.ts`

- **修改位置**：第 216–236 行附近（空闲时乐观入库与启动流式逻辑）。
- **具体改动**：
  1. 调用 `const flushedContextState = flushContextStateBeforeSend(sessionId);` 获取可能存在的状态变更文本；
  2. 若 `flushedContextState` 存在且非空，挂载至 `streamOptionsWithClientMsg.contextState`；
  3. 构造高内聚聚合文本：
     ```typescript
     const finalUserDisplayText = flushedContextState
       ? `[用户输入]\n${displayText}\n\n[系统环境上下文]\n${flushedContextState}`
       : displayText;
     ```
  4. 在本地 Store 乐观入库 `addMessage` 时，传入 `text: finalUserDisplayText`；
  5. 传给底层 `runStreamingAssistant(input, userMsgId, sessionId, streamOptionsWithClientMsg)` 时保持契约稳定，`input` 保持输入透传，`streamOptionsWithClientMsg.contextState` 携带状态文本。

### 2.2 `apps/crish-desktop/src/hooks/chat-stream/slashSendQueueHelper.ts`

- **修改位置**：
  - 移除无用引用 `import { contextInjectionDispatcher } from '../../api/contextInjectionDispatcher';`；
  - 核心函数 `flushContextStateBeforeSend`（第 62–100 行）；
  - 排队辅助函数 `enqueueFollowUpMessage`（第 130–165 行）。
- **具体改动**：
  1. **剔除载体注入**：彻底移除 `contextInjectionDispatcher.inject(...)` 调用，不再向会话中写入 `workspace_env` 载体卡片。
  2. **保留差分与基线更新**：
     - 保留 `diffContextStateSnapshot(getLastSentContextSnapshot(sessionId), next)`；
     - 当 `changed.length === 0` 时平滑返回 `undefined`；
     - 发生变更时更新 `setLastSentContextSignature` 与 `setLastSentContextSnapshot`，并返回提取的 `rawText`。
  3. **排队消息（Follow-up）格式对齐**：在 `enqueueFollowUpMessage` 中同步更新：
     ```typescript
     const flushedContextState = flushContextStateBeforeSend(sessionId);
     const finalDisplayText = flushedContextState
       ? `[用户输入]\n${displayText}\n\n[系统环境上下文]\n${flushedContextState}`
       : displayText;
     ```
     在乐观入库与 `runControl.followUp` 调度中均统一传递 `finalDisplayText`。
