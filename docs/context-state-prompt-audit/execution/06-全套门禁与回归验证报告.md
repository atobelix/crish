## 二、单元测试补充实现详述

### 2.1 `sessionHydrationMessages.test.ts` 测试套件补充

在 `apps/crish-desktop/src/api/session-persistence/sessionHydrationMessages.test.ts` 中新增了 `purgeStaleContextStateBubbles: 历史脏数据自愈净化` 测试套件，共包含 5 组针对性测试用例：

1. **测试 1：精准修剪历史孤儿对**
   - **场景**：输入消息列表中穿插了历史孤儿对：
     - 用户消息：“当前已切换到模型 ornith:latest（服务商 ollama）。权限模式：full。思考档位：Max。”
     - 紧邻助手消息：“明白了。当前配置：模型已设置为 ornith:latest。”
   - **断言**：净化后该孤儿对被物理剔除，前后两轮正常对话（LRU 缓存提问与解答、单元测试提问与解答）100% 完整保留。

2. **测试 2：多种脏数据变体覆盖**
   - **场景**：
     - 变体 A：带有 `[系统环境提示：]` 前缀的用户消息 + “好的。当前配置已更新。”确认回复；
     - 变体 B：带有 `metadata: { kind: 'context-state' }` 显式标记的用户消息 + “收到。当前配置：deepseek-chat”确认回复；
     - 变体 C：无伴生回复的孤儿状态消息（如被外部中断只残留了伪用户消息）。
   - **断言**：所有变体均被准确识别并连带修剪，后续正常对话完全不受影响。

3. **测试 3：高内聚信封消息零误伤保护**
   - **场景**：用户发送包含 `[用户输入]\n...\n\n[系统环境上下文]\n...` 的高内聚信封消息，助手返回常规分析结果。
   - **断言**：消息列表完整保留（`length === 2`），证明自愈逻辑严格以首部特征匹配，绝不误伤正当随附环境上下文的正常用户发言。

4. **测试 4：普通用户对话与工具调用场景完整保留**
   - **场景**：
     - 包含执行 `git status` 的 `run_command` 工具调用助手消息；
     - 包含正文中自然提及“新切换的模型为什么在控制台没有响应？”的常规提问。
   - **断言**：消息列表全员保留，工具调用参数与输出完好无损。

5. **测试 5：`sanitizeMessagesForHydrate` 管道全链路协同**
   - **场景**：同时混入历史脏孤儿对、因异常退出而遗留的 `status: 'processing'` 流式消息、以及需要因果保序的多轮消息。
   - **断言**：脏孤儿对被清理；未收敛流式消息被收敛为 `status: 'completed'`；并且赋予严格单调自增的 `engineSequence: [0, 1, 2, 3]`。

### 2.2 `sessionEventProjection.test.ts` 测试套件补充

在 `apps/crish-desktop/src/api/sessionEventProjection.test.ts` 中新增了 `context-state 事件拦截与投影防腐` 测试套件，共包含 5 组针对性测试用例：

1. **测试 1：`message-start` 事件拦截**
   - **场景**：传入 `role: 'user'` 且 `metadata: { kind: 'context-state' }` 的 `message-start` 事件。
   - **断言**：投影生成的 `result.messages` 为空，绝不生成 `sender === 'user'` 的 SessionMessage，零用户气泡。

2. **测试 2：`message-end` 事件拦截**
   - **场景**：传入 `role: 'user'` 且 `metadata: { kind: 'context-state' }` 的 `message-end` 事件。
   - **断言**：同样被硬性拦截，投影结果为空。

3. **测试 3：无 `client_message_id` 的裸正文历史事件拦截**
   - **场景**：模拟引擎旧版 `idle-resume` 生成的无 `client_message_id` 且正文以 `当前已切换到模型` 开头的事件（包装在 `runtime-event` 信封中）。
   - **断言**：无论是 `message-start` 还是 `message-end`，均被防腐守卫拦截，零用户气泡。

4. **测试 4：多轮对话混合场景端到端投影**
   - **场景**：
     - 轮次 1：正常用户提问 1 + 正常助手回复 1；
     - 异常插入：引擎发出的 `cs-u-fake` 伪用户消息；
     - 轮次 2：正常用户高内聚提问 2（含 `[用户输入]` 与 `[系统环境上下文]`）+ 正常助手回复 2。
   - **断言**：`cs-u-fake` 被彻底过滤；输出正好为 4 条合法消息，角色序列严格为 `['user', 'assistant', 'user', 'assistant']`，且客户端消息 ID（`c-u1`, `c-u2`）被权威保留。

5. **测试 5：`isContextStateBogusUserMessage` 纯函数边界契约**
   - **断言**：
     - `null` / `undefined` → `false`
     - `metadata.kind === 'context-state'` → `true`
     - 裸文本匹配且无 `client_message_id` → `true`
     - 携带有效 `clientMessageId` 的普通提问 → `false`（防误伤）
     - 携带 `[用户输入]` 前缀的信封消息 → `false`（防误伤）
