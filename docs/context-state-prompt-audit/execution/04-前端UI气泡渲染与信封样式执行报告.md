## 一、任务背景与核心目标

在上下文状态（Context-State）提示词注入与用户消息协同管线中，当用户消息包含结构化的环境快照时（如 `[用户输入]` 与 `[系统环境上下文]` 标记）：

1. **气泡内部优雅解耦呈现**：避免将系统环境配置生硬地与用户提问粘合为单一扁平长句，而是在用户消息气泡内部优雅划分为两段呈现：
   - **(a) 顶部主体段**：以常规气泡字号清晰呈现用户实际输入的业务提问；
   - **(b) 底部随附段**：以精致、扁平、克制的随附信封容器（`.userBubbleContextEnvelope`）呈现系统环境上下文状态，带有微小胶囊徽标、浅色柔和边框与弱化字体（`var(--text-tertiary)`）。
2. **纯净向后兼容**：普通不带标记的用户消息 100% 保持原生单一文本渲染，零回归。
3. **复制与编辑语义对齐**：
   - **复制（`handleCopy`）**：完整复制包含系统环境标签的完整文本，确保上下文溯源与分享无损；
   - **就地编辑（`onStartEdit`）**：编辑回填输入框时，**自动过滤系统环境标签**，仅将用户的实际输入提问填入编辑框，彻底防止用户编辑提问时不慎将脏标记二次提交入库。
4. **严格遵守行数门禁与设计红线**：
   - 遵守 `npm run check:line-counts`（UI 组件 ≤ 500 行）；
   - 遵守 `AGENTS.md §13/§14`：克制激活边框、禁止重阴影、优先 HSLA/Design Token/`color-mix`。

## 二、代码实现架构与细节

### 2.1 结构化文本解析器：`parseStructuredUserText`

在 `ChatUserMessageRow.tsx` 中实现了高效、确定的 O(N) 结构化解析器，避免灾难性正则回溯：

```typescript
export interface ParsedStructuredUserText {
  isStructured: boolean;
  userInputText: string;
  contextStateText?: string;
}

export function parseStructuredUserText(
  text: string | undefined | null
): ParsedStructuredUserText {
  const raw = text || '';
  const userTag = '[用户输入]';
  const ctxTag = '[系统环境上下文]';
  const userIdx = raw.indexOf(userTag);
  const ctxIdx = raw.indexOf(ctxTag);

  if (userIdx === -1 || ctxIdx === -1) {
    return { isStructured: false, userInputText: raw };
  }

  let userInputText =
    userIdx < ctxIdx
      ? raw.slice(userIdx + userTag.length, ctxIdx).trim()
      : raw.slice(userIdx + userTag.length).trim();
  let contextStateText =
    userIdx < ctxIdx
      ? raw.slice(ctxIdx + ctxTag.length).trim()
      : raw.slice(ctxIdx + ctxTag.length, userIdx).trim();

  // 容错去除标签后可能跟随的半角/全角冒号
  if (userInputText.startsWith(':') || userInputText.startsWith('：')) {
    userInputText = userInputText.slice(1).trim();
  }
  if (contextStateText.startsWith(':') || contextStateText.startsWith('：')) {
    contextStateText = contextStateText.slice(1).trim();
  }

  return { isStructured: true, userInputText, contextStateText };
}
```

**特性保证**：

- 支持 `[用户输入]` 在前、`[系统环境上下文]` 在后，或相反顺序；
- 支持标签后跟随冒号（`:` 或 `：`）或换行符；
- 仅当两者均存在时才触发结构化判定，避免普通提问中偶发单标签被误判；
- 结合 `useMemo`，若未展开的 `displayText` 因长文本预览截断了尾部标记，自动回退到 `msg.text` 结构探测，并对主体段安全应用预览截断，随附信封完整展现。

    parsedStructured.isStructured ? (

        className={styles.userBubbleStructuredContent}

      </div>
    ) : (
      <div className={styles.userBubbleText}>
        {displayText}
        {queuedBadge}
      </div>
    )
  ) : null;
}

### 2.3 复制与编辑交互差异化处理

#### 1. 复制无损保真（`handleCopy`）

```typescript
const handleCopy = useCallback(() => {
  const text = msg.text || '';
  if (!text) return;
  void copyTextBestEffort(text).then((ok) => {
    if (!ok) {
      showToast('复制失败');
      return;
    }
    setCopied(true);
    if (copiedTimer.current != null) {
      window.clearTimeout(copiedTimer.current);
    }
    copiedTimer.current = window.setTimeout(() => setCopied(false), 1200);
  });
}, [msg.text, showToast]);
```

- 使用原生 `msg.text`，保证复制出来的文本为包含完整上下文标记的原始字符。

#### 2. 就地编辑标签剥离（`handleStartEdit`）

```typescript
const handleStartEdit = useCallback(() => {
  if (!onStartEdit) return;
  if (parsedStructured.isStructured) {
    const sanitizedMsg: SessionMessage = {
      ...msg,
      text: parsedStructured.userInputText,
    };
    const originalText = msg.text;
    let mutated = false;
    try {
      if (!Object.isFrozen(msg)) {
        (msg as { text?: string }).text = parsedStructured.userInputText;
        mutated = true;
      }
    } catch {
      /* swallow-ok: read-only object */
    }
    try {
      (onStartEdit as (m?: SessionMessage) => void)(sanitizedMsg);
    } finally {
      if (mutated) {
        try {
          (msg as { text?: string }).text = originalText;
        } catch {
          /* swallow-ok */
        }
      }
    }
    return;
  }
  onStartEdit();
}, [msg, onStartEdit, parsedStructured]);
```

- **双重保证**：既通过参数传入净化后的 `sanitizedMsg`，又在同步调用周期内安全隔离 `msg.text` 并在 `finally` 中原样恢复，确保上层无论直接读取参数还是闭包引用的消息对象，均只拿到纯净的用户提问，彻底消除标签回填隐患。
