# 前端聊天 UI 气泡渲染与状态微提示组件专项审计报告

> **审计专题**：系统上下文状态提示（Context-State Notice）被错误渲染为右侧独立用户输入气泡（附带复制/编辑/Pin按钮与时间戳）的 UI 渲染状态机根因剖析与多层防御方案  
> **审计角色**：聊天 UI 气泡渲染与状态微提示组件专项审计员

>   **核心结论**：系统状态通知本应渲染为居中 20px 极简发丝微分割线提示（`ContextStateNotice`），却在用户现场呈现为右侧深色独立用户输入气泡并挂载操作栏。其直接病灶为：后端 `run_idle.rs` 伪造了 `role: AgentMessageRole::User` 事件；前端事件投影层 `sessionEventProjection.ts` 存在校验盲区，未对 `metadata.kind === 'context-state'` 拦截，盲目调用 `pushUser` 赋予 `sender: 'user'`；虚拟滚动列表 `MessageVirtualizer.tsx` 仅凭 `sender === 'user'` 单一条件分流给 `ChatUserMessageRow`；同时既有微提示守卫 `isContextStateCarrierMessage` 严厉要求 `sender === 'assistant'` 且正文必须为空，导致该消息不仅无法触发既有微提示通道，反而被用户行完整吸收，并因被误判为「会话最后一条用户消息」而错误挂载了就地编辑（铅笔图标）与撤回/Pin操作栏。

## 1. 现场还原与问题定性分析

### 1.1 用户现场截图特征还原

在用户提供的真实截图与系统日志中，展示了如下诡异的 UI 呈现：

1. **右侧深色气泡**：在聊天消息流最右侧，出现了一个全尺寸深色用户消息气泡（`.userBubble`）；
2. **气泡内部文本**：正文完整呈现了系统状态快照文本：  
   `「当前已切换到模型 ornith:latest（服务商 ollama）。权限模式：full。思考档位：Max。」`；
3. **顶部/悬停元信息与操作栏**：
   - 顶部/侧边显示时间戳 `00:47`；
   - 悬停时激活 `UserMessageActionsBar`，依次展示：
     - **复制按钮**（`AppIcon name="copy"`）；
     - **编辑按钮**（`AppIcon name="pencil"`，Tooltip 提示“编辑上一条消息（回填输入框并重新编辑）”）；
     - **Pin 按钮**（带颜色选择器的置顶图钉）；
4. **业务违和感**：
   - 该文本属于底层系统环境切换通知（由前端配置栏切换触发），完全不是人类用户打字输入的指令；
   - 用户却能“编辑”这句话、“复制”这句话、“Pin”这句话，甚至大模型紧接着针对这句话作出了冗余的“配置确认”答复。

### 1.2 预期视觉规范 vs 实际劣化视觉对比

| 视觉与交互维度   | 预期设计规范（`ContextStateNotice` 契约）              | 实际劣化现场（现场截图表现）                                        | 差异与破坏根因                                     |
| :--------------- | :----------------------------------------------------- | :------------------------------------------------------------------ | :------------------------------------------------- |
| **对齐方式**     | **全宽水平居中**（`justify-content: center`）          | **靠右对齐**（`align-items: flex-end`）                             | 误入 `.rowUser` / `.userStack` 分支                |
| **容器形态**     | **极简发丝分割线**：两侧 0.5px 发丝，中间 11px 浅灰字  | **全尺寸带圆角深色背景气泡**（`var(--user-bubble-bg)`）             | 误渲染为 `.userBubble` 实体气泡                    |
| **外框与内边距** | 零背景、零边框、高度固定 20px、紧凑 4px 垂直节奏       | 气泡 padding 12px 16px、行内 padding-bottom 16px                    | 撑大垂直视觉间距，造成严重的视觉噪音               |
| **交互操作栏**   | **严禁任何操作按钮**（无复制、无编辑、无撤回、无 Pin） | **挂载完整 `UserMessageActionsBar`**（时间戳、复制、编辑铅笔、Pin） | 赋予系统状态不该有的用户消息操作特权               |
| **语义与无障碍** | `role="status"` / `aria-live="polite"`，不计入问答轮次 | `role="article"` / `data-role="user"`，被视作独立 Prompt            | 破坏对话时间线语义，导致自动化测试与屏幕阅读器困惑 |
| **编辑态特权**   | 不可编辑，无输入框转移挂载                             | 因处于尾部被标记 `isLastUser`，允许回填输入框重发                   | 极度反常，用户可以编辑系统提示后再次提交给模型     |

**为什么原设计的居中微提示通道没有生效？**

## 3. 渲染状态机与三级断层分析

通过上述代码链路，我们归纳出导致该 Bug 的三级断层模型：

```
[后端 engine run_idle.rs]
       │
       │ (1. 角色篡改断层: 将 context_state 伪造为 role: AgentMessageRole::User)
       ▼
[网络事件: message-start / message-end]
       │
       │ (2. 投影盲区断层: sessionEventProjection 未校验 metadata.kind, 直接 pushUser)
       ▼
[前端 SessionMessage: sender='user', text='当前已切换到模型...']
       │
       │ (3. 路由单一断层: MessageVirtualizer 见 sender==='user' 即丢给 ChatUserMessageRow)
       ▼
[ChatUserMessageRow]
       │
       ├─► 未识别 context-state 触发源 ──► 绘制深色气泡 (.userBubble)
       ├─► 正文塞入 .userBubbleText ──► 展示「当前已切换到模型...」
       └─► 误判为最后一条消息 (isLastUser) ──► 挂载 UserMessageActionsBar (复制/编辑/Pin/00:47)
```

### 3.1 断层一：协议与角色篡改（Backend Level）

后端引擎设计者混淆了“状态发生告知”与“用户交互提问”，在 `run_idle.rs` 中为图省事，将未被消化的 `context_state` 条目包装为 `AgentMessageRole::User` 重新推入执行管道。这是整个灾难的源头。

### 3.2 断层二：投影层单向盲信（Projection Level）

前端 `sessionEventProjection.ts` 作为防腐层（Anti-Corruption Layer），完全丧失了对非法用户消息的防御能力。它盲目相信 `role === 'user'`，没有检查载荷中的 `metadata.kind === 'context-state'`，直接把系统通知投影成了带有 `sender: 'user'` 的真实用户消息。

### 3.3 断层三：渲染层二分路由短路（Render Level）

前端渲染层在 `MessageVirtualizer.tsx` 中缺乏防御深度，将 `msg.sender === 'user'` 作为是否进入 `ChatUserMessageRow` 的唯一开关。`isContextStateCarrierMessage` 规则过于死板（要求 `sender === 'assistant'` 且正文必须为空），未能识别出这种变异的“伪用户状态消息”，导致微提示组件（`ContextStateNotice`）完全没有触发机会。

## 4. UI 渲染层与投影层深度防御方案

即使后端因为历史遗留会话数据、第三方插件或旧版引擎事件流传来了 `role: user` 且包含 `kind: 'context-state'` 的消息，前端也必须具备刚性的**自愈防腐与规范化重构能力**。

### 4.1 投影防腐层防御（`sessionEventProjection.ts`）

在事件流转为 `SessionMessage` 的源头截断伪用户消息：

```typescript
// 建议落地于 apps/crish-desktop/src/api/sessionEventProjection.ts

/**
 * 判定事件消息是否为伪造为 User 角色的上下文状态切换通知（防御性检查）
 */
export function isContextStateBogusMessage(
  msg: AgentMessage | null | undefined
): boolean {
  if (!msg) return false;
  // 1. 元数据枚举命中
  const meta = msg.metadata as Record<string, unknown> | undefined;
  if (meta?.kind === 'context-state' || meta?.mode === 'context-state') {
    return true;
  }
  // 2. 文本特征兜底匹配（对抗 metadata 丢失的历史脏数据）
  const { text } = projectAgentMessageContent(msg);
  if (
    text.startsWith('当前已切换到模型') &&
    (text.includes('权限模式') || text.includes('思考档位'))
  ) {
    return true;
  }
  return false;
}
```

**投影动作改造**：
当 `event.type === 'message-start'` 或 `message-end` 检测到 `isContextStateBogusMessage(msg)` 时：

1. **绝对禁止调用 `pushUser`**；
2. 将其转化为标准纯状态载体消息（`sender: 'assistant'`, `text: ''`，携带解析后的 `MessageContextInjection`）；
3. 或作为会话元数据合并入上下文，并直接跳过生成独立消息对象。

### 4.2 水合自愈层防御（`sessionHydrationMessages.ts` / 消息去重合并）

对于已经持久化在 SQLite 或 IndexedDB 中的历史会话脏数据：
在消息水合加载阶段，增加自愈过滤器：

```typescript
// 对历史消息进行净化
export function sanitizeLoadedMessages(
  messages: SessionMessage[]
): SessionMessage[] {
  return messages.map((m) => {
    if (m.sender === 'user') {
      const meta = m.metadata as Record<string, unknown> | undefined;
      const isBogusState =
        meta?.kind === 'context-state' ||
        (m.text &&
          m.text.startsWith('当前已切换到模型') &&
          m.text.includes('权限模式'));

      if (isBogusState) {
        // 自愈为纯载体消息
        return {
          id: m.id.startsWith('ctx-carrier-') ? m.id : `ctx-carrier-${m.id}`,
          sender: 'assistant',
          text: '',
          timestamp: m.timestamp,
          blocks: [
            {
              type: 'context_injection',
              id: `inj-${m.id}`,
              injection: {
                id: `inj-${m.id}`,
                kind: 'workspace_env',
                mode: 'context-state',
                summary: m.text,
                content: m.text,
                timestamp: m.timestamp,
              },
            },
          ],
        };
      }
    }
    return m;
  });
}
```

## 6. 总结与审计员裁决

1. **现象根因锁定**：本次缺陷并非前端单一组件失误，而是后端角色伪造、事件投影盲信、虚拟列表单一分流、微提示守卫门槛严苛共同导致的**多层击穿（Swiss Cheese Model）**。
2. **整改原则**：
   - **后端除根**：彻底拔除 `run_idle.rs` 伪造 `role: AgentMessageRole::User` 的行为（由总方案维度一、二负责）；
   - **前端筑墙**：在投影层（`sessionEventProjection.ts`）、水合层（`sessionHydrationMessages.ts`）与路由层（`MessageVirtualizer.tsx`）建立三道防线，即使拿到脏数据也能自愈渲染为优雅的居中发丝微提示（`ContextStateNotice`）。
3. **最终交付物状态**：本报告作为战役分维审计第 04 卷定稿，为后续代码实施波提供精确的代码定位、逻辑证据与改造指引。
