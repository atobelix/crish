### 维度 1：现代 CSS `@starting-style` 宿主兼容性与退出死锁对抗

#### 1.1 宿主 WebView2 / Chromium 运行时核实
- **实测数据**：
  Conex 采用 Tauri v2 架构，宿主底层直接消费 Windows Edge WebView2 Evergreen 运行时。经现场探针检测，本机已安装 WebView2 版本为 `146.0.3856.109` / `147.0.3912.72`。
- **现代标准支持矩阵**：
  - `@starting-style`：Chromium 117+ 全面支持（2023 年 9 月入标）。
  - `transition-behavior: allow-discrete`：Chromium 117+ 全面支持。
  - `overlay: auto`：Chromium 117+ 全面支持。
  - **结论**：在标准 Windows 宿主环境下，Chromium 内核原生支持度为 **100%**。

#### 1.2 对抗漏洞 1：旧版内核/企业环境缩写语法失效（CSS Shorthand Hazard）
- **风险暴露**：方案 04 书写了如下过渡缩写：
  ```css
  transition: opacity 150ms var(--ease-accelerate), display 150ms allow-discrete;
  ```
  在 CSS 语法解析规范中，如果一个复合简写属性值（Shorthand）中包含当前内核未知的标识符（如旧版 Chromium < 117 或嵌入式 WebView2 不认识 `allow-discrete`），**浏览器将直接废弃整条 `transition` 声明**，导致连原本支持的 `opacity` 过渡也一同失效，弹窗立刻变成生硬的即时闪烁。
- **纯 CSS 优雅降级方案**：
  必须分层声明，优先声明基础数值过渡，再通过 `@supports` 声明离散过渡：
  ```css
  /* 基础降级：确保所有内核都有透明度与位移过渡 */
  transition: opacity 150ms var(--ease-accelerate), transform 150ms var(--ease-accelerate);

  /* 现代特性增强：支持 allow-discrete 时接管 display */
  @supports (transition-behavior: allow-discrete) {
    transition:
      opacity 150ms var(--ease-accelerate),
      transform 150ms var(--ease-accelerate),
      display 150ms allow-discrete;
  }
  ```

#### 1.3 对抗漏洞 2：`useModernPresence` 退出死锁（致命缺陷）
方案 04 第 7.2 节提出的极简 `useModernPresence` 钩子存在**三大运行时死锁缺陷**：
```tsx
// 方案 04 的原始提案代码：
const onTransitionEnd = (e: React.TransitionEvent) => {
  if (e.target === e.currentTarget && !isOpen) {
    setIsMounted(false);
  }
};
```
1. **`prefers-reduced-motion` 与节能模式死锁**：
   方案 04 第 610 行明确定义：在 `prefers-reduced-motion: reduce` 或节能模式下，`transition: none !important;` 或时长为 `0ms`。
   **W3C 规范硬性规定：当元素的 `transition-duration` 为 0 或 `transition: none` 时，浏览器绝不会派发 `transitionend` 事件！**
   一旦用户开启系统的“减弱动态效果”或性能档，弹窗关闭后 `onTransitionEnd` **永远不会被调用**，`isMounted` 永久为 `true`，弹窗组件永久驻留内存并占用后台资源！
2. **JSDOM 单元测试环境挂死**：
   Conex 门禁执行 `npm test`（Vitest），运行环境为 JSDOM。**JSDOM 完全不支持 CSS 过渡引擎，不会触发任何真实的 `transitionend` 事件**。现有 `Dialog.test.tsx` 中所有依赖退出卸载的测试用例（如“退场：open=false 后动画时长结束才卸载”）将全部超时失败，导致 CI 全红！
3. **多属性触发多次回调**：
   浮层同时对 `opacity`、`transform`、`display` 声明了 transition，会派发 3 次 `transitionend`。若未对 `propertyName` 或单一生命周期做防抖守卫，会在最快的一个属性（如 80ms 的 transform）结束时误将正在播放 150ms opacity 的组件提前卸载！

### 维度 3：`Dialog` 复合化重构的存量兼容性

#### 3.1 核心盲区：`DialogOverlayContext` 断裂与下拉框沉底
在现有架构中，模态弹窗并非完全封闭的卡片，内部常常嵌入 `<Select>`、`<Menu>` 或级联选择器（如 [`ModelsCascadeSelect.tsx:34`](file:///c:/Software/conex/apps/crish-desktop/src/components/settings-models/ModelsCascadeSelect.tsx#L34)）。

- **层叠上下文物理机制**：
  弹窗遮罩 `.dialogOverlay` 的 `z-index` 为 `var(--z-modal, 1000)`。若内部的 Select 浮层默认 portal 到 `document.body`，其默认 `z-index`（`--z-dropdown: 900`）将**低于遮罩层 1000**，导致下拉列表被遮罩与弹窗卡片无情遮挡，用户完全看不见也点不到！
- **Conex 既有单源解法**：
  Conex 在 [`dialogOverlayContext.ts`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Dialog/dialogOverlayContext.ts) 定义了 `DialogOverlayContext`。弹窗向该上下文注入遮罩 DOM 节点；内部的 `SelectContent.tsx` 优先消费该上下文，将下拉菜单 portal 直接挂在遮罩 DOM 内部，利用 DOM 树的局部层叠自然高过弹窗主体！该机制已被 [`SelectDialogOverlay.test.tsx`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Select/__tests__/SelectDialogOverlay.test.tsx) 严格列为自动化门禁。
- **方案 05 漏报断言**：
  方案 05 提出的复合化结构（`<Dialog><DialogOverlay><DialogContent>...</DialogContent></DialogOverlay></Dialog>`）**完全忽略了 `DialogOverlayContext`**。如果开发者使用复合语法，弹窗内的所有下拉菜单将立刻失去父级 portal 容器，陷入“下拉列表消失在弹窗背后”的恶性体验 Bug！

#### 3.2 变量断裂：`--dialog-z` 丢失与设置面板冲突
- 现有 `Dialog.module.css` 明确定义：`z-index: var(--dialog-z, var(--z-modal));`；
- 全局设置面板 [`SettingsPanel.tsx`](file:///c:/Software/conex/apps/crish-desktop/src/components/settings/SettingsPanel.tsx) 依赖传入 `classNames={{ overlay: styles.settingsOverlay }}`，并在该类中显式覆盖 `--dialog-z: var(--z-settings-modal)` 以实现特定层级压制；
- 方案 04 的现代 CSS 蓝图中写死了 `z-index: var(--z-modal, 1000);`，将导致设置弹窗的层叠自适应失效。

#### 3.3 复合语法糖与双层遮罩冲突
现有 Conex 架构具备弹窗叠弹窗（Nested Modals）特性（如在设置面板中唤起“模型配置弹窗”）。
在 [`Dialog.scrim.test.ts`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Dialog/Dialog.scrim.test.ts) 中守卫了如下 `:has()` 规则：
```css
[data-focus-trap]:has(~ [data-focus-trap] > [data-dialog-overlay]:not([data-dialog-state='exiting'])) > [data-dialog-overlay] > .backdrop {
  background: transparent;
}
```
该规则依靠独立的 `.backdrop` 节点让位，保证两个弹窗嵌套时不会叠加成死黑。
方案 04 试图将 `background: var(--modal-scrim)` 直接合入 `.dialogOverlay`，消灭 `.backdrop`。**一旦消灭独立的 `.backdrop` 节点，上述 CSS 选择器直接失效，嵌套弹窗将发生遮罩死黑**，直接破坏既有测试资产！

### 维度 4：`Tabs` 纯 CSS 指示器可行性核验

#### 4.1 方案 05 “剥离 ResizeObserver” 属于严重设计失误
方案 05 §3.3.1 提出：
> “1. 废弃 ResizeObserverManager 监听：移除在 TabsList 挂载期间对 DOM 尺寸的轮询观察。  
> 2. 纯 CSS 变量直接驱动物理平滑滑块：仅在 activeEl 变化时通过 style.setProperty 更新 CSS 变量。”

审计团队通过构建对抗用例，证实该设计存在 **4 处必现致命 Bug**：

1. **多语言切换（i18n）宽度突变无法跟随**：
   用户在界面切换中英文（如 `General` $\rightarrow$ `通用设置`），当前 Tab 的 `value`（`"general"`）并未改变。由于方案 05 剥离了 `ResizeObserver` 且只监听 `value` 变化，CSS 变量 `--tab-indicator-w` 将**不会得到任何更新**！滑块宽度保持旧尺寸，文字瞬间溢出或留白！
2. **窗口与多窗格拖拽缩放（Split Pane Resize）断层**：
   在 Conex 的二叉树多窗格布局（`BinaryTreeLayout`）中，用户拖拽分割条改变视口大小是桌面端最基础交互。当窗格变窄、Tab 文字压缩换行或弹性伸缩时，没有 `ResizeObserver` 捕获尺寸，指示器滑块将严重偏离实际物理按钮位置，飘在半空中！
3. **动态添加/删除 Tab 坐标漂移**：
   当用户在左侧关闭一个前序 Tab，当前激活的 Tab 物理位置前移，但其 `value` 未变。指示器将停留在原本的物理坐标上，指向已不存在的空位。
4. **首帧渲染飞入闪烁（Fly-In Flash）**：
   在组件首帧挂载时，`--tab-indicator-x` 与 `--tab-indicator-w` 初始为 0。当 `updateIndicatorVars` 注入计算值后，由于 CSS 声明了 `transition: transform 250ms, width 250ms`，**用户在每次打开含 Tabs 的页面时，都会看到指示器从左上角 (0,0) 拖拽飞入当前选项卡！体验极其廉价！**

#### 4.2 架构穿透与正确解法
方案 05 混淆了“**ResizeObserver 的罪过**”：
- **真正的性能毒瘤**：原实现将测量结果调用 `setSliderRect()` 存入 React State，导致每次观察都触发 `TabsList` 及其所有子节点重新 Render；
- **优雅的工业级解法**：**保留轻量单例 `ResizeObserver`，但在回调中 100% 走纯 DOM `style.setProperty`，0 次 React 重渲染**！同时在首帧测量未就绪前挂载 `data-indicator-ready="false"` 禁用 transition，彻底消灭首帧飞入！

### 维度 5：跨方案标尺与 Token 冲突（横向矛盾）

#### 5.1 `Button` 四档尺寸 vs 方案 04 三档密度对撞
- 现有 [`Button.tsx:12`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Button/Button.tsx#L12) 严格按照全仓四档尺寸规范建立：
  `xs: 24px`, `sm: 28px`, `md: 32px`, `lg: 40px`；
- 方案 04 第 3.3 节却定义：
  `sm: 24px`, `md: 28px`, `lg: 36px`；
- **灾难性对撞**：
  若按方案 04 第 373 行执行 `const effectiveSize = size ?? density`：
  当外层容器声明 `<Density density="sm">` 时，Button 解析出 `effectiveSize="sm"`。然而在 `Button.module.css` 中，`[data-size='sm']` 的物理高度是 **28px**，而不是密度期望的 **24px**！
  反之，如果方案 04 强行修改 `Button.module.css` 将 `data-size='sm'` 改为 24px，全仓原本显式声明 `size="sm"` 的几百个业务按钮（高度预期 28px）将无差别全部缩水 4px，导致现有视觉大面积溃败！

#### 5.2 Token 命名孤岛（`--control-h` vs `--control-height`）
- 现有 `tokens-space.css` 统管的系统单真理源为 `--control-height`（28px/24px/32px）与 `--control-height-sm` 等；
- 方案 04 引入了全新的 `--control-h`，但在现有全局样式中，只有少量组件认识 `--control-h`。若 `[data-density='sm']` 不反向映射修改 `--control-height`，未改造的存量组件将无法获得级联缩放效果。

#### 5.3 Tooltip 生命周期矛盾（方案 04 vs 方案 05）
- **方案 04 §7.1** 声称：Tooltip 采用 **CSS 驻留（Keep Mounted）**，`display: none` 隐藏；

## 三、 阻断性风险清单与改进补丁规范

为确保方案顺利进入工程落地，提出以下 4 项必接补丁规范：

### 补丁 1：`useModernPresence` 鲁棒性与测试环境安全守卫补丁

重构 `useModernPresence`，注入**双轨超时安全天花板（Safety Timeout Ceiling）**与 **JSDOM 环境自愈**，杜绝任何状态挂死：

```tsx
// 改进规范：useModernPresence.ts
import { useState, useEffect, useRef, useCallback } from 'react';

export interface UseModernPresenceOptions {
  visible: boolean;
  /** 最大安全超时兜底（默认 300ms），防 transitionend 丢失导致永久挂死 */
  safetyTimeoutMs?: number;
}

export function useModernPresence({
  visible,
  safetyTimeoutMs = 300,
}: UseModernPresenceOptions) {
  const [isMounted, setIsMounted] = useState(visible);
  const timeoutRef = useRef<ReturnType<typeof setTimeout> | undefined>(undefined);

  useEffect(() => {
    if (visible) {
      setIsMounted(true);
      if (timeoutRef.current) clearTimeout(timeoutRef.current);
    } else {
      // 1. JSDOM 测试环境自愈：无真实 CSS 引擎，直接同步/微任务置 false
      if (typeof window !== 'undefined' && (window as any).navigator?.userAgent?.includes('jsdom')) {
        setIsMounted(false);
        return;
      }
      
      // 2. 真实浏览器环境：挂载安全天花板兜底定时器
      // 无论 transition: none、prefers-reduced-motion 还是 tab 切换后台，确保必卸载！
      timeoutRef.current = setTimeout(() => {
        setIsMounted(false);
      }, safetyTimeoutMs);
    }

    return () => {
      if (timeoutRef.current) clearTimeout(timeoutRef.current);
    };
  }, [visible, safetyTimeoutMs]);

  const onTransitionEnd = useCallback((e: React.TransitionEvent) => {
    // 过滤子元素冒泡；仅当当前容器退出且 target 匹配时卸载
    if (e.target === e.currentTarget && !visible) {
      if (timeoutRef.current) clearTimeout(timeoutRef.current);
      setIsMounted(false);
    }
  }, [visible]);

  return {
    isMounted,
    presenceProps: {
      'data-state': visible ? ('open' as const) : ('closed' as const),
      onTransitionEnd,
    },
  };
}
```

### 补丁 3：`Tabs` 现代化混合指示器引擎（RO 驱动 CSS 变量 + 首帧防闪）

恢复轻量 `ResizeObserver`，但**严禁调用 React `setState`**，实现零重渲染物理自适应：

```tsx
// 改进规范：TabsList 内部指示器核心实现
export const TabsList = forwardRef<HTMLDivElement, TabsListProps>(function TabsList(props, ref) {
  const { value, orientation } = useTabsContext();
  const listRef = useRef<HTMLDivElement | null>(null);
  const isFirstRender = useRef(true);

  const applyIndicatorToDOM = useCallback((activeEl: HTMLElement, listEl: HTMLElement, animate: boolean) => {
    // 若首帧挂载，暂时将过渡时长置为 0ms，防止从 (0,0) 飞入闪烁！
    if (!animate) {
      listEl.style.setProperty('--tab-duration', '0ms');
    } else {
      listEl.style.removeProperty('--tab-duration');
    }

    listEl.style.setProperty('--tab-indicator-x', `${activeEl.offsetLeft}px`);
    listEl.style.setProperty('--tab-indicator-y', `${activeEl.offsetTop}px`);
    listEl.style.setProperty('--tab-indicator-w', `${activeEl.offsetWidth}px`);
    listEl.style.setProperty('--tab-indicator-h', `${activeEl.offsetHeight}px`);
    listEl.style.setProperty('--tab-indicator-opacity', '1');
  }, []);

  const update = useCallback((animate = true) => {
    const listEl = listRef.current;
    if (!listEl) return;
    const activeEl = listEl.querySelector<HTMLElement>(`[data-tabs-trigger][data-value="${CSS.escape(value)}"]`);
    if (activeEl) {
      applyIndicatorToDOM(activeEl, listEl, animate);
    } else {
      listEl.style.setProperty('--tab-indicator-opacity', '0');
    }
  }, [value, applyIndicatorToDOM]);

  // 1. 值改变时更新（带动画）
  useLayoutEffect(() => {
    const isInitial = isFirstRender.current;
    update(!isInitial);
    if (isInitial) {
      // 首帧完成后开启后续动画
      requestAnimationFrame(() => {
        isFirstRender.current = false;
      });
    }
  }, [update]);

  // 2. 响应窗格缩放、i18n 多语言文案突变、字体加载（无动画，即时贴靠，0 次 React 重渲染！）
  useEffect(() => {
    const listEl = listRef.current;
    if (!listEl) return;
    const ro = ResizeObserverManager.getInstance();
    const handleResize = () => update(false);
    ro.observe(listEl, handleResize);
    return () => ro.unobserve(listEl, handleResize);
  }, [update]);

  // ... 纯渲染逻辑
});
```
