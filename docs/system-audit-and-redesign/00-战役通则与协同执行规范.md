## 一、战役总则与核心纪律（General Principles）

### 1.1 纯逻辑与反退避铁律

- **效果锁不容妥协**：用户给定的效果与审计发现的缺陷范围即为重构目标，任何 Agent 无权擅自降级、裁撤功能或用“简化版/MVP”敷衍；
- **禁止退避裁判**：严禁以“实现太难”、“生态流行度”、“业界都用 X”为由否决合理架构或劝退自研；不确定的地方必须通过真实测试或 CDP 机器真值验证；
- **彻底杜绝打补丁**：严禁盲目循环遍历、坐标魔数补偿、临时兼容代码。必须穿透现象定位架构断层，以 $O(1)$、高内聚、单向数据流的优雅原生方案解决；
- **问题一律同权**：方案仅按逻辑依赖顺序编排，不谈工期、人天与业务优先级。

### 1.2 Git 提交与权限隔离

- **主控独占 Git 提交权**：所有子 Agent 绝对**严禁执行 `git commit`、`git push` 或任何 `git reset` / `git checkout .` / `git restore` 回撤操作**；
- **子 Agent 产出边界**：代码修改保留在工作区，由主控执行代码审计后使用 `git commit --only <paths...>` 进行原子提交；
- **禁止绕过门禁**：严禁使用 `--no-verify` 跳过 Husky / pre-commit 门禁。

### 1.3 运行环境与编码纪律

- **执行环境**：统一使用 **pwsh7（PowerShell 7+）**，禁止使用 Windows PowerShell 5.1；
- **文档与源码编码**：全量文件强制使用 **UTF-8 无 BOM** 编码，中文注释与文档内容。

### 1.4 调度与定时器铁律

- **定时器最小阈值**：如果设置定时器，最短是 **100 秒**；
- **命令等待与事件响应**：如果命令耗时较长，最佳方式是**等待命令执行完成后的系统推送通知（Reactive Wakeup）**，而不是一直高频轮询任务状态。

### 2.2 浮层、Trigger 与 Tooltip 统一契约（Universal Popover & Tooltip Contract）

1. **Tooltip 零坐标与程序性焦点绝对防御**：
   - 必须通过 `!rect || (rect.width <= 0 && rect.height <= 0 && rect.top === 0 && rect.left === 0)` 拦截谓词，全零坐标下绝对禁止挂载 Portal，根除 `(8px, 8px)` 左上角漂移；
   - 过滤 `items[0]?.focus()` 等程序性自动聚焦事件，仅响应真实用户 `:focus-visible` 与 `:hover`；
   - 在 `useAnimatedPresence` 的 `exiting` 阶段冻结已知合法坐标，杜绝退场动画帧突跳。
2. **Popover & Trigger 架构解耦**：
   - 触发按钮统一采用 **「显式 Anchor 锚定 + 按钮自主 onClick 切换」**（对齐 `ComposePlusMenu` 原生方案）；
   - 严禁在 `Menu` 基座内对 `trigger` 进行暴力解构与注入匿名 Ref，彻底消灭 Double-Toggle / Quad-Click 震荡。

### 2.3 设置页与主工作区布局解耦契约（Settings & Shell Layout Decoupling）

1. **侧栏状态独立性**：主工作区侧栏的折叠/展开状态（`sidebarCollapsed`）**严禁污染设置页面的左侧分类导航**；进入设置页时，设置导航栏必须始终独立可见并拥有专属布局容器；
2. **主底栏入口重构（对齐图 2/3/5）**：
   - 侧栏最底部重构为双列容器：**左侧为用户个人卡片（头像 + 用户名），右侧为独立设置齿轮按钮**；
   - 原设置快捷菜单绑定于用户卡片点击展开；点击右侧设置齿轮平滑进入全屏/主区设置面板；
3. **色彩继承与温润质感**：
   - 设置左侧导航背景继承 `--bg-secondary`（暖灰），右侧配置主区承载 `--bg-primary`（温润白），保持与主工作区完全一致的视觉层次与同心圆角外壳。

### 2.4 核心聊天链路与错误处理规范（Chat Core & IPC Connectivity）

1. **IPC 协议与错误分层**：
   - 前端 `chat-bridge` $\to$ Tauri IPC $\to$ Rust `crates/conex-session-loop` $\to$ `crates/conex-agent-provider` 必须全链路打通并正确处理 `CoreError`；
   - 区分软性重试与硬性故障，杜绝盲目上抛通用 S6【软件内部错误】。

## 三、子 Agent 工作流与交付约定（Agent Workflow & Output Conventions）

1. **唯一产出路径**：
   - 本战役所有分析文档均落盘于 `docs/` 下的对应专题目录；
   - 主控为每个子 Agent 分配唯一文件名（`NN-*.md`），严禁并发写冲突；
2. **分析阶段零代码修改**：
   - 调研与分析类 Agent 专注于源码逆向、时序推导与方案设计，严禁修改任何业务代码；
3. **自适应长度与信息量充实**：
   - 不设 token 限制，输出内容力求详尽透彻，配齐代码路径、行号证据、Mermaid 时序图与数学推导；
4. **真实 CDP 验证**：
   - 涉及 UI 检查必须直接对接 `http://127.0.0.1:9222` Tauri WebView2 环境，严禁使用浏览器沙箱 Mock 状态敷衍验收。

- 本文档为动态演进规范。任何子 Agent 在执行过程中若发现新的踩坑点、架构断层或可复用设计模式，均可在本文档末尾以 `### 追加规范 [Agent角色 - 日期]` 形式**只追加、不删除**；
- 每轮执行收口后由主控统一去重整理，沉淀为正式全仓标准。
