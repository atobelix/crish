### 1.2 目标架构核心指标与质量断言

1. **SQLite 读写 0 阻塞与 0 崩溃**：
   - 全库连接（主连接 + 写连接 + 8 只读连接）100% 配置 `busy_timeout = 5000ms`；
   - 常规读取操作 100% 路由至 `ReaderPool`（自适应非阻塞探测，命中时延 < 5µs），主写连接仅服务写入与事务，消除写锁饥饿与线程阻塞；
2. **知识库毫秒级检索（CJK FTS5 倒排索引）**：
   - 升级 `blocks_fts` 为 `trigram` 倒排索引，彻底移除全表 `instr()` 暴力子串扫描；中文、英文及混合代码搜索均实现 $O(\log N)$ 级倒排检索，BM25 相关度排序准确率 100%；
3. **Diff 引擎 100% 精确 Unified Header**：
   - 建立双游标行号追踪模型，首行插入/删除/上下文混合场景下 `@@ -start,count +start,count @@` 100% 符合 GNU/POSIX Patch 规范；
4. **CAS 存储模型单一权威**：
   - 统一 CAS 元数据与存储结构，建立 `BlobLeaseGuard` 内存租约与 SQLite `active_blob_leases` 表的双向状态同步，确保两阶段 GC（7 天隔离期 + 读反隔离自愈）100% 保护活数据；
5. **感知系统零死锁与零漏报**：
   - 浏览器对话框状态机引入代次强校验（Generation Tagging），根除 ABA 竞态；
   - 帧通道采用多订阅广播模型，支持多次重建重连；
   - UIA 遍历建立顶层窗口边界断言，杜绝 Desktop 根节点越界；
   - `InputBackend` 共享层全面接入 `run_steps_guarded` 与 `EmergencyStop` 实时中断；
6. **彻底践行反过度设计铁律**：
   - 拔除违背红线的 1,900 行同步 DNS A/AAAA 解析器与双重 Gate 冗余；
   - 物理删除 `parse_handwritten.rs`（295 行）、4 个临时探针测试文件（1,239 行）及形式主义测试。

### 2.3 并发与状态机不变量定理（Invariants I1~I6）

- **不变量 I1（读写无锁共存与超时防护）**：任何时刻，执行 `LocalDb::read` 的只读连接不得阻塞其他只读连接；任何读写连接在争用底层 SQLite 锁时，必须等待不少于 5000ms 的 `busy_timeout`，严禁即刻抛出 `SQLITE_BUSY`。
- **不变量 I2（CAS 单一权威与软删除安全）**：所有 CAS Blob 写入与引用必须统一收拢；无全域引用的孤儿必须经过不少于 7 天的 `marked_for_delete_at` 软删除隔离期；任何对处于隔离期 Blob 的 `get_blob` 读取必须原子自愈清除标记。
- **不变量 I3（知识库检索亚毫秒倒排）**：`search_fulltext` 对任意包含 CJK 字符的查询必须走倒排索引匹配，禁止在无索引列上执行全表 `instr()` 或逐行遍历。
- **不变量 I4（Diff Hunk Header 数学守恒）**：对于任意文本 Diff Hunk，其 Header 行号 `@@ -O,L +N,M @@` 必须严格满足：$O \ge 1$ 且 $N \ge 1$；当 $L > 0$ 时，$O$ 对应旧文本中被修改/删除的首行 1-based 行号；当 $M > 0$ 时，$N$ 对应新文本中插入/替换的首行 1-based 行号。
- **不变量 I5（对话框生命周期 Generation 严格单调）**：`DialogRegistry` 中的代次 `gen` 必须严格单调递增；超时自动 dismiss 任务在唤醒后必须且仅当 `current_state.gen == task.gen` 时方可执行关闭操作。
- **不变量 I6（急停绝对优先级）**：当 `EmergencyStop` 被触发激活时，所有正在执行或排队的键鼠输入指令必须在下一次底层系统调用前即刻中止并返回错误，禁止任何穿透执行。

## 三、`LocalDb` 统一连接模型与并发事务调度

### 3.1 10 连接物理分裂根因分析与收敛方案

在 `crates/conex-db/src/lib.rs` 中，`LocalDb::open` 同时初始化了：

1. `self.conn: Arc<Mutex<Connection>>`（单主连接）；
2. `self.writer: DbWriteHandle`（独立的 Single Writer Actor 线程与独立连接）；
3. `self.reader_pool: Arc<ReaderPool>`（默认打开 8 个独立只读连接）。

然而在所有业务 CRUD 文件中，全部硬编码调用 `let conn = self.conn.lock()`。这造成了严重的架构分裂：

- `self.writer`（5ms 组提交 Actor）在真实业务中处于完全空转状态；
- `self.reader_pool`（8 个只读连接）被完全架空，所有读请求与写请求挤在 `self.conn` 的单一互斥锁上串行排队；
- **整改方案**：
  1. 建立统一的读调度接口 `LocalDb::read<F, R>(&self, f: F) -> Result<R, DbFailure>`：
     - 首先尝试从 `self.reader_pool` 获取只读连接；
     - 若 `reader_pool` 为空（如在内存模式下），平滑回退至 `self.conn.lock()`；
  2. 将所有只读查询（`get_session`, `list_sessions`, `get_message`, `list_messages`, `list_events`, `get_blob` 等）全部迁移至 `self.read(...)`；
  3. 保留 `self.conn` 作为唯一的权威写连接（或按需使用 `self.writer` 批量流式写入），实现真正的 SQLite WAL 模式多读者并发无锁读取。

### 3.2 全链路 `busy_timeout = 5000ms` 与 WAL 优化配置

在 SQLite 初始化阶段，对每一个物理打开的连接必须显式设置 `busy_timeout` 与优化 PRAGMA：

```rust
// 统一连接配置宏/辅助函数
pub fn configure_sqlite_connection(conn: &Connection, is_read_only: bool) -> Result<(), rusqlite::Error> {
    // 1. 设置 5000ms 忙等待超时（根除 SQLITE_BUSY 即死崩溃）
    conn.busy_timeout(std::time::Duration::from_millis(5000))?;

    if is_read_only {
        conn.execute_batch(
            "PRAGMA query_only = ON;
             PRAGMA synchronous = NORMAL;
             PRAGMA cache_size = -2000;
             PRAGMA temp_store = MEMORY;"
        )?;
    } else {
        conn.execute_batch(
            "PRAGMA journal_mode = WAL;
             PRAGMA synchronous = NORMAL;
             PRAGMA busy_timeout = 5000;
             PRAGMA cache_size = -4000;
             PRAGMA temp_store = MEMORY;
             PRAGMA foreign_keys = ON;"
        )?;
    }
    Ok(())
}
```

### 3.3 读写分离统一调度门面实现

在 `crates/conex-db/src/lib.rs` 中提供统一的读取抽象：

```rust
impl LocalDb {
    /// 执行只读查询（优先调度至 ReaderPool 8 槽位无锁并发读取，无池时平滑回退主连接）
    pub fn read<F, R>(&self, f: F) -> Result<R, DbFailure>
    where
        F: FnOnce(&Connection) -> Result<R, rusqlite::Error>,
    {
        // 尝试从只读连接池获取连接
        if let Ok(reader) = self.reader_pool.acquire() {
            return f(&reader).map_err(|e| DbFailure {
                message: format!("reader pool query error: {e}"),
                kind: DbFailureKind::Query,
            });
        }

        // 回退路径：主连接互斥锁
        let conn = self.conn.lock().map_err(|e| DbFailure {
            message: format!("lock poisoned: {e}"),
            kind: DbFailureKind::Lock,
        })?;
        f(&conn).map_err(|e| DbFailure {
            message: format!("fallback query error: {e}"),
            kind: DbFailureKind::Query,
        })
    }
}
```

  3. 彻底消除两处重复复制的 `put_blob`、`get_blob`、`content_hash` 实现，将通用 CAS 核心收拢至统一模块。

### 4.2 内存租约 `BlobLeaseGuard` 与 SQLite 表 `active_blob_leases` 双向同步闭环

针对审计中发现的 `BlobLeaseGuard`（内存 `RwLock<HashMap>`）与数据库 `active_blob_leases` 表互不同步、导致 GC 扫描忽略内存租约的缺陷，设计双向同步闭环：

```rust
pub struct BlobLeaseGuard {
    leases: parking_lot::RwLock<HashMap<String, Instant>>,
}

impl BlobLeaseGuard {
    /// 申请内存租约并原子同步至 SQLite active_blob_leases 表
    pub fn acquire_lease_synced(
        &self,
        db_conn: &Connection,
        hash: &str,
        duration: Duration,
    ) -> Result<LeaseToken, DbFailure> {
        let expire_at = Instant::now() + duration;
        let expire_unix_ms = std::time::SystemTime::now()
            .duration_since(std::time::UNIX_EPOCH)
            .unwrap_or_default()
            .as_millis() as i64
            + duration.as_millis() as i64;

        // 1. 写入数据库持久化租约表
        db_conn.execute(
            "INSERT INTO active_blob_leases (hash, expires_at_ms) VALUES (?1, ?2)
             ON CONFLICT(hash) DO UPDATE SET expires_at_ms = MAX(expires_at_ms, excluded.expires_at_ms)",
            params![hash, expire_unix_ms],
        ).map_err(|e| DbFailure {
            message: format!("failed to insert blob lease: {e}"),
            kind: DbFailureKind::Query,
        })?;

        // 2. 更新内存快速缓存
        self.leases.write().insert(hash.to_string(), expire_at);

        Ok(LeaseToken {
            hash: hash.to_string(),
        })
    }
}
```

在 `cas_gc.rs` 执行垃圾回收扫描时，双重比对数据库租约表与内存 `BlobLeaseGuard`，确保双重防线无死角：

## 五、知识库全文检索与 CJK 中文分词优化

### 5.1 CJK 检索退化为全表 `instr()` 暴力子串扫描性能瓶颈与危害

在现有实现 `fts_search.rs:36-60` 中，只要查询包含任意 CJK 字符，系统便完全放弃 FTS5 倒排索引，对 `blocks` 表执行 `WHERE doc_id = ?1 AND instr(plain_text, ?2) > 0`。

- **性能灾难**：随着笔记和文档数量增长，全表扫描耗时从几毫秒急剧恶化至数百毫秒，CPU 100% 满载，且无法计算相关度打分（BM25）。

### 5.2 SQLite FTS5 Trigram 倒排索引升级方案

SQLite FTS5 内置了高性能的 `trigram` 分词器，专门用于支持任意语言（特别是无空格分词的 CJK 中日韩字符）的快速子串倒排检索。

在 `crates/conex-workspace-store/src/migrate.rs` 中，将 `blocks_fts` 升级为 `trigram` 分词器：

```sql
-- 迁移并创建支持 CJK 子串检索的高性能 Trigram 虚表
CREATE VIRTUAL TABLE IF NOT EXISTS blocks_fts USING fts5(
    plain_text,
    block_id UNINDEXED,
    doc_id UNINDEXED,
    tokenize = 'trigram'
```

### 5.3 统一 FTS5 MATCH 检索与 BM25 排序

在 `crates/conex-workspace-store/src/fts_search.rs` 中，移除 `search_fulltext_cjk_instr` 分支，统一走倒排索引：

```rust
pub fn build_fts5_query_unified(raw_query: &str) -> String {
    let q = raw_query.trim();
    if q.is_empty() {
        return String::new();
    }

    // 对每个词条进行短语转义，保留完整倒排匹配
    q.split_whitespace()
        .filter(|t| !t.is_empty())
        .map(|t| {
            let escaped = t.replace('"', "\"\"");
            format!("\"{escaped}\"")
        })
        .collect::<Vec<_>>()
        .join(" AND ")
}

pub fn search_fulltext_indexed(
    conn: &Connection,
    doc_id: &str,
    query: &str,
    limit: i64,
) -> Result<Vec<BlockHit>, StoreError> {
    let match_expr = build_fts5_query_unified(query);
    if match_expr.is_empty() {
        return Ok(Vec::new());
    }

    let mut stmt = conn.prepare(
        "SELECT b.doc_id, b.block_id, b.kind,
                snippet(blocks_fts, 0, '<b>', '</b>', '...', 16) AS snip,
                bm25(blocks_fts) AS rank,
                b.props_json
         FROM blocks_fts f
         JOIN blocks b ON b.doc_id = f.doc_id AND b.block_id = f.block_id
         WHERE f.doc_id = ?1 AND blocks_fts MATCH ?2
         ORDER BY rank ASC
         LIMIT ?3"
    )?;

    let rows = stmt.query_map(params![doc_id, match_expr, limit], |r| {
        Ok(BlockHit {
            doc_id: r.get(0)?,
            block_id: r.get(1)?,
            kind: r.get(2)?,
            snippet: r.get(3)?,
            rank: r.get(4)?,
            props_json: r.get(5)?,
        })
    })?;

    let mut hits = Vec::new();
    for r in rows {
        hits.push(r?);
    }
    Ok(hits)
}
```

### 5.4 模糊匹配器（`FuzzyMatcher`）堆分配消减与 Rayon 线程池复用

在 `crates/conex-search/src/lib.rs` 中：

1. **消减堆分配**：使用 `smallvec` 或复用缓冲区，避免对每个路径分配 4 个 `Vec`；
2. **复用线程池**：用 `rayon::prelude::*` 替代 `std::thread::scope` 每次新建 OS 原生线程：

```rust
// 使用 Rayon 并行迭代器，复用全局工作线程池
pub fn search_files_parallel(
    query: &str,
    paths: &[String],
    limit: usize,
    matcher: &FuzzyMatcher,
) -> Vec<FileHit> {
    use rayon::prelude::*;

    if paths.is_empty() || query.is_empty() {
        return vec![];
    }

    let mut hits: Vec<FileHit> = paths
        .par_iter()
        .filter_map(|path| {
            let (score, indices) = matcher.score_and_indices(query, path);
            if score > 0 {
                Some(FileHit {
                    path: path.clone(),
                    score,
                    match_indices: indices,
                })
            } else {
                None
            }
        })
        .collect();

    hits.par_sort_unstable_by(|a, b| b.score.cmp(&a.score));
    hits.truncate(limit);
    hits
}
```

## 六、Diff 引擎行号索引修正与上下文压缩容错

### 6.1 `DiffEngine` 首行插入/删除 Unified Diff Hunk Header 索引计算越界 Bug 根因与精准修正

在 `crates/conex-diff/src/lib.rs:114-120` 中，原始代码：

```rust
let old_idx = change.old_index().unwrap_or(0);
let new_idx = change.new_index().unwrap_or(0);
if old_start.is_none() {
    old_start = Some(*old_idx + 1); // ❌ 若首行为 Insert，old_idx 被强转为 0，得到 0+1=1！
    new_start = Some(*new_idx + 1); // ❌ 若首行为 Delete，new_idx 被强转为 0，得到 0+1=1！
}
```

根据 Unified Diff 规范：

- 当 Hunk 首行为 `Insert` 时，旧文件的起始行号应为插入点所在的前一行或下一个上下文行的基准坐标；
- 当 Hunk 首行为 `Delete` 时，新文件的起始行号应为删除点在新文件中的对应基准行号。

### 6.2 双游标行号追踪模型

```rust

struct DiffCursorTracker {
    current_old_line: usize,
    current_new_line: usize,
}

// 在构建 Hunk 时，准确提取起始行号：
let mut old_start_line = None;
let mut new_start_line = None;

for (tag, old_opt, new_opt, _) in hunk_changes {
    if old_start_line.is_none() {
        if let Some(idx) = old_opt {
            old_start_line = Some(idx + 1);
        }
    }
    if new_start_line.is_none() {
        if let Some(idx) = new_opt {
            new_start_line = Some(idx + 1);
        }
    }
```

```rust
pub fn estimate_json_bytes(value: &serde_json::Value) -> usize {
    match value {
        serde_json::Value::Null => 4,
        serde_json::Value::Bool(b) => if *b { 4 } else { 5 },
        serde_json::Value::Number(_) => 8,
        serde_json::Value::String(s) => s.len() + 2,

        }
    }
```
