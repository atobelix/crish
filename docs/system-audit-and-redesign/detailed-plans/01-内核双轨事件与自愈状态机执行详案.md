### 1.2 目标架构核心指标与质量断言

1. **实时事件 0 延迟发射**：所有 `TurnStart`、`TurnEnd`、`ToolStart`、`ToolProgress`、`ToolEnd`、`MessageStart`、`MessageEnd` 在触发当下立即经 `LiveEventSink` 广播至 Tauri IPC，前端工具卡片与思考视口即时渲染；
2. **复合因果 Key 零颠簸（RUL-01）**：收口轨事件携带递增 `sequence`，到达前端后按复合 Key（`type:toolId` / `type:turnIndex`）执行 Commit Phase 元数据对齐，不重复插入节点，杜绝时间线闪烁；
3. **后台任务管理器 100% 连通**：`ToolContext.background` 与 `log_root` 完整接线，`background_task` 工具全指令（`list`/`status`/`read_log`/`send_input`/`kill`）即时可用，同步超限输出自动溢出落盘；
4. **Tool-Promise 三层自愈防暴毙（RUL-02）**：引入三层反向过滤规则，精确识别行动自白；若未发工具调用，状态机自动注入 Steering Nudge 驱动模型执行；自愈上限硬锁定为 2 次，超限安全收口，杜绝死循环；
5. **白名单准出契约**：仅在模型显式输出用户答复、用户主动 Cancel、或用尽 max_turns 时才收敛。

### 2.3 状态机数学模型与转移不变量定理

为确保长程任务绝不中途死锁或暴毙，定义 4 大状态机不变量定理：

$$\mathcal{S} = \langle \text{State}, \text{Context}, \text{Events}, \text{Invariants} \rangle$$

- **定理 I1（工具结果观测闭环不变量）**：
  $$\forall c \in \text{ToolCalls}, \exists ! m \in \text{Conversation} \text{ s.t. } m.\text{role} = \text{Tool} \land m.\text{tool\_call\_id} = c.\text{id}$$
  _证明要求_：任何工具调用（无论成功、失败、权限拒绝、审批超时或进程崩溃），必须生成 `AgentMessageRole::Tool` 并写入对话历史，严禁将其作为未捕获异常掐死状态机。

- **定理 I2（行动承诺推进不变量）**：
  $$\text{If } (\text{tool\_calls} = \emptyset \land \text{IsActionPromise}(\text{text}) \land \text{heal\_count} < 2) \implies \text{NextState} = \text{PreparingTurn}$$
  _证明要求_：当模型输出具有执行意图的文本但未产生结构化工具调用时，在未达 2 次硬上限前，禁止转移至 `Done`，必须转移至 `PreparingTurn` 并携带自愈 Nudge。

- **定理 I3（双轨因果复合键单调性）**：
  $$\text{Key}(\text{LiveEvent}) = \text{Key}(\text{TerminalEvent}) = \langle \text{Type}, \text{Identifier} \rangle$$
  _证明要求_：实时轨（`sequence = None`）与收口轨（`sequence = Some(n)`）对同一物理实体（工具调用或轮次）必须派生完全相同的复合 Key，收口轨事件仅用于更新持久化状态（Commit Phase），禁止重复创建视图节点。

- **定理 I4（白名单有限收敛性）**：
  $$\text{TerminalCondition} \iff (\text{IsUserResponse}(\text{text}) \lor \text{Aborted} \lor \text{TurnIndex} \ge \text{MaxTurns} \lor \text{HealCount} \ge 2)$$
  _证明要求_：系统收敛收场的条件严格限定在上述四项白名单内，排除了中间工具失败或格式微小偏差导致的非预期暴毙。

### 3.4 前后端复合因果 Key 契约与 Commit Phase 对齐

遵循主控 **RUL-01 权威裁决**，前端 `EventRouter.ts` 重构去重 Key 计算逻辑：

```typescript
// apps/crish-desktop/src/api/chat-bridge/EventRouter.ts 契约实现

export function buildEventDedupeKey(
  envelope: AgentEventEnvelope
): string | null {
  // 1. 持久化收口轨：带有 sequence 的事件，按全局 sequence 精确去重
  if (envelope.sequence != null) {
    return `seq:${envelope.sequence}`;
  }

  // 2. 实时流式增量（message-delta）：永远放行，绝不去重（根除 TheTheThe 乱码）
  if (envelope.event.type === 'message-delta') {
    return null;
  }

  // 3. 实时工具事件：按复合因果 Key (type:tool_call_id) 寻址与幂等
  if (
    envelope.event.type === 'tool-start' ||
    envelope.event.type === 'tool-end'
  ) {
    return `${envelope.event.type}:${envelope.event.callId}`;
  }

  // 4. 实时轮次事件：按复合因果 Key (type:turn_index) 寻址
  if (
    envelope.event.type === 'turn-start' ||
    envelope.event.type === 'turn-end'
  ) {
    return `${envelope.event.type}:${envelope.event.turnIndex}`;
  }

  return null;
}
```

- **Commit Phase 处理机制**：
  当收口轨事件（`sequence: Some(n)`）到达前端时，前端检测到对应 `callId` 的工具卡片或对应 `turnIndex` 的轮次容器已由实时轨预先创建，此时**仅执行状态同步（更新为 `status: 'completed'`、注入最终耗时与 token usage），绝不执行 DOM 节点重新插入**，彻底消除界面跳动与时间线颠簸。

## 五、`Tool-Promise` 意图自愈与白名单收口状态机（RUL-02 落地详案）

### 5.1 口头自白后中途暴毙现场与收敛陷阱根因

用户反馈：“AI 输出了【尝试单独调用 PowerShell 原生删除命令。】自白后，莫名其妙突然断掉了”。
**深层根因**：

1. 模型在遇到上一步工具报错后，在当前轮输出了口头解释与下一步行动自白，但由于推理模式或分步生成，本轮没有附带结构化的 Function Call；
2. 旧版 `streaming.rs` 检测到 `tool_calls.is_empty()`，直接派发 `E::NoToolCalls`；
3. `turn_complete.rs` 见 `tool_call_count == 0`，粗暴判定为“任务已全部完成的普通纯文本回复”，直接派发 `E::ShouldStop` 强行收场，导致系统半途暴毙。

### 5.3 意图侦测模式与关键词矩阵（`ToolPromiseDetector`）

在 `crates/session-loop/src/steering/strategy.rs` 中实现 `ToolPromiseDetector`：

````rust
// crates/session-loop/src/steering/strategy.rs

pub struct ToolPromiseDetector;

impl ToolPromiseDetector {
    /// 核心判定函数：返回 Some(action_snippet) 表示检测到行动承诺且通过三层过滤
    pub fn detect_action_promise(text: &str) -> Option<String> {
        let trimmed = text.trim();
        if trimmed.is_empty() {
            return None;
        }

        // ── 第一层过滤：排除教程与代码示例 ──
        if trimmed.contains("```markdown") || trimmed.contains("```json")
            || trimmed.contains("例如：") || trimmed.contains("示例如下：")
            || trimmed.contains("配置如下：") {
            return None;
        }

        // ── 第二层过滤：排除向用户反问与确认 ──
        if trimmed.contains("是否需要") || trimmed.contains("您希望")
            || trimmed.contains("请确认") || trimmed.ends_with('？')
            || trimmed.ends_with('?') || trimmed.contains("如需继续请") {
            return None;
        }

        // ── 第三层过滤：排除第三人称与过去历史描述 ──
        if trimmed.contains("上一轮中") || trimmed.contains("之前已经")
            || trimmed.contains("刚才尝试了") || trimmed.contains("失败原因是") {
            return None;
        }

        // ── 正向行动意图匹配（重点关注文本尾部 200 字符） ──
        let tail = if trimmed.len() > 300 {
            &trimmed[trimmed.len() - 300..]
        } else {
            trimmed
        };

        // 典型行动宣誓模式
        let action_patterns = [
            "尝试单独调用",
            "正在调用",
            "现在开始执行",
            "接下来使用",
            "准备运行",
            "尝试通过",
            "我将执行",
            "使用 PowerShell",
            "使用 shell_command",
            "重新运行",
        ];

        for pattern in &action_patterns {
            if let Some(pos) = tail.rfind(pattern) {
                let snippet = &tail[pos..];
                // 截取到句末标点
                let end_pos = snippet.find(['。', '！', '\n', '.']).unwrap_or(snippet.len());
                return Some(snippet[..end_pos].to_string());
            }
        }

        None
    }
}
````

```rust
    if let Some(snippet) = ToolPromiseDetector::detect_action_promise(&text) {
        if state.options.tool_promise_recovery_enabled
            && state.tool_promise_heals < state.options.max_tool_promise_heals
        {
            state.tool_promise_heals += 1;
            tracing::warn!(
                session_id = %state.session_id,
                heal_count = state.tool_promise_heals,
                snippet = %snippet,
                "检测到 AI 行动宣誓但未调用工具，触发 Tool-Promise 自愈推进"
            );

            // 构造针对性的 Steering Nudge 注入下一轮
            let nudge_prompt = format!(
                "【系统自动推进】：你刚刚在回复中表达了执行动作的意图（“{}”），但当前轮次未检测到结构化的工具调用。请立即调用相应的系统工具（如 `shell_command`、`write_file` 等）执行操作，或者给出明确针对用户的最终结论。",
                snippet
            );

            state.input_queue.enqueue_steer(AgentMessage::user_nudge(nudge_prompt));

            // 派发 NextTurn 继续驱动模型
            dispatch(state, E::NoProgressContinue)?;
            return Ok(HandlerOutcome::continue_run());
        }
    }
}
```

### 5.5 硬顶上限（最大 2 次自愈）防死循环保护与白名单准出契约

为防止极端情况下模型陷入持续输出口头承诺的死循环：

1. **硬上限锁定（Hard Ceiling = 2）**：`state.tool_promise_heals` 在单次 Run 内累计达到 2 次后，自愈闸门完全关闭；
2. **安全退出收敛**：达到上限后，状态机将不再注入 Nudge，而是安全派发 `E::NoToolCalls` -> `TurnComplete` -> `EndDecision::stop`，将当前文本作为最终回复安全呈现给用户，**绝不 panic、绝不无限循环、绝不报 S6 崩溃**。
