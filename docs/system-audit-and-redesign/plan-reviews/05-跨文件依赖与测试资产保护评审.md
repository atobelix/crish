## 二、第一部分：跨文件改动冲突与代码覆盖死锁审查

### 2.1 冲突一：`ToolCallOutput.tsx` 架构撕裂（DIM-05 vs DIM-07）

- **冲突文件**：`apps/crish-desktop/src/components/chat-tool-call/ToolCallOutput.tsx`
- **冲突详述**：
  - **DIM-05 §6.4** 将 `ToolCallOutput.tsx` 重构为结构化两段式容器，内部组合 `<ToolCallInputPane />`（入参表、CWD、CLI 命令行）与 `<ToolCallOutputPane />`（退出码、耗时、状态横幅、2000 行/256KB 视口、日志下载）；
  - **DIM-07 §6.3** 在提供 `ToolCallOutput.tsx` 的代码蓝图时，竟然给出了**基于旧版代码**的简易修改方案：直接在旧版单体 DOM 结构中将 `<button>在终端查看</button>` 替换为 `<button>在命令检查器中查看</button>`，其代码片段完全**未引入** DIM-05 的 `ToolCallInputPane` 与 `ToolCallOutputPane`！
- **后果评估**：
  - 若按照 DIM-07 的代码覆盖落盘，DIM-05 的两段式结构化分栏（包括输入参数表展示、Stdout/Stderr 区分诊断、耗时计算等）将被**100% 彻底冲毁覆盖**，发生严重架构倒退！
- **整改指令**：
  - `ToolCallOutput.tsx` 唯一架构主权归属于 **DIM-05**；DIM-07 涉及的“在命令检查器中查看”按钮及抽屉打开逻辑，必须作为子属性或回调集成进 DIM-05 的 `<ToolCallOutputPane />` 内部，DIM-07 **严禁**提供独立的 `ToolCallOutput.tsx` 顶层覆盖代码。

### 2.2 冲突二：`ChatAssistantMessageRow.tsx` 与思维链组件架构分裂（DIM-02 vs DIM-03）

- **冲突文件**：
  - `apps/crish-desktop/src/components/chat-message-row/ChatAssistantMessageRow.tsx`
  - `apps/crish-desktop/src/components/chat-message-row/MessageThinkingSection.tsx`
  - `apps/crish-desktop/src/components/chat-message/TimelineThoughtSection.tsx`
- **冲突详述**：
  - **DIM-02 §6.1 / §6.2** 彻底推翻了“顶部单一大思考块”的压平模式，在 `ChatAssistantMessageRow.tsx` 中移除了顶层 `<MessageThinkingBlock />` / `<MessageThinkingSection />`，下放给 `MessageContent.tsx` 中的交错时间线渲染器，并在 `components/chat-message/` 下创建了支持多步骤交错展开折叠的 `<TimelineThoughtSection />`；
  - **DIM-03 §3.3 / §4.2** 依然基于旧版的“顶部单一大思考块”模型编写代码蓝图，直接修改了 `components/chat-message-row/MessageThinkingSection.tsx`（添加 8k~12k 弹性视口、渐变遮罩、操作条与 `FullThoughtModal` 入口按钮），并假设其依然由 `ChatAssistantMessageRow.tsx` 顶层渲染！
- **后果评估**：
  - 若 DIM-02 删除了顶层思维链渲染，DIM-03 对 `MessageThinkingSection.tsx` 的全部修改将变成**无效死代码**；用户在交错时间线步骤中将无法看到 DIM-03 的 8k~12k 渐变遮罩与沉浸式查阅器按钮；
  - 若 DIM-03 强行保留顶层渲染，则会与 DIM-02 产生“双重思维链渲染”的灾难性 UI 重影！
- **整改指令**：
  - 废弃 `MessageThinkingSection.tsx` 的顶层挂载；将 DIM-03 的全部功能（8k~12k 自适应切片、渐变淡出遮罩、字数统计、`FullThoughtModal` 唤起按钮）与 DIM-02 的 `<TimelineThoughtSection.tsx>` **深度合并为单一组件**，统一置于 `apps/crish-desktop/src/components/chat-message/TimelineThoughtSection.tsx`，供 `MessageContent.tsx` 在交错时间线中按步骤调用。

### 2.3 冲突三：`thoughtInspectorStore.ts` 状态库接口命名与行为分歧（DIM-02 vs DIM-03）

- **冲突文件**：`apps/crish-desktop/src/store/thoughtInspectorStore.ts`
- **冲突详述**：
  - **DIM-02 §7.9** 定义的 Store 接口为：
    ```typescript
    interface ThoughtInspectorStore {
      isOpen: boolean;
      activeContent: string;
      turnIndex?: number;
      messageId?: string;
      openInspector: (params: {
        content: string;
        turnIndex?: number;
        messageId?: string;
      }) => void;
      closeInspector: () => void;
    }
    ```
  - **DIM-03 §3.4 / §5.2** 定义的 Store 接口为：
    ```typescript
    interface ThoughtInspectorStore {
      isOpen: boolean;
      fullThought: string;
      messageId: string;
      sessionId: string;
      activeTab: 'preview' | 'outline' | 'search';
      searchQuery: string;
      outline: ThoughtHeading[];
      openThoughtModal: (params: {
        messageId: string;
        sessionId?: string;
        fullThought: string;
      }) => void;
      closeThoughtModal: () => void;
    }
    ```
- **后果评估**：
  - Action 方法名严重分歧（`openInspector` vs `openThoughtModal`）；
  - 属性字段名冲突（`activeContent` vs `fullThought`）；
  - 导致 DIM-02 的 `<TimelineThoughtSection />` 编译失败或无法正常唤起 DIM-03 的 `<FullThoughtModal />`。
- **整改指令**：
  - 强制统一定义。统一命名为 `thoughtInspectorStore.ts`，主 Action 统一为 `openInspector(params: { messageId: string; sessionId?: string; content: string; turnIndex?: number })`，状态属性统一为 `content`，包含 `activeTab`、`searchQuery` 与 `outline`。

- **强制拆分重构方案**：
  - DIM-05 必须强制将 `toolCardPresenter.ts` 拆解为 `api/tool-presentation/` 目录下的 5 个高内聚子模块：

    5. `extractors/toolLabelSanitizer.ts`（安全清洗锁与定界符拦截，≤ 120 行）。

### 5.1 断层一：DIM-01 与 DIM-02 之间 `TurnStart` 事件 `messageId` 缺失

- **断层现象**：
  - DIM-02 在 `EventRouter.ts` 中针对 `turn-start` 事件定义的 Dedupe Key 为 `turn-start:${msgId}:turn-${turnIdx}`；
  - 但 DIM-01 §6.9 在 `prepare_turn.rs` 中发射的 `AgentEvent::TurnStart` 载荷仅包含 `turn_index: u32`，完全没有 `message_id`；
- **后果**：
  - 前端接收到事件时，`event.messageId` 为 `undefined`，Key 退化为 `turn-start:undefined:turn-1`，在多会话并发或单会话重连时发生去重错乱；
- **整改要求**：
  - DIM-01 必须在 `AgentEvent::TurnStart` 与 `AgentEvent::TurnEnd` 中显式携带 `message_id: Option<String>` 或 `run_id: String`，确保前后端因果 Key 字段对齐。
