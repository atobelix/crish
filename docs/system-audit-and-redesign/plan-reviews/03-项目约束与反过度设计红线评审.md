## 二、13 项反过度设计硬性红线逐条穿透审查

### 2.1 禁令 1~3：系统底座与持久化安全（沙箱/环形缓冲/单机共识）

#### 1. 禁令 1 审查：严禁跨平台 OS 内核级沙盒（Seatbelt / Seccomp / Cgroups）

- **规范标准**：桌面端应用无须引入操作系统内核 C 绑定（如 `macOS Seatbelt` 或 `Linux seccomp-bpf`）；仅保留 `CommandGatekeeper` 指令防爆网、Windows `Job Object`（`KILL_ON_JOB_CLOSE`）与前台用户审批。
- **方案审查（方案 02 §2.2 / 方案 06 §5.1）**：
  - 方案严格基于现有的 Rust `RegexSet` 与 AST 指令防爆网，未引入任何外部 C 动态沙盒驱动；
  - 进程树生命周期完全交由既有的 `process_tree` 与 Windows Job Object 管理；
  - **裁决**：✅ **严格合规**。

#### 2. 禁令 2 审查：严禁编写 Rust 端无锁环形缓冲区（`sab_ring_buffer`）与极端零拷贝

- **规范标准**：桌面大模型文本传输速率极低（10~50 Token/s，约 2 KB/s），彻底禁止自制 C 级别 SharedArrayBuffer RingBuffer，统一使用标准 Tokio `mpsc` 通道与 `Arc<AgentMessage>`。
- **方案审查（方案 02 §2.1 / 方案 03 §3.3）**：
  - 方案 02/03 全程基于 Tokio 异步任务、`tokio::sync::mpsc` 与 `Arc<RwLock<ModelCatalog>>` 标准 Rust 并发原语，完全无任何原生共享内存环形缓冲区设计；
  - **裁决**：✅ **严格合规**。

#### 3. 禁令 3 审查：严禁在单机桌面端引入分布式共识协议与两阶段提交（2PC / Raft / Paxos）

- **规范标准**：单机本地存储一致性一律基于「单写者模式 + Windows 3 阶段原子重命名写入 + SQLite WAL Group Commit + CAS 乐观版本号 (`WHERE rev = ?`)」，严禁套用分布式共识算法。
- **方案审查（方案 02 §2.1 / 方案 06 §5.1）**：
  - `profile-config.json` 采用基于文件锁与临时文件原子替换（`atomic_write`）的单写者模型；
  - SQLite 数据库维持标准 WAL 模式与本地 CAS 版本控制，未引入任何虚假 2PC 分布式事务；
  - **裁决**：✅ **严格合规**。

### 2.2 禁令 4~8：大模型协议与上下文治理（模型固定/禁止前置 DNS/禁止黑盒 Prompt 篡改/SSOT 单一真源/DPAPI 凭据隔离）

#### 1. 禁令 4 审查：严禁后台自动切换模型（废弃 `DynamicModelRouter` / `FallbackChain`）

- **规范标准**：用户在 UI 选定了什么模型，请求就固定使用该模型；发生 429/5xx 时仅在当前选定模型上做指数退避重试，严禁未经用户授权自动降级/切换模型。
- **方案审查（方案 02 §6.4 / 方案 03 §1.3）**：
  - 方案 02 第 49 行明确写明：“默认模型切换与引擎原子热重载流程：用户在 UI 选定模型后，请求固定使用该模型”；
  - 方案 03 第 130 行明确写明：“彻底杜绝后台静默切模型，错误时向用户抛出清晰选项与原地重试入口”；
  - **裁决**：✅ **严格合规**。

#### 2. 禁令 5 审查：严禁出站请求前发起 DNS A/AAAA 异步解析与公有后缀检查

- **规范标准**：取消 API 请求前的异步 DNS 预解析与公有后缀校验，以防误杀本地 Ollama（`http://localhost:11434`）或私有网关。
- **方案审查（方案 02 §3.2）**：
  - `provider_probe_ping` 原生探活命令直接调用 `reqwest::Client` 发送目标 URL，仅保留基础的 `http://` / `https://` 语法校验，移除了所有前置 DNS 解析逻辑，完美支持本地 localhost 与私有 IP；
  - **裁决**：✅ **严格合规**。

#### 3. 禁令 6 审查：严禁在 LLM 请求链路中加入黑盒「Prompt 意图重写与动态拦截链」

- **规范标准**：用户输入指令必须如实透明传入模型，所有切片注入与系统提示词在 UI/Trace 中完全可见。
- **方案审查（方案 03 §1.1 / 方案 06 §5.4）**：
  - 方案 03 保持 `useSlashSend.ts` 到 Rust `core_run_task` 的原始 Prompt 透传；
  - 移除了任何中间拦截重写层，仅保留显式斜杠命令分发（`/files`, `/terminal` 等客户端本地路由）；
  - **裁决**：✅ **严格合规**。

#### 4. 禁令 7 审查：注入到上下文的一切链路都必须可审计、可追踪，单一真相源（SSOT）

- **规范标准**：全链路可审计（精确绑定 `run_id`, `tool_call_id`, `occurred_at_ms`）；同一份会话状态与配置在内存中只能存在唯一权威真源。
- **方案审查（方案 02 §2.1 / 方案 06 §1.3）**：
  - 彻底废除前端 `localStorage.crish_provider_profiles_v1` 的真源地位，确立 Rust 引擎为全系统唯一权威真源；
  - 前端 `useProviderStore` 降级为纯响应式只读投影，彻底根除“三源漂移”；
  - **裁决**：✅ **严格合规**。

#### 5. 禁令 8 审查：多 Provider 凭据零残留与安全隔离

- **规范标准**：凭据统一基于 OS Keychain / Windows DPAPI 加密存储；前端下发列表绝对禁止包含明文 API Key，仅下发 `hasKey` 与 `apiKeyLast4`；删除服务商必须级联清除密钥文件。

## 五、原生 O(1) 优雅性与杜绝打补丁审查

评审重点排查方案中是否含有“魔术数字补偿”、“坐标遍历测距”、“定时器轮询延时”等打补丁坏味道：

### 5.1 浮层定位：原生 O(1) 防御谓词取代 DOM 轮询与定时补偿

- **历史坏味道**：部分方案试图通过 `setTimeout(..., 50)` 或 `requestAnimationFrame` 轮询检查 DOM 是否已经渲染出来，若未渲染则加一个固定偏移量补偿；
- **方案 05 的优雅解**：
  采用严密的纯逻辑数学前置谓词：
  ```typescript
  export function isValidFloatingRect(
    rect: DOMRect | null | undefined
  ): boolean {
    if (!rect) return false;
    // 当元素 display: none、处于未挂载首帧或全零时，绝对禁止挂载 Portal
    if (
      rect.width <= 0 &&
      rect.height <= 0 &&
      rect.top === 0 &&
      rect.left === 0
    ) {
      return false;
    }
    return true;
  }
  ```
  在几何计算前直接 $O(1)$ 拦截，从物理源头上扼杀 `(8px, 8px)` 钳位坍塌，零轮询、零定时器。

### 5.2 曲率阶梯：原生几何公理 $R_{\text{in}} = \max(0, R_{\text{out}} - P)$ 取代魔术数字

- **历史坏味道**：随意指定 `border-radius: 5px`、`7px`、`9px`，导致嵌套子元素刺破容器外壳；
- **方案 05 的优雅解**：
  确立全系统唯一的 4 级曲率阶梯代数方程：
  $$R_{\text{inner}} = R_{\text{outer}} - P_{\text{padding}}$$
  - 容器外壳：`var(--radius-2xl)` ($12\text{px}$)
  - 内部选区：$12\text{px} - 6\text{px} = 6\text{px}$ (`var(--radius-md)`)
  - 胶囊药丸：统一使用 `var(--radius-full)` ($9999\text{px}$)
    完全基于 CSS Design Tokens 声明式渲染，彻底清除散落各处的魔术像素。

---

### 5.3 状态机驱动：显式 Anchor + 原生受控事件流取代 `cloneElement` 劫持

- **历史坏味道**：`Menu.tsx` 动态解构 `children`，使用 `React.cloneElement` 强行注入内联匿名 `ref`，导致 React 19 报错与 Ref Null 瞬态时序撕裂（产生 Quad-Click 现象）；
- **方案 05 的优雅解**：
  彻底抛弃 `asChild` 暴力克隆，改用 Radix 原生推荐的 **显式 Anchor 锚定模式**：
  ```tsx
  // 显式 Anchor 锚定，按钮自主持有 onClick 与 ref
  <button ref={btnRef} onClick={handleToggle}>
    {children}
  </button>
  <Popover.Anchor virtualRef={btnRef} />
  ```
  通过受控状态机驱动，消除事件争抢，完美兼容 React 19。

---

### 5.4 布局自适应：CSS Container Query 取代 JS Resize 监听

- **历史坏味道**：在 `FilesCard` 中使用 `window.addEventListener('resize')` 或频繁 setState 监听宽度来切换单双栏；
- **方案 04 的优雅解**：
  采用现代 CSS 容器查询（Container Queries）：
  ```css
  .filesContainer {
    container-type: inline-size;
  }
  @container (max-width: 440px) {
    .filesListPane {
      width: 100%;
    }
    .filesDetailPane {
      display: none;
    }
  }
  ```
  完全由浏览器排版引擎原生接管，零 JS 性能开销，零布局抖动。
