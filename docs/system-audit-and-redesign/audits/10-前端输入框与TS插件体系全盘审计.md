## 一、审计执行概览与架构定性

本次审计针对 `chat-composer` 输入框纯净化及 `plugins` TypeScript 插件微内核体系进行了全量只读源码与测试用例扫描。

### 核心结论摘要

1. **输入框纯净化方面**：Tiptap 输入层虽然在 `StarterKit` 禁用了块级排版节点，但在 `TiptapSlashMenu`、`serialization/`、`AiCommandSlashExtension.ts` 中**残留大量历史排版代码、死事件与定义漂移**；且斜杠指令（`/clear`, `/stop`, `/compact`, `/settings` 等）存在**未接线的空派发事件**，点选后直接作为 prompt 误发给后端 LLM。
2. **几何防漂移方面**：`safeCursorAnchor.ts` 的四级备援与视口边缘翻折算法在独立函数层面逻辑清晰，但在实际与 `SlashExtension.ts` 和 `TiptapSlashMenu.tsx` 串联时，由于 `new DOMRect()` 转型，**关键字段 `suggestedSide` 被直接丢弃**，导致所有视口边缘自适应翻折失效，恒定回退为默认 `'top'`。
3. **TS 插件微内核体系方面**：`apps/crish-desktop/src/plugins/` 处于**架构孤岛状态（Phantom Scaffolding）**。四大官方插件并未承载真正的业务逻辑，主应用的文档、浏览器、后续建议和设置中心均绕过了 `PluginRegistry` 和 `usePluginStore`；且 `PluginContext.invokeIpc` 存在**未声明权限通道默认放行的安全红线漏洞**。
4. **测试有效性方面**：测试套件虽然通过（142 passed），但存在严重的**假绿灯、孤岛断言及海量 React `act(...)` 控制台警告**，未能覆盖真实链路上的核心断层。

## 三、维度二：几何防 (0,0) 漂移与 safeCursorAnchor 严密性审计

### 3.1 DOMRect 实例化抹除 suggestedSide 导致翻折算法退化

#### 发现 6：`SlashExtension.ts` 转换 `DOMRect` 时丢弃了 `suggestedSide` 属性

- **代码位置**：
  - [`apps/crish-desktop/src/components/chat-composer/SlashExtension.ts:150-161`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/SlashExtension.ts#L150-L161)
  - [`apps/crish-desktop/src/components/chat-composer/TiptapSlashMenu.tsx:218-247`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/TiptapSlashMenu.tsx#L218-L247)
- **事实与证据**：
  1. 在 `SlashExtension.ts` 中计算安全锚点并返回给 Tiptap Suggestion：
     ```ts
     const safeAnchor = calculateSafeCursorAnchor({
       rawCursorRect: rawBox,
       editorViewDom: view.dom,
     });
     if (safeAnchor) {
       lastCachedBox = new DOMRect(
         safeAnchor.left,
         safeAnchor.top,
         safeAnchor.width,
         safeAnchor.height
       );
       return lastCachedBox;
     }
     ```
     这里的 `safeAnchor` 是 `SafeAnchorRect` 类型，包含 `suggestedSide: 'top' | 'bottom'`。然而将其封装进 `new DOMRect(...)` 时，`suggestedSide` 与 `nearEdge` 字段被**完全丢弃**。
  2. 在 `TiptapSlashMenu.tsx` 接收到 `clientRect()` 返回的 `DOMRect` 后：
     ```ts
     const side: 'top' | 'bottom' =
       'suggestedSide' in anchor &&
       (anchor.suggestedSide === 'bottom' || anchor.suggestedSide === 'top')
         ? anchor.suggestedSide
         : 'top';
     ```
     由于 `anchor` 是一个标准的 `DOMRect` 对象，`'suggestedSide' in anchor` 恒为 `false`！
- **后果与危害**：
  `safeCursorAnchor.ts` 中精心编写的 `computeViewportEdgeAlignment`（距离顶部 < 120px 时智能翻折为 `bottom`）在运行期**100% 被架空**，`side` 永远恒定为 `'top'`，视口顶部翻折机制失效。

### 3.3 客户端坐标计算与弹层挂载的双重冗余计算

### 3.4 CJK IME 组合态初次触发坐标抖动与缓存穿透风险

#### 发现 9：`lastCachedBox` 初始为 null 时，IME 期间坐标直接返回 null 导致弹层关闭

- **代码位置**：[`apps/crish-desktop/src/components/chat-composer/SlashExtension.ts:125, 143-146`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/SlashExtension.ts#L125)
- **事实与证据**：
  ```ts
  let lastCachedBox: DOMRect | null = null;
  // ...
  if (view.composing || (view as any).input?.composing) {
    return lastCachedBox;
  }
  ```
- **问题分析**：
  若用户通过输入法直接打出 `/`（例如通过中文输入法输入 `/` 触发 `onStart`），在首帧 `lastCachedBox` 尚为 `null` 时若 `view.composing` 为 `true`，`clientRect()` 会直接返回 `null`；

  ```ts

    return null;
  }
  ```
  直接触发熔断返回 `null`，导致斜杠菜单在中文输入法首字输入时无法正常弹出。

### 4.4 IPC 权限白名单「默认放行」高危安全漏洞

#### 发现 13：`PluginContext.invokeIpc` 遇到未知 Channel 时跳过鉴权（Open-by-default）

- **代码位置**：[`apps/crish-desktop/src/plugins/types.ts:177-208`](file:///c:/Software/conex/apps/crish-desktop/src/plugins/types.ts#L177-L208)
- **事实与证据**：
  ```ts
  public async invokeIpc<TResult = unknown>(channel: string, payload?: unknown): Promise<TResult> {
    const requiredPermission = this.resolveRequiredPermission(channel);
    const declaredPermissions = this.manifest.permissions ?? [];

    if (
      requiredPermission &&
      !declaredPermissions.includes(requiredPermission)
    ) {
      throw new Error(`[PluginSecurityError] ...`);
    }
    return (await this.hostIpc(channel, payload)) as TResult;
  }

  private resolveRequiredPermission(channel: string): string | null {
    if (channel.startsWith('fs:')) return 'fs:access';
    if (channel.startsWith('conex-markdown:') || channel.startsWith('markdown:')) return 'markdown:render';
    if (channel.startsWith('browser:')) return 'browser:control';
    if (channel.startsWith('network:')) return 'network:access';
    if (channel.startsWith('computer:')) return 'computer:control';
    if (channel.startsWith('screen:')) return 'screen:capture';
    if (channel.startsWith('assistant:')) return 'assistant:suggestions';
    return null; // 未知 channel 返回 null！
  }
  ```
- **安全漏洞剖析**：
  - 如果一个插件调用了高危 IPC 通道，例如 `system:execute_command`、`auth:steal_token`、`kernel:raw_eval`；
  - `resolveRequiredPermission` 返回 `null`；
  - `if (requiredPermission && ...)` 条件判断为 `false`；
  - 鉴权逻辑被直接绕过，`hostIpc` 直接执行！
- **违背原则**：
  严重违背安全基线中要求的「默认拒绝 (Default-Deny) / 最小权限原则」。
