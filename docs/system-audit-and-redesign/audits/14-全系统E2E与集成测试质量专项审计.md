- **核心漏洞**：`ime-composition.spec.ts` 与 `keyboard-navigation.spec.ts` **被直接从冒烟列表中剔除**！

## 三、假阳性、错误守卫与魔术数字补偿排查

### 3.1 条件分支包庇空 Pass（False Green 逃逸）

在多个 E2E 测试文件中发现了严重的「条件判断包庇」反模式：当被测 UI 组件未渲染或处于异常状态时，测试未抛出断言失败，而是直接跳过测试体并输出绿灯！

#### 案例 1：`ui-store-invariants.spec.ts` 中极其恶劣的条件断言逃逸

审查 [`tests/e2e/ui-store-invariants.spec.ts:143-175`](file:///c:/Software/conex/tests/e2e/ui-store-invariants.spec.ts#L143-L175)：

```typescript
// 03. Tab 页切换与 Store 不变量监控
const chatTab = page.locator('[data-testid="tab-chat"]').first();
if (await chatTab.isVisible()) {
  await clickAndAssertInvariants(
    page,
    '[data-testid="tab-chat"]',
    '切换到对话 Tab'
  );
}

const addBtn = page.locator('[data-testid="add-panel-button"]').first();
if (await addBtn.isVisible()) {
  await clickAndAssertInvariants(
    page,
    '[data-testid="add-panel-button"]',
    '点击添加面板按钮'
  );
  const terminalItem = page
    .locator('[data-testid="add-panel-item-terminal"]')
    .first();
  if (await terminalItem.isVisible()) {
    await clickAndAssertInvariants(
      page,
      '[data-testid="add-panel-item-terminal"]',
      '选择打开终端面板'
    );
  }
}

// 04. 模型选择主交互与 Store 频次断言
const modelBtn = page.locator('[data-testid="model-selector-button"]').first();
if (await modelBtn.isVisible()) {
  await clickAndAssertInvariants(
    page,
    '[data-testid="model-selector-button"]',
    '点击模型选择器按钮'
  );
  const modelMenu = page.locator('[data-testid="model-picker-menu"]').first();
  if (await modelMenu.isVisible()) {
    await expect(modelMenu).toBeVisible();
  }
}
```

- **致命漏洞**：如果整个前端界面白屏、或者 `tab-chat`、`add-panel-button`、`model-selector-button` 因 React 报错根本没有渲染出来，`isVisible()` 返回 `false`，所有的 `if` 分支全部跳过，测试用例以 **0 断言、0 操作** 顺利通过并在 CI 中显示绿色！
- **判定**：这是典型制造「虚假安全感」的逃逸测试代码，必须立刻重构为强制的 `await expect(locator).toBeVisible()` 前置断言！

#### 案例 2：`console-errors.spec.ts` 的条件断言

审查 [`tests/e2e/console-errors.spec.ts:26-31`](file:///c:/Software/conex/tests/e2e/console-errors.spec.ts#L26-L31)：

```typescript

  console.error('RUNTIME ERRORS DETECTED:', errors);
  expect(errors.length).toBe(0);
} else {
  console.log('NO RUNTIME ERRORS DETECTED!');
```

- **漏洞**：当页面无错误时，`expect` 根本不会被调用。虽然 Playwright 允许无断言通过，但这破坏了测试结果中关于断言计数的精确可信度。必须统一采用无条件 `expect(errors).toEqual([])`。

#### 案例 3：`mirror-detect.spec.ts` 多重 `test.skip` 掩盖未交付状态

审查 [`tests/e2e/webview/mirror-detect.spec.ts:23, 42, 63, 78`](file:///c:/Software/conex/tests/e2e/webview/mirror-detect.spec.ts#L23)：
