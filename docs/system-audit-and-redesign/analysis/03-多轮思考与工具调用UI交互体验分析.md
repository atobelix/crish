# 多轮思考与工具调用 UI 交互体验深度分析报告

**分析师角色**：多轮思考与工具调用 UI 交互体验分析师
**被分析模块**：`apps/crish-desktop/src/components/chat-message-row/`、`chat-message/`、`chat-tool-call/` 及相关 API / 数据流管道
**用户痛点反馈**：

> _“以及中间的思考内容怎么没看到呢。按理来说，中间过程也是会有思考的。 我看现在是全部的任务都完成了，并输出总结了才会显示呢，这个体验也太差了。”_

## 一、四大核心问题深度审查与代码级证据

### 1. 展开/收起状态审查（`MessageThinkingSection.tsx` & `ChatAssistantMessageRow.tsx`）

#### (1) 流式期间（`status === 'processing'` / `isThinkingMsg === true`）

- **缺陷 A：4 行严重夹痛**（`ChatMessageRow.module.css:380-389`）：
  ```css
  .thinkingFoldBody {
    max-height: calc(var(--font-size-sm) * 1.5 * 4); /* 仅 4 行！约 84px */
    overflow-y: auto;
  }
  ```
  现代大模型 Extended Thinking / Reasoning（如 DeepSeek-R1、Claude 3.7 Sonnet）动辄几百行思考，用户只能在仅有 84px 高的微型缝隙中查看。
- **缺陷 B：无实时追尾滚动（No Auto-Scroll）**：
  `MessageThinkingSection.tsx` 中 `{thinkingBudget.text}` 只是静态放入 `<div>`，没有任何针对 `scrollTop = scrollHeight` 的侦听或 `useLayoutEffect` 驱动。当后续几百行思考 token 快速生成时，滚动条保持在最顶部（`scrollTop = 0`），用户视口停留在最初的几句话，以为思考卡住了。
- **缺陷 C：流式交互硬锁死**（`MessageThinkingSection.tsx:44`）：
  ```tsx
  onClick={() => {
    if (isThinkingMsg) return; // 思考中禁止用户点击折叠/展开
    setThinkingOpen((v) => !v);
  }}
  ```
  用户不仅无法手动收起，也无法自主控制高度。

#### (2) 流式结束后（`status !== 'processing'`）

- **缺陷 D：骤然闭合断崖**（`ChatAssistantMessageRow.tsx:202-205`）：
  ```tsx
  useEffect(() => {
    if (isThinkingMsg) setThinkingOpen(true);
    else setThinkingOpen(false); // 👈 流式一旦结束，立即强制折叠为 false！
  }, [isThinkingMsg, msg.id]);
  ```
  当所有工具执行完毕、总结正文输出的瞬间，`isThinkingMsg` 变为 `false`，思考块**立即收拢闭合**。
  - 用户在流式中因为 4 行限制 + 无自动滚动没能看到内容；
  - 任务刚结束，思考内容瞬间折叠消失，只留下底部大段 Markdown 总结。

### 2. 多轮思考在时间线中的展示逻辑审查（Timeline & Interleaving）

#### (1) 多轮思考被压平为单一字符串

- **数据面**：`SessionMessage.thinking`（`types.ts`）与 `StreamEntry.thinking`（`streamingStore.ts`）均设计为单一字符串字段 `thinking?: string`。
- 多轮 Agent 经历：`Round 1 思考 -> Call Tool 1 -> Tool 1 Result -> Round 2 思考 -> Call Tool 2 -> ...`。所有轮次的思考被简单无界拼接在 `state.assistantThought` 中。

#### (2) 时间线规范化器完全丢失思考块

- 检查 `apps/crish-desktop/src/api/tool-presentation/timelineNormalizer.ts:204-270`（`buildAssistantTimeline`）：
  ```ts
  for (const b of blocks) {
    if (b.type === 'text') {
      flushTools();
      items.push({ kind: 'text', content: c, key: `text-${xi++}` });
    } else if (b.type === 'tool_call' && b.id) {
      toolBuf.push(tc);
    }
    // 🔴 严重断层：完全没有对 b.type === 'thought' 的处理！直接被忽略并丢弃！
  }
  ```
- **后果**：整个多轮会话被渲染为：
  `[顶部一个巨大的合并思考块]` -> `[中间一堆工具卡片]` -> `[底部最终 Markdown 正文]`。
  用户根本看不到中间各步工具调用前后的独立思考推理过程！

### 3. 工具调用卡片（`CompactToolRow.tsx` / `ToolCallOutput.tsx`）审查

#### (1) 运行中（`running`）状态审查

- **代码硬编码禁展**（`toolCardPresenter.ts:348-355`）：
  ```ts
  export function toolHasExpandableBody(tc: MessageToolCall): boolean {
    if (tc.status === 'running' || tc.status === 'pending_approval') return false; // 👈 硬限制！
    ...
  }
  ```
- **缺陷**：工具在运行期间（如执行时长 5~30s 的测试、搜索、构建命令）：
  1. 卡片处于单行静态不可点击状态，光标为 `cursor: default`；
  2. 用户无法点开查看该工具完整的输入参数（入参 JSON、执行目标路径等）；
  3. 用户无法看到工具的实时输出流（stdout 增量日志），只能看着一个转圈动画干等。

### 核心改造要点：

1. **思考容器高度放宽 + 自动追尾滚动（Sticky Follow-Scroll）**：
   - 增加 `useLayoutEffect` 驱动的追尾吸底滚动；
   - CSS 高度放宽到 260px（Live）与 480px（展开态）；
2. **解除运行态工具展开限制**：
   - `toolHasExpandableBody` 对 `running` 状态且带参数或输出的工具放行展开；
3. **交错式思维链时间线改造**：
   - 扩展时间线模型支持 `thought` 节点，按真实时序在工具前后穿插渲染各阶段思考。
