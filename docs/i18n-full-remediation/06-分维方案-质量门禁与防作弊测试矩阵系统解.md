## 摘要与战役核心裁决

根据用户明确指示：“**不允许偷懒和作弊，需要有审计，确保整个工作流程都不偷懒**”。在全仓国际化改造战役中，若仅靠口头承诺与人工肉眼抽查，子 Agent 极易通过“将中文直接拷贝到英文包中冒充对齐”、“滥用忽略注释隐藏硬编码”、“字符串裸拼接破坏语序”、“虚假单测断言”等手段糊弄过关。

本方案基于 Phase 1 深度勘察报告（[`06-质量门禁与防回归自动化测试矩阵勘察.md`](file:///c:/Software/conex/docs/i18n-full-remediation/problems/06-质量门禁与防回归自动化测试矩阵勘察.md)）的实测数据与代码级证据，制定全流程刚性防作弊质量门禁、双轨拦截机制与立体测试矩阵的系统性终极解决方案。

### 核心决议与突破点

1. **源码零硬编码中文扫描器（`scripts/check-i18n-hardcoded.mjs`）**：
   - 采用 **“正则预检快筛 + TypeScript Compiler API (`ts.createSourceFile`) AST 深度语义遍历”** 的两段式混合动力引擎，实测全仓 420 个生产 TSX 文件扫描耗时严格压制在 **< 150ms**；
   - 建立 **基线棘轮（Baseline Ratchet）** 机制，将存量 319 个文件的硬编码行数登记于 `docs/i18n-full-remediation/基线记录/i18n-hardcoded-baseline.md`，**只许单向递减收敛，新增硬编码直接拦截阻断（exit 1）**；
   - 制定严格的单行抑制注释语法（`/* i18n-allow: <正当理由> */`）与专有名词白名单（DeepSeek, Qwen 等），严禁文件级通配豁免。
2. **词典 100% 对称性与纯度断言扫描器（`scripts/check-i18n-symmetry.mjs`）**：
   - 动态扫描 `locales/` 构建 $N \times N$ 语言对齐校验矩阵；
   - **反作弊语言纯度刚性断言**：非中文语言包（如 `en-US`）严禁包含任何汉字（`[\u4e00-\u9fff]`），彻底封死直接拷贝中文糊弄单测的作弊路径；
   - **插值参数恒等性断言**：双语同一 key 的 `{param}` 占位符集合必须 100% 严格一致；
   - 刚性拦截空字符串、纯空白与敷衍性占位文本（`TODO`, `TBD`, `test` 等）。
3. **未消费死词条扫描器（`scripts/check-i18n-unused-keys.mjs`）**：
   - 扫描词典中定义但源码中未引用的废弃词条，防止虚报完成度与垃圾沉淀；
   - 联动 [`packages/shared-types/src/errors/info.ts`](file:///c:/Software/conex/packages/shared-types/src/errors/info.ts) 中的 105 个核心错误码及动态 Tab 规则，杜绝误报。
4. **CI 流水线与 Pre-commit 刚性集成**：
   - 将扫描器无缝织入 `.husky/pre-commit`（执行开销 < 180ms）与 `package.json` 的 `npm run check:desktop`；
   - 联动 [`scripts/check-guard-system.mjs`](file:///c:/Software/conex/scripts/check-guard-system.mjs) 实施“守卫防御”，严格恪守 [`AGENTS.md`](file:///c:/Software/conex/AGENTS.md) §1.7 **禁止 `--no-verify` 铁律**。
5. **7 大作弊偷懒模式攻防矩阵与双盲交叉审计协议**：
   - 全面解构“伪翻译拷贝、滥用抑制注释、字符串拼接伪国际化、三元硬编码分支、占位符敷衍、排版截断视盲、虚假测试断言”并配备自动化检测武器；

## 二、门禁一：源码零硬编码中文扫描器（`scripts/check-i18n-hardcoded.mjs`）

### 2.1 混合动力引擎架构设计

在全仓 420 个生产 TSX 文件上，纯 AST 遍历需耗时约 412ms，而纯正则扫描虽仅需 18ms 但无法区分 UI 属性与代码逻辑。
因此，扫描器采用 **“正则预检快筛 + TypeScript Compiler API (`ts.createSourceFile`) AST 深度语义遍历”** 的两段式混合动力引擎：

```
文件进入检查
     │
     ▼
[Step 1: 正则极速预检 (18ms)] ─── 不含中文字符 ───► [直接放行 (耗时 0.04ms/文件)]
     │
     ▼ 命中中文字符
[Step 2: TypeScript AST 语义深检]
     │
     ├── 1. 过滤 JsxText (<div>中文</div>) ──► 捕获违规
     ├── 2. 检查 UI 属性 (title="中文", placeholder="中文", aria-label="中文") ──► 捕获违规
     ├── 3. 检查数据对象属性 (label: "中文", text: "中文", message: "中文") ──► 捕获违规
     ├── 4. 检查是否处于 isInsideNonUiContext / 抑制注释 / 白名单 ──► 放行
     └── 5. 比对 Baseline Ratchet ──► 超出基线报错拦截 (exit 1)
```

### 2.2 AST 节点精准捕获判据

扫描器基于 TypeScript Compiler API 精确遍历以下 AST 节点，严密覆盖所有用户可感知界面元素：

1. **`ts.isJsxText(node)`**：
   捕获 JSX 标签间的裸文本节点，例如：
   ```tsx
   <Button>确定</Button>        // ❌ 违规捕获：JsxText 含有 "确定"
   <div>正在同步...</div>       // ❌ 违规捕获：JsxText 含有 "正在同步..."
   ```
2. **UI 专属属性 `ts.isJsxAttribute(node)`**：
   捕获面向用户的核心 UI 属性集合 `UI_ATTRS`：
   `title`, `placeholder`, `aria-label`, `aria-description`, `aria-roledescription`, `alt`。
   不管是纯字符串字面量还是表达式容器，均予以拦截：
   ```tsx
   <input placeholder="请输入项目名称" />               // ❌ 违规捕获：UI 属性字面量
   <span aria-label={loading ? "加载中" : "就绪"} />   // ❌ 违规捕获：UI 属性表达式中的中文
   ```
3. **数据配置字段 `ts.isPropertyAssignment(node)`**：
   捕获在常量数组、下拉选项、菜单配置中常见的文案字段 `DATA_COPY_KEYS`：
   `label`, `title`, `description`, `placeholder`, `message`, `reason`, `text`, `summary`, `subtitle`, `helper`, `empty`, `hint`。
   ```tsx
   const options = [{ label: '全部模型', value: 'all' }]; // ❌ 违规捕获：配置字段 label 含有中文
   ```
4. **字符串与模板字面量 `ts.isStringLiteral(node)` / `ts.isTemplateExpression(node)`**：
   检查处于业务逻辑中的中文字符串，排除非 UI 场景后予以捕获。

### 2.3 智能非 UI 上下文放行机制（防误报）

为了杜绝误报，扫描器实现严密的上下文嗅探逻辑（`isInsideNonUiContext`）：

- **翻译函数放行（`isInsideTCall`）**：调用 `t('key', '中文兜底')` 或 `t('key')` 中的参数允许出现中文（作为 fallback）；
- **富文本组件放行（`isInsideTrans`）**：`<Trans i18nKey="...">` 内部的结构化模板放行；
- **非 UI JSX 属性放行（`NON_UI_JSX_ATTRS`）**：
  `className`, `class`, `style`, `id`, `key`, `htmlFor`, `for`, `href`, `src`, `viewBox`, `fill`, `d`, `path`, 以及所有以 `data-*` 开头的属性；
- **技术代码块放行**：处于 `<pre>`, `<code>`, `<samp>`, `<kbd>` 标签内部的文本直接放行；
- **底层工具调用放行**：`console.log`, `console.warn`, `console.error`, `fetch`, `encodeURIComponent`, `JSON.stringify`, `new RegExp(...)` 等系统级调用中的中文字符串直接放行。

### 2.4 单行显式抑制规范与防滥用机制

为了防止开发者或 Agent 滥用抑制注释逃避国际化，确立以下铁律：

1. **严禁全局/文件级通配豁免**：禁止使用 `/* eslint-disable i18n */`、`/* i18n-ignore-all */` 或在 `package.json` 中配置大面积文件豁免；
2. **仅允许单行显式理由抑制**：格式必须为：
   ```tsx
   // 行内注释形式
   {
     /* i18n-allow: 国内大模型专有品牌词 */
   }
   <span>文心一言</span>;

   // 或单行代码注释形式
   const name = '通义千问'; // @i18n-allow: 国内大模型专有品牌词
   ```
   **语法要求**：`i18n-allow:` 冒号后必须包含 **大于 3 个字符的具体理由**。空的 `/* i18n-allow */` 将被扫描器视为无效并直接拦截！

### 2.5 品牌与技术专有名词内置白名单

扫描器内置技术名词与品牌词白名单，对以下词条自动放行，无需手写抑制注释：

- **AI 厂商与模型品牌**：
  `DeepSeek`, `Qwen`, `百度`, `文心一言`, `通义千问`, `智谱AI`, `月之暗面`, `MiniMax`, `零一万物`, `商汤科技`, `百川智能`, `讯飞星火`, `Kimi`, `Claude`, `OpenAI`, `ChatGPT`, `Grok`, `Ollama`, `Gemini`, `Anthropic`, `Mistral`；
- **技术标准与系统词**：

### 2.6 基线棘轮机制（Baseline Ratchet）

由于当前有 319 个文件包含未国际化的硬编码中文，若直接开启零容忍全阻断将导致提交瞬间瘫痪。因此，采用成熟的 **基线棘轮（Baseline Ratchet）** 机制推进收敛：

1. **基线记录文件**：`docs/i18n-full-remediation/基线记录/i18n-hardcoded-baseline.md`。
   格式采用带标记区的严密键值格式：
   ```markdown
   # i18n 源码硬编码中文门禁基线

   > 由 `node scripts/check-i18n-hardcoded.mjs --update` 生成/刷新（仅允许收紧）。
   > 语义：实测 > 基线 → FAIL；实测 ≤ 基线 → 通过。存量按战役波次递减清零。

   <!-- BASELINE_START -->

   apps/crish-desktop/src/components/chat-card/ChatCard.tsx 12
   apps/crish-desktop/src/components/chat-composer/ChatComposer.tsx 28
   apps/crish-desktop/src/components/settings/SettingsAppearanceTab.tsx 8
   <!-- BASELINE_END -->
   ```
2. **棘轮单向收紧铁律**：
   - **新增文件零容忍**：未在基线中的文件一旦出现硬编码中文，门禁直接报错阻断（`exit 1`）；
   - **存量超标阻断**：若基线中文件的当前硬编码数 > 基线记录数，门禁直接报错阻断；
   - **`--update` 只降不升**：执行 `--update` 时，仅当所有文件的当前违规数 $\le$ 基线数且总违规数减少时才允许写回；**严禁抬高基线掩盖退化**！
   - **基线缺失报错**：禁止静默建线（Silent Baseline Pass），基线文件不存在直接报错退出。
3. **FAIL 五元报错标准输出**：
   对齐本仓规范，拦截时输出五元结构化指引：
   `[check-i18n-hardcoded] 源码硬编码中文 · <文件路径>:<行号> · 当前实测值 N 处 · 基线阈值 M 处 · 正确做法：将中文抽取至 locales/ 并在组件中使用 t('key') 消费`。

function toPosix(p) {
  return p.split(sep).join('/');
}

// 递归收集目标源文件
function collectSourceFiles(dirOrFile, out = []) {
  const fullPath = resolve(REPO_ROOT, dirOrFile);
  if (!existsSync(fullPath)) return out;

  const stat = statSync(fullPath);
  if (stat.isFile()) {
    if (fullPath.endsWith('.tsx') || fullPath.endsWith('.ts')) {
      const posix = toPosix(fullPath);
      if (!EXCLUDE_PATTERN.test(posix)) out.push(fullPath);
    }
    return out;
  }

  for (const entry of readdirSync(fullPath)) {
    const child = join(fullPath, entry);
    const posix = toPosix(child);
    if (EXCLUDE_PATTERN.test(posix)) continue;

    const childStat = statSync(child);
    if (childStat.isDirectory()) {
      collectSourceFiles(child, out);
    } else if (child.endsWith('.tsx') || child.endsWith('.ts')) {
      out.push(child);
    }
  }
  return out;
}

// 剥离注释并保持换行结构（用于 Stage 1 极速预检）
function stripCommentsKeepLines(code) {
  return code
    .replace(/\/\*[\s\S]*?\*\//g, (match) =>
      '\n'.repeat((match.match(/\n/g) || []).length)
    )
    .replace(/\/\/[^\n]*/g, '');
}

// 检查是否包含有效单行抑制注释
function hasValidSuppressionComment(sf, node) {
  const fullText = sf.getFullText();
  const nodeStart = node.getStart(sf);
  const lineStart = sf.getPositionOfLineAndCharacter(
    sf.getLineAndCharacterOfPosition(nodeStart).line,
    0
  );
  const lineText = fullText.slice(lineStart, node.getEnd());

  // 匹配 /* i18n-allow: <理由> */ 或 // @i18n-allow: <理由>
  const match = lineText.match(
    /(?:\/\*\s*i18n-allow:\s*([^\*\/]+)\*\/|\/\/\s*@?i18n-allow:\s*([^\n]+))/
  );
  if (match) {
    const reason = (match[1] || match[2] || '').trim();
    if (reason.length >= 2) return true; // 具备有效正当理由
  }
  return false;
}

// 检查当前节点是否处于翻译函数 t() 内部
function isInsideTCall(node) {
  let curr = node.parent;
  while (curr) {
    if (ts.isCallExpression(curr)) {
      const expr = curr.expression;
      if (ts.isIdentifier(expr) && expr.text === 't') return true;
      if (ts.isPropertyAccessExpression(expr) && expr.name.text === 't')
        return true;
    }
    curr = curr.parent;
  }
  return false;
}

// 检查当前节点是否处于非 UI 上下文（代码、日志、技术标签）
function isInsideNonUiContext(node) {
  let curr = node.parent;
  while (curr) {
    if (ts.isJsxElement(curr)) {
      const tagName = curr.openingElement.tagName.getText();
      if (['pre', 'code', 'samp', 'kbd'].includes(tagName)) return true;
      if (tagName === 'Trans') return true;
    }
    if (ts.isCallExpression(curr)) {
      const text = curr.expression.getText();
      if (
        text.startsWith('console.') ||
        text === 'fetch' ||
        text === 'encodeURIComponent' ||
        text === 'JSON.stringify'
      ) {
        return true;
      }
    }
    curr = curr.parent;
  }
  return false;
}

// 检查字符串值是否属于内置白名单
function isAllowedLiteral(text) {
  const trimmed = text.trim();
  if (!trimmed || !CHINESE_REGEX.test(trimmed)) return true;
  for (const brand of BRAND_ALLOWLIST) {
    if (trimmed.includes(brand)) return true;
  }
  return false;
}

// 执行 AST 深度分析单文件
function analyzeFileWithAst(filePath, content) {
  const sf = ts.createSourceFile(
    filePath,
    content,
    ts.ScriptTarget.Latest,
    true,
    ts.ScriptKind.TSX
  );
  const violations = [];

  function visit(node) {
    // 1. 检查 JSX 裸文本节点: <div>中文</div>
    if (ts.isJsxText(node)) {
      const text = node.getText(sf);
      if (CHINESE_REGEX.test(text) && !isAllowedLiteral(text)) {
        if (
          !hasValidSuppressionComment(sf, node) &&
          !isInsideNonUiContext(node)
        ) {
          const { line } = sf.getLineAndCharacterOfPosition(node.getStart(sf));
          violations.push({
            line: line + 1,
            text: text.trim().slice(0, 40),
            kind: 'JsxText',
          });
        }
      }
    }

    // 2. 检查 UI 专属属性: <Component title="中文" placeholder="中文" />
    if (ts.isJsxAttribute(node)) {
      const attrName = node.name.getText(sf);
      if (UI_ATTRS.has(attrName) && node.initializer) {
        let attrVal = '';
        if (ts.isStringLiteral(node.initializer)) {
          attrVal = node.initializer.text;
        } else if (
          ts.isJsxExpression(node.initializer) &&
          node.initializer.expression
        ) {
          if (ts.isStringLiteral(node.initializer.expression)) {
            attrVal = node.initializer.expression.text;
          }
        }
        if (CHINESE_REGEX.test(attrVal) && !isAllowedLiteral(attrVal)) {
          if (!hasValidSuppressionComment(sf, node) && !isInsideTCall(node)) {
            const { line } = sf.getLineAndCharacterOfPosition(
              node.getStart(sf)
            );
            violations.push({
              line: line + 1,
              text: attrVal.trim().slice(0, 40),
              kind: `JsxAttr(${attrName})`,
            });
          }
        }
      }
    }

    // 3. 检查数据配置对象属性: { label: "中文", text: "中文" }
    if (ts.isPropertyAssignment(node)) {
      const propName = node.name.getText(sf);
      if (DATA_COPY_KEYS.has(propName)) {
        if (
          ts.isStringLiteral(node.initializer) ||
          ts.isNoSubstitutionTemplateLiteral(node.initializer)
        ) {
          const valText = node.initializer.text;
          if (CHINESE_REGEX.test(valText) && !isAllowedLiteral(valText)) {
            if (
              !hasValidSuppressionComment(sf, node) &&
              !isInsideTCall(node) &&
              !isInsideNonUiContext(node)
            ) {
              const { line } = sf.getLineAndCharacterOfPosition(
                node.getStart(sf)
              );
              violations.push({
                line: line + 1,
                text: valText.trim().slice(0, 40),
                kind: `DataCopy(${propName})`,
              });
            }
          }
        }
      }
    }

    ts.forEachChild(node, visit);
  }

  visit(sf);
  return violations;
}

// ── 基线操作 ────────────────────────────────────────────────────────────────
function readBaseline() {
  if (!existsSync(BASELINE_PATH)) return null;
  const content = readFileSync(BASELINE_PATH, 'utf8');
  const start = content.indexOf(START_MARKER);
  const end = content.indexOf(END_MARKER);
  if (start < 0 || end < 0 || end < start) return { __malformed: true };

  const body = content.slice(start + START_MARKER.length, end);
  const map = new Map();
  for (const line of body.split('\n')) {
    const trimmed = line.trim();
    if (!trimmed || trimmed.startsWith('#')) continue;
    const parts = trimmed.split(/\s+/);
    if (parts.length !== 2) return { __malformed: true };
    const count = parseInt(parts[1], 10);
    if (isNaN(count)) return { __malformed: true };
    map.set(parts[0], count);
  }
  return map;
}

function writeBaseline(fileViolationsMap) {
  const lines = [START_MARKER];
  const sortedFiles = [...fileViolationsMap.keys()].sort();
  for (const f of sortedFiles) {
    const count = fileViolationsMap.get(f);
    if (count > 0) lines.push(`${f} ${count}`);
  }
  lines.push(END_MARKER);

  const newBlock = lines.join('\n');
  let header = `# i18n 源码硬编码中文门禁基线\n\n> 由 \`node scripts/check-i18n-hardcoded.mjs --update\` 自动生成（仅允许收紧）。\n> 语义：实测 > 基线 → FAIL；实测 ≤ 基线 → 通过。各波次任务逐步收敛清零。\n\n`;

  let currentContent = existsSync(BASELINE_PATH)
    ? readFileSync(BASELINE_PATH, 'utf8')
    : '';
  const start = currentContent.indexOf(START_MARKER);
  const end = currentContent.indexOf(END_MARKER);

  let finalOutput = '';
  if (start >= 0 && end > start) {
    finalOutput =
      currentContent.slice(0, start) +
      newBlock +
      currentContent.slice(end + END_MARKER.length);
  } else {
    finalOutput = header + newBlock + '\n';
  }
  writeFileSync(BASELINE_PATH, finalOutput, 'utf8');
}

// ── 主程序执行流程 ──────────────────────────────────────────────────────────
export function runHardcodedCheck() {
  const t0 = Date.now();
  const allFiles = [];
  for (const target of TARGET_SCAN_DIRS) {
    collectSourceFiles(target, allFiles);
  }

  const fileViolationsMap = new Map();
  const detailedHits = [];
  let astScannedCount = 0;

  for (const file of allFiles) {
    const rawContent = readFileSync(file, 'utf8');

    // Stage 1: 正则预检快筛（剥离注释后判断是否含中文）
    const stripped = stripCommentsKeepLines(rawContent);
    if (!CHINESE_REGEX.test(stripped)) {
      continue; // 瞬间放行
    }

    // Stage 2: 命中中文字符，进入 TypeScript AST 语义深检
    astScannedCount++;
    const relPath = toPosix(relative(REPO_ROOT, file));
    const fileViolations = analyzeFileWithAst(file, rawContent);

    if (fileViolations.length > 0) {
      fileViolationsMap.set(relPath, fileViolations.length);
      for (const v of fileViolations) {
        detailedHits.push({ relPath, ...v });
      }
    }
  }

  const elapsed = Date.now() - t0;
  return {
    allFilesCount: allFiles.length,
    astScannedCount,
    fileViolationsMap,
    detailedHits,
    elapsed,
  };
}

## 三、门禁二：词典 100% 对称性与纯度断言扫描器（`scripts/check-i18n-symmetry.mjs`）

### 3.1 动态语言包自动感知与解析引擎

为杜绝现存测试中写死导入 `zhCN` 与 `enUS` 的缺陷，扫描器具备全动态语言包自动感知能力：

1. **全景探测**：扫描 `apps/crish-desktop/src/i18n/locales/` 目录，探测所有语言定义文件（如 `zh-CN.ts`, `en-US.ts`，或未来扩展的 `zh-TW.ts`, `ja-JP.ts`）；
2. **支持模块化目录**：既兼容单文件形态，也兼容按模块拆分后的子目录形态（`locales/en-US/{common,nav,chat,...}.ts`）；
3. **安全 AST/TS 编译求值**：借助 TypeScript Compiler API 的 `ts.transpileModule` 动态转译并提取字典键值树，零运行期外部打包依赖，执行耗时 **< 30ms**。

### 3.2 五重刚性断言阶梯（Anti-Cheat Assertion Ladder）

```
                     ┌──────────────────────────────────────────────┐
                     │          词典五重刚性断言校验阶梯            │
                     └──────────────────────────────────────────────┘
                                             │
      ┌──────────────────────────────────────┼──────────────────────────────────────┐
      ▼                                      ▼                                      ▼
【断言 1: 键集合对称】                【断言 2: 零空值断言】                 【断言 3: 语言纯度断言】
TargetKeys ≡ BaseKeys                v !== '' && v.trim().length > 0        en-US 严禁出现汉字
双向零缺失、零冗余                   拒绝空白字符占位                       封死中文拷贝作弊
      │                                      │                                      │
      └──────────────────────────────────────┼──────────────────────────────────────┘
                                             │
                      ┌──────────────────────┴──────────────────────┐
                      ▼                                             ▼
          【断言 4: 插值参数对称】                      【断言 5: 拒绝敷衍占位】
          {params} 集合 100% 恒等                       拦截 "TODO", "TBD", "..."
          防运行时参数替换失效                          拦截直接拿 Key 充当 Value
```

1. **断言 1：键集合双向零缺失、零冗余（Key Parity）**：
   以基准语言 `zh-CN` 为真理源基准，对所有目标语言 $L_{target}$ 进行双向严格对比：
   - 缺失键断言：$Missing = Keys(Base) \setminus Keys(Target) = \emptyset$；
   - 冗余键断言：$Redundant = Keys(Target) \setminus Keys(Base) = \emptyset$。
2. **断言 2：叶子节点零空值与有效性（Non-Empty Leaf Assertions）**：
   递归遍历字典每一个叶子节点，断言其值必须是有效非空字符串：
   `typeof val === 'string' && val.trim().length > 0`。
   任何赋空值 `""` 或全空格 `"   "` 的行为直接判定为违规并阻断。
3. **断言 3：反作弊语言纯度断言（Purity & Anti-Copy Guard）**：
   **这是彻底击碎假翻译作弊的核心武器**。
   对所有非中文语言包（如 `en-US`），执行汉字字符集扫描：
   `CHINESE_REGEX = /[\u4e00-\u9fff]/`。
   若在英文语言包中检测到汉字，直接输出红字报警：
   `❌ [en-US] 键 "chat.welcome" 检测到未翻译的硬编码中文拷贝: "欢迎"！禁止直接复制中文敷衍对齐！`
4. **断言 4：变量占位符 100% 对称性（Interpolation Parity）**：
   解析双语模板字符串中所有形如 `{varName}` 的插值变量：
   - 提取 `zh-CN` 模板中的参数集合 $P_{base}$ 并排序；
   - 提取目标语言模板中的参数集合 $P_{target}$ 并排序；
   - 断言 $P_{base} \equiv P_{target}$。
     杜绝参数漏写、错拼导致运行时暴露未解析占位符的低级 Bug。
5. **断言 5：敷衍占位符黑名单过滤（Placeholder Ban）**：
   内置垃圾占位文本黑名单：`TODO`, `TBD`, `TEMP`, `FIXME`, `N/A`, `...`, `test`，且严禁直接将 Key 路径赋值给文案（如 `chat.send: "chat.send"`）。

// 动态编译并安全加载 TS 词典文件
function loadDictionaryModule(filePath) {
  const tsCode = readFileSync(filePath, 'utf8');
  const jsCode = ts.transpileModule(tsCode, {
    compilerOptions: {
      module: ts.ModuleKind.CommonJS,
      target: ts.ScriptTarget.ES2022,
    },
  }).outputText;

  const moduleObj = { exports: {} };
  const fn = new Function('module', 'exports', 'require', jsCode);
  fn(moduleObj, moduleObj.exports, require);

  // 提取导出的词典对象
  const exports = moduleObj.exports;
  const dict =
    exports.default ||
    exports.zhCN ||
    exports.enUS ||
    exports.dictionary ||
    Object.values(exports)[0];
  if (!dict || typeof dict !== 'object') {
    throw new Error(`无法从 ${filePath} 中解析出有效的词典导出对象！`);
  }
  return dict;
}

// 递归展开字典为扁平点分映射表
function flattenDictionary(obj, prefix = '', result = new Map()) {
  for (const [k, v] of Object.entries(obj)) {
    const fullKey = prefix ? `${prefix}.${k}` : k;
    if (v && typeof v === 'object' && !Array.isArray(v)) {
      flattenDictionary(v, fullKey, result);
    } else {
      result.set(fullKey, v);
    }
  }
  return result;
}

// 提取字符串中的所有参数占位符
function extractParams(str) {
  if (typeof str !== 'string') return [];
  const matches = [];
  let m;
  const re = new RegExp(INTERPOLATION_REGEX.source, 'g');
  while ((m = re.exec(str))) {
    matches.push(m[1]);
  }
  return matches.sort();
}

  const locales = new Map();

  for (const file of files) {
    const localeId = file.replace('.ts', '');
    try {
      const dict = loadDictionaryModule(join(LOCALES_DIR, file));
      const flatMap = flattenDictionary(dict);
      locales.set(localeId, flatMap);
      console.log(`  - 载入语言包 [${localeId}]: ${flatMap.size} 个词条`);
    } catch (err) {
      console.error(
        `❌ [check-i18n-symmetry] 无法解析语言包 ${file}: ${err.message}`
      );
      process.exit(1);
    }
  }

  if (!locales.has(BASE_LOCALE)) {
    console.error(
      `❌ [check-i18n-symmetry] FAIL: 缺少基准语言包 ${BASE_LOCALE}.ts！`
    );
    process.exit(1);
  }

  const baseMap = locales.get(BASE_LOCALE);
  let totalErrors = 0;

  // 2. 对所有目标语言执行五重断言
  for (const [localeId, targetMap] of locales.entries()) {
    if (localeId === BASE_LOCALE) continue;
    console.log(
      `\n[check-i18n-symmetry] 正在比对 [${BASE_LOCALE}] 与 [${localeId}]...`
    );

    // 断言 1: 键对称性（零缺失、零冗余）
    const missingKeys = [...baseMap.keys()].filter((k) => !targetMap.has(k));
    const redundantKeys = [...targetMap.keys()].filter((k) => !baseMap.has(k));

    if (missingKeys.length > 0) {
      console.error(`❌ [${localeId}] 缺失翻译键 (${missingKeys.length} 处):`);
      for (const k of missingKeys.slice(0, 10)) console.error(`    - ${k}`);
      if (missingKeys.length > 10)
        console.error(`    ... 等共 ${missingKeys.length} 项`);
      totalErrors += missingKeys.length;
    }

    if (redundantKeys.length > 0) {
      console.error(
        `❌ [${localeId}] 包含基准语言不存在的冗余键 (${redundantKeys.length} 处):`
      );
      for (const k of redundantKeys.slice(0, 10)) console.error(`    - ${k}`);
      totalErrors += redundantKeys.length;
    }

    // 断言 2、3、4、5: 叶子值检验
    for (const [key, baseVal] of baseMap.entries()) {
      if (!targetMap.has(key)) continue;
      const targetVal = targetMap.get(key);

      // 断言 2: 零空值与有效性
      if (typeof targetVal !== 'string' || targetVal.trim().length === 0) {
        console.error(
          `❌ [${localeId}] 空值违规: 键 "${key}" 的值为空或全为空格！`
        );
        totalErrors++;
        continue;
      }

      // 断言 3: 反作弊纯度断言（非中文包严禁包含汉字）
      if (localeId !== 'zh-TW' && CHINESE_REGEX.test(targetVal)) {
        console.error(
          `❌ [${localeId}] 纯度违规（作弊拦截）: 键 "${key}" 包含未翻译的中文残留: "${targetVal}"`
        );
        totalErrors++;
      }

      // 断言 4: 插值参数对称性
      const baseParams = extractParams(baseVal);
      const targetParams = extractParams(targetVal);
      if (JSON.stringify(baseParams) !== JSON.stringify(targetParams)) {
        console.error(
          `❌ [${localeId}] 占位符不匹配: 键 "${key}" 基准参数 [${baseParams}] vs 目标参数 [${targetParams}]`
        );
        totalErrors++;
      }

      // 断言 5: 拒绝敷衍占位
      const lower = targetVal.trim().toLowerCase();
      if (JUNK_VALUES.has(lower) || targetVal.trim() === key) {
        console.error(
          `❌ [${localeId}] 敷衍占位文案违规: 键 "${key}" 被填充为无意义文本 "${targetVal}"！`
        );
        totalErrors++;
      }
    }
  }

  const elapsed = Date.now() - t0;
  if (totalErrors > 0) {
    console.error(
      `\n❌ [check-i18n-symmetry] 校验失败: 累计发现 ${totalErrors} 处词典违规错误 (耗时: ${elapsed}ms)`
    );
    process.exit(1);
  }

  console.log(
    `\n✅ [check-i18n-symmetry] 完美通过！词典 100% 对称性、纯度、参数恒等校验全绿 (耗时: ${elapsed}ms)`
  );
  process.exit(0);
}

const isDirectRun =
  process.argv[1] &&
  fileURLToPath(import.meta.url) === resolve(process.argv[1]);
if (isDirectRun) {
  checkI18nSymmetry();
}

## 四、门禁三：未消费死词条扫描器（`scripts/check-i18n-unused-keys.mjs`）

### 4.1 设立背景与虚报完成度防范

在以往国际化重构中，常见作弊手段是：Agent 批量向词典中填入 500 个 Key，声称“已全部完成国际化抽取”，但业务代码中由于拼写错误或重构，根本未调用这些 Key。
死词条不仅虚报工程完成度，还会导致打包体积膨胀与后续维护地雷。门禁 C 专用于清除此类死代码。

### 4.2 词典键集与全仓源码交叉索引引擎

扫描器采用倒排索引算法：

1. 提取基准词典 `zh-CN.ts` 中全部完整的点分 Key 集合 $K_{dict}$；
2. 遍历全仓前端与桌面源码，通过 AST 字符串字面量收集与正则极速快扫，建立全仓已消费键集合 $S_{consumed}$；
3. 比对 $Unused = K_{dict} \setminus S_{consumed}$。

### 4.3 动态命名空间放行规则（Dynamic Key Whitelist）

为了防止将通过逻辑拼接调用的合法 Key 误判为死词条，扫描器联动底层模型建立白名单规则：

- **105 个核心错误码标题放行**：
  读取 [`packages/shared-types/src/errors/info.ts`](file:///c:/Software/conex/packages/shared-types/src/errors/info.ts) 中的 `CRISH_ERROR_REGISTRY`，所有符合 `error.<code_domain>.<code_name>.title` 的键均视为合法消费；
- **建议操作域放行**：
  所有在 `CRISH_ERROR_REGISTRY` 中声明的 `action.<domain>.<action_name>` 视为合法消费；
- **设置面板动态 Tab 放行**：
  匹配 `settings.${tabId}.*` 模式的配置键自动放行；
- **工具调用卡片动态前缀**：
  匹配 `tool.<tool_name>.*` 的动态工具文案放行。

### 4.4 完整工程级脚本实现代码：`scripts/check-i18n-unused-keys.mjs`

/**
 * scripts/check-i18n-unused-keys.mjs
 * 未消费废弃词条扫描器 (TASKFORCE-05 方案实现)
 *
 * 语义：扫描词典中定义但在源码中从未被引用的孤儿 Key，根绝虚报完成度与词典膨胀。

 * 运行方式:
 *   node scripts/check-i18n-unused-keys.mjs

import { readFileSync, readdirSync, existsSync, statSync } from 'node:fs';
import { resolve, dirname, join } from 'node:path';
import { fileURLToPath } from 'node:url';
import { createRequire } from 'node:module';

const require = createRequire(import.meta.url);
const ts = require('typescript');

const __dirname = dirname(fileURLToPath(import.meta.url));

const LOCALES_DIR = resolve(REPO_ROOT, 'apps/crish-desktop/src/i18n/locales');
const ERROR_REGISTRY_PATH = resolve(
  REPO_ROOT,
  'packages/shared-types/src/errors/info.ts'

const SCAN_DIRS = [
  'apps/crish-desktop/src',
  'apps/agent-workbench/src',
  'packages/editor-kit/src',
  'packages/block-paper/src',
  'packages/conversation-flow/src',

// 动态提取 105 个错误码白名单
function getErrorRegistryKeys() {
  const allowed = new Set();
  if (existsSync(ERROR_REGISTRY_PATH)) {
    const content = readFileSync(ERROR_REGISTRY_PATH, 'utf8');
    // 正则提取所有形如 'provider.network': { ... action: 'action.provider.check_network' }
    const codeMatches =
      content.match(/'([a-zA-Z0-9_]+\.[a-zA-Z0-9_]+)':\s*\{/g) || [];
    for (const m of codeMatches) {
      const code = m.replace(/[':\s{]/g, '');
      allowed.add(`error.${code}.title`);
    }
    const actionMatches = content.match(/action:\s*'([^']+)'/g) || [];
    for (const m of actionMatches) {
      const action = m.replace(/action:\s*'|'/g, '');
      allowed.add(action);
      allowed.add(action.replace(/^action\./, ''));
    }
  }
  return allowed;
}

// 递归遍历文件
function walkFiles(dir, out = []) {
  if (!existsSync(dir)) return out;
  for (const e of readdirSync(dir, { withFileTypes: true })) {
    const full = join(dir, e.name);
    if (e.isDirectory()) {
      if (
        e.name !== 'node_modules' &&
        e.name !== 'dist' &&
        e.name !== 'locales'
      ) {
        walkFiles(full, out);
      }
    } else if (
      /\.(tsx?|jsx?|mjs)$/.test(e.name) &&
      !e.name.endsWith('.test.ts')
    ) {
      out.push(full);
    }
  }
  return out;
}

export function checkUnusedKeys() {
  const t0 = Date.now();
  console.log('[check-i18n-unused-keys] 开始扫描未消费死词条...');

  // 1. 载入基准词典全部扁平键
  const zhFile = join(LOCALES_DIR, 'zh-CN.ts');
  const tsCode = readFileSync(zhFile, 'utf8');
  const jsCode = ts.transpileModule(tsCode, {
    compilerOptions: { module: ts.ModuleKind.CommonJS },
  }).outputText;
  const mod = { exports: {} };
  new Function('module', 'exports', 'require', jsCode)(
    mod,
    mod.exports,
    require
  );
  const dict = mod.exports.zhCN || mod.exports.default;

  const dictKeys = new Set();
  function flatten(obj, p = '') {
    for (const [k, v] of Object.entries(obj)) {
      const full = p ? `${p}.${k}` : k;
      if (v && typeof v === 'object' && !Array.isArray(v)) flatten(v, full);
      else dictKeys.add(full);
    }
  }
  flatten(dict);
  console.log(`  - 词典总键数: ${dictKeys.size} 个`);

  // 2. 收集全仓源码中引用的所有字符串字面量
  const sourceFiles = [];
  for (const d of SCAN_DIRS) walkFiles(resolve(REPO_ROOT, d), sourceFiles);
  console.log(`  - 扫描源码文件: ${sourceFiles.length} 个`);

  const fullSourceCorpus = sourceFiles
    .map((f) => readFileSync(f, 'utf8'))
    .join('\n');

  // 3. 动态白名单
  const errorAllowed = getErrorRegistryKeys();
  const orphanKeys = [];

  for (const key of dictKeys) {
    if (errorAllowed.has(key)) continue; // 错误码动态放行
    if (
      key.startsWith('settings.') &&
      fullSourceCorpus.includes('settingsTabsMeta')
    )
      continue;
    if (key.startsWith('tool.') && fullSourceCorpus.includes('ToolCard'))
      continue;

    // 断言是否在源码中静态出现过 'key' 或 "key"
    const searchPattern = new RegExp(
      `['"\`]${key.replace(/\./g, '\\.')}['"\`]`
    );
    if (!searchPattern.test(fullSourceCorpus)) {
      orphanKeys.push(key);
    }
  }

  const elapsed = Date.now() - t0;
  if (orphanKeys.length > 0) {
    console.warn(
      `\n⚠️  [check-i18n-unused-keys] 检出 ${orphanKeys.length} 个疑似未消费的孤立词条 (耗时: ${elapsed}ms):`
    );
    for (const k of orphanKeys.slice(0, 15)) console.warn(`    - ${k}`);
    if (orphanKeys.length > 15)
      console.warn(`    ... 等共 ${orphanKeys.length} 项`);
    console.warn(
      '  提示：请核对是否为重构遗留废弃键。若是，请从词典中清退；若是动态调用，请在白名单中登记。'
    );
  } else {
    console.log(
      `\n✅ [check-i18n-unused-keys] 完美！全量词典键均被有效消费，零死词条残留 (耗时: ${elapsed}ms)`
    );
  }
  process.exit(0);
}

const isDirectRun =
  process.argv[1] &&
  fileURLToPath(import.meta.url) === resolve(process.argv[1]);
if (isDirectRun) {
  checkUnusedKeys();
}

3. **断言基线防静默清空**：断言 `docs/i18n-full-remediation/基线记录/i18n-hardcoded-baseline.md` 标记区必须完整存在。

### 6.4 恪守 AGENTS.md §1.7 禁止 `--no-verify` 铁律

任何子 Agent 或执行者绝对禁止使用 `--no-verify` 绕过 pre-commit。
在 CI 快中层流水线中，将强制全量重跑 `npm run check:i18n` 与 `npm test`。本地任何绕过手段在服务端均无法合并。

## 七、7 大作弊偷懒模式攻防矩阵与双盲交叉审计协议

### 7.1 7 大作弊偷懒模式攻防矩阵

| 作弊/偷懒反模式                                  | 作弊典型手段                                    | 潜在严重危害                              | 自动化拦截武器                                                      | 人工/审计员复核指引                                     |
| :----------------------------------------------- | :---------------------------------------------- | :---------------------------------------- | :------------------------------------------------------------------ | :------------------------------------------------------ |
| **1. 伪翻译拷贝**<br>_(Fake Translation)_        | 直接将中文复制到 `en-US.ts` 冒充已完成。        | 英文环境下界面充斥中文，用户体验崩塌。    | **门禁 A 语言纯度校验器**：`[\u4e00-\u9fff]` 汉字扫描强制拦截阻断。 | 抽查 `en-US.ts` 的 git diff，确保用词符合原生桌面习惯。 |
| **2. 滥用抑制注释**<br>_(Suppression Abuse)_     | 遇到中文报错直接加 `/* i18n-allow */`。         | 留下永久未翻译死角，破坏重构完整性。      | **门禁 B 格式校验**：必须写明 >2 字符正当理由；全仓台账监控。       | 审查所有新增抑制注释，凡对业务文案加豁免的一律打回。    |
| **3. 字符串拼接**<br>_(String Concatenation)_    | `t('user') + ': ' + name` 拼接字符串。          | 破坏不同语言的主谓宾语序语法。            | **门禁 B AST 检测**：`BinaryExpression (+)` 中包含 `t()` 发出警告。 | 检查所有动态语句，强制要求采用 `{name}` 插值。          |
| **4. 三元硬编码分支**<br>_(Ternary Hardcode)_    | `isZh ? '保存' : 'Save'` 散落在业务中。         | 违背单一真理源，无法支持第 3 种语言扩展。 | **门禁 B AST 遍历**：三元表达式内含中文直接捕获拦截。               | 全局搜索 `=== 'zh-CN'` 分支，收口入词典。               |
| **5. 占位符敷衍**<br>_(Dummy Placeholders)_      | 批量填充 `"TODO"`, `"TBD"`, `"..."` 或 Key 名。 | 界面充斥半成品草稿，严重降低品质。        | **门禁 A 垃圾词名单**：严格拦截无意义占位符。                       | 检查新词条释义完整度，拒绝粗制滥造。                    |
| **6. 排版断裂视盲**<br>_(Layout Overflow)_       | 英文膨胀 40% 导致按钮撑破、换行坍塌。           | 视觉布局碎裂，截断省略号影响阅读。        | **Playwright 多语言巡检**：自动比对容器元素宽高与溢出状态。         | 启动应用切换至 `en-US`，肉眼巡检 15 个 Tab 与侧栏排版。 |
| **7. 虚假测试断言**<br>_(Dummy Test Assertions)_ | 单测写 `expect(true).toBe(true)` 或假 Mock。    | 测试覆盖率虚高，实际业务全盘失效。        | **立体契约测试矩阵**：必须通过真实 DOM 渲染并断言 `textContent`。   | 双盲审查测试源码，杜绝无意义假断言。                    |

### 7.2 Phase 8 执行期交叉双盲审计操作规程

为了避免“自己写代码、自己做审查”的自欺欺人现象，Phase 8 将启动双盲交叉审计协议：

```
    实现 Agent (A) 提交代码 ──┐
                              │
                              ├──► 自动化门禁 (Gate A + B + C) 机器初审
                              │    (零容忍，自动拦截 90% 机械性作弊)
                              │
    专职审计 Agent (B) 介入 ──┘
         │
         ├── 1. 差异审计：审查 git diff 中的所有字典抽取与 i18n-allow 抑制注释
         ├── 2. 覆盖审计：验证本波次承诺的组件是否 100% 抽取干净，有无遗漏
         ├── 3. 语言审计：核对 en-US 英文文案的地道性与原生性（拒绝中式英语）
         └── 4. 现场立体实验：在真实的桌面上下文中启动并切换双语验收
```

1. **A/B 角色完全分离**：
   - 实现 Agent（A）负责按照任务书抽取词条、重构组件并更新基线；
   - 审计 Agent（B）独立于实现者，拥有完全平行的派单指令，负责挑刺与寻找漏洞；
2. **四重审计标准操作规程（SOP）**：
   - **SOP-1：Git Diff 穿透审查**：逐行审查补丁中的每一个 `t()` 提取与新增词条，核查是否有裸字符串遗漏；
   - **SOP-2：抑制注释合理性答辩**：审计员有权要求实现者说明每一处 `/* i18n-allow */` 的必要性，非专有名词一律驳回；
   - **SOP-3：英文原生性评审**：审查 `en-US` 文案是否符合桌面工具规范（例如：应使用 `Preferences` / `Settings`、`New Chat`、`Discard Changes`，严禁机器直译中式英文）；
   - **SOP-4：真实桌面现场切换验收**：必须启动应用并在真实的 WebView2 宿主中进行双语切换验收，确保零控制台告警、零布局错位。
