## 三、架构净收敛与防过度设计复核

本战役在重构过程中严格恪守仓库根目录 [`ANTI_OVERENGINEERING_GUARDRAILS.md`](../../../ANTI_OVERENGINEERING_GUARDRAILS.md) 红线，杜绝任何“为了国际化而引入复杂抽象”的架构倒退：

1. **零引入过度设计**：
   - 严禁引入动态模型路由器（`DynamicModelRouter`）；
   - 严禁引入环形共享缓冲（`SharedArrayBuffer`）；
   - 严禁引入六段式工具流水线或深度嵌套反序列化路由；
   - 翻译核心保持轻量纯函数（Pure Functions）与 React 标准 Context 单例通道，无黑盒副作用。
2. **单一真理来源（SSOT）**：
   - 词条定义物理收敛于 `src/i18n/locales/{zh-CN,en-US}/` 下的 10 个独立领域文件，通过根 `index.ts` 统筹聚合；
   - 错误码注册表严格由 `CRISH_ERROR_REGISTRY` 统一维护，UI 层不再自行猜测错误类型或中文长句；
   - 语言热切换基于 Session Language Epoch 令牌单向递增，彻底杜绝异步竞态与状态回滚。
3. **彻底根除三大技术债坏味道**：
   - **消灭假三元分支**：清退全部 `isEn ? 'English' : 'Chinese'` 临时补丁，全部纳管至双语词典；
   - **消灭字符串拼接**：清退裸露的 `+ " " +`，全部采用命名参数插值 `{param}`；
   - **消灭原生 `title` 属性**：遵循 `AGENTS.md` §12 规范，全部替换为项目自定义 `<Tooltip>` 组件，并联动文本物理截断状态（`disabled={!isTruncated}`）实现自适应感知。

## 四、长效防回潮与刚性质量工程机制

为确保本战役成果永久固化、杜绝后续开发过程中出现硬编码反弹或词条不对称，建立了五道全自动刚性门禁防线：

1. **词典 100% 对称性与纯度守卫（`check-i18n-symmetry.mjs`）**：
   - 刚性断言 `zh-CN` 与 `en-US` 词条集合双向完全同构；
   - 刚性断言 `en-US` 词典中汉字字符数与全角标点数恒等于 **0**（彻底拦截直接复制中文充数的偷懒作弊）；
   - 刚性断言动态插值参数集合恒等；
   - 已集成至 `.husky/pre-commit`，违规立即阻断提交。
2. **源码硬编码单向棘轮守卫（`check-i18n-hardcoded.mjs`）**：
   - 基于 TypeScript Compiler API AST 语法树深度语义分析；
   - 实施单向棘轮算法：$\forall f, C_{\text{curr}}(f) \le C_{\text{base}}(f)$，任何文件新增硬编码即刻阻断；
   - 基线已稳固锁死在 5135 处，后续只许递减清零，绝无回弹可能。
3. **前端收敛规则防线（`check:convergence`）**：
   - G-01 ~ G-17 规则全天候守门，刚性拦截原生 title、裸交互标签、非法药丸样式与 `!important` 提权。
4. **全仓严格类型防线（`npm run typecheck`）**：
   - 覆盖客户端与全部共享库的 11 个 TSConfig 工程，0 错误零容忍。
5. **4000 端口真机实测套件（`verify-desktop-i18n-mcp.mjs`）**：
   - 固化真机 MCP 套接字自动化实测能力，持续守护生产环境运行态双语表现。
