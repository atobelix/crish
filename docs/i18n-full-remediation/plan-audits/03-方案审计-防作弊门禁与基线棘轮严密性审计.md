### 1.1 裁决结果与一票否决核心理由

本审计员作为【防作弊门禁与基线棘轮严密性专职审计员】，依据仓库最高协作基准 [`AGENTS.md`](file:///c:/Software/conex/AGENTS.md) §1.1（反退避）、§1.7（严禁打补丁与作弊）、§7.1（立体验证纪律）以及 [`00-战役工作纪律与规范.md`](file:///c:/Software/conex/docs/i18n-full-remediation/00-战役工作纪律与规范.md)，对主控总方案《01-总方案》、分维方案《06-分维方案》及独立总案《03-独立总计划》中设计的 **3 大刚性门禁与 7 大防作弊攻防机制** 进行了全面、独立、代码级的双盲穿透审查。

审查结论：🔴 **BLOCKER（一票否决 / 方案阻断）**。

行使一票否决权的 **4 项根本性 Blocker 缺陷** 如下：

1. **AST 深度扫描存在重大“漏检黑洞”（Fake Safety）**：  
   方案在文字上郑重承诺拦截“三元硬编码分支（`loading ? '加载中' : '就绪'`）”、“模板字面量拼接（`` `当前：${x}` ``）”以及“字符串相加拼接（`t('a') + ': ' + b`）”。然而，审查《06-分维方案》给出的生产脚本实现源码 `analyzeFileWithAst`，**根本未实现 `ts.isConditionalExpression` 与 `ts.isBinaryExpression` 判定**；JSX 属性检查只提取 `ts.isStringLiteral`，三元表达式直接被当成空串跳过；JSX 子节点仅检查 `ts.isJsxText`，直接丢弃 `{ "保存" }` 与 `{ cond ? "中A" : "中B" }`；模板字面量仅检查无替换项的 `NoSubstitutionTemplateLiteral`，对于含变量的 `TemplateExpression` 完全视而不见；对象属性仅白名单匹配 12 个字段，遗漏 `tooltip`、`confirmText`、`cancelText`、`content` 等常见 UI 字段。实测上述代码，**门禁报告违规数均为 0**！
2. **白名单全局穿透漏洞（Fatal Allowlist Substring Bypass）**：  
   `isAllowedLiteral` 采用了 `trimmed.includes(brand)` 的简单子串包含逻辑。由于白名单包含 `'百度'`、`'React'`、`'Git'` 等词，导致任何包含上述词汇的中文长句（如 `"请点击确认以跳转至百度登录"`）直接被全局放行；甚至作弊 Agent 只需在任何中文文案末尾追加 `/* (百度) */` 或中文字符串内嵌品牌词，即可实现 100% 豁免！
3. **架构致命断裂：语言包加载引擎与模块化物理拆分完全不兼容（Architecture Crash）**：  
   门禁二 `scripts/check-i18n-symmetry.mjs` 宣称支持目录拆分子模块，但其实现函数 `loadDictionaryModule` 仅使用 `ts.transpileModule` 产出 CommonJS 并执行 `new Function('module', 'exports', 'require', jsCode)`。当语言包按 05 方案拆分为 `import { common } from './zh-CN/common'` 时，Node 原生 `require` 在脚本目录下既无法寻址相对路径，也无法直接解析 `.ts` 文件，**门禁脚本将直接抛出 `Cannot find module` 崩溃并中断**；且 `readdirSync` 仅过滤 `.ts` 文件，无法递归识别语言包子目录！
4. **守卫体系冲突与假门禁问题（Guard System Breach & Pseudo-Gate）**：  
   - 门禁三 `scripts/check-i18n-unused-keys.mjs` 在检测到死词条时仅调用 `console.warn`，最终无条件调用 `process.exit(0)`，**根本不具备任何门禁阻断能力**，属于“纸面门禁”；
   - 新增的 `check-i18n-symmetry.mjs` 与 `check-i18n-unused-keys.mjs` 均未实现 `--list` 或 `--guide`，一旦落盘将直接使仓库受护指标 `guide_capable_missing` 从 36 跃升至 38，**触犯 `@ratchet` 只降不升铁律，直接导致全仓 Pre-commit 瘫痪**；
   - 方案仅将门禁挂载于 `.husky/pre-commit`，未编入 `.github/workflows/ci.yml` 或 `ci-mid.yml` 服务端流水线，一旦开发者或 Agent 执行 `git commit --no-verify`，服务端 CI 将处于无防守状态！

## 二、门禁一：`scripts/check-i18n-hardcoded.mjs` AST 判据深度解构与漏洞验证

### 2.1 AST 漏检黑洞攻防实测

审查《06-分维方案》第 2.7 节给出的 `analyzeFileWithAst` 核心实现（第 372~430 行）：

```javascript
function analyzeFileWithAst(filePath, content) {
  const sf = ts.createSourceFile(filePath, content, ts.ScriptTarget.Latest, true, ts.ScriptKind.TSX);
  const violations = [];

  function visit(node) {
    // 1. JsxText 检查
    if (ts.isJsxText(node)) { ... }

    // 2. JsxAttribute 检查
    if (ts.isJsxAttribute(node)) {
      const attrName = node.name.getText(sf);
      if (UI_ATTRS.has(attrName) && node.initializer) {
        let attrVal = '';
        if (ts.isStringLiteral(node.initializer)) {
          attrVal = node.initializer.text;
        } else if (ts.isJsxExpression(node.initializer) && node.initializer.expression) {
          if (ts.isStringLiteral(node.initializer.expression)) {
            attrVal = node.initializer.expression.text;
          }
        }
        if (CHINESE_REGEX.test(attrVal) && !isAllowedLiteral(attrVal)) { ... }
      }
    }

    // 3. PropertyAssignment 检查
    if (ts.isPropertyAssignment(node)) {
      const propName = node.name.getText(sf);
      if (DATA_COPY_KEYS.has(propName)) {
        if (ts.isStringLiteral(node.initializer) || ts.isNoSubstitutionTemplateLiteral(node.initializer)) { ... }
      }
    }
    ts.forEachChild(node, visit);
  }
  visit(sf);
  return violations;
}
```

针对上述 AST 遍历逻辑，本审计员构造了典型的业务组件代码进行现场攻防实测：

```tsx
// 攻防测试样本：test-exploit.tsx
export function ExploitComponent() {
  const opt = { label: `当前已选择：${modelName}` }; // Case A: 模板字面量插值
  const modal = { tooltip: "点击查看详情", confirmText: "立即删除" }; // Case B: 未在 DATA_KEYS 中的配置
  return (
    <div>
      {/* Case C: JSX 表达式中的三元条件分支 */}
      <Button aria-label={loading ? "正在加载中" : "就绪"}>
        {isZh ? "保存更改" : "Save Changes"}
      </Button>

      {/* Case D: JSX 表达式容器中的裸中文字符串 */}

      {/* Case E: 模板字面量属性 */}

```

**实测执行结果**：

**实测结果证实：全量 6 处硬编码中文，捕获率居然是 0%！全部安全漏过！**

#### 根因穿透分析：
1. **三元表达式漏检**：
   - 当属性写为 `aria-label={loading ? "正在加载中" : "就绪"}` 时，`node.initializer` 是 `JsxExpression`，其 `expression` 节点的 AST 语法类型为 `ts.SyntaxKind.ConditionalExpression`。
   - 脚本代码只判断了 `if (ts.isStringLiteral(node.initializer.expression))`，条件直接为 `false`，变量 `attrVal` 维持为 `""`，彻底漏检！
   - JSX 子节点 `{isZh ? "保存更改" : "Save Changes"}` 是 `JsxExpression`，而脚本的 JSX 检查只处理了 `ts.isJsxText`。在 TSX 语法树中，大括号容器内部的节点属于 `JsxExpression`，绝不会进入 `ts.isJsxText` 分支！
2. **模板字面量漏检**：
   - 包含变量替换的模板字符串（如 `` `当前已选择：${modelName}` ``）在 TS AST 中是 `ts.SyntaxKind.TemplateExpression`（由 `head`、`templateSpans` 组成），而无替换项的模板字符串（如 `` `纯文本` ``）才是 `ts.isNoSubstitutionTemplateLiteral`。
   - 脚本在属性和对象字段中只判断了 `ts.isNoSubstitutionTemplateLiteral`，直接导致所有使用模板变量拼接中文的语句 100% 逃逸！
3. **二元相加拼接（`+`）纸面宣称**：
   - 方案在 7.1 节防作弊矩阵中宣称：“门禁 B AST 检测：BinaryExpression (+) 中包含 t() 发出警告”。
   - 但在脚本的 AST 遍历树中，**根本不存在任何对 `ts.isBinaryExpression` 的判定分支**！纯属纸面承诺！
4. **对象文案键名集合过于狭窄**：
   - `DATA_COPY_KEYS` 仅列出了 12 个键名：`label, title, description, placeholder, message, reason, text, summary, subtitle, helper, empty, hint`。
   - 实际前端组件库中大量使用 `tooltip`、`tip`、`content`、`confirmText`、`cancelText`、`warning`、`error`、`badge`、`actionText`、`tab` 等字段。这些字段中的中文字面量直接逃逸。

### 2.2 品牌专有名词白名单机制（`isAllowedLiteral`）的灾难性全局穿透漏洞

审查《06-分维方案》第 362~369 行的白名单实现：

```javascript
function isAllowedLiteral(text) {
  const trimmed = text.trim();
  if (!trimmed || !CHINESE_REGEX.test(trimmed)) return true;
  for (const brand of BRAND_ALLOWLIST) {
    if (trimmed.includes(brand)) return true; // ⚠️ 致命漏洞：子串包含即放行！
  }
  return false;
}
```

#### 漏洞利用推演：
白名单 `BRAND_ALLOWLIST` 包含了 `'百度'`、`'React'`、`'Git'`、`'Claude'`、`'OpenAI'`、`'Markdown'` 等通用词汇。
`trimmed.includes(brand)` 判定的是**只要整个字符串包含该词，就将整个字符串视为合法白名单**！

**现场实测代码与结果**：
```javascript
isAllowedLiteral("点击确认后将通过百度搜索重定向到登录页面") -> true  (放行！)
isAllowedLiteral("确定要清空全部聊天记录并注销账号吗？（文心一言）") -> true  (放行！)
isAllowedLiteral("当前会话已超时，请重新登录智谱AI服务") -> true  (放行！)
isAllowedLiteral("这是一个完全未翻译的普通业务界面（React）") -> true  (放行！)
```

**危害判定**：
- **意外放行**：任何包含品牌词的真实中文长句，原本应当被抽取为词条（如 `"redirect_baidu": "点击确认后将通过百度搜索..."`），却因包含“百度”二字被静默放行；

```javascript
// ==============================================================================
// 加固 1: 扩展 UI 字段与品牌白名单差分判定
// ==============================================================================
const EXTENDED_DATA_COPY_KEYS = new Set([
  'label', 'title', 'description', 'placeholder', 'message', 'reason',
  'text', 'summary', 'subtitle', 'helper', 'empty', 'hint', 'tooltip',
  'tip', 'content', 'confirmText', 'cancelText', 'okText', 'warning',
  'error', 'badge', 'actionText', 'status', 'heading'
]);

function isAllowedLiteral(text) {
  const trimmed = text.trim();
  if (!trimmed || !CHINESE_REGEX.test(trimmed)) return true;
  if (BRAND_ALLOWLIST.has(trimmed)) return true;

  // 差分剔除法：移除所有白名单词汇后，若依然残留汉字，则判定为违规！
  let stripped = trimmed;
  for (const brand of BRAND_ALLOWLIST) {
    if (stripped.includes(brand)) {
      stripped = stripped.replaceAll(brand, '');
    }
  }
  return !CHINESE_REGEX.test(stripped);
}

// ==============================================================================
// 加固 2: 严密穿透 AST 遍历器（覆盖三元、模板字面量、二元拼接、JsxExpression）
// ==============================================================================
function analyzeFileWithAst(filePath, content) {
  const sf = ts.createSourceFile(filePath, content, ts.ScriptTarget.Latest, true, ts.ScriptKind.TSX);
  const violations = [];

  function recordViolation(node, rawText, kind) {
    if (CHINESE_REGEX.test(rawText) && !isAllowedLiteral(rawText)) {
      if (!hasValidSuppressionComment(sf, node) && !isInsideTCall(node) && !isInsideNonUiContext(node)) {
        const { line } = sf.getLineAndCharacterOfPosition(node.getStart(sf));
        violations.push({ line: line + 1, text: rawText.trim().slice(0, 50), kind });
      }
    }
  }

  function inspectExpression(expr, parentNode, attrOrPropName) {
    if (!expr) return;

    // 1. 字符串字面量
    if (ts.isStringLiteral(expr) || ts.isNoSubstitutionTemplateLiteral(expr)) {
      recordViolation(expr, expr.text, attrOrPropName || 'StringLiteral');
    }
    // 2. 含变量插值的模板字面量: `当前选择：${model}`
    else if (ts.isTemplateExpression(expr)) {
      const texts = [expr.head.text, ...expr.templateSpans.map(s => s.literal.text)].join(' ');
      recordViolation(expr, texts, attrOrPropName ? `${attrOrPropName}(Template)` : 'TemplateExpression');
    }
    // 3. 三元条件表达式: cond ? "中文A" : "中文B"
    else if (ts.isConditionalExpression(expr)) {
      inspectExpression(expr.whenTrue, expr, attrOrPropName ? `${attrOrPropName}(TernaryTrue)` : 'TernaryTrue');
      inspectExpression(expr.whenFalse, expr, attrOrPropName ? `${attrOrPropName}(TernaryFalse)` : 'TernaryFalse');
    }
    // 4. 二元加号拼接: t('key') + "：中文"
    else if (ts.isBinaryExpression(expr) && expr.operatorToken.kind === ts.SyntaxKind.PlusToken) {
      inspectExpression(expr.left, expr, 'BinaryConcatLeft');
      inspectExpression(expr.right, expr, 'BinaryConcatRight');
    }
  }

  function visit(node) {
    // 1. JsxText 裸文本: <div>中文</div>
    if (ts.isJsxText(node)) {
      recordViolation(node, node.getText(sf), 'JsxText');
    }

    // 2. JSX 表达式容器: <div>{cond ? "中文" : "En"}</div> 或 <div>{"纯中文"}</div>
    if (ts.isJsxExpression(node) && node.expression && !ts.isJsxAttribute(node.parent)) {
      inspectExpression(node.expression, node, 'JsxChildExpr');
    }

    // 3. UI 专属 JSX 属性: <input placeholder={loading ? "加载中" : "就绪"} />
    if (ts.isJsxAttribute(node)) {
      const attrName = node.name.getText(sf);
      if (UI_ATTRS.has(attrName) && node.initializer) {
        if (ts.isStringLiteral(node.initializer)) {
          recordViolation(node.initializer, node.initializer.text, `JsxAttr(${attrName})`);
        } else if (ts.isJsxExpression(node.initializer) && node.initializer.expression) {
          inspectExpression(node.initializer.expression, node, `JsxAttr(${attrName})`);
        }
      }
    }

    // 4. 数据配置对象字段: { tooltip: "中文", confirmText: `确认：${name}` }
    if (ts.isPropertyAssignment(node)) {
      const propName = node.name.getText(sf);
      if (EXTENDED_DATA_COPY_KEYS.has(propName)) {
        inspectExpression(node.initializer, node, `DataCopy(${propName})`);
      }
    }

    ts.forEachChild(node, visit);
  }

  visit(sf);
  return violations;
}
```
