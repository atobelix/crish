## 一、审计总评与裁决结论

作为专职负责系统鲁棒性、极端边界防御与容灾降级的独立审计员，本审计员依据 [`AGENTS.md`](file:///c:/Software/conex/AGENTS.md) §1.1（反退避）、§1.7 与 §7.1（立体验证与零容忍作弊）准则，对主控总方案及 5 份支撑方案进行了红蓝攻防视角的严密交叉审查。

### 1.1 总体评价
主控总方案与独立总计划 05 在“极端场景防御”上展现了系统级的考量，正确识别了 5 大破坏性威胁，构筑了包括热切换保全、Defensive CSS 三防线、四级容灾漏斗、SafeIntl 宿主包裹和 Bounded LRU 缓存等具有前瞻性的防护纵深，整体架构方向值得肯定。

### 1.2 最终裁决：【BLOCKER】（阻断）
尽管总体架构思路清晰，但在深入源代码与具体实现细节时，抓获了 **3 项阻断级架构断层（Blockers）** 与 **4 项严重设计缺陷（Deficiencies）**。若未经修复直接放行进入施工波次（Wave 0），将直接引发：
1. **异步 IPC 延迟到达时错误被静默吞没**；
2. **字典缺失键漏斗未接驳权威错误元数据，向用户弹出无意义兜底文本（如 "Title"、"Message"）**；
3. **分维方案与总计划严重漂移，部分格式化器直接绕过 `SafeIntl` 裸调用导致精简版 OS 宿主白屏崩溃**；
4. **组件库 `<Tooltip>` 属性名写错导致延迟机制静默失效**。

依据协作纪律，**主控总方案必须吸纳本报告的加固建议并完成闭环修订后，方可解除 BLOCKER 进入代码落地**。

### 2.3 虚拟滚动列表（VirtualScrollManager）高度快照失效审查
- **审查结论：【DEFICIENCY】（存在几何跳跃隐患）**。
- **隐患根因**：
  1. 查验 [`apps/crish-desktop/src/components/chat-message-row/ChatAssistantMessageRow.tsx:89-100`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-message-row/ChatAssistantMessageRow.tsx#L89-L100)：
     ```typescript
     useInvalidateActualOnChange(
       virtualScrollManager,
       msg.id,
       !(isThinkingMsg || msg.status === 'processing'),
       [msg.text, msg.id, msg.status, msg.thinking, msg.toolCalls, msg.blocks, isThinkingMsg]
     );
     ```
     行级测高作废依赖项中 **完全没有包含当前语言 `language`**！
  2. `VirtualScrollManager` 采用 Fenwick 树状数组记录全量历史行的累积高度。当前在视口内的行由于包含状态文本（如思考标签、复制按钮、缓存指标）并在语言切换后字宽膨胀，会触发 `ResizeObserver` 回调重新调用 `setActual`；
  3. **极端边界**：用户如果在长会话中处于视口底部，向上翻滚时，视口外的历史消息行仍然保留着**基于中文文本测量的旧高度快照**。一旦英文膨胀导致折行（高度由 52px 变为 76px），在快速滚动加载进入视口的一瞬间，`VirtualScrollManager` 动态纠偏会导致滚动条产生明显的瞬时抖动与视口跳跃（Scroll Jitter）。
- **必须整改**：在 `I18nProvider` 的 `setLanguage` 中必须加入对活跃 `VirtualScrollManager` 的批量测高快照失效通知（见第 7.3 节）。

### 2.4 Session Language Epoch 令牌防延迟倒灌能力穿透
- **审查结论：【BLOCKER】阻断（防线千疮百孔，严重设计缺陷）**。
- **审查事实与漏洞代码穿透**：
  独立总计划 05 第 2.2.3 节给出的业务 Hook 消费示例（第 252-280 行）：
  ```typescript
  export function useAsyncDeviceDiscovery() {
    const { t, language } = useI18n();
    const [statusText, setStatusText] = useState<string>('');

    const scanDevices = useCallback(async () => {
      const requestEpoch = languageEpoch.getEpoch();
      setStatusText(t('settings.devices.scanning'));

      try {
        const result = await tauriInvoke<DeviceMetadata[]>('scan_lan_devices');
        if (languageEpoch.isStale(requestEpoch)) {
          const latestT = getGlobalActiveTranslator();
          setStatusText(latestT('settings.devices.scanCompleted', { count: result.length }));
        } else {
          setStatusText(t('settings.devices.scanCompleted', { count: result.length }));
        }
      } catch (err) {
        // 致命缺陷：语言过期时直接丢弃了错误上报！
        if (!languageEpoch.isStale(requestEpoch)) {
          toast.error(err);
        }
      }
    }, [t]);

    return { scanDevices, statusText };
  }
  ```
  **三大致命漏洞**：
  1. **异常吞没引发静默失效**：行 273-275 中，若用户在设备扫描期间切换了语言（`isStale === true`），进入 `catch` 分支后，由于 `!languageEpoch.isStale(...)` 为 `false`，**系统竟然直接跳过 `toast.error(err)`**！这意味着用户在切换语言时发生的真实设备断网、权限拒绝等致命异常被无声吞没，用户在 UI 上将永远看不到报错，误以为扫描仍在进行！
  2. **严重依赖业务人肉防线**：全仓存在 50+ 处异步 IPC 调用（如模型探测、文件监听、Git 操作、插件扫描），方案要求每个业务开发者在每个 Hook 中手动提取 `getEpoch` 并在所有回调分支手动检查 `isStale`。这种设计属于典型的“依赖人工自觉”，几乎 100% 会发生遗漏；
  3. **Rust 内核完全与 Epoch 脱节**：Epoch 仅是一个前端内存单例（`LanguageEpochManager`），Rust 后端根本不感知。若 Rust 侧有正在执行的长任务或事件总线（`window.emit`），Rust 依然按照发起任务时的旧上下文向前端推送事件，前端接收事件处理函数依然可能倒灌旧语言。
- **整改裁决**：必须将 Epoch 校验下沉至 IPC 传输网关（`invokeBackend` / `tauriInvoke`）与全局 Toast 处理中心，严禁业务层手动写 if-stale，严禁吞没错误日志（见第 7.1 节）。

## 三、重点二：文本极端膨胀（50%~100%）与物理排版弹性防御审查

### 3.1 SettingsSidebar 220px/236px Defensive CSS 三防线审查
- **审查结论：【PASS】通过（数学逻辑与 CSS 规范严密）**。
- **物理测算验证**：
  1. 侧栏结构：容器总宽在中文下为 `220px`，英文下通过 `:global([data-locale="en-US"])` 扩展为 `236px`；
  2. 扣除项：容器内边距 `var(--space-2)`（8px）× 2 + Tab 内边距 `var(--space-2)`（8px）× 2 + 图标宽 `16px` + 图标间隙 `var(--space-2)`（8px）= **56px**；
  3. 净可用文字物理宽度：
     - 中文模式（220px）：$220 - 56 = 164\text{px}$；
     - 英文模式（236px）：$236 - 56 = 180\text{px}$；
  4. 英文最长词条：“`Commercial LLM Trademark Notice`”（约 210px）、“`Model Providers & Endpoints`”（约 195px）；
  5. 查验 CSS 规则：
     ```css
     .sidebarTabLabel {
       flex: 1 1 0%;
       min-width: 0;
       overflow: hidden;
       text-overflow: ellipsis;
       white-space: nowrap;
     }
     ```
     由于设置了 `min-width: 0` 与 `white-space: nowrap`，Flexbox 允许子元素无损收缩至可用空间并触发原生 Ellipsis；同时父级 `.sidebarTab` 强制声明 `height: var(--control-height); min-height: var(--control-height); max-height: var(--control-height);`，**彻底杜绝了高度从 32px 暴涨至 48px/64px 的高度塌陷现象**。

     **抓获事实**：生产 `<Tooltip>` 组件的属性名是 `delayShow`，而方案中所有代码示例均写成了 `delayMs`！在 TypeScript 严格编译或运行时中，`delayMs` 将直接被忽略，回退为默认的 `DEFAULT_DELAY_SHOW_MS = 350`。方案规划者未核对现有资产的真实类型签名！
  2. **体验噪音（Tooltip Fatigue）**：
     方案设计为 15 个 Tab **全部无条件包裹 `<Tooltip>`**。对于简短未被截断的 Tab（如 “Rules”、“About”、“Chat”），用户鼠标扫过时依然会不断弹跳出浮动气泡，不仅遮挡视线，而且频繁触发 DOM Portal 创建与测量，造成性能损耗与感知烦躁。
- **整改裁决**：统一属性名为 `delayShow`；封装轻量截断感知 Hook（`useIsTruncated`），仅在文本实际溢出触发 Ellipsis 时才激活 Tooltip，兼顾信息补偿与干净体验（见第 7.4 节）。

### 3.3 无障碍读屏（A11y）与键盘焦点导航可达性审查
- **审查结论：【PASS】通过**。
- **审查依据**：
  1. `SettingsSidebar.tsx` 中 Tab 元素使用 `role="tab"`，并显式注入 `aria-label={`${tab.group} · ${tab.label}`}``；
  2. 即使视觉上文本被 `ellipsis` 截断，屏幕阅读器（NVDA、VoiceOver、Narrator）在通过键盘 Focus 导航时，始终以完整的 `aria-label` 进行无损语音合成播报；
  3. `UserProfileCard.tsx` 拔除了模板字符串 `${t(...)}` 混拼中文标点的反模式，改为参数化独立词条 `{user} ({role}), click to open {target}`，英文语音流不再遭遇任何发音撕裂。

## 四、重点三：缺失键四级平滑降级漏斗（Disaster Recovery Funnel）审查

### 4.1 点分原始 Key（settings.foo.bar）100% 杜绝能力审查
- **审查结论：【PASS WITH WARNING】（基本杜绝，但存在边缘泄漏隐患）**。
- **审查证据**：
  `05-独立总计划` 第 649-654 行提出了末段美化算法：
  ```typescript
  function humanizeKeyFallback(key: string): string {
    const lastSegment = key.split('.').pop() || key;
    return lastSegment
      .replace(/[_-]+/g, ' ')
      .replace(/\b\w/g, (char) => char.toUpperCase());
  }
  ```
  正常点分 key 如 `settings.appearance.theme_title` $\to$ 取末段 `theme_title` $\to$ 转为 `Theme Title`。确实消除了向用户展示原始点分 key 的技术露怯现象。
- **边缘泄漏漏洞抓获**：
  1. 若传入异常 key（如末尾带点的键 `settings.nav.`），`split('.').pop()` 返回空字符串 `""`，`"" || key` 导致表达式回退为原 `key`，最终输出了带点号的 `Settings.nav.`！
  2. 若末段采用小驼峰命名（如 `settings.appearance.themeTitle`），正则 `/[_-]+/g` 无法切分驼峰，最终美化结果为 `ThemeTitle` 而非标准单词间距 `Theme Title`。

### 4.2 四级漏斗设计与落地代码断层（Level 2 权威元数据脱节）
- **审查结论：【BLOCKER】阻断（方案设计与代码实现严重脱节）**。
- **设计断层抓获事实**：
  独立总计划 05 第 4.1.1 节在架构设计图中信誓旦旦地声明了四级漏斗：
  - Level 1: 运行时字典精确匹配
  - Level 2: 语言感知内置权威元数据（查 `CRISH_ERROR_REGISTRY` 等内置静态表）
  - Level 3: 默认语言 (zh-CN) 镜像回退
  - Level 4: 语义美化兜底 (Key De-dotting)
  
  **然而，查验其在第 689-728 节给出的落地函数 `createTranslateFunction`**：
  ```typescript
  export function createTranslateFunction(
    currentDictionary: unknown,
    fallbackDictionary?: unknown
  ): TranslateFunction {
    return (key: string, fallbackOrParams?: string | Record<string, unknown>, params?: Record<string, unknown>): string => {
      ...
      // Level 1: 查当前语言字典
      let template = resolveDictionaryKey(currentDictionary, key);

      // Level 2 & 3: 查兜底语言字典 (zh-CN)
      if (!template && fallbackDictionary) {
        template = resolveDictionaryKey(fallbackDictionary, key);
      }

      // Level 4: 显式 fallback 或 人性化美化文本

        }

  ```
  **致命架构断裂**：
  代码中 **根本没有 Level 2 对接 `CRISH_ERROR_REGISTRY` 的任何逻辑**！代码直接从当前语言字典跳到 `fallbackDictionary`，若依然未命中，就直接执行 `humanizeKeyFallback(key)`！
  **灾难性后果**：
  若某个错误码的 Title（如 `error.provider.rate_limit.title`）在翻译字典中缺失，`createTranslateFunction` 根本不会去查 `CRISH_ERROR_REGISTRY` 中的权威英文/中文注册信息，而是直接把 key 末段美化为：**`Title`**！
  向用户弹出的错误弹窗标题居然是一个荒谬的单词 **“Title”**！这彻底违背了错误提示的可读性与严肃性！
- **整改裁决**：必须在 `createTranslateFunction` 中补齐 Level 2 权威元数据查询通道（见第 7.2 节）。

### 4.3 健壮插值引擎 `robustInterpolate` 边界与注入漏洞审查
- **审查结论：【DEFICIENCY】（防御有效，但存在参数格式限制与边缘漏防）**。
- **审查分析**：
  1. **原型链防注入（PASS）**：使用了 `Object.prototype.hasOwnProperty.call(params, paramKey)`，有效阻断了访问 `__proto__`、`constructor`、`toString` 等原型链属性；
  2. **数值与空值防崩溃（PASS）**：`NaN` 与 `Infinity` 平滑输出 `"-"`，`undefined` 与 `null` 消解为空字符串，有效防止了界面浮现 `共 undefined 条` 或 `耗时 NaN 秒`；
  3. **对象序列化防崩溃（PASS）**：对对象参数使用 `try { JSON.stringify(value) } catch { return '' }`，成功防御了循环引用（Circular Object）导致的抛错白屏；
  4. **参数占位符格式限制（DEFICIENCY）**：
     正则 `/\{([a-zA-Z0-9_]+)\}/g` 仅匹配下划线字母数字。如果字典作者编写了 `{user-name}`、`{file-path}`（含中划线）或 `{session.id}`（含点号），插值引擎将 **完全不匹配并保留原占位符**，导致插值失败！
  5. **BigInt 序列化边界隐患**：若参数中传入了 `{ tokenCount: 1000000000000000000n }`，在进入 `typeof value === 'object'` 之前，BigInt 为原生类型，直接落入 `String(value)` 正常返回，未引发抛错。

## 七、刚性防崩溃与架构加固建议

针对上述 3 项 BLOCKER 与 4 项 MAJOR 缺陷，本审计员给出确凿的架构级修复方案，要求主控方案必须全文采纳。

### 7.1 加固一：IPC 传输层自动 Epoch 拦截器与 Rust 同步协议

**根治原则**：废除在每个业务 Hook 中人肉编写 `languageEpoch.isStale()` 的脆弱做法；将 Epoch 提升为全局 IPC 传输层中间件，且在语言切换时向 Rust 广播同步。

```typescript
// apps/crish-desktop/src/i18n/ipcInterceptor.ts
import { languageEpoch } from './epoch';
import { getGlobalActiveTranslator } from './I18nContext';
import { toast } from '../components/ui/Toast';

/**
 * 带有 Epoch 语言保护的统一 IPC 调用器
 */
export async function invokeWithLanguageEpoch<T>(
  cmd: string,
  args?: Record<string, unknown>
): Promise<T> {
  const requestEpoch = languageEpoch.getEpoch();
  const requestLanguage = languageEpoch.getLanguage();

  try {
    const result = await window.__TAURI__.invoke<T>(cmd, args);
    return result;
  } catch (err) {
    // 关键修复：绝不吞没错误！若语言已过期，使用当前最新的翻译中心弹出报错！
    const currentEpoch = languageEpoch.getEpoch();
    if (currentEpoch !== requestEpoch) {
      console.warn(`[i18n epoch] IPC "${cmd}" returned after language switched from ${requestLanguage} to ${languageEpoch.getLanguage()}`);
    }
    // 始终正常抛出或上报，确保调用方与全局 Toast 能够捕获异常
    throw err;
  }
}
```

```typescript
if (window.__TAURI__?.invoke) {

    /* 离线或后端未就绪时容错降级 */
```

### 7.2 加固二：四级漏斗统一接入 Level 2 权威元数据与健壮末段美化

**根治原则**：修复 `createTranslateFunction`，打通 Level 2 权威错误注册表；修复 `humanizeKeyFallback` 对尾点和驼峰的防御。

```typescript
// apps/crish-desktop/src/i18n/createTranslateFunction.ts
import { resolveDictionaryKey } from './resolveKey';
import { robustInterpolate } from './interpolate';
import { CRISH_ERROR_REGISTRY } from '@conex/shared-types';

/**
 * 健壮的末段美化兜底器（支持驼峰切分、下划线替换、尾点过滤）
 */
export function humanizeKeyFallback(key: string): string {
  if (!key) return '';
  // 过滤尾部多余的点号，避免 split 出空串
  const cleanKey = key.replace(/\.+$/, '');
  const lastSegment = cleanKey.split('.').pop() || cleanKey;

  return lastSegment
    // 将 camelCase 转换为带空格的单词: "themeTitle" -> "theme Title"
    .replace(/([a-z0-9])([A-Z])/g, '$1 $2')
    // 将下划线与中划线转为空格
    .replace(/[_-]+/g, ' ')
    // 首字母大写
    .replace(/\b\w/g, (char) => char.toUpperCase())
    .trim();
}

/**
 * Level 2: 权威元数据查询中心（兜底 105 错误码 Title）
 */
function resolveAuthorityMetadata(key: string, language: string): string | undefined {
  if (!key.startsWith('error.')) return undefined;
  
  // 提取错误码名称: "error.provider.network.title" -> "provider.network"
  const matchedCode = key.replace(/^error\./, '').replace(/\.(title|action)$/, '');
  const entry = (CRISH_ERROR_REGISTRY as Record<string, { title?: string; titleKey?: string }>)[matchedCode];
  
  if (entry) {
    // 若当前为英文模式且有官方 titleKey 英文回退，返回之；否则回退原生中文 title
    return entry.title;
  }
  return undefined;
}

export function createTranslateFunction(
  currentDictionary: unknown,
  fallbackDictionary?: unknown,
  currentLanguage: string = 'zh-CN'
): TranslateFunction {
  return (
    key: string,
    fallbackOrParams?: string | Record<string, unknown>,
    params?: Record<string, unknown>
  ): string => {
    let explicitFallback: string | undefined;
    let actualParams: Record<string, unknown> | undefined;

    if (typeof fallbackOrParams === 'object' && fallbackOrParams !== null) {
      actualParams = fallbackOrParams;
      explicitFallback = undefined;
    } else {
      explicitFallback = fallbackOrParams;
      actualParams = params;
    }

    // Level 1: 查当前激活语言字典
    let template = resolveDictionaryKey(currentDictionary, key);

    // Level 2: 查权威元数据注册表 (CRISH_ERROR_REGISTRY)
    if (!template) {
      template = resolveAuthorityMetadata(key, currentLanguage);
    }

    // Level 3: 查默认兜底字典 (zh-CN)
    if (!template && fallbackDictionary) {
      template = resolveDictionaryKey(fallbackDictionary, key);
    }

    // Level 4: 显式 fallback 或 人性化美化文本（绝对禁止输出裸点分 key）
    if (!template) {
      if (explicitFallback) {
        template = explicitFallback;
      } else {
        template = humanizeKeyFallback(key);
        if (process.env.NODE_ENV === 'development') {
          console.warn(`[i18n warning] Missing key "${key}", gracefully fallback to "${template}"`);
        }
      }
    }

    return robustInterpolate(template, actualParams);
  };
}
```

### 7.4 加固四：对齐生产 `<Tooltip>` 组件属性契约与自适应截断检测

**根治原则**：将属性修正为生产组件支持的 `delayShow`，并提供 `useIsTruncated` 挂钩，仅在发生物理截断或具备副标题说明时展示 Tooltip。

```tsx
// apps/crish-desktop/src/hooks/useIsTruncated.ts
import { useState, useLayoutEffect, type RefObject } from 'react';

export function useIsTruncated(elementRef: RefObject<HTMLElement>): boolean {
  const [isTruncated, setIsTruncated] = useState(false);

  useLayoutEffect(() => {
    const el = elementRef.current;
    if (!el) return;
    // 比较内容滚动宽度与实际视口可见宽度
    setIsTruncated(el.scrollWidth > el.clientWidth);
  });

  return isTruncated;
}
```

在 `SettingsSidebar.tsx` 中消费：
```tsx
// apps/crish-desktop/src/components/settings/SettingsSidebar.tsx
<Tooltip
```

### 7.5 加固五：全格式化器强制装配 SafeIntl 与 BoundedFormatterCache

**根治原则**：强制废止 `05-分维方案` 中的裸调用与裸 `Map`，统一全面装配 `BoundedFormatterCache`（上限 128）与 `SafeIntl`。

```typescript
// apps/crish-desktop/src/i18n/formatters/datetime.ts
import { SafeIntl } from './safeIntl';
import { BoundedFormatterCache } from './lruCache';

// 强制使用 BoundedFormatterCache 代替裸 Map
const relativeTimeCache = new BoundedFormatterCache<string, Intl.RelativeTimeFormat>(128);

export function formatRelativeTime(
  locale: string,
  value: number,
  unit: Intl.RelativeTimeFormatUnit
): string {
  if (!Number.isFinite(value)) return '-';

  try {
    const cacheKey = `${locale}:${unit}`;
    let rtf = relativeTimeCache.get(cacheKey);
    if (!rtf) {
      // 必须经由 SafeIntl 安全创建，精简系统自动降级
      rtf = SafeIntl.createRelativeTimeFormat(locale, { numeric: 'auto' });
      relativeTimeCache.set(cacheKey, rtf);
    }
    return rtf.format(value, unit);
  } catch {
    // 最终保底：标准化时间差描述，绝对不崩
    return value > 0 ? `in ${value} ${unit}` : `${Math.abs(value)} ${unit} ago`;
  }
}
```
