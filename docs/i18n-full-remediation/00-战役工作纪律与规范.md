# i18n 全面多语言化战役工作纪律与规范

> **战役代号**：`i18n-full-remediation`
> **权威协作基准**：仓库根目录 [`AGENTS.md`](../../AGENTS.md) 与 [`.agents/LOGIC_PLAN_NO_RETREAT.md`](../../.agents/LOGIC_PLAN_NO_RETREAT.md)。
> **战役目标**：将 Conex / Crish 客户端从当前“仅有基础骨架、UI 覆盖率 < 3%”的样板起步状态，全面升级为成熟、完善、类型安全、零死角覆盖且具备自动化防回归门禁的企业级国际化（i18n）系统。

---

## 一、核心原则与反作弊铁律（零容忍）

根据 [`AGENTS.md`](../../AGENTS.md) §1.1、§1.7 及 7.1，参与本战役的主控与所有子 Agent 必须无条件恪守以下纪律：

1. **效果锁与完整性（禁止降级与偷懒）**：
   - 严禁自行砍需求、砍范围、以“MVP / 简化版”为借口只做几个页面；
   - 必须穿透到所有实际用户交互面：所有设置面板（15 个 Tab）、对话流、输入框（Composer）、工具调用卡片、侧边栏、状态通知、模态弹窗、可访问性读屏（`aria-label` / `aria-description`）；
   - 必须覆盖 105 个核心错误码（`CRISH_ERROR_REGISTRY`）与底层渲染层（如 Markdown 复制按钮）。

2. **严禁打补丁与伪国际化（杜绝表面功夫）**：
   - 严禁使用字符串拼接方式翻译句子（如 `t('user') + ':' + name` 或 `aria-label={'用户卡片：' + ...}`），必须使用标准变量插值 `{name}`，确保语序符合各语言语法习惯；
   - 严禁在代码中写死中文三元表达式（如 `lang === 'zh-CN' ? '中文' : 'English'`），所有文本必须收口入字典；
   - 严禁盲目复制机器翻译而不核对语境，英文文案必须符合原生桌面软件术语规范。

3. **立体验证与门禁不妥协**：
   - 绝对禁止使用 `--no-verify` 跳过 Git 门禁；
   - 静态类型检查（`npm run typecheck`）与单元测试全绿是基本底线；
   - 必须建立自动化扫描与门禁：字典 100% 对齐检查（Zero Missing Keys）、TSX 源码零未声明中文字符扫描门禁（Zero Hardcoded Chinese in unexempted UI components）；
   - 真实渲染与截断校验：必须考虑英文文本相较中文膨胀 30%~50% 对 Flex/Grid 布局造成的排版影响，杜绝溢出与省略号截断。

4. **审计与监督机制**：
   - 战役全流程设立专职审计位，贯穿“方案前审计”、“方案期审计”、“实现期交叉抽检”与“最终验收审计”；
   - 审计 Agent 必须独立执行严格检查，凡发现“空头承诺”、“未落地假完成”、“单测仅做假断言”等作弊偷懒行为，一律打回重做并在审计报告中留痕。

## 二、战役协作流与规范（全生命周期）

根据 `docs/agent-roles/README.md` §3 规范，本战役严格执行标准协作流：

```
Phase 1: 全景勘察与问题发现（多 Agent 6 维度并行摸底，问题同权）
    ↓
Phase 2: 分维最佳系统解方案（各维独立成文，深入架构根因）
    ↓
Phase 3: 独立总计划（2~3 份独立总案，全局贯通）
    ↓
Phase 4: 主控定夺总方案与分维终稿（收敛总纲与执行标准）
    ↓
Phase 5: 方案双盲独立审计（审查任务粒度、冲突点、门禁与验收断言）
    ↓
Phase 6: 主控发布通用执行规范与波次派单（明确文件域与串并行锁）
    ↓
Phase 7: 分波次实现（代码重构、字典构建、业务替换、门禁研发）
    ↓
Phase 8: 执行期交叉审计与立体验证（动静态扫描、真实 UI 对齐、防回归测试）
    ↓
Phase 9: 主控统一收口与交付（主 Agent 执行 git commit --only 收口）
```

## 三、文件域与提交纪律

1. **战役目录规范**：
   - 根目录：只允许存放调度状态/锚点、总方案与分维终稿；
   - 子目录（严格一级）：`problems/`、`independent-plans/`、`plan-audits/`、`audits/`、`execution/`；
   - 严禁散落碎片文件夹。
2. **提交权仅归主 Agent**：
   - 子 Agent 完成任务后改动留在工作区，由主 Agent 验证无误后使用 `git commit --only <paths>` 收口提交；
   - 严禁任何 Agent 执行 `reset --hard`、`checkout .` 或 `restore`；
   - 文件写入必须保证 UTF-8 无 BOM。
