## 一、执行总纲与纵向贯通战略蓝图

### 1.1 规划使命与破局定位

在现代桌面客户端混合架构（Rust 内核 + Tauri IPC 桥接 + Webview2 React 前端）中，国际化（i18n）最致命的陷阱往往是“**横向看面面俱到，纵向上一触即溃**”：
- 很多国际化方案仅停留于前端 TSX 视觉文案的简单抽取，却对**底层 Rust 内核渲染器（conex-markdown）**中硬编码生成的 HTML 视而不见；
- 当 Rust 试图直接修改 HTML 属性时，又由于前端 **DOM 调和器（unitReconciler.ts）** 在底层写死了中文选择器反向依赖，引发了难以排查的排版隔离失效与重排掉帧故障；
- 会话循环（session-loop）在自愈推进大模型输出时，不管用户使用的是英文还是中文，强行单向注入中文 Steering Nudge，导致大模型上下文被中文污染并发生严重的语言漂移；
- 跨端 IPC 通信与移动推送层面，Rust 侧抛出野生中文拼接错误，前端又假设错误已被 Rust 本地化，导致 Toast 与通知双向陷入“假本地化”错觉；
- 业务逻辑层由于缺乏中立设计，在会话行（SessionRow.tsx）依赖中文正则剥离会话标题，破坏英文分支；在脱水逻辑（chatEmptyState.ts）中硬编码中文破坏 UI 表现。

**本规划师的唯一核心使命**：站在**全栈纵向架构贯通（Vertical Full-Stack Integration）**的至高视角，自底向上打通一条从 **Rust 内核渲染与推进引擎 ➔ Tauri IPC 跨进程通信与推送 ➔ 共享类型契约（shared-types） ➔ 前端翻译与错误中枢 ➔ 前端 DOM 调和器与 React UI 呈现** 的无缝真国际化数据高速链路。彻底破除跨层壁垒，消除反向耦合，提供一套**可执行、可验证、零硬编码、零回归、零退避**的全局总计划。

## 二、Rust 内核渲染引擎与前端 DOM 调和器纵向解耦闭环

### 2.1 架构决议：语言中立语义 DOM 结构（方案 B）

在底层 Markdown 渲染架构选型上，本规划坚定确立并裁决采纳 **方案 B（语言中立语义 DOM + 表现层解耦）**，彻底否决“让 Rust 内核感知用户 Locale（方案 A）”的退避与过度设计方案：

```
┌────────────────────────────────────────────────────────────────────────┐
│ 为什么必须选择方案 B？(架构不变量与性能证据)                           │
├────────────────────────────────────────────────────────────────────────┤
│ 1. 保护 Rust LRU 渲染缓存命中率：                                       │
│    crates/conex-markdown 维护全局 LRU 渲染缓存。若将语言作为缓存 Key，  │
│    缓存将膨胀分裂；用户切换语言会导致数千条富文本缓存全量雪崩失效。    │
│ 2. 保证历史消息 0 毫秒即时切换：                                       │
│    SQLite 数据库持久化了历史消息的 HTML 渲染产物。采用方案 B，历史产物 │
│    天然语言中立，切换语言时无需全库重新解析渲染，前端样式与事件瞬间自愈。│
│ 3. 严格恪守单一真理源 (SSOT)：                                         │

│    笨重不可控的第三方本地化库（恪守 ANTI_OVERENGINEERING_GUARDRAILS）。 │
└────────────────────────────────────────────────────────────────────────┘
```

#### 2.4.1 致命隐患根因

#### 2.4.2 紧急解耦与向下兼容实现
在 `unitReconciler.ts` 中建立标准选择器常量，以中立类名与数据属性为核心，同时向下兼容旧历史消息：

```typescript
/**
 * 表格排版隔离选择器（Layout Containment Selector）
 * 核心真理源：中立类名 `.md-table-wrap` 与语义属性 `[data-md-table]`
 * 兼容层：对历史持久化消息中的已渲染 HTML 保留向下兼容支持
 */
export const TABLE_LAYOUT_ISOLATION_SELECTOR = [
  '.md-table-wrap',
  '[data-md-table]',
  '[role="region"][data-role="table"]',
  // 历史存量消息向下兼容容错（只读兼容，严禁新代码产出）
  '[role="region"][aria-label="表格"]',
  '[role="region"][aria-label="Data table"]',
  '[role="region"][aria-label="Table"]',
].join(', ');

function applyLayoutIsolation(element: Element): void {
  if (element.matches(TABLE_LAYOUT_ISOLATION_SELECTOR)) {
    (element as HTMLElement).style.contain = 'layout';
  }
}

function createUnitNode(unit: MarkdownUnit): Node {
  const clone = unit.sourceNode.cloneNode(true);
  if (clone.nodeType === Node.ELEMENT_NODE) {
    const element = clone as Element;
    applyLayoutIsolation(element);
    for (const nested of Array.from(
      element.querySelectorAll(TABLE_LAYOUT_ISOLATION_SELECTOR)
    )) {
      applyLayoutIsolation(nested);
    }
  }
  return clone;
}
```

在核心引擎层，会话意图推进的提示词注入必须具备**会话语言环境感知（SLC）**，避免在英文对话中强插中文 Nudge 导致模型混乱：

```
┌────────────────────────────────────────────────────────┐
│ 会话语言环境 (SLC) 四级动态推导架构                    │
├────────────────────────────────────────────────────────┤
│ Level 1: 显式会话配置 (Explicit Assembly Setting)       │
│          options.assembly.locale (e.g. "en-US")        │
├──────────────────────────┬─────────────────────────────┤
│                          ▼ (若为 None / 缺省)          │
│ Level 2: 意图命中特征分流 (Trigger Pattern Match)       │
│          ToolPromiseDetector 命中的关键词是英文还是中文 │
├──────────────────────────┬─────────────────────────────┤
│                          ▼ (若无法判定)                │
│ Level 3: 上下文 CJK 密度探测 (Context CJK Ratio)        │
│          最后一条 Assistant 消息的 CJK 字符比例 (< 10%) │
├──────────────────────────┬─────────────────────────────┤
│                          ▼ (兜底默认)                  │
│ Fallback: 客户端全局语言环境 / 默认语言 ("zh-CN")      │
└────────────────────────────────────────────────────────┘
```

#### 探测引擎纯逻辑实现（Rust）：
```rust
// crates/session-loop/src/steering/locale_detector.rs

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SessionLocale {
    ZhCn,
    EnUs,
}

impl SessionLocale {
    pub fn from_str_loose(s: &str) -> Self {
        if s.starts_with("en") || s.eq_ignore_ascii_case("english") {
            SessionLocale::EnUs
        } else {
            SessionLocale::ZhCn
        }
    }
}

pub struct SessionLanguageDetector;

impl SessionLanguageDetector {
    pub fn resolve_locale(
        explicit_locale: Option<&str>,
        matched_snippet: &str,
        assistant_text: &str,
    ) -> SessionLocale {
        if let Some(locale) = explicit_locale {
            if !locale.trim().is_empty() {
                return SessionLocale::from_str_loose(locale);
            }
        }
        if Self::looks_like_english(matched_snippet) {
            return SessionLocale::EnUs;
        }
        let cjk_count = assistant_text.chars().filter(|c| is_cjk_char(*c)).count();
        let total_count = assistant_text.chars().count();
        if total_count > 0 && (cjk_count as f64 / total_count as f64) < 0.10 {
            SessionLocale::EnUs
        } else {
            SessionLocale::ZhCn
        }
    }

    fn looks_like_english(s: &str) -> bool {
        let ascii_count = s.chars().filter(|c| c.is_ascii_alphabetic()).count();
        let cjk_count = s.chars().filter(|c| is_cjk_char(*c)).count();
        ascii_count > cjk_count && cjk_count == 0
    }
}

#[inline]
fn is_cjk_char(c: char) -> bool {
    matches!(c, '\u{4E00}'..='\u{9FFF}' | '\u{3400}'..='\u{4DBF}' | '\u{F900}'..='\u{FAFF}')
}
```

```typescript
export const BRANCH_SUFFIX_REGEX = / - (?:分支|Branch)$/i;

export function getSessionCleanTitle(title: string, isBranched: boolean): string {
  if (!isBranched) return title;
  return title.replace(BRANCH_SUFFIX_REGEX, '').trim();
```
