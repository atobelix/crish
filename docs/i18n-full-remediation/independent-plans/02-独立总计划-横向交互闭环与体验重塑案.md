## 规划师誓约与总体架构使命

作为【横向交互闭环与体验重塑独立总规划师】，本规划师不谈空洞的口号与抽象的分层，**将视线 100% 聚焦于真实终端用户打开软件、操作界面、感知反馈、聆听读屏的端到端交互现场**。

国际化（i18n）绝非简单的“提取字符串并在界面调用 `t(key)`”。在现代本地优先（Local-First）高密度桌面应用中，语言切换是一场对**视图状态机、动态配置表单、CSS 物理几何排版、异步数据求值、无障碍辅助树（a11y Tree）以及全局错误与通知反馈链条**的全面考验。

当前 Conex / Crish 客户端在横向交互面上存在大量“伪国际化”、“架构硬编码”与“排版视盲”缺陷：

1. **设置中心 15 个 Tab 的静态死锁**：`TAB_META` 写死中文静态常量，切换语言后侧栏与搜索别名零响应；`useAppearanceSchema` 等表单 Hook 强行在逻辑层物化汉字；
2. **侧边栏物理排版缺乏弹性防御**：220px 容器硬编码，英文宽度膨胀 30%~70% 引发致命折行、垂直错位与高度塌陷；
3. **会话分支逻辑与中文强绑定**：`SessionRow.tsx:270` 依赖中文正则 `replace(/ - 分支$/, '')` 还原标题，导致英文分支逻辑撕裂；
4. **对话流主列下层绑死上层**：`api/chatEmptyState.ts` 脱水业务纯逻辑直接输出中文常文，破坏 UI 国际化并绑死 699 行单测资产；
5. **Composer 输入全家桶与权限模式硬编码**：四档权限模式说明、斜杠指令、思考时间度量、工具审批倒计时全量裸写中文；
6. **Toast 告警采用中文正则猜类型**：通知系统不仅自身写死中文，还使用 `/失败|错误|无法|拒绝/` 猜测错误等级，对后端返回的 105 个结构化错误码视而不见；
7. **无障碍读屏（a11y）科学怪人式拼接**：`UserProfileCard.tsx` 等组件使用模板字符串拼接中文，导致英文 TTS 屏幕阅读器产生严重的语音合成畸变与爆音。

本规划师承诺：**恪守反退避铁律，不砍功能、不降级需求、不打临时补丁；建立横向交互全域闭环，确保 100% 可见 UI 纳入 10 模块物理字典，实现零硬编码残留、零排版折行、零单测退化、零 a11y 语言污染**。

## 一、设置中心 15 个 Tab 与动态表单重构系统解

### 1.1 SchemaRenderer 原生 i18nKey 契约与自动求值引擎

#### 1.1.1 根因分析

在 [`apps/crish-desktop/src/components/settings/SettingsSchemaRenderer.tsx`](file:///c:/Software/conex/apps/crish-desktop/src/components/settings/SettingsSchemaRenderer.tsx#L6-L42) 中：

- `SchemaProperty` 原契约仅包含 `title: string`、`desc?: string`、`options?: { label: string }[]`；
- 所有配置表单生成 Hook（如 `useAppearanceSchema`）必须在声明时就将自然语言文本写入属性，或者由外层强行透传 `t` 函数。这不仅违背了“配置 Schema 纯数据化”原则，而且一旦在语言切换时组件未能触发全树重构，表单将保留旧语言文字。

#### 1.1.2 架构升级：原生 i18n 兼容类型契约

扩展 `SettingsSchemaRenderer.tsx` 的接口定义，支持 `*Key` 原生属性，同时保留原始属性作为向下兼容兜底：

```typescript
// apps/crish-desktop/src/components/settings/SettingsSchemaRenderer.tsx

import type { KnownTranslationKey } from '../../i18n/types';

export interface SchemaOption {
  value: string;
  /** 国际化键名（优先求值） */
  labelKey?: KnownTranslationKey | string;
  /** 兜底自然语言标签（向前兼容） */
  label?: string;
  /** 国际化提示说明键名 */
  hintKey?: KnownTranslationKey | string;
  /** 兜底提示说明 */
  hint?: string;
}

export interface SchemaToggleOption {
  value: string;
  /** 国际化键名（优先求值） */
  labelKey?: KnownTranslationKey | string;
  /** 兜底自然语言标签 */
  label?: React.ReactNode;
  icon?: React.ReactNode;
  badge?: React.ReactNode;
}

export interface SchemaProperty {
  key: string;
  type:
    | 'boolean'
    | 'select'
    | 'string'
    | 'number'
    | 'range'
    | 'color'
    | 'preset-grid'
    | 'font-selector'
    | 'toggle-group';

  /** 国际化标题键名（如 'settings.appearance.theme.title'） */
  titleKey?: KnownTranslationKey | string;
  title?: string | React.ReactNode;

  /** 国际化描述键名 */
  descKey?: KnownTranslationKey | string;
  desc?: string | React.ReactNode;

  /** 国际化占位符键名 */
  placeholderKey?: KnownTranslationKey | string;
  placeholder?: string;

  options?: SchemaOption[];
  toggleOptions?: SchemaToggleOption[];
  // 其余物理约束属性 (min, max, step, category 等保持不变)
}

export interface SchemaSection {
  titleKey?: KnownTranslationKey | string;
  title?: string;
  properties: SchemaProperty[];
}
```

#### 1.1.3 内部自动求值求真引擎

在 `SettingsSchemaRenderer` 顶层统一消费 `useI18n()`，通过纯函数在渲染时动态求值。任何语言切换瞬间，无须上层 Hook 重新构造，全表单自动秒级更新：

```tsx
// SettingsSchemaRenderer.tsx 内部纯函数
const { t } = useI18n();

const resolveI18n = (
  key: string | undefined,
  fallback: React.ReactNode | string | undefined
): React.ReactNode => {
  if (key) {
    const translated = t(key);
    if (translated !== key) return translated;
  }
  return fallback ?? '';
};
```

### 1.3 静态 TAB_META 升级为动态 useSettingsTabs() Hook

#### 1.3.1 架构撕裂点穿透

现有 [`apps/crish-desktop/src/components/settingsTabsMeta.ts`](file:///c:/Software/conex/apps/crish-desktop/src/components/settingsTabsMeta.ts#L63-L323) 将 15 个 Tab 的 `label`、`group`、`keywords` 写死为全局静态常量 `TAB_META`。

- **后果**：用户在设置中将语言从中文改为英文时，侧边栏、Tab 面板标题以及搜索过滤索引依然固定为中文，导致“用户改了语言，设置列表纹丝不动”的假国际化事故。

#### 1.3.2 解耦设计：不可变身份层 (TabIdentity) 与动态求值层 (useSettingsTabs)

将 `settingsTabsMeta.ts` 彻底解耦为两层：

1. **不可变身份层（`TAB_IDENTITIES`）**：存放语言中立的 `id`、`icon`、翻译 Key 和英文规范别名（Canonical Aliases）；
2. **动态响应 Hook（`useSettingsTabs`）**：监听 `useI18n()`，在语言切换时毫秒级重新计算 `label`、`group`、展开关键词池并维护分组与搜索函数。

```typescript
// apps/crish-desktop/src/components/settingsTabsMeta.ts
```

```typescript
// apps/crish-desktop/src/components/settings/useSettingsTabs.ts
export function useSettingsTabs(): UseSettingsTabsResult {
  const { t, language } = useI18n();

  const tabs = useMemo<TabMeta[]>(() => {
    return TAB_IDENTITIES.map((identity) => {
      const label = t(identity.labelKey);
      const group = t(identity.groupKey);
      const localizedKeywords = t(identity.keywordsKey)
        .split(/[,|、]/)
        .map((k) => k.trim())
        .filter(Boolean);
      const mergedKeywords = Array.from(
        new Set([
          ...localizedKeywords,
          ...identity.canonicalAliases,
          label.toLowerCase(),
        ])
      );

      return {
        id: identity.id,
        icon: identity.icon,
        label,
        group,
        keywords: mergedKeywords,
        demoOnly: identity.demoOnly,
      };
    });
  }, [t, language]);

  const searchTabs = useMemo(
    () =>
      (rawQuery: string): TabMeta[] => {
        const q = rawQuery.trim().toLowerCase();
        if (!q) return tabs;
        return tabs.filter(
          (tab) =>
            tab.label.toLowerCase().includes(q) ||
            tab.group.toLowerCase().includes(q) ||
            tab.keywords.some((k) => k.toLowerCase().includes(q))
        );
      },
    [tabs]
  );

  return { tabs, searchTabs /* ... */ };
}
```

```typescript
// apps/crish-desktop/src/utils/sessionTitle.ts

export const BRANCH_SUFFIX_REGEX = / - (?:分支|Branch)$/i;

/** 语言中立的分支标题纯净化函数 */
export function getSessionCleanTitle(
  title: string,
  isBranched: boolean
): string {
  if (!isBranched) return title;
  return title.replace(BRANCH_SUFFIX_REGEX, '').trim();
}

/** 语言感知的分支标题生成工厂 */
export function generateBranchTitle(
  parentTitle: string,
  lang: SupportedLanguage
): string {
  const clean = parentTitle.replace(BRANCH_SUFFIX_REGEX, '').trim();
  const suffix = lang === 'en-US' ? ' - Branch' : ' - 分支';
  return `${clean}${suffix}`;
}
```

#### 4.1.2 架构重构：原生消费结构化错误模型

对 `ToastStore` 进行重塑，原生支持接收 `CrishErrorPayload`、`CrishError`、`Error` 与字符串：

- 废除中文正则猜解；
- 统一通过 `toUserVisibleError()` 进行多语言标准化解析；
- 自动识别用户主动取消类异常（如 `runtime.aborted`），自动转为静默或微交互，不弹窗轰炸用户。

```typescript
// ToastStore 重构核心逻辑
class ToastStore {
  error(input: unknown, options?: ToastOptions) {
    // 统一经由翻译中心求真
    const visibleError = toUserVisibleError(
      input,
      activeTranslator,
      currentLanguage
    );
    if (!visibleError.visible) return; // 静默异常拦截

    this.push({
      id: generateId(),
      type: 'error',
      title: visibleError.title,
      message: visibleError.message,
      action: visibleError.action
        ? {
            label: visibleError.action.label,
            onClick: visibleError.action.handler,
          }
        : undefined,
      code: visibleError.code,
      retryable: visibleError.retryable,
    });
  }
}
```
