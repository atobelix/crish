1. **效果锁定与反退避（No-Retreat Iron Rule）**：
   严禁将全仓国际化降级为“只翻译几个常用页面”的 MVP 缩水版。所有 15 个设置 Tab、对话核心流、输入 Composer 全家桶、底层渲染复制与表格、105 个核心错误码及 Action 引导词条，必须 100% 达成无死角双语化。
2. **拒绝表面功夫与假本地化（Zero Fake Localization）**：
   彻底杜绝“英文包直接复制中文敷衍”、“模板字符串裸拼中文标点”、“代码内嵌三元硬编码分支”、“假断言欺骗测试”等 7 大劣质作弊手法。
3. **机器守门先于人工审计（Automated Guard First）**：
   把所有作弊模式转化为编译期、AST 静态分析期、提交前（Pre-commit）及 CI 服务端的刚性断言武器，让偷懒代码“写不进文件、提不进仓库、合不进主干”。
4. **立体验证与双盲交叉审计（3D Verification & Double-Blind Audit）**：

## 二、三大核心门禁工程化落地详案

为彻底根除作弊漏洞并兼顾极速反馈，本方案在 `scripts/` 下落地 3 个高内聚、零外部侵入、原生 Node.js 实现的刚性门禁脚本。

### 2.1 源码零硬编码中文扫描器（`scripts/check-i18n-hardcoded.mjs`）

#### 2.1.1 两段式混合动力引擎机制
全仓存在 420 个生产 TSX 文件。纯 AST 语法树遍历需耗时 400ms+，纯正则扫描耗时 18ms 但无法区分技术注释、样式类名与真实 UI。
为此，扫描器采用**两段式混合动力架构**：
- **Stage 1: 剥离注释的极速正则快筛（Fast Regex Filter）**：
  在内存中瞬间剥离代码块中的块级注释与单行注释（保留物理换行结构以保准行号），使用 `/[\u4e00-\u9fff]/` 检测是否存在汉字。若无中文字符，在 0.04ms 内直接放行该文件；
- **Stage 2: TypeScript Compiler API AST 深度语义判定（AST Deep Analyzer）**：
  仅对命中中文字符的文件启动 `ts.createSourceFile` 语法树精确分析，深度遍历 JSX 与数据对象，耗时精准控制在 100ms 左右。

#### 2.1.2 精确 AST 节点捕获与判定判据
扫描器针对以下 4 类节点实施精准捕获：

1. **JSX 裸文本节点 (`ts.isJsxText`)**：
   ```tsx
   <Button>保存更改</Button>           // ❌ 捕获违规：JsxText 包含 "保存更改"
   <span>当前状态：就绪</span>         // ❌ 捕获违规：JsxText 包含 "当前状态：就绪"
   ```
2. **用户感知 UI 属性 (`ts.isJsxAttribute`)**：
   限定扫描面向用户的专属 UI 属性集合 `UI_ATTRS`：
   `title`、`placeholder`、`aria-label`、`aria-description`、`aria-roledescription`、`alt`。
   无论是字面量还是表达式容器中的中文，全部严密捕获：
   ```tsx
   <input placeholder="请输入检索内容" />              // ❌ 捕获违规：UI 属性字面量
   <button aria-label={loading ? "加载中" : "就绪"} /> // ❌ 捕获违规：条件表达式中的中文
   ```
3. **数据配置对象字段 (`ts.isPropertyAssignment`)**：
   捕获下拉菜单、列表配置、Tab 声明中常见的数据文案字段 `DATA_COPY_KEYS`：
   `label`、`title`、`description`、`placeholder`、`message`、`reason`、`text`、`summary`、`subtitle`、`helper`、`empty`、`hint`。
   ```tsx
   const options = [{ label: "紧凑布局", value: "compact" }]; // ❌ 捕获违规：配置字段 label
   ```
4. **字符串与模板字面量 (`ts.isStringLiteral` / `ts.isTemplateExpression`)**：
   分析表达式中的自然语言中文，排除非 UI 场景后予以判定。

#### 2.1.3 智能非 UI 上下文安全放行规则（防误报）
为确保扫描器零误报、零打扰，内置以下 5 重上下文智能放行判据：
- **翻译调用放行 (`isInsideTCall`)**：在 `t('key', '中文兜底')` 或 `t('key')` 调用中的中文，作为开发期兜底允许存在；
- **结构化富文本组件放行 (`isInsideTrans`)**：在 `<Trans i18nKey="...">` 内部的结构化插槽标签允许存在；
- **非 UI 技术属性放行 (`NON_UI_JSX_ATTRS`)**：
  `className`、`class`、`style`、`id`、`key`、`htmlFor`、`for`、`href`、`src`、`viewBox`、`fill`、`d`、`path`、`stroke`、`width`、`height`，以及所有以 `data-*` 开头的属性放行；
- **技术代码呈现容器放行**：处于 `<pre>`、`<code>`、`<samp>`、`<kbd>` 标签内部的文本直接放行；
- **系统级基础设施调用放行**：`console.log`、`console.warn`、`console.error`、`fetch`、`encodeURIComponent`、`JSON.stringify`、`new RegExp` 等技术调用中的中文直接放行。

#### 2.1.4 严格单行抑制注释与专有名词白名单
为了彻底封死“滥用抑制注释逃避国际化”的作弊通道：
- **禁止全局与文件级通配豁免**：严禁出现 `/* eslint-disable */` 或 `/* i18n-ignore-all */`；
- **仅允许单行显式理由抑制**：语法规范为：
  ```tsx
  {/* i18n-allow: 国内大模型厂商专有名词 */}
  <span>文心一言</span>
  ```
  **语法强约束**：`i18n-allow:` 冒号后必须包含 **$\ge 3$ 个字符的具体正当理由**。形如 `/* i18n-allow */` 或 `/* i18n-allow: fix */` 的无意义注释直接被判定为无效并阻断！
- **内置品牌专有名词白名单**：
  `DeepSeek`、`Qwen`、`百度`、`文心一言`、`通义千问`、`智谱AI`、`月之暗面`、`MiniMax`、`零一万物`、`商汤科技`、`百川智能`、`讯飞星火`、`Kimi`、`Claude`、`OpenAI`、`ChatGPT`、`Grok`、`Ollama`、`Gemini`、`Anthropic`、`Mistral`、`Markdown`、`JSON`、`YAML`、`Git`、`API`、`OAuth`、`UTF-8`、`HTTP`、`HTTPS`、`IPC`、`Tauri`、`Rust`、`React`。

#### 2.1.5 CLI 规约与五元标准输出
脚本支持以下运行模式：
- `node scripts/check-i18n-hardcoded.mjs`：门禁判定模式（Pre-commit 与 CI 默认调用，实测超标即 `exit 1`）；
- `node scripts/check-i18n-hardcoded.mjs --list`：详细清单模式，打印具体文件、行号与违规内容代码段；
- `node scripts/check-i18n-hardcoded.mjs --update`：棘轮收紧模式，仅当实测违规数单调减少时允许更新基线文件。

**报错遵循仓库五元规约标准**：
```

   · 当前实测: 1 处 [JsxText "正在生成分析报告..."] 
   · 基线阈值: 0 处 (超标/退化) 
   · 正确做法: 将中文抽取至 apps/crish-desktop/src/i18n/locales/zh-CN/chat.ts 并使用 t('chat.generatingReport') 消费
```

### 2.2 词典 100% 对称性与纯度断言扫描器（`scripts/check-i18n-symmetry.mjs`）

#### 2.2.1 动态探测与 AST 转译引擎
现有测试硬编码静态导入 `zh-CN.ts` 与 `en-US.ts`，无法感知新增语言包和物理目录拆分。
全新扫描器具备**全自动动态探测引擎**：
1. 扫描 `apps/crish-desktop/src/i18n/locales/`，自动识别所有语言包目录与单文件；
2. 借助 `ts.transpileModule` 动态转译 TS 字典模块并安全求值，提取全量深层键值对象；
3. 将字典结构展开为点分扁平映射表（Flat Key-Value Map，如 `settings.appearance.theme: "主题"`）；
4. 执行耗时严格保持在 **< 30 毫秒**。

#### 2.2.2 五重刚性断言阶梯（Anti-Cheat Assertion Ladder）

```
                     ┌──────────────────────────────────────────────┐
                     │          词典五重刚性断言校验阶梯            │
                     └──────────────────────────────────────────────┘
                                             │
      ┌──────────────────────────────────────┼──────────────────────────────────────┐
      ▼                                      ▼                                      ▼
【断言 1: 键集合 100% 对称】           【断言 2: 零空值与零纯空白】           【断言 3: 反拷贝语言纯度断言】
Keys(Target) ≡ Keys(Base)             v !== '' && v.trim().length > 0        en-US 严禁包含汉字
双向零缺失、零冗余                     拒绝空字符串占位                       封死中文拷贝作弊
      │                                      │                                      │
      └──────────────────────────────────────┼──────────────────────────────────────┘
                                             │
                      ┌──────────────────────┴──────────────────────┐
                      ▼                                             ▼
          【断言 4: 插值参数集合恒等】                  【断言 5: 拒绝敷衍占位文本】
          {params} 集合双语 100% 恒等                   拦截 "TODO", "TBD", "..."
          防运行时参数解析丢失与语序损坏                严禁直接拿 Key 充当文案 Value
```

1. **断言 1：键集合双向零缺失、零冗余（Key Parity）**：
   以 `zh-CN` 为真理源基准，对所有目标语言（`en-US` 等）计算对称差分：
   - 缺失键断言：$Missing = Keys(zhCN) \setminus Keys(Target) = \emptyset$；
   - 冗余键断言：$Redundant = Keys(Target) \setminus Keys(zhCN) = \emptyset$。
2. **断言 2：叶子节点零空值断言（Non-Empty Value Guard）**：
   递归遍历每一个叶子节点的值，断言：
   `typeof val === 'string' && val.trim().length > 0`。
   赋值为 `""` 或全空格字符的，直接拦截阻断。
3. **断言 3：反作弊语言纯度断言（Anti-Copy Purity Guard）**：
   **这是彻底封杀“复制中文到英文包冒充对齐”的核心杀手锏**。
   对 `en-US` 字典中所有叶子节点执行汉字扫描：
   `CHINESE_REGEX = /[\u4e00-\u9fff]/`。
   若检测到汉字字符，立刻输出刺目警报并中断提交：
   `❌ [en-US] 键 "chat.welcome" 包含未翻译的中文残留: "欢迎使用"！禁止直接复制中文敷衍对齐！`
4. **断言 4：插值占位符参数集合 100% 恒等（Interpolation Parity）**：
   抽取模板中所有 `{paramName}` 占位符集合：
   断言 $Params(zhCN, key) \equiv Params(Target, key)$。
   杜绝参数漏写、拼写错误导致运行时暴露未解析变量。
5. **断言 5：敷衍性占位文本黑名单（Anti-Stub Placeholders）**：
   内置垃圾占位文本黑名单：`TODO`、`TBD`、`TEMP`、`FIXME`、`N/A`、`...`、`test`。
   同时严禁直接使用 Key 作为翻译值（如 `settings.save: "settings.save"`）。

### 2.3 未消费死词条与孤儿 Key 扫描器（`scripts/check-i18n-unused-keys.mjs`）

#### 2.3.1 设立初衷与防虚报机制
在国际化战役中，常见的偷懒行为是：批量在词典中塞入数百个 Key，声称“工作已全部完成”，但前端业务层由于重构或遗忘，根本未调用这些词条。
死词条会虚报工程进度、污染代码库并导致打包体积膨胀。门禁 C 专用于清除此类死代码。

#### 2.3.2 倒排索引交叉扫描引擎
1. 提取基准词典 `zh-CN` 中全部点分 Key 集合 $K_{dict}$；
2. 扫描前端与桌面全量源码文件（排除 `locales/` 本身与测试用例），建立全仓字符串索引；
3. 比对未在源码中被字面量或调用消费的孤儿键：$Unused = K_{dict} \setminus S_{consumed}$。

#### 2.3.3 动态调用白名单放行体系
为了防止逻辑动态调用的合法 Key 被误伤，扫描器建立 4 类动态白名单：

2. **设置面板动态 Tab 命名空间放行**：

3. **工具调用卡片动态工具名前缀放行**：
   放行形如 `tool.${toolName}.*` 的动态卡片文案；
4. **Markdown 与底层渲染动态中立映射放行**：
   放行与 `data-code-action` 绑定的操作文案。

#### 2.4.1 “门禁没有守卫”的元问题根治
实战中常发生的致命漏洞包括：

3. **`unreleased_guard`（零容忍）**：
   断言 `.gitignore` 中必须显式放行门禁脚本（`!scripts/check-i18n-*.mjs`），确保脚本 100% 入库；

#### 3.1.2 棘轮单向收紧算法（Monotonic Ratchet Invariant）
门禁脚本在判定与更新时执行以下数学约束：
1. **新增文件零容忍**：若文件未在基线列表中，允许的硬编码数默认为 0。一旦发现硬编码中文，直接阻断；
2. **存量反弹零容忍**：对基线已登记的文件 $f$，若当前实测违规数 $C_{curr}(f) > C_{base}(f)$，直接报错阻断；
3. **`--update` 铁律**：执行更新时，断言 $\forall f, C_{curr}(f) \le C_{base}(f)$ 且 $\sum C_{curr} < \sum C_{base}$。**只要有任何一个文件的违规数发生上升，立即拒绝写入并抛出异常**！

### 4.1 模式 1：伪翻译拷贝（Fake Translation Copy）

- **作弊手段**：将 `zh-CN.ts` 中的条目直接复制粘贴到 `en-US.ts` 中，假装完成了英文化工作。
- **潜在危害**：英文语言环境下界面充斥汉字，国际化名存实亡。
- **全自动防御机制**：
  在 `scripts/check-i18n-symmetry.mjs` 中内置语言纯度断言：
  ```javascript
  // 扫描非中文语言包（en-US 等）的汉字字符
  if (localeId !== 'zh-TW' && /[\u4e00-\u9fff]/.test(targetVal)) {
    console.error(`❌ [${localeId}] 汉字纯度违规（作弊拦截）: 键 "${key}" 包含未翻译的中文: "${targetVal}"`);
    totalErrors++;
  }
  ```
- **拦截时机**：Pre-commit 与 CI 阶段瞬时阻断。

### 4.2 模式 2：滥用抑制注释（Suppression Comment Abuse）

- **作弊手段**：遇到门禁报硬编码中文，直接在该行或文件头部添加注释绕过扫描。
- **潜在危害**：真实业务文案被永久遗漏在国际化体系之外。
- **全自动防御机制**：
  在 `scripts/check-i18n-hardcoded.mjs` 中对抑制注释做强校验：
  1. 彻底禁用 `eslint-disable`、`i18n-ignore` 等通配注释；
  2. 仅允许单行 `/* i18n-allow: <正当理由> */`；
  3. 理由文本去除空白后长度必须 $\ge 3$ 个字符，否则视为作弊拦截；
  4. 审计阶段提取全仓所有抑制注释生成台账，非专有名词一律驳回。

### 4.3 模式 3：字符串拼接伪国际化（String Concatenation Anti-Pattern）

- **作弊手段**：
  ```tsx
  <span>{t('common.user') + '：' + userName}</span>
  <div aria-label={`用户卡片：${userName}`} />
  ```
- **潜在危害**：将句子切碎拼接，严重破坏英文、德文等语言的语序和动宾结构，导致屏幕阅读器（TTS）破音。
- **全自动防御机制**：
  在 `scripts/check-i18n-hardcoded.mjs` AST 遍历中注入二元相加与模板检测：
  - 当发现 `ts.isBinaryExpression` 操作符为 `+`，且左侧或右侧包含 `t()` 调用时，判定为拼接违规；
  - 强制要求改为参数化插值：`t('common.userColon', { user: userName })`。

### 4.4 模式 4：三元硬编码分支（Ternary Hardcoded Language Branching）

- **作弊手段**：
  ```tsx
  <span>{currentLang === 'zh-CN' ? '保存配置' : 'Save Settings'}</span>
  ```
- **潜在危害**：绕过统一字典真理源，代码四处散落多语言硬编码，未来扩展第三种语言（如日语、法语）时全部瘫痪。
- **全自动防御机制**：
  AST 遍历 `ts.isConditionalExpression`：
  - 若条件分支中直接出现中文字符串字面量，门禁判定为硬编码违规；
  - 无论是否有英文分支，中文一律必须抽取至 `locales/zh-CN/`。

### 4.5 模式 5：敷衍占位符（Dummy Placeholders & Stubs）

- **作弊手段**：批量向英文字典填入 `"TODO"`、`"TBD"`、`"..."`、`"test"`，或直接把键名赋给值：`settings.about: "settings.about"`。
- **潜在危害**：界面充斥半成品开发占位符，严重影响软件品质。
- **全自动防御机制**：
  在 `scripts/check-i18n-symmetry.mjs` 中内置垃圾词库与同名检查：
  ```javascript
  const JUNK_VALUES = new Set(['todo', 'tbd', 'temp', 'fixme', 'n/a', '...', 'test']);
  const lower = targetVal.trim().toLowerCase();
  if (JUNK_VALUES.has(lower) || targetVal.trim() === key) {
    console.error(`❌ [${localeId}] 敷衍占位文案违规: 键 "${key}" 被填充为无意义文本 "${targetVal}"！`);
    totalErrors++;
  }
  ```

---

### 4.6 模式 6：排版截断与溢出视盲（Layout Truncation & Defensive Overflow Blindness）

- **作弊手段**：只管把英文塞进组件，不管英文较中文膨胀 30%~70% 对固定宽高容器（如侧栏 220px、标签页 32px 高度）造成的挤压坍塌。
- **潜在危害**：文本重叠折行、按钮破损、关键信息被省略号截断且无 Tooltip 提示。
- **全自动防御机制**：
  1. **静态 CSS 规则断言**：在侧边栏、Tab 标签中强制注入防御性 CSS（`white-space: nowrap; text-overflow: ellipsis; overflow: hidden; min-width: 0;`）；
  2. **Playwright 多语言排版巡检**：启动 Headless 浏览器比对元素 `scrollWidth > clientWidth` 状态，若发生文字溢出截断，必须断言该元素被自定义 `<Tooltip>` 包裹！

## 五、流水线编排、Git 提交钩子与 CI 双轨集成

### 5.1 `.husky/pre-commit` 毫秒级挂载方案（< 180ms）

### 6.2 双盲交叉审计标准操作规程（SOP-1 至 SOP-5）

专职审计 Agent（B 组）在审查实现产出时，必须严格执行以下 5 项标准操作规程：

#### SOP-1：Git Diff 增量穿透审计（Code Diff Penetration）
- **操作方式**：执行 `git diff main...HEAD -- apps/`，逐行审查所有提交的文件差异；
- **审查重点**：
  1. 是否存在漏网的硬编码中文字符串；
  2. 是否存在将句子切碎的字符串拼接（`+` 或模板字符串混合）；
  3. 新增的词条是否合理归入对应的模块目录，命名空间是否清晰规范。

#### SOP-2：抑制注释合理性答辩与抽检（Suppression Scrutiny）
- **操作方式**：全局检索工作区新增的 `i18n-allow` 注释；
- **审查重点**：
  1. 理由是否充分真实（如必须是特定厂商名“文心一言”，而不是为了省事给常用 UI 文案加豁免）；
  2. 凡属于通用 UI 交互文案（如“确认”、“取消”、“加载中”）却加抑制注释的，**一律直接打回重做**。

#### SOP-3：原生英文语感与桌面术语审计（Idiomatic English Review）
- **操作方式**：通读审查 `locales/en-US/` 中新增的全部英文翻译；
- **审查重点**：
  1. 严禁中式机翻（如把“新建分支”直译为 `New Branching`，正确应为 `Create Branch` 或 `Branch Session`）；
  2. 桌面客户端专业术语对齐：
     - “设置”使用 `Preferences` 或 `Settings`；
     - “快捷键”使用 `Keyboard Shortcuts`；
     - “放弃更改”使用 `Discard Changes`；
     - “清除会话”使用 `Clear Chat History`。

#### SOP-4：真实 Tauri/WebView2 桌面宿主现场立体验证（Live App Verification）
- **操作方式**：根据 [`AGENTS.md`](file:///c:/Software/conex/AGENTS.md) §16，通过唯一的 4000 端口 Tauri MCP 通道进入正在运行的桌面应用；
- **审查重点**：
  1. 在“通用设置”中实时切换 `zh-CN` 与 `en-US`；
  2. 检查 15 个设置 Tab 与侧边栏的渲染反应：
     - 验证 DOM 文本即时更新，无需手动刷新应用；
     - 验证 `document.documentElement.lang` 正确变为 `en-US`；
     - 验证控制台零未捕获异常、零 Missing Key 警告；
  3. 巡检侧栏与长文本按钮，确认在英文膨胀下无截断错位、无文字重叠。

#### SOP-5：防回归契约单测完整性穿透审查（Test Assertion Verification）
- **操作方式**：审查新增和修改的单元测试文件源码；
- **审查重点**：
  1. 断言是否具有实质约束力（断言真实文案与状态转移，而非仅仅断言函数被调用）；
  2. 105 个错误码映射是否全部具备测试用例支撑；
  3. 变量插值参数错漏是否能被测试准确捕获。

### 6.4 审计裁决分级与一票否决权机制

审计 Agent 在出具审计报告时，严格按照以下 4 级缺陷分类裁决：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        审计缺陷分级与处置权矩阵                        │
├──────────┬─────────────────────────────┬───────────────────────────────┤
│ 缺陷级别 │ 判定标准                    │ 处置权                        │
├──────────┼─────────────────────────────┼───────────────────────────────┤
│ Blocker  │ 发现作弊欺瞒（如英文包抄中文│ 【一票否决】立即打回重做，    │
│ (阻断)   │ 伪造单测断言、绕过门禁）    │ 计入协作黑名单并在报告中留痕  │
├──────────┼─────────────────────────────┼───────────────────────────────┤
│ Critical │ 遗漏核心功能翻译、运行时    │ 【阻断交付】修复并通过复验后  │
│ (严重)   │ 报错白屏、严重排版挤压坍塌  │ 方可进入下一波次              │
├──────────┼─────────────────────────────┼───────────────────────────────┤
│ Major    │ 英文文案不符合桌面原生规范、│ 限期整改，收口前必须修复      │
│ (较重)   │ 翻译语序生硬、缺失 Tooltip  │                               │
├──────────┼─────────────────────────────┼───────────────────────────────┤
│ Minor    │ 代码格式细节、冗余空格等    │ 随手清理或记录为建议项        │
│ (轻微)   │                             │                               │
└──────────┴─────────────────────────────┴───────────────────────────────┘
```

**一票否决原则**：凡发现属于 **Blocker** 级别的作弊偷懒行为，审计 Agent 拥有一票否决权，无需征得实现者同意，直接判定任务失败并打回重做。
