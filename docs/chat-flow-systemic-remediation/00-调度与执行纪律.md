## 一、核心裁判原则与纯逻辑规划

1. **问题同权与纯逻辑依赖**：
   - 本方案及后续分项任务中，**所有列出的问题优先级完全相同**（禁止使用 P0/P1 业务优先级挑选、延后或砍项）；
   - 方案仅以**逻辑依赖与数据流拓扑**作为唯一执行先后约束（如：数据模型契约先于视图消费，单测桩基先于视图挂载）；
   - **绝对不涉及**工期、人天、人员排班或时间安排。

2. **坚决杜绝打补丁与应付心理（零容忍）**：
   - 严禁基于盲目猜测的字符串正则匹配、文本截断补丁（如使用 `replace` 剥离方括号、机器标头或硬编码服务端标识）；
   - 穿透表象找到架构断层，以 O(1) 结构化元数据作为单一真理源（SSOT）；
   - 严禁使用任何 `if (kind === 'file_context') return null;` 类粗暴隐藏手段，正常业务功能必须百分之百保留与优雅呈现。

3. **双向兼容剥离与正常功能保全**：
   - 剥离历史双向兼容层、废弃 Props 和冗余适配器时，必须通过完备的自动化单测和现场验证，确保合法功能（文件引用、Diff 预览、代码高亮、会话状态机、终端输出等）毫发无损。

4. **严格禁止硬编码（纯逻辑与 UI 同等执行）**：
   - **逻辑层**：模型、服务商、权限模式、思考档位必须通过结构化 `metadata` 传递与计算，杜绝魔术字符串；
   - **UI 与样式层**：坚决消灭 `#ffffff`, `#000000`, `rgba(...)`，统一使用系统 Design Tokens（如 `var(--bg-card)`, `var(--text-primary)`, `var(--border-subtle)` 等）；严格遵循 Conex §13 焦点态微环对比度 <= 10% 规范。

本战役所有文档存放在 `docs/chat-flow-systemic-remediation/` 目录下：

## 三、协作与验证铁律

1. **Git 提交权与现场保护**：
   - 提交权严格归主控 Agent，子 Agent 仅在工作区留存改动，严禁执行 `git commit`、`git push`；
   - **严禁任何回撤**：任何 Agent 严禁使用 `reset --hard` / `checkout .` / `restore`；
   - 改动自己文件使用精确编辑，主控提交时统一使用 `git commit --only <paths>`。
2. **立体化验收门禁**：
   - 静态类型：`npm run typecheck` 0 报错；
   - 编码与冲突：`npm run check:css-encoding` 与 `npm run check:conflict-markers` 100% 绿灯；
   - 治理门禁：`npm run check:line-counts` 无违规超标；
   - 单元测试：对话流相关全部 Vitest 套件 100% PASS。
