# 原地更新与载体消息边界缺陷审计报告

## 缺陷 01：【载体误杀与数据蒸发】`contextInjectionUtils.ts` 中 `isContextStateCarrierMessage` 使用 `.some()` 判定状态载体，混杂态下将包含常规文件/规则上下文的消息误杀蒸发
- **代码文件与精确行号**：
  - `apps/crish-desktop/src/components/chat-injection/contextInjectionUtils.ts:248-276`
  - `apps/crish-desktop/src/components/chat-card/useChatMessages.ts:63-67`
- **断层事实**：
  在 `contextInjectionUtils.ts:272-275` 中，判定消息是否为状态载体时错误使用了析取匹配 `.some()`：
  ```ts
  return (
    injections.some((inj) => isContextStateInjection(inj)) ||
    blocks.some((b) => isContextStateInjection(b.injection))
  );
  ```
  当一条空正文助手消息既包含用户的真实文件注入（如 `file_context`，内含数百行代码或 Diff），又包含一条 `context-state` 状态提示时，`injections.some(...)` 评估为 `true`，导致整条消息被定性为“纯状态载体消息”。在 `useChatMessages.ts:66` 调用的 `dedupeStateCarrierMessages` 中：
  ```ts
  if (isContextStateCarrierMessage(current)) {
    const next = messages[i + 1];
    if (next && isContextStateCarrierMessage(next)) {
      continue;
    }
  }
  ```
  若该消息之后紧跟另一条状态变更消息，`current` 直接被 `continue` 跳过丢弃。
- **危害后果**：
  用户的关键代码文件上下文、规则约束或 Git 状态卡片在界面渲染列表（`displayMessages`）中被无声删除。用户在界面上完全看不到之前注入的文件上下文，造成灾难性的视图层数据蒸发。

## 缺陷 02：【逻辑析取漏洞与物理级数据清除】`sessionInjectionMount.ts` 使用 `||` 判定纯载体，导致非状态块在 store 中被 `splice` 永久物理抹除
- **代码文件与精确行号**：
  - `apps/crish-desktop/src/store/sessionInjectionMount.ts:30-44`
  - `apps/crish-desktop/src/store/sessionCrudActions.ts:365-376`
- **断层事实**：
  在 `sessionInjectionMount.ts:44` 中：
  ```ts
  const allInjectionsState =
    hasInjections &&
    injections.every(
      (inj) =>
        inj.metadata?.mode === 'context-state' ||
        inj.title?.includes('状态切换')
    );
  const allBlocksState =
    blocks.length > 0 &&
    blocks.every(
      (b) =>
        b.injection?.metadata?.mode === 'context-state' ||
        b.injection?.title?.includes('状态切换')

  return allInjectionsState || allBlocksState;
  ```

  此处使用的是逻辑或 `||` 而非与 `&&`。如果某条消息的 `injections` 数组仅有 1 个状态注入项（`allInjectionsState === true`），但其 `blocks` 数组中挂载了未完成双轨同步的 `rule` 或 `file_context` 块（`allBlocksState === false`），该函数依然返回 `true`，将其断定为“仅承载过时 context-state 的纯载体消息”。随后在 `sessionCrudActions.ts:375` 中：
  ```ts
  if (pruneStart < targetIdx) {
    sess.messages.splice(pruneStart, targetIdx - pruneStart);
  }
  ```
- **危害后果**：
  包含真实有效业务注入块（blocks）的消息被直接判定为冗余纯载体，从 `sess.messages` 数组中物理 `splice` 剔除，导致未提交给后端持久化或仅在 blocks 维护的上下文块被不可逆地永久删除。

## 缺陷 03：【载体粗暴误伤与操作面板全面截瘫】`ChatAssistantMessageRow.tsx` 中 `isPureCarrier` 误将全部注入卡片视同微状态提示，导致操作按钮与 Pin 状态全面失效
- **代码文件与精确行号**：
  - `apps/crish-desktop/src/components/chat-message-row/ChatAssistantMessageRow.tsx:127-138, 164-171, 188-217`
- **断层事实**：
  在 `ChatAssistantMessageRow.tsx:127-138` 中，对 `isPureCarrier` 的推导存在严重的混淆概念：
  ```tsx
  const isPureCarrier =
    !msg.text?.trim() &&
    (!msg.toolCalls || msg.toolCalls.length === 0) &&
    !msg.thinking?.trim() &&
    Boolean(
      (msg.blocks &&
        msg.blocks.length > 0 &&
        msg.blocks.every((b) => b.type === 'context_injection')) ||
      (msg.injections &&
        msg.injections.length > 0 &&
        (!msg.blocks || msg.blocks.length === 0))
    );
  ```
  该逻辑判定的是“是否只包含注入块”，而**完全没有检查注入项是否为 context-state 微提示**。当一条消息仅承载系统 `rule` 规则卡片或富文本 `file_context` 注入时，`isPureCarrier` 同样被判定为 `true`。紧接着在组件渲染层：

  ```tsx
    aria-label={isPureCarrier ? '系统状态提示' : rowAria}
    data-pinned={!isPureCarrier && isPinned ? 'true' : undefined}

    ...
    {!isLive && !isPureCarrier && (
      <MessageActions ... />
    )}
  </div>
  ```
- **危害后果**：
  1. 正常的富文本文件注入卡片被套上了 `.rowCarrier`（行居中、无内边距、无边框），产生布局坍塌变形；
  2. 整行语义被篡改为 `role="status"` 与“系统状态提示”，屏幕阅读器用户完全无法得知这是一个文件上下文卡片；
  3. `!isPureCarrier && isPinned` 导致即使该注入消息被 Pin 住，置顶高亮样式也无法生效；
  4. 行底操作栏 `MessageActions` 被彻底剥离，用户无法对注入卡片进行重新生成、复制正文、Pin 或查看差异面板。

## 缺陷 16：【时间戳副作用引发侧栏时序漂移】`addContextInjection` 篡改 `sess.timestamp` 导致无发言会话异常冲顶
- **代码文件与精确行号**：
  - `apps/crish-desktop/src/store/sessionCrudActions.ts:381-392`
- **断层事实**：
  在 `sessionCrudActions.ts:381-392` 的 `addContextInjection` 实现中：
  ```ts
  if (
    typeof injection.timestamp === 'number' &&
    Number.isFinite(injection.timestamp)
  ) {
    sess.timestamp = new Date(injection.timestamp).toISOString();
  } else {
    sess.timestamp = nowIsoTimestamp();
  ```

- **危害后果**：
