## 缺陷 01：【虚假契约与死代码链路】`onRetryTool` 声明但在主业务装配链路中断绝，重试能力沦为单测专用假象

  - `apps/crish-desktop/src/components/chat-tool-call/ChatToolCallBlock.tsx:31, 55`
  - `apps/crish-desktop/src/components/chat-message-list/useChatMessageState.ts:287-295`
- **断层事实**：
  在 `ToolCallHeader.tsx:405-418` 中声明了错误工具重试按钮的渲染逻辑：
  ```tsx
  {tc.status === 'error' && onRetryTool ? (
    <Button
      type="button"
      variant="ghost"
      size="sm"
      className={styles.retryBtn}
  ```

  ```tsx

    (): ChatToolStackSharedProps => ({

      activeSessionId,
  ```

  全局代码中仅在 `ChatToolCallBlock.test.tsx` 单元测试中为其传入 mock 函数。

## 缺陷 03：【高频独立轮询与性能隐患】每个运行态工具独立挂载 100ms `setInterval` 引发渲染风暴
- **代码文件与精确行号**：
  - `apps/crish-desktop/src/components/chat-tool-call/CompactToolRow.tsx:67-72, 79-82`
- **断层事实**：
  在 `CompactToolRow.tsx:67-72` 中：
  ```tsx
  const [liveNow, setLiveNow] = useState(Date.now());
  useEffect(() => {
    if (tc.status !== 'running' || !tc.startedAt) return;
    const id = setInterval(() => setLiveNow(Date.now()), 100);
    return () => clearInterval(id);
  }, [tc.status, tc.startedAt]);
  ```
  每个处于 `running` 状态的工具调用行，各自启动一个独立的 100ms 间隔定时器，高频调用 `setLiveNow(Date.now())` 强制触发当前组件重渲染。
- **危害后果**：
  在多 Agent 协同或并发执行多个工具（如批量代码检索、文件读取、后台任务）时，若有多个工具同时处于运行态，每个组件都会独立高频触发 React 重新渲染，每秒造成几十次乃至上百次重排与组件树 Diff。在消息列表包含复杂 DOM 的情况下，会直接造成主线程 CPU 飙升、动画严重掉帧（Jank）、输入卡顿与设备发热，且违背定时器与事件驱动的设计纪律。

## 缺陷 06：【动态行高测量污染与视口跳变死循环】`VirtualPlainCodeViewer` 误将视口首行折行高度采为全局基准行高
- **代码文件与精确行号**：
  - `apps/crish-desktop/src/components/diff/VirtualPlainCodeViewer.tsx:84-91, 172-176`
- **断层事实**：
  在 `VirtualPlainCodeViewer.tsx:172-176` 中：
  ```tsx
  {visibleLines.map((l, idx) => (
    <div
      key={l.num}
      ref={idx === 0 ? firstLineRef : undefined}
      className={styles.line}
  ```
  `firstLineRef` 被挂载在当前视口切片渲染的第一个元素（`idx === 0`）上。
  随后在 `useLayoutEffect` 中：
  ```tsx
  useLayoutEffect(() => {
    const lineEl = firstLineRef.current;
    if (lineEl) {
      const measured = lineEl.offsetHeight;
      if (measured > 0 && measured !== rowHeight) {
        setRowHeight(measured);
      }
    }
  ```
- **危害后果**：
  `visibleLines` 是随滚动动态变化的切片数组，`idx === 0` 仅代表当前滚动可视窗口的第一行。当用户滚动到某一长文本折行（例如因自动换行高度达到 66px 或 88px）切入视口顶部时，`measured` 会误将该多行折行的高度当作单行基准高度，调用 `setRowHeight(88)` 改写全局标量；而全局总高度 `totalHeight = totalVisualLines * rowHeight` 随之暴增，排版引擎计算的视口切片剧烈移位，引发严重滚动跳跃（Scroll Jitter）以及由于高度反跳导致的布局振荡死循环（Layout Oscillation）。

## 缺陷 09：【未捕获 Promise 与虚假成功反馈】剪贴板异步写入未 await 与无异常捕获
- **代码文件与精确行号**：
  - `apps/crish-desktop/src/components/chat-tool-call/ToolCallDiffPreview.tsx:45-47`
  - `apps/crish-desktop/src/components/chat-tool-call/ModernTerminalToolCall.tsx:44-46, 52-54`
  - `apps/crish-desktop/src/components/chat-tool-call/ModernCodeBlock.tsx:25-27`
- **断层事实**：
  在 `ToolCallDiffPreview.tsx:45-47` 中：

  在 `ModernTerminalToolCall.tsx` 与 `ModernCodeBlock.tsx` 中亦采用相同写法。
- **危害后果**：

  此处直接使用 `void` 丢弃 Promise 且未包裹 try-catch，导致抛出未捕获的 Unhandled Promise Rejection 异常；更严重的是，即使剪贴板写入彻底失败，界面依然执行 `setCopied(true)` 显示“已复制”，向用户传递虚假的成功反馈。
