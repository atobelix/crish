## 一、状态格式化与多语言断层（ContextState Formatting & i18n Defects）

### 【缺陷编号 DEFECT-CS-01】硬编码中文与多语言 (i18n) 契约断裂，无国际化与语言协商机制
- **代码文件与精确行号**：
  `apps/crish-desktop/src/components/chat-injection/contextInjectionUtils.ts:207-238`
- **断层事实**：
  ```ts
  if (metadata) {
    const parts: string[] = [];
    if (metadata.model) {
      let modelPart = metadata.model;
      if (metadata.permission) {
        modelPart = `${modelPart} (${metadata.permission})`;
      } else if (metadata.profile) {
        modelPart = `${modelPart} (${metadata.profile})`;
      }
      parts.push(`切换到 ${modelPart}`);
    } else if (metadata.permission) {
      parts.push(`权限: ${metadata.permission}`);
    }
    if (
      metadata.thinking &&
      metadata.thinking !== 'off' &&
      metadata.thinking !== 'default'
    ) {
      parts.push(`思考 ${metadata.thinking}`);
    }
    if (parts.length > 0) {
      return `系统 · ${parts.join(' · ')}`;
    }
  }

  // 纯文本兜底（首行提取，安全防御）
  const trimmed = fallback.trim();
  if (!trimmed) return '系统 · 状态切换';
  const firstLine =
    trimmed.split('\n').find((l) => l.trim().length > 0)?.trim() ||

  return firstLine.startsWith('系统 · ') ? firstLine : `系统 · ${firstLine}`;
  ```
- **危害后果 / 真实运行期隐患**：
  1. `系统 · `、`切换到 `、`权限: `、`思考 `、`系统 · 状态切换` 等展示文案全部以中文字符串硬编码写死在底层工具函数中，完全脱离前端 i18n 资源包与国际化翻译管道（如 `t(...)`）；
  2. 国际化用户在英文或其它语言配置下，对话流中始终突兀出现硬编码中文微提示，造成多语言体验彻底割裂；
  3. 符号规范混乱：`权限: ` 采用半角英文冒号与半角空格，而前缀采用全角间隔符 `系统 · `，中西文混排缺乏标准化对齐。

### 【缺陷编号 DEFECT-CS-02】`metadata.permission` 与 `metadata.profile` 互斥分支导致 Profile 元数据被强制剥离与吞没
- **代码文件与精确行号**：
  `apps/crish-desktop/src/components/chat-injection/contextInjectionUtils.ts:208-218`
- **断层事实**：
  ```ts
  if (metadata.model) {
    let modelPart = metadata.model;
    if (metadata.permission) {
      modelPart = `${modelPart} (${metadata.permission})`;
    } else if (metadata.profile) {
      modelPart = `${modelPart} (${metadata.profile})`;
    }
    parts.push(`切换到 ${modelPart}`);
  } else if (metadata.permission) {
    parts.push(`权限: ${metadata.permission}`);
  }
  ```
- **危害后果 / 真实运行期隐患**：
  1. `if (metadata.permission)` 与 `else if (metadata.profile)` 构成了互斥分支。当用户在指定服务商 Profile（例如 `DeepSeek-Official`）下使用某权限模式（如 `ask`）切换模型时，`metadata.permission` 恒为真，`else if (metadata.profile)` 分支被无条件跳过；
  2. 结果导致服务商 `profile` 信息被静默抹除，界面仅渲染 `系统 · 切换到 deepseek-reasoner (ask)`，用户无法获知实际生效的服务商通道；
  3. 当用户仅切换 Profile（例如从代理切换到官方源）而保持模型 ID 不变时，因 `metadata.model` 缺失且没有 `else if (metadata.profile)` 处理分支，`parts` 计算结果为空数组，逻辑直接回退到不可预测的纯文本兜底。

## 二、纯状态载体与核心 UI 吞没断层（PureCarrier & Critical UI Swallowing Defects）

### 【缺陷编号 DEFECT-PC-01】`isContextStateCarrierMessage` 对多维核心消息字段全盲，引发正常回答被降级吞没
- **代码文件与精确行号**：
  `apps/crish-desktop/src/components/chat-injection/contextInjectionUtils.ts:244-273` 与 `apps/crish-desktop/src/store/sessionInjectionMount.ts:30-50`
- **断层事实**：
  ```ts
  export function isContextStateCarrierMessage(
    msg:
      | {
          sender?: string;
          text?: string;
          toolCalls?: unknown[];
          thinking?: string;
          blocks?: Array<{ type: string; injection?: Partial<MessageContextInjection> }>;
          injections?: Array<Partial<MessageContextInjection>>;
        }
      | undefined
  ): boolean {
    if (!msg || msg.sender !== 'assistant') return false;
    if ((msg.text || '').trim()) return false;
    if (msg.toolCalls && msg.toolCalls.length > 0) return false;
    if ((msg.thinking || '').trim()) return false;
    const blocks = msg.blocks || [];
    const injections = msg.injections || [];
    const hasBlocks = blocks.length > 0;
    const hasInjections = injections.length > 0;
    if (!hasBlocks && !hasInjections) return false;
    if (hasBlocks && !blocks.every((b) => b.type === 'context_injection')) {
      return false;
    }
    const allBlocksState =
      !hasBlocks || blocks.every((b) => isContextStateInjection(b.injection));
    const allInjectionsState =
      !hasInjections || injections.every((inj) => isContextStateInjection(inj));
    return allBlocksState && allInjectionsState;
  }
  ```
- **危害后果 / 真实运行期隐患**：
  1. `SessionMessage` 实体（`types.ts:509-570`）承载有 `thinkingTurns`（多轮结构化深度推理）、`images`（多模态生成图片引用）、`attachments`（消息附件）及 `errorDetail`（报错诊断详情）；
  2. `isContextStateCarrierMessage` 仅检查了 `text`、`toolCalls`、`thinking`，对 `thinkingTurns`、`images`、`attachments`、`errorDetail` **全盲无感**；
  3. 当深度推理模型（如 o1 / DeepSeek-R1）仅通过 `thinkingTurns` 吐出多轮思考内容而尚未产出正文 `text` 时，或者当模型仅产出图表/多模态图片（`msg.images` 有效但 `msg.text` 为空）时，该消息被误判为纯状态载体（`isPureCarrier=true`）；
  4. 误判后触发 `ChatAssistantMessageRow.tsx:183`，彻底屏蔽 `MessageActions`，外层剥除助手消息外壳（`.rowCarrier` 与 `role="status"`），思考链与多模态图片被塞入高度为 20px 的发丝微容器中，产生毁灭性的 UI 塌陷与关键交互丧失。

- **代码文件与精确行号**：

### 【缺陷编号 DEFECT-A11Y-01】双层嵌套 `role="status"` 触发屏幕阅读器递归重入冲突与双重回声
