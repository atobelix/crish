## 缺陷 01：【测高盲区与内存泄漏】顶级 ResizeObserver 挂载依赖项严重缺失导致滚入新节点脱离观察与游离 DOM 驻留
- **代码文件与精确行号**：
  - `apps/crish-desktop/src/components/chat-message-list/MessageVirtualizer.tsx:147-190`
- **断层事实**：
  在 `MessageVirtualizer.tsx:147-190` 中，顶级 `ResizeObserver` 负责监听所有当前渲染消息行的真实尺寸：
  ```tsx
  const roRef = useRef<ResizeObserver | null>(null);
  const observedRowsRef = useRef<Set<Element>>(new Set());
  useEffect(() => {
    const container = containerRef.current;
    if (!container) return;
    if (!roRef.current) {
      roRef.current = new ResizeObserver((entries) => {
        for (const entry of entries) {
          const el = entry.target;
          if (!(el instanceof HTMLElement)) continue;
          const msgId = el.dataset.vindex;
          if (msgId != null && entry.contentRect.height > 0) {
            setActual(msgId, entry.contentRect.height);
          }
        }
        // ...
      });
    }
    const ro = roRef.current;
    const observed = observedRowsRef.current;
    const current = new Set<Element>(
      Array.from(container.querySelectorAll('[data-vindex]'))
    );
    for (const row of current) {
      if (!observed.has(row)) {
        ro.observe(row);
        observed.add(row);
      }
    }
    for (const row of observed) {
      if (!current.has(row)) {
        ro.unobserve(row);
        observed.delete(row);
      }
    }
  }, [msgIds, containerRef, setActual]);
  ```
  该 `useEffect` 的依赖数组为 `[msgIds, containerRef, setActual]`。在会话交互生命周期中，`msgIds` 为当前会话所有消息 ID 的数组映射（`messages.map((m) => m.id)`）。当用户在会话内向上或向下滚动翻看历史记录时，`msgIds` 引用与内容完全未变，只有切片窗口 `startIndex` 与 `endIndex` 发生推移。这导致组件重新渲染后，该 `useEffect` **根本不会重新触发**。
- **危害后果**：
  1. 伴随视口滚动新挂载到 DOM 树中的 `[data-vindex]` 节点，完全脱离了顶级 `ResizeObserver` 的观察视野。新进入视口的消息行在渲染完成后，其实际尺寸永远无法回写进 `VirtualScrollManager`，其高度终生停留在 120px 粗估回退值；
  2. 已从 DOM 树中卸载离开视口的老节点，无法执行 `ro.unobserve(row)`，其 DOM 引用被 `observedRowsRef.current` 强引用驻留，导致游离脱落 DOM 子树（Detached DOM Tree）严重的内存泄漏；
  3. 历史消息行若包含动态加载的图片或延迟高亮代码块，尺寸变更彻底处于静默状态，引发列表总高计算严重偏离物理真实。

## 缺陷 03：【架构绕道与状态脱节】行级局部 RO 绕过 `useVirtualScroll` 调度器直接突变底层 VSM 树状数组

- **断层事实**：
  在 `useVirtualScroll.ts:150-172` 中，虚拟滚动引擎提供了具备防抖、同值跳过与 `actualTick` 响应式通知的受控入口 `setActual`：
  ```tsx
  const setActual = useCallback(
    (id: string, height: number) => {
      const cur = manager.getActualHeight(id);
      if (cur !== null && cur === height) return;
      pendingActualRef.current.set(id, height);
      if (actualRafRef.current == null) {
        actualRafRef.current = requestAnimationFrame(() => {
          actualRafRef.current = null;
          let changed = false;
          for (const [msgId, h] of pendingActualRef.current) {
            changed = manager.setActual(msgId, h) || changed;
          }

  );
  ```

## 缺陷 04：【测量半闭环与虚假失效】工具段 RO 仅执行 `invalidateActual` 且未回写测高，Fenwick 树永久滞后
- **代码文件与精确行号**：
  - `apps/crish-desktop/src/components/chat-message-row/MessageToolCallsSection.tsx:117-129`
  - `apps/crish-desktop/src/api/VirtualScrollManager.ts:258-267`
- **断层事实**：
  在 `MessageToolCallsSection.tsx:117-129` 中，工具区声明了独立的 `ResizeObserver`：
  ```tsx
  useLayoutEffect(() => {
    const el = sectionRef.current;
    if (!el) return;
    const ro = new ResizeObserver((entries) => {
      for (const entry of entries) {
        if (entry.contentRect.height > 0) {
          virtualScrollManager?.invalidateActual(msgId);
        }
      }
    });
    ro.observe(el);
    return () => ro.disconnect();
  }, [msgId, virtualScrollManager]);
  ```
  而在 `VirtualScrollManager.ts:258-267` 中，`invalidateActual` 的实现为：
  ```ts
  invalidateActual(id: string): void {
    const entry = this.heightsById.get(id);
    if (entry) {
      const lastKnownHeight = entry.actual ?? entry.estimated;
      entry.actual = null;
      entry.estimated =
        lastKnownHeight > 0 ? lastKnownHeight : this.fallbackHeight;
      // 保持当前高度与 BIT 树不变，平滑过渡防止视口抖动
    }
  }
  ```
  `invalidateActual` 的设计契约仅是将 `actual` 字段标记为 `null`，并**显式保持当前高度与 BIT 树（Fenwick Tree）不变**。
  在 `MessageToolCallsSection` 中，当工具调用展开产生高度剧增时，RO 触发后仅调用了 `invalidateActual(msgId)`，它**既未调用任何 `setActual`**（因为其持有的仅是工具局部 `sectionRef`，无法得知整行完整高度），也**未通知任何外层组件**。
- **危害后果**：
  若父级 `ChatAssistantMessageRow` 或顶层 `MessageVirtualizer` 的 RO 因同帧合并或已被阻断未能触发，VSM 内部的树状数组前缀和将永远维持在工具展开前的旧高度数值；`invalidateActual` 变成只擦除实测标记却不更新几何尺寸的“半闭环死锁”。列表总高度不会增加，展开的工具内容直接超出虚拟列表分配的高度槽，与下方行重叠或被底部分割线暴力切除。

  React 官方严格规范要求：组件的 Render 函数必须是纯函数（Pure Function），严禁在渲染体内部直接修改外部对象、单例状态或执行非受控的内存突变。
- **危害后果**：
  在 React 18/19 的并发模式（Concurrent Mode）或快速重渲染调度中，React 可能会多次调用 Render 函数、打断低优先级渲染甚至丢弃本次渲染产物。在 Render 阶段直接重写全局单例 VSM 的树状数组与下标映射，会导致并发分支正在消费的旧树状数组瞬间被破坏覆盖，引发不可预测的下标越界、高度错位或 `undefined` 取值崩溃。
