## 一、文本防抖持久化与生命周期截断缺陷（快速输入、窗口关闭、文档切换丢失）

### 【DEF-NOTE-PERSIST-01】`useNoteTextPersistence.ts` 缺乏并发锁与请求排队，重入执行引发差量基准错位与文本重复插入损坏
- **【代码文件与精确行号】**：`apps/crish-desktop/src/components/note-paper/useNoteTextPersistence.ts:114-152, 221-230`
- **【断层事实】**
  ```typescript
  // useNoteTextPersistence.ts:114-150
  const flushBlockText = useCallback(
    async (blockId: string): Promise<void> => {
      const pending = pendingFlushRef.current.get(blockId);
      if (!pending) return;
      const target = pending.text;
      const seed = blocksRef.current.find((b) => b.id === blockId)?.text ?? '';
      const oldText = lastPersistedTextRef.current.get(blockId) ?? seed;
      const op = computeTextEditOp(blockId, oldText, target);
      if (!op) {
        pendingFlushRef.current.delete(blockId);
        return;
      }
      // ...
      setLocalSaveStatus('saving');
      const intentId = `text-edit-${Date.now()}-${Math.random().toString(36).slice(2, 8)}`;
      const ok = await sendApplyOps(JSON.stringify([op]), intentId);
      if (ok) {
        lastPersistedTextRef.current.set(blockId, target);
        const cur = pendingFlushRef.current.get(blockId);
        if (cur && cur.text === target) {
          pendingFlushRef.current.delete(blockId);
        }
        setLocalSaveStatus('saved');
      } else {
        setLocalSaveStatus('unsaved');
      }
    },
    [sendApplyOps]
  );
  ```
  `flushBlockText` 为裸 `async` 异步函数，内部既无 `inFlight` 互斥保护，也无操作队列（Queue）。`lastPersistedTextRef` 仅在 `sendApplyOps` 异步 Promise 真正 resolve 且 `ok=true` 后才会落盘更新。
  而在输入场景中，用户连续击键触发防抖、按下回车（`handleTextCommit` 立即触发 `flushBlockText`）或发生失焦时，如果前序 `sendApplyOps` 仍在 IPC/SQLite 通道中排队，后续的 `flushBlockText` 会立即并发执行。此时后续执行读取到的 `lastPersistedTextRef.current.get(blockId)` 依然是上一次尚未完成保存的陈旧基准！
  例如初始为空串 `""`：
  1. 第一次保存输入 `"A"`，生成 op `{ start: 0, end: 0, insert: "A" }` 并进入 IPC 等待；
  2. 用户紧接着输入 `"B"` 并按回车，第二次 `flushBlockText` 立即触发，此时 `lastPersistedTextRef` 仍为 `""`，计算 `"" -> "AB"` 产生 op `{ start: 0, end: 0, insert: "AB" }`；
  3. 后端引擎按到达顺序先后应用两笔 op：先在 0 偏移插入 `"A"`，紧接着又在 0 偏移插入 `"AB"`，最终文本演变为 `"ABA"`！
- **【危害后果 / 真实运行期隐患】**
  彻底破坏协同差量算法的数学不变量，导致频繁打字或按回车确认时字符被重复拼接、光标乱跳与文本不可逆损坏。

### 【DEF-NOTE-COLLAB-01】`note_documents.rs` 与 `persist_plugin.rs` 初始版本号断层导致新建文档首笔写入 100% 触发 CAS 冲突拒绝


  任何通过正常 UI 流程（侧栏“+”按钮、顶栏下拉菜单“新建”）创建的新便签文档，在用户打入任何文字的瞬间，都会无一例外地触发底层 CAS 乐观锁版本冲突，导致首笔写盘彻底失败，新建笔记完全无法保存！

### 【DEF-NOTE-COLLAB-04】`useNoteTextPersistence.ts` 在远程写入时强行覆盖本地基准导致差量范围穿孔
- **【代码文件与精确行号】**：`apps/crish-desktop/src/components/note-paper/useNoteTextPersistence.ts:199-211`
