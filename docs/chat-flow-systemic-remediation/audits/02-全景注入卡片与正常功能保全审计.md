### 【缺陷分类与编号】交互回调断裂 · DEFECT-INJ-01
- **代码文件与精确行号**：`apps/crish-desktop/src/components/chat-message/MessageContent.tsx:163-178` & `apps/crish-desktop/src/components/chat-injection/contextInjectionTypes.ts:16-19`
- **断层事实（附带真实代码片段）**：
  在 `contextInjectionTypes.ts` 中明确定义了受控折叠状态映射表契约：
  ```typescript
  export interface ContextInjectionSharedProps {
    activeSessionId: string;
    msgId: string;
    expandedInjections?: Record<string, boolean>;
    onToggleInjection?: (injectionId: string, nextOpen: boolean) => void;
    onOpenPath?: (filePath: string) => void;
    onOpenDiff?: (diff: FileDiff) => void;
  }
  ```
  而在主时间线唯一渲染单项注入卡片的组合根 `MessageContent.tsx` 中：
  ```typescript
  if (item.kind === 'injection') {
    return (
      <CompactInjectionRow
        key={item.key}
        rowKey={item.key}
        injection={item.injection}
        activeSessionId={toolStackProps?.activeSessionId ?? ''}
        msgId={msgId}
        {...(toolStackProps?.actions?.onOpenDiff
          ? { onOpenDiff: toolStackProps.actions.onOpenDiff }
          : {})}
        {...(toolStackProps?.actions?.onOpenPath
          ? { onOpenPath: toolStackProps.actions.onOpenPath }
          : {})}
        {...(toolStackProps?.onToggleInjection
          ? { onToggleInjection: toolStackProps.onToggleInjection }
          : {})}
      />
    );
  }
  ```
  `expandedInjections` 属性被彻底遗漏，从未向 `CompactInjectionRow` 透传。
- **危害后果 / 真实运行期隐患**：
  `CompactInjectionRow.tsx:85` 中 `const controlled = expandedInjections?.[injection.id]` 恒定为 `undefined`，外部受控折叠机制完全瘫痪。用户在卡片上手动展开/收起的操作仅保存在组件本地 state（`localOpen`）。当对话流产生新消息、流式正文更新、或虚拟滚动列表（`MessageVirtualizer`）回收并重新挂载该行 DOM 时，本地 state 被强制重置为 `defaultOpen`，用户阅读中的卡片发生异常收起或展开，引发视口高度剧烈跳动（CLS 震荡）。

### 【缺陷分类与编号】交互回调断裂 · DEFECT-INJ-02
- **代码文件与精确行号**：`apps/crish-desktop/src/components/chat-injection/CompactInjectionRow.tsx:88-92` vs `apps/crish-desktop/src/components/chat-message-row/ChatAssistantMessageRow.tsx:124-127` & `apps/crish-desktop/src/components/chat-tool-call/ChatToolCallBlock.tsx:51`
- **断层事实（附带真实代码片段）**：
  `CompactInjectionRow.tsx` 触发折叠时传递的是计算后的**下一状态（`nextOpen`）**：
  ```typescript
  const handleToggle = useCallback(() => {
    const next = !isOpen;
    if (controlled === undefined) setLocalOpen(next);
    onToggleInjection?.(injection.id, next);
  }, [isOpen, controlled, injection.id, onToggleInjection]);
  ```
  然而在跨层桥接组件 `ChatAssistantMessageRow.tsx:124` 与 `ChatToolCallBlock.tsx:51` 中，该回调参数名为 `currentlyOpen`，遵循的是 `onToggleTool(toolId, currentlyOpen)` 的参数语义：
  ```typescript
  onToggleInjection: (injectionId: string, currentlyOpen: boolean) => {
    toolStackProps.onToggleInjection?.(injectionId, currentlyOpen);
    virtualScrollManager?.invalidateActual(msg.id);
  }
  ```
  外部状态处理器（如 `useChatMessageState.ts:173` 的 `toggleTool` 模式）如果按照 `currentlyOpen` 实现状态取反（`[id]: !currentlyOpen`），将对已经取反的 `next` 再次取反。
- **危害后果 / 真实运行期隐患**：
  形成参数语义“二义性倒置”。若外层消费方按变量名 `currentlyOpen` 实行 `!currentlyOpen` 逻辑，则每次点击折叠时，状态计算为 `!(!isOpen) === isOpen`，导致受控状态永远处于当前状态，卡片被彻底锁死无法切换展开；反之若不取反，则破坏与 `ChatToolStack` 统一的交互契约。
