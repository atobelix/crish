# 对话流注入卡片彻底物理废除与防回潮铁律（专项记录）

> **生效日期**：2026-09-07（用户裁决）
> **权威位置**：`docs/chat-flow-systemic-remediation/00-专项记录-对话流注入卡片彻底物理废除与防回潮铁律.md` 与根目录 `AGENTS.md` §21
> **铁律性质**：**永久生效，绝对禁止再次恢复、封装或变相回潮**

---

## 一、背景与问题根因

在过去的实现轮次中（特别是历史提交 `76c2500f` BATCH-07），由于过度设计与历史兼容包袱，误将本已废弃的巨型注入卡片（`file_context`、彩虹色边框卡片、带有厚重抽屉和反常展开逻辑的折叠框）重新引入对话流时间线，严重破坏了对话界面的干净、专业与沉浸体验。

对此，用户于 2026-09-07 明确下达裁决：
1. **第一类（文件上下文 `file_context`）与第二类（斜杠命令注入卡片 `skill`/`goal`/`schedule`）必须彻底物理删除，不留一点痕迹**；
2. **第三类定时任务配置确认卡片（`WorkflowConfirmCard`）具备真实业务交互价值（修改配置/确认激活），改版解耦后保留独立业务能力**；
3. **第四类系统状态切换微提示（`ContextStateNotice`）仅保留 20px 居中极简发丝分割线，去除一切外框、抽屉、冗余按钮**；
4. **全系统界面杜绝任何 Emoji 表情，图标资产绝对禁止误删**；
5. **本次物理删除改动必须立项专项记录，并铁律标明禁止再恢复**。

## 三、生成源与消费链路收口规范（单一真理源）

1. **生成源彻底封死（No-op 拦截）**：
   - `apps/crish-desktop/src/hooks/chat-stream/slashContextCards.ts`：所有 `dispatchSkillContextCard`、`dispatchGoalModeCard`、`dispatchGrillMeCard`、`dispatchAttachmentCards` 均已置空（no-op），不再往 SessionStore / Message 历史树注入任何卡片结构。
   - `apps/crish-desktop/src/api/workflow-api/workflowAssistantCard.ts`：`dispatchWorkflowAssistantCard` 返回 `null`，引导指令统一走输入框 safe_seed，禁止写入时间线。
2. **时间线渲染链路拦截**：
   - `apps/crish-desktop/src/components/chat-message/MessageContent.tsx`：
     - `ProcessItemRenderer` 仅对 `isContextStateInjection(item.injection)` 放行极简 `ContextStateNotice`；
     - 任何其他 `item.kind === 'injection'` 均一律 `return null`，绝不挂载任何外框；
     - `stateItems` 与 `turnProcessItems` 数据过滤中已严格排除所有非状态类 injection。
