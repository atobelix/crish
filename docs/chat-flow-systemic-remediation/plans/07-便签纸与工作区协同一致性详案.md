## 一、架构背景与同权缺陷映射矩阵

在 Conex 便签纸（Note Paper）与工作区协同体系中，前端基于 React + Virtual DOM + contenteditable 混合视口（`PaperList` / `StrictContentRowLeaf`），底层依托 Rust 引擎（`conex-workspace-store`、`conex-doc-collab`、`conex-note-runtime`）与 SQLite WAL 事务持久化。
依据 `audits/18` 深度审计，系统在文本持久化防抖、文档生命周期切换、版本号 CAS 校验、内存会话缓存、事件总线以及交互实现层存在严重的架构断裂与数据覆灭风险。

根据反退避与纯逻辑规划原则，**19 项缺陷地位完全同权，严禁以“概率低”、“实现复杂”或“已有超时防护”为由降级或绕过**：

| 缺陷编号 | 缺陷分类 | 断层核心事实与真实危害 | 架构修复决策与根除方案 | 涉及的核心代码域 |

### 2.1 新建文档与内存会话初始版本号（rev = 0）零断层契约

#### 核心不变量
1. **空文档基准版本为 0**：任何新建但未提交任何块操作的文档，数据库 `doc_meta.rev` 与内存 `DocSession.rev` **恒为 0**。
2. **首笔写盘 CAS 无缝晋升**：客户端打开新建文档并键入首个字符时，前端或内存会话携带 `expect_rev = Some(0)` 发起 `note_apply_ops`，数据库通过 `WHERE doc_meta.rev = 0` 进行乐观锁判定，执行 `rev = rev + 1` 将其原子晋升为 `1`。

#### Rust 存储层改造契约 (`crates/conex-workspace-store/src/note_documents.rs`)
```rust
// note_documents.rs
pub fn create_note_document(
    &self,
    doc_id: &str,
    title: &str,
    now_ms: i64,
) -> Result<DocMetaRow, StoreError> {
    let conn = self.conn.lock().map_err(|e| StoreError::Lock(e.to_string()))?;

    let effective_now = normalize_timestamp_ms(now_ms, current_time_ms());
    let trimmed_title = title.trim();
    let final_title = if trimmed_title.is_empty() {
        "未命名笔记"
    } else {
        trimmed_title
    };

    // 彻底修复 DEF-NOTE-COLLAB-01：初始 rev 强制为 0
    conn.execute(
        r#"
        INSERT INTO doc_meta (doc_id, rev, updated_at, title, created_at)
        VALUES (?1, 0, ?2, ?3, ?2);
        "#,
        params![doc_id, effective_now, final_title],
    )?;

    Ok(DocMetaRow {
        doc_id: doc_id.to_string(),
        rev: 0,
        updated_at: effective_now,
        title: final_title.to_string(),
        created_at: effective_now,
        block_count: 0,
    })
}
```

### 2.2 存储层与内存会话生命周期严格级联驱逐（Anti-Zombie Session）

#### 核心不变量
物理删除文档时，必须**同时在内存运行时与底层 SQLite 中实施原子双清**。任何已删除文档的内存句柄必须立即作废，防止后续延迟任务使已删数据死而复生。

#### 后端运行时驱逐门面 (`crates/conex-note-runtime/src/store_backend.rs`)
在 `StoreNoteBackend` 中实现统一的文档物理删除生命周期管理：
```rust
// store_backend.rs
impl StoreNoteBackend {
    /// 彻底物理删除文档并级联驱逐内存会话（解决 DEF-NOTE-COLLAB-02）
    pub fn delete_document(&self, doc_id: &str) -> Result<bool, StoreError> {
        // 1. 驱逐内存打开的会话索引
        {
            let mut sessions = self.sessions.lock().unwrap_or_else(|e| e.into_inner());
            sessions.remove(doc_id);
        }

        // 2. 清理并发水合互斥许可锁
        {
            let mut hydrating = self.hydrating.lock().unwrap_or_else(|e| e.into_inner());
            hydrating.remove(doc_id);
        }

        // 3. 清理已缓存的 intent 结果
        {
            let mut intents = self.intents.lock().unwrap_or_else(|e| e.into_inner());
            intents.retain(|k, _| !k.contains(doc_id));
        }

        // 4. 执行底层 SQLite 9 张表的级联硬删除事务
        self.store.delete_document(doc_id)
    }
}
```

#### Tauri IPC 指令接线 (`apps/agent-workbench/src-tauri/src/note_commands_document.rs`)

### 2.3 差量计算与并发写入因果链保护（Delta Causality & Rebase Contract）

#### 核心不变量
1. **基准文本单调推进**：`computeTextEditOp(blockId, oldText, target)` 中的 `oldText` 必须严格等于后端已确认落盘的文本。
2. **远程写入因果变基**：当远端协同写入到达时，若本地存在待提交草稿，必须根据三方变基算法（Base / Remote / Local）调整待落盘区间，杜绝以旧换新引发差量错位穿孔。

#### 差量计算变基协议定义
```typescript
export interface TextEditRebaseResult {
  /** 变基后本地需提交的新 target */
  rebasedTarget: string;
  /** 变基后的新基准 */
  newBaseText: string;
}

/**
 * 远端更新到达时对本地草稿实施因果变基
 */
export function rebaseLocalDraft(
  baseText: string,
  remoteText: string,
  localDraft: string
): TextEditRebaseResult {
  if (baseText === remoteText) {
    return { rebasedTarget: localDraft, newBaseText: remoteText };
  }
  if (baseText === localDraft) {
    return { rebasedTarget: remoteText, newBaseText: remoteText };
  }
```

```typescript
const executeBlockFlushQueue = async (blockId: string): Promise<void> => {
  if (inFlightBlocksRef.current.has(blockId)) {
    // 已有写入在执行中，后序调用静默等待出队，严禁并发重入
    return;
  }

  const queue = blockFlushQueueRef.current.get(blockId);
  if (!queue || queue.length === 0) return;

  // 标记当前块处于 inFlight
  inFlightBlocksRef.current.add(blockId);

  try {
    while (queue.length > 0) {
      // 批处理合并：取队列中最新的一个目标状态，中间瞬态自然坍缩
      const currentTask = queue[queue.length - 1];
      queue.length = 0; // 清空前序堆积

      const target = currentTask.targetText;
      const seed = blocksRef.current.find((b) => b.id === blockId)?.text ?? '';
      const oldText = lastPersistedTextRef.current.get(blockId) ?? seed;

      const op = computeTextEditOp(blockId, oldText, target);
      if (!op) {
        lastPersistedTextRef.current.set(blockId, target);
        currentTask.resolve();
        continue;
      }

      setLocalSaveStatus('saving');
      const intentId = `text-edit-${Date.now()}-${Math.random().toString(36).slice(2, 8)}`;
      const ok = await sendApplyOps(JSON.stringify([op]), intentId);

      if (ok) {
        // 成功落盘：原子推进基准文本！
        lastPersistedTextRef.current.set(blockId, target);
        currentTask.resolve();
      } else {
        currentTask.reject(new Error('apply_ops_failed'));
        setLocalSaveStatus('unsaved');
        break; // 失败阻断后序出队
      }
    }
  } finally {
    inFlightBlocksRef.current.delete(blockId);
    updateAggregatedSaveStatus();
  }
};
```

### 5.4 密码学安全与分布式时钟块 ID 生成器（Robust Block ID Generator）

重构 `apps/crish-desktop/src/components/note-paper/noteBlockId.ts`：

```typescript
let sequenceCounter = 0;
const CLIENT_INSTANCE_ID = Math.floor(Math.random() * 0xffff);

export function newNoteBlockId(): string {
  const c = typeof crypto !== 'undefined' ? crypto : undefined;
  if (c && typeof c.randomUUID === 'function') {
    return c.randomUUID();
  }

  const bytes = new Uint8Array(16);
  if (c && typeof c.getRandomValues === 'function') {
    c.getRandomValues(bytes);
  } else {
    // 安全单调时钟退化
    const now = Date.now();
    const seq = ++sequenceCounter & 0xffff;
    const inst = CLIENT_INSTANCE_ID;

    bytes[0] = (now >>> 24) & 0xff;
    bytes[1] = (now >>> 16) & 0xff;
    bytes[2] = (now >>> 8) & 0xff;
    bytes[3] = now & 0xff;
    bytes[4] = (inst >>> 8) & 0xff;
    bytes[5] = inst & 0xff;
    bytes[6] = 0x40 | ((seq >>> 12) & 0x0f); // version 4
    bytes[7] = (seq >>> 4) & 0xff;
    bytes[8] = 0x80 | ((seq & 0x0f) << 2);   // variant 10xx
    for (let i = 9; i < 16; i++) {
      bytes[i] = Math.floor(Math.random() * 256);
    }
  }

  bytes[6] = (bytes[6] & 0x0f) | 0x40;
  bytes[8] = (bytes[8] & 0x3f) | 0x80;

  const hex = Array.from(bytes, (b) => b.toString(16).padStart(2, '0')).join('');
  return `${hex.slice(0, 8)}-${hex.slice(8, 12)}-${hex.slice(12, 16)}-${hex.slice(16, 20)}-${hex.slice(20)}`;
}
```
