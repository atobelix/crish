## 一、断层事实与安全隐患

1. **PTY 孤儿进程与 IPC 监听器泄漏（DEF-TERM-01~05）**：
   - 分屏切换或会话销毁时，副格子 PTY 进程未下发 kill 指令，在操作系统后台持续空转；
   - `ptyHistoryMap` 导致 Tauri IPC 事件监听器永不解绑，会话来回切换多次后监听器数量成倍暴增造成内存持续泄漏；
   - `ptyDetach`、`ptyAttach`、`ptyPing` 仅在 API 中声明但在生产代码中零调用，导致后端心跳保活和垃圾回收机制失联。
2. **Xterm 高频数据涌入阻塞主线程（DEF-XTERM-01~05）**：
   - 密集同步 `term.write`，在海量日志输出（如 build 阶段）时抢占主线程，导致 UI 完全假死冻结；
   - 终端输入无背压防护，用户长按按键高频冲击 IPC。
3. **端口探测器并发竞争与孤儿请求（DEF-PORT-01~04）**：
   - `fetchActiveDevPorts` 缺少并发请求去重与 AbortController 销毁，切换卡片后孤儿请求仍在后台向未知端口持续轮询。
4. **跨窗口通信安全边界破裂（DEF-BRIDGE-01~05）**：
   - 预览宿主向 iframe 广播 postMessage 时使用通配符 `'*'`，且接收外部 iframe 消息时零 `origin` 和 `source` 校验，第三方恶意页面可通过伪造 postMessage 窃取开发环境状态。

## 二、架构设计与隔离规范

```
┌─────────────────────────────────────────────────────────────┐
│ 1. PTY 生命周期精确收敛 (PTY Lifecycle SSOT)                │
│    • 副格子与主格子严格绑定 Tab 生命周期                      │
│    • unmount 时显式下发 pty_kill 并清理 IPC unlisten 句柄    │
│    • 接入 pty_ping 保活与超时回收                             │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. Xterm 高频写入缓冲切片 (Chunked Write with Microtask)    │
│    • 引入 16ms RAF / requestIdleCallback 切片写入队列        │
│    • 单次写入上限 64KB，超量自动分帧，保证主线程 60fps 响应   │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. 跨窗口通信安全沙箱 (Secure PostMessage Protocol)          │
│    • 严禁 targetOrigin='*'，严格校验 event.origin 与 source  │
│    • 建立两段式握手协议（HANDSHAKE_REQ / ACK），心跳保活     │
└─────────────────────────────────────────────────────────────┘
```

## 三、纯逻辑落地执行次序

### 阶段 1：PTY 进程销毁与 IPC 监听器生命周期收敛
1. 在 `TerminalCard.tsx` 的清理函数中，针对所有活动的 PTY 实例调用 `killPtySession`；
2. 在 `ptySessionApi.ts` 中，保存所有 `listen` 返回的 unlisten 函数，并在 `unsubscribe` 时严格调用释放；
3. 清理全仓未引用的假导出。

### 阶段 2：Xterm 高频写入分帧缓冲
1. 在 `ptyLifecycle.ts` 中改造数据流入管道：
   ```ts
   const writeQueue: string[] = [];
   let isFlushing = false;
   function scheduleFlush() {
     if (isFlushing) return;
     isFlushing = true;
     requestAnimationFrame(() => {
       const chunk = writeQueue.splice(0, 50).join('');
       term.write(chunk);
       isFlushing = false;
       if (writeQueue.length > 0) scheduleFlush();
     });
   }
   ```
2. 彻底消除海量日志卡死主线程的隐患。

### 阶段 3：跨窗口桥接安全与起源白名单
1. 在 `previewHostBridge.ts` 中：
   - 仅向 iframe 真实 origin 发送消息；
   - 监听 `message` 事件时，校验 `event.source === iframe.contentWindow`；
2. 建立心跳断连检测，iframe 崩溃或刷新时及时重置拾取器状态。

### 阶段 4：CSS 规范与软环焦点对齐
1. 清除 `TerminalCard.module.css` 中的旧式 `rgba(...)`；
2. 消除硬实线焦点环，改用 Conex §13 软环标准；
3. 移除原生 HTML `title` 属性，改用项目 `<Tooltip>`。

## 四、验收断言

1. **PTY 零泄漏断言**：在分屏终端中打开 4 个终端格子，切换会话或关闭卡片后，后台 PTY 进程数量准确归零；
2. **IPC 监听器零常驻断言**：反复开关终端 20 次，IPC 活跃监听器数量不增长；
3. **跨窗口安全断言**：伪造外部 window 发送恶意 postMessage，宿主直接安全忽略；
4. **单元测试**：`TerminalCard.test.tsx` 与 `previewProtocol.test.ts` 100% PASS。
