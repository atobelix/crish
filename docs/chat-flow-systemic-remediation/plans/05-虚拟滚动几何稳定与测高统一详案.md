## 二、纯净垂直节奏与统一盒模型架构（Pure Vertical Rhythm & Box Model）

### 2.1 消除相邻兄弟外边距黑洞（DEF-13）

#### 1. 根因剖析
原有 `ChatMessageList.module.css:40-48` 中注入的相邻兄弟选择器规则：
```css
/* 危险代码：相邻兄弟外边距黑洞 */
[data-chat-list-inner] > :not([hidden]) + :not([hidden]) {
  margin-top: 16px;
}
[data-chat-list-inner] > :not([hidden]) + :not([hidden]) > [data-vindex] {
  margin-top: 16px;
}
```
W3C 规范明确规定：DOM 元素的 `ResizeObserver.contentRect` 以及 `offsetHeight` **绝对不包含任何外部 `margin`**。在 100 条消息的长会话中，DOM 物理上累积了 `100 × 16px = 1600px`（若层叠则高达 3200px）的外边距空隙。然而，虚拟滚动管理器（VSM）树状数组中记录的行高总和完全忽略了这 1600px。当滑动切片使得上部真实节点被卸载、替换为 `style={{ height: startOffset }}` 的占位 Spacer 时，原本支撑几何高度的 `margin-top` 随 DOM 销毁瞬间蒸发，导致视口内所有消息行在虚拟化切片切换时发生数十至数百像素的向下或向上剧烈瞬移阶跃。

#### 2. 纯净垂直节奏重塑方案
彻底废弃并移除 `ChatMessageList.module.css` 中的所有相邻兄弟选择器 `+` 边距规则。垂直节奏全面收敛为**内部盒模型（Internal Box Model）**：

```css
/* 纯净垂直节奏体系：彻底消除 margin 塌陷与黑洞 */
.row {
  display: flex;
  flex-direction: column;
  width: 100%;
  margin-top: 0;
  margin-bottom: 0;
  /* 统一通过内部 padding-bottom 赋予标准垂直间距（16px） */
  padding-bottom: 16px;
  box-sizing: border-box;
  min-width: 0;
  max-width: min(var(--chat-col-max, 760px), 100%);
  margin-left: auto;
  margin-right: auto;
}

/* 状态微提示载体消息（PureCarrier）赋予紧凑发丝节奏（4px） */
.rowCarrier {
  padding-bottom: 4px;
}
```

### 2.2 盒模型统一度量契约（Box-Sizing SSOT）

#### 1. 度量源升级
在 `MessageVirtualizer.tsx` 顶级 RO 中，彻底淘汰 `entry.contentRect.height`（该值不含 padding 与 border），统一升级为度量元素完整的盒模型外框尺寸：

```ts
// 统一度量入口：包含 content + padding + border，严格排除外部 margin
const measuredHeight =
  entry.borderBoxSize?.[0]?.blockSize ??
  el.offsetHeight ??
  Math.ceil(entry.contentRect.height);
```

#### 2. 几何等式不变量
保证在整个虚拟化生命周期中，严格满足以下几何等式：
$$\text{DOM Physical Height}(el) \equiv \text{VSM Measured Height}(id) \equiv \text{Spacer Unit Calculation}$$
误差严格为 **0.0px**，消除任何因盒模型边界不同导致的前缀和断层。

### 2.3 剔除双重虚拟化冲突（DEF-14）

#### 1. 根因剖析
在 `ChatMessageRow.module.css:1-17` 与 `streaming-animation.css:129` 中存在硬编码：
```css
/* 危险代码：双重虚拟化自相残杀 */
.row {
  content-visibility: auto;
  contain-intrinsic-size: auto 120px;
}
.md-block-sealed {
  content-visibility: auto;
  contain-intrinsic-size: auto 320px;
}
```
JS 虚拟滚动已经通过 `[startIndex, endIndex]` 动态切片挂载严格控制了 DOM 数量，并预留了 `overscan = 6` 条缓冲行。这 6 条缓冲行位于视口之外，但位于 DOM 树中。浏览器的 `content-visibility: auto` 判定其处于屏幕之外，强制跳过排版并强行把高度压缩为 `contain-intrinsic-size`（120px 或 320px）。此时 RO 被触发，将 120px 错误回写进 VSM；用户稍微滚动使其进入视口时，`content-visibility` 解除跳过，高度瞬间从 120px 暴增至真实高度（如 800px），诱发持续的 120px ↔ 800px 剧烈反复横跳与 `ResizeObserver loop limit exceeded` 浏览器报警。

#### 2. 治理决策
从 `.row` 及 `.md-block-sealed` 中彻底删除 `content-visibility: auto` 与 `contain-intrinsic-size`。
仅保留纯粹的排版隔离：
```css
.row {
  /* 仅保留布局与重绘隔离，严禁尺寸跳变容器 */
  contain: layout paint;
}
```
DOM 的挂载与卸载生命周期由 JS 虚拟列表独家全权接管，严禁 CSS 引擎二次干扰几何测量。

### 2.4 容器内衬与 Sticky 吸顶几何基线校准（DEF-15, DEF-16）

#### 1. 坐标基线漂移纠正
`ChatMessageList.module.css` 中的 `.listInner` 具有 `padding: 48px 20px 16px;`。
在数学二分查找中：
- 真实消息第 0 项的实际物理 `offsetTop` 是 `48px`；
- 原有 `vs.manager.computeVisibleRange(scrollTop, ...)` 直接传入原始 `scrollTop`，在 `scrollTop = 40px` 时误判已经滚过了第 0 项的 40px，引发系统性 48px 基线脱节。

#### 2. 基线校准算法
确立容器内边距补偿算法：
```ts
export const CHAT_LIST_PADDING_TOP = 48;

/**
 * 虚拟滚动视口坐标变换
 */
export function computeEffectiveScrollTop(physicalScrollTop: number, paddingTop: number = CHAT_LIST_PADDING_TOP): number {
  return Math.max(0, physicalScrollTop - paddingTop);
}
```
在 `computeVisibleRange` 时：
```ts
const effectiveScrollTop = computeEffectiveScrollTop(vs.scrollTop, CHAT_LIST_PADDING_TOP);
const { startIndex, endIndex, startOffset, estimatedTotalHeight } =
  vs.manager.computeVisibleRange(
    effectiveScrollTop,
    vs.viewportHeight,
    messages.length,
    overscan
  );
```
在渲染 Spacer 时，第一项元素上方的 Spacer 高度精确为 `startOffset`，容器原本的 `padding-top: 48px` 原生保留，保证物理视图与数学查找完全重合。

#### 3. 刻度跳转（Scrubber Target）与吸顶栏几何补偿（DEF-16）
在 `flowScrubberModel.ts:171-195` 中，重构目标滚动坐标计算公式，纳入 `CHAT_LIST_PADDING_TOP` 与 Sticky 吸顶栏 `pinnedBar` 的实际高度：

```ts
export function calculateScrubberTargetScrollTop(params: {
  targetOffset: number;
  targetHeight: number;
  viewportHeight: number;
  paddingTop?: number;
  stickyHeaderHeight?: number;
}): number {
  const {
    targetOffset,
    targetHeight,
    viewportHeight,
    paddingTop = 48,
    stickyHeaderHeight = 0,
  } = params;

  // 物理基线偏移
  const physicalTop = targetOffset + paddingTop;
  // 有效可视视口高度（剔除吸顶栏遮挡）
  const availableViewHeight = Math.max(0, viewportHeight - stickyHeaderHeight);
  // 视口居中目标位置
  const centerDelta = Math.max(0, (availableViewHeight - targetHeight) / 2);
  const targetScrollTop = physicalTop - stickyHeaderHeight - centerDelta;

  return Math.max(0, targetScrollTop);
}
```
彻底终结目标跳转后头部文字被吸顶栏物理遮挡的缺陷。

### 3.2 动态节点 O(1) 观察生命周期（DEF-01 根治）

#### 1. 根因剖析
原有 `MessageVirtualizer.tsx:147-190` 的 `useEffect` 依赖数组为 `[msgIds, containerRef, setActual]`。当用户上下翻看历史时，`msgIds` 引用不变，仅切片下标 `startIndex` 与 `endIndex` 改变。因此该 Effect 根本不会重新执行，新挂载进 DOM 的行处于“观测全盲”状态，而卸载离开视口的行被 `observedRowsRef.current` 强引用驻留，造成游离 DOM 内存泄漏。

#### 2. 行级自注册与解挂机制
在虚拟列表渲染循环中，通过行级 Callback Ref 或 Layout Effect 实现 O(1) 精准注册/注销：

```tsx
// MessageVirtualizer.tsx 中的单轨观测注册器
const registerRowElement = useCallback((id: string, el: HTMLElement | null) => {
  const ro = roRef.current;
  if (!ro) return;
  const currentMap = elementMapRef.current;
  const oldEl = currentMap.get(id);
  if (oldEl && oldEl !== el) {
    ro.unobserve(oldEl);
    currentMap.delete(id);
  }
  if (el) {
    ro.observe(el);
    currentMap.set(id, el);
  }
}, []);
```
在虚拟切片渲染单行时，挂载 `ref={(node) => registerRowElement(msg.id, node)}`：
- 行组件首次挂载入 DOM：立即触发 `ro.observe(node)`，零延迟接入尺寸监测；
- 行组件从视口卸载 unmount：Callback Ref 传入 `null`，立即触发 `ro.unobserve(oldEl)`，并从 Map 中彻底剔除引用，**内存泄漏彻底归零（0 Detached DOM Leaks）**。

## 四、用户主动滚动与流式自动吸底无振荡状态机（Non-Oscillating Scroll State Machine）

### 4.1 核心状态与跃迁规则（DEF-08, DEF-11）

彻底终结在 ResizeObserver 回调中强写 `scrollTop = maxScroll` 的野蛮实现。确立无振荡状态机（`ChatScrollStateMachine`）：

```
[会话初始化 / 进入新会话] ──> STICK_TO_BOTTOM (流式吸底锁定)
                                │       ▲
           滚轮向上 / 触摸向上   │       │ 用户主动滑回底部 (distance <= 2px)
           拖动滚动条脱离底部    │       │ 或点击地表按钮
                                ▼       │
                          USER_BROWSING (用户翻看历史)
                                │
                                │ 上方内容被动折叠收缩 (scrollHeight 下降)
                                ▼
                   PASSIVE_SHRINK_COMPENSATING (锚点锁定补偿)
                   保持阅读位置相对坐标不变，严禁误杀为吸底！
```

#### 1. 状态定义
- `STICK_TO_BOTTOM`：视口牢牢跟随最新输出流。仅在该状态下，新的 Token 或排版变化才允许推进视口；
- `USER_BROWSING`：用户正在查阅历史记录。**任何后台打字、尺寸改变、流式追加绝对禁止修改 `scrollTop`**！
- `PASSIVE_SHRINK_COMPENSATING`：上方历史消息被动折叠，容器物理收缩。保持当前屏幕正在阅读的行（Anchor Row）在视口内的相对坐标恒定不变。

#### 2. 用户手势明确断开（消灭 60Hz 暴力拉扯，DEF-08）
监听滚动容器的 `wheel`、`touchstart`、`touchmove` 原生事件：
```ts

  if (e.deltaY < 0) {
    scrollStateMachine.transitionToBrowsing();
  }

```
在 `USER_BROWSING` 模式下，流式生成过程中的任何 RO 回调、Token 更新被彻底屏蔽，无法触碰 `scrollTop`。用户向上滚动丝滑流畅，屏幕绝无任何 60Hz 拉扯闪烁。

function handleContainerScroll(
  currentTop: number,
  scrollHeight: number,
  clientHeight: number,
  userScrollActive: boolean

### 5.1 双阶段虚拟列表消息跳转（`scrollToMessage` 彻底修复，DEF-09）

#### 1. 根因剖析

#### 2. 双阶段虚拟寻址架构
```ts
export function scrollToMessageVirtualized(
  messageId: string,
  options: {
    container: HTMLElement;
    vsm: VirtualScrollManager;
    paddingTop?: number;
    stickyHeaderHeight?: number;
    onCompleted?: (el: HTMLElement) => void;
  }
): boolean {
  const { container, vsm, paddingTop = 48, stickyHeaderHeight = 0, onCompleted } = options;

  // Phase 1: 视口内快速命中
  const existingDom = findMessageElement(messageId, container);
  if (existingDom) {
    alignElementInView(existingDom, container, stickyHeaderHeight);
    onCompleted?.(existingDom);
    return true;
  }

  // Phase 2: 虚拟化数学寻址
  const order = vsm.getOrder();
  const index = order.indexOf(messageId);
  if (index === -1) return false;

  const targetOffset = vsm.getOffset(index);
  const targetHeight = vsm.getHeightAt(index);
  const viewportHeight = container.clientHeight;

  const targetScrollTop = calculateScrubberTargetScrollTop({
    targetOffset,
    targetHeight,
    viewportHeight,
    paddingTop,
    stickyHeaderHeight,
  });

  // 1. 物理跳转驱动虚拟切片重新计算挂载
  container.scrollTop = targetScrollTop;

  // 2. 挂载后精准定位与高亮（两个 rAF 确保 React Commit 与 Paint 结束）
  window.requestAnimationFrame(() => {
    window.requestAnimationFrame(() => {
      const mountedEl = findMessageElement(messageId, container);
      if (mountedEl) {
        alignElementInView(mountedEl, container, stickyHeaderHeight);
        onCompleted?.(mountedEl);
      }
    });
  });

  return true;
}
```

## 七、立体化验收断言与现场验证基线（Acceptance Assertions）

### 断言 1：零外边距几何等价性断言（Zero-Margin Equivalence）
- **测试方法**：在包含 100 条各异消息（含代码块、长文本、单行微提示、思考链）的会话中，遍历所有挂载消息行。
- **断言目标**：
  $$\forall i \in [startIndex, endIndex], \quad \text{getComputedStyle}(el_i).marginTop \equiv 0\text{px}$$
  $$\sum_{i=0}^{N-1} \text{el}_i.\text{offsetHeight} \equiv \text{VSM.getTotalHeight}(N)$$
  误差不得超过 $\pm 0.5\text{px}$（亚像素舍入允许范围），彻底根除 1600px 几何黑洞。

### 断言 2：单轨 RO 与零死循环告警断言（Zero-Loop Limit Exceeded）
- **测试方法**：在测试用例中连续快速展开/折叠包含 200 行 Diff 的代码卡片及多行 Markdown 复杂表格，监听浏览器控制台与运行时 Error 事件。
- **断言目标**：
  1. 全局监听 `window.onerror` 与 `console.error`，`ResizeObserver loop limit exceeded` 或 `undelivered notifications` 告警出现次数恒等于 **0**；
  2. 页面中运行的 `ResizeObserver` 实例数量严格为 **1**（仅顶级虚拟滚动宿主持有一个实例）。

### 断言 3：动态展开/折叠双相测高闭环断言（Expand/Collapse Invalidation）
- **测试方法**：
  1. 点击用户超长气泡展开全文；
  2. 点击思考链控制栏展开 1000px 过程节点；
  3. 点击 Diff 卡片“展开剩余 200 行”；
  4. 点击上下文文件注入卡片展开。
- **断言目标**：
  展开瞬间 `manager.getActualHeight(id)` 立即转为 `null`（保持 estimated），随后在 1 帧内被单轨 RO 捕获并回写真实高度；Fenwick 树对应前缀和增加量与 DOM 物理高度膨胀量严格相等，后续所有行向下平滑位移，零重叠、零文字截断、零底部异常留白。

### 断言 4：滚轮向上与后台流式 60Hz 零振荡断言（Zero-Oscillation on Stream）
- **测试方法**：在模拟后台以 50ms/token 高频推送的流式生成期间，模拟用户向上滚动 30px（发送向上 Wheel 事件）。
- **断言目标**：
  1. 状态机立即进入 `USER_BROWSING` 状态；
  2. 随后到达的 100 个 Token 期间，滚动容器的 `scrollTop` 恒定保持在用户滚停的位置，**绝对不允许发生向底部拉扯的跳动（振荡频率 = 0Hz）**；
  3. 当用户主动点击“回到底部”悬浮按钮时，平滑滚动至底部并重新恢复 `STICK_TO_BOTTOM` 状态。

### 断言 5：虚拟化视口外跨切片精准寻址断言（Off-Screen Jump Navigation）
- **测试方法**：在包含 200 条消息的长会话中，滚动停留至底部，调用 `scrollToMessage(messages[5].id)`（第 5 条消息物理处于视口外上千像素处）。
- **断言目标**：
  1. 函数返回 `true`，Toast 绝不报“未找到该固定消息”；
  2. 视口平滑滚动至第 5 条消息区域；
  3. 第 5 条消息被正确挂载入 DOM，且其头部文字与吸顶栏底部保留标准间距，不发生物理重叠遮挡；
  4. 目标消息节点精准高亮触发 `rowPinFlash` 动画。

### 断言 6：撤销视口同步锚定稳定断言（Undo Viewport Stability）
- **测试方法**：在中间位置查阅消息时执行消息撤回或恢复快照。
- **断言目标**：
  当前视口顶部第一条可见消息在撤回前后的视口相对像素偏移量变化量 $\Delta \le 1.0\text{px}$，视口内容绝对不发生向上或向下千像素巨幅震荡。

### 断言 7：高速滚动零棋盘格白屏断言（Zero-Checkerboarding）
- **测试方法**：以 3000px/s 的速度快速滚动列表，在每一帧捕获视口中间点的 DOM 元素。
- **断言目标**：
  视口内可见区域内 `[data-vsm-spacer]` 占位符暴露在视口中央的帧数恒等于 **0**，动态 Overscan 保障真实消息行节点先于视口显现完成 DOM 挂载。
