# 文件上下文与注入卡片极简渲染详案

> **文件路径**：`docs/chat-flow-systemic-remediation/plans/02-文件上下文与注入卡片极简渲染详案.md`  
> **方案定位**：对话流可见注入卡片协议与极简呈现详案（对齐总方案阶段三与阶段五）  
> **指导思想**：纯逻辑规划、反退避、拒绝打补丁、问题同权、契约驱动、立体化闭环  

---

## 摘要与问题背景

在对话流系统性净化与架构重塑战役中，**文件上下文（`file_context`）与系统注入卡片**的视觉和交互断层属于七大结构性病灶之一（ISSUE-C、ISSUE-D、ISSUE-F）：
1. **粗暴隐藏误杀功能**：历史代码曾在 `CompactInjectionRow.tsx` 与 `MessageContent.tsx` 中直接写入 `if (kind === 'file_context') return null;`，企图通过应付式屏蔽快速消除大卡片，导致用户在输入框引用 `@file`、代码选区批注或工具注入文件上下文时在对话流中完全不可见，破坏了上下文感知闭环；
2. **样式违规与彩虹边框**：注入卡片历史散落红橙黄绿蓝紫等多种高饱和度彩色粗边框、重阴影与硬编码色值，严重背离 Conex 极简高雅的设计哲学；
3. **交互伪实现与断层**：卡片 Header 与 Body 上的「打开文件」、「查看 Diff」、「重试注入」等交互存在回调未透传或悬空断层，缺乏与桌面宿主文件能力和 Diff 预览器的真实连通；
4. **无障碍与焦点违规**：卡片焦点态存在高对比度硬黑边（违背 Conex §13 焦点态微环对比度 ≤ 10% 规范），且缺少规范的键盘折叠与跳转导航支持。

本详案旨在提供从底层数据契约、单一真理源（SSOT）、视图层级架构、真实交互链路到立体化验证的严密落地方案，彻底消除误杀补丁，实现全 9 类注入卡片的高质感极简呈现。

## 一、契约与数据模型（Data Contract Layer & SSOT Architecture）

### 1.1 `file_context` 标准元数据契约（`FileContextMetadata`）

为杜绝基于标题或正文字符串正则解析的脆弱做法，确立 `file_context` 的结构化元数据契约。数据在产生端即完成结构化绑定，并通过 `MessageContextInjection.metadata` 传递：

```ts
/**
 * 文件上下文专属结构化元数据契约（SSOT）
 */
export interface FileContextMetadata {
  /** 主文件绝对路径或项目相对路径 */
  filePath: string;
  /** 关联的目标文件路径列表（支持多文件引用） */
  targetPaths: string[];
  /** 关联的文件改动快照（Diff）列表（可选） */
  diffs?: FileDiff[];
  /** 精确计算或估算的上下文 Token 消耗量 */
  tokenCount?: number;
  /** 选区行号范围或代码范围提示（例如 "L12-L45"） */
  lineRange?: string;
  /** 文件摘要或批注说明（纯文本，供 Header 快速预览） */
  summary?: string;
  /** 注入触发类型：选区批注 / 文件引用 / 语义检索 / 工具上下文 */
  triggerKind?: 'annotation' | 'at_file' | 'retrieval' | 'tool_output';
  [key: string]: unknown;
}
```

### 1.2 全 9 类上下文注入契约（`ContextInjectionKind` 全景矩阵）

对话流可见上下文注入卡片覆盖以下 9 种业务来源，所有分类均具备合法的语义图标、展示标签与样式类：

| 注入分类 (`kind`) | 语义图标 (`Lucide`) | 分类徽标展示文案 | 核心语义与内容形态 | CSS 模块 Tone 类 |
| :--- | :--- | :--- | :--- | :--- |
| `rule` | `ShieldCheck` | 规则注入 | 项目/全局开发规范（如 `AGENTS.md`、安全基线、反退避铁律） | `toneRule` |
| `skill` | `Sparkles` | 技能上下文 | 专家技能/提示词模板（如 `antigravity-guide`、专业分析模板） | `toneSkill` |
| **`file_context`** | `FileCode2` | **文件上下文** | 文件引用、选区批注快照、代码选区内容与关联 Diff | `toneFile` |
| `git_status` | `GitBranch` | Git 状态 | 当前分支状态、工作区变更统计、未跟踪文件快照 | `toneGit` |
| `terminal_output` | `Terminal` | 终端上下文 | 命令执行回执、错误日志堆栈、测试运行失败现场 | `toneTerminal` |
| `runtime_steering` | `Navigation` | 运行时纠偏 | 动态目标纠偏指令（如 `/goal` 推进、运行期提示词干预） | `toneSteering` |
| `schedule_trigger` | `Clock` | 定时唤醒 | 定时任务触发、定时唤醒计划元数据 | `toneSchedule` |
| `memory` | `Brain` | 会话记忆 | 跨轮次持久化记忆抽取、阶段性决策摘要 | `toneMemory` |
| `workspace_env` | `FolderTree` | 工作区环境 | 工作区根路径、环境配置、目录拓扑契约 | `toneWorkspace` |

### 1.3 上下文注入实体核心契约（`MessageContextInjection`）

在 `apps/crish-desktop/src/store/types.ts` 中维系统一实体契约，杜绝命名漂移：

```ts
export type ContextInjectionKind =
  | 'rule'
  | 'skill'
  | 'file_context'
  | 'git_status'
  | 'terminal_output'
  | 'runtime_steering'
  | 'schedule_trigger'
  | 'memory'
  | 'workspace_env';

export type ContextInjectionStatus =
  | 'pending'   // 准备注入中（脉冲旋转指示器）
  | 'injected'  // 已注入当前轮次（常规可用态）
  | 'active'    // 持续生效中（跨轮次持久态）
  | 'expired'   // 已过期（沉淀为历史）
  | 'failed';   // 注入失败（标红高亮 + 失败诊断 + 重试按钮）

export interface MessageContextInjection {
  id: string;
  kind: ContextInjectionKind;
  title: string;
  summary?: string;
  status: ContextInjectionStatus;
  source: string;
  content: string;
  tokenEstimate?: number;
  diffs?: FileDiff[];
  targetPaths?: string[];
  timestamp: number;
  isFoldable?: boolean;
  defaultFolded?: boolean;
  errorMessage?: string;
  metadata?: Record<string, unknown>;
}
```

### 1.4 单一真理源与双投影数据流（SSOT Pipeline）

为确保文件引用在输入阶段与时间线呈现阶段不发生割裂，采用**单一暂存源、双投影输出**架构：
1. **产生端（Producer）**：
   - 当用户在输入框键入 `@file` 或通过选区添加批注时，`fileAnnotations.ts` 在会话隔离池中登记 `PendingFileAnnotation`；
   - 立即向输入框附件条派发 `ChatAttachment` 供用户二次查看或删除；
2. **派发端（Dispatcher）**：
   - 消息发送时，`contextInjectionDispatcher` 将 `PendingFileAnnotation` 转换为规范的 `MessageContextInjection`，其中 `kind = 'file_context'`，`metadata` 注入 `FileContextMetadata`；
   - 显式声明 `defaultFolded = true`（文件上下文默认折叠）与 `isFoldable = true`；
3. **装配端（Mounting）**：
   - `sessionInjectionMount.ts` 通过 `appendInjectionToMessage` 将其原子挂载至宿主消息的 `injections` 与 `blocks` 时间线中；
   - 绝不产生孤立于消息系统之外的悬空 DOM 节点。

### 2.1 极简单行折叠 Header 规范

#### 1. 默认折叠策略（Default Fold Strategy）
- **`file_context` 严格默认折叠**：
  ```ts
  const defaultOpen =
    injection.defaultFolded !== undefined
      ? !injection.defaultFolded
      : injection.kind === 'file_context'
        ? false
        : !((injection.content || '').length > INJECTION_COLLAPSE_CHAR_THRESHOLD);
  ```
  - `file_context` 通常承载代码片段或大量选区文本，默认铺开会严重挤压对话视窗；默认折叠能确保对话流清爽，同时提供清晰的文件名与 Token 占用；
  - 非 `file_context` 注入项遵循 160 字符阈值（`INJECTION_COLLAPSE_CHAR_THRESHOLD = 160`），短内容默认直接展现；
  - 受控状态（`expandedInjections[injection.id]`）优先于本地内部 state，保证虚拟滚动与翻页状态稳定。

#### 2. 无彩虹条与发丝边框规范（Purge Rainbow Borders）
- **彻底清退历史彩虹粗边框**：
  - 严禁对不同类别使用红、橙、黄、绿、青、蓝、紫等强饱和度左侧粗竖条；
  - 全量注入项统一收敛为高雅内敛的 `var(--border-subtle)`（1px 发丝边框），左缘绝不施加差异化强调色；
  - 所有类型的 `iconSlot` 统一采用次级中性色 `var(--text-tertiary)`，仅保留图标本身的语义轮廓，彻底消除视觉杂乱感；
- **微悬停反馈**：
  - 卡片底色默认采用 `var(--bg-card)`；
  - 悬停时通过微交互过渡至 `var(--tint-hover)`，边框微调为 `color-mix(in srgb, var(--border-color) 92%, var(--text-primary) 8%)`，保证质感温润且无刺眼突变。

#### 3. 设计系统图标矩阵（Icon Matrix）
- 引入统一的 `InjectionIconComponent` 签名，尺寸限定为 14px，描边厚度统一为 `strokeWidth={1.8}`；
- 状态指示：
  - `pending` 状态：展示 12px 品牌色脉冲旋转圈（`loading-spinner`）；
  - `failed` 状态：展示 `AlertCircle` 警示图标（`var(--text-danger)`）；
  - 其他状态展示分类对应的标准 Lucide 图标。

### 2.2 行内快捷操作（Inline Quick Actions）

在 Header 右侧元数据区（`rowHeadMeta`）集成高频快捷操作，无需展开详情面板即可一键直达，且所有子操作必须调用 `e.stopPropagation()` 与 `onKeyDown={(e) => e.stopPropagation()}`，防止误触整行折叠：

1. **「打开文件」按钮（`onOpenPath`）**：
   - **呈现条件**：卡片包含 `targetPaths`（取第一个路径）或 `metadata.filePath`，且父级注入了有效 `onOpenPath` 回调；
   - **DOM 结构**：
     ```tsx
     <Tooltip content={`打开文件: ${targetPath}`}>
       <button
         type="button"
         className={styles.headerActionBtn}
         onClick={(e) => {
           e.stopPropagation();
           onOpenPath(targetPath);
         }}
         aria-label={`打开文件 ${targetPath}`}
         data-injection-path-btn="true"
       >
         <ExternalLink size={12} aria-hidden />
         <span>打开文件</span>
       </button>
     </Tooltip>
     ```
2. **「查看 Diff」按钮（`onOpenDiff`）**：
   - **呈现条件**：卡片包含 `diffs` 且数组长度 > 0，且父级注入了 `onOpenDiff` 回调；
   - **DOM 结构**：
     ```tsx
     <Tooltip content={`查看 Diff: ${firstDiff.filePath}`}>
       <button
         type="button"
         className={styles.headerActionBtn}
         onClick={(e) => {
           e.stopPropagation();
           onOpenDiff(firstDiff);
         }}
         aria-label={`查看 ${firstDiff.filePath} 的改动`}
         data-injection-diff-btn="true"
       >
         <GitCompare size={12} aria-hidden />
         <span>查看 Diff</span>
       </button>
     </Tooltip>
     ```
3. **「重试注入」按钮（`onRetryInjection`）**：
   - **呈现条件**：`injection.status === 'failed'` 且父级注入了 `onRetryInjection`；
   - **视觉特征**：`RotateCcw` 图标，悬停时微红微光背景，专属 Tooltip 提示「重新注入此上下文」。

### 2.3 展开后详情体（`InjectionBody`）与防溢出保护

展开后的详情体承载富文本与多重关联资源，必须配备严密的防溢出与自适应机制：
1. **Markdown 异步渲染与代码格式化**：
   - 正文托管给 `StreamingMarkdownView`，接入后台 Web Worker / Rust 异步解析引擎，自动获得语法高亮、代码折叠与无损 XSS 净化；
   - 保证流式更新与静态消息呈现时的零主线程阻塞；
2. **路径芯片集群（Path Chips）**：
   - 当 `targetPaths` 包含多个文件时，详情体底部渲染水平流动换行的 `pathChipBtn` 芯片；
   - 样式：圆角胶囊（`border-radius: 9999px`）、等宽字体（`var(--font-mono)`）、单芯片最大宽度 `max-width: 220px`（超出省略）；
   - **防泛滥限流**：最多展示前 8 个文件芯片，超出部分显示 `+N` 灰色胶囊，Tooltip 悬停展示全量路径列表；
3. **防溢出与高度保护**：
   - `bodyInner` 容器强制约束最大高度：`max-height: 360px; overflow-y: auto;`；
   - 滚动条接入系统极简滚动条样式，杜绝横向滚动条撕裂布局；
   - 长单词与长路径施加 `word-break: break-word;`，错误信息诊断框施加 `white-space: pre-wrap;`。

## 三、真实交互链路闭环（Real Interaction & Host Bridge Integration）

### 3.1 打通 `onOpenPath` 与桌面宿主文件能力

从卡片点击到桌面宿主打开文件的完整闭环拓扑如下：

```
[用户点击「打开文件」/ 路径芯片]
             │
             ▼
CompactInjectionRow (onOpenPath)
             │
             ▼
MessageContent (renderTools & processItemRenderer)
             │
             ▼
useChatMessageState (toolStackProps.actions.onOpenPath)
             │
             ▼
ChatCard (navigation.onOpenPath: state.openPathInFilesPanel)
             │
             ▼
useChatSessionActions.ts (openPathInFilesPanel)
             ├──────────────────────────────────────────────────────┐
             ▼ (项目内工作区文件)                                     ▼ (项目外绝对路径/其它)
  resolveWorkspacePath(path)                               isAbsoluteFsPath(path)
             │                                                      │
             ▼                                                      ▼
  readTextFile(resolved, 1)                               isOfficeOrBinary
             │                                           ├──────────┴──────────┐
             ▼                                           ▼ (二进制/Office)     ▼ (纯文本代码)
  openToolInActiveTab('files')                    openPathDefault()     openFileViewerInSession()
  window.dispatchEvent('crish-open-file')         (拉起操作系统原生程序)    (新建会话代码查看器标签)
```

#### 关键容错与异常处理
1. **空路径校验**：若传入空串或空白字符，直接拦截并调用 `toast.show('文件不存在')`；
2. **笔记/Notebook 协议分流**：若路径匹配 `^(note|notebook)(:|$)`，直接分流至 `openFileInPanel(filePath)` 打开内部笔记画布；
3. **多媒体与 Office 文件原生关联**：对 `.docx`, `.xlsx`, `.pptx`, `.pdf`, `.zip`, `.png` 等二进制文件，在打开文件管理器定位的同时，调用 Tauri 宿主底层 `openPathDefault(path)` 拉起操作系统默认程序；
4. **文件缺失保护**：若 `readTextFile` 捕获到 `not_found`、`Path does not exist` 或 `No such file`，优雅降级并弹窗提示 `文件不存在`，避免页面白屏或未捕获 Promise 异常。

### 3.2 打通 `onOpenDiff` 与 Diff 预览器

从卡片点击「查看 Diff」到右侧 Diff 面板挂载呈现的完整链路如下：

```
[用户点击「查看 Diff」/ diffChipBtn]
             │
             ▼
CompactInjectionRow (onOpenDiff)
             │
             ▼
MessageContent (toolStackProps.actions.onOpenDiff)
             │
             ▼
useChatMessageState (toolStackProps.actions.onOpenDiff)
             │
             ▼
ChatCard (navigation.onOpenDiff: state.openDiffInRightPanel)
             │
             ▼
useChatDiffPanel.ts (openDiffInRightPanel)
             │
             ├─► setActiveDiffSourceAccess(diff)  [Store Action: 写入全局当前活跃 Diff]
             │
             └─► handleGlobalTabClick('diff')     [Layout Action: 激活右侧面板 Diff 选项卡]
```

#### 数据契约一致性
- `FileDiff` 必须完整包含 `{ filePath, originalContent, newContent, additions, deletions }`；
- Diff 面板接收到 `setActiveDiffSourceAccess` 信号后，以 O(1) 速度切换到对应文件的分栏/统一对比视图，并将高光聚焦于首个改动行。

### 3.3 优雅处理 `onRetryInjection` 重试契约

#### 1. 历史断层根因
历史实现中，`useChatMessageState` 的 `toolStackProps.actions` 未包含 `onRetryInjection`，导致 `MessageContent.tsx` 在渲染 `item.kind === 'injection'` 时无法向下透传重试回调，卡片失败态上的重试按钮处于“有 UI 无动作”的悬空假状态。

#### 2. 闭环修复方案
1. **在 `ContextInjectionSharedProps` 与 `ChatToolStackSharedProps` 中统一注册回调契约**：
   ```ts
   export interface ContextInjectionSharedProps {
     // ...
     onRetryInjection?: (injectionId: string) => void;
   }
   ```
2. **在 `MessageContent.tsx` 中显式绑定并向下透传**：
   ```tsx
   if (item.kind === 'injection') {
     return (
       <CompactInjectionRow
         key={item.key}
         rowKey={item.key}
         injection={item.injection}
         activeSessionId={toolStackProps?.activeSessionId ?? ''}
         msgId={msgId}
         {...(toolStackProps?.actions?.onOpenDiff
           ? { onOpenDiff: toolStackProps.actions.onOpenDiff }
           : {})}
         {...(toolStackProps?.actions?.onOpenPath
           ? { onOpenPath: toolStackProps.actions.onOpenPath }
           : {})}
         {...(toolStackProps?.actions?.onRetryInjection
           ? { onRetryInjection: toolStackProps.actions.onRetryInjection }
           : {})}
       />
     );
   }
   ```
3. **重试状态机逻辑**：
   - 用户点击重试时，首先将注入项状态原子置为 `pending`，清除既有 `errorMessage`；
   - 重新触发对应的加载器（如重新读取文件、重新拉取 Git 状态或重新解析规则）；
   - 若重新加载成功，状态迁移至 `injected`，卡片恢复正常发丝微边框；若再度失败，状态切回 `failed`，展示新的错误原因。

## 四、可访问性与键盘导航（WAI-ARIA & Ergonomics）

### 4.1 语义角色与无障碍树结构（WAI-ARIA Tree）

为确保屏幕阅读器（NVDA、JAWS、Narrator）能够无歧义解析注入卡片，构建符合 WAI-ARIA 1.2 标准的无障碍树：

1. **外层卡片容器（`ContextInjectionBlock`）**：
   - 声明 `role="region"`；
   - 挂载动态无障碍标签：`aria-label="系统上下文注入（共 N 项）"`；
   - 若全部注入项均为状态切换微提示，则动态切换为 `role="status"`；
2. **单行卡片外壳（`CompactInjectionRow`）**：
   - 声明 `role="article"` 或标准语义容器；
   - 携带完整的 `data-injection-id`、`data-injection-kind`、`data-injection-status` 属性，便于自动化测试与辅助技术抓取；
3. **可交互 Header 栏（`InjectionHeader`）**：
   - 若卡片可折叠或具备路径跳转能力，声明 `role="button"` 与 `tabIndex={0}`；
   - 属性联动：`aria-expanded={canToggle ? isOpen : undefined}`；
   - 控制目标联动：`aria-controls={canToggle ? bodyId : undefined}`；
   - 若卡片不可折叠且无路径跳转，退化为静态标题容器（移除 `role="button"` 与 `tabIndex`，追加 `.rowHeadStatic` 类名）；
4. **详情面板（`InjectionBody`）**：
   - 声明 `role="region"`；
   - 声明唯一的 `id={bodyId}`，并挂载 `aria-label="{title} 详情"`。

### 4.2 语音播报合成规范（`rowAriaLabel`）

Header 的 `aria-label` 由纯逻辑工具按顺序格式化组装，杜绝信息遗漏：
```ts
const rowAriaLabel = [
  '系统上下文注入',
  kindLabel,                                             // 例如 "文件上下文"
  injection.title,                                       // 例如 "📎 文件批注：a.ts"
  injection.summary || null,                             // 例如 "用户关注选区批注"
  statusText,                                            // 例如 "已注入" / "注入失败"
  canToggle ? (isOpen ? '已展开' : '已折叠') : null,
  canToggle ? (isOpen ? '按 Enter 或空格折叠' : '按 Enter 或空格展开') : null,
]
  .filter(Boolean)
  .join('，');
```

### 4.3 键盘导航与焦点管理

1. **Enter / Space 展开与折叠**：
   - 焦点位于 Header 时，按 `Enter` 或 `Space` 键阻止默认滚动（`e.preventDefault()`），并触发折叠状态切换；
   - 若当前卡片不可折叠但包含文件路径，按 `Enter` 或 `Space` 键直接调用 `onOpenPath` 打开文件；
2. **Escape 快速收起**：
   - 当卡片处于展开态且焦点位于 Header 时，按 `Escape` 键可立即收起卡片，并将焦点安全锁定在当前 Header 上，防止视线迷失；
3. **子元素事件阻断**：
   - Header 内的快捷按钮（`[打开文件]`、`[查看 Diff]`、`[重试]`）在处理 `onClick` 与 `onKeyDown` 时均显式调用 `e.stopPropagation()`，防止键盘激活操作按钮时意外触发外层 Header 的折叠切换。

### 4.4 焦点态微环规范（对齐 Conex §13 铁律）

严格落实 Conex UI 规范，禁止任何厚重、深黑、高对比度实心边框：
```css
.rowHead:focus-visible,
.retryBtn:focus-visible,
.pathChipBtn:focus-visible,
.diffChipBtn:focus-visible,
.headerActionBtn:focus-visible {
  outline: none;
  border-radius: var(--radius-sm, 4px);
  /* 焦点混入严格 ≤10%（Conex §13 上限量级） */
  box-shadow: 0 0 0 1.5px
    color-mix(in srgb, var(--border-color) 90%, var(--text-primary) 10%);
}
```
- 焦点微环相对基线仅加深 3%~10%，足以提示当前焦点位置，但绝不破坏阅读沉浸感；
- 适配 `@media (prefers-reduced-motion: reduce)`，在用户开启减弱动效时延长或禁用不必要的过渡动画。
