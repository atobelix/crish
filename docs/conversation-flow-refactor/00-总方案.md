# 00-对话流界面重构总方案

> 战役：对话流（Chat Flow）界面重构。依据：`survey/01-参考仓库对话流架构调研.md`、`survey/02-本仓对话流现状审计.md`。
> 遵循 AGENTS.md §1 反退避：目标效果不降级、问题同权、纯逻辑规划（不含工期/人员）。

## 一、目标效果（锁定，不得自行砍项）

1. **一条流式真相路径**：会话事件（含流式 chunk）→ 单一折叠管线 → 不可变视图快照；废除 streamState 账本与视图层 merge 双轨。
2. **统一节点渲染契约**：所有对话元素（用户/助手/思考/工具/注入/压缩/错误/重试/审批）走同一 keyed Seat + data-* 锚点 + kind 注册表；未知类型兜底展示，永不静默丢弃。
3. **简洁的视觉语言**（对齐 dsh + 本仓 UI 铁律）：24px 单行工具/思考行、整 turn 级运行状态、过程折叠（TurnProcess）、turn-tail 页脚、统一行距 rhythm；工具卡收敛为一代表。
4. **正确且顺滑的滚动**：reader/programmatic 判别、跟随签名、prepend 锚点补偿、跨会话滚动恢复、零高度 sticky 回底；与现有 VSM 虚拟化共存。
5. **立体验证**：静态门禁（check:desktop / typecheck / 单测）+ 新增滚动契约 e2e + 4000 Tauri MCP 真实宿主视觉验收（禁 mock 会话）。

## 二、架构决策

- **D1 事件管线**：在 `api/chat-bridge` 之上建 `ConversationAssembler`（借鉴 dsh Definition 状态机，裁剪为本仓事件面）：seq 单调窗口、per-kind `match/start/update/publication`、三级发布节流（none / RAF×3 / immediate）、产出 `ConversationSnapshot { order, nodes(per-key source), timeline }`。
  - 文件域：`apps/crish-desktop/src/api/conversation/`（新）；`api/chat-bridge/handlers/*` 收敛为事件源适配。
- **D2 渲染契约**：`ChatNodeSeat` + `conversation.chat.node` keyed 注册表（挂 `services/view-registry`）；`.flowItem` 统一包裹 + `data-chat-node-key/kind/turn` 锚点；sibling-combinator 行距。
  - 文件域：`components/chat-message-list/`（Seat、注册表）、`components/chat-nodes/`（新，各 kind 渲染器）。
- **D3 虚拟化共存**：VSM 继续管窗口与高度缓存；Seat 行为 VSM 的行单元；折叠/展开失效高度缓存走 manager 既有接口。
- **D4 工具卡一代化**：以 24px 单行 DisclosureRow + 类型化展开卡（terminal/diff/read/search/IO）为新唯一实现；`ChatToolCallBlock/CompactToolRow/ModernToolCall` 三代迁净后删除。
- **D5 视觉 token**：保留本仓 token 名，补齐语义别名层（border-l1..l3/label-primary..caption/state-*）；宽度轴 `--chat-content-width`（760px 基准）+ 用户气泡 70% 轴；行距 `--chat-flow-gap` sibling 方案。
- **D6 滚动模型**：滚动所有权收敛进一个 `useChatFlowScroll`（账本判别 + followSig + 500ms 采样 + scrollend + 锚点补偿 + 会话级位置保存）；回底按钮零高度 sticky（z 序 composer 7 / 回底 8 / 菜单 9）。

## 三、任务单元（逻辑递进，问题同权）

### 阶段 A：数据层收敛（先立真相，后换皮）
- **A1** 会话事件窗口化：chat-bridge 事件源输出 `seq` 单调窗口（append/prepend/replace 变更语义）。验收：窗口重放（同事件序列）产出逐字节一致快照；乱序/缺窗回退 replace。
- **A2** `ConversationAssembler` + 核心 Definition（user / assistant / thought / tool-call / tool-result / turn-error / model-retry / compaction / injection / unknown）。验收：每个 Definition 纯函数单测覆盖 chunk 边界、落定、中断（合成前缀）、重试复位；发布节流单测（RAF×3 合帧、immediate 取消挂起帧）。
- **A3** echo→durable 原子换装：本地发送回显与持久 user 节点同帧互斥。验收：发送→回显→落定全链路无重复、无闪跳（组件测试 + 真机验收）。
- **A4** 退役 streamState 账本与 applyStream* merge：流式唯一经 A2 折叠。验收：全仓 grep 无 streamState/applyStreamTextToMessage 引用；相关测试改写后全绿。

### 阶段 B：渲染层统一（换渲染契约，逐 kind 迁移）
- **B1** ChatNodeSeat + flowItem + data 锚点 + kind 注册表；MessageVirtualizer 改为按 order 渲染 Seat。验收：行容器统一带 data-node-key/kind/turn；未知 kind 渲染兜底卡。
- **B2** 用户行/助手行迁移（保留现有 Markdown 阶梯与图片 gallery 合并逻辑）。验收：流式只重渲染目标行（per-key source 生效，性能测试不回退）；连续图片同 gallery 不重挂载。
- **B3** 工具行一代化（D4）+ 注入/压缩/错误/重试行迁移。验收：chat-tool-call 三代组件删除后全链路视觉验收通过；错误行折叠态显示失败首行。
- **B4** 思考行 + TurnProcess 过程折叠 + turn-tail 页脚。验收：折叠行 24px、运行态 summary 跟随最新行、prefers-reduced-motion 降级；展开状态会话内持久。
- **B5** prop drilling 收敛：列表层 props 打包对象化 + 渲染器经注册表自取依赖。验收：ChatMessageList→Virtualizer 透传 props ≤ 8 个分组对象。

### 阶段 C：滚动与跟随
- **C1** useChatFlowScroll（D6）替换 useScrollAnchor/useChatScroll 分散逻辑。验收：契约 e2e——历史分页锚点补偿（几何容差 2px）、流式中回甩不被 snap、惯性滚动不被 chrome 重渲染打断。
- **C2** 跨会话/跨标签滚动位置保存恢复。验收：切走再切回恢复锚点行位置；新会话落底。
- **C3** 回底按钮零高度 sticky 化，从 ChatStatusRibbons 迁出。验收：按钮不撑 scrollHeight；z 序栈生效。

### 阶段 D：视觉统一与验收
- **D1** token 补层 + 行距 rhythm + 用户气泡/宽度轴对齐（遵守 §13/§14/§19/§20：焦点 3%~10% 软灰、邻近圆角一致、无奇葩圆角）。
- **D2** 契约 e2e 套件落地（`tests/e2e/`，语义行断言、虚拟化无关）。
- **D3** design-qa 流程验收：真实宿主（npm run dev:workbench + 4000 Tauri MCP）双主题截图对比，P1/P2 分级清零后收口。

## 四、不变量与纪律

- 测试资产保护（§9）：现有 chat-* 测试随迁移改写保留，禁止删除了事。
- 提交纪律（§3）：仅主控提交、`commit --only` 限定路径；子代理改动留工作区。
- 验证纪律（§7/§7.1）：每阶段收口跑 `npm run check:desktop` + `npm run typecheck` + 相关单测；禁止 --no-verify；UI 验收只认 4000 Tauri MCP 真实宿主（§15/§16）。
- 反过度设计（§8）：不引入 dsh 的 cordis 服务内核与多 target 视图注册全量——按本仓事件面裁剪；不加虚拟化重写（VSM 保留）。

## 五、风险与对策

- **事件 seq 缺失**：本仓部分事件可能无单调 seq → A1 先补事件信封（桥接层派生 monotonic 序），不改 Rust 契约。
- **长会话性能回退**：折叠管线每帧全量 diff 的风险 → 沿用 dsh 的 dirty-context + upserts 增量模式，配 perf 测试锚定。
- **工具卡迁移长尾**：三代卡被各处引用（agent-card/InlineAgentTimeline 等）→ B3 按 kind 逐个切流，旧组件冻结新增引用后统一删除。
