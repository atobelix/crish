# 参考仓库对话流架构调研（deepseek-harness + codex-host）

> 调研人：主控。仓库版本：deepseek-harness `d347e70390`（master 最新）、codex-host `de24f83`（main 最新）。
> 结论：**deepseek-harness 是本仓对话流重构的第一参考**（完整线性对话流 UI + 数据管线）；codex-host 是宿主扩展，对话流本体属于 Codex Desktop，可借鉴的是注入手法、设置页设计语言与 design-qa 验收流程。

---

## 1. deepseek-harness 总体分层

```
SessionEventSource（seq 单调事件窗口：entries + revision + prepend/append/settle-assistant 变更）
  → ConversationNodeAssembler（增量状态机引擎，958 行）
      ├─ Event Registry：N 个业务 Definition（match/start/update/publication/buildViewNode）
      ├─ Location Index：turn/step 层级 + per-location 业务数据
      └─ View Registry：按 target（chat / trajectory）注册增量 ViewBuilder
  → ConversationSnapshot（不可变 order + 稳定 per-key observables）
  → ChatView（每个 node 一个 keyed Seat，独立订阅）
```

关键文件：
- `packages/client/ui-conversation/src/client/conversation/assembly.ts`（BoundConversation：发布节流）
- `packages/client/ui-conversation/src/client/conversation/assembler.ts`（增量引擎）
- `packages/client/ui-conversation/src/client/contract/conversation.ts`（Definition 契约）
- `packages/client/ui-chat/src/client/chat/`（渲染层 42 文件，总计约 5.6k 行）
- `packages/client/ui-chat/src/client/conversation-nodes/`（业务 Definition：assistant/message/tool/compaction/retry/turn-tail/turn-error 等）

## 2. 数据层要点

1. **事件溯源 + 增量折叠，无第二条真相路径**。每个业务节点是一个小状态机（`ConversationNodeDefinition`，conversation.ts:185-245）：`match` 按业务身份（如 `turn:step`）认领事件，`start/update` 折叠进 State，`publication` 声明发布节奏，`buildViewNode` 物化最终节点。流式 chunk（text-delta/reasoning-delta/tool-call-delta/block-start/block-end/usage）只是事件的一种，落定（`assistant/message`）与中断（合成前缀节点，fractional seq）走同一条 State 折叠路径（assistant.ts:93-163, 320-341）。**不存在「流式账本 + 权威快照 + 视图 merge」三套账**。
2. **发布节流三级**：`none` / `animation-frame` / `immediate`（conversation.ts:179）。BoundConversation 对 animation-frame 请求**跨三个 requestAnimationFrame** 再发布（assembly.ts:127-144），高频 token 流每三帧最多发布一次；immediate（如消息落定）直接取消挂起帧。
3. **视图快照增量 apply**：ViewBuilder 收到的只有「本次物化值变化的节点」（upserts），order 数组只在 append 时整体替换（contract/conversation.ts:253-274）。
4. **echo→durable 原子换装**（ChatView.tsx:139-157）：本地发送回显（submission echo）与持久 user 节点同帧互斥渲染——凡持久节点或队列里出现同一 rpcId，回显当帧隐藏，不重复、不闪跳。
5. **per-key observables**：ChatNodeStore.source(key) 给每个节点 key 一个稳定订阅源（snapshot.ts:16-41），渲染层每行只订阅自己。

## 3. 渲染层要点

1. **统一 Seat 包裹**：每个节点渲染进 `.flowItem` 容器，带 `data-chat-anchor-key / data-chat-flow-key / data-chat-flow-kind / data-chat-turn` 等锚点属性（ChatNodeSeat.tsx:126-137），滚动命中、导航、测试全部走 data 属性 O(1) 定位——与本仓 §7「data-* 无损映射」铁律同源。
2. **kind → renderer 注册表**（register-node-renderers.ts）：`conversation.chat.node` keyed slot，14 种节点类型（user/steering/context/system-prompt/assistant-step/command/manual-compaction/compaction/model-retry/turn-error/turn-max-tokens/turn-process/turn-tail/unknown），未知 kind 兜底 JSON 卡，永不静默丢弃。
3. **行间 rhythm 用 sibling combinator**（ChatView.module.css:49-52）：`.column > :not([hidden]):not(.flowItem:empty) ~ :not(...)` 相邻可见兄弟统一 `margin-top: var(--dsh-chat-flow-gap, 16px)`；隐藏/空行不产生间距；`.flowItem:empty { display:none }`。没有散落的 margin-bottom 链。
4. **过程折叠（TurnProcess）**：把一个 turn 的 reasoning + 工具调用折叠为一行「思考了一会儿 · N 个工具调用 · M 条消息」（TurnProcessNodeView.tsx），落定答案常显；展开状态存 per-session store。折叠可见性由 Seat 统一计算（ChatNodeSeat.tsx:69-98），行仍保留 DOM（`hidden until-found`，浏览器查找可揭示，searchable-hidden.ts）。
5. **思考行（ReasoningRow）**：24px 单行 DisclosureRow；运行中 summary 显示**最新一行**并右对齐跟随（`data-follow-end`，ReasoningRow.module.css:77-89），落定后显示首行；运行态一条 300px 扫光掠过（2.6s ease-out，prefers-reduced-motion 降级）。
6. **工具行（ToolRow）**：24px 单行 = [16px 图标] gap6 [13px 标题] gap8 [2×2 分隔点] gap8 [ellipsis 摘要]（ToolRow.module.css:1-7）；展开体按工具类型出类型化卡片（Terminal/Diff/Read/Search/Web/Code/IN-OUT 卡，全部由 ui-primitives 绘制）；错误行摘要换失败首行并染错误色；diff 行折叠态直接带 `+N -N` 统计；文件路径渲染为虚线下划线链接；hover 浮现 Inspect 药丸跳转 trajectory。
7. **turn-tail 页脚行**：复制/分支/用量图标行，非最新 turn hover 才显示（`data-actions-reveal="hover"`，TurnTailNodeView.tsx:41）；用量面板给出 ttft、tokens/s、精确 token 分账。
8. **用户气泡**：右对齐，`border-radius: 22px`，`padding: 10px 16px`，14px/22px，背景 `--dsw-specific-bubble`（浅色 deepseek-50、暗色 neutral-bluish-850）；最大宽度 = 内容宽轴的 70.2%（525/748，随列宽拖动自适应，MessageItem.module.css:17-41）；附件行在气泡上方右对齐，文件卡 240×64 radius 16 border 0.5px。
9. **Markdown 管线**：`MarkdownText` 来自 ui-primitives（流式感知）；连续 image block 合并进一个 gallery，key 取组内**首个 block 下标**，流式追加只增长组不重挂载（AssistantMarkdown.tsx:72-95）；宽表格用 container query（`.scroll { container-type: inline-size }` + `100cqw` breakout，ChatView.module.css:20）。
10. **运行状态行**：整 turn 级「Deep diving」品牌蓝 shimmer 文案 + 15 秒后出现 tabular-nums 计时（ChatView.tsx:167-201），不随每个工具/步骤闪烁。

## 4. 滚动架构（最值得抄的部分）

ChatView.tsx:19-696 全部围绕「跟随 vs 阅读」所有权：

- **reader 判别靠账本而非设备名**：每次程序化写 scrollTop 都同步记入 `observedTopRef`；scroll 事件里偏差 >0.5px 即判定读者输入（555-580）。wheel/touch/滚动条/键盘统一覆盖，程序化投递（含浏览器 shrink-clamp）不误判。
- **高频采样节流**：scroll 事件只置标志，500ms 间隔采样一次，`scrollend` 补最后一样（584-610）。
- **跟随签名 followSig**（346, 528-536）：只有 flow 头部签名（openState/firstSeq/lastKey/order.length/running/最后 steering/最后 submission）变化才重钉底部；at-bottom 的 chrome 重渲染不触发 snap，不打断惯性滚动。
- **prepend 锚点补偿**（503-521）：load-older 前记录 `PagingAnchor {key, top}`，新页落地后 `el.scrollTop += flowTop(row) - anchor.top` 恢复阅读位置。
- **跨会话滚动位置恢复**：`chatScroll.save/read` 以 `{anchorKey, anchorTop, scrollTop}` 保存，重挂载/换标签恢复而不是弹回底部（467-499）；由 apply.ts:135-141 按 SessionId 存 Map。
- **Turn 导航栏（TurnNavigator）**：右侧 rail 列出全部 turn + 预览；active 标记按阅读线命中（elementsFromPoint 优先、行扫描兜底，50-66）；跳未加载 turn 用 `loadThrough(seq)` 分页加载 + settle 落点（658-690）。
- **回底按钮零高度 sticky**（171-214）：sticky 槽 `height: 0; bottom: 16px`，按钮 `margin-top: -34px` 上移，不撑 scrollHeight；z-index 8 在 sticky composer（7）之上、@/菜单（9）之下；随 `--dsh-composer-height` 变量跟随 composer 增高。
- **动态高度跟随**：ResizeObserver 观察 flow 列 + composer seat，图片加载/工具展开引起的列高变化在 pinned 时自动跟随（628-643）。

## 5. 样式体系

- **三层 token**（ui-theme/src/styles/design-platform.css）：`static-*`（调色板）→ `alias-*`（语义：bg/border-l1..l4/label-primary..caption/state/button/interactive/markdown/scrollbar）→ `specific-*`（产品位：bubble/input/menu/sidebar）。暗色仅重指 alias（body[data-ds-dark-theme]），组件层永不写死色值。border 全系 0.5~4% 黑白透明度极轻。
- **字号轴**：`--dsh-content-font-delta`（正文字号偏好增量）+ `--dsh-content-font-size-secondary`（次级 13px 档）；所有行高写成 `calc(22px + delta)`，设置页改字号全局等比（连 SVG 图标 14px 也随 delta 缩放，MessageItem.module.css:92-97）。
- **宽度轴**：`--dsh-chat-content-width`（默认 748px）居中列；窄视口下 transcript 恒比 composer 窄 32px（`--dsh-composer-side-clearance`）；列宽可拖拽并持久化（ConversationRoot.tsx:213-235）。
- **布局轴变量由 ResizeObserver 发布**：`--dsh-composer-height` / `--dsh-conversation-viewport-height` / `--dsh-conversation-column-width` 都由观察器写回 CSS 变量（ConversationRoot.tsx:163-178），组件只消费变量，不各自量高度。
- **corner-shape: round 渐进增强**、`color-mix`、container query 等 CSS 新特性均有降级。

## 6. 质量门：交互契约 e2e

`apps/web/tests/chat-scroll-contract.e2e.ts`：「deliberately virtualizer-neutral」——断言语义行位置、底部所有权、交互状态与真实滚动宿主，而非 spacer DOM 结构；场景覆盖历史分页、live 工具流、跨会话恢复、输入冲突、rail 导航、**流式进行中回甩阅读**；几何容差 2px。另有 `composer-tab-geometry.e2e.ts`、`chat-continuous-conversation.e2e.ts` 等 86 个断言组。

## 7. codex-host 可借鉴点

1. **注入式适配现有宿主**：`versioned-renderer-adapter.ts`（1227 行）按宿主版本探测 DOM 契约（`[data-codex-composer-root]`、textarea/contenteditable 选择器族），隐藏原生控件、挂载自有控件（NativeControlState 保存原 hidden/aria 状态以便还原）。
2. **设置页设计语言**（settings/shell.css，2332 行）：`light-dark()` 单行双主题 token；13px 基准字、9% 边框、7% 分隔线、5% hover —— 与 Codex Desktop 对齐的「更密、更静」层级（更少同强度描边、行高 52px、非选中动作 hover 才出现）。
3. **design-qa.md 验收方法**：以目标截图为视觉锚点，P1/P2/P3 分级逐轮修复（尺寸过大→边框过多→层级噪声），同尺寸前后对比 + 双主题留档 + 交互渲染验证后才标 passed。这套流程可直接用于本仓对话流重构的视觉验收。

## 8. 对本仓的适配性判断

- dsh 的 Definition 状态机可裁剪落地：本仓 chat-bridge 已有 eventParser/handlers 分层，缺的是「seq 单调窗口 + per-kind 状态机折叠 + 三级发布节流 + 不可变 order」这四件事。
- dsh 无虚拟化（行数依赖 hidden/empty 不占距 + 浏览器原生滚动），本仓有自研 VSM 虚拟化（长会话需要），两者可并存：虚拟化管窗口，契约测试断言语义行而非 spacer。
- 本仓已有 `services/view-registry`（SlotOutlet）与 `workspace.chat.stream` slot，node-kind 注册表可直接建在其上。
