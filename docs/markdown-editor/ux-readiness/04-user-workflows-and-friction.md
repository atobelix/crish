# 04 · 日常工作流与摩擦分析（User Workflows & Friction）

> **类型**：可用性分析（Usability），**不是**功能清单打勾表
> **日期**：2026-08-03
> **产品定位**：Markdown 原生 + 块级 UX；日常写作（笔记 / 技术文档 / 研究记录）。**不是** Notion Database / CRM。
> **证据来源**：
> - 运行时：`reference/chat-composer-component/js/markdown-editor/*`（真实现）
> - 契约：`packages/conex-mdx`（类型 + stub；`mount` 尚未运行时）
> - 规格：`reference/.../docs/markdown-editor/`（愿景、CROSSCUTTING、feature-catalog、行源码、表、IME、导出）
> **诚实边界**：以下「当前摩擦」按**架构与代码可推断**的用户感知撰写；未做受控可用性实验室。标注「推断」处可被实测推翻。

## 0. 读法与严重度定义

### 0.1 本文回答什么

用户每天反复做的 **15 条主路径**，每条都拆成：

| 维度 | 含义 |
|------|------|
| **理想路径** | 好用时用户「脑子里一步」就能完成 |
| **当前摩擦** | 架构/实现导致的卡顿、惊讶、多步、不可靠 |
| **严重度** | 见下表 |
| **设计修复方向** | 交互/信息架构层解法（**不写代码**；模块落点可指目录） |

本文**不**争论「是否已有某 API」，只争论：**做这件事时手感像不像一流写作工具**。

### 0.2 严重度标尺（用户时间损失）

| 级 | 名称 | 用户感知 | 修复优先级暗示 |
|----|------|----------|----------------|
| **S0** | 阻断 | 主路径做不成，或数据明显损坏/丢失 | 立刻 |
| **S1** | 高频痛 | 每天会碰到，每次都要绕路或重做 | U 波次前列 |
| **S2** | 中频摩擦 | 场景常见但可忍受；专业用户会抱怨 | 同能力面一并修 |
| **S3** | 边角 | 低频或仅专家路径 | 可后置 |
| **S4** | 打磨 | 正确但不优雅 | 动效/文案/密度 |

### 0.3 架构快照（摩擦推断的公共前提）

理解摩擦必须先看清**当前交互模型**，否则会误判「缺功能」：

```
扁平 Block[] + indent
  └─ 未聚焦块：精致 readView（渲染）
  └─ 聚焦块：editView（行源码 / 单块 contenteditable 或 fence 源）
  └─ 事务：model.update/insert/remove + 全量 clone 历史栈
  └─ 入口：/ 与 、（slash）· Ctrl+P（命令面板）· 快捷键 · 行首前缀 promote
  └─ 序列化真相：Markdown（GFM + Conex 扩展）
  └─ 硬政策：不做预览/源码双 Tab 硬切换；禁页顶永久格式栏
```

**核心张力（贯穿全文）**：

1. **块边界 contenteditable** 带来精致阅读与 DnD，但天然弱于「跨段连续选区 / 浏览器原生粘贴语义」。
2. **行源码聚焦**（Typora 气质）与「所见即所得折叠标记」之间，用户心智需要一贯教育。
3. **`editor.js` 编排巨石 + 分模块卫星** 已部分拆出（IME / demote / promote / height-lock / table / media），但协调一致性仍是摩擦之源。
4. **`@conex/mdx` 仍是脚手架**：桌面宿主尚未形成稳定「打开文档 → 写 → 导出」产品闭环时，部分工作流只能在 reference demo 上体验。

## 1. 产品「好用」的一句话

> **打开即能写，写时像排版好的文档，结构变换不打断思路，粘贴进来不脏，离开时 MD 给同事不丢结构。**

日常写作工具的「好用」不是功能点数，而是：

- **启动摩擦 ≈ 0**（光标已在可写处）
- **格式摩擦 ≈ 肌肉记忆**（快捷键 / `/` / 前缀，而不是找菜单）
- **认知摩擦 ≈ 0**（读态与写态不「换产品」）
- **恢复摩擦 ≈ 0**（撤销、导出、只读预览可信）

Conex MD 的承诺是：**Notion 式块操作感 + Typora 式行源码 + GFM 可往返**，且**不做**数据库。
若某条工作流逼用户「先学会块模型才能写一段话」，则该工作流失败——与功能是否存在无关。

### WF-01 · 打开写一段

#### 场景与意图

用户从对话 Artifact / 笔记列表 / 空白文档进入编辑器，目标是：**立刻打字**，不配置、不选模式、不找「开始写作」。

#### 理想路径

1. 打开文档 → 看到精致排版（或干净空白页与浅灰 placeholder）。
2. 光标已在首段或上次位置；键盘直接输入中文/英文。
3. 输入过程中段落保持「像正文」，不闪、不跳、不弹格式栏。
4. 停顿后 autosave 静默发生；无「已保存」噪声（除非首次教育）。

步数感：**0 次点击 + 1 次击键 = 在写**。

#### 当前摩擦（推断）

| 摩擦点 | 机制 | 用户感知 |
|--------|------|----------|
| **挂载点分裂** | 真运行时在 reference IIFE；`@conex/mdx.mount` 仍 stub throw | 桌面宿主若误接包 API → 白屏/异常，写作入口不稳 |
| **焦点不默认** | 块模型常要求「点某块」才 enterEdit；空文档若只有空段落也可能要一次点击 | 「为什么不能直接打字？」 |
| **首屏精致 vs 空文档** | 读态依赖 parse 出的块；空文档 placeholder 与高度锁若未统一 | 空白页不像「纸」，像未加载控件 |
| **宿主壳层抢焦** | Notebook 浮层 pin/Esc/顶栏 与编辑器 Esc 分层需对齐 | 第一次 Esc 关错层，挫败 |
| **onChange 防抖** | autosave 300–800ms 类设计合理，但若 onChange 触发宿主重渲染整树 | 打字卡顿，像输入法坏了 |

架构证据：产品愿景 G-E1/G-E4 要求块边界编辑 + debounce 写回；CROSSCUTTING D2 未聚焦=read / 聚焦=edit；集成契约要求 host 只接 `initialMarkdown` + `onChange`。

#### 严重度

**S1**（入口失败则所有后续工作流无意义；桌面未闭环时甚至 S0）。

#### 设计修复方向

1. **默认焦点契约**：`mount` 后若 `viewOnly=false` 且文档有且仅有空段落 → 自动 enterEdit 首块并 `focus()`，无需点击。
2. **空文档纸感**：统一 min-height、行高、placeholder「输入 `/` 或 `、` 插入，或直接开写」——教育放在 placeholder，不弹气泡。
3. **宿主薄适配**：Desktop 只接 ports + lifecycle；禁止 host 每次 onChange 全量 re-mount。
4. **双运行时消歧**：文档与产品 UI 明确「生产写作用哪条运行时」；脚手架期禁止静默 fallback 到 stub。
5. **上次光标**：同文档再开恢复 blockId + offset（可后置 S2，但空文档默认焦是 P0）。

#### 验收体感

新人第一次打开空白笔记，**不看帮助**也能在 1 秒内开始写中文句子；关再开内容还在。

### WF-02 · 标题层级调整

#### 场景与意图

写技术文档时频繁：H2→H3、段落变标题、标题降回正文、连续改层级。意图是**结构大纲可塑**，不是「调样式」。

#### 理想路径（多入口等价）

- **前缀**：行首 `## ` 空格 promote 为 H2。
- **退格阶梯**：空标题 Backspace → 降级 H3→H2→H1→段落（不一次删整块）。
- **Slash / 、**：`、标题` / `/h2` 转类型。
- **快捷键（可选）**：`Mod+Alt+1..6` 或命令面板「设为标题 2」。
- 失焦后立刻呈现对应字阶；**文档高度不因 `##` 灰标显隐而跳**。

#### 当前摩擦（推断）

| 摩擦点 | 机制 | 用户感知 |
|--------|------|----------|
| **行源码显隐** | 聚焦显示 `##`，失焦隐藏为渲染标题 | 可接受；但高度锁不稳时会「跳一下」 |
| **promote 规则严** | 必须 `#`+空格；`#Title` 不提升 | 用户以为坏了；缺即时反馈 |
| **demote 与 re-enterEdit** | 降级后 `enterEdit` 重建表面 | 偶发 caret 丢到行首/行尾 |
| **无「只改 level 不碰正文」的明显手柄** | 依赖源码 `#` 数量或 slash 转类型 | 中文用户不习惯数 `#` |
| **大纲侧栏缺失** | TOC 是块而非始终可见大纲 | 调层级时看不到全局结构后果 |
| **有序列表/标题混淆** | `1. ` promote 为列表而非标题 | 预期错位（规格正确，教育不足） |

证据：`edit/promote.js` 完成表；`edit/demotion.js` LADDER_GOLD（H3 空：gap→H2→H1→paragraph）；line-source 聚焦灰标。

#### 严重度

**S1**（文档写作高频；阶梯错误会摧毁信任）。

#### 设计修复方向

1. **保持退格阶梯金标准**，并在 UI 上让灰标 `###` 可点选减号式降级（可选弱 affordance，非页顶工具栏）。
2. **promote 失败反馈**：输入 `#` 无空格时灰标「松散」态，提示「空格确认标题」——不 toast 轰炸。
3. **命令面板条目**：「升/降一级标题」作用于当前块，服务不记 `#` 的用户。
4. **与 TOC 联动**：改 level 后 TOC 块刷新；若有侧栏大纲则高亮当前标题。
5. **禁止**页顶 Heading 下拉永久条（D16）；层级调整入口必须是上下文型。

#### 验收体感

把三级标题连续 Backspace 降成正文再 `# ` 升回，全程不丢字、不整块蒸发、不整页闪白。

### WF-03 · 列表连续输入与退出

#### 场景与意图

记步骤、写要点：连续 Enter 出新项，空项再 Enter 退出列表回正文，Tab 缩进，Shift+Tab 反缩进。

#### 理想路径

1. `- ` / `* ` / `1. ` 或 `/无序` 进入列表。
2. Enter → 同级新项，标记自动出现。
3. 空项 Enter → **退出列表**成普通段落（不留下幽灵 `*`）。
4. Tab / Shift+Tab 改 indent（扁平模型下改 `indent`）。
5. 任务列表 checkbox 在读态可点，写态不破坏组字。

#### 当前摩擦（推断）

| 摩擦点 | 机制 | 用户感知 |
|--------|------|----------|
| **扁平 item vs 真树 list** | 规格曾有 `bullet_list` 容器树，运行时是 `bullet_item` + indent | 序列化/嵌套边界与心智可能不一致 |
| **软标记 `·` vs 源 `*`** | 读态圆点、聚焦还原 `*` | 第一次困惑「圆点哪去了」；属行源码教育问题 |
| **空项退出路径** | demote：空 bullet → strip-gap → strip-mark→paragraph；与「空项 Enter 退出」是两条路径 | 用户习惯 Typora/Notion 的 **Enter 退出**；若只实现 Backspace 退出则违和 |
| **有序编号显示** | 源码常写 `1.`，读态应重编号 | 编辑时全是 `1.` 可能不安（GFM 正常） |
| **嵌套仅 indent** | 无 drop-into（D7） | 拖拽无法「放进子列表」，只能 Tab |
| **任务项 checked 与 demote** | 降级丢 checked | 可接受，但需不误触 |

证据：keyboard-map「空项 Enter 退出列表」；demotion 列表 strip-mark；CROSSCUTTING D1 flat+indent、D7 无 drop-into。

#### 严重度

**S1**（列表是笔记第一公民）。

#### 设计修复方向

1. **统一退出语义矩阵**（必须写进键盘地图并实现一致）：
   - 空项 **Enter** → 退出列表为 paragraph
   - 空项 **Backspace** → 先去标记再 merge（阶梯）
   - 非空 Enter → 新项
2. **indent 视觉**：左侧缩进轨要稳定，禁止 Tab 时整行重挂导致跳动。
3. **连续输入性能**：新项 insert 走局部 reconcile，禁止 fullRender。
4. **教育**：placeholder「空项再按 Enter 结束列表」仅在列表空项出现一次级文案。
5. **不做**自定义 bullet 皮肤商店；序列化统一 `-`。

#### 验收体感

写完 8 条步骤，空项 Enter 干净回到正文；Tab 两层子步骤；导出 MD 同事用任意渲染器都能看。

### WF-04 · 跨段复制粘贴

#### 场景与意图

选中「从第二段中间到第四段中间」的内容，Ctrl+C / Ctrl+V 到另一处或另一文档。这是**所有编辑器的氧气**。

#### 理想路径

1. 鼠标拖蓝或 Shift+方向键形成跨段选区。
2. 复制得到：**内部块结构** + `text/plain` MD/纯文本 + 可选 `text/html` 消毒子集。
3. 粘贴到段落中间：首尾与上下文合并，中间块完整插入。
4. 粘贴到空块：直接展开为多块。
5. 一次撤销整次粘贴。

#### 当前摩擦（推断）——**当前最大可用性债之一**

| 摩擦点 | 机制 | 用户感知 |
|--------|------|----------|
| **块边界 CE** | 每块独立 edit surface，浏览器无法原生跨 contenteditable 连续选区 | 拖蓝一出块就断；只能块内选 |
| **规格已承认降级** | 03-line-renderer：跨块拖蓝 v1 可变为块选，非连续文本选 | 「为什么选不了两段？」 |
| **复制载荷不完整** | 缺统一 clipboard writer（plain MD / 内部 JSON / html）时，跨应用粘贴只剩纯文本 | 结构丢失（标题变正文、列表变行） |
| **粘贴无 html→blocks** | 块内 paste 多走 `text/plain`；HTML 路径不完整 | 从本编辑器 A 处到 B 处都可能扁平成一段 |
| **多块删除** | 无块选时无法一次删三段 | 只能逐块 Backspace |

证据：`03-line-renderer.md` §10 选区模型；feature-catalog 01 剪贴板条目；`06-clipboard-undo-find` 预留专项；model 有单块 CRUD，无「选区 range 事务」一等 API 暴露给 UI。

#### 严重度

**S0–S1**（跨段是日常写作刚需；缺失会逼用户退回纯源码编辑器）。

#### 设计修复方向

1. **明确产品选择（二选一，禁止半吊子）**：
   - **方案 A（推荐 v1）**：跨块拖选 = **块选**（高亮整块），复制序列化为 MD 多块；粘贴 = parse 多块插入。接受「不能选半段+整段+半段」直到 v1.1。
   - **方案 B（重）**：虚拟连续选区（自研 range）——成本高，见 02 专文。
2. **无论 A/B**：必须定义 `clipboard` 三通道：`text/plain`（MD）、内部 `application/x-conex-mdx-blocks`、消毒 `text/html`。
3. **块选 chrome**：左边 gutter 轻高亮，**禁止**厚蓝框手术台（A34）。
4. **粘贴事务**：单 history 条目；失败 partial 要可撤销。
5. **教育**：若选方案 A，首次跨块选择时不气泡，但复制后粘贴结果必须「看起来对」。

#### 验收体感

从文档中部拖过三个标题段落，粘到文末，结构仍在；Ctrl+Z 一次全部收回。

### WF-05 · 从网页 / Word 粘贴

#### 场景与意图

调研写作：浏览器复制一段带标题/列表/链接/加粗的内容，或从 Word/WPS 贴入。期望**结构化进入**，不是 HTML 垃圾或全纯文本。

#### 理想路径

1. Ctrl+V。
2. 管道：`text/html` → 消毒 → 语义映射（h1–h6、ul/ol、a、strong/em、code、table 粗映射）→ blocks；若无 html 则 `text/plain` → MD 启发式 / 纯段。
3. 未知样式（字体色、span class）**丢弃**且不报错刷屏。
4. 危险标签 script/iframe 永不进入。
5. 大粘贴（>N 块）批量 commit，stagger 入场 ≤5（A25）。

#### 当前摩擦（推断）

| 摩擦点 | 机制 | 用户感知 |
|--------|------|----------|
| **图片 paste 有、富文本弱** | `media/drop-paste.js` 专注 image/*；通用 HTML→blocks 未见对等主路径 | 贴网页变纯文本墙或残留怪异空白 |
| **Word 的脏 HTML** | `mso-` 样式、条件注释、嵌套 span | 即使用 html 解析也易炸；需专用清洗档 |
| **链接与加粗丢失** | 行内 marks 若靠 htmlToInlineMd 不完整 | 「我的加粗呢？」 |
| **表格从 Excel** | 表内 TSV 路径相对成熟；整表从网页贴入另一路径 | Excel 凑合，网页表翻车 |
| **静默有损无说明** | 规格要求导入不静默丢关键结构 | 用户不知丢了什么 |

证据：media drop-paste 图片端口；table clipboard-tsv；feature-catalog 05 IO「导入不静默丢数据」；安全基线禁 raw script。

#### 严重度

**S1**（研究/技术写作极高频）。

#### 设计修复方向

1. **单一 PastePipeline**（模块：`edit/paste-pipeline` 类职责）：优先级 `image files` > `internal blocks` > `text/html` > `text/plain`。
2. **HTML 映射表白名单**：只映射语义标签；其余扁平为 text。
3. **有损提示**：仅当丢表/丢图时轻 toast「已粘贴为纯文本结构（N 项未保留）」；普通加粗丢失可不提示。
4. **Word 档**：检测 `xmlns:o` / `mso-` → 走强化清洗；不承诺像素级版式。
5. **永不**为贴 Word 引入永久页顶「粘贴选项」条；可用一次性小胶囊「保留文本 | 保留结构」。

#### 验收体感

### WF-11 · 撤销 / 重做

#### 场景与意图

写错了、粘多了、误降级标题 → Ctrl+Z / Ctrl+Shift+Z 回到心理安全点。

#### 理想路径

1. 键入合并为合理粒度（按词/按停顿/按 IME end），不是每字母一栈。
2. 结构操作（插表、合并单元格、slash 转块）一步一栈。
3. 撤销后 **选区/焦点** 尽量恢复。
4. 重做栈在新编辑后清空（标准）。
5. AI 写回若有：整次替换一步撤销。

#### 当前摩擦（推断）

| 摩擦点 | 机制 | 用户感知 |
|--------|------|----------|
| **全量 cloneDoc 栈** | model pushHistory 克隆整份 Doc | 中大文档撤销慢、内存涨 |
| **粒度** | updateBlock 常 addToHistory:true；输入路径若每键 push | Z 要按几十次才回退一句 |
| **撤销时 exitEdit + fullRender** | editor 对 Mod+Z：exitEdit 后 undo 再 fullRender | 闪屏、失焦、caret 丢 |
| **IME** | composition 中应 addToHistory:false；end 后一次提交 | 组字中若入栈，Z 拆汉字 |
| **表与图** | 多模块自行 update，历史边界不一致 | 撤销表结构与单元格文本体验割裂 |

证据：`model.js` undo/redo MAX_HIST=100；editor keydown Ctrl+Z 分支；CROSSCUTTING 中文 IME 条款；feature-catalog 05 AI 可撤销。

#### 严重度

**S1**（信任底线）；fullRender 闪屏在长文为 **S1 性能痛**。

#### 设计修复方向

1. **事务合并**：输入用 mergeKey（时间窗 + 同 blockId + 非结构）；结构变更强制新事务。
2. **撤销呈现**：优先局部 reconcile + 恢复 activeId；禁止无脑 fullRender（除非 setDoc）。
3. **选择栈深度与内存**：大文档差分 history（后置）或降低 clone 频率。
4. **IME**：硬挡 composition 入栈；compositionend 一次 commit。
5. **用户可见**：不需要做复杂时间旅行 UI；可靠的 Z/Y 优于花哨历史面板（历史面板 P2）。

#### 验收体感

写一段中文 → 加粗 → 插列表 → 连按 Z 按「心理步骤」回退；无整页白闪。

### WF-12 · 长文滚动与焦点不跳

#### 场景与意图

#### 理想路径

1. 滚动流畅；块 hover 把手不改 gutter 宽度（A07）。
2. enterEdit / exitEdit **高度锁**（height-lock）→ 零 CLS。

| **fullRender 路径** | undo、setMarkdown、部分 reconcile 失败回退 | 滚动位置归零 |

1. **所有 enter/leave 表面强制 height-lock + scrollPreserve**。
2. **禁止**用 margin/height 动画块切换；只 opacity/transform。
3. **滚动容器单一事实**：文档 scroller API 内部化，浮层跟它听 scroll。
4. **性能预算**：输入路径禁止全文 innerHTML；>N 块开启窗虚拟化。
5. **焦点环**仅控件（把手/按钮），不给整块行手术台描边。

#### 验收体感

在长文中部点标题编辑再点别处，页面不「喘」；闭眼滚动无布局闪烁。

| **导出入口弱** | getMarkdown 有；产品级「分享」按钮看宿主 | 用户只会全选复制，又撞 WF-04 跨段问题 |
| **pure-gfm 模式** | 规格 D13 有 mode；UI 是否可达 | 专家知道、新人不知 |
| **blob 图** | 见 WF-09 | 邮件里裂图 |
| **往返测试** | roundtrip 测试存在但不等于「人类可读差异为 0」 | 空格/列表标记统一导致 diff 吓人 |

证据：serialize 主路径；D4/D13；feature-catalog 05 F-IO；conex-mdx onChange 默认真源 MD。

#### 严重度

**S1**（协作边界）；裂图 + 合并表静默损坏为 **S0**。

#### 设计修复方向

1. **导出菜单三档**（命令面板即可，无页顶栏）：
   - 复制 Markdown（Conex）
   - 复制兼容 GFM（降级）
   - 下载 .md
2. **降级报告**：兼容模式若拆合并表/去 wiki，摘要「3 处已降级」。
3. **图检查**：导出前扫描 `blob:` / `local-only` → 阻断并提示先上传。
4. **默认文件即 MD**：Notebook 保存不写私有 JSON 为主（可并行 sidecar，但不替代）。
5. **不做**默认导出 PDF/Word 内核；交给宿主适配器。

#### 验收体感

导出丢进 GitHub PR，同事渲染正常；TOC/callout 降级可预期且有说明。

### WF-15 · 只读预览

#### 场景与意图

审阅 AI 生成报告、分享只读链接、会议投屏：能滚动、能点链接/TOC/任务？视策略，**不能**误改。

#### 理想路径

1. `viewOnly=true`：无把手、无 slash、无编辑光标；仍有精致渲染。
2. 链接可点；任务勾选是否可点由宿主策略（纯审阅关，清单协作开）。
3. 代码可复制；表可横向滚不可改。
4. 与编辑态**同一套 read 渲染**，不是另一套 CSS 皮肤。
5. 切回编辑无闪、不丢滚动位置。

#### 当前摩擦（推断）

| 摩擦点 | 机制 | 用户感知 |
|--------|------|----------|
| **viewOnly 分支** | editor 多处 `if (viewOnly)` 降级 onChange/chrome | 遗漏分支可能仍可 focus contenteditable |
| **任务勾选** | 读态 checkbox | 只读模式下误允许切换 = 数据脏 |
| **复制** | 只读仍应允许选文本复制 | 若 user-select:none 过度则伤审阅 |
| **与「预览 Tab」混淆** | 产品禁双 Tab；只读是能力位不是模式皮肤 | 文档需避免叫「预览模式」挑起硬切换联想 |
| **宿主** | Artifact 打开默认编辑还是只读 | AI 报告场景默认只读更安全？产品决策 |

证据：MountOptions.viewOnly；root `is-view-only`；text-read 对 checkbox disabled；CROSSCUTTING D3 禁预览/源码硬切换。

#### 严重度

**S2** 一般；在「AI 产物审阅」主画像下 **S1**。

#### 设计修复方向

1. **能力位矩阵**：`canEdit / canToggleTask / canCopy / canFollowLink` 拆开，不只一个 bool。
2. **视觉**：只读不增加水印式大字「只读」除非宿主要；可靠禁编比贴纸重要。
3. **命名**：产品文案用「查看」而非「预览/源码」。
4. **同一 render 管线**，仅关闭交互层。
5. **Esc**：只读下 Esc 关面板，不进入 exitEdit 怪状态。

#### 验收体感

投屏打开报告，观众看到精致排版；演示者误触键盘不会改掉标题。

## 4. 「好用」原则 10 条

以下原则用于评审任何 PR / 交互稿：**违反任一条，即使功能点 +1 也算可用性失败。**

### P1 · 打开即写（Zero setup）

不选模式、不点「编辑」、不先开 slash。空文档自动可输入。任何「先点一下块」都必须有默认焦点兜底。

### P2 · 读写真同构（One document feel）

未聚焦精致、聚焦可编，但**不换皮肤体系**。禁止预览 Tab / 源码 Tab 成为主路径。行源码灰标是细节，不是第二产品。

### P3 · Markdown 诚实（Honest serialization）

屏幕上结构 = 导出大致结构。扩展语法要么可往返，要么导出时明示降级。禁止 blob 图假装已保存。

### P4 · 块是手段不是宗教（Blocks serve typing）

用户在想句子，不是在想 BlockId。块把手、DnD、slash 服务于结构，**不得**强迫用户为打字先管理块。

### P5 · 中文第一输入法（IME-first）

所有热路径 composition 安全。`、` 与 `/` 同权。快捷键与 Windows 输入法冲突表必须测。

### P6 · 肌肉记忆分层（Progressive power）

- 新手：直接打字 + 空段 `/`
- 熟手：前缀 promote、快捷键 marks
- 专家：Ctrl+P、GFM 兼容导出、源码级 fence
三层互不锁死；上层永不删除下层能力。

### P7 · 结构可逆（Reversible structure）

标题/列表/引用的进入与退出是**阶梯**，不是陷阱。误操作靠 Backspace/Enter/Z 可回，不靠「删除块再重做」。

### P8 · 布局冷静（Calm layout）

无激活行厚框、无 hover 抬升阴影、无页顶永久格式栏。高度锁优先于动画。浮层不顶开正文。

### P9 · 粘贴可预期（Predictable paste）

同一套 PastePipeline；图/内部块/HTML/纯文本优先级固定。有损可提示，静默吞结构不可接受。

### P10 · 撤销是心理时光机（Undo is trust）

粒度贴合意图；撤销不闪整页；AI/粘贴/结构变更可整步收回。不可靠的撤销比没有更糟。

## 5. 反模式 10 条（禁止再引入）

### A1 · 功能堆砌当好用

「合并单元格做了」但导出裂表、失败无中文原因 → **不算**交付。好用是闭环，不是勾选。

### A2 · 预览 / 源码硬切换回潮

任何 PR 若加回主 UI 双 Tab「预览|Markdown」，直接否决（D3）。查看源码只能是高级抽屉/命令，不得默认。

### A3 · 页顶 Word 式格式栏

永久 Bold/Italic/H1 下拉违背 D16 与 Composer 冷静。选区条默认关；需要时用快捷键与命令面板。

### A4 · 激活行手术台描边

`.is-active { border: 1px solid; background: #f5f5f5 }` 类样式是阅读杀手。焦点用 caret + 弱把手。

### A5 · 代码双壳

上 Prism 下 textarea 并列。用户立刻感到「玩具 demo」。单卡片互斥状态是底线。

### A6 · 组字中拆块

composition 期间 promote/demote/leave/slash/历史入栈。中文用户一天内就会卸载产品。

### A7 · 静默假持久化

object URL 图、未 flush 的 autosave、只写内存的 onChange，对用户说「已保存」。数据诚实 > 演示漂亮。

### A8 · 跨段无能却宣传「Notion 级」

没有块选/多块剪贴板时，对外叙事应收敛为「块内精致编辑」，避免过度承诺导致信任崩盘。

### A9 · 上帝文件续命

新逻辑继续塞进 `editor.js` 3000+ 行。后果是 IME、粘贴、表、撤销互相踩踏——**直接制造摩擦**。新路径进 `edit/*` `inline/*` `ui/*`。

### A10 · 为 Database 开后门

属性列、看板、关联页、多维表。偏离 MD 日常写作定位，拖垮序列化与心智。扩展层可挂研究块，但**永不**把 CRM 当 P0。

## 6. 信息架构：Slash · Ctrl+P · 快捷键 · 源码 何时用哪个

四种入口**不是**重复建设，而是**不同认知负担与上下文**的工具。混用规则必须稳定，否则用户会问「到底用哪个？」。

### 6.1 总览决策表

| 用户意图 | 首选入口 | 次选 | 不要用 |
|----------|----------|------|--------|
| 空段插入新结构（标题/表/代码/图） | **Slash `/` 或 `、`** | Ctrl+P「插入…」 | 源码手写（可但非首选） |
| 把当前块**转换成**另一类型 | Slash（转） / 行首前缀 | Ctrl+P「设为…」 | 删除重插 |
| 行内加粗/斜体/代码 | **快捷键** | 源码 `**` `` ` `` | Slash（太重） |
| 插入/编辑链接 | **Mod+K** | 源码 `[ ]( )` / 命令面板 | 页顶栏 |
| 改代码语言、复制代码、表对齐 | **块内 chrome / 右键** | Ctrl+P | Slash 刷屏 |
| 跳转标题、导出、只读切换、AI 动作 | **Ctrl+P** | 宿主菜单 | Slash（应保持「插入」心智） |
| 精确控制 fence/HTML 转义/怪异 GFM | **行源码 / 代码源** | 纯 MD 文件外编 | 假装 GUI 全能 |
| 列表缩进、移块 | **Tab / Alt+↑↓** | 把手 DnD | 命令面板（可有但慢） |
| 撤销 | **Mod+Z** | — | 历史侧栏（非 P0） |

### 6.2 Slash / 顿号 — 「在光标处插入或转换」

**心智模型**：我在**写作光标**上，需要一个块级变化。

| 适用 | 不适用 |
|------|--------|
| 空段或行首插入 | 全局导出、主题切换 |
| 过滤式发现「表格」「任务」「目录」 | 行内 marks 主路径 |
| 中文用户用 `、` 少切英文 | 替代所有快捷键 |

**规则**：

- 触发域：空段 / 规则允许的行首；避免句中 `/` 误开（路径、正则）。
- 成功后面板关、触发符消、焦点留在新块。
- 无结果：「未找到相关命令」+ 固定次文案（ux/slash-palette）。
- **不**承担应用级命令（设置、导出）——那些进 Ctrl+P。

### 6.3 Ctrl+P（命令面板）— 「我不知道点哪，或要全局动作」

**心智模型**：命令行式发现；**与光标弱绑定或显式声明目标**。

| 适用 | 不适用 |
|------|--------|
| 导出 MD / 兼容 GFM | 每敲一个字的格式 |
| 跳转到标题… | 替代 Enter 换行 |
| AI 改写/总结（有 port 时） | 空段插段落（slash 更快） |
| 切换 viewOnly（若宿主暴露） | 与 slash 列表 100% 重复无分组 |

**规则**：

- 打开键：Ctrl/Cmd+P；可同时 Ctrl+Shift+P（VS 气质）但不强制双面板。
- 分组：导航 | 插入 | 格式 | 导出 | AI（无 port 整组隐藏）。
- 模糊：中文 title + 英文 id/aliases（command-palette 已具备方向）。
- **插入类命令**执行后应表现得像 slash：在当前块上下文插入，而不是文档末尾乱插。

### 6.4 快捷键 — 「高频肌肉记忆」

**心智模型**：我不看 UI，手已经按下。

| 类别 | 示例 | 约束 |
|------|------|------|
| 行内 | Mod+B/I/` ，Mod+K | IME composing 时忽略 |
| 历史 | Mod+Z / Mod+Shift+Z | 见 WF-11 |
| 结构 | Tab 缩进、Alt+↑↓ 移块、Enter/Backspace 阶梯 | 与列表/表上下文抢键时表优先在表内 |
| 明确不做 | Mod+S 独立保存、Mod+/ 注释 | 与 autosave、slash 冲突 |

**规则**：快捷键必须在命令面板可搜到（可发现性）；不必贴满 tooltip 墙。

### 6.5 源码（行源码 / fence / 非硬切换）— 「精确与可携」

**心智模型**：这一行/块的 **Markdown 真相**暂时可见，用来精确控制或排查。

| 适用 | 不适用 |
|------|--------|
| 标题 `#` 数量、列表标记、fence 语言 | 整页 raw 编辑当默认 |
| 怪异表格对齐、转义 | 日常加粗（快捷键更快） |
| 用户从 Obsidian 带来的源码肌肉记忆 | 替代只读精致阅读 |

**规则**：

- **聚焦行**显示结构前缀 + 正文 marks 策略（见 03）。
- **代码块**聚焦 = 完整 fence，不是平行预览。
- **高级「查看全文源码」**若做：抽屉/命令，确认后可复制；默认不进主 IA。
- 源码修改提交必须经 parse，禁止把非法 MD 永久弄脏 Doc 而不提示。

### 6.6 冲突与抢键裁决（简表）

| 冲突 | 裁决 |
|------|------|
| 句中 `/` vs slash | 仅空段/行首规则允许时打开 |
| 表内 Tab vs 列表 Tab | 表单元格优先 |
| 代码块 Tab vs 缩进 | 插入空白 |
| Esc | slash/菜单 → 退出块编 → 关宿主面板（分层） |
| 方向键 | slash 打开时只移菜单；composing 不跨块 |
| Ctrl+P vs 浏览器打印 | 编辑器焦点内 preventDefault；失焦还浏览器 |

### 6.7 给设计/实现的 IA 检验句

做任何新入口前背诵：

1. 这是 **光标处结构** 吗？→ Slash
2. 这是 **全局/导航/导出/AI** 吗？→ Ctrl+P
3. 这是 **每分钟会按** 的吗？→ 快捷键
4. 这是 **要看见 MD 字符** 才能安心吗？→ 行源码/fence
5. 四条都不像？→ **可能不该做**，或应进宿主壳而非编辑器

## 10. 结论

**诊断**：骨架正确（块 + 行源码 + MD 真相 + 中文触发），好用卡在五闸——**跨块选区/剪贴板、IME 纪律、撤销×渲染耦合、粘贴管道、导出诚实**。W0–W10「done」≠ 氧气管接通。

1. IME 全路径硬门禁（WF-13）
2. 块选 + MD 剪贴板 MVP（WF-04/05/14 地基）
3. 撤销粒度 + 禁 fullRender 闪屏（WF-11/12）

**目标叙事**：打开报告直接改中文 → 网页结论贴入仍是列表 → 表+图 → Ctrl+P 导出兼容 MD 给同事 → 无模式切换、无假保存、无「选不中两段」。
