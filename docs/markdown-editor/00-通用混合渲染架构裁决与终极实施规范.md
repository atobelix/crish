## 一、核心愿景与设计哲学

### 1.1 混合渲染的技术本质与行业深水区

在富文本与代码编辑器的工程光谱中，**原地混合渲染（Live Preview / WYSIWYG Markdown）**处于最复杂的交叉深水区：
- **纯文本/代码编辑器（VS Code / CodeMirror 纯代码模式）**：
  文档模型与视口拓扑完全对称。文本严格等宽，每行高度严格等于行高常量，字符索引与物理坐标之间存在天然的双射关系。
- **纯富文本编辑器（ProseMirror / TipTap / Slate）**：
  视口内只有渲染树，底层无实时可编辑的 Markdown 纯文本。用户操作直接突变 AST，不存在“光标滑入富文本瞬间展开为 ASCII 字符源码”的几何分裂。
- **原地混合渲染（Typora / Obsidian / Conex）**：
  **底层是严格保真的单字符逻辑索引 Markdown 纯文本；视口中呈现精美的排版微件（粗体、复选框、数学公式、表格卡片）；当光标进入某一区间时，该区间必须原地无缝展开为纯文本源码；光标离开时又无缝收缩为富文本。**

这种技术特性在物理几何上带来了根本性挑战：
$$\text{Source Representation (源码态)} \not\equiv \text{Visual Representation (渲染态)}$$
在同一逻辑字符区间内，源码态是等宽字符序列（固定宽度、标准基线）；渲染态是 SVG 图标、KaTeX 复杂排版盒、表格卡片或自定义微件（不同宽度、不同基线、不同高度）。

### 1.2 为什么必须彻底杜绝“打补丁”？

传统混合渲染系统容易陷入恶性打补丁循环：
1. 复选框显示不全 $\rightarrow$ 添加 `margin-left` 与 `width: 16px`；
2. 复选框视觉偏低 $\rightarrow$ 添加 `transform: translateY(-1px)` 提升合成层，破坏亚像素渲染与 HitTest；
3. 文本行被撑大 $\rightarrow$ 遗留 `vertical-align: sub` 导致行盒撑至 35px，切换源码态时坍塌为 31.6px，垂直剧跳 3.4px；
4. 隐藏标记无法测光标 $\rightarrow$ 使用 `display: none` 导致 DOM Range 返回 `(0,0,0,0)`，编写 `measureLineFallback` 强行把光标扔到行首左上角；
5. 光标移动视口跳动 $\rightarrow$ 在 `HiddenInput` 强写 `scrollTop = top - 40` 抢拉视口；
6. 虚拟滚动颠簸 $\rightarrow$ 修改 `HeightOracle` 猜测常数（1.3, 1.15）。

**每一次局部修补都是为了压制前一个补丁产生的副作用，从未在底层盒模型与数学映射上建立不可破坏的守恒律。**
本方案彻底摒弃“打补丁”思维，对齐 CodeMirror 6 与现代浏览器排版流规范，确立五大不可破坏的绝对不变量。

## 二、第一支柱：通用装饰层协议与 IFC 行盒几何守恒（$\Delta H \equiv 0$）

### 2.1 CSS IFC 包含块基线与高度锁定模型

根据 W3C CSS Inline Layout 规范，行盒的高度由其内部所有行内级框（Inline-level boxes）的对齐最高点与对齐最低点之间的距离决定：
$$\text{LineBox Height} = \max(\text{Ascender}_{\text{all}}) - \min(\text{Descender}_{\text{all}})$$
当行内元素声明了 `vertical-align: sub` 或 `super` 时，元素基线发生偏移，导致行盒的物理高度被硬性拉伸至 32.7px ~ 35.0px。当光标移入该行使其退化为源码态时，基线复位，行盒坍塌回 28px/31.6px，引发下游所有文本的剧烈上下震颤（抖动量 3.4px ~ 7.0px）。

**架构裁决**：
1. **全面清退原生 `vertical-align: sub`、`vertical-align: super` 与 `vertical-align: baseline` 任意魔术偏移**。
2. **全面清退所有硬编码的 `transform: translateY(...)` 样式补偿**。
3. **行盒采用严格 28px 网格锁定**：
   ```css
   :root {
     --grid-size: 28px;
     --line-height-base: 28px;
     --font-mono: 'JetBrains Mono', 'Fira Code', Menlo, Consolas, monospace;
   }

   .virtual-row {
     box-sizing: border-box;
     min-height: var(--grid-size);
     line-height: var(--grid-size);
   }

   .line-block {
     display: block;
     width: 100%;
     min-height: var(--grid-size);
     line-height: var(--grid-size);
     white-space: pre-wrap;
     word-break: break-word;
     font-family: var(--font-mono);
   }
   ```

### 2.2 统一原子微件包含块契约（InlineWidget Slot）

所有行内微件（复选框、状态标签、行内公式、脚注标记、行内代码）必须遵循统一的包含块插槽模型：
- **显示模式**：`display: inline-grid` 或 `display: inline-flex`。
- **对齐基准**：`vertical-align: top; align-items: center; justify-content: center;`。
- **高度绝对锁定**：`height: var(--grid-size); box-sizing: border-box;`。
- **行高隔离**：`line-height: 0;`。`line-height: 0` 彻底切断了微件内部文本对外部包含块（IFC Line Box）的继承影响，使得微件内部的任何排版变化都不会向上渗透撑大父级行盒。

```css
/* 统一原子行内微件插槽 */
.atomic-widget-slot {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  height: var(--grid-size);
  line-height: 0;
  vertical-align: top;
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}
```

### 2.3 上下标、脚注与行内格式化标记的零高度侵入隔离

上下标（$\text{H}_2\text{O}$、$\text{E}=\text{mc}^2$）与脚注（`[^1]`）不得依赖默认的 `<sub>` / `<sup>` HTML 标签排版行为。
**规范方案**：
```css
.style-sub,
.style-sup,
.footnote-ref {
  font-size: 0.75em;
  line-height: 0;
  display: inline-block;
  vertical-align: top;
  position: relative;
  height: var(--grid-size);
  pointer-events: auto;
}

/* 仅在纯视觉层使用 top 偏移字形，不改变排版框尺寸 */
.style-sub > .glyph-wrapper {
  position: relative;
  top: 0.25em;
}

.style-sup > .glyph-wrapper,
.footnote-ref > .glyph-wrapper {
  position: relative;
  top: -0.25em;
}
```

### 2.4 垂直高度守恒定理数学证明

**定理 1（行盒高度恒等律）**：
设虚拟化行 $L$ 包含纯文本序列 $T$ 与行内微件集合 $\{W_1, W_2, \dots, W_k\}$。
在纯文本态（源码态），行盒高度为：
$$H_{\text{source}}(L) = \max(H(T)) = \text{line-height} = 28.000\text{px}$$
在混合渲染态，由于：
$$\forall i, \quad W_i.\text{vertical-align} = \text{top}, \quad W_i.\text{height} = 28.000\text{px}, \quad W_i.\text{line-height} = 0$$
外部 IFC 行盒的高程计算：
$$H_{\text{render}}(L) = \max(H(T), \max_i(W_i.\text{height})) = \max(28.000\text{px}, 28.000\text{px}) = 28.000\text{px}$$
因此：
$$\Delta H = H_{\text{render}}(L) - H_{\text{source}}(L) \equiv 0.000\text{px} \quad \blacksquare$$

## 三、第二支柱：等宽槽位守恒与幽灵字符流架构（$\Delta X \equiv 0$）

### 3.1 彻底清退 `display: none` 的物理必然性

传统实现中使用 `display: none` 隐藏 Markdown 源码标记（如任务列表的 `- [ ] `、标题前缀 `# `、粗体标记 `**`），存在两大致命缺陷：
1. **水平横移（$\Delta X \neq 0$）**：渲染态的复选框总占宽为 31.69px，而源码态 `- [ ] `（6 个等宽字符）在标准字体下占宽 $6 \times 7.698\text{px} = 46.19\text{px}$，切换瞬间正文发生 **14.5px** 的剧烈右移/左跳。标题 `# ` 展开时正文横移 **35.4px**。
2. **Range 测量瘫痪（0x0 异常）**：浏览器规范规定，`display: none` 祖先节点下的所有文本节点从 Layout 渲染树中彻底剔除。对其调用 `document.createRange().getBoundingClientRect()` 恒返回 `DOMRect(x: 0, y: 0, width: 0, height: 0)`。由于拿到全零矩形，测量引擎跌入兜底代码，强行将光标抛甩到行首左上角。

### 3.2 幽灵字符流协议（Ghost Token Stream Protocol）

**严禁将 DOM 节点从渲染树中删除**。所有隐藏的 Markdown 标记采用**幽灵字符流（Ghost Token Stream）**：
- 节点始终存在于 DOM 树中，参与排版流；
- 视觉上通过 `color: transparent; font-family: var(--font-mono);` 保持隐藏，或者在重叠槽位中被精准覆盖；
- 用户选择行为：`user-select: text`，允许复制和拖选；
- 浏览器 Range API 对幽灵字符依然具备 100% 物理尺寸和真实亚像素坐标，测量**永不返回 0x0**。

### 3.3 槽位等宽定理（Slot Invariance Theorem）

为保证正文起始点在展开与折叠时横向绝对静止，引入**等宽流式槽位（Width-Locked Slot）**：
- 渲染态视觉组件的槽位宽度必须严格对齐源码字符数：
  $$\text{SlotWidth} = N_{\text{chars}} \times 1\text{ch}$$
- 对于任务列表 `- [ ] `：包含 6 个字符（`-`、` `、`[`、` `、`]`、` `），槽位宽度锁定为 `6ch`。在 `6ch` 的空间内，左侧居中渲染可交互复选框，其余空间自然填充，使正文首字符的物理 X 坐标恒等于 $6\text{ch}$。
- 采用 **Layer 0 幽灵流 + Layer 1 视觉微件绝对居中悬浮（Overlay Pattern）**：
  ```css
  /* 等宽槽位容器 */
  .slot-container {
    position: relative;
    display: inline-flex;
    align-items: center;
    justify-content: center;
    height: var(--grid-size);
    vertical-align: top;
    box-sizing: border-box;
  ```

### 3.4 水平位置绝对守恒数学证明

**定理 2（正文水平坐标恒等律）**：

在源码态下，正文首字符 $C_0$ 的物理 X 坐标为：

$$X_{\text{render}}(C_0) = X_{\text{line\_start}} + \text{Padding}_{\text{left}} + \text{Width}(\text{Slot}) = X_{\text{line\_start}} + \text{Padding}_{\text{left}} + K \times W_{\text{ch}}$$
两态之差：
$$\Delta X = X_{\text{render}}(C_0) - X_{\text{source}}(C_0) \equiv 0.000\text{px} \quad \blacksquare$$

### 5.1 逻辑选区作为单一真理源（SSOT）

2. 视图层的选区高亮（`SelectionHighlight`）与光标渲染（`CursorLayer`）由 $\mathcal{S}$ **单向纯函数投影生成**。

### 5.2 视觉行盒几何对齐与零重叠选区高亮（$\Omega \equiv 0$）

**现象与病因**：
在 `SelectionHighlight.tsx` 中，`Range.getClientRects()` 返回的是 TextNode 字形框（受字体内在 half-leading 影响，天然下沉偏下 4~6px）。原系统使用 `min(top) + 28px` 计算行高，导致选区下缘溢出侵入下一行，发生跨行重叠（Overlapping Rectangles）。

**绝对零重叠投影算法**：
```typescript
/**
 * 视觉行盒绝对零重叠对齐算法
 * 保证: line_N.bottom === line_{N+1}.top (Ω ≡ 0.000px)
 */
export function projectNormalizedSelectionRects(
  rawRects: DOMRect[],
  containerRect: DOMRect,
  lineGridHeight: number = 28
): ProjectedSelectionRect[] {
  const result: ProjectedSelectionRect[] = [];
  
  for (const raw of rawRects) {
    // 1. 将物理视口坐标转换为相对于容器的局部坐标
    const localTop = raw.top - containerRect.top;
    const localLeft = raw.left - containerRect.left;
    
    // 2. 几何网格对齐: 将字形下沉坐标规整到所属的标准行盒基准
    const lineIndex = Math.floor((localTop + raw.height / 2) / lineGridHeight);
    const normalizedTop = lineIndex * lineGridHeight;
    const normalizedBottom = normalizedTop + lineGridHeight;
    
    result.push({
      left: Math.round(localLeft),
      top: normalizedTop,
      width: Math.round(raw.width),
      height: lineGridHeight, // 严格等于 28px
      bottom: normalizedBottom
    });
  }
  
  return result;
}
```
**几何守恒证明**：
相邻两行 $N$ 与 $N+1$：
$$\text{Line}_N.\text{bottom} = N \times 28 + 28 = (N+1) \times 28 = \text{Line}_{N+1}.\text{top}$$
重叠区域高度：
$$\Omega = \max(0, \text{Line}_N.\text{bottom} - \text{Line}_{N+1}.\text{top}) \equiv 0.000\text{px} \quad \blacksquare$$

### 6.3 树状数组（Fenwick Tree）维护全局前缀高度和

利用 Fenwick Tree 实现 $O(\log N)$ 的前缀高度和计算与单点更新：
```typescript
export class FenwickHeightTree {
  private tree: Float64Array;
  private size: number;

  constructor(size: number, defaultLineHeight: number = 28) {
    this.size = size;
    this.tree = new Float64Array(size + 1);
    // 初始化 O(N) 构建
    for (let i = 1; i <= size; i++) {
      this.tree[i] += defaultLineHeight;
      const parent = i + (i & -i);
      if (parent <= size) {
        this.tree[parent] += this.tree[i];
      }
    }
  }

  public updateDelta(index: number, delta: number): void {
    let i = index + 1;
    while (i <= this.size) {
      this.tree[i] += delta;
      i += (i & -i);
    }
  }

  public queryPrefixSum(index: number): number {
    let sum = 0;
    let i = index + 1;
    while (i > 0) {
      sum += this.tree[i];
      i -= (i & -i);
    }
    return sum;
  }
}
```

### 6.4 pre-rAF 物理滚动补偿与绝对视口锚定

当视口上方的可见行在挂载后由真实 DOM 回填真实高度并产生高度差 $\Delta H_j = H_{\text{real}} - H_{\text{predicted}}$ 时：
**严禁直接修改 DOM 触发二次重排**！
在同一个渲染帧的 `useLayoutEffect` 中，计算视口上方所有高度修正总和：
$$\Delta H_{\text{total}} = \sum_{j < \text{viewportAnchorLine}} \Delta H_j$$
立即同步原子补偿滚动条：
$$\text{container.scrollTop} \leftarrow \text{container.scrollTop} + \Delta H_{\text{total}}$$
**物理效果**：
视口内用户正在阅读的文字行相对于屏幕物理像素的位移：
$$\Delta Y_{\text{screen}} = \Delta Y_{\text{element}} - \Delta Y_{\text{scroll}} = \Delta H_{\text{total}} - \Delta H_{\text{total}} \equiv 0.000\text{px} \quad \blacksquare$$
视口当前内容纹丝不动，彻底消灭虚拟滚动拉扯颠簸！
