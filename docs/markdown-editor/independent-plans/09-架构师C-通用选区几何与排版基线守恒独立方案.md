## 简答题 1：视觉行盒（Visual Line Box）几何对齐与零重叠选区投影系统

**现象与根因：**
在 `SelectionHighlight.tsx` 中，选区构建依赖 `Range.getClientRects()`，该 API 返回的是文本节点（TextNode）的**字形盒（Glyph Box）**。在 CSS IFC 中，由于 `half-leading`（半行距）的存在，字形盒天然低于视觉行盒（Visual Line Box），导致选区下沉。旧方案在 `mergeVisualLineRects` 中粗暴使用 `min(top)` 加上硬编码的 `28px`，导致折行时选区上下重叠、边缘溢出。

**通用架构设计与数学解法：**
为了实现单行及折行段落的绝对零重叠（`line_N.bottom === line_{N+1}.top`），必须废弃对“碎片化字形盒 top/height”的依赖，转而使用**容器网格化降维映射**。物理真理源应为 `[data-line-start]` 行容器的 bounding box。

1. **数学映射模型**：
   设行容器起始 Y 坐标为 $Y_{base}$，标准行高为 $H_{line}$（如 28px）。对于 `Range.getClientRects()` 返回的任意碎片矩形，取其中轴 $Y_{mid} = r.top + r.height / 2$。
   该碎片所属的视觉逻辑行索引 $k$ 为：
   $$k = \lfloor \frac{Y_{mid} - Y_{base}}{H_{line}} \rfloor$$
   则该视觉行的绝对物理边界被严格锁定为：
   $$Top_k = Y_{base} + k \times H_{line}$$
   $$Bottom_k = Top_k + H_{line}$$

2. **工程实现替换 (`SelectionHighlight.tsx`)**：
   在遍历碎片时，不直接采纳 $r.top$ 和 $r.height$，而是代入上述公式归一化。
   ```typescript
   // 获取当前行的基准坐标与行高
   const lineRect = line.getBoundingClientRect();
   const LINE_HEIGHT = 28; // 或基于 getComputedStyle 动态获取

   // 遍历 clientRects 时：
   const yMid = r.top + r.height / 2;
   const visualLineIndex = Math.max(0, Math.floor((yMid - lineRect.top) / LINE_HEIGHT));

   lineRawRects.push({
     top: lineRect.top + visualLineIndex * LINE_HEIGHT - containerRect.top + container.scrollTop,
     left: r.left - containerRect.left + container.scrollLeft,
     width: r.width,
     height: LINE_HEIGHT, // 绝对固定行高
   });
   ```
   *数学结果：所有同一折行的碎片绝对对其到 $Top_k$，无缝拼接。两行之间的间距 $(Top_{k+1}) - (Bottom_k) = 0$，实现绝对零间隙。*

## 简答题 2：语法前缀与正文无缝连续物理二分探测（消除 `#` 边界奇异点）

**现象与根因：**
在 `core/measure.ts` 中，`locateRowIndexByPhysicalBisection` 所依赖的 `TreeWalker` 将 `display: none` 的 `.syntax-hidden` 节点直接 `FILTER_REJECT`。这就导致隐藏的语法字符（如 `# `）从物理投影空间中凭空消失。当鼠标从左侧滑入时，由于物理坐标系与逻辑字符串偏移量（Offset）断层，欧氏距离计算失效，引发选区或光标漂移。

**通用架构设计与物理空间连续化：**
必须构建一个**连续同胚**的物理投影空间，使隐藏字符拥有物理坐标，但宽度收敛于 0。

1. **CSS 层契约重构 (`index.css`)**：
   将 `display: none` 替换为字号坍缩，保留 DOM 挂载和物理拓扑，但不占据视觉宽度。
   ```css
   .syntax-hidden {
     /* 废弃 display: none; */
     font-size: 0;
     opacity: 0;
     pointer-events: none;
     user-select: none;
   }
   ```

2. **TypeScript 探测器解禁 (`core/measure.ts`)**：
   在 `TreeWalker` 的 `acceptNode` 拦截器中，将 `.syntax-hidden` 移出黑名单。
   ```typescript
   // core/measure.ts
   const ignoreEl = p.closest(
     '.katex-mathml, .math-preview, .code-gutter, [data-copy-button], [data-ignore-measure]' // 移除了 .syntax-hidden
   ) as HTMLElement | null;
   ```
   调整零宽矩形判定：
   ```typescript
   const cr = range.getBoundingClientRect();
   // 允许宽高为 0 但物理坐标合法（非未渲染元素）的零宽字符汇入欧氏距离测算池
   if (cr.width > 0 || cr.height > 0 || (cr.left > 0 && cr.top > 0)) {
     chars.push({ node: entry.node, offset: c, globalPos: entry.globalStart + c, rect: cr });
   }
   ```
   *架构收益：无论字符处于展开（渲染态）还是坍缩（隐藏态），鼠标向其逼近时的 \Delta X 距离变化连续且单调，二分法 100% 精准落于对应 `offset`。*

## 简答题 3：任务列表项源码态天然基线守恒（Baseline Invariance）

**现象与根因：**
`.interactive-checkbox` 在 `index.css` 声明了 `display: inline-flex; align-items: center;` 以实现 UI 居中。然而在 Live Preview 下，当光标进入该行触发展开态（源码 `- [x]`）时，组件仍受 `flex` 容器几何挟持。纯文本被放入 `inline-flex` 后，原生的 IFC 基线被破坏，导致 `[` 和汉字产生垂直高低错位。

**通用架构设计与解耦契约：**
我们需要实现**状态机与排版体系的严格正交**。渲染态使用 Flex 布局，源码态必须回归纯粹的 Text IFC。

1. **状态驱动的 CSS 基线还原 (`index.css`)**：
   利用上层 `.is-active-line` 状态标量，向下熔断 Flex 容器。
   ```css
   /* 源码态基线守恒契约 */
   .is-active-line .interactive-checkbox,
   .is-active-token .interactive-checkbox {
     display: inline;             /* 卸载 flex 容器 */
     height: auto;                /* 解除固定高度锁定 */
     line-height: inherit;        /* 继承外部行高 */
     vertical-align: baseline;    /* 回归原生文本基线 */
     font-weight: normal;         /* 匹配正文粗细 */
   }
   ```
   *架构收益：彻底剥离 Flex 轴对齐计算，组件退化为内联 `span`，基线对齐交还给浏览器排版引擎，确保 |\Delta Y| <= 0.1px。*

## 简答题 4：表格单元格就地文本编辑与划词拖选流水线修复

**现象与根因：**
在 `HiddenInput.tsx` 的 `handleDragMouseMove` 中，表格拖选分支错误使用了状态覆盖：
```typescript
editorStore.getState().setSelection(cellDrag.anchorIdx, clampedHead);
editorStore.getState().setCursorPos(clampedHead); // 致命调用
```
查阅 `EditorStore.ts` 的 `setCursorPos` 实现可知，其会将 `selectionStart` 与 `selectionEnd` 强制折叠收缩为一点。这导致在拖拽的每一个 RequestAnimationFrame (RAF) 帧中，选区刚被建立就立刻被摧毁，造成无法划词。

**通用架构设计与事件流修正：**
`setSelection` 自身是完备的方向性区间构造函数（其内部妥善维护了 `anchorPos` 和 `headPos` 并同步 `cursorPos` 为 `headPos`），属于高阶状态更新。

1. **移除强制折叠 (`HiddenInput.tsx`)**：
   直接删除 `setCursorPos` 的破坏性调用：
   ```typescript
   // 修正后的单元格拖拽响应
   const clampedHead = Math.max(
     cellDrag.start,
     Math.min(cellDrag.start + cellDrag.len, headIdx)
   );
   // 仅调用 setSelection 即可维持锚点并更新游标，底层引擎会自动派生正确的选区范围
   editorStore.getState().setSelection(cellDrag.anchorIdx, clampedHead);
   // [DELETED] editorStore.getState().setCursorPos(clampedHead);
   ```

2. **状态机解耦：**
   分离“单击（Click/Focus）”与“拖拽（Drag）”的语义流。`mousedown` 生成 `anchor` 但不生成区间；`mousemove` 超出 `DRAG_THRESHOLD_PX` 后仅发射 `setSelection(anchor, head)`，彻底解决表格编辑态下行为流冲突的问题。

## 简答题 5：块引用（Blockquote）原地混合渲染状态机接线

**现象与根因：**
在 `index.css` 中存在一条错误的 CSS 规则：
```css
.line-blockquote:not(.is-active-line) .token-blockquote-prefix { width: 0 !important; ... }
```
由于编辑器 DOM 树结构为 `<div class="virtual-row is-active-line"><div class="line-blockquote">...</div></div>`，状态标量 `.is-active-line` 是挂载在最外层的行宿主容器上。因此内层的 `.line-blockquote` **永远无法满足** 拥有 `.is-active-line`（它自身没有被添加该类名），导致其 `:not(.is-active-line)` 否定选择器恒为真，`> ` 源码前缀被永久折叠。

**通用架构设计与选择器契约：**
父容器的状态机变量必须沿着 DOM 树正确下传（Top-down cascade）。

1. **DOM 结构感知修复 (`index.css`)**：
   修正复合选择器，以父容器 `.virtual-row` 的状态否定作为触发条件，穿透至 `.line-blockquote`：
   ```css
   /* 架构修正：状态标量宿主分离 */
   .virtual-row:not(.is-active-line) .line-blockquote .token-blockquote-prefix {
     display: inline-block;
     width: 0 !important;
     overflow: hidden;
     vertical-align: top;
   }
   ```
   *架构收益：当光标切入时，`.virtual-row` 获得 `.is-active-line`，上述否定选择器失效，配合下方的展开规则 `.is-active-line .token-blockquote-prefix .syntax-hidden { display: inline; }`，实现前缀文本的平滑零阻力展开与连贯编辑。*
