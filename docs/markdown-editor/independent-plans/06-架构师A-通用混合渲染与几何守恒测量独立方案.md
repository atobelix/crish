# 独立架构师 A：通用混合渲染（Live Preview）与几何守恒测量系统独立方案

## 简答题 1：通用行内 Widget 契约与行盒（Line-Box）几何高度守恒

**问题剖析与第一性原理：**
在 CSS 的 Inline Formatting Context (IFC) 中，行盒 (Line-Box) 的高度由其内部所有行内级盒子的最高和最低点决定。`vertical-align: sub/super` 等会使元素偏离基线 (Baseline)，进而撑破原有的 Line-Box 高度。由于 Markdown 混合渲染需要在“源码态”和“渲染态”之间频繁切换，任何高度上的突变都会累积成为页面的剧烈跳动（即 $\Delta H \neq 0$）。

**解决方案架构：**

1.  **废弃影响基线的 vertical-align 与硬编码 transform：**
    所有行内 Widget（如 `.interactive-checkbox`、`[^1]`）全面禁用 `vertical-align: sub` 等导致基线偏移的属性。
2.  **强制高度隔离契约 (`line-height: 0`)：**
    在包裹行内 Widget 的容器上使用 `line-height: 0` 和 `font-size: 0`，确保它们对于外部 Line-Box 的高度贡献为 0，不破坏基础行高（例如 28px）。
3.  **Flexbox 中轴锁定网格体系：**
    利用 CSS Flexbox 的绝对对齐。构建一个与文本 `line-height` 完全相等的虚拟插槽盒。
    ```css
    .widget-container {
      display: inline-flex;
      align-items: center;
      justify-content: center;
      line-height: 0; /* 隔离外部撑破 */
      height: 28px;   /* 绝对锁定基础行高 */
      vertical-align: middle; 
    }
    ```
4.  **数学保证：**
    在任何状态下（正常、悬停、激活、编辑），行内级的盒子模型 $H_{widget} \le 28px$，借由 `line-height: 0` 加上 `align-items: center`，行盒高度守恒 $\Delta H \equiv 0$。

## 简答题 2：等宽槽位守恒与幽灵字符流（消除 14.5px/35.4px 横移与 Range 0x0 失效）

**问题剖析与第一性原理：**
`display: none` 从 DOM 的渲染树中移除了节点，导致 `Range.getBoundingClientRect()` 无法获取坐标（返回全 0），系统跌入降级的退化测量逻辑，造成光标乱甩。而从源码态到渲染态，宽度存在断层，产生了显著的横移。

**解决方案架构：**

1.  **全面废除 `display: none`，建立幽灵字符流（Ghost Token Stream）：**
    将需要被隐藏的源码标记（如 `# ` 或 `- [ ] `）转化为透明度为 0、缩放为近乎无但保留盒模型的“幽灵节点”。
    ```css
    .ghost-token {
      visibility: hidden;
      opacity: 0;
      /* 不要使用 display: none */
      pointer-events: none;
    }
    ```
2.  **通用等宽槽位（Slot Invariance）：**
    通过 CSS `ch` 单位 (字符宽度) 让视觉 Widget 与源码标记占位严格绑定。如果源码态包含 4 个字符（如 `- [ ] `），渲染态的 Widget 宽度必须通过容器限制为 $4 \times 1\text{ch}$。
    ```css
    .widget-slot {
      display: inline-flex;
      width: calc(var(--char-count) * 1ch); 
      justify-content: flex-start;
    }
    ```
    使得视觉组件被约束在这个槽位中，保证展开/收起时整体占宽不变，$\Delta X \equiv 0$。
3.  **合法物理几何锚点：**
    由于源码字符并未 `display: none`，它们仍旧存在于 DOM 且拥有合法坐标集。针对不可见的幽灵字符，`Range.getBoundingClientRect()` 能正常返回坐标，彻底根除了测量的 0x0 失效。

## 简答题 3：双层无盲区光标几何投影管线（Caret Projection Pipeline）

**问题剖析与第一性原理：**
光标的测量常常陷入组件内部的复杂嵌套 DOM 树（如 KaTeX 渲染生成的树），导致测量出的坐标毫无意义，而 `measure.ts` 对此没有防御，直接跌入 `measureLineFallback` 丢弃精度。同时 `HiddenInput.tsx` 的抢拉滚动破坏了用户体验。

**解决方案架构：**

1.  **Tier 1: 纯文本物理 Range 快速测量：**
    常规文本区域执行直接的原生 Range 测量。由于幽灵字符流架构，纯文本即使不可见也有精确的物理坐标。
2.  **Tier 2: 复合 Widget 盒模型比例几何插值投影：**
    如果光标命中了 Widget 内部，**严禁**穿透进 Widget 内部层级去逐字测量。
    我们将 Widget 视作一个黑盒。如果用户的光标在逻辑上位于 Widget 源码的第 $i$ 个字符位置，Widget 总共有 $N$ 个字符，则光标的物理坐标 $X$ 直接进行线性插值投影：
    $$X = \text{Rect.left} + \left( \frac{i}{N} \right) \times \text{Rect.width}$$
    这保证了测量是 $O(1)$ 常数时间，不会迷失在深层 DOM 树中。
3.  **拆除强依赖与状态同步：**
    - 废除 `measureLineFallback`（因 Tier 1 与 Tier 2 已覆盖全域 $100\%$ 情况）。
    - 建立 `decorationVersion` -> `posCache` 强制刷新机制。每次 React 渲染周期带来装饰层变动，均使旧坐标缓存失效，重新触发精准投影。
    - 彻底剥离 `HiddenInput.tsx` 中向 DOM 强写 `scrollTop` 的行为，将视口滚动职责交还给专用的滚动管理器处理。

## 简答题 4：多模态自适应行高树（HeightMap）与平滑视口锚定

**问题剖析与第一性原理：**
静态魔法倍率无法应对动态变化的复杂内容（数学公式、表格换行）。当用户滚动，元素被挂载，其实际高度撑开了容器，HeightMap 更新引发重新布局，致使视口剧烈拉扯，出现颠簸卡顿。

**解决方案架构：**

1.  **基于 AST 特征的初始预测模型：**
    丢弃死板的 `1.3`、`1.15` 倍率。在解析 Markdown AST 时，依据节点特征估算高度：
    - 代码块：`Math.max(1, astNode.lineCount) * baseLineHeight`
    - 数学块：基于行数及特定的公式行高放大系数。
    - 表格：`(astNode.rowCount) * cellHeight`
2.  **单向自适应回填树 (One-Way Backfill Tree)：**
    将预测值放入 HeightMap 树中。组件被挂载后，利用 `ResizeObserver` 捕获其“真实物理高度”。此时使用真实物理高度 **回填** HeightMap 节点。并且这个更新是“单向递增式”合并或平滑过渡的。
3.  **强力视口滚动锚定（Scroll Anchoring）：**
    在回填导致上方高度发生 $\Delta H_{diff}$ 变化时，传统的做法任由浏览器重新排列导致当前视口内容跳动。
    - **方法 1：** 原生开启 `overflow-anchor: auto;`。
    - **方法 2（精密架构）：** 手动追踪视口顶部第一个可见元素。当 HeightMap 在该元素**上方**发生 $\Delta H_{diff}$ 变动时，实时计算并在下一帧自动注入 `container.scrollTop += \Delta H_{diff}`。从而使得下方的视觉阅读区域在屏幕像素上做到“纹丝不动”。
