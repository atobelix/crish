# 独立架构师 D：通用选区几何与排版基线守恒独立方案

针对目前 Markdown 原地混合渲染（Live Preview）编辑器交互体验中的 5 项关键反馈，从 CSS Inline Formatting Context (IFC)、包含块几何守恒以及物理真理源单一化（SSOT）出发，深度架构解法如下。严禁补丁式（patch）修复，追求第一性原理。

## 简答题 1：视觉行盒（Visual Line Box）几何对齐与零重叠选区投影系统

### 现象与根因
在 `SelectionHighlight.tsx` 中，底层直接依赖原生 `Range.getClientRects()` 进行物理测量。原生的物理测量返回的是 **字形盒（Glyph Bounding Box）**，受到字体自身度量（Font Metrics）和 `half-leading` 的影响，其顶部与底部天然向内收缩并发生下沉。
旧版 `mergeVisualLineRects` 算法粗暴地使用 `Math.min(top)` 加上固定行高 `28px`，导致在多折行、多字体混排时，选区矩形脱离了真实的**视觉行盒（Visual Line Box）**边界，出现明显的下沉、上下不对称以及底缘溢出跨行重叠（即 `line_N.bottom > line_{N+1}.top`）。

### 通用架构与数学解法
**1. 将 Y 轴真理源从字形盒转移至行高网格（Line Height Grid）：**
摒弃文本节点原生的 Y 轴几何测量。X 轴（`left`, `width`）保留 `getClientRects` 提供的精确光栅化坐标，但 Y 轴必须由虚拟行盒网格进行强制规整化。
**2. 绝对零重叠数学投影（Absolute Zero-Gap Projection）：**
在 `mergeVisualLineRects` 算法中，首先算出视觉行的绝对基准 `LineTop = Math.floor(min(r.top))`。随后，将选区矩形按照物理行高 $H$（如 `28px`）进行量子化对齐：
对于一条行内存在多个 `clientRects` 片段，算出其所处的视觉折行索引 $k$：
$$ k = \lfloor \frac{r.top - LineTop}{H} \rfloor $$
则该片段被强制投影为：
- $Top = LineTop + k \times H$
- $Bottom = LineTop + (k + 1) \times H$
由于整数乘法与加法，这从数学上保证了 $Bottom_k \equiv Top_{k+1}$，彻底消灭 ±1px 亚像素间隙和任何形式的跨行重叠。

## 简答题 2：语法前缀与正文无缝连续物理二分探测（消除 `#` 边界跳跃）

### 现象与根因
在 `core/measure.ts` 的 `locateRowIndexByPhysicalBisection` 算法中，其 `TreeWalker` 的 `acceptNode` 函数使用了粗暴的过滤条件：
```typescript
const ignoreEl = p.closest('.syntax-hidden, ...');
if (ignoreEl) return NodeFilter.FILTER_REJECT;
```
当光标处于非激活态，前缀字符 `#` 或 `> ` 会被加上 `.syntax-hidden` 类从而隐藏。但当鼠标在行首滑动，行状态瞬变为激活态（展开源码），原本被 `TreeWalker` 拒收的节点又突然出现。由于过滤策略与实际鼠标事件的视觉投影断裂，物理二分测距时会遇到 0 宽突变或节点缺失，导致命中最近欧氏距离时漂移至正文开头。

### 通用架构与数学解法
**1. 统一连续物理投影空间（Physical Continuum）：**
在物理探测阶段，**绝对不能通过 `NodeFilter.FILTER_REJECT` 将 `.syntax-hidden` 从 DOM 树剔除**，而应接收并处理。
**2. 零宽坍缩节点的欧氏投影粘合：**
在二分遍历计算字符距离时，对于处于隐藏态、即测得 `r.width === 0` 的前缀文本，不再跳过，而是将它的 `left` 与 `right` 坐标**继承并等同于**相邻第一个可见正文字符的左边缘（或者继承其父元素的 `left`）。
这意味着在欧氏空间上，隐藏的 `#` 与正文第一个字符被压缩在同一个数学点 $X_0$ 上。当鼠标滑动到该处时，物理二分依旧能正确找到索引，而不会发生越级断层。

## 简答题 3：任务列表项源码态天然基线守恒（Baseline Invariance）

### 现象与根因
当前任务列表在 `index.css` 的 `.interactive-checkbox` 中被定义为 `display: inline-flex; align-items: center; vertical-align: top;`。
在**渲染态**下，这能完美居中渲染一个 UI Checkbox。但当所在行被激活进入**源码态**时，引擎直接展现出纯文本 `- [x]`。由于这层外壳依旧被 `flex` BFC 环境包裹，导致纯文本脱离了外层的 Inline Formatting Context (IFC)，其基线被 Flex 垂直居中算法强制扰乱，与后续中文字符产生致命的垂直高低错位。

### 通用架构与 CSS 解法
**彻底解耦渲染态与源码态的排版契约，卸载 Flex 包裹：**
将组件状态机映射至 CSS 级联选择器。对于处于编辑态（`.is-active-line`）的虚拟行，必须强制将 Checkbox 降维回归纯文本 IFC。
```css
/* 1. 默认/非激活行（渲染态）：保持 UI 组件几何对齐 */
.virtual-row:not(.is-active-line) .interactive-checkbox {
  display: inline-flex;
  align-items: center;
  vertical-align: text-bottom;
}

/* 2. 激活行（源码态）：卸载 Flex，回归原生 IFC 文本基线 */
.virtual-row.is-active-line .interactive-checkbox {
  display: inline;
  vertical-align: baseline;
  /* 使得包裹内的 `- [x]` 文本与同行正文 baseline 100% 绝对贴合，|ΔY| <= 0.1px */
}
```

## 简答题 4：表格单元格就地文本编辑与划词拖选流水线修复

### 现象与根因
在全局 `HiddenInput.tsx` 的 `handleDragMouseMove` 中，状态机直接向 `store` 提交拖拽更新。问题在于：底层在调用 `setSelection(anchor, head)` 更新选区范围后，立即触发了 `setCursorPos()` 同步光标。
但 `setCursorPos` 的底层语义是**折叠光标（Collapse to point）**，这就导致每一帧（16ms）拖选生成的 Range 瞬间被粉碎并收敛为单点，造成用户永远无法在单元格内部正常拖蓝文字。此外，表格单元格自带内部 input，全局的拖选引擎在此处产生了事件流冲突。

### 通用架构与解法
**1. 拖选引擎的作用域下放与隔离（Scope Isolation）：**
全局 Drag 状态机在进入 `mousemove` 生命周期前，必须探测落点环境（`target.closest('.token-table-cell')`）。如果在单元格内且处于编辑态，直接**中止全局拖拽接管**，将控制流（`pointer-events`）无缝交还给单元格内部的输入框，利用浏览器原生 IFC 划词系统处理。
**2. 核心状态机状态互斥法则：**
严格规定 `setCursorPos` 仅用于纯点击（Click / mousedown 且未偏移）、键盘方向键。在 `DRAG_THRESHOLD_PX` 被激活进入拖选态后，流水线必须**锁死并禁止调用** `setCursorPos`，全程只允许使用 `setSelection` 游动 `head` 指针。

## 简答题 5：块引用（Blockquote）原地混合渲染状态机接线

### 现象与根因
CSS 定义了规则：
`.line-blockquote:not(.is-active-line) .token-blockquote-prefix { width: 0 !important; overflow: hidden; }`
然而，由于 Live Preview 架构中负责管理状态的类名 `.is-active-line` 是挂载在最外层容器 `.virtual-row` 上的，内层的 `.line-blockquote` 自身永远没有这个类。因此 `:not(.is-active-line)` 恒定为真，导致语法前缀 `> ` 在任何状态下都被压扁为 `0px` 宽，点击无法展开源码进行修改或删除。

### 通用架构与 CSS 解法
**级联状态下放（Cascading State Delegation）与平滑空间插值：**
修正 CSS 选择器契约，令外层 `.virtual-row` 的激活状态正确穿透到子级前缀节点。为实现类似 Obsidian 的原汁原味体验，必须加入缓动以防文字瞬间跳闪。
```css
/* 当外层行处于非激活态时，折叠内部块引用的源码前缀 */
.virtual-row:not(.is-active-line) .line-blockquote .token-blockquote-prefix {
  display: inline-block;
  width: 0 !important;
  opacity: 0;
  overflow: hidden;
  white-space: nowrap;
}

/* 当外层行被激活（鼠标点入）时，平滑展开源码前缀 */
.virtual-row.is-active-line .line-blockquote .token-blockquote-prefix {
  display: inline-block;
  width: auto !important; /* 或者具体的 ch 宽度 */
  opacity: 1;
}

/* 通用前缀缓动契约：实现零生硬跳跃 */
.token-blockquote-prefix {
  transition: width 0.15s cubic-bezier(0.4, 0, 0.2, 1), opacity 0.1s ease-in;
}
```
通过选择器升维，将真理源牢牢绑定在 `.virtual-row.is-active-line` 这个唯一物理 SSOT 上，彻底保证原地渲染状态机的确定性。
