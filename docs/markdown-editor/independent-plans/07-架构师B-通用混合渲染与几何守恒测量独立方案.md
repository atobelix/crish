# 【独立架构师 B 卷】通用混合渲染（Live Preview）与几何守恒测量系统

本提案严格从 CSS Inline Formatting Context (IFC) 第一性原理与通用系统设计出发，针对高品质 Markdown 原地混合渲染（Live Preview）编辑器的核心痛点提出彻底的数学、CSS 及 TypeScript 重构方案。我们的绝对目标是：**零上下跳（ΔH ≡ 0）、零正文横移（ΔX ≡ 0）、零光标盲区、零虚拟滚动颠簸**。

---

## 简答题 1：通用行内 Widget 契约与行盒（Line-Box）几何高度守恒

> [!WARNING]
> **病因剖析**：`src/index.css` 中，`.interactive-checkbox` 滥用了 `vertical-align: sub` 和 `transform: translateY(-1px)`；且上下标及脚注存在高度外溢。这直接破坏了 IFC，导致激活/非激活状态下行盒（Line-Box）被撑破，在 35px 与 31.6px 之间剧烈震荡（产生 3.4px 下游跳动）。

### 解决方案：IFC 第一性原理与通用 InlineWidget 契约

要彻底保证任何行内结构在各种状态下其物理高度恒定等于 28px（ΔH ≡ 0），必须采用**网格锁定（Grid Lock）**与**中轴隔离（Axis Isolation）**：

1. **废弃 Baseline 对齐，启用 Inline-Flex 中轴对齐**
   必须全面清退 `vertical-align: sub/super/middle`。对于所有的 InlineWidget，建立统一的包含块：
   ```css
   .inline-widget-container {
     display: inline-flex;
     align-items: center; /* 基于 Flexbox 的中轴几何对齐，绝对居中 */
     justify-content: center;
     height: var(--grid-size); /* 严格锁定 28px */
     line-height: 0; /* 剥夺其对父级 Line-Box 撑大的能力 */
     vertical-align: top; /* 强行贴合网格顶端 */
   }
   ```
2. **上下标及脚注的零撑破契约（Zero-inflation Contract）**
   对于 `.style-sub`、`.style-sup` 和脚注 `[^1]`，不再让它们参与行高计算：
   ```css
   .style-sub, .style-sup, .footnote-ref {
     line-height: 0;
     display: inline-block;
     vertical-align: baseline; 
     /* 利用 relative + top 替代 vertical-align: sub 产生的行盒撑破 */
     position: relative;
   }
   .style-sub { top: 0.3em; }
   .style-sup { top: -0.3em; }
   ```
3. **消除 Transform 外溢**
   废除 `transform: translateY(-1px)` 的硬编码补丁，将 Widget 置于 `inline-flex` 中后，依靠 `align-items: center` 实现数学级别的完美中轴对齐。

## 简答题 2：等宽槽位守恒与幽灵字符流（消除横移与 Range 0x0 失效）

> [!CAUTION]
> **病因剖析**：当前系统用 `display: none` 隐藏源码标记（如 `- [ ] ` 或 `# `）。这造成两大灾难：
> 1. **ΔX 剧烈突变**：展开态占据 46.19px，收起态占 31.69px，存在 14.5px 几何断层。
> 2. **Range 测量失效**：`measure.ts` 对 `display: none` 进行 `Range.getBoundingClientRect()` 永远返回 `(0, 0, 0, 0)`，迫使测量跌入 `measureLineFallback`，导致光标甩至行首。

### 解决方案：Slot Invariance 与 Ghost Token Stream 架构

必须彻底废除 `display: none`。

1. **Ghost Token Stream（幽灵字符流）**
   源码字符不仅不能 `display: none`，还要让它保留合法的物理几何锚点。
   ```css
   .syntax-hidden {
     /* 摒弃 display: none，使用视觉隐藏与不响应事件 */
     opacity: 0;
     pointer-events: none;
     color: transparent;
     /* 保持占据空间 */
     display: inline-block;
   }
   ```
2. **等宽槽位守恒（Slot Invariance）**
   要使视觉 Widget 占宽严格等于源码占宽（N * ch），采用网格绝对布局：
   - 对于 Markdown 任务列表标记 `- [ ] `（6个字符，占用 6ch 等宽）：
   ```css
   .slot-container {
     position: relative;
     display: inline-block;
     width: 6ch; /* 严格等于源码字符数宽度 */
   }
   .ghost-stream {
     opacity: 0; pointer-events: none; user-select: none;
   }
   .visual-widget {
     position: absolute;
     left: 50%; top: 50%;
     transform: translate(-50%, -50%);
     /* 视觉组件悬浮渲染，绝对不影响底层字符流的几何占位 */
   }
   ```
   **优势**：由于文本节点并未真正消失（只是不可见），`Range` 测量永远能拿到绝对精准的 BoundingClientRect，彻底消除横移 ΔX ≡ 0。

## 简答题 3：双层无盲区光标几何投影管线（Caret Projection Pipeline）

> [!WARNING]
> **病因剖析**：`src/core/measure.ts` 存在粗暴的 `measureLineFallback`，一旦抛锚就把光标扔到 `(line.left, line.top)`。同时 `posCache` 缺少依赖感知，在装饰态切换（展开/收起）时提供旧坐标。`HiddenInput.tsx` 中出现抢拉视口的丑陋代码。

### 解决方案：两级投影体系与刚性缓存联动

1. **彻底抹除 `measureLineFallback` 行首退化，引入两级投影（Tier 1 & Tier 2）**
   ```typescript
   function measureTokenExact(entry: TokenEntry, offsetInToken: number): MeasuredRect | null {
     // Tier 1: 纯文本物理 Range 快速测量
     const located = locateTextNode(entry, offsetInToken);
     if (located) {
       // ... 执行 Range 测量 ...
       return rect;
     }
     
     // Tier 2: 复合 Widget 盒模型比例几何插值投影
     // 当遇到没有 TextNode 的幽灵槽位或 Widget 时，严禁退化到行首，而是进行几何插值。
     const er = entry.el.getBoundingClientRect();
     const ratio = offsetInToken / Math.max(1, entry.length);
     const cursorHeight = 14 * 1.15;
     
     return {
       left: er.left + ratio * er.width,
       top: er.top + (er.height - cursorHeight) / 2,
       height: cursorHeight,
       bottom: er.top + (er.height + cursorHeight) / 2
     };
   }
   ```
2. **刚性缓存联动：`decorationVersion` 挂载**
   修改 `posCache` 的键值计算：
   ```typescript
   // 缓存键必须感知激活态装饰的突变
   const cacheKey = `${index}:${container.scrollTop}:${container.scrollLeft}:${decorationVersion}`;
   ```
3. **剥离抢拉逻辑（Scroll Hijacking）**
   彻底剥离 `HiddenInput.tsx` 中的强写 `scrollTop` 的抢拉逻辑。滚动跟随应该由单独的 `ScrollAnchorEffect` 或者集成在 `TanStack Virtualizer` 中的 `scrollToIndex` 控制，杜绝组件内部直接突变 `container.scrollTop`。

## 简答题 4：多模态自适应行高树（HeightMap）与平滑视口锚定

> [!IMPORTANT]
> **病因剖析**：`HeightMap.ts` 当前存在严重失真的魔术常量倍率（标题 1.3 倍，公式 1.15 倍）。这导致滚动预测完全错误（如 KaTeX 实测 87.2px 预测却只有 32.2px），触发大量的 `resizeItem` 导致画面颠簸卡顿。

### 解决方案：AST 特征预测模型与单向自适应回填

1. **废除魔术常量，引入 AST 衍生预估（Ast-Derived Predictor）**
   在 `predict` 阶段，通过直接扫描源码特征来动态计算初始估值，而不是盲猜。
   ```typescript
   predict(kind: LineKind, raw: string, _codeState: CodeState | boolean): number {
     if (kind === 'math') {
       // 预估公式高度：扫描换行符特征（多行特征预留）
       const lines = raw.split('\n').length;
       return lines * 40; // 假设每行公式平均占据 40px
     }
     if (kind === 'table_row') {
       // 表格列数卷积：扫描列数和最大单元格长度，预测 wrap 导致的高度膨胀
       const pipes = raw.split('|').length - 1;
       // 精算高度逻辑...
     }
     // ...
   }
   ```
2. **挂载后的单向自适应回填树（Adaptive Backfill）**
   利用 `ResizeObserver` 获取元素的 `offsetHeight`，调用 `HeightMap.setHeight` 时：
   - 只要发生 `|measured - stored| > STABLE_EPSILON`，便触发脏标记 `dirtyMin`；
   - **单向流动**：高度测量始终从 DOM 往 Tree 单向更新，绝对禁止 `HeightMap` 反向硬编码修改 DOM 的 `style.height`，由外部的 Virtualizer 同步消费。
3. **平滑视口滚动锚定（Scroll Anchoring）**
   为了避免上方行高自我修正导致的当前阅读区（或编辑光标）发生颠簸：
   - 在触发 `HeightMap` 更新时，计算上方所有块的累积修正误差 `ΔH`。
   - 同步通过浏览器底层的 `scrollBy(0, ΔH)` 补偿视口的偏移量。
   - 或依靠原生 CSS `overflow-anchor: auto` 挂载在滚动视口的每一个行元素，保证视口中处于激活交互状态的节点纹丝不动，避免卡顿与颠簸。
