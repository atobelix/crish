# 子代理协作与生命周期架构总案（2026-10-28）

> **战役工作区**：`docs/subagent-collaboration-redesign/`
> **性质**：系统性设计（非补丁清单）。目标 = 让子 agent 成为主 agent 的助力，而不是权限/配置/通信上的阻力；支撑 24 小时长程任务与断线重连。
> **实施进度（2026-10-28）**：S1 领域抽取已落地（`crates/conex-agents`：任务/能力/状态、可配 `SpawnPolicy`、`AgentPolicy`/`CommPolicy` 预设、`AgentFault`、端口）。旧 `RecursionGuardConfig` 与 16 硬上限已删除；默认扁平（depth=1）+ 数量不限。详见 [01-分维 §七](./01-分维-Crate边界与可扩展基础设施.md)。
> **用户口径（裁决原文摘要）**：
> - 权限默认继承父 agent，父变更时子同步；子可只读，也可由只读转可编辑；保留申请机制兜底。
> - 深度只是默认值，只有主 agent 可以调整；机制要可扩展，不写死。
> - 数量原则上不限制；服务商限流等压力由主 agent 审时度势调整。
> - agent 之间主要是通信与协作；错误要有明确错误码 + 让主 agent 可调整的机制，并带上下文反馈。
> - 通信分即时/非即时；紧急信息可单独计数并配更长窗口计数器；参数只给合理默认，不硬编码。
> - 子代理提示词的针对性附加上下文是基本操作。

## 一、现状勘测（证据）

| 能力 | 现状 | 结论 |
| :--- | :--- | :--- |
| 权限继承 | spawn 时快照：显式 > 父 `ActiveRun.permission_mode` > Smart（`subagent_spawner/spawn.rs:120-130`） | 只继承一次，父变更不同步 |
| 运行时权限变更 | 无入口；`ToolBatchOptions.permission_mode` 在 run 装配时固化（`run_launch.rs:1352`） | 主 agent 自己也不会跟随设置切换 |

| 工具面 | 子代理注册表剔除 `run_subagent` / `kill_subagent` / `send_message`（`run_launch.rs:1030-1039`） | 子代理**没有**向父 agent 主动发消息的能力；子→父只有终态 steering 通知 |
| 深度/数量 | `RecursionGuardConfig` 常量默认 depth=1 / siblings=16 / concurrent=16（`guard.rs:27-31`） | 写死，主 agent 不可调 |
| 模型分配 | `model_override` 在所有构造点显式 None、不落库、不消费（`contract.rs:96-100`） | 死字段；子代理永远用当前全局 provider |
| 错误反馈 | spawn 错误有码（`subagent.*`），但容量/限流只有文案；恢复阶梯存在（AutoRetry→Steering→Fork→User） | 缺机器可执行的「建议动作 + 负载快照」 |
| 运行中汇报 | `subagent-event(kind=progress)` 是 Delta 观测事件，不落库、不进父 agent 上下文（`run_resume.rs:794-870`） | 父 agent 看不到子代理过程，只能等终态 |
| 断线重连 | run/事件持久化，`resume_subagent` 可 fork 重派 | 启动后无「未终态子代理对账」；主 agent 不知道谁被中断 |
| 通信防风暴 | steering 队列有容量/分组替换（`steering_queue.rs:149-226`），终态通知单条入队 | 无即时/摘要分级、无速率窗口、无紧急长窗口配额 |

## 二、设计原则

1. **权限不是门槛，是能力协商**：默认继承、运行时生效、只可收窄；申请是兜底而不是前置配置。
2. **单一真源，双面存储**：`session_agents`（持久身份/配置）+ `ActiveRun`（运行时活状态）；不复制第三份。
3. **活单元（Live Cell）代替广播**：权限/能力/模型用共享可变单元，读取方在工具批次边界取最新值，避免事件风暴与竞态。
4. **错误是一等数据**：每个失败都有码、范围、可重试性、负载快照、可执行建议；错误自动回流到主 agent 的决策上下文。
5. **策略可调，不写死**：深度/并发/通信节奏都是 `AgentPolicy` 字段，主 agent 可改；代码只提供默认值与安全兜底。
6. **通信有背压**：即时通道只给「需要立刻决策」的信息；过程信息走摘要通道，避免 24h 任务把主 agent 唤醒风暴打爆。
7. **优雅扩展**：新增一种能力/通道/错误类型只动枚举与策略，不改调度骨架。

## 三、核心抽象（最小集合）

```
AgentRegistry (per session, 持久)
  └─ AgentRecord { agent_id, run_id, session_id, parent_run_id, depth,
                   task_type, capability, model_override, status, resumable, created_at }

AgentHandle (runtime, 由 ActiveRun 持有)
  ├─ LivePermission   // 运行时权限解析（读父链，批次边界取值）
  ├─ CapabilityCell   // read-only / read-write / execute / all（可升降）
  ├─ ModelCell        // Option<model>（运行中切换，下一次模型调用生效）
  ├─ Mailbox          // 即时队列 + 摘要缓冲 + 令牌桶
  └─ FaultLog         // 最近失败（供上报与恢复）

AgentPolicy (session_meta 持久，主 agent 可改)
  ├─ spawn: { max_depth, allow_child_spawn, max_active_per_parent?, max_active_per_session? }
  ├─ capability: { default_by_task_type, upgrade_requires_approval }
  ├─ communication: CommPolicy
  └─ durability: { heartbeat_timeout_ms?, interrupt_policy, retention_days? }

AgentBus (通信)
  ├─ instant(msg)   // 立即入 steering（可配置绕过摘要桶）
  ├─ digest(msg)    // 摘要缓冲，按时间/条数/字节/父空闲触发 flush
  └─ throttle       // 普通/紧急两级令牌桶 + 长窗口计数器 + 合并去重

ProviderResolver (模型)
  └─ resolve(model_override) -> Arc<dyn ProviderCall>（按 model 复用缓存）

AgentFault (错误信封)
  └─ { code, scope, retryable, retry_after_ms, load, details, suggested_actions[] }
```

不引入消息中间件、不引入第二套事件存储：通信落地仍是 steering 队列 + 既有事件表。

## 四、权限与能力模型

### 4.1 权限（PermissionMode：Ask < Smart < Full）

- **有效权限 = min(父当前权限, 子请求权限)**。子请求只能收窄，不能放宽；未请求则等于父当前权限。
- **运行时解析**：子 run 的工具批次装配时，经 `LivePermission::effective()` 沿父链读取父 `ActiveRun` 的当前值；父已终态则读父最后持久化值（`session_meta`/`runs`）。
- **父变更同步**：新增 `core_set_permission_mode(run_id, mode)`（命令 + 主 agent 工具），更新父 run 的权限单元与 `session_meta`；父自身与所有子代理在**下一个工具批次**自动生效，无需广播。
- **兜底**：父不可达（进程重启/记录缺失）时回退 spawn 时的快照（`SubagentRunConfig.permission_mode`）。
- 审批链路不变：子代理审批 → 主 agent（死锁检测命中 → 用户）。

### 4.2 能力（Capability，与权限正交）

- 四档沿用现有枚举：`read-only / read-write / execute / all`。
- **默认值**：由 `task_type` 默认集给出（analysis/organization=read-only，design/review=read-write(仅文档)，implementation=read-write+execute，commit=execute(git)），可由 spawn 显式指定，只能 ≤ 父能力。
- **运行时存储**：`CapabilityCell` 挂在 run 上，并持久化到 `session_agents.capability_mode`。
- **升级/降级**：
  - 子代理 `request_capability(to, reason)` → 作为 `Question` 即时消息到父 → 父 `grant_capability(agent_id, to)`（或用户审批）。
  - 父可主动 `grant_capability`；降级立即生效（下一批次）。
- **执行面 gate**：写类/执行类工具在分发点按 `CapabilityCell` 判定（fail-closed，返回 `subagent.capability_denied` + 申请建议）；spawn 时的注册表裁剪保留为纵深防御。
- 申请被拒也是结构化 `AgentFault`（`suggested_actions` 含「缩小任务范围 / 改用只读产出」）。

## 五、模型分配与切换

### 5.1 三个时刻

| 时刻 | 机制 |
| :--- | :--- |
| 初次分配 | `run_subagent` 增加 `modelOverride`（已有字段转正）；落入 `SubagentRunConfig` + `session_agents.model_override` |
| 运行中切换 | 主 agent 工具 `switch_agent_model(agent_id, model)` → 更新 `ModelCell` + 持久化；**下一次模型调用（下一 turn）生效**，不打断在途请求 |
| 停止后再启动 | `resume_subagent` 增加 `modelOverride`；未传则沿用持久化值 |

主 run 同一机制（设置切换模型后，下一 turn 生效），解决「设置改了但当前 run 还走旧模型」。

### 5.2 实现

- `ProviderResolver`：以当前生效配置为模板，`model` 作为覆盖键构建 `ProviderCall`，按 `(base_url, key, endpoint, model, protocol)` 缓存复用。
- `SwitchingProvider`：实现 `ProviderCall` 的委托壳，每次调用前读 `ModelCell` 并解析 provider —— session-loop 不需要知道模型可变。
- 模型不可用（404/未配置/额度耗尽）→ `AgentFault{ code: subagent.model_unavailable, suggested_actions:[switch_model, resume_with_model] }`，即时到父。
- 不做：子代理独立凭据/独立 baseURL（同一供应商配置，仅模型名可换）。

## 六、调度与容量

### 6.1 深度：默认值，不是常量

```rust
SpawnPolicy {
  max_depth: Option<u32>,     // 默认 Some(1)：主 agent→子代理，扁平
  allow_child_spawn: bool,    // 默认 false；为 true 且未到 max_depth 时，子代理注册表才包含 run_subagent
  max_active_per_parent: Option<u32>,  // 默认 None（不限）
  max_active_per_session: Option<u32>, // 默认 None（不限）
}
```

- 深度 = 从主 agent 起算的代数；主=0，直接子=1。
- **只有主 agent 可改**：`configure_agents` 工具仅存在于主 agent 注册表；子代理注册表永远剔除它。
- 默认扁平（1）；主 agent 显式提高 `max_depth` + `allow_child_spawn=true` 才允许嵌套；祖先环检测（`check_ancestor_chain`）保留。
- 硬编码 `DEFAULT_RECURSION_GUARD` 降级为「策略默认值」；守卫读取 `AgentPolicy`。

### 6.2 数量与压力

- 默认不限制兄弟/全局数量（`None`）；主 agent 可按服务商压力自行设置软上限。
- 压力信号：容量拒绝错误携带 `load { active_agents, active_siblings, provider_pressure_1m, queue_depth }`；provider 429/5xx 计入 `provider_pressure` 并在 spawn/wait 的 fault 中回传。
- `suggested_actions` 直接给出可执行调整：`configure_agents(max_active_per_session=8)` / `wait(30s)` / `reduce_scope`。
- 批量 spawn 保持现有原子语义（任一守卫拒绝 → 零 run）。

## 七、通信协议（即时 / 摘要）

### 7.1 消息模型

```rust
AgentMessage {
  id, from, to,
  kind: Instruction | Progress | Question | Fault | Result | Notice,
  priority: Critical | Normal,
  dedupe_key: Option<String>,   // 同键合并（进度/状态类）
  created_at, expires_at: Option<u64>,
  payload: Value,
}
```

### 7.2 通道与路由

| kind | 通道 | 说明 |
| :--- | :--- | :--- |
| Instruction（父→子） | instant（子 inbox，下一安全点消费） | 现有 L1 steer/注入 |
| Question（子→父） | instant（critical 桶） | 需要父决策；可带选项 |
| Fault（子→父/系统） | instant（critical 桶，必达） | 终态/容量/模型/能力错误 |
| Result（子→父） | instant | 子代理终态摘要 |
| Progress（子→父） | digest | 过程信息，合并成批 |
| Notice（系统） | digest | 对账/策略变更/降级提示 |

- 子代理新增 `report_progress`（可自动埋点）与 `ask_parent` 工具；`send_message` 对子代理开放「子→父」方向（父→子保持现状）。工具面仍剔除 `run_subagent`（除非策略允许嵌套）。
- 父→子指令也走令牌桶，避免主 agent 对单个子代理刷屏。

### 7.3 节流参数（默认值，全部可配）

```rust
CommPolicy {
  digest_interval_ms: 90_000,
  digest_max_items: 20,
  digest_max_bytes: 8_192,
  digest_flush_on_parent_idle: true,
  instant_capacity: 3, instant_refill_per_min: 3,
  critical_capacity: 5, critical_refill_per_hour: 12,
  critical_cooldown_ms: 600_000,      // 紧急桶耗尽后的长窗口抑制
  coalesce_window_ms: 5_000,
  suppress_marker: true,              // 被抑制时在摘要中标注 [N 条已合并/抑制]
}
```

- 普通即时桶与紧急桶独立；紧急消息可绕过普通桶，但消耗紧急配额；紧急配额耗尽进入长窗口冷却（长计数器），期间 Fault 仍必达（安全优先）。
- 溢出策略：同 `dedupe_key` 合并；否则写入下一次摘要并附计数标记，不静默丢弃。
- 24h 效果：过程信息不再逐条唤醒主 agent；主 agent 空闲时一次摘要唤醒；错误即时到达。

## 八、错误模型与反馈闭环

```rust
AgentFault {
  code: String,                  // 复用 subagent.* 并新增：capacity_pressure / capability_denied / model_unavailable / comm_throttled / interrupted
  scope: Spawn | Run | Tool | Capability | Communication | Provider,
  retryable: bool, retry_after_ms: Option<u64>,
  agent_id / run_id: Option<String>,
  load: Option<{ active_agents, active_siblings, provider_pressure_1m, queue_depth }>,
  details: Value,
  suggested_actions: Vec<AgentAction>,
}
AgentAction = ConfigureAgents{..} | Wait{ms} | SwitchModel{model} | GrantCapability{..}
            | ResumeSubagent{..} | ReduceScope | AskUser
```

- 出现位置：`run_subagent`/`wait_subagents` 工具结果、`subagent-ended.payload.fault`、子→父即时消息、摘要行。
- 恢复阶梯（已有 AutoRetry→Steering→Fork→User）复用同一信封：阶梯 2/4 的通知从自由文本升级为 fault + suggested_actions；阶梯 1 重试保留。
- 原则：**永不静默**。可降级（progress 可丢）但错误、终态、容量拒绝必须可达。

## 九、生命周期、断线重连与 24h

- **持久真源**：`session_agents`（identity/config/status/resumable）、`runs`（终态/usage）、事件表（历史）。运行中句柄在 `ActiveRun`。
- **启动对账**：进程启动/客户端重连时，扫描 `session_agents` 中非终态但无活 run 的代理 → 置 `interrupted` + `resumable=true` → 向父发一条 `Notice`（摘要）或 `Fault`（若策略要求立即）；不自动重派，由主 agent 决定（可配 `auto_resume_on_restart`）。
- **客户端重连**：按事件游标重放 + 注册表恢复 UI；引擎内 run 不受客户端断连影响（现有模型）。
- **心跳**：子代理 run 在每轮/进度点更新 `last_heartbeat`；watchdog 阈值走策略（默认沿用现有 120s）。
- **预算**（可选策略）：每 agent 的 token/时长预算，超限发 `Fault`（非硬杀，主 agent 决定收尾或续）。
- **清理**：terminal 记录保留天数策略；活跃数量无硬上限但由注册表与调度队列自然有界。

## 十三、分阶段实施与验收

### P0 · 权限与能力（改动最小、收益最快）
- LivePermission（min 规则 + 运行时读取 + `set_permission_mode`）。
- CapabilityCell + 执行面 gate + `request_capability` / `grant_capability`。
- `AgentPolicy` 取代常量守卫：depth 默认 1、可调；并发默认 None；`configure_agents` 仅主 agent。

**验收**：父切 Full→子下一批次变 Full；子请求超过父 → 被钳制并返回 info fault；read-only 子写文件 → `capability_denied`，授权后同 run 内写入成功；depth=1 时子代理无 spawn 工具，主 agent 调到 2 后子代理可派发；并发默认不拒绝，设置软上限后拒绝带 load/suggested_actions。

### P1 · 通信
- AgentBus（instant/digest、双桶、合并/抑制标记）；子→父 progress/ask/result；父→子指令限速。
- 提示词协作协议段。

**验收**：100 条 progress 在 90s 内合并为 ≤1 条摘要唤醒；critical 超限后进入冷却但 fault 仍达；子代理提问 1s 内唤醒父；摘要含抑制计数。

### P2 · 模型
- ProviderResolver + SwitchingProvider + 持久化；spawn/switch/resume 三入口。

**验收**：运行中切模型下一次调用生效；resume 默认沿用持久化模型；模型不可用返回可执行 fault。

### P3 · 长程与重连
- 启动对账、interrupted/resumable、摘要通知；24h 浸泡测试（心跳、心跳超时、摘要节奏、内存/句柄稳定）。

**验收**：杀进程重启后未终态代理全部收敛为 interrupted 且有据可查；主 agent 收到一条汇总通知；不自动重派。

## 十四、取舍与明确不做

- **不做分布式多机 agent**；仍是单进程引擎。
- **不做每 agent 独立凭据/独立 baseURL**；只做模型名覆盖。
- **默认不嵌套**（depth=1）；允许主 agent 显式打开，但祖先环检测常驻。
- **不做无界内存缓冲**：摘要与即时队列都有容量与合并策略，参数可配。
- **不把 progress 写进上下文**：process 只进摘要；只有 fault/question/result 即时。
- **不复活注入大卡片**：前端展示走既有轻量状态/消息通道（AGENTS §21）。

## 十五、开放决策（待用户拍板）

1. 默认并发：彻底无上限（`None`）还是给一个高默认（如 64）防失控？本方案默认 `None`，压力由 fault 反馈。
2. 摘要默认节奏：90s/20 条/8KB 是否合适？可整体调。
3. 只读升级默认路径：子申请→父批准（本方案默认）；是否也允许父无需申请直接授权？本方案允许。
4. 运行中模型切换粒度：下一 turn（本方案）；是否需要「立刻中断重发」选项（会丢失在途流）。
