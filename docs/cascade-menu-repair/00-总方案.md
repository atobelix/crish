## 1. 问题根因与架构全景总结

在 Conex / Crish 桌面端应用中，用户在底部工具栏激活 `ModelBadgePickerMenu` 时，Hover 服务商行导致二级级联面板不可见且主菜单右侧突发滚动条，根本原因由以下四重因素交织形成：

1. **CSS 包含块裁剪（物理截断）**：
   - 基座 `Menu.module.css`（`.menuContent`）与 `ModelBadgePickerMenu.module.css`（`.mbMenu`）声明了 `overflow-y: auto; overflow-x: hidden;`；
   - 二级子菜单 `.mbSubMenu` 声明了绝对定位 `position: absolute; right: calc(100% + 4px);` 并内联嵌套在服务商行内部；
   - 根据 W3C 盒模型规范，水平向左延伸 194px 的子菜单超出滚动容器 Padding Box，在 X 轴被 100% 裁剪隐形；
   - 子菜单的垂直高度（280px）撑大了父容器的 Scrollable Overflow Area，在 Y 轴触发了截图中可见的异常滚动条。
2. **声明式 `autoFocus` 焦点劫持与滚动震荡**：
   - 子菜单首个模型按钮上硬编码了 `autoFocus={modelIndex === 0}`；
   - 鼠标 Hover 展开时 React Mount 强制执行浏览器原生 `focus()`，不仅剥夺了外部交互焦点，更触发了隐式 `scrollIntoView`，导致主菜单内部产生微小位移，使鼠标脱离服务商行触发 `mouseleave` 闪退。
3. **视口边界越界隐患**：
   - 硬编码向左展开与 `<Lucide.ChevronLeft />`，在靠左视口（$X < 190\text{px}$）或 600px 窄窗口下会导致子菜单出现负坐标（$X < 0$）穿出屏幕左侧。
4. **浮层拓扑与 LayerStack 脱节**：
   - 若直接将子菜单 Portal 化而未向 `LayerStackManager` 注册 `parentId`，点击子菜单会被父级 Radix Popover 的 `onPointerDownOutside` 误判为外点点击，从而瞬间误杀父菜单。

## 3. 具体实现方案与修改清单

### 3.1 [MODIFY] `apps/crish-desktop/src/components/ui/Menu/position.ts`
新增纯函数几何定位算法，内置**刚性双向数学钳位**：
```typescript
export interface SubmenuPlacementResult {
  x: number;
  y: number;
  side: 'left' | 'right';
  transformOrigin: string;
}

export function calculateSubmenuPosition(
  rowRect: DOMRect,
  submenuWidth = 190,
  submenuHeight = 280,
  sideOffset = 4,
  edgePadding = 8
): SubmenuPlacementResult {
  const vp = getEffectiveViewport();
  const minX = vp.offsetLeft + edgePadding;
  const maxX = vp.offsetLeft + vp.width - edgePadding;
  const minY = vp.offsetTop + edgePadding;
  const maxY = vp.offsetTop + vp.height - edgePadding;

  const spaceLeft = rowRect.left - minX - sideOffset;
  const spaceRight = maxX - rowRect.right - sideOffset;

  let side: 'left' | 'right' = 'left';
  let targetX = rowRect.left - submenuWidth - sideOffset;

  // 当左侧放不下且右侧空间更大时，翻转至右侧展开
  if (submenuWidth > spaceLeft && spaceRight >= spaceLeft) {
    side = 'right';
    targetX = rowRect.right + sideOffset;
  }

  // 双向刚性数学钳位，绝对杜绝任何负坐标 (X >= minX) 与右侧越界 (X + W <= maxX)
  const clampedX = Math.min(
    Math.max(minX, targetX),
    Math.max(minX, maxX - submenuWidth)
  );

  // 垂直方向：默认顶部对齐 (top: rowRect.top - 4)，底部贴边向上钳位
  const targetY = rowRect.top - 4;
  const clampedY = Math.min(
    Math.max(minY, targetY),
    Math.max(minY, maxY - submenuHeight)
  );

  return {
    x: clampedX,
    y: clampedY,
    side,
    transformOrigin: side === 'left' ? 'top right' : 'top left',
  };
}
```

### 3.2 [MODIFY] `apps/crish-desktop/src/components/ui/Menu/Menu.tsx`
1. 导出 `MenuContext`：
   ```typescript
   export const MenuContext = React.createContext<{ menuId: string | null }>({
     menuId: null,
   });
   ```
2. 在 `Menu` 内部通过 `<MenuContext.Provider value={{ menuId }}>` 向下传递；
3. 在 `Popover.Content` 的 `onPointerDownOutside` 与 `onInteractOutside` 中放行子孙 Layer：
   ```typescript
   onPointerDownOutside={(e) => {
     if (onPointerDownOutside) {
       onPointerDownOutside(e);
       return;
     }
     const target = e.detail.originalEvent.target as Node | null;
     const triggerEl = anchor?.current ?? triggerRef.current;
     if (triggerEl && target && triggerEl.contains(target)) {
       e.preventDefault();
       return;
     }
     // 放行属于该菜单子孙的 Portal 浮层点击，防止误杀父菜单
     const isDescendant = layerStackService
       .getDescendants(menuId)
       .some((child) => {
         const el = child.elementRef.current;
         return el && target && el.contains(target);
       });
     if (isDescendant) {
       e.preventDefault();
     }
   }}
   ```
