> **维度**：W1（基础层，无前置依赖）

## 2. 目标态

### 2.1 引入单一身份类型（TS 与 Rust 各一份，语义同构）

**TS**（落在 `apps/crish-desktop/src/api/modelsCatalogTypes.ts`，与既有树契约同文件）：

```ts
/** 模型在系统中的唯一身份。任何解析/索引/匹配/选中判定都必须携带完整二元组。 */
export interface ModelRef {
  readonly providerId: string;
  readonly modelId: string;
}

/** 归一化：两段均 trim + 小写，与 modelsCatalogStore.buildIndexes 的索引键一致 */
export function normalizeModelRef(ref: ModelRef): ModelRef;
/** 唯一序列化形式（用于 Map 键 / 比较 / 日志），禁止各处自行拼接 */
export function modelRefKey(ref: ModelRef): string;   // `${normPId}::${normMId}`
export function sameModelRef(a: ModelRef, b: ModelRef): boolean;
```

**Rust**（落在 `crates/agent-provider/src/models/catalog_types.rs`）：

```rust
/// 模型唯一身份。lookup 的入参形态。
#[derive(Clone, Debug, PartialEq, Eq, Hash)]
pub struct ModelRef { pub provider_id: String, pub model_id: String }
impl ModelRef {
    pub fn new(provider_id: impl Into<String>, model_id: impl Into<String>) -> Self;
    pub fn normalized(&self) -> Self;              // trim + lowercase
    pub fn key(&self) -> String;                   // "{pid}::{mid}"
}
```

**约束**：`LiveModels::find` 的既有签名 `find(provider_id, model_id)` **保持不变**（承上游契约），`ModelRef` 只作为调用方组织入参的载体，不新增第二套 lookup。

### 2.2 删除所有裸 `modelId` 跨供应商解析

| 位置 | 现状 | 目标 |
| --- | --- | --- |
| `profileValidation.ts:359-368` | `normalized.find((x) => x.models.includes(storedModel))` | **物理删除该分支**。仅有 modelId 而无 providerId 时，**不解析**（返回 `null`，交给 W2 的置空语义）。 |
| `profileValidation.ts:379-385` | `normalized.find((x) => x.models.includes(engineModel))` | **物理删除该分支**。`engineModel` 若不带 provider 信息则不可用于定位（见 §5 未确认项 5）。 |
| `modelCatalogPure.ts:133-166` | `pickDefaultCatalogEntry` 裸 id 匹配 | 若无生产消费者则**物理删除**；若有，改为接收 `ModelRef`。 |
| `modelsCatalogSelectors.ts:32-35` | `globalModelIndex.get(normMId)` → `list[0]` | **物理删除** `selectModelGlobally` 或改为返回 `IndexedModelEntry[]`（全部同名候选）并由调用方按 providerId 消歧。禁止返回单个 `[0]`。 |
| `catalog.rs:479-487` | `lookup_by_model_id` | **物理删除**（全仓零引用）。 |

### 2.3 分支顺序重构（`pickDefaultModelSelection`）

删除跨厂商分支后，解析优先级收敛为**全部带 providerId**：

```
1) storedProfileId + storedModel  且 该 provider 的 models 含该 model   → 采纳
2) storedProfileId（无 storedModel 或不在列表）→ 该 provider 首个模型  → 采纳
3) 无 storedProfileId → 返回 null（不猜、不跨厂商）        ← W2 置空语义
```

**关键**：`first_available`（现分支 5/6，`profileValidation.ts:387-405`）**同样删除**——它会在「没有任何活动选择」时自动挑一个可用模型，直接违反 U1。取而代之的是返回 `null`，由 UI 显示「未配置模型」。

### 2.4 三处同源（INV-4）

| 处 | 当前源 | 目标源 |
| --- | --- | --- |
| 设置界面模型页 | localStorage（服务商档案）+ yaml 镜像（模型列表） | **全部读 yaml 镜像**（`modelsCatalogStore`）。服务商档案中的 `name`/`enabled`/`baseUrl` 若与 yaml 冲突，**yaml 赢**。 |
| 对话界面选择器 | yaml 镜像（已正确） | 保持 |
| yaml 文件 | — | **唯一可编辑面** |

**服务商档案（localStorage）的定位裁决**：降级为「**凭据与运行期偏好**」容器，**不再承载** `models` 列表与 `baseUrl` 的权威值（权威值在 yaml）。W2 负责切除活动选择字段，W3 负责切除字典回落；本维负责**读取时 yaml 优先**。

## 4. 验收断言

### A 源码形状
- `modelsCatalogTypes.ts` 导出 `ModelRef` 及其 3 个函数。
- `profileValidation.ts` 中不再存在 `models.includes(storedModel)` / `models.includes(engineModel)` 形式的**跨厂商** find（分支 1 内的同 provider `p.models.includes(...)` 保留，因其已由 `byId(storedProfileId)` 限定）。
- `profileValidation.ts` 中不再存在 `first_available` 字样。
- `modelsCatalogSelectors.ts` 中 `globalModelIndex.get(...)` 后不再直接 `[0]` 返回单个对象。
- `catalog.rs` 中 `lookup_by_model_id` grep = 0。

### B 本会话真跑测
- 新增单测：两供应商 A、B 都含 `same-model`；`pickDefaultModelSelection(profiles, { storedModel: 'same-model' })`（**无** `storedProfileId`）→ 断言返回 **`null`**（而非命中 A 或 B）。
- 新增单测：`pickDefaultModelSelection(profiles, { storedProfileId: 'a', storedModel: 'same-model' })` → 断言返回 `{ profileId: 'a', model: 'same-model' }`。
- 新增单测：`pickDefaultModelSelection(profiles, {})`（无任何 stored）→ 断言 `null`。
- 既有测试 `providerProfiles.test.ts:983-991` 的 `stored_model_match` 正例**必须同步更新或删除**（该分支已不存在）。
- 新增 Rust 单测：`ModelRef::key()` 归一化正确；`find(pid, mid)` 双键命中，同名不同 provider 返回各自条目。

### C 真实宿主用户路径
- 建 A、B 两家，各加同名模型；在设置页与对话选择器中**分别**选中 A 的同名模型与 B 的同名模型 → 断言：两处选中态**互不干扰**（选中判定按二元组）。

## 5. 未确认项（实现时必须先钉）

1. `engineModel` 的来源是否携带 provider 信息 —— 若**不带**，则分支 4 删除后引擎回报的模型无法定位，需确认 W2 的置空语义是否会因此误判。**若确认不带，则引擎侧应补充回报 providerId**（属本维扩展）。
2. `modelCatalogPure.ts` / `modelsCatalogSelectors.ts` 的相关函数是否**真的**零生产消费者 —— 前序勘察已确认「无 UI 消费者」，但实现前需再 grep 一次以决定「删除」还是「改签名」。
3. `clientApi.updateSettings` 的其他调用点是否也写 `defaultModel`（影响 W2 能否彻底切除）。
