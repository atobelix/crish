## 2. 目标态

### 2.1 删除 `infer_vendor`（修复问题 17）

- **物理删除** `behavior.rs:310-360` 的 `infer_vendor`。
- 其唯一生产调用点 `cache_policy.rs:159`：该处需要 vendor 的场景，改为从 **yaml 的 provider 条目**取（`providerId` 即身份），或从 `CompatSpec` 的显式声明取。**禁止**任何 URL 子串 / 模型前缀推断。
- 同文件 `MODEL_SERIES_CACHE_BEHAVIOR`（`:380-413`）**物理删除**（模型 ID 硬编码）。
- 若 `behavior.rs` 删除这两块后无剩余内容 → **整个文件删除**。

**约束**：删除后若出现「无法决定缓存行为」的情形 → **fail-closed**（不追踪），**不得**回落到猜测。这与 W3 的 TTL fail-closed 一致。

### 2.2 `migration.rs` 厂商表限制在迁移边界（修复问题 18，N4）

`migration.rs:533-604` 的四张表（`default_base_url_for_vendor` / `infer_protocol_for_vendor` / `infer_compat_for_vendor` / `format_vendor_display_name`）：

**裁决**：**迁移是数据变换，允许一次性使用厂商表**，但必须满足：
1. **仅** `ConfigMigrationManager::ensure_migrated`（`models_yaml.rs:316`）可调用 —— 在 `migration.rs` 内将这四张表**改为私有**（`fn` 而非 `pub fn`），确保运行时无法从外部调用。
2. **删除** `_ => "https://api.openai.com/v1"` 的兜底 —— 未识别厂商应留**空 baseUrl**（用户必须自己填），**禁止**静默指向 OpenAI。这是 U4 的直接推论：不得替用户猜厂商。
3. 迁移完成后，这四张表**不再被任何非迁移路径引用**（负向断言）。

**若**确认存量迁移已全部完成（§5 未确认 1）→ 可直接**物理删除**这四张表 + 迁移分支，彻底净收敛。

### 2.3 协议字面量收敛为单一导出源（修复问题 21，N6）

/** 协议唯一枚举源。所有下拉、模板、默认值、归一化都从此派生。 */
export const PROTOCOLS = [
  'openai/chat',
  'openai/responses',

/** 旧名 → 规范名。唯一兼容点，仅读边界使用。 */
const LEGACY_PROTOCOL_ALIASES: Record<string, ModelProtocol> = {
  'google/interactions': 'google/generate-content',

export function normalizeProtocol(raw: unknown): ModelProtocol | undefined;

## 4. 验收断言

### A 源码形状
- `behavior.rs` 中 `infer_vendor` grep = 0。
- `behavior.rs` 中 `MODEL_SERIES_CACHE_BEHAVIOR` grep = 0。
- `cache_policy.rs` 中 `infer_vendor` grep = 0。
- `migration.rs` 中 `pub fn default_base_url_for_vendor` 等四函数 `pub` 修饰符 grep = 0（改为私有或删除）。
- `migration.rs` 中 `"https://api.openai.com/v1"` grep = 0。
- 生产代码（排除数据文件）中 `'openai/chat'` / `'anthropic/messages'` / `'google/generate-content'` / `'openai/responses'` 字面量**仅出现在 `modelsNormalize.ts`**（其他文件 grep = 0）。
- `directFetchBridge.ts` 中 `deepseek-v4-flash` grep = 0。

### B 本会话真跑测
- 单测：`normalizeProtocol('google/interactions')` → `'google/generate-content'`；`normalizeProtocol('openai/chat')` → `'openai/chat'`；`normalizeProtocol('乱写')` → `undefined`。
- 单测：`PROTOCOLS` 长度 = 4，且 `YAML_PROTOCOL_SELECT_OPTIONS` 的 value 集合与 `PROTOCOLS` **完全相等**（派生一致性断言）。
- 单测：新建供应商（不填 protocol）→ 断言落盘 yaml 的 `protocol` = `DEFAULT_PROTOCOL`（承上游 M15）。
- Rust 单测：迁移 v1 配置（含未知厂商）→ 断言 baseUrl 为**空**（**不**是 `https://api.openai.com/v1`）。
- Rust 单测：yaml 声明 protocol 的模型 → 断言协议决议取自 yaml，**不**受 baseUrl 影响（构造一个 baseUrl 含 `anthropic` 但 protocol 声明 `openai/chat` 的用例，断言结果是 `openai/chat`）。

### C 真实宿主用户路径
- 新增供应商，baseUrl 填一个含 `anthropic` 字样的第三方地址，protocol 选 `openai/chat` → 断言：请求按 `openai/chat` 发出（**不**被 URL 嗅探成 anthropic）。
- 迁移剧本：用一份含未知厂商的旧配置启动 → 断言：该供应商 baseUrl 为空且 UI 提示用户填写（**不**静默指向 OpenAI）。
