## 1. 定案：什么是「统一入口」

### 1.1 抽象层 = 一个词表 + 一个读 API + 一张每模型 map

「统一入口」不是「没有词表」，而是**只有一个词表、只有一个读口**。用户否掉的是 v1 之前那套**散落的常量表**：

| v0 旧方案的错 | 为什么错 |
| --- | --- |
| `PROTOCOLS` / `THINKING_LEVELS` / `PROTOCOL_LABELS` / `LEGACY_PROTOCOL_ALIASES` / `CANONICAL_*` 五张表散在 `modelsNormalize.ts` | 不是「一个入口」，是**五份各自为政的具体清单** |
| 归一表与真源表并存 | 每加一档要改多处，必然漂移 |

**v2 的形状**（消费方只依赖这三件）：

```
消费方（UI / 引擎 / 计费）
        ↓ 只依赖：词表（跨模型可比较的档位语言）
        ↓ 只依赖：modelsCatalogLive（唯一读 API）
modelsCatalogStore（yaml 镜像）
        ↓
~/.conex/models.yaml（每模型 thinking map = 用户配置面）
        ↓
内核 ReasoningEffort（词表唯一权威）
```

### 1.2 词表唯一权威 = 内核（已存在，不是新增）

内核**早已实现**封闭词表，本定案只是把它确认为权威，而非新建：

| 事实 | 证据 |
| --- | --- |
| 词表枚举 = `Off / Minimal / Low / Medium / High / XHigh / Max` | `crates/agent-provider/src/request/vendor.rs:99-111` `ThinkingIntensity`；`request/vendor/dialect.rs:77-87` `to_title_case()` |
| 别名接受集（读边界归一） | `request/vendor/dialect.rs:63-74` `from_title_case()`：`Off\|off\|None\|none\|Disabled\|disabled`、`Minimal\|minimal`、`Low\|low`、`Medium\|medium`、`High\|high`、`XHigh\|xhigh\|X-High\|x-high`、`Max\|max` |
| 强度序（用于排序 / 钳制） | `request/vendor_wire.rs:24-72`（1024/2048/4096/8192/16384 刻度） |
| 请求面白名单校验（fail-closed） | `apps/agent-workbench/src-tauri/src/engine_provider/thinking.rs:52-81` `validate_reasoning_effort` |
| 默认不降级策略 | `DegradePolicy`（默认 `Reject`）；降级仅在 `AllowDegrade` 下由 `normalize_thinking_intensity` 提供（`request/vendor.rs:214-241`） |

**参考实现一致**：`reference/pi` `packages/ai/src/types.ts:83-85` `ThinkingLevel = "minimal"|"low"|"medium"|"high"|"xhigh"|"max"`、`ModelThinkingLevel = "off"|ThinkingLevel`、`ThinkingLevelMap = Partial<Record<ModelThinkingLevel, string|null>>`。

#### 1.2.1 权威类型消歧（必读，避免改错文件）

内核存在**三个**相近类型，权威只有一个：

| 类型 | 位置 | 档位 | 角色 |
| --- | --- | --- | --- |
| **`ReasoningEffort`** | `crates/agent-provider/src/request/vendor/dialect.rs:36-47`（注释自称「2026 标准化思考强度等级」） | `Off/Minimal/Low/Medium/High/XHigh/Max`（**无 `Auto`**） | ✅ **词表唯一权威**：拥有 `from_title_case`（别名接受集）、`to_title_case`（规范拼写）、`assemble_thinking_dialect`（wire 注入） |
| `ThinkingIntensity` | `crates/agent-provider/src/request/vendor.rs:99-111` | 同 7 档 | 并行既有类型（budget 刻度消费，`vendor_wire.rs`）；**不是**权威，勿在此处新增档位 |
| `ReasoningEffort`（legacy） | `crates/agent-provider/src/request/vendor.rs:66-95` | 7 档 + **`Auto`** | 旧类型（dialect.rs 内以 `LegacyReasoningEffort` 别名引入）；`Auto` 属旧语义 |

**`Auto` 与前端哨兵 `default` 不属于档位词表**——它们是「跟随引擎默认/不注入显式档位」的**哨兵**，由 `parse_reasoning_effort`（`run_launch.rs:144`）与前端 `DEFAULT_THINKING_SENTINEL`（`clientApiNormalize.ts`）承载。**门禁与 UI 词表均不含 `Auto`/`default`**。

> 因此文档中凡写「词表唯一权威 = 内核 `ReasoningEffort`」，均指 **`request/vendor/dialect.rs` 的 `ReasoningEffort`**（7 档、无 `Auto`）。


### 1.3 前端词表：镜像 + 门禁守护（不新增架构）

前端需要词表来**排序、显示标签、校验本机偏好**。做法：

- 前端持**一份**镜像常量（唯一一处，例如 `apps/crish-desktop/src/api/modelsNormalize.ts` 的 `THINKING_LEVELS`，含规范拼写与顺序）。
- 新增门禁 `scripts/check-thinking-vocabulary-ssot.mjs`：解析 `dialect.rs` 的 `from_title_case` / `to_title_case` 分支与前端镜像常量，断言**集合与顺序一致**；不一致即失败。
- 镜像文件头标注「真源 = 内核 `ReasoningEffort`，由 `check-thinking-vocabulary-ssot.mjs` 守护，禁止手改顺序」。

> **可选增强（非本轮必须）**：把词表做成契约注册表项（`crates/conex-types/contracts/`）+ 生成器分发，彻底消灭手写镜像。当前生成器只硬编码 `engine-events` / `device-protocol` 两条分支（`scripts/generate-engine-bindings.mjs:1373-1384`），新增第三条属于扩展生成器，列为后续项。**门禁方案已满足 SSOT 要求且零新增架构（不撞 N9）。**

## 2. 每模型 map：用户唯一可配置面

### 2.1 形状（已存在，不新增 schema）

```yaml
providers:
  acme:
    models:
      - id: acme-thinker
        thinking:            # 键 = 词表档位（可用别名拼写）；值 = 该模型真实 wire 值
          Off: "off"
          Low: "low"
          High: "high"
          XHigh: "xhigh"
```

内核类型：`crates/agent-provider/src/models/catalog_types.rs:485` `pub thinking: Option<IndexMap<String, String>>`。

### 2.2 用户可配置什么 / 不可配置什么（边界必须写死）

| 项 | 可配置？ | 理由 |
| --- | --- | --- |
| 每模型**支持哪些档**（子集） | ✅ 是 | 能力是每模型的（实测 28/59 厂商内部有 reasoning 分歧，见 `survey/02`） |
| 每档的 **wire 值** | ✅ 是 | 各厂商 wire 拼写不同（google `"LOW"`、deepseek `"off"`） |
| 键的**别名拼写**（`None`/`Disabled`/`X-High`/大小写） | ✅ 是（读边界接受集，见 §1.2） | 由 `from_title_case` 定义，用户不必记规范拼写 |
| 是否声明 `thinking`（= 是否思考模型） | ✅ 是 | 整体缺省 = 非思考模型 |
| **词表本体**（新增第 8 档） | ❌ 否 | 词表连着内核强度序与 budget 刻度，任意增项无法推导语义 |

**词表扩展契约**（写死，供将来需要时执行）：新增档位必须**同时**改 ① `ThinkingIntensity`/`ReasoningEffort` 枚举 ② `from_title_case`/`to_title_case` ③ `vendor_wire` 强度刻度 ④ 前端镜像常量。门禁守护四处一致。**不允许只改 yaml 或只改前端。**

### 2.3 「强制思考」语义（不引入 null）

`thinking` 是 `IndexMap<String,String>`，**无法表达 null**。因此：

- **键缺失 = 该档不支持**；`thinking` 整体缺失 = 非思考模型。
- 「强制思考」= map 中**无关闭档键**（`Off`/`None`/`Disabled` 均未声明）→ UI 无关闭项。
- v1/N10 的「`null` = 显式不支持」**作废**（当前 schema 不可落地，且与「键缺失」表达重复）。

## 3. 档位失效：置空，不钳制（承 U1）

```
切换模型 / 供应商
    ↓
用户原选档位在该模型 thinking 声明中存在？（经别名归一后精确成员判定）
    ├─ 是 → 保留（原样交出 key 与 wire）
    └─ 否 → 置空，UI 显示「请选择思考档位」引导重选
```

**默认不降级**（与内核 `DegradePolicy::Reject` 默认一致，且对齐 U1「不强行给用户找一个能用的」）。

- **禁止**：回落字典首项、回落「默认档」、按强度序降级到最近可用档。
- 内核 `AllowDegrade` + `normalize_thinking_intensity`（`request/vendor.rs:214-241`）**保留为内核策略位，不由 UI 触发，不在任何维删除**——它是 `DegradePolicy` 的另一档语义，不是死代码。清册 C2 已按此登记（2026-09-13 修正：早前「删除属 W5」的表述作废）。
- **已落地**：`apps/crish-desktop/src/api/modelsCatalogLive.ts:144-180` `resolveThinkingHandoff`（未选/未命中 → `selectedTitle=null`）、`apps/crish-desktop/src/api/chat-bridge/readiness.ts:114-135`（空对象，不伪造 Off）、UI 引导文案见 `components/provider/ModelBadgePickerMenu.tsx:167-170`、`components/chat-composer/ComposerFusedTrigger.tsx:113-118`。

## 4. 词表外的键：显式诊断（不静默、不伪连通）

用户在 yaml 写了词表外的键时，**现状是两种坏结果**，必须消除：

| 现状 | 证据 | 后果 |
| --- | --- | --- |
| 键不能被 `from_title_case` 解析 → 请求面白名单校验失败 | `engine_provider/thinking.rs:73-75` | **硬拒**（`Err(InvalidRequest)`，网络 I/O 前） |
| wire 值不能被 `parse_reasoning_effort` 解析 → `None` | `apps/agent-workbench/src-tauri/src/run/run_launch.rs:142-154`（fail-open `_ => None`） | **静默不生效**（按提供方默认跑），用户以为生效 = 伪连通 |

**裁决**：

1. **配置界面侧（第一防线）**：用户保存 yaml 前，对每个模型的 `thinking` 键做词表校验（经别名归一）；有词表外键 → **明确提示**「档位键 `Xhigh` 不受支持，可用集合：Off / Minimal / Low / Medium / High / XHigh / Max」，阻止落盘或要求确认。
2. **内核侧（最后防线）**：`validate_reasoning_effort` 保持 fail-closed 拒绝，并在错误文案中**列出该模型可用的档位集合**（现文案只带 `UNSUPPORTED_REASONING_EFFORT` 标签，见 `engine_provider/thinking.rs:85-90`）。
3. **禁止**把词表外键当「自定义透传档」静默放过——那会让 `parse_reasoning_effort` 的 fail-open 变成用户可见的「档位没反应」。

## 5. 大小写与别名：归一在数据读取边界，不散落在调用方

### 5.1 两类大小写，处理方式不同

| 类别 | 例子 | 处理 | 落点 |
| --- | --- | --- | --- |
| **档位键** | `XHigh` vs `Xhigh`；`None` vs `Off` | **读边界归一**（接受集 = `from_title_case`）；规范拼写 = `XHigh` | 内核 `from_title_case`（已存在）+ 前端配置校验 |
| **providerId / modelId** | `Acme` vs `acme` | **精确匹配**（+首尾 trim），不做小写归一 | W10（见 §7） |
| **wire 值** | google `"LOW"` | **逐字节原样**，绝不改动 | 内核直读 yaml |

**关键**：档位键**有**别名归一，且这归一**只存在于一处**（内核 `from_title_case`）。v1 说「代码不做别名归一」是错的——`Off|None|Disabled` 是内核已定义的合法同义词，去掉它才是破坏。

### 5.2 规范拼写

- 规范拼写 = `Off / Minimal / Low / Medium / High / XHigh / Max`（TitleCase）。
- 内核 `to_title_case()` 对 `XHigh` 返回 `"X-High"`（`dialect.rs:84`），而 yaml 字典主用 `XHigh`，导致 `dialect.rs:226-233` 需要**隐式双拼写兜底**。
- **裁决**：规范拼写统一为 **`XHigh`**；`X-High` 仅保留为读边界别名。`to_title_case()` 返回值改为 `"XHigh"`（并删除 `dialect.rs:227-233` 的隐式兜底分支），使「一处规范拼写」成立。

### 5.3 已确认的真 bug（W9-C 唯一目标）

**实测**：字典 63 个带 `thinking` 的模型，键 `Xhigh`（大写 X + 小写 h）出现 2 次：

| 厂商 | 模型 | 键 | wire |
| --- | --- | --- | --- |
| openai | `openai/gpt-6-astra` | `Xhigh` | `xhigh` |
| bailian | `qwen/qwen3.8-27b` | `Xhigh` | `xhigh` |

`from_title_case("Xhigh")` → `None`（不在 `dialect.rs:70` 的接受集）→ `validate_reasoning_effort` 拒绝 → **该模型任何显式档位都发不出去**（网络 I/O 前 `Err`）。

**修复**：键 `Xhigh` → `XHigh`（数据修复，1 处拼写）。
**不修**：键 `None`（`dialect.rs:65` 已把它当 `Off` 同义词）——v1 的「Off/None 统一命名」是误判，且与「不做旧名归一」自相矛盾，**撤销**。

### 5.4 数据文件未入版本控制（真 bug）

`apps/crish-desktop/src/services/modelsAutofillBaselineData.json`（字典源数据，被 `apps/crish-desktop/src/services/modelsAutofillBaseline.ts:19` import）被 `.gitignore:379` 的全局裸 `*.json` 误伤，**从未入库**（`git log` 为空）。

  > 行号不写入本文档（`.gitignore` 频繁变动，写死行号必然漂移）——按**模式内容**检索。

## 7. 跨端归一化对称（W10）

**问题**（α4 发现，实测确认）：

| 端 | 行为 | 证据 |
| --- | --- | --- |
| TS | `trim().toLowerCase()` | `apps/crish-desktop/src/api/modelsCatalogStore.ts:257,261` |
| Rust | 精确匹配（无 trim / 无 lowercase） | `crates/agent-provider/src/models/catalog.rs:466-470`（`entries.contains_key`）、`catalog_types.rs:331-333`（`m.id == model_id`） |

**裁决**：**两端统一为「精确匹配 + 首尾 trim」**（不做 lowercase）。

理由：① yaml 是配置真源，用户写的 `providerId` 应原样成为身份；② 读写一致是最强不变量；③ 小写归一会让「用户改大小写」成为无效操作。

**实现（含 Rust 侧，v1 遗漏）**：

- TS：`modelsCatalogStore.ts:257,261` 去掉 `.toLowerCase()`，保留 `.trim()`。
- Rust：`catalog_types.rs:331` `find_model` 与 `catalog.rs` 索引查询**增加首尾 trim**（当前无）。
- 注释同步：`modelsCatalogLive.ts:6` 现写「大小写不敏感，与 `modelIndex ${normPId}::${normMId}` 一致」，与裁决冲突，须改为「精确匹配（首尾 trim）」。
- 单测：`(providerId: 'Acme', modelId: 'XHigh-Model')` 在两端 lookup 结果一致（含首尾空白变体）。

> 注：档位键的别名归一（§5.1）**不受本条影响**——本条只管 `providerId`/`modelId` 身份键。
