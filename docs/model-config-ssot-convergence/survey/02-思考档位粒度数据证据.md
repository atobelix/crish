### 具体缺陷实例

| 缺陷 | 实例 | 是否真 bug |
| --- | --- | --- |
| **键不在内核接受集 → 请求被拒** | `openai/openai/gpt-6-astra`、`bailian/qwen/qwen3.8-27b` 的键 `Xhigh`：`dialect.rs:63-74` `from_title_case` 只接受 `XHigh\|xhigh\|X-High\|x-high` → `None` → `engine_provider/thinking.rs:73-75` 在网络 I/O 前 `Err(InvalidRequest)` | ✅ **真 bug（硬故障）** |
| **大小写漂移（非白名单内）** | `anthropic/claude-fable-5.1` → `XHigh`（合法）；`openai/gpt-6-astra` → `Xhigh`（非法，见上） | 上行为合法，下行为 bug |
| **档位集合不一致** | `anthropic/claude-fable-5` → 4 档（无 XHigh）；`claude-fable-5.1` → 5 档（有 XHigh） | ❌ 非 bug（能力是每模型的，正常） |
| **`Off` vs `None`** | `deepseek/deepseek-v4-flash` → `{Off->"off"}`；`openai/gpt-5.6-terra` → `{None->"none"}` | ❌ **非 bug**：`dialect.rs:65` 把 `None` 当 `Off` 同义词接受；`run_launch.rs:144` 也接受 wire `"none"` |
| **强制思考** | `gpt-5.6-sol-pro`（调研文档标「强制思考」）无关闭档键 | ❌ 非 bug（**裁决**：无关闭档键 = 强制思考，用键缺失表达） |
| **档位序** | 键为任意字符串 | ❌ 前提不成立：内核 `vendor_wire.rs:24-72` 已有强度刻度；裁决为**默认不降级**（U1） |

## 5. 既有调研文档的粒度（`docs/model-capability/surveys/01-...`）

调研文档**同样按模型**记录档位，且明确区分「可选开启 / 强制思考」：

| 模型 | 思考能力状态 | 档位 |
| --- | --- | --- |
| `openai/gpt-5.6-sol` | 可选开启 (Optional) | `none, low, medium, high, xhigh, max`（6 档） |
| `openai/gpt-5.6-sol-pro` | **强制思考 (Mandatory)** | `low, medium, high, xhigh, max`（5 档，无 none） |
| `openai/gpt-5.5` | 可选开启 (Optional) | `low, medium, high`（3 档） |
| `openai/gpt-5.5-pro` | 强制思考 (Mandatory) | `low, medium, high` |
| `openai/o3-pro` | 强制思考 (Mandatory) | `low, medium, high` |
| `openai/gpt-image-2` | 强制思考 (Mandatory) | Visual CoT 图像语义推理 |

**同一厂商、同一系列、仅 pro 与非 pro 之差 → 档位集合与强制性都不同。**

调研文档对 OpenAI 的总述是「全 6 档控制：`none, low, medium, high, xhigh, max`」——这是**厂商级可达档位的并集**，但**每个模型只支持其中一部分**。这正是「统一词表 + 每模型 map」要表达的：词表是并集，map 是各模型的实际子集。

## 6. 结论

1. **能力粒度 = 每模型**。数据集（`isReasoning` 在模型上）、调研文档（按模型列档位）、参考实现（`reasoning` + `thinkingLevelMap` 都在 Model 上）三方一致。
2. **厂商级假设是错的**：28/59 厂商内部有 reasoning 分歧。
3. **统一词表 + 每模型 map 是正确解法**：词表提供跨模型可比较的档位语言，map 表达每个模型的真实子集与 wire 值。**参考实现 `reference/pi` 用的正是这个形状**（`packages/ai/src/types.ts:83-85`）：封闭 `ThinkingLevel` + `ModelThinkingLevel` + `ThinkingLevelMap`。
4. **词表不必新建——内核早已实现**：`crates/agent-provider/src/request/vendor.rs:99-111` `ThinkingIntensity` = `Off/Minimal/Low/Medium/High/XHigh/Max`；`request/vendor/dialect.rs:63-87` 提供别名接受集与规范拼写；`request/vendor_wire.rs:24-72` 提供强度刻度。**词表唯一权威 = 内核**，前端只需门禁守护的镜像（`plans/09` §1.3）。
5. **我们当前实现缺两样**：① 前端无词表镜像与顺序（UI 按 yaml 插入序）；② 数据键未对齐内核接受集（16 种签名中 `Xhigh` 会触发请求拒绝）。修正路径见 `plans/09` §9（W9-C/D/F）。
6. **两处 v1 误判已撤销**：`Off`/`None` 是内核已定义的**合法同义词**（非缺陷，无需改名）；「禁止钳制/降级」改为「**默认不降级**」（内核 `DegradePolicy` 默认 `Reject`，`AllowDegrade` 保留但不由 UI 触发）。
