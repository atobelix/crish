## 0. 一句话结论

> 出站请求的能力决议（协议 / 思考 / 字段名 / 模态 / 窗口 / 定价）**已收敛到 `~/.conex/models.yaml`**。

## 5. 活动选择决议链（摇摆根因）

### 5.1 模型标识符：键正确，消费侧退化
- **前端主索引正确**：`modelsCatalogStore.buildIndexes` 的 `modelIndex.set(`${normPId}::${normMId}`, entry)`（`:264`）；`globalModelIndex` 以 `normMId` 为 key 存**数组**（`:266-268`）。
- **Rust 索引正确**：`catalog.rs:337` `entries: BTreeMap`，键 = `vendor::model`（`:273-275,336`）；`LiveModels::find(provider_id, model_id)`（`:768-770`）双键。
- **⚠️ 违规：裸 `modelId` 跨供应商匹配**
  - `profileValidation.ts:360` —— `pickDefaultModelSelection` 第 2 优先级 `stored_model_match`：`normalized.find((x) => x.models.includes(storedModel))`。**只按 modelId、跨所有 provider 顺序命中第一个**。
  - `profileValidation.ts:381` —— 第 4 优先级 `engine_match`：`normalized.find((x) => x.models.includes(engineModel))`，同样裸 id 跨厂商。
  - `modelCatalogPure.ts:152` —— `pickDefaultCatalogEntry`：`usable.find((e) => e.model === prefModel)`。
  - `modelsCatalogSelectors.ts:32-35` —— `selectModelGlobally`：`globalModelIndex.get(normMId)` 后 `return list[0]`，**显式取同名首个**。
  - `crates/agent-provider/src/models/catalog.rs:479-487` —— `lookup_by_model_id`「跨供应商首个匹配项」（BTreeMap 字典序最小 vendor）。**全仓零引用 = 死代码**。
- `profileValidation.ts:310-313` 过滤后 `normalized` 顺序 = `loadProfiles()` 顺序 = localStorage 数组顺序（`profileStorePersistence.ts:76-88`），会因 `saveProfiles`/`upsertProfile`（`:162-170` push 到尾部）改变。

### 5.2 关闭供应商的处理
- `setProfileEnabled`（`profileStorePersistence.ts:207-224`）：
  ```ts
  p.enabled = enabled;
  saveProfiles(list);
  if (!enabled && getActiveProfileId() === profileId) {
    clearActiveProfileId();   // 只删 localStorage
    clearActiveModelId();     // 只删 localStorage
  }
  ```
- `removeProfile`（`:193-205`）同样只清 localStorage。
- **`AppSettings.defaultModel` 未被清**——这是摇摆的关键缺口。

### 5.3 自愈逻辑及其短路
- `resolveActiveModelAfterMetaChange`（`ModelsSettingsTab.tsx:64-96`）**非死代码**，被 `:207` 真实调用（在 `useEffect` `:199-222` 内）。
- 逻辑正确：`:79-85` **只在同 provider 内** `storeIds.find(...)`；`:94-95` 同厂商无可用 → `nextActive: null`（调用方 `:218` 执行 `clearActiveModelId()`）。
- **⚠️ 但在供应商级关闭时被短路**：`:200` 守卫 `if (!activeProfileId || !globalActiveModelId) return;` —— `setProfileEnabled` 已清空 localStorage，故自愈**根本不运行**。

### 5.4 顶栏解析链与反馈回路
- `resolveHeaderModelFromCatalog`（`ChatHeaderControls.tsx:54-92`）：`:60-64` 候选 = `storedModel || engineModel || settingsDefault`；`:66-78` 仅当 `profileId && candidate` 同时存在才走同厂商精确校验；`:80-89` `profileId` 存在但精确失败 → 同厂商首个；`:91` `profileId` 空 → `{profileId:null, model:''}`。**本函数自身不跨厂商**。
- 注入点：`applyResolvedModelLabel`（`:104-113`）传 `settingsDefault: appSettings?.defaultModel`（`:109`）。
- **⚠️ 三个重解析 effect**：
  - `:115-121` 依赖 `[projectTick, appSettings?.defaultModel]` → `fetchEngineStatus` + `applyResolvedModelLabel`。
  - `:123-126` 依赖 `[catalogVersion]`。
  - `:137-144` 订阅 `onUiEvent('model-changed')` → `setEngineModel`/`setActiveProfileId` + `fetchEngineStatus`。
- **反馈回路**：`activateProfileModel` 成功 → `emitUiEvent('model-changed')`（`profileStoreActivation.ts:121-126,182`）+ `persistSelectionToAppSettings` 写 AppSettings → `setAppSettings` → `appSettings?.defaultModel` 变化（`ChatHeaderControls.tsx:121`）→ **再次重解析 + 写回**。

### 5.5 摇摆机制的因果链（逐步还原）

1. 供应商 A、B 都提供同名模型 `gpt-4o`。当前活动 = (A, `gpt-4o`)。**双写**：localStorage（`profileStoreActivation.ts:179-180`）+ AppSettings（`:107-108`）。
2. 用户关闭供应商 A → `setProfileEnabled('A', false)`（`profileStorePersistence.ts:207`）→ 命中 `:219-222`，**清空 localStorage 的 active profile/model，不改 AppSettings**。
3. 系统进入不一致中间态：`getActiveProfileId()` 为空，`appSettings.defaultModel` 仍为 `'gpt-4o'`。
4. `resolveActiveModelAfterMetaChange` 自愈 effect 因 `ModelsSettingsTab.tsx:200` 守卫直接 return，**不介入**。
5. 任一重解析触发点命中（`ChatHeaderControls.tsx:121`/`:123`/`:137-144`）。
6. 解析进入 `pickDefaultModelSelection`：`storedProfileId` 空 → 跳过分支 1（`:346`）→ 进入分支 2 `stored_model_match`（`:359-368`），执行 `normalized.find((x) => x.models.includes('gpt-4o'))` —— **跨供应商裸 id 匹配**，命中数组顺序中第一个含该 id 的启用供应商 = B。
7. 结果经 `activateProfileModel` 写回（`:179-183`）→ 发 `model-changed` → 写 AppSettings → 触发第 5 步重解析。
8. **非确定性来源**：`normalized` 数组顺序（`profileValidation.ts:360` 的 `find`）与 yaml providers 插入序（`ChatHeaderControls.tsx:82`、`modelsCatalogLive.ts:64`）——二者均**不以 `(providerId, modelId)` 复合身份消歧**，故同名下结果依赖顺序 → 表现为 A/B 摇摆。

### 5.6 用户期望 vs 当前行为

| 用户期望 | 当前行为 | 差距 |
| --- | --- | --- |
| 关闭正在使用的供应商后，**不强行找可用模型**，置空让用户重配 | `pickDefaultModelSelection` 分支 2/4/5/6 **强行跨厂商找同名字段并激活** | 需删除跨厂商回落，改为置空 + 显式引导 |
