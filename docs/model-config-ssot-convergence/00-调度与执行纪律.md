# 调度与执行纪律

> **适用**：本战役全部轮次。主控与子 Agent 均须遵守。
> **上位纪律**：仓库根 `AGENTS.md`（尤其 §1 反退避、§2 子 Agent 调度、§3 Git 提交、§7 严禁补丁）。

---

## 1. 派单纪律

- **每轮 5–12 个子 Agent**；收尾轮可不保底。同时存活（未终态）≤16。
- **嵌套禁止**：子 Agent 深度 1，无派发能力。执行中发现问题 → 上报主控裁决。
- 派单前明确四要素：**输入文档 / 产出路径 / 验收标准 / 文件冲突注意事项**。
- 子 Agent 只执行分配任务；**不得**自行扩大文件域。

## 2. 文件域互斥（本战役关键）

同文件**禁止并行写**。串行约束见 `00-索引.md` 的「关键文件串行约束」表。

主控派单时必须核对：本轮各 Agent 的文件集**两两不相交**。相交则拆轮。

## 3. 子 Agent 执行规范

- 命令统一用 **pwsh7（PowerShell 7+）**；写文件 **UTF-8 无 BOM**。
- **只读勘察类** Agent：最多写一份文档，且必须由主控分配文件名。
- **实现类** Agent：必须自带测试（正例 + 负例），不得只改代码不写测。
- **禁止** `--no-verify`、禁止 `reset --hard` / `checkout .` / `restore`。
- **禁止**提交（提交权仅主控）。改动留在工作区，自查后上报。

## 4. 空返回处理

子 Agent 汇报为空 → 默认是供应商网络问题而非任务失败：
1. 先核查文件是否已落盘 + `git status` 检查是否被并行 Agent 误伤。
2. 1–3 次 → 用 `task_id` 接续原会话（先判最终状态）。
3. 4–6 次 → 拆分或换新 Agent 重新分发，**总任务量不变**。
4. 6 次以上 → 主控接管实现。

## 5. 验收纪律（三层，禁止单一检查抬关）

| 栏 | 要求 |
| --- | --- |
| **A 源码形状** | 提供 grep 命令与输出；无 `dead_code`；负向断言 |
| **B 本会话真跑测** | 写明命令与出口码；**未跑不得称绿** |
| **C 真实宿主用户路径** | `00-总方案.md` §8 五剧本真机跑通 |

**禁止**以「模块内自测绿灯」「类型检查无报错」「文档声明完成」作为交付依据。

**每个实现 Agent 的轮次报告必须包含**：
- 改动文件清单（`文件:行号`）
- A 栏证据（grep 命令 + 输出）
- B 栏证据（测试命令 + 结果）
- **诚实段**：未闭合项、未确认项、存疑处

## 6. 物证要求（用户裁决）

本战役交付必须提供**全链路物证**：

| 物证 | 内容 |
| --- | --- |
| 触发端 | 用户在 UI 的交互能准确发起请求 |
| 传输端 | 跨层契约在主注册表中真实存在并有效收发 |
| 介质端 | 数据完整落盘至 yaml；**旧孤岛数据源零写入且被物理清退** |
| 消费端 | 内核实际业务调用处真实读取并应用新配置；渲染树真实携带新配置 |
| **负向断言物证** | 自动化测试中断言旧字段、旧方法、旧类名已被彻底根除 |

## 7. 主控职责

- 每轮：核对文件域互斥 → 派单 → 收齐终态 → 抽检 → 提交（`git commit --only <paths>`）。
- 轮次报告：`execution/{轮}-轮次报告.md`。
- 审计位：`audits/{轮}-执行位抽检.md`。
- 发现方案与代码不符 → 以代码为准并更新方案，记录在轮次报告。

## 8. 禁止事项（零容忍）

- 功能伪连通（写了函数但真实调用链未生效；传 `Default`/`None`/空配置）
- 多轨并存 / 给旧岛续命（注释、隐藏、永久 Shim 掩盖旧轨）
- 幽灵契约（调用未注册命令）
- 破坏性容错回退（丢弃关键配置后继续）
- catch 块静默吞咽核心异常
- 虚构 token / 裸 Hex / 魔术数字补偿
- 为「让测试绿」而保留死符号或登记幽灵命令

### 9.2 提交权

- **提交权归主 Agent**，子 Agent **一律不提交**（承 §3、§7）。改动留在工作区，自查后上报，由主 Agent `git commit --only <paths>` 收口。

### 9.3 同文件串行约束

- `catalog_types.rs` 由**内核与跨端组独占**：其 `allows_off()`（W9-F）与 `find_model`/身份归一（W10）属同一文件的两处改动，若分属两组将并行写同一文件 → 冲突。故该文件在本组内**串行**执行（先 W9-F 后 W10，或反之，由组内定序）。
- 其余跨子任务共用的文件（如 `modelsCatalogLive.ts` 被 W9-D 与 W9-E 同时涉及）同样遵循「同文件不并行写」，由所在组串行处理。
