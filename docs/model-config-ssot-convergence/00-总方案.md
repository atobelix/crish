## 1. 本战役要修复的两个用户可见故障

### 1.1 故障 A：同名模型跨供应商摇摆

**现象**：两个供应商都提供同名模型（如 `gpt-4o`）时，关闭正在使用的那个供应商后，软件会在另一供应商的同名模型上来回跳。

**根因（三段叠加，缺一不可）**：

```
① 活动选择状态双写：localStorage（轨A）+ AppSettings.defaultModel（轨B）
       ↓ 关闭供应商只清轨A（profileStorePersistence.ts:219-222），轨B 残留旧裸 modelId
② 解析器裸 modelId 跨厂商匹配：pickDefaultModelSelection 分支2/4
   normalized.find((x) => x.models.includes(storedModel))   （profileValidation.ts:360,381）
       ↓ 命中「数组顺序里第一个含该 id 的供应商」——不是原供应商
③ 反馈回路放大：写回 → model-changed 事件 + AppSettings 变化 → 再次重解析（ChatHeaderControls.tsx:121,137-144）
       ↓ 数组顺序 / yaml 插入序可变 → 命中项可变 → 视觉上「摇摆」
```

**修复方向**：① 活动选择**单源化**（U2）；② 删除解析器的跨厂商回落，失效即置空（U1）；③ 切断「解析→写回→再解析」回路（U2）。

### 1.2 故障 B：三处配置不一致

**现象**：设置界面、对话界面、yaml 文件三者显示不同。

**根因**：三处读三份数据（见 `survey/01` §1）。设置页服务商档案读 localStorage，对话选择器读 yaml 镜像，引擎读 `provider-config.json`；三者仅靠**一次性、带完成标记**的 LS→yaml 导入桥接（`modelsLsImport.ts:34-42` 命中标记即 return），标记置位后新配置永不同步。

**修复方向**：**yaml 为唯一配置真源**，其余存储降级为纯运行期态或物理切除（U2/U3）。

## 2. 目标态（完成定义）

完成定义不是「系统里有 yaml 模块」，而是下面每条链上的**每个动词都能在本会话被断言**。

### 2.1 单一真源链

```
用户唯一可编辑的配置面：~/.conex/models.yaml
    ↓ workbench_read_models_yaml / workbench_save_models_yaml
modelsCatalogStore（前端唯一镜像）
    ↓ 投影
设置界面模型页  ≡  对话界面模型选择器  ≡  引擎 live_catalog()
    （三者读同一棵树，呈现同一份内容——U2）
```

### 2.2 模型身份链

```
模型身份 ≡ (providerId, modelId) 复合键
    ↓ 任何解析、索引、匹配、选中判定都必须带 providerId
    ↓ 禁止任何只按 modelId 的跨供应商 find / [0] / lookup
```

### 2.3 活动选择失效链（U1）

```
供应商被关闭 / 删除，或模型被停用 / 删除
    ↓ 检测到「当前活动选择不再有效」
置空活动选择（清空唯一指针源）
    ↓ 不查找替代、不匹配同名、不选第一个可用
UI 显示「未配置模型」+ 引导用户手动重选
```

### 2.4 字典边界链（U3）

```
字典（D1 预填库 / D2 内置目录）唯一允许的出口：
    用户在「添加模型」表单输入模型名
        → 字典提供字段建议填充草稿
        → 用户可改写，用户值 100% 覆盖字典值
        → 保存后写入 yaml
任何其它读取路径 = 违规，必须物理删除
```

### 2.5 出站决议链（承上游 M6/M13）

```
profile = live_catalog().find(config.provider_id, config.model)
    ↓ Miss → 引擎未就绪（fail-closed），不得回落字典/前缀表/env
所有能力决策（协议 / 思考 / 字段名 / 模态 / 窗口 / 缓存 TTL / 定价）
    全部来自这一次命中
```

## 8. 验收分层（禁止单一检查抬关）

| 栏 | 含义 | 不得用来证明 |
| --- | --- | --- |
| **A 源码形状** | grep 热路径、调用序、无 dead_code 守卫、负向断言 | 用户已能正确配置与发出请求 |
| **B 本会话真跑测** | 写明命令与出口；未跑不得称绿 | 三处在用户机器上真的一致 |
| **C 真实宿主用户路径** | 建两个同名模型供应商 → 关闭当前 → 观察置空；改 yaml → 观察三处同步 | 「组件测里有断言」 |

### C 栏剧本（本战役核心，必须真跑）

1. **同名模型置空剧本**：新建供应商 A、B，都添加模型 `test-model-x`；激活 (A, `test-model-x`)；关闭 A → 断言：对话界面显示「未配置模型」，**不**自动切到 B。
2. **三处一致剧本**：在设置页给 A 的 `test-model-x` 改 displayName → 断言：磁盘 yaml 出现新名、对话选择器显示新名、设置页显示新名。
3. **字典边界剧本**：在 yaml 中**不**配置某模型 → 断言：对话界面**不**出现该模型（不因字典有而显示）；在添加表单输入该模型名 → 断言：字段被预填且可改写。
4. **缓存 TTL 剧本**：yaml 中某模型**无** `cacheTtl` → 断言：不追踪缓存（fail-closed），**不**出现内置字典推断出的 TTL。
5. **反例剧本**：手工把 yaml 改坏（非法 YAML）→ 断言：UI 显示明确错误，**不**静默清空用户配置。
