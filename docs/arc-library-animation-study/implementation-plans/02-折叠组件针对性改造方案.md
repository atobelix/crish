## 一、背景、痛点与升级总纲

### 1.1 现存三大折叠组件定位梳理与拓扑关系

在 Conex 桌面聊天消息流（Timeline）中，折叠组件承担着“信息降噪”与“深度溯源”的双重职能。当前存在三大折叠组件，分别运行在消息渲染的不同层级：

```
┌────────────────────────────────────────────────────────────────────────┐
│ FoldableProcessSection (正文间独立过程段外层容器，控制栏高度 33px)     │
│  - 承载全段总耗时与主导动作（「工作 12s ›」）                          │
│  - 内部聚合：思考过程 + 工具执行组                                    │
│  ┌──────────────────────────────────────────────────────────────────┐  │
│  │ ReasoningRow (24px 极简单行流式思考行)                           │  │
│  │   - 流式运行态：状态圆点 + 扫光微交互 + 512B 尾窗文字追踪        │  │
│  │   - 终态闭合态：「已思考 3.2s ›」，等宽数字                      │  │
│  │   - 展开态：自然向下融入主文档流，零局部滚动条                   │  │
│  └──────────────────────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────────────────────┐  │
│  │ FoldableToolGroup (24px 过程段单组工具折叠容器)                  │  │
│  │   - 门槛：≥2 个工具折叠为极简摘要（「已搜索 2 次 · 已运行 1 条」）│  │
│  │   - 单工具：直出工具行（意图与命令常驻可见，详情默认收拢）       │  │
│  │   - 展开态：平铺渲染内部各个工具的调用块与终端详情输出           │  │
│  └──────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────┘
```

各组件代码路径与核心职责：
1. **`FoldableToolGroup.tsx`**（`apps/crish-desktop/src/components/chat-tool-call/`）：
   - 过程段内连续工具调用的聚合折叠容器。
   - 具有 24px 高度极简摘要头，利用 CSS Grid `0fr / 1fr` 做开合过渡，支持原生 `hidden="until-found"` 与 `beforematch`。
2. **`ReasoningRow.tsx`**（`apps/crish-desktop/src/components/chat-message-row/`）：
   - 24px 极简思考行。
   - 流式接收 token 阶段具备 `contain: size layout; height: 24px;` 硬件级阻断能力，终态收敛时具备两阶段折叠卸载。
3. **`FoldableProcessSection.tsx`**（`apps/crish-desktop/src/components/chat-message/`）：
   - 顶级分段折叠容器，33px 控制栏承载工作时间，折叠时使用原生 `hidden="until-found"` 隐藏整段，支持单思考段与单工具段的无缝穿透穿透展开。

### 1.3 升级原则与设计哲学

本方案严格遵守以下三条顶层原则：
1. **反退避与架构净收敛**：绝不通过延时盲猜（如随意 `setTimeout` 补丁）或魔术数字修补问题。必须从数学模型与物理状态机层面抽象可复用底层工具，实现系统性收敛；
2. **护城河零退化（Zero Regression）**：坚决捍卫既有的 `hidden="until-found"` 搜索穿透能力与流式 token 期的 `contain: size layout` 硬件级布局隔离；
3. **渐进增强与轻量无感**：完全基于原生 Web API（ResizeObserver、CSS Grid 0fr/1fr、CSS 自定义属性、Web Animations/Transitions），不引入厚重第三方动效依赖，开箱即用。

## 二、坚决捍卫的两大既有核心护城河

在动效与体验改造的全生命周期中，**任何代码变更必须以不破坏以下两项核心资产为第一绝对前提**。

### 2.1 护城河一：Chromium 原生 `hidden="until-found"` 与 `beforematch` 页面搜索穿透

#### 2.1.1 机制原理解剖
Chromium 引入的 `hidden="until-found"` 属性具有革命性意义：它在视觉上完全隐藏内容（避免占据布局空间），但**保留在 DOM 树与可检索树（Search Accessibility Tree）中**。
当用户在桌面端按下 `Ctrl+F`（或 Tauri 原生查找指令）搜索关键字时：
1. 浏览器检索器能够直接命中处于 `hidden="until-found"` 节点内部的匹配文字；
2. 浏览器排版引擎自动向该隐藏节点派发原生 `beforematch` 事件；
3. 浏览器自动剥离 `hidden` 属性，并将视口高亮聚焦到匹配文本处。

#### 2.1.2 动效过渡与 `hidden` 的协同铁律
原生 `hidden="until-found"` 会被浏览器施加类似 `content-visibility: hidden` 的渲染优化。**若在收合动画刚开始时立刻打上 `hidden="until-found"`，Chromium 将立即停止对该节点的几何计算与重绘，导致正在播放的 `0fr` 高度过渡动画被硬生生掐死（Jumping to zero instantly）**。

因此，三大折叠组件必须严格执行**两阶段协同状态机**：
- **展开阶段（Opening）**：
  1. 第一微秒：立即执行 `node.removeAttribute('hidden')`，恢复完整布局计算；
  2. 启动高度扩展（CSS Grid 从 `0fr` 向 `1fr` 变形或动态高度过渡）；
- **收起阶段（Closing）**：
  1. 启动高度收合过渡，此时**严禁附加 `hidden` 属性**，保持 DOM 节点可见并平滑缩小；
  2. 监听 `transitionend`（针对 `grid-template-rows` 或高度属性）；
  3. 待过渡完全结束后，才挂载 `node.setAttribute('hidden', 'until-found')`；
  4. 同步设置一个与自适应时长严格对齐的 Safety Timer（兜底计时器），防止在窗口切后台或 GPU 节流时丢失 `transitionend` 事件导致状态失锁。

### 2.2 护城河二：ReasoningRow 流式输出期 `contain: size layout` 硬件级布局阻断

#### 2.2.1 布局回流风暴（Reflow Storm）物理机理
在 LLM 大模型进行深度推理时，Thinking 字段可能长达数万字符，以每秒 30~80 个 token 的高速持续输出。
若外层容器没有严格的几何隔离：
- 每吐出一个 token，浏览器就需要重新计算整篇 Markdown 的行内断行、段落高度、外层消息气泡尺寸、虚拟滚动容器的滚动条高度；
- 造成每秒数十次的全页重排（Global Reflow），导致主线程 CPU 飙升至 100%，输入框打字卡顿、光标失去响应。

#### 2.2.2 硬件级隔离硬性契约
Conex 在 `ReasoningRow.module.css:15-22` 中确立了严格的 CSS 尺寸与布局隔离：
```css
/* 未展开且未处于过渡折叠中时，严格执行 24px 硬件级尺寸隔离，切断流式回流风暴 */
.reasoningContainer:not([data-expanded='true']):not([data-collapsing='true']) {
  contain: size layout;
  height: 24px;
  min-height: 24px;
  max-height: 24px;
  box-sizing: border-box;
  overflow: hidden;
}
```
**铁律约束**：
1. 流式输出阶段（`isLive === true`），折叠态下绝对禁止将容器 `height` 放开为 `auto`，绝对禁止撤销 `contain: size layout`；
2. 尾窗预览文本通过 `extractLatestLine` 在 512 字节微型缓冲区内 O(1) 提取，单行溢出通过 `text-overflow: ellipsis` 截断，保证 24px 内联空间严格恒定。

## 三、核心底层基建抽象与契约设计

为了根除散落在各业务组件中的临时补丁，本方案将公共逻辑下沉为三大高内聚通用基建。

### 3.1 视口防迷失 Hook：`useAccordionViewportGuard`

#### 3.1.1 架构设计
当用户折叠长内容时，通过探测锚点元素与视口相对位置，智能判断是否需要执行视口平滑回退，防止用户视线脱离上下文。

```
┌────────────────────────────────────────────────────────┐
│ 视口顶端 (Viewport Top, y = 0)                         │
└────────────────────────────────────────────────────────┘
          ▲
          │ rect.top < safeOffset (已滚出屏幕上方，发生越界)
          ▼
┌────────────────────────────────────────────────────────┐
│ [Foldable Component Header] (已脱离当前视野)           │
├────────────────────────────────────────────────────────┤
│                                                        │
│   (用户已阅读到此处的长日志内容，长达 2000px)           │
│                                                        │
│   [用户点击收起按钮]                                   │
└────────────────────────────────────────────────────────┘
          │
          ▼ 触发 useAccordionViewportGuard
   自动执行平滑回滚至 Header 锚点，消灭视口跳突迷失！
```

#### 3.1.2 源码级接口契约与实现
创建文件：`apps/crish-desktop/src/hooks/useAccordionViewportGuard.ts`

```typescript
/**
 * apps/crish-desktop/src/hooks/useAccordionViewportGuard.ts
 *
 * 折叠手风琴视口保护 Hook。
 * 当长折叠组件收拢时，若其顶部已滚出视口（top < offset），
 * 自动平滑滚动将其起始锚点拉回视口可见区域，彻底消灭“视口跳跃丢失”。
 */

import { useCallback, useRef } from 'react';

export interface AccordionViewportGuardOptions {
  /** 视口顶部安全保护边距（像素，默认 16px，防止元素死贴浏览器边缘） */
  offsetPx?: number;
  /** 滚动行为：'smooth' 或 'auto'（自动检测 reduced-motion 时降级为 auto） */
  behavior?: ScrollBehavior;
  /** 可选：显式指定的滚动宿主容器（缺省时使用原生 element.scrollIntoView） */
  scrollContainer?: HTMLElement | null;
  /** 滚动前回调钩子（可用于日志追踪或外部锁定） */
  onBeforeScroll?: (deltaY: number) => void;
}

export function useAccordionViewportGuard<T extends HTMLElement = HTMLElement>(
  targetRef: React.RefObject<T | null>,
  options: AccordionViewportGuardOptions = {}
) {
  const {
    offsetPx = 16,
    behavior = 'smooth',
    scrollContainer,
    onBeforeScroll,
  } = options;

  const isGuardingRef = useRef(false);

  const triggerViewportRecovery = useCallback(() => {
    const el = targetRef.current;
    if (!el) return;

    // 读取元素在当前视口中的几何包围盒
    const rect = el.getBoundingClientRect();

    // 判定条件：顶部已经脱离视口上方（rect.top < offsetPx）
    if (rect.top < offsetPx) {
      isGuardingRef.current = true;
      const deltaY = rect.top - offsetPx;
      onBeforeScroll?.(deltaY);

      // 检测系统无障碍减弱动态偏好
      const prefersReduced =
        typeof window !== 'undefined' &&
        window.matchMedia('(prefers-reduced-motion: reduce)').matches;
      const finalBehavior: ScrollBehavior = prefersReduced ? 'auto' : behavior;

      if (scrollContainer) {
        // 自定义滚动宿主场景
        const currentScroll = scrollContainer.scrollTop;
        scrollContainer.scrollTo({
          top: Math.max(0, currentScroll + deltaY),
          behavior: finalBehavior,
        });
      } else {
        // 原生视口滚动场景（对齐 arc-library ExpandableText）
        el.scrollIntoView({
          block: 'start',
          behavior: finalBehavior,
        });
      }

      // 微任务后释放保护锁
      queueMicrotask(() => {
        isGuardingRef.current = false;
      });
    }
  }, [targetRef, offsetPx, behavior, scrollContainer, onBeforeScroll]);

  return {
    triggerViewportRecovery,
    isGuardingRef,
  };
}
```

### 3.2 距离自适应物理时长模型：`calcAccordionDuration`

#### 3.2.1 物理学建模与分段拟合公式
arc-library 在 `expandable-text.tsx` 中验证了非对称自适应时序。Conex 面向桌面工作台的极客体验，既要避免 220ms 展开 2500px 时的疯狂跳闪，又要让日常单行工具收合干净利落。

设计对数饱和自适应模型（Logarithmic Saturation Model）：
- **展开（Opening）**：
  $$\text{duration}_{\text{open}}(h) = \text{clamp}\left(180 + 90 \cdot \ln\left(1 + \frac{h}{120}\right), 180, 480\right) \text{ ms}$$
- **收起（Closing）**：
  $$\text{duration}_{\text{close}}(h) = \text{clamp}\left(150 + 65 \cdot \ln\left(1 + \frac{h}{120}\right), 150, 350\right) \text{ ms}$$

```
时长 (ms)
  500 ┌─────────────────────────────────────────── [展开上限: 480ms]
  450 │                                   .....'
  400 │                          ......'''
  350 ├───────────────────. . .'' ─────────────── [收起上限: 350ms]
  300 │             ..''        ..''
  250 │       ..''''      ..''''
  200 ├─..''''      ..''''
  150 └─────'───────────────────────────────────── [收起起步: 150ms]
      0    200   400   600   800  1000  1200  1600+ 内容高度 (px)
```

#### 3.2.2 关键参数取值对比表
| 内容展开高度 (px) | 典型应用场景 | 展开时长 $T_{\text{open}}$ | 收起时长 $T_{\text{close}}$ | 视觉质感特征 |
| :---: | :--- | :---: | :---: | :--- |
| **30 px** | 极简单行工具详情、1行警告 | **200 ms** | **164 ms** | 极速收合，指尖紧致机械感 |
| **120 px** | 常见 3~5 行命令输出或短思维链 | **242 ms** | **195 ms** | 平滑舒适，与既有 220ms 紧密衔接 |
| **500 px** | 常见代码块、工具聚合展开（5个工具） | **330 ms** | **258 ms** | 视觉从容展开，眼球平顺追踪 |
| **1500 px** | 深度思考大篇幅推理、超长大日志 | **415 ms** | **319 ms** | 沉稳滑行，绝不产生一闪而过的掉帧感 |

#### 3.2.3 核心实现代码
扩展：`apps/crish-desktop/src/utils/motionTokens.ts`

```typescript
/**
 * 距离自适应手风琴折叠展开物理时长计算器。
 * 替代全局生硬死板的固定 220ms，根据内容物理真实位移高度动态推导。
 *
 * @param height 展开目标高度（像素）
 * @param isOpening 是否为展开动作（true 为展开，false 为收起）
 * @returns 毫秒时长（整数）
 */
export function calcAccordionDuration(
  height: number,
  isOpening: boolean
): number {
  const safeHeight = Math.max(0, Number.isFinite(height) ? height : 0);

  if (isOpening) {
    // 展开：180ms 起步，上限 480ms
    const raw = 180 + 90 * Math.log(1 + safeHeight / 120);
    return Math.round(Math.min(480, Math.max(180, raw)));
  } else {
    // 收起：150ms 起步，上限 350ms（收起动作要求更为干净敏捷）
    const raw = 150 + 65 * Math.log(1 + safeHeight / 120);
    return Math.round(Math.min(350, Math.max(150, raw)));
  }
}
```

### 3.3 按钮文案单格重叠防抖架构（CSS Grid 1 / 1）

#### 3.3.1 物理机理
传统通过 `{isExpanded ? '收起' : '展开详情 (3 项)'}` 的写法，由于中文或英文在开闭状态下的字数不同，导致 `button` 的物理包围盒宽度在切换时发生瞬变。由于 Chevron 箭头通常处于文本右侧，文案宽度的突变会把 Chevron 瞬间向右推或向左扯，产生肉眼极易察觉的“毛刺抖动”。

arc-library 创新性地利用了 CSS Grid 的天然特性：**当多个网格元素指定相同的 `grid-area: 1 / 1` 时，Grid 容器会自动计算并以两者中“最宽的那个子元素”作为容器的固定宽度**。

### 3.4 动态渐进增强遮罩（1.6lh Dynamic Mask）

#### 3.4.1 现代 CSS `1.6lh` 单位与非线性幂雾
当大篇幅代码块或 Markdown 文本收起时，普通的 `overflow: hidden` 会让最后一行文字在下边框处被硬生生拦腰截断（硬切半个汉字）。
引入以容器自身行高为基准的 `1.6lh` 渐变遮罩：

```css
/* 展开过渡中或局部折叠态下的柔雾遮罩 */
.maskedContent[data-masking='true'] {
  mask-image: linear-gradient(
    to bottom,
    #000 calc(100% - 1.6lh),
    rgb(0 0 0 / 0.05) 100%
  );
  -webkit-mask-image: linear-gradient(
    to bottom,
    #000 calc(100% - 1.6lh),
    rgb(0 0 0 / 0.05) 100%
  );
}

/* 完全静止展开后立刻切换为 none，彻底释放离屏 Alpha 蒙版显存 */
.maskedContent:not([data-masking='true']) {
  mask-image: none;
  -webkit-mask-image: none;
}
```

**关键技术细节**：
- 采用 `calc(100% - 1.6lh)`，无论用户在设置中选择 13px 还是 18px 字号，渐变区高度永远严格精确等于 1.6 倍行高，与排版体系实现纯几何耦合；
- 动画停止后必须切回 `mask-image: none`，使渲染引擎恢复直接光栅化，保证文字亚像素级抗锯齿与极速滚动性能。
