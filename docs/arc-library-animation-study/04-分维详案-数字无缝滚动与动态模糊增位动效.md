## 一、位权锚定（Place-value Keying）数学算法与 DOM 稳定性

### 1.1 `partsFor` 的逆向位权建模
在 `animated-counter.tsx:24-34` 中，数字不是被简单地作为普通文本切片，而是使用 `Intl.NumberFormat.prototype.formatToParts` 结合**逆向位权（Place Value）**建立具有物理不变性的 Key：

```typescript
// animated-counter.tsx:24-34
function partsFor(value: number, decimals: number, locale: string): Part[] {
  const parts = new Intl.NumberFormat(locale, { 
    minimumFractionDigits: decimals, 
    maximumFractionDigits: decimals, 
    numberingSystem: "latn" 
  }).formatToParts(value);

  let place = parts.reduce((count, part) => count + (part.type === "integer" ? part.value.length : 0), 0);
  let fraction = 0;
  let order = 0;

  return parts.flatMap((part, index): Part[] => {
    if (part.type === "integer") return [...part.value].map(char => ({ key: `i${--place}`, digit: Number(char), order: order++ }));
    if (part.type === "fraction") return [...part.value].map(char => ({ key: `f${fraction++}`, digit: Number(char), order: order++ }));
    return [{ key: part.type === "group" ? `g${place}` : part.type === "decimal" ? "d" : `${part.type}${index}`, text: part.value }];
  });
}
```

#### 键值持久化规则：
- **个位（Ones）**：`key` 永远固定为 **`i0`**（$10^0$）；
- **十位（Tens）**：`key` 永远固定为 **`i1`**（$10^1$）；
- **百位（Hundreds）**：`key` 永远固定为 **`i2`**（$10^2$）；
- **千位（Thousands）**：`key` 永远固定为 **`i3`**（$10^3$）；
- **千分位逗号（Group）**：以其左侧紧邻的高位 place 锚定，例如千分位 `,` 的 key 为 **`g3`**。

### 1.2 999 跃升为 1,000 的完整状态流转与 React 调和推导

| 状态阶段 | 渲染值 | 分词序列 | 产出的 Part 键值序列 | React 调和与 DOM 行为 |
| :--- | :--- | :--- | :--- | :--- |
| **初始态** | `999` | `[integer: "999"]` | `["i2", "i1", "i0"]` | 挂载 3 个 `<Column>` |
| **目标态** | `1000` | `[integer: "1", group: ",", integer: "000"]` | `["i3", "g3", "i2", "i1", "i0"]` | 保持 `i2, i1, i0` 实例不变，前置插入 `i3, g3` |

#### 为什么低位滚轮完全不发生 DOM 重建或跳位？
1. **React Reconciliation 实例复用**：
   新旧 VDOM 树的末尾三项都是 `key="i2"`, `key="i1"`, `key="i0"`。React 判定为同一组件实例，**复用既有 DOM 节点**，触发 `Column` 的内部 `useEffect` 执行数字从 9 到 0 的滚动动画，状态机绝对平滑延续；
2. **高位伸展机制（`AnimatePresence` + `width: 0 -> auto`）**：
   新进的千位 `<Column key="i3">` 与分隔符 `<motion.span key="g3">` 受到 `presence` 变体控制：
   ```typescript
   const presence = { 
     initial: { width: 0, opacity: 0 }, 
     animate: { width: "auto", opacity: 1 }, 
     exit: { width: 0, opacity: 0 } 
   };
   transition = motionTokens.spring.morph; // visualDuration: 0.42, bounce: 0
   ```
   新列的物理宽度从 `0` 渐变展开至 `auto`，低位滚轮无需任何特殊的补丁偏移，仅靠弹性盒流式推挤（Flex flow push）向右自然滑动，全程零抖动。

## 二、滚轮定向环形滚动（Odometer Wrapping）机制

### 2.1 方向判定与累积目标增量
在 `AnimatedCounter` 中，整个数值的增减决定所有数字滚动的基准方向（`animated-counter.tsx:71-73`）：
```typescript
const [previous, setPrevious] = useState(value);
const [direction, setDirection] = useState(1);
if (value !== previous) { 
  setPrevious(value); 
  setDirection(value > previous ? 1 : -1); 
}
```
进入 `Column`（`animated-counter.tsx:55`）：
```typescript
state.target += direction < 0 && state.revealed 
  ? -((state.digit - digit + 10) % 10) 
  : (digit - state.digit + 10) % 10;
state.digit = digit;
```
- **典型案例：19 变为 21（数值增加，个位从 9 变为 1）**：
  $\Delta = (1 - 9 + 10) \pmod{10} = 2$。
  `target` 增加 +2（从 9 顺时针滚过 0 到达 1）。
  **里程表效应（Odometer Wrapping）**：绝不会因为 $1 < 9$ 就发生倒退滚动，而是沿着数值整体增量方向向前顺时针绕卷。

### 2.2 环形滚轮的取模映射公式（Glyph Modulo Transform）
在每个 `Column` 内部静态挂载了 0~9 共 10 个 `<Glyph>`。每一个 Glyph 根据轮子当前的浮点位置 `position` 动态计算自己在视口中的垂直相对位置（`animated-counter.tsx:38`）：

$$\text{offset}(current) = \left( ((\text{digit} - current) \pmod{10} + 15) \pmod{10} \right) - 5$$

- **数学证明**：通过加 15 与双重取模，实数差值 $\text{digit} - current$ 被周期性地折叠在对称开区间 **$[-5, +4]$** 内；离当前焦点最近的数字永远落在 $[-0.5, +0.5]$ 之间；
- **$O(1)$ 视口绝对剪裁**：
  ```typescript
  const visibility = useTransform(offset, current => Math.abs(current) >= 1 ? "hidden" : "visible");
  ```
  当 $|\text{offset}| \ge 1$ 时，DOM 节点的 `visibility` 立即被置为 `hidden`。在任何时刻，**有且仅有最多 2 个数字（过渡期）或 1 个数字（静止期）处于可见与渲染合成状态**，彻底避免 10 个元素的重绘开销。

## 三、动态模糊（Motion Blur）与亚像素字体保护

### 3.1 核心痛点：为什么不能常驻 CSS Blur？
在 Windows (DirectWrite / ClearType) 及 macOS 上，只要元素应用了非 `none` 的 CSS `filter`（哪怕是 `blur(0px)`），浏览器渲染引擎就会丢弃 RGB 亚像素抗锯齿（Subpixel Antialiasing），降级为灰度平滑（Grayscale Antialiasing），导致字体笔画发灰发虚。

### 3.2 AnimatedCounter 的亚像素安全断言
在 `animated-counter.tsx:42` 中：
```typescript
const filter = useTransform(offset, current => 
  Math.abs(current) < .02 || Math.abs(current) >= 1 
    ? "none" 
    : `blur(${(Math.abs(current) * motionTokens.blur.subtle).toFixed(2)}px)`
);
```
- **$|\text{offset}| < 0.02$（准静止区）**：
  在阻尼弹簧运动的尾声，当偏离中心小于 2% 字符高度时，强制输出字符串 `"none"`。浏览器立即卸载滤波着色器（Filter Shader），瞬间恢复系统级清晰的 ClearType 原生亚像素字体排版！
- **$0.02 \le |\text{offset}| < 1.0$（活跃运动区）**：
  模糊半径线性关联：$|\text{offset}| \times 2\text{px}$。在数字交替最剧烈的 0.5 处模糊达到 1.0px 峰值，形成逼真的运动残影。

### 3.3 SlotText 的速度驱动模糊（Velocity-Driven Blur）
在 `slot-text.tsx:107-110` 中，模糊直接与物理运动速度挂钩：
```typescript
const blur = useTransform(useVelocity(pos), velocity => {
  const amount = Math.min(Math.abs(velocity) * .05, 2.4);
  return amount < .15 ? "none" : `blur(${amount.toFixed(2)}px)`;
});
```
旋转初段速度极大，模糊迅速推至 2.4px 峰值；随着平滑刹车，速度衰减；当 `amount < 0.15` 时迅速切回 `"none"`，保证停止着陆的瞬间绝无一丝毛刺。

## 四、宽度弹簧与尺寸测量（Sizer 机制）

```css
/* animated-counter.module.css:1, 6-8 */
.counter { font-variant-numeric: tabular-nums; }
.column {
  --feather: .16em;
  position: relative;
  display: inline-block;
  overflow: hidden;
  margin-block: calc(var(--feather) * -1);
  padding-block: var(--feather);
  mask-image: linear-gradient(to bottom, transparent, #000 calc(var(--feather) * 1.5), #000 calc(100% - var(--feather) * 1.5), transparent);
}
.sizer { visibility: hidden; }
.glyph { position: absolute; inset: var(--feather) 0; text-align: center; }
```
1. **静态骨架（`.sizer`）**：`<span className={styles.sizer}>0</span>` 处于正常文档流中，在 `tabular-nums` 等宽字体下牢牢撑开字宽与基线高度；
2. **绝对定位解除回流（`.glyph`）**：滚动的数字全部绝对定位，运动时**容器物理尺寸零变动**，浏览器不触发 Reflow，仅在 GPU 执行合成；
3. **羽化蒙版（Mask Feathering）**：`mask-image` 配合内补丁，使数字在到达边缘前 0.24em 渐隐，消除生硬横切线；
4. **`bounce: 0` 临界阻尼**：宽度伸展动画绝不反弹，防止右侧文本像果冻一样左右抽搐。
