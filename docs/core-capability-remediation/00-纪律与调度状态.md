## 二、方案文档结构规范

每份方案文档必须严格按照以下结构组织：
1. **现状与根因穿透**：列明当前代码中的具体 `文件路径:行号`、表面功夫的表现与深层架构断裂。
2. **架构重构设计与核心契约**：给出彻底解决问题的新架构，拒绝修修补补，给出清晰的数据结构、状态机转移与接口契约。
3. **改动文件与接口清单**：明确列出涉及的全部 Rust/TS 文件及具体的改动职责。
4. **非必要不兼容声明**：列出哪些历史死代码、胶水层、伪兼容代码需要在此次重构中物理拔除。
5. **立体验证与验收用例设计**：覆盖单元测试、极端并发测试、端到端现场验收步骤。
