### 1.1 SSE 分帧器脆弱性与合法增量丢弃（BC08-3）

* **代码锚点**：
  * 分隔符匹配：[`crates/agent-provider/src/sse/frame.rs:202-220`](file:///c:/Software/conex/crates/agent-provider/src/sse/frame.rs#L202-L220)
  * 步进长度计算：[`crates/agent-provider/src/sse/frame.rs:226-232`](file:///c:/Software/conex/crates/agent-provider/src/sse/frame.rs#L226-L232)
  * 多行拼接与 JSON 解析：[`crates/agent-provider/src/sse/frame.rs:247-285`](file:///c:/Software/conex/crates/agent-provider/src/sse/frame.rs#L247-L285)
  * 分帧循环与错误传播：[`crates/agent-provider/src/sse/frame.rs:161-193`](file:///c:/Software/conex/crates/agent-provider/src/sse/frame.rs#L161-L193)
* **表现与根因穿透**：
  1. **分隔符盲区导致挂起与虚假超限**：
     标准 WHATWG Server-Sent Events 规范明确规定行分隔符可为 `CRLF`、`LF` 或单个 `CR`，事件间空行可以是 `\r\n\r\n`、`\n\n`、`\r\r`、`\n\r\n` 或 `\r\n\n`。然而当前 `find_separator` 仅硬编码查找 `\n\n` 和 `\r\n\r\n`，`separator_len` 仅在以 `\r\n\r\n` 起始时计为 4、其余硬返回 2。当遇到中间代理或部分供应商吐出的 `\r\r` 或 `\n\r\n` 时，分帧器完全无法识别帧边界，数据一直积攒在 `pending` 缓冲中，最终触发 `MAX_PENDING_BYTES` (4MB) 虚假溢出并报错 `FrameTooLarge` 炸流。
  2. **多行 `data:` 粘连为非法 JSON 破坏流**：
     在 `parse_frame_body` 中，多行 `data:` 被简单使用 `\n` 连接成一个单一字符串 `data = data_lines.join("\n")`，随后直接调用 `serde_json::from_str::<Value>(&data)`。当代理为了压缩 TCP 交互，在一个 SSE 批次内推送多个独立的单行 JSON 对象时（如 `data: {"type":"delta",...}\ndata: {"type":"delta",...}`），拼接后的字符串不再是单个合法 JSON，触发 `MalformedSseFrame` 错误。
  3. **单帧异常导致先前已解析增量与缓冲状态全量丢弃（Drain Failure）**：
     在 `split_frames` 循环中：
     ```rust
     if let Some(frame) = parse_frame_body(&body)? {
         ...
         frames.push(frame);
     }
     consumed = index + sep_len;
     ```
     一旦中间某帧由于非标格式报错，`?` 操作符直接让函数提前退出。后果极其恶劣：
     * 本次 `push` 批次中排在坏帧前面的全部合法已解析帧 `frames` 被直接 drop 丢弃！
     * `self.pending.drain(..consumed)` 未被调用，缓冲游标根本没有向前移动！
     * 损坏的数据仍然堵在 `self.pending` 头部，导致下一次调用必然再次在同一坏帧上溃败，整条正在流式传输的对话彻底中断。
  4. **合法 JSON 数组被静默丢弃**：
     `match serde_json::from_str::<Value>(&data)` 在遇到 `Ok(Value::Array(_))` 时落入 `Ok(_) => Ok(None)`，没有任何日志记录，直接当作空帧吞掉（如部分代理将 Gemini 多 candidate 封装为数组返回时导致回答完全蒸发）。

## 二、架构重构设计与核心契约

为从根源根除上述缺陷，方案坚决杜绝“打补丁”、“加兼容器”式的临时修补，重构建立清晰的四层防御体系：
1. **传输分帧层**：WHATWG 规范兼容的有限状态机单遍扫描器，多 JSON 流式解包，隔离性排空保障与 HTTP Content-Type 响应自适应路由。
2. **协议方言层**：思考块完整签名与加密载荷保真，端到端原样回放，Gemini 工具选择白名单精准注入，Anthropic 运行时转向保全。
3. **出站安全闸门**：Responses 协议出站工具调用成对性（Tool Pairing Gate）验证刚性守门，孤儿调用在本地 Fail-Closed 拦截。
4. **流式消费与用量层**：基于协议族的 SSOT 缓存计费口径（Included vs Excluded）注入，全生命周期（正常、截断、错误、取消）用量保全，错误分类真源流转。

### 2.1 稳健 SSE 分帧器与传输层重构（BC08-3, BC08-1, BC08-2）

#### 2.1.1 WHATWG 兼容的全分隔符有限状态机（FSM）

废弃原脆弱的 `find_separator`，在 [`crates/agent-provider/src/sse/frame.rs`](file:///c:/Software/conex/crates/agent-provider/src/sse/frame.rs) 中实现单遍状态机，精确捕获所有合法的 SSE 事件边界，并准确计算边界字节跨度。

```rust
/// 识别出的 SSE 帧边界
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct SseSeparator {
    /// 分隔符在缓冲区的起始字节偏移
    pub offset: usize,
    /// 分隔符跨越的字节长度（2、3 或 4 字节）
    pub len: usize,
}

/// 单遍状态机扫描合法帧边界
/// 覆盖：\r\n\r\n (4), \n\n (2), \r\r (2), \n\r\n (3), \r\n\n (3)
pub fn find_sse_separator(bytes: &[u8]) -> Option<SseSeparator> {
    let mut i = 0;
    while i < bytes.len() {
        match bytes[i] {
            b'\n' => {
                if bytes.get(i + 1) == Some(&b'\n') {
                    return Some(SseSeparator { offset: i, len: 2 });
                } else if bytes.get(i + 1) == Some(&b'\r') && bytes.get(i + 2) == Some(&b'\n') {
                    return Some(SseSeparator { offset: i, len: 3 });
                }
            }
            b'\r' => {
                if bytes.get(i + 1) == Some(&b'\n') {
                    if bytes.get(i + 2) == Some(&b'\r') && bytes.get(i + 3) == Some(&b'\n') {
                        return Some(SseSeparator { offset: i, len: 4 });
                    } else if bytes.get(i + 2) == Some(&b'\n') {
                        return Some(SseSeparator { offset: i, len: 3 });
                    }
                } else if bytes.get(i + 1) == Some(&b'\r') {
                    return Some(SseSeparator { offset: i, len: 2 });
                }
            }
            _ => {}
        }
        i += 1;
    }
    None
}
```

#### 2.1.2 多 JSON 流式反序列化与坏帧隔离排空保证

针对单帧内多行 `data:` 或单行内多个紧密排列的 JSON 对象，采用流式迭代提取；对于单帧解析故障，实行强制 `drain` 隔离，绝不波及已解析帧。

```rust
impl SseParser {
    /// 从 pending 中提取全部已就绪帧，杜绝坏帧级联丢帧
    fn split_frames(&mut self) -> (Vec<SseFrame>, Option<SseFrameError>) {
        let mut frames = Vec::new();
        if self.done {
            return (frames, None);
        }

        let mut consumed = 0usize;
        let mut terminal_err: Option<SseFrameError> = None;

        while consumed < self.pending.len() {
            let Some(sep) = find_sse_separator(&self.pending.as_bytes()[consumed..]) else {
                break;
            };

            let frame_start = consumed;
            let frame_end = consumed + sep.offset;
            let next_consumed = frame_end + sep.len;

            let body = &self.pending[frame_start..frame_end];
            match parse_frame_body_flexible(body) {
                Ok(mut parsed_frames) => {
                    for frame in parsed_frames.drain(..) {
                        if frame.is_done() {
                            self.done = true;
                            frames.push(frame);
                            consumed = next_consumed;
                            self.pending.clear();
                            return (frames, None);
                        }
                        frames.push(frame);
                    }
                    consumed = next_consumed;
                }
                Err(err) => {
                    tracing::warn!(
                        target: "agent_provider::sse",
                        error = %err,
                        raw_body = %body,
                        "SSE 单帧数据格式异常，已主动切除跳过，保护既有帧安全"
                    );
                    // 核心铁律：必须推进 consumed，将坏帧物理排空，杜绝死锁与丢弃前面的合法帧
                    consumed = next_consumed;
                    terminal_err = Some(err);
                    // 遇到格式异常时记录，但不提前中断循环，继续尝试消费后续就绪帧
                }
            }
        }

        if consumed > 0 {
            self.pending.drain(..consumed);
        }

        (frames, terminal_err)
    }
}

/// 弹性帧体解析：支持多 data 行聚合解析、多 JSON 对象流式解包、JSON 数组平铺
fn parse_frame_body_flexible(body: &str) -> Result<Vec<SseFrame>, SseFrameError> {
    let mut event = None;
    let mut id = None;
    let mut retry = None;
    let mut data_lines = Vec::new();

    for line in body.lines() {
        let trimmed = line.trim();
        if let Some(rest) = trimmed.strip_prefix("data:") {
            data_lines.push(rest.trim());
        } else if let Some(rest) = trimmed.strip_prefix("event:") {
            event = Some(rest.trim().to_string());
        } else if let Some(rest) = trimmed.strip_prefix("id:") {
            id = Some(rest.trim().to_string());
        } else if let Some(rest) = trimmed.strip_prefix("retry:") {
            retry = rest.trim().parse::<u64>().ok();
        }
    }

    if data_lines.is_empty() {
        return Ok(Vec::new());
    }

    // 1. [DONE] 哨兵直通
    if data_lines.len() == 1 && data_lines[0] == "[DONE]" {
        return Ok(vec![SseFrame {
            event,
            data: Some("[DONE]".to_string()),
            id,
            retry,
        }]);
    }

    let joined = data_lines.join("\n");
    let mut results = Vec::new();

    // 2. 尝试单对象/整体解析
    if let Ok(val) = serde_json::from_str::<Value>(&joined) {
        match val {
            Value::Object(_) => {
                results.push(SseFrame {
                    event,
                    data: Some(joined),
                    id,
                    retry,
                });
                return Ok(results);
            }
            Value::Array(items) => {
                // 平铺 JSON 数组中的每个对象为独立事件帧
                for item in items {
                    if item.is_object() {
                        results.push(SseFrame {
                            event: event.clone(),
                            data: Some(item.to_string()),
                            id: id.clone(),
                            retry,
                        });
                    }
                }
                return Ok(results);
            }
            _ => return Ok(Vec::new()), // 非对象 keep-alive 忽略
        }
    }

    // 3. 多 JSON 紧密拼接场景：流式反序列化提取（Stream Deserializer）
    let de = serde_json::Deserializer::from_str(&joined);
    let mut stream = de.into_iter::<Value>();
    let mut parsed_any = false;

    while let Some(Ok(val)) = stream.next() {
        if val.is_object() {
            parsed_any = true;
            results.push(SseFrame {
                event: event.clone(),
                data: Some(val.to_string()),
                id: id.clone(),
                retry,
            });
        }
    }

    if parsed_any {
        return Ok(results);
    }

    // 若内容形似 JSON 却完全无法解析，抛出 MalformedSseFrame 供隔离记录
    if joined.trim_start().starts_with('{') || joined.trim_start().starts_with('[') {
        return Err(SseFrameError::MalformedSseFrame { raw: joined });
    }

    Ok(Vec::new())
}
```

```rust
/// 扫描 Responses input items 中的孤儿工具调用与孤儿结果
pub fn detect_responses_unpaired_tool_calls(items: &[Value]) -> Vec<String> {
    let mut call_ids = std::collections::HashSet::new();
    let mut output_ids = std::collections::HashSet::new();
    let mut orphan_ids = Vec::new();

    for item in items {
        let item_type = item.get("type").and_then(Value::as_str).unwrap_or("");
        match item_type {
            "function_call" => {
                if let Some(call_id) = item.get("call_id").and_then(Value::as_str) {
                    call_ids.insert(call_id.to_string());
                }
            }
            "function_call_output" => {
                if let Some(call_id) = item.get("call_id").and_then(Value::as_str) {
                    output_ids.insert(call_id.to_string());
                }
            }
            _ => {}
        }
    }

    // 检查有 call 无 output
    for cid in &call_ids {
        if !output_ids.contains(cid) {
            orphan_ids.push(cid.clone());
        }
    }
    // 检查有 output 无 call
    for oid in &output_ids {
        if !call_ids.contains(oid) && !orphan_ids.contains(oid) {
            orphan_ids.push(oid.clone());
        }
    }

    orphan_ids
}

/// 刚性出站校验：存在孤儿工具调用直接阻断，杜绝远端 400
pub fn validate_responses_tool_pairing(items: &[Value]) -> Result<(), RequestBuildError> {
    let orphans = detect_responses_unpaired_tool_calls(items);
    if !orphans.is_empty() {
        return Err(RequestBuildError::UnpairedToolCalls {
            orphan_ids: orphans,
        });
    }
    Ok(())
}
```
