# F3 审计：Provider 与工具层（agent-provider / agent-tools / conex-sandbox / conex-fs / conex-search）

- 审计日期：2026-08-07
- 审计模式：只读（未改动任何源码）
- 审计范围：
  - `crates/agent-provider/src/`（全部：sse / transport / parse / request / consume / error / retry / config / credentials / models）
  - `crates/agent-tools/src/`（全部：executor / context / middleware / permission / shell / fs / write_paths / explore_quota / subagent / output_dir / mcp 等）
  - `crates/conex-sandbox/src/lib.rs` + `src/semantics.rs`
  - `crates/conex-fs/src/lib.rs`（path_utils / trash / watch / impact）
  - `crates/conex-search/src/lib.rs`
- 审查维度：SSE/流解析边界、请求构建、错误分类与重试、工具执行安全、ToolContext 边界、search/fs、错误处理残留、测试盲区（8 项全覆盖）

---

## 结论（先行）

架构质量总体很高：SSE 双段超时/abort 竞速（biased）、每流恰好一个 stop 的状态机、`[DONE]` 哨兵消费、错误帧后终止、Retry-After 钳制 5 分钟、红线先行（任何权限模式不可豁免）、删除形态接管回收站、影响面遍历不跟随符号链接、编码 lossy 护栏、幂等域与中间件超时，均为设计严谨且测试充分的实现。**未发现可被无条件利用的通用漏洞**（红线门禁 + 删除接管 + 审批矩阵整体闭合）。

但存在 **1 个 P0（命令语义门禁可被换行符分隔绕过）** 与 **3 个 P1（写路径符号链接逃逸、搜索器 Unicode 折叠越界 panic、流内错误永不重试）**，另有 10 项 P2。P0 的利用前提是模型（或被注入的模型上下文）输出特定形态命令，实际风险取决于工作区是否允许非首 token 的毁灭性命令形态；建议优先修复。

## 按审查维度的补充说明

1. **SSE/流解析边界**：分帧/UTF-8 增量/`[DONE]` 消费/错误帧后终止/finish 幂等/双段超时+abort 竞速均有测试且实现正确（frame.rs、reader.rs）。缺口：单帧与全文无大小上限（#5）；`read_sse_stream` 在 `[DONE]` 后不再调 finish——分帧层 `done` 已置位，行为正确，但流状态与 EOF 路径不一致的边界缺少测试。
2. **请求构建**：消息映射边界（空消息跳过、Require 空思考带键、id 消毒、canonical 序列化）覆盖好。缺口：`temperature` 传 NaN/Inf 时 `json!()` 静默变 `null`（build.rs:137-139 无有限性校验，provider 可能 400）；max_tokens 0/超大无钳制（透传）；URL 拼接在 agent-provider 无发送层（发送在引擎侧，base_url 原样透传，本审计范围仅记录）。#8 为 id 兜底碰撞。
3. **错误分类与重试**：分类表 13 行逐行测试、优先级正确；Retry-After 秒/HTTP-date/负值/超大钳制完备（#11 极端年份溢出例外）；重试预算共享语义正确（state 由调用方持有，文档化）。缺口：#4 流内错误永不重试。
4. **工具执行安全**：红线先行、三态矩阵、删除接管、cd 拦截、write_claims 互斥、中间件超时均强。缺口：#1 换行分隔绕过（P0）、#2 符号链接写逃逸（P1）、#7 ask 默认放行、#9 配额 TOCTOU。
5. **ToolContext 边界**：abort_token 为轮询式（长任务需自查，shell 超时树杀互补）；workspace_root 为空/不存在时 resolve 路径 fail-safe（文本包含性校验拒绝）；ask 并发：每次 execute 独立 ask，重试会重复询问（安全方向正确，UX 可优化）。
6. **search/fs**：grep_search 有 max_files/max_file_bytes/max_matches/gitignore/max_depth 全套护栏；fuzzy `build_directory_index` 无文件数/内存上限（巨型仓库全量驻留，P2 提示）；`impact::assess` 遍历不跟随 symlink 且防环（正确）；编码检测 BOM/NUL/lossy 标记完备。#3 为 fuzzy 折叠 panic。
7. **错误处理**：生产路径 unwrap/expect 基本清干净（frame.rs 两处 expect 有前置 from_utf8 校验属合理保留）；`subagent.rs:2560/2566` 锁 unwrap 违反项目恢复式惯例（#10）；`let _` 吞错集中于审计 sink 与诊断（可接受）；`classify_stream_error` 用 unwrap_or_default 兜底序列化失败（consume/mod.rs:290）可接受。
8. **测试盲区**（对应上述发现，均无覆盖）：
   - 换行符分隔 + `--` 变体 + PowerShell 别名的红线绕过（#1）
   - 符号链接父目录 + 新建文件写入逃逸（#2）
   - Unicode 折叠（İ）fuzzy 匹配（#3）
   - 流内 error 帧 → 重试链（#4）
   - 超长单帧/慢流内存压力（#5）
   - gatekeeper 前缀混淆 `C:/project` vs `C:/project_evil`（#6）
   - ask=None 危险工具执行路径（#7）
   - 并行写文档配额竞争（#9）
   - Retry-After 极端年份（#11）
