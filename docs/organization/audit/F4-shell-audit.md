- 严重度：P0 = 直接可利用高危；P1 = 明确缺陷需优先修复；P2 = 边界/健壮性缺陷；P3 = 已知登记/设计权衡

## 结论先行

整体工程纪律与安全设计在该量级的 Tauri 壳中属**上游水平**：统一错误协议（CoreError）、注册面与 manifest 双源测试锁定、WorkspaceRegistry 沙箱信任锚、git 参数白名单、统一门禁（CommandGatekeeper）、DPAPI 密钥槽、删除接管（trash）等均已成体系，且每层都有测试锚定。

**未发现 P0**。共记录 **6 项 P1、17 项 P2、7 项 P3/观察项**。P1 集中在四类：

1. **配置不生效**：`config_profile_apply` 声称"进程内直写引擎"，但 `EngineHandle` 的 provider（含 apiKey/baseUrl/model）是构造时一次性快照，运行期改配置后下一次 run 仍使用旧凭据（engine.rs:927-945 与 provider.rs:479-533 断开）。
2. **沙箱绕过变体**：
   - 写路径 dangling symlink 逃逸（types.rs:164-212 词法分支 + write.rs:38-48 create_dir_all 跟随）；
   - 会话产出目录 meta 相对路径无工作区校验，删除会话可 trash 工作区外目录（outputs_config.rs:340-342）；
   - `core_rebuild_search_index` 接受任意 root，绕开目录枚举沙箱（core_commands.rs:161-187）。
3. **git/push 白名单绕过**：`push` 的 `+refspec` 前缀等价 `--force`，未被 C-04 声称的"拒绝 force push"覆盖（git.rs:121-123 + 381-389）。
4. **shell 拼串残留**：`open_path_with_default_app` 仍走 `cmd /C start "" <target>` 拼接（execute.rs:267-268），`&` 元字符注入面依赖红线正则（只覆盖毁灭性命令）。
