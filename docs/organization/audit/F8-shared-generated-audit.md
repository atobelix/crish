## 0. 结论摘要

共享层整体防御设计扎实：生成 parser 对未知事件类型/未知枚举值 fail-closed（parseEngineEvent 无 default 放行）、Rust↔registry 双向漂移护栏（`registry_drift.rs`）与 CI 生成物新鲜度门禁（`ci.yml` engine-bindings-drift）构成三层防护；前端消费面（`eventParser.ts` 宽容归一 + EventRouter 显式 unknown 登记）也以"可观测不静默吞"为原则。但存在以下结构性缺陷：

**P0 级问题 0 项。P1 级 6 项**（按影响排序）：

1. 生成 parser 递归无深度上限 → 深层载荷栈溢出逃逸 ParseResult，且消费侧无 try/catch；
2. `tool.write_path_conflict` 错误码漏注册（共享码表 TS/Rust 双侧缺失，无漂移守卫所以能漏）；
3. `JsonlAppendBatcher` 写失败静默吞数据（主持久化路径）；
4. `StreamingFileReader` UTF-8 多字节字符跨块截断 → 中文内容损坏；
5. plugin-sdk 路径逃逸校验（assertPathWithinPluginDir）生产链路零接线，绝对路径入口可直接进 dynamic import；
6. PluginLoader 失败路径 TrustGate 缓存泄漏 + Validator 在 manifest 缺能力清单字段时抛 TypeError 绕过回滚。

**流程缺口**：错误码清单无 TS↔Rust 双向漂移测试（事件有，错误码没有）；本地开发无"改 registry 必须重生成"的钩子（仅 CI 兜底）；生成 parser 无任何对抗性单测。

## 2. 维度核查结论

### 2.1 生成代码（parser / 漂移守卫 / 错误行为）

- **fail-closed 判定**：整体合格。未知事件类型、未知枚举值、缺必填字段、类型错配全部返回 `ParseResult.err`；`parseEngineEvent` 无 default 放行分支（parser.ts:1791-1839）。未知事件在消费侧显式登记（EventRouter.ts:119-127），不静默吞。
- **fail-open 残留点**：整数语义放宽（F8-07）、可选字段 null 严格化（F8-08 属过度严格而非放宽）、递归深度异常（F8-01 属崩溃型，比 fail-open 更糟）。
- **漂移守卫**：三层（cargo test registry_drift.rs 双向锁 Rust↔registry；CI engine-bindings-drift 锁 registry→TS 生成物；生成器自身 validateRegistry 自洽校验）。缺口在错误码域（无守卫，见 F8-42）与本地开发新鲜度（F8-14）。
- **生成管线**：`scripts/generate-engine-bindings.mjs` 确定性输出（无时间戳/随机数），HEADER 注明真源与再生成命令；registry 校验含 I5-M7 背压级别全覆盖断言。管线设计合格。

### 2.2 类型一致性

- 生成 schema（events.ts/types.ts/parser.ts）与 registry 一一对应（生成器驱动），registry 与 Rust serde 行为被 registry_drift.rs 锁定——**生成侧无漂移**。
- **漂移全部集中在手写类型**（events.ts/tool.ts）：AgentEndReason 缺 stopped（F8-09）、approval-resolved 语义错位（F8-10）、ProviderDiagnostic.phase 缺 invalid-tool-call（F8-11）、ProviderErrorKind 名集陈旧（F8-12）、providerRetry 字面量 false（F8-13）。根因：双源维护。修复方向：手写事件/工具类型改为 re-export 生成类型或生成驱动。

### 2.3 错误体系

- 码集合现状：TS codes.ts 82 码 = Rust codes 模块 82 常量 = Rust CRISH_ERROR_REGISTRY 82 条插入（实测计数一致，注释里"79"为陈旧文案）。
- **唯一漏码**：tool.write_path_conflict（F8-02）——发生在 codes 模块之外（agent-tools 局部 const），正因无 TS↔Rust 码清单漂移测试而漏网。这是本审计在错误域的最实质发现。
- 分类边界：category 四类（transient/permanent/security/protocol）两侧同构；Rust `CrishErrorCategory`（error.rs:27-36）与 TS 一致。
- cause 链：双侧 depth=8 对齐，截断语义见 F8-28。

### 2.4 工具函数边界

- RingBuffer：容量 0/负/NaN 拒绝（F8-20 分数容量缺口）；覆盖语义双 API（push 丢弃 / pushOverwritingOldest 覆盖）明确。
- retry：retry-openai.ts 钳制完备（Retry-After 上限 5min、预算、jitter 钳制）；retry.ts 存在 maxAttempts≤0→throw undefined 与软上限问题（F8-16）。
- 流式文件工具：UTF-8 半字符截断（F8-04，P1）；diff parser 无界 buffer + 行号漂移（F8-21）；jsonl reader 损坏行静默跳（F8-22）；WAL 缺目录 fsync（F8-18）与畸形行崩溃（F8-19）。
- 持久化：JsonlAppendBatcher 静默吞写失败（F8-03，P1）为最高危项。

### 2.5 logger/telemetry

- `packages/logger`、`packages/telemetry` **不存在**；logger 实现于 shared-utils/src/logger.ts（108 行），telemetry 面为 metrics-exporter.ts/prometheus-exporter.ts（117/2800 字节）。
- 脱敏：默认恒等 + 无调用点 + 仅 msg 不覆盖 meta（F8-17）——按"安全基线"标准为不达标，但当前无接线意味着实际日志面暂无脱敏承诺。
- 级别过滤：LEVEL_PRIORITY 数值比较正确，无边界问题。RingBuffer 容量与丢弃语义见 F8-20（logger 未使用 RingBuffer）。

### 2.6 plugin-sdk

- 注册/生命周期：状态机（plugin-state.ts）+ 能力清单后置比对（PluginValidator）+ 失败回滚设计良好，但存在 F8-06 的异常路径绕过。
- 权限边界：TrustGate 为依赖注入契约（实现归属 agent-permissions），plugin-sdk 自身不校验权限——属设计决策；full 级别"无校验"语义需宿主严格管控授权面（F8-30 的独立调用缺口）。
- manifest 校验：字段必填性校验不全（F8-06）、origin 限制条件性生效（F8-30）、路径逃逸校验未接线（F8-05，P1）。
- 代码执行面：同进程 dynamic import 有环境变量门，但门控语义为"dev/spike only"，生产构建若继承该环境变量即失去保护——建议生产构建强制关闭（打包时剔除）。

### 2.7 decision-engine

- `packages/decision-engine` **不存在**。命令分类/权限判定在 Rust 侧（agent-tools/agent-permissions），不在本审计范围。无对应发现。
