# F2 审计：orchestrator 与 conex-db 编排/数据层边界审计报告

- 审计日期：2026-08-07
- 审计范围：`crates/orchestrator/`（全部）+ `crates/conex-db/`（全部）；只读审计，未改任何代码
- 审计维度：orchestrator 边界 / 恢复与快照 / conex-db 迁移 / SQL 与数据完整性 / 并发写 / 错误处理 / 测试盲区
- 严重度：P0（数据丢失或库不可打开）＞ P1（一致性/竞态缺口，有真实触发路径）＞ P2（边界瑕疵、防御不足、性能）

---

## 结论（TL;DR）

**总体判断**：两 crate 的架构质量高——会话级原子取号（T08.12）、状态机终态拒绝、快照双文件损坏回退、迁移逐版本事务、LocalDbStore 全量 spawn_blocking 包裹等核心防线均落地且测试充分。**未发现 P0**。

但有 **2 个 P1 级崩溃一致性缺口**、**2 个 P1 级数据丢失窗口**和 **1 个 P1 级生产接线缺失**需要优先处理：

1. **迁移崩溃窗口（P1）**：`PRAGMA user_version` 设置在迁移事务之外，且 v3→v4 的 `session_messages ADD COLUMN updated_at` 无幂等检查——「commit 成功 → user_version 更新前崩溃」后重跑迁移必然 `duplicate column` 失败，库进入 failure latch 不可打开。
2. **flow 重复 spawn（P1）**：`FlowScheduler::advance` 中 spawn 成功后仅在整轮循环结束才持久化 `flow_state`——「spawn 成功 → 崩溃」重启后节点重建为 Pending，同一节点被再次 spawn（旧 run 孤儿双跑）。
3. **孤儿清理误删运行中会话（P1）**：`cleanup_orphan_sessions` 只按 `updated_at` 宽限期判定，不检查 in-flight run——运行中 run 的会话若超过宽限期未 touch，级联删除 runs/events/pending_inputs。
4. **快照并发写（P1）**：`save_snapshot_now` 无互斥，终态/周期/退出三触发可并发；tmp 文件名固定（`{path}.{pid}.tmp`），并发写同一文件可致快照损坏（有 .prev 兜底，后果降级）。
5. **C7 恢复阶梯生产未接线（P1）**：`RecoveryCoordinator::on_subagent_run_failure`（阶梯 1/2）在生产二进制中无调用点，仅测试与 `resume` 命令面覆盖——子代理 run 失败时引擎侧不会自动重试/steering。

其余为 P2 边界瑕疵（详见清单）。编码检查：审计范围内源文件 UTF-8 无 BOM、中文完好（`?` 均为终端显示问题，非文件损坏）。

## 二、各维度结论

1. **orchestrator 边界**：会话级原子取号（persist.rs:226-234 + conex-db events.rs:72-98，单连接互斥下成立）与终态唯一事件（normalize.rs:116-120 + run.rs:130-135）是可靠防线；跨 run 并发取号有 stress 测试锚定。主要风险在「终态收口错位」（F2-03）与「fork 幂等后置」（F2-09）。
2. **恢复与快照**：双文件轮转 + checksum 回退 + 增量重放设计健壮；主要缺口在「打断非原子」（F2-10）与「保存并发」（F2-11）。
3. **迁移**：逐版本事务 + 备份时序确定化（11-T2）完成度高，唯一 P1 是 user_version 事务外（F2-01/16）；v3→v4 是唯一非幂等步骤，是迁移链最薄弱环。
4. **SQL 与数据完整性**：参数化全覆盖（无字符串拼接注入面，cleanup 的动态 IN 占位符构造正确）；主要风险在孤儿清理的 in-flight 误删（F2-22）。
5. **并发写**：LocalDbStore 全量 spawn_blocking ✓；RecoveryStore/lifecycle 同步面未包裹（F2-27，接线前必须处理）；快照保存无互斥（F2-11）。
6. **错误处理**：DbFailure → StoreError → CrishError 映射链完整（error.rs:69-75 + persist.rs:242-250）；吞错集中在文件轮转与 WAL PRAGMA 三处（F2-31）。
7. **测试盲区**：迁移中断（F2-36）与 flow 重复 spawn（F2-37）是两个最值得补的崩溃一致性用例；现有 crash_consistency.rs（921 行）与 migrations.rs（900 行）覆盖质量高，缺口集中在「多语句持久化之间崩溃」的错位窗口。
