## 二、目标与边界

### 2.1 目标

1. 中层两 job（`test` / `test:integration`）由"确定性必红"转为"确定性全绿"，且**非空跑**（有真实用例执行）；
2. TS 压力轨（tests/stress）从"零产品接触"转为"真实驱动生产模块"，注入 bug 可红；
3. 门禁口径统一：coverage 单一口径、`--locked` 全覆盖、knip 或接线或明确搁置、e2e 归位（Playwright 管 e2e，vitest 管非 e2e）；
4. 全部验收以**实跑输出**为准（命令 + EXIT code + 关键输出行），留下红→绿证据链。

### 2.2 边界（明确不修什么）

- **不改 crates/ 下任何内核代码**（Rust 内核零改动；`cargo` 命令仅改 workflow 参数）。
- 不修 P0-1（命令红线）、P1 安全组/数据组/会话循环组/壳引擎组/前端组——本任务书只覆盖 P0-2/3/4 + P1-C1/C2/C3/C4。
- 不落地 bench 轨改造（R3 已纠偏为非空转）；不接 visual 回归（F10-10，另立任务）。
- 不动 `reference/markdown-editor/`（AGENTS.md 铁律：测试资产禁止删除/清理）。
- **禁止删除 tests/e2e 下 5 个 markdown-editor 专项 spec**（ast-block-tables / format-checker / ime-composition / keyboard-navigation / wysiwyg-interaction）。
- 覆盖率阈值只允许"对齐实测基线 + 注释理由"，禁止无依据单向下调。

## 四、防作弊条款（强制执行）

1. **实跑证据格式**：每条验收必须记录 `$ <命令>` → `EXIT=<n>` + 关键输出行（≤5 行），登记位置三选一：提交信息、PR 描述、任务产出文档。**只给结论不给实跑记录的验收视为未完成**。
2. **红→绿证据链**：每个任务先记录改动前红（EXIT≠0 + 错误行原文），再记录改动后绿。红证据可引用 R3/F10 已实跑记录（注明出处），但**改动后绿必须本人实跑**。
3. **禁止假绿手段**（发现即打回）：
   - 删除/缩小测试文件集让 job 空跑（include 缩窄必须伴随"文件确实不属于该层且下层接管"的证据；vitest 项目空匹配即"空跑"，不允许 `passWithNoTests` 式假绿）；
   - 命令加 `|| true`、`continue-on-error: true`、临时注释/删除 job 后不还原、`git commit --no-verify`；
   - 阈值无依据单向下调掩盖回归（阈值调整必须附实测基线数据 + 注释理由 + 余量说明）；
   - 把断言改写成恒真（如 `expect(x).toBeTruthy()` 替代具体值）——stress 不变式必须可失败。
4. **快层门禁不回退**：`npm run test:coverage -- --project=unit`（45/70/65/45）与 `cargo check --workspace --locked` 全程保持绿。
5. **测试资产保护（AGENTS.md 铁律）**：`reference/markdown-editor/` 全部源码与测试禁止删除/清理；tests/e2e 5 个 markdown-editor 专项 spec 禁止删除（T2.7 可跑它们、绝不删）；新增/调试脚本立即 `git add` 提交，不留未跟踪状态。
6. **变更面核对**：全部任务不得触碰 `crates/` 下内核代码；执行中发现必须改内核才能完成某项时，**停止并上报调度者裁决**（任务书不授权越界）。
