## 一、目标与边界

### 1.1 目标

修复 P1 数据组全部 8 项，使以下契约成立：

| 契约                                       | 对应任务  | 失效后果                             |
| ------------------------------------------ | --------- | ------------------------------------ |
| 迁移崩溃重跑自愈，库永远可打开             | T3.1 (D1) | 库进入 failure latch 永久不可开      |
| 前端持久化旧批次不得覆盖新批次             | T3.2 (D6) | 已提交消息回滚消失                   |
| 孤儿清理不删运行中会话                     | T3.3 (D3) | 运行中 run + 全部事件被级联静默删除  |
| flow 节点 spawn 后崩溃不重复 spawn         | T3.4 (D4) | 同一任务孤儿双跑                     |
| 快照并发保存不损坏文件                     | T3.5 (D5) | 主快照损坏（.prev 兜底降级）         |
| 懒水合 >800 事件不截断、截断态不固化回写   | T3.6 (D2) | 长会话正文不可逆截断                 |
| parser 深层载荷返回 ParseResult 而非抛异常 | T3.7 (D7) | RangeError 逃逸破坏 fail-closed 契约 |
| StreamingFileReader 跨块 UTF-8 不损坏      | T3.8 (D8) | 中文/emoji 每 64KB 边界 U+FFFD 污染  |

### 1.2 边界（依赖与约束）

1. **D1 迁移框架改动必须覆盖已有库形态**（R2 §1）：修复后的 v3→v4 步骤需同时兼容三类库——
   ① 正常 v3 结构 + user_version=3；② 崩溃中间态 v4 结构 + user_version=3（commit 已成功、PRAGMA 未执行）；③ 已完整迁移的 v6 生产库（user_version=6，重跑幂等 no-op）。既有 `migrations.rs`（900 行，覆盖 v0/v1/v2/v3/v5 fixture、幂等二次 open、备份黄金字节）与 `upgrade_e2e.rs` 全部保持绿。
2. **T3.2 是唯一改动 Rust 命令面的任务**：批次戳 CAS 需要 `save_session_body` 增加入参（messages.rs:66-94 为 DELETE+INSERT 全量替换）。命令签名变更必须同步更新命令 manifest（双源校验）与 TS 调用面；若评审裁定 CAS 风险过大，允许降级为「纯前端串行队列 + 契约测试修正」，降级需在提交说明中显式声明。
3. **T3.7 的生成器与生成物必须同一提交**：`scripts/generate-engine-bindings.mjs` PARSER_PREAMBLE 与重生成的 `parser.ts` 一起提交，否则 CI engine-bindings-drift 门禁必红。
4. **T3.6 与 T3.2 共享文件族**（sessionRustDb.ts / store-persistence.ts）：串行执行，T3.6 排在 T3.2 之后，避免同文件并行冲突。
5. **测试资产保护铁律**：本组新增测试文件与测试断言全部入库提交；不删除任何既有测试（T3.2 删除的是**错误契约断言**，属契约修正，git diff 须可见「断言方向翻转」而非「删测试逃逸」）。
6. 本任务书只写方案，不改代码；每项任务的实现、红绿提交、测试输出报告由实现轮承担。

## 三、防作弊条款（实现轮必须遵守）

1. **红测试先行，每项两段提交**：每项任务先写红测试（复现原缺陷的断言：崩溃重跑失败 / 旧覆盖新 / 运行中会话被删 / 重复 spawn / 快照损坏 / 截断回写 / parser 抛异常 / U+FFFD），确认**红**（附测试输出）→ 改实现 → 确认**绿**。git 提交记录必须体现「红测试」与「修复实现」两笔（或至少 diff 可见测试先于实现）。
2. **T3.2 契约修正规则**：必须先修正错误契约测试（把「旧覆盖新」断言改为「新不被旧覆盖」）再改实现；**禁止保留任何形式的旧覆盖新断言**（删除 :278-308 原用例；git diff 必须可见断言方向翻转，不允许以「删测试逃逸」方式绕过）。若实现轮认为原「最后写者胜」语义有业务理由，必须先在评审中提出，未经裁决不得保留。
3. **禁止 sleep/固定时序掩盖竞态**：所有并发测试使用真实并发原语——Rust 侧 `tokio::join!` / spawn + join（必要时 Barrier）；TS 侧 `Promise.all` + 夹具注入延迟（如既有 `saveDelayMs/probeDelayMs` 机制）。测试内禁止出现「等 500ms 再断言」的固定等待。
4. **每项报告真实输出**：实现轮提交中附带实际 `cargo test` / `npx vitest run` 输出（测试名 + pass/fail 行），红绿两段均要。禁止编造测试结果。
5. **回归门禁**（每项完成后至少跑对应的那一层，全部完成后全量）：
   - Rust：`cargo test --workspace`（73 套件基线，含 conex-db migrations/orphan_grace_contract、orchestrator crash_consistency/drive/kill_all）；

   - 引擎代码改动后跑 `reference/markdown-editor` 门禁 `npm test`（vitest run tests/unit）确认不受影响。
