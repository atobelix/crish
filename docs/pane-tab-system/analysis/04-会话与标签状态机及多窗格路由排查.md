## 1. 执行摘要与架构概览

在现代桌面端工作区布局体系中，多窗格（Multi-Pane）分屏与多会话标签（Multi-Session Tabs）是复杂度最高的交互枢纽。本排查针对桌面端在会话域（`sessionStore`）、外壳标签域（`workspaceShellStore`）、几何二叉树域（`layoutTreeStore`）以及只读门面层（`storeAccess.ts`）之间的状态流转、数据流契约与路由生命周期进行了深度代码溯源。

```
  ┌────────────────────────────────────────────────────────────────────────┐
  │                         Global Top Bar UI                              │
  │                  [GlobalSessionTabBar: Tab A | Tab B*]                 │
  └───────────────────────────────────┬────────────────────────────────────┘
                                      │ (activateTab / openNewDraftTab)
                                      ▼
  ┌────────────────────────────────────────────────────────────────────────┐
  │                       workspaceShellStore                              │
  │  openTabs: [TabSurface A, TabSurface B]                                │
  │  activeTabId: "tab-B"                                                  │
  │  rightDock: { collapsed, openPanelIds, activePanelId, widthRatio }     │
  └─────────────┬────────────────────────────────────────────┬─────────────┘
                │                                            │
   (setActiveSessionId)                           (applyDockToTree /
                │                                  bindActiveChatLeafSession)
                ▼                                            ▼
  ┌───────────────────────────┐                ┌───────────────────────────┐
  │       sessionStore        │                │      layoutTreeStore      │
  │ sessions: [Session A, B]  │                │ tree.root: Binary Tree    │
  │ activeSessionId: "sess-B" │                │ activeLeafId: "leaf-1"    │
  │ draftFolder: ""           │                │ Leaf: { panelId, tabs,    │
  │ hydrationComplete: true   │                │         activeTab,        │
  └───────────────────────────┘                │         sessionId }       │
                                               └───────────────────────────┘
```

### 核心排查结论
1. **职责划分清晰度**：系统在领域所有权上有严格划分——`workspaceShellStore` 拥有会话标签的存在与顺序（`openTabs`）、活动标签（`activeTabId`）与各标签的右侧工具坞配置（`rightDock`）；`layoutTreeStore` 拥有纯二叉树几何结构（`splitRatio`、`direction`、`children`）与面板叶子（`LayoutLeaf`）；`sessionStore` 拥有会话内容（`messages`、`title`、`agents`）。
2. **多窗格路由断路风险**：排查发现，由于历史重构移除了窗格内部的独立 TabStrip，全局仅保留窗口顶栏 `GlobalSessionTabBar`，但在 `leafBindingHelpers.ts` 中针对多 Chat 窗格保留了“多窗格下点击未绑定的 Tab 不允许抢占已有窗格（禁止偷 session）”的守卫逻辑。**导致在分屏场景下，用户在顶栏点击未展示在当前分屏中的 Tab 时，顶栏虽然高亮切换，但画布中所有窗格均不会渲染该会话，产生假死现象**。
3. **草稿（PENDING_DRAFT）态设计自洽但存在边缘竞争**：草稿不进 `openTabs`、不持久化，通过 `PENDING_DRAFT_SESSION_ID` 哨兵驱动界面空态，首条消息发送时由 `commitDraftIfNeeded` 原子化 mint 真实会话并反写 `openTabs`。但在多窗格下，`openNewDraftTab` 会将活动 Leaf 的 `sessionId` 置为 `undefined`，若此时用户在另一窗格操作，存在活动焦点与草稿所属窗格失配的风险。

## 3. Shell Store 与 Layout Tree Store 的标签数据流契约

### 3.1 字段语义差异与职责映射

在数据结构中，存在两套看似重叠的 `tabs` 字段，其在底层有截然不同的架构语义：

```
           workspaceShellStore                           layoutTreeStore
    ┌───────────────────────────────┐             ┌───────────────────────────────┐
    │ openTabs: TabSurface[]        │             │ tree.root: LayoutNode         │
    │  ├─ tabId: "tab-1"            │             │  └─ LayoutLeaf (Chat)         │
    │  ├─ kind: 'conversation'      │             │      ├─ panelId: 'chat'       │
    │  ├─ sessionId: "sess-abc" ────┼─────────────┼────► ├─ sessionId: "sess-abc" │
    │  ├─ title: "重构排查"         │             │      ├─ tabs: ['chat']        │
    │  └─ rightDock: { ... }        │             │      └─ activeTab: 'chat'     │
    │                               │             │                               │
    │                               │             │  └─ LayoutLeaf (Tool)         │
    │                               │             │      ├─ panelId: 'terminal'   │
    │                               │             │      ├─ tabs: ['term','diff'] │
    │                               │             │      ├─ activeTab: 'term'     │
    │                               │             │      └─ sessionId: "sess-abc" │
    └───────────────────────────────┘             └───────────────────────────────┘
```

1. **`workspaceShellStore.openTabs` (`TabSurface[]`)**：
   - 源码定义：[`apps/crish-desktop/src/store/workspace-shell/types.ts:31-41`](file:///c:/Software/conex/apps/crish-desktop/src/store/workspace-shell/types.ts#L31-L41)
   - **语义**：代表用户在当前窗口中打开的**对话会话实例清单**。每一个 `TabSurface` 代表一个真实的对话（`kind: 'conversation'`），其 `sessionId` 为会话唯一标识，`rightDock` 保存该会话专属的右侧工具坞配置（展开状态、打开的工具面板列表、激活面板、宽度比例）。
2. **`LayoutLeaf.tabs` 与 `LayoutLeaf.activeTab` (`string[]` / `string`)**：
   - 源码定义：[`apps/crish-desktop/src/store/layout-tree/types.ts:8-23`](file:///c:/Software/conex/apps/crish-desktop/src/store/layout-tree/types.ts#L8-L23)
   - **语义**：代表该特定**叶子面板内部容纳的视图面板（Tool Panels）列表**。
     - 对于 **Chat 叶子**（`viewRegistry.isPrimary(leaf.panelId) === true`）：`leaf.tabs` 固定为 `['chat']`，`leaf.activeTab` 为 `'chat'`。**会话身份通过 `leaf.sessionId` 单独标定，绝对不使用 `leaf.tabs` 存储 session ID**（见 `workspaceShellStore.ts:30` 注释）。
     - 对于 **Tool 叶子**（`panelId !== 'chat'`，如 `terminal`、`diff`、`preview`、`files`）：`leaf.tabs` 存储该功能区中打开的工具 Tab 列表（如 `['terminal', 'diff']`），`leaf.activeTab` 为当前选中的工具。
3. **`LayoutLeaf.sessionId` (`string | undefined`)**：
   - **Chat 叶子**：标定该对话面板当前展示哪一个会话（多 Chat 分屏下优先以此为准）。
   - **Tool 叶子**：标定该工具属于哪一个 Conversation Unit（所属主会话的 ownerSessionId），确保工具操作（如 Terminal PTY、Diff 文件、Preview）精准绑定会话上下文。

### 3.2 核心不变量：`1 sessionId ↔ 0..1 ChatLeaf` 绑定机制

系统在 Phase 2 确立了 Conversation Unit 的数学不变量：
$$\forall \text{session } s, \quad \text{count}(\{l \in \text{ChatLeaves} \mid l.\text{sessionId} = s\}) \le 1$$

源码在多个关键截面上对此不变量进行了防御性保障：
- **查询与重复检测**：[`conversationUnit.ts:49-94`](file:///c:/Software/conex/apps/crish-desktop/src/store/layout-tree/conversationUnit.ts#L49-L94) 的 `findChatLeafBySessionId` 与 `findDuplicateSessionChatLeaves`。
- **重复消除归一化**：[`conversationUnit.ts:168-202`](file:///c:/Software/conex/apps/crish-desktop/src/store/layout-tree/conversationUnit.ts#L168-L202) 的 `dedupeDuplicateSessionChatLeaves` 循环扫描全树，若发现同一 `sessionId` 绑定了多个 Chat 叶子，强制只保留先序遍历的第一个，并将其余多余叶子从树中删除。
- **Store 写入前置校验**：[`leafBindingHelpers.ts:26-32`](file:///c:/Software/conex/apps/crish-desktop/src/store/workspace-shell/leafBindingHelpers.ts#L26-L32) 的 `dedupeSessionLeavesInStore` 在任何生命周期写树后均被执行。

## 4. 多窗格分屏下的标签路由机制与状态困境

### 4.1 历史设计与现状实现的架构割裂

在多窗格分屏（如 Pane 1: `[会话A, 会话B]`, Pane 2: `[会话C, 会话D]`）场景下，代码库中存在两套演进阶段遗留的设计理念冲突：

1. **底层算法模型（`unitTabPlacement.ts`）**：
   - 源码：[`apps/crish-desktop/src/store/workspace-shell/unitTabPlacement.ts:1-204`](file:///c:/Software/conex/apps/crish-desktop/src/store/workspace-shell/unitTabPlacement.ts#L1-L204)
   - 设计假设：每个 Chat 窗格应该拥有局部的 TabStrip。`tabsForUnit` 函数根据当前 Unit 的 `leaf.sessionId` 计算该窗格应展示哪些 Tab；已绑定到该窗格的 Tab 显示在该窗格，而尚未绑定到任何窗格的 Tab（`unplaced tabs`）则由活跃窗格承载（`unitHostingUnplaced`）。
2. **UI 表现层现状（`BinaryTreeWorkspace.tsx` + `GlobalSessionTabBar.tsx`）**：
   - 源码：[`BinaryTreeWorkspace.tsx:8-10`](file:///c:/Software/conex/apps/crish-desktop/src/components/binary-tree/BinaryTreeWorkspace.tsx#L8-L10) 注释明确规定：“*leaf chrome（真树；不要复活 ChatHeader / UnitSessionTabStrip）: chat 叶：UnitChromeActions ... 会话身份在窗口顶栏 GlobalSessionTabBar + 侧栏列表，叶内不再做第三套标题行*”。
   - 现状：窗格内部完全**没有**会话 Tab 栏，仅由 [`UnitChromeActions.tsx`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-card/UnitChromeActions.tsx) 展示当前窗格会话标题。所有的会话 Tab 一并平铺在最顶部的全局 [`GlobalSessionTabBar.tsx`](file:///c:/Software/conex/apps/crish-desktop/src/components/shell/GlobalSessionTabBar.tsx) 中。

### 4.2 核心缺陷：多窗格分屏下点击顶栏非绑定 Tab 导致“视图失步/无响应”

当界面处于分屏状态（例如 Pane 1 绑定会话 A，Pane 2 绑定会话 C，而 `openTabs` 中还有会话 B 和 D）时：

```
  [User clicks "Tab B" in Global Top Bar]
                   │
                   ▼
  1. workspaceShellStore.activateTab("tab-B")
     - activeTabId = "tab-B"
     - sessionStore.activeSessionId = "sess-B"
                   │
                   ▼
  2. leafBindingHelpers.bindActiveChatLeafSession("sess-B")
     - chats = [Leaf 1 (sess-A), Leaf 2 (sess-C)]
     - bound = null (sess-B not bound)
     - chats.length = 2 (> 1)
     - unbound = [] (no unbound leaves)
     - CONDITION FAILS! -> DOES NOTHING! (else: tab 打开但无可见 unit)
                   │
                   ▼
  3. UI Renders:
     - Global Top Bar: Tab B is highlighted as ACTIVE.
     - Pane 1 (TreeLeafPanel 1): leaf.sessionId = "sess-A" -> renders Session A
     - Pane 2 (TreeLeafPanel 2): leaf.sessionId = "sess-C" -> renders Session C
     - Session B is NOT RENDERED ANYWHERE! (Appears as "Click has no effect")
```

- **问题机理**：当 `chats.length > 1` 时，如果用户点击了未挂载到任何 Leaf 的 Tab B，`bindActiveChatLeafSession` 拒绝将当前聚焦的 Leaf 重绑定为 Tab B。而 `TreeLeafPanel` 由于 `leaf.sessionId` 未被改变（仍为 `sess-A`），导致 Pane 1 依然渲染会话 A。用户直观感受是：“**点击顶栏 Tab B 没有任何反应，内容仍然停留在会话 A**”。

## 6. 关键代码缺陷与架构隐患清单

### 缺陷 1：多窗格分屏下点击顶栏未挂载 Tab 导致“视图不更新/假死” 【严重度：HIGH】
- **位置**：[`apps/crish-desktop/src/store/workspace-shell/leafBindingHelpers.ts:124-134`](file:///c:/Software/conex/apps/crish-desktop/src/store/workspace-shell/leafBindingHelpers.ts#L124-L134)
- **现象**：当分屏存在 2 个以上 Chat 窗格时，若用户在顶栏点击未挂载在当前任何窗格的会话 Tab，`bindActiveChatLeafSession` 因 `unbound.length === 0` 直接跳过重绑定。`layoutTreeStore` 上的各个叶子维持原有 `sessionId`，导致顶栏 Tab 高亮切换了，但画布中央的窗格内容没有任何变化。
- **根因**：单窗格多 Tab 时代与多窗格分屏时代的路由假设冲突。单窗格模式下支持直接重绑唯一 Leaf，但多窗格模式下未定义“未挂载 Tab 应该在当前活动窗格打开还是新开分屏”的默认路由策略。

### 缺陷 2：`unitTabPlacement.ts` 与 `BinaryTreeWorkspace` 的架构割裂 【严重度：MEDIUM】
- **位置**：[`apps/crish-desktop/src/store/workspace-shell/unitTabPlacement.ts`](file:///c:/Software/conex/apps/crish-desktop/src/store/workspace-shell/unitTabPlacement.ts) vs [`apps/crish-desktop/src/components/binary-tree/BinaryTreeWorkspace.tsx:8-10`](file:///c:/Software/conex/apps/crish-desktop/src/components/binary-tree/BinaryTreeWorkspace.tsx#L8-L10)
- **现象**：`unitTabPlacement.ts` 实现了完整的 Obsidian 风格窗格 Tab 分配算法（`tabsForUnit`、`unitHostingUnplaced`），但在 UI 渲染层被完全废弃，窗格内部只保留了 `UnitChromeActions`（纯面包屑与操作按钮）。这导致 `tabsForUnit` 成为孤儿代码，且分屏下缺乏窗格级 Tab 切换能力。

### 缺陷 3：Draft 模式在多窗格分屏下的焦点争夺风险 【严重度：MEDIUM】
- **位置**：[`apps/crish-desktop/src/store/workspace-shell/workspaceShellStore.ts:444-458`](file:///c:/Software/conex/apps/crish-desktop/src/store/workspace-shell/workspaceShellStore.ts#L444-L458)
- **现象**：`openNewDraftTab` 执行时，尝试寻找 `treeStore.activeLeafId` 并将其 `sessionId` 置为 `undefined`。但在多窗格下，如果用户的焦点刚刚离开窗格（例如点击了顶栏加号），`activeLeafId` 可能不是用户期望的窗格，导致清除了错误窗格的会话绑定。

### 缺陷 4：`workspaceKey` 跨项目切换时的过滤白屏隐患 【严重度：LOW】
- **位置**：[`apps/crish-desktop/src/components/shell/GlobalSessionTabBar.tsx:151-176`](file:///c:/Software/conex/apps/crish-desktop/src/components/shell/GlobalSessionTabBar.tsx#L151-L176)

## 7. 演进与重构建议

### 建议 1：明确多窗格下的 Tab 路由策略（二选一收敛）
