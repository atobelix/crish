## 一、 排查综述与核心结论

在现代桌面多窗格瓦片布局（Tiling Multi-Pane Layout）中，**系统级控制区**（如 Windows 窗口控制三键、macOS 左上角红绿灯交通灯、侧边栏悬浮展开按钮）与**工作区内部窗格标题栏/标签栏（Pane Header / TabStrip）**常常处于同一水平视觉带。

若二叉树工作区中的所有叶子面板（Leaves）被无差别对待，会导致严重的 UI 碰撞与视觉缺陷：
1. **左上角遮挡**：侧边栏收起时，悬浮展开按钮（Floating Toggle Button）直接遮挡左上窗格的第一枚会话/工具标签页，导致用户无法点击；
2. **右上角穿透**：右上窗格的标签页或操作按钮延伸至 Windows 系统窗控三键（最小化/最大化/关闭）下方，产生点击冲突与重叠污染；
3. **过度避让污染**：若对所有窗格全局施加固定的左/右安全边距，会导致内部（非边缘）窗格出现难看的空白缝隙，浪费宝贵的可视空间。

### 核心排查结论

1. **几何感知是唯一正确解**：
   依靠二叉树展平计算得到的归一化几何参数 `rect = { x, y, width, height }`，能够**以 100% 纯函数、无状态**的方式精准判定每个 Leaf 是否处于 `isTopRow`、`isLeftEdge`、`isRightEdge`、`isBottomRow`。
2. **必须引入浮点容差（Epsilon Tolerance）**：
   多次分屏与 Sash 拖拽调整比例（如 `0.3333333333`、`0.6666666667`）后，`rect.x + rect.width` 极可能出现 `0.9999999999999999` 或 `1.0000000000000002`，因此**严禁使用严格相等 `=== 1` 或 `=== 0`**，必须采用 `rect.y <= 0.001`、`rect.x <= 0.001` 以及 `rect.x + rect.width >= 0.99`。
3. **声明式安全通道（Safe Channel Clearance）契约**：
   - **左上窗格（`topRow && leftEdge`）**：侧栏折叠时让位 `44px`（Windows）或 `106px`（macOS 交通灯），侧栏展开时 `padding-left: 0`；
   - **右上窗格（`topRow && rightEdge`）**：Windows 平台让位 `112px`（窗口三键），macOS 平台让位 `38px`（仅避让常驻 Quick Dock 按钮）；
   - **非边缘窗格（Internal Panes）**：左右安全避让边距严格为 `0`，标签栏 100% 占满宽度。

## 二、 拓扑几何模型与多窗格边缘感知算法

### 2.1 归一化百分比坐标系与矩形定义

在 [`apps/crish-desktop/src/store/layout-tree/layoutTreeFlatten.ts:19`](file:///c:/Software/conex/apps/crish-desktop/src/store/layout-tree/layoutTreeFlatten.ts#L19) 及 [`geometry.ts:21-28`](file:///c:/Software/conex/apps/crish-desktop/src/store/layout-tree/geometry.ts#L21-L28) 中，二叉树工作区采用归一化百分比坐标系：
- 坐标原点 `(0, 0)` 为工作区画布（Canvas）的左上角；
- $x \in [0, 1)$：左侧相对偏移；
- $y \in [0, 1)$：顶部相对偏移；
- $width \in (0, 1]$：相对宽度（占画布宽度的比例）；
- $height \in (0, 1]$：相对高度（占画布高度的比例）。

每个叶子节点展平后产出的 `FlatPanel` 结构为：
```typescript
// apps/crish-desktop/src/store/layout-tree/types.ts
export interface FlatPanel {
  leafId: string;
  panelId: string;
  tabs: string[];
  activeTab: string;
  sessionId?: string;
  rect: { x: number; y: number; width: number; height: number };
}
```

### 2.2 浮点精度与 Epsilon 容差阈值分析

#### 浮点精度陷阱
当二叉树经过多层嵌套分割（例如 3 等分比例 `1/3`、`2/3`）或用户通过 `TreeResizeSash` 拖拽调整比例时：
```typescript
// 示例：三次水平分割可能产生的 rect
paneA.rect = { x: 0, y: 0, width: 0.3333333333333333, height: 1 };
paneB.rect = { x: 0.3333333333333333, y: 0, width: 0.3333333333333333, height: 1 };
paneC.rect = { x: 0.6666666666666666, y: 0, width: 0.3333333333333333, height: 1 };

// 计算 paneC 的右边缘：
paneC.rect.x + paneC.rect.width = 0.9999999999999999;
paneC.rect.x + paneC.rect.width === 1.0; // false! 严格相等判定失效！
```

若直接使用 `rect.x + rect.width === 1`，paneC 将被误判为非右边缘窗格，导致右上窗格避让规则完全失效，标签页直接撞上 Windows 窗控按钮！

#### 阈值选取
设容差阈值 $\epsilon = 0.005$（即 $0.5\%$ 的画布宽度/高度，在 $1920\text{px}$ 屏幕上对应约 $9.6\text{px}$，远小于任何最小窗格宽度 $200\text{px}$）：
- 只要 `rect.x + rect.width >= 1 - \epsilon`（即 `>= 0.995`，工程上取 `>= 0.99` 亦极为稳健），即可判定窗格紧贴右边缘；
- 只要 `rect.x <= \epsilon`（即 `<= 0.001`），即可判定窗格紧贴左边缘；
- 只要 `rect.y <= \epsilon`（即 `<= 0.001`），即可判定窗格紧贴顶边缘。

### 2.3 核心边缘判定数学模型

边缘感知算法的纯数学形式化定义如下：

$$\text{isTopRow}(rect) \iff rect.y \le 10^{-3} \land rect.height > 10^{-3}$$

$$\text{isLeftEdge}(rect) \iff rect.x \le 10^{-3} \land rect.width > 10^{-3}$$

$$\text{isRightEdge}(rect) \iff (rect.x + rect.width) \ge 0.99 \land rect.width > 10^{-3}$$

$$\text{isBottomRow}(rect) \iff (rect.y + rect.height) \ge 0.99 \land rect.height > 10^{-3}$$

```typescript
/**
 * 二叉树窗格边缘感知算法（纯函数）
 */
export interface PaneEdgeFlags {
  /** 位于顶行（接触工作区顶部） */
  isTopRow: boolean;
  /** 位于最左列（接触工作区左边缘） */
  isLeftEdge: boolean;
  /** 位于最右列（接触工作区右边缘） */
  isRightEdge: boolean;
  /** 位于底行（接触工作区底部） */
  isBottomRow: boolean;
}

export function computePaneEdgeFlags(rect: {
  x: number;
  y: number;
  width: number;
  height: number;
}): PaneEdgeFlags {
  // 排除折叠或零尺寸面板
  if (rect.width <= 0.001 || rect.height <= 0.001) {
    return {
      isTopRow: false,
      isLeftEdge: false,
      isRightEdge: false,
      isBottomRow: false,
    };
  }

  const EPSILON = 0.001;
  const RIGHT_BOTTOM_THRESHOLD = 0.99;

  return {
    isTopRow: rect.y <= EPSILON,
    isLeftEdge: rect.x <= EPSILON,
    isRightEdge: rect.x + rect.width >= RIGHT_BOTTOM_THRESHOLD,
    isBottomRow: rect.y + rect.height >= RIGHT_BOTTOM_THRESHOLD,
  };
}
```

### 2.4 折叠域与零尺寸边界剔除

在 [`apps/crish-desktop/src/store/layout-tree/layoutTreeFlatten.ts:95-97`](file:///c:/Software/conex/apps/crish-desktop/src/store/layout-tree/layoutTreeFlatten.ts#L95-L97) 中，当传入 `collapsedDomain: 'tool'` 时：
```typescript
rect: leafMatchesCollapsedDomain(node, collapsedDomain)
  ? { x: rect.x, y: rect.y, width: 0, height: 0 }
  : rect,
```
此时被折叠的工具叶尺寸为 `width: 0, height: 0`。若不剔除零尺寸节点，其 `rect.y === 0` 且 `rect.x === 0` 会被误判为 `isTopRow=true, isLeftEdge=true`，从而在其不可见元素上激活动画或样式计算。必须在前置判断中加入 `rect.width > 0.001 && rect.height > 0.001` 的校验。

### 2.5 算法落点评估：展平期注入 vs 渲染期纯函数派生

| 评估维度 | 方案 A：展平期直接注入 `FlatPanel` | 方案 B：渲染期纯函数派生（`TreeLeafPanel`） |
| :--- | :--- | :--- |
| **计算位置** | `layoutTreeFlatten.ts` | `TreeLeafPanel.tsx` 或 `BinaryTreeWorkspace.tsx` |
| **类型变更** | 需要修改 `FlatPanel` 结构（增加 4 个布尔值） | 零类型污染，`FlatPanel` 保持精简 |
| **React Memo 影响** | 展平产物变大，需修改 `rectPropsEqual` 比较逻辑 | 纯粹根据 `rect` 计算，配合 `useMemo` 或纯函数零开销 |
| **Sash Live Resize** | Sash 拖拽修改 DOM 时不会触发 store re-render | `useLayoutEffect` 中可直接依据 flags 设置 class/attribute |
| **架构评价** | 略显冗余（视图派生属性侵入持久/中间数据结构） | **推荐方案**（关注点分离，符合纯函数衍生原则） |

### 3.1 左上窗格避让（Top-Left Clearance）

#### 触发条件
`isTopRow === true && isLeftEdge === true`

#### 几何避让规范
1. **当侧边栏展开（`sidebarCollapsed === false`）**：
   - 侧边栏宽度通常为 `220px ~ 280px`（`var(--sidebar-width)`），侧边栏顶部自身包含独立的固定切换按钮（[`apps/crish-desktop/src/components/top-bar/AppTopBar.tsx:100-123`](file:///c:/Software/conex/apps/crish-desktop/src/components/top-bar/AppTopBar.tsx#L100-L123)）；
   - 左上角窗格左侧紧贴侧边栏右侧发丝边框，不需要任何额外避让；
   - `padding-left: var(--pane-inner-pad, 4px)`。
2. **当侧边栏折叠收起（`sidebarCollapsed === true`）**：
   - 侧边栏宽度变为 `0`，左上角出现常驻的悬浮展开按钮（Floating Toggle Button，尺寸 `28px × 28px`，左间距 `8px`，右间距 `8px`，合计占位 `44px`）；
   - 左上窗格的 `PaneHeader` 必须向右内凹让出 `44px`；
   - `padding-left: var(--safe-channel-left, 44px)`；
   - 动画效果：使用 `transition: padding-left var(--transition-fast, 150ms ease-out)`，与侧栏展开收起动画完全同步。

### 3.2 右上窗格避让（Top-Right Clearance）

#### 触发条件
`isTopRow === true && isRightEdge === true`

#### 几何避让规范
1. **Windows / Linux 平台（含真窗控三键）**：
   - 窗口控制区宽度分解：
     - 最小化按钮：`32px`
     - 最大化/向下还原按钮：`32px`
     - 关闭按钮：`32px`
     - 三键主体宽度：`96px`
     - 快捷帮助按钮 / 间距 / 右内边距：`16px`
     - 合计避让宽度：**`112px`**（参考 [`reference/chat-composer-component/css/composer.css:1830-1832`](file:///c:/Software/conex/reference/chat-composer-component/css/composer.css#L1830-L1832) 的 `112px`）；
   - 右上窗格的 `PaneHeader` 必须向左内凹让出 `112px`；
   - `padding-right: var(--safe-channel-right-win, 112px)`；
   - 标签列表及新建按钮（`+`）在滚动和渲染时，其最右边界被限制在 `112px` 避让区左侧，绝不延伸至系统三键下方。
2. **macOS 平台（无右上窗口三键）**：
   - macOS 窗口三键（红黄绿交通灯）位于窗口左上角，右上角无系统控件；
   - 右上角仅存在工作区常驻的单一物理右坞切换按钮（`#topQuickDockBtn`，`28px` + 边距 = `38px`）；
   - `padding-right: var(--safe-channel-right-mac, 38px)`。

### 3.3 内部与非边缘窗格（Internal / Non-Edge Panes）

#### 触发条件
`!(isTopRow && isLeftEdge) && !(isTopRow && isRightEdge)`
（包括：所有第二行及以下窗格、中间列窗格、右上窗格的左侧、左上窗格的右侧）

#### 几何避让规范
- `padding-left: var(--pane-inner-pad, 4px)`（常规卡片内边距）；
- `padding-right: var(--pane-inner-pad, 4px)`；
- **核心收益**：非边缘窗格拥有 100% 的有效宽度，标签可横向铺满，没有任何突兀的空白或不对称留白。

## 四、 参考实现与当前代码全景对照

### 4.1 原型参考实现解析（Reference Baseline）

在 `reference/chat-composer-component` 中，边缘感知与避让是通过以下方式配合实现的：

1. **递归标志传递（[`reference/chat-composer-component/js/popovers.js:2238-2244`](file:///c:/Software/conex/reference/chat-composer-component/js/popovers.js#L2238-L2244)）**：
```javascript
// reference/chat-composer-component/js/popovers.js:2238-2244
if (node.direction === 'horizontal') {
  lf = { topRow: flags.topRow, leftEdge: flags.leftEdge, rightEdge: false };
  rf = { topRow: flags.topRow, leftEdge: false, rightEdge: flags.rightEdge };
} else {
  lf = { topRow: flags.topRow, leftEdge: flags.leftEdge, rightEdge: flags.rightEdge };
  rf = { topRow: false, leftEdge: flags.leftEdge, rightEdge: flags.rightEdge };
```

### 6.1 单窗格 → 垂直二分分屏（1 → 2）

```
  flags: { isTopRow: true, isLeftEdge: true, isRightEdge: false, isBottomRow: true }
```

### 6.3 窗格关闭与合并回退（3 → 2 → 1）

当用户关闭右上窗格 Leaf B1 时：
- Leaf B2 上升占据右侧全高：`rect = { x: 0.5, y: 0, width: 0.5, height: 1 }`；
- Leaf B2 的 flags 瞬间自适应为 `{ isTopRow: true, isLeftEdge: false, isRightEdge: true, isBottomRow: true }`；
- CSS 规则毫秒级无缝为 Leaf B2 附加 `padding-right: 112px`，彻底杜绝状态残留或漏设避让。
