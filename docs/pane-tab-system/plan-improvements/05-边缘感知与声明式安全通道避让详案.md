## 一、 方案概述与核心目标

### 1.1 现状缺陷与痛点回顾

在桌面多窗格平铺瓦片布局（Tiling Multi-Pane Layout）中，系统级控件（如 Windows 窗控最小化/最大化/关闭按钮、macOS 左上角红绿灯交通灯、侧边栏展开/收起浮动切换按钮）与工作区二叉树各叶子窗格（Leaf Panes）的顶部标题栏/标签栏处于同一水平操作带。

根据第一步排查报告 [`05-系统按键避让与边缘检测几何排查.md`](file:///c:/Software/conex/docs/pane-tab-system/analysis/05-系统按键避让与边缘检测几何排查.md)，现有实现存在三大致命缺陷：

1. **DOM 语义与边缘标记缺失**：
   - [`apps/crish-desktop/src/components/binary-tree/TreeLeafPanel.tsx:192-206`](file:///c:/Software/conex/apps/crish-desktop/src/components/binary-tree/TreeLeafPanel.tsx#L192-L206) 渲染的叶子节点容器上仅挂载了 `data-leaf-id`、`data-panel-id`、`data-tab-count`、`data-active`，**完全缺失边缘感知标志（`data-top-row`、`data-left-edge`、`data-right-edge`）**。
   - CSS 无法通过属性选择器对处于窗口外沿的面板进行精确微分。

2. **组件内部局部硬编码边距冲突（Hardcoded Margins）**：
   - [`apps/crish-desktop/src/components/chat-card/UnitChromeActions.module.css:156-159`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-card/UnitChromeActions.module.css#L156-L159) 与 [`apps/crish-desktop/src/components/binary-tree/LeafToolTabStrip.module.css:298-300`](file:///c:/Software/conex/apps/crish-desktop/src/components/binary-tree/LeafToolTabStrip.module.css#L298-L300) 中依赖 JS 状态（如 `isDockActivelyRendered`、`withDockMargin`、`dockSlotReserved`）为面板强行添加 `36px` 的右侧内/外边距。
   - **严重副作用**：当用户创建多个 Chat 面板并将其中一个放置在**左下角**时，该左下角面板在右坞折叠时仍然会被错误附加 `36px` 右边距，导致操作按钮被无故向左推挤；而右上角面板若未触发特定 JS 状态，其标签又会直接穿透并被 Windows 窗口控制按键遮挡。

3. **浮点累积误差导致的边缘失效风险**：
   - 二叉树经过多次 Sash 拖拽调整比例（如 `1/3 = 0.3333333333333333`、`2/3 = 0.6666666666666666`）后，`rect.x + rect.width` 会产生类似 `0.9999999999999999` 的浮点残差。
   - 若直接采用严格相等 `=== 1` 或 `=== 0` 判断，分屏调整后边缘标志会立刻丢失，导致避让瞬间失效崩塌。

### 1.2 方案核心原则与架构预期

本方案致力于通过**数学几何微内核 + 声明式 CSS 级联规则**，彻底将避让逻辑从 React 组件业务逻辑中剥离：

1. **纯函数几何感知（Pure Functional Geometry）**：
   - 建立专用几何算法微内核 [`paneEdgeGeometry.ts`](file:///c:/Software/conex/apps/crish-desktop/src/components/binary-tree/paneEdgeGeometry.ts)，以归一化 `rect` 为唯一输入，无副作用地输出窗格拓扑边缘标志。
   - 引入 $\epsilon = 0.001$ 容差防线，无视任何浮点计算残差。
2. **声明式安全通道（Declarative Safe Channel Clearance）**：
   - 在 DOM 根节点注入标准数据属性（`data-top-row`、`data-left-edge`、`data-right-edge`）。
   - 全部避让边距由 CSS 变量与属性选择器驱动，**Zero-JS DOM 修改**，确保 React 重新渲染次数归零。
3. **空间利用率最大化（Zero Margin Pollution for Non-Edge Panes）**：
   - 非边缘窗格（内部窗格、下方窗格）安全避让边距强制为 `0`，标签条与标题操作区 100% 占满，彻底消除空白冗余。
4. **全屏与多平台无缝自适应（Cross-Platform & Fullscreen Adaptation）**：
   - 针对 Windows（`112px`）、macOS（`106px` / `38px`）、全屏态（`44px` / `38px`）建立统一变量覆盖矩阵。
5. **Live Resize 动画绝缘（Resize Transition Insulation）**：
   - 在用户拖拽分屏 Sash 期间，通过全局 `.tree-resizing` 样式切断 padding 缓动过渡，避免拖拽顿挫。

## 二、 数学模型与边缘感知微内核设计 (`paneEdgeGeometry.ts`)

### 2.1 归一化百分比坐标体系

二叉树工作区在展平计算（[`apps/crish-desktop/src/store/layout-tree/layoutTreeFlatten.ts:62-98`](file:///c:/Software/conex/apps/crish-desktop/src/store/layout-tree/layoutTreeFlatten.ts#L62-L98)）中，将整个工作区画布视为标准二维直角坐标系 $[0, 1] \times [0, 1]$：

- **原点 $(0, 0)$**：二叉树画布左上角；
- **$x \in [0, 1)$**：面板左边界相对画布总宽的归一化横坐标；
- **$y \in [0, 1)$**：面板顶边界相对画布总高的归一化纵坐标；
- **$width \in (0, 1]$**：面板宽度相对画布总宽的归一化占比；
- **$height \in (0, 1]$**：面板高度相对画布总高的归一化占比。

每个面板的右下角坐标由 $(x + width, y + height)$ 隐式确定。

### 2.2 浮点精度与 $\epsilon$ 容差防线数学推导

在双精度浮点数（IEEE 754 64-bit Float）运算下，分割比例累加极易产生微小截断误差：

$$\frac{1}{3} + \frac{1}{3} + \frac{1}{3} \approx 0.3333333333333333 + 0.3333333333333333 + 0.3333333333333333 = 0.9999999999999999 \neq 1.0$$

若分屏比例经过 Sash 拖拽（例如通过像素比例逆运算 `currentPx / totalPx`）：
$$x = 0.6666666666666666,\quad width = 0.3333333333333333 \implies x + width = 0.9999999999999999$$

为了防止误判，设定容差阈值 $\epsilon = 0.001$（对应画布宽高的 $0.1\%$，在 $1920\text{px} \times 1080\text{px}$ 屏幕上对应 $1.92\text{px} \times 1.08\text{px}$，远小于最小窗格最小约束尺寸 $200\text{px}$）：

- **顶行判定 $\text{isTopRow}$**：
  $$\text{isTopRow}(rect) \iff rect.y \le \epsilon \land rect.height > \epsilon$$
- **左边缘判定 $\text{isLeftEdge}$**：
  $$\text{isLeftEdge}(rect) \iff rect.x \le \epsilon \land rect.width > \epsilon$$
- **右边缘判定 $\text{isRightEdge}$**：
  $$\text{isRightEdge}(rect) \iff (rect.x + rect.width) \ge (1 - \epsilon_{right}) \land rect.width > \epsilon$$
  *（工程实践中，$\epsilon_{right}$ 取 $0.01$，即只要 $x + width \ge 0.99$ 即可 100% 可靠认定贴合右边缘）*
- **底行判定 $\text{isBottomRow}$**：
  $$\text{isBottomRow}(rect) \iff (rect.y + rect.height) \ge 0.99 \land rect.height > \epsilon$$

### 2.3 零尺寸与折叠域剔除机制

当布局树启用折叠域（例如右侧工具栏折叠 `collapsedDomain: 'tool'`，见 [`layoutTreeFlatten.ts:95-97`](file:///c:/Software/conex/apps/crish-desktop/src/store/layout-tree/layoutTreeFlatten.ts#L95-L97)）时，被折叠的面板被赋予虚拟几何：
$$rect = \{ x: rect.x, y: rect.y, width: 0, height: 0 \}$$

若不进行前置零尺寸校验：
- 该面板的 $x \le 0.001$ 且 $y \le 0.001$ 成立，会被错误判定为 `isTopRow=true, isLeftEdge=true`；
- 从而导致隐藏的 DOM 节点计算额外的 CSS 选择器并触发无谓的样式重排。

因此，算法微内核必须包含硬性保护条件：
$$\text{if }(rect.width \le 10^{-3} \lor rect.height \le 10^{-3}) \implies \text{all flags } = \text{false}$$

### 2.4 完整 TypeScript 源码实现详案

规划文件路径：[`apps/crish-desktop/src/components/binary-tree/paneEdgeGeometry.ts`](file:///c:/Software/conex/apps/crish-desktop/src/components/binary-tree/paneEdgeGeometry.ts)

```typescript
/**
 * 二叉树窗格边缘感知算法微内核 (Pane Edge Geometry Micro-kernel)
 *
 * 核心职责：
 * 1. 基于二叉树展平得到的归一化几何 rect ({ x, y, width, height })，
 *    纯函数计算窗格在工作区画布中的拓扑边缘状态；
 * 2. 内置 Epsilon 容差，防范分屏拖拽引起的 IEEE-754 浮点累积误差；
 * 3. 严格剔除零尺寸与折叠域面板，防止隐藏容器污染选择器。
 */

export interface PaneRect {
  /** 归一化 X 偏移 (0 <= x < 1) */
  x: number;
  /** 归一化 Y 偏移 (0 <= y < 1) */
  y: number;
  /** 归一化宽度 (0 < width <= 1) */
  width: number;
  /** 归一化高度 (0 < height <= 1) */
  height: number;
}

export interface PaneEdgeFlags {
  /** 是否位于顶行（接触工作区顶部边界） */
  isTopRow: boolean;
  /** 是否位于最左列（接触工作区左侧边界） */
  isLeftEdge: boolean;
  /** 是否位于最右列（接触工作区右侧边界） */
  isRightEdge: boolean;
  /** 是否位于底行（接触工作区底部边界） */
  isBottomRow: boolean;
}

/** 浮点容差上限 (0.1% 画布尺寸) */
export const PANE_EDGE_EPSILON = 0.001;

/** 右侧/底侧贴合阈值 (99.0% 画布尺寸，绝对规避 0.9999999999999999 截断) */
export const PANE_EDGE_FAR_THRESHOLD = 0.99;

/** 零尺寸或完全折叠面板的默认边缘标志 */
export const INACTIVE_PANE_EDGE_FLAGS: Readonly<PaneEdgeFlags> = Object.freeze({
  isTopRow: false,
  isLeftEdge: false,
  isRightEdge: false,
  isBottomRow: false,
});

/**
 * 纯函数：计算面板几何边缘标志
 *
 * @param rect 归一化百分比矩形
 * @returns 边缘标志对象
 */
export function computePaneEdgeFlags(rect: PaneRect | null | undefined): PaneEdgeFlags {
  if (!rect) {
    return INACTIVE_PANE_EDGE_FLAGS;
  }

  const { x, y, width, height } = rect;

  // 1. 防御性剔除：宽度或高度极小/为零的折叠面板
  if (width <= PANE_EDGE_EPSILON || height <= PANE_EDGE_EPSILON) {
    return INACTIVE_PANE_EDGE_FLAGS;
  }

  // 2. 顶边缘判定：y 坐标无限逼近 0
  const isTopRow = y <= PANE_EDGE_EPSILON;

  // 3. 左边缘判定：x 坐标无限逼近 0
  const isLeftEdge = x <= PANE_EDGE_EPSILON;

  // 4. 右边缘判定：x + width 覆盖达到或超过 0.99
  const isRightEdge = x + width >= PANE_EDGE_FAR_THRESHOLD;

  // 5. 底边缘判定：y + height 覆盖达到或超过 0.99
  const isBottomRow = y + height >= PANE_EDGE_FAR_THRESHOLD;

  return {
    isTopRow,
    isLeftEdge,
    isRightEdge,
    isBottomRow,
  };
}
```

### 2.5 算法落点评估与 React Memo 绝缘策略

```typescript
// apps/crish-desktop/src/components/binary-tree/paneEdgeGeometry.ts
/**
 * 二叉树窗格边缘感知算法微内核
 */

export interface PaneRect {
  x: number;
  y: number;
  width: number;
  height: number;
}

export interface PaneEdgeFlags {
  isTopRow: boolean;
  isLeftEdge: boolean;
  isRightEdge: boolean;
  isBottomRow: boolean;
}

export const PANE_EDGE_EPSILON = 0.001;
export const PANE_EDGE_FAR_THRESHOLD = 0.99;

export const INACTIVE_PANE_EDGE_FLAGS: Readonly<PaneEdgeFlags> = Object.freeze({
  isTopRow: false,
  isLeftEdge: false,
  isRightEdge: false,
  isBottomRow: false,
});

export function computePaneEdgeFlags(rect: PaneRect | null | undefined): PaneEdgeFlags {
  if (!rect) return INACTIVE_PANE_EDGE_FLAGS;
  const { x, y, width, height } = rect;

  if (width <= PANE_EDGE_EPSILON || height <= PANE_EDGE_EPSILON) {
    return INACTIVE_PANE_EDGE_FLAGS;
  }

  return {
    isTopRow: y <= PANE_EDGE_EPSILON,
    isLeftEdge: x <= PANE_EDGE_EPSILON,
    isRightEdge: x + width >= PANE_EDGE_FAR_THRESHOLD,
    isBottomRow: y + height >= PANE_EDGE_FAR_THRESHOLD,
  };
}
```
