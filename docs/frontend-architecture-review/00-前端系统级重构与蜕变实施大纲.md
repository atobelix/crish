## 一、 执行摘要与系统性蜕变愿景

### 1.1 现状诊断与核心矛盾

通过对 `apps/crish-desktop/src/` 的 27 份全景审查报告进行系统性交叉比对，当前 Conex（Crish）前端呈现出**「优秀的底层算法内核与粗糙失控的上层交互外壳并存」**的剧烈撕裂状态：

- **底层资产卓越**：二叉树布局纯函数操作算子（`operations.ts`）、无 Immer 的 Token 级流式热缓冲（`streamingStore.ts`）、DOM Ref 增量直写引擎（`StreamingTextBlock.tsx`）、交错时间线纯函数缓存（`timelineNormalizer.ts`）均达到工业级性能标准。
- **上层架构腐蚀**：
  1. **巨型上帝对象与伪门面**：`layoutStore.ts` 强行揉合 5 重异构状态域，`sessionStore`/`workspaceStore` 仅是同一单例的虚假别名，修改一个设置 Tab 导致全屏 100% 组件无差别重刷；
  2. **8,000+ 行死样式地层堆叠**：`settings-models.css`（2550行）沉积了 5 代重构地层，TSX 广泛保留 `styles.xxx` 与全局类名双重绑定；
  3. **交互与几何失调**：浮层事件争抢导致四击才能关闭菜单、供应商级联选择鼠标移动引发闪退瘫痪、设置页全屏右下暴露 8px 灰褐色断层、36 个改动文件挤压在 280px 限高盒中；
  4. **硬编码视图分发**：`TreeLeafPanel.tsx` 依赖静态 `switch(panelId)`，致使已开发完毕的 `BrowserPanel` 与 `FlowDagView` 被边缘孤立。

### 1.2 重构铁律与指导原则

1. **反退避铁律**：效果锁死，严禁以“实现困难”为由降级为简陋方案。
2. **反过度设计红线**：杜绝盲目引入冗余框架，坚持原生 CSS 变量、Flexbox、Grid 与纯函数架构。
3. **零补丁与架构穿透**：严禁坐标测距魔术数字补偿、严禁 `!important` 军备竞赛，穿透表象找到数据流与盒模型断层。
4. **验证责任**：改动前后严格履行类型检查与渲染性能比对，保证 0 回归。

### 1.3 核心质变指标与量化预期

| 维度                     | 当前现状 (Before)                     | 重构目标 (After)                              | 收益量化                       |
| :----------------------- | :------------------------------------ | :-------------------------------------------- | :----------------------------- |
| **死代码体积**           | 8,064 行死 CSS + 1,232 行孤儿组件     | 物理彻底删除，0 残留                          | **代码库瞬间减负 ~9,300 行**   |
| **设置项操作 Re-render** | 全屏 100% 组件无差别重刷 (~80ms 延迟) | 纯 CSS 属性直写 + 局部 Dialog 重绘 (< 2ms)    | **消除 99% 无效 VDOM 协调**    |
| **窗口缩放 FPS**         | 掉帧、回流绞肉机 (15~25 fps)          | 彻底剔除 rAF 轮询，GPU 图层隔离 (稳定 60 fps) | **CPU 占用降低 70%，消除卡顿** |
| **Diff 工具栏高度**      | 76px 双行松散布局                     | 34px 单行紧凑高集成度工具栏                   | **垂直可视面积释放 55%**       |
| **顶栏 Chrome 高度**     | 74px 双层生硬堆叠 (44px + 30px)       | 36px 沉浸式一体化单行顶栏                     | **释放 38px 垂直空间**         |
| **浮层交互可靠性**       | 四击关闭、Hover 闪退瘫痪              | 单次点击必开关、Radix Sub 安全三角轨迹        | **100% 交互成功率**            |

### 2.1 Top Layer: Feature Views (可插拔业务面板域)

所有业务面板自包含于 `src/features/<domain>/` 目录下（含组件、Hooks、私有子组件与类型），**严禁跨 Feature 直接访问私有状态**：

- `features/chat/`: 对话主卡片、消息流排版、Composer 富文本输入框；
- `features/diff/`: 差异比对、代码补丁审查、字符级 Intraline Diff；
- `features/files/`: 文件目录树、单文件代码阅读器（`VirtualPlainCodeViewer` 下沉共享）；
- `features/overview/`: 工作区项目状态总览、Git 改动折叠树；
- `features/settings/`: 收敛 5 大设置子目录（Profile, Models, Extensions, Security, etc.）；
- `features/runtime/`: 运行时监控、终端、LiveTasks、进程急停。

### 2.2 Middle Layer: ViewRegistry 动态注册表 & Shell 布局容器

#### 2.2.1 声明式视图注册中心 (ViewRegistry)

彻底消除 `TreeLeafPanel.tsx:265-295` 的硬编码 `switch(panelId)`，赋予外部面板动态注册能力：

```typescript
// src/services/view-registry/ViewTypes.ts
export interface ViewRenderContext {
  panelId: string;
  leafId: string;
  sessionId?: string;
  isActive: boolean;
  onShowToast: (msg: string) => void;
  openView: (panelId: string) => void;
}

export interface ViewDefinition {
  readonly id: string;
  readonly title: string | ((ctx: ViewRenderContext) => string);
  readonly icon: React.ComponentType<{ size?: number; className?: string }>;
  readonly category: 'primary' | 'tool' | 'auxiliary';
  readonly singleton?: boolean;
  readonly component: React.ComponentType<ViewRenderContext>;
  readonly headerActions?: React.ComponentType<ViewRenderContext>;
}
```

```typescript
// src/services/view-registry/ViewRegistry.ts
class ViewRegistryService {
  private views = new Map<string, ViewDefinition>();
  private listeners = new Set<() => void>();

  public registerView(view: ViewDefinition): () => void {
    this.views.set(view.id, view);
    this.listeners.forEach((l) => l());
    return () => {
      this.views.delete(view.id);
      this.listeners.forEach((l) => l());
    };
  }

  public getView(id: string): ViewDefinition | undefined {
    if (id.startsWith('file-viewer:')) return this.views.get('file-viewer');
    return this.views.get(id);
  }

  public getAllViews(): ViewDefinition[] {
    return Array.from(this.views.values());
  }

  public subscribe(listener: () => void): () => void {
    this.listeners.add(listener);
    return () => this.listeners.delete(listener);
  }
}
export const viewRegistry = new ViewRegistryService();
```

#### 2.2.2 声明式插槽引擎 (SlotRegistry & `<Slot />`)

#### 2.2.3 纯几何二叉树工作区容器 (GenericBinaryTreeWorkspace)

   ```typescript
   // src/features/overview/lib/gitTreeBuilder.ts
   export interface GitTreeNode {
     id: string;
     name: string;
     path: string;
     isFolder: boolean;
     file?: GitStatusFile;
     children?: GitTreeNode[];
   }
   export function buildGitTree(files: GitStatusFile[]): GitTreeNode[] {
     const root: GitTreeNode = {
       id: '__root__',
       name: '',
       path: '',
       isFolder: true,
       children: [],
     };
     for (const file of files) {
       const parts = file.path.replace(/\\/g, '/').split('/');
       let current = root;
       let currPath = '';
       for (let i = 0; i < parts.length; i++) {
         const part = parts[i]!;
         currPath = currPath ? `${currPath}/${part}` : part;
         const isLast = i === parts.length - 1;
         current.children = current.children || [];
         if (isLast) {
           current.children.push({
             id: currPath,
             name: part,
             path: currPath,
             isFolder: false,
             file,
           });
         } else {
           let folderNode = current.children.find(
             (c) => c.isFolder && c.name === part
           );
           if (!folderNode) {
             folderNode = {
               id: currPath,
               name: part,
               path: currPath,
               isFolder: true,
               children: [],
             };
             current.children.push(folderNode);
           }
           current = folderNode;
         }
       }
     }
     return root.children || [];
   }
   ```

### 4.7 难题七：根治新会话空态状态污染 (18 文件变更悬浮胶囊)

#### 1. 现场病灶根因

- `useChatCardState.ts:165` 无条件订阅了全局 `terminalStore.diffFiles`（存储的是工作区 18 个未提交 Git 改动）；
- `ChatStatusRibbons.tsx:292` 的 `dynamicChipBar` 仅判断 `diffCount > 0 && onOpenDiff`，**未判断当前会话是否为空态或草稿态**；
- 导致点击「新建对话」进入空白欢迎页时，输入框上方突兀横跳出 `[ 🌿 18 个文件变更 ]` 悬浮胶囊。

#### 2. 重构落地解法

1. **会话 Diff 纯函数派生**：
   废除全局 `terminalStore.diffFiles` 订阅，改为仅由当前会话的 `messages` 纯函数派生：
   ```typescript
   // src/features/chat/lib/chatCardDiffSelectors.ts
   export function selectSessionDiffFiles(
     messages: SessionMessage[] | undefined
   ): FileDiff[] {
     if (!messages || messages.length === 0) return [];
     const map = new Map<string, FileDiff>();
     for (const m of messages) {
       if (m.sender !== 'assistant') continue;
       const diffs = collectMessageDiffs(m);
       for (const d of diffs) map.set(d.filePath, d);
     }
     return filterPublishableDiffs([...map.values()]);
   }
   ```
2. **空态绝对纯净门闩 (Clean Slate Invariant)**：
   在 `ChatStatusRibbons.tsx` 中增加严格门闩：
   `const shouldRenderDynamicBar = !onEmptySurface && (activeBgTasks.length > 0 || hasActivePlan || (diffCount > 0 && onOpenDiff));`  
   空态与草稿态下强制屏蔽任何动态胶囊与抽屉，恢复 100% 禅意纯净欢迎面。

## 五、 核心交互与视觉规范收敛 (Pixel-Perfect Polish)

### 5.1 6px / 7px / 9px 同心圆角阶梯与主面板 14px 规范

依据同心圆角公式 $R_{inner} = \max(0, R_{outer} - Padding)$，在全仓严格固化几何阶梯：

- **主面板外壳 / 页面级大卡片**：`border-radius: 14px` (`var(--radius-2xl)`);
- **浮层 / 弹窗外框 / 卡片外框**：`border-radius: 9px` (`var(--radius-lg)`);
- **常规按钮 / 输入框 / 分段切换器 / 下拉选框 / 搜索输入框**：`border-radius: 7px` (`var(--radius-md)`);

- **坚决杜绝**：在常规交互按钮上随意使用 `border-radius: var(--radius-full)` (9999px) 造成巨大药丸突起。

### 5.3 统一 IDE 平嵌 TabStrip (彻底废除 999px 跑道圆药丸)
