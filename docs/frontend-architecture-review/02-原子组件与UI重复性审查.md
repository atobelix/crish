## 一、执行摘要与全仓清查全景

在对 `apps/crish-desktop/src/` 下全量前端源码进行清查后发现：虽然项目在 `src/components/ui/` 目录下建立了包含 `Button`、`Input`、`Dialog`、`ConfirmDialog`、`Select`、`Switch`、`TabStrip`、`Tooltip`、`Menu` 在内的初版原子组件库，但在全仓 170+ 个业务组件中，**原子组件普及率严重两极分化，基础 UI 抽象严重滞后于业务膨胀速度，导致了广泛的 DRY（Don't Repeat Yourself）原则违反与自造轮子现象**。

### 1.1 全仓基础控件散落度统计

| 控件类别                               | `components/ui/` 标准组件引用数          | 业务模块中原生 HTML 标签或私有轮子散落文件数                      | 碎片化率 |
| :------------------------------------- | :--------------------------------------- | :---------------------------------------------------------------- | :------- |
| **按钮 (Button)**                      | 48 个文件引入 `ui/Button`                | **94+ 个文件** 散落原生 `<button>` 或私有类                       | ~66.2%   |
| **输入框 (Input)**                     | 仅 **4 个文件** 引入 `ui/Input`          | **44+ 个文件** 散落原生 `<input>` 或私有输入框                    | ~91.7%   |
| **下拉选择 (Select/Menu)**             | 22 个文件引入 `ui/Select` 或 `ui/Menu`   | **12+ 个文件** 自行使用 Popover/Portal/手写 DOM 封装下拉          | ~35.3%   |
| **对话框/模态 (Dialog/Modal)**         | 9 个文件引入 `ui/Dialog`/`ConfirmDialog` | **5 个文件** 手写独立 `createPortal` 遮罩与弹窗                   | ~35.7%   |
| **分段控制器 (Segment/ToggleGroup)**   | **0（原子层缺失）**                      | **7 个模块** 各自手写不同 class 的 Segmented 按钮                 | **100%** |
| **胶囊/徽标 (Chip/Badge)**             | **0（原子层缺失）**                      | **14 个模块** 各自手写 `.preset-chip` / `.tag` / `.badge`         | **100%** |
| **滑块/颜色拾取 (Slider/ColorPicker)** | **0（原子层缺失）**                      | **Settings 模块** 直接内联行内样式裸 `<input type="range/color">` | **100%** |

### 1.2 核心矛盾点总结

1. **原子输入框 `ui/Input` 普及率不足 10%**：全仓 44 个输入场景中，仅 `BrowserImportSection`、`SettingsDevicesTab` 与 Wizard 等极少数文件使用了 `ui/Input`，其余 40 处全部散落原生 `<input>`，配合 `.settings-field-input`、`.mrdFieldInput`、`.searchInput`、`.urlInput` 等五花八门的 CSS 类名。
2. **手写 Portal 与模态弹层绕过 `ui/Dialog`**：如 `PriceConfigModal.tsx` 手写 `createPortal` 遮罩与点击外层关闭，缺少 `FocusTrap`、焦点恢复、`aria-modal` 与 Escape 安全守卫。
3. **分段控制器（Segmented Control）重复造轮子达 7 处**：`DiffHeaderControls`（`.sourceSeg`）、`FileActions`（`.filesSeg`）、`SettingsSchemaRenderer`（`.ui-segment`）、`WorkflowForm`（`.sched-preset-chips`）、`SettingsSecurityTab`（`.presetGroup`）、`SettingsRulesTab`（`.presetGroup`）等均在手写同构样式与逻辑。
4. **斜杠菜单与下拉浮层双轨并立**：`chat-composer/TiptapSlashMenu.tsx` 与 `note-paper/SlashMenuOverlay.tsx` 各自基于 Radix Popover 与自定义 block-paper DOM 实现了两套几乎一致的斜杠指令过滤浮层。
5. **违规原生 `title=` 属性散落未清理**：全仓仍有 10+ 处直接在 DOM 元素上挂载原生 `title={...}`，破坏了项目的自定义 `<Tooltip>` 设计规范。

- **问题定位**：在面包屑路径导航中，为了实现「点击目录弹出子文件列表」，手动在 `useEffect` 中监听 `document.addEventListener('mousedown')` 与 `window.addEventListener('keydown')`（Esc 键），并在 JSX 中手写了一套包含搜索框、滚动列表和选项按钮的 Flyout 面板。而 `ui/Menu` 已经基于 Radix DismissableLayer 实现了完备的外点关闭与键盘漫游。

```tsx
// FileBreadcrumb.tsx:148-168（手写事件监听与焦点归还）
  useEffect(() => {
    if (!bcFlyout) return;
    const onDoc = (e: MouseEvent) => {
      const t = e.target as Node;
      if (crumbsRef.current?.contains(t)) return;
      setBcFlyout(null);
      requestAnimationFrame(() => bcTriggerRef.current?.focus());
    };
    const onKey = (e: KeyboardEvent) => {
      if (e.key === 'Escape') {
        setBcFlyout(null);
        requestAnimationFrame(() => bcTriggerRef.current?.focus());
      }
    };
    document.addEventListener('mousedown', onDoc);
    window.addEventListener('keydown', onKey);
    return () => {
      document.removeEventListener('mousedown', onDoc);
      window.removeEventListener('keydown', onKey);
    };
  }, [bcFlyout]);

// FileBreadcrumb.tsx:233-260（手写 Flyout 浮层结构与原生 search input）
```

## 三、基础 UI 抽象不足与各业务模块私有轮子根因剖析

### 3.1 为什么现有的 `components/ui/` 未能成为全仓权威标准？

深入分析现有 `src/components/ui/` 的设计，可以发现存在以下架构缺陷和功能断层：

1. **`Button` 契约过窄与样式死板**：
   - 目前 `Button` 仅支持 `variant="primary" | "secondary" | "ghost" | "danger"` 和 `size="sm" | "md"`；
   - `Button.module.css` 中固定了 `border-radius: var(--radius-full)` 或 `var(--radius-md)`，高度固定为 `var(--control-height)` / `var(--control-height-sm)`；
   - 业务中大量需要 **方形微型图标按钮（24x24 / 28x28）**、**纯文字链接按钮（无 padding、下划线）**、**表单嵌入式提交按钮（无圆角药丸变形）**；因为标准 `Button` 不支持 `size="xs"`、`variant="link"` 或 `square` 属性，业务开发者被迫写内联 style（如 `ProviderProfileForm.tsx:85` 的 `borderRadius: '7px', height: '34px'`）或直接改用原生 `<button>`。
2. **`Input` 缺乏复合态与 Form-Control 适配**：
   - 现有的 `Input` 组件（`Input.tsx`）将 `<label>`、`<p className={styles.inputError}>`、`<p className={styles.inputHint}>` 全部硬编码在自身的最外层 `wrapClasses` 中；
   - 当业务需要横向排版的表单行（如 `SettingsRow`、`WorkflowForm`、`DiffCard` 的单行搜索条）时，`Input` 自带的外层包装和默认上下 margin 无法贴合紧凑布局；
   - 缺失 `Textarea` 原子组件，导致所有多行文本输入（`RulesEditorDialog`、`WorkflowForm`、`DiffCardGitActions`、`BrowserImportSection`）只能裸写 `<textarea>`。
3. **缺失关键原子组件**：
   - **Checkbox / Radio**：全仓完全没有 `Checkbox` 和 `Radio` 原子组件。所有需要复选框的地方（`BgTaskActions` 的追加换行、`SkillEditorModal` 的待导入列表）全部裸写 `<input type="checkbox">`。
   - **SegmentedControl / ToggleGroup**：全仓 7 处手写单选分段按钮。
   - **Slider / Range**：Settings 模块直接写原生 `<input type="range">`。
   - **Badge / Chip**：全仓 14 处手写各类状态标签与预设 Chip。
   - **Popover**：除了 `Menu`（下拉菜单）之外，缺乏通用的非菜单型浮层容器（导致 `FileBreadcrumb` 手写 Flyout）。

## 四、属性、交互与无障碍（A11y）割裂深度审计

### 4.1 焦点环（Focus Ring）与交互激活态断层

在全仓样式与交互审查中，发现焦点环规范存在明显断层：

1. **Tokens 统一规范 vs 裸 outline: none**：
   - 标准 `Button.module.css:21` 使用 `.button:focus-visible { outline: none; box-shadow: var(--focus-ring); }`；
   - 然而在 `CheatsheetModal.module.css:89` 中，输入框仅定义了 `outline: none;`，由外层 div 监听 `:focus-within { border-color: var(--accent-color); }`，**完全丢失了键盘 Tab 导航时专用的 `--focus-ring` 发光环**；
   - 在 `DiffCard.module.css` 与 `ThoughtSearchBar.module.css` 中，许多手写按钮直接重置了 `outline: none`，且未补充 `:focus-visible` 状态，导致纯键盘用户无法获知当前焦点位置。
2. **激活态颜色违规**：
   - 仓库铁律明确要求焦点对比度上限约 10%，禁止深黑实线；
   - 但在 `SettingsShortcutsTab.tsx:482` 的 `.shortcut-key-btn.recording` 中，激活态直接施加了硬高亮，缺乏平滑过渡。

### 4.2 禁用态（Disabled State）表现割裂与语义失步

全仓对「禁用」的处理存在 3 种互不兼容的做法：

1. **原生 `disabled` 属性**：正确施加在 `<button>` 或 `<input>` 上，同时触发 `:disabled` 伪类（如 `ui/Button`）；
2. **纯 CSS 类名标记（无原生 disabled）**：如 `SettingsRulesTab.tsx:228` 中的 `.settings-rule-preset.is-disabled`，虽然在 JSX 中也传递了 `disabled={exists}`，但在 CSS 中使用了私有 `.is-disabled` 类名，导致部分通过键盘 Tab 漫游的无障碍设备无法及时感知不可交互状态；
3. **`aria-disabled="true"` 但未阻止点击**：在某些自定义 div（如 `DiffCardGitActions.tsx` 中的 `.commitTriggerBar`）中，未正确同步 `aria-disabled`，点击事件也未判断 `disabled` 守卫。

### 4.3 提示系统撕裂：Tooltip 规范与原生 `title=` 属性散落违规

项目在 `AGENTS.md` 铁律第 12 条明确规定：**必须始终使用项目自定义 `<Tooltip>` 组件，严禁使用原生 HTML `title` 属性作为主悬停提示**。
然而审查发现，全仓仍有 10+ 处违规直接使用原生 `title`：

```tsx
// 1. ModelConfigPanel.tsx:107（网络延迟测试结果展示）
<span
  style={{ ... }}
  title={meta.lastTest.error || (meta.lastTest.ok ? '测试成功' : '测试失败')}
>

// 2. SkillEditorModal.tsx:107（技能候选列表标签）
<label
  key={s.id}
  className={styles.skillsDiscoverItem}
  title={s.description || s.name}
>

// 3. SettingsSecurityTab.tsx:269（命令输入框风险提示）
<input
  id={wlInputId}
  type="text"
  title={inputRiskTitle}
  className={`settings-field-input ...`}
/>

// 4. SettingsShortcutsTab.tsx:360, 391（快捷键筛选输入与状态）
<input id={filterId} title={filterTitle} ... />
<span id={headMetaId} title={filterTitle} ... />

// 5. GlobalSessionTabBar.tsx:240（会话标签）
<div title={tab.label} ... />

// 6. SecurityAuditSection.tsx:80（安全审计列表）

// 7. TrashSection.tsx:148（回收站列表）
```

- **后果**：原生 `title` 会触发浏览器默认的黄色/灰白色小矩形气泡，出现延迟高（约 1-2 秒才弹出）、无法自定义样式、遮挡 UI 且在深色模式下极其刺眼，破坏了整体软件质感。

### 4.4 键盘导航（Keyboard Navigation & Roving Tabindex）覆盖不均

- `ui/TabStrip` 和 `ui/Menu` 实现了非常优秀的 `roving tabindex` 与 `ArrowUp/ArrowDown/Home/End` 导航支持；
- 但在各业务模块自造的列表中（如 `SettingsShortcutsTab.tsx:320-340`、`DiffCardFileList.tsx`、`ProjectPickerMenu.tsx`、`FileBreadcrumb.tsx`），键盘事件监听是各写一套、按键覆盖不全（缺少 Home/End 或无法循环聚焦），甚至部分手写下拉完全不支持键盘上下方向键选择。
