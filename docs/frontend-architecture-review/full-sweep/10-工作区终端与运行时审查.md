# 工作区终端、Web 预览与运行时面板 (Workspace Terminal, Preview & Runtime) 深度审查报告

> **审查范围**：`apps/crish-desktop/src/components/workspace/` 及关联布局、标签系统、IPC 桥与状态机
> **核心焦点**：TerminalCard 终端卡片渲染与交互、PreviewCard 网页预览与地址栏、BrowserPanel / ComputerPanel 挂载断层、RuntimePanel 运行时面板架构以及统一 ViewRegistry 重构设计
> **审查基准**：严格基于前端源码实现，以精准代码路径、真实组件结构、类名及 `文件路径:行号` 为证据支撑。

## 摘要与核心发现 (Executive Summary)

Conex / Crish 桌面工作区承载着终端（Terminal）、网页预览（Preview）、AI 受管浏览器（Managed Browser）、电脑操作（Computer Use）以及运行时状态（Runtime）等多种专业工具面板。本次全景深度审查穿透源码层，揭示了以下四个维度的严重架构断层与演进矛盾：

1. **TerminalCard 交互与动作栏完全架空**：终端虽引入了 `@xterm/xterm` + `@xterm/addon-webgl` 交互式 PTY 引擎，但其控制柄 `InteractiveXtermHandle`（含 `clear`、`restart`、`focus`、`getPtyId`）在组件装配层**从未传递 `ref`**；样式表（`TerminalCard.module.css`）遗留了超过 180 行用于工具栏、命令镜像、输入框、搜索栏的死样式；UI 层面**零操作按钮**（无清屏、无复制、无滚动锁定、无重启、无 Shell 切换、无搜索高亮），与专业级终端（VS Code / Hyper / Warp）存在明显代差。
2. **PreviewCard 单一体积膨胀与响应式视口缺失**：Web 预览卡片基于 iframe 实现了安全沙箱、导航栈与历史/书签浮层，但完全缺乏**设备视口模拟（Mobile / Tablet / Desktop Presets）**与 **CSS Transform 自适应等比缩放**，在狭窄分屏下网页直接被截断；且刷新机制仅靠 `iframe.src = src` 无法绕过缓存。
3. **BrowserPanel 与 ComputerPanel 挂载断层与寄生异化**：
   - **技术实现高度完备**：`BrowserPanel` 已完整实现了 Tauri Channel JPEG 帧解码（12 字节定长头 + createImageBitmap 异步解码）、DPR 自适应画布、坐标逆映射输入直转（`InputLayer`）、隐藏式 IME 输入法桥接（`imeBridge`）、4 态接管指示条（`IndicatorBar`）及多浏览器 Cookie/Profile 提取；`ComputerPanel` 也实现了三态激活指示器与全局急停（Estop）。
   - **注册表与路由全面封杀**：`cardPanelHelpers.ts` 的 `KNOWN_BODY_IDS`、`ui-panel.ts` 的 `PANEL_TITLE_MAP`、`CardPanelHeader.tsx` 的 `PANEL_ADD_IDS`、`LeafToolTabStrip.tsx` 的 `PANEL_LABELS` 完全排除了两者；`ui-panel.ts:18` 甚至将 `browser` 强制降级别名重定向为 `preview`；在 Classic 布局（`CardPanelLayout.tsx`）与二叉树布局（`TreeLeafPanel.tsx`）中均会命中兜底未知/无法显示空态。
   - **寄生在 PreviewCard 内部**：为了能够在 UI 中运行，开发者在 `PreviewCard.tsx` 内部通过一个布尔状态 `aiBrowser` 将 `BrowserPanel` 与 `ComputerPanel` 强行垂直堆叠渲染。这导致受管浏览器无法作为独立 Tab 参与工作区拖拽、分屏与持久化。
4. **RuntimePanel 运行时面板全树每秒重绘与轮询开销**：`RuntimePanel` 聚合了 11 个区段，但由于顶层 `useRuntimePanelData` 包含 `setInterval(1000)` 时钟，导致每秒触发整面板及其所有子 Section 的 React 遍历；`FlowDagView` 每 3 秒发起无条件 IPC 轮询，缺乏事件驱动的按需唤醒。

#### 3. 分屏拖拽中的帧率降采样控制

在 `TerminalCard.xterm.tsx:452-476` 中，为了避免分屏拖拽（Resizing）时 WebGL 频繁 `fit()` 引起高频重绘闪烁，代码引入了智能限频：

```tsx
const scheduleFit = () => {
  // 布局拖拽中：约 12fps (80ms)，与 sash 几何刷新对齐、降低 WebGL 闪烁
  const minInterval = isLayoutResizing() ? 80 : 32;
  const now = performance.now();
  const wait = Math.max(0, minInterval - (now - lastFitAt));

  if (wait > 0) {
    if (throttleTimer) return;
    throttleTimer = window.setTimeout(() => {
      throttleTimer = 0;
      if (raf) cancelAnimationFrame(raf);
      raf = requestAnimationFrame(() => {
        raf = 0;
        doFit();
      });
    }, wait);
    return;
  }

  if (raf) return;
  raf = requestAnimationFrame(() => {
    raf = 0;
    doFit();
  });
};
```

**分析**：通过检查 `document.body` 上的 `.tree-resizing` / `.is-resizing` 等类名，将分屏拖拽期间的重排开销压制在 12fps，在流畅度与性能开销之间取得了极佳平衡。

### 1.2 交互与快捷操作栏的严重架空

尽管底层 PTY 和渲染引擎表现优异，但顶层组件交互存在**致命的断层与代码架空**。

#### 1. `InteractiveXtermHandle` 句柄被阻断，Ref 丢失

在 `TerminalCard.xterm.tsx:39-46, 108-135` 中，子组件精心定义并导出了命令接口：

```tsx
export type InteractiveXtermHandle = {
  focus: () => void;
  /** 发送 Ctrl+L（清屏），本地 buffer 同步 clear */
  clear: () => void;
  getPtyId: () => string | null;
  /** 强制重建当前会话 PTY */
  restart: () => void;
};
```

然而，在父组件 `apps/crish-desktop/src/components/workspace/TerminalCard.tsx:98-106` 中：

```tsx
<div className={styles.xtermWrap}>
  <InteractiveXtermTerminal
    sessionKey={sessionKey}
    cwd={fullCwd || undefined}
    restartToken={restartToken}
    onStatusChange={handlePtyStatus}
    onPtyMissing={handlePtyMissing}
  />
</div>
```

**缺陷诊断**：`TerminalCard.tsx` **根本没有向 `InteractiveXtermTerminal` 传入 `ref`**！

- 内部实现的 `clear()`（发送 `\x0c` + `term.clear()`）完全无法从外部触发；
- 内部实现的 `restart()`（强制 `killPtyForSession` 并重建）完全无法从外部触发；
- `restartToken` 状态在 `TerminalCard.tsx:33` 中被写死为静态常量 `const [restartToken] = useState(0);`，永远不会更新。

#### 2. CSS 样式表存在大量死代码

`apps/crish-desktop/src/components/workspace/TerminalCard.module.css` 中保留了大量上一代伪终端/镜像条的样式规则：

- 行 13-46：`.toolbar`, `.toolbarLabel`, `.files-icon-btn`（已移除）
- 行 48-134：`.mirrorStrip`, `.mirrorHeader`, `.mirrorToggle`, `.mirrorCount`, `.mirrorBody`（已移除）
- 行 195-232：`.inputRow`, `.prompt`, `.input`（已移除）
- 行 233-298：`.bar`, `.barIco`, `.barMeta`, `.barCwd`, `.barBtn`（已移除）
- 行 335-386：`.searchRow`, `.searchIco`, `.searchInput`, `.searchClear`（已移除）

而在 `TerminalCard.tsx:1-4` 中赫然写着：

> _“终端面板：VS Code 式交互式 PTY + xterm。纯终端：无顶栏 / 无镜像条 / 无搜索壳；仅 xterm 全屏 + PTY 不可用时的简短提示。”_

**缺陷诊断**：组件采取了激进的“极简砍功能”策略，将顶栏工具栏彻底剔除，但样式表中遗留了超过 180 行无主 CSS 类，造成维护负担。

#### 3. 与专业级终端（VS Code / Hyper / Warp）的功能代差

由于去掉了顶栏与动作入口，用户在界面上**无法进行任何快捷操作**：

- **无清屏按钮（Clear）**：用户必须在键盘上手动输入 `clear` 或按下 `Ctrl+L`，对于触控或鼠标操作极不友好；
- **无复制全部/选区复制按钮（Copy All / Copy Selection）**；
- **无滚动锁定（Scroll Lock / Auto-Scroll）**：当后台持续产生海量输出时，无法锁定视口向上阅读历史；
- **无 Shell 切换器**：无法在 PowerShell、CMD、Git Bash、WSL 之间切换；
- **无终端标签页管理（Multiple PTY Tabs）**：每个会话严格绑定单个 PTY 实例，不支持在同一面板中创建多个并发终端 Tab。

## 二、PreviewCard 网页预览与地址栏深度审查

### 2.1 iframe 容器安全沙箱与跨域策略

`PreviewCard` 提供内置 Web 预览能力，结构由 `PreviewToolbar`（工具栏）、`PreviewHistoryPanel`（历史书签抽屉）和 `iframe` 容器组成。

#### 1. 安全沙箱与 Referrer 策略

在 `apps/crish-desktop/src/components/workspace/PreviewCard.tsx:224-237` 中：

```tsx
<iframe
  ref={iframeRef}
  key={frameSrc}
  aria-label="预览页面"
```

### 2.3 关键设计缺陷与缺失能力

1. **缺失设备视口模拟（Device Mode & Viewport Emulation）**：
   - 作为一个现代 Web 预览器，无法切换 Mobile（375×667）、Tablet（768×1024）或 Desktop（1440×900）分辨率预设；
   - 无法切换横竖屏（Orientation）。
2. **缺失自适应等比缩放（Adaptive Zoom & CSS Scale Transform）**：
   - 当用户在右侧工具栏（通常宽度为 300px~450px）预览一个非自适应的 PC 网页时，iframe 内容会被直接裁剪截断；
   - 缺乏 `transform: scale(factor)` 缩放控制器（如 50%, 75%, 100%, 125%），无法将完整的 1920px 网页等比缩入窄面板。
3. **缺少缓存旁路硬刷新（Hard Reload / Bypass Cache）**：
   - `usePreviewNavigation.ts:245` 中的 `reload()` 仅仅执行了 `el.src = src;`，直接复用浏览器内存/磁盘缓存；在本地前端开发热更新失效时，无法强制刷新拉取最新构建产物。
4. **缺少协议与证书安全指示（Protocol Security Indicator）**：
   - 地址栏固定展示 `<Lucide.Globe>` 图标，无法区分 `https://`（安全锁）、`http://`（明文警告）与本地 `localhost`。

## 三、BrowserPanel 受管浏览器与 ComputerPanel 挂载断层深度审查

### 3.1 完整实现的技术深度

`BrowserPanel` 与 `ComputerPanel` 是两套为了支持 AI Autonomous Agent（浏览器自动化与桌面自动化）而开发的高阶重型运行时面板。通过源码审查，其内部实现具备极高的专业水准：

#### 1. BrowserPanel：基于 Channel 帧流与 Canvas 的双向协作渲染

- **二进制帧协议解析**（`frameProtocol.ts:26-53`）：
  每帧数据以 12 字节定长小端头开头（`seq: u32`, `width: u32`, `height: u32`），后接 JPEG 图像二进制载荷；
- **异步渲染循环与丢帧追新**（`useFrameStream.ts:100-160`）：
  使用 `createImageBitmap` 在主线程之外异步解码 JPEG Blob；队列深度固定为 1（新帧直接覆盖未渲染帧，绝不积压追赶）；结合 DPR 处理物理像素缩放；使用 `containFit` 纯函数保持纵横比；
- **输入层逆向投影与直转**（`InputLayer.tsx:48-112` + `usePanelInput.ts:80-160`）：
  捕获用户的鼠标点击、移动、滚轮、右键菜单与 ASCII 键盘输入；通过 `containFit` 将 CSS 容器坐标逆向映射为远程受管浏览器的绝对视口坐标，经 `browser_input` invoke 上行给后端；

### 5.1 标准化视图元数据契约 (`ViewDefinition<TProps>`)

在 `apps/crish-desktop/src/types/viewRegistry.ts` 中定义通用的面板契约：

```typescript
import React from 'react';
import type { ShowToastFn } from '../hooks/useToastQueue';

export type ViewCategory = 'core' | 'tools' | 'ai-runtime' | 'system';

export interface ViewComponentProps {
  wsId?: string;
  sessionId?: string | null;
  onShowToast: ShowToastFn;
  isActive?: boolean;
}

export interface ViewDefinition<
  TProps extends ViewComponentProps = ViewComponentProps,
> {
  /** 唯一视图标识，如 'terminal' | 'preview' | 'browser' | 'computer' | 'runtime' */
  readonly id: string;

  /** 视图显示名称（或动态计算函数） */
  readonly title: string | ((props?: TProps) => string);

  /** 视图简要提示（用于 Tooltip / 读屏） */
  readonly hint?: string;

  /** 视图专属图标 */
  readonly icon: React.ComponentType<{
    size?: number;
    strokeWidth?: number;
    className?: string;
    'aria-hidden'?: boolean;
  }>;

  /** 分类归属 */
  readonly category: ViewCategory;

  /** 是否可从标签栏关闭（chat 与 overview 通常不可关闭） */
  readonly closable: boolean;

  /** 是否为单例面板（同一工作区内是否仅允许开启一个实例） */
  readonly singleton?: boolean;

  /** 是否绑定会话作用域（如 terminal / chat 绑定 sessionId；files / runtime 为工作区全局） */
  readonly sessionScoped?: boolean;

  /** 懒加载组件 */
  readonly component:
    | React.LazyExoticComponent<React.ComponentType<TProps>>
    | React.ComponentType<TProps>;

  /** 预设最小尺寸与初始比例 */
  readonly layoutOptions?: {
    minWidth?: number;
    minHeight?: number;
    defaultWidthRatio?: number;
  };
}
```

## 结论

本次深度审查表明，Conex / Crish 桌面端在终端、受管浏览器与运行时面板上积累了深厚的技术资产（如高性能 WebGL 终端管线、Channel 视频帧流、IME 虚拟注入桥与三态急停门禁），但受限于**早期硬编码注册表、路由别名降级、单一卡片寄生挂载与句柄调用断层**，导致这些高价值能力无法在用户界面中完全释放。

通过推行以 **`ViewRegistry` 为单一事实来源** 的全景重构，将彻底打通工作区面板的注册、路由、分发与生命周期管理，不仅能直接修复受管浏览器与电脑面板的挂载断层，更为后续扩展更多专业 AI Agent 工具面板奠定坚实、优雅的架构基座。
