## 一、审查综述与核心问题矩阵

主对话输入区（Chat Composer）与底部操作栏（Footer Actions）是 Crish 桌面端与用户产生高频交互的核心枢纽。整个模块承担了富文本/纯文本切换、附件管理、权限模式切换、扩展加号菜单、AI 斜杠指令（Slash Menu）、消息撤回以及模型切换等诸多关键职责。

然而，在深入代码审查与真实事件流追踪后，发现该模块在**事件分发链路**、**浮层生命周期**以及**视觉几何体系**上存在严重的架构断层与状态竞争，集中体现为两大恶性问题：

1. **四击才能关闭面板（Quad-Click Bug）**：尽管源码注释声称已通过迁移 ui/Menu 消除该 Bug，但由于 `LayerStackService`、Radix UI `DismissableLayer`、`Menu.tsx` 自管 Pointer 追踪以及 `Tooltip` 原子组件的四重事件争抢，在真机环境下依然导致用户点击触发器无法可靠关闭浮层，陷入多击才能退出的恶性循环；
2. **底部操作栏圆角视觉失调**：底部操作栏容器与内部各个操作控件（加号按钮、权限模式胶囊、撤回按钮、模型选择徽标）之间缺乏统一的几何阶梯法则，`Button` 原子类的 `border-radius: var(--radius-full)` 与业务 CSS 的 `var(--radius-lg)` 发生层叠覆盖竞态，导致药丸形状过大、方圆混杂、极度不协调。

## 二、四击关闭恶性 Bug（Quad-Click Bug）深度解剖与事件流溯源

### 2.1 源码自称与真实现状的断层悖论

在 [`PermissionModeMenu.tsx:19-26`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/PermissionModeMenu.tsx#L19-L26) 中，存在一段明确的修复声明注释：

```tsx
/**
 * 权限模式菜单（T05.3.2 迁移到 ui/Menu 基座 / 显式 Anchor 模式）：
 * - 药丸按钮拥有独立的 pillBtnRef 与 onClick 处理器，消除 Popover.Trigger 与 Tooltip 争抢导致的 Quad-Click 四击 Bug；
```

然而在真机环境（Chromium / Edge WebView2）下，用户反馈「点击四次才能关闭面板」的恶性体验依然稳定复现。

### 2.2 四大竞争层与多重监听器事件碰撞全景

排查发现，当前体系中存在多达 **4 个相互独立的事件管理层**：

#### 1. Layer 1：LayerStackService 全局单例监听器

- **源码位置**：[`LayerStackService.ts:349-356, 439-473`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/internal/layer-stack/LayerStackService.ts#L349-L356)
- **行为**：在 `window` 与 `document` 的 capture 阶段全局监听 `pointerdown`。
- **冲突机制**：当点击发生时，`LayerStackService` 检查 `anchorEl.contains(target)`（第 457 行），判定点击在触发源内部，因此**不执行** `dismissLayer`，将开关权转交给触发源自身的 `onClick`。

#### 2. Layer 2：Radix Popover.Content 内部 DismissableLayer

- **源码位置**：[`Menu.tsx:452-475`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Menu/Menu.tsx#L452-L475)
- **行为**：Radix 在 `document` capture 阶段派发 `pointerdownoutside` 与 `interactoutside`。
- **冲突机制**：
  ```tsx
  onPointerDownOutside={(e) => {
    const target = e.detail.originalEvent.target as Node | null;
    const triggerEl = anchor?.current ?? triggerRef.current;
    if (triggerEl && target && triggerEl.contains(target)) {
      e.preventDefault(); // 阻止 Radix 在 pointerdown 阶段自动关闭
    }
  }}
  ```
  `Menu.tsx` 显式调用 `e.preventDefault()` 阻止 Radix 关闭，目的是防止「Radix 在 pointerdown 先关了一次，button 的 onClick 紧接着又开了一次」的 Double Toggle 竞态。

#### 3. Layer 3：Menu.tsx Anchor 模式下的 WO-26 机制

- **源码位置**：[`Menu.tsx:153-180`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Menu/Menu.tsx#L153-L180)
- **行为**：
  ```tsx
  useEffect(() => {
    if (!isOpen || !anchor?.current) return;
    const anchorEl = anchor.current;
    let trackedPointerId: number | null = null;

    const handlePointerDown = (e: PointerEvent) => {
      trackedPointerId = e.pointerId;
    };

    const handlePointerUp = (e: PointerEvent) => {
      if (trackedPointerId !== null && e.pointerId === trackedPointerId) {
        trackedPointerId = null;
        const target = e.target as Node | null;
        if (!anchorEl.contains(target)) {
          handleOpenChange(false);
        }
      }
    };

    anchorEl.addEventListener('pointerdown', handlePointerDown);
    window.addEventListener('pointerup', handlePointerUp, true);
    // ...
  }, [isOpen, anchor, handleOpenChange]);
  ```
  此处的 `window.addEventListener('pointerup', ..., true)` 在捕获阶段运行。如果用户在点击胶囊按钮时发生轻微滑动（Pointer Move）导致 `target` 偏移至 button 外部（例如滑到相邻空白处或 SVG 子节点边缘），WO-26 会在捕获阶段直接触发 `handleOpenChange(false)`！

#### 4. Layer 4：Tooltip 原子组件的 PointerDown / Click 劫持与 120ms 退出动画残影

- **源码位置**：[`Tooltip.tsx:274-277, 431-443, 523-552`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Tooltip/Tooltip.tsx#L274-L277)
- **行为**：
  ```tsx
  const { state, isMounted } = useAnimatedPresence({
    visible,
    exitDurationMs: 120,
  });
  ```
  当点击胶囊按钮时，Tooltip 的 `handlePointerDown` 触发 `setVisible(false)`，但 `useAnimatedPresence` 保持 `isMounted === true` 达 **120ms**！
  在 120ms 的退出动画期间，Tooltip 在 `document.body` 上挂载的 Portal 节点依然存在：
  ```tsx
  createPortal(
    <DismissableLayer.Branch asChild>
      <div ref={tipRef} id={tipId} role="tooltip" data-tooltip-portal="true" ... />
    </DismissableLayer.Branch>,
    document.body
  )
  ```
  该 Portal 节点注册为 `DismissableLayer.Branch`，直接干扰了后续连续点击的命中测试（Hit Testing）。

### 2.3 四次点击（Click 1 ~ Click 4）在真机 WebView2 下的完整时序回溯

通过上述竞争层的交织，我们完整还原现场「四击关闭」的时序证据链：

```
【初始状态】：Menu 处于打开状态 (open === true)，Tooltip 处于 disabled 状态。

[第 1 击 (Click 1)]：
1. 用户在胶囊按钮上按下鼠标（PointerDown）；
2. Menu.tsx 的 onPointerDownOutside 触发 e.preventDefault()，阻止 Radix 关闭；
3. 按钮触发 onClick -> handleToggle() -> setOpen(false)；
4. React 调度更新，Menu open 变为 false，Menu 开始关闭并卸载；
5. 同时 Tooltip 的 disabled 属性从 true 变为 false！
6. Radix Popover 卸载时触发 onCloseAutoFocus，将焦点归还给 button；
7. 按钮重新获得焦点 + 鼠标仍然悬停在按钮上方 -> Tooltip 瞬间被触发 (setVisible(true))；
8. Tooltip 挂载 Portal，浮层在 0~120ms 内产生 DOM 插入与重排。

[第 2 击 (Click 2)]：
1. 用户以为面板已关，或者在快速连击时，第 2 次点击发生；
2. 此时 Tooltip 刚刚完成挂载或正在进行 enter 动画；
3. PointerDown 命中了 Tooltip 的 handlePointerDown -> 触发 setVisible(false) -> Tooltip 进入 120ms 退出动画；
4. 退出动画期间的 Portal 遮挡或状态更新导致此次点击事件未能正确触发外部期望的干净闭合状态（状态处于 exiting 瞬态）。

[第 3 击 (Click 3)]：
1. 用户发现状态异常，再次点击；
2. 此时由于前次点击导致 Tooltip 刚退出完成，焦点与 hover 重新竞争；
3. Menu 的 internalOpen 与 externalOpen 产生单帧状态失步，button 的 onClick 触发了 setOpen(true)，导致菜单被重新意外打开！

[第 4 击 (Click 4)]：
1. 用户第 4 次点击，此时没有 Tooltip 挂载竞争，Menu 终于正常接收到关闭信号并彻底关闭。
```

**结论**：所谓的“消除了 Quad-Click Bug”只消除了单纯的 `Popover.Trigger` 原生事件冒泡，**根本没有解决 Tooltip 的生命周期闪烁、Radix 焦点还原与 120ms 退出残影之间的事件争抢**。

### 2.4 Menu.tsx Trigger 兼容模式下的 React 19 克隆与 e.stopPropagation() 毒点

在 [`Menu.tsx:382-405`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Menu/Menu.tsx#L382-L405) 的 trigger 兼容路径中，存在一个极其危险的事件阻断写法：

## 三、footerActions 按钮圆角与视觉几何阶梯失调审查

### 3.1 6px / 7px / 9px 几何阶梯与同心圆角法则基线

在现代桌面 GUI 工业设计体系中，嵌套元素的视觉和谐必须严格遵循**同心圆角法则（Concentric Radius Rule）**：
$$R_{inner} = \max(0, R_{outer} - Padding)$$

在本仓库设计系统 [`tokens.css:771-777, 847-853`](file:///c:/Software/conex/apps/crish-desktop/src/styles/tokens.css#L771-L777) 中，定义了标准的圆角阶梯变量：

- `--radius-xs`: 3px ~ 4px
- `--radius-sm`: 4px ~ 6px
- `--radius-md`: 5px ~ 7px（微型/紧凑按钮标准）
- `--radius-lg`: 7px ~ 9px（标准交互控件 squircle 圆角）
- `--radius-xl`: 9px ~ 11px
- `--radius-2xl`: 11px ~ 13px（容器卡片圆角）
- `--radius-full`: 9999px（仅用于状态圆点与单字符小徽标）

## 四、加号菜单（ComposePlusMenu）与斜杠菜单（TiptapSlashMenu）交互审查

### 4.1 ComposePlusMenu 的浮层定位、生命周期与键盘漫游

#### 1. 条件渲染导致的生命周期截断（Lifecycle Chopping）

- **源码位置**：[`ComposePlusMenu.tsx:94`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/ComposePlusMenu.tsx#L94)
- **缺陷**：
  ```tsx
  if (!open) return null; // ◀ 致命生命周期截断
  return (
    <Menu open={open} ... />
  );
  ```
  当 `open` 从 `true` 变为 `false` 时，`ComposePlusMenu` 直接返回 `null` 并从 React DOM 树中瞬间销毁！
  这导致内部包裹的 Radix `Popover.Root` 与 `useLayerRegistration` 无法执行正常的淡出退场动画，也无法触发 Radix 的 `onCloseAutoFocus` 焦点恢复机制。

#### 2. 菜单项包装 Tooltip 导致键盘漫游与提示冲突

- **源码位置**：[`ComposePlusMenu.tsx:112-137`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/ComposePlusMenu.tsx#L112-L137)
- **缺陷**：
  ```tsx
  renderItem={(item) => (
    <Tooltip key={item.id} content={item.hint || item.label}>
      <button type="button" className={styles.item} role="menuitem" ...>
  ```
  当用户使用键盘方向键 `↑` / `↓` 漫游时，[`Menu.tsx:308-315`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Menu/Menu.tsx#L308-L315) 会将原生 `focus()` 移动到对应的菜单项 button 上。
  由于每个 button 都被 `<Tooltip>` 包裹，按钮一获得 focus，Tooltip 便立即弹出；用户快速按上下键漫游时，Tooltip 在屏幕上疯狂闪烁与重绘。

#### 3. 键盘 Enter 与 Native Click 双发风险

- **源码位置**：[`Menu.tsx:245-254`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Menu/Menu.tsx#L245-L254) vs [`ComposePlusMenu.tsx:119-122`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/ComposePlusMenu.tsx#L119-L122)
- **缺陷**：
  在 `options` 模式下，`Menu.tsx` 监听了 `Enter` / `Space`：
  ```tsx
  if (e.key === 'Enter' || e.key === ' ') {
    opt.onClick?.();
    onSelect?.(opt.id, opt);
    handleOpenChange(false);
  }
  ```
  而在 `renderItem` 渲染的原生 `<button>` 上，浏览器原生也会在用户按 Enter 时派发 `click` 事件。
  在部分 WebView2 焦点状态下，`opt.onClick()` 会被**连续调用两次**，导致例如添加文件对话框被连续唤起或报错。

#### 4. 焦点交接争抢

- **源码位置**：[`ComposePlusMenu.tsx:50`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/ComposePlusMenu.tsx#L50) vs [`ChatComposer.tsx:375`](file:///c:/Software/conex/apps/crish-desktop/src/components/chat-composer/ChatComposer.tsx#L375)

  - `ComposePlusMenu` 执行：`queueMicrotask(() => restoreFocusRef?.current?.focus?.());`（聚焦回 `+` 按钮）；
  - `ChatComposer` 执行：`requestAnimationFrame(focusComposerTextarea);`（聚焦到编辑器）。
    微任务与动画帧在同一轮事件循环中互相抢夺 `document.activeElement`，导致输入框光标时有时无。

## 五、输入框底部操作栏彻底根治重构方案

为彻底根除四击关闭 Bug、消除事件争抢、实现单次点击必开关，并将所有视觉圆角规范化为统一的 6px/7px/9px 阶梯，制定以下彻底重构方案：

### 5.1 架构解耦与单次点击必开关标准模型

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          标准单向事件流驱动模型                                │
└──────────────────────────────────────┬──────────────────────────────────────┘
                                       │
                ┌──────────────────────┴──────────────────────┐
                ▼                                             ▼
┌───────────────────────────────┐             ┌───────────────────────────────┐
│ Trigger 触发器层               │             │ Menu / Popover 浮层容器层      │
│ (拥有单一显式 isMenuOpen 状态) │             │ (纯受控 open / onOpenChange)   │
└───────────────┬───────────────┘             └───────────────┬───────────────┘
                │                                             │
                ├─────────────────────────────────────────────┤
                ▼                                             ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ [核心协议 1] Tooltip 互斥抑制协议:                                          │
│ 当 isMenuOpen === true 或刚刚触发关闭 150ms 内，Tooltip 完全 disabled 且不挂载 │
└─────────────────────────────────────────────────────────────────────────────┘
                │
                ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ [核心协议 2] 单一外部点击判定协议 (Single Outside Pointer Protocol):       │
│ 1. 废弃内部冗余的 WO-26 window pointerup 监听器                             │
│ 2. Radix onPointerDownOutside 不再滥用 preventDefault()                     │
│ 3. 点击 Trigger 时，由 Trigger 自身统一分发 setOpen((v) => !v)              │
│ 4. 点击 Trigger 外部时，由 Radix onOpenChange(false) 统一收口               │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 实施要点 1：消除 `ComposePlusMenu` 与 `PermissionModeMenu` 的生命周期截断

- **禁止** `if (!open) return null`；
- `<Menu>` 组件必须保持在树中常驻，由 `open={showPlusMenu}` 进行纯受控驱动，允许 Radix 完整的 exit 动画与 DOM 清理。

#### 实施要点 2：彻底切断 Tooltip 在 Menu 切换期的瞬态闪烁

在 `PermissionModeMenu.tsx` 与 `ChatComposer.tsx` 中，引入抗抖动的 Tooltip 守卫：

```tsx
const [open, setOpen] = useState(false);
const lastClosedAtRef = useRef(0);

const handleOpenChange = useCallback((nextOpen: boolean) => {
  if (!nextOpen) {
    lastClosedAtRef.current = Date.now();
  }
  setOpen(nextOpen);
}, []);

// 刚关闭 150ms 内依然禁用 Tooltip，绝不允许焦点归还瞬间触发 Tooltip
const isTooltipDisabled = open || Date.now() - lastClosedAtRef.current < 150;
```

#### 实施要点 3：统一 Trigger 锚定规范

在 `Menu.tsx` 中，全面废弃对 trigger 的脆弱 clone 与 `e.stopPropagation()` 侵入，统一采用 `anchor={ref}` 显式锚点模型；所有 Trigger 按钮保持普通原生/UI 按钮语义，由自身 `onClick` 驱动状态。
