## 1. 审查背景与架构全景 (Overview & Architecture Panoramic)

### 1.1 组件层次结构与拓扑

聊天主工作区 (`ChatCard`) 是 Crish 桌面端的人机交互核心，承载了从空白会话建立、状态通知展示、长会话消息虚拟化流式呈现，到输入框协同的完整生命周期。其核心拓扑结构如下：

```

 ├── ChatHeader (顶部标题栏、搜索切换、右坞工具展开)
 │    ├── ChatMsgFilterBar (本地消息关键词过滤输入框)
 │    └── UnitChromeActions (总览/文件/差异/终端入口 + 右坞切换)
 ├── chatDocFlow (.chatDocFlow 滚动流包裹层)
 │    ├── [mainSurface === 'scheduled'] -> ScheduledTasksPanel (定时任务主面板)
 │    ├── [emptyKind != null] -> ChatEmptyState (三态空态欢迎引导)
 │    │    ├── EmptyIcon (三态专属矢量图标)
 │    │    ├── ProjectPickerMenu (内联项目切换下拉菜单)
 │    │    └── QuickPromptCard (快捷提示词触发卡片)
 │    └── [else] -> ChatMessageList (消息流主列表)
 │         ├── useChatMessageState (消息引脚、状态派生与工具堆栈属性)

 │              └── StreamingAssistantRow (流式 Assistant 消息热装配行)
 └── ChatComposerWrapper (.chatFooter 页脚容器)
      ├── ChatStatusRibbons (散装状态横幅集合)
      │    ├── dynamicChipBar (后台任务/计划进度/文件变更 Chip 栏)
      │    ├── dynamicPlanDrawer (展开的计划详情清单)
      │    ├── SetupHintBanner (密钥/模型/引擎连接软提示)

      │    └── ApprovalDock (待审批工具调用 Sticky 条)
      └── ChatComposer (主输入框与模型/权限选择器)
```

### 2.4 项目选择器悬停延迟与 Popover 焦点陷阱

`ProjectPickerMenu.tsx` 采用了 hover 自动触发与定时延迟关闭机制：

```tsx
// apps/crish-desktop/src/components/chat-card/ChatEmptyState.tsx:41-43, 149-174
const PROJECT_PICKER_CLOSE_DELAY_MS = 400;

const scheduleProjectPickerClose = useCallback(() => {
  if (!onShowProjectPicker) return;
  cancelProjectPickerClose();
  projectPickerCloseTimerRef.current = setTimeout(() => {
    onShowProjectPicker(false);
    projectPickerCloseTimerRef.current = null;
  }, PROJECT_PICKER_CLOSE_DELAY_MS);
}, [onShowProjectPicker, cancelProjectPickerClose]);
```

#### 关键缺陷分析：

1. **鼠标快速移动时的闪烁与误关**：用户鼠标从大标题上的项目按钮移动到下方 Popover 菜单的过程中，若经过中间的 6px `sideOffset` 间隙，很容易因为 400ms 定时器未被及时取消或因 React 状态重渲染导致定时器失效，使下拉菜单在鼠标即将移入时突然闪退。
2. **键盘导航与 Tab 焦点捕获断裂**：通过 Hover 展开的 `Menu` 在键盘无障碍体系中无法正确管理 `aria-activedescendant` 与焦点陷阱，使得键盘用户在按 Tab 键时直接跳过了项目菜单中的选项。

## 4. 消息虚拟列表 (MessageVirtualizer) 滚动与动态高度深度审查

### 4.1 逻辑窗口截断与虚拟滚动的双重嵌套断层 (Double Windowing)

在 `ChatMessageList.tsx:236-249` 与 `MessageVirtualizer.tsx:66-71` 中，存在严重的双重窗口截断：

```tsx

```

```tsx

  () => visibleMessages.map((m) => m.id),
  [visibleMessages]

  ids: visibleMsgIds,
  itemCount: visibleMessages.length,
  overscan: 6,
  fallbackHeight: MESSAGE_ESTIMATED_ROW_HEIGHT,
```

#### 关键缺陷分析：

1. **架构职责严重重叠**：
   - 第一层：`ChatMessageList` 使用 `windowMessages` 进行业务逻辑截断，默认只切片最后 20 条消息，并在顶部渲染「显示更早的 X 条」按钮；
   - 第二层：`MessageVirtualizer` 在已截断的 `visibleMessages` 基础之上，再次引入 `useVirtualScroll` 虚拟滚动引擎（overscan: 6）。
2. **虚拟滚动的性能红利被逻辑窗口抵消**：
   虚拟滚动本身的数学意义在于**无上限地容纳成千上万条 DOM 数据而保持恒定内存**。然而 Crish 却在虚拟滚动之上强加了一层分页式点击「显示更早」的逻辑窗口。
3. **窗口展开导致虚拟滚动状态重置与高度缓存断裂**：
   当用户点击「显示更早」时，`expandedOlder` 改变引起 `visibleMessages` 数组首部追加新元素，导致 `vs.syncOrder(ids)` 发生全量重排。虽然 `VirtualScrollManager` 基于 `messageId` 保留了旧消息的高度，但新插入消息在首部的估算高度（`fallbackHeight: 120px`）会导致整个列表的 `startOffset` 与 `totalHeight` 发生剧烈重算，引发滚动条瞬时跳动。

### 4.2 双重滚动监听与 RAF 帧滞后冲突

在滚动控制链路上，同时存在两个独立的 Hook 在操纵 DOM 滚动：

1. `useChatAutoScroll.ts`（通过 `ChatCard -> ChatScrollAnchor` 引入）：
   ```typescript
   // apps/crish-desktop/src/hooks/useChatAutoScroll.ts:35-74

     const el = resolveScrollEl(chatFlowRef.current);

       }
     }
   });
   ```
2. `useVirtualScroll.ts`（在 `MessageVirtualizer` 内部）：
   ```typescript
   // apps/crish-desktop/src/hooks/useVirtualScroll.ts:121-129

     latestScrollTopRef.current = e.currentTarget.scrollTop;
     if (rafRef.current == null) {
       rafRef.current = requestAnimationFrame(() => {
         rafRef.current = null;
         setScrollTop(latestScrollTopRef.current);
       });
     }
   }, []);
   ```

#### 关键缺陷分析：

- **两个并发 rAF 之间的状态竞态**：
  当流式消息产生新 Token 时，`useChatAutoScroll` 在其自己的 rAF 中直接突变 `el.scrollTop`；此时原生 DOM 派发 `scroll` 事件，触发 `useVirtualScroll` 的 `onScroll` 回调，将其放入**另一个独立的 rAF** 中执行 `setScrollTop`。
- **虚拟滚动视口计算滞后 1 帧**：
  由于 `setScrollTop` 滞后，React 在渲染 `visibleRange` 时所使用的 `scrollTop` 是上一帧的旧值，导致底部正在生成的消息行有时在 1 帧的时间窗口内被虚拟滚动判定为「超出视口下方」而未挂载，下一帧又被重新挂载，产生流式输出过程中的**肉眼可见的闪烁与抽搐**。

### 4.3 动态高度频繁更新引发 O(N) 偏移缓存重建

审查 `VirtualScrollManager.ts:156-181` 与 `359-383`：

```typescript
// apps/crish-desktop/src/api/VirtualScrollManager.ts:156-181
setActual(id: string, height: number, callerGeneration?: number): boolean {
  if (callerGeneration !== undefined && callerGeneration !== this.generation) return false;
  if (!id || !Number.isFinite(height) || height <= 0) return false;
  const safeHeight = height;
  const entry = this.heightsById.get(id);
  if (entry) {
    if (entry.actual === safeHeight && entry.estimated === safeHeight) {
      return false;
    }
    entry.actual = safeHeight;
    entry.estimated = safeHeight;
  } else {
    this.heightsById.set(id, { estimated: safeHeight, actual: safeHeight });
  }
  this.markDirty(); // 清空 offsetsCache
  return true;
}

// apps/crish-desktop/src/api/VirtualScrollManager.ts:374-383
private rebuildOffsets(upTo: number): void {
  const len = Math.max(upTo, this.order.length + 1);
  const cache = new Array<number>(len);
  cache[0] = 0;
  for (let i = 1; i < len; i++) {
    cache[i] = cache[i - 1]! + this.getHeightAt(i - 1);
  }
  this.offsetsCache = cache;
  this.dirty = false;
}
```

#### 关键缺陷分析：

- 在 Assistant 回复流式输出期间，随着文本不断增加、代码块高亮渲染、工具调用状态变更，`ResizeObserver` 会以每秒 30~60 次的高频触发 `setActual`；
- 每次 `setActual` 都会执行 `this.markDirty()` 将 `offsetsCache` 置为 `null`；
- 在随后的 `computeVisibleRange` 中，必须执行完整的 `for (let i = 1; i < len; i++)` 线性扫描以重建前缀和数组（Prefix Sum Array），时间复杂度为 $O(N)$；
- 频繁的数组分配与垃圾回收在高负载、长会话（数百条消息）时造成明显的主线程卡顿（Jank）。

### 4.4 流式吸附锁与高度收缩阈值误判

在 `VirtualScrollManager.ts:63-66` 中定义了：

```typescript
export class VirtualScrollManager {
  /** 全局流式吸附锁：在 Run 处于 processing 期间强制吸底，免疫历史折叠坍塌 */
  private stickToBottomLock = false;
  ...
```

然而在实际的自动滚动实现 `useChatAutoScroll.ts:49-65` 中：

```typescript
// apps/crish-desktop/src/hooks/useChatAutoScroll.ts:49-65

  if (isProcessing && prevHeight > 0) {
    const dh = scrollHeight - prevHeight;
    if (dh > 0) {
      el.scrollTop = Math.min(el.scrollTop + dh, scrollHeight);
    } else if (dh < 0) {
      // F7-F17：内容收缩时若贴底则重新吸附
      const atBottom = scrollHeight - el.scrollTop - el.clientHeight < 60;
      if (atBottom) {
        el.scrollTop = Math.max(0, scrollHeight - el.clientHeight);
      }
    }
  } else {
    el.scrollTop = scrollHeight;
  }
  setShowScrollToBottom(false);
}
```

#### 关键缺陷分析：

1. **吸附锁未真正介入主滚动判定**：
   `VirtualScrollManager` 中的 `stickToBottomLock` 完全是一个未与 `useChatAutoScroll` 联通的孤立属性；
2. **高度骤降引发的误解离锁 (Unlock)**：
   当 AI 在流式输出过程中生成了一个思考折叠框（Thought Block）或工具调用完成收起时，`scrollHeight` 会突然暴降（例如 -200px）。由于 `handleScroll` 监听器只使用了简单的 `scrollHeight - scrollTop - clientHeight < 60` 阈值，在高度瞬间坍塌的那一帧，`scrollTop` 尚未被调整，计算结果骤然大于 60px，导致 `userScrolledRef.current` 被**错误地置为 `true`**。系统误以为「用户主动向上滚动了」，从而彻底断开了流式自动吸底，用户被莫名卡在半空中。

### 5.2 一体化状态通知中心 (Unified Notification & Status Hub)

#### 5.2.1 状态分级收敛模型

将十余种散装横幅统一收敛为具有优先级仲裁的状态流水线：

```
      ↓
[Informational 信息级] -> 后台任务运行 Chip / 文件变更 Chip / 系统提示 (RunNotice)
```

#### 5.2.2 一体化通知栏结构与解耦浮动 FAB

1. **状态栏高度自适应与单行折叠**：
   状态栏默认最多展示 **1 条高优先级横幅** + **单行动态 Chip 栏**，多条通知通过折叠徽标或轮播查看，严禁在垂直方向无底线堆叠；
2. **FAB 挂载位置归位**：
   将 `chatScrollFab` 从 `ChatStatusRibbons` 与 `ChatComposerWrapper` 中解耦，移入 `ChatMessageList` / `MessageVirtualizer` 视口内部，使用绝对定位贴合消息容器底部边缘（`bottom: 24px; right: 24px;`），彻底消除与输入框高度的耦合。

### 5.3 丝滑高性能流式消息虚拟列表体系 (Virtualizer 2.0)

#### 5.3.1 架构改进要点

1. **消除双重截断，统一采用纯虚拟滚动**：
   移除 `windowMessages` 中的 20 条硬编码切片逻辑，将全量 `messages` 直接交给 `VirtualScrollManager` 管理；
2. **差量分段前缀和（Fenwick Tree / Blocked Prefix Sum）**：
   将 `VirtualScrollManager` 的 O(N) 线性重建重构为分段块结构（Chunk Size = 32）。单行高度变化时，仅更新局部块，前缀和更新从 $O(N)$ 降至 $O(\sqrt{N})$ 或 $O(\log N)$；
3. **统一原生滚动控制器与锁底状态机**：
   将 `useChatAutoScroll` 合并进 `useVirtualScroll`，由同一个滚动控制器统一接管 `scrollTop`、流式吸底锁与用户主动滚动打断逻辑。

```mermaid

    A[Engine Stream Token] --> B[StreamingAssistantRow]

    C -->|局部分块更新 O(log N)| D[Offset Tree / Binary Search]
    D -->|RAF Coalesced Tick| E[VirtualScrollState]
    E --> F[Visible Window Slice]

    G[User Wheel Scroll] -->|Scroll Interceptor| H{Is at bottom threshold?}
    H -->|Yes & Stream Processing| I[StickToBottomLock: True -> Force Scroll to End]
    H -->|No| J[StickToBottomLock: False -> Show ScrollFab]
```
