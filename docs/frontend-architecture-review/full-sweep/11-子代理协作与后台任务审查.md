### 2.2 核心缺陷与代码证据

#### 缺陷一：虚假进度条与硬编码百分比（Fake Progress Illusion）

- **代码位置**：[`apps/crish-desktop/src/components/agent-card/AgentTeamBoard.tsx:217-226`](file:///c:/Software/conex/apps/crish-desktop/src/components/agent-card/AgentTeamBoard.tsx#L217-L226)
- **代码实现**：
  ```typescript
  function progressPercent(
    agent: SessionAgent,
    prog: ReturnType<typeof toolProgress>
  ): number {
    if (prog.total > 0) return Math.round((prog.done / prog.total) * 100);
    if (agent.status === 'completed') return 100;
    if (agent.status === 'running') return 35; // ❌ 硬编码 35%
    if (agent.status === 'failed') return 100;
    return 0;
  }
  ```
- **问题分析**：
  当子 Agent 处于 `running` 状态且尚未派发任何工具调用时，进度条硬编码直接展示为 `35%`。
  而在 [`AgentCard.module.css:496-524`](file:///c:/Software/conex/apps/crish-desktop/src/components/agent-card/AgentCard.module.css#L496-L524) 中，该进度条高度仅为 `1.5px`（`.agentTeamCardBar`），与下方文本外边距为 `0`。此设计不仅在视觉上极其微弱且容易黏连，更关键的是给用户提供了**虚假的进度确定性**（一个刚启动甚至阻塞的 Agent 凭空显示已完成 35%）。

#### 缺陷二：扁平列表排版与 Multi-Agent 拓扑关系缺失

- **代码位置**：[`apps/crish-desktop/src/components/agent-card/AgentTeamBoard.tsx:242-261`](file:///c:/Software/conex/apps/crish-desktop/src/components/agent-card/AgentTeamBoard.tsx#L242-L261)

### 3.3 核心缺陷与安全隐患代码证据

#### 缺陷一：二次确认中「记住意图（Remember Intent）」串扰漏洞

- **代码位置**：[`apps/crish-desktop/src/components/agent-card/ApprovalAskCard.tsx:184-198`](file:///c:/Software/conex/apps/crish-desktop/src/components/agent-card/ApprovalAskCard.tsx#L184-L198), [`ApprovalActions.tsx:48-66`](file:///c:/Software/conex/apps/crish-desktop/src/components/agent-card/ApprovalActions.tsx#L48-L66)
- **代码实现**：
  ```typescript
  // ApprovalAskCard.tsx
  const fireAllow = useCallback(
    (remember: boolean) => {
      if (busy) return;
      const phase = nextAllowConfirmPhase(needsDouble, confirmArmed);
      if (phase === 'armed') {
        setConfirmArmed(true);
        setRememberIntent(remember); // ⚠️ 记录了 remember 意图
        return;
      }
      const doRemember = remember || rememberIntent; // ⚠️ 只要历史有 intent 或当前传入为 true 即生效
      setConfirmArmed(false);
      setRememberIntent(false);
      if (doRemember) onAllowRemember(note);
      else onAllow(note);
    },
    [
      busy,
      needsDouble,
      confirmArmed,
      rememberIntent,
      onAllowRemember,
      onAllow,
      note,
    ]
  );
  ```
- **交互漏洞剖析**：
  1. 场景：高风险命令需要二次确认（`needsDouble === true`）。
  2. 第一步：用户误点击了「记住并准备允许」（此时 `setConfirmArmed(true)` 且 `setRememberIntent(true)`）。
  3. 第二步：用户意识到不应记住白名单，因此在二次确认时点击了主「再次确认允许」按钮（该按钮传入 `remember = false`）或者直接按下了键盘 `Enter` 快捷键。
  4. 结果：由于 `const doRemember = remember || rememberIntent` 采用了逻辑或运算，虽然用户第二次明确选择了普通允许，系统仍然执行了 `onAllowRemember(note)`，将该命令永久加入了白名单！
  5. **危害等级**：高。违反最小权限原则，导致非预期的权限提升。

#### 缺陷二：审批卡片纵向膨胀严重，信息层级过载

- **代码位置**：[`apps/crish-desktop/src/components/agent-card/ApprovalAskCard.tsx:276-385`](file:///c:/Software/conex/apps/crish-desktop/src/components/agent-card/ApprovalAskCard.tsx#L276-L385), [`ApprovalAskCard.module.css:1-14`](file:///c:/Software/conex/apps/crish-desktop/src/components/agent-card/ApprovalAskCard.module.css#L1-L14)
- **问题分析**：
  审批卡片内一次性平铺了 10 个功能块：
  1. 顶部 Badge
  2. Question 标题
  3. Summary 摘要
  4. RiskReason 详细原因
  5. 风险标签 Chips
  6. 完整 Command 预格式化代码块
  7. Revert / Delete 影响面多文件清单
  8. 快照建议 / 武装告警
  9. 补充说明 Textarea（自带 2 行高 + 计数器）
  10. 4 个操作按钮 + 倒计时进度条
      整个卡片在默认状态下的垂直高度达 `350px ~ 480px`。在主流分辨率下，该卡片一旦弹出，会瞬间将主对话历史全部挤出可视区域，用户无法在卡片内同时对照上下文代码做出审批决策，缺乏**渐进式折叠（Progressive Disclosure）**设计。

#### 缺陷三：单条主时间线内联 vs 底部 Dock 的可见性盲区

- **代码位置**：[`apps/crish-desktop/src/api/chatApprovalUi.ts:122-160`](file:///c:/Software/conex/apps/crish-desktop/src/api/chatApprovalUi.ts#L122-L160)
- **代码实现**：
  ```typescript
  export function approvalRenderMode(
    c: ApprovalPendingCounts
  ): ApprovalRenderMode {
    const { mainCount, agentCount } = clampApprovalCounts(c);
    if (mainCount + agentCount <= 0) return 'none';
    // 单条且已在主时间线 → 只靠内联卡（dock 再出现 = 双渲染）
  ```

### 4.3 架构断层根因分析

这一断层的产生源于典型的「特性开发阶段脱节」：

- 在 `T-AB-20` 迭代中，开发者严谨地编写了 `bgTaskCardLib.ts`、`BgTaskActions.tsx`、`BgTaskCard.tsx` 及其配套的 3 组完整单测。
- 但在 `RuntimePanel` 与 `OverviewCard` 的装配阶段，负责容器组装的代码直接使用了早期的占位组件 `BgTasksSection`（仅调用 `openBackgroundTaskInTerminal`），遗漏了将成熟的 `BgTaskCard` 接入列表。
- 造成大量高质量的交互逻辑（内联交互、stdin 预填、日志展开、kill 防护）沦为**未接线的死代码**。

## 5. 商业级 Multi-Agent 交互与审批重构方案

为对标成熟商业级 AI 编程平台（如 Cursor Composer 协同流、Windsurf Cascade、Claude Code 交互审批、Devin 任务拓扑图），提出以下系统化重构方案：

### 5.1 Multi-Agent 协作流与拓扑可视化重构 (AgentFlow & DAG)

```
┌────────────────────────────────────────────────────────────────────────┐
│                   Multi-Agent 协同工作流 (AgentFlow)                    │
├────────────────────────────────────────────────────────────────────────┤
│  [主控 Agent] ──┬──► (探索/只读) 01-SearchEngine   [● 成功 · 2.1s · 4 tools]  │
│                 ├──► (方案/设计) 02-ArchPlan       [● 成功 · 5.4s · 2 tools]  │
│                 └──► (代码实现) 03-FrontendImpl   [◌ 运行中 · 12s · 执行中]  │
│                                │                                       │
│                                └──► 实时产出流: components/NewCard.tsx  │
├────────────────────────────────────────────────────────────────────────┤
│ 状态看板: 3 并行 / 2 完成 / 1 运行中       [全部停止] [一键汇流产出]     │
└────────────────────────────────────────────────────────────────────────┘
```

1. **废弃假百分比，采用真实活动流指标**：
   - 彻底删除 `progressPercent` 中的 `status === 'running' ? 35 : 0` 硬编码。
   - 替换为：**「活动脉冲 (Activity Pulse) + 当前工具名 + 运行用时 + 实时产出 Token/行数」**。
2. **引入轻量级 DAG / 泳道拓扑结构**：
   - 在 `AgentTeamBoard` 中增加模式切换：`List View`（紧凑列表）与 `Flow View`（依赖泳道拓扑）。
   - 依据 Agent 的 `mode` 或命名契约（如 `survey` / `analysis` / `execution` / `audit`）自动归类到不同执行阶段，清晰呈现多 Agent 并行与汇流关系。
3. **收敛双端交互，消除认知冲突**：
   - 明确主对话时间线 `InlineAgentPanel` 为「进度只读与快速审批」窗口；侧栏 `AgentCard` 为「深度交互与调试」窗口。
   - 当侧栏打开某 Agent 时，主时间线的内联面板收缩为紧凑的状态条，并提供「侧栏已激活」的直接聚焦跳转，不再在两端同时渲染全量 `ComposerField`。

---

### 5.2 渐进式轻量化审批卡片重构 (Progressive Compact Approval)

```
┌────────────────────────────────────────────────────────────────────────┐
│ [🛡️ 需确认] 执行高危命令: `rm -rf /dist/temp`       [拒绝]  [允许 (Enter)] │
│ ────────────────────────────────────────────────────────────────────── │
│ ▾ 展开影响面与安全选项 (包含 12 个文件 · 信任域: 本地工作区)             │
│   ┌──────────────────────────────────────────────────────────────────┐ │
│   │ [x] 记住该命令前缀 (加入白名单)                                    │ │
│   │ 补充说明: [                                              ]       │ │
│   └──────────────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

1. **2 行式默认紧凑态（Compact Default）**：
   - 默认仅展示：风险图标 + 操作摘要 + 关键参数代码行 + 「拒绝」与「允许」两个核心按钮。
   - 将补充说明 Textarea、详细原因、Delete/Revert 详细文件列表全部收入「▾ 展开详情」折叠区中，将默认卡片高度从 `400px` 压缩至 `64px`，完全不打断对话阅读。
2. **根除二次确认白名单串扰**：
   - 将「单次允许」与「记住白名单」解耦为两个独立的状态维度：
     - 主「允许」按钮仅根据当前上下文执行单次放行。
     - 「记住并加入白名单」设计为独立的 Checkbox 或明确的二级确认操作，二次确认时严禁自动回退读取历史 `rememberIntent`，彻底消除权限提升漏洞。
3. **全局审批悬浮状态条（Floating Approval Ribbon）**：
   - 无论用户滚动到主对话的任何位置，只要存在待审批项，均在底栏 Composer 上方渲染一条仅高 `28px` 的悬浮气泡（`1 项工具等待审批 · 点击跳转`），彻底解决 `inline-only` 模式下的可见性盲区。

### 5.3 后台任务体系接线闭环与终端联动 (Unified BgTasks)

1. **废弃旧版 `BgTasksSection`，全面接线 `BgTaskCard`**：
   - 在 `apps/crish-desktop/src/components/workspace/RuntimePanel.tsx` 中，直接使用 `BgTaskCard` 替换老旧的平铺行。
   - 接入现成的 `BgTaskActions`，直接赋予用户在侧栏对后台任务进行 `终止 (kill)`、`输入响应 (send_input)`、`查看最近 20 行日志 (logTail)` 的全部能力。
2. **智能 Prompt 交互拦截**：
   - 利用 `bgTaskCardLib.ts` 的 `recommendPromptAnswer`，当检测到命令卡在 `[y/N]` 或安装确认提示时，直接在卡片上弹出快捷建议按钮（如 `[点击发送 'y']`），大幅提升自动化 CLI 交互体验。
