## 一、执行概要与核心问题拓扑

当前 Conex / Crish 桌面端消息流（Chat Message Stream）承担着多步骤交错思考链（Interleaved Thinking）、复杂工具调用栈（Tool Stack）、增量流式 Markdown 文本以及消息操作元数据的实时渲染任务。在完成了底层 O(1) 增量 DOM 直写与虚拟滚动优化后，**视觉呈现层与排版样式层暴露出大量“拼凑感强”、“对比度失调”、“样式粗糙”、“组件视觉嵌套过重”的典型缺陷**。

### 核心视觉病灶一览：

```
[消息流排版四大失调区域]
 ├── 1. 工具调用展开区 (ToolCallOutput / InputPane / OutputPane)
 │     ├── 22px 魔术左边距 + 双层 Nested Cards 结构
 │     ├── Emoji 硬编码 (📥/📤/⏳/✕/✓) 破坏专业工程质感
 │     ├── 无语法高亮的原始 <pre> 代码块 + 刺眼的纯白/纯黑混合
 │     └── 伪高度 CSS 动画 (max-height: 2000px) + 20 余处 !important 补丁
 │
 ├── 2. 消息底部工具栏与缓存条 (MessageActionsBar / CacheMetricsBadge)
 │     ├── 22px 按钮与 11px 徽标挤在单行，高度参差不齐
 │     ├── 必须 Hover 才能显示关键元数据与操作，触屏/无鼠标场景断层
 │     ├── 亮绿/亮蓝高饱和度大药丸 Badge，文字超 30 字符抢占主视觉
 │     └── 「未命中」显式灰色标签给用户传递误导性负面暗示
 │
 ├── 3. 思考链折叠区 (TimelineThoughtSection)
 │     ├── 独立灰盒子与外围 Border 切割助手文档流
 │     ├── 实时流 pulse-live 呼吸缩放产生视觉躁动
 │     ├── 0fr->1fr Grid 动画嵌套 320px 内部滚动条，造成滚轮劫持
 │     └── 截断渐变硬编码 #0f172a，在非纯黑主题下呈现脏黑块
 │
 └── 4. 建议胶囊与批准卡片 (FollowUpSuggestions / PlanApproval)
       └── 冗余边框、多重嵌套 Button、占据大面积纵向高度
```

## 二、工具调用 (Tool Call) 展开排版与垃圾样式深度剖析

### 2.1 多层卡片嵌套（Nested Cards）与背景色暗黑主题失真

在 `apps/crish-desktop/src/components/chat-tool-call/` 中，工具调用展开区域存在严重的“盒中盒（Nested Cards）”结构与背景色计算失真问题。

#### 代码定位：

- `apps/crish-desktop/src/components/chat-tool-call/ChatToolCallBlock.module.css:334-366`
- `apps/crish-desktop/src/components/chat-tool-call/ToolCallOutput.tsx:93-123`

```css
/* apps/crish-desktop/src/components/chat-tool-call/ChatToolCallBlock.module.css:334-366 */
.toolResultBody {
  display: flex;
  flex-direction: column;
  gap: var(--space-2, 8px);
  padding: 8px 10px 10px 10px;
  background: var(--bg-surface-subtle, hsl(0 0% 0% / 0.02));
  border-radius: var(--radius-xl, 10px);
  border: 1px solid
    color-mix(
      in srgb,
      var(--border-color, var(--border-subtle)) 92%,
      var(--text-primary) 8%
    );
  margin: 4px 0 6px 22px; /* ⚠️ 22px 魔术左边距 */
  box-sizing: border-box;
  overflow: hidden;
  position: relative;
}

/* 子级卡片：输入栏与输出栏 */
.toolSection {
  display: flex;
  flex-direction: column;
  background: var(--bg-surface, hsl(0 0% 100% / 0.8)); /* ⚠️ 致命的白透明度 */
  border-radius: var(--radius-lg, 8px);
  border: 1px solid var(--border-subtle, hsl(0 0% 0% / 0.05));
  overflow: hidden;
}
```

#### 严重缺陷分析：

1. **暗黑主题下背景色爆炸**：
   `.toolSection` 的背景直接使用了回退值 `hsl(0 0% 100% / 0.8)`（80% 不透明度白色）。当系统处于暗色主题（Dark Mode）且 `--bg-surface` 未能正确覆盖时，展开的输入输出面板会直接呈现为一个白花花的强光大色块，彻底刺瞎用户眼睛。
2. **三层边框与背景叠加**：
   最外层 `toolRow`（`ChatToolCallBlock.module.css:21`）包着 `toolResultBody`（带 1px 边框和背景），`toolResultBody` 内部又包含了两个 `toolSection`（各自带 1px 边框和背景），而 `toolSection` 内部在渲染键值对时又有一层 `.toolValPre`（`ChatToolCallBlock.module.css:528`，带独立背景与圆角）。这违背了《反过度设计硬性红线》与《Forbidden Cliché Design Tropes》中“禁止 3 层以上嵌套卡片”的铁律。
3. **22px 魔术边距破坏栅格对齐**：
   `margin: 4px 0 6px 22px;` 试图通过硬编码 22px 与头部图标左侧对齐，但在窄屏（如分屏或侧边栏模式）下，导致可用宽度骤降，内容产生不自然的横向挤压。

#### 严重缺陷分析：

1. **Emoji 跨平台渲染极度不一致**：

2. **与整体 Lucide 矢量图标体系冲突**：
   应用顶栏和侧栏统一使用 `lucide-react`（如 `CheckCircle2`, `XCircle`, `Terminal`, `FileCode`），而此处在 Header 内部却硬编码 Emoji，形成了明显的视觉撕裂。

### 2.3 纯文本 `<pre>` 裸奔与代码高亮缺失

### 2.5 `max-height: 2000px` 伪动画与 `!important` 样式污染

在动画和样式覆盖方面，该模块充斥着大量脆弱的 hack 代码。

#### 代码定位：

- `apps/crish-desktop/src/components/chat-tool-call/ChatToolCallBlock.module.css:22, 28, 54, 62, 77, 188-201, 435-445`

```css
/* 伪高度展开动画 */
.toolBody {
  max-height: 0;
  overflow: hidden;
  opacity: 0;
  transition:
    max-height 220ms cubic-bezier(0.16, 1, 0.3, 1),
    opacity 150ms ease;
}

.toolBody.expanded {
  max-height: 2000px; /* ⚠️ 经典反模式：伪高度导致短内容瞬间弹开、超长内容展开不全 */
  opacity: 1;
}

/* 滥用 !important 压制特异性 */
.toolRow {
  border: none !important;
  box-shadow: none !important;
}
.toolRowHead {
  border: none !important;
  box-shadow: none !important;
}
.toolSectionActionBtn {
  height: 20px !important;
  padding: 0 6px !important;
  font-size: 11px !important;
  border-radius: var(--radius-md, 6px) !important;
  color: var(--text-tertiary) !important;
}
```

#### 严重缺陷分析：

- **`max-height: 2000px` 导致动效失真**：当展开内容只有 40px 高度时，由于 220ms 内要走完 2000px 的插值，前 4.4ms 就完成了 40px 的展开，用户感知到的就是生硬的“瞬开”无过渡；而当内容超过 2000px 时，内容直接被裁断。
- **20+ 处 `!important` 污染**：表明 CSS 类名特异性管理彻底失控，组件内部必须用 `!important` 强行覆盖基础 UI 库样式，极易在后续重构中引发样式覆盖灾难。
