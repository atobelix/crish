### 1. 缩进算法过窄与纵向层级线（Guide Lines）缺失

- **精确代码位置**：[`FileTreeView.tsx:252`](file:///c:/Software/conex/apps/crish-desktop/src/components/files/FileTreeView.tsx#L252)
  ```tsx
  style={{
    position: 'absolute',
    top: `${top}px`,
    left: 0,
    width: '100%',
    height: `${ITEM_HEIGHT}px`,
    paddingLeft: 4 + e.depth * 10,
    display: 'flex',
    alignItems: 'center',
  }}
  ```
- **排版问题分析**：
  1. **10px 缩进阶梯过窄**：现代 IDE（VSCode、IntelliJ、Sublime）默认单级缩进为 `16px`（或最低 `12px ~ 14px`）。当前每增加一级目录仅偏移 `10px`，当项目嵌套至 4~5 层深时（如 `apps/crish-desktop/src/components/files/hooks`），深层文件与浅层文件在视觉上几乎贴在一起，层级归属极难分辨。
  2. **完全缺失缩进引导线（Indent Guides）**：由于采用虚拟滚动绝对定位渲染（每行都是独立绝对定位块），行与行之间没有父子 DOM 容器包裹，且没有绘制纵向的引导辅助线（CSS 伪元素或点阵背景线）。在长列表展开多个深层目录时，用户极易产生视线迷失。

### 2. 绕过标准 `ui/Menu` 导致的六大体验割裂与缺陷

#### (1) 全局事件脱管与 LayerRegistration 体系失效

- **缺陷分析**：
  项目在 [`src/components/ui/internal/layer-registration/`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/internal/layer-registration/) 中建立了全局统一的弹出层管理器（`useLayerRegistration`），用于管理 Dropdown、Dialog、Tooltip、ContextMenu 的层级栈与 Esc 按键分发。
  然而在 [`FileBreadcrumb.tsx:148-168`](file:///c:/Software/conex/apps/crish-desktop/src/components/files/FileBreadcrumb.tsx#L148-L168) 中：
  ```tsx
  useEffect(() => {
    if (!bcFlyout) return;
    const onDoc = (e: MouseEvent) => {
      const t = e.target as Node;
      if (crumbsRef.current?.contains(t)) return;
      setBcFlyout(null);
      requestAnimationFrame(() => bcTriggerRef.current?.focus());
    };
    const onKey = (e: KeyboardEvent) => {
      if (e.key === 'Escape') {
        setBcFlyout(null);
        requestAnimationFrame(() => bcTriggerRef.current?.focus());
      }
    };
    document.addEventListener('mousedown', onDoc);
    window.addEventListener('keydown', onKey);
    return () => {
      document.removeEventListener('mousedown', onDoc);
      window.removeEventListener('keydown', onKey);
    };
  }, [bcFlyout]);
  ```
  直接在 `document` 上监听 `mousedown` 与 `keydown`。当用户在打开面包屑浮层的同时点击了侧边栏菜单或触发了系统 Dialog 时，原生事件监听与 Radix Popover 的 PointerDown 拦截产生竞态，浮层可能无法正常注销，甚至导致多层菜单同时驻留在屏幕上。

#### (2) 视口边界碰撞检测与裁切缺失（Clipping Defect）

- **缺陷分析**：
  在 [`FilesCard.module.css:328-343`](file:///c:/Software/conex/apps/crish-desktop/src/components/files/FilesCard.module.css#L328-L343) 中：
  ```css
  .filesBcFlyout {
    position: absolute;
    top: calc(100% + 6px);
    left: 0;
    z-index: var(--z-breadcrumb);
    width: min(320px, 70vw);
    max-height: min(52vh, 400px);
    ...
  }
  ```
  该浮层完全是挂载在面包屑父级 `<span>` 内部的 `position: absolute` 元素。
  - **无 Portal 穿透**：浮层未被传送至 `document.body`，直接受制于父级卡片 `.filesCard` 的 `overflow: hidden` 与 `container-type: inline-size`；
  - **无边界 Flip 翻转**：当面包屑靠近窗口右侧或底部时，浮层无法计算视口剩余空间，会直接超出可视区域右边界被截断，导致用户看不到右侧文件名与滚动条。

#### (3) ARIA 语义混乱与非法嵌套

- **缺陷分析**：
  - 触发器声明了 `aria-haspopup="listbox"`（[`FileBreadcrumb.tsx:215`](file:///c:/Software/conex/apps/crish-desktop/src/components/files/FileBreadcrumb.tsx#L215)）；
  - 浮层容器声明了 `role="listbox"`（[`FileBreadcrumb.tsx:235`](file:///c:/Software/conex/apps/crish-desktop/src/components/files/FileBreadcrumb.tsx#L235)）；
  - 但在 `role="listbox"` 容器内，第一项是一个包含 `<input type="search">` 的检索栏，最后一项是一个 `<Button>`（“打开此目录”），中间才是 `<button role="option">`！
  - **严重违背 WAI-ARIA 规范**：`role="listbox"` 的直接子节点只允许是 `role="option"` 或 `role="group"`。包含 input 和 action button 的混合面板必须使用 `role="dialog"` 或标准的 `role="menu"` 组合。

#### (4) 键盘漫游完全缺失

- **缺陷分析**：
  当浮层打开时，代码使用 `requestAnimationFrame` 将焦点强行置于搜索框（[`FileBreadcrumb.tsx:139`](file:///c:/Software/conex/apps/crish-desktop/src/components/files/FileBreadcrumb.tsx#L139)）。
  但用户在搜索框内按下 `ArrowDown` / `ArrowUp` / `Enter` 时：
  - **没有拦截上下方向键**，光标仅在 input 内移动；
  - **无法通过键盘将焦点移至下方文件列表项**；
  - **无法通过回车直接打开筛选后的第一个文件**；
  - 键盘用户必须按多次 `Tab` 键穿透，这与现代 IDE 面包屑（如 VSCode Breadcrumbs: `Cmd+Shift+.` 打开后直接上下键选中回车）的操作习惯完全背离。

#### (5) 散落多处的脆弱焦点操纵

- **缺陷分析**：
  在 [`FileBreadcrumb.tsx`](file:///c:/Software/conex/apps/crish-desktop/src/components/files/FileBreadcrumb.tsx) 中，共有 **7 处** 散落的 `requestAnimationFrame(() => bcTriggerRef.current?.focus())`（第 122, 142, 154, 159, 223, 253, 320 行）。
  由于 DOM 节点在异步渲染和状态切换期间可能会被重新挂载，这种手写的命令式焦点恢复极易遇到 `bcTriggerRef.current` 为 `null` 或失效的问题，而标准 `ui/Menu` 原生支持 Radix 的自动焦点恢复机制（`onCloseAutoFocus`）。

#### (6) 样式与设计 Token 不统一

- **缺陷分析**：
  浮层使用了手写的阴影 `box-shadow: var(--shadow-lg, 0 12px 28px rgba(0, 0, 0, 0.1))`，以及非标准的内边距和圆角定义，与全局标准 `Menu` 组件呈现出截然不同的视觉质感与动画曲线。

### 2. 行号槽（Gutter）硬编码与排版生硬

- **精确代码位置**：[`VirtualPlainCodeViewer.tsx:62, 64`](file:///c:/Software/conex/apps/crish-desktop/src/components/diff/VirtualPlainCodeViewer.tsx#L62-L64)、[`DiffCard.module.css:709-722`](file:///c:/Software/conex/apps/crish-desktop/src/components/diff/DiffCard.module.css#L709-L722)
  ```css
  /* DiffCard.module.css:709-722 */
  .gutterNum {
    display: flex;
    justify-content: flex-end;
    align-items: flex-start;
    padding: 2px 6px 2px 0;
    color: var(--text-tertiary);
    font-size: var(--font-size-xxs);
    user-select: none;
    opacity: 0.55;
    text-align: right;
    border-right: 1px solid var(--border-subtle);
    background: var(--md-code-bg);
  }
  ```
- **排版问题分析**：
  1. **45px 固定宽度缺乏动态自适应**：
     - 在大文件中（行数超过 9999 行），5 位数行号 `10000` 加上 `paddingRight: 8px` 会直接撑破 45px 容器，导致行号与代码重叠或被截断；
     - 在小文件（如只有 15 行的脚本）中，45px Gutter 又过宽，白白浪费水平空间。
     - **标准方案**：应根据总行数长度动态计算宽度：`Math.max(3, String(totalLines).length) * ch + padding`。
  2. **生硬的背景与竖线割裂感**：
     - 行号槽使用了 `background: var(--md-code-bg); border-right: 1px solid var(--border-subtle);`，在代码区域左侧强行切出一条深色垂直带。
     - 现代专业代码查看器（VSCode、GitHub Code View、JetBrains）均采用**一体化无缝背景**，行号仅通过柔和的次级文字颜色（`var(--text-tertiary)`，透明度约 40%~60%）自然区分，去除僵硬的竖直边框线，保持视线的开阔与流动。

### 3. 行内独立滚动条（`overflow-x: auto`）灾难

- **精确代码位置**：[`VirtualPlainCodeViewer.tsx:65`](file:///c:/Software/conex/apps/crish-desktop/src/components/diff/VirtualPlainCodeViewer.tsx#L65)

  - **严重体验缺陷**：当某一行代码较长（如复杂的 SQL、超长 JSON、嵌套解构）时，**该单行容器内部会独立出现一个横向滚动条**！如果代码中有 5 行超长，屏幕上就会错落出现 5 个独立的微型滚动条。

### 1. 面包屑导航重构：基于标准 `ui/Menu` 的极简实现

彻底废弃 `FileBreadcrumb.tsx` 中 100 多行的手写 Flyout 状态、`document` 事件监听与命令式 `requestAnimationFrame`，采用系统标准的 `Menu` 组件重塑：

```tsx
// 重构设计：FileBreadcrumb 使用标准 Menu 组件
import React, { useMemo, useState } from 'react';
import { Menu, Button, Tooltip } from '../ui';
import { ChevronRight, Folder, FolderOpen, FileCode2 } from 'lucide-react';
import { listDirectory, type FsDirEntry } from '../../api/workspaceFsApi';

export const RefactoredBreadcrumbItem: React.FC<{
  item: { label: string; path: string; isFile?: boolean };
  onNavigate: (path: string) => void;
  onOpenFile: (path: string) => void;
}> = ({ item, onNavigate, onOpenFile }) => {
  const [entries, setEntries] = useState<FsDirEntry[]>([]);
  const [loading, setLoading] = useState(false);
  const [searchQuery, setSearchQuery] = useState('');

  const handleOpenChange = async (open: boolean) => {
    if (open && entries.length === 0) {
      setLoading(true);
      try {
        const list = await listDirectory(item.path);
        setEntries(list);
      } finally {
        setLoading(false);
      }
    }
  };

  const filteredOptions = useMemo(() => {
    const q = searchQuery.trim().toLowerCase();
    const list = q
      ? entries.filter((e) => e.name.toLowerCase().includes(q))
      : entries;
    return list.map((ent) => ({
      id: ent.path,
      label: ent.name,
      icon: ent.isDir ? <Folder size={14} /> : <FileCode2 size={14} />,
      onClick: () => {
        if (ent.isDir) onNavigate(ent.path);
        else onOpenFile(ent.path);
      },
    }));
  }, [entries, searchQuery, onNavigate, onOpenFile]);

  if (item.isFile) {
    return <span className={styles.bcChipFile}>{item.label}</span>;
  }

  return (
    <Menu
      align="start"
      side="bottom"
      sideOffset={4}
      onOpenChange={handleOpenChange}
      trigger={
        <button type="button" className={styles.bcChip}>
          {item.label}
        </button>
      }
      options={filteredOptions}
    />
  );
};
```

- **重构收益**：
  1. **完全接入 LayerRegistration**：自动继承系统的 Esc 键分发栈与外部点击检测。
  2. **视口防碰撞**：Radix Popover 自动根据视口边缘翻转或平移（Flip/Shift），彻底消除裁剪与溢出问题。
  3. **WAI-ARIA 合规**：原生支持键盘上下方向键、Enter 选中与焦点自动恢复。

### 2. 文件树规范化重构：缩进标尺、状态图标与精致交互

3. **选区高亮与焦点环（Focus Ring）**：

   .filesRow {

### 3. 专业级代码阅读器（VirtualCodeViewer）升级设计

1. **高性能行级语法着色引擎**：
   - 利用 `codeHighlight.ts` / `highlight.js` 对行分词，或在 Web Worker / Rust syntect 线程中生成带类名的 Token 流；
   - 在虚拟滚动视口内，将高亮结果注入行内：
     ```tsx
     <div
       className={styles.lineText}
       dangerouslySetInnerHTML={{
         __html: highlightCode(l.content, lang),
       }}
     />
     ```
2. **自适应行号槽宽度（Dynamic Gutter Width）**：
   - 动态计算 Gutter 宽度：
     ```ts
     const gutterWidth = useMemo(() => {
       const digits = Math.max(3, String(totalLines).length);
       return digits * 8 + 16; // 动态字符宽度 + 内边距
     }, [totalLines]);
     ```
   - 统一背景色：行号槽与代码主体共用 `var(--bg-primary)`，仅行号字体采用 `var(--text-tertiary)`，移除生硬的垂直深色边框。
3. **统一全局横向滚动**：
   - 彻底移除单行 `.lineText` 上的 `overflow-x: auto`；
   - 由最外层 `scrollParent` 容器统一承载 `overflow-x: auto; overflow-y: auto;`，保持代码块整体排版的严格对齐与流畅滚动。
