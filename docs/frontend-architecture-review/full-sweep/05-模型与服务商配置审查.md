## 一、供应商级联展开面板 Hover 瘫痪根因解剖

在用户现场实测中，设置页面中的「全局默认模型」供应商与模型级联选择器（`ModelsCascadeSelect`）在鼠标 Hover 移向二级模型列表时出现**严重瘫痪、面板闪烁、无法展开或不可交互**的现象。通过对源码的逐行解剖，锁定了以下三大结构性断层：

### 1.1 代码事实定位

- **组件定义**：`apps/crish-desktop/src/components/settings-models/ModelProfileList.tsx:19-127`
- **外层浮层基座**：`apps/crish-desktop/src/components/ui/Menu/Menu.tsx:433-554`
- **基座样式约束**：`apps/crish-desktop/src/components/ui/Menu/Menu.module.css:5-28`
- **业务级联样式**：`apps/crish-desktop/src/components/settings-models/ModelsSettingsTab.module.css:984-1113`

```tsx
// apps/crish-desktop/src/components/settings-models/ModelProfileList.tsx:41-125
```

### 1.2 根因一：CSS BFC 容器裁剪陷阱（`overflow: hidden` / `overflow-y: auto` 物理截断）

1. `Menu.tsx:437-447` 渲染了 Radix Popover 内容容器 `<Popover.Content className={styles.menuContent}>`。
2. 查看 `apps/crish-desktop/src/components/ui/Menu/Menu.module.css:5-19`：
   ```css
   .menuContent {
     z-index: var(--z-dropdown-menu);
     max-height: min(var(--radix-popover-content-available-height, 360px), 70vh, 360px);
     overflow-y: auto;   /* 触发滚动上下文 */
     overflow-x: hidden; /* 强制水平裁剪！ */
     overscroll-behavior: contain;
     ...
   }
   ```
3. 查看 `apps/crish-desktop/src/components/settings-models/ModelsSettingsTab.module.css:1054-1065`：
   ```css
   .cascadeFlyout {
     position: absolute;
     right: calc(100% + 6px); /* 试图向左侧飞出 */
     top: 0;
     min-width: 180px;
     max-height: 280px;
     overflow-y: auto;
     z-index: var(--z-model-flyout);
     ...
   }
   ```
4. **致命事实**：`.cascadeFlyout` 作为 `.cascadeRow`（`position: relative`）的子节点，其包含块（Containing Block）处于 `.menuContent` 的滚动/裁剪视口内。`.menuContent` 显式声明了 `overflow-x: hidden` 与 `overflow-y: auto`。
5. 当 `.cascadeFlyout` 试图通过 `right: calc(100% + 6px)` 渲染到一级菜单左外侧时，**超出 `.menuContent` 边界的部分被浏览器排版引擎直接裁切（Clipped），在屏幕上完全不可见或被截断为宽度 0 的透明缝隙**。

### 1.3 根因二：鼠标移动轨迹缝隙与事件抖动坍塌（Hover Flapping）

1. 在 `ModelProfileList.tsx:61` 中，外层容器监听了 `onMouseLeave={() => setFlyProfileId(null)}`；在 `ModelProfileList.tsx:79` 中，每行监听了 `onMouseEnter={() => setFlyProfileId(p.id)}`。
2. `.cascadeFlyout` 的位置为 `right: calc(100% + 6px)`，与父级 `.cascadeRow` 之间存在 `6px` 的物理空隙。
3. 当用户的鼠标从 `.cascadeRow` 向二级菜单 `.cascadeFlyout` 移动时：
   - 鼠标一旦经过这 `6px` 的空白缝隙，立即触发了 `.cascadeList` 的 `onMouseLeave` 事件；
   - `setFlyProfileId(null)` 被同步调用，React 立即卸载（Unmount）`.cascadeFlyout` DOM 节点；
   - 用户鼠标刚到达二级菜单位置，目标节点已经销毁，导致二级菜单如同「幽灵」般闪烁消失，用户根本无法点击任何二级模型选项。

### 1.4 根因三：Radix Popover 事件拦截与 Z-Index / Portal 脱节

1. `ui/Menu` 组件（`Menu.tsx`）是基于 `@radix-ui/react-popover` 封装的一级浮层。Radix Popover 的 `Popover.Content` 拥有内部 PointerDown / OutsideClick 拦截逻辑，并在 `Menu.tsx:449-450` 拦截了 `onMouseDown` 与 `onPointerDown` 的冒泡。
2. 二级菜单 `.cascadeFlyout` 没有通过 Portal 独立挂载至根层，导致其不仅受制于一级容器的样式堆叠上下文（`isolation: isolate` 或 `z-index: var(--z-dropdown-menu)`），而且在键盘漫游体系中完全脱节（`Menu.tsx:196-302` 的键盘监听无法漫游至手写的 `.cascadeFlyout` 内部）。

## 三、7px 圆角暴力内联与 5 代历史样式堆叠混乱

### 3.1 7px 圆角与内联样式暴力覆盖实证

在 `apps/crish-desktop/src/components/settings-models/ProviderProfileForm.tsx:78-92`：

```tsx
// apps/crish-desktop/src/components/settings-models/ProviderProfileForm.tsx:78-92
<Button
  type="button"
  variant="secondary"
  size="sm"
  disabled={!keyDraft.trim()}
  onClick={() => void saveKey()}
  style={{
    borderRadius: '7px', // [反模式] 裸写 7px，暴力破坏 Design Tokens 统一规范
    height: '34px', // [反模式] 覆盖标准 control-height-sm (28px) / control-height (32px)
    padding: '0 14px',
    flexShrink: 0,

  保存

```

#### 审查定性：

1. **破坏设计系统**：标准设计规范使用 `var(--radius-sm)` (6px)、`var(--radius-md)` (7px)、`var(--radius-lg)` (9px)、`var(--radius-full)` (999px)。此处硬编码 `borderRadius: '7px'` 是典型的「视觉调试期随意打补丁」遗留物。
2. **尺寸失调**：`size="sm"` 的标准高度为 28px，输入框 `.mrdFieldInput` 的高度为 34px，开发者未通过 CSS 容器弹性对齐，而是使用内联 `style={{ height: '34px' }}` 强行拉伸按钮，导致与项目整体 Design Tokens 完全脱节。

在 `ProfileHeader.tsx:115-145`、`ModelListHeader.tsx:44-52, 72-80, 124-132`、`ModelList.tsx:154-160, 176-182` 中，同样充斥着大量内联 `style={{ height: '26px', borderRadius: '6px', ... }}` 的打补丁代码。

## 四、商业级模型配置重构落地方案

为彻底根治级联 Hover 瘫痪、预置服务商凭据死锁、样式冲突与死代码问题，提出以下商业级架构重构方案：

### 4.1 方案一：采用标准 Radix `DropdownMenu.Sub` 级联组件重构供应商/模型选择器

彻底废弃在 `Popover` 内部手动用 `div` + `position: absolute` + `onMouseEnter` 拼凑二级悬浮窗的做法，改用标准的 `@radix-ui/react-dropdown-menu` 级联体系：

```
┌────────────────────────────────────────────────────────┐
│ DropdownMenu.Root (受控/非受控双模)                     │
│  └─ DropdownMenu.Trigger                               │
│  └─ DropdownMenu.Portal                                │
│      └─ DropdownMenu.Content (一级：服务商列表)          │
│          ├─ DropdownMenu.Item (直选/快捷项)             │
│          └─ DropdownMenu.Sub (级联子菜单)               │
│              ├─ DropdownMenu.SubTrigger (服务商项)      │
│              └─ DropdownMenu.Portal                    │
│                  └─ DropdownMenu.SubContent (模型列表)  │
│                      └─ DropdownMenu.Item (具体模型)    │
└────────────────────────────────────────────────────────┘
```

#### 架构收益：

1. **原生 Safe Triangle（安全三角区算法）**：Radix SubContent 自动内置鼠标移动轨迹预测算法，当光标从 Trigger 斜向移动到 SubContent 时，不会因为离开 Trigger 边界而发生闪退。
2. **独立 Portal 逃逸**：SubContent 挂载于 `document.body` 独立的 Portal 容器中，彻底摆脱一级菜单 `overflow-x: hidden` / `overflow-y: auto` 的物理裁剪与 Z-Index 堆叠上下文限制。
3. **全键盘 WAI-ARIA 漫游**：方向键 `→` 展开子菜单，`←` 收起子菜单，`↑`/`↓` 在子模型列表中自由导航，`Enter` 选中。

### 4.2 方案二：全量服务商凭据表单统一模型（消除 `'custom-'` 硬编码）

消除以 `selected.id.startsWith('custom-')` 区分凭据表单的逻辑，建立统一的 `ProviderProfile` 凭据配置能力矩阵：

```typescript
// 统一状态判断模型
interface ProviderCapabilityProfile {
  id: string;
  name: string;
  baseUrl: string;
  isPreset: boolean; // 是否为内置模板
  allowRename: boolean; // 是否允许重命名（custom=true, preset=false）
  allowDelete: boolean; // 是否允许删除（custom=true, preset=false/可重置）
  authType: 'api_key' | 'oauth2' | 'subscription';
  requiresKey: boolean; // 是否需要 API Key
  models: string[];
}
```

- **凭据区无条件开放**：无论是 `deepseek`, `openai`, `anthropic` 还是 `custom-*`，只要其实例属于 API Key 认证，均无条件渲染 `ProviderProfileForm`，允许用户配置 API Key 和覆盖默认 Base URL。
- **预置标签与徽标**：通过统一的 Badge 展示「预置服务商」或「自定义服务商」，而非在 UI 层直接对表单输入进行粗暴拦截。

### 4.3 方案三：清理 2550 行全局废弃样式，收敛 Design Tokens

1. **废弃并移除** `apps/crish-desktop/src/styles/settings/settings-models.css`（2550 行全部删除）。
2. 从 `apps/crish-desktop/src/index.css:16` 中移除 `@import './styles/settings/settings-models.css';`。
3. **清理 `ModelsSettingsTab.module.css` 中的 175 行计费死代码**（移除 `.modelsBilling` 等无消费类名）。
4. **清除所有内联硬编码**：将 `ProviderProfileForm.tsx:85` 的 `style={{ borderRadius: '7px' }}` 等全部替换为标准 CSS Modules 类与 Design Tokens（`var(--radius-md)`, `var(--control-height-sm)`）。
