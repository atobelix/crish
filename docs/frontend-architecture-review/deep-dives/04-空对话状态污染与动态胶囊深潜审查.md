## 一、执行摘要与问题判定

在用户打开全新空白对话（点击「新建对话」进入草稿会话 `__pending_*` 或空会话 `sess-*`）时，界面中央正展示优雅的欢迎语与快捷提示（`ChatEmptyState`），但在底部输入框（`ChatComposer`）上方，却突兀地横亘着一个带有分支图标的悬浮胶囊：**「🌿 18 个文件变更」**（对应 DOM 类名 `_dynamicChip_1ipuz_27`）。

```
+-------------------------------------------------------------------+
|  [ChatHeader]                                                     |
+-------------------------------------------------------------------+
|                                                                   |
|              我们该在 [conex-desktop] 中处理什么？                  |
|                                                                   |
|   [ > 解释当前目录的模块架构... ]                                   |
|   [ > 优化性能热点...           ]                                   |
|                                                                   |
+-------------------------------------------------------------------+
|  [ 🌿 18 个文件变更 ]  <-- 【严重状态污染：新对话输入前横跳出 18 个文件变更】  |
|  +-------------------------------------------------------------+  |
|  | 输入消息或按 / 查看指令...                     [发送] [模型] |  |
|  +-------------------------------------------------------------+  |
+-------------------------------------------------------------------+
```

### 核心判定结论

1. **工作区全局 Git 状态越界入侵局部会话卡片**：
   `terminalStore.ts:33` 中的 `diffFiles` 实际上存储的是工作区全局 Git 变更缓存（由底层 `git status` / `git diff` 或跨会话工具发布）。`useChatCardState.ts:165` 无条件订阅了全局 `selectDiffFiles`，并在 `ChatCard.tsx:83` 直接将其数组长度赋值给 `diffCount`，将仓库物理状态与当前会话产出混为一谈。
2. **空态与草稿态生命周期门闩完全失效**：
   虽然 `useChatEmptyKind.ts` 精确算出了 `emptyKind = 'session-empty'` 并标识了 `onEmptySurface = true`，但 `ChatStatusRibbons.tsx:292-356` 的 `dynamicChipBar` 渲染条件仅判断 `diffCount > 0 && Boolean(onOpenDiff)`，**完全没有检查当前会话是否处于空态、是否为草稿态、或者该会话的消息列表中是否真正产生过任何 AI Diff**。
3. **三层状态架构边界崩塌**：
   前端在状态管理上，将「工作区全局环境状态（Workspace-Global）」、「当前会话专属状态（Session-Scoped）」与「未发生任何操作的纯净白板状态（Clean Draft State）」完全糅合在一起。除 `diffCount` 外，全局后台任务（`useBackgroundTaskPolling`）和全局权限计划模式（`permissionStore`）同样存在穿透污染空态的重大架构隐患。

## 三、会话生命周期与工作区全局状态边界模糊深潜

### 3.1 三级状态模型架构失位

在现代多会话 AI 工作台架构中，状态必须按生命周期和作用域严格划分为三级。当前代码将三者完全混淆：

| 状态层级                                            | 定义与典型数据                                                                             | 应当出现的位置                                                  | 当前错误行为                                                    |
| :-------------------------------------------------- | :----------------------------------------------------------------------------------------- | :-------------------------------------------------------------- | :-------------------------------------------------------------- |
| **Tier 1: Workspace-Global**<br/>(工作区环境状态)   | 本地 Git 仓库状态、工作区全部后台 Daemon 任务、全局配置                                    | 侧栏 Tab Badge、底部全局状态栏、Overview 卡片、独立 Diff 侧边栏 | **穿透注入到具体 Session 的 ChatCard 内**，伪装成该会话的产出。 |
| **Tier 2: Session-Scoped**<br/>(会话专属产出状态)   | 当前会话通过 AI Tool 修改的文件（`SessionMessage.toolCalls`）、本会话专属 Goal / Checklist | 对话消息流中的卡片、对话进行中输入框上方的实时产出状态胶囊      | 未做会话级统计，直接被全局 Tier 1 状态粗暴覆盖。                |
| **Tier 3: Clean Draft State**<br/>(纯净空态/草稿态) | 尚未产生任何 Prompt 发送、消息数为 0 的初始白板                                            | 呈现极简禅意的欢迎界面与引导，**严禁任何运行期脏状态侵入**      | **完全暴露在 Tier 1 污染下**，空态欢迎面瞬间破功。              |

### 3.2 SessionRuntimeRegistry 的设计承诺与现实背离

深入检查 `apps/crish-desktop/src/api/SessionRuntimeRegistry.ts` 可以发现，架构最初其实**明确规划了按会话隔离 diff 状态**：

```typescript
// apps/crish-desktop/src/api/SessionRuntimeRegistry.ts:1-12

 * 按会话隔离的运行时状态容器。

 *

 * - diffFiles：按会话隔离的 diff 状态  <-- 【明确的设计契约】
 * - attachments：按会话隔离的附件

  sessionId: string;
  diffFiles: FileDiff[]; // <-- 会话专属 Diff 容器
  // ...
```

**架构断层**：
虽然 `SessionRuntimeRegistry` 定义了会话隔离的 `diffFiles`，但后续在编写 `useChatCardState.ts` 和 `ChatCard.tsx` 时，开发者为了「省事」直接调用了 `useTerminalField(selectDiffFiles)`，把整个生命周期绑定到了全局的 `terminalStore` 上，导致 `SessionRuntimeRegistry` 的隔离设计形同虚设！

同时，`apps/crish-desktop/src/components/diff/useDiffData.ts` 内部其实已经具备精准收集单会话 Diff 的纯函数能力：

```typescript
// apps/crish-desktop/src/components/diff/useDiffData.ts:108-121
```

### 4.2 空态禅意欢迎流的视觉断裂

在设计系统规范中，`ChatEmptyState` 旨在建立一个无噪音、高聚焦的「沉浸式空白起跑线」：

- **上部**：居中大标题 `chatEmptyTitleHero`（`ChatEmptyState.module.css:70-86`），引导选择当前项目；
- **中部**：卡片式快捷 Prompt 列表 `chatEmptyPrompts`（`ChatEmptyState.module.css:168-186`）；
- **下部**：干净、扁平、无重阴影的输入框 `ChatComposer`。

当 `dynamicChipBar` 突然注入时：

1. **视觉割裂**：一个孤立的、带有边框和高亮呼吸点/图标的胶囊浮在输入框正上方，割断了快捷提示与输入框之间的自然视线流；
2. **认知负担**：用户会产生误判——「我是不是不小心打开了旧会话？」、「为什么这个对话已经改了 18 个文件？」、「我在这里发消息会不会覆盖之前的改动？」。

### 4.3 渲染门闩与时机决策矩阵

| 会话状态场景                     | `messages.length` | `emptyKind`       | `sessionDiffCount` | `dynamicChipBar` 正确展现策略              |
| :------------------------------- | :---------------- | :---------------- | :----------------- | :----------------------------------------- |
| **空白草稿会话** (`__pending_*`) | `0`               | `'session-empty'` | `0`                | **绝对禁止渲染**（强制纯净白板）           |
| **已建但无消息会话** (`sess-*`)  | `0`               | `'session-empty'` | `0`                | **绝对禁止渲染**（强制纯净白板）           |
| **搜索无匹配空态**               | `> 0`             | `'filter-empty'`  | `>= 0`             | **禁止渲染**（避免与过滤重置冲突）         |
| **无会话空态**                   | `0`               | `'no-session'`    | `0`                | **绝对禁止渲染**                           |
| **正常对话流中（有消息）**       | `> 0`             | `null`            | `> 0` (本会话)     | **仅当本会话有 Diff 时展示会话变更胶囊**   |
| **正常对话流中（无变更）**       | `> 0`             | `null`            | `0`                | **不展示文件变更胶囊**（Git 状态请去侧栏） |

## 五、会话上下文严格隔离重构方案

### 5.1 状态所有权与分层契约定义

彻底解耦 `Workspace-Global` 与 `Session-Scoped`，确立三大铁律：

1. **会话卡片只反映会话事实**：`ChatCard` 内的一切状态（Diff 数量、进度列表、审批项、任务运行状态），**必须且只能由当前会话的 `SessionState`（消息历史、工具调用、会话元数据）派生**；
2. **工作区状态归位到全局壳**：工作区未提交 Git 差异（18 个变更）应当只呈现在顶栏/侧栏 Diff Tab 的 Badge 上或 Overview 面板中，**严禁越界注入到 `ChatStatusRibbons`**；
3. **空态绝对纯净不变量（Clean Slate Invariant）**：当会话处于空态（`onEmptySurface === true` 或 `emptyKind != null` 或 `messages.length === 0`）时，`dynamicChipBar` 必须物理阻断渲染。

### 5.2 会话 Diff 抽取纯函数与 Selector 重构

在 `apps/crish-desktop/src/components/chat-card/useChatCardState.ts` 中，废除直接订阅全局 `terminalStore.diffFiles` 的危险模式，改为由会话消息派生：

```typescript
// apps/crish-desktop/src/components/chat-card/chatCardDiffSelectors.ts
import type { SessionMessage, FileDiff } from '../../store/types';
import { collectMessageDiffs } from '../diff/ChangeOverviewCard';
import { filterPublishableDiffs } from '../../api/publishToolDiffs';

/**
 * 从当前会话的所有历史消息中，纯函数计算本会话产生的实际文件变更。
 * 零全局副作用，空消息列表恒返回空数组。
 */
export function selectSessionDiffFiles(
  messages: SessionMessage[] | undefined
): FileDiff[] {
  if (!messages || messages.length === 0) return [];
  const map = new Map<string, FileDiff>();
  for (const m of messages) {
    if (m.sender !== 'assistant') continue;
    const diffs = collectMessageDiffs(m);
    for (const d of diffs) {
      map.set(d.filePath, d);
    }
  }
  return filterPublishableDiffs([...map.values()]);
}
```

在 `useChatCardState.ts` 中切换依赖：

```typescript
// apps/crish-desktop/src/components/chat-card/useChatCardState.ts (重构后)
import { selectSessionDiffFiles } from './chatCardDiffSelectors';

// 移除: const diffFiles = useTerminalField(selectDiffFiles);
// 改为基于当前会话 messages 的 memoized 派生:
const sessionDiffFiles = useMemo(
  () => selectSessionDiffFiles(messages),
  [messages]
);
```

## 六、总结与落地建议

通过对 `apps/crish-desktop` 中 8 个关键源码文件的端到端代码追溯，证实了用户截图 2 反馈的「18 个文件变更胶囊悬浮空对话」问题，是**工作区全局 Git 状态越界直通注入**与**组件空态门闩缺失**共同导致的典型架构缺陷。

实施本报告提出的「会话上下文严格隔离契约」后：

1. **空白草稿会话（ChatEmptyState）将恢复 100% 纯净无暇的禅意欢迎布局**；
2. **文件变更胶囊将精准且仅在当前对话产生实际代码编辑时才出现**；
3. **全局 Git 变更回归到独立的 Diff 面板与工作区状态栏**，彻底消除用户的认知混淆，实现架构的优雅与健壮。
