# 分维详案 02：标签页新建与空态状态机防劫持详案

> **文档位置**：`docs/pluggable-import-architecture/02-标签页新建与空态状态机防劫持详案.md`  
> **所属战役**：可插拔导入插件架构重构与主视口解耦  
> **设计原则**：空白画布神圣不可侵犯（Sacred Blank Slate）、零死锁、零劫持

---

## 1. 目标与范围

根除“用户在有外部未导入会话时，点击新建标签页创建不成功并被打回对话导入界面”的严重死锁缺陷，从状态机层面彻底保障新标签页与新会话的纯洁性与即时可用性。

---

## 2. 状态机冲突根除与加固

### 2.1 状态机解构与根除死锁链条
原有死锁形成的四重因素已在分析阶段明晰：
1. `addTab` -> `enterComposer` 将 `activeTabId` 置为 `''`；
2. 处于草稿态时，条带不画物理 Tab 药丸（遵循未提交不占位哲学）；
3. 原侵入式 Hook 每次监听到 `session-empty` 就无脑全盘扫描，命中了未导入的长会话；
4. 命中的会话抹杀了 `emptyKind` 并劫持了输入框；再次点击加号被 `enterComposer` 幂等守卫（`leaf.activeTabId === ''`）静默拦截为 NO-OP。

**根治措施**：
随着分维详案 01 彻底删除 `useExternalLongSessionDetection` 及其分支：
- 点击新建标签页进入草稿态（`activeTabId: ''`）时，`useChatEmptyKind` 稳定计算出 `emptyKind = 'session-empty'`；
- 没有任何异步扫描或外部检测逻辑介入，主视图 100% 确定性呈现原生的新对话落地欢迎面（`ChatLandingBrand` + `ComposerProjectPicker`）；
- 输入框 100% 聚焦可用，用户输入文字回车后物化为真实会话并插入真实 Tab 药丸。
- 整个创建流程中绝对不会被任何外部扫描打断或回退。

### 2.2 防劫持断言测试套件建设
在 [`apps/crish-desktop/src/components/binary-tree/__tests__/TreeLeafPanel.tabAntiHijack.test.tsx`](file:///c:/Software/conex/apps/crish-desktop/src/components/binary-tree/__tests__/TreeLeafPanel.tabAntiHijack.test.tsx) 中新建专项防回归断言：
1. **用例 1（空白态防劫持与即刻可打字）**：
   - 模拟本地存在多个未导入的 Claude Code / Codex 长会话；
   - 用户点击窗格标题栏的 `+` 按钮触发 `addTab(leaf.id)`；
   - 断言：窗格正确进入新会话草稿态；
   - 断言：输入框中绝不存在任何类似“点击以导入对话并继续输入…”的幽灵按钮；
   - 断言：输入框处于可打字状态，模拟键入 `Hello World` 并断言文本正常填入；
   - 断言：发送按钮可用，点击后正常进入消息发送流程。
2. **用例 2（加号多次点击幂等且绝不异化）**：
   - 连续点击两次 `+` 按钮；
   - 断言：界面始终保持为干净的新对话空白欢迎态，绝无任何视图漂移或异常弹窗。
