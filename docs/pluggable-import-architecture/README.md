## 1. 战役背景与用户诉求（REQ）

用户明确反馈：
1. **死锁困境**：在启用了对话导入功能后，当前的对话很容易锁死在“需要点击同意导入”的界面。
2. **新建标签页被劫持**：点击其他功能（如新建标签页），直接创建不成功，并立即被打回对话导入界面。
3. **视觉与交互混乱**：当前的对话导入非常不清晰，缺少上下文和来源提示，且界面伪装成常规聊天。
4. **强行剥夺取消权**：界面上只有“点击导入对话以继续”这一个选项，用户被强制导入，无法点击取消或开启空白对话。
5. **假插件与核心严重耦合**：该功能本应是一个独立的官方/第三方插件，可以自由插拔、随时禁用/卸载，但当前实现却直接生硬焊死在软件核心架构中（`ChatCard`、`ChatComposer`、`settingsStore`、`AppGlobalDialogs`）。
6. **重构纪律**：用户明确指示——“不要兼容、不要打补丁，需要删除代码就删除，需要重构就重构。不要最短路径改动，在软件内的代码应该是最先进的，不允许多个版本存在。”

## 3. 纪律与红线

1. **零补丁原则**：彻底删除侵入核心 UI 的 `previewExternalSession` 与 `externalSessionPreview`，绝不保留过渡性兼容层。
2. **零多版本**：所有插件体系与导入逻辑收敛至单一真理源（SSOT），杜绝多套 LocalStorage 状态与硬编码开关并存。
3. **主 Agent 统一提交**：子 Agent 只写分析与方案文档，代码落地由主控统一验证后通过 `git commit --only` 提交。
