# 分维详案 03：可插拔插件架构与扩展插槽详案

> **文档位置**：`docs/pluggable-import-architecture/03-可插拔插件架构与扩展插槽详案.md`  
> **所属战役**：可插拔导入插件架构重构与主视口解耦  
> **设计原则**：真正的控制反转（IoC）、零开销闲置（Zero-Overhead Inactivity）、规范化插拔

## 1. 目标与范围

将“外部会话导入”真正重构为符合现代微内核架构的可插拔插件，明确插件与宿主的边界，将管理主流程归位至一等公民扩展工作台，清理宿主根生命周期与核心配置中的杂质。

### 2.2 扩展工作台作为导入的主承载面
1. **用户主动发起的管理流**：
   - 所有的外部历史导入由用户在“扩展中心 -> 对话导入 -> 管理”或从 Composer `+` 菜单中的“导入对话”显式打开 [`ExternalSessionsWorkbench`](file:///c:/Software/conex/apps/crish-desktop/src/components/extensions-surface/ExternalSessionsWorkbench.tsx)；
   - 工作台具备以下透明元数据展示与管理能力：
     - 明确显示来源图标（Claude Code 橙紫 / Codex 绿）；
     - 来源路径（cwd）展示，支持悬浮自定义 Tooltip 查看全路径；
     - 准确统计消息条数与最后更新时间；
     - 支持双栏抽屉式真实会话只读预览（带明确的“只读预览”标识与来源水印）；
     - 支持全选、多选、批量导入与软去重检测。

### 2.3 基于标准插槽的非侵入式提示（如需轻量提醒）
若官方插件需要在主界面提供轻量感知提示，必须且只能通过宿主标准扩展插槽 `slotCore.registerSingle('workspace.chat.composerAbove', ...)` 挂载：
- **位置**：只挂载在输入框上方插槽；
- **输入框保护**：底部的 Composer 100% 保持原生输入能力，绝不替换输入框；
- **对等双向动作**：提供【导入并接续】、【在工作台预览】、【跳过本次】、【永久屏蔽】按钮；
- **打字自然淡出**：用户一旦在底栏输入文字，上方提示条平滑渐隐淡出（Type-to-Dismiss）；
- **停用即销毁**：当用户在设置中停用插件时，插槽注销函数被原子执行，DOM 节点瞬时清除，零额外监听，零扫描开销。
