## ② 逐发现项

### 红级

#### 红-01 完成态渲染陈旧 timeline → 最终消息文本截断（REMEDIATION-06 未覆盖的残余缺陷）

- **等级**：红（功能回归，真机可复现）
- **现场**：`api/tool-presentation/timelineNormalizer.ts:286-323`（`timelineSignature`）+ `components/chat-message/MessageContent.tsx:146-160`（`timelineCacheRef`）
- **缺陷机制**：
  1. `timelineSignature` 对最后一条 text 块**只记 `{last:1, e:empty}` 标记、永不记内容**（timelineNormalizer.ts:295-304）——REMEDIATION-06 此举本意是让流式期签名稳定以命中缓存（修复纯文本无 blocks 时流式区不激活的问题，该修复对纯文本完成态是安全且正确的：commit 时 `updateMessageText` 使 blocks 0→1，签名分支翻转强制重建）。
  2. 但**交错消息**（blocks 已含 `[{text},{tool_call},{text}]`）在最后一次工具事件之后继续流式增长正文时：最后一次签名变化 = 工具事件；此后每帧签名恒定 → 缓存命中 → timeline 最后 text 项内容被冻结为「工具事件瞬间」的值。
  3. 完成态 `streaming=false` → `splitRef` 的 before 分支返回**全量陈旧 timeline**（MessageContent.tsx:269-283）→ 最终文本渲染为截断内容；用户看到「流式期间全文完整、完成后反而缩水」。
- **复现证据**（临时探针，已删除，git 干净）：
  - tsx 纯逻辑模拟：`completed-commit` 帧与 `stream-frame-3` 签名完全一致；缓存 timeline 的 `lastTextContent` 为流式首帧值「这是正在生成的很长的正文内容」≠ 最终「…总共一百个字左右」。
  - 组件级 vitest 探针：MID（流式期）含全文 = **true**；FINAL（完成态）= "开头运行命…"，断言含 '总共一百个字左右' = **FAIL**。
- **触发面**：所有「commit 前已存在 blocks（引擎/快照写入）+ 最后一次工具事件后仍有正文流」的助手消息——即工具型消息的常见形态；纯文本消息不受影响（blocks 0→1 翻转签名）。
- **修复建议**（任选其一，优先 a）：
  - a) 签名在**非流式态**（`msg.status !== 'processing'`，或流式文本缺位）时将最后 text 块内容计入签名 → 完成/停止/错误时签名必然变化 → 强制重建；
  - b) MessageContent 在 `streaming` true→false 转换时显式失效 `timelineCacheRef`；
  - c) 引入文本版本戳（提交纪元）入签名。
- **回归测试**：新增「交错 blocks（text+tool_call+text）消息：流式完成前后渲染文本 = 完整最终文本」单测；当前 `timelineSignature` / `buildAssistantTimelineCached` **无任何直接单测**（全仓 grep 无匹配）——本次修复裸奔，必须补。
