## ③ 逐发现项

### D-1（黄）R-1 只接 GC 一条线，detach/attach/ping 注册面仍死；GC 上线使「3 态」叙事部分成真但半套契约

- **证据**：`main.rs:833` 已调 `spawn_pty_gc_loop`；`pty/mod.rs:92-110` detach/attach/ping 仍 `#[allow(dead_code)]` 且未入 command_registry!（main.rs:159-162）/command_manifest.rs:78-81；前端 `ptySessionApi.ts` 仅 4 命令。GC 内部：`session.rs:145-162` `is_gc_eligible` 现在每 30s 真跑。
- **缺陷机制**：上轮三件套（GC 启动 / detach/attach/ping 注册 / 前端 Tab 切接）只完成第一件。而第一件单独生效改变了运行期行为：Active 会话 >120s（ACTIVE_IDLE_TIMEOUT_MS=120_000，session.rs:35）无活动即被 GC 自动迁 Detached，再 >2h（DETACHED_GC_GRACE_MS=7_200_000，:38）无任何输出被 kill——**但前台没有 ping/保活通道**（ping 命令未注册、前端零调用、touch 仅由 write/resize/reader 输出触发，session.rs:520/541/437），于是「用户正盯着的前台 Tab 中空闲 >2h 的 shell」会被静默回收，UI 仍显示会话存在。设计预定的「Frontend Tab switch detaches session + ping 保活」缺失使 GC 的单侧运行产生误杀面。
- **修复建议**：补齐另两件（注册 detach/attach/ping + 前端 Tab 切接时 detach、聚焦时 ping）；在补齐前，至少在 GC kill 前广播 `pty://gc-killed` 事件（`_app` 参数现仍闲置）并让前端据此关闭/刷新对应 Tab，消除「UI 有会话、引擎已回收」的假象。
- **影响**：中；判定：黄（§15.2 半连通——比上轮红级改善，但契约仍缺两件且新引入前台误杀面）。
