## ① 总判色：黄偏红

**主安全面全绿**：服务默认关闭不 bind（D5 D-01 红线 1）、配对模式强制 wss、Bearer 令牌常量时间比较、命令白名单 + 显式排除面、配对期例外 fail-closed、401/404/503 错误映射——fail-open 面未发现。

- **R1**：HMAC-SHA256 消息签名 + Nonce 幂等防重放中间件「实现未接线」——原语与规范化函数已实现且有单测，但网关 / WS 入站路径从未消费；注释与实现状态互相矛盾。

### Y1（黄）port_probe 回退测试 flaky（端口竞争型）

- 证据：mod.rs:614-629 测试占住 `base_port` 后断言回退 `base_port + 1`；真跑全量 238 过 1 挂（`left: 17295, right: 17294`——base+1 被并行环境占用），**单独重跑通过**。
- 缺陷机制：探测回退依赖全局端口空间相邻槽空闲，测试无原子性保障（并行进程 / 系统服务可抢占 base+1）。
- 修复建议：测试同时占住 base+1 断言回退 base+2；或对探测面做 mock 注入。

### Y2（黄）Watchdog 装配缺 agents_source 注入 → 已完成子代理过滤失效

- 证据：engine_build.rs:283-290 `Watchdog::new` 无 agents_source 实参（watchdog.rs 结构含 `agents_source: Option<...>`）；watchdog.rs 扫描段在 None 时不过滤已完成子代理（声明保留全量）。
- 影响：子代理已完成但声明未核销时，兜底可能对已结束的等待注入假阳性 steering。
- 修复建议：装配注入 `SubagentStatusSource`（可与 WaitChannel 共享实例）。

### Y3（黄）active_timer_probe 恒 0 → REQ-C05「既没有设置定时器」条件失效

- 证据：engine_build.rs:288 `Arc::new(|| 0)`；注释（engine_build.rs:281-282）自认「TimerRegistry 无同步计数接口（timers.rs 本轮只读），缺省 0 不抑制兜底——同步计数接线登记遗留」。
- 影响：兜底触发面宽于设计——存在活跃 timer 的 run 也会被兜底唤醒（潜在重复 steering 注入）。
- 修复建议：TimerRegistry 提供同步计数接口并接线；遗留登记限期消化。

### Y4（黄）dispatch 声明「裸键全局单槽」跨会话隔离缺失

- 证据：wait_channel.rs:188-197 `LocalDbWaitStore::load_all` 用 `DISPATCH_META_KEY_*` **裸键**（无 session 前缀）；同口径证据：conex-db explore_docs_quota_store.rs:255 注释「单会话引擎传空 session_id 的接线形态」。
- 影响：单会话引擎下自洽（watch 落库与 watchdog 读面同键）；多会话演进时声明槽跨会话互相覆盖。
- 修复建议：键加 session 前缀（前瞻多会话）；期间登记 SD 债。

### Y5（黄）命令白名单守卫覆盖面窄于宣称

- 证据：router.rs:123-138 `ensure_command_execution_allowed` 仅挂 runTask / runControl / cancelRun 三个写端点；approve / deny 不挂（注释理由：I-02 pending 校验另行防御）；remote_whitelist.rs 自称「命令执行面唯一真源」。
- 影响：白名单实际覆盖写命令子集；后续新增写端点无编译期强制守卫。
- 修复建议：路由注册表驱动式强制挂载（新端点默认带守卫），或修正宣称口径。

### Y6（黄）WaitChannel 生产用 MemoryAgentSource（半连通）

- 证据：engine_build.rs:268 `Arc::new(MemoryAgentSource::new())`；wait_channel.rs:91-94 `SubagentStatusSource` 语义为「读本会话 session_agents 行」。
- 影响：snapshot 面与真实代理行数据面脱钩（重启后恒空 / fail-open 显示运行中）；与 Y2 同源。
- 修复建议：LocalDb 装配分支注入 session_agents 真适配。

### Y7（黄）文件行数严重超标（结构债 / 上帝文件）

- 证据（wc -l 实测）：router.rs 3518、ws.rs 3049、mod.rs 1376、auth.rs 857、fanout.rs 824、pairing.rs 808、pair_endpoint.rs 664、watchdog.rs 650、multi_device_network.rs 649——均超 review.md §13 约 400 行门禁数倍。

- 修复建议：router（路由表 / 处理器）与 ws（协议处理器）优先拆分；或登记 Rust 侧行数基线并限期消化。
