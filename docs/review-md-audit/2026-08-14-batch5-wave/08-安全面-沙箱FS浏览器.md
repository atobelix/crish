## 二、红级问题

### H1（红）PowerShell 调用操作符 `&` 包裹间接命令 → 删除语义全链漏检 → gatekeeper Allowed

**证据（真跑）**：

| 命令                                                   | analyze() 结果                                  | gatekeeper 处置                                            |
| ------------------------------------------------------ | ----------------------------------------------- | ---------------------------------------------------------- |
| `& cmd /c rmdir /s /q D:\old`                          | overall=Indirect, **has_indirect_delete=false** | **Allowed**（真跑确认）                                    |
| `cmd /c rmdir /s /q D:\old`（对照组，无 `&`）          | overall=Indirect, **has_indirect_delete=true**  | RequiresApproval ✓                                         |
| `Invoke-Command -ScriptBlock {rmdir /s /q D:\old}`     | overall=DeleteShape（花括号提取生效）           | 未标 has_indirect_delete → 静态正则不命中 → **Allowed**    |
| `& cmd /c rm -rf /`                                    | Indirect, false                                 | Blocked（静态正则 `\brm\s+-[a-z]_rf[a-z]_\s+(/             | \/\* | \*)` 兜底） |
| `& cmd /c rm -rf /tmp/x`                               | Indirect, false                                 | **Allowed**（非根目标不在正则）                            |
| `& bash -c 'rm /tmp/x'`                                | Indirect, false                                 | **Allowed**（无 -rf 不在正则）                             |
| `& cmd /c Remove-Item D:\old.txt`（无 -Recurse/-Path） | Indirect, false                                 | **Allowed**（`\bRemove-Item\b.*(-Recurse\|-Path)` 不匹配） |
| `& "cmd" /c rmdir /s /q D:\old`                        | Indirect, false                                 | **Allowed**（引号剥离后同 H1 主链）                        |
| `$x = 'rm'; & $x -rf /tmp/x`                           | Dangerous ✓                                     | RequiresApproval ✓（已覆盖，对照组）                       |

**缺陷机制**（链式根因，`crates/conex-sandbox/`）：

1. `semantics.rs:61-64` `INDIRECT_COMMANDS` 清单**不含调用操作符 `&`**；`& cmd /c rmdir` 的段首命令是 `&`，args[0]="cmd"。
2. `semantics.rs:135-139`（I2-S4 has_indirect_delete 标记）：仅 `INDIRECT_COMMANDS.contains(&normalized)` 时提取内层删除形态 → `&` 段不触发 → **has_indirect_delete=false**。
3. `semantics.rs:561-567`（AST 动态调用分支）：只对 args[0] 为 `$`/`(`/`{`（`& $var` 动态目标）返回 Dangerous；args[0] 为静态命令名 `cmd`/`bash` 时漏检。
4. `semantics.rs:690-720` `scan_ps_command_tokens`：args[0]="cmd" 命中 INDIRECT 返回 `Some(Indirect)`（仅标记，不递归分析其参数删除形态）→ `classify_depth` 步骤 0.1（semantics.rs:1044-1053）对 Indirect 不 return。
5. `semantics.rs:1056-1071` classify_depth 步骤 1：`INDIRECT_COMMANDS.contains(&command)` 为 false（command=`&`）→ 不递归 `analyze_indirect`。
6. `lib.rs:85-123` `check_command`：步骤 1 只拦 Redline（91-94）；步骤 2 静态正则（26-51，无 rmdir 条目，`\brd\b` 对 "rmdir" 词边界不匹配、`\bdel\b.*[A-Za-z]:` 不匹配）；步骤 3 只拦 Dangerous/has_indirect_delete（105-113）→ Indirect 不触发；步骤 4 approval_patterns（53-65）只有 git/npm/cargo/sudo/runas → **最终 `GatekeeperResult::Allowed`**。

**影响**：绕过删除接管/审批管线。`& bash -c 'rm /tmp/x'`、`& cmd /c Remove-Item D:\old.txt`（单文件）、`& cmd /c rmdir /s /q D:\old`（递归目录）等形态均可无审批删除。BATCH-05 AST gate 声称覆盖「& 调用」仅覆盖动态目标（`& $var`），**静态命令名目标为盲区**。`Invoke-Command` 变体虽提取出 DeleteShape 但 gatekeeper 同样不处理该 class（命令面若另行消费 DeleteShape 则需确认接线是否兜底）。

**修复建议**：

1. `INDIRECT_COMMANDS` 增补 `"&"`（及 `"$("`、`"&("`、`"&{"` 形态归一到 `&`），使 `analyze_depth` 步骤 1 与 `classify_depth` 步骤 1 对 `& cmd ...` 走 analyze_indirect 递归（`& cmd /c rmdir /s /q D:\old` 内层提取 `cmd /c rmdir /s /q D:\old` → 段首 cmd 命中 INDIRECT → 再递归 → rmdir 删除形态 → DeleteShape → has_indirect_delete=true）。
2. `scan_ps_command_tokens`（semantics.rs:690-720）对命中 INDIRECT 的 token（`cmd`/`bash`）返回前，用该 token 之后的内容继续递归（而非仅返回 Indirect 标记）。
3. gatekeeper `check_command` 步骤 3 增补 `overall_class == Indirect` 或要求命令面在消费侧把 Indirect+非空 delete_targets 视为 RequiresApproval。
4. 补回归测试：`& cmd /c rmdir /s /q D:\old` → RequiresApproval；`& bash -c 'rm /tmp/x'` → RequiresApproval；`& "cmd" /c`、`& cmd.exe /c`、`Invoke-Command -ScriptBlock {rmdir ...}` 变体。

### H2（红）HTML 净化器未闭合标签绕过（plugin-sdk sanitizer）

**证据（真跑，node 直调 `sanitizeHtml`）**：

| 输入                                                       | sanitizeHtml 输出                            | 结果         |
| ---------------------------------------------------------- | -------------------------------------------- | ------------ |
| `<img src=x onerror=alert(1)`（无 `>`）                    | `<img src=x onerror=alert(1)` **原样保留**   | **XSS 残留** |
| `<a href="javascript:alert(1)"`（无 `>`）                  | `<a href="javascript:alert(1)"` **原样保留** | **XSS 残留** |
| `<img src=x onerror=alert(1)>`（闭合）                     | `<img src="x" />`（onerror 被剥离）          | ok ✓         |
| `<a href="javascript:alert(1)">x</a>`（闭合）              | `<a rel="noopener noreferrer">x</a>`         | ok ✓         |
| `<img src="jav&#x61;script:alert(1)">`                     | `src` 实体被转义 + javascript: 拒绝          | ok ✓         |
| `<IMG SRC=x ONERROR=alert(1)>`                             | onerror 剥离                                 | ok ✓         |
| `<a href="data:text/html,<script>alert(1)</script>">x</a>` | href 剥除                                    | ok ✓         |
| `<style>@import url(javascript:alert(1))</style>`          | 空                                           | ok ✓         |
| `isSafeUrl('jav&#x09;ascript:alert(1)')`                   | false                                        | ok ✓         |

**缺陷机制**（`packages/plugin-sdk/src/sanitizer/htmlSanitizer.ts:228`）：`tagRegex = /<\/?([a-zA-Z0-9:-]+)((?:[^"'>]|"[^"]*"|'[^']*')*)\/?>/g` 要求标签以 `>`（或 `/>`）**闭合**才匹配；未闭合标签（`<img ...` 缺 `>`）不匹配 → `sanitizeHtml` 的 replace（230 行）不处理 → **原样返回**。浏览器 HTML 解析器在 EOF（或其后某处 `>`）处隐式闭合 → `<img src=x onerror=alert(1)` 的 `onerror` 生效（src=x 404 触发 onerror）；`<a href="javascript:alert(1)"` 点击即执行。`sanitizer.test.ts`（17 项，全绿）只覆盖闭合标签与实体混淆，**未覆盖未闭合向量**。

**影响**：依赖 `sanitizeHtml` 渲染不可信 HTML 的视图（如插件贡献的 HTML 内容、AI 生成的 markdown 富文本等）存在存储型/注入型 XSS 面。当前仓库内调用点需逐一确认渲染方式（如 `dangerouslySetInnerHTML`/`innerHTML`），即便当前调用点仅做文本输出（escapeHtml 路径）不受影响，**净化器作为公开 SDK API 的语义保证已被打破**，后续调用点随时可踩雷。

**修复建议**：

1. tagRegex 之前加**残片预处理**：对 `/<([a-zA-Z][a-zA-Z0-9:-]*)(\s[^<>]*)?$/`（以 `<tag` 开头且无 `>` 结尾的残余）整体转义或剥除（`escapeHtml` 处理），或改用真正的 HTML 解析器（DOMParser 不可用则手写状态机）。
2. 或在净化主循环中：遇到 `<` 后若在合理长度内无 `>`，将 `<` 转义为 `&lt;`（文本语义）而不是放行原样。
3. 补回归测试：未闭合 `<img onerror>`、未闭合 `<a javascript:`、`<img src=x onerror="alert(1)<b>">`（属性内含 `<` 的闭合变体已安全，见 §三 P 项）、EOF 截断变体。
4. 约定：`sanitizeHtml` 输出仅允许经 `dangerouslySetInnerHTML` 白名单渲染；文档注明「输出不可直接 innerHTML 到脚本上下文」。

## 三、黄级问题

### M1（黄）`trash.rs` snapshot 用 `path.exists()` 判定存在性 → 权限拒绝被吞 → 误登记 nil-content → 恢复=删除原路径（fail-open）

- 位置：`crates/conex-fs/src/trash.rs`（snapshot 重构，263 行改动）
- 机制：旧实现 `Err(e) if e.kind() == NotFound` 仅对 NotFound 登记 nil-content 条目，**其他 IO 错误 bail（fail-closed）**；新实现 `path.exists()` 把 **PermissionDenied 等错误吞为 false**（std 语义：`exists()` 遇权限错误返回 false）→ 误判「原文件不存在」→ 登记 `original_existed=false` → 恢复语义=删除原路径 → 不可访问的原文件被**误删**。
- 违反 §6（错误处理 fail-closed）。修复：恢复 `fs::metadata`/`symlink_metadata` 的 `kind()` 分支；或 `exists()` 前先 `metadata` 判断，`Err(e) if e.kind() == NotFound` → nil，其他 Err → bail。
- 注：`watcher_stop_produces_no_more_events` 单独跑通过（1 passed），全量并发跑偶发 FAILED（64 passed; 1 failed），重跑全量 65 passed 全绿 → **flaky（notify 事件时序敏感）**，非功能缺陷，建议后续加事件确认轮询。

### M2（黄）`gate.rs` 传输层 blocked_urls 清单仅覆盖 `http://` 前缀 → `https://<内网IP>` 不在传输层阻断面

- 位置：`crates/conex-browser/src/gate.rs`（blocked_urls 构建，`http://10.*` 等前缀模式）
- 机制：Chromium `setBlockedURLs` 做 URL 前缀匹配；内网/保留段阻断清单只写 `http://` 形态，`https://10.x.x.x` 直连内网不在传输层阻断面（语义层 `check()` 仍会拦，属纵深防御缺口而非主防线失效）。确认过：导航路径均先过 `gate.check()`（browser-tools lib.rs:154 `FormalDomainGate::new` 兜底接线），故为黄级。
- 修复：blocked_urls 增补 `https://` 同网段条目（或前缀含 `//10.`、`//192.168.` 等共享形态）。

### M3（黄）传输层事件循环静默吞错 + 每导航事件全量重算重发 + `within_rebinding_window` 疑似死代码

- 位置：`crates/conex-browser/src/lib.rs`（NavigationStarted 事件里 `let _ = channel.send_command(NETWORK_SET_BLOCKED_URLS, ...)` 静默吞错，违反 §6）；每次导航事件重算 `blocked_urls()`（100+ 条）并重发（性能）；`gate.rs:496 within_rebinding_window` 生产侧无调用点（仅测试使用，grep 确认），而 `check()` 每次重新解析 DNS 已覆盖重绑定 → 窗口记录疑似冗余状态。
- 修复：send_command 失败记录 warn 日志；blocked_urls 惰性缓存（URL 列表变更时重算）；删除或正式接线 within_rebinding_window（若删，同步删测试 gate.rs:939-985）。

### M4（黄）`window_gate.rs` fail-open 边缘 + magic string 状态传递

- 位置：`crates/conex-computer/src/window_gate.rs`（+147）
- 机制：`process_is_elevated` 中 `err == ERROR_ACCESS_DENIED || err != 0` 冗余（等价 `err != 0`），err==0 边缘 fail-open；`resolve_foreground_target` 用魔法串 `access_denied_elevated.exe` 传递 fail-closed 状态（隐式约定，§13；审计日志/进程列表会泄漏伪进程名）。测试 `process_is_elevated(4)`（PID 4=System，依赖环境）与 `Enigo::new`（CI 无桌面可能失败）属环境敏感测试。
- 修复：显式错误码分支（0=不提升、ERROR_ACCESS_DENIED=不确定→fail-closed、其他=失败）；用 enum/Result 传递状态而非 magic 文件名；测试对 `Enigo::new` 失败做 skip 守卫。

### M5（黄）白名单模式跳过解析校验 → allowlist 域名可解析到内网（SSRF 面）

- 位置：`crates/conex-browser/src/gate.rs`（allowlist 非空跳过 DNS 解析校验；browser-tools gate.rs:177 同理 MvpDomainGate）
- 机制：「显式信任」设计决策（测试断言锁定），但 allowlist 内域名若被 DNS 重绑定指向内网，语义层不拦。仅记录设计权衡，建议文档明示信任面；`with_fail_closed_resolve(false)` 仅测试使用（grep 确认生产路径 `FormalDomainGate::new` 默认 fail-closed ✓）。

### M6（黄）`watch.rs` 临时文件过滤过宽 → 真实用户文件事件漏报

- 位置：`crates/conex-fs/src/watch.rs`（is_internal_atomic_transient_path）
- 机制：`ends_with(".tmp")/.bak`、`contains(".tmp.")` 一刀切过滤 → 用户真实文件 `report.tmp`、`config.bak`、`notes.tmp.md` 的变更事件被静默漏报（数据面漏报 vs 误报权衡）。建议收窄为「内部原子写专用临时名」（如 `.<name>.<hash>.tmp` 或仅过滤本模块 write 的已知临时名前缀）。

### M7（黄）`impact.rs` MAX_DEPTH=64 深度守卫超深目录静默不计数

- 位置：`crates/conex-fs/src/impact.rs`（+41）
- 机制：深度 >64 静默停止计数 → 影响面低估（edge，不影响安全）。正向：深度守卫防栈溢出 ✓。建议超限时显式标记「估算值」。
