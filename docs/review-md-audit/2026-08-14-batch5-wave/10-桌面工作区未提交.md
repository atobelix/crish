## ② 逐发现项

### R-01【黄·接近红】SessionCoordinator 半拆未接线；删除会话不清理 streamingStore

- **证据**：`apps/crish-desktop/src/store/SessionCoordinator.ts:23-40` 定义 `deleteSessionCascade`（清理 terminal + streaming + snapshots）；生产代码**零调用**（仅 `sessionStore.ts:185`、`storeAccess.ts:170-171` 再导出，消费方仅 `SessionCoordinator.test.ts`）。真实删除路径 `sessionCrudActions.ts:409-445`（`deleteSession`）只做 `dropTerminalForSession` + `clearMessageSnapshots(id)`（:442），**无 `clearSessionStreams`**；调用点 `components/sidebar/useSidebarContextMenu.ts:234`。
- **缺陷机制**：删除会话后 `streamingStore.byKey` 条目残留 → 内存泄漏 + 幽灵流状态；Cascade 本应修复此洞，但新模块未接到产品路径。
- **修复建议**：在 `sessionCrudActions.deleteSession` 内补 `clearSessionStreams(id)`；或把删除调用点统一改走 `deleteSessionCascade`（用 `rg` 复核全部 `deleteSession(` 调用后接线）。

### R-02【黄】useUndoWithScrollAnchor 未接线；快照 undo 面零消费方（只存不撤）

- **证据**：`MessageVirtualizer.tsx:88` 调 `useUndoWithScrollAnchor(containerRef, manager)` 但**不使用返回值**；`useUndoWithScrollAnchor.ts:19-72` 的 `performUndoWithAnchor` 生产零引用；`MessageSnapshots` 的 `undo`/`applyDelta` 生产零引用（仅 `MessageSnapshots.test.ts` / `useUndoWithScrollAnchor.test.ts`）。save 面已接：`sessionMessageActions.ts:121-133`（withdrawMessage 保存快照）+ `useChatHandlers.ts:111-193`（撤回 UI 已通）。
- **缺陷机制**：快照系统「只存不撤」——撤销恢复（含高度回灌 `hydrateHeightMap` 与滚动锚定）闭环只存在于测试；BATCH-06 宣称的 "heightMap scroll anchor" 未进产品路径。
- **修复建议**：撤回二次确认加「恢复」入口，恢复时 `snaps.undo()` + `performUndoWithAnchor(...)`；若本期不做，须在收尾清单显式标注「延期」，禁止以测试绿冒充交付。

### R-03【黄】store → components 逆向依赖

- **证据**：`apps/crish-desktop/src/store/streamingStore.ts:387-390` re-export `../components/chat-message/streamMessageViewModel`（`applyStreamTextToMessage` 等）。
- **缺陷机制**：store 层反向引用 components 目录，违反分层单向依赖（review.md §1 / AGENTS §11.5「底层工具包不得反向引入上层业务包」）；链路 `components/MessageContent → api/store-access/componentAccess → store/streamingStore → components/chat-message/streamMessageViewModel` 形成跨层折返。
- **修复建议**：`streamMessageViewModel.ts` 为无 JSX 纯函数，移到 `api/`（如 `api/streamMessageViewModel.ts`），componentAccess 直连，streamingStore 仅保留自身状态逻辑。

### R-04【黄】autoIndexMiddleware 测试断言注水 + 注释与实现矛盾

- **证据**：`autoIndexMiddleware.test.ts:103-110` 用例声明「sessions 数组引用变化但 id 集合不变 → 不重建 map」，但实现 `autoIndexMiddleware.ts`（`partial.sessions !== prevSessions` 时无条件重建 `sessionsById`）**确实重建**；断言 `toStrictEqual(mapBefore)` 只比内容相等——重建后内容相同照样绿，改成 `toBe` 会红。
- **缺陷机制**：immer 下任何会话内容变更都会产生新 sessions 数组引用 → 每次变更都重建 map → 订阅 `sessionsById` 的组件收到新引用而多余重渲染；测试未锁定「未重建」行为，注释与实现相互矛盾。
- **附带**：`sessionsIdKey`（autoIndexMiddleware.ts:40/:152 导出）仅测试使用，生产死导出。
- **修复建议**：断言改 `toBe(mapBefore)` 并把实现（或注释）对齐到真实语义；删除 `sessionsIdKey` 死导出。

### R-05【黄】MessageSnapshots 内存估算低估 + 全量副本

- **证据**：`api/MessageSnapshots.ts`（220 有效行）`estimateBytes` 只计 `delta.inserted` 与 heightMap 键值；`SnapshotEntry.messages` 存**全量消息副本**但不计入 byteSize → 5MB/20 条 LRU 上限失真，实际内存可能显著超限；且 undo 未接线（R-02）时全量副本纯浪费。
- **修复建议**：byteSize 计入 `messages` 序列化长度（或快照改为引用 + 写时复制）；LRU 阈值按真实成本校准。

### R-06【黄】finalizeAgentMessages 按会话粒度清流 → 并发误伤

- **证据**：`apps/crish-desktop/src/store/sessionAgentActions.ts:200-203`：`queueMicrotask(() => clearSessionStreams(sessionId))`——按会话清空 `byKey` 全部条目。
- **缺陷机制**：同会话多 agent 并行流式时，先 finalize 的 agent 会清掉同会话其它 agent **仍在流中**的条目 → 视觉断流/状态丢失。
- **修复建议**：按 messageId（或 agent 维度）精确清理已 finalize 的消息流，而不是整会话清空。

### R-07【黄轻】MessageContent 渲染期 setState（render-phase update）

- **证据**：`components/chat-message/MessageContent.tsx` 流式区块：resync 时 `setStreamKey(k => k+1)`、`fresh.length > 0` 时 `setStreamImgs` 在**渲染期间**调用（有 guard 收敛为一次性，`MessageContent.test.tsx` 覆盖三元降级）。
- **缺陷机制**：渲染期 setState 会触发同组件额外一次渲染；guard 未覆盖的路径有循环风险（当前逻辑幂等、可接受）。
- **修复建议**：补充注释锁定「仅一次」不变量；追加断言「resync 后同帧只多渲染一次」的回归测试（当前 102 行仅 1 个 it，单薄）。

### R-08【黄轻】useApprovalCountdown 100ms 硬编码 interval

- **证据**：`components/agent-card/useApprovalCountdown.ts`：`setInterval(..., 100)` 刷新剩余时间。
- **修复建议**：提取为常量（如 `TICK_MS`）并注释；或按 deadline 单次 setTimeout 派生，避免每 100ms 心跳（review.md §7 硬编码延迟精神）。

### R-09【黄轻】MessageSnapshots.test.ts 装饰性 mock

- **证据**：`api/MessageSnapshots.test.ts` 顶部 `vi.mock('../store/sessionStore')`，但 `MessageSnapshots.ts` 不依赖该模块（仅 import type SessionMessage）。
- **缺陷机制**：无用 mock 造成「测试与 store 耦合」的误导性观感（§7 测试真实性）。
- **修复建议**：删除该 mock。
