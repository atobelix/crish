# 01 · 事件覆盖完整性审计

> 战役：agent 循环过程的全链路可追溯性与原子化观测
> 维度：事件覆盖完整性——主循环每个阶段/子系统是否有事件发射，找出「无声动作」
> 日期：2026-08-14
> 审计类型：内部审计（只针对本项目代码，不参考外部软件）
> 范围：`crates/session-loop`（主循环全链路）+ `crates/orchestrator`（事件存储/恢复）+ `apps/agent-workbench/src-tauri`（壳层 run 驱动与事件发射）+ `crates/conex-types/src/events.rs`（49 事件契约）

---

## 一、结论摘要

1. **主链（run → turn → message → tool）事件覆盖基本完整、成对性良好**：`agent-start/end`、`turn-start/end`、`message-start/end`、`tool-batch-start/end`、`tool-start/end` 五对生命周期事件均有发射点且恒成对（`message` 由 `record_message` 单点保证；`tool` 由 `exec_batch`/`exec_single` 循环保证）。**主链达到可追溯，单工具调用从发起到结果的生命线可重建**（tool-batch-start → tool-start → approval-requested → approval-resolved? → tool-update* → tool-end → tool-batch-end）。

2. **但「全链路可追溯」判定为：不达标**。大量子系统动作是「无声的」——steering 决策细节与计数重置、safe point/控制总线消费、length 阶梯升级、hook 执行结果、缓存判定、escape watch 起停、**checkpoint 写库、stage summary 触发与产出、摘要后台调度全程**等只有 tracing 日志或完全无痕。尤其摘要后台任务（summary_dispatch/summary_coordinator）与 stage summary（壳层）是**事件流黑洞**——任务 spawn/重试/成功/失败全部不可见。

3. **两个契约事件是「死事件」**：`checkpoint-created` / `checkpoint-restored`（conex-types 契约 + 落库映射 + 同步白名单齐备，但**全仓无生产发射点**，grep 仅命中 normalize.rs 持久化映射与测试）；`tool-input-repaired` 同样**无生产发射点**。契约承诺了观测，运行期永不发射——从事件流无法得知检查点被创建/恢复、工具入参曾被修复。

4. **存在孤儿 turn-start**：abort/强停收敛路径（streaming_aborted、各 handler 起始 check_control、executing-tools 批后 check_control）在 `turn-start` 已发后直接收敛，**不经 turn_complete handler，`turn-end` 缺失**——turn 对在中断场景下不成对。

5. **工具批事件的契约字段被架空**：`tool-batch-start.calls` 与 `tool-batch-end.calls`（契约声明承载 `Vec<ToolBatchCall>` / `Vec<ToolBatchResult>`）发射时**恒为空 Vec**（executing_tools.rs:219/345），批级事件自身无法聚合出批内调用清单与结果；且事件体无 turn_index，工具事件与轮次的关联只能靠顺序推断。

## 四、事件成对性缺口

| 事件对                                   | 成对性                   | 缺口说明                                                                                                                                                                                                                                                                                                                                                         |

| turn-start ↔ turn-end                    | ❌ **abort 路径不成对**  | `turn-start` 在 prepare_turn 步骤 3 必发；但 `streaming_aborted`（streaming.rs:252-284）、streaming 起始 check_control（streaming.rs:46-48）、executing-tools 批后 check_control（executing_tools.rs:130-132）、apply_recovery Abort（loop_exec.rs:261-273）在 turn-start 之后直接收敛，**不经 turn_complete handler → turn-end 缺失**。孤儿 turn-start 无法闭合 |

## 五、原子观测要素缺口

| ------------------------------------------------------------ | ------------------------ | ------------------------------- | ------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| agent-start/end                                              | ✅                       | session_id                      | runId（信封）                   | reason/error ✅                      | —                                                                                                             |
| turn-start/end                                               | ✅                       | session_id + turn_index         | runId（信封）                   | tool_call_count（end）✅             | **事件体无 run_id**（依赖信封；delta 轨/离线重放时靠信封）                                                    |

**共性缺口汇总**：

1. **轮次关联缺失**：tool 域、approval 域、provider-diagnostic 事件均无 `turn_index`——跨域生命线重建需依赖消息顺序与 message-end.turnIndex 对齐。
2. **错误码不进事件体**：runtime-error 只有人读文案，结构化 code/category/retryable 的 retryable 有但 code 无。
3. **事件体 run_id 依赖信封**：除 run-terminal 外事件体均无 run_id——多 run 并发过滤依赖壳层信封注入正确（缺失时前端放行不过滤，events.rs:1094-1096 已注明）。
4. **时间戳口径不统一**：部分事件 timestamp（ISO8601 字符串），部分事件 epoch ms 字段（timer/cron/recovery 域），message 域无事件级时间戳——跨域排序需归一化。

## 六、建议方向（只给方向，不做方案选型）

1. **决策类动作观测化**：为「steering 评估命中/跳过与计数重置、length 升级、nudge 重试、熔断触发、预算钳制、安全点消费、控制意图入队/消费」补充轻量观测事件（或扩展现有 provider-diagnostic/runtime-steering 承载语义），至少 Delta 级可丢——不阻塞主链，只补可追溯性。
2. **死契约事件处置二选一**：`checkpoint-created` / `checkpoint-restored` / `tool-input-repaired` 要么在真实动作点接线发射（checkpoint 收口采集处发 checkpoint-created、恢复注入处发 checkpoint-restored、入参修复点发 tool-input-repaired），要么从契约与注册表收敛删除——契约与现实的漂移会误导所有事件消费者。
3. **后台任务事件化**：summary_dispatch / summary_coordinator 的 spawn/attempt/success/failure/放弃留痕进事件面（Soft/Delta 级），与 ContextCompressionEnd 的 summaryState 形成完整闭环。
4. **abort/强停路径成对补齐**：turn-end 的发射点从 turn_complete handler 上移到收口决策层（converge 前统一补发），保证 turn-start 恒有 turn-end 闭合；cooperative_stop 的 reason 透出到 agent-end 或诊断字段。
5. **事件字段补齐**：tool 域事件加 turn_index；tool-batch-start/end 填充真实 calls 载荷；approval-resolved 填 request_id 与裁决理由；runtime-error 事件体补 error_code。
6. **stage summary / checkpoint 观测化**：至少为里程碑触发与 checkpoint 落库各补一条事件（可复用 checkpoint-created 与 goal 域模式），使「跨 run 持久状态何时被改写」可审计。
7. **hook 结果观测**：HookDispatchOutcome（blocked/failed/timeouts）汇总为观测事件或并入 runtime-error——tool.pre 阻止、turn.end 建议 stop 在事件流可辨。
8. **工具执行内部阶段可见性**：中间件改写后的实际执行入参、approval-required 重试次数、幂等命中标记——在 ToolStart/ToolEnd 载荷或 tool-update 中显式携带（不新增事件类型优先）。
9. **run 创建面事件**：run 注册/启动失败路径补一条可观测事件（或复用 runtime-error），使 run 未进入 session-loop 前的事故也可追溯。
