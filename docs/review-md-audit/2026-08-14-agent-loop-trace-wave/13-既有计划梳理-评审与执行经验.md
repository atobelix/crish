## 一、评审维度与典型问题类型

### 1.1 五份评审各审什么

**评审分层结构**：独立方案（6 视角）→ REV-01/02/03（方案级评审：一致性/可执行性/纪律）→ 总计划框架（主 Agent 17 条裁决收敛）→ 维度详案（D-01…07）→ REV-04/05（详案级评审：冲突逻辑/派单就绪度）→ 定稿。**每层评审都有对应的裁决消化机制**：REV-01/02/03 的问题汇入总框架裁决，REV-04/05 的问题汇入定稿；REV-04 显式核对「裁决落实度」，防止评审意见悬空。

### 1.2 评审发现的典型问题类型（可复用于本战役评审）

1. **多方案重复认领同一文件域**（REV-01/02/03 均命中）：depcruise 修复三方声明（G-04/SR-08/CT-03）、前端 3 HARD 双方声明（G-03/SR-07）、note_commands.rs 三方竞争（B2/CT-01/SR-06 批⑥）——后果是「同文件双 Agent 互抹」。**对策：总方案唯一派单裁决，其余降级验收视角**。
2. **口径矛盾 / 悬空引用**：G-03「HARD 只能拆」vs SR-07「或按 `--update` 登记」（经读脚本源码 `check-line-counts.mjs:160-168` 验证 G-03 为真，登记路径不存在）；SR-06 验收「≥80% 以两方案定稿口径为准」——定稿前不存在的口径是悬空引用。**对策：定稿前逐项拍死，执行轮不接受「以定稿为准」类措辞**。
3. **行号锚点 / 数字漂移**：核心文件持续增长导致锚点普遍失真（core_run_commands 15101→16637→17510→17828；「5755 处 cfg(test)」实测仅 11 处；G-02 批表相加 86≠声称 88；messages.find 13 处实测 12 处；行数双口径系统性差 4–8%）。**对策：派单前开工动作三件套（G-00 快照 + git status + 锚点重定位），行数口径统一以门禁脚本输出为权威**。
4. **过期项未核销**（问题池 #8/#9/#24）：`19-实现波调度状态.md` 已登记 SD-22…49 全部落盘、CONN-D×G2′ 已合入，问题池仍引用旧数字；00-summary 与 19 双源漂移。**对策：状态账核验先行——消费问题池前逐项对照当前树实测核销，禁止重派已落盘整包**。
5. **伪断言 / 不可测断言**：REV-02 点名「人工核对」「二选一」「或（DOM 或状态）」三类弱断言——「`rg "mod tests"` 零命中 ≠ 测试归零」（实现段散落 11 处 `#[cfg(test)]`）、「逐点人工核对」不可机器执行。**对策：断言全部命令化 + 明确二选一各自的可证伪条件**（如「保留 → ≥1 生产者+≥1 消费者 grep；删除 → rg 零命中」）。
6. **编号空间撞车**：audit 报告建议「SD-26…31」与 block 波已占用的 SD-26…45 同名不同义。**对策：总方案统一编号空间（域前缀），禁裸引用歧义名**。
7. **「未真跑」转真责任悬空**（REV-05 风险 5）：全部详案声明未真跑，点名测试锚依赖执行轮真跑。**对策：派单卡强制附「真跑验证清单」（逐单元列命令），主控验收以命令输出日志为准，拒收「源码形状」代「真跑绿」**。
8. **批粒度自相矛盾**：SR-06「每批 1–2 个最大文件」标题 vs 批表 6–14 文件；「一批 = 1 任务单元」则违反「一包一刀」。**对策：每文件 = 1 任务单元，批仅为派单分组（每轮 2–3 文件）**。

**轮次边界逻辑**：① 每轮 8–10 个单元（定稿建议 5–12，实际维持 8–10）；② **⚠ 前置条件不满足即顺延，用同轮可并行单元换入**（轮 4/5 的 SR-01、G-03c、B2、S2 连续顺延两轮）；③ 轮 3 末固定的「冻结+收口」动作点；④ 轮末主控统一 `git commit --only` 提交（子 Agent 一律不提交）；⑤ 轮末输出「门禁状态 Δ 表」做环比（crate-size FAIL / line-counts HARD+VIOL / depcruise / 结构债红级四维）。实际共 8 轮形状，ROUND1–5 为已写汇总的前 5 轮。

### 2.2 轮次汇总格式（ROUND*-汇总.md 模板）

1. **元数据表**：轮次（R3-x）/ 派单数与完成情况 / 提交数（主控统一）/ HEAD / 子 Agent 异常记录（空返回 + 处置）/ 主控修复记录 / 环境动作。
2. **一、单元完成状态表**：单元（含合单）/ 内容（改动摘要，带「→ 行数」量级）/ 验证结果（**真跑结果**：cargo test 数字、vitest 数字、rg 零命中、exit code）/ 结果 + 提交号。
3. **二、门禁状态 Δ 表**：上一轮 → 本轮收口（crate-size FAIL / line-counts / depcruise / 结构债），每行带说明（哪些是并行域增量、哪些是本方收敛）。
4. **三、主控介入/修复记录**：子 Agent 遗留的编译错误（缺 `#[path]` 接线、自引用导入）、eslint 遗留（未用变量）、类型错误——逐条精确 edit 修复并说明。
5. **四、待处理清单（下一轮输入）**：顺延单元 + 新发现缺口 + 收口轮事项（编号化，供下轮消费）。
6. **五、下一轮预告**：按定稿轮次表 + 实际换入候选。

### 2.3 执行文档格式（单单元产出）

每单元一份 `execution/NN-单元-主题.md`：元数据表（轮次/单元/任务卡/基线文件/纪律）→ 实况（登记/清理/跳过三清单，各带实测行数与判定依据）→ 真跑验证记录（命令 + 数字 + exit code）→ 纪律声明（未 git 写、未 `--update` 全量、未登记并行域 M、未 `--no-verify`、未派生子 Agent）→ 诚实边界句（≠ EL / ≠ 打开完成）。

## 三、踩坑教训清单（规划阶段需避免的）

### 3.1 规划阶段就该避免的（定稿前拍死）

1. **多方案认领不收敛就派单**：depcruise/3 HARD/note_commands 三类「多方声明同文件」在 REV-01/02/03 反复出现——**规划期唯一派单裁决，执行期同文件串行链写死**（note_commands 链：SR-06 批⑥ → B2 → CT-01）。
2. **验收断言含「人工核对 / 二选一 / 或 / 以定稿口径为准」**：全部在评审期硬化成可 grep、可命令、可证伪断言；「真跑验证清单」必须作为派单卡附件（REV-05 §四 逐单元列命令）。
3. **行号锚点与门禁数字直接照搬审计报告**：锚点 1/3 漂移、行数双口径（Measure-Object vs 脚本）差 4–8%——**派单前开工动作三件套写死为执行约束而非建议**：G-00 快照（真跑四门禁）+ `git status` 复核目标文件非 M + 锚点重定位；一切行数验收以脚本输出为权威。
4. **过期问题池项直接消费**：#8/#9/#24 已落盘仍进方案——**消费问题池前逐项核销（对照 19/状态账/当前树实测）**，核销动作内建进每个结构/连通单元的开工作业。
5. **测试资产仅静态核验**：SR-05 拆分宣称「5 旁挂 46 用例零删除」，补验发现仅 1/5 旁挂落盘、40 用例只剩 8——**拆分类单元验收必须「点名测试锚真跑」，禁止以行数/接线静态形状替代**（SR-06d 教训同族：子 Agent 缺最终消息时也必须核查 cargo check 真绿，不能只凭落盘判定完成）。
6. **冻结≠收口的双动作混淆**：冻结（功能写入停止）与收口（提交完成）是两件事；「冻结宣布后并行域仍在动」导致 SR-01 连续两轮顺延——**规划期明确冻结窗口由谁宣布、并行域如何配合，或为依赖方预留换入预案**。

### 3.2 执行期高频坑（组织执行轮时需预期）

1. **子 Agent 空返回但已落盘**：CT-03/CONN-01/SR-06d/executor/write_paths 多次出现——处置标准：先核查落盘 + `git status`，再核查**真跑验证绿**（SR-06d 教训），再按附录 B 接续/重派。
2. **主控高频小修复**：eslint 未用变量、类型误改（Pick<LayoutStore>→Pick<SettingsStore>）、import React 未用——每轮 1–2 处，属预期成本，轮末统一清。
3. **并行域 M 文件反复顺延**：SR-01/G-03c/B2/S2 连顺延两轮——轮次表需内建「⚠ 顺延 + 换入候选」列；顺延单元逐轮复查而非永久搁置。
4. **新测试旁挂自身超限**：shell_tests 1462 / executor_tests 1020 / wait_subagents_tests 1098——拆分产出新文件立即触发 crate-size FAIL，需「测试旁挂豁免/登记」专项约定（G-01 语义与豁免面协调）。
5. **门禁实红期间 CI 必红**：crate-size FAIL 88 起点 + line-counts HARD 4——验收以本地真跑为主、CI 绿仅追认；G-00 快照如实记录双红基线；「门禁红禁称绿」条款前置。
6. **会话内数字仍持续漂移**：G-02 批④ 登记 137 条、轮内二次收紧（core_backend 1607→1611、router 3391→3686）——登记/收紧类单元预期「写基线前再实测一次」。
7. **钩子全工作区 diff --check 阻塞**：他人文件 trailing whitespace 阻塞全部提交——最小 whitespace 修复或上报主控（AGENTS.md §3.5 处置）。
8. **sessions.db 运行期噪声**：git 跟踪 + 持续漂移夹带进 git status——执行期登记表给「运行期面」单独归类，收口轮治理排除面。
