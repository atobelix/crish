## 一、维度目标

**一句话**：把引擎已有的 49 类事件全量接进前端消费面（生成绑定 / 归一器 / dispatch 三链同步 + 连续性命中），以「live 信封 + 历史 read_run_events」双数据源落地 run 级时间线与观测回填，同时闭合安全审计「放行后执行 / 拒绝 / 非 run 上下文」三块盲区与三处 decision 展示歪曲——**不加新表、不加新 IPC、不加新指标系统**。

**逻辑递进图**（先有绑定 → 再有归一器 → 接分派 → 上 UI → 补安全面；UI 历史面依赖 D-01 读侧，审计键依赖 D-02，落库双发依赖 D-04）：

```
[契约面先行]  OV-01 生成绑定 41→49 + --check 幂等 + TS drift 钉测 ──┬─→（契约变更窗口末与 D-03/SA-04 统一 regen）
                                                                    │
[消费面补全]  OV-02 8 类宽容归一器（样本已存在，只补归一器）──────────┘
                    │
                    ▼
              OV-03 dispatch 49 键全注册 + continuityHandlers 接线
              （恢复横幅数据源 = D-01 读侧；intervention choices 最小消费，契约随 D-03）
                    │
                    ▼
[UI 观测面]   OV-04 RunTimelinePanel 最小形态 + projectRunTimeline 49 键映射 + 日志面板半项
                    │（live=信封；历史=read_run_events 依赖 D-01）
                    ▼
[增量与回放]  OV-05 engineCursor 增量补事件（三触发源禁轮询）
              └→ OV-06/07 事件表回填消费面（子代理重放主事件快照降级 + 观测 store 回填）
                    │（OV-06 依赖 D-01 读侧信封完整；OV-07 对未落库域诚实留缺口）
                    ▼
[归属加固]    OV-08 广播事件双消费防护（无 runId 白名单放行 + sessionId 过滤臂）
                    │
                    ▼
[安全审计闭合] SA-01 放行后执行补审计 ── SA-02 非 run 审计落库双发（依赖 D-04 落库点）
              SA-03 decision 三处展示归位（Rust 枚举不动）
              SA-04 ApprovalResolved 补 reason（契约窗口随 D-03）
              SA-05 审批拒绝入审计（denied/blocked 语义区分，tool_call_id 依赖 D-02）
```

**关键裁决锚点**（总框架 R-33~R-37 定稿，不得偏离）：

- R-33：生成器 41→49 + `--check` 幂等 + TS 侧 drift 钉测 + 补 8 类宽容归一器（**8 条样本已存在**于 normalizer-drift.test.ts:297-363，工作是补归一器非补样本，目标 8 passed/0 failed）+ dispatch 接线 continuityHandlers（**接线不核销**）。
