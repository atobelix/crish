## 一、维度目标

**一句话**：以「run 级 trace_id 作为日志-事件双通道共享关联键」+「span 上下文原生传播修复（instrument 取代 enter、spawn 显式继承）」为主线，把日志侧改造成「每一行可归属到 run/会话、可钉到事件链、崩溃现场可还原」的观测通道，与事件侧（权威链）以 `(trace_id, run_id, sequence)` 三元组对齐，双通道从「人工拼图」升级为「机器可查」。

**逻辑递进图**（单元间依赖序：契约根基 → 上下文传播 → 补点 → 崩溃/脱敏并行 → 清理 → 测试收口）：

```
TR-01 信封面（trace_id 信封 4 处同步 + run 级生成 + 事件桥注入）
  │  ← conex-types 契约窗口（与 D-02/D-03/D-06 字段同窗，REV-02 问题 1）
  │  ← engine_channels.rs 注入点与 D-04 PC-01 伪 runId 同构造点串行（REV-02 问题 3）
  ▼
TR-02 日志面（.instrument() 骨架函数取代 span.enter() + 7 spawn 点显式继承 + run span 三字段）
  │  ← trace_id 概念先立（TR-01），span 字段才有第三元；core_run_commands.rs 同文件串行
  ▼
TR-03 补点面（recovery 阶梯 1-4 每阶梯 ≥1 info + restore 逐条 interrupted + 干预/steering/turn 边界）
  │  ← 上下文可靠后补点才有归属；tool_call_id 子项排 D-02 之后
  │  ← recovery.rs / restore_manager.rs 与 D-01 同文件串行
  ├──────────────────────────┬───────────────────────┐
  ▼                          ▼                       ▼
TR-04 崩溃面（backtrace×2 +     TR-07 脱敏面（file 层      （两批并行：不同文件域，
  单槽活跃 run 注册表 +          写出 chokepoint 兜底打码     TR-07 与 TR-04 互不阻塞）
  环形缓冲最后 512 行）           + 关联键白名单永不打码）
  │  ← 依赖 TR-02 的骨架入口       │  ← 既有 2 接线点不动
  ▼  （drive_run_loop 挂注册表）    │
  ▼                               ▼
TR-08 清理面（main.rs 启动一次性 cleanup_logs 接线 + crash 保留 3→10）
  │  ← 依赖 TR-04 的新 crash 结构/保留语义
  ▼
TR-06 测试面（LogCapture 6 族断言资产化，依赖 TR-01/02/04/07 全绿后收口）
```

**归组表**（本维度承接问题 → 单元）：G-30 无共享 trace id → TR-01；G-31 span 上下文不确定性丢失 → TR-02；G-32 编排/恢复层日志空白 → TR-03；G-33 崩溃留痕缺料 + cleanup_logs 死代码 → TR-04 + TR-08；时间三轨异质 → **归 D-01**（created_at 毫秒化并入 v9 迁移）；脱敏覆盖面 → TR-07；无日志侧回归测试 → TR-06。

8. **crash 文件消费端不在本维度**：前端日志面板/运维工具读取 crash 新段归 D-06 或后续战役；本维度只产写（新增段向后兼容，旧解析不坏）。

10. **不构成 EL 关账**：本详案是建议面，验收全部以执行轮真跑记录为准；「日志可归属」≠「全链路可追溯」整体达成，其余缺口（持久化/读侧/前端）归其它维度。
