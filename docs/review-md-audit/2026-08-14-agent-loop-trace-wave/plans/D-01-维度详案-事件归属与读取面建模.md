## 一、维度目标

**一句话目标**：让「run 归属」成为 events 表第一类数据——**列 + 完整信封并用**（列 = 查询权威、信封 = 还原权威，同一注入点产出，写面测试锚定二者不漂移），写面全部持久化路径收敛到带 run_id 的单一落库通道，读面消灭静默丢弃并修通按 run 查询，迁移单波 v9 落地。

**逻辑递进图（任务单元依赖序）**：

```

   │  列存在后，写面才有落点
   ▼
DM-02 conex-db 事件域（append_event 写 run_id 列 + created_at 显式毫秒 + query_events_by_run 新查询）
   │  conex-db 面先行，Store trait 面才有可代理的签名
   ▼
```

**关键裁决锚点**（本维度内不可再动摇）：

- 列 + 信封并用（R-01，01 方案 R1）：不择一、不做 start_sequence 列（01 方案 R3，登记为可选增强）。
- 写面注入 = EventQueue 构造期绑定 `run_id: Option<String>`（R-02，01 方案 R2），非 push 逐次传参；13+ 广播构造点零改动（**EventQueue 构造点本身全要改**，REV-02 §五已点名，派单卡写清）。
- 不扩大 reserve_sequence 直写面（R-03 裁决 C-6）；recovery_store 直写改规范化（补 type 标签）。
- goal-* 三事件归**轮次域**（R-06，裁决 C-2 采纳 04 PC-07）：不归任何 run，run 查询不含；其余终态后尾事件（审计排空/子代理收尾）按发生时 run 上下文归属，run 查询含 tail。
- 存量行 run_id=NULL 不回填（R-07，诚实未知）；created_at 毫秒化与迁移同波（R-08）。
- D8 合成 fallback **实现**（R-04，主案实现而非登记核销——禁止退避；见 DM-06）。
