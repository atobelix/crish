## 一、维度目标

**一句话：把「横向链路」从四处断开修成两条可反查的链——一条以 `tool_call_id` 为键（工具调用 → 安全审计 → 子代理 spawn 链），一条以 `subagent_run_id + session_id` 为键（父会话三事件视图 ↔ 子会话完整事件流），键在唯一构造点注入、三处消费点接线、映射落显式存储、死路径按 CT-03 分类法收口，全部新字段按 S5 范式钉契约测。**

## 五、诚实声明（未验证项）

1. **本详案未真跑任何测试**（方案轮只读）；全部验收断言以执行轮实际输出为准，行号锚点派单前必须重定位。
2. **「任务注册表 tool_call_id 记忆能力」未在代码中验证**：10 检查 §六.1 声称「壳层任务注册表已有 tool_call_id 记忆能力」，本会话实测 `bg_registry.rs` 无 tool_call_id 字段——LK-03 任务域真值化的真实注入点（任务工具 adopt 链路是否经 ToolContext 传 call id）需执行轮实测；若任务启动面确实无工具调用上下文，则按「置 None + 诚实注释」落地（禁空串），与「真值」同为有效完成态。
3. **kill 直发 ended(cancelled) 与收口兜底的双发幂等**：kill 直发后 run 收口时 `on_subagent_terminal` 是否会二次发射 ended，需执行轮实测行状态/记账释放的幂等条件；完成定义按「实测后落地防护」表述，未预写实现。
4. **flow 路径 started/ended 的子会话 id 装配**：FlowScheduler 发射点（flow_graph.rs:1068-1097 / :1194-1231）从 `spawn` 结果取子会话 id 的路径（result 信封含 sessionId）需执行轮实测，若结果对象不可达子会话 id，则经 flow_state 映射或 spawner 记账补齐——不因取不到而跳过发射。
5. **resume_subagent 的「spawn 时写 path_json」可行性**：SessionTree 根→叶路径在 spawner 装配时是否可得（父路径上下文），需执行轮实测；若初始 spawn 路径不可得，退化为「命令面显式标注仅 fork 后可用」+ derive_task 改源（b 项），两项任一可证伪即验收成立（主控 R-14 三选一保留）。
6. **R-12 广播面执行风险（LK-05）**：started/ended 补广播（先落库后广播、runId=父 run、前端幂等键）由本详案 **LK-05** 唯一执行；发射面载荷真值（LK-02 parent_tool_call_id + LK-04 subagent_session_id）先行保证。若 LK-05 执行轮发现载荷缺口，缺口项回归 LK-02/LK-04 核验；前端消费（幂等键去重）归 D-06。
7. **本详案不构成任何 EL 关账**：链路键接通 ≠ 全链路可追溯；测钉绿 ≠ 消费面完整；cancelled 真值 ≠ 前端展示完善（stopped/failed 映射核验归 D-06）。
8. **未验证边界**：前端 subagentHandlers 消费细节（转引 03 检查未展开）、push/移动端场景、escape_watch holder 细化（04 §五.4 可选增强，本战役后置）、progress 补发升级（后置决策）。
