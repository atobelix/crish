## 一、维度目标

**一句话**：把「宣称落库」与「实际落库」逐事件域对齐（timer/cron 明确不落库、task 终态补落库、approval 双发收口、迟到事件归属定案、失败路径不假装可回放），并把「背压级 + 是否落库 + 桥丢帧优先级」三套口径收敛为**单一分类函数产出**——让每个动作的持久化状态不再靠「不走队列」侥幸成立，且从结构上消灭多套分类漂移。

**关键裁决锚点**（本详案必须遵守，不得偏离）：

1. **R-22**：timer/cron 本战役明确不落库（sessionId 空串 FK 硬约束 + 无 run 可标 failed）——但必须完成伪 runId 契约对齐 + 「仅实时轨」分级标注；「定时器会话化 R-CF3」登记为后续战役前置依赖（**非砍项**）。
2. **R-23**：task 终态 4 事件补落库走 **D-01 规范化落库点**（run_id=NULL + type 标签，**不新建 reserve_sequence 直写通道**）；output/heartbeat/suspicious 保持 Delta/Soft + 显式 persist=false；task-started 的 sessionId 非空实测前置。
3. **R-24**：approval-requested 保留实时轨（sequence=None）+ 收口 emit skip（T09.1 delta skip 同构）；前端 EventRouter（`apps/crish-desktop/src/api/chat-bridge/EventRouter.ts`，REV-02 已修正实际路径）加防御守卫 + 契约测。
4. **R-25**：conex-types 新建 `EventPolicy{backpressure, persist, bridge_priority}` + 单一 `event_policy()` match 产出三值；EventClass / drop_class_of / event_backpressure 三消费方迁移；注册表条目扩展三字段，registry_drift 三字段双向锁定。
5. **R-26**：迟到事件归属定案写入 read_run_events 契约（同 runId 尾事件 = run 收尾区；goal-* 归轮次域；空闲态归会话域）。
6. **R-27**：不做自动重试（维持「不假装可回放」）；finalize_failed 改 best-effort + 失败计数观测。

**与其它维度衔接**：本维度是「数据根基（D-01）→ 链路接线（D-02）→ 事件补全（D-03）→ **落库对齐（D-04）** → 日志统一（D-05）→ 消费闭合（D-06）」链上的第四环——依赖 D-01 的规范化落库点与 run_id 列；产出（落库语义 / 分类口径）被 D-05（信封 trace_id 追随落库面）、D-06（读侧消费与 normalizer-drift 镜像）消费。
