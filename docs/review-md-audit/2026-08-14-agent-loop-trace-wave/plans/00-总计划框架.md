# 00 · 总计划框架 —— agent 循环全链路可追溯性与原子化观测

> 战役：2026-08-14 agent-loop-trace-wave（主控定夺稿 v1，待详案轮与评审修订）
> 目标：让 agent 循环中的**任何一个动作**都有完整、连贯、单一的全链条记录——能从任意节点回溯整条链、能对每个原子动作单独观测，支持事后排查与循环过程改进追踪。
> 输入：检查轮 10 份（01~~10）、梳理轮 3 份（11/12/13）、独立方案 6 份（01~~06）、评审 3 份（REV-01/02/03）。
> 本框架只谈逻辑依赖与任务单元，不谈时间与优先级；问题一律同权。

---

## 一、战役目标与完成定义（效果锁）

1. **按 run 追溯畅通**：给定任意 run_id（含子代理 run），能从事件存储导出该 run 的完整、有序事件链（含终态后尾事件）。
2. **横向链路可反查**：安全审计 ↔ 工具调用 ↔ 子代理 ↔ 父 run/turn 的关联键真实接线，任意节点可双向回溯。
3. **事件面完整**：循环每个阶段的动作都有事件或显式登记的日志留痕；start/end 恒成对；原子要素（时间戳/耗时/id/结果）齐备。
4. **落库语义一致**：每一类事件明确「落库/不落库」并实现与文档一致；分类口径单一。
5. **日志-事件双通道统一**：共享 trace_id 关联键；日志带可追溯上下文；崩溃现场可还原。
6. **前端与审计可观测**：49 类事件全量解析；UI 有 run 级时间线；高危操作全链路可追责。
7. **契约与测试同步**：所有新事件/字段走契约变更窗口 + registry_drift + normalizer-drift + S5 测钉，不留死事件、不留未接线死代码（核销需登记）。

## 三、维度划分与逻辑递进关系（主控裁决）

六个维度按逻辑递进组织：**数据根基 → 链路接线 → 事件补全 → 落库对齐 → 观测统一 → 消费闭合**。前序产出是后续输入，不得跳步。

```
D-01 事件归属与读取面建模（数据根基：run_id 列 + 信封落库 + 读侧规范化）
        │
        ▼
D-02 横向关联键与链路接线（tool_call_id / parent_tool_call_id / 子会话映射）
        │ （D-01 保证事件可切分后，键才有可落之地）
        ▼
D-03 事件面补全与原子要素（死事件/无声动作/turn 对/工具要素/输入留痕）
        │ （契约变更集中窗口，随 D-01/D-02 新字段同步）
        ▼
D-04 落库覆盖对齐与事件分类统一（timer/cron/task/approval/分类单一口径）
        │ （依赖 D-01 的规范化落库点）
        ▼
D-05 Trace ID 与日志统一（S2 承接：trace_id 信封字段 + span 注入 + 崩溃留痕）
        │ （trace_id 数据面追随 D-01 的信封落库；日志字段依赖 D-02）
        ▼
D-06 前端观测面与安全审计闭合（49 类解析 + 时间线 + 审计盲区 + 展示归位）
        │ （依赖 D-01 按 run 查询 + D-04 落库语义 + D-02 关联键）
```

### D-01 事件归属与读取面建模（根基，最大件）

- **R-01**（采纳 01 R1）：events 表加 `run_id` 列（`(session_id, run_id, sequence)` 复合索引）**且** payload 存完整信封 JSON（含 runId/sequence/schemaVersion）——列解决查询、信封解决还原，二者并用各司其职。
- **R-02**（采纳 01 R2 修订）：写面注入收敛——EventQueue 构造时绑定 `run_id: Option<String>`，push 内部经 `normalize_envelope` 构造信封落库；`append_event` 签名加 run_id（Store trait/LocalDb/两实现/PersistedEvent 连锁）；13+ 广播构造点保持零改动。
- **R-03**（裁决 C-6，采纳 01 哲学否决 04 直写）：task/审计等旁路落库统一改走 EventQueue 规范化落库（run_id=None 或真实归属），**不扩大 reserve_sequence 直写面**；recovery_store 直写改规范化（补 type 标签）。
- **R-04**（裁决 G-02 责任归属，补 REV-01 黑洞）：读侧规范化与防御入本维度——`parse_envelopes` 对 run-interrupted/recovery-* 补 type 标签或显式透出原始行，消灭静默丢弃；D8 合成 fallback 实现或登记核销。
- **R-05**：按 run 查询修复（read_run_events_impl 修通 + 契约文档对齐）；Store trait limit 下推；信封字段回填（sequence 列 → 信封输出）。
- **R-06**（裁决 C-2，采纳 04）：goal-* 尾事件归属轮次域（goal-round-started 在 agent-start 前发射，查询不并入 run 链）；其余终态后尾事件（审计排空/子代理收尾）按发生时 run 上下文归属，run 查询含 tail。
- **R-07**：迁移单一波 v9（run_id 列 + 索引 + created_at 毫秒化 + D-02 的 sub_session_id 列合并入同波，migrate.rs 单写锁，备份跳过区间扩至 5..=9；02 LK-04 的 v7 修正为并入 v9）；存量行 run_id=NULL 不回填（诚实未知）。
- **R-08**（采纳 05 TR-05 合并）：created_at 秒→毫秒（strftime %f）与迁移同波；排序唯一依据 = sequence 写入契约文档。
