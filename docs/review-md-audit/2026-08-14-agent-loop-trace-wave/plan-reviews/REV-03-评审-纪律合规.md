## 三、退避裁判逐条论证（任务书点名 6 处）

### 3.1 04 PC-01「timer/cron 明确不落库」——**论证存在方法论矛盾，需主控裁决 R-CF3 边界**

- **论证链**：① FK 硬阻塞（sessionId 空串过不了 `FOREIGN KEY (session_id) REFERENCES sessions(id)`）；② timer/cron 无 run 上下文，EventQueue 失败收口语义绑定 run 状态机，定时器域无可用的持久化通道；③ 会话化决议属 R-CF3 跨域契约变更；④ 「不假装」原则（挂着 Critical 不落库不如显式声明）。
- **矛盾点**：同一方案 PC-02 对任务域论证「任务事件有真实会话归属（事件体带 sessionId 形态）——FK 可行，与 PC-01 的 timer/cron 阻塞本质不同」。但 **timer 的 sessionId 空串是可修复的现状**（`timers.rs:198-209` 注释自述「会话归属语义在 R-CF3 定时器会话化时定稿」）——若 PC-02 能为 task 补/确认真实会话归属，timer 同样可以；「每引擎一个」是注册表级设计决策，不是物理约束。04 方案把「可补的归属字段」当成「不可跨越的 FK 障碍」，论证不一致。
- **效果锁视角**：timer 触发是「动作」之一，战役目标「任何动作都有完整全链条记录」；02 检查轮建议 6 首选「按 Critical 分级把 timer/cron 纳入 EventQueue 持久化」，次选「显式修订文档与分级」——04 选了次选，且登记 R-CF3「本战役内不可闭合」。这不是检查轮授权的二选一落空，而是**在两项都可行时选了更弱的一项**。
- **判定**：**最接近退避的定案**。不构成一票打回（论证完整、替代事实源明确：session_meta fired 标记 + steering 续 run 链），但 R-CF3 边界必须由主控/用户裁决：若 R-CF3 会话化不在本战役推进，需用户确认「timer 触发事件面不持久化」是否可接受；若用户要求落库效果，PC-01 决策 A 需翻转为「补会话归属 + 落库」（先例 = PC-02 任务域路径）。

### 3.2 02 LK-07「禁实现真超时」——合理范围裁决，「禁」字表述过强

- timeoutMs 是**功能承诺**（工具入参）而非可追溯性承诺；本战役目标是「记录链条」，不要求「超时」功能本身。检查轮 03 建议 6 明示「或实现或移除」二选一。移除死参数 + 入参保留兼容忽略 = 收口契约与现实的漂移，方向正确。
- **问题**：①「禁」字把「本战役不实现」上升为「永久禁止」——超时是用户可见契约面（模型传 timeoutMs 期望超时语义），移除入参语义是否需用户点头，方案未请示；② 论证里「L3 kill 面已可终止」是现状说明，不是「超时不可行」的论证——好在方案没有用「超时太难」当理由，落在范围裁决上。
- **判定**：合理复杂度控制（非退避）。建议总案将「禁」改为「本战役不实现，契约字段删除；真超时登记为功能项待用户裁决」。

### 3.3 03 G3「不建工具域实时轨」——边界可接受，**论证夸大且未走先例评估路径**

- **论证缺陷 1**：「实时轨 = 新事件通道，违反『加字段不加系统』红线」——不准确。DeltaSink（message-delta 实时）与 BridgeAuditSink（审计实时）是既有通道，检查轮 04 建议 3 明示「对齐 DeltaSink/BridgeAuditSink 先例」——工具域事件实时发射**可复用现有桥**，不是新系统。用「新事件通道」定性夸大了成本。
- **论证缺陷 2**：检查轮 04 建议 3 的选项是「评估实时通道」或「至少审批挂起期补 tool-pending 表达」；03 方案未走「先评估先例通道可行性」的路径（无成本评估、无复用分析），直接判「不建」——从形式上是「用反过度设计红线当刹车」的退避模式（红线本身真实存在，但应先论证「复用先例通道」为何仍违反红线，而非预设其为新系统）。
- **论证成立部分**：① 非审批工具执行毫秒~秒级，批收口延迟对可追溯性影响有限；② G2 执行时刻打点修复后，事后重建精度不受实时性损失影响；③ 审批挂起可见性已有（run 状态机 awaiting-approval + list_pending_approvals）；④ 「实时反馈」是产品体验面而非追溯链完整性，触发条件（>N 秒场景/用户要求）已登记。
- **判定**：**合理复杂度控制但论证需修正**——把「新事件通道」改为「复用既有桥的接线工作量评估」并给出先例评估结论（或补一行「DeltaSink 复用不可行，因为 X」）；实时轨登记触发条件保留。若总案裁决做实时轨，路径已指明（对齐 DeltaSink）。

### 3.4 04 PC-06「不做自动重试」——**完全合理，非退避**

- 检查轮 05 §4.2 对「无自动重试」的描述是**正面语义**（「不假装可回放」是正确收口）；没有任何检查轮建议要求引入自动重试。PC-06 是对现状语义的显式定案 + 论证（部分成功歧义、Q25 无空洞被破坏、CT-01 先例、瞬时失败占比未实测），并补两个小修（finalize_failed best-effort、失败计数）。
- **判定**：合理定案；「未实测 busy_timeout」已诚实声明回审条件，符合诚实纪律。

### 3.5 05「不做 OTel trace 树 / 不建自定义 Layer / 不建 trace_id 列」——**完全合理**

- S2 蓝图（用户已裁决的上一战役定稿）锁定「禁 OTel、禁新 span 层级」；trace_id 与 run_id run 级 1:1，「按 trace 过滤 ≡ 按 run 过滤」——不建列有正确性论证（列 = 重复建设），非砍项。

- **判定**：合理复杂度控制（有用户已锁契约 + 正确性论证双支撑）。
