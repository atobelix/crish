## 一、结论摘要

**判定：6 份详案整体达到「可进入执行轮」水平——R-01~R-37 全部有承接单元、REV-01/02/03 的阻塞级问题（读侧黑洞领衔、迁移 v9 合并、契约集中窗口、EventRouter 路径、编号体系）均已消化落实；但存在 1 个必须主控拍死的悬空（PC-03 广播无归位）、1 个迁移清单不一致（runs.model 列漏入 v9）、1 处前端对裁决的实质误读（OV-07 误读 R-23 task 落库口径）以及若干同文件双认领与旧编号引用错位，建议**修订后定稿进入执行轮**，不改则执行轮派单矩阵会踩雷。**

主要障碍（按阻断程度排序）：

1. **subagent-started/ended 广播实现悬空（最高）**：总框架 R-12 唯一派单 = 04 PC-03；D-02 详案撤销 LK-05（并入 PC-03）不建单元、只保证载荷真值；D-04 详案明确「PC-03 不在本维度」。**「先落库后广播」顺序约束与实际广播接线没有任何详案单元承载**——两详案互相指向对方，均不认领。
2. **v9 迁移清单缺 runs.model 列**：D-03 EV-13 声称 runs.model 列「并入 v9 迁移窗口」，但 v9 唯一执行者 D-01 DM-01 的完成定义/文件域锁/验收断言均无 runs 表改动——迁移输入清单不一致，执行轮必漏。
3. **D-06 OV-07 误读 R-23**：将 task 域整体视为「本战役不落库不回填」，与 R-23/D-04 PC-02「task 终态 4 事件补落库（Persist）」直接矛盾，导致前端永久缺 task 终态回填。
4. **read_run_events IPC 通道悬空**：D-01 DM-07 明示退役命令「不恢复 IPC 注册」，D-06 OV-04 历史补拉却假定「Tauri command 已存在」——历史时间线无可用通道。
5. **归属契约双写**：D-01 DM-08 与 D-04 PC-07 认领同一文档面 + 测试锚重叠。

## 三、详案间冲突清单（逐条）

### 冲突 #1 · subagent 广播实现悬空（PC-03 无归位）【阻断级】

- **冲突点**：总框架 R-12 裁决「started/ended 补广播（先落库后广播，runId=父 run）= 04 PC-03 唯一派单；02 LK-05 撤销并入」。
- **D-02 立场**：LK-05 撤销不建单元，只保证发射面载荷真值（LK-02/LK-04），「投递顺序约束与 D-04 串行注记见 §四」——D-02 §四 串行表将「**D-04 PC-03 广播**」列为 subagent_spawner.rs 串行链末端。
- **D-04 立场**：修订注记②「PC-03（subagent 广播对称）归 D-02 R-12 唯一派单，本详案不含」；单元表「PC-03 不在本维度」。
- **后果**：两边互指、均不认领。「先落库后广播、runId=父 run、前端幂等键」三要素无五要素承载（无完成定义/无验收断言/无文件域锁）。D-02 LK-05 空缺理由「并入 D-04 PC-03」指向一个不存在的单元。
- **建议**：主控二选一拍死：① D-02 恢复 LK-05 单元（按 R-12 语义写全五要素，串行排在 LK-02/LK-04 之后）；② D-04 恢复 PC-03 单元（按 R-12 语义，与 D-02 载荷单元串行）。**禁止继续「互指」状态进入执行轮。**

### 冲突 #2 · v9 迁移清单缺 runs.model 列【阻断级】

- **冲突点**：D-03 EV-13 完成定义②「runs 表补 model 列……schema 变更**并入 v9 迁移窗口**（D-01 迁移唯一执行，本单元只出列定义与写回点设计）」；总框架 R-20 原措辞「并入 v9 迁移窗口**评估**」。
- **双方**：D-03 EV-13 认定已并入；D-01 DM-01 完成定义（LATEST_VERSION/迁移臂/备份区间/备份 DDL）与验收断言（rg 锚点）**无任何 runs 表项**，文件域锁不含 runs 相关面。
- **后果**：v9 实际执行者不知道 model 列，执行轮按 DM-01 派单必漏该列；EV-13 的「设计交付 D-01」在派单卡层面无登记点。
- **建议**：主控将 runs.model 列 DDL 显式并入 DM-01 完成定义（同波三件事变四件事，迁移测试加 model 列断言），或 EV-13 交付物升级为「可直入 DM-01 的 DDL 片段 + 写回点设计」并登记于 DM-01 串行注记。

### 冲突 #3 · D-06 OV-07 误读 R-23（task 落库口径）【高】

- **冲突点**：OV-07 完成定义 4 与诚实边界句均写「未落库事件域（timer/cron/**task**——D-04 定案本战役不落库）」→ 回填白名单排除全部 task-*。
- **事实**：R-23 + D-04 PC-02 定案 = **task 终态 4 事件（started/completed/failed/killed）补落库（Persist）**，仅 output/heartbeat/suspicious 不落库（NoPersist）。
- **后果**：前端观测 store 对已落库的 task 终态事件永久不回填；与 PC-02 定案表（3.3：task 终态 4 = Persist）直接矛盾。
- **建议**：OV-07 回填白名单改为「task-started/completed/failed/killed 可回填（依赖 D-04 落库面）+ output/heartbeat/suspicious 留缺口」，删除「task 不落库」表述。

### 冲突 #4 · read_run_events IPC 通道悬空【高】

- **冲突点**：D-01 DM-07 禁止项「禁止恢复 core_read_run_events 的 IPC 命令注册（归主控/D-06）」；D-06 OV-04 完成定义 3「经 core_read_run_events(runId, sessionId, afterSequence) 分页补拉」+ 禁止项「禁止新增 IPC/查询命令（复用 core_read_run_events，Tauri command 已存在）」。
