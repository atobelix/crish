## 二、`--check` 模式现状与设计要点

### 2.1 现状（实测）

`node scripts/generate-engine-bindings.mjs --check` → **exit 1**，报错：

```
Error: 未知参数 --check（支持 --registry <path> / --out <dir> / --only <contract>）
    at parseArgs (scripts/generate-engine-bindings.mjs:1289)
```

- `parseArgs` 仅识别 `--registry <path>` / `--out <dir>` / `--only <contract>`（:1282-1292）；未识别参数直接 `fail()` 抛错退出。
- 生成路径：`emitEngine`/`emitDevice`（:1294/:1313）直接 `writeFileSync` 落盘（:1304/:1337），**无内存化产出、无比对概念**。
- 生成器自带幂等前提（:12-15：无时间戳/随机数、迭代顺序 = JSON.parse 保序）——`--check` 的字节比对可行性成立。

### 2.2 设计要点（供轮 4 实现参考，不构成本轮改动）

1. **参数面**：`parseArgs` 增布尔 `--check`（:1282-1292 内先于未知参数判断）；可与其他参数组合（如 `--check --only engine-events`、`--check --registry <path>`、`--check --out <dir>`）。
2. **发射器改造（最小侵入）**：`emitEngine`/`emitDevice` 现为「组装 files 映射 → 逐文件 writeFileSync」；建议把「组装映射」与「写盘」拆开（或加 `write: boolean` 参数），`--check` 模式**只组装不写盘**，逐文件 `readFileSync` 与现盘文件做**逐字节比对**（`Buffer.equals` 或字符串全等，因幂等声明，字节等价即产物一致）。
3. **退出语义**：全等 → exit 0（可打印 `up to date`）；任一处 diff → **exit 非零**（CI 可拦），并打印每个差异文件路径（可不打完整 diff，避免噪音；若要 diff 明细，`--check` 加 `--verbose` 可选，反过度设计不默认）。
4. **校验范围**：默认跑全部注册表（engine + device 双契约），`--registry/--only` 收窄；device 段继续依赖 engine 交叉校验（:338-350，当前 49 同名同序已满足）。
5. **幂等边界（诚实标注）**：`--check` 只锁「注册表当前输入 → 产物」一致（生成器幂等断言）；**不锁「events.rs ↔ 注册表」语义**——后者由 `cargo test -p conex-types` 的 registry_drift 锁定（D-06 OV-01 验收断言已列）。regen 前若有并行 Agent 手改生成产物，`--check` 立即红，属期望行为。
6. **回归**：轮 4 实现后验收 = `--check` 连续跑两次 exit 0 且 `git diff --stat packages/shared-types/src/generated/` 为空；regen 后（49 类产物在盘）`--check` 仍 exit 0。
7. **禁止项**（D-06 OV-01）：禁加配置面/缓存；禁改 events.rs/注册表；`Cargo.lock` 零 diff；生成产物禁手改。
