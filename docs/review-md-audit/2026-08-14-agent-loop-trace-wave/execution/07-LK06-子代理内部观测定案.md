## 一、定案（裁决 B 落地登记）

### 1.1 结论一句话

**子代理内部细节以子会话事件流为准（`sub-sess-N` 会话内完整 agent/turn/message/tool 事件），父会话侧保持三事件视图（started / event(progress) / ended），不做子流复制；`subagent-event` 的 message/tool 类契约显式标注「未启用」（CT-03：不删不装、注册表保留、契约层标注）。**

### 1.2 裁决锚点

| 锚点  | 内容                                                                                            |
| ----- | ----------------------------------------------------------------------------------------------- |
| R-13  | 子代理内部观测定案 B + message/tool 契约「未启用」标注（D-02 详案 §1.2）                        |

| EV-01 | 契约保真清单状态列「未启用」与本案一致（核对见 §三）                                            |

### 1.3 定案要素

1. **观测主轨 = 子会话事件流**：每个子代理拥有独立子会话（`sub-sess-N` 命名，深度 1），其 agent/turn/message/tool 全过程事件落在子会话事件流，子会话事件按会话查询（D-01 轮 2 DM-07 已落地按 run 查询，子会话按会话查询面同族）。
2. **父会话侧保持三事件视图**：
   - `subagent-started`（启动，Critical 必达落库）；
   - `subagent-event(kind=progress)`（进度增量，Delta 可丢，既有发射方）；
   - `subagent-ended`（终态，Critical 必达落库）。
   - 父会话**不承载**子代理内部 agent/turn/message/tool 事件。
3. **progress 补发保留并标准化**：emit_subagent_progress 收口补发为既有行为，保持 Delta 级**不升级**（升级 = 后置决策，本战役不扩范围；`core_run_commands.rs` emit_subagent_progress 只读复核，未改）。
4. **诚实边界句**（随契约标注入 events.rs 注释）：补发制不升级；父会话侧无实时内部动作——子代理内部细节以子会话事件流为准。

### 1.4 否决 A 案理由（复制子流到父会话）

> A 案 = 把子代理内部事件流复制/镜像到父会话事件流（父会话可见子代理内部全过程）。

**否决理由：复制即双源漂移，违反战役「单一全链条记录」目标。**

1. 同一事实（子代理内部一轮 turn、一条 message）将同时存在于子会话事件流与父会话事件流两份副本——两份副本若有一个字节不一致（发射时序、字段演进、序列号分配），追溯时无法判定哪份为真，「单一记录」承诺破产。
2. 事件序列号（sequence）按会话分配：子流复制进父会话会占用父会话序列空间、破坏父会话 sequence 单调连续性，下游游标/重放去重（03 §5.1-2/3）受污染。
3. 体积与背压：子代理内部全量复制使父会话流与子代理数成正比膨胀（N 个子代理 = N 份内部流），背压分级（Critical 必达落库）将被迫为复制流让路——观测成本反噬主链。
4. 事件契约字段（如 `subagent_session_id` 反向键）在复制流下失去意义：复制流本身即可定位，无需跨会话导航——复制方案恰恰消灭了「跨会话导航」这一战役要建立的能力。
5. 消费面复杂度：前端需为「同一事件两种来源」建立去重/合并逻辑（幂等键冲突），观测层把简单问题做成双源问题。

**B 案（定案）以「跨会话导航」替代「复制」**：父会话三事件视图 + 事件级/行级键跳转子会话，子会话是内部细节唯一真源——单一全链条记录目标下**每条事件只有一个归属会话、一份记录**。
