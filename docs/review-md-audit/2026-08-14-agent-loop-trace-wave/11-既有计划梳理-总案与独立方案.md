### 1.2 总计划框架（`00-总计划框架.md`）的结构

- **元数据表**：输入 / 角色 / 纪律 / 用途（本框架作为第四步详案派单依据与第五步评审对照基准）。
- **一、主 Agent 裁决**（17 条收敛口径表，每条带依据出处）：编号空间统一、唯一派单归属、验收口径（门禁双红期间以本地真跑为主、CI 绿仅追认）、行数口径以门禁脚本输出为权威、同文件串行铁律、问题池核销（过期项禁派）等。**裁决先行，详案必须遵守**。
- **二、维度划分**：维度 0–8（前置快照/门禁/契约小修/结构/并发/可观测/契约核心/连通/收口），每个维度 = **核心问题 + 任务单元（带 ID）+ 验收**；组序 = 逻辑依赖序（非优先级），组内无文件域重叠者可并行。
- **三、执行原则**（7 条）：同文件串行铁律、子 Agent 留工作区主控 `commit --only`、派单前开工动作（G-00 快照 + git status + 行号锚点重定位）、问题池消费前逐项核销、诚实边界句全保留、每轮闭环（派单→并行修复→主控验证→统一提交→审计复查→下一轮）、方案可复用（本框架结构作为下一轮战役模板）。
- **四、后续流程**：第四步派 7 详案 → 第五步派 ≥2 评审 → 第六步定稿 → 执行轮。

### 1.3 执行方案定稿（`00-执行方案定稿.md`）的形态

- **必拍板 3 件事**（定稿前主控确认）：SR-01/02 冻结窗口（core_run_commands 在轮 3 末由主控冻结+收口）、验收口径（门禁红禁称绿）、行数口径统一（以脚本输出为权威）。
- **可派单总表**：47 任务单元 → ≈40 槽（合并建议已落实：CT-04→CT-03 槽、S4→S1 槽、B1-6→B1-4 槽、CONN-05→CONN-00/06 槽、G-06→G-02 收尾槽）；展开 SR-06/G-02 子槽后 ≈55–60 槽。
- **轮次划分表**：8 轮 ×（轮次 / 主题 / 单元 / 关键串行约束）。逻辑：先行不变量（G-00/CONN-00）→ 无依赖小修 → 门禁根因+结构首刀 → G-02 登记+结构大件（轮 3 末冻结）→ 收尾+串行启动 → 结构二刀+并发 → 结构链+契约 → 链尾+可观测 → 收口（可不保底）。**任务单元粒度 = 一个子 Agent 任务**，按「ID + 文件域锁 + 完成定义 + 真跑验证清单 + 禁止项 + 诚实边界句」派单。
- **验收方式**：验收断言全部为「命令 + exit code + grep/契约断言」（如 `cargo test -p xxx` 真跑绿、`rg` 零命中、字节级复检、diff 白名单断言）；门禁实红期间以**执行轮本地真跑**为主，CI 绿仅追认。

### 3.1 直接相关、部分已规划（复用为主，勿重复建设）

**A. 无共享 trace id（本战役 06） ↔ 上个战役 S2 分布式追踪最小面（04 方案 §三 S2 / 执行定稿轮 7）**

- 上个战役已做/已规划：run 级 `trace_id` 挂既有 run span（`info_span!("run", session_id, run_id, trace_id)`，不加新 span 层级）；`AgentEventEnvelope` 增可选 `trace_id` 字段；前端 invoke 载荷透传（**禁按 HTTP 头**，Tauri IPC 无此语义）；`tool.ts:55` `traceId` 死字段接线或删除二选一；验收 `rg trace_id` 生产代码 ≥1 命中；排 SR-02/SR-04 之后。
- **未覆盖的缺口（本战役新发现）**：
  1. S2 只做「字段 + span」，**未涉及落库面**——events 表无 run_id 列、payload 无 runId（本战役 02/05/09 结构性第一大缺口）。S2 的 AgentEventEnvelope 字段若只在广播构造点填、落库仍写裸事件体（本战役 02：「信封只在广播时构造」），按 run 回溯依旧断。**本战役需决定 trace_id 与 run_id 落库列的关系（同键 or 双键），并补「库中事件含 run_id」验收断言（S2 只断言「事件流任意事件含 trace_id」）。**
  2. S2 未解决 **span 上下文不确定性丢失**（本战役 06：全仓仅 2 处手动 span、0 处 `#[instrument]`、tokio 线程迁移丢上下文）——S2 是「在 run 启动处挂一个 span」，跨线程传播未设计。
  3. 日志与事件无统一关联键（本战役 06）——S2 验收只覆盖 IPC/事件面，未含日志侧。

**B. 事件时间戳问题（本战役 04/09） ↔ S3 性能热点埋点（04 方案 §三 S3）**

- 上个战役：S3 三热点（慢序列化/长锁等待/渲染帧预算）耗时计数 + 条件告警，复用 `EmitReport.dropped → tracing::warn` 样板，消费 B5 计数原语，**挂边界函数不挂 Mutex 实例**。
- 不重叠但同域：本战役 09「时间戳双源异质（ISO 毫秒 vs created_at 秒精度）」、04「事件时间戳是翻译时刻非执行时刻（批后一次性翻译）」是**时间戳语义**问题，S3 是**耗时计数**问题——互补不重复；但修复面同在 engine.rs 事件桥/序列化面（S3 排 SR-04 后），**同文件串行纪律沿用**。本战役的「执行时刻打点、单一时源」可成为 S3 埋点的数据基础。
