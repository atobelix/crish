## 一、review.md §2 并发与锁安全

### 1. 跨 `.await` 持锁 — 🟢 未发现（生产）

- 生产代码中 `block_on` **零命中**：全部命中在 `#[cfg(test)]` / benches（`agent-tools/src/explore_quota.rs:702,716` 为测试 `parallel_writes_respect_quota_atomically` 内的双线程验证；`conex-browser/src/gate.rs:1107,1123` 为测试；`conex-computer/src/desktop_capture.rs:321-326` 为测试 helper；`orchestrator/src/persist.rs:783+` 为测试）。
- hooks 分派**先快照克隆、读锁不跨 handler await**：`session-loop/src/hooks.rs:516-535`（注释「读锁不跨 handler 调用持有，避免 handler 内注册死锁」）——正确。
- 事件缓冲锁不跨 await（AA-02 已注记）：`apps/agent-workbench/src-tauri/src/buffer.rs:62`。
- `summary_coordinator.rs:272` 的 `#![allow(clippy::await_holding_lock)]` 仅用于测试串行锁，注释明确「非真实代码路径的锁语义，豁免」——非生产缺陷。
- 注意边界：`store_backend.rs` 在**同步段**内持 `sessions` 锁跨 `commit_ops`（SQLite 写），不构成跨 await，但见 §3 锁争用热点。

### 2. 毒丸锁 / `unwrap_or_else(|e| e.into_inner())` — 🟡 黄（静默面大、可观测面小）

- 全仓生产代码（排除 `**/tests/**` 目录）粗扫：`unwrap_or_else(|e| e.into_inner())`（含 `|p|` 变体）约 **258 行 / 54 文件**（含 test module 内命中，如 `tool_exec.rs` 9 处全部在 `#[cfg(test)] mod tests`（`tool_exec.rs:1568` 起），**生产为 0**；`tools/shell.rs` 命中 5 处中 2 处是 `ChildStdout::into_inner()`（类型方法，非毒丸），其余在测试）。
- **静默恢复（无日志/无计数）**，重点核实：
  - `agent-tools/src/note_memory.rs`：12 处（71/92/102/142/229/276/302/313/347/416/449/473）全部静默；该后端为 dev/test 内存后端（文件头诚实声明），非生产 Store 路径。
  - `conex-note-runtime/src/store_backend.rs`：7 处生产（125/154/209/246/304/430/482），全部静默；其中 304/482 在写路径（apply_collab_ops_json / apply_block_ops）。
  - `session-loop/src/loop/summary_coordinator.rs`：9 处生产（99/107/114/131/191/221/240/249/262），静默。
  - `agent-tools/src/explore_quota.rs`：4 处生产（150/161/176/191），均为 `InMemoryExploreDocsQuotaStore`（测试/未接线兜底实现，生产 session_meta 后端在引擎侧），静默。
  - `apps/agent-workbench/src-tauri/src/engine.rs:2083-2088`：事件桥缓冲锁毒化分支静默 `into_inner().enqueue(...)`。
  - `crates/conex-telemetry/src/file.rs:147`：静默。
- **可观测恢复（tracing::error! 成对）**，正确样板：
  - `agent-tools/src/registry.rs`：13 处生产全部带 `tracing::error!`（如 51-55、64-69、76-81、88-93、99-110、126-129、134-141、145-153、175-182、193-196）。

  - `conex-fs/src/watch.rs:391-396`：带 `tracing::error!`。
- **安全基线关联**：`docs/rust-rewrite/31-security-baseline.md:153` 明确 A 模式 = `unwrap_or_else(|e| e.into_inner())`（恢复式）——即本仓官方许可形态；但基线同时要求「恢复式须可观测」，静默面与该条精神不符。

### 3. 锁粒度与组合 — 🟡 黄（粒度粗、无死锁环）

- **未发现锁序环**（逐点核对）：
  - `store_backend`：`sessions` → `store.conn`（单向；store 侧 `SharedWorkspaceStore.conn: Mutex<Connection>`（`conex-workspace-store/src/lib.rs:187`）不反向感知 sessions，无环）。
  - `note_memory`：`docs` 锁在取 `intents` 锁前显式 `drop(docs)`（`note_memory.rs:345-348, 414-418`），无嵌套。
  - `summary_coordinator`：`task → config`、注册表 `sessions → config`，无反向路径。
  - `registry`：`tools` 锁 drop 后再取 `order`（`registry.rs:63-70`）。
- **粒度问题**：`StoreNoteBackend.sessions: Mutex<HashMap<String, DocSession>>`（`store_backend.rs:56`）是**全文档共用一把锁**；写路径持锁跨 `commit_ops`（SQLite 落库 + 投影索引，`store_backend.rs:301-315`、479-512），读路径（`document_to_md` 全文序列化 `store_backend.rs:122-133`、outline DFS `store_backend.rs:426-433`）同锁互斥——多文档并发读写被串行化（典型单活动文档场景可接受，多 Agent 并发写不同文档时成为争用点）。与 `resolve_authority_rev`/`import_mirror_proposal`/`export_md_mirror` 中「先克隆树、drop 锁、再 I/O」的正确样板（`store_backend.rs:158, 205-215, 243-255`）相比，apply 路径未采用同模式（需保持单写者语义，属设计取舍，非缺陷）。

### 4. 阻塞调用误用 — 🟡 黄（fs/note 路径同步 IO 直跑 async 线程）

- **`spawn_blocking` 覆盖良好处**：orchestrator persist 全部 DB 调用经 `blocking_db_call`（`orchestrator/src/persist.rs:568-585`）；摘要 Summarizer 阻塞调用经 `spawn_blocking`（`session-loop/src/loop/summary_dispatch.rs:592`）；shell 工具用 `tokio::process::Command`（`agent-tools/src/tools/shell.rs:37,862`）——正确。
- **缺口**：
  - `agent-tools/src/tools/fs.rs`：`std::fs::metadata/read/write/read_dir` 直接在 `async fn execute` 内（75/106/346/385/467/514/524），无 spawn_blocking——批执行 `join_all` 并行 fs 工具时可能占满运行时 worker。
  - note 命令链：Tauri 命令为 `pub async fn`（`note_commands.rs:269/283/301/348/385/420/472`）直接 `.await` 后端；后端内部是同步 SQLite（query_blocks / commit_ops / mirror detect-import）+ 全文序列化，在 async worker 线程上执行——零 spawn_blocking。
  - `conex-telemetry/src/file.rs:147-183`：每次写调用同步 open+append（`open_log_file` 每次打开当日文件句柄），文件头注释已声明「tracing-appender 接入后改为独立线程 + 非阻塞写（待 PE-10 声明依赖）」——已登记债。
  - `std::thread::sleep` 生产命中集中在 conex-computer（截图/动作模拟，专用线程语义，非 async 主线程），不判问题。

### 5. 共享状态读写比例 — 🟡 黄（读被写串行化）

- `store_backend.sessions` 单 Mutex 同时当读锁写锁（见 §3）；`workspace-store.conn` 单连接 Mutex 串行化**全部** DB 访问（query/FTS/commit/mirror/refs 共一口）。读多写少的 query_blocks/outline 被同锁串行。建议面：per-doc 锁（doc_id 分片）或写路径单锁 + 读路径投影表快照（既有 `projection.rs` 索引已承担部分读路径）。
- `agent-tools/src/registry.rs` `get()`：每次工具调用取 `tools` 锁 + Arc clone（`registry.rs:75-84`），临界区极短，可接受。
- 原子计数（`AtomicUsize`）用于配额/并发门（explore_quota / summary 全局上限 / subagent 计数），无锁读——正确。

## 二、review.md §3 性能热点与资源开销

### 6. 隐式深拷贝 — 🟢 低风险

- 重点文件未发现「大面积 clone 整个上下文/集合」：`tool_exec.rs` 批执行路径 clone 的是 `ToolContext`（字段为 Arc/PathBuf/String，`agent-tools/src/context.rs:100-145`，浅拷贝）、`ToolBatchOptions`、`ToolExecutor`（`clone_executor`，`tool_exec.rs:1426`，内部 Arc 浅拷贝）——成本可忽略。
- 例外（有界）：`summary_coordinator.last_outcome()` 每次调用 clone 整个 `SummaryDispatchOutcome`（`summary_coordinator.rs:96-101`）——低频（查询/审计面），不判问题。
- `registry.rs list_definitions()` 每 run 克隆全部 ToolDefinition + 排序（`registry.rs:168-189`）——n 为常量级工具数，每 run 一次，可接受。

### 7. 序列化黑洞 — 🟢 SQL 路径已分页；🟡 dev 后端有全量取

- **生产 SQL 路径正确**：`query_blocks` limit 归一化（默认 50 / 上限 200，`conex-workspace-store/src/query_blocks.rs:39-41,116-118`），`fetch_n = limit + 1` 下推 SQL `LIMIT`（`query_blocks_sql.rs:60,123,189,289-291`）——**不是先全量取再截断**。
- **dev 后端**：`note_memory.rs query_blocks` 全量过滤收集全部命中（每命中 clone id/kind/attrs）后才 `truncate`（`note_memory.rs:158-216`）——dev/test 专用，非生产热路径，黄（低）。
- outline / get_md：整树遍历/整文档序列化属语义必需（无分页契约），不判问题。
- IPC 载荷：get_md 全文一次透传为契约行为；未发现「分页操作全量序列化」的生产形状。

### 8. O(N²) 渲染/计算 — 🟡 两处点名形状（均低危）

- **前端**：`useStreamCallbacks.onChunk` 每 chunk 执行 `getSessionById(sid)?.messages.find(...)`（`apps/crish-desktop/src/hooks/chat-stream/useStreamCallbacks.ts:849-851`）——每 token 一次 O(会话消息数) 查找；消息数通常 ≤ 数百，常数小，黄（低）；`streamedFullText += chunk`（:840）依赖 V8 rope，未判问题；`StreamRenderBuffer.onFrame → setStreamText(frame.full)`（:324）为全量覆盖写，受预算约束（见 §12）。
- **Rust**：`note_memory.rs` `ref_from` 过滤在逐块循环内 `doc.blocks.iter().find(...)`（`note_memory.rs:193-202`）→ O(N²)，dev 后端专用；生产 Store 路径的 ref 过滤在 SQL 侧（`query_blocks_sql.rs` ref_from 参数化），无此形状。

### 9. 锁争用热点 — 🟡 两处全局串行点

- `StoreNoteBackend.sessions`（全文档共用）+ `SharedWorkspaceStore.conn`（单连接）：多 Agent 并发写不同文档、或写与 outline/get_md 并发时全部串行（证据同 §3/§5）。未实测争用时长。
- 反例（无争用）：批次写入走 `NoteBatchTokens`（内存 token，非全局锁）；approval 等待走 channel（`tool_exec.rs:170` `tokio::time::timeout` 包 wait）；mirror 检测走 store 锁（低频）；subagent 并发门是 `AtomicUsize`。

## 三、review.md §12 并发模型与背压

### 10. 背压传播 — 🟢 全链路有界（形状证据）

- **引擎→桌面事件缓冲**：`BufferedRunEventBridge` 默认 `EventBuffer::default()` = `EventBuffer::new(64, 256)`（`engine.rs:2068` → `buffer.rs:200-206`）：Soft 水位 64（message-delta 旧帧优先丢）、Critical 水位 256（terminal/审批/工具事件永不丢），丢帧计数经 `EnqueueOutcome.dropped` → `tracing::warn` 可观测（`engine.rs:2089-2098`，PE-04 T04.2-3）。`DeltaSink::push` = emit+flush（实时轨立即发射，`engine.rs:2144-2151`）。**有界 + 可观测丢帧，不是无界缓存**。
- **前端批合并**：文本 8000 字符 / thinking 4000 字符 / 工具 patch 按 key 合并，超预算强制 flush（`useStreamBatchers.ts:51,67,106`，`streamTextBatcher.ts:188-196`）。
- **前端渲染节奏**：`StreamRenderBuffer` rAF 预算 6ms/帧、单帧 ≤8192 字符、final 标记后拒收、大残余分帧收口（`apps/crish-desktop/src/api/StreamRenderBuffer.ts:46-52,78-125`）；`flushFinal` ≤2×8192 同步、更大走预算循环。
- **orchestrator 消息队列**：`PendingMessageQueue` 有容量上限 + 驱逐最旧（`orchestrator/src/steering_queue.rs:119-125,386`）。
- **EventQueue**：非内存队列，是 store 追加落库 + 序列分配（`orchestrator/src/events.rs:161-207`），delta 事件不落库不等待——无内存无界积累面。

### 11. 并发度控制 — 🟢 子 Agent/摘要/配额有门；🟡 并行工具组无上限

- **子 Agent 并发门（强制面）**：`DEFAULT_RECURSION_GUARD` = max_depth 1 / max_siblings 16 / max_concurrent 16（`agent-tools/src/tools/subagent.rs:498-501`），守卫判定序「深度→兄弟→并发」（:595-617），批量派发前瞻预加（测试钉：:3073-3111），工具面注册表剔除派发能力 + 守卫层 `nesting_denied` 结构化错误——**嵌套/上限未被绕过**。
- **explore 配额（原子占用）**：`try_consume` 互斥内读改写，无 TOCTOU 窗口（`explore_quota.rs:168-187`，F3 #9 修复）；失败 Drop 自动 release（:189-195）。
- **摘要任务全局上限**：`ACTIVE_SUMMARY_TASKS` ≤ 2（`summary_coordinator.rs:40-44,143-154`），fetch_add 前查 + 失败回滚。
- **缺口（黄）**：`tool_exec.rs` 批执行对 `ToolConcurrency::Parallel` 组直接 `join_all`（`tool_exec.rs:459-549`），**组内并行工具数无信号量上限**（上限隐含为 LLM 单批工具数）；批中多个 shell/fs 并发时无全局进程/IO 限流。子 Agent 路径有门、工具路径无门，是结构不对称。

### 12. 超时与取消传播 — 🟢 有超时、取消可穿透；两处边界注记

- 单工具执行有超时包装（`tool_exec.rs:1052-1054`）；审批等待默认 120s（`tool_exec.rs:126,158`）；hook 每 handler 超时（`hooks.rs` timeout_ms）；摘要任务墙钟 + 退避上限（`summary_dispatch.rs:583-592`）。
- **取消穿透**：abort token 在审批等待（`tool_exec.rs:162-173,423,450`）、执行循环（:658）逐点检查；shell 子进程在 abort 时 `kill_child`（`agent-tools/src/tools/shell.rs:1169-1227,1318`）。
- 边界注记（黄，低）：`spawn_blocking` 内的 Summarizer 调用中途不可取消，只能靠墙钟上限兜底（设计取舍）；EventQueue 非持久化 delta 事件不落库（取消即丢，属契约）。

### 13. 线程池隔离 — 🟢/🟡 见 §4（与隔离重叠）

- 摘要阻塞调用走 `spawn_blocking`（独立阻塞池，`summary_dispatch.rs:592`）；orchestrator DB 走 `spawn_blocking`（`persist.rs:577`）；shell 走 `tokio::process` 自带 IO 驱动。隔离主流正确；fs 工具与 note 命令链为未隔离缺口（同 §4）。

### 14. 反过度设计红线对照 — 🟢 未回潮

- 内核级沙箱（Seatbelt/seccomp）：未发现（拦截面是 `CommandGatekeeper` 指令级 + 进程树 Job Object，属允许清单）。
- `sab_ring_buffer` / SharedArrayBuffer 环形缓冲：未发现（事件走 tokio/tauri 通道 + 有界 EventBuffer）。
- 滑动窗口 CircuitBreaker：未发现（provider retry 为指数退避，`agent-provider/src/retry.rs` 形状符合红线）。
- 六段工具中间件/`IpcRouter` 二次套娃：未发现（工具链只有 before/after；Tauri 命令直调业务）。
- `React.memo` 全覆盖 CI 断言：未发现。
- 本报告 §11 建议的「并行工具组限流」若实施须用轻量信号量，禁止升级为滑动窗口/熔断器形态。
