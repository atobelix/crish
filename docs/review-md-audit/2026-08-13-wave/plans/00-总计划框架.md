## 二、维度划分（总框架）

> 组序 = 逻辑依赖序（非优先级）；组内无文件域重叠者可并行；可跨轮执行，每轮 5–12 Agent（收尾轮可不保底）。

### 维度 0 · 前置快照与核销（G-00 + CT-05）

- **核心问题**：全波派单缺统一开工基线；问题池 3 项过期未核销。
- **任务单元**：G-00 双口径门禁快照 + 责任域登记表（状态列白名单机器可校验）；CT-05 保真复验清单（批写 token / provisional≠kind 纪律钉测）先行落盘供全波引用。
- **验收**：快照文档状态列只允许 {FAIL, PASS} 且与脚本 exit code 对应；CT-05 清单含可 grep 钉测名。

### 维度 1 · 门禁治理（G-01 → G-02 → G-03 → G-05 → G-06）

- **核心问题**：crate-size 88 个未登记 FAIL（HEAD 实红）+ 登记即永久豁免盲区（core_run_commands 2524→17495 零信号）；line-counts 3 HARD + 7 VIOL；CSP 缺失。
- **任务单元**：
  - G-01 脚本语义硬化：登记带行数、已登记回涨即 FAIL；独立迁移路径；`--check-format` 模式。
  - G-02 88 项按域分批收敛（纯登记/顺带拆分分流；每批 ≤5–8；时限注记 = 「SD-xx/SR-xx ID + 触发事实」二元结构，5 禁词）。
  - G-03 line-counts 收敛：3 HARD 各拆独立子任务（noteApi 704 / BrowserImportSection 751 / useStreamCallbacks 950+400ms 常量），7 VIOL 拆或登记；不碰 eventParser。
  - G-05 CSP 两阶段：首屏内联外链化 → 显式 CSP 声明（dev/prod 双态验收）。

## 三、执行原则（所有维度共用）

1. **同文件串行为铁律**（以 REV-01 §二.2 冲突矩阵为准）；基线文件单写锁。
2. **子 Agent 留工作区、主控 `git commit --only`**；子 Agent 不许 git 操作；禁 `--no-verify`；禁回撤。
3. **派单前开工动作**：G-00 快照 + `git status` + 行号锚点重定位（全波强制）。
4. **问题池消费前逐项核销**（#8/#9/#24 已核销）；19 与 EL-dashboard 为权威状态账。
5. **诚实边界句全保留**（37/37）；不关 EL；不去 `-S`；不 fixture 伪装；provisional ≠ kind。
6. **每轮闭环**：派单 → 子 Agent 并行修复 → 主控验证 → 统一提交 → 审计 Agent 复查前轮完成情况 → 下一轮。
7. **方案可复用**：本框架结构直接作为下一轮修复战役的模板。
