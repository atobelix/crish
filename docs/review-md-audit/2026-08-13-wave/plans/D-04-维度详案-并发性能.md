## 一、维度目标（一句）

### 3.0 公共改动模式（六片共用）

**成对样板（对齐 `registry.rs:51-55` 既有 13 处）**：

```rust
let guard = self.sessions.lock().unwrap_or_else(|e| {
    tracing::error!(
        target: "conex_note_runtime",
        "sessions 锁中毒，恢复式继续（into_inner）"
    );
    POISON_RECOVERIES.fetch_add(1, Ordering::Relaxed);
    e.into_inner()
});
```

**计数原语（B5 并入 B1 落地，对齐 `EmitReport.dropped` 的 `tracing::warn` 统计形态，零新依赖）**：

- 每片所在模块加一个模块级 `static POISON_RECOVERIES: AtomicU64`（或每文件一个），`fetch_add(1, Ordering::Relaxed)`；
- 提供 `pub(crate) fn poison_recovery_count() -> u64`（供本 crate 毒化测断言 + S3 埋点消费；engine 片在 Tauri crate 内部函数）；
- 禁止建服务/新表/新指标系统；禁止把计数做进热路径锁内（计数在毒化分支，非正常路径）。

**毒化测模板（复用 `crates/session-loop/tests/observability.rs` 的 `LogCapture`+`with_capture` 模式，同形复制到所在 crate 测试面，不新增依赖）**：

```rust
#[test]
fn poisoned_sessions_lock_recovers_with_log_and_count() {
    // 1. 另起线程持锁后 panic → 毒化
    // 2. 调用公开 API → 正常返回
    // 3. with_capture 捕获到含 "锁中毒" 的 error 行
    // 4. poison_recovery_count() == before + 1
}
```

**文件级核对清单断言（取代「逐点人工核对」伪断言，REV-02 检查项 1-B）**：

- 以本详案 §8 清单（`rg -l "into_inner"` 文件级）为核对表；
- 断言形态：域内每个文件 `rg -c "into_inner"` 命中处均含成对 `tracing::error!` 或 `fetch_add`（实现层每处就近成对，测试用毒化测兜底逐锁）；`rg -n "into_inner"` 每命中行的 ±8 行窗口内含 `tracing::error` 或 `POISON_RECOVERIES`（可脚本扫描）；
- 每文件 ≥1 毒化测（复用 LogCapture，断言「正常返回 + 日志 + 计数」三要素，禁止空壳）。

**全波共同约束**：`cargo test --workspace` 全绿；不触达安全面新增面（锁改动触达 31 基线 B8 → 毒化测即 B8 验收测试，`rg "\.lock\(\).*expect"` 无新增命中）；B1 不改恢复语义（仍恢复、不 panic、不传播）。

## 四、B3 锁粒度：二选一裁决建议

### 裁决：方案 A —— per-doc 分片锁（doc_id 分片）

> 04 报告给「per-doc 锁（doc_id 分片）或写单锁 + 读投影快照」二选一；本详案**裁决方案 A**，论证如下。

**论证（按路径合法排序键：效果完整度 → 正确性/不变量 → 可验证性 → 契约一致 → 结构干净）**：

1. **效果完整度**：per-doc 分片直接解除「不同 doc 读写互斥」这一核心问题（04 §3/§5：多 Agent 并发写不同文档、写与 outline/get_md 并发全被串行化）。而「读投影快照」只覆盖 `query_blocks` 一类投影读面——`get_md`（`document_to_md` 全文序列化，`store_backend_query.rs:32`）与 `document_outline`（DFS，`store_backend.rs:167-185`）**必须**读完整会话树，投影表承载不了；要让 outline/get_md 走快照需另造「树快照」机制（深拷贝/Arc 换装）——半覆盖 + 新机制，效果不完整且滑向过度设计（红线：不扩连接、不加设施）。
2. **正确性/不变量**：per-doc 锁保持 apply 原子性（单次 `commit_ops` 事务，`store_backend_apply.rs:72/:134`）与同 doc 单写者语义完全不变——锁序仍为 `doc → store.conn` 单向（conn 在 `conex-workspace-store/src/lib.rs:159`，实测：04 报告 :187 已漂移），无反向取锁、无环（04 §3 已逐点核对）。读投影快照则改变读路径数据源与一致性模型（快照 vs 实时树），语义风险更高。
3. **可验证性**：双线程并发写不同 doc 的时序断言（对齐 `explore_quota.rs:681 parallel_writes_respect_quota_atomically` 双线程模式）对方案 A 直接可写可跑；方案 B 的快照一致性断言需额外定义。
4. **契约一致**：per-doc 锁是纯内部数据结构改动（`sessions` 字段形态），公开 API / IPC 契约零 diff，既有 store_backend_tests 族 4 文件（tests/_apply_md/_batch/_hydrate）只需保持绿；方案 B 会触碰 query/outline/get_md 行为面。
5. **结构干净 + 与 B1/B2 同域协同**：per-doc 锁的 13 处 `lock()` 调用点适配与 B1 片 1 同文件域、与 B2 字段 Arc 化同域——同一 Agent 串行链（裁决 9）内顺带完成，实现量最小；方案 B 是独立新设施。

**实现形态要点（约束内给方向，不锁死实现）**：

- `sessions: Mutex<HashMap<String, DocSession>>` → `sessions: Mutex<HashMap<String, Arc<Mutex<DocSession>>>>`（map 锁只保护索引 get/insert 的短临界，`ensure_session` 查插原子性在 map 锁内保持；doc 锁持长临界：apply 全程 / outline / get_md 序列化）；`intents` 锁不动；
- 锁序保持 `map 锁 → doc 锁 → store.conn` 单向（doc→conn 不变式）；
- **有界性诚实口径**：实测 `sessions` map 现无 close/evict 路径（`rg "fn close|evict|remove"` 零命中）——锁条目数上界 = 打开的 doc 数（与现状 map 同界），不因调用次数增长；「增删无泄漏」断言按此定义（锁条目数 == sessions 索引条目数），不伪造 close 语义；
- **conn 诚实边界**：per-doc 锁解除的是「内存会话锁」面；SQLite `commit_ops` 仍经 `conn` 单连接串行（03 §五-4 裁决**不扩连接数**，连接池属过度设计风险）——验收断言以内存面重叠为准（双 doc 并发 apply 不因 sessions 锁全串行），不得宣称「全链路无串行」。

**验收断言（方案 A）**：

- 双线程并发写**不同** doc：两路同时启动（barrier 式），断言不再全串行（参考 explore_quota 双线程模式）；同 doc 并发写仍串行（单写者不变）；
- 同 doc 既有单飞/幂等（intent 幂等）/批 token 测全绿；`store_backend_tests` 族 4 文件全绿；
- 锁表有界：并发 apply N 个不同 doc 后锁条目数 == N（不随调用次数增长）；
- `cargo test --workspace` 全绿。

**禁止项**：引入反向锁序（`store.conn → sessions`）；per-doc 锁表无限增长（无界）；改变 apply 原子性（单次 `commit_ops` 事务语义）；新表/新服务/连接池；趁 B3 改 rev/apply 语义（与 CT-01 CAS 正交，03 §四）。
