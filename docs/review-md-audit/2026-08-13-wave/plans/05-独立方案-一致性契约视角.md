## 一、总览（整体修复路径 · 一句话）

**把「契约可信面」作为修复主线：持久层把 rev 从「LWW 单调计数器」升级为「可期望版本比对的条件更新」（最小面 SQL，无新表无新服务），前端把 3 处分层违规收回 storeAccess 公共面并把过期诚实句对齐到已接线的 CONN-B3 事实，编码面清零 3 个 BOM，再对 W4-B/W4-F 批写 token 与 provisional ≠ kind 两条已绿纪律做复验保真——契约维度先还清「声称与实现不一致」的账，为其他五视角提供可依赖的边界。**

拆解为四条主脉：

1. **持久层写入契约（CT-01，本维度核心）**：`doc_meta.rev` 从无争用检测的 LWW 升级为条件更新（`WHERE rev = 期望值`），冲突产生结构化错误并复用既有 P-H2 事务回滚路径整体回滚（updates 零追加）。最小面：trait 只加一个带默认实现的方法，既有 10 个测试实现零改动；不引入新表、新服务、新抽象层。
2. **前端分层契约（CT-03）**：3 处 depcruise 违规（continuityHandlers.ts:16/:22、subagentHandlers.ts:15）改经 `store/storeAccess.ts` 公共面；缺的 session 只读面补到 storeAccess（本会话代码验证确实缺失）。同子任务顺带修正 `intentBridge.ts:202` 过期诚实句（与 CONN-B3 事实对齐）。
3. **层间边界判定与固化（CT-04）**：leaves→chrome 逆向 import 2 处（intentBridge.ts:47、mdPrefixHost.ts:31）给出明确判定——**可接受（非真逆向违规）**，以头注释固化边界防滑坡；不迁移类型（反过度设计）。
4. **编码纪律（CT-02/CT-05）**：3 个 BOM 文件字节级去 BOM；W4-B/W4-F 批写 token 过期拒写、provisional ≠ kind 两条纪律复验在轨并保真（头句与钉测不回退）。

**本维度不承接**（仅引用）：门禁实红（G-01…G-06）、巨石拆分（SR-01…SR-08）、并发（B1…B6）、可观测（S1…S5）、连通（C 系）——详见 §二归组。

### 3.2 任务单元表

#### CT-01 · 持久层乐观锁（CAS）最小面落地（本维度核心）

**背景（代码验证）**：

- `crates/conex-workspace-store/src/persist_plugin.rs:70-80`：`INSERT INTO doc_meta … ON CONFLICT(doc_id) DO UPDATE SET rev = rev + 1`——**纯 LWW 单调递增，无期望版本比对**；跨进程并发写同一 doc 时陈旧写入者会把 rev 无声顶掉，`mirror_detect.rs` 依赖的 authority_rev 语义被破坏。
- `crates/conex-workspace-store/src/cas.rs`：`blob_cas` 表 + SHA-256 内容寻址去重——**是附件字节去重，不是乐观锁**（07 §8 判定与本会话读码一致，此处再确认）。
- `crates/conex-doc-collab/src/persistence.rs:36-44`：`PersistError` 仅 `NotFound / Io / Corrupt` 三个变体，**无 Conflict 变体**——CAS 冲突需要结构化错误码（审计报告未点明此缺口，见 §五.1）。
- `persistence.rs:47-51`：trait 必选方法 `on_committed(&self, doc_id, commit)`；`session.rs:506` `emit_commit` 调 `p.on_committed`；`session.rs:802` apply 前 `self.rev += 1`（apply 前 rev 即期望版本，会话内可取得）；`session.rs:576-577` P-H2 失败回滚机制在轨（`on_committed` 失败 → 树/文本/rev/last_tx 整体回滚到 apply 前）。
- 同进程写已经由 `conn: Mutex<Connection>` 串行化（persist_plugin.rs:21-24 等），CAS 的争用场景是**跨进程陈旧写入**；SQLite 事务内 `WHERE rev = ?` 条件更新是原子比对，无需新锁。

**最小面设计（禁止新表/新服务/新抽象层）**：

1. `persistence.rs` 新增**带默认实现**的 trait 方法：`fn on_committed_expect(&self, doc_id: &str, commit: &CommitBatch, expect_rev: Option<u64>) -> Result<(), PersistError> { self.on_committed(doc_id, commit) }`——默认忽略期望值，**既有全部实现者（MemoryPersistence + session.rs 内测 impl）零改动**。
2. `persist_plugin.rs` 覆写 `on_committed_expect`：`expect_rev = Some(期望)` 时使用条件更新 SQL（`ON CONFLICT(doc_id) DO UPDATE SET rev = rev + 1, updated_at = … WHERE doc_meta.rev = ?期望`；INSERT 分支不变——若行已存在且期望不匹配则 UPDATE 受影响行数 = 0）；受影响行数 = 0 → `PersistError::Conflict`。`expect_rev = None` 走现有 SQL（向后兼容，现有调用零行为变化）。
3. `session.rs` 的 `emit_commit` 经 `on_committed_expect(doc_id, &batch, Some(本次 apply 前 rev))` 落盘（undo/restore 路径传各自 `rev_before`）；冲突经既有 P-H2 路径整体回滚，**updates 零追加**（doc_updates 与 doc_meta 在同一事务内，回滚连带）。
4. 新增 `PersistError::Conflict` 变体并映射到命令层结构化错误码（err_outcome 形状，见 §四-可观测联动）。

| 要素                     | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **目标边界（文件域锁）** | `crates/conex-workspace-store/src/persist_plugin.rs` + `persist_plugin_tests.rs`（如有对应测试文件）；`crates/conex-doc-collab/src/persistence.rs`（trait 默认方法 + `PersistError::Conflict`）；`crates/conex-doc-collab/src/session.rs`（仅 `emit_commit` 调用点改 `on_committed_expect`）；冲突错误码的命令层映射点（`apps/agent-workbench/src-tauri/src/note_commands.rs` 的 err_outcome 面，仅加分支映射）。**不碰**：`cas.rs`（blob 去重保持原样）、`mirror_import.rs` / `mirror_detect.rs`（镜像语义不动）、`note_backend.rs` / Memory 面、`doc_updates` 表结构 |
