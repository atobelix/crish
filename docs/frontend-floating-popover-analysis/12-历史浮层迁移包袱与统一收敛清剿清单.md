## 一、核心结论概览

经过对全前端代码库（`apps/crish-desktop/src/` 及相关包）的排查与静态代码追踪，得出以下定性审计结论：

1. **旧 `UnifiedSelectPopover` 已完成物理清剿**：源码文件已删除，`src/` 内零活动代码 import，仅在少量注释中保留溯源说明，无残留逻辑包袱。
2. **多处组件存在严重的手写私自实现与双重实现**：
   - `FileViewerCard.tsx` 与 `FileActions.tsx` 存在近乎镜像复制的手写 `useMenu`、`mousedown` 监听与内联 absolute 下拉菜单（`filesOpenMenu` / `filesMoreMenu`）；
   - `CardPanelHeader.tsx`（`placeTabsAddMenu` + portal）与 `LeafToolTabStrip.tsx`（`.menuBackdrop` 全屏遮罩 + inline absolute）分别用两套截然不同的土制轮子实现了「添加面板」下拉功能；
   - `ModelProfileList.tsx`（`ModelsCascadeSelect`）仍在依靠手写 `place()` 坐标计算与已过时的全局类名 `.sort-filter-menu` / `.settings-select` 苟延残喘；
   - `workspaceChromeHooks.ts` 维护着无键盘导航、无防碰撞的手写 `useChromeAddMenu`；
   - 发现 3 处**迁移未完全的死代码与僵尸监听器**（`useModelProfilesState.ts` 空转监听、`useSidebarHandlers.ts` 无效坐标计算、`ContextMenuFlyout.tsx` 无效 `measureMenu` 调用）。

## 三、排查发现的 3 处死代码与僵尸监听器

1. **`useModelProfilesState.ts` (L276-293) 僵尸监听器**：
   - 现象：定义了 `addRef` 并注册全局 `mousedown` 与 `scroll` 监听关闭 `addOpen`；
   - 根因：`AddProviderMenu` 早已迁入 `ui/Menu`，`addRef` 根本未传给任何组件，此段代码纯属空转泄漏性能。
2. **`useSidebarHandlers.ts` (L151-152) 无效坐标计算**：
   - 现象：点击排序按钮时调用 `getBoundingClientRect()` 计算 `setSortDropdownCoords`；
   - 根因：`ContextMenuFlyout.tsx` 已由 `ui/Menu`（`anchor={sortTriggerRef}`）由 floating-ui 自行定位。
3. **`ContextMenuFlyout.tsx` (L206-214) 僵尸 `measureMenu` 执行**：
   - 现象：组件内保留了 `useLayoutEffect` 对 `sortMenuRef.current` 执行 `measureMenu`；
   - 根因：`sortMenuRef` 并没有挂载在任何 DOM 节点上，此 Effect 永远命中空分支。

## 四、历史浮层统一收敛清剿路线图

### 阶段一：清剿无技术障碍的手写下拉（低风险）

1. **统一文件操作菜单**：将 `FileViewerCard.tsx` 与 `FileActions.tsx` 中的下拉菜单统一提炼为 `ui/Menu` 实现，删除私有 `useMenu`。
2. **统一工作区加号菜单**：将 `SessionStrip.tsx` 与 `WorkspaceStrip.tsx` 的加号菜单改为 `<Menu>`，删除 `useChromeAddMenu`。
3. **统一添加面板菜单**：
   - 改造 `CardPanelHeader.tsx`，删除 `placeTabsAddMenu` 及 `useCardPanelTabs.ts` 中手写的 50 余行坐标/键盘逻辑；
   - 改造 `LeafToolTabStrip.tsx`，删除 `.menuBackdrop` 全屏遮罩。
4. **清理死代码**：拔除 `useModelProfilesState.ts`、`useSidebarHandlers.ts`、`ContextMenuFlyout.tsx` 中的 3 处僵尸逻辑。

### 阶段二：清剿全局样式依赖与级联子菜单（中风险）

1. **改造 `ModelProfileList.tsx`（`ModelsCascadeSelect`）**：
   - 参考 `ModelBadgePickerMenu.tsx` 成熟的 `ui/Menu` + CSS Modules + `onEscapeKeyDown` 逐级关闭模式；
   - 废除 `place()` 及全局 `.settings-select` / `.sort-filter-*` 依赖，解绑 `settings-base.css`。
2. **规范化 `ProjectPickerMenu.tsx`**：子菜单样式 CSS Module 化，对齐二级菜单键盘交互。
3. **收敛 `FileBreadcrumb.tsx` 与 `PriceConfigModal.tsx`**：分别迁入 `ui/Menu`（带搜索面板）与 `ui/Dialog`。

### 阶段三：规范化右键菜单基座

1. 将 `SessionContextMenu.tsx` 的右键菜单机制沉淀为 `ui/Menu` 官方支持的 ContextMenu 模式（虚拟鼠标坐标锚点），统一整站右键交互。
