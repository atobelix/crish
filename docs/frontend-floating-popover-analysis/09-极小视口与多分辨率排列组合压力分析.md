## 一、核心结论与执行摘要 (Executive Summary)

经过对前端 5 大核心浮层组件在 **4 档视口高度**（400px / 600px / 800px / 1200px+）、**3 档底部距离**（10px / 20px / 60px）、**4 档输入框膨胀**（1行 48px / 2行 58px / 5行 135px / 10行 290px）以及 **2 种展开方向**（`side="top"` / `side="bottom"`）共计 **96 种交叉状态** 的严密几何推导与代码审查，得出以下核心结论：

1. **基座自适应能力稳健，但存在两处致命局部覆写**：
   - `ui/Menu` 基座通过 Radix Popover (`avoidCollisions={true}`, `collisionPadding={12}`) 与 CSS `max-height: min(70vh, 360px); overflow-y: auto;` 在绝大部分场景下具备良好的钳位与内嵌滚动能力；
   - **重大安全隐患 1（高危）**：`ModelBadgePickerMenu.module.css:10` 强制声明了 `overflow: visible !important;`，直接击穿并剥夺了基座的滚动钳制能力；
   - **重大安全隐患 2（高危）**：`ModelBadgePickerMenu` 的二级模型子菜单 `.mbSubMenu` 采用静态 `position: absolute; top: -4px; right: calc(100% + 4px)` 定位，**脱离了 Radix Popper 避让体系**，在极小视口（400px）下必定穿出视口底部 130px 造成无法点击。

2. **`--radix-popover-content-available-height` 变量未接入消费链**：
   - 当前所有组件（`Menu.module.css`, `PermissionModeMenu.module.css`, `TiptapSlashMenu.module.css`）的 `max-height` 均基于静态 `vh`（如 `70vh` 或 `40vh`）或静态像素限制，**没有绑定 `--radix-popover-content-available-height`**。
   - 当触发器处于视口中间偏下导致单侧可用高度小于 `70vh` 时，浮层无法精确贴合可用高度，只能依赖 Radix 的 `shift` 中间件向上/向下硬推，导致浮层覆盖触发器或与视口边缘发生贴边形变。

3. **Tiptap 光标联动具备天然翻转鲁棒性**：
   - `TiptapSlashMenu` 基于当前光标 `DOMRect` 动态锚定，结合 `max-height: min(320px, 40vh)`（400px 下为 160px），在输入框自 1 行膨胀至 10 行时，能精准在上翻（光标在下方）与下翻（光标在上方）之间无缝切换，几何交集完全封闭在安全视口内。

## 二、全维度排列组合压力测试矩阵 (96 种状态交叉分析)

### 1. 几何参数定义

- $V_H$: 视口高度（400px, 600px, 800px, 1200px）
- $B_{pad}$: Composer 底部距视口下边缘（10px, 20px, 60px）
- $H_{comp}$: Composer 总高度（1行=48px, 2行=58px, 5行=135px, 10行=290px）
- $H_{footer}$: Composer Footer 触发器区域高度（固定 36px，位于 Composer 底部）
- $P_{col}$: Radix `collisionPadding`（固定 12px）
- $S_{off}$: Radix `sideOffset`（Menu 系为 6px，Slash 为 8px）
- $Y_{trig}$: Footer 触发器顶部坐标 $= V_H - B_{pad} - H_{footer}$
- $Space_{top}$: 触发器上方可用空间 $= Y_{trig} - S_{off} - P_{col} = V_H - B_{pad} - 54\text{px}$
- $Space_{bottom}$: 触发器下方可用空间 $= (V_H - P_{col}) - (Y_{trig} + 28\text{px} + S_{off}) = B_{pad} + 2\text{px}$

## 三、5 大组件的真实 DOM 几何剖析与代码审查

### 1. `Menu.tsx`（菜单基座）

- **文件路径**：`apps/crish-desktop/src/components/ui/Menu/Menu.tsx:320-336`
- **样式文件**：`apps/crish-desktop/src/components/ui/Menu/Menu.module.css:5-23`
- **真实 DOM 高度公式**：
  $$H_{dom} = 2\times P_{vertical} + 2\times B_{width} + N_{opt}\times H_{item} + (N_{opt}-1)\times G_{item} + H_{title}$$
  - $P_{vertical} = 4\text{px}$ (`--dropdown-padding`), $B_{width} = 1\text{px}$
  - $H_{item} \approx 30\text{px}$ (`padding: 6px 8px; font-size: 13px; line-height: 18px`)
  - $G_{item} = 2\text{px}$ (`--dropdown-gap`)
  - 10 个标准选项高度 $= 8 + 2 + 10\times 30 + 9\times 2 = 328\text{px}$。
- **CSS 约束分析**：
  `max-height: min(70vh, 360px); overflow-y: auto;`
  - 在 400px 视口下，$70\text{vh} = 280\text{px}$。328px 的 DOM 高度会被强行截断至 280px，并激活原生内嵌滚动条。
  - Radix `avoidCollisions={true}` 结合 `collisionPadding={12}` 保证容器上边界不超出 $y = 12\text{px}$。

### 2. `PermissionModeMenu.tsx`（权限模式菜单）

- **文件路径**：`apps/crish-desktop/src/components/chat-composer/PermissionModeMenu.tsx:50-95`
- **样式文件**：`apps/crish-desktop/src/components/chat-composer/PermissionModeMenu.module.css:62-76`
- **选项构成**：`['ask', 'deep', 'plan', 'full']`（固定 4 项）
- **真实 DOM 几何测算**：
  - 容器 Padding: 4px 上下 $= 8\text{px}$，Border: $2\text{px}$
  - 4 个 `.permMenuItem`（`min-height: 28px; padding: 5px 8px;`）：$4 \times 28\text{px} = 112\text{px}$
  - Gap: $3 \times 1\text{px} = 3\text{px}$
  - **总固有高度** $= 8 + 2 + 112 + 3 = \mathbf{125\text{px}}$
- **压力表现**：
  - 即使在 $V_H=400\text{px}$ 且输入框膨胀至 10 行 ($Space_{top}=286\text{px}$) 下，125px 远小于 286px，**永远不需要产生滚动条，且绝无溢出风险**。

## 四、极限视口下的安全高度计算公式与 CSS 约束清单

### 1. 严格安全高度推导公式

为了在任意视口高度 $V_H$、任意输入框膨胀高度 $H_{comp}$ 下实现 100% 几何不溢出，浮层高度上限计算公式必须满足：

$$MaxHeight_{safe} = \min\left( \text{DesignMax}, \max(120\text{px}, \text{AvailableHeight}) \right)$$

其中：

- $\text{AvailableHeight} = \text{var}(--\text{radix-popover-content-available-height})$
- 最小安全保底高度 $120\text{px}$（保证至少可见 2~3 个选项可供键盘漫游与滚动）。
