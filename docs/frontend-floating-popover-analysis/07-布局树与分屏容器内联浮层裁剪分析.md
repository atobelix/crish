# 07 - 布局树、分屏容器与内联浮层裁剪深度分析报告

**分析师角色**：【Agent 07: 布局树 / SplitView / 容器边界分析师】  
**审计范围**：`apps/crish-desktop/src/components/` 下所有多卡片分屏、布局树、工具标签页与侧栏组件  
**审计基准**：纯分析，零代码修改

## 核心结论摘要

1. **容器边界与裁剪死锁**：
   - 布局树容器 `.workspaces-stack`（`overflow: hidden !important; isolation: isolate;`）、`.leaf`（`overflow: hidden; isolation: isolate;`）、`.leafBody`（`overflow: hidden;`）、`.filesCard`（`overflow: hidden;`）以及 `.header`/`.ws-chrome-row`（`height: 30px/38px; overflow: hidden;`）形成了多层严格的裁剪视口与独立层叠上下文（Stacking Context）。
   - 任何未通过 React `createPortal` 或 Radix `Popover.Portal` 脱离 DOM 树的内联浮层（`position: absolute`），在遇到多分屏（2x2、3 分屏）、窄视口或靠近卡片边缘时，会被**100% 裁剪截断或完全不可见**。

2. **发现的 5 大类严重内联浮层裁剪缺陷**：
   - **`LeafToolTabStrip.tsx:227-259`**：工具 leaf 加号下拉菜单 `.addDropdownMenu` 绝对定位在 `height: 30px; overflow: hidden;` 的 `.header` 内，展开即被 100% 裁切消失！
   - **`SessionStrip.tsx:91-114` / `WorkspaceStrip.tsx:98-125`**：会话/工作区添加菜单 `.wsChromeAddMenu` 绝对定位在 `overflow: hidden` 的 `ws-chrome-row` 内，同样被整体截断！
   - **`FileBreadcrumb.tsx:233-329`**：文件面包屑目录弹出层 `.filesBcFlyout`（宽 320px、高 400px）内联绝对定位在 `.filesCard` 内，在窄分屏或低矮分屏下被严重削顶/截断！
   - **`FileActions.tsx:273-336, 360-412` 与 `FileViewerCard.tsx:306-367, 403-446`**：文件打开方式菜单 `.filesOpenMenu` 与更多菜单 `.filesMoreMenu` 全为内联绝对定位，在垂直分屏下底部项目全被截断！
   - **`SlashMenuOverlay.tsx:127-158`**：NotePaper 的 React slash 浮层直接绝对定位在 `.readingColumn` 内，分屏下靠近卡片底部即被 `.leaf` 裁切。

3. **4 处二级 Flyout 级联越界死角（无碰撞反转）**：
   - `ContextMenuFlyout.tsx`（`.sortFilterFlyout`）、`ProjectPickerMenu.tsx`（`.cascadeSubmenu`）、`ModelProfileList.tsx`（`ModelsCascadeSelect` 的子 flyout）、`ModelBadgePickerMenu.tsx`（`.mbSubMenu`）均为硬编码单向弹出（向右或向左），在靠近视口边缘时直接溢出屏幕，缺乏双向碰撞反转。

4. **需要废弃收敛的自定义坐标计算与手写浮层状态**：
   - `CardPanelHeader.tsx:29-47` 的 `placeTabsAddMenu`
   - `ModelProfileList.tsx:32-40` 的 `place()`
   - `FileActions.tsx` 与 `FileViewerCard.tsx` 的手写 `useMenu`、`mousedown` 监听与自定义 Portal/绝对定位
   - `workspaceChromeHooks.ts:329-352` 的 `useChromeAddMenu`
