# 一、重构宪章与系统级不变量 (System Charter & Invariants)

### 1.1 零信任设计哲学与单一真相源 (SSOT)

1. **DOM 树完全隔离原则**：所有具有弹出性质的浮层（Menu, Popover, Tooltip, Dialog, Flyout, Toast）必须通过 `createPortal` 挂载至 `document.body` 根节点下的受控容器，严禁在卡片或局部具有 `overflow: hidden`、`contain: content`、`transform`、`backdrop-filter` 的 DOM 节点内采用内联绝对定位。
2. **单一几何真相源（SSOT Geometry）**：所有坐标计算一律以 `window.visualViewport` 提供的物理视口为绝对基准坐标系，严禁在不同组件内使用不同的视口宽度源（`innerWidth` vs `clientWidth` vs `visualViewport`）。
3. **可审计单一状态栈（Single Auditable Layer Stack）**：全系统浮层生命周期、焦点锁定、Esc 消费与外点关闭，收敛于全局唯一的 `LayerStackService`，禁止任何业务组件私自注册捕获阶段的全局键盘/指针监听器。

### 1.2 绝对禁止的 8 大反模式 (The 8 Architectural Prohibitions)

- ❌ **禁手写坐标计算**：禁止任何组件裸写 `getBoundingClientRect` 偏移算法（如 `placeTabsAddMenu`、`place()`）。
- ❌ **禁内联绝对定位浮层**：禁止在具有裁剪特性的祖先中渲染 `position: absolute` 下拉菜单。
- ❌ **禁全屏透明 Backdrop**：禁止使用 `position: fixed; inset: 0` 的隐式遮罩拦截鼠标事件（破坏 WebView2 原生事件传递与拖拽区识别）。
- ❌ **禁全局 Capture 阶段抢占**：禁止裸写 `window.addEventListener('keydown', ..., true)` 拦截 `Escape`。
- ❌ **禁破坏性 CSS 属性**：禁止在全局或工作区容器中使用 `transform: translateZ(0)`、`contain: paint/content` 作为硬件加速手段。
- ❌ **禁点矩形光标坍缩**：禁止将光标构造为宽高为 0 的 `(x, y, 0, 0)` 点矩形并以此定位浮层。
- ❌ **禁虚假零点防御逻辑**：禁止通过 `rect.top !== 0 || rect.left !== 0` 判定坐标有效性。
- ❌ **禁 DOM 原型链猴子补丁**：禁止在测试中将 `Range.prototype.getBoundingClientRect` 粗暴 Mock 为全 0 数据。

# 二、`LayerStackService` 全局浮层与焦点管理中枢

### 2.1 全局浮层栈注册拓扑

建立单例 `LayerStackService`，统一管理系统中所有处于激活状态的浮层实例：

```typescript
export type LayerType =
  | 'dialog'
  | 'menu'
  | 'submenu'
  | 'contextmenu'
  | 'popover'
  | 'tooltip'
  | 'toast';

export interface LayerRegistration {
  id: string;
  type: LayerType;
  parentId?: string;
  element: HTMLElement;
  portalContainer: HTMLElement;
  dismissible: boolean;
  trapFocus: boolean;
  restoreFocusRef?: React.RefObject<HTMLElement | null>;
  onDismiss: () => void;
  onEscapeKeyDown?: (event: KeyboardEvent) => boolean | void; // 返回 true 表示已消费，阻止默认退栈
}
```

- **树状层级拓扑（Tree-Aware Hierarchy）**：支持注册 `parentId`。当一级菜单打开二级子菜单（SubMenu）或弹窗内打开 Select 下拉菜单时，子层级明确指向父层级。
- **动态层级提升**：当子层级注册时，`LayerStackService` 自动将其挂载在父层级相同的逻辑上下文之上，杜绝遮罩被截断。

### 2.2 栈式 Esc 单一消费链设计 (Single Consumer Escape Dispatcher)

彻底拔除散落在业务代码中的 15 处全局 `addEventListener('keydown', ..., true)` 与 17 处未调用 `stopPropagation` 的冒泡监听器。

1. **唯一宿主监听器**：全系统仅在 `LayerStackService` 构造时在 `document` 上注册 **1 个** 标准 `keydown` 监听器。
2. **精确顶层分发时序**：
   ```
   [User presses Escape]
     ──> LayerStackService.handleKeyDown (Capture Phase or Bubble Phase)
     ──> 获取 Stack.top (当前最顶层激活的 Layer)
     ──> 检查 IME 状态 (e.isComposing || e.keyCode === 229) -> 若为 true 直接放行，不触发任何关闭
     ──> 执行 Stack.top.onEscapeKeyDown?(e)
     ──> 若未被 preventDefault:
           调用 Stack.top.onDismiss()
           调用 e.preventDefault() 与 e.stopPropagation()
           焦点平滑还原至 Stack.top.restoreFocusRef
   ```
3. **根治 6 大灾难性穿透场景**：
   - 设置页录制快捷键时，录制状态作为顶层虚拟 Layer 注册，按 Esc 仅取消录制，设置页保持开启；
   - 审批卡、计划抽屉、多层确认弹窗严格按栈顶一次退一层，绝无按一次 Esc 连关三层的问题。

### 2.3 `FocusTrap` 架构重构与引用计数白名单引擎

彻底重构 `ui/Dialog/focusTrap.tsx`：

1. **白名单判定算法（Whitelist Algorithm）**：
   `FocusTrap` 在遍历 `document.body.children` 注入 `inert` 和 `aria-hidden` 时，执行以下谓词判定：
   ```typescript
   function shouldBypassInert(node: Element, currentLayerId: string): boolean {
     if (node.hasAttribute('data-focus-trap')) return true;
     if (node.hasAttribute('data-radix-popper-content-wrapper')) return true;
     if (
       node.hasAttribute('data-layer-portal') ||
       node.hasAttribute('data-tooltip-portal')
     )
       return true;
     if (node.classList.contains('toastStack')) return true;
     return false;
   }
   ```
2. **引用计数与堆叠沙盒（Reference-Counted Isolation）**：
   - 引入全局 `inertMap: Map<Element, number>`。
   - 当 Layer 1 激活时，将 `#root` 的计数加 1，并设为 `inert=true`；
   - 当 Layer 2（子弹窗）激活时，仅将 Layer 1 与 `#root` 的计数各加 1；
   - 当 Layer 2 卸载时，将计数各减 1；由于 Layer 1 对 `#root` 的计数仍为 1，`#root` 依然保持 `inert=true`，直到 Layer 1 退出时计数归零才完全解冻！

### 2.4 Radix `DismissableLayer.Branch` 树拓扑与 PointerDown 统一收敛

1. **Branch 自动注册**：在 `ui/Menu` 与 `ui/Dialog` 中，所有挂载在 `document.body` 上的子浮层（Tooltip、Flyout、ConfirmGate）均自动包裹 Radix 的 `<DismissableLayer.Branch>`。
2. **PointerDown 统一拦截**：
   - 在 `Dialog`、`Menu`、`Tooltip` 的 Portal 根节点上统一绑定 `onPointerDown={(e) => e.stopPropagation()}` 与 `onMouseDown={(e) => e.stopPropagation()}`；
   - 阻断事件穿透至底层 Radix 的 `onPointerDownOutside` 监听器，彻底消除“点击 Tooltip 或子确认框导致父 Menu 闪退”的故障。

# 三、`ui/Menu` 统一基座彻底升级与级联子菜单架构

### 3.1 视口可用高度动态闭环与高度安全公式

在 `Menu.module.css` 中，强制将 `max-height` 绑定 Floating UI 注入的可用高度变量：

```css
.menuContent {
  max-height: min(
    var(--radix-popover-content-available-height, 360px),
    70vh,
    360px
  );
  max-width: min(
    var(--radix-popover-content-available-width, 100vw),
    calc(100vw - 24px)
  );
  overflow-y: auto;
  overflow-x: hidden;
  -webkit-overflow-scrolling: touch;
}
```

### 3.2 触发器与 Ref 拓扑穿透收敛

1. **多层 Tooltip 递归解构**：`Menu.tsx` 内部实现 `unwrapTooltipTrigger(trigger)`，无损提取最内层真实 DOM 节点与 Tooltip content。
2. **无损 Ref 合并**：接入 `useMergeRefs(forwardedRef, childRef, customAnchorRef)`。

### 3.3 Anchor 模式与 Trigger 模式的外点竞争消解 (Anti-Double-Toggle)

在 `anchor` 模式下，针对用户点击锚点按钮试图关闭菜单时的「外点关闭 vs 原生 click 重开」竞态，在 `onInteractOutside` 中通过 `anchor.current?.contains(event.target)` 进行白名单拦截并调用 `e.preventDefault()`。

### 3.4 工业级级联子菜单（SubMenu / Flyout）基座体系

采用 `@radix-ui/react-popover` 嵌套子实例或基于 Floating UI 虚拟锚点的 `MenuSub` 基座组件，支持双向视口碰撞自适应（右侧不足自动向左翻转），并引入 120ms 防抖与键盘漫游互斥锁。

# 四、LineBox 富文本光标选区几何测量系统 (Tiptap / ProseMirror)

### 4.1 物理 LineBox 测量数学模型与字形包围盒恢复

彻底废除 `SlashExtension.ts:277` 返回的 `new DOMRect(coords.left, coords.bottom, 0, 0)` 零维点矩形。

```typescript
export function measureCursorLineBox(view: EditorView, pos: number): DOMRect {
  const coords = view.coordsAtPos(pos, 1);
  const lineHeight = Math.max(18, coords.bottom - coords.top);
  const top = coords.top;
  const bottom = coords.bottom;
  const left = coords.left;
  const right = Math.max(coords.right, coords.left + 2);

  return new DOMRect(left, top, right - left, bottom - top);
}
```
