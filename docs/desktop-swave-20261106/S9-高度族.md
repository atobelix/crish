### A1. H-01 逐行生长 + H-03 发送后回落 —— 卡片高度同钟滑翔

新增 `apps/crish-desktop/src/components/chat-composer/useComposerCardHeightGlide.ts`：

- 引擎 `ComposerCardHeightGlide`（框架无关、独立单测）：以卡片 `scrollHeight + 边框` 测自然高（不受显式 height 干扰），用 WAAPI 把卡片 `height` 从**当前呈现值**滑翔到目标高；时长 `calcAccordionDuration(|Δ|, 方向)`（高度族单一时长源，展开 150–220ms / 收起 150–200ms 口径由该函数内建），曲线 `EASE_DECELERATE` token，无任何内联时长/曲线字面量。
- 重靶向：动画中途目标再变（连续打字逐行生长）时，先读当前动画实时呈现高、取消旧动画、从实时值向新目标重靶向——不跳回起点、不排队。文本回显零延迟：引擎只写卡片外框 `height` 一个属性，编辑器本体高度与内容布局即时生效、不裁剪（守 H 册反例 3）。
- Hook 绑定：`ResizeObserverManager` 监听卡片全部子元素（主输入网格随编辑器生长/模式重构变高、顶槽手风琴变高均触发），`MutationObserver(childList)` 在附件条/顶槽挂卸时重绑并同步；首次接管直接落位（挂载不播动画）；减动效（`prefers-reduced-motion` 或应用 `[data-reduced-motion]`）直接落位；卸载时取消动画并清除显式高度。
- H-03 发送后回落是同一机制的反向路径：清空文本 → 编辑器收缩 + 模式翻回单行，两条滑翔/补偿同时反向生效，无单独代码。
- 附带效应（如实登记，不冒充其他项结案）：附件条整条挂卸（H-04 的高度分量）、顶槽开合引起的卡片总高变化也会被同一滑翔吸收；芯片级退场仍归 S4 退场基建，本批不 claim。

### A2. H-02 模式切换平移补偿 —— FLIP

新增 `apps/crish-desktop/src/components/chat-composer/useComposerModeFlip.ts`：

- FLIP：每次布局提交后记录左右两组控件的落定位置；`isMultiline` 翻转的同一提交内（本 hook 的翻转 effect 声明在记录 effect 之前，保证先消费旧位置），先以 `transform: translate(旧-新)` 把两组瞬时逆位移到旧位置并强制回流，再以 `calcAccordionDuration(位移距离, true)` + `EASE_DECELERATE` 过渡回 identity——控件滑到新行而非瞬移。
- 中途反向（动画未完又翻回去）：从元素当前视觉位置（含 transform 的包围盒）重新逆位移，先清旧定时器，不跳回起点重播（E 类 2 可打断/可反向硬要求）。

- 边界（如实登记）：字段槽（文本区）在两态间是整行宽度重排，属布局重排而非平移，未做 transform 补偿（scale 会拉伸文本）；其高度分量由 A1 滑翔覆盖。

## B 组 · 底部折叠案（用户点名）——机制定位 + 守卫侧已施工 + 主机制规格登记

### 机制定位结论（全链逐行核查，代码事实）

用户场景（工具内容展开、滚到最底部、点收起 → 下方内容先上移、再被高度修正机制往回拽，两步弹跳）由**三个行为者**叠加，决定性主因在虚拟滚动层：

1. **切换即脱离跟随（既有裁定，非缺陷）**：`useScrollAnchoringOnToggle.ts` 的 `activateAnchorLock()` 在指针按下捕获期即把 `isAtBottom` 置假并锁 500ms（批 B ⑰口径，toggle 即 detach）。故折叠期间贴底跟随不工作——用户要的也不是恢复跟随，而是**这次折叠自身**把滚动同钟回收。
2. **主因：手风琴运动锁的延迟落高 → 总高一步提交 → 浏览器钳制回拉**。`FoldableToolGroup` 收起时经 `acquireAccordionMotionLock(dur + 60)`（`api/VirtualScrollManager.ts`）上锁；锁定期内 `hooks/useVirtualScroll.ts` 的 `setActual` / `scheduleActualFlush` / `flushActualMeasurements` 全部短路，逐帧测得的行高只进 `pendingActualRef` 缓冲。布局侧：行在切片容器内是流式排布，折叠行下方各行随高度动画**同步上移**（第一步「下方内容先上移」），但占位层 `.listInner` 的 height 仍是模型旧总高，`scrollHeight` 不变、scrollTop 不动，内容物理底边与视口底边之间张开一条随折叠增长的空带。解锁瞬间 `onAccordionUnlock → flushActualMeasurements(true)` 把 ΔH **一次性**提交：总高/占位高/scrollHeight 同帧阶跃 −ΔH，浏览器把 scrollTop 一次性钳制回拉（第二步「往回拽」）。这与 A 册对滚动条的实测（virtualizer 约在动画 232ms 处一步提交总高）是同一机制的两个侧面。
3. **竞速的第三运动：守卫的 scrollIntoView**。`ReasoningRow`（点击处理内、状态翻转前）与 `FoldableToolGroup`（isExpanded effect 内）在折叠起点调用 `useAccordionViewportGuard.triggerViewportRecovery()`；当折叠元素顶已滚出视口上方（判底时展开着高个工具组/思考体，此为常态）时，守卫以 `scrollIntoView({block:'start', behavior:'smooth'})` 另起一条**浏览器时钟**的平滑滚动，与高度动画（手风琴时钟）互不知情——既不是底边钉住，也不是同钟回收。
   - 附注：思考行（ReasoningRow）折叠不经 VSM 运动锁，其行高经逐 rAF flush 渐进提交、钳制逐帧发生，本身接近单程运动；它的判底竞速主要来自第 3 项。工具组折叠（用户点名原案「工具内容」）则三项全中。

**文件归属判定**：主因（第 2 项）的决定性代码在 `hooks/useVirtualScroll.ts` + `api/VirtualScrollManager.ts` + 锁的取得方（FoldableToolGroup 内 `acquireMotionLock` 链），属主消息列表虚拟滚动面（S3 批「virtualizer 总高一步提交协调」已登记的同一机制）与禁改文件本体——按红线**不施工**，精确规格见下。第 3 项的决定性代码在独立 hook `hooks/useAccordionViewportGuard.ts`（不在禁改清单）——**已施工**。

### 已施工：守卫判底豁免（`hooks/useAccordionViewportGuard.ts`，+56 行）

- `triggerViewportRecovery()` 入口新增判底：滚动容器（显式 `scrollContainer` 选项 ?? 新增的 `findScrollableAncestor` 向上发现首个 overflow-y 可滚动且内容真溢出的祖先）满足 `scrollHeight - clientHeight > 1` 且距底 ≤ `BOTTOM_STICK_EPSILON_PX`（2px，与 `messageVirtualizerScrollState` 自身贴底判定共用同一常量，`hooks/virtualScrollConstants.ts`）时**直接返回**，不发任何回收滚动——判底折叠的底边由折叠自身的同钟回收负责（下节规格），守卫不再另起时钟竞速。
- 非底部路径逐字不变：rect.top 判定、deltaY 数学、显式容器 `scrollTo` 分支、无容器 `scrollIntoView` 分支、reduced-motion 降级、isGuardingRef 时序全部原样（发现到的容器只用于判底，不改变回收的执行路径）。

### 规格登记（主因同钟回收，交 S3 批或收口后专批执行）

目标：判底折叠时，总高提交与滚动回收逐帧随高度动画同钟完成，解锁时 Δ≈0、无阶跃、无钳制跳。

1. **判底标记**：`VirtualScrollManager.acquireAccordionMotionLock` 取得锁时（或首次 locked flush 时）由 `useVirtualScroll` 以其 `containerRef` 判底（`scrollHeight - scrollTop - clientHeight ≤ BOTTOM_STICK_EPSILON_PX`）；判底则给本锁打 `bottomPinned` 标记（manager 上加一字段，随锁计数生命周期）。非判底锁行为与现状**完全一致**（延迟落高 + 解锁时 deltaAbove 补偿不动）。
2. **锁内逐帧落高 + 钉底**：`bottomPinned` 锁活跃期间，`setActual` 的缓冲与 `scheduleActualFlush` 不再短路（按未锁路径逐 rAF flush）；每次 flush 提交后同帧执行 `container.scrollTop = max(0, container.scrollHeight - container.clientHeight)`，使视口底边逐帧钉住——总高收缩多少、scrollTop 同步回收多少，与高度 transition 同一帧序列（同一时钟 = 手风琴自身的帧推进，非另起 smooth 滚动）。
3. **手势让行**：flush/钉底前检查手势状态（`gestureActiveRef` 为真，或原生 scroll 事件显示用户已离底 > ε）→ 立即取消本锁的 `bottomPinned`，余下时长回落到现行延迟语义，用户滚动零对抗。
4. **解锁对账**：现有 `onAccordionUnlock → flushActualMeasurements(true)` 保留为终局对账；bottomPinned 路径下其增量应 ≈0（契约测试钉住：解锁帧 totalHeight 阶跃 ≤ 1px）。
5. **取得方**：`FoldableToolGroup` 的 `acquireMotionLock(dur + 60)` 调用点与 ReasoningRow 的无锁路径均不需改签名——判底在 useVirtualScroll 侧以容器几何自判；ReasoningRow 折叠维持现有逐 rAF 渐进提交 + 本批守卫豁免即可，不纳入 bottomPinned（避免双轨）。
6. **回归面**：`hooks/useVirtualScroll.test.ts`、`api/VirtualScrollManager.test.ts`、`api/__tests__/virtualScroll.stability.test.ts`、`MessageVirtualizer.*.test.tsx`（domPurge/measure/perf）须全绿；新增契约：判底折叠全程逐帧 `scrollHeight - scrollTop - clientHeight ≤ 1px` 且解锁帧无阶跃；非判底折叠轨迹与现状快照一致。
