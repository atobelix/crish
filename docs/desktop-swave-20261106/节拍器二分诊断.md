| alidns-dom | 09:48:31.685Z | 04:48:31 | 无 | ≥2100s（满窗口） |

各连接的 +720s（10:00:31Z）、+1440s（10:12:31Z）时刻均无事件。**纯闲置流在公网路径上活过了 2.92 个标称周期**——若杀手是路径上的闲置超时或定点节拍器，本窗口内必应至少触发两次。检测盲区如实声明：本法可检出带 FIN/RST 的拆除；静默黑洞式死亡（映射丢失且无拆除包）检不出，但每 60s 的新建握手探针证明路径本身全程可用（见 §1.4），且同一服务器对 tailnet 流的拆除是带 FIN 的（§1.3），无理由认为公网侧会独走静默模式。

### 1.3 实测到的真节拍器：中继服务器 ≈61s 首字节超时（服务端）

relay-tailnet 原始 TCP（连上后不发任何字节）被服务器以 FIN 周期性拆除，29 个周期高度规整：

- 存活时长：n=29，**均值 61.05s，最小 60.4s，最大 61.9s**（抖动 ±0.8s）。
- 断点时刻（UTC，首五次 + 末次，其余 23 次见原始日志）：09:49:32.314 → 09:50:43.423 → 09:51:55.016 → 09:53:06.588 → 09:54:17.324 → … → 10:22:59.388；每次重连后重新计时，是**流龄计时**而非墙钟相位。
- 定性：这是中继服务器对「TCP 已连接但迟迟不发首字节（不做 TLS ClientHello）」的握手阶段超时（≈60s），属**服务端应用层策略**，与 NAT/路径无关（拆除带 FIN、重连立即成功）。它证明一件事：**该中继服务端确实在执行激进的连接计时策略**。

附带校准（运行 #2，09:45:57Z 起的一次短观测）：一条完成 TLS 握手但不发应用数据的 relay-public 连接，在建立（09:46:07Z）后约 100s 内被服务端 FIN（09:47:4xZ 快照见 CloseWait）。该读数与本次主窗口「同形态连接存活 2100s」不一致，且与我方停止该次观测任务的时刻相距 ±30s 内，**时间归属有歧义**，只登记为弱证据：服务端对未认证 TLS 连接的容忍度可能随其状态波动，不作为定论依据。

### 1.4 唯一路径事件：≈90s 新建连接停滞（非周期、非拆流）

10:07:28–10:08:54Z（EST 05:07:28–05:08:54）出现一次短暂事件：

| 时刻（UTC） | 事件 |
|---|---|
| 10:07:28.680 | 观测心跳出现 26s 间隔（观测器主循环被阻塞的探针调用拖住） |
| 10:07:53.417 | probe-relay-public 新建 TLS 握手读超时失败（另有一次成功握手耗时 11366ms） |
| 10:08:33–10:08:54 | relay-tailnet 重连被拖延（间隔 21.3s，平常 10.4s） |
| 10:08:53.388 | probe-cf-public 新建连接超时（8009ms） |

探针总计：relay 35 成功 / 1 失败，cf 34 成功 / 1 失败，两次失败同落此窗。特征：**只伤新建连接，已建立的闲置流无一被拆**（三条 TLS 流与 SSH 活跃会话均无事件）；公网与 tailnet 两条路径同时受累，指向 PC 出网侧/中转链路的一次短暂拥塞或抖动。相位核对：事件起点距 relay 流建立 +1137s、距 SSH 会话建立 +1383s，**与 720s 的任何整倍数不对齐**。35 分钟内仅此一次，不构成节律。

### 1.5 拓扑事实（与节律判定相关）

- PC 仅 Wi-Fi 联网：Realtek 8821CE，192.168.0.196，网关 192.168.0.1；以太网未接。
- tracert 出网：hop2 = **172.21.4.1**、hop3 = **192.168.205.2**（均为私网地址）→ 家庭路由器 WAN 侧之后还有运营商私网层；STUN 公网地址 **39.144.129.14（中国移动）**；Tailscale netcheck：`MappingVariesByDestIP: true`（端点相关映射，即对称型 CGNAT 行为）、UDP 可用、最近 DERP 为东京（83ms）。
- 结论：**多层 NAT + 运营商 CGNAT 的拓扑属实**，但其超时行为在本窗口未触发（见 §二）。
