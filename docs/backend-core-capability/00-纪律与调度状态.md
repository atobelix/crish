## 1. 核心闭环（本轮边界）

用户发一条消息之后，后端必须走完这条链，并且每一步的结果能被下一步当真：

```text
Tauri core_run_*
  → orchestrator（run / 会话树 / 事件）
  → session-loop（回合状态机 / 控制 / 工具批）
  → agent-provider（请求 / 流 / 解析 / 重试）
  → agent-tools + conex-sandbox（工具 / 权限 / 沙箱）
  → conex-db（会话、消息、run、事件、压缩块）
  → 压缩与摘要回到下一回合
  → 事件桥回到壳
```

笔记与工作区存储算在闭环里：代理改文档走 `NoteBackend` → `conex-note-runtime` → `conex-workspace-store`，不是旁边的编辑器功能。

本轮不覆盖（相邻后端，另开）：浏览器、电脑操作、多设备与中继、推送、PTY、定时任务、遥测、认证、Markdown 渲染。

## 2. 什么算问题

要记：

- 能力做不到，或调用方以为接上了，生产路径却是空实现、`None`、只打日志
- 做错：丢字段、重复执行、终态不对、工具对拆开、序列号断
- 静默降级：失败变成成功、跳过、空结果
- 双轨：两套状态或两套协议会分叉
- 契约断裂：层与层之间字段、错误类、事件名对不上
- 数据丢、回合卡住、核心路径上的安全口子

不记：风格、行数、命名、注释语言、纯重构愿望、测试数量本身。旧文档（`docs/rust-rewrite/`、`docs/backend-optimization/`、`docs/architecture/system-map-clear.md`）只当线索。以当前代码为准。已经修好的写进「已核对闭合」，不要再当成现存问题。
