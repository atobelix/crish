## 二、缺陷深度剖析与极致修复方案

### [严重级别: 致命] 分组渲染与评分排序索引脱节导致的按键回车/高亮错选与 ARIA 错位
- **文件路径**：`apps/crish-desktop/src/components/settings/FontSelectField.tsx:87-98, 174-177, 313-339, 349-375` & `apps/crish-desktop/src/components/settings/internal/useFontKeyboardNav.ts:90-95`
- **缺陷剖析**：
  1. `filterAndSortIndexedOptions` 返回的 `filteredOptions` 是按**加权匹配得分（Score）倒序 + 中文 Collator**排序的一维数组；
  2. 但在 JSX 渲染阶段，组件使用 `groupedList` 将选项强行拆分为 `presets`（预设）与 `locals`（本机）两个子数组，并**固执地先渲染全部预设组、后渲染全部本机组**；
  3. 渲染循环中通过自增 `let flatOptionCursor = 0` 为 DOM 节点分配 `flatIdx`（DOM 结构中所有 preset 为 `0 ~ N-1`，所有 local 为 `N ~ N+M-1`）；
  4. 当用户输入搜索词（如 `"cas"`）时：
     - `filteredOptions[0]` 为 `Cascadia Code`（本机字体，得分 85）；
     - `filteredOptions[1]` 为 `Inter`（预设字体，得分 70）；
     - 在 DOM 树中，`Inter` 先被渲染并分得 `flatIdx = 0`（`id="...-opt-0"`），`Cascadia Code` 后被渲染并分得 `flatIdx = 1`（`id="...-opt-1"`）；
     - 初始 `focusedIndex = 0`，视觉高亮 `.isFocused` 亮在 `flatIdx = 0`（即 `Inter`），`activeDescendantId` 也指向 `Inter`；
     - 但用户按下 `Enter` 键时，`useFontKeyboardNav` 执行 `onSelectCurrent(0)`，直接索引 `filteredOptions[0]`，实际选中的却是 `Cascadia Code`！
  5. 鼠标悬停交互同样全面错乱：用户鼠标 Hover 在本机字体 `Cascadia Code`（`flatIdx = 1`）上触发 `setFocusedIndex(1)`，随即按回车，选中的却是 `filteredOptions[1]`（`Inter`）！
  6. **结果**：视口高亮项、屏幕阅读器读出的活动项（`aria-activedescendant`）与按键实际选中的条目发生严重的**三方脱节**。
- **极致修复方案**：
  放弃在 JSX 模板中二次分组时重新生成序号，统一以平铺的 `filteredOptions`（或构建结构化的 Flat Render List）作为单一数据事实源（Single Source of Truth），或者在搜索过滤激活时直接按打分序平铺渲染；在分组渲染时，必须将 DOM 索引与 `filteredOptions` 原始索引建立严格映射，或者让 `flatRenderList` 作为统一的导航与选择索引：
  ```tsx
  // 方案：统一构建平铺渲染队列并保留分组边界标头
  interface RenderItem {
    kind: 'header' | 'option';
    title?: string;
    option?: IndexedFontOption;
    optionIndex?: number; // 对应 filteredOptions 中的索引
  }

  const renderItems = useMemo<RenderItem[]>(() => {
    // 若处于搜索状态，按综合打分排序直接平铺，避免预设组与本机组被强行割裂
    if (searchQuery.trim().length > 0) {
      return filteredOptions.map((opt, idx) => ({
        kind: 'option',
        option: opt,
        optionIndex: idx,
      }));
    }
    // 无搜索词时，按预设/本机分组呈现
    const items: RenderItem[] = [];
    if (groupedList.presets.length > 0) {
      items.push({ kind: 'header', title: '预设与内嵌' });
      groupedList.presets.forEach((opt) => {
        const idx = filteredOptions.indexOf(opt);
        items.push({ kind: 'option', option: opt, optionIndex: idx });
      });
    }
    if (groupedList.locals.length > 0) {
      items.push({ kind: 'header', title: `本机系统字体 (${groupedList.locals.length})` });
      groupedList.locals.forEach((opt) => {
        const idx = filteredOptions.indexOf(opt);
        items.push({ kind: 'option', option: opt, optionIndex: idx });
      });
    }
    return items;
  }, [searchQuery, filteredOptions, groupedList]);
  ```

### [严重级别: 致命] 中文输入法 (IME) 合成阶段方向键与 Esc 冒泡拦截导致输入法候选框被劫持且弹窗误关闭
- **文件路径**：`apps/crish-desktop/src/components/settings/internal/useFontKeyboardNav.ts:48-60, 62-85`
- **缺陷剖析**：
  1. 在 `useFontKeyboardNav.ts` 的 `handleKeyDown` 中，针对 IME 合成态的判断逻辑为：
     ```typescript
     const isImeKey =
       isComposingRef.current ||
       (e.nativeEvent as unknown as { isComposing?: boolean })?.isComposing ||
       e.keyCode === 229 ||
       Date.now() - compositionEndStampRef.current < 160;

     if (isImeKey) {
       if (e.key === 'Enter') {
         e.preventDefault();
         e.stopPropagation();
         return; // 仅在此处拦截了 Enter
       }
     }
     ```
  2. 当用户在内嵌搜索框中使用中文输入法（如微软拼音、搜狗输入法、Rime）输入拼音（例如输入 `weiruan`），并按下 `ArrowDown` / `ArrowUp` 翻页选字，或者按下 `Escape` 取消当前拼音输入时：
     - 由于 `isImeKey` 判断分支内部**仅对 `e.key === 'Enter'` 进行了拦截并退出**；
     - 流程随后直接穿透并执行了后续的 `if (e.key === 'ArrowDown')`、`if (e.key === 'Escape')` 等分支；
     - `e.preventDefault()` 和 `e.stopPropagation()` 被强行触发；
  3. **后果**：
     - 用户在输入法候选栏按上下键选字时，输入法候选框失灵，而下方的字体下拉列表却在疯狂切换高亮；
     - 用户在拼音未上屏状态下按 `Escape` 试图清空拼音字母时，`onClose()` 被直接执行，**导致整个字体选择器下拉弹窗瞬间崩溃关闭**，未提交的输入全部丢失。
- **极致修复方案**：
  在 IME 合成态（及 `compositionend` 保护窗口）期间，除了明确需要捕获的 Enter 之外，直接无条件阻断组件内部所有的快捷键导航与关闭逻辑，允许浏览器与操作系统输入法正常消费键盘事件：
  ```typescript
  const handleKeyDown = useCallback(
    (e: React.KeyboardEvent<HTMLInputElement>) => {
      const isImeKey =
        isComposingRef.current ||
        (e.nativeEvent as unknown as { isComposing?: boolean })?.isComposing ||
        e.keyCode === 229 ||
        Date.now() - compositionEndStampRef.current < 160;

      // 处于 IME 状态时，严禁拦截并篡改 ArrowDown / ArrowUp / Escape / Space 等输入法专用键
      if (isImeKey) {
        if (e.key === 'Enter') {
          e.preventDefault();
          e.stopPropagation();
        }
        return;
      }

      if (e.key === 'ArrowDown') {
        e.preventDefault();
        e.stopPropagation();
        if (filteredCount > 0) {
          setFocusedIndex((prev) => (prev + 1) % filteredCount);
        }
        return;
      }
      // ...
    },
    [filteredCount, focusedIndex, onApplyCustom, onClose, onSelectCurrent]
  );
  ```

### [严重级别: 严重] 菜单基座 `Menu` 与内嵌输入框之间的焦点抢夺与双重键盘控制器冲突
- **文件路径**：`apps/crish-desktop/src/components/settings/FontSelectField.tsx:151, 187-220` & `apps/crish-desktop/src/components/ui/Menu/Menu.tsx:195-203`
- **缺陷剖析**：
  1. `FontSelectField` 将其全部浮层内容作为 `children` 传入了 `ui/Menu` 基座；
  2. `FontSelectField` 同时将 `menuOptions` 传给了 `Menu` 的 `options` 属性；
  3. 在 `Menu.tsx:195-203` 中，`Menu` 内部自带了一套焦点同步逻辑：
     ```typescript
     useEffect(() => {
       if (focusedIndex >= 0 && contentRef.current) {
         const items = contentRef.current.querySelectorAll<HTMLButtonElement>(
           '[role="menuitem"], [role="option"]'
         );
         const target = items[focusedIndex];
         target?.focus();
       }
     }, [focusedIndex]);
     ```
  4. 当弹窗打开时，`Menu` 会立刻将 DOM 焦点强制派发给第一项 `<button role="option">`；
  5. 此时 `FontSelectField.tsx:151` 中的 `setTimeout(() => searchInputRef.current?.focus(), 30)` 又在 30ms 之后强行把焦点抓回 `<input>`；
  6. 这引发了典型的**焦点拉锯竞争（Focus Race Condition）**，并在低端机器或重负载渲染时导致光标在按钮与输入框之间来回跳跃；同时，若焦点停留在 option 按钮上，`Menu` 的键盘监听器和 `FontSelectField` 的输入框键盘监听器会同时监听同一按键事件，导致双倍步进。
- **极致修复方案**：
  当 `FontSelectField` 作为自定义 Combobox 渲染且提供专属内嵌搜索框时，不应向 `Menu` 传递冗余的 `options={menuOptions}`，避免触发 `Menu` 内部的 `role="menuitem"` 自动捕获与按键漫游，统一由 `FontSelectField` 专属控制器管理焦点：
  ```tsx
  <Menu
    openState={{ open, onOpenChange: handleOpenChange }}
    // 明确清空 Menu 内部默认 option 调度，交由 FontSelectField 独占管理
    options={[]}
    position={{ side: 'bottom', align: 'start', sideOffset: 4 }}
    panel={{
      contentClassName: styles.settingsSelectMenu,
      contentStyle: { width: menuWidth, maxHeight },
    }}
    trigger={/* ... */}
  >
    {/* ... */}
  </Menu>
  ```

### [严重级别: 严重] 500+ 本机字体 `<button role="option">` 缺少 `tabIndex={-1}` 导致 Tab 漫游灾难
- **文件路径**：`apps/crish-desktop/src/components/settings/FontSelectField.tsx:317-338, 353-374`
- **缺陷剖析**：
  1. 在 WAI-ARIA 1.2 Combobox 设计模式中，活动项应由带有 `role="combobox"` 的 `<input>` 元素保持 DOM 焦点，并通过 `aria-activedescendant` 指向列表项；
  2. 列表项本身必须声明 `tabIndex={-1}`（或使用不可聚焦元素），以确保按下 `Tab` 键时，焦点能够正常跳出当前浮层移向页面的下一个表单控件；
  3. `FontSelectField.tsx` 中将每个字体选项实现为原生的 `<button type="button" role="option">`，但**完全遗漏了 `tabIndex={-1}` 声明**；
  4. 浏览器默认将 `<button>` 视为可 Tab 聚焦元素。当系统扫描出 500+ 款本地字体后，用户在搜索框内按下 `Tab` 键，焦点不会移至下一个设置项，而是陷入必须按 500 多次 Tab 才能遍历完所有字体按钮的**键盘焦点陷阱（Tab Trapping / Focus Swamp）**。
- **极致修复方案**：
  为所有 `role="option"` 按钮显式添加 `tabIndex={-1}`：
  ```tsx
  <button
    key={opt.value}
    id={`${listboxId}-opt-${flatIdx}`}
    data-opt-index={flatIdx}
    type="button"
    role="option"
    tabIndex={-1}
    aria-selected={isSelected}
    className={`${styles.settingsSelectItem} ${
      isSelected ? styles.isActive : ''
    } ${isFocused ? styles.isFocused : ''}`}
    onMouseEnter={() => setFocusedIndex(flatIdx)}
    onClick={() => handleSelect(opt.value)}
  >
    {/* ... */}
  </button>
  ```

### [严重级别: 严重] `scanViaQueryLocalFontsSafe` 未清理 `setTimeout` 定时器引发内存泄漏与未捕获拒绝
- **文件路径**：`apps/crish-desktop/src/components/settings/internal/fontStoreScan.ts:170-175`
- **缺陷剖析**：
  1. 在 `scanViaQueryLocalFontsSafe` 中，使用了 `Promise.race` 对 `win.queryLocalFonts()` 与 3000ms 超时 Promise 进行了竞态封装：
     ```typescript
     const rawFonts = await Promise.race([
       win.queryLocalFonts!(),
       new Promise<never>((_, reject) =>
         setTimeout(() => reject(new Error('queryLocalFonts timeout')), timeoutMs)
       ),
     ]);
     ```
  2. 当 `queryLocalFonts()` 在正常毫秒级（如 40ms）内解析成功时，创建的 `setTimeout` 定时器**从未被 `clearTimeout` 清除**；
  3. 3000ms 后，该定时器在后台触发并调用了 `reject(new Error('queryLocalFonts timeout'))`；
  4. 虽然外层 `Promise.race` 已经 resolve，但在部分 JS 运行时、单元测试环境（Vitest）或 Node.js 环境中，已经 orphan 的 Promise 触发 reject 会抛出 `UnhandledPromiseRejection` 警告或导致异步上下文泄漏。
- **极致修复方案**：
  显式管理定时器 Handle，并在任一方完成或出错时在 `finally` 块中严格清理：
  ```typescript
  export async function scanViaQueryLocalFontsSafe(timeoutMs = 3000): Promise<LocalFontEntry[]> {
    const supported = await canQueryLocalFonts();
    if (!supported) {
      throw new Error('Local fonts permission denied or unsupported');
    }

    const win = window as WindowWithLocalFonts;
    let timerId: ReturnType<typeof setTimeout> | undefined;

    try {
      const timeoutPromise = new Promise<never>((_, reject) => {
        timerId = setTimeout(() => reject(new Error('queryLocalFonts timeout')), timeoutMs);
      });

      const rawFonts = await Promise.race([win.queryLocalFonts!(), timeoutPromise]);

      if (!Array.isArray(rawFonts) || rawFonts.length === 0) {
        throw new Error('queryLocalFonts returned empty font catalog');
      }

      // ... 数据净化逻辑
    } finally {
      if (timerId !== undefined) {
        clearTimeout(timerId);
      }
    }
  }
  ```

### [严重级别: 严重] `yieldToMain` 采用 `requestAnimationFrame` 导致后台标签页字体扫描无限期冻结
- **文件路径**：`apps/crish-desktop/src/components/settings/internal/fontStoreScan.ts:132-140`
- **缺陷剖析**：
  1. `fontStoreScan.ts` 中的主线程让出切片函数实现为：
     ```typescript
     export function yieldToMain(): Promise<void> {
       return new Promise<void>((resolve) => {
         if (typeof requestAnimationFrame === 'function') {
           requestAnimationFrame(() => resolve());
         } else {
           setTimeout(resolve, 0);
         }
       });
     }
     ```
  2. 现代 Chromium 及桌面 WebView（Tauri / Electron）在标签页处于后台、窗口最小化或遮挡时，出于省电与性能策略，会将 `requestAnimationFrame` 的回调调用频率**降为 0 fps（彻底暂停执行）**；
  3. 当用户点击“全量扫描本机字体”并切换至其他工作窗口时，分片扫描循环在执行到 `await yieldToMain()` 时会被直接冻结挂起，直到用户重新激活该窗口才会缓慢恢复；
  4. 对于非渲染任务的主线程切片调度，`requestAnimationFrame` 是完全错误的 API 选择。
- **极致修复方案**：
  优先采用标准的 `scheduler.yield()`，降级采用 `MessageChannel` 或 `setTimeout(resolve, 0)`，确保在后台非激活状态下依然能够稳定推进任务：
  ```typescript
  export function yieldToMain(): Promise<void> {
    // 优先采用标准调度 API
    if (typeof (globalThis as unknown as { scheduler?: { yield?: () => Promise<void> } }).scheduler?.yield === 'function') {
      return (globalThis as unknown as { scheduler: { yield: () => Promise<void> } }).scheduler.yield();
    }
    // 降级使用 MessageChannel 或 setTimeout，严禁使用 requestAnimationFrame
    return new Promise<void>((resolve) => {
      if (typeof MessageChannel !== 'undefined') {
        const channel = new MessageChannel();
        channel.port1.onmessage = () => resolve();
        channel.port2.postMessage(null);
      } else {
        setTimeout(resolve, 0);
      }
    });
  }
  ```

### [严重级别: 严重] Canvas 2D 差分测宽测试字符串缺失 CJK 汉字导致纯中文字体假阴性漏报
- **文件路径**：`apps/crish-desktop/src/components/settings/internal/fontStoreScan.ts:203-222`
- **缺陷剖析**：
  1. 在 Canvas 2D 差分测宽探测函数 `isFontInstalledMultiBase` 中，测试基准字符串定义为：
     `const testStr = 'mmmmmmmmmmlli@Ww10';`
  2. 该字符串全部由西文字母、数字和符号构成，**没有任何 CJK 汉字字符**；
  3. 国内大量商用或系统专用中文字体（例如特定版本的《仿宋》、《楷体》、《霞鹜文楷》或特定 CJK 书法字体）并未内置专门设计的拉丁西文字形，西文字符会直接借用系统全局的 `monospace` 或 `sans-serif` 回退字形；
  4. 当测量 `ctx.font = '72px FangSong, monospace'` 时，由于 `'FangSong'` 缺省西文字形，Canvas 实际渲染的正是基准 `monospace`，导致 `monoTarget === monoBase` 与 `sansTarget === sansBase`；
  5. 偏离值判定全部小于 0.2px，导致已正确安装的本地中文字体被判定为“未安装”，产生严重的假阴性漏检。
- **极致修复方案**：
  在测宽探针字符串中必须同时混合西文极宽/极窄字符与高频 CJK 特征汉字（如“永”、“国”、“字”等）：
  ```typescript
  export function isFontInstalledMultiBase(family: string, ctx: CanvasRenderingContext2D): boolean {
    // 必须包含中英文特征字符，避免纯中文字体因西文回退导致测宽无差分
    const testStr = 'mmmmmmmmmmlli@Ww10字國永';
    const testSize = '72px';
    const cleanFam = `'${family.replace(/['"\\]/g, '')}'`;

    // 基准 1: monospace
    ctx.font = `${testSize} monospace`;
    const monoBase = ctx.measureText(testStr).width;
    ctx.font = `${testSize} ${cleanFam}, monospace`;
    const monoTarget = ctx.measureText(testStr).width;

    // 基准 2: sans-serif
    ctx.font = `${testSize} sans-serif`;
    const sansBase = ctx.measureText(testStr).width;
    ctx.font = `${testSize} ${cleanFam}, sans-serif`;
    const sansTarget = ctx.measureText(testStr).width;

    return Math.abs(monoTarget - monoBase) > 0.2 || Math.abs(sansTarget - sansBase) > 0.2;
  }
  ```

### [严重级别: 一般] `scrollIntoView` 缺乏边界约束导致外层容器/视口抖动
- **文件路径**：`apps/crish-desktop/src/components/settings/internal/useFontKeyboardNav.ts:27-35`
- **缺陷剖析**：
  1. 当键盘上下切换选项时，调用了 `(activeEl as HTMLElement).scrollIntoView({ block: 'nearest' })`；
  2. 原生 `scrollIntoView` 会沿着 DOM 树向上递归寻找所有具有滚动能力的祖先容器；
  3. 当设置面板本身处于页面滚动容器中或存在嵌套模态弹窗时，直接调用 `scrollIntoView` 会导致父级页面乃至整个窗口产生非预期的瞬态跳跃与抖动。
- **极致修复方案**：
  将滚动范围严格限制在当前的列表容器 `scrollContainerRef.current` 内部，通过精确的 `scrollTop` 差值计算进行局部平滑卷动：
  ```typescript
  useEffect(() => {
    if (focusedIndex < 0 || !scrollContainerRef.current) return;
    const container = scrollContainerRef.current;
    const activeEl = container.querySelector(
      `[data-opt-index="${focusedIndex}"]`
    ) as HTMLElement | null;

    if (!activeEl) return;

    const containerTop = container.scrollTop;
    const containerBottom = containerTop + container.clientHeight;
    const elemTop = activeEl.offsetTop;
    const elemBottom = elemTop + activeEl.offsetHeight;

    if (elemTop < containerTop) {
      container.scrollTop = elemTop;
    } else if (elemBottom > containerBottom) {
      container.scrollTop = elemBottom - container.clientHeight;
    }
  }, [focusedIndex]);
  ```

  import { sanitizeFontFamily } from '../components/settings/internal/fontPinyinMatcher';

  export function normalizeFontPrefs(raw: unknown): FontPreferences {

    base.monoFont = mono as MonoFontChoice;
    base.monoLigatures = Boolean(o.monoLigatures);
    base.v = 1;

## 三、审查结论与整改路线

本期字体选择器在双引擎扫描设计、分片调度理念、拼音首字母匹配以及 CSS 安全净化方向上搭建了极佳的基础架构。但在交互深水区暴露出了 **2 项致命级缺陷**（分组与评分脱节导致的错选、IME 输入法合成态按键被劫持）与 **5 项严重级缺陷**（Menu 焦点拉锯、Tab 漫游陷阱、超时定时器泄漏、rAF 后台挂起、Canvas 测宽缺失 CJK 字符）。

建议按以下优先级立即整改：
1. **P0（立即修复）**：修复 `useFontKeyboardNav.ts` 中的 IME 合成态全键盘放行逻辑；修复 `FontSelectField.tsx` 中的平铺渲染与索引映射脱节问题；
2. **P1（高优修复）**：移除 `Menu` 的自动焦点竞争；为所有 option 添加 `tabIndex={-1}`；清理 `scanViaQueryLocalFontsSafe` 中的 `setTimeout`；
3. **P2（核心优化）**：将 `yieldToMain` 从 `rAF` 迁移至 `scheduler.yield` / `MessageChannel`；为 `isFontInstalledMultiBase` 补齐 CJK 测试字符；
4. **P3（细节收敛）**：补全 `fontPinyinMap.ts` 常用字体字典；收敛复选框 `accent-color` 与 CSS Design Tokens。
