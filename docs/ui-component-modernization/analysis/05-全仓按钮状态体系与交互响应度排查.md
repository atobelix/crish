## 一、“按钮变肉”与交互响应迟钝四大深层根因解构

在近期的用户体验反馈中，“按钮变肉了”、“点按感觉粘滞”、“缺少点击确认感”成为核心槽点。通过对渲染管线、CSS 选择器、物理动效模型与 DOM 事件链路的深度剖析，定位出导致“肉感”的 **4 大深层根因**：

```
                                 ┌──────────────────────────────────────────────┐
                                 │     用户感知“按钮变肉了”的 4 大深层根因      │
                                 └──────────────────────┬───────────────────────┘
                                                        │
         ┌───────────────────────┬──────────────────────┴───────────────────────┬───────────────────────┐
         ▼                       ▼                                              ▼                       ▼
  【1. 物理形变缺失】     【2. 色阶差仅 3%】                            【3. 过渡曲线对称阻尼】  【4. Tooltip 重渲染阻断】
  Button :active 完全无    Secondary hover(3.5%)                          入场过渡 100ms 拖泥带水  pointerdown 同步触发
  scale / translateY 形变  vs active(6.5%) 仅差 3%                        未建立 0ms 瞬态按压     setVisible(false) 抢占
  点按如木板死肉          肉眼在数十毫秒内完全无感                        释放弹性非对称模型      关键点击帧导致掉帧卡顿
```

### 1. 根因一：机械触感与物理形变缺失（Lack of Micro-Spring Active Displacement）

- **现象表现**：用户鼠标按下按钮时，按钮在空间几何上“岲然不动”，没有任何下陷或微缩物理回馈。
- **源码对照**：
  - 在 [`SegmentedControl.module.css:L230-L233`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/SegmentedControl/SegmentedControl.module.css#L230-L233) 中，分段控制器拥有明确的物理压缩：
    ```css
    .item:active:not(:disabled) .itemInner {
      transform: scale(0.97) translateY(1px);
      transition: transform var(--tab-press-duration) ease-in-out;
    }
    ```
  - 但在原子基座 [`Button.module.css:L64-L67`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Button/Button.module.css#L64-L67) 中：
    ```css
    .button:active:not(:disabled)::before {
      background-color: var(--btn-active-overlay);
      opacity: 1;
    }
    ```
    `.button` 本身**完全没有** `transform: scale(...)` 或 `transform: translateY(...)`，也没有阴影向内压制收拢的位移。
  - **心理学与物理学解析**：人类神经系统对指尖点按的即时确认（Tactile Confirmation）极度依赖视觉的“微位移”。当按钮仅依靠微弱的色彩渐变而缺乏微观几何形变时，大脑会直觉判定为“系统响应迟缓或未命中”，形成极强的“肉感”。

### 2. 根因二：`:active` 视觉阶梯差仅 3%（Invisible State Transition & Alpha Clashing）

- **现象表现**：点击次级按钮（Secondary）、轻量按钮（Ghost）或平铺按钮（Plain）时，视觉上几乎看不到任何变化。
- **源码分析**（[`Button.module.css:L140-L149`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Button/Button.module.css#L140-L149) 与 [`tokens.css:L66-L67`](file:///c:/Software/conex/apps/crish-desktop/src/styles/tokens.css#L66-L67)）：
  ```css
  /* tokens.css */
  --tint-hover: color-mix(in srgb, var(--text-primary) 3.5%, transparent);
  --tint-active: color-mix(in srgb, var(--text-primary) 6.5%, transparent);

  /* Button.module.css */
  .buttonSecondary {
    --btn-bg: var(--bg-card, hsl(0 0% 100%));
    --btn-hover-overlay: var(--tint-hover);   /* 3.5% 黑色透明度 */
    --btn-active-overlay: var(--tint-active); /* 6.5% 黑色透明度 */
  }
  ```
- **数据推导**：在浅色纯白底板上，3.5% Alpha 的 `#111111` 混合后为 `#f6f6f6`，6.5% Alpha 为 `#eeeeee`。
  - 两者亮度差 $\Delta L^* < 2.5$，在用户快速点击的 $60\text{ms} \sim 100\text{ms}$ 内，人眼感光细胞根本无法捕捉到如此细微的灰阶跳变！
  - 此外，对于 `Primary` 按钮（[`Button.module.css:L134-L135`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Button/Button.module.css#L134-L135)），Hover 是 `15%` 白色微光，Active 是 `15%` 纯黑阴影。当鼠标从 Hover 按下进入 Active 时，由于 `::before` 仅对 `opacity` 做过渡，底色从亮白瞬间切到暗黑，产生脏色干涉或突兀跳变，失去纯净的物理质感。

### 3. 根因三：对称过渡阻尼阻碍瞬时入场（Symmetric Transition Damping）

- **现象表现**：按钮点击动作感觉“慢半拍”，仿佛拖着一层胶水。
- **源码剖析**（[`Button.module.css:L43-L58`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Button/Button.module.css#L43-L58)）：
  ```css
  .button {
    transition:
      border-color var(--transition-micro, 100ms) ease-out,
      box-shadow var(--transition-micro, 100ms) ease-out;
  }
  .button::before {
    transition: opacity var(--transition-micro, 100ms) ease-out;
  }
  ```
- **动力学失配分析**：
  - 物理世界的真实机械按键，手指下压的一瞬间（Press-In）加速度极大，形变与触点闭合发生在 $0\text{ms} \sim 30\text{ms}$（瞬态）；
  - 手指抬起松开时（Release-Out），由于弹簧回弹力与阻尼，才会产生 $100\text{ms} \sim 150\text{ms}$ 的平滑回弹。
  - 当前代码使用对称的 `100ms ease-out`。当用户在 $60\text{ms}$ 内完成快速点按时，CSS 过渡尚未进行到一半就被强制中断重置，导致按压动效被严重“吞帧”，留下迟缓发肉的拖尾感受。

### 4. 根因四：Tooltip 包装器与 React 渲染管线卡顿（Wrapper Re-render Blocking）

- **现象表现**：大量带有 Tooltip 的按钮在按下瞬间出现掉帧、微卡顿。
- **源码链路排查**（[`Tooltip.tsx:L294-L304`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Tooltip/Tooltip.tsx#L294-L304) 与 [`IconButton.tsx:L43-L45`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Button/IconButton.tsx#L43-L45)）：
  ```tsx
  // Tooltip.tsx
  const handlePointerDown = (e: React.PointerEvent<HTMLElement>) => {
    hideImmediate(); // 内部触发 setVisible(false) -> 导致组件树同步 Re-render！
    childHandlers.onPointerDown?.(e);
    restHandlers.onPointerDown?.(e);
  };

  const handleClick = (e: React.MouseEvent<HTMLElement>) => {
    hideImmediate(); // 再次触发 setVisible(false)！
    childHandlers.onClick?.(e);
    restHandlers.onClick?.(e);
  };
  ```
- **调用栈阻塞放大**：
  1. 用户在按钮上按下鼠标（`pointerdown`）：`Tooltip` 立即执行 `hideImmediate()`，触发 React `setVisible(false)` 状态更新；
  2. React 调度 `Tooltip` 子树重新渲染，连同内部的 `Button`、`icon`、`useAnimatedPresence` 状态机执行重算；
  3. `createPortal` 对应的浮层节点被标记销毁或执行退出动画；
  4. 浏览器主线程在最关键的 16ms 点按交互帧中，被 React 的 DOM 操作与垃圾回收抢占，导致 GPU 无法平滑渲染 CSS `:active` 伪类，产生物理掉帧与卡顿！

### 3. `IconButton` 专属特征与包装陷阱

审查 [`IconButton.tsx:L25-L49`](file:///c:/Software/conex/apps/crish-desktop/src/components/ui/Button/IconButton.tsx#L25-L49)：
- **特性**：强制要求 `aria-label` 无障碍标签；自动将宽度设为 `--btn-h` 实现完美 $1:1$ 正方形。
- **现存陷阱**：
  1. **Tooltip 嵌套灾难**：`IconButton` 自带 `tooltip?: React.ReactNode` 属性，但大量业务调用方（如 `SubagentHeaderPanel.tsx:L125-L136`）习惯性在外层又包裹了一层 `<Tooltip>`，造成 **双层 Tooltip 挂载**，产生双重 DOM Portal、双重全局单槽争抢与多余的事件转发；
  2. **Ghost 态点击手感软弱**：大部分 `IconButton` 默认使用 `variant="ghost"`，在小面积（$24\text{px} \times 24\text{px}$ 或 $28\text{px} \times 28\text{px}$）下，没有实体背景与按下物理反馈，用户频繁误以为“没点中图标”。

- **微观交互排查与优化空间**：
  - **长按（PointerDown 未释放）状态**：当前 Switch 的果冻拉伸完全绑定在 `animation: thumb-stretch-on` 上（由 `click` 后的 class 切换驱动）。如果用户按住鼠标左键不放（`:active`），滑块本体没有即时的按压形变（例如横向轻微膨胀），直到松开鼠标触发 `onClick` 后才开始播放关键帧动画。如果能在 `:active` 态加入瞬时微拉伸，触感将进一步达到 iOS 原生级体验。

## 五、现代化全仓按钮状态与非对称物理动效改造方案

为了彻底解决全仓按钮“变肉、迟钝、发灰、无反馈”的问题，制定以下 **四大核心技术改造方案**：

```
                               ┌──────────────────────────────────────────────────────────┐
                               │       全仓按钮现代化状态体系与非对称动效方案             │
                               └────────────────────────────┬─────────────────────────────┘
                                                            │
         ┌───────────────────────┬──────────────────────────┴──────────────────────────┬───────────────────────┐
         ▼                       ▼                                                     ▼                       ▼
  【1. 非对称微弹物理动效】 【2. 色彩对比度矩阵重构】                             【3. Tooltip 异步卸载】 【4. 统一键帽与徽标】
  按压 30ms 瞬态 0.975x    Secondary hover 4% vs active 10%                      pointerdown 仅标记视觉   Keycap 补齐 1px 浮起底脊
  释放 140ms 弹性回弹      Primary active 叠加 brand-deep 压制                   延迟至宏任务静默清理     统一 diagLevel 与 monoBadge
```

### 1. 方案一：非对称微弹物理动效模型（Asymmetric Micro-Spring Press Model）

在 `Button.module.css` 中引入非对称动力学模型：**按压入场 30ms 瞬态响应，释放离场 140ms 柔和回弹**。

```css
/* apps/crish-desktop/src/components/ui/Button/Button.module.css */

/* 1. 默认静止态与释放回弹（Release-Out：140ms 平滑微弹） */
.button {
  position: relative;
  display: inline-flex;
  align-items: center;
  justify-content: center;
  box-sizing: border-box;
  /* 基础变换原点居中 */
  transform: scale(1) translateY(0);
  transform-origin: center center;
  will-change: transform, box-shadow;

  /* 释放恢复：140ms 柔和物理贝塞尔曲线 */
  transition:
    transform 140ms cubic-bezier(0.2, 0, 0, 1),
    box-shadow 140ms cubic-bezier(0.2, 0, 0, 1),
    border-color var(--transition-micro, 100ms) ease-out;
}

/* 2. 按压瞬态反馈（Press-In：30ms 极速下陷与低空收拢） */
.button:active:not(:disabled) {
  /* 机械按压微缩 0.975x + 垂直微沉 0.5px */
  transform: scale(0.975) translateY(0.5px);
  /* 阴影瞬间收贴至地表 */
  box-shadow: 0 0 1px color-mix(in srgb, var(--shadow-color, hsl(0 0% 0%)) 6%, transparent);
  /* 瞬态响应：极速 30ms 响应用户指尖，彻底消灭“肉感” */
  transition:
    transform 30ms cubic-bezier(0, 0, 0.2, 1),
    box-shadow 30ms cubic-bezier(0, 0, 0.2, 1);
}

/* 3. 物理微光交互层 (Opacity Transition) */
.button::before {
  content: '';
  position: absolute;
  inset: 0;
  border-radius: inherit;
  background-color: var(--btn-hover-overlay);
  opacity: 0;
  pointer-events: none;
  transition:
    opacity 80ms ease-out,
    background-color 80ms ease-out;
}

.button:hover:not(:disabled)::before {
  opacity: 1;
}

.button:active:not(:disabled)::before {
  background-color: var(--btn-active-overlay);
  opacity: 1;
}
```

### 3. 方案三：Tooltip 卸载与渲染帧保护优化

优化 `Tooltip.tsx` 中的事件分发，避免在 `pointerdown` 瞬间同步阻塞渲染管线：

```tsx
// 改造方案概念：Tooltip 退出解耦
const handlePointerDown = (e: React.PointerEvent<HTMLElement>) => {
  // 仅在视觉上先隐藏（不立即触发复杂的 React 状态重置与 Portal 销毁），保护首帧渲染
  if (tipRef.current) {
    tipRef.current.style.opacity = '0';
    tipRef.current.style.pointerEvents = 'none';
  }
  // 将真实的状态清理排入下一个微任务/宏任务，不与当前帧的 :active 动画争抢主线程
  requestAnimationFrame(() => {
    hideImmediate();
  });
  childHandlers.onPointerDown?.(e);
  restHandlers.onPointerDown?.(e);
};
```

同时，规范 `IconButton` 业务调用，禁止出现 `<Tooltip><IconButton tooltip="..." /></Tooltip>` 双重嵌套。
