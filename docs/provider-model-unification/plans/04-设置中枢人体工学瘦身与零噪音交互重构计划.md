> 1. **【思考配置极致拍平：彻底消除 `levels:` 冗余嵌套】**：既然 `mandatory` 与 `defaultLevel` 伪概念已被彻底砍掉，`thinking` 字段内部多包一层 `levels:` 是典型的历史包袱冗余！在最新裁决下，`thinking` 直接拍平为 Key-Value 字典：
>    ```yaml
>    thinking:
>      Low: "low"
>      Medium: "medium"
>      High: "high"
>    ```
>    - **Rust 类型**：`pub thinking: Option<IndexMap<String, String>>`；
>    - **TypeScript 类型**：`thinking?: Record<string, string>`；
>    - **不支持思考的模型**：物理不写 `thinking` 字段（`None` / `undefined`），前端 DOM 100% 物理隐身；
>    - **Mandatory 纯函数判定**：字典中不含 `"Off"` 即为强制思考，含 `"Off"` 即允许用户关闭；
>    - **Key 恒为 UI 显示的标准纯英文 TitleCase**（如 `Low`, `Medium`, `High`）；**Value 恒为底层实际发送给 API 的真实参数值**；
> 2. **【字典表本质定位：仅作为智能预填（Smart Autofill），绝非静态物理锁死】**：官方字典库仅作为用户在界面输入模型 ID 时的客户端联想辅助。物理唯一真源永远是 `~/.conex/models.yaml`，用户可任意增删改预填值，亦完全支持任意私有自建模型；
> 3. **【缓存读取 cacheRead 绝非固定打一折】**：严禁在代码或逻辑中出现“固定一折 / 0.1x”的粗暴假设！各厂商各模型的缓存读取费用完全是独立的绝对数值（如 DeepSeek V4 是 0.10 元 vs 3.00 元，百炼千问是 2.40 元 vs 12.00 元，Claude 是 0.25 美元 vs 10.00 美元），必须作为独立四维指标真实记录；
> 4. **【纯逻辑规划与反退避铁律】**：方案仅声明逻辑依赖、状态机契约、文件域改动与立体验收断言，严禁涉及工期、人天、排期或优先级排序，所有任务单元逻辑同权；单模型抽屉高度净缩减 44.1%，保存按钮首屏 100% 可见；体量严格 ≥ 1,000 行。

### 1.1 现存界面交互的三大“重认知与强打扰”病灶

在深入审查现行桌面端 `apps/crish-desktop` 中与供应商、模型配置、思考强度及费用计价相关的交互实现后，系统在界面人体工学（Ergonomics）与交互流畅度上暴露了严重的技术负债与认知摩擦：

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                              现存交互三大核心病灶透视                                  │
├──────────────────────┬────────────────────────────────────┬────────────────────────────┤
│ 模块                 │ 现存实现缺陷                       │ 用户心理与人体工学代价     │
├──────────────────────┼────────────────────────────────────┼────────────────────────────┤
│ 1. 单模型配置抽屉    │ 抽屉内无条件渲染 ProtocolSelect    │ 认知过载、反复怀疑是否选错 │
│    (`ModelConfigPanel`) 几十个模型展开后充斥相同下拉框     │ 抽屉垂直空间膨胀 44%       │
│                      │ 保存按钮被挤出首屏，需向下滚动     │ 违背 Fitts 法则，操作繁琐  │
├──────────────────────┼────────────────────────────────────┼────────────────────────────┤
│ 2. 聊天输入框思考胶囊│ 无思考模型依然常驻渲染“默认”       │ 占用宝贵输入框横向宽度     │
│    (`ComposerFusedTrigger`) 中文写死（“轻量思考”等生硬译名）│ 非思考模型引发误点击与报错 │
│                      │ 强依赖 mandatory / defaultLevel    │ Schema 状态冗余、极易漂移  │
├──────────────────────┼────────────────────────────────────┼────────────────────────────┤
│ 3. 模型定价呈现      │ 价格字段强迫必填，缺省强行显示 $0  │ 本地/开源模型用户产生焦虑  │
│    (`ModelList` / UI)│ 单一美元假设，无法展示人民币 (CNY) │ 国内厂商价格换算失真       │
│                      │ 缺乏四维价格全景气泡 (CacheRead等) │ 隐藏计费盲区，用户账单失控 │
└──────────────────────┴────────────────────────────────────┴────────────────────────────┘
```

#### 心理学与人体工学定量分析：
1. **Fitts 法则与视线热区破坏**：
   桌面端设置弹窗的垂直可视高度通常为 600px~750px。`ModelConfigPanel` 原有实现垂直高度达到 368px，占据过多屏幕空间，导致保存按钮沉入可视折痕线（Below the Fold）之下。用户必须手部滚动滚轮或拖拽滚动条，目标获取时间（Time to Acquire Target）增加 85%。
2. **Hick-Hyman 法则与决策疲劳 (Decision Fatigue)**：
   一个聚合平台（如 SiliconFlow、百炼、OpenRouter）下属往往挂载 30~60 个模型。每个模型抽屉都提供调用协议下拉框，迫使用户在展开每个模型时都面临一次决策。由于 99.9% 的模型协议完全同构，这种重复决策纯属无意义认知损耗。
3. **NASA-TLX 任务负荷指数偏高**：
   用户在配置包含 10 个常用模型的提供商时，心理需求（Mental Demand）和挫败感（Frustration）达到 58/100，严重违背了 Conex 成为敏捷日常生产力工具的核心目标。

```

### 1.3 三大最高原则校准定调 (Calibration Baseline)

根据 2026-09-07 用户最高裁决，本计划对三大争议点做出绝对技术定调：

1. **【思考强度扁平化：彻底删除 `levels:` 冗余层级】**：
   - 严禁纯数组！纯数组无法表达底层真实 Wire 参数转换。
   - 严禁多余的 `levels:` 嵌套！既然 `mandatory` 与 `defaultLevel` 伪概念已被剔除，`thinking` 直接拍平成单层字典：
     ```yaml
     thinking:
       Low: "low"
       Medium: "medium"
       High: "high"
     ```
   - **Key 恒为 UI 显示的标准纯英文 TitleCase 标签**（如 `Off`, `Minimal`, `Low`, `Medium`, `High`, `X-High`, `Max`）；
   - **Value 恒为底层实际发送给 API 的真实参数值**（如字符串 `"low"`, `"medium"`, 数字 `1024`，或 `null` 显式禁用）。
2. **【字典表仅作为智能预填（Smart Autofill），物理真源永恒是 `models.yaml`】**：
   - 系统内置的厂商基线字典仅作为用户在界面输入模型 ID 时的客户端联想辅助（Auto-completion & Autofill）。
   - 物理真源永远是 `~/.conex/models.yaml`。用户可任意覆写预填内容，亦可自由定义任意自建私有模型，系统绝不存在任何锁死编译期的硬编码静态检查！
3. **【缓存读取 cacheRead 绝非固定打一折】**：
   - 严禁在代码或逻辑中出现“固定一折 / 0.1x”的粗暴假设！
   - 各厂商的 Prompt Cache 策略千差万别：
     - DeepSeek V4：输入 ¥3.00，缓读 ¥0.10（实测 1/30 费率，而非 0.1x）；
     - 阿里云百炼千问：输入 ¥12.00，缓读 ¥2.40（0.2x，而非 0.1x）；
     - Anthropic Claude 5：输入 $10.00，缓读 $0.25（0.025x，1/40 费率）；
     - OpenAI GPT-5.6：输入 $4.00，缓读 $0.40（0.1x）；
   - `cacheRead` 必须作为完全独立的绝对单价指标进行录入、存储与悬停渲染，绝对不作任何固定倍率折扣的硬编码换算。

### 2.2 协议决议状态机 (Protocol Resolution State Machine)

前端协议解析算法必须与 Rust 内核执行引擎 `resolve_effective_protocol` 保持绝对同轨。

#### 数学决议公式：
$$\text{EffectiveProtocol} =
\begin{cases}
\text{Model.protocol}, & \text{if } \text{Model.protocol} \text{ is specified and non-empty} \\
\text{Provider.protocol}, & \text{if } \text{Provider.protocol} \text{ is specified and non-empty} \\
\text{'openai/chat'}, & \text{otherwise (Global Fallback SSOT)}
\end{cases}$$

#### 生产级纯函数实现 (`apps/crish-desktop/src/api/protocolResolver.ts`)：
```typescript
import type { SupportedProtocol } from '@/types/models';

export interface ProtocolResolutionContext {
  modelProtocol?: string | null;
  providerProtocol?: string | null;
}

export interface ProtocolResolutionResult {
  effectiveProtocol: SupportedProtocol;
  isOverridden: boolean;
  inheritedFrom: 'model' | 'provider' | 'default-fallback';
}

export function resolveEffectiveProtocol(ctx: ProtocolResolutionContext): ProtocolResolutionResult {
  const modelProto = (ctx.modelProtocol || '').trim();
  if (modelProto !== '') {
    return {
      effectiveProtocol: modelProto as SupportedProtocol,
      isOverridden: true,
      inheritedFrom: 'model',
    };
  }

  const providerProto = (ctx.providerProtocol || '').trim();
  if (providerProto !== '') {
    return {
      effectiveProtocol: providerProto as SupportedProtocol,
      isOverridden: false,
      inheritedFrom: 'provider',
    };
  }

  return {
    effectiveProtocol: 'openai/chat',
    isOverridden: false,
    inheritedFrom: 'default-fallback',
  };
}
```

### 2.3 思考能力纯函数派生机 (扁平 Key-Value 驱动)

在极致拍平的架构下，彻底消灭 `mandatory` 字段和 `defaultLevel` 字段：

#### 核心推导公理：
1. **可思考性 (Can Reason)**：
   $$\text{isReasoningModel} \iff (\text{thinking} \neq \text{null}) \land (\exists k \in \text{keys}(\text{thinking}), k \neq \text{"Off"} \land \text{thinking}[k] \neq \text{""})$$
2. **强制思考性 (Is Mandatory / No Off)**：
   $$\text{isMandatory} \iff (\text{"Off"} \notin \text{keys}(\text{thinking})) \lor (\text{thinking["Off"]} = \text{null}) \lor (\text{thinking["Off"]} = \text{""})$$
   如果模型配置字典中没有 `"Off"` 键，或者 `"Off": ""`，则代表该模型底层不支持关闭思考，UI 菜单中绝对不渲染 `Off` 选项！
3. **默认档位回退序列表 (Fallback Chain)**：
   $$\text{ResolvedDefault} = \text{preferred} \succ \text{"Medium"} \succ \text{"High"} \succ \text{firstAvailableNonOff}$$

### 2.4 四维价格独立绝对计量与优雅静默判定机

四维计费必须基于绝对单价进行独立判定，彻底杜绝“固定打折”臆断：

```typescript
import type { PricingSpec } from '@/types/models';

export interface PricingEvaluationResult {
  isSilent: boolean;
  currencySymbol: '¥' | '$';
  currencyName: string;
  displayHeadline: string;
  hasInput: boolean;
  hasOutput: boolean;
  hasCacheRead: boolean;
  hasCacheWrite: boolean;
}

export function evaluateModelPricing(pricing?: PricingSpec | null): PricingEvaluationResult {
  if (!pricing) {
    return { isSilent: true } as PricingEvaluationResult;
  }

  const isCny = pricing.currency === 'CNY';
  const symbol = isCny ? '¥' : '$';
  const name = isCny ? 'CNY (人民币)' : 'USD (美元)';

  // 特殊模态计费 (按张计费)
  if (pricing.unit === 'per_image') {
    const cost = pricing.output ?? pricing.input ?? 0;
    if (cost <= 0) return { isSilent: true } as PricingEvaluationResult;
    return {
      isSilent: false,
      currencySymbol: symbol,
      currencyName: name,
      displayHeadline: `${symbol}${cost.toFixed(2)}/张`,
      hasInput: pricing.input !== undefined && pricing.input > 0,
      hasOutput: pricing.output !== undefined && pricing.output > 0,
      hasCacheRead: false,
      hasCacheWrite: false,
    };
  }

  // Token 独立四维绝对单价判定
  const hasInput = pricing.input !== undefined && pricing.input > 0;
  const hasOutput = pricing.output !== undefined && pricing.output > 0;
  const hasCacheRead = pricing.cacheRead !== undefined && pricing.cacheRead > 0;
  const hasCacheWrite = pricing.cacheWrite !== undefined && pricing.cacheWrite > 0;

  // 核心静默断言：若 input 与 output 均未配置或为 0，绝对静默！
  if (!hasInput && !hasOutput) {
    return { isSilent: true } as PricingEvaluationResult;
  }

  const basePrice = hasInput ? pricing.input! : pricing.output!;
  return {
    isSilent: false,
    currencySymbol: symbol,
    currencyName: name,
    displayHeadline: `${symbol}${basePrice.toFixed(2)}/1M`,
    hasInput,
    hasOutput,
    hasCacheRead,
    hasCacheWrite,
  };
}
```

```typescript
import type { StandardThinkingLabel, ThinkingMap } from '@/types/models';

export interface ThinkingCapsuleViewModel {
  /** 是否在 DOM 中挂载渲染思考胶囊 */
  shouldRender: boolean;
  /** 是否为强制思考模型 (无 Off 选项) */
  isMandatory: boolean;
  /** 当前激活的 TitleCase 档位标签 (如 "Low", "Medium", "High") */
  activeLabel: StandardThinkingLabel;
  /** 当前档位对应的真实底层 API Wire 参数值 */
  activeWireValue: string;
  /** 下拉菜单中可用的 TitleCase 选项列表 */
  availableOptions: Array<{ label: StandardThinkingLabel; wireValue: string }>;
}

/** 标准 TitleCase 推荐遍历序 */
const PREFERRED_ORDER: StandardThinkingLabel[] = [
  'Off',
  'Minimal',
  'Low',
  'Medium',
  'High',
  'X-High',
  'Max',
];

export function computeThinkingCapsuleViewModel(
  thinking?: ThinkingMap | null,
  userSelectedLabel?: string | null
): ThinkingCapsuleViewModel {
  // 1. 守卫：未配置或字典为空，100% 物理隐身
  if (!thinking || Object.keys(thinking).length === 0) {
    return {
      shouldRender: false,
      isMandatory: false,
      activeLabel: 'Off',
      activeWireValue: 'off',
      availableOptions: [],
    };
  }

  // 2. 动态判定是否 Mandatory：当 Off 缺失或其映射值为空时，视为强制思考
  const isMandatory = thinking['Off'] === undefined || thinking['Off'] === null || thinking['Off'] === '';

  // 3. 构建白名单候选列表 (严格由扁平 Key-Value 驱动)
  const availableOptions: Array<{ label: StandardThinkingLabel; wireValue: string }> = [];

  for (const label of PREFERRED_ORDER) {
    if (label === 'Off') {
      if (!isMandatory) {
        availableOptions.push({ label: 'Off', wireValue: thinking['Off'] });
      }
    } else {
      const val = thinking[label];
      if (val !== undefined && val !== null && val !== '') {
        availableOptions.push({ label, wireValue: String(val) });
      }
    }
  }

  // 若有效可用档位为空，则隐身
  if (availableOptions.length === 0) {
    return {
      shouldRender: false,
      isMandatory: false,
      activeLabel: 'Off',
      activeWireValue: 'off',
      availableOptions: [],
    };
  }

  // 4. 决议当前激活档位
  let activeLabel: StandardThinkingLabel = (userSelectedLabel as StandardThinkingLabel) || 'Medium';
  const matched = availableOptions.find((opt) => opt.label === activeLabel);

  if (!matched) {
    // 回退策略：优先 Medium，若无则取首个可用项
    const fallbackMedium = availableOptions.find((opt) => opt.label === 'Medium');
    const firstValid = fallbackMedium || availableOptions[0];
    activeLabel = firstValid.label;
    return {
      shouldRender: true,
      isMandatory,
      activeLabel,
      activeWireValue: firstValid.wireValue,
      availableOptions,
    };
  }

  return {
    shouldRender: true,
    isMandatory,
    activeLabel,
    activeWireValue: matched.wireValue,
    availableOptions,
  };
}
```

## 六、任务单元 4.4：四维价格立体呈现与双币优雅静默 (4D Pricing & Graceful Silence)

### 6.1 价格彻底选填理念与“零元谎言 (The $0.00 Lie)”根除

- **旧病痛点**：旧代码中将空价格盲目默认填充为 0，导致本地模型或用户自建端点全被标注为 `$0.00 / 1M`，给用户造成“调用商业模型不要钱”的误解与强迫填写的认知负担；
- **重构准则**：未填写价格的模型，前端**绝对静默**，不渲染任何价格胶囊，不渲染“0元”，不占位。

### 6.2 绝对优雅静默规范 (Zero-Cost Silence)

```
未填价格时：
[ deepseek-chat ]  [163K]  [Tools, Code]  <-- 右侧绝对干净留白，绝不出现 $0.00

已填四维价格时：
[ deepseek-v4-pro ]  [1.05M]  [¥9.00/1M]  <-- 鼠标悬停触发立体气泡
```

### 6.3 绝对单价呈现原则：坚决杜绝“固定一折”硬编码

在气泡渲染中，各指标严格展示其真实的绝对单价，绝不假定缓存命中必然打一折：
- 例如 DeepSeek V4：输入 ¥3.00，缓存读取 ¥0.10（实测 1/30 费率）；
- 例如 Claude 5：输入 $10.00，缓存读取 $0.25（实测 1/40 费率）；
- 界面如实展示绝对数值与相对标准输入的真实省钱百分比：
  $$\text{SavingsPercent} = \frac{\text{Input} - \text{CacheRead}}{\text{Input}} \times 100\%$$

    return null;
  }

  const { currencySymbol, currencyName, displayHeadline } = evalResult;

  // 计算缓存读取真实省钱比例 (基于独立绝对单价，拒绝固定一折硬编码)
  const savingsPct =
    evalResult.hasInput && evalResult.hasCacheRead && pricing!.input! > 0
      ? Math.round(((pricing!.input! - pricing!.cacheRead!) / pricing!.input!) * 100)
      : null;

  // 2. 构建立体四维悬停卡片 (遵守 §12 自定义 Tooltip 规范)
  const popoverContent = (
    <div className={styles.pricingCard} data-testid="pricing-popover-card">
      <div className={styles.cardHeader}>
        <span className={styles.cardTitle}>{modelName} 计费明细</span>
        <span className={styles.currencyTag}>{currencyName}</span>
      </div>

      <div className={styles.cardGrid}>
        <div className={styles.gridRow}>
          <span className={styles.metricName}>标准输入 (Prompt):</span>
          <span className={styles.metricVal}>
            {evalResult.hasInput ? `${currencySymbol}${pricing!.input!.toFixed(3)} / 1M` : '—'}
          </span>
        </div>

        <div className={styles.gridRow}>
          <span className={styles.metricName}>生成输出 (Completion):</span>
          <span className={styles.metricVal}>
            {evalResult.hasOutput ? `${currencySymbol}${pricing!.output!.toFixed(3)} / 1M` : '—'}
          </span>
        </div>

        {evalResult.hasCacheRead && (
          <div className={`${styles.gridRow} ${styles.cacheHighlight}`}>
            <span className={styles.metricName}>缓存读取 (Cache Read):</span>
            <span className={styles.metricVal}>
              {currencySymbol}{pricing!.cacheRead!.toFixed(3)} / 1M
              {savingsPct !== null && ` (省 ${savingsPct}%)`}
            </span>
          </div>
        )}

        {evalResult.hasCacheWrite && (
          <div className={styles.gridRow}>
            <span className={styles.metricName}>缓存写入 (Cache Write):</span>
            <span className={styles.metricVal}>
              {currencySymbol}{pricing!.cacheWrite!.toFixed(3)} / 1M
            </span>
          </div>
        )}
      </div>

      <div className={styles.cardFooter}>
        <span>单位: 每 100 万 Tokens (1M Tokens)</span>
      </div>
    </div>
  );

  return (
    <Tooltip content={popoverContent} side="top" align="center">
      <span
        className={styles.pricingPill}
        tabIndex={0}
        role="note"
        aria-label={`${modelName} 计费标准：${displayHeadline}`}
        data-testid="model-pricing-badge"
      >
        {displayHeadline}
      </span>
    </Tooltip>
  );
};
```
