## 二、目标真源：Provider-Centric 树状 Schema 设计

物理文件：`~/.conex/models.yaml`（跨系统唯一 SSOT）：

```yaml
# ==============================================================================

  # DeepSeek 官方
  # ----------------------------------------------------------------------------
  deepseek:
    displayName: "DeepSeek"
    baseUrl: "https://api.deepseek.com"
    protocol: "openai/chat"                # 供应商总协议（默认全部模型继承）
    compat:
      thinkingFormat: "deepseek"           # 深度求索原生思考方言 (thinking: { type })
      supportsDeveloperRole: false         # deepseek 使用 system 角色而非 developer
      maxTokensField: "max_tokens"
    models:
      - id: "deepseek-v4-flash"
        displayName: "DeepSeek V4 Flash"
        contextWindow: 1048576
        maxOutputTokens: 384000
        thinking:
          enabled: true
          mandatory: true                  # 强制思考：UI 彻底隐藏 Off 选项
          defaultLevel: "medium"
          levels:                          # 严格纯英文白名单三态映射
            minimal: "minimal"
            low: "low"
            medium: "medium"
            high: "high"
            xhigh: "xhigh"
            max: "max"
        pricing:                           # 价格完全选填
          currency: "USD"                  # 支持 USD / CNY
          unit: "per_1m_tokens"            # per_1m_tokens 或 per_image
          input: 0.44
          output: 1.32
          cacheRead: 0.014

      - id: "deepseek-chat"
        displayName: "DeepSeek V3"
        contextWindow: 65536
        maxOutputTokens: 8192
        thinking:
          enabled: false                   # 非思考模型：UI 彻底折叠隐藏思考胶囊

  # 阿里云百炼 (国内站双币与 CNY 人民币计价)

  qwen:

            low: "low"
            medium: "medium"
```

## 三、五大宏观分析议题（全景攻坚域）

为了做到真正全面、深邃且覆盖系统各层，我们将攻坚领域聚合成 **五大宏观分析议题**：

### 【议题 A】Provider 拓扑结构、凭据生命周期与动态发现体系
1. **树状层级建模**：`ProviderSpec`（顶层）➔ `ModelSpec`（子层）的双层强类型 Schema，彻底取代扁平拍平结构；
2. **凭据安全与 DPAPI 统一桥接**：保持 OS 级凭据槽隔离（`config_secret_set`），消除前端明文 key 散落，解决自定义服务商与官方模板的认证归一；
3. **模型探测（Probe）与自愈合流**：`probe_scan_models_core` 探测返回的模型列表与 `models.yaml` 智能合并，建立“新发现则追加、已配置则保留”的不变性保证；
4. **多网络通道与自定义 Headers**：支持自定义 Proxy、请求头注入（如 `HTTP-Referer`、`X-Title` 等），适配 OpenRouter / Vercel AI Gateway。

### 【议题 B】AI 协议路由、请求方言与内核执行链条全线打通
1. **根除编译期静态单例**：彻底废除 `bundled_catalog()` 与硬编码 `catalog.json`，构建由 `models.yaml` 驱动的运行时 `ModelCatalog`；
2. **多层协议决议状态机**：
   $$\text{EffectiveProtocol} = \text{Model.protocol} \succ \text{Provider.protocol} \succ \text{'openai/chat'}$$
   URL 端点、Payload 序列化器与 SSE 流解析器严格“三件套同轨”；
3. **11 类方言矩阵精细适配**：涵盖 `developer` vs `system` 角色转换、`max_completion_tokens` 字段适配、Tool choice 模式（Strict JSON Schema vs Function）、Prompt Cache 标记（`cache_control` vs `prompt_cache_key`）；
4. **内核零等待热重载（RCU/RwLock）**：用户保存 `models.yaml` 后，Rust 内存指针原子 CAS 替换，正在进行的会话零中断，新会话即刻走新配置。

### 【议题 C】思考推理（Thinking/Reasoning）全协议方言与 UI 深度自适应
1. **纯英文 7 档严格标准化**：全系统消除生硬中文，统一呈现 `Default`, `Off`, `Minimal`, `Low`, `Medium`, `High`, `X-High`, `Max`；
2. **三态 `levels` 映射机制**：
   - 存在且为 string ➔ 允许选择并指定 wire 字符串；
   - 缺省或为 null ➔ 模型不支持该档，UI 彻底不渲染；
   - `"off": null` ➔ 标记为强制思考（Mandatory），UI 物理隐藏 Off 选项；
3. **UI 零浪费视觉自适应**：
   - 非思考模型（`enabled: false`）：物理折叠隐藏输入框思考胶囊，空间 100% 让渡给模型名称；
   - 动态选项计算：根据当前活动模型的 `levels` 实时生成菜单项，保存 YAML 后毫秒级动态重绘；
4. **Token 预算动态钳制（Token Clamp）**：针对 Anthropic / Gemini 等预算制思考模型，实现思考预算与输出 Token 动态协调，保障不超过上下文上限。

### 【议题 D】多模态能力、上下文截断与双币计量结算体系
1. **模态矩阵建模**：精确声明输入模态（text, image, video, audio, pdf）与输出模态，驱动前端上传组件可用性与多模态 Payload 组装；
2. **上下文窗口与子代理预算**：`contextWindow` 与 `maxOutputTokens` 真实接入上下文截断算法与子代理 Prompt 预算裁剪，消灭硬编码 `KNOWN_CONTEXT`；
3. **双币体系 (CNY/USD) 与清晰单位**：
   - 货币自由切换：人民币 `CNY (¥)` 与 美元 `USD ($)`，国际站与国内站独立定价；
   - 计量单位明确：`¥/1M Tokens`、`$/1M Tokens`、`按张计费`；
4. **价格彻底选填交互**：未配置价格时系统静默跳过费用统计，设置页面杜绝“强制填价格”或“0元提示”的视觉干扰。

### 【议题 E】前端状态中枢重构、界面人体工学瘦身与全量立体验证
1. **服务商设置页布局升级**：
   - 在 Base URL 与 API Key 凭证区下方、**模型列表的正上方**，置顶“调用协议 (Protocol)”选择器；
   - **单模型抽屉全面瘦身**：展开具体模型配置面板（`ModelConfigPanel`）**彻底移除协议下拉选项**，保持几十个模型列表干净清爽，底层保留隐式覆盖；
2. **前端 Store 树状单轨重写**：`modelsCatalogStore.ts` 重写为订阅 Provider 树状结构，淘汰历史兼容层与冗余缓存；
3. **展示名与元数据优先回退链**：`formatModelDisplayName` 与 `getModelMeta` 全面优先读取 YAML 镜像中的 `displayName` 与上下文限制；
4. **全链路立体门禁**：覆盖 YAML 往返序列化单测、协议路由一致性断言、UI 动态档位渲染测试与真机无未捕获异常验证。

## 四、多 Agent 双重交叉分析矩阵 (Double-Agent Cross Analysis Matrix)
