### 1.2 现状审查：旧双价模型在现代 Agent 架构下的全面溃败

在传统的单轮短文本对话时代（如 GPT-3.5 时代，对话往往在 2K~4K tokens 内完成），`TotalCost = (input_tokens * input_rate + output_tokens * output_rate) / 10^6` 尚能勉强工作。

然而，在以 Conex / Crish 为代表的**现代多轮智能体（Coding Agent）**交互中：
- 每次 Agent 调用均需要携带完整的系统提示词（System Prompt，通常包含 20+ 个工具定义、代码格式规范、环境上下文字符串，往往多达 8K ~ 32K tokens）；
- 每次工具调用（Tool Call）及其返回结果（Tool Result）都会作为新的上下文追加至对话历史中；
- 到了第 10 轮交互，总输入上下文往往突破 100K ~ 200K tokens；
- **现代大模型（DeepSeek V3/V4, Claude 3.5/4.5/5, GPT-5.6, Qwen3.8 等）均具备高效的 KV 缓存机制**。在第 10 轮调用中，95% 以上的输入 token 实际上是此前已处理过的历史上下文，在上游仅按 **Cache Read（读取命中单价）** 甚至 **0.1折~1折** 计费。

#### 崩溃事实：
如果 Conex 继续使用旧双价模型：
1. **费用虚高 5~10 倍**：系统计算出的账单显示本轮对话消耗了 \$0.80（按全量 input 算），而开发者在 API 账单中心实际只被扣除了 \$0.09。用户会误认为本软件极度昂贵，从而不敢在大型代码仓库中开启深度分析；
2. **长文本惩罚恐惧**：用户为了“省钱”，会不敢向上下文塞入大型代码文件，这与现代 Agent 强调上下文感知和反退避的初衷彻底背道而驰；
3. **阶梯计费失效**：针对 OpenAI GPT-5.6 或 Qwen3.7-plus 等在超过 256K 或特定阈值时调整费率的模型，旧模型无法表达阶梯门槛（`inputTokensAbove`），导致计算结果与真实开销脱轨。

### 2.2 DeepSeek 原生缓存经济学（Hit ¥0.5/M vs Miss ¥2.0/M 及 V4 极速版实测）

DeepSeek 是全球推行“全自动无感 Prompt Caching”最彻底的厂商。其底层利用了自研的 DualPipe 与前缀树存储架构。

#### 1. 真实价格对照
- **DeepSeek V3 稳定版（官方刊例）**：
  - **未命中缓存（Cache Miss / 普通输入）**：`¥2.00 / 1M tokens`（国际站 `$0.27 / 1M`）；

## 三、四价模型（Four-Dimensional Pricing）必要性与数学证明

### 3.1 现代 Coding Agent 真实长交互模式建模

在 Conex 的真实交互链条中，一个典型的全自动代码重构任务由多个轮次（Turn）组成：
- **基准上下文 $S$**：系统提示词、工作区目录树、核心规范（如 `AGENTS.md`），固定约为 $16,000$ tokens；
- **每轮工具调用及输出增量 $\Delta_i$**：包括文件读取（`view_file`）、AST 解析输出、测试执行日志，平均每轮新增 $12,000$ tokens；
- **模型输出 $O_i$**：思考过程与工具调用参数或回答文本，平均每轮 $2,500$ tokens；
- **轮次总数 $N$**：设定为典型的 $10$ 轮交互。

在第 $k$ 轮交互时，发向上游 API 的总输入 Token 数量为：
$$T_k = S + \sum_{i=1}^{k-1} (\Delta_i + O_i)$$

由于前 $k-1$ 轮的全部内容在前缀树中保持不变，因此：
- **缓存命中读取量（Cache Read）**：$C_k^{\text{read}} = T_k - \Delta_k^{\text{new}} \approx T_{k-1}$
- **未命中新输入量（Uncached Input）**：$C_k^{\text{input}} = T_k - C_k^{\text{read}} \approx \Delta_k$

### 3.3 四大核心价格维度的本质与独立核算价值

由上述推演可见，四维价格体系具备坚不可摧的数学与经济学逻辑：
1. **`input`（未命中普通输入单价）**：衡量模型对全新上下文的初次理解与注意力计算成本；
2. **`output`（生成补全单价）**：衡量模型自回归解码（Autoregressive Decoding）与长链推理思考的 GPU 算力成本，通常为输入单价的 3~5 倍；
3. **`cacheRead`（KV 缓存命中读取单价）**：仅需从内存或高速显存中读取既有 KV Cache 矩阵，无需重算注意力，成本降幅达 75%~97.5%；
4. **`cacheWrite`（KV 缓存创建写入单价）**：衡量构建 KV Cache 状态并持久化保留至分布式缓存集群的附加开销（Anthropic 为 1.25x，开源生态通常免费）。

---

### 3.4 缓存敏感型上下文工程（Cache-Friendly Prompt Engineering）的反向促进

当系统拥有了精确的四维计费时，反过来能够极大促进 Agent 的上下文工程架构升级：
- **静态前置原则（Static Prefix First）**：Agent 应将极其稳定的 `System Prompt`、`Tool Definitions` 永远置于消息序列的最前端，严禁在前端插入动态时间戳或随机数；
- **历史只读锁（Append-Only History）**：对话历史保持纯粹追加，避免就地修改早期消息导致整个会话的 KV 缓存全部失效（Cache Busting）；
- **用户收益可视化**：在界面直观展示“本次调用为您通过缓存节省了 82% 费用”，极大增强用户信任感。

---

## 四、双币体系 (CNY/USD) 深度设计与价格选填静默逻辑

### 4.1 汇率浮动陷阱与财务核算刚性合规原则

长期以来，许多开发者工具为了“偷懒”，在底层强制使用单一美元（USD）存储单价，并尝试在前端拉取实时汇率（如 1 USD = 7.15 CNY）动态换算显示人民币。

**审计结论：该做法在工业级产品中属于严重的反模式，必须刚性取缔**。原因如下：
1. **国内厂商官方刊例为固定人民币**：阿里云百炼 Qwen3.8 Max 官方刊例就是严格的 `¥12.00 / 1M`，并非随汇率每天波动的美元换算值。若强行换算，今天显示 ¥12.01，明天显示 ¥11.98，引起用户强烈质疑；
2. **企业合规报销与审计对账**：中国大陆企业用户在阿里云、火山引擎、智谱清言充值获取的是增值税专票（单位为元），本地开发工具导出的用量清单必须精确到分，汇率漂移将导致企业财务无法对账；
3. **独立法定货币体系原则**：系统应当将货币作为一等公民（`Currency::Cny` 与 `Currency::Usd`），供应商属于哪个站，就配置对应站的官方币种，两者在底层绝对隔离，**严禁私自自动兑换**。

---

### 4.2 双币种隔离与跨平台显示规范

在数据结构中，每个模型的 `PricingSpec` 必须显式绑定单一法定货币：
- `currency: "CNY"`：前缀显示 `¥`，中文环境或国内模型优先；
- `currency: "USD"`：前缀显示 `$`，国际模型优先。

跨会话累计与状态栏呈现规则：
- 当用户在同一个会话中混用了多个模型（例如先用 Qwen 分析，再用 Claude 重构），结算系统**严禁将美元和人民币直接相加**，而应分列呈现：
  $$\text{Session Total: } ¥0.42 + \$0.15$$
- 保持各币种账单的纯洁性与真实性。

---

### 4.3 彻底选填与静默降级（Zero-Cost Silence 原则）

在人机交互与状态呈现上，必须恪守 **Zero-Cost Silence（选填静默）原则**：

```
                    检查模型配置中的 pricing 字段
                                  │
                  ┌───────────────┴───────────────┐
                  ▼                               ▼
         pricing 为 None?                  pricing 存在?
                  │                               │
                  ▼                               ▼
       【Zero-Cost Silence 触发】         执行微元算费引擎
    1. 不执行任何费用累加计算             计算出精确 CostBreakdown
    2. UI 彻底折叠费用胶囊 (Hidden)       UI 呈现柔和金额胶囊 (如 ¥0.052)
    3. 杜绝呈现 "$0.00" 或 "¥0.00"        悬停展示四维明细 Tooltip
    4. 表单校验 100% 放行 (选填)
```

#### 消除三大视觉噪音：
1. **禁止假“0元”**：许多工具在用户未填价格时默认赋值 `0.0`，进而在每条消息下方打上 `Cost: $0.0000`。对于商业付费模型，这具有严重的误导性；对于本地模型，这属于无意义的冗余信息；
2. **禁止强迫必填**：在供应商或模型配置表单中，价格项必须 100% 允许留空。未填即代表用户不在意费用统计；
3. **静默折叠**：当且仅当模型配置了 `pricing` 且计算结果有效时，界面才优雅挂载费用指示标签。

---

### 4.4 私有网关与自建服务（Ollama / vLLM）零干扰体验

对于通过 Ollama、vLLM、SGLang 或企业内网中转部署开源模型的开发者，算力属于自有固定资产，并不存在按 Token 结算的 API 账单。
- 在 `models.yaml` 中，这些模型的 `pricing` 属性自然缺省为 `null`；
- Conex 在运行全程零报错、零黄色警示、零费用标签，界面完全保持极简纯粹。

## 五、生图与多模态模型按张计费（Per-Image）扩展规范

### 5.1 图像生成与编辑模型的计费痛点（Token 计费失效）

根据最新模型调研，诸如 `google/gemini-3.1-flash-image` (Nano Banana 2)、`openai/gpt-image-2`、`qwen/qwen-image-3`、`bytedance-seed/seedream-5-0-pro` 等多模态旗舰，已全面接通生图与图生图。

然而，这些模型的官方商业结算模式与传统文本模型存在本质冲突：
- 它们可能接收少量的文本 Prompt 或参考图片，但主要输出为固定分辨率的图像；
- 官方计费通常以**“按张计费（per_image）”**为主，例如：
  - `qwen-image-3`：国内站输出标清图 `¥0.20 / 张`，输入参考图 `¥0.02 / 张`；
  - `seedream-5-0-pro`：生成商用设计图 `¥0.25 / 张`；
  - `meta/muse-image`：生成图片 `$0.01 / 张`。
- 如果强行套用 `per_1m_tokens`，系统不仅无法向用户汇报正确的花费，还会导致输出 Token 统计与实际账单发生天文数字般的偏差。

---

### 5.2 复合单位矩阵建模（`per_1m_tokens` vs `per_image` vs `per_request`）

我们设计如下枚举契约：
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum PricingUnit {
    Per1mTokens,
    PerImage,
    PerRequest,
}
```

- 当 `unit == PricingUnit::Per1mTokens` 时：单价按每百万 Token 计算；
- 当 `unit == PricingUnit::PerImage` 时：
  - `input` 表示每张输入参考图（Reference Image）的基础处理单价；
  - `output` 表示每张生成目标图像（Generated Output Image）的标准单价；
- 当 `unit == PricingUnit::PerRequest` 时：单次调用按固定基础费用结算。

---

### 5.3 图生图与多参考图的复合算费算法

在现代复杂图像编辑与视觉 Agent 任务中，一次调用可能携带多张参考图并要求生成多张候选图。其算费逻辑如下：

$$\text{Cost} = (N_{\text{ref\_images}} \times \text{Rate}_{\text{input\_per\_image}}) + (N_{\text{output\_images}} \times \text{Rate}_{\text{output\_per\_image}})$$

若模型同时支持混合计费（如部分文字按 Token 计费，出图按张计费），引擎支持通过 `image_rates` 字段进行复合求和。

---

### 5.4 分辨率与生成档位阶梯费率设计

图像模型往往根据输出分辨率（如 1024x1024 标清 vs 2048x2048 高清 2K vs 4K）实行阶梯收费：
- 例如 OpenAI `gpt-image-2`：标清约为 `$0.040 / 张`，高清 2K 约为 `$0.130 / 张`；
- 在扩展规格中，支持在 `image_options` 中声明质量档位乘数（Quality Multiplier: Standard=1.0x, HD=2.5x）。

---

## 六、高精度无损微元（Micros）计费算法实现

### 6.1 浮点数在金融与计费结算中的致命陷阱（IEEE 754 精度塌陷）

计算机底层的 IEEE 754 双精度浮点数（`f64` / `number`）基于二进制表示小数，无法精准表达十进制的分数。
一个经典现象：
```typescript
console.log(0.1 + 0.2); // 输出 0.30000000000000004
```
在百万级别 Token 的高频交互中，若持续使用 `f64` 进行乘除与累加：
1. **累积漂移**：经过几千次工具调用，累加值与真实值发生分级漂移；
2. **格式化跳动**：用户看到金额在 `¥0.05000000000000002` 与 `¥0.04999999999999999` 之间不可控跳动；
3. **无法精确断言**：在单元测试和金融级集成门禁中，浮点数相等性判断 `cost == 0.05` 必定不可靠。

---

### 6.2 微元定点数（Micros / $10^{-6}$ 单位）数学原理与算式推导

为彻底根除这一行业顽疾，本审计确立基于 **微元（Micros，即 $10^{-6}$ 元）** 的定点数纯整数计算标准。

#### 1. 定义
- **1 元（CNY）** = $1,000,000$ 微元（Micro-CNY）；
- **1 美元（USD）** = $1,000,000$ 微元（Micro-USD）；
- **1 分（Cent）** = $10,000$ 微元。

#### 2. 无损单价转换
用户在配置中填写的单价通常是以“元/百万 Token”为单位（例如 DeepSeek 输入 `3.00` 元/1M tokens）。
注意极其精妙的数学对称性：
$$\text{单价 } P \text{ 元 / 1M tokens} = \frac{P \times 10^6 \text{ 微元}}{10^6 \text{ tokens}} = P \text{ 微元 / 1 token}$$

这意味着：
**输入单价为 3.00 元/1M tokens，等价于每个 Token 恰好价值 3 微元（3 micros）！**

#### 3. 核心无损算式
若请求消耗了 $T$ 个 token，单价为 $R$（元/1M tokens），则该项消耗的微元整数为：
$$\text{Cost}_{\text{micros}} = \left\lfloor \frac{T \times \text{round}(R \times 10^6) + 5 \times 10^5}{10^6} \right\rfloor$$
或者简写为精准四舍五入整数乘除：
$$\text{Cost}_{\text{micros}} = \text{round\_div}(T \times R_{\text{micros\_per\_token}}, 1)$$

在全部各项计算完成并进行整数累加后，仅在最终呈现给人类阅读时，才执行格式化字符串除法（格式化为保留 3~5 位有效数字），从而**在计算全生命周期内实现 100% 零精度损失**。

---

### 6.3 阶梯计费（Tiered Pricing）倒序匹配算法

当模型配置了 `tiers` 列表时，匹配算法必须遵循：
1. 依据 `input_tokens_above` 门槛降序排序；
2. 扫描当前请求的总输入 Token（`prompt_tokens`）；
3. 第一个满足 `prompt_tokens >= tier.input_tokens_above` 的阶梯即为生效阶梯；
4. 该阶梯的四项单价完整替换基准单价，整单执行结算。

---

### 6.4 错峰时段折扣（Off-Peak 50%）与批处理结算引擎

当模型声明了 `supports_off_peak_discount: true` 时：
1. 内核获取当前请求发起时刻的当地时间（如 DeepSeek 以北京时间 CST 为基准）；
2. 判定是否处于错峰窗口（非高峰期或周末）；
3. 若命中错峰，微元单价乘以 `500_000` 并除以 `1_000_000`（即 0.5 整数衰减）；
4. 输出明细中断言包含 `is_off_peak_discount_applied: true`。

---

### 6.5 Rust 内核生产级无损微元计费引擎完整实现

落盘规划：`crates/agent-provider/src/pricing_engine.rs`

```rust
// =============================================================================
// Conex / Crish - 生产级微元无损计费引擎 (pricing_engine.rs)
// =============================================================================

use serde::{Deserialize, Serialize};

/// 结算法定货币
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum Currency {
    #[serde(rename = "USD")]
    Usd,
    #[serde(rename = "CNY")]
    Cny,
}

impl Currency {
    pub fn symbol(&self) -> &'static str {
        match self {
            Currency::Cny => "¥",
            Currency::Usd => "$",
        }
    }
}

/// 计量单元
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum PricingUnit {
    Per1mTokens,
    PerImage,
    PerRequest,
}

/// 阶梯费率配置
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct PricingTier {
    pub input_tokens_above: u64,
    pub input: f64,
    pub output: f64,
    #[serde(default)]
    pub cache_read: Option<f64>,
    #[serde(default)]
    pub cache_write: Option<f64>,
}

/// 模型四价计费体系 (100% 选填)
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct ModelPricing {
    pub currency: Currency,
    #[serde(default = "default_unit")]
    pub unit: PricingUnit,
    pub input: f64,
    pub output: f64,
    #[serde(default)]
    pub cache_read: Option<f64>,
    #[serde(default)]
    pub cache_write: Option<f64>,
    #[serde(default, skip_serializing_if = "Vec::is_empty")]
    pub tiers: Vec<PricingTier>,
    #[serde(default)]
    pub supports_off_peak_discount: bool,
}

fn default_unit() -> PricingUnit {
    PricingUnit::Per1mTokens
}

/// 微元计费明细报告
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct CostBreakdownMicros {
    pub currency: Currency,
    /// 普通输入消耗微元
    pub input_micros: i64,
    /// 生成输出消耗微元
    pub output_micros: i64,
    /// 缓存读取消耗微元
    pub cache_read_micros: i64,
    /// 缓存写入消耗微元
    pub cache_write_micros: i64,
    /// 总微元消耗 (1 元 = 1,000,000 微元)
    pub total_micros: i64,
    /// 是否命中了错峰半价优惠
    pub is_off_peak: bool,
    /// 格式化人性化显示字符串 (如 "¥0.052" 或 "$0.0034")
    pub formatted_total: String,
}

/// 生产级无损计费引擎
pub struct MicrosBillingEngine;

impl MicrosBillingEngine {
    /// 计算某次请求的完整无损微元账单
    /// 若 pricing 为 None，直接返回 None (实现 Zero-Cost Silence)
    pub fn calculate(
        pricing_opt: &Option<ModelPricing>,
        prompt_tokens: u64,
        completion_tokens: u64,
        cached_read_tokens: u64,
        cached_write_tokens: u64,
        is_off_peak_hour: bool,
    ) -> Option<CostBreakdownMicros> {
        let pricing = pricing_opt.as_ref()?;

        // 1. 处理按张计费模式 (PerImage)
        if pricing.unit == PricingUnit::PerImage {
            let ref_images = prompt_tokens;      // 约定：输入张数
            let gen_images = completion_tokens;  // 约定：生成张数

            let input_rate_micros = Self::to_micros(pricing.input);
            let output_rate_micros = Self::to_micros(pricing.output);

            let input_micros = (ref_images as i64) * input_rate_micros;
            let output_micros = (gen_images as i64) * output_rate_micros;
            let total_micros = input_micros + output_micros;

            let formatted_total = Self::format_micros(total_micros, pricing.currency);

            return Some(CostBreakdownMicros {
                currency: pricing.currency,
                input_micros,
                output_micros,
                cache_read_micros: 0,
                cache_write_micros: 0,
                total_micros,
                is_off_peak: false,
                formatted_total,
            });
        }

        // 2. 处理标准按百万 Token 计费模式 (Per1mTokens)
        let mut active_input = pricing.input;
        let mut active_output = pricing.output;
        let mut active_cache_read = pricing.cache_read.unwrap_or(0.0);
        let mut active_cache_write = pricing.cache_write.unwrap_or(0.0);

        // 检索命中最高门槛的阶梯费率
        if !pricing.tiers.is_empty() {
            let mut sorted_tiers = pricing.tiers.clone();
            sorted_tiers.sort_by(|a, b| b.input_tokens_above.cmp(&a.input_tokens_above));
            for tier in sorted_tiers {
                if prompt_tokens >= tier.input_tokens_above {
                    active_input = tier.input;
                    active_output = tier.output;
                    if let Some(cr) = tier.cache_read {
                        active_cache_read = cr;
                    }
                    if let Some(cw) = tier.cache_write {
                        active_cache_write = cw;
                    }
                    break;
                }
            }
        }

        // 错峰时段半价因子
        let apply_discount = pricing.supports_off_peak_discount && is_off_peak_hour;
        let discount_factor_num = if apply_discount { 1 } else { 2 };
        let discount_factor_den = 2;

        // 扣除缓存命中读取后的普通未命中输入
        let non_cached_prompt_tokens = prompt_tokens.saturating_sub(cached_read_tokens);

        // 计算微元分量：(Tokens * Rate_per_1M) 微元四舍五入
        // 证明：Rate 元/1M = Rate * 10^6 微元 / 10^6 Token = Rate 微元 / 1 Token
        let input_micros = Self::compute_token_micros(
            non_cached_prompt_tokens,
            active_input,
            discount_factor_num,
            discount_factor_den,
        );

        let output_micros = Self::compute_token_micros(
            completion_tokens,
            active_output,
            discount_factor_num,
            discount_factor_den,
        );

        let cache_read_micros = Self::compute_token_micros(
            cached_read_tokens,
            active_cache_read,
            discount_factor_num,
            discount_factor_den,
        );

        let cache_write_micros = Self::compute_token_micros(
            cached_write_tokens,
            active_cache_write,
            discount_factor_num,
            discount_factor_den,
        );

        let total_micros = input_micros + output_micros + cache_read_micros + cache_write_micros;
        let formatted_total = Self::format_micros(total_micros, pricing.currency);

        Some(CostBreakdownMicros {
            currency: pricing.currency,
            input_micros,
            output_micros,
            cache_read_micros,
            cache_write_micros,
            total_micros,
            is_off_peak: apply_discount,
            formatted_total,
        })
    }

    /// 将浮点单价转为以微元为基准的整数（保留精确到 10^-6）
    #[inline]
    fn to_micros(rate: f64) -> i64 {
        (rate * 1_000_000.0).round() as i64
    }

    /// 计算指定 Token 消耗在给定费率和折扣下的无损整数微元
    #[inline]
    fn compute_token_micros(
        tokens: u64,
        rate_per_1m: f64,
        discount_num: i64,
        discount_den: i64,
    ) -> i64 {
        if tokens == 0 || rate_per_1m <= 0.0 {
            return 0;
        }
        // Rate (元/1M) = Rate (微元/Token)
        // 微元 = (tokens * (rate_per_1m * 10^6) * discount_num) / (10^6 * discount_den)
        // 巧妙化简：微元 = (tokens * rate_in_nano) / (1000 * discount_den)
        let rate_nanos = (rate_per_1m * 1_000_000_000.0).round() as i128;
        let tokens_i128 = tokens as i128;
        let raw_product = tokens_i128 * rate_nanos * (discount_num as i128);

        // 执行加半四舍五入整数除法
        let divisor = 1_000_000_000i128 * (discount_den as i128);
        let rounded = (raw_product + (divisor / 2)) / divisor;
        rounded as i64
    }

    /// 将微元格式化为带法定符号的人性化金额文本
    pub fn format_micros(micros: i64, currency: Currency) -> String {
        let sym = currency.symbol();
        if micros == 0 {
            return format!("{}{}", sym, "0.00");
        }

        let is_negative = micros < 0;
        let abs_micros = micros.abs();

        let yuan = abs_micros / 1_000_000;
        let rem = abs_micros % 1_000_000;

        let sign_str = if is_negative { "-" } else { "" };

        // 极小额度显示 (如少于 0.001 元，即 1,000 微元)
        if yuan == 0 && rem < 1_000 {
            let fraction = (rem as f64) / 1_000_000.0;
            return format!("{}{}{:.5}", sign_str, sym, fraction);
        }

        // 小于 1 元且大于等于 0.001 元，格式化保留 4 位有效显示
        if yuan == 0 {
            let fraction = (rem as f64) / 1_000_000.0;
            return format!("{}{}{:.4}", sign_str, sym, fraction);
        }

        // 大于等于 1 元，保留常规 3 位小数
        let val = (abs_micros as f64) / 1_000_000.0;
        format!("{}{}{:.3}", sign_str, sym, val)
    }
}
```

```typescript
// =============================================================================
// Conex Web/Desktop - 前端微元高精度对称计费工具 (pricingEngine.ts)
// =============================================================================

export type Currency = "USD" | "CNY";
export type PricingUnit = "per_1m_tokens" | "per_image" | "per_request";

export interface PricingTier {
  inputTokensAbove: number;
  input: number;
  output: number;
  cacheRead?: number;
  cacheWrite?: number;
}

export interface ModelPricing {
  currency: Currency;
  unit?: PricingUnit;
  input: number;
  output: number;
  cacheRead?: number;
  cacheWrite?: number;
  tiers?: PricingTier[];
  supportsOffPeakDiscount?: boolean;
}

export interface CostBreakdownMicros {
  currency: Currency;
  inputMicros: number;
  outputMicros: number;
  cacheReadMicros: number;
  cacheWriteMicros: number;
  totalMicros: number;
  isOffPeak: boolean;
  formattedTotal: string;
}

export class FrontendPricingEngine {
  /**
   * 纯前端高精度微元计算函数
   * 若 pricing 为 undefined，直接返回 null (Zero-Cost Silence)
   */
  public static calculate(
    pricing?: ModelPricing | null,
    promptTokens: number = 0,
    completionTokens: number = 0,
    cacheReadTokens: number = 0,
    cacheWriteTokens: number = 0,
    isOffPeak: boolean = false
  ): CostBreakdownMicros | null {
    if (!pricing) {
      return null;
    }

    const currency = pricing.currency;
    const unit = pricing.unit ?? "per_1m_tokens";

    if (unit === "per_image") {
      const inputMicros = Math.round(promptTokens * pricing.input * 1_000_000);
      const outputMicros = Math.round(completionTokens * pricing.output * 1_000_000);
      const totalMicros = inputMicros + outputMicros;
      return {
        currency,
        inputMicros,
        outputMicros,
        cacheReadMicros: 0,
        cacheWriteMicros: 0,
        totalMicros,
        isOffPeak: false,
        formattedTotal: this.formatMicros(totalMicros, currency),
      };
    }

    let activeInput = pricing.input;
    let activeOutput = pricing.output;
    let activeCacheRead = pricing.cacheRead ?? 0;
    let activeCacheWrite = pricing.cacheWrite ?? 0;

    // 阶梯判定
    if (pricing.tiers && pricing.tiers.length > 0) {
      const sortedTiers = [...pricing.tiers].sort((a, b) => b.inputTokensAbove - a.inputTokensAbove);
      for (const tier of sortedTiers) {
        if (promptTokens >= tier.inputTokensAbove) {
          activeInput = tier.input;
          activeOutput = tier.output;
          if (tier.cacheRead !== undefined) activeCacheRead = tier.cacheRead;
          if (tier.cacheWrite !== undefined) activeCacheWrite = tier.cacheWrite;
          break;
        }
      }
    }

    const applyDiscount = !!pricing.supportsOffPeakDiscount && isOffPeak;
    const discountMultiplier = applyDiscount ? 0.5 : 1.0;

    const uncachedPrompt = Math.max(0, promptTokens - cacheReadTokens);

    const inputMicros = Math.round(uncachedPrompt * activeInput * discountMultiplier);
    const outputMicros = Math.round(completionTokens * activeOutput * discountMultiplier);
    const cacheReadMicros = Math.round(cacheReadTokens * activeCacheRead * discountMultiplier);
    const cacheWriteMicros = Math.round(cacheWriteTokens * activeCacheWrite * discountMultiplier);

    const totalMicros = inputMicros + outputMicros + cacheReadMicros + cacheWriteMicros;

    return {
      currency,
      inputMicros,
      outputMicros,
      cacheReadMicros,
      cacheWriteMicros,
      totalMicros,
      isOffPeak: applyDiscount,
      formattedTotal: this.formatMicros(totalMicros, currency),
    };
  }

  public static formatMicros(micros: number, currency: Currency): string {
    const sym = currency === "CNY" ? "¥" : "$";
    if (micros === 0) return `${sym}0.00`;

    const isNegative = micros < 0;
    const abs = Math.abs(micros);
    const sign = isNegative ? "-" : "";

    if (abs < 1_000) {
      return `${sign}${sym}${(abs / 1_000_000).toFixed(5)}`;
    }
    if (abs < 1_000_000) {
      return `${sign}${sym}${(abs / 1_000_000).toFixed(4)}`;
    }
    return `${sign}${sym}${(abs / 1_000_000).toFixed(3)}`;
  }
}
```

### 8.6 生产环境集成门禁刚性断言清单

所有涉及价格、用量解析与账单呈现的代码变更，必须通过以下 **8 大刚性断言**：
- [ ] **GATE-01**：在所有代码库中，严禁出现针对未配置价格显示 `$0.00` 或 `¥0.00` 的逻辑；
- [ ] **GATE-02**：所有货币金额展示必须带有法定明确符号（`¥` 或 `$`），严禁无符号裸数字；
- [ ] **GATE-03**：严禁在内核或前端引入浮动汇率自动兑换模块，双币账单保持绝对隔离；
- [ ] **GATE-04**：内核计算必须通过 `MicrosBillingEngine` 整数运算，禁止对 `f64` 金额直接执行 `+=`；
- [ ] **GATE-05**：必须正确解析 DeepSeek / Qwen 流式返回中的 `cached_tokens`，且计算时必须先扣除该部分再算普通输入；
- [ ] **GATE-06**：必须正确解析 Anthropic 的 `cache_creation_input_tokens` 并匹配 `cacheWrite` 单价；
- [ ] **GATE-07**：生图模型的 `PricingUnit::PerImage` 必须能按张正确输出账单；
- [ ] **GATE-08**：CI 门禁套件包含上述全部 28 个自动化测试用例，覆盖率达 100%。
