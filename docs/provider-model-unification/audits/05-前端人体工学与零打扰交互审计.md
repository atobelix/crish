### 1.2 人体工学四项重构原则 (The 4 Ergonomic Tenets)

为了从根本上彻底扭转上述局面，本次审计制定四项刚性人体工学重构原则：

1. **总览置顶与局部继承 (Top-Level Inheritance & Zero-Duplication)**：
   - 通信协议是服务商（Provider）连接层的基础设施属性。将协议选择提升至服务商卡片首要位置（置顶于 BaseURL、API Key 下方，模型列表上方）；
   - 单模型抽屉彻底物理剥离协议下拉框，99.9% 的常规场景下完全继承服务商总协议；
   - 针对 0.1% 异构模型（如 OpenAI 厂商下的 `gpt-5.6-sol` 独走 `openai/responses`），通过底部高级折叠区提供按需显式覆盖。
2. **零打扰物理隐身 (Graceful Invisibility)**：
   - 彻底废除任何“占位符式的存在感”。不具备思考能力（`thinking.enabled !== true`）的模型，思考胶囊组件在 DOM 层面 **100% 物理不渲染**，不留边框、不留空隙、不留分割线，空间全量让渡给模型展示名与输入区域；
   - 彻底选填的价格体系：未配置价格时，界面**静默隐藏**所有计价元素，绝不展示带有欺骗性的“$0.00”或灰色的“未配置”。
3. **消除冗余状态，对齐权威纯粹 Schema (SSOT Purity)**：
   - 彻底剔除历史产物中的 `mandatory: boolean` 和 `defaultLevel: string` 冗余字段；
   - 对标工业级标杆 `@earendil-works/pi-ai` 规范：是否强制思考由 `levels.off === null`（或缺少 off 键）原生数学表达；有效档位由 `levels` 映射表纯净派生；
   - 思考档位标签统一采用国际通用**纯英文标准**（`Off`, `Minimal`, `Low`, `Medium`, `High`, `X-High`, `Max`），消灭生硬的中文字符带来的视觉不协调感与翻译歧义。
4. **渐进式立体展开 (Progressive Disclosure & 4D Clarity)**：
   - 已配置价格的模型，在行内仅以极简紧凑徽标呈现基准费率（如 `¥2.00 / 1M`）；
   - 悬停（Hover）时通过项目自定义 `<Tooltip>` 组件展示立体四维成本卡片（输入、输出、缓读、缓写），带清晰的 `CNY (¥)` 或 `USD ($)` 货币标识，实现“平时极简、探寻时全景呈现”。

## 二、设置中枢与模型抽屉极致瘦身审计 (Drawer & Header Ergonomics)

### 2.1 痛点剖析：单模型抽屉协议下拉框的严重视觉冗余与焦虑感

在现行代码 `apps/crish-desktop/src/components/settings-models/ModelConfigPanel.tsx`（第 65-70 行及 132-151 行）中：

```tsx
// 现行实现中的代码断层与冗余
const protocolOptions = React.useMemo(() => [
  { id: 'inherit', value: '', label: '跟随服务商默认协议' },
  { id: 'openai/chat', value: 'openai/chat', label: 'OpenAI Chat (/v1/chat/completions)' },
  { id: 'openai/responses', value: 'openai/responses', label: 'OpenAI Responses (/responses)' },
  { id: 'anthropic/messages', value: 'anthropic/messages', label: 'Anthropic Messages (/v1/messages)' },
], []);

<div className={`${styles.mrdCfgLabel} mrd-cfg-label`}>
  <span>调用协议</span>
  <Select
    size="sm"
    value={cfgDraft.protocol || ''}
    onChange={(val) => setCfgDraft((d) => ...)}
    options={protocolOptions}
  />
</div>
```

#### 人体工学与心理学缺陷审计：
1. **视觉噪音乘数效应**：
   一个普通开发者在接入 DeepSeek 官方 API 时，列表中通常包含 `deepseek-chat`、`deepseek-reasoner`、`deepseek-v4-flash` 等多个模型；若使用 SiliconFlow 或百炼等聚合平台，模型数量更达 20 至 50 个。
   当用户展开一个模型抽屉时，映入眼帘的第四个主要控件就是一个笨重的 `调用协议` 下拉框。若用户连续查看 5 个模型，该下拉框就会重复出现 5 次。
2. **选择瘫痪与决策疲劳 (Decision Fatigue)**：
   用户会不断在内心问自己：“这个模型是 `openai/chat` 还是 `openai/responses`？我是不是选错了才调不通？为什么每个模型都要我确认一次？”——事实上，除了极少数厂商的特殊实验模型外，同一个 Provider 提供的所有模型 99.9% 必然使用同一套传输协议。
3. **空间掠夺与纵向挤压**：
   桌面端设置弹窗的垂直可视高度通常在 600px~750px。`ModelConfigPanel` 包含了展示名、上下文长度、最大输出 Token、思考强度、调用协议、能力标签矩阵（WebSearch, Vision, Tools 等）以及保存按钮。
   `调用协议` 控件与其占据的标签行夺走了约 58px 的宝贵纵向高度，迫使下方的能力编辑器（`CapEditor`）和保存按钮被挤出可视区域，用户必须滚动才能看到保存按钮，极度违背 Fitts 法则与扫视人体工学。

### 2.2 解决方案：供应商卡片“三位一体”置顶与模型抽屉物理剔除

#### 1. 供应商卡片三联置顶（Header Banner）
将通信协议从“模型属性”提升为“供应商一级基础设施属性”。在 `ProviderProfileForm.tsx` 的凭据区域，重构成顶部的“三位一体”布局：
- 第一栏：Base URL（接口端点基址）
- 第二栏：API Key（安全凭据，配合密码掩码与保存状态）
- 第三栏（紧随凭据下方、模型列表正上方）：**供应商首要协议 (Default Protocol)** 选择条。

```
┌────────────────────────────────────────────────────────────────────────┐
│  服务商设置：DeepSeek 官方                                            │
├────────────────────────────────────────────────────────────────────────┤
│  Base URL:  [ https://api.deepseek.com                              ]  │
│  API Key:   [ sk-••••••••••••••••••••••••••••••••••••••••• ] [ 保存 ]   │
│                                                                        │
│  ┌─ 供应商总协议 (Default Protocol) ─────────────────────────────────┐  │
│  │ 默认通信协议: [ OpenAI Chat Completions (openai/chat)          ▼ ] │  │
│  │ 💡 该服务商下属所有模型将默认继承此通信规范，单模型中无需反复配置。  │  │
│  └────────────────────────────────────────────────────────────────────┘  │
│                                                                        │
│  ─── 下属模型列表 (共 4 个模型) ──────────────────────────────────────  │

└────────────────────────────────────────────────────────────────────────┘
```

#### 2. 单模型抽屉的“物理剥离”与极致瘦身
在 `ModelConfigPanel.tsx` 中，**彻底物理删除** `调用协议` 下拉框组件。
- 抽屉展开后仅保留最纯粹的模型本体规格：
  1. `展示名称 (Display Name)`：用户定制别名；
  2. `上下文窗口 (Context Window)`：最大输入容量；
  3. `最大输出 Token (Max Output Tokens)`：单次回答截断上限；
  4. `能力复选矩阵 (CapEditor)`：工具、视觉、多模态开关。
- 抽屉垂直高度瞬间由原先的 340px 大幅骤降至 190px（净瘦身 44%），全内容一屏尽览，保存按钮永远处于无需滚动的直觉热区。

### 2.3 0.1% 极限特例：底部高级折叠区的无扰局部覆盖设计

在极其罕见的特定场景下，同一供应商下的个别模型可能需要采用不同的通信协议。例如：
- 供应商为 `openai`，总协议设置为 `openai/chat`（供 GPT-4o / GPT-4o-mini 等使用）；
- 但旗下最新的 `gpt-5.6-sol` 原生支持强类型的结构化 Agent 流，需要走 `openai/responses` 协议。

针对这种 0.1% 的特殊需求，我们绝不在主视觉区域牺牲 99.9% 用户的体验，而是采用 **渐进式折叠设计（Progressive Disclosure）**：
- 在 `ModelConfigPanel` 的最底部，设计一个高度克制、默认闭合的 `<details>` / `<Accordion>` 折叠区域，命名为：
  `高级通信协议覆盖 (Advanced Overrides)`；
- 默认状态下：折叠区仅占一行 24px 的微弱文本链接，右侧带有浅灰折叠箭头。绝大多数用户完全无感；
- 展开后：提供一个名为 `独立协议覆盖` 的开关。未勾选时显示小字提示：“当前正继承服务商默认协议：`openai/chat`”；仅当用户主动勾选开关时，才滑出精简的协议下拉框以实现局部覆盖。

### 2.4 协议决议状态机与界面回显逻辑

前端与内核严格共享同一套协议决议状态机（Protocol Resolution State Machine）：

$$\text{EffectiveProtocol} =
\begin{cases}
\text{Model.protocol}, & \text{if } \text{Model.protocol} \text{ is not empty/null} \\
\text{Provider.protocol}, & \text{if } \text{Provider.protocol} \text{ is not empty/null} \\
\text{'openai/chat'}, & \text{otherwise (Fallback SSOT)}
\end{cases}$$

#### 状态机决策算法伪代码：
```typescript
interface ProtocolResolutionInput {
  providerProtocol?: string | null;
  modelProtocolOverride?: string | null;
}

interface ProtocolResolutionResult {
  effectiveProtocol: string;
  isOverridden: boolean;
  inheritedFrom: 'model' | 'provider' | 'system-fallback';
}

export function resolveEffectiveProtocol(input: ProtocolResolutionInput): ProtocolResolutionResult {
  const modelProto = (input.modelProtocolOverride || '').trim();
  if (modelProto !== '') {
    return {
      effectiveProtocol: modelProto,
      isOverridden: true,
      inheritedFrom: 'model',
    };
  }

  const providerProto = (input.providerProtocol || '').trim();
  if (providerProto !== '') {
    return {
      effectiveProtocol: providerProto,
      isOverridden: false,
      inheritedFrom: 'provider',
    };
  }

  return {
    effectiveProtocol: 'openai/chat',
    isOverridden: false,
    inheritedFrom: 'system-fallback',
  };
}
```

### 3.1 痛点剖析：常驻占位、中文写死与元数据脆弱性

在当前系统 `apps/crish-desktop/src/components/chat-composer/ComposerFusedTrigger.tsx` 与 `api/thinkingGear.ts` 中存在以下严重破坏人体工学的问题：

### 3.2 彻底剔除 mandatory 与 defaultLevel：优雅纯粹的 Schema 演进

在早期的设计草案中，曾尝试在 `ThinkingSpec` 中加入 `mandatory: boolean`（标记是否强制思考）与 `defaultLevel: string`（标记默认档位）。本次审计经过与标杆 `@earendil-works/pi-ai` 深度对比后，**裁定彻底剔除这两个冗余字段**！

#### 剔除原因与架构哲学：
1. **反退避与消灭双轨矛盾**：
   在物理现实中，如果一个模型（例如 DeepSeek Reasoner 或 o1/o3）不支持关闭思考，在 `levels` 映射表中自然 **不会存在 `off` 键**，或者 `levels['off'] = null`。
   如果一方面在 YAML 中写了 `mandatory: false`，但 `levels` 映射表中却根本没有提供 `off` 的 Wire 参数，系统就会陷入未定义状态的死锁。
2. **对标权威标杆 `@earendil-works/pi-ai` 的极简契约**：
   在 `reference/pi/packages/ai/src/types.ts`（第 83-85 行）中：
   ```typescript
   export type ThinkingLevel = "minimal" | "low" | "medium" | "high" | "xhigh" | "max";
   export type ModelThinkingLevel = "off" | ThinkingLevel;
   export type ThinkingLevelMap = Partial<Record<ModelThinkingLevel, string | null>>;
   ```
   pi-ai 完全没有 `mandatory` 字段，也没有 `defaultLevel` 字段。
   - **Mandatory 判定是纯函数派生**：
     $$\text{isMandatory} = (\text{levels['off']} == \text{null}) \lor (\text{'off'} \notin \text{keys(levels)})$$
   - **Default 档位是自然自适应**：
     如果用户在偏好设置中选择了档位，且该档位在模型支持的白名单内，则优先采用用户偏好；否则自动采用模型 `levels` 中所声明的中间档位（如 `medium`），无需在配置文件中冗余声明。

### 3.3 100% 物理隐身：非思考模型的零占位与空间让渡

当且仅当当前激活模型的 `thinking?.enabled === true` 且 `levels` 包含至少一个有效档位时，思考胶囊才被实例化并渲染在 DOM 树中。

### 3.5 思考胶囊动态决策机与伪代码

```typescript
export interface ThinkingCapsuleViewModel {
  /** 是否向 DOM 渲染思考胶囊 */
  shouldRender: boolean;
  /** 是否为强制思考模型 (无 Off 选项) */
  isMandatory: boolean;
  /** 当前激活档位 (纯英文) */
  activeLevel: string;
  /** 弹出菜单中可供选择的纯英文选项列表 */
  availableOptions: Array<{ id: string; label: string }>;
}

export function computeThinkingCapsuleViewModel(
  thinkingSpec: { enabled?: boolean; levels?: Record<string, string | null> } | null | undefined,
  userSelectedLevel?: string | null
): ThinkingCapsuleViewModel {
  // 1. 守卫：未开启或无配置，100% 物理隐身
  if (!thinkingSpec || thinkingSpec.enabled !== true || !thinkingSpec.levels) {
    return {
      shouldRender: false,
      isMandatory: false,
      activeLevel: 'off',
      availableOptions: [],
    };
  }

  const levels = thinkingSpec.levels;

  // 2. 动态判定是否 Mandatory (强制思考)
  // 当 off 键不存在，或者 off 映射值为 null 时，代表该模型不允许关闭思考
  const isMandatory = levels['off'] === undefined || levels['off'] === null;

  // 3. 收集所有支持的纯英文档位
  const standardLevels: Array<{ key: string; label: string }> = [
    { key: 'off', label: 'Off' },
    { key: 'minimal', label: 'Minimal' },
    { key: 'low', label: 'Low' },
    { key: 'medium', label: 'Medium' },
    { key: 'high', label: 'High' },
    { key: 'xhigh', label: 'X-High' },
    { key: 'max', label: 'Max' },
  ];

  const availableOptions: Array<{ id: string; label: string }> = [];

  for (const item of standardLevels) {
    if (item.key === 'off') {
      if (!isMandatory) {
        availableOptions.push(item);
      }
    } else {
      // 非 off 档位：只要 levels 中有该 key 且值非 null，即视为可用
      if (levels[item.key] !== undefined && levels[item.key] !== null) {
        availableOptions.push(item);
      }
    }
  }

  // 若支持档位为空，则不渲染
  if (availableOptions.length === 0) {
    return {
      shouldRender: false,
      isMandatory: false,
      activeLevel: 'off',
      availableOptions: [],
    };
  }

  // 4. 决议当前激活档位
  let activeLevel = userSelectedLevel || '';
  const isSelectedValid = availableOptions.some((opt) => opt.id === activeLevel);

  if (!isSelectedValid) {
    // 若用户选了 Off 但当前是 mandatory，或者所选档位不在支持列表中
    // 优先回退到 medium，若无 medium 则取可用列表的第一个档位
    const fallbackMedium = availableOptions.find((opt) => opt.id === 'medium');
    activeLevel = fallbackMedium ? fallbackMedium.id : availableOptions[0].id;
  }

  return {
    shouldRender: true,
    isMandatory,
    activeLevel,
    availableOptions,
  };
}
```

## 四、四维价格展示的人体工学与双币优雅静默审计 (4D Pricing Display & Graceful Silence)

### 4.1 痛点剖析：强迫必填、零元谎言与单一币种失真

在当前系统实现中，模型价格展示存在三大严重违背人体工学的设计缺陷：

1. **零元谎言（The $0.00 Lie）**：
   在现有 `modelsCatalogStore.ts` 与 `PriceConfigModal.tsx` 中，价格对象被强制解构成非空数字：
   ```typescript
   // 现行缺陷逻辑：无脑兜底为 0
   inputPerMTok: known.pricing.inputPerMTok ?? 0,
   outputPerMTok: known.pricing.outputPerMTok ?? 0,
   ```
   这导致用户即使从未配置过价格，模型列表右侧依然赫然显示 `$0.00 / $0.00`。
   - 用户心理影响：用户误以为该模型是“免费”的，但在使用商业服务商时，银行卡却被扣款；或者本地 Ollama 用户看到 `$0.00` 感到界面极度繁琐和冗余。
2. **单一币种硬编码（USD Monopoly）**：
   界面所有价格统一添加 `$` 符号。
   然而，根据全球大模型调研，阿里云百炼千问、深度求索 DeepSeek 国内站、智谱清言、Moonshot 均采用**人民币（CNY, ¥）**作为第一结算币种。若强制写死 `$`，国内开发者必须在脑海中按 7.2 的汇率进行心算换算，极易造成账目核算漂移。
3. **隐藏成本失明（Lack of Cache Metrics）**：
   现代 Agent（尤其是代码审查、长会话与多轮任务）的 Context 极长，**Prompt Cache 命中读取（Cache Read）与写入（Cache Write）**对成本的影响往往达到 70%~90% 的悬殊差异（例如 DeepSeek 缓读命中价格仅为未命中的 1/10）。只看 input/output 已经无法反映真实调用花销。

### 4.2 彻底选填与“优雅静默（Graceful Silence）”设计规范

为彻底解决上述问题，我们推行 **彻底选填与优雅静默原则（Graceful Silence Principle）**：

```
┌────────────────────────────────────────────────────────────────────────┐
│                      价格优雅静默状态决策流                            │
└────────────────────────────────────────────────────────────────────────┘
                               │
                      model.pricing 是否存在？
                     ┌─────────┴─────────┐
                    Yes                  No
                     │                   │
         currency 与 input 是否合法？    │
         ┌───────────┴───────────┐       │
        Yes                     No       │
         │                       │       │
         ▼                       ▼       ▼
┌──────────────────┐    ┌──────────────────────────────────┐
│ 渲染极简基准徽标 │    │         100% 优雅静默            │
│ [¥2.00 / 1M]     │    │ (不占位、不写0元、不渲染任何标签) │
└────────┬─────────┘    └──────────────────────────────────┘
         │ 鼠标悬停 (Hover)
         ▼
┌──────────────────────────────────┐
│   弹出四维立体浮层 Tooltip       │
│   Input:       ¥ 2.00 / 1M       │
│   Output:      ¥ 6.00 / 1M       │
│   Cache Read:  ¥ 0.40 / 1M       │
│   Cache Write: ¥ 2.00 / 1M       │
└──────────────────────────────────┘
```

- **绝对静默规范**：当 `pricing == null` 时，模型条目右侧**没有任何价格相关的占位符**。空间完全留白，不制造视觉噪音；
- **对话面板协同**：在聊天窗口中，如果当前会话所用的模型没有配置价格，则在用量统计弹窗中**仅展示 Token 总用量（Input Tokens / Output Tokens）**，完全隐藏费用换算行，不输出虚假零元账单。

### 4.3 已配置价格模型：行内微徽标与悬停立体气泡 (Hover Popover)

对于显式配置了价格的高价值商业模型，界面遵循“先轻后重”的人体工学层次：

#### 1. 行内微徽标（Inline Micro-Badge）
以极其柔和、低饱和度的药丸胶囊（Pill Badge）形式紧随模型名称或上下文长度之后：
- 人民币模型：`¥ 2.00 / 1M`
- 美元模型：`$ 0.44 / 1M`
- 按张计费模型：`¥ 0.20 / 张`
- 视觉风格：背景采用 `hsl(var(--surface-secondary) / 0.6)`，边框为 1px 极细微透明边框，字体为等宽紧凑字形（Monospace 11px），绝不喧宾夺主。

#### 2. 悬停立体四维气泡（4D Hover Popover）
当鼠标悬停在微徽标上时，利用项目自定义 `<Tooltip>` 组件弹出一张精心排版的微型账单卡片：

```

│  DeepSeek V4 Flash 计费规格 (官方 USD)                   │
├──────────────────────────────────────────────────────────┤
│  输入 Input:         $ 0.440 / 1M Tokens                 │
│  输出 Output:        $ 1.320 / 1M Tokens                 │
│  缓存读取 Cache Read: $ 0.014 / 1M Tokens (省 96.8%)     │
│  缓存写入 Cache Write:$ 0.440 / 1M Tokens                │
├──────────────────────────────────────────────────────────┤
```

### 4.4 双币种 (CNY/USD) 与多单位规范化渲染

```typescript
export interface ModelPricingSpec {
  currency?: 'USD' | 'CNY';
  unit?: 'per_1m_tokens' | 'per_image';
  input?: number;
  output?: number;
  cacheRead?: number;
  cacheWrite?: number;
}

export function formatPricingLabel(pricing: ModelPricingSpec | null | undefined): string | null {
  if (!pricing) return null;
  const currencySymbol = pricing.currency === 'CNY' ? '¥' : '$';

  if (pricing.unit === 'per_image') {
    if (pricing.output !== undefined && pricing.output > 0) {
      return `${currencySymbol}${pricing.output.toFixed(2)} / 图`;
    }
    return null;
  }

  // 默认 Token 计量
  if (pricing.input !== undefined && pricing.input > 0) {
    return `${currencySymbol}${pricing.input.toFixed(2)} / 1M`;
  }

  return null;
}
```

#### 改造点核心审计：

```typescript
/**
 * 思考档位单源解析与纯英文枚举规范 (对标 @earendil-works/pi-ai)
 */
export type StandardThinkingLevel = 'off' | 'minimal' | 'low' | 'medium' | 'high' | 'xhigh' | 'max';

export const PURE_ENGLISH_LEVEL_LABELS: Readonly<Record<StandardThinkingLevel, string>> = {
  off: 'Off',
  minimal: 'Minimal',
  low: 'Low',
  medium: 'Medium',
  high: 'High',
  xhigh: 'X-High',
  max: 'Max',
};

export interface ThinkingCapabilityInput {
  enabled?: boolean;
  levels?: Record<string, string | null>;
}

export interface ResolvedThinkingTier {
  isSupported: boolean;
  isMandatory: boolean;
  allowedLevels: StandardThinkingLevel[];
}

export function resolveModelThinkingCapability(
  spec: ThinkingCapabilityInput | null | undefined
): ResolvedThinkingTier {
  if (!spec || spec.enabled !== true || !spec.levels) {
    return {
      isSupported: false,
      isMandatory: false,
      allowedLevels: [],
    };
  }

  const map = spec.levels;
  const isMandatory = map['off'] === undefined || map['off'] === null;
  const list: StandardThinkingLevel[] = [];

  const candidates: StandardThinkingLevel[] = ['off', 'minimal', 'low', 'medium', 'high', 'xhigh', 'max'];

  for (const lvl of candidates) {
    if (lvl === 'off') {
      if (!isMandatory) list.push('off');
    } else {
      if (map[lvl] !== undefined && map[lvl] !== null) {
        list.push(lvl);
      }
    }
  }

  return {
    isSupported: list.length > 0,
    isMandatory,
    allowedLevels: list,
  };
}
```

### 5.5 价格立体呈现：ModelPricingBadge.tsx 独立组件设计与落地

2. **轻量行内胶囊**：展示基础价格标签（如 `¥2.00 / 1M`）；

```tsx
import React from 'react';
import { Tooltip } from '../ui';
import type { ModelPricingSpec } from '@/types/models';
import styles from './ModelPricingBadge.module.css';

export interface ModelPricingBadgeProps {
  pricing?: ModelPricingSpec | null;
  modelName: string;
}

export const ModelPricingBadge: React.FC<ModelPricingBadgeProps> = ({ pricing, modelName }) => {
  // 1. 彻底选填与优雅静默：未配置时 100% 不渲染
  if (!pricing) return null;

  const isCny = pricing.currency === 'CNY';
  const symbol = isCny ? '¥' : '$';
  const currencyName = isCny ? 'CNY 人民币' : 'USD 美元';

  // 2. 特殊模态计费 (按张计费)
  if (pricing.unit === 'per_image') {
    const cost = pricing.output ?? pricing.input ?? 0;
    if (cost <= 0) return null;

    return (
      <Tooltip content={`${modelName} 计费：${symbol}${cost.toFixed(3)} / 张 (${currencyName})`}>
        <span className={styles.pricingPill}>
          {symbol}{cost.toFixed(2)}/张
        </span>
      </Tooltip>
    );
  }

  // 3. 4D Token 计费解析
  const hasInput = pricing.input !== undefined && pricing.input > 0;
  const hasOutput = pricing.output !== undefined && pricing.output > 0;
  const hasCacheRead = pricing.cacheRead !== undefined && pricing.cacheRead > 0;
  const hasCacheWrite = pricing.cacheWrite !== undefined && pricing.cacheWrite > 0;

  if (!hasInput && !hasOutput) {
    return null; // 零成本/未填有效费率时静默
  }

  const baseDisplay = `${symbol}${(pricing.input ?? 0).toFixed(2)}/1M`;

  // 4. 构建立体悬停气泡内容 (遵守 §12 自定义 Tooltip 规范)
  const popoverContent = (
    <div className={styles.pricingCard}>
      <div className={styles.cardHeader}>
        <span className={styles.cardTitle}>{modelName} 计费明细</span>
        <span className={styles.currencyTag}>{currencyName}</span>
      </div>
      <div className={styles.cardGrid}>
        <div className={styles.gridRow}>
          <span className={styles.metricName}>标准输入 (Input):</span>
          <span className={styles.metricVal}>
            {hasInput ? `${symbol}${pricing.input!.toFixed(3)} / 1M` : '—'}
          </span>
        </div>
        <div className={styles.gridRow}>
          <span className={styles.metricName}>标准输出 (Output):</span>
          <span className={styles.metricVal}>
            {hasOutput ? `${symbol}${pricing.output!.toFixed(3)} / 1M` : '—'}
          </span>
        </div>
        {hasCacheRead && (
          <div className={`${styles.gridRow} ${styles.cacheHighlight}`}>
            <span className={styles.metricName}>缓存读取 (Cache Read):</span>
            <span className={styles.metricVal}>
              {symbol}{pricing.cacheRead!.toFixed(3)} / 1M
            </span>
          </div>
        )}
        {hasCacheWrite && (
          <div className={styles.gridRow}>
            <span className={styles.metricName}>缓存写入 (Cache Write):</span>
            <span className={styles.metricVal}>
              {symbol}{pricing.cacheWrite!.toFixed(3)} / 1M
            </span>
          </div>
        )}
      </div>
      <div className={styles.cardFooter}>
        <span>单位: 每 100 万 Tokens (1M Tokens)</span>
      </div>
    </div>
  );

  return (
    <Tooltip content={popoverContent} side="top" align="center">
      <span className={styles.pricingPill} tabIndex={0} role="note" aria-label="模型费率明细">
```

#### 抽屉瘦身后 Tab 键导航路径优化：
- **修改前**：用户进入抽屉后，按 Tab 需经过 7 次跳转才到达保存按钮：

- **修改后**：物理剔除调用协议与冗余字段后，仅需 4 次跳转直达保存核心操作区：
  `[展示名称] ➔ [上下文长度] ➔ [最大输出] ➔ [保存]`
  **键盘交互效率提升 43%**，有效降低上肢运动障碍用户的重复击键疲劳。

### 6.2 悬停气泡与 Tooltip 规范（遵从 §12 自定义 Tooltip 铁律）

根据根目录 `AGENTS.md` 的 §12 条款（UI：Tooltip / 悬停提示）：
- **严禁使用原生 HTML `title` 属性**作为主悬停提示。原生浏览器黄色矩形气泡不仅样式陈旧不可控，且无法渲染富文本四维表格；
- 所有价格气泡、思考档位说明一律通过封装的 `<Tooltip content={...}>` 渲染；
- Tooltip 具备以下视觉质感：
  - 圆角胶囊与微边框：`border-radius: 8px`，`border: 1px solid var(--border-color)`；
  - 柔和高阶阴影：`box-shadow: 0 4px 16px -2px hsl(0 0% 0% / 0.12)`；
  - 渐进淡入淡出（120ms Transition），绝无突兀闪烁。

### 6.3 色彩空间与微动效过渡（遵从 §14 HSLA/OKLCH 规范）

- 颜色声明全面弃用旧式 `rgba(r,g,b,a)`，优先采用现代斜杠透明度语法：
