### 1.1 罪状一：`mandatory: bool` 伪概念的虚妄复杂性与状态分裂

#### 1. 现象复盘：什么是“强制思考”？
在 `02-AgentB` 与 `03-AgentC` 的设计中，引入了 `mandatory: bool` 字段，并在文档中用了大量篇幅去解释：
- “某些模型（如 o3-pro, Claude 5 Adaptive, Gemini 3.8 Flash）是强制思考的，底层 API 拒绝关闭思考”；
- “为了防止用户选 Off 导致 400 Bad Request，必须增加 `mandatory: true` 并在 UI 物理剔除 Off”。

甚至在代码校验层写出了如下防御逻辑：
```rust
// 摘自 03-AgentC 校验逻辑
if spec.mandatory && spec.levels.get(&ModelThinkingLevel::Off).is_some() {
    return Err("Mandatory model cannot define off level wire string");
}
```

#### 2. 根因穿透：为什么 `mandatory` 是个彻头彻尾的伪概念？
从纯逻辑与集合论（Set Theory）的视角审视：
- 一个模型支持哪些档位，在物理世界中是一个**离散集合 $S \subseteq \{\text{Off}, \text{Low}, \text{Medium}, \text{High}, \text{Max}\}$**。
- 如果模型原生常开思考且无法关闭（例如 DeepSeek V4 Pro 或 o3-pro），其物理支持集合就是 $S = \{\text{Low}, \text{Medium}, \text{High}\}$。在这个集合中，**$\text{Off} \notin S$**。
- 既然集合里根本没有 $\text{Off}$，UI 根据集合渲染选项时自然就不会渲染 $\text{Off}$！
- **为什么还要画蛇添足地在外面包一个 `mandatory: true`？**
  - 这好比一个电风扇只有 1 档、2 档、3 档，没有 0 档（拔插头才停）。我们只需要标明其档位是 `[1, 2, 3]`，而不需要写 `gears: [1, 2, 3], mandatory_running: true`！
  - 既有设计先搞了一个全集，再搞一个 `levels` 映射，最后又搞了一个 `mandatory` 布尔值来“二次修正”集合，导致同一件事有了三个不同的表达途径，严重违反了《反过度设计硬性红线指南》**禁令 7：保证单一真相源（Single Source of Truth, SSOT）**。

#### 3. 认知负担危害：
- **对于终端用户与运维人员**：每次在 `models.yaml` 增加或修改一个模型时，必须去查阅各大厂商长达数页的 API 规范，确认该模型“到底是可选思考还是强制思考”，然后再艰难决定 `mandatory` 是填 `true` 还是 `false`。这平白增加了巨大的心理负担。
- **对于系统开发者**：在 Rust 内核、IPC 传输、前端 Store、UI 渲染组件中，处处要写 `isMandatory = spec.mandatory || levels["off"] === null`，代码充斥双重判定，为潜在的逻辑漂移和 Bug 埋下了温床。

### 1.2 罪状二：`defaultLevel` 静态绑架交互的认知噪音

#### 1. 现象复盘：为什么 YAML 里塞满了 `defaultLevel: "medium"`？
在 `00-总纲`、`02-AgentB`、`03-AgentC` 中，几乎每一个思考模型的 YAML 配置样例都强制带有：
```yaml
thinking:
  enabled: true
  mandatory: false
  defaultLevel: "medium"
  levels: ...
```
在 Rust 中更定义了 `default_level: ThinkingLevel` 并附带 `default = "default_thinking_level"`。

#### 2. 根因穿透：为什么静态 `defaultLevel` 既无必要又有害？
大模型的思考强度不是静态的，而是**强烈的交互驱动型（Interaction-Driven）与任务驱动型（Task-Driven）状态**。

- **危害 1：粗暴打断用户的连续交互体验**
  设想场景：用户正在处理一个极高难度的算法竞赛题，在输入框中明确将思考胶囊切到了 `High`（高强度推理）。当用户在测试不同模型的效果，将模型从 `deepseek-v4-flash` 切换到 `gpt-5.6-sol` 时，由于每个模型配置里都硬生生写了 `defaultLevel: "medium"`，系统立刻把用户的选择强行从 `High` 降级为 `Medium`！用户每次切模型，都必须重新去点一次胶囊，交互体验极其沮丧与反智。
- **危害 2：无谓的配置膨胀与“填空强迫症”**
  系统拥有成百上千个模型。在每一个模型下面复制粘贴 `defaultLevel: "medium"`，不仅制造了海量毫无信息量的代码垃圾，还逼迫用户去思考“这个模型我该给它定什么默认档位”。
- **危害 3：与前端自愈状态机严重冲突**
  若 YAML 中配置了 `defaultLevel: "xhigh"`，但该模型在 `levels` 中根本不支持 `xhigh`，系统又不得不编写长达几十行的“默认值降级搜寻算法”来兜底。这纯粹是自己制造问题再自己打补丁！

**结论**：默认思考强度在静态配置中完全没有必要！激活档位应当由**前端用户的交互操作实时驱动，并基于当前模型的支持集合进行就近自愈对齐**。

### 1.3 罪状三：三态嵌套映射（`Option<Option<String>>`）的类型污染与过度抽象

#### 1. 现象复盘：工业级标杆的机械搬运后遗症
`@earendil-works/pi-ai` 作为 Node.js 生态的 CLI 框架，其 TS 类型定义如下：
```typescript
export type ThinkingLevelMap = Partial<Record<ModelThinkingLevel, string | null>>;
```
在 TS 中，`null` 语义较为灵活。但 `02-AgentB` 将其机械搬入 Rust 强类型系统后，演变成了令人毛骨悚然的结构：
```rust
pub struct ThinkingLevelMap {
    pub off: Option<Option<String>>,
    pub low: Option<Option<String>>,
    pub medium: Option<Option<String>>,
    pub high: Option<Option<String>>,
    ...
}
```
在代码中充斥着嵌套匹配：
```rust
match spec.levels.get(&level) {
    Some(Some(wire)) => ..., // 支持且自定义
    Some(None) => ...,       // 显式禁用
    None => ...,             // 缺省回退
}
```

#### 2. 根因穿透：
这是典型的**“把运行时的动态推断推卸给静态反序列化”**。
- 为了表达“不支持”，不仅要写键名，还要将其赋值为 `null`；
- 在 YAML 中写出 `off: null`、`max: null`，极其不自然；
- 事实上，如果一个模型支持某档位，且该档位发给 API 的就是标准英文名称（如 OpenAI、Anthropic、Google 均直接接收 `"low"`, `"medium"`, `"high"`），为什么不能直接用一个简单明了的字符串数组 `levels: ["Off", "Low", "Medium", "High"]`？
- 只有极少数模型需要特殊的底层 Wire 参数时，才需要键值映射。用最繁杂的三态嵌套作为全系统的底座，完全违反了软件工程的奥卡姆剃刀原则（如无必要，勿增实体）。

### 2.1 “支持即存在，不支持即消失”的投影原则

在纯能力投影哲学下：
1. **支持即存在**：模型支持哪些档位，就在 `levels` 中声明哪些档位。
   - 例：模型 A 既能关闭又能分级思考：`levels: ["Off", "Low", "Medium", "High"]`
   - 例：模型 B 原生强制思考，不可关闭：`levels: ["Low", "Medium", "High"]`（无需写 `mandatory`，因为没有 `Off`，系统就知道不能关闭）
   - 例：模型 C 为二元思考（仅开/关）：`levels: ["Off", "Medium"]`
2. **不支持即消失**：
   - 如果一个档位不在 `levels` 列表中，它在 UI 上就**物理不渲染、不存在、不可选**；
   - 如果一个模型根本不具备思考能力（如纯文本模型、生图模型），则在配置中**彻底不声明 `thinking` 节点（或设为 null/空列表）**。输入框下方的思考胶囊将**100% 物理折叠隐藏**，不占用任何界面像素，零视觉噪音。

---

### 2.2 动静解耦：静态事实（Static Facts） vs 交互运行时（Interactive Runtime）

我们彻底划分配置与运行时的神圣边界：
- **静态配置 (`models.yaml`) 只负责声明客观事实 (Objective Facts)**：
  - 事实 1：模型有没有思考能力？
  - 事实 2：模型支持哪些英文档位？
  - 事实 3：（可选）是否需要特殊方言映射？
  - **严禁声明任何主观意图**：严禁写 `mandatory`（这是对客观事实的重复包装），严禁写 `defaultLevel`（这是静态僭越了动态交互）。
- **交互运行时 (UI & Engine) 负责承载主观意图 (Subjective Intent)**：
  - 用户当前的思考倾向是全局偏好或会话级状态（如“我当前希望高强度推理”）；
  - 运行时根据客观事实集合，将主观意图映射到当前模型支持的最佳档位上；
  - 切换模型时，意图平滑保持，只有在客观事实不支持时，由前端状态机完成**智能就近对齐（Natural Alignment）**。

---

### 2.3 零心智负担原则（Zero Cognitive Overhead Rules）

1. **零样板（Zero Boilerplate）**：新接入一个支持全档位思考的标准模型，YAML 中只需写 `levels: ["Off", "Low", "Medium", "High"]`，无需任何附加开关。
2. **零歧义（Zero Ambiguity）**：不存在“`mandatory: true` 但列表里有 `Off`”的冲突，不存在“默认档位在可用列表之外”的荒谬状态。
3. **零误操作（Zero Misoperation）**：不支持关闭的模型绝不出现 Off 选项，用户在物理交互上不可能误触引发 API 400 报错。
4. **零感知切换（Zero Friction Switching）**：切换同类型模型时，思考强度自然继承，无需用户反复重新点击设定。

```rust
use serde::{Deserialize, Serialize};
use std::collections::HashMap;

/// ============================================================================
/// 1. 标准纯英文 5 档核心枚举 (TitleCase / 纯英文，兼具直观与严谨)
/// ============================================================================
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum ThinkingLevel {
    #[serde(rename = "Off", alias = "off")]
    Off,
    #[serde(rename = "Low", alias = "low")]
    Low,
    #[serde(rename = "Medium", alias = "medium")]
    Medium,
    #[serde(rename = "High", alias = "high")]
    High,
    #[serde(rename = "Max", alias = "max")]
    Max,
}

impl ThinkingLevel {
    /// 转换为展示标签（纯英文，人体工学大写）
    pub fn as_str(&self) -> &'static str {
        match self {
            Self::Off => "Off",
            Self::Low => "Low",
            Self::Medium => "Medium",
            Self::High => "High",
            Self::Max => "Max",
        }
    }

    /// 转换为标准 Wire 参数小写字符串
    pub fn as_wire_str(&self) -> &'static str {
        match self {
            Self::Off => "off",
            Self::Low => "low",
            Self::Medium => "medium",
            Self::High => "high",
            Self::Max => "max",
        }
    }

    /// 排序权重，用于档位就近降级对齐算法 (0 为 Off, 4 为 Max)
    pub fn rank(&self) -> u8 {
        match self {
            Self::Off => 0,
            Self::Low => 1,
            Self::Medium => 2,
            Self::High => 3,
            Self::Max => 4,
        }
    }
}

/// ============================================================================
/// 2. 极简思考能力规范 (ThinkingSpec)
/// ============================================================================
/// 彻底删除 enabled, mandatory, defaultLevel 伪概念！
/// 模型支持什么档位，levels 里就有什么档位；模型若不支持思考，整个 ThinkingSpec 为 None。
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[serde(untagged)]
pub enum ThinkingSpec {
    /// 极简形式：纯标准英文档位列表（满足 95% 现代模型需求，直接在 YAML 写 [Off, Low, Medium, High]）
    Simple(Vec<ThinkingLevel>),

    /// 进阶形式：支持自定义 Wire 参数映射（仅针对上游 API 采用奇次方言的极少数第三方网关）
    Advanced {
        /// 支持的档位及其映射到的 Wire 字符串
        levels: HashMap<ThinkingLevel, String>,
    },
}

impl ThinkingSpec {
    /// 快速提取当前模型所支持的全部可用档位（已保序并去重）
    pub fn supported_levels(&self) -> Vec<ThinkingLevel> {
        let mut list = match self {
            Self::Simple(vec) => vec.clone(),
            Self::Advanced { levels } => levels.keys().copied().collect(),
        };
        list.sort_by_key(|a| a.rank());
        list.dedup();
        list
    }

    /// 判定当前模型是否支持关闭思考 (Off)
    /// 纯集合运算：集合包含 Off 则支持关闭，不包含则为强制思考！
    pub fn supports_off(&self) -> bool {
        self.supported_levels().contains(&ThinkingLevel::Off)
    }

    /// 决议特定档位发往上游 API 的真实 Wire 字符串
    pub fn resolve_wire_value(&self, level: ThinkingLevel) -> Option<String> {
        match self {
            Self::Simple(vec) => {
                if vec.contains(&level) {
                    Some(level.as_wire_str().to_string())
                } else {
                    None
                }
            }
            Self::Advanced { levels } => levels.get(&level).cloned(),
        }
    }
}

/// ============================================================================
/// 3. 单模型规范 (ModelSpec) 中思考节点的轻量挂载
/// ============================================================================
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct ModelSpec {
    pub id: String,

    #[serde(skip_serializing_if = "Option::is_none")]
    pub display_name: Option<String>,

    #[serde(default = "default_context_window")]
    pub context_window: u64,

    #[serde(default = "default_max_output_tokens")]
    pub max_output_tokens: u64,

    /// 思考能力配置：Option<ThinkingSpec>
    /// 若为 None，代表非思考模型，前端 100% 折叠思考胶囊，内核跳过任何思考参数拼接！
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub thinking: Option<ThinkingSpec>,
}

fn default_context_window() -> u64 { 128_000 }
fn default_max_output_tokens() -> u64 { 16_384 }
```

本章节详述纯交互驱动的核心状态机。

### 4.1 用户意图保持法则（User Intent Continuity）

用户在桌面端进行多轮对话或切换模型时，其心理意图具有强烈的**时间局部性与惯性（Locality & Inertia）**：
1. **意图延续性**：如果用户当前任务需要深度推理，用户将胶囊点到了 `High`。用户换一个同样支持推理的模型继续提问时，用户的核心意图依然是 `High`。系统必须优先**保持用户的意图，而不是粗暴重置**！
2. **就近自愈性**：如果用户切换到的新模型不支持 `High`（例如新模型最高只支持 `Medium`），系统不报错、不弹窗，而是**自然顺滑地对齐到新模型支持的最高档位（就近向下投影）**。
3. **沉睡与唤醒**：如果用户临时切到了一个纯文本模型（无思考），思考胶囊瞬间折叠隐藏，界面清爽；但用户的思考意图在内存中**沉睡**。当用户稍后切回思考模型时，胶囊重新展开，并**瞬间唤醒恢复用户此前的思考强度**！

### 4.3 UI 胶囊交互逻辑与 React Hook 工业级实现

落地代码：`apps/crish-desktop/src/hooks/useThinkingCapsule.ts`。

```typescript
import { useMemo, useCallback } from "react";
import { ModelSpec, ThinkingLevel, getSupportedThinkingLevels } from "@conex/types";
import { useSessionStore } from "@/stores/sessionStore";

export interface ThinkingCapsuleState {
  /** 胶囊是否可见（非思考模型为 false，物理不渲染） */
  visible: boolean;
  /** 当前模型真实支持的纯英文档位列表（已剔除不支持项） */
  availableLevels: ThinkingLevel[];
  /** 当前生效的激活档位 */
  activeLevel: ThinkingLevel;
  /** 切换档位交互回调 */
  onSelectLevel: (level: ThinkingLevel) => void;
}

/** 档位排序权重表 */
const LEVEL_RANK: Record<ThinkingLevel, number> = {
  Off: 0,
  Low: 1,
  Medium: 2,
  High: 3,
  Max: 4,
};

/**
 * 纯交互驱动的思考胶囊 Hook
 * 零配置默认档位、零 mandatory 概念，全自动自愈与意图延续
 */
export function useThinkingCapsule(currentModel: ModelSpec | null | undefined): ThinkingCapsuleState {
  // 从会话 Store 中读取用户主观选定的思考意图（跨模型记忆）
  const userIntent = useSessionStore((s) => s.preferredThinkingLevel);
  const setUserIntent = useSessionStore((s) => s.setPreferredThinkingLevel);

  // 1. 纯能力投影：获取当前模型支持的所有合法档位
  const availableLevels = useMemo(() => {
    const list = getSupportedThinkingLevels(currentModel?.thinking);
    return list.sort((a, b) => LEVEL_RANK[a] - LEVEL_RANK[b]);
  }, [currentModel?.thinking]);

  // 2. 物理可见性：仅当可用档位大于等于 1 个且非纯 Off 时可见
  // 若列表为空，彻底折叠隐藏
  const visible = availableLevels.length > 0;

  // 3. 纯函数就近自愈算法 (Natural Alignment)
  const activeLevel = useMemo<ThinkingLevel>(() => {
    if (!visible) return "Off";

    // 场景 A：用户的历史意图在当前模型支持集合中，直接命中！
    if (userIntent && availableLevels.includes(userIntent)) {
      return userIntent;
    }

    // 场景 B：用户此前选了 Off，但当前模型不支持 Off（即常开模型）
    // 自然就近对齐到集合中的第一个非 Off 档位（通常是 Low 或首项）
    if (userIntent === "Off" && !availableLevels.includes("Off")) {
      const nonOff = availableLevels.find((lvl) => lvl !== "Off");
      return nonOff ?? availableLevels[0];
    }

    // 场景 C：用户此前的档位过高（如 Max），新模型不支持
    // 向下搜寻最接近的最高支持档位
    if (userIntent) {
      const targetRank = LEVEL_RANK[userIntent];
      const lowerOrEqual = availableLevels.filter((lvl) => LEVEL_RANK[lvl] <= targetRank);
      if (lowerOrEqual.length > 0) {
        return lowerOrEqual[lowerOrEqual.length - 1];
      }
    }

    // 场景 D：初次使用无记忆，自然寻找 Medium（黄金中位数），若无则取首个
    if (availableLevels.includes("Medium")) {
      return "Medium";
    }
    return availableLevels[0];
  }, [visible, availableLevels, userIntent]);

  // 4. 用户交互切换
  const onSelectLevel = useCallback(
    (level: ThinkingLevel) => {
      if (availableLevels.includes(level)) {
        setUserIntent(level);
      }
    },
    [availableLevels, setUserIntent]
  );

  return {
    visible,
    availableLevels,
    activeLevel,
    onSelectLevel,
  };
}
```

### 5.3 内核请求体序列化单向纯函数实现

落地代码：`crates/session-loop/src/thinking_wire.rs`。

```rust
use crate::catalog_types::ThinkingLevel;
use serde_json::{json, Map, Value};

/// 思考协议方言标识
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ThinkingFormat {
    OpenAi,
    DeepSeek,
    Qwen,
    Anthropic,
    Google,
    OpenRouter,
    Zai,
    Together,
    Baseten,
    ChatTemplate,
    AntLing,
}

/// 核心注入纯函数：将用户选定的思考强度无损转译并注入到 JSON 请求体中
pub fn inject_thinking_to_payload(
    payload: &mut Map<String, Value>,
    format: ThinkingFormat,
    level: ThinkingLevel,
) {
    // 1. 若为 Off，执行安全清除/关闭逻辑
    if level == ThinkingLevel::Off {
        match format {
            ThinkingFormat::Anthropic => {
                payload.insert("thinking".to_string(), json!({ "type": "disabled" }));
            }
            ThinkingFormat::Google => {
                let gen_config = payload.entry("generationConfig").or_insert_with(|| json!({}));
                if let Some(obj) = gen_config.as_object_mut() {
                    obj.insert("thinkingConfig".to_string(), json!({ "thinkingLevel": "OFF" }));
                }
            }
            _ => {
                // 其余方言（OpenAI, DeepSeek, Qwen 等）直接移除或不注入思考字段
                payload.remove("reasoning_effort");
                payload.remove("thinking");
                payload.remove("enable_thinking");
                payload.remove("reasoning");
            }
        }
        return;
    }

    // 2. 非 Off 档位：按方言注入标准化参数
    let wire_str = level.as_wire_str();

    match format {
        ThinkingFormat::OpenAi => {
            payload.insert("reasoning_effort".to_string(), json!(wire_str));
        }
        ThinkingFormat::DeepSeek => {
            payload.insert("thinking".to_string(), json!({ "type": "enabled" }));
            // DeepSeek 同时兼容可选的 reasoning_effort
            payload.insert("reasoning_effort".to_string(), json!(wire_str));
        }
        ThinkingFormat::Qwen => {
            payload.insert("enable_thinking".to_string(), json!(true));
        }
        ThinkingFormat::Anthropic => {
            payload.insert("thinking".to_string(), json!({ "type": "adaptive" }));
            payload.insert("output_config".to_string(), json!({ "effort": wire_str }));
        }
        ThinkingFormat::Google => {
            let google_level = match level {
                ThinkingLevel::Low => "LOW",
                ThinkingLevel::Medium => "MEDIUM",
                ThinkingLevel::High | ThinkingLevel::Max => "HIGH",
                ThinkingLevel::Off => unreachable!(),
            };
            let gen_config = payload.entry("generationConfig").or_insert_with(|| json!({}));
            if let Some(obj) = gen_config.as_object_mut() {
                obj.insert(
                    "thinkingConfig".to_string(),
                    json!({ "thinkingLevel": google_level }),
                );
            }
        }
        ThinkingFormat::OpenRouter | ThinkingFormat::AntLing => {
            payload.insert("reasoning".to_string(), json!({ "effort": wire_str }));
        }
        ThinkingFormat::Zai => {
            payload.insert("thinking".to_string(), json!({ "type": "enabled" }));
        }
        ThinkingFormat::Together => {
            payload.insert("reasoning".to_string(), json!({ "enabled": true }));
        }
        ThinkingFormat::Baseten => {
            payload.insert("chat_template_args".to_string(), json!({ "thinking": true }));
        }
        ThinkingFormat::ChatTemplate => {
            payload.insert("chat_template_kwargs".to_string(), json!({ "thinking": true }));
        }
    }
}
```

### 6.1 `models.yaml` 自动化瘦身清洗管道

当 Rust 内核读取到包含旧格式的 YAML 文件时，自动执行如下**无损降级与清洗管道**：

```rust
// 伪代码：旧数据结构自动归一化管道
pub fn sanitize_legacy_thinking_spec(raw_yaml: &serde_yaml::Value) -> Option<ThinkingSpec> {
    let thinking_node = raw_yaml.get("thinking")?;

    // 1. 若本身已经是极简数组形式，直接反序列化
    if thinking_node.is_sequence() {
        return serde_yaml::from_value(thinking_node.clone()).ok();
    }

    // 2. 处理历史遗留的对象形式
    if let Some(obj) = thinking_node.as_mapping() {
        // 若显式声明了 enabled: false，直接判定为不支持思考 (None)
        if let Some(enabled) = obj.get(&serde_yaml::Value::String("enabled".to_string())) {
            if enabled.as_bool() == Some(false) {
                return None;
            }
        }

        let is_mandatory = obj
            .get(&serde_yaml::Value::String("mandatory".to_string()))
            .and_then(|v| v.as_bool())
            .unwrap_or(false);

        let mut levels = Vec::new();

        // 解析旧 levels 映射
        if let Some(levels_node) = obj.get(&serde_yaml::Value::String("levels".to_string())) {
            if let Some(levels_map) = levels_node.as_mapping() {
                for (k, v) in levels_map {
                    if let Some(k_str) = k.as_str() {
                        // 若旧字段值为 null，代表不支持
                        if v.is_null() {
                            continue;
                        }
                        if let Ok(lvl) = serde_yaml::from_str::<ThinkingLevel>(k_str) {
                            levels.push(lvl);
                        }
                    }
                }
            }
        }

        // 若历史标记了 mandatory: true，强制剔除 Off
        if is_mandatory {
            levels.retain(|l| *l != ThinkingLevel::Off);
        }

        // 若未解析出任何有效档位，回退至基础档位
        if levels.is_empty() {
            levels = if is_mandatory {
                vec![ThinkingLevel::Low, ThinkingLevel::Medium, ThinkingLevel::High]
            } else {
                vec![ThinkingLevel::Off, ThinkingLevel::Low, ThinkingLevel::Medium, ThinkingLevel::High]
            };
        }

        levels.sort_by_key(|l| l.rank());
        levels.dedup();
        return Some(ThinkingSpec::Simple(levels));
    }

    None
}
```

### 8.1 核心审计结论精要
