### 3.2 色

**半（拦截）+ 断（出站图像）。**

- 通：纯文本模型 + 正则命中 `NON_VISION`（如 `deepseek-chat`）+ 带图 → 预检 abort，不再像 Wave 4 前那样 toast 后继续发。  
- 半：catalog store 常空（A 链不写 YAML + 读路径丢 modalities）→ 掉到 LS meta；meta 无 `modalities` → **正则 fail-open**。用户在抽屉去掉 image 的 `gpt-4o` 仍会被 `VISION_MODEL_PATTERNS` 判 true（`modelVisionSupport.ts:27-31`）。  
- 断：`supports_image_input` 不在生产拦截面上。  
- 断：即便前端放行，`image_url` 到不了 provider HTTP body。

纯文本传图会不会静默出站？

| 模型 | 前端 | Rust | 实际出站 |
| ---- | ---- | ---- | -------- |
| `deepseek-chat` + 图 | 正则 false → abort | 不参与 | **不发**（前端挡住） |
| 自定义纯文本、无 meta.modalities、名字不含 vl/vision | `isModelVisionSupported` 默认 false → abort | 不参与 | **不发** |
| `gpt-4o` 但用户 YAML/抽屉关掉 image | 正则 true → **放行** | 无拦截 | 发 **文本备注**，图字节仍丢 |
| 任意视觉模型 + 图 | 放行 | 无拦截 | 同上，**结构化图断** |

「静默出站 image_url 打纯文本 API 400」这条 Wave 4 前的主事故，被前端 abort **部分**堵住；换成「视觉模型也发不出图」+「抽屉关视觉挡不住正则放行」。

### 3.3 断点

1. 双轨：store 优先，失败 fallback meta，再 fallback 正则（`slashSendPreflight.ts:61-78` + `modelVisionSupport.ts:100-129`）。store 空是产品默认（A 断）。  
2. `utils/multimodal.ts` 8 行重导出，**全仓零 import**（产品守卫在 `hooks/chat-stream/multimodal.ts`）。  
3. `RunTaskOptions` 无多模态字段（`run_launch.rs:209-249`）。  
4. `supports_image_input` 仅测。  
5. `parse_yaml_to_catalog` 的 `DynamicYamlModalities` 是 `image/video/audio: bool`（`catalog.rs:751-759`），与 YAML 一等公民 `{ input: ["text","image"], output: ["text"] }` **字段形状不兼容**；即便 `live_catalog` 被读，vision 位也接不上 v2 modalities。
