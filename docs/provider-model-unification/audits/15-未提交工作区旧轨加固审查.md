## 3. 任务问答（六问六答）

### 3.1 树状契约接到 `models.yaml` 新轨，还是写进 LocalStorage `ModelMeta`？

**写进 LocalStorage `ModelMeta`，同时在旧类型文件里复制一份 yaml 形状的「纸面契约」。**

证据链：

- 运行时写入：`setModelModalities` / `setModelThinking` / `setModelPricing` → `upsertModelMeta` → `saveMap` → `localStorage.setItem('crish_model_meta_v1', …)`（`modelCatalogMeta.ts:14,74-82,176-193,319-355`）。
- 设置保存仍走旧岛：`useModelConfigSession.ts:186` `applyMetaForModel(...)`；`useModelProfilesState.ts:320` 手动加模型同样 `applyMetaForModel`。`applyMetaForModel`（HEAD 已存在、本批未改）调用的正是这批新 setter（`modelsIpcHelpers.ts:99-157`）。
- 新轨写路径 `modelsCatalogStore.updateModel` / `serializeModelsYamlTree` / `workbench_save_models_yaml`：**本批零 diff**。
- 后半段 `ModelsYamlTree` / `ReadModelsYamlWire` 只是类型声明，没有任何模块改去消费它们写盘。`modelCatalog.ts` 甚至不 re-export 这些新类型。

### 3.2 `modelCatalogMeta.ts` +51 是否把 modalities/thinking/pricing persist 进 `crish_model_meta_v1`？

**是。这会把「统一体系」重新嵌进旧岛。**

`upsertModelMeta` 的 patch 白名单从

`enabled | contextLength | maxOutputTokens | lastTest | displayName | capabilities | defaultThinkingLevel | protocol`

扩为再含 `modalities | thinking | pricing`。三个新 setter 没有旁路、没有 yaml adapter、没有「仅内存」。`getModelMeta` 读回的就是这份 LS map。

副作用：`upsertModelMeta` 先 `const prev = getModelMeta(...)`（`modelCatalogMeta.ts:198`）。`getModelMeta` 对缺省 `contextLength` 会填 `guessContextLength(model)`（`modelCatalogMeta.ts:162,169`）。因此**任意一次** `setModelModalities` / `setModelThinking` / `setModelPricing` 都会把 autofill 猜到的窗口**物化进** `crish_model_meta_v1`，即使用户没改上下文。旧岛不仅续命，还会被新 setter 主动灌数据。

### 3.3 新类型是否与 `modelsCatalogTypes.ts` / `catalog_types.rs` 重复定义？协议是否再引入 `google/interactions` 并与内核不一致？

**是，三轨类型；协议比新轨还退步。**

HEAD 已提交新轨 `apps/crish-desktop/src/api/modelsCatalogTypes.ts`（`ModelProtocol` 含 `google/generate-content` **以及** 别名 `google/interactions`）。本批在旧文件再定义同名 `ModelProtocol` / `ModelSpec` / `ProviderSpec` / `ModelsYamlTree` / `ModelPricingSpec` / `ThinkingLevelTitle` 等。

| Google 协议 | **仅** `'google/interactions'`（`modelCatalogTypes.ts:148-152`） | `'google/generate-content'` + `'google/interactions'`（`modelsCatalogTypes.ts:11-16`） | 规范名 `google/generate-content`，**serde alias** `google/interactions`（`catalog_types.rs:109-111`）；`as_str()` 只返回 generate-content（`catalog_types.rs:127`） | **只有** `google/generate-content`，**无 alias**（`models_yaml.rs:29-38`），且父结构 `deny_unknown_fields` |

## 4. 与已提交 Wave 4 / BATCH-UNIFY-04 的冲突

1. **编译缺口被错误补法**：HEAD 设置层与预填库已经按新名字 import，但指向旧文件。正确收口是改 import 到 `modelsCatalogTypes.ts`，并把 `applyMetaForModel` 改接到 `modelsCatalogStore.updateModel`。本批选择在旧文件**造齐符号**，把缺口变成旧轨 API。
2. **与 Wave 3 门禁对撞**：总案要求清除 LS 双轨、拔除 `KNOWN_CONTEXT`。本批只做了后半句的一半（`guessContextLength` 改读预填），前半句反着做（LS 字段变多）。
3. **与已提交新轨文件对撞**：`modelsCatalogTypes.ts` / `modelsCatalogActions.ts` / `modelsCatalogIpc.ts` 已是 yaml 树的 TS 镜像。同名 `ModelSpec` 再出现在 `modelCatalogTypes.ts`，预填库绑旧、Store/Actions 绑新，结构兼容但协议枚举与定价必填性不一致，属于静默分叉。
4. **与内核磁盘 schema 对撞**：`models_yaml.rs:29-38` 不认 `google/interactions` 为规范变体。新轨 IPC 已做归一化；旧岛类型把 interactions 当成**唯一** Google 值，堵住了正确归一。
5. **价格三写**：同一 `applyMetaForModel` 在 HEAD 已 `upsertPrice`（`modelsIpcHelpers.ts:148-155`）；本批再 `setModelPricing` 写入 meta。yaml 仍是第三套。Wave 4「价格未填优雅静默」若只看 UI，LS 里已经留下 `currency: 'USD'` 的残对象。
6. **思考双字段**：新 `thinking` map 与旧 `defaultThinkingLevel` 并存（`ComposerFusedTrigger.tsx` 仍 `setModelThinkingLevel`）。yaml schema 没有 defaultLevel。本批把拍平 map 放进 LS，并不删除旧档位，认知负担与双写继续。
