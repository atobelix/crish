## 一、结论先行

1. **Wave 4（`f98b7f62`）对 `devil_cases_tests.rs` 的净 -780 行是去掉测试替身，不是卸门禁。** 28 个 `#[test]` 函数全部保留；删掉的是 Wave 3 内联复制的 `pub mod pricing` / `pub mod models_config` / `pub mod migration`（约 630 行实现替身）。计费 / 迁移 / 协议继承类用例现已 `use agent_provider::…` 直连生产模块。
2. **替身未清零。** 文件头仍写「100% 直连生产模块」，但 Case 13 仍在测试文件内实现名为 `ArcSwap` 的 `RwLock` 包装；Case 14–17 / 20 / 21 / 23 / 25 仍是测试体内本地算术或 `json!` 手搓，不调用生产函数。
3. **单测绿 ≠ 全线打通。** `PricingEngine::calculate_cost` 在 `crates/session-loop` 与 `apps/` **零生产调用**；`assemble_thinking_dialect` 虽已写入 `build_chat.rs`，但宿主 `engine_provider.rs` **从不填充** `thinking_map` / `thinking_format`，生产 chat 路径恒走 OpenAiEffort 兜底。`ModelConfigPanel` 的「保存」测试只断言按钮在 DOM，生产 `saveConfig` 仍写 `crish_model_meta_v1` LocalStorage，不写 `models.yaml`。
4. **计划承诺的前端魔鬼套件从未落地**：`apps/crish-desktop/tests/integration/devil_cases.test.ts` **不存在**；`models_unification_tests.rs` **不存在**。28 个 Rust 魔鬼用例全绿，抬不起「全线打通」关账。
5. **陪葬测试活着会挡住删旧轨。** `modelCatalogMeta.test.ts` 等仍把 `crish_model_meta_v1` 当契约钉死；设置面板保存路径仍走该键。旧轨测试全绿 = 旧轨「还有人用」的假证据。
