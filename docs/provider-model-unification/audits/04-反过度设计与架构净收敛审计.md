## 一、审计背景、法定审查基准与核心用户指示

### 1.1 审计使命与“架构净收敛”核心哲学

在经历前一轮 5 位架构专家的大体量专项方案分析（`01-AgentA` 至 `05-AgentE`）后，方案呈现出显著的**“军备竞赛式过度设计”**倾向：各详案为了在形式上满足千行硬指标、对标所谓工业级全景理论，引入了极其繁琐的状态机、多级回退链、黑魔法式的三态语义映射以及在单机桌面环境下毫无立足之地的伪共识合并算法。

**架构净收敛（Architecture Net Convergence）的核心哲学**要求：
1. **单一真理路径（Single Source of Truth, SSOT）**：一个核心概念在全系统生命周期内只能存在唯一表达，严禁“主字段 A”与“字典特殊值 B”并存表达同一个语义；
2. **零假设与零臆想防御**：不为 0.01% 未经验证的极端臆想场景编写重型调度框架、拦截器与回退链条；
3. **彻底尊重人机认知工效**：系统绝对不应把供应商底层 API 的死板限制转化为主观限制强加给开发者，更不能在前端制造层层锁死和视觉噪音；
4. **穿透根因，杜绝“以抽象掩盖抽象”**：去除套娃式策略工厂、伪三向合流引擎与命令执行器，用原生语言（Rust / TypeScript）最直白、最扁平的数据结构和确定性函数解决问题。

### 1.3 用户最高指示：“强制思考不用管，默认思考强度没必要”

在需求论证与方案评审过程中，用户针对思考推理参数给出了决定性裁决：
> **“强制思考这个不用管，加上这个还多一个认知负担。默认思考强度也没有必要。”**

这一最高指示直接切中了前一轮设计的命门。各详案为了拟合所谓工业级模型“强制推理”的特性，生造出了大量的复杂度：
- 增加了 `mandatory: bool` 字段，又发明了 `"off": null` 的语义双关；
- 前端设计了“强制思考锁态”UI（黄色小锁头、禁用 Off 选项、悬浮告警）；
- 后端编写了用户选 Off 时的“自动拦截与纠偏器（Auto-correct）”；
- 增加了 `defaultLevel` 默认强度推导器，在模型切换时触发连锁重置。

**结论明确：全是一厢情愿的过度工程！** 用户的思考强度诉求极其直白：提供一个干净的菜单，用户选什么就发什么；不需要客户端做爹味十足的“强制锁死”与“自动纠偏”，更不需要为每个模型配置冗余的默认强度。

## 二、五大分析详案地毯式反过度设计审查与违规点清算

### 2.1 【01-AgentA 审查】凭据执行命令 RCE 漏洞、探针三向合流与无锁并发膨胀

`01-AgentA-Provider拓扑与内核协议打通详案.md` 作为拓扑方案，确立了 Provider 为第一公民的正确方向，但在防御与并发层出现了严重的技术变形：

#### 违规项 A1：凭据四级流水线引入 `!command` 执行系统 Shell，制造致命 RCE 漏洞
- **详案出处**：第 138-142 行、第 235 行、第 1190-1230 行。
- **违规代码还原**：
  ```rust
  // 详案 01-AgentA 中极度危险的凭据命令执行设计
  if let Some(cmd) = val.strip_prefix('!') {
      let output = tokio::process::Command::new("sh")
          .arg("-c")
          .arg(cmd)
          .output()
          .await?;
      return Ok(String::from_utf8(output.stdout)?.trim().to_string());
  }
  ```
- **触犯红线**：🚫 **禁令 8（多 Provider 凭据零残留与安全隔离）**。
- **危害剖析**：桌面应用不是个人终端脚本环境。一旦恶意的 `models.yaml` 随 Git 仓库被 clone 下来（如针对工作区配置），或者用户从外部导入共享配置，带有 `!powershell -enc ...` 或 `!curl ... | sh` 的配置将直接在宿主机器静默执行，导致系统彻底被黑客控制。
- **净收敛裁决**：**彻底斩除 `!command` 凭据执行通道！** 桌面端只允许读取 OS 原生 DPAPI 钥匙串槽（`vault://`）或只读环境变量（`$ENV`）。

#### 违规项 A2：模型动态探测引入“三向合并（Three-Way Merge）”状态机
- **详案出处**：第 1239-1320 行。
- **违规代码还原**：详案设计了 `ProbedModelRaw`、`MergeReport`、`is_probed: bool`、`stale: bool` 字段，并编写了根据上游返回值智能选择性更新 `contextWindow` 与 `maxOutputTokens` 的算法。

## 三、核心斩断专项深度剖析

### 3.1 专项一：彻底斩断 `mandatory` 强制思考状态机与 `"off": null` 语义双关

#### 3.1.1 详案过度设计深度还原与病态代码剖析

在前一轮方案中，架构师们在强制思考这一伪需求上耗费了大量篇幅：

#### 3.1.2 认知负担与架构破坏性根因分析

1. **认知负担剧增**：开发者使用 AI 辅助编程是为了解决核心工程问题，绝不想被工具强加多余心智负担。界面的黄色小锁、悬浮告警和动态隐藏的选项不仅让人困惑，还极易引发“为什么我的菜单项突然不见了”的系统性报障。
2. **破坏单一真理路径（SSOT）**：同一个“强制思考”概念，既可以用布尔字段表达，又可以用字典中的空值表达，逼迫系统写校验器来防范自身设计的漏洞。
3. **违反反篡改原则（禁令 4）**：后端在暗中拦截用户发出的请求并强行替换为其他参数，违反了透明确定性原则。

#### 3.1.3 极简净化方案：纯粹档位白名单与用户自由选择权

系统对思考能力的理解回归物理本质：
1. **纯粹的档位白名单**：模型要么支持思考（`enabled: true` 并声明支持的英文档位），要么不支持思考（`enabled: false`）；
2. **纯粹的用户自由选择**：只要支持思考，前端胶囊下拉菜单**永远固定包含标准项**：`Off`（关闭思考）以及该模型正向声明的具体档位（如 `Low`, `High`）；
3. **零客户端假拦截**：若用户选 `Off`，请求体直接不附带任何思考参数。如果上游原生端点要求开启思考，上游的错误信息自然会透明抛给用户。客户端绝不自作聪明搞拦截纠偏！

### 3.2 专项二：彻底斩断 `defaultLevel` 默认强度推导器与级联回退状态机

#### 3.2.1 详案过度设计深度还原与病态推导器剖析

详案中为数百个模型配置维护了 `defaultLevel`，并设计了级联推导器：

```typescript
// 【详案 03-AgentC 中的病态推导器还原】
function resolveEffectiveThinking(model: ModelSpec, userSetting?: string) {
  const { mandatory = false, levels = {}, defaultLevel } = model.thinking;
  const isMandatory = mandatory || levels["off"] === null;
  const allowed = Object.keys(levels).filter(k => levels[k] !== null);

  let effectiveLevel = userSetting ?? defaultLevel;
  if (isMandatory && effectiveLevel === "off") {
    effectiveLevel = defaultLevel;
  }
  if (!allowed.includes(effectiveLevel) && effectiveLevel !== "off") {
    effectiveLevel = allowed[0] ?? defaultLevel ?? "off";
  }
  return effectiveLevel;
}
```

#### 3.2.2 状态漂移与渲染副作用级联根因分析

1. **配置膨胀**：每个模型都必须硬编码一行 `defaultLevel`，增加大量视觉杂讯与维护负担；
2. **违背心智模型**：思考强度是用户在特定编码场景下的**工作流状态**（想深思还是想快答），并非模型的固有静态属性。用户切模型并不希望档位被擅自重置；
3. **渲染抖动**：每次切模型都触发 Store 的级联重算与组件全局重绘。

#### 3.2.3 极简净化方案：消除模型级 defaultLevel，系统级单一偏好

1. **从全部 Schema、Store、UI 中彻底删除 `defaultLevel`**；
2. **工作区单一会话记忆**：当前思考档位（`activeThinkingLevel`）完全由用户主动点选决定（初始缺省为 `off`）；
3. **极简有效性校验**：切模型时，若当前档位在新模型支持列表中，则保持不变；若不支持，简单回退为 `off`。零副作用推导！

### 3.3 专项三：彻底斩断探针合流算法（Probe Scan & Three-Way Merge）

#### 3.3.1 详案过度设计深度还原：把单机当分布式数据库合流

详案 01 与 04 中编写了长达 150 行的 `merge_probed_models` 函数，引入了类似 Git 或分布式数据库的三向合并状态机，包含大量深层字段对比与局部覆盖判断。

#### 3.3.2 上游数据残缺导致的数据污染与破坏性风险

现实中上游 `/v1/models` 返回的数据往往极度残缺（通常仅有 `id`，缺乏可信的上下文窗口与定价）。三向合并算法在面对残缺数据时，极易将用户在本地精心配置的 1,048,576 上下文覆盖冲成 4096 默认值，造成灾难性数据污染。

#### 3.3.3 极简净化方案：差集比对与纯增量追加（Set Difference & Append Only）

坚决落实禁令 3 与禁令 7。模型探针功能彻底回归其纯粹本质：
1. **纯只读探测**：获取上游模型 ID 列表；
2. **纯差集筛选**：计算 `new_ids = remote_ids - local_ids`；
3. **用户自主按需追加**：仅将用户勾选的新模型以安全默认模板（128K 上下文、继承 Provider 协议）直接追加至末尾；
4. **零破坏铁律**：**严禁探测逻辑修改或覆写任何既有模型的任何字段！** 彻底删除 `MergeReport`、`is_probed`、`stale` 及三向合并代码。

### 3.4 专项四：彻底斩断不必要的防御层与重度抽象

#### 3.4.1 斩断 `!command` 凭据解析：根除桌面端 RCE 安全灾难，收敛为 OS DPAPI + $ENV + 明文

在桌面 GUI 应用中支持以 `!` 开头执行系统 Shell 命令是不可接受的严重漏洞隐患。
- **收敛方案**：严格收敛为三态解析，绝不派生任何子进程：
  1. `vault://<id>` ➔ 系统原生 Windows DPAPI / Keychain；
  2. `$VAR` / `${VAR}` ➔ 当前进程环境变量读取；
  3. 明文字符串 ➔ 字面量。

#### 3.4.2 斩断阶梯计费（Tiered Pricing Overengineering）：回归四价标准计量与选填静默

05-AgentE 中设计的阶梯计费（`inputTokensAbove`）属于极端小众场景，为系统引入了繁重的微积分式分段算法。
- **收敛方案**：
  - 严格保留极简四价结构：`input`, `output`, `cacheRead`, `cacheWrite`，支持双币 `currency: "USD" | "CNY"`；
  - **价格 100% 选填**：未填价格时系统静默跳过费用计算，UI 彻底隐藏价格胶囊，杜绝显示“$0.00”。

#### 3.4.3 斩断过度微服务化与虚假并发防护（标准 RwLock 取代繁琐 Lock-free 状态机）

将配置热重载收敛为标准 Tokio `RwLock<Arc<RuntimeCatalog>>`，配合 500ms 防抖更新。代码极简、无竞态漏洞。

```rust
    compat: Option<&CompatConfig>,
    level: ThinkingLevel,
    wire_val: Option<&str>,

        return;

        "deepseek" => {
            json_body["thinking"] = serde_json::json!({

                "budget_tokens": serde_json::Value::Null

        }
        _ => {

            json_body["reasoning_effort"] = serde_json::json!(wire_str);
```

```rust
    provider: &mut ProviderSpec,
    discovered_ids: Vec<String>,
) -> usize {
    let existing_ids: HashSet<String> = provider.models.iter().map(|m| m.id.clone()).collect();
    let mut added_count = 0;

    for id in discovered_ids {
        if !existing_ids.contains(&id) {
            let new_model = ModelSpec {
                id: id.clone(),
                display_name: id.clone(), // 默认以 ID 作为展示名
                protocol: None,           // 自动继承 Provider 全局协议
                context_window: 128_000,  // 安全标准默认值
                max_output_tokens: 16_384,
                thinking: ThinkingSpec::default(), // 默认不思考
                pricing: None,            // 选填留空，绝不塞假价格
                enabled: true,
            };
            provider.models.push(new_model);
            added_count += 1;
        }
    }

    added_count
}
```

### 5.6 极简凭据解析流水线（DPAPI + $ENV + Literal）

```rust
//! crates/conex-providers/src/credentials.rs

use crate::vault; // 内部封装 Windows DPAPI / Keychain 调用

pub fn resolve_credential(raw_val: Option<&str>) -> Option<String> {
    let val = raw_val?.trim();
    if val.is_empty() {
        return None;
    }

    // 1. OS 原生安全凭据槽
    if let Some(vault_key) = val.strip_prefix("vault://") {
        return vault::get_secret(vault_key).ok();
    }

    // 2. 只读环境变量插值 (无 Shell 进程派生)
    if val.starts_with('$') {
        let env_var_name = val.trim_start_matches('$').trim_matches(|c| c == '{' || c == '}');
        return std::env::var(env_var_name).ok();
    }

    // 3. 明文字符串字面量兜底
    Some(val.to_string())
}
```
