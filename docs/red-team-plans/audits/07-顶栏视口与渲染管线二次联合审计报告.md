# 二、 36px 沉浸顶栏与外壳几何漏洞审查 (TopBar Chrome & Viewport Shell)

### 【AUDIT-B2-01】AppTopBar macOS 交通灯避让在侧栏折叠时几何坍塌与全屏状态监听漏网

- **涉及文件及精准行号**：
  - `apps/crish-desktop/src/components/top-bar/AppTopBar.tsx:47-60`, `84-88`
- **违反的详案契约条款**：`03 详案` §1.1.2、§1.1.3、§4.1 (断言 1)；`02 修复方案` §3.3 (AUDIT-B-09)
- **代码病理剖析与确凿证据**：
  在 `AppTopBar.tsx` 中，左侧 `rail` 容器的内边距与宽度计算逻辑如下：
  ```tsx
  // apps/crish-desktop/src/components/top-bar/AppTopBar.tsx:84-93
  <div
    className={`${styles.rail} app-top-bar__rail`}
    style={{
      width: sidebarCollapsed ? '36px' : resolvedSidebarWidth,
      minWidth: sidebarCollapsed ? '36px' : resolvedSidebarWidth,
      paddingLeft:
        isMacDesktop && !isFullscreen && !sidebarCollapsed ? 70 : 12,
      marginRight: sidebarCollapsed ? 0 : -16,
      transition: isResizing
        ? 'none'
        : 'width 200ms cubic-bezier(0.16, 1, 0.3, 1), min-width 200ms cubic-bezier(0.16, 1, 0.3, 1)',
    }}
    data-tauri-drag-region
  >
  ```
  **病灶剖析**：
  1. **侧栏折叠时的交通灯穿透与几何重叠**：
     代码中设置了 `!sidebarCollapsed ? 70 : 12`。这意味着在 macOS 桌面端非全屏模式下，当用户将侧栏折叠（`sidebarCollapsed === true`）时，`width` 变为 `36px`，而 `paddingLeft` 被强行降为 `12px`！
     然而，macOS 操作系统原生的红黄绿三色交通灯按钮是**物理常驻在窗口左上角 $X = 0 \sim 70\text{px}$ 区域**的！
     当 `rail` 宽度仅为 36px 且 `paddingLeft` 为 12px 时：
     - 系统交通灯的黄色与绿色按钮（位于 $X \approx 35 \sim 65\text{px}$ 处）将直接物理覆盖在紧随其后的 `app-top-bar__main`（会话标签栏）的首个 Tab 上！
     - 侧栏折叠按钮（`sidebar-toggle`）被挤压在 $X = 12\text{px}$ 处，与系统关闭红灯发生 100% 物理重叠！用户点击折叠按钮时极易误触系统关闭窗口，或被系统交通灯完全吞噬点击事件！
  2. **全屏状态监听在多屏幕与 Space 切换下漏网**：
     在第 51-53 行中，代码仅通过 `win.onResized` 回调同步 `isFullscreen`：
     ```tsx
     unlisten = await win.onResized(async () => {
       setIsFullscreen(await win.isFullscreen());
     });
     ```
     在 macOS 下，通过快捷键 `Cmd + Ctrl + F` 或 Mission Control / Space 漫游进入全屏模式时，窗口可能仅触发 Space 切换与 `tauri://scale-change`，在某些 WebKit/Tauri 运行期不会可靠触发 `onResized`，导致 `isFullscreen` 状态滞后，顶栏保留 70px 巨大空白死区。
- **精确整改建议**：
  macOS 下的避让逻辑必须基于窗口全屏状态与物理几何：当处于 macOS 且非全屏时，顶栏最左侧必须拥有固定的 `>= 70px` 保护区（无论侧栏是否折叠）；侧栏折叠时 `rail` 宽度不得小于 70px，或者将侧栏折叠按钮平移至交通灯右侧（$X = 72\text{px}$ 处），杜绝物理重叠。全屏监听需结合 `window.addEventListener('resize')` 与 Tauri 窗口状态事件。

### 【AUDIT-B2-12】ConexFloatHandle X 轴防遮挡算法逻辑倒置：内嵌时直接覆盖正文首字符，且大代码块/表格垂直位置严重脱靶

- **涉及文件及精准行号**：
  - `apps/crish-desktop/src/components/note-paper/ConexFloatHandle.tsx:87-92`
- **违反的详案契约条款**：`05 详案` §2.2、§3.1 (Task-R02)；`02 修复方案` §3.4 (AUDIT-B-03)
- **代码病理剖析与确凿证据**：
  在 `ConexFloatHandle.tsx` 计算悬浮把手坐标时：
  ```tsx
  // apps/crish-desktop/src/components/note-paper/ConexFloatHandle.tsx:87-92
  const blockRect = hitBlock.getBoundingClientRect();
  const scrollerRect = scroller.getBoundingClientRect();

  const top = blockRect.top - scrollerRect.top + scroller.scrollTop;
  // X 轴几何防遮挡：左侧空间不足 28px 时自动内嵌，绝不覆盖首字符
  const rawLeft = blockRect.left - scrollerRect.left - 28;
  const left = rawLeft < 0 ? blockRect.left - scrollerRect.left + 4 : rawLeft;
  ```
  **病灶剖析**：
  1. **内嵌降级坐标计算完全错误，形成首字符 100% 遮挡**：
     `blockRect.left - scrollerRect.left` 是正文块内容区域的左边界起始点（即文字第一个字符渲染的位置）。
     当左侧边距不足 28px（`rawLeft < 0`）时，代码计算出的 `left` 为 `blockRect.left - scrollerRect.left + 4`！
     把手本身的物理宽度为 24px。把手被放置在从 `+4px` 到 `+28px` 的位置，**恰好 100% 覆盖在正文第一行的前 2~3 个中文字符或英文字母正上方**！这完全违反了「绝不遮挡正文」的设计初衷；
  2. **大尺寸 Markdown 语法块（多行代码块、大表格、嵌套列表）垂直锚定脱靶**：
     `top` 坐标直接取 `blockRect.top`。若文档中存在一个 80 行的代码块或 30 行的大表格（高度达 1500px），当用户在代码块第 50 行（屏幕中间）悬停时，把手依然被死死钉在代码块第 1 行顶部（在屏幕上方 1000px 处，已完全滚出可视视口）！用户在代码块中间悬停时根本看不到把手，造成视觉断层。
- **精确整改建议**：
  1. X 轴防遮挡：当左侧空间不足 28px 时，把手应转换为块顶部悬浮胶囊形态（$Y = \text{blockRect.top} - 26\text{px}, X = \text{blockRect.left}$），或者在正文外部保留固定 28px gutter 占位；
  2. 垂直跟随：对于高度超过视口高度（如 $> 120\text{px}$）的大型 Block，把手的 $Y$ 坐标应根据鼠标指针当前悬停的行（Line / Row）或视口相交区间动态钳位在可视范围内。

### 【AUDIT-B2-14】`useAutoGrowTextarea.ts` 在不支持 field-sizing 环境中 rAF 回流时序滞后导致单帧抖动

- **涉及文件及精准行号**：

- **违反的详案契约条款**：`05 详案` §1.4.1、§1.4.2；`02 修复方案` §3.4 (AUDIT-B-08)
- **代码病理剖析与确凿证据**：
  在 `useAutoGrowTextarea.ts` 的降级实现中：
  ```typescript
  // apps/crish-desktop/src/hooks/useAutoGrowTextarea.ts:51-62
  requestAnimationFrame(() => {
    const cs = getComputedStyle(el);
    const line = resolveComposerLineHeightPx(cs, COMPOSER_LINE_HEIGHT);
    const padY =
      (parseFloat(cs.paddingTop) || 0) + (parseFloat(cs.paddingBottom) || 0);
    const minH = composerMaxHeightPx(line, minLines, padY);
    const maxH = composerMaxHeightPx(line, maxLines, padY);
    const contentH = el.scrollHeight;
    const next = Math.min(Math.max(contentH, minH), maxH);
    el.style.height = `${next}px`;
    el.style.overflowY = contentH > maxH + 1 ? 'auto' : 'hidden';
  });
  ```
  **病灶剖析**：

- **精确整改建议**：
  在降级管线中，使用 `useLayoutEffect` 执行同步高度测量（仅读取 `scrollHeight`，坚决不设 `height = '0px'`），确保 DOM 更新在浏览器 Paint 绘制之前同步完成，消除单帧抖动。
