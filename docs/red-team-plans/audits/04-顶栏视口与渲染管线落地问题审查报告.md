### 【AUDIT-B-01】TerminalCard 异步 PTY 初始化竞态与 IPC 监听器永久泄露

- **涉及文件及精准行号**：`apps/crish-desktop/src/components/workspace/TerminalCard.xterm.tsx:250-403`
- **违反的详案契约条款**：`03 详案` §1.4.1、§3.2 (Task-G07)；`05 详案` §5.2；`AGENTS.md` §7
- **潜在风险/病理剖析**：
  `TerminalCard.xterm.tsx` 中的 `start()` 为大型异步函数，内部包含多处关键 `await` 异步调用（如 `await ptyCreate(...)` 与 `await import(...)` 动态加载 xterm 模块）。
  当用户快速切换会话标签或分屏 Pane 发生快速挂载/卸载时，组件 unmount 会立即触发 cleanup 并将 `cancelled = true`，同时清理当时的 listener 句柄（此时由于异步未完成，listener 尚为 `null`）。
  当挂起的 `start()` 异步恢复执行时，代码**完全忽略了 `cancelled` 标志**，依然继续执行 `subscribePtyOutput(...)` 与 `fitAddon.fit()`，并将 IPC 监听句柄绑定至脱离 DOM 的闭包中。
  这导致底层的 Tauri PTY IPC 监听器无法被注销，xterm 实例与 PTY 进程句柄发生永久性内存泄露；每次快速切标签都会残留幽灵监听器，持续消费底层 PTY 数据流并引发后台隐蔽报错。
- **精确整改建议**：
  在 `start()` 内部的每一个 `await` 恢复点之后立即插入取消守卫：`if (cancelled) { if (createdPtyId) ptyKill(createdPtyId); return; }`；将所有异步注册的订阅句柄加入由 unmount 回调共享的 `activeDisposables` 清理栈中，确保组件在任何生命周期节点注销都能物理注销底层 IPC 监听。

### 【AUDIT-B-02】TerminalCard 尺寸调度未接入 LayoutAnimationStore，残留 Body Class 轮询并引发 IPC 洪峰

- **涉及文件及精准行号**：`apps/crish-desktop/src/components/workspace/TerminalCard.xterm.tsx:420-431`
- **违反的详案契约条款**：`03 详案` §1.4.2、§3.2 (Task-G08)；`05 详案` §1.2
- **潜在风险/病理剖析**：
  `TerminalCard.xterm.tsx` 仍旧通过 `document.body.classList.contains('tree-resizing')` 检查旧版类名，完全脱轨于现代 `layoutAnimationStore` 响应式状态机与 `document.body.dataset.layoutFrozen` 冻结属性。
  在二叉树分屏拖拽、侧栏折叠过渡或全屏布局动画过程中，TerminalCard 无法感知当前的冻结态，依然频繁触发 xterm 的 `ResizeObserver` 回调并执行 `fitAddon.fit()`，向 Rust 内核高频发送 `pty_resize` IPC 请求。这直接破坏了「Zero-JS Layout Resize」原则，导致布局动画发生剧烈掉帧，并造成终端文本重排闪烁。
- **精确整改建议**：
  移除对 `document.body.classList` 的硬编码检查；统一接入 `useLayoutAnimationStore` 或 `ResizeObserverManager.isSuspended()`，在 `layoutAnimationStore.activeAnimations.size > 0` 或 `data-layout-frozen="true"` 时强制挂起 `fitAddon.fit()` 与 `ptyResize` IPC，待 `app:window-resize-settled` 或动画完成事件触发后再执行单次补偿性 `fit()`。

### 【AUDIT-B-05】LayerStackManager 优先级排序致死锁：Toast 存在时完全瘫痪所有菜单与弹窗的外点关闭

### 【AUDIT-B-08】输入框自动增高仍使用高度归零强刷重排算法，未落地 CSS field-sizing: content

- **涉及文件及精准行号**：`apps/crish-desktop/src/hooks/useAutoGrowTextarea.ts:37-57`、`73-75`
- **违反的详案契约条款**：`05 详案` §1.4.1、§1.4.2、§2.3、§3.2 (Task-R05)
- **潜在风险/病理剖析**：
  `useAutoGrowTextarea.ts` 在用户每次敲击按键导致 `value` 变化时，都会在 `useLayoutEffect` 中同步调用 `applyAutoGrowHeight`：
  `el.style.height = '0px'` -> `getComputedStyle(el)` -> `el.scrollHeight` -> `el.style.height = ...`。
  这是典型的 AP-04「高度归零强制同步回流环（Forced Synchronous Layout）」。在快速打字或批量粘贴长文本时，每一次按键都会强迫浏览器重排整个页面文档树，造成明显的按键掉帧、输入卡顿以及输入法选词框抖动。`05 详案` 要求的 CSS `field-sizing: content` 与 0 重排 Hook 完全未落地。
- **精确整改建议**：
  重构输入框增高方案，优先采用现代 CSS `field-sizing: content; max-height: calc(10 * var(--line-height));` 纯样式引擎自增高；对旧环境通过 `useZeroReflowTextarea` 仅在行数变化时单向增量调整高度，彻底取缔每次按键把 `height` 归零为 `0px` 测高的毒性代码。

### 【AUDIT-B-12】Tooltip 仍保留 120ms 延迟退出与 Branch 滥用，且全量挂载至 document.body 而非专用 Portal Root

- **涉及文件及精准行号**：
  - `apps/crish-desktop/src/components/ui/Tooltip/Tooltip.tsx:276, 524, 551`
  - `apps/crish-desktop/index.html:45-49`
- **违反的详案契约条款**：`04 详案` §1.6.2、§2.4、§3.2 (Task-L06)
- **潜在风险/病理剖析**：

## 结论汇总

本次红队审查共穿透发现 **12 项** 严重偏离详案规范、破坏视口几何与引发死锁/重排的结构性缺陷：
