## 一、 微内核与视图注册中心架构问题 (ViewRegistry & SlotCore)

### 【问题 A-01】内置视图自注册依赖模块副作用，应用启动生命周期未显式挂载

- **涉及文件及精准行号**：`apps/crish-desktop/src/services/view-registry/index.ts:4`, `apps/crish-desktop/src/main.tsx:1-120`
- **违反的详案契约条款**：`01-微内核与视图注册维度详案.md` §1.2.4、§3.1 (Phase 3 / Task-R01)、§3.4
- **潜在风险/病理剖析**：
  `registerBuiltInViews()` 的执行被放置在 `services/view-registry/index.ts` 顶层，作为模块加载的隐式副作用（Side Effect）执行。在现代 ESM / Vite / Rollup 打包与 Tree-shaking 优化下，若外部文件通过深路径直接引入 `ViewRegistry`（如 `import { viewRegistry } from './ViewRegistry'`），`index.ts` 不会被加载，副作用无法触发；且在应用启动主入口 `main.tsx` 与 `bootstrap-*.ts` 中完全没有显式调用 `registerBuiltInViews()`。这会导致生产运行时 `viewRegistry` 初始注册表为空，二叉树工作区在初次分屏或加载时全部命中 `未知面板类型` 的错误 fallback。
- **精确整改建议**：
  1. 移除 `services/view-registry/index.ts:4` 的顶层裸调用；
  2. 在 `apps/crish-desktop/src/main.tsx` 的 `startup()` 阶段（Phase 1 或 Phase 1.5 之前）显式执行 `registerBuiltInViews()` 与 `registerBuiltInSlots()`。

### 【问题 A-03】ViewRegistry.clear() 彻底销毁内置 URI 解析器导致不可逆状态污染

- **涉及文件及精准行号**：`apps/crish-desktop/src/services/view-registry/ViewRegistry.ts:173-178`
- **违反的详案契约条款**：`01-微内核与视图注册维度详案.md` §1.2.2、§1.2.3
- **潜在风险/病理剖析**：
  `ViewRegistry.ts:175` 在 `clear()` 方法中直接执行 `this.uriResolvers = []`。构造函数中初始化的 `file-viewer:` 动态 URI 解析器被直接清空。在单元测试（如 `beforeEach(() => viewRegistry.clear())`）或开发期热更新执行后，注册中心将永久丢失 `file-viewer:` 的路由解析能力，导致后续所有 `file-viewer:...` URI 均无法识别。
- **精确整改建议**：
  在 `clear()` 方法中，将 `this.uriResolvers` 重置为仅包含内置核心解析器的初始状态，或提取 `initDefaultResolvers()` 私有方法在 `clear()` 后重新挂载。

### 【问题 A-04】SlotCore 与 SlotOutlet 强类型 SlotMap 编译期约束模型完全缺失

### 【问题 A-05】SlotOutlet Single 插槽缺少影子退让（Abdication Protocol）错误隔离捕获边界

- **涉及文件及精准行号**：`apps/crish-desktop/src/services/view-registry/SlotOutlet.tsx:37-41`, `apps/crish-desktop/src/services/view-registry/SlotCore.ts:101-116`
- **违反的详案契约条款**：`01-微内核与视图注册维度详案.md` §1.3.1
- **潜在风险/病理剖析**：
  `SlotCore.ts` 实现了 `abdicateSingle` 状态机，旨在当胜出组件崩溃时将控制权退位给次优 Priority 组件；然而在 `SlotOutlet.tsx:37-41` 中：
  ```tsx
  const single = slotCore.getSingle(slotKey);
  if (single) {
    const Comp = single.component;
    return <Comp {...context} />;
  }
  ```
  `Comp` 裸渲染在 `SlotOutlet` 中，没有局部 ErrorBoundary 包装。当 `winner-item` 发生渲染异常时，整个 React 树向上冒泡崩溃，`SlotCore.abdicateSingle` 根本没有被触发的运行时机，影子退让容灾机制沦为空壳逻辑。
- **精确整改建议**：
  在 `SlotOutlet` 处理 `Single` 模式时，使用专属内部轻量 `SlotErrorBoundary` 包裹 `Comp`；当 `componentDidCatch` 触发时，自动调用 `slotCore.abdicateSingle(slotKey, single.id)` 触发重新渲染。
