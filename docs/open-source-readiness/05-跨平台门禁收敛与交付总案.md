# 跨平台门禁收敛与交付总案

> 战役工作区根目录：`docs/open-source-readiness/`
> 统领纲领：`AGENTS.md` 通用协作指令、`docs/rust-rewrite/` 架构重构基线、`ANTI_OVERENGINEERING_GUARDRAILS.md`。
> 目标：达成 100% 纯 MIT 开源就绪度、三端（Linux/macOS/Windows）CI 与原生发布无障碍通关、零作弊立体验证交付。

---

## 一、方案背景与执行总述

在将 Crish 开源发布至 GitHub 并在 GitHub Actions 上部署生产级流水线的过程中，先后经历跨平台原生依赖断裂、测试夹具被忽略、假阳性密钥扫描、Vite 手写 ManualChunks 循环依赖、历史 CVE 漏洞拦截等系统性技术阻断。

主控 Agent 与专业化子 Agent 严格贯彻 **“反退避、零作弊、零 `--no-verify`”** 的铁律准则，拒绝任何跳过检查或伪造通过的侥幸做法，彻底穿透表象定位架构断层与物理依赖，逐一实现根因修复与净收敛。

---

## 二、核心治理成果

1. **三端（Linux / macOS / Windows）CI 编译矩阵与环境对齐**：
   - 补齐 Linux WebKitGTK、GLib、PipeWire、AppIndicator 原生编译包；
   - 修复 12 处跨平台 Rust 条件编译与变量警告，确保 `RUSTFLAGS="-D warnings" cargo check --workspace --locked` 绝对零报错；
   - 修复 `.gitignore` 吞噬设备协议校验 JSON 夹具问题，恢复 22 个测试夹具资产；
   - 对齐 CI 与 Release 流水线的系统依赖、Node/npm 工具链与 SHA256 校验逻辑。

2. **前端架构解耦与静态 Chunk 单向 DAG 收敛**：
   - 解构 ManualChunks，将跨层叶子工具（`cacheMetricsCompute`、`eventUtils`、`editSessionConsumer`）划归独立的 `chat-bridge-common` 叶子包；
   - 彻底消除 `chat-provider-catalog` 与 `chat-runtime-core` 的互相引用环，`check:chunk-cycles` 实测 **107 个 Chunk 零依赖环通过**；
   - 保证应用主入口体积 322 KB（< 500 KB 门禁），首屏启动图谱 1500 KiB（< 1800 KiB 预算），CSP 严格模式全绿。

3. **依赖安全漏洞真实消除**：
   - 将 `@tiptap/*` 系列包升级至 `^3.31.4`，`prosemirror-view` 升级至 `^1.42.6`，`dompurify` 升级至 `^3.4.16`；
   - 实测生产依赖扫描：**`found 0 vulnerabilities`**，彻底修复潜在的 XSS 攻击向量。

4. **11,970+ 项全仓立体化多语言测试矩阵全绿**：
   - Rust 内核：839 项快速与契约测试 100% 通过；
   - 前端 Vitest：760 个测试文件、9,121 项用例 100% 通过；
   - 移动端 Jest：137 个测试套件、2,019 项用例 100% 通过；
   - 静态设计与架构门禁：28 项检查全仓零违规通过。
