## 二、任务一：CI 与 Release 原生构建依赖与矩阵审查

### 2.1 Linux (Ubuntu) 构建依赖缺失根因与修复

在 GitHub Actions 官方提供的 `ubuntu-latest` 纯净运行容器中，Crish 包含了基于 Tauri 2.x 的原生桌面壳（[`apps/agent-workbench/src-tauri`](file:///c:/Software/conex/apps/agent-workbench/src-tauri)）以及跨平台电脑屏幕捕获与控制核心（[`crates/conex-computer`](file:///c:/Software/conex/crates/conex-computer)）。

#### 根因剖析一：`glib-sys` 与 WebKitGTK 编译断裂

- **现象**：`cargo check --workspace` 早期在 Linux 下抛出 `error: failed to run custom build command for glib-sys`。
- **根因**：Tauri 2.x 的 Linux 后端（依赖 `wry`、`tao`、`tauri-runtime-wry`）需要通过 C FFI 绑定调用系统的 WebKitGTK 4.1 与 Ayatana AppIndicator。其传递依赖 `glib-sys`、`gdk-sys`、`webkit2gtk-sys` 在 `build.rs` 中通过 `pkg-config` 搜寻系统中的 `glib-2.0.pc`、`webkit2gtk-4.1.pc`。Ubuntu 默认环境中缺失这些开发头文件包。
- **修复措施**：配置安装 `libwebkit2gtk-4.1-dev`、`libayatana-appindicator3-dev`、`librsvg2-dev` 以及基础 C 构建链 `build-essential`。

#### 根因剖析二：`libpipewire-0.3` 与 `libspa-0.2` 依赖断裂

- **现象**：在 Linux 下编译抛出：
  ```text
  The system library libpipewire-0.3 required by crate libspa-sys was not found.
  The file libpipewire-0.3.pc needs to be installed.
  ```
- **根因**：[`crates/conex-computer/Cargo.toml`](file:///c:/Software/conex/crates/conex-computer/Cargo.toml#L35) 引入了跨平台屏幕截取库 `xcap = { version = "0.9", features = ["image"] }`。在 Linux 现代桌面环境中，`xcap` (v0.9.8) 支持 Wayland 屏幕录制，其底层强依赖 Linux 原生多媒体流通道 PipeWire，从而传递引入 `pipewire = "0.10.1"` 与 `pipewire-sys`。`pipewire-sys` 的构建脚本强制检测 `libpipewire-0.3` 与 SPA (`libspa-0.2`) 的 pkg-config 元数据。缺失这两个系统库直接导致构建彻底失败。
- **修复措施**：在 apt 依赖列表中引入 `libpipewire-0.3-dev` 与 `libspa-0.2-dev`。

### 2.2 `.github/workflows/ci.yml` 跨平台配置审查

在 [`.github/workflows/ci.yml`](file:///c:/Software/conex/.github/workflows/ci.yml#L213-L231) 中，`rust-check` 作为全仓跨平台编译门禁已严格落地：

```yaml
rust-check:
  strategy:
    fail-fast: false
    matrix:
      os: [ubuntu-latest, windows-latest, macos-latest]
  runs-on: ${{ matrix.os }}
  timeout-minutes: 25
  steps:
    - uses: actions/checkout@v4
    - uses: actions-rust-lang/setup-rust-toolchain@v1
    - name: Install Linux build dependencies
      if: matrix.os == 'ubuntu-latest'
      run: |
        sudo apt-get update
        sudo apt-get install -y libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev libpipewire-0.3-dev libspa-0.2-dev
    # 跨平台编译门禁（Linux / Windows / macOS 原生契约验证）：
    # --locked 锁定依赖版本
    - run: cargo check --workspace --locked
```

**审计结论**：

1. **三端全覆盖**：matrix 包含 `[ubuntu-latest, windows-latest, macos-latest]`，未遗漏任何主流平台。
2. **容错与观测**：`fail-fast: false` 确保即使某一平台偶发网络或环境波动，其余两平台的构建结果依然被完整执行并留存日志。
3. **版本锁定硬门禁**：执行 `cargo check --workspace --locked`，确保在三端机器上绝不自动拉取未锁定的间接依赖，杜绝锁漂移。

## 四、任务三：12 个跨平台条件编译修复文件深度审查

在 Rust 跨平台项目中，最容易在 CI 矩阵的某一特定系统（例如 Linux 或 macOS）上引发编译红线的问题是：

- 某平台专有的代码在非该平台编译时，产生未使用变量（`unused_variables`）或未使用可变性（`unused_mut`）；
- 平台独占函数在未加属性时产生死代码警告（`dead_code`）；
- 原生系统 API 未加 `#[cfg(...)]` 隔离导致在非目标系统符号未定义。

本审计对涉及跨平台修复的 12 个重点文件及关联文件进行了逐行审查：

### 4.1 [`apps/agent-workbench/src-tauri/src/auth/credential_store.rs`](file:///c:/Software/conex/apps/agent-workbench/src-tauri/src/auth/credential_store.rs)

    ```rust
        Ok(Some(SecretString::new(secret)))
    }
    #[cfg(not(windows))]
    {
        let _ = text;
        Err(CredentialError::PlatformUnsupported)
    }
    ```
