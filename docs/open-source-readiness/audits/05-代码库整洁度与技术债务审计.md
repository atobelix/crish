## 摘要与就绪度综合评定

本审计报告针对 Conex / Crish 项目距离正式在 GitHub 等公网平台开源，在**工程整洁度、历史技术债务、调试残留、异常崩溃防护以及包元数据规范性**五个维度进行了全面、穿透式的源码级审查。

通过执行静态分析、Ripgrep 正则扫描、Node.js AST 与元数据检查以及 Cargo Workspace 深度统计，本次审计核查了全仓 25 个 Rust Crates、11 个 npm Packages 以及仓库根目录的所有现存文件。

### 综合评估结论

**当前工程整洁度与技术债务就绪度状态：核心架构规范严格（如 Clippy 强行封禁 `dbg!` 与 `unimplemented!`），但工程表面附着了大量多轮迭代残留的“地表杂物”，存在 3 项阻断级（P0）缺陷与 5 项严重级（P1）缺陷，严重影响开源专业度与运行时健壮性，必须在公开前执行系统性整改。**

- **优秀基线**：
  1. **宏级守门严格**：根 `Cargo.toml` 配置了 `dbg_macro = "deny"` 与 `unimplemented = "deny"`，全仓生产代码零 `dbg!()`、零 `unimplemented!()`；
  2. **分层清晰**：Rust 内核与前端 React UI 拥有严格的类型检查门禁与架构解耦规则；
  3. **自动化基线意识完备**：仓库内置了大量基线检查脚本（如 unwrap 基线、行数门禁、Token SSOT 门禁）。
- **核心风险与差距**：
  1. **【P0 - 阻断】私有包防发布守门缺失**：`packages/plugin-import-claude-codex/package.json` 遗漏 `"private": true`；全仓 25 个 Rust Crates 均未配置 `publish = false`，一旦流水线触发 `cargo publish` 或 `npm publish` 将直接产生灾难性公网误发；
  2. **【P0 - 阻断】导线层 Fail-Closed 进程自毁隐患**：`agent-provider` 中的 4 处请求体构造入口为规避重构签名，在检测到孤儿工具调用时通过 `panic!()` 强行崩溃整个 Tauri 桌面进程；
  3. **【P0 - 阻断】开发者本地数据与私人资产泄露**：前端 UI `UserProfileCard.tsx:15` 硬编码默认用户名 `username = 'orange'`（开发者本地 OS 用户名）；根目录散落 `exports/wedding-card/` 等个人非项目产物；
  4. **【P1 - 严重】根目录严重脏乱与 .gitignore 掩耳盗铃**：根目录下堆积了 16 个 Python 脚本、2 个 Shell 脚本、17 个临时/调试文本与数据、5 个报告 JSON、7 个原型 HTML/CSS 文件以及 `--version/` 等异常文件夹；`.gitignore` 滥用 `/*.txt`、`/*.json`、`/*.html`、`/*.png`、`/*.mjs`、`/*.py` 粗暴遮盖，掩盖了脏乱现状；
  5. **【P1 - 严重】Unwrap 门禁脚本判定失效**：`scripts/check-unwrap-baseline.mjs` 测试文件正则缺失对 `tests_*.rs` 和 `*_tests_*.rs` 的支持，导致 `conex-db` 等 Crates 400+ 处测试 unwrap 被误判为生产代码，门禁全线崩溃退出（exit 1），门禁失去防护意义；
  6. **【P1 - 严重】生产高危链路裸调 unwrap/expect**：文档协作树操作（`session_apply.rs:283, 304`）、项目树构建（`project_tree.rs:300, 324`）以及桌面操作（`conex-computer` 39 处 OS Handle）存在裸 `unwrap/expect`，外部输入异常可直接引发崩溃。
