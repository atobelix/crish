## 一、逐项核验（Q1–Q10）

### Q1 · 摘要锁外 spawn 是否真在锁外

**结论：已真正在锁外。**

- `crates/session-loop/src/loop/summary_dispatch.rs:517-617`：
  - 注释 `// 锁内只做单飞 / 护栏 / 组装；tokio::spawn 必须在 task 锁外`（:517）
  - `let prepared = { let guard = self.task.lock()... }` 块内只做单飞去重（:524-533）、窗口护栏（:536-568）、组装 `(task,config,recorder,background,ids)`（:569-597），块结束即 `drop(guard)`；
  - 块外 `let (task,config,recorder,...)=prepared; let handle = tokio::spawn(...)`（:600-603）在锁外；
  - 再短锁回写 `*guard = Some(handle)`，并做并发复查：`if existing.is_finished()==false { handle.abort(); return false; }`（:604-616），避免覆盖丢 handle。

- `crates/session-loop/src/loop/summary_coordinator.rs:168-251` 同模式：
  - `let prepared = { let guard = self.task.lock()...; fetch_add + 全局上限检查; ... (task,config,callback,background) }`（:170-229）
  - 块外 `let slot = ActiveSummarySlot; let handle = tokio::spawn(async move { let _slot=slot; run_summary_task(...) })`（:231-237）在锁外；`ActiveSummarySlot` 的 `Drop` 保证 abort 未起步也能 `fetch_sub`，不泄漏 `ACTIVE_SUMMARY_TASKS`；
  - 再短锁回写并复查存活句柄（:238-251）。

- 锁中毒面同步收敛：两文件 `task`/`retry_gate`/`config`/`background_sink`/`sessions` 的 `lock().unwrap_or_else(|e| e.into_inner())` 已全部改为 `tracing::error!(target:"session_loop",...) + e.into_inner()`（`summary_dispatch.rs:521,538,576,606` 等，`summary_coordinator.rs:171,204,239,277` 等）。

**验收：`grep tokio::spawn` 在两文件各 1 处，且均不在 `task.lock()` 区间内；现有摘要后台测试语义不变。**

### Q3 · flow advance 是否 O(dirty)

**结论：已改为 O(dirty) 脏集增量，且语义与全量一致。**

- `crates/orchestrator/src/flow_graph.rs`：

  - `advance()` 入口：`if dirty_set.is_empty() { seed_dirty_pending() }` 全量灌 Pending 仅首轮/恢复/预算重试兜底，否则保持增量集（:966-969）；预计算 `order_index: HashMap<FlowNodeId, usize>` 保证就绪集按声明序（:972-977）；
  - 循环不变量：`if dirty_set.is_empty() { break; }`（:984-986,991-993）；`ready_ids` 仅从 `dirty_set` 遍历 `graph.node(id)` 再 `is_ready`，`sort_by_key(order_index)`（:996-1004），本轮判后 `dirty_set.clear()` 后续由状态迁移再入集；
  - 预算满：`budget_blocked.extend(ready_ids[idx..])`，轮末 `dirty_set.extend(budget_blocked)` 保留剩余就绪节点（:1012-1013,1178-1180），下次终态释放后重试，O(dirty) 保留不全量重扫；

  - `mark_successors_dirty` 合并两类后继：`graph.dependents(id)` DAG 反向边 + 同波次串行后继（`!parallel && depends_on == changed.depends_on` 且声明序在后，:1699-1732），保证串行约束与全量重算一致。

- 测试：`flow_graph.rs:2162-2414` 新增 `RecordingTestSpawner` + 3 集成测 `advance_dirty_ready_set_matches_full_is_ready` / `advance_dirty_spawn_fail_skip_matches_full_ready_same_call` / `advance_dirty_block_propagation_matches_full_scan`，每测以 `full_ready_ids()` 全量 is_ready 为 oracle，对照增量启动集与脏集收空。

**验收：`advance` 从 `O(nodes² × iterations)` 降为 `O(dirty × iterations)`；增量就绪集与全量重算调度结果一致（测试覆盖 DAG 后继、同波次串行、Block 传递）。**

### 重复1 · `ComputerSession` 三重分派入口（n=2 新增的重复路径）

- **位置**：`crates/conex-computer/src/lib.rs:96-223` `set_abort_checker` / `clear_abort_checker` / `dispatch_with_abort<F>` / `dispatch_inner` / `dispatch`

- **位置**：`crates/conex-computer-tools/src/session.rs:90-98` `impl Clone for PerceptionGuard { Self(self.0.clone()) }`
