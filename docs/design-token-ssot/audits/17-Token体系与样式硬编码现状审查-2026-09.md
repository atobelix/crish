# 17 · Token 体系 vs 样式硬编码现状审查（2026-09）

> **性质**：只读审查 + 量化扫描。不改生产代码。  
> **范围**：`apps/crish-desktop/src`（CSS Modules / 全局 CSS / 业务 TS；排除 `tokens.css` 自身、gallery、测试）。  
> **对照**：`docs/design-token-ssot/00-总方案` / `01-分维`、既有门禁 `check-token-consistency` / `check-text-color-tokens` / `check-color-ssot`。

---

## 一、结论先行

| 层级 | 现状 | 严重度 |
|---|---|---|
| **Token 定义层** | 已相当完整：约 **602** 个 CSS token + **76** 个 JS 注入；含 surface / text / border / radius / space / shadow / motion / z / scrollbar / xterm / composer 等 | 体系本身不是空的 |
| **组件 CSS 颜色字面量** | **约 84 处 / 31 个文件**（排除 tokens/gallery/测试后） | 中——量不大，但门禁盖不住 |
| **高程 / 圆角 / z / 动效「伪 token 化」** | 裸 `box-shadow` 仍约 **260** 处量级；裸 `border-radius` **~200**；裸 `z-index` **59**；内联 `cubic-bezier` **~73** | **高——这是真正「很严重」的主体** |
| **平行色板 / 运行时双真源** | `themePresets.ts` **209** 处硬编码仍在；`useXtermTerminal` 再备一套 ANSI hex | **高——改 tokens 不一定改界面** |
| **一致性门禁** | 当前 **FAIL**：`undefined_refs=1`，`dead_tokens=6` | 中（可立刻修） |
| **色彩门禁假通过** | `check-color-ssot` 通过，但只扫 CSS 的 `background`/`color`，**不扫** border / shadow / fill / stroke / TSX | **高——门禁与真实问题脱节** |

**一句话**：颜色字面量在 CSS 里已经收敛到「可数的几十处」；真正失控的是 **高程、圆角、z-index、动效的裸数值**，以及 **主题运行时平行色板**。用户感觉「很严重」，主要不是 `#hex` 还剩多少，而是 **token 有、组件不用 / token 不够用就随手写 / 门禁只挡了一小角**。

## 二、门禁实测（本回合跑过）

| 门禁 | 结果 | 说明 |
|---|---|---|
| `node scripts/check-token-consistency.mjs` | **FAIL** | `undefined_refs=1`（`--chat-stream-pad-x` 有 fallback）、`dead_tokens=6` |
| `node scripts/check-text-color-tokens.mjs` | PASS | 只管文字 `color:` 属性 |
| `node scripts/check-color-ssot.mjs` | PASS | 只管 `background`/`color` + 假 fallback `var(--x, #hex)` |

### 2.1 一致性缺口（可立刻修）

| 指标 | 项 | 位置 |
|---|---|---|
| undefined（含 fallback） | `--chat-stream-pad-x` | `ChatMessageList.module.css:38`、`ChatScrollFloorSlot.module.css:20`（注释写明应对齐 20px，但 token 未定义） |
| dead | `--edge-reserve-right-win/macos`、`--shell-safe-inset-left/right`、`--shell-canvas-gutter-compact` | `tokens.css:425-435`（布局战役半成品：定义了未消费） |
| dead | `--z-pinned-bar` | `z-index.css:32`（有定义、无 `var()` 消费方） |

### 2.2 门禁覆盖缺口（根因级）

`check-token-consistency` 注释已写明 **不检查**：

- 裸 hex/rgb/hsl/oklch 与颜色关键字（G3）
- 刻度合规（G5）
- 内联 style 硬编码（G4）
- 逃逸值（G6）

`check-color-ssot` 只匹配：

```js
// scripts/check-color-ssot.mjs hardProp
/(?:^|[;{\s])(background(?:-color)?|color)\s*:\s*([^;]+)/gi
```

因此 **`border-color: hsl(...)`、`box-shadow: 0 16px 36px hsl(0 0% 0% / 0.08)` 全部放行**——这与 01-分维 §4.2 记录的「仅 G1/G2 落成，G3–G6 未建」完全一致。

## 三、组件 CSS 颜色字面量（84 处盘点）

### 3.1 按文件（Top）

| 处数 | 文件 | 性质 |
|---:|---|---|
| 27 | `chat-message-row/ChatMessageRow.module.css` | 钉选色轮 conic-gradient 产品调色板 + 白描边 |
| 12 | `chat-composer/ChatComposer.module.css` | **warning 条写死 `hsl(38, 90%, 50%)`**（token 已有！）+ 多层 elevation |
| 3 | `styles/markdown-typography.css` | 暗色表头/行 hover 局部覆盖 |
| 3 | `shell/sessionTabDrag.module.css` | 拖拽浮层 elevation |
| 2×多 | Input/Textarea/Switch/Button/… | 多数是 **shadow 阴影里的黑色 alpha** |

### 3.2 分类裁决

#### A. 随手硬编码（token 已有，应直接改写）——优先

| 证据 | 应改用 |
|---|---|
| `ChatComposer.module.css:72,77,96` 写死 `hsl(38, 90%, 50%)` | 已有 `--color-warning` / `--color-warning-bg` / `--color-warning-border`（`tokens.css:251-253`） |
| `Input.module.css:50,62`、`Textarea.module.css:52,63` 写死 `hsl(30 4.8% 91.8%)` | 应收敛为 `--border-color` / `--border-subtle` 或 **Input 专用边框 token**（当前值与 `--border-subtle: hsl(30 6% 94.5%)` 不一致，要么对齐要么显式开档） |
| `WorkingStatusIndicator.module.css:31,44` 写死 `hsl(158 64% 52% / …)` | 应走 `--color-success` / 专用 `--glow-success` |
| 大量 `box-shadow: … hsl(0 0% 0% / 0.0x)` / `rgba(0,0,0,…)` | 应有 **elevation 语义档**，而不是每处发明 |

#### B. Token 体系跟不上（应扩档，再迁移）——与用户判断一致

| 缺口 | 现状 | 建议扩 token |
|---|---|---|
| 高程刻度不足 | 只有 `--shadow-sm/md/lg/2xl` + dropdown/popover；composer 浮起、拖拽 ghost、scroll floor、按钮按压、状态光晕各写一套 | `--shadow-float-composer`、`--shadow-drag-ghost`、`--shadow-floor`、`--shadow-press`、`--glow-*`（用 color-mix 绑 `--shadow-color`） |
| 钉选/标签产品色板 | `colorPickerUtils.ts` 5 色 + CSS conic-gradient 同源 hex | `--pin-palette-*` / `--preset-pin-*` 六元（与 PRESET_PIN_COLORS 单源） |
| 暗色 markdown 表头 | 局部写在 `markdown-typography.css` 而非 tokens | `--md-table-header-bg` 等升入 tokens 暗色段，或保留但禁止第二真源数值 |
| 终端 ANSI | tokens 有 `--xterm-*`，但 `useXtermTerminal.ts` 再写 68 处 hex 作 fallback | JS 侧只允许 `readCssVar('--xterm-*')`，默认值从同一常量导出（双写变单写） |
| 主题平行色板 | `themePresets.ts` 209 处（总方案 R1，**仍未做**） | 不是「再加几个 token」能解决，是 **A1 定义真源唯一化** |

#### C. 合理白名单（不应强行 token 化）

| 对象 | 理由 |
|---|---|
| `assets/icons/fileIcons.ts` / `modelVendor*.ts`（~640 hex） | 品牌图标数据，不是 UI 表面色 |
| `WindowControls.module.css` 关闭按钮 `#e81123` | 系统 chrome |
| 导出 HTML 字符串（`agentCardUtils` / `sidebarHelpers`） | 离线导出，建议维持 allowlist 并注释 |
| `LoggerService` console 色 | 开发日志 |
| 钉选彩虹 conic 中的纯产品色 | 若保留独立产品色，应 **token 化成 preset 族** 而非散落 hex；但允许存在「产品色板」层 |

## 四、非颜色裸刻度（真正的大头）

| 维度 | 约计数 | Token 是否已有 | 问题 |
|---|---:|---|---|
| `box-shadow` 无 `var(--shadow-*)` | **~260** | 有 sm/md/lg/2xl | 高程档位不够 + 习惯性手写 |
| `border-radius` 无 `var(--radius-*)` | **~200** | 有 xs…full | 其中 50%/0/999 可白名单；4/6/8/12px 应走刻度 |
| 裸 `z-index: <number>` | **59** | `z-index.css` 7 级 + 角色别名 | BinaryTree 160/150、DraftUndoToast 30 等逃逸 |
| 内联 `cubic-bezier` | **~73** | `--ease-standard/emphasized` + transition 族 | ChatComposer 13 处最重 |

这与总方案 §5.4 条目 26–29 的病灶清单一致；**清理明显不完整**。
