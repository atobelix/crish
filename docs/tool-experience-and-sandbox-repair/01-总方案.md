# 工具调用体验与沙箱误报系统性整改总方案

> 战役工作区：`docs/tool-experience-and-sandbox-repair/`  
> 权威参考：A1–A8 各专项调研分析报告（`analysis/01` 至 `08`）

---

## 一、方案全景与目标

针对用户反馈的排版混乱、沙箱阻断误报、字号过小、数字乱转、缺少边缘渐隐、展开卡顿与流式刷屏等一系列问题，本方案提供系统级、无退避的端到端根治重构。

```
┌────────────────────────────────────────────────────────────────────────┐
│                        用户界面视觉与交互重构                           │
├────────────────────────────────────────────────────────────────────────┤
│ 1. 单工具穿透 (E3) : 卸载外层无意义控制栏，单行头闭环自承载折叠与耗时 │
│ 2. 卡片排版 (E4)   : 统一 18px 基线内边距，柔和外描边与贯穿发丝分割线 │
│ 3. 字号统一 (E5)   : 28 项界面交互文本提升至 14px，代码日志维持 12px   │
│ 4. 数字滚动 (E6)   : animateOnView 默认置 false，展开零空转首帧直出终态│
│ 5. 上下渐隐 (E7)   : 渐隐带扩至 40px + 5 阶平滑曲线 + 4-6px 端态微羽化 │
│ 6. 性能与节流 (E8) : 手风琴动画期加锁避免虚拟列表重测高，流式平滑双缓冲│
├────────────────────────────────────────────────────────────────────────┤
│                        Rust 底层与数据管道加固                         │
├────────────────────────────────────────────────────────────────────────┤
│ 7. 沙箱误杀 (E1)   : 正则尾部定界断言 + 转义修复 + git grep 纳入白名单 │
│ 8. CLIXML 噪音 (E2): 注入 $ProgressPreference 抑制源头，解码真实错误   │
└────────────────────────────────────────────────────────────────────────┘
```

## 二、各维度精细化实施矩阵

### E1：沙箱 Redline 误杀修复与词法加固
- **执行模块**：`crates/conex-sandbox/`、`crates/agent-tools/src/tools/shell/shell_path_guard.rs`
- **核心落地**：
  1. `tokenize.rs`：修复双引号状态下 `\"` 转义字符解析；
  2. `shell_path_guard.rs`：重构 `UNIX_PATH_REGEX`，尾部必须断言空白或引号边界；`is_valid_unix_path` 排除裸点 `.` 和相对路径片段；
  3. `read_only.rs`：将 `git grep` 加入只读安全白名单。

### E2：PowerShell CLIXML 协议垃圾全链路消除
- **执行模块**：`crates/agent-tools/src/tools/shell/`、`crates/agent-provider/`、`apps/crish-desktop/src/`
- **核心落地**：
  1. `shell_invoke.rs`：在 Windows 启动脚本中注入 `$ProgressPreference='SilentlyContinue'` 等环境变量；
  2. `shell_output.rs`：实现纯 Rust `clean_clixml_stream`，丢弃 `<Obj S="progress">` 进度块，解码提取 `<S S="Error">` 真实业务错误；
  3. `clean_output.rs`：发往大模型的 Wire 上下文前置剥离 CLIXML，阻断 LLM 正文复读；
  4. `streamCallbacksEvents.ts`：修复 `displayOut || output` 空值回退陷阱。

### E3：单工具双层折叠套娃消除与统一穿透
- **执行模块**：`apps/crish-desktop/src/api/tool-presentation/timelineSegmenter.ts`、`FoldableProcessSection.tsx`
- **核心落地**：
  1. `timelineSegmenter.ts`：落实契约 `showWorkTime: isFirstGroup && (thoughtCount + toolCount >= 2)`；单工具时 `hasGroupHeader = false`；
  2. `FoldableProcessSection.tsx`：为单工具扩展穿透豁免 `omitOuterControlBar = isSingleThought || isSingleTool`；
  3. 耗时自然由内层 `ToolCallHeader` 的 `durationStr` 承载，消除双层折叠头。

### E4：工具卡片排版规范化、内边距对齐与微描边
- **执行模块**：`ChatToolCallBlock.module.css`、`ToolCallOutputPane.tsx`、`ToolCallInputPane.tsx`
- **核心落地**：
  1. 移除 `.toolSectionShellSingleLine` 中的 `padding: 4px 0`，统一收敛为水平 18px 对齐；
  2. `.toolResultBody` 加上 `1px solid var(--border-subtle)` 微描边；输入与输出之间增加发丝分隔线；
  3. 紧缩 `showHeader` 判定条件，普通成功执行无元数据时不渲染空 Header，消除多余空白；
  4. 明确区分“复制命令”与“复制输出”。

### E5：全局文字 14px 统一提升
- **执行模块**：`FoldableProcessSection.module.css`、`FoldableToolGroup.module.css`、`ReasoningRow.module.css`、`ChatToolCallBlock.module.css`
- **核心落地**：
  1. 过程折叠栏、多工具组头、工具单行头（动作词、参数路径、意图标签、耗时、差异统计）、思考行等 28 项界面文本统一提升至 14px；
  2. 代码输出、终端日志、Diff 差异行等 24 项输出类严格维持等宽 12px/11px；
  3. 同步更新 `processTypographyContract.test.ts`、`FoldableProcessSection.test.tsx` 等门禁断言。

### E6：NumericText 数字滚动乱触发与体验优化
- **执行模块**：`NumericText.tsx`、`AnimatedCounter.tsx`、`ToolNumericText.tsx`
- **核心落地**：
  1. `NumericTextProps.animateOnView` 默认值反转为 `false`；
  2. 单列滚轮 `Column` 在 `animateOnView === false` 时首帧直出目标数字；手风琴展开、历史数据回屏绝对零空转；
  3. 唤醒 `ToolNumericText.tsx` 中的实况门控校验，仅在活跃实况窗且显式请求时平滑滚动。

### E7：高度受限容器上下平滑渐隐（ScrollFade）强化
- **执行模块**：`ScrollFadeRegion.tsx`、`useScrollFade.ts`、`scroll-fade.css`
- **核心落地**：
  1. 渐隐遮罩高度从 28px 扩展至 40px，全面升级为 5 阶非线性平滑 Ease 曲线；
  2. 引入 4–6px 端态微羽化（Micro-Feathering），消除顶底硬触边界；
  3. 补齐 DiffPreview、ApprovalAskCard 等限高视口的渐隐挂载，恢复上下呼吸槽。

### E8：手风琴展开 60fps 流畅度与流式平滑节流
- **执行模块**：`VirtualScrollManager.ts`、`useToolExpansionState.ts`、`useStreamBatchers.ts`
- **核心落地**：
  1. 设立手风琴动画锁（Accordion Motion Lock）：动画期间暂停虚拟滚动测高重渲染通知，落定后单次提交；
  2. 两阶段分相调度（Phase 1 动画轻量渲染，Phase 2 结束水合重型组件）；
  3. 流式打字节流优化：收紧起涌门槛至 12 字，稳态速率 60~80 字/s，结合微步长阻尼平滑涌现。

## 三、验证与收口标准
1. **沙箱回归门禁**：`git grep` 正则命令执行测试 100% 通过，无 Redline 阻断；
2. **CLIXML 门禁**：Windows 模拟执行 stderr CLIXML，确认 Tool Result 与大模型上下文零污染；
3. **前端渲染门禁**：单工具单行直出无外层套娃；卡片内边距 18px 绝对对齐且带微描边与分隔线；文字 14px 且代码 12px；展开时数字静止直出；受限视口上下平滑渐隐；手风琴动画无掉帧。
4. **代码门禁**：`npm run typecheck` + `npm run test` + `cargo test` 全绿，零 `--no-verify`。
