# 调研边界与效果锁

## 用户锁定（本战役不得降级）

1. **对话流插件式**：叙事编排（思考 / 目的 / 工具 / 子任务 / 产物 / 权限条）不是内核死绑；以扩展挂上。
2. **默认直来直去**：未挂叙事插件时，产品就是用户消息 ↔ 助手正文的线性对话。不把 Purpose 树、计划条、时间线做成默认必选项。
3. **参考仓是能力矿，不是成品**：`index.html` 是整应用演示（侧栏 + 顶栏 + 二叉树容器 + 流 + 计划条 + composer + 一堆 popover）。只吸收信息架构、组件边界、视觉语言；不把演示壳整页搬进 desktop。
4. **除对话流以外一并盘点**：排版布局、样式设计、新组件、文件预览、markdown 编辑器演示、Skill/斜杠/@ 等。能进产品的要标插件边界；不能进的标「演示/禁搬」。
5. **与已锁壳一致**：产品壳仍是 `App → BinaryTreeWorkspace → TreeLeafPanel → SlotOutlet + viewRegistry`。笔记走 `activateNotePaper` 模式。对话叙事走同类激活/注销，不复活已删的 `src/plugins` / `ContributeViewRegistry` / 1.4 万行星壳 CSS。
6. **美学**：先看气质（干净、可扫读、与 composer 同一套 surface），次看 AFFiNE、再看 AppFlowy；禁止截图驱动照抄。
7. **架构与性能同权**：迁任何一块都要写清包含块、虚拟化/折叠高度、包边界；禁止环形缓冲、六段中间件等已禁过度设计。

## 非目标

- 不在本轮实现、不改 `apps/crish-desktop` 产品源码。
- 不把参考仓 markdown 编辑器再注册成第二个笔记内核。
- 不把参考仓左侧历史栏 / 窗口按钮 / 假 binaryTree 容器当成产品布局。
- 不把「打开笔记完成 / EL / 9222 真壳」并进本战役假装能关。
- 不重开 `docs/composer-preview`、`docs/input-stream-consolidation`、`docs/frontend-convergence` 为平行主战役；只对照，不吞并。
- 涉及 AI 调用的真机验收本轮不做。

## 与壳换代的边界

| 面 | 归属 |
| --- | --- |
| 二叉树、插槽、视口包含块、笔记扩展打开完成 | 仍 `shell-rehost`；本战役不重做 |

## 验收（调研轮）

- 八份 survey 齐，且每份有：现码证据路径、参考仓路径、建议插件边界、明确「不要做」。
- 主控据此写 `00-总方案.md` + 分维终稿。写完之前不派实现刀。
