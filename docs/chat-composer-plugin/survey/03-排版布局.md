## 0. 结论（先读）

参考仓 `index.html` 是 **整应用演示壳**：左侧会话史 + 顶栏窗控 + 空 `binaryTreeWorkspaceContainer` + 对话列 + 底栏 composer + 计划条 + 视口级预览模态。其中 **对话叶内部竖叠**（stream 滚动 / permission+plan 贴 composer 上沿 / composer 底栏不滚走）是要吸的布局面。整页壳、窗控、假二叉树、侧栏 resizer、JS 量宽切行、JS 锁块高，全部不进产品。

产品已有一条高度链，对话叶只要填满叶子包含块，不要再造第二套视口公式：

```
html / #root / .app-container / .main-layout
  → #crish-sidebar（产品已有会话树，本战役不替换）
  → .workspaces-* → .section → .canvas（确定高）
    → .leaf（abs + %，相对画布，不是测内容高）
      → .leafBody → SlotOutlet(display:contents) → ChatCard
        → .chatBody 列 flex
            → .chatDocFlow / ChatMessageList   ← 唯一对话滚动容器
            → .chatFooter                      ← composer + 状态条 shrink-0
```

证据：`apps/crish-desktop/src/styles/shell/shell-layout.css:6-54`；`BinaryTreeWorkspace.module.css:13-47,318-332`；`TreeLeafPanel.tsx:121-128,200-214`；`SlotOutlet.tsx:6,188-196`；`ChatCard.module.css:1-67`。

**插件边界（布局）**

| 面 | 边界 |
| --- | --- |
| 整页壳 / 侧栏 / 窗控 / 假树 | **禁搬**。壳战役 + 产品 `Sidebar` 已覆盖 |

## 4. Markdown 编辑器布局 vs `note-paper` / `block-paper*`

参考仓有 **另一套** 块编辑器（`mdx-*`），不是产品笔记：

| 层 | 参考仓 | 产品 |
| --- | --- | --- |
| 根盒 | `.mdx-root` `height:100%; min-height:180px` 列 flex（`css/markdown-editor/index.css:13-48`） | `.panel` 列 flex；`flex:1; min-height:200px`（`NotePaperPanel.module.css:15-27`） |
| 滚动 | `.mdx-scroller` `flex:1; overflow:auto; min-height:0`（`index.css:73-78`） | 纸面 body `flex:1; overflow:auto`（同文件 `:184-188` 一带） |
| 宿主 | 独立 `markdown-editor.html` 再造 `.me-app` 100% 列（演示壳） | `extensions/note-paper/activate.ts` → `registerView('note')` → `NoteLeafHost` → `NotePaperStrictPanel` |
| 实现包 | `js/markdown-editor/**`（自研 DOM 编辑器） | `@crish/block-paper` + `block-paper-contract` + `editor-kit`（`HeightMap` 虚拟化） |
| 高稳定 | `edit/height-lock.js` 读 `offsetHeight` / `getBoundingClientRect`，写 `style.minHeight` | 叶高由画布 % 给；纸面吃 `.leafBody` flex 剩余 |

关系判定：

1. **内核重复，禁止再注册。** 调研边界：「不把参考仓 markdown 编辑器再注册成第二个笔记内核」（`00-调研边界.md:15`）。`apps/crish-desktop` 无 `mdx-root` / `conex-mdx` 引用。
2. **样式可迁的是 token / 禁则，不是整张 `mdx-*` 表。** 例如禁止激活行全行描边（`css/markdown-editor/index.css:87-125`）、密度变量、gutter 宽。迁入对象是 `packages/block-paper` chrome / `NotePaperPanel.module.css`，且须服从壳战役「不改 tokens 暗色 30%」。
3. **继续只活在笔记扩展。** 打开路径只有 `registerView('note')` + `openToolInSession(..., 'note')`（`shell-rehost/00-总方案.md:31-37`）。对话叶不嵌 `mdx-editor`。
4. **`height-lock.js` 产品禁搬。** 见 §5。参考仓自己的 fused 重构规格也把它标成「终局删除」（`reference/chat-composer-component/docs/markdown-editor/ux-readiness/12-FUSED-EDITOR-REFACTOR-SPEC.md` 表行 `height-lock.js`）。

`editor-kit` 的 `HeightMap`（`packages/editor-kit/src/viewport/HeightMap.ts`）是 **虚拟化前缀和**（估算 + 回填），键是序列 index，**禁止像素测距选块**。这与「量叶高写叶 style」不是一回事：虚拟化可以在 **已确定包含块内部** 量已挂载块，用来滚文档；不得用测量结果去设 `.leaf` / `.canvas` / `#root` 的高度。

## 5. 包含块 vs JS 测高对照表

产品锁（壳战役）：高度链用 flex 剩余；顶栏 shrink-0；**禁止 `calc(100vh - 顶栏)`**；叶子 `height: ${rect.height*100}%` 相对 **画布确定高**，不是量内容（`shell-rehost/00-总方案.md:36,107`；`01-视口包含块.md:70-89`；`TreeLeafPanel.tsx:121-128`）。

| 场景 | 参考仓做法 | 类型 | 产品口径 |
| --- | --- | --- | --- |
| 整页高 | `.chat-app-layout { height:100vh }` | CSS 视口 | 用已有 `#root 100vh` 链，不叠第二 100vh |
| 工作区高 | `.workspace-content-body { flex:1 1 0; min-height:0 }` | CSS 包含块 | 对齐 `.workspaces-*` / `.canvas` |
| 对话列高 | `.chat-main-pane { height:100%; flex column }` | CSS 包含块 | `.chatBody` 已是 `height:100%; flex:1 1 0%` |
| 流滚动高 | `.chat-stream-container { flex:1 1 0; min-height:0; overflow-y:auto }` | CSS 包含块 | `ChatMessageList` 同构 |
| 底栏 composer | sticky + shrink-0，高随内容 | CSS（内容高合法） | `.chatFooter` shrink-0 |
| 计划/手风琴展开 | `grid-template-rows: 0fr/1fr` | CSS 包含块 | **应吸收此模式** |
| 叶几何 | 假树 `L.style.flex = ratio`（`popovers.js:1677-1685`） | JS 写 flex | 产品 sash + `%` rect，禁止再写一套 |
| 侧栏宽 | `getBoundingClientRect` → `--sidebar-width` | JS 量宽 | 不进对话战役；侧栏已有变量 |
| 叶内预览宽 | `leafEl.clientWidth * 0.7` → `--panel-width` | JS 量叶宽 | 开邻叶；不要叶内第二套 resizer |
| composer 单/多行 | 测 `clientWidth`/`offsetWidth` + 隐藏 span 字宽（`composer-core.js:34-48,90-107`） | JS 量控件 | **禁搬**。产品已用 CSS `min/max-height: calc(1em * lh * N)` |
| 块进出编辑防跳 | `MdxHeightLock.lock`：`offsetHeight` / `getBoundingClientRect` → `el.style.minHeight`（`js/markdown-editor/edit/height-lock.js:18-57`） | **JS 量叶/块高** | **禁搬**。换壳用 CSS 或编辑器内部虚拟化，不写 inline min-height 撑布局 |
| 滚动位置保持 | `MdxHeightLock.withScrollPreserve` 读写 `scrollTop`（同文件 `134-179`） | JS 滚位置 | 仅允许在 **已有滚动容器内部** 做虚拟化 pin（`editor-kit` `domPinning`）；不据此改叶高 |
| 同步 composer 水平 | `syncComposerHorizontalAlignment` 已是空函数，注释写「CSS sticky」（`composer-core.js:324-331`） | 死 JS | 不要复活 |
| 假树叶内容高 | `.tree-pane-content { height: calc(100% - 36px) }`（`composer.css:1761-1764`） | CSS calc 减顶栏 | 禁。产品 `.leafBody` 是 flex 剩余 |
| 预览面板高 | `--fp-max-h: min(860px, 92vh)` | CSS 视口 | 改成叶内 `flex:1 1 0%; min-height:0; height:100%` |
| 虚拟化块高 | （参考仓无 HeightMap） | — | `HeightMap` 只服务纸面滚动估算，不写壳/叶 style |

**合法 vs 非法（一句话）**

- 合法：父级有确定高 → 子级 `flex:1 1 0%` + `min-height:0` → 溢出在内层 `overflow:auto`。
- 合法：内容自身高度（composer 行数、计划条文案）由内容决定，底栏 shrink-0。
- 非法：读叶/块 `offsetHeight` 再写回该节点或祖先的 `height`/`min-height` 来「撑开布局」。
- 非法：`100vh` 减任意 chrome 当对话叶公式。

`height-lock.js` 即便只锁「块」而非「叶」，也会在换壳时把测量像素钉进 inline style（`css/markdown-editor/line-source.css:265-272` 还声明 inline min-height 优先）。产品笔记换壳走 `block-paper` reconcile，不得引入这套锁。
