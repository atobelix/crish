# 02 · 对话流：默认直来直去 vs 可插拔叙事层

> 战役：`docs/chat-composer-plugin/`  
> 用户锁：叙事编排不是内核死绑；未挂插件时产品就是用户 ↔ 助手正文的线性对话。  
> 参考仓：`reference/chat-composer-component/`（能力矿，不是成品壳）。  
> 本文件只调研；不改产品源码、不提交 git。

---

## 0. 结论先行

| 裁决 | 一句话 |
| --- | --- |
| 默认 | **直来直去**：同一 `chat` 主叶上，只渲染用户气泡 + 助手正文（+ 流式 caret）。Purpose / 计划条 / 左边轨道 / 记事本 / PermissionBar **不是默认必选项**。 |
| 插件 | 叙事层以 **`activateConversationNarrative()`** 挂上（对齐 `activateNotePaper` 的激活/注销形态），在 **同一 chat 叶内替换 stream renderer**，**不**把 `chat` 从内置名单删掉。 |
| 投影器 | `flow-projector` **进插件包**，不进内核。输入是 desktop 已有的 `SessionMessage`（由 session-loop 事件经现有 `sessionEventProjection` 投影），输出 `FlowNode[]`。不发明新 IPC。 |
| 时间线轨道 | `FlowTimelineRail` **不是死代码、不是演示开关**，是规格 §1.3 禁用项在 reference 里的 **视觉回潮**。产品侧禁止迁入。 |
| 高度 | 折叠体用 **CSS `max-height` + overflow**；JS `scrollHeight` 只用来开关 fade class，属风险面。`getBoundingClientRect` 画轨是禁止路径。 |

内核继续拥有：`chat` 内置叶、`SessionMessage`、session-loop 事件投影、线性 MessageContent。插件拥有：Purpose 树、思考折叠、Action、Subagent、Artifact/Notebook、PermissionBar、Task/Plan 流内根、投影算法。

## 1. 默认直来直去：无插件必须能用

### 1.1 最小组件集（内核 / 默认 renderer）

无叙事插件时，chat 叶只保证这三块：

| 单元 | 用户看到的 | 数据 | 现码入口 |
| --- | --- | --- | --- |
| 用户气泡 | 右侧气泡，纯文本 | `SessionMessage.sender === 'user'` + `text` | `ChatUserMessageRow.tsx`；参考仓 `FlowMount.renderUserMessage` → `.flow-user-bubble`（`FlowMount.js:156-166`，`flow-base.css:65-75`） |
| 助手正文 | 主阅读色 Markdown | `SessionMessage.text` / `blocks[]` 里 `type:'text'` | `MessageContent.tsx` 的 `kind === 'text'` 分支（`MessageContent.tsx:80-107`）+ `AsyncMarkdownBlock`；参考仓 `TextBlock` 的 `tone:'primary'`（`TextBlock.js:159-181`） |
| 流式光标 | 尾部闪烁 caret | 热缓冲 `streamText` + `isThinkingMsg` | desktop 已有：`StreamingTextBlock` + `.assistantText.isStreaming::after`（`StreamingTextBlock.tsx:30-31,47-50`，`ChatMessageRow.module.css:383-398`）。参考仓对应物是 `ComposingHint`（「正在整理结果…」），**不是 caret**——默认层用 desktop 现成 caret，不必搬 ComposingHint。 |

**无插件时必须能用**的宿主链（现码已存在，不要另起叶）：

```
registerBuiltInViews → id:'chat'（primary）
  → ChatCard
    → ChatMessageList → MessageVirtualizer
      → ChatUserMessageRow | StreamingAssistantRow → ChatAssistantMessageRow
        → MessageContent（默认：text + 可选极薄兜底，见 1.3）
    → ChatComposerWrapper → ChatComposer
```

证据：

- `chat` **仍是内置主叶**：`registerBuiltInViews.tsx:62-69`（`id: 'chat'`，`category: 'primary'`）；`ViewRegistry.isPrimary` 硬编码 `id === 'chat'`（`ViewRegistry.ts:183-191`）；`main.tsx:25-36` factory 把 chat 绑到 `ChatCard`。
- 默认树水合仍以 chat 为根：`store-initializers.ts:169`（`cards: [{ id: 'chat', title: '对话' }]`）。
- 没有现码表明 chat 已不是主叶。**禁止**把 `chat` 从内置名单删掉。

### 1.2 默认层明确不含

未激活叙事插件时，下列节点 **不得** 作为默认 UI（数据可以仍在 store 里）：

- Purpose 折叠行 / 老虎机 secondary
- TaskRoot / PlanStep 流内里程碑
- Subagent 双行根 + 缩进面板
- Artifact chip + Notebook 浮层
- Composer 上方 PermissionBar（审批策略见 §3.6：无插件时沿用现有内联卡，不把「上提条」做成默认）
- 左边轨道 / SVG rail / 用户消息 minimap scrubber
- SessionStart 品牌条（参考仓自己已 `display: none !important`，`flow-base.css:2-4`）

### 1.3 工具数据不能黑洞（默认兜底，不是叙事树）

后端仍会下发 `toolCalls` / `thought`。默认 renderer **不得假装没发生过**，也 **不得** 因此把 Purpose 树做成默认。

建议（逻辑，非本轮实现）：

| 字段 | 无插件默认 | 挂上叙事插件后 |
| --- | --- | --- |
| `text` | 主正文 | 同左（`TextBlock` primary / interstitial） |
| `thinking` / `blocks.thought` | **不展开叙事思考块**；可完全不画，或一行极弱「已思考」且默认折叠。现码 `TimelineThoughtSection` 已是完整思考 UI（`TimelineThoughtSection.tsx`），应视为将被插件接管的面，而不是默认最小集。 | `ThinkingBlock` |
| `toolCalls` | 极薄线性兜底：按时间序一行「已调用 · 名称」，**不** Purpose 合并、不 rail、不 inspect 组头。现码 `ChatToolStack` + `buildToolRenderItems` 的「N 步」分组（`timelineNormalizer.ts:9-12,119-124`）已是半叙事，应随插件走，不要当默认。 | `PurposeBlock` + `ActionRow` |
| `pending_approval` | 维持现有 `ApprovalAskCard` 内联（`CompactToolRow.tsx:75-105`）+ 条件 `ApprovalDock`（`chatApprovalUi.ts:3-5`） | 抽到 `PermissionBar`，流内不再放完整审批卡 |
| `SessionAgent` | 现有 `InlineAgentPanel` 内嵌（`MessageToolCallsSection.tsx:12-45`）——这是当前默认，但规格把它归叙事层；插件激活后换 `SubagentRoot` | `SubagentRoot` |

直来直去的验收句：**关掉叙事插件，用户只感到在跟助手说话**；工具过程不抢主阅读色、不长出目的树。

## 3. 投影器：进插件包，对齐已有事件，不发明 IPC

### 3.1 应进插件包

`flow-projector.js` 的职责是 **把已投影好的 SessionMessage 编成叙事树**，不是会话协议本身。

| 面 | 放哪 |
| --- | --- |
| session-loop 事件、`sessionEventProjection`、`messageProjection`、`streamingStore` | **内核**（已有） |
| `timelineNormalizer.alignToolCallBlocks` / `buildAssistantTimeline`（thought/text/tool 交错） | **内核默认路径**；插件激活后可旁路，不必删 |
| `toolCardPresenter`（人话标签、spam explanation、路径/命令抽取） | **内核可留**（插件调用，避免两套 humanize） |
| `projectPurposes` / `projectMessage` / `projectConversation` / `extractPendingApprovals` | **插件** |
| `buildToolRenderItems` inspect 分组 | 现默认半叙事；插件 Purpose 覆盖后，默认路径不再走组头 |

参考仓自己已经把巨石 renderer 收成薄壳：`stream-renderer.js:1-5,10-21` 只调 `FlowMount` + `FlowProjector`。迁 desktop 时同样：Chat 叶默认 `MessageContent`；插件替换的是 **这一段组装**，不是整个 `ChatCard`。

### 3.2 输入（插件投影器看到的）

不要对接原始 SSE。对接 desktop **已经存在** 的消息模型：

```
SessionMessage {
  id, sender, text?, thinking?, thinkingTurns?,
  toolCalls?: MessageToolCall[],
  blocks?: { type: 'thought'|'text'|'tool_call'|… }[],
  status, timestamp
}
MessageToolCall {
  id, name, arguments?, status, output?, explanation?,
  diffs?, startedAt?, completedAt?, turnId?, approvalMeta?
}
```

参考仓还接受 demo 预整形 `blocks: purpose|subagent|artifact|plan|composing`（`flow-projector.js:545-697`）。产品路径 **没有** 这些块类型（`MessageTimelineBlockType` 只有 thought/text/tool_call/image/step_start/step_end，`store/types.ts:359-360`）。插件必须从 `toolCalls + thought/text` 自己长出 Purpose/Artifact/Subagent，不能等后端先改协议。

### 3.3 输出树

对齐规格 §5.2 / 实现 `projectMessage`（`flow-projector.js:704-752`）：

```
{ nodes: FlowNode[], pendingApprovals: PendingApproval[] }

FlowNode =
  thinking | text | purpose{ actions: ActionNode[] } |
  subagent{ traces, children } | artifact | composing | plan/task
```

`pendingApprovals` **离开消息树**，交给 PermissionBar。

### 3.4 与 session-loop 事件如何对齐（只谈已有逻辑）

低级流（`crates/session-loop/src/stream.rs:132-157`）：

| 事件 | 已有前端落点 | 默认 UI | 插件 UI |
| --- | --- | --- | --- |
| `text-delta` | 热缓冲 `streamText` → `StreamingTextBlock` | 正文 + caret | `TextBlock`；尾帧可加 `ComposingHint`（可选） |
| `thought-delta` | `thinking` / thought 块 | 默认可不画 | `ThinkingBlock` live |
| `tool-call` | `toolCalls[]` + `blocks.tool_call` 锚点 | 极薄一行兜底 | 并入当前 Purpose / 新开 Purpose |
| `tool-result`（引擎块） | 写入对应 toolCall.output；时间线仍是 `tool_call` 锚点（`messageProjection.ts:71-73`） | 同上 | 展开 Action 的 output |
| `stop` | `status: completed` | 去掉 caret | `ThinkingBlock.settle` / 去掉 composing |
| 审批（既有 approval 通道，非本文件发明） | `pending_approval` | ApprovalAskCard | PermissionBar |

水合/重放已经走 `projectEventsToMessages`（`sessionEventProjection.ts:112-114`：「只保证文本 + 工具主路径」）。插件投影是这条链的 **再下一层**，在 `SessionMessage` 稳定之后。

```
session-loop ProviderStreamEvent
  → chat-bridge parseBridgeEvent（已有）
  → sessionEventProjection / streamingStore（已有）
  → SessionMessage
  → [默认] buildAssistantTimeline → MessageContent
  → [插件] FlowProjector.projectMessage → FlowMount 等价物
```

**不**新增 `purpose_id` IPC；**不**让投影器直读引擎事件；**不**在热路径上用 immer（规格 §11.3，与现 streaming 热缓冲纪律一致）。

### 3.5 与现 `timelineNormalizer` 的关系

| | `timelineNormalizer`（内核） | `flow-projector`（插件） |
| --- | --- | --- |
| 输入 | 同一 `SessionMessage` | 同一 `SessionMessage` |
| 工具折叠 | inspect 连续组，「N 步」 | Purpose 人话 + 多 Action |
| 思考 | 作为 timeline item 原样交错 | 独立 Thinking 节点 |
| 审批 | 仍在 tools 列表里，UI 内联卡 | 抽出 pending 队列 |
| 子 agent | 工具行里嵌 InlineAgentPanel | SubagentRoot 同构子流 |

插件激活 = MessageContent 的 timeline 组装换成 projector 树。内核 normalizer 保留给未挂插件 / 插件崩溃退让（SlotOutlet 已有 abdicate，见 §4）。

## 4. 插件激活形态（不要删 chat 叶）

### 4.1 笔记扩展是「新工具叶」；对话叙事是「同叶换渲染器」

现码笔记：

```34:57:apps/crish-desktop/src/extensions/note-paper/activate.ts
export function activateNotePaper(): () => void {
  ...
  const unregisterView = viewRegistry.registerView({
    id: 'note',
    ...
    category: 'tool',
    ...
  });
  ...
}
```

`note` **不是**第 12 内置（`activate.ts:1-2`；`main.tsx:130-133` 启动时可选激活）。这是「多一个可卸叶」。

对话叙事 **不能**再 `registerView({ id: 'narrative-chat' })`：用户还在原来的 chat 叶里说话。壳铁律仍是 `App → BinaryTreeWorkspace → TreeLeafPanel → SlotOutlet + viewRegistry`（调研边界 §与壳换代的边界）。

### 4.2 建议形态

```
activateConversationNarrative(): () => void
deactivateConversationNarrative(): void
```

内部做 **同一 chat 叶上的 renderer 替换**，优先用已有插槽而不是复活 `src/plugins` / `ContributeViewRegistry`：

1. **主路径（推荐）**：`slotCore.registerSingle('chat.stream.renderer', { id: 'narrative', priority: 高于默认, component: NarrativeFlowMount })`。`ChatCard` / `MessageContent` 外包一层 `SlotOutlet`：无插件 → 默认线性；有插件 → 叙事树。崩溃走现成 `abdicateSingle`（`SlotOutlet.tsx:70-73`，`SlotCore.ts:97-99`）。
2. **次路径**：在 chat 扩展模块里 `registerChatStreamRenderer`，ChatCard 订阅替换函数。效果相同，但不如插槽与壳一致。
3. **不要**：`registerView({ id: 'chat' })` 整叶换掉 ChatCard（会丢掉 composer / 虚拟列表 / 空态 / ribbons）；不要从 `registerBuiltInViews` 剔除 `chat`。

Composer 上方条（PermissionBar）是 **第二个单槽**，例如 `chat.composer.above`：无插件为空（现有 PlanGoalRibbons / ApprovalDock 仍由 ChatComposerWrapper 内核渲染）；插件注册 PermissionBar，并把 pending 从流内抽走。不要把计划条从内核拆走——那是已有产品面，不是参考仓 PlanRoot。

注销 = 调用 `activate` 返回的 unsub，Chat 叶立刻回到直来直去。这与 `deactivateNotePaper` 同构，只是对象从「叶定义」换成「叶内 renderer」。

### 4.3 chat 仍是主叶（现码证据）

## 5. 高度 / 折叠 / fade：CSS 包含块 vs JS 测高

产品侧原则：折叠体高度由 **包含块 + CSS `max-height` + `overflow`** 约束；fade 用伪元素。JS 测高只允许「是否溢出」这种开关，且必须 rAF 合并；禁止用测距画装饰轨。

### 5.1 用 CSS max-height 的（可迁）

| 面 | token / 规则 | 证据 |
| --- | --- | --- |
| 思考展开 | `--flow-thinking-max-h: 168px`（规格 160～200） | `conversation-tokens.css:78`；`thinking.css:112-120` |
| 子 agent 面板 | `--flow-subagent-max-h: 280px`（规格 240～320） | `conversation-tokens.css:79`；`subagent.css:144-167` |
| Action 输出 | `--flow-output-max-h: 140px` + 内边距 | `conversation-tokens.css:80`；`action.css:276-295` |
| 折叠动画 | `.flow-acc { grid-template-rows: 0fr → 1fr }` | `flow-base.css:143-157`；`dom-utils.js:144-156` |
| Notebook 浮层 | `max-height: min(560px, calc(100vh - 72px))` | `artifact-notebook.css:154-155` |
| Composing 移除 | JS 写 `max-height:0` 做 dismiss（`ComposingHint.js:45-53`） | 不推荐；用 CSS class 即可 |
| desktop 工具输出预算 | `TOOL_OUTPUT_PIXEL_CAP = 600` | `workers/thoughtWorker.ts:31`；规格 §11.3 要求对齐。插件 Action 展开高度应与此同量级，避免虚拟列表抖高 |

思考/子 agent/输出的 **上下 fade** 是 `linear-gradient` 伪元素，不是边框（`thinking.css:134-171`，`subagent.css:176-196`，`action.css:303-332`）。方向正确。

### 5.2 JS 测高（风险，产品应收成包含块）

| 调用 | 干什么 | 风险 |
| --- | --- | --- |
| `dom-utils.updateOverflowFade`：`scroller.scrollHeight > clientHeight + 2`（`dom-utils.js:194-220`） | 给 fade 宿主加 `is-overflowing` | 读布局。已 rAF 合并，比每帧写 height 好，但仍是测高。产品优先 **CSS 常驻淡 fade**（溢出才看得见），可去掉 JS |
| `ThinkingBlock` / `ActionRow` / `SubagentRoot` 在 toggle 后 `requestAnimationFrame(refreshFade)` | 展开后补测 | 同左 |
| `FlowTimelineRail.updateContainer`：`getBoundingClientRect` 算 iconX / body 高，画 SVG line（`FlowTimelineRail.js:32-115`） | 左边轨道 | **禁止迁入**。强制回流，且违反规格禁令 |
| `NotebookPanel.positionNear`：`getBoundingClientRect` 锚点（`NotebookPanel.js:139-154`） | 浮层定位 | 浮层难以纯 CSS；可接受，但不要再对 hover 改 `box-shadow`（现码 `artifact-notebook.css:159-169` 已有 hover 阴影，规格 §8.7 禁 hover 阴影——迁时改掉） |
| `PermissionBar` `void track.offsetWidth` 强制 reflow 做数字滚动（`PermissionBar.js:139-140`） | 倒计时老虎机 | 演示加戏，不迁 |
| `FlowScrubber` IntersectionObserver + tick `getBoundingClientRect`（`FlowScrubber.js:62-73,167`） | minimap | 演示壳，不迁 |
| desktop `TimelineThoughtSection` live `scrollTop = scrollHeight`（`TimelineThoughtSection.tsx:64-69`） | 思考吸底 | 已有产品行为；插件 Thinking 若做 live，用同一策略，不要再测像素画轨 |

虚拟列表：节点展开会改高度。desktop `ChatAssistantMessageRow.tsx:75-79` 已规定流式中不每 token invalidate，结束再 `invalidateActual`。插件折叠/展开必须打同一钩，否则 MessageVirtualizer 会错位。这是包含块纪律的一部分，不是新测高框架。
