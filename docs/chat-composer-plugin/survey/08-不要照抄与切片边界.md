## 0. 结论（先读）

**产品句（本战役要锁进总案的宿主）**

产品壳仍是 `App → BinaryTreeWorkspace → TreeLeafPanel → SlotOutlet('workspace.leaf.panel')`。对话落在内置叶 `chat`：未挂叙事插件时，叶内就是用户消息 ↔ 助手正文的线性流，composer 与流共用同一 surface。叙事（Purpose / 思考 / 工具 / 子任务 / 产物 / 权限条 / 计划根）以 **activate / deactivate** 挂上，模式对齐 `activateNotePaper`，**不**复活已删插件轨。文件预览走叶/槽（`file-viewer` / `files`），不走整页模态。笔记仍是扩展，不把参考仓 markdown 演示注册成第二个内核。

**演示句（永远不是产品）**

`reference/chat-composer-component/index.html` 是整应用橱窗：假侧栏 + 假窗控 + 空 `binaryTree` 壳 + 硬编码会话/计划/附件/模型列表 + `demo-data.js` 合成一轮。它证明信息架构与组件边界，**不是** desktop 布局、**不是** 数据源、**不是** 可粘贴的 DOM 树。

两条失败模式同等禁止：

1. 把橱窗整页搬进 `apps/crish-desktop`（壳重复、窗控双份、侧栏双份）。
2. 为了「先能看」把叙事 / 预览 / 新 composer 件 / token 从总案删掉（效果锁被偷换成简化面）。

本文件只划边界与逻辑切片。实现刀由主控写 `00-总方案.md` 后再派。

## 2. 必须进计划的能力面（完整，不因难而删）

用户锁：插件式对话流 + 默认直出 + 排版/样式/新组件一并盘进计划。下面每面都是总案必收项。**「完成长什么样」是效果验收句，不是本调研轮交付。**

### 2.1 默认线性流（未挂叙事插件）

**完成长什么样：** 打开 `chat` 叶，一问一答只看到用户气泡与助手正文（及产品已有的思考折叠 / 工具行若后端有 toolCalls 但插件未开——见开放问题 1）；**没有** Purpose 树、计划条、Task 根、时间线竖轨、默认展开的工具墙。

现码宿主已在：`ChatCard` 空态 vs `ChatMessageList`（`ChatCard.tsx:145-206`）；虚拟列表 `MessageVirtualizer.tsx:1-30`。缺的是「叙事未激活」的显式契约，而不是再造一个线性渲染器。

### 2.2 叙事插件（思考 / 目的 / 工具 / 子任务 / 产物 / 权限条 / 计划根）

**完成长什么样：** `activateNarrativeFlow()`（名由总案定）之后，同一 `chat` 叶把 toolCalls 投影成 Purpose → Action → 可展开命令/输出；思考限高 fade；Subagent 两行根 + 同构子流；Artifact chip；PermissionBar 在 composer 上方；进入计划模式才出现 Task/PlanStep 三层。`deactivate` 后回到 §2.1，节点可恢复（规格 §4.6：折叠不是删除）。

插拔面必须对齐笔记：**只用**现有 `registerView` / 会话级模块激活，**禁止** `src/plugins`、`ContributeViewRegistry`。叙事不是第 12 个内置视图——它是 `chat` 叶上的投影插件。

规格映射（迁入时对照，不照抄 vanilla）：

| 参考组件 | 现码落点 |
| --- | --- |
| FlowMount | `MessageContent.tsx:1-35` + 时间线 |
| flow-projector | `timelineNormalizer.ts` 升级或旁路 `flowProjector`（规格 §6.2、§12.2） |
| ThinkingBlock | 交错时间线 `TimelineThoughtSection`（`MessageContent.tsx:19`）；独立置顶思考块已拔（`ChatAssistantMessageRow.tsx:6-8,111`） |
| ActionRow / PurposeBlock | `ChatToolCallBlock.tsx` / `CompactToolRow`（已不 flatten，`ChatToolCallBlock.tsx:2-7`） |
| SubagentRoot | `InlineAgentPanel.tsx` 外壳 |
| PermissionBar | 从行内 `ApprovalAskCard`（`CompactToolRow.tsx:4,87`）+ 底部 `ApprovalDock.tsx:1-8` **上提到 composer 上方** |
| ArtifactChip + Notebook | 新件；与 Files 分流 |
| TaskRoot / plan bar | 仅计划模式；对现 `PlanGoalRibbons.tsx` |

DoD 对照规格 §13：Phase 1–4 是 **reference 闭环**；产品要的是同等效果挂在插件上，且 **默认关闭**。Phase 5「迁 desktop」不得跳过默认线性诚实。

### 2.3 Composer 新件

**完成长什么样：** 输入区与对话流同一套 surface（圆角、弱焦点、无重阴影、无粗黑边）。具备：附件卡、行内文件/Skill tag、`/` 命令、`@` 引用、`@@` 目录树、+ 菜单、权限模式、模型×思考融合触发、拖放叠层；计划条仅插件+计划模式出现。占位与交互对齐参考仓 IA，实现接现 `ChatComposer.tsx:1-17`（tiptap 主路 + textarea 回落），**不**用 `composer-core.js` 替换。

现码已有：plus / permission / slash / 附件 / 队列 / 撤回（`ChatComposer.tsx:71-118`）。缺件（文件卡视觉、inline tag、`@@`、融合模型+思考、拖放皮）进计划，不因「已有 textarea」省略。

参考 TSX 矿：`reference/.../src/components/ChatComposer/ChatComposer.tsx` + `FileCard.tsx` + `InlineTag.tsx`——吸收组件边界，不吸收演示默认文案。

### 2.4 排版包含块

**完成长什么样：** 对话列是叶内唯一纵向包含块：流区域可滚、composer 锚底、权限条/计划条（若插件开）占流与输入之间的稳定槽；思考/子 agent/工具输出有 max-height + 上下 fade；节点高度变化通知 Virtualizer；不在叶外再套 `chat-app-layout`。

现码包含块：`ChatCard` `chatBody` + `chatDocFlow` + `ChatComposerWrapper`（`ChatCard.tsx:119-226`）坐在 `TreeLeafPanel` `leafBody`（`TreeLeafPanel.tsx:200-227`）。参考仓把同一结构画在假 workspace 里（`index.html:222-274`）。迁的是 **叶内节奏**（规格 §8.3 间距 8px、§8.4 表面、§11.3 像素帽），不是外层壳。

高度链仍归 shell-rehost 01；本战役不重做 `#root` 骨架，但对话流自身的折叠高度 / 虚拟化预算必须写进总案（`TOOL_OUTPUT_PIXEL_CAP`：`workers/thoughtWorker.ts:31`）。

### 2.5 Token / 组件

**完成长什么样：** 对话流与 composer 共用三档字号（14 / 13 / 12，规格 §8.1、§14.1）、三层墨色、极弱边框、胶囊滚动条、自定义 Tooltip；组件按规格 §6.1 逻辑边界拆清（纯 props，不读 DemoData）。产品 token 映射进现有 CSS 变量，**禁止**硬编码 HEX 墙，**禁止**把 `conversation-tokens.css` 的 rail 品牌叙事带进来。

禁令并集（产品必须遵守，参考仓自己打脸的部分以规格为准）：

- `DESIGN_SYSTEM.md:21-25`：禁厚阴影、禁粗黑 focus（混入 text-primary ≤ 5–10%）。
- `DESIGN_SYSTEM.md:42-44`：禁原生 `title`。
- 规格 §8.7：禁侧边轨、禁 hover 阴影洗版、禁绿勾墙、禁流内重审批卡、禁预览/源码硬切换当文档默认、禁字号超三档、禁方块 spinner、禁英文 `Parallel`。
- 仓库 UI：自定义 Tooltip；HSLA / 斜杠透明度；焦点对比克制（Agents.md §12–14）。
- 编辑器若仅吸收视觉：`BANNED-VISUAL-UX.md` BAN-01～05（无全行激活 chrome、无读写两套皮、无半吊子能编不能编、无换壳当终局、无页顶永久格式条、无 mock AI 运行时）。

### 2.6 文件预览

**完成长什么样：** 点附件卡 / `@` 引用 / 工具路径：代码与工作区文件在 **右侧（或分屏）`file-viewer` / `files` 叶**打开；md/csv/pdf/image 等走适配器阅读态。预览壳的 toolbar / focus-trap / 格式适配器是能力，**宿主是 SlotOutlet，不是 `document.body` 模态**。文档类产物走 Artifact Notebook（§2.2），**代码文件不进 Notebook**（规格 §1.3、§14.1）。

现码：`FileViewerCard.tsx:23-40`；`FilePreview.tsx:1-53`（files 叶内预览，且 md 仍有 `mdMode: 'render' | 'source'`——迁入时规格禁止把硬切换当**文档默认**，files 源码模式与对话 Notebook 分流，见开放问题 3）。参考矿：`js/file-preview/**`、`css/file-preview/**`。

### 2.7 与笔记编辑器的关系

**完成长什么样：** 笔记继续 `activateNotePaper` → `registerView('note')` → 叶内 Strict 纸面；卸扩展叶子消失。对话战役 **不**把 `js/markdown-editor/**` 再注册成视图。聊天气泡「发送到笔记」保持 Intent 桥（`ChatSendToNoteEntry.tsx:1-12`），目标是已有 `docId`，**不是**第一打开就 `apply+commit` 一篇 persist。Artifact Notebook 是对话产物阅读/就地改，内核不是第二套 conex-mdx 注册。

现码：`main.tsx:129-133` 官方捆绑可关；`activate.ts:1-63` 对称注销；`registerBuiltInViews.tsx:50-56` 注释钉死 11 槽、缺 id 跳过；`noteViewFactory.tsx:4-7` lazy 叶；`productLeafBindings.ts:1-6` **禁止 `sessionId` 当 docId**，合成 `strict-${wsId}` 是诚实空。

BAN 文件效力：参考编辑器与将来 `packages/conex-mdx`；本战役若只动 chat 皮，不得借机给笔记加激活行描边或源码硬切。

## 3. 建议切片顺序（逻辑依赖，不是工期）

排序键：效果完整度 → 正确性 → 可验证性 → 已锁壳一致 → 结构干净。条目同权；下列顺序只表达 **「没有 X 则 Y 无法诚实」**。

```
S0 契约钉死（总案）
    │  产品句 / 演示永不搬 / 插件 activate 面 / 负产出
    ▼
S1 默认线性宿主诚实
    │  chat 叶内：未激活叙事 = 直出；composer 已在同一 surface
```

## 6. 开放问题（留给主控总案，最多 8 条）

不在此降级。总案必须拍板或显式「保持待决 + 验证钉」，不得静默选简化项。

1. **插件关着时，后端仍下发 toolCalls，线性默认怎么渲染？** 选项：纯正文（工具进折叠「N 次操作」一条、无人话 Purpose）；或沿用现 `ChatToolCallBlock` 扁平行但无 Purpose 树。规格默认是叙事开着才有 Purpose；关插件时扁平行是否算「直出」要钉，避免 S1 验收二义。
2. **叙事 activate 的粒度？** 应用级（类 `shouldActivateOfficialNotePaper` 默认关）vs 会话级 vs 计划模式才开。默认必须能直出；官方捆绑是否默认关需要用户口径。
3. **文件预览三套皮如何收敛？** `files` 叶内 `FilePreview`（含 md render/source）、`file-viewer` 叶、参考仓 `FilePreview.open` 模态。总案应收敛到叶/槽 + 适配器，并回答：md 源码模式是否仅 files 叶保留、对话 Notebook 是否永远阅读态默认（规格 §14.1）。
4. **Artifact Notebook 与 `note` 叶是否共用 conex-mdx？** 共用则包边界/BAN-* 立刻生效，且不能把产物写入当成「打开完成」。独立轻阅读面则避免第二内核，但就地 autosave 落在哪条 persist。禁止选「先不做 Notebook」。
5. **PermissionBar 与现 ApprovalAskCard / ApprovalDock 的单一真相？** 规格已决：composer 上方独立条、流内无重卡。现码是行内卡 + 底 dock 滚动定位（`ApprovalDock.tsx:1-8`，`chatApprovalUi.ts:4`）。总案写替换序与双份审批的负验收，不能长期两套。
6. **FlowScrubber 与 `MessageVirtualizer`？** 无轨刻度要按真实块高度映射（`DESIGN_SYSTEM.md:36-40`）。是 VSM 侧条还是独立层；高度通知契约（规格 §11.3）谁维护。禁止「先不做定位条」。
7. **Token 冲突：零蓝 / 品牌绿轨 / 产品 tokens.css 暗色环。** `DESIGN_SYSTEM.md:11-14` 零蓝；`conversation-tokens.css:4-6` 运行轨品牌绿；shell-rehost 05 不改 tokens 暗色 30%。总案指定对话 token 映射表，禁止再引入轨，也禁止借对话战役改全局暗色环。
8. **无 `purpose_id` 时的启发式窗口**（规格 §14.2 仍待决：explanation 归一 + 30s 窗等）以及 live thinking 默认是否只预览行。这是投影正确性，不是「太难所以扁平行凑合」。协议增强（规格 §11.2 Phase B）可并列进计划，不得作为不做 Purpose 的理由。

规格 §14.2 其余（老虎机内容、并行文案、Notebook 单例）并入 8，不另开第 9 条。
