# 06 · 现产品对话面差距（desktop ↔ 参考仓）

> 战役：`docs/chat-composer-plugin/`
> 性质：只对照「产品里现在的对话面」与「参考仓对话 + composer」。找差距与可迁切片，**不重开**旧战役。
> 对照点：`reference/chat-composer-component/CONVERSATION_FLOW_SPEC.md` §11；`index.html` 的 stream + composer；`src/components/ChatComposer/`。
> 效果锁：默认直来直去；叙事编排以扩展挂上。参考仓是能力矿，不是成品。

---

## 0. 结论先行

1. **默认线性宿主已在产品里**。`chat` 是内置主叶（`registerBuiltInViews` + `main.tsx` factory → `ChatCard`）。空会话是欢迎面 + footer composer；有消息则是用户气泡 ↔ 助手正文（交错 thought / text / tools）。未挂叙事插件时，**不要再写第二套 ChatCard / 第二套流**。
2. **参考仓多出来的是叙事编排与演示壳，不是「从零对话」**。Purpose 树、PermissionBar、Artifact chip + Notebook、Subagent 两行根、TaskRoot、流内 ComposingHint、竖轨 / scrubber —— 产品没有（或只有不同位置的半成品）。这些才是本战役可迁切片。
3. **产品 composer 远比参考仓 TSX 桩完整**。Tiptap + textarea 回落、斜杠、@ mention、附件、权限模式、队列、撤回、L2/L3 停止、草稿回填，全部已接线。参考仓 `src/components/ChatComposer/ChatComposer.tsx` 是 contenteditable 演示桩，**禁止覆盖产品输入区**。
4. **人话标签与折叠投影产品已是权威**。参考仓 `js/tool-presentation.js` 自称对齐 desktop。迁叙事时复用 `api/tool-presentation/`，不要二次作者。
5. **旧战役不阻塞本战役的效果锁**。它们锁的是：时间线单源、composer 草稿 persist、上帝 Hook 拆分、笔记扩展模式。本战役应**装饰**现有投影，而不是另起时间线或另起输入内核。

判定口径：

- **缺能力**：产品无对等行为，或对等物语义相反（例如审批在流里 vs 条在 composer 上）。
- **仅缺皮**：行为已有，差视觉语言 / 密度 / 位置。
- **归属**：默认线性 / 叙事插件 / composer 插件 / 不要做。
