# 01 · 默认线性宿主（S1 终稿）

| 字段 | 内容 |
| --- | --- |
| **效果** | 未激活叙事 = 用户仍在原来的 `chat` 叶里直出对话；槽口已在，插件随时可挂 |
| **切片** | S1 |
| **依赖** | 无（本战役第一刀） |
| **被依赖** | S2 起全部 |

## 1. 目标效果

1. `ChatCard` 的文档流位置改为 `SlotOutlet('workspace.chat.stream')`，`fallback` 仍是现 `ChatMessageList`（空态/定时任务面保持现逻辑，不要被槽吞掉）。
2. `activateConversationFlow()` / `deactivateConversationFlow()` 存在，外形对齐 `activateNotePaper`，**不** `registerView` 新 id。
3. 官方捆绑 **默认关**。`main.tsx` 不自动激活，或仅在显式开关为真时激活。
4. 关插件时 DOM/源码契约：无 Purpose 根、无 `FlowTimelineRail`、无 Composer 上方 PermissionBar、无参考仓计划 Hub。
5. 关插件时工具/思考仍走现扁平行（拍板 #1），不删 `ChatToolCallBlock` / `TimelineThoughtSection`。

## 2. 文件域

| 路径 | 动作 |
| --- | --- |
| `apps/crish-desktop/src/components/slots/SlotTypes.ts`（或现 Slot 类型文件） | declaration merging 增 `workspace.chat.stream` |
| `apps/crish-desktop/src/components/chat-card/ChatCard.tsx` | `.chatDocFlow` 有消息时走 SlotOutlet；fallback=`ChatMessageList` |
| `apps/crish-desktop/src/extensions/conversation-flow/activate.ts` | 新建。登记/注销 stream 槽；本轮可登记占位或空操作，但 API 对称 |
| `apps/crish-desktop/src/extensions/conversation-flow/index.ts` | 桶导出 |
| `apps/crish-desktop/src/main.tsx` | 读开关，默认不调用 activate |
| `apps/crish-desktop/src/extensions/conversation-flow/*.test.ts` | 契约测 |

禁止改：`registerBuiltInViews.tsx` 11 名单、`layoutStore` 的 `setChatMainSurface`、笔记扩展、并行战役脏文件。

## 3. 任务单元

1. 扩槽类型 + ChatCard 接线（有消息列表那一枝）。
2. activate/deactivate + 测试开关（对称 note 的 `setOfficial…ForTesting`）。
3. 源码/单测钉：默认 `getView` 无新 id；`package-boundary` 精神——无 `id: 'conversation-flow'`。
4. 单测：未激活 → SlotOutlet 走 fallback；激活登记后再卸 → 回到 fallback。

本轮 **不** 实现 projector、不搬 flow CSS、不改 Composer。

## 4. 验收

- vitest：activate 登记 / deactivate 卸槽 / 默认不激活。
- 源码测：无 `registerView({ id: 'conversation-flow'`；无 `src/plugins`。
- 类型检查覆盖改动文件。全桌面 typecheck 若被并行战役染红，只报本域。
- **不是**打开完成，**不是**真壳像素。

## 5. 非目标

不剥现思考/工具扁平行；不默认开叙事；不覆盖整颗 ChatCard；不把计划条藏掉（那是会话 plan 模式，不是叙事插件）。

## 6. 诚实

槽名以实现时 `SlotTypes` 现码为准，语义锁定为 chat 叶内 stream。若 SlotOutlet 对 fallback 的用法与笔记叶不同，跟现 `SlotOutlet` 契约，不新写插件运行时。
