# Agent 角色库

> **协作总则**：仓库根 [`AGENTS.md`](../../AGENTS.md)（只追加维护）。
> **本目录**：角色参考 + **轻量**阶段提示词 + **全员共享追加日志**。
> **战役正文**（总方案/分维/审计报告）落在 `docs/<战役>/`，不要堆在这里。

## 1. 设计原则（提示词要轻）

主控把 `prompts/` 当**参考**，按任务改写后派单；子 Agent 也可读。提示词**不要**写成逐步牢笼，只保住三条：

| 原则            | 含义                                                                             |
| --------------- | -------------------------------------------------------------------------------- |
| **诚实**        | 做到哪、没做哪、额外发现、对当前工作流的改进想法；不夸大、不隐瞒                 |
| **必做 / 禁做** | 任务书规定要做的必须做；不能做的不做；禁止偷懒、作弊、绕门禁、假完成             |
| **负责**        | 对自己任务负责、对项目负责；发现任务外关键问题可写入共享日志，不擅自改别人文件域 |

**明确不要**：业务 P0/P1 砍项、按「重要性」丢问题、用 token/工期/人员/流行栈否决路径；问题**一视同仁**。实现难度不作为否决理由（单文档体量建议约 **3500 行**量级为舒适上限，超出可写**替代保底方案**，但**优先非替代完整方案**）。

## 3. 推荐方案构建流（逻辑序）

```
问题发现（分析/审计多 Agent 并行，分类列出，问题同权）
    → 分维系统方案（各维 Agent 结合文档给「该维最佳系统解」）
    → 2～3 份独立总计划（各 Agent 通读前文后独立成文）
    → 主控定夺 → 最终总方案（含维度划分）
    → 各维终稿详案（单维完整方案）
    → 2～3 份计划审计（流程连贯、轮次工作量一致、验收规范等）
    → 主控定稿
    → 输出「本轮次子 Agent 通用执行规范」（吃历史教训）
    → 实现：总方案 + 本维详案 + 本轮通用规范
```

同轮人数按需，常见 **6–16**。独立总计划建议 **2–3**；计划审计建议 **2–3**。主控对派单与最终文档有规划自由。

## 4. 战役工作区（docs 下）

根目录：`00-索引`、`00-总方案`、分维终稿。
子目录仅一层：`problems/` `dimension-drafts/` `independent-plans/` `plan-audits/` `round-norms/` `execution/` 等。
共享追加日志固定用 `docs/agent-roles/shared-append/`（跨战役反馈用，**只作提议**；用户启动工作流改进巡航时再扫）。

## 5. 怎么用 prompt

1. 先贴/要求遵守 `general_task/三原则.md`
2. 选用 `prompts/` 里对应阶段作参考，主控按实况增删
3. 需要记问题或工作流建议 → 按 `shared-append/00-追加协议.md` 追加
4. 硬铁律（嵌套禁止、Git、禁 --no-verify 等）仍以根 `AGENTS.md` 为准，不必在每条 prompt 里重复长篇
