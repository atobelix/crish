# 审计与收敛问题清单（收敛版）

> **用途**：主控给 **① 审计 Agent** 派单时的方向清单；实现 Agent 自检亦可对照。
> **来源**：通用架构审问题型 + block-workspace / multi-agent 实现波审计实证（实证条目以「实证 ID + 日期」记，不引用会过期的方案文档编号）。
> **纪律**：
>
> - 清单项是 **检查意图**，不是关 EL / 效果锁的捷径；审计 **只写 audit 或点名证据**，不擅自关账。
> - **目标函数 = 正确性审计 + 收敛性审计**。每轮审计必须同时回答：功能做对了吗？结构收敛了吗（概念路径数、未接线标记趋势、净删除量）？
> - **删除裁决权在主控**：审计只列证据（重复路径、死层、陪葬测试、无日期 fallback），不擅自删；主控亲自验证代码后裁决（§23）。
> - 本文件与规范文档共享 **瘦身轮**：每 3～5 轮按「还剩几条铁律」重写，禁止只膨胀不收敛。

### 1. 架构分层与防腐 (Architecture Layering & Anti-Corruption)

检查模块间依赖方向是否正确，是否存在跨层污染。

- **壳层/接入层污染**：命令或控制器层是否包含了核心业务逻辑（如熔断、恢复策略、SQL 拼装）。
- **上帝模块/文件**：单个文件行数、职责数量是否过载（如同时处理快照、审批、评分）。
  - 本仓经验门槛：**源文件 >400 行或 >30KB** 记疑似上帝文件；实现主文件长期 **>900** 必进 SD 债包（如 `store_backend` 切开前 ~2k）。
- **依赖倒置违反**：外层是否直接引用了内层具体实现（如 UI 直接操作数据库），绕过抽象接口。
- **领域模型泄露**：基础设施概念（如 HTTP 响应体组装）是否侵入领域层。
- **跨 surface import**：note-paper / chat / markdown-editor / EditorStore 是否违反 isolation 测（`surface.isolation` / `note-paper.boundary`）。
- **chrome → leaves 层序**：生产代码是否为 id 等横切能力反向依赖叶模型（应用中性 `intentId` 等）。
- **壳层业务逻辑含量**：Tauri 壳/命令层是否包含引擎级逻辑（调度器、定时器、唤醒系统、子代理派生、完整服务端）；引擎逻辑必须位于 crates，壳层只留 IPC 注册与生命周期。

### 2. 并发与锁安全 (Concurrency & Lock Safety)

检测异步运行时中的死锁隐患、锁粒度和阻塞调用。

- **跨 `.await` 持锁**：在持有同步锁（`std::sync::Mutex`）期间是否调用异步函数，尤其是配合 `block_on`。
- **锁粒度与组合**：是否存在分散的多把锁手动组合操作，易导致死锁或状态撕裂。
- **阻塞调用误用**：CPU 密集或阻塞任务是否直接运行在异步主线程上，造成线程饥饿。
- **共享状态的读写比例**：全局互斥锁（`Arc<Mutex<T>>`）是否导致读操作也被串行化。
- **毒丸锁 / unwrap_or_else**：热路径是否用 poison 吞掉真正的并发故障而无可观测。

### 3. 性能热点与资源开销 (Performance Hotspots & Resource Cost)

识别无谓的堆分配、重复计算和序列化膨胀。

- **隐式深拷贝**：为了逃避借用检查而大面积 `clone()` 整个上下文或集合。
- **序列化黑洞**：分页/截断操作是否先全量取出再截取，导致大量无效序列化。
- **O(N²) 渲染/计算**：高频触发（如流式每一帧）的回调中是否包含对全量数据的遍历重组。
- **锁争用热点**：高频写入是否共用同一把全局锁，造成 CPU 时间片浪费。
- **空态全量 content-row**：大文档 Strict 默认是否无窗口上界（PaperList 未开时）→ 呈现性能债。

### 4. 状态管理与数据流 (State Management & Data Flow)

审查前端/全局状态的生命周期、归属及更新辐射范围。

- **上帝 Store**：全局 Store 是否混合了 UI 瞬态、持久化数据和业务状态。
- **高频局部状态穿透**：输入框内容、悬停等极高频状态是否被写入全局 Store，导致大范围无意义重渲染。
- **多源真相同步**：是否存在两套平行的状态树需要手动修补对齐，易出现悬挂或循环。
  - 本仓高频：**Memory plan ∥ Store plan**、**poll ∥ OS watcher**、**DomHost slash catalog ∥ React Overlay**、**content-row ∥ PaperList**。
- **订阅粒度与短路漏洞**：Selector/短路逻辑中的条件是否因无关全局变量（如活跃 ID）而频繁击穿。
- **写后读回断链**：`send_to_note` / apply 成功后 Strict 投影是否仍旧（缺 `refreshToken` / 总线通知）。
- **概念路径枚举**：审计范围内每个概念列出**全部实现路径**（文件:符号），判定 canonical；路径数 >1 的记入 07 收敛度量表。

### 5. 组件/模块内聚与复杂度 (Cohesion & Complexity)

衡量函数、组件或模块的职责单一性和可维护性。

- **巨型组件/函数**：JSX/函数行数、内部 `useState` 数量是否远超阈值。
  - 本仓：`NotePaperStrictPanel` 装配壳目标 **<400**（行为互斥另论）；`plan_block_ops_to_collab` 类函数 **>300 行** 记长逻辑。
- **上帝 Hook**：自定义 Hook 是否返回几十个状态和回调，将不相关的局部状态强行集中。
- **职责混合**：一个模块是否同时处理渲染、网络重试、状态更新和业务计算。
- **半拆分未接线**：磁盘上已有 `store_plan_ops.rs` 等拆文件，但 `lib.rs` **未 `mod` 接线** → 有害双份（审计须核「可编译可跑」而非「文件存在」）。

### 6. 错误与异常治理 (Error Handling & Resilience)

审计错误传播路径，识别异常吞噬和静默降级。

- **空 `catch` 吞噬**：是否存在空代码块或仅 `log` 却返回默认值的 `catch`，使系统在错误状态下继续运行。
- **Fail-Open 降级分叉**：关键错误是否被静默降级到备用路径（如 localStorage），导致多份数据分叉而无感知。
- **兜底值误导**：关键路径（如目录解析）是否使用 `unwrap_or_default()` 掩盖致命错误。
- **错误边界缺失**：前端是否缺失顶层 Error Boundary，让异常直接导致白屏或状态错乱。
- **execution_unknown 半写**：批写失败是否仍留下半提交树（须 dry_run / abort 测钉）。
- **无日期降级路径**：每条 fallback/降级/临时兼容路径必须带**删除日期**（代码注释 + 任务书）；无日期的降级 = 红，记入 08 删除清单。

### 7. 测试与 Mock 真实性 (Test Integrity & Mock Fidelity)

确保自动化测试不会制造「虚假绿灯」。

- **过度 Mock 内核**：是否 Mock 了整个底层引擎或核心 IPC，使集成测试沦为单元假象。
- **原生 API 篡改**：是否覆盖了浏览器原生 DOM 几何 API（如 `getBoundingClientRect`），屏蔽真实布局问题。
- **类型断言滥用**：测试中是否大量使用 `as any`、`@ts-ignore` 规避类型检查，隐藏接口破坏。
- **硬编码延迟/补丁**：测试或生产代码中是否存在 `setTimeout(50)` 等纯靠等待规避生命周期的烂补丁。
- **测只快乐路径**：plan/apply 是否缺 IdConflict / NotFound / dry_run 零写 / 过期 token 分支。
- **单测绿抬 e2e / 满表**：`mdPrefixHost` / `conn_d_*` / Memory 批写绿 **≠** A-BLK-08/09 e2e **≠** EL 关。
- **审计只读文档不跑测**：① prompt 须点名测命令；报告须区分「源码形状」与「本会话真跑绿」。
- **陪葬测试识别**：哪些测试的存在理由是保护死层/旧轨（列文件清单）；随死层删除的陪葬测试不算删资产，但须走 §23 流程。

### 8. 跨语言边界与契约 (Cross-Boundary Contracts & IPC)

检查序列化、竞态和沙箱策略的正确性。

- **阻塞序列化**：IPC 命令中对巨大载荷的序列化是否运行在异步主线程。
- **乐观锁缺失**：并发写入持久化层时是否缺少版本号或 CAS 校验。
- **边界错误渗透**：后端错误是否正确序列化并穿透到前端，而不是被中间层吞掉。
- **沙箱与安全**：文件/命令执行是否正确应用了白名单、路径穿越拦截，是否存在内核级过度设计。
- **source / hydrate_path 撒谎**：fixture 是否伪装 `tauri-ipc`；`prefer_query` 与 `doc-session` 标签是否诚实透传。
- **UI 有条无 IPC**：MirrorDriftStatusBar 可点但无 `note_mirror_*` / import 命令 → **半连通**。
- **库有桥桌面零引用**：`commitMdPrefixFromLeaf` 仅库测、桌面 grep 零命中 → 链仍红/黄。

### 9. 安全与输入验证 (Security & Input Validation)

审计各类注入风险、权限绕过及敏感数据处理。

- **命令/路径注入**：是否所有系统命令执行、文件路径操作都经过严格白名单校验和路径穿越防护。
- **动态执行代码**：是否存在 `eval`、`Function` 构造或未过滤的 SQL 拼接。
- **认证与授权缺失**：IPC 或 API 接口是否有越权风险，前端路由是否进行权限检查。
- **敏感信息泄露**：日志、错误消息、前端构建产物中是否包含密钥、令牌或内部堆栈信息。
- **CSP/安全头**：Web 层是否正确配置内容安全策略，防止 XSS 和资源加载劫持。
- **Plan Deny / 批写 token**：note 写工具是否可绕 plan 矩阵；过期 batch token 是否拒写。

### 10. 可观测性 (Observability)

确保系统在异常时具备足够的可追踪能力，而不是静默失败。

- **结构化日志**：关键路径是否记录了包含会话 ID、操作类型的结构化日志，而非仅 `console.log`。
- **关键异常的告警暴露**：捕获的错误是否必须上报到监控，是否存在被完全吞噬且未记录的现象。
- **分布式追踪**：跨 IPC、跨 Agent 的请求是否带有 Trace ID 进行关联。
- **性能指标埋点**：慢序列化、长锁等待、O(N²) 渲染等热点是否暴露了耗时或计数指标。
- **健康检查端点**：Rust 侧是否提供心跳或就绪探针，以供前端或运维检测引擎存活状态。
- **DOM 可观测诚实属性**：`data-hydrate-source` / `data-hydrate-path` / `data-slash-write-mode` / `data-presentation-mode` 是否存在且 **禁止**被测文案写成关 EL。

### 11. 数据一致性与幂等性 (Data Consistency & Idempotency)

检查异步操作和持久化流程是否会产生脏数据或丢失。

- **幂等保证**：工具执行、状态写入是否具备幂等键，防止重试导致重复副作用。
- **乐观锁与 CAS**：并发写入（如会话保存）是否依赖版本号或条件更新，而非简单的全量覆盖。
- **事务边界**：涉及多表、多步的逻辑是否在同一个数据库事务中，防止部分成功。
- **事件溯源/日志完整性**：关键操作是否以不可变事件形式持久化，可重放以恢复状态。
- **缓存失效策略**：前端内存缓存与持久化层之间的失效和刷新逻辑是否一致，避免陈旧数据。
- **mirror unpushed / X-05**：未确认导入是否可静默盖写；三路决策与 unpushed 计数是否一致。
- **provisional ≠ kind**：`pending_turn_into_flavour` 落盘 **≠** 权威 kind（须 RS apply 消费）；UI 禁单读 attrs 当 flavour。

### 12. 并发模型与背压 (Concurrency Patterns & Backpressure)

除了锁安全，还需关注系统在高压下的自适应能力。

- **背压传播**：流式处理或消息队列消费者是否将压力反向传导给生产者，而非无界缓存导致内存溢出。
- **并发度控制**：是否用信号量（Semaphore）或限流器限制同时运行的 Agent/请求数量，避免资源耗尽。
- **超时与取消传播**：所有异步操作是否都绑定了合理的超时，取消信号是否正确穿透所有嵌套 Future。
- **线程池隔离**：CPU 密集、IO 密集、阻塞类任务是否使用独立的线程池，防止互相拖慢。
- **子 Agent 嵌套 / 配额**：子 Agent 是否派生子 Agent（须拒绝）；同父并发上限是否被绕过。

### 13. 可维护性与代码风格一致性 (Maintainability & Code Hygiene)

让审计 Agent 也能扫描那些影响长期维护效率的软性问题。

- **魔术数字/硬编码**：是否残留未命名的常数、硬编码色值、固定延迟值，而非集中定义的常数或 Token。
- **命名一致性**：模块、变量、文件命名是否遵循项目约定，是否存在误导性或过于宽泛的名称。
- **废弃代码与 TODO**：是否遗留大段注释掉的代码、未完成的功能开关、超过约定时限的 TODO/FIXME。
- **循环依赖**：模块之间是否存在循环引用导致心智负担和潜在的初始化顺序问题。
- **未使用的依赖与声明**：Cargo.toml/package.json 中是否包含未使用的 crate/包，或存在未使用的变量/导入。
- **过期诚实句 / 叙事债**：注释仍写「query 投影派生 / React chrome 未交付」而代码已 doc-session / 已挂载 → **会计假关或假降级**。
- **中文注释编码**：UTF-8 无 BOM；禁止写入阶段变成 `?` 的坏路径。
- **波次命名禁令**：新文件/模块/提交信息禁止波次批次编号（`w\d+[a-z]?[_-]`、`BATCH-`、`Round`、`SD-*` 文件命名）；存量波次命名文件列入删除/重命名清单。
- **未接线标记趋势**：记录 `未接线|待接线|临时|TODO|FIXME|hack|占位|降级` 标记总数与上轮 Δ；**新增 = 0 为硬性要求**，趋势上升 = 红。
- **改名 ≠ 收敛**：宣称「重构完成」时核验：仅改名未删旧实现 = 假收敛（记入 §15.4）。

### 14. 构建与依赖治理 (Build & Dependency Governance)

审计供应链风险、构建性能和多环境配置。

- **依赖版本锁死**：Cargo.lock/package-lock 是否提交，防止漂浮版本破坏构建。
- **已知漏洞依赖**：扫描第三方库是否存在 CVE，是否有低版本包含已知严重缺陷。
- **特性门控与条件编译**：非必要的平台特性或实验功能是否通过 feature flags 控制，避免膨胀。
- **环境配置分离**：是否将所有环境变量、密钥从代码中抽离，是否有明确的开发/生产配置切换机制，杜绝误用。
- **构建产物大小与优化**：是否无意中引入了巨大的二进制资源或未压缩的 WASM，影响加载时间。
- **合入纪律**：禁止 `--no-verify`；lint-staged 红须正面修；**禁止**为干净 diff 做 `reset --hard` 丢用户存档。
- **运行时产物入库**：数据库文件（sessions.db / workspace.db）、快照、日志等运行期产物不得被 git 跟踪。

### 15.3 完成定义诚实边界句（审计盯「是否被抹」）

实现包注释/测头应保留类似边界，审计核对 **未被删改成满关**：

- `≠ EL-0x` / `≠ 打开完成` / `≠ inotify 满关` / `≠ A-BLK e2e`

### 15.4 假收敛与假删除（①a 必查）

> 假关的对偶：**宣称收敛/删除完成，但旧路径仍存活**。删除是一等动作，因此「假装删了」与「假装完成」同罪。

| 检查项                   | 说明                                            | 典型假收敛形态                                                |
| ------------------------ | ----------------------------------------------- | ------------------------------------------------------------- |
| **宣称已删但旧引用仍在** | 删除声明须配套 grep 旧路径/符号 **零命中** 证据 | 「localStorage 轨已移除」但 `sessionPersistence.ts` 仍 import |
| **改名 ≠ 收敛**          | 文件重命名/搬移不改变「双实现」事实             | `w6_a_s.rs` 改名 domain.rs，旧逻辑双份仍存                    |
| **删 A 加 A′**           | 删除路径后立即以新名字重建同逻辑                | 「移除 fallback」后出现 fallback2 / Retry 新壳                |
| **收敛无负产出**         | 报告「收敛完成」但无删除行数/路径数记录         | 04 计划只有 SD 包，无删除清单条目                             |
| **陪葬测试陪葬逻辑**     | 删测试保死层 / 删死层留测试空转                 | 死层已无调用，测试仍全绿占位                                  |

| 未接线/临时标记总数       |        |        |     |

## 23. 删除纪律

1. **删除裁决权在主控**：审计/子 Agent 只列证据与建议，不擅自删（与「不擅自关账」同构）。
2. **主控裁决前必须亲自验证**：读被删对象的 ≥1 个关键文件 + grep 全部调用点，确认无存活引用。
3. **陪葬测试删除流程**：Agent 列测试清单 → 主控确认 → 与死层**同批**删除；「测试还活着」不是死层存在的理由。
4. **删除完成证据**：删除后必须复跑相关门禁（typecheck / 单测 / 涉及 e2e），绿灯才算删除完成。
5. **删除声明必须附 grep 零命中证据**（旧路径/符号/import），禁止无证据宣称「已删/已收敛」。
6. **防借尸还魂**：每次删除写入规范文档「已删除/已废弃记录」节（删了什么、为什么、替代路径）。
