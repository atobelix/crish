# review 角色 · findings（跨战役毒点沉淀）

## 用途

- 存放**反复出现、应默认进下轮 ① 目的清单**的大问题/假关模式/半连通模式。
- **不是**某次战役的 `audits/00–06` 工作区（那些写在 `docs/<campaign>/audits/`）。

## 写入规则

1. **只追加**，不改写历史条目的结论（可在新文件引用旧 ID）。
2. 文件名：`YYYY-MM-DD-<短横线英文或拼音题>.md`。
3. 每条尽量含：现象 · 为何危险 · 证据路径模式 · 防伪动作 · 是否已有代码门。
4. 来源战役在文首一行标注（如 `source: docs/codebase-full-review/audits/...`）。
5. 与 `review.md` §15–18 重复时：`review.md` 可后续吸收；本目录保留**带日期的原始记录**。

## 何时写入

- 假关 EL / 去 `-S` / fixture 伪装等红线级模式新变种
- 半连通 Top 断点稳定复现
- 调度事故（过期 04 重派、半拆当交付）导致合入事故

小问题：留在战役 `audits/`，积 1–2 轮后再由补充计划消化，**不必**进 findings。
