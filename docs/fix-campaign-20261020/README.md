## 二、强制阅读顺序

1. `00-战役总纲.md`：先确认目标、范围、阶段与不变量。
2. `01-反作弊与反偷懒执行铁律.md`：确认红线、任务级别、证据标准、DoD。
3. `02-统一修复任务账本.md`：确认自己要做的条目、文件域、依赖与验收断言。
4. `../full-audit-20261020/00-全面问题清单.md`：读取对应审计条目的完整证据与修复建议。
5. 对应任务书 / 源码 / 测试 / CI 配置。

## 三、战役硬性规则（摘要）

- **标准只升不降**：不得为让审查或 CI 变绿而降低覆盖率、性能 SLA、行数/体积基线，扩大 allowlist/ignore/exclude，删除或弱化测试，自动接受 snapshot，或把 error 降级为 warning/report-only。
- **任务量守恒**：任务量大时按 L/XL 协议增加分解、验证与证据，不得缩范围、砍验收、把难项静默丢弃。
- **同类全量修复**：审计列出的同类问题必须全量搜索并一次清完；只修一个调用点、只测 happy path、只改文档不改行为，均按未完成处理。
- **证据先于结论**：交付必须附命令、退出码、原始日志、测试计数、修复前后对比；无证据视为未完成。
- **禁止假成功**：不得保留 stub、假提示、TODO 冒充完成；未实现必须显式不可用并登记。
- **主控唯一收口**：子 Agent 不提交、不回滚、不改他人文件；主控 100% 审 diff 并独立复跑关键命令。
- **诚实阻塞优先**：未完成/阻塞必须显式标注并列入账本与未验证清单；允许诚实失败，不允许虚假通过。

完整规则以 `01-反作弊与反偷懒执行铁律.md` 为准。

## 四、文档命名与维护规则

- 根目录只放导航/纪律/总纲/账本类文档，编号从 `00` 开始；阶段记录、验收记录等按编号递增。
- 子目录只允许一级；本工作区当前不建子目录，避免碎片化。
- 文件编码统一 UTF-8 无 BOM；中文正文；任务 ID 与审计 ID 保持可检索。
- 账本中的条目只能追加、状态流转、补证据，不得删除；确需废弃的条目改为 `cancelled` 并写明理由。
- 任何“完成”状态必须有 `01` §14 DoD 要求的证据；没有证据的状态只能是 `待复核` 或 `阻塞`。
- 本工作区文档不提交代码、不提交测试资产、不修改仓库入口文件；代码修复由各任务按 `AGENTS.md` §3 的提交纪律收口。
