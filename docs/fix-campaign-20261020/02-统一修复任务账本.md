## 0. 状态与证据规则

| 状态 | 含义 | 进入条件 |
| :--- | :--- | :--- |
| `pending` | 已导入，未开始 | 审计条目已登记 |
| `in_progress` | 正在实现/测试 | 已有负责人、任务卡、基线证据 |
| `blocked` | 无法继续 | 有阻塞证据、已尝试路径、所需外部条件 |
| `in_review` | 待红队/主控复核 | 实现完成，证据包齐全，等待独立复跑 |
| `done` | 完成 | 满足 DoD；证据可复现；复核通过 |
| `deferred` | 经用户裁决暂缓（非废弃、非完成） | 有用户裁决原文、生效条件与解除条件；不进入本期验收范围，但**不得删除行、不得转为 `done`** |
| `cancelled` | 经批准废弃 | 有理由、批准人、替代方案或风险说明 |

- **`deferred` 语义（2026-10-20 新增）**：与 `cancelled` 严格区分。`cancelled` 表示「该项不再需要做」；`deferred` 表示「该项仍需要做，但用户裁决暂不处理」，必须在行内写明裁决原文与解除条件。`deferred` 不计入 `pending`，也不计入完成度；阶段汇总中单独成列，禁止用 `deferred` 掩盖未完成。
- **证据列**必须包含：命令、退出码、原始日志路径、测试计数、修复前后对比、复核人。
- **无证据不得 `done`**；日志含 `FAILED` / `error` / `panic` 时不得 `done`。
- **不得用「基本完成」「后续优化」代替状态**；未完成就写 `blocked` 或 `in_progress`，并列出剩余项。
- **不得删除行**：审计条目与账本行必须保持可追溯的一一对应关系（允许一个审计条目拆成多行，但必须在「审计 ID」列标注同一 ID）。
- **父/子行规则**：拆分行必须保留父行（任务 ID 与审计 ID 相同），父行只有在全部子行 `done` 后才可 `done`；子行任务 ID 用字母后缀（`-a` 与 `07b` 两种既有写法并存，**不得事后改名**，避免引用断链与核对漏行），不得另立审计 ID。
