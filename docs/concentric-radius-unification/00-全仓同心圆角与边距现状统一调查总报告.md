# 全仓同心圆角与边距现状统一调查总报告（CONCENTRIC-RADIUS-UNIFICATION）

> **报告状态**：第一阶段（Survey & Analysis）全量收口  
> **调查范围**：`apps/crish-desktop`、`apps/agent-workbench` 及 `packages/`  
> **数据规模**：全仓扫描 **874 处** `border-radius` / 单角样式，勘察 **30+ 浮层弹层**、**15+ 设置表单卡片**、**12 组侧栏容器**、**10 组输入与对话卡片**。  
> **真理公式**：工业级同心圆角标尺 $$R_{outer} = R_{inner} + Padding \quad \Longleftrightarrow \quad R_{inner} = \max(0, R_{outer} - Padding)$$  
> **同心差值判据**：$\Delta = R_{outer} - (R_{inner} + Padding)$
> - $\Delta = 0$：绝对同心（内外圆弧处处平行，间隙均匀，完美呼吸）；
> - $\Delta < 0$：内角挤压顶出 / 严重倒挂（外壳比内容更方，四角漏出或产生锐角张力）；
> - $\Delta > 0$：角部超距平直（内边距吃光圆角或外圆角过大，内角退化为平直区）。

## 一、 为什么感觉“Pop 和设置界面元素圆角偏小，且与输入框不统一”？四大全局深层根因

### 1. 根因一：5 档 SSOT 的“代数不完备性”与级数断裂（Scale Completeness Failure）
在 2026-10-10 的圆角统一改革中，系统将圆角强行收敛为 5 档：
- `s: 4px`, `m: 8px`, `l: 12px`, `input: 20px`, `pill: 9999px`。
- 与此同时，间距体系 `--space-*` 提供了 `2, 4, 6, 8, 10, 12, 14, 16px` 全偶数阶梯。

**数学断裂证明**：
当开发者面对一个最常见的 8px 内部组件（`--radius-m`）和 6px 内部边距时，按照同心公式：
$$R_{outer} = 8\text{px} + 6\text{px} = 14\text{px}$$
然而，5 档 SSOT 中**根本不存在 14px 这个 Token**！同理，系统也缺少 **6px、10px、16px、24px** 等关键阶梯。
为了“遵守 SSOT”，开发者只能被迫将外壳降级到 `12px`，导致全站所有包含 8px 选项和 6px 内衬的浮动菜单（全仓多达 10+ 处）**无一例外恒定存在 $\Delta = 12 - (8 + 6) = -2\text{px}$ 的角部微挤压**！

### 2. 根因二：`--radius-2xl` 坍塌至 12px 导致全站浮层与弹窗“生硬方化”
- 历史穿透：为了强推 5 档收敛，`tokens.css:508` 将 `--radius-2xl` 与 `--radius-xl` 双双等同于 `var(--radius-l)`（**12px**）。
- 破坏性现状：
  - 尺寸达 $1040 \times 760\text{px}$ 的全屏大模态弹窗（`SettingsModal`、`Dialog`）圆角坍塌至 **12px**，在千像素视口下曲率极其扁平，呈现生硬方锐的矩形冷漠感；
  - `ProjectManageModal.module.css:4` 开发者显式声明 `border-radius: var(--radius-2xl, 24px);`，意图给予 24px 现代大圆角，但因 `:root` 存在 12px 的 `--radius-2xl`，后备值 `24px` 彻底失效；
  - 弹窗 Header 内边距高达 16px，因 $Padding (16px) > R_{outer} (12px)$，内部右上角关闭按钮直接跌入超距平直区，丧失几何呼应。

### 3. 根因三：空间视觉层级“倒挂”（Hierarchy Inversion）
- 视口底层：`ChatComposer` 拥有 **20px**（单行）甚至 24px（多行）大圆角；用户消息气泡为 **20px**；
- 顶层浮层：居中悬浮在最前方的 `Dialog`、`ProjectManageModal` 却仅有 **12px**；
- 倒挂差值：$R_{outer} - R_{inner} = 12 - 20 = -8\text{px}$！
在空态落地页，弹窗正上方覆盖在输入框中央，人眼产生极度强烈的“浮层比底下的输入框更方、更锐、更小”的视觉逆差。

### 4. 根因四：代码中的同心意图被全局 Token 强行抹平（注释铁证）
调查发现，原设计者早在多处关键代码中严格设计了同心标尺，并在注释中留下铁证：
- `SmartPanel.module.css:195` 注释：`/* 槽位化菜单条目 (Outer 14px - Padding 6px = Item 8px) */`，声明了 `var(--sep-radius-outer, 14px)`；
- 但 `tokens.css:282` 将 `--sep-radius-outer` 钉死为 `--radius-l` (12px)，14px 的同心设计被无情降为 12px；
- `ChatComposer.module.css:1292` 多行态声明了 `var(--composer-radius-multi, 24px)` 配合 8px 内边距达成同心，但被 `tokens.css:512` 强行锁回 20px，造成多行态下内挤压 $\Delta = -2\text{px}$。

## 三、 全仓查获的优秀典范（正面基线）

调查发现，仓内优秀的模块已经自发践行了同心数学，具备现成可复用的成熟范式：

1. **`SetupHintBanner` 范式（用户指定的同心标杆）**：
   - 代码：`--soft-hint-radius: calc(var(--soft-hint-btn-radius) + var(--soft-hint-py));`
   - 按钮 8px + 边距 10px = 外框 18px，内外圆弧平行同心，完全消除倒挂；
2. **`ui/Select` 动态阶梯范式**：
   - 随尺寸档（sm/md/lg）联动：`calc(var(--radius-m) + 4px)` (12px)、`+ 6px` (14px)、`+ 8px` (16px)，三档均达成 $\Delta = 0$；
3. **`TiptapSlashMenu` 反向派生范式**：
   - 外圆角由外向内减扣：`--slash-radius-inner: calc(var(--slash-radius-outer) - var(--slash-pad));`，保持内外等距同心；
4. **批注与附件微卡片范式**：
   - 附件叉号（$12 = 9 + 3$）、批注卡片（$18 = 6 + 12$）、终端卡片复制钮（$12 = 4 + 8$），均严格满足 $\Delta = 0$。

## 四、 统一治理方案设计（供裁决推进）

基于 6 份调查报告与同心数学模型，提出**“三大统一治理支柱”**：

### 支柱一：Token 体系补齐与枢纽键确立（修复根因一与二）
1. **平反顶级模态圆角（恢复 24px / 20px 枢纽键）**：
   - 将 `--radius-2xl` 平反为 **`20px` ~ `24px`**（专供全局 `Dialog`、`SettingsModal`、`ProjectManageModal` 等顶层模态）；
   - 彻底解决顶层弹窗（12px）比底层输入框（20px）更方、更锐的层级倒挂！
2. **平反二级浮层圆角（恢复 14px / 16px 枢纽键）**：
   - 将 `--sep-radius-outer`（所有下拉菜单、上下文面板外壳）由 12px 修正为 **`14px`**（$14 = 8 + 6$，达成完美同心）；
   - 将通用卡片容器（`--radius-xl`）由 12px 提升至 **`16px`**（$16 = 8 + 8$，包容 8px 控件与内衬）。
3. **补齐关键过渡阶梯**：
   - `--radius-xs: 4px`，`--radius-sm: 6px`，`--radius-md: 8px`，`--radius-lg: 10px`，`--radius-xl: 14px/16px`，`--radius-2xl: 20px/24px`。

### 支柱二：全仓推行 `calc()` 同心标尺（推广积极范式）
在任何存在“外容器内嵌可交互子卡片/按钮”的组件中，坚决淘汰“父子复用同一 Token”的粗暴写法，全面推行：
```css
/* 范式 A（外向内推导）：已知外圆角与内边距 */
.childItem {
  border-radius: max(0px, calc(var(--parent-radius) - var(--parent-pad)));
}

/* 范式 B（内向外推导）：已知子控件圆角与内边距 */
.parentCard {
  border-radius: calc(var(--child-radius) + var(--card-pad));
}
```

### 支柱三：治愈极端倒挂病灶（逐项清剿）
- **模型凭据卡**（`ModelsSettingsTab`）：将外层 `.credentialsContainer` 从 7px 恢复为卡片级 **14px/16px**；
- **计划表单**（`ScheduledTasksPanel`）：外框提升至 **16px/20px**，内输入框保持 **8px**；
- **会话条目**（`SessionItem`）：外层保持 8px 时，内部更多操作小按钮调整为 **6px**（配合 2px padding 达成 $8 = 6 + 2$ 完美同心）；
- **用户卡片**（`UserProfileCard`）：外层提升至 **16px/18px**（如 $13px (\text{Avatar}) + 4px = 17px \approx 16px/18px$），彻底消灭内凸外平。
