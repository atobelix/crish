# Conex / Crish — 统一提示词与上下文注入总方案 (Master Architecture Plan)

> **战役工作区**：docs/prompt-injection-pipeline/
> **权威性质**：总调度定稿方案（收敛 6 份独立方案、3 份深度评审报告与 5 份连贯可执行详案）。
> **主控复核**：2026-09-02 主控逐条对照代码现实复核并修订（本版含契约统一裁决、跨维执行顺序与现实基线注记）。
> **核心使命**：彻底根治散落在各 UI 与 Hook 中的硬编码 Prompt 与隐式通道，贯彻「对话流可见注入卡片（Visible Context Injection Card）」一等公民模型，建立 Prompt 集中库（SSOT）、三级会话草稿隔离管道（SessionDraftManager）、5 维上下文引用标准化与定时任务编排助手（Workflow Grill-Me）端到端闭环。

## 一、核心架构范式转移（Paradigm Shift）

### 1. 彻底清退「隐式 System 拼接」与「多余 AI Tool Call」
- **全新单一真理模型（SSOT）**：
  - **静态 System 基座**：仅保留 L0 基础身份与 L1 环境契约，会话内绝对不可变，享受 100% Prompt Caching 命中；
  - **动态注入与模式助手**：升级为**「对话流上下文可见注入卡片（Visible Context Injection Card）」**，由系统在动作触发时（如点击在对话中创建、输入 /schedule、选区代码引用 @file、规则热载入等）**直接被动注入（Passive Direct Injection）**进入时间线；
  - **UI 视图投影**：在前端渲染为精致的折叠卡片（同构于 ToolCard，具备 7 色语义微光与 Token 估算）；
  - **Wire 协议投影**：按时间戳作为带 [系统上下文注入 · Title] 标头的标准 messages 消息块透传给大模型，模型天然按时间因果序读取。

### 2. 静态 System 基座的真理源边界（主控复核裁决）
- **前端不发明 AI 身份**：本项目当前**没有任何前端硬编码的身份文本**——基座 systemPrompt 来自用户配置（provider profile / `options.systemPrompt`），Agent 身份与能力定义由 Rust 侧 `engine_build.rs` 的 M1 ContextInjector 冻结契约（注入顺序 `[System, Skills, Mcp, AgentDefinition]`，动态字段带 `@dynamic` 标记保护缓存）承载。
- 因此 `prompts/core/systemCore.ts` 的 L0 层职责是**透传用户基座 + 叠加本项目工程纪律**（中文注释、UTF-8 无 BOM、反退避、门禁零绕过等），**严禁虚构/照抄外部产品的身份声明**（如 Antigravity/DeepMind 署名）。
- Rust 侧 M1 ContextInjector 是**既有冻结契约**：本战役对其只做「核对与收敛接入」，不做盲删——`@dynamic` 机制已解决动态字段的缓存失效问题，详案中的 Rust 清退动作一律先核对 `engine_build.rs` 现状再动。

## 三、统一契约裁决（全战役唯一卡片契约，主控定案）

评审 01 已裁决「统一收敛为单一通用契约」，**主控复核后定案如下，全部详案以此为准**：

1. **唯一时间线卡片契约 = `apps/crish-desktop/src/store/types.ts` 的 `MessageContextInjection`**（详案 02 定义版）：
   - `kind`（9 类，snake_case）：`rule | skill | file_context | git_status | terminal_output | runtime_steering | schedule_trigger | memory | workspace_env`；
   - `status`（5 态）：`pending | injected | active | expired | failed`（含 failed + 重试语义）；
   - 字段名以详案 02 为准：`summary`（非 description）、`tokenEstimate`（非 estimatedTokens）。
   - **不另立** `src/types/injectionCard.ts`（详案 05 / 评审 01 的 `ContextInjectionCardPayload` 废止，其 `mode-assistant` 场景映射为 `kind: 'schedule_trigger'`）。
2. **附件元数据不另立平行实体**：详案 04 的 `ContextAttachmentPayload` 降级为 `MessageContextInjection.metadata` 内的类型化子结构（截断信息、行号锚点、退出码等挂 metadata），由 `kind: file_context / git_status / terminal_output / workspace_env` 承载；`src/types/attachmentContracts.ts` 仅承载该 metadata 子结构 schema，**不作为顶层卡片实体**。
3. **写卡动作单一路径**：统一经详案 02 的 `ContextInjectionDispatcher`（其底层在 `sessionStore.ts` 新增 `addContextInjection` action，实现上复用既有 `addMessage` 的 `injections` 字段写入）。详案 03/05 不得绕过派发器直写 `addMessage`。
4. **草稿管理器唯一路径**：`src/api/draft/sessionDraftManager.ts`（详案 03 定义版）；上层只调 `injectSeed / setDraft / undoDraft`，**禁止**绕过 manager 直接双写 `setComposerDraft`（详案 05 初稿的双写已废止）。
5. **截断归属**：Head-Tail 截断与 Token 预算钳制的 **wire 权威在 Rust**（session-loop / agent-provider）；前端 TS 同构实现仅用于卡片预览与展示估算，**取代** `multimodal.ts` 现存的 80KB 尾部 slice（不得三层并存）。
