## 一、维度目标与物理现实穿透

彻底恢复桌面主窗口顶部「单轨同层整合」布局，使会话标签条（`PaneHeader`）与 Windows 窗控按钮（最小化、最大化、关闭）以及帮助按钮（`?`）无缝并存于同一高度（`var(--header-height, 36px)`）。

### 物理现象与断层剖析
1. **现状**：
   - `.workspaces-column` 下有两个直接子元素：`<AppTopBar />` 与 `<div className="workspaces-stack">`。
   - `AppTopBar` 占据了文档流高度 36px，且宽度为 100%；
   - `workspaces-stack` 内部的二叉树叶子 `PaneHeader` 又占据了 36px；
   - 顶部总高度 $36\text{px} + 36\text{px} = 72\text{px}$，产生一行巨大的无内容空白带。
2. **目标物理态**：
   - `workspaces-column` 建立局部定位上下文（`position: relative; overflow: hidden;`）；
   - `AppTopBar` 作为绝对定位浮层（`position: absolute; top: 0; right: 0; height: var(--header-height); pointer-events: none; z-index: var(--z-sticky, 20);`），不占据文档流高度；
   - `workspaces-stack` 占满 `100%` 高度，首行叶子的 `PaneHeader` 物理高度依然为 36px，从 `top: 0` 开始渲染；
   - 二叉树多窗格拓扑引擎根据叶子位置输出 `[data-top-row="true"][data-right-edge="true"]`；
   - 最右上角的 `PaneHeader` 通过 `padding-right: var(--edge-reserve-right-win)`（Windows 下 144px，macOS 下 38px）自动为窗控让位；
   - 其余非最右上角的窗格标签栏不受避让影响，自然铺满。

## 二、纯逻辑执行步骤与任务单元

### 任务单元 1.1：`workspaces-column` 定位参考系固化
- **文件域**：`apps/crish-desktop/src/styles/shell/shell-layout.css`
- **逻辑内容**：
  - 确保 `.workspaces-column` 具有 `position: relative;`，作为其内部所有绝对定位微件（包含 `AppTopBar`）的唯一父级定位包含块；
  - 保证 `.workspaces-stack` 具有 `height: 100%; flex: 1 1 0%;`，直接与列顶对齐。

### 任务单元 1.2：`AppTopBar` 悬浮化与事件穿透重构
- **文件域**：
  - `apps/crish-desktop/src/components/top-bar/AppTopBar.module.css`
  - `apps/crish-desktop/src/components/top-bar/AppTopBar.tsx`
- **逻辑内容**：
  - 将 `.topBar` 改为绝对浮层：
    ```css
    .topBar {
      position: absolute;
      top: 0;
      left: 0;
      right: 0;
      height: var(--header-height, 36px);
      min-height: var(--header-height, 36px);
      max-height: var(--header-height, 36px);
      display: flex;
      align-items: center;
      background: transparent;
      box-sizing: border-box;
      user-select: none;
      -webkit-app-region: no-drag;
      app-region: no-drag;
      pointer-events: none;
      z-index: var(--z-sticky, 20);
    }
    ```
  - `.trail`（承载帮助按钮与 `WindowControls`）维持 `pointer-events: auto;` 与 `flex-shrink: 0;`；
  - `.spacer` 维持 `data-tauri-drag-region`，但仅在非标签覆盖区支持拖拽窗口。

### 任务单元 1.3：`PaneHeader` 顶行右缘 Token 避让体系恢复
- **文件域**：`apps/crish-desktop/src/components/binary-tree/PaneHeader.module.css`
- **逻辑内容**：
  - 恢复顶行最右侧叶子的内边距避让规则，严禁裸写数字，全部调用已验证的 Design Tokens：
    ```css
    :global([data-top-row="true"][data-right-edge="true"]) .paneHeader {
      padding-right: var(--edge-reserve-right-win);
    }
    :global([data-platform="macos"]) :global([data-top-row="true"][data-right-edge="true"]) .paneHeader {
      padding-right: var(--edge-reserve-right-macos);
    }
    ```
  - 清理废弃的注释与临时补丁。

### 任务单元 1.4：工作区外壳容器 `.section`（`_section_tyyig_18`）四周零 Padding 落地
- **文件域**：`apps/crish-desktop/src/components/binary-tree/BinaryTreeWorkspace.module.css`
- **逻辑内容**：
  - 用户明确指示：「`class="_section_tyyig_18"这个应该是没有padding的，四周应该都没有`」；
  - 彻底切除 `.section` 上的 `padding: var(--shell-canvas-gutter, 8px);`，改为 `padding: 0;`；
  - 消除四周 8px 的空隙落差，使工作区与顶栏及边缘 100% 贴边，实现极致空间利用率与严丝合缝的单轨对齐。

## 三、负向红线与验收断言

1. **负向断言**：
   - 严禁顶栏存在任何裸写 `margin-top` / `padding-top` 补偿；
   - 严禁 `workspaces-column` 存在高度大于 36px 的任何单独顶栏节点；
   - 任何分屏状态下，非右上角的叶子标签栏绝不出现右侧 144px 的无效空隙。
2. **正向验收断言**：
   - `AppTopBar` 与 `PaneHeader` 在真实渲染树中物理 Y 轴起点均为 `0`；
   - Windows 环境下，最右侧 Tab 标签在达到极限宽度时，与窗控左边缘保持至少 8px 安全间隙，无物理遮挡与点击穿透错位。
