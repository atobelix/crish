## 二、目标态（自上而下的唯一真源链）

```
出厂能力字典（只读，Rust 编译期打包，唯一）
        │  装载期合成：用户声明优先 → 出厂字典兜底
        ▼
用户配置树 models.yaml  ←── 唯一写者 ModelsStore（CAS + 原子写 + 凭据引用）
        │
        │  同一提交事务内派生
        ▼
运行期已合成快照（能力 / 定价 / 上下文 / 模态 / 缓存 TTL / 思考档位，revision 与盘上恒等）
        │
        ├──► 出站请求决议（热路径只读快照，零回退兜底）
        ├──► 前端展示面（模型列表 / 定价 / 设置页，经命令面读取，零本地副本）
        └──► 活动选择（activeModel，唯一来源 = 树）
```

**完成定义**：链上任一环节都只有一份实现、一份数据、一个 revision；任何「在链外能独立决定模型身份 / 能力 / 价格」的代码即架构断层。

## 三、三条架构裁决（消除多轨与兼容层的依据）

### 裁决 ①：出厂能力字典**不属于**用户配置树

- **依据**：`crates/agent-provider/src/models/catalog.json`（6167 行 / 368 id）是编译期打包的出厂数据（`models/catalog.rs:365` `include_str!`），与用户声明是**不同性质**的数据；而 `ModelsStore` 的 CAS 语义建立在「用户声明即真源」上（`model_store.rs:288-303`）。
- **结论**：**禁止**把出厂字典投影写进 `models.yaml`（会污染用户声明、破坏 CAS 语义、把只读数据变成可写状态）。正确形态 = **独立只读字典读面**，由 Rust 唯一提供并注册进命令面，前端零本地副本。
- **后果**：前端 6 份硬编码定价表与 61KB 预填字典**物理删除**，不是「保留为兜底」。

### 裁决 ②：运行期快照必须由 `ModelsStore` 的已提交树派生

- **依据**：现行 `LIVE_CATALOG`（`engine_provider/protocol.rs:46`）走独立读盘路径（`models/catalog.rs:727` `load_user()` 读同一文件但独立解析），且刷新口零生产调用方（`:297`）；保存后 `reload_provider()`（`engine_build.rs:509`）只重载 baseUrl/model/apiKey 三件套 ⇒ 同一请求内**新旧修订混用**。
- **结论**：能力快照**不得**有独立读盘路径，必须从 `ModelsStore::committed()` 派生，并在**同一次提交事务内**重建，使快照 revision 与盘上 revision 恒等；出厂字典只参与**装载期**合成。
- **后果**：`LiveModels::load_user()` 的读盘语义删除（降级为纯 `from_tree()` 投影）；热路径 `bundled_catalog().lookup`（`engine_build.rs:984`）与 `ttl.rs:62 vendor_default_ttl` 物理删除。

### 裁决 ③：模型身份 = `(providerId, modelId)` 二元组

- **依据**：`00-总方案.md:304` 已禁止「裸 `modelId` 跨供应商匹配」；现行 `pricingResolver.ts:100-105` 的 `model.includes(key) || key.includes(model)` 双向子串匹配使身份非确定（同名模型跨供应商摇摆正是本战役故障 A）。
- **结论**：**禁止**任何 substring / 前后缀 / vendor 猜测匹配参与身份、能力、价格决议；模糊匹配只能存在于「用户输入的搜索/过滤 UI」且不得产出解析结果。
- **后果**：三处模糊匹配改精确二元组查表；`modelsAutofillBaseline.ts:102`、`:105-140` 的魔术打分表删除。
