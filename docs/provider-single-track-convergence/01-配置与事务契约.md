# 配置与事务契约

本分案细化总方案 B/C/D/E 的交接边界。只规定结构与依赖，不分配人员或安排时间。

## 核心数据

```ts
type ModelRef = { providerId: string; modelId: string };
type ModelsYamlTree = {
  version: 2;
  activeModel: ModelRef | null;
  providers: Record<string, ProviderSpec>;
};
```

- Rust 对应 `UnifiedModelsConfig.active_model: Option<ModelRef>`，写出 `activeModel: null` 表示未配置。
- ModelRef 两段 trim 后保留大小写；索引采用 JSON 二元组编码或同样无歧义的结构键，不用 `::` 拼接。
- `normalize_for_commit(&mut self)` 是核心验证、规范化和失效选中清除入口；解析及提交必须实际调用。
- `CompatSpec::merge(provider, model)` 是唯一字段级继承实现。显式 false、0 和关闭值覆盖供应商声明，未提供字段才继承。
- Provider 包含 enabled、order、proxyUrl、apiKeyRef；Model 包含 enabled、order、cacheTtl、supportsTools。其它已公开字段须完整保留。
- `pricing.input/output` 为可选数值，0 代表明确免费，未配置不能被造为 0。`unit` 取 `per_1m_tokens`、`token`、`per_image`；图片价和阶梯价完整往返。
- apiKeyRef 是显式凭据引用：`dpapi:<不透明槽ID>` 或 `env:<变量名>`。核心只验证引用形状，实际凭据读取在有权访问系统凭据库的边界完成。
- Windows 凭据槽不可由 providerId 直接拼接。不同大小写、Unicode 或带分隔符的模型身份不应造成凭据串用或路径错误。
- `apiKey`、旧 capabilities、contextLength、价格别名不进入规范运行树；历史转换在明确的迁移边界完成。明文旧 key 必须先成功导入系统凭据库，再原子改写引用；失败保留原件并返回错误。

## 提交边界

核心事务必须统一支持两种用户输入：规范配置树（表单、活动选择）以及完整 YAML 文本（高级编辑器）。两者共用验证、CAS、写盘、快照发布和错误传播；不能分别维护两套保存实现。

1. 读取返回规范树、原文、路径、内容修订号及必要的脱敏凭据状态。
2. 保存必须带 `expectedRevision`；在写锁内对实际磁盘内容校验。过期输入返回结构化冲突，拒绝覆盖。
3. 先完成全部语义验证，再原子写文件；返回实际落盘后的完整规范树和新修订号。
4. 只有成功回执才能更新前端已提交镜像、活动选择和下一请求的内核快照。
5. 外部文件改变沿同一读取/验证入口刷新；无效原文保留并报告错误，不用空树替代。

IPC 名称和参数以实际新增/改造并注册的命令为准。实现交接时必须同时提供 Rust 主注册表、前端调用点和权限定义，不允许先在前端登记一个不存在的命令。

## 前端镜像边界

`modelsCatalogStore` 保存规范树、修订号、加载/错误状态和派生索引。草稿留在编辑会话内；不得让写失败的草稿成为已提交目录。

活动模型读取直接投影 `tree.activeModel`。供应商档案、选择器、就绪提示也从同一树派生；Settings.defaultModel/defaultProvider、LocalStorage profiles/meta/active 键均不参与生产读写。

前端负责输入交互和错误呈现，不重复实现核心 YAML 解析或有损字段白名单序列化。规范树通过结构化 IPC 提交，高级编辑器才提交用户原文。

## 运行与历史边界

有效请求配置绑定 `ModelRef + revision`，并包含当次出站和计价所需完整配置。凭据、代理与协议发生变化时，下一个请求使用新配置，已经开始的请求继续使用原快照。

实际使用量与价格快照/结果必须随运行持久化。历史查询只读取当次记录；当前活动模型和当前价格不参与历史重新定价。

## 必须命中的断言

- 两个只在大小写上不同的供应商可独立索引、选择及保管凭据。
- 含 `::` 的两段身份不会撞键；规范后重复身份明确拒绝。
- 单改显示名后，价格、缓存、能力、协议覆盖和 headers 与原值一致。
- 未配置、0、false、显式清空各自保持语义；无效数值拒绝写盘。
- 一个窗口提交成功，另一个旧修订窗口无法覆盖；冲突不损失草稿。
- 禁用当前项与清空活动选择属于同次提交；没有任何自动替代模型。
- 修改价格后旧运行费用不变；运行中改价不改变正在执行请求的计价依据。
- 无匹配身份、缺失凭据引用、错误 YAML 时，上游收到零请求。
