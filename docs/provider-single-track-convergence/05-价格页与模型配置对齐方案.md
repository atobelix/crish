# 05 · 价格页与模型配置对齐方案（分维详案）

> 上级总方案：`04-端到端系统性收敛方案.md`（§阶段 3「真源唯一化」）。
> 本文只解决**价格面**的名单与真源对齐，不重复 04 已裁决的字典读面接线。
> 需求来源：用户 2026-09-15 口述四条（见 §1）。

---

## 1. 用户需求原文（不得降级）

1. 现在的价格配置那里和模型配置界面也是**不匹配**的。
2. 模型配置列表里面**没有锁死的厂商**，任何厂商都是可以删除的。
3. 模型价格：因为有智能填充字典，用户在配置界面配置了模型后，价格页可以**先根据字典生成一个预估价格**；如果用户自己配置了，则**以用户实际定义为准**；如果用户删除了模型，那么**模型价格也不应该存在**。
4. 对于模型字典，**只做参考，实际以用户配置为准**。

---

## 2. 现状实证（根因链）

### 2.1 名单不同源（需求 1 的直接成因）

| 面 | 名单真源 | 证据 |
|---|---|---|
| 模型配置界面 | 统一树 `~/.conex/models.yaml` → `modelsCatalogStore.modelIndex` | `apps/crish-desktop/src/api/modelsCatalogStore.ts:57-70`（`emptyState`/索引）；`components/settings-models/useModelProfilesState.ts:61-71`（`toSettingsProfile` 由 `IndexedProviderEntry` 投影） |
| 价格配置界面 | **localStorage 扁平价表** `crish_model_prices_v1` | `components/settings/SettingsUsageTab.tsx:2`（`loadPrices`）、`:24-26`（`safeLoadPrices`）、`:45`（`useState<ModelPrice[]>`）、`:186`（传入弹窗）；`api/pricingStore.ts:74-84`（`loadPrices` 直读 LS） |

⇒ 价格页只显示「用户曾经手输过价」的条目，**不显示**用户在模型配置里配好的模型（如 `ollama/ornith`）；反过来，模型已删但价表残留的条目仍会显示。这就是「不匹配」。

### 2.2 价格编辑面唯一，但落到第二存储

- 模型配置抽屉**已不含**价格编辑：`components/settings-models/ModelConfigPanel.tsx:115` 注释「四维计费：用户裁决 #3 移出抽屉（在用量配置单价里配置）」。
- `components/settings-models/ModelPricingEditor.tsx` 全仓**只有它自己的测试引用**（`ModelPricingEditor.test.tsx:5,16,37,57`），生产无消费方 ⇒ 死 UI（另见 §6 清理项）。
- 因此唯一价格编辑面 = `components/settings/PriceConfigModal.tsx`，其写入走 `api/pricingStore.ts:88-92`（`savePrices` → LS）、`:94-99`（`upsertPrice` → LS）。

### 2.3 树里其实**有** pricing 字段，但没有价格编辑面写它

- 树 schema 含 `pricing`：`crates/agent-provider/src/models/catalog_types.rs:281`（`pub pricing: Option<ModelPricingSpec>`）；前端镜像 `api/modelsCatalogTypes.ts:113-121`（`PricingConfig`）。
- 写路径存在：`api/modelsCatalogStore.ts:318-329`（`updateModel(providerId, modelId, patch: Partial<ModelSpec>)`，走 CAS 提交）。
- 但**没有任何价格编辑 UI**调用它 ⇒ 树的 `pricing` 只能由用户手改 YAML 或草稿写入。

### 2.4 反向缺陷：字典预估价被当成「用户声明」写进树（违反需求 4）

链路：
- `components/settings-models/manualAddAutofill.ts:20`（`findAutofillModel` 取基线/字典）→ `:76-84`（把 `autofill.pricing` 填进草稿 `pricing`）。
- `components/settings-models/catalogWriteGate.ts:90-96`（`addDraftToModelInput`）→ `:94`（`draftToModelPatch(draft)`）。
- `api/modelsDraftMap.ts:30,38`（`pricing` 在映射字段表内）→ `:107-131`（`pricingFromDraft` 产出 `PricingConfig`）。

⇒ 用户手动新增模型时，**字典/基线的预估价被写进 `models.yaml`**，此后与「用户自己配的价」不可区分。这正是需求 4 要禁止的「参考值冒充用户声明」。

### 2.5 估算链当前读的是 LS 价表（不是树）

`api/pricingStore.ts:147-156`（`resolve4dPrices`）：`inputPerMTok = hit?.inputPerMTok ?? snap?.inputPerMTok`，其中 `hit = resolveModelPrice(ref)` = **LS 价表**（`:105-108`），`snap` = 出厂字典快照。⇒ 用户在树里（手改 YAML）配的价**不参与**对话成本估算，第三处不一致。

### 2.6 需求 2（厂商可删）现状

已修复：`components/settings-models/ProfileHeader.tsx` 原以 `selected.id.startsWith('custom-')` 硬编码判定可删（历史缺陷），现已去除与厂商 id 的绑定；负向断言见 `components/settings-models/providerDeletability.test.ts`。**本方案不改此项**，仅在验收清单中复核。

## 3. 目标契约（单一真源）

**定价唯一源 = 用户声明（统一树）覆盖 + 出厂字典预估兜底。**

| 概念 | 真源 | 说明 |
|---|---|---|
| 价格页**名单** | 统一树 `modelIndex`（全部已配置模型） | 有 provider 维度；模型删除 ⇒ 名单自动少一条 |
| 单个模型的**用户价** | 树 `ModelSpec.pricing` | 身份 = `modelRefKey(providerId, modelId)`（裁决 ③） |
| **预估价** | 出厂字典快照 `resolveSnapshotPrice(ref)`（按 model id） | **只读参考**，UI 必须显式标注「预估」 |
| **未收录** | 两者皆无 | 显式空值 + 「未收录」标记；**禁止**渲染为 0 |
| LS 价表 `crish_model_prices_v1` | **退役** | 对齐 `04-…方案.md` R-7（价格轨与阶段 3 合并） |

解析优先级（唯一回退链，禁止 substring / 模糊回退）：

```
树 ModelSpec.pricing  →  出厂字典快照（预估）  →  null（未收录）
```

## 4. 分期实现（每期独立可合入 / 可回滚）

### 期 1：名单对齐（需求 1、3、4 的可见面）

- 价格页名单改为树派生：新增 `api/modelPricingSource.ts`
  - `listConfiguredPrices(): ConfiguredPriceRow[]` —— 由 `modelsCatalogStore.modelIndex` 投影，携带 `{ ref, providerId, modelId, displayName, userPricing, estimated }`。
  - `resolveEffectivePrice(ref)` —— 实现 §3 回退链，返回 `{ source: 'user' | 'estimate' | 'none', ... }`。
- `components/settings/PriceConfigModal.tsx` 与 `components/settings/SettingsUsageTab.tsx` 改为消费该投影；每行标注价格来源（用户 / 预估 / 未收录）。
- 空名单提示区分「树里没有模型」与「搜索无匹配」。
- **不改** LS 价表读写（期 1 内 `userPricing` 仍读 LS，作为过渡），确保可回滚。

### 期 2：用户价落树（需求 3 的写入面）

- 价格页编辑改为 `modelsCatalogStore.updateModel(providerId, modelId, { pricing })`（CAS 异步 + 失败显式提示，禁止静默降级）。
- `api/pricingStore.ts` 的 `resolveModelPrice` 改为读树 `ModelSpec.pricing`（**签名不变**，`resolve4dPrices` / `estimateCostUsd` / `getModelCurrency` 消费方零改动）。
- 一次性幂等迁移：LS 价表条目能由树解析**唯一**供应商 → 写入树；歧义 / 未知 → 丢弃（不猜）；树未加载 → 不迁移、不改写。迁移完成后 LS 键置空。
- 删除 `savePrices` / `upsertPrice` 的 LS 写入面。

### 期 3：防「预估冒充声明」（需求 4 的写入面）

- `manualAddAutofill.ts` 的 `pricing` 预填语义改为**界面提示**：草稿中区分 `pricingFromAutofill`（参考）与 `pricing`（用户显式输入）。
- `api/modelsDraftMap.ts` 的 `draftToModelPatch` **不写** `pricing`，除非用户显式编辑过价格字段。
- 门禁断言：新增模型落树时，未显式编辑价格的模型**不得**带 `pricing` 字段。

### 期 4：门禁与验证

- 断言 P-1：价格页名单 ⊆ 树模型集合（无孤儿、无缺漏）。
- 断言 P-2：模型从树删除后，其价格不可再解析出（`resolveModelPrice` 返回 null）。
- 断言 P-3：字典预估价不得出现在 `models.yaml` 的 `pricing` 中（未显式编辑时）。
- 断言 P-4：未收录不得渲染为 0。
- 真机 MCP 验收：配置页加/删模型 → 价格页名单与来源标注同步变化。

## 5. 验收断言（可执行）

| 编号 | 断言 | 判据 |
|---|---|---|
| P-1 | 价格页名单 = 树模型集合 | 对任意 `modelIndex` 快照，名单条目数相等且 `modelRefKey` 一一对应 |
| P-2 | 删模型 ⇒ 价消失 | 树 `removeModel` 后 `resolveModelPrice(ref) === null` |
| P-3 | 预估价不落树 | 走「手动新增」流程且未编辑价格 → 落树补丁无 `pricing` 键 |
| P-4 | 未收录 ≠ 0 | 两者皆无时估算返回 `null`，UI 渲染「未收录」而非 `0` |
| P-5 | 身份二元组 | 价格写入必须用 `modelRefKey`，禁止 `::` 拼接（沿用 D5 防线） |
