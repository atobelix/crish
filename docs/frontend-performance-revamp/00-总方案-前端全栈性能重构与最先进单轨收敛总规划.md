# 00 — 前端全栈性能重构与最先进单轨收敛总方案

> **文档版本**：v1.0.0 战役总纲  
> **战役工作区**：`docs/frontend-performance-revamp/`  
> **核心原则**：最先进单轨代码落地、零无谓伪兼容、全链路 120fps 极速响应、长会话内存有界、首屏 TTI ≤ 120ms。  
> **指挥纪律依据**：`AGENTS.md`、`.agents/LOGIC_PLAN_NO_RETREAT.md`、`ANTI_OVERENGINEERING_GUARDRAILS.md`。

## 一、战役背景与战略目标

在 Conex / Crish 的持续演进中，前端层积累了大量多版本别名、降级分叉、伪兼容层与低效协调机制（如深层 Immer 树克隆、DOM 测高回流、跨帧状态漂移、未绑定的全局观察器与无界消息缓存）。

**用户核心战略指示**：

> 1. “不要兼容、不要多版本号迭代。如果是重要的，涉及历史遗留的这种是可以有兼容的（如历史对话数据结构）。对于没有多大意义，但是依旧兼容的就没有必要了。尽量是能留一个最先进的代码方案就留最先进的就行。”
> 2. “去掉兼容层的时候，要确保已经存在的代码能完全替代，以及能更好的发挥之前的旧代码发挥不了的作用，而且是更强大更先进的才行。”
> 3. “先建立战役工作区，梳理好总方案以及每个阶段需要做的事情。第一个 agent 负责 12 阶段，第二个负责 23 阶段。这样每个阶段就有两个 agent 产生对应的计划方案了。第二轮方案生成的时候，一个 agent 就能看到两个方案，然后综合或者融合或者是有更好的方案，生成对应的最终计划文档。”

### 核心物理目标（全量锁定）：

1. **渲染帧率**：120Hz 刷新率下交互与连续滚动 0 掉帧（单帧主线程 JS 开销 ≤ 0.5ms）；
2. **流式开销**：100 Token/s 高频推流期间主线程 CPU 占有率从 10% 降至 **< 1.0%**；
3. **长会话内存**：1000+ 条超长消息会话常驻内存严格有界（DOM 节点稳定受控 ≤ 360 个）；
4. **冷启动水合**：首帧内容绘制 LCP < 80ms，可交互时间 TTI **≤ 120ms**，白屏瀑布彻底归零；
5. **代码纯净度**：物理切除伪兼容别名与过渡期回退分支，实现架构净收敛。

### 各阶段职责、技术突破与交付断言清单

#### Stage 01：状态管理与重渲染优化（State Management & Re-render Topology）

- **职责范围**：Zustand Store 拓扑重构、选择器粒度收敛、重渲染级联阻断、持久化防抖大一统。
- **核心做的事情**：
  1. 状态树物理拆分：将会话元数据（`metaById`）与消息数据（`messagesBySessionId`）物理拆分为两棵独立子树，会话标题/状态变动不再触发万级消息数组比对；
  2. 标量版本代数槽位（Epoch Slots）：为高频变动实体配备整数版本代数（`epoch: number`），视图层借由 `useSyncExternalStore` 配合 `Object.is` 进行寄存器级标量比对，单消息更新零对象深克隆；
  3. 持久化防抖单轨收敛：全仓统一使用单一 `STORAGE_PERSIST_DEBOUNCE_MS = 300` 常量，消灭散落的 50ms、100ms、1000ms 竞争定时器；
  4. 拔除旧版伪兼容选择器别名，保留且仅保留直接定位原子状态的 SOTA 选择器。

#### Stage 02：对话流式引擎与消息流水线优化（Streaming Engine & Pipeline）

- **职责范围**：实时 Token 注入、流状态机、双轨锁存交接、DOM 直通渲染。
- **核心做的事情**：
  1. 双轨锁存交接协议（Dual-Latch Handoff）：在流式生成进入终态（`completed`/`error`/`aborted`）时，激活状态机自锁存并结合双帧 `requestAnimationFrame`（或 `onTurnCommitted` 布局提交握手），新消息在 DOM 完全渲染上屏前绝不清空热备缓存，彻底根除流终态单帧白屏；
  2. StreamDirect 双轨直通引擎：活跃尾部消息的 Token 增量 100% 绕过 React Virtual DOM 协调，直接调用原生 DOM `TextNode.appendData` 进行 $O(\text{chunk.length})$ 追加，推流 CPU 压降至 <1.0%；
  3. `finalAgents` 原子归档：子 Agent 运行期消息与终态快照原子写入对应槽位，消灭异步时序竞争丢失；
  4. 拔除旧式双向代理与流式临时兼容包装，确立单一确定性流处理流水线。

#### Stage 03：长对话虚拟滚动与列表渲染优化（Virtual Scroll & Message List）

- **职责范围**：VirtualScrollManager（VSM）、树状数组（BIT）计算、手势保护、复合作用域隔离。
- **核心做的事情**：
  1. 树状数组 $O(\log N)$ 二进制倍增寻址：虚拟滚动全量依托 Fenwick Tree 进行前缀和与二分查找，消除线性累加遍历；
  2. 惯性手势保护网：硬件 Touchpad/Wheel 活跃期冻结程序位移补偿与 DOM 强写，消除滚动条抽搐；在会话切换与吸底时实现布局期同步直达，消灭 2~4 次上下抖动；
  3. `${paneId}::${sessionId}` 复合作用域隔离：彻底消除多分屏同会话下的 VSM 实例覆盖与幽灵注销；
  4. 粗粒度混合分桶虚拟化：现代 CSS `content-visibility: auto` + 100 行分桶，页面总 DOM 节点数恒定 ≤ 360，长会话流畅度提升至 120fps。

#### Stage 04：增量Markdown解析与Worker卸载优化（Incremental Markdown & Worker Pool）

- **职责范围**：Markdown 解析管道、代码高亮、数学公式、Worker 卸载与调度池。
- **核心做的事情**：
  1. Web Streams TransformStream DFA 单遍流式增量 Lexer：废除尾部投机反引号注入与全文字符串反复切片，流式发射块事件，代码块原生追加；
  2. 三级级联取消接入：会话切换或删除时，立即强杀 Worker 任务并原地补建 Worker 实例，阻断幽灵任务回写；
  3. `BlockGeometryBook` 纯内存化：全面移除 Markdown 内部散落的独立 DOM ResizeObserver，单一归口到消息外层容器；
  4. 清退旧版重复解析补丁，保留单一高效增量 AST 构建管线。

#### Stage 05：富文本输入器与块编辑器优化（Composer & Block Paper）

- **职责范围**：Tiptap 输入器、Block Paper 编辑器、草稿持久化、IME 与选区保护。
- **核心做的事情**：
  1. 双级自愈混合增量缓存：L1 WeakMap（内存快照）+ L2 版本代数与脏块区间账本，根治 ProseMirror Undo/Transform 节点重建导致的缓存击穿；
  2. 分屏拖拽交互期 IME 与光标绝对保护：拖拽分屏时锁定输入器选区，杜绝中文输入法未上屏状态下的断词、吞字与丢焦；
  3. `(sessionId, leafId)` 草稿物理分区持久化：消灭全局单草稿冲突与跨窗格污染；
  4. SWR 静默重验 4 项硬性断言：输入器配置热更新期间 0 卸载、0 丢焦、0 闪烁、0 卡顿。

#### Stage 06：多窗格分屏布局与侧边栏优化（Pane Layout & Sidebar）

- **职责范围**：二叉树窗格布局系统、分屏拖拽、侧边栏会话列表虚拟滚动。
- **核心做的事情**：
  1. 细粒度窗格级冻结（Gated Resizing）：拖拽分屏调节条时，仅冻结交互涉及的窗格，后台推流窗格与全屏浮层 100% 保持吸底和贴合；
  2. 8ms 时间预算分片排空循环：松手时测高排空单帧耗时超过 8ms 自动顺延至下一帧 rAF，根除 Long Task；配 200ms Windows 失焦看门狗；
  3. 侧边栏 `.sidebarScroll` 虚拟滚动宿主绑定修复：活跃 DOM 节点严格限制在 ≤ 45 行，彻底清除全子树 MutationObserver（MO）；
  4. 拔除旧版全局大一统单例挂起状态，收敛至窗格级细粒度状态机。

#### Stage 07：重型工具视图终端Diff与文件树优化（Heavy Views: Diff, Terminal, Tree）

- **职责范围**：Xterm 终端、大文件 Diff 视图、虚拟化文件树、DAG 流程图。
- **核心做的事情**：
  1. L1 视口核心工作集锁定 + L2 分块 Chunk 缓存池：彻底根治大 Diff 跨跳时 2000 行 LRU 击穿颠簸与 Worker 堵死；
  2. 终端 512KB 有界环形缓冲吞吐与 ANSI 警示标记：超出阈值自动压缩截断并触发自愈，终端吞吐突破 5MB/s 零卡顿；
  3. 文件树纯前缀路径局部变异与 $\le 60$ 恒定 DOM：目录折叠展开仅更新变更前缀节点，全树 DOM 节点数严格受限；
  4. 采用 Blink 原生 `CSS.highlights` 渐进增强替代逐行 Span 拆分，超长行水平滚动耗时 $\le 0.5\text{ms}$。

#### Stage 08：UI原子组件浮层与CSS渲染合成优化（UI Components, LayerStack & CSS）

- **职责范围**：Design System UI 原子组件、LayerStack 浮层调度、CSS 渲染规则与样式合成。
- **核心做的事情**：
  1. 门控大清洗：收敛为三大确定性物理原语（`DirectDomWriter`, `NativeContentVisibility`, `EpochSlotObserver`），废除所有基于模糊坐标或测距魔术数字的补偿补丁；
  2. Blink `class_rules_` $O(1)$ 哈希规则桶恢复：全仓彻底清退 `[class*="..."]` 属性模糊匹配，第三方类名规范化为 CSS Modules `:global(...)`，样式匹配耗时削减 90%；
  3. 原生 `:popover` 与 CSS 锚点定位驱动零回流浮层：浮层展示期间 JS 主线程 CPU 开销归零；
  4. SafeAim 原生连通屏障与分屏拖拽独立浮层通道：多级子菜单三角防抖无延迟，拖拽时浮层无错位、无残留。

#### Stage 09：内存泄漏与生命周期管理优化（Memory & Lifecycle Management）

- **职责范围**：全局资源生命周期、Worker/Timer/Listener 销毁、长会话内存回收。
- **核心做的事情**：
  1. 三级级联取消总线（Three-Tier Cascade Cancellation Bus）：会话销毁时，Tier 1 计算级 terminate Worker、Tier 2 通信级注销 Stream、Tier 3 存储级注入 SQLite 500 容量 LRU 墓碑，彻底终结幽灵复活；
  2. 多窗格分屏可见性绝对豁免软逐出：未激活窗格只进行轻量级 DOM 占位，其 VSM 内存高度状态绝对不丢失，重聚焦时零测量秒级复原；
  3. 单点内聚两行切入清理：所有副作用统一依托 SLR（Scoped Lifecycle Registry）自动注销，拔除遗留的散落 `window.removeEventListener` 死代码；
  4. 存储防抖大一统为 300ms，消除异步写竞争造成的内存泄漏。

#### Stage 10：冷启动链路与构建拆包优化（Startup, Hydration & Bundle Splitting）

- **职责范围**：应用冷启动时序、Shell-Zero 骨架水合、Vite 构建拆包、3-Way Merge 增量写屏障。
- **核心做的事情**：
  1. Shell-Zero 动态代偿水合架构：提取 ≤60KB 纯静态骨架内联于 `index.html`，结合 <1.5KB 原生代偿队列代理首帧用户点击，TTI 压降至 **≤ 120ms**，LCP **< 80ms**；
  2. 三方合并增量写屏障（Delta Write Barrier & 3-Way Merge）：仅拦截启动期空数据全盘冲刷，放行用户交互新会话，磁盘慢响应下执行集合论无损合并，用户数据 0 丢失；
  3. Vite 构建动态拆包三阶刚性验证：拆分 Editor、Terminal、Diff、Markdown 等重型模块为异步 Dynamic Import，首屏主 bundle 体积削减 65% 以上；
  4. 彻底切除首屏阻塞式同步 IPC 检查，改走异步后台预热通道。
