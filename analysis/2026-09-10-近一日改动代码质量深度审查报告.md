配合 `:133-141` 的免费判定（要求 `per_image.unwrap_or(0.0) == 0.0`）：`per_image: Some(0.0)` + `input: 3.0` 的模型 → 不走 free 分支 → 走分支 1 → `total_micros = 0`、`is_free = false`、UI 显示 `$0.0000`。**计费静默归零，且不像"免费"那样可识别。**

**② `:146` `let image_count = completion_tokens;` —— 一个 `u64` 字段承担两种语义**
`calculate_cost_from_usage`（`:215-230`）就是从 `usage.completion_tokens` 直填。文档注释（`:117`）承认了"`completion_tokens` 解释为张数"这个约定，但类型上没有 `ImageCount` newtype 之类的保护。**若某家 provider 对生图模型照常上报真实 completion_tokens，就会把 token 数当张数计费**，量的级别完全错。

**③ `:250` `f64_to_micros` 把负费率静默归零**
```rust
if !val.is_finite() || val <= 0.0 { return 0; }
```
负值（折扣/录入笔误 `-0.5`）→ 0 → 免费。无校验、无日志。价格数据是外部录入的 YAML，这个输入面应该 fail-closed 或至少落告警。

**④ `:170-186` 阶梯只覆盖 tier 显式提供的维度，未提供的沿用"基础费率"而非"上一档费率"**
```rust
active_input_rate = tier.input;
active_output_rate = tier.output;
if let Some(cr) = tier.cache_read { active_cache_read_rate = cr; }   // 否则保留基础 cache 价
```
一个只声明 input/output 的档位会**静默沿用基础 cache 价**，与它自己已改的 input 价不自洽。

**⑤ "零金额"有两个真源，字符串不一致**
`CostBreakdown::free()`（`:56-67`）产出 `"免费"` + `is_free: true`；`format_micros(0)`（`:269-271`）产出 `"$0.0000"`。而 `:133` 的免费判定要求 `tiers.is_empty()`，于是 **tiers 非空但费率全 0** 的模型落到 `is_free: false` + `"$0.0000"` —— 经济含义相同的两种状态，对外表现不同。
