## 二、本轮新确认的确定性缺陷

### 2.1 【阻断】思考块三源 + 去重键错误：既会重复渲染，又会误删

`apps/crish-desktop/src/api/tool-presentation/timelineReconciler.ts:138-160`

```ts
if (msg.thinkingTurns && msg.thinkingTurns.length > 0) {
  const existingThoughtTurns = new Set(          // ← 循环外建一次
    blocks.filter((b) => b.type === 'thought' && b.turnIndex != null)
          .map((b) => sanitizeTimelineTurnIndex(b.turnIndex))
  );
  for (const tt of msg.thinkingTurns) {
    const cleanTurn = sanitizeTimelineTurnIndex(tt.turnIndex);
    if (tt.content?.trim() && !existingThoughtTurns.has(cleanTurn)) {
      const thoughtBlock = {
        type: 'thought', content: tt.content, turnIndex: cleanTurn,
        durationMs: tt.durationMs,
        id: tt.id || `thought-turn-${cleanTurn}`,   // ← id 由 turnIndex 派生
      };
      if (cleanTurn === 0) blocks.unshift(thoughtBlock); else blocks.push(thoughtBlock);
    }
  }
}
```

两个独立缺陷叠加：

**(a) `existingThoughtTurns` 在循环内从不更新。** 输入 `thinkingTurns = [{turnIndex:0,content:'A'},{turnIndex:0,content:'B'}]` 且 blocks 无 thought：
- tt#1：`has(0)`=false → push，id = `thought-turn-0`
- tt#2：`has(0)` **仍是 false** → 再 push，id 同样 = `thought-turn-0`

→ 两个 thought 块**共享同一个 id**，`reconcileAssistantMessageBlocks` 步骤 2 会把 incoming 的两块都 push 进 result。渲染层若用 `block.id` 作 key 就是**重复 key**，且同一段思考来源被渲染两次。

**(b) 去重键只用 `turnIndex`，不看内容或 id。** 反过来，只要该轮已有任意 thought，后续新增的思考块会被**全部丢弃**——同一轮内的多段思考（真实存在：模型在一轮里思考两次）会被静默吃掉。

**结论**：这个去重键在一个方向上重复、在另一个方向上误删。正确做法是按 `id`（或 `id + content` 哈希）去重，并在循环内维护集合。

### 2.2 【阻断】`enforceThoughtBeforeText` 在实时路径上恒为空转 —— 这解释了为什么 6 轮都没修好

`apps/crish-desktop/src/api/tool-presentation/timelineNormalizer.ts:251-272`

```ts
for (let i = 0; i < result.length; i++) {
  const cur = result[i]!;
  if (cur.kind !== 'thought') continue;
  const curTurn = cur.turnIndex;
  if (curTurn == null) continue;                     // :260
  const misplacedTextIdx = result.findIndex(
    (it, idx) => idx < i && it.kind === 'text' && it.turnIndex === curTurn   // :263 严格相等
  );
  ...
}
```

判据是 `it.turnIndex === curTurn`（数字严格相等）。而**实时流式路径产出的 text 块根本不带 `turnIndex`**：

`store/sessionMessageActionsCore.ts:242-247`
```ts
msg.blocks.push({ type: 'text' as const, content: segment, startTime: now, durationMs: 0 });
//                              ^^^ 没有 turnIndex
```

于是 `it.turnIndex` 是 `undefined`，`undefined === 0` 恒为 false → `findIndex` 恒返回 -1 → **这个函数在实时路径上一次都不会重排**。它只在"已经从持久化里读回来、且 text 块恰好带 turnIndex"的数据上才会生效——而那批数据早就被上游 `reconcile` 定序过了。

`pushParsedText` 的两个调用点也都传 `undefined`（`timelineNormalizer.ts:219` 与 `:236`），进一步确认实时路径必然拿不到 turnIndex。

**这是本轮最有价值的发现**：`58243c26`（"accurate chronological block timeline"，第 6 次尝试）加的"物理因果时序守卫"**在它要修的那条路径上根本不触发**。5 次失败的启发式 + 第 6 次一个空转的守卫，这才是"同一问题改 6 次不收敛"的机械原因。

### 2.3 【严重】同一份代码里两条法则正面冲突：reconciler 禁重排，view-model 强制重排

| 位置 | 法则 |
|---|---|
| `timelineReconciler.ts:83` 注释 | 「严格按流式到达的插入顺序输出——**禁止任何 type/turn 强制重排**，真实时间线顺序即为唯一权威」 |
| `timelineReconciler.ts:122-123` | `// 严格按插入顺序（流式到达顺序）返回，不做任何 type/turn 重排序` |
| `timelineNormalizer.ts:247-249` 注释 | 「物理因果时序守卫：同一轮次内，**思考必定先于正文**产生，严禁因底层 blocks 乱序将同轮次 thought 排在 text 之后」 |

### 2.10 【严重·安全】`asset:` 协议 scope 覆盖全盘，且 CSP 的 `connect-src` 允许 `asset:`

`apps/agent-workbench/src-tauri/tauri.conf.json:27-30`
```json
"assetProtocol": {
  "enable": true,
  "scope": ["$APPDATA/**", "$RESOURCE/**", "**", "*/**", "*:\\**", "*:/**"]
}
```
`**` / `*:\\**` / `*:/**` = **整机文件系统**（含 Windows 与 POSIX 两种写法）。

而同一个文件的 CSP（`:23`）：
```
"connect-src 'self' ipc: http://ipc.localhost ... asset: http://asset.localhost https://asset.localhost;"
"media-src 'self' data: blob: asset: ...; img-src 'self' data: blob: asset: ...; frame-src 'self' ... asset: ..."
```

**`connect-src` 里带 `asset:`** 意味着 **JS 可以 `fetch('asset://localhost/C:/Users/<user>/.ssh/id_rsa')` 并读到响应体**——这是一条任意本地文件读取原语。`script-src 'self'`（无 `unsafe-inline`）说明直接 XSS 有门槛，但这个应用的主要功能就是**渲染模型生成的 Markdown**，渲染链路上的任一注入缺口都会被放大成"读任意文件 + 通过 `img-src`/`frame-src` 外带"。

**建议**：把 asset scope 收窄到 `$APPDATA/attachments/**` 这类确需目录；把 `connect-src` 里的 `asset:` 删掉（本地图片用 `img-src` 就够，不需要 JS 可读）。
