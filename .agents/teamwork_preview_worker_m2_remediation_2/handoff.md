## 1. Observation

### Upstream Defects Identified
1. **CodeBlock Language Loss**: In `src/extensions/code-structure/CodeBlockExtension.ts`, `language.parseHTML` was previously only checking `element.getAttribute('data-language')`. When `tiptap-markdown` parsed HTML code blocks of the format `<pre><code class="language-rust">...</code></pre>`, `<pre>` had no `data-language` attribute and no `language-*` class on `<pre>` itself, causing the language attribute to default to `'javascript'`.
2. **WikiLink Double-Escaping**: In `src/extensions/code-structure/WikiLinkExtension.ts`, DOM node transformation inside `updateDOM` previously wrapped the rendered DOM span content with literal `[[` and `]]` delimiters (`<span ...>[[TargetLabel]]</span>`). During Markdown serialization, `tiptap-markdown` applied `open: '[['` and `close: ']]'` while escaping internal brackets in the text node, yielding `[[\[\[TargetLabel\]\]]]`.

## 2. Logic Chain

### Step 1: Remediation of `CodeBlockExtension.ts` `parseHTML`
- **Observation**: HTML generated by Markdown parser emits code blocks as `<pre><code class="language-rust">...</code></pre>` or `<pre class="language-rust">...</code>` or `<div data-language="rust">...</code>`.
- **Reasoning**: To reliably extract the language attribute without falling back to `'javascript'`, `CodeBlockExtension.ts` lines 34–48 now check four places in sequence:
  1. `element.getAttribute('data-language') || element.querySelector('code')?.getAttribute('data-language')`
  2. `element.getAttribute('class')` matching `/language-([a-zA-Z0-9_+-]+)/`
  3. `element.querySelector('code')?.getAttribute('class')` matching `/language-([a-zA-Z0-9_+-]+)/`
  4. Fall back to `this.options.defaultLanguage || 'javascript'`.
- **Conclusion**: When parsing ` ```rust `, ` ```python `, ` ```cpp `, or ` ```typescript `, `node.attrs.language` correctly captures the language name and serializes back to ` ```rust `, ` ```python `, etc.

### Step 2: Remediation of `WikiLinkExtension.ts` DOM Parser & Serializer
- **Observation**: `WikiLinkExtension.ts` configures `serialize` as `{ open: '[[', close: ']]', expelEnclosingWhitespace: true }`.
- **Reasoning**: `tiptap-markdown` automatically prepends `[[` and appends `]]` around mark text nodes. The DOM node produced in `updateDOM` (lines 86–92) must set inner HTML content to `${displayText}` without wrapping outer `[[` and `]]` inside the span text. When `target !== label`, `displayText` is `${target}|${label}` (e.g. `TargetDoc|TargetLabel`); when `target === label`, `displayText` is `${target}` (e.g. `TargetDoc`).
- **Conclusion**: AST serialization emits clean `[[TargetDoc|TargetLabel]]` or `[[TargetDoc]]` without bracket double-escaping (`\\[\\[`).

### Step 3: Verification via Unit Testing & Suite Execution
- **Observation**: Added `src/__tests__/unit/m2BiDirectionalSerializationRemediation.test.ts` to test multi-language CodeBlocks (`rust`, `python`, `cpp`) and WikiLinks (`[[TargetDoc]]`, `[[TargetDoc|TargetLabel]]`, `[[Architecture_2026]]`).
