  1.5 !important 系统性消除计划
  ============================================================

  当前总计 ~588 处（stylelint 已配置 declaration-no-important: true 阻止新增）

  按文件分布（从高到低）：

  消除策略（按 !important 的必要性分类）：

    类别A —— CSS 特异性战争：由于全局类名和 CSS Module 混合使用导致
           的选择器优先级冲突，这才是绝大多数 !important 的根源。
      解决方案：在文件拆分后，利用 @layer 重新建立层叠优先级。
        例：@layer reset, layout, components, overrides;
        将 polish 修正放入 overrides 层，无需 !important 即可自然覆盖。

    类别B —— 第三方/浏览器 UA 样式覆盖：例如 autofill 背景色、
           WebKit scrollbar 样式等。
      解决方案：保留 !important（这是它们的设计用途），或使用
            更高的特异性选择器（如 html[data-theme] 前缀）。

    类别C —— 内联样式对抗：JavaScript 动态设置的 style 属性。
      解决方案：重构为 CSS 自定义属性驱动，在 JS 中设置 --var 而非 style。

    类别D —— 误用：完全可以通过层级或选择器特异性解决的。
      解决方案：直接移除 !important。

  执行计划（分 3 轮进行）：
    第1轮：拆分后的 shell-*.css 和 settings-*.css 文件
           采用 @layer 消除类别A/D 的 !important
           目标：从 334 处减至 50 处以下（仅保留类别B）
    第2轮：组件 CSS Module 文件（ChatCard 32 处、Sidebar 18 处等）

  ============================================================
  1.6 CSS Module 与全局类名混用策略规范化
  ============================================================

  当前问题:
    大量组件同时使用 `styles.className`（CSS Module 局部作用域）
    和 `"global-class-name"`（全局类名，如 "agent-card-btn"）。
    这种混用导致：
    - 无法从代码确定选择器的实际特异性
    - 全局类名污染导致意料之外的样式覆盖
    - 孤儿类名（如 agent-card-btn）在代码审查中难以发现

  规范化方案：
    1. 全局 CSS 类名仅用于以下用途：
       - 布局结构（.sidebar, .workspace-card, .card-header 等）
       - 主题/密度变体（html[data-theme], html[data-ui-size]）
       - 工具类（.tool-row, .tool-stack 等跨组件共享的样式）
    2. 所有组件特有的视觉样式，统一迁移到 .module.css 文件中
    3. 对于需要跨组件共享的样式，定义在 tokens.css 中作为 CSS 自定义
       属性（如 --tool-row-height），由组件 CSS Module 引用
    4. 所有全局类名必须在 styles/ 目录下某文件中明确定义，
       不允许组件内使用未定义在全局样式文件中的裸类名

  ============================================================

五、弹窗/菜单原生 CSS 过渡动画系统（Phase 5）
──────────────────────────────────────────────────────────────────────────────

  逻辑说明：Phase 4 完成后子智能体界面干净。Phase 5 解决所有弹窗/
  浮层/菜单"瞬间消失"的生硬体验——使用现代 CSS 原生能力，零依赖。

  ============================================================
  5.1 技术基础 —— @starting-style + transition-behavior
  ============================================================

  核心理念：
    避免引入 framer-motion（~32KB gzipped）和 Radix UI（~15-20 个包）。
    利用 CSS 原生特性实现弹出层的进入/退出动画：

    @starting-style {
      /* 元素刚刚插入 DOM 时的初始状态 */
      .popover { opacity: 0; transform: translateY(8px); }
    }
    .popover {
      /* 稳定状态 */
      opacity: 1;
      transform: translateY(0);
      transition: opacity var(--transition-smooth),
                  transform var(--transition-spring);
    }
    .popover.closing {
      /* 关闭状态 */
      opacity: 0;
      transform: translateY(4px);
    }

    配合 transition-behavior: allow-discrete 使 display:none → display:block
    的切换也能触发过渡动画（Chrome 117+ / Edge 117+ / Tauri WebView2 兼容）。

  方案架构：
    a. 所有弹窗/浮层使用条件 CSS 类（.is-open / .is-closing）驱动状态
    b. React 端使用单层状态机管理进入/退出时序：
       - 打开：设置 is-open → 等一帧（requestAnimationFrame） → 浏览器自动过渡
       - 关闭：设置 is-closing → 等待过渡结束（ontransitionend）→ 移除 DOM
    c. 封装为 useAnimatedPresence hook 供所有弹窗组件复用

  ============================================================
  5.2 useAnimatedPresence Hook 实现
  ============================================================

  文件：src/hooks/useAnimatedPresence.ts（新建）

  接口：
    interface UseAnimatedPresenceOptions {
      visible: boolean;
      exitDurationMs?: number;
      onExited?: () => void;
    }

    interface UseAnimatedPresenceReturn {
      state: 'entering' | 'open' | 'exiting' | 'closed';
      ref: React.RefCallback<HTMLElement>;
    }

  实现逻辑：
    1. visible 从 false → true：
       设置 state = 'entering'（此时 DOM 插入，@starting-style 触发入场动画）
       下一次 rAF 后设置 state = 'open'（过渡完成后稳定状态）
    2. visible 从 true → false：
       设置 state = 'exiting'（触发退场动画）
       等待 transitionend 事件（或 exitDurationMs 超时回退）
       设置 state = 'closed'（DOM 删除）
    3. ref 用于在 DOM 元素上绑定 transitionend 监听

  CSS 使用指南（每个弹窗组件）：
    .popover {
      opacity: 0;
      transform: translateY(8px);
    }
    .popover.is-entering,
    .popover.is-open {
      opacity: 1;
      transform: translateY(0);
      transition: opacity var(--transition-smooth),
                  transform var(--transition-spring);
    }
    .popover.is-exiting {
      opacity: 0;
      transform: translateY(4px);
      transition: opacity var(--transition-exit),
                  transform var(--transition-exit);
    }
